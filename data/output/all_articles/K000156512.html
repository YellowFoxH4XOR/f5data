K000156512: Global Log Receiver 401 Unauthorized Error with SentinelOne Integration

2025-09-17

2025-09-17
Applies to

Source

Description

When configuring a new Global Log Receiver (GLR) in F5® Distributed Cloud to forward logs to a SentinelOne Data Lake endpoint, attempts to test the connection may result in the following error:

Http failure response: 500 Server Error  
There was a server error in processing request  
connection test status: FAIL unable to send test message:  
ERROR sink{component_kind="sink" ... component_type=http}:request{request_id=1}: vector::sinks::util::retries: Not retriable; dropping the request. reason="Http status: 401 Unauthorized" internal_log_rate_limit=true

This error indicates that the outbound request to the SentinelOne endpoint is being rejected with a 401 Unauthorized status.

Environment

  • Global Log Receiver

Cause

A 401 Unauthorized error occurs when the Authorization token is either not included in the outbound request or is formatted incorrectly. In this scenario, issues were observed where:

  • The GLR configuration did not properly save or transmit the Authorization header as expected.
  • The content-type header sent by GLR is application/x-ndjson and cannot be changed to application/json.

Answer/Recommended Actions

  1. Token Configuration

    • When configuring the GLR in the F5 XC Console, enter only the raw token value in the authentication field. Do not prepend "Bearer" to the token; F5 XC will automatically format it as Authorization: Bearer <token>.
    • If configuring via API, ensure your header appears as follows: 
      {
  "name": "Authorization",
  "value": "Bearer <YOUR_S1_TOKEN>"
}
    • Do not include "Bearer" in front of your token if using Console's built-in authentication field.

  2. Content-Type Header

    • The GLR sends logs with Content-Type: application/x-ndjson. This value is fixed and cannot be changed. Ensure that your receiving endpoint (e.g., SentinelOne Data Lake) accepts this content type.

  3. Verification

    • After updating your configuration, use “Test Connection” within XC Console to verify successful communication. A successful test should return HTTP 202 or another success code from your endpoint.

  4. Troubleshooting

    • If you continue receiving a 401 Unauthorized error:
      • Double-check that your token value is correct and valid.
      • Ensure that your token has not expired or been revoked.
      • Confirm that your receiving endpoint accepts both your provided token and content type.
      • Avoid including "Bearer" in front of your token when using Console’s authentication field.
