Known Issue

Note: For more information about Interface Mirroring, refer to: K8573: Overview of port mirroring and clone pools.

Important: This issue only affects the BIG-IP 1000, 2400, 5100, and 5110 platforms.

This is the result of a known issue. When configuring Interface Mirroring, a BIG-IP administrator selects a Destination Interface and one or more Mirrored Interfaces. If both copper and fiber interfaces are selected to participate in Interface Mirroring, in either direction, it will initially work as expected but will cease to work after the configuration is reloaded or the BIG-IP system is rebooted.

Note: This issue does not occur when mirroring exclusively between copper interfaces or between fiber interfaces.

In BIG-IP versions 9.4.0 through 9.4.8, the configuration will fail to load with a message that appears similar to the following example:

BIGpipe unknown query error:

01020036:3: The requested interface (2.7) was not found.

In BIG-IP versions 9.4.0 through 9.4.8, you have to set Interface Mirroring State to disabled in order to be able to load the configuration again.

F5 Product Development is tracking this issue as CR104430 for the 9.3.x software branch and as CR103685 for the 9.4.x software branch.

Additionally, this issue was fixed in Hotfix-BIGIP-9.3.1-74.0-HF7 issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

Workaround

While there is no way to prevent this issue, if the BIG-IP configuration was reloaded and you still require to use Interface Mirroring, you may set Interface Mirroring State to disabled and then re-enable it. However, you will re-encounter the same issue if the configuration is reloaded again.
