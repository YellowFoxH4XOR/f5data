Known Issue

This is the result of a known issue. TMM will stop logging syslog messages (including those specified in an iRule using the log command) when it receives an internal ICMP port unreachable message upon sending UDP traffic to the syslog-ng daemon, which listens on the loopback interface.

An error message that appears similar to the following example will be written to the /var/log/messages file:

localhost.localdomain > tmm: icmp: localhost.localdomain udp port syslog unreachable [tos 0xc0]

The ICMP port unreachable message is generated whenever a log message is sent while the syslog-ng daemon is not listening. The syslog-ng daemon may not be listening under any of the following conditions:

  • The syslog-ng daemon is restarted, and has not yet resumed listening.
  • During scheduled daily/weekly/monthly log rotation. (The syslog-ng daemon is restarted during the log rotation process.)
  • Any log file exceeds 2 GB, forcing log rotation.

Once the ICMP port unreachable message is received, syslog-ng logs no further messages until TMM is restarted.

The issue is most likely to manifest during times of heavy logging, since it is triggered by a race condition in which a log message must have been sent during the small interval when the syslog-ng daemon is temporarily not listening. If no log message is sent while the syslog-ng daemon is unavailable, the issue does not occur.

F5 Product Development tracked this issue as ID 334227 and it was fixed in BIG-IP version 9.4.8. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, or WebAccelerator release notes.

Workaround

You can work around this issue by restarting the TMM process. To do so, type the following command at the BIG-IP command line:

bigstart restart tmm

Important: Restarting TMM is the equivalent of performing a restart of the system, and as a result, connections to or through BIG-IP virtual servers may be disrupted. In a redundant pair configuration, restarting TMM will result in a failover.
