Known Issue

The Server/Application State Protocol (SASP) monitor unexpectedly terminates and produces a core file.

This issue occurs when all of the following conditions are met:

  • The BIG-IP configuration contains a resource that uses the SASP monitor.
  • More than one Group Workload Manager (GWM) server, and all servers, are down at the same time.

Impact

When the monitor produces a core file, a pool member is marked down, which may lead to an outage.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You view error messages in the /var/log/ltm file that appear similar to the following example:

    info bigd[<pid>]: Starting saspd, PID: <pid>
    info bigd[<pid>]: reap_child: child process PID = <pid> exited with signal = 6
    info bigd[<pid>]: reap_child: child process PID = <pid> dumped core
    info bigd[<pid>]: saspd process exited, PID: <pid>
  • You view error messages in the /var/log/messages file that appear similar to the following example:

    notice logger: Started writing core file: /var/core/SASPD_monitor.bld675.12.core.gz for PID <pid>
    notice logger: Finished writing 4207267 bytes for core file: /var/core/SASPD_monitor.bld675.12.core.gz for PID <pid>
  • You view a SASPD_monitor core file in the /var/core directory.
