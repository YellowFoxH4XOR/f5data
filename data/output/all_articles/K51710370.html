Description

The BIG-IP ASM System has been configured to set the secure cookie attribute as advised in K13787: Configuring the 'secure' and 'HttpOnly' attributes for BIG-IP ASM cookies, but the TS cookie is missing the "secure" attribute.

Environment

  • cookie_secure_attr parameter enabled
  • ASM service was restarted

Cause

The cookie in question is generated from the ASM policy which is attached to a non-HTTPS Virtual Server.

The secure attribute is advice to a client web browser to only send the specific cookie via HTTPS. By default, ASM does not set the secure attribute in a cookie sent via HTTP.

Recommended Actions

There is an internal parameter assume_https that can be enabled to insert the secure cookie attribute regardless of the protocol (HTTP or HTTPS).

Note: The internal parameter is available starting from BIG-IP versions 12.1.3.2, 13.1.1.4, and 14.0.0.

Impact of procedure: You must restart the BIG-IP ASM service, causing brief traffic disruption.

  1. Log in to bash

  2. To enable the assume_https parameter, type the following command:
    /usr/share/ts/bin/add_del_internal add assume_https 1

  3. To restart the BIG-IP ASM services, type the following command:
    tmsh restart /sys service asm

  4. To verify the services are in the run state, type the following command:
    tmsh show /sys service asm

    The command output appears similar to the following example:
    asm          run (pid 25144) 10 seconds, 2 starts

You can disable the assume_https attribute by repeating the three steps previously listed; however, in step 2, you should substitute the value of 0 for 1.

For example:
/usr/share/ts/bin/add_del_internal add assume_https 0
