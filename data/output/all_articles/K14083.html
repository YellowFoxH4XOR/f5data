K14083: Preventing synchronization when installing a UCS archive on a BIG-IP DNS system

Type
Knowledge
Published
2014-09-18
Updated
2025-06-10
Applies to
  • BIG-IQ
Source

Topic

You should consider using this procedure under the following condition:

  • You want to prevent the BIG-IP DNS (formerly known as BIG-IP GTM) system, such as a Return Materials Authorization (RMA) replacement, from synchronizing the contents of the user configuration set (UCS) archive to the sync group when installing a UCS on a device.

Description

Before installing a UCS archive on a BIG-IP DNS system that will be added to an existing sync group, note the following information:

  • When the BIG-IP DNS system loads the UCS, the MCP daemon generates a new configuration change identifier (commit ID).
  • The new commit ID causes the BIG-IP DNS system to synchronize the contents of the UCS archive to the BIG-IP DNS sync group.

You may like this behavior if you want to install the UCS on a current sync group member and roll the entire BIG-IP DNS sync group back to the configuration contained in the UCS archive.

However, in some cases you may want to install a UCS and prevent the BIG-IP DNS system from synchronizing the contents of the UCS archive to the BIG-IP DNS sync group. For example, if you are installing a UCS on a new device, such as an RMA replacement, you can prevent the system from synchronizing the configuration in the UCS to the sync group. To do so, perform the following procedure:

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have command-line access to the BIG-IP DNS system.
  • You can temporarily disconnect the BIG-IP DNS Traffic Management Microkernel (TMM) switch port interfaces from the production network.

Procedures

Preventing synchronization when installing a UCS archive on a BIG-IP DNS system (11.5.0 and later)

Impact of procedure: The following procedure requires that you temporarily disconnect the BIG-IP DNS system's TMM switch port interfaces from the production network and leave the management interface connected. The goal is to isolate the BIG-IP DNS system from the production network and restore the UCS file. This action prevents the system from potentially synchronizing an older configuration to the sync group.

  1. Physically disconnect the BIG-IP DNS system's TMM switch port interfaces from the network.
  2. Log in to the Configuration utility using the management interface.
  3. Restore the UCS archive.

    Note: For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

  4. After the UCS archive is installed, navigate to DNS > Settings > GSLB > General.
  5. Change the Group Name to a unique value.

    Note: Changing the Group Name ensures that iQuery-connected BIG-IP devices respond to the existing sync group and the device on which you are loading the UCS archive.

    tmsh modify gtm global-settings general synchronization-group-name tempnamehere
  6. Clear the Synchronize check box.  
    tmsh modify gtm global-settings general synchronization no
tmsh modify gtm global-settings general synchronize-zone-files no
  7. Click Update. 
    tmsh save sys config
  8. Reconnect the BIG-IP DNS system's TMM switch port interfaces to the network.
  9. Log in to the BIG-IP DNS command line.
  10. On another GTM in GTM sync group in production, update a non-traffic impacting object, such as a description, so its commit ID (cid.id) is higher than the commit ID on the new RMA device. Note: This prevents the newly added RMA device from syncing an empty configuration to the GTM cluster. 
    tmsh run cm watch-devicegroup-device
    or
    tmsh show gtm iquery
    Note: Check 'cid.id' in tmsh run cm watch-devicegroup-device for device group 'gtm' or 'Configuration Commit ID' in tmsh show gtm iquery for one of GTM devices in GTM sync group.
  11. Add the BIG-IP DNS system to the BIG-IP DNS synchronization group by typing the following command:

    Note: The gtm_add script is interactive, and replaces the BIG-IP DNS configuration on the system on which it is run with the configuration of the remote BIG-IP DNS system in the specified sync group.

    gtm_add <Server IP address of a member of the target GTM synchronization group>

Preventing synchronization when installing a UCS archive on a BIG-IP GTM system (11.0.0 - 11.4.1)

Impact of procedure: The following procedure requires that you temporarily disconnect the BIG-IP GTM system's TMM switch port interfaces from the production network and leave the management interface connected. The goal is to isolate the BIG-IP GTM system from the production network and restore the UCS file. This action prevents the system from potentially synchronizing an older configuration to the sync group.

  1. Physically disconnect the BIG-IP GTM system's TMM switch port interfaces from the network.
  2. Log in to the Configuration utility using the management interface.
  3. Restore the UCS archive.

    Note: For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

  4. After the UCS archive is installed, navigate to System > Configuration > Global Traffic > General.
  5. Clear the Synchronization check box. 
  6. Change the Group Name to a unique value.

    Note: Changing the Group Name ensures that iQuery-connected BIG-IP devices respond to the existing sync group and the device on which you are loading the UCS archive.

  7. Click Update.
  8. Reconnect the BIG-IP GTM system's TMM switch port interfaces to the network.
  9. Log in to the BIG-IP GTM command line.
  10. Add the BIG-IP GTM system to the BIG-IP GTM synchronization group by typing the following command:

    Note: The gtm_add script is interactive, and replaces the BIG-IP GTM configuration on the system on which it is run with the configuration of the remote BIG-IP GTM system in the specified sync group. 

    gtm_add <Server IP address of a member of the target GTM synchronization group>

    Note: After the config copy performed by gtm_add the commit IDs displayed with show gtm iquery will not match until after the first post ucs restore config change is synced across the gtm synchronization group.
