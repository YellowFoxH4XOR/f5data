Known Issue

This is the result of a known issue. The Linux IP routing policy rule forces lookups for processes binding the management address to first consult the management route table (entry number 245). The Linux IP routing policy rule is missing. As a result, traffic ignores the management route when more specific TMM routes are available. Outbound traffic is affected, such as SNMP traps, NTP packets, and syslog packets, which are commonly routed through the management route.

To display the IP routing policy rules that the Linux operating system uses, type the following command:

ip rule show

The correct command output that contains the management route table entry number 245 displays.

For example:

# ip rule show
0: from all lookup local
245: from <mgmt IP address> lookup 245
32766: from all lookup main
32767: from all lookup 253

Note: The <mgmt IP address> is the assigned management IP address of your system.

Affected versions are missing the management route table entry number 245.

For example:

# ip rule show
0: from all lookup local
32766: from all lookup main
32767: from all lookup 253

F5 Product Development tracked this issue as ID 327024 (formerly CR102380) and it was fixed in BIG-IP 11.3.0, and BIG-IP 11.2.1 HF6. For information about upgrading, refer to the BIG-IP LTM, APM, ASM, Edge Gateway, GTM, Link Controller, PSM, WebAccelerator, or WOM release notes.

Note: This issue does not affect BIG-IP 10.0.0 through 11.1.0.

Workaround

You can work around this issue to ensure that the Linux IP routing policy correctly references the management route. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Enter the management route table entry to the running configuration by typing the following command:

    ip rule add priority 245 from <mgmt IP address> lookup 245

    For example:

    ip rule add priority 245 from 10.10.10.10 lookup 245

    Note: You must enter the management route table entry into the /config/startup file to allow the system to reload the entry after a reboot.
  3. Add the IP route corresponding with the route policy by typing the following command:

    ip route add <mgmt_subnet>/<CIDR_netmask> dev eth0 table 245

    For example:

    ip route add 10.10.10.0/24 dev eth0 table 245

    Note: You must enter the management route table entries into the /config/startup file to allow the system to reload the entry after a reboot.
  4. Create a backup of the /config/startup file by entering the following command:

    cp /config/startup /config/startup.SOL9143
  5. Change permissions on the /config/startup file to allow modifications by typing the following command:

    chmod +w /config/startup
  6. Using a text editor, edit the /config/startup file and add one of the following entries at the end of the file:

    For a single system, non redundant configuration

    The following change should only be made to a standalone or single system that is not in a redundant pair configuration. If this change is performed on a system that is in a redundant pair configuration, when a configsync is performed, the change will overwrite the configuration on the peer unit.

    ip rule add priority 245 from <mgmt IP address> lookup 245
    ip route add <mgmt_subnet>/<CIDR_netmask> dev eth0 table 245

    For example:

    ip rule add priority 245 from 10.10.10.10 lookup 245
    ip route add 10.10.10.0/24 dev eth0 table 245

    For systems that are configured as a failover pair (BIG-IP 9.4.5 - 9.4.8 only)

    The following script will configure and update the network entry correctly when used on a redundant pair configuration and the configsync command is used.

    For a BIG-IP configured within a redundant pair, copy the following script to the end of the /config/startup file and replace the following entries in the script with informatin appropriate appropriate to your network information.

    The <your current versions> entry should be in the x.x.x format. For example:

    VERSION=9.4.7

    The <mgmt IP address for unit1> entry should be in the x.x.x.x format. For example:

    UNIT1_MGMT_IP=172.24.65.10

    The <mgmt subnet> entry should be in the xxx.xxx.xxx.xxx/xx format. For example:

    UNIT1_MGMT_NET=172.24.65.0/24

    ##############################################
    # Sol 9143 redundant workaround script
    # Configure the following entries
    # to correspond with your management
    # network settings.

    VERSION=<your current versions>

    UNIT1_MGMT_IP=<mgmt IP address for unit1>
    UNIT1_MGMT_NET=<mgmt subnet>

    UNIT2_MGMT_IP=<mgmt IP address for unit2>
    UNIT2_MGMT_NET=<mgmt subnet>

    ##############################################
    # Do not configure or make changes below here.

    MGMTCheck=1

    case $( sed -n '/^failover/,/^}/s/.*unit \([12]\).*$/\1/p' /config/bigip_base.conf ) in
    1) MGMT_IP=$UNIT1_MGMT_IP
    MGMT_NET=$UNIT1_MGMT_NET
    MGMTCheck=0
    ;;
    2) MGMT_IP=$UNIT2_MGMT_IP
    MGMT_NET=$UNIT2_MGMT_NET
    MGMTCheck=0
    ;;
    *) logger -p local0.notice "/config/startup: Could not determine the Unit ID."
    ;;
    esac

    CURRENT_MGMT_IP=$( grep '^mgmt [0-9]' /config/bigip_base.conf | awk '{ print $2 }' )

    if [ $MGMT_IP != $CURRENT_MGMT_IP ]
    then
    logger -p local0.notice "/config/startup: '$MGMT_IP' does not seem to be the current management IP."
    MGMTCheck=1
    fi

    CURRENT_VERSION=$( uname -r | sed -e 's/.*-//' | cut -d '.' -f 1-3 )

    if [ $VERSION != $CURRENT_VERSION ]
    then
    logger -p local0.notice "/config/startup: Current software version seems to be '$CURRENT_VERSION'. This startup script was configured to run only on $VERSION. Please update /config/startup if necessary."
    MGMTCheck=1
    fi

    if [ $MGMTCheck -eq 0 ]
    then
    ip rule add priority 245 from $MGMT_IP lookup 245
    ip route add $MGMT_NET dev eth0 table 245
    fi
    ##############################################
    # Done with Sol 9143 workaround script
  7. Save the file.
  8. Change permissions on the /config/startup file back to the original settings by typing the following command:

    chmod -w /config/startup

Important: The ip rule and ip route add commands must be removed from the /config/startup file prior to upgrading to a new version of BIG-IP software. This step prevents a possible conflict if any changes are made in later versions. To do so, reverse the changes made in the procedure above, or restore the original startup script by typing the following command:

cp /config/startup.SOL9143 /config/startup
