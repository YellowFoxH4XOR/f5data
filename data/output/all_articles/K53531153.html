Known Issue

Memory can leak if the system calls the STREAM::replace command more than once in the STREAM_MATCHED event within an iRule.

This issue occurs when all of the following conditions are met:

  • The iRule contains a STREAM_MATCHED event.
  • The STREAM::replace command is called more than once within the iRule.

Impact

Minimal memory is leaked, eventually causing the system to run out memory, resulting in a system restart and traffic disruption.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system leaks minimal memory each time you invoke the iRule.
  • When you use the following tmctl command, the cur_allocs for memory_usage_stat output increases each time you invoke the iRule.

    tmctl -w128 memory_usage_stat | egrep "^filter|allocated| -"

Resolution

Workaround

To work around this issue, F5 recommends, if possible, that you change the way the iRule is written so that the STREAM::replace command is not called more than once in the iRule's STREAM_MATCHED event.
