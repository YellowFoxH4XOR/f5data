Known Issue

In rare circumstances, the TMOS Shell (tmsh) command does not correctly handle absence of an input stream after closing interactive SSH sessions and remains active in an infinite loop using the equivalent of 100% CPU.  For this to occur, tmsh must be a process group leader. 

This issue occurs when all of the following conditions are met:

  • tmsh is a process group leader.
  • The parent SSH shell is terminated.

Impact

The equivalent of one CPU core is utilized to 100% by the tmsh process. It may be scheduled on one core or spread over multiple control plane cores, which may cause a CPU bound performance impact on the BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe the process list tmsh command using 100% of CPU.  You can see this using a command such as top.
  • The BIG-IP system performance may be degraded.

Workaround

To work around this issue, you can manually stop the offending tmsh processes. To do so, perform the following procedure:

Impact of workaround: The following procedure should have no negative impact on the BIG-IP system. 

Important:  The tmsh process should never be intentionally promoted to a process group leader.

  1. Log in to the BIG-IP host as the root user.
  2. Stop all tmsh processes with the following command:

    Note: This procedure stops all tmsh processes on the system, not just abandoned ones.

    killall -9 tmsh

    If you are able to identify the process ID (PID) of the specific tmsh process utilizing excessive CPU, you can stop only this process by using the following command syntax:

    kill -9 <PID>

    Note: <PID> is the process ID you want to stop.
