Description

You want to know how to check the High Availability (HA) status of BIG-IQ using the Command Line Interface (CLI), specifically the goal is to identify which node is set as Primary and which one is set as Secondary. While this can be confirmed through the Graphical User Interface (GUI), this is not possible via CLI.

Environment

  • BIG IQ High Availability 
  • BIG-IQ CLI
  • ElasticSearch

Cause

Working as expected. There are BIG-IP daemons in BIG-IQ that are not in use, an example of this are the pacemaker and quorum daemons. The HA status is not visible through the CLI because the BIG-IP daemons, specifically pacemaker and quorum, which are responsible for managing HA status in BIG-IP, do not interact with ElasticSearch. ElasticSearch underpins the HA functionality of these daemons, and without direct communication between these components, the HA status cannot be displayed in the CLI environment.

 

Recommended Actions

You can retrieve the HA status in CLI by making a REST API call.

1. First, acquire an authentication token to enable access to ElasticSearch within BIG-IQ by executing the following command in the bash shell by using the admin credentials:

 curl -sk -X POST https://localhost/mgmt/shared/authn/login -d '{"username":"<My_Admin_User>", "password":"<My_Admin_Pass"}' | jq .

2. Next, utilise the obtained token to make a request for the HA status of the device with:

 curl -k -H "X-F5-Auth-Token: <My_Token>" https://localhost/mgmt/shared/failover-state | jq .

After that you should be able to see the HA status of the BIG-IQ in question.

 

Additional Information

Connecting via CLI to a BIG-IQ in HA will not show who's the Primary or who's the Secondary, the CLI will look like the following:

[root@bigiq-cm1:Active:Standalone] config #
