K37827528: SNMP traps for certificate expiration are missing

Type
Support Solution
Published
2021-06-17
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K37827528

Description

  • Users not receiving the emails about the certificate expiration.
  • You are not able to see the expected logs about expired certificates in /var/log/ltm when you run the command,
tmsh run sys crypto check-cert

  • Expected logs,

01420007:4: Certificate 'CN=example.com,OU=EXAMPLE CA,O=EXAMPLE Internet,C=US' in file /Common/example.crt expired on Jan 1 23:00:00 2016 GMT

01420008:4: Certificate 'CN=SOL15288testcert.com,C=US' in file /Common/SOL15288testcert.crt will expire on <date>

Environment

  • BIG-IP is configured to send SNMP traps per K15288.
  • BIG-IP is configured with a syslog filter that is sending the logs to a remote server.

Cause

If the syslog filter is using a remote publisher the logs will be forwarded to the configured remote server, you can use the below command to confirm the current configured syslog filters,

tmsh list sys log-config filter

Recommended Actions

In order to workaround this issue you can pick up one of the next options,

  1. Remove the syslog filter,
tmsh delete sys log-config filter <remote-syslog-filter-name>
  1. A local log-config filter can be created to matches a specific message-id and transmits it to the local-syslog log publisher.
From the CLI enter following commands:
  
tmsh create /sys log-config publisher local-syslog destinations add { local-syslog }
tmsh create /sys log-config filter filter_cert_will_expire message-id 01420008 publisher local-syslog
tmsh create /sys log-config filter filter_cert_expired message-id 01420007 publisher local-syslog
