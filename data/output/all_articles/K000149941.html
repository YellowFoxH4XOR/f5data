K000149941: Large UCS backup file caused by EPSEC (EndPoint Security) files from previously provisioned APM module

Type
Support Solution
Published
2025-02-24

Applies to

  • BIG-IP APM: 17.0.0, 17.1.1, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2

Source

Description

Large UCS backup file due to EPSEC (EndPoint Security) files, resulting from a previously provisioned but now de-provisioned APM module.

Once the APM module is provisioned, an APM Endpoint Security (EPSEC) reference and image is automatically made available for use by the APM module.

However, when the APM module is de-provisioned, the default EPSEC image, along with any subsequently installed EPSEC images and their references, are not automatically removed, which can result in larger UCS files for future creations.

Environment

  • APM (De-provisioned)
  • UCS archive
  • LTM

Cause

The presence of outdated / unnecessary EPSEC ISO image files contributed significantly to the size of UCS archives, particularly when APM was de-provisioned.

   ID 557470: (RFE) Delete Epsec related config when APM is de-provisioned

Recommended Actions

The officially supported procedure for reducing the size of the UCS file is to re-provision the APM module, following the steps in K21175584 to remove unnecessary OPSWAT EPSEC images from the BIG-IP APM system, and once the removal is complete, proceeding with de-provisioning the APM module.

Note: The procedure outlined above enables the removal of all subsequent EPSEC system images, except for the default EPSEC image, which will continue to consume approximately 200 to 300MB in future UCS file creations. Manual EPSEC file removal and trial adjustments to the bigip.conf file could be attempted, but this is not advised (nor supported) as it carries the risk of unintended outcomes.
