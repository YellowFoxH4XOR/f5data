Description

You observed the below error message in the F5 Container Ingress Service(CIS) logs.

Error log [ERROR] [CORE] Ingress class resource not found

Environment

  • F5 Container Ingress Service(CIS, formerly known as Container Connector)
  • Required IngressClass resource is missing in the Kubernetes cluster.

Cause

The CIS instance will output the log when it does not find the required IngressClass.

Recommended Actions

This log indicates the required IngressClass is missing, so it is recommended to create the correct IngressClass. You may refer to the below YAML configuration examples to create the IngressClass based on your requirements. Please note that if you set the IngressClass as your default Ingress Controller, all Ingress resources without an ingressClassName field specified will be assigned this default IngressClass.

For the scenario where you want the CIS to be the default Ingress Controller:

apiVersion: networking.k8s.io/v1
kind: IngressClass
metadata:
  name: f5
  annotations:
    # Set the annotation as true to make CIS default ingress controller of k8s cluster
    ingressclass.kubernetes.io/is-default-class: "true"
spec:
  # Provide the controller name as "f5.com/cntr-ingress-svcs"
  # Warning: don't change the controller name as cis verify the controller name while processing the ingress resource
  controller: f5.com/cntr-ingress-svcs

For the scenario where you do NOT want the CIS to be the default Ingress Controller:

apiVersion: networking.k8s.io/v1
kind: IngressClass
metadata:
  name: f5
spec:
  # Provide the controller name as "f5.com/cntr-ingress-svcs"
  # Warning: don't change the controller name as cis verify the controller name while processing the ingress resource
  controller: f5.com/cntr-ingress-svcs

To validate if there is an existing IngressClass in your cluster, you may use the below command.

kubectl get ingressclasses

Additional Information

As per the Kubernetes documentation on the Ingress object describes as below, all Ingress resources without an ingressClassName field specified will be assigned to the default IngressClass:
Ingresses can be implemented by different controllers, often with different configurations. Each Ingress should specify a class, a reference to an IngressClass resource that contains additional configuration including the name of the controller that should implement the class.
You can mark a particular IngressClass as default for your cluster. Setting the ingressclass.kubernetes.io/is-default-class annotation to true on an IngressClass resource will ensure that new Ingresses without an ingressClassName field specified will be assigned this default IngressClass.
