Issue

Error Message

warning tmm[<PID>]: 011e0002:4: Aggressive mode <policy> <action> (<context>) (<flows>)

In this error message, note the following:

  • <PID> is the process ID for the tmm process
  • <policy> is the partition and name of the eviction policy that was triggered (11.6.0 and later)
  • <action> is either activated or deactivated
  • <context> is the context to which the eviction policy is associated (11.6.0 and later)
  • <flows> is the number of affected connection flows

For example:

  • 11.6.0 and later

    warning tmm3[11944]: 011e0002:4: sweeper_segment_cb_any: Aggressive mode /Common/default-eviction-policy activated (3000000000000) (vs /Common/vs_example). (12/12 flows)

  • 11.5.x and earlier

    warning tmm1[4625]: 011e0002:4: sweeper_update: aggressive mode activated. (244147/287232 pages)

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file
Description

This message occurs when all of the following conditions are met:

  • The log.sweeper.activation.enabled database variable is set to true (default).
  • Aggressive mode is either activated or deactivated for adaptive connection reaping.

You can associate the BIG-IP adaptive connection reaping feature in a global context, or in the context of a virtual server or route domain. When the aggressive sweeper reaches its threshold, the BIG-IP system generates this message and reaps connections as needed.

Impact

The adaptive connection reaper continues to reap connections while memory use or connection flows exceed activation thresholds.

Recommended Actions

When the system generates this error message, consider performing the following actions:

  • This message may indicate an overloaded virtual server or a high traffic load to the BIG-IP system. To mitigate this issue, you can reduce the traffic load to the affected virtual server or reduce overall traffic to the BIG-IP system. You may also be able to mitigate this issue by modifying the parameters in the eviction policy or by changing eviction policies.

    Note: F5 does not recommend modifying the default eviction policy. If you want non-default values, you should create a custom eviction policy.

  • In BIG-IP 12.0.0 and later, you can suppress this message by executing the tmsh modify /sys db log.sweeper.activation.enabled value false command. The adaptive connection reaper will still reap connections; however, the system will no longer generate this message.
