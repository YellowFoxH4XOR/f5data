Topic

The VIPRION system is composed of a chassis and one to eight blades. Each blade is a self-contained system consisting of a base motherboard and a mezzanine switchboard. All installed blades form a cluster, which behaves and is administered as a single BIG-IP system. When the cluster initializes, one blade is determined to be the primary blade and all other blades are secondary blades. In addition to processing traffic like other blades, the primary blade is a management blade, which sets and maintains the configuration for the whole cluster.

While each blade is assigned an individual management IP address used to access the blade directly, a floating management IP address is also present to facilitate management of the cluster using the primary blade. This IP address, which is also known as the cluster management IP address, is always owned by the primary blade. The IP address ensures that when a BIG-IP Administrator connects to the IP address, the administrator is connecting to the primary blade, regardless of which blade is currently the primary blade.

Important: If the services are stopped on all blades in a cluster you will not be able to connect to the cluster management IP address.

When a blade is required to send traffic out of its management interface, you should consider the following information regarding the source IP address determination process:

  • Management traffic sourced from the primary blade will use the cluster management IP address as the source IP address. When a blade is the primary blade, the cluster management IP address has precedence over the blade’s individual management IP address.

    Important: In BIG-IP 9.6.0 through 11.1.0, management traffic sourced from the VIPRION primary blade may use the incorrect source IP address. For more information, refer to K11716: Management traffic sourced from the VIPRION primary blade may use the incorrect source IP address.

  • Management traffic sourced from secondary blades will use the blade’s individual management IP address. This address is the only management IP address available to secondary blades.

For example, when executing the ping command from the primary blade, if the routing table determines that the traffic should leave from the management interface, the cluster management IP address will be used by default as the source IP address of the Internet Control Message Protocol (ICMP) packets. When the same process is executed on a secondary blade, the blade’s individual management IP address will be used.

Note: The VIPRION system does not differ from other BIG-IP platforms in how the routing table determines whether to use the management interface or TMM (switch ports). For more information, refer to K3669: Overview of management interface routing.

The bulleted information may be relevant when a network administrator is required to configure access lists on a firewall or router that the VIPRION system will transverse with its management traffic. Likewise, any application performing source IP address filtering (for example, an Active Directory server used by the VIPRION system for remote authentication) should account for the same considerations.

Note: For more information about configuring management IP addresses on the VIPRION system, refer to the Configuring cluster-related IP addresses section in the VIPRION Systems: Configuration manual.
