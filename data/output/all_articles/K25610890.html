Description

Normally the Endpoint Inspector will only download / install a new OPSWAT EPSEC package in first session connection with client security check.
When this issue happened, the client will download / install the OPSWAT EPSEC package every session, maybe see the "User Account Control" alert.
In the client log file logterminal.txt, the log may like:

SINSTALLER, 0,,,, finished writing file, start installation
SINSTALLER, 48, \service.cpp, 1673, InstallControlCAB(), enter, C:\Users\<Username>\AppData\Local\Temp\f5tmp\OesisInspector.cab
SINSTALLER, 0,,,, inside user mode service - prompt user for consent
SINSTALLER, 48, \urSmartUpdateEx.cpp, 2290, USmartUpdateEx::VerifyCABEx(), WINTRUST_FILE_INFO (pcwszFilePath), C:\Users\<Username>\AppData\Local\Temp\f5tmp\OesisInspector.cab

Environment

  • BIG-IP APM
  • Client security checks configured
  • updated to OPSWAT OESIS package version later than 1.0.0.892

Cause

There was a change to the code signing certificates used for Windows in ID 825049.
This epsec-1.0.0-900.0 installation fails because the client doesn't have the new key. 

Recommended Actions

Before updating the OPSWAT OESIS package on the BIG-IP APM, you should ensure the BIG-IP and APM Clients versions are supported by the EPSEC pagage being installed.

You can verify the supported minimum versions by referring to the readme_minimum_version.txt file included in the OPSWAT release notes on downloads.f5.com.

For example, the readme_minimum_version.txt for the epsec-1.0.0-900.0 indicates the following minimum versions:

BIG-IP 15.1.0.2 or later
BIG-IP 15.0.1 or later and APM Clients 7.1.8.3 or later
BIG-IP 14.1.2 or later and APM Clients 7.1.8.3 or later
BIG-IP 13.1.3 or later and APM Clients 7.1.8.3 or later
BIG-IP 12.1.5.1 or later
