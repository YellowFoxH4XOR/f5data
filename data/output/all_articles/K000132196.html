K000132196: UDP and TCP Traceroute packets are dropped by the default Management Interface firewall rules

Description

  • Traceroute to the management IP address using UDP or TCP will be dropped by default starting in v14
  • Traceroute using ICMP is still allowed

Environment

  • BIG-IP running v14 or higher
  • ICMP, TCP, UDP

Cause

The default Management Interface Firewall Rules were updated in v14 to block most UDP and TCP ports.

 

 Recommended Actions

Use one of the following methods to resolve the issue:

 

  • Add a Management Interface Firewall rule to allow UDP and TCP traceroute ports via the command line:

tmsh modify /security firewall management-ip-rules rules add { traceroute-udp { action accept ip-protocol udp place-before first destination { ports add { 33434-33534 } } } }

 

tmsh modify /security firewall management-ip-rules rules add { traceroute-tcp { action accept ip-protocol tcp place-before first destination { ports add { 33434-33534 } } } }

 

  • Add a Management Interface Firewall rule to allow the traceroute traffic via the Configuration Utility:

1. Log in to the Configuration utility.
2. Go to System > Platform.
3. Select the Security tab.
4. To create a new rule, select Add.
5. Add the appropriate rules
 

  • Force traceroute to use ICMP (traceroute -I)

 

Additional Information 

  • If you have a deny-all rule in your management firewall, you must explicitly allow ICMP if you want ICMP traceroute to work (see K000138223 for v15.1.9+).
  • The tmsh commands use a placeholder for ports. For traceroute, the default UDP ports are typically 33434-33534, but you should specify the actual port range as needed for your environment.
