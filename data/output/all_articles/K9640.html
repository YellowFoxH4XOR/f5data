K9640: Portal Access NTLM authentication does not support the WWW-Authenticate: Negotiate HTTP header

Known Issue

This is the result of a known issue. When a user accesses a web application requiring NTLM authentication through Portal Access, FirePass may report an error message that appears similar to the following example:

Error
FirePass server could not handle the request GET <URL>.
Reason: can't handle request

Note: The URL field is the URL the user attempted to access.

This issue occurs when the back-end web server sends the WWW-Authenticate: Negotiate header, but not the WWW-Authenticate: NTLM header in the HTTP response. The correct behavior is for FirePass to perform NTLM authentication when the WWW-Authenticate: Negotiate header is sent in the HTTP response, regardless of whether the WWW-Authenticate: NTLM header is also sent.

Note: When this issue occurs, FirePass displays the same error message regardless of whether valid logon credentials were provided.

Most modern web servers send both the WWW-Authenticate: Negotiate header and the WWW-Authenticate: NTLM header when NTLM authentication is required. However, some web servers send only the WWW-Authenticate: Negotiate header.

F5 Product Development tracked this issue as CR114919 and it was fixed in FirePass version 6.1.0. For information about upgrading, refer to the FirePass release notes.

This issue has been fixed in cumulative hotfix HF-603-1 issued for FirePass version 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by configuring your web server to send the Authenticate: NTLM HTTP header in addition to the WWW-Authenticate: Negotiate HTTP header.
