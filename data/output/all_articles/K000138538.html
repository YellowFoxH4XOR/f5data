K000138538: Mcpd audit log messages are truncated at 8192 bytes

Type
Support Solution
Published
2024-02-08
Updated
2024-02-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.0.0, 16.0.X, 16.0.1, 17.X.X, 16.X.X, 17.1.X, 17.1.1, 17.1.0, 17.0.X, 17.0.0, 16.1.X, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0
Source
https://my.f5.com/manage/s/article/K000138538

Description

When audit logging is enabled, configuration changes are logged to the /var/log/audit file, however there is a 8K (8192 byte) limit to the size of these messages, meaning that if a larger mcp object is modified, the audit log message related to that change may be truncated.

Note that there is a similar, but distinctly different, issue related to audit messages of objects containing carriage returns (typically irules) - see ID842669, which can give the appearance of the log message being truncated earlier than 8192 bytes.
 

Environment

  • BIG-IP 16.x - 17.x

Cause

This is due to a known bug ID1281661


Recommended Actions

Create smaller mcp objects that are able to be expressed completely in less than 8192 bytes. 

For example, consider multiple smaller APM ACL objects, all attached to the same apm policy, rather than one large ACL.

For LTM, consider using different policies with a few rules attached to a Virtual Server instead of one big policy with multiple rules.

This BUG affects audit logs only. APM/ASM/GTM logs are not affected.
