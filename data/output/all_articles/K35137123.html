Known Issue

Applying a BIG-IP APM User Connectivity License (CCU) add-on license fails to change original CCU license limits.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is deployed in a high availability (HA) configuration.
  • Your BIG-IP APM systems are licensed with a base BIG-IP APM license.
  • You apply a CCU add-on license to BIG-IP APM devices.

Impact

The licensed CCU value does not change.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H663861 on the Diagnostics > Identified > Medium|High page.
  • After applying a CCU add-on license, the licensed CCU value reflects the original base BIG-IP APM license value.
  • When total CCU sessions surpass the original BIG-IP APM CCU license limit, the BIG-IP system logs error messages similar to the following example to the /var/log/apm file:

    warning tmm1[16201]: 01490508:4: 3b533fac: Global concurrent connectivity session limit reached.

  • When total CCU sessions surpass the original BIG-IP APM CCU license limit, the BIG-IP system displays an error message similar to the following example to users who attempt to establish an access session.

    Your session could not be established.

    The maximum number of concurrent user sessions has been reached. No new user sessions can start at this time.

Workaround

To work around this issue, you can restart the Traffic Management Microkernel (TMM) service. To do so, perform one of the following procedures:

  • Correcting the CCU license limits for BIG-IP APM 12.0.0 and later
  • Correcting the CCU license limits for BIG-IP APM versions prior to 12.0.0

Correcting the CCU license limits for BIG-IP APM 12.0.0 and later

The following procedure is required to correctly apply the CCU add-on license for BIG-IP APM 12.0.0 and later.

Impact of workaround: Restarting TMM causes the BIG-IP system to drop all current connections. You should perform this action only during a maintenance window.

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    tmsh restart /sys service tmm

Correcting the CCU license limits for BIG-IP APM versions prior to 12.0.0

You must perform the following procedures to correctly apply the CCU add-on license for BIG-IP APM versions prior to 12.0.0.

Impact of workaround: During this workaround, your BIG-IP devices will experience a temporary offline state where traffic will not be processed by either of the HA devices. You should perform this action only during a maintenance window.

  • Forcing one of the HA peer devices offline
  • Removing the HA failover configuration
  • Reactivating the license of device one
  • Forcing the second unit offline
  • Releasing the offline state of the first device
  • Reactivating the license of the second device
  • Reconfiguring the HA configuration

Forcing one of the HA peer devices offline

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Devices.
  3. Click on the name of the local device.
  4. Click Force Offline.
  5. Click OK.

Removing the HA failover configuration

  1. Navigate to Management > Device Groups.
  2. Click the name of the failover device group.
  3. In Configuration section for Members, click each device fully qualified domain name (FQDN) in the Includes and move >> to Available.
  4. Click Update.

Reactivating the license of device one

  1. Navigate to System > License.
  2. Click Re-activate.
  3. Select the appropriate Activation Method for your environment.

Forcing the second device offline

  1. Navigate to Device Management > Devices.
  2. Click on the name of the local device.
  3. Click Force Offline.
  4. Click OK.

Releasing the offline state of the first device

  1. Navigate to Device Management > Devices.
  2. Click on the name of the local device.
  3. Click Release Offline.
  4. Click OK.

Reactivating the license of the offline second device

  1. Navigate to System > License.
  2. Click Re-activate.
  3. Select the appropriate Activation Method for your environment.

Reconfiguring the HA configuration

  1. Navigate to Management > Device Groups.
  2. Click the name of the failover device group.
  3. In Configuration section for Members click each of the original peer device FQDNs in the Available and move << to Includes.
  4. Click Update.
