K000089976: Health monitor duplicated in each server block. Excessive health Monitor Traffic

Type
Support Solution
Published
2021-07-18
Updated
2021-08-04
Source
https://my.f5.com/manage/s/article/K000089976

Description

After applying a Health Monitor to a Work Group in one component, the dataplane generates a large amount of traffic to the Work Group.

Environment

  • A configuration with multiple gateways.
  • Nginx Controller versions 3.13 to 3.18.1 inclusive

 

Cause

The Controller incorrectly configures a health monitor in all gateways.

This is evident by examining the nginx.conf file generated on the dataplane.
Example:

Simplified nginx.config file

   }

   server {

       server_name wanted.local; ++GATEWAY++


++APPLIED HERE++

       location = /_health_check_Wanted_pool_1.1.1.1_http_765e7405-5fd8-4f8b-bb2c-dc5c96bac58d {

           internal;

           proxy_set_header Host $host;

           proxy_set_header Connection '';

           health_check interval=5 fails=1 passes=1 uri=/health-check.html;

           proxy_pass http://Wanted_pool_1.1.1.1_http_765e7405-5fd8-4f8b-bb2c-dc5c96bac58d;

       }


   }

   server {

       server_name dont_crappon_me.local; +GATEWAY++


++UNWANTED COPY APPLIED HERE++

     

       location = /_health_check_Wanted_pool_1.1.1.1_http_765e7405-5fd8-4f8b-bb2c-dc5c96bac58d {

           internal;

           proxy_set_header Host $host;

           proxy_set_header Connection '';

           health_check interval=5 fails=1 passes=1 uri=/health-check.html;

           proxy_pass http://Wanted_pool_1.1.1.1_http_765e7405-5fd8-4f8b-bb2c-dc5c96bac58d;

       }


   }

When the configuration has a large number of gateways, the duplicated configuration will generate a large amount of traffic, impacting the Work Group servers.

Recommended Action

This is resolved in version 3.18.2 and later. The fixed configuration is sent when you next edit your Components.
