K000134827: ASM Server Technology Detection may cause delay of non-standard Web service

Type
Support Solution
Published
2023-06-15
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP ASM: 14.X.X, 14.1.X, 14.1.5, 14.1.4, 14.1.3, 14.1.2, 14.1.0, 14.0.X, 14.0.1, 14.0.0
Source
https://my.f5.com/manage/s/article/K000134827

Description

When enabling the "Server Technology Detection" feature on ASM, you may experience latency issues in the application as ASM accumulates the entire body before transmitting it to the client. While capturing packets on ASM, you may observe abnormal behavior from the backend web server, which responds to the HTTP body first before sending the HTTP response header.

Environment

  • Delay response
  • Server Technology Detection 

Cause

This is expected behavior. The Server Technology Detection feature depends on the HTTP response code and content-type value, before the ASM receives the HTTP response header, it will accumulate the entire body. According to RFC2616, the Web Server should respond to the HTTP header first, then send the HTTP body.

 Recommended Actions

This compatibility issue arises due to the non-standard behavior of the backend web server. Please consult with the backend web server engineer to rectify the abnormal behavior, including adjusting the server's response and complying with the RFC2616, to ensure that the HTTP header is sent before the HTTP body. Alternatively, if resolving the abnormal behavior is not feasible, disabling the Server Technology Detection feature on ASM may be considered as a workaround.
