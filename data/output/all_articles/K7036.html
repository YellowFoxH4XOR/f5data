Known Issue

This is the result of a known issue. BIG-IP versions 9.0.0 through 10.0.1 use the Linux version 2.4 kernel. The kernel computes the system uptime based on the internal jiffies counter, which counts the time since boot in units of 10 milliseconds, or jiffies. In Linux version 2.4, the counter is a 32-bit counter, which has a maximum value of 2^32, or 4,294,967,296. When the counter reaches this value (after 497 days, 2 hours, 27 minutes, and 53 seconds, or approximately 16 months), it wraps back around to zero and continues to increment.

Note: For more information, refer to K3645: Base operating system information for the BIG-IP Host system.

F5 Product Development tracked this Linux issue as CR74550, and it was fixed in BIG-IP version 10.1.0 and in Enterprise Manager version 2.0 with implementation of the Linux 2.6 kernel that uses a 64 bit jiffies counter, which is capable of counting for millions of centuries before wrapping back to zero. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

This issue still affects FirePass.

When the jiffies counter wraps, you may observe the following side effects:

  • The ps (Process Status) command may report incorrect TIME values for daemons that were running at the time of the counter wrap
  • The Linux uptime command and other time related commands may no longer report the correct values
  • Some processes that depend on accurate elapsed time calculations may be adversely affected, as detailed in the following Solutions:

K7071: SCCP kernel driver i2c read failure

K8087: SCCP kernel driver timer wrap may cause system component health misreadings (FirePass only)

K9679: The lacpd daemon stops sending LACP messages after 497 day linux uptime wraparound

K9683: The gtmd, tmm, or bcm56xxd daemons may crash after 497 day linux uptime wraparound

K10311: The performance graphs no longer display data after 497 day linux uptime wraparound

Note: These are the only known side effects of the uptime counter wrapping. The issues documented in these Solutions have been patched as noted therein. If you encounter issues that seem related but are not documented here, contact F5 Technical Support.

Determining system uptime

Determining system uptime may require different procedures depending upon your platform and whether the jiffies counter has already wrapped. The Linux uptime command will report the correct uptime if the jiffies counter has not yet wrapped. However, if the system has been up for more than 497 days, the Linux uptime command will be affected by the counter wrapping and will not reflect the system's actual uptime. To authoritatively determine whether the system has been up for more than 497 days, you can calculate the difference between the datestamp of the /var/log/ksysms.0 file, which is created when the system is booted, and the date reported by the system clock, which is not affected by the jiffies counter wrap.

Using the Linux uptime command

If your system has been up for less than 497 days, you can use the Linux uptime command to determine how soon you should schedule a preventive reboot. The uptime command produces output that appears similar to the following example:

19:52:48 up 20 days, 9:24, 1 user, load average: 0.09, 0.05, 0.11

Note: For platforms with SCCP, run the uptime command while logged into the SCCP. To determine if your platform uses SCCP, refer to K9476: The F5 hardware/software compatibility matrix.

However, if the system has been up for more than 497 days, the Linux uptime command may be affected by the counter wrapping and may not reflect the system's actual uptime. To determine whether the system has been up for more than 497 days, you can examine the datestamp of the /var/log/ksysms.0 file, which is created when the system is booted.

Important: If your system has been up for longer than 497 days, or you are not sure how long the system has been up, do not rely on the output of the uptime command. Instead, refer to the following sections for procedures to authoritatively determine how long the system has been up.

Calculating uptime on non-SCCP systems

On non-SCCP systems, use the following command to determine the number of days since the last boot time:

echo $[(`date +%s` - `ls -l --time-style +%s /var/log/ksyms.0 | awk '{print $6}'`) / 86400]

The command returns an integer value indicating the number of full days the system has been up. For example, if the current date is Fri Sep 18 12:14:49 PDT 2009 and the datestamp of the /var/log/ksysms.0 file is Jun 26 10:54, the system has been up for approximately 84 days, 1 hour, 20 minutes, and the echo command returns 84, indicating the system has been up for 84 full days.

Calculating uptime on SCCP systems

On SCCP systems, perform the following procedure:

  1. Log in to the SCCP.
  2. To determine the current date expressed as the number of seconds since the last UNIX epoch, type the following command:

    date +%s

  3. Exit the SCCP to the TMM command prompt.
  4. To determine the datestamp of the /var/log/ksyms.0 file expressed as the number of seconds since the last UNIX epoch, type the following command:

    ls -l --time-style +%s /var/log/ksyms.0 | awk '{print $6}'

  5. Subtract the second value from the first to obtain the number of seconds the system has been up.
  6. Divide the result by 86,400 (the number of seconds in a day) to determine the number of days the system has been up.

Note : To determine if your platform uses SCCP, refer to K9476: The F5 hardware/software compatibility matrix

Workaround

You can avoid this issue by rebooting the system prior to the 497 day counter wrap.

  1. Log in to the BIG-IP command line.
  2. Reboot the system by typing one of the following commands:
    • For platforms with SCCP:
       
      • BIG-IP versions 9.1.2, 9.1.3, 9.2.4 and later

        full_box_reboot

      • BIG-IP versions 9.0.0 through 9.1.1 and 9.2.0 through 9.2.3

        touch /.sccp_hard_reboot ; reboot
    • All other platforms:

      reboot
Note: To determine if your platform uses SCCP, refer to K9476: The F5 hardware/software compatibility matrix.
