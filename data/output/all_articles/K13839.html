Known Issue

If a user attempts to access a web page with a URL that contains a colon (:) port separator with no port defined, the web page will fail to load.

For example, the following page would fail to load:

http://www.example.com:

The FirePass reverse proxy content rewrite ensures that HTTP requests are routed through the FirePass interface. When the reverse proxy engine encounters a colon in a URL, and the port information is not defined, the proxy substitutes a 0 (zero) for the port. RFC1738 states that the colon should not be included unless the port is defined. Modern web browsers work around this issue by substituting a default of port 80 that masks the error in the originating HTML data.

Impact

The web page may fail to load or may partially load.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Users may receive the following error message, where <http request> is the the HTTP request that is missing the port information:

    Error FirePass server could not handle the request <http request>
    Reason: Error while connect: Connection timed out.

Workaround

Ensure the web server generating the web page is not including the port separator colon or is supplying port information.
