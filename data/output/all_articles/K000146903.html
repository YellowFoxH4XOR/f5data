K000146903: Why am I getting response code - csrf_origin_mismatch ?

Type
Support Solution
Published
2024-11-08
Updated
2025-03-03
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000146903

Description

  • You enabled Cross-Site Request Forgery Protection (CSRF) and default configuration
  • You see multiple 403 Forbidden and rsp_code - csrf_origin_mismatch

Environment

  • F5® Distributed Cloud HTTP Load Balancer

Answer/Recommended Actions

  • Instead of using All HTTP Load Balancer Domains, use Specified domains
  • If you have multiple domains as above you could protect them all or a subset of the domains by specifying which domains you would allow as the Source Domain.

Cause

  • If "rsp_code_details" is "csrf_origin_mismatch"  and CSRF is enabled, we compare the value of origin header against a list of allowed domains.
  • If origin is not there WAF engine blocks the request. 

Additional Information

  • How the POST or PUT requests are being set?
  • Do you have the Origin or Referer header set? 
    • And does that match what is set in the CSRF policy?
      • ELSE - we'll get a 403 - if the request is forbidden due to the CSRF Policy?
        • Do you see any 403's because of CSRF? csrf_origin_mismatch
