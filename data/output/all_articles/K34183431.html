K34183431: BIG-IP ASM security policy removes CORS headers when Cross-Domain Request Enforcement is "Disabled"

Type
Knowledge
Published
2019-05-28
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP ASM: 14.1.0
Source
https://my.f5.com/manage/s/article/K34183431

Issue

Description

After you upgrade to BIG-IP ASM 14.1.0, web pages which are protected by a security policy and require Cross-Origin Resource Sharing (CORS) access-control headers show a blank page or are blocked in some browsers.

Browsers that do not load the page may show errors similar to the following examples when debugging using developer tools:

  • Chrome browser

    Access to XMLHttpRequest at 'https://targetsubdomain.domain.com/cors/page' from origin 'https://originsubdomain.example.com' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.

  • Firefox browser

    Access-Control-Allow-Origin and Access-Control-Allow-Credentials headers are missing and thus impacting the provided service

Environment

  • Upgraded to BIG-IP ASM 14.1.0
  • Application web page uses CORS HTTP headers
  • HTML5 Cross-Domain Request Enforcement set to disabled for the URL in the security policy

Cause

BIG-IP ASM strips the Access-Control-Allow-* headers from the server's response. F5 Product Development tracks this issue as ID 746394.

Recommended Actions

To resolve this, you should do one of the following actions:

  • Enable and configure HTML5 Cross-Domain Request Enforcement in the URL configuration in the security policy
  • Enable Cross-Domain Request Enforcement and add the required CORS subdomains. For more information, refer to the Setting Up Cross-Domain Request Enforcement chapter of the BIG-IP Application Security Manager: Implementations manual. 

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  • Create an iRule to save the headers so they can be re-added after the BIG-IP ASM system modifies the response using the following iRules stanza:

    when HTTP_RESPONSE {
    array set header_list { }
    foreach header_name [HTTP::header names] {
    if { [string tolower $header_name] starts_with "access-control-" } {
    set header_list($header_name) [HTTP::header $header_name]
      }
     }
    }
    when HTTP_RESPONSE_RELEASE {
    foreach header_name [array names header_list] {
    if {!([HTTP::header exists $header_name])} {
    HTTP::header insert $header_name $header_list($header_name)
      }
     }
    }
