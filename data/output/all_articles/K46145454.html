Known Issue

Configuration synchronization (ConfigSync) operations fail when a private key is encrypted with a passphrase and is imported into the FIPS card.

This issue occurs when all of the following conditions are met:

  • The BIG-IP configuration contains a private key that is encrypted with a passphrase, and the key is imported into the FIPS card.
  • You attempt to perform a ConfigSync operation.

Impact

The ConfigSync operation fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The ConfigSync operation fails.
  • You observe error messages similar to the following examples:
    • In the Configuration utility:

      01070712:3: Passphrase specified, but key (/Common/import-pass2.key) is not protected.

    • In the /var/log/ltm file:

      err mcpd[6211]: 01071488:3: Remote transaction for device group /Common/device-group-failover-0483365bb90f to commit id 200 6337003435460891188 /Common/bigip2.localdomain 0 failed with error 01070712:3: Caught configuration exception (0), Passphrase specified, but key (/Common/import-pass2.key) is not protected

Workaround

To avoid this issue, you should ensure that private keys that are meant to be imported to the FIPS card are not encrypted with a passphrase.

To work around the issue, you can remove the passphrase from the encrypted private key before importing to FIPS. For instructions, refer to the Removing a passphrase from an encrypted private SSL key procedure in K14912: Adding and removing encryption from private SSL keys (11.x - 13.x).
