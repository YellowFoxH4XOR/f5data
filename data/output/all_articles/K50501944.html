Topic

This article provides information about data-gathering tools you can use to identify potential causes of Network Access failure events.

You should consider using this procedure under the following conditions:

  • You have a BIG-IP system with the BIG-IP APM module licensed and provisioned.
  • You have configured BIG-IP APM Network Access resources.
  • You are unable to connect to the tunnel or access configured resources and want to gather troubleshooting data for analysis.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Configuration utility and the command line.

Procedures

Use the following procedures to gather diagnostic data on the BIG-IP APM system:

Note: Before attempting to reproduce an issue, close all existing connections to the Network Access virtual servers, including any clientless connections such as Outlook Anywhere, Autodiscover, and Outlook Web Access (OWA).

  • Enabling and disabling access policy debug logging
  • Generating packet captures
  • Decrypting packet captures using pre-master secret keys
  • Decrypting packet captures using private keys
  • Gathering diagnostic data

Enabling and disabling access policy debug logging

To enable the debug logging level, perform the following procedure:

Impact of procedure: Setting the logging level to debug increases access policy logging. You should only perform this procedure when troubleshooting.

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs > Configuration > Options.
  3. Scroll down to Access Policy Logging.
  4. In the Access Policy list, click Debug.
  5. Click Update.

To disable debug logging and revert to the default setting once troubleshooting is complete, repeat steps 1 through 3, click Notice in the Access Policy list for the logging level in step 4, and click Update.

Generating packet captures on the BIG-IP APM system

Impact of procedure: Performing the following procedure should not have a negative impact the system.

  1. Log in to BIG-IP Advanced shell (bash).
  2. You can capture traffic by specifying the 0.0 interface or the connectivity profile in use by the virtual server.

    To capture network access traffic between the client and the virtual server, specify the 0.0 interface using the following command syntax:

    tcpdump -ni 0.0:nnn -s0 host <virtual_server_IP> -w /path/to/capture_file

    For example, if the virtual server IP address is 172.16.10.10 and you want to send the output to the /var/tmp/NetworkAccess.pcap file, type the following command:

    tcpdump -ni 0.0:nnn -s0 host 172.16.10.10 -w /var/tmp/NetworkAccess.pcap

    To capture network access application traffic to the server by specifying the connectivity profile, use the following command syntax:

    tcpdump -ni <connectivity_profile> -s0 -w /path/to/capture_file

    For example, if the connectivity profile is named my_connect and you want to send the output to the /var/tmp/NetworkAccess.pcap file, type the following command:

    tcpdump -ni my_connect -s0 -w /var/tmp/NetworkAccess.pcap

  3. Log in to the client system and reproduce the issue by attempting to access Network Access resources through the virtual server. First, close all browsers to prevent capturing resumed SSL sessions.
  4. After you reproduce the issue, stop tcpdump by typing Ctrl+C at the command line. The output of tcpdump appears in the /var/tmp/NetworkAccess.pcap file.
  5. After you complete troubleshooting, return the access policy logging level to Notice using the Enabling and disabling access policy debug logging procedure.

Decrypting packet captures using pre-master secret keys

Impact of procedure: Performing the following procedure should not have a negative impact the system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List and click the name of the virtual server configured for Network Access.
  3. Scroll down to SSL Profile (Client) and identify the profile in use.
  4. Navigate to Local Traffic > Profiles > SSL > Client and click the name of the profile you identified in the previous step.
  5. Under Configuration, for Certificate Key Chain, identify the value for the Key setting in the profile. You will match this value to the key file in the following steps.
  6. Log in to the command line and type the following command to open the /config/filestore/files_d/Common_d/certificate_key_d/ directory:

    cd /config/filestore/files_d/Common_d/certificate_key_d/

  7. Identify the key file name associated with the value for the Key setting from the previous step. For this example, test.org.key_1.
  8. Generate a pre-master secret (PMS) key log file using the following command syntax:

    ssldump -r /path/to/tcpdump_capture_file -k /path/to/private_key -M /path/to/pre-master-key_log_file

    For example, to create a PMS key log file named NetworkAccess.pms using the NetworkAccess.pcap capture file and the test.org.key_1 key file, type the following command:

    ssldump -r /var/tmp/NetworkAccess.pcap -k /config/filestore/files_d/Common_d/certificate_key_d/\:Common\:test.org.key_1 -M /var/tmp/NetworkAccess.pms

  9. You can now upload the resulting NetworkAccess.pms file and the NetworkAccess.pcap file to a packet-analysis tool, such as Wireshark, to view the decrypted data without the need for the server's private key.

Decrypting packet captures using private keys

Note: You should securely store private SSL keys. You should not gather private keys when collecting diagnostic data for troubleshooting.

Impact of procedure: Performing the following procedure should not have a negative impact the system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List and click the name of the virtual server configured for Network Access.
  3. Scroll down to SSL Profile (Client) and identify the profile in use.
  4. Navigate to Local Traffic > Profiles > SSL > Client, and click the name of that profile in the list.
  5. Identify the value for the Key setting in the profile. You will match this to the respective key file in the next steps.
  6. Log in to bash.
  7. Type the following command to change to the /config/filestore/files_d/Common_d/certificate_key_d/ directory:

    cd /config/filestore/files_d/Common_d/certificate_key_d/

  8. Identify the key file name associated with the value for the Key setting from the previous step. For this example, test.org.key_1.
  9. Decrypt the tcpdump capture file using the following command syntax:

    ssldump -AdenN -r /path/to/tcpdump_catpure_file -k /path/to/private_key > /path/to/output_file

    For example:

    ssldump -AdenN -r /var/tmp/NetworkAccess.pcap -k /config/filestore/files_d/Common_d/certificate_key_d/\:Common\:www.site.com.key_1 > /var/tmp/NetworkAccess.txt

  10. The resulting NetworkAccess.txt file contains the decrypted traffic, which you can analyze to help determine the cause of the issue.

Gathering the diagnostic data

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

After you reproduce the issue and generate packet captures, you can gather the diagnostic data into one place for future analysis. To do so, perform the following procedure:

  1. Log in to bash.
  2. Create a new directory for the diagnostic files by typing the following command:

    mkdir /var/tmp/diag_files

  3. Copy the packet capture files and the PMS file to the new directory by typing the following command:

    cp /var/tmp/NetworkAccess.pcap /var/tmp/NetworkAccess.pms /var/tmp/NetworkAccess.txt /var/tmp/diag_files/

  4. Generate a tarball file of the log files by typing the following command:

    tar -czvf /var/tmp/diag_files/logfiles.tar.gz /var/log/*

    Note: This command creates a file named logfiles.tar.gz in the newly created directory.

  5. Generate a tech.out diagnostic file by typing qkview at the command line.

    Output appears in the /var/tmp/ directory.

  6. Move the qkview output to the newly created directory using the following command syntax:

    mv /var/tmp/<hostname>.qkview /var/tmp/diag_files

    For example:

    mv /var/tmp/bigip.example.com.qkview /var/tmp/diag_files
