Topic

If you have a Windows 2000 system and try to use Netscape or Internet Explorer to upload files that are 2.5 MB or larger through BIG-IP, the upload is limited to approximately 40K per second. This symptom occurs on connections to the SSL proxy or any self IP address.

This problem is caused by a compatibility issue between some clients and the delayed acknowledgement feature enabled, by default, on BIG-IP.

Delayed acknowledgement

Delayed acknowledgment is a standard (RFC2581 located at http://www.ietf.org/rfc/rfc2581.txt), commonly used method to optimize TCP throughput and avoid traffic congestion. By delaying acknowledgement (ACK) packets, the number of small, ACK-only packets that are generated by the TCP recipient are minimized. The receiver may delay acknowledgments until one of the following circumstances occurs:

  • Two packets, with payload size equal to the MSS for that connection, are received.
Or
  • 500 milliseconds (maximum allowed by RFC) from the arrival of the first unacknowledged packet has elapsed.

The result is that an ACK packet is generated for every 2 MSS bytes of data received in exactly two packets, or at least every 500 milliseconds, regardless of the volume of data or number of packets received.

By default, delayed acknowledgment is enabled on BIG-IP for connections to:

  • SSL proxy

  • Any TCP connection to a self-IP (for example, used for access through SSH or the Configuration utility)

This is set as a default, because for the majority of connections, delayed acknowledgment increases TCP throughput by 10 to 20 percent.

The symptoms of this problem occur relatively infrequently, but can happen when a client connected to an SSL proxy, or any TCP service on any self-IP, sends a TCP packet with the PSH flag set, and the payload size less than MSS, and stops sending additional packets until it receives acknowledgement for the small PSH packet. In this situation, the client will experience up to a 200-millisecond delay in traffic flow.

The delay is caused by the delayed acknowledgment timeout, which is set to 200 milliseconds on BIG-IP.

In most cases, this behavior occurs with SSL connections, because some SSL clients send a PSH packet after every 8K bytes of data. If the 8K limit is not aligned with the MSS limit, the client has to send less than MSS-sized TCP packets with the PSH flag set.

The issue is not a flaw in the BIG-IP TCP/IP stack; it is a design decision, which, in the vast majority of cases, allows an increase of effective TCP throughput and helps avoid network congestion.

Workaround

Beginning in BIG-IP 4.5 PTF-05, you can disable delayed acknowledgement by enabling the tcp_delack_disabled internal variable.

Important: Do not change an internal variable unless you are aware of, and accept, the risks outlined in K920: Overview of internal variables.

This global setting influences all TCP connections to any self IP address and SSL proxy. Disabling this setting will dramatically increase TCP throughput to broken clients (broken clients are relatively rare) and decrease throughput to healthy clients by approximately 10 to 20 percent.

To globally disable delayed acknowledgments, type the following command:

bigpipe internal set tcp_delack_disabled = 1

Type the following command to save the change:

echo "/sbin/bigpipe internal set tcp_delack_disabled = 1" >> /etc/rc.local

Note: This global setting has no affect on traffic to virtual servers or traffic passing through a NAT or SNAT.
