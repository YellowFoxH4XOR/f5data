Known Issue

This is the result of a known issue. When specifying a rule for the snap-recon.pl snapshot reconstitution script, if the specified report directory contains reports from other snapshot rules, the script will fail with an error message that appears similar to the following example:

No matching snapshots found.
Please check the names supplied to the --namespace, --volume, and --rule filter switches.

For example, refer to the following command:

./snap-recon.pl --report-dir /acopia/reports/--namespace <NAMESPACE NAME> --volume /<VOL NAME> --rule MySnapshotRule1

If the /acopia/reports directory contains reports for a snapshot rule other than the MySnapshotRule1 rule, the script will fail.

F5 Networks Product Development tracked this issue as ARX ID 37771 and it was fixed in ARX version 5.1.5. For information about upgrading, refer to the ARX Release Notes.

Note: F5 Networks Product Development is tracking another issue under ARX ID 37771. For information, refer to K11169:The snap-recon.pl snapshot reconstitution script does not read .rpt report files.

Workaround

When using a snapshot rule with the snap-recon.pl script, ensure the report directory specified only contains files for the snapshot rule.

For the following command example, you would only place the reports for MySnapshotRule1 into the /acopia/reports directory:

./snap-recon.pl --report-dir /acopia/reports/--namespace <NAMESPACE NAME> --volume /<VOL NAME> --rule MySnapshotRule1
