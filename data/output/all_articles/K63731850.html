Description

A TCP capture indicates that there could be an issue wth SNI or that SSL handshake is failing.

Environment

  • BIG-IP v15.x
  • Error message (var/log/tmm)
    warning tmm1[22254]: 01260009:4: 192.0.2.1:20434 -> 10.0.0.1:443: Connection error: ssl_hs_rxhello:10784: alert(70) unsupported version

Cause
The captured SSL - Client Hello looks as it should:

Frame 12: 720 bytes on wire (5760 bits), 720 bytes captured (5760 bits)
Ethernet II, Src: <MAC>, Dst: <MAC>
802.1Q Virtual LAN, PRI: 0, DEI: 0, ID: 4094
Internet Protocol Version 4, Src: <IP>, Dst: <IP>
Transmission Control Protocol, Src Port: 2780, Dst Port: 443, Seq: 1, Ack: 1, Len: 520
Transport Layer Security
    TLSv1.2 Record Layer: Handshake Protocol: Client Hello
        Content Type: Handshake (22)
        Version: TLS 1.2 (0x0303)
        Length: 515
        Handshake Protocol: Client Hello
            Handshake Type: Client Hello (1)
            Length: 511
            Version: TLS 1.2 (0x0303)


... but, going further into the frame we see:
 

            Extension: supported_versions (len=3)
                Type: supported_versions (43)
                Length: 3
                Supported Versions length: 2
                Supported Version: TLS 1.3 (0x0304)


The incoming client connection is actually trying to connect using TLS v1.3.
And the default "clientssl" profile in BIG-IP v15.1.3 has no TLS v1.3 by default:

     
options { dont-insert-empty-fragments no-tlsv1.3 }

 

Recommended Actions

  • Enable TLSv1.3, you can do this by following the instructions in the article K10251520
or
  • Change the client to use TLSv1.2

Additional Information
If you decide to enable TLSv1.3 some attention to ciphers may be needed, since TLSv1.3 in BIG-IP can use only a smaller set of special ciphers (one of which is TLS13-AES128-GCM-SHA256).
