Known Issue

This is the result of a known issue. When the client sends a close_notify alert to a BIG-IP clientssl virtual server before closing the write side of the Secure Sockets Layer (SSL) connection, the BIG-IP system fails to respond with a close_notify alert. Instead, the BIG-IP system sends a TCP FIN packet. According to RFC2246, Section 7.2.1, each party in the SSL session is required to send a close_notify alert before closing the write side of the connection.

This issue occurs even if the Unclean Shutdown setting is disabled in the clientssl profile, and irrespective of whether the Strict Resume setting is enabled.

F5 Product Development tracked this issue as CR104465 and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-9.4.8-407.0-HF4 issued for BIG-IP 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
