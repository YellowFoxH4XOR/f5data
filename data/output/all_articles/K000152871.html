K000152871: Using existing policy as a template to deploy or create new security policies via WebUI and REST API

Type
Support Solution
Published
2025-08-04
Updated
2025-08-04
Applies to

Source

Description

Existing security policies can be used as a Policy Template for future policy creation or deployments. This article covers the steps on how to accomplish that via both WebUI and REST API.

Environment

  • BIG-IP ASM provisioned and running 15.x, 16.x or 17.x release
  • Desire to export or create existing security policy as a Policy Template and use that template for future security policy deployments

Cause

N/A.

Recommended Actions

  • Creating a Policy Template and creating the new Security Policy using the template via WebUI
  • Creating a Policy Template and creating the new Security Policy using the template via REST API

Creating a Policy Template and creating the new Security Policy using the template via WebUI

  1. Navigate through to Security ›› Options : Application Security : Advanced Configuration : Policy Templates section and select Create option.
  2. Specify a unique name for this new policy template, let Template File option use the Use existing security policy dropdown option and subsequently select the security policy from the dropdown that needs to be used as a template. Upon specifying that, select Create option.
  3. Once the policy template is created, navigate through to Security ›› Application Security : Security Policies : Policies List section and select Create option.
  4. Under the policy's General Settings section, locate the Policy Template option and select the newly created template from step #2 under the dropdown list. Configure any other policy configuration settings in this section as desired and then select Save to create the policy.

 

Creating a Policy Template and creating the new Security Policy using the template via REST API

The following steps can be used to create a new Policy Template using an existing security policy and then use that template for creating new policies via REST API. Replace the credentials and device hostname or management IP in these commands respectively:

1. Extract the security policy's name and REST UUID:

# curl -k -u ${BIGIP_USER}:${BIGIP_PASS} -H "Content-Type: application/json" "https://${BIGIP_MGMT}/mgmt/tm/asm/policies/?\$filter=name+eq+test_policy" 2>/dev/null | jq '.items[] | {name, id}'

Note: Replace "test_policy" with your desired policy name.

 

2. Extract the security policy's REST UUID and save it to a variable:

# POLICY_UUID=$(curl -k -u ${BIGIP_USER}:${BIGIP_PASS} -H "Content-Type: application/json" "https://${BIGIP_MGMT}/mgmt/tm/asm/policies/?\$filter=name+eq+test_policy&\$select=id" 2>/dev/null | jq -r '.items[].id')

Note: Replace "test_policy" with your desired policy name.

 

3. Create the policy import task:

# curl -k -u ${BIGIP_USER}:${BIGIP_PASS} -H "Content-Type: application/json" "https://${BIGIP_MGMT}/mgmt/tm/asm/tasks/import-policy-template/" -X POST -d '{"name" : "test_policy_template", "policy": "test_policy", "policyReference": {"link": "https://localhost/mgmt/tm/asm/policies/'${POLICY_UUID}'"}}' 2>/dev/null | jq .

Note: Replace "test_policy_template" with a unique template name of your choice. Make note of the template's REST UUID from the "selfLink" field in this output, as that will be used in the next step.

 

4. Confirm that the task was completed:

# curl -k -u ${BIGIP_USER}:${BIGIP_PASS} -H "Content-Type: application/json" "https://${BIGIP_MGMT}/mgmt/tm/asm/tasks/import-policy-template/tSEiPD7RyKihX93QhnwHtg" 2> /dev/null | jq .

Note: Ensure that you replace "tSEiPD7RyKihX93QhnwHtg" with the respective the policy template's REST UUID that was observed in the "selfLink" field within step #3. Make note of the status field in this command's output is set to COMPLETED.

 

5. Once the policy template import task has been completed, you can verify the template configuration:

# curl -k -u ${BIGIP_USER}:${BIGIP_PASS} -H "Content-Type: application/json" "https://${BIGIP_MGMT}/mgmt/tm/asm/policy-templates/?\$filter=name+eq+'test_policy_template'" 2> /dev/null | jq .

Note: Substitute the "test_policy_template" with the unique policy template name that was provided in step #3

 

6. This policy template can now be used to create new security policies by using this user-defined template and leveraging this template's API reference:

# curl -k -u ${BIGIP_USER}:${BIGIP_PASS} -H "Content-Type: application/json" "https://${BIGIP_MGMT}/mgmt/tm/asm/policies/" -X POST -d '{"name" : "API_policy", "templateReference": {"link" : "https://localhost/mgmt/tm/asm/policy-templates/NI2cDyYeszrEEixYUeIMdA", "title" : "test_policy_template"}}' 2>/dev/null | jq .

Note: Replace "API_policy" with the desired name for your new security policy and substitute the appropriate reference for the policy template that was returned in the output for step #5 along with specifying your policy template's name that was used in step #3.
