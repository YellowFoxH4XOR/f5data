Description

When follow the article like K41600007 or K08485455, create the iRule to insert the SNI in the serverside TLS handshake, it will cause the VMWare Horizon client cannot access the RDP server.
Meanwhile, we can see the follow error log in the /var/log/ltm:

err tmm[PID]: 01220001:3: TCL error: /Common/<Irule name> <SERVERSSL_CLIENTHELLO_SEND> - can't read "sni_value": no such variable     while executing "string length $sni_value"

Environment

  • BIG-IP APM
  • Virtual server
  • Access profile
  • VMWare Horizon RDP resource
  • VMWare Horizon client

Cause

When APM access the VMWare Horizon server, some TLS connection are not HTTPS, cannot get the value for SNI, cause the iRule cannot work, and TLS handshake fail, TCP connection reset.

Recommended Actions

Please edit the iRule to avoid this error, verify the SNI existed before insert the SNI extension, for example:

when REWRITE_REQUEST_DONE {
  #log local0. "HOST: [HTTP::host]"
  set sni_value [getfield [HTTP::host] ":" 1]
}
when SERVERSSL_CLIENTHELLO_SEND {
  # SNI extension record as defined in RFC 3546/3.1
  #
  # - TLS Extension Type                =  int16( 0 = SNI )
  # - TLS Extension Length              =  int16( $sni_length + 5 byte )
  #    - SNI Record Length              =  int16( $sni_length + 3 byte)
  #       - SNI Record Type             =   int8( 0 = HOST )
  #          - SNI Record Value Length  =  int16( $sni_length )
  #          - SNI Record Value         =    str( $sni_value )
  # verify the SNI value existed.
  # Calculate the length of the SNI value, Compute the SNI Record / TLS extension fields and add the result to the SERVERSSL_CLIENTHELLO
 if {[info exists sni_value]} {
   SSL::extensions insert [binary format SSScSa* 0 [expr { [set sni_length [string length $sni_value]] + 5 }] [expr { $sni_length + 3 }] 0 $sni_length $sni_value]
 }
}
