Description

Using unsupported characters on an HTTP profile at version 13.x and 14.0.x is allowed, once the unit is upgraded to version 14.1.x and higher,  the following error is encountered during configuration load:

01070744:3: Configuration error: HTTP Fallback, Status: item 1 text '-': is not a valid rfc2616 status.

Environment

  • HTTP Profiles
  • Upgrading from 13.x and 14.0.x to 14.1.x or higher.

Cause

An Enhancement was introduced on v14.1.x and upwards, which contained a massive clean up on profiles and surrounding code.

Recommended Actions

  • Prior to Upgrading an Appliance to a version that is after 14.1.x, review your http profiles that use a "-" on the fallback-status-codes:

    # list /ltm profile http fallback-status-codes

    Go to the Configuration Utility, navigate to Configuration Utility >> "Local Traffic" Tab >> "Profiles"  >> "Services" >> "http" on the open menu or select Services. Go to the target http profile(s), locate the Fallback on Error Codes and edit the lines accordingly by removing the "-" signs and leave only blank spaces between codes.

    NOTE: After this, the upgrade should run without errors, if you upgraded with the error and rolled back to correct the profiles, do not forget to select yes on the Install Configuration Option at the "Boot locations" tab.
     
  • In case the unit has been upgraded and you're facing the error on the target version, you can correct the bigip.conf file and remove the unauthorized "-" characters from the problematic http profiles. 

    First backup the bigip.conf file:
    #cp /config/bigip.conf /config/bigip.conf.K22201116

    Then look for the culprit profiles:
    # grep fallback-status-code bigip.conf

    Use a file editor and remove the "-"  characters and leave a blank space between codes, save and write the file.

    Now load the configuration:
    #tmsh load sys config

    Upon load, another issue may appear, when entering the appliance via Configuration Utility, the following banner appears Configuration not loading with banner error message "This device is not operational because the loaded configuration contained errors or unlicensed objects. Please adjust the configuration and/or the license, and re-license the device.  This issue is fixed by restarting the mcpd process, you can follow the solution on the article below:

    K13223635: Configuration not loading with banner error message "This device is not operational because the loaded configuration contained errors or unlicensed objects. Please adjust the configuration and/or the license, and re-license the device.

Additional Information

For example:

Prior to upgrade steps:

  1. #list /ltm profile http fallback-status-codes

    ltm profile http http-test1 {
        fallback-status-codes { 404 500 503 }
    }
    ltm profile http http-test2 {
        fallback-status-codes { 404 - 500 - 503 }
     
  2. Go to the Configuration Utility >> "Local Traffic" Tab >> "Profiles"  >> "Services" >> "http". Select "test2", locate the Fallback on Error Codes line and edit the lines by removing the "-" signs and leave only blank spaces between codes, like test1.
If upgrade failed and the configuration load on new version failed:
  1. #cp /config/bigip.conf /config/bigip.conf.K22201116
     
  2. grep fallback-status-code bigip.conf

    [root@new-bug-id-bigip1:Active:Standalone] config # grep fallback-status-code bigip.conf
        fallback-status-codes { 404 500 503 }
        fallback-status-codes { 404 - 500 - 503 }
     
  3. vim /config/bigip.conf and modify the fallback-status-codes.
     
  4. If the following error is met when logging via Configuration Utility, bigstart restart MCPD:
    #bigstart restart mcpd
The unit should be successfully upgraded.
