Known Issue

A Virtual Clustered Multiprocessing (vCMP) guest may fail to load a configuration that uses a non-zero high availability (HA) group trunk threshold value.

This issue occurs when all of the following conditions are met:

  • You have multiple vCMP guests in an HA configuration.
  • You set the HA group trunk on the vCMP guest with a threshold value greater than zero.
  • You perform one of the following actions:
    • You roll forward the BIG-IP configuration by upgrading the vCMP guest to an affected software version listed in the Applies to (see versions) box, located in the upper-right corner of this article.
    • You take a user configuration set (UCS) backup prior to the upgrade and attempt to load the UCS on the vCMP guest manually after you boot into the affected software version.

Impact

The vCMP guest may fail to upgrade or restore the BIG-IP configuration from a previous UCS backup due to the HA group trunk threshold value. In addition, you cannot set the HA group trunk threshold value of a vCMP guest to a non-zero value on the affected software version.

Note: Setting the HA group trunk threshold to 0 disables the HA group trunk configuration altogether.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H614068 on the Diagnostics > Identified > High screen.
  • The vCMP guest fails to load the BIG-IP configuration after a software upgrade or a UCS restore.
  • You view an error message in the /var/log/ltm file that appear similar to the following example:

    err tmsh[<PID>]: 01420006:3: Loading configuration process failed.
    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all base" - failed. -- 01071569:3: Ha group ha_group threshold for trunk <trunk_name> 1 is greater than the maximum number of members 0. Unexpected Error: Loading configuration process failed.

  • The vCMP guest running the affected software version is not configured with an HA group trunk threshold value greater than zero, with an error message in the /var/log/ltm file that appears similar to the following example:

    err mcpd[<PID>]: 01071569:3: Ha group ha_group threshold for <trunk_name> 1 is greater than the maximum number of members 0.

Workaround

You can recover the system by manually editing the /config/bigip_base.conf file to set the HA group trunk threshold to 0 and reloading the configuration. To do so, perform the following procedure:

Note: Setting the HA group trunk threshold to 0 disables the HA group trunk configuration altogether.

Impact of workaround: Performing the suggested workaround will disable the HA group trunk configuration. As a result, the vCMP guest in an HA configuration will not trigger a failover, even if all the trunk members configured in the HA group trunk are down.

  1. Log in to the BIG-IP command line.
  2. Create a backup copy of the /config/bigip_base.conf file by typing the following command:

    cp /config/bigip_base.conf /config/bigip_base.conf.K84539934

  3. Edit the /config/bigip_base.conf file using the text editor of your choice.
  4. Locate the stanza for the HA group setting.

    For example:

    sys ha-group ha-trunk {
         trunks {
             my_trunk {
                 threshold 1
                 weight 10
             }
        }
    }

  5. Search for the line that includes the threshold value and modify the threshold value to 0.

    For example:

    sys ha-group ha-trunk {
         trunks {
             my_trunk {
                 threshold 0
                 weight 10
             }
        }
    }

  6. Save the changes and exit the text editor.
  7. Reload the configuration by typing the following command:

    tmsh load /sys config

    The configuration should reload successfully.
