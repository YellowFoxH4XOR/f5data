K10815273: Security logging profile didn't take effect after changes

Description

After modifying the security logging profile from the virtual server, the new security logging profile is not taking effect. The event logs are still sent to the old log server which is defined in the old security logging profile.

Example modifications using the Configuration utility to a virtual server that may trigger the issue:

  • Virtual Server > Security > Policies, add "Log all requests" Log Profile to the virtual server and save.
  • Virtual Server > Security > Policies, remove "Log all requests" Log Profile from the virtual server, add "Log illegal requests" Log Profile and save.

Environment

  • BIG-IP ASM/AWAF
  • Security logging profile
  • Event logs

Cause

Bug ID 941853: Logging Profiles do not disassociate from the virtual server when multiple changes are made

Recommended Actions

Upgrade to a fixed version as specified in Bug ID 941853.

Alternatively, if you have few virtual servers on BIG-IP, and you know which virtual server has this kind of issue, you can perform each Log Profile change individually as described below:

  1. Log in to BIG-IP GUI, enter to virtual server logging profile configuration page.
  2. Remove the current association security logging profile and update.
  3. Add the new association security profile and update again.
If you have lots of virtual servers that have issues, and it is hard to change one by one, you may restart the asm service to make the new security logging profile take effect:
  1. Log in to BIG-IP ASM command line.
  2. Restart the asm service with the following tmsh command:

tmsh restart sys service asm

Important: This procedure will cause a temporary traffic disruption while the BIG-IP ASM process restarts.
You should failover the device to standby first, then perform this procedure and do this during a scheduled maintenance period.
