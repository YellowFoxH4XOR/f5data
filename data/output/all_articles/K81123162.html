Topic

You should consider using these procedures under the following conditions:

  • NGINX Controller stopped updating the nginx.conf files on the managed NGINX Plus instances.
  • You want to update the NGINX Plus configuration by manually modifying the nginx.conf file.

Important: You should use this procedure for troubleshooting purposes only. Manually updating nginx.conf files may result in configuration inconsistencies between NGINX Controller and its managed instances.

Description

Under normal circumstances, you should not update the nginx.conf files on NGINX Plus instances that are managed by NGINX Controller. Manually editing the nginx.conf file on managed instances may adversely affect system performance. In most cases, NGINX Controller reverts or overwrites manual updates made to the nginx.conf file.

However, if NGINX Controller isn't pushing updates to the nginx.conf files, manually updating the file may be required for troubleshooting or applying workarounds. After users manually edit the nginx.conf files, the related components in NGINX Controller may appear to go into an invalid state in the browser interface and API; there's no harm if this happens.

This article describes the procedures for manually updating NGINX Plus instance configuration files when NGINX Controller is down and restoring the linked components to valid status after NGINX Controller is functional.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have a valid user account to access the NGINX system.

Procedures

  • Manually update the configuration on the Controller-managed NGINX Plus instance
  • Recover the application components from an invalid state after the Controller functionality is restored

Manually update the configuration on the Controller-managed NGINX Plus instance

When NGINX Controller is down and unable to push the configuration changes to the managed NGINX Plus instance, you can manually change the configuration by editing the nginx.conf file on the NGINX Plus instance. To do so, perform the following procedure:

Impact of procedure: The procedure changes the nginx.conf file locally on the NGINX Plus instance and the related components in NGINX Controller may result in an invalid state after the communication with NGINX Controller is restored.

  1. Log in to the command line of the NGINX Plus system.
  2. To change to the directory where the nginx.conf file is located, enter the following syntax:

    cd <file_directory>

    Note: Depending on the system, the configuration file can be located in the /usr/local/nginx/conf, /etc/nginx, or /usr/local/etc/nginx directories.

  3. Back up the configuration file by entering the following command:

    sudo cp -a nginx.conf nginx.conf.backup

  4. Edit the nginx.conf file using a text editor of your choice.

    For example:

    vi nginx.conf

  5. Save the changes and exit the editor.
  6. To check the new configuration for syntactic validity and reload NGINX Plus, enter the following command:

    nginx -t && nginx -s reload

Recover the application components from an invalid state after the Controller functionality is restored

When NGINX Controller functionality is restored, you must update the components in NGINX Controller to the desired state and then push the configuration. Pushing the configuration overwrites the manual edits with the desired changes and reestablishes NGINX Controller as the source of truth. After the configuration is pushed, the components appear healthy again in the user interface. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure pushes and overwrites the configurations on the Controller-managed NGINX Plus instance. 

  1. Log in to the user interface of the NGINX Controller system.
  2. Go to Services.
  3. Make corresponding changes to the apps and services that were previously modified manually on the NGINX Plus instance.
  4. To submit the changes and overwrite the existing configuration on the NGINX Plus instance, select Submit.
  5. Verify that the component's health status is restored.
