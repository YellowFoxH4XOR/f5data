Topic

For clients to authenticate with an ARX system's CIFS front-end service using Kerberos authentication, the appropriate Server Principal Name (SPN) must be associated with the computer object representing that ARX system's global server in the Active Directory of the Microsoft Windows Server Domain Controller (DC).  An SPN, which is included as part of the ticket request, must exist on the DC that matches the hostname specified by the client. Otherwise, the DC cannot determine for which computer the client is requesting a Kerberos ticket.

For example, if clients are failing to authenticate when specifying a Windows Internet Name Service (WINS) name or a WINS Alias name that you have just created on the ARX, or when specifying the virtual server's IP address, they would receive an error message that appears similar to the following example:

\\AskF5VIP-Alias is not accessible. You might not have permission to use this network resource. Contact the administrator of this server to find out if you have access permissions. The security database on the server does not have a computer account for this workstation trust relationship.

Additionally, a corresponding warning message logs to the error.log file on your ARX system that appears similar to the following example:

2008-06-25T23:14:39.672+0000:AskF5ARX:1-1-ACM-18873:VCIFS-1-4-KRBINTEGRITY:: Failed to authenticate user from address 10.0.0.2 to CIFS service AskF5VIP.AskF5.com. The client PC may have a stale ticket cache (reboot the client and retry). If this error persists, the domain controller and switch's secret key may be skewed (you must re-execute the domain-join for the affected CIFS service to reestablish a new secret key).

This failure occurs because the hostname that the client specified is not a registered SPN on the DC.

Resolution

On the DC, you can work around this issue by using the setspn utility to:

  • Check whether the desired server name is missing from the SPN list on the DC.
  • Add the desired server name to the SPN list, if necessary.

Note: The setspn utility is a Microsoft utility that should be present on a DC. Refer to your vendor and your product documentation to confirm that the examples presented in this Solution are valid for your server.

Displaying the SPN list

To list all of the SPNs associated with a computer, perform the following procedure:

  1. Open a command window on the DC.
  2. Use the following command syntax:

    setspn -L <computer name>

    Note: In the command, <computer name> is the name of the computer object in your domain's Active Directory. For our purposes, that is the name of the virtual server on the ARX system. 

    The output will appear similar to the following example:

    C:\>setspn -L AskF5VIP
    Registered ServicePrincipalNames for CN=AskF5VIP,CN=Computers,DC=AskF5,DC=com:
      CIFS/AskF5VIP.AskF5.com
      CIFS/AskF5VIP
      HOST/AskF5VIP.AskF5.com
      HOST/AskF5VIP

If the hostname that your clients are specifying does not appear with a CIFS entry in this list, you must add one using the following procedure.

Adding an SPN to the list

To add an SPN to the list, perform the following procedure:

  1. Open a command window on the DC.
  2. Use the following command syntax:

    setspn -A CIFS/<SPN> <computer name>

    Note: In the command, <SPN> is the hostname that the clients are trying to authenticate, and <computer name> is the name of the computer object in your domain's Active Directory.

    The command output will appear similar to the following example:

    C:\>setspn -A CIFS/AskF5VIP-Alias AskF5VIP
    Registering ServicePrincipalNames for CN=AskF5VIP,CN=Computers,DC=AskF5,DC=com:
             CIFS/AskF5VIP-Alias
    Updated object
