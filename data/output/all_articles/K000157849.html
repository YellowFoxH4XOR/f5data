K000157849: Directives limit_conn_zone and limit_conn in configuration do not seem to limit

Description

After implementing directives limit_conn_zone and limit_conn in NGINX [Plus] configuration, network traffic through NGINX [Plus] does not limit connections as expected. Example configuration:

http {
  geo $limited {
    default 1;
    1.1.1.10/32 0;
  }
  map $limited $limit {
    1 $binary_remote_addr;
    0 "";
  }
  limit_conn_zone $limit zone=addr:10m;
  limit_conn addr 5;
}

Environment

NGINX [Plus]

Cause

This can occur when a proxy service exists in front of NGINX [Plus]. The source ip address for ingress traffic to NGINX [Plus] will be that of the proxy server and not the expected ip address of user-agents. Therefore, the geo directive will never match on the expected user-agent ip address and limit_connection_zone key ($limit) will always evaluate to nil.

Recommended Actions

To resolve this, implement the proxy special parameter into the geo directive configuration.

Example configuration:

http {
  geo $limited {
    proxy 2.2.2.0/24;
    1.1.1.10/32 1;
    default 0;
  }
  map $limited $limit {
    1 $binary_remote_addr;
    0 "";
  }
  limit_conn_zone $limit zone=addr:10m;
  limit_conn_zone $binary_remote_addr zone=default:10m;
  limit_conn addr 20;
  limit_conn default 100;
}

The proxy parameter within the geo directive configuration specifies trusted ip addresses. When requests match these addresses, an address from the requests' "X-Forwarded-For" request header will be used instead (by default, geo evaluates $remote_addr). Refer to the NGINX geo documentation for more information.

Additional Information

Documentation for limit_conn_zone and limit_conn

In the Recommended Actions example above, requests from user-agent 1.1.1.10/32 that are proxied, or not, by an address within address space 2.2.2.0/24 will be limited by limit_conn_zone addr ($limit evaluates to $limited which evaluates to 1). All requests are limited by limit_conn_zone default. Since the connections threshold for limit_conn_zone default (100) is greater than that of limit_conn_zone addr (20), requests that come from 1.1.1.10/32 will be limited by limit_conn_zone addr and will never reach the connections threshold of limit_conn_zone default.
