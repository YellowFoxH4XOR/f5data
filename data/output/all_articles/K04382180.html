K04382180: Failure - Error starting VM caused by missing /config/ssl/ssl.csr

Type
Support Solution
Published
2021-11-11
Updated
2023-02-21
Source
https://my.f5.com/manage/s/article/K04382180

Description
After rebooting the VCMP host, some guests failed to run by showing below error message:
"Failure - Error starting VM. Timed out after 900 seconds."

Following the instruction of K68404255 to collect the console log of the guest and see below error messages:

serial-console.log
=======================================================
missing     /config/ssl/ssl.csr
1 critical file(s) missing
=======================================================
0 critical file(s) modified
=======================================================

Integrity Check Result: [ FAIL ]
Contact F5 Networks Technical Support.
Unmounting file systems
umount: /var/log: device is busy.
        (In some cases useful info about processes that use
         the device is found by lsof(8) or fuser(1))
umount: /var: device is busy.
        (In some cases useful info about processes that use
         the device is found by lsof(8) or fuser(1))
umount: /usr: device is busy.
        (In some cases useful info about processes that use
         the device is found by lsof(8) or fuser(1))
System halting.
[   21.603607] System halted.

Environment

  • The BIG-IP device has a license that includes the FIPS 140-2 option (FIPS full-box license)
  • The device is provisioned with vCMP dedicated and has VCMP guests running on it
  • The device is rebooted

Cause

Due to Bug ID 939085: /config/ssl/ssl.csr directory disappears after creating certificate archive, some vCMP guests are missing /config/ssl/ssl.csr directory. When the system missing /config/ssl/ssl.csr, it is causing Integrity Check to fail after the reboot. Then System halted while booting due to a FIPS integrity check failure K25205233. 


Recommended Actions

First part: Following below steps to bring the guest up and running

  1. Open two ssh sessions, one to start the guest, and one to vconsole into the guest.
    You have about 2 seconds from issuing
    (tmos)# modify vcmp guest <guestname> state deployed
    to running
    # vconsole <guestname>
    and pressing an arrow key to interrupt the grub autoboot.
    Note: Before the countdown expires, use the Up Arrow and Down Arrow keys to stop the countdown
     

  2. Select the appropriate boot image, Press the key 'e' to start the edit options.

     +-------------------------------------------------------------------------+
    | BIG-IP 12.1.2 Build 0.0.249 - drive vda.1              <---              |
    | TMOS maintenance                                                         |
    |                                                                          |
    +--------------------------------------------------------------------------+
     
  3. A new GRUB menu displays, Select the line starting with "kernel" by using Arrow key then Press "e" to edit
     +-------------------------------------------------------------------------+
     | root (hd0,0)                                                            |
     | kernel /boot/1/vmlinuz ro root=UUID=f24788d5-197a-41cf-af1d-53df7b190>  |
     | initrd /boot/1/initrd                                                   |
     |                                                                         |
     +-------------------------------------------------------------------------+

  4. Add the "NO_FIPS_INTEGRITY=1" option to the end of the line starting with "kernel"

    <1d-53df7b1901c8  console=ttyS0 panic=1 platform=Z101 quiet
    -----
    Add the option:
    -----
    < console=ttyS0 panic=1 platform=Z101 quiet NO_FIPS_INTEGRITY=1
    -----

    "Enter" to accept the change, and then "b" to boot with the defined options.

Second part: After guest is UP and running, you can access the guest and perform the workaround to fix BUG ID 939085:

Recreate /config/ssl/ssl.csr directory and set correct file permissions FOR EACH GUEST which was not running before:

  # mkdir /config/ssl/ssl.csr
 # chmod 755 /config/ssl/ssl.csr/
 # chcon -R --reference=/config/ssl/ssl.crt/ /config/ssl/ssl.csr

Also check if /config/f5_public/fipserr is 0 size, if not, then need to zero out the fipserr integrity check file by using below command:

# cat /dev/null > /config/f5_public/fipserr
