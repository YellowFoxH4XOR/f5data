Description

This solution will detail the conditions under which the following log message is generated.

  • You observe the following notification message in /var/log/apm:
<big-ip_hostname> notice tmm3[19628]: 01490505:5: /Common/Access_Policy_ap:Common:<session_id>: Route domain not reachable for PPP tunnel 0x56016abe4100 (strict mode) assigned rtdom 301 connectivity/tunnel interface rtdom 0

Note in the above log message "301" is a Route Domain ID and the session_id refers to the unique APM Session ID.

Environment

  • Network Access
  • Route Domains
  • Virtual Server
  • VLANS and Tunnels
  • APM
  • LTM

Cause

This message is generated when a Route Domain/VLAN is configured on the same Virtual Server as a APM Access Policy with Network Access where the Network Access clients do not have access to the Route Domain. In the example log message above it is telling us that Route Domain 301 is not accessible from Route Domain 0 because Strict Mode is enabled in the Route Domain.

For example we have the following Route Domain configured as ID 301 in VLAN /Common/Test_VLAN:

net route-domain /Common/RD_301 {
    id 301
    vlans {
        /Common/Test_VLAN
    }
}

On the Virtual Server we have set to listen on ALL VLAN and Tunnels (in the VLAN and Tunnel Traffic selection). Note this is a default setting and does not display in the bigip.conf file for this reason:

ltm virtual /Common/Test_VIP_443 {
    destination /Common/10.10.10.1:443
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
        /Common/Access_Policy_ap { }
        /Common/SSL_Profile_clientssl {
            context clientside
        }
        /Common/apm_conn_cp {
            context clientside
        }
        /Common/example_http { }
        /Common/ppp { }
        /Common/rba { }
        /Common/tcp { }
        /Common/websso { }
    }
    rules {
        /Common/HTTP_Header
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
}

Virtual Server with VLAN and Tunnel Traffic set to Enabled On the F5 Connectivity Profile and the External VLAN:

ltm virtual /Common/Test_VIP_443 {
    destination /Common/10.10.10.1:443
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
        /Common/Access_Policy_ap { }
        /Common/SSL_Profile_clientssl {
            context clientside
        }
        /Common/apm_conn_cp {
            context clientside
        }
        /Common/example_http { }
        /Common/ppp { }
        /Common/rba { }
        /Common/tcp { }
        /Common/websso { }
    }
    rules {
        /Common/HTTP_Header
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
 vlans {
        /Common/F5_Conn_Profile
        /Common/External
    }
    vlans-enabled
}

Recommended Actions

Set the Route Domain Parent ID to a common ID.

  1. Login to the BIg-IP GUI.
  2. Navigate to Network>Route Domains.
  3. Click on the name of the Route Domain
  4. In the Parent Name drop down select a Parent Route Domain.
Note: This will need to be done for both Route Domain unless one is the default Route Domain (Route Domain 0).

Disable strict mode on the Route Domain.

  1. Login to the Big-IP GUI.
  2. Navigate to Network>Route Domains.
  3. Click on the name of the Route Domain
  4. Uncheck the Enable for Strict Isolation.
  5. Click Update.
Remove the Route Domain VLAN from the APM Virtual Server.
  1. Login to the Big-IP GUI.
  2. Navigate to Local Traffic>Virtual Servers>Virtual Server List
  3. Click on the APM Virtual Server.
  4. Set VLAN and Tunnel Traffic to Enabled On.
  5. Select the APM Connectivity Profile and the VLAN.
  6. Click Update.
  Note: You can also choose the "Disabled On" option and select the Route Domain VLAN.
