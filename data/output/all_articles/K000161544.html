Description

The mcpd process performs validation checks on iRules at the time they are saved, which may result in warnings being logged to the ltm log, and also appearing in ther terminal, when using tmsh to save or update an irule.   

A warning will not prevent the rule from being saved, despite the syntax error, and if the rule is triggered by traffic passing through a virtual server, the syntax error may trigger an 'iRule Execution Error', causing that connection to be abruptly reset.

Examples:

If an http response body is provided to the HTTP::respond command, without preceding that value with the keyword "content", a validation warning will be produced:

The following incorrect iRule commands will result in an "invalid argument" warning:

HTTP::respond 200 "my http response"

The expected/correct syntax is:

HTTP::respond 200 content "my http response"

The following warning message will be seen in /var/log/ltm:

warning: [The following errors were not caught before. Please correct the script in order to avoid future disruption. "invalid argument my http response 29 38][HTTP::respond 200 "my http response" ]

Note: mcpd warning messages are not displayed in the BIG-IP GUI.  They will only be seen in the /var/log/ltm log, or in the tmsh commandline shell.

Environment

  • LTM virtual servers with iRules applied to them, which make use of the HTTP::respond command

  • Use of incorrect command syntax

Cause

Use of HTTP::respond commands in iRules with that do not include the required keyword "content" or "content-type" arguments immediately before the values for those arguments.

Recommended Actions

  • Update the iRule syntax for HTTP::respond commands to include the "content" and "Content-Type" arguments as follows:

    • Replace:

      HTTP::respond 302 "No resource found"

      With:


      HTTP::respond 302 content "No resource found"

      (or, as needed):

      HTTP::respond 302 content "No resource found" Content-Type "text/plain"

  • Review and implement corrected iRule syntax to ensure compliance with BIG-IP’s configuration validation requirements.

  • Validate configuration after changes to confirm warnings are resolved.

    • tmsh load sys config verify
