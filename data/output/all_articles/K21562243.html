K21562243: F5 Ingress controller and Kubernetes integration - ssl-redirect irule conflicts with LTM policies

Type
Support Solution
Published
2020-12-16
Updated
2023-02-21
Applies to
  • F5 Automation and Orchestration
  • F5 Container Ingress Services
Source
https://my.f5.com/manage/s/article/K21562243

Description

  • You are integrating Kubernetes deployment/s with  BIG-IP using F5-Ingress-Controller 
  • At a time of creating this SSL-Redirect object, F5 ingress controller creates a virtual server (VS) on port 80 with both the redirect iRule and an LTM policy.
  • On the other hand, when LTM policy exists in BIG-IP configuration along with an iRule, LTM policy takes precedence over the iRule.
  • This conflict, results in a none encrypted communication to back-end server, which maybe a consequence of undesirable outcome 

Environment

  • F5-Ingress-Controller
  • Big-IP
  • Container Ingress Services [CIS]

Cause

  • Missing HOST field in the Ingress yaml file 

Recommended Actions

  • Include/add 'host' filed in the ingress yaml as shown below 
        spec:
          tls:
          - hosts:                               <-- hosts field 
            - www.example.com
            secretName: Common/clientssl
          rules:
           - host: www.example.com                            <-----  host rule is added here
