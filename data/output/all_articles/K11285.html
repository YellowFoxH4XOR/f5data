Known Issue

This is the result of a known issue. If a virtual server uses a cookie hash persistence profile and you apply an iRule that selects a pool, TMM may crash when the virtual server closes an HTTP connection. This issue occurs when all of the following conditions are met:

  • The virtual server receives multiple HTTP requests from the client within a single HTTP Keep-Alive connection
  • One or more of the HTTP requests includes a cookie, and one or more does not
  • An iRule changes the target pool for at least one of the requests

F5 Product Development tracked this issue as CR134551 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or PSM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You can work around this issue by setting cookie hash persistence within the iRule. To do so, enter the persist cookie hash command after each pool selection command in the iRule. The syntax of persist cookie hash command is the following:

persist cookie hash <cookie_name> [ {<offset> [<length>]} [<timeout-in-seconds>]] ]

For example:

persist cookie hash "COOKIE_NAME" 0 0

Note: For more information about iRules commands, refer to the F5 DevCentral site. A separate DevCentral login is required to access this content.
