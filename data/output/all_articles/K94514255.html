Topic

Using Accept XFF and XFF Alternative Names Option in HTTP Profile with ASM Application Security (L7) DOS Protection.

Description

You should consider using this procedure under the following condition:

  • You have identified that an attacker is sending DDOS traffic to your application.
  • You want to block the HTTP request based on an IP address in the HTTP Header value such as normally with X-Forwarded-For or a HTTP Header value that resembles an IPv4 address.
  • You want to use the F5 ASM Application Security Dos Protection enabled Dos Profile 

    Application Security Manager™ (ASM) helps protect web applications from DoS attacks aimed at the resources that are used for serving the application: the web server, web framework, and the application logic. Application Security Manager™ determines that traffic is a DoS attack based on calculations for transaction rates on the client side (TPS-based) or latency on the server side (stress-based). ASM monitors requests from source IP and determines it is a malicious if it exceeds the defined detection threshold in the Application (L7) Security Dos Protection enabled Dos Profile.

    There may be instances that the IP address information that you would like to ASM Dos Profile to action is in an HTTP X-Forwarded-For header, which is typically added when the original client IP address is translated by a Web Proxy.

    It may also be possible that the IP address information is in an HTTP Header header value. In such case, an iRule may be used to extract the IP address information and use it as a custom HTTP header value so that ASM Dos Profile can use the information and apply Dos Protection features against it.

    HTTP Profile Accept XFF and XFF Alternative Names Options

    The Accept XFF option in the HTTP profile enables or disables trusting the client IP, and statistics from the client IP address, based on the request's X-Forwarded-For (XFF) headers, if they exist. Particularly with ASM Application (L7) Security Dos Protection, the Accept XFF option allows the BIG-IP system to take action based on IP addresses from the X-Forwarded-For header that match, for example, an Access List.

    Another option in the HTTP Profile, XFF Alternative Names  which specifies that alternative XFF headers are trusted, instead of the default X-Forwarded-For header. This can be useful if the IP address information that you would like ASM Dos Protection to action against is not in the default X-Forwarded-For header.

    Prerequisite

    You must meet the following prerequisites to use this procedure:
    You have administrative access to the BIG-IP Configuration Utility (WebUI)
    You have a basic understanding of iRules
    An existing configured ASM DoS Profile with TPS-based detection, Stress-based or Behavioral Dos Protection is applied to a Virtual Server that is under stress/attack

    For more information on configuring ASM DoS Profile and its features, please see Manual Chapter : Preventing DoS Attacks on Applications

    Note: The reference configuration for the HTTP Profile Accept XFF and XFF Alternative Names Options and ASM DoS Profile are independent of the Custom XFF Headers setting in an ASM Security Policy. 

    Consider the following sample HTTP Traffic, where the IP address information is based in a custom HTTP Header named "SpecialToken"  with a value of "aaaaaaaa_2.2.2.2" and an existing X-Forwarded-For HTTP Header with a value of "1.1.1.1"

    GET /app1/info.json HTTP/1.1 
    Host: somesite.app  
    Accept: application/json 
    Accept-Charset: UTF-8 
    SpecialToken: aaaaaaaa_2.2.2.2   
    Connection: keep-alive 
    User-Agent: specialapp 
    Accept-Encoding: gzip,deflate,br 
    X-Forwarded-For: 1.1.1.1

    Using the default X-Forwarded-For HTTP Header value that ASM Dos Profile will action against


    You will need to modify the HTTP Profile used on the Virtual Server where the ASM Dos Profile is applied to enable the Accept XFF option.

    Procedure


    1.  From the Configuration Utility, Go to Local Traffic  ››  Profiles : Services : HTTP  ››  <HTTP Profile Name>

    2. Under Settings, click checkbox next to Accept XFF and set it to Enabled. This option is disabled by default.

    Using the IP address information value in the custom HTTP Header value that ASM Dos Profile will action against


    To use the IP address information value in the custom HTTP Header value so ASM Dos Profile can action against it, the IP address need to be extracted using an iRule, apply the created iRule to the Virtual Server where the ASM Dos Profile is applied and enabled Accept XFF and configure XFF Alternative Names from the HTTP Profile.

    Procedure


    Given the custom HTTP Header ??????SpecialToken: aaaaaaaa_2.2.2.2 as the example where the IP address information is included;

    1. Extract the IP address information thru an iRule and insert it as a new HTTP header. Provide a custom iRule name. 

    From the Configuration Utility, Go to Local Traffic  ››  iRules : iRule List  ››  New iRule...: 

    Name: example: custom_extraction_xff

    when HTTP_REQUEST { 

        # Check if ??????SpecialToken header exists 
        if {[HTTP::header exists "??????SpecialToken"]}{ 

           # Save the value of ??????SpecialToken
           set ??????SpecialToken_val [getfield [HTTP::header value ??????SpecialToken] "_" 2]
           #log local0. "extracted IP in ??????SpecialToken_val is $??????SpecialToken_val" 

           # Insert the X-??????SpecialToken with value from ??????SpecialToken_val
           HTTP::header insert X-??????SpecialToken $??????SpecialToken_val
          # log local0. "X-??????SpecialToken value is [HTTP::header "X-??????SpecialToken"]" 

        } 
     }

    Note: Review the comments (#) in the iRule. The HTTP header where the extracted IP address is inserted to is X-??????SpecialToken and was extracted using the getfield iRule command.

    Important: This is an example scenario only. Different scenarios can be encountered and thorough review of the sample HTTP Traffic should be done and use of appropriate iRule commands and syntax should be tested. For more information and assistance on iRules, refer to IRULES (https://devcentral.f5.com/irules) or engage the F5 Professional Services to get the help you need for your F5 solutions (https://www.f5.com/services/professional-services).

    2. Apply the created iRule to the  Virtual Server where the ASM Dos Profile is applied

    From the Configuration Utility, Go to Local Traffic  ››  Virtual Servers : Virtual Server List  ››  <Virtual Server> : iRules : Manage

    3.  Modify the HTTP Profile used on the Virtual Server where the ASM Dos Profile is applied to enable the Accept XFF option.

    From the Configuration Utility, Go to Local Traffic  ››  Profiles : Services : HTTP  ››  <HTTP Profile Name>

    Under Settings, click checkbox next to Accept XFF and set it to Enabled. This option is disabled by default.

    4. Enable XFF Alternative Names and define the custom HTTP header name where the IP address information is located.

    Under Settings, click checkbox next to XFF Alternative Names to enable it and define the custom HTTP header name

    Example:  
    XFF Alternative Names X-??????SpecialToken
