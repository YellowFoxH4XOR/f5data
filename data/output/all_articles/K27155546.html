Security Advisory Description

By spoofing the target resolver with responses that have a malformed ECDSA signature, an attacker can trigger a small memory leak. It is possible to gradually erode available memory to the point where named crashes for lack of resources. (CVE-2022-38177)

Impact

There is no impact; F5 products are not affected by this vulnerability in default, standard, or recommended configurations. However, if the BIND configuration (named.conf) has been modified to enable DNS recursion with the recursion yes; line added to the options section of your BIND configuration file, an attacker can trigger a small memory leak and erode available memory over time, causing named to terminate.

Security Advisory Recommended Actions

If your BIND configuration has been modified to enable DNS recursion, you can mitigate this vulnerability by changing the recursion line in the options section of the BIND configuration file (named.conf).

Mitigation

Disable DNS recursion on the BIG-IP system

To disable DNS recursion on the BIG-IP system, perform the following steps:

  1. Log in to the Configuration utility.
  2. Navigate to DNS > Zones > ZoneRunner > named Configuration.
  3. In the Options box, scroll down to the options section, find the recursion yes; statement, and edit it to read recursion no;.
  4. Select Update.

Alternatively, you can mitigate this vulnerability by disabling the following algorithms in your BIND configuration using the disable-algorithms option:

  • ECDSAP256SHA256
  • ECDSAP384SHA384

Impact of action: After you disable these algorithms, the BIG-IP system treats zones signed with these algorithms as insecure.

The disable-algorithms statement should be used in a global options clause in your BIND configuration. For example, the following disable-algorithms statement disables the ECDSAP256SHA256 and ECDSAP384SHA384 algorithms for all domains:

disable-algorithms "." {
        "ECDSAP256SHA256";
        "ECDSAP384SHA384";
    };
