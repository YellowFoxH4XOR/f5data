Topic

You should consider using these procedures under the following condition:

  • You want to increase the SSH keys on the BIG-IP system from 1024-bit to 2048-bit keys.

Description

This article provides the steps to modify the keyswap.sh file to generate 2048-bit RSA keys for the BIG-IP system.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have command-line access to the BIG-IP system as a root user.
  • Your BIG-IP system is currently using 1024-bit SSH keys.

Procedures

To increase the SSH keys on the BIG-IP system from 1024 to 2048 bits, perform all of the following procedures:

  • Verify the current private key strength
  • Edit the keyswap.sh file
  • Regenerate the SSH keys

Verify the current private key strength

To verify the BIG-IP system is currently using a 1024-bit RSA private key, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To verify the current private key size, enter the following command:

    openssl rsa -noout -text -in /var/ssh/ssh_host_rsa_key | grep -i key

    For a BIG-IP system using 1024-bit keys, the output of the command appears similar to the following example:

    Private-Key: (1024 bit)

  3. To view the current ssh-keygen data, enter the following command:

    grep keygen /usr/bin/keyswap.sh

    For a BIG-IP system using 1024-bit keys, if the output of the command appears similar to the following example, please move to Editing the keyswap.sh file:

     ssh-keygen -q -f ${tmpdir}/${identity} -t rsa -b 1024 -N "" -C "$username"
     ssh-keygen -q -f ${tmpdir}/ssh_host_key -t rsa1 -b 1024 -N "" -C "$hostname"
     ssh-keygen -q -f ${tmpdir}/ssh_host_rsa_key -t rsa -b 1024 -N "" -C "$hostname"
     ssh-keygen -q -f ${tmpdir}/ssh_host_dsa_key -t dsa -b 1024 -N "" -C "$hostname"

    If the output of the command appears similar to the following example, proceed to the Regenerate the SSH keys procedure:

      ssh-keygen -q -f ${tmpdir}/${identity} -t rsa -N "" -C "$username"
      ssh-keygen -q -f ${tmpdir}/ssh_host_key -t rsa1 -N "" -C "$hostname"
      ssh-keygen -q -f ${tmpdir}/ssh_host_rsa_key -t rsa -N "" -C "$hostname"
      ssh-keygen -q -f ${tmpdir}/ssh_host_dsa_key -t dsa -N "" -C "$hostname"
      ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -N "" -C "$hostname"
      ssh-keygen -q -f ${tmpdir}/ssh_host_ed25519_key -t ed25519 -N "" -C "$hostname"
      ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -N "" -C "$hostname"
      ssh-keygen -q -f ${tmpdir}/ssh_host_ed25519_key -t ed25519 -N "" -C "$hostname"

Edit the keyswap.sh file

Note: You must perform this procedure as a root user.

To edit the /usr/bin/keyswap.sh file to update the ssh-keygen commands to generate 2048-bit RSA keys, perform the following procedure:

Impact of procedure: Use caution when editing the keyswap.sh file. Incorrect editing may result in a corrupt keyswap.sh file that fails to execute.

  1. To remount the /usr file system in read-write mode, enter the following command:

    mount -o remount,rw /usr

  2. To create a backup of your current keyswap.sh file, enter the following command:

    cp /usr/bin/keyswap.sh /usr/bin/keyswap.sh_K26031800

  3. Using a text editor, open the /usr/bin/keyswap.sh file and edit the ssh-keygen commands to generate 2048-bit RSA keys. To do so, locate the following lines:

     ssh-keygen -q -f ${tmpdir}/${identity} -t rsa -b 1024 -N "" -C "$username"
     ssh-keygen -q -f ${tmpdir}/ssh_host_key -t rsa1 -b 1024 -N "" -C "$hostname"
     ssh-keygen -q -f ${tmpdir}/ssh_host_rsa_key -t rsa -b 1024 -N "" -C "$hostname"

    Change 1024 to 2048, as follows:

     ssh-keygen -q -f ${tmpdir}/${identity} -t rsa -b 2048 -N "" -C "$username"
     ssh-keygen -q -f ${tmpdir}/ssh_host_key -t rsa1 -b 2048 -N "" -C "$hostname"
     ssh-keygen -q -f ${tmpdir}/ssh_host_rsa_key -t rsa -b 2048 -N "" -C "$hostname"

    Note: Do not update the ssh-keygen command for the DSA key.

  4. Save the /usr/bin/keyswap.sh file.
  5. To ensure the /usr/bin/keyswap.sh file was updated correctly, enter the following command:

    grep keygen /usr/bin/keyswap.sh

    The output of the command appears similar to the following example:

     ssh-keygen -q -f ${tmpdir}/${identity} -t rsa -b 2048 -N "" -C "$username"
     ssh-keygen -q -f ${tmpdir}/ssh_host_key -t rsa1 -b 2048 -N "" -C "$hostname"
     ssh-keygen -q -f ${tmpdir}/ssh_host_rsa_key -t rsa -b 2048 -N "" -C "$hostname"
     ssh-keygen -q -f ${tmpdir}/ssh_host_dsa_key -t dsa -b 1024 -N "" -C "$hostname"

    Note: Confirm the ssh-keygen commands for the RSA keys are 2048, and the DSA key is still 1024.

  6. To remount the /usr file system in read-only mode, enter the following command:

    mount -o remount,ro /usr

Regenerate the SSH keys

To regenerate and apply the 2048-bit RSA keys, perform the following procedure:

Impact of procedure: The sshd service restarts. Depending on your BIG-IP version, your SSH session may be terminated. If your session is terminated, when you reconnect, the BIG-IP system may display a Warning - POTENTIAL SECURITY BREACH! message. This is an expected warning because the SSH private keys have changed.

  1. To regenerate the SSH keys to be new 2048-bit keys, enter the following command:

    /usr/bin/keyswap.sh -genkeys

  2. The command causes the sshd service to stop and restart. Output of the command appears similar to the following example:

    Stopping sshd: [  OK  ]
    Starting sshd: [  OK  ]

  3. If required, re-establish your SSH session.

    Note: When you reconnect, the BIG-IP system may display a Warning - POTENTIAL SECURITY BREACH! message. This is an expected warning because the SSH private key has changed.

  4. To verify the new 2048-bit current private key is being used, enter the following command:

    openssl rsa -noout -text -in /var/ssh/ssh_host_rsa_key | grep -i key

    The output of the command appears similar to the following example:

    Private-Key: (2048 bit)
