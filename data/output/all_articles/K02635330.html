Topic

After 497 days, the SNMP OID  sysUpTime rolls over.

Description

There are two popular SNMP OID's uses to monitor system uptime:

  1.  SNMPv2-MIB::sysUpTime  .1.3.6.1.2.1.1.3 
  2.  HOST-RESOURCES-MIB::hrSystemUptime .1.3.6.1.2.1.25.1.1
The time (in hundredths of a second) since the network management portion of the system was last re-initialized, experiences a counter rollover after 497.1 days.
This behavior is due to the counter used by the TimeTicks, which sysUpTime references, using a 32-bit integer value (range is 0 through 4,294,967,295).
 

Environment

  • SNMP is used to monitor system uptime 

Cause

  • sysUpTime and hrSystemUptime use a 32 bit integer value 

Recommended Actions

1. Be aware that if the system is up more than 498 days that the result may be inaccurate. 
     For Example:   If the system is up for 500.1 days both OID's will report an uptime of 3 days (500.1 - 497.1) 
2. Consider using F5-BIGIP-SYSTEM-MIB::sysSystemUptimeInSec, this high capacity counter under sysSystem that would provide the uptime of the system in seconds and wouldn't overflow 497 days.
