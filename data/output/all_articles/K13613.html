Known Issue

Requests with repeated wildcard parameters may generate incomplete violation details, may fail to generate learning suggestions and may generate extra database entries.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM policy contains a wildcard parameter with the Allow Repeated Occurrences option disabled
  • The illegal repeated parameter name violation is set to learn and alarm
  • A request contains repeated occurrences of the affected wildcard parameter in the query string, with the same value for each occurrence

    Note: A blank or null value for both parameter instances will also meet this condition.

Given a BIG-IP ASM policy with the wildcard parameter MyParam* defined and otherwise configured as described previously, either of the following example requests would cause this issue to occur:

GET page.php?MyParam=1&MyParam=1

GET page.php?MyParam=&MyParam=

These requests will cause records that do not contain any learning suggestion data to be unnecessarily saved to the BIG-IP ASM request database. Since all active web applications share the request database, and the database has a hard limit for request storage, writing unnecessary records to the database may waste space that can be used for logging legitimate requests.

Impact

  • Excessive unnecessary records may cause legitimate learning suggestions to be rotated out of the database too quickly
  • Learning suggestions may not be generated for violations with learning enabled
  • The system may report violations with incomplete details

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Learning suggestions are removed from the Application Security > Policy Building > Manual screen faster than expected based on observed rate of requests that should be generating learning suggestions and violations
  • The violation details for the illegal repeated parameter name violation will incorrectly list the value in the Wildcard Parameter Name field as N/A
  • Illegal repeated parameter name violations shown in the Reporting screen will generate no corresponding entries in the Traffic Learning screen

Workaround

To work around this issue, you can modify the BIG-IP ASM security policy. To do so, perform one of the following procedures:

Important: Each of the following procedures modifies the policy to work around this issue in a different way. You should evaluate your security policy and application traffic to determine which change will be most appropriate for your environment.

  • Allow the specific wildcard parameter to be repeated
  • Disable the illegal repeated parameter name violation
  • Define an explicit parameter

Allow the specific wildcard parameter to be repeated

Impact of workaround: None.

To allow repeat occurrences of a wildcard parameter in a query string, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Open the Application Security > Parameters > Parameters List screen.
  3. Select the affected wildcard parameter from the Parameters List.
  4. Enable the Allow Repeated Occurrences option.
  5. Click Update.
  6. Click Apply Policy.

Disable the illegal repeated parameter name violation

Impact of workaround: This workaround will enable repeated parameter occurrences for the entire security policy.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Open the Application Security > Policy > Policy Properties screen.
  3. Confirm that the Change edited policy option displays the policy you want to edit.
  4. In the Blocking tab, select Settings.
  5. Disable the Alarm and Block options from the Illegal Repeated Parameter Name violation.
  6. Click Save.
  7. Click Apply Policy.

Define an explicit parameter

Impact of workaround: None.

If the affected parameter is consistent across requests, you can include the parameter in the security policy as an explicit parameter, rather than a wildcard parameter, by performing the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Select the Application Security > Parameters > Parameters List screen.
  3. Select the affected wildcard parameter from the Parameters List.
  4. Click Delete.
  5. Confirm by clicking OK.
  6. Click Create.
  7. Enter the explicit form of the parameter in the Parameter Name field.
  8. Select any remaining options that are appropriate for your environment.
  9. Click Create.
  10. Click Apply Policy.
