Description

How to setup gRPC through Aspen Mesh.

 

Environment

You are using Aspen Mesh, which is Istio.

You've followed guides, but it doesn't seem to work and you don't know why.

Cause

Aspen Mesh processes gRPC perfectly. However its hard to test.

gRPC is a structured protocol. Its hard to set up a test to make protocol calls. Unlike REST.

 

To debug this, be aware that gRPC uses HTTP/2 as its transport.

There is nothing in Aspen mesh which is gRPC specific.

Recommended Actions

To test ideally you should create a simple echo server that listens with HTTP/2. However you should still be able to get a status reply from a gRPC server.

Then test with

curl -v --http2 http://example.com/

If it works with HTTP/2 it will work with gRPC.

For Aspen mesh to process gRPC calls, the services must be enabled for the "http2" protocol

For convenience, Aspen Mesh supports the "gprc" protocol. However this is identical to "http2" and is provided as convenience for people, not the software.

Protocol specification is done by correctly naming the port on the connecting service, or by adding the appProtocol Field

Use the command

istioctl analyze -A


To discover issues with port naming. 

Additional Information

This is discussed in detail here.

https://istio.io/latest/docs/ops/configuration/traffic-management/protocol-selection/

 

The reason for using a protocol rather than using "tcp" for everything is that is enables the DestinationRule to deal with the traffic correctly.

HTTP/2 is intended to establish long lived connections and multiplex requests down them. This means that it will attach to a specific pod and then not load balance.

If the DestinationRule is aware that it is a HTTP/2 server by marking the matching service as "http2" or "grpc",  then additional options are available.

See   ConnectionPoolSettings.HTTPSettings  under https://istio.io/latest/docs/reference/config/networking/destination-rule/
