Topic

The BIG-IP APM system provides support for step-up authentication using per-request policy subroutines. This allows the BIG-IP APM system to prompt users for credentials when accessing certain sites or after a configured period of time.

Description

BIG-IP APM 12.1.0 introduces support for step-up authentication, which provides the ability to prompt users for credentials when accessing a specific area of an application. To use this feature, you can apply a per-request policy configured with a subroutine to the virtual server through which the users access the application.

This functionality is useful when access to an application is generally available for all users, but there are specific areas of the application that should be only available to a smaller list of authorized users.

Prerequisites

Before configuring a per-request policy to prompt users for credentials, you should create the following configuration elements:

  • A BIG-IP APM access policy that is configured and applied to the virtual server. This is required to apply the per-request policy to the virtual server, and if no other authentication is needed, it can be a simple policy with only a start and the Allow ending.
  • A BIG-IP APM AAA Server profile for the authentication server that will validate the user's credentials.
  • A custom URL category with the HTTP URLs of the website or application that will require additional authentication.

Procedure

After the prerequisite elements are configured, you can set up a basic step-up authentication configuration on the BIG-IP system to prompt users for authentication when they attempt to access the restricted sites. To do so, perform the following procedure:

Note: The BIG-IP APM system supports step-up authentication for Active Directory, Lightweight Directory Access Protocol (LDAP), Remote Authentication Dial-in User Service (RADIUS), and Client Certificate authentication types.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Navigate to Access Policy > Per-Request Policies.
  3. Click Create.
  4. Populate the Name field and then click Finished.
  5. Next to the new per-request policy to enter the visual policy editor, click Edit.
  6. Immediately after the start of the policy, insert a Category Lookup item.
  7. Select the appropriate Categorization Input option to trigger the BIG-IP system to prompt users for credentials.
  8. Set the Category Lookup Type option to use the desired categories.
  9. Optional: Set the Reset on Failure option.

    Note: By default, this option is set to Enabled.

  10. Click Branch Rules.
  11. Click Add Branch Rule.
  12. In the Name field, enter a name and then click change to add an expression.
  13. Click Add Expression.
  14. For the Agent Sel setting, select Category Lookup.
  15. For the Condition setting, select Category Lookup.
  16. For the Category is setting, select the custom URL category you created prior to performing this procedure.
  17. Click Add Expression.
  18. Click Finished.
  19. To save the Category Lookup item configuration, click Save.
  20. To create a subroutine in which the authentication actions will be configured, click Add New Subroutine.
  21. Select a subroutine template and click Save.

    Note: Depending on the template chosen, you may need to also configure authentication settings to complete the configuration.

  22. To configure the subroutine timeout settings or rename the subroutine, click Subroutine Settings / Rename, enter the appropriate values, and click Save.
  23. Add the subroutine to the Category Lookup item branch in the per-request policy, so users are required to complete authentication when they request access to the protected resources.
  24. Ensure the successful branch of the subroutine reaches an Allow ending of the per-request policy.
  25. Navigate to Local Traffic > Virtual Servers.
  26. Select the virtual server with the access policy.
  27. In the Access Policy section, select the per-request policy you created for the Per-Request Policy setting.
  28. Click Update.
