K73052202: ha-status shows peer device as offline

Type
Support Solution
Published
2019-08-30
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.X.X, 13.0.X, 13.1.5, 13.1.4, 13.1.3, 13.1.1, 13.1.X, 13.0.1, 13.0.0, 13.1.0
Source
https://my.f5.com/manage/s/article/K73052202

Description

Peer device status in a HA configuration shows as offline when viewed from Device Management > Devices > <Device>, or when using the show /cm device command, similar to the following example:

------------------------------------------------------------------------------------------------
CentMgmt::Device: /Common/LTM1.com
------------------------------------------------------------------------------------------------
Hostname                       LTM1.com
Mgmt Ip                        192.168.1.100
Configsync Ip                  192.168.5.1
Mirroring IP                   10.10.10.1
Mirroring Secondary IP         10.10.20.1
Failover Multicast IP          ::
Failover Unicast IP(s)         10.10.10.1, 10.10.20.1
Device HA State                active
Device HA Load Capacity        0
Device Current Load Factor     1
Device Next Active Load Factor 0

------------------------------------------------------------------------------------------------
CentMgmt::Device: /Common/LTM2.com
------------------------------------------------------------------------------------------------
Hostname                       LTM2.com
Mgmt Ip                        192.168.1.200
Configsync Ip                  192.168.5.2
Mirroring IP                   10.10.10.2
Mirroring Secondary IP         10.10.20.2
Failover Multicast IP          ::
Failover Unicast IP(s)         10.10.10.2, 10.10.20.2
Device HA State                offline <------------------ HA state offline
Device HA Load Capacity        0
Device Current Load Factor     0
Device Next Active Load Factor 0

Environment

  • High availability configuration

Cause

Management IP is not defined as a failover IP, and TMM self IPs which are defined do not allow UDP port 1026.

Recommended Actions

Modify the Port Lockdown setting of all self IPs used for failover, to allow UDP port 1026.

For self IPs that are used for high availability purposes, it is recommended to use Allow Default, which allows access for a pre-defined set of network protocols and services that are typically required in a BIG-IP deployment. See the following article for more information:

  • K17333: Overview of port lockdown behavior (12.x - 15.x)

It is also highly recommended to configure the management IP as a second failover IP on each system. The reasons for this are explained in the following article:

  • K14135: Defining network resources for BIG-IP HA features (11.x - 14.x)
