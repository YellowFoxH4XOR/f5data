Description

After upgrading a vCMP Guest system, configuration failed to load. The following similar messages are seen from /var/log/ltm:
err mcpd[7337]: 010712a5:3: Ha_group <ha_group_name> unknown trunk <trunk_name>.
err tmsh[8830]: 01420006:3: Loading configuration process failed.
emerg load_config_files[8828]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- Loading schema version: 14.1.2.6
err mcpd[7337]: 01070422:3: Base configuration load failed.

Or when running 'tmsh load sys config verify', system reports similar to the following:
Loading configuration...
Loading schema version: 13.1.3.4
  /config/bigip_base.conf
  /config/bigip_user.conf
  /config/bigip.conf
Loading schema version: 14.1.4.1
010712a5:3: Ha_group <HA group name> unknown trunk <trunk name>.
Unexpected Error: Loading configuration process failed.
--or--
Unexpected Error: Validating configuration process failed.

Environment

  • BIGIP VCMP Guest
  • Upgrade
  • HA Group
Cause

This is a known issue tracked under ID1009133: BIG-IP vCMP guests that have HA Groups configured to include trunk scoring may fail to upgrade properly.

Recommended Actions

Option 1: Before attempting the upgrade or if you've reverted back to previous version

  • Remove all trunks from the HA Group.
    Note: This should be done on the standby unit first to prevent a failover.
  • The trunks can then be re-added to the HA Group after the upgrade:  System >> High Availability >> HA Group List

Option 2: If already booted into an affected version

  • Edit the /config/bigip_base.conf to add a line like the following declaring the trunk exists, and reload the configuration or reboot:
    net trunk <trunk name> { }
