Description

When performing high-volume REST API operations to modify GTM wide IP configuration items on BIG-IP DNS devices, extremely slow response times (10–16 seconds per request) may occur. This issue happens when an external REST API tool sends concurrent PATCH requests to the management interface. The delay is not caused by backend processing (restjavad, icrd, mcpd), but is related to the httpd process handling incoming connections. Increasing the httpd max-clients value significantly improves API performance.

Environment

  • Default httpd max-clients setting: 10
  • REST API tool sending concurrent PATCH requests to modify GTM wide IP objects
  • Management plane memory available: ~6GB (example)
  • Each httpd child process uses ~30MB management plane memory

Cause

The slow REST API performance is caused by the default httpd max-clients setting (10) being insufficient for the concurrent connection load from the REST API tool. When concurrent HTTPS connections exceed this limit, excess connections are queued and must wait for existing connections to complete. Each httpd child process handles one concurrent connection; with only 10 allowed, high-concurrency API operations experience significant queuing delays. Increasing max-clients allows more concurrent connections to be serviced, eliminating the bottleneck.

Answer/Recommended Actions

  1. Calculate the appropriate max-clients value:
    • Formula:
      Max HTTPD child processes = (Available management plane memory × 80% - Current used memory) / 30MB per process
    • Example calculation:
      (9.3GB × 80% - 3.9GB) / 30MB ≈ 118 maximum safe httpd child processes
  2. Configure httpd max-clients to match actual concurrent connection requirements:
    • Monitor httpd process count during API operations to determine the required value.
  3. Apply the configuration change:
    tmsh modify sys httpd max-clients <calculated_value>
    tmsh save /sys config
    tmsh restart /sys service httpd
    tmsh restart /sys service tomcat
  4. Monitor httpd process count during API operations:
    ps aux | grep "/usr/sbin/httpd -DTrafficShield -DAVRUI -DSAM" | wc -l
  5. Avoid setting max-clients to the maximum value (256) unless necessary:
    • Excessive httpd processes can exhaust management plane memory and trigger OOM events, leading to loss of management access and potential impact on ASM-related processes.
  6. Restarting httpd and tomcat services:
    • Causes temporary loss of GUI connectivity but does not affect data plane traffic or business operations.

Additional Information

  • Each httpd child process consumes approximately 30MB of management plane memory.
  • The management plane OOM threshold is typically 80% of available management plane memory.
  • Apache documentation clarifies that MaxClients (max-clients) sets the limit on simultaneous requests; excess connections are queued.
  • For environments with varying concurrency, monitor actual usage and adjust max-clients accordingly to balance performance and memory safety.
