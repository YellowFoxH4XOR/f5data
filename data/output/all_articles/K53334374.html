Issue

Old Behavior

In versions prior to BIG-IP 11.5.0, if the Bad multipart parameters parsing validation check is disabled in the security policy, and the BIG-IP ASM system encounters a parsing error in a multipart request, the system checks the request headers for Request for Comment (RFC) violations but does not check the request payload for attack signature violations.

For example, if the BIG-IP ASM system encounters a bad boundary while parsing a multipart request, the system continues to check the request headers for RFC violations. However, no attack signature checks are performed on the message payload.

New Behavior

Beginning in BIG-IP 11.5.0, if the Bad multipart parameters parsing validation check is disabled in the security policy, and the BIG-IP ASM system encounters a parsing error in a multipart request, the system checks the request headers for RFC violations and continues to check the request payload for attack signature violations.

For example, if the BIG-IP ASM system encounters a bad boundary while parsing a multipart request, the system continues to check the request headers for RFC violations and performs attack signature checks on the message payload.

F5 Product Development tracked this change as ID 421755.

Impact

None. The system continues to perform attack signature matching on the request payload.

Recommended Actions

None
