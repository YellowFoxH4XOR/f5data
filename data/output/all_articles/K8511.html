Known Issue

This is the result of a known issue. The SSH daemon (sshd) is unable to log messages to the lastlog file when the daemon’s log level is set to debug.

This behavior occurs because the /var/log/lastlog file does not exist in the /var/log directory. When the sshd process log level is set to debug, the following messages are reported in the /var/log/secure file:

sshd[14176]: lastlog_filetype: Couldn't stat /var/log/lastlog: No such file or directory
sshd[14176]: lastlog_openseek: /var/log/lastlog is not a file or directory!
sshd[14176]: lastlog_filetype: Couldn't stat /var/log/lastlog: No such file or directory
sshd[14176]: lastlog_openseek: /var/log/lastlog is not a file or directory!

This message is benign and informational; it does not affect the user’s ability to log into the system using SSH.

F5 Product Development tracked this issue as CR80788 and it was fixed in BIG-IP 9.4.2, for the BIG-IP 9.4.x software branch. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, WebAccelerator, or Link Controller release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF2 issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
