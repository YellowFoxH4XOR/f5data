Known Issue

This is the result of a known issue. Deleting more than 10 SNMP access objects through the Configuration utility at one time will cause the Configuration utility to lock up or report an exception error, depending on which version of BIG-IP you are running.

When this issue occurs in BIG-IP versions 9.3.0 through 9.4.1, the Configuration utility will lock up and become unresponsive.

When this issue occurs in BIG-IP version 9.4.2 and later, the Configuration utility will time out while attempting to process the request and then report the following error message:

"; nested exception is: java.net.SocketTimeoutException: Read timed out"

Note: This behavior does not affect BIG-IP version 10.0.0 or later, due to architectual changes that were made within the Configuration Utility.

F5 Product Development is tracking this issue as CR86978.

Workaround

You can work around this issue, depending on which version of BIG-IP you are running.

BIG-IP versions 9.3 through 9.4.1

You can restore access to the Configuration utility by stopping the syscalld process, which will cause the BIG-IP system to restart the process automatically. To do so, type the following command from the command line:

kill -9 `pidof syscalld`

Note: The ` mark is a back tick.

BIG-IP versions 9.4.2 through 9.6.1

To work around this issue in BIG-IP version 9.4.2 through 9.6.1, limit the number of SNMP access objects to 10 or less.
