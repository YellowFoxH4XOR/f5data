Description

TCP traffic is dropped by client after failover 

Environment

  • TCP traffic
  • BIG-IP configured with fastl4 virtual server
  • Ciient and server both using timestamp option
  • HA cluster with mirroring of the VS configured
  • AFM provisioned and Time Stamp Cookie (TScookie) enabled under DOS device protection.
  • Software version 17.1.x, 16.1.x
  • Failover between the HA pair whilst TCP connection established

Cause

TScookie will change the TSval sent in the timestamp option set by the server to the client. The clientside value will be larger than the value received from the server. When failover occurs, the tscookie value is not used and the original value from the server is sent as TSval. The client sees a stream of packets with incrementing TSval. When failover occurs, the client receives packets with a lower TSval, which it drops, believing them to be implausably old.

Answer/Recommended Actions

  • Disable TScookie
  • Configure fastl4 profile with "TCP Timestamp mode" set to "rewrite" or "strip" (will disable PVA)

Additional Information

Note that prior to version 17.1.0 TScookie was applied to specific vlan under "TCP BAD ACK Flood" vector, by default TScookie was not applied to any vlans. In version 17, vector "TCP BAD ACK Flood" is removed and two new vectors are added "TCP ACK Flood" and "TCP ACK (TS)", the latter is similar to the previous "TCP BAD ACK Flood". TScookie is applied to all vlans for "TCP ACK (TS)" vector. In version 17, TScookie can only be enabled or disabled.

To disable TScookie

  tmsh modify security dos device-config dos-device-config dos-device-vector { tcp-ack-ts { tscookie disabled }}
