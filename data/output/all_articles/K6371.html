K6371: Redundant pairs of Link Controllers may not synchronize wideip.conf, zone files, and other GTM-specific configuration elements

Type

Published
2007-01-22
Updated

Status

Applies to

  • BIG-IP Link Controller: 9.2.3, 9.2.2

Known Issue

This is the result of a known issue. BIG-IP Link Controllers create a BIG-IP configuration object that is not redundant, by default. As a result, BIG-IP Link Controllers that are configured as a redundant pair may fail to synchronize GTM configuration information, such as the wideip.conf file and zone files.

Note: Because LTM-specific configuration elements, such as the bigip.conf file, bigip_base.conf file, and the configuration database use a different synchronization mechanism than GTM-specific configuration elements, LTM configuration files may be synchronized properly even when GTM configuration files are not.

F5 Product Development tracked this issue as CR63367 and CR63555 and it was fixed in BIG-IP Link Controller 9.2.4, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP Link Controller Release Notes.

Workaround

If upgrading is not an immediate option, you can work around this issue by performing the following procedure:

Important: To correct this issue, you must edit the wideip.conf file. If you make a mistake when editing wideip.conf file, the BIG-IP Link Controller may no longer work properly.

  1. Log in to the command line.
  2. Back up the existing wideip.conf file, by typing the following command:

    cp /config/wideip.conf /config/wideip.sol6371

  3. Edit the file /config/wideip.conf file.
  4. Locate the server statement for the redundant pair that is not working properly. There should be one box statement within the server statement.

    Note: If there are two box statements, you are not experiencing the issue described in this Solution.

  5. If there is only one box statement, add a second box statement, using the self IP addresses of the other BIG-IP Link Controller. The statement should appear as follows:

    Note: You must also specify the unit ID as either 1 or 2. Use the value that is different from the unit ID on the redundant unit. For example, if the unit ID of the redundant unit is 1, specify the unit ID of the second box statement as 2.

      box { // gtm
address <address>
address <address>
unit_id <ID>
}

    For example:

       box { // gtm
address 172.16.25.1
address 172.16.25.2
unit_id 2
}
  6. Save the file and exit the editor.
  7. Run the gtmparse command.

    The gtmparse command should not report any errors. If the gtmparse command does report errors, edit the file again and correct the errors.

  8. Log in to the BIG-IP Link Controller redundant unit and run the gtm_add command.

    Running this command will pull the new configuration from the other BIG-IP Link Controller unit.

  9. Run the gtmload command.

    Running this command ensures that the new configuration is loaded.

The BIG-IP Link Controller should now synchronize the GTM-specific configuration elements.
