Description

You want to replace an existing Self-signed device certificate with a third-party or internal CA-signed device certificate using the configuration utility.

Environment

  • BIG-IP
  • Self-signed Device Certificate
  • CA-signed Device Certificate

Cause

For some reason, you need to replace the device certificate. One of it is that the Vulnerability scanner does not trust a self-signed certificate. 

Recommended Actions

1.) (Optional) Back up the current BIG-IP system's self-signed device certificate and key to /shared/tmp with the following bash commands:

cp /config/httpd/conf/ssl.crt/server.crt /shared/tmp
cp /config/httpd/conf/ssl.key/server.key /shared/tmp

2.) Generate the CSR:

Log in to the Configuration utility. Go to System > Certificate Management > Device Certificate Management > Device Certificate. Select 'Renew'. From the Issuer select 'Certificate authority' (Create the CSR in this section). Click 'Finished'.  Click Download server.csr or copy the value of "Request Text" to send to the CA.

3.) Send the CSR to your trusted third-party or internal CA and get the Certificate and Key (can be in a PEM file or separated cert/key).

Note: ensure that the new SSL key and certificate includes the client authentication (clientAuth) and server authentication (serverAuth) extended key usage (EKU) extensions.  

4.) Import the Certificate/Key received from the CA to System > Certificate management > Device certificate management > Device certificate. Click 'Import'.

After importing the certificate, you should see the new CA certificate reflected in the Certificate Management >  Device Certificate Management > Device Certificate section,  validate the information.

5.) In the case the CA provides an intermediate certificate, for proper iQuery communication you must append any chain or root certificates.

a. Copy the chain/root certificate files to the following directory:
/config/httpd/conf/ssl.crt/

b. Configure httpd to use the new combined chain certificate file to secure the Configuration utility. To do so, use the following command syntax:
tmsh modify sys httpd ssl-certchainfile /config/httpd/conf/ssl.crt/<chain_file_name>.crt 
              
c. Restart the httpd process to load the new certificates into the running configuration. To do so, use the following command syntax:
tmsh restart sys service httpd

After restarting the httpd daemon and refreshing the configuration utility, you should be able to see the new cert in your browser.

6.) Test the cert by running the bash command: 

openssl s_client -showcerts -connect <ip_address_of_configuration_utility>:443
 Note: Follow additional steps in Additional Information if this is a BIG-IP DNS (GTM) or a BIG-IP monitored by BIG-IP DNS.
 

Additional Information

The new CA (and any intermediate certificates) must be saved to the Trusted Certificate Store so that BIG-IP can verify the new device certificate for iQuery communication.

The CA (and any intermediate certificates) should be verified/imported in the following locations from the Configuration Utility:
All BIG-IP systems: System > Certificate Management > Device Certificate Management > Device Trust Certificates
BIG-IP DNS only: DNS > GSLB > Servers > Trusted Server Certificates

  • Remove the old self-signed certificates as they are no longer needed.
  • The CA (and any intermediate certificates) will verify the remote device from now on.
