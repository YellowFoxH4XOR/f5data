Known Issue

The BIG-IP system may erroneously return a negative value for certain Simple Network Monitoring Protocol (SNMP) management information base (MIB) object queries.

This issue occurs when all of the following conditions are met:

  • You attempt to monitor a BIG-IP object (for example, the ltm pool queue-depth-limit) using SNMP.
  • The BIG-IP object has a large positive value (greater than 2147483647).
  • The SNMP MIB object (for example, ltmPoolQueueDepthLimit) representing the BIG-IP object is classified as a 32-bit integer.

    The command and output to display the classification of the MIB object may appear similar to the following example:

    grep ltmPoolQueueDepthLimit F5-BIGIP-LOCAL-MIB.txt | head -1

    ltmPoolQueueDepthLimit                                 Integer32,

Impact

An SNMP query on the affected MIB objects may result in an incorrect value.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When performing an SNMP query, the BIG-IP system returns a negative value for the affected MIB objects.

    The following example shows the command to query the SNMP MIB object named ltmPoolQueueDepthLimit, which has a configured value of 4000000000, and its corresponding output:

    snmpwalk -v 2c -c public localhost ltmPoolQueueDepthLimit

    F5-BIGIP-LOCAL-MIB::ltmPoolQueueDepthLimit."/Common/bob" = INTEGER: -294967296
