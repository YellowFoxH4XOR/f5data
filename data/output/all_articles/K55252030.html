Description

BIG-IP Live Update may fail and generate an error message in /var/log/tomcat/liveupdate.log similar to the following:

curl: (60) SSL certificate problem: unable to get local issuer certificate

A packet capture between the BIG-IP device and the F5 Live Update address, callhome.f5.com, may show that the original callhome.f5.com certificate is replaced during the TLS/SSL handshake by a certificate issued by the organization’s internal CA.

In the packet capture, the client, BIG-IP, may send the following alert and terminate the handshake, resulting in Live Update failure:

TLSv1.2 Alert (Level: Fatal, Description: Unknown CA)

Environment

  • BIG-IP Live Update
  • BIG-IP’s route to the Internet is terminated or intercepted by a TLS/SSL proxy, such as SSL Orchestrator, a firewall with SSL decryption, or a web gateway.

Cause

The shell command curl is used by Live Update to access F5 Live Update services on the Internet. The command uses the CA bundle located at /config/ssl/ssl.crt/ca-bundle.crt to validate the server certificate.

When the organization’s internal CA certificate, which signs the replacement certificate presented by the TLS interception proxy instead of the actual F5 Live Update service certificate, is not included in this CA bundle, the TLS/SSL handshake fails.

Answer/Recommended Actions

Use the following commands to append the organization’s CA certificate to the BIG-IP CA bundle:

printf '\n' >> /config/ssl/ssl.crt/ca-bundle.crt

cat /var/tmp/company-root-ca.crt >> /config/ssl/ssl.crt/ca-bundle.crt

Please note that the CA bundle file is managed by the BIG-IP system. This means that after a TMOS upgrade, or after updating the CA bundle using the procedure in K60612439, the organization’s CA certificate will be overwritten. If that happens, you will need to append the organization’s CA certificate again after each update.
