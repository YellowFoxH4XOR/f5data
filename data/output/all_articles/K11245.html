K11245: Subdirectories are not moved as expected when the fileset is configured with the path match and recurse options

Known Issue

This is the result of a known issue. If the recurse option is configured with the path match option for a fileset, subdirectories are not moved as expected when the fileset is used by a place rule. The place rule report will show that only the top level directory specified by the path match configuration is found. As a result, the subdirectories under the top level directory are not moved.

For example, with the following fileset, only the /TopLevel/ directory will be moved. Any subdirectories in the /TopLevel/ directory will not be moved.

  policy-filename-fileset RecurseTest-FileSet
    path match /TopLevel/
    name match *
    recurse
    exit

F5 Product Development tracked this issue as ID 37639 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.

Workaround

To ensure subdirectories are found and moved by the place rule, you must add an asterisk (*) at the end of the path match statement.

For example, the fileset in the previous example should appear as follows:

  policy-filename-fileset RecurseTest-FileSet
    path match /TopLevel/*
    name match *
    recurse
    exit
