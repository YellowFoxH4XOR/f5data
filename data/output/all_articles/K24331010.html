Known Issue

The BIG-IP system does not remove IPsec tunnel security associations (SAs) when receiving an Invalid-SPI message for the SAs.

This issue occurs when all of the following conditions are met:

  • An IPsec peer deletes an SA before the agreed lifetime without sending a Notify Delete message to the BIG-IP system.
  • The BIG-IP system continues to use the affected IPsec tunnel SAs.
  • The BIG-IP system receives an Invalid-SPI message when trying to use the deleted security associations.

When an IPSec peer prematurely deletes an SA and does not send a Notify Delete message, the BIG-IP system continues to try to use the affected IPsec tunnel SA. The peer rejects the subsequent inbound SPI packets and replies with an Internet Security Association and Key Management Protocol (ISAKMP) Invalid-SPI notify message. When the BIG-IP system receives the Invalid-SPI message, the system does not remove the associated SAs. As a result, when the BIG-IP system is configured to always be the Initiator, and the peer is configured as the Responder, neither will initiate a new tunnel until the agreed lifetime expires.

Note: The remote IPsec peer system can be a BIG-IP system or third-party device.

Impact

The IPsec tunnel may experience traffic disruptions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The IPsec tunnel may experience intermittent traffic disruptions.
  • The BIG-IP system logs INVALID-SPI messages.

Workaround

To work around this issue, you can manually delete expired or invalid SAs using the TMOS Shell (tmsh). To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Display the SAs that have been negotiated with the IPsec peer, and determine the SPI of the expired or invalid SAs by using the following command syntax:

    show /net ipsec ipsec-sa dst-addr <IPsec_peer_addr>

  3. Delete the invalid SAs by using the following command syntax:

    delete /net ipsec ipsec-sa spi <invalid_spi>

  4. Save the change by typing the following command:

    save /sys config
