K000160919: Resolving /var/log disk utilization issues on BIG-IQ Data Collection Device due to excessive webd access.log growth

Description

On BIG-IQ Data Collection Device, the /var/log directory may experience rapid disk space consumption, leading to system instability, failed log collection, or inability to load the GUI. The primary symptom is abnormal growth of the /var/log/webd/access.log file. This occurs when the device receives a high volume of internal REST API polling requests, typically due to unresolved High Availability (HA) cluster formation issues between BIG-IQ Central Managers. Repeated disk space warnings may occur, and truncating or deleting large log files only provides temporary relief.

Environment

  • BIG-IQ Data Collection Device, version 8.4.1 (also applicable to 8.4.0)
  • /var/log mounted on a dedicated logical volume
  • HA cluster configuration with incomplete or failed failover/quorum between BIG-IQ Central Managers
  • Logrotate configured for /var/log, but not sufficient to prevent rapid log growth

Cause

Excessive internal polling requests to /mgmt/shared/failover-state are generated when the device believes it is part of an HA cluster but cannot establish quorum. Each polling request is logged in /var/log/webd/access.log, causing the file to grow rapidly and fill the /var/log partition. This behavior is directly linked to unresolved HA cluster formation issues.

Answer/Recommended Actions

  1. Resolve HA Cluster Issues
    • Address and resolve any HA cluster formation or failover issues between BIG-IQ Central Managers. Once HA is properly established, excessive polling and log growth will cease.
  2. Immediate Relief: Truncate Large Log Files
    • Identify the largest files in /var/log:

    find /var/log/ -xdev -type f -exec du {} \; | sort -rn | head -20

    • Truncate the access.log file to free up space (do not delete while webd is running):

    > /var/log/webd/access.log

    • Optionally, truncate /var/log/webd/access.log.1 if present.
  3. Temporary Workaround
    • If HA cannot be immediately resolved, set up an hourly cron job to truncate /var/log/webd/access.log as a stopgap measure.
  4. Monitor and Prevent Recurrence
    • Regularly monitor /var/log disk usage:

    df -h | grep /var/log

    • Ensure logrotate is properly configured for /var/log/webd/access.log.
    • Review and adjust log retention settings as needed.
  5. Verify Partition Mounts
    • It is expected behavior for /var/log to be mounted on a dedicated logical volume and shared across software volumes.
