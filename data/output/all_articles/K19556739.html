Topic

Client fingerprinting refers to a method in which a device ID is assigned to each browser that visits a website. A device ID is a unique string of characters that identifies the client device accessing your application. You can use the device ID to identify nefarious clients and diagnose security issues, such as session hijacking, web scraping, brute force login attempts, and others.

Description

The BIG-IP ASM system prevents many security issues and potential attacks by combining security features, such as the Session Hijacking feature, with a device identification method to track clients. The device ID and related security features allow the BIG-IP system to mitigate or block a specific client without affecting others.

When you enable a feature in the security policy that supports device identification, the BIG-IP system uses JavaScript to obtain a device ID for the client device. The JavaScript makes a series of function calls to determine the unique attributes of the client, such as the browser type and version, installed updates, installed fonts, and others. The BIG-IP ASM system encrypts and stores the device ID in the TSPD101 cookie, which remains with the client for the duration of the HTTP session. If the device ID or message key changes during the session or the session times out, the BIG-IP ASM system considers the request to be an attack and performs the actions defined in the learning and blocking settings for the policy. To use device ID mode, you must configure the feature in Bot defense profile and assign the profile to a virtual server.

Note: Changes to the browser or client, such as upgrading the browser or installing a font, may require the client to obtain a new device ID.

The following BIG-IP ASM security features use fingerprinting (device IDs):

  • Session Hijacking (Security > Application Security > Sessions and Logins > Session Tracking)
  • Session Awareness with Device ID Threshold (Security > Application Security > Sessions and Logins > Session Tracking)

    Note: You can enable the Device ID Threshold from the Block All, Log All Requests, and Delay Blocking tabs.

  • Bot Defense profile (Security > Application Security > Bot Defense > Bot Defense profile > Browsers > Device ID Mode) (15.x and later)
  • Brute Force Protection (Security > Application Security > Anomaly Detection > Brute Force Attack Prevention) (12.1.x through 14.1.0)
  • Web Scraping: Fingerprinting (Security > Application Security > Anomaly Detection > Web Scraping) (12.1.x through 14.1.0)

Recommendations

When configuring BIG-IP ASM features that use the device ID method, you should consider the following factors:

  • Use the Reporting page and the TMOS Shell (tmsh) to track the behavior of device IDs on your BIG-IP system. If either the average number of IP addresses associated with a single device ID, or the number of device IDs associated with a single IP address over an hour is high, using device IDs may not be suitable for your environment. You can track device ID usage as follows:
    • To track device IDs using tmsh, enter the following command:

      tmsh show /analytics dos-l7 report view-by device-id

    • To track device IDs using the Configuration utility, go to the following page:

      Security > Reporting > DoS > Dashboard

  • Use the tmsh list /security bot-defense profile <profile_name> deviceid-mode command to verify whether device ID mode is currently configured in the Bot defense profile assigned to your virtual server. 

    For example, the following command can be used to verify whether device ID mode is enabled for a Bot defense profile called MyBotDefense:

    tmsh list /security bot-defense profile MyBotDefense deviceid-mode
