Known Issue

The BIG-IP HTTP profile may block non-compliant HTTP traffic.

This issue occurs when the following condition is met:

  • The BIG-IP HTTP profile processes traffic which uses unknown HTTP extension methods.

Impact

The BIG-IP system may block valid HTTP traffic when you use the HTTP profile in pass-through mode.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe that the HTTP profile blocks HTTP payloads for unknown HTTP extension methods.
  • You observe that the HTTP profile completely blocks invalid HTTP traffic.

Resolution

Status

Note: If you upgrade to BIG-IP 11.4.1, you must also enable the appropriate database variables, and these actions may still not fix the issue. For more information about how to enable database variables, refer to K30321965: Overview of database variables to control non-compliant HTTP traffic. If you upgrade to BIG-IP 11.5.0 or later, you can use the Configuration utility to set the HTTP profile’s Proxy Mode to Transparent (pass-through mode) instead of enabling database variables.

Workaround

To work around this issue, you can create an iRule for your HTTP profile that filters for a particular unknown HTTP extension method or for all unknown HTTP extension methods. When the iRule encounters traffic matching the defined extension method or methods, it disables the HTTP profile and switches to pass-through mode. To do so, perform one of the following procedures:

  • Creating an iRule to filter for a particular unknown HTTP extension method
  • Creating an iRule to filter for all unknown HTTP extension methods

Creating an iRule to filter for a particular unknown HTTP extension method

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system. However, F5 recommends that you perform this procedure during a scheduled maintenance window and test the iRule in a staging environment to ensure effectiveness.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Enter a name in the Name box.
  5. In the Definition box, enter the following iRule syntax to disable the HTTP profile for a particular extension method:

    when HTTP_REQUEST {
       if { [HTTP::method] eq "<x>" } {
         HTTP::disable
       }
    }

    Note: In the previous syntax <x> indicates the name of the specific HTTP extension method you want the iRule to filter.

    For example, to disable the HTTP profile for the DVRGET HTTP extension method, enter the following text:

    when HTTP_REQUEST {
       if { [HTTP::method] eq "DVRGET" } {
         HTTP::disable
       }
    }

  6. Click Finished.

Creating an iRule to filter for all unknown HTTP extension methods

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system. However, F5 recommends that you perform this procedure during a scheduled maintenance window and test the iRule in a staging environment to ensure effectiveness.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Enter a name in the Name box.
  5. In the Definition box, enter the following text to disable the HTTP profile for all unknown HTTP methods:

    when HTTP_REQUEST {
       switch [HTTP::method] {
        "GET" -
        "POST" -
        "PUT" -
        "HEAD" -
        "DELETE" -
        "TRACE" -
        "CONNECT" {}
        default {
            HTTP::disable
            return
        }
      }
    }

  6. Click Finished.
