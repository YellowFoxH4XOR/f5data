Known Issue

This is the result of a known issue. Under rare conditions, using persistence mirroring on VIPRION systems may cause connections to stall. This issue occurs when a persistence query is sent from a TMM instance on one blade to a TMM instance running on another blade in the cluster. The remote TMM instance drops the entry, due to a full queue or the blade dies. The TMM instance sending the query will never receive a response from the receiving TMM and the connection will hang indefinitely.

F5 Product Development is tracking this issue as CR112031.

This issue was fixed in BIGIP-9.6.1-839.0-HF3, which was issued for BIG-IP version 9.6.1. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
