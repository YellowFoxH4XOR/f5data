K000157026: F5OS-A Not able to change LDAP filter in rSeries

Type
Support Solution
Published
2025-10-15
Updated
2025-10-15
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.8.3, 1.8.0
Source
https://my.f5.com/manage/s/article/K000157026

Description

  • Unable to change the LDAP filter used for authentication on an F5 rSeries appliance running F5OS 1.8.0. 
  • Despite configuring the system to use standard LDAP attributes for a Windows LDAP server, the device continued to send authentication queries using the POSIX 'posixAccount' filter, resulting in failed authentication attempts.

Environment

  • F5OS-A (rSeries Appliance), version 1.8.0
  • LDAP authentication configured for a Windows LDAP server (Active Directory)
  • Configuration set: system aaa authentication ldap active_directory false, system aaa authentication ldap unix_attributes false
  • LDAP over TLS (LDAPS) on port 7636

Cause

The root cause is a known software defect (Bug ID 1660961) in F5OS-A 1.8.0, where LDAP integration with Active Directory fails to use the correct filter when LDAP over TLS is configured. The system continues to use the POSIX 'posixAccount' filter due to this bug, regardless of configuration settings intended to disable UNIX attributes.

Recommended Actions

  • SSH into the system as root and create the following configuration file:

    /var/docker/config/platform.yml
    with contents: 
    version: '2.2'
services:
  authentication-mgr:
    environment:
      LDAPTLS_REQCERT: never
  userman:
    environment:
      LDAPTLS_REQCERT: never
  • Apply the workaround for Bug ID 1782925 to ensure the fix persists after a system reboot.
  • Reboot the system to apply changes.
