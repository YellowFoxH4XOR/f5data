Known Issue

The BIG-IP RAM cache may incorrectly serve responses with a 0 (zero) Content-Length.

This issue occurs when all of the following conditions are met:

  • The virtual server is configured with an iRule that invokes the CACHE::enable command.
  • The iRule's CACHE::enable command is triggered to cache the response for an HTTP HEAD request.

If an iRule invokes the CACHE::enable command for an HTTP HEAD request, the actual Content-Length of the OWS's HEAD response is replaced with a Content-Length of 0 (zero) when stored in the RAM cache. As a result, subsequent responses that the system serves from the RAM cache are served with a zero content length (Content-Length: 0).

Impact

Affected HTTP responses that the system serves from the RAM cache fail to display or render.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Responses that the system serves from the RAM cache fail to display or render.
  • The affected RAM cache response contains a Content-Length: 0 HTTP header.

Workaround

To work around this issue, you can modify your iRule to ensure it does not cache responses for HTTP HEAD requests.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.
