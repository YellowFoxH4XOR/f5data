Description

This article describes a scenario where configuration synchronization between BIG-IP DNS (GTM) devices fails. When attempting to add a device to the GTM sync group, the process does not complete and configuration changes (such as WideIP creation) do not replicate between devices. The following error may be observed in logs:

Unable to find LTM pool <pool_name> Note: This command requires an LTM pool.

This issue occurs when a GTM iRule references an LTM pool name that is not present on all devices in the sync group.

Environment

  • BIG-IP DNS (GTM) module
  • Two or more BIG-IP devices configured in a GTM sync group
  • Each device has a GTM iRule referencing a local LTM pool with a unique name (e.g., "pool1" and "pool2")
  • GTM sync group configured for configuration synchronization
  • iQuery connectivity established and device certificates exchanged
  • Log filters or systemd-journald log suppression may affect visibility of error messages

Cause

The GTM iRule references an LTM pool name that only exists locally on each device. i.e. when used in an HSL command:

set hsl [HSL::open -proto UDP -pool pool1]

Since GTM sync only synchronizes configuration in bigip_gtm.conf and not bigip.conf, the referenced pool must exist with the same name on all devices in the sync group. The absence of a common pool name causes the configuration load to fail and blocks DNS sync.

Recommended Actions

  1. Rename the LTM pool on each device so that it uses a common name (e.g., "my_pool_name") across all GTM devices in the sync group.
  2. Update the GTM iRule to reference this common pool name.
  3. Ensure that an LTM pool with this common name exists on all devices, even if their members differ.
  4. Re-run the GTM sync process to confirm successful synchronization.
  5. If troubleshooting is required, temporarily remove any log filters or disable systemd-journald log suppression to ensure relevant errors are visible.

Additional Information

  • Only bigip_gtm.conf is synchronized by GTM; referenced objects in ltm.conf must exist on all devices with identical names.
  • Pool members can differ between devices, but the pool object’s name must be consistent across all units.
  • Log filtering or suppression may hide critical error messages during troubleshooting.
