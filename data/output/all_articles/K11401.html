Known Issue

After installing the ENG-10.1.0-101 engineering hotfix for BIG-IP APM 10.1.0, users may be unable to load their configuration. This issue occurs when the BIG-IP APM configuration contains multiple Active Directory servers defined for the same domain but have different IP addresses. The users will receive the following error message:

BIGpipe unknown creation error: 010712f7:3: Existing aaa active directory server test2 uses Domain controller <IP Address> for the specified domain test.com. Domain controller must be <IP Address> for this domain.

The AAA server definition would appear similar to the following example:

aaa active directory server server1 {
domain controller "10.10.10.20"
domain "example.com"
admin name "test"
admin password crypt ";F=PX^d:Gj9Qn,pG@F:CYPW/=xoc;95[aKWAtRh_YwVYL;Z"
}
aaa active directory server server2 {
domain controller "10.20.20.30"
domain "example.com"
admin name "test"
admin password crypt "[3kfD[4.J<_Ot7^]Jd^ES[Qa=P)[:05Ib_C?jUbGLKPUO<j"
}

Two separate AAA objects are defined for the example.com domain: server1 and server2. The IP addresses are different for both. Whenever an access policy with an Active Directory server is edited and applied, the BIG-IP APM should update the /etc/krb5.conf file; however, the BIG-IP APM system does not update the /etc/krb5.conf file when multiple IP addresses are defined for the same domain. For example, the example.com configuration would look similar to the following:

[realms]
EXAMPLE.COM = {
kdc = 10.10.10.20
admin_server = 10.10.10.20
}

Even though two IP addresses are defined for server1 and server2, only the IP address of server1 is included in the configuration. The hotfix prevents BIG-IP APM administrators from creating multiple Active Directory AAA servers for the same domain with different IP addresses. However, the hotfix does not check the existing configuration. If the existing configuration has multiple Active Directory servers for the same domain with different IP addresses prior to the hotfix installation, the administrator will be unable to load the configuration after installing the hotfix.

F5 Product Development tracked this issue as CR128612 and was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP APM Release Notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing 10.x hotfixes on systems with a Logical Volume Management (LVM) disk-formatting scheme, refer to K10025: Managing BIG-IP product hotfixes (10.x). For information about installing 10.x hotfixes on systems with a partitioned disk-formatting scheme, refer to K9819: Managing F5 product hotfixes for BIG-IP version 10.0.x systems using the partitions disk formatting scheme.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

If your configuration matches the above scenario and the hotfix is already applied, the issue can be resolved by manually editing the bigip.conf file. You must change the AD definitions to have the same IP addresses for the domain name. For example, for example.com, you could modify the entries as follows:

aaa active directory server server1 {
domain controller "10.10.10.20"
domain "example.com"
admin name "test"
admin password crypt ";F=PX^d:Gj9Qn,pG@F:CYPW/=xoc;95[aKWAtRh_YwVYL;Z"
}
aaa active directory server server2 {
domain controller "10.10.10.20"
domain "example.com"
admin name "test"
admin password crypt "[3kfD[4.J<_Ot7^]Jd^ES[Qa=P)[:05Ib_C?jUbGLKPUO<j"
}

If the IP addresses are the same for the same domain name, it is considered a valid configuration and will properly load.
