Known Issue

The BIG-IP system may erroneously remove next hop RIP routes from the routing table.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is licensed for the Advanced Routing Module (ARM).
  • The RIP protocol is enabled on the system.
  • Two or more next hop routers announce the same destination network route to the BIG-IP system.
  • One upstream router withdraws and readvertises the route within the RIP timeout period.

For example, this issue may occur when the BIG-IP is configured to route traffic to multiple next hop destinations (for example, RouterA and RouterB). If one of the next hop routers (RouterA) withdraws and readvertises the route within the RIP timeout, the BIG-IP system will delete that router's RIP routes for the destination. This will prevent the BIG-IP system from being able to route to the destination until the system establishes the second router's (RouterB) routes.

Impact

This issue may result in routing disruptions on the affected network segment.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Unexpired next hop RIP routes may flap on the BIG-IP system.

Workaround

To work around this issue, create static routes for the upstream routers, and then restart the tmrouted process. To do so, perform the following procedures:

Creating static routes using the Configuration utility

Impact of workaround: None.

  1. Log in to the Configuration utility.
  2. Click Network.
  3. Click Routes.
  4. Click Add.
  5. Define the appropriate route to the upstream router.
  6. Repeat steps 1-5 for additional upstream routers.

Restarting the tmrouted process

Impact of workaround: Restarting the tmrouted process will cause all dynamically learned routes to be temporarily unavailable.

  1. Log in to the command line.
  2. Type the following command:

    bigstart restart tmrouted
