Description

Fault detected in LCD module

Environment

  • F5OS-A
  • LCD

Cause

You will see these below events and alarms regarding the LCD Health is Not OK. There is no impact on traffic only an impact to the LCD module.

Recommended Actions

Impact of procedure: LCD functionality will be unavailable while the LCD module is rebooting.

  1. Check the platform logs.
  2. Log in to CLI as root, and run below command in bash mode:
    lsusb | grep f5f5
    If the output shows f5f5:df11, then it means that LOP is in bootloader mode. If it does not have f5f5:df11 in the output, then you will need to reset the LCD.
  3. To reset the LCD module, run the command below:
    docker exec platform-hal psf call post:lcd/reboot
  4. Once you run this command, it will appear to hang and take a minute or two before it returns an output. It will appear similar to:
    [root@appliance-1(R2600-R9-S20) ~]# docker exec platform-hal psf call post:lcd/reboot
    field | value
    ----------+--------
    success | true
  5. Then run this below command to check the LCD status:
    docker exec platform-hal psf call get:lcd/health
