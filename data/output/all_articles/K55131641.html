Description

A quick reference for iRule logging and debugging commands.

Environment

  • BIG-IP
  • Virtual servers
  • iRules

Cause

None

Recommended Actions

  • Debugging
  • Constant Logging
  • Statistical Sampling
Debugging

When you want to add logging to your iRule that you can turn on and off, consider using a static variable.

when RULE_INIT {
    # Using unique <rulename>_debug variable name will prevent this variable from colliding with other iRules
    set static::<rulename>_debug 1 
}

when <EVENT> {
    # Tests debug variable to see if it should log
    if { $static::<rulename>_debug } {log <facility>. "<message>"}
}

Constant Logging

When you want to log something every time the iRule executes, use a log command outside of a conditional statement.

when <EVENT> {
    # Unconditional logging statement
    log <facility>. "<message>"
}

Statistical Sampling

When you need to sample data from connections, but have concerns about the performance impact your device may experience from logging all traffic, consider using this method to log a configurable portion of the traffic.

when <EVENT> {
    # Statistical sampler; Set sample_percent to whatever percentage of traffic you would like to collect. Value must be greater than zero and less than or equal to 100. This example will log 35% of events
    set sample_percent 35

    # This example will log the request to <facility>, but can and should be configured to use high speed logging to a remote device if put into production.
    if { $sample_percent >= rand()*100 } { log <facility>. "<message>" }
}
