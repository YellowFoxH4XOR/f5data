Description

  • When attempting an API call, the BIG-IP Next subsystem returns a 500 internal server error
  • The API never comes online
  • You are unable to log in via the Local Manager or Central Manager
  • You are unable to gather a qkview
     

Environment

  • BIG-IP Next system Virtual Edition

Cause

This can have one or more causes
1. One or more of the internal subsystems is failing to start

  • f5-csm-icb
  • f5-csm-api-engine
  • f5-eesv-vault
  • data-store

2. <something else>

Recommended Actions

While logged in as root on the BIG-IP Next VM, run kubectl to get the status of the potentially affected pods.  All pods should be running.

kubectl get pod | grep 'data-store\|vault\|csm'

Look for errors in the API engine log file

grep -i "err" /opt/f5/mbip-ve/f5-toda-logs/log/f5-csm-api-engine-stdout.log

Additional Information

When the API server is not functioning, it is a catastrophic error because you cannot interact with the BIG-IP Next system via the API.  This means you cannot run any diagnostics via the API, you cannot run qkview or tcpdump, and you are forced to enter the terminal of the VM, su to root, and run direct kubectl commands to do additional diagnosis.  It may be easier to delete the VM and start over than to try to diagnose why the API failed to start.
