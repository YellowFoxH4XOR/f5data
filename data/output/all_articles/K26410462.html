Topic

You should consider using this procedure under the following condition:

  • You want to configure the BIG-IP APM system to perform secure network address translation (SNAT).

Description

You can configure SNAT on the BIG-IP APM system to change the client source IP address for traffic destined to the server, which then uses the new source IP address as the destination when responding to the request. This configuration ensures that the server response is sent back through the BIG-IP APM system.

You can apply SNAT settings for app tunnels, optimized applications, remote desktops, portal access, Citrix connections, and LTM+APM deployments in the access policy session and override the SNAT settings for the virtual server.

You apply SNAT settings for a Network Access tunnel in the Network Access resource Network Settings. The BIG-IP system does not use the SNAT settings for the virtual server for Network Access.

You can also apply SNAT using a layered virtual server matching the server-side destination address. If BIG-IP APM traffic matches another user-defined virtual server while egressing the server-side, the system applies the SNAT settings from the last user-defined virtual server to the connections.

To configure SNAT on the BIG-IP APM system, perform the following procedures as needed:

  • Configuring SNAT in an access policy
  • Configuring SNAT in the Network Settings of a Network Access resource
  • Configuring SNAT using a layered virtual server

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the Configuration utility.

Procedures

Configuring SNAT in an access policy

You can use the Route Domain and SNAT Selection access policy setting to specify the source IP address to use in server-side traffic for app tunnels, optimized applications, remote desktops, portal access, Citrix connections, and LTM+APM deployments. You first create a SNAT pool specifying the source IP address for the system to use, then apply the SNAT pool to the access policy using the Route Domain and SNAT Selection access policy setting. To do so, perform the following procedure:

Note: If you don't have SNAT configured in the access policy for portal access and LTM+APM deployments, the system uses the SNAT setting for the virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Address Translation > SNAT Pool List.
  3. Click Create.
  4. Type a name for the SNAT pool.
  5. In Member List, for IP Address, type the IP address to use as the server-side source IP address.
  6. Click Add.
  7. Click Finished.
  8. Navigate to Access > Profiles / Policies.

    Note: For BIG-IP 11.x - 12.x, navigate to Access Policy > Access Profiles.

  9. Click Edit in the Per-Session Policy column for the access profile you want to edit.

    The visual policy editor opens for the access policy.

  10. In the visual policy editor, click the (+) icon to add a new policy item.
  11. Click the Assignment tab.
  12. Click Route Domain and SNAT Selection and then click Add Item.
  13. In the Route Domain list, click 0.
  14. In the SNAT list, click snatpool.
  15. In the SNAT Pool list, click the SNAT pool you created previously.
  16. Click Save.
  17. Click Close to close the visual policy editor.
  18. Select the check box for the edited access profile and click Apply.

    Note: For BIG-IP 11.x - 12.x, click Apply Access Policy.

Configuring SNAT in the Network Settings of a Network Access resource

You apply the SNAT settings for BIG-IP APM Network Access tunnels in the Network Settings of the Network Access resource. When configuring SNAT for the Network Access resource, you can click None, Automap, or specify a previously configured SNAT pool. To create a SNAT pool and reference that SNAT pool in the Network Access resource settings, perform the following procedure:

Note: If the SNAT Pool setting in the Network Access resource is set to Automap, the system uses the non-floating self IP address for the connection. To use the floating self IP address, create a SNAT pool specifying the floating IP address and associate the SNAT pool with the Network Access resource.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Address Translation > SNAT Pool List
  3. Click Create.
  4. Type a name for the SNAT pool.
  5. In Member List, for IP Address, type the IP address to use as the server-side source IP address.
  6. Click Add.
  7. Click Finished.
  8. Navigate to Access > Connectivity / VPN > Network Access (VPN).

    Note: For BIG-IP 11.x - 12.x, navigate to Access Policy > Network Access.

  9. Click the name of the network access resource.
  10. Click the Network Settings tab.
  11. Under General Settings, in the SNAT Pool list, click the SNAT pool you created previously.
  12. Click Update.

Configuring SNAT using a layered virtual server

You can specify the source IP address the system uses for traffic to servers by configuring a SNAT pool on a layered virtual server. The SNAT setting for the layered virtual server is applied to matching server-side BIG-IP APM traffic as it egresses the BIG-IP system. To create a layered virtual server with a SNAT pool, perform the following procedure:

Note: Layered virtual servers do not apply for Citrix Independent Computing Architecture (ICA) and VMware PC over IP (PCoIP) User Datagram Protocol (UDP) traffic. The system always sends this traffic directly to the destination server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Address Translation > SNAT Pool List
  3. Type a name for the SNAT pool.
  4. In Member List, for IP Address, type the IP address to use as the server-side source IP address.
  5. Click Add.
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click Create.
  9. Type a name for your virtual server.
  10. In the Type list, click the type of virtual server. For example, Forwarding (IP).
  11. For Destination Address, depending on your configuration, type the host IP address of your server or the destination network address and mask prefix for the server resource. The system processes traffic by the layered virtual server with the most specific match.
  12. For Service Port type the port for which your server is configured to accept traffic and click the appropriate port type in the list.
  13. In the Protocol list, click the protocol to use for the traffic.
  14. In the Source Address Translation list, click SNAT, and then in the SNAT Pool list, click the name of the SNAT pool you created previously.
  15. Click Finished.
  16. Navigate to Local Traffic > Virtual Servers > Virtual Address List.
  17. Click the IP address of the newly created layered virtual server.
  18. Under Configuration, clear the ARP check box.
  19. Click Update.
