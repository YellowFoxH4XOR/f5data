K74137570: Failed to delete Legacy Application Service: Failed to get cm-bigip-allBigIpDevices device

Type
Support Solution
Published
2021-12-31
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IQ Platforms
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.X.X, 7.X.X
Source
https://my.f5.com/manage/s/article/K74137570

Description

Big IQ is unable to remove Legacy Application Service in GUI and gives an error similar to below:

"Failed to delete APP_NAME. Failed to delete Legacy Application Service: Failed to get cm-bigip-allBigIpDevices device for machine id 1560d977-a91a-4247-b407-cfecc5fe1gdd: Device not found in device group: Device not found in device group: Failed to get cm-bigip-allBigIpDevices device for machine id 1560d977-a91a-4247-b407-cfecc5fe1gdd: Device not found in device group: Device not found in device group"

Environment

  • BIG-IQ CM 7.x, 8.x
  • Legacy Application Service

Cause

In BIG-IQ database there is a dependency to non-existing BIG-IP which is blocking application removal.  

Recommended Actions

Remove wrong device ID using following procedure:
  1. Log in to BIG-IQ CM CLI (bash console)
  2. Take the device ID from the error and assign it to the variable
    deviceid=<Device-ID-From-Error>
    Example:
    deviceid=1560d977-a91a-4247-b407-cfecc5fe1gdd

  3.  Search for the wrong association 

    broken_device_group=$(restcurl -u admin:admin /mgmt/cm/shared/cluster-health/ | grep "$deviceid\|selfLink" | grep "machineId" -A 1 | grep "selfLink" | tr -d "\", " | cut -c 27-) ; restcurl -u admin:admin $broken_device_group

    Example output:

    {
      "id": "ec9b4f15-1a98-3cc8-8142-9b4f14e9b4f1",
      "kind": "cm:shared:cluster-health:clusterhealthstate",
      "name": "Prod_LTM",
      "devices": [
        {                                                             <------------------
          "machineId": "1560d977-a91a-4247-b407-cfecc5fe1gdd"         <------------------ Section with not removed correctly machineID
        },                                                            <------------------
        {
          "asmSync": "disabled",
          "autoSync": "disabled",
          "machineId": "a3a9a6ca-efc3-efc3-b752-b9efc3a6c392",
          "failoverGroup": "/Common/device-group-failover-My_Failover"
        },
        {
          "asmSync": "disabled",
          "autoSync": "disabled",

        }
      ],
      "selfLink": "https://localhost/mgmt/cm/shared/cluster-health/ec9b4f15-1a98-3cc8-8142-9b4f14e9b4f1",
      "generation": 5,
      "useBigiqSync": false,
      "lastUpdateMicros": 1615378541205742,

        "link": "https://localhost/mgmt/shared/resolver/device-groups/cm-bigip-cluster_Prod_LTM"
      },

    }
  4. Copy the output to some text editor and remove the section with the wrong device ID like in example:

          "failoverGroup": "/Common/device-group-failover-My_Failover"
        },
        {
          "asmSync": "disabled",
          "autoSync": "disabled",

        }

  5. Patch wrong association with edited data from 4th point:
    restcurl -u admin:admin -X PATCH $broken_device_group -d '<edited-output>'

    Example:

      "id": "ec9b4f15-1a98-3cc8-8142-9b4f14e9b4f1",
      "kind": "cm:shared:cluster-health:clusterhealthstate",

        },
