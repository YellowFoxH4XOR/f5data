Topic

This article applies to BIG-IP 9.4.0 through 11.3.0. For information about other versions, refer to the following articles:

  • K14996: Configuring a virtual server to automatically redirect HTTP requests to HTTPS (11.4.0 and later)
  • K3847: Configuring a virtual server to automatically redirect HTTP requests to HTTPS (9.0.0 - 9.3.1)

Description

In BIG-IP LTM 9.0.0 through 9.3.1, it is necessary to create an iRule to configure a virtual server to automatically redirect HTTP requests to HTTPS. Beginning in BIG-IP 9.4.0, you can configure an HTTP class profile to cause the virtual server to redirect HTTP requests to HTTPS.

Though iRules continue to work and are more flexible in BIG-IP 9.4.0 and later, HTTP classes are more efficient than iRules, and you should use HTTP classes wherever possible.

Note: For more information about the HTTP Class profile, refer to K7280: Overview of the HTTP class profile.

Configuring an HTTP class profile to cause the virtual server to redirect HTTP requests to HTTPS

To configure an HTTP class profile so that the virtual server automatically redirects HTTP requests to HTTPS, you must perform the following procedures:

  • Creating an HTTP class profile to automatically redirect HTTP requests to HTTPS
  • Associating the HTTP class profile with the virtual server

Creating the HTTP class profile to automatically redirect HTTP requests to HTTPS

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles.
  3. For Protocol, select HTTP Class.
  4. Select Create.
  5. Type the name of the profile.
  6. For Parent Profile, select httpclass.
  7. For Actions, select the Send To check box.
  8. For Send To, select Redirect to.
  9. Enter the following in the Redirect to Location dialog box to preserve the host and URI information when rewriting the redirect to HTTPS:

    https://[getfield [HTTP::host] ":" 1][HTTP::uri]

    Note: The [getfield [HTTP::host] ":" 1] function extracts the host name from the host header and, if a non-standard port is specified, it removes the port from the host header.

    Note: Redirect to Location may contain a regular string or an appropriate TCL expression.

  10. Select Finished.

Associating the HTTP class profile with the virtual server

Note: The following procedure applies to an HTTP virtual server. There is no configuration change required on the HTTPS virtual server.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the virtual server you want to associate with the HTTP class profile.
  4. Select Resources.
  5. For HTTP Class Profiles, select Manage.
  6. For Resource Management, move the appropriate HTTP class profile to Enabled.
  7. Select Finished.
