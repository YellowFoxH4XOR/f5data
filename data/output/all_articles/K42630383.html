Known Issue

The logstatd process may unexpectedly restart.

This issue occurs when the following condition is met:

  • Your BIG-IP system processes a syslog message that is greater than 8 KB in size.

Impact

The logstatd process exits and restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP APM system displays repeating console messages similar to the following example:

    emerg logger: Re-starting logstatd

  • Garbled messages are logged to the /var/log/messages and /var/log/user.log files.
  • Log messages similar to the following example are logged to the /var/log/messages file:

    notice syslog-ng[<pid>]: Configuration reload request received, reloading configuration;

Workaround

To work around this issue, you can modify the syslogd-ng.conf configuration to limit the processed message size to 8 KB or less. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) of the affected system by typing the following command:

    tmsh

  2. Set the maximum processed syslog message value to your desired value (ensure that the value does not exceed 8192 bytes) by typing the following command syntax:

    modify /sys syslog include "options {log_msg_size(<desired size>); };"

    For example, you would type the following command to limit the processed message size to 8192 bytes:

    modify /sys syslog include "options {log_msg_size(8192); };"

  3. Save the configuration changes by typing the following command:

    save /sys config

  4. To exit the tmsh utility, type the following command:

    quit
