Description

When managing the BIG-IP via ssh, from a remote network, connection often gets stuck after a few seconds or when running longer tmsh or bash commands.

Environment

  • SSH connection to BIG-IP
  • Management interface
  • Auto Last-Hop feature is enabled on the BIG-IP MGMT interface

Cause
Auto Last Hop feature on the BIG-IP management interface ignores the path MTU data. As a result, responses sent over the management interface may have the Do Not Fragment flag set, and the responses may be too large for the intermediate device to receive them.
Bug ID 554506: PMTU discovery from management does not work

Recommended Actions

  • This article provides a workaround to the issue by reducing the MTU value for the management interface to match the smallest MTU of the path.
    K47835034: Responses transmitted from the BIG-IP management interface may be too large to reach the destination

  • Alternatively, you can simply disable auto last-hop for the management interface. To do this:

  1. Log in to the command line of the BIG-IP

  2. Type this command:
    #tmsh modify /sys db mgmt.autolasthop value disable

  3. For changes to take effect, reboot the device

  4. To verify the auto last-hop feature is disabled run:
    #tmsh list sys db mgmt.autolasthop value

Additional Information
Note that before disabling the auto last-hop for the management interface, you need to make sure you have in place management routes to reach any remote management networks. To create management routes, please refer to this article:
K13284: Overview of management interface routing (11.x and later)
