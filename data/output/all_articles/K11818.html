Known Issue

This is the result of a known issue. If an iRule executes both the ACCESS::session data get and ACCESS::respond commands, and Clustered Multiprocessing (CMP) is enabled on the virtual server, the Traffic Management Microkernel (TMM) may fail to respond to the client request that triggered the iRule. This issue occurs intermittently and only affects the specific request that triggered the iRule. In most instances, the issue does not recur when the client resubmits the request.

Note: The iRule ACCESS commands require the BIG-IP APM module. For more information about iRule commands and syntax, refer to DevCentral. A separate DevCentral login is required to access this content.

F5 Product Development tracked this issue as ID 328315 and ID 324335 (formerly CR140323) and it has been fixed in BIG-IP 10.2.1. For information about upgrading, refer to the BIG-IP APM release notes.

In addition, this issue has been fixed in Hotfix-BIGIP-10.1.0-3402.0-HF2 issued for BIG-IP 10.1.0, and Hotfix-BIGIP-10.2.0-1755.1-HF1 issued for version 10.2.0. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.
