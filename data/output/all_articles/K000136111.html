K000136111: APM Kerberos AAA error "No key table entry found matching HTTP/<FQDN>@"

Type
Support Solution
Published
2023-09-06
Updated
2024-06-25
Applies to
  • BIG-IP
  • BIG-IP APM: 16.1.4, 17.1.1, 15.1.9, 17.0.0, 17.0.X, 17.1.0, 17.1.X, 17.X.X, 15.1.10
Source
https://my.f5.com/manage/s/article/K000136111

Description

You observe Kerberos AAA errors similar to those below on your BIG-IP APM system:

Sep 30 11:13:51 bigip debug apmd[14480]: 01490266:7: /Common/ap1:Common:12345678: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'PrintGssErrorImpl()': 177: 12345678 : GSS-API error gss_acquire_cred_from: d0000 : Unspecified GSS failure. Minor code may provide more information
Sep 30 11:13:51 bigip debug apmd[14480]: 01490266:7: /Common/ap1:Common:12345678: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'PrintGssErrorImpl()': 177: 12345678 : GSS-API error gss_acquire_cred_from: 25ea101 : No key table entry found matching HTTP/apm.example.com@

Environment

  • BIG-IP with APM
  • Kerberos AAA (client authentication)
  • FQDN used to access the APM Virtual Server is an alias of the FQDN used to create the keytab file

Cause

Starting in BIG-IP v15.1.9, v16.1.4, v17.0.0 or later versions of the krb library is used, which no longer does rDNS resolution to retrieve the FQDN used in the keytab file. Instead the FQDN used to access the APM Virtual Server is used. This value is stored in the APM session variable "session.server.network.name". If the FQDN used to access the APM Virtual Server is an alias of the FQDN used to create the keytab file, the entry cannot be found and the Kerberos authentication fails.

Recommended Actions

  1. Create a Variable Assign VPE item just before the Kerberos Auth VPE item to save the current value of the APM session variable "session.server.network.name" to a custom variable and assign the FQDN used to create the keytab file (the FQDN which the alias is pointing to) to the APM session variable "session.server.network.name".
  2. Create a Variable Assign VPE item just after the Kerberos Auth VPE item to assign the value of the custom variable created in step 1 to the APM session variable "session.server.network.name".
  3. Make sure that "Request Based Auth" is set to "Disabled" in the "Kerberos Auth" VPE object
