K22535664: ASM process is continuously restarting in version 16.1.0.

Type
Support Solution
Published
2021-10-05
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 16.1.0
Source
https://my.f5.com/manage/s/article/K22535664

Description
After upgrading to version 16.1.0, the ASM process is continuously restarting. CLI is filled with such messages and botd is also down. 
The output of tmsh show sys service all, shows multiple restarts of the ASM and botd.
You can specify those two services with following command:

# tmsh show sys service asm botd
asm          run (pid 25160) 0 seconds, 2 starts, 38 restarts
botd         down, waiting for asm to release ready semaphore

After upgrading the system, the ASM initial configuration script fails with the below error message in /var/log/ts/ts_debug.log: 

asm|INFO|Sep 23 22:34:07.480|16920|,,01070265:3: The ASM policy (/Common/testASMPolicy) cannot be deleted because it is in use by a API Protection Profile (/Common/testAPIProfile)
asm|INFO|Sep 23 22:34:07.507|16920|,,failed to initialize

Environment

  • BIG-IP ASM
  • TMOS version 16.1.0
  • Error message referencing an API Protection Profile

Cause
The issue is identified as Bug ID 1051237
This issue occurs If ASM security profile is configured and referenced with an API protection profile, and the configuration is loaded, or upgraded to affected version with such configuration

Recommended Actions

  1. Disable liveinstall.saveconfig and liveinstall.moveconfig on the device by running the below commands in tmsh mode.
    Refer to article  K13438: Controlling configuration import when performing software installations
    modify /sys db liveinstall.moveconfig value disable
    modify /sys db liveinstall.saveconfig value enable
  2. Save the changes. 
    save /sys config
  3. Proceed with performing the software installation using the Configuration utility, in case of an upgrade.
  4. Provision ASM module and wait for the device to become Active
  5. Load (using TMSH) the UCS file by following the process in section
    Restore configuration data from the command line using tmsh:  from K13132: Backing up and restoring BIG-IP configuration files with a UCS archive

Additional Information
When liveinstall.moveconfig and liveinstall.saveconfig is disabled, no configuration will be installed on the target boot location. Please refer K13438: Controlling configuration import when performing software installations for more information.
