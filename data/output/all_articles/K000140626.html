K000140626: F5OS-A rSeries software upgrade failed after installing optics-mgr-package "OStree rebase to version <ver> failed"

Published

Description

Attempted to upgrade F5OS-A after installing optics-mgr-package following K000138946.

Upgrade failed (in this example, from F5OS-A v1.5.2 to F5OS-A v1.7.0):

R5600# show system image install
system image state install install-os-version 1.5.2-21056
system image state install install-service-version 1.5.2-21056
system image state install install-status failed

Messages similar to the following are observed in /var/log/sw-util.log:

Rebasing to velocity:1.5.2-21056
0 metadata, 0 content objects imported
Checking out tree 7cdf9c9... + date
<...>
Enabled rpm-md repositories: base updates extras
error: cannot update repo 'base': Cannot prepare internal mirrorlist: Curl error (6): Couldn't resolve host name for http://mirrorlist.centos.org/?release=7&arch=x86_64&repo=os&infra=$infra [Could not resolve host: mirrorlist.centos.org; Unknown error]
+ log_message LOG_FATAL_UPGRADE_OSTREE_REBASE_FAIL '${command}' 1.5.2-21056
<...>
++ jq -r .LOG_FATAL_UPGRADE_OSTREE_REBASE_FAIL.id /etc/logging/sw-mgmt.json
+ local msg_num=021
++ jq -r .LOG_FATAL_UPGRADE_OSTREE_REBASE_FAIL.message /etc/logging/sw-mgmt.json
+ local 'msg_str=OStree rebase to version %s failed.'
++ printf 'OStree rebase to version %s failed.' 1.5.2-21056
+ local 'msg=OStree rebase to version 1.5.2-21056 failed.'

Environment

  • Software upgrade
  • rSeries r5x00 or above
  • optics-mgr-package

Cause

Bug ID1621861 – Install of optics-mgr-package breaks 'rpm-ostree rebase' during SW upgrade.

Recommended Actions

ID1621861 has no fix at the time of this article's publication.

To work around the issue, uninstall the optics-mgr-package, then perform the software upgrade. You may re-install the optics-mgr-package after the upgrade has completed.

Follow the steps in K000138946 to uninstall the optics-mgr-package.

Note: Installing or uninstalling the optics-mgr-package triggers a system reboot.

Additional Information

If this issue is encountered on F5OS-A v1.5.1 or earlier, your rSeries system may proceed in upgrading the services version, even if the OS version upgrade has already failed.

R5600# show system image install
system image state install install-os-version 1.5.1-12283       <-- OS version failed
system image state install install-service-version 1.5.2-21056  <-- But service version has still upgraded
system image state install install-status failed

This is undesirable behaviour, and is a result of bug ID1181929.

If you encounter this problem you can follow the same workaround described above to recover - the base OS version should be upgraded to match the services version.

This symptom should should not occur when upgrading from F5OS-A v1.5.2 or later. Neither the base or services version will be upgraded if software upgrade fails due to ID1621861.
