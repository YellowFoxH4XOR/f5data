Description

DNS resolution for a RRs in the affected zone fails with "SERVFAIL"

  • BIND fails to load a zone file after manual zone file modification and generates error similar to below
    Jun 13 15:06:35 bigip.dns.local err named[26657]: 13-Jun-2020 15:06:35.754 general: error: db.external.example.com.:1: no current owner name

 

Environment

  • Manual editing of the zone file
  • At least one leading white space in zone SOA, zone TTL or zone default FQDN section

Cause

If a resource record name (that starts in the first column) is a space or tab, then the name from the last resource record is used.
This error is produced when a line in a zone file contains leading white space (tabs/spaces) but there is no current record owner name to inherit the name from.

Recommended Actions

Remove leading space or tab in zone SOA, zone TTL or zone default FQDN section

F5 highly recommend to do any zone files updates using ZoneRunner utility only. If there is a specific reason to modify a zone file manually, please keep in mind the steps recommended by F5 listed in "Supplemental Information" section

Additional Information

K7032: Freezing zone files to allow manual update to ZoneRunner-managed zone files

Important: When making manual changes to a BIND zone file, you must remember to increment the serial within the zone.  Failing to do so will prevent the zone update from synchronizing with other BIG-IP DNS systems and DNS servers.
