Known Issue

The BIG-IP system incorrectly sends TCP RST or ICMP unreachable packets in response to incoming connections that cannot be matched with virtual server connections when the tm.rejectunmatched db key is set to false. The BIG-IP system only behaves incorrectly for virtual servers using a FastL4 profile.

The tm.rejectunmatched db key is set to true by default and the BIG-IP system sends a TCP RST or ICMP unreachable packet for incoming packets that cannot be matched with virtual server connections. When the key is set to false, the system is supposed to silently drop unmatched packets.

Impact

The BIG-IP system may unexpectedly send TCP RST or ICMP unreachable packets.

Symptoms

As a result of this issue, the BIG-IP system may experience the following symptoms:

  • Packet captures may indicate that the BIG-IP system is incorrectly sending TCP RST or ICMP unreachable packets in response to unmatched packets.
