Topic

You can configure the BIG-IP system to automatically populate node and pool member lists by using a fully qualified domain name (FQDN).

Description

When you configure the BIG-IP system to auto-populate pools, the system queries the DNS server for FQDN information at the interval provided in the node configuration and updates the node and pool member list with the information from A and AAAA type records provided in the DNS response. For example, a DNS query for the www.example.net FQDN returns three A records, similar to the following:

;; ANSWER SECTION:
www.example.net.              38400   IN      A       10.12.23.1
www.example.net.              38400   IN      A       10.12.23.2
www.example.net.              38400   IN      A       10.12.23.3

Note: the BIG-IP system ignores all records types returned in the DNS response except A and AAAA, even if the other record types contain IPv4 and IPv6 addresses.

After receiving this information, the BIG-IP system allows you to build a node and pool member list similar to the following example:

# tmsh list ltm pool example.net | grep address
            address 10.12.23.1
            address 10.12.23.2
            address 10.12.23.3

Impact to existing connections when using FQDN to auto-populate the BIG-IP pool configuration

If the BIG-IP system queries the DNS server and DNS information for the FQDN has changed, the BIG-IP system updates its configuration. The BIG-IP system updates the node and pool member configuration by adding or removing members. Added pool members become available to load balance new connections, and removed pool members impact existing connections. This configuration change can occur while the BIG-IP system processes traffic, and you should understand how this event impacts information that relates to current connections (such as connection table entries, persistence table entries, and pool member monitoring).

Connection table entries

When a pool member is removed, the existing established connections are not disrupted. The connection remains until the client disconnects, and then load balancing decisions no longer includes the removed pool member.

Persistence table entries

When a pool member is removed, the existing persistence table entries are removed and returning clients can load balance using the updated pool member list.

Pool member monitoring

When a pool member is removed, pool member monitoring discontinues immediately.

Recommendations

If you have configured the BIG-IP system to auto-populate the configuration based on a DNS server response, you should consider the following factors:

  • DNS servers

    The BIG-IP system allows you to configure multiple DNS servers. If you decide to use multiple DNS servers, ensure that they receive DNS information at the same time and from the same DNS source. In addition, make sure the DNS servers return all of the A records used to populate the pool and not a partial list of A records or IP addresses.

  • Interval 

    You configure the Interval setting on the node. The value is the number of seconds before the BIG-IP system performs a DNS query for the given FQDN. The BIG-IP system creates new nodes or delete ephemeral nodes based on the IP addresses in the DNS response. For more information, refer to K47726919: The FQDN ephemeral nodes refresh behavior on the BIG-IP system.

    Note: The default setting is 3600 seconds.

  • Down Interval 

    You configure the Down Interval setting on the node. The value is the number of seconds before the BIG-IP system begins querying the DNS server after it receives a failed DNS query. The BIG-IP system continues to load balance by using the current node and pool member list until a successful DNS response is received.

    Note: The default setting is 5 seconds.
