Topic

You should consider using this procedure under the following condition:

  • You want to configure more than one DNS server for the DNS Express feature.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to your DNS servers.
  • You can access the Configuration utility for your BIG-IP system.
  • You have previously configured a DNS Express virtual server or listener.

    For details, refer to the Enabling DNS Express section of the Configuring DNS Express on BIG-IP Systems chapter in the BIG-IP Global Traffic Manager: Implementations guide.

    Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

  • You have two available IP addresses to use for virtual servers, including a TCP virtual server to use as the Target IP Address in the DNS Express Zone, and a User Datagram Protocol (UDP) virtual server to process and forward DNS NOTIFY messages. F5 recommends that you use addresses that are non-routable on the Internet, or an internal IP address.

Description

The DNS Express feature enables you to offload the DNS requests from your authoritative DNS servers and allows the BIG-IP system to act as a high-performance secondary DNS server for all of your DNS zones. By default, the DNS Express feature allows you to configure only one Target IP Address for requesting zone transfers from the authoritative Primary DNS server.

If you need to configure more than one DNS server for zone transfers, you can configure the DNS servers to be in a pool, and associate the pool with a TCP virtual server. You can then configure the TCP virtual server IP address as the Target IP Address in the DNS Express Zone. Finally, to manage and forward incoming DNS NOTIFY messages, you can configure a DNS profile and iRule, and then associate them with a UDP virtual server. To do so, perform the following procedures:

11.5.0 and later

Configuring the authoritative DNS servers to allow zone transfers

Before configuring the necessary resources on the BIG-IP system, you must configure the authoritative DNS servers to allow zone transfer requests from the BIG-IP system. For BIND-based DNS servers, you must add the self IP address or the secure network address translation (SNAT) address of the BIG-IP system to the allow-transfer statement. For example, the following allow-transfer statement in a BIND-based DNS server allows the BIG-IP system with self IP address 192.168.1.17 to request zone transfers:

allow-transfer { localhost; 192.168.1.17; };

For more information about modifying your DNS server to allow zone transfer from a remote host, refer to the documentation for your DNS server.

Note: Enabling zone transfer for a specific host allows that host to have the full list of names/IP addresses for that zone.

Configuring a DNS monitor to monitor the DNS servers (optional)

Beginning in BIG-IP 11.2.0, you can configure a DNS monitor if you want to have a content verification check on the DNS servers. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. For Name, enter a name for the DNS monitor.
  5. For Type, select DNS.
  6. Configure the remaining settings, as appropriate.

    For details of each of the settings, refer to the DNS monitor settings section under the Monitors Settings Reference chapter of the BIG-IP Local Traffic Manager: Monitors Reference guide.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  7. To save the configuration, select Finish.

Configuring a pool for the authoritative DNS servers

You must add the authoritative DNS servers to a pool on the BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select Create.
  4. For Name, enter a name for the pool.
  5. In the Available list, select a health monitor and move it to the Active list.
  6. Select a Load Balancing Method appropriate for your environment.
  7. For Address, enter the IP address of the authoritative DNS server.
  8. For Service Port, enter the DNS zone transfer port of the authoritative DNS server.

    Note: This is typically port 53.

  9. Select Add.
  10. Repeat steps 7 through 9 for each authoritative DNS server.
  11. To save the configuration, select Finish.

Configuring a TCP virtual server for requesting zone transfers

For requesting zone transfers from multiple authoritative DNS servers, you must configure a TCP virtual server to use the DNS pool that you created in the previous procedure. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create.
  4. For Name, enter a name for the TCP virtual server.
  5. For Type, select Standard.
  6. For Destination Type, select Host.
  7. For Destination Address, enter an IP address for the TCP virtual server.
  8. For Service Port, enter the DNS zone transfer port for the TCP virtual server.
  9. For Protocol, select TCP.
  10. For Default Pool, select the pool that you configured in the previous procedure.
  11. To save the configuration, select Finish.

Configuring the nameserver

You must configure a nameserver object to use the IP address of the TCP virtual server configured in the previous procedure. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to DNS > Delivery > Nameservers.
  3. Select Create.
  4. For Name, enter a name for the multiple authoritative DNS servers. This name will be used to choose the IP address of the virtual server in the next procedure.
  5. For Address, enter the IP address of the TCP virtual server that you configured in the previous procedure.
  6. To save the configuration, enter Finish.

Configuring the DNS Express Zone to use the TCP virtual server

You must configure the DNS Express Zone to reference the nameserver that you configured in the previous procedure. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to DNS > Zones > Zones > Zone List.
  3. Select Create.
  4. For Name, enter the DNS zone name for zone transfer.
  5. Under DNS Express, for Server, select the nameserver that you configured in the previous procedure.
  6. Under Allow NOTIFY From, for Address add the IP addresses of the authoritative DNS servers.
  7. To save the configuration, select Finish.

Configuring a UDP virtual server to handle DNS NOTIFY messages

You must configure a UDP virtual server to use a DNS profile. This UDP virtual server accepts the DNS NOTIFY messages from the authoritative DNS servers, and forwards them to DNS Express.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create.
  4. For Name, enter a name for the UDP virtual server.
  5. For Type, select Standard.
  6. For Destination Type, select Host.
  7. For Destination Address, enter an IP address for the UDP virtual server.
  8. For Service Port, enter the DNS NOTIFY port for the UDP virtual server.
  9. For Configuration, select Advanced.
  10. For Protocol, select UDP.
  11. For DNS Profile, select DNS.
  12. To save the configuration, select Finish.

Configuring the also-notify statement on the authoritative DNS server with the IP address of the UDP virtual server

You must configure the also-notify statement on the authoritative DNS server with the IP address of the UDP virtual server created in the previous step. For BIND-based DNS servers, the following also-notify statement adds the UDP virtual server with the IP address 192.168.1.52 as a server that will be sent a DNS NOTIFY message when a zone file is reloaded:

also-notify {192.168.1.52;};

For more information about configuring the also-notify statement on your DNS server, refer to the documentation for your DNS server.

Note: Configuring the also-notify statement for a specific host specifies that the host will be sent a DNS NOTIFY message when a zone file is reloaded.

Configuring a DNS profile to handle DNS NOTIFY messages

You must configure a DNS profile to handle DNS NOTIFY messages from the authoritative DNS servers. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Services > DNS.
  3. Select Create.
  4. For Name, enter the name of the DNS profile.
  5. For Unhandled Query Actions, select Allow, and for Process Recursion Desired select Enabled. All remaining settings must be set to Disabled or not configured.
  6. To save the configuration, select Finish.

Configuring an iRule to process and forward DNS NOTIFY messages

You must configure an iRule to rewrite the source IP of the DNS NOTIFY messages from authoritative DNS servers, and then forward them to the DNS Express virtual server or listener.

Note: If the virtual command in the DNS_REQUEST iRules event references a virtual server with a mismatched protocol (like TCP protocol), it may result in the known issue reported in K16046: Protocol mismatches may cause the TMM to restart.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. Ensure that the vsname applied on this procedure has a matching protocol.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Create an iRule using the following example template:

    when CLIENT_ACCEPTED {
    set vsname [Name of the DNS Express virtual server or listener which is the actual UDP virtual server that listens for DNS requests]
    set snatip [IP address of the TCP virtual server created in the Configure a TCP virtual server for requesting zone transfers procedure]
    }

    when DNS_REQUEST {
    if { [DNS::header opcode] equals "NOTIFY" } {
    virtual $vsname
    snat $snatip
    }
    }

    For example, if the name of the DNS Express virtual server or listener is dnsExpressVS_udp, and snatip is applied with the IP address of the TCP virtual server as 192.168.1.51:

    when CLIENT_ACCEPTED {
    set vsname dnsExpressVS_udp
    set snatip 192.168.1.51
    }

    when DNS_REQUEST {
    if { [DNS::header opcode] equals "NOTIFY" } {
    virtual $vsname
    snat $snatip
    }
    }

  5. To save the configuration, select Finish.

Configuring a UDP virtual server to use the DNS profile and iRule

You must configure a UDP virtual server to use the DNS profile and iRule created in the two previous steps. This UDP virtual server accepts the DNS NOTIFY messages from the authoritative DNS servers, and forwards them to the DNS Express virtual server or listener.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create.
  4. For Name, enter a name for the UDP virtual server.
  5. For Type, select Standard.
  6. For Destination Type, select Host.
  7. For Destination Address, enter an IP address for the UDP virtual server.
  8. For Service Port, enter the DNS NOTIFY port for the UDP virtual server.
  9. For Configuration, select Advanced.
  10. For Protocol, select UDP.
  11. For DNS Profile, select the new DNS profile created earlier to handle DNS NOTIFY messages.
  12. Under Resources, select and enable the iRule that you created in the previous procedure.
  13. To save the configuration, select Finish.
