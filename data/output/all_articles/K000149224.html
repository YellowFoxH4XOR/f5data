K000149224: Verifying the Secure attribute of cookies in requests for /private/fm/cache-fm.js (or /private/fm/cache-fm-Modern.js)

Type
Support Solution
Published
2025-01-09
Updated
2026-11-02
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000149224

Description

A vulnerability scanner reports that the Secure attribute is not set for the cookies in requests to the Portal Access rewriter file /private/fm/cache-fm.js (or cache-fm-Modern.js). When you examine the request in the browser Developer Tools, the cookies do not show the path=/; secure attributes.

The Cookie header of a request, for example a request for /private/fm/cache-fm.js, contains the names and values of the cookies, similar to the following example:

LastMRH_Session=<value>; TIN=<value>; MRHSession=<value>; F5_fullWT=<value>; F5_ST=<value>

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access

  • Webtop

Cause

Cookie attributes such as Secure and path that the server sets are sent in the Set-Cookie response header, not in the Cookie header of later requests. A finding that is based on the request for /private/fm/cache-fm.js therefore does not show whether the cookies have the Secure attribute. You need to verify the Secure attribute for each reported cookie.

Answer/Recommended Actions

Verify the Secure attribute of each cookie that the scanner reports. Use one of the following methods:

  • Use the Cookies option in the browser Developer Tools to inspect the stored cookies of the BIG-IP APM virtual server host, for example https://apm.example.com, and check whether each reported cookie is marked as secure.

  • In the browser Developer Tools, find the response that sets the cookie, and check whether its Set-Cookie response header includes the secure attribute.

Document the Secure flag that you observe for each reported cookie, and compare it with the scanner's evidence: which request or response the scanner inspected for each finding.

If a cookie does not have the Secure attribute, open a support case and provide the cookie name, the response that sets the cookie, the scanner finding, and the data listed in the Collect HTTPWatch or HAR files for support section of K14184: Troubleshooting BIG-IP APM Portal Access applications.
