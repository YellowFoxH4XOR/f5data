Description

The TCP keepalive is a mechanism used to discover closed connections and dead peers. It prevents TCP connections from closing due to network inactivity. TCP keepalive is non-invasive concept, one peer of the connection sends TCP frame with no data every time the keepalive timer reaches zero. The remote side of the connections sends the same TCP frame with no data and the TCP ACK flag set. TCP keepalives are implemented on Sockets and are managed by the Linux kernel. This is the opposite to HTTP keepalives which are controlled by applications and the application decides when to send HTTP request to perform verify the peer server.

Most of the linux distribution enables TCP keepalives with the following settings:

sudo sysctl -a | grep tcp_keepalive
net.ipv4.tcp_keepalive_intvl = 75
net.ipv4.tcp_keepalive_probes = 9
net.ipv4.tcp_keepalive_time = 7200

Environment

  • Aspen Mesh: 1.6.x - 1.11.x
  • Kubernetes: 1.17x - 1.22.x
  • Red Hat OpenShift: 4.6.x - 4.8.x

Cause

Some network proxies use tcp keepalive timers different than the usual default settings configured on Linux hosts. One of the examples is AWS Network Load Balanced which sets the idle TCP timeout to 350 seconds and this value cannot be modified. If the client or the server residing between AWS NLB will not send TCP, HTTP or other keepalive messages then the NLB will close the connection without notifying the applications (without sending frames with RST or FIN flags). In that case applications will steel keep the sockets for those connections open and may try to send TCP frames even after 350 seconds (the default TCP timeout on Linux is 7200 seconds). NLB load balancer will reply with RST frame to every frame sent to the closed connection. This may introduce unnecessary errors on the application sides and the need to open a new TCP connection via 3-way handshake.

In a typical cloud architecture Load Balancers (e.g., AWS NLB) route traffic to an ingress gateway which is the entry point to a service mesh. Having the NLB exposed to the internet the client traffic might be distributed and originated from many different sources the service owner might not control. In that scenario connection keepalives should be configured on the server side. Otherwise, the Load Balancer might silently close the connection after the keepalive timeout (350 seconds for AWS NLB). In this article we are going to show how to enable and configure TCP keepalives on Istio Ingress Gateway.

Recommended Actions

TCP keepalives are configured on the Linux socket level. The application needs to tell Linux to enable and configure keepalives while opening socket with system calls. Envoy proxy provides an API to specify Socket Options for a specific listener. To apply socket options in Istio we must use EnvoyFilters.

Here is an example of the EnvoyFilter which enables TCP keepalives on the ingress gateway and listener on port 8080. The port number should be customized to the TCP port configured in a Gateway object used to expose the service:

apiVersion: networking.istio.io/v1alpha3
kind: EnvoyFilter
metadata:
  name: ingress-gateway-socket-options
  namespace: istio-system
spec:
  configPatches:
  - applyTo: LISTENER
    match:
      context: GATEWAY
      listener:
        name: 0.0.0.0_8080
        portNumber: 8080
    patch:
      operation: MERGE
      value:
        socket_options:
        - description: enable keep-alive
          int_value: 1
          level: 1
          name: 9
          state: STATE_PREBIND
        - description: idle time before first keep-alive probe is sent
          int_value: 7
          level: 6
          name: 4
          state: STATE_PREBIND
        - description: keep-alive interval
          int_value: 5
          level: 6
          name: 5
          state: STATE_PREBIND
        - description: keep-alive probes count
          int_value: 2
          level: 6
          name: 6
          state: STATE_PREBIND

“int_values”, levels and name numbers are specific to the operating system. Numbers from the above example were tested on Ubuntu Linux and EKS 1.21 (Amazon Linux) but should be the same on most of Linux distributions. For more details, please look at socket man pages or “sys/socket” libraries.

Note: Istio Ingress Gateway must be restarted after EnvoyFilter was deployed and provisioned.
