Topic

The BIG-IP ASM Data Guard feature allows you to configure the BIG-IP ASM to protect sensitive data returned by the web server. For example, if a web server response contains a credit card number, the BIG-IP ASM can block or mask the response.

When the security policy is in Transparent mode and the Mask Data setting is selected, the BIG-IP ASM masks sensitive data returned by the web server by returning asterisk ( * ) characters to the client instead of the sensitive data.

When the security policy is in Blocking mode and the Mask Data setting is selected, and Data Guard: Information leakage detected blocking setting is disabled, the BIG-IP ASM masks sensitive data by returning asterisks to the client instead of the sensitive data.

However, when the security policy is in Blocking mode and the Mask Data setting is selected, and Information leakage detected blocking is enabled, the BIG-IP ASM blocks responses containing sensitive data.

If your security policy is in Blocking mode, and you want to use the Data Guard feature to mask sensitive data returned by the web server by returning asterisks to the client instead of a blocking page, you should enable the Mask Data setting, and disable blocking for the Information leakage detected blocking violation.

BIG-IP ASM 12.0.0 and later

To disable blocking for the Data Guard: Information leakage detected violation, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Confirm the correct policy is selected in the Current edited policy menu at the top of the page.
  4. Select Advanced to view the Policy Building Settings section.
  5. Expand Data Guard in the Policy Building Settings section and clear the Block check box for Data Guard: Information leakage detected.
  6. Click Save.
  7. Click Apply Policy.
BIG-IP ASM 11.3.0 through 11.6.1

To disable blocking for the Data Guard: Information leakage detected violation, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Blocking.
  3. Confirm the correct policy is selected in the Current edited policy menu at the top of the page.
  4. In the Negative Security Violations section, clear the Block check box for Data Guard: Information leakage detected.
  5. Click Save.
  6. Click Apply Policy.

BIG-IP ASM 10.2.0 through 11.2.1

To disable blocking for the Data Guard: Information leakage detected violation, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Policy > Blocking.
  3. Confirm the correct policy is selected in the Current edited policy menu at the top of the page.
  4. In the Negative Security Violations section, clear the Block check box for Data Guard: Information leakage detected.
  5. Click Save.
  6. Click Apply Policy.

BIG-IP ASM 9.4.2 through 10.1.0

To disable blocking for the Information leakage detected violation, perform the following procedure:

Note: The Data Guard feature does not mask data when the response uses gzip compression. For more information, refer to K8772: The Data Guard feature does not mask data when the response uses gzip compression.

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Policies List.
  4. Click the relevant security policy.
  5. From the Blocking drop-down menu, select Settings.
  6. In the Negative Security Violations section, clear the Block check box for Information leakage detected.
  7. Click Save.
  8. Click Apply Policy.
