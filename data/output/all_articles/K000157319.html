K000157319: Network-manager process cores out on VELOS System Controller, causes unexpected tenant failover

Type
Support Solution
Published
2025-11-06
Updated
2025-11-06
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000157319

Description

On VELOS platforms running F5OS-C, the network_manager process may crash during tenant operations such as creation, extension, deletion, or database reset/restore. A network_manager core file generates on the system controller, and can correlate with unexpected BIG-IP failover events.

Example network_manager core file being generated:

Core-helper.Controller: nodename=controller-2(p1) priority="Err" msgid="0x6501000000000001" msg="Core dumped on Controller" process="network_manager" location="/var/F5/partition1/shared/core/container/core.partition1_net.network_manager.<pid>.<timestamp>.core.gz"

Environment

  • F5OS VELOS platform
  • Software Version: F5OS-C 1.7.1 or older
  • Configuration: Tenants deployed.
  • Actions: Tenant creation, extension, deletion, upgrade/downgrade, or database reset/restore

Cause

Bug ID 1920325: The network-manager container crashes when it fails to create FDB entry in database.

Recommended Actions

  • Upgrade to F5OS-C 1.8.1 or preferably, the latest release, where the bug is resolved.
  • If upgrade is not possible, request an engineering hotfix built on F5OS-C 1.7.1.
  • When performing tenant operations (creation/deletion/upgrade/downgrade/database reset/restore), ensure all tenants are on Standby to avoid service impact if a crash occurs. Even if the network_manager process cores out, there will be no traffic impact.
