Summary

The Enterprise Manager system does not support managed devices that are configured with an sshd allow list that exceeds 1024 characters.

Description

When a managed device is configured with an sshd allow list that has more than 1024 characters, the Enterprise Manager system is unable to manage and monitor the device. If the managed device is yet to be discovered by the Enterprise Manager system, the Enterprise Manager system will not be able to discover the device. This is by design.

For example, the following sshd allow list has 1059 characters (including the spaces).

sys sshd {
    allow { 172.16.31.140 192.168.207.95 172.16.31.1 172.16.31.2 172.16.31.3 172.16.31.4 172.16.31.5 172.16.31.6 172.16.31.7 172.16.31.8 172.16.31.9 172.16.31.10 172.16.31.11 172.16.31.12 172.16.31.13 172.16.31.14 172.16.31.15 172.16.31.16 172.16.31.17 172.16.31.18 172.16.31.19 172.16.31.20 172.16.31.21 172.16.31.22 172.16.31.23 172.16.31.24 172.16.31.25 172.16.31.26 172.16.31.27 172.16.31.28 172.16.31.29 172.16.31.30 172.16.31.31 172.16.31.32 172.16.31.33 172.16.31.34 172.16.31.35 172.16.31.36 172.16.31.37 172.16.31.38 172.16.31.39 172.16.31.40 172.16.31.41 172.16.31.42 172.16.31.43 172.16.31.44 172.16.31.45 172.16.31.46 172.16.31.47 172.16.31.48 172.16.31.49 172.16.31.50 172.16.31.51 172.16.31.52 172.16.31.53 172.16.31.54 172.16.31.55 172.16.31.56 172.16.31.57 172.16.31.58 172.16.31.59 172.16.31.60 172.16.31.61 172.16.31.62 172.16.31.63 172.16.31.64 172.16.31.65 172.16.31.66 172.16.31.67 172.16.31.68 172.16.31.69 172.16.31.70 172.16.31.71 172.16.31.72 172.16.31.73 172.16.31.74 172.16.31.75 172.16.31.76 172.16.31.77 172.16.31.78 172.16.31.79 172.16.31.80 }
}

If you configure a managed device with the previous sshd allow list, and the device is an existing Enterprise Manager managed device, the Enterprise Manager cannot manage and monitor this device, and reports error messages similar to the following examples:  

  • In the Configuration utility Device List page:

    Database update failure

  • In the /var/log/em file:

    04070a00:3: Could not refresh device with uid = 6: Database Update Error while refreshing device with uid = 6: Could not modify device row: Data too long for column 'shell_access_filter' at row 1

If the device is not an existing Enterprise Manager managed device, and you attempt to use the Enterprise Manager system to discover this device, the Enterprise Manager system cannot discover the device, and reports error messages similar to the following examples:

  • In the Configuration utility Discovery Device Task page:

    Could not save device information to database

  • In the /var/log/em file:

    04072115:3: Could not save device information to database: 172.16.31.151, Could not insert device row: Data too long for column 'shell_access_filter' at row 1

Recommendations

When configuring the sshd allow list on a managed device that is managed or to be managed by the Enterprise Manager system, you should consider the following:

  • Limit the sshd allow list to 1024 characters or less.
  • If you have already configured a managed device with an sshd allow list exceeding 1024 characters, you can modify the sshd allow list to use a subnet, for example 172.16.31.0/255.255.255.0, or revert the sshd allow list to the default of ALL. To do so, perform the following procedure:

    Impact of procedure: Reverting to the default sshd allow list of ALL allows any IP client to connect. This may violate your organization's security policy.

    1. Log in to the tmsh utility.
    2. To modify the sshd allow list, use the following command syntax:

      modify /sys sshd allow replace-all-with { <replace-with-your-desired-list> }

      For example, you would enter the following command to replace the list with IP address 192.168.207.95 and subnet 172.16.31.0/255.255.255.0:

      modify /sys sshd allow replace-all-with { 192.168.207.95 172.16.31.0/255.255.255.0 }

    3. To save the changes, type the following command:

      save /sys config
