Known Issue

The VIPRION system is unable to completely remove all logical volumes from the HD1.1 volume set of a newly installed blade.

This issue occurs when all of the following conditions are met:

  • You install a new factory default blade in a VIPRION chassis.
  • HD1.1 is empty on the blades of the existing cluster.

Impact

Attempts to install software to HD1.1 will fail due to the inconsistent state of the volume sets between the cluster.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Output of the tmsh show sys software command appears similar to the following example:

    ----------------------------------------------------------------------------
    Sys::Software Status
    Volume  Slot  Product  Version     Build  Active                      Status
    ----------------------------------------------------------------------------
    HD1.1      1   BIG-IP   11.5.2   0.0.141      no  failed to delete volumeset
    HD1.3      1   BIG-IP   10.2.3    123.29      no                    complete
    HD1.3      2   BIG-IP   10.2.3    123.29      no                    complete
    HD1.3      3   BIG-IP   10.2.3    123.29      no                    complete
    HD1.4      1   BIG-IP   11.5.3  0.58.163     yes                    complete
    HD1.4      2   BIG-IP   11.5.3  0.58.163     yes                    complete
    HD1.4      3   BIG-IP   11.5.3  0.58.163     yes                    complete
     

  • In the /var/log/daemon.log file, you observe messages similar to the following example:

    notice lind/volumeset:   Can't remove open logical volume set.1._config

Workaround

To work around this issue, you can manually remove logical volumes that the VIPRION system was unable to remove from the HD1.1 volume set during blade installation. To do so, perform the following procedure:

Impact of workaround: Any data on the logical volumes that you remove will be irrecoverably lost. The procedure involves restarting a service; therefore, F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Create a user configuration set (UCS) backup of the VIPRION system. If Virtual Clustered Multiprocessing (vCMP) guests are deployed on the system, create UCS backups of all guests. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 12.x).
  2. Log in to the VIPRION command line.
  3. Review the /var/log/liveinstall.log file to find the name of the logical volume in the HD1.1 volume set that the VIPRION system was unable to remove.
    For example:

    'Can't remove open logical volume set.1._config'.

  4. If necessary, unmount the problematic logical volume by using the following syntax:

    umount <path/to/logical/volume>

    For example:

    umount /dev/vg-db-sda/set.1._config

  5. Manually remove the logical volume, by using the following syntax

    lvremove <path/to/logical/volume>

    For example:

    lvremove /dev/vg-db-sda/set.1._config

  6. Restart lind, the software management process, by typing the following command:

    tmsh restart sys service lind
