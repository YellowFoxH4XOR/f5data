Known Issue

In rare circumstances, upgrading to BIG-IQ Centralized Management 5.0.0 may fail with a Waiting for BIG-IQ services to become available error message.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IQ 7000 series hardware platform.
  • Your BIG-IQ system is running either 4.5.0 or 4.6.0.
  • You perform a software upgrade to 5.0.0.
  • After the installation completes, you reboot the BIG-IQ system to the same slot where you performed the upgrade, which is either running 4.5.0 or 4.6.0.
  • You reboot the BIG-IQ system to the newly installed 5.0.0 software slot.

Impact

The configuration of the affected BIG-IQ system is lost, which includes the discovered devices.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When logging in to the Configuration utility, you view the following message:

    Waiting for BIG-IQ services to become available...

  • You observe that the restjavad process is down when you check the status by typing the following command:

    tmsh show /sys service restjavad

  • The affected BIG-IQ system configuration is lost, which includes the discovered devices.
  • When you review the /var/log/liveinstall.log file after Live Install has completed installing 5.0.0, the first boot_marker entry shows that the system boots to BIG-IQ 4.5.0 or 4.6.0. For example, on the system that you rebooted to 4.6.0, the Live Install log file may appear similar to the following example:

    *** Live install end at 2016/06/07 14:40:01: succeeded ***
    2016-06-07T14:47:45-07:00 bigiq notice boot_marker : ---===[ MD1.2 - BIG-IQ 4.6.0 Build 0.0.119 <MD1.2> ]===---
    2016-06-07T14:52:13-07:00 localhost notice boot_marker : ---===[ MD1.3 - BIG-IQ 5.0.0 Build 0.0.3026 <MD1.3>]===---

Workaround

To recover from this issue, you can choose either one of the following options:

  • If you have a copy of the UCS archive prior to the upgrade, you can recover from the issue using the user configuration set (UCS) archive. Refer to the procedure, Recovery using the UCS archive file. After this recovery procedure, you have the option to return to the 4.5.0/4.6.0 software slot.
  • If you do not have a copy of the UCS archive, you can recover from the issue by editing the Live Install log file. Refer to the procedure, Recovery by editing the Live Install log file.
  • If you want to preserve the options to use both the software slots (the 4.5.0/4.6.0 software slot and the newly installed 5.0.0 software slot), you must have a copy of the UCS archive prior to the upgrade and perform both the procedures. First, perform the Recovery using the UCS archive file, then perform the Recovery by editing the Live Install log file procedure.
  • For high-availability pair deployments, recover back with the 4.5.0/4.6.0 configuration by performing the following steps:
    • Create a new instance running 4.5.0/4.6.0 on the affected device.
    • Perform the high-availability pairing with the other peer that is still running 4.5.0/4.6.0. When you repair the devices, the affected device with the new 4.5.0/4.6.0 instance will receive the configuration from the peer device.
    • Thereafter, you can avoid this issue by performing the installation of 5.0.0 using the tmsh installation command with the reboot option.

      ?For example:

      tmsh install /sys software image <ISO-File> volume <Software-Slot> reboot
 
Recovery using the UCS archive file

To recover from the issue using a UCS archive file while the BIG-IQ system is running at the 4.5.0 or 4.6.0 software slot, perform the following procedure:

Impact of workaround: The copy of the UCS archive file may not contain the latest configuration; it depends when you backed up this configuration. Performing the following procedure will replace the current configuration on the BIG-IQ system.

  1. Ensure that the BIG-IQ system is running on the software slot where you attempt to perform the upgrade installation. The system software slot should be running on either 4.5.0 or 4.6.0, depending on your system's initial state when you perform the installation of 5.0.0.
  2. Transfer the copy of the UCS archive file to the /shared/ucs_backups directory on the BIG-IQ system.

    Note: For more information about transferring files, refer to K175: Transferring files to or from an F5 system.

  3. Log in to the Traffic Management Shell (tmsh) utility of the affected BIG-IQ system with administrator role credentials.
  4. Restore the UCS archive file using the following command syntax:

    load /sys ucs /shared/ucs_backups/<UCS-filename>

    For example:

    load /sys ucs /shared/ucs_backups/SOL40338232.ucs

  5. Perform the upgrade to 5.0.0 again with the reboot option, using the following command syntax:

    install /sys software image <ISO-File> volume <Software-Slot> reboot

    For example:

    install /sys software image BIG-IQ-5.0.0.0.0.3026.iso volume MD1.3 reboot

    The command will perform the installation of BIG-IQ 5.0.0. Subsequently, the system reboots into the newly installed software slot when the installation is complete.

  6. Exit the tmsh utility by typing the following command:

    quit

    After the reboot, the system will be running 5.0.0.

Recovery by editing the Live Install log file

To recover from the issue by editing the Live Install log file while the BIG-IQ system is running at the 5.0.0 software slot, perform the following procedure:

Impact of workaround: System reboot is involved in this procedure. However, this is a recovery procedure and system access disruption is expected.

  1. Ensure that the BIG-IQ system is running on the newly installed 5.0.0 software slot.
  2. Log in to the affected BIG-IQ system's Advanced shell with administrator role credentials.
  3. Use a text editor of your choice and edit the /var/log/liveinstall.log file.
  4. Remove all the boot_marker entries right after the line indicating the latest successful installation.

    For example, remove line 986 and 987 in the following log with line numbers:

    985:*** Live install end at 2016/06/07 14:40:01: succeeded ***
    986: 2016-06-07T14:47:45-07:00 bigiq1 notice boot_marker : ---===[ MD1.2 - BIG-IQ 4.6.0 Build 0.0.119 <MD1.2> ]===---
    987: 2016-06-07T14:52:13-07:00 localhost notice boot_marker : ---===[ MD1.3 - BIG-IQ 5.0.0 Build 0.0.3026 <MD1.3> ]===---

  5. After removing the boot_marker lines, the last line in the log file may appear as follows:

    985: *** Live install end at 2016/06/07 14:40:01: succeeded ***

  6. Save the changes and exit the text editor.
  7. Reboot the BIG-IQ system by typing the following command:

    reboot

    After the reboot, the system will be running 5.0.0.
