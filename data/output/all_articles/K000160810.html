Description

When deploying Load Balancer objects in F5 Distributed Cloud using Regional Edge (RE) data planes, it may not be immediately clear how to control which Regional Edge locations participate in client-side (ingress) and server-side (egress) traffic flows. Virtual Sites provide a mechanism to logically group Regional Edge locations and apply that grouping to both VIP Advertisement and Origin Pool configurations, enabling granular control over traffic patterns.

 

  • How can Virtual Sites be used to control which Regional Edge locations advertise a VIP to clients?
  • How can Virtual Sites be used to restrict which Regional Edge locations send traffic to an origin server?
  • What is the difference between applying a Virtual Site to VIP Advertisement only, Origin Pool only, or both?
  • How does F5 Distributed Cloud route traffic when the ingress Regional Edge is not included in the Origin Pool Virtual Site?
  • How do you build and configure a Regional Edge Virtual Site in F5 Distributed Cloud?

Environment

  • F5 Distributed Cloud (SaaS)
  • Regional Edge (RE) data plane
  • HTTP, HTTPS, or TCP Load Balancer objects
  • VIP Advertisement configured on Load Balancer objects
  • Origin Pool configured with RE-based server-side routing
  • Virtual Sites configured for Regional Edge grouping
  • Additional Tenant IP or BYO-IP in use for scoped VIP Advertisement (required for non-default Virtual Sites)
  • F5 Distributed Cloud Software Defined Network (SDN) Fabric (relevant for Solution 4 topology)

Cause

None

Answer/Recommended Actions

F5 Distributed Cloud uses Virtual Sites to logically group Regional Edge (RE) data plane instances. These groupings can be applied to VIP Advertisement (client-side/downstream) and/or Origin Pool configurations (server-side/upstream) to control where traffic ingresses and egresses the F5 Distributed Cloud platform.

Building a Regional Edge Virtual Site

Navigate to: Shared Configuration → Manage → Virtual Sites → Add Virtual Site

  1. Provide a Name, optional Labels, and a Description for the Virtual Site.
  2. Under Site Type, select RE (Regional Edge).
  3. Under Site Selector Expression, add label selectors to define which Regional Edges are included:
    • To find the labels for a specific Regional Edge, navigate to Multi-Cloud Network Connect → Overview → Sites.
    • Add a filter for Site Type → In → REGIONAL_EDGE.
    • Expand the arrow to the left of the desired site to review its JSON and locate the labels section.
    • Use these pre-defined labels (e.g., by country or site name) as selector expressions for your Virtual Site.

Note: Never configure a Virtual Site with only a single Regional Edge location. F5 Distributed Cloud performs maintenance every 4–8 weeks that takes RE locations offline. A single-location Virtual Site will result in an outage during maintenance windows.

Applying Virtual Sites to VIP Advertisement (Client-Side/Downstream)

  1. Ensure you have a secondary IP address (Additional Tenant IP or BYO-IP) available for your tenant. The Default Tenant IP is attached to the global ves-io-all-res Virtual Site and cannot be scoped to a custom Virtual Site. To find available IPs, navigate to Shared → Manage → Public IP Addresses.
  2. Select the IP address you wish to scope. Expand the Virtual Site option within that IP Address configuration and select your custom Virtual Site.
  3. Navigate to the target Load Balancer and locate VIP Advertisement.
  4. Select Internet (Specified VIP) and choose the IP address updated in step 2.
  5. Update DNS to point to the new IP address.

Applying Virtual Sites to Origin Pool (Server-Side/Upstream)

  1. Navigate to Multi-Cloud App Connect or Web App & API Protection → Manage → Load Balancers → Origin Pools. Add or edit the relevant Origin Pool.
  2. Select Add Origin Servers and choose the discovery method appropriate for your environment:
    • IP Address of Origin Server on given Sites
    • DNS Name of Origin Server on given Sites
    • K8s Service Name of Origin Server on given Sites
    • Consul Service Name of Origin Server on given Sites
  3. After entering the server or service information, select Virtual Site from the Site or Virtual Site dropdown and choose the desired Virtual Site.
  4. For RE Virtual Sites, always select Outside Network under the network selection dropdown.

Traffic Pattern Topologies

The following four solutions illustrate common deployment topologies using Virtual Sites on Regional Edges. All examples use a single US-based origin (3.34.15.8), a US Client (24.140.32.44), and an EU Client (86.106.83.55).

Solution 1: All Regional Edges (Default)

  • Uses the default ves-io-all-res Virtual Site by selecting Internet for VIP Advertisement and a public DNS/IP for the Origin Pool.
  • Traffic ingresses and egresses through the nearest Regional Edge to the client.
  • US Client routes through New York; EU Client routes through Paris. Both egress locally to the US Origin.
  • The US Origin must allow all Regional Edge SNAT ranges for health checks and traffic.

Solution 2: North America Only (VIP Advertisement/Client-Side Only)

  • VIP Advertisement is scoped to a North America Virtual Site using a secondary IP. Origin Pool remains global (no Virtual Site).
  • US Client continues to route through New York. EU Client routes to Montreal (the nearest NA RE) via F5's global backbone after failing to find a local VIP advertisement.
  • Limitations of this topology:
    • EU, APAC, and AUS Regional Edges will continue to health monitor the origin, generating unwanted traffic and potential ACL/NSG failures at origin.

  • Resolves the limitations of Solution 2 by:
    • Eliminating health monitor traffic from non-NA Regional Edges to origin.
    • Ensuring traffic will never egress from Regional Edges outside the defined Virtual Site, even in failure scenarios.
    • Removing red/down origin server entries from non-NA regions, maintaining a clean Application Score.

Solution 4: North America Only (Origin Pool/Server-Side Only) - Recommended

  • VIP Advertisement remains global (all Regional Edges). Only the Origin Pool is scoped to a North America Virtual Site.
  • This is the recommended "Secure Edge" or "Umbrella/Funnel" model, as it:
    • Applies proxy services (WAF, L7 DDoS, API Security, Bot Protection, etc.) as close to the client as possible, globally.
    • Ensures all egress traffic to origin sources only from the defined NA Regional Edges, satisfying ACL/NSG requirements at origin.
    • Takes full advantage of globally distributed compute to serve good clients and block malicious traffic, regardless of the client's geographic location.
  • When the ingress Regional Edge (e.g., Paris) is not included in the Origin Pool Virtual Site, F5 Distributed Cloud uses its Software Defined Network (SDN) Fabric to route the traffic internally to the nearest NA Regional Edge (e.g., Montreal) for egress to origin.
  • The US Origin will see the source IP of the egress Regional Edge (e.g., Montreal SNAT), not the ingress Regional Edge (Paris).

Additional Information

F5 Distributed Cloud operates as a proxy architecture, creating a full OSI stack twice for L7 services — once for the client-side/downstream connection and once for the server-side/upstream connection. Each side includes an L3/L4 connection, TLS session, and L7 request. Understanding this dual-stack proxy model is fundamental to understanding how Virtual Sites can independently control ingress and egress behavior:

  • Client-Side / Downstream: The connection between the client and the F5 Distributed Cloud proxy (configured via VIP Advertisement).
  • Server-Side / Upstream: The connection between the F5 Distributed Cloud proxy and the origin server/application (configured via Origin Pool).

F5 Distributed Cloud's overlay SDN fabric allows these two sides of the proxy to be handled by completely different Regional Edge instances. This is what enables Solution 4's "Globally Dispersed Proxy" model, where traffic ingresses in Paris but egresses in Montreal. This split also occurs naturally in failure scenarios — if a health monitor fails at the ingress RE, traffic is automatically rerouted via the SDN fabric to the nearest RE with a healthy health monitor.

Two default Virtual Sites exist within every F5 Distributed Cloud tenant:

  • ves-io-all-res: The default global Virtual Site attached to the Default Tenant IP. Used when selecting "Internet" for VIP Advertisement or when no site is specified for an Origin Pool.
  • ves-io-no-sites: Used when selecting "Do Not Advertise" under VIP Advertisement, effectively disabling advertisement of the Load Balancer.

Virtual Sites support two Site Types mapping to F5 Distributed Cloud's data plane types:

  • RE (Regional Edge): Groups F5-managed SaaS data plane locations using pre-defined RE labels (e.g., by country, continent, or site name).
  • CE (Customer Edge): Groups customer-managed data plane instances using custom labels defined by the customer.

This article focuses exclusively on RE Virtual Sites. A follow-up article covering CE Virtual Sites and combined RE+CE topologies is planned as part of this mini-series.
