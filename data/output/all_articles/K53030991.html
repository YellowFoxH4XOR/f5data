Topic

You should consider using this procedure under the following conditions:

  • The file system mounted on the /var/lib/mysql directory is full or filling with binary transaction log files.
  • You want to purge the excess log files to create more disk space.

Description

The MySQL database logs transactions to binary log files in the /var/lib/mysql directory. Some services that rely on the MySQL database, such as BIG-IP ASM, BIG-IP APM, and BIG-IP Analytics, have the potential to log large amounts of data in the binary files. If the files accumulate over time they may grow to consume all available disk space. This can negatively impact MySQL functionality and cause the BIG-IP system to behave unexpectedly or experience traffic disruptions.

Note: Binary transaction logging for the database is disabled globally starting in BIG-IP 14.0.0.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP Advanced Shell (bash).

Procedures

To prevent binary log files from filling the /var/lib/mysql file system, you can purge excess binary log files manually or configure MySQL to remove them automatically. To do so, perform the following procedures:

  • Checking the disk usage for the /var/lib/mysql file system
  • Purging binary log files
  • Configuring MySQL to automatically remove binary log files

Checking the disk usage for the /var/lib/mysql file system

You can check the disk usage for the /var/lib/mysql file system using the df -h command. If the file system is nearing capacity, you can check to see if there are any binary log files that can be purged. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Advanced Shell (bash).
  2. Check the disk usage for /var/lib/mysql by typing the following command:

    df -h

    Locate the line for /var/lib/mysql and check the value in the Use% column. In the following example the value is 100%, indicating the file system is full:

    Filesystem                                       Size  Used Avail Use% Mounted on
    /dev/mapper/vg--db--sda-app.ASWADB.set.2.mysqldb 12G  12G     0   100% /var/lib/mysql

  3. Check to see if you can purge any binary log files to free disk space by using the ls command.  The following example shows eight binary log files that are approximately 1 GB in size:

     

    ls -l /var/lib/mysql | grep -i bin

    -rw-rw----  1 mysql       mysql            1073741974 Oct  5 17:22 2018 mysqld-bin.000001
    -rw-rw----  1 mysql       mysql            1073742306 Oct  6 04:55 2018 mysqld-bin.000002
    -rw-rw----  1 mysql       mysql             486179613 Oct  6 10:14 2018 mysqld-bin.000003
    -rw-rw----  1 mysql       mysql            1073742155 Oct  6 21:51 2018 mysqld-bin.000004
    -rw-rw----  1 mysql       mysql            1073742015 Oct  7 09:17 2018 mysqld-bin.000005
    -rw-rw----  1 mysql       mysql             144967363 Oct  7 10:50 2018 mysqld-bin.000006
    -rw-rw----  1 mysql       mysql            1073742371 Oct  7 22:13 2018 mysqld-bin.000007
    -rw-rw----  1 mysql       mysql            1073741904 Oct  8 09:42 2018 mysqld-bin.000008

    -rw-rw----  1 mysql       mysql            1073742221 Oct  9 09:40 2018 mysqld-bin.000011

Purging binary log files

You can purge older binary log files to free up space in the file system. To purge binary log files based on their creation date, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash.
  2. Purge the binary log files using the following command syntax:

    /usr/bin/mysql --user=root --password=`perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` -e 'use mysql; PURGE BINARY LOGS BEFORE "<YYYY>-<MM>-<DD> <hh>:<mm>:<ss>";'

    Using the previous syntax, if you want to keep only files created after 6:00 a.m. on October 8, you can purge all log files created before 6:00 a.m. on October 8, 2018 using the following command:

    /usr/bin/mysql --user=root --password=`perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` -e 'use mysql; PURGE BINARY LOGS BEFORE "2018-10-08 06:00:00";'

  3. Using the previous example, output of the ls -l /var/lib/mysql | grep -i bin command now appears similar to the following:

    -rw-rw----  1 mysql       mysql            1073741904 Oct  8 09:42 2018 mysqld-bin.000008
    -rw-rw----  1 mysql       mysql              95809113 Oct  8 10:43 2018 mysqld-bin.000009
    -rw-rw----  1 mysql       mysql            1073742382 Oct  8 22:07 2018 mysqld-bin.000010
    -rw-rw----  1 mysql       mysql            1073742221 Oct  9 09:40 2018 mysqld-bin.000011

Configuring MySQL to automatically remove binary log files

You can configure MySQL to automatically remove older binary log files, based on the number of days' worth of logs you specify. To configure MySQL to automatically remove binary log files, perform the following procedure:

Note: Changes to the my.cnf file are lost during the upgrade process and during hotfix and point release installation and are not synchronized to peer devices in a high-availability (HA) configuration. You must perform this procedure for all member devices in the HA configuration.

Impact of procedure: Performing the following procedure requires restarting the MySQL service and should be done during a maintenance window.

  1. Log in to the bash shell.
  2. Use a file editor such as vi to open the /var/lib/mysql/my.cnf file (BIG-IP 11.x - 13.x) or /etc/my.cnf (BIG-IP 14.x) for editing.
  3. Add the following syntax to the end of the common tuning parameters section:

     

    expire_logs_days = <# of days to keep>

    For example, to keep four days' worth of binary log files, edit the common tuning parameters section of the my.cnf file to look similar to the following:

    # common tuning parameters
    max_allowed_packet          = 16M
    read_buffer_size            = 1M
    sort_buffer_size            = 16M
    thread_cache_size           = 8
    set-variable                = max_connections=500
    expire_logs_days            = 4

  4. Save the changes to the my.cnf file and close the file editor.
  5. Restart MySQL by typing the following command:

    tmsh restart /sys service mysql

  6. After MySQL successfully starts, check to see if you need to restart any other services need by typing the following command:

    tmsh show /sys service | grep -i "normally up"

    The following output shows the asm and monpd services are down and need to be restarted:

    asm down 2 minutes, normally up
    monpd down 2 minutes, normally up

    To restart the asm and monpd services, type the following command:

    tmsh restart /sys service asm monpd
