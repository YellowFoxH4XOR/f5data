Description

BIG-IP IPsec peer to remote site has formed ike-sa and ipsec-sa. Interesting traffic is arriving at BIGIP but not being encrypted and passed as ESP to the unprotected network.

Environment

  • BIG-IP configured as IPsec peer using IKEv2
  • Remote peer is configured traffic-selectors (TS) that are a subset of the BIGIP selectors
  • BIG-IP is IPsec initiator

Cause

BIG-IP using IKEv2 can perform traffic-selector narrowing. This means that if the selectors for the remote peer are a subset of the BIG-IP selector then BIG-IP will accept the subset TS proposal and create security associations (SA) with the peer. If the clear text traffic arriving at BIG-IP match the configured TS but do not fall within the subset offered by the peer, then it will trigger the creation of SAs (if required) and will be dropped as it does not match the narrowed TS.

Recommended Actions

Configure both IPsec peers with matching traffic-selectors.

Additional Information

Here is a schematic showing the failing scenario. Note the highlighted configuration mismatch leading to the traffic-selector narrowing.
 

10.1.1.1 ---> [peer LHS] -------------- <encrypted> ----------> [peer RHS] ---> 192.168.1.1
 

net ipsec traffic-selector ts_left {                 net ipsec traffic-selector ts_right {
  destination-address 192.168.1.0/24                   destination-address 10.1.1.100/32
  ipsec-policy policy_left                             ipsec-policy policy-right
  source-address 10.1.1.0/24                           source-address 192.168.1.0/24
}                                                    }
 

The ping from 10.1.1.1 to 192.168.1.1 matches the TS ts_left and the ikev2 negotiation is therefore started. The source address on TS ts_right is different from, but is a subset of, ts_left. As this is ikev2, the initiator (LHS) performs traffic narrowing. This means that it accepts the 10.1.1.100/32 TS  (rather than its configured 10.1.1.0/24) and creates appropriate SAs. However, the icmp packets from 10.1.1.1 to 192.168.1.1 do not match the narrowed TS and therefore BIGIP does not forward the packets over IPsec. ie: no ESP packets are seen.
