K000162316: Deleting Cached Files Can Leave Previously Cached Content and Cache Metadata Inconsistent, Leading to Error 500

Type
Support Solution
Published
2026-07-17
Updated
2026-07-17
Applies to
  • NGINX Products
  • NGINX Plus: R36
Source
https://my.f5.com/manage/s/article/K000162316

Description

Intermittent HTTP 500 errors occur after cached files are deleted while the NGINX service remains running or is only reloaded. The application may report an error 

Environment

  • NGINX Plus
  • Proxy caching enabled
  • NGINX cached content and metadata stored on the local filesystem
  • Temporary cached content stored in:

    /var/cache/nginx/client_temp/

  • Cached files were deleted
  • NGINX was reloaded after the files were deleted
  • The issue affected only a small percentage of requests and occurred intermittently

Cause

  • Deleting cached files can leave previously cached content and cache metadata inconsistent. An NGINX reload does not restart the cache loader process. As a result, metadata for previously cached content may not be fully rebuilt during the reload.
  • Clients with existing sessions or cached content may continue to reference content that is no longer available. NGINX can then forward requests to the upstream application, which may not expect those requests or may return a non-JSON response. The application subsequently reports parsing error.

Answer/Recommended Actions

  1. If cached files have been deleted and intermittent HTTP 500 errors begin, restart the NGINX service rather than performing only an NGINX reload.
  2. Confirm that the application errors stop after the service restart.
  3. Avoid manually deleting NGINX cache files during active traffic unless the operational procedure accounts for rebuilding the cache state.
  4. To use a different cache location, configure the proxy_cache_path directive. For example:

    http {
         proxy_cache_path /data/nginx/cache keys_zone=mycache:10m;

         server {
            proxy_cache mycache;

            location / {
               proxy_pass <upstream-server>;
            }
         }
    }

  5. Monitor cache-directory size and file counts using operating-system monitoring tools. NGINX does not provide low-level monitoring or alerting for filesystem directory changes.

Additional Information

  • The NGINX cache loader runs once when the NGINX service starts and loads metadata for previously cached data into the shared memory zone.
  • An NGINX reload does not recreate the cache loader process.
  • A full service restart recreates the cache manager, cache purger, and cache loader processes and reloads the cache metadata.
  • The proxy_cache_path directive defines the cache location and shared-memory zone for proxy caching.
