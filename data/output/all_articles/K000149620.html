Description

There is intermittent issue with Concurrent Connection Counts shown different count in GUI (Graphical User Interface) and CLI (Command Line Interface).

When you check connection table entries for the virtual server by running command:

  # show sys connection cs-client-addr <VS-IP-Address>

the output shows Total records returned: 0.

In GUI, Statistic ››  Module Statistic : Local Traffic ››  Pools is Current Connection for the pool assigned to the virtual server in question (e.g.  Current Connection: 1)

Configuration example:

ltm virtual /Common/my_virtual-Test1 {
  cmp-enabled no
  description "Test1"
  destination 10.10.10.10:443
  ip-protocol tcp
  last-modified-time 2025-01-05:15:55:55
  mask 255.255.255.255
  persist {
    /Common/source_addr {
      default yes
    }
  }
  pool /Common/my_pool-Test1
  profiles {
    /Common/clientssl_test1 {
      context clientside
    }
    /Common/oneconnect { }                
    /Common/serverssl_test1 {
      context serverside
    }
    /Common/tcp { }
  }
  serverssl-use-sni disabled
  source 0.0.0.0
  source-address-translation {
    type automap
  }
  translate-address enabled
  translate-port enabled
}

Environment

  • BIG-IP LTM
  • GUI
  • CLI (# show sys connection cs-client-addr <VS-IP-Address>)
  • OneConnect profile

Cause

When a client establishes a new connection to a BIG-IP virtual server with a OneConnect profile, the BIG-IP system processes the HTTP request, chooses a server based on the pool's load-balancing method, and sets up a connection to that server.
Once the client's initial HTTP request is finished, the BIG-IP system keeps the connection open for a short time and allows the idle TCP connection to be reused by a pool member.

 <...>
  }
    /Common/oneconnect { }                  <<========= OneConnect
    /Common/serverssl_test1 {
      context serverside
    }
<...>

Recommended Actions

To address the issue where the BIG-IP system keeps the connection open for a short time and allows the idle TCP connection to be reused by a pool member, resulting in intermittent discrepancies in Concurrent Connection Counts shown in the GUI, it is recommended to disconnect the OneConnect profile. By doing so, the system will no longer reuse idle TCP connections, which should help resolve the inconsistencies in connection counts and improve overall performance and reliability. 

Additional Information

There are differences between the two interfaces Graphical User Interface (GUI) and a Command Line Interface (CLI). For example:

  • Graphical User Interface (GUI):
  1. Efficiency: Can be slower for experienced users due to the need to navigate through menus and windows.
  2. Resource Usage: Typically consumes more system resources (CPU, memory) because of the graphical elements.
  3. Precision: Lower then CLI.
  • Command Line Interface (CLI):
  1. Efficiency: Can be much faster for experienced users, as commands can be executed quickly without navigating through menus.
  2. Resource Usage: Generally uses fewer system resources, making it suitable for systems with limited resources.
  3. Precision: Higher then GUI.

The frequency at which the GUI pool connection statistics are updated in F5 can vary depending on the specific configuration and version of the software you are using.

Typically, these statistics are refreshed almost in real-time to ensure current information about the connection status. GUI consumes more system resources then CLI.
