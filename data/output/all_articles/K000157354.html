K000157354: Pool Members Flapping possible after upgrade to v17.1.3 due to code change that restricts content-length limit of 5120 bytes for in-tmm HTTP/HTTPS monitors

Type
Support Solution
Published
2025-11-11
Updated
2026-01-12
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000157354

Description

From BIG-IP v17.1.2 (Bugs 1287045, 1289845), in-tmm HTTP/HTTPS monitors now enforce a 5120-byte content-length limit, matching bigd’s behavior (K3451).

 

Environment

  • LTM
  • Upgraded from 17.1.1 to 17.1.3 or later

 

Cause

  • Bug ID 1287045
  • Bug ID 1289845

 

In version 17.1.3 and later, monitors are marked down if the expected string ("UP") is not found within the first 5120 bytes of the HTTP response (including headers).

 

Enforcement of this 5120 bytes limit was introduced for in-tmm monitors as well—matching existing bigd behavior per K3451: Content length limits for HTTP and HTTPS health monitors.

 

Monitors now mark pool members DOWN if the receive string is not present within the first 5120 bytes of response data.

 

A code change beginning with BIG-IP v17.1.2 (Bug ID 1287045 and 1289845) enforced a strict content-length limit of 5120 bytes for in-tmm HTTP/HTTPS monitors—the same as bigd’s long-standing behavior (K3451: Content length limits for HTTP and HTTPS health monitors). Previously, these monitors would search beyond this limit, allowing matches further into large responses or error pages like custom 404s.

 

If "UP" appears after byte 5120, or only in certain error responses (like a large/dynamic 404 page), the pool member will be marked down post-upgrade.

 

Recommended Actions

  • Ensure monitored URLs exist on pool members and return "UP" within the first 5120 bytes of their response.

 

  • Avoid relying on generic error pages or dynamic content that may push expected strings beyond this limit.

 

  • Consider switching to TCP monitors as an interim mitigation if application changes are not immediately possible.

 

  • There is no native method to identify all affected pools via logs alone; only that “Response matched regex” may appear when a match occurs.
