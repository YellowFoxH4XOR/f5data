Topic

You should consider using this procedure under the following conditions:

  • You use the f5fpc standalone client for Linux when establishing a BIG-IP APM access session.
  • You want to implement a two-factor authentication access policy.
  • Your authentication environment consists of RADIUS, SecurID, or both.
  • Your authentication is based on the user login name and multiple passwords.

Description

When using the BIG-IP APM Linux standalone command line client f5fpc to establish an access session, each user is limited to entering a single username and a single password. This limitation impacts the ability to supply an additional one-time password (OTP) for use in a two-factor authentication access policy.

The procedures in this article cover creating an access policy that allows each Linux user to enter a username and multiple passwords. You create the access policy to split the single password into two distinct passwords, based on a known delimiting character in the user-provided password.

The system saves each password to variable assignments. When authenticating, the system sends the configured variable assignment for the specific authentication method to the authentication device using the common username. For example, if the user authenticates to a RADIUS server using the entered username and a specific password, upon successful completion they must present a numeric OTP to a second authentication device before the system establishes the access session. They can enter their passwords as a singular password, where the passwords are separated with a delimiter character or space.

When a user launches the command-line f5fpc client, the system prompts them for their password.

For example:

f5fpc -s -u bob -x -t https://192.168.0.88:443
Enter password:

When entering their password, they can use a special character delimiter to designate two separate passwords. In the following procedures, the system sends the first password (session.logon.first_password) to the first authentication resource and the second password (session.logon.second_password) to the second OTP authentication resource.

Command syntax:

<password1> <password2>

  • Example using a space:

    mYpassw0rd! 033847

  • Example using a slash (/):

    mYpassw0rd!/033847

  • Example using a colon (:):

    mYpassw0rd!:033847

Note: In the previous examples, the user password is mYpassw0rd! and the OTP is 033847.

Important: It is critically important that you make sure that user passwords do not include the character you choose to use as the special character delimiter.

Note: The Variable Assign stanza example in this article uses the slash (/) as a delimiting character.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have configured your BIG-IP APM with the required authentication profiles, webtops, network access profiles, access control lists (ACLs), and any other required resources and profiles for the access policy to use.
  • The authentication devices are RADIUS, SecurID, or both.

    Note: The authentication devices allowed are a limitation of the BIG-IP APM access policy structure in which you can modify the password-session variable in the flow of the access policy.

Launching VPE

The following procedure assumes that you previously created an access profile.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in Configuration utility.
  2. Go to Access > Profiles / Policies.
  3. To launch VPE, in the Per-Session Policy column, select Edit for the access profile.

Adding the Logon Page agent

The following procedure creates the Logon Page agent in the access policy.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In VPE, on the fallback branch after Start, select the add icon (+).
  2. On the Logon tab, select Logon Page, and then select Add Item.
  3. In the pop-up window, on the Properties tab under Customization, modify the Form Header Text with the text you want to use.
  4. Select Save.

Adding the Client OS agent

The following procedure adds the Client OS agent that the policy uses to segregate Linux devices into the intended policy.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. After the Logon Page agent, on the fallback branch, select the add icon (+).
  2. Select the Endpoint Security (Server-Side) tab.
  3. Select Client OS and select Add Item.
  4. In the pop-up window, on the Properties tab, select Save.

Adding the Client Type agent

The Client Type agent attempts to determine the client software that initiated a request. This allows the access policy to apply policy decisions based on the determined client type.

The following procedure adds a Client Type agent to the access policy, which limits policy actions to apply to clients that are standalone Edge Client and browser-based access. The focus of this step is to determine whether the Linux user is using the standalone Edge Client.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In VPE, in the Client OS agent, on the Linux branch, select the add icon (+).
  2. In the pop-up window, select the Endpoint Security (Server-Side) tab.
  3. Select Client Type and select Add Item.
  4. Select the Branch Rules tab.
  5. Select the Remove icon (x) for to remove the rules for Edge Portal, Windows Inbox F5 VPN Client, F5 Access, Machine Tunnel, Citrix Receiver, Citrix Receiver (legacy), VMware View, Microsoft RDP Client, and MS-OFBA Compliant.

    Do not remove the rules for Edge Client and Full or Mobile Browser.

  6. Select Save.

Creating the Split-Passwords variable assignments

When a user enters their password, the system saves the value of the password in the assignment variable session.logon.last.password. You can create a variable assign that parses the user password for specific characters and split characters that precede or follow the special character, which assigns the independent character sets to a variable assign value.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In VPE, after the Client Type agent, on the Edge Client branch, select the add icon (+).
  2. In the pop-up window, select the Assignment tab.
  3. Select Variable Assign and select Add Item.
  4. On the Properties tab, change the Name to Split-Passwords.
  5. Under Variable Assign, select Add new entry.

    Note: Leave the setting Insert Before at the default setting 1.

  6. Under Assignment select change.
  7. In the variable assign pop-up window, for the left box, select Custom Variable, Secure, and enter the following variable name:

    session.logon.second_password

  8. For the right box, leave the default setting Custom Expression and enter the following stanza:

    return [lindex [split [mcget -secure {session.logon.last.password}] "/"] 1]

    Note: This stanza searches the user-entered password (session.logon.last.password) for characters that follow the slash character (/).

    Note: When using repeating delimiter characters such as //, be sure to increment the count value appropriately. For example, since there are two slashes, // requires the value of 2.

    The following figure shows the variable assign pop-up window as it should appear after you configure the previously described settings.

      

    Figure: Variable assign example

  9. Select Finished.
  10. Under Variable Assign select Add new entry.
  11. For 1 select change.
  12. In the variable assign pop-up window, for the left box, select Custom Variable , Secure and enter the following variable name:

    session.logon.first_password

  13. For the right box, leave the default setting Custom Expression and enter the following stanza:

    return [lindex [split [mcget -secure {session.logon.last.password}] "/"] 0]

    Note: The stanza searches the user-entered password (session.logon.last.password) for characters that precede the slash (/).

    The following figure shows the variable assign pop-up window as it should appear after you configure the previously described settings.

     

    Figure: Variable assign example

  14. Select Finished.
  15. Select Save.

Adding the first authentication agent

The following procedure adds a RADIUS authentication agent to the access policy. The password variable assignment used when authenticating the user is session.logon.first_password.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In VPE, after the Split-Passwords agent, on the fallback branch, select the add icon (+).
  2. Select the Authentication tab.
  3. Select RADIUS Auth and select Add Item.
  4. For AAA Server, select your previously configured RADIUS device.
  5. Optionally, for Show Extended Error, select Enabled.
  6. For Password Source, replace the existing text with the following:

    %{session.logon.first_password}

  7. Select Save.

The following figure shows the Properties tab for the RADIUS Auth agent pop-up window as it should appear after you configure the previously described settings.

Figure: RADIUS Auth agent with modified Password Source

Adding the second authentication agent (OTP)

The following procedure adds a RADIUS or SecurID authentication agent to the access policy. When authenticating a user, the password variable assignment used is session.logon.second_password.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In VPE, after the RADIUS Auth agent, on the Successful branch, select the add icon (+).
  2. Select the Authentication tab.
  3. Select RADIUS Auth and select Add Item

    Note: Depending on your environment, you may select RSA SecurID instead.

  4. For AAA Server, select your previously configured RADIUS OTP or RSA SecurID device.
  5. For Name, change RADIUS Auth(1) to OTP Auth.
  6. Optionally set Show Extended Error to Enabled.
  7. For Password Source, replace the existing text with the following:

    %{session.logon.second_password}

  8. Select Save.

The following figure shows the Properties tab for the OTP Auth agent pop-up window as it should appear after you configure the previously described settings.

Figure: OTP Auth agent with modified Password Source

Adding the Resource Assign agent

The following procedure outlines assigning resources to the authenticated access session. You must create the resources you want to assign before you perform this procedure. Creating these resources is not covered in this article.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In VPE editor, after the OTP Auth agent, on the Successful branch, select the add icon (+).
  2. Select the Assignment tab.
  3. Select the assignment type for your deployment (Advanced Resource Assign) and select Add Item.
  4. Select Add new entry.
  5. Select Add/Delete.
  6. Select the previously created resources you wish to assign for the access session.
  7. Select Update.
  8. Select Save.

Modifying the policy end point

For a successfully authenticated access session to complete the establishment of an access session, you need to set the access policy branch end point to Allow.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. After the Advanced Resource Assign agent, on the fallback branch, select the Deny end point.
  2. In the Select Ending pop-up window, select Allow.
  3. Select Save.
  4. Select Apply Access Policy.

Configuring additional settings

After you perform the previous procedures, the access policy is configured to process request for Linux clients using the standalone f5fpc client to establish an access session that requires multi-factor authentication.

The access policy Client OS type non-Linux branches and you need to configure the Client Type branch for Linux Full or Mobile browser settings as required by your OTP software vendor.

Note: Although you can use the logic of the access policy for browser-based access, F5 recommends implementing a previously documented browser-based solution.
