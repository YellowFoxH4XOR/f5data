Known Issue

The bigd process may produce a core file and restart when using receive strings with multiple wildcards.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP monitor using a receive string.
  • The receive string contains multiple wildcards and begins with a period and an asterisk character (.*).

    For example:

    recv_string: .*HTTP.*200 OK.*

Impact

The BIG-IP system does not perform health monitoring while the bigd process is restarting. As a result, the BIG-IP system may not collect information used for load balancing decisions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ltm file, you observe an error message that appears similar to the following example:

    emerg logger: Re-starting bigd

  • Your BIG-IP system logs a bigd core file to the /shared/core directory.

Workaround

To work around this issue, you can remove the period and asterisk characters at the beginning of the receive string.

Impact of workaround: Performing this suggested workaround should not have a negative impact on your system.
