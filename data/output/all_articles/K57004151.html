Known Issue

When you enter a command that uses the :p modifier with the tcpdump utility to capture server-side traffic, the first few server-side packets are missing. For example, the tcpdump -i <vlan>:p host <client-ip> command syntax causes this issue.

This issue occurs when all of the following conditions are met:

  • You use the :p modifier with the tcpdump utility to capture server-side flows associated with client-side flows that match a tcpdump filter.
  • Traffic flows are captured for one of the following virtual server and profile configurations:
    • Performance (Layer 4) virtual server type with an associated FastL4 profile
    • Standard virtual server type with an associated User Datagram Protocol (UDP) profile

Impact

None. The BIG-IP system captures the packets, even though they are not displayed.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you use the tcpdump utility with the :p modifier to capture server-side traffic, the first few server-side packets are not displayed.

Workaround

To work around this issue, you can specify a filter in the command that includes server-side traffic, such as including pool member addresses, by including the following code in your tcpdump command:

host <addr>

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
