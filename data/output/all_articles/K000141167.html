K000141167: Is there a way to "load balance" DNS clients by randomising the order of multiple returned A records on the Big-IP?

Type
Support Solution
Published
2024-09-24
Updated
2024-09-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.2
Source
https://my.f5.com/manage/s/article/K000141167

Description

Randomising the order when multiple A records are returned by the BIGIP LTM's DNS resolver would be the appropriate way to "load balance" DNS clients, since most DNS clients will just use the first entry unless it times out, in which case they'll use the 2nd entry, and then the 3rd, etc.

 

Environment

BIG-IP LTM

 

Cause

This common DNS client behaviour is despite the fact that the DNS specifications state that if a client gets more than one A record then it should pick one at random - most DNS clients just pick the first returned entry from the list and use it, and only use the 2nd as a fallback and the 3rd as a 2nd fallback, and so on.

 

Recommended Actions

This functionality is not currently in LTM's "net dns-resolver" - we merely cache entries we get from upstream DNS servers and serve them up exactly as cached for every client request.

 

The DNS cache feature on the Big-IP does have this functionality already ( DNS ›› Caches : Cache List ›› New... ).

There is a setting in it called called RRSet rotate:

 

RRSet Rotate

Specifies the resource record rotation method used within cached responses. The default is none. 

none: Specifies that resource record order is not modified.

query id: Specifies that resource record order is a function of the client's query id.

 

Thus, with RRSet Rotate set to "query id", you could achieve this functionality, however it needs the DNS Cache feature to be enabled on the Big-IP, as it is not available with the base LTM feature.
