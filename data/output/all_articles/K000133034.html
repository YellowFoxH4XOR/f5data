K000133034: The VPN application on MacOS is stuck on Connecting or unresponsive

Type
Support Solution
Published
2023-03-17
Updated
2025-01-13
Applies to
  • BIG-IP
  • BIG-IP APM: 16.1.2
Source
https://my.f5.com/manage/s/article/K000133034

Description

The VPN application on MacOS is stuck on Connecting or unresponsive. There is no access to the resources behind VPN.

The following can be seen in the session logs:

TunnelStats: LCP_LINK_FAILURES 1,LCP_PROTO_REJ 1,FSM_UNEXPECTED_DOWN

LCP Link failure means that the PPP tunnel was marked down with the LCP parameter value.

Link Control Protocol (LCP) is used to set up, maintain, and shut down the connection.

You can see these errors by running the following command in the BigIP CLI:

tmctl -d blade tmm/ppp/errors

Additionally, these packets can be seen during a packet capture:

Macbook -> Virtual server: Alert (Level: Warning, Description: Close Notify)

Macbook -> Virtual server: ICMP Destination unreachable (Port unreachable)

Environment

  • VPN
  • APM
  • MacOS Device

Cause

Every time the user closes the lid, the MacBook goes into sleep mode and the Mac disconnects from the network and terminates any active connections. After waking up the device, when the Mac attempts to use the same session, the APM may reject the connection attempt, causing LCP Link failure and other related errors on the device and sometimes causing the VPN app to freeze.

Recommended Actions

  • If you want the users to re-authenticate every time they try to reconnect, then you can set the field "Client Power Management" under Network Access Settings to "Terminate".
  • Alternatively, don't let the device get into sleep mode with VPN active (you can adjust the power plan for that).
