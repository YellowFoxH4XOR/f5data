K000152989: Replacing Client-SSL certificate causes application to stop loading

Type
Support Solution
Published
2025-08-13
Updated
2025-08-13
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000152989

Description

After updating the Client-SSL profile on a VIP to use a new cert and chain, the application will no longer load.

Looking at a pcap from the F5, you confirm that the Server Hello passes along the correct/updated SSL certificates, after which the connection is terminated.

You may also see a pcap from the Client side which shows the Server Hello never arrives, but instead after sending the Client Hello the connection is then closed by the Server.


Environment

  • New SSL Certificate & chain for application
  • New Client-SSL profile for new cert & chain
  • App completely stops working when the new Client-SSL profile is applied.
  • Virtual Server is in DMZ


Cause

Firewall between VIP and Client is configured to inspect application traffic. It does this by using the Server Certificate and Private Key to decrypt SSL traffic, inspect it, then re-encrypt it. Packets are inspected in both directions. When the Server SSL Certificate is updated, the firewall can no longer do the inspection properly, so it closes or terminates the connections instead of forwarding them through.


Recommended Actions

Install the updated certificate on the firewall so it is able to continue decrypting/inspecting/encrypting traffic properly.


Additional Information

Different firewalls may call this process by different names, but if the firewall needs to decrypt and inspect the traffic, it likely has a certificate installed in order to do so.
