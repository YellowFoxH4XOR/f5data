Known Issue

If you update a secure network address translation (SNAT) pool, the BIG-IP system may reset statistics for members of the SNAT pool. As a result, the members of the SNAT pool may appear to start using a different load balancing distribution method.

This issue occurs when the following condition is met:

  • In the Configuration utility, you clicked Update on the SNAT pool properties page.

The Least Connection load balancing algorithm is used for distribution of connections across members of a SNAT pool. However, when you use the Configuration utility to update a SNAT pool, the statistics used to calculate the least connections for the pool are reset. As a result, the connection counts for each member in the SNAT pool will be reset to 0. The SNATs may initially appear to use the Round Robin distribution method, even though they are still using the Least Connection distribution method.

Impact

SNAT address distribution may appear to start using the Round Robin algorithm.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The SNAT pool statistics page in the Configuration utility indicates the statistics for the affected SNAT pool have been reset.
  • The tmsh show ltm snatpool command indicates the statistics for the affected SNAT pool have been reset.
  • SNAT address distribution appears to begin using the Round Robin algorithm.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to make configuration changes to a SNAT pool.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
