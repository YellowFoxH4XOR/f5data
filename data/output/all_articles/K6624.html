K6624: BIG-IP ASM blocks certain requests when blocking is set to disabled on the web application policy

Topic

When building a web application policy, you may want to place the BIG-IP Application Security Module (ASM) in the flow of traffic for your web application, but disable the blocking feature until the policy is complete. There are, however, some scenarios under which BIG-IP ASM will block requests when the blocking feature is disabled on the policy.

The following table represents those requests that BIG-IP ASM will block when the blocking feature is disabled, and the actions you can take to correct the blocked request:

Blocked requestsCorrect requests
Improper HTTP versionThe valid HTTP versions are: 0.9, 1.0, and 1.1
Improperly terminated headerHeaders must be terminated by \r\n or \n
Improperly terminated header sectionThe header section must be terminated by \r\n\r\n, \n\n, or \r\n\n
Improperly formatted URIThe properly formatted URI will appear as follows:

<request method> [space] <URI> [space] <version>

Refer to RFC2616 section 5.1 for details.

Improperly formatted multipart bodyFor example, an HTTP request that contains no closing boundary and no chunked content.

Refer to RFC2046 section 5.1 and RFC2616 section 19.2 for details.

Improperly formatted chunked requestFor example, you must not send data sent after last chunk, or a negative chunk size.

Refer to RFC2616 section 3.6.1.

Request exceeds maximum request length valueThe default maximum request length value for the BIG-IP ASM is 10,000,000 bytes, as defined in the internal parameter, long_request_buffer_size

URI length exceeds maximum URI length valueThe default maximum URI length for ASM is 2048 bytes as defined in the internal parameter, ecard_max_http_req_uri_len
