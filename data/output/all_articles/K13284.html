Topic

This article applies to BIG-IP 11.x through 21.x. For information about other versions, refer to the following article:

  • K3669: Overview of management interface routing (9.x - 10.x)

The Traffic Management Microkernel (TMM) controls all of the BIG-IP switch ports (TMM interfaces), and the underlying Linux operating system controls the BIG-IP management interface. The management interface processes only administrative traffic. The TMM interfaces (self IP) can process both application traffic and administrative traffic.

Description

You can categorize traffic processed by the BIG-IP system as either application traffic (also referred to as data plane traffic), or as administrative traffic (also referred to as control plane or management traffic).

The BIG-IP system's management interface is intended to only process administrative traffic.  Administrative traffic is described as follows:

Inbound administrative traffic

The Linux operating system processes inbound traffic sent to the BIG-IP management IP address and arriving on the management interface. Inbound connections sent to the BIG-IP self IP addresses that arrive on a TMM interface are processed by TMM. If the self IP address is configured to allow a connection to the destination service port, TMM hands the connection off to the Linux operating system, which then processes the connection request. By default, for traffic destined to the management-IP (but not to self IP), the BIG-IP system uses Auto Last Hop to return response traffic to a remote host. Auto Last Hop returns response traffic to the MAC address of the device from which the traffic last traversed before reaching the BIG-IP system.  This feature allows access to the management interface without the need to configure specific return routes  (management routes) on the BIG-IP device.

For more information on the 'Management Auto Last Hop' feature refer to K52592992: Overview of the Auto Last Hop feature on the management interface

Note: Beginning in BIG-IP 14.1.0, the Auto Last Hop feature is no longer available on the BIG-IP management interface. For more information, refer to K55225090: BIG-IP VE no longer supports Auto Last Hop for management connections.

Outbound administrative traffic

The Linux operating system processes outbound traffic sent from the BIG-IP system by administrative applications, such as SNMP, SMTP, SSH, and NTP. These connections may use either the management address or a self IP address as the source address. The BIG-IP system compares the destination address to the routing table to determine both the interface through which the BIG-IP system routes the traffic, and which source IP address will be used for the outbound connection.

Packets sent from the management IP address (for example, reply packets sent out in response to incoming management traffic) use a separate Linux routing table, which contains only the management routes (no tmm routes). This ensures that egress packets from the management IP address will only ever use management routes to select the next hop device towards that destination.  From a technical point of view, this is implemented using an IP rule that directs the Linux kernel to table 245 when the source IP address is equal to the system management IP:

In the example below, the management address is 192.168.1.245, and the default management route is via 192.168.1.1:

[root@bigip1:Active:Standalone] # ip rule show | grep 245
245:    from 192.168.1.245 lookup 245 

[root@bigip1:Active:Standalone] config # ip route show table 245
default via 192.168.1.1 dev mgmt 
192.168.1.0/24 dev mgmt scope link src 192.168.1.245

To avoid any doubt, responses to administrative (management) traffic directed to a self IP will respond out a tmm interface, per the tmm route table. For self IPs to respond to management traffic, port lockdown ('allowed-services') must be configured within the self IP settings, to allow such traffic.

Note: If the kernel lasthop module is present and enabled, the normal kernel route lookup process described above will be skipped, and the packet will be addressed to the layer-2 MAC address of the original sender (lasthop) without performing any nexthop lookup or ARP resolution.

BIG-IP routing tables

The BIG-IP device consists of two distinct TCP/IP stacks - one implemented within the Traffic Management Microkernel (tmm) process (which "production" traffic passing through tmm uses), and a second in the Linux kernel itself.  The BIG-IP system populates the default kernel route table with routes from tmm, so that Linux commands and utilities are able to reach endpoints via tmm self IP addresses.    Management routes are installed into the Linux kernel routing table with a higher metric, making them less preferred over any tmm routes that also match the destination.  

When TMM is not running, the TMM self IP addresses are not available, and any TMM routes are removed from the kernel routing table. As a result, when TMM is not running, and with management auto last hop disabled or not present, outbound administrative traffic uses the most specific matching management route.

Important: When the destination address does not match the management interface subnet, the system uses the default gateway of TMM unless there is a more specific route configured on the management interface.  When there is no default route specified in TMM, the system uses the default route specified for the management interface.

Monitor traffic

LTM monitor traffic is sent by the bigd process, and uses the default kernel route table to reach pool members.  Before sending a packet out, the bigd process checks to see if it would egress via the management interface, and drops it if it would - this ensures that monitor packets follow the same network path as production tmm traffic, avoiding the situation where a unreachable pool member is inappropriately marked up if it was reachable via the BIG-IP management interface.   It is possible to disable this bigd check, by setting the system db variable "Bigd.MgmtRouteCheck" to "disabled", but this is not recommended, for the reasons just described.

GTM (DNS module) monitor traffic is sent by the big3d process, and the same check is performed, but can not be altered for the big3d process.  If the route to a pool member would egress via the management interface, big3d will not sent the probe, and will return a down reason of "No route to host" instead.   

Note: If the kernel lasthop module (management auto last hop) is present and enabled, and a pool member has recently sent a packet to the management IP of the BIG-IP device, then the route lookup mentioned above may return the management interface as the selected egress interface, causing both bigd and big3d to fail the monitor probe.   In this situation, the kernel lasthop module must be disabled, and management routes must be configured.

 

Managing routing parameters

To manage routing parameters for the management interface, you can perform the following functions:

Note: To manage the BIG-IP system routing information, you are must authenticate to the BIG-IP with an account with the 'Administrator' role.

Viewing, deleting, and adding management IP addresses

  • To view the management IP address, type the following command:

    tmsh list /sys management-ip

  • To delete an existing management IP address, use the following command syntax, replacing <address> with the management IP address:

    tmsh delete /sys management-ip <address>

  • To add a new management IP address, use the following command syntax, replacing <address> with the management IP address and <netmask> with the network mask:

    tmsh create /sys management-ip <address>/<netmask>

Viewing, deleting, and adding management routes

  • To view the management route, type the following command:

    tmsh list /sys management-route

  • To delete an existing static route for the management network, type the following command:

    tmsh delete /sys management-route <name>

    For example:

    tmsh delete /sys management-route log_receiver_net

  • To add a static route for traffic to use the management network, use the following command syntax:

    tmsh create /sys management-route <name> network <destination network>/<netmask> gateway <management gateway>

    Replace <name> with the name you want to use to identify this route. Replace <destination network>/<netmask> with the IP address and netmask of the network you are routing to. Replace <management gateway> with the IP address of the router used to access the destination network.

    For example:

    tmsh create /sys management-route log_receiver_net network 10.10.10.0/255.255.255.0 gateway 172.16.1.254

    Note: If the destination specified in the management route is not directly connected to the management interface, then the entry will not be included into the routing table. The BIG-IP Configuration utility would display a warning to the effect.

  • To save changes to the static routes for the management network, type the following command:

    tmsh save /sys config

Viewing routing tables

  • To view existing management routes, type the following command:

    tmsh list /sys management-route

  • To view all existing TMM routes, type the following command:

    tmsh show /net route

  • To view all existing routes in the Linux kernel routing table, type the following command:

    netstat -rn

    Note: The management interface is represented by the netstat command as eth0, in the command output.

  • To view routes in the routing table, main, type the following command:

    ip route show table main

  • To view the management routing table routes (table 245), type the following command:

    ip route show table 245

Viewing, deleting, adding IP rules

  • To view existing IP rules, type the following command:

    ip rule show

  • To delete an existing IP rule, use the following command syntax, replacing <address> with the management IP address:

    ip rule del from <address>

  • To add an IP rule to the management routing table, use the following command syntax, replacing <address> with the management IP address:

    ip rule add from <address> pref 245 table 245

    Note: This command adds the management address to the management routing table with a route metric of 245.

Recommendations

When configuring management traffic, you should consider the following factors:

  • F5 recommends that you add static routes for management traffic whose destination does not match the directly-connected management network. This configuration is useful, for example if you need to send syslog, SNMP or LDAP traffic to a destination on a non directly-connected network,, or have other network services that are hosted on networks that are not accessible through the TMM self IP interfaces.
  • A Virtual Clustered Multiprocessing (vCMP) host administrator can reconfigure the default management gateway for a vCMP guest, by making changes to the VCMP guest configuration on the VCMP host . The applied configuration takes precedence and overrides the value configured on the vCMP guest.

    Note: F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.
