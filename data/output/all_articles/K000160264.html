Description

BIG-IP APM implements a policy with a Patch Management inspection agent. However some users report that the check consitently fails for them despite having applied all the latest software updates.

The resulting session variables and log for the failed session are listed below:

  • session.check_software.last.pm.item_3.state set to 0
  • session.check_software.last.pm.result set to 0
  • session.policy.result set to deny

Log message (apm logs):

Nov 11 11:11:11 slot1/host.example.com notice apmd[111111]: 014902f7:5: /Common/mypolicy:Common:11111111:/Common/mypolicy_checker_act_pm_software_check_ag_1: endpoint software detected (sdk=4.1.1111.0,type=pm,id=111111,vendor_id=111111,version=3.0,state=0,name=Software Update,vendor_name=Example,db_signature=11111,db_version=,db_time=,last_scan=,engine_version=,missing_updates=0).

Users are unable to pass the Patch Management check and are denied access.

Environment

  • BIG-IP APM (Access Policy Manager)
  • MacOS client
  • Patch Management inspection enabled in APM access policy

Cause

By default, Patch Management is configured with "Automatic Updates" set to "Enabled". That setting means that Patch Management inspection will fails when none of the macOS automatic update features are enabled. The endpoint inspection logic reports a state = 0 and, irrespective to the amount of missing_updates, the checks fails.

The configuration of the inspection agent shows:

apm policy agent endpoint-check-software /Common/POLICYNAME_act_pm_software_check_ag { items { 0 { missing-updates 1 platform mac state enabled } } type patch-management } 

In the logs, inspecting the session variables for the failed session, we can observe:

session.check_software.last.pm.result 0

session.check_software.last.pm.item_3.state 0

The first line indicates that the check failed (Success is indicated with the value 1). The second line indicates that the state of Automatic Updates is disabled.

Note: Automatic Updates may also appear as a grayed out option if they are managed by a 3rd party.

Answer/Recommended Actions

To resolve the issue and allow users to pass the Patch Management check:

  1. On the affected macOS device, open System Settings.
  2. Navigate to General > Software Update.
  3. Ensure that at least one of the automatic update options is enabled (e.g., "Check for updates," "Download new updates when available," or similar).
  4. Retry the APM access process.

Alternatively, you can also change the Patch Management agent configuration in the VPE to set "Automatic Updates" to "Unspecified"
