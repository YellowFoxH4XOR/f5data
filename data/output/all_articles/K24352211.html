Known Issue

The remote client-ldap system-auth ssl-check-peer option may not retain the disabled state setting.

This issue occurs when all of the following conditions are met:

  • You configure a remote cert-ldap system-auth profile using the Traffic Management Shell (tmsh).
  • The client-ldap authentication profile is configured with ssl enabled.
  • You enable the ssl-check-peer configuration option.
  • You later disable the ssl-check-peer configuration option.
  • After you disable the ssl-check-peer option (using either the tmsh utility or Configuration utility), the system modifies the cert-ldap configuration .

Impact

The ssl-check-peer option reverts to the enabled configuration state.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The cert-ldap system-auth configuration continues to require and verify the server certificate.
  • When you review the cert-ldap system-auth configuration after you disable the ssl-check-peer, the ssl-check-peer is set to "no."
  • When you modify any aspect of the cert-ldap system-auth configuration after you set the ssl-check-peer to "no," the ssl-check-peer is set to "yes."
