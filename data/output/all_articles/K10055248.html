Description

The device_trust_group is stuck in a Sync Failed state, and the following error message appears:

01070734:3: Configuration error: Device group (/Common/dos-global-dg) cannot be deleted; only empty device groups can be deleted

Environment

  • After upgrade
  • After configuration reload
  • AFM provisioned

Cause

Dissimilar provisioning of AFM between peers in device group.

During configuration load, MCP checks the AFM provisioning, and if provisioned, creates the dos-global-dg device group, otherwise deletes it.

On a non-AFM unit, this may result in the dos-global-dg group being deleted automatically if previously created - syncing of this change will fail because the group is still present and has members on the peer unit - which has AFM provisioned.

Note: The device_trust_group device group is synced automatically.

Recommended Actions

It's recommended that all devices in a device group have equivalent provisioning to avoid this issue.

To work around the immediate issue, remove the members from the dos-global-dg group and it will be deleted automatically:

tmsh modify cm device-group dos-global-dg devices none

This should recover the sync status of the device_trust_group device group.

Reloading the configuration (or reprovisioning AFM) should re-create the dos-global-dg device group. Do not do this until all members of the group have equivalent AFM provisioning.

Additional Information

ID1033497 has been created to improve handling of this situation.
