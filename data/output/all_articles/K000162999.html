K000162999: BIG-IP DNS: NS, SOA, and CAA Queries Dropped When Local BIND Lookup Is Disabled

Type
Support Solution
Published
2026-10-13
Updated
2026-10-13
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP DNS
Source
https://my.f5.com/manage/s/article/K000162999

Description

BIG-IP DNS answers A-record queries through GTM/Wide IP processing but does not respond to NS, SOA, or CAA queries for the same zone.

Typical symptoms include:

  • NS or SOA queries time out.
  • CAA queries return SERVFAIL.
  • Extended DNS Error (EDE) 22 (No Reachable Authority) is returned.
  • Packet captures show that queries reach the DNS listener, but no response is returned.
  • A-record queries continue to succeed.

The issue occurs when the required records exist in a ZoneRunner/local BIND zone, but the DNS profile is not configured to consult local BIND.

Environment

  • Classic BIG-IP DNS with external UDP/53 listener virtual servers.
  • DNS profile settings:
    • use-local-bind no
    • unhandled-query-action drop
    • enable-dns-express no
  • A ZoneRunner/local BIND zone containing:
    • SOA records.
    • NS records.
    • CAA records.
    • Glue A records for the authoritative name servers.
  • A-record responses provided by GTM/Wide IP processing.
  • DNSSEC enabled on the delegated upstream DNS provider.
  • Client traffic reaching the DNS listener without address translation when source-based BIND access control is required.

Cause

The DNS listener receives queries that are not answered by the GTM/Wide IP processing path. Because use-local-bind is disabled, the listener does not consult the local BIND service for records maintained in the ZoneRunner zone.

With unhandled-query-action set to drop, unanswered NS, SOA, and CAA queries are silently discarded. A-record queries continue to work because they are handled by GTM/Wide IP processing.

Answer/Recommended Actions

Note: It is recommended to first test the configuration on a non-production zone first.

  1. Confirm that the ZoneRunner zone exists on each BIG-IP DNS device and contains the required SOA, NS, CAA, and glue A records.
  2. In the BIG-IP TMOS GUI, go to:
    DNS > Zones > ZoneRunner > named Configuration > Options
  3. Add an allow-query statement containing:
    • The existing BIG-IP internal ACL.
    • localhost, where required.
    • Approved DNS provider source IP addresses or CIDR ranges.
    • Approved certificate-validation service source IP addresses or CIDR ranges.
    • Any additional approved DNS client networks.
      Example: 
      allow-query {
    localhost;
    <approved-dns-provider-ip-or-cidr>;
    <approved-certificate-validation-ip-or-cidr>;
};
  4. Add allow-query as a separate access-control setting. Do not use the existing statement below as a query allowlist: 
    allow-transfer { localhost; };
allow-transfer controls zone transfers and does not authorize normal DNS queries.
  5. Do not use a DNS provider or certificate-validation service hostname as the BIND allowlist mechanism. Use approved IP addresses or CIDR ranges.
  6. Use the ZoneRunner GUI to update the BIND configuration.
    Important: F5 recommends configuring BIND through the BIG-IP DNS ZoneRunner GUI rather than editing named.conf directly from the command line. Navigate to DNS > Zones > ZoneRunner > named Configuration to add or modify the required BIND options. ZoneRunner performs syntax validation and helps prevent configuration changes from adversely affecting BIND or the ZoneRunner daemon (zrd)..

  7. Enable local BIND lookup in the DNS profile on each required BIG-IP DNS device: 
    tmsh modify ltm profile dns dns_profile use-local-bind yes
  8. Initially retain the existing setting: 
    unhandled-query-action drop
    Change this action only if NS, SOA, or CAA queries remain unanswered after enabling local BIND and confirming the ZoneRunner configuration.
  9. If the configuration was changed through the CLI, save it: 
    tmsh save sys config
  10. Verify the results against each DNS listener: 
    dig NS <zone-name> @<dns-listener-ip>
dig SOA <zone-name> @<dns-listener-ip>
dig CAA <certificate-validation-name> @<dns-listener-ip>
dig A <wide-ip-name> @<dns-listener-ip>
  11. Confirm that:
    • NS and SOA queries return authoritative records.
    • CAA queries return the expected CAA policy.
    • Existing A-record resolution continues to work.
    • Each DNS listener provides the expected responses.
  12. Confirm whether source NAT exists between the requesting client and the BIG-IP DNS listener. If NAT is present, BIND evaluates the translated source address rather than the original client address. The translated address must therefore be permitted by allow-query.
  13. Apply and validate the configuration independently on each required BIG-IP DNS device. The change is not propagated through GTM configuration synchronization.

      Additional Information

      • Enabling use-local-bind allows the DNS listener to use records maintained by the local BIND/ZoneRunner service. It does not replace GTM/Wide IP processing for records already handled by GTM.
      • Restricting queries with allow-query is appropriate only when the required source IP ranges are known and stable.
      • If the DNS listener must remain accessible to unrestricted users worldwide, listener-level source restrictions may not be suitable. Review DNS iRules, AFM policies, DNS rate limiting, and other security controls according to the deployment requirements.
      • Review the DNS and security architecture before enabling local BIND for the first time.
      • Configuration for one zone should not be assumed to exist for another zone. Verify each required zone separately.
