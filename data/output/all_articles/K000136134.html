K000136134: BIG-IP Edge client is constantly logging error messages

Type
Support Solution
Published
2023-09-29
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP APM: 14.1.5
Source
https://my.f5.com/manage/s/article/K000136134

Description

BIG-IP Edge client is constantly logging the following error messages.

 

2023-05-23,14:25:25:759, 12876,10448,DIALER, 1, \URLConnect.cpp, 663, URLConnect::BeginConnection, HttpSendRequest failed with HTTP 0. Proxy detected, please check your proxy settings

2023-05-23,14:25:25:759, 12876,12880,DIALER, 2, \URLConnect.cpp, 942, URLConnectEx::DownloadFile, Connection failed (URL: http://108.157.142.24/product/avail.txt)

2023-05-23,14:25:25:759, 12876,12880,DIALER, 48, \DialerCaptivePortalDetector.cpp, 204, DetectCaptivePortal, Download failed (rc, HTTP status), -1, 0

 

 

Environment

  • BIG-IP APM
  • BIG-IP Edge client
  • Error messages
  • Integrated IP filtering
  • Prohibit Route Changes
  • Captive Portal

 

Cause

Captive portal is triggered each time there is any network event happens. This is described in K05434484 or K18820340 linked below.

 

The BIG-IP Edge client automatically attempts to connect to the captive portal URL. As part of this the BIG-IP Edge client will attempt to add a route to the route table.

 

The log messages are the result of a combination of settings within the Network Access configuration.

 

Captive portal enabled

Integrated IP filter enabled

Prohibit Route changes enabled

 

This configuration combination prevents the Edge client to patch the clients routing table with 108.157.142.24 resulting in the errors seen above.

 

Recommended Actions

Option 1: Add the address space of probe to the address space exclude. This allows prohibit route changes and integrate filter to remain enabled.

 

apm resource network-access /Common/Network_Access_Example {

address-space-exclude-dns-name {.... }

address-space-exclude-subnet {

{

subnet 192.168.1.0/24

}

[...]                                     <<<< to add 108.157.142.0/24.

{

subnet 10.10.10.0/24

}

 

Note: It is possible the address can change in future if AWS changes their public IPs. If this happens the address space exclude would need to be updated.

 

Option 2: Prohibit route table changes and Integrated IP filtering options can be disabled. Then the Customer won't need to worry about adding or changing the probing IPs.

 

Option 3: The customer can disable captive portal detection.

 

K14766: Disabling BIG-IP Edge Client captive portal detection
