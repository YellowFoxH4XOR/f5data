K000159933: BIG-IP Custom F5 CA Bundle in Version 17.1.3 and Entrust CA Certificate Deprecation

Type
Support Solution
Published
2026-02-09
Updated
2026-02-09
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000159933

Description

BIG-IP version 17.1.3 introduced a custom F5 CA bundle containing multiple certificate authorities instead of relying solely on Entrust CA certificates. This change addresses the industry-wide deprecation of Entrust CA certificates and ensures continued connectivity to F5 services.

On BIG-IP versions prior to 17.1.3, the f5-ca-bundle.crt file contains only the Entrust CA certificate. Starting with version 17.1.3, the f5-ca-bundle.crt file includes 36 certificates from multiple trusted certificate authorities.

Systems running versions earlier than 17.1.3 may experience CA Bundle Manager failures with error messages such as:

  • "Download failed: https://cdn.f5.com/product/ca-bundle/blended-bundle.crt - Peer certificate cannot be authenticated with given CA certificates"

This issue impacts services that require outbound connectivity to F5 services and the internet, including:

  • CA Bundle Manager updates
  • BIG-IP SSL Orchestrator (SSLO)
  • F5 Secure Web Gateway (SWG)
  • BIG-IP APM HTTP Connectors
  • iRule sideband connections

Environment

  • Product: BIG-IP (all modules)
  • Affected Versions:
    • BIG-IP 17.1.2.2 and earlier (contains only Entrust CA in f5-ca-bundle.crt)
    • BIG-IP 17.5.1.2 and earlier
    • BIG-IP 16.1.6 and earlier
    • BIG-IP 15.1.10.7 and earlier
  • Fixed Versions:
    • BIG-IP 17.1.3 and later (contains 36 certificates in f5-ca-bundle.crt)
    • BIG-IP 17.5.1.3 and later
    • BIG-IP 16.1.6.1 and later
    • BIG-IP 15.1.10.8 and later
  • Configuration Objects:
    • /config/ssl/ssl.crt/f5-ca-bundle.crt
    • CA Bundle Manager
  • Related Features:
    • Firmware signature verification
    • BIG-IP image signing and verification process

Cause

Entrust CA certificates are being deprecated industry-wide due to trust status changes. Major browsers and certificate authorities no longer trust Entrust as a certificate authority. In March 2025, F5 replaced the Entrust certificate used at F5 services hosting managed CA bundles.

BIG-IP versions released before October 2025 rely on the Entrust CA certificate in f5-ca-bundle.crt to establish trust with F5 services (such as cdn.f5.com). When F5 rotated certificates away from Entrust CA, older BIG-IP versions can no longer authenticate connections to these services, causing CA Bundle Manager updates and other F5 service connections to fail.

Additionally, BIG-IP firmware images released in October 2025 and later are signed with new cryptographic keys. Older BIG-IP versions may not automatically verify these newer images due to the CA certificate rotation.

Answer/Recommended Actions

Primary Recommendation: Upgrade to BIG-IP 17.1.3 or Later

Upgrade your BIG-IP system to one of the following versions or later to resolve this issue:

  • BIG-IP 17.5.1.3
  • BIG-IP 17.1.3
  • BIG-IP 16.1.6.1
  • BIG-IP 15.1.10.8

Important considerations for upgrades:

  1. Due to firmware signature verification changes in October 2025 releases, you may need to temporarily disable BIG-IP ISO signature verification when upgrading from pre-October 2025 versions to 17.1.3 or later
  2. After installing the new version, re-enable BIG-IP ISO signature verification
  3. Manually verify all F5-provided software images using the procedures described in K24341140

Alternative: Manual CA Bundle Update (If Upgrade Not Immediately Possible)

If you cannot upgrade immediately, you can update the f5-ca-bundle.crt file manually using the F5-provided script:

  1. Log in to the BIG-IP system Advanced shell (bash) as root
  2. Download the f5-ca-bundle-installer script from F5 GitHub
  3. Run the script to update the CA bundle
  4. The script will update CA Bundle Manager configuration objects to use the new curated CA trust anchor bundle

Refer to K000157916 for detailed script instructions and procedures.

Avoid Manual Modification Without Upgrade

Do not manually modify f5-ca-bundle.crt on versions prior to 17.1.3 without using the F5-provided script, as:

  • Firmware signature verification depends on the CA certificates present in the running version
  • Manual modifications may not resolve all connectivity issues
  • Upgrades may overwrite manual changes

Additional Information

Understanding the Entrust CA "Expiry":

  • The Entrust CA certificate deprecation is not due to the certificate's actual expiration date
  • The deprecation is due to Entrust being designated as "untrustworthy" by major browsers and certificate authorities
  • References to "February 2026 expiry" in documentation refer to the planned deprecation timeline, not the certificate's technical expiration date

Impact on Firmware Signature Verification:

  • BIG-IP versions released October 2025 or later use new cryptographic keys to sign firmware images
  • Older BIG-IP versions may fail to verify newer firmware images due to CA certificate changes
  • Newer BIG-IP versions (17.1.3+) may fail to verify older firmware images signed with the previous CA

Services Affected by CA Bundle Issues:

  • CA Bundle Manager automatic updates
  • Forward proxy configurations (SSL Orchestrator, Secure Web Gateway)
  • APM HTTP Connectors reaching internet services
  • iRule sideband calls to external services
  • Any feature requiring outbound TLS connections to validate remote server certificates

Certificate Bundle Contents:

  • BIG-IP 17.1.2.2 and earlier: f5-ca-bundle.crt contains 1 certificate (Entrust CA only)
  • BIG-IP 17.1.3 and later: f5-ca-bundle.crt contains 36 certificates from multiple trusted CAs
  • The expanded bundle ensures continued access to F5 services and reduces dependency on any single CA
