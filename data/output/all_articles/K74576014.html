K74576014: REST framework updates to remote BIG-IP systems running BIG-IP 11.3.0 through 11.4.1 require a TMM restart

Topic

When the BIG-IQ system updates the REST framework on remote BIG-IP systems running 11.3.0 through 11.4.1, the Traffic Management Microkernel (TMM) receives an update that requires the process to be restarted. A TMM restart briefly interrupts traffic processing on the remote BIG-IP system.

Description

The BIG-IQ system uses the Representational State Transfer (REST) communication protocol to manage remote BIG-IP systems. When performing an initial device discovery of remote BIG-IP systems, the BIG-IQ system performs a REST framework check and automatic update to ensure the most recent REST framework is installed.

When using BIG-IQ 4.5.0 or 4.6.0 to perform an initial device discovery of a BIG-IP system running 11.3.0, 11.4.0, or 11.4.1, the remote BIG-IP system's TMM receives an update that requires TMM to be restarted. While the system is restarting TMM, traffic processing on the remote BIG-IP system will be interrupted, and error messages similar to the following are logged to the /var/log/ltm file:

notice logger: sshd: root@example ==> /usr/bin/bigstart restart tmm
notice tmm[12345]: 01010019:5: Caught signal 15, exiting

Recommendations

When using the BIG-IQ system to discover remote BIG-IP systems running 11.3.0 through 11.4.1, you should consider the following factors:

  • To determine if the remote BIG-IP system's TMM requires an update and restart, run the following command on the remote BIG-IP system's command line:

    grep 'set .*MAX_CONTENT_LENGTH 104857600' /usr/lib/tmm/tmm_mgmt.tcl

    If the command returns no output, a TMM update and restart is required. If the command returns output similar to the following, no TMM update or restart is required:

    set static::MAX_CONTENT_LENGTH 104857600

  • If the remote BIG-IP system requires the TMM update, F5 recommends that you perform the initial device discovery during a planned maintenance window.
