Known Issue

This is the result of a known issue. If you restore the configuration of a standby node in a failover pair from a backup file, the standby node will not perform a full synchronization with the active node until it is restarted. Similarly, if you restore the configuration of a secondary node in a cluster from a backup file, the secondary node will not perform a full synchronization with the primary node until it is restarted. If you select the Restore Networking Configuration check box while performing the restore operation, FirePass prompts you to restart the controller to finalize the restore operation. If you select the Restore Users and Groups Settings check box, but not the Restore Networking Configuration check box while performing the restore operation, FirePass displays a message that appears similar to the following example:

Restore operation complete.

Additionally, FirePass does not prompt you to restart.

If you do not restart the controller, some settings on the standby or secondary node may be inconsistent with the settings configured on the active or primary node. These inconsistent settings will not be updated through the incremental synchronization mechanism. In order to force a full synchronization, the failover or secondary node must be restarted after its configuration is restored. After the full synchronization occurs during startup, any new changes on the active or primary node will be synchronized to the standby or secondary node through the incremental update mechanism.

Note: You can restore the configuration of a FirePass controller from a backup file on the Device Management: Maintenance: Backup/Restore page.

F5 Networks Product Development tracked this issue as CR89185 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Additionally, this issue has been fixed in cumulative Hotfix HF-602-9, which has been issued for FirePass version 6.0.2. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by restarting the standby or secondary node after restoring its configuration from a backup file. To do so, perform the following procedure:

  1. Log on to the FirePass Administrative Console of the standby or secondary node.
  2. Navigate to the Device Management: Maintenance: Restart Services page.
  3. Click the Restart Controller link.
  4. Click the Restart button (FirePass versions 5.4 and later) or the Go! button (FirePass version 5.2).
