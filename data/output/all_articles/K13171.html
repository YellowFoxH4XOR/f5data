You should consider using this procedure under the following condition:

  • You want to configure a custom cipher list for a Client or Server SSL profile.

Description

BIG-IP SSL stacks

BIG-IP Secure Sockets Layer (SSL) profiles can use ciphers from two different SSL stacks. The NATIVE stack is built into the Traffic Management Microkernel (TMM), and the COMPAT stack is based on the OpenSSL library. The NATIVE stack is an optimized SSL stack that the BIG-IP system can use to take advantage of hardware acceleration for most SSL ciphers. F5 recommends that you use the NATIVE stack because it is suitable for most SSL connections.

Note: For information on the cipher suites that are hardware accelerated, refer to K13213: SSL algorithms that are hardware accelerated (11.x - 14.x).

In BIG-IP 11.x, the default SSL profiles use ciphers from only the NATIVE SSL stack. To use SSL ciphers from the COMPAT stack, you must manually configure the cipher string (for the profile) to COMPAT, which appears similar to the following example:

COMPAT:AES128-GCM-SHA256

Note: Beginning in BIG-IP 12.0.0, the COMPAT stack contains no SSL ciphers, by default. For a complete list of supported SSL ciphers from the NATIVE and COMPAT SSL stacks, refer to K13163: SSL ciphers supported on BIG-IP platforms (11.x - 13.x).

Default cipher list for SSL profiles

When you configure an SSL profile on the BIG-IP system, you can manually specify the ciphers available for SSL connections, or you can use the default cipher string, DEFAULT. When you use the - symbol preceding a cipher, the SSL profile removes the cipher from the cipher list, but it can be added back to the cipher list if there are later options that allow it. F5 recommends that you use the DEFAULT cipher string for Client and Server SSL profiles. However, you can configure an SSL profile to use a custom cipher suite. By applying different profiles to different virtual servers, you can make Client SSL virtual servers more or less permissive than others. For example, you can use this approach to allow only strong ciphers, thereby enforcing the PCI requirement for strong cryptography and eliminating Weak Supported SSL Ciphers Suite violations.

Configuring the SSL profile to include a specific SSL cipher

Before you add a cipher to an SSL profile, you should verify that the desired cipher is not already included in the DEFAULT cipher list for your BIG-IP system version.

Note: For information about SSL ciphers used in the default SSL profiles, refer to K13156: SSL ciphers used in the default SSL profiles (11.x - 13.x).

After you verify that the desired cipher is not already included in the DEFAULT cipher list, you can add the cipher to the SSL profile. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to to Local Traffic > Profiles > SSL > Client.
  3. Select the Create button.
  4. Type a name for the SSL profile.
  5. In the Parent Profile list, select clientssl.
  6. For Configuration, select Advanced.
  7. For Ciphers, select the Custom check box.
  8. In the Ciphers box, type the cipher string.

    For example, appending the :ECDHE:ECDHE_ECDSA:DHE_DSS string after DEFAULT to include all DSA ECC ciphers appears similar to the following:

    DEFAULT:ECDHE:ECDHE_ECDSA:DHE_DSS

  9. Complete the remaining profile settings.
  10. Select the Finished button.

Note: Alternatively, to configure an SSL profile to include all DSA ECC ciphers using the Traffic Management Shell (tmsh), use the following command syntax:

tmsh create /ltm profile client-ssl <profile_name> ciphers 'DEFAULT:ECDHE:ECDHE_ECDSA:DHE_DSS

Configuring the SSL profile to use only TLSv1.2 compatible ciphers

Impact of procedure: Configuring the profile to use only TLSv1.2 causes connection failure for clients that do not support TLS 1.2.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select the Create button.
  4. Type a name for the SSL profile.
  5. In the Parent Profile list, select clientssl.
  6. For Configuration select Advanced.
  7. In the Ciphers list, select the Custom check box.
  8. In the Ciphers box, type the cipher string.

    For example, the following string configures an SSL profile to use only TLS 1.2 compatible ciphers:

    TLSv1_2

  9. Complete the remaining profile settings.
  10. Select the Finished button.

Note: Alternatively, to configure an SSL profile to use only TLSv1.2 compatible ciphers using tmsh, use the following command syntax:

tmsh create /ltm profile client-ssl <profile_name> ciphers 'TLSv1_2'

Configuring the SSL profile to block a specific SSL cipher

Impact of procedure: Configuring the profile to block a specific SSL cipher may cause certain client connections to fail.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select the Create button.
  4. Type a name for the SSL profile.
  5. In the Parent Profile list, select clientssl.
  6. For Configuration, select Advanced.
  7. For Ciphers, select the Custom check box.
  8. In the Ciphers box, type the cipher string.

    For example:

    The following string allows the default ciphers for the SSL profile and blocks the AES128-SHA cipher:

    DEFAULT:!AES128-SHA

    Appending the :!AES string after DEFAULT to block all CBC mode ciphers appears similar to the following:

    DEFAULT:!AES

    Appending the :3DES string after DEFAULT to block all 3DES ciphers appears similar to the following:

    DEFAULT:!3DES

  9. Complete the remaining profile settings.
  10. Select the Finished button.

Note: The following are alternatives:

 - To create an SSL profile to block the AES128-SHA cipher using tmsh, use the following command syntax:
   tmsh create /ltm profile client-ssl <profile_name> ciphers 'DEFAULT:!AES128-SHA'

- To configure an SSL profile to block all CBC mode ciphers using tmsh, use the following command syntax:
  tmsh create /ltm profile client-ssl <profile_name> ciphers 'DEFAULT:!AES'

- To configure an SSL profile to block all 3DES ciphers using tmsh, use the following command syntax:
  tmsh create /ltm profile client-ssl <profile_name> ciphers 'DEFAULT:!3DES'

Configuring the SSL profile to order SSL ciphers by strength

Impact of procedure: Ordering SSL ciphers by strength may cause the virtual server to process fewer SSL transactions per second (TPS).

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select the Create button.
  4. Type a name for the SSL profile.
  5. In the Parent Profile list, select clientssl.
  6. For Configuration, select Advanced.
  7. For Ciphers, select the Custom check box.
  8. In the Ciphers box, type the cipher string.

    For example, the following string sorts the cipher list in order of encryption algorithm key length:

    DEFAULT:@STRENGTH

  9. Complete the remaining profile settings.
  10. Select the Finished ???????button.

Note: Alternatively, to create an SSL profile to order SSL ciphers by strength using tmsh, use the following command syntax:

tmsh create /ltm profile client-ssl <profile_name> ciphers 'DEFAULT:@STRENGTH'
