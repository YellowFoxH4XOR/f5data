Description

The connection is terminated with a reset error message " [F5RST: iRule execution (reject command)]" packet sent by the BIG-IP.

15695   5.221618 0.000064 230 X.X.X.X → X.X.X.X  22 54980 TCP OUT s1/tmm0 : 22 → 54980 [RST, ACK] Seq=1 Ack=1 Win=0 Len=0 [F5RST: iRule execution (reject command)] 

Environment

  • BIG-IP LTM
  • iRule
  • F5RST

Cause

In packet captures, the reset packet will show "[F5RST: iRule execution (reject command)]", confirming the rejection occurred at the BIG-IP level due to iRule execution.

The ‘reject’ response observed in this scenario is expected  and does not indicate a defect in the BIG-IP.

Recommended Actions

Important : The iRule must have been previously operating prior to contacting F5 support. For more information refer to the F5 support policies attached in the related content.

 

  1. Identify the iRule applied to the virtual server by reviewing the virtual server configuration:

#tmsh list ltm virtual <virtual_server_name> rules

  1. Review the iRule content to identify the restriction logic:

#tmsh list ltm rule <irule_name>

  1. Update the iRule to allow the traffic 
  2. Save the modified iRule configuration

#tmsh save sys config

  1. Verify that the iRule logic matches the intended access policy for all required traffic.

 

Note: Running these commands should not give any negative impact to the system.
