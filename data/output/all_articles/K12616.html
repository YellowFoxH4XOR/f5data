Known Issue

This is the result of a known issue. The BIG-IP system may reject passive FTP data connections when the virtual server operates in CMP mode and the system is not configured for VLAN-keyed connections. As a result, the FTP commands that the clients issue fail.

Note: CMP mode is available only on certain BIG-IP platforms and software versions. For more information, refer to K7751: Overview of Clustered Multi-Processing.

Note: The BIG-IP system is configured to use VLAN-keyed connections by default. This local-traffic property is generally disabled in deployments where asymmetric routing is required. For more information, refer to the Configuring local-traffic properties section of the TMOS Management Guide for BIG-IP Systems (formerly BIG-IP Network and System Management Guide).

F5 Product Development tracked this issue as ID 323748, ID 247898, ID 330809, and ID 224726 (formerly CR137457), and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM and Link Controller release notes.

Additionally, this issue has been fixed in cumulative Hotfix-BIGIP-9.4.8-407.0-HF4, which has been issued for BIG-IP 9.4.8, and cumulative Hotfix-BIGIP-10.2.0-1789.0-HF2, which has been issued for BIG-IP 10.2.0. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For information about installing a hotfix for 9.x systems, refer to K6845: Managing F5 product hotfixes for BIG-IP version 9.x systems.

For information about installing a hotfix for 10.x systems, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by disabling CMP mode for the affected virtual servers. For more information, refer to K7751: Overview of Clustered Multi-Processing.
