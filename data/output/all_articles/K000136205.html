K000136205: While trying to upgrade to v15.1.10 or v17.5.1.1x the "Install Configuration" option is either empty or incorrect

Description

When using the GUI to switch boot locations after an upgrade from v15.1.x to v15.1.10.x, or from v17.5.1.x to v17.5.1.1x, the "Install Configuration" drop down may not work properly, and may either:

  • show a narrow blank dropdown
  • show an incorrect or empty list of source boot volumes
  • if the "Source Volume" field is left blank, pressing "Activate" may cause the system to report the error "null does not exist."

Environment

  • BIG-IP VE / Appliance
  • upgrading from v15.1.x to v15.1.10.x
  • upgrading from v17.5.1.x to v17.5.1.1x

Cause

Bug ID 1349933

Note: This bug is fixed 17.5.1.9 and higher.

Recommended Actions

Choose the option that matches your situation:

Scenario 1: No configuration changes after the software installation: If you have not made any changes to the BIG-IP configuration after installing the image and plan to boot into the new boot location straight away, select No for the Install Configuration option, then click Activate.

Note: During the software installation process, a copy of the current configuration from the current boot location is copied into the new boot location, so a separate configuration install is not needed.

Scenario 2: Configuration changes made after the software installation: If you made changes after the image installation and plan to boot into the new boot location after making those configuration changes, use the cpcfg command in the bash CLI, as described in K14724: Using the cpcfg command to copy a configuration from one boot location to another, to copy the latest config to the new boot location from the current boot location. Then proceed to boot into the new location.

Additional Information

See K64400324: Should I use Install Configuration when activating a new Boot Location?

Another option is to reinstall the software on a target partition prior to reboot. The cpcfg process is part of the installation process, which you can see in /var/log/liveinstall.log.
