Description
The following article will guide you through gathering data to troubleshoot DNS inconsistent health status or iQuery mesh issues.

  • Inconsistent health status of iQuery mesh
  • DNS pool member down

Environment

  • DNS/GTM
  • Pools or pool members

Cause
There are various causes for an inconsistent iQuery mesh. Some include blocking Firewall rules, Port Lockdown issues, or No Route to Host

Recommended Actions

First determine if the bigip monitor can reach the target by running one of these from bash:    iqdump <ip_address>       or    telnet <ip_address> 4353
In order to further troubleshoot problems with GTM/DNS monitors or iQuery communication you can enable debug logging on the local GTM.

Enable Debug Logging
Impact of procedure: Enabling debug logging may cause excessive logging in a system with a large iQuery mesh, or on a system processing large numbers of DNS queries. You should only enable debug logging when troubleshooting and disable debug logging after you've finished troubleshooting.

Log into the command line utility as root and type the appropriate command for the issue you are troubleshooting

  • To log incoming wide-IP query processing on the system
    tmsh modify /sys db gtm.querylogging {value "enable"} 
  • To log more information about GTM monitor probe activity
    tmsh modify /sys db gtm.debugprobelogging {value "enable"} 
  • To log big3d processing of iQuery statistics and virtual server discovery
    tmsh modify /sys db log.big3d.level {value "debug"} 
  • To check gtmd iQuery connection information regarding configuration updates or monitor probes
    tmsh modify /sys db log.gtm.level {value "debug"} 
  • To log Zonerunner zone updates
    tmsh modify /sys db log.zrd.level {value "debug"}

Note: It is common to run more than one of these debug commands for troubleshooting, but it is unusual to need all of them at the same time. Please consult with your Support provider for further instructions.

Disable debug logging

tmsh modify /sys db gtm.querylogging {value "disable"}
tmsh modify /sys db gtm.debugprobelogging {value "disable"}
tmsh modify /sys db log.big3d.level {value "notice"}
tmsh modify /sys db log.gtm.level {value "notice"}
tmsh modify /sys db log.zrd.level {value "notice"}


Troubleshooting iQuery Communication
For instance, if you run tmsh show gtm iquery and see that some Servers are in Connecting or Not-Connected status:

To check iQuery communication between GTM/DNS and other F5 devices, you can use the 'iqdump' command:

iqdump -s <sync_group_name>  X.X.X.X
  • Where <sync_group_name> is the Group Name as defined in DNS > Settings > GSLB > General > Group Name
  • Where X.X.X.X is the self-IP of the remote system.

F5 Technical Support may ask for a fresh qkview and/or a log tarball after running debug activity. Please contact Support for instructions.
