Known Issue

The BIG-IP system may use the incorrect source IPv6 address for traffic sent from the Linux host.

This issue occurs when the following conditions are met:

  • Traffic originates from the Linux host.
  • The route table contains a default IPv6 route.
  • The route table also contains a more specific IPv6 route to the specific destination, and the more specific route uses a different nexthop address.
  • The neighbor entry for the more specific route's nexthop address is in a 'FAILED' state.

    Note: The route's nexthop status can be determined by using the ip -6 neighbor show command.

Impact

The BIG-IP system may be unable to reach remote IPv6 hosts, and monitor connections to the hosts may fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Remote IPv6 hosts are unreachable.
  • BIG-IP monitor connections to remote IPv6 hosts are failing.

Workaround

To work around this issue, you can configure a Gateway ICMP monitor to monitor the more specific route's nexthop address. In addition, you can recover from this issue by using the ping utility to ping the more specific route's nexthop address.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
