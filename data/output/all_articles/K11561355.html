Known Issue

The BIG-IP APM system may exhaust available file descriptors and stop evaluating access policies.

This issue occurs when all of the following conditions are met:

  • The log severity level for access policy logging is set to Debug.
  • You load or reload complex access policies with many agents configured.

If the log level for access policy logging is set to a severity of Warning or lower (Notice, Informational, Debug), specifically Debug, loading complex access policies may cause the apmd process to eventually exhaust all available file descriptors. When this behavior occurs, the BIG-IP APM system is unable to create new sessions and stops evaluating access policies.

Impact

The BIG-IP APM system fails to process traffic until you restart the apmd process.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to establish sessions with the BIG-IP APM system.
  • When connecting to the BIG-IP APM system, the system displays a message indicating that the user's session is finished.
  • The system generates messages to the /var/log/apm file that appear similar to the following example:

    err apmd[14427]: 01490000:3: HTTPParser.cpp func: "readFromSocket()" line: 86 Msg: epoll_create() failed [Too many open files].

  • When running the following command on the BIG-IP APM system, a large number of open files appear in the output:

    lsof -p `pidof apmd` | grep TCP; lsof -p `pidof apmd` | grep UDP

Workaround

To work around this issue, you can increase the log level severity for access policy logging and restart the apmd process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will cause a brief traffic disruption while the apmd process restarts.

Note: In 12.0.0 and later, do not use the log.accesscontrol.level database variable to modify the log level severity.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To set the access policy log level to Error, type the following command:

    modify apm log-setting all access modify { all { log-level { access-control err } } }

  3. To verify the log level for access-control, type the following command:

    list apm log-setting all-properties

    The command output appears similar to the following example:

    log-level {
       access-control err
       access-per-request notice
       apm-acl notice
       eca notice
       oauth notice
       sso notice
       swg notice
    }

  4. To close open file descriptors and restart the apmd process, type the following command:

    restart sys service apmd

  5. To exit the tmsh utility, type q.
