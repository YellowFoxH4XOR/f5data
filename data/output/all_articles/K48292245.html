Description

With TS1.19 and later version, BIG-IP Admin may notice Telemetry Streaming skips some reports when restnoded memory utilization is high.

Error messages in /var/log/restnoded/restnode.log

Thu, 14 Oct 2021 11:17:59 GMT - info: [telemetry] Total Memory Provisioned (node process): 1433 MB. Memory Threshold: 1290 MB (90%)
Thu, 14 Oct 2021 11:17:59 GMT - info: [telemetry] Monitor checks updated. Interval: 5s | Memory Threshold: 1290 MB
Thu, 14 Oct 2021 11:23:54 GMT - info: [telemetry] Total Memory Provisioned (node process): 1433 MB. Memory Threshold: 1290 MB (90%)
Thu, 14 Oct 2021 11:23:54 GMT - info: [telemetry] Monitor checks updated. Interval: 3s | Memory Threshold: 1290 MB
Thu, 14 Oct 2021 11:24:00 GMT - warning: [telemetry] MEMORY_USAGE_HIGH. Incoming data will not be forwarded.
Thu, 14 Oct 2021 11:24:00 GMT - warning: [telemetry] MEMORY_USAGE_HIGH. Temporarily disabling system poller(s).
Thu, 14 Oct 2021 11:24:00 GMT - warning: [telemetry] Skipped Data - Category: "LTM" | Consumers: ["My_Consumer"]

~~

Thu, 14 Oct 2021 12:17:59 GMT - warning: [telemetry] MEMORY_USAGE_OK. Resuming data pipeline processing.
Thu, 14 Oct 2021 12:17:59 GMT - warning: [telemetry] MEMORY_USAGE_OK. Re-enabling system poller(s).

Environment

Telemetry Streaming v1.19 and later version

Cause

This works as designed.  
"memoryThresholdPercent" parameter is added in "Controls" class on TS v1.90.0, "Once memory usage reaches this value, processing may temporarily stop until levels return below the threshold.". This is why some reports were skipped. We introduce this feature to protect restnoded from restarting under high memory pressure.
 

{
    "class": "Telemetry",

    "controls": {
            "class": "Controls",
            "logLevel": "debug",
            "memoryThresholdPercent": 90,    ########## default value is 90
            "debug": true
        },

    "My_Consumer": {
 

More details at CloudDocs Home > Telemetry Streaming > Appendix A: Schema
 

Recommended Actions

Although the skipping report behavior is as expected when restnoded memory usage is high , we recommend you to work with F5 Support to  find out why restnoded is using so much memory.


Some notes for debugging restnoded memory usage.

1.  use top command to find restnoded memory usage, 
e.g
top -p `pidof f5-rest-node` -n1

   PID USER      PR  NI    VIRT    RES    SHR S  %CPU %MEM     TIME+ COMMAND  30491 restnod+  20   0 2496792   1.3g   9084 S  13.3  5.4   3220:02 f5-rest-node          

"RES" default Max is 1433MB (1.4G). 1.3G here is more than configured 90% threshold. 

2. When more than one iControl applications are installed, you can remove telemetry declare and verify if TS caused restnoded high memory.
 To delete TS declare see:

CloudDocs Home > Telemetry Streaming > Deleting the Telemetry Streaming configuration

If high memory usage was caused by TS, after deleting declare, restnoded memory utilization will decrease  gradually.

3. One known reason which can cause restnoded high memory utilization is connections to Consumer do not close in time, either on http layer or on TCP layer.
For example, if a http consumer does not reply 200OK and close the http connection, BIG-IP will keep the connection open until idle timeout.
