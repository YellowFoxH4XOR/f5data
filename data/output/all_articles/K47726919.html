Topic

This article discusses the fully qualified domain name (FQDN) ephemeral node refresh behavior on the BIG-IP system at configuration load time.

Description

When you load the BIG-IP system configuration, the FQDN ephemeral nodes may not refresh immediately.

This is expected behavior. The FQDN ephemeral nodes do not repopulate the IP address returned in response to a DNS query until the configured FQDN time-to-live (TTL) interval expires. The default TTL interval is 3,600 seconds.

The following example illustrates a scenario in which the FQDN ephemeral nodes may not refresh immediately:

  • At 09:00, the BIG-IP system is configured with the following FQDN node configuration and the BIG-IP system has already received the ephemeral information. When you list the node configuration, the configuration may appear similar to the following example:

    # tmsh list /ltm node

    ltm node myserver {
        fqdn {
            name myserver.myf5.lab
        }
        state fqdn-up
    }
    ltm node _auto_192.168.10.100 {
        address 192.168.10.100
        ephemeral true
        fqdn {
            name myserver.myf5.lab
        }
    }

  • At 09:05, you perform a configuration load. You may see the FQDN ephemeral nodes (_auto_192.168.10.100) no longer display in the BIG-IP configuration. The FQDN ephemeral nodes only refresh after the TTL interval expires from the last DNS query.

Recommendations

  • If you perform a configuration load and the BIG-IP configuration does not display the FQDN ephemeral node(s) information, you can check on the FQDN node configuration again after the TTL interval period. To display the FQDN node configuration including the FQDN TTL interval setting, use the following command syntax:

    tmsh list /ltm node <node_name> all-properties

    For example, to list the node configuration for the node named myserver, enter the following command:

    tmsh list /ltm node myserver all-properties

    Note: You can use a glob expression in the tmsh command to specify the node configurations to display. For example, to list all nodes with names beginning with www.example, enter the tmsh list /ltm node www.example* all-properties command.

    The output appears similar to the following example:

    ltm node myserver {
        address any6
        app-service none
        connection-limit 0
        description none
        dynamic-ratio 1
        ephemeral false
        fqdn {
            address-family ipv4
            autopopulate enabled
            down-interval 5
            interval 3600
            name myserver.myf5.lab
        }
        logging disabled
        metadata none
        monitor default
        partition Common
        rate-limit disabled
        ratio 1
        session user-enabled
        state fqdn-up
    }

  • You can change the FQDN TTL interval to a smaller value if you want to. To do so, use the following command syntax:

    Impact of procedure: Lowering the FQDN TTL interval increases the frequency in which the BIG-IP system initiates DNS queries to resolve FQDN for node objects.

    tmsh modify /ltm node <node_name> fqdn { interval <seconds> }

    For example, to change the FQDN interval to 180 seconds for node myserver, enter the following command:

    tmsh modify /ltm node myserver fqdn { interval 180 }

    To save your changes, enter the following command:

    tmsh save /sys config

  • If you are troubleshooting and do not want to wait until the FQDN TTL interval is over, you can restart the bigd process to reset the TTL timer and force the ephemeral nodes to immediately repopulate.

    Impact of procedure: Restarting the bigd process temporarily interrupts the BIG-IP monitor processing, which may cause an interruption in traffic processing.

    To restart the bigd process, enter the following command:

    tmsh restart /sys service bigd

    To verify the bigd process status, enter the following command:

    tmsh show /sys service bigd

  • You should upgrade to BIG-IP 12.1.3.3 or later. Beginning in BIG-IP 12.1.3.3,  FQDN nodes are updated immediately when you load the system's configuration.
