Known Issue

This is the result of a known issue. When an access policy SSO configuration is using the SSO NTLMv1 method, and the SSO server needs to add a cookie in an HTTP 401 Unauthorized response, the SSO server may prompt the user to authenticate even if they have already authenticated. The BIG-IP APM ignores the HTTP 401 Unauthorized  response cookie; however, the SSO server expects the cookie in order to track the session.

Note: This behavior has been noted only when using PingFederate Internet Identity Security Platform; however, it may exist for other vendors.

F5 Product Development tracked this issue as ID 341053 and it was fixed in BIG-IP APM version 10.2.1. For information about upgrading, refer to the BIG-IP APM release notes.
