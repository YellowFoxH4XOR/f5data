K000130443: Once an ASM variable has been added via the CLI using '/usr/share/ts/bin/add_del_internal' it can then be viewed and modifed in the GUI

Type
Support Solution
Published
2023-01-03
Updated
2023-01-03
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000130443

Description

Per a KB article or maybe via F5 Support you were given instructions to run a command to use an ASM variable that does not appear in the ASM GUI portion of the BIG-IP. The most common ones are found here Security ›› Options : Application Security : Advanced Configuration : System Variables. Once the command has been run you then try to verify the setting on the CLI, but find that you cannot do so. You can only Add, Modify, or Delete.

 

Environment

  • ASM variables
  • CLI, GUI

Cause

There are usually a couple of reasons that an ASM variable needs to be dealt with in this way. The most common is a new variable that was provided to deal with a bug. The second one is to deal with one that has not been added to the GU.I

 

 Recommended Actions

  1. So the variable has been added using a command such as /var/share/ts/bin/add_del_internal add <variable to added> <variable value>. You then want to check it to ensure it is correct, but find that via the CLI you cannot. The CLI will only allow you to Add, Modify, or Delete. You can even look at the file and that is no help.
  2. The purpose of the command is to invoke the variable. Once that has been done, and ASM has been restarted, you can then go to Security ›› Options : Application Security : Advanced Configuration : System Variable and view it there. From there you will be able to check the current setting and modify it from the GUI.
