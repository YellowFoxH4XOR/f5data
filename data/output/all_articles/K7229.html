Topic

There are many ways of configuring administrative access to nodes through the BIG-IP system including but not limited to the following options:

  • Virtual servers
  • Forwarding virtual servers
  • ICMP and other Protocols
  • VLANs
  • NATs

Virtual servers

To configure SSH administrative access to nodes through the BIG-IP LTM system, you can perform the following tasks:

  • Create a pool containing the relevant node, specifying TCP port 22
  • Create a virtual server, using an available IP address, specifying TCP port 22

For more information about configuring virtual servers, refer to the BIG-IP LTM Configuration Guide.

Forwarding virtual servers

Forwarding virtual servers work like IP forwarding, but only expose selected nodes and services. You can create a forwarding virtual server for a host address or network address in a VLAN, allowing access from an alternate VLAN.

Host forwarding virtual servers

In a configuration with an external and an internal VLAN, you can configure a host forwarding virtual server to send administrative traffic from the external VLAN to the node on the internal VLAN. If the external VLAN, where the client resides, is assigned to the 192.168.0/24 network, and the internal VLAN, where the node resides, is assigned to the 10.0.0/24 network, you can create a host forwarding virtual server with an address of 10.0.0.1 that will be enabled on the external VLAN.

Network forwarding virtual servers

Alternatively, you can configure a network forwarding virtual server to send administrative traffic from the external VLAN to any host on the internal VLAN.

If the external VLAN, is assigned to the 192.168.0/24 network, and the internal VLAN is assigned to the 10.0.0/24 network, you can create a network forwarding virtual server with an address of 10.0.0.0 that will be enabled on the external VLAN.

For information about configuring forwarding virtual servers, refer to the BIG-IP LTM Configuration Guide.

ICMP and other protocols

If you want to pass ICMP, or a protocol such as GRE, you will need to create a virtual server type that supports all protocols (* All Protocols), such as Forwarding IP, Performance L4, or Forwarding L2. By designating a virtual server to support all protocols, you are specifying that the virtual server supports all TCP/IP network protocols.

VLANs and VLAN groups

VLANs do not require special configuration. However, you can configure two distinct VLANs into a VLAN group which can be used to load balance or forward administrative traffic in a layer 2 network. Typically, a VLAN group contains VLANs that are configured in the same IP address space.

For example, if you have a group of systems associated with the VLAN called external, and you would like all the systems on this VLAN to have administrative access the web servers that are in the VLAN called internal, you can create a VLAN group and add VLANs external and internal as members of the VLAN group. Once you have created the VLAN group, you can create a virtual server, such as a Forwarding L2 virtual server to process administrative traffic. A forwarding L2 virtual server shares the same IP address as a node in an associated VLAN.

By default, VLAN groups bridge IP traffic. If you want to pass other types of administrative traffic through the VLAN group you can enable the Bridge All Traffic VLAN group setting.

For information about configuring VLAN groups, refer to the BIG-IP LTM Configuration Guide.

NATs

The least secure option for allowing administrative traffic to nodes through the BIG-IP system, is to use a NAT. A NAT provides an IP alias that a node can use as its source IP address when making or receiving connections to clients on the external network. You can use the NAT to connect directly to the node through the LTM system. NATs do not support port translation, and are not suitable for protocols that embed IP addresses in the packet, such as FTP, NT Domain or CORBA IIOP.

For information about configuring NATs, refer to the BIG-IP LTM Configuration Guide.
