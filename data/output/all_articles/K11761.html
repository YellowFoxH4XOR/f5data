Issue

Error Message

HTTP module: authentication with <username> failed in authenticateUser(): Curl perform failed: problem with the SSL CA cert (60)

This is an expected behavior. When you use HTTPS with an HTTP AAA virtual server, SSL HTTP Forms authentication fails and the system generates an error message in the /var/log/apm file that appears similar to the following example:

HTTP module: authentication with user1 failed in authenticateUser(): Curl perform failed: problem with the SSL CA cert (60)

Recommended Actions

The way that the BIG-IP APM system uses the existing BIG-IP LTM SSL engine causes this error message. To work around this conflict, you can create a layered virtual server to proxy the AAA HTTP virtual server. To do so, perform the following procedures:

Important: This article uses unencrypted data internal to the BIG-IP APM system. All communication from the client to the BIG-IP APM system and from the BIG-IP APM system to the AAA virtual server are encrypted using SSL.

Note: Before using these procedures, you should already have an HTTP Forms AAA virtual server configuration defined.

  • Creating a web pool
  • Creating the layered virtual server
  • Updating the HTTP AAA virtual server

Creating a web pool

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools.
  3. Click Create.
  4. In the Name box, type a name for your pool.
  5. Under Resources , for New Members in the Address box, type the IP address of your AAA HTTP virtual server.
  6. In the Service Port list, click HTTPS.
  7. Click Finished.

Creating the layered virtual server>

  1. Log in to the Configuration utility.
  2. Expand Local Traffic > Virtual Servers.
  3. Click Create.
  4. In the Name box, type a name for your virtual server.
  5. In the Destination Address/Mask box, type the IP address of your AAA HTTP virtual server.
  6. In the Service Port list, click HTTP.
  7. Under Configuration, for SSL Profile (Server), in the Available box, click serverssl and move it to the Selected box.
  8. In the VLAN and Tunnel Traffic list, click Enabled on.
  9. For VLANs and Tunnels, in the Available box, click the appropriate VLAN and move it to the Selected box.
  10. In the Source Address Translation list, click Auto Map.
  11. Click Finished.
  12. Click the Virtual Address List tab.
  13. Click the IP address of your AAA HTTP virtual server.
  14. Clear the ARP check box.
  15. Click Update.

Updating the HTTP AAA virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Access > Authentication.

    Note: For BIG-IP 12.x and earlier, navigate to Access Policy > AAA Servers.

  3. Click the Name of the HTTP AAA virtual server that you are updating.
  4. In the Start URI box, change the URI scheme from https:// to http://.

    For example, change the following example:

    https://www.example.com/logon.aspx

    to:

    http://www.example.com/logon.aspx

  5. Optional: If Form Action has the same AAA virtual server as Start URI, you must update Form Action as described in step 4.
  6. Click Update.

Note: You may need to restart your BIG-IP APM system for the changes to take effect. To do so, type tmsh restart /sys service all  from the command line or use the BIG-IP APM Configuration utility to navigate to System > Configuration > Device > General and, under Properties and Operations, for Operations, click Reboot.

After completing these procedures, you should test authentication to verify that the error message is cleared. If the error message is cleared but authentication still fails, you must perform more troubleshooting to identify additional issues.
