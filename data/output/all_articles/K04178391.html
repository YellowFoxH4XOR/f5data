Known Issue

The BIG-IP system fails to process Secure Sockets Layer (SSL) connections.

This issue occurs when all of the following conditions are met:

  • You enable SSL persistence on the virtual server.
  • The SSL handshake message boundary does not align with the underlying Transmission Control Protocol (TCP) segment boundary. Any of the following examples may trigger the issue:
    • The maximum transmission unit (MTU) size of the TCP connection is changed to a value of 1,200 bytes or less.
    • The SSL handshake message size is greater than the maximum configured size (default 32 KB).

      Note: The SSL handshake buffer maximum message size is set by the tmm.ssl.maxhandshakesize system database key. For more information about this database key, refer to K17088: Increasing the size of the SSL handshake buffer.

Impact

SSL connections fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • On the client or server side, the SSL connections stop responding.
  • A packet capture of the affected traffic shows the SSL handshake message spans across two TCP segments on the client side, and the virtual server does not forward any messages to the associated pool member after the first segment.

Workaround

To work around this issue, you can use an alternative persistence type such as source address affinity.

Impact of workaround: Depending on your application environment, using an alternative persistence type may cause the system to distribute and persist connections unevenly across multiple pool members. F5 recommends that you test such changes in an appropriate environment.
