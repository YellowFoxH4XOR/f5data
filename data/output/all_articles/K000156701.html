K000156701: Receive Disable String feature overrides health check status of the additional health monitors

Type
Support Solution
Published
2025-09-30
Updated
2025-09-30
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000156701

Description

When configuring a BIG-IP LTM pool with multiple health monitors, including at least one monitor using the "Receive Disable String" feature, pool members may remain in a "disabled" state even if other monitors report the member as "up" and the pool's Availability Requirement is set to a minimum of one active monitor.

Environment

  • BIG-IP
  • Pool configured with multiple health monitors
  • One of the monitors is using "Receive Disable String"

Cause

If any assigned monitor receives a response matching its configured "Receive Disable String," the affected pool member is placed into a disabled session status, similar to manual disabling. This overrides the member's up/down status from other monitors and persists until explicitly re-enabled. The recv-disable mechanism allows server teams to disable traffic for maintenance without requiring direct BIG-IP administrative action.

Once disabled by recv-disable, the member does not automatically return to enabled status - even if subsequent responses no longer match the disable string and other monitors report up - preventing unintended traffic forwarding during maintenance or recovery periods.

Recommended Actions

  • Review your pool and monitor configuration so operational behavior matches expectations when using multiple monitors and recv-disable features.
  • Consult F5 documentation for further details on health monitoring logic and usage of Receive Disable String.
