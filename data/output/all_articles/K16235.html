Known Issue

The after iRule command may cause a Traffic Management Microkernel (TMM) memory leak.

This issue occurs when the following condition is met:

  • The after iRule command is assigned to a variable.

Assigning the after command to a variable prevents the release of the object and its related connection flow object, resulting in a memory leak for connflow, tcl (variable), tclrule_pcb, and filter (variable).

Impact

Memory exhaustion may cause TMM to produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system may eventually become unresponsive due to memory exhaustion.
  • The system may unexpectedly fail over or the TMM process may restart.
  • Memory utilization grows over time for the following objects:

    • connflow
    • tcl (variable)
    • tclrule_pcb
    • filter (variable)

      For example, running the following command over time may indicate that the memory utilization for the tcl (variable) object grows:

      tmctl memory_usage_stat | grep "tcl (variable)"

Workaround

To work around this issue, you can configure the iRule to unset the variable containing the after object.

For example:

when HTTP_REQUEST priority 800 {
set SCRIPT_ID [\
after $static::one_second {
log local0. "$LOG_MSG"
} \
]
}

when CLIENT_CLOSED {
unset SCRIPT_ID
}

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
