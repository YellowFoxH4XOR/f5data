Known Issue

The BIG-IP local device trust may be corrupt after loading a single configuration file (SCF).

This issue occurs when all of the following conditions are met:

  • You restore the BIG-IP system to default settings using the tmsh load sys config default command.
  • You load a previously saved SCF file with all centralized management (CM) objects removed, using the tmsh load sys config file <scf-filename> command syntax.

Note: For information about SCF, refer to K13408: Overview of single configuration files (11.x - 12.x).

Impact

The device trust data is no longer available, and you are not able to restore the data from the Configuration utility.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You cannot access the Device Trust page in the Configuration utility.
  • When you run the tmsh show cm device-group device_trust_group command, the BIG-IP system returns an error message that appears similar to the following example:

    01020036:3: The requested device group (/Common/device_trust_group) was not found.

  • The /var/log/webui.log file contains error messages that appear similar to the following examples:

    ERROR [TP-Processor8] system.xuistatus_jsp:_jspService - Error rendering HA indicator: com.f5.mcp.io.McpQueryException: 01020036:3: The requested devicegroup (/Common/device_trust_group) was not found.
    ERROR [TP-Processor8] system.xuistatus_jsp:_jspService - Error rendering HA indicator: com.f5.mcp.io.McpQueryException: 01020036:3: The requested devicegroup (/Common/device_trust_group) was not found.

  • The /var/log/ltm file contains error messages that appear similar to the following examples:

    err mcpd[30538]: 01020036:3: The requested devicegroup (/Common/device_trust_group) was not found.
    err mcpd[30538]: 01020036:3: The requested devicegroup (/Common/device_trust_group) was not found.

Workaround

To work around this issue, you can restart the devmgmtd process, causing the process to regenerate missing device trust objects. To do so, perform the following procedure:

Restarting the devmgtmtd process from the tmsh utility

Impact of workaround: Performing the following procedure should not have a negative impact on your system. However, in some cases, this workaround may not regenerate the device trust, and requires that you clear the configuration and merge the previous configuration from an SCF file. To do so, perform the Clearing the configuration and merging the previous configuration from an SCF file procedure.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the devmgmtd process by typing the following command:

    restart /sys service devmgmtd

  3. Verify the device group information has been restored by typing the following command:

    show cm device-group device_trust_group

Clearing the configuration and merging the previous configuration from an SCF file

In the event that a restart of the devmgmtd process does not resolve the issue and rebuild the device trust objects, you must clear the configuration and merge the previous configuration from an SCF file. To do so, perform the following procedure:

Impact of workaround: Loading a blank configuration will interrupt all traffic processing. This procedure should be performed on a non-active system and/or during a maintenance window.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Load the default configuration by typing the following command:

    load /sys config default

  3. Merge the SCF file using the following command syntax:

    load /sys config file <scf-filename> merge

    Note: Unless a full path has been specified for <scf-filename>, the tmsh utility will search for the SCF file in /var/local/scf/.

  4. Save the change by typing the following command:

    save /sys config
