K000159612: After powering off the active controller1 on VELOS chassis, controller1 became standby controller but not seeing three blades

Type
Support Solution
Published
2026-01-19
Updated
2026-01-20
Applies to

  • F5 Distributed Cloud Services
  • F5OS-C: 1.8.2
Source
https://my.f5.com/manage/s/article/K000159612

Description

After performing a power cycle of the active system controller on an F5OS-C VELOS chassis, certain blades may not be visible or recognized from the affected controller's perspective. The blades appear as present but show poweredOn=false and halOk=false in the platform inventory output.

The following error messages appear in the controller's system logs during boot:

[ 4.225303] ixgbe 0000:06:00.1: invalid MAC address

[ 4.230238] ixgbe: probe of 0000:06:00.1 failed with error -5

This issue is intermittent and occurs specifically during controller power-up events following a power cycle (planned or unplanned). It does not occur during normal reboots or runtime operations.

Environment

  • F5OS-C version 1.8.2
  • VELOS chassis (CX410 with BX110 blades)
  • Condition: Active system controller power cycle (AOM power-off/power-on)
  • Affected component: ixgbe network driver for backplane interfaces

Cause

Bug ID 2183141

Recommended Actions

Immediate Workaround:

  1. Reboot the controller.
  2. After the controller restarts, verify blade visibility using the following command from the controller bash CLI:
    docker exec -it platform-hal psf call GET:chassis/platforms
  3. Confirm that all blades show halOk=true, poweredOn=true, and present=true

Detection for Future Occurrences:

  1. Check the controller's system logs for ixgbe probe failures using the following command from the controller bash CLI:
    cat /var/log/dmesg | grep ixgbe | grep failed
  2. If logs show ixgbe: probe of 0000:06:00.X failed with error -5, perform an AOM power cycle of that controller

Long-term Resolution:

  • Upgrade to F5OS-C version 1.8.3 or later when available, as the fix for Bug ID 2183141 is expected in that release.

Additional Information

This issue only manifests during controller power-up events (power cycles). It does not occur during:

  • Normal system reboots
  • Software upgrades
  • Runtime operations

The issue is intermittent and may not occur on every power cycle event.
