Topic

You should consider using this procedure under the following conditions:

  • You want to license your BIG-IP system using the REST application programming interface (API).
  • You want to provision BIG-IP resources for a licensed module using the REST API.

Description

You can use the iControl REST API to license a BIG-IP system.

REST licensing allows for two licensing options:

  • Manual: The REST command JSON value of activationMethod is set to MANUAL. This requires you to manually interact with the licensing procedure, obtaining the system dossier, manually retrieving the license from the F5 licensing server, and applying the license through a REST command to the BIG-IP system.
  • Automatic: The REST command JSON value of activationMethod is set to AUTOMATIC. For new BIG-IP systems you need to use a REST command to set the administrative password and install the BIG-IP base registration key. When you use automatic, the BIG-IP system should be in a network environment where the BIG-IP system can route to the Internet in order to automatically obtain a license from the F5 license server.

    Note: Use of these options are described in the Installing the license base registration key procedure in this article.

Typographic conventions

The following typographic conventions are used in the command syntax examples:

  • POST = curl -sk -u admin:<password> -H "Content-Type: application/json" -X POST https://<big-ip address>
  • PUT = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PUT https://<big-ip address>
  • PATCH = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PATCH https://<big-ip address>
  • GET = curl -sk -u admin:<password> -H "Content-Type: application/json" -X GET https://<big-ip address>

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Your BIG-IP system is configured with a management IP address and is network accessible on TCP port 443.
  • You have command line access to a Linux system (or an alternate BIG-IP system) with the curl and jq (command line JSON processor) utilities installed.
  • You local device used for executing the REST commands has Internet access.

Setting the administrator password

To modify the BIG-IP administrator password from the system default, use the following command syntax:

Note: This procedure is required only when the destination BIG-IP system has not previously modified the administrator password from the initial system default.

Impact of procedure: The system administrator password is changed.

PATCH /mgmt/tm/auth/user/admin -d '{"password":"<new password>"}'

Note: Replace <new password> with the password you want to use for the system administrator.

Note: The initial user name used when setting the new password is admin and the password admin. All other references to the admin password after this procedure requires the new password that you set in this procedure.

For example, to set the administrative password to NewPassword01!, type the following command:

PATCH /mgmt/tm/auth/user/admin -d '{"password":"NewPassword01!"}'

Installing the license base registration key

To install the F5 provided license base registration key, use the following command syntax:

Impact of procedure: The system becomes temporarily unavailable while the base registration key is installed and a system dossier is generated.

POST /mgmt/tm/shared/licensing/activation -d '{"baseRegKey":"'<base registration key>'","automaticActivation":"false","activationMethod":"MANUAL"}'

Note: Replace <base registration key> with the F5 provided license registration key.

The base registration key is a 27-character string that appears similar to the following example:

ABCDE-ABCDE-ABCDE-ABCDE-ABCDEFG

Note: Replacing "activationMethod":"MANUAL" with "activationMethod":"AUTOMATIC" triggers the BIG-IP system to attempt to access the public Internet licensing server. BIG-IP systems that reside in a network that allows outbound Internet connections the licensing are automatic and all the following procedures are not required.

Acquiring the system dossier

To obtain the required BIG-IP system dossier used to obtain a license from the F5 license server, use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

Note: This procedure is not required when using "activationMethod":"AUTOMATIC" in the Installing the license base registration key procedure.

GET /mgmt/tm/shared/licensing/activation | jq -M .

Important: Extract the dossier text after the ("dossier":" ) statement and before the closing ( "). The dossier should contain only alpha-numeric characters after extraction.

Retrieving the license from the F5 license server

Using the dossier text from the previous procedure, you can access the F5 licensing server and provide the dossier. The F5 licensing server generates a license based on the dossier for download.

Impact of procedure: Using the following procedure should not have a negative impact on your system.

From your local device, submit the dossier to the F5 license server to obtain the BIG-IP license at the following URL: https://secure.f5.com/Infopage/index.jsp

Installing the system license

To install the license obtain from the F5 license server use the following command syntax:

Impact of procedure: The commands in the following procedure cause the BIG-IP system to be temporarily unavailable while system processes are restarted.

Note: This procedure is not required when using "activationMethod":"AUTOMATIC" in the Installing the license base registration key procedure.

POST /mgmt/tm/shared/licensing/registration --data-binary "{\"licenseText\":\"<license text>\"}"

Note: Replace <license text> with the complete license texted obtained from the F5 license server.

Important :The license text contains quotation marks (") that must be removed or the REST command fails. Save the license to a file on your local device, and you can use the following Linux command syntax to strip the quotation marks from the license file: cat ./<you license file name> | sed s'/"//'g 

Note: Application of the license can take several minutes as system services are restarted. You can check the status of the BIG-IP system using the following REST command:

<GET> /mgmt/tm/cm/failover-status | jq -M .

The following Advanced Shell (bash) script can help you in uploading the license file to your BIG-IP system.

Save the license text obtained from the F5 license server in the same local directory of the script with the filename license_file_data.

## Upload license.
## Place license in file the local directory (same as this script location), with the file name of license_file_data
cat ./license_file_data | sed s'/"//'g > ./license_file_data_cleaned
LICENSE=$(< ./license_file_data_cleaned)
curl -v -k -u admin:<password> -X PUT -H "Content-type:application/json" https://<ip address>/mgmt/tm/shared/licensing/registration --data-binary "{\"licenseText\":\"$LICENSE\"}"

Note: Replace <password> with the administrator password created in the first procedure of the article. Replace <ip address> with the IP address of the BIG-IP management interface.

Important: This method of license installation may not work reliably on all BIG-IP versions; if you encounter a non-syntax related error, refer to the Using an alternate license installation procedure.

Using an alternate installation of the system license

If the previous procedure returns a REST error, you can install the license obtained from the F5 license server by using the following command syntaxes:

Impact of procedure: The following commands cause the BIG-IP system to become temporarily unavailable while system processes are restarted.

Note: This procedure is not required when using "activationMethod":"AUTOMATIC" in the Installing the license base registration key procedure.

Determining content size of the license file

Use the following Linux command to determine the license file size required as part of the REST command to upload the file:

Impact of procedure: Using the following commands should not have a negative impact on your system.

stat -c%s license_file_data

For example:

stat -c%s license_file_data
13394

Uploading the license file to the BIG-IP /shared/images directory

To upload the BIG-IP license file to the BIG-IP device, use the following REST command syntax:

Impact of procedure: Using the following command should not have a negative impact on your system.

curl -sk -u admin:<password> -H "Content-Type: application/json" -X POST -H "Content-Type: application/octet-stream" -H "Content-Range: 0-<file size>]/<file size>" --data-binary "@license_file_data" https://<ip address>//mgmt/cm/autodeploy/software-image-uploads/license_file_data

Important:The POST command used to upload the license file to the BIG-IP is different in that the data is sent to the BIG-IP system using an octet-stream. Therefore, the syntax does not follow the typographical convention for POST stated at the beginning of this article.

Note: Replace <ip address> with the BIG-IP management interface IP address, and replace <password> with the password set in the first procedure. Replace <file size> with the numeric value obtained from the stat -c%s command.

Copying the upload file to /config/bigip.license

The following REST command syntax copies the previously uploaded file license_file_data to the default license file /config/bigip.license.

Impact of procedure: Using the following command overwrites the file /config/bigip.license and requires setting the proper file privileges to function, which are covered in the following procedure.

POST /mgmt/tm/util/unix-mv -X -d "{\"command\":\"run\",\"utilCmdArgs\":\"/shared/images/license_file_data /config/bigip.license\"}"

Setting the appropriate Linux filesystem file privileges for the license file

In order for the license file to load successfully the Linux file, you must set system privileges. The following REST command syntaxes set the owner and group of the license file.

Impact of procedure: Using the following commands should not have a negative impact on your system.

POST /mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c ' chown root /config/bigip.license'\"}"
POST /mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c ' chgrp root /config/bigip.license'\"}"

Removing the uploaded file license_file_data

To clean up after installation of the license the following REST command deletes the previously uploaded file license_file_data.

Impact of procedure: Using the following command should not have a negative impact on your system.

POST /mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c ' rm -f /shared/images/license_file_data'\"}"

Restarting the mcpd system process

The BIG-IP system services need to be restarted in order to apply the new license. The following REST command syntax restarts the mcpd process.

Impact of procedure: The following command causes the BIG-IP system to become temporarily unavailable for as long as six minutes while system processes are restarted.

POST /mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c ' tmsh restart \/sys service mcpd'\"}"

Note: Restarting mcpd process can take several minutes, and the system is likely to experience a HTTP 500 error; however, this is not indicative of a failed mcpd restart.

Note: Application of the license can take several minutes as system services are restarted; you can check the status of the BIG-IP system using the following REST command syntax:

<GET> /mgmt/tm/cm/failover-status | jq -M .

Provisioning modules

You can use the REST application programing interface to provision licensed modules on BIG-IP systems that have been successfully licensed.

Available modules are BIG-IP AFM, BIG-IP AM, BIG-IP APM, BIG-IP ASM, BIG-IP AVR, FPS, BIG-IP GTM, ILX, LC, BIG-IP LTM, BIG-IP PEM, SWG, and VCMP.

You can independently provision each module using a predetermined allotment of memory, CPU, and disk space using the following provision levels:

  • dedicated: The system allocates all resources (CPU, memory, and disk) to the module.
  • minimum: The system allocates the least amount of resources required to run the module. No additional resources are ever allocated to the module.
  • nominal: Initially the system allocated the least amount of resources required. After all other modules are allocated, the module gets a portion of any remaining resources.
  • none: The module is not provisioned and therefore is not a running module.

Additionally, you can specify custom resource provisioning for each module. When using custom provision setting, any module provisioned must be specified with individual custom levels; you can not mix modules configured with the predefined resource allotments with modules that are configured with custom levels. When defining custom resource level for a module you must specify the cpuRatio, diskRatio, and memoryRatio for the module. Acceptable ranges (percentages) are from 0 (zero) to 255, where 0 (zero) is the minimal allocation and 255 dedicates the entire resource to the module. The TMOS operating system determines the level of resource from existing resources to apply to the module based on the configured ratio.

To configure provisioning for a licensed module using a predefined provision level use the following REST command syntax:

Impact of procedure: The following command causes the BIG-IP system to become temporarily unavailable while system processes are restarted.

<PATCH> /mgmt/tm/sys/provision/<module> -d '{"level":"<predefined level>"}'

For example: <PATCH> /mgmt/tm/sys/provision/ltm -d '{"level":"nominal"}'

Note: Replace <module> with the licensed module you want to provision and replace <predefined level> with one of the following levels: Minimum, Nominal, Dedicated, or None.

To configure custom provision levels for a licensed module, use the following REST command syntax:

Impact of procedure: The following command causes the BIG-IP system to become temporarily unavailable while system processes are restarted.

<PATCH> /mgmt/tm/sys/provision/<module> -d '{"cpuRatio":"<value 0-255>","diskRatio":"<value 0-255>","memoryRatio":"<value 0-255>"}'
For example: <PATCH> /mgmt/tm/sys/provision/ltm -d '{"cpuRatio":"30","diskRatio":"30","memoryRatio":"30"}'

Note: Replace <module> with the licensed module and <value 0-255> with a numeric value that represents the ratio of the type of resource you want to allocated to the module.
