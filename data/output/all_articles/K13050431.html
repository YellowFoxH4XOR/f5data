Topic

Command execution or operating system command injection is a common attack against web applications in which the attacker runs arbitrary commands on the host operating system by way of a vulnerable application. The web applications can be manipulated to process user input using the command line and to run the commands.

Description

BIG-IP ASM and Advance WAF can mitigate a command execution injections attack with the attack signature feature or with defined metacharacters. This article lists the steps you must follow to mitigate command execution injection using attack signatures; the article assumes that the default configuration is defined.

The following procedures include how to assign the relevant attack signature set, enable it, and configure it in blocking mode so you can mitigate the command execution attacks. The final step is the mitigation verification where the administrator can see the system blocking the command execution.

Note: Default configuration means any of the BIG-IP ASM templates have the transparent and staging period on for the policy.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Have administrative access to the ASM Configuration utility.

 

    Procedures

    Adding a command execution attack signature set includes various types of operating systems that allow the protection regardless of the backed servers.

    • Adding the command execution signatures
    • Enabling and enforcing the command execution signatures
    • Switching to blocking mode
    • Verifying that Command execution attacks are being blocked

     Impact of procedure: Adding attack signatures to the security policy can generate false positives. In such cases, use the learning page to remove the false positives. Enabling attack command execution attack signatures when the security policy is configured with blocking mode blocks requests that trigger a command execution violation. Setting the security policy to blocking mode enables the BIG-IP ASM security policy to block requests that trigger violations that are specifically configured with blocking enabled.

    Adding the command execution signatures

    1. Log in to the BIG-IP ASM Configuration utility.
    2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
    3. Select  Advanced.
    4. Expand Attack Signatures.
    5. Near the upper-right corner of the Attack Signatures section, select Change.
    6. Select SQL injection signatures options and select change.
    7. Select Save.
    8. Select Apply Policy.

    Enabling and enforcing the command execution signatures

    1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
    2. Select Advanced.
    3. Expand Attack Signatures.
    4. For the SQL injection signatures set select Enforcing and Enabling all Attack Signatures in the Signature Set.
    5. Clear Enable signatures staging.
    6. Select Save. 
    7. Select Apply Policy.

    Switching to blocking mode

    1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
    2. Select Blocking.
    3. Select Save.
    4. Select Apply Policy.

    Verifying that command execution attacks are being blocked

    1. Go to Security > Event logs > Request.
    2. In the filter icon choose the second tab  IP / Username / URL.
    3. Under Attack Type select SQL injection.
    4. Select Apply Filter.
    5. The blocked request with SQL injection should be listed in the request log.
    6. The violation name in the request log is shown as Attack Signature Detected.
