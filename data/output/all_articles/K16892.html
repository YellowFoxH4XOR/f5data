Known Issue

The BIG-IP APM Network Access Point-to-Point Protocol (PPP) tunnel may remain open after access session closure.

This issue mainly occurs when the Compression setting of the Network Access configuration is set to GZIP Compression. However, this issue can also occur randomly without the Compression setting.

Impact

The PPP tunnel remains open and continues to hold resources. As a result, you may encounter performance and resource availability issues on the BIG-IP APM system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system logs messages to the /var/log/apm file that appear similar to the following example:

    Jan 17 18:17:17 <device name> notice tmm[8153]: 01490502:5: 19de7664: Session deleted due to user inactivity or errors.
    Jan 19 16:15:37 <device name> notice tmm1[8153]: 01490505:5: 19de7664: PPP tunnel 0x570046b9ba00 closed.

    Note in the previous message that the PPP tunnel closes much later after the access session.
  • As a result of Network Access leasepool exhaustion, the system logs messages to the /var/log/apm file that appear similar to the following example:

    Jan 20 12:02:47 <device name> notice tmm[8709]: 01490505:5: b9b62fd7: IPv4 Allocation failure: leasepool /<partition>/<lease pool name> is out of addresses
