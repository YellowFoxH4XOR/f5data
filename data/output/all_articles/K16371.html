General Information

Provide the following information when you open a case with F5 Technical Support:

  • A full description of the issue, including the following details:
    • The symptoms of the issue, including a brief description of any systems related to the configuration
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the system
    • Steps to reproduce the issue
    • Any changes you made to the system before the issue first occurred
    • Any steps you have taken in an attempt to resolve the issue
    • Whether this is a new implementation
    • A high-level description of the environment the instance is running in

      For example:

      • Is LineRate on bare metal or a virtual machine? Which virtual machine and what is its hypervisor version?
      • Is the device in a testing or production environment?
    • Whether you have already uploaded a Phone Home bundle to the iHealth portal
  • A description of the impact that the issue is having on your site, using the following definitions:
    • Site Down

      All network traffic has ceased, causing a critical impact to your business.

    • Site at Risk

      The primary unit has failed, resulting in no redundancy. The site is at risk of going down.

    • Performance Degraded

      Network traffic is partially functional, causing some applications to be unreachable.

    • General Assistance Required

      Questions regarding configurations. Troubleshooting non-critical issue or request for product functionality that is not part of the current product feature set.

  • The hours that you are available to work (including the time zone) on the issue and any alternative contacts that can work on the issue if you are not available.
  • Remote access information, if possible.

    Remote access to your network environment is important because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Technical Support will work directly with you to resolve the issue over the phone; however, this method can often be more time consuming and may require file transfers, replication, and additional testing.

Product-specific information

Collect the following information from the affected systems and provide the information when you open the case. For information about sending this information to F5, refer to K2486: Providing files to F5 Technical Support.

Tech Support Information

Generate system diagnostic information using the show tech-support detailed CLI command.

  1. Log in to the LineRate CLI.
  2. Create a tech-support file named tech-support that will contain system diagnostic information in the /home/linerate directory by typing the following command:

    show tech-support detailed "file:///home/linerate/tech-support"

Scripting information (for LineRate Precision only)

Is this issue related to scripting? If so, redact any sensitive information and upload to F5 Technical Support. You must include file-based scripts exclusively. By default, these files are located in the /home/linerate/data/scripting directory, but there may be additional directories and files to consider, depending on your host's configuration. To package the scripts, perform the following procedure, providing additional script paths as needed:

Note: Inline scripts placed in the configuration of LineRate (script "name" inline) are already included in the show tech-support command output.

  1. Log in to the LineRate CLI.
  2. Open the bash shell by typing the following command:

    bash

  3. Create a tar archive named scripts.tar.gz that will contain the main scripting files in the /home/linerate/data/scripting directory by typing the following command:

    sudo tar -czpf /home/linerate/scripts.tar.gz /home/linerate/data/scripting/*

Log files

Provide all the log files on the system by performing the following procedure:

  1. Log in to the LineRate CLI.
  2. Open the bash shell by typing the following command:

    bash

  3. Create a tar archive named logfiles.tar.gz that will contain the main log files in the /var/log directory by typing the following command:

    sudo tar -czpf /home/linerate/logfiles.tar.gz /var/log/*.messages"

Core files

Gather relevant core files and provide them with the case. To confirm whether core files exist, perform the following procedure:

  1. Log in to the LineRate CLI.
  2. Open the bash shell by typing the following command:

    bash

  3. Confirm whether core files exist by typing one of the following commands:
    • sudo cat /var/log/controller.messages | grep core

      The command output appears similar to the following example:

      LROS LROS: ProcManager: lb_http exited: exited due to signal 10 (core dumped). Restarting.

    • sudo ls /var/crash | grep core$

      The command output appears similar to the following example:

      lb_http.1223.core

  4. Create a tar archive named corefiles.tar.gz that will contain the main core files in the /var/crash directory by typing the following command:

    sudo tar -czpf /home/linerate/corefiles.tar.gz /var/crash/`sudo ls -rth /var/crash | grep core$ | tail -n 1`

Note: If there are multiple core files present, usually only the most recent is required.

Finalizing initial information gathering

Upload the generated tar files to F5 Technical Support. For more information, refer to K2486: Providing files to F5 Technical Support.

As a reminder, the following files were generated in the /home/linerate directory of the LineRate system:

  • tech-support
  • scripts.tar.gz
  • logfiles.tar.gz
  • corefiles.tar.gz

F5 Technical Support will be alerted about the information posted to the case, start analyzing the information provided, and reach out to the case contact with further instructions.
