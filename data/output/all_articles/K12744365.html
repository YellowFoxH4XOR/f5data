Topic

This article describes how to configure a API protection proxy service on the BIG-IP APM as an OAuth resource server, with Postman as an OAuth client, using Azure Active Directory (AD) as an OAuth authorization server. The following describes the flow:

  1. Postman use OAuth 2.0 to get an access token from Microsoft Azure AD.
  2. Postman sends an API request with the access token to BIG-IP APM.
  3. BIG-IP APM internally validates the JSON web token (JWT) before authorizing the API request to the backend API servers.

Postman-OAuth-Azure-BIG-IP APM flow

This article uses Microsoft identity platform 2.0. With its release, the previous version, 1.0, is deprecated. For differences between the two, refer to Why update to Microsoft identity platform (v2.0).

Description

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have a Microsoft Azure AD account
  • You have administrative permissions to the the Configuration utility on the BIG-IP APM.
  • You can install Postman on a client device
  • You have an API server and a corresponding API spec file to import to BIG-IP APM. If you do not have an API server, for testing purposes only, you can use sample projects such as the Petstore API project with an API spec file. The spec file specifies petstore.swagger.io as the API server so your BIG-IP system require internet access to work.

    Important: These links take you to a resource outside of AskF5. F5 does not provide support for this and does not recommend exposing your back-end network to the internet; use the Petstore project only for testing. It is possible that the document may be removed without our knowledge.

Procedures

This article leads you through configuring the following three entities:

  • An application on the Azure portal
  • BIG-IP APM API protection gateway service
  • Postman client

  • Create an application in Azure AD portal
  • Configure a BIG-IP APM API protection proxy service

Configure a BIG-IP APM API protection proxy service

This procedure consists of six sub procedures that you perform on the BIG-IP APM. The information in the following table describes the building blocks.

BIG-IP resourceDescription
Virtual serverAPI protection proxy service
API Protection profileAssociated to the virtual server providing API functionality.
JWT providerReferenced from the OAuth scope agent in the Per request policy of the API protection profile to validate JWT tokens internally
OAuth resource server providerReferenced by the JWT provider to use the App you created on Azure MS Identity Platform 2.0
JWT Token ConfigurationCreated automatically by the BIG-IP system when you create the OAuth resource server provider.

Create a OAuth resource server provider

  1. Go to Access > Federation > OAuth Client / Resource Server > Provider.
  2. Select Create.
  3. Enter an appropriate name. For example:

    exampleOAuthAzureProvider

  4. For Type, select MS Identity Platform 2.0
  5. For OpenID URI, use the following syntax:
    https://login.microsoftonline.com/<tenantID>/v2.0/.well-known/openid-configuration

    Note: For the tenantID, refer to the value you noted in the Create an application in Azure AD portal procedure.
    Note: Ensure the URI has v2.0 in its path. You can test by entering the URI on a browser. It should display a text file with the different endpoints that you can use.

  6. Select Discover.

    Note the Authentication URI and Token URI values for the subsequent Postman procedure.

  7. Select Save.

Configure the JWT Token Configuration with Audience

The previous procedure automatically creates a new JWT configuration resource. Configure this with an audience.

  1. Go to Access > Federation > JSON Web Token > Token Configuration.
  2. Select the new JWT configuration. The system appended auto_jwt_ to the name you used in the previous procedure.
  3. For Audience, enter the Client ID you noted in the Create an application in Azure AD portal procedure
  4. Select Add.
  5. Select Save.

Create a JWT provider

Create a JWT provider using the OAuth resource server provider created in the previous procedure. This JWT provider validates JWT tokens sent from the Postman client internally on the BIG-IP APM system. Specifically, you reference this in the OAuth Scope agent in the Per request policy of the API protection profile.

  1. Go to Access > Federation > JSON Web Token > Provider List.
  2. Select Create.
  3. Enter an appropriate name. For example,

    exampleJWTProvider

  4. For Provider, select the exampleOAuthAzureProvider,the OAuth resource server provider created in the previous procedure.
  5. Select Add.
  6. Select Save.

Create a API protection profile

In this procedure, you create an API protection profile by importing an OpenAPI file. For testing, you may use a sample from the Petstore app in swagger.io. Refer to the Prerequisites section for more information.

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

  1. Go to Access > API Protection > Profile.
  2. Select Create.
  3. Enter an appropriate name for the profile. For example:

    exampleAPIProfile

  4. Select Browse and select your OpenAPI file to use.
  5. For SSL Profile, select an appropriate server SSL profile. For example:

    serverssl

  6. For DNS Resolver, select an appropriate one. Alternatively, you can create a new one at Network > DNS Resolvers.
  7. For Authorization, select OAuth 2.0, and select Add.
  8. Select Save.

Configure JWT provider to validate tokens in the Per request policy

  1. Go to Access > API Protection > Profile.
  2. Select Edit next to the new API profile you created.
  3. Scroll down to Subroutine: OAuth Scope Check AuthZ.
  4. Select OAuth Scope
  5. For Token Validation Mode, select Internal.
  6. For JWT Provider List, select the JWT provider you created previously, exampleJWTProvider.
  7. For Response, select an appropriate response when authentication is unsuccessful. For example, select xxx_auto_response1.
  8. Select Save.

Review Subroutine: OAuth Scope Check AuthZ. Observe that the BIG-IP APM allows only OAuth Authentication, where the request must contain an access token. The system then validates the access token presented against the JWT provider you created before authorizing access.

Create a API protection virtual server

  1. Go to Local Traffic > Virtual Servers.
  2. Select Create.
  3. Configure the virtual server with the settings in the following table.
    ParameterValues
    NameapiVirtualServer
    Destination Address/Mask<Your virtual server IP address>
    Service Port443
    HTTP Profile (Client)http
    SSL Profile (Client)clientssl
    Source Address TranslationAutoMap (if system requires a Self IP to reach the backend server)
    API Protection ProfileexampleAPIProfile <Name of the API protection profile created in the previous procedure>
  4. Select Finished.

Use Postman to send API requests with access token

For download and more information, refer to Download Postman. After install, you must update to the latest version. The following procedure was tested with Postman 9.14.0.

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Note: Postman is a third party API client and F5 does not provide support for it.

  1. Open Postman on your client device.
  2. Select File > New Tab to create a new request.
  3. In the Enter request URL field, enter the URL to your backend server. Using the Petstore example, enter:
    https://petstore.swagger.io/v2/pet/findByStatus?status=available

    Note: You can find more example requests from the Petstore project site.

    Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

    This request is equivalent to the following curl request which you can run from your client device as well:
    curl -X 'GET' 'https://petstore.swagger.io/v2/pet/findByStatus?status=available' -H 'accept: application/json'

  4. Select Send to send a GET request directly to your API server.

    You should successfully receive a JSON response from the API server and observe 200 OK on Postman.

  5. To send the same request to the BIG-IP APM virtual server you created, replace the host in the URL in the previous step with the IP address of the virtual server you created. For example, use the following command syntax:

    https://<virtual server IP>/v2/pet/findByStatus?status=available

    Recall that in the Subroutine: OAuth Scope Check AuthZ in the Per request policy of your API protection profile, an OAuth access token is required in all requests. As this request does not contain an access token, selecting Send therefore fails. You should receive a 403 Forbidden response.

  6. To configure Postman to get an access token from MS Azure Identity platform 2.0, perform the following:
    1. Select the Authorization tab.
    2. For Type, select OAuth 2.0.
    3. Use the values in the following table to enter the values in Postman.
      FieldValues
      Token NameexampleTokenName
      Grant TypeAuthorization Code
      Callback URLRetrieve this from the table of values in the Create an application in Azure AD portal procedure.
      Auth URLRetrieve this value by pasting your OpenID URI on a browser. Your OpenID URI may have the following syntax:
      https://login.microsoftonline.com/<tenant ID>/v2.0/.well-known/openid-configuration

      The Auth URL may have the following syntax:
      https://login.microsoftonline.com/<tenant ID>/oauth2/v2.0/authorize

      Note: Auth URL also automatically discovered on the BIG-IP system at step 6 of the Create a OAuth resource server provider procedure.
      Access Token URLRetrieve this value by pasting your OpenID URI on a browser. Your OpenID URI may have the following syntax:
      https://login.microsoftonline.com/<tenant ID>/v2.0/.well-known/openid-configuration

      This may have the following syntax:
      https://login.microsoftonline.com/<tenant ID>/oauth2/v2.0/token

      Note: Access Token URL also automatically discovered on the BIG-IP system at step 6 of the Create a OAuth resource server provider procedure.
      Client IDRetrieve this from the table of values in the Create an application in Azure AD portal procedure.
      Client SecretRetrieve this from the table of values in the Create an application in Azure AD portal procedure.
      ScopeYou can obtain this value in Azure portal, by going to the top-left menu and selecting Azure Active Directory > App registrations > <your app name>, expose an API
      This may have the following syntax:

      api://<client ID>/<scope name>

  7. Select Get New Access Token
  8. Log in with your Microsoft account.
  9. Select Proceed and Use Token.
  10. Select Send to send the same request to the BIG-IP APM virtual server with the new access token. You should receive a 200 OK on Postman with a valid JSON response.
