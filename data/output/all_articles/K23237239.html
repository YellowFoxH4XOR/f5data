Description

Client connections to the VPN are not completing, there are two possible symptoms
  • Tunnel establishes, but the GUI is stuck on "Connecting"
  • Tunnel does not establish. Client completes Access Policy and tries to start tunnel, but this fails after about 1 minute with an Error message in edge.log:
    ... ,edge, 2, /TunnelController.mm, 187, TunnelController, tunnelError(), Error code, Tunnel Server HTTP server cannot be started

Environment

  • Client device is running MacOS 12, aka "Monterey"
  • BIG-IP APM is provisioned and configured for Network access VPN
  • Network Access profile contains a PAC file reference with "http" URL (Client Proxy Autoconfig Script)

Cause

Apple have changed the behaviour in MacOS 12 Monterey to requires PAC files to be accessed via HTTPS rather than the insecure HTTP.

Note: The setting in the Network Access "Ignore Client Proxy Autoconfig Script Download Failure" also affects the behaviour.

Recommended Actions

  1. Configure all PAC servers to be able to be accessed via HTTPS with valid certificates for the FQDN used.
  2. Change PAC file reference to "https" URL (from http)
To quickly check if your Network Access profile contains a PAC file reference, run the commands below on the APM and look for http only references
 grep 'client-proxy-script' /config/bigip.conf
  grep 'client-proxy-script http:' /config/bigip.conf 

Alternatively, you can find the Client Proxy Autoconfig Script setting on the Configuration Utility by going to:

Access >> Connectivity / VPN >> Network Access (VPN) >> Network Access Lists >> “Your NA name” >> Network Settings >> Client Proxy Autoconfig Script
