K000160087: Disabled signature for JSON parameter is not working properly

Description

When using BIG-IP Advanced WAF with a security policy that includes JSON parameters, legitimate requests containing JSON data in the request body are being blocked by attack signatures, specifically the SQL-INJ 'end-quote UNION signature. The blocking occurs even though the JSON parameter is configured with "Perform Staging" enabled and attack signatures are set to "Disabled" for that parameter.

The security policy configuration shows:

  • JSON parameter configured with attack signatures disabled
  • Perform Staging enabled for the parameter
  • Requests are still being blocked by signature (SQL-INJ 'end-quote UNION)
  • The violation shows "Attack signature detected" in the request logs

Environment

  • Security policy with JSON profile enabled
  • JSON parameters configured in the policy
  • Header-Based Content Profile for JSON set to "N/A" for wildcard URL (*)
  • Attack signatures enabled at policy level
  • JSON parameter configured with "Perform Staging" enabled and attack signatures "Disabled"

Cause

The issue occurs because the Header-Based Content Profile for JSON is set to "N/A" for the wildcard URL (*) in the security policy configuration. When this setting is "N/A", the WAF does not properly parse the request body as JSON content, even though JSON parameters are defined in the policy. As a result, the WAF treats the request body as generic data rather than structured JSON, which causes the attack signature enforcement to apply at the raw data level instead of respecting the parameter-specific settings. This means that even though attack signatures are disabled for the JSON parameter, the signatures are still evaluated against the unparsed request body content. The "N/A" setting effectively bypasses the JSON parsing mechanism, preventing the WAF from recognizing the JSON structure and applying the appropriate parameter-level security controls.

Recommended Actions

To resolve this issue, modify the Header-Based Content Profile setting for JSON in the security policy:

  1. Log in to the BIG-IP Configuration utility (web UI)
  2. Navigate to Security > Application Security > Content Profiles > Header-Based Content Profiles
  3. Locate the wildcard URL (*) entry in the Header-Based Content Profiles list
  4. For the JSON content type, change the setting from N/A to Default
  5. Click Save to apply the changes
  6. Deploy the updated security policy
  7. Test the application to verify that legitimate JSON requests are no longer blocked

Note: After making this change, the WAF will properly parse JSON content in request bodies and apply the parameter-specific security settings, including the disabled attack signatures for JSON parameters.

Additional Information

The Header-Based Content Profile setting determines how the WAF processes different content types in HTTP requests. When set to "Default" for JSON, the WAF uses the built-in JSON parser to analyze the request body structure and apply security controls at the parameter level.

Key points about JSON content processing in BIG-IP Advanced WAF:

  • The "N/A" setting disables JSON-specific parsing for the specified URL pattern
  • The "Default" setting enables the standard JSON parser with default security controls
  • Parameter-level security settings (such as disabled attack signatures) only apply when JSON parsing is enabled
  • Without proper JSON parsing, the WAF cannot distinguish between JSON structure and raw data
