Known Issue

The PEM listener may ignore Re-Authorization-Request (RAR) messages if the target session is in a Provision-Pending state.

This issue occurs when all of the following conditions are met:

  • A new PEM session is created, and the PEM listener sends a Credit-Control-Request Initialization (CCR-I) message.
  • The Policy and Charging Rules Function (PCRF) host responds with a Credit-Control-Answer Initialization (CCA-I) message, but the PEM listener fails to receive it.

    Note: The CCA-I message from the PCRF host may be delayed or lost in transmission.

Impact

New PEM sessions remain in a Provision-Pending state.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The PEM listener sends a CCR-I message, and expects a CCA-I response within a certain amount of time. When the expected time is exceeded, the affected PEM session remains in a Provision-Pending state (this state implies that the listener is waiting for the PCRF host to provide a policy update for the target session).
  • While in the Provision-Pending state, the PEM system does not have any specific policies to apply to the affected PEM session. Consequently, the PEM system continues to apply the unknown subscriber policies for the affected PEM session.
  • The PEM listener continues to retransmit CCR-I messages until a CCA-I response is received from the PCRF host. If a RAR message is received from the PCRF host, while the retransmissions are occurring, the RAR message is ignored and the PCRF host is unaware of the state of the session.
