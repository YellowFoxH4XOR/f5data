Description
This article discusses how to capture broadcast and multicast traffic on BIG-IP and VIPRION systems.

Environment

  • Multicast traffic and broadcast traffic are in concern and needs to be captured.

Cause
The tcpdump utility provides several useful filter to capture these kinds of traffic.

Recommended Actions

In different layers of network, definitions of multicast traffic and broadcast traffic are different. For example, from the perspective of link layer, destination Ethernet addresses of multicast traffic usually show the first octet has its least significant bit as 1, but from the perspective of IP layer, only several subnets meet, such as 224.0.0.0/4 and ff00::/8. Before capturing traffic, make sure what needs to be captured.
  • To capture Ethernet broadcast traffic on TMM interfaces, run:
# tcpdump -ni 0.0:nnn ether broadcast -s 0 -w /var/tmp/K15446570_ethernetBroadcast.pcap
  • To capture Ethernet multicast traffic on TMM interfaces, run:
# tcpdump -ni 0.0:nnn ether multicast -s 0 -w /var/tmp/K15446570_ethernetMulticast.pcap
  • To capture IPv4 broadcast traffic on TMM interfaces, run:
# tcpdump -ni 0.0:nnn ip broadcast -s 0 -w /var/tmp/K15446570_IPv4Broadcast.pcap
  • To capture IPv4 multicast traffic on TMM interfaces, run:
# tcpdump -ni 0.0:nnn ip multicast -s 0 -w /var/tmp/K15446570_IPv4Multicast.pcap
  • To capture IPv6 multicast traffic on TMM interfaces, run:
# tcpdump -ni 0.0:nnn ip6 multicast -s 0 -w /var/tmp/K15446570_IPv6Multicast.pcap
