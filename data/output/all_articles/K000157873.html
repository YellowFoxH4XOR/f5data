K000157873: DNS/GTM sync not working after upgrade to 17.1.3, NTP authentication keys missing

Description

After upgrading BIG-IP DNS devices from version 15.1.8.1 to 17.1.3, users may encounter configuration synchronization failures between devices. Symptoms include:

  • GTM (Global Traffic Manager) sync issues between two DNS systems.
  • NTP (Network Time Protocol) service remains in INIT state and fails to synchronize, leading to a time mismatch between devices.
  • GUI may show no configured NTP servers, while tmsh CLI displays them as present.
  • No NTP packets are exchanged, despite management interface connectivity to NTP servers is working.

Environment

  • Product: BIG-IP DNS (GTM)
  • Version: 17.1.3 (after upgrade from 15.1.8.1)
  • Configuration: NTP authentication enabled
  • Recent Change: Upgrade from BIG-IP DNS 15.1.8.1 to 17.1.3
  • Affected Features: GTM configuration sync, NTP time synchronization

Cause

The root cause is missing NTP authentication keys on BIG-IP DNS device (/etc/ntp/keys) after the upgrade. This prevents successful NTP time synchronization, resulting in a time drift between systems and subsequent configuration sync failures.

Recommended Actions

  1. Add the correct NTP authentication keys for all configured NTP servers on each BIG-IP DNS device to /etc/ntp/keys.
    Define advanced NTP configurations on the BIG-IP system (11.x - 17.x)
    How to set NTP Authentication and Passphrase Criteria
  2. Restart the ntpd daemon after updating the key file.
    tmsh restart /sys service ntpd
  3. Verify time synchronization status, ensure both devices report synchronized times.
    ntpq -pn
  4. Reattempt configuration sync between the devices.
