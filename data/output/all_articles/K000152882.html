K000152882: Portal Access users see a TRACE menu, or Portal Access is slow, when web applications debug logging is enabled

Type
Support Solution
Published
2025-08-05
Updated
2026-11-02
Applies to
  • BIG-IP
  • BIG-IP APM: 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K000152882

Description

When users access an application through BIG-IP APM Portal Access, you may observe one or both of the following symptoms:

  • Users see a TRACE menu when they right-click inside the Portal Access application, for example inside a Remote Desktop Services (RDS) web portal session. When a user activates this menu and selects Apply, the browser displays F5 debug code, and an F5_DebugMode cookie is set with the selected trace options. This internal debug and trace menu must not be accessible to end users in production environments.

  • Portal Access applications become slow, while access policies without Portal Access and Local Traffic Manager (LTM) traffic work as expected.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource and rewrite profile, or a webtop with a Portal Access application

  • For the TRACE menu: log.webapplications.level is set to Debug or higher, and log.webapplications.trace.sessionid contains a session value

  • For the slowness: log.webapplications.level is set to Debug

Cause

The two symptoms have separate conditions:

  • TRACE menu: The TRACE menu is part of the internal debugging functionality of the Portal Access web applications engine. It becomes available to users when the following database variables are set:

    • log.webapplications.level is set to Debug or higher

    • log.webapplications.trace.sessionid contains a session value

  • Slowness: log.webapplications.level is set to Debug. Debug logging can slow down Portal Access, and the rewrite log files become large.

Answer/Recommended Actions

Important: Do not leave Portal Access logging at Debug. Debug logging for Portal Access is not intended for production use, and causes issues such as slowness. Set log.webapplications.level back to Notice (the default value).

Impact of procedure: Users who see the TRACE menu must start a new access session after this change.

  1. Clear the debug session ID:

    tmsh modify /sys db log.webapplications.trace.sessionid { value " " }

  2. Set the Portal Access logging level to Notice:

    tmsh modify /sys db log.webapplications.level { value "Notice" }

  3. Ask users to start a new access session (log out and log in again), so that the TRACE menu no longer appears.

  4. Verify the settings:

    tmsh list sys db log.webapplications.level
    tmsh list sys db log.webapplications.trace.sessionid

    log.webapplications.level must show Notice, and log.webapplications.trace.sessionid must not contain a session ID.

  5. If the TRACE menu still appears, clear the browser cookies and cache, and start a new access session.

If Portal Access is still slow after you set the logging level to Notice, refer to K14184: Troubleshooting BIG-IP APM Portal Access applications.

Additional Information

Debug logging affects the performance of the BIG-IP system, and you should enable it only during troubleshooting. This applies to all BIG-IP APM log levels, not only to Portal Access. For more information, refer to K15530: Overview of diagnostic logging and BIG-IP system resource utilization.
