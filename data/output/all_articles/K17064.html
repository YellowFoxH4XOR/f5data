Topic

You should consider using this procedure under the following condition:

  • You want to customize the diameter attribute-value-pair (AVP) on the BIG-IP PEM system.

Description

In BIG-IP PEM 11.6.0 and earlier versions, the system does not provide a user interface for customizing the diameter AVP; however, you can create a custom AVP by applying an iRule to the Gx or Gy virtual servers.

Note: This article uses the IP-Can-Type diameter AVP to explain how to configure an iRule to customize the AVP.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You thoroughly understand the purpose of customizing diameter AVPs.
  • You are familiar with the diameter protocol and diameter iRule events.
  • You have experience writing and designing iRules.

Procedures

To create a suitable iRule for modifying the target AVP, you must identify the iRule event that allows the target diameter AVP to be parsed. You can modify the target AVP by removing the old AVP value and then appending the desired value. For example, the IP-Can-Type AVP can be modified in the DIAMETER_EGRESS iRule event.

Using an iRule to customize the IP-Can-Type AVP

Impact of procedure: The impact of the changes made to the target AVP depends on your individual environment. F5 recommends testing the environment and validating changes before pushing the iRule into a deployed environment; you should perform this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. Enter a name for the iRule.

    For example:

    changeIpCanType

  5. Create the iRule to remove the old IP-Can-Type AVP, and add a new AVP with the desired value.

    For example:

    when RULE_INIT {
      # set the IP Can Type value
      # 3GPP TS 29.212 v9.4 Enumerated Values
      # (0) 3GPP-GPRS
      # (1) DOCSIS
      # (2) xDSL
      # (3) WiMAX
      # (4) 3GPP2
      # (5) 3GPP-EPS
      # (6) Non-3GPP-EPS
      set static::ip_can_type_value 2
     
      # To enable debug_custom_attribute set value to 1, to disable set value to 0
      set static::debug_custom_attribute 0
    }

    when DIAMETER_EGRESS {
      # process CCR only
      if {[DIAMETER::command] == 272} {
        if { $static::debug_custom_attribute }{ log local0. "Sending diameter CCR messages"}
        # process initial and update requests
        set req_type [DIAMETER::avp data get 416 "integer32"]

        # Modify the IP-CAN-Type only for request type INITIAL (1) or UPDATE (2)
        if { $static::debug_custom_attribute }{ log local0. "Request type $req_type"}
        if {($req_type == 1) || ($req_type == 2)} {
          DIAMETER::avp delete 1027
          DIAMETER::avp append 1027 [DIAMETER::avp create 1027 1 1 1 10415 $static::ip_can_type_value "integer32"]
          if { $static::debug_custom_attribute }{ log local0. "IP-CAN-Type changed to $static::ip_can_type_value"}
        } else {
          if { $static::debug_custom_attribute }{ log local0. "No IP-CAN-Type changes"}
        }
      }
    }

  6. Now that the iRule is created, associate it to the target virtual server.

    For this example, the iRule created in step 4 (named changeIpCanType), is referenced by the Gx virtual server as follows:

    ltm virtual sample_Gx {
        description "Used by listener sample_Gx"
        destination 0.0.0.0:diameter
        ip-protocol tcp
        mask any
        pool sample_Gx_pool
        profiles {
            tcp { }
            sample_Gx { }
        }
        rules {
            changeIpCanType
        }
        source 0.0.0.0/0
        translate-address disabled
        vlans-enabled
        vs-index 14
    }

Verifying the customization configuration

After setting up the customized IP-Can-Type AVP, you can verify the configuration by passing the target PEM traffic and then performing the following tasks:

  • Access the /var/log/ltm file, with debug_custom_attribute enabled, and you may observe log messages similar to the following example:

    bigip01 info tmm[7029]: Rule /Common/changeUpCanType <DIAMETER_EGRESS>: Sending diameter CCR messages
    bigip01 info tmm[7029]: Rule /Common/changeUpCanType <DIAMETER_EGRESS>: Request type 1
    bigip01 info tmm[7029]: Rule /Common/changeUpCanType <DIAMETER_EGRESS>: IP-CAN-Type changed to 2

  • Perform a packet capture on the Policy and Charging Rules Function (PCRF) server.

    For example, you can use a tshark command similar to the following:

    tshark -V -ni any -R 'tcp.port == 3868' | grep -E 'Command Code:|AVP:'
