Description

  • If you run tmsh list sys syslog, you can see the configured syslog destination servers. For example:

    sys syslog {
        auth-priv-from notice
        auth-priv-to emerg
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include "
        filter f_remote_loghost {
            level(warning..emerg);
        };

        destination d_remote_loghost {
            tcp(\"10.0.0.1\" port(1468));
            udp(\"10.0.0.2\" port(514));
        };

        log {
            source(s_syslog_pipe);
            filter(f_remote_loghost);
            destination(d_remote_loghost);
        };
        "
        iso-date disabled
        kern-from notice
        kern-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers none
        user-log-from notice
        user-log-to emerg
    }

  • If you run tmsh list sys syslog remote-servers, you see none syslog destination servers

    sys syslog {
        remote-servers none
    }

  •  Unable to see configured remote syslog servers on GUI

Environment

  • BIG-IP
  • tmsh
  • GUI
  • Syslog

Cause

Seen behavior is expected. The device is configured to filter the log messages that the system sent to remote syslog servers.

As per K13333:

"If you want to filter the log messages that the system sent to remote syslog servers, you must first remove the remote-servers statement and then configure a syslog include statement that defines a filter rule and the remote server."

"If you previously defined a remote syslog server using the tmsh modify /sys syslog remote-servers command, you must remove the remote-servers statement before you define the filter rule."
