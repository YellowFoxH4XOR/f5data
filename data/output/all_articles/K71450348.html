Known Issue

Universal Inspection Engine (UIE) persistence records may fail to update.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is running multiple Traffic Management Microkernel (TMM) instances.
  • You have a virtual server configured with a UIE persistence profile that uses an iRule.
  • The persistence profile's iRule uses the pool command to bind the persistence record for the connection.
  • Returning connections arrive before and exist beyond the configured UIE timeout value.

Impact

Connection persistence fails.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Returning connections for active connections do not persist if they surpass the configured UIE timeout value.

Workaround

To work around this issue, you can modify the UIE iRule to use the persist command instead of the pool command to set the persistence record.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
