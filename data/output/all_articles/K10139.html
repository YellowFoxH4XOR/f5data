Known Issue

This is the result of a known issue. If you attempt to load a configuration containing an external class definition that references a nonexistent external class file, the configuration will fail to load. An error message that appears similar to the following example is logged to the /var/log/ltm file:

BIGpipe class creation error:
01070630:3: The requested class file (/config/MyClass.txt) was not found).

Note: In BIG-IP LTM versions 9.0 through 9.4.x, an external class definition referencing a nonexistent external class file did not prevent the configuration from loading. As a result, this issue may first be encountered when upgrading from version 9.x to version 10.x.

Note: CMP platforms may encounter this issue if an external class referenced is located in a subdirectory of the /config directory. For more information, refer to K10201: External class files may not be synchronized to secondary cluster members.

F5 Product Development is tracking this issue as CR118866.

Workaround

You can work around this issue by ensuring the external class file has been created on the system before loading a configuration that references it. If the external class is no longer required, you can remove the class definition that references the nonexistent class file.
