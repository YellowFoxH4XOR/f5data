K17917301: ASM policy is not getting synced with standby unit or not showing up in GUI on standby unit with error ''MCP Validation error - 01071726:3: Cannot deactivate policy'' in /var/log/asm

Type
Support Solution
Published
2021-12-07
Updated
2025-06-10
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K17917301

Description

One or few ASM security policies not showing up in GUI in standby peer unit in HA. When performing synchronization manually from active to standby, /var/log/asm is logging below logs:

crit g_server_rpc_handler_async.pl[1722]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): MCP Validation error - 01071726:3: Cannot deactivate policy '/Common/ASM_Policy'. It is in use by ltm policy '/Common/asm_auto_l7_policy__VirtualServer_HTTPS'.

At the same time, the policy is present in bigip.conf on standby unit. Issue is with policy not showing up in GUI on standby unit. 
 

Environment

  • ASM/AWAF provisioned 
  • HA pair with sync-failover device group with asm-sync enabled.
  • ASM security policy present in bigip.conf on standby unit. 


Cause

Unknown
 

Recommended Actions
Restarting the asm_config_server process
Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Restart the asm_config_server process by typing the following command:
    pkill -f asm_config_server


Additional Information

None.
