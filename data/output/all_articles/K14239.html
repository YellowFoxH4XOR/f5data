Known Issue

A virtual server using a web acceleration profile may cause TMM to leak memory.

This issue occurs when both of the following conditions are met:

  • The virtual server is using a web acceleration profile
  • The affected virtual server has an iRule that performs HTTP::disable

Impact

TMM memory may eventually be exhausted and may result in a crash. If the system is configured as part of a high availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The TMM memory utilization graph may constantly grow.
  • TMM may crash with a SIGFPE signal and generate a core in the /shared/core directory.
  • Error messages may be logged to the /var/log/ltm file. The error messages appear similar to the following example:

    011e0002:4: sweeper_update: aggressive mode deactivated.    
    011e0002:4: sweeper_update: aggressive mode activated.

Workaround

There is no workaround for this issue. To avoid the issue, you may change the configuration of the affected virtual server so that the virtual server does not use a web acceleration profile in combination with an iRule that includes the HTTP::disable command.
