Description

On more recent versions of BIGIP, the Key Exchange Algorithms when acting as a SFTP client have been reduced resulting in smaller probability of matching Key Exchange algorithms on remote SSH/SFTP servers. The error usually appears as such:

# sftp username@remote.server.com 
no matching key exchange method found: client ecdh-sha2-nistp256,ecdh-sha2-nistp384,ext-info-c server diffie-hellman-group1-sha1,diffie-hellman-group-exchange-sha256,diffie-hellman-group14-sha1
Connection closed

On OpenSSH page https://www.openssh.com/legacy.html there is said that on version 7.0 and higher, you may see that "diffie-hellman-group1-sha1" is no longer supported during key exchanged since it is considered weak.

There is also security thread https://security.stackexchange.com/questions/238527/how-does-the-weakness-of-sha-1-introduce-attack-vectors-in-ssh saying that SHA1 algorithms are considered weak. In our new software releases, we follow this practice. So even if you specify "diffie-hellman-group1-sha1,diffie-hellman-group14-sha1" in tmsh, BIG-IP will not copy it into SSHD config file.

Environment

  • BIG-IP (SFTP/SCP client)
  • Remote SFTP/SCP server

Cause

  • Limited Key Exchange Algorithms sent by BIG-IP which doesn't match what the remote SFTP/SCP server supports.

Recommended Actions

Note: Consider point 3 as very last resort as this may put BIG-IP device at a security risk.

  1. Instead of issuing sftp or scp command from the bigip, pull the file of the BIG-IP from a remote Linux/Unix based system:

    From the destination device:
    scp <username>@<IP>:/path/to/remote-file /path/to/local-destination
     
  2. Force the BIGIP to use a key exchange algorithm that is supported by the remote server using the following SFTP option '-o KexAlgorithms=<comma-separated list>'. In the above-mentioned example, the server supports the following: diffie-hellman-group1-sha1,diffie-hellman-group-exchange-sha256,diffie-hellman-group14-sha1.

    The command to use would be:
    # sftp -oKexAlgorithms=diffie-hellman-group1-sha1,diffie-hellman-group-exchange-sha256,diffie-hellman-group14-sha1 username@remote.server.com
     
  3. Change KEX algorithms in /config/ssh/ssh_config but it is possible that performing this procedure could prevent the BIG-IP from establishing outbound SSH connections, and that in turn could impact specific modules ie GTM. It is also important to note that these configuration changes are not synced across a device group and are not carried forward during a software upgrade.
     
  4. Change KEX algorithms on SFTP/SCP server to use SHA2 instead of SHA1.
