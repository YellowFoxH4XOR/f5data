Known Issue

A Virtual Clustered Multiprocessing (vCMP) guest may assign different media access control (MAC) addresses to the same Virtual Local Area Network (VLAN).

This issue occurs when all of the following conditions are met:

  • The Master Control Program Daemon (mcpd) has restarted on the vCMP hypervisor.
  • A vCMP guest instance is deployed after the mcpd restart.

Impact

The vCMP guest is intermittently unable to process client connections or communicate with remote hosts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H488388 on the Diagnostics > Identified > High screen.
  • Client connections are reset.
  • Locally sourced traffic such as monitors or peer high availability (HA) connections are failing.
  • The vCMP guest does not update the local Address Resolution Protocol (ARP) table appropriately.
  • The vCMP guest VLAN has different MAC addresses. To check the MAC addresses for a vCMP guest, use the following syntax:

    ifconfig -a | grep [VLAN]

    For example, to check the MAC address allocation for a VLAN named internal, use the following command:

    ifconfig -a | grep internal

    internal Link encap:Ethernet HWaddr 00:23:E9:9A:08:05
    internal Link encap:Ethernet HWaddr 00:23:E9:9A:08:06

  • The vCMP guest fails to start, and in the /var/log/ltm file, you observe error messages similar to the following example:

    err chmand[12345]: 012a0003:3: unexpected init failure : VcmpPlatform: MAC pool size from hypervisor is zero
    crit chmand[12345]: 012a0002:2: critical platform initialize failure. exiting...

    Note: If the vCMP guest is running a software version listed in the Versions Fixed column of the following table, the vCMP guest can detect if the vCMP host is running a fixed version of software. If the host is not running a fixed version, the guest will fail to initialize.

Workaround

To work around this issue, you can re-deploy the vCMP guest. To do so, perform the following procedure:

Impact of workaround: The vCMP guest will be unavailable to process traffic while being re-deployed.

Using the Configuration utility re-deploy a vCMP guest

  1. Log in to the Configuration utility of the vCMP host.
  2. Navigate to vCMP > Guest List.
  3. Select the check box to the left of the affected guest.
  4. Select the Disable option.
  5. Once the Requested State changes to Configured, select the check box to the left of the affected vCMP guest.
  6. Select the Deploy option.
  7. Once the Requested State changes to Deployed, the vCMP guest should be available for processing traffic.

Using the tmsh utility to re-deploy a vCMP guest

  1. Log in to the command line of the vCMP host, and enter the Traffic Management shell (tmsh) by typing the following command:

    tmsh

  2. To list all available guests, type the following command:

    show vcmp guest

  3. To disable the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state configured

    For example, to disable a vCMP guest named vcmp_one, type the following command:

    modify vcmp guest vcmp_one state configured

  4. To ensure that the affected vCMP guest is disabled, use the following command syntax:

    Note: The vCMP guest will not appear once completely disabled.

    show vcmp guest [Name]

    For example, to ensure that the vCMP guest named vcmp_one is disabled, type the following command:

    show vcmp guest vcmp_one

  5. To deploy the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state deployed

    For example, to deploy a vCMP guest named vcmp_one, type the following command:

    modify vcmp guest vcmp_one state deployed

  6. To verify that the vCMP guest is deployed, use the following command syntax:

    Note: The vCMP guest Status will change to running and the Requested State will change to deployed.

    show vcmp guest [Name]

    For example, to verify that the vCMP guest named vcmp_one is deployed, type the following command:

    show vcmp guest vcmp_one
