Known Issue

Description

The TMM process may crash when performing the reselect action on service down. This issue occurs when all of the following conditions are met:

  • A pool is configured to Reselect for Action On Service Down.
  • The pool is assigned to a virtual server with a FastL4 profile.
  • The FastL4 profile is enabled with TCP keepalive interval.
  • Pool members go down and trigger service down action.

Impact

The BIG-IP system may experience service interruptions and failover if configured as part of a high-availability system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H387724 on the Diagnostics > Identified > Low screen.
  • TMM crashes with a SIGSEGV.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system fails over to the standby system.

Workaround

To work around this issue, you can modify the pool to use an action other than Reselect for the Action On Service Down setting. To do so, perform the following procedure:

Impact of workaround: Changing the setting to an action other than Reselect may require clients to re-establish connections when a pool member is marked down.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Click the name of the affected pool.
  4. From the Configuration box, select Advanced.
  5. From the Action On Service Down box, select any action other than Reselect.
  6. To save the change, click Update.
