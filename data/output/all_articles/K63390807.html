Known Issue

The BIG-IP system may fail to complete startup and continually produce core files for the sod process.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured for syslog remote server logging.
  • The configured remote syslog servers use DNS names as the host reference.
  • There are duplicate remote syslog server hosts in the syslog configuration.
  • Your BIG-IP system is unable to resolve the syslog hosts DNS names.
  • You restart your BIG-IP system.

Impact

The watchdog timer detects that the sod process has not completed startup within the expected time, triggering a restart of the sod process.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system logs messages to the /var/log/boot.log file that appear similar to the following example:

    notice syslog-ng: Error resolving hostname; host='<host name>'
    notice syslog-ng: Target host cannot be resolved, persistent disk buffer file will be lost; host='<host name>'
    notice syslog-ng: Error resolving hostname; host='<host name>'
    notice syslog-ng: Initiating connection failed, reconnecting; time_reopen='60'
    notice syslog-ng: Error resolving hostname; host='<host name>'
    notice syslog-ng: Target host cannot be resolved, persistent disk buffer file will be lost; host='<host name>'
    notice syslog-ng: Duplicate stats counter; counter='udp((null):9514)'
    notice syslog-ng: Duplicate stats counter; counter='udp((null):9514)'

  • Your BIG-IP system logs messages to the /var/log/ltm file that appear similar to the following example:

    notice overdog[<pid>]: 01140029:5: HA daemon_heartbeat sod fails action is restart all.
    notice sod[<pid>]: 01140029:5: HA proc_running tmm fails action is go offline and down links.

  • Your BIG-IP system produces core files for the sod process to the /shared/core directory.

Workaround

To work around this issue, you can remove duplicate host syslog entries from the syslog configuration or modify the syslog startup script by adding a time delay. To modify the syslog startup script, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the affected BIG-IP system's command line.
  2. Using a text editor, open the /etc/bigstart/scripts/sod file.
  3. Insert the following line at the top of the file:

    /bin/sleep 120

  4. Save the updated /etc/bigstart/scripts/sod file.
  5. Restart the affected device.
