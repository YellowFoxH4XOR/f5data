Description

When deploying an F5 Virtual Edition image (OVA file) you may observe an certificate expired warning.

If you obtain a BIG-IP  Virtual Edition image file from the F5 Downloads site, and then deploy the file using an application such as the VMware vSphere client, you may observe an certificate expired warning. This warning is triggered because the certificate used to sign the Virtual Edition image file has expired.

As a result of this issue, you may encounter the following symptom:

  • When using software to deploy an F5 Virtual Edition image, you may observe an invalid certificate warning message that appears similar to the following examples:
    • ! bigipve.f5.com (Invalid certificate)
    • Entrust Certification Authority - L1K (Invalid certificate)

Environment

  • BIG-IP Virtual Edition OVA files from downloads.f5.com

Cause

This warning is triggered because the certificate used to sign the Virtual Edition image file has expired.

Recommended Actions

  • There is no impact and issue deploying the OVA file. You can safely complete the deployment process. If you use a browser with the Flash plug-in to deploy the affected image, the deployment may be blocked, and you may be prompted to use an alternative client that supports HTML5.
  • Manually verify the validity of the certificate. To do so,
  1. From the client application you are using, download the Entrust Certification Authority - L1K certificate.
  2. Open the certificate with a certificate viewer on Windows or using the following command:

    openssl x509 -in "Entrust Certification Authority - L1K.cer" -text | grep "Serial\|Key Identifier" -A1

  3. You should observe the following output:

    Serial Number:
    92:09:01:18:ff:73:8e:a3:00:00:00:00:51:04:5d:e8
    --
    X509v3 Authority Key Identifier:
    keyid:82:A2:70:74:DD:BC:53:3F:CF:7B:D4:F7:CD:7F:A7:60:C6:0A:4C:BF
    --
    X509v3 Subject Key Identifier:
    C6:3B:5F:0D:11:2E:B9:80:79:E8:93:70:4B:6C:D2:A4:D2:77:07:BD

  • Deploy the following BIG-IP OVA versions which do not have the issue described in this article
    • BIG-IP 13.1.5.1
    • BIG-IP 14.1.5.2
    • BIG-IP 15.1.8
    • BIG-IP 16.1.3.2
