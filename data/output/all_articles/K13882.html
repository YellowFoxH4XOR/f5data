Known Issue

The BIG-IP GTM Configuration utility may remove the incorrect trusted device certificate or trusted server certificate.

This issue occurs when the following conditions are met:

  • Trusted device certificates exist with the same common name and different expiration dates.
  • Trusted server certificates exist with the same common name and different expiration dates.
  • You attempt to remove a trusted device certificate or trusted server certificate with the farthest expiration date using the Configuration utility.

When this issue occurs, the BIG-IP GTM system deletes the certificate with the closest expiration date. For example, the BIG-IP GTM system contains two trusted device certificates named bigip1.crt. One of the certificates expires in one year and the other certificate expires in 10 years. When you navigate to System > Device Certificates > Trusted Device Certificates and attempt to delete the certificate that expires in 10 years, the system incorrectly deletes the certificate that expires in one year.

The trusted device certificates are used by the big3d agent of the local BIG-IP device to authenticate a connection from a remote BIG-IP device. Trusted device certificates are located in the Configuration utility by navigating to System > Device Certificates > Trusted Device Certificates.

The trusted server certificates are used when the local BIG-IP GTM system authenticates to a remote F5 device. Trusted server certificates are located in Configuration utility by navigating to Global Traffic > Servers >Trusted Server Certificates.

Impact

iQuery communication between devices fails.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • iQuery communication between devices fail after the certificate is removed
  • The BIG-IP GTM system logs status that appears similar to the following example to the /var/log/gtm file:

    gtmd[13267]: 011ae0f2:1: Monitor instance /Common/bigip 10.1.100:80 UNKNOWN_MONITOR_STATE --> DOWN from gtmd (no reply from big3d: timed out)
    gtmd[13267]: 011a6006:1: SNMP_TRAP: VS /Common/vip_two (ip:port=10.1.1.100:80) (Server /Common/gtm2) state change blue --> red (Monitor /Common/bigip from gtmd : no reply from big3d: timed out)
    gtmd[13267]: 011a5004:1: SNMP_TRAP: Server /Common/gtm2 (ip=10.1.1.21) state change green --> red (No enabled VS available)
    gtmd[13267]: 011ab004:1: SNMP_TRAP: Data center /Common/Spokane state change green --> red (No enabled servers available)
  • iqdump connections to the remote system fail with a certificate verify failed message:

    iqdump error:14090086:SSL routines:SSL3_GET_SERVER_CERTIFICATE:certificate verify failed:s3_clnt.c:984:

Workaround

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

To recover the deleted certificate, you can re-run bigip_add or big3d_install to re-populate the certificate bundle with the desired certificate. For more information about running the bigip_add or big3d_install utilities, refer to K13312: Overview of the BIG-IP GTM big3d_install, bigip_add, and gtm_add utilities (11.x - 12.x).
