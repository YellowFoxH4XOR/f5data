Description
The configuration sync is failed since the device has some orphaned monitor instance that is preventing removal of the monitor object /Common/<monitor> from config. 

Error message:
Sync error on <device>: Load failed from <peer> 01070083:3: Monitor /Common/<monitor name> is in use.

Environment

  • The monitor object /Common/<monitor> is not in use in <device>.
  • <device> has that monitor object that no longer exists in <peer>.
  • <peer> device does not have that monitor object so it should be deleted in <device> when performing the configuration sync.

Cause

The MCPD database is out of sync with the binary configuration file.

Recommended Actions

To fix this issue, follow the steps below to force load the MCPD.

Forcing the mcpd process to reload the configuration (BIG-IP 10.x and later):

Important: When a device group is auto-sync enabled, automatic saving of the configuration to the text files is disabled by default (manual saving using tmsh save sys config is still effective). In this situation, forcing a rebuild of mcpd.bin may result in the configuration reverting to a much older state than expected. Always inspect the text-based configuration files in /config and /config/partitons/*/ before performing this procedure to ensure that the configuration there is the one you intend to load.

Impact of procedure: BIG-IP system traffic processing is interrupted while the system restarts.

  1. Log in to the Advanced Shell (bash).
  2. To create a null file with the file name forceload in the /service/mcpd directory, enter the following command:
    touch /service/mcpd/forceload
    On VIPRION systems, enter the following command to run this command on all blades:
    clsh touch /service/mcpd/forceload
     
  3. To restart the BIG-IP system, enter the following command:
    reboot
    On VIPRION systems, enter the following command to run this command on all blades:
    clsh reboot
