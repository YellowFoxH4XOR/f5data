K000161209: F5OS appliance activated FDB entries for MAC masquerade address during tenant UCS load

Support Solution
Published
2026-05-11

2026-05-11

  • BIG-IP LTM: 21.1.X, 21.0.X, 17.5.X, 17.1.X, 21.1.0, 21.0.0, 17.5.1, 17.5.0, 17.1.3, 17.1.2, 17.1.1, 17.1.0
Source

Description

During a UCS load to a new tenant, the F5OS appliance created static FDB entries for the MAC masquerade address. Log messages similar to the following were observed in /var/F5/system/log/platform.log:

api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000039 msg="Receive listener request from tenant client" tenant="tenant01" instid=0 listeners_count=0 mac_masq_listeners_count=1.
api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000080 msg="Listener mac masq request" vlantag=77 mac="16:a9:d0:a9:7e:20" op=0.
fpgamgr[16]: priority="Info" version=1.0 msgid=0x307000000000031 msg="Adding static L2 entry." ENTRY="MAC=16:a9:d0:a9:7e:20, NTI=4095, VID=77, Type=1".
api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000082 msg="Network manager mac masquerade reply returned OK" tenant="tenant01" tenantinstance=0 vlantag=77 mac="16:a9:d0:a9:7e:20" op=0.

Entries were not deleted, despite the tenant going into standby state in favour of active peer after the UCS load.

Connectivity issues to objects associated with the floating traffic group are observed (e.g., pinging a floating self IP will fail).

Environment

  • UCS load to BIG-IP tenant on F5OS platform
  • MAC masquerade configuration present in UCS

Cause

  • Bug ID 2291429: On F5OS, a masquerade MAC is not removed after loading a UCS file

Recommended Actions

Make the tenant active, then fail it over again.

The static FDB entries for the MAC masquerade address will be deleted on transition to standby.

Messages similar to the following will be observed in /var/F5/system/log/platform.log when the static entries are deleted:

api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000039 msg="Receive listener request from tenant client" tenant="tenant01" instid=0 listeners_count=0 mac_masq_listeners_count=1.
api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000080 msg="Listener mac masq request" vlantag=77 mac="16:a9:d0:a9:7e:20" op=2.
fpgamgr[16]: priority="Info" version=1.0 msgid=0x307000000000032 msg="Deleting static L2 entry." ENTRY="MAC=16:a9:d0:a9:7e:20, NTI=4095, VID=77, Type=1".
api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000082 msg="Network manager mac masquerade reply returned OK" tenant="tenant01" tenantinstance=0 vlantag=77 mac="16:a9:d0:a9:7e:20" op=2.

Additional Information

The static FDB entries are created to ensure ingress packets to that MAC can be correctly delivered to the tenant that is active for the traffic group in question. The entries should only be present on the appliance running the active tenant.
