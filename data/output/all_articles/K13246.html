Known Issue

When the BIG-IP ASM hard disk has insufficient disk space, operations that import files to the BIG-IP ASM system may fail.

This issue occurs when the following condition is met:

  • The file size of an attack signature update file or a WhiteHat vulnerability file exceeds the free space available on the root partition (/) of the BIG-IP ASM hard disk drive.

Impact

Attack signature updates and WhiteHat vulnerability file uploads fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Uploading a WhiteHat vulnerability file produces an error message in the Configuration utility similar to the following example:

    Could not import WhiteHat Sentinel Vulnerabilities; Error: Vulnerability XML file is invalid ( no element found at line 1, column 0, byte -1 )"; no log messages found.

  • The automatic attack signature update process generates an error message in the Configuration utility similar to the following example:

    Signature file is not valid

  • The automatic attack signature update process generates an error message in the var/log/asm file similar to the following example:

    01310027:2: ASM subsystem error (asm_config_server_rpc_handler.pl,F5::ASMConfig::Handler::handle_error): Code: 999, Error message = Signature file is not valid

  • Free space on the BIG-IP ASM hard disk displays a value less than the size of the attack signature update file or WhiteHat vulnerability file.

Workaround

To work around this issue, you can free additional space on the root file system. To do so, perform the following procedures:

  • Determining the amount of free space
  • Determining the size of the attack signature update or WhiteHat vulnerability file
  • Identifying files that may be removed from the system
  • Removing files to free space on the BIG-IP ASM root file system

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Determining the amount of free space

  1. Log in to the BIG-IP ASM command line.
  2. To display the current file system disk space usage, type the following command:

    df -h

    Command output appears similar to the following example:

    Filesystem Size Used Avail Use% Mounted on
    /dev/hdc5 6.0G 84M 5.6G 2% /
    /dev/hdc7 6.0G 34M 5.7G 1% /config
    /dev/hdc9 6.0G 576M 5.1G 10% /usr
    /dev/hdc8 36G 2.2G 32G 7% /var
    /dev/hdc1 31G 11G 18G 38% /shared
    /shared/.LoopbackLogFS
    6.6G 37M 6.3G 1% /var/log
    none 2.0G 312K 2.0G 1% /dev/shm
    none 2.0G 6.7M 2.0G 1% /var/tmstat
    prompt 4.0M 4.0K 4.0M 1% /var/prompt
    none 2.0G 1.6M 2.0G 1% /var/tmpfs
    none 3.2G 3.2G 10M 100% /dev/mprov/tmm

  3. Look under the Mounted on column for the root file system, represented by the forward slash (/) character. The available disk space for the root file system is the value displayed in the Avail column for the row identified in step 3.

    In the example output of step 2, the available disk space on the root file system is 5.6 Gb.

Determining the size of the attack signature update or WhiteHat vulnerability file

This process varies depending on your operating system. For other operating systems, refer to your operating system manual.

For example, for an attack signature update file residing in the /var/tmp/ directory of a BIG-IP or other GNU/Linux system, type the following command:

ls -sh /var/tmp/ASM-SignatureFile_20111026_054601.im

Command output returns the size of the file, similar to the following example:

712K /var/tmp/ASM-SignatureFile_20111026_054601.im

Identifying files that may be removed from the system

You may safely remove the following common files from the system:

  • Outdated qkview and tcpdump files created for past F5 Support cases.

    These files may have names similar to the following naming conventions:

    • qkview files

      bigip.example.com.tgz

    • tcpdump files

      C12345-intenal.dmp

      or:

      C123456-intenal.pcap

  • Outdated user configuration set (UCS) archive files. These files may have names that appear similar to the following example:

    My_UCS_Archive.ucs

Important: For more assistance in identifying files that may be removed, or if you are unsure of the suitability of a particular file for removal, contact F5 Technical Support.

Removing files to free space on the BIG-IP ASM root file system

Important: Files removed by this command cannot be recovered. Ensure that you have backups, as needed.

  1. Log in to the BIG-IP ASM command line.
  2. Use the following command syntax:

    rm -rf <filename>

    In the previous command syntax, note the following:

    • <filename> represents the full path and file name of the file you want to delete from the system.

    For example:

    rm -rf /home/user1/bigip.example.com.tgz
