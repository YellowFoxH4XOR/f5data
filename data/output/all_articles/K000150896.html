K000150896: Configure IPv6 BGP Neighbors on BIG-IP and Advertise Virtual Server IPv6 Addresses to BGP Neighbors

Type
Support Solution
Published
2025-04-16
Updated
2025-04-23
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000150896

Description

To exchange BGP routing updates between BIG-IP and another BGP-speaking neighbor over IPv6, BIG-IP supports the BGP4+ extension.

This guide details step-by-step, how to establish a BGP neighbor adjacency relationship so available network prefixes (Network Layer Reachability Information or NLRI within BGP UPDATE messages) are exchanged between BGP peers in IPv6 networks.

After establishing BGP, Route Health Injection (RHI) will be configured for IPv6 virtual-addresses, allowing them to be advertised to BGP neighbors (RIB-Out). Additional context will be provided to detail the changes in the BGP routing tables (BGP RIB): Adj-RIBs-In, Loc-RIB, and Adj-RIBs-Out.

Environment

  • BIG-IP LTM with Advanced Routing Module (ARM) licensed and provisioned 
  • Route Domain with BGP routing-protocol enabled
  • eBGP (BIG-IP with different ASN as external core router network) or iBGP (BIG-IP with same ASN as its peer) neighbor configured
  • Virtual Server with its associated virtual-address "route-advertisement" setting configured to "selective" or "enabled" (RHI).

Cause

Need BIG-IP to communicate BGP routing updates in an IPv6 network. BGP neighbor can share the same Autonomous System Number (ASN) or different ASN as BIG-IP.

Recommended Actions

In this example, the peers already have BGP configured and Established over IPv4. The desired configuration is a dual stack IPv4/IPv6 network.

The iBGP neighbor relationship will be established between localhost1 (self ip: 10.2.115.171, 2620:100d:100e:f5::11)  and localhost2 (self ip: 10.2.115.171, 2620:100d:100e:f5::10). Both are BIG-IP devices in an HA pair and have ASN 255.

eBGP neighbor relationship will be established from localhost1 to localhost3 (self ip: 10.2.115.172, 2620:100d:100e:f5::9), and from localhost2 to localhost3. localhost3 has ASN 365.

  1. Prior to adding the BGP configuration in ZebOS, ensure BIG-IP is configured with an IPv6 self ip address. Additionally, the BGP routing protocol must be added to the route-domain configuration.

    Note    : For simplicity in this example, Port Lockdown is configured on the self ip addresses to allow all traffic. The default setting does not allow port 179 for BGP traffic. Review F5 Support's guidelines on Port Lockdown to properly secure your network.

  2. Configure the BGP neighbor relationship on both devices over IPv6.

    1. Configure BGP neighbor in router configuration mode
(config-router)# neighbor [y:y:y:y:y:y:y:y] remote-as [ASN]

2. Enter address-family ipv6 configuration mode
(config-router)# address-family ipv6 unicast

3. Activate BGP neighbor under address-family ipv6
(config-router-af)# neighbor [y:y:y:y:y:y:y:y] activate

4. Redistribute Kernel injected routes for Route Health Injection
(config-router-af)# redistribute kernel

5. save running-configuration to startup-configuration (can be executed in any command mode, except the initial User EXEC Mode)
# write

    In our example, we will add the IPv6 address of the respective peer devices on localhost1, localhost2, and localhost3 to configure iBGP and eBGP respectively. 
    1. Note that the BGP neighbor must be added first, prior to activating.
localhost1[0](config-router)# neighbor 2620:100d:100e:f5::10 remote-as 255
localhost1[0](config-router)# neighbor 2620:100d:100e:f5::9 remote-as 365

2. Enter address-family IPv6 configuration mode
localhost1[0](config-router)# address-family ipv6 unicast

3. activate iBGP and eBGP neighbors
localhost1[0](config-router-af)# neighbor 2620:100d:100e:f5::10 activate
localhost1[0](config-router-af)# neighbor 2620:100d:100e:f5::9 activate

4. Redistribute Kernel routes, allowing tmrouted to share with BGP process
localhost1[0](config-router-af)# redistribute kernel

5. Configure the same for the peer device, localhost2
localhost2[0](config-router)# neighbor 2620:100d:100e:f5::11 remote-as 255
localhost2[0](config-router)# neighbor 2620:100d:100e:f5::9 remote-as 365
localhost2[0](config-router)# address-family ipv6
localhost2[0](config-router-af)# neighbor 2620:100d:100e:f5::11 activate
localhost2[0](config-router-af)# neighbor 2620:100d:100e:f5::9 activate
localhost2[0](config-router-af)# redistribute kernel

6. Configure the eBGP neighbors for localhost3 over IPv6
localhost3[0](config-router)# neighbor 2620:100d:100e:f5::11 remote-as 255
localhost3[0](config-router)# neighbor 2620:100d:100e:f5::10 remote-as 255
localhost3[0](config-router)# address-family ipv6
localhost3[0](config-router-af)# neighbor 2620:100d:100e:f5::11 activate
localhost3[0](config-router-af)# neighbor 2620:100d:100e:f5::10 activate
localhost3[0](config-router-af)# redistribute kernel

  5. With the BGP peers now established over IPv6, the "redistribute kernel" command must be configured under "address-family ipv6". "redistribute kernel" allows virtual-addresses, which appear as Kernel-injected routes in the IP routing table, to be advertised to BGP neighbors (Adj-RIBs-Out). If this was not done earlier, then IPv6 virtual-addresses enabled with RHI will be in the BGP Loc-RIB table (IPv6: show bgp ipv6 | IPv4: show ip bgp), but not advertised to BGP neighbors (Adj-RIBs-Out table, show bgp ipv6 neighbors [y:y:y:y::y] advertised-routes). 

    Configuring "redistribute kernel" in the BGP router process alone will only enable RHI for IPv4 virtual-addresses, not IPv6 virtual-addresses.

    router bgp [ASN]

...
 
 !
 address-family ipv6
 redistribute kernel   
 neighbor [y:y:y:y::y] activate
 neighbor [y:y:y:y::y] activate

Additional Information

Allow some time for the BGP to go through the 6 states: Idle, Connect, Active, OpenSent, OpenConfirm, Established.  

Depending on the size of the configuration and network topology, BGP may not immediately show an Established state. Convergence can take several seconds, possibly longer. 

The BGP neighbor tables (show ip bgp summary | show bgp ipv6 summary | show ip bgp neighbors | show bgp ipv6 neighbors) will output the number of prefixes (State/PfxRcd) learned from its peer when BGP is Established.

While BGP configurations can be implemented in ZebOS IMI, BGP configurations can be deployed in TMOS with a few exceptions. Review the subsection titled, Move ZebOS BGP routing configuration to tmsh, within the BIG-IP Dynamic Routing with tmsh and iControl REST guide. Migrating the BGP configuration to TMOS would allow replication of the ZebOS config in a DSC cluster and compatibility with iControl automation.

Route redistribution can be implemented with route-maps, but is out of scope for this article.

Manual configuration of the ZebOS configuration file in the IMI shell, such as the examples detailed in this article, needs to be done on each BIG-IP device, whether in an HA pair or not.
