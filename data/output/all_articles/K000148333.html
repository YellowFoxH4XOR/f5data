K000148333: LTM logs spam with Error Message: 01ad0016:5: Monitor Agent TMM <Number>: deleted/created activity: MID <MonitorID>

Type
Support Solution
Published
2024-11-14
Updated
2024-11-14
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000148333

Description

This article addresses an issue where excessive logging of In-TMM monitor events floods the LTM logs on F5 BIG-IP devices. This constant logging can reduce the visibility of other essential log entries and potentially lead to log file truncation as the log files fill up quickly.

  • Log messages similar to the below that were encountered in very short periods:
    Error Message: 01ad0016:5: Monitor Agent TMM <Number>: deleted activity: MID <MonitorID>
    Error Message: 01ad0016:5: Monitor Agent TMM <Number>: created activity: MID <MonitorID>

Environment

In this particular case, the following conditions are met:

  • BIG-IP LTM,
  • You have checked the K53430919 and conditions don't match,
  • In-TMM monitoring enabled,
  • db bigd.reusesocket disabled.

Cause

The excessive logging in the LTM is caused by bigd socket reuse being disabled, which results in bigd sending a new monitor probe to the TMM for each health check, due to in-TMM monitoring being enabled. As each probe requires a new connection, this generates repeated log entries, such as Monitor Agent TMM <Number>: created activity and deleted activity, flooding the LTM logs with these messages and reducing visibility for other critical log events.

Recommended Actions

To address this logging issue, follow these steps to check if in-TMM monitoring is enabled and if bigd socket reuse is disabled:

tmsh list sys db bigd.tmm

sys db bigd.tmm {
    value "enable"
}

tmsh list sys db bigd.reusesocket

sys db bigd.reusesocket {
    value "disable"
}

If you received the same command output and want to prevent these logs from flooding the LTM log while keeping in-TMM monitoring enabled, you can either:

Set bigd.socket_reuse to enable to reduce the frequency of log entries by reusing sockets for monitor probes. Use the following command:

tmsh modify sys db bigd.reusesocket value enable

Alternatively, you can change the log level for TMM messages to reduce verbosity by setting log.tmm.level to warning (instead of notice) in case you have to keep bigd.reusesocket disabled. This will suppress some of the less critical log entries:

tmsh modify sys db log.tmm.level value warning
