Description

When the BIG-IP AWAF Bot Defense profile is applied to HTTP traffic routed through a front-end cache server that performs HTTP/2 offload, users may experience significant page load delays and repeated bot challenges. This issue occurs if the cache server strips the ASM "Set-Cookie: TSxxxxxxxxxxx" header from HTTP responses before sending them to clients. Without this cookie, Bot Defense cannot correctly identify or validate client sessions.

Environment

  • Bot Defense profile configured with "After Access" device ID mode
  • HTTP/2 offload and proxy performed by a front-end cache server
  • HTTP traffic forwarded from cache server to BIG-IP as HTTP/1.1
  • Virtual server with Bot Defense and WAF profiles enabled

Cause

The cache server removes the ASM "Set-Cookie: TSxxxxxxxxxxx" header from HTTP responses before forwarding them to clients, resulting in repeated bot challenges and connection delays.

Recommended Actions

  • Reconfigure the cache server to preserve and forward the "Set-Cookie: TSxxxxxxxxxxx" header in HTTP responses to clients.
  • Ensure that all ASM/Bot Defense-related cookies are retained by intermediate proxies or cache servers to maintain proper client validation.
  • After making the necessary changes, verify the cache server settings to confirm that both application functionality and ASM/Bot Defense mechanisms are working as intended.
