Known Issue

This is the result of a known issue. If an origin web server (OWS) sends an HTTP response that includes an Expires HTTP header with a non-date value of 0 or -1, such as Expires: 0 or Expires: -1, the BIG-IP WebAccelerator will interpret the response as an invalid date format for the Expires HTTP header and log an entry in the /var/log/wa/pvac.log file. Creating a log entry for invalid date formats may result in excessive logging and allow for the file system capacity to be exceeded in a short time.

F5 Product Development tracked this issue as CR93301 and it was fixed in BIG-IP version 9.4.6. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.5-HF2. You may download this hotfix or later versions of the hotfix from the F5 Downloads site. 

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You can configure the BIG-IP WebAccelerator to translate a non-date value of 0 or -1 to use a valid formatted date that has already expired. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /config directory by typing the following command:

    cd /config
  3. Back up the original profile_base.conf file by typing the following command:

    cp profile_base.conf profile_base.conf.sol8569
  4. Open the profile_base.conf file in a text editor.
  5. Locate the when HTTP_RESPONSE section for rule _sys_WA_serverside.
  6. Add the following entry to the top of the HTTP_RESPONSE event:
        # Microsoft IIS Sends Expires: 0 or Expires: -1 for a date in the past.
    if {[HTTP::header "Expires"] <= "0" } {
        # Replace 0 or -1 with a valid expired date format for the header.
        set header_date "Mon, 1 Jan 1990 00:00:00 GMT"
        HTTP::header replace "Expires" $header_date
    }

    The HTTP_RESPONSE event should now appear similar to the following example:

       when HTTP_RESPONSE {
        # Microsoft IIS Sends Expires: 0 or Expires: -1 for a date in the past.
        if {[HTTP::header "Expires"] <= "0" } {
            # Replace 0 or -1 with a valid expired date format for the header.
            set header_date "Mon, 1 Jan 1990 00:00:00 GMT"
            HTTP::header replace "Expires" $header_date
        }

        if {$tmm_wa_no_detach == 1} {
          # Don't detach or disable if NTLM authorization
          ONECONNECT::detach disable
          ONECONNECT::reuse disable
        } elseif {$tmm_wa_oc == 0} {
          # Don't return connections to the connpool
          ONECONNECT::reuse disable
        }
      }

  7. Save the profile_base.conf file.
  8. Reload the configuration by typing the following command:

    bigpipe load
  9. Clear the BIG-IP WebAccelerator cache by typing the following command:

    wa_clear_cache

    Important: Clearing the cache on the BIG-IP WebAccelerator system will temporarily increase traffic to the OWS until the BIG-IP WebAccelerator system repopulates its cache.

    Note: The wa_clear_cache command was not introduced until BIG-IP WebAccelerator version 9.4.2. For information about clearing the BIG-IP WebAccelerator cache for earlier versions, refer to K7618: Clearing the WebAccelerator cache from the command line.
