K8409: Conditions for the cluster primary node to mark a secondary node down

Topic

When a secondary node fails to synchronize with the primary node of a FirePass cluster, the primary node will mark the secondary node as down on the Clustering: Stats page. The Last Sync column on the page will display Down!  Logins will not be redirected to any secondary node while the secondary node is marked as down. The secondary node must synchronize with the primary node to be marked up again (as indicated by the Last Sync column displaying the number of seconds since last successful synchronization). Synchronization connections are always initiated by the secondary node, using the TCP port specified under the Internal Synchronization section of the Device Management: Configuration: Network Configuration page.

In order to be marked down, the secondary node must fail to synchronize for five consecutive minutes, which is equivalent to 300 seconds. The five-minute period is not dependent upon the Synchronization Interval setting on the Device Management: Configuration: Clustering and Failover page (i.e. the period is not the product of the synchronization period multiplied by a fixed number of failures).
