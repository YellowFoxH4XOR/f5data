Procedures

Prepare for a BIG-IQ upgrade

Part 1: Check the BIG-IQ DCD configuration (BIG-IQ 7.x and earlier)

Preparing for a BIG IQ upgrade: Checking the BIG-IQ DCD configuration

When you upgrade, BIG-IQ 7.x and earlier systems do not save the settings for your statistics retention and aggregation policies. Therefore, you must note them so that you can reset them after you upgrade.

Important: This procedure is not necessary on BIG-IQ 8.x and later systems

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to System > BIG-IQ Data Collection > BIG-IQ Data Collection Cluster.
  2. Under Configuration, select Statistics Data Collection.
  3. Select Configure Retention.
  4. To ensure you see all the settings, select Advanced Settings.
  5. Note the settings, so that you can reset them after you upgrade.
  6. On the Statistics Retention Policy page, in the upper-left, select Back (←).
  7. Select Configure Aggregation.

    The settings for aggregating BIG-IP ASM transactions statistics display.

  8. Note your settings.
  9. On the Aggregation Configuration page, on the left, select each service and note its aggregation settings.
  10. In the upper-left, select Back (←).
  11. After you upgrade, follow the same paths to reset your configuration.

Part 2: Download and upload files

Preparing for a BIG-IQ upgrade: Downloading and uploading files

When you prepare for a BIG-IQ upgrade, you download files for the pre-upgrade tool and BIG-IQ software image, and then you upload the pre-upgrade tool and software image to the BIG-IQ system.

When you download the BIG-IQ pre-upgrade check tool, you download the README, TAR, and MD5 files.

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Download the ISO, README, TAR, and MD5 files

  1. On MyF5, go to Resources > Downloads.

    Note: An F5 login is required to access this content.

  2. In Account, if you have more than one MyF5 account, select the account you want.
  3. If you agree with the End User License Agreement and Product Terms, select the check box and select Next.

    Note: The check box displays only when F5 does not yet have a record of you accepting these agreements.

  4. In Group, select BIG-IQ.
  5. In Product Line select Centralized Management and for Product Version select the version you want.
  6. Under Select a product container, select the product container you want. For example v8.2.0.
  7. Under Select a download file, select a file that you want to download.
  8. At the bottom of the page, for Download locations, select the location nearest you.
  9. Select Download.
  10. After the system finishes downloading the first file you selected, return to the Select a download file section, and select the next file you want to download.
  11. Repeat steps 10 and 11 until you finish downloading all the files you want.
  12. Ensure you have downloaded the following files:
    BIG-IQ-<version string>.iso
    F5_Networks_BIG_IQ_PreUpgradeCheck_Tool_README.txt
    F5_Networks_BIG-IQ_PreUpgradeCheck_Tool-v<version>.tar
    F5_Networks_BIG-IQ_PreUpgradeCheck_Tool-v<version>.tar.md5.

Upload the BIG-IQ ISO file

  1. Open the BIG-IQ user interface and go to System > Software Management > Images.
  2. Select Upload Image.
  3. Select Choose File.
  4. Locate the ISO file you downloaded and then select Open.
  5. Select Upload.
    The upload may take a few minutes.
  6. Repeat on the Secondary BIG-IQ

Part 3: Run the pre-upgrade check tool

Preparing for a BIG-IQ upgrade: Running the pre upgrade check tool

For an overview of the pre-upgrade check tool, refer to K15988343: Overview of the BIG-IQ preUpgradeCheck tool. The article refers to you the README file, which contains the latest procedures.

In this procedure, you use the command line to upload and run the tool on your BIG-IQ device. You can also upload the TAR file to the BIG-IQ system using WINSCP or a similar utility.

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Upload the pre-upgrade check tool files

  1. Log in to the command line for the client that you downloaded the tool TAR file to.
  2. To upload the file to the BIG-IQ and specify the location, use the following syntax:

    scp F5_Networks_BIG_IQ_PreUpgradeCheck_Tool-v<version>.tar* root@<your IP address>:/shared/tmp/

    In this command, <version> is the pre-upgrade check tool version, root@<your IP address> is the user and IP address of your BIG-IQ device, and you upload the file to the /shared/tmp directory.

  3. Enter your device password.

    The system confirms that you copied both files to your BIG-IQ device.

  4. Log in to the Active BIG-IQ CM command line as the root user (use admin for Public Cloud deployments such as AWS or Azure).
    Note: If you are logged in to the administrator account, switch to the Advanced Shell (bash). Additionally, when using a specific user (like admin), ensure the default shell for that user is set to bash on all CMs and DCDs. For more information, refer to K16413: Enabling Advanced Shell or tmsh access for BIG-IQ user accounts.
  5. Change to the /shared/tmp directory by entering the following command:

    cd /shared/tmp

  6. To run the md5sum check, use the following syntax:

    md5sum -c F5_Networks_BIG_IQ_PreUpgradeCheck_Tool-v<version>.tar.md5

    The system displays that the TAR file is OK. If the file is not OK, the system displays NOK, and you must download the file again.

  7. Enter the following syntax to extract the RPM file from the TAR file:

    tar -xvf F5_Networks_BIG_IQ_PreUpgradeCheck_Tool-v<version>.tar

  8. Remove any existing version which you have installed previously.
    1. Check if a previous version has been installed by entering the following command. If there is no output, you can skip to step 9.

      rpm -qa | grep pre-upgrade-check

    2. Remove the previous RPM by using the following syntax:

      rpm -e pre-upgrade-check-1.0.0-<version>.noarch

    3. Remove the /shared/scripts/preUpgradeChecks directory by entering the following command:

      rm -rf /shared/scripts/preUpgradeChecks

  9. Install the RPM file using the following syntax:

    rpm -i pre-upgrade-check-1.0.0-<version>.noarch

    The RPM installs all files related to the pre-upgrade check script to /shared/scripts/preUpgradeChecks.

Run the pre-upgrade check tool

  1. Change to the /shared/scripts/preUpgradeChecks directory by entering the following command:

    cd /shared/scripts/preUpgradeChecks

  2. Enter the following command:

    ./preUpgradeCheck

    The tool checks the status of the license, CPU, disk, memory, and DCD cluster. The system highlights in red that you must reactivate your licenses to prevent issues when you upgrade and reboot to new volumes. Your service contract date must be later than your service check date for the version you are upgrading to. For more information, refer to K15365: License activation may be required prior to software upgrade for the BIG-IQ system.

  3. To continue as the root user, enter No.

    The system begins running disk compatibility checks for your BIG-IQ devices. The system displays that the checks are OK. If the system displays NOK, which means not OK, contact F5 Support.

  4. To check each DCD node, enter Yes and your password.

    Since you have not yet set up SSH trust, the system prompts you to enter your password.

    The system confirms that the nodes pass disk compatibility checks. If the system displays NOK, which means not OK, contact F5 Support.

Part 4: Ensure you have multiple DCDs

Preparing for a BIG-IQ upgrade: Ensuring you have multiple DCDs

When you perform a rolling upgrade, the BIG-IP system requires that you have more than one DCD to send data to. You must ensure that you have multiple DCDs.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Open the BIG-IQ user interface and go to System > BIG-IQ Data Collection > BIG-IQ Data Collection Devices.
  2. In the list that displays, check that you have more than one DCD.

    Note: The system automatically assigns a DCD to each BIG-IP device; therefore, you can't configure which BIG-IP devices use which DCDs.

  3. To see the the DCD the system assigns to each BIG-IP device, select the Devices tab. 

Upgrade the BIG-IQ and DCDs

Part 5: Upgrade the BIG-IQ system

Upgrading the BIG-IQ system

This demonstration performs a rolling upgrade. During a rolling upgrade, a data collection device, or DCD, remains available to collect data. You must have at least three DCDs.

When you select a regular upgrade, the system adds the option to make a snapshot of the DCDs before upgrade, because it disables the BIG-IQ system and the DCDs when it upgrades them, leaving no DCDs available to collect data during the upgrade.

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

  1. Go to System > Software Management.
  2. Select Upgrade.

    The message that displays shows the systems you are upgrading and provides a warning that you must manually upgrade your secondary BIG-IQ system.

  3. Select Continue.
  4. Select Rolling Upgrade.
  5. In the Software Image list, select the software image you downloaded.
  6. To upgrade all the devices to a new volume, under Devices, at the right side of the row for each device, select New Volume, and then enter the name of a new volume.
  7. Select Install.

    The system initiates the upgrade and terminates your session.

Watch the progress of your upgrade

  1. To see the progress of your upgrade, log in again.
  2. For Existing BIG-IQ Data Collection Device cluster upgrade task, select OK.
  3. Go to Installations.
  4. Under Last Upgrade, select a task.
  5. Do both of the following:
    • Under General Properties, in Progress, you can watch the progress of the upgrade.
    • Under Devices, under Status, you can see the upgrade progress for each device.

    When the overall upgrade reaches 80 percent and transitions to upgrading the BIG-IQ device, the system terminates your session.

Ensure that the system upgraded successfully

  1. When you are able to log in again, go to System > Software Management > Installations.
  2. Under Last Upgrade, select a task.
  3. Do all of the following:
    • Under General Properties, in Status, you can see that the upgrade is complete.
    • Under Upgrade Tasks, in HA Pair, note that the high availability pair (HA) pair is broken, because you still must manually upgrade the secondary BIG-IQ system, and then add it back.
    • Under Devices, under Status, you can see the progress for each device is Finished.
  4. To check your system's software version, go to This Device > General Properties.
  5. Under Properties, in Version Installed, check the version.

Note: If the version of AS3 software that was running on the BIG-IQ before you upgraded was newer than the AS3 software version post upgrade, then you need to perform additional steps to restore the original version. To upgrade AS3, refer to K54909607: BIG-IQ Centralized Management compatibility with F5 Application Services 3 Extension and F5 Declarative Onboarding.

Part 6: Upgrade the secondary system

Upgrading the BIG IQ and DCDs: Upgrading the secondary system

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Clear the configuration on the secondary BIG-IQ system

You must clear the configuration on the secondary BIG-IQ system before you upgrade. After you upgrade the secondary system and rejoin it to the primary BIG-IQ system, the primary system synchronizes all of its data to the secondary system.

  • At the command line for the secondary BIG-IQ system, enter the following command:

    clear-rest-storage

    The system clears the configuration, which can take a few minutes.

Manually upgrade the secondary BIG-IQ system

The secondary BIG-IQ system is not part of the rolling upgrade you performed on the other devices, because the HA pair is broken and it is currently a standalone system. Therefore, you must upgrade it manually.

  1. Open the BIG-IQ user interface and go to System > Software Management.
  2. Select Upgrade.
  3. In Software Image, select the software image you downloaded.
  4. In Target Volume, select New Volume, and then enter the volume name.
  5. Select Install.
  6. Select Continue.

    In Installing Software, you can watch the progress of your installation or select Close.

  7. To check the progress of your installation using another method, at the command line for the secondary BIG-IQ system, enter the following command:

    tmsh show sys sof

    Under Status, you can see the percentage complete of the installation.

  8. To watch the continual progress of your installation, enter the following command:

    watch "tmsh show sys sof"

    Under Status, you can watch the progress of your installation. This process can take a few minutes.

    To quit the watch command, select Ctrl+c.

Complete the post-upgrade process

Part 7: Add back the secondary BIG-IQ system

Completing the post upgrade process: Adding back the secondary BIG-IQ

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Open the BIG-IQ user interface and go to System > BIG-IQ HA.
  2. Select Add Standby.
  3. In IP Address, enter the IP address of the secondary system.
  4. In Username, enter the user name for the secondary system.
  5. In Password, enter the password for the secondary system.
  6. In Root Password, enter the root password, which enables an SSH connection.
  7. In HA Settings choose the desired option for Failover settings.
  8. Select Add.
  9. Select OK.

    This process can take a few minutes.

  10. After the system successfully adds the secondary BIG-IQ to the HA pair, select Close.

    The BIG-IQ HA page displays both systems and their status.

  11. To check the settings for the HA pair, select BIG-IQ HA Settings.

    Note the following:

    • In HA Pair State, the system displays Operational.
    • In Standby Device, the system displays the of the name of the second device.

Part 8: Re-import the devices and services

Completing the post upgrade process: Reimporting devices and services

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Devices > BIG-IP Devices.
  2. To select all of your devices, at the top of the first column, select the check box.
  3. For More, select Re-discover and Re-import.
  4. For Name, enter a name for the task.
  5. For Shared Object Conflict Resolution Policy, select Use BIG-IP.
  6. For Version Object Conflict Resolution Policy, select Create Version.

    This option determines how the system resolves importing conflicts. When you select this option, the BIG-IQ system stores a copy of the BIG-IP LTM monitor or profile object that is on the BIG-IP device, which is specific to the software version you are running on your BIG-IP system. Later, when the BIG-IQ system deploys a new configuration, it replaces that object on all the managed BIG-IP devices running that version. For more information, refer to K63557165: Discovering a BIG-IP device with a BIG-IQ system and importing the BIG-IP service configuration.

  7. Under Selected, ensure the list contains all the managed devices you want to import.
  8. Select Create.
  9. In the Services column, you can see the status of your importing task. If you receive an import error in this column, do the following:
    • Select the error.
    • For Configuration Import, select Re-import.
    • Under Name, select the listed objects to see the discrepancies between the devices you already imported in to the BIG-IQ and the device you are importing now.

      The system displays the object properties that differ between the BIG-IQ and BIG-IP systems. You have the option to use either the version the BIG-IQ already has or the version on the BIG-IP system you are importing, whichever works best for your environment.

  10. For Conflict Resolution, select Device Specific Objects, to see if there are any additional conflicts.
  11. Select Continue.
  12. Select Resolve.
  13. In the upper-left, select Back (←).

    Under Device Name and Services, you can see that the system re-imported the devices and services.

Part 9: (VMware) Install the certificate

Completing the post upgrade process: VMware Installing the certificate

When you are using a VMware service scaling group, the BIG-IQ system communicates with the vCenter using Transport Layer Security (TLS). To enable that communication, you must install the certificate from the VCenter on the BIG-IQ system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To securely copy the files, at the BIG-IQ command line, enter the following command, substituting the appropriate information for your environment:

    scp root@<IP address>:/etc/vmware-sso/key/ssoserverRoot.crt /config/ssl/ssl.crt/

  2. To change to the the ssl.cert directory, enter the following command:

    cd /config/ssl/ssl.crt

  3. To create a symbolic link for the file, enter the following command:

    Note: Because the BIG-IQ refers to the certificate file by its hash value, this command references the file and creates a symbolic link for it.

    ln -s ssoserverRoot.crt 'openssl x509 -hash -noout -in ssoserverRoot.crt'.0

  4. To view the file, enter the following command:

    ls
