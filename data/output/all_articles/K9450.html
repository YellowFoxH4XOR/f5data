Known Issue

This is the result of a known issue. When the FirePass Portal Access reverse-proxy engine patches a Java applet, it re-signs the Java class or archive using an internal signing certificate. The internal signing certificate included in FirePass version 6.0.3 and earlier expires on November 29, 2008 at 00:00:00 GMT.

After the certificate expires, users may receive an error message indicating that the certificate has expired when accessing Java applets through Portal Access. This error message does not prevent the Java applet from loading or running unless the user declines to accept the expired certificate.

F5 Product Development tracked this issue as ID 296109 (formerly CR103052) and it was fixed in FirePass version 6.1.0.

This issue has been fixed in hotfix-103052-1 issued for FirePass versions 5.5, 5.5.1, 5.5.2, 6.0.1, cumulative Hotfix HF-602-9 issued for FirePass version 6.0.2, and Hotfix HF-603-1 issued for FirePass version 6.0.3. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Note: After installing hotfix-103052-1, the new Java signing certificate expires on November 10, 2011 at 23:14:56 GMT.
