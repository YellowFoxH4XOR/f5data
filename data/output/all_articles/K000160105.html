Description

In rare situations, the BIG-IP may be unable to display statistics on virtual servers even though traffic is flowing through them.

You may observe:

  • In GUI, under Statistics, Module Statistics, Local Traffic (Statistics Type: Virtual Servers), all readings are 0.
  • In tmsh, "show /ltm virtual" shows all readings as 0.

Environment

  • BIG-IP LTM
  • Virtual server statistics

Cause

The TMM segment file might be corrupted.

Recommended Actions

  1. Verify if any TMM segment file is indeed corrupted.

    Login to the BIG-IP via SSH and run the following command (in 1 line):

    # for FILE in /var/tmstat/blade/tmm[0-999]; do echo "File: $FILE"; tmctl -f $FILE -V; echo; done 2>&1 | less

    There is 1 TMM segment file per TMM thread. The number of TMM segment file varies by platform. The command verifies each of the TMM segment files..

    Inspect the output of the command.

    Example output for a functional TMM segment file

    # for FILE in /var/tmstat/blade/tmm[0-999]; do echo "File: $FILE"; tmctl -f $FILE -V; echo; done 2>&1 | less
    File: /var/tmstat/blade/tmm0
    Verify: File size is 4194304
    Verify: Segment ID is 1
    Verify: Slab size is 4096
    Verify: Slab count is 1024
    Verify: Table count is 428
    tmctl: tmstat_check_slab: slab 3 for table '.hash' lines_per_row 0 does not match 63 based on rowsz 4032
    tmctl: tmstat_check_slab: slab 3 for table '.hash' has zero lines_per_row
    tmctl: tmstat_check_slab: slab 22 for table '.hash' lines_per_row 0 does not match 63 based on rowsz 4032
    tmctl: tmstat_check_slab: slab 22 for table '.hash' has zero lines_per_row
    - snip -
    tmctl: tmstat_check_slab: slab 645 for table '.hash' lines_per_row 0 does not match 63 based on rowsz 4032
    tmctl: tmstat_check_slab: slab 645 for table '.hash' has zero lines_per_row
    tmctl: tmstat_check_slab: slab 647 for table '.hash' lines_per_row 0 does not match 63 based on rowsz 4032
    tmctl: tmstat_check_slab: slab 647 for table '.hash' has zero lines_per_row
    tmctl: tmstat_check_table: table '.hash' column count is zero

    The output is very verbose. A value or count of 0 does not indicate an issue.

    If every TMM segment file shows verbose output like above, the files are not corrupted. Do not proceed to the next step.


    Example output for a corrupted TMM segment file

    # for FILE in /var/tmstat/blade/tmm[0-999]; do echo "File: $FILE"; tmctl -f $FILE -V; echo; done 2>&1 | less
    File: /var/tmstat/blade/tmm0
    tmctl: tmstat_check_file: /var/tmstat/blade/tmm0: Invalid argument

    If any of the TMM segment files show an error like above, the file is corrupted. Proceed to the next step.

  2. If any of the TMM segment files is corrupted, deleting them and restarting TMM will resolve the issue.

    Impact of workaround: The procedure will cause service interruption if the BIG-IP is active. Perform the procedure in a maintenance window. In a HA setup, failover to the peer device before the procedure.

    Login to the affected BIG-IP via SSH:

    Delete TMM segment files
    # rm -f /var/tmstat/blade/tmm[0-999]

    Restart TMM (which regenerates any deleted TMM segment files)
    # bigstart restart tmm

    In a HA setup, after performing the procedure above, you may fail back to the affected BIG-IP before checking if virtual servers are showing statistics.
