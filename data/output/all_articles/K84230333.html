Description

Customers attempting to deploy the BIG-IP Iprep service behind Azure Firewall require the BIG-IP to include the SNI during the TLS handshake for the Azure Firewall to allow outbound connection success.

Environment

1. BIG-IP with Iprep enabled
2.  Outbound connection is through Azure FW.


Cause
Azure Firewall is blocking the connection because the BIG-IP update does not send the TLS SNI header in versions prior to 15.1.4 and 16.1.3.

"Azure Firewall uses SNI TLS headers to filter HTTPS and MSSQL traffic" https://docs.microsoft.com/en-us/azure/firewall/overview.
 

Recommended Actions

SNI Support is available on 15.1.4+ and 16.1.3+ where the BIG-IP connects using the BrightCloud SDK and API.

Additional Information

What is Azure Firewall? (https://www.seedthe.net/topic/204-azure-firewall/)

"Azure Firewall uses SNI TLS headers to filter HTTPS and MSSQL traffic If browser or server software doesn't support the Server Name Indicator (SNI) extension, you can't connect through Azure Firewall. If browser or server software doesn't support SNI, then you may be able to control the connection using a network rule instead of an application rule. See Server Name Indication for software that supports SNI."
