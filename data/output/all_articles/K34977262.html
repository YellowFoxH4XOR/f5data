Description

The following articles describe how to retrieve and configure access logs:

  • K67125033: Aspen Mesh: How to get isto-proxy logs
  • K19302224: Configure Access Logs in Aspen Mesh

In this article, we explain how to read the access logs and what is happening with our requests.

Environment

  • Kuberntes: 1.17x,1.18.x,1.19.x,1.20.x
  • Aspen Mesh: 1.6.x, 1.9.x 

Cause

Let’s use the following access log from our application example:

[2021-09-01T20:43:08.778Z] "GET /headers HTTP/1.1" 200 - via_upstream – 
" " 0 346 24 24 "-" "curl/7.69.1" "c903c436-6c4a-4bb1-b9c8-bdbe59408ccf" 
"httpbin.default:8000" "100.96.7.79:80" out-bound|8000||httpbin.default.svc.cluster.local 100.96.7.75:45418 100.68.205.113:8000 100.96.7.75:47918 - default

The example above was a request using a sleep pod performing a curl to httpbin service.

The access logs should look like this:

"[%START_TIME%] \"%REQ(:METHOD)% %REQ(X-ENVOY-ORIGINAL-PATH?:PATH)% %PROTOCOL%\" %RESPONSE_CODE% %RESPONSE_FLAGS% %RESPONSE_CODE_DETAILS% %CONNECTION_TERMINATION_DETAILS% \"%UPSTREAM_TRANSPORT_FAILURE_REASON%\" %BYTES_RECEIVED% %BYTES_SENT% %DURATION% %RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)% \"%REQ(X-FORWARDED-FOR)%\" \"%REQ(USER-AGENT)%\" \"%REQ(X-REQUEST-ID)%\" \"%REQ(:AUTHORITY)%\" \"%UPSTREAM_HOST%\" %UPSTREAM_CLUSTER% %UPSTREAM_LO-CAL_ADDRESS% %DOWNSTREAM_LOCAL_ADDRESS% %DOWNSTREAM_REMOTE_ADDRESS% %REQUESTED_SERVER_NAME% %ROUTE_NAME%\n

The access log configuration is default for every istio-proxy, ingress-gateway and egress-gateway in the mesh.

From our application example:

FormatValueDescription
[%START_TIME%][2021-09-01T20:43:08.778Z]The start time of the request.
%REQ(:METHOD)%GETThe HTTP method used for the request.
%REQ(X-ENVOY-ORIGINAL-PATH?:PATH)%/headersThe original HTTP path requested by the client.
%PROTOCOL%HTTP/1.1Either HTTP/1.1 or HTTP/2. If the protocol is TCP, the value will be ‘–‘.
%RESPONSE_CODE%200The HTTP response code. If the request is a TCP request, the value will be ‘–‘.
%RESPONSE_FLAGS%-These provide additional details about the response or connection if any above and beyond the standard response code.
You can check all the response flags in Envoy configuration reference.
%RESPONSE_CODE_DETAILS%via_upstreamTTP response code details provide additional information about the response code, such as who set it (the upstream or envoy) and why.
%CONNECTION_TERMINATION_DETAILS%-Connection termination details may provide additional information about why the connection was terminated by Envoy for L4 reasons.
%UPSTREAM_TRANSPORT_FAILURE_REASON%-If upstream connection failed due to transport socket (e.g. TLS handshake), provides the failure reason from the transport socket. The format of this field depends on the configured upstream transport socket.
%BYTES_RECEIVED%0The body bytes received. For WebSocket connections, the Bytes Sent will include response header bytes.
%BYTES_SENT%346The body bytes sent. For WebSocket connections, the Bytes Sent will include response header bytes.
%DURATION%24The total duration, in milliseconds, of the request from the start time to the first byte read from the upstream host.
%RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)%24The time, in milliseconds, spent by the upstream host processing the request. This is useful if you want to compare the service time compared to network latency.
%REQ(X-FORWARDED-FOR)%-The XFF HTTP header field identifies the originating IP address of the client.
%REQ(USER-AGENT)%curl/7.69.1The user agent string, which allows the server to identify the specific type of software request agent.
%REQ(X-REQUEST-ID)%c903c436-6c4a-4bb1-b9c8-bdbe59408ccfThe x-request-id header is used by Envoy to uniquely identify each request. This is especially important for distributed tracing and stable access logging across multiple microservices.
%REQ(:AUTHORITY)%httpbin.default:8000The value of the Host (HTTP/1.1) or Authority (HTTP/2) header.
%UPSTREAM_HOST%100.96.7.79:80The upstream host URL, i.e., the target destination for the request.
%UPSTREAM_CLUSTER%outbound|8000||httpbin.default.svc.cluster.localUpstream cluster to which the upstream host belongs to.
%UPSTREAM_LOCAL_ADDRESS%100.96.7.75:45418Local address of the upstream connection. If the address is an IP address it includes both address and port.
%DOWNSTREAM_LOCAL_ADDRESS%100.68.205.113:8000Local address of the downstream connection. If the address is an IP address it includes both address and port. If the original connection was redirected by iptables REDIRECT, this represents the original destination address restored by the Original Destination Filter using SO_ORIGINAL_DST socket option. If the original connection was redirected by iptables TPROXY, and the listener’s transparent option was set to true, this represents the original destination address and port.
%DOWNSTREAM_REMOTE_ADDRESS%100.96.7.75:47918Remote address of the downstream connection. If the address is an IP address it includes both address and port.
%REQUESTED_SERVER_NAME%-String value set on ssl connection socket for Server Name Indication (SNI).
%ROUTE_NAME%defaultName of the route.
