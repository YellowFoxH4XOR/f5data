Description
If the BIGIP system boot the software volume from HD1.1 to HD1.3 and need to access the files from HD1.1, such as UCS, you may access these files without rebooting to the new partition by mounting the filesystem of inactive volume  HD1.1. 

For example: 
If you want to access the files saved under HD1.1 boot partition from HD1.3. 

 [root@bigip_ltm_v11_b:] config # tmsh show sys software
 
---------------------------------------------------
Sys::Software Status
Volume  Product  Version    Build  Active    Status
---------------------------------------------------
HD1.1    BIG-IP   11.4.1    608.0      no  complete
HD1.2      none     none     none      no  complete
HD1.3    BIG-IP   11.6.0  0.0.401     yes  complete

Environment

  • Filesystem
  • Boot Partition
  • Mount inactive boot partition. 

Cause
The filesystem such as root, /var/local, /etc are limited to current software volume and filesystems like /shared, /var/log are accessible across multiple boot volumes. 

Recommended Actions

  1.  To mount the /var file system, run the lvdisplay command to display all the logical volume information.

      LV Name                /dev/vg-db-sda/set.2._var
      LV Name                /dev/vg-db-sda/set.3._var

After determining which MD device you would like to mount, you may mount the filesystem.
 

     3. To mount the logical volume, I created a test folder. 
          [root@LTM1.example.com:] config # mkdir /mnt/test
 
     4. Mount the LV /dev/vg-db-sda/set.1._var on the newly-created directory. 
         [root@LTM1.example.com:] config # mount /dev/vg-db-sda/set.1._var /mnt/test
     Note: Here /dev/vg-db-sda/set.1._var is the /var filesystem of partition on HD1.1 or MD1.1
