Introduction

Upgrading BIG-IP VE instances in an Amazon Web Services (AWS) autoscaling group is different from other updates, because an AWS autoscaling group resource manages and scales up or down the BIG-IP instances on demand. Use this chapter to upgrade BIG-IP VE instances in an AWS autoscaling group deployed using F5 AWS CloudFormation 2.0.

Important: Due to the heavy customization requirements of external cloud resources and BIG-IP configurations in these solutions, F5 does not provide technical support for deploying, customizing, or troubleshooting the templates themselves or the procedures in this article. However, the various underlying products and components used (for example, F5 BIG-IP Virtual Edition) are F5-supported. For more information, refer to the Getting Help section in F5 AWS CloudFormation 2.0.

General procedure

The method you use to update depends on how you initially created your BIG-IP instances and how you currently manage them. In general, the procedure is to:

  1. Change the current Amazon Machine Image (AMI) ID of the BIG-IP image to one that has the BIG-IP version you are upgrading to. The CloudFormation Template (CFT) uses the new AMI ID to launch new BIG-IP instances.
  2. Perform the upgrade by updating the F5 AWS CloudFormation 2.0 stack.
  3. The deployment uses the AutoScalingRollingUpdate policy to replace your old BIG-IP instances with new ones that are running the BIG-IP version you are upgrading to.
  4. Load the BIG-IP configuration on the new BIG-IP instances.

The last step varies. You can load the BIG-IP configuration in a number of ways:

  • From a user configuration set (UCS) archive generated before the upgrade, such as F5 AWS CloudFormation Templates 1.0.
  • From a configuration sync process from another upgraded BIG-IP instance, such as F5 AWS CloudFormation Templates 1.0.
  • When you use F5 AWS CloudFormation 2.0, F5 Declarative Onboarding (DO), Application Services 3 Extension (AS3), and F5 Telemetry Streaming (TS), load the BIG-IP configuration using the configuration file, runtime-init-conf-payg.yaml, which you specify at the time of deployment.

Procedure for BIG-IP instances launched from F5 AWS CloudFormation 2.0

You can update BIG-IP VE instances that you created and manage using the F5 AWS CloudFormation 2.0 on GitHub.

Important: F5 deprecated the F5 AWS CloudFormation Templates 1.0 and replaced it with F5 AWS CloudFormation 2.0. F5 recommends moving to the latter.

The steps to update BIG-IP VE instances in an AWS autoscaling group deployed from F5 AWS CloudFormation 2.0 are as follows:

  1. Determine and note the bigIpImage parameter you want the F5 AWS CFT to use to create new BIG-IP instances. The bigIpImage parameter is a string that contains license information and the BIG-IP version you want to upgrade to.
  2. Edit the F5 AWS CFT by replacing the existing bigIpImage parameter with the one determined in step 1.
  3. Update the F5 AWS CloudFormation 2.0 stack.

When the upgrade begins, the system upgrades each BIG-IP instance according to the AutoScalingRollingUpdate policy.

Upgrade vs. update

This chapter may use the word upgrade to refer to either a software upgrade or update. For a definition that explains the difference between the two terms, refer to Upgrading vs. updating in the Introduction.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your previously deployed your BIG-IP VE instances and autoscaling group from F5 AWS CloudFormation 2.0 on GitHub.
  • You can perform the upgrade using one of the following methods:
    • You have the required AWS credentials to log in to the AWS console to manage the F5 AWS CloudFormation 2.0 stack and the resources it manages. 
    • You have access to one of the following client systems:
      • You have access to the AWS console and AWS Cloudshell.
      • You have your own client system. 
        • You have the AWS CLI version 2 tool installed on your client system.
        • You used aws configure to configure the tool on your client system.

Prepare for the update or upgrade

Impact of procedure: Performing the procedures in this section should not have a negative impact on your system.

Determine the bigIpImage parameter

In F5 AWS CloudFormation 2.0, when you deploy or perform an update, you can specify either the AMI ID or the bigIpImage parameter. The bigIpImage parameter is a string that specifies the description field of a BIG-IP image. It consists of the BIG-IP version and license information about the image. For more information on how to get the description field of a BIG-IP image, refer to K25195893: Get AWS BIG-IP image information on AWS marketplace.

The following examples are strings you can specify for bigIpImage:

Note: The CFT performs an AMI lookup using the bigIpImage parameter you provide. For more information, refer to Understanding AMI Lookup Function on GitHub.

  • *16.0.1.1-0.0.6**PAYG-Adv WAF Plus 25Mbps*
  • *15.1.2-0.0.9 PAYG-PVE Adv WAF_LTM 200Mbps*
  • *BIGIP-14.1.4-0.0.11**PAYG-Adv WAF Plus 25Mbps*

For example, if the description of your current BIG-IP image is BIGIP-14.1.4-0.0.11 PAYG-Adv WAF Plus 200Mbps, and you want to display a list of BIG-IP images you can upgrade to, you can use the following command syntax:

aws ec2 describe-images --region us-east-1 --owners '679593333241' --filters Name=description,Values='*PAYG-Adv WAF Plus 200Mbps*' --query "Images[*].[Description, CreationDate, ImageId]"

If you want to upgrade to the BIG-IP image F5 BIGIP-16.1.0-0.0.19 PAYG-Adv WAF Plus 200Mbps-210623020038, you can set the bigIpImage parameter to any of the following examples:

  • F5 BIGIP-16.1.0-0.0.19 PAYG-Adv WAF Plus 200Mbps*
  • *BIGIP-16.1.0-0.0.19 PAYG-Adv WAF Plus 200*
  • *16.1.0-0.0.19 PAYG-Adv WAF Plus 200Mbps*

Check the current rolling update policy

Check the current AutoScalingRollingUpdate policy so that you know how it is configured. To do so, perform the following procedure:

  1. Log in to the AWS Management Console.
  2. Go to Services > CloudFormation > Stacks.
  3. Select the name of the BIG-IP autoscale nested template.

    For example, you select the following template:

    BigIp-Autoscale-WAF-examplename-BigipAutoscale-15OTGKZRP880L

  4. Select the Template tab.
  5. Search for the UpdatePolicy attribute in the template.
  6. Optional: If you need to configure the update policy, refer to K95091044: Specify how F5 AWS CloudFormation 2.0 handles rolling BIG-IP VE updates in an autoscaling group.

Update or upgrade

You upgrade the BIG-IP VE instances in a autoscaling group by updating the bigIpImage parameter in the AWS parent template. F5 recommends that you make only one change in the template, as described in this procedure. To do so, perform one of the following:

Impact of procedure: When the system updates the new AWS template, it launches BIG-IP VE instances one-at-a-time depending on your rolling update policy. If you have more than one BIG-IP VE instance, services may not be disrupted. However, the autoscaling group may have BIG-IP VE instances with different BIG-IP versions at any one time. F5 recommends performing this procedure during a scheduled maintenance window.

Upgrade with the AWS Management Console

  1. Log in to the AWS Management Console.
  2. Go to Services > CloudFormation > Stacks.
  3. Select the parent template.
  4. Select Update.
  5. Select Next to use the Use current template option.
  6. Search for the F5 BIG-IP Image parameter and replace it with the string you identified in the Determine the bigIpImage parameter procedure.

    For example, you enter:

    "*16.1.0-0.0.19 PAYG-Adv WAF Plus 200Mbps*"

  7. Select Next.
  8. Verify the rest of the settings.
  9. Select Next.
  10. Select the two check boxes to acknowledge AWS CloudFormation requirements.
  11. Select Update stack.
  12. Follow the upgrade progress by selecting the Events tab of the stack.

Upgrade with the aws tool

You can use the update-stack command in the aws tool to update your stack. When you do so, F5 AWS CloudFormation 2.0 uses the values you define in the --parameters switch ahead of the values in the template file. If you do not define any values for the parameters, F5 AWS CloudFormation 2.0 uses the default values defined in the template file. For more information, refer to K79020475: Overview of updating F5 AWS CloudFormation 2.0 stack.

Perform the following procedure to update your stack using the aws tool either on AWS Cloudshell or on your client system with the tool installed:

  1. Log in to AWS Cloudshell or your client system with the aws tool installed.

  2. To get a list of all the current parameters in use by F5 AWS CloudFormation 2.0, use the following command syntax:

    aws cloudformation describe-stacks --region <region> --stack-name <stackname>

    For example, you enter the following command:

    aws cloudformation describe-stacks --region us-east-1 --stack-name BigIp-Autoscale-WAF-Examplename

  3. Create a file to define your parameters.

Recommendations

  • When you modify the image string of the deployment, perform only one change at a time. Making multiple changes may result in issues whose root cause you are unable to determine.
  • Have a good understanding of parent and nested templates in F5 AWS CloudFormation 2.0, and check for drifts before the update. For more information, refer to K79020475: Overview of updating F5 AWS CloudFormation 2.0 stack.
  • Have a good understanding of F5 AWS CloudFormation 2.0 stack update behavior. For more information, refer to AWS CloudFormation stack updates in the AWS CloudFormation User Guide.

    Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

  • Understand how F5 AWS CloudFormation 2.0 updates the BIG-IP VE instances using F5 AWS CloudFormation 2.0 and F5 BIG-IP Runtime Init. The AWS deployment updates each BIG-IP instance one-at-a-time, including time to initialize each instance. Each instance upgrade and initialization constitutes the following processes:
    1. The system launches a new virtual machine based on the image bigIpImage parameter you provided.
    2. The system downloads and runs F5 BIG-IP Runtime Init.
    3. F5 BIG-IP Runtime Init applies DO, AS3, and TS to load the BIG-IP configuration.
    4. The system destroys the old virtual machine.

The more instances you have, the more time is required.

Troubleshoot

After you update the stack, follow the events in AWS Management Console > CloudFormation > Stacks > <stackname> > Events to ensure there are no errors.

The following table lists common issues, possible causes, and resolutions.

Table 14.1 Common issues, possible causes, and resolutions
Common issuesPossible causesResolutions
The new BIG-IP instance takes a long time to initialize.Each instance upgrade and initialization goes through the following processes:
  1. The system destroys the old virtual machine.
  2. The system launches a new virtual machine based on the image Uniform Resource Name (URN) you provided.
  3. The BIG-IP system downloads and runs F5 BIG-IP Runtime Init.
  4. F5 BIG-IP Runtime Init downloads, installs and runs DO, AS3, and TS to load the BIG-IP configuration.
As the deployment launches each BIG-IP VE instance, you can optionally log in to follow the initialization process in the following files:
  • /var/log/cloud/bigIpRuntimeInit.log
  • /var/log/cloud/startup-script.log
  • /var/log/ltm
  • /var/log/restnoded/restnoded.log
The status of the update in Events stays at UPDATE_IN_PROGRESSThe AWS stack is unable to launch the BIG-IP instance. One possible cause is that your AWS account is not subscribed to the specific BIG-IP software. The update will fail after around an hour with the following error:

Failed Scaling Activity: In order to use this AWS Marketplace product you need to accept terms and subscribe. To do so please visit https://aws.amazon.com/marketplace/pp?sku=5slq71e3px6zi3a93bgnczk92. Launching EC2 instance failed.

Depending on the specific error, you can perform the following:
  • Address the error AWS reports and repeat the upgrade procedure to redeploy the deployment again.
  • In the event that you need to subscribe to the software, follow the link in the error message to subscribe. You need to do this only once for the software.
The new BIG-IP instance does not contain any objects or configuration.The system did not successfully load the bigIpRuntimeInitConfig file that contains the BIG-IP configurations, and DO, AS3 and TS are not running as a result. Enter the following command:

grep "version:" /var/log/restnoded/restnoded.log
