Known Issue

BIG-IP monitors may erroneously mark node and pool members up and down.

This issue occurs when the following conditions are met:

  • You are running a 6900/8900/8950 BIG-IP platform.
  • You are using a BIG-IP monitor to monitor pool members.

This issue occurs due to clock skew, which may cause internal timestamps to become corrupted and the bigd process to fail.

Note: External monitors are not affected.

Impact

Pools may be marked down causing an interruption to service.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H388287 on the Diagnostics > Identified > Medium screen.
  • Pools are unexpectedly marked down.
  • Errors that appear similar to the following examples show up in the /var/log/ltm log file:

    notice sod[6117]: 01140029:5: HA daemon_heartbeat bigd fails action is restart.

    err tmm1[21527]: 01010028:3: No members available for pool /Common/<pool_name>

    notice mcpd[18736]: 01070640:5: Node /Common/10.129.4.4 address 10.129.4.4 monitor status down. [ was up for 235hrs:15mins:16sec ]

  • You may see bigd core files in the /shared/core directory.

Workaround

To work around this issue, you can restart the bigd daemon each time the issue occurs. To do so, perform the following procedure:

Impact of workaround: This workaround only mitigates the issue and it may re-occur.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.

  2. Type the following command to restart the bigd service:

    restart sys service bigd
