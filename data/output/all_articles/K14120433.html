Known Issue

The mcpd process may restart and produce a core file when the dwbld process encounters an auto-denylisted IP address.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP AFM system is configured with a network protection DoS profile and the auto-denylisting feature is enabled in at least one of the configured attack types.
  • Your BIG-IP AFM system's dwbld processes IP addresses that were previously auto-denylisted by a network protection DoS profile.

Impact

The BIG-IP system may be unavailable when the mcpd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The mcpd process will produce a SIGABRT core file, located in the /shared/core directory.
  • Your BIG-IP system fails over if configured as part of a high availability (HA) group.

Workaround

To work around this issue, you can disable the debug.afm.shun.notify_peers system database key. To do so, perform the following procedure:

Impact of workaround: Disabling this database key prevents the BIG-IP system from notifying the secondary slots when the primary slot's Traffic Management Microkernel (TMM) has auto shunned an IP address.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To disable the system database key, type the following command:

    modify sys db debug.afm.shun.notify_peers value disable
