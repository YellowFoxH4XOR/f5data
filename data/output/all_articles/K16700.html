Topic

This article applies to BIG-IP 11.6.X. For information about other versions, refer to the following article:

  • K12783074: Decrypting SSL traffic using the SSL::sessionsecret iRules command (12.x and later)

You should consider using this procedure under the following condition:

  • You want to decrypt and examine Secure Socket Layer (SSL) application data using the SSL session key.

Description

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You are running a system with the Wireshark application installed.

Beginning BIG-IP 11.6.0, you can use the SSL::sessionsecret iRules command to extract the SSL session key from SSL sessions that are terminated by the Traffic Management Microkernel (TMM). This method allows you to decrypt an SSL session and review the application data using the Wireshark application without having access to the server's private key. This procedure functions on both client- and server-side and works with Diffie-Hellman and Elliptic Curve Diffie-Hellman key exchange algorithms as well as RSA.

To decrypt SSL traffic using the SSL::sessionsecret iRules command, perform one of the following procedures:

  • Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache enabled)
    • Producing a Master Secret log file and decrypting the SSL session
  • Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache disabled)
    • Producing a Master Secret log file and decrypting the SSL session

Procedures

Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache enabled)

If the SSL session cache feature is enabled in the SSL profile, you can use the following procedure to decrypt SSL traffic using the SSL::sessionsecret iRules command. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client | Server.
  3. Click the name of the SSL profile.
  4. Set the Configuration view to Advanced.
  5. Verify that the Cache Size setting is a non-zero value.
  6. Navigate to Local Traffic > iRules > iRules List.
  7. Click Create and define an iRule using a SSL::sessionsecret iRules command syntax similar to the following example:

    Note: In the following example, <client_IP_addr> is the IP address of the remote client accessing the BIG-IP virtual server.

    when CLIENTSSL_HANDSHAKE {
      # Check if client IP is <client_IP_addr>, in any route domain
      if { [IP::addr [getfield [IP::client_addr] "%" 1] equals <client_IP_addr>] } {
        log local0. "[TCP::client_port] :: RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
      }
    }
     For more information, refer to     https://clouddocs.f5.com/api/irules/IP__client_addr.html  

    Note: To dump a server-side session key, use SERVERSSL_HANDSHAKE instead of CLIENTSSL_HANDSHAKE.

  8. Associate the iRule with the virtual server.
  9. From the BIG-IP command line, run the tcpdump command on the BIG-IP system.
  10. From the client system, access the virtual server.
  11. Stop the tcpdump command.
  12. Download the generated tcpdump file.
  13. Perform the Producing a Master Secret log file and decrypting the SSL session procedure.

Producing a Master Secret log file and decrypting the SSL session

You can produce a Master Secret log file and use the file to decrypt the SSL session using either of the following methods:

  • Producing a Master Secret log file using the sed command
  • Producing a Master Secret log file manually

Producing a Master Secret log file using the sed command

  1. On the BIG-IP command line, type the following command:

    sed -e 's/^.*\(RSA Session-ID\)/\1/;tx;d;:x' /var/log/ltm > /var/tmp/sessionsecrets.pms

    Note: Run this command exactly as shown.

  2. Download the /var/tmp/sessionsecrets.pms file to your local drive.
  3. On the client system, open the Wireshark application.
  4. Navigate to Edit > Preferences > Protocols > SSL.

    Note: In the latest version of Wireshark (3.x and higher) navigate to Edit > Preferences > Protocols > TLS.

  5. For (Pre)-Master-Secret log filename, click Browse and locate the session key file you created.

    Note: If you are using an older version of Wireshark, you may need to manually enter the file information.

  6. Click OK.
  7. Open the packet capture.

    The selected SSL sessions are now decrypted.

Producing a Master Secret log file manually

  1. On the BIG-IP system, locate the SSL session keys in the /var/log/ltm log file. They appear similar to the following example:

    info tmm1[19365]: Rule /Common/Decrypt_session <CLIENTSSL_HANDSHAKE>: 50194 :: RSA Session-ID:2b14674e4bb505ab97a63ab8fe47cf6f827aa34964871338dc3b5bcc034bd91c Master-Key:7bfcb98c9725de0da25eda2110937550d9097039912ad422c877e20b43d8741572d9467365dac6a6a3e4cc19ec608bfd

    Note: The previous example represents a single log line.

  2. Copy the last section of the log lines, starting with the R in RSA.

  3. On the client system, open a text editor such as Notepad.
  4. Paste the string into the text editor and ensure each line of the file has the following syntax:

    RSA Session-ID:<session_id> Master-Key:<master_key>

    Note: Make sure to carefully check the syntax. If you vary the syntax, Wireshark cannot recognize the file.

  5. Save the file. To use the same filename as the previous instructions, name it sessionsecrets.pms 
  6. Open the Wireshark application.
  7. Navigate to Edit > Preferences > Protocols > SSL.

    Note: In the latest version of Wireshark (3.x and higher) navigate to Edit > Preferences > Protocols > TLS.

  8. For (Pre)-Master-Secret log filename, click Browse and locate the session key file you created.

    Note: If you are using an older version of Wireshark, you may need to manually enter the file information.

  9. Click OK.
  10. Open the packet capture.

    The selected SSL sessions are now decrypted.

Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache disabled)

In BIG-IP version 12.0.0 and later, you can decrypt SSL traffic using the SSL::sessionsecret iRules command in the event that the SSL session cache feature is disabled in the SSL profile. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client | Server.
  3. Click the name of the SSL profile.
  4. Set the Configuration view to Advanced.
  5. Verify that the Cache Size setting is set to zero (0).
  6. Navigate to Local Traffic > iRules > iRules List.
  7. Click Create and define an iRule using a SSL::sessionsecret iRules command syntax similar to the following example:

    Note: In the following example, <client_IP_addr> is the IP address of the remote client accessing the BIG-IP virtual server.

    when CLIENTSSL_HANDSHAKE {
      if { [IP::addr [getfield [IP::client_addr] "%" 1] equals <client_IP_addr>] } {
        log local0. "[TCP::client_port] :: Master-Key:[SSL::sessionsecret]"
      }
    }

    Note: To dump a server-side session key, use SERVERSSL_HANDSHAKE instead of CLIENTSSL_HANDSHAKE.

  8. Associate the iRule with the virtual server.
  9. On the BIG-IP command line, run the tcpdump command.
  10. On the client system, access the virtual server.
  11. Stop the tcpdump command.
  12. Download the generated tcpdump file to the client system.
  13. Perform the Producing a Master Secret log file (SSL session cache disabled) procedure.

Producing a Master Secret log file (SSL session cache disabled)

  1. On the client system, open the Wireshark application.
  2. Locate the Client Hello SSL message and random byte string for the TCP session you want to decrypt. To do so, type a filter similar to the following example into the Wireshark filter field and press the Enter key:

    tcp.port==<source_port> and ssl.handshake.random

    For example, if the TCP source port is 59159, use the following filter syntax:

    tcp.port==59159 and ssl.handshake.random

  3. Right-click the random byte string, and click Copy > ...as a Hex Stream.

    For example,

    Random: 5b575261adebe673ff8a3ed4ce01835b8840905151389eea...

  4. Open a text editor such as Notepad, and type the following:

    CLIENT_RANDOM

  5. Paste the random byte string into the file following the CLIENT_RANDOM string.

    For example:

    CLIENT_RANDOM 5b575261adebe673ff8a3ed4ce01835b8840905151389eea21df2658e271b1c1

  6. On the BIG-IP system, locate the master key in the /var/log/ltm file. The entry appears similar to the following example:

    info tmm1[5394]: Rule /Common/ssl_caching <CLIENTSSL_HANDSHAKE>: 59159 :: Master-Key:9608b87427c6c9f8612901e4fd7892b437d3cf84b0664ad8d6c6e76cc3a52d0e62a910ab1ab5d0e343f231bb4a220b51

    Note: The previous example represents a single log line.

  7. Copy the master key portion of the log line.

    For example,

    9608b87427c6c9f8612901e4fd7892b437d3cf84b0664ad8d6c6e76cc3a52d0e62a910ab1ab5d0e343f231bb4a220b51

  8. On the client system, paste the master key string into the text file following the random byte string. Ensure each line of the file uses the following syntax:

    CLIENT_RANDOM <random_byte_string> <master_key_string>

    Note: Make sure to carefully check the syntax. If you vary the syntax, Wireshark cannot recognize the file.

  9. Save the file as sessionsecrets.pms.
  10. Navigate to Edit > Preferences > Protocols > SSL.

    Note: In the latest version of Wireshark (3.x and higher) navigate to Edit > Preferences > Protocols > TLS.

  11. For to (Pre)-Master-Secret log filename, click Browse and locate the session key file you created.

    Note: If you are using an older version of Wireshark, you may need to manually enter the file information.

  12. Click OK.
  13. Open the packet capture.

    The selected SSL sessions are now decrypted.
