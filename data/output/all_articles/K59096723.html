Known Issue

The bd process may repeatedly stop responding after you upgrade the BIG-IP ASM system and roll forward the configuration.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM configuration contains an active security policy with request log data.
  • You upgrade your BIG-IP ASM system from 12.1.x to a later version.
  • The upgrade process is interrupted by a reboot.

Impact

The bd process becomes unresponsive and traffic processing is disrupted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The bd process repeatedly exits and produces core files in the /var/core directory.
  • The CONFIG_TYPE_DATA_PROTECTION table is missing from the list of read tables that the system logs to the /ts/log/bd.log file after startup.

Workaround

To work around this issue, you can disable the option to roll forward traffic data before performing the upgrade. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To disable the option to roll forward traffic data, type the following command:

    modify /sys db ucs.asm.traffic_data.save value disable
