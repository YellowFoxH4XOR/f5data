K3199: IP protocols other than TCP and UDP may not be correctly routed by a SNAT

Topic

A SNAT provides a many-to-one address translation. For example, the following SNAT will translate the nodes 1.1.1.1 and 1.1.1.2 to 2.2.2.2:

bigpipe snat 1.1.1.1 1.1.1.2 to 2.2.2.2

In this example, two nodes share the same SNAT address of 2.2.2.2. The client, 1.1.1.1, attempts to ping through the BIG-IP to an external address. For this example, the external address is 192.168.1.1.

When the BIG-IP receives the packet, it will translate the source to 2.2.2.2 and send it to the next hop, which is based on the BIG-IP's routing table. When the remote server receives the ping packet, it translates the packet's source address to 2.2.2.2. When the server responds, it responds to the SNAT address of 2.2.2.2.

When the BIG-IP receives a reply packet, it notes an existing connection table entry showing that 1.1.1.1 was attempting to ping 192.168.1.1. Therefore, if the BIG-IP receives a packet with the source IP address of 192.168.1.1 destined for 2.2.2.2, the BIG-IP will send the packet back to 1.1.1.1.

Alternatively, if both 1.1.1.1 and 1.1.1.2 ping the same destination, the clients will send the packets through the BIG-IP. When the BIG-IP tries to respond, it will have two connections in the connection table that match the reply packet. For example, two packets with a source of IP address of 192.168.1.1 destined for 2.2.2.2.

Note: Beginning in BIG-IP version 4.6, the BIG-IP is able to differentiate and properly respond to traffic generated by a ping (ICMP ECHO REQUEST and ICMP ECHO REPLY). This special handling only applies to ping traffic; all non-TCP or non-UDP traffic may still be susceptible to this issue. For more information, refer to K1906: Change in Behavior: SNATs now allow ICMP responses.

To solve this issue, you can perform one of the following options:

  • Use NATs, (one-to-one mapping) rather than SNATs (many-to-one mapping).
  • Use routable addresses on the nodes behind BIG-IP and create a forwarding virtual server that allows traffic to flow through the BIG-IP without being translated.
    Note: For information about configuring the BIG-IP system, refer to the BIG-IP Reference Guide.
