K000161820: Outlook desktop client authentication failure via BIG-IP with SSL bridging and Exchange EPA enabled

Type
Support Solution
Published
2026-06-29
Updated
2026-06-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161820

Description

Outlook desktop clients fail to authenticate to a Microsoft Exchange server when traffic is routed through BIG-IP , while authentication succeeds when F5 is bypassed entirely. Clients gets HTTP 401 unauthorized responses when traffic passing through BIG IP. NTLM handshake completes successfully (NTLMSSP_NEGOTIATE → NTLMSSP_CHALLENGE → NTLMSSP_AUTH), but Exchange server rejects the final authentication with HTTP 401.

 

Environment

  • BIG IP LTM
  • Virtual server with Client and server SSL profiles
  • NTLM profile associated to the virtual server
  • Microsoft Exchange Server with Extended Protection for Authentication (EPA) enabled
  • MAPI over HTTP (Outlook desktop)

 

Cause

There is a mismatch between the SSL certificate used on the BIG-IP client SSL profile and the SSL certificate installed on the Exchange server.

When Microsoft Exchange has Extended Protection for Authentication (EPA) enabled (a mitigation for CVE-2024-21410 — NTLM relay attacks), it enforces Channel Binding Token (CBT) validation. CBT validation requires that the TLS channel binding information embedded in the NTLM authentication token matches the certificate presented by the server.

With SSL bridging in place, BIG-IP terminates the client TLS session and establishes a separate TLS session to the Exchange server. If the certificate on the BIG-IP client SSL profile differs from the certificate on the Exchange server, the CBT embedded in the client's NTLM token will not match what Exchange expects, causing Exchange to reject the authentication with HTTP 401 — even though the NTLM handshake itself completes successfully.

 

Answer/Recommended Actions

  1. Export the SSL certificate currently installed on the Exchange server.
  2. Import the Exchange server's SSL certificate into the BIG-IP system (navigate to System > Certificate Management > Traffic Certificate Management > SSL Certificate List > Import).
  3. Create a new Client SSL profile on BIG-IP using the imported Exchange server certificate (navigate to Local Traffic > Profiles > SSL > Client > Create)
  4. Assign the new Client SSL profile to the affected virtual server (replacing or supplementing the existing client SSL profile).

 

Additional Information

EPA and CBT: Extended Protection for Authentication (EPA) was enabled on Exchange as a security mitigation for Microsoft CVE-2024-21410, which addresses NTLM relay attack vulnerabilities. When EPA is enabled, Exchange validates the Channel Binding Token (CBT) in the NTLM authentication message. With SSL bridging on BIG-IP, the client establishes a TLS session with BIG-IP (not directly with Exchange), so the certificate BIG-IP presents to the client must match the Exchange server's certificate for CBT validation to succeed.
