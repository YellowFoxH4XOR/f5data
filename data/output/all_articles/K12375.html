Known Issue

Note: A similar issue that involves running the tcpdump command on a physical interface twice may result in the BIG-IP system dropping LACP packets. For more information, refer to K12937: Running the tcpdump command twice on the same interface may cause the BIG-IP system to drop LACP packets.

This is the result of a known issue. When you run the tcpdump command on a physical interface, the BIG-IP system may drop STP BPDU frames on that interface. This behavior may affect the following platforms:

  • BIG-IP 6900 (D104)
  • BIG-IP 8900 (D106)
  • BIG-IP 8950 (D107)
  • BIG-IP 11050 (E102)
  • VIPRION (PB100, PB200)

For example, when you run the tcpdump command on a physical interface, such as 1.1, while the interface is processing a moderate to high amount of traffic, the BIG-IP system intermittently drops BPDU frames. When this issue occurs, you may experience STP state changes on the BIG-IP system even though the topology has not changed. In addition, the system writes log messages indicating the stpd state changes to the /var/log/ltm file. The log messages appear similar to the following example:

Note: This issue does not occur when running tcpdump on a non-physical interface, such as a VLAN or interface 0.0.

F5 Product Development is tracking this issue as ID 342946.

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.2-852.0-HF1, which has been issued for BIG-IP 10.2.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP 10.x systems.

Workaround

You can work around this issue by running tcpdump on non-physical interfaces, such as a VLAN or interface 0.0. In addition, you can use an external traffic sniffer device to run an interface tcpdump.

Note: For more information, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system.
