Known Issue

The imi process may exit when BIG-IP ARM users are manually created.

This issue occurs when all of the following conditions are met:

  • Dynamic routing is enabled on your BIG-IP system.
  • You perform either of the following tasks:

    • Create a BIG-IP ARM user name and encrypted password by using the IMI Shell (imish).
    • Add a user name and encrypted password by editing the /config/zebos/rd<n>/ZebOS.conf file and saving the change.
For example, this issue can occur if you attempt to create a new user with an encrypted password by using the following imish command:

(config)#username testuser privilege 15 password 8 testpasswd

Impact

The imish interface for BIG-IP ARM is unavailable while the imi process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system generates an imi core file to the /shared/core/ directory.
  • Administrators cannot access the BIG-IP ARM user interface.

Workaround

To work around this issue, you can avoid creating users directly in BIG-IP ARM. To limit access to the BIG-IP ARM configuration, you can use the Configuration utility or Traffic Management Shell (tmsh) to create users.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
