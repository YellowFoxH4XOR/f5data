K213: SNATs route by packet, rather than by connection

Published

Known Issue

This is the result of a known issue. When only a SNAT handles connections, BIG-IP performs a route lookup for each packet that arrives at the SNAT. If a default gateway pool is configured, BIG-IP may send packets from the same connection to different gateways within the default gateway pool.

F5 Networks Product Development tracked this issue as CR20801 and CR41771.

Workaround

To work around this issue, configure a network virtual server that handles the same traffic as the SNAT. The virtual server will process the traffic before the SNAT and will route traffic according to the connection, rather than by packet.
