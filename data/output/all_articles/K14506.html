Known Issue

Modification of an inactive BIG-IP ASM policy with the Traffic Management Shell (tmsh) creates a new unmodifiable policy named ./.

This issue occurs when all of the following conditions are met:

  • A BIG-IP ASM policy is in the inactive state.
  • The inactive BIG-IP ASM policy is edited using tmsh.

The edits to the original inactive BIG-IP ASM policy are not saved. Instead, a new policy named ./ is created with the edited settings.

Impact

  • The original inactive BIG-IP ASM policy is not updated.
  • The new ./ policy cannot be referenced using tmsh.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Modifications to the inactive policy are not reflected in the policy.
  • Using tmsh to modify or delete the ./ tmsh policy name fails with the following error message:

    Unexpected Error: ASMConfig exception: [102] Could not get the Policy 'Security Policy .', No matching record was found.

Workaround

To work around this issue, you can place the inactive policy you want to edit into the active state by creating a new HTTP Class that is BIG-IP ASM-enabled and associate the inactive BIG-IP ASM policy to the new HTTP Class prior to editing the inactive policy. To do so, perform the following procedures:

Using tmsh to create a new BIG-IP ASM-enabled HTTP Class

Impact of workaround: None

Note: There is no impact as long as a virtual server does not reference the HTTP Class that is assigned to the intended inactive policy.

  1. To create the HTTP Class profile with BIG-IP ASM enabled, enter the following command:

    tmsh create ltm profile httpclass <httpclass name> asm enabled
  2. To remove the new incomplete and inactive BIG-IP ASM policy generated by creating a new BIG-IP ASM-enabled HTTP Class, enter the following command:

    tmsh delete asm policy <httpclass name>
  3. To activate the inactive BIG-IP ASM polciy by assigning the policy to the newly created HTTP Class, enter the following command:

    tmsh modify asm policy <inactive ASM policy> httpclass-profile <httpclass name>

Deleting the ./ tmsh automatically generated policy

It is not possible to delete the ./ policy using tmsh commands. F5 recommends that you delete the ./ policy using the Configuration utility. To do so, perform the following procedure:

Impact of workaround: None

  1. Log on to the BIG-IP Configuration utility with administrative access.
  2. Navigate to Security > Application Security > Security Policies.
  3. Select Inactive Policies.
  4. Select the ./ policy option and click Delete.
  5. To confirm that you have deleted the policy, click OK.
