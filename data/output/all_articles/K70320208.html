K70320208: Configuring the dynconfd daemon for remote syslog debug level logging

Type
Support Solution
Published
2019-12-03
Updated
2023-02-21
Applies to
  • BIG-IP LTM: 15.X.X
Source
https://my.f5.com/manage/s/article/K70320208

Description

Configuring remote syslog for the dynconfd daemon debug level logging of FQDN dynamic updates for auto-populating pool members and nodes 

Environment

  • Dynconfd debug level logging enabled (refer to K48023553 for details)
  • BIG-IP v12.1.3.3 +
  • BIG-IP v13.1.0 +

Recommended Actions

Enable dynconfd debug level logging

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command
    tmsh
     
  2. To configure the BIG-IP system to log FQDN dynamic debug level updates, you must set the dynconfd.loglevel BigDB database key by typing the following command:
    modify sys db dynconfd.loglevel value debug_msg

Defining a syslog include statement that references the remote server(s) for dynconfd remote debug level logging
Note: Modifications to the syslog configuration properties that are made by using this procedure may not be reflected in the Configuration utility.
Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:
    tmsh
     
  2. To define the desired include statement that references dynconfd remote logging, type the following command:
    edit /sys syslog all-properties

    The syslog configuration opens in the vi text editor and appears similar to the following example:

    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include none
        iso-date disabled
        kern-from notice
        kern-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers none
        user-log-from notice
        user-log-to emerg
    }
     
  3. Replace the include none line with the desired syslog statement.

    For example, to configure syslog-ng to remotely log dynconfd debug level logging to both 10.155.24.x over UDP port 514, use the following syntax:

    include "
    source s_dynconfdlog {
                pipe(/var/run/dynconf_log.pipe);
        };
        destination d_dynconfdlog {
                udp(10.155.24.97 port(514));
                udp(10.155.24.98 port(514));
        };
        log {
                source(s_dynconfdlog);
                    destination(d_dynconfdlog);
        };
    "

    After adding the previous include statement, the syslog configuration appears similar to the following example:

    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        clustered-host-slot enabled
        clustered-message-slot disabled
        console-log enabled
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include "
        source s_dynconfdlog {
                pipe(/var/run/dynconf_log.pipe);
        };
        destination d_dynconfdlog {
                udp(10.155.24.97 port(514));
                udp(10.155.24.98 port(514));
        };
        log {
                source(s_dynconfdlog);
                    destination(d_dynconfdlog);
        };
        "
        iso-date disabled
        kern-from debug
        kern-to emerg
        local6-from notice
        local6-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers none
        user-log-from notice
        user-log-to emerg
    }
     
  4. Exit the text editor by typing the following key sequence:
    :wq!
     
  5. At the following prompt, type y to save the changes to the file:

    Save changes? (y/n/e)
     
  6. Save the configuration by typing the following command:
    tmsh save /sys config


The BIG-IP syslog-ng system now sends dynconfd debug level logging traffic to the remote server(s) using the defined syslog include statement.

Remove the defined include statement configuration

  1. Run the following command from tmsh:
    modify /sys syslog include none

Additional Information

If syslog remote servers are defined in addition to the include statement defined then both general syslog level logging as well as the defined dynconfd debug level logging will be remotely logged based on the destination definitions assigned.
