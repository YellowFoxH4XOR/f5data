K60222431: /var/log/messages show: Error Message: logrotate[XXXX]: ALERT exited abnormally with [1] every 5 minutes.

Type
Support Solution
Published
2020-09-14
Updated
2025-04-02
Applies to
  • BIG-IP LTM: 14.1.2
Source
https://my.f5.com/manage/s/article/K60222431

Description

  • Every 5 minutes, the below error message will populate in /var/log/messages
    • Error Message: logrotate[XXXX]: ALERT exited abnormally with [1]
       
  • Additionally at the same interval log messages similar to the following populate to /var/log/ts/cron.log
    • skipping "/ts/log/bd_agent.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
    • skipping "/ts/log/bd.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
    • skipping "/ts/log/bigdb_var.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
    • skipping "/ts/log/cron.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
    • skipping "/ts/log/set_ibdata1_size.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
    • skipping "/ts/log/ts_debug.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
    • skipping "/ts/log/update_dpi_sigfile.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
    • skipping "/ts/log/xui.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation.
       

Environment

  • BIG-IP LTM 14.1.X or later, now including the logrotate v3.8.0 package
  • The volume configuration, including the systemwide /var partition must have been created with a version 11.4.x or earlier
  • The ASM product is NOT provisioned during the upgrade procedure.

Cause

  • A known issue tracked as ID429221 caused the initial/factory installation of the volumes for the /var/log filesystem created under 11.4.x with open permissions
  • When ASM is provisioned, during upgrade, these permissions will be automatically corrected.  When ASM is not provisioned on reboot, the new logrotate software trigger errors showing these permissions
  • Changes to logrotate introduced in https://github.com/logrotate/logrotate/blob/r3-8-0/CHANGES
    • You can check the current version of logrotate by running the following command within the Bash CLI 
      • # logrotate
logrotate 3.8.6 - Copyright (C) 1995-2001 Red Hat, Inc.
This may be freely redistributed under the terms of the GNU Public License

Recommended Actions

Run the following commands from the Bash CLI on the device showing the error, to resolve this issue.

  1. # ls -ld /var/log/ts
    • This should show the follow output:
    • drwxrwxrwx. 7 root root 4096 Jan 1 12:34 /var/log/ts
       
  2. # /usr/sbin/logrotate -s /var/lib/logrotate-asm.status /etc/ts/common/asm_logrotate.conf
    • This will not show any output.
       
  3. # echo $?
    • If this shows a 1, it confirms the issue with the log message.
       
  4. # chmod og-w /var/log/ts
    • This command fixes the directory permissions to /var/log/ts
    • running the command in step 1 should now show the following directory permissions.
      • drwxr-xr-x. 7 root root 4096 Jan 1 12:34 /var/log/ts
         
  5. # /usr/sbin/logrotate -s /var/lib/logrotate-asm.status /etc/ts/common/asm_logrotate.conf
  6. # echo $?
    • If step 4 was successful, you should see a "0" output from this command

After running this, the logrotate issue is resolved and you should no longer see the log entry:
  • Error Message: logrotate[XXXX]: ALERT exited abnormally with [1]
