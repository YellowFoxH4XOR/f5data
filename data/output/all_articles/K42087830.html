Description

Health check not marking pool member down when the application is not available

Environment

  • BIG-IP LTM
  • LTM Pool
  • HTTP or HTTPS Monitor
  • Non-functioning pool member

Cause

The health monitor applied to the pool does not have a receive string configured. If you do not specify both a send string and a receive string, the monitor performs a simple service check and connect only.

ltm monitor https /Common/example_https_monitor {
    adaptive disabled
    defaults-from /Common/https
    destination *:*
    interval 5
    ip-dscp 0
    recv none
    recv-disable none
    send "GET /example/healthcheck.html \r\n"
    time-until-up 0
    timeout 16
}

Recommended Actions

Add a receive string to your monitor so that BIG-IP can identify a valid monitor response
  1. Navigate to HTTP or HTTPS health monitor in question
  2. Add the desired 'mark up' string to the Receive String field
  3. Click 'Update' to save the configuration change

Additional Information

Without a receive string configured on the monitor, any HTTP response will cause the BIG-IP to mark the pool member as available.
