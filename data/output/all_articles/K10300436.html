Known Issue

The BIG-IP system may fail to recover from a crypto-failsafe condition.

This issue occurs when all of the following conditions are met:

  • You are using one of the following platforms:
    • BIG-IP 2000 or 2200 (C112) series
    • BIG-IP 4000 or 4200 (C113) series
    • BIG-IP i2600 or i2800 (C117) series
  • The crypto-failsafe action is set to fail over and the failsafe condition is triggered.

Impact

You are unable to activate the BIG-IP system, even after the cryptographic hardware recovers.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Output of the tmsh show sys ha-status command appears similar to the following example:

    -------------------------------------------------------------------------------
     Sys::HA Status
     Slot  Feature               Key              Action                        Fail
     -------------------------------------------------------------------------------
     1     crypto-failsafe       cn-crypto-11     failover                      yes

  • In the /var/log/ltm file, you observe messages similar to the following examples:

    crit tmm[9184]: 01010025:2: Device error: crypto codec cn-crypto-0 queue is stuck.
    notice sod[8874]: 01140029:5: HA crypto_failsafe_t cn-crypto-0 fails action is failover.

Workaround

When your BIG-IP system is in an affected state, you can recover from this issue by restarting the Traffic Management Microkernel (TMM). To do so, perform the following procedure:

Impact of workaround: Because a system in an affected state is already unable to process traffic, restarting TMM should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Restart TMM by typing the following command:

    restart /sys service tmm

Note: If performing this recover action does not return the BIG-IP system to a functional state, the cryptographic hardware may not yet have fully recovered from the failure. Alternatively, the system may be encountering a different issue with similar symptoms.
