K51208625: New ICAP logging subset and messages

Type
Knowledge
Published
2018-04-16
Updated
2025-02-06
Applies to

  • BIG-IP LTM: 13.1.0
Source

Issue

Old Behavior

In versions prior to BIG-IP 13.1.0, it is not possible to adjust the logging level for Internet Content Adaptation Protocol (ICAP) messages.

New Behavior

Beginning in BIG-IP 13.1.0, logging enhancements for ICAP messages are introduced. New messages are added to better identify events related to the ICAP profile and the internal virtual server used to process ICAP functions. The ICAP log messages appear in the /var/log/ltm file. Additionally, a new log.icap.level database variable is introduced to allow you to adjust the log level for ICAP messages. The default value of the log.icap.level database variable is Error.

Note: The BIG-IP 13.1.0 Fixes and Known Issues document incorrectly indicates a default value of Notice for the log.icap.level database variable.

F5 Product Development tracked this change as ID 640399.

Impact

Improves log messaging for ICAP events and provides the ability to adjust the log level for ICAP logging.

Recommended Actions

If you need to adjust the logging level for events related to the ICAP profile or the internal virtual server used for ICAP functions, for example to enable debug logging, you can modify the log.icap.level database variable. To do so, perform the following procedure:

Impact of procedure: F5 recommends that you return the ICAP log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor performance.

  1. Log in to the TMOS Shell tmsh by typing the following command:

    tmsh

  2. Enable ICAP debug logging by typing the following command:

    modify /sys db log.icap.level value debug

    Important: After you test ICAP functions for the virtual server, you should disable ICAP debug logging by typing the following command: modify /sys db log.icap.level value error.
