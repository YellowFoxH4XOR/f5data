Known Issue

This is the result of a known issue. If you use the HTTP::retry iRule command in the HTTP_RESPONSE or HTTP_RESPONSE_DATA event with a BIG-IP ASM or BIG-IP WebAccelerator-enabled virtual server, the BIG-IP ASM or WebAccelerator system aborts the connection and sends a TCP reset to the client.

For example:

when HTTP_RESPONSE {
if { [HTTP::is_redirect] } {
HTTP::retry "GET [HTTP::header location] HTTP/1.1\r\nHost: [HTTP::host]\r\n\r\n"
}
}

F5 Product Development tracked this issue as ID 349510 and it was fixed in BIG-IP 10.2.2. For information about upgrading, refer to the BIG-IP ASM and WebAccelerator release notes.
