Known Issue

IPsec traffic selector narrowing may cause the Traffic Management Microkernel (TMM) to restart with an Assertion "flow not in use" message.

This issue occurs when the following condition is met:

  • Your BIG-IP system uses an IPsec tunnel configuration that includes IKE peers, IPsec policies, and IPsec traffic selectors.

When traffic selector narrowing occurs during IPsec/IKE negotiations, the narrowed selector policies are added and deleted multiple times for the same parent IPsec policy. During this process, improper release of flows by TMM may cause the tmm process to restart and produce a core file.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily fails to process traffic as it recovers from TMM restarting.
  • A message similar to the following example is logged to the /var/log/tmm file:

    notice panic: ../base/flow_table.c:598: Assertion "flow not in use" failed.
  • A message similar to the following example is logged to the /var/log/racoon.log file:

    INFO: ISAKMP-SA deleted 405d::1001[500]-405d::1002[500] spi:031294d110ac653a:d6206822134c417b
    INFO: caught signal 15
    INFO: Deleting inbound/outbound ipsec sa [0x847c76db] [0x234fc86]
    INFO: racoon shutdown
  • The BIG-IP system generates a TMM core file to the /var/core directory, with a time stamp that correlates to the traffic interruption, similar to the following example:

    -rw-r--r-- 1 root root 226M Jan 01 15:01 tmm.0.bld0.0.520.core.gz
  • If configured for HA, the BIG-IP system fails over to the standby system.
