Description

When deploying multiple F5 Container Ingress Services (CIS) instances to manage load balancing and GSLB (Global Server Load Balancing) across multiple datacenters, issues may arise when configuring a single ExternalDNS Custom Resource Definition (CRD) with multiple pools referencing different dataServerName values. The following error may be observed:

 GTM: Error while creating pool: F5CcclError - Virtual Server Resource not Available in BIG-IP

Additionally, GSLB pools may be created with missing members, or only one pool is populated as expected.

Environment

  • Product: F5 K8S-BIGIP-Controller (CIS)
  • Version: 2.16.1 and 2.20.0
  • Platform: F5 LTM and GTM appliances in a multi-datacenter deployment
  • Configuration:
    • Multiple CIS instances (one per datacenter or namespace)
    • Each CIS instance manages its own LTM and GTM pair
    • ExternalDNS CRDs used for GSLB configuration
    • Service discovery enabled (no delete)
    • VirtualServer CRDs deployed in separate namespaces

 

Cause

This issue occurs because each CIS instance can only manage resources within its configured namespace(s) and BIG-IP partition(s). When a single ExternalDNS CRD is configured with multiple pools referencing dataServerName values for virtual servers not managed or visible to the current CIS instance, the controller cannot locate the referenced virtual server resources on the BIG-IP, resulting in the error:

 GTM: Error while creating pool: F5CcclError - Virtual Server Resource not Available in BIG-IP

This is due to namespace and resource visibility limitations inherent to CIS controller configuration.

Recommended Actions

Use Separate ExternalDNS CRDs:

Instead of specifying multiple pools within a single ExternalDNS CRD, create separate ExternalDNS CRDs in the respective namespaces managed by each CIS instance. Each CRD should reference only the dataServerName that is visible and managed by that specific CIS instance.

apiVersion: cis.f5.com/v1
kind: VirtualServer
metadata:
  labels:
    f5cr: "true"
  name: example-vitual-1
  namespace: cistest
spec:
  host: example.com
  pools:
  - monitor:
      interval: 20
      recv: ""
      send: /
      timeout: 10
      type: http
    path: /
    service: svc-1
    servicePort: 80
  virtualServerAddress: 172.16.3.4
---
apiVersion: cis.f5.com/v1
kind: VirtualServer
metadata:
  labels:
    f5cr: "true"
  name: example-virtual-2
  namespace: cistest-two
spec:
  host: example.com
  pools:
  - monitor:
      interval: 20
      recv: ""
      send: /
      timeout: 10
      type: http
    path: /
    service: svc-2
    servicePort: 80
  virtualServerAddress: 172.16.3.5

 

 

Namespace and Controller Configuration:

Ensure each CIS instance is configured to watch the correct namespace and BIG-IP partition. Each controller should only reference resources it manages.

GTM and LTM Configuration:

Both LTMs must be configured as Server objects on the GTM (in the Common partition), with virtual server discovery enabled.

The dataServerName field in the ExternalDNS CRD must match the GTM server name.

If GTM and LTM resources are on different BIG-IPs, configure your CIS deployment with appropriate GTM parameters (gtm-bigip-url, gtm-bigip-username, gtm-bigip-password).

Troubleshooting:

If errors persist, verify that:

The GTM has discovered the virtual server for the domain matching the ExternalDNS resource.

The CIS instance has access to both the namespace and partition where its VirtualServer CRD is deployed.

The virtual server exists and is healthy on its respective LTM.
