Known Issue

This is the result of a known issue. When you configure BIG-IP WebAccelerator parameter value substitution for a leaf node, you must define a Source and a Target for the substitution action. The Source determines the value which will be substituted for the defined Target wherever it is found in the origin web server (OWS) response. However, when the Source is defined as Request URL and the request uses the HTTPS protocol scheme, the BIG-IP WebAccelerator system incorrectly re-writes the protocol scheme to HTTP when substituting the encoded URL in matching query parameter targets found in the response. As a result, links embedded in the response page may not function as expected.

Note: Parameter value substitution is configured in the BIG-IP WebAccelerator Configuration utility on the Assembly Policy tab of the leaf node. For more information, refer to the Configuring Assembly Rules chapter of the Policy Management Guide for the BIG-IP WebAccelerator.

For example:

  • The following configuration instructs the BIG-IP WebAccelerator to parse each OWS response for any embedded link that contains a parameter named url, then replace its value with the encoded request URI:

    Source Type:           Request URL
    Target Type:           Query Parameter    
    Parameter name:        url
  • The BIG-IP WebAccelerator virtual server receives a request for the following URI and proxies the request to the OWS:

    https://www.site.com/mypage.jsp?entity=orange
  • The OWS response contains the target parameter url within an embedded link:

    <a href="https://www.site.com/page2.jsp?url=&ID=123456">
  • After substitution, the embedded URL, as served by the BIG-IP WebAccelerator system, is expected to appear as follows:

    <a href="https://www.site.com/page2.jsp?url=https%3A%2F%2Fwww.site.com%2Fpage1.jsp%3Fentity%26orange&ID=123456">
  • However, due to the known issue described, the BIG-IP WebAccelerator incorrectly re-writes the value of the target parameter using the HTTP protocol scheme:

    <a href="https://www.site.com/page2.jsp?url=http%3A%2F%2Fwww.site.com%2Fpage1.jsp%3Fentity%26orange&ID=123456">

F5 Product Development tracked this issue as ID 342889, and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.
