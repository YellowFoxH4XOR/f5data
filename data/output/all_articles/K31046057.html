Topic

You should periodically check your BIG-IP configuration for known vulnerabilities. To check for vulnerabilities you can use third-party vulnerability scanners or else upload your QKView file to F5 iHealth, where you can review system diagnostics. For more information about iHealth, refer to K27404821: Using F5 iHealth to diagnose vulnerabilities.

Note that third-party vulnerability scanners may return false positives when scanning F5 products. Scanners are designed for generic servers and the results are not always accurate when run against an appliance. Check any results that a scanner returns against the available articles on AskF5. If you have any remaining questions, feel free to open a support ticket.

Description

False positive results often occur when a scanner analyzes software versions that a scan returns and the versions reference only the base software version of the item that the scanner is checking. For example, if a base software version is identified as vulnerable, and the vulnerability is addressed in a software patch applied to that base version, the scan result returns a false positive. F5 implements software patches from CentOS (Red Hat). These patches are often applied to the base version and, therefore, do not increment the base software version. A scanner that checks only for the base version triggers a false positive in this scenario.

For more information, refer to K3645: Base operating system information for the BIG-IP host system.

When CentOS updates packages to implement security patches, they do not update the version number as presented by a banner or header, which could lead to a false positive. For more information about Red Hat's Security Backporting Practice, refer to Backporting Security Fixes.

The following is an example of a false positive relating to CVE-2015-5600, as a result of using a vulnerability scanner.

  • The F5 Security Advisory K17113: OpenSSH vulnerability CVE-2015-5600 indicates that the vulnerability is fixed in the software version that the customer is running (13.1.0.x), but the vulnerability scanner still flags this CVE.
  • This CVE is flagged because on BIG-IP 13.1.x, F5 uses OpenSSH 6.6.1p1 and has implemented many security patches without updating the actual version number. The scanner might detect the OpenSSH 6.6.1p1. version and act as though it is not an officially patched version.

This problem is well known in the community and is not specific to F5.

  • False positive Apache version in scanner results on Centos

Recommended Actions

Check what software version is running on what BIG-IP version. Refer to the following articles:

  • K11398383: BIG-IP third-party software matrix (17.x)
  • K48851448: BIG-IP third-party software matrix (16.x)
  • K51874520: BIG-IP third-party software matrix (15.x)
  • K59285635: BIG-IP third-party software matrix (14.x)
  • K65097545: BIG-IP third-party software matrix (12.x - 13.x)

If the vulnerability scanner reports that the BIG-IP system is vulnerable to a particular CVE, check if F5 has published an official Security Advisory by searching for the CVE number on support.f5.com. If the Security Advisory indicates that the vulnerability is fixed in a particular version, refer to the scanner documentation and methods to detect the vulnerability.
