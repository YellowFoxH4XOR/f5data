Topic

This article covers how to use the BIG-IQ authentication token to perform iControl REST requests using the cURL utility. This method is required when the basic HTTP authentication is disabled on the BIG-IQ system.

The basic HTTP authentication setting is disabled by default. When a requestor that is using basic HTTP authenticated iControl REST requests wants to access a BIG-IQ system that has basic HTTP authentication disabled, the system denies the requestor access because of this change in behavior. This change also applies when the BIG-IQ system receives requests using cURL commands with methods like GET, POST, DELETE, or PATCH.

For more information about the change in behavior for basic HTTP authentication, refer to K43725273: The BIG-IQ system has HTTP basic authentication disabled by default.

Description

The BIG-IQ authentication token is represented on the HTTP request header with the variable name X-F5-Auth-Token, and the token has an access timeout value and a refresh timeout value. Before the access token's timeout expires, you can continue to use the access token to send iControl REST requests to the target BIG-IQ system. When the access token timeout expires, you must get a new access token before you can send in the subsequent iControl REST requests.

The BIG-IQ authentication token has two types of timeout parameters. The default timeout values are hard coded and you cannot change them. The two types of timeout parameters are as follows:

  • You receive the newly requested access token whenever you perform an authenticated login to the BIG-IQ system. The access token has a default timeout of 5 minutes, and you can use it to send iControl REST requests to the target BIG-IQ system before the timeout expires. Any iControl REST requests that use an expired access token receive an error code 401 with the message invalid registered claims from the target BIG-IQ system.
     
  • You receive the refresh token whenever you request a new access token with authenticated login. The refresh token has a default timeout of 10 hours, and you can exchange it for the subsequent new access token without performing an authenticated login. In addition, the refresh token timeout counter continues to count down to its expiration (of 10 hours), starting from your first authenticated login, during which you receive the refresh token. The timeout counter does not reset or extend whenever you perform a refresh request.

There are two ways to request a new access token:

  • Perform an authenticated login to the BIG-IQ system.
  • Within the token validity period, use the refresh token to request for a new access token without performing an authenticated login.

Procedure

The following procedures illustrate how the system applies the access and refresh tokens when you communicate to a BIG-IQ system with basic HTTP authentication disabled. 

  • Determine if the BIG-IQ system is enabled with basic HTTP authentication
  • Use an authenticated login to request a new access token from the target BIG-IQ system
  • Use the refresh token to exchange for a new access token
  • Send an iControl REST request to the target BIG-IQ system using the F5 authentication token header
  • Use the shell environment variable to store the F5 token and the refresh token
  • Use the shell environment variable refresh token to exchange for a new access
  • Use the shell environment variable token to send iControl REST requests

About cURL and jq utilities

To perform the following procedures in this article, you must have command-line access to a UNIX-type system with the cURL utility and the jq (command line JSON processor) utility installed. For more information about the jq utility, refer to https://stedolan.github.io/jq.

Determine if the BIG-IQ system is enabled with basic HTTP authentication

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ system advanced shell.
  2. Enter the following command:

    set-basic-auth

  3. Check on the output, and determine the setting as follows:
    • If the output displays the following:

      Basic auth is enabled.

      This means that the BIG-IQ system has basic HTTP authentication enabled.

    • If the output displays the following:

      Basic auth is disabled.

      This means that the BIG-IQ system has basic HTTP authentication disabled, and you must use the BIG-IQ authentication token to send iControl REST requests to the BIG-IQ system.

Use an authenticated login to request a new access token from the target BIG-IQ system

When you are authenticated using the authentication login API endpoint, you receive a pair of tokens, the access token and the refresh token. This procedure explains the differences and which variable to capture the two tokens and observe their properties.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the remote UNIX-type system command-line shell or a terminal session.

    Note: This remote system has the required network connectivity to the target BIG-IQ system.

  2. To authenticate and receive the tokens (for both Access and Refresh), use the BIG-IQ iControl REST endpoint /mgmt/shared/authn/login using the following command syntax:

    curl -ks -X POST -d "{'username':<ADMIN_USERID>, 'password':<ADMIN_PASSWORD>, 'loginProviderName':<LOGIN_PROVIDER_NAME>}" https://<BIQ_IP>/mgmt/shared/authn/login

    In the previous syntax, note the following:

    • <ADMIN_USERID> refers to the system's default admin (that is, primary admin user) user ID.
    • <ADMIN_PASSWORD> refers to the user's password.
    • <LOGIN_PROVIDER_NAME> refers to the method of user authentication configured on the target BIG-IQ system. This option is required when the BIG-IQ system is configured with a remote authentication method.
    • <BIQ_IP> refers to the IP address (or hostname if it is resolvable) of the target BIG-IQ system that you are trying to access with the cURL command.  If you are logged in to the BIG-IQ system, you can direct the cURL commands to the local host.
    • /mgmt/shared/authn/login is the authentication login API.
    • The double quotes surrounding the POST data allow for variable expansion and command substitution; however, the curl command may result in a 401 Authentication failed error or another HTTP error. If you're not using those shell features, you can replace the double quotes with single quotes in these cases which should allow the command to work.

    The output from this login endpoint have many variables and this article only focuses on the access token (output variable .token) and the refresh token (output variable .refreshToken).

Use the refresh token to exchange for a new access token

Use the refresh token to send an exchange request for a new access token to allow continual access to the target BIG-IQ system without performing another authenticated login. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the remote UNIX-type system command-line shell or a terminal session.

    Note: This remote system has the required network connectivity to the target BIG-IQ system.

    If the refresh token is still within the 10 hours expiration period, to renew the access token, perform the following command with the refresh token using the authentication exchange API endpoint:

    curl -ks -X POST -d "{'refreshToken': {'token':'<REFRESH_TOKEN>'}}" https://<BIQ_IP>/mgmt/shared/authn/exchange

    In the previous syntax, note the following:

    • <REFRESH_TOKEN> refers to the refresh token string value.
    • <BIQ_IP> refers to the IP address (or hostname if it is resolvable) of the target BIG-IQ system that you are trying to access with the cURL command. If you are logged into the BIG-IQ system, you can direct the cURL commands to the local host.
    • /mgmt/shared/authn/exchange is the authentication exchange API.

Send an iControl REST request to the target BIG-IQ system using the F5 authentication token header

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the remote UNIX-type system command-line shell or a terminal session.

    Note: This remote system has the required network connectivity to the target BIG-IQ system.

  2. If the Access Token is still within the 300 seconds expiration period, you can send a iControl REST request with the access token header by using the following cURL command syntax:

    curl -sk -H "X-F5-Auth-Token: <ACCESS_TOKEN>" https://<BIQ_IP>/<URI_PATH>/ 

    In the previous syntax, note the following:

    • <ACCESS_TOKEN> refers to the access token string value.
    • <BIQ_IP> refers to the IP address (or hostname if it is resolvable) of the target BIG-IQ system that you are trying to access with the cURL command. If you are logged into the BIG-IQ system, you can direct the cURL commands to localhost.
    • <URI_PATH> refers to the URL path where you can access the BIG-IQ system objects.

Use the shell environment variable to store the F5 token and the refresh token

This is an alternative method where you can use the command-line shell environment variable to store the F5 token. This procedure uses the jq command to illustrate how the JSON formatted output with the F5 token and the refresh token are assigned to the shell environment variables.

To use this method, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the remote UNIX-type system command-line shell or a terminal session.

    Note: This remote system has the required network connectivity to the target BIG-IQ system.

  2. Log in to the target BIG-IQ system using the cURL syntax, and store the F5 token and refresh token in the two shell environment variables so you can use them to perform the next consecutive procedures that require this token. To do so, use the following command syntax:

    read -r -d '\n' <TOKEN_VAR_1> <TOKEN_VAR_2> <<<$(curl -ks -X POST -d "{'username':'<ADMIN_USERID>', 'password':'<ADMIN_PASSWORD>', 'loginProviderName':'<LOGIN_PROVIDER_NAME>'}" https://<BIQ_IP>/mgmt/shared/authn/login | jq .token.token,.refreshToken.token)

    In the previous syntax, note the following:

    • <TOKEN_VAR_1> refers to the shell environment variable name used to store the access token.
    • <TOKEN_VAR_2> refers to the shell environment variable name used to store the refresh token.
    • <ADMIN_USERID> refers to the system's default admin (that is, primary admin user) user ID.
    • <ADMIN_PASSWORD> refers to the user's password.
    • <LOGIN_PROVIDER_NAME> refers to the method of user authentication configured on the target BIG-IQ system. This option is required when the BIG-IQ system is configured with a remote authentication method.
    • <BIQ_IP> refers to the IP address (or hostname if it is resolvable) of the target BIG-IQ system that you are trying to access with the cURL command. If you are logged into the BIG-IQ system, you can direct the cURL commands to localhost.
    • /mgmt/shared/authn/login is the Authentication Login API.

For example, when the BIG-IQ system uses the remote authentication method configured as MyRadius, use the following command:

read -r -d '\n' Token RefreshToken <<<$(curl -ks -X POST -d "{'username':'admin', 'password':'admin', 'loginProviderName':'MyRadius'}" https://10.100.100.100/mgmt/shared/authn/login | jq .token.token,.refreshToken.token)

In the previous example, a copy of the access token string is stored on the shell environment variable $Token, and the refresh token is stored in the shell environment variable $RefreshToken, and you can use them to send iControl REST requests to the BIG-IQ system.

Use the shell environment variable refresh token to exchange for a new access

Use the shell environment variable refresh token to exchange for a new access token for continual access to the target BIG-IQ system without performing another authenticated login. This procedure uses the jq utility to illustrate how the JSON formatted output with the F5 token is assigned to the shell environment variable.

To use this method, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To use the environment variable refresh token to exchange for a new access, use the following cURL command syntax:

    <TOKEN_VAR>=$(curl -ks -X POST -d "{'refreshToken': {'token':<REFRESHTOKEN_VAR>}}" https://<BIQ_IP>/mgmt/shared/authn/exchange|jq .token.token)

    In the previous syntax, note the following:

    • <TOKEN_VAR> refers to the shell environment variable name used to store the access token's refreshed value.
    • <REFRESHTOKEN_VAR> refers to the refresh token environment variable name.
    • <BIQ_IP> refers to the IP address (or hostname if it is resolvable) of the target BIG-IQ system that you are trying to access with the cURL command. If you are logged into the BIG-IQ system, you can direct the cURL commands to localhost.
    • /mgmt/shared/authn/exchange is the Authentication Login API.

For example:

Token=$(curl -ks -X POST -d "{'refreshToken': {'token':$RefreshToken}}" https://10.100.100.100/mgmt/shared/authn/exchange | jq .token.token)

Use the shell environment variable token to send iControl REST requests

To use the shell environment variable access token to send iControl REST requests to the BIG-IQ system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To use the shell environment variable token and send an iControl REST request, use the following cURL command syntax:

    curl -sk -H "X-F5-Auth-Token: <TOKEN_VAR>" https://<BIQ_IP>/<URI_PATH>/ | jq

    In the previous syntax, note the following:

    • <TOKEN_VAR> refers to the shell environment variable name used to store the access token.
    • <BIQ_IP> refers to the IP address (or hostname if it is resolvable) of the target BIG-IQ system that you are trying to access with the cURL command. If you are logged into the BIG-IQ system, you can direct the cURL commands to localhost.
    • <URI_PATH> refers to the URL path where you can access the BIG-IQ system objects.

For example:

curl -ks -H "X-F5-Auth-Token: $Token" https://10.100.100.100/mgmt/shared/diagnostics/device-stats| jq

You can continue to use the $Token variable until it is expired, at which point you have to log in again to store the new token with the environment variable, or use the valid refresh token to exchange for a new token.
