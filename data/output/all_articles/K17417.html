Issue

Error Message

err websso.1[<PID>]: 014d0049:3: <session_ID>: Invalid NTLM type 2 message received for SSO configuration '/<partition>/<object_name>' type:'ntlmv2'

In this error message, note the following:

  • <PID> is the process ID for the websso service
  • <session_ID> is the session ID associated with the authentication attempt
  • <partition> is the name of the partition where the NTLMv2 single sign-on (SSO) configuration is located
  • <object_name> is the name of the NTLMv2 SSO configuration object on the BIG-IP APM system

For example:

err websso.1[18156]: 014d0049:3: 3e88e0f4: Invalid NTLM type 2 message received for SSO configuration '/Common/NTLMv2_example' type:'ntlmv2'

Message Location

You may encounter this message in the following location:

  • The /var/log/apm file

Description

This message occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for NTLMv2 SSO.
  • The BIG-IP system receives an "HTTP 401 - Unauthorized" response from the backend server, which includes duplicate WWW-Authenticate: NTLM headers.

When the BIG-IP APM system is configured for NTLMv2 SSO, and a client requests a resource that requires NT LAN Manager (NTLM) authentication, the backend server normally responds to the BIG-IP APM system with an "HTTP 401 - Unauthorized" response and specifies NTLM in the WWW-Authenticate HTTP header field.  If the server response also includes a duplicate WWW-Authenticate: NTLM header, the BIG-IP APM system may cancel the authentication process; this is expected behavior. "HTTP 401 - Unauthorized" responses are only required to include a single WWW-Authenticate HTTP header for proper NTLM functionality.

Impact

The NTLM authentication process fails to complete, and users are prompted for credentials.

Recommended Actions

When configuring backend resources for NTLMv2 SSO with the BIG-IP APM system, you should configure servers to include a single WWW-Authenticate header in "HTTP 401 - Unauthorized" responses.
