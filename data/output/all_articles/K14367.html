Known Issue

The BIG-IP system continues to forward SIP messages to a pool member when the pool member is marked down. This issue occurs when all of the following conditions are met:

  • A virtual server is configured with a SIP profile
  • The SIP profile is configured with the Dialog Aware setting enabled
  • The pool member is marked down during an established SIP session

Enabling the Dialog Aware setting in the SIP profile allows the BIG-IP system to use information from the SIP dialog (typically Call-ID) and automatically forwards SIP messages belonging to the established SIP dialog to the selected pool member. When the selected pool member is marked down (either by a monitor or manually) during an established SIP session, the BIG-IP system continues to forward SIP messages from the client to the previously selected pool member instead of reselecting a new pool member.

Impact

The SIP session on the client may appear to hang even though it remains connected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H419209 on the Diagnostics > Identified > Medium screen.
  • The SIP session on the client may appear to hang even though it remains connected.
  • A packet capture on the affected traffic shows the system continues to forward SIP messages to the pool member that is marked down.

Workaround

To work around this issue, you can author an iRule to reselect a new pool member if the current pool member is marked down during an established SIP session, and associate the new pool member with the affected SIP virtual server. To do so, perform the following procedure:

Impact of workaround: The following iRule may not apply to all environments. F5 recommends you author an iRule that works best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. Enter a name for the iRule.

    For example:

    sol14367

  5. In the Definition box, author an iRule that appears similar to the following example, replacing <pool name> with the name of the affected pool:

    when LB_SELECTED {
        if {[LB::status pool <pool name> member [LB::server addr] [LB::server port]] eq "down"} {
            log local0. "pool member down"
            eval LB::reselect pool <pool name>
        }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. In the Resources column, click the Edit link for the affected SIP virtual server.
  9. Click Manage for the iRules section.
  10. Click the new iRule authored in step 3 from the Available list, and move it to the Enabled list.
  11. Click Finished.
