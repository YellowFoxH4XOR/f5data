Topic

You should consider using this procedure under the following condition:

  • You want to enable logging of login attempts for the Anti-Fraud profile.

Description

In BIG-IP Fraud Protection Service (FPS) 13.1.1.3 and 14.1.0.3, the Anti-Fraud profile includes logging settings that enables reporting of login attempts to third party platforms such as Splunk.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the Configuration utility.
  • You have administrative access to the command line.
  • You have the login page URL and the username parameter information on hand.
  • Optional: If you are sending logs to a remote high-speed log pool, you must ensure you have already configured the desired log pool before performing the procedures described in the next section.

Procedures

To configure logging of login attempts for the Anti-Fraud profile, you need to perform the following procedures:

  • Configure a login page URL in your Anti-Fraud profile
  • Create a new log destination
  • Create a new log publisher
  • Activate the Anti-Fraud logging settings using tmsh
  • Configure the Anti-Fraud logging settings
  • Change the encoding level
  • Enable login-attempt logging for an Anti-Fraud profile

Configure a login page URL in your Anti-Fraud profile

To configure a login page URL in your anti-fraud profile, you must add the URL and minimally define a parameter for a user name. If you like to have more details in the notification that includes login result status, then you would need to configure the Login Page properties. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Fraud Protection Service > Anti-Fraud Profiles.
  3. Select the profile you want to use.
  4. Under Anti-Fraud Configuration, select URL List.
  5. If there are existing URLs defined in your Anti-Fraud profile, select the URL that you want to set as the login page. If you want to create a new URL to be a login page, select Add. The Configuration utility displays the URL Configuration page.
  6. If you are creating a new URL, for URL Path, enter the URL you want to use (for example /myloginpage) . If you are using an existing URL, skip to the next step.
  7. Under URL Configuration, select Parameters.
  8. For Parameter Name, enter the username parameter information (for example myloginname) and select Add.
  9. Select the Identify as Username check box for the parameter you have added in the previous step.
  10. If you like to have more details in the notification that includes login result status, under URL Configuration, select Login Page Properties.
  11. Select the Yes check box for the URL is Login Page setting. The Configuration utility presents a list of options to validate that the login was successful. You must configure at least one of the options. If you configure more than one option, then all selected options must be met for the BIG-IP system to consider the login successful. Refer to the following list for information about these options:
    • For A string that should appear in the response body, enter a string that should appear in the successful response to the login URL.
    • For A string that should NOT appear in the response body, enter a string that should not appear in the successful response to the login URL.
    • For Expected HTTP response status code, select the Specify check box and enter the HTTP response status code that the server must return to the user upon successful login. Otherwise select None.
    • For Expected response header, enter a header name that the successful response to the login URL must match.
    • For Expected cookie name, enter a cookie name that the successful response to the login URL must include.
  12. Select Create if you are creating a new URL, otherwise select Save to save your changes.

Create a new log destination

You can create a log destination to specify that log messages are sent to a remote log server. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Logs > Configuration > Log Destinations.
  3. Select Create.
  4. For Name, enter a name for the new log destination.
  5. For Enter, select the kind of destination log server. Depending on the selection you make, additional controls are displayed.
  6. If you selected Remote High-Speed Log, you need to also choose an existing log pool. For information about the various methods for Distribution, refer to K17398: Configuring the High Speed Logging traffic distribution method.
  7. Select Finished to save your configuration.

Create a new log publisher

When you have completed configuring the new log destination, you must proceed to create a new log publisher that points to the remote log server via the newly configured log destination. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Logs > Configuration > Log Publishers.
  3. Select Create.
  4. For Name, enter in a name for the log publisher.
  5. For Log Destinations choose a publisher by moving one or more destinations from the Available list to the Selected list. In this case, choose the log destination configured from the previous procedure.
  6. Select Finished.

Activate the Anti-Fraud logging settings using tmsh

In order to use the Anti-Fraud Logging Settings, you need to activate the antifraud.riskengine.reportlogins database variable from the TMOS Shell (tmsh). To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to tmsh.
  2. Activate the Anti-Fraud logging settings using the database variable antifraud.riskengine.reportlogins by entering the following command:

    modify sys db antifraud.riskengine.reportlogins value enable

Configure the Anti-Fraud logging settings

You can now configure Anti-Fraud logging to specify the content of the messages that the system sends when there is a login attempt or when the Rate Limit Threshold is exceeded. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. After you enable the Anti-Fraud Logging Settings in the previous procedure, you must log out of the Configuration utility and log in again to be able to view the Anti-Fraud Logging Settings page.
  2. Go to Security > Fraud Protection Service > Anti-Fraud Logging Settings.
  3. You can customize the log message when there is a login attempt registered by entering the Message and choosing the relevant items from the Available Items list of Login Message setting.

    For example, you can enter There is a login attempt from, then select client_ip in the Available Items list and move it to create a customize log message template reading There is a login attempt from ${client_ip}. Alternatively, you can select items from Available Items and move them in sequential order to populate the Message.

  4. Similarly, you can customize the log message when the rate-limit threshold for login attempts is exceeded by entering in the Message and choosing the relevant items from the Available Items list of the Rate-Limit Exceeded Message setting. Alternatively, you can select items in Available Items and move them in sequential order to populate the Message.
  5. For Rate-Limit Threshold, set the maximum number of messages that can be sent per-second per-virtual-server (for a single TMM). You can choose Unlimited to send messages for all login attempts without restrictions; however this may subject the device to potential DDoS attack. F5 recommends that you limit the number of messages that can be sent.
  6. Select Save to save your changes.

Change the encoding level

The BIG-IP FPS system supports three encoding levels for the log messages:

  • 0: NEVER, no encoding is used. This is the default value.
  • 1: MINIMUM, only selected fields that are not always alphanumeric are encoded (for example, URL, user-agent, and cookies).
  • 2: MAXIMUM, all fields are encoded, except pure alphanumeric values.

You can change the default encoding level by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh.
  2. You can change the encoding level for the log messages using the following command syntax:

    modify sys db antifraud.internalconfig.number2 value <0/1/2>

    For example, to change the encoding level to level two, enter the following command:

    modify sys db antifraud.internalconfig.number2 value 2

Enable login attempt logging for an Anti-Fraud profile

You can now enable login-attempt logging for an Anti-Fraud profile. You must perform this procedure for every Anti-Fraud profile for which you want to enable login-attempt logging. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Fraud Protection Service > Anti-Fraud Profiles.
  3. Select the Anti-Fraud profile you want to use.
  4. Under Anti-Fraud Configuration, select General Settings.
  5. For Log Publisher select the publisher you want to use.
  6. Select Save.
