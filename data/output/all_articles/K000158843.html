K000158843: mcpd down - Unable to encrypt application variable in SNMP config

Published
2025-12-18
Updated
2025-12-18
Applies to

  • BIG-IP DNS: 17.1.3
Source

Description

mcpd down 12 hours after making changes to SNMP objects

Environment

BIG-IP with SNMP trap configuration.

The ltm log will include:

Dec 11 07:59:23 peer-11-1.lab.local err mcpd[9404]: 0107102b:3: Master Key decrypt failure - decrypt failure - final
Dec 11 07:59:23 peer-11-1.lab.local notice mcpd[9404]: 01071029:5: Master decrypt final
Dec 11 07:59:23 peer-11-1.lab.local notice mcpd[9404]: 01071027:5: Master key OpenSSL error: 140266802468704:error:02001002:system library:fopen:No such file or directory:bss_file.c:175:fopen('','r')
Dec 11 07:59:23 peer-11-1.lab.local notice mcpd[9404]: 01b00001:5: Processed value is empty: class name (trapsess) field name ()
Dec 11 07:59:23 peer-11-1.lab.local err mcpd[9404]: 01071684:3: Unable to encrypt application variable (/Common/nameofthingtwo auth_password trapsess /Common/snmpd).

Note that this log is an indicator of a general problem that may not be due to the specific cause discussed in this solution article.

Cause

It is possible to send a base64 encoded string when creating the trap the config, for example:

# tmsh modify sys snmp communities replace-all-with { nameofthingone { community-name NSMmonitoring } } traps replace-all-with { nameofthingtwo { security-name NSMmonitoring privacy-protocol aes security-level auth-privacy auth-protocol sha version 3 host 192.0.2.1 privacy-password blah auth-password $M$dQ$Ey5j/ACKg1aaynT6DQ11/ww= } }

$M$dQ$Ey5j/ACKg1aaynT6DQ11/ww= is interpreted as literal string when it is added to the config, but when the string is later re-read the syntax indicates it is a base64 string and the BIG-IP attempts to decode it using its master key. Since this base64 string was not generated by the BIG-IP, the master key cannot decode the string and config validation fails.

In other words, the config is accepted but the next time the config is read, mcpd can't start because the BIG-IP tries to read and decode the input password as base64.

This will also immediately negatively impact the HA peer when the config is synchronized.

Recommended Actions

Do not attempt to use base64 encoded password strings when configuring SNMP traps.
