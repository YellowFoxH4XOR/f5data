Known Issue

The BIG-IP system does not use TCP Slow-Start congestion avoidance when serving objects from cache.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses a TCP virtual server with a Web Acceleration profile configured to cache objects.
  • Your BIG-IP system serves objects from cache for the TCP virtual server.

The TCP Slow-Start congestion avoidance option is enabled, by default, in the TCP profile and causes the system to use larger initial window sizes, as specified in RFC 3390: Increasing TCP's Initial Window, to help reduce roundtrip times. TCP Slow-Start congestion avoidance is a method of assigning the appropriate amount of data to a link without overloading the link, to help prevent the system from dropping packets. However, as a result of this issue, when serving objects from cache, the system does not use Slow-Start congestion avoidance, which may cause an increase in network congestion.

Impact

The BIG-IP system may experience excessive network congestion that can result in a traffic outage.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H446726 on the Diagnostics > Identified > Medium page.
  • The BIG-IP system experiences excessive network congestion that can result in a traffic outage.
  • In the /var/log/webui.log file, you notice error messages similar to the following example:

    err mcpd[5033]: 01070668:3: The amount of cache memory assigned to Web Acceleration profiles (705MB) exceeds the maximum amount (400MB) defined by Ramcache.MaxMemoryPercent (50)
