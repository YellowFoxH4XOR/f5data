Intermittent issue with BIG-IP management access (CLI and GUI), but ping works fine

Description

Intermittently unable to access BIG-IP via GUI or CLI (SSH).

When issue occurs, GUI does not load at all. SSH works, but unable to log in with access denied message.

Environment

  • iSeries
  • Management access

Cause

These symptoms are typically caused by an IP address conflict with the SSH server used by AOM.
In this case, users are still able to access SSH, but they can't log in ("access denied"), because the AOM will have a specific user defined.

Recommended Actions

To confirm if the AOM SSH server conflicts with the management IP, connect to the AOM menu via console, and use the I option.

Example showing the AOM SSH server is disabled:

AOM Command Menu:
B --- Set console baud rate
I --- Display platform information
P --- Power on/off host subsystem
R --- Reset host subsystem
N --- Configure AOM network
S --- Configure SSH Server
A --- Reset AOM
Q --- Quit menu and return to console
 
 
Enter Command: I
 
Host subsystem information:
    ...
 
Firmware versions
    ...
 
AOM Management Network Configuration
    IPv4 Address              : 0.0.0.0 (Unspecified)   <--- Not configured in this case
    IPv4 Address Subnet Mask  : 0.0.0.0
    IPv4 gateway              : 0.0.0.0
    MAC Address               : f4:15:63:51:bc:80
    SSH session idle timeout  : 600 (seconds)

If there is a conflict with the management IP used within TMOS, change the IP.
If you do not want to use the AOM SSH server, set the IP to 0.0.0.0.

Additional Information

When troubleshooting this issue in a packet capture, if the Server: Protocol packet contains a string similar to "SSH-2.0-OpenSSH_6.0p1 Debian-4+deb7u3" this means the connection is going to the AOM and not the Host.  A BIG-IP host would look something like "SSH-2.0-OpenSSH_7.4".

 

Intermittent management access can have numerous root causes. Further troubleshooting may be required if there is no conflict with the AOM SSH server.
