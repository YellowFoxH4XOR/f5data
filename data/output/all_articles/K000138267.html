Description

If there is no proxy in the path from client to the BIG-IP ASM, then the ASM event log shows the "Source IP Address" as the real source IP address.

While in the real world, one or more proxies probably exist in the middle. By default, the ASM event log shows the "Source IP Address" as the last IP address when there is the X-Forwarded-For header in the request. It makes you can not obtain the original source IP address (The first IP address in the HTTP request header X-Forwarded-For list) of the remote client. For example with following traffic flow:

  • Scenario 1:

Client (192.168.10.10) ---> Proxy (172.16.10.11) ---> BIG-IP ASM

  • Scenario 2:

Client (192.168.10.10) ---> Proxy 1 (172.16.10.11) ---> Proxy 2 (172.16.10.12) ... Proxy N-1 (10.10.10.13)---> Proxy N (10.10.10.14) ---> BIG-IP ASM

The X-Forwarded-For header in the request when it arrives at ASM shows as:

  • Scenario 1:

X-Forwarded-For: 192.168.10.10, 172.16.10.11

  • Scenario 2:

X-Forwarded-For: 192.168.10.10, 172.16.10.11, 172.16.10.12, ... , 10.10.10.13, 10.10.10.14

The ASM event log shows the "Source IP Address" as:

  • Scenario 1: 172.16.10.11

  • Scenario 2: 10.10.10.14

Environment

  • BIG-IP ASM

  • ASM Event Log

  • X-Forwarded-For

Cause

None

Recommended Actions

  • If there is only one proxy in the middle like scenario 1, please enable the "Trust XFF Header" in the ASM policy, then the "Source IP Address" in the ASM event log will be 192.168.10.10

  • If there are multiple proxies in the middle like scenario 2, please enable the "Trust XFF Header" in the ASM policy, and attach following iRule to the virtual server, then the "Source IP Address" in the ASM event log will be 192.168.10.10

when HTTP_REQUEST {
    if { [HTTP::header exists "X-Forwarded-For"] } {
        set original_ip [getfield [HTTP::header "X-Forwarded-For"] "," 1]
        HTTP::header replace "X-Forwarded-For" $original_ip
    }
}

Additional Information

Enable the "Trust XFF Header" in the ASM policy makes the "Source IP Address" in the ASM event log shows as the second-to-last address in the X-Forwarded-For header.

For example, the "Source IP Address" in the ASM event log will be 10.10.10.13 in scenario 2 when the "Trust XFF Header" is enabled and without the iRule attached to the virtual server.
