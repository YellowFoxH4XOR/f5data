Description

HTTPs monitor fails to send SNI extension field configured in the Server SSL profile attached to the monitor.

On a packet capture of the monitor traffic, you cannot see the server_name extension in the Client Hello Handshake Protocol details.

Environment

  • In-tmm monitor is enabled
  • Server-name field configured on Server SSL profile attached to monitor
  • Monitor on non-default Route Domain

Cause

Bug ID 944121: Missing SNI information when using non-default domain https monitor running in tmm mode

Recommended Actions

To mitigate the issue, upgrade to the fixed versions listed in ID 944121. To workaround the issue on affected versions, you can configure the monitor on the default Route Domain, RD0.

Additional Information

Even though you cannot see the SNI field on a monitor packet capture when this issue is present, you can test with curl command to access the server with SNI, and the connection should be successful and show the SNI field as below:
