Description

You may encounter log messages from the clusterd process in the /var/log/ltm file related to blade failures or changes in the cluster primary blade status.

Two common messages are:

1. err clusterd[6259]: 013a0014:3: Blade 1: blade 2 FAILED
This indicates the primary blade (Blade 1) reports that a peer blade (Blade 2) has failed and is unable to join the cluster.

2. notice clusterd[7154]: 013a0024:5: Blade 2: Changing primary from 1 to 2 (self)
This indicates that Blade 2 is assuming primary status from Blade 1.

These messages reflect cluster membership status and leadership changes within a VIPRION or vCMP chassis environment and are generated by the clusterd process that manages blade synchronization.

Environment

  • BIG-IP systems with a multi-blade cluster configuration (VIPRION or vCMP)
  • Systems using the clusterd process to manage intra-cluster communication.                                                                                                                                                                   
  • Log file: /var/log/ltm

Cause

These messages occur under different conditions:

Blade Failure Message (013a0014:3):
A cluster member has transitioned to Slot State FAILED, OR

The clusterd process is not receiving packets from peer cluster members on the management backplane.

Primary Change Message (013a0024:5):

The cluster has elected a new primary blade due to status transition, restart, or health condition of the previous primary.

Recommended Actions

For Blade Failure (FAILED status):

On the afflicted cluster member, issue the following command to attempt rejoining the cluster:
bigstart restart clusterd

Check the current cluster status using:
tmsh show sys cluster

If the partition on the management backplane has dissolved before clusterd restarts, the failed blade should rejoin the cluster normally.

For Primary Blade Status Change:

No action required. This is a routine notification and does not indicate an issue unless accompanied by failure messages or other symptoms.


Additional Information

1. <PID> in log messages refers to the process ID of the clusterd process.
2. These messages are informational, but a blade in FAILED status will remain unavailable until it successfully rejoins the cluster.

Message severities:

  • err level (e.g., 013a0014:3) signals a failure.
  • notice level (e.g., 013a0024:5) signals a status change with no functional impact.
  • Common locations to check: /var/log/ltm
