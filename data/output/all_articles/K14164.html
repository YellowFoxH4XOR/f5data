Known Issue

The BIG-IP system may fail to perform a ConfigSync after you modify the iApp configuration on a device group member.

This issue occurs when all of the following conditions are met:

  • You have an iApp Template and an associated iApp Application Service configured on a synchronized device group.
  • You perform a sequence similar to the following:

    • You delete an iApp Application Service on a device group member (Host A).
    • You create a new iApp Application Service on Host A, referencing the same iApp Template.
    • A second device group member (Host B) becomes the synchronization leader. This can happen if you make any small change to the BIG-IP configuration on this system.

      Note: For more information on setting synchronization leaders, please refer to K13887: Forcing a BIG-IP device group member to initiate a ConfigSync operation.

    • You attempt to push the Host B configuration to other hosts in the device group using ConfigSync.

Impact

You are unable to perform a ConfigSync and hosts within a device group have inconsistent configurations.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • From the BIG-IP Configuration utility of the system on which you are initiating the ConfigSync (Host B), you see an error that appears similar to the following:

    [sync error on /Common/host1.f5.com]: Load failed from /Common/host2.f5.com 01070710:3: Database error (13), Can't save/checkpoint DB object, class:app_instance_object status:13 - EdbCfgObj.cpp, line 122

  • In the /var/log/ltm file of the standby system to which you are attempting to perform a ConfigSync (Host A), you see an error that appears similar to the following example:

    err mcpd[<pid>]: 01071488:3: Remote transaction for device group /Common/device-group-failover-8e727da60f61 to commit id 17 5838882393943487379 /Common/host2.f5.com failed with error 01070710:3: Database error (13), Can't save/checkpoint DB object, class:app_instance_object status:13 - EdbCfgObj.cpp, line 122..

Workaround

To work around this issue, you can delete the newly-created iApp application on the receiving system (Host A). To do so, perform the following procedure:

Impact of workaround: None

Note: Due to a change in behavior between BIG-IP 11.2.0 and 11.2.1, when you attempt to overwrite a configuration with a newer timestamp, you may need to follow the steps in K13887: Forcing a BIG-IP device group member to initiate a ConfigSync operation to perform a ConfigSync on 11.2.0 systems.

  1. Using the Configuration utility of the receiving system (Host A), navigate to iApp > Application services.
  2. Delete the iApp application that has been modified.
  3. On the sending system (Host B), navigate to Device Management > Device Groups.
  4. Select your device group.
  5. Click Config-Sync.
  6. To perform a ConfigSync, select Synchronize to Group.
