Known Issue

After you modify the SSL Profile setting on an HTTPS monitor on a BIG-IP device in a high availability (HA) configuration and perform a full configuration synchronization (ConfigSync), the SSL Profile setting for the HTTPS monitor on the peer unit(s) may not update.

This issue occurs when all of the following conditions are met:

  • You use an HTTPS monitor in an HA configuration.
  • You modify the SSL Profile setting on an HTTPS monitor on your BIG-IP system.
  • You perform a full ConfigSync to propagate the SSL Profile setting change to a peer device.

Impact

After a failover event, virtual servers using HTTPS monitors may not behave as expected because the monitors are not identically configured.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The SSL Profile setting for the HTTPS monitor on the peer unit does not update, and the BIG-IP system and its peer device erroneously report themselves as being in-sync when they have different HTTPS monitor configurations.

Workaround

To work around this issue, you can disable In-TMM monitors and configure the individual SSL attributes (cipherlist, key, cert, and compatibility) directly within an HTTPS monitor by manually editing the /config/bigip.conf file to replace the Server SSL profile. To do so, perform the following procedures:

  • Disabling In-TMM monitoring
  • Editing the /config/bigip.conf file to replace the Server SSL profile

Disabling In-TMM monitoring

Impact of workaround: Disabling In-TMM monitors may have a performance impact on your BIG-IP system. F5 recommends that you perform this procedure during a scheduled maintenance period.

To disable In-TMM monitoring, refer to K11323537: Configuring In-TMM monitoring.

Editing the /config/bigip.conf file to replace the Server SSL profile

Impact of workaround: Editing the /config/bigip.conf file and performing a manual configuration load disrupts service. F5 recommends that you perform this procedure during a scheduled maintenance period.

Note: SSL attributes may generate deprecation warnings and are not visible in the Configuration Utility, but the configuration still takes effect.

  1. Log in to the BIG-IP command line.
  2. To make a copy of the /config/bigip.conf file, type the following command:

    cp /config/bigip.conf /config/bigip.conf.K74431483

  3. Use a text editor to edit the /config/bigip.conf file.
  4. Locate the affected HTTPS monitor. For example, the following HTTPS monitor has the example serverssl profile associated to it:

    ltm monitor https /Common/example_https {
        adaptive disabled
        defaults-from /Common/https
        destination *:*
        interval 5
        ip-dscp 0
        recv none
        recv-disable none
        send "GET /\r\n"
        ssl-profile /Common/example_serverssl
        time-until-up 0
        timeout 16
    }

    Note: Track the SSL attributes of the example serverssl profile.

  5. Remove the serverssl profile from the HTTPS monitor and configure the individual SSL attributes noted in step 4. For example, the following monitor specifies the certificate, cipherlist, compatibility, and key attributes.

    ltm monitor https /Common/example_https {
        adaptive disabled
        cert /Common/default.crt
        cipherlist DEFAULT:+SHA:+3DES:+EDH
        compatibility enabled
        defaults-from /Common/https
        destination *:*
        interval 5
        ip-dscp 0
        key /Common/default.key
        recv none
        recv-disable none
        send "GET /\r\n"
        time-until-up 0
        timeout 16
    }

  6. Save the changes and exit the text editor.
  7. To reload the configuration using the TMOS Shell (tmsh), type the following command:

    tmsh load /sys config

For more information, refer to K51131340: SSL settings used by an HTTPS monitor are now configured using a Server SSL profile
