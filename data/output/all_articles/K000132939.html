K000132939: [F5OS] Restoring an F5OS configuration backup may restore an older version of a BIG-IP Tenant

Type
Support Solution
Published
2023-03-13
Updated
2024-04-26
Applies to
  • F5OS
  • F5OS-C
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000132939

Description

When following K47512994 to restore the configuration for an F5OS-A deployment on an rSeries system, additional steps may be required to restore the tenants to the desired version they were on.

 

When an F5OS configuration backup is created, the tenant image version in the configuration file is the version the tenant was initially deployed with, not the current or latest version it is on. If one later updates a tenant to a higher or different version, that is not included in the F5OS configuration file.

 

As a result, when one restores an F5OS configuration file, it will restore the tenant's initial image version, requiring one to then manually upgrade to the desired version the BIG-IP tenant was on.

 

For example,

1. Initially deploy a tenant as 15.1.5.

2. Upgrade the tenant to 15.1.8

3. Create an F5OS configuration backup.

Later on,

4. Restore the F5OS configuration

5. The tenant's image that is to be deployed will be 15.1.5 (initial image version) instead of 15.1.8 (desired version).

6. A manual upgraded is then needed from 15.1.5 to 15.1.8 prior to tenant UCS configuration restoration.

 

Environment

* F5OS-A deployment on an rSeries system.

* Tenant(s) deployed on an initial version, then later upgraded to a different/higher version.

* F5OS restoration to be done.

 

Cause

The F5OS configuration backup contains the configuration and transactions that happened within F5OS itself. Since the upgrade is performed within the tenant, F5OS configuration is not updated with the tenant’s upgraded version. Currently F5 supports only the following ways to have a tenant with a new version:

  • Deploy a new tenant with a new version OR
  • Perform an upgrade within the tenant

Recommended Actions

Step 5 above can be skipped, allowing the F5OS restoration to directly deploy the tenant with the desired version (15.1.8 in the above example). This can be done by editing the configuration backup file and updating the <image> version from the original to the desired one.

 

* Edit the F5OS configuration backup file using your favourite editor. For example,

# vim myF5OSBackup.dms

* Search for your tenant's configuration by its name, in our example snippet below, the tenant's name is myBigIP1

<tenants xmlns="http://f5.com/yang/tenants">
   <tenant>
     <name>myBigIP1</name>
     <config>
       <name>myBigIP1</name>
       <tenantID>6</tenantID>
       <unit-key>xxx</unit-key>
       <unit-key-hash>xxx</unit-key-hash>
       <tenant-op>provisioned</tenant-op>
       <type>BIG-IP</type>
       <image>BIGIP-15.1.5.1-0.0.14.ALL-F5OS.qcow2.zip.bundle</image>
       <nodes>1</nodes>
       <mgmt-ip>10.xxx.xxx.xxx</mgmt-ip>
       <prefix-length>24</prefix-length>
       <gateway>10.xxx.xxx.xxx</gateway>
       ...<snip>
   </tenant>

 

* Update the <image> line to reflect the updated or desired QCow2 zip bundle version of your tenant. In the example above, 15.1.8 would be

BIGIP-15.1.8-0.0.7.ALL-F5OS.qcow2.zip.bundle

* Repeat if necessary with any other tenants to be deployed, if available.

* Save the updated configuration file, and upload it into the F5OS platform to be loaded onto.

Note: Please ensure to enter the correct zip.bundle file name into the <image> section, and ensure to have the bundle image uploaded to the F5OS platform prior to restoring the F5OS configuration file.
