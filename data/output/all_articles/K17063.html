Topic

Purpose

You should consider using this procedure under the following condition:

  • You would like to retrieve the User Principal Name (UPN) from the certificate's Subject Alternative Name (SAN) and populate the associated value to a session variable (for example, session.logon.last.upn) for use during access policy evaluation.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have administrative access to the BIG-IP APM Configuration utility.
  • You must be familiar with the BIG-IP APM visual policy editor.
  • You must be familiar with BIG-IP APM session variables.
  • Your access policy uses a Client Cert Inspection or an On-Demand Cert Auth action to verify validity of the client certificate.
  • The client certificate contains an x509 extension SAN of type otherName:UPN.

Description

The BIG-IP APM access policy provides the ability to incorporate Client Cert Inspection and the On-Demand Cert Auth agents that validate client certificates.

You can use these agents to allow passwordless authentication. Additionally, when used with Kerberos SSO, the client’s UPN can be derived from the certificate presented by the client when accessing the BIG-IP APM access profile.

Certificates that use the x509 extension may contain additional fields such as the SAN field type of otherName:UPN, which corresponds to the UPN value.

When the BIG-IP APM Client Cert Inspection and the On-Demand Cert Auth agents are used to validate a x509 client certificate, all fields from the x509 extension are populated into session variable session.ssl.cert.x509extension.

You can extract the UPN value from the session variable string of the session.ssl.cert.x509extension using the following procedure.

Procedures

Extracting the UPN value from the certificate SAN

You can extract the UPN from a client certificate's SAN in an Access Policy that uses a Client Cert Inspection or an On-Demand Cert Auth action. To do so, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Profiles > Access Profiles List.
  3. To the right of the name of the access policy to edit, click Edit.
  4. On the Successful branch of the Client Cert Inspection or On-Demand Cert Auth action, click the (+) symbol.
  5. In the Assignment section, select Variable Assign.
  6. Click Add Item.

    The Variable Assign properties pop-up screen displays.

  7. In the Name field, type a name for the Variable Assign action.

    For example: 

    Extract SAN

  8. Click Add new entry.
  9. Click the change link.

    A new pop-up screen displays.

  10. In the Custom Variable section, type a name for your variable.

    For example:

    session.logon.last.upn

  11. In the Custom Expression section, enter the following expression to parse the value of variable session.ssl.cert.x509extension, and extract the UPN.

    set x509e_fields [split [mcget {session.ssl.cert.x509extension}] "\n"]; 
    # For each element in the list: 
    foreach field $x509e_fields { 
    # If the element contains UPN:
    if { $field contains "othername:UPN" } { 
    ## set start of UPN variable 
      set start [expr {[string first "<" $field] +1}] 
    # UPN format is <user@domain> 
    # Return the UPN, by finding the index of opening and closing brackets, then use string range to get everything between. 
      return [string range $field $start [expr { [string first ">" $field $start] - 1 } ] ];  } } 
    # Otherwise return UPN Not Found: 
    return "UPN-NOT-FOUND";

  12. Click Finished.
  13. Click Save.

Extracting username and domain from UPN (Optional)

In addition, depending of your implementation, you can also extract the username and domain from the previously retrieved UPN (session.logon.last.upn). To do so, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In the visual policy editor, click the name (Extract SAN) of the previously created Variable Assign action.
  2. Click Add new entry.
  3. Click the change link.

    A new pop-up screen displays.

  4. In the Custom Variable section, type a name for the username variable.
    For example:

    session.logon.last.username

  5. In the Custom Expression section, enter the following expression to parse the value of variable session.logon.last.upn, and extract the username. 
    set upn [mcget {session.logon.last.upn}]; 
# if $upn contains @ symbol, extract the username, otherwise return $upn as-is. 
if { $upn contains "@" } { 
# Use string first to find index of the @ symbol, then return everything in-front of the @. 
  return [string range $upn 0 [expr { [string first "@" $upn] - 1 } ] ]; } else { 
# Assume UPN only contains a username 
  return $upn; 
}
  6. Click Finished.
  7. Click Add new entry.
  8. Click the change link.

    A new pop-up screen displays.

  9. In the Custom Variable section, type a name for the domain variable.
    For example:

    session.logon.last.domain

  10. In the Custom Expression section, enter the following expression to parse the value of variable session.logon.last.upn, and extract the username.

    set upn [mcget {session.logon.last.upn}];
    # if $upn contains @ symbol, extract the username, otherwise return $upn as-is.
    if { $upn contains "@" } {
    # Use string first to find index of the @ symbol, then return everything behind the @.
      return [string range $upn [expr { [string first "@" $upn] + 1 } ] end ]; } else {
    # Otherwise return an admin defined default domain:
      return "DEFAULT-DOMAIN-HERE";
    }

  11. Click Finished.
  12. Make sure the expression assigning session.logon.last.upn from session.ssl.cert.x509extension is on top of the list, by moving the arrow button on the left up.
  13. Click Save.
  14. Click Apply Access Policy.
  15. Click Close.

Additional Information

Custom Expression syntax

The custom expression in this article includes several elements, including the mcget statement, the x509 extension, and the expr and return functions.

Note: The Custom Expression field is a simple text block. It optionally supports line breaks and spacing, although these are not recommended. Each line of code must end with a semicolon.

Message cache get (mcget) statement

The following is the command syntax of the mcget statement:

[mcget {session.ssl.cert.x509extension}]

mcget allows access to session variables from inside branch rules. In this example, it returns the data inside the session.ssl.cert.x509extension variable. The data in the session populates when BIG-IP APM receives a client certificate.

x509 extensions

The x509 extensions are a long list of attributes separated by newline characters.

You can break the list using the Tcl [split] command and then run through the list with a foreach loop.

In each line of the x509 extensions, if the line contains othername:UPN, use a set of string commands to extract this value and return it. That returned value is assigned to the arbitrary session.logon.last.upn session variable. It is also defined on the left side of the Variable Assignment policy item. If othername:UPN is not found, the code returns “UPN-NOT-FOUND”.

expr and return

Each branch rule contains one or more expression (expr) or return commands. The expr command functions as a Boolean operator. When it returns true for an input value, the policy follows the branch. When it returns false, the policy follows the next available branch. This continues until the policy reaches the fallback branch. If more than one branch returns true, the first true policy path executes.

The expr command is the same one used in Tcl math, so the following expression works:

expr { 10/5 == 2 }

You can use expr to output a value for variable assignment. For example:

session.custom.count = expr { [mcget {session.custom.count}] + 1 }

The return operator returns a values from the message cache using the mcget command:

return [mcget {session.logon.last.username}]
