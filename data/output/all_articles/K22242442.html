Description

While using the NativeRDP features that come with BIG-IP APM, users' sessions may be hosted to the wrong (or unexpected) RDSH machines.
This can typically when the existing session is being disconnected -> while reconnecting within seconds, the new session does not resume the previous one: previous work is lost and it opens a fresh new session:

  • this does mean the new session is open on a different remote host than for the previous session.

Environment

  • You're using BIG-IP APM;
  • It's configured with "Remote Desktop Web Access" (a.k.a RemoteApps) from the NativeRDP objects;
  • The Virtual Server is configured with an MSRDP persistence profile
  • The MSRDP persistence profile is set with "Has Session Broker" enabled/selected.
Cause

Before Windows 2012 R2, the BIG-IP could see the text "Cookie: msts=xxxxxxx" or "Cookie: mstshash=xxxxxxxx" in the actual RDP first segment of data sent by the client, and MSRDP persistence used this info to select the correct RDSH server for that connection.
Starting with windows 2012 R2 servers, this data is encrypted, and the BIG-IP can no longer see this plaintext cookie in the traffic.
As such, our MSRDP persistence started breaking after RDP started using encryption.

Recommended Actions

F5 Networks recommends choosing the "source IP" persistence profile, instead of the MSRDP one.
