Known Issue

The BIG-IP system may not count HTTP persistent requests toward the Maximum Requests setting.

This issue occurs when all of the following conditions are met:

  • An HTTP profile with a custom Maximum Requests value is in use
  • The HTTP::redirect or HTTP::response iRules commands generate responses for HTTP persistent requests

The Maximum Requests setting in the HTTP profile specifies the allowed number of HTTP requests per connection (also referred to as HTTP persistence). The BIG-IP system closes connections once this limit is reached. The BIG-IP system does not count client-side requests processed by the HTTP::redirect or HTTP::response iRules commands toward the configured maximum requests value. As a result, if the HTTP::redirect or HTTP::respond iRules commands are the only response to the requests for the connection, the connection could remain open regardless of the Maximum Request setting.

Impact

HTTP persistent connections to affected virtual servers could remain open longer than anticipated.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • F5 iHealth lists Heuristic H430122 on the Diagnostics > Identified > Medium screen.
  • An increase in long-lived connections in statistics
  • An increase in memory utilization
  • In the /var/log/ltm file, you may observe messages that appear similar to the following example:

    notice tmm[14734]: 01010029:5: Clock advanced by 303 ticks

Workaround

To work around this issue, you may be able to use the HTTP::close command or similar functionality in the iRule to close the connection after a predetermined number of requests. For more information about HTTP iRules commands, refer to the HTTP command list on F5 Cloud Docs.
