Topic

You should consider using this procedure under the following conditions:

  • You want to change the minimum IP fragment size that your BIG-IP system accepts.

Description

Beginning in BIG-IP 11.4.0, as part of the firewall integration, F5 introduced the tm.minipfragsize BigDB variable. You can use this database variable to modify the minimum IP fragment size that the system accepts, which affects packets that have the More Fragments (MF) flag set to 1. When the payload length of an IP packet with MF set to 1 is below the value of the tm.minipfragsize BigDB variable, the IP packet is dropped. Because this functionality only applies to packets with the MF flag set to 1, this does not apply to packets which are the final fragment in an IP datagram or unfragmented IP datagrams. You may experience traffic disruption after an upgrade to BIG-IP 11.4.0 or later; the disruption may be the result of this BigDB variable having a value that is not suitable for the application environment.

Note: The tm.minipfragsize BigDB variable applies to the payload length of an IP packet only and does not include IP header size.

  • You can view the following tmsh list sys db tm.minipfragsize all-properties command output to view the current default value, and the minimum and maximum range of values.

    For example:

    13.0.0 and later:

    sys db tm.minipfragsize {    
        default-value "552"    
        scf-config "true"    
        value "552"    
        value-range "unsigned integer min:1 max:65512"
    }

    12.0.0 - 12.1.5:

    sys db tm.minipfragsize {
        default-value "552"
        scf-config "true"
        value "552"
        value-range "unsigned integer min:1 max:65515"
    }

    11.6.0 through 11.6.5:

    sys db tm.minipfragsize {
        default-value "556"
        scf-config "true"
        value "556"
        value-range "unsigned integer min:1 max:65515"
    }

    11.5.0 - 11.5.10:

    sys db tm.minipfragsize {
        default-value "576"
        scf-config "true"
        value "576"
        value-range "unsigned integer min:24 max:65535"
    }

    11.4.0 - 11.4.1:

    sys db tm.minipfragsize {
        default-value "576"
        scf-config "true"
        value "576"
        value-range "unsigned integer min:0 max:65535"
    }

    Note: The default-value, value, and value-range may vary across BIG-IP versions.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have administrative access to the TMOS Shell (tmsh).

Procedures

Modify default IP fragment size settings

To change the value of the tm.minipfragsize BigDB variable to your desired value, perform the following procedure:

Impact of procedure: F5 recommends that you do not modify the default value of the tm.minipfragsize BigDB variable, because lowering the value may expose your BIG-IP system to the IP Fragment Too Small or IP Fragmentation exploits. By lowering the default IP fragment size, you may be exposing your BIG-IP system to denial-of-service (DoS) attacks, and hence, you should consider changing the default IP fragment size setting only if your BIG-IP system is dropping packets that are smaller than the default IP fragment size, for example, 64 byte Encapsulating Security Payload (ESP) packets in a Virtual Private Network (VPN) tunnel configuration.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To change the value of tm.minipfragsize BigDB variable, type the following command:

    modify sys db tm.minipfragsize value <NewValue>

Note: The change to the BigDB variable takes effect immediately, without requiring a restart of the BIG-IP system or a reload of the configuration.
