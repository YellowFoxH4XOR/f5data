Known Issue

The Traffic Management Shell (tmsh) does not process certain characters correctly in the health monitor Send String or Receive String.

This issue occurs when the following condition is met:

  • You use tmsh to configure a health monitor with a Send String or Receive String that contains one of the following character combinations:
    • A backslash and a question mark (\?) character
    • A backslash and a left bracket (\[) character

Impact

The health monitor may incorrectly mark a pool member down.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The configuration save or load operation completes successfully. However, you may notice subsequently that the affected monitor has the Send String or Receive String with the backslash and question mark or backslash and left bracket characters translated into a literal question mark (?) or a literal left square bracket ([). The erroneous translation may cause the health monitor to incorrectly mark a pool member down.

    For example, the Receive String of the affected health monitor may appear similar to the following example:

    path\?test

    However, the tmsh list ltm monitor& command shows the Receive String similar to the following example:

    path?test

Workaround

To work around this issue, instead of using the backslash to escape the question mark or left bracket, you can enclose those characters with opening and closing brackets ([ ]).

Note: This workaround is not valid for send strings.

For example:

[?] or [[]

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
