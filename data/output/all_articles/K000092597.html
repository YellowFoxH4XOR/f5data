K000092597: BIG-IP returning chunked and compressed response with invalid content

Type
Support Solution
Published
2022-11-10
Updated
2022-11-10
Source
https://my.f5.com/manage/s/article/K000092597

Description

BIG-IP is returning a chunked and compressed response with additional data at the beginning of the payload.

In the case of response types with strict syntax requirements, such as JSON, this may break application functionality.

For example:

HTTP/1.1 200 OK
Cache-Control: no-cache,must-revalidate,max_age=0,no-store,private
X-XSS-Protection: 1; mode=block
Pragma: no-cache
X-FRAME-OPTIONS: SAMEORIGIN
Connection: keep-alive
Vary: Accept-Encoding
Last-Modified: Tue Sep 27 16:00:15 CEST 2022
X-Content-Type-Options: nosniff
Content-Type: application/json;charset=UTF-8
Content-Encoding: gzip
Transfer-Encoding: chunked

1ee9                <--- Incorrect
{"test"
<...remainder of JSON response...>

Environment

  • BIG-IP version with the fix for ID902377
  • Rewrite or HTML profile
  • Compression profile

Cause

Bug ID 1155393: Failure to remove chunk headers from chunked response with Rewrite/HTML profile and compression

This issue happens when a pool member returns a chunked response that is eligible for compression.

The pool member's chunk headers are retained by the BIG-IP as part of the payload, when re-chunking and compressing the response to the client. This is invalid, as the chunk header is then presented to the application as part of the payload.

Given the example in the Description of this article, 1ee9 is the hexadecimal chunk header ASCII representation of a JSON response that is 7913 bytes in length.
This is not part of the payload.
After the client removes the BIG-IP's "outer" chunk headers, the 1ee9 remains, breaking application functionality.

Recommended Actions

Remove the compression profile from the virtual server, or modify the compression profile to ensure the response in question is no longer eligible for compression.

ID1155393 has no fixed version at the time of this article's publication.

An engineering hotfix may be requested by contacting F5 Support and referencing this article.
