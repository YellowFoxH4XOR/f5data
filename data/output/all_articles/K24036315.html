Known Issue

Hardware crypto queues may erroneously become unavailable under heavy load.

This issue occurs when the following condition is met:

  • You are using Secure Sockets Layer (SSL) hardware acceleration on one of the following platforms:
    • BIG-IP i4000  Series (C115)
    • BIG-IP i5000 Series (C119)
    • BIG-IP i7000 Series (C118)
    • BIG-IP i10000 Series (C116)
    • VIPRION B4400N blade, VIPRION B4450 blade (A114)

Note: A similar issue exists on other BIG-IP platforms. For more information, refer to K17554: Hardware SSL acceleration may cause the BIG-IP system to become unresponsive

Impact

The BIG-IP system may become unresponsive and fail over to a standby system if configured as part of a high availability (HA) system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • The BIG-IP system stops responding and fails to process traffic.
  • The BIG-IP system logs error messages in the /var/log/ltm file that appear similar to the following examples:

    notice tmm3[<pid>]: 01010029:5: Clock advanced by 1052 ticks
    crit tmm2[<pid>]: 01010025:2: Device error: crypto codec cn-crypto-2 queue is stuck.
    warning sod[<pid>]: 01140029:4: HA crypto_failsafe_t cn-crypto-2 fails action is failover.
    notice sod[<pid>]: 010c0052:5: Standby for traffic group /Common/traffic-group-1.
