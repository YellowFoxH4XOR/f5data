Known Issue

If you manually configure Active Directory forest trust relationships on the ARX system, or if the forest configuration changed after ARX joined the domain, CIFS clients from trusted domains may be unable to connect to CIFS shares on the ARX system. When this issue occurs, an error message that appears similar to the following example is logged to the ARX syslog:

Failed to obtain authentication credentials for host 'frv01$@US.EXAMPLE.COM' on behalf of principal 'ext01@UK.EXAMPLE.COM' at IP address 10.10.10.15 to CIFS service 'trl02.us.example.com'.
Switch does not have knowledge of domain 'UK.EXAMPLE.COM', which may be required in a multi-domain or multi-forest Active Directory environment.

F5 Product Development tracked this issue as ARX ID 38144 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.

This issue has been fixed in V5.1.5 Hotfix 2 issued for ARX version 5.1.5. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

Additionally, this issue has been fixed in a hotfix available for ARX version 5.0.6. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this article number and ARX ID 38144.

Workaround

You can work around this issue by removing and reconfiguring the forest configuration using the active-directory-forest and active-directory forest-trust commands. Once that is complete, re-join the ARX system to the domain using the domain-join command. For more information about the active-directory-forest, active-directory forest-trust, and domain-join commands, refer to the ARX CLI Reference Guide.
