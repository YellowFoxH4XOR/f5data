Installing or upgrading to F5OS-A 1.4.0 may cause multiple issues on the F5 rSeries hardware product

This issue occurs when one of the following conditions is met:

  • You upgrade your F5 rSeries hardware product from a version prior to F5OS-A 1.4.0 to F5OS-A 1.4.0.
  • You perform a bare-metal install on your F5 rSeries hardware product using F5OS-A 1.4.0.

These issues occur because the F5OS-A primary key is erroneously changed due to a race condition during installation. The primary key encrypts certain parts of the F5OS-A configuration including the following:

  • The TLS private key used by the F5OS-A api_svc_gateway service which the BIG-IP tenant platform_agent service connects to during its startup.
  • The BIG-IP tenant unit key.
  • Authentication, Authorization and Accounting (AAA) server credentials configuration.
  • Configured F5 iHealth portal credentials.

Impact

  • You are unable to login to the F5OS-A CLI or web UI using administrator account configured to authenticate remotely.
  • The deployed BIG-IP tenants are inoperable.
  • You are unable to upload a qkview to F5 iHealth portal from the rSeries hardware product using the configured iHealth credentials.

When these issues occurred, they will persist despite attempts to roll back to previous versions. Additionally, you may not be unable to restore the BIG-IP configuration on the BIG-IP tenant using a previously saved UCS archive. The only recovery action is to reset the F5OS-A system configuration including the deployed BIG-IP tenants.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Deployed BIG-IP tenants have reached the Running phase but their management address and data plane are inoperable. If you access the BIG-IP tenants using virtctl console, the tenants appear unlicensed, and the mcpd and chmand processes will not be running.
  • F5OS-A administrators using remotely authenticated accounts fail to access to the F5OS-A CLI or web UI.
  • Attempts to upload a qkview directly from the rSeries hardware product to F5 iHealth portal using the configured iHealth credentials fail.
  • You may observe the following error message repeatedly logged to the /var/F5/system/log/platform.log file:

    appliance-1 api-svc-gateway[9]: priority="Crit" version=1.0 msgid=0x5804000000000069 msg="gRPC Server failed to start, server ports will be inactive." TYPE="n/a".

  • You may observe the system_api_svc_gateway container restarting using the following command when you log in as the root user:

    [root@appliance-1 ~]# docker ps --filter 'Name=system_api_svc_gateway' --format "{{.Names}}: {{.Status}}"
    system_api_svc_gateway: Restarting (1) About an hour ago

Workaround

There is no workaround for these issues. If you have downloaded F5OS-A 1.4.0, F5 recommend not to install on your F5 rSeries hardware product. If you have already installed F5OS-A 1.4.0 on your F5 rSeries hardware product and you have experienced the issues described in this article on your F5 rSeries hardware product, then the only way is to recover the system by resetting the F5OS-A configuration including the deployed BIG-IP tenants. To reset the F5OS-A configuration and tenants configuration, perform the following procedure:

Impact of workaround: Performing this procedure removes all configuration on the F5OS-A device including the management IP information and you may have to manually re-configure these configurations.

  1. Log in to the affected F5 rSeries hardware product CLI using the root account.
  2. Delete all F5OS-A configuration and tenants configuration for the device by entering the following command:

    rm -f /var/F5/system/cdb/*.cdb

  3. Reboot the device by entering the following command:

    reboot

  4. Once the device boots up, you must connect to the device using the serial console port. The default baud rate and serial port configuration is 19200/8-N-1.
  5. Refer to the Run the Setup Wizard section under the F5 rSeries system initial configuration chapter of the F5 rSeries Systems: Getting Started guide for details on configuring the initial network management access to the device using the appliance-setup-wizard utility. Note that the admin credentials would have reset to its default.
  6. When you have completed the initial network management access configuration, proceed to configure the portgroup, interfaces and VLANs as needed. For more information on configuring VLANs, refer to the Create required VLANs from the webUI section under the F5 rSeries system initial configuration chapter of the F5 rSeries Systems: Getting Started guide.
  7. When you have completed the configuration of portgroup, interfaces and VLANs, proceed to re-create the BIG-IP tenants. For more information on configuring a BIG-IP tenant, refer to the Deploy tenants from webUI section under the F5 rSeries system initial configuration chapter of the F5 rSeries Systems: Getting Started guide.
  8. When you have deployed your BIG-IP tenant, you can attempt to recover the tenant’s previous configuration. The newly-deployed tenant is created with new unit keys which may impact restoring its previous UCS archive file taken prior to these issues occurring especially if the UCS archive contains SecureVault-encrypted configuration. If the BIG-IP tenant has an high availability (HA) peer configured and the HA peer is still available, you can join the newly deployed BIG-IP tenant to the HA configuration before attempting to ConfigSync from the HA peer. If the HA peer is not available or if the newly deployed BIG-IP tenant is a standalone device, then depending on your scenario you should follow the procedures described in K9420: Installing UCS files containing encrypted passwords or passphrases (11.5.x and later) to restore the UCS archive.
