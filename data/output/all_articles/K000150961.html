Description

  • On F5 rSeries platforms running F5OS, the management interface and platform may become completely unreachable, with no logs generated during the outage period.
  • After a forced reboot via console, normal operation resumes. Log review shows a gap in platform activity
  • Examination of crash logs (vmcore-dmesg.txt) reveals multiple hardware errors, including:

    [Hardware Error]: Machine check events logged
    EDAC skx MC0: HANDLING MCE MEMORY ERROR
    EDAC MC0: 1 UE memory read error on CPU_SrcID#0_MC#0_Chan#0_DIMM#0 ...
    Kernel panic - not syncing: Fatal machine check

Environment

  • F5 rSeries 2800 platform.
  • F5OS-A.
  • BIG-IP Tenant 17.1.1.1.
  • Management and tenant connectivity via F5OS.
  • No special configuration required.

 

Cause

Hardware failure in the system memory (DIMM). Machine Check Exception (MCE) logs and EDAC (Error Detection and Correction) messages confirm both correctable and uncorrectable memory errors, leading to a kernel panic and system halt. This results in the platform becoming unresponsive and management access being lost until a manual reboot is performed.

Recommended Actions

Initiate an RMA (Return Material Authorization) for the affected rSeries appliance.
