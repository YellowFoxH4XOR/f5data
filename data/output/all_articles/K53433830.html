Known Issue

The BIG-IP system does not maintain TCP timestamps on a connection, even though timestamps have been negotiated when you have activated syncookie mode.

This issue occurs when all of the following conditions are met:

  • A Layer 7 (L7) virtual server is configured.
  • A TCP profile with RFC 1323 timestamps is enabled on the virtual server.
  • syncookie mode is activated.

Impact

Some client TCP stacks may reset connections that require timestamps to be maintained when negotiated.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system does not maintain timestamps on connections.
  • Your BIG-IP system resets connections.

Workaround

To work around this issue, you can disable TCP timestamps from your TCP profile. To do so, perform the following procedure:

Impact of workaround: There may be a small performance impact for hosts that require timestamps to enhance high-speed networking.

  1. From the Configuration utility, navigate to Local Traffic > Profiles > Protocol > TCP.
  2. Select the TCP profile you want to change.
  3. In the Congestion Control section, disable the Timestamps Extension for High Performance (RFC 1323) option by de-selecting the option.

    To make this modification, you can use the following Traffic Management Shell (tmsh) command:

    modify ltm profile tcp <profile-name> timestamps disabled

    For example:

    modify ltm profile tcp tcp-example timestamps disabled
