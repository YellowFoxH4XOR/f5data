K000136100: Kibana stdout file is not logrotated in Traffix SDC

Type
Support Solution
Published
2023-09-06
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K000136100

Description

  • You notice that the kibana log file does not log rotate and its log file is allowed to grow continuously.
/var/log/kibana$ ll -ha
total 132K
drwxrwxr-x 2 root users 0 Jul 18 03:05 ./
drwxrwxr-x 2 root users 4.0K Jul 18 03:06 ../
-rw-rw-r-- 1 root users 343K Jul 17 03:41 kibana.stderr
-rw-rw-r-- 1 root users 8.8G Jul 20 01:21 kibana.stdout

Environment

  • SDC 5.x
  • EMS
  • ELK

Cause

EMS 5.x logrotate configuration does not include the definition config to rotate kibana log files.

 Recommended Actions

1. Backup the logrotate-traffix.conf in salt sls files under /srv/salt/<sdc version>/system/logrotate
2. Append the following lines to end of /srv/salt/<sdc version>/system/logrotate/logrotate-traffix.conf
 
/var/log/kibana/kibana.stderr /var/log/kibana/kibana.stdout {
daily
dateext
dateformat -%Y-%m-%d-%s
create
rotate 10
size 10M
missingok
notifempty
delaycompress
compress
copytruncate
postrotate
pkill -HUP rsyslogd #>/dev/null 2>&1
endscript
}
 
3. Push the logrotate state to the EMS nodes
 
***From EMS1 node,
salt '*' state.sls system.logrotate
 
4. Verify the /etc/logrotate.d/logrotate-traffic.conf file is updated with those new lines added in step #2
 
5. Optional step, if you would want to logrotate the kibana log file immediately:
 
logrotate --verbose -f /etc/logrotate.d/logrotate-traffic.conf

Additional Information

None.
