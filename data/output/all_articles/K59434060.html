Description

Neurond daemon in restart loop

  • neurond restarting continuously logged in /var/log/daemon.log
  • Errors similar to:

    err neurond[2774]: neuron_proxy_nsp_send_command: Timeout polling for response 0 from neuron device[0] via HSB

Environment

This can be caused if any of the following are true:

  • /var or /root disk was full at boot during neurond-hsb initialization
  • /var disk has no free inodes at boot during neurond-hsb initialization
  • neurond has been restarted using systemctl
  • recent upgrade with firmware update

Cause

The neurond process has an initialization phase that is only ran once at boot, or when the daemon is added. If this initial initialization with the hsb fails subsequent restarts will fail.

  • ID 880289: FPGA firmware changes during configuration loads
  • ID 981485: Neurond enters a restart loop after FPGA update.

Recommended Actions

1. Free up disk space or inodes in the filesystem. Please see K14403: Maintaining disk space on the BIG-IP system for details

2. Remove and reinstall neurond into bigstart:

  1. Remove neurond from bigstart
    bigstart remove neurond

  2. Reset neurond configuration to defaults:
    bigstart add --default neurond

  3. Add neurond back to bigstart:
    bigstart add neurond

  4. If the issue persists, reboot the system.

Note: If a full physical hard-reboot of the system is unavailable, an AOM initialized reboot can suffice, following the steps indicated in the following article:

K14594: Accessing the AOM Command Menu
