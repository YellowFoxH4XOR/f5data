Known Issue

This is the result of a known issue. The SNMP configuration is synchronized by default between members of a redundant pair. If you have configured a unique trapsource address for each system in a redundant BIG-IP pair, it will be overwritten on the receiving unit by the first configsync operation, and subsequent SNMP traps will be sent from the same address by each unit.

F5 Product Development tracked this issue as CR94205 and it was fixed in versions 9.4.7 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

You can prevent the SNMP trap source from synchronizing between units by performing one of the following procedures on both systems in the pair.

Important: The procedure must be performed on both members of the redundant pair, or the trapsource address will continue to be synchronized.

Version 9.0.0 through 9.3.1

In BIG-IP version 9.0.0 through 9.3.1, you can prevent the /config/snmp/snmpd.conf file from being synchronized between units by performing the following procedure:

  1. Log in to the command line.
  2. Back up the /usr/libdata/configsync/cs.dat file by typing the following command:

    cp /usr/libdata/configsync/cs.dat /usr/libdata/configsync/cs.dat.SOL9749
  3. Use a text editor to edit the /usr/libdata/configsync/cs.dat file.

  4. Add the following three lines to the end of the file:

    save.1210.file          = /config/snmp/snmpd.confsave.1210.backup        = yessave.1210.local         = yes
  5. Save the file.

Version 9.4.0 through 9.4.2

In BIG-IP version 9.4.0 through 9.4.2, you can prevent the /config/snmp/snmpd.conf file and other files from being synchronized between units by setting the Configsync.Excludes </path/to/file> bigpipe database variable. The Configsync.Excludes variable must refer to a single file. If snmpd.conf is the only file you are excluding from synchronization, perform the Excluding only snmpd.conf procedure. If you are currently using the Configsync.Excludes variable to prevent other files from being synchronized, perform the Excluding multiple files procedure.

Excluding only snmpd.conf

  1. Log in to the command line as a root user.
  2. Enter the following command:

    bigpipe db Configsync.Excludes /config/snmp/snmpd.conf
  3. Save the changes made to the database by typing the following command:

    bigpipe save

Excluding multiple files

  1. Log in to the command line as a root user.
  2. Create an excludes file that contains multiple files to exclude from synchronization by typing the following command:

    touch excludes_file
  3. Using an editor, edit the excludes_file file and enter the path and file name of each file to be excluded from synchronization.

    For example:

    /config/snmp/snmpd.conf
    /config/zebos.conf
  4. Save the changes made to the excludes_file file.
  5. Configure the Configsync.Excludes variable to point to the newly created excludes file by typing the following command:

    bigpipe db Configsync.Excludes /config/excludes_file
  6. Save the changes made to the database by typing the following command:

    bigpipe save

Version 9.4.3 through 9.4.6

In BIG-IP versions 9.4.3 through 9.4.6, you can prevent the trapsource address from being synchronized between units by performing the following procedure:

  1. Log in to the command line as a root user.
  2. Back up the /defaults/config_base.conf file by typing the following command:

    cp /defaults/config_base.conf /defaults/config_base.conf.SOL9749
  3. Change the permissions on the /defaults/config_base.conf file to allow editing by typing the following command:

    chmod 644 /defaults/config_base.conf
  4. Use a text editor to edit the /defaults/config_base.conf file.

  5. Locate the following section in the file:

    trapsource {
    display "User specified address for where trap's from."
    type ipaddr
    default none
    appdata "unix_config_snmpd.replace.trapsource"
    clustered enable
    configsyncd enable
    }

  6. Change the line reading configsyncd enable to read configsyncd disable instead:

    trapsource {
    display "User specified address for where trap's from."
    type ipaddr
    default none
    appdata "unix_config_snmpd.replace.trapsource"
    clustered enable
    configsyncd disable
    }
  7. Save the file.
  8. Return the permissions on the /defaults/config_base.conf file to read-only by typing the following command:

    chmod 444 /defaults/config_base.conf
  9. Load the new configuration by typing the following command:

    bigpipe load
