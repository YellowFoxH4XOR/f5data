Known Issue

This is the result of a known issue. CRC collision error messages are incorrectly reported as a fatal error within the Policy Builder log files.

The BIG-IP ASM uses CRC calculations based on the first 255 characters of a parameters name to create the parameter key ID within the BIG-IP ASM database. The key value of different parameters may result in the same parameter ID. The BIG-IP ASM will report any instances of same parameter ID's using the fatal log reporting level.

When this issue occurs, error messages that appear similar to the following example may be logged to the /var/log/ts/policy_builder/pb-<##>.log file, where <##> is the security policy ID number:

FATAL <date> <time> [5.db.mysql.Table]: CRC collision on fast table PBS.PBH_PARAMS : (id = 26,account_id = 2,param_id = 29,key_input_type = 0,key_ui_type = 0,flg_null_value = 0,max_len = 0,min_value = null,max_value = null,name = ???)

This error message indicates it may take the Policy Builder longer to analyze the specific parameters; the issue is not fatal.

F5 Product Development is tracking this issue as ID 291468 (Formerly CR 119292).

Workaround

You can prevent CRC collision log entries from filling up the Policy Builder log file by modifying the logkit.xconf file. To do so, perform the following procedure:

Important: Perform the following changes during a maintenance window. A restart of the BIG-IP ASM module is required, which will result in traffic disruption.

  1. Log in to the BIG-IP ASM command line.
  2. Change directories to the /var/ts/crawlers/plc_crawler/conf/ directory using the following command syntax:

    cd /var/ts/crawlers/plc_crawler/conf/
  3. Backup the log definition file logkit.xconf.

    For example:

    cp logkit.xconf logkit.xconf.orig

  4. Open the logkit.xconf file in an editor.
  5. Locate the following section:

    <category name="mysql" log-level="WARN">
    <log-target id-ref="main-log"/>

  6. Change the log-target id-ref value from main-log to null-target, so that it appears as follows:

    <category name="mysql" log-level="WARN">
    <log-target id-ref="null-target"/>

  7. Save the configuration change to the log definition file.
  8. Restart the BIG-IP ASM to load the changes by typing the following command:

    bigstart restart asm
