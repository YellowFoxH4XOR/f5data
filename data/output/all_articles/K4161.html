Topic

The configuration of the BIG-IP system determines how it manages out-of-order packets.

L4 traffic

Generally, layer 4 traffic uses the FastL4 profile and is accelerated by the PVA. The BIG-IP system passes these packets to their destination without reassembly or reordering.

FastHTTP profile

When the BIG-IP system is configured to use the FastHTTP profile, it handles the packets that contain HTTP headers or data payload based on whether the packets are received in the correct order.

If the packets that contain HTTP headers or data payload are received out-of-order, the BIG-IP system drops them since the system does not buffer the data. If the system receives the packets that contain HTTP data payload in the correct order, the BIG-IP system passes the packet to its destination without reordering the packets.

TCP profile

When the BIG-IP system is configured to use the TCP profile, it queues up to 48 packets at a time, reassembles them, and sends the new packets to the destination in the correct order.

SYN cookies

If the virtual server has SYN cookies enabled and an out-of-order packet arrives before the final ACK in the TCP three-way handshake, the BIG-IP system will reset the connection due to No Flow. This is by design, as the BIG-IP system does not maintain flow state when SYN cookies are enabled and by default it sends a reset packet when a packet arrives that does not match an existing flow. Out-of-order packets of the TCP three-way handshake are not queued.
