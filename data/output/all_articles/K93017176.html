Topic

Summary

A virtual server is a traffic management object on the BIG-IP system that is represented by a virtual IP address and a service, such as 192.168.20.10:80. When clients send application traffic to the virtual server, the BIG-IP system listens for that traffic and directs the traffic according to the virtual server configuration.

A Standard virtual server is a general purpose virtual server that is the default virtual server type when you create a virtual server. A Standard virtual server directs client traffic to a load balancing pool, and is the most basic type of virtual server used for everything not expressly provided by the other type of virtual servers.

Description

A Standard virtual server has configurable settings that allow you to customize what traffic is processed by the virtual server. For example, you can specify a specific protocol like TCP, User Datagram Protocol (UDP), Stream Control Transmission Protocol (SCTP), or even all protocols. Additionally, you can customize how the BIG-IP system processes various types of traffic by assigning profiles to the Standard virtual server. For example, through profile assignment, a Standard virtual server can enable compression on HTTP request data as the data passes through the BIG-IP system, or decrypt and re-encrypt SSL connections and verify SSL certificates. For each type of traffic, such as TCP, UDP, HTTP, SSL, Session Initiation Protocol (SIP), and FTP, you can assign a custom profile to the virtual server or use the default profile.

When you create a Standard virtual server, you specify the pool or pools that you want to use as the destination for any traffic coming from that virtual server. You also configure its general properties, profiles, secure network address translations (SNATs), and other resources you want to assign to it, such as iRules or session persistence types.

Note: If you do not define a pool or node in a BIG-IP standard virtual server, the virtual server may still route traffic based on the TMM routing table. For more information, refer to K04116537: BIG-IP standard virtual server routes traffic even without a pool defined.

SettingDescription

Connection Rate LimitSpecifies the maximum number of connections-per-second allowed for a virtual server. When the number of connections-per-second reaches the limit for a given virtual server, the system drops (UDP) or resets (TCP) additional connection requests. Connection Rate Limit ModeControls the scope of the rate limit defined for the virtual server, specifically, per virtual server object, per source address, per destination address, or a combination of source and destination addresses.   • Per Virtual Server and Source Address: Applies Connection Rate Limit Source Mask to the source IP address of incoming connections to this virtual server, and applies the rate limit to connections sharing the same subnet.   • Per Destination Address (All Rate Limiting Virtual Servers): Applies rate limiting based on the specified destination address for all virtual servers that have rate limits specified.
  • Per Source and Destination Address (All Rate Limiting Virtual Servers): Applies rate limiting based on the specified source and destination addresses for all virtual servers that have rate limits specified.

Auto Last HopWhen enabled, allows the system to send return traffic to the MAC address that transmitted the request, even if the routing table points to a different network or interface. As a result, the system can send return traffic to clients even when there is no matching route. For example, if the system does not have a default route configured and the client is located on a remote network. This setting is also useful when the system is load balancing transparent devices that do not modify the source IP address of the packet. Without the last hop option enabled, the system could return connections to a different transparent node, resulting in asymmetric routing. You can configure this setting globally and on an object level. You set the global Auto Last Hop value on the System > Configuration > Local Traffic > General page. To configure this setting globally, retain the Default setting. iRulesSpecifies the iRules you want run on this virtual server. iRules help automate the intercepting, processing, and routing of application traffic. You can move iRules from the Available list to the Enabled to enable them, and you can use the Up and Down keys to reorder the lists.
  • Enabled: This list contains the iRules on the system that are already applied to the virtual server. The system applies an iRule in the order in which it appears in the list.
  • Available: This list contains the iRules on the system that are available to apply to the virtual server.
PoliciesSpecifies the policies for the virtual server. You can move policies from the Available list to the Enabled to enable them, and you can use the Up and Down keys to reorder the lists. Policies run in the order they appear in the list.

  • Available: This list contains policies on the system that are available to apply to the virtual server.
