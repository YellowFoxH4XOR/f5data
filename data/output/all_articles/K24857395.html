Description
Qualys scan reports weak DSA 1024 keys as an option for BigIP SSH access.

Environment

  • Any 13.x+ BigIP systems

Cause
The option is still available even if stronger RSA 2048 key is actually being used by the system
You may get slightly different results from 'grep keygen /usr/bin/keyswap.sh' command when following K26031800 article.

# openssl rsa -noout -text -in /var/ssh/ssh_host_rsa_key | grep -i key
Private-Key: (1024 bit)

# grep keygen /usr/bin/keyswap.sh
ssh-keygen -q -f ${tmpdir}/${identity} -t rsa -N "" -C "$username"
ssh-keygen -q -f ${tmpdir}/ssh_host_key -t rsa1 -N "" -C "$hostname"
ssh-keygen -q -f ${tmpdir}/ssh_host_rsa_key -t rsa -N "" -C "$hostname"
ssh-keygen -q -f ${tmpdir}/ssh_host_dsa_key -t dsa -N "" -C "$hostname"
ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -N "" -C "$hostname"
ssh-keygen -q -f ${tmpdir}/ssh_host_ed25519_key -t ed25519 -N "" -C "$hostname"
ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -N "" -C "$hostname"
ssh-keygen -q -f ${tmpdir}/ssh_host_ed25519_key -t ed25519 -N "" -C "$hostname"

Recommended Actions
Increasing RSA SSH keys from 1024-bit to 2048-bit keys and removing DSA keys

  1. Change all RSA key options to
ssh-keygen -q -f ${tmpdir}/${identity} -t rsa -b 2048 -N "" -C "$username"
ssh-keygen -q -f ${tmpdir}/ssh_host_key -t rsa1 -b 2048 -N "" -C "$hostname"
ssh-keygen -q -f ${tmpdir}/ssh_host_rsa_key -t rsa -b 2048 -N "" -C "$hostname"

2. Comment out any DSA key options and then manually delete the /var/ssh/ssh_host_dsa_key* files
