You can configure an ECV to monitor a default.asp page; however, it is preferable to search for a desired result rather than an error. If you search for a specific error and you receive a different error, the service will still be marked as UP. Therefore, it is better to search for an expected result.

Following is an example of an ECV used to monitor a default.asp page. In the following example, the bigd daemon will report the service as UP as long as the connection is established and an HTTP 404 Not Found error is not returned from the web server.

b monitor no404s_monitor '{ use http reverse dest *:80 interval 10 timeout 33 send "GET /" recv "404" }'

b node *:80 monitor use no404s_monitor

If your application does not require a failure on a defined error, a more robust way of monitoring the service is to configure a specific HTML page to return an I'm OK message.

In the following example, the bigd daemon does not receive the I'm OK message, so it marks the service as DOWN. This ECV would not utilize a reverse logic statement but would look for a positive result from the query.

b monitor All_OK '{ use http dest *:80 interval 15 timeout 50 send "GET /bigip.html" recv "Im OK" }'

Note: You can use this type of ECV if your default page contains static content, such as a site name or URL; however, the static content must be contained within the page or the ECV will mark the service as DOWN based on an invalid response from the server.

<HTML>
<TITLE> BigIP Service Check Page </TITLE>
<BODY>
I'm OK
</BODY></HTML>
