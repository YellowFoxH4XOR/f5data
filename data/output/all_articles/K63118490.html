Description

When a network access profile is created on BIG-IP APM systems, the system defines a pool of IP addresses that it uses to assign an IP address to the client connections. This article provides an overview of how this works and gives example SNAT address considerations.

Environment

  • Client device establishing network access VPN connection to the BIG-IP APM.
  • BIG-IP APM Network Access lease pools

Cause

None

Recommended Actions

Refer to K4283: APM Network Access Lease pool Reserved Addresses when configuring your Network Access lease pool.

Additional Information

A lease pool is a group of IPv4 or IPv6 addresses from which IP addresses are assigned to clients which try to establish Network Access (VPN) tunnels with BIG-IP APM.

Figure: Lease pool assignment after VPN establishment, you virtually connect a device over the internet to an internal network, get an IP address dynamically assigned, and use that IP address to start communicating with the internal network. 

How it works

IP addresses are assigned with a Freelist algorithm. When a client requests for the IP address, the first one in the list is given out. When any client releases the IP address, it is added back to the Freelist. This also applies when having multiple ranges defined in the lease pool. 

Note: The number of IP addresses in an IP pool that are available to clients is always three less than the total number of IP addresses in the subnet. Refer to the article K4283: BIG-IP APM Network Access lease pool reserved addresses for information about reserved IP addresses.

In the following example, four IP address ranges are configured:


apm resource leasepool lease_pool {
    members {
        10.10.10.1-10.10.10.254 { }
        10.10.20.1-10.10.20.254 { }
        10.10.30.1-10.10.30.254 { }
        10.10.40.1-10.10.40.254 { }
    }
}


The first IP address available from the range 10.10.10.x will be assigned to the first user. Then the second user will be assign with the second IP address of the same range, and this process will continue sequentially until all the available addresses of the range are in used. 

If all the IP address from the range 10.10.10.x are already in used, the BIG-IP will give out an IP address from 10.10.20.x. However, if during the process one of the IP address of the range 10.10.10.x is no longer in used, that IP address will be assigned to the next client.

Note: If the leasepool address list changes, the next IP address provided might not immediately reflect the change.

Lease IP address considerations related to NAT/SNAT


For more detailed information about how secure network address translation (SNAT) behavior varies, depending on the type of BIG-IP APM resource you are using refer to K33368912: Understanding the SNAT interaction with the BIG-IP APM system. The following figure shows a deployment scenario in which no NAT or SNAT is in use: 




Figure: Deployment scenario in which no NAT or SNAT is in use


  1. VPN clients use lease pool IP addresses as source IP addresses when trying to communicate with internal servers.
  2. With Proxy address resolution protocol (ARP) configured, during lease pool IP address assignment, BIG-IP APM can also broadcast gratuitous ARP (GARP) packets.
  3. Internal servers can also actively initiate connection back to client using the lease pool IP address.
  4. Internal network administrator must properly configure route to reach these lease pool IP addresses.


The following figure shows a deployment scenario in which SNAT is in use.




Figure: Deployment scenario in which SNAT is in use


  1. VPN clients use an IP address from SNAT pool (or BIG-IP APM self IP when SNAT automap is used).
  2. For SNAT pool addresses, an internal network administrator needs to configure proper routes to reach the SNAT pool.


NOTE: F5 recommends you do not exceed a ratio of 10 lease pool IPs to 1 SNAT IP (10:1) when creating the SNAT Pool.  This ensures there are adequate ports for each member to access internal resources.  You may need to modify the ratio depending on your users port use.

NOTE: Lease Pool's do not include a Lease Timeout parameter.  Rather, it is the Access Profile's Maximum Session Timeout parameter that effectively dictates the Lease Pool's Lease Timeout period.
