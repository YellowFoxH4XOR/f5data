K000151505: Changes to BIG-IP DNS configuration made via big3d auto-discovery do not automatically get noted in BIG-IQ's DNS configuration

Type
Support Solution
Published
2025-05-23
Updated
2025-06-04
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.0
Source
https://my.f5.com/manage/s/article/K000151505

Description

Changes made to DNS configuration that are made via virtual server auto-discovery do not result in BIG-IQ DNS updates.

Environment

  • BIG-IQ DNS and LTM
  • Virtual server auto-discovery

Cause

This is an expected behavior.

Recommended Actions

  1. Create a Wide IP on BIG-IQ:
  2. Give the Wide IP pools on BIG-IQ:
  3. Point those pools to existing Virtual Servers on LTMs
  4. Note their current IP addresses in the BIG-IQ.
  5. Deploy this configuration to the BIG-IP DNS unit.
  6. Note that on BIG-IQ the server group has virtual server auto-discovery enabled
  7. Make changes to the LTM virtual servers on BIG-IQ that are pool members of the DNS Wide IP. (Note the IP address changes)
  8. Deploy those changes to the LTMs
  9. Note that the IP addresses in the Wide IP pool members change on the BIG-IP as expected:
  10. But notice that back on BIG-IQ, the pool member addresses for the Wide IPs are unchanged:
  11. Re-discover and re-import DNS configuration on BIG-IQ, selecting BIG-IP as the conflict resolution source:
  12. Now note that the Wide IP pool member addresses for DNS configuration on BIG-IQ are corrected:

Additional Information

This is because the DNS configuration correction on the DNS unit comes from big3d's auto-discovery of LTM virtual servers. BIG-IQ does not utilize big3d and therefore does not automatically receive the cross-module correction.
