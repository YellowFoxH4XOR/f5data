Description

HTTPS health monitors on BIG-IP LTM fail with SSL handshake errors after Server Name Indication (SNI) is enabled on backend servers, like an IIS server. The issue is isolated to SSL/TLS negotiation, as TCP monitors report pool members as UP, confirming network connectivity and port availability. The problem occurs because the default HTTPS health monitor does not send the required SNI in its Client Hello messages [K65219243].

Environment

  • Product: BIG-IP LTM
  • Backend servers with SNI enabled
  • HTTPS monitor with default or custom HTTP request and Host header
  • Virtual server uses HTTPS health monitor for Backend pool members
  • In-TMM monitoring [Disabled by default]

Cause

The BIG-IP HTTPS health monitor does not send the required SNI in its SSL Client Hello messages when In-TMM monitoring is disabled and the monitor is not configured to include the SNI value. After SNI is enabled on backend servers, the servers require SNI for successful SSL/TLS handshakes, causing the health checks to fail. 

Answer/Recommended Actions

  1.  Enable In-TMM Monitoring, by running the below command [K11323537]. This shifts Health-check processing from the "bigd" process to "TMM":
    tmsh modify sys db bigd.tmm value enable

  2. Configure HTTPS Monitor to Include SNI:

    • Assign a Server SSL profile to the HTTPS monitor.
    • Set the SNI value in the desired Server SSL profile to match the backend server's hostname (e.g., server1.example.com)

  3.  Review Monitor Send Strings, by ensuring all custom HTTP/HTTPS monitor send strings explicitly specify the HTTP version (e.g., HTTP/1.1) and use correct CR/LF sequences (\r\n ) [K16343688]. Example send string:

    GET /path HTTP/1.1\r\nHost: server1.example.com\r\nConnection: Close\r\n\r\n
  4. Check Resource Utilization, since Enabling In-TMM monitoring may increase TMM CPU and Memory usage [K85210713]. Monitor system resources after enabling for some days.
  5. Review Monitor Interval and Timeout, by ensuring that the monitor Interval divides evenly into the timeout value to avoid probe timing anomalies [K000158945].
  6. Test in Maintenance Window, by planning for a brief period (up to 2× the longest monitor interval) for monitors to re-establish health status after enabling In-TMM monitoring.

Note: iRules cannot be used to add SNI to health monitor probes.

Additional Information

  • During the transition from "bigd" to In-TMM monitoring, pool member status may briefly flap or show as Unknown until the first TMM-based probe completes.
  • HTTPS monitors with SSL Profile set to "None" may fail under In-TMM monitoring. Explicitly assign a Server SSL profile to each HTTPS monitor.
  • In-TMM monitoring is stricter about HTTP compliance than "bigd". Non-compliant send strings may cause monitors to fail.
  • The actual impact on TMM resources depends on the number of monitors and system capacity; monitor resource usage after changes.
