Known Issue

This is the result of a known issue. The HTTP::header count <header name> iRule command returns the number of HTTP headers present in the request or response that match the header name value.

When HTTP::header count <header name> is used an iRule, the BIG-IP system fails to count the last header line. As a result, if the header being counted is on the last line in the request or response, an incorrect count occurs.

For example, if your iRule uses the HTTP::header command to count the number of times the Cookie header appears in the request or response, any instance of the Cookie header appearing on the last line of the request or response is not counted by the BIG-IP system.

In the following GET request example, the BIG-IP system will count Cookie: value1, but not Cookie: value2:

GET / HTTP/1.1
User-Agent: curl/7.13.2
Host: AskF5
Pragma: no-cache
Accept: */*
Cookie: value1
Cookie: value2

F5 Networks Product Development tracked this issue as CR114612 and it was fixed in BIG-IP LTM version 9.4.8 and version 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.
