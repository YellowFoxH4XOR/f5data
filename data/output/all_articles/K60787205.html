Topic

The QKView file provides a running snapshot of your BIG-IP system with up-to-the-minute configuration and diagnostic information. Organizations may be restricted by confidentiality policies or contractual obligations when sharing data in the QKView. This article helps you understand the information in a QKView and how to manage the data it contains.

Information in a QKView

A QKView archive contains the following categories of information.

Categories of information in QKView files
CategoryDescription
Device informationThis includes the device license and serial number with device certificates. The QKView file does not include SSL keys used in SSL profiles by default.
BIG-IP configurationThis may contain server hostnames, IP addresses, usernames, passwords, passphrases in encrypted form, and other information about the network.
Log filesDepending on the logging verbosity and logging sources provisioned on the system, such as iRules and BIG-IP modules, this may contain the following:
  • Client IP addresses
  • HTTP requests headers
  • Some organizational structure information, such as department names, if your BIG-IP APM is configured with Active Directory (AD) or Lightweight Directory Access Protocol (LDAP).
Core filesCore files consist of the recorded state of the working memory of a process at a specific time when a process terminates abnormally. The kind and amount of information in core files depend on the process that generated the core file and the memory state at the time.

For example, a Traffic Management Microkernel (TMM) core file usually contains traffic through a virtual server and hence user data. On the other hand, a process on the control plane, such as csyncd, is unlikely to generate a core file that contains user data.

You can exclude core files when generating a QKView.
Command outputsThe QKView gathers diagnostic information by running Traffic Management Shell (tmsh) and Advanced Shell (bash) commands. In general, this information provides a snapshot of the running state of the BIG-IP system relating to:
  • CPU
  • Disk space
  • Memory usage
  • BIG-IP configuration
  • Commands previously executed on the system
  • Oher system features
  • FIPS private key information (may be collected)

    For more information about FIPS, refer to K52534643: Overview of the Platform FIPS BIG-IP system.

Files saved in directories marked for collectionFor example, when you save a tcpdump capture in the /config directory, the system includes it in the QKView.

Examine the contents of a QKView

To determine whether a QKView file contains sensitive data, you must examine the contents of the QKView. You can use the following methods to do so.

Use tar or zip commands

The QKView is essentially a .tar package that you can extract, and then you save its contents to a file system using the tar command or any zip tools.

To untar the contents on the current directory, enter the following command:

  • tar -xvf <filename>.qkview

    Locate the manifest.xml file in the output in the root directory. This file contains a list of directories and files included in the package and the commands the system runs when generating the archive.

To print the contents of the files in a directory in a QKView archive, use the following command syntax:

  • tar xfz /var/tmp/<qkview_name>.qkview <directory/file name> -O

    Note: When you specify a directory, the command selects and prints files in the directory and its sub-directories recursively. This may include a large number of files, including compressed and binary files, which may not be desirable.

    For example, you enter the following command to output the contents of every file in the config directory and save its contents to output.txt:

    tar xfz /var/tmp/example.qkview config -O > output.txt

    From the output file, you can perform a search for keywords.

Use iHealth API

When you upload your QKView to iHealth, the iHealth servers perform privacy checks on the original file prior to any processing, and the system overwrites the original QKView file with the post-privacy check QKView file.

You can use iHealth API to view the contents of a QKView uploaded to iHealth. To do so, perform the following procedures.

For more options to manage your QKView on iHealth, refer to iHealth Home on F5 Cloud Docs.

Note: F5 Support does not support the iHealth API; however, F5 provides it as a helpful addition that you can use to keep your BIG-IPs running well.

Authenticate to iHealth

To authenticate to iHealth, you must generate an API token with Client ID and Client Secret issued from the iHealth API token service. For information about generating the iHealth API token, refer to K000130498: Generating new iHealth API credentials using iHealth API token service.

Get the metadata of a QKView on iHealth

Before you can get the metadata of a QKView on iHealth, you must first get the QKView ID on iHealth. To do so, enter the following code syntax:

  • curl -X GET -sk -H "Accept: application/json" -H "Authorization: Bearer <iHealth API token>" https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews | jq

    For example, you enter the following command:

    curl -X GET -sk -H "Accept: application/json" -H "Authorization: Bearer MYTOKEN" https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews | jq

To get the metadata of a QKView on iHealth, enter the following code syntax:

  • curl -X GET -sk -H "Accept: application/json" -H "Authorization: Bearer <iHealth API token>" https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews/<qkview_id> | jq

    For example, you enter the following command:

    curl -X GET -sk -H "Accept: application/json" -H "Authorization: Bearer MYTOKEN"  https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews/99241184 | jq

Get the list of files in a QKView

To get the list of files in a QKView, enter the following code syntax:

  • curl -X GET -sk -H "Accept: application/json" -H "Authorization: Bearer <iHealth API token>" https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews/<qkview_id>/files | jq

    For example, you enter the following command:

    curl -X GET -sk -H "Accept: application/json" -H "Authorization: Bearer MYTOKEN" https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews/99241184/files | jq

    Note: The output of this command contains the file_id for each file which you can use to print the contents of a file in the next command.

Print the contents of a file

To print the contents of a file, use the following command syntax:

  • curl -X GET -sk -H "Accept: application/octet-stream" -H "Authorization: Bearer <iHealth API token>" https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews/<qkview_id>/files/<file_id>

    For example, enter the following:

    curl -X GET -sk -H "Accept: application/octet-stream" -H "Authorization: Bearer MYTOKEN" https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews/99241184/files/dmFyL2xvZy9hc20uMQ

Manage the files you want to include in a QKView

The QKView has the following features that enable you to manage and decide which files to include:

  • Beginning at the QKView generation process, you can use different switches in the qkview command to control which files you want to include. For example, the -C switch excludes core files from the collection, and the --exclude switch enables you to specify categories of files to exclude.

    For more information, refer to K23928121: Overview of qkview command-line options.

  • Beginning in BIG-IP 12.1.3.6 on the 12.x branch and BIG-IP 13.1.0, you can specify data that you want to obfuscate in the QKView file by using regular expression matching. For more information, refer to K55559493: Obfuscating sensitive data in a QKView file.

    Note that this feature works better with text files than binary and compressed files.

Recommendations

Whether a QKView contains sensitive information primarily depends on what the organization considers sensitive. Some organizations consider server and network infrastructure information sensitive, while others consider user traffic that goes through a virtual server sensitive. In addition to examining the contents of a QKView using the steps from this article, also consider the following factors:

  • Additional information may be included in the QKView with some BIG-IP modules. For example, a BIG-IP APM system configured with AD authentication, authorization, and accounting (AAA) may log user information stored in AD. Similarly, BIG-IP ASM may log user names, Client IP addresses, and HTTP request headers.
  • The following may contain business related information such as department names, organization structure, and product information:
    • Configuration files
    • File names
    • Names of BIG-IP resources, such as virtual servers and BIG-IP APM and BIG-IP ASM policy names
  • The amount of information in log files depends on the logging verbosity defined in logging profiles and the presence of logging sources, such as iRule logging, iCall, and other customizations, if any.
