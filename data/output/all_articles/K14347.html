The BIG-IP system removes the IP address on the management interface.

This issue occurs when all of the following conditions are met:

  • Install Configuration is enabled when booting to a slot that is running one of the following BIG-IP 11.3.0 hotfix versions:
    • Hotfix-BIGIP-11.3.0-3017.0-HF2
    • Hotfix-BIGIP-11.3.0-3022.0-HF3
    • Hotfix-BIGIP-11.3.0-3093.0-HF4
  • The source configuration being installed is from BIG-IP 11.3.0 with no hotfixes.

Note: Hotfix-BIGIP-11.3.0-2968.0-HF1 is not affected by this issue.

Note: The VIPRION system and the Virtual Clustered Microprocessor (vCMP) guest that runs on a VIPRION system are not affected by this issue because these systems derive their management IP address from the cluster IP address.

Impact

The BIG-IP system is not accessible through the management interface in subsequent restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H418105 on the Diagnostics > Identified > Low page.
  • The following utilities report no management IP address on the affected BIG-IP system:
    • tmsh list sys management-ip
    • The Configuration utility System > Platform > Configuration page
  • For BIG-IP systems that have been previously configured using the management IP address for Failover Unicast, system configuration loading with a Traffic Management Shell (tmsh) command may display an error message at the end of the load sequence output that appears similar to the following example:

    tmsh load /sys config
    0107146f:3: Self-device unicast source address cannot reference the non-existent Self IP (<original-ip-address-of-mgmt-interface>); Create it in the /Common folder first.
    Unexpected Error: Loading configuration process failed.

  • The /config/bigip_base.conf file has no configuration stanza for the management-ip object.
  • After subsequent restarts, the affected BIG-IP system is not accessible through the management interface.

Workaround

There is no workaround for this issue. However, you can recover from this issue by reconfiguring the management IP address either through the serial console or a self IP address if it is configured to allow Configuration utility access. To do so, perform either of the following procedures applicable to your environment:

  • Reconfiguring the management IP address through the serial console
  • Reconfiguring the management IP address using the Configuration utility through a self IP address

Reconfiguring the management IP address through the serial console

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Connect to the serial console of the affected BIG-IP system.
  2. Log in to tmsh by typing the following command:

    tmsh

  3. Reconfigure the management IP address by using the following command syntax:

    create /sys management-ip <IP address>/<netmask>

    For example, you would enter the following command to reconfigure 192.168.1.100 as the management IP address:

    create /sys management-ip 192.168.1.100/255.255.255.0

  4. Save the change by typing the following command:

    save /sys config

Reconfiguring the management IP address using the Configuration utility through a self IP address

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility through a self IP address.
  2. Click System.
  3. Click Platform.
  4. Click Configuration.
  5. Enter the appropriate information in the following fields:
    • IP Address
    • Network Mask
    • Management Route
  6. Click Update.
