K000151268: Getting error after upgrading to BIG-IP version 17.5.0 or later with err iprepd[13784]: 015c0004:3: Cannot determine Internet Protocol for host api.domain.com

Description

After upgrading to BIG-IP LTM version 17.5.0 or later, the following error message may appear repeatedly in system logs:

err iprepd[xxxxx]: 015c0004:3: Cannot determine Internet Protocol for host api.bcti.brightcloud.com.

This error is associated with the IP Intelligence (IPI) service and indicates a failure to determine whether IPv4 or IPv6 should be used to connect to the BrightCloud update server.

Environment

  • BIG-IP LTM 
  • Version: 17.5.0 and later (using updated IPI SDK)
  • IP Intelligence (IPI) provisioned/enabled
  • No internet connectivity or DNS resolution on the BIG-IP system
  • Outbound connections to external FQDNs (such as api.bcti.brightcloud.com) are blocked or not configured

Cause

Starting with BIG-IP version 15.1.4, the IP Intelligence (IPI) service uses an updated SDK that supports both IPv4 and IPv6 protocols with an auto-detect setting. If the BIG-IP system cannot resolve or reach the BrightCloud update servers due to lack of internet access or DNS resolution, the IPI daemon (iprepd) cannot determine which protocol to use, resulting in repeated log errors.

 

Recommended Actions

If IP Intelligence (IPI) is required:

Ensure outbound connectivity and DNS resolution from the BIG-IP management interface to these FQDNs on port 443 (HTTPS):

• api.bcti.brightcloud.com.

• localdb-ip-daily.brightcloud.com.

• localdb-ip-rtu.brightcloud.com.

• localdb-ipv6-daily.brightcloud.com.

Verify firewall/proxy rules allow these connections.

If IPv6 is not supported or not in use:

1.Force IPI service to use IPv4 only by running:

tmsh modify sys db iprep.protocol value ipv4

tmsh save sys config

 

2.Restart the IPI service:

tmsh restart sys service iprepd

 

Check IPI Database Status:

• To verify status of IPI database, run:

tmsh show sys iprep-status

If connectivity is available, both IPv4 and IPv6 databases should be loaded.

 

Check DNS Resolution:

• Use nslookup api.bcti.brightcloud.com. or dig api.bcti.brightcloud.com. A +short; dig api.bcti.brightcloud.com. AAAA +short; from the BIG-IP shell to confirm that required FQDNs can be resolved.
