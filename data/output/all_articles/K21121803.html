Topic

You should consider using this procedure under the following condition:

  • You want to shut down or restart a tenant on the VELOS and rSeries systems.

Description

You can do the following on a VELOS and rSeries system:

  • Shut down a tenant by changing its state from Deployed to Provisioned. This is the only available method to shut down a tenant.
  • Restart a tenant by changing its state to Provisioned and then back to Deployed. This is the only available method if you want to perform the restart from the F5OS system.

    Note: The other method to restart a tenant is by using the reboot command in the tenant's command line. This method does not involve the F5OS system.

For the VELOS system, you can change the state of the tenant using either the partition webUI, partition command line interface (CLI), or partition representational state transfer (REST) API. Similarly, for the rSeries system, you can change the state of the tenant using the webUI, CLI, or REST API.

The following table describes the available states of the tenant.

State of the tenantDescription
Configured

This is the default state when you create a tenant. The tenant's F5OS-level configuration (name, image, IP address, requested vCPU/memory/storage size, VLANs, etc.) exists on the VELOS partition or rSeries system in either case below.

If the tenant has never been Provisioned or Deployed: no hardware resources are allocated and no virtual disk is created for the tenant.
If the tenant was previously Provisioned or Deployed and is then changed to Configured: the tenant stops running, but its virtual disk — including the BIG-IP configuration stored on it — is retained.

Note: If you configure the state of the tenant to Deployed but the system does not have sufficient resources to allocate to the tenant, the status of the tenant indicates Pending and the tenant does not run. For more information, refer to K70034058: F5OS Tenant status indicates Pending.

ProvisionedIn the Provisioned state, the system allocates hardware resources to the tenant, per its configuration, but it is not running. Set the tenant to this state when you want to shut down the tenant without deallocating its hardware resource.
DeployedIn the Deployed state, the system allocates hardware resources to the tenant, per its configuration, and it is running. Set the tenant to this state when you want to start a tenant that is shut down.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have the partition administrative access to the partition webUI, CLI, or REST API for the VELOS system.
  • You must have administrative access to the webUI, CLI, or REST API for the rSeries system.

Procedures

  • Shut down a tenant on the VELOS and rSeries systems
  • Start a tenant on the VELOS and rSeries systems

Shut down a tenant on the VELOS and rSeries systems

You can shut down a tenant on the VELOS and rSeries systems by changing the state to Provisioned using any of the following methods:

  • Use the webUI
  • Use the command line
  • Use the REST API

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Use the webUI

  1. Log in to the partition webUI as the partition administrator for a VELOS system, or the webUI as the admin user for an rSeries system.
  2. Go to TENANT MANAGEMENT > Tenant Deployments.
  3. Select the name of the tenant you want to shut down.
  4. For the State setting, select Provisioned.
  5. Select Save & Close.
  6. Select OK to confirm the change of state for the tenant.

Use the command line

  1. Log in to the partition command line as the partition administrator for a VELOS system, or the CLI as the admin user for an rSeries system.
  2. To view the current state of the tenant, enter the following command syntax:

    show tenants tenant <name of the tenant>

    For example, you enter the following command to view the current state of the my-example-bigip-tenant tenant:

    show tenants tenant my-example-bigip-tenant

    Observe the status of the tenant in the command output. In the following example, the tenant is deployed and running, and the status is Running:

     state vcpu-cores-per-node 2

  3. Enter the Configuration mode terminal by entering the following command:

    config

  4. Shut down the tenant by changing the running-state of the tenant to Provisioned using the following command syntax:

    tenants tenant <name of the tenant> config running-state provisioned

    For example, you enter the following command to shut down the my-example-bigip-tenant tenant:

    tenants tenant my-example-bigip-tenant config running-state provisioned

  5. Save the change by entering the following command:

    commit

  6. Exit the Configuration mode terminal by entering the following command:

    exit

  7. Wait for the tenant to completely shut down.

Use the REST API

  1. Log in to a system with the curl and jq utilities installed.

    Alternatively, you can log in to the command line as the root user for the VELOS chassis or the rSeries system.

  2. To view the current state of the tenant, enter the following REST API command syntax:

    curl -X GET -H "Content-Type: application/yang-data+json" -sku <username>:<password> "https://<ip address>/api/data/f5-tenants:tenants/tenant=<tenant>"

    Note: Replace <username> and <password> with the administrative username and password to access the VELOS partition or the rSeries system, and replace <ip address> with the management IP address of the VELOS partition or the rSeries system.

    For example, you enter the following REST API command to view the current state of the my-example-bigip-tenant tenant:

    curl -X GET -H "Content-Type: application/yang-data+json" -sku admin:admin "https://192.168.80.132/api/data/f5-tenants:tenants/tenant=my-example-bigip-tenant"

  3. Shut down the tenant by changing the running-state of the tenant to Provisioned using the following command syntax:

    curl -X PATCH -H "Content-Type: application/yang-data+json" -sku <username>:<password> "https://<ip address>/api/data/f5-tenants:tenants/tenant=<tenant>t/config/running-state" -d '{"running-state": "provisioned"}'

    Note: Replace <username> and <password> with the administrative username and password to access the VELOS partition or the rSeries system, and replace <ip address> with the management IP address of the VELOS partition or the rSeries system.

    For example, you enter the following REST API command to change the running-state of the my-example-bigip-tenant tenant to provisioned:

    curl -X PATCH -H "Content-Type: application/yang-data+json" -sku admin:admin "https://192.168.80.132/api/data/f5-tenants:tenants/tenant=my-example-bigip-tenant/config/running-state" -d '{"running-state": "provisioned"}'

    Note: There is no output for this REST API command; it is expected behavior.

  4. Wait for the tenant to completely shut down.

Start a tenant on the VELOS and rSeries systems

You can start a tenant on the VELOS and rSeries systems by changing the state to Deployed using any of the following methods:

  • Use the webUI
  • Use the command line
  • Use the REST API

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Use the webUI

  1. Log in to the partition webUI as the partition administrator for a VELOS system, or the webUI as the admin user for a rSeries system.
  2. Go to TENANT MANAGEMENT > Tenant Deployments.
  3. Select the name of the tenant you want to start.
  4. For the State setting, select Deployed.
  5. Select Save & Close.
  6. Select OK to confirm the change of state for the tenant.

Use the command line

  1. Log in to the partition command line as the partition administrator for a VELOS system, or the CLI as the admin user for a rSeries system.
  2. To view the current state of the tenant, enter the following command syntax:

    show tenants tenant <name of the tenant>

    For example, you enter the following command to view the current state of the my-example-bigip-tenant tenant:

    show tenants tenant my-example-bigip-tenant

    Observe the status of the tenant in the command output. In the following example, the tenant is not running, and the status is Provisioned:

  3. Enter the Configuration mode terminal by entering the following command:

    config

  4. Start the tenant by changing the running-state of the tenant to Deployed using the following command syntax:

    tenants tenant <name of the tenant> config running-state deployed

    For example, you enter the following command to start the my-example-bigip-tenant tenant:

    tenants tenant my-example-bigip-tenant config running-state deployed

  5. Save the change by entering the following command:

    commit

  6. Exit the Configuration mode terminal by entering the following command:

    exit

  7. Wait for the tenant to start. You can use the command show tenants tenant <name of the tenant> to monitor the status of the tenant. When the tenant is deployed and running, the status of the tenant should indicate Running.
