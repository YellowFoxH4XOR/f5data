Known Issue

TMM may produce a core file when rate-shaper with the Stochastic Fair Queueing (SFQ) method is configured in a rate shaping class.

This issue occurs when all of the following conditions are met:

  • The SFQ method is configured in a rate-shaping class.
  • The rate-shaping class is assigned to a virtual server.

Impact

The BIG-IP host may stop responding and fail over to a standby host or another host in the device group.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H424614 on the Diagnostics > Identified > Medium screen indicating the device configuration matches the fingerprint.
  • BIG-IP iHealth lists Heuristic H424614 on the Diagnostics > Identified > High screen indicating the device configuration matches the fingerprint and a TMM core file exists in the /shared/core directory.
  • The BIG-IP host may stop responding and fail over to a standby host or another host in the device group.
  • You may observe a TMM core file in the /shared/core directory.

Resolution

Status

F5 Product Development has assigned ID 408104 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the top right corner of the article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, you can use the Priority FIFO (PFIFO) queueing method instead of SFQ. To do so, perform the following procedure:

Impact of workaround: Differences in the queueing methods may change how the BIG-IP system dequeues packets.

  1. Log in to the Configuration utility as the admin user.
  2. Navigate to Network > Rate Shaping.
  3. Select the rate-shaping profile you would like to change.
  4. Change the General Properties from Basic to Advanced.
  5. Under Queue Method, change the method from SFQ to PFIFO.
  6. Click Update.

Note: In BIG-IP 11.4.0, the Rate Shaping option moved to the Acceleration menu.
