Description

In certain cases where heavy UDP traffic traverses a properly configured virtual server, the BIG-IP system may experience port exhaustion.

For example, if you use a high-speed logger on your network which is operated behind a UDP virtual server on UDP port 514, and one appliance that utilizes this service sends profuse levels of syslog traffic to the virtual server, you may experience this issue.

Environment

Protocol profile for virtual server

Cause

The default UDP profile will use an idle timeout value of 60 seconds, such as this example profile:

ltm profile udp /Common/sample_udp_profile {
    app-service none
    datagram-load-balancing enabled
    defaults-from /Common/udp
    idle-timeout 60
}

It's notable that TMM will create a connection table entry for every UDP session that traverses, but these connections are not reused, and in this case, they take one minute to time out. Where heavy traffic is experienced, it is possible for a single node to exceed the port exhaustion thresholds, thus resulting in port exhaustion warnings.

Recommended Actions

Reduce the idle-timeout setting to a maximum of 5 seconds, especially for high-traffic UDP applications. To do so, perform the following procedure:

Impact of procedure: The impact of the following procedure depends on the changes you apply through the local traffic profile. Always ensure modifications are compatible with your environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the BIG-IP Advanced shell (bash).
  2. Enter the following command:

    tmsh

  3. Create a new UDP profile using the following syntax:

    create /ltm profile udp <profile_name> [<property_1> <value>] [<property_2> <value2>] ... [<property_n> <value>]

    For example, to create a UDP profile named udp_example with an idle-timeout of 5 seconds and datagram-load-balancing enabled, enter the following command:

    create /ltm profile udp udp_example idle-timeout 5 datagram-load-balancing enabled

  4. Enter the following command to save the changes:

    save /sys config

  5. In order to apply the new UDP profile to the virtual server, you need to first remove the existing UDP profile, then add the new UDP profile to the virtual server. To avoid errors when a profile has dependencies, make the changes in batch mode. Use the following syntax to create a transaction and enter into batch mode:

    create /cli transaction

    The command line displays [batch mode].

    Note: You can get help by entering the command help /cli transaction.

  6. Add a command to the transaction to remove the UDP profile you want to replace. To do so, use the following syntax:

    modify /ltm virtual <virtual_name> { profiles delete { <profile name> }}

    For example, this command removes the default UDP profile from the virtual server named vs_example:

    modify /ltm virtual vs_example { profiles delete { udp }}

  7. Add the new UDP profile to the virtual server by using the following syntax:

    modify /ltm virtual <virtual name> { profiles add { <profile name> }}

    For example, this command adds the udp_example profile to the virtual server:

    modify /ltm virtual vs_example { profiles add { udp_example }}

  8. (Optional) Review the commands in the transaction by entering the following command:

    list /cli transaction

  9. Submit the transaction by entering the following command:

    submit /cli transaction

  10. Save the configuration change to disk by entering the following command:

    save /sys config
