Issue

When a virtual server with an HTTP profile receives unexpected HTTP data, the BIG-IP system logs an error message to the /var/log/ltm file. The error message appears similar to one of the following examples, depending on your specific version:

  • BIG-IP 11.4.0 and later

    err tmm[PID]: 011f0007:3: http_process_state_prepend - Invalid action:0x109010 (Server side: vip=<vipname> profile=<httpprofile> server_ip=<ip_address>)

  • Versions prior to BIG-IP 11.4.0

    err tmm[PID]: 011f0007:3: http_process_state_prepend - Invalid action EV_INGRESS_DATA during ST_HTTP_PREP END_HEADERS (Server side: vip=<vipname> profile=<httpprofile> pool=<poolname>)

Any response that is not compliant with Internet Engineering Task Force (RFC 7230) causes this error message, such as a web server response that includes a Content-Length header indicating a smaller value than the length of the data in the response. Another common cause of this error message is an extra HTTP 100 Continue message, which may be included in a POST response by Microsoft Internet Information Services (IIS) version 6.0. To identify the specific cause of error messages, you must analyze the HTTP traffic with tools, such as tcpdump and Wireshark, and locate requests that do not conform to RFC 7230.

If the BIG-IP system that reports the error message is the active unit, the system also immediately sends a RST packet to the client, resetting the client-side connection.

If a virtual server is configured to mirror its connections to the standby unit, the standby BIG-IP system may log this error message. The error is most frequently seen when the virtual server is also configured to manipulate the server response. For example, when OneConnect, HTTP pipelining, compression, or caching are enabled in the HTTP profile.

When seen on the standby BIG-IP system, this message indicates that the HTTP response packets were mirrored to the standby BIG-IP system and before the mirrored packets containing the request had been parsed by the standby BIG-IP system. This causes a state-tracking failure in the HTTP processing engine, triggering the error message.

If the BIG-IP system that reports the error message is the standby unit, the BIG-IP system removes the connection from its connection table, and discards any further packets received for this mirrored flow. Because the connection is no longer valid in the context of the standby unit, upon failover, the newly active BIG-IP system sends a RST packet in response to any packets sent on the connection.

To eliminate these messages on the standby BIG-IP system, disable connection mirroring for the affected virtual server.

Important: F5 does not recommend connection mirroring for HTTP virtual servers. HTTP clients typically resubmit unanswered requests, and in most cases, recover gracefully after failover without user intervention. Therefore, the overhead incurred by mirroring HTTP connections is excessive given the minimal advantages.

If connection mirroring must be configured, you may attempt to minimize the number of error messages logged by the standby BIG-IP system by disabling all HTTP profile options that manipulate the server response (for example, HTTP pipelining, OneConnect, Compression and Caching). However, because mirrored packets may not be parsed by the standby BIG-IP system in the intended order, this approach may not eliminate all occurrences of these error messages.
