Known Issue

Redundant vCMP guests may simultaneously enter an active state when the standby guest is starting up.

This issue is caused during startup when the secondary guest's sod process incorrectly receives configuration data from the secondary mcpd process before mcpd has received updated configuration data. As a result, sod instructs the standby vCMP guest to enter an active state.

Impact

The vCMP redundant pair may temporarily fail to pass traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H406738 on the Diagnostics > Identified > Low screen.
  • The standby vCMP guest logs messages to the /var/log/ltm file indicating that the guest is in an active state. The messages appear similar to the following examples:

    notice sod[5012]: 010c0053:5: Active for traffic group /Common/traffic-group-1.    
    notice sod[5012]: 010c0019:5: Active

  • The standby vCMP guest sends gratuitous ARP requests after it has finished booting up.
  • The redundant vCMP guests experience an IP conflict.
  • The active vCMP guest generates IP conflict error messages to the /var/log/ltm file that appear similar to the following example:

    slot1/tmm warning tmm[6024]: 01190004:4: address conflict detected for 10.10.93.80 (00:23:e9:06:1a:c4) on vlan 262

  • The vCMP redundant pair may temporarily fail to pass traffic.

Workaround

To work around this issue, you can edit the /etc/bigstart/scripts/sod script and slightly delay the startup time for the sod process. To do so, perform the following procedure:

Note: Changes made to the /etc/bigstart/scripts/sod script file are not sync'd between BIG-IP systems. Additionally, the file is not saved in a UCS archive.

Impact of workaround: This procedure causes the sod process to start up slower, and may also slightly increase the vCMP guest bootup time.

  1. Log in to the command line.
  2. Use a text editor to edit the /etc/bigstart/scripts/sod file.
  3. Locate the following section of the file:

    # set resource limits, affinity, etc
    setproperties ${service}

  4. Add a sleep statement directly following the lines in Step 3.

    For example:

    # set resource limits, affinity, etc
    setproperties ${service}
    # --- add this line to delay sod startup
    sleep 25
    # record that we're starting
    logthestart ${service} ${start_cnt}

  5. Save the changes and exit the file.
