Description

You observe that many files like the following are created in the /shared partition:

1162530 /shared/tmp/ts_db.save_dir_5531.cstmp/ts_db.data.PRX.REQUEST_LOG.cstmp.traffic_data
1162540 /shared/tmp/ts_db.save_dir_2858.cstmp/ts_db.data.PRX.REQUEST_LOG.cstmp.traffic_data
1107928 /shared/tmp/ts_db.save_dir_32316.cstmp/ts_db.data.PRX.REQUEST_LOG.cstmp.traffic_data
1100348 /shared/tmp/ts_db.save_dir_29730.cstmp/ts_db.data.PRX.REQUEST_LOG.cstmp.traffic_data

Similar files return even after manual deletion, and this leads to the /shared partition being filled.

Environment

  • ASM provisioned
  • Disk space

Cause

The system creates these ts_db.save_dir_xxxx.cstmp directories under /shared/tmp during a UCS save. They contain ASM-related files which will be included in the UCS. Under normal conditions they are all deleted when the UCS save completes. However, there is a way they can get left behind.

If the UCS save doesn't complete successfully, or is cancelled (for example, the tmsh is killed, or the SSH session is killed), all of these files will be left behind and will need to be manually deleted.

Recommended Actions

It's completely safe to delete these files.

Investigate any external scripts that may periodically connect to the system and save a UCS file. If this operation is not completing successfully, it's highly likely to be the cause of this issue.

Additional Information

Various files from different modules are saved to /shared temporarily during a UCS save.
