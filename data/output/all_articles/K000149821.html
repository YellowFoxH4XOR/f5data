Description

This article explains how to distinguish between TCP health monitor probe packets and regular TCP 3-way handshake packets in a packet capture (pcap). This distinction is essential for identifying whether traffic is related to health monitoring or actual application communication.

By analysing pcap data, we can differentiate these two types of connections based on the TCP handshake process and the behaviour of TCP flags (SYN, ACK, RST).


Environment

  • Health Monitor Probes
  • Wireshark
  • TCP probe

 

Cause

TCP health monitor probes are designed to check the availability of backend servers without establishing a full connection. This is achieved through a half-open TCP handshake, followed by an immediate termination using a reset (RST) packet.
Regular TCP handshakes, on the other hand, involve completing a full 3-way handshake to establish a persistent connection for data transfer.

Key Differences and Packet Capture Examples

  1. TCP Health Monitor Probe
    • Half-open TCP Handshake:
      • SYN → SYN-ACK → RST
    • The probe sends a SYN packet.
    • The backend server responds with a SYN-ACK.
    • The probe immediately sends an RST packet to terminate the connection without completing the handshake.
    • No data transfer occurs after the handshake.
      Example from Packet Capture:

      10:14:00.000 IP <Monitor_IP>.1259 > <Server_IP>. 80 [SYN] Seq=0 Win=29200 Len=0 MSS=1460 SACK_PERM TSval=4134368345 TSecr=0 WS=128
      10:14:00.001 IP <Server_IP>.80 > <Monitor_IP>.1259: [SYN, ACK] Seq=0 Ack=1 Win=65160 Len=0 MSS=1460 SACK_PERM TSval=3138099260 TSecr=4134368345 WS=128

      10:14:00.002 IP <Monitor_IP>.1259 > <Server_IP>. [RST, ACK] Seq=1 Ack=1 Win=0 Len=0

      Key Indicator: Look for the immediate RST packet after the SYN-ACK with no data transfer.


  2. Regular TCP 3-Way Handshake
    • Full TCP Handshake:
      • SYN → SYN-ACK → ACK → (Data Transfer)
    • The client (SNIP) sends a SYN packet.
    • The server responds with a SYN-ACK.
    • The client sends an ACK to complete the handshake, followed by data transfer.
      Example from Packet Capture:

      20:00:00.000 IP <Client_IP>.44320 > <Server_IP>.443: Flags [S], seq 0 
      20:00:00.001 IP <Server_IP>.443 > <Client_IP>.44320: Flags [S.], seq 0, ack 1 
      20:00:00.002 IP <Client_IP>.44320 > <Server_IP>.443: Flags [ACK], seq 1, ack 1 

      Key Indicator: Look for the ACK packet completing the handshake, followed by data packets.

 

Recommended Actions

 

  1. Packet Capture Analysis
    • Use tcpdump or Wireshark to capture traffic and filter packets by TCP flags (SYN, ACK, RST) and port numbers.
    • Ensure traffic is captured on both the management and TMM interfaces for a comprehensive view.
  2. Monitor TCP Window Size
    • Health monitor probes typically have a window size of 29200 bytes in the TCP SYN packet.
    • This value is commonly observed and optimized for health monitoring use cases.
  3. Example TCP SYN Packet (Health Monitor Probe):

    Seq=0 Win=29200 Len=0 MSS=1460 SACK_PERM=1 TSval=<timestamp> TSecr=0 WS=128 


    Additional Information

  • The TCP window size value of 29200 is frequently seen in health monitor probe packets.
  • This value indicates the amount of data (in bytes) the sender is willing to receive before requiring an acknowledgment.
  • Multiple packet captures from various cases confirm this behavior, showing Win=29200 in the SYN packets of health monitor probes.
