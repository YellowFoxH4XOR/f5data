Known Issue

F5 SSL Orchestrator may fail to resolve the host name in an explicit-proxy request for HTTP sites.

This issue occurs when all of the following conditions are met:

  • You have deployed an explicit proxy on F5 SSL Orchestrator 14.1.0-5.0 through 14.1.0-5.3.
  • You have configured a local DNS server for the Local Forwarding NameServer(s) option in the DNS Settings section on the SSL Orchestrator Settings page.

Impact

Clients cannot access HTTP sites via the explicit-proxy deployed on F5 SSL Orchestrator.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The client’s explicit-proxy request containing HTTP traffic fails to be processed by F5 SSL Orchestrator. However, HTTPS traffic works as expected.
  • An affected client's browser returns an HTTP 404 error with syntax similar to the following example:

    Cannot resolve hostname ‘<website>’ in explicit-proxy request

  • In the /var/log/ltm file, you observe a log message with syntax similar to the following example:

    Rule /Common/sslo_explicit_sslo.app/sslo_explicit_sslo-xp <HTTP_PROXY_REQUEST>: Cannot resolve hostname 'f5.com' in explicit-proxy request

Workaround

To work around this issue, you must restart the named process manually. To do so, perform the following procedure:

Impact of workaround: Configurations that depend on the named process may temporarily stop functioning while the process restarts.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the named process by typing the following command:

    restart /sys service named
