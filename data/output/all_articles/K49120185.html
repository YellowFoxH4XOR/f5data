K49120185: VPN users cannot access HTTP service intermittently

Type
Support Solution
Published
2021-03-03
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP APM: 12.1.5
Source
https://my.f5.com/manage/s/article/K49120185

Description

  • Users connected through VPN intermittently fail to access HTTP applications/websites
  • Problem is not observed when accessing HTTPS or SSH applications/websites
  • Same users are able to access the same HTTP application if they disconnect and reconnect to VPN

Environment

  • BIG-IP APM
  • VPN users
  • HTTP application


Cause

On BIG-IP APM Network Access, a virtual server (VS) called _tmm_apm_fwd_vip_http which has an HTTP profile is automatically created internally. An administrator is not able to modify or disable this virtual. HTTP traffic will go through this internal APM ACL listener. Occasionally, this virtual server will use a self-IP as the source IP to communicate with the HTTP application backend servers, which causes the connection to fail as the backend servers expect source IPs defined from a lease pool.

The traffic capture below shows the failure. Based on the VPN PPP IP, we can observe that the VS _tmm_apm_fwd_vip_http uses the self-IP as the source address to communicate with the HTTP server but gets no response because the source IP address is not allowed access to the backend application. 

Note: Here 10.10.10.10 is the VPN PPP IP, the 192.168.100.1 is the Self-IP, 172.16.10.1 is the HTTP application server
 

1   10.10.10.10      56341    172.16.10.1   80    HTTP  _tmm_apm_fwd_vip_http    IN  s3/tmm0 : GET / HTTP/1.1 
2   192.168.100.1    42976    172.16.10.1   80    TCP   _tmm_apm_fwd_vip_http    OUT s3/tmm0 : 42976 → 80 [SYN] 
3   192.168.100.1    42976    172.16.10.1   80    TCP   _tmm_apm_fwd_vip_http    OUT s3/tmm0 : [TCP Retransmission] 42976 → 80 


A working example below shows the _tmm_apm_fwd_vip_http using the VPN PPP IP as the source to communicate to the HTTP server:
 

1   10.10.10.10      1652     172.16.10.1    80    TCP    _tmm_apm_fwd_vip_http    OUT s1/tmm0 : 1652 → 80 [SYN]
2   172.16.10.1      80       10.10.10.10    1652  TCP    _tmm_apm_fwd_vip_http    IN  s1/tmm0 : 80 → 1652 [SYN, ACK]
3   10.10.10.10      1652     172.16.10.1    80    TCP    _tmm_apm_fwd_vip_http    OUT s1/tmm0 : 1652 → 80 [ACK]
4   10.10.10.10      1652     172.16.10.1    80    HTTP   _tmm_apm_fwd_vip_http    OUT s1/tmm0 : GET / HTTP/1.1 


Recommended Actions

Create a new IP forwarding VS with the following configuration:
  • Source Address is same as the VPN lease pool
  • Destination Address/Mask is the target HTTP website. If there are multiple HTTP servers from different subnets, use 0.0.0.0/0
  • Service Port is 80 for HTTP
  • Leave others as default
