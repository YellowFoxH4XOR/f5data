K000137417: SSH public key authentication stops working after an upgrade

Description

You configured SSH public key authentication on your BIG-IP device by creating a symlink /home/<user>/.ssh/authorized_keys to /etc/ssh/<user>/authorized_keys . After upgrade, SSH public key authentication stops working, and you are prompted to enter a password.

For example, you configured SSH public key authentication for user bigipadmin. 

Before upgrade

# ls -l /etc/ssh/bigipadmin/

total 1

-rw-------. 1 root webusers 751 2023-09-27 23:33 authorized_keys

# ls -l /home/bigipadmin/.ssh/

total 1

lrwxrwxrwx. 1 root webusers 33 2023-09-28 01:19 authorized_keys -> /etc/ssh/bigipadmin/authorized_keys

Actual authorized_keys is placed in /etc/ssh/bigipadmin/ and a symlink was created to it in /home/bigipadmin/.ssh/ .

After upgrade

# ls -l /etc/ssh/bigipadmin/

total 0

# ls -l /home/bigipadmin/.ssh/

total 1

lrwxrwxrwx. 1 35636 webusers 33 Sep 28 01:48 authorized_keys -> /etc/ssh/bigipadmin/authorized_keys

After upgrade, /etc/ssh/bigipadmin/authorized_keys is missing. The symlink /home/bigipadmin/.ssh/authorized_keys points to /etc/ssh/bigipadmin/authorized_keys which is non-existent. SSH public key authentication breaks for user bigipadmin.

When attempting to use SSH public key authentication:

# ssh bigipadmin@<BIG-IP IP address>

Password:

The BIG-IP prompts for password as authorized_keys is missing.

 

Environment

  • BIG-IP LTM
  • SSH public key authentication configured, by creating a symlink for /home/<user>/.ssh/authorized_keys to /etc/ssh/<user>/authorized_keys
  • Upgrade from a version affected by Bug ID 581921
  • Upgrade to any higher version

Cause

Bug ID 581921

Recommended Actions

Follow the workaround of Bug ID 581921 .
