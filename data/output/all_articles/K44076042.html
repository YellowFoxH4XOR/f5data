Known Issue

Idle Secure Sockets Layer (SSL) connections may not be removed from the connection table on a standby BIG-IP system.

This issue occurs when all of the following conditions are met:

  • BIG-IP systems, in a high availability (HA) device group, are set in an active-standby configuration.
  • The SSL virtual server is configured to mirror connections.
  • The HA mirroring connection between active and standby BIG-IP systems is interrupted and then re-established.

When the HA mirroring connection between the active and standby systems is interrupted and then re-established, a sweeper process on the standby BIG-IP system incorrectly refreshes the idle timeout for mirrored SSL connections.

Impact

SSL connections that are idle longer than the specified idle timeout are not removed from the connection table on a standby BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The idle timeout on a mirrored SSL connection is constantly refreshed while the connection is idle.
  • Current connection statistics for SSL virtual servers are different on the active and standby BIG-IP systems.
  • Over time, standby unit performance degrades, and the standby unit eventually becomes unresponsive or reboots due to memory exhaustion.

Workaround

To work around this issue, you can temporarily disable and then re-enable connection mirroring for the affected SSL virtual servers. To do so, perform the following procedure:

Note: You should additionally identify, and resolve if needed, the reason the HA mirror connectivity was interrupted.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the affected virtual server.
  4. From the Configuration menu, select Advanced.
  5. Clear the Connection Mirroring check box.
  6. Click Update.
  7. Select the Connection Mirroring check box.
  8. Click Update.
  9. Repeat this procedure for any other affected virtual servers.
