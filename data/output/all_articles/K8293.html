Known Issue

This is the result of a known issue. During the upgrade process, the BIG-IP system's time zone is initially set to the default Pacific time zone, then reset back to the time zone contained in the pre-upgrade configuration. System daemons that are started when the default Pacific time zone is configured may continue to log messages using the default Pacific time zone until they are restarted, while other daemons may simultaneously log messages using the configured time zone. In addition, the timestamp on the initial boot_marker log entry may be logged using the default time zone. The incorrect timestamp displayed in affected log messages is cosmetic, and does not affect the functioning of the BIG-IP system.

F5 Product Development tracked this issue as CR83163 and it was fixed in BIG-IP version 9.6.0 and BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

F5 Product Development is also tracking this issue as CR83163 for the BIG-IP 9.3.x and 9.4.x software branches.

Workaround

In order to ensure all the BIG-IP system daemons operate and log properly once the time zone has been changed, reboot the BIG-IP system again once the first boot has completed. To do so, restart the BIG-IP system by typing the following command:

reboot

Note: If you are installing a hotfix immediately after installing the base software, the extra reboot is not required. Rebooting again as required to complete the hotfix installation is sufficient to realign the time zone configuration.
