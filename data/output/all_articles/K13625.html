Topic

The Simple Network Management Protocol (SNMP) is typically used for managing devices on the IP network. SNMP has evolved from version 1, to version 2c, to version 3. This article provides information about SNMP version 3 (SNMPv3) agent access on the BIG-IP system.

Description

SNMPv3 introduces security and administrative framework features that previous versions of SNMP were lacking. For example, previous SNMP versions use a community string that is sent in clear text for authenticating any request from any agent. Depending on the network environment, this may pose as a security risk to organizations. In SNMPv3, security features, such as the user-based security model, provide the encryption for privacy protocol and MD5 or SHA digests for authentication protocol.

The BIG-IP system supports the configuration and usage of SNMPv3 for agent access. However, SNMP traps continue to use previous SNMP versions. You can configure SNMPv3 on the BIG-IP system by navigating to System > SNMP > Agent > Access (v3), and then clicking the Create button. Security levelDefinition
noAuthNoPrivUsername is required to make queries, but no authentication and no encryption will be performed. Similar to SNMPv1.

Performing an SNMPv3 query

You can perform an SNMPv3 query using the following command syntax:

<snmp command> -v 3 -u <username> -a <authentication hash> -A <authentication password> -x <encryption> -X <authentication password> -l <security level> <IP address of system being queried> <OID>

Note: If the password contains special characters, such as an exclamation mark ( ! ), it must be escaped ( \! ) and not enclosed in double quotes ( " ) to prevent processing as a bash event.

The following list provides examples of performing an SNMPv3 query using SNMP commands, such as snmpget or snmpwalk, for different security levels:

  • An SNMPv3 user snmp3user is configured with authentication type SHA, authentication password snmpauth, privacy protocol AES and privacy password snmppriv. This configuration combination yields a security level of authPriv. For example, to perform an SNMPv3 query for this configuration combination, you can enter the snmpget command, similar to the following example:

    snmpget -v 3 -u snmp3user -a SHA -A "snmpauth" -x AES -X "snmppriv" -l authPriv localhost sysSystemUptime.0

    The command may return the following response:

    F5-BIGIP-SYSTEM-MIB::sysSystemUptime.0 = Timeticks: (25545600) 2 days, 22:57:36.00

  • An SNMPv3 user snmp3authonly is configured with authentication type SHA and authentication password authnopriv, no privacy protocol, and no privacy password is configured. This configuration combination yields a security level of authNoPriv. For example, to perform an SNMPv3 query for this configuration combination, you can enter the snmpget command, similar to the following example:

    snmpget -v 3 -u snmp3authonly -a SHA -A "authnopriv" -l authNoPriv localhost sysSystemUptime.0

    The command may return the following response:

    F5-BIGIP-SYSTEM-MIB::sysSystemUptime.0 = Timeticks: (25600800) 2 days, 23:06:48.00

  • An SNMPv3 user snmp3noauthnopriv is configured with no authentication type, no authentication password, no privacy protocol, and no privacy password. This configuration combination yields a security level of noAuthNoPriv. For example, to perform an SNMPv3 query for this configuration combination, you can enter the snmpget command, similar to the following example:

    snmpget -v 3 -u snmp3noauthnopriv -l noAuthNoPriv localhost sysSystemUptime.0

    The command may return the following response:

    F5-BIGIP-SYSTEM-MIB::sysSystemUptime.0 = Timeticks: (25617400) 2 days, 23:09:34.00

If the security level is specified incorrectly, the SNMP command fails to obtain the results and may return an error message that appears similar to the following example:

Error in packet Reason:
authorizationError (access denied to that object)
