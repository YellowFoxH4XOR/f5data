Known Issue

The BIG-IP system may experience a slow memory leak when it is using HTTP cache. 

This issue occurs when all of the following conditions are met:

  • The system is using the HTTP cache feature.
  • The system is in the process of refreshing a cached document.

Impact

The BIG-IP system experiences degraded performance due to memory leaks, and the system may stop responding. The magnitude and speed of the leak depends on the number of times a cached document is refreshed.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system leaks memory because memory is not being freed.
  • BIG-IP system performance is degraded due to memory consumption.
  • The BIG-IP system runs out of memory and stops responding.

Workaround

To work around this issue, you can avoid refreshing cached documents. 

Impact of workaround: The impact and feasibility of this workaround is dependent on the customers particular configuration and needs.

If the document cannot be refreshed, the memory leak will not occur.

A server configuration change or a response iRule that removes the Last-Modified, Expires, and Cache-Control headers may allow the BIG-IP system to cache documents and serve them from cache, but will not attempt to refresh them and thus avoid this leak. Configuring such an iRule is specific to each implementation and outside the scope of this article.
