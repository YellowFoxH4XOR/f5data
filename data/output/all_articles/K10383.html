Known Issue

This is the result of a known issue. It is possible to configure a VLAN named default and enable it on a virtual server using the Configuration utility. However, using bigpipe commands to further modify any configuration object or to reload the configuration will fail. The changes are saved to the configuration file, but the system is unable to load the modified configuration containing the VLAN named default.

If you attempt to use bigpipe commands to modify a configuration containing a VLAN named default, you may observe the following effects:

  • The bigpipe command silently ignores an attempt to set a VLAN named default as enabled or disabled for a virtual. This occurs whether you are creating or modifying the virtual server associated with the VLAN named default.
  • Using the bigpipe virtual <vs_name> {vlan default} command (without the enable or disable keyword) does not reset the virtual server's VLAN association to the default setting of none disable, and does not produce an error or warning message. Attempting to modify VLAN associations for any virtual server using the bigpipe virtual command to enable or disable all VLANs (using the keyword all or none with the keyword enable or disable, such as bigpipe virtual <vs_name> {vlan all enable}) does not modify the VLAN association, and generates an error message that appears similar to the following example:

    BIGpipe parsing error:
    012e0010:3: The requested value (all enable) is invalid ((<vlan key list> | all | none) (enable | disable)) for 'vlans' in 'virtual'
  • A VLAN named default can be assigned to a virtual from the Configuration utility only. If you attempt to assign the VLAN to a virtual server using the bigpipe command, the system does not apply the change. If the configuration is reloaded using the bigpipe command (manually, upon reboot, or after configsync), the VLAN association is ignored.
  • Modifications to any other configuration objects, including direct modification of the configuration files such as the bigip.conf and profile_base.conf files will not take effect.

F5 Product Development is tracking this issue as CR124723.

Note: This issue does not apply to BIG-IP 10.x.

Workaround

You can work around this issue by removing the VLAN or renaming the VLAN to a name other than default, then reloading the configuration.
