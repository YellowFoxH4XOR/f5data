K05401029: Configuration failed to load with FIPS 140 operations not available on this system

Type
Support Solution
Published
2021-02-25
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K05401029

Description

When customer boot device back to v15 from v16, configuration failed to load with below error message:

err mcpd[9776]: 01070712:3: Caught configuration exception (0), FIPS 140 operations not available on this system.
emerg load_config_files[14343]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01070712:3: FIPS 140 operations not available on this system
err mcpd[9776]: 01070712:3: Caught configuration exception (0), FIPS 140 operations not available on this system.
err tmsh[27530]: 01420006:3: Attempt to open FIPS 140 subsystem failed.
err tmsh[27545]: 01420006:3: Attempt to open FIPS 140 subsystem failed.

Environment

  • FIPS Hardware
  • Upgrade between v15 and v16

Cause

Due to Bug ID 969637, Config load failed with "FIPS 140 operations not available on this system" after upgrade to 15.1.1

Recommended Actions

1. Using a text editor, delete all FIPS keys referenced in the /config/bigip.conf file.

Note: Delete the TMOS objects (likely "sys file ssl-key" objects) that reference the HSM (and anything that references _those_ key objects, e.g. SSL profiles, and then anything that references _those_ objects) -- at some point, you may find it easier to update SSL profiles to simply point at default.key and default.crt, rather than chasing the entire tree of objects and removing them from /config/bigip.conf.

2. Delete all FIPS keys in the /config/ssl/ssl.cavfips directory by typing the following command:
rm -rf /config/ssl/ssl.cavfips/*

3. Delete all FIPS keys referenced in the /config/filestore/files_d/partition-name/certificate_key_d/ directory.

4. To load the system configuration, type the following command:
tmsh load sys config partitions all

5. To save the system configuration, type the following command:
tmsh save sys config partitions all

Recovering FIPS from the configuration load failure
