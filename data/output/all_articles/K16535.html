Known Issue

The System Activity Report (sar) utility fails to run due to corrupt report files.

This issue occurs when the following condition is met:

  • The sar utility report files exceed the logrotate utility's maxsize file setting.

The sar utility is a system monitoring tool used to report kernel system load, including CPU activity, memory/paging, and device load. The sar utility logs binary and XML files in the /var/log/sa directory. If the binary files exceed the default maximum file size of 1024 KB, the logrotate utility attempts to split the binary file and the file becomes corrupted. The XML files are unaffected.

Impact

Kernel statistics that you normally view with the sar utility may be corrupt and unavailable.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When using the sar utility to view kernel statistics, you may view a message that appears similar to the following example:

    sar -f /var/log/sa.1

    Invalid system activity file: sa.1 (0xa05)

Workaround

To work around this issue, you can either disable log file splitting by setting the logrotate maxsize setting to zero, or increasing the maxsize value above the size of the largest expected sar binary file. To do so, perform the following procedure:

Impact of workaround: Adjusting the maxsize parameter for logrotate affects all log files.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Modify the logrotate maxsize value using the following command syntax:

    modify /sys log-rotate max-file-size <size>

    For example, to adjust the file size to 2048 KB, type the following command:

    modify /sys log-rotate max-file-size 2048

  3. Save the change by typing the following command:

    save /sys config
