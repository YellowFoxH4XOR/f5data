K000157139: VELOS Chassis Controller Generates Outbound Connections to Docker Hub (registry-1.docker.io)

Type
Support Solution
Published
2025-10-27
Updated
2025-10-27
Applies to
  • F5OS
  • F5OS-C: 1.5.0, 1.6.0, 1.5.1, 1.8.1, 1.8.0, 1.6.4, 1.6.2, 1.6.1, 1.8.2
Source
https://my.f5.com/manage/s/article/K000157139

Description

VELOS chassis controllers running Openshift-based F5OS may generate outbound connections every 5 seconds to external IP addresses associated with registry-1.docker.io over port 443. These repeated connection attempts are directed at Docker Hub endpoints and may be detected or blocked by network firewalls or monitoring systems.

Environment

Openshift-based F5OS (Below version 2.0.0)

Cause

The observed outbound traffic to registry-1.docker.io is caused by the Ansible Service Broker (ABS) component within the F5OS platform. The ABS pod utilizes a ConfigMap ("broker-config") that includes Docker Hub as a default external registry endpoint, resulting in periodic attempts to reach Docker Hub regardless of local image requirements. This behavior is tracked under Bug alias 2053373 and is related to the current use of OpenShift in the F5OS architecture.

Recommended Actions

Outbound traffic from VELOS chassis controllers to registry-1.docker.io (Docker Hub) can be safely blocked at the firewall without affecting core system functionality. This issue will be addressed in a future release of F5OS (planned for an upcoming 1.8.x version or latest by 2.0.0).
