Topic

You should consider using this procedure under the following condition:

  • You want to configure an HTTP (or HTTPS) monitor receive string to accept double-byte character sets (DBCS).

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the Configuration utility.
  • You have access to the BIG-IP command line.
  • You have the Wireshark program or a similar utility installed on your workstation.

Description

You can configure a BIG-IP HTTP monitor to check for double-byte characters in content that returns from the pool member. To do this, you can capture traffic that contains double-byte characters from the pool member, then convert the characters to a hexadecimal string by using a utility like Wireshark, and then configure the HTTP health monitor to look for the string.

Procedures

Capturing traffic containing double-byte characters from the pool member

Before you can configure the HTTP monitor to check for double-byte characters, you must capture traffic that contains the double-byte characters from the pool member. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Use the following tcpdump syntax to start a packet capture that contains the double-byte characters:

    tcpdump -s0 -nni 0.0 host <poolmbr_ip> and port <port> -w /var/tmp/<tcpdump>.dmp

    For example, the following tcpdump command captures traffic from pool member 192.168.10.10:80 to the file doublebyte.dmp:

    tcpdump -s0 -nni 0.0 host 192.168.10.10 and port 80 -w /var/tmp/doublebyte.dmp

  3. While the packet capture is running, open a second console window and send an HTTP/1.1 GET request to the pool member.

    For example, to send an HTTP/1.1 GET request to pool member 192.168.10.10:80, type the following command, and then press Enter:

    telnet 192.168.10.10 80

  4. At the prompt, enter an appropriate HTTP request line and HTTP headers. Press Enter once after each line.

    For example:

    GET / HTTP/1.1 <enter>
    Host: www.yoursite.com <enter>
    Connection: close <enter>
    <enter>

  5. Stop the tcpdump capture in step 2 by typing the following command sequence:

    Ctrl+C

  6. Use Secure Copy (SCP) to copy the tcpdump capture file to your local workstation.

    Note: For information about transferring files to or from an F5 system, refer to K175: Transferring files to or from an F5 system.

Displaying the tcpdump capture file in Wireshark

After you copy the tcpdump capture file to your local workstation, open the capture file using the Wireshark program, and then copy the double-byte characters as Offset Hex Text. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Open the Wireshark utility on your local workstation.
  2. Click File.
  3. Click Open.
  4. Open the tcpdump capture file.
  5. Click Analyze.
  6. Click Decode As.
  7. Click the Transport tab.
  8. Select HTTP from the protocol list.
  9. Click OK.
  10. Locate the pool member response.

    The response is most likely an HTTP/1.1 200 OK response code.

  11. Locate the data portion of the HTTP response that represents the double-byte characters.

    The HTML code on the pool member may display double-byte characters that appear similar to the following example:

    <p>??</p>

    Wireshark displays the previous string as follows:

    0000 00 3c 00 70 00 3e 00 00 8a 49 84 3c 00 2f 00 70 .<.p.>...I.<./.p
    0010 00 3e 00 0d .>..

    In the previous example, <p> is encoded in hexadecimal numbers as 3c 70 3e, and </p> is encoded in hexadecimal numbers as 3c 2f 70 3e. The double-byte content is encoded as 8a 49 84.

  12. Right click the double-byte characters.
  13. Click Copy.
  14. Click Bytes.
  15. Click Offset Hex Text.
  16. Paste the Offset Hex Text to a text file to create the monitor receive string.

Creating the HTTP monitor

When you create the HTTP monitor, use the hexadecimal-encoded content obtained from the previous procedure to define the monitor receive string. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Monitors.
  3. Click Create.
  4. From the Type box, select HTTP.
  5. Type a name for the monitor.
  6. In the Receive String box, format the hexadecimal-encoded double-byte characters.

    For example, in the previous procedure, the hexadecimal-encoded characters are 8a 49 84.

    Format the receive string as follows:

    \x8a\x49\x84

  7. Click Finished.
  8. You can now associate the monitor with the pool.
