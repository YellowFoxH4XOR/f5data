Topic

You should consider using these procedures under the following conditions:

  • You are new to using the iControl representation state transfer (REST) application programming interface (API).
  • You want a basic example of using REST commands to create an SSL VPN access profile and policy for use with a virtual server.

Description

The following REST command examples show you how to use REST commands to create an SSL VPN access profile and policy with user authentication that you can configure in the virtual server Access Policy > Access Profile and Connectivity Profile settings. For more information on using iControl REST API to create a virtual server refer to: K13225405: Common iControl REST API command examples. F5 recommends that you use a common base name for all objects and prefacing object names for profile, policy, agent, and policy item suffixes. This article uses <base name> in command syntax and the example configurations use simple-vpn as the base name. When you create an access policy, all objects are interdependent and there are a considerable number of objects used to create the SSL VPN access profile and policy. Keep in mind when using the iControl REST API to create an access profile and policy, nothing is assumed and each required configuration object will need to be individually created using a REST API command.

The sections in this article use cURL with two distinct methods of HTTP POST. The first method is a standard HTTP post to the iControl REST API IP address. The second requires the additional POST parameters X-F5-REST-Coordination-Id:<ID>, where the ID must be generated prior using REST syntax. The transaction style POST is used when implementing (validating) the interconnecting configuration objects that create the access profile and policy as presented in the Virtual Policy Editor (VPE).

In most cases, you can view an object's configuration using the GET method and the Uniform Resource Identifier (URI) of the specific object. Viewing objects with a REST command can produce verbose JSON output. To format the JSON output to a more user-friendly format, use the jq command line JSON processor command. The jq command -M flag sets the formatted JSON output to use monochrome when displaying the JSON output.  The '.' (period) parameter is optional in jq 1.5 and later. 

curl -sk -u admin:default GET https://10.95.0.55/mgmt/tm/apm/policy/access-policy/~Common~simple-vpn| jq -M .

Note: The JSON output of the object configuration includes links to view additional nested configuration details.

When using the JSON links, replace localhost with the IP address of the BIG-IP system.

Typographic conventions

The following typographic conventions are used in the command syntax examples:

  • <POST> = curl -sk -u admin:<password> -H "Content-Type: application/json" -X POST https://<big-ip apm address>
  • <POST+ID> = curl -sk -X POST -u admin:<password> -H "X-F5-REST-Coordination-Id:<ID>" -H "Content-Type: application/json" https://<big-ip apm address>
  • <PATCH> = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PATCH  https://<big-ip apm address>
  • <DELETE> = curl -sk -u admin:<password>  -H "Content-Type: application/json" -X DELETE https://<big-ip apm address>
  • <GET> = curl -sk -u admin:<password>   -H "Content-Type: application/json" -X GET https://<big-ip apm address>

    Note:  For example, to run <GET> /mgmt/tm/apm/policy/access-policy/~Common~simple-vpn| jq -M, you enter curl -sk -u admin:<password> GET https://<big-ip apm address>/mgmt/tm/apm/policy/access-policy/~Common~simple-vpn| jq -M, replacing <password> and <big-ip apm address> with the appropriate administrative password and BIG-IP APM management IP address.

    Note: POST+ID requires a previous generation of a transaction ID, which is covered in the Generating the Transaction ID section.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Your BIG-IP APM system is licensed, provisioned, and configured with a management IP address.
  • You have administrative access to the BIG-IP APM Configuration utility.
  • You have command line access to a Linux system (or an alternate BIG-IP system) with the cURL and jq (command line JSON processor) utilities installed.
  • You have a general familiarity with the F5 iControl REST API syntax.

Viewing configured components

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To obtain a list of all configured BIG-IP APM component objects for each component type, use the following command syntax:

    <GET> /mgmt/tm/apm/<component type> | jq -M .

    Note: Change <component type> to one of the following component types: aaa, ntlm, resource, client, oauth, saml, configuration, policy, sso, ephemeral-auth, profile, epsec, report, acl, application-filter, swg-content-type, apm-avr-config, log-setting, url-filter, application, risk-class, application-family, or session.

  • To view a specific configuration type object use the following syntax:

    <GET> /mgmt/tm/apm/<component type>/<component object name> | jq -M .

  • To expand on the subcollections for a configuration object you can append the statement ?expandSubcollections=true to the query:

    <GET> /mgmt/tm/apm/<component type>/<component object name>?expandSubcollections=true | jq -M .

  • To view a specific configuration object that resides in a non-default partition, include the partition name prefixed and suffixed with the tilde (~) character:

    <GET> /mgmt/tm/apm/<component type>/~<partition>~<component object name> | jq -M .

  • To view all current established access sessions, use the following syntax:

    <GET> /mgmt/tm/apm/access-info | jq -M .

Creating a Radius, LDAP, TACACS+, or  Local User DB authentication server

  • To create a LDAP authentication server for an access policy to use, use the following command syntax:

    Impact of procedure: Using the following commands should not have a negative impact on your system.

    <POST> /mgmt/tm/apm/aaa/radius -d '{"name":"<base name>_act_radius_auth","acctPort":"<port>","authPort":"<port>","mode":"auth","secret":"<secret>","serviceType":"authenticate-only","address":"<radius server ip>","usePool":"disabled"}'

    Note: Replace <base name> with the chosen profile name, <port> with the Radius accounting port value and the Radius authentication port value. Replace <secret> with the Radius server requires secret and <radius server ip> with the IP address of the destination Radius server.

    For example, to create a Radius authentication server configuration with the destination authentication server configured as direct (configuration does not reference a pool, enter the following:

    <POST> /mgmt/tm/apm/aaa/radius -d '{"name":"simplevpn_act_radius_auth","acctPort":"1813","authPort":"1812","mode":"auth","secret":"testing123","serviceType":"authenticate-only","address":"192.168.1.97","usePool":"disabled"}'

    For example, to create a Radius authentication server configuration with the destination Radius authentication server residing in a pre-existing pool, enter the following:

    <POST> /mgmt/tm/apm/aaa/radius -d '{"name":"simplevpn_act_radius_auth","acctPort":"1813","authPort":"1812","mode":"auth","secret":"testing123","serviceType":"authenticate-only","address":"192.168.1.97","pool","radius_pool","usePool":"enabled"}'

  • To create a LDAP authentication server for an access policy to use, use the following command syntax:

    Impact of procedure: Using the following commands should not have a negative impact on your system.

    <POST> /mgmt/tm/apm/aaa/ldap -d '{"name":"<base name>","address":"<ldap server ip>","adminEncryptedPassword":"<password>","adminDn":"CN=<cn>,CN=<cn>,DC=<dc>,DC=<dc>","baseDn":"DC=<dc>,DC=<dc>","isLdaps":"false","port":389,"usePool":"disabled"}'

    Note: Replace <base name> with the chosen profile name,<ldap server ip address> with the IP address of the destination LDAP server, <password> with the LDAP administrative user password in relation to the adminDN, <port> with the LDAP server port value. For adminDN replace CN=<cn>,CN=<cn>,DC=<dc>,DC=<dc> with the appropriate LDAP configured values. For baseDn replace DC=<dc>,DC=<dc> with the appropriate LDAP configured base DN values.

    For example, to create a LDAP authentication profile configuration with the destination authentication server configured as direct (configuration does not reference a pool), enter the following:

    <POST> /mgmt/tm/apm/aaa/ldap -d '{"name":"rest-ldap-auth-pool","address":"192.168.1.119","adminEncryptedPassword":"zentyal123!","adminDn":"CN=BIG-IP APM,CN=Users,DC=vmlab,DC=local","baseDn":"DC=vmlab,DC=local","isLdaps":"false","port":389,"usePool":"disabled"}'

    For example, to create a LDAP authentication server configuration with the destination LDAP authentication server residing in a pre-existing pool, enter the following:

    <POST> /mgmt/tm/apm/aaa/ldap -d '{"name":"rest-ldap-auth-pool","address":"192.168.1.119","adminEncryptedPassword":"zentyal123!","adminDn":"CN=BIG-IP APM,CN=Users,DC=vmlab,DC=local","baseDn":"DC=vmlab,DC=local","isLdaps":"false","port":389,"pool":"zentyal","usePool":"enabled"}'

  • To create a TACACS+ authentication server for an access policy to use, use the following command syntax:

    Impact of procedure: Using the following commands should not have a negative impact on your system.

    <POST> /mgmt/tm/apm/aaa/tacacsplus -d '{"usePool":"disabled","address":"<tacacs+ server ip>","authService":"ppp","authType":"pap","encrypt":"enabled","port":49,"privLvl":"min","protocol":"unknown","secret":"<secret>","service":"none","name":"<base name>_act_tacacs_auth"}'

    Note: Replace <tacacs+ server ip> with the destination TACACS+ server IP address, replace <port> with the TACACS+ server  port value. Replace <secret> with the Radius server requires secret and <base name> with the name for the authentication profile.

    For example:

    <POST> /mgmt/tm/apm/aaa/tacacsplus -d '{"usePool":"disabled","address":"192.168.1.97","authService":"ppp","authType":"pap","encrypt":"enabled","port":49,"privLvl":"min","protocol":"unknown","secret":"testing123","service":"none","name":"rest_tacacs"}'

  • To create a Local User DB  authentication database for an access policy to use, use the following command syntax:

    Impact of procedure: Using the following commands should not have a negative impact on your system.

    <POST> /mgmt/tm/apm/aaa/localdb -d '{"name":"<base profile name>","partition":"<partition>","fullPath":"/<partition>/<base profile name>","lockoutThreshold":4}'

    Note: Replace <instance name> with the chosen profile name, replace <lockout> with the number of authentication attempts allot to a user the system locks them out.

    For example:

    <POST> /mgmt/tm/apm/aaa/localdb -d '{"name":"simple-vpn-db","partition":"/Common","fullPath":"/Common/simple-vpn-db","lockoutThreshold":4}'

    To add or delete users of  a Local User DB, you have to run the BIG-IP APM command line utility ldbutil. You do this using the iControl REST API utility access to Bash:

    • To add a user to the Local User DB, use the following syntax:

      <POST> /mgmt/tm/util/bash -H "Content-type: application/json" -X POST -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'ldbutil --add --instance="<partition>/<instance name>" --uid="" --first_name="<first name>" --last_name="<last name>" --email="<email>" --uname="<username>" --password="<password>" --change_passwd="0" --user_groups="" --login_failures="0" --locked_out="0"'\"}"

      For example:
      <POST> /mgmt/tm/util/bash -d '{"command":"run","utilCmdArgs":"-c ldbutil --add --uname=\"ned\" --instance=\"/Common\'${1}'DB\" --password=\"nedf\" --change_passwd=\"0\" --first_name=\"Ned\" --last_name=\"Flanders\" --user_groups=\"Group-Simpsons\" --email=\"nedf@example.com\" --login_failures=\"0\" --locked_out=\"0\""}'

    • To delete a user from the Local User DB, use the following syntax:

      <POST> /mgmt/tm/util/bash -H "Content-type: application/json" -X POST -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'ldbutil --delete --uname="<username>" --instance="<partition>/<instance name>"'\"}"

Creating a Network Access webtop resource

To create a webtop resource for the access policy, use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/resource/webtop -d '{"name":"<base name>","customizationGroup":"/<partition>/<base profile name>","webtopType":"network-access"}'

Note: Replace <base name> with the base name used for all objects created for the network access profile and policy.

For example, to create a new webtop for network access with the name of vpn-webtop in the Common partition, you enter the following:

<POST> /mgmt/tm/apm/resource/webtop -d '{"name":"simple-vpn","customizationGroup":"/Common/simple-vpn_customization","webtopType":"network-access"}'

Creating a Connectivity profile

To create a Connectivity profile for use by the network access virtual server, use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/profile/connectivity -d '{"name":"<base name>_profile","defaultsFrom":"/<partition>/connectivity","clientPolicyReference":{"items":[{"name":"<base name>_profile_clientPolicy","ec":{"componentUpdate":"yes","locationDns":["<local domain first>","<local domain second>"]},"servers":[{"alias":"<virtual server alias>","host":"<virtual server fqdn>"}]}]}}'

Note: Replace <base name> with the base name used for all objects created for the network access profile and policy. Replace <local domain first> and <local domain second> with local domains located on the destination VPN network.

For example:

<POST> /mgmt/tm/apm/profile/connectivity -d '{"name":"simple-vpn_profile","defaultsFrom":"/Common/connectivity","clientPolicyReference":{"items":[{"name":"simple-vpn_profile_clientPolicy","ec":{"componentUpdate":"yes","locationDns":["intranet.loc","corporate.loc"]},"servers":[{"alias":"vpn","host":"vpn.example.com"}]}]}}'

Creating a lease pool resource

To create a lease pool for distribution of IP addresses for access sessions, use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/resource/leasepool -d '{"name":"<base name>-vpn-leasepool","members":[{"name": "<leasepool start ip>-<leasepool end ip>"}]}'

Note: Replace <base profile name> with the base name, replace <leasepool start ip> and <leasepool end ip> to set the available IP address for distribution from the lease pool. For a singular IP address enter the single address.

For example:

<POST> /mgmt/tm/apm/resource/leasepool -d '{"name":"simple-vpn-vpn-leasepool","members":[{"name": "10.0.10.100-10.0.10.150"}]}'

Creating the Network Access resource

To create a network access profile use the following syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/resource/network-access -d '{"name":"<base name>_netaccess_profile","leasepoolName":"/<partition>/<base name>-vpn-leasepool"}'

Note: Replace <base name> with the base name used for all objects created for the network access profile/policy.

For example:

<POST> /mgmt/tm/apm/resource/network-access -d '{"name":"simple-vpn_netaccess_profile","leasepoolName":"/Common/simple-vpn-vpn-leasepool"}'

Creating ACL rules

To create ACL rules, you should uniquely name each rule set, followed by the rule entries as noted in the following syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/acl -d '{"name":"<base name>_blockports","entries":[{"action":"reject","dstEndPort":<acl end port>,"dstStartPort":<acl start port>,"dstSubnet":"<acl network applied>","log":"none","protocol":6,"srcEndPort":0,"srcStartPort":0,"srcSubnet":"<acl network applied>"}]}'

Note: Replace  <base name> with the base name used for all objects created for the network access profile and policy. Replace <acl end port> with the last port number of the port range, and replace <acl start port> with the first port number of the port range. Replace <acl network applied> with the network/masq of the network to apply the ACL (typically the same network as the addresses used in the lease pool).

For example:

<POST> /mgmt/tm/apm/acl -d '{"name":"simple-vpn_blockports","entries":[{"action":"reject","dstEndPort":23,"dstStartPort":20,"dstSubnet":"10.0.10.0/24","log":"none","protocol":6,"srcEndPort":0,"srcStartPort":0,"srcSubnet":"10.0.10.0/24"}]}'

Generating the transaction ID

The system uses the transaction ID  when implementing (validating) the interconnecting configuration objects of the access profile and policy. Each configuration object must use the transaction ID in the HTTP POST header when creating the object. The system validates all objects created with the same transaction ID when creating the final profile and access policy.

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/transaction -d '{}' | jq -M .

Example output:

/mgmt/tm/transaction -d '{}' | jq -M .
{
  "transId": 1595105174628752,
  "state": "STARTED",
  "timeoutSeconds": 120,
  "asyncExecution": false,
  "validateOnly": false,
  "executionTimeout": 300,
  "executionTime": 0,
  "failureReason": "",
  "kind": "tm:transactionstate",
  "selfLink": "https://localhost/mgmt/tm/transaction/1595105174628752?ver=16.0.0"
}

Alternatively, you can use the following syntax to extract just the ID value:

<POST> /mgmt/tm/transaction -d '{}' | cut -d, -f1 | cut -d: -f2

Example output:

1595105174628752

Creating the Authentication agent

  • Radius

    To create a Radius authentication agent for the access policy to use, use the following syntax:

    Impact of procedure: Using the following commands should not have a negative impact on your system.

    <POST+ID> /mgmt/tm/apm/policy/agent/aaa-radius  -d '{"name":"<base name>_act_radius_auth_ag","partition":"<partition>","fullPath":"/<partition>/<base name>_act_radius_auth_ag","maxLogonAttempt":3,"passwordSource":"%{session.logon.last.password}","server":"/<partition>/<base name>_act_radius_auth","showExtendedError":"true","usernameSource":"%{session.logon.last.username}"}'

    Note: Replace <base name> with the base name used for the access profile and policy configuration. Replace <partition> with the partition name for the location of the object (default is Common).

    For example:

    <POST+ID> /mgmt/tm/apm/policy/agent/aaa-radius -d '{"name":"simple-vpn_act_radius_auth_ag","partition":"Common","fullPath":"/Common/simple-vpn_act_radius_auth_ag","maxLogonAttempt":3,"passwordSource":"%{session.logon.last.password}","server":"/Common/simple-vpn_act_radius_auth","showExtendedError":"true","usernameSource":"%{session.logon.last.username}"}'

  • LDAP, TACACS+, and LocalDB

    To create an authentication agent other than Radius for the access policy to use, use the following syntax:

    Impact of procedure: Using the following commands should not have a negative impact on your system.

    /mgmt/tm/apm/policy/agent/<auth-server-agent> -d '{"name":"<base name>_act_<auth-server-type>_auth_ag","partition":"<partition>","fullPath":"/<partition>/<base name>_act_<auth-server-type>_auth_ag","maxLogonAttempt":3,"passwordSource":"%{session.logon.last.password}","server":"/<partition>/<base name>_act_<auth-server-type>_auth","showExtendedError":"true","usernameSource":"%{session.logon.last.username}"}'

    Note: Replace <auth-server-agent> with the authentication server type aaa-ldap, tacacsplus or localdb. Replace <auth-server-type> with the authentication type name ldap, tacacsplus or localdb. Replace <base name> with the base name used for the access profile and policy configuration. Replace <partition> with the BIG-IP partition location for the object (default is Common).

    LDAP example:

Running validation and policy creation

Validation reviews all the objects created using the <POST+ID> method for inter-dependencies. When the dependencies are met, the system generates the access policy configuration.

Use the following command syntax to run validation and subsequent policy generation for objects created with a common transaction ID.

Impact of procedure: Using the following commands should not have a negative impact on your system.

<PATCH> /mgmt/tm/transaction/<transaction ID> -d '{"state":"VALIDATING"}'

Note: Replace <transaction ID> with the transaction ID value previously generated in the Generating the Transaction ID section.

For example:

<PATCH> /mgmt/tm/transaction/1595085056113967 -d '{"state":"VALIDATING"}'

After the system validates the access policy objects and generates the access policy, the access policy is not applied to traffic until you apply it.

Scripting

The following Bash script example uses each of the previous procedures to configure a Network Access profile and policy that uses Radius authentication to establish a Network Access VPN session. The example script takes a single execution variable at the command line, the destination BIG-IP APM IP address. The script prompts for configuration information (Radius server ports 1812 and 1813 are assumed) and present the information for review (excluding passwords). Upon successful completion, you can use the Network Access profile and Connectivity profile when configuring a Network Access virtual server.

Script example:

## Script execution: ./<script name> <big-ip apm ip address>
## Example: ./generate_apm_vpn 192.168.0.87
## You will be promtped for the admin password and additional configuration information.
##
##
#!/bin/bash
clear
bigip_ip_address="${1}"
test ${bigip_ip_address} 1>&- || {
echo "Script syntax: ./<script name> <big-ip apm ip address>"
echo "The BIG-IP APM IP address command line argument was not provided - Exiting."
exit 0
}
echo -n "Enter admin@${bigip_ip_address} password: ";read -s password;echo
echo -n "Enter a base name for all objects : ";read base_name;echo
echo -n "Enter the BIG-IP administrative partition name (case sesnsitive) : ";read partition_name;echo
echo -n "Enter Radius server IPv4 address : ";read radius_server_ip;echo
echo -n "Enter Radius server secret : ";read -s secret;echo
echo -n "Enter Lease Pool starting IP address : ";read leasepool_startip;echo
echo -n "Enter Lease Pool ending IP address : ";read leasepool_endingip;echo
echo -n "Enter a local network domain of the VPN : ";read local_domain_first;echo
echo -n "Enter a second local network domain of the VPN : ";read local_domain_second;echo
echo -n "Enter virtual server FQDN : ";read virtual_server_fqdn;echo
echo -n "Enter virtual server FQDN alias : ";read virtual_server_alias;echo
echo -n "Enter blocking ACL network/subnet (example: 10.0.10.0/24) : ";read acl_network_applied;echo
echo -n "Enter ACL block ports starting port : ";read acl_start_port;echo
echo -n "Enter ACL block ports ending port : ";read acl_end_port;echo
echo "*** Here are the settings you supplied:";echo
echo "BIG-IP partition to create all objects: ${partition_name}
Base name used for ALL objects: ${base_name}
Radius server IP: ${radius_server_ip}
Lease Pool IP range: ${leasepool_startip}-${leasepool_endingip}
Local VPN domains: ${local_domain_first} and ${local_domain_second}
Virtual sever alias and FQDN: ${virtual_server_alias} - ${virtual_server_fqdn}
VPN ACL rule block ports: ${acl_start_port} to ${acl_end_port} on ${acl_network_applied}
"
tput rev; echo -n " *** Warning *** "
tput sgr0; echo "Provided input data is not validated prior to execution!"
echo -n " Information is correct {n/y}? : ";read ISOK;echo
test ${ISOK} ==  "y" 2>&- || test ${ISOK} == "Y" 2>&- || {
echo "${ISOK} - Aborting..."
exit 0
}
echo "Starting..."
sleep 1
#-----------------------#
echo "Create Radius profile ::::::"
curl -sk -X POST -u admin:${password} -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/aaa/radius -d '{"name":"'${base_name}'_act_radius_auth","acctPort":"1813","authPort":"1812","mode":"auth","secret":"'${secret}'","serviceType":"authenticate-only","address":"'${radius_server_ip}'","usePool":"disabled"}' | jq -M .

#-----------------------#
echo "Create Webtop ::::::"
curl -sk -X POST -u admin:${password} -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/resource/webtop -d '{"name":"'${base_name}'","customizationGroup":"/'${partition_name}'/'${base_name}'_customization","webtopType":"network-access"}' | jq -M .

#-----------------------#
echo "Create Connectivity profile ::::::"
curl -sk -X POST -u admin:${password} -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/profile/connectivity -d '{"name":"'${base_name}'_profile","defaultsFrom":"/'${partition_name}'/connectivity","clientPolicyReference":{"items":[{"name":"'${base_name}'_profile_clientPolicy","ec":{"componentUpdate":"yes","locationDns":["'${local_domain_first}'","'${local_domain_second}'"]},"servers":[{"alias":"'${virtual_server_alias}'","host":"'${virtual_server_fqdn}'"}]}]}}'| jq -M .

#-----------------------#
echo "Create Leasepool ::::::"
curl -sk -X POST -u admin:${password} -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/resource/leasepool -d '{"name":"'${base_name}'-vpn-leasepool","members":[{"name": "'${leasepool_startip}'-'${leasepool_endingip}'"}]}'| jq -M .

#-----------------------#
echo "Create Network Access profile ::::::"
curl -sk -X POST -u admin:${password} -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/resource/network-access -d '{"name":"'${base_name}'_netaccess_profile","leasepoolName":"/'${partition_name}'/'${base_name}'-vpn-leasepool"}'| jq -M .

#-----------------------#
echo "Add ACL profile rules ::::::"
curl -sk -X POST -u admin:${password} -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/acl -d '{"name":"'${base_name}'_blockports","entries":[{"action":"reject","dstEndPort":'${acl_end_port}',"dstStartPort":'${acl_start_port}',"dstSubnet":"'${acl_network_applied}'","log":"none","protocol":6,"srcEndPort":0,"srcStartPort":0,"srcSubnet":"'${acl_network_applied}'"}]}' | jq -M .

#-----------------------#
echo "Generate Transaction ID ::::::"
ID=`curl -sk -X POST -u admin:${password} -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/transaction -d '{}' | cut -d, -f1 | cut -d: -f2`
echo "Transaction ID: ${ID}"

#-----------------------#
echo "Create Radius agent ::::::"
curl -sk -X POST -u admin:${password} -H "X-F5-REST-Coordination-Id:${ID}" -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/policy/agent/aaa-radius  -d '{"name":"'${base_name}'_act_radius_auth_ag","partition":"'${partition_name}'","fullPath":"/'${partition_name}'/'${base_name}'_act_radius_auth_ag","maxLogonAttempt":3,"passwordSource":"%{session.logon.last.password}","server":"/'${partition_name}'/'${base_name}'_act_radius_auth","showExtendedError":"true","usernameSource":"%{session.logon.last.username}"}' | jq -M .

#-----------------------#
echo "Create Customization Group ::::::"
curl -sk -X POST -u admin:${password} -H "X-F5-REST-Coordination-Id:${ID}" -H "Content-Type: application/json" https://${bigip_ip_address}/mgmt/tm/apm/policy/customization-group -d '{"name":"'${base_name}'_act_logon_page_ag","fullPath":"'${base_name}'_act_logon_page_ag","type":"logon"}' | jq -M .
