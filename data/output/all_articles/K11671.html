K11671: SNMP software that uses the net-snmp package may display the wrong route domain when polling the sysSelfIpAddr.ipv4z SNMP attribute

Type
Knowledge
Published
2010-06-09
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP LTM: 10.2.0, 10.1.0
Source
https://my.f5.com/manage/s/article/K11671

Topic

SNMP software that uses older versions of the Net-SNMP software package may not display the correct route domain when polling the BIG-IP system for the sysSelfIpAddr.ipv4z attribute. When this occurs, the route domain is reported as zero even though the BIG-IP system returns the correct value.

For example:

# snmpwalk -m /usr/share/snmp/mibs/F5-BIGIP-SYSTEM-MIB.txt -v 1 -c public 172.16.0.16 sysSelfIpAddr.ipv4z
F5-BIGIP-SYSTEM-MIB::sysSelfIpAddr.ipv4z."10.0.0.1%0" = Hex-STRING: 0A 00 00 01 00 00 00 02
F5-BIGIP-SYSTEM-MIB::sysSelfIpAddr.ipv4z."192.168.0.1%0" = Hex-STRING: C0 A8 00 01 00 00 00 01
#

This is caused by a display issue in older versions of the Net-SNMP software package. You can work around this issue by installing Net-SNMP version 5.5 or later on the SNMP polling station, or by specifying numeric output when polling for the sysSelfIpAddr.ipv4z attribute.

For example:

# snmpwalk -On -m /usr/share/snmp/mibs/F5-BIGIP-SYSTEM-MIB.txt -v 1 -c public 172.16.0.16 sysSelfIpAddr.ipv4z
.1.3.6.1.4.1.3375.2.1.2.8.1.2.1.2.3.8.10.0.0.1.0.0.0.2 = Hex-STRING: 0A 00 00 01 00 00 00 02
.1.3.6.1.4.1.3375.2.1.2.8.1.2.1.2.3.8.192.168.0.1.0.0.0.1 = Hex-STRING: C0 A8 00 01 00 00 00 01
#

In the example above, the string 0.0.0.2 following 10.0.0.1 indicates that the self IP address 10.0.0.1 belongs to route domain 2, and the string 0.0.0.1 following 192.168.0.1 indicates that the self IP address 192.168.0.1 belongs to route domain 1.
