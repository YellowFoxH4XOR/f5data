Topic

Prior to BIG-IP and 3-DNS version 4.6.2 and 4.5.11, you could only to revert to a previous software version by reinstalling the system software.

Beginning in versions 4.5.11 and 4.6.2, BIG-IP and 3-DNS include a new utility that allows you to roll back to the previous version of the same software branch. For example, you could use this script to roll back from version 4.6.2 to version 4.6 or from version 4.5.11 to 4.5.10; however, you cannot roll back from version 4.6.2 to version 4.5.9.

Performing a software roll back

To revert to a previous software version, perform the following steps:

Important: As described in the following instructions, you must run the mkrb script before you run install the software version to which you want to revert.

  1. Download the BIG-IP or 3-DNS upgrade package for the software version to which you want to revert.

    Note: If are currently running a version prior to 4.5.11 or 4.6.2, you must install the mkrb package. Contact F5 Network Technical Support to obtain this package.

  2. Run the mkrb script, by typing the following command:

    mkrb <IM Package of New Version>

    The mkrb script will examine the IM package for the new version that you want to install and compare it to the current contents of the filesystem. It will then create a new IM package containing any different files, plus the following:

    • A standard .ucs archive
    • Backup of libc
    • /VERSION
    • Contents of /config
    • Contents of /etc
    • Contents of /root
    • Contents of /3dns
    • Contents of /usr/share/locale
    • Contents of /usr/share/sendmail
    • Contents of /usr/share/zoneinfo
    • /usr/local/www/bigipgui/.users
    • /VENDOR
    • /CONTACTS
    • /usr/local/www/bigipgui/images/background.jpg
    • /usr/local/www/bigipgui/images/configutil.jpg
    • /usr/local/www/bigipgui/images/header.jpg
    • /usr/local/www/bigipgui/images/logo.jpg
    • /usr/local/www/3dns/images/_logo.jpg

    The script will place the updated roll back file containing the changes in the /var/tmp/rb directory.

  3. Copy the file from BIG-IP or 3-DNS for safe keeping.
  4. Install the desired software version.

Limitations

The mkrb script has the following limitations.

  • IM database

    The mkrb script does not update the IM database. This means that the IM database will report the latest version that you installed, even if you have used the roll back script to revert to a previous version.

    For example, if you upgraded to version 4.6.2 and then rolled back to version 4.6, the IM database would still report the system as running version 4.6.2.

    This can cause an error later when you upgrade. For example, if you attempt to install version 4.6.1 after you reverted to 4.6, the upgrade will fail to install and will report that the current version is newer than the version you are installing.

    To work around this you must force IM, by typing the following command:

    im -force <Upgrade Package>

  • Pre- and post-installation scripts

    The pre- and post-installation scripts move files and make changes to files during the upgrade process. The mkrb script cannot replicate some of these processes. This typically does not cause a problem, since these files are changed when the roll back archive is created.

  • Hotfix packages

    The version number tracked by IM does not change when you install a hotfix. As a result, an old roll back archive could be used after multiple hotfixes have been installed. When installing hotfixes, make sure to run the mkrb script after installing each one.
