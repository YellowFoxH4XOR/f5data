K000161111: "CSRF token absent" and "Origin header validation failed" for API and Mobile Endpoints

Type
Support Solution
Published
2026-05-07
Updated
2026-08-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161111

Description

When CSRF protection is enabled in BIG-IP ASM, violations such as "CSRF token absent" or "Origin header validation failed: Origin is absent" may occur for API endpoints accessed by non-browser clients, including native mobile applications and AJAX requests. These violations are logged when the client does not include a CSRF token or Origin header in the request, resulting in false positives for API and mobile app traffic.

Environment

  • Product: BIG-IP ASM
  • Version: 17.5.1
  • Configuration:
    • CSRF protection enabled on API endpoints (e.g., /api-gw/user-service/otp/send/email)
    • Requests originating from native mobile applications (e.g., User-Agent: ExampleApp/1 CFNetwork/... Darwin/...)
    • AJAX requests or API calls (isAjax:true)
    • Enforcement action set to "Verify CSRF Token" or "Verify Origin"
  • Typical symptoms:
    • Event log entries for "CSRF token absent"
    • Event log entries for "Origin header validation failed: Origin is absent"

Cause

CSRF token enforcement is intended for browser-based HTML forms, where BIG-IP ASM injects a CSRF token via JavaScript. Non-browser clients (such as mobile apps and AJAX calls) do not receive or submit this token, resulting in false positive "CSRF token absent" violations. Similarly, mobile apps typically do not send an Origin header, leading to "Origin header validation failed: Origin is absent" violations when "Verify Origin" is enforced.

Answer/Recommended Actions

  1. Set Enforcement Action to "None" for Affected Endpoints
    • Go to:
      Security > Application Security > Security Policies > [Your Policy] > Advanced Protection > CSRF Protection
    • Locate the entry for the affected endpoint (e.g., /api-gw/user-service/otp/send/email).
    • Change the "Enforcement Action" from "Verify CSRF Token" or "Verify Origin" to "None".
    • Click Save, then Apply Policy.
  2. Ensure URL List Order
    • Make sure the specific URL entry is listed above any wildcard (*) entries in the CSRF URL list. The list is evaluated top-down; if a wildcard appears first, it will override specific entries.
  3. (Optional) Exclude Mobile App User-Agent from CSRF Enforcement
    • If you prefer to exclude all requests from a specific User-Agent (e.g., your mobile app), run the following command and restart ASM during a maintenance window:

    /usr/share/ts/bin/add_del_internal add csrf_excluded_user_agent_patterns "*ExampleApp*"

    bigstart restart

    • Reference: KB K000137017
  4. Inform Application Teams
    • CSRF is a browser-specific attack vector and does not apply to native mobile apps. For API-level protection, consider implementing authentication controls (e.g., OAuth tokens, API keys) at the application layer.

Additional Information

  • "Verify CSRF Token" is only appropriate for browser-based HTML forms.
  • "Verify Origin" is suitable for AJAX/API requests that include an Origin or Referer header, but not for native mobile apps.
  • False positives are expected if CSRF protection is enforced on endpoints accessed by non-browser clients.
  • The window["_csrf_"] JavaScript object is intentionally obfuscated on each page load; this is expected behavior.
