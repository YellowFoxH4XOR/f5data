Known Issue

This is a result of a known issue. In BIG-IP LTM 9.4.5, the default location of the LDAP client configuration file changed, causing any LDAP monitor request to fail. Failure of the LDAP monitor to establish a session with the server causes the monitored pool members to be marked down. An error message that appears similar to the following example is logged in the /var/log/kern.log file, indicating that the LDAP monitor cannot parse the configuration file:

SubDomain: REJECTING r access to /usr/etc/openldap/ldap.conf (LDAP_monitor(8311) profile /usr/bin/bigd active /usr/bin/bigd)

F5 Product Development tracked this issue as CR103688, and it was fixed in BIG-IP 9.4.6. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, or WebAccelerator Release Notes.

Workaround

You can work around this issue by allowing the monitoring daemon to locate the configuration file. To do so, perform the following procedure:

  1. Edit the /etc/subdomain.d/usr.bin.bigd file.
  2. Add the following line to the end of the file, between the last line of text and the closing bracket:

    /usr/etc/openldap/ldap.conf r,

  3. Restart the security subsystem by typing the following command:

    bigstart restart subdomain

When the new configuration has been successfully loaded, output that appears similar to the following example will be displayed on the console:

Unloading SubDomain profiles[OK]

Loading SubDomain profiles[OK]

Note: The LDAP configuration files are not synchronized between members of a redundant pair; when configuring a redundant pair, you must repeat this procedure on both systems.

Note: If you are monitoring LDAPS servers, you may need to perform another procedure to enable a monitor created using the built-in LDAP monitor template. For more information, refer to K9530: An LDAP monitor with TLS/SSL enabled fails with 'Bind failed' error.
