Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP ASM system is configured with an active security policy.
  • You would like to disable BIG-IP ASM or DoSL7 content processing based on the properties of the requested URL.

Description

The BIG-IP ASM system processes the request to determine if the request meets the security policy or DoSL7 profile configured criteria.

Disabling attack signatures and performing other policy checks does not keep the BIG-IP ASM system from processing content. In some cases the BIG-IP ASM system continues to log information about the processed content. If you would like the BIG-IP ASM system to not process (and log) details about specific URL-based content, you can perform the following procedure.

Prerequisites

You must meet the following prerequisites to perform this procedure:

  • Have administrative access to the BIG-IP ASM Configuration utility.
  • Have a general understanding of BIG-IP ASM security policies.
  • Have a general understanding of BIG-IP iRules.

Procedures

Creating a URL data group exclusion list

You can create an iRule data group to store URLs that you do not want the BIG-IP ASM or DoSL7 security policies to process.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Local Traffic > iRules > Data Group List.
  3. Click Create.
  4. Type a Name for the URL exclusion data group.
  5. For Type, click String.
  6. In both the String and Value fields, type the expected URL path content that prevents the BIG-IP ASM or DoSL7 security policies from processing the request.
  7. Click Add.
  8. Repeat steps 6 and 7 for each URL path that you do not want the BIG-IP ASM or DoSL7 security policies to process.
  9. Click Finished.

Creating and applying a custom iRule

You can create a custom iRule that examines the HTTP URI request for the matching content of a data group. The BIG-IP ASM or DoSL7 security policies do not process content that is matched and the content is not logged.

Impact of procedure: F5 recommends that you perform the following procedure during a scheduled maintenance window. 

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create (+).
  4. Type a Name for the custom iRule.
  5. In the Definition field, use the following iRules syntax to define the new iRule.

    Note: The following example uses the contains evaluation and will trigger if the system matches the data group value (which is not case sensitive) anywhere in the request URL.

    when HTTP_REQUEST {
    if { [class match  [string tolower [HTTP::uri]] contains <data-group name>]  } {
    ASM::disable
    DOSL7::disable
    # For testing remove the "#" symbol at the beginning of the next line to log the URLs identified by the iRule.
    #log local0. "[HTTP::uri] found ASM/DOSL7 disabled."
       }
       return
    }

    Note: Change <data-group name> to match the partition and name of the data group you created in the previous procedure.

    Important: If your BIG-IP ASM security policy is not configured with a DoSL7 profile, remove the line DOSL7::disable.

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Server List.
  8. Click the name of the BIG-IP ASM enabled virtual server to which you want to apply the custom iRule.
  9. Click the Resources tab.
  10. Click the iRules Manage button.
  11. Click the new custom iRule in the Available column and click << to add the iRule to the Enabled column.
  12. Click Finished.
