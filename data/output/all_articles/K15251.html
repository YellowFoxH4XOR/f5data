Known Issue

The BIG-IP GTM system may incorrectly mark down BIG-IP LTM 10.2.x virtual servers.

This issue occurs when the following conditions are met:

  • Your BIG-IP LTM system initially runs 11.x, and then you subsequently roll the system back to 10.x or reboot the system to a partition that runs 10.x.
  • The BIG-IP LTM virtual server is configured in a non-default route domain.
  • The virtual server name contains a period (.) character.

BIG-IP GTM 11.x systems use the following syntax in configuration files to represent a BIG-IP 11.x virtual server name:

/<folder_name>/<virtual_server_name>

For example, a BIG-IP 11.x virtual server name may appear similar to the following example:

/Common/vs.name.route.domain

If a BIG-IP 11.x system rolls back to a software version that does not support folders, the virtual server name in the BIG-IP GTM 11.x configuration no longer matches the virtual server name in the BIG-IP 10.x configuration. Furthermore, because the virtual server is not in the same route domain, the IP address/port lookup fails and the virtual server monitor request times out.

Impact

The BIG-IP GTM system marks the affected virtual servers down.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP GTM system marks the affected virtual servers down.
  • You observe activity log entries in the /var/log/gtm file that appear similar to the following example:

    gtmd[8365]: 011ae0f2:1: Monitor instance /Common/bigip 10.1.1.1:80 UP --> DOWN from gtmd (no reply from big3d: timed out)
    gtmd[8365]: 011a6006:1: SNMP_TRAP: VS virtual1 (ip:port=10.1.1.1:80) (Server /Common/ltm.example.com) state change green --> red ( Monitor /Common/bigip from gtmd : no reply from big3d: timed out)

Workaround

To work around this issue, you can manually remove the /Common/ folder prefix from the ltm-name stanzas in the bigip_gtm.conf file before downgrading to BIG-IP 10.x. To do so, perform the following procedure:

Impact of workaround: The following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP GTM system as the root user.
  2. Using a text editor, edit the /config/bigip_gtm.conf file.
  3. For each ltm-name stanza, remove the folder name.

    For example:

    /Common/

  4. Save the configuration and restart the BIG-IP GTM system.
