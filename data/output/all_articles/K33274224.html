Description

After an upgrade, several virtual servers were not functioning and after reverting to the previous version, the virtual servers resumed functioning as normal.

A traffic capture taken on the affected version, shows F5 sending a TCP RST to the client with RST cause: BIG-IP: [0x2b2d3fc:2338] Route domain not reachable (strict mode). However, the Virtual Server and selected pool member are in the same route domain.

Environment

  • Virtual Server with iRule attached
  • iRule using node command
  • Route Domains
  • After upgrade

Cause

Bug ID 934697: Route domain not reachable (strict mode)

Recommended Actions

To workaround the issue on affected versions, you can explicitly add the Route Domain ID to the node commands on the iRules attached to the Virtual Servers affected. For example:

else {
    node $node%1 $port         → Add %1 to explicitly specify route-domain ID 1 for the node command
 }

Additional Information

This can happen with iRules and LTM policies.
