Description

When configuring BIG-IP LTM as an Explicit HTTP Proxy, HTTP 503 "Service Unavailable" Errors may occur for all Client requests. This can happen even if DNS Resolution and Routing appear functional from the BIG-IP CLI. Packet captures show client HTTP CONNECT requests to the proxy, with the proxy responding with HTTP 503 Errors. The issue can be caused by incorrect configuration of the DNS Resolver's Forwarder Zone within the HTTP Explicit Proxy profile.

Environment

  • BIG-IP LTM
  • Explicit HTTP Proxy Virtual Server is configured
  • DNS Resolver object attached to the HTTP-Explicit profile
  • DNS Resolver Forwarder Zone misconfiguration
  • Self IPs assigned to external and internal VLANs
  • No APM or SWG modules involved
  • Default Route configured via Gateway pool
  • Outbound traffic Routed through Active gateway normally
  • SNAT pool may be configured for user traffic

Cause

The root cause could be an incorrect configuration of the DNS Resolver's Forwarder Zone which is assigned to the HTTP-Explicit profile. The Forwarder Zone object was created with a simple words like "FQDN" or even with the "IP Address" as the Zone Name, rather than the required "." (dot) for the Root Zone. This simply prevents the Proxy from using the specified DNS Server(s) to Resolve external Domains, resulting in HTTP 503 Errors for all Client requests. Correcting the Forwarder Zone to use "." as the Name and specifying the correct DNS Server IP(s) resolves the issue.

Answer/Recommended Actions

  1. Remove any incorrectly configured Forwarder Zone objects from the DNS Resolver.
  2. Create a new Forwarder Zone with the name "." (dot) and add the desired DNS Server IP(s) to the Name Servers list.
  3. Attach the corrected DNS Resolver object to the HTTP-Explicit profile on the Virtual Server.
  4. Verify that the proxy can now resolve external Domains and that Client requests are processed successfully.
  5. For system-initiated Traffic (such as DNS lookups from BIG-IP CLI), the source IP will be the Self-IP selected by the TMOS Routing table. Use below command to determine which Self-IP will be used: # ip route get <DNS_IP> 
  6. For user Traffic processed through the Virtual Server, the SNAT Pool configuration determines the source IP.
  7. Ensure outbound Routing and Firewall rules permit traffic from the relevant Self-IPs or SNAT Pool Addresses to the DNS Server and Internet.

Additional Information

  • Using "." as the Forwarder Zone name ensures that BIG-IP will use the specified DNS Servers for all Domain resolution.
  • The SNAT Pool only affects user Traffic processed through the Virtual Server; System-initiated Traffic uses Self-IPs based on Routing.
  • If DNS queries from CLI succeed but proxy Traffic fails, verify the DNS Resolver configuration attached to the proxy profile.
  • HTTP 503 Errors in Explicit proxy scenarios are often linked to DNS Resolution failures or misconfiguration.
  • Self-IPs assigned to traffic-group-local-only are permanently Active and do not participate in HA failover.
