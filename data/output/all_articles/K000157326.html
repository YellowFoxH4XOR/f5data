Description

Attempts to save and apply changes to an ASM security policy failed with the error "Policy configuration failed to apply: set active failed". /var/log/asm indicates below database related error.

<Date> <Time> <BIG-IP_Hostname> crit g_server_rpc_handler_async.pl[31655]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::SetActive::Impl::set_active): Setting policy active failed: Failed to insert to DCC.ACCOUNT_NEGSIG_XML_EXCLUSIONS (DBD::mysql::db do failed: Column 'profile_templ_id' cannot be null at /usr/local/share/perl5/F5/BatchInsert.pm line 243.

You have signature exception configured in one of the XML profiles, associated with the security policy. 

Environment

  • BIG-IP ASM/advanced WAF
  • Security policy with an associated XML profile containing attack signature exceptions

Cause

A database inconsistency in the DCC.ACCOUNT_NEGSIG_XML_EXCLUSIONS table, resulting in a failed database insert and preventing the policy from being activated.

Recommended Actions

  1. Navigate to Security ›› Application Security : Content Profiles : XML Profiles.
  2. Select the affected policy and open the relevant XML profile.
  3. In the Attack Signatures section, remove the problematic exception, then update, save, and apply the policy.
  4. If the exception is still required, re-add it, then update, save, and apply the policy again.

If the issue persists, open a support ticket with the F5 technical support for further investigation.
