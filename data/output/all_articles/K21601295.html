Description

You have made changes to the A record on your BIG-IP GTM / BIG-IP DNS, however DNS resolution from your LDNS is not showing the new changes.

For example, you have made changes to domain example.net where A record was 10.10.10.111 changed to 10.10.10.222.

Running dig directly to the BIG-IP GTM/DNS will show that the A record resolution is correct. Refer to the example below where 192.168.1.1 is the BIG-IP GTM/DNS listener.
dig @192.168.1.1 example.net
example.net. 3600 IN   A       10.10.10.222  <- New IP address

When running dig towards a LDNS or public DNS, the A record is still resolving the older IP address. Refer to the example below where 172.16.10.10 is your LDNS.
dig +trace @172.16.10.10 example.net        
...
example.net.        300     IN      A       10.10.10.111 <- Older IP address    
...

Note: Use dig as dig will provide a more comprehensive output as compared to nslookup

Environment
  • BIG-IP GTM/DNS
  • dig
  • LDNS
  • Resolving IP directly from BIG-IP GTM/DNS is correct
  • Resolving IP from LDNS / Public DNS is not correct

Cause

There is no issue with the BIG-IP GTM/DNS.
The issue is with the LDNS or DNS which the LDNS is referring to where the older A record is being cached.

Recommended Actions

Contact your LDNS administrator and inform them on this issue.

Additional Information

None.
