K05281631: Users may be unable to access some resources when connected to a full-tunnel VPN

Type
Support Solution
Published
2021-09-09
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP APM
  • APM Clients
Source
https://my.f5.com/manage/s/article/K05281631

Description
When connected to a VPN that does not use split tunneling, all traffic from the client, including traffic for external sites, is directed through the BIG-IP. The routing decision for the next-hop is made based on the BIG-IP's routing table, which can cause some resources to be inaccessible based on the BIG-IP's routing configuration and the overall network design.

Environment

  • APM
  • Network Access
  • Split Tunneling not configured

Cause
Because traffic uses the BIG-IP's routing table, the BIG-IP APM needs to have a valid route to send traffic to all possible destinations. In most cases, this can be covered by having a default TMM route configured to address external traffic. However we also need to ensure that return traffic routes back on the same VLAN it egressed the BIG-IP from. This can cause problems if we have separate internal and external VLANs that use the same gateway device when that gateway isn't the BIG-IP. Because all traffic from VPN-connected clients comes from the same source IP in our lease pool, the return traffic from both internal and external hosts will use the same route. If the same gateway router handles both the internal and external VLANs, then that can result in either return traffic from external hosts being sent to the BIG-IP's internal VLAN, or return traffic from internal hosts being sent to the BIG-IP's external VLAN. This will cause either internal or external hosts to be inaccessible due to asymmetric routing.

Recommended Actions

  1. Ensure that the network design does not use the same gateway device for multiple VLANs on the BIG-IP.
  2. Disable VLAN-keyed connections globally

None.
