K000137514: After upgrading to version 17.1.1, GUI Shows "Error getting auth token from login provider" - (Remote-Auth)

Type
Support Solution
Published
2023-11-09
Updated
2026-03-05
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000137514

Description

After upgrading to version 17.1.1, you may observe a warning message "Error getting auth token from login provider" in your GUI. For example, when you click and enter the below pages, you may have this issue:

  • Device Management ›› Overview (or directly click Standalone, Active, or Standby in the system status section at the upper left section of GUI)
  • System ›› Support
  • Shared Objects ›› Address Lists
  • Shared Objects ›› Port Lists

You may also find the below logs while accessing the affected GUI pages:
In /var/log/restjavad.0.log log:

2023-11-01 00:12:34.000 +00:00 1700000001000 Warn RestOperationIdentifier Failed to validate Authentication failed.
In /var/log/ltm log(and similar message in /var/log/audit log):
01420006:3: 01020036:3: The requested user (cmsystemauthnproviderstmos<GENERATED-UUID>) was not found.

This article applies to the situation in which remote authentication is used, for example, LDAP, RADIUS, or TACACS+. Under the situations in which you do not have remote authentication configured, it could be valuable to check the Additional Information section below.

Environment

  • Version 17.1.1 or your software contains the fix for Bug ID 1147633
  • GUI shows "Error getting auth token from login provider"
  • Remote Authentication is in use.

Cause

This is caused by Bug ID 1395081: Remote users are unable to generate authentication tokens.

Recommended Actions

Bug ID 1395081 is fixed at BIG-IP 17.1.1.1. Note however that when you upgrade to BIG-IP 17.1.1.1, you may encounter the issue described in K000137505: Error getting auth token from login provider post 17.1.1 software upgrade. The workaround in K000137505 is still required with BIG-IP 17.1.1.1.

Additional Information

This warning message shows when the GUI uses iControl RESTful API, it should not affect your business traffic and you can use TMSH as an alternative to accomplish your operations. Below are the relevant references that might help guide you in using the command line to finish those tasks.

  • K14856: Performing a ConfigSync using tmsh
  • K12878: Generating diagnostic data using the qkview utility Check Section: Running the qkview utility from the command line (BIG-IP or BIG-IQ)

The warning message "Error getting auth token from login provider" may occur for various reasons.
You may also consider adding memory resources to the restjavad component and restarting restjavad/restnoded services, for more details on those scenarios, you may further check:

  • K15519229: Error getting auth token from login provider
  • K43377453: Error message on GUI: Error getting auth token from login provider

Under the situation that you upgraded to 17.1.1 but do not have remote authentication configured, you may also refer to the below article for the solution to ID 1353957:

  • K000137505: Error getting auth token from login provider post 17.1.1 software upgrade
