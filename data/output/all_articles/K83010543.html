Known Issue

Automatic Policy Builder configurations may trigger high CPU usage.

This issue occurs when all of the following conditions are met:

  • You configure the BIG-IP ASM security policy with Automatic Policy Builder.
  • Policy Builder is configured as follows:
    • The Learn New HTTP URLs setting is set to Always.
    • The Collapse many common HTTP URLs into one wildcard HTTP URL setting is enabled.
  • The automatic policy building process encounters an error.

Impact

The BIG-IP ASM system uses more CPU resources than normal, which may result in degraded performance.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ts/asm_config_server.log file, you notice repeating log messages similar to the following example:

    config |NOTICE|...|src/ConfigurationHelper.cpp:3082|Skipped 85 repeated messages. asmconfig::add_or_update_url_content_profile(): Async process socket is full - ignoring
    config |NOTICE|...|src/ConfigurationHelper.cpp:993|Skipped 85 repeated messages. asmconfig::update_url(): Async process socket is full - ignoring
    config |NOTICE|...|src/ConfigurationHelper.cpp:2379|Skipped 179 repeated messages. asmconfig::add_policy_builder_internal_info(): Async process socket is full - ignoring
    config |NOTICE|...|src/ConfigurationHelper.cpp:4345|Skipped 3 repeated messages. ASMConfig failed to update suggestion for for policy id 11. ASMConfig error : Async process socket is full - ignoring

  • When viewing CPU usage by process, you notice that the asm_config_server_rpc_handler_async.p process uses a disproportionate amount of CPU resources.

Workaround

To work around this issue, in the Automatic Policy Builder settings, you can modify the Learn New HTTP URLs setting or disable the Collapse many common HTTP URLs into one wildcard HTTP URL setting. To do so, perform one of the following procedures:

  • Modifying the Learn New HTTP URLs setting
  • Disabling the Collapse many common HTTP URLs into one wildcard HTTP URL setting

Modifying the Learn New HTTP URLs setting

This procedure changes the Learn New HTTP URLs setting from Always to Selective.

Impact of workaround: After performing this procedure, Policy Builder adds only an explicit URL with relaxed settings rather than creating a comprehensive accept list policy that includes all encountered URLs.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the Current edited security policy menu, select the affected security policy.
  4. In the Policy Building Settings section, expand the URLs options.
  5. In the Learn New HTTP URLs menu, select Selective.
  6. Click Save.
  7. Click Apply Policy.

Disabling the Collapse many common HTTP URLs into one wildcard HTTP URL setting

This procedure disables the Collapse many common HTTP URLs into one wildcard HTTP URL setting.

Impact of workaround: After performing this procedure, Policy Builder does not collapse common HTTP URLs into one wildcard URL.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the Current edited security policy menu, select the affected security policy.
  4. Clear the Collapse many common HTTP URLs into one wildcard HTTP URL check box.
  5. Click Save.
  6. Click Apply Policy.
