Description

When adding a device to iQuery using the command line utilities bigip_add or gtm_add as "root" you receive an error message similar to the following: 

ERROR: Can't read remote cert via /usr/bin/ssh -o UserKnownHostsFile=/root/.ssh/known_hosts

Environment

  • DNS
  • bigip_add or gtm_add
  • SSH

Cause

There are old or invalid known_hosts entries in /root/.ssh/known_hosts

 

Recommended Actions

 

  1. Check that the port lockdown is allowed on SSH (22) for the self address which you are going to use.
  2. Verify that SSH allowed IP address has been configured with the source address which you are going to run big_add or gtm_add.
  3. Remove all matching IP addresses from the /root.ssh/known_hosts file for the device that you are trying to add using bigip_add or gtm_add.
  4. Check that the SSH configuration for all devices have the same Ciphers and/or MAC and key exchange algorithms used by the SSH service. 

    An example of that condition:
    Note: You can view the following configuration information with the TMSH command: 

    #tmsh list sys sshd all-properties

        sys sshd {
              allow { ALL }
              banner disabled
              banner-text none
             description none
             fips-cipher-version 1
             inactivity-timeout 0
             include "Ciphers aes128-gcm@openssh.com,aes256-gcm@openssh.com,aes128-ctr,aes192-ctr,aes256-ctr
             MACs hmac-sha1
             KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384,ecdh-sha2-nistp521"
             log-level info
             login enabled
             port 22
        }
        
        sys sshd {
              allow { ALL }
              banner disabled
              banner-text none
              description none
              fips-cipher-version 1
              inactivity-timeout 0
              include none
              log-level info
              login enabled
              port 22
         }

    Note: In comparing the two configurations the above output from two different BIG-IPs, the include sections do not match.

    Configure same settings on all BIGIPs, or configure de default values for those settings
    To configure the default values, you can follow the procedure "Restoring the include setting of the SSH configuration to the default value" from the following article:

    K80425458: Modifying the list of ciphers and MAC and key exchange algorithms used by the SSH service on the BIG-IP or BIG-IQ systems
