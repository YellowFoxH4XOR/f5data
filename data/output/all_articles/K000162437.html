Description

Customers running NGINX Plus in Kubernetes/containerized environments may ask whether JWT license auto-renewal (introduced in NGINX Plus R35) works the same way as it does on VM or bare-metal deployments, and what happens to the renewed license if a pod restarts.

  • Synopsis: NGINX Plus auto-renewal stores the renewed license in state_path, not in the original license.jwt file. If state_path is not persistent, the renewed license does not survive a pod restart.
  • Symptoms: After a pod restart, NGINX Plus appears to be running on the original (unrenewed) JWT rather than the most recently renewed one. In some cases, NGINX Plus fails to start after a restart.
  • Error messages: None specific to this behavior under normal operation. If state_path fails to mount, the license artifacts NGINX Plus relies on will be missing.

Environment

  • NGINX Plus R35 or later
  • Containerized/Kubernetes deployments (e.g., NGINX Ingress Controller, NGINX Gateway Fabric, or NGINX Plus running in pods)
  • state_path directive (default: /var/lib/nginx/state) not mounted on a persistent volume
  • License subscription within its validity period, or within the 90-day grace period after expiration

Cause

The renewed JWT license is not written back to the original license.jwt file. license.jwt may not belong to NGINX Plus and may even be mounted read-only, so NGINX Plus cannot modify it. Instead, the renewed license and reporting state are stored in state_path, which is the existing mechanism NGINX Plus uses to persist its own artifacts.

If state_path is ephemeral (e.g., not backed by a persistent volume), this data is lost whenever the pod restarts.

Answer/Recommended Actions

  1. If a pod restarts and the renewed license was lost (because state_path was not persistent), NGINX Plus reverts to the original license.jwt and starts up normally, provided the subscription is still within its validity period or the 90-day grace period. Usage reporting resumes, and the first successful report renews and overwrites the token in state_path again. No manual intervention is required in this case.
  2. If a pod restarts after the 90-day grace period has passed, NGINX Plus will not start. There is no automatic renewal or reporting possible in this state. The license must be manually renewed/replaced before NGINX Plus can start again.
  3. To take full advantage of automatic JWT renewal in Kubernetes and avoid any gap after a restart, make state_path persistent across pod restarts (for example, mount it on a persistent volume rather than an ephemeral one).
  4. If persisting state_path is not feasible, license.jwt can instead be managed manually: mount it from a single centralized path and update it directly when renewal is needed. NGINX Plus does not require write access to license.jwt itself, so this path can remain read-only.

Additional Information

  • If state_path fails to mount entirely, the license artifacts NGINX Plus stores there are missing, not just the license itself.
  • If enforce_initial_report is set to on and the instance cannot reach the reporting server at startup, NGINX Plus will not start, independent of license state.
