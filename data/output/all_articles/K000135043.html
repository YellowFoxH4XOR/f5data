K000135043: Secondary is not actively streaming. Postgres may be down.

Applies to

Description

On top the BIG-IQ GUI, a yellow banner will show :

Secondary is not actively streaming. Postgres may be down.

Following logs are noted in var/log/postgres/postgresql logs on either devices 

LOG: could not accept SSL connection: sslv3 alert certificate expired

FATAL: could not connect to the primary server: SSL error: certificate verify failed
FATAL: could not connect to the primary server: SSL error: certificate verify failed

Environment

  • BIG-IQ Centralized Management in HA
  • Still issue exist even performing workaround mentioned in article K32297374 and K93250514

Cause

SSL certificate of device is expired.

Recommended Actions

1. Perform backup of BIG-IQ Centralized Management under System--> Backup Files

2. Check the SSL certificate status of the device using below command. You will see if SSL certificate of device is expired.    

openssl x509 -in /var/lib/pgsql/config/server.crt -issuer -subject -startdate -enddate -noout     

If SSL certificate of device is expired, proceed with step 3                                       

3. To break HA, run the following from bash on both systems           

ha_reset -f <SELF DISCOVERY IP> 

Note:The Discovery address can be identified in the BIG-IQ GUI: System > This Device > General Properties

4. To generate new HA certificates, run the following from bash on both systems: 

           ha_generate_certs -f <SELF DISCOVERY IP>  

          Note: Each HA certificate must contain the Discovery IP configured on the same BIG-IQ device it is generated on.

5. You will notice certificate is renewed when you run the command from step2
6. Add the standby BIG-IQ CM device in HA
7. Now BIG-IQ device becomes active and standby

Additional Information

This error message can also occur when /var or /shared is out of disk space. Use the following command to verify on both BIG-IQ devices and increase disk space as necessary:

df -h /var /shared

Note: tokumond will stop when the space on /var reaches 10% free. This is working as designed to ensure database updates do not cause the space to become fully exhausted
