Description

How do I determine if any of my virtual servers are using a client-side HTTP/2 profile with the HTTP MRF router option?

You can configure the HTTP/2 profile in the client or server-side context for a virtual server.

To do so, refer to the Recommended Actions section.

Environment

  • HTTP/2 profile
  • HTTP MRF router

Cause

Not applicable

Recommended Actions

  1. Log in to the BIG-IP command line.
  2. Determine how many HTTP/2 profiles are configured on the system. Your virtual server may be using the default HTTP/2 profile (http2) or a custom HTTP/2 profile. To determine how many HTTP/2 profiles are configured, enter the following command:

    tmsh list ltm profile http2 | grep "ltm profile"

    The output should list "ltm profile" followed by the HTTP/2 profile names and end with a parenthesis ({). For example:

    ltm profile http2 http2 {
    ltm profile http2 MyCustomHttp2 {
    ltm profile http2 xyz {

    The above example output shows the following HTTP/2 profiles on the system: the parent HTTP/2 profile (http2) and two custom HTTP/2 profiles based on the parent (MyCustomHttp2 and xyz).

  3. Determine if any virtual server references an HTTP/2 profile. To do so, use the following tmsh command syntax, specifying the profile names output in step 2:

    tmsh list ltm virtual all profiles | grep -e http2 -e <HTTP/2 profile name> -e <HTTP/2 profile name>

    For example, the following tmsh command uses the profile names output in step 2 to display virtual servers that reference the parent or custom HTTP/2 profiles:

    tmsh list ltm virtual all profiles | grep -e http2 -e MyCustomHttp2 -e xyz

    The output should list any HTTP/2 profile name that is referenced by a virtual server and ends with a parenthesis ({). If the same profile is listed more than once, then the profile is referenced by more than one virtual server. If no output is returned, then you don't have any virtual servers that reference an HTTP/2 profile. For example,

    MyCustomHttp2 {
    http2 {
    MyCustomHttp2 {

    The above example output shows that a virtual server references the parent HTTP/2 profile (http2) and more than one virtual server references the custom HTTP/2 profile (MyCustomHttp2).

  4. Determine which virtual servers reference the HTTP/2 profiles. To do so, use the following tmsh command syntax, specifying one of the profile names output in step 3:

    tmsh list ltm virtual all profiles | grep 'ltm virtual\|<HTTP/2 profile name>'

    For example, the following command displays all virtual server names and indicates which virtual servers reference the custom HTTP/2 profile, MyCustomHttp2:

    tmsh list ltm virtual all profiles | grep 'ltm virtual\|MyCustomHttp2'

    The following output shows that the custom HTTP/2 profile, MyCustomHttp2 is associated with virtual servers MyVirtual2 and MyVirtual3:

    ltm virtual MyVirtual1 {
    ltm virtual MyVirtual2 {
         MyCustomHttp2 {
    ltm virtual MyVirtual3 {
         MyCustomHttp2 {
    ltm virtual MyVirtual4 {
    ltm virtual MyVirtual5 {

  5. Repeat step 4 for each HTTP/2 profile name that references a virtual server.
  6. After you have determined which virtual servers reference an HTTP/2 profile, review the virtual server profile configuration for any virtual servers using the HTTP/2 profile in the client-side context with the HTTP MRF router (httprouter) option. To do so, use the following command syntax, specifying the virtual server names from step 4 that reference an HTTP/2 profile:

    tmsh list ltm virtual <virtual server name> profiles

    For example, the following command lists the profile configuration for the virtual server, MyVirtual2:

    tmsh list ltm virtual MyVirtual2 profiles

    The following output shows the custom HTTP/2 profile (MyCustomHttp2) is configured in the client-side context and the MRF router option (httprouter) is enabled for the virtual server (HTTP2_MFR):

    ltm virtual HTTP2_MFR {
      profiles {
        clientssl-secure {
          context clientside
        }
        http {
          context all
        }
        MyCustomHttp2 {
          context clientside
        }
        httprouter {
          context all
        }
        serverssl-secure {
          context serverside
        }
        tcp {
          context all
        }

Additional Information

The HTTP/2 profile can be associated with a virtual server for processing client-side or server-side HTTP/2 traffic. In addition, you can enable full proxy HTTP/2 support for a virtual server by applying HTTP/2 client/server-side profiles and enabling the HTTP MRF Router option.
