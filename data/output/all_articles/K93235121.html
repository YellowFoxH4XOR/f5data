Description
Disk space for /shared shows 100% full and unable to save configuration.

Environment

  • BIG-IP
  • /shared directory
  • mcpd

Cause
/shared can become 100% full if mcpd debugging was enabled .

Recommended Actions
Check if there are file handles being held in /shared/tmp folder which is taking a huge disk space and make these file sizes 0.

  1. Check if mcpd debug is turned off. If yes, run the following to list process id of mcpd daemon

    ps -ef | grep mcpd
    root 2708 27733 0 03:07 pts/1 S+ 0:00 grep mcpd
    root 9751 8079 0 Mar20 ? S 0:02 runsv mcpd
    root 9754 9751 28 Mar20 ? Sl 6629:53 /usr/bin/mcpd -dbmem 512 -listen 127.0.0.1 -f
     
  2. Note the Process ID or pid for mcpd, which is 9754. Note: Process ID varies between linux systems

    [BIGIP:Active:Disconnected] shared # lsof -p 9754 | grep mcpd.out
    mcpd 9754 root 1w REG 253,1 37706967848 2342922 /shared/tmp/mcpd.out (deleted) <<----
    mcpd 9754 root 2w REG 253,1 37706967848 2342922 /shared/tmp/mcpd.out (deleted) <<----
     
  3. We need to make the above file sizes zero (0). Refer to the illustration below on how to make the file size as zero;

           [BIGIP:Active:Disconnected] shared # cd /proc/<pid number>/fd/

           Note:  change < pid number > to actual process id number as seen in previous output

           For instance:

            [BIGIP:Active:Disconnected] shared # cd /proc/9754/fd/

            [BIGIP:Active:Disconnected] fd # echo -n > 1; echo -n > 2
            [BIGIP:Active:Disconnected] fd # echo -n > 1; echo -n > 2

 [BIGIP:Active:Disconnected] fd # lsof -p <pid> | grep mcpd.out

mcpd <pid> root 1w REG 0 2342922 /shared/tmp/mcpd.out (deleted)
mcpd <pid> root 2w REG 0 2342922 /shared/tmp/mcpd.out (deleted)

Additional Information
In case above doesn't solve the problem then we would require to reboot the device which will cause failover in HA pair.
