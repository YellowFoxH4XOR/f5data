Description
 

After a software upgrade, when trying to sync new changes from the GUI on the following section Device Management  ››  Overview

You will see the message: "REST framework is not available" on the top of the screen and the configuration will not sync.

On the /var/log/ltm logs, you will see logs similar to these ones:

JVM heap limit exceeded. Using maximum supported value of 2500 instead of provision.extramb <XXXX>
JVM heap limit exceeded. Using maximum supported value of 2500 instead of provision.extramb <XXXX>
JVM heap limit exceeded. Using maximum supported value of 2500 instead of provision.extramb <XXXX>

On the CLI and /var/log/daemon.log logs, you will see restjavad continuously restarting, similar to the following example:

emerg logger: Re-starting restjavad
emerg logger: Re-starting restjavad
emerg logger: Re-starting restjavad
emerg logger: Re-starting restjavad
 

Environment
 

  • BIG-IP LTM
  • HA pair
  • db variable provision.extramb


Cause
 

Previous to the upgrade, you have provided more than the maximum supported value for management on the db variable provision.extramb
 

Recommended Actions
 

  1. Using SSH log in to tmsh by entering the following command:
    tmsh
     
  2. To view the current configured extra system memory, enter the following command:
    list sys db provision.extramb all-properties

    Output appears similar to the following:

    sys db provision.extramb {
        default-value "0"
        scf-config "true"
        value "XXXX"
    value-range "integer min:0 max:8192"
    }

    Note the maximum value for this variable.
     
  3. To modify the provisioned memory value, use the following command syntax:
    modify  /sys db provision.extramb value <numeric value>
     
  4. Save the configuration change by entering the following command:
    save /sys config partitions all
