Description

After upgrading BIGIP to v17.1.3 and later, you may notice remote authentication users can login CLI and WebUI, but cannot access some WebUI pages.

For example:

Using radius for remote authentication,username: "John Doe" with a space in username.

Customer can SSH to CLI console and login to WebUI successfully, but cannot open some pages which use Rest API to query data.

e.g: "Security ›› Event Logs : Application : Requests"

The error message is "Error getting auth token from login provider".

Environment

BIGIP v17.1.3 and later

Cause

Security enhancement , an intentional change made with ID1710621 and  multiple bugs involved.

Remote authentication username standards should align with REST API Naming Conventions.

REST API Naming Conventions:

- Username's length should be 1-255

- Username shall contains exclusively alphanumeric(a-z, A-Z, 0-9), '-',  '_',  '.',  '@' and '\' (backslash) characters.

- Username shall not among the reserved words ("password", "manager", "operator", "guest", "partition", "all", "delete", "disable", "enable", "help", "list", "none", "show", "None");

Recommended Actions

Aligning Remote Authentication Username Standards with REST API Naming Conventions.

Using the same the example above:

Removing the space in the username: "John Doe",

Acceptable examples:

  • "JohnDoe"
  • "John_Doe"
