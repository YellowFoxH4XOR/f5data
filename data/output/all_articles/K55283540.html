Description

After performing an upgrade the /shared/avr or /shared/avr_afm filesystems are reporting full.
  • log messages similar to the following appear in the LTM logs
    • 011d0004:3: Disk partition /shared/avr has only 0% free
  • df -h shows /shared/avr/ or /shared/avr_afm/ disk space at 100% after upgrade

Environment

  • Upgraded BIG-IP
  • Modules that use AVR (APM, AFM, and ASM use AVR)
    • AVR does not need to be provisioned for use by these modules

Cause

Temporary files stored in the /shared/avr or /shared/avr_afm directories are not properly cleaned up after upgrade

Recommended Actions

During the upgrade process temporary files are stored in the /shared/avr or /shared/avr_afm directories in order to rebuild the mysql database. After the upgrade is completed these files may not be deleted properly or the mysql db may still have file descriptors open for the deleted files. It is possible that a reboot may clear the file descriptors and free up the disk space.

However, if a reboot fails to restore the disk space you should perform the following:

Backup any existing statistics files you wish to save, remove all files from the /shared/avr directory, and reset the AVR statistics.
  1. Create a tarball of the desired files in /shared/avr and/or /shared/avr_afm and save to a remote location.
  2. Remove all files from the /shared/avr and/or /shared/avr_afm directores. For example:
    rm -f /shared/avr/*
    rm -f /shared/avr_afm/*
  3. Reset AVR statistics. For information refer to K14956: Resetting BIG-IP AVR statistics
