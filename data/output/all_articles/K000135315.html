Description

On BIG-IP systems, the following technical symptoms may occur:

  • Aggressive mode sweeper is activated, causing intermittent connection drops and loss of access to services.
  • System logs may display messages such as:

sweeper_segment_cb_any: Aggressive mode sweeper /Common/default-eviction-policy activated (global memory).

TCP: Memory pressure activated

Aggressive mode sweeper: /Common/default-eviction-policy (global memory) 479 Connections killed

  • Aggressive mode sweeper correlates with a bot signature update seen in /var/log/dosl7/dosl7_bot_signatures.log:

asm_config_server.pl|INFO|<date>|19003|F5::Dos::BotSignatures::prepare,,Generating bot signatures for profile /Common/bot-defense

  • Memory statistics from commands like show /sys memory indicate significant max allocation to "DoS Layer 7 ACY".

Environment

  • Product: BIG-IP ASM
  • Configuration details:
    • Multiple Bot Defense profiles (e.g., 8 profiles across 5 virtual servers)
    • At least two unique bot signature configurations due to signature overrides
    • System with multiple TMM cores (e.g., 8 cores)

Cause

The root cause is related to the memory requirements of the "DoS Layer 7 ACY" subsystem, which stores compiled bot signature sets. Each unique bot signature configuration—determined by differences in signature overrides—results in a separate compiled collection loaded into memory for each TMM core. Key points:

  • Each unique configuration allocates memory per TMM core (for example, approximately 75MB per state machine per core).
  • During bot signature updates, the system temporarily doubles this allocation while new signatures are compiled and loaded before old ones are released.
  • Multiple unique bot signature configurations can result in high total memory usage, leading to system-wide memory pressure and activation of aggressive mode sweeper mechanisms that kill connections to free up resources.

Recommended Actions

  1. Reduce Unique Bot Signature Configurations
    • Review all Bot Defense profiles and minimize use of custom signature overrides.
    • Remove unused profiles or align their signature override settings with those actively used on virtual servers.
    • For instance, if a profile is not assigned but has unique overrides, remove it or standardize its configuration.
  2. Increase TMM Memory Allocation
    • If reducing unique configurations is not possible due to business requirements, consider increasing the amount of memory allocated to TMM processes.
  3. Monitor Memory Usage
    • Regularly monitor "DoS Layer 7 ACY" and overall TMM memory consumption using available system tools (show /sys memory), especially after making configuration changes or updating signatures.
  4. Schedule Updates Appropriately
    • Perform bot signature updates during maintenance windows or periods of low traffic since these operations temporarily increase memory usage.
