Known Issue

The VIPRION system may erroneously remove members from its Link Aggregation Control Protocol (LACP) trunk. This issue occurs when all of the following conditions are met:

  • The VIPRION system is installed with two or more blades and an LACP trunk configured with interfaces from each of them.
  • The primary blade is subsequently rebooted.

This issue occurs because the actual interface media for each trunk member may not have been detected during the initial creation of the trunk by the mcpd process, and the mcpd process uses the default media option as the reference media. When the primary blade reboots, the mcpd process on the new primary blade revalidates each trunk member's actual media and compares it with the reference media. Due to the discrepancy between the reference media and the actual media, the mcpd process on the new primary blade removes the trunk member from the LACP trunk.

Impact

The VIPRION system has an inconsistent amount of LACP trunk members between blades.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H487076 on the Diagnostics > Identified > Medium screen.
  • After a primary blade reboots, and a secondary blade takes over as the primary blade, you notice missing LACP trunk members from the running configuration on each blade.

    For example, a VIPRION system with four blades installed has a trunk tr1 configured with four interfaces (one interface from each blade). When the primary blade reboots and a secondary blade takes over, the running configuration shows that blade 1 and 2 have only two trunk members while blade 3 has only three trunk members:
