Known Issue

This is the result of a known issue. The RULE_INIT iRule event is triggered when an iRule is added or modified. The RULE_INIT event is used to initialize global variables used inside iRules. If a RULE_INIT event contains a syntax error, and the iRule is not associated with a virtual server, attempting to correct the syntax error will fail.

For example, if you create the following iRule containing the RULE_INIT event and an undefined variable, the system triggers the iRule event, and generates the defined log statement to the /var/log/ltm file:

Note: Creating an iRule with a missing or invalid Tcl argument in a RULE_INIT iRule event does not generate an error message in the Configuration utility. For more information, refer to K10687: A missing or invalid Tcl argument in a RULE_INIT iRule event does not generate an error message.

when RULE_INIT {
log local0. "in RULE_INIT, test starts"
set static:test_var
}

However, when you attempt to correct the iRule by adding the missing variable, the iRule is not re-initialized, and the system does not log the defined log statement to the /var/log/ltm file.

F5 Product Development tracked this issue as CR133851 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, WebAccelerator, and WOM release notes.

Additionally, this issue has been fixed in BIGIP-10.0.1-402.7-HF4 has been issued for BIG-IP version 10.0.1 and BIGIP-10.1.0-3372.0-HF1 for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes on systems refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

To work around this issue, you must remove and recreate the iRule with the correct Tcl argument.
