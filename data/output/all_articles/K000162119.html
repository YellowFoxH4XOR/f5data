Description

When Telemetry Streaming pull consumer polling is configured with a very short interval (every 20–30 seconds) on a BIG-IP SSL Orchestrator (SSLO) high availability (HA) pair, the system may experience unexpected SSLO auto-remediation, configuration reconciliation, or iAppLX object rebuilds despite no administrator‑initiated changes.

Observed symptoms include:

  • SSLO GUI becoming unresponsive
  • The Configuration utility displaying "The iApp LX sub-system is currently unresponsive" when accessing the iAppsLX GUI page iApps >> Package Management LX
  • Management-plane CPU spikes
  • Repeated REST timeouts such as {"code":500,"message":"[RestOperationNetworkHandler] request timeout."}
  • HA verification failures
  • Missing or non-functional SSLO service objects after the rebuild

Environment

  • BIG-IP SSLO (SSL Orchestrator)
  • Telemetry Streaming

Cause

Excessively aggressive Telemetry Streaming polling causes memory exhaustion in restnoded, overloading the REST framework. This leads to SSLO HA verification timeouts or failures, which the system interprets as an HA configuration mismatch, triggering SSLO auto-remediation or iApp object rebuild.

Recommended Actions

  1. Increase the Telemetry Streaming pull consumer polling interval to reduce REST framework load and prevent memory exhaustion.
  2. If the SSLO GUI or iAppLX subsystem is unresponsive, restart restnoded and restjavad to restore the REST stack (Note: This is a temporary workaround if polling remains aggressive).
  3. Monitor management-plane CPU and memory usage and adjust Telemetry Streaming configuration as needed. 
  4. If SSLO configuration objects or services are missing or non-functional after auto-rebuild:
  1. Ensure floating self IPs exist for all required service VLANs.
  2. Redeploy affected SSLO services from the GUI to recreate missing objects.
  3. Validate pool member status and service connectivity.
