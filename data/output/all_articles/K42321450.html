K42321450: Reassembly error, protocol DTLS: New fragment overlaps old data

Type
Support Solution
Published
2022-09-07
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 16.1.2
Source
https://my.f5.com/manage/s/article/K42321450

Description

  • Users experience VPN slowness
  • DTLS is being downgraded to TLS.
  • Packets show the following warnings in Wireshark:

160307    2022-01-01 19:20:45.186555    0.000002    10.10.1.1    10.10.1.2    DTLSv1.2    1659    OUT s1/tmm3 : Certificate[Reassembly error, protocol DTLS: New fragment overlaps old data (retransmission?)]
160308    2022-01-01 19:20:45.186556    0.000001    10.10.1.1    10.10.1.2    DTLSv1.2    1659    OUT s1/tmm3 : Certificate[Reassembly error, protocol DTLS: New fragment overlaps old data (retransmission?)]
160309    2022-01-01 19:20:45.186558    0.000002    10.10.1.1    10.10.1.2    DTLSv1.2    1659    OUT s1/tmm3 : Certificate[Reassembly error, protocol DTLS: New fragment overlaps old data (retransmission?)]
160310    2022-01-01 19:20:45.186559    0.000001    10.10.1.1    10.10.1.2    DTLSv1.2    1542    OUT s1/tmm3 : Certificate[Reassembly error, protocol DTLS: New fragment overlaps old data (retransmission?)]

Environment

  • BIG-IP APM
  • Network Access (VPN) with DTLS

Cause

There is a possibility this is due to problems with large UDP packets fragmentation

Recommended Actions

  1. Create a new UDP profile: Local Traffic >> Profiles : Protocol : UDP >> New UDP Profile
  2. Name the profile and keep "UDP" as parent profile. (ex. udp_with_fragment)
  3. Set "Don't Fragment Mode" to disable. Check the custom box on the right side of the page.
  4. Keep all settings as they are.
  5. Save the profile and apply this profile to the DTLS VIP.
  6. Test your DTLS connections.
