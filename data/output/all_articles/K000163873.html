Description

In a situation where you need to protect your application PHP Vulnerabilities (CVE-2026-109618 & CVE-2026-109619) you can mitigate these vulnerabilities using F5 WAF for NGINX.

  • CVE-2026-109618: PHP Remote Code Execution, ID 200103697 and ID 200204115
    • 200103697 - ASM/Adv WAF Attack Signature Sets: WebSphere signatures, Server Side Code Injection Signatures, Low and Medium Accuracy Signatures, All Signatures
    • 200204115 - ASM/Adv WAF Attack Signature Sets: WebSphere signatures, Server Side Code Injection Signatures, Low and Medium Accuracy Signatures, All Signatures
  • CVE-2026-109619: PHP Remote Code Execution, ID 200204113
    • 200204113 - ASM/Adv WAF Attack Signature Sets: WebSphere signatures, Server Side Code Injection Signatures, Low and Medium Accuracy Signatures, All Signatures

Environment

F5 WAF for NGINX Attack Signatures

Cause

Your environment is susceptible to PHP Vulnerabilities (CVE-2026-109618 & CVE-2026-109619).

Answer/Recommended Actions

To mitigate these vulnerabilities can involve a couple of steps. Starting in version F5 NGINX App Protect WAF 5.1 / 4.9 Released April 18, 2024 Time-based signature staging was added.

  1.  The first step will be to update your Attack Signature Database. The steps to do so are fairly simple and are found here...Update F5 WAF for NGINX signatures
  2. If you are on a version that uses the Time-based signature staging...
    1. Before enforcing the signatures they should be tested where that is possible.
    2. If they need to be enforced immediately you will need to move the signatures out of staging to enforce them.
      1. Set the stagingCertificationDatetime to the timestamp of the latest signature update.
      2. This moves all the signatures out of staging.
      3. When you install a new signature update in the future, all new or modified signatures in that update will automatically be placed in staging.

IMPORTANT: Do not set the stagingCertificationDatetime to the current time (when you finish reviewing).

    • A future signature update might have been created before that time.
    • If so, modified signatures from that update would be older than the stagingCertificationDatetime, and they would not be staged as expected.

NOTE: This is for F5 WAF for NGINX. If you are still using App Protect please review the following...
