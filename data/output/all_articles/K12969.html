Topic

This article applies to BIG-IP GTM 10.2.1 HF1 and 10.2.2. For information about other versions, refer to the following articles:

  • K9655: Overview of the virtual server and link auto-discovery features (9.x - 10.x)
  • K13994: Configuring virtual server and link auto-discovery (11.x - 12.x)
Purpose

Use the procedures in this article to configure the BIG-IP GTM system to discover and monitor virtual server objects that reside in non-default route domains.

Prerequisites
  • The BIG-IP configurations should not include route domains with overlapping IP addresses.
  • The BIG-IP LTM system must contain all of the following configuration elements:
     
    • Virtual Local Area Networks (VLANs) through which route domain traffic passes
    • Default and non-default route domains that represent each network segment
    • Self IP addresses that represent the address spaces for the route domains
    • Virtual servers that are associated with the route domains
Description

Route domains is a BIG-IP LTM feature that allows you to segment network traffic for different applications on the network. Traffic management objects, such as virtual servers, can be designated to reside in the default route domain (route-domain 0), or a non-default route domain, and process traffic for the application in its own route domain.

Starting in BIG-IP GTM 10.2.2, (BIG-IP GTM 10.2.1 HF1 also includes this functionality), it is possible to configure the BIG-IP GTM system to discover and monitor BIG-IP virtual server objects that reside in both the default route domain and non-default route domains. To do so, you must create multiple BIG-IP server objects on the BIG-IP GTM system to represent a single BIG-IP LTM device.

In previous versions, it is possible to configure the BIG-IP GTM system to discover and monitor BIG-IP virtual server objects associated with only the default route domain. Consider the following items when you deploy the BIG-IP GTM system in environments that use route domains.

  • F5 does not support configuration of non-default route domains on BIG-IP systems licensed with the BIG-IP GTM module.
  • BIG-IP GTM module can only monitor and discover local virtual servers that are configured in the default route domain.
  • BIG-IP GTM module can monitor and discover remote virtual servers configured in non-default route domains, but requires a separate BIG-IP GTM server object for each route domain.
Procedures

To configure the BIG-IP GTM system to discover and monitor virtual server objects that reside in both the default and non-default route domains, you must complete the following tasks:

  • Determining the IP addresses to use for the server objects
  • Defining BIG-IP server objects for each route domain in the BIG-IP GTM system
  • Running the bigip_add utility
  • Running the big3d_install utility
  • Determining the server object status

Determining the IP addresses to use for the server objects

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Before you can configure the server objects on the BIG-IP GTM system, you must determine which IP addresses to use for the server objects. To do so, log in to the BIG-IP LTM Configuration utility or command line and identify the self IP addresses that match the route domain address spaces. These addresses are used to create the BIG-IP server objects on the BIG-IP GTM system.

For example, the following command output displays each route domain and associated VLAN defined in the BIG-IP LTM system:

# tmsh list net route-domain

net route-domain 0 {
    description "Default Route Domain"
    vlans {
        external
    }
}
net route-domain 1 {
    description RD-1
    vlans {
        routedomain1
    }
}
net route-domain 2 {
    description RD-2
    vlans {
        routedomain2
    }
}
net route-domain 3 {
    description RD-3
    vlans {
        routedomain3
    }
}

You must now identify the self IP addresses that are assigned to the associated VLANs. For example, the following command output displays the self IP addresses and associated VLANs:

# tmsh list net self

net self 10.24.2.30/24 {
    allow-service default
    vlan external
}
net self 192.168.1.10%1/24 {
    allow-service default
    vlan routedomain1
}
net self 192.168.2.20%2/24 {
    allow-service default
    vlan routedomain2
}
net self 192.168.3.30%3/24 {
    allow-service default
    vlan routedomain3
}

Assuming that virtual servers are configured in each of the previous four route domains, you would need to configure BIG-IP server objects for the following self IP addresses on the BIG-IP GTM system:

Note: When you define the server objects on the BIG-IP GTM system, do not include the route domain ID designation of %ID.

Server_object1: 10.24.2.30
Server_object2: 192.168.1.10
Server_object3: 192.168.2.20
Server_object4: 192.168.3.30

Defining BIG-IP server objects for each route domain in the BIG-IP GTM system

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To configure the BIG-IP GTM system to discover and monitor virtual server objects that reside in non-default route domains, you must define a distinct BIG-IP server object for each route domain address space that contains the virtual servers to be monitored. This involves configuring multiple server objects to represent a single BIG-IP device or failover pair.

Note: If your BIG-IP GTM configuration will reference virtual servers in both the default and non-default route domains, and you are not using the Virtual Server Discovery feature to automatically discover the virtual servers, you will need to manually create the virtual servers and associate them with the appropriate BIG-IP server object.

To create the BIG-IP server objects on the BIG-IP GTM system, perform the following procedure:

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Navigate to DNS > GSLB > Servers > Server List.

    Note: In BIG-IP 11.4.1 and earlier, navigate to Global Traffic > Servers > Server List.
  3. Click Create.
  4. Type the name for the server object.

    For example:

    Server_object1

  5. Type the IP address for the first server object.

    For example:

    10.24.2.30

  6. In the Data Center list, select a data center.
  7. In the Health Monitor section, assign the bigip monitor to the server.
  8. If you want the BIG-IP GTM system to automatically discover virtual servers for the route domain address space, from the Virtual Server Discovery list, select Enabled.
  9. Click Create.

Repeat the previous steps for each BIG-IP server object.

Running the bigip_add utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

After you have defined new BIG-IP server objects, you must run the bigip_add utility on the BIG-IP GTM system to exchange the device certificates between the systems. To do so, perform the following procedure:

  1. Log in to the BIG-IP GTM command line.
  2. Run the following command:

    bigip_add

    Note: If no IP addresses are specified after the bigip_add command, the script attempts to exchange certificates with all the BIG-IP controllers currently configured.

  3. Type the appropriate password, when prompted.

Running the big3d_install utility

Note: You must perform this step only if one or more of the F5 devices in the BIG-IP GTM configuration are running versions earlier than 10.2.2.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

The next step is to run the big3d_install utility on the BIG-IP GTM system to install the current version of the big3d process on remote F5 systems. To do so, run the following command from the BIG-IP GTM command line:

big3d_install

Determining the server object status

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

The final step is to determine the server object status. To do so, perform the following procedures:

Determining server status using the Configuration utility

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Navigate to DNS > GSLB > Servers > Server List.

    Note: In BIG-IP 11.4.1 and earlier, navigate to Global Traffic > Servers > Server List.
  3. Identify the status for the BIG-IP server objects.

    A green circle indicates the server object is available.

Determining server status using the tmsh utility

  1. Log in to the command line.
  2. Type the following command:

    tmsh show gtm server
