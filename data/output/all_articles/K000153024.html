Description

Starting with BIG-IP version 17.5.0, a change was introduced for BIG-IP Virtual Edition (VE) running on Microsoft Azure and Hyper-V.
The xnet-DPDK driver is now used by default for VMBUS devices, even when accelerated networking (SR-IOV) is disabled.
Before 17.5.0, the sock was the only driver

The following symptoms may be observed after upgrading to version 17.5.0 or above.

  • Frequent TCP retransmissions.

  • Continuous TMM Restarts and Core Dumps Triggered by SIGSEGV

  • The BIG-IP may go offline or take a long time to recover from the offline state.

  • Repeated log entries such as:
    localhost.localdomain notice hn_rx_queue_alloc(): Could not allocate rxbuf info for queue <n>

  • If the BIG-IP is configured as an IPsec tunnel endpoint, internal connection redirections might be seen increasing (which may affect IPsec tunnel negotiation/stability):

    tmctl -d blade tmm/cmp -s ipsec_pkt_loop

Environment

  • Product: BIG-IP LTM

  • Platform: Microsoft Hyper-V or Azure cloud

  • Affected Versions: 17.5.0, 17.5.1+

Cause

  • Previous Behavior (before 17.5.0): Only the sock driver was used for VMBUS devices in Azure/Hyper-V environments.

  • New Behavior (from 17.5.0): The xnet-DPDK driver is selected by default for VMBUS devices, even if accelerated networking is not configured or supported.

Recommended Actions

Check Which Driver Is Being Used

To verify the current driver in use for your network devices, run the following command from the BIG-IP shell:

tmctl -d blade tmm/device_probed

Review the driver_in_use column:

  • If it shows xnet, the DPDK driver is active.

  • If it shows sock, the sock driver is active.

Switch Back to Sock Driver (If Accelerated Networking Is disabled)

Impact of procedure: The following procedure requires you to edit the /config/tmm_init.tcl file and restart the VE instance. Network traffic is disrupted while the system restarts.

Important: The /config/tmm_init.tcl file is not included with a configuration synchronization (ConfigSync); you must perform the procedure on each device individually. For members of a high availability (HA) device group, you must perform the following procedure on each member of the device group. Additionally, the procedure must be performed for each boot location you want to boot to.

If /config/tmm_init.tcl does not exist, create the file.  (for example, vi /config/tmm_init.tcl). The file will be created upon saving. If the file already exists, do not remove other data in the file unless directed by F5 Support.

Add the following line to /config/tmm_init.tcl

device driver vendor_dev f5f5:f550 sock

After making this change, you must reboot the BIG-IP
