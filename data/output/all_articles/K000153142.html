K000153142: Issue with nginx-asg-sync Agent, When Azure Virtual Machine Scale Sets (VMSS) distributed across multiple resource groups

Type
Support Solution
Published
2025-08-23
Updated
2025-08-23
Applies to
  • NGINX Products
  • NGINX Plus: R29, R32, R31, R30, R35, R34, R33
Source
https://my.f5.com/manage/s/article/K000153142

Description

  • You deployed NGINX Plus in Azure .
  • NGINX Plus is configured to load balance among the instances in multiple Azure Virtual Machine Scale Sets
  • You are using the nginx-asg-sync tool to automate the synchronization backend servers.
  • nginx-asg-sync uses the Azure API to get the list of IP addresses of the instances of a Virtual Machine Scale Set. 
  • However, if Azure Virtual Machine Scale Sets (VMSS) are distributed across multiple resource groups, you encounter issue when using nginx-asg-sync
  • nginx-asg-sync is limited to polling VMSS within a single resource group, which prevents automatic updates of backend server lists when VMSS span more than one resource group.

Environment

  • NGINX Plus
  • Microsoft Azure Cloud
  • NGINX in Active-Active High Availability (HA) mode
  • Multiple Azure VM Scale Sets (VMSS) located in different Azure resource groups
  • nginx-asg-sync

Cause

  • nginx-asg-sync is designed to poll and synchronize backend instances only from VMSS within a single Azure resource group.

Recommended Actions

  • nginx-asg-sync does not support aggregating or managing VMSS that are distributed across multiple resource groups.
  • If your deployment requires backend VMs from multiple resource groups, nginx-asg-sync will not be able to automatically synchronize all instances.
  • As a workaround, you may have to create and implement you own custom solution outside of nginx-asg-sync agent, which uses NGINX API and scripting to dynamically update the NGINX configuration with backend instances from all required resource groups.
