K000160957: BIG-IQ CM GUI keeps showing “Waiting on services restarting” after a large DNS configuration is imported

Type
Support Solution
Published
2026-04-23
Updated
2026-07-29
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.2, 8.4.X, 8.3.0, 8.3.X, 8.4.0, 8.4.1
Source
https://my.f5.com/manage/s/article/K000160957

Description

  • The BIG-IQ CM GUI keeps showing “Waiting on services restarting”.
  • The tokumond daemon is in a restart loop on the BIG-IQ CM.
  • The log file /var/log/tokumon/current shows messages similar to the following sample:

YYYY-MM-DD_HH:MM:SS.XXXX [SEVERE] es: _index:dns command:index status:400 _id:https://localhost/mgmt/cm/dns/working-config/wideip/a/XXXXXX-XXX-XXXX-XXXX-XXXXXXX error:{"type":"illegal_argument_exception","reason":"Limit of total fields [5000] in index [dns] has been exceeded"} see searchd log for complete error.

Environment

  • BIG-IQ 8.3 or 8.4
  • Import of a BIG-IP DNS configuration that includes more than 5,000 DNS items.

Cause

F5 tracks this issue as Bug ID 1571973

Recommended Action

To estimate the current total_fields limit value in the searchd Elasticsearch instance, use the following command:

curl -s XGET "localhost:9210/dns/_mapping" | jq . | grep "\":" | wc -l

There is a workaround to mitigate this issue by following these steps:

1. Change the /usr partition permissions to read/write to allow editing of configuration files:

mount -o remount,rw /usr

2. Make a backup copy of the tokumond configuration file dns.js:

cp /usr/share/rest/tokumon/config/modules/{dns.js,dns.js.orig}

3. Edit the /usr/share/rest/tokumon/config/modules/dns.js file using nano or vim. Under settings.index, modify the following line, then save the file and exit the editor:

settings: {}, // Use these to overwrite parts or all of ES_SETTINGS

To this:

settings: {   // Use these to overwrite parts or all of ES_SETTINGS
  "index" : {
    "mapping" : {
      "total_fields" : {
        "limit" : "5000"
      }
    }
  }
},

4. Force tokumon to delete and rebuild all indices in searchd:

bigstart kill tokumond

5. If tokumond enters a continuous restart loop, there is likely a syntax error in the changes made in step 3. In this case, stop tokumond, review and correct the changes from step 3, and then restart the service.

bigstart stop tokumond

6. If a similar error persists with the new limit, repeat steps 3 and 7, increasing the limit by 5,000 each time. The maximum supported value is 20,000.

If the problem persists, restore the file from the backup created in step 2 and open a case with F5 Support.

7. If tokumond is no longer in a restart loop, wait approximately five minutes for the indices to be created, and then verify the change:

curl -s localhost:9210/dns/_settings | jq .dns.settings.index.mapping

The follwing output will be seen:

{ "total_fields": { "limit": "10000" } } 

8. Ensure that the /usr partition is remounted as read-only:

mount -o remount,ro /usr
