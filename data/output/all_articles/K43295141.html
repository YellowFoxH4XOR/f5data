Known Issue

The BIG-IP system may erroneously permit you to configure custom health monitors with conflicting values.

This issue occurs when all of the following condition are met:

  • You create a custom health monitor setting interval to be greater than the timeout.
  • You apply the custom monitor to a server or virtual server object.

    Example:

    gtm monitor http exmple_misconfiguration {
        defaults-from http
        destination *:*
        interval 50
        probe-timeout 5
        recv none
        send "GET /"
        timeout 3
    }

    Note: The timeout value (3) should be greater than the interval value (50) to avoid having the BIG-IP system erroneously mark the server as unavailable.

Impact

The BIG-IP system may erroneously mark the monitored object as unavailable.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You notice in /var/log/gtm log file that the monitored object state continually changes from available to unavailable and back.

Workaround

To work around this issue, you can ensure that monitor timeout values are greater than the interval value. F5 recommends setting the timeout value three times higher than the interval value, plus one second. For example, a monitor configured with an interval of 10 seconds should have a timeout value of 31 seconds.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
