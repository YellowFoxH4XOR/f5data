Description

Some of the ASM Event Logs / Support IDs are missing on BIG-IP.
Ignored traffic counter > 0 in /var/log/ts/pabnagd.log (available in v14.1.x and later):

pbngmodel  |NOTICE |Mar 10 15:03:42.413|11062|PabNagModel.cpp:949|Resources: CPU use in last 60s: tot=6% (usr=5%, sys=1%), traffic: 11131 (185/sec), ignored traffic: 422 (7/sec), config-in: 0 (0/sec), config-out-suggestions: 31 (0/sec), config-out-rql-proto: 47 (0/sec), config-out-other: 0 (0/sec). Memory usage: VmSize=3938660 VmRSS=330672

pbngmodel  |NOTICE |Mar 10 15:01:42.387|11062|PabNagModel.cpp:949|Resources: CPU use in last 60s: tot=5% (usr=5%, sys=0%), traffic: 8162 (136/sec), ignored traffic: 3391 (56/sec), config-in: 0 (0/sec), config-out-suggestions: 48 (0/sec), config-out-rql-proto: 48 (0/sec), config-out-other: 0 (0/sec). Memory usage: VmSize=3938660 VmRSS=330672

Environment

  • ASM Event logging locally on BIG-IP

Cause

BIG-IP ASM Local Event logging is a best effort feature. ASM system focuses on protecting customer application and the resources reserved for local logging are limited.

Recommended Actions

You can confirm, that you are running into described limitation by reviewing ignored traffic counter in /var/log/ts/pabnagd.log (available in v14.1.x and later) or by running a test.
During the test you can generate multiple illegal requests and note Support IDs:

  1. Browse to the ASM protected VS and trigger any violation (for example, you can try to trigger a XSS signature violation by browsing to the site https://<domain name>/?a=<script>. Make sure that parameter XSS signature is enabled).
  2. Try refreshing the page a few times and record the support IDs being received.
  3. [Optional] Go to your remote syslog server and verify if you can locate all the Support IDs seen in the browser on the remote ASM syslog server.
  4. Verify if Support IDs seen in the browser, are ALL visible in BIG-IPs GUI Security  ››  Event Logs : Application : Requests.

If all or some of the Requests / Support IDs are missing, you are most likely running into local ASM Request logging limitation. Please follow below recommendation:

  1. F5 recommends using remote syslog servers to store any logs generated by BIG-IP, including ASM Event logs.
  2. Avoid using logging profiles, that log all requests. Logging all request should be used for troubleshooting purposes and disabled when not needed. Logging only illegal requests is preferred. Switching from 'Log All' to 'Log Illegal Requests' can prevent logging from hitting the limit or at least decrease number of requests that are not logged.

Additional Information

Missing Event logs can also be result of high number of logged Request resulting in fast log rotation. Following article describes BIG-IP ASM request log rotation.
K45320421: ASM event logs are deleted or rotated out very quickly
