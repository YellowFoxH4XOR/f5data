Known Issue

This is the result of a known issue. After installing BIG-IP version 9.4.2 or later on a 520 or 540 (D35) platform and adding a VLAN, TMM CPU utilization spikes to 100 percent when the system is not processing any traffic.

For example, an idle BIG-IP 540 (D35) platform running version 9.4.5 displays the following partial tmstat output:

CPU: 100% busy 0% idle 0% sleep

This issue should not impact TMM's performance as the extra CPU polling cycles are used for processing traffic when the box is under load. However, Linux host processes such as httpd and gtmd receive less CPU time. This behavior will negatively affect management and BIG-IP GTM performance, depending on the platform:

  • 520 platform

    The 520 platform is a single-processor system. If you install BIG-IP version 9.4.2 or later on a 520 platform, Linux host processes are only guaranteed 10 percent of the CPU time, and management and BIG-IP GTM performance is heavily degraded. F5 Networks does not recommend installing BIG-IP version 9.4.2 through 9.4.5 on the 520 platform.
  • 540 platform

    The 540 platform is a dual-processor system. If you install BIG-IP version 9.4.2 or later on a 540 platform, you will most likely not experience noticeable Linux host process performance degradation.

F5 Networks Product Development tracked this issue as CR106634 and it was fixed in BIG-IP version 9.4.6. For information about upgrading, refer to the BIG-IP LTM, GTM, Link Controller, and WebAccelerator Release Notes.
