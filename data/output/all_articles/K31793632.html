Description

It is often necessary to create a decrypted capture in order to track down an issue while troubleshooting.

This has most often been done by adding an iRule to the virtual in question.

This can be cumbersome as there can be many variables in how and what proper format to use to capture the proper traffic.

Note: If you are trying to decrypt https monitor traffic from the BIG-IP, this process will only work if you have In-TMM monitoring enabled.

Environment

  • TLS Traffic
    • TLS (Including TLSv1.3)
    • QUIC
    • HTTP/2
  • BIG-IP 15.0.0 and later
  • Virtual Server with a client-ssl or server-ssl profile applied.
  • Administrator access to tmsh or the Advanced Shell (bash)

Cause

The DB Variable tcpdump.sslprovider has been introduced and will cause the LTM to save the TLS Master Secret, Client Random and Server Random data to the end of each TLS packet in the capture.

Recommended Actions

  • Enable TLS Session Secret Ethernet Trailers
  • Capture Traffic with --f5 ssl flag
  • Create Pre-Master Secret Log File Using tshark
  • Disable TLS Session Secret Ethernet Trailers
  • Enable F5 Ethernet Trailers for TLS
  • Create Pre-Master Secret Log File By Hand
  • Load Pre-Master Secret Log File Into Wireshar
  • Create a single decrypted pcap file (optional)

Enable TLS Session Secret Ethernet Trailers

Starting in version 15.0.0 sys db tcpdump.sslprovider has been added. That will enable you to create the information needed to decrypt a capture.
Note: We recommend disabling the db after use. 

  1. SSH to log into the Advanced Shell (bash) prompt.
  2. Run the following command:
    tmsh modify sys db tcpdump.sslprovider value enable

Capture Traffic with --f5 ssl flag

To use the new functionality, add --f5 ssl to the tcpdump flags.

For example

tcpdump -s0 -nni 0.0:nnn --f5 ssl host 192.0.2.100 -vw /var/tmp/decrypt.pcap

Important: When you perform a tcpdump capture with tcpdump.sslprovider enabled, understand that the TLS master secret will be written to the tcpdump capture itself. Be careful with whom you share the capture file.

Important: Using the "ssl" option captures additional information related to the SSL/TLS connections, such as master secrets. This enables some packet capture analysis tools to decrypt the SSL/TLS payload in the captured packets. Use only as needed for troubleshooting purposes, and handle captured data with caution.

Most often, due to the full proxy architecture of the BIG-IP the capture will need to catch traffic on both sides of the BIG-IP. To do so the syntax will need to include the IP, and normally the port, of the appropriate traffic on the client and server side. There is a way to so outside of that by including the "p" flag in the capture. To do so please review  K20233108: Running the tcpdump utility using the p interface modifier prior to doing so.

Note: As a quick preliminary check, that the packet capture does include the information needed to decrypt a capture, the utility tshark can be be used with the appropriate display filter:

ssl && frame matches "\xf5\xde\xb0\xf5....\x00\x04\x00\x00"

or

tls && frame matches "\xf5\xde\xb0\xf5....\x00\x04\x00\x00"

For example:

[root@bigip:Active:Standalone] # tshark -r file.pcap -Y "ssl && frame matches \"\\xf5\\xde\\xb0\\xf5....\\x00\\x04\\x00\x00\""

Create Pre-Master Secret Log File Using tshark

Note: This procedure can be performed on BIG-IP version 17.1.1 and later. Older versions of the BIG-IP operating system do not contain the newer version of tshark needed to create the .pms file using this command. In most cases the F5 Support engineer assisting you can upload the pcap files to a repro and do this for you, if you do not access to do that version of the OS.

  1. Log into a BIG-IP system running version 17.1.1 or later, or copy the capture to a Unix workstation or shared environment with a current version of tshark (3.2 or later).

  2. Run the following command to create a Pre-Master Secret Log File named pre_master_log.pms:
    Note: Replace decrypt.pcap with the name of your packet capture file.

    tshark -r decrypt.pcap -Y f5ethtrailer.tls.keylog -Tfields -e f5ethtrailer.tls.keylog | sed 's/,/\n/g' > ./pre_master_log.pms

Disable TLS Session Secret Ethernet Trailers

To revert back disable SSL key logging via tcpdump, enter the following command:

  1. SSH to log into the Advanced Shell (bash) prompt.
  2. Run the following command:

    tmsh modify sys db tcpdump.sslprovider value disable

Enable F5 Ethernet Trailers for TLS

Open Wireshark (version 3.2 and later) and ensure you have the F5 TLS Dissector enabled.

  1. Navigate to Analyze > Enabled Protocols
  2. Check the box to enable Protocol F5 TLS : Description F5 Ethernet Trailer Protocol - TLS Provider

  4. Right Click the line with [Keylog entry:] (all four will be needed and are done one at a time)
  5. Click Copy > Value
  6. Paste the value into a text document and name it pre_master_log.pms (this is arbitrary).
  7. Repeat Steps 3 through 6 for all desired streams.

Load Pre-Master Secret Log File Into Wireshark

Load the Pre-Master Secret Log file into Wireshark and start decrypting Application Layer (L7) data.

  1. In Wireshark Navigate to Edit > Preferences > Protocols > TLS
  2. In the section labeled '(Pre)-Master-Secret log filename' browse to the pre_master_log.pms file and click OK.

If all goes well, you will now be observing decrypted L7 data.

Create a single decrypted PCAP file (optional)

If required, you can inject the TLS secret into a PCAP file to have a single decrypted PCAP file. 

To inject TLS secret into a PCAP file, use the following command:

editcap --inject-secrets tls,<pms_file> <input_tcpdump_file> <output_tcpdump_file>

For example:

editcap --inject-secrets tls,pre_master_log.pms decrypt.pcap decrypted.pcap

Note: After injection, you can open the decrypted.pcap file in Wireshark to view decrypted TLS traffic.

Additional Information

Using this method will take some practice, but alleviates having to deal with adding an iRule to a virtual server. This can ease many things. For example where iApps are involved and dealing with disabling strict updates or ensuring the iRule syntax is correct and functions as desired.
