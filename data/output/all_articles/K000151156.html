Description

Under certain scenarios you may want to while list an IP address in ASM/AWAF policy.

Once done ASM/AWAF policy will not enforce the checks on that IP address.

Environment

  • BIG-IP ASM/AWAF 

Cause

How not to enforce ASM/AWAF policy checks on an IP address.

Recommended Actions

Creating IP address exceptions

For each security policy, you can create a list of IP address exceptions, and indicate how you want the system to handle the traffic from these IP addresses. From the centralized IP Address Exceptions list, you can configure whitelists or blacklists to allow or block traffic from an IP address or subnet.

1. On the Main tab, click Security ›› Application Security : Security Policies : Policies List

2. Open a security policy

3. Navigate Policy Configuration > IP Address Exceptions

4. Click Create

5. The above fields are displayed and are configurable as follows.

IP Address

List of IP addresses that the security policy trusts.

Note: You can add %n after an IP address to add a route domain, where «n» is the route domain identification number.

Netmask

The netmask of the IP address. p class="note">Note: If an IP address belongs to more than one range (using netmasks) so that there are overlapping IP address ranges, then the range with the longest prefix mask takes precedence.

Description

Enter a brief description of the IP address. This field is optional and only used when creating an exception. It is not displayed in the IP Address Exceptions List.

Block this IP Address

How the system responds to blocking requests sent from this IP address.

Policy Default: The Application Security > Policy > Blocking > Settings will be used for requests from this IP address.

Never Block: The system does not block requests sent from this IP address, even if your security policy is configured to block all traffic.

Always Block: The system blocks requests sent from this IP address on condition that IP is blacklisted is set to Block under Policy Building Settings.

Policy Builder Traffic

How the Policy Builder treats traffic from this IP address.

Trust this IP: The Policy Builder considers traffic from this IP address to be legitimate. The Policy Builder automatically adds to the security policy data logged from traffic sent from this IP address.

Don’t trust IP: The Policy Builder does not consider traffic from this IP address to be any different than traffic from any other IP address.

Brute Force Detection

How the security policy treats traffic from this IP address with regard to brute force detection.

Ignore IP: Specifies that the system considers traffic from this IP address to be safe. The security policy does not take this IP address into account when performing brute force prevention from requests which were sent from this IP address. The system performs brute force prevention to traffic from this IP address according to the configuration of the security policy.

Include IP: Specifies that the system does not consider traffic from this IP address to be any safer than traffic from any other IP address. The system performs brute force prevention to traffic from this IP address according to the configuration of the security policy. Once you enable this option, the system automatically adds this IP address to the IP Address Whitelist setting on the Brute Force Attack Prevention screen.

Learning Suggestions

How the system treats traffic from this IP address with regard to learning suggestions.

Ignore IP: The system does not generate learning suggestions from traffic sent from this IP address.

Include IP: The system generates learning suggestions from traffic sent from this IP address for violations with the Learn check box enabled on the Learning and Blocking Settings screen.

Log Traffic from this IP Address

Whether the system logs traffic sent from this IP address.

Allow Logging: The system logs traffic sent this IP address according to the violation settings on the Security > Application Security > Blocking > Settings screen and according to the configured logging profile.

Never Log: The system does not log requests or responses sent from this IP address, even if your security policy is configured to log all traffic.

IP Intelligence

Whether the system compares this IP address to the IP Intelligence database (a database of questionable IP addresses).

Ignore IP: The system considers traffic from this IP address to be safe even if it matches an IP address in the IP Intelligence database.

Include IP: The system does not consider traffic from this IP address to be any safer than traffic from any other IP address. As a result, if the IP Intelligence feature is enabled, the system continues to check whether this IP address matches any IP addresses in the IP Intelligence database.
