K000157085: Failed to upgrade to v15.1.10.8 because /var partition becoming 100% full

Type
Support Solution
Published
2025-10-22
Updated
2025-10-22
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.7
  • BIG-IP LTM: 15.1.7
Source
https://my.f5.com/manage/s/article/K000157085

Description

Upgrading BIG-IP LTM on the F5-BIG-I7800 platform from version 15.1.7 to 15.1.10.8 can result in the /var partition becoming 100% full, causing critical services such as mcpd and devmgmt to continuously restart and preventing normal system operation. Common error messages include:

mkdir: cannot create directory '/var/run/bigstart': File exists

[FAILED] Failed to start System Logger Daemon. See 'systemctl status syslog-ng.service' for details.

Disk partition /var has only 0% free

logger: tomcat can't start because /var is at 100%.

exception: (Can't create tmsh temp directory "...": No space left on device) (framework/TempDir.cpp, line 139), exiting...

Attempts to add disk space after booting into the new volume do not resolve the issue.

Environment

  • Product: BIG-IP LTM
  •  
  • Platform: F5-BIG-I7800, C118
  •  
  • Software Version: Upgrade from 15.1.7 to 15.1.10.8
  •  
  • Provisioned Modules: ASM (Application Security Manager)
  •  
  • Configuration: Large UCS files and ASM configuration present

Cause

Insufficient disk space allocated to the /var and /usr partitions during the upgrade process leads to these partitions filling up completely when loading large configurations or ASM data after upgrade, resulting in service failures.

Recommended Actions

  1. Delete the affected software volume
    Run: delete sys software volume HD1.2 (replace HD1.2 with your target volume).
  2. Reinstall BIG-IP version
    Install BIG-IP 15.1.10.8 onto the deleted volume.
  3. Verify installation
    Use tmsh show sys software to confirm successful installation of version 15.1.10.8.
  4. Increase partition sizes before booting into new volume
    Before booting into the newly installed volume, increase /usr  and /var  partition sizes using procedures described in K000148660: How to resize disk partitions on BIG-IP VE or hardware platforms running TMOS v14.x and later releases (including v16.x).
    Example commands:

    lvextend -L+1000M --resizefs /dev/mapper/vg-db-sda-set.2._usr

    lvextend -L+1000M --resizefs /dev/mapper/vg-db-sda-set.2._var

    Adjust logical volume paths as appropriate for your system.
  5. Boot into upgraded volume
     After resizing partitions, boot into the new software volume.
  6. Verify system operation
     Ensure all services start normally and that /var  and /usr  have sufficient free space.
