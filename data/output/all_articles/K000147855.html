K000147855: How to make F5® Distributed Cloud Load Balancer retry when an 5xx error has been returned by the origin server?

Published

Updated

Applies to

  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000147855

Description

To avoid prompting your website visitors with an error, in some cases a good workaround is to have the load-balancer sending the request to the origin web server again.

Example: sporadic/random connectivity issues end-up causing HTTP 503 errors.

Environment

  • F5® Distributed Cloud HTTP Load Balancer

Cause

You want to modify the default retry behavior of one (1) retry to increase it or set it to zero (0).

Recommended Actions

Before starting with the actual setup, gather as much information as possible on the requests that are causing errors (domain, path, HTTP method...). Then visit the configuration section of the corresponding load-balancer and:

  1. In the top-right corner click on Edit Configuration
  2. Scroll down to the Route section, activate Show Advanced Fields if necessary, and click on Configure
  3. In the Routes list that appears, click on Add an item if the list is empty, or click on the route matching the path causing the errors you are trying to remove
  4. If you were adding an item in the previous step, adjust the parameters in the screenshot below to match as closely as possible the errors you are trying to suppress. Note that adding an origin pool is mandatory.
  5. At the bottom of this, find the Advanced Options, and click on Configure
  6. Scroll down to Miscellaneous Options and choose Custom Retry Policy
  7. Click Configure and in the Retry Condition form that appears, add a retry condition on errors 5XX like in the screenshot below. It is up to you to adjust the Number of Retries or the Per Try Timeout (in ms) as necessary:
  8. Save your configuration by clicking on Apply, then Apply, then Add item, and your new route should be configured:

Repeat these steps for as many routes on which you need the load-balancer to retry sending the request to the origin server.

 

Additional Information

Be aware that, the per-try-timeout has to be greater than or equal to the max response time for a http request (you might set this to what's currently configured in the Route -> Miscellaneous Options -> Timeout (ms)). As well as, the Routes Timeout should be greater than or equal to No of Retries * (PerTryTimeout + MaxRetryInterval).

Example: if the PerTryTimeout is 30000ms and with 3 retries and 100ms max interval then the Routes timeout should be atleast 91000ms.

 

  • When the route points to multiple origin pools, on retry, it can go to a different origin pool
  • If priority is configured on the origin pool, then the request will be served only by the highest priority origin pools
