Description

After upgrading to epsec-1.0.0-936.0.iso, epsec-1.0.0-960.0.iso or epsec-1.0.0-969.0.iso on the APM, macOS clients start failing to pass the Access Policy and don't connect to the APM VPN or resource.

You will see messages like the following in the client edge.log (in ~/Library/Logs/F5Networks/ on the macOS device)

/PackageDownloader.mm, 84, PackageDownloader, PackageDownloader, Downloading package, https://vpn.example.com/public/download/mac_oesisInspector.tar
/PackageDownloader.mm, 154, PackageDownloader, PackageDownloader, Received response, code 200
/InspectionHostView.mm, 399, InspectionHost, InspectionHost, Package Downloader failed, Wrong package size

You will see messages like the following in the /var/log/apm on the APM

 notice tmm4[8267]: 01490567:5: /Common/an_AP:Common:54a1c486: Session deleted (network_error; code - 16388).

Environment

  • BIG IP APM providing Portal or Network Access
  • MacOS end user device running Edge Client (Browser connections using F5 Endpoint Inspector are not affected)
  • Endpoint tests like Anti-virus check, Anti-Malware check, Firewall check are configured in an Access Policy
  • Recently upgraded to epsec-1.0.0-936.0.iso or greater. 

Cause

With the release of epsec-1.0.0-936.0.iso and more recent there was an incompatibility with existing apm client versions (7.2.1, 7.1.9.x or 7.1.8.x).
This is a known issue and is tracked under ID 961977

With the release of newer epsec-1.0.0-969.0.iso there was another incompatibility with newer apm client versions (7.2.1.1, 7.2.1.1 and 7.1.9.9).
This is a known issue and is tracked under ID 1021141

The endpoint inspection tests above check the APM for updates, and if available downloads the latest mac_oesisInspector.tar
In epsec version 936 and above this download fails, and the incoming session test responds "Deny", and the end user VPN connection fails.

Recommended Actions

  • A fix for the problem introduced with epsec 963, was included in the following apmclient.iso releases 7.2.1.1, 7.1.9.8 and 7.1.8.5
  • A fix for the problem introduced with epsec 969,  was included in the following apmclient.iso releases 7.2.1.3 and 7.1.9.9 update 1
  • Recommend upgrading to apmclients 7.2.1.3 (as this has the latest CVE fixes) or 7.1.9.9 Update 1(aka 7199.2021.527.907-5235)
  • As macOS clients connect to the VPN they should automatically update their installed clients
  • You can then upgrade to the epsec release version 1003 or more recent, for the latest client OS support once your apmclient is upgraded

Additional Information

Manually downloading this epsec update is possible with the following steps (you will need to authenticate for some steps).
This could be pushed out along with the new APMCLIENTS installer using a MDM solution.

# Set the address of your APM
MYAPM="YOUR.APM.VPN.EXAMPLE.COM"
# Make the directory in case it doesn't exist 
sudo mkdir -p /Library/F5Networks/Inspectors
# move to that directory
cd /Library/F5Networks/Inspectors/
# get the updated file from APM
sudo curl -O https://${MYAPM}/public/download/mac_oesisInspector.tar
# unpack the file into the same directory
sudo tar -xvf  mac_oesisInspector.tar
# Remove the tar file you downloaded
sudo rm  mac_oesisInspector.tar
#Check for the latest version date string
cat OesisInspector.ver
