Known Issue

A client connection may stop responding when the NT LAN Manager (NTLM) and OneConnect profiles are used together.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured to use the NTLM and OneConnect profiles.
  • Client connections use NTLM authentication to access resources.

Impact

A client connection is not serviced and the Traffic Management Microkernel (TMM) leaks memory. Over a long period, this issue may cause widespread service disruptions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the NTLM authentication profile and a OneConnect profile are used together in an LTM virtual server to label an authenticated connection to a Domain Controller (DC), the connection stops responding if the persisted connection to the DC is reused.
  • If the sweeper fails to clean up the suspended connection, the system leaks memory.

Workaround

To work around this issue, you can avoid using OneConnect profiles for virtual servers that use NTLM profiles.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system. Connections to the DC are not pooled, but all other features are retained.
