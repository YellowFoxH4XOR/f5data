K000135020: False-positive violations may occur when parsing binary content as text

Type
Support Solution
Published
2023-06-13
Updated
2023-06-13
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000135020

Description

ASM attack signature and meta-character violations may occur when configured to handle binary parameter values or request bodies as text data.


Environment

  • ASM policy applied to VS
  • Parameter value types set to any textual data type
  • Body handling set to JSON or XML
  • Receiving binary data

Cause

Due to the nature of binary data being represented by printable ASCII characters when transferred via HTTP, strings and patterns may develop in these files which match textual ASM attack signatures or result in meta-character and language encoding violations.


Recommended Actions

In general, it is not recommended to configure ASM to parse binary fields as a text input. Disabling meta-character checks and attack signature checks at the parameter level will remove these false positives. It is recommended to use third party ICAP inspection services to check binary data for viruses or malicious behavior if available. F5 recommends identifying any file upload parameters (usually sent in multipart-formdata) and configuring these as explicit parameters with data type "File Upload" which will allow some simple binary and length checks, or setting Parameter Value Type to "Ignore Value".


If using TMOS v15.1+ and a file upload parameter could also receive plain text input then using the Parameter Value Type "Auto-Detect" will allow limited detection of binary content to avoid applying meta-character or signature checks only when binary is received while retaining these checks on plain text.
