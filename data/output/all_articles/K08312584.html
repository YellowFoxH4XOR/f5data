Description

Application server administrator is reporting that the F5 BIG-IP is not load balancing the traffic to all the pool members according to the configuration.

Based on the BIG-IP pool statistics, it shows that the BIG-IP is load balancing the traffic correctly according to the configuration.

Environment

The following conditions must be met

  • BIG-IP LTM
  • Persistence profile is not used
  • OneConnect profile is not used
  • Pool members are up.
  • The uneven load balancing is seen/indicated from the servers but not on the BIG-IP
  • BIG-IP Pool statistics shows traffic load balanced as per load balancing method

Cause

The issue is very likely that the connection is not being processed by the BIG-IP. Instead, the traffic is being forwarded directly to the server (pool member).

Recommended Actions

You will need to confirm that the BIG-IP is properly load balancing the traffic.

  1. Login to the Configuration Terminal (GUI)
  2. Navigate to Local Traffic > Pools > Pool List
  3. Click on the pool name
  4. Click on Statistics
  5. Compare the Bits and Packets of all the pool server. If the values matches the load balancing method, it means the load balancing is working as expected.
Once you have confirmed that the BIG-IP is load balancing the traffic as per configured load balancing method, you will need to run a packet capture on the server which is receiving the traffic. The packet capture will identify what device is forwarding the traffic to the server.
