Source
https://my.f5.com/manage/s/article/K41286542

Description
Velos system controller has CrashLoopBackOff state for master-etcd-controller-x.chassis.local.

on CLI of the affected controller, can not run the below script.

/etc/etcd/dump_etcd.sh
-bash: /etc/etcd/dump_etcd.sh: No such file or directory

/etc/etcd does not have any files.

Environment

  • F5OS-C
  • Velos
  • Controller
  • CrashLoopBackOff

Cause

  • unknown.

Recommended Actions

  1. set all tenants Provision mode on GUI
    or On Partition CLI, log in as admin,
    # config
    (config)# tenants tenant <tenant_name1> config running-state provisioned ; top
    (config)# commit
    repeat above commands for all tenants, once all done, rather commit command, run:
    (config)# commit and-exit
     
  2. Then check the tenant status
    # show tenants tenant state status
    NAME       STATUS
    ---------------------------
    tenant1    Provisioned
    tenant2    Provisioned
    tenant3    Provisioned
     
  3. on CLI of Active Controller (use floating IP), log in as root and run
    touch /var/omd/CLUSTER_REINSTALL
     
  4. Above command triggers to reinstall OpenShift,
    If you are on the version affected by this bug:
    Bug ID 1138085: On VELOS, reinstalling OpenShift does not return partition to functional state
    partition need to be disabled and reinabled.

    set all partition disabled, and then enabled on Controller GUI, or
    on Controller CLI with
    su admin
    # config
    (config)# partitions partition <name of partition> config disabled ; top
    (config)# commit
    (config)# partitions partition <name of partition> config enabled ; top
    (config)# commit
    repeat above commands for all partitions, once all done, rather commit command, run:
    (config)# commit and-exit
     
  5. check all enabled properly
    # show partitions
                                                                               RUNNING
                          BLADE OS    SERVICE                 PARTITION        SERVICE     STATUS

                                                  2           running-standby  1.5.0-8535  0d
    MyPartition2      1   1.5.0-8535  1.5.0-8535  1           running-active   1.5.0-8535  0d
                                                  2           running-standby  1.5.0-8535  0d

                                                  2           disabled         -           -
     
  6.  Then log in to Partition GUI, and set all tenants status to Deploy, or
    Partition CLI, log in as admin,
    # config
    (config)# tenants tenant <tenant_name1> config running-state deployed ; top
    (config)# exit
    repeat above commands for all tenants, once all done, rather commit command, run:
    (config)# commit and exit
     
  7. Check the tenant status
    # show tenants tenant state status
    NAME       STATUS
    ---------------------------
    tenant1    Running
    tenant2    Running
    tenant3    Running
