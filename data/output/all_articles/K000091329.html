K000091329: NGINX caches ip addresses of upstream server domain names

Type
Support Solution
Published
2022-03-22
Updated
2022-03-22
Source
https://my.f5.com/manage/s/article/K000091329

Description

NGINX performs name resolution queries for upstream server domain names upon service starts and reloads and after TTL of cached responses expire. NGINX caches the name resolution responses using the TTL value obtained from said responses.

 Environment

NGINX Plus with one or more upstream servers specified via a domain name

 Cause

Default behavior

 Recommended Actions

To override this default behavior implement the resolve parameter within the server directive of the desired upstream configuration.

Note: the resolve parameter requires the resolver directive to be implemented

Example:

http {
...
  resolver 192.168.0.1;
  upstream example {
    zone upstream_example 64k;
    ...
    server upstream.example.com   resolve;
    ...
  }
  server {
    ...
    location / {
      ...
      proxy_pass http://example;
    }
  }
...
}

Alternatively to or in conjunction with the resolve parameter implement the valid parameter within the resolver directive and set it to a low time value.

Example:

http {
...
  resolver 192.168.0.1 time=5s;
...
}

The above example will result in NGINX setting the TTL value for name resolution responses to 5 seconds, overriding the original TTL value returned from said responses.

 Additional Information

For more information on the resolve parameter refer to the server directive of the ngx_http_upstream_module.html#server documentation
For more information on the resolver directive and the valid parameter therein refer to the ngx_http_upstream_module.html#resolver documentation
See example NGINX+ configuration implementing resolver and resolve for load balancing AWS ELBs:  Using NGINX Plus in Front of ELB
