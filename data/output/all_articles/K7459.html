Known Issue

This is the result of a known issue. The BIG-IP LTM system may not respond to traceroute UDP packets if the packet is sent to a virtual address that shares the same address used by a mapped SNAT that is defined on the same VLAN as the BIG-IP LTM system.

Under normal conditions, the BIG-IP LTM system responds to both ICMP- (Microsoft Windows) and UDP- (Unix/Linux) based traceroute packets. If the virtual address that is used for the destination address also shares the same address for a mapped SNAT on the same VLAN, the SNAT can incorrectly intercept the packet and prevent a reply from being issued.

Note: In all versions of the BIG-IP LTM code, UDP traceroute packets are accepted by a Forwarding VIP (IP or Layer 2) that is defined on the same ingress VLAN as the target of the traceroute and is configured to accept UDP traffic. This behavior is by design, and is not currently scheduled to change in any future version. In all conditions, ICMP traceroute replies are not affected.

F5 Product Development tracked this issue as CR63896 and it was fixed in BIG-IP LTM 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
