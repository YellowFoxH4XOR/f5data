Description

You are trying to add a new GTM/DNS device to an existing GTM sync group. You've performed gtm_add and there are no output errors on the command line, however the GTM configuration was not pulled over or didn't synchronized.

Environment

  • BIG-IP GTM/DNS
  • Adding a new GTM device to an existing GTM sync group
  • gtm_add result is ok but GTM config didn't successfully sync
  • there's an error on /var/log/gtm at the time of synchronization:
    err iqsyncer[20361]: 011ae104:3: Gtm config sync result from local mcpd: result { result_code 17237778 result_message "01070712:3: Values(/<partition>/<external monitor script name>) specified for external monitor parameter (/<partitiopn>/<monitor name> 2 RUN_I=): foreign key index (to_file) do not point at an item that exists in the database." }

Cause

The existing GTM devices have external health monitors referencing an external file. The command gtm_add failed to pull the configuration because the new GTM did not have the external file uploaded locally on this device. This is also related to BUG ID511865.

Recommended Actions

  • Step 1: Upload/Import the same external file to the new BIG-IP DNS/GTM. Follow the steps below:
  1. Navigate to System > File Management.
  2. Click the tab for the file type that you intend to import. For example, if you want to import an external monitor script file, click External Monitor Program File List.
  3. Click Import.
  4. Browse to the location of the external file type that you want to import, and then click Open.
  5. In the Name box, type the file name or click Overwrite Existing to overwrite an existing file.
  6. Click Import.
  • Step 2: Run gtm_add command from the new BIG-IP DNS/GTM and it should now synchronize the configurations
