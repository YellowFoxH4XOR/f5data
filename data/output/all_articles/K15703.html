Known Issue

The BIG-IP APM apd process may experience high CPU utilization when using Kerberos.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured to use Kerberos authentication.
  • The connection to the Kerberos distribution center is closed immediately after having been established.

Impact

System performance may degrade over time, and the system may eventually stop responding or reboot due to resource exhaustion.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Output from the top or ps commands shows high CPU usage for the apd process.
  • System performance degrades over time and the system eventually stops accepting new connections.
  • The system becomes unresponsive or reboots.

Workaround

To recover from this issue, you can restart the apd process. To do so, perform the following procedure:

Impact of workaround: Traffic is briefly disrupted while the apd process restarts.

  1. Log in to the BIG-IP APM command line.
  2. To restart the apd process, type the following command:

    bigstart restart apd

  3. Use a command such as top or ps to confirm CPU utilization has been reduced. For example, you can use the following ps command:

    ps aux |grep "CPU"; ps aux |grep /usr/bin/apd

    Output appears similar to the following example:

    USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND

    root 22747 0.0 0.9 141248 36832 ? Sl Oct07 0:01 /usr/bin/apd -d 5 -f -n 20 -u 2
