Known Issue

The Configuration utility may fail to export a properly formatted Secure Socket Layer (SSL) certificate that is in (Distinguished Encoding Rules) DER format.

This issue occurs when the following condition is met:

  • You use the Configuration utility to export an SSL certificate that is stored in DER format.

Impact

Your certificate file becomes corrupted after the export and may become invalid.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system exports a corrupted SSL certificate.
  • All bytes with values greater than 0x7E are replaced with 0x3F, and a byte 0x0a is added to your exported certificate at the end of the binary file.

Note: This issue does not occur in BIG-IP 13.0.0 and later.

Workaround

To work around this issue, instead of using the Configuration utility, you can use the openssl command line utility to export the certificate; you must have Traffic Management Shell (tmsh) or Advanced Shell (bash) access. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP system.
  2. To export the certificate in a different format, use the following command syntax:

    openssl x509 -out <path_to_cert>/<output_cert_name> -in <path_to_cert>/<input_cert_name> -inform <input_format>

    For example, to export the certificate that is stored in the DER format myder.crt to a mycert.pem in the PEM format, you would type the following command:

    openssl x509  -out mycert.pem -in /config/filestore/files_d/Common_d/certificate_d/\:Common\:myder.crt_75978_1 -inform der
