Known Issue

The BIG-IP system may experience a memory leak when processing Secure Sockets Layer (SSL) client chain certificates.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with a Client SSL profile that requires client authentication.
  • The client sends a certificate chain signed by an intermediary during the SSL handshake.
  • The Client SSL profile has only the Root certificate for the chain that is configured for Trusted Certificate Authorities.

Impact

System performance may degrade over time, and the system may eventually become unresponsive or reboot due to memory exhaustion. If the system is configured as part of a high availability (HA) pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you monitor memory usage using the tmsh show /sys memory command, you observe that memory consumption for the ssl and work subsystems increases steadily and does not decrease over time.
  • Your BIG-IP system experiences intermittent performance degradation or becomes unavailable.
  • If configured for HA, your BIG-IP system fails over to the standby system.
  • Your BIG-IP system begins aggressive connection reaping to free memory; in the /var/log/ltm file, you observe messages similar to the following example:

    warning tmm1[<PID>]: 011e0003:4: Aggressive mode sweeper: 1 Connections killed

Workaround

To work around this issue, you can configure the Client SSL profile to trust all intermediate certificates in the certificate chain. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Click the name of the profile to edit.
  4. In the Trusted Certificate Authorities setting, select a trusted CA certificate bundle containing the Root CA and all Intermediate CA certificates used in the client certificate chain.
  5. To save the change, click Update.
