Description

This article will discuss:

  • How to speed up iBGP update messages

  • When trying implement an iBGP architecture and there are some parameters that you can adjust to suit your needs.

  • What to do if there is a delay of ~14s (the amount of delay may vary) after deleting one route.  For example:

Environment

  • iBGP
  • ZebOs
  • RIB

Cause

If you are experiencing a delay BGP routing delay, that it may be due to a mis-configuration.

Recommended Actions

To speed up the advertisement time  adjust the advertisement-interval and as-origination-interval for the iBGP neighbors to reduce advertisement time to. The values of the intervals for each parameter are the following:

neighbor <address> advertisement-interval <0-65535>
neighbor <address> as-origination-interval <1-65535>

  1. The first parameter is the advertisement-interval, most of the times we may think this is the only parameter we need to adjust to set the update interval. The advertisement-interval is the minimum time between advertisement updates to a neighbor. This value can be seen with the show ip bgp neighbor output, and the default iBGP value in ZebOS is 5 seconds. However, if we only modify this interval we may not have the desire results. For example, I set the advertisement-interval to zero, we may expect this will cause the updates messages being sent almost immediately but the results are different.

  2. The second parameter we need to adjust is the as-origination-interval.The as-origination-interval is the minimum time between updates that originate from our own AS (RHI routes fall into this category). The default here is 15 seconds. So depending on timing of an update it could be up to 20 seconds before an update gets advertised to the neighbor.

  3. To speed up the advertisement time we need to adjust the advertisement-interval and as-origination-interval for the iBGP neighbors to reduce advertisement time to.

router bgp 65210
bgp log-neighbor-changes
bgp graceful-restart restart-time 120
redistribute static
neighbor 10.120.139.194 remote-as 65210
neighbor 10.120.139.194 as-origination-interval 1
neighbor 10.120.139.194 advertisement-interval 0
!

Additional Information
This is how the configuration looks like without the as-origination-interval

router bgp 65210
bgp log-neighbor-changes
bgp graceful-restart restart-time 120
redistribute static
neighbor 10.120.139.194 remote-as 65210
neighbor 10.120.139.194 advertisement-interval 0


For example, I set the advertisement-interval to 0 and as-origination-interval to 1 and I got a delay of ~1s:
