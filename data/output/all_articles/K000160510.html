Description

After log rotation runs on the BIG-IP system, the most recently rotated log file (for example, /var/log/ltm.1) remains uncompressed until the next rotation cycle. Only on the following rotation does it become /var/log/ltm.2.gz. This behavior is by design due to the delaycompress directive present in the default BIG-IP logrotate configuration.

If immediate compression of rotated log files is required — so that ltm.1 becomes ltm.1.gz at the time of rotation rather than one cycle later — the logrotate configuration must be overridden via tmsh to remove the delaycompress directive and ensure the compress directive is active.

Symptoms: 
After a logrotate cycle completes, you observe a pattern similar to the following when listing /var/log/ltm*:

-rw-------. 1 root root 3.4M Jan 28 03:41 ltm.9.gz
-rw-------. 1 root root 3.2M Jan 29 03:19 ltm.8.gz
-rw-------. 1 root root 3.0M Jan 30 03:09 ltm.7.gz
-rw-------. 1 root root 3.3M Jan 31 03:41 ltm.6.gz
-rw-------. 1 root root 2.8M Feb  1 03:44 ltm.5.gz
-rw-------. 1 root root 3.0M Feb  2 03:16 ltm.4.gz
-rw-------. 1 root root 5.3M Feb  3 03:33 ltm.3.gz
-rw-------. 1 root root 3.3M Feb  4 03:06 ltm.2.gz
-rw-------. 1 root root 177M Feb  5 03:29 ltm.1         <-- uncompressed
-rw-------. 1 root root  83M Feb  5 14:18 ltm           <-- active log

The file ltm.1 is large and uncompressed, while all older rotated files (ltm.2.gz and beyond) are already compressed.

Environment

  • BIG-IP LTM
  • Version: 11.x – 17.x

Cause

The default BIG-IP logrotate configuration for /var/log/ltm includes both the compress and delaycompress directives. The delaycompress directive instructs logrotate to skip compression of the most recently rotated file (ltm.1) and instead compress it during the next rotation cycle. This is standard logrotate behavior intended to avoid compressing a file that a process (such as syslog-ng) may still have open.

Recommended Actions

The BIG-IP system uses template-based configuration management. Do not directly edit /etc/logrotate.d/syslog-ng or /var/run/config/logrotate_common.conf. Changes made directly to these files will be lost on restart or configuration reload. Always use tmsh to make logrotate changes, as described below.

Note: The syslog-include parameter is used here (rather than include or common-include) because /var/log/ltm is managed by the syslog-ng logrotate stanza. The syslog-include option appends configuration into that stanza, making it the correct parameter for overriding behavior of syslog-ng-managed log files such as /var/log/ltm.

Procedure to enable immediate compression for /var/log/ltm:

  1. Log in to the TMOS Shell (tmsh): 
    tmsh
  2. Edit the logrotate configuration: 
    edit /sys log-rotate all-properties
  3. Apply the override configuration using syslog-include to add compress without delaycompress for /var/log/ltm (in vi editor). Press 'i' for insert mode, then add: 
    syslog-include "/var/log/ltm {
    compress
    missingok
    notifempty
    sharedscripts
    postrotate
    endscript
}"

Note: The rotate count is intentionally omitted in the minimal example above. When omitted, logrotate inherits the global default from /etc/logrotate.conf, which is controlled by the Logrotate.LogAge database variable (default: 8 days/rotations). This is not the same as common-backlogs (default: 24). If you require a specific number of retained copies, explicitly add a rotate <N> directive as shown in the extended example below with explicit rotate count.
Example:

syslog-include "/var/log/ltm {
    compress          <-- Enable immediate compression (no delaycompress)
    missingok
    notifempty
    sharedscripts
    postrotate
    endscript
    rotate 2          <-- Number of rotated copies to keep
}"

Important: Ensure the compress directive is present and the delaycompress directive is NOT included.

  1. Save and exit:
    Press Esc, type :wq, press Enter 
  2. Save the configuration: 
    save /sys config
    Note that these changes might need to be done on both devices in an HA pair and will not survive upgrades. For further information on the 'logrotate' utility, you can consult the Linux manpages.
  3. (Optional) Verify the resulting logrotate configuration: 
    cat /var/run/config/logrotate_common.conf

Confirm that the /var/log/ltm stanza contains compress  and does not contain delaycompress.

  1. (Optional) After saving, validate that the syslog-ng configuration contains no syntax errors:  
    syslog-ng -s
     If the command returns no output, the syntax is valid and syslog-ng will load the configuration correctly. If an error is returned (e.g., syntax error at line X), the syslog-include stanza contains invalid syntax. In that case, correct it before proceeding, or roll back using: 
  2. (Optional) The following command tests the validity of the log rotation instructions, and may provide an indication as to why log rotation failed (This command does NOT perform any actual rotation and will show why postrotate script is not executed):  
    logrotate -d /etc/logrotate.conf
  3. (Optional) Test the rotation manually (forces an immediate rotation regardless of schedule): 
    logrotate -f /etc/logrotate.conf

After these runs, verify that ltm.1.gz (or ltm.1) is now compressed.

Please note: this command forces an immediate rotation of all logs defined in that configuration file, regardless of their normal schedule.

To roll back to default behavior:

modify /sys log-rotate syslog-include none
save /sys config

Impact of procedure: This change affects future logrotate cycles only. It overrides the default delaycompress behavior for /var/log/ltm. No traffic impact is expected.

Additional Information

  1. The syslog-include override configured via tmsh applies to future rotation cycles only. To compress an already-existing uncompressed ltm.1 file immediately, see the One-Time Manual Compression section below.
  2. These changes may not survive a software upgrade. After upgrading, re-apply this configuration. Alternatively, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive to include the configuration in a UCS file so it survives a single upgrade.

One-Time manual compression of an existing ltm.1 file:
If an uncompressed ltm.1 file already exists and you want to compress it immediately without waiting for the next rotation cycle, run the following command from the BIG-IP command line:

gzip /var/log/ltm.1

This will produce /var/log/ltm.1.gz immediately. This is a one-time manual operation and does not affect the logrotate configuration.

Note: Ensure no process is actively writing to ltm.1 before compressing it manually. Under normal BIG-IP operation, syslog-ng writes to the active ltm file, not to ltm.1, so this is generally safe.
