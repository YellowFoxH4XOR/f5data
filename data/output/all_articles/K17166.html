Known Issue

The Traffic Management Microkernel (TMM) may restart when IPsec lifebyte is enabled between security association (SA) endpoints.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP system as an IPsec SA endpoint.
  • The BIG-IP system or third-party device has an IPsec security policy with lifebyte enabled.
  • The BIG-IP system has negotiated IPsec security associations with the remote IPsec device.

    Note: The remote system can be a BIG-IP system or third-party device.

Impact

TMM may become unstable and produce a core file due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.

Workaround

To work around this issue, you can disable IPsec lifebyte. To disable lifebyte on the BIG-IP system, perform the following procedure:

Impact of workaround: Performing the following procedure may cause the established IKE security association to last longer than expected.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To disable IPsec lifebyte, type the following command:

    modify net ipsec ipsec-policy <policy_name> { ike-phase2-lifetime-kilobytes 0}

    For example, to disable lifebytes for the IPsec security policy named policy_one, type the following command:

    tmsh modify net ipsec ipsec-policy policy_one { ike-phase2-lifetime-kilobytes 0}
  3. To save the configuration, type the following command:

    save sys config
