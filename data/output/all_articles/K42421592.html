Description
bigd process has high CPU utilization.

Environment

  • BIG-IP
  • Any version

Cause

Any number of the following may cause bigd to have high CPU usage.

  • ECDHE/DHE cipher suite for HTTPS monitor or custom monitor which use SSL/TLS is very CPU intensive.

Note: This issue can be exacerbated when bigd is set to run in Single Threaded mode. See Bug ID 505973: Monitoring daemon, bigd, runs as single processes for distributed monitoring load for more information on this.

  • Too many 'content monitor' (HTTPS, HTTP, etc) instances are running for the spec of the BIG-IP.
  • Too many tcp-half open monitors. This comes down to how the tcp_half_open monitors work. They use the kernel SOCK_RAW binding instead of a SOCKET binding. This causes tcp_half_open monitors to process all SYN/ACK traffic returned to the host, trying to find the SYN/ACK response to the initial SYN that it sent to the monitored pool member.

Recommended Actions

One of below may mitigate this issue:

  • Use a simple monitor (TCP, ICMP etc) instead of (TCP half-open monitor, HTTPS, HTTP, etc)
  • Use in-band Monitor: K61010136: Overview of the inband monitor
  • Increase the interval of content monitor (HTTPS, HTTP, etc), if you configure several hundred instance per bigd thread
  • Disable ECDHE/DHE ciphers, from HTTPS monitors : K55584748: Configuring the SSL cipher strength for a custom HTTPS health monitor (13.1.0 and later)
  • Consider allocating the Linux host more memory from TMM.

    For example, to allocate and additional 500MB by entering the following command:

    tmsh modify sys db provision.extramb value 500

  • Use In-TMM monitor: K11323537: Configuring In-TMM monitoring
    Note: However, this function may have bugs and might not work as expected in your version.

Additional Information

To see how many bigd process are running, use the following command:

top -cbn 1  | grep bigd

  • If you see bigd -S in output, then only 1 bigd process is running.
  • If it has "/etc/bigstart/scripts/bigd.start --procs 10" in output, 10 bigd processes are running.

You can find out how many instances of these monitors you have running by generating a qkview and uploading it to iHealth. Once it is uploaded go to Status > Overview > Configuration Totals and click on the hyperlink for Monitor Instances.
