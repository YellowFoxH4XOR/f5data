Description

Packets are dropped on VMXNET3 interfaces on BIG-IP VE on VMware ESXi. This includes both packets destined to BIG-IP and transmitted by BIG-IP. This occurs when the vNIC ring buffer, or device queue, is full.

These packet drops may be observed in the following ways:

  • For packets transmitted by the BIG-IP, run ' tmctl -d blade -s iface,device,tmm,blocked,drop_rej_dd,drop_full_dq,drop_full_iq,drop_iface_inactive tmm/ndal_tx_stats -w 200 -SK iface,tmm ' and observe the blocked and drop columns. Blocked indicates TMM held packets in internal buffers because the device queue is full. Not all packets that cause a blocked event to occur are dropped.
  • For packets received by the BIG-IP, use vsish on the hypervisor to get stats for the interface. Look for lines similar to the following:
    running out of buffers:14
    # of times the 1st ring is full:14
    # of times the 2nd ring is full:0
    This indicates 14 events.
  • To see if 'drop' is related to ring buffer or not, while 'drop' is reproducing, check tmstat output and confirm if counter values increments during 'drop':
    • tmctl -d blade tmm/ndal_tx_stats
    • tmctl -d blade tmm/ndal_rx_stats
    • tmctl -d blade tmm/iq_rx_stats -OSK dropped
    • tmctl -d blade tmm/iq_tx_stats -OSK dropped


Additionally, if transmitted packets are dropped at a high rate you may see high CPU use due to Bug ID 888517.

Environment

  • BIG-IP VE
  • VMware ESXi 
  • VMXNET3 interfaces

Cause

The default ring buffer size configured by BIG-IP VE may be insufficient for the environment, or the hypervisor may need to be configured to handle higher throughput.

Recommended Actions

F5 recommends that you increase the ring buffer size (512, 1024, 2048 or 4096) and configure one transmit thread per vNIC on the hypervisor.

Impact of procedure: This procedure requires restarting the VM, which will interrupt traffic.

Note: The ring buffer sizes should be as small as possible while avoiding drops due to bursty traffic.  Finding the optimal size requires tuning and testing the VE environment.

  1. To increase the ring buffer sizes on BIG-IP to 4096, use a text editor to insert the following lines in /config/tmm_init.tcl 
    Important: this is version-dependent. If the content for v12-13 is used on v14 or higher, it may cause TMM to crash during startup. You must update this manually when upgrading.
    For v12-13:

    ndal rx_devq_sz 4096 vmxnet3

    ndal tx_devq_sz 4096 vmxnet3

    For v14 and higher:

    ndal rx_devq_sz 4096 15ad:07b0

    ndal tx_devq_sz 4096 15ad:07b0

  2. Shut down the BIG-IP VE.
  3. Configure ctxPerDev=1 for each vmxnet3 interface attached to the BIG-IP. Instructions to do this can be found in this DevCentral article.
    ctxPerDev=3 is also an option, allocating more resource on ESXi side per tx queue per interface rather than just per interface.  
  4. Start the BIG-IP VE.

Additional Information

The default ring buffer size in BIG-IP v12.x and v13.x is 256.
Starting in BIG-IP v14.x, the default ring buffer size has been increased to 512 to align with "standard" operating environments. 
Tuning and testing maybe necessary to determine the optimal performance VMWare environments.

The following commands can be used to verify the tx and rx buffer size values on BIG-IP VE:

  • tmctl -d blade tmm/ndal_rx_stats -s q_sz device=vmxnet3
  • tmctl -d blade tmm/ndal_tx_stats -s q_sz device=vmxnet3


The maximum ring buffer size is 4096. Any lower number which is a power of 2 may also be used (256, 512, 1024, 2048 or 4096).

Factors to be considered with overly large buffer sizes (not tuned for hypervisor):

  • increased latency
  • increased memory usage
