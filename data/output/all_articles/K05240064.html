Description

Traffic can be blocked due to Maximum Array Value on JSON Profile even when JSON profile is set to Any allowed value.

  • There are blocks in the event logs due to Maximum Array Value.
  • Configured Array Value is set to Any.
  • Block will look similar to this: 

    Violation Details
    JSON data does not comply with format settings [1]
    Failed DefenseMaximum Array Length
    Allowed Value-1
    Detected Value501
    DescriptionExceeded limits
    ContextURL
    JSON Profile<JSON Profile Name>
    Applied Blocking Settings Block Alarm Learn

Environment

Relevant environmental factors specific to the topic

  • Need to have custom JSON profile created in the security policy and it needs to apply to the incoming traffic.
  • Applies to ASM and Advanced WAF policies only.
  • JSON content profile option Parse Parameter is enabled which is the default setting.

Cause

There are two factors that apply to how this traffic is handled:

1. The first priority for limit value is Maximum Array/Object Elements length that can be found in: Security > Application Security > Content Profiles : JSON Profiles > JSON Profile Properties (default JSON profile). It will use the set value here and apply that to the specific traffic that matches.

2. In case that Maximum Array/Object Elements set to Any, the limit value is calculated to be the maximum value of Check maximum number of parameters and max_num_request_params. The default for this setting is 500.

So when you set Maximum Array/Object Elements to Any *then* it takes the max of Check maximum number of parameters and max_num_request_params otherwise it will just use whatever value you defined for Maximum Array/Object Elements. Overall the absolute maximum limit for the Check maximum number of parameters is 5000. 

Note: This is expected behavior. The JSON profile is functioning as designed.

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. If you are getting a block for the Maximum Array length and you have the value set to Any then it is likely the request contains more parameters then what is configured in the value of Check maximum number of parameters and max_num_request_params. 

    Note: The Check maximum number of parameters and max_num_request_params settings are a global setting for the specific security policy.
     
  2. Instead of setting the Maximum Array value to Any for the JSON profile, determine how many you need and then configure them appropriately by inputting a actual Maximum value.
     
  3. Apply that to the security policy and then test again.

Additional Information

bd internal parameters such as max_num_request_params can be set using the /usr/share/ts/bin/add_del_internal utility.

USAGE:

/usr/share/ts/bin/add_del_internal add <param_name> <param_value> [--default <default_value>]

/usr/share/ts/bin/add_del_internal update <param_name> <param_value> [--default <default_value>]

/usr/share/ts/bin/add_del_internal delete <param_name>
