Known Issue

Exporting BIG-IP ASM security policies may cause a memory leak.

This issue occurs when the following condition is met:

  • A long-lived process exports multiple security policies without being restarted.

    For example, the asm_config_server_rpc_handler process may leak memory if used by iControl to export multiple security policies.

Impact

The system may become unstable and possibly produce a core file as a result of exhausted memory.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP ASM system logs a bd core file to the /var/core directory.
  • The top command indicates that a long-lived process, such as the asm_config_server_rpc_handler process, is consuming excessive memory.

    For example, the following top output shows the asm_config_server_rpc_handler.pl process is consuming 1.5 GB of memory:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    19881 root 20 0 1.5G 912.9M 2.7M S 0.7 23.0 05:28:00.74 1 asm_config_server_rpc_handler.pl
  • The system becomes unresponsive as a result of exhausted memory.

Workaround

To work around this issue, you can restart the long-lived process that is exporting security policies. To do so, perform the following procedure:

Impact of procedure: Restarting the asm_config_server_rpc_handler process does not affect traffic processing or security enforcement on the BIG-IP ASM system.

  1. Log in to the BIG-IP ASM command line.
  2. Restart the long-lived process by typing the following command:

    # pkill -f asm_config_server_rpc_handler.pl
