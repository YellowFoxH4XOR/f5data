Known Issue

An iRule that calls a procedure may fail validation when you apply the iRule to a virtual server.

This issue occurs when all of the following conditions are met:

  • An iRule calls a procedure that contains one or more of the following HTTP commands:
    • HTTP::header
    • HTTP::method
    • HTTP::uri
    • HTTP::version
  • You reboot the BIG-IP system or a user restarts mcpd.
  • You apply the iRule to a virtual server.

Impact

Applying iRules to a virtual server fails with a validation error.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Applying iRules to a virtual server fails with a validation error.
  • In the /var/log/ltm file, you may observe messages similar to the following example:

    <HTTP command> command in a proc in rule (<rule>) under <event> event at virtual server (<virtual>) does not satisfy cmd/event/profile requirement.

Workaround

To work around this issue, you can modify the existing iRule to remove the procedure call and replace it with the code from the procedure.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your environment.

The following example shows an iRule with a procedure:

ltm rule proc_global_rule {
    proc proc_global { name value } {
        set uri    "[HTTP::uri]?$name=$value"
        set header [HTTP::header names]
        set method [HTTP::method]
        set version [HTTP::version]
        return "$uri-$header-$method$version"
    }
}

Additionally, the configuration contains an iRule that calls a procedure defined in the previous iRule:

ltm rule call_proc_global_rule {
    when HTTP_REQUEST {
        set call_proc [call proc_global_rule::proc_global "test_name" "test_value"]
        log local0. "proc return: $call_proc"
    }
}

In this situation, you can change the existing iRule to replace the procedure call with the code from the procedure.
For example:

ltm rule new_call_proc_global_rule {
    when HTTP_REQUEST {
        set name "test_name" 
        set value "test_value"
        set uri    "[HTTP::uri]?$name=$value"
        set header [HTTP::header names]
        set method [HTTP::method]
        set version [HTTP::version]
        log local0. "$uri-$header-$method$version"
    }
}
