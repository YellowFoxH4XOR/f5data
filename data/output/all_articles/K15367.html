Topic

You should consider using this procedure under the following condition:

  • You require setting up the gateway fail-safe feature using the TMOS Shell (tmsh).

Description

The gateway fail-safe feature allows further redundancy between a failover pair of BIG-IP systems that point to different gateways. The gateway fail-safe feature allows each BIG-IP system to monitor the upstream gateway to which they are connected. If the gateway is marked down, the BIG-IP system can fail over to its partner system to prevent further disruption to traffic.

Before configuring the gateway fail-safe feature, you should consider the following information:

  • If the redundant BIG-IP systems reference the same virtual Hot Standby Router Protocol (HSRP)/Virtual Router Redundancy Protocol (VRRP) gateway, specify the virtual router group IP address in the gateway fail-safe pool.
  • In most cases, the Failover action is the optimal gateway fail-safe action. You can use the Reboot and Restart All actions when upstream equipment requires the BIG-IP system to drop the links to clear out their Address Resolution Protocol (ARP) cache or cause a reset of their interfaces.

The gateway fail-safe feature makes use of gateway pools for monitoring the gateways. Therefore, the gateway pools must be assigned to their corresponding units that they are connected, since the pool information will be synchronized between the systems. To configure the gateway fail-safe feature, perform the following procedures:

Note: The BIG-IP only monitors the gateway pool assigned to itself and does not monitor the gateway pool assigned to peer devices. You will observe an unchecked status (a blue square in the Configuration utility) for the peer gateway pools.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have administrative access to tmsh.
  • You must have a basic understanding of the use case for the gateway fail-safe feature.

Procedures

  • Configuring gateway pools for the BIG-IP systems
  • Configuring the gateway fail-safe feature
  • Syncing and verifying the configuration

Configuring gateway pools for the BIG-IP systems

The first step of configuring the gateway fail-safe feature is to create one gateway pool for each BIG-IP system in the failover pair. Each gateway pool must consist of the upstream gateway that the system is connected to. For example, if bigip1 is connected to upstream gateway 10.10.1.1 and bigip2 is connected to upstream gateway 10.20.2.2, then you must configure two gateway pools; gateway_pool1 consists of pool member 10.10.1.1:any and gateway_pool2 consists of pool member 10.20.2.2:any. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh on the first BIG-IP system by typing the following command:

    tmsh

  2. To create the first gateway pool, use the following command syntax:

    create /ltm pool <gateway pool name> monitor <monitor name> members add { <member1 IP address:Port> <member2 IP address:Port>... }

    Important: The gateways specified in the pools should contain only the gateway associated with the unit to which they are assigned. For example, the gateway pool for unit 1 should only contain the IP address of the upstream router to which unit 1 is connected. Failure to follow this rule may result in the units changing state from active to standby, or rebooting, as the respective units cannot communicate with the partner system's gateway.

    For example, to create gateway_pool1 consisting of pool member 10.10.1.1:any using the monitor gateway_icmp, type the following command:

    create /ltm pool gateway_pool1 monitor gateway_icmp members add { 10.10.1.1:any }

  3. Create the next gateway pool using the same command syntax from the previous step.

    For example, to create gateway_pool2 consisting of pool member 10.20.2.2:any using the monitor gateway_icmp, type the following command:

    create /ltm pool gateway_pool2 monitor gateway_icmp members add { 10.20.2.2:any }

  4. Save the changes by typing the following command:

    save /sys config

Configuring the gateway fail-safe feature

The next step is to configure the newly created gateway pools with the gateway fail-safe feature. For example, the device for which the gateway pool belongs (gateway-failsafe-device), the minimum number of pool members before triggering the fail-safe action (min-up-members), the fail-safe action (min-up-members-action), and enabling/disabling the gateway fail-safe feature (min-up-members-checking). To do so, perform the following procedure:

Impact of procedure: If both BIG-IP systems are unable to reach their respective gateway through Internet Control Message Protocol (ICMP) after enabling the gateway fail-safe feature, both systems will attempt to failover to its peer and may result in a failover loop.

  1. Log in to tmsh on the first BIG-IP system by typing the following command:

    tmsh

  2. To configure the gateway pools to indicate which device each pool belongs to, use the following command syntax:

    modify /ltm pool <gateway pool name> gateway-failsafe-device <device name>

    For example, to indicate gateway_pool1 belongs to bigip1 and gateway_pool2 belongs to bigip2, type the following commands:

    modify /ltm pool gateway_pool1 gateway-failsafe-device bigip1
    modify /ltm pool gateway_pool2 gateway-failsafe-device bigip2

  3. To configure the gateway pools with the minimum number of pool members before triggering the fail-safe action, in addition to the fail-safe action, use the following command syntax:

    modify /ltm pool <gateway pool name> min-up-members <n> min-up-members-action <failover | reboot | restart-all>

    For example, to configure both gateway pools to failover when there is less than 1 pool member available, type the following commands:

    modify /ltm pool gateway_pool1 min-up-members 1 min-up-members-action failover
    modify /ltm pool gateway_pool2 min-up-members 1 min-up-members-action failover

  4. To enable the gateway fail-safe feature on the gateway pools, use the following command syntax:

    modify /ltm pool <gateway pool name> min-up-members-checking enabled

    For example, to enable the gateway fail-safe feature on both gateway_pool1 and gateway_pool2, type the following commands:

    modify /ltm pool gateway_pool1 min-up-members-checking enabled
    modify /ltm pool gateway_pool2 min-up-members-checking enabled

  5. Save the configuration changes by typing the following command:

    save /sys config

Syncing and verifying the configuration

When you have completed configuring the gateway fail-safe feature, you must sync the configuration to the peer BIG-IP system and verify the configuration. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh on the first BIG-IP system by typing the following command:

    tmsh

  2. To sync the configuration to the peer BIG-IP system, use the following command syntax:

    run /cm config-sync to-group <device_group_name>

    For example, if both the BIG-IP systems belong to the myexampledevicegrp device group, you would sync the configuration by typing the following command:

    run /cm config-sync to-group myexampledevicegrp

  3. To check that the gateway fail-safe feature is enabled by verifying the high availability (HA) table when the configuration synchronization (ConfigSync) is complete, type the following command:

    show /sys ha-status all-properties

  4. Log in to tmsh on the peer BIG-IP system by typing the following command:

    tmsh

  5. To check that the gateway fail-safe feature is enabled by verifying the HA table, type the following command:

    show /sys ha-status all-properties

    If the gateway fail-safe feature has been correctly configured on the gateway pools, you should observe the following entries from the show /sys ha-status all-properties command on the respective BIG-IP system:

    bigip1

    pool-mbr-down       gateway_pool1  failover                      no    yes      no    1       mcpd          0

    bigip2

    pool-mbr-down       gateway_pool2  failover                      no    yes      no    1       mcpd          0
