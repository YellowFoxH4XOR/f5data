K39330054: DCD status restarting when adding secondary CM node

Type
Support Solution
Published
2021-10-28
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IP Platforms
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K39330054

Description

After adding a standby BIG-IQ to a high availability (HA) configuration or while (less likely) adding a DCD, the DCD cluster no longer functions.
Under System BIG-IQ-DATA-COLLECTION > BIG-IQ DATA COLLECTION CLUSTER > STATUS   we see Restarting...

/var/log/restjavad.0.log  contains

 Failed POST to ElasticSearch: org.elasticsearch.client.ResponseException: method [POST], host [https://127.0.0.1:9200], URI [/access-acl-stats_writer/doc/_bulk], status line [HTTP/1.1 503 Service Unavailable]
Open Distro not initialized
    at org.elasticsearch.client.RestClient$1.completed(RestClient.java:552)
    at org.elasticsearch.client.RestClient$1.completed(RestClient.java:537)
    at org.apache.http.concurrent.BasicFuture.completed(BasicFuture.java:119)

Environment

  • BIG-IQ DCD Cluster version 8.0.0
  • Adding Secondary CM  to Cluster

Cause

ID1005049

 

Recommended Actions

Enable Opendistro on  added CM device by  following procedure below:
 
  1. Connect to  ssh on BIG-IQ CM device
  2. Run following command  :
    export JAVA_HOME=/usr/lib/jvm/jre-1.8.0-openjdk.x86_64 ; /bin/bash -c "/usr/share/elasticsearch/plugins/opendistro_security/tools/securityadmin.sh -h `netstat -nap | grep ':9300 ' | grep LISTEN | awk '{print $4}' |  rev | cut -c 6- | rev` --accept-red-cluster -cd /var/config/appiq/elasticsearch/utils/ -icl -nhnv -cacert /var/config/rest/elasticsearch/config/es_root-ca.pem  -cert /var/config/rest/elasticsearch/config/es_admin.pem  -key /var/config/rest/elasticsearch/config/es_admin-key.pem"

Additional Information

None.
