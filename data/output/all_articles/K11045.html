Topic

Following the installation of a hotfix, the version.build and version.edition fields in the BigDB.dat file are not updated to reflect the version and the edition written in the version file located in the root directory.

For example, the base installation of BIG-IP version 10.0.1 displays the following bigpipe version output:

Kernel:
Linux 2.4.21-10.0.1.283.0smp
Package:
BIG-IP Version 10.0.1 283.0
Final Edition

# cat /VERSION
Product: BIG-IP
Version: 10.0.1
Build: 283.0
BaseBuild: 283.0
Edition: Final
Date: Tue May 12 18:19:43 PDT 2009
Built: 090512181943
Changelist: 628513

# bigpipe db version.build
version.build = 283.0
# bigpipe db version.edition
version.edition = Final

The following section of the BigDB.dat file contains the version.build and version.edition fields:

[version.build]
display_name=version.build
value=283.0
realm=private_local
type=string

[version.edition]
display_name=version.edition
value=Final
realm=private_local
type=string

After the installation of Hotfix-BIGIP-10.0.1-378.0-HF3, BIG-IP version 10.0.1 displays the following bigpipe version output:

Kernel:
Linux 2.4.21-10.0.1.283.0smp
Package:
BIG-IP Version 10.0.1 378.0
Hotfix HF3 Edition

# cat /VERSION
Product: BIG-IP
Version: 10.0.1
Build: 378.0
BaseBuild: 283.0
Edition: Hotfix HF3
Date: Sat Nov 14 01:38:17 PST 2009
Built: 091114013817
Changelist: 660767

# bigpipe db version.build
version.build = 378.0

# bigpipe db version.edition
version.edition = Hotfix HF3

The following section of the BigDB.dat file contains the version.build and version.edition fields:

[version.build]
display_name=version.build
value=283.0
realm=private_local
type=string

[version.edition]
display_name=version.edition
value=Final
realm=private_local
type=string

These examples convey that the BigDB.dat file was not updated following the hotfix installation. However, the version file was updated and the bigpipe db commands for the version.build and version.edition fields report the correct information.

This behavior is expected. The BigDB.dat file entries with a realm set to private_local are not persisted or updated when a change occurs. Instead, the values reported by bigpipe db are the current running configuration that the mcpd process retrieves using the version2bigdb script that parses the version file.
