Description

By default DNS Express populates Authority (AA) and Additional Records (AR) sections.

The authority section contains RRs that point toward an authoritative name server; the additional records section contains RRs which relate to the query, but are not strictly answers for the question.

$ dig @192.168.1.1 host1.test.local
; <<>> DiG 9.11.9 <<>> @192.168.1.1 host1.test.local
; (1 server found)
;; global options: +cmd
;; Got answer:
;; WARNING: .local is reserved for Multicast DNS
;; You are currently testing what happens when an mDNS query is leaked to DNS
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 42825
;; flags: qr aa rd; QUERY: 1, ANSWER: 1, AUTHORITY: 1, ADDITIONAL: 2
;; WARNING: recursion requested but not available

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 4096
;; QUESTION SECTION:
;host1.test.local.               IN      A

;; ANSWER SECTION:
host1.test.local.        60      IN      A       192.168.1.3

;; AUTHORITY SECTION:
test.local.             60      IN      NS      ns1.test.local.

;; ADDITIONAL SECTION:
ns1.test.local.         60      IN      A       192.168.1.4

;; Query time: 3 msec
;; SERVER: 192.168.1.1#53(192.168.1.1)
;; WHEN: Mon Sep 21 10:11:23 UTC 2020
;; MSG SIZE  rcvd: 94


The Authority section and Additional section records allow the resolver to speed up processing by eliminating the need for a separate address lookups. 
However, adding these records to responses is not mandatory and requires additional database lookups, causing extra latency.

Environment

  • DNS Express
  • BIG-IP version 11.6.0 or higher
  • Authority (AA) and Additional (AR) records

Cause

None.  The behavior is expected.

Recommended Actions

To improve the performance, you can reduce response volumes by configuring DNS Express to only add the Authority section (AA) and Additional section (AR) records when such records are required by the DNS protocol (for example, when returning delegations or negative responses).
 
This provides the best server performance but may result in more client queries.

Enable minimal responses for DNS Express using the dnsexpress.minimalresponse db key.  To do so perform the following:
  1. Log in to the BIG-IP command line
  2. Enable the dnsexpress.minimalresponse db value:
    tmsh modify sys db dnsexpress.minimalresponse value true
  3. Save the configuration:
    tmsh save sys config



Example response after the change:
