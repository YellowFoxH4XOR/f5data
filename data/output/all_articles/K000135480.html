K000135480: Disk partition /shared/vmdisks (slot x) has only 0%

Type
Support Solution
Published
2023-07-13
Updated
2023-07-13
Source
https://my.f5.com/manage/s/article/K000135480

Description

vCMP guests experiencing disk space issues. From logs of vCMP Host you can see logs similar to the following samples (in the /var/log/ltm):

err diskmonitor[18789]: 011d0004:3: Disk partition /shared/vmdisks (slot 2) has only 0% <--
err diskmonitor[13892]: 011d0004:3: Disk partition /shared/vmdisks (slot 1) has only 13% free


Output from "df-h" shows:

Filesystem Size Used Avail Use% Mounted on
/dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks 230G 219G 0 100% /shared/vmdisks
 

Environment

  • vCMP
  • vmdisks
 

Cause

When deployed, a guest is assigned 100Gb or 150Gb of space (depending on platform) in the host virtual disk. However, it should be taken into account that the virtual disk is created as a sparse file (which means that the file size is not the same that the disk space it occupies, this is because the null bytes are not saved to the disk therefore, the virtual disk takes much less than 150 G). It is important to understand that a sparse file works as a high watermark.

Over time, the guest's virtual disk size can grow. Any time the guest writes new data to the disk, it converts unallocated space into allocated space.

When data is deleted from the guest, there is not any automatic procedure to recover sparseness.

 

Recommended Actions

There are two possible methods/options to address this scenario.

  • Option 1: Remove unwanted/unused guests and their virtual disks to release the space.
  • Option 2: Create a sparse version of the original virtual disk of a guest or multiple guests.
Example of procedure for option 2:

1.- Verify the current virtual disks with command:  # tmsh show vcmp virtual-disk

      For the purpose of this example, we'll do the process on a guest labeled as GUEST2:


# tmsh show vcmp virtual-disk
------------------------------------------------------------------------------------------
Vcmp::VirtualDisk
Name                Slot ID  Operating System  Status  Disk Use (bytes)  Disk Size (bytes)
------------------------------------------------------------------------------------------
GUEST2.img                2              tmos  in-use              5.1G             150.0G
GUEST2.img                1              tmos  in-use              5.3G             150.0G
Guest1.img                2              tmos  in-use              4.8G             150.0G
Guest1.img                1              tmos  in-use              5.2G             150.0G


2.- Navigate to the directory of the vmdisks with: 
       # cd /shared/vmdisks/

3.- Create a sparse copy of the vdisk image of the guest (this should be lower in size)
      # cp --sparse=always GUEST2.img Sparse_GUEST_2.img

4.- Display the virtual disk and you should see the copy created above:

# tmsh show vcmp virtual-disk
-------------------------------------------------------------------------------------------
Vcmp::VirtualDisk
Name                Slot ID  Operating System   Status  Disk Use (bytes)  Disk Size (bytes)
-------------------------------------------------------------------------------------------
Sparse_GUEST_2.img                    1                         unknown  unknown                                       4.2G                               150.0G
GUEST2.img                2              tmos   in-use              5.1G             150.0G
GUEST2.img                1              tmos   in-use              5.3G             150.0G
Guest1.img                2              tmos   in-use              4.9G             150.0G
Guest1.img                1              tmos   in-use              5.2G             150.0G

5.- Now, you should pass the Guest to Configured state with command: 
       # tmsh modify vcmp guest GUEST2 state configured

6.- Once the guest is in ‘configured’ state, you can assign to it the new .img to the guest:
      # tmsh modify vcmp guest GUEST2 virtual-disk Sparse_GUEST_2.img

7.- Then you can pass the guest to Deployed state again:
   # tmsh modify vcmp guest GUEST2 state deployed

8.- Once the guest is fully deployed and we can confirm it's operational, we are ready to delete the original virtual disk "GUEST2.img " and recover disk space in the host. (this example shows the deleting command for a guest that has been deployed on 2 Slots)
     # tmsh delete vcmp virtual-disk GUEST2.img/1
  # tmsh delete vcmp virtual-disk GUEST2.img/2

9.- After the procedure, you should see an output similar to this:

# show vcmp virtual-disk
------------------------------------------------------------------------------------------
Vcmp::VirtualDisk

------------------------------------------------------------------------------------------
