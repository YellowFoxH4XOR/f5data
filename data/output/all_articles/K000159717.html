K000159717: BIG-IP SSLO Guided Configuration UI fails to load after upgrading to version 17.1.3 due to RPM package mismatch

Source

Description

After upgrading BIG-IP to ISO version 17.1.3, the SSLO Guided Configuration UI page fails to load and displays the following error message:

  • "The requested URL was not found on this server."

This issue occurs due to an RPM package mismatch for the SSLO module, where remnants of a previous SSLO RPM from an earlier ISO version conflict with the bundled SSLO RPM version 11.2.3 included in ISO 17.1.3.

Environment

  • BIG-IP SSLO module, version 17.1.3
  • SSLO Guided Configuration
  • RPM package mismatch between old SSLO RPM and bundled SSLO RPM version 11.2.3
  • Recent action: Upgrade to ISO version 17.1.3

Cause

ID 2137721

The root cause is an RPM package mismatch for SSLO after upgrading to ISO version 17.1.3. The upgrade includes SSLO RPM version 11.2.3 as part of the bundle, but remnants of a previous RPM from an earlier ISO remain on the system, preventing the correct bundled RPM from activating and causing the SSLO UI to fail to load.

Recommended Actions

To workaround the issue: 

  1. After upgrading to ISO version 17.1.3, navigate to iApps  ››  Application Services : Applications LX and delete the old f5-ssl-orchestrator-dg-data.
  2. Navigate to iApps  ››  Package Management LX and remove the outdated f5-iappslx-ssl-orchestrator RPM package from the system. 
  3. Once the old RPM is deleted, click on the SSL Orchestrator  ›› Configuration. This action will trigger the activation of the RPM bundled with ISO 17.1.3 
  4. Verify that the SSLO Guided Configuration UI is accessible

Note: This workaround only affects the control plane (SSLO Guided Configuration UI) and does not impact service traffic or data plane operations.

Additional Information

  • This issue only affects access to the SSLO UI, which is the control plane
  • Deleting f5-ssl-orchestrator-dg-data and f5-iappslx-ssl-orchestrator will have no impact on service traffic
  • The workaround does not affect data plane operations or existing SSLO service configurations
