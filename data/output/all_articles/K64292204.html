Security Advisory Description

sshd in OpenSSH before 7.4, when privilege separation is not used, creates forwarded Unix-domain sockets as root, which might allow local users to gain privileges via unspecified vectors, related to serverloop.c. (CVE-2016-10010)

Impact

In the default configuration, there is no impact. However, if the administrator disables privilege separation in the system sshd_config file, the system can be exposed to this vulnerability.

Mitigation

To mitigate this vulnerability for BIG-IP products, F5 recommends that you re-enable privilege separate, if you have disabled it. To do so, perform the following procedure:

Impact of action: Improper modifications to the SSH configuration can prevent SSH login. You should perform changes from the serial console.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To determine if you have privilege separation disabled, type the following command:

    list /sys sshd

    If you observe the following command output, then privilege separation is disabled, and you should proceed to step 3.

    sys sshd {
        include "UsePrivilegeSeparation no"
    }

    If there is no command output, or you do not see the UsePrivilegeSeparation no include statement in the output, then privilege separation is enabled, and you do not need to proceed.

    Note: For more information regarding the UsePrivilegeSeparation option, refer to the manual page for sshd_config, by typing the following command from the Advanced Shell (bash) prompt (not tmsh):

    man sshd_config

  3. To re-enable privilege separation, remove the custom include statement by typing the following command:

    edit /sys sshd

    If there are multiple include statements, locate the UsePrivilegeSeparation no line, and remove just that statement.

    If UsePrivilegeSeparation no is the only include statement, replace that statement with the word none.

    For example:

    modify sshd {
        include none
    }

  4. Save your changes for the sshd configuration, and exit the vi editor.
  5. To save the configuration, type the following command:

    save /sys config

  6. To exit tmsh, type q and press Enter.

    Note: You do not need to restart the sshd service; the new changes are active once you save the configuration.
