Topic

You should consider using these procedures under the following conditions:

  • You want to capture and analyze SSL handshake and decrypted application data on the client side.
  • You use a browser that is based on the Chromium project, such as Google Chrome, Opera, or Microsoft Edge.
  • You want to analyze decrypted application data quickly without having to use a private key to decrypt a TCP packet capture.

Description

There are different methods to capture and analyze SSL application data. For example, you can capture traffic using the tcpdump command and then use software such as Wireshark to analyze data when troubleshooting. NetLog is an event logging mechanism for Chrome’s network stack to help debug problems and analyze performance. This feature is available in browsers based on the Chromium project, such as Google Chrome, Opera, and Microsoft Edge.

Important: This feature is provided by the Chromium project and is not supported by F5 Support.

This method is useful if:

  • Due to security reasons, you can only reproduce or view the SSL application data of one user.
  • You can’t access, or you don’t want to run commands on, the BIG-IP system.
  • You want to view application data on the browser easily and quickly without having to perform decryption with an SSL key or pre-master secret.
  • You want to troubleshoot issues with HTTP/2 or HTTP/3 (QUIC) frames.

For more information about NetLog, refer to NetLog: Chrome’s network logging system and How to capture a NetLog dump.

Note: These links take you to a resource outside of AskF5, and it is possible that the documents may be removed without our knowledge.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You are using a browser that is based on the Chromium project (such as Google Chrome, Microsoft Edge, or Opera) on the client system to access the application.

Procedures

To view and analyze SSL application data, you must first capture the SSL traffic while the issue is happening. After traffic is captured, you can use the NetLog viewer to analyze the data. To do so, perform the following procedures:

  • Create a NetLog dump
  • Import the NetLog dump
  • Analyze the NetLog dump

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Create a NetLog dump

  1. Open your browser and enter one of the following options in the address bar as appropriate for your browser type:
    • chrome://net-export
    • edge://net-export
    • opera://net-export
  2. Select the appropriate options depending on the verbosity of the dump you prefer.
    Note: You should select the Include raw bytes option when troubleshooting but remember that private information such as private cookies and credentials will be captured and visible in plaintext.
  3. When ready to reproduce the issue, select Start Logging to Disk.
  4. Enter an appropriate file name for your log file and select Save.
  5. Reproduce the issue by opening a new tab and accessing your BIG-IP virtual server.
  6. After you have reproduced the issue, return to the NetLog dump tab, and then select Stop Logging.
  7. Note the location of the NetLog dump file by selecting Show File.

Import the NetLog dump

  1. Open a new browser tab and enter the following text in the address bar:

    netlog-viewer.appspot.com/#import

  2. Select Choose File and then select the NetLog dump file you created in the previous procedure.
  3. Select Open.

Analyze the NetLog dump

  1. To start, use the options in the left menu. For example, you can select Events, which contains the highest volume of details for troubleshooting.
  2. Use the text field to filter new events. For example, enter the URL of the BIG-IP virtual server, similar to https://example.com.
  3. Analyze the SOCKET and URL_REQUEST events:
    • For SSL handshakes, raw data bytes (including credentials), and other details, review SOCKET events.
    • For HTTP content, review URL_REQUEST events
  4. To search keywords in the captured data, perform the following steps:
    1. Select all events. To do so, select the check box in the top row of the table.
    2. Use the search or Ctrl+F function of the browser to search the webpage contents.
  5. Explore other options in the left menu:
    • For DNS requests, select DNS.
    • For HTTP/2 content, select HTTP/2.
    • For HTTP/3 over QUIC content, select QUIC_SESSION events to view SSL handshake details.
