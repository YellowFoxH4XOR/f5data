Known Issue

This is the result of a known issue. The syscall daemon manages system call functions for the BIG-IP system. An issue was discovered with the syscalld process, which may result in the process leaking memory.

F5 Product Development tracked this issue as CR128759 and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WAN Optimization Release Notes.

This issue was fixed in Hotfix-BIGIP-10.0.1-378.0-HF3 issued for BIG-IP 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes on systems with a logical volume management (LVM) disk-formatting scheme, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about installing version 10.x hotfixes on systems with a partitioned disk-formatting scheme, refer to K9819: Managing F5 product hotfixes for BIG-IP version 10.0.x systems using the partitions disk formatting scheme.

Workaround

You can work around this issue by determining how much memory the syscalld process is utilizing, and restarting the process when it consumes an excessive amount of memory. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Enter the following command and examine the VSZ column:

    ps -auxwf

    For example, the following command output displays that syscalld is utilizing 111MB of memory:

    Note: Under normal conditions, the syscalld process utilizes less than 20 MB of memory.

    USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND

    root 2009 0.0 3.3 111168 16224 ? S Mar08 896:25 | \_ /usr/bin/syscalld
  3. If syscalld is utilizing an excessive amount of memory, enter the following command to restart the process:

    bigstart restart syscalld
