K50443441: No connectivity from any interface after upgrading to 15.1.5.1

Description
GTM VE on Vmware has no connectivity from any interface after upgrading to 15.1.5.1

   1. An upgrade from v15.1.2 to v15.1.5, works, you have network connectivity.
   2. An upgrade from v15.1.5 (base) to v15.1.5.1 you have NO network connectivity.
   3. There is no ssh/GUI access on the new code. There is full access after a rollback to earlier TMOS other than v15.1.5.1.

Environment

  • DNS VE
  • Vmware
  • Upgrading prior TMOS version from v15.1.0

Cause
K12149: Adding TMM interfaces to the BIG-IP or BIG-IQ VE running on VMware ESXi
 

Recommended Actions

Remap /etc/ethmap to line up to what VMware is reflecting. For information, refer to the Checking interface mapping between the BIG-IP system and the hypervisor section of K34607084: Troubleshooting BIG-IP VE performance issues
  • Checking interface mapping between the BIG-IP system and the hypervisor

    If you are experiencing issues after adding or removing a hypervisor interface, you may want to check the interface mappings between the BIG-IP system and the hypervisor. For example, if you attempt to add an interface using the hypervisor software, and the change is not detected by the BIG-IP system, you can verify the interface mappings by comparing the media access control (MAC) addresses of the interfaces displayed by the BIG-IP system to those displayed by the hypervisor client. If the interface mappings are incorrect, the system may fail to properly process network traffic. To verify the interface mappings between the BIG-IP system and the hypervisor, perform the procedure for your BIG-IP software version:

    Checking interface mapping (BIG-IP 11.5.0 and later)

    1. Log in to the BIG-IP command line.
    2. Review the interface mapping by typing the following command:
    cat /etc/ethmap

    For example, the following output shows the interface mapping for a BIG-IP system with four virtual interfaces:

    eth0 00_50_56_92_79_c4
    eth1 00_50_56_92_02_fe
    eth2 00_50_56_92_6c_70
    eth3 00_50_56_92_2a_20

    Note: Additionally, you can use the tmsh show /net interface all-properties command to determine the interface mapping .

    3. Log in to the hypervisor client software, and check the interface settings for the BIG-IP VE system.
    For example, for VMware vSphere Client, right-click the BIG-IP VE virtual machine name and then click Edit Settings. Under the Hardware tab, click the listed interfaces and take note of the MAC address.

    4. If you recently added an interface using the hypervisor client, and the interface mappings do not match, you can map the new network interface and MAC address into the BIG-IP system database by typing the following command:
    f5-swap-eth -w
     
Alternative POA:
To pre-empt your /etc/ethmap prior to booting into the upgraded slot. Note mileage may vary but is essential if you want to have this fixed before you boot into the next partition.
  1. Install new volume in new slot
  2. Mount new volume root disk.  It will be something like if in HD1.2 "/dev/mapper/vg--db--vda-set.2.root". 
    The number after the . dictates the volume group mount command would be "mount /dev/mapper/vg--db--vda-set.2.root /root/2.root" /root/2.root is a directory that was created
  3. Using diff check ethmap files.  diff /etc/ethmap /root/2.root/etc/ethmap
  4. If the two files are different, compare and correct the file in /root/2.root/etc/ethmap.  Please make a backup of the file
  5. reboot into upgraded volume and the device should boot with the network correctly mapped
