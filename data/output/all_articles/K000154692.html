Description

When configuring Brute Force Protection, administrators may use wildcard login URL definitions (for example, /*/login) to match multiple login endpoints. In some cases, brute force detection may not trigger for certain login pages if an explicit URL definition exists in the policy.


Environment

  • BIG-IP ASM
  • Brute Force Protection enabled
  • Wildcard login URL configured (e.g., /*/login)
  • Explicit URL objects also defined in the policy

Cause

In ASM, explicit URL objects always take precedence over wildcard URL objects.


If a login page is defined as wildcard (for example /*/login) but in URL definition there are two objects like this:


  • A wildcard URL (for example, /*/login)
  • An explicit URL object (for example, /example/login)


The explicit URL will take priority. If the explicit URL object is not configured as a login page, the Brute Force Protection engine will not bind to it, and brute force detection will not be triggered for that endpoint.


Recommended Actions

To ensure brute force protection applies correctly:


  • Review the Allowed URLs and Login Pages configuration in the ASM policy.
  • If an explicit URL should act as a login page, configure it as a login URL.
  • If the explicit URL is unnecessary, remove it from the Allowed URLs list so that the wildcard login URL can take effect.
  • Re-test brute force detection on the affected endpoint to confirm expected behavior.


Additional Information

In ASM, explicit URL definitions override wildcard definitions. If an explicit URL is defined without login page configuration, it can prevent security features (such as Brute Force Protection) from functioning as expected.
