Description

Users may encounter the message: "The VPN connection has failed because it attempted to connect to an insecure network. Please switch to a secure network," even after correctly following the instructions to populate the vpn.serveriplist DB variable according to K000138683.

Additionally, in logterminal.txt (which is a part of the Client Troubleshooting Utility report generated per Overview of the Client Troubleshooting Utility for Windows (f5.com) or located under %TEMP% as explained in Gathering F5 VPN client logs) we can see logs similar to:

YYYY-MM-DD,HH:MM:SS:mmm, 10868,10876,HOST, 48,,,, HostCtrlStatusCallback:CONNECTING_TO_SERVER - [<IPv6/IPv4>].

NOTE: This IP address <IPv6/IPv4> is client DNS server resolved for the Access Virtual server used to connect to the VPN.
YYYY-MM-DD,HH:MM:SS:mmm, 10868,10876,HOST, 48,,,, HostCtrlStatusCallback:CONNECTED_TO_SERVER - [<IPv6/IPv4>]. Abort operation.
...
YYYY-MM-DD,HH:MM:SS:mmm, 10848,11448,HOST, 1, \m_VerifyPreConfigInfo.cpp, 545, verifyPreConfigLocalAndServerIpInformation, ALERT: Provided Resolved IP is NOT a Valid APM Server IP, seems the VS IP is spoofed
...
YYYY-MM-DD,HH:MM:SS:mmm, 10848,11448,APPCTRL, 1, , 53, CAppTunnelEx::OpenByParam, VPN connection is failed due to possible server IP attack, please change your network

Important: This article only applies to environments in which actions from article K000138683: Users cannot connect to BIG-IP APM virtual servers with BIG-IP Edge Client 7246 (f5.com) were already followed, yet the issue persists. If you haven't yet applied that fix, please do that first, if faced with the Insecure Network prompt.

Environment

  • BIG-IP Edge Client 7246 or 7247
  • DB Variable correctly set

Cause

The issue is most likely due to the vpn.serveriplist DB variable not including the IPv6 address of the VPN server or missing a few IPv4 address (especially in scenarios where only a few users have this problem, as they may be going through a different route), in cases where the VPN FQDN translates to multiple IPv4 and/or multiple IPv6 address. The vpn.serveriplist DB variable must include all of the IPv4 and IPv6 addresses returned by nslookup on VPN FQDN on all devices to avoid the connection being flagged as insecure.

Recommended Actions

1. Determine the IPv6 Address/es:

On the client device, use the nslookup command to determine the IPv6 address/es of the FQDN used to connect to the VPN. This will show both IPv4 and IPv6 addresses if both are in use.

nslookup <vpn-fqdn>

Note that you may have to perform this command on more than 1 client device if there are differences in network environments/paths used to reach the VPN Virtual Server between client devices.

2. Add IPv6 Address/es to vpn.serveriplist:

In the same way as explained in K000138683: Users cannot connect to BIG-IP APM virtual servers "The VPN connection has failed because it attempted to connect to an insecure network" with BIG-IP Edge Client 7246 and above, also include the missing IPv6/IPv4 address/es.

Once you find all possible IP addresses resolved by the DNS server, remember to separate them by space when modifying the DB key. For example:

tmsh modify sys db vpn.serveriplist value "<IPv4> <IPV4> <IPv6> <IPv6> ..."

tmsh save sys config

To verify that these have been added correctly, you may use the following command:

tmsh list sys db vpn.serveriplist

Additional Information

Other possible causes, especially in situations where only some clients are getting the insecure prompt include:

Bug ID 1580505: There is a known issue where the maximum number of IPs that can be configured is approximately 18. This issue was fixed since APM client package version 7248.

Bug ID 1586657: Using the vpn.serveriplist DB variable when the BIG-IP APM VPN enabled virtual server is using an IPv6 address may fail with a network is vulnerable error. This issue was fixed since version 7248.

Bug ID 903501: VPN Tunnel establishment fails with some IPv6 address. An EHF (Engineering Hotfix) can be requested for this BugID (BigIP ISO, not an APM client EHF for this one, that includes fixes for both Bug ID 903501 and article K000138683). You can also perform the workaround mentioned in Bug ID 903501 (f5.com).

K000149990: VPN Connectivity issues caused by DNS64 mechanisms on DNS server in BIG-IP APM - Insecure prompts can also appear in environments with DNS64/NAT64 in use, which is oftern the case with mobile operators.
