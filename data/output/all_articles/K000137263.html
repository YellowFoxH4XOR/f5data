K000137263: Active Directory user in BIG IQ fails to log in with: "User has no roles or group associations"

  • BIG-IQ Centralized Management: 8.X.X, 8.3.X, 8.3.0, 8.2.X, 8.2.0, 8.1.X, 8.1.0, 8.0.X, 8.0.0
Source

Description

Active Directory user fails to log in with error message:
"User has no roles or group associations"
In case it tested under the 'Auth Provider' page of the BIG-IQ, the test is successful.
This also works if the role is added directly in the BIG-IQ.
Using the default filters 'Group Search Filter' & 'Group Membership User Attribute' does not work.

Environment

  • BIG-IQ 
  • Active Directory

Cause

Working as expected. The user must belong to any of the User Groups configured in the BIG-IQ before a role can be assigned during login, therefore the BIG-IQ must know the "memberOf" that is being used in the Active Directory server.

Recommended Actions

The BIG-IQ administrator can ask the Active Directory administrator to get the "memberOf" attributes of the user he would like to log in.
Alternatively the BIG-IQ administrator can use the following command on BIG-IQ to query the memberOf attribute:

# ldapsearch -x -H ldap://<AD server address> -D "CN=<my_Common_Name>,CN=<my_Common_Name_n>,DC=<my_Domain_Component>,DC=<my_Domain_Component_n>" -W -b "DC=<my_Domain_Component>,DC=<my_Domain_Component_n>" "(sAMAccountName=<my_user>)" memberOf -ZZ

Additional Information

Legend:

  •  -x: This option specifies to use simple authentication instead of SASL (Simple Authentication and Security Layer).
  •  -H ldap://<AD server address>: This part specifies the LDAP server's address. You should replace <AD server address> with the actual address of your Active Directory server.
  • -D "CN=<my_Common_Name>,CN=<my_Common_Name_n>,DC=<my_Domain_Component>,DC=<my_Domain_Component_n>": This option is used for the bind DN (Distinguished Name), which is essentially the username for authenticating the search. 
  • -W: This option prompts for the password of the bind DN.
  • -b "DC=<my_Domain_Component>,DC=<my_Domain_Component_n>": This sets the search base, which is the starting point within the directory from where the search will begin. In short, it's specifying the domain.
  • "(sAMAccountName=myuser)": This is the search filter. It specifies that you're looking for an entry where the sAMAccountName (Security Accounts Manager Account Name) matches `myuser`. 
  • memberOf: This specifies the attribute you want to retrieve, which in this case is `memberOf`. This attribute lists all groups that the user is a member of.
  • -ZZ: This option enables StartTLS, a way to take an existing insecure LDAP connection and upgrade it to a secure connection using SSL/TLS.
