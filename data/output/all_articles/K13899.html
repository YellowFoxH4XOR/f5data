Known Issue

Disabling BIG-IP GTM synchronization may cause the BIG-IP GTM system to delete virtual servers from the configuration on one of the synchronization group members.

This issue occurs when the following conditions are met:

  • Two or more BIG-IP GTM systems are configured in a synchronization group
  • The BIG-IP GTM configuration contains BIG-IP server objects and auto-discovered virtual servers
  • BIG-IP GTM synchronization is subsequently disabled for the synchronization group members

The following sequence illustrates how this issue can occur:

  • BIG-IP GTM devices GTM-1 and GTM-2 are configured in a synchronization group
  • The BIG-IP GTM configuration contains server object LTM-3, which has Virtual Server Discovery set to Enabled
  • The GTM-1 device is responsible for auto-discovering BIG-IP virtual server objects

    Note: The synchronization group member with the lower numbered self IP address is responsible for auto-discovery. For example, the 10.20.20.2 self IP address is lower than the 192.168.1.1 self IP address.
  • Synchronization is subsequently set to disabled on the GTM-2 system
  • Auto-discovered virtual servers associated with the LTM-3 server object are missing from the GTM-2 configuration

Impact

Auto-discovered virtual server objects may not be available for load balancing.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Auto-discovered virtual server objects may not be available for load balancing
  • The Configuration utility Server List page shows no configured virtual servers for the affected server object

Workaround

You can work around this issue by restoring the missing virtual server configuration. To do so, perform the Running the gtm_add script on the affected BIG-IP GTM system procedure.

You can prevent this issue by changing the Virtual Server Discovery setting to Enabled (No Delete). To do so, perform the Changing the Virtual Server Discovery setting to Enabled (No Delete) procedure.

Running the gtm_add script on the affected BIG-IP GTM system

Impact of workaround: The gtm_add script removes the BIG-IP GTM configuration on the local device and replaces it with the BIG-IP GTM configuration from the remote BIG-IP GTM device.

Note: If synchronization is enabled on the remote BIG-IP GTM system, running the gtm_add script will enable synchronization on the local device.

  1. Log in to the command line on the affected BIG-IP GTM system.
  2. To restore the configuration from the remote GTM device, use the following command syntax:

    gtm_add <remote_gtm_device>

Changing the Virtual Server Discovery setting to Enabled (No Delete)

Impact of workaround: The BIG-IP GTM will no longer delete previously discovered virtual servers that have been removed from the remote BIG-IP LTM device, though the virtual server will be available for selection in the BIG-IP GTM virtual server list.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Servers.
  3. Select the name of your server.
  4. Click Virtual Servers.
  5. From the Virtual Server Discovery menu, select Enabled (No Delete).
  6. Click Update.
