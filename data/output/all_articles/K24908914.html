Environment

  • BIG-IP LTM
  • Using remote syslog feature

Cause

Remote syslog causing to generate many multiple log messages with progressive <level> messages like "notice", "alert", "err".

Recommended Actions

Device should stop logging invalid truncated messages by removing syslog config and restore it back.
Procedure may depend on your syslog configuration.
Use the following steps:

  1. Connect to affected device using SSH.
  2. Collect your current syslog server configuration using following command: tmsh list /sys syslog all-properties

    Important: This syslog output and include section contains example configuration. Setup within your environment can be different and you should stick up to yours syslog config.

    sys syslog {
        auth-priv-from notice
    ...
        description none
        include "destination d_remote_loghost {udp(192.0.2.2 port(514));};log {source (s_syslog_pipe);filter (f_remote_loghost);destination (d_remote_loghost);};"
    ...
        user-log-to emerg
    }
  3. Use command to remove syslog config:
    tmsh modify /sys syslog include none
  4. Using below example template command configure back your initial syslog server configuration:
    tmsh modify sys syslog include "destination d_remote_loghost {udp(\"192.0.2.2\" port(514));};log {source (s_syslog_pipe);filter (f_remote_loghost);destination (d_remote_loghost);};"
  5. Save configuration:
    tmsh save sys config

Note: Due to an issue in specific BIG-IP versions, the BIG-IP system may send a truncated host name to the remote syslog server. For more information, refer to Known Issue article K16133: Using a localhost address as a remote syslog destination can cause recursive log messages

Additional Information

If device wouldn't stop logging above messages after execution of recommended actions, please open Service Order by contacting F5 Networks Support.
