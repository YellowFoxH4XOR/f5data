Topic

Wildcard entities can be used in the BIG-IP ASM security policy to represent object types, web objects, and parameters. Wildcard entities contain one or more shell-style wildcard characters, which can be used to build a general security policy without in-depth knowledge of the web application. You can then gradually refine and specify the security policy.

The following table describes the wildcard entities that you can use in the security policy:

Wildcard PatternDescription
*Matches all characters
?Matches any single character
[seq]Matches any character in the sequence
[!seq]Matches any character not specified in the sequence
[a-e]Matches exactly one character in the range
[!a-e]Matches any character not in the range

Wildcard rules

You can reference the following wildcard rules when using wildcard entities in the security policy:

  • Wildcard pattern matching is case sensitive.

    For example, [abc] and [ABC] are distinct patterns.

  • The wildcard character ( * ) matches any sequence of characters.

    For example, the *.asp pattern matches any object that contains the .asp extension.

  • The wildcard character ( * ) may appear anywhere in the string.

    For example, filename.* and *.extension are both valid.

  • The pipe character ( | ) can be used to represent or.

    For example, [(A|a)] represents either A or a.

  • Patterns such as [a-z] defines one character in the range.

    For example, the [a-z] pattern does not match the string abc, but rather any one character between characters a and z.

Note: In BIG-IP ASM 9.4.2 - 9.4.4, object wildcard expressions require an eight character limitation. For more information, refer to K8625: The BIG-IP ASM limits object type wildcard expressions to eight characters.
