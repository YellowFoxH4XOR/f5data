Known Issue

A network virtual server with ARP enabled reverts to ARP disabled.

This issue occurs when all of the following conditions are met:

  • The virtual server is configured with a network destination address.
  • The BIG-IP configuration is reloaded using the tmsh command.

The default setting for the virtual server is ARP enabled. If ARP is disabled on the virtual server, the BIG-IP system will not answer ARP requests from upstream devices, and will not send gratuitous ARP (GARP) packets during a high availability (HA) failover event.

Impact

Connections to the virtual server may be interrupted.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The virtual server does not respond to ARP requests.
  • The BIG-IP system does not send GARP packets for the affected virtual server during an HA failover event.
  • The virtual server ARP setting reverts to disabled after you reload the configuration using the tmsh command.

Workaround

To work around this issue, you can re-enable ARP for the affected virtual server using the Configuration utility.

Impact of workaround: None.
