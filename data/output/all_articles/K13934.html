Known Issue

When Border Gateway Protocol (BGP) is configured on a multi-blade VIPRION chassis, the BGP process on secondary blades may consume over 90 percent of CPU time.

This issue occurs when the following conditions are met:

  • You have a VIPRION chassis with two or more blades installed.
  • BGP is configured with a non-default scan-time.

Impact

There is potential for performance degradation if the VIPRION system normally uses many CPU cycles.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H400925 on the Diagnostics > Identified > Medium page.
  • There is high CPU activity on secondary blades, with the bgpd process consuming more than 90 percent, as shown in the following example output from the top command on a secondary blade:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    2215 root 25 0 9264 3036 2148 R 92.4 0.0 5:33.47 bgpd

Workaround

To work around this issue, you can set the bgp scan-time setting to the default value. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line on the primary blade.
  2. Start the imish shell by typing the following command:

    imish

  3. Enter privileged mode by typing the following command:

    enable

  4. Enter terminal configuration mode by typing the following command:

    configure terminal

  5. Enter router mode by using the following command syntax:

    router bgp <ASN>

    Replace <ASN> with the ASN (Autonomous System Number) of your system.

  6. Set the bgp scan-time setting back to the default value by typing the following command:

    no bgp scan-time

  7. Exit router mode and save the running configuration by typing the following commands:

    end

    copy running-config startup-config

  8. Exit the imish shell by typing the following command:

    exit

  9. Check the bgpd process CPU usage by running the following command on the secondary blades:

    top -n 1

  10. If the bgpd processes is still taking upwards of 90 percent CPU, restart the tmrouted process by running the following command from the primary blade:

    bigstart restart tmrouted
