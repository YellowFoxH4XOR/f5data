K32110264: After rebooting BIG-IP in Azure environment, no GUI or TMSH CLI access

Description

You may lose connectivity to the BIG-IP GUI and TMSH CLI when there are manual management route objects which conflict with DHCP assigned routes in Azure Cloud.

Environment

BIG-IP Virtual machines running in Azure environment.

Cause

Conflict between manually added defined management route objects and DHCP assigned default routes in Azure Cloud.

Recommended Actions

  1. Remove ALL management-routes using “delete sys management-route <name>”
  2. Release dhclient leases using “dhclient -r eth0”
  3. Renew dhclient leases using “dhclient eth0”
  4. Check the configuration with “ifconfig eth0”
  5. Clean the cloud-init log with “cloud-init clean –logs”
  6. Create the forcereload file with “touch /service/mcpd/forceload”
  7. Reboot the device with “reboot”
    Note: If the BIG-IP continues to display manually created default management-route, you can perform the following additional steps
  8. Delete the management-ip using “delete management-ip <IP_address/Net_mask> 
  9. Repeat Steps 2 through 7 again
  10. You can view your management ip address and routes using the following commands:
    list sys management-ip
    list sys management-route
  11. You may require to repeat same steps again if your management route still does not appear
  12. Make sure your management route appears through DHCP lease
  13. Save your configuration using:
    save /sys config
  14. Reboot the BIG-IP system
