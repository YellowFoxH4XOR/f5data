Description

This article will outline the steps needed to review the session variables from a Per-Request Policy using the sessiondump utility.

Environment

  • BIG-IP APM
  • Per-Request Policies
  • Session Variables

Cause

Sub-session variables are not visible in the GUI.

Recommended Actions

Note: These steps are only applicable if there is a subroutine that creates a subsession. 

  1. First you will need to get the SessionID of the Per-Session:
    # sessiondump --list

    [root@apm4:Active:Standalone] config # sessiondump --list
    ebd588b3 10 SessionKey
     
  2. Next you will need to find the associated subsid:
    # sessiondump --subsid='<SessionID>'

    [root@apm4:Active:Standalone] config # sessiondump --subsid=ebd588b3
    ebd588b3./Common/saml_1/YXhzMnN1YnNpZA== 0
     
  3. Use this to review your Per-Request session variables with the subkeys command:
    # sessiondump --subkeys '<subsid>'

    [root@apm4:Active:Standalone] config # sessiondump --subkeys 'ebd588b3./Common/saml_1/YXhzMnN1YnNpZA=='

    From the example below we can see the SAML Attributes from the SAMLResponse from the IdP:

    ebd588b3./Common/saml_1/YXhzMnN1YnNpZA==.subsession.saml.last.audience 27 https://sp.apmsupport.local ebd588b3./Common/saml_1/YXhzMnN1YnNpZA==.subsession.saml.last.attr.name.blahblah 9 123456789 ebd588b3./Common/saml_1/YXhzMnN1YnNpZA==.subsession.saml.last.attr.name.Password 12 YWJjMTIzIUA= ebd588b3./Common/saml_1/YXhzMnN1YnNpZA==.subsession.saml.last.attr.name.Name 11 b.smith ebd588b3./Common/saml_1/YXhzMnN1YnNpZA==.subsession.saml.last.attr.name.Domain 16 APMSUPPORT.LOCAL
