Known Issue

A sweeper triggered by a policy change may erroneously reap a flow that had a match in a global (or route domain) rule with the accept decisively action.

This issue occurs when all of the following conditions are met:

  • The BIG-IP AFM system is configured with the default firewall action set to drop or reject.
  • An incoming connection matches a rule in the global or route domain context that is configured with the accept decisively action.
  • The established connection does not match the virtual server or self IP firewall rules.
  • You apply a configuration change to the firewall policy.
When you apply a firewall policy change, the system will trigger the sweeper to re-evaluate all the existing connections against the new firewall configuration.

Impact

The system may drop established connections after the firewall policy configuration change.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The incoming connection that matches a rule and the connection was established correctly before the firewall policy configuration change.
  • After the firewall policy configuration change, the sweeper reaps the affected established connection.
  • This behavior is incorrect; the established connection has a matched rule that should be accepted in the firewall configuration.
