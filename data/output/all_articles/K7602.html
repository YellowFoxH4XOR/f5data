Topic

Core files provide a snapshot of memory behavior at the time an issue occurs. Because the core file is a snapshot of the entire memory, the file can be large—sometimes exceeding 1 GB.

Due to the file's large size, transferring it can take a long time. If issues occur during transmission, you may have to restart the transfer. Additionally, if size restrictions are imposed on a network or large transfers are given a lower priority over other traffic, the upload may be slow or problematic.

To circumvent possible restrictions, you can break the core file into smaller, more manageable files. This method allows you to easily upload the files again if a problem occurs during the upload. Additionally, smaller file sizes may receive higher priority within the network, resulting in faster upload times.

Splitting the core file

To break a large core file into smaller, more manageable files, perform the following procedure:

  1. Log in to the command line of your F5 device.

  2. Change directories to the /var/core directory by typing the following command:

    cd /var/core

  3. To list the core files in the directory, type the following command:

    ls

    Command output appears similar to the following example:

    -rw-r--r-- 1 root root 30259610 Jun 19 07:14 SH-tmm.bld517.5.core.gz

  4. Calculate a checksum for the core file using the following command syntax:

    Note: Calculating a checksum allows you to verify the file size when the smaller files are later reassembled.

    md5sum <core_file_name> > md5sum.txt

    For example:

    md5sum SH-tmm.bld517.5.core.gz > md5sum.txt

  5. To split the core file into smaller files, use the following command syntax:

    split -b <file_size> <core_file_name>

    For example:

    Note: The following example splits the core file into 10 MB files. The result of the split is two files of 10 MB each, with one file containing the remainder.

    split -b 10m SH-tmm.bld517.5.core.gz

    Output appears similar to the following example:

    # ls

    -rw-r--r-- 1 root root 10485760 Jun 19 17:04 xaa

    -rw-r--r-- 1 root root 10485706 Jun 19 17:04 xab

    -rw-r--r-- 1 root root 9288090 Jun 19 17:04 xac

    -rw-r--r-- 1 root root 58 Jun 19 17:04 md5sum.txt

  6. Upload the core files and the md5sum.txt file to F5 Technical Support.

    Note: For instructions, refer to K000090853: Exchange files with F5 Support using MyF5.

  7. Notify F5 Technical Support that the files have been uploaded.

Reassembling a multi-part core file

  1. Log in to the command line of your F5 device.

  2. Reassemble the files into a single core file by typing the following command:

    cat xaa xab xac > SH-tmm.bld517.5.core.gz

  3. Create a new md5sum of the reassembled files using the following command syntax:

    md5sum <file_name> > newmd5sum.txt

    For example:

    md5sum SH-tmm.bld517.5.core.gz > newmd5sum.txt

  4. Compare the new md5sum file with the original md5sum file using the following command syntax:

    diff <original_md5_file> <new_md5_file>

    For example:

    diff md5sum.txt newmd5sum.txt

If the checksums are the same, you will return to the command prompt without any messages. This lack of output indicates that the core file has been successfully split and joined back together.
