Known Issue

BIG-IP APM session content may not render correctly when using Internet Explorer 11.

This issue occurs when the following condition is met:

  • Internet Explorer is configured with Compatibility view.

Impact

Content does not render correctly.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing the content code received from the BIG-IP APM system, the X-UA-Compatible meta tag is located within client-side JavaScript.
  • When you access the destination resource directly, content appears to render correctly.

Workaround

To work around this issue, you can create and apply an iRule to the affected virtual server. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform this procedure during a scheduled maintenance window.

Creating the HTTP username header iRule

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the new iRule text Name box, type a name for the iRule.

    For example:

    compatibility_meta_tag
  5. In the Definition box, enter the following text:

    when HTTP_REQUEST {
    if { [HTTP::path] contains "<path of affected content>" } {
    set insert_meta 1
    } else {
    set insert_meta 0
    }
    }
    when REWRITE_REQUEST_DONE {
    if {$insert_meta != 0} {
    REWRITE::post_process 1
    }
    }
    when REWRITE_RESPONSE_DONE {
    #log local0. "just a spare log"
    set strt [string first {<head>} [REWRITE::payload]]

    REWRITE::payload replace $strt 6 "<head><meta http-equiv='X-UA-Compatible' content='IE=10' />"
    }
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the name of the virtual server that is affected by this issue.
  9. Click the Resources tab.
  10. In the iRules section, click Manage.
  11. From the Available column, select the iRule you previously created.
  12. To move the iRule to the Enabled column, click the << button.
  13. Click Finished.
