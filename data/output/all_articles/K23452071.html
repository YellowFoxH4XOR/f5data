Description

  • Beginning in BIG-IP version 12.0, a new SSL alert error message is available for troubleshooting in /var/log/ltm:

    warning tmm1[<PID>]: 01260009:4: Connection error: ssl_shim_vfycerterr:4539: application verification failure (46)

  • You notice this error when troubleshooting Client Certificate Authentication

Environment

  • SSL profile
  • Client Authentication configured
  • Set to require certificate from clients

Cause

This error is logged with default SSL logging levels when a virtual server is configured with an SSL profile that requires certificates for client side requests, but the client does not provide one. These warnings are logged when the SSL handshake fails for this reason. 

Recommended Actions

To verify if this behavior is functioning as designed:

  1. List the SSL profiles that have peer-cert-mode set to require, using tmsh list /ltm profile client-ssl. The output will look similar to this example:

     

    ltm profile client-ssl /Common/<Profile_Name> {
        ca-file /Common/ca-bundle.crt
        cert-lifespan 30
        cert-lookup-by-ipaddr-port disabled
        chain /Common/ca-bundle.crt
        cipher-group none
        ciphers DEFAULT
        client-cert-ca /Common/ca-bundle.crt
        crl-file none
        defaults-from /Common/client-ssl-profile
        key /Common/default.key
        peer-cert-mode require     <=== Note: require
    }

  2. Review a packet capture to verify that a client did not supply a client certificate in response to the serverhello from the Virtual Server. The client SSL response will look similar to the following examples:

     

    No certificate provided by client:

    Secure Sockets Layer
        TLSv1 Record Layer: Handshake Protocol: Multiple Handshake Messages
            Content Type: Handshake (22)
            Version: TLS 1.0 (0x0301)
            Length: 269
            Handshake Protocol: Certificate
                Handshake Type: Certificate (11)
                Length: 3
                Certificates Length: 0            <=== the client certificate was not included in the response
            Handshake Protocol: Client Key Exchange
        TLSv1 Record Layer: Change Cipher Spec Protocol: Change Cipher Spec
        TLSv1 Record Layer: Handshake Protocol: Encrypted Handshake Message

    Certificate correctly provided by client:

    Secure Sockets Layer
        TLSv1 Record Layer: Handshake Protocol: Certificate
            Content Type: Handshake (22)
            Version: TLS 1.0 (0x0301)
            Length: 5393
            Handshake Protocol: Certificate
                Handshake Type: Certificate (11)
                Length: 5389
                Certificates Length: 5386            <=== the client certificate was included in the response
                Certificates (5386 bytes)
    Secure Sockets Layer
        TLSv1 Record Layer: Handshake Protocol: Client Key Exchange
        TLSv1 Record Layer: Handshake Protocol: Certificate Verify
        TLSv1 Record Layer: Change Cipher Spec Protocol: Change Cipher Spec
        TLSv1 Record Layer: Handshake Protocol: Encrypted Handshake Message

  3. If this configuration to require a client certificate, is the expected behaviour, you can attempt to fix the issue by re-installing the certificate on Client side, following steps on Importing the client certificate (.pfx file) on
    K12140946: Configuring the BIG-IP system to perform two-way SSL authentication
