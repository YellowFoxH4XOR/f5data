Known Issue

Connections to Large Scale NAT (LSN) pools in port block allocation mode may cause the tmm process to produce a core file.

This issue occurs when the following conditions are met:

  • The affected virtual server references the udp_gtm_dns profile.
  • The virtual server is processing a large amount of traffic, or a small number of translation addresses are configured for the pool.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the Traffic Management Microkernel (TMM) restarting. Systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • You observe messages in the /var/log/ltm file that appear similar to the following example:

    notice sod[8810]: 01140045:5: HA reports tmm NOT ready.

  • You observe messages in the /var/log/tmm* file that appear similar to the following example:

    notice ** SIGSEGV **

Workaround

To work around this issue, you can remove the udp_gtm_dns profile from the virtual server, and replace it with a FastL4 profile.
