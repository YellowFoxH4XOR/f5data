K000135373: F5OS uses only the default hostname when logging to the system logs

Type
Support Solution
Published
2023-07-05
Updated
2024-08-19
Applies to
  • F5OS
  • F5OS-C: 1.3.0, 1.5.0, 1.3.2, 1.3.1, 1.6.2, 1.6.1, 1.6.0, 1.5.1
  • F5OS-A: 1.5.1, 1.5.0, 1.4.0, 1.3.2, 1.3.1, 1.3.0
Source
https://my.f5.com/manage/s/article/K000135373

Description

F5OS logging uses the rsyslogd daemon that runs inside each container in the F5OS system to consolidate their logs into a centralized location.

After you configure a new hostname on your VELOS or rSeries system, you observe that the system continues to log the default hostname (e.g. controller-1 on F5OS-C or appliance-1 on F5OS-A) locally in the system log files and also remotely in remote log servers.

For example:
F5OS-C /var/F5/system/log/velos.log:
<Date Timestamp> controller-1(p3) partition-ha[1]: priority="Info" version=1.0 msgid=0x4602000000000004 msg="Active going Standby".

F5OS-A /var/F5/system/log/platform.log:
<Date Timestamp> appliance-1 platform-mgr[13]: priority="Emerg" version=1.0 msgid=0x103000000000006 msg="Platform-mgr Firmware update in progress" elapsedseconds=30.

Environment

  • F5OS-C or F5OS-A
  • Logging

Cause

Bug ID 1300749

Recommended Actions

It is possible to use an iRule workaround that replaces custom strings in syslog traffic depending on the client's IP address. For more information, refer to Bug ID 1300749: Syslog target files do not use the hostname configured via system user interface.
