In a typical configuration where BIG-IP is installed in front of nodes, you must change the default route for each node so that it can route through BIG-IP. If you want each of the nodes to retain their existing default route, you can configure BIG-IP to apply a default SNAT to all incoming client traffic.

When configured with a default SNAT, BIG-IP will translate the source address for all incoming traffic to the nodes so that the traffic appears to be coming from a single source address on the same network. You do not need to change the default route when using a default SNAT, because the source address for the default SNAT is on the same network and a default gateway is not required to reach it.

Note: Since the source addresses are translated before the connections reach the servers, the servers will not be able to use client source addresses for activities such as logging or filtering.

To configure BIG-IP to translate the source address for all incoming connections to a specified virtual server address, perform the following steps:

  1. Create a pool for the nodes, by typing the following command:

    bigpipe pool <pool name> { member <IP address>:<port> member... }

    For example:

    bigpipe pool TrickyPool { member 10.90.101.51:80 member 10.90.101.52:80 }

  2. Create a virtual server that uses the pool, by typing the following version-specific command.

    BIG-IP versions 4.0 through 4.6.4

    bigpipe virtual <IP address>:<port> use pool <pool name>

    For example:

    bigpipe virtual 172.16.101.21:80 use pool TrickyPool

    BIG-IP versions 3.0 - 3.3.1 PTF-06

    bigpipe vip <IP address>:<port> use pool <pool name>

    For example:

    bigpipe vip 172.16.101.21:80 use pool TrickyPool

  3. Create a default SNAT that uses the same IP address as the virtual server, by typing the following command:

    bigpipe snat map default to <IP address>

    For example:

    bigpipe snat map default to 172.168.101.21
