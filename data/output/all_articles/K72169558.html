K72169558: How-to add BGP / OSPF debug output file into automatic log-rotate

Type
Support Solution
Published
2025-02-26
Updated
2025-02-26
Source

Description
Often, one will come across the necessity to enable BGP / OSPF debug to troubleshoot some specific issue.  Sometimes, the problem being troubleshooted doesn't occur very often and therefore one needs to leave debug enabled for extended periods of time.  By default, custom log files (such as a BGP / OSPF debug file, created via imish shell 'log file <file>' command) are not rotated automatically.  Diskspace is limited, so leaving the debug running eternally might end up create diskspace problems.  Adding automatic log-rotate to the custom file would therefore be desirable and this article intends to explain how to achieve that.

Environment

  • BIG-IP

Recommended Actions

- Providing an example, let's say we created inside ZebOS the following log file:

# imish
# enable
# configure terminal
# log file /var/log/zebos.log

- Next, we should add this file to log-rotate configuration.  Below is a sample of the default log-rotate config:
# tmsh
(tmsh)# list sys log-rotate all-properties

sys log-rotate {
    common-backlogs 24
    common-include none
    description none
    ilx-include none
    ilx-rotations 10
    ilx-schedule daily
    ilx-size 10240
    include none
    max-file-size 1024000
    mysql-include none
    syslog-include none
    tomcat-include none
    wa-include none
}

- In order to add /var/log/zebos.log file to the log-rotate list (for automatic log rotation), one needs to edit log-rotate config and add the below (notice 'include' section):

# tmsh
(tmsh)# edit sys log-rotate all-properties

sys log-rotate {
    common-backlogs 24
    common-include none
    description none
    ilx-include none
    ilx-rotations 10
    ilx-schedule daily
    ilx-size 10240
    include "
    /var/log/zebos.log {
       compress
       missingok
       notifempty
       copytruncate
    }"
    max-file-size 1024000
    mysql-include none
    syslog-include none
    tomcat-include none
    wa-include none
}

Additional Information
Note the 'copytruncate' above.  This is necessary, else bgp process will still hold the inode of the original file (which after log-rotation will be /var/log/zebos.log.1) and continue to write to the previous file/inode (/var/log/zebos.log.1) and not the new file (/var/log/zebos.log).
