Description

BIG-IP DNS's Wide-IP is intermittently resolving DNS query for a specific URL.

Decision Logging (K25751652) will show error in /var/log/gtm:
tmm notice tmm[18191]: 011ae024:5: UNRESOLVED rrtype = A, wip = www.example.org, LDNS(10.11.16.221), Drop packet
 

Environment

  • BIG-IP DNS
  • Wide-IP Persistence.
  • big3d
  • gtmd
  • iQuery Broadcast

Cause

This issue happens when multiple BIG-IP DNS is in sync-group with Wide IP persistence enabled and working  as a cluster to resolve incoming DNS queries. When DNS query is received by one of the BIG-IP in the sync-group which is missing current persistent record for the client, it drops the request and wait for the persistence record to be synced to it from other peers.
 
Following error message can appear in /var/log/ltm when BIG-IP DNS drop the query due to missing or stale persistence record.

tmm[18191]: 2020-01-01 01:00:00 gtm-a.local from 172.16.10.10#22222 [www.example.org A] [*pool member selection failed* - persistence key (10.11.16.221) does not exist] [dropped packet - persistence record is unavailable]

 

Recommended Actions

To workaround the issue, Wide-IP Persistence can be disabled if your application does not require it.

  1. Login BIG-IP DNS Configuration Terminal
  2. Navigate to DNS > GSLB > Wide IPs > Wide IP List
  3. Click on the Wide IP is Name which is having the issue
  4. Click on Pools tab
  5. Under Persistence, change Enable to Disable
  6. Click Update
