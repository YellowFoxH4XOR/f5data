K000161420: F5 APM - Passkey QR code is not working when BIG-IP VPN is connected

Type
Support Solution
Published
2026-05-26
Updated
2026-05-26
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161420

Description

Microsoft Passkey QR Code not working as expected

Environment

  • BIG-IP APM
  • Virtual server
  • Access profile
  • Network Access configured to use a Proxy or Proxy PAC file.
  • Edge Client or browser

Cause

Microsoft Passkey can present a QR Code to be scanned by Microsoft Authenticator on a Mobile device. The Authenticator Application uses Bluetooth on the Mobile device to communicate with the PC to provide an extra layer of security, in that the Mobile device must be in Bluetooth range of the PC. However, the Microsoft Passkey application on the PC does not use the Proxy Server that maybe configured in the APM VPN, which means that the application will send requests directly over the VPN, so the backend network on the APM Server, needs to allow these requests.

At the time of writing, the Microsoft Passkey application will send requests to the following URLs

 

PlatformURL
Android cable.ua5v.com
iOS

cable.auth.com

app-site-association.cdn-apple.com

app-site-association.networking.apple

 

Recommended Actions

If you have a split tunnel VPN then you can exclude the IP Addresses for these URLs,

If all traffic is being force via the VPN, then you will have to add firewall rules to your internal network to allow these connections
