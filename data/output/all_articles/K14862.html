Known Issue

BIG-IP database monitors may report an incorrect pool member status.

This issue occurs when all of the following conditions are met:

  • Multiple database monitors are configured with the same IP::Port destination (same pool member).
  • The affected database monitors are configured with different receive strings.
  • The pool member is monitored using any of the following database monitor types:
    • Oracle
    • MSSQL
    • MySQL
    • PostgreSQL

When multiple database monitors are checking the same pool member, a race condition may allow the system to incorrectly report a database monitor status. As a result, the system may incorrectly mark an available pool member as down, or an unavailable pool member as up.

Note: This issue can occur at the monitor's default time intervals. However, the likelihood of this issue occurring increases if the monitor's time interval is decreased and the monitor is performed more frequently.

Impact

The BIG-IP system incorrectly marks the affected pool members as up or down.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H438681 on the Diagnostics > Identified > High screen.
  • The BIG-IP system intermittently marks an available pool member as down.
  • The BIG-IP system intermittently marks an unavailable pool member as up.

Workaround

To reduce the likelihood of this issue occurring, you can increase the time interval for the affected monitors.

Impact of workaround: The system checks the pool members less frequently, and it may take you longer to detect a pool member failure.
