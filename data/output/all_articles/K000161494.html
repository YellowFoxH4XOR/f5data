K000161494: Illegal Requests Forwarded to Backend Before DNS-Based Violation Evaluation

Description

When using BIG-IP ASM policy with violation "Server-side access to disallowed host" set to Alarm mode and Violation Rating in Blocking mode, some illegal requests (Violation Rating 3) may be forwarded to backend servers before all violations are fully evaluated. This results in backend servers processing requests that should have been blocked, while the client receives the configured blocking response.

 

Environment

Product: BIG-IP ASM

ASM Policy with violation "Server-side access to disallowed host" set to Alarm mode (no Blocking mask) and "Violation Rating" in Blocking mode


Cause

This behavior is caused by a bug (ID2296473) in which the Violation Rating is evaluated before the DNS lookup is completed. If a DNS-based violation is detected after the initial evaluation, the Violation Rating is not recalculated. As a result, the request may be forwarded to the backend before all violations are considered.


Answer/Recommended Actions

To prevent illegal requests from being forwarded to backend servers enable the blocking mask for the "Server-side access to disallowed host" violation in the asm policy.

This will cause ASM to hold the request until DNS resolution is complete and block the request before forwarding if the violation is detected.

There is currently no ETA for a permanent fix for Bug ID2296473.


Additional Information

The Violation Rating is calculated before asynchronous DNS offload. Violations detected after DNS resolution are not included in the initial rating, and the block is enforced on the response path (after the backend has already received the request).

Only violations with the Blocking mask enabled will cause ASM to hold the request before forwarding.
