K1735: Using a rule to issue a redirect when the client specifies the wrong protocol in an HTTP URL

Topic

When you configure an SSL proxy to perform SSL decryption but not re-encryption, the BIG-IP communicates with the node using only the HTTP protocol. Because the node receives only HTTP requests, it may create redirects or dynamically generated URLs that reference the HTTP protocol. When clients attempt to follow the redirects or dynamically generated URLs, they will attempt to connect to BIG-IP using the HTTP protocol. Because BIG-IP is configured to use an SSL proxy, HTTP requests are rejected.

To avoid this problem, you can configure an HTTP virtual server on BIG-IP and create a rule for the virtual server that issues a redirect to HTTPS when an incoming URL specifies HTTP.

Note: A rule is not always the simplest or most efficient way to modify URLs. For more information about this topic, refer to K450: Preventing nodes from responding with redirects or links that contain HTTP references when the node is accessed through an SSL proxy.

If your nodes contain different directories for secure and non-secure content and, as a result, BIG-IP is already configured with an HTTP virtual server that uses the same nodes, you can create a rule that issues a redirect to HTTPS only when the URI indicates the client is accessing a secure area.

For example, if your nodes contain all secure content in the directory /secure/, you could redirect all requests for URIs that contain that directory name to HTTPS with the following rule:

if ( http_uri contains "secure") {
redirect to "https://%h/%u"
}
else {
use pool web
}

In the above example, if the virtual server is www.askf5.com, all requests that bear a URL beginning with HTTP://www.askf5.com/secure/ will be redirected to HTTPS://www.askf5.com/secure/. Requests for other URLs, such as HTTP://www.askf5.com/public/ will not be changed and are passed to the virtual server pool.

Important: In BIG-IP versions 4.2 through 4.2 PTF-08 and 4.5 through 4.5 PTF-01, BIG-IP may crash when using redirect rules. For more information, refer to K456: Known Issue: BIG-IP may crash and dump core when processing a rule that uses the redirect statement without the %u (URI) variable.
