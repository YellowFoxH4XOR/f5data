Description

The application server (Pool Member):

  1. Display "This site can't be reached" (for web servers)
  2. Does not respond to ICMP (ping) from the backend on BIG-IP direct ICMP request

Environment

Relevant environmental factors specific to the topic

  • Conditions
  • Configuration objects and settings
  • Products and features

Cause

  • IP Conflicted with BIG-IP SNAT Pool with BIG-IP Self IP
  • Potential IP conflict or ARP mis-mapping in the network.

Recommended Actions

Please follow below steps to investigate further into the root causes on why there's no response from the Pool Member.

  1. Perform a PCAP on the BIG-IP.
    • If possible, perform a concurrent PCAP on the pool member (backend server) and relevant network device (firewall/router).
  2. Check and confirm that the pool member or router has mapped the correct source MAC address for the BIG-IP related TMM interfaces.
    • If the MAC address is incorrect, investigate for possible IP conflicts.
    • Review the BIG-IP SNAT Pool configuration for duplicate IPs as the BIG-IP Self IP addresses.
    • Check the network for other devices using the same IP address.
  3. For detailed steps on resolving IP conflicts and ARP issues, refer to:
    • K24677132: Pool members on standby intermittently flap status due to IP conflict with a BIG-IP self-IP
    • K91425546: Error Message: 01190004:4: address conflict detected for <IP> (<MAC>) on vlan <VLAN>
  4. If above steps doesn't help, please raise a support case and share the QKView and the packet capture for further investigation.
