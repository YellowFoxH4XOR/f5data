Topic

When moving or inserting blades from a configured VIPRION chassis, you should consider the following suggestions before inserting that blade into the other VIPRION chassis:

Description

  • The host chassis configures the blade management IP configuration and it will not carry over to the new chassis.
  • The newly inserted blade may take 20 minutes or more to become fully functional because it needs to copy the software and configuration.
  • The new blade may reboot multiple time to install the required software and/or firmware.
  • Blades will not retain vCMP guest configuration when moved between chassis. Guest configuration will be overwritten and all data lost.
  • Ensure that the blades in the system are all the same model. F5 does not support running mismatched blades in a single system.
  • If the current primary blade only has one volume created, you may need to create a second volume and install software onto the volume so that the new blade can upgrade properly. The new blade may need to boot into a different partition while it performs upgrades to the primary boot slot of the new blade.
  • If the newly inserted blade was inserted into an administratively disabled slot, the configuration copied from the primary blade will continue to indicate the slot as down. The Traffic Management Microkernel (TMM) will not enable interfaces or process traffic on the newly inserted blade until the slot is enabled.
  • BIG-IP 11.5.0 and later supports direct upgrades to point release software. 
  • If you need to preserve a guest that is on the blade, please take a UCS file and follow the restoration guidelines in K14302.
