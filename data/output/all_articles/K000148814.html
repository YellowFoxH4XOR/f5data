Description

Some of the connections are closed with the TCP Reset sent from virtual server. In pcap file can see: [F5RST: iRule execution (reject command)].

The details of the iRule and the conditions that triggered the reject command should be reviewed to understand why the connection was terminated. The reject command is used to terminate the connection immediately, typically by sending a TCP reset to the client.

Environment

  • BIG-IP LTM
  • iRule (contain specific substring, in scenarios such as validating parts of a client certificate's Distinguished Name (DN)).

 

Cause

By expanding frame 16, it was observed that the F5 device received a certificate from the client. Upon inspection, it was found that the certificate does not contain the required subject attributes. Specifically, the expected subject distinguished name (DN) was not present. This discrepancy indicates that the certificate may not meet the necessary criteria for authentication or access:

 

The iRule is configured to inspect the subject_dn (subject distinguished name) of client certificates. If the subject_dn does not contain any of the specified values, the connection will be rejected. This ensures that only clients with the appropriate certificates are allowed to connect. Here’s an explanation of how the iRule works in relation to the outcome:

ltm rule /common/test-irule {  
    when CLIENTSSL_CLIENTCERT {
    # Check if client provided a cert
    if {[SSL::cert 0] ne ""} {
        set subject_dn [string tolower [X509::subject [SSL::cert 0]]]
        if { not ( $subject_dn contains "cn=example1.us" || $subject_dn contains "cn=example2.us" || $subject_dn contains "cn=example3.us" ) } {
            log local0. "request blocked from $subject_dn"
            reject
            return
        }
    }
}

 

The outcome shows the actual values in the Subject DN of a certificate. To determine if the iRule condition is met, we compare these values against the specified strings in the iRule. If there is none of the specified CN values in the iRule:

Therefore, in this specific case, the condition in the iRule would evaluate to false, as the Subject DN does not contain any of the specified strings. The iRule would then proceed to the else part (if defined) or take no action if there's no else part.

 

In frame 19, you may observe the TCP RST (reset) packet, which was triggered by an iRule on the F5 device. Specifically, this reset was initiated by the reject command within the iRule. This action indicates that the connection did not meet the criteria defined in the iRule, leading to its rejection. 

 

Recommended Actions

This issue could be due to a misconfiguration on the client side or an incorrect certificate being presented.

It is recommended to verify the certificate configuration and ensure that it includes all required attributes.
