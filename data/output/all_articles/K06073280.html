Description

When you want to use evaluate access feature for apm in your BIG-IQ(Evaluation(Access) page(Deployment -> EVALUATE&DEPLOY -> Access) you might see error similar to this one:

[WARN][19 Apr 2021 17:34:21 CEST][/cm/access/tasks/resolve-cross-module-references/d6250179-637a-4b1e-8579-e61dc3927c9b/worker AccessResolveCrossModuleObjectsTaskWorker] Failure in post-processing of object URIs. Object  /Common/DNS-Notify, kind=tm:ltm:virtual:virtualstate not found. Create this object for the target device and try the operation again., Reason : java.lang.IllegalStateException: Object  /Common/DNS-Notify, kind=tm:ltm:virtual:virtualstate not found. Create this object for the target device and try the operation again.
 at com.f5.rest.workers.global.task.superdeploy.ResolveCrossModuleObjectsTaskWorker$10.failed(ResolveCrossModuleObjectsTaskWorker.java:646)
 at com.f5.rest.workers.global.task.superdeploy.ResolveCrossModuleObjectsTaskWorker$10.failed(ResolveCrossModuleObjectsTaskWorker.java:625)

Environment

  • APM, BIG-IQ
  • Evaluate access feature

Cause

None at time of publication. 

Recommended Actions

The only workaround that is available now is to uncheck the "Include associated LTM Objects" option on the Evaluation(Access) page(Deployment -> EVALUATE&DEPLOY -> Access)

With the above workaround, it also means that customers will need to evaluate/deploy LTM and Access-related configurations separately.
 

Additional Information

Do note, in the event that a new Access Policy and VS is created on BigIQ, you will need to first eval/deploy LTM Objects before proceeding to eval/deploy APM, else error similar to the following will occur: Transaction 1620253460795326 on BIG-IP X.X.X.X failed after 1 seconds: 01020036:3: The requested virtual server (/Common/some_vs) was not found.
