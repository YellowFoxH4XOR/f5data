Known Issue

A large number of BIG-IP APM resources may cause the apmd process to enter an infinite restart loop when initializing.

This issue occurs when all of the following conditions are met:

  • Your system is configured with a large number (thousands) of BIG-IP APM resources (for example, access control list entries, webtops, app tunnels, and so on).
  • You perform an operation that requires the apmd process to start. For example, you restart the BIG-IP APM system or you manually restart the apmd process.

This issue is most likely to occur with the access control list (ACL) resource. During initialization, when the apmd process fails to initialize the Allow Ending policy item within the allocated 30 seconds timeout, it restarts.

Impact

The BIG-IP APM system fails to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You cannot access resources using the BIG-IP APM system.
  • In the /var/log/apm file, you observe initialization error messages similar to the following example:
    014902bc:3: Agent initialization failed: name: /Common/<access_policy_name>_end_allow_ag, type: agent_ending_allow, error: -200
    01490000:3: modules/ResourceAssignment/ResourceAssignAgent.cpp func: "initInstance()" line: 1165 Msg: ResourceAssignAgent::initInstance(): Init Error

Workaround

Impact: Performing the suggested workaround should not have a negative impact on your system.

You can reduce the number of BIG-IP APM resources configured in the access policy.
