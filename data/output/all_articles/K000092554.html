K000092554: Huge id number for synchronization of device group

Type
Support Solution
Published
2023-03-20
Updated
2023-03-21
Source
https://my.f5.com/manage/s/article/K000092554

Description

You are concerned or merely curious about the huge number in a config-sync log message like the following:

Nov 4 16:00:30 Big-IPA.Company.net notice mcpd[8022]: 0107168c:5: Incremental sync complete: This system is updating the configuration on device group /Common/HA device %cmi-mcpd-peer-/Common/Big-IPB.Company.net from commit id { 12918 7162299158014578136 /Common/Big-IPA.Company.net } to commit id { 12926 7162299488787848350 /Common/v_15A.Company.net }.

 

The number in question is the bold number, 7162299488787848350.
 

Environment

Big-IP with a Config-Sync device group.

Cause

That number is a 74-bit number that always grows larger with each confg-sync.

Recommended Actions

None, expected behavior.

Additional Information

The magnitude of the number is of no concern until 2038 approaches, which is when the 32-bit number used by *nix systems for "epochtime" reaches its maximum value. "Epochtime" is the number of seconds that have elapsed since 00:00:00 UTC on 1 January 1970, excluding leap seconds. This limitation will be addressed within the *nix operating systems before this becomes an issue.
