K000140072: VELOS controller upgrade install status "failed", BIOS AFU failure in controller's velos.log

Type
Support Solution
Published
2024-06-20
Updated
2024-06-20
Applies to
  • F5OS
  • F5OS-C: 1.6.X, 1.5.X, 1.6.2, 1.6.1, 1.6.0, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000140072

Description

Attempted to upgrade VELOS system controllers (for example, from v1.5.1 to v1.6.2), but the upgrade was marked as failed after the standby controller was upgraded.

(show system image)
                     SERVICE      ISO      INSTALL  
NUMBER  OS VERSION   VERSION      VERSION  STATUS   
----------------------------------------------------
1       1.5.1-14085  1.5.1-14085  -        failed   
2       1.6.2-26579  1.6.2-26579  -        failed   

The /var/log_controller/velos.log file contains entries similar to:

controller-2 platform-fwu[8]: priority="Err" msg="CMD Error: Exit Code: 1\\nFailed to execute operation: Connection timed out" interface="job-515" actionKey="POST:shell" jobId=515

controller-2 diag-agent[8]: priority="Err" msgid=0x098200000000001a msg="Component Attribute Changed" component="controller/firmware/bios" attribute="firmware:update-status" severity="Error" value="error" interface="diag-controller"

The /var/log_controller/cc-confd file contains an entry similar to:

vcc_install_check_afu_status: Vcc-ConfD-RU: AFU error message detected in afu-cookie file, marking install as failed.

Environment

  • VELOS system controller upgrade
  • AFU

Cause

The platform-fwu process attempted to execute a systemctl enable reboot-guard command to prevent the system from rebooting during firmware update. Execution of this command failed, which aborted the upgrade. However, the firmware update most likely succeeded.

Bug ID1597669 tracks this issue. This is a rare issue.

Recommended Actions

You can confirm the BIOS firmware status with the following command, from bash:

docker exec diag-agent psf run --format=json-lines GET:components/attributes component=controller/firmware/bios | jq .

Example output, indicating the BIOS has been updated and is healthy:

{
  "tags": [
    "firmware",
    "bios",
    "controller-1"
  ],
  "id": 0,
  "description": "Firmware version",
  "severity": "Info",
  "health": "Ok",
  "updatedAt": "2024-06-12T09:57:58-07:00",
  "type": "string",
  "options": [
    "pub-health",
    "pub-value"
  ],
  "value": "2.02.170.1",        <--- This is the BIOS version for F5OS-C v1.6.2
  "component": "controller/firmware/bios",
  "attribute": "firmware:version",
  "field": "currentVersion",
  "visibility": "Public",
  "updatedCount": 20
}

If the firmware update failed, open a case with F5 Support.

If the firmware update succeeded, you can recover that controller by performing a clean install of the previous version via PXE or USB to the upgraded controller (matching the version of the non-upgraded controller). This process can take up to 90 minutes. You can then attempt another upgrade.

Additional Information

Upgrade failures may be caused by a variety of reasons. If your VELOS system's logs do not contain entries matching the examples in this article's description, this issue is most likely not applicable to your scenario, and further investigation is required.
