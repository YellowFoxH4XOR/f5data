Known Issue

When the BIG-IP system log files become excessively large, users may not be able to access the Configuration utility.

This issue occurs when all of the following conditions are met:

  • The system log configuration uses audit logging options where the MCP setting is set to Enable or Verbose mode.
  • The system log configuration uses at least one local traffic logging option set to the Debug level.
  • You view the log files by accessing the Configuration utility System > Logs page.

Impact

Users cannot access the Configuration utility.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Log files of the affected system become excessively large after a period of time.
  • Users cannot access the Configuration utility when viewing the log files via the System > Logs page.

Workaround

To work around this issue, when the Configuration utility is in an unresponsive state, you can restart the tomcat service. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the tomcat service, type the following command:

    restart /sys service tomcat

To mitigate the issue, you can configure the BIG-IP system logging options to show only the most severe output. For example, you can use the Emergency or Error level settings.
