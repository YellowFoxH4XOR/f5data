Known Issue

This is the result of a known issue. When BIG-IP LTM virtual servers are deleted, the pvad process does not set the netmask of the control frame to PVA2 correctly. In some situations, this issue causes the PVA2 chip to lock up, resulting in a TMM core dump. This issue can occur when a BIG-IP LTM virtual server is manually deleted, or when the system is relicensed. When the BIG-IP system is relicensed, all configuration objects are deleted and recreated.

F5 Product Development tracked this issue as CR71531 and CR71385 and it was fixed in BIG-IP LTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
