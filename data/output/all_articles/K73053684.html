K73053684: ASM event logs not being observed from BIG-IQ monitoring page

Type
Support Solution
Published
2022-06-07
Updated
2025-02-07
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K73053684

Description

  • packet captures indicate that port 8514 on the DCD is receiving the logs and the the ASM index file is increasing in size
  • looking at the BIG-IQ CM Monitoring page for Web Application Security events shows a blank screen

Environment

  • Web Application Security service is enabled on the DCD
  • ASM logs being sent to the BIG-IQ
  • BIG-IQ Data Collection Cluster

Cause

Most likely due to a corrupted ASM log index file

Recommended Actions

1. Identify the name(s) of the asmindex* file(s)

      # curl -s -u admin:admin --insecure https://localhost:9200/_cat/indices?v | grep asm
   # curl -s -u admin:admin --insecure https://localhost:9200/_cat/aliases?v | grep asm

2. Disable the Web Application Security (ASM) service on each DCD in the CM (this stops the DCDs from listening on port 8514)

3. On the CM terminal run the following command against each instance of asm index found on step 1.
      # curl -ku admin:admin -sX DELETE "https://localhost:9200/name_of_the_index_file" | json_pp

4. Confirm that the index is no longer present

   # curl -s -u admin:admin --insecure https://localhost:9200/_cat/indices?v | grep asm
   # curl -s -u admin:admin --insecure https://localhost:9200/_cat/aliases?v | grep asm

5. Re-enable the Web Application Security (ASM) service on each DCD in the CM

6. Observe that when event logs get sent to the BIG-IQ cluster a new asmindex gets created.

   This can be checked by looking for the presence of the asmindex_writer in the elasticsearch alias output:
    # curl -s -u admin:admin --insecure https://localhost:9200/_cat/aliases?v | grep asm

Additional Information

Make sure to use URL encoding for the special characters in the index file name
