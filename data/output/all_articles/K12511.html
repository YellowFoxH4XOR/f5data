Known Issue

This is the result of a known issue. In BIG-IP version 10.0.0, the bigpipe route command incorrectly adds a /96 mask when creating an IPv6 default route or static non-default route.

For example:

bigpipe route default inet6 { gateway 3ffe:1900:4545:3:200:f8ff:fe21:67cf }

Adding an IPv6 default route to the above example command will incorrectly create the route as shown in the following ip -f inet6 route show output:

unreachable ::/96 dev lo metric 1024 error -101 mtu 16436 advmss 16376::/96 via 3ffe:1900:4545:3:200:f8ff:fe21:67cf dev external metric 1024 mtu 1500 advmss 1440

F5 Product Development tracked this issue as ID 207479 (formerly CR120323) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

Workaround 

You can work around this issue by creating IPv6 default routes with the ip command instead of the bigpipe route command, as shown in the following example:

ip -f inet6 route add default via 3ffe:1900:4545:3:200:f8ff:fe21:67cf dev external

Note: For more information about the ip command, consult the ip man page and usage guide by typing the following commands:

man ip

ip -h
