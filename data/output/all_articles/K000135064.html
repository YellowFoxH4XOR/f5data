Description

It seems that if we create a new policy (with asm-sync disabled) we see the new policy on the peer but if we make a change to a policy that change does not sync. Will a new policy be created on the peer device, even without the asm-sync enabled?

Environment

ASM policy creation

No ASM sync group

Cause

This is expected behavior. When ASM sync is not configured, the shell policy configuration is stored in /config/bigip.conf, which will be synced with the LTM configuration in the normal way. This is necessary to provide the link between the ASM and LTM configurations. The bulk of the ASM configuration in the database is synced only when ASM Sync is enabled for a device group.

Recommended Actions

Add Application Security Synchronization to a Device Sync group

Additional Information

Here is an expamle showing the expected behavior:

( 1 ) No ASM sync is configured.
( 2 ) Create a new policy.
( 3 ) This is created (by default) as blocking and can be seen in /config/bigip.conf

asm policy /Common/test_policy {
policy-template POLICY_TEMPLATE_COMPREHENSIVE
}

( 4 ) Because it's in bigip.conf it *IS* synced with the normal LTM configuration to the peer device.
( 5 ) However because ASM sync is not configured, ASM policy changes will not be reflected on the peer. For example I changed the policy from blocking -> transparent and this change is not synced so I end up with the policy set to blocking on one device and transparent on another.
