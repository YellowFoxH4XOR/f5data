Known Issue

HTTP compression statistics may not correctly identify JavaScript content.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP virtual server is configured to use an HTTP compression profile.
  • HTTP content processed by the virtual server contains a Content-Type other than application/x-javascript for the JavaScript header.

    Following are some examples of alternate JavaScript Content-Type headers:

    text/javascript
    application/javascript

Impact

JavaScript compressed by the BIG-IP system that does not use the application/x-javascript Content-Type header is included in the HTTP compression statistics classification of Other.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view http-compression profile statistics, the statistics classification of Other has a disproportionate value.
  • When you view http-compression profile statistics for known, compressed JavaScript content that does not contain the application/x-javascript Content-Type header, the compression statistics for JavaScript is not incremented.

Workaround

To work around this issue, you can implement a custom iRule to modify the specific JavaScript HTTP Content-Type header to classify the JavaScript content as application/x-javascript. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name for the new iRule.
  5. In the Definition box, enter the following text:

    when HTTP_RESPONSE {
        if {[HTTP::header Content-Type] contains "text/javascript"} {
        HTTP::header replace Content-Type application/x-javascript
        log local0. "after [HTTP::header Content-Type]"
        }
    }

    Note: If required, replace text/javascript with the HTTP Content-Type header of the non-matching JavaScript header that your application sent.

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the name of the affected virtual server.
  9. Click the Resources tab.
  10. Click the iRule Manage button.
  11. In the Available column, select the new iRule, and click the << button to move the iRule to the Enabled column.
  12. Click Finished.
