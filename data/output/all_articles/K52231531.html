Known Issue

When you set the tm.simultaneousopen database key to reset or drop_connection, the Traffic Management Microkernel (TMM) may produce a core file during a TCP simultaneous four-way handshake.

This issue occurs when all of the following conditions are met:

  • You set the tm.simultaneousopen database key to reset or drop_connection.
  • The BIG-IP system initiates a TCP four-way (simultaneous open) handshake.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and failover may occur if you've configured the system as part of a high-availability (HA) group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H611508 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system generates a TMM core file in the /shared/core directory, with a time stamp that correlates to the time of the traffic interruption.
  • The BIG-IP system may unexpectedly fail over to another system in the device group.

Workaround

To work around this issue, you can set the tm.simultaneousopen database key variable to drop_pkt. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) as an administrator by typing the following command:

    tmsh

  2. Type the following command:

    modify sys db tm.simultaneousopen value drop_pkt

  3. To save your changes, type save / sys config and press Enter.
  4. To exit the tmsh utility, type quit and press Enter.
