K11327: Following an upgrade, a BIG-IP system may become active before the BIG-IP ASM daemons have started

Known Issue

This is the result of a known issue. During the first boot following an upgrade, a BIG-IP system may become active and begin accepting traffic before the BIG-IP ASM daemons have started. During this time, BIG-IP ASM-enabled virtual servers are unreachable. This condition usually resolves itself within a few minutes, after the BIG-IP ASM daemons have restarted.

This issue occurs when a large BIG-IP ASM configuration is rolled forward during an upgrade. After the upgrade is complete and the BIG-IP system is rebooted, the BIG-IP ASM configuration is loaded into the MySQL database. Depending on the size of the BIG-IP ASM configuration, the BIG-IP system may set itself active before it has finished importing all the data into the MySQL database.

The BIG-IP ASM system is ready to accept traffic when the following message is written to the /var/log/asm file:

ASM started successfully

The expected behavior is for the BIG-IP system to remain offline until it has completed importing the BIG-IP ASM configuration.

F5 Product Development tracked this issue as ID 224737 (formerly CR137496) and it was fixed in BIG-IP ASM 11.1.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

You may be able to work around this issue in one of the following ways:

  • If you are upgrading a BIG-IP high availability pair, ensure that each unit you upgrade remains standby after it is rebooted. Wait until the ASM started successfully message appears in the /var/log/asm file before failing over to that unit.

    Note: To ensure that the BIG-IP systems do not automatically swap roles after an upgrade, set the Redundancy State Preference setting of both units to None. For more information, refer to K8184: Overview of the Redundancy State Preference setting.
  • If you are installing a hotfix and you do not require importing the configuration of the currently active boot location onto the target boot location, perform the hotfix installation using the image2disk utility invoked with the --nosaveconfig option. This option tells the BIG-IP system not to save and reimport the configuration during an installation.

    Note: For more information about installing BIG-IP version 10.x hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems or K9819: Installing a BIG-IP version 10.x hotfix on a partitioned system.
