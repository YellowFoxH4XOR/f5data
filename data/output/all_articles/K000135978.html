K000135978: Users failing APM endpoint inspection checks after changing Windows system language

Type
Support Solution
Published
2023-08-25
Updated
2023-08-25
Applies to
  • BIG-IP
  • APM Clients
  • BIG-IP APM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000135978

Description

After changing the system language of a Microsoft Windows client, the client is unable to authenticate to access policy due to endpoint inspection checks failures, like failing to detect Firewall or Antivirus state. For example, when changing the Windows client language from English to German, authentication starts to fail. Changing language back to English clears the issue.


Example of session logs failing to detect a Firewall as enabled:

<date> <hostname> notice apmd[15545]: 01490113:5: /Common/MyAccessPolicy:Common:<session ID>: session.check_software.last.fw.item_1.state is 0

<date> <hostname> notice apmd[15545]: 01490113:5: /Common/MyAccessPolicy:Common:<session ID>: session.check_software.last.fw.result is 0

<date> <hostname> notice apmd[15545]: 01490113:5: /Common/MyAccessPolicy:Common:<session ID>: session.check_software.last.fw.state is 0


Environment


• BIG-IP APM

• Access policy with endpoint inspection checks

• Microsoft Windows system with language different than English

• EPSEC build version 1468


Cause

Unknown at the time of publication.


Recommended Actions

Update EPSEC version to v1483 (epsec-1.0.0-1483.0.iso) or latest version available at the time.


Additional Information

None.
