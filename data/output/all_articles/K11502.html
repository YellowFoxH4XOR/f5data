K11502: The BIG-IP ASM may insert a Cache-Control: no-cache header in all its responses

Type
Knowledge
Published
2011-09-22
Updated
2023-02-21
Status

Applies to

  • BIG-IP ASM: 10.2.0, 10.1.0
Source

Topic

When a BIG-IP ASM-enabled virtual server is configured to use RAM Cache, the BIG-IP ASM will insert a Cache-Control: no-cache header in all its responses if any of the following features are enabled for the security policy:

  • Tightening
  • Staging
  • Learning
  • Policy Building

If the server response already includes a Cache-Control header, the BIG-IP ASM will change its value to no-cache.

This behavior is by design; the BIG-IP ASM uses the Cache-Control: no-cache header to prevent RAM Cache from potentially caching malicious or sensitive content while the security policy is being built.

The RAM Cache feature is not intended to be used while the ASM security policy is being built. F5 recommends that you enable RAM Cache only once the policy has been built and put in blocking mode.

Because the Cache-Control header propagates all the way to the client, a web application may not function as intended if all the responses transmitted by the BIG-IP ASM contain a Cache-Control: no-cache header. For example, this behavior results in Internet Explorer failing to open Microsoft Office documents with external helper applications because content is immediately removed from the disk after downloading.

F5 Product Development tracked a Request for Enhancement (RFE) to implement a better mechanism to prevent RAM Cache from caching responses while the ASM security policy is being built. F5 Product Development tracked this RFE as ID 342123 and ID 225842 (formerly CR140291) and it was resolved in BIG-IP version 10.2.1.

Workaround

If a web application is adversely affected by the behavior described in this Solution, you should perform one of the following actions:

  • Stop all Tightening/Staging/Learning/Policy building, which means you have completed building the security policy.
  • Disable RAM Cache while the security policy is still building.
