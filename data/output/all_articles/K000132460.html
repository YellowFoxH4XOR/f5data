Description

Requests that contain parameters undefined in OpenAPI schema file does not trigger any violation on application security policy which was created using the same schema file.

For example:

OpenAPI Schema File:
openapi: 3.0.0
info:
  version: 1.0.0
  title: Sample API
  description: A sample API to illustrate OpenAPI
paths:
  /transaction:
    post:
      description: Lets a user post a new transaction
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              additionalProperties: false
              properties:
                username:
                  type: string
                firstname:
                  type: string
                lastname:
                  type: string
                accountID:
                  type: integer

HTTP Request containing parameter "test" which is undefined in the schema file above does not trigger any violation:
POST /transaction HTTP/1.1
Host: www.domain.com
Content-type: application/json
Content-Length: 135

{
    "username": "testuser",
    "firstname": "testfirst",
    "lastname": "testlast",
    "accountID": 123456,
    "test": "moo"             <<<<<<<<<<<<<
}

Environment

  • BIG-IP ASM / Advanced WAF
  • ASM security policy created using schema file attached to Virtual Server

Cause

This behavior is expected because as per https://github.com/OAI/OpenAPI-Specification/blob/main/versions/3.0.3.md#schemaObject:
"additionalProperties - Value can be boolean or object. Inline or referenced schema MUST be of a Schema Object and not a standard JSON Schema. Consistent with JSON Schema, additionalProperties defaults to true."
Note: This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

Recommended Actions

additionalProperties must be set to false within the schema file.
