Topic

When Clustered Multiprocessing (CMP) is enabled, the BIG-IP system may modify the client source port for secure network address translation (SNAT) connections in order to ensure that both client and server-side flows are hashed to the same Traffic Management Microkernel (TMM) instance.

Most traffic is not negatively impacted when the BIG-IP system modifies the client's source port. However, this behavior can be problematic for certain types of traffic that require the source port to be preserved, such as nPath, and some Session Initiation Protocol (SIP) implementations.

By default, the BIG-IP system attempts to preserve the client's source port for server-side flows. The following describes BIG-IP source port behavior and how to change the default behavior.

You should consider using this procedure under the following condition:

  • You have applications that require a SNAT object to preserve or change the source port.

Description

In BIG-IP 10.0.0 and later, you can specify whether a SNAT object preserves the client's source port by changing the source port setting for the SNAT. The source port settings are as follows:

  • Preserve

    Specifies that the system attempts to preserve the value configured for the source port unless the source port from a particular SNAT is already in use, in which case the system uses a different port. Preserve is the default behavior.

  • Preserve Strict

    Specifies that the system preserves the value configured for the source port. If the port is already in use by another connection, the system resets the client-side connection. To minimize the number of collisions resulting in resets, F5 recommends that you restrict use of this setting to cases that meet at least one of the following conditions:

    Note: This functionality requires that the port is configured for User Datagram Protocol (UDP) traffic (BIG-IP 10.0.0 and later) or TCP traffic (BIG-IP 11.3.0 and later.)

    • Clustered multi-processing (CMP) is disabled.
    • The system is configured for nPath routing or is running in transparent mode (there is no translation of any other Layer 3 (L3) or Layer 4 (L4) field).
    • There is a one-to-one relationship between virtual IP addresses and node addresses.
  • Change

    Specifies that the system always uses the next available port. No attempt is made to preserve the client source port. This setting ensures that a unique port is chosen for each new connection, and may be helpful in avoiding premature port reuse when load balancing legacy systems that use longer than usual TIME-WAIT windows.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the TMOS Shell (tmsh).

Procedures

  • Using the Configuration utility to modify the source port preservation for SNATs
  • Using tmsh to modify the source port preservation for SNATs

Using the Configuration utility to modify the source port preservation for SNATs

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: Prior to version 12.0.0, you must use tmsh to change the source port setting for a SNAT.

  1. Log in to the Configuration utility.
  2. Navigate to Address Translation > SNAT List.
  3. Under Configuration, change the Source Port setting to the desired value.
  4. Click Update.

Using tmsh to modify the source port preservation for SNATs

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: Prior to version 12.0.0, you must use tmsh to change the source port setting for a SNAT.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Change the source port setting for a SNAT by using the following tmsh syntax:

    modify /ltm snat <snat_name> source-port <change | preserve | preserve-strict>

    For example, to change the source port setting to preserve-strict for a SNAT called SNAT-1, you would use the following command:

    modify /ltm snat SNAT-1 source-port preserve-strict

  3. Save the change by typing the following command:

    save /sys config
