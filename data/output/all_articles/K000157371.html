Description

  • You're running NGINX App Protect, and the client requests get '444' response codes.
  • The NGINX error log shows 'APP_PROTECT aborting request xxxx ctx id xxxx'.
  • The NGINX App Protect log, bd-socket-plugin.log, shows 'Too many threads! (RW_threads_number = 256), trying again'.

Environment

  • NGINX App Protect

Cause

The NGINX worker processes are set higher than the supported BD thread limit (127), causing thread mismatches and disconnections between NGINX and App Protect, which led to mass request aborts and HTTP 444 errors under high load.

Recommended Actions

Manually set the NGINX worker_processes in nginx.conf to 127 or less, and set the worker_cpu_affinity directive to auto.

---- /etc/nginx/nginx.conf ----
user  nginx;
worker_processes  127;    <<=== Set to 127 or less
worker_cpu_affinity auto; <<=== Set to auto

error_log  /var/log/nginx/error.log info;
pid        /run/nginx.pid;

load_module modules/ngx_http_app_protect_module.so;
...

The NGINX team is working on this to extend the DB thread limit and will release it in a future version.

Additional Information

  • NGINX worker_processes directive
  • NGINX worker_cpu_affinity directive
