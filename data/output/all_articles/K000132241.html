Description

Logging different JWT claims when using OIDC for authentication.

Environment

  • NGINX Ingress Controller
  • OIDC
  • NGINX Instance Manager

Cause

Find the complete JWT sent from the customer to NGINX and log this information.

 Recommended Actions

Add the full JWT to your log-format 
log-format:  '$remote_addr - $remote_user [$time_local] "$request" $status $grpc_status $body_bytes_sent "$http_referer"  "$http_user_agent" "$http_x_forwarded_for" "$resource_name" "$resource_type" "$resource_namespace" "$service"\nJWT Subject: $jwt_claim_sub\nFull JWT: $session_jwt\n'
You can decode the Full JWT using a website like jwt.io
You can see in this decoded version of the JWT there is a claim called sub. This is the claim that NGINX uses for the header named username
You can log any of these claims that you would like to log using the same example above. (See JWT Suject: $jwt_claim_sub)
 

Additional Information

Each different IDP can send whatever information they want in these claims. So, you can decode your particular claim and log whatever information you would like to see.
