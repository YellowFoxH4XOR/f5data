Known Issue

The Traffic Management Microkernel (TMM) may restart when two subscriber connections share a Dynamic Host Configuration Protocol (DHCP) server connection.

This issue occurs when all of the following conditions are met:

  • You are using BIG-IP PEM DHCP to discover subscribers.
  • You have configured a DHCP relay virtual server.
  • Two BIG-IP PEM DHCP subscriber connections share the same connection to a remote DHCP server.
  • One of the BIG-IP PEM DHCP subscriber's connections expires.
  • The unexpired BIG-IP PEM DHCP subscriber sends a new DHCP request.
  • The remote BIG-IP PEM DHCP server responds to the new BIG-IP PEM subscriber request.

Impact

Traffic processing is interrupted while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system fails to process traffic for a brief period.
  • Your BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.

Workaround

To work around this issue, ensure that you have configured the remote DHCP server's routing table to send DHCP ACK packets back to each BIG-IP PEM DHCP subscriber.

Impact of workaround: Performing the recommended workaround should not have a negative impact on your system.
