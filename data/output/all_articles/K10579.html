Known Issue

Note: This article applies to BIG-IP 1600, 3600, 3900, 6900, 8900, and VIPRION platforms only.

This is the result of a known issue. A network interface on the BIG-IP system may fail to come up under the following circumstances:

  • The network interface is configured to use a fixed media type and the interface is disabled and then re-enabled.
  • The network interface is configured to use a fixed media type and the mcpd service is restarted or the BIG-IP system is rebooted.

Note: Depending on your software version, the issue you are experiencing may be a combination of the issue described in this article and the issues described in K9150: The interface media setting is lost upon a system reboot or an mcpd process restart and K9469: A disabled interface is enabled after a reboot or an mcpd process restart.

F5 Product Development tracked this issue as CR117186 and it was fixed in BIG-IP 9.4.8 and 10.1.0. For information about upgrading refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WAN Optimization release notes.

This issue was fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

Workaround

If an interface configured to use a fixed media type does not come up after it was disabled or the mcpd service was restarted, you can work around this issue by setting the interface to auto and then back to the desired fixed media type. Temporarily changing the interface to auto will make it come back up.

Additionally, you may automate this workaround every time the mcpd service is restarted by performing the following procedure:

  1. Connect to the BIG-IP system via secure shell (SSH).
  2. Using a text editor, open the /config/user_alert.conf file.
  3. Assuming you want to configure the 1.1 and 1.2 interfaces to 1000baseT full, add the following lines to the end of the file:

    alert if_media_workaround "Initialization complete. The MCP is up and running" {
    exec command="sleep 15";
    exec command="/bin/bigpipe interface 1.1 media auto";
    exec command="/bin/bigpipe interface 1.2 media auto";
    exec command="/bin/bigpipe interface 1.1 media 1000baseT full";
    exec command="/bin/bigpipe interface 1.2 media 1000baseT full";
    exec command="/bin/bigpipe base load";
    exec command="/bin/bigpipe load"
    }

    Note: The bigpipe base load and bigpipe load commands first wipe out all running configuration and then reload the configuration. Executing these commands ensures that gratuitous Address Resolution Protocols (ARPs) are sent once the interfaces are up.
  4. Save the file and quit the editor.
