K000152648: BIG-IP DNS configuration changes fail to synchronize to all sync group members

Type
Support Solution
Published
2025-07-21
Updated

Applies to

  • BIG-IP DNS: 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source

Description

BIG-IP DNS (GTM) synchronization failure may occur in environments where objects created on one device do not propagate to other devices in the sync group. Manual synchronization using gtm_add can temporarily resolve the issue, but automatic synchronization remains inconsistent. Configuration review may reveal duplicate GTM server objects or missing address translation settings.

Environment

  • Product: BIG-IP DNS (GTM)
  • High Availability (HA) with multiple BIG-IP DNS devices
  • BIG-IP DNS sync group configured
  • Address translation between public and private IPs

Cause

Duplicate or conflicting BIG-IP DNS server objects for the same device(s), where one contains the public addresses and the other contains the private addresses, prevent proper object synchronization within the sync group.

Recommended Actions

  1. Review all BIG-IP DNS server object configurations on each device in the sync group.
  2. Ensure that each physical device-group is represented by a single BIG-IP DNS server object.
  3. Configure address translation correctly within each server object, mapping public IP addresses to their corresponding private IP addresses.
  4. Example of correct configuration:

    gtm server <server_name> {
        datacenter <datacenter_name>
        devices {
            "<device_peer_name>" {
                addresses {
                    <public_ip> { translation <private_ip> }
                }
            }
            <server_name> {
                addresses {
                    <public_ip_2> { translation <private_ip_2> }
                }
            }
        }
        monitor <monitor_name>
        product bigip
    }

  5. Remove any duplicate or conflicting server objects from all devices.
  6. After making corrections, use gtm_add as needed to re-establish synchronization amongst sync group members.
  7. Confirm that new objects created on any member of the sync group are now visible on all peers.
