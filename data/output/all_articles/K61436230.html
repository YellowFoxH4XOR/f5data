Description

BIG-IP system failover happened even though the device is not part of HA cluster.

The following logs were seen in /var/log/ltm:

Jan  1 12:00:00 <big_ip_name> sod[1111]: 01111111:1: Sod requests links down.
Jan  1 12:00:00 <big_ip_name> sod[1111]: 01111111:1 Offline for traffic group traffic-group-1.
Jan  1 12:00:00 <big_ip_name> sod[1111]: 01111111:1: 010c003e:5: Offline
Jan  1 12:00:00 <big_ip_name> sod[1111]: 01111111:1: Failover event detected. (Switchboard failsafe disabled while offline)


Environment

  • Standalone Device
  • Device offline for a few minutes


Cause

The reason for the failover was that a daemon ( for e.g. bd process ) was terminated by kernel due to memory exhaustion.

The fail action for when sod ( Switch-Over-Daemon ) does not detect heartbeat from the terminated daemon ( bd ) , it instructs the BIG-IP to 'go offline and down links'

This causes the failover.

If the BIG-IP was part of a HA cluster, the traffic will float to the peer device. The peer device will take the Active role.

Once the daemon is running again ( online ) and sod detects the heartbeart, the BIG-IP will return from offline status.

Note: bd daemon will restart on its own.

The following logs from /var/log/ltm indicate BIG-IP is online again:

Jan  1 12:00:00 <big_ip_name> bd[2222]: 01111112:2: HA daemon_heartbeat bd enabled.
Jan  1 12:00:30 <big_ip_name> sod[1111]: 01111111:1: HA proc_running bd is now responding.
Jan  1 12:00:30 <big_ip_name> sod[1111]: 01111111:1: Active for traffic group traffic-group-1.
 

Recommended Actions

None.
 

Additional Information

Should there be a need to change the settings of the heartbeat action for sod, it can be done from CLI:

tmsh modify sys daemon-ha sod heartbeat-action <Values>

<Values>
  failover                       go-active                      go-offline-downlinks           go-offline-restart             none                           restart
  failover-restart-tm            go-offline                     go-offline-downlinks-restart   go-offline-restart-tm          reboot                         restart-all
