Description
This article provides the instruction on how to do SNAT in iRule for HTTP2 Virtual Server with HTTP MRF Router profile.

Note: For an HTTP2 Virtual Server with HTTP MRF Router profile, the SNAT iRule command can only be used in the LB_SELECTED event.

Environment

  • BIG-IP LTM
  • HTTP2 protocol
  • HTTP MRF  Router profile
  • iRule

Cause
Bug ID 980617: SNAT iRule is not working with HTTP/2 and HTTP Router profiles

Recommended Actions
In connection to the said bug, to do SNAT in iRule, use the "snat" iRule command in the LB_SELECTED iRule event. For example, as shown below,  to use different SNAT IP addresses for different client subnets: 

when LB_SELECTED {
    if { [class match [IP::client_addr] equals snat-group-1] } {
        snat x.x.x.x
    } elseif { [class match [IP::client_addr] equals snat-group-2] } {
        snat y.y.y.y
    } else {
        snat none
    }
}

ltm data-group internal /Common/snat-group-1 {
    records {
        172.16.0.0/16 { }
    }
    type ip
}
ltm data-group internal /Common/snat-group-2 {
    records {
        10.0.0.0/8 { }
    }
    type ip
}

Note: Replace x.x.x.x and y.y.y.y with the desired floating or non-floating self-IP addresses.
