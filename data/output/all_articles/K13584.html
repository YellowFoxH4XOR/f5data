Known Issue

Description

ARX migration of compressed files from a Windows filer to an Isilon system filer fails.

When migrating files, the ARX system attempts to synchronize the file attributes. Some attributes are not supported by the file servers, and filers are required to ignore certain attributes that are not supported. In this case, the Isilon system does not support compressed files, but it does not ignore the FILE_ATTRIBUTE_COMPRESSED attribute request as it should, and this breaks the migration.

Impact

The migration of the compressed files fails.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You may see a POLICY_ACTION-10-ERR-POLICY_ACTION_FAILED message in the ARX syslog that appears similar to the following example:

    POLICY_ACTION-10-ERR-POLICY_ACTION_FAILED::

    Rule [ns-ny:/EDDS1460850:EDDS1460850_migration]: Migration of file

    [/Temp/365ddfbe-397d-4160-9e18-06ce2bb4b1f4018d.tif] from share

    [nyccm44-EDDS1460850-1$] to share [n1-EDDS1460850$] failed. Attempt [3]

    encountered an error [The DME was unable to complete a CIFS transfer request

    [-217] (STATUS_INVALID_PARAMETER from target)]. Maximum number of attempts is

    set to [3]. File could not be migrated within the maximum attempts allowed.

  • When reviewing a packet capture, you see a "STATUS_INVALID_PARAMETER" error returned from the filer.

Workaround

To work around this issue, you must uncompress the files identified for migration. For more information about removing file compression, please refer to Microsoft Support for assistance.

Impact of workaround: Files will no longer be compressed and may impact storage requirements.
