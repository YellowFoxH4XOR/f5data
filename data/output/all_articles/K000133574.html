Description

The dag-adjustment VLAN setting allows BIG-IP tenants running on VELOS or r5000/r10000/r12000-DS series appliances to fine-tune the DAG hash algorithm for ingress traffic. Previous F5 platforms could tune the DAG calculation using one of these sys db variables (depending on the platform):

  • mhdag.pu.table.size.multiplier
  • dagv2.pu.table.size.multiplier

However, on VELOS and r5000/r10000/r12000-DS series appliances, the equivalent functionality is achieved using the dag-adjustment VLAN setting. There are four possible values:

  • None
  • Bit roll
  • Xor 5 Mid, Xor 5 Low (default)
  • Nibble roll

The dag-adjustment setting was introduced via ID1088037. Prior to this, BIG-IP tenants on VELOS and r5000/r10000/r12000-DS series appliances could not tune the DAG hash algorithm. This resulted in an uneven distribution of traffic among BIG-IP tenant TMMs in environments where hosts favored even-numbered source ports when opening new connections. The new dag-adjustment VLAN setting with its default value of xor-5mid-xor-5low resolves this issue.

Environment

The dag-adjustment VLAN setting is present in the following TMOS versions:

  • 15.1.8 or above.
  • 17.1.0 or above.

Cause

The dag-adjustment setting takes effect only in BIG-IP tenants running on VELOS or r5000/r10000/r12000-DS series appliances. If you attempt to change the dag-adjustment on a platform that does not support it, the setting is ignored and a warning is shown:

  01071e17:3: DAG adjustment is not supported on this platform.

Recommended Actions

The default setting, Xor 5 Mid, Xor 5 Low(xor-5mid-xor-5low), typically provides even distribution of ingress traffic for most scenarios. If there are application environments that favor even/odd-numbered source ports or where another port stride is present, which caused prominent distribution bias between TMM cores, you may consider using other dag adjustment options such as Bit roll(bit-roll) or Nibble roll(nibble-roll).

In case you need to check whether you'd have such an imbalance distribution issue among TMMs, you may follow the K91433389: Analyze and troubleshoot traffic distribution across data plane cores in BIG-IP systems. Additionally, the below command could give an output showing how many number of packets are fowarded to each of the data processing cpus(TMMs) on r5/r10k platforms.

Note: This command is supposed to be executed on F5OS Bash CLI. The stats are accumulative since the start of the tenant, you may need to restart the tmm or reboot the tenant to reset the stats from zero, otherwise, it is required to calculate the delta to get valid distribution data between two turn run of this command.

Additional Information

The dag-adjustment setting is not to be confused with the cmp-hash VLAN setting. The cmp-hash setting selects the fields in the packet header to be used for the DAG hash. The default cmp-hash setting uses the L4 source and destination ports in the header of ingress packets for the DAG hash.

The dag-adjustment does not change which packet header fields that are used, but instead tunes the way the hash is calculated.
