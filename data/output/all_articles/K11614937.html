Description

You cannot access a recently created or modified Virtual Server.

When capturing Virtual Server traffic you see TCP resets with reset cause: [F5RST: TCP retransmit timeout].

We are not getting a response from the backend server (pool member) as shown on below packet capture example:

Server side traffic (BIG-IP to pool member):

10.10.10.1 → 10.10.10.80   41040   22  TCP OUT s1/tmm1 : 41040 → 22 [SYN]
10.10.10.1 → 10.10.10.80   41040   22  TCP OUT s1/tmm1 : [TCP Retransmission] 41040 → 22 [SYN]
10.10.10.1 → 10.10.10.80   41040   22  TCP OUT s1/tmm1 : [TCP Retransmission] 41040 → 22 [SYN]
10.10.10.1 → 10.10.10.80   41040   22  TCP OUT s1/tmm1 : [TCP Retransmission] 41040 → 22 [SYN]
10.10.10.1 → 10.10.10.80   41040   22  TCP OUT s1/tmm1 : 41040 → 22 [RST, ACK] [F5RST: TCP retransmit timeout]

Environment

  • Virtual Server with Source Address Translation set to None
  • Pools
  • Establishing connections

Cause

This RST cause shows when the BIG-IP has resent the data segment to the affected TCP connection the maximum number of times (in this case 3 SYN Retransmissions with no response from server side).

However, the backend server might not respond for a number of reasons, in this case, is due to asymmetric routing, since the Virtual Server does not have Source Address Translation option enabled, the traffic from backend server to BIG-IP is being routed elsewhere and never reaching the BIG-IP, hence why the BIG-IP closes the connection with a RST [F5RST: TCP retransmit timeout].

The other reason can be firewall sitting between F5 and backend server. It may have a rule blocking traffic originated from Self-IP. This means SYN packets that BIG-IP sends may never reach the backend server which also have the same result in packet capture - RST [F5RST: TCP retransmit timeout].

Recommended Actions

1. Set the Source Address Translation option on the Virtual Server to Automap or SNAT pool.  This way the traffic originated to the server will use a Self-IP reachable by the server, and the return traffic will be obligated to pass through the BIG-IP.

2. Check if traffic from BIG-IP flows through firewall and if the firewall allows the traffic from Self-IP.

Additional Information

If the traffic passing through the Virtual Server is SSH traffic (port 22), the error seen on client side might be similar to:

ssh_exchange_identification: read: Connection reset by peer
