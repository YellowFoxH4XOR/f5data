Description

When capturing a pcap on the BIG-IP, sometimes the order in which the frames in the pcap are recorded by tcpdump is not in the exact order of time.

Environment

  • BIG-IP
  • Packet Capture
  • Wireshark Analysis 

Cause

Each tmm sends it's traffic to tcpdump for aggregation, and sometimes the order in which the frames are written to file is not the same order as they were received or sent (although the frame timestamps should still be correct generally).

You can click the time column in Wireshark to reorder frames by time, but the wireshark analyser still treats frames in the order they were recorded rather than by timestamp. This leads to a lot of false wireshark flags/alerts when analysing a pcap, and renders the wireshark built-in protocol analyser unreliable.

Recommended Actions

Download 'reordercap' utility bundled with Wireshark. 

sample usage to reorder capture:

# reordercap [options] <infile> <outfile>

This will reorder the captured frames in a pcap by timestamp value, and wireshark's analysis should be accurate once again.
