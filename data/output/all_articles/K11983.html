K11983: Deleting an HTTP class while the Deployment Wizard is running may prevent later instances of the Deployment Wizard from running

Known Issue

This is the result of a known issue. If a user runs the Deployment Wizard for a web application and then deletes the HTTP class associated with that web application while the Deployment Wizard is running, the user's attempts to run another instance of the Deployment Wizard will fail and the Configuration utility displays an error message that appears similar to the following example:

Cannot complete operation because Deployment Wizard is already running

F5 Product Development tracked this issue as ID 226298 and ID 328794 (formerly CR141169) and it was fixed in BIG-IP ASM 10.2.1. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K10025: Managing F5 Networks product hotfixes for BIG-IP version 10.x systems.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

Workaround

If you are experiencing this issue and are unable to run the Deployment Wizard, perform the following procedure:

  1. Log in to the command line.
  2. Log in to the MySQL database by typing the following command:

    mysql -uroot -p`perl -I/ts/packages -MF5::GenUtils -e 'print get_mysql_password().qq{\n}'`
  3. Display the policy names (domain_name) and corresponding account IDs (account_id) by entering the following MySQL command:

    select account_id,domain_name from DCC.ACCOUNTS;

    Output that appears similar to the following example is displayed: 
    +------------+----------------+| account_id | domain_name    || +----------+----------------+        |    17      | ASM_QA_HTTP    |  |     8      | NMBlogging     |  |     5      | ASM_abc        |  |     2      | ASM_123        |  +------------+----------------+
  4. Locate the account ID for the policy in which the HTTP class was removed.
  5. Delete the Deployment Wizard instance by using the following command syntax:

    DELETE FROM WIZ.WIZ_DEPLOYMENT_STATUS WHERE account_id='$account_id'

    For example, to delete the Deployment Wizard instance for the ASM_123 policy, you would enter the following command:

    DELETE FROM WIZ.WIZ_DEPLOYMENT_STATUS WHERE account_id='2';

You can now attempt to run the Deployment Wizard.
