Topic

You should consider using this procedure under the following condition:

  • You want to create multiple BIG-IP device groups using F5 Modules for Ansible.

Description

Ansible automates and manages multi-machine configuration and deployment. You use F5 Modules for Ansible to create, edit, update, and delete configuration objects on BIG-IP 12.0 and later, and BIG-IQ 5.4.0 and later.

Learn to set up multiple BIG-IP device groups using F5 Modules for Ansible by referencing the following example playbook as you step through the procedures that describe how to create it.

Example playbook

---
- name: Set up device groups on multiple hosts
  hosts: bigips
  gather_facts: False
  connection: local
  serial: 2
  vars:
    provider:
      password: "{{ bigip_password }}"
      server: "{{ ansible_host }}"
      user: "{{ bigip_username }}"
      validate_certs: False

  tasks:
    - name: Collect bigip facts
      bigip_device_facts:
        gather_subset: self-ips
        provider: "{{ provider }}"
      register: self_ips

    - name: Configure device connectivity
      bigip_device_connectivity:
        config_sync_ip: "{{ (self_ips | json_query('self_ips[?floating==`no`]') | selectattr('address', 'search', '192.168.1') | list | first).address }}"
        provider: "{{ provider }}"
        unicast_failover:
         - address: "{{ (self_ips | json_query('self_ips[?floating==`no`]') | selectattr('address', 'search', '192.168.1') | list | first).address }}"

    - name: Add trust for all peer devices in play batch
      bigip_device_trust:
        peer_server: "{{ hostvars[item].ansible_host }}"
        peer_hostname: "{{ item }}"
        peer_user: "{{ hostvars[item].bigip_username }}"
        peer_password: "{{ hostvars[item].bigip_password }}"
        provider: "{{ provider }}"
      run_once: True
      loop: "{{ ansible_play_batch }}"
      notify:
        - Sync configuration from device to group
        - Save the running configuration to disk

    - name: Create device group
      bigip_device_group:
        name: superlative_group
        provider: "{{ provider }}"
        state: present
        type: sync-failover
      run_once: True

    - name: Add the hosts in the play batch to device group
      bigip_device_group_member:
        device_group: superlative_group
        name: "{{ item }}"
        provider: "{{ provider }}"
        state: present
      loop: "{{ ansible_play_batch }}"
      run_once: True

  handlers:
    - name: Save the running configuration to disk
      bigip_config:
        provider: "{{ provider }}"
        save: yes

    - name: Sync configuration from device to group
      bigip_configsync_action:
        device_group: superlative_group
        provider: "{{ provider }}"
        sync_device_to_group: yes
 

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have read the User's Guide on F5 Modules for Ansible.
  • You installed Ansible 2.7 or later on the control machine.
  • You installed BIG-IP 12.x or later on the devices in your device group.
  • You installed the Python packages required for each module and filter you want to use on the control machine. For example, the F5 Modules require the f5-sdk package and the JSON Query filter requires the jmespath package. For more information, refer to the Module Index in the Ansible User Guide.

Procedures

Learn to set up multiple BIG-IP device groups using F5 Modules for Ansible by performing the following steps from the example playbook:

  1. Setting up the hosts file
  2. Creating group variables
  3. Encrypting BIG-IP passwords for the playbook
  4. Creating the playbook
    • Defining play settings
    • Configuring device group connectivity
    • Adding devices to the trust domain in each group
    • Creating BIG-IP device groups
    • Saving the configuration on all hosts
  5. Running the playbook

Setting up the hosts file

To set up the hosts file, do the following:

This step enables you to more easily reference and reorder groups in a playbook, as required in later steps.

  1. Use fully qualified domain names (FQDNs) to list your BIG-IP systems in Ansible groups that correspond to the device groups you want to create.
  2. List the device that you want to be the trust authority for each device group in the first position of each Ansible group.
  3. Create a parent group and put your groups in it, making them child groups of the parent group.

For example, you create the following hosts file:

[bigips:children]
14_dg
13_dg
12_dg

[14_dg]
bigip01.example.net ansible_host=10.154.210.207
bigip02.example.net ansible_host=10.154.210.213

[13_dg]
bigip03.example.net ansible_host=10.154.210.208
bigip04.example.net ansible_host=10.154.210.206

[12_dg]
bigip05.example.net ansible_host=10.154.210.212
bigip06.example.net ansible_host=10.154.210.204
 

Creating group variables

  • Create group variables for the parent and child groups in separate variable files.

For example, you create the following directory tree, and place the bigip_username and bigip_password group variables in the vars.yml files:
Note: In the example playbook the devices to be added to the device group have the same username and the same password.

+-- group_vars
¦   +-- 12_dg
¦   ¦   +-- vars.yml
¦   ¦   +-- vault.yml
¦   +-- 13_dg
¦   ¦   +-- vars.yml
¦   ¦   +-- vault.yml
¦   +-- 14_dg
¦   ¦   +-- vars.yml
¦   ¦   +-- vault.yml
 

Encrypting BIG-IP passwords for the playbook

  • Encrypt BIG-IP passwords for the playbook by placing them in the vault. For more information, refer to K64450989: Using the 'ansible-vault' command to encrypt BIG-IP passwords used in a playbook

Creating the playbook

Defining play settings

To configure the play settings in your playbook, do the following:

  1. Define the hosts for the play. Following the previous example, the value for hosts is the bigips group of groups.
  2. Include the connection: local directive if all tasks are F5 Modules for Ansible as is shown in the example playbook. For more information, refer to the Connection or delegation chapter of the F5 Modules for Ansible User Guide.
  3. Create a playbook variable called provider using the var keyword. Add the BIG-IP connection details with your group variables you defined in the Creating group variables procedure as the values to the provider variable. You can then reference the provider variable in the provider parameter in each BIG-IP module.
  4. By default, Ansible manages all of the machines referenced in a play in parallel. However, you can define the number of hosts Ansible manages at a single time using the serial keyword. This keyword enables Ansible to divide your hosts into batches and run each play on each batch. Each batch contains the number of hosts that you specify after the keyword. By default, Ansible creates batches using hosts in the order in which they appear in the hosts file. To define a batch, use the serial play keyword.

    In the example, 2 specifies that Ansible will divide the hosts in batches of two in the order in which they are listed, which results in the first batch consisting of the hosts in 14_dg;  the next batch is the hosts in 13_dg, and so on. If you have groups of three devices you can specify 3 as the value of serial or, for example, if you have a group of three devices listed first in your inventory followed by any number of groups with two devices, you can specify a list as the value:
    serial:
      - 3
      - 2

    Defining batches enables the play in the example playbook to run separately on each batch (device group), instead of running on all the hosts in bigips at one time. Consequently, the F5 bigip_device_trust and bigip_group_member modules can run on each device group separately, instead of all the hosts in the play at one time. You use Ansible's magic variable, ansible_play_batch, to reference the list of hostnames for the current batch.

The following is the play settings section from the previously listed example playbook showing all the elements discussed in this procedure:

Note: In the following example, F5 assumes that the server parameter value is ansible_host. You can also use inventory_hostname for this parameter if it is an FQDN and the control machine can resolve it.

---
- name: Set up device groups on multiple hosts
  hosts: bigips
  gather_facts: False
  connection: local
  serial: 2
  vars:
    provider:
      password: "{{ bigip_password }}"
      server: "{{ ansible_host }}"
      user: "{{ bigip_username }}"
      validate_certs: False
 

Configuring device group connectivity

It is common practice to use a dedicated VLAN and subnet to configure device group connectivity. In Ansible, you can automate this process. For example, you can use a conditional statement that only connects devices with self IPs that start with a specific network ID.

To configure device group connectivity, do the following:

  1. Create a task that uses the F5 bigip_device_facts module to gather the self-ip subset from the devices in each batch. Register the gathered facts returned as self_ips in a variable also called self_ips.

    Note: the fact subset is called self-ip; however the list of key/value pairs it returns is called self_ips.

  2. Create a task that uses the F5 bigip_device_connectivity module and a conditional statement to configure the devices in each batch for connectivity.
  3. Optional: To see the self IP that matches the filter criteria, you can add the following task to the playbook:

    - debug: msg="{{ (self_ips | json_query('self_ips[?floating==`no`]') | selectattr('address', 'search', '192.168.1') | list | first).address }}"

For example, the following two tasks from the example playbook set up the configuration synchronization IP and unicast failover IP of each device with a self IP starting with the 192.168.1 network ID. The json_query filter finds non-floating self IP addresses while the selectattr filter searches for an address starting with 192.168.1. The first filter returns the first self IP address that matches the criteria so only a single IP address is provided for each address in the bigip_device_connectivity module.

    - name: Collect bigip facts
      bigip_device_facts:
        gather_subset: self-ips
        provider: "{{ provider }}"
      register: self_ips

    - name: Configure device connectivity
      bigip_device_connectivity:
        config_sync_ip: "{{ (self_ips | json_query('self_ips[?floating==`no`]') | selectattr('address', 'search', '192.168.1') | list | first).address }}"
        provider: "{{ provider }}"
        unicast_failover:
         - address: "{{ (self_ips | json_query('self_ips[?floating==`no`]') | selectattr('address', 'search', '192.168.1') | list | first).address }}"

Adding devices to the trust domain in each group

The F5 bigip_device_trust module only needs to run on a single host in each batch to create device trust for the device group because:

  • Ansible executes tasks from first to last; therefore, it runs on the first host in your group.
  • You placed the device you want to be the trust authority in the first position of each group in the hosts file.
  • The task uses the ansible_play_batch variable to add the other hosts to the trust domain.

Because you only need to run the task once, y???ou use the run_once directive.

To add devices to the trust domain in each group:

  1. Create a task that uses the F5 bigip_device_trust module to add the first device in each batch to the trust domain.
  2. Use the ansible_play_batch and hostvars variables to add the other hosts to the device trust domain.
  3. Use the run_once directive to run the task one time.
  4. Include Notify statements in the bigip_device_trust module to notify handlers to run at the end of the play.

    You create the handlers as your final step in creating the playbook.

For example, the following task from the example playbook adds devices to the trust domain in each group:

    - name: Add trust for all peer devices in play batch
      bigip_device_trust:
        peer_server: "{{ hostvars[item].ansible_host }}"
        peer_hostname: "{{ item }}"
        peer_user: "{{ hostvars[item].bigip_username }}"
        peer_password: "{{ hostvars[item].bigip_password }}"
        provider: "{{ provider }}"
      run_once: True
      loop: "{{ ansible_play_batch }}"
      notify:
        - Sync configuration from device to group
        - Save the running configuration to disk
     

Creating BIG-IP device groups

You can create a BIG-IP device group object on just one host in each batch using the F5 bigip_device_group module. Then, you use the ansible_play_batch variable and F5 bigip_device_group_member module to loop through the list of hostnames in each batch and add them to the group.

To create a BIG-IP device group:

  1. Create a task that uses the F5 bigip_device_group module to create a BIG-IP device group in each batch.
  2. Use the run_once directive in the task to create the device group on one host.
  3. Create a task that uses the ansible_play_batch variable and the F5 bigip_device_group_member module to add the hosts in each batch to the device group.
  4. Use the run_once directive in the task to run the task one time.

For example, the following two tasks from the example playbook create BIG-IP device groups for each batch of hosts:

    - name: Create device group
      bigip_device_group:
        name: superlative_group
        provider: "{{ provider }}"
        state: present
        type: sync-failover
      run_once: True

    - name: Add the hosts in the play batch to device group
      bigip_device_group_member:
        device_group: superlative_group
        name: "{{ item }}"
        provider: "{{ provider }}"
        state: present
      loop: "{{ ansible_play_batch }}"
      run_once: True

Saving the configuration on all hosts

To save the configuration on all hosts, do the following:

  1. Create a task (handler) that uses the F5 bigip_config module to save the running configuration on the first host to disk.
  2. Create a task (handler) that uses the F5 bigip_configsync_action module to push the configuration synchronization from the first host to the other devices in each batch and complete the initial synchronization.

Note: If you provisioned BIG-IP ASM on your BIG-IP system, the system may display an error similar to the following example:

RUNNING HANDLER [Sync configuration from device to group] *******************************************************************************************************************************
fatal: [bigip01.example.net -> localhost]: FAILED! => {"changed": false, "msg": "Recommended action: Synchronize bigip01.example.net to group datasync-global-dg"}

This error occurs because:

  • The BIG-IP ASM system includes a datasync-global-dg device group.
  • The datasync-global-dg device group requires an initial synchronization after Ansible runs the bigip_configsync_action module.

However, you can safely ignore this error because the bigip_configsync_action module still synchronizes the target group (superlative_group in the example below) and the error has no effect. In Ansible, when a task fails on a host, it removes the host from future tasks. Since this is the last task, removing the host has no effect.

For example, the following two handler tasks from the example playbook save the running configuration on the first host in each group to disk and push that configuration to the remaining devices in each group:

    - name: Save the running configuration to disk
      bigip_config:
        provider: "{{ provider }}"
        save: yes

    - name: Sync configuration from device to group
      bigip_configsync_action:
        device_group: superlative_group
        provider: "{{ provider }}"
        sync_device_to_group: yes
