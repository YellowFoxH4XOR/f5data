Known Issue

An outbound Internet Content Adaptation Protocol (ICAP) request can double-chunk an HTTP payload (that is, have extra chunk headers inserted within the body chunks).

This issue occurs when the following condition is met:

  • A primary virtual server has an HTTP profile and has either request-adapt or response-adapt profiles and a corresponding internal virtual server with an ICAP profile.

    The outbound ICAP request payload might be double-chunked if any of the following is true:

    • The primary virtual server has a request-adapt profile and either of the following is true:
      • The HTTP client sends a POST request with a chunked payload, and the HTTP profile has the request chunking mode preserve configured (which is the default).
      • The HTTP client sends a POST request with a chunked payload, and the HTTP profile has the request chunking mode selective configured (unless certain other HTTP-related profiles are present on the HTTP virtual server).
    • The primary virtual server has a response-adapt profile, and the ICAP server responds with a body (200 OK) response.
    • The HTTP server responds with a chunked payload, and the HTTP profile has the response chunking mode preserve configured.

Impact

The ICAP server receives a corrupt payload and might malfunction or return a corrupt payload to the receiving client or server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • An outbound ICAP request body is double-chunked (has extra chunk headers inserted within the body chunks).
  • The ICAP payload data becomes corrupted.
