Description

A new virtual server was created, but does not respond to TCP SYNs when testing.

Deleted and re-created the virtual server, but the issue persists. Traffic appears to be dropped.

Environment

  • Virtual server
  • AFM provisioned

Cause

AFM is configured in firewall (default deny) mode, and there is no rule configured to accept the traffic.

sys db tm.fw.defaultaction {
    default-value "accept"
    scf-config "true"
    value "drop"                <---
    value-range "accept drop reject"
}

Recommended Actions

Configure a rule in a firewall policy to allow the traffic. Apply the policy to a context.

The action defined in sys db tm.fw.defaultaction only applies if no policy matches the traffic.

Additional Information

AFM's Packet Tester may be used to validate if traffic matches a configured rule.
