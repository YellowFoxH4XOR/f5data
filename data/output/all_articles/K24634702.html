Known Issue

Geolocation upgrade files do not replicate on secondary blades.

This issue occurs when all of the following conditions are met:

  • You have multi-blade VIPRION platforms/Virtual Clustered Multiprocessing (vCMP) guests with BIG-IP 12.1.2 or later.
  • You attempt to upgrade geolocation files.

Impact

The GeoIP database does not update accordingly with the primary blade GeoIP database.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The geolocation upgrade files fail to replicate on the secondary blades.

Workaround

To work around this issue, you can update the GeoIP database on the secondary blades by performing one of the following procedures:

  • Manually creating the GeoIP directory on the secondary blades
  • Editing the csyncd.conf file, restarting csyncd.conf, and running the geoip_update_data command

Impact of workarounds: Performing the following procedures should not have a negative impact on your system. However, F5 recommends performing the procedures during a maintenance window to prevent traffic disruption.

Manually creating the GeoIP directory on the secondary blades

  1. Log in to the command line using the root account of each secondary blade.
  2. To create the /shared/GeoIP/v2 directory, type the following command:

    mkdir /shared/GeoIP/v2

  3. Log in to the primary blade and type the following command for each geolocation file:

    geoip_update_data -f -v </path to RPM file and file name>

    For example:

    geoip_update_data -f -v /var/tmp/geoip-data-v2-Region2-2.0.0-20171204.291.0.i686.rpm
    geoip_update_data -f -v /var/tmp/geoip-data-v2-ISP-2.0.0-20171204.291.0.i686.rpm
    geoip_update_data -f -v /var/tmp/geoip-data-v2-Org-2.0.0-20171204.291.0.i686.rpm

Editing the csyncd.conf file, restarting csyncd.conf, and running the geoip_update_data command

  1. Log in to the command line of the primary blade.
  2. Edit the /etc/csyncd.conf file.
  3. Locate the following two terms:

    monitor dir /shared/GeoIP {...)
    monitor dir /shared/GeoIP/v2 {...}

    Into one term:

    monitor dir /shared/GeoIP {
            queue geoip
            pull pri2sec
            recurse yes
            defer no
            lnksync yes
            md5 no
            post "/usr/local/bin/geoip_reload_data"
    }

  4. Save the changes.
  5. To restart the csyncd.conf file, type the following command:

    bigstart restart csyncd

  6. To update the GeoIP data, type the following command:

    geoip_update_data -f -v </path to RPM file and file name>

    For example:

    geoip_update_data -f -v /var/tmp/geoip-data-v2-Region2-2.0.0-20171204.291.0.i686.rpm
    geoip_update_data -f -v /var/tmp/geoip-data-v2-ISP-2.0.0-20171204.291.0.i686.rpm
    geoip_update_data -f -v /var/tmp/geoip-data-v2-Org-2.0.0-20171204.291.0.i686.rpm
