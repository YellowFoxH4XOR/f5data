Policy Information

The new behavior described in this article is the standard behavior for the subsequent major branch. There will be no further updates unless new information is discovered.

The BIG-IP Link Controller and BIG-IP GTM link cost-based and inbound link path-based load balancing features have reached End of Life (EoL).

  • Existing customers within the United States who used these EoL load balancing features prior to January 26, 2016, may be eligible to re-enable the functionality. Contact F5 Support to open a case and determine eligibility for acquiring a software patch.
  • Existing customers outside of the United States should contact F5 Support and open a case to activate this patch if needed.

This patch applies to the following versions of BIG-IP: BIG-IP DNS 12.0.0 and later; BIG-IP Link Controller 11.6.0 HF3, 11.5.1 HF6, or 11.4.1 HF6 and later; and BIG-IP GTM 11.6.0 HF3, 11.5.1 HF6, 11.4.1 HF6 and later.

These notices are subject to change.

Old behavior

In versions prior to BIG-IP Link Controller and BIG-IP GTM 11.6.0 HF3 for the 11.6.x software branch, 11.5.1 HF6 for the 11.5.x software branch, and 11.4.1 HF6 for the 11.4.x software branch link selection can be based on link cost, and can be configured as follows:

  • BIG-IP GTM systems are configured as follows:
    • The wide IP references a pool using the following configuration:
      • The load balancing method is set to Quality of Service.
      • The Link Capacity (under Quality of Service Weights) is set to a non-zero value.
      • The Dynamic Ratio setting is enabled (checked).
    • The Weighting setting for the link is configured for Price (Dynamic Ratio).
  • BIG-IP Link Controller systems are configured as follows:
    • The inbound wide IP uses the following configuration:
      • The load balancing method is set to Quality of Service.
      • The Link Capacity (under Quality of Service Weights) is set to a non-zero value.
      • The Dynamic Ratio setting is enabled (checked).
    • The Weighting setting for the link is configured for Price (Dynamic Ratio).
  • For BIG-IP LTM systems (with a Link Controller or GTM license), the pool load balancing method is using a Dynamic Ratio load balancing method.

When the GTM pool or Link Controller wide IP load balancing method is set to Round Trip Time, Hops, or Completion Rate or set to Quality of Service with Quality of Service Weights set for Round Trip Time, Hops and/or Completion Rate, the system uses the performance metrics collected by big3d when making load balancing decisions for each link in a data center.

New behavior

Beginning in BIG-IP DNS 12.0.0, BIG-IP Link Controller and BIG-IP GTM 11.6.0 HF3, 11.5.1 HF6, and 11.4.1 HF6, cost-based link selection and inbound path-based link selection have reached EoL. If you configure these load balancing methods for BIG-IP DNS, BIG-IP Link Controller, and BIG-IP GTM in these versions, you will experience the following:

  • If the link Weighting option is set to Price (Dynamic Ratio), the system will not perform load balancing according to price, unless the appropriate patch is installed.
  • For BIG-IP DNS and GTM pools or Link Controller wide IP load balancing using a Quality of Service pool load balancing method, the system sets the dynamic ratio to the static Link Ratio for the link.
  • For local traffic pool load balancing based on dynamic-ratio, the dynamic ratio will be set to the static Link Ratio.
  • For BIG-IP DNS and GTM pools or Link Controller wide IPs that utilize a load balancing method of Round Trip Time, Hops, or Completion Rate or a load balancing method of Quality of Service with non-zero Quality of Service Weights for Round Trip Time, Hops and/or Completion Rate, only the score for one link in each data center will be used unless the appropriate patch installed.
  • The tmsh show gtm pool members command indicates that the pool member status is unlicensed and Not Authorized as shown in the following command output:

    -----------------------------------------------------------------
    | Gtm::Pool Member: pool_member1
    -----------------------------------------------------------------
    | Status
    | Availability : unlicensed
    | State : enabled
    | Reason : Not Authorized
    |

Procedure

Once you have acquired the software patch from F5 Support, complete the following procedure to apply the patch.

Impact of procedure: The BIG-IP system is unable to process traffic while the unit is rebooting.

  1. Copy the patch to the /var/tmp/ directory on the BIG-IP system.
  2. Log in to the BIG-IP command line.
  3. Change directories to the /var/tmp/ directory by entering the following command:

    cd /var/tmp/

  4. Install the patch by entering the following command:

    im /var/tmp/linkcost.im

    Note: For VIPRION systems, you must run the im command on each individual blade in the VIPRION chassis.

  5. Enable the gtm.loadlinkcost database variable by entering the following command:

    tmsh modify /sys db gtm.loadlinkcost value enable

    Note: For VIPRION systems, you must perform this step from the primary blade in the VIPRION chassis.

Note: When installing linkcost.so, you may see the following error message: DB_VERSION_MISMATCH: Database environment version mismatch. If this occurs, follow the workaround in Bug ID 770989 in F5 Bug Tracker.

Post-patch installation considerations

After installing the linkcost patch, you should be aware of the following maintenance considerations:

  • The patch and database variable setting persist through BIG-IP software upgrades and hotfix installations.
  • If you replace an appliance or VIPRION blade (due to RMA or for some other reason), you will need to perform the following tasks to enable these features on the new unit:
    • Reapply the patch by running the im command.

      For example:

      im /var/tmp/linkcost.im

      Note: For VIPRION systems, you only need to run the im command on the replacement blade.

    • After reapplying the patch, run the following commands:

      tmsh modify /sys db gtm.loadlinkcost value disable

      tmsh modify /sys db gtm.loadlinkcost value enable

      Note: For VIPRION systems, you must perform this step from the primary blade in the VIPRION chassis.

      Note: You can alternatively reboot the unit or replacement blade to enable the patch.

  • If you add a new blade to your VIPRION chassis, you will need to perform the following tasks to reapply the patch on the new blade:
    • Reapply the patch by running the im command on the new blade.

      For example:

      im /var/tmp/linkcost.im

    • After reapplying the patch, run the following commands on the primary blade in the VIPRION chassis:

      tmsh modify /sys db gtm.loadlinkcost value disable

      tmsh modify /sys db gtm.loadlinkcost value enable

      Note: You can alternatively reboot the replacement blade to enable the patch.
