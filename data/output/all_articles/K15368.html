Topic

The BIG-IP AFM system logs network firewall events using the logging profile associated with the network firewall rule.

Description

You can configure the BIG-IP AFM system to log network firewall events using the following two components:

  • The Logging setting for a network firewall rule.

    When you configure a network firewall rule, you can either enable or disable logging by configuring its Logging setting. When enabled, the BIG-IP AFM system sends the details of an event that matches this rule to the associated logging profile for further processing.

  • The logging profile.

    The logging profile controls how the system handles logging. You can configure the logging profile to send logs either locally or remotely. You can configure the logging profile to log only certain types of rule matches, for example, to log only traffic that the system rejects by using a rule. You can also configure the logging profile to log certain types of errors, for example, to log traffic containing TCP errors.

Understanding the association between the logging profile and the network firewall rule context

A network firewall rule is applied to objects in the following context:

  • Global
  • Route domain
  • Virtual server
  • Self IP
  • Management port

By default, all network firewall rules that the system applies to objects in the global, route domain, self IP, and management port contexts are associated with the default global-network logging profile. However, by default, the global-network logging profile is configured to perform no logging. You can configure the global-network logging profile to perform network firewall event logging by setting the appropriate log publisher and the logging rules.

When the system applies a network firewall rule to an object in the virtual server context, if the virtual server object is configured with a logging profile, the associated logging profile takes precedence over the global-network logging profile. If the virtual server object is not configured with a logging profile, the global-network logging profile handles the logging for the virtual server network firewall rule.

This behavior also applies to network firewall rules in a Network Firewall Rule list, as well as a network firewall policy (introduced in BIG-IP AFM 11.4.0).

Recommendations

When configuring a network firewall rule to log events, you should consider the following factors:

  • Ensure that each individual rule has its Logging setting set to Enabled.
  • Ensure that the object to which you apply the network firewall has an appropriately configured logging profile. Virtual server objects have a logging profile assigned. For objects in the global, route domain, self IP, and management port context, you must appropriately configure the global-network logging profile. For more information, refer to the guides listed in the Supplemental Information section of this article.
  • When you configure a logging profile, ensure that you log the event logs to the local MySQL database to use the local-db-publisher log publisher. Also ensure that you can view these event logs in the Configuration utility (navigate to Security > Event Logs > Network > Firewall). If you configure a logging profile to use the local-syslog-publisher log publisher, the system logs the event logs to the /var/log/ltm file, and you cannot view them in the Configuration utility.
  • If you expect a vast amount of network firewall event logs, F5 recommends that you consider logging the event logs remotely to prevent logging from consuming resources on the BIG-IP AFM system. For more information, refer to the guides listed in the Supplemental Information section of this article.

By default, the system does not log implicit default firewall actions unless configured to do so. For example, when you are troubleshooting a flow dropped by the default rule, the system does not generate drop log messages.

To turn on logging for implicit firewall actions using the TMOS Shell (tmsh) at the command line, perform the following procedure:

Impact of procedure: When you are troubleshooting dropped traffic, it may be helpful to turn on logging for these actions; however, when you log these actions during normal operation, the system may create an unnecessary amount of logging.

  1. Log into tmsh by typing the following command:

    tmsh

  2. Enable logging for implicit firewall actions by typing the following commands:

    modify /sys db tm.fw.defaultrule.log value enable
    modify /sys db tm.fw.stageddefaultrule.log value enable
    modify /sys db tm.fw.globaldefaultrule.log value enable
    modify /sys db tm.fw.stagedglobaldefaultrule.log value enable

To turn off logging for implicit firewall actions using tmsh at the command line, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into tmsh by typing the following command:

    tmsh

  2. Disable logging for implicit firewall actions by typing the following commands:

    modify /sys db tm.fw.defaultrule.log value disable
    modify /sys db tm.fw.stageddefaultrule.log value disable
    modify /sys db tm.fw.globaldefaultrule.log value disable
    modify /sys db tm.fw.stagedglobaldefaultrule.log value disable
