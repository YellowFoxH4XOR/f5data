Known Issue

If you create wildcard URLs without specifying the wildcard order, the system may not enforce the wildcard URLs.

This issue occurs when all of the following conditions are met:

  • You use the REST interface to add multiple wildcard URLs to the Wildcard URLs List of a security policy in a single transaction, without specifying a unique Wildcards Order value for each wildcard URL.
  • You apply the updated security policy.
  • The BIG-IP ASM security policy processes traffic that matches the newly created wildcard URLs.

Impact

The system does not enforce all of the wildcard URLs.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view the URL enforcement of wildcard URLs that have the same wild card order value, only one of the URLs is enforced.
  • Requests to access a URL that matches one of the configured wildcard URLs triggers a violation (when the security policy is configured for blocking the request).

Workaround

To work around this issue, when you use the REST interface to configure multiple wildcard URLs, you can specify a unique Wildcards Order value (for example, wildcardOrder=3) for each wildcard URL entry.

Impact of workaround:  Performing the suggested workaround should not have a negative impact on your system.
