Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K15720: Certain tasks related to the management of SSL certificates do not support encrypted private keys (11.x - 12.x)

The following tasks, related to the management of Secure Sockets Layer (SSL) certificates, do not support encrypted private keys (private keys protected with a passphrase):

  • SSL certificate renewal using the Configuration utility
  • Key conversion to FIPS

When the private key is encrypted, these tasks will fail and return one of the following two error messages, depending on the BIG-IP version you are running:

  • BIG-IP 10.x

    OpenSSL error: error:0906406D:PEM routines:PEM_def_callback:problems getting password

  • BIG-IP 9.x

    Certificate/Key mismatch

Workaround

You can work around this issue by renewing a passphrase-protected SSL certificate from the command line interface and converting an encrypted private key to FIPS by first decrypting it. To do so, perform the following procedures:

Renewing a passphrase-protected SSL certificate

  1. Log in to the BIG-IP system command line.
  2. Create a backup of the configuration by typing the following command:

    bigpipe config save /var/tmp/SOL12454.ucs
  3. To generate a certificate signing request (CSR) file, type the following command:

    openssl x509 -x509toreq -in <certificate file> -signkey <key file> -out <csr file>

    For example:

    openssl x509 -x509toreq -in /config/ssl/ssl.crt/askf5.crt -signkey /config/ssl/ssl.key/askf5.key -out /config/ssl/ssl.csr/askf5.csr
  4. If the certificate is a self-signed certificate, generate the new certificate file by typing the following command:

    openssl x509 -req -in <csr file> -signkey <key file> -days <days of validity> -out <crt file>

    For example:

    openssl x509 -req -in /config/ssl/ssl.csr/askf5.csr -signkey /config/ssl/ssl.key/askf5.key -days 365 -out /config/ssl/ssl.crt/askf5.crt

    If the certificate is not a self-signed certificate, submit the CSR file you generated in the previous step to your Certificate Authority (CA) to obtain the new certificate file.

    Note: In either case, once the expiring SSL certificate has been replaced, the BIG-IP system may not use the new SSL certificate until the configuration is reloaded or the SSL profiles are updated. For more information, refer to K10561: The BIG-IP system may not use a renewed SSL certificate.

Converting an encrypted private key to FIPS

  1. Log in to the BIG-IP system command line.
  2. Create a backup of the configuration by typing the following command:

    bigpipe config save /var/tmp/SOL12454.ucs
  3. To create a decrypted version of the private key, type the following command:

    Note: The command will prompt you to enter the passphrase.

    openssl rsa -in <encrypted private key> -out <decrypted private key>

    For example:

    openssl rsa -in /config/ssl/ssl.key/askf5.key -out /var/tmp/askf5.key
  4. To replace the encrypted private key with the decrypted private key, type the following command:

    mv <decrypted private key> <encrypted private key>

    For example:

    mv /var/tmp/askf5.key /config/ssl/ssl.key/askf5.key
  5. Log in to the Configuration utility.
  6. Navigate to Local Traffic > SSL Certificates.
  7. Click the certificate and key pair you need to convert to FIPS.
  8. Click the Key tab.
  9. Click the Convert to FIPS button.
