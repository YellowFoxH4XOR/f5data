K9278: Using the LB::detach iRule command then selecting a new load balancing target may stall the connection

Known Issue

This is the result of a known issue. Using the LB::detach iRule command to disconnect from a server to make another load balancing decision may cause a stalled connection.

If the LB::detach command is called after the TCP three-way handshake to the initially selected server has completed, the original request is passed to the newly selected server as expected. However, if the TCP handshake has not yet completed when LB::detach is called, the original request is lost and the connection may stall.

F5 Networks Product Development tracked this issue as CR107335 and it was fixed in BIG-IP LTM versions 9.4.7 and 10.0.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in BIGIP-10.0.0-5514.0-HF2 for BIG-IP version 10.0.0. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
