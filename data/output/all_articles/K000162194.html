K000162194: BIG-IP may send STARTTLS when backend server HELLO with STARTTLS

Type
Support Solution
Published
2026-08-16
Updated
2026-08-16
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162194

Description

SMTP communication from BIG-IP LTM fails to connect to the configured SMTP server. Symptoms include inability to send emails, misleading "OK" status in the GUI, and packet captures showing incomplete SMTP sessions or errors such as "Invalid domain name." The BIG-IP may attempt to initiate a TLS connection even when "encrypted-connection none" is configured if the backend HELO with STARTTLS

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.3
  • SMTP configuration

Cause

BIG-IP may attempt to initiate a STARTTLS connection even when "encrypted-connection none" is configured if the backend HELO with STARTTLS, leading to failed SMTP communication if the backend server does not support or require TLS. Using an invalid domain name for local-host-name results in SMTP server errors such as "501 5.5.4 Invalid domain name."

Answer/Recommended Actions

  1. Verify SMTP Server Requirements
    • Confirm whether the backend SMTP server requires TLS and/or user authentication.
    • If TLS is required, configure the BIG-IP SMTP server settings to enable encrypted connection and provide necessary credentials.
  2. Check Routing and ARP Records
    • Ensure the management interface (mgmt) is correctly routed to the SMTP server.
    • Validate ARP records to confirm connectivity.
  3. Packet Capture Analysis
    • Use tcpdump to capture traffic on the mgmt interface during SMTP tests.
    • Review captures for evidence of STARTTLS negotiation and session termination.
  4. Hostname Configuration
    • Use a valid FQDN for the local-host-name in the SMTP configuration. Avoid using email addresses or invalid domain names, as this can cause the SMTP server to reject the connection.
  5. GUI Display Issue
    • Be aware that the "OK" status in the GUI may be misleading if the local-host-name is not a valid FQDN. Actual communication may not be completed.
  6. Workaround
    1. Use backend SMTP server that supports TLS, if not then need to check why the backend server HELO with STARTTLS

Additional Information

  • The issue was not observed in BIG-IP versions where no STARTTLS was requested from backend server.
  • The ARP record and routing configuration are critical for successful SMTP communication.
