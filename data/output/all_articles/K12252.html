K12252: Microsoft Active Directory authentication using UPN may fail if the user's UPN suffix does not match the domain suffix

Topic

When using Microsoft Active Directory (AD) authentication using the User Principal Name (UPN), if the user's UPN and the domain name are different, authentication will fail. In addition, users will receive an error message that appears similar to the following example:

The username or password is not correct. Please try again.
(error: Client '<username>\@<domain name>' not found in Kerberos database, principal name: <username>@<domain name>. Please verify Active Directory and DNS configuration.)

For example, if the user's UPN is user1@local.com and the AD domain name is siterequest.com, authentication for this user will fail because local.com is different from siterequest.com. This is expected behavior. The BIG-IP APM AD authentication uses the UPN suffix to resolve domain information.

Workaround

You can work around this behavior by configuring APM to use LDAP authentication instead of AD authentication. The following example illustrates how to configure LDAP authentication to an AD domain controller (DC) using the users UPN. You will need to have a virtual server and any resources you are granting access to defined.

Important: This example is a demonstration of how to configure an LDAP policy. You will need to integrate this into your specific environment.

Creating the LDAP AAA server

  1. Log in to the BIG-IP APM Configuration utility.
  2. Click Access Policy.
  3. Click AAA Servers.
  4. Click Create.
  5. In the Name text box, type a name for your AAA server configuration.

    For example:

    LDAP-AD

  6. From the Type drop-down menu, select LDAP.
  7. In the Host text box, enter the name of your domain controller.

    For example:

    dc1.siterequest.com

    Note: You can also specify the IP address of the server, if you prefer.

  8. In the Admin DN text box, you need to enter the distinguished name of the administrator account you will use to connect to the AD LDAP. A DN looks similar to the following example:

    CN=administrator,CN=Users,DC=siterequest,DC=com

  9. In the Admin Password text box, type the password of the AD administrator account.
  10. In the Verify Admin Password text box, enter the password again.
  11. Click Finished.

Configuring the LDAP authentication access policy

Important: This example is a demonstration of how to configure an LDAP policy. You will need to integrate this into your specific environment.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. Click Create.
  5. In the Name text box, type a name for the access policy.

    LDAP-ap

  6. Click Finished.
  7. On the row that has the Name of your access policy, click the Edit link.

    The visual policy editor (VPE) opens in a new browser window.
  8. Click the + icon on the fallback branch.
  9. In the Authentication section, click the LDAP Auth option button.
  10. Click the Add Item button.

    A pop-up window opens.
  11. From the Server drop-down menu, select the name of the AAA LDAP server created in the last section.

    For example:

    LDAP-AD

  12. In the SearchDN text box, enter the base DN to search from.

    For example:

    DC=siterequest,DC=com

    Note: This is usually the top DN of your domain structure.

  13. In the SearchFilter text box, type the following:

    (UserPrincipalName=%{session.logon.last.username})

  14. Click Save.

    The LDAP Auth action appears in your access policy diagram.
  15. Click the + on the Successful branch.

    A pop-up window opens.
  16. In the General Purpose section, click the Resource Assign option button.

    A pop-up window opens.
  17. Click the Add new entry button.
  18. Click the resource type keyword for the type of resource you want this access policy to assign.

    For example, set Network Access Resource to assign a network access type resource to this policy.
  19. Click the option button for the resource that will be assigned to this access policy.

    For example:

    NetworkAccess_na_res

  20. Click Update.

    The pop-up window closes.
  21. Click Save.

    The pop-up window closes.
  22. At the end of the fallback branch from the Resource Assign action, click the Deny link.

    A pop-up window appears.
  23. Click the Allow option button.
  24. Click Close.

Connecting the access policy to the virtual server

  1. Click Local Traffic.
  2. Click Virtual Servers.
  3. Click the name of the virtual server to which you want to add the LDAP access policy.
  4. In the Access Policy section, on the Access Profile drop-down menu, select the name of the access policy you have created in the last section.
  5. Click Update.

Applying the access policy

  1. Click Access Policy.
  2. Click Access Profiles.
  3. Select the check box next to the name of the access policy created earlier.
  4. Click the Apply Access Policy button.

    The Status flag turns green.
