Topic

You should consider using this procedure under the following condition:

  • You want to monitor configuration changes made to Virtual Clustered Multiprocessing (vCMP) guests using the BIG-IP audit logs.

Description

As a vCMP system administrator, you can create BIG-IP guest instances and then delegate the management of the BIG-IP software within each instance to individual administrators. In some cases, you may need to determine when an individual administrator or service made a configuration change to a vCMP guest instance by reviewing the audit log files on the vCMP host. For example, you may want to determine when a vCMP guest instance was deleted and what user deleted the guest. To review the MCP audit log messages for the vCMP guest configuration changes, refer to the following procedures:

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the BIG-IP advanced shell.

Procedures

Monitoring vCMP guest state transitions using the audit logs

You can monitor vCMP guest state transitions that occur on the system. The BIG-IP logs the following vCMP guest state transitions to the audit log file:

  • Configured causes a guest's hardware resources to be de-allocated.
  • Provisioned allocates resources to the guest.
  • Deployed allocates necessary resources and attempts to boot the guest.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To display log messages indicating that a user changed the requested state of a vCMP guest using the Configuration utility, use the egrep or zgrep commands to search for certain patterns in the /var/log/audit* files similar to the following example:

zgrep -E "client tmui.*vcmp_state" /var/log/audit*

You may observe messages similar to those described in the following table.

Audit messageDescription
01070417:5: AUDIT - client tmui, user admin - transaction #453011-3 - object 0 - modify { vcmp { vcmp_name "Guest1" vcmp_state 0 } } [Status=Command OK]The admin user transitioned the guest to the Configured state. The Configured state causes a guest's hardware resources to be de-allocated. This does not cause the guest's virtual disks to be deleted. Those persist on disk and are re-used when the vCMP guest moves out of the Configured state.
01070417:5: AUDIT - client tmui, user admin - transaction #481095-3 - object 0 - modify { vcmp { vcmp_name "Guest1" vcmp_state 1 } } [Status=Command OK]The admin user transitioned the guest to the Provisioned state: The Provisioned state allocates all necessary resources to the guest, such as CPU cores, virtual disk, and so on. In this state, a guest has hardware resources allocated but no virtual machines (VMs) running. A virtual disk is created and the initial software image is installed. To shut down a guest's virtual BIG-IP system without de-allocating its hardware resources, move the vCMP guest from the Deployed state to the Provisioned state.
01070417:5: AUDIT - client tmui, user admin - transaction #383440-3 - object 0 - modify { vcmp { vcmp_name "Guest1" vcmp_state 2 } } [Status=Command OK]The admin user transitioned the guest to the Deployed state: The Deployed state allocates all necessary resources to the guest, such as CPU cores, virtual disk, and so on. In this state, a guest has hardware resources and should have VMs running. The system tries to launch and keep running any VMs belonging to vCMP guests in the Deployed state. After moving a vCMP guest to the Deployed state, you must wait while the guest boots and becomes accessible. Then, you can log in to the vCMP guest to provision specific BIG-IP modules. A guest can manage traffic in the Deployed state only

Monitoring vCMP guest creation or deletion using the audit logs

The BIG-IP vCMP host logs messages related to vCMP guest creation and deletion to the /var/log/audit file. If you locate a log message that indicates that a guest instance was deleted, you can review the log entry to help determine when the guest was deleted and what user deleted the guest. To review log files related to vCMP guest creation or deletion, refer to the following commands:

Impact of procedure: Performing the suggested actions should not have a negative impact on your system.

To display log messages indicating that a user deleted a vCMP guest instance, use the egrep or zgrep commands to search for certain patterns in the /var/log/audit* files similar to the following example:

zgrep -E "obj_delete.*vcmp" /var/log/audit*

To display log messages indicating that a user created a vCMP guest using the Configuration utility, use the egrep or zgrep commands to search for certain patterns in the /var/log/audit* files similar to the following example:

zgrep -E "tmui.*create.*vcmp_name" /var/log/audit*
