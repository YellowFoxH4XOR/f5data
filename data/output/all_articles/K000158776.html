K000158776: Tenant is not processing incoming traffic after controller/partition upgrade to F5OS-C 1.8.2

Type
Support Solution
Published
2025-12-16
Updated
2025-12-16
Applies to
  • F5OS
  • F5OS-C: 1.8.2
Source
https://my.f5.com/manage/s/article/K000158776

Description

The symptoms of the issue are as following:

  1. After upgrading F5OS controller/partition to version 1.8.2, the affected tenant is accessible via its management IP, but traffic is not received on its VLAN interface. Self-IPs are unreachable and tenant effectively is non-functional from traffic processing perspective.
  2. "show dag-states" command output on partition does NOT include the affected tenant.
  3. The following error can be observed in the tenant ltm log:

<date time > <hostname> info platform_agent[5691]: 01e10007:6: fetched 350576 bytes of daglib

<date time> <hostname> err platform_agent[5691]: 01e10004:3: Error opening tcl file

 

Environment

  • Product: BIG-IP tenant running on Velos
  • Version: F5OS-C 1.8.2, TMOS 17.5.x
  • Platform: F5-VEL-LTM-CX410-AC, F101

Cause

Incorrect ownership and permissions of the tmm_velocity_init.tcl file within the tenant prevented inclusion of the tenant in the SDAG table and disrupted traffic processing. The root cause is undetermined and there is no bug  ID. Refer to the next section for a workaround to make tenant functional.

Recommended Actions

To workaround the issue perform the following steps:

 

  1. On the affected tenant, check owner, group, permissions and SELinux context of tmm_velocity_init.tcl (the file should be located in /config directory):
    ls -l /config/tmm_velocity_init.tcl  (or if the path is different, <path_to_tmm_velocity_init.tcl>)
    ls -Z /config/tmm_velocity_init.tcl (or if the path is different, <path_to_tmm_velocity_init.tcl>)
  2. If owner/group are not root, change them:
    chown root:root /config/tmm_velocity_init.tcl
  3. Restart platform agent:
    bigstart restart platform_agent
  4. Check ltm log for errors related to opening tcl files (supposed to be none).
  5. Verify contents of tmm_velocity_init.tcl for a line beginning with "sdag true".
  6. If present, perform a full tenant reboot and check if traffic is restored.
