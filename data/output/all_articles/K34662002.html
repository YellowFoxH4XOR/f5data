Topic

This article applies to BIG-IP DNS 12.0.0 through 14.1.0 and BIG-IP GTM 11.x.

Important: This article addresses only BIG-IP DNS and GTM features when configured as an authoritative name server (GSLB, Local BIND, and DNS Express).

Note: DNS cache configurations are not addressed in this article.

This document contains recommendations for configuring BIG-IP DNS and GTM to meet Request for Comment (RFC) compliance requirements of DNS Flag Day. Additionally, this article includes recommendations for versions of BIG-IP DNS and GTM that are not fully EDNS RFC compliant.

Note: F5 Technical Support has determined in experimental configurations that BIG-IP DNS and GTM versions that are not fully EDNS RFC compliant can be configured to meet (or exceed) minimum requirements of DNS Flag Day.

For more information regarding EDNS RFC, refer to K07808381: BIG-IP DNS processing and DNS Flag Day

Note: These recommendations are provided on a best effort basis. F5 recommends that you validate your environment using the ednscomp tool provided by ISC.

Description

As of February 1, 2019, the DNS Flag Day site states the following regarding the minimal working configuration:

Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

  • The minimal working setup which will allow your domain to survive DNS Flag Day must not have a timeout result in any of the plain DNS and EDNS version 0 tests implemented in the ednscomp tool.

    Note: The minimal compliance is not full compliance and may cause future compliance issues. For this reason, F5 recommends you to work towards full EDNS compliance.

Supported BIG-IP DNS and GTM versions can be configured to help meet the DNS Flag Day compliance requirements.

Note: F5 recommends upgrading to versions with full EDNS compliance where possible.

Recommendations

The BIG-IP DNS and GTM systems offers multiple configuration options to resolve DNS queries. Different zones may be resolved using DNS Express and Local BIND. Make sure to test all resolution paths and all listeners that are utilized for DNS resolution for compliance.

When configuring the BIG-IP DNS and GTM systems using the Configuration utility, consider the following configuration settings:

  • The configuration of a BIG-IP DNS or GTM TCP listener is mandatory. This is not directly EDNS related, but is required for minimal compliance for DNS Flag Day, checked by the edns512tcp test. This requirement is established in Internet Engineering Task Force (RFC 7766).

    Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

  • In the supported BIG-IP DNS and GTM software versions, Local BIND will correctly handle any Extension Mechanisms for DNS (EDNS0) queries it receives.
    • For queries to reach Local BIND of the BIG-IP system, Use BIND Server on BIG-IP must be set to Enabled, and Unhandled Query Actions must be set to Allow on the DNS profile.

      Note: For BIG-IP DNS and GTM versions that are affected, EDNS version 1 queries are dropped early in processing and all edns1 tests will timeout. This meets minimum requirements for DNS Flag Day; EDNS0 queries are unaffected. For more information refer to Bug ID 463202.

  • Setting Unhandled Query Actions to Drop causes timeouts to be reported by the ednscomp tool under any of the following conditions:
    • You are testing a zone which is not loaded in DNS Express
    • DNS Express is disabled in the DNS profile
    • You are using a BIG-IP version which is not listed as EDNS RFC-compliant for DNS Express.

      Note: For more information, refer to K07808381: BIG-IP DNS processing and DNS Flag Day.

  • Setting Unhandled Query Actions to Reject, Hint, or No Error meets minimum requirements for DNS Flag Day (no timeouts), but if the DNS Express feature is not configured, this may result in a misconfigured but functional zone. Specifically this may cause nosoa or noaa errors on several tests from the ednscomp tool.
  • The FPGA-accelerated hardware cache does not handle some EDNS options correctly.
    Note: It is recommended to disable FPGA acceleration until this issue is addressed in a forthcoming release. For more information, refer to K25351434: The DNS FPGA hardware-accelerated cache may drop DNS queries that contain EDNS OPT records.

Recommended Configuration

The following recommendations are provided to aid in configuring the BIG-IP DNS and GTM systems to achieve EDNS RFC compliance. Obtaining compliance may not be limited to these configuration recommendations.

All Versions

  • If zones are delegated to BIG-IP DNS and GTM, ensure that the configuration will serve SOA and other records for the zone using one of the following configuration options:
    • Serve the zone using DNS Express.

      Note: For more information, refer to K15585: Answering all DNS queries for a zone when the GTM listener uses a Default Pool.

    • Ensure the BIND Server is Enabled and Unhandled Query Actions is set to Allow.
  • If you are not serving your DNS zone from DNS Express, do not set Unhandled Query Actions to Drop on the DNS profile.
  • Ensure that the TCP listener is configured using the same DNS profile as the User Datagram Protocol (UDP) listener.

Versions which are not fully EDNS RFC-compliant

  • Do not set the Unhandled Query Actions to Drop on the DNS profile.
