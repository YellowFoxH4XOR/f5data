Description

After you upgrade the BIG-IP system to BIG-IP 14.1.2 and later, the configuration may fail to load and exhibit the following symptoms:

  • You observe messages similar to the following in /var/log/ltm:
    01070734:3: Configuration error: undefined error at authz/ConfigWriter.cpp
    01420006:3: Loading configuration process failed.
  • You observe messages similar to the following in /var/log/auditd/audit.log:
    Note: The message contains denied and unlabeled_t shown in bold below.
    avc: denied { unlink } for pid=8210 comm="mcpd" name="tmm_externalventiadevcrldpprofile1" dev="dm-18" ino=1174 scontext=system_u:system_r:mcpd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=lnk_file
  • Multiple daemons such as mcpd, gtmd, or named are in a restart loop due to lack of permission and you observe errors in /var/log/daemon.log similar to the following:
    err named[<pid>]: open: /config/named.conf: permission denied
    crit named[<pid>]: loading configuration: permission denied
    crit named[<pid>]: exiting (due to fatal error) 
  • The Configuration utility displays the following:
    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

Environment

  • BIG-IP 14.1.2 and later
  • A BIG-IP Upgrade

Cause

The issue is caused by broken SELinux permissions due to Bug ID 862937.

Recommended Actions

Choose one of the following:
  • Perform the workaround in Bug ID 862937.
  • Prior to upgrading to BIG-IP 14.1.2 and later, check the BigDB value is enabled for liveinstall.moveconfig and liveinstall.saveconfig with the following command:

    tmsh list sys db liveinstall.moveconfig liveinstall.saveconfig

    Then boot to the newly installed software by setting Install Configuration to No. When the Live Install BigDB settings are enabled, the configuration is automatically copied to the new boot location during upgrade. Setting the Install Configuration option to Yes is only for situations when you've made changes to the configuration between the time you install the software and when you boot to the new boot location. For more information about the Live Install BigDB settings and how to modify them refer to, K13438: Controlling configuration import when performing software installations

Additional Information

Any BIG-IP daemon can be affected by this unlabeling issue. You can check which have not been labeled properly by running the command below:

ls -laRZ / 2> /dev/null | grep unlabel
