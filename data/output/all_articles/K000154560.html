In most cases, this can be resolved by following K13600166, but sometimes it's impossible to delete /var/tmp directory as described in the article.


[root@bigip1:Active:In Sync] var # rm -rf tmp

rm: cannot remove 'tmp': Device or resource busy


Environment

- failed software install

- "Could not access configuration source; sda, 1" in /var/log/liveinstall.log

- cannot delete /var/tmp directory


Cause

/var/tmp directory is invalid and cannot be deleted


Recommended Actions

To successfully delete /var/tmp directory, you need to:


1. Reboot and during startup choose 'TMOS maintenance' in the GRUB menu.

2. Mount the /var volume for the problematic location.


switch_root:/# mount /dev/mapper/vg--db--vda-set.1._var /var

[ 37.879671] EXT4-fs (dm-8): Mounted filesystem with ordered data Mode. Opts: (null)


3. Delete the /var/tmp directory and re-create the symlink to ../shared/tmp.


switch_root:/# cd /var

switch_root:/var# rm -rf tmp

switch_root:/var# In -s -v .. /shared/tmp /var/tmp

'/var/tmp' -> ' .. /shared/tmp


4. Reboot and go to the desired boot location.

5. Change and confirm that the correct security contexts are applied to /var/tmp


[root@bigip1:Active:In Sync] config # ls -lZd /var/tmp /shared/tmp

drwxrwxrwt. root root system_u:object_r:tmp_t:s0    /shared/tmp

lrwxrwxrwx. root root system_u:object_r:unlabeled_t:s0 /var/tmp -> ../shared/tmp

[root@bigip1:Active:In Sync] config # chcon -v -h --reference=/shared/tmp /var/tmp

changing security context of '/var/tmp'

[root@bigip1:Active:In Sync] config # ls -lZd /var/tmp /shared/tmp

drwxrwxrwt. root root system_u:object_r:tmp_t:s0    /shared/tmp

lrwxrwxrwx. root root system_u:object_r:tmp_t:s0    /var/tmp -> ../shared/tmp

 


Once /var/tmp is correctly pointing to /shared/tmp and has a valid security context (as above), the installation should be successful.
