Known Issue

The BIG-IP SASP monitor may leak memory.

This issue occurs when all of the following conditions are met:

  • Your configuration contains a resource that uses the SASP monitor.
  • The SASP monitor actively polls a Group Workload Manager (GWM) server.

Impact

Over time, the system may become unresponsive or reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H438543 on the Diagnostics > Identified > Medium screen.
  • You observe a progressive increase in the amount of memory that the SASPD_monitor process uses. You can monitor the memory usage by using the top command.

    For example:

    top -cbn 1 -p `pidof SASPD_monitor`

    Mem:  16438936k total, 16323052k used,   115884k free,   221136k buffers
    Swap:  1048312k total,    21164k used,  1027148k free,   300668k cached

      PID USER      PR  NI  VIRT  RES  SHR S %CPU %MEM    TIME+  COMMAND
    15494 root      15   0  7556 2384 1576 S  0.0  0.0   0:00.00 /usr/share/monitors/SASPD_monitor

  • The BIG-IP system fails over to a system in the device group, due to memory exhaustion.
  • The BIG-IP system unexpectedly reboots.
