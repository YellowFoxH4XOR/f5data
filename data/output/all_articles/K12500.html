Topic

Beginning with the ARX version 5.3.x software branch, F5 started enforcing licensed features and system limits based on the values contained in the system's license. Limitations were previously hard-coded on a per-platform basis; the ARX is now enforcing limitations based on the system's license.

The system's base registration key is used to generate the license. The format of the base registration key is as follows:

AAAAA-BBBBB-CCCCC-DDDDD-EEEEEEE

Additional features and limitations are enabled by applying add-on registration keys and generating a new license. The format of the add-on registration key is as follows:

AAAAAAA-BBBBBBB

Currently, if any add-on keys are purchased with the initial order, the add-on functionality is bound with the system's base registration key, and the add-on functionality is included with a license generated from the base registration key.

ARX version 5.3.x does not provide the ability to apply an add-on registration key. This functionality was introduced in ARX version 6.0.0. Therefore, if an add-on key is purchased after the initial order is completed, the add-on key must be saved and applied to the system once the system has been upgraded to ARX version 6.0.0 or later. However, not being able to apply an add-on key in version 5.3.x has no impact because the only available add-on key for ARX version 5.3.x is for an additional protocol, and this limitation is not yet enforced, nor was it previously enforced. An ARX version 5.3.x system licensed for only one protocol still permits the use of two protocols.

Viewing licensed features and system limits

You can view the licensed features and system limits on a running ARX system using the show active-license command.

For example, the output of show active-license command on an ARX 1500 system appears similar to the following example:
