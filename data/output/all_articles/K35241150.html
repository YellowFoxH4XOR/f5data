Known Issue

Address Resolution Protocol (ARP) replies may not reach the Traffic Management Microkernel (TMM) process on VIPRION B4450 blades.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION 4480 or 4800 chassis with one or more B4450 blades installed.
  • The Broadcom switch learned a corrupted Layer 2 (L2) forwarding database (FDB) entry on an internal HiGig trunk.

Impact

Traffic processing will fail for connections associated with the corrupt L2 FDB entry.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system fails to process traffic for some connections.
  • Your BIG-IP system fails to process some ARP replies.

Workaround

To work around this issue, you can flush L2 FDB entries for the affected Virtual Local Area Network (VLAN). To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Determine the affected VLAN. This is the ingress VLAN of the affected remote client packet.
  3. To flush L2 FDB entries, type the following command:

    delete /net fdb vlan <vlan_name>

    For example, to flush L2 FDB entries on the VLAN named external, type the following command:

    delete /net fdb vlan external
