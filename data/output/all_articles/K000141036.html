Description

You have a BIG-IP device where the access to Configuration Utility and CLI is failing for clients behind a firewall.

During the same period, local clients not behind the firewall can access the system.

Environment

  • BIG-IP
  • High Availability
  • Clients access the BIG-IP management behind a firewall.

Cause

Unknown

Recommended Actions

  1. Perform a traceroute from the client to check if the traffic reached the BIG-IP. 
  2. Check with firewall admins for any blocks that may have occurred for the same client traffic.
  3. Check BIG-IP network interface status.
    1. tmsh show net interface
  4. Check the system services for any indication of an interruption or a service restart.
    1. show /sys service
  5. Take a packet capture using the command below; this will help determine if the traffic reached the BIG-IP device.
    1. tcpdump -envi <interface_ID> -s0 -w /shared/tmp/$(/bin/hostname)_$(date +%Y.%m.%d-%H.%M.%S).pcap host <IP_Address>
    2. Here the host IP address could be the client IP which you tried accessing from or the NAT IP provides by the firewall.
    3. Interface ID is the interface where the management access request would receive based on the accessed IP (management or self-ip(s)) 
    4. The capture file would be created in /shared/tmp/ directory.
  6. Use a secure copy tool to download the captured pcap file from the BIG-IP to a local computer.
  7. Open the capture with Wireshark and check for errors in the flow.
  8. Check the BIG-IP logs to find any indication of network failure or interface down situation.
    1. Open the /var/log/ltm file(s) using BIG-IP CLI and search for "Link: <Inteface_ID>".
  9. Check the BIG-IP logs to find if there is any access errors.
    1. Open the /var/log/httpd/httpd_errors file(s) using BIG-IP CLI and look for the errors.
  10. If above steps unable to find the cause, generate a fresh QK view and log tarball.
    1. Generate the tarballs from CLI.
    2. tar -zcvf /shared/tmp/$(/bin/hostname)_$(date +%Y.%m.%d-%H.%M.%S)_tarball.tgz /var/log
    3. Generate a fresh QKview. K12878: Generating diagnostic data using the qkview utility

Open a case with F5 support, include the QKview, log tarball, packet capture and your troubleshooting results.
