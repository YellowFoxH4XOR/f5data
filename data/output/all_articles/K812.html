Issue

Most Cookie Persistence timer problems are the result of one, or more, of the following issues:

  • The system clocks are not correct.
  • The time zone is not correctly offset from Greenwich Mean Time (GMT).
  • The /etc/localtime file is not properly linked to the correct time zone file.
  • The BIG-IP BIOS time zone to GMT UTC does not match the system's time.

To troubleshoot and resolve the cause of the problem, use the following methods:

Verify the system clocks and make corrections as necessary

To verify that the BIG-IP and web client clocks are correctly set, perform the following steps:

  1. Check the BIG-IP clock by typing the following command from the BIG-IP command line:

    date

    The date, time, time zone and year will display in a format similar to the following:

    Tue Apr 29 15:00:28 EDT 2003

  2. Check the web client clock. Depending on the platform, you may either see the time in a date/clock program (as in Windows) or through the command line for that particular system. If you are not sure how to check the time on your web servers, consult the documentation from your server vendor.

    If the time and date are not correct, reset it appropriately. For specific instructions, refer to K597: Setting the time and date on BIG-IP and 3-DNS.

Verify the time zone offset from GMT

When the cookie is set on the client computer, the expiration date is given as GMT time; the client computer converts the expiration to the local time. If the time zone offset from GMT is incorrect, this can cause cookie persistence issues.

To check if the time zone information is the cause of cookie persistence issues, set the cookie timer to 30 minutes more than the offset from GMT on BIG-IP. For example, if BIG-IP is located in the EDT time zone, the offset is 4 hours so you would set the set the cookie expiration to be 4 hours and 30 minutes.

To set the cookie expiration, perform the following steps:

  1. From the navigation pane of the Configuration Utility, select Pools.

    The Pool list displays.

  2. Select the pool that contains the cookie timer you want to modify.

    The Pool Properties screen displays.

  3. Click the Persistence tab at the top of the screen.

    The Persistence options for the Pool displays.

  4. In the Active Cookie row, change the cookie expiration time to the desired value.
  5. Click Apply.

If changing the cookie timer in this manner stops the cookies from expiring prematurely, the issue, is most likely that the time zone information is incorrect on either the BIG-IP or the web client.

To verify time zone information on BIG-IP, type the following command:

date

You will see output similar to the following:

Thu May 8 15:16:53 PDT 2000

You should see an acronym for the time zone between the time and the year. If one does not display, the time zone is not set correctly or the time zone data is corrupt.

Note: If the time zone data is corrupt, contact F5 Technical Support for further assistance.

To verify the time zone information on the web client, use the utilities provided with the computer's platform. For example, in Windows, the time zone, time and date are set using the Date and Time control panel.

Verify that the BIG-IP /etc/localtime file is properly linked to the correct time zone file

The file /etc/localtime is a symbolic link to a binary data file that contains information about the offset from GMT and also any Daylight/Standard time conversions. If the link is not pointing to the correct file, time is not being calculated properly. The file name varies according to the actual time zone, and only the time zone files actually needed are present to save disk space.

To verify that the BIG-IP /etc/localtime file is properly linked to the correct time zone file, type the following command:

ls -la /etc/localtime

You should receive output similar to the following:

lrwxr-xr-x 1 root wheel 30 Apr 29 16:12:36 /etc/localtime@ -> /usr/share/zoneinfo/US/Eastern

If the time zone data file is missing, run the config command to set the time zone correctly. This will allow you to reset the time zone correctly and replace the missing time zone file.

Change the BIG-IP BIOS time zone to GMT UTC to match the system's time

If none of the previous steps have corrected the cookie persistence problem, you may need to change the hardware time and time zone in the BIG-IP BIOS. To avoid system issues, contact F5 Technical Support for assistance with this process.

After these changes are made, the cookie timers should function properly. If you are still having issues, contact F5 Technical Support for assistance.
