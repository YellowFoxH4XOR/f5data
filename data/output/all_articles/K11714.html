Known Issue

This is the result of a known issue. Connections to a virtual server configured with both cookie hash and OneConnect profiles may cause a TMM memory leak. This issue may occur when the client sends multiple HTTP/1.1 requests over the same connection.

You can determine if your BIG-IP system is affected by the memory leak by checking the TMM memory allocation over time and checking the HTTP filter memory utilization. To do so, log in to the BIG-IP Configuration utility, navigate to Overview >> Performance, and change the Graph Interval to Last 7 Days. If TMM memory allocation has consistently climbed during the interval, you should check the memory allocation for the HTTP filter.

Checking the memory allocation for the HTTP filter

  1. Log in to the BIG-IP Configuration utility.
  2. Click Statistics.
  3. Click the Memory tab.
  4. Under Memory Pool Name, find the filter (variable) subsystem.
  5. If the filter (variable) subsystem is consuming hundreds of megabytes and continues to grow, the system is likely experiencing the HTTP filter memory leak.

Note: You can also view system memory utilization using the bigpipe memory command. For example, the following command displays the HTTP filter memory utilization every 10 seconds:
watch -n 10 "b memory |grep filter"

F5 Product Development tracked this issue as ID 225920 (formerly CR140446) and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WAM, WOM, or APM release notes.

Workaround

You can work around this issue by either removing the OneConnect profile from the virtual server, or replacing the cookie hash persistence profile with another persistence profile, such as Universal persistence. To do so, perform one of the following procedures:

Removing the OneConnect profile from the virtual server

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Select the virtual server that contains the OneConnect and cookie hash profiles.
  4. Change the OneConnect Profile drop-down menu to None.
  5. Click Update.

Replacing the cookie hash persistence profile with another persistence profile, such as Universal persistence

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Select the virtual server that contains the OneConnect and cookie hash profiles.
  4. Click the Resources tab.
  5. Choose a persistence profile other than cookie hash from the Default Persistence Profile drop-down menu.
  6. Click Update.
