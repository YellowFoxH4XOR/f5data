K000163029: After upgrade to 17.5.1.8, client-certificate handshake failure when an intermediate CA is configured as the trusted CA

Description

After upgrading BIG-IP LTM to 17.5.1.8, client-certificate authentication failed when the Client SSL profile used an intermediate CA as the Trusted Certificate Authority. TLS handshakes failed with ssl_shim_vfycerterr:4610: alert(48) unable to get issuer certificate.


 

Environment

BIG-IP LTM version 17.5.1.8

Client SSL profile configured for client-certificate authentication

Intermediate CA configured as the Trusted Certificate Authority and Advertised Certificate Authority


 

Cause

A BIG-IP 17.5.1.8 defect identified as Bug ID2384197 caused SSL handshake failures during client-certificate authentication when an intermediate CA was configured as the Trusted Certificate Authority in a Client SSL profile. The defect caused BIG-IP to report unable to get issuer certificate and reject otherwise valid client certificate chains.


 

Answer/Recommended Actions

Open support case and request an EHF for ID2384197.

IMPORTANT: If FIPS is enabled in your environment, please include this information in the support case.

Install the engineering hotfix on affected BIG-IP 17.5.1.8 guests.

Validate the hotfix before applying it to production.

Confirm successful TLS client authentication using the affected certificate chain.

Follow the applicable F5 engineering-hotfix handling and rollback procedures during deployment.
