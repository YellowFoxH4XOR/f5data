Known Issue

In rare circumstances, an unexpected iSession tunnel state transition can cause TMM to restart.

This issue occurs when all of the following conditions are met:

  • An iSession profile with connection reuse enabled is associated with a virtual server.
  • The iSession profile is modified while a virtual server configured with the profile has idle iSession connections that are awaiting reuse.

Impact

The BIG-IP AAM system may temporarily fail to process traffic as it recovers from the Traffic Management Microkernel (TMM) restarting. Systems configured for high availability (HA) may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system unexpectedly fails over to another system in the device group.
  • Your BIG-IP system generates a TMM core file to the /shared/core/ directory.

Workaround

To work around this issue, you can modify the affected iSession profile and disable the Reuse Connection feature. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > iSession.
  3. Click the name of the affected profile.
  4. In the Outbound iSession to WAN section, set Reuse Connection to Disabled.
  5. Click Finished.
