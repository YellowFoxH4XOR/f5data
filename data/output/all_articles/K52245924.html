Topic

This article applies to BIG-IP 11.x through 13.x. For information about other versions, refer to the following articles:

  • K10127: Bypassing the BIG-IP WebAccelerator with an iRule in 10.x
  • K6882: Bypassing the BIG-IP WebAccelerator with an iRule in 9.4.x

You should consider using these procedures under either of the following conditions:

  • You need to selectively bypass BIG-IP WebAccelerator or BIG-IP AAM processing using iRules.
  • You need to selectively bypass BIG-IP HTTP cache processing using iRules.

Description

You can bypass BIG-IP WebAccelerator or BIG-IP AAM processing based on information in either the HTTP request or HTTP response. To bypass BIG-IP WebAccelerator or BIG-IP AAM processing based on information in the HTTP request, you must use the WAM::disable iRules command in the HTTP_REQUEST iRules event. To bypass BIG-IP WebAccelerator or BIG-IP AAM processing based on information in the HTTP response, you must use the WAM::disable iRules command in the HTTP_RESPONSE iRule event.

If you have configured your BIG-IP system to use only the BIG-IP HTTP cache, you must use the CACHE::disable iRules command in the HTTP_REQUEST iRules event to bypass BIG-IP HTTP cache processing based on information in the HTTP request. If you want to bypass BIG-IP HTTP cache processing based on information in the HTTP response, you must use the CACHE::disable iRules command in the HTTP_RESPONSE iRules event.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have Administrative access to the Configuration utility on the BIG-IP system.

Procedures

  • Disabling BIG-IP WebAccelerator or BIG-IP AAM processing based on information in the HTTP request
  • Disabling BIG-IP WebAccelerator or BIG-IP AAM processing based on information in the HTTP response
  • Disabling BIG-IP HTTP cache processing based on information in the HTTP request
  • Disabling BIG-IP HTTP cache processing based on information in the HTTP response

Disabling BIG-IP WebAccelerator or BIG-IP AAM processing based on information in the HTTP request

Impact of procedure: The example iRule may not apply to all environments. F5 recommends you author an iRule that may work best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. Enter a name for the iRule in the Name setting. For example, K52245924_bypass_wam_req.
  5. In the Definition setting, enter an iRule similar to the following example. The following example iRule disables BIG-IP WebAccelerator or BIG-IP AAM processing for all HTTP POST requests:

    when HTTP_REQUEST {
       if { [HTTP::method] equals "POST" }{
          WAM::disable
       }
    }

  6. To save the iRule, select Finished.
  7. Go to Local Traffic > Virtual Servers > Virtual Server List.
  8. Under the Resources column for the virtual server, select the Edit link.

    Note: The virtual server must be configured with BIG-IP WebAccelerator or BIG-IP AAM.

  9. Under the iRules section, select Manage.
  10. Locate the iRule created from previous steps 3 to 6 in the Available list and move it to the Enable list.
  11. To save the changes, select Finished.

Disabling BIG-IP WebAccelerator or BIG-IP AAM processing based on information in the HTTP response

Impact of procedure: The example iRule may not apply to all environments. F5 recommends you author an iRule that may work best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. Enter a name for the iRule in the Name setting. For example, K52245924_bypass_wam_resp.
  5. In the Definition setting, enter an iRule similar to the following example. The following example iRule disables BIG-IP WebAccelerator or BIG-IP AAM processing for HTTP responses with video or audio content type:

    when HTTP_RESPONSE {
        if { [HTTP::header exists "Content-Type"] } {
            switch -glob [HTTP::header "Content-Type"] {
                "application/octet-stream" -
                "video/*" -
                "audio/*" {
                    WAM::disable
                }
            }
        }
    }

  6. To save the iRule, select Finished.
  7. Go Local Traffic > Virtual Servers > Virtual Server List.
  8. Under the Resources column for the virtual server, select the Edit link.

    Note: The virtual server must be configured with BIG-IP WebAccelerator or BIG-IP AAM.

  9. Under the iRules section, select Manage.
  10. Locate the iRule created from previous steps 3 to 6 in the Available list and move it to the Enable list.
  11. To save the changes, select Finished.

Disabling BIG-IP HTTP cache processing based on information in the HTTP request

Impact of procedure: The example iRule may not apply to all environments. F5 recommends you author an iRule that may work best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. Enter a name for the iRule in the Name setting. For example, K52245924_bypass_cache_req.
  5. In the Definition setting, enter an iRule similar to the following example. The following example iRule disables BIG-IP HTTP cache processing for HTTP requests with URI path ending with .pdf:

    when HTTP_REQUEST {
       if { [HTTP::path] ends_with ".pdf" } {
          CACHE::disable
       }
    }

  6. To save the iRule, select Finished.
  7. Go Local Traffic > Virtual Servers > Virtual Server List.
  8. Under the Resources column for the virtual server, select the Edit link.

    Note: The virtual server must be configured with BIG-IP HTTP cache.

  9. Under the iRules section, select Manage.
  10. Locate the iRule created from previous steps 3 to 6 in the Available list and to move it to the Enable list.
  11. To save the changes, select Finished.

Disabling BIG-IP HTTP cache processing based on information in the HTTP response

You can disable BIG-IP HTTP cache processing based on information in the HTTP response by performing the following procedure:

Impact of procedure: The example iRule may not apply to all environments. F5 recommends you author an iRule that may work best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. Enter a name for the iRule in the Name setting. For example, K52245924_bypass_cache_resp.
  5. In the Definition setting, enter an iRule similar to the following example. The following example iRule disables BIG-IP HTTP cache processing for HTTP responses with video or audio content type:

    when HTTP_RESPONSE {
        if { [HTTP::header exists "Content-Type"] } {
            switch -glob -- [HTTP::header "Content-Type"] {
                "application/octet-stream" -
                "video/*" -
                "audio/*" {
                    CACHE::disable
                }
            }
        }
    }

     

  6. To save the iRule, select Finished.
  7. Go Local Traffic > Virtual Servers > Virtual Server List.
  8. Under the Resources column for the virtual server, select the Edit link.

    Note: The virtual server must be configured with BIG-IP HTTP cache.

  9. Under the iRules section, select Manage.
  10. Locate the iRule created from previous steps 3 to 6 in the Available list and move it to the Enable list.
  11. To save the changes, select Finished.
