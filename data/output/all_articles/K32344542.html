Description

Some IPsec clients, for example the native Windows IPsec client, rely on a second protocol such as Layer 2 Tunneling Protocol (L2TP) or Point-to-Point Tunneling Protocol (PPTP) to establish a second channel for IP addressing and packet encapsulation.

The BIG-IP does not support IPsec clients that require L2TP or PPTP establishment over the tunnel.

Note: The BIG-IP can forward L2TP packets between an L2TP client and server over an established IPsec tunnel. In that scenario, a Virtual Server or other listener must be configured to handle L2TP sessions, just as any client to server flow requires a listener in order for the flow to be processed by the BIG-IP.
 

Environment

  • IPsec client
  • L2TP as the transport protocol
  • IPsec tunnel
 

Cause

LTM cannot act as an L2TP client or server.
 

Recommended Actions

For a traditional traveling/remote VPN use case, where clients need to dial in to the BIG-IP over a secure channel, consider use APM.  What is BIG-IP APM?
The BIG-IP can be securely managed over SSH or the configuration utility (Web UI).
