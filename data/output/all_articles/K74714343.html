Known Issue

The bigd process may leak memory when using a fully-qualified domain name (FQDN) to automatically populate the BIG-IP pool configuration.

This issue occurs when all of the following conditions are met:

  • You have configured your BIG-IP system to automatically populate pool member lists using a FQDN.
  • The Auto Populate option is enabled on both the node and pool members configurations.

Note: The amount of memory leaked increases with the number of node IP addresses returned in response to DNS queries.

Impact

Pool or node monitoring is unavailable while the bigd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Memory consumption continually increases for the bigd process.
  • In the /var/log/kern.log file, you observe messages similar to the following example:

    err kernel: Out of memory: Kill process 23456 (bigd) score 101 or sacrifice child
    err kernel: Killed process 23456, UID 0, (bigd) total-vm:2345678kB, anon-rss:420444kB, file-rss:12345kB

  • You observe a bigd core file in the /var/core directory.

Workaround

To work around this issue, you can ensure the Auto Populate option is set to disabled for the node and pool member configurations. Alternatively, you can increase the Interval value of the FQDN node or periodically restart the bigd process. To do so, perform one of the following procedures:

  • Increasing the Interval value of the FQDN node
  • Restarting the bigd process

Increasing the Interval value of the FQDN node

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Nodes.
  3. Click the FQDN node under Name.
  4. Under FQDN, locate the Interval setting and increase the current value.
  5. Click Update.

Restarting the bigd process

This workaround only recovers the memory lost from the memory leak and will need to be performed on a regular basis.

Impact of workaround: Restarting the bigd process temporarily interrupts pool and node monitoring. F5 recommends testing any such changes during a maintenance window.

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    bigstart restart bigd
