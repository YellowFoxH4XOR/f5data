Description

Starting BIG-IP version 15.0.0, when using Portal Access on BIG-IP APM, the DNS cache resolver will no longer attempt to resolve a TLD (Top Level Domain) of "onion.", "test." or "invalid." to comply with RFC7686 and RFC6761.
If you attempt to use any Portal Access resource with an fqdn matching any of these TLD, this will not work and you will notice similar log under /var/log/apm:

Apr  8 14:06:19 bigip1 notice tmm1[18185]: 01490504:5: /Common/AP_example:Common:0217f164: host.domain.test can not be resolved

A DNS capture will show such DNS query/response:

  644   6.478396 0.003026 140 192.168.2.10 → 192.168.2.11  116 18389 53 DNS OUT s1/tmm0 : Standard query 0xe82f A Host.dOmaIn.teSt.<Null> OPT
  645   6.492486 0.014090 140  192.168.2.11 → 192.168.2.10 788 53 18389 DNS IN  s1/tmm0 : Standard query response 0xe82f No such name A Host.dOmaIn.teSt.<Null> ...

Environment

  • APM using Portal Access starting 15.0.0
  • web servers configured with a TLD of "onion.", "test." or "invalid."

Cause

This is by design starting BIG-IP version 15.0.0 in order to comply with RFC7686 and RFC6761.

Recommended Actions

Do not use fqdn with a TLD of "onion.", "test." or "invalid." for web servers fqdn.
