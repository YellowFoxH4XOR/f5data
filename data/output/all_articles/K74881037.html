Description

This is a specific case of error:"01340004:3: HA Connection detected dissimilar peer:" (K13828).
BigIP getting error messages similar to the following: "01340004:3: HA Connection detected dissimilar peer: local npgs 8, remote npgs 8, local npus 24, remote npus 24, local pg 0, remote pg 0, local pu 2, remote pu 1."

 

Environment

  • The system is with High Availability (HA) and mirroring between the HA peers:
  • Both devices have a mirroring IP configured.                              
  • Both devices are set up to be in the same sync-failover device group.    
  • The devices use identical platforms.

Cause

Using a non-default cmp-hash for the mirroring VLAN causing the errors to appear.
As the Recommended Action from  K13828 says:
Follow F5 recommendations for hardware parity in high availability (HA) configurations, especially for connection mirroring.
In this particular case we can find a related cause,therefore we will break the error message:
01340004:3: HA Connection detected dissimilar peer: local npgs 8, remote npgs 8,
                                                      local npus 24, remote npus 24,
                                                      local pg 0, remote pg 0,
                                                      local pu 1, remote pu 2.                       <-  Those suppose to be identical
Check mirror VLAN settings:

net self /Common/selfip_10.10.10.10-27 {
    address 10.10.10.10/27
    allow-service {
        default
    }
    fw-enforced-policy /Common/FW_enforced-policy_failover_traffic_cluster
    traffic-group /Common/traffic-group-local-only
    vlan /Common/Vlan_Public
}

net vlan /Common/Vlan_Public {
    cmp-hash src-ip              <-----------Using non-default CMP HASH
    interfaces {
        1/1.1 {
            tag-mode service
            tagged
        }
    }
    sflow {
        poll-interval-global no
        sampling-rate-global no
    }
    tag 1111
}

Recommended Actions

As described from article K14135 under Mirroring recommendations:
Use the default Clustered Multiprocessing (CMP) hash setting for the VLAN in which mirroring is configured (BIG-IP 11.3.0 and later).
The CMP hash setting for the VLAN specifies how the BIG-IP system disaggregates traffic for the VLAN. The default hash (Default) specifies that the system uses L4 ports when disaggregating traffic on the VLAN. Choosing a non-default hash, such as Source Address, may disrupt mirroring traffic between TMM instances.

  1. From WebUI - Go to: Network  -›  VLANs : VLAN List  -›  VLAN_NAME
  2. Open Configuration to Advanced
  3. Set CMP HASH to Default
  4. Click on Update

Additional Information

To verify the error messages disappeared, you may check the ltm log (/var/log/ltm).
In case of using for connection mirroring between HA peers, make sure that the VLAN's CMP Hash setting is set to the default value. Otherwise, the system cannot establish the HA connection.
