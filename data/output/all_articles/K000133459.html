Description

You created a rule that uses “URL Match” with the "Glob Match" condition through SSLO guided configuration for a topology.

but comes up as "undefined" condition when checking it from the WebGUI under Access >> Profiles / Policies : Per-Request Policies(PRP) >> the created PRP for the topology.

Same observation when checking from the configuration file /config/bigip.conf for the relevant codes.

apm policy policy-item /Common/ssloP_url-filter.app/ssloP_url-filter_testurl_act_url_branching {
 agents {
  /Common/ssloP_url-filter.app/ssloP_url-filter_testurl_act_url_branching_ag {
   type category-lookup
  }
 }
 app-service /Common/ssloP_url-filter.app/ssloP_url-filter
 caption "URL Branching"
 color 1
 item-type action
 rules {
  {
   caption Allow
   expression "expr { [mcget {perflow.branching.url}] undefined \"https://*.example.com/\" }"
   next-item /Common/ssloP_url-filter.app/ssloP_url-filter_testurl_out
  }
  {
   caption fallback
   next-item /Common/ssloP_url-filter.app/ssloP_url-filter_testurl_out_failed
  }
 }
}

 

In /var/log/ltm file, you would see this a similar log message is logged and the traffic is impacted.

info tmm[16514]: 01220002:6: Rule /Common/_sys_APM_Expression_Evaluation: syntax error in expression " [mcget {perflow.branching.url}] undefined "https://*.example....": extra tokens at end of expression while compiling "expr { [mcget {perflow.branching.url}] undefined "https://*.example.com/" } " while compiling "return [ expr { [mcget {perflow.branching.url}] undefined "https://*.example.com/" } ]" (compiling body of proc "accessv2_proc0", line 1)

Environment

SSL Orchestrator's security policy
 

Cause

Bug ID 1017053: [SSL Orchestrator] Policy fails to complete when URL branching is configured

Bug ID 1232665: Security Policy (URL Branching agent) match condition configured as "Undefined" in Per-requestPolicy 

 

Recommended Actions

To work around the issue, you can consider using a custom category lookup:

1. Under Main > Access > Secure Web Gateway > URL Categories : create a new category with "Glob Pattern Match" checked and URL

Example:

 

2. In SSLO guided configuration of a topology, navigate to Security Policy > select rule > Choose Category Lookup(All) > choose the category created earlier and action "ALLOW" and Deploy.

Example:

 

There are a couple of bugs to deal with, the BigIP v15.1.9 and later releases have these fixes, please consider upgrading to a version that covers the fixes.

For BigIP v15.1.8 and below you may consider contacting F5 Support to request the engineering hotfix.
