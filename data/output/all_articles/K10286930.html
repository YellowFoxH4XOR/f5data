Description
Even customer does not configure mail alert, you can see below error logs below:
In /var/log/maillog

err sSMTP[<PID>]: Unable to connect to "localhost" port 25.
err sSMTP[<PID>]: Cannot open localhost:25

In /var/log/cron

err anacron[<PID>]: Tried to mail output of job `cron.daily', but mailer process (/usr/sbin/sendmail) exited with ststus 1

Environment

  • BIG-IP
  • Anacron

Cause

The cause is the knonw bug Bug ID 722991: 'dead.letter' file might appear in the /root directory
Note that even there is no file named "dead.letter" in /root directoy, it is still possible target the bug above.
You can run below command to trigger the error to double confirm customer targets the bug 

run-parts /etc/cron.daily

The output is as below

/etc/cron.daily/cleanup_sync_files:
ls: cannot access /config/filestore/sync_file_request_d: No such file or directory 

Recommended Actions

To be more clear, you can follow below procudure .

  1. Login bash and enter vi to edit the file

vi /etc/cron.daily/cleanup_sync_files

  1. Press "i" to enter edit mode
  2. Move the cursor to the line of " for file in `ls $path`"

#! /bin/bash

# This script will be invoked by crond daily.
# It deletes files under  /config/filestore/sync_file_request_d/
# which have  not been modified for last 1 day.

cleanup_sync_files()
{
    if [ $# -lt 2 ]; then
        return
    fi

    path=$1
    age=$2

    for file in `ls $path`<--------------------------------------------------------------before change
Modify the line above to below
    for file in `ls $path 2>/dev/null` <--------------------------------------------------after change(you can add   >/dev/null    )

  1. Press ESC  to quite the edit mode
  2. Press !wq to save and leave

You can confirm the issue fixed by running below command immediately, there should be no error output.

run-parts /etc/cron.daily
