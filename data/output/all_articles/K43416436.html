Known Issue

BIG-IP PEM may fail to create a subscriber session when an iRule uses the PEM::subscriber subscriber-id-type attribute.

This issue occurs when all of the following conditions are met:

  • BIG-IP PEM controls subscriber traffic.
  • Your configuration includes an iRule that creates BIG-IP PEM sessions using the PEM::subscriber subscriber-id-type attribute.

    For example:

    when HTTP_REQUEST {
        PEM::subscriber create 123456789 subscriber-id-type imsi ip-address 192.168.10.100
        log local0.info "This HTTP request load balances using a fixed policy list"   
    }

Impact

BIG-IP PEM fails to create subscribers.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You cannot create a subscriber session when using the PEM::subscriber subscriber-id-type attribute.
  • You successfully create a subscriber session when using other attributes of the PEM::subscriber command.

Workaround

To work around this issue, you can use the subscriber-type attribute instead of the subscriber-id-type attribute.

Impact of workaround: Performing the recommended workaround should not have a negative impact on your system.

For example:

when HTTP_REQUEST {
    PEM::subscriber create 123456789 subscriber-type imsi ip-address 192.168.10.100
    log local0.info "This HTTP request load balances using a fixed policy list"
}
