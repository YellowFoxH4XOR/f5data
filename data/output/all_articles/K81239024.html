Description
When testing the validity of an HTTP or HTTPS monitor send string, using commands such as curl or wget add additional HTTP Headers, such as User-Agent, etc that may seem to indicate that an HTTP or HTTPS monitor send string is valid, when it's not.

Environment

  • HTTP or HTTPS Monitor
    • Custom send string

Cause
curl and wget automatically add additional HTTP headers when invoked. BIG-IP HTTP and HTTPS monitors do not automatically add any additional headers.

Recommended Actions

For HTTPS connections, use openssl s_client command to send the desired send string and test the response the pool member will provide.

Note: The following commands are written with the following assumptions. You must update these commands to be relevant to your environment.
Note: Assumption #1: Pool Member IP Address is 192.0.2.10
Note: Assumption #2: Pool Member Port is 443 for HTTPS and 80 for HTTP
Note: Assumption #3: Monitor Send string is: GET /index.html HTTP/1.1\r\nHost: example.com\r\nConnection: Close\r\n\r\n

  • Using openssl s_client to test the response of an encrypted (HTTPS) pool member in the Default Route Domain
  • Using openssl s_client to test the response of an encrypted (HTTPS) pool member in a non-Default Route Domain
  • Using netcat (nc) to test the response of an unencrypted (HTTP) pool member in the Default Route Domain
  • Using netcat (nc) to test the response of an unencrypted (HTTP) pool member in a non-Default Route Domain

Using openssl s_client to test the response of an encrypted (HTTPS) pool member in the Default Route Domain

  1. SSH to log into the Advanced Shell (bash) of the BIG-IP
  2. Run the following command:
    (echo -e "GET /index.html HTTP/1.1\r\nHost: example.com\r\nConnection: Close\r\n\r\n";sleep 1) | openssl s_client -connect 192.0.2.10:443

Using openssl s_client to test the response of an encrypted (HTTPS) pool member in a non-Default Route Domain

This scenario assumes that your pool member is in Route Domain 50 (192.0.2.10%50) See Manual Chapter : Route Domains for more information on Route Domains

  1. SSH to log into the Advanced Shell (bash) of the BIG-IP
  2. Run the following command:
    (echo -e "GET /index.html HTTP/1.1\r\nHost: example.com\r\nConnection: Close\r\n\r\n";sleep 1) | rdexec 50 openssl s_client -connect 192.0.2.10:443

Using netcat (nc) to test the response of an unencrypted (HTTP) pool member in the Default Route Domain

  1. SSH to log into the Advanced Shell (bash) of the BIG-IP
  2. Run the following command:
    (echo -e "GET /index.html HTTP/1.1\r\nHost: example.com\r\nConnection: Close\r\n\r\n";sleep 1) | nc 192.0.2.10 80

Using netcat (nc) to test the response of an unencrypted (HTTP) pool member in a non-Default Route Domain

  1. SSH to log into the Advanced Shell (bash) of the BIG-IP
  2. Run the following command:
    (echo -e "GET /index.html HTTP/1.1\r\nHost: example.com\r\nConnection: Close\r\n\r\n";sleep 1) | rdexec 50 nc 192.0.2.10 80
