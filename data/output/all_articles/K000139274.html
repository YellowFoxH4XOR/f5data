Description

This article outlines the enforcement of sub-violation the "Content-Type header in GET requests" by BIG-IP ASM, highlighting its significance in maintaining adherence to HTTP standards and best practices.

 

Environment

BIG-IP ASM (Advanced WAF) versions 12.1.3 and above

 

Cause

The enforcement of sub-violation the "Content-Type header in GET request" stems from the need to ensure compliance with HTTP standards and best practices.

It has been introduced with the implementation of ID534247.

Typically, the Content-Type header is associated with requests containing a payload, like PUT and POST requests. In contrast, GET requests are primarily used for retrieving resources and do not include a request body. When ASM encounters a Content-Type header in a GET request without a corresponding body, it interprets this as a deviation from standard behavior, hence the violation.

 

The usual header expected in place of Content-Type for GET requests is the "Accept" header, which informs the server about the types of content the client can handle. This allows the server to respond appropriately.

 

Recommended Actions

To address potential traffic blocks resulting from the presence of the Content-Type header in GET requests, consider the following actions:

 

1. Review Application Behavior: Assess your application's behavior to determine why the Content-Type header is included in GET requests. Adjustments may be necessary to align with standard HTTP practices.

2. Consider Alternative Headers: Explore alternative headers such as "Accept" for conveying client preferences in GET requests, ensuring compatibility with server responses.

3. Policy Adjustments: If necessary, consider modifying the ASM policy to disable the enforcement of the Content-Type header in GET requests. However, exercise caution as this may have security implications.

 

Additional Information

The enforcement of the sub-violation "Content-Type header in GET requests" aims to maintain consistency and security in web transactions. Although, there is no direct reference in the RFC regarding the prohibition of the Content-Type header in GET requests, adhering to HTTP standards and best practices guides our approach.
