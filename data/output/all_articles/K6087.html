Topic

Accessing Microsoft applications such as Outlook Web Access through a decrypting SSL virtual server may require use of a custom 'FRONT-END-HTTPS: on' HTTP header.

Description

When you access Microsoft applications such as Microsoft Outlook Web Access through a decrypting SSL virtual server that terminates SSL services, the back-end application server will be configured to provide HTTP services. As a result, when the application server responds to the client with dynamic links, the responses will specify the HTTP protocol. However, because the BIG-IP system is configured to respond to client requests using the HTTPS protocol, the client receives no response when it makes HTTP requests.

Some Microsoft applications, such as Microsoft Outlook Web Access, are aware of this configuration option and will specify the HTTPS protocol in responses if a custom HTTP header named FRONT-END-HTTPS with a value of on is present in the request.

Recommendations

When you configure a decrypting SSL virtual server to provide access to Microsoft Outlook Web Access servers, you should configure the HTTP profile used by the virtual server to insert an HTTP Request header named FRONT-END-HTTPS with a value of on. To do so, either create a custom HTTP profile or modify the existing custom HTTP profile used by the virtual server, with FRONT-END-HTTPS: on in the Request Header Insert field of the profile.

Note: F5 recommends that you create a custom HTTP profile instead of modifying the default HTTP profile. For information, refer to K14488: Working with profiles.
