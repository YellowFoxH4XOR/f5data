K000138170: APM: None of the configured JWK keys match the received JWT header. The trigger - JWT Audience mismatch

Type
Support Solution
Published
2024-01-09
Updated
2024-01-09
Source
https://my.f5.com/manage/s/article/K000138170

Description

BIGIP administrator may notice the below error for setup where APM is configured as oAuth Client (and/or Resource Server) under oAuth Scope agent:

Dec 28 10:01:59 bigip.local err apmd[15543]: 01490290:3: /Common/ap_test:Common:50e16731:/Common/ap_test_act_oauth_scope_ag: OAuth Scope: failed for jwt-provider-list '<name_of_JWT_provider_list>' , error: None of the configured JWK keys match the received JWT token, JWT Header: eyJ0eXAiOiJKV1QiLCJhbGciOiJSUzI1NiIsImtpZCI6IjVCM25SeHRRN2ppOGVORGMzRnkwNUtmOTdaRSJ9

The error itself may have several triggers. This article will describe the Audience mismatch trigger.

Environment

  • APM
  • oAuth
  • Audience

Cause

The Audience claim mismatch may result to the error.

Recommended Actions

Make sure that audience setting value from 'apm oauth jwt-config' matches with audience value in received access-token. For example, how the error was triggered:
1) In received on APM access-token in jwt format after decode (for instance, it can be done in https://jwt.io), in JWT Payload section it was observed the audience value:

<omitted for brevity>
"aud": "db53b685-4bde-4a67-8cd9-4074449d40e9" <<< (!)
<omitted for brevity>

2) But at the same time in 'apm oauth jwt-config' config section, the audience value was set to none:

# tmsh list apm oauth jwt-config /Common/<replace_with_name_of_jwt-config> all-properties 
apm oauth jwt-config auto_jwt_oauth-aad {
    access-token-expires-in 0
    allowed-keys {
        auto_jwk_oauth-aad1 { }
        auto_jwk_oauth-aad2 { }
        auto_jwk_oauth-aad3 { }
    }
    allowed-signing-algorithms { RS256 }
    app-service none
    audience none <<< (!)
    auto-generated true
    blacklist-access-tokens none
    blocked-keys none
    blocked-signing-algorithms none
    issuer https://login.microsoftonline.com/<tenant_id>/v2.0
    jwks-uri https://login.microsoftonline.com/<tenant_id>/discovery/v2.0/keys
    partition Common
    use-jwt-provider-list-settings true
}

And due to Audience values mismatch, it resulted to the 'None of the configured JWK keys match the received JWT token'.
3) To resolve the issue, add the audience value seen in received JWT access-token to the APM's 'apm oauth jwt-config' section similar to:

# tmsh modify apm oauth jwt-config /Common/<replace_with_name_of_jwt-config> audience add { db53b685-4bde-4a67-8cd9-4074449d40e9 }
# tmsh save sys config 

And as result of above commands, you should get the new updated provider config similar to:

# tmsh list apm oauth jwt-config /Common/<replace_with_name_of_jwt-config> all-properties
apm oauth jwt-config auto_jwt_oauth-aad {
    access-token-expires-in 0
    allowed-keys {
        auto_jwk_oauth-aad1 { }
        auto_jwk_oauth-aad2 { }
        auto_jwk_oauth-aad3 { }
    }
    allowed-signing-algorithms { RS256 }
    app-service none
    audience { db53b685-4bde-4a67-8cd9-4074449d40e9 } <<<< (!) added the audience value seen in access-token
    auto-generated true
    blacklist-access-tokens none
    blocked-keys none
    blocked-signing-algorithms none
    issuer https://login.microsoftonline.com/<tenant_id>/v2.0
    jwks-uri https://login.microsoftonline.com/<tenant_id>/discovery/v2.0/keys
    partition Common
    use-jwt-provider-list-settings true
}
