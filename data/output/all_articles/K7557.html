K7557: The OneConnect feature does not work for certain connections after upgrading to BIG-IP version 4.5.11 or later

Type

Published
2007-06-19
Updated

Status

Applies to

  • BIG-IP 4.X: 4.6.4
Source

Topic

The BIG-IP OneConnect feature allows the BIG-IP system to minimize the number of server-side TCP connections by making existing connections available for reuse by other clients.

For BIG-IP version 4.5.11, a OneConnect fix was introduced that verifies whether the client and server maximum segment sizes (MSS) are equal before reusing an existing OneConnect connection. In BIG-IP versions 4.5.11 through 4.6.4, if the client and server have the same MSS, the connections are eligible for aggregation. If the server MSS is smaller than client MSS, the connections are not eligible for aggregation.

Workaround

You can work around this issue by overriding the MSS advertised by the BIG-IP system when it accepts connections from clients. To do so, perform the following procedure:

  1. Log in to the command line.
  2. To override the MSS advertised by the BIG-IP, type the following command:

    bigpipe internal set tcphps_mss_override = <value>

    For example, if the client's advertised MSS is 1460 and the server's MSS is 960, you should set the tcphps_mss_override setting to 960 or lower. To do so, you would type the following command:

    # bigpipe internal set tcphps_mss_override = 960

  3. To ensure that the internal setting runs at system start up, add the command you used in Step 2 to the /config/startup file on the BIG-IP system.

    For example, if the desired MSS setting is 960, you would add the following command:

    # echo internal set tcphps_mss_override = 960 >>/config/startup
