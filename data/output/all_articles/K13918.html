Topic

Purpose

You should consider using this procedure under the following condition:

  • You want to configure Auto Last Hop on a BIG-IP system.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility or TMOS Shell (tmsh) on the BIG-IP system.

Description

Beginning with BIG-IP 11.0.0, you can configure Auto Last Hop globally and on an object level. The objects that have Auto Last Hop are virtual servers, SNATs, NATs, VLAN group, and VLANs. For more information on the behavior of Auto Last Hop configured across multiple network objects, refer to K13876: Overview of the Auto Last Hop setting (11.x - 17.x).

You can set Global Auto Last Hop to Enabled or Disabled, and you can configure the network object virtual server, SNAT, NAT, VLAN group, or VLAN to be Enabled, Disabled, or Default.

Procedures

Configure the settings of Auto Last Hop for:

  • Global setting
    • Modify Global Auto Last Hop using the Configuration utility
    • Modify Global Auto Last Hop using tmsh
  • Virtual servers
    • Modify Auto Last Hop on a virtual server using the Configuration utility
    • Modify Auto Last Hop on a virtual server using tmsh
  • SNATs
    • Modify Auto Last Hop on a SNAT using the Configuration utility
    • Modify Auto Last Hop on a SNAT using tmsh
  • NATs
    • Modify Auto Last Hop on a NAT using the Configuration utility
    • Modify Auto Last Hop on a NAT using tmsh
  • VLAN groups
    • Modify Auto Last Hop on a VLAN group using the Configuration utility
    • Modify Auto Last Hop on a VLAN group using tmsh
  • VLANs
    • Modify Auto Last Hop on a VLAN using the Configuration utility
    • Modify Auto Last Hop on a VLAN using tmsh

Modify Global Auto Last Hop using the Configuration utility

Impact of procedure: Depending on your network environment, you may need Auto Last Hop. F5 recommends testing the change in a test environment before making the change in production.

Note: If only BIG-IP APM or BIG-IP ASM is provisioned on your BIG-IP system and not BIG-IP LTM, Auto Last Hop may not be exposed in the Configuration utility. In that case, follow Modify Global Auto Last Hop using tmsh procedure.

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Local Traffic > General.
  3. To enable Auto Last Hop, select the check box under Properties. To disable it, clear the box.
  4. Select Update.

Modify Global Auto Last Hop using tmsh

Impact of procedure: Depending on your network environment, you may need to use Auto Last Hop. F5 recommends testing the change in a test environment before making the change in production.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable Global Auto Last Hop, enter the following command:

    modify /sys db connection.autolasthop value enable

    To disable Global Auto Last Hop, enter the following command:

    modify /sys db connection.autolasthop value disable

  3. Save the change by entering the following command:

    save /sys config

Modify Auto Last Hop on a virtual server using the Configuration utility

Impact of procedure: Depending on your network environment, you may need Auto Last Hop. F5 recommends testing the change in a test environment before making the change in production.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the name of the virtual server on which you want to modify Auto Last Hop.
  4. For Configuration, select Advanced.
  5. For Auto Last Hop, select Default, Enabled, or Disabled.
  6. Select Update.

Modify Auto Last Hop on a virtual server using tmsh

Impact of procedure: Depending on your network environment, you may need Auto Last Hop. F5 recommends testing the change in a test environment before making the change in production.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable Auto Last Hop on the virtual server, use the following command syntax:

    modify /ltm virtual <virtual_server_name> auto-lasthop enabled

    To disable the setting, use the following command syntax:

    modify /ltm virtual <virtual_server_name> auto-lasthop disabled

    To set it to default, use the following command syntax:

    modify /ltm virtual <virtual_server_name> auto-lasthop default

    For example, to enable Auto Last Hop on the virtual server named vs_1, enter the following command:

    modify /ltm virtual vs_1 auto-lasthop enabled

  3. Save the change by entering the following command:

    save /sys config

Modify Auto Last Hop on a SNAT using the Configuration utility

Impact of procedure: Depending on your network environment, you may need Auto Last Hop. F5 recommends testing the change in a test environment before making the change in production.

BIG-IP 11.3.0 and later

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Address Translation > SNAT List.
  3. Select the name of the SNAT on which you want to modify Auto Last Hop.
  4. For Auto Last Hop for this SNAT, select Default, Enabled, or Disabled.
  5. Select Update.

BIG-IP versions prior to 11.3.0

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > SNATs.
  3. Select the name of the SNAT on which you want to modify Auto Last Hop.
  4. For Auto Last Hop for this SNAT, select Default, Enabled, or Disabled.
  5. Select Update.
