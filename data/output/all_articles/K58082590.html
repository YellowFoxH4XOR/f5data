Topic

You should consider using this procedure under the following condition:

  • You want to display BIG-IP ASM learning suggestions for a security policy using the iControl REST API.

Description

As a BIG-IP administrator, you can use the iControl REST API to retrieve the policy builder learning suggestions and modify the policy suggestions as needed. This article shows you how to use the iControl REST API to display learning suggestions for a particular security policy. You can retrieve the learning suggestions by making an HTTP GET request and specifying the proper URI structure. By default, the system retrieves the first 500 entities. For more information about the iControl REST API, refer to the iControl REST user guide that applies to your BIG-IP version, available on DevCentral.

The following table lists learning suggestion properties that you can display using the iControl REST API.

PropertyDescription
idSpecifies a unique identifier for a reference.
creationDatetimeSpecifies the creation time for a suggestion, as a date-time value.
firstOccurrenceDatetimeSpecifies the first time a matching request for a suggestion occurred.
lastOccurrenceDatetimeSpecifies the last time a matching request for a suggestion occurred.
statusSpecifies the learning status of a suggestion. Possible values are: pending, ignored, accept, or status accept-and-stage. The accept-and-stage status enables the staging flag for the target entity, if applicable, and implements the changes specified in the entity Changes field.
alwaysManualIndicates that a suggestion will be learned manually, as a Boolean value. If true, a suggestion will never be learned automatically.
commentSpecifies the user's notes on the suggestion.
isReadIndicates that a suggestion has been read by a user, as a Boolean.
scoreSpecifies an index based on R2 or R3 measurement that reflects the strength of a suggestion.
triggerType or reasonSpecifies the reason for the suggestion. Possible values are violation-mitigation, policy-tightening, or policy-refinement.
violationReferenceSpecifies the type of violation that triggered a suggestion, if the trigger type is a violation. This attribute is not required.
entityChangesSpecifies the changes to apply to an entity or entity Reference if you accept the suggestion.
entityKindSpecifies the type of element for a suggestion. This attribute is not required.
entityNameSpecifies the name of an item instance. This attribute is not required.
actionSpecifies the suggested operation for an item. Possible values are: delete, add-or-update, update-append, or update-remove. This value is not required.
entity, entityReferenceSpecifies a reference to a policy if the entity exists in the policy; otherwise, specifies the details of the entity to create.
parentEntityReferenceSpecifies a reference to a parent policy entity that matched a wild card value.
occurrenceCount or occurrencesSpecifies the number of requests that triggered a suggestion.
trustedIpCount or trustedSourcesCountSpecifies the number of distinct client IP addresses, on a list of trusted clients, that triggered a suggestion.
untrustedIpCount or untrustedSourcesCountSpecifies the number of distinct client IP addresses, not on a list of trusted clients, that triggered a suggestion.
trustedSessionCountSpecifies the number of distinct client sessions, from trusted IP addresses, that triggered a suggestion.
untrustedSessionCountSpecifies the number of distinct client sessions, not from trusted IP addresses, that triggered a suggestion.
sampleRequestsSpecifies a collection of representative requests, from various IP addresses and sessions, that triggered a suggestion.
descriptionSpecifies a description of the changes to implement.
refinement, refinementReferenceSpecifies a reason for a suggestion for when a type is policy-refinement rather than violation-mitigation.
signatureReferenceSpecifies a reference to an attack signature, either as an override on another object, or to effect a change on the signature itself, such as disabling the signature.
metacharSpecifies a reference to a metachar, either as an override on another object, or to modify the metachar itself, such as allowing the character itself.
averageViolationRatingSpecifies the average violation rating for a suggestion, if applicable.
violationRatingCountsSpecifies the number of violation ratings for each request.
sectionReferenceSpecifies the category or section of the application security policy such as URLs, Cookies, Evasion Techniques, or HTTP Protocol Compliance.

curl and jq utilities

Performing the following procedure requires command-line access to a system with the curl utility and, optionally, the jq (command line JSON processor) utility installed. These utilities are commonly available on Linux systems but can also be installed on Microsoft Windows and Mac OS X systems. Additionally, you can perform this procedure on a BIG-IP system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP ASM system is licensed, provisioned, and configured with a management IP address.
  • You have administrative access to the BIG-IP Configuration utility.
  • You have login access to DevCentral to review iControl REST API documentation.

Procedures

Locating the security policy MD5 hash identifier

BIG-IP ASM security policies have a unique MD5 hash identifier that represents the policy name. You must determine the MD5 hash identifier for the policy before you can display the security policy configuration using the iControl REST API. After you have located the policy MD5 hash identifier, you include the hash value when you define the URI to retrieve the configuration elements. To determine the MD5 hash identifier for the specific policy, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to determine the MD5 hash identifier for the policy name:

    curl -sku <username:password>  https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies?\$select=name,id | jq '.'

    For example, the following command returns two security policies, parent_policy and child_policy1, and related MD5 hash identifiers (id) for host BIGIP.example.com:

    curl -sku admin:admin  https://BIGIP.example.com/mgmt/tm/asm/policies?\$select=name,id | jq '.'

Displaying learning suggestions for a security policy using the iControl Rest API

To display learning suggestions for a security policy, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to list the learning suggestions for the security policy:

    curl -sku <username:password>  https://<BIG-IP hostname or IP address>/mgmt/tm/asm/policies/<MD5hash>/suggestions | jq '.'

    For example, the following command lists the learning suggestions for the security policy with the MD5 hash identifier of 2fFJIXo8nnfwGG9O78o3ig for host bigip.example.com:

    curl -sku admin:admin  https://bigip.example.com/mgmt/tm/asm/policies/2fFJIXo8nnfwGG9O78o3ig/suggestions | jq '.'

  3. Review the learning suggestions and refer to the previous table for information about learning suggestion properties.

Displaying specific properties of the learning suggestions list using the iControl Rest API

To display only properties you specify from the suggestions for a security policy, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to display only specific properties with the jq utility in the list of learning suggestions :

    curl -sku <username:password> https://<BIG-IP hostname or IP address>/mgmt/tm/asm/policies/<MD5hash>/suggestions | jq '.items[].<property>'

    For example, the following command lists the entityName for each learning suggestion for the security policy with the MD5 hash identifier of 2fFJIXo8nnfwGG9O78o3ig on host bigip.example.com:

    curl -sku admin:admin https://bigip.example.com/mgmt/tm/asm/policies/2fFJIXo8nnfwGG9O78o3ig/suggestions | jq '.items[].entityName'

    For multiple properties, use the jq pipe operator to filter items[] by a comma separated list of properties:

    curl -sku <username:password> https://<BIG-IP hostname or IP address>/mgmt/tm/asm/policies/<MD5hash>/suggestions | jq '.items[] | .<property>,.<property2>'

    For example:

    curl -sku admin:admin https://bigip.example.com/mgmt/tm/asm/policies/2fFJIXo8nnfwGG9O78o3ig/suggestions | jq '.items[] | .description,.entityName'

  3. To optionally filter for certain properties while still displaying the kind, selfLink and top-level properties, use the following command syntax with the $select query string:

    curl -sku <username:password> https://<BIG-IP hostname or IP address>/mgmt/tm/asm/policies/<MD5hash>/suggestions?\$select=<property> | jq '.'

    For example, the following command displays the description:

    curl -sku admin:admin https://bigip.example.com/mgmt/tm/asm/policies/2fFJIXo8nnfwGG9O78o3ig/suggestions?\$select=description | jq '.'

    For multiple properties, use a comma separated list:

    curl -sku <username:password> https://<BIG-IP hostname or IP address>/mgmt/tm/asm/policies/<MD5hash>/suggestions?\$select=<property>,<property2> | jq '.'

    For example:

    curl -sku admin:admin https://bigip.example.com/mgmt/tm/asm/policies/2fFJIXo8nnfwGG9O78o3ig/suggestions?\$select=description,entityName | jq '.'
