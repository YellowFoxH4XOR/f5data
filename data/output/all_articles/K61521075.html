Description

BIG-IP failed to boot after the hypervisor outage. Once using the hypervisor console to access to the device, it can not type anything, showing the message similar to the following.

set.2./: UNEXPECTED INCONSISTENCY; RUN fsck MANUALLY.
        (i.e., without -a or -p options)

Environment

  • BIG-IP VE
  • Running software version v13.x and above
  • Hypervisor outage
  • Unable to perform file system check (unable to type anything)

Cause

Many file system failures on the BIG-IP VE.

Recommended Actions

  1. Reboot the BIG-IP VE.
  2. Access to TMOS maintenance shell, referring to K14245.
  3. Use the following command to list all partitions on the BIG-IP.

    lvscan

    The result will display similar to the following.

    bash (try 'info') / > lvscan

    ACTIVE '/dev/vg-db-sda/dat.maint.1' [200.00 MB] normal
    ACTIVE '/dev/vg-db-sda/dat.share.1' [30.00 GB] normal
    ACTIVE '/dev/vg-db-sda/dat.log.1' [7.00 GB] normal
    ACTIVE '/dev/vg-db-sda/set.1.root' [256.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.1._usr' [1.34 GB] normal
    ACTIVE '/dev/vg-db-sda/set.1._config' [512.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.1._var' [3.00 GB] normal
    ACTIVE '/dev/vg-db-sda/set.2.root' [256.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.2._usr' [1.34 GB] normal
    ACTIVE '/dev/vg-db-sda/set.2._config' [512.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.2._var' [3.00 GB] normal
    ACTIVE '/dev/vg-db-sda/set.3.root' [256.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.3._usr' [1.25 GB] normal
    ACTIVE '/dev/vg-db-sda/set.3._config' [512.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.3._var' [3.00 GB] normal
     
  4. Use the following command to recover the file system.

    *** You need run the command on all partitions listed above ***

    e2fsck -yf <partition_name>

    For the example:

    e2fsck -yf /dev/vg-db-sda/dat.maint.1
     
  5. Reboot the device after check all file systems.

    reboot

Additional Information

If this procedure is unable to fix the issue, you may need to copy the configuration via accessing MOS mentioned on K14245 and create a new instance with using the configuration.
