K14604: The BIG-IP ASM system may incorrectly reset an established connection when Data Guard is enabled

Known Issue

The BIG-IP ASM system may incorrectly reset an established connection. This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM security policy is configured with either the Cross Site Request Forgery (CSRF) Protection or the Web Scraping Detection enabled
  • The BIG-IP ASM security policy is configured with the Data Guard feature to mask sensitive data

    Note: The Data Guard feature can either mask sensitive data or block a response depending on the security policy configuration. For more information about the two different operating modes for the Data Guard feature, refer to the Protecting sensitive data section under the Manually Configuring Security Policies chapter of the Configuration Guide for BIG-IP Application Security Manager.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Impact

Clients may experience failed connections.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP ASM system resets existing connections
  • In the /var/log/ltm file, you may observe an error message similar to the following example:

    http_process_state_prepend - Invalid action EV_INGRESS_DATA during ST_HTTP_PREPEND_HEADERS (Server side: vip=<vs name> profile=<http profile> pool=<pool name>)
  • In the response payload captured by the mpidump utility, you may observe an error message similar to the following example:

    ERROR: ERR_BOUNDS

Workaround

There is no workaround for this issue. However, you may be able to mitigate this issue by disabling the Data Guard feature. To do so, perform the following procedure:

Impact of workaround: The BIG-IP ASM system will no longer mask sensitive data when the Data Guard feature is disabled.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Application Security.
  3. Click Data Guard.
  4. Clear the Enable Data Guard check box.
  5. Click Save.
  6. Click Apply Policy.
