Description

iRule stops working after enabling TLS 1.3.

Environment

  • TLS 1.3 enabled
  • iRule with SSL::renegotiate

Cause

Renegotiation is removed in TLS 1.3, so SSL::renegotiate cannot be used. TLS 1.3 connections that trigger an SSL::renegotiate will fail silently.

Recommended Actions

Remove the SSL::renegotiate command from the iRule, or rewrite the iRule in such a way to ensure that SSL::renegotiate only triggers for non TLS 1.3 connections.

Additional Information

With earlier versions of TLS, SSL::renegotiate may be used to enforce new encryption settings or certificate requirements for certain URIs.

TLS 1.3 introduces the Post-Handshake Authentication feature, which allows a server to send a CertificateRequest after the initial TLS handshake has completed.

The BIG-IP does not currently support Post-Handshake Authentication. See the following article for more information:

  • K52170084: BIG-IP does not support TLS 1.3 Post-Handshake Authentication
