Topic

F5 Support requests a range of different diagnostic files from customers to help resolve technical support issues. Organizations may be restricted by confidentiality policies or contractual obligations when sharing these files. This article provides an overview of the different files F5 Support requests from customers and how engineers can help customers better understand what they are sharing and make a better assessment on whether the files contain sensitive or confidential data.

Description

When making an assessment on whether a file contains sensitive or confidential data, you should consider the following factors:

Classifying sensitive information

You need to understand what an organization considers as sensitive. Some organizations consider server and network infrastructure information sensitive while others consider only user production traffic that goes through a virtual server sensitive. The following describes some of the different categories of information:

  • Usernames and passwords include encrypted passwords and passphrases such as those found in /config/bigip.conf. The BIG-IP system's Secure Vault feature uses a hardware-protected master key to encrypt and decrypt passwords and passphrases stored in BIG-IP configuration files. For more information, refer to K9420: Installing UCS files containing encrypted passwords or passphrases (11.5.x and later).
  • SSL certificates and keys used in SSL profiles include private keys used to encrypt and decrypt traffic data through a virtual server.
  • Server-side information includes server hostnames, IP addresses, and other network infrastructure information.
  • Client-side information includes client IP address, proxy IP addresses, browser information, user and device information such as file and folder names, and names of software on client system.
  • Production traffic refers to traffic through a virtual server that contains user and application data.

Modules provisioned and specific configurations on the BIG-IP system

The amount of detail stored on a BIG-IP system varies depending on the modules provisioned. A BIG-IP APM system typically contains information such as users' usernames, Client IP addresses, and, depending on the logging verbosity configured in logging profiles, APM session variables or Active Directory/LDAP information which may reveal user login information, organizational structure, and so on. Similarly, BIG-IP ASM systems stores event logs with client requests and responses that contains client-side information such as origin IP addresses, browser information, HTTP headers, and so on.

Configuration files may also contain names of policies and profiles that may reveal department names, organization structure, and product information.

Logging verbosity and additional logging sources

The logging verbosity and logging profile configurations on the system can determine how much information goes into the log files. In addition, some BIG-IP systems may be configured with additional logging sources such as iRules logging, iCall, and other customizations that may add additional information to log files and files not located in the default /var/log log directory.

Customizations

System administrators may save files (such as tcpdump captures) through customized scripts or during troubleshooting in locations that may be picked up and saved when generating F5 archive files such as qkview, UCS archive, asmqkview, or the BIG-IP APM's Client Troubleshooting Utility (CTU) report.

Recommendations

While customers and administrators of the BIG-IP system are the best judge of which data is sensitive and confidential, F5 Support engineers are familiar with the kind of files, where they are located in the system, and what files are included in archive files such as the qkview, UCS archives, and so on. Support engineers should consider the following factors when assisting the customer make an accurate assessment on the confidentiality of the data before the customer shares it with F5 Support:

  • Help the customer understand the contents they are sharing, in particular the data collected in archive files such as qkview, UCS archives, and so on. Provide options (such as command-line switches) when available to exclude files that may contain restricted content.
  • Understand the BIG-IP modules provisioned and BIG-IP configurations specific on the system and provide appropriate advice.
  • Remind customers of customizations that may lead to exceptions where files are saved.
