Description

Applications running in a Kubernetes cluster use DNS resolution to discover services in the cluster. You usually configure your application to reach other services using the service’s DNS domain name instead of IP address. IP addresses assigned to pods and services in Kubernetes are dynamic and may change. A DNS server is running in every Kubernetes cluster and every pod is configured to use the internal DNS server for domain name resolution. DNS requests by default are not intercepted by istio-proxy sidecars and every application tries to resolve the DNS name before opening the connection to another service. DNS Proxy is a new feature added in the Aspen Mesh 1.9 release which may help to control DNS Resolution in pods running with istio-proxy sidecars within the Aspen Mesh service. There are pros and cons of using DNS Proxy in the service mesh. They are explained in the DNS Proxy section of the Istio documentation here:

In this article we are going to describe how to enable DNS Proxy, how it is designed and how to debug the proxy.

Note: In Aspen Mesh 1.9.x DNS Proxy is not supported in clusters deployed in Istio CNI mode. Support for DNS Proxy in CNI clusters will be added in Aspen Mesh 1.10.

Note: DNS Proxy is an alpha feature and it may be changed, redesigned or removed in the next releases.

Enable DNS Proxy in Aspen Mesh
You can enable DNS Proxy in Aspen Mesh globally or for only specific pods.
To enable DNS Proxy globally, for every pod in the service mesh, perform the following procedure:

  1. Add the following DNS Proxy config to the meshConfig  section in your values.yaml Helm file.

    meshConfig:
      defaultConfig:
        proxyMetadata:
          # Enable basic DNS proxying
          ISTIO_META_DNS_CAPTURE: "true"
          # Enable automatic address allocation, optional
          ISTIO_META_DNS_AUTO_ALLOCATE: "true

  2. Upgrade the Istiod chart configuration by running the following command:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery --namespace istio-system --values values.yaml

To enable or disable DNS Proxy for a specific pod in the service mesh you must add an annotation for your pod yaml manifest. You do not have to enable DNS Proxy globally to enable this feature for a specific pod. The pod level configuration will overwrite the global configuration.

  1. Add the following annotations to your pod/deployment

    annotations:
      proxy.istio.io/config: |
        proxyMetadata:
          ISTIO_META_DNS_CAPTURE: "true"
          # optional
          ISTIO_META_DNS_AUTO_ALLOCATE: "true"

  2. Restart the pod

How DNS Proxy is implemented in Aspen Mesh

Istio-proxy intercepts all DNS queries from the application container. The interception is done in the same way istio-proxy intercepts other types of traffic, by iptables rules. Istio adds additional iptables rules to redirect all DNS packets on port 53 (TCP and UDP) that is sent to the Kubernetes DNS service (e.g. kube-dns), to port 15053 as follows:

# 100.64.0.10/32 is k8s kube-dns service IP
-A OUTPUT -d 100.64.0.10/32 -p udp -m udp --dport 53 -j REDIRECT --to-ports 15053
-A ISTIO_OUTPUT -d 100.64.0.10/32 -p tcp -m tcp --dport 53 -j REDIRECT --to-ports 15053

DNS queries are redirected to the pilot-agent process running in the istio-proxy container which is listening on port 15053 as shown in the following output:

$ oc debug node/worker-20 -- chroot /host nsenter -t 281039 -n sudo /usr/bin/nsenter --target 281039 -n netstat -anp | grep -i 15053
netstat -anp | grep -i 15053
tcp        0      0 127.0.0.1:15053         0.0.0.0:*               LISTEN      281039/pilot-agent
udp        0      0 127.0.0.1:15053         0.0.0.0:*                           281039/pilot-agent

The pilot-agent process has local DNS server running on port 15053 and it stores DNS records for every Kubernetes service discovered by the Istio Name Discovery Service (NDS) and also DNS records for all dummy IPs assigned by Istio, e.g. to external ServiceEntries (without wildcard hosts) with DNS resolution set to DNS or STATIC. To assign dummy IP addresses to our external services, configured with the ServiceEntry object, you have to enable ISTIO_META_DNS_AUTO_ALLOCATE on our pod.

# dummy IPs assigned to external services:
? istioctl pc listener sleep-657956d474-kgm8b.ns2 --port 9080
ADDRESS     PORT MATCH DESTINATION
203.0.113.1 9080 ALL   Cluster: outbound|9080||test1.aspenmesh.local.com
203.0.113.2 9080 ALL   Cluster: outbound|9080||test2.aspenmesh.local.com

DNS Proxy along with ISTIO_META_DNS_AUTO_ALLOCATE can solve the problem of TCP ServiceEntries configured with the same TCP Port and without address fields. Without DNS Proxy you could have only 1 TCP ServiceEntry in the namespace or you would have to configure the address field.

The following is an example of TCP ServiceEntries using the same TCP port:

apiVersion: networking.istio.io/v1alpha3
kind: ServiceEntry
metadata:
  name: test1-servicentry
spec:
  hosts:
  - test1.aspenmesh.local.com
  ports:
  - number: 9080
    name: tcp
    protocol: TCP
  location: MESH_EXTERNAL
  resolution: DNS
---
apiVersion: networking.istio.io/v1alpha3
kind: ServiceEntry
metadata:
  name: test2-servicentry
spec:
  hosts:
  - test2.aspenmesh.local.com
  ports:
  - number: 9080
    name: tcp
    protocol: TCP
  location: MESH_EXTERNAL
  resolution: DNS

Enable debug logs for DNS Proxy and pilot-agent

To enable debug logs for DNS Proxy and pilot-agent you have to add additional annotations in the pod yaml manifest as follows:

     annotations:
        sidecar.istio.io/agentLogLevel: "dns:debug

Once the debug is enabled you can see debug logs in the istio-proxy container with the following command:

? kubectl logs -n ns-dns nettools-deploy-8fd7f8b78-9tb77 -c istio-proxy | grep debug
