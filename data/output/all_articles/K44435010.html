Description

When you run a config sync from Standby to Active, "Suggestions" may be deleted automatically on Active.
However it is an expected behavior of suggestion when running config-sync.

Here are two examples, both cases are expected behavior of ASM;

[Example 1]
  - Before config-sync:
     Active  "Have Suggestion": 1
     Standby "Have Suggestion": 0
  - Config-sync from Standby to Active
  - After config-sync:
     Active  "Have Suggestion": 0
     Standby "Have Suggestion": 0
*The suggestion on Active is deleted after config sync.


[Example 2]
  - Before config-sync:
     Active  "Have Suggestion": 0
     Standby "Have Suggestion": 1
  - Config-sync from Standby to Active
  - After config-sync:
     Active  "Have Suggestion": 0
     Standby "Have Suggestion": 1
*The suggestion on Active shows still "0" suggestion after config sync.

Environment

  • BIG-IP ASM
  • Running Config-Sync from Standby to Active

Cause

It is by design.

"Suggestions" itself is not synced.
However the statistics (suggestion is created based on this statistics) is synced.
When running the config sync from Standby to Active, the old or empty statistics is synced to Active.
Active device is creating a suggestion based on the old or empty statistics.
Because the statistics are old or empty, Active device creates 0 suggestion.
So this is expected behavior, the "Suggestions" will be deleted automatically on Active when running config sync from Standby to Active.
 

Recommended Actions

If you would not like to delete the suggestion on Active device,
Please refrain from running config sync from Standby to Active.

Or, please review and take a "action" (Ex.ignoring/accepting a suggestion) before running config-sync.
