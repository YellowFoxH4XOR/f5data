Description

Client connects to the VPN through browser and then closes the browser (in this scenario the VPN still remains on).
Although the Client doesn't realise this and tries to login to access policy through browser again but cannot get connect and shows disconnected.

The Client cannot login again, unless their first active session which was created was manually killed or inactivity timeout triggers.

Environment

  • APM - network access
  • Browser based VPN

Cause

When the Client closes the browser there is no way the APM gets any kind of communication that main webtop browser is closed.

Recommended Actions

There are a couple options that can be used to workaround this issue:
  1. Go to Access > Connectivity / VPN > Network Access (VPN) > Network Access Lists > (network_access_resource) > Network Settings > Client Power Management -> set to Terminate
    ==> This scenario will be terminate the VPN when Client closes the laptop or goes in hibernate or sleep mode
     
  2. Reduce Inactivity Timeout to 1 or 2 hours.
Additional Information

Extracted from Manual Chapter : Configuring Network Access Resources:

Client Power Management    Ignore, Prevent, or TerminateSpecifies how network access handles client power management settings, for example, when the user puts the system in standby, or closes the lid on a laptop.
    • Ignore
    - ignores the client settings for power management.
      • Prevent
      - prevents power management events from occurring when the client is enabled.
        • Terminate
        - terminates the client when a power management event occurs.
