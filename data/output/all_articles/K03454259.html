K03454259: BIG-IP DNS configuration fails to synchronize when iQuery reports the server type as BIGIP instead of BIGIP-DNS

Type
Support Solution
Published
2026-08-25
Updated
2026-08-25
Applies to
  • BIG-IP
  • BIG-IP GTM
  • BIG-IP DNS: 15.0.0, 15.0.1, 15.1.0, 15.1.1, 15.1.2, 15.1.3, 15.1.4, 15.1.5, 15.1.6, 15.1.7, 15.1.8, 15.0.X, 15.1.X, 15.X.X
Source

Description

You may observe the following symptoms while troubleshooting a BIG-IP DNS synchronization issue:

  • DNS configuration fails to synchronize to a peer device that is in the same sync group.
  • iQuery is full-meshed.
  • When you check the iQuery details for the server type, you find that some iQuery connections are recognized as BIGIP, but not BIGIP-DNS.
tmsh show gtm iquery
--------------------------------------------------------------------------------

Gtm::IQuery: 192.168.1.1
--------------------------------------------------------------------------------
Server                                                                         Server1
Server Type                                                                      BIGIP<--------Server1 should be BIGIP-DNS server type
Data Center                                                                         DC1
Connection Time                                                       05/07/21 18:15:50
State                                                                         connected
Connection ID                                                                         8
Reconnects                                                                            0
--------------------------------------------------------------------------------
Gtm::IQuery: 192.168.2.2
--------------------------------------------------------------------------------
Server                                                                         Server2
Server Type                                                                   BIGIP-DNS
Data Center                                                                         DC1
Connection Time                                                       05/07/21 18:15:50
State                                                                         connected

Environment

  • BIG-IP DNS
  • iQuery
  • Sync Group

Cause

An incorrect DNS configuration, such as the following, can trigger the symptoms described above.

For example, 192.168.1.1 and 192.168.2.2 are non-floating self IP addresses on one physical DNS server, but the DNS server is incorrectly configured as two devices, as shown below:

tmsh list gtm server
gtm server /Common/DNSserver {
    datacenter /Common/EUR
    devices {
        DNSserver1 {
            addresses {
                192.168.1.1 { }
            }
        }
        DNSserver2 {
            addresses {
                192.168.2.2 { }
            }
        }
    }

Answer/Recommended Actions

Correct the configuration as below: remove DNSserver2 and add 192.168.2.2 to DNSserver1.

tmsh list gtm server
gtm server /Common/DNSserver
 {
    datacenter /Common/EUR
    devices {
        DNSserver {
            addresses {
                192.168.1.1 { }
                192.168.2.2 { }
            }
        }
    }
