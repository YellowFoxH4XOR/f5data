Known Issue

Virtual servers with Client SSL profiles may not respond to Secure Sockets Layer (SSL) handshakes after a configuration synchronization (ConfigSync).

This issue occurs when all of the following conditions are met:

  • You delete a key/cert pair from a Client SSL profile on a BIG-IP system.
  • You then create a new key/cert pair with the same name as the previously deleted key/cert pair.
  • You synchronize to another BIG-IP system in the device group.
  • Your system does not have automatic ConfigSync enabled.

This issue can affect the device that receives the ConfigSync, and may also occur after an upgrade following the first ConfigSync in a device group.

Impact

SSL traffic to affected virtual servers may be disrupted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H491316 on the Diagnostics > Identified > Medium screen.
  • SSL-enabled virtual servers fail to negotiate SSL handshakes.
  • When you perform a packet capture on SSL traffic of an affected virtual server, the BIG-IP system acknowledges the Client Hello message, but does not respond with a Server Hello message.
  • The system logs an error message to the /var/log/ltm file that appears similar to the following example:

    crit tmm[<pid>]: 01260000:2: Profile /Common/<profile>: could not load key/certificate

    In this error message, note the following:
    • <pid> is the process ID of the tmm process and <profile> is the name of the SSL profile.

Workaround

To work around this issue, you can perform a ConfigSync after deleting the cert/key pair, and then again after creating the new cert/key pair of the same name.

If this issue has already occurred, you must restart the tmm process to restore the SSL client. To do so, perform one of the following procedures:

Impact of workaround: The BIG-IP system goes offline and temporarily stops processing traffic. These procedures should be performed while the BIG-IP system is in a standby state or during a maintenance window.

Restarting the tmm process on a BIG-IP system from the shell command prompt

  1. Log in to the BIG-IP system as the root user.
  2. To restart the tmm process, type the following command:

    bigstart restart tmm

Restarting the tmm process on a BIG-IP system from the tmsh utility

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To restart the tmm process, type the following command:

    restart sys service tmm
