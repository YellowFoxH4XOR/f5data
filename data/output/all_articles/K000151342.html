Description

After enabling TACACS+ authentication on BIG-IP, access to the device using the local "root" account via CLI may fail. Attempts to log in as "root" result in authentication failure, even if the TACACS+ shared secret does not contain a pound sign (#), which is a known cause of authentication issues. No specific error message may be displayed, but login is unsuccessful.

Environment

  • Authentication
  • Tacacs Authentication
  • Default root account
  • SSH Login Failure
  • TACACS+ shared secret does not contain a pound sign (#).
  • "Fallback to Local" is enabled
  • GUI
  • CLI

Cause

The root account is disabled in the BIG-IP configuration. When the root account is disabled (via BIG-IP GUI > System > Platform > Root Account), it cannot be used for CLI or SSH access, regardless of TACACS+ configuration or shared secret content.

Recommended Actions

Please follow the troubleshooting steps as listed below:

  1. Check Root Account Status:

    • Navigate to BIG-IP GUI > System > Platform > Root Account.
    • Ensure the root account is enabled. If it is disabled, enable it and set a new password.

  2. Review Authentication Configuration:

    • Confirm that local authentication is still permitted for the root account.
    • Verify that "Fallback to Local" is enabled if you want local accounts to be accessible when TACACS+ is active.

  3. TACACS+ Shared Secret:

    • Ensure the TACACS+ shared secret does not contain unsupported characters such as the pound sign (#), as this can cause authentication failures for all administrative accounts.

  4. Console Access:

    • If locked out, attempt to access the device via direct console. If console access is also blocked, recovery via single-user mode may be required.

  5. Logs and Troubleshooting:

    • Review /var/log/secure for authentication-related errors.
    • If further troubleshooting is needed, generate a qkview file from the CLI using the qkview command.

  6. Restore Access if Locked Out:

    • If unable to regain access, follow the procedure to revert to local authentication by booting into single-user mode.
