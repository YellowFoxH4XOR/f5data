Issue

Depending on the type of service an application is configured for, the application may attempt to access both TCP and UDP ports for a virtual server. Examples of applications that use UDP services include DNS and RealMedia servers.

By default, UDP is disabled for services on BIG-IP. If an application using UDP attempts to connect to a virtual address on BIG-IP, for which UDP ports are disabled, you will receive a message similar to the following:

kernel: denial: no idle timeout for this udp port
kernel: denial: no idle timeout for this udp port 192.168.1.200:4555 -> 
192.168.64.11:25

To avoid this error, enable UDP services and specify an idle connection timeout. This is required because, unlike TCP, UDP is a connectionless protocol that has no mechanism for maintaining end-to-end packet tracking; UDP simply streams data to a destination address. When a BIG-IP receives a UDP packet stream, it selects a node to load balance the stream to, and if the UDP stream is idle for a certain amount of time, it stops the stream to the node and load balances any new streams. This is why the error message includes the idle timeout.

For more instructions about how to enable UDP services on BIG-IP, refer to the BIG-IP Reference Guide specific to the version of BIG-IP that you are running.
