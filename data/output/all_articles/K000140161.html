Topic

This article describes the available methods for finding the serial number of the transceiver module (SFP/SFP+/QSFP+/QSFP28) installed in your VELOS partition or F5 rSeries hardware product. The serial number of a transceiver module is necessary whenever you request a replacement transceiver module from F5.

Description

You can find the serial number of a transceiver module installed in your VELOS partition or F5 rSeries hardware product using the following methods:

  • Physical product label
  • QKView uploaded to F5 iHealth
  • F5OS-C/A command line (CLI)
  • F5OS-C/A REST API

Physical product label

You should use this method if you have already pulled out the non-functioning transceiver module from your VELOS partition or F5 rSeries hardware product. On one side of every transceiver module, there is a product label that includes the model and serial number. The serial number is usually listed as S/N on the label. For information on the location of the label for each type of transceiver module, refer to the following articles:

  • K6097: Specifications of the Fiber Gigabit Ethernet SFP, XFP, SFP+, QSFP+, and QSFP28 module ports on BIG-IP system platforms
  • K12287: Specifications for the Copper Gigabit Ethernet SFP module ports on BIG-IP system platforms

QKView uploaded to F5 iHealth

You can generate a QKView file from your VELOS partition or F5 rSeries hardware product and upload it to F5 iHealth. For information about generating a QKView file from your VELOS partition or F5 rSeries hardware product and uploading it to F5 iHealth, refer to the following articles appropriate for your hardware product:

  • K02521182: Generating diagnostic data for the VELOS system using the qkview utility
  • K04756153: Generating diagnostic data for rSeries systems using the qkview utility
  • K25613593: Generating a QKView diagnostic file on the VELOS and rSeries systems using the REST API
  • K000134530: Upload rSeries and VELOS system QKView diagnostic files to iHealth

Perform the following procedure to find the serial number of the transceiver modules using the QKView file uploaded to F5 iHealth:

Impact of procedure: Performing this procedure should not have any negative impact on the system.

  1. Log into the F5 iHealth portal.
  2. Select the QKView you have uploaded for your VELOS partition or F5 rSeries hardware product.
  3. Select Commands > Standard.

     

  4. Select the following based on your hardware product.

    VELOS: partitionX_manager > partition2_manager - /confd/scripts/f5_confd_run_cmd show portgroups; where X is the partition number. This should bring up a new window displaying the output collected for this command.

    rSeries: system_manager > system_manager - /confd/scripts/f5_confd_run_cmd show portgroups. This should bring up a new window displaying the output collected for this command.

  5. Scroll to the port number you are looking for and you should find the serial number in the state vendor-serialnum row. If there is no transceiver module installed in that port, the port does not show any state information.

F5OS-C/A command line (CLI)

If the transceiver module is still functional and installed in your VELOS partition or F5 rSeries hardware product, you can login to the command line (CLI) to find the serial number of the transceiver module. To do so, perform the following procedure:

Impact of procedure: Performing this procedure should not have any negative impact on the system.

  1. Log in to the command line (CLI) of the VELOS partition as the partition admin user or the F5 rSeries system as the admin user.
  2. To find the serial number of all existing installed transceiver module in the system, enter the following command:

    show portgroups portgroup state vendor-serialnum

    The command should return an output similar to the following example:

    PORTGROUP                    
    NAME       VENDOR SERIALNUM  
    -----------------------------
    1/1        X9KBNKB           
    3/1        X9KBN9J           

    If you are looking for the serial number of a specific port, enter the following command:

    show portgroups portgroup <port number> state vendor-serialnum

    For example, you would enter the following command to find the serial number of port 1/2 in a VELOS partition:

    show portgroups portgroup 1/2 state vendor-serialnum

F5OS-C/A REST API

If the transceiver module is still functional and installed in your VELOS partition or F5 rSeries hardware product, you can send representational state transfer (REST) API query to the hardware product to find the serial number of the transceiver module. To do so, perform the following procedure:

Impact of procedure: Performing this procedure should not have any negative impact on the system.

  1. Log in to a local workstation that has network access to the management interface of your VELOS partition or F5 rSeries hardware product. Additionally, the local workstation should be installed with the curl and jq utilities.
  2. Using the curl and jq utilities, send the following curl command to query for the serial number of the transceiver modules installed in the VELOS partition or F5 rSeries hardware product:

    curl -X GET -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/f5-portgroup:portgroups/portgroup" | jq '.[][] | { "portgroup": .portgroup_name, "part number": .state."vendor-partnum", "serial number": .state."vendor-serialnum" }'

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the VELOS partition or F5 rSeries hardware product.
    • <mgmt_address> is the host name or management IP address of the VELOS parition or F5 rSeries hardware product.

    For example,

    curl -X GET -sku admin:admin -H "Content-Type: application/yang-data+json" "https://192.168.81.60/api/data/f5-portgroup:portgroups/portgroup" | jq '.[][] | { "portgroup": .portgroup_name, "part number": .state."vendor-partnum", "serial number": .state."vendor-serialnum" }'

    The command should return an output similar to the following example:

    {
      "portgroup": "1/1",
      "part number": "OPT-0031        ",
      "serial number": "X9KBNKB         "
    }
    {
      "portgroup": "1/2",
      "part number": null,
      "serial number": null
    }
    {
      "portgroup": "3/1",
      "part number": "OPT-0031        ",
      "serial number": "X9KBN9J         "
    }
    {
      "portgroup": "3/2",
      "part number": null,
      "serial number": null
    }

    If you only want to query for the serial number of the transceiver module installed in a specific port, send the following curl command:

    curl -X GET -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/f5-portgroup:portgroups/portgroup=<port_number>/state/vendor-serialnum"

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the VELOS partition or F5 rSeries hardware product.
    • <mgmt_address> is the host name or management IP address of the VELOS partition or F5 rSeries hardware product.
    • <port_number> is the port of the blades assigned to a VELOS partition or the port on the F5 rSeries hardware product. The ports in a VELOS partition is represented in the format of <blade number>/<blade port number>; for example, 1/2 means port number 2 on blade 1 of the VELOS partition.

      Note: When sending the VELOS partition port number in the REST API query, you have to convert the slash (/) character to the URL ASCII Encoding format %2F.

    For example, if you want to query for the serial number of the transceiver module installed in port 1/1:

    curl -X GET -sku admin:admin -H "Content-Type: application/yang-data+json" "https://192.168.81.60/api/data/f5-portgroup:portgroups/portgroup=1%2F1/state/vendor-serialnum"

    The command should return an output similar to the following:

    {
      "f5-portgroup:vendor-serialnum": "X9KBNKB         "
    }

    Note that if there is no transceiver module installed in the queried port, the command would return an error similar to the following example:

    {
      "ietf-restconf:errors": {
        "error": [
          {
            "error-type": "application",
            "error-tag": "invalid-value",
            "error-message": "uri keypath not found"
          }
        ]
      }
    }
