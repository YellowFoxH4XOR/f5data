Description

Integration with BIG-IP APM and Microsoft Intune

when querying for Windows 10 devices, the BIG-IP APM is unable to query the compliance status of a Windows 10 device against MS Intune.

In the APM logs, a log message similar to the below can be seen

Feb 27 12:44:50 bigip1 err apmd[18663]: 01490254:3: /Common/test_AP:Common:eae0544f: mdm [/Common/ems_intune:ms-intune]: Device ID was not found in session variables

Environment

  • BIG-IP APM
  • Microsoft Intune
  • Windows 10

Cause

BIG-IP APM does not support compliance check for Windows 10 devices against Microsoft Intune. F5 VPN clients (either F5 Access or BIG-IP Edge Client) on Windows 10 cannot extract a unique device ID that APM could use for compliance check queries against MS Intune. This is the reason why you're seeing that Device ID was not found in session variables error log

Recommended Actions

You can workaround this limitation by pushing a temporary user certificate (valid for 60 mins) from Azure AD (a.k.a. Azure AD Conditional Access) into the F5 VPN client, if the device is compliant and user authenticated.
