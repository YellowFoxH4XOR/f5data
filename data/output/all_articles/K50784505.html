Description

This article applies to BIG-IP 10.1.x through 11.4.x. For information about other versions, refer to the following article:

  • K9420: Installing UCS files containing encrypted passwords or passphrases (11.5.x and later)

Some BIG-IP configuration items, such as monitors and SSL profiles, may require the use of passwords or passphrases. To add an extra layer of security, the BIG-IP system stores these passwords and passphrases in the configuration file in an encrypted format, with the prefix $M$. For example:

passphrase $M$g2$UEOTKSvSN/7kasHTLIBsEw==
password $M$Sx$z5wBus7I+VhvLCndYNz+Mg==

The BIG-IP system's Secure Vault feature uses a hardware-protected master key to encrypt and decrypt passwords and passphrases stored in BIG-IP configuration files. In some cases, such as when preparing to install a UCS file containing encrypted passwords or passphrases on a new BIG-IP system, you may need to recover the master key by performing one of the procedures in this article.

Important: After you encrypt configuration object passwords or passphrases, you can decrypt them only by using the same master key that you used to encrypt them. F5 recommends that you retain a record of each configuration object password or passphrase in a secure location on a system other than the BIG-IP system that uses the password or passphrase. Doing so makes it possible for you to restore a UCS configuration archive when the original master key is not available.

Decryption Errors

When you attempt to install a UCS file or load a configuration that contains passwords or passphrases encrypted with a different master key, the UCS installation fails and the system displays an error message that appears similar to one of the following examples:

0107102b:3: Master Key decrypt failure - decrypt failure - final
01071769:3: Decryption of the field (pvalue) for object (/Common/http_monitor_example 1 PASSWORD=) failed.
01071769:3: Decryption of the field (passphrase) for object (/Common/client_ssl_example example_encrypt) failed.

Potential UCS file installation issues

F5 strongly recommends that you be familiar with UCS file installation prior to performing the procedures detailed in the Procedures section of this article. Installation failure may result if you don’t fully understand UCS licensing and hardware considerations.

  • Licensing: Before installing a UCS file on a new BIG-IP system, for example a Return Materials Authorization (RMA) device, read the information in the Licensing section of K13132: Backing up and restoring BIG-IP configuration files.
  • Hardware platforms: Before moving a UCS file from one hardware platform type to another, for example from a Virtual Clustered Multiprocessing (vCMP) guest to a hardware device, read K82540512: Overview of the UCS archive platform-migrate option.

DSC ConfigSync option

You can use device service clustering (DSC) configuration synchronization (ConfigSync) to restore a BIG-IP system's configuration instead of installing a UCS file. When replacing an existing BIG-IP system peer in a DSC high-availability (HA) configuration, F5 recommends that you first configure basic networking on the replacement BIG-IP system and then join the new BIG-IP system to the DSC device group. After the BIG-IP system becomes a member of the device group, you can run ConfigSync from a peer that has the current configuration. ConfigSync synchronizes the original master key and the configuration to the newly installed BIG-IP system. For more information about setting up DSC device groups, refer to the following articles:

  • K13649: Creating a device group using the Configuration utility
  • K13639: Configuring a device group using tmsh

Procedures

When preparing to install a UCS file containing encrypted passwords or passphrases on a new BIG-IP system, you may encounter one of the scenarios described in this section. Perform the procedure most relevant to your scenario.

  • You don't know the master key password or passphrase, you don't have access to the original BIG-IP system, and you don't know the configuration object passwords or passphrases
  • You don't know the BIG-IP system master key password or passphrase but have access to the original BIG-IP system
  • You don't know the master key password or passphrase and don't have access to the original BIG-IP system, but you know the configuration object passwords or passphrases

You don't know the master key password, you don't have access to the original BIG-IP system, and you don't know the configuration object passwords or passphrases

BIG-IP 11.0.0 - 11.4.x

If you don't know the original unencrypted passwords or passphrases for your configuration objects, you can manually copy the master key from the peer system and then install the UCS file to restore the configuration. To do so, perform the following procedure:

  1. Log in to the peer BIG-IP system command line.
  2. From the active peer BIG-IP system, obtain the master key by typing the following command:

    f5mku -K

    The command output appears similar to the following example:

    oruIVCHfmVBnwGaSR/+MAA==

  3. Copy the output.

    Note: The output is the master key that you will install on the RMA BIG-IP system.

  4. Log in to the RMA BIG-IP system command line.
  5. Install the master key that you copied in step 3 to the RMA BIG-IP system using the following command syntax:

    f5mku -r <key_value>

    For example:

    f5mku -r oruIVCHfmVBnwGaSR/+MAA==

  6. Verify that the master key is the same on the active peer BIG-IP system and the RMA BIG-IP system by typing the following command from the command lines of both systems:

    f5mku -K

  7. Restore the UCS file to the RMA BIG-IP system using the following command syntax:

    tmsh load sys ucs <file_name>.ucs no-license

  8. To save and load the configuration and to ensure no errors exist, type the following commands from the RMA BIG-IP system command line:

    tmsh save sys config

    tmsh load sys config

  9. Set the active peer BIG-IP system as the sync leader using the following command syntax:

    tmsh modify cm device-group <device_group> devices modify { <Active peer BIG-IP> { set-sync-leader } }

    In this command, note the following:

    • <device_group> is the name of the device group for the active peer system and the RMA BIG-IP system.
    • <Active peer BIG-IP> is the host name of the active peer BIG-IP system.
  10. To sync the configuration to the RMA BIG-IP system, use the following command syntax from the active peer BIG-IP system command line:

    tmsh run cm config-sync to-group <device_group>

    Note: This command can take up to a full minute to initialize the new configuration on the RMA device.

  11. Verify the sync status by typing the following command:

    tmsh show cm sync-status

BIG-IP 10.x

If you don't know the original unencrypted passwords or passphrases for your SSL private keys, you can manually copy the master key from the peer system and then install the UCS file to restore the configuration using tmsh. To do so, perform the following procedure::

Restoring the configuration by using tmsh

  1. Log in to the peer BIG-IP system command line.
  2. From the active peer BIG-IP system, obtain the master key by typing the following command:

    f5mku -K

    The command output appears similar to the following example:

    oruIVCHfmVBnwGaSR/+MAA==

  3. Copy the output.

    Note: The output is the master key that you will install on the RMA BIG-IP system.

  4. Log in to the RMA BIG-IP system command line.
  5. Install the master key that you copied in step 3 to the RMA BIG-IP system using the following command syntax:

    f5mku -r <key_value>

    For example:

    f5mku -r oruIVCHfmVBnwGaSR/+MAA==

  6. Verify that the master key is the same on the active peer BIG-IP system and the RMA BIG-IP system by typing the following command from the command lines of both systems:

    f5mku -K

  7. Restore the UCS file to the RMA BIG-IP system using the following command syntax:

    tmsh load sys ucs <filename>.ucs rma

  8. To save and load the configuration and to ensure no errors exist, type the following commands from the RMA BIG-IP system command line:

    tmsh save sys config

    tmsh load sys config

  9. To sync the configuration to the RMA BIG-IP system, type the following command from the active peer BIG-IP system command line:

    tmsh run sys config-sync

    Note: This command can take up to a full minute to initialize the new configuration on the RMA device.

  10. Verify the sync status by typing the following command:

    tmsh show sys config-sync

You don't know the BIG-IP system master key password or passphrase but have access to the original BIG-IP system

If you still have access to the original BIG-IP system, you can fetch its current master key, create a new UCS archive, install the same master key on the new or replacement BIG-IP system, and then install the UCS archive on that system.

Important: Before you perform this procedure, ensure that there are no existing configuration load errors relating to decryption of configuration objects on the source system.

  1. Log in to the command line of the source BIG-IP system.

  2. Obtain its current master key by typing the following command:

    f5mku -K

    The command output appears similar to the following example:

    oruIVCHfmVBnwGaSR/+MAA==

  3. Copy the output.

    Note: The output is the master key that you will install on the new or target BIG-IP system.

  4. Create a new UCS archive using the following command syntax:

    tmsh save sys ucs <file_name>

    For example, to create a new UCS file named example.ucs in the /var/local/ucs directory, type the following command:

    tmsh save sys ucs example.ucs

  5. Securely copy the new UCS file from the /var/local/ucs directory to the /var/local/ucs directory of the new or target BIG-IP system. For information about transferring files, refer to K175: Transferring files to or from an F5 system.

  6. Log in to the new BIG-IP system command line.

  7. Install the master key that you copied, from step 3, to the new BIG-IP system using the following command syntax:

    f5mku -r <key_value>

    For example:

    f5mku -r oruIVCHfmVBnwGaSR/+MAA==

  8. Verify that the new master key was installed correctly by typing the following command:

    f5mku -K

  9. Load the UCS file by using the following command syntax:

    tmsh load sys ucs <ucs_archive_name>

    For example:

    tmsh load sys ucs example.ucs

  10. Save the configuration by typing the following command:

    tmsh save sys config

  11. To ensure no errors exist, load the configuration by typing the following command:

    tmsh load sys config

You don't know the master key password or passphrase and don't have access to the original BIG-IP system, but you know the configuration object passwords or passphrases

If you don't know the master key password or passphrase and don't have access to the original BIG-IP system, but you do know the configuration object passwords or passphrases, you can edit the BIG-IP configuration files, type the passwords or passphrases in clear text, and then load the configuration. This restores and re-encrypts the configuration. To do so, perform one of the following procedures, as appropriate for your system:

BIG-IP LTM 10.x - 11.4.x

  1. After restoring the UCS file, open the /config/bigip.conf file with a text editor.
  2. Edit each configuration object containing a password or passphrase, replacing each encrypted password or passphrase with the unencrypted version.
  3. To load the new configuration into memory, type the following command:

    tmsh load sys config

  4. To save the running configuration with the encrypted passwords or passphrases in the bigip.conf file, type the following command:

    tmsh save sys config
