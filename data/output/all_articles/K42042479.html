Description

When you receive an RMA device and load an old configuration that allows it to connect to an existing synchronization group before using the gtm_add script, you may find the old local BIG-IP DNS configuration has synced to the remote BIG-IP DNS

Environment

  • BIG-IP DNS synchronization group is enabled
  • UCS with old configuration is loaded on RMA device.
  • Adding a BIG-IP DNS system to an existing DNS synchronization group using gtm_add

Cause

The issue is due to loading an old configuration on to a new system which updates its commit time. If the device contains the DNS synchronization group configuration, it will join the existing group and advertise its newer commit time, synchronizing its older configuration to the group.

If the older config has already synchronized to the group, then running gtm_add will not restore the newer, overwritten, configuration - if this is required, it must be restored from a newer UCS

Recommended Actions

There are two workarounds to the problem.

  1. Before loading a configuration on the RMA device, disable DNS synchronization on all existing members. Then after loading the UCS and verifying established iquery, enable synchronization again.
  2. Disable synchronization in the UCS before loading. See related content.

You can use the following command to verify the BIG-IP DNS configuration time.

#tmsh show gtm iquery 192.168.1.1
