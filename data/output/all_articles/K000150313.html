K000150313: Connection error: per-tmm crypto request limit reached

Type
Support Solution
Published
2025-03-10
Updated
2026-09-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.0, 17.5.X, 21.0.X, 21.0.0, 17.5.1, 21.X.X, 17.1.2, 17.1.3
Source
https://my.f5.com/manage/s/article/K000150313

Description

Starting in BIG-IP 17.1.2, BIG-IP administrators may see this error messages like below:

Feb 29 00:00:00 hostname​.example​.com warning tmm[12345]: 01260009:4: 10.0.0.1:34557 -> 10.1.2.3:443: Connection error: ssl_hs_check_crypto_limit:4449: alert(80) The number of crypto requests 513 reached the per-tmm limit 512

Feb 29 00:00:00 hostname​.example​.com warning tmm[12345]: 01260009:4: 10.0.0.1:34557 -> 10.1.2.3:443: Connection error: ssl_hs_check_crypto_limit:4559: alert(80) Excessive crypto requests 5000 per-tmm limit 2048 completed rate 0 active handshakes 10000

Environment

  • BIG-IP receives SSL/TLS flows

Cause

Starting in BIG-IP 17.1.2, a per-tmm crypto (SSL) request limit was introduced, with a default value of 512. This limit applies to the cryptographic operations queue. In some normal use cases, this value may be too conservative and can cause valid SSL connections to be terminated.

Starting in 17.1.3 and 17.5.1.3, the default per-tmm crypto (SSL) request limit is increased to 2048, and a new sys db variable sys db tmm.ssl.cryptoqueuemax was introduced to configure the limit.

Note: The crypto queue limit was added to mitigate internally discovered CVE-2025-21087 and is not a limit on licensing.

For more information on tmm.ssl.cryptoqueuemax and a new BIG-IP SSL/TLS intelligent rate-limiting feature, refer to K000159053: Overview of the BIG-IP SSL/TLS intelligent rate-limiting feature.

Answer/Recommended Actions

Prerequisite: You must have an administrative shell (bash) access to BIG-IP to perform this procedure.

Starting in 17.1.3 and 17.5.1.3, the per-tmm crypto (SSL) request limit can be configured by modifying the sys db setting.

tmsh modify sys db tmm.ssl.cryptoqueuemax value <preferred_value>

The default value of the sys db variable is 2048.

$ tmsh list sys db tmm.ssl.cryptoqueuemax all-properties
sys db tmm.ssl.cryptoqueuemax {
    default-value "2048"
    scf-config "true"
    value "2048"
    value-range "unsigned_integer min:0 max:4294967295"
}

In 17.1.2 and 17.1.2.x, the per-tmm crypto (SSL) request limit can be configured with a custom tmm_init.tcl file.

Important: Modifications to /config/tmm_init.tcl are synchronized to cluster members (for example, VIPRION blades), but are not synchronized to device group members. This procedure must be performed on each device group member to ensure consistent behavior.

If /config/tmm_init.tcl does not exist, open a text editor as if the file existed, for example, vi /config/tmm_init.tcl. The BIG-IP Linux system will create the file when it’s saved.

Impact of procedure: Making any change to TMM behavior requires a TMM restart (tmsh restart /sys service tmm). BIG-IP system traffic processing is interrupted while TMM restarts. If configured for high availability, a failover will occur. It's recommended to perform this after making the device stand-by or during a maintenance window.

Restore the limit to its default value (Recommended)

  1. Log in to the BIG-IP command line. Depending on your account configuration, you may have direct shell (bash) access, or you may need to invoke it from tmsh (run /util bash)
  2. Delete the line containing ssl_crypto::queue_max and its value from /config/tmm_init.tcl.
  3. Save /config/tmm_init.tcl.
  4. Restart TMM: clsh tmsh restart /sys service tmm
    Note: The clsh command is only for environment where BIG-IP is a bladed systems eg. VIPRION platform.

Increase or decrease the limit (use only as directed by F5 Support)

  1. Log in to the BIG-IP command line. Depending on your account configuration, you may have direct shell (bash) access, or you may need to invoke it from tmsh (run /util bash)
  2. Add ssl_crypto::queue_max to /config/tmm_init.tcl on its own line with the new value. The valid range for this value is 1–2147483647. For example,

    ssl_crypto::queue_max 1024

  3. Save /config/tmm_init.tcl.
  4. Restart TMM: clsh tmsh restart /sys service tmm
    Note: The clsh command is only for environment where BIG-IP is a bladed systems eg. VIPRION platform.
  5. When TMM restarts, a message with the new value will appear in /var/log/tmm, for example:

    <13> Feb 29 01:02:03 hostname​.example​.com notice ssl_crypto::max set to 1024

Completely remove the limit (Not recommended; use only as directed by F5 Support for troubleshooting)

  1. Log in to the BIG-IP command line. Depending on your account configuration, you may have direct shell (bash) access, or you may need to invoke it from tmsh (run /util bash)
  2. Add ssl_crypto::queue_max to /config/tmm_init.tcl on its own line with the value 0, for example, ssl_crypto::queue_max 0.
  3. Save /config/tmm_init.tcl.
  4. Restart TMM: clsh tmsh restart /sys service tmm
    Note: The clsh command is only for environment where BIG-IP is a bladed systems eg. VIPRION platform.
  5. When TMM restarts, a message with the new value will appear in /var/log/tmm, for example:

    <13> Feb 29 01:02:03 hostname​.example​.com notice ssl_crypto::max set to 0
