Known Issue

The BIG-IP ASM system may reset requests that exceed the maximum buffer length size, instead of generating a Request length exceeds defined buffer size violation.

This issue occurs when the following condition is met:

  • The content length of an HTTP request exceeds the value defined for the long_request_buffer_size parameter.

The long_request_buffer_size parameter value is defined in the Application Security > Options > Advanced Configuration screen in the Configuration utility. The default value of the parameter is 10 MB.

Impact

The BIG-IP ASM system will reset client connections.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP ASM system issues a TCP RST to client requests with a content length that exceeds the value defined for the long_request_buffer_size parameter.

    Note: A packet capture utility, such as tcpdump, may be required to diagnose this symptom. For more information, refer to K411: Overview of packet tracing with the tcpdump utility.
  • The BIG-IP ASM system does not generate a Request length exceeds defined buffer size violation for requests that exceed the defined buffer size.

Workaround

There is no workaround for this issue. However, you can mitigate the circumstances under which this issue occurs by modifying the value of the long_request_buffer_size parameter. To do so, perform the following procedure:

Impact of workaround: Increasing the size of the maximum request length processed by the BIG-IP ASM may result in increased resource use. You should carefully test any increase under load in a non-production environment. Increasing the parameter value requires the BIG-IP ASM service to be restarted, resulting in a brief traffic interruption.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Application Security > Options > Advanced Configuration.
  3. Enter the desired maximum size in bytes for the long_request_buffer_size parameter value.

    Note: You can increase the value to a maximum of 20 MB.
  4. Click Save.
  5. Log in to the command line.
  6. Restart the BIG-IP ASM service by typing the following command:

    Important: This step will cause a brief traffic disruption.

    bigstart restart asm
