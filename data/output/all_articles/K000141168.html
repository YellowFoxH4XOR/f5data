K000141168: SSLO: Service is returning HTTP 503 but SSLO is still sending traffic to it despite 'action on service down' being set to 'ignore' on that service

Type
Support Solution
Published
2024-09-24
Updated
2024-09-24
Applies to
  • F5 App Protect
  • F5 SSL Orchestrator
Source
https://my.f5.com/manage/s/article/K000141168

Description

A HTTP proxy working as an SSLO service was seen to occasionally respond to a client's request with HTTP error codes such as "503 Service Unavailable", but SSLO was seen to be still sending traffic to it and not bypassing that service even though 'action on service down' was already set to 'ignore' for that service in SSLO.

This caused confusion since the admin expected the SSLO to continue and forward the client request further down the SSLO service chain even if it did not receive the request back from the service, due to 'action on service down' being set to 'ignore'.

 

Environment

SSLO

 

Cause

The service is only marked down by SSLO if the configured inline monitor fails - in this case, the monitor was not configured to look at the HTTP error codes to mark the service down, so the service was not being marked down as it was not failing the configured device monitor probe.

'action on service down' only takes effect if SSLO actually marks the service down (the line to the service in the SSLO visualisation GUI turns red to indicate that SSLO has marked a service down).

 

Recommended Actions

The admin would need to change the monitor(s) on the service to actually mark the device down in this situation for that setting (Action on service down: Ignore) to take effect.
