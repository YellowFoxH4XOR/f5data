Known Issue

This is the result of a known issue. In the SSL Client Certificate LDAP Authentication Configuration, you can specify a list of up to five valid roles to which a user must be assigned before authorization is performed. However, if you specify more than one valid role, every second entry in the list is ignored. Only the first, third, fifth, seventh, and ninth entries are recognized by the system as configured valid roles.

To determine if a user should be granted access to a resource, the BIG-IP LTM system searches through the roles assigned to the user and attempts to match to one of the valid roles defined by the Authentication Configuration object profile. To be authorized, a client need only be a member of one of the roles specified in the profile.

For example, the following list is configured for the Valid Roles list:

role1
role2
role3
role4

Users assigned to roles matching any of these listed should be authorized. However, since only role1 and role3 are recognized by the BIG-IP LTM system as valid roles, only users assigned to role1 or role 3 will be authorized.

F5 Product Development tracked this issue as CR107965 and it was fixed in BIG-IP LTM 9.4.7 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround
You can work around this issue by adding fictitious valid role entries in the list between the actual valid roles for which authorization is warranted, forcing the system to ignore the fictitious entries instead of the real entries, by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Select Configurations from the Authentication menu.
  5. Click the Authentication Configuration you want to modify.
  6. Select Advanced from the Configuration menu.
  7. In the Valid Roles dialog box, remove any existing entries by successively highlighting each and clicking Delete.
  8. In the Valid Roles dialog box, enter the first actual valid role, and click Add.
  9. In the Valid Roles dialog box, enter the first fictitious valid role, and click Add.
  10. Repeat steps 7 and 8 until all actual valid roles have been added. The resulting list appears similar to the following example:

    role1
    bogus1
    role2
    bogus2
    role3
    bogus3
    role4
  11. Click Update.

Note: You can still define up to five actual valid roles; the five limit maximum only takes into account the valid roles that are recognized by the system.
