Known Issue

Description

The BIG-IP port selection algorithm may cause intermittent connection failures on CMP-compatible platforms. This issue occurs when all of the following conditions are met:

  • CMP-compatible BIG-IP
  • Client sends multiple sequential connections through a single TMM instance

The issue occurs when the port-selection algorithm, used to steer connections through a particular TMM instance, selects a port number that is close to the port specified by the client. For clients that use sequential source port numbers, this behavior change—from previous and subsequent BIG-IP versions—may result in the BIG-IP system attempting to reuse a socket that is still in the TIME_WAIT state on the backend server. Since the port is unavailable, the connection may be reset or delayed.

Impact

The BIG-IP system may incorrectly terminate connections.

Symptoms

As a result of this issue, you may encounter one of the following symptoms:

  • FTP clients observe that some FTP commands succeed while others intermittently fail
  • FTP clients may receive an FTP 425 (Can't open data connection) error
  • HTTP client connections may be delayed or reset
  • Other protocols may experience intermittent connection resets

To work around this issue, you can configure the BIG-IP system to change the source port. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to the Local Traffic > Virtual Servers page.
  3. Click on the name of the virtual server in question.
  4. Change the Configuration drop-down option to Advanced.
  5. Set the Source Port drop-down option to Change.
  6. To save your changes, click Update.
