Known Issue

BIG-IP Fraud Protection Service (FPS) may not function properly on a virtual server that is configured with an BIG-IP APM access profile.

This issue occurs when all of the following conditions are met:

  • The same BIG-IP virtual server is configured with both an Anti-Fraud Profile for FPS and an BIG-IP APM access profile.
  • The access profile is configured for BIG-IP APM Portal Access.
  • A user accesses the web application through the BIG-IP APM Portal Access.

The BIG-IP FPS inserts JavaScript in pages from the web application. The BIG-IP APM Portal Access later rewrites the previously inserted JavaScript causing the FPS functionality to break.

Impact

The BIG-IP FPS does not function as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing the HTTP content, FPS JavaScipt is not inserted into the web application responses.
  • Access to the web application may be impaired.

Workaround

To work around this issue, you can configure two virtual servers on the BIG-IP system where user traffic is first directed to the virtual server containing the Anti-Fraud Profile, then routed to a second virtual server containing the access profile. To do so, you can specify the second virtual server as a load balancing target of the first virtual server by using the virtual iRule command.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Configuring a virtual server with the Anti-Fraud profile (vs_anti_fraud) to route traffic to a second virtual server with an access profile (vs_access_profile)

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the new iRule Name box, type a name for the iRule.

    For example:

    vip_fps_to_vip_apm

  5. In the Definition box, enter the following text:

    when HTTP_REQUEST {
    virtual vs_access_profile
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the name of the virtual server that is configured with the Anti-Fraud Profile (vs_anti_fraud).
  9. Click the Resources tab.
  10. In iRules, click Manage.
  11. From the Available column, select the iRule you previously created (vip_fps_to_vip_apm).
  12. Move the iRule to the Enabled column.
  13. Click Finished.

Note: For more information about the virtual iRules command, refer to the virtual command wiki page on DevCentral. A separate DevCentral login is required to access this content.
