K000162857: NIM Helm chart NetworkPolicy causes upstream errors after Kubernetes upgrade

Type
Support Solution
Published
2026-08-10
Updated
2026-08-10
Applies to
  • NGINX Products
  • NGINX Instance Manager
Source
https://my.f5.com/manage/s/article/K000162857

Description

NGINX Instance Manager API Gateway requests return HTTP 502 or 503 errors because the default Helm chart NetworkPolicy uses an ipBlock ingress rule that does not explicitly allow internal pod-to-pod traffic from an ingress controller in another namespace.

Environment

  • NGINX Instance Manager deployed with the NIM Helm chart
  • Kubernetes cluster
  • NIM API Gateway pods and ingress-controller pods deployed in separate namespaces
  • NetworkPolicy enabled for the NIM API Gateway
  • Default policy file: nms-apigw-network-policy.yaml

Cause

The default NetworkPolicy uses an ipBlock ingress rule. ipBlock is intended for matching cluster-external IP addresses and does not explicitly identify internal pods communicating across namespaces. When NetworkPolicy enforcement is applied, traffic from the ingress controller to the NIM API Gateway may be denied, resulting in HTTP 502 or 503 errors.

Recommended Actions

  1. Identify the namespace or namespaces from which the ingress controller connects to the NIM API Gateway.
  2. Edit nms-apigw-network-policy.yaml and replace the default ipBlock ingress rule with a namespaceSelector that matches the ingress-controller namespace:

    ingress:
    - from:
    - namespaceSelector:
    matchLabels:
    kubernetes.io/metadata.name: <ingress-namespace>

  3. Add a selector for each additional namespace that requires access.
  4. Apply the updated NetworkPolicy.
  5. Verify that the ingress controller can connect to the NIM API Gateway and that requests no longer return HTTP 502 or 503 errors.
  6. To preserve the change across Helm upgrades, apply the modification through a Kustomize overlay configured as a Helm post-renderer.
  7. Upgrade to a NGINX Instance Manager release containing the chart correction when available, then validate the rendered NetworkPolicy.

Additional Information

  • Ensure that the selector matches the labels present on the ingress-controller namespace.
  • Restrict access to only the namespaces that require connectivity to the NIM API Gateway.
  • Direct changes to generated Helm manifests may need to be reapplied after a chart upgrade.
  • The NetworkPolicy correction is available through a product fix. Verify the applicable release documentation before upgrading.
