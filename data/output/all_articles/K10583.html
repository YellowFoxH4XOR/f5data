Topic

HTTP forms is one of many authentication types supported by FirePass. HTTP forms allows FirePass to interoperate with most web applications with a username and password style HTTP page. Configuring FirePass for this type of login is straightforward. However, this type of login may present issues when hidden or less obvious inputs are required by the authenticating web server to process the logon request correctly.

You can use the following two methods to determine the appropriate inputs into the web server to log in:

  • Examining the HTML source of the page
  • Using a third party tool to view the CGI data transmitted by the web browser


Examining the HTML source of the page

Using the F5 Networks login page https://login.f5.com/resource/login.jsp as an example, if you view the source of this page and search for <form to find the HTML form, you will find the following login form:

<form name="login" method="POST" action="./loginAction.jsp">

This form displays the transmission method (POST) and the relative path of the action (./loginAction.jsp). Because the page's current URL path is https://login.f5.com/resource/login.jsp, the ./loginAction.jsp path will cause the browser to request https://login.f5.com/resource/loginAction.jsp so that it is the full URL of the action.

To obtain the inputs, and the value and names of each, when you search for <input, you will find the following:

 <input type="text" name="userid" property="userid" class="userid" size="20">
 <input type="password" name="passwd" property="passwd" class="passwd" size="20">
 <input type="submit" class="loginSubmit" value="LOGIN" onClick="if (validateForm(this.form))return true; else return false">

You can disregard the input without a defined name property (the submit input). Some submit inputs contain names, some do not. In this case, the name property will not be transmitted to the web server. Be sure to include any hidden inputs, as these often define actions for the web server to take and may be necessary. The two remaining inputs in this case are userid and passwd.

Note: All inputs, such as check boxes, selects, and submits, in addition to username and password must be defined in the Hidden form parameters and values section in the Master Group settings.

Using a third party tool to view the CGI data transmitted by the web browser

It may be easier to use a third party tool to examine the login POST directly instead of checking the HTML source of the login page, such as when the form is built dynamically by JavaScript code. The required inputs may not appear in the source. Popular applications for this purpose include Firebug or HTTPWatch. When using these types of tools, you should see a POST into the login page immediately after you click the login page's Submit button. Using the https://login.f5.com/resource/login.jsp example, the POST data would appear similar to the following:

userid=myusername&passwd=mypassword

The format of this POST data is name=value, separated by an ampersand ( & ) character. For this example, only two values are required: username and password. Any other name=value pairs should be placed into the Hidden form parameters and values section in the Master Group settings.

In some cases, the data could be submitted in a GET instead of a POST. In this case, you would examine the Request-URI section of the HTTP request. For example, if the F5 Networks login page was a GET instead of a POST, the Request-URI would be the following:

/login.f5.com/resource/loginAction.jsp?userid=myusername&passwd=mypassword

This data is formatted the same way as the POST data, you would just use everything after the question mark ( ? ) character in the URI. You now have all the information necessary to populate the Master Group HTTP form-based authentication window in FirePass.

Configuring FirePass to use HTTP form-based authentication

To configure FirePass to use HTTP form-based authentication, perform the following procedure:

  1. From the Administrative Console, navigate to Users: Groups: Master Groups.
  2. Select the group that you want to convert to HTTP form-based authentication.
  3. Click the Authentication tab.
  4. Click the Convert authentication method link .
  5. Click the HTTP Form-based Authentication link.
  6. Click the Continue button.
  7. Using the https://login.f5.com/resource/login.jsp example, populate the following fields in the HTTP Form-Based Authentication Settings section.
  8. In the Start URL optional field, enter the following:

    https://login.f5.com/resource/login.jsp

    Note: This cookie acquired from this page will be used in the POST call generated during the next step.
  9. In the Form action field, enter the following:

    https://login.f5.com/loginAction.jsp

    Important: This field needs to have an absolute URL. FirePass will use the information in this field to make POST requests to the URL.

    Note: This field is mandatory and is the equivalent to the URL in the HTML <form> "action" element.
  10. In the Form parameter for user name field, enter the following:

    userid
  11. In the Form parameter for password field, enter the following:

    passwd
  12. Leave the Hidden form parameters and values field blank.
  13. Leave the Number of redirects to follow field blank.
  14. Leave the Pass cookies to client browser field unchecked.
  15. In the Successful logon detection section, select the By specific string in result body field and insert AUTHORIZED in the blank field.

    Note: The specific string in the result body must be a single word; it cannot contain a space.
  16. Click on Save Settings.
