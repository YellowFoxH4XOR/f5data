Topic

You should consider using this procedure under the following conditions:

  • You configured the BIG-IP system with an HTTP or HTTPS virtual server that includes processing traffic for Webex.
  • You want a local traffic policy to segregate the Webex traffic to an alternate resource pool based on expected Webex URIs.
  • You have a known list of Webex URIs accessed through the virtual server. 

Description

In some Webex deployments, client HTTP request are processed to a destination resource where the resource determines redirection or passthrough for a Webex request and related content.

You can configure the BIG-IP system to selectively (based on the client requested URL) send known Webex requests to the Webex destination resource, removing the extra processing from the non-Webex resources.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Your BIG-IP system is configured with a virtual server for load balancing an HTTP or HTTP request.
  • Currently the load-balanced destination resources determine and redirect Webex content.
  • You have a known list of URLs used by clients when interacting with Webex in your environment. 
  • You configured a pool containing the desired Webex resource(s).

Procedures

Creating the URL data-group

To create a data group of know URIs that the local traffic policy references when determining resource selection for Webex URIs, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > iRules > Data Group List.
  2. Click Create.
  3. Enter a Name for the data-group.
  4. Set Type to String.
  5. In the String text box, enter the expected Webex specified internal URI path.

    For example:

    /webex/
    /webex.com

    Important: The listed URIs are not inclusive and your Webex deployment needs may require other deployment-specific URIs.

  6. Click Add.

    Note: Repeat steps 5 and 6 for each known internal Webex URL path (processed by your Webex servers) required for your deployment environment.

  7. Click Finished.

Creating the local traffic policy

To create a new local traffic policy that will selectively (based on the matched URI) send Webex request to a specific resource pool.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic Policies > Policy List.
  2. Click Create.
  3. Enter a policy Name.
  4. Leave Strategy to the default first option.
  5. Click Create Policy.
  6. Click Create in Rules.
  7. Click [+] to the right of All traffic.
  8. Set the first condition to HTTP URI.
  9. Set the second condition to path.
  10. Set the third condition to contains.
  11. Set the fourth condition to in datagroup.
  12. Set the fifth condition to the Webex URL data group created in the previous procedure.
  13. Set the sixth condition to request.
  14. Click Options.
  15. Select the Use normalized URI check box.
  16. Click Save.
  17. For Do the following when the traffic is matched: click (+).
  18. Set the first condition to Forward traffic.
  19. Set the second condition to pool.
  20. Set the third condition to the pool name created to process Webex traffic.
  21. Set the fourth condition to request.
  22. Click Save.
  23. Go to Local Traffic > Policies > Policy List.
  24. In Draft Policies, select the check box for the newly created policy.
  25. Click Publish.

Assigning the local traffic policy

To configure an existing virtual server with the newly created local traffic policy, perform the following procedure:

Note: The configured local traffic policy sends the Webex request based on the URI to the Webex resource pool.

You should configure the virtual server with a default resource (pool) to process requests not identified by the policy.

Impact of procedure: Performing the following procedure implements policy decisions on traffic processed by the virtual server.

  1. Go to Local Traffic > Virtual Servers > Virtual Server List.
  2. Click the name of the virtual server that will process Webex traffic.
  3. Select the Resources tab.
  4. In the Policies section, click Manage.
  5. In the Available column, select the policy you created in the previous procedure.
  6. To move the policy to the Enabled column, click <<.
  7. Click Finished.

    Note: You can also accomplish pool selection based on the URI using a custom crafted iRule.

    For example:

    when HTTP_REQUEST {
       if { [class match [string tolower [HTTP::uri]] eq "<data-group name>" ] } {
            pool <pool name>
       }
    }
