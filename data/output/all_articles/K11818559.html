Topic

Cookie persistence may not be preserved when HTTP and HTTPS virtual servers share the same pool and clients make initial connections to an HTTPS virtual server with subsequent connections to an HTTP virtual server in that pool.

Description

In BIG-IP 12.0.0 and later, the Secure Attribute option exists for the HTTP Cookie Insert method for the cookie persistence profile. Enabled by default as a security measure, this option adds the Secure Attribute value to persistence cookies, which the system inserts into HTTP response headers.

When a client browser receives an HTTP cookie with the Secure Attribute value set, the browser includes the cookie in subsequent HTTP requests only if the request is transmitted over a secure channel, which is typically Secure Sockets Layer (SSL) or TLS. For more information about the HTTP Secure Attribute value, refer to section 4.1.2.5 of the Internet Engineering Task Force (RFC 6265).

Connections may not persist as expected under the following conditions:

  • An HTTP virtual server and an HTTPS virtual server (virtual server associated with a Client SSL profile) share the same pool.
  • The shared pool is configured with cookie persistence with the Secure Attribute option enabled.
  • A client first connects to the HTTPS virtual server and then attempts to make a subsequent connection to the HTTP virtual server in the shared pool.

Under these conditions, the client initially connects to the HTTPS virtual server and receives a cookie with the Secure Attribute value set. When the client makes a subsequent connection to the HTTP virtual server, the client does not add the stored cookie with the Secure Attribute value set to the HTTP request because the HTTP request is not secure. Because the request does not present a cookie to the BIG-IP system, the system makes a new load balancing decision which may not connect the client to the same HTTP pool member as before.

Recommended Actions

If possible, after traffic is directed to an HTTPS virtual server, ensure that all links and subsequent client requests are maintained within the HTTPS virtual server. If this is not possible, you can disable the Secure Attribute option in the cookie persistence profile. To do so, perform the following procedure:

Impact of procedure: If the Secure Attribute is disabled, an active network attacker can intercept HTTP requests and possibly gain access to sensitive information. For more information, refer to section 8.3 of the Internet Engineering Task Force (RFC 6265).

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Persistence.
  3. Click the name of the cookie persistence profile.
  4. In the Configuration section, enable editing of the Secure Attribute field by selecting the check box in that field.
  5. Select Disabled from the Secure Attribute menu.
  6. Click Update.
