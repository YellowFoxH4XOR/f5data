Description

When querying for a Wide-IP that is using a topology load balancing method, it doesn't load balance it to the correct country/region compared to the GeoIP database result. 

For example:

(1) Sending a DNS Request to Listener IP

dig @163.116.193.32 www.mydomain.com +short +subnet=8.8.8.8

(2) DNS logging shows that the EDNS 8.8.8.8 country/region is in EU, therefore it sends it to EU Pool

Mar 29 10:00:16 bigip info tmm[11188]: Rule /Common/dns_logging <DNS_REQUEST>: EDNS: 8.8.8.8 - EDNS-LOCATION: EU EU {} {}

(3) GeoIP Lookup for 8.8.8.8 is showing correct country/region which is US California

Cause

At some point the selinux permissions on the symlinks got messed up and tmm is having a hard time accessing them so tmm is using the local files instead of the updated GeoIP database files

Permissions type is set to default_t instead of shared_geoip_t

[root@bigip:Active:Standalone] GeoIP # cd /usr/share/GeoIP/v2/

Recommended Actions

Do the following steps to correct the permission on the GeoIP database files

# cd /shared/GeoIP/v2/
# chcon -h -t shared_geoip_t F5GeoIP.dat
# chcon -h -t shared_geoip_t F5GeoIPISP.dat
# chcon -h -t shared_geoip_t F5GeoIPOrg.dat
# chcon -h -t shared_geoip_t F5GeoIPv6.dat
# bigstart restart tmm mcpd
