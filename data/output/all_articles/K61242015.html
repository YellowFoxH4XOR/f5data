Description

Security audit discovers that password hash for root account password hash shows up as MD5-128 instead of SHA on devices that have been upgraded from older versions.

Password hash should be SHA-512

Environment

  • BIG-IP Linux Host subsystem 
  • /etc/shadow

Cause

The root password is handled by host not by TMOS but TMOS is in control of the PAM modules that provide login security.

Recommended Actions

Change the root password as outlined in

K13121: Changing system maintenance account passwords (11.x - 14.x)

This will reset the hash  so that it will be recalculated based on what PAM specifies. 
 

Additional Information

When upgrading versions the password hash will not be updated.  You can use this command to see what, if anything, has been changed from the defaults,  

tmsh show running-config auth password-policy all-properties

for example:

[root@ltm2:Active] pam.d # tmsh show running-config auth password-policy all-properties
auth password-policy {
    description none
    expiration-warning 7
    max-duration 99999
    max-login-failures 0
    min-duration 0
    minimum-length 6
    password-memory 0
    policy-enforcement disabled
    required-lowercase 0
    required-numeric 0
    required-special 0
    required-uppercase 0
}

To see what hash the system is using you'd look at /etc/pam/system-auth.

[root@ltm2:Active] pam.d # grep password /etc/pam.d/system-auth | grep requisite
password    requisite     pam_unix.so use_authtok sha512 shadow remember=0 min_days=0 max_days=99999 warn_age=7

Note: most of these command will only work if you're signed in as the root user, admin or other users will not work to view /etc/shadow.

In the last line you can see the values match up with what the tmsh command reported (parameters that use default values aren't generally added to the line).  It also shows that we're configured to be using sha512 to encrypt the password.  

To see what you're currently using you can look at /etc/shadow.  The second field in the file is the hashed password for each user, and it is generally separated by $ signs into three parts, which are the hashing algorithm, the salt and the hash itself (if it doesn't have the first section then it's using the default hash algorithm, which is DES).

$0$ is DES,
$1$ is MD5,
$2$ and $2a$ are Blowfish,
$3$ is NT Hash,
$5$ is SHA-256
$6$ is SHA-512.

The following command will allow you to just see the encryption hash algorithm:for the root user:

grep root /etc/shadow | awk -F: '$2 ~ /^\$[0-6]\$/ {print $2}' | cut -c-3

For example:

[root@ltm2:Active] pam.d # grep root /etc/shadow | awk -F: '$2 ~ /^\$[0-6]\$/ {print $2}' | cut -c-3
$6$

This shows that it's using encryption hash algorithm 6 or SHA-512, if it's 1 then it's MD5.

This will happen if you've done an upgrade from an older version of the LTM software that was using MD5 to a newer version that's using sha512.  Host can continue to use other version based on the value of that $x$ field.
