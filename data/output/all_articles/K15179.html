Known Issue

The Traffic Management Microkernel (TMM) process may produce a core file when you attempt to reset the runtime statistics for firewall global rules.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP AFM configuration contains either of the following:

    • Firewall global rules that contain no rules.
    • Firewall global rules that contain only rules and/or rule lists that are either disabled and/or empty.
  • You reset the runtime statistics for the firewall global rules using the following Traffic Management Shell (tmsh) command:
     
    reset-stats /security firewall global-rules rules

Impact

The BIG-IP system may temporarily fail to process traffic, and fails over if configured as part of a high-availability (HA) pair.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H457936 on the Diagnostics > Identified > Low|High  screen.
  • The BIG-IP system unexpectedly fails over to another system in the device group.
  • The TMM process stops responding and generates a SIGSEGV core file in the /shared/core directory.
  • The BIG-IP system fails over to the peer system in an HA configuration.
  • The BIG-IP system logs an error message to the /var/log/ltm log file that appears similar to the following example:

    notice mcpd[6510]: 01070406:5: Removed publication with publisher id TMM
    err mcpd[6510]: 01070927:3: Request failed, data provider (%TMM) disconnected from mcpd.

Workaround

There is no workaround for this issue. To avoid this issue, you should ensure that the firewall global rules contain at least one active rule and the rule list is not empty when you need to reset the runtime statistics for the firewall global rules.
