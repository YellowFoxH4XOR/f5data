Description

 

Attaching both VDI and HTTP/2 profiles on an APM Virtual Server, results in the APM logon page not being displayed.

It hangs at https://APM-VS/my.policy.
 

The browser console logs show:

Failed to load resource: net::ERR_HTTP2_PROTOCOL_ERROR


Under /var/log/ltm you can see the below error:
 

TCL error: /Common/_sys_APM_VDI_Helper <HTTP_RESPONSE_RELEASE> - can't read "tmm_apm_feed_login": no such variable while executing "if { ($tmm_apm_client_type == "rdg-http" || $tmm_apm_feed_login) && $tmm_apm_is_nego_auth } { # Getting response header fo..."


Connection Reset under /var/log/apm:

server-side connection was reset, reason: iRule execution error
 

Environment

  • BIG-IP APM
  • On the BIG-IP APM Virtual Server
    •      VDI profile
    •      HTTP/2 profile


Cause

 

VDI does not support HTTP/2

 

Recommended Actions

 

Both profiles cannot be attached to the APM Virtual Server. One of the profile needs to be removed.
 

Additional Information
 

  • BIG-IP APM Client compatibility Matrix includes the below note under:

             Remote Desktop Gateway Compatibility Matrix

             Note: Virtual Desktop Infrastructure (VDI) does not support the HTTP/2 protocol.
