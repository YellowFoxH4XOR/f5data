Description

  • You have configured Standard Virtual Server to load balance traffic between RDP servers
  • You can directly reach backend servers (pool members) on RDP port 3389 
  • Backend servers (pool members) are reachable from BIG-IP and able to telnet RDP port 3389
  • On packet capture you can see that request from client source IP (for example: 192.168.2.1) is reaching BIG-IP VS IP (for example: 192.168.1.1) but there is no reply back:
1    1970-01-01 00:00:00.112233    192.168.2.1    192.168.1.1    RDP    220    IN  s1/tmm1 : Negotiate Request

Environment

  • BIG-IP
  • Virtual Server (type: Standard)
  • RDP traffic

Cause

HTTP profile attached to Virtual Server which is not expected to handle HTTP traffic.

Recommended Actions

 Review the HTTP Profile (Client) setting on affected virtual servers to ensure it is able to send and receive traffic for RDP protocol:
  1. Navigate to Local Traffic > Virtual Servers and select the virtual server in question.
  2. Scroll down to Configuration (Basic) section.
  3. Under HTTP Profile (Client) setting set it to "None".
