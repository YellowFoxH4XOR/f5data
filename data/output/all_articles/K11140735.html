Description

Administrators are being forced to re-enter credentials too frequently when accessing the BIG-IP GUI.
The following error message appears in the /var/log/httpd/httpd_errors file

httpd<pid>: [error] <client_ip> AUTHCACHE Error processing cookie <cookie_string> - Cookie user mismatch

In this error message, note the following:

<pid> is the httpd process ID.
<client_ip> is the remote client IP address.
<cookie_string> is the 40-byte BIGIPAuthCookie cookie value.

For example:

httpd[13553]: [warn] [client 10.10.10.10] AUTHCACHE Error processing cookie 49C0835182DB98C6A3986E9E54FF7AF8EB7E2EC4 - Cookie user mismatch

Environment

  • Accessing the BIG-IP GUI (Configuration Utility)
  • Admins prompted for credentials too frequently

Cause

This message can occur when a client or an iControl application makes frequent connections to the BIG-IP Configuration utility.
The BIG-IP system implements an authentication cache (pamcache) for all Configuration utility requests. The cache works by storing information such as a username hash and the remote client's IP address in the memory file system, which prevents the system from prompting the user for user name and password every time the user attempts to log in. Clients sending requests to the Configuration utility authenticate to the cache by submitting a BIGIPAuthCookie to the BIG-IP system. If the client or iControl application makes a request without returning the BIGIPAuthCookie cookie before the pamcache timeout period, the system logs the error message.

Recommended Actions

If your Admin or iControl application logs in frequently without the BIGIPAuthCookie cookie, you may perform one or more of the following actions.

  • Adjust the pamcache timeout
  • Make sure that your client or iControl application saves and returns the BIGIPAuthCookie cookie for subsequent requests
  • K57912912: Workaround to filter Log messages: Error message: httpd<pid>: [error] <client_ip> AUTHCACHE Error processing cookie <cookie_string> - Cookie user mismatch

Adjust the pamcache timeout.
If your client or iControl application frequently logs in to the Configuration utility without the BIGIPAuthCookie cookie, you can adjust the pamcache timeout to a value that is less than the login frequency of the client. For example, if the client or iControl application logs in every 1000 seconds, you can try adjusting the pamcache timeout to 800 seconds.

Note: The default pamcache timeout is 1200 seconds. The minimum timeout is 120 seconds and the maximum is 2147483647 seconds.

Impact of procedure: The length of the pamcache timeout affects the frequency at which the system prompts users to log in. If the timeout value is too short, the system frequently prompts users to log in. If the timeout value is too long, the system never prompts users to log in.

1. Log in to the TMOS Shell (tmsh) by typing the following command:

tmsh

2. Modify the pamcache timeout by typing the following command syntax:

modify sys httpd auth-pam-idle-timeout <value>

For example:

modify sys httpd auth-pam-idle-timeout 120

3. Verify the pamcache timeout by typing the following command:

list sys httpd auth-pam-idle-timeout

The command should return an output similar to the following example:
sys httpd {
    auth-pam-idle-timeout 120
}

Make sure your client or iControl application saves and returns the BIGIPAuthCookie cookie for subsequent requests.
Review the documentation for your browser and/or iControl application to ensure the BIGIPAuthCookie is saved and returned when accessing the BIG-IP GUI
