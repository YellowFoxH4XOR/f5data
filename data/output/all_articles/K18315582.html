Known Issue

Kerberos single sign-on (SSO) authentication may fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM access profile is configured with Kerberos SSO.
  • The Kerberos SSO configuration delegation account is configured in Active Directory to use the enforced AES256 encryption type.

Impact

SSO authentication fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the delegation account configuration in Active Directory has the enforced AES256 encryption option disabled, Kerberos tickets are processed successfully.
  • In the /var/log/apm file, you observe log messages similar to the following example:

    info websso.3[<pid>]: 014d0011:6: <sessionid>: Websso Kerberos authentication for user '<username>' using config '/<partition>/<access profile name>'
    err websso.3[<pid>]: 014d0005:3: Kerberos: can't decrypt S4U2Self ticket for user <username>@<domain> - Decrypt integrity check failed (-1765328353)
    err websso.1[<pid>]: 014d0024:3: <sessionid>: Kerberos: Failed to get ticket for user <username>@<domain>
    err websso.1[<pid>]: 014d0048:3: <sessionid>: failure occurred when processing the work item
    err websso.0[<pid>]: 014d0026:3: <sessionid>: Could not find SSO username, check SSO credential mapping agent setting
    err websso.0[<pid>]: 014d0043:3: <sessionid>: SSO username is empty - SSO is disabled

Workaround

To work around this issue, you can modify the Active Directory Kerberos delegation account and disable the enforced AES256 encryption option.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
