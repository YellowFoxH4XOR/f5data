Issue

When requests appear to traverse a BIG-IP WebAccelerator system more than once, the following error message may be logged to the /var/log/wa/pvac.log file :

WA ERROR: Circular HTTP request loop detected - check your application host mappings.

This error message may be reported under any of the following conditions:

  • A misconfiguration in the network causes requests to loop
  • A universal persistence profile is applied to a BIG-IP version 9.x WebAccelerator-enabled virtual server
  • The unmapped hosts setting is configured and the requested hostname resolves to a local virtual address
  • The application architecture uses multiple BIG-IP WebAccelerator-enabled virtual servers

A misconfiguration in the network causes requests to loop

The error messages is generated if a misconfiguration in the network or name resolution services causes a request to unintentionally loop back to the same BIG-IP WebAccelerator system. When this occurs, the connection is also closed to prevent an infinite request loop. To determine the source of the messages, examine the requests received by the BIG-IP WebAccelerator system.

A universal persistence profile is applied to a BIG-IP version 9.x WebAccelerator-enabled virtual server

In version 9.x, the universal persistence profile is not compatible with WebAccelerator-enabled virtual servers. If you apply a universal persistence profile to a WebAccelerator-enabled virtual server, the error message is logged upon receipt of each HTTP request, and the connection is closed.

Note: For more information, refer to K8769: The universal persistence profile and the BIG-IP WebAccelerator are incompatible.

The unmapped hosts setting is configured and the requested hostname resolves to a local virtual address

The unmapped hosts setting is used when it is not possible to configure the BIG-IP WebAccelerator for all requested hostnames you want the BIG-IP WebAccelerator to process. When a BIG-IP WebAccelerator is configured to process requests for unmapped hosts, and the destination host name in the requested URL resolves to a WebAccelerator-enabled virtual address on the same BIG-IP WebAccelerator, the page will not load and the following set of error messages is logged in the /var/log/wa/pvac.log file:

WA ERROR: Circular HTTP request loop detected - check your application host mappings.
WA ERROR: Circular HTTP request loop detected - check your application host mappings.
WA ERROR: PvAsyncFetcherHttpData::taskDone(), sts != E_OK, Error: Server closed connection.

Note: The connection is closed to prevent an infinite request loop.

Note: The unmapped hosts setting is not intended to support use of the BIG-IP WebAccelerator as a forward proxy to the Internet. While possible, this implementation is discouraged; the infinite number of potential unmapped hosts may overwhelm the capabilities of the BIG-IP WebAccelerator.

The application architecture uses multiple BIG-IP WebAccelerator-enabled virtual servers

In an application architecture that uses multiple WebAccelerator-enabled virtual servers on the same BIG-IP WebAccelerator, the BIG-IP WebAccelerator may receive requests that include an X-PvMAC header whose value is the same as its own management interface MAC address. The origin web servers may also propagate the X-PvMAC header along with other HTTP headers from the front-end requests into their own back-end requests. When this occurs, the error message is logged, but the connection is not closed.

If the error message results from such an intentional application architecture, the message is benign and may be safely ignored. In this case, F5 recommends using an iRule that removes the X-PvMAC header in order to prevent the error messages from occurring during normal operation.

In version 10.x, you can use an iRule similar to the following to remove the X-PvMAC header from requests sent by the BIG-IP WebAccelerator virtual servers:

when HTTP_REQUEST_SEND {
   clientside {
      if { [HTTP::header exists "X-PvMAC"] } {
         HTTP::header remove "X-PvMAC"
      }
   }
}

Note: This iRule should be applied to any WebAccelerator-enabled virtual server that will be sending requests to another WebAccelerator enabled virtual server.

In version 9.x, and in 10.x as an alternative to the solution above, you can use an iRule similar to the following to remove the X-PvMAC header from requests received by the BIG-IP WebAccelerator virtual servers:

when HTTP_REQUEST {
   if { [HTTP::header exists "X-PvMAC"] } {
      HTTP::header remove "X-PvMAC"
   }
}

Note: This iRule should be applied to any WebAccelerator-enabled virtual server that will be receiving requests from another WebAccelerator-enabled virtual server.
