DescriptionHA failing to establish a connection to peer and provisioning status displayed by WebGui is incorrect. The following logs will be displayed in /var/log/ltm

< Date > < Hostname > warning tmm2[12649]: 01260009:4: Connection error: hud_ssl_handler:911: invalid profile (40)
< Date > < Hostname > err tmm2[12649]: 01340005:3: HA Connection with peer x.x.x.x:33026 for traffic-group /Common/traffic-group-1 failed TLS handshake.

Failed TLS handshake message can also happen upon upgrading one of the HA peers with connection mirroring enabled. System variable 'statemirror.secure' default value was changed to TRUE since version 16.x due to a fix for ID825449.

Environment

  • BIG-IP LTM
  • High Availability
  • Connection mirroring enabled

Cause1. The trust relations between peers became out of sync.
2. Due to a fix for ID825449, system variable 'statemirror.secure' was changed to TRUE on the upgraded system. The not-upgraded one still has 'statemirror.secure' set to FALSE.

Recommended Actions

  1. Rebuild the trust relationship following article K42161405.
  2. Set 'statemirror.secure' to TRUE on the not-upgraded system. This will cause the connection mirroring to come up immediately. However, it is recommended to upgrade the remaining system as well.
