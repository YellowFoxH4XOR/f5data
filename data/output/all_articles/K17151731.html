Description

During startup of large BIG-IP AFM systems (Large number of BIG-IP AFM rules) it is possible to encounter condition 
when blob compilation in BIG-IP AFM protected system is failing due to system been busy

Log entries to point to potential issue:

Oct 13 22:53:52 BIGIPAFM emerg pccd[5338]: 015d0000:0: Activation of Blob pktclass2 failed (timeout 30 secs).


Environment

  • BIGIP- AFM version 12.x and up with large rule sets

Cause

System startup consumes resources that are delaying ruleset compilations.

Recommended Actions

It is advisable to increase PCCD compilation timeout via db variable

sys db pccd.deploy.timeout {
default-value "30"
scf-config "true"
value "30"
value-range "unsigned_integer min:20 max:4294967295"
}
 

    Additional Information

    However, customer may be concerned if system is unprotected during this longer timeout.

    There is no reason for this concern:
    Starting in BIG-IP v12.0 release, pccd is using two-blob system. Blob files are shared with TMM. While TMM is using one of the blobs, pccd can write to another. Once complete, pccd notifies TMM to switch over to the other blob. At _any time there is one active blob file used for packet matching_ by TMM. All we are saying with 120 sec delay - do not compile and activate second blob.
