Topic

You should consider using these procedures under the following condition:

  • You want to download a QKView diagnostic file from the F5 rSeries or VELOS system and upload it to the new iHealth system.

Description

You can download a QKView file from the rSeries and VELOS systems using the webUI, CLI, or REST API. After you download the file, you can upload it to the new iHealth system.

The new iHealth system uses a new identity and authentication provider. You can use your MyF5 credentials to log in to the iHealth website. To authenticate using the iHealth API, you must generate a bearer token with a Client ID and Client Secret issued from the iHealth token service.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You created a MyF5 account.
  • You have administrative access to the rSeries or VELOS system webUI, CLI, and REST API.
  • You have access to a system with the curl and jq utilities installed if you are using the REST API or iHealth API procedures.
  • You have a remote HTTPS, SCP, or SFTP server if you are using the CLI or REST API procedures.

Procedures

  • List the QKView files on the rSeries or VELOS system
  • Download the QKView file
  • Upload the QKView file to iHealth

List the QKView files on the rSeries or VELOS system

You can list the currently available QKView files on the rSeries or VELOS system using the webUI, CLI, or REST API. To do so, perform the appropriate procedure:

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

  • Use the webUI
  • Use the CLI
  • Use the REST API

Use the webUI

  1. Log in to the webUI of the rSeries system or VELOS system controller or chassis partition as the admin user.
  2. Go to SYSTEM SETTINGS > File Utilities.
  3. For Base Directory, select diags/shared.
  4. Under Base Directory, select the qkview directory.

Use the CLI

  1. Log in to the CLI of the rSeries system or VELOS system controller or chassis partition as the admin user.
  2. To view the QKView files on the rSeries system, enter the following command:

    show system diagnostics qkview state files

    The command output appears similar to the following example:

    FILENAME                  SIZE       CREATED ON
    ---------------------------------------------------------------------
    example.qkview                 215479973  2023-03-01T16:38:19.951552812Z
    example2.qkview               215094906  2023-03-01T21:06:35.717112984Z

    To view the QKView files on a VELOS system controller or chassis partition, enter the following commands:

    config

    system diagnostics qkview list

    The command output appears similar to the following example:

    result  {"Qkviews":[{"Filename":"controller-1.qkview","Date":"2023-03-01T17:52:40.466110479Z","Size":829267868}]}

    resultint 0

Use the REST API

  1. Log in to a system with the curl utility installed.
  2. View the QKView files using the following command syntax:

    rSeries:

    curl -X GET -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:state/f5-system-diagnostics-qkview:files/f5-system-diagnostics-qkview:file"  

    VELOS:

    curl -X POST -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:list"

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the rSeries system or VELOS system controller or chassis partition.
    • <mgmt_address> is the host name or management IP address of the rSeries system or VELOS system controller or chassis partition.

    For example, to list the QKView files on an rSeries system with management IP address 10.10.10.200, enter the following command:

    curl -X GET -sku admin:admin -H "Content-Type: application/yang-data+json" "https://10.10.10.200/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:state/f5-system-diagnostics-qkview:files/f5-system-diagnostics-qkview:file"

    The command returns output similar to the following example:

    {
      "f5-system-diagnostics-qkview:file": [
        {
          "filename": "example.qkview",
          "size": 215094906,
          "created-on": "2023-03-01T21:06:35.717112984Z"
        }
      ]
    }

Download the QKView file

You can download a QKView file from the rSeries and VELOS systems using the webUI, CLI, or REST API. To do so, perform the appropriate procedure:

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

  • Use the webUI
  • Use the CLI
  • Use the REST API

Use the webUI

  1. Log in to the webUI of the rSeries system or VELOS system controller or chassis partition as the admin user.
  2. Go to SYSTEM SETTINGS > File Utilities.
  3. For Base Directory, select diags/shared.
  4. Under Base Directory, select the qkview directory.
  5. Select the QKView file to download.
  6. Select Download.

Use the CLI

  1. Log in to the CLI of the rSeries system or VELOS system controller or chassis partition as the admin user.
  2. Export the QKView file to the remote system using the following command syntax:

    file export protocol < https | scp | sftp> local-file <local_file_path> remote-host <ip_address> remote-file <remote_file_path> remote-port <port> username <user> password <password> [insecure]

    In the command syntax, note the following:

    • <https | scp | sftp> is the protocol to use when transferring the file to the remote system.
    • <local_file_path> is the path and file name of the QKView file on the F5 system. For example, diags/shared/qkview/example.qkview.
    • <ip_address> is the host name or IP address of the remote system.
    • <remote_file_path> is the directory, including the trailing slash character, on the remote system where the file will reside.
    • <port> is the destination port on the remote system.
    • <user> is a username on the remote system.
    • <password> is the password for the user on the remote system.
    • [insecure] Optional: If insecure is specified, remote system identity verification is disabled.

    For example, to export the diags/shared/qkview/example.qkview file to the diags/ directory on a remote system at 10.10.10.100 using HTTPS (443) with the insecure option, enter the following command:

    file export protocol https local-file diags/shared/qkview/example.qkview remote-host 10.10.10.100 remote-file diags/ remote-port 443 username admin password admin insecure

    The command output appears similar to the following example:

    result File transfer is initiated.(diags/shared/qkview/example.qkview)

  3. Enter the following command to check the status of the transfer:

    show file transfer-operations

    The following example output shows the transfer has completed:

    file transfer-operations transfer-operation diags/shared/qkview/example.qkview 10.10.10.100 diags/ "Export file" "HTTPS " status " Completed" timestamp "Wed Mar 01 17:59:27 2023"

Use the REST API

  1. Log in to a system with the curl utility installed.
  2. Export the QKView file to the remote system using the following command syntax:

    curl -X POST -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/f5-utils-file-transfer:file/export" -d '{"f5-utils-file-transfer:insecure":"","f5-utils-file-transfer:username":"<user>","f5-utils-file-transfer:password":"<password>","f5-utils-file-transfer:local-file":"<local_file>","f5-utils-file-transfer:remote-url":"<remote_url>"}'

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the rSeries system or VELOS system controller or chassis partition.
    • <mgmt_address> is the host name or management IP address of the rSeries system or VELOS system controller or chassis partition.
    • <user> is a username on the remote system.
    • <password> is the password for the user on the remote system.
    • <local_file> is the path and file name of the QKView file on the F5 system. For example, diags/shared/images/example.qkview.
    • <remote_url> is the URL of the remote directory where the QKView file will reside. For example, https://10.10.10.100/diags/.

    For example, to export the diags/shared/qkview/example.qkview file to the diags/ directory on the remote system at 10.10.10.100 using HTTPS (443) with the insecure option, enter the following command:

    curl -X POST -sku admin:admin -H "Content-Type: application/yang-data+json" "https://10.10.10.200/api/data/f5-utils-file-transfer:file/export" -d '{"f5-utils-file-transfer:insecure":"","f5-utils-file-transfer:username":"admin","f5-utils-file-transfer:password":"admin","f5-utils-file-transfer:local-file":"diags/shared/qkview/example.qkview","f5-utils-file-transfer:remote-url":"https://10.10.10.100/diags/"}'

  3. Check the status of the transfer using the following command syntax:

    url -X GET -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/f5-utils-file-transfer:file/transfer-operations"

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the rSeries system or VELOS system controller or chassis partition.
    • <mgmt_address> is the host name or management IP address of the rSeries system or VELOS system controller or chassis partition.

    For example, to check the transfer status using the previous example, enter the following command:

    curl -X GET -sku admin:admin -H "Content-Type: application/yang-data+json" "https://10.10.10.200/api/data/f5-utils-file-transfer:file/transfer-operations"

    The command returns output similar to the following example:

    {
      "f5-utils-file-transfer:transfer-operations": {
        "transfer-operation": [
          {
            "local-file-path": "diags/shared/qkview/example.qkview",
            "remote-host": "10.10.10.100",
            "remote-file-path": "diags/",
            "operation": "Export file",
            "protocol": "HTTPS   ",
            "status": "         Completed",
            "timestamp": "Wed Mar  1 16:16:00 2023"
          }
        ]
      }
    }

Upload the QKView file to iHealth

You can upload QKView files to the iHealth system using the iHealth website or the iHealth API. To do so, perform the appropriate procedure:

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

  • Use the iHealth website
  • Use the iHealth API

Use the iHealth website

  1. Log in to ihealth.f5.com using your MyF5 login credentials.
  2. In the upper-left corner, select Upload.
  3. Select Choose to locate the QKView file. Alternatively, you can drag and drop the QKView file onto the page.
  4. For F5 Support Case (SR), enter the support case number if applicable.
  5. For Description, enter text to identify the QKView.
  6. Select Upload QKView(s). 

Use the iHealth API

  1. Follow the steps in K000130498: Generating new iHealth API credentials using iHealth API token service to generate a Client ID and Client Secret as needed. A pop-up window will appear that contains the curl request for the bearer access token with the authorization information pre-populated. Copy this entire curl command string for use in the next steps to request and save a bearer token.
  2. Log in to a system with the curl and jq utilities installed.
  3. Generate a token and save it to an environment variable using the following command syntax:

    export <var_name>=$(<copied_curl_command> | jq -r '.access_token')

    In the command syntax, note the following:

    • <var_name> is a name for the environment variable.
    • <copied_curl_command> is the entire curl command string you copied from the iHealth pop-up window.

    For example, the following command saves the bearer token to a variable named MYTOKEN:

    export MYTOKEN=$(curl --request POST --url https://identity.account.f5.com/oauth2/ausp95ykc80HOU7SQ357/v1/token -H "accept:application/json" -H "authorization: Basic vp3Z955PeOG08jP8BDHvB5muBZjd0DI6zzguBpLJnBzRdXvXIb2xEil5vgYlCrvWuXeCp4dW4h1MRfeZmOck" -H "cache-control: no-cache" -H "content-type: application/x-www-form-urlencoded" --data "grant_type=client_credentials&scope=ihealth" | jq -r '.access_token')

  4. Using the newly created bearer token, upload the QKView file to the iHealth system using the following command syntax:

    curl -X POST -sk -H "Accept: application/vnd.f5.ihealth.api" -H "Authorization: Bearer $<token_variable>" https://ihealth-api.f5.com/qkview-analyzer/api/qkviews -F "qkview=@<qkview_name>" -F "description=<description>" -F "f5_support_case=<case_number>" -F "visible_in_gui=True"

    In the command syntax, note the following:

    • <token_variable> is the name of the newly created environment variable to which the bearer token is saved. In the example, the variable name is MYTOKEN.
    • <qkview_name> is the QKView file name.
    • <description> is a description for the QKView in iHealth.
    • <case_number> is the associated support case number if relevant.

    For example, to upload the example.qkview file to iHealth when the bearer token is saved to the MYTOKEN environment variable, enter the following command:

    curl -X POST -sk -H "Accept: application/vnd.f5.ihealth.api" -H "Authorization: Bearer $MYTOKEN" https://ihealth-api.f5.com/qkview-analyzer/api/qkviews -F "qkview=@example.qkview" -F "description=ihealth_example" -F "f5_support_case=C12345678" -F "visible_in_gui=True"

    The command returns output similar to the following example:

    <?xml version="1.0" encoding="UTF-8" standalone="yes"?><qkview_upload><result>OK</result><id>20772134</id><location>https://ihealth-api.f5.com/qkview-analyzer/api/qkviews/20772134</location><expiration_date>1679165760</expiration_date></qkview_upload>
