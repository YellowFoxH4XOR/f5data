Issue

Description

Command execution or Operating system command injection Web application is a common attack against web applications and target the Operating system commands to gain access to the operating system.
The Web application can be manipulated to process user input with the operating system command line and execute them on behalf of the web server permission. 

Environment

  • BIG-IP ASM / AWAF version 11
  • The application is under an OS Command Injection attack
  • A security policy is assigned to the virtual server
  • BIG-IP ASM request log is enabled by default to illegal request

Cause

None

Recommended Actions

To mitigate the OS Command Injection / command execution attack, perform the following procedures in the order they are listed.

Impact of procedure: Adding attack signatures to the security policy can generate false positives. In such case false positives should be removed using the learning page. Adding Command execution attack signatures set includes various types of operating systems which allows the protection regardless of the backed servers.

  • Add the Command execution signatures
  • Enable and enforce the Command execution signatures
  • Switch to blocking
  • Verify that the Command execution is being blocked

Add the Command execution signatures

  1. Go to Security > Application Security > Attack Signatures > Attack Signatures Configuration.
  2. From the right combo box Available Signature Sets choose Command execution signatures and the add button.
  3. The signature set will be added to the list of Assigned Signature Sets.
  4. Click Save and then click Apply Policy. The page will reload.

Enable and enforce the Command execution signatures

  1. Uncheck the Enable signatures staging option.
  2. Click Save then click Apply policy.

Switch to blocking

  1. Go to Security > Application Security > Blocking > Settings.
  2. Under Enforcement Mode, select Blocking.
  3. Click Save and Apply Policy.

Verify that the Command execution is being blocked

  1. Go to Security > Event Logs > Application > Requests.
  2. Click on Show Filters Details to open the filer.
  3. Under Violation, choose Attack signature detected, then click Go.
  4. The blocked request with Command execution should be listed in the request log.
  5. The attack type name in the request log will be shown.

Additional Information

BIG-IP ASM and Advance WAF can mitigate Command execution injections attack with the attack signature feature or with defined metacharacters. This procedure lists the steps needed to mitigate Command execution injection using the Attack signatures and assumes that default configuration is defined.

The procedure below includes how to assign the relevant attack signature set, enable it and configure it in blocking mode so that the Command execution attacks can be mitigated. The final step is the mitigation verification where the admin can see the Command execution being blocked.

*Default configuration means any of the BIG-IP ASM templates with transparent and staging period on for the policy.
