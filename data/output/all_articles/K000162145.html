Description

Procedure for Safely Restarting the NetworkManager Service on an F5OS Controller HA (High Availability)

Environment

  • F5OS-C 1.8.1

Cause

None

Answer/Recommended Actions

Step 1 - Identify active/standby controllers:

From either controller (admin user): # show system redundancy

Note which is Active (e.g., controller-1) and which is Standby (e.g., controller-2).

Step 2 - Restart NM on the Standby controller first:

Log into standby as root:

 # systemctl restart NetworkManager

Impact: This will cause a brief (~5–10 second) loss of management network connectivity on the standby controller while NM reinitializes interfaces. Failure to perform this action in accordance with the high-availability procedures may introduce indirect risks to the tenant(s).

Verify recovery:

 # systemctl status NetworkManager

Step 3 - Initiate controlled failover to the Standby:

From the active controller (F5OS-C CLI): # system redundancy failover

Wait for full HA stabilization.

Confirm the former standby is now Active before proceeding:

 # show system redundancy

Step 4 - Restart NM on the newly promoted Standby controller:

Log into standby as root: # systemctl restart NetworkManager

Impact: This will cause a brief (~5–10 second) loss of management network connectivity on the newly promoted standby controller while NM reinitializes interfaces. Failure to perform this action in accordance with the high-availability procedures may introduce indirect risks to the tenant(s).

Step 5 - Optional: Fail back to original active:

If operational preference is to restore the original active/standby roles:

 # system redundancy failover

Confirm roles restored via show system redundancy.
