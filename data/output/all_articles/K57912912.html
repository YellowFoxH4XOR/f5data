Description

Workaround to filter Log messages:  Error message: httpd<pid>: [error] <client_ip> AUTHCACHE Error processing cookie <cookie_string> - Cookie user mismatch

If you are concern about excessive Logs like the following example on your BIGIP device under /var/log/ltm

Oct 28 04:14:21 LTM-1 warning httpd[18770]: [warn] [client 10.10.10.11] AUTHCACHE Error processing cookie 09B4151A00F5C69150CECC7300CCC29EAE1D31AF - Cookie user mismatch
Oct 28 04:14:21 LTM-1 warning httpd[18770]: [warn] [client 10.10.10.11] AUTHCACHE Error processing cookie 75D49454FA28443B9D3942590658F96772C6A644 - Cookie user mismatch
Oct 28 04:14:21 LTM-1 warning httpd[18770]: [warn] [client 10.10.10.11] AUTHCACHE Error processing cookie 8D3A13C4BB3E9D327A8A701A87BCD748F4CAEE0F - Cookie user mismatch
Oct 28 04:14:21 LTM-1 warning httpd[18770]: [warn] [client 10.10.10.11] AUTHCACHE Error processing cookie CA2B2707289CD5F9B39667397C22D36A634790AE - Cookie user mismatch
Oct 28 04:14:23 LTM-1 warning httpd[20698]: [warn] [client 10.10.10.11] AUTHCACHE Error processing cookie 8D3A13C4BB3E9D327A8A701A87BCD748F4CAEE0F - Cookie user mismatch

Environment

  • BIG-IP LTM
  • AUTHCACHE Error
  • Cookie Missmatch

Cause

This logs can be caused due to:

  • A client or an iControl application makes frequent connections to the BIG-IP Configuration utility; if that's the case, then you can follow up the recommendations described in here:   

  • K11140735: Error message: httpd<pid>: [error] <client_ip> AUTHCACHE Error processing cookie <cookie_string> - Cookie user mismatch

  • Similar messages may also be logged when a user logs in to either REST or the GUI and remote authentication is configured (ldap/tacacs/radius/etc). This is regardless of the auth-pam-validate-ip setting described in K13048 .


Recommended Actions

Despite the conditions on which you are facing these logs and if you want to get rid of them, what you can do is to create a Syslog filter to do it.
You can use one like of the following example:

==============================
sys syslog { include "
# remote logging
# Log level : Warning - Emergency
destination d_loghost {
    udp(\"172.27.9.200\" port(514));
};

filter f_remote_severity {
    level(warn..emerg);
};

filter f_remote_ft {
    not match("AUTHCACHE");
};

log {
   source(s_syslog_pipe);
   filter(f_remote_severity);
   filter(f_remote_ft);
   destination(d_loghost);
};

filter f_local6 {
   facility(local6) and
   not (level(warning) and (match('Cookie user mismatch') or match('AUTHCACHE Error processing cookie')));
};

"}
==============================


So, after you save it, you should see it like this using the CLI:


root@(gallery-big-ip-13-1-3-4)(cfg-sync Standalone)(TimeLimitedModules::Active)(/Common)(tmos)# edit  /sys syslog all-properties
modify syslog {
    auth-priv-from notice
    auth-priv-to emerg
    clustered-host-slot enabled
    clustered-message-slot disabled
    console-log enabled
    cron-from warning
    cron-to emerg
    daemon-from notice
    daemon-to emerg
    description none
    include "                                                                            <<---------------------  the filter starts here
    # remote logging
    # Log level : Warning - Emergency
    destination d_loghost {
             udp(\"10.10.10.11\" port(514));               <<------------ you will need to change the ip for your remote syslog-ip
    };

    filter f_remote_severity {
           level(warn..emerg);
    };

    filter f_remote_ft {
           not match(AUTHCACHE);
    };

    log {
        source(s_syslog_pipe);
        filter(f_remote_severity);
        filter(f_remote_ft);
        destination(d_loghost);
    };

    filter f_local6 {
        facility(local6) and
        not (level(warning) and (match('Cookie user mismatch') or match('AUTHCACHE Error processing cookie')));
    };

    "                                                                                           <<------------------------ and filter finishes here
    iso-date disabled
    kern-from debug
    kern-to emerg
    local6-from notice
    local6-to emerg
    mail-from notice
    mail-to emerg
    messages-from notice
    messages-to warning
    remote-servers replace-all-with {
        remotesyslog1 {
            description none
            host 10.10.10.11
            local-ip none
            remote-port 514
        }
    }
    user-log-from notice
    user-log-to emerg
}


Another example of filter to get rid of this messages is:

==============================
include "
filter f_authpriv {
((facility(auth, authpriv) and level(notice..emerg)) and not match ('AUTHCACHE'))
or program(sshd)
or ((facility(auth,authpriv) and (program(httpd) or program(tamd))) and not match('AUTHCACHE'))
or message(pam_audit)
;
};

filter f_local0 {
facility(local0) and not match(soap);
};
"
==============================
