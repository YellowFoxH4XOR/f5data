Topic

BIG-IP and 3-DNS use the standard Unix logging utility, syslog, to deliver system messages to log files. You can configure the level of information that syslog delivers to log files or specify additional log files for different levels of information.

Facilities

The following facilities are available on BIG-IP and 3-DNS. Each facility handles messages for specific elements of the system, as described in the following table:

FacilityDescriptionDefault log file
local0All BIG-IP-specific messages other than bigd, sod, and proxyd messages./var/log/bigip
local1All bigd (health check) and sod messages./var/log/bigd
local2All 3-DNS-specific messages other than sod messages./var/log/3dns
local3All proxyd (SSL proxy) messages./var/log/proxyd
local4ITCM portal and server (iControl) messages./var/log/ITCM.log
local6All local LDAP messages./var/log/sldapd.log
local7All mrad (pvad) and MRA related messages./var/log/pva.log
cronAll messages related to the cron daemon./var/log/cron

authprivUser authentication messages that contain sensitive information./var/log/secure
ftpUnused on BIG-IP and 3-DNS. Messages for ftp are reported under daemon.N/A
lprUnused on BIG-IP and 3-DNS, as they do not provide printing support.N/A

Levels

The following levels are available for each facility. The facilities are listed in order of the severity of the messages they handle. Generally, higher levels contain all the messages for lower levels. For example, the alert level will generally also report all messages from the emerg level. The debug level will generally also report all messages for all levels.

LevelDescriptionVerbosity
emergEmergency system panic messages.Minimum
alertSerious errors that require administrator intervention.Low
critCritical errors, including hardware and filesystem failures.Low
errNon-critical, but possibly very important, error messages.Low
warningWarning messages that should at least be logged for review.Medium
noticeMessages that contain useful information, but may be ignored.Medium
infoMessages that contain useful information, but may be ignored.High
debugMessages that are only necessary for troubleshooting.Maximum

Adding new entries to syslog.conf file

You can configure the syslog utility by adding entries to its configuration file, /etc/syslog.conf.

Important: F5 Networks recommends that you do not change the existing entries contained in the syslog.conf file, because it already specifies the minimum amount of logging recommended. You can, however, increase the level of logging, or add additional log files.

Entries that you add to the syslog.conf file are cumulative. You cannot add a line to the file that will reduce the amount of logging from the default configuration. When adding entries to the syslog.conf file, you can use the wildcard character (*) in any of the fields. This allows you to choose multiple facilities at a specific level, multiple levels for a specific facility, or to log a message to multiple log files.

To add entries to syslog.conf file, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /etc directory by typing the following command:

    cd /etc

  3. Create a backup copy of the syslog.conf file by typing the following command:

    cp syslog.conf syslog.conf.original

  4. Using a text editor, edit the syslog.conf file.
  5. To the end of the file, add new entries in the following format:

    <facility>.<level> <log path>

    Note: You must include at least one tab between <facility>.<level> and <log path>.

  6. Restart the syslog daemon by typing the following command:

    Note: The following command includes back ticks, not single quotes.

    kill -HUP `pidof syslogd`

Sample configuration options

Following are sample configuration options for the syslog.conf file.

The following three entries will log the three most severe levels of BIG-IP messages (from local0) to a new log file:

local0.emerg   /var/log/hotbigip
local0.alert   /var/log/hotbigip
local0.crit   /var/log/hotbigip

The following entry will log all messages from facilities, at all levels, to one log file:

*.* /var/log/biglog

The following entry will log messages at the emergency level, from all facilities, to one log file:

*.emerg /var/log/emergency

The following entry will log messages from the daemon facility, at any level, to one log file:

daemon.* /var/log/daemon

The following entry will log all kernel messages to all the files in the /var/log directory:

kern.* /var/log/*

The following entry will log debug level messages from daemons to a log file:

daemon.debug /var/log/daemon-debug
