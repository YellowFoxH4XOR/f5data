Description

After upgrading or rebooting a BIG-IP VE, the BIG-IP appears to stop responding to all traffic on some or all of it's interfaces.

Environment

  • BIG-IP Virtual Edition (VE)
  • BIG-IP not replying to ARP requests

Cause

This issue is commonly caused by the hypervisor silently changing the order of interfaces it presents to the VE
Note: this can sometimes also occur on a reboot of a VE even without an upgrade.

Recommended Actions

A quick procedure to check that each interface on the VE is actually the hypervisor interface the admin expects it to be, is as follows:
  1. Disable ("disconnect") all but one interface given to the VE in the hypervisor.
  2. Reset all interface stats on the BIG-IP VE
    Note: this step is optional, but it makes it easier to see which interface' stat counters are still incrementing in the next step.
  3. Send some traffic to the BIG-IP on the one interface still enabled on the hypervisor, and check on the BIG-IP interface stats as to which interface is still showing an increasing number of "packets in".
The admin can do the above on each interface one by one, in order to get a mapping of "hypervisor interfaces" to "BIG-IP VE interfaces", and then change the vlans assigned to the hypervisor interfaces (on the hypervisor) to match what they'd expect to work from the BIG-IP side (so the BIG-IP config doesn't need to be changed).
