Description

This article speaks to whether a 'commit' operation required on F5OS when changes are issued via API.

Environment

  • Configuration changes are issued on F5OS via API using RESTCONF protocol

Cause

A 'commit' operation is essential when making changes via ConfD CLI. This is done within config mode after making the desired configuration changes. Exiting the config mode without issuing the 'commit' operation will lead to a prompt on whether or not to save the changes or cancel then, similar to the following:

syscon-1-active(config)# exit
Uncommitted changes found, commit them? [yes/no/CANCEL] yes
syscon-1-active#


When making changes via API using RESTCONF protocol, the change is instantaneous and there isn't a need to issue a 'commit' operation, as that is automatically performed by the user. If an active session is open via ConfD CLI to the F5OS device, the following messages will be seen in the prompt anytime changes are made via API:

syscon-1-active#
System message at 2024-10-03 11:15:45...
Commit performed by admin via http using rest.
syscon-1-active#

Recommended Actions

A 'commit' operation has to be manually issued only when making changes via ConfD CLI.

When making changes via API, the 'commit' operation is performed automatically and doesn't need to be issued by the user.
