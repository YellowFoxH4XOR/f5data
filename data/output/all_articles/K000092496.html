K000092496: Event log shows 'Delayed Violation' and 'unblocked' for illegal requests

Type
Support Solution
Published
2022-12-21
Updated
2022-12-30
Source
https://my.f5.com/manage/s/article/K000092496

Description

For an illegal http request, the request status is 'Unblocked', and the Blocking Exception Reason is 'delayed violation' in event logs.

Such requests can have introduce a potential security risk to the application.
 

Environment

  • Session tracking

Cause

This is due to the configuration under Security > Application Security > Sessions and Logins > Session Tracking > Delay Blocking

 

Recommended Actions

There are many different options in 'Delay Blocking' and each of them can affect the outcome. 

The simplest way is to lower the value of each option, such as changing 'IP Address Threshold' from 10 to 2 or even disabling the relevant option to block illegal requests.

If the request is detected by ASM attack signatures, the following workaround could be used to solve this issue.

Note: The following is an example using log4j signatures.

1. Create a ltm data-group which will include all the detected log4j signature.

The configuration file looks like below:

ltm data-group internal /Common/log4j2_signatures {

   records {

       200104768 { }

       200104769 { }

       200004450 { }

       200004451 { }

       200004474 { }

       200104770 { }

       200104771 { }

       200104772 { }

       200104773 { }

   }

   type string

}

2. Create below iRule:

ltm rule /Common/log4j2_sig_test {

when ASM_REQUEST_DONE {

if {[ASM::violation names] contains "VIOLATION_ATTACK_SIGNATURE_DETECTED" and [class match [ASM::violation details] contains log4j2_signatures] }

{

 ASM::raise sig-detected

 log local0. "ASM working"

}

}

}

3. Attach the iRule to the affected virtual server

4. Browse to Security > Application Security > Security Policies > Policies List and find the security policy in question, select 'Advanced', and then choose 'normal mode' for Trigger ASM iRule Events.

5. Click 'Save', then apply 'policy'

6. the ASM::raise method requires a user-defined (custom) violation.

a. browser to Security > Options > Application Security > Advanced Configuration > Violations List

b. Click on User-Defined Violations

c. Create violation named sig-detected

Now the request will be blocked immediately but you will still see the same 'delayed violation' for Blocking Exception Reason and 'unblocked' for request status, which is fine.
