Known Issue

When BIG-IP AFM classifies certain Internet Control Message Protocol (ICMP) packets that match the rules at the Global and Route Domain contexts, the Traffic Management Microkernel (TMM) may produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • You have configured BIG-IP AFM with a Logging profile in which both Rule Logging and Log Translations are enabled.
  • From the Security > Reporting menu, the server-side AVR Statistics collection is enabled.
  • Certain ICMP packets (for example, multicast ICMP echo) are classified and match the BIG-IP AFM rules at the Global and Route Domain contexts.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If you have configured the BIG-IP system as part of a high availability (HA) group, a device failover may occur.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if the system is configured for HA.
  • The TMM process restarts and produces a core file in the /shared/core directory.
  • You observe log entries in the /var/log/tmm* files that appear similar to the following example:

    panic: ../lib/fw_log/fw_log.c:5289: Assertion "max fw_log_opaque entries" failed.

Workaround

There is no work around for this issue. However, you can avoid the issue by disabling Log Translations in the BIG-IP AFM Logging profile configuration.
