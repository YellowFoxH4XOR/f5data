Topic

You should consider using this procedure under the following condition:

  • You want to protect your web application from session (cookie) hijacking attacks.

Description

Session (cookie) hijacking is an attack which exploits a computer session to gain unauthorized access to information in a computer system or web application. An attacker hijacks cookies from a user session and attempts to use the cookies for authentication.

You can mitigate session hijacking by configuring your BIG-IP ASM security policy to track client sessions by enabling the Session Hijacking feature. When you enable the Session Hijacking feature in the security policy, the BIG-IP ASM system uses JavaScript to obtain a unique device ID for the client device. The system encrypts and stores the device ID in the ASM cookie, which remains with the client for the duration of the HTTP session. If the device ID or message key changes during the session or the session times out, the BIG-IP ASM system considers the request to be an attack and performs the actions defined in the learning and blocking settings for the policy.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have access to the Configuration utility.

Procedures

  • Enable Accept XFF in the HTTP profile
  • Enable the Session Hijacking feature
  • Enable blocking modes for session hijacking violations (BIG-IP 15.x and later)
  • Enable blocking modes for session hijacking violations (BIG-IP 14.x and earlier)

To watch a video demo of these procedures, go to  Configure session hijacking .

Enable Accept XFF in the HTTP profile

If you deploy your BIG-IP ASM system behind an internal or other trusted proxy, then you should enable the Accept XFF setting in the HTTP profile associated with the virtual server. Doing so allows the BIG-IP ASM system to use the IP address that initiated the connection to the proxy when creating the device ID.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Services > HTTP.
  3. Select the HTTP profile associated with the BIG-IP ASM-enabled virtual server.
  4. Under Settings, select the Custom check box.
  5. Select the Accept XFF check box.
  6. Select Update.

Enable the Session Hijacking feature

Impact of procedure: After you enable the Session Hijacking feature, the security policy blocks client browsers that do not support JavaScript.

  1. Go to Security > Application Security > Session Tracking.

    Note: For BIG-IP 16.0.x and earlier, go to Security > Application Security > Sessions and Logins > Session Tracking.

  2. In Session Hijacking, for the policy you want to modify, for Detect Session Hijacking by Device ID Tracking, select the Enabled check box.

    Note: Device-ID mode must be configured in Bot profile and the profile assigned to the virtual server for this option to work.

  3. Select Save.
  4. Select Apply Policy.

Enable blocking modes for session hijacking violations (BIG-IP 15.x and later)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Security > Application Security > Security Policies > Policies List.
  2. For Policies List, select the name of the policy you want.
  3. Under Policy Configuration, select General Settings.

    Note: For BIG-IP 15.x through 16.0.x, under Security Policy Configuration, select General Settings.

    Note: Setting Enforcement Mode to Blocking blocks all requests that cause violations which are set to block.

  4. For Enforcement Mode, select the Blocking.
  5. Select Save.
  6. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  7. For Policy Building Settings, expand Sessions and Logins, and, for ASM Cookie Hijacking, select the Learn, Alarm, and Block check boxes.
  8. Select Save.
  9. Select Apply Policy.

Enable blocking modes for session hijacking violations (BIG-IP 14.x and earlier)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. Under General Settings, For Enforcement Mode, select Blocking.

    Note: Setting Enforcement Mode to Blocking blocks all requests that cause violations which are set to block.

  3. For Policy Building Settings, expand Sessions and Logins, and for ASM Cookie Hijacking, select the Learn, Alarm, and Block check boxes.
  4. Select Save.
  5. Select Apply Policy.
