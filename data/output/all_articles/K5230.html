K5230: Discovery and automatic configuration sets the unit ID of a 3-DNS or Link Controller redundant peer to unit 1

Known Issue

This is the result of a known issue. Auto-configuration will always set the Unit ID of a redundant peer to Unit 1, if a unit ID is not already configured.

An incorrect unit address can cause problems with failover.

If the Unit ID has been set incorrectly to Unit 1, perform the following steps to change the Unit ID to Unit 2:

  1. Log in to the command line.
  2. Set the Unit ID, by typing the following command:

    bigpipe db set Local.Bigip.Failover.UnitId = "2"

  3. Set the config command default Unit ID setting, by typing the following command:

    bigpipe db set Local.Bigip.FTB.UnitNumber = "2"

  4. Reboot the 3-DNS, by typing the following command:

    reboot

After the system reboots, 3-DNS will use the new unit number.

F5 Network Product Development tracked this issue as CR24734 and CR24735.
