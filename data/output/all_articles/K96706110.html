Description

Getting error while deploying a new topology/application on SSLO

 There is a pending configuration. Add new, modify and delete of existing deployed instances are not allowed.


Symptoms you may see: 

On Active unit:
 --topology is stuck on Interception rule creation during deploying

 --clicking Undeploy from iApps > Application Service > Applications LX , it is stuck with the message "Undeploying Configuration , Please wait" for long

 --due to the Topology has many rules defined, you couldn't afford to delete the entire topology.
 --from the output of tmsh list mgmt shared gossip-conflicts command, looks like there were some conflicts


On Standby unit:
 --the topology is deployed successfully
 

Environment

  • Upgrade BIG-IP from v15.1.1 to v16.x
  • Config fails to load

Cause

Due to introduced RFE ID719338 in v15.1.1
ID947905 is created to trace this upgrade problem

Recommended Actions

Pre-requisites:
1. Make sure these prerequisites are in place:
  *The ha-sync script requires passwordless SSH access from the local BIG-IP device, where the script runs, to the remote BIG-IP HA peer. See the Reverting the effect of ssh-copy-id and removing the passwordless SSH access section below for the procedural steps. This can also be set up by following the instructions in K13454: Configuring SSH public key authentication on BIG-IP systems (11.x - 15.x).
     *The following is a summary (procedure) of the aforementioned article. Run the following commands on the BIG-IP device where the ha-sync script would be executed. (Replace $HA_PEER with the IP address of the remote HA peer device).
      ssh-keygen
      ssh-copy-id -i ~/.ssh/id_rsa.pub $(whoami)@$HA_PEER
The user account ($(whoami)) should have superuser privileges on the remote BIG-IP HA peer device.

2. Reverting the effect of ssh-copy-id and removing the passwordless SSH access (optional)
The ha-sync script requires passwordless SSH access from the local BIG-IP device, where the script runs, to the remote BIG-IP HA peer.
Optionally, you may use the following procedure to revert the effect of ssh-copy-id and remove the passwordless SSH access. This can also be set up by following the instructions in K13454

  a. SSH into the BIG-IP device where ssh-copy-id has been invoked.
  b. Identify the public key used with ssh-copy-id: cat ~/.ssh/id_rsa.pub.
  c. SSH into the remote HA peer (where the related key has been copied).
  d. Edit the /root/.ssh/authorized_keys file and remove the line containing the key retrieved in step 2.

For more information, see:
Manual Chapter : Overview: SSL Orchestrator High Availability Diagnostics and Sync-Repair Tool


BIG-IP 16.0 and later versions:
ha-sync is already included and can be found in /usr/bin/ha-sync


Prior to BIG-IP 16.0.0:

1. Contact F5 support to obtain the ha-sync script

2. Copy the ha-sync script to an arbitrary location on the Standby BIG-IP device (e.g. /var/tmp).

3. Make the file readable, writable and executable, by running this command:

   chmod 777 /var/tmp/ha-sync

4. Run the ha-sync tool in repair mode.
   /var/tmp/ha-sync -f -H $HA_PEER -D $DEVICE_GROUP

   where:
       $HA_PEER: a routable IP address of the remote HA sync peer
       $DG_GROUP: the HA-sync device group

5. Run the ha-sync tool in diagnostic mode and make sure all is good:
   /var/tmp/ha-sync --diagnostic -H $HA_PEER -D $DEVICE_GROUP
