K56428353: TTL 0 when all nodes are offline or disabled. Where is that coming from?

Type
Support Solution
Published
2023-05-05
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP GTM
  • BIG-IP DNS: 14.1.X, 14.1.5, 14.1.4, 14.1.3, 14.1.2, 14.1.0
Source
https://my.f5.com/manage/s/article/K56428353

Description

Queries return a TTL of 0 when wide IPs and pools are disabled, even though their primary, alternate, and fallback load balancing method is set to round robin.

Environment

  • These wide IPs and pools are disabled at the data center level.
  • The TTL at the wide IP and pool level is set to 30, which is the default.

Cause

The TTL of 0 is coming from local BIND per the DNS profile applied to the GTM/DNS listener. This setting, "use-local-bind", is enabled by default. 

Recommended Actions

Disable local BIND on the DNS profile.

  • DNS  ››  Delivery : Profiles : DNS  ››  New DNS Profile...
  • Check "Use BIND Server on BIG-IP" on the right column
  • Then choose Disabled from the drop down list
  • Update to save.
  • Apply this DNS profile to the GTM/DNS listener

Additional Information

  1.  Is there a way to change this TTL?
    • Change the TTL for A records per zone within ZoneRunner.
    • DNS  ››  Zones : ZoneRunner : Zone List
  2. Is there a global zone runner TTL or is it per record?
    • There's no global mechanism to change ALL A records. Change the TTL via BIND directly per K7032 or via ZoneRunner (recommended).
      • K7032: Freezing zone files to allow manual update to ZoneRunner-managed zone files
         
  3. How do these BIND records refresh?
    • The zone records in /var/named/config/namedb are managed via ZoneRunner from the WebUI.
    • Delete zones via DNS  ››  Zones : ZoneRunner  ››   Zone List then select the MASTER record and delete.
    • If "Synchronize DNS Zone Files" is enabled in the GTM/DNS sync settings (DNS >> Settings >> GSLB >> Settings) then this update is propagated across the GTM/DNS in this sync group.
       
  4. What happens to that old, unused, no longer necessary BIND record?
    • Once the MASTER record is deleted this zone file no longer exists in the WebUI
    • This change is then propagated to other GTMs.
    • In the CLI, this zone record is renamed to .bak & the journal file is removed.
    • Note: Deleting this record from the CLI is possible, but change doesn't propagate to other GTMs.
