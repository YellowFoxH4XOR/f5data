Description

This article provides a checklist of common issues that may result in loss of BIG-IP ASM policy data after performing one of the following activities:

  • restarting services
  • system reboot
  • software upgrade
  • relicensing
  • loading configuration

Environment

  • BIG-IP ASM
  • Maintenance activity

Cause

K14933289: ASM policy changed from Transparent to Blocking mode after configuration failed to load

Recommended Actions

  1. Check and resolve config validation errors
    tmsh load sys config verify
  2. Resolve mysql database issues
    K14194: Troubleshooting the BIG-IP ASM MySQL database
  3. Create a dummy BIG-IP ASM Policy to ensure sync is working
    K09532358: Troubleshooting and data gathering to investigate ASM and Advanced WAF configuration sync issues and questions
  4. If you're not running the latest BIG-IP software maintenance release, disable BIG-IP ASM sync feature during maintenance activity to mitigate any BIG-IP ASM sync issues common in older versions of software.  See Related Content.
    GUI: Security ›› Options : Application Security : Synchronization : Application Security Synchronization Device Group

Additional Information

Ensure a valid UCS backup has been generated in case the configuration needs to be restored post activity.
Backup BIG-IP ASM Policies using Policy Export feature - K13905104: Overview of importing and exporting BIG-IP ASM security policies
