Description

TMM memory usage goes high after enabling Data 0-RTT in Client profile, the below tmm warning log can be observed in /var/log/ltm log:

  • 01010290:4: TCP: Memory pressure activated
  • 011e0002:4: sweeper_segment_cb_any: Aggressive mode /Common/default-eviction-policy activated.
The below command's subsystem memory table shows SSL EB Tree's usage is 2-2.5GB:
 
tmsh show sys memory 
...
SubSystem                        Alloc (bytes)  Max Alloc (bytes)  Object Size  Current Allocations  
===================================================================================================
SSL EB Tree                               2.3G               2.3G            1                65552
 

Environment

  • BIG-IP
  • V15.1 and above
  • Client SSL profile 
  • Data 0-RTT
  • clientssl-quic default profile
     

Cause

By design: When Data 0RTT is enabled and in use, BIG-IP allocates static memory (about 2-2.5GB) in TMM reserved memory.
However low TMM memory environment (RAM size, LTM provision none, minimum, etc), we may consider design change: Bug ID 883089 
 

Recommended Actions

  • BIG-IP has less than 8GB with LTM only provisioned
    This will likely cause lack of memory issue. If you can add RAM, please consider to increase it. 
  • BIG-IP has more than 8GB with multiple module are provisioned
    Depending on the combination of module provisioned, lack of memory issue could hit due to this design.
    • Make sure you are not moving TMM memory with db key provision.extramb.
    • Check how many objects you configure for the BIG-IP, follow provision recommendation for Management (MGMT)
    • If you set LTM provision none or minimum, then consider to set it to nominal, and if other userland processes need more memory adjust it with db key provision.extramb little by little.
      Please refer further detail about the db key: K26427018: Overview of Management provisioning.
