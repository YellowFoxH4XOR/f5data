Description

How to configure persistence on BIG-IP LTM so that it is enabled only for traffic to a specific subdomain or URI path, while other traffic remains non-persistent. Persistence profiles alone cannot provide conditional persistence based on HTTP Host or URI; an iRule is required. Example iRule, required profiles, and SSL termination requirements for HTTPS applications are provided.

Environment

  • Product: BIG-IP LTM

  • Version: 17.1.1 (applies to 11.x and later)

  • Scenario: HTTPS application requiring persistence only for a specific subdomain or URI path

  • Prerequisites: SSL certificate installed on BIG-IP for SSL termination; HTTP profile enabled on the virtual server

Cause

BIG-IP LTM persistence profiles do not natively support enabling persistence for only certain subdomains or URI paths. Conditional persistence requires inspection of HTTP headers or URI, which is only possible after SSL decryption (for HTTPS) and with an HTTP profile. An iRule is needed to apply or disable persistence based on the request's Host or URI.

Answer/Recommended Actions

  1. Ensure the virtual server has the following profiles attached:

    • Client SSL profile (for SSL termination)

    • HTTP profile (default is sufficient)

    • A persistence profile (e.g., source_addr or universal) to be referenced by the iRule

  1. Example iRule to enable persistence only for a specific subdomain and URI path:

   when HTTP_REQUEST {
       set host [string tolower [HTTP::host]]
       set uri [string tolower [HTTP::uri]]
       if { $host eq "subdomain.example.com" && [string match "/specificpath*" $uri] } {
           persist uie [IP::client_addr]
           log local0. "Applied persistence for specificpath: [IP::client_addr]"
       } else {
           persist none
           log local0. "No persistence for this request"
       }
   }

Note: Adjust the host and URI conditions as needed for your environment.

  1. Attach the iRule to the virtual server:

    • Go to Local Traffic > Virtual Servers > [Your Virtual Server] > Resources > iRules > Manage > add the iRule.

 

Additional Information

  • If you receive an error when attaching the iRule, ensure the HTTP profile is enabled on the virtual server.

  • For HTTPS traffic, SSL termination is required on the BIG-IP to inspect HTTP headers/URI.

  • The persistence profile referenced in the iRule must also be attached to the virtual server.

  • To adjust the persistence timeout (e.g., to 20 minutes), edit the persistence profile under Local Traffic > Profiles > Persistence, set the desired timeout, and update.
