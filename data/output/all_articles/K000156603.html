K000156603: FQDN pool resolving IPv4 and IPv6 addresses, causing "No route to host" errors for some requests

Type
Support Solution
Published
2025-09-24
Updated
2025-09-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000156603

Description

Intermittent errors such as:

RST sent from <IP>:443 to <IP>:<port>, [0x31cf394:5322] No route to host

or

connection refused

may occur when connecting to a BIG-IP LTM virtual server with a pool member defined by FQDN (e.g., example.com). These errors are observed even though DNS resolution for the FQDN returns both IPv4 and IPv6 addresses, while the network environment is configured to use only IPv4.

Environment

  • Product: BIG-IP LTM
  • Software Version: 17.x
  • Configuration:
    • Pool member defined by FQDN (e.g., example.com)
    • Node configuration:

      ltm node /Common/example.com {

          fqdn {

              address-family all

              autopopulate enabled

              name example.com

          }

      }

    • Organization network supports only IPv4; IPv6 is not used.

Cause

When an FQDN node is configured with address-family all, BIG-IP automatically creates ephemeral pool members for both IPv4 and IPv6 addresses returned by DNS. If the network does not support IPv6, connections to these pool members will fail, resulting in "no route to host" or "connection refused" errors.

Recommended Actions

To resolve this issue, configure the FQDN node to use only IPv4 addresses:

 

  1. Delete the existing FQDN node.
  2. Recreate it using:
    tmsh create ltm node /Common/example.com fqdn { name example.com address-family ipv4 autopopulate enabled }
  3. Add the node back into your pool configuration.
  4. After applying these changes, only IPv4 pool members will be created and used, preventing routing errors related to unused IPv6 addresses.
