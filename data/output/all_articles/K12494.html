Known Issue

This is the result of a known issue. A UDP virtual server referencing an iRule containing commands that can suspend operation may result in the TMM not responding when the adaptive reaper becomes more aggressive.

Note: For information about iRules commands that temporarily suspend iRule execution, refer to K12962: Some iRules commands may temporarily suspend iRule processing.

When these iRule commands are triggered, the TCL interpreter is suspended until the command completes. If the adaptive reaper closes the connection that triggered these commands, and the TCL interpreter attempts to resume processing on the now-closed connection, TMM stops responding.

F5 Product Development tracked this issue as ID 242448 (formerly CR133972) and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM, Link Controller, or WOM release notes.

In addition, BIG-IP iHealth lists Heuristic H380421 on the Diagnostics > Identified > High screen.

Note: For more information about a similar known issue, refer to K12643: A UDP virtual server that uses an iRule with a suspending command in the CLIENT_CLOSED iRule event may cause TMM to crash.
