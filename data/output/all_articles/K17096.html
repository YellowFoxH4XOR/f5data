Known Issue

In a Virtual eXtended LAN (VXLAN) tunnel, remote endpoint gratuitous Address Resolution Protocols (ARP) may not trigger a forwarding database (FDB) update on all Traffic Management Microkernel (TMM) instances.

This issue occurs when all of the following conditions are met:

  • You have configured a VXLAN tunnel with a failover pair of remote endpoints.
  • The remote endpoints are configured to use the same Media Access Control (MAC) address.
  • A failover event occurs, which triggers gratuitous ARP messages from the active endpoint peer.

Impact

Connections may fail through the VXLAN tunnel if the BIG-IP system forwards packets to the wrong interface.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Connections intermittently fail through the VXLAN tunnel.
  • When using the Traffic Management Shell (tmsh) to view the FDB, the same MAC address is associated with two different endpoints IP addresses:

    # tmsh show net fdb tunnel

    ---------------------------------------------------------------------
    Net::FDB
    Tunnel            Mac Address        Member                   Dynamic
    ---------------------------------------------------------------------
    example_vxlan123  04:23:f7:aa:00:c3  interface:192.168.1.100  yes
    example_vxlan123  04:23:f7:aa:00:c3  interface:192.168.1.101  yes

Workaround

To work around this issue, ensure tunnel endpoints do not use the same MAC address in their high-availability configuration.

Impact of workaround: Performing the suggested workaround may reduce reliability and failover speed in lossy networks and with switches that are slow to respond to gratuitous ARP requests.
