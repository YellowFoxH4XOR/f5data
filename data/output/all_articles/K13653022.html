Description

In rare instances, F5 Support may ask to enable debugging for the pabnagd daemon.

Note: This article applies to BIG-IP ASM systems running 14.x or earlier.  For 15.x and later systems, use the procedure of K71214833: Enabling pabnagd debugging in 15.x and later.

Environment

  • ASM provisioned

Cause

Not applicable.

Recommended Actions

Note: The extra logging can cause some additional load (particularly I/O load) on the unit.

Enabling pabnagd debugging

To enable additional pabnagd debugging, perform the following steps:

  1. Make a backup of the pabnagd logging configuration:

/bin/cp /etc/ts/pabnagd/log4crc /etc/ts/pabnagd/log4crc.orig

  1. Edit the /etc/ts/pabnagd/log4crc file
  2. For each setting in the file for which additional debugging is desired, change the priority from "notice" to "trace".

For example, to enable additional debugging related to the learning of file types, find this line

<category name="filetypes"    priority="notice" appender="pabnag" additivity="false"/>

Change it to this:

<category name="filetypes"    priority="trace" appender="pabnag" additivity="false"/>

  1. Save and return to the CLI.

Note: The change should be detected automatically by the pabnagd daemon.  No restart should be required.

Disabling pabnagd debugging

To turn off the additional debugging, change the modified priority or priorities back to "notice" and save.

Alternatively, replace the modified file by the backup copy:

/bin/cp /etc/ts/pabnagd/log4crc.orig /etc/ts/pabnagd/log4crc

Additional Information

If using the reset-to-default option with the "tmsh modify sys db log.asm.pabnagd.level" command, the pabnagd daemon has to be restarted manually.
