Known Issue

This is the result of a known issue. If a virtual server is configured with an HTTP profile with RAM Cache enabled, and the virtual server processes two HTTP pipeline requests for RAM Cache objects, the second request causes the TMM process to crash.

F5 Product Development tracked this issue as CR76498 and it was fixed in BIG-IP LTM 9.3. For information about upgrading, refer to the BIG-IP LTM Release Notes.
