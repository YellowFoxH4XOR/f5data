Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP system is configured to offload Secure Sockets Layer (SSL) processing using a virtual server and an associated Client SSL profile.
  • You have imported and associated a new Certificate Authority (CA) signed SSL certificate with the Client SSL profile.
  • You want to verify the new CA signed SSL certificate is in use and is working properly.

Description

When you associate a new CA-signed SSL certificate with a Client SSL profile, you should verify that the new SSL certificate is working as expected. This article assumes that the new CA -igned SSL certificate is being used to secure a website and will use information from your BIG-IP system and your web browser to verify that the SSL certificate is in use and working correctly.

It is important that remote clients avoid any web browser warning messages when visiting a trusted and secure website. Most popular web browsers will pause a new SSL connection and advise the client to avoid the website when any of the following SSL certificate validations fail:

  • Trusted CA: The SSL certificate must be signed by a trusted CA held in the browser's Trusted Root CA store.
  • Validity: The SSL certificate must be currently valid. CA-signed SSL certificates are typically valid for one to three years.
  • Domain Name: The domain name typed in the web browser's URL must match the SSL certificate's Common Name (CN).
  • Hash Algorithm: SSL certificates must be signed using a SHA-2 hashing algorithm.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.
  • You have associated the new CA-signed SSL certificate with the Client SSL profile.
  • You have a workstation with a popular and up-to-date web browser.

Procedures

  • Obtaining the SSL certificate properties from the BIG-IP system
  • Verifying the SSL certificate using a web browser
  • Mismatching SSL certificate properties

Obtaining the SSL certificate properties from the BIG-IP system

This procedure will help you obtain the CA-signed SSL certificate property information from the BIG-IP system. The SSL certificate property information will be used in the next procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to the SSL Certificate List.

    13.0.0 and later:

    System > Certificate Management > Traffic Certificate Management > SSL Certificate List.

    12.1.2 and earlier:

    System > File Management > SSL Certificate List.

  3. Under Name, select the new CA-signed SSL certificate that is associated with the secure website.
  4. In the Certificate Properties section, make note of the following certificate properties:

    Serial NumberA number that uniquely identifies the certificate. Assigned by the CA at the time of signing.df:09:60:94:9a:07:ea:7a
    233931343
    Subject > Common NameThe domain name of the web site.www.example.com
    *.example.com
    IssuerThe name of the CA that signed the SSL certificate.Symantec Corporation

Verifying the SSL certificate using a web browser

From your workstation, connect to the secure website to verify that there are no web browser warning messages and that the new signed SSL certificate is in use.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your local workstation.
  2. Open a new web browser page.
  3. Type the domain name of the secure website into the URL field and hit Enter. For example:

    https://www.example.com

  4. The web browser should not display any warning messages. If any warning messages appear, review the article introduction regarding SSL certificate validation. There are also several SSL checker websites that offer in-depth analysis of SSL certificates.
  5. If the web browser displayed no warning messages, a lock icon should be displayed in or near the URL field.

    Note: Use the following to help determine lock icon position:

     
    BrowserColor / Position
    Chrome
    Firefox    		Green / Left
    Internet ExplorerGrey / Right
    SafariGrey / Left
  6. Click the lock icon and select either View certificates, More Information, or Show Certificate to obtain the SSL certificate property information.

    Note: You may need to determine how your specific web browser presents the SSL certificate information.

  7. Compare the SSL certificate properties obtained in the web browser with the SSL certificate properties obtained on the BIG-IP system.

    Note: Use the following table to correctly map the SSL certificate properties:

     
    BIG-IPWeb Browser
    ExpiresValid to
    Serial NumberSerial Number
    Subject > Common NameSubject > CN
    IssuerIssuer
  8. If the SSL certificate properties do not match, continue to the next procedure.

Mismatching SSL certificate properties

There may be several reasons that the SSL certificate properties obtained in the previous procedures do not match:

  • The CA-signed SSL certificate was imported, but not associated with the Client SSL profile.
  • The Client SSL profile is associated with a different SSL virtual server.
  • The IP address of the web site domain name maps to a different server or virtual server.
  • The updated BIG-IP system's redundancy status is STANDBY.

You can use the following procedures to help determine why the SSL certificate properties are mismatching.

On the BIG-IP system

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Next to the F5 icon, verify the BIG-IP system status is ONLINE (ACTIVE).
  3. Navigate to Local Traffic > Profiles > SSL > Client.
  4. Under Name, select the appropriate Client SSL profile.
  5. Select the Certificate Key Chain and click Edit.
  6. Ensure the new CA-signed SSL certificate has been selected.
  7. Click Update if any modifications were made to the Certificate Key Chain.
  8. Navigate to Local Traffic > Virtual Servers.
  9. Under the Virtual Server List, select the appropriate virtual server.
  10. Under General Properties, make note of the Destination Address for the next procedure.
  11. Under Configuration, verify that the SSL Profile (Client) option has the proper profile under Selected.

From the workstation

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Access the workstation's command line utility.
  2. To obtain the IP address for the website domain name, use the following command syntax:

    nslookup <domain_name>

    For example, to obtain the IP address for the website using www.example.com domain name, type the following command:

    nslookup www.example.com

    The command output should appear similar to the following example:

    Non-authoritative answer:
    Name:   www.example.com
    Address: 192.168.10.100

  3. Verify the IP address in the DNS response matches the Destination Address obtained in the previous procedure.
