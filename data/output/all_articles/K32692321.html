Topic

This article explains the system capacity and technical recommendations specific to the NGINX Controller App Security add-on. For general technical recommendations for NGINX Controller and NGINX Controller Agent, refer to NGINX Controller Tech Specs.

Description

Review this article before installing, updating, or deploying NGINX Controller App Security.

Notes:

  • The following recommendations are provided as guidance and apply to most scenarios. However, some specific deployments might have different recommendations.
  • The following sizing constraints are as of NGINX Controller App Security 3.15.0. Product Development is continuously working to reduce constraints and improve performance.

Local storage

When using local storage for the security analytics database, NGINX recommends provisioning a minimum of 230 GB of free disk space. This includes the standard recommendation of 80 GB and an additional 150 GB for the local analytics database.

Security events (EPS)

Security events are sent to Controller App Security when NGINX App Protect identifies an HTTP request as an attack, a possible attack, or when the HTTP request needs further threat examination. HTTP requests identified by NGINX App Protect as Possible False Positive and Most Likely False Positives are not sent to Controller App Security.

NGINX Controller can support up to 6,000 security events per second (EPS) on each instance. The results are based on a Malicious HTTP Request Size of 2 KB; the EPS is higher for smaller HTTP requests. Additionally, the EPS can be lower based on the number of metrics flowing through the system.

Note: Exceeding 6,000 EPS does not impact or prevent NGINX App Protect from identifying and blocking attacks. However, security events might be delayed or missing on NGINX Controller.

Security policy compilation time

With NGINX Controller App Security, the system compiles security policies when one of the following events occurs:

  • You either enable WAF on an App Component with a new security policy.
  • You modify the security policy on an App Component.
  • You add an instance to a gateway (using Placements).
The time it takes to compile a security policy depends on multiple factors, including the following:
  • The number of security controls in the policy
  • The NGINX App Protect instance version on the data plane
  • The storage I/O performance on NGINX App Protect instances
  • The traffic rate (RPS) on NGINX App Protect instances

Note: When adding an instance to a gateway, all the security policies configured in the gateway must be compiled in the instance. Depending on how long it takes to compile all policies on the instance, you might experience timeouts (IND-20752).
