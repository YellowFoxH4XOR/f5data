Known Issue

If an iRule selects a profile using only its name and not the full path, the internal lookup may fail.

This issue occurs when the following condition is met:

  • An iRule calls the path name SSL::profile, but does not supply the complete path to the profile.

Impact

A new version of the Secure Sockets Layer (SSL) profile created each time the iRule is invoked may lead to excess memory usage over time.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You experience excessive Traffic Management Microkernel (TMM) memory usage over time.

Workaround

To work around this issue, you can use the full path name to SSL::profile when referencing the SSL profile in your iRule.

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

For example:

SSL::profile /Common/clientssl
