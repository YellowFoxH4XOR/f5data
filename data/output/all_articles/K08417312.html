Environment

  • BIG-IQ CM
  • BIG-IQ DCD
  • Managed BIG-IP HA cluster
  • Stats collection enabled for the BIG-IPs
  • BIG-IP auto sync not configured 

Cause

The BIG-IQ CM periodically re-enables statistics collection, by deleting and reinstalling the analytics iApp. This causes the Commit ID to change and end up being different between the peers.

Recommended Actions

You can consider

  • Either Changing the settings in the BIG-IP to enable auto-sync. This will push any change made by the BIG-IQ to the peer device automatically or
  • Set autoReenableStats to false on BIG-IQ CM

Set autoReenableStats to false on BIG-IQ CM

  1. On the Centralized Manager CLI: Go to the REST configuration directory:
    # cd /var/config/rest/config
  2. Backup the restjavad.properties.json file
    # cp restjavad.properties.json restjavad.properties.json.backup
  3. Using a text editor like vi or nano edit the restjavad.properties.json
  4. Insert the following lines under the "stats" section:
    "deviceMonitor":
        {
               "scheduleDelaySec": 60,
               "scheduleCheckDelaySec": 60,
               "minimumConfigAgeSec": 600,
               "correctDCDCheckFirstDelayMin": 10,
               "correctDCDCheckSecondDelayMin": 720,
               "minimumReenableIntervalSec": 600,
               "lastPostAgeCheckSec": 300,
               "autoReenableStats": false
         }
    Note: if "deviceMonitor" subsection already exists with some of the parameters using non-default values under the "stats" section, then only insert/ add the "autoReenableStats": false line.
  5. Save the file and exit the text editor.
  6. Restart restjavad to load the new settings (no service impact, WebUI will restart)
    # bigstart restart restjavad
