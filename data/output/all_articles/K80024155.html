Known Issue

Mirroring connections or persistence records may cause a Traffic Management Microkernel (TMM) memory leak.

This issue occurs when all of the following conditions are met:

  • You have enabled the mirroring option for virtual servers or persistence profiles.
  • The mirroring channel is unavailable. For example, the link is down or there are no mirror IP addresses defined for the device group.

Impact

Traffic is disrupted while the TMM process produces a core file and restarts. Systems configured as part of a high availability (HA) device group may fail over to a peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The tmsh show /sys memory command indicates that TMM memory usage increases over time.
  • The TMM process generates a core file to the /shared/core directory.
  • The BIG-IP system generates a SIGSEGV fault message in the /var/log/tmm log file.

Workaround

To work around this issue, you can disable the mirroring option for the virtual servers and persistence profiles or make sure the mirroring channel is properly configured and operational. For information about troubleshooting the mirroring channel, refer to K54622241: Troubleshooting connection mirroring.
