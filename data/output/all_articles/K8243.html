Topic

In addition to global and master group-based server-side inactivity timeouts, a new client-side inactivity timeout was introduced in FirePass version 6.0.1. The new timeout is implemented through an ActiveX control, which is downloaded to the user's browser. The configuration to use the client-side inactivity timeout is located on the Device Management: Security: Timeouts page.  Select the length of time the user is allowed to be inactive with the drop-down menu, then click the Update button.

The new client-side inactivity timeout determines inactivity by different criteria than the server-side timeouts. The client-side timeout considers any form of interaction with the operating system to be activity, such as mouse movements or keyboard input into any application (not just the browser communicating with the FirePass controller). When the user generates activity, the inactivity timer is reset.

The new client-side inactivity timeout is configurable on a master group basis.

The server-side inactivity timeouts use network traffic from the client to the FirePass controller as the basis for determining inactivity. Any network traffic received by the FirePass controller resets the timer. A specified amount of traffic for Network Access favorites can be excluded from the reset calculation by configuring the Bitrate threshold on the Network Access: Global Settings page. For more information, refer to K3106: Configuring session time limits.

Because the client-side component is an ActiveX control, this feature is only available for systems that are able to run ActiveX controls, such as Windows 2000, Windows XP or Windows Vista. Refer to the FirePass Release Notes for supported client operating systems for your version of FirePass software.
