Description

After upgrading, re-deploying a tenant, renewing the license, restarting TMM or changing sys db provision.extramb on a tenant that runs on an R2R4 rSeries appliance, many services including TMM are restarting.

Many core files from unrelated daemons may be created.

Provisioning might also fail, with an unusual failure message similar to the following:

err mcpd[14594]: 01071008:3: Provisioning failed with error 255 - Unrecognized character \x01

Environment

  • BIG-IP tenant
  • Running on r2x00 or r4x00

Cause

  • Bug ID 1928261: TMM Crashes Due To Memory Corruption Typically Following A Restart

This issue occurs rarely due to memory corruption.

When the problem occurs, you may observe messages similar to the following in /var/log/messages on the rSeries appliance:

kernel: DMAR: [DMA Write] Request device [ec:01.2] fault addr 2fefefefefef000 [fault reason 04] Access beyond MGAW
kernel: DMAR: [DMA Write] Request device [ec:05.2] fault addr 2fefefefefef000 [fault reason 04] Access beyond MGAW
kernel: DMAR: [DMA Write] Request device [ec:05.1] fault addr 2fefefefefef000 [fault reason 04] Access beyond MGAW
kernel: DMAR: [DMA Write] Request device [ec:01.0] fault addr 2fefefefefef000 [fault reason 04] Access beyond MGAW

The presence of these messages does not always mean there will be an issue with memory corruption, and the messages may be logged some time prior to the symptoms being observed.

Recommended Actions

Re-deploying the tenant will typically clear this issue.

An appliance reboot may be required in some cases.
