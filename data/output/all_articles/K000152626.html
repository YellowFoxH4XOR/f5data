Description

When upgrading App Protect, and it is managed, in what order is the upgrade done.

Environment

App Protect needs to be upgraded but it is on a managed instance. A review of Upgrade NGINX App Protect WAF on Managed Instances (version5 or version4) are not clear on what should be upgraded first.

Cause

There’s no strict requirement for whether the control plane or data plane should be upgraded first—either order should work.

Recommended Actions

A bit more context and detail:

Current Versions (At the time of this article creation as an example):

Control Plane

  • Instance Manager (NIM): v2.16.0
  • Security Monitoring: v1.7.1
  • App Protect Build: 5.48.0

Data Plane

  • NGINX Plus: 1.25.5 (nginx-plus-r32)
  • NAP: 4.10.0 / 5.2.0 (assumed)

Note: Review Support for NGINX App Protect WAF  for more information about version compatibility

If upgrading the Control Plane first:

  • It’s recommended to upgrade NGINX Instance Manager (NIM) to at least v2.19.0 (ideally the latest v2.20.0) since Security Monitoring has been integrated into NIM starting from v2.19.0 and is no longer released separately.
  • Updating the App Protect build on the control plane is not mandatory, as long as:
    • The NGINX repository key and certificate are uploaded.
    • At least one App Protect compiler is installed on NIM.
  • When you publish a policy, NIM will automatically download the appropriate App Protect build based on the NAP version on the data plane.

Then upgrade the Data Plane:

  • Stop the Agent service.
  • Upgrade App Protect to the desired version—preferably the latest (e.g., 4.15 / 5.7).

Note: Installing these versions will also upgrade NGINX Plus to R34. Starting with R33, NGINX Plus requires a valid JWT license.

  • After upgrading App Protect:
    • Upgrade the Agent using the NIM-provided script.
    • Restart the Agent and NGINX.

 Don’t forget to take appropriate precautions such as backups before proceeding with upgrades.
