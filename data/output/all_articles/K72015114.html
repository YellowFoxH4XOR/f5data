Topic

You should consider using this procedure under the following conditions:

  • You want to create an HTTP/2-compatible iRule that captures HTTP version from client requests.
  • You want to convert a current iRule so it can capture the correct HTTP version from HTTP/2 requests.

Description

Note: Starting in BIG-IP version 16.0.0, the HTTP::version iRule command has been updated to return the corresponding HTTP version observed in the request. For example, if the client sends a HTTP/2 request, the HTTP::version command reports: HTTP version: 2.0. For more information, refer to Bug ID 842053: Added the ability for the iRule [HTTP::version] command to report HTTP2 and HTTP3 versions.

The HTTP::version iRules command is commonly used to capture HTTP versions from client requests; however, the command is not compatible with HTTP/2 and only returns the version as 1.1 for HTTP/2 requests. Contrarily, the HTTP2::version iRules command, introduced in BIG-IP version 11.6.0, is capable of capturing HTTP versions from HTTP/2 requests but is unable to handle non-HTTP/2 requests. To configure an iRule that is compatible with all supported HTTP versions, including HTTP/2, you need to create a conditional script so the version can be correctly determined based on the version string captured from a HTTP request.

You can use the following key commands to build the iRule:

  • The HTTP::version command captures and returns the HTTP version from non-HTTP/2 requests.
  • The HTTP2::version command captures and returns the HTTP version from HTTP/2 requests.
  • You use the switch command to create a multi-way branch script. Different parts of the script are evaluated depending on a given value.

    For example, the following iRules example shows a value assigned to the HTTP version variable http_version, based on the return string from the HTTP2::version command:

    switch [HTTP2::version] {
      "2" {
        set http_version [HTTP2::version]
      }
      "h2" {
        set http_version 2
      }
      default {
        set http_version [HTTP::version]
      }
    }

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Configuration utility.
  • You have a virtual server configured with an HTTP profile and an HTTP/2 profile.

Procedures

Creating an iRule to log the captured HTTP versions 

To create an iRule to log the captured HTTP versions, including HTTP/2, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. For Name, enter a name for the iRule.
  5. For Definition, enter the HTTP-version-capture iRule.

    For example, the following iRule captures the HTTP versions from client requests and outputs to the /var/log/ltm file:

    when HTTP_REQUEST {
      switch [HTTP2::version] {
        "2" {
          set http_version [HTTP2::version]
        }
        "h2" {
          set http_version 2
        }
        default {
          set http_version [HTTP::version]
        }
      }
      log local0. "HTTP version: $http_version"
    }

  6. Select Finished.
  7. Associate the iRule with the virtual server.
