Known Issue

Disabling the ucs.asm.traffic_data.save system database variable may not function as expected.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM configuration contains an active security policy with request log data.
  • You have previously attempted to upgrade your BIG-IP ASM system and roll forward the configuration.
  • You configure the ucs.asm.traffic_data.save system database variable to disabled.
  • You upgrade your BIG-IP ASM system to an affected version and roll forward the configuration.

Impact

The system database variable setting does not take effect.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP ASM bd process produces multiple core files in the /var/core directory.
  • In the /var/log/asm file, you observe log messages similar to the following example:

    ASM subsystem error (asm_start,F5::DbUpgrade::__ANON__): DBD::mysql::db do failed: Too many partitions (including subpartitions) were defined

  • When you view contents of the /var/asmdata1/traffic_data system directory, files from the pre-upgrade configuration are present.

Resolution

Status

F5 Product Development has assigned ID 648008 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table.

Workaround

To work around this issue, you can create a user configuration set (UCS) archive of your BIG-IP ASM system and restore the configuration on a clean installation of BIG-IP ASM 12.1.x or later.

For more information on creating a UCS archive and restoring the BIG-IP configuration, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 13.x)

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
