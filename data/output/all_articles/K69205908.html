Known Issue

Pool member status may change to Unknown after you make changes to the monitor configuration.

This issue occurs when all of the following conditions are met:

  • You create a pool configured with a pool member that uses a fully-qualified domain name (FQDN).
  • Two or more monitors are associated with the pool member.
  • You change a monitor rule for one of the monitors.

For example, if you remove one of the associated monitors from the pool, either by manually removing the monitor or by performing a configuration synchronization (ConfigSync), the monitor status for the pool changes to Unknown (blue).

Impact

The monitor status for the pool changes to Unknown (blue).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The monitor status of a pool changes to Unknown (blue) after you make changes to one of the associated monitors.
  • The monitor status of a pool changes to Unknown (blue) after you perform a ConfigSync.
  • The ephemeral node status for the pool member is Unknown, but the pool member status is Available (green).

Workaround

To mitigate this issue, you can modify the monitor configuration manually by editing the /config/bigip.conf file. To do so, perform the following procedure:

Impact of procedure: Performing a configuration load on an Active device group member can potentially disrupt traffic. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Advanced Shell (bash).
  2. Before you edit the /config/bigip.conf file, perform a backup of the existing copy by typing the following command:

    cp -a /config/bigip.conf /config/bigip.conf_K69205908

  3. Using your preferred text editor, open the /config/bigip.conf file for editing.
  4. Locate the stanza with the affected pool and make the changes you want to the monitors.
  5. Save the edits and exit the editor.
  6. To manually load the configuration, type the following command:

    tmsh load /sys config

To work around this issue, you can either add another monitor to the pool or restart the bigd process. To restart the bigd process, perform the following procedure:

Impact of workaround: Restarting the bigd process temporarily interrupts the BIG-IP monitor processing, which may cause an interruption in traffic processing.

  1. Log in to bash.
  2. To restart the bigd process, type the following command:

    tmsh restart /sys service bigd
