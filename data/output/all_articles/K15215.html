Known Issue

When you modify the interface resources on a Virtual Local Area Network (VLAN), changes may not take effect immediately.

This issue occurs when all of the following conditions are met:

  • The unit is a BIG-IP 2000 or 4000 series platform.
  • The system uses a VLAN configured with at least one interface.
  • The interface changes from tagged to untagged (or the other way around), but the VLAN ID remains unchanged.

This issue only affects a VLAN when you change an existing interface tag attribute from tagged to untagged (or the other way around). For example, if you initially add an interface as tagged to a VLAN, and then you set the tag attribute to untagged, the change does not take effect until you restart the Traffic Management Microkernel (TMM) process.

Impact

Traffic may not flow as expected until you restart the TMM process.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Traffic does not flow as expected after you change the interface tag attributes on a VLAN.
  • The interface tag attributes on a VLAN are not effective until you restart the TMM process.

Workaround

To work around this issue, you can restart the TMM process after modifying the interface tag attributes. To do so, perform the following procedure:

Impact of workaround: Restarting TMM interrupts traffic processing; you should perform this procedure during a maintenance window. If the system is configured as part of a high-availability pair, the device may fail over.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the TMM process by typing the following command:

    restart /sys service tmm
