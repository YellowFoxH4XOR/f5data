Topic

Non-existent object access violations occur when an HTTP request references an object that is not defined in the ASM security policy.

By default, Block, Alarm, and Traffic Learning are all enabled for requests containing an object that is not defined in the ASM security policy. Therefore, the system blocks requests for non-existent objects, registers a violation for the requested object on the Reporting page, and displays a Learning suggestion for the violation on the Traffic Learning page.

Note: You can control how the system responds to non-existent object access violations by editing the blocking settings for the policy under Policy > Blocking > Settings > Access Violations > Non-existent object.

There may be times when you want to use the BIG-IP ASM Configuration utility to add a non-existent object to the security policy. For example, you may want to use the Accept button to add an object to the policy from the Reporting screen, or Policy Builder screen. To do so, you must perform the following tasks:

  • Verify/change two security policy settings
  • Add the non-existent object to the security policy

Verifiy/change two security policy settings

Before you can add the objects to the policy, you may need to verify/change the following policy settings:

Object Types Associations

The Object Types Associations screen allows you to configure how the Policy Builder processes object types that do not yet exist in the security policy. For example, you can configure whether the system verifies requests referring to a specific object, or whether the system adds the object to the policy when you click the Accept button from the Reporting page, or the Policy Builder screen. To change the Object Types Association setting for an object, perform the following procedure:

  1. From the Application Security Main tab, click Policy.
  2. Select Object Types Associations from the Advanced drop-down menu.
  3. Verifiy/change how the system processes objects types that do not yet exist in the policy.

    Note: If you select Ignore Object for an object type, the system does not verify requests referring to new objects of this type.
  4. Click Save.
  5. Click Apply Policy.

Policy Builder Security Template

In order to use the Accept button to add an individual object to the policy change the Policy Builder Security Template from Basic to Typical. To do so, perform the following procedure:

  1. From the Application Security Main tab, click Automatic under Policy Building.
  2. Select Typical from the Security Template drop-down menu.

    Note: When changing the Security Template, make sure to clear heuristics by clicking the Reset Statistics button.
  3. Click Apply Policy.

Add the non-existent object to the security policy

After you have verified/changed the above policy settings, you can add non-existent objects to the security policy using one of the following methods:

  • Adding a non-existent object to the policy using the Traffic Learning screen
  • Adding a non-existent object to the policy using the Reporting screen

Adding a non-existent object to the policy using the Traffic Learning screen

To add a non-existent object to the policy using the Traffic Learning screen, perform the following procedure:

  1. From the Application Security Main tab, click Manual under Policy Builder.
  2. In the Traffic Learning section, click Non-existent object.
  3. In the Non-existent object section, select the check box next to the object that you want to add to the policy.
  4. Click the Accept button.

The object is now added to the security policy and can be viewed by clicking Objects from the Application Security Main tab.

Note: When you accept an object, the Learning Manager no longer generates learning suggestions for the object.

Adding a non-existent object to the policy using the Reporting screen

To add a non-existent object to the policy using the Reporting screen, perform the following procedure:

  1. From the Application Security Main tab, click Reporting.
  2. Click the request that generated the non-existent object violation.
  3. In the View Full Request Information window, click the Accept button.

The object is now added to the security policy and can be viewed by clicking Objects from the Application Security Main tab.
