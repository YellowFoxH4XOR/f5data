Description

Openshift rebuild/reinstall is initiated, but /var/log/openshift.log does not show any progress, but instead repeatedly logs:

Pausing all processing due to /tmp/omd/pause existing

Environment

  • VELOS
  • F5OS-C 1.x
  • Openshift

Cause

The orchestration manager (omd) pauses its work if the file /tmp/omd/pause exists. This pause file is typically created by the system while certain maintenance tasks are performed, but an error may result in the pause file remaining in place when it should have been removed. For example, the renew_nodes.sh script creates /tmp/omd/pause on both controllers, but may not clean them up in some circumstances.

While the /tmp/omd/pause file exists, the orchestration manager will not proceed with cluster maintenance operations such as rebuilding Openshift or adding blades.

Recommended Actions

SSH to the active Controller as 'root'. Remove the pause file by running:

rm /tmp/omd/pause

Once this file is removed, the orchestration manager on the active controller will resume its work.

Next, SSH to the standby controller and remove the pause file from it too, if it exists.
