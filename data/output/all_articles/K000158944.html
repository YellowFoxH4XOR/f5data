Description

This article provides guidance for configuring and operating F5 Cloud Failover Extension (CFE) in Microsoft Azure environments with BIG-IP High Availability (HA) deployments. It addresses:

  • IP address remapping during failover events
  • Azure permissions and resource tagging requirements
  • Configuration update procedures
  • Operational maintenance considerations

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1 (applicable to other versions with CFE support)
  • Platform: BIG-IP Virtual Edition on Azure
  • Configuration Components:
    • Active-Standby HA pair with Cloud Failover Extension
    • Azure Network Interfaces with secondary IP configurations
    • Azure Storage Account for CFE state file (f5cloudfailoverstate.json)
    • CFE configuration with scoping tags
    • Traffic groups and virtual addresses on BIG-IP
  • Cloud Provider: Microsoft Azure

Cause

  • Insufficient Azure permissions for managed identity or service principal to access storage account and modify network interface configurations
  • Missing or incorrect scoping tags on Azure network interfaces preventing CFE from identifying managed resources
  • CFE configuration not updated after infrastructure or virtual address changes

Recommended Actions

  • Confirm the managed identity or service principal has permissions to:
    • Read and write to the Azure Storage Account containing the CFE state file
    • Modify network interface IP configurations
    • List and update network interface tags

  • Check restnoded.log for permission-related errors:

    /var/log/restnoded/restnoded.log

  • Look for errors such as:

    AuthorizationPermissionMismatch This request is not authorized to perform this operation using this permission

 

  • Follow configuration steps detailed in Set up access to Azure’s Instance Metadata Service
  • Perform a dry-run test to preview failover operations without making changes 
    • On the standby device run the following command:

curl -su admin: -X POST -d '{"action":"dry-run"} http: //localhost:8100/mgmt/shared/cloud-failover/declare | jq .

  • Review the dry-run output for:

    • toActive: Addresses that will be moved to the new active unit
    • toStandby: Addresses that will be removed from the current active unit
    • operations: Route changes (if configured)

 

  • Verify failover discovery process in restnoded.log:
[f5-cloud-failover] Performing Failover - discovery
[f5-cloud-failover] Getting failover addresses using selfAddresses
  • verify successful failover in restnoded.log:
[f5-cloud-failover] Associate NICs successful.
[f5-cloud-failover] Addresses reassociated successfully

 

  • Monitor restnoded.log regularly for CFE operation status and errors
  • Update CFE configuration only when Azure infrastructure or BIG-IP virtual addresses change
  • No special procedures required for BIG-IP node restarts
  • Configuration updates need only be posted to one unit, then synced via ConfigSync

Additional Information

CFE Configuration Updates:

  • Configuration updates are only necessary when changes occur to Azure resources (network interfaces, tags, storage accounts) or BIG-IP virtual addresses
  • The POST command updates the stored state in the Azure Storage Account to maintain consistency across failover events
  • Configuration changes synchronize between HA peers through standard BIG-IP ConfigSync mechanisms

Scoping Tags:

  • The "f5_cloud_failover_label" tag enables CFE to identify which Azure resources to manage during failover
  • Tags must be consistent between the CFE configuration file and Azure resource tags
  • The "requireScopingTags" parameter in CFE configuration determines whether tags are mandatory for resource discovery
  • All network interfaces managed by CFE should have matching scoping tags

Address Group Definitions:

  • The "scopingAddress" parameter in addressGroupDefinitions identifies which network interface contains the failover addresses
  • CFE uses this to determine which secondary IPs should be moved during failover events
  • Multiple address groups can be defined for complex configurations

Expected Behavior:

  • During failover, CFE automatically reassociates secondary IP addresses from the previous active unit's network interface to the new active unit's network interface
  • The failover process includes discovery, address operations, and route operations (if configured)
  • State information is stored in the Azure Storage Account to maintain consistency

Azure’s new control plane:

  • Azure’s new control plane is a internal enhancement focusing on architectural improvements to the Azure Network Control Plane. 
  • Microsoft has an early access program for their new control plane, which enables CFE to failover in seconds. 
  • To gain early access, contact your F5 Account Manager or Sales Engineer for more information.
