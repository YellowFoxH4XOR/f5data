Issue

In BIG-IP systems configured as high availability pairs, the ConfigSync auto detect feature automatically detects configuration status and displays that status on all Configuration utility screens. This status indicator displays whether the systems consider themselves to have the same configuration or if a ConfigSync operation needs to be completed for the configurations to be synchronized. The configsync state daemon (cssd) checks the status of each unit.

In BIG-IP 9.x when the ConfigSync auto detect feature is enabled and one member of a high availability pair is rebooted, or the mcpd process is otherwise restarted, the ConfigSync auto detect indicator will not change its status. If the pair was considered synchronized before the reboot, and no changes have been made, the indicator will still display Sync: OK after the reboot.

Beginning in BIG-IP 10.x, when the ConfigSync auto detect feature is enabled, and one member of a high availability pair is rebooted, or the mcpd process is otherwise restarted, the ConfigSync auto detect indicator will change following the restart.

To ensure that any configuration changes introduced during an mcpd reload or device reboot are propagated across the high availability pair, when the reload or reboot is complete, the ConfigSync auto detect indicator displays a message that appears similar to the following example in the Configuration utility:

Sync Recommended

Additionally, the value of the db variable Configsync.State will be set to 1 or 2, as shown in the following two example results of the command bigpipe db Configsync.State:

Configsync.State = 2 - Peer config modified, recommend configsync from peer

Configsync.State = 1 - Local config modified, recommend configsync to peer

The status change in this situation does not represent a verified disparity between the configurations, however, F5 recommends that you perform a ConfigSync because the systems are also not verifiably synchronized from the point of view of the configsync state daemon.

Removing the synchronization recommendation message

You can remove the synchronization recommendation message from the BIG-IP system display either by synchronizing the pair or by setting the Configsync.LocalSyncedTime database key to the same value on both systems in the BIG-IP LTM high availability pair. To do so, perform the following procedure:

  1. Log in to the command line of the BIG-IP redundant system.
  2. Reset the Configsync.LocalSyncedTime database key on each device to the current date and time of the UNIX time stamp by typing the following command:

    bigpipe db Configsync.LocalSyncedTime `date +%s`

    Note: The date +%s command returns the current time, in seconds, since the UNIX epoch. For instructions about manually converting time into seconds since the UNIX epoch, refer to K148: Converting a date and time into the number of seconds since the beginning of the UNIX epoch.

  3. Immediately repeat this procedure on the other member of the redundant system.
