K74566933: How to disable HTTP OPTIONS method at global level for the Configuration Utility

Type
Support Solution
Published
2019-11-25
Updated
2023-02-21
Applies to
  • Virtual Editions
Source
https://my.f5.com/manage/s/article/K74566933
Description


When a vulnerability assessment (VA) scan runs against the BIG-IP, the scan detects that the F5 Configuration Utility allows HTTP OPTIONS method.  
For example, when sending OPTIONS method via curl to the F5 configuration utility you will notice the below results:

[root@LTM1.example.com] config # curl -lkX OPTIONS https://10.10.10.50 -i
HTTP/1.1 501 Not Implemented
Date: Mon, 29 Apr 2019 20:58:34 GMT
Server: Apache
X-Frame-Options: SAMEORIGIN
Strict-Transport-Security: max-age=16070400; includeSubDomains
Allow: OPTIONS,GET,HEAD,POST,TRACE 
Content-Length: 205
Connection: close
Content-Type: text/html; charset=iso-8859-1
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">
<html><head>
<title>501 Not Implemented</title>
</head><body>
<h1>Not Implemented</h1>
<p>OPTIONS to /index.html not supported.<br />
</p>
</body></html>

Environment
  • Vulnerability Assessment Scan
  • HTTP OPTIONS method 
Cause

HTTP method OPTIONS is allowed on the Configuration Utility 

Recommended Actions

F5 recommends you update to a BIG-IP version that contains the fix for ID 944513. If you are unable to update/upgrade your system, as a temporary workaround, you can disable the OPTIONS method.

To disable the OPTIONS method perform the following procedure: 
  1. Login to TMSH utility 
    # tmsh 
  2. Edit the sys httpd  configuration
    # edit sys httpd 
  3. Press I to insert 
  4. Add the below lines to httpd configuration to limit the methods.

    Impact of procedure: Disabling OPTIONS may cause unexpected WebUI functionality issues, and if this occurs, then allowing OPTIONS may be required. In such cases, update to a BIG-IP version that contains the fix for ID 944513.

    Note: The following configuration enables only the POST and GET methods in the httpd configuration. You can add other methods such as TRACK, TRACE and HEAD as required.

    include "
            <Location />
                <LimitExcept GET POST>
                    order deny,allow
                    deny from all
                </LimitExcept>
            </Location>
    "

  5. Press escape key
  6. Type :wq! to save and exit the file. 
  7. Verify the configuration by running the below command 
    # curl -k -X OPTIONS https://<ip_address> -v
Note: When you synchronize the configuration to its peer device in a HA pair, the peer will also disable the HTTP OPTION method.

Additional Information

Sample httpd configuration before Change

root@(LTM1.example.com)(cfg-sync In Sync)(Active)(/Common)(tmos)# list sys httpd
sys httpd {
      auth-pam-dashboard-timeout on
      auth-pam-idle-timeout 2147483647
      redirect-http-to-https enabled
      ssl-protocol TLSv1.2 }

Sample httpd configuration after Change
root@(LTM1.example.com)(cfg-sync In Sync)(Active)(/Common)(tmos)# list sys httpd
sys httpd {
      auth-pam-dashboard-timeout on
      auth-pam-idle-timeout 2147483647
      include "
        <Location />
            <LimitExcept GET POST PUT DELETE CONNECT PATCH PROPFIND PROPPATCH MKCOL COPY MOVE LOCK UNLOCK>
                deny from all
            </LimitExcept>
        </Location>
      "
      redirect-http-to-https enabled
      ssl-protocol TLSv1.2
}
