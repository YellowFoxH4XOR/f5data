Known Issue

Description

The gtm_add or bigip_add command line utility exits with the following error message:

ERROR: Can't create a hard link

This issue occurs when the following condition is met:

  • One or both of the following files exists on the affected BIG-IP GTM system:

    /config/gtm/server.crt.backup
    /config/big3d/client.crt.backup

Impact

The bigip_add or gtm_add command line utility does not function as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H422725 on the Diagnostics > Identified > Medium screen.
  • Attempting to run the bigip_add or gtm_add utility causes the following error message:

    ERROR: Can't create a hard link
  • You are unable to use the bigip_add or gtm_add utility to add BIG-IP devices to a synchronization group or update devices in a synchronization group.

Workaround

To work around this issue, copy the server.crt.backup and/or the client.crt.backup files to the /var/tmp directory on the affected system, and then remove these files from the /config/gtm directory.

To do so, perform the following procedures:

  • Copying the backup certificates
  • Deleting the original backup certificates
  • Optional: Re-running the bigip_add or gtm_add utility

Copying the backup certificates

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP GTM system.
  2. Copy the server.crt.backup and/or client.crt.backup files to the /var/tmp directory. To do so, use the following commands:

    cp /config/gtm/server.crt.backup /var/tmp/gtm_server.crt.backup
    cp /config/gtm/client.crt.backup /var/tmp/gtm_client.crt.backup

Deleting the original backup certificates

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Important: Prior to deleting the backup files, ensure that only the files that end with the suffix .backup are selected. Similar file names that do not have the .backup suffix should not be deleted.

  1. Log in to the command line of the affected BIG-IP GTM system.
  2. To remove the server.crt.backup and/or client.crt.backup files from the /config/gtm directory, use the following commands:

    rm /config/gtm/server.crt.backup
    rm /config/gtm/client.crt.backup

Optional: Re-running the bigip_add or gtm_add utility

Impact of workaround: The bigip_add utility will exchange SSL certificates with the remote BIG-IP system by appending the certificate from each device to the local list of authenticated SSL certificates (/config/gtm/server.crt) on each device. The gtm_add utility will replace the current configuration files (bigip_gtm.conf, named.conf, and named zone files) on the local BIG-IP GTM system with the configuration of the remote BIG-IP GTM system referenced when running the utility.

  1. Log in to the command line of the affected BIG-IP GTM system.
  2. To add a device to the synchronization group, run the bigip_add or gtm_add utility. For example:

    bigip_add <ip-address-of-remote-device>
    gtm_add <ip-address-of-remote-configured-gtm-device>

Important: When running the gtm_add utility, the utility replaces the local BIG-IP GTM local balance and DNS configuration with the load balance and DNS configuration of the remote BIG-IP GTM system.
