Description

When a DNS query reaches a BIG-IP GTM/DNS listener, it will respond with a DNS response based on the follow configured objects:

  • GLSB
  • DNS Express
  • DNS Cache
  • DNS Load Balancing
  • ZoneRunner (BIND)

For example, you have configure domain (zone) www.example.com in all of the objects mentioned above with different IP addresses.
This article explains the order of precedence on how the BIG-IP GTM/DNS makes a decision to provide the DNS response.

Environment

  • BIG-IP GTM/DNS
  • How BIG-IP GTM/DNS decides on the DNS response

Cause

The following are the order of precedence when the BIG-IP GTM/DNS provide a DNS response to the DNS client (top takes the highest precedence)

  1. LTM DNS_REQUEST iRule event
  2. DNSSEC query types (e.g. DNSKEY or NSEC3PARAM)
  3. GSLB / wideIP (including GTM iRules)
  4. DNS Express
  5. DNS Cache (DNS profile) - DNS response has been cached
  6. Resolver Cache (DNS profile) - DNS response has not been cached
  7. Unhandled Query action from DNS profile
  8. DNS Load Balancing to LTM pool member
  9. ZoneRunner (BIND)
