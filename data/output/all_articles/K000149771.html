Description

CRLDP authentication fails and this message is logged in /var/log/apm log file when it happens

CRLDP Auth agent: CRL lookup failed for LDAP url <CRLDP URI> reason ''

 

For example

warning apmd[<PID>]: 0149015e:4: (null):Common:abcd1234: CRLDP Auth agent: CRL lookup failed for LDAP url 'ldap://:::389/CN=test,CN=Configuration,DC=example,DC=com,DC=cn?certificateRevocationList?base?objectClass=cRLDistributionPoint?certificateRevocationList' reason ''

warning apmd[<PID>]: 0149015e:4: (null):Common:abcd1234: CRLDP Auth agent: CRL lookup failed for 'http://<CRLDP_server_FQDN>/certenroll/test.crl' reason ''

Environment

  • BIG-IP provisioned with APM
  • APM access policy configured with a CRLDP Auth agent

 

Cause

One cause of that error is the CRL file to be outdated.

Certificate Revocation List
 signedCertificateList
  thisUpdate: utcTime (0)
   utcTime: 2018-06-20 13:20:26 (UTC)
  nextUpdate: utcTime (0)
   utcTime: 2018-06-27 13:20:26 (UTC)

 

Another possible cause is that in the certificate received from the client the CRL path is LDAP:///<path> and the BIG-IP cannot get the hostname for the LDAP server. If the path is LDAP://<LDAP_server_FQDN_or_IP>/<path>, then APM will try to access the LDAP server to get the CRL file.

 

Answer/Recommended Actions

Verify CRLDP time and push a new CRL file with revoked certificates.

If LDAP path did not contain the hostname, suggestion is re-generate the certificate with correct LDAP path.
