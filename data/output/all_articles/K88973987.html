Known Issue

The Security Assertion Markup Language (SAML) websso process may overrun memory from other processes.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured as an Identity Provider (IdP).
  • SAML single logout (SLO) is configured on the attached service provider (SP) connector.
  • The BIG-IP APM system is processing SAML traffic.

Impact

Impact differs based on the process that is overrun. If the Traffic Management Microkernel (TMM) process is overrun, the BIG-IP system fails to process traffic while the TMM restarts.

Symptoms

As a result of this issue, the symptoms differ based on the affected process. If the tmm process is overrun, you may encounter one or more of the following symptoms:

  • Users are temporarily unable to access the BIG-IP APM system.
  • The tmm process generates a core file to the /shared/core directory.
  • The BIG-IP system generates a SIGSEGV fault and stack trace log message in the /var/log/tmm file, similar to the following example:

Workaround

There is no workaround for this issue; however, you can disable SAML SLO to stop the websso process from overrunning memory from other processes. To do so, remove SLO request and SLO response URLs from the configuration in appropriate SAML SP connectors.
