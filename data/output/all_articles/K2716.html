K2716: Nodes may report errors when monitored by BIG-IP or 3-DNS

Topic

A standard TCP monitor tests for the status of a service on a specified node by establishing a TCP connection with the node on the configured service port and then immediately closing the connection.

Unless specifically configured to do so, no data is sent from the BIG-IP system to the service being monitored. This causes some services, such as telnet, to generate a warning/error message on the monitored node indicating a connection error or invalid port. In these cases, there is actually no issue with the monitored node except for log files being unnecessary filled with invalid errors.

To avoid these error messages, either use a monitor designed to communicate enough to the service being monitored to not generate an error, or monitor a service that does not generate error messages on empty connections, such as daytime.

You can use the TCP monitor as a template to create a slightly more sophisticated monitor that sends a query and expects a response from the service being monitored. Often times this is enough to stop the error messages from being generated, but requires a substantial amount of knowledge about the service protocol in order to configure the monitor with an appropriate dialog.

If a more sophisticated dialog is desired from the monitor, then it may be necessary for you to configure a custom monitor/EAV. For more information about configuring monitors, refer to the BIG-IP Reference Guide.
