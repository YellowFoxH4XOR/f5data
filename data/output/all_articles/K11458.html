K11458: Content assembly functions are always applied on objects served from BIG-IP WebAccelerator Smart Cache

Topic

By default, the Enable Content Assembly on Proxies setting (located on the Assembly tab in the WebAccelerator policy) is enabled for WebAccelerator policies. When the setting is enabled, the BIG-IP WebAccelerator system performs content assembly functions, such as Intelligent Browser Referencing (IBR) and Multiconnect (if enabled), to content served to clients, even if the content is not served from the BIG-IP WebAccelerator system's cache.

When the Enable Content Assembly on Proxies setting is disabled in the policy and the content in the BIG-IP WebAccelerator system cache is not expired, the BIG-IP WebAccelerator system serves the response from its cache and performs content assembly functions. If the WebAccelerator system cache is empty or the content is expired, the BIG-IP WebAccelerator system refreshes its cache by sending the request to the origin web server (OWS) for content, and does not perform content assembly. This response from the OWS also includes ETags from the OWS.

If you want the BIG-IP WebAccelerator system to provide consistent content assembly behavior, when Enable Content Assembly on Proxies is disabled, the Always proxy requests for this node setting should be selected on the Proxying tab in the policy.
