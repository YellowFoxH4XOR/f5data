Known Issue

The nexthop <IP address> iRules command fails validation.

This issue occurs when the following condition is met:

  • You create an iRule using the nexthop command that references only an IP address.

Impact

You are unable to associate the iRule containing the nexthop <IP address> command with a virtual server.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The nexthop command enables you to specify a forwarding address in an iRule. The validator rejects the form that takes an IP address with an error message similar to the following example:

    01070151:3: Rule [/Common/irule_example] error: Unable to find vlan, vlangroup or tunnel (IP address) referenced at line 2: [nexthop IP address]

Workaround

To work around this issue, you can specify the VLAN with which the IP address is associated.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

In this example, the following iRule uses the nexthop command and fails validation:

when HTTP_REQUEST {
  nexthop   10.0.0.1
}

However, when you use an iRule that specifes the VLAN containing the subnet, the command works, as in the following example:

when HTTP_REQUEST {
  nexthop  internal 10.0.0.1
}
