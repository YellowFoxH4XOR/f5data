K55581546: Troubleshooting boot locations stuck in deleting volumeset

Type
Support Solution
Published
2023-09-07
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K55581546

Description

Attempts to delete an inactive boot location may fail with a "not found" diagnostic message. When deleting via tmsh CLI the message can be seen as:

(tmos)# delete sys software volume <name>
01020036:3: The requested software desired (<name>) was not found.
(tmos)#

Environment

Attempting to delete a boot location which is not currently active

Cause

For volume management TMOS uses process lind. If for some reason lind was not able to delete the boot location immediately and/or without any additional diagnostics, then TMOS may consider the volume present still reporting it either "failed to delete" or "deleting":

(tmos)# show sys software

-----------------------------------------------------------------------------
Sys::Software Status
Volume        Product   Version     Build  Active                      Status
-----------------------------------------------------------------------------
HD1.1          BIG-IP    15.1.0      0.1.0     no  failed to delete volumeset
HD1.2          BIG-IP    15.2.0      0.2.0    yes                    complete
<…>

or:

----------------------------------------------------------------------------
Sys::Software Status
Volume  Slot  Product  Version      Build  Active                      Status
-----------------------------------------------------------------------------
HD1.2      1   BIG-IP   15.2.0       0.2.0    yes                    complete
HD1.3      1   BIG-IP   13.3.1       0.3.0     no          deleting volumeset
<…>

Recommended Actions

  1. Diagnostics "was not found" suggests that the issue may be cosmetic: lind was probably able to delete the boot location and TMOS sees a phantom entry. Applying In bash CLI:

    bigstart restart lind

    should clear the condition
    Note: Applying the command will interrupt any ongoing software installation

  2. If step 1 does not make a difference, then try applying in bash CLI:

    bigstart restart

    Note: Applying the command will interrupt all ongoing activuities of TMOS
     
  3. If the problem persists still, then consider contacting F5 Support for further troubleshooting
