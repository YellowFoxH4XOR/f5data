K48531153: Unexpected blocking by the Bot Defense profile

Type
Support Solution
Published
2021-02-03
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K48531153

Description

Unexpected blocking is observed under Bot Defense event log:

Security  ››  Event Logs : Bot Defense : Bot Traffic

For example under Bot Defense Mitigation settings "Malicious Bot" is configured with mitigation  "Alarm".
Request is blocked in Event Log even if it should be allowed with just "Alarm" flag set on.

Environment

  • Bot Defense Profile

Cause

Bot Defense blocking can occur if device is under active DDoS attack and Bot Defense profile has enabled for "DoS Attack Mitigation Mode".
If DoS Attack Mitigation Mode option is enabled the following Mitigation and Verification Settings will be in effect during a DoS attack:

  • Browser: Verify Before Access
  • Trusted Bots: Alarm
  • Untrusted Bots: Block
  • Suspiciuos Browsers: Block
  • Malicious Bots: Block
  • Unknown: Block

DoS Attack Mitigation Mode requires a DoS protection enabled.

Recommended Actions

This is expected behaviour. You can disable DoS Attack Mitigation Mode however this may increase impact of potential DoS Attack.

Additional Information

Active or historical DoS Attack can be checked under Configuration Utility(GUI) page:

Security  ››  Reporting : DoS : Dashboard

Alternatively in logs "/var/log/dosl7/dosl7d.log".

Example:

DOSL7D_ARB|NOTICE|Jan 01 21:39:30.234|12948|dosl7d_anomaly_engine.cpp:5574|>>>>>>>>> ARBITRATOR:  DOS TPS ATTACK START  on vs /Common/my_vs_443 profile /Common/my_dos_profile attack id 123456789<<<<<<<<<
