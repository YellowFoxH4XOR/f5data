Known Issue

Users cannot create a virtual server in a non-default route domain. 

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses a custom partition configured with a route domain.
  • The route domain is configured as the Default Route Domain for the partition.
  • A virtual server with the same address exists in the /Common partition.
  • You do not specify the specific route domain ID when creating the virtual server.

Typically, when you do not specify the route domain ID for a partition object, the BIG-IP system uses the ID of the route domain that was configured as the Default Route Domain for the partition. However, under the aforementioned conditions, the BIG-IP system uses the default route domain of 0, instead of the non-default route domain.

Impact

You cannot create a virtual server in a non-default route domain.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you attempt to save the new virtual server in the Configuration utility, the system logs error messages that appear similar to one of the following examples:

    01070333:3: Virtual Server /<partition-name>/<virtual-server-name> illegally shares both address and vlan with Virtual Server /Common/<virtual-server-name>

    01070734:3: Configuration error: Virtual address /Common/<ip address> encodes IP address <ip address> which differs from supplied address field <ip address><route domain number>

  • The BIG-IP system does not automatically assign the Partition Default Route Domain when creating a virtual server.

Workaround

To work around this issue, you can specify the specific route domain ID when creating the virtual server. For example, you can specify 10.10.10.10%3 as the route domain ID.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
