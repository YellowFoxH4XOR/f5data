K54013660: Error message: ERR_VAL: SSL action will not take effect, the handshake has already been processed

Type
Support Solution
Published
2021-04-07
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.0
Source
https://my.f5.com/manage/s/article/K54013660
Description

While using BIG-IP SWG, you'd need to configure the proxy to not intercept some traffic.
To do so, the PerRequest policy can be configured with an "SSL Bypass set" agent.
When hitting the difficulty described here, the browser shows the SSL flow has been intercepted by BIG-IP SWG.
Alongside with the traffic being intercepted, you notice the following record in the APM log file:
ERR_VAL: SSL action will not take effect, the handshake has already been processed

Environment

  • You're using BIG-IP SWG
  • SWG is configured either as "transparent" or "explicit"
  • You configured SWG to not intercept the SSL traffic (the PerRequest policy is set up with an "SSL Bypass set" agent).
Cause

Such message may mean the BIG-IP SWG had to "unseal" the SSL traffic to perform some operations as per the configuration of the PerRequest Policy.
As an example, the PerRequest policy may be configured with an "L7 Protocol Lookup" agent (that does require BIG-IP SWG to look into into the SSL traffic to categorise the traffic inside it).
When a flow is open, unseal or intercepted by BIG-IP SWG, it cannot be sealed again (with "SSL Bypass Set", typically).

Recommended Actions

The bottom line is: we must reconfigure the PerRequest policy in such a way that the original SSL traffic is left untouched when it's to reach the "SSL Bypass set" agent.
Typically: you may need to replace the "L7 Protocol Lookup" agent with an "SSL Check" agent.
