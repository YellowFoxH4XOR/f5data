Description

The BIGIP (APM) administrator can notice the similar error in /var/log/apm during changes related to machine-account configuration object which is part of NTLM authentication:

Sep 17 11:30:21 example.local err nlad[7591]: 01620000:3: <0x2ac18d7ad700> client[21]: DC[10.1.1.1]: schannel[0]: RPC exception: Failed to athenticate with machine account.

  • where 10.1.1.1 is the domain controller (DC) IP.

Environment

  • APM
  • Machine-account configuration object
  • NTLM authentication configuration object
  • More than 1 DC in domain forest

Cause

APM may bring RPC machine account related error even during the initial creation of machine account and ntlm authentication related configuration objects if there are problems in netlogon/sysvol/dfsr components which are part of DCs trust relationship.
After running Microsoft related utility 'dcdiag' on DC, the administrator may notice the error(s) similar to:

[...]
Doing primary tests
   Testing server: Default-First-Site-Name\DC2
      Starting test: Advertising 
         Warning: DsGetDcName returned information for \\DC1, when we were trying to reach DC2.
         SERVER IS NOT RESPONDING or IS NOT CONSIDERED SUITABLE.
         ......................... DC2 failed test Advertising <<< (!)
[...]
Starting test: NetLogons 
         Unable to connect to the NETLOGON share! (\\DC2\netlogon)
         [DC2] An net use or LsaPolicy operation failed with error 67, The network name cannot be found..
         ......................... DC2 failed test NetLogons <<< (!)
[...]
 

Recommended Actions

Make sure that there are no errors in dcdiag output on DCs.
Consult with Microsoft server administrators if required.

If there are no errors in dcdiag output, but the error in APM log still appears, then collect the data in the following manner:
  1. Set logs to debug level for ECA/AP components under access-profile in question
  2. Start tcpdump filtering on DC(s) IPs (replace x.x.x.x), for example:

    tcpdump -ni 0.0:nnn host x.x.x.x -s0 -vw /var/tmp/machine-account_issue.pcap

  3. Enable Netlogon logging on DC
  4. Recreate the machine account and ntlm authentication objects from scratch using new names and check if the error is still present in /var/log/apm for just created configuration objects
  5. Collect the fresh Qkview file and the tarball of logs
  6. Return to Notice the log level for ECA/AP components under access-profile in question
  7. Open the ticket with F5 Support and provide the collected data: K2633: Instructions for submitting a support case to F5
