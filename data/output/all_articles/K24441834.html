Topic

You can create local user database instances on the BIG-IP APM system to provide authentication and store user information. Administrators are able to manage local user database using the Configuration utility.

Description

The user records for the local user database are stored locally in the MySQL database in the BIG-IP APM system. When creating a user in the local user database, the user name is case insensitive. A single database entry is created to represent case variations in user names.

When a user attempts to authenticate to a BIG-IP APM system, any case variation of the local user database user name will be accepted, provided the passphrase given matches the entry in the database. For example, the user names USER, User, and user are able to authenticate if the user name for the account is User. When successfully authenticated, a separate user session is created for each user name variation.  

Unexpected behavior may occur if you configure the Max Sessions Per User setting in the access profile. For example, you set the Max Sessions Per User setting to 1, and create the user Larry in the local user database. When a user logs in with the user name Larry, the BIG-IP APM system authenticates the user with the local user database entry and creates a new session as expected. If a user then logs in with the user name LARRY, the user is authenticated with the same database entry and a second session is created, one for each user name. You can view this using the sessiondump -allkeys | grep -i session.logon.last.username command:

1b54b8ab.session.logon.last.username 5 Larry
14b57448.session.logon.last.username 5 LARRY

You can force users to only one session per user name by configuring a variable assign object in the access policy to set the user names to lowercase. To do so, perform the following procedure:

Impact of procedure: You may be required to restart the TMM process, which will cause a traffic disruption. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Navigate to the local user database:
    • 13.0.0 and later:

      Access > Authentication > Local User DB

    • 10.x through 12.x:

      Access Policy > Local User DB

  3. Ensure that user names are configured in all lowercase characters by deleting and recreating user names that include uppercase or mixed case characters.
  4. Navigate to the access profiles:
    • 13.0.0 and later:

      Access > Profiles/Policies

    • 11.x through 12.x:

      Access Policy > Access Profiles

  5. Open the visual policy editor by clicking Edit to the right of the Access Profile name.
  6. Click the plus sign ( + ) to the right of the Logon Page box.
  7. Select the Assignment tab.
  8. Click Variable Assign.
  9. Click Add Item.
  10. Click Add new entry.
  11. For the newly created empty assignment, change.
  12. Leave the Custom Variable menu selection at the default setting of Unsecure.
  13. In the Custom Variable box, type the following:

    session.logon.last.logonname

  14. In the Custom Expression box, type the following:

    expr {[string tolower [mcget {session.logon.last.username}] ]}

  15. Click Finished.
  16. Click Add new entry.
  17. For the newly created empty assignment, click change.
  18. Leave the Custom Variable menu selection at the default setting of Unsecure.
  19. In the Custom Variable box, type the following:

    session.logon.last.username

  20. In the Custom Expression box, type the following:

    expr {[string tolower [mcget {session.logon.last.username}] ]}

  21. Click Finished.
  22. Click Save.
  23. Click Apply Access Policy in the upper-left corner of the visual policy editor.
  24. Log in to the command line of the affected BIG-IP APM system.
  25. To clear cached user name information, you can restart the TMM process by typing one of the following commands:
    • Restarting the TMM process using the Traffic Management Shell (tmsh):

      tmsh restart /sys service tmm

    • Restarting the TMM process by rebooting the BIG-IP APM system:

      full_box_reboot
