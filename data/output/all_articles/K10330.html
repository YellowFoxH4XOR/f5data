Known Issue

This is the result of a known issue. When upgrading an ARX 3.x system to version 5.0.x, after failing over to the upgraded system, the CIFS virtual services may fail to start and remain in Starting state. This issue is the result of a timing issue that affects upgraded ARX systems configured with a CIFS or Multi-Protocol Namespace using CIFS metadata.

The show virtual service command will indicate the CIFS virtual services are in a Starting state similar to the following:

Switch                  ARX1               
------------------------
  Global Server           Virtual IP Address      Service     State
  ------------------------------------------------------------------------
  max1-10.10.1.41        10.10.1.41             CIFS        Starting   
  max1-10.10.1.42        10.10.1.42             CIFS        Starting   
  max1-10.10.1.43        10.10.1.43             CIFS        Starting   
  max1-10.10.1.44        10.10.1.44             CIFS        Starting   
  max1-10.10.1.45        10.10.1.45             CIFS        Starting    

The show logs error.log command will display errors similar to the following: 

DNAS_PGRP-13-ERR-MSG3:: Cifs Shim failed to add filer info /.acopia/metadata/dnas/ns_1/vol_199
MGT_DNAS_CONFIG-13-ERR-MSG3:: Volume start failed.
MGT_DNAS_CONFIG-13-ERR-MSG3:: Volume 199, instance 13 start unsuccessful.  Operation will be retried.
CIFS_SHIM_LIB-13-ERR-MSG3:: already connected to filer 10.11.22.45:445 share share_1021-cifs-max-ARX1 - cannot change
CIFS_SHIM_LIB-13-ERR-MSG3:: failed to add storage for namespace 1 volume 205 

F5 Product Development tracked this issue as ARX ID 35489 and it was fixed in ARX 5.0.5. For information about upgrading, refer to the ARX Release Notes.

Additionally, this issue has been fixed in a hotfix available for ARX 5.0.1. To request this hotfix, contact F5 Technical Support and reference this article and ARX ID number.

Workaround

An ARX system experiencing this issue will experience a loss of service. To restore service, fail over the ARX system, or restart the affected VPU domain for the Global Server by using the following command syntax:

restart namespace <namespace_name> volume <volume_name>
