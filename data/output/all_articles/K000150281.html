K000150281: Disable Strict Updates setting for iApp deployments without access to the GUI.

Type
Support Solution
Published
2025-03-12
Updated
2025-03-12
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000150281

Description

An error message similar to the following is generated when attempting to modify a configuration object:

010715bc:3: The application service (/Common/test.app/test) has strict updates enabled, the object (Persistence Profile /Common/test.app/test_cookie-persistence) must be updated using an application management interface.

But you are unable to disable Strict Updates due to the iApps section of the GUI not loading correctly.

Environment

  • iApps configured.
  • iApps deployment objects not showing on the GUI.

Cause

It is not possible to modify objects directly when they were created by an iApp due to the Strict Updates setting. This is the default setting and can be disabled for each deployed application service.

This process is traditionally performed following K51033596: Error Message: 010715bc:3: The application service (&amp;lt;iApp name&amp;gt;) has strict updates enabled, the object (&amp;lt;iApp object&amp;gt;) must be updated using an application management interface. but, it may be that under certain conditions such as the following, the iApps GUI section won't show the iApps objects:

  • Running the clear-rest-storage command.
  • Issues with tomcat/restjavad daemons.
  • High CPU and memory usage on control plane.

*Note: Even if the iApps deployment are not accessible/visible through the GUI, the configuration objects created by it still exist.

Recommended Actions

Disable Strict Updates via the CLI with the following command:

tmsh modify sys application service </Partition/APP_NAME.app>/<APP_NAME> strict-updates disabled

Once you modify your configuration objects, you can enable Strict updates with the following command:

tmsh modify sys application service </Partition/APP_NAME.app>/<APP_NAME>E strict-updates enabled.

None.
