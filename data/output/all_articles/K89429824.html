Description
You wish to verify configuration parity between BIG-IP devices in the same DSC group.

Environment

  • BIG-IP Device Service Cluster (DSC)
  • Changes Pending Sync Status

Cause
None

Recommended Actions

Use the following commands to show and count object differences.

  1. Log into the BASH prompt.
  • Run the below command to get an idea of what objects (and how many) exist on the current unit that do not exist on the peer (or possibly objects that DO exist but need updated/synced from the current unit).

    Note: Replace <sync failover group name> with the name of your Sync/Failover Device Group.

    Note: You must run the following command from the BASH prompt. If you run from the tmsh utility, the tmsh utility will return an error message similar to the following:

    Syntax Error: "awk", grep is currently the only filter that is supported

    tmsh show cm device-group <sync failover group name> incremental-config-sync-cache | grep "create" | awk -F '_object' '{print $1 FS}' | tee /dev/tty | wc -l


    Example:

    # tmsh show cm device-group Failover incremental-config-sync-cache | grep "create" | awk -F '_object' '{print $1 FS}' | tee /dev/tty | wc -l
    create { pool { pool_name "/Common/pl_bigip2_01" pool_object
    create { pool { pool_name "/Common/pl_bigip2_02" pool_object
    create { virtual_address { virtual_address_name "/Common/1.2.3.4" virtual_address_object
    create { virtual_server { virtual_server_name "/Common/vs_bigip2_01" virtual_server_object
    create { virtual_server_profile { virtual_server_profile_vs_name "/Common/vs_bigip2_01" virtual_server_profile_profile_name "/Common/tcp" virtual_server_profile_object
    5

    Note: The object count (5) at the end of the output.
     
  • To see any changes which might exist from the peer unit's perspective, you would need to run the same command on the peer unit.
  • This is what the output looks like when there are no changes:

    # tmsh show cm device-group Failover incremental-config-sync-cache | grep "create" | awk -F '_object' '{print $1 FS}' | tee /dev/tty | wc -l
    0
  • Another example showing a modified pool (versus a newly-created one):

    # tmsh show cm device-group Failover incremental-config-sync-cache | grep "create" | awk -F '_object' '{print $1 FS}' | tee /dev/tty | wc -l
    create_if { pool { pool_name "/Common/pl_bigip2_01" pool_object
    1
  1. Other methods to look for differences are:
    • Upload qkviews to iHealth and use the Compare feature
    • Use BIG-IQ to look for differences
    • Gather bigip.conf files and use an application like diff to manually compare the files

Note: Comparing using the iHealth compare feature is more reliable for finding discrepancies that are ASM related
