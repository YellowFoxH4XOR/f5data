Known Issue

The Traffic Management Microkernel (TMM) may restart when you use an HTTP/2 profile with the BIG-IP APM system.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for network access or optimized applications.
  • The access virtual server is configured with an HTTP/2 profile.

Impact

Traffic is disrupted while the tmm process restarts. The system fails over if configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/tmm file, you observe messages similar to the following example:

    notice panic: ../modules/hudfilter/spdy/spdy.c:4108: Assertion "spdy pcb initialized" failed.

  • TMM generates a core file to the /shared/core/ directory.
  • Clients are unable to connect to the BIG-IP APM system.

Workaround

To work around this issue, you can remove the HTTP/2 profile from the virtual server configuration. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the access virtual server.
  4. In Acceleration, for HTTP/2 Profile, click None.
  5. Click Update.
