Known Issue

The Traffic Management Shell (tmsh) does not display bd process memory usage.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system is configured with a security policy that actively processes HTTP and/or XML requests.
  • You view the bd process memory usage with the tmsh utility.

Impact

You cannot view bd process memory usage.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You cannot determine the amount of bd process memory usage for troubleshooting purposes.
  • You cannot monitor bd process memory usage.

Workaround

To work around this issue, you can view bd process memory usage in the /var/log/ts/bd.log file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of your BIG-IP ASM system.
  2. To view log messages regarding memory usage, type the following command:

    grep -i "UMU: total" /var/log/ts/bd.log

    The output appears similar to the following example:

    UMU: total 106 ( 0M) VM (1639M) RSS (164M) SWAP ( 0M) trans 0
    UMU: total 106 ( 0M) VM (1639M) RSS (163M) SWAP ( 0M) trans 0
    UMU: total 5 ( 0M) VM (1612M) RSS (163M) SWAP ( 0M) trans 0

    Note: If you have not configured your security policy for XML, you do not have to complete the following steps.

  3. To view memory consumption specifically related to parsing of XML content, enable debug logging on the /etc/ts/bd/logger.cfg file.

    Important: If the BIG-IP system is experiencing high resource usage, in rare cases enabling debug logging may cause poor performance or a system failure.

  4. Using a text editor, open the /etc/ts/bd/logger.cfg file.
  5. Add the following three lines to the bottom of the file:

    MODULE=BD_XML;
    LOG_LEVEL=TS_INFO | TS_DEBUG;
    FILE = 2;

  6. Save the text file changes.
  7. Run the following command to load the /etc/ts/bd/logger.cfg configuration:

    /usr/share/ts/bin/set_active.pl --update_logger_cfg

  8. After the system loads the logger configuration, you can view memory consumption using the following command:

    grep -i "UMU: total" /var/log/ts/bd.log

  9. To disable debug logging for XML parsing (recommended), open the /etc/ts/bd/logger.cfg file with a text editor and use the following command to remove the three lines that you previously added to the bottom of the file:

    MODULE=BD_XML;
    LOG_LEVEL=TS_INFO | TS_DEBUG;
    FILE = 2;

  10. Run the following command to load the logger.cfg configuration:

    /usr/share/ts/bin/set_active.pl --update_logger_cfg
