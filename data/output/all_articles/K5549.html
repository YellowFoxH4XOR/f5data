Known Issue

This is the result of a known issue. The tcpdump utility may display slightly inaccurate timestamps for packets when a tcpdump is performed on an interface. When a tcpdump is performed on an interface, the ouput reflects timestamps in 200 millisecond intervals. When a tcpdump is performed on a VLAN, the output reflects timestamps which correspond more closely to the the actual system time.

There is a difference in timestamps because packet capture at the VLAN level performs within TMM and is local to the user process running the tcpdump utility. Interface-level captures perform within the switch fabric and packets are sent in blocks to TMM every 200 ms. This behavior is by design; however, alternative mechanisms that allow more accurate timestamping are being investigated.

Example tcpdump output

The following examples demonstrate the differing display of tcpdump output when specifying an interface versus a VLAN:

tcpdump output specifying an interface displays packets with timestamps in 200 ms blocks:

# tcpdump -i 1.1

22:22:53.120000
22:22:53.120000
22:22:53.440000
22:22:53.440000
22:22:53.440000
22:22:53.440000
22:22:54.080000
22:22:54.080000
22:22:54.080000
22:22:54.080000
22:22:54.400000
22:22:54.400000
22:22:54.400000
22:22:54.400000

tcpdump output specifying a VLAN displays packets with the system timestamp:

# tcpdump -i myVLAN
