Description

You may have encountered a situation where Kerberos authentication ceases to function on an Exchange Server after the latest Windows Server patches released in January 2024, leading to disruptions in email services for your subscribers. You check the APM logs and notice the following logs:

Jan 29 11:06:55 slot1/example.apm err websso.0[20238]: 014d0019:3: /Common/example.apm.policy:Common:00000000: Kerberos: Failed to resolve IP address: ::ffff:10.2.100.85

Jan 29 11:06:55 slot1/example.apm err websso.0[20238]: 014d0048:3: /Common/example.apm.policy:Common:735be224: failure occurred when processing the work item: Kerberos failed

Environment

  • F5 BIG-IP APM.

  • Microsoft Exchange

  • Windows Server

Cause

It has been identified a failure on the Kerberos authentication was caused by a missing reverse DNS lookup (PTR record) for the Exchange Server's IP address. This issue was observed after the Exchange Server received Windows updates from January 2024. The absence of a PTR record is causing the Kerberos authentication process to fail, as evidenced by errors logged in the BIG-IP APM system.

Recommended Actions

  1. Verify the DNS configuration by running the following nslookup commands on the BIG-IP APM to diagnose which DNS server is not resolving the PTR record correctly (replace the IP addresses with those relevant to your environment supposing that  10.2.100.85 is the IP address of the Exchange Servers):
    • nslookup -type=PTR 10.2.100.85 <primary_dns_ip_addr>
    • nslookup -type=PTR  10.2.100.85 <secondary_dns_ip_addr>
  2. Following the verification, add the appropriate PTR record for the Exchange Server's IP address to the DNS server. This will ensure that reverse DNS lookups are successful.
  3. After adding the PTR record, conduct a new test to confirm that Kerberos authentication is functioning correctly.
  4. Monitor the Exchange Server and APM logs to ensure no further Kerberos authentication errors are occurring.

Additional Information

It is important to maintain accurate DNS records, especially PTR records, for services that rely on Kerberos authentication. The missing PTR record issue seems to be an undocumented consequence of the Windows updates. You should regularly check DNS records post-update to ensure services remain operational. If similar issues arise in the future, reviewing the APM logs for authentication errors can provide early indications of DNS-related problems.
