Known Issue

This is the result of a known issue. The Enterprise Manager Data Statistics Collection feature requires access to managed devices over both port 443 and port 4353, as described in K9743: The Statistics Data Collection feature requires access to TCP port 4353 and 443 on managed devices. When all of the following conditions are true, the Enterprise Manager will write multiple copies of its client certificate to the Trusted Device Certificates bundle (/config/big3d/client.crt) on the managed device:

  • Data Statistics Collection is first enabled, or a new device is discovered after Data Statistics Collection has been enabled
  • The Enterprise Manager can establish a connection over port 443 to the iControl API on the managed device
  • The Enterprise Manager cannot establish an iQuery connection over port 4353 to the big3d agent on the managed device

As a result, the client.crt file on the managed device quickly grows too large for the big3d agent to manage. Once the size of the client.crt file exceeds 200MB, the contents of the file will be lost and the big3d daemon may core.

Note: If the managed system is part of a network for which the BIG-IP GTM is managing traffic, loss of the Trusted Device Certificates file may result in an incomplete iQuery mesh. As a result, the BIG-IP GTM system's ability to manage traffic may be adversely affected as described in K9837: An incomplete iQuery mesh across a sync group may result in inconsistent responses or configuration loss.

All of the following symptoms will be observed when this issue is encountered:

  • The size of the /config/big3d/client.crt certificate file on the managed device increases by several megabytes every few minutes
  • The Enterprise Manager logs the following errors in the /var/log/em file:

    Could not open stats connection to 10.10.10.2 (-42 seconds)
  • The managed device logs the following errors to the /var/log/gtm file:

    SSL_CTX_load_verify_locations: SSL error:0D07209B:asn1 encoding routines:ASN1_get_object:too long
    SSL_CTX_load_verify_locations: SSL error:0D068066:asn1 encoding routines:ASN1_CHECK_TLEN:bad object header
    SSL_CTX_load_verify_locations: SSL error:0D07803A:asn1 encoding routines:ASN1_ITEM_EX_D2I:nested asn1 error
    SSL_CTX_load_verify_locations: SSL error:0907400D:PEM routines:PEM_X509_INFO_read_bio:ASN1 lib
    SSL_CTX_load_verify_locations: SSL error:0B084009:x509 certificate routines:X509_load_cert_crl_file:PEM lib

F5 Product Development tracked this issue as ID 316756 (formerly CR118860) and it was fixed in Enterprise Manager version 1.8.0. For more information about upgrading, refer to the Enterprise Manager release notes.

Workaround

You can work around this issue by disabling the Statistics Data Collection feature on the Enterprise Manager, or by performing one or both of the following actions:

  • Enable port 4353 access from the Enterprise Manager to the managed device by opening the port on any intervening firewalls or routers
  • Ensure the Port Allow list for the appropriate VLAN on the affected managed device allows port 4353

Once access to port 4353 on the managed device has been established, it may be necessary to perform the following procedure on the managed device:

  1. Log in to the BIG-IP command line.
  2. Stop the big3d agent by typing the following command:

    bigstart stop big3d
  3. Delete the /config/big3d/client.crt Trusted Device Certificate file by typing the following command:

    rm -f /config/big3d/client.crt
  4. Restart the big3d agent by typing the following command:

    bigstart restart big3d

If the device is part of a network for which the BIG-IP GTM is managing traffic, it may also be necessary to rebuild the Trusted Device Certificate bundle on the affected device. You can do so by pushing the Trusted Device Certificates from the BIG-IP GTM sync group members to the affected unit using the bigip_add command as described in K8195: Overview of the BIG-IP GTM big3d_install, bigip_add, and gtm_add utilities.
