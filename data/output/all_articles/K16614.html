Topic

You should consider using this procedure under the following condition:

  • You want to detect and block attacks targeting an origin web server (OWS) that supports both form-encoded data and JSON data to a single URL.

Description

You can have a web application that is designed to use parameter-based navigation. For example, requests for http://www.example.com/?page=contact and http://www.example.com/?page=api both share the same base URL, while the query string parameters may lead to different content and encoding.

Because the percent symbol (%) is a valid JSON character, the ASM JSON parser blocks payload such as <script>, but not encoded payload such as %3cscript%3e.

In the Adding JSON Support to an Existing Security Policy section of the BIG-IP Application Security Manager: Implementations guide, an example configuration is provided for associating a JSON profile with a URL, matching the Request Header Name with the wildcard value *json*. This value will match all request headers which contain the string json.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

For example:

Content-Type: application/x-www-form-urlencoded; charset=UTF-8;json

Since json at the end of this example string is a match for the JSON profile, the BIG-IP ASM system treats the content as JSON, and allows potentially malicious percent encoded payload to be sent to the OWS for content-types multipart/form-data and application/x-www-form-urlencoded.

To prevent this situation from occurring, you can create attack signatures to detect and block requests that contain both form-encoded data and JSON data in the same request.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have an existing BIG-IP ASM system provisioned and one or more security policies configured on the system to protect your OWS.
  • You should be familiar with both the Perl Compatible Regular Expressions (PCRE) and RE2 regular expression syntax.
  • You must have administrative access to the Configuration utility.

Procedures

Creating and assigning a user-defined attack signature in the BIG-IP ASM system

You need to create two separate attack signatures to detect and block malicious requests that target the previously described combination JSON and form-encoded enabled OWS. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to one of the following locations:
    • BIG-IP ASM 11.3.0 through 11.6.0

      Navigate to Security > Options > Application Security > Attack Signatures > Attack Signature List

    • BIG-IP ASM 11.2.x

      Navigate to Application Security > Options > Attack Signatures > Attack Signature List

  3. To create a new user-defined attack signature, click Create.
  4. In the Name box, type a unique name for the new user-defined attack signature.

    Note: The user-defined attack signature name must not be the same as a system-supplied attack signature, otherwise subsequent signature updates may fail.

    For example:

    JSON_urlencoded

  5. For the Signature Type setting, select Request.
  6. Select the appropriate system for the Systems setting by moving the selected entry from the Available Systems to the Assigned Systems.

    For example:

    Apache

    Apache Tomcat

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  7. Select the appropriate attack type for the Attack Type setting.

    For example:

    Other Application Attacks

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  8. Enter the following rule syntax as one line in the Rule setting:

    headercontent:"Content-Type"; nocase; headercontent:"x-www-form-urlencoded"; nocase; headercontent:"json"; nocase; re2:"/Content-Type:[^\r\n]+?\bx-www-form-urlencoded\b/Hi"; re2:"/Content-Type:[^\r\n]+?\bjson\b/Hi";

  9. Configure the remaining settings, as desired.
  10. To save the configuration for the user-defined attack signature, click Create.
  11. To create another new user-defined attack signature, click Create.
  12. In the Name setting for the new user-defined attack signature, type a unique name. The user-defined attack signature name must not be the same as a system-supplied attack signature, otherwise subsequent signature updates may fail.

    For example:

    JSON_multipart

  13. In the Signature Type box, select Request.
  14. Select the appropriate system for the Systems setting by moving the selected entry from the Available Systems to the Assigned Systems.

    For example:

    Apache
    Apache Tomcat

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  15. Select the appropriate attack type for the Attack Type setting.

    For example:

    Other Application Attacks

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  16. In the Rule setting, enter the following rule syntax as one line:

    headercontent:"Content-Type"; nocase; headercontent:"multipart/form-data"; nocase; headercontent:"json"; nocase; re2:"/Content-Type:[^\r\n]+?\bmultipart\/form-data\b/Hi"; re2:"/Content-Type:[^\r\n]+?\bjson\b/Hi";

  17. Configure the remaining settings, as desired.
  18. To save the configuration for the second user-defined attack signature, click Create.
  19. Navigate to one of the following locations:
    • BIG-IP ASM 11.3.0 through 11.6.0

      Navigate to Security > Options > Application Security > Attack Signatures > Attack Signature Sets

    • BIG-IP ASM 11.2.x

      Navigate to Application Security > Options > Attack Signatures > Attack Signature Sets

  20. To create a new user-defined attack signature set, click Create.
  21. For the new user-defined signature set, type a unique name in the Name box.

    For example:

    JSON_formEncodedSet

  22. For the Type setting, select Manual.
  23. Select the filters as appropriate in the Signatures Filter section based on the selection of the Systems and/or Attack Type settings that you made when you created the user-defined attack signature. The Configuration utility will then refresh the Signatures list. For example, if you have selected Apache for the Systems setting and Other Application Attacks for the Attack Type setting, the Configuration utility should refresh the Signatures list to display the user-defined attack signature that you created in previous steps.

    Note: Depending on the number of available attack signatures on your system, the Configuration utility may take some time to refresh the Signatures list.

  24. Select both the user-defined attack signatures created in previous steps in the Available signatures list and move them to the Assigned signatures list by clicking <<.
  25. To save the configuration for the user-defined attack signature set, click Create.
  26. Navigate to Security > Application Security > Attack Signatures > Attack Signatures Configuration.
  27. From the Current edited policy list, select the desired security policy.
  28. In the Attack Signature Sets Assignment setting, select the user-defined attack signature set you have created in previous steps from the Available Signature Sets list and move it to the Assigned Signature Sets list by clicking <<.
  29. To save the changes, click Save.
  30. To activate the change, click Apply Policy.
