K000093205: Nginx Rate Limiting is not working after configuring signal sciences module

Type
Support Solution
Published
2022-12-09
Updated

Source

Description

We are able to use a customized NGINX image with nginx plus ingress, signal science and consul and able to do rate limiting using the customized image but when we add the signal science module configuration in nginx configmap we observe the rate-limiting stops working.
Below are the configs in configmap which is causing the issue. 
 main-snippets: |
    load_module /etc/nginx/modules/ngx_http_sigsci_module.so;
http-snippets: |
    sigsci_agent_host unix:/sigsci/tmp/sigsci.sock;
    sigsci_agent_max_post_len 0;
To be specific we are observing the issue whenever we load the config 'sigsci_agent_host unix:/sigsci/tmp/sigsci.sock;'
and if we remove this line everything works fine.
 

Environment

  • NGINX Ingress Controller
  • Rate-Limiting
  • Signal Sciences
  • sigsci

Cause

The rate limiting module is loaded in the `NGX_HTTP_PREACCESS_PHASE`. Which is after our default.

sigsci module is a step before it, so the rate limiting module never gets implemented. The rate limiting module does not distinguish between different request methods and always works after reading the request headers.

 Recommended Actions

Add the following to the http-snippets 
sigsci_handler_phase access;
