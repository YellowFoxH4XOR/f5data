Description

You have configured and applied a security log profile to log to a remote log server. You observe that no logs are being sent even though requests and violations are occurring.

The log server is configured in a non-0 route domain, similar to the following example:

[root@bigip1:Active:Standalone] test-part # tmsh list security log profile /test-part/test-part_log_profile
security log profile /test-part/test-part_log_profile {
    application {
        /test-part/test-part_log_profile {
            filter {
                request-type {
                    values { all }
                }
            }
            format {
                fields { attack_type }
            }
            local-storage disabled
            logger-type remote
            protocol udp
            remote-storage remote
            servers {
                10.10.10.88%555:514 { }
            }               ^___________________!
        }
    }
    partition test-part
}

You may also observe log messages in /var/log/asm similar to the following example:

ASM configuration error: event code L2909 Failed to write to remote logger

Note: If the security log profile is created in a non-Common partition, and that partition has a default route domain, the log server will automatically default to that route domain if no route domain notation is specified upon creation.

Environment

  • Security log profile
  • Remote logging
  • Event logs
  • Route domains

Cause

When bd tries to send logs to a destination in a non-0 route domain, it will fail. Route domains are a TMM concept and bd is a userland daemon that has no concept of route domains.

Recommended Actions

Use the following command to verify if your log server is configured to be reachable from a non-0 route domain:

tmsh list security log profile <profile>

Log servers must be configured in route domain 0. If the security log profile's partition has a default route domain that isn't 0, you must explicitly specify route domain 0 as part of the destination IP when creating the security log profile in that partition. For example, 10.10.10.88%0.

Additional requirements are:

  • VLAN in route domain 0
  • Self IP in that VLAN
  • Route configured in route domain 0, either default, or explicitly sending traffic to the log destination (unless it is directly connected)

Additional Information

Regular syslog is also unable to send traffic to a non-0 route domain destination.
