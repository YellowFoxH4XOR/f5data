Known Issue

Application Visibility and Reporting (AVR) does not display Max read latency units.

This issue occurs when the following condition is met:

  • You have provisioned AVR, BIG-IP ASM, DoS, or BIG-IP AFM.

Impact

The system does not display any units.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • AVR does not display units for Max Read Latency.

Workaround

To work around this issue, you can modify the monp_disk_info_measures.cfg file to display the correct units. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. Change the directory to /etc/avr/monpd by typing the following command:

    cd /etc/avr/monpd

  3. Make a backup of the monp_disk_info_measures.cfg config file by typing the following command:

    cp monp_disk_info_measures.cfg monp_disk_info_measures.cfg.orig

  4. Open the editor so you can edit the monp_disk_info_measures.cfg file.
  5. Locate the following section:

    [read_lat_us]
    formula=round(max(rd_lat_us),0)
    merge_formula=round(max(read_lat_us),0)
    display_name=Max Read Latency
    tmsh_display_name=max-read-latency
    tmsh_context_help=Max read latency

  6. Add the following entry at the end of the section in the previous step:

    units=microsecond

    For example:

    [read_lat_us]
    formula=round(max(rd_lat_us),0)
    merge_formula=round(max(read_lat_us),0)
    display_name=Max Read Latency
    tmsh_display_name=max-read-latency
    tmsh_context_help=Max read latency
    units=microsecond

  7. Save the changes you made to the monp_disk_info_measures.cfg file.
  8. To allow the changes to be read, restart the monpd services by typing the following command:

    tmsh restart sys service monpd
