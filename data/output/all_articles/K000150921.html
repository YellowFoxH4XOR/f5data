Description

When configuring a BIG-IP LTM Standard Virtual Server (VS) with an HTTP profile, it is important to understand when the system establishes a server-side TCP connection to pool members. This includes how the BIG-IP handles different HTTP methods (such as GET and POST), requests with bodies, and non-standard scenarios like GET requests containing a body. This article explains the precise behavior for server-side TCP connection initiation in these contexts.

Environment

  • BIG-IP LTM
  • Standard Virtual Sever
  • HTTP Profile
  • HTTP GET and POST requests

Cause

The timing of server-side TCP connection setup by the BIG-IP LTM is governed by its HTTP profile processing logic. The system waits until it has received a complete and valid HTTP request from the client before initiating the three-way handshake (3WHS) with a pool member.

Recommended Actions

  1.  For standard GET requests, once all headers are received (ending with an empty line), BIG-IP starts 3WHS to the selected pool member.
  2. For POST or any method where a body is present, BIG-IP waits for both headers and full body before starting 3WHS.
  3. If a GET request contains a body (though not typical per RFC standards), BIG-IP treats it like any other request-with-body scenario—waiting for full receipt of both headers and body before connecting to the pool member.

Additional Information

HTTP GET request can contains body, it is not explicitly prohibited by the RFC. BIG-IP LTM will forward that as mentioned above.
