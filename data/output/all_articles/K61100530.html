Description

Configuring a management interface firewall rule to drop, reject or log ICMP traffic is not taking effect
ICMP is still being accepted and the rule counter does not increment to indicate hits
 

Environment

  • BIG-IP management network
  • BIG-IP AFM may or may not be provisioned

Cause

This is caused by a pre-built chain that has a rule that accepts all ICMP traffic, which takes precedence over user-configured policies. This is tracked as Bug ID 760355.

Recommended Actions

You can manually add firewall rules for this requirement using the commands below:

# /sbin/iptables -N id760355
# /sbin/iptables -I INPUT 1 -j id760355
# /sbin/iptables -I id760355 1 -i mgmt -p icmp -j LOG --log-prefix "IPTables-Log: "
# /sbin/iptables -A id760355 -i mgmt -p icmp --icmp-type 8 -j DROP
 

Note: The above example is for ICMP echo only and for all sources and destinations. Make sure to review your requirements when blocking ICMP traffic to avoid inadvertently blocking ICMP signaling packets. These configurations do not survive upgrades.
