Issue

Error Message

<hostname> err logger: /usr/libexec/aws/aws-failover-tgactive.sh : AWS_ACCESS_KEY not set. Set 'tmsh sys global-settings aws-access-key' for HA to work on AWS.

or

<hostname> err logger: /usr/libexec/aws/aws-failover-tgactive.sh : AWS_SECRET_KEY not set. Set 'tmsh sys global-settings aws-secret-key' for HA to work on AWS.

In these error messages, note the following:

  • <hostname> is the hostname of the BIG-IP system.

For example:

<bigip1> err logger: /usr/libexec/aws/aws-failover-tgactive.sh : AWS_ACCESS_KEY not set. Set 'tmsh sys global-settings aws-access-key' for HA to work on AWS.

or

<bigip1> err logger: /usr/libexec/aws/aws-failover-tgactive.sh : AWS_SECRET_KEY not set. Set 'tmsh sys global-settings aws-secret-key' for HA to work on AWS.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when the following condition is met:

  • The BIG-IP Virtual Edition (VE) system running on the Amazon Web Services (AWS) EC2 cloud service is not configured with the appropriate AWS EC2 access key and secret key.

During the failover process, BIG-IP VE systems running on the AWS EC2 cloud service use the AWS API with the assigned access key and secret key to access the AWS resource through the management network. If the access key or secret key is not set, the system logs these error messages during failover.

Impact

The BIG-IP VE system running on the AWS EC2 cloud service is unable to fail over to its peer system in a high availability (HA) configuration.

Recommended Actions

If the access key or secret key is not set, you must obtain the necessary access key and secret key from the AWS EC2 management console and use them to configure your system. For information about obtaining and configuring the access key and secret key, refer to K14827: Configuring failover for BIG-IP VE on Amazon EC2.
