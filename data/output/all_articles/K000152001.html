Security Advisory Description

An HTTP/2 implementation flaw allows a denial-of-service (DoS) that uses malformed HTTP/2 control frames to break the maximum concurrent streams limit (HTTP/2 MadeYouReset Attack). (CVE-2025-54500)

Impact

This vulnerability allows a remote, unauthenticated attacker to cause an increase in CPU usage that can lead to a degradation of service to some users of the BIG-IP system.

Security Advisory Status

F5 Product Development has assigned ID 1937817 (BIG-IP), ID 1937817-5 (BIG-IP Next), and ID 1937817-6 (BIG-IP Next SPK, BIG-IP Next CNF, and BIG-IP Next for Kubernetes) to this vulnerability. This issue has been classified as CWE-770: Allocation of Resources Without Limits or Throttling.

Security Advisory Recommended Actions

If you are running a version listed in the Versions known to be vulnerable column, you can eliminate this vulnerability by installing a version listed in the Fixes introduced in column. If the Fixes introduced in column does not list a version for your branch, then no update candidate currently exists for that branch and F5 recommends that you upgrade to a version with the fix (refer to the tables).

If the Fixes introduced in column lists a version prior to the one you are running, in the same branch, then your version should have the fix.

Mitigation

BIG-IP and BIG-IP Next

To mitigate this issue for systems and configurations that are able to use either HTTP or HTTP/2, F5 recommends using HTTP and disabling HTTP/2.

For Single CPU BIG-IP VE, small vCMP guests, and F5OS tenant deployments, consider increasing the number of CPU cores to increase capacity of handling crypto transactions and adjust the per-TMM crypto limit. For more information, refer to K000150313: Connection error: per-tmm crypto request limit reached.

BIG-IP Next SPK, BIG-IP Next CNF, and BIG-IP Next for Kubernetes

To mitigate this vulnerability, where possible, you can delete the F5SPKIngressHTTP2 Custom Resource. For more information, refer to the F5SPKIngressHTTP2 CR page and the documentation for your product on F5 Cloud Docs.

BIG-IP ASM and Advanced WAF

To mitigate this vulnerability, you can create a BIG-IP ASM/Advanced WAF DoS protection profile configured with TPS and stress-based attributes, including Behavioral DoS Detection and Mitigation, and associate the BIG-IP ASM/Advanced WAF DoS protection profile with the HTTP/2 virtual server. For TPS and stress-based thresholds and mitigation, set appropriate Relative and Absolute Thresholds and appropriate mitigations for your environment. Note that Stress-based Detection detects and mitigates per server stress. Behavioral DoS Detection needs to observe traffic patterns and server stress under normal conditions in order to detect changes, so you must enable Behavioral DoS Detection before changes in the normal traffic pattern occur.

Indicators of attack for BIG-IP systems

For BIG-IP systems, you can inspect the HTTP/2 profile statistics. If the number of RST_STREAM frames Sent and WINDOW_UPDATE frames Received significantly exceeds the number of other frames received from clients, this may indicate that a malicious actor is conducting this type of attack. If there is no impact on the CPU load of the BIG-IP system, you may not need to take remedial action; however, if a significant or troublesome increase in CPU load is observed, download and install the engineering hotfix for this issue. For information about how to view the HTTP/2 profile statistics using the Configuration utility, tmsh, or SNMP, refer to K000137190: Overview of HTTP/2 Statistics.
