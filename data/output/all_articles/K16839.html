Known Issue

The BIG-IP, BIG-IQ, or Enterprise Manager system may reboot when configured to synchronize its clock with a Network Time Protocol (NTP) server.

This issue occurs when all of the following conditions are met:

  • You have configured the system to synchronize its clock with an NTP server.
  • During the 24 hour window prior to a leap second event, a Red Hat kernel livelock condition occurs.

    Important: For information about the Red Hat kernel-based livelock condition, refer to the RHBA-2012:1198-2 Red Hat advisory.

When a leap second event triggers a Red Hat kernel livelock condition, the BIG-IP hardware watchdog process may trigger a reboot to allow the system to recover.

Important: A leap second event that triggers this issue will occur on December 31, 2016, 23:59:60 UTC time.

Impact

The system may reboot and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system reboots and temporarily fails to process traffic.
  • The BIG-IP system fails over to another host in the device group.
  • Error messages similar to the following example may appear in the /var/log/daemon.log file:

    notice ntpd[6789]: kernel time sync enabled

  • Error messages similar to the following example appear in the /var/log/ltm file:

    notice boot_marker : ---===[ MD1.2 - BIG-IP 11.3.0 Build 3158.21 ]===---
    chmand[6586]: 012a0005:5: CPLD indicates prior Host CPU subsystem reset
    chmand[6587]: 012a0005:5: Host CPU subsystem reset - PCI reset asserted
    chmand[6588]: 012a0005:5: Host CPU subsystem reset caused by a Southbridge system reset
    chmand[6589]: 012a0004:4: Host CPU subsystem reset caused by *** Super I/O watchdog timeout ***

Workaround

To work around this issue, you can temporarily remove the NTP time server from the BIG-IP or Enterprise Manager system configuration. After the leap second event has passed (for example, December 31, 2016, 23:59:60 UTC time), you can add the NTP server back to the configuration. To do so, perform the following procedure:

Using the Configuration utility to temporarily remove an NTP server

Impact of workaround: The BIG-IP or Enterprise Manager system will not receive time updates or adjust for any time skews while not configured with an NTP server. However, this should not have a negative impact on your system over a short duration.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device.
  3. Click NTP.
  4. In the Time Server List screen, select the IP address of the defined NTP server.

    Record the NTP server IP addresses for later use in step 11 when you add the NTP servers back.

    Note: You can hold and drag the mouse to select multiple IP addresses.

  5. Click Delete.
  6. Click Update.
  7. After December 31, 2016, 23:59:60 UTC time, you can add the NTP server IP addresses back to the configuration.
  8. Log in to the Configuration utility.
  9. Navigate to System > Configuration > Device.
  10. Click NTP.
  11. On the Properties screen, in the Address field, type the IP address of the NTP server.
  12. Click Add.
  13. Repeat step 11 and 12 to add all desired NTP servers.
  14. Click Update.

Using the tmsh utility to temporarily remove an NTP server

Impact of workaround: The BIG-IP or Enterprise Manager system will not receive time updates or adjust for any time skews while not configured with an NTP server. However, this should not have a negative impact on your system over a short duration.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To list the current NTP server IP address, type the following command.

    Record the NTP server IP addresses for use in step 5, when you add the NTP servers back.

    list sys ntp servers

  3. To remove the NTP server, type the following command:

    modify sys ntp servers none

  4. After the leap second event has passed (for example, December 31, 2016, 23:59:60 UTC time), you can add the NTP server IP addresses back to the configuration.
  5. To add the NTP server IP addresses back into the NTP configuration, use the following command syntax:

    modify sys ntp servers add { <IP Address 1> <IP Address 2> }

    For example, to add NTP servers 192.168.1.100 and 192.168.1.101 back to the configuration, use the following command:

    modify sys ntp servers add { 192.168.1.100 192.168.1.101 }

  6. To save the configuration, type the following command:

    save sys config
