Topic

Beginning in BIG-IP ASM 13.0.0, you can create a parent security policy and have child security policies refer to it (layered policies).

A parent security policy defines common Policy Section elements and settings that provide baseline protection for your environment and are inherited by all child policies attached to it. You identify the elements and settings that can be modified in child security policies and those that are mandatory and cannot be modified. When you modify elements and settings in the parent security policy, the system rapidly applies them to all attached child policies.

For example, consider a scenario is which you discover a zero-day exploit. Using a parent policy, you create the signatures you need to mitigate the attack, and then add them to the policy. Then, all the attached child security policies automatically inherit the signature set in the parent policy, so you don't have to manually add the new attack signatures to multiple security policies.

Description

Parent and child security policy terminology and configuration options

A parent security policy:

  • Is a virtual policy that does not process traffic and cannot be assigned to a virtual server.
  • Acts as a template for attached child security policies by sharing the configuration of specific Policy Section elements and settings.

A child security policy:

  • Behaves as a standard security policy that can be assigned to a virtual server.
  • Inherits the Policy Section elements and settings of the parent security policy, when attached to one.
  • Generates traffic learning suggestions and request log entries, when attached to a parent security policy. 
  • Can attach and detach from a parent security policy.
  • Can only be modified when the parent security policy allows updates to attached child security policies or the child policy is detached from a parent policy's inheritance settings.

Note: Parent and child policies are case sensitive and must have the same Application Language and differentiation settings for HTTP/WS and HTTPS/WSS URLs.

Policy Section elements and settings

Child security policies inherit the following Policy Section elements and settings from the parent security policy to which they are attached:

  • Attack signatures sets
  • Custom violations
  • Data Guard
  • Evasion techniques
  • File types
  • General policy settings
  • Headers
  • HTTP protocol compliance
  • IP addresses and geolocations
  • Parameters - (Only Parameter violations and learning settings are inherited)
  • Policy building process
  • Server technologies
  • WebSocket protocol compliance
  • HTTP protocol compliance failed
  • Attack signatures
  • Evasion technique detected

Inheritance settings

The following Inheritance settings define how attached child security policies inherit Policy Section elements and settings:

  • None: Attached child security policies do not inherit parent security policy elements and settings.
  • Mandatory: Attached child security policies inherit parent security policy elements and settings, which can only be modified on the parent policy.
  • Optional: Attached child security policies can accept or decline to inherit parent security policy elements and settings.

Recommendations

Policy tuning considerations 
When fine-tuning parent and child security policies, consider the following points:

  • The parent security policy cannot be assigned to a virtual server and only provides learning suggestions for attached child security policies.
  • When you configure child security policies with mandatory inheritance, all learning suggestions for Policy Section elements and settings are disabled on the Traffic Learning page.

    Note: The parent security policy only displays learning suggestions when they reach a score of 50% or greater.

  • You can only set child security policies to Blocking; you cannot set parent security policies to Blocking.
  • You cannot accept traffic learning suggestions for Event Logs > Application > Requests log entries in child security policies attached to a parent security policy.

    Note: The Delete Request and Export Request options in the Event Logs > Application > Requests log are available.

  • When you create a new child security policy from an existing child policy that is attached to a parent security policy, the new policy inherits the parent policy of the existing child policy.
