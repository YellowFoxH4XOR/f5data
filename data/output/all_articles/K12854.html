Issue

Error Message

This add-on could not be downloaded because of connection failure <host>

In this error message, note the following:

  • <host> is the IP address or fully-qualified domain name used to connect to the FirePass or BIG-IP APM device.

    For example:

    This add-on could not be downloaded because of connection failure 10.10.10.1

Message Location

You may encounter this message in the following location:

  • Firefox users receive the This add-on could not be downloaded because of connection failure <host> error message in their browser.

Description

This message occurs when all of the following conditions are met:

  • The user connects to a FirePass or BIG-IP APM system with a Firefox 4 or later browser.
  • The FirePass or BIG-IP APM system has an SSL certificate that Firefox does not trust. Following are some of the most common reasons why Firefox may not trust a certificate:
    • The SSL Certificate was signed by a Certificate Authority that is not natively included in the Firefox 4 Certificate Manager Authorities store.
    • The SSL Certificate is a self-signed certificate.
    • The SSL Certificate has expired.
    • The user connects to the FirePass or BIG-IP APM system using a URL that does not match the Common Name listed in the SSL Certificate.
  • The user attempts to download and install an XPI installer module by way of the FirePass or BIG-IP APM controller connection.

The error message This add-on could not be downloaded because of connection failure <host> occurs when a Firefox user attempts to install an .xpi extension package. You will most often see this error message when the user attempts to connect to an Application Tunnel favorite for the first time, but you may see the error message under other circumstances as well. The change in the Firefox behavior is the result of an additional security measure that Firefox added beginning in version 4. Firefox requires that all .xpi packages come from a trusted source. If the SSL certificate is not listed in the Certificate Manager Authorities store, Firefox does not consider the certificate a trusted source and sends the error message to the user. The system continues to reprompt users who run Firefox 3.6.10 and earlier to add an exception for each file contained in the .xpi package, instead of sending them the This add-on could not be downloaded because of connection failure <host> error message. Because this is a change in behavior in Firefox, F5 is unable to supply a hotfix for this error message.

You may see an additional error message on the Firefox Error Console, which appears similar to the following example, when the previously mentioned conditions are met:

Warning: WARN addons.xpi: Download failed: [Exception... "Certificate issuer is not built-in."
nsresult: "0x80004004 (NS_ERROR_ABORT)" location: "JS frame ::
resource://gre/modules/CertUtils.jsm :: checkCert :: line 87" data: no]

Note: F5 officially stops supporting the Mozilla Firefox browser the Firefox 34 release.

Impact

Firefox users are unable to connect to resources that require that they install an .xpi package.

Recommended Actions

To resolve this issue on the FirePass or BIG-IP APM device, install an SSL certificate that is trusted by the Firefox browser. If you previously used a self-signed certificate, you may have to install a third-party SSL certificate that a trusted Certificate Authority has signed.
