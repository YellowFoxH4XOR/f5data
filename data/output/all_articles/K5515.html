Known Issue

This is the result of a known issue. If a static route is configured on the BIG-IP system, a dynamically learned route for the same destination will not be installed into the Traffic Management Microkernel (TMM) routing table. As a result, a default management route that is learned dynamically through ZebOS/ARM may not be installed into the TMM routing table, and the static default management route may override the dynamically learned default management route.
This issue will occur when all of the following conditions are true:
  • A static default management route has been configured on the BIG-IP system
  • The BIG-IP has dynamic routing (ZebOS/ARM) configured
  • A peer is intended to supply the BIG-IP system with a dynamic default management route

F5 Product Development tracked this issue as CR84729 and it was fixed in BIG-IP 9.6.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, or WebAccelerator release notes.

Workaround

The root cause of this issue is the addition of the static default route to GATEWAY entry in the /etc/sysconfig/network file. You can work around this issue by removing this value. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Change directories to the /etc/sysconfig directory by typing the following command:

    cd /etc/sysconfig

  3. Back up the network file by typing the following command:

    cp network network.sol5515

  4. Open the network file using a file editor.
  5. Change the existing GATEWAY entry to the following:

    GATEWAY=none

  6. Save the /etc/sysconfig/network file.
  7. Reboot the BIG-IP system by typing the following command:

    reboot
