Description

When the BIG-IP LTM receives a packet from the client, it will forward this packet to the pool member (node). The node will respond with a packet but this packet will not be forward back to the client.

In summary, client sends a packet to the Virtual Server VIP.
<client > → <Virtual Server>

The Virtual Server will forward that packet to the node.
<Virtual Server SNAT> → <node>

The node will respond to the packet back to the Virtual Server.
<Virtual Server SNAT> ← <node>

However the Virtual Server does not forward the packet back to the client.
<client >    <Virtual Server>

This behaviour can can happen on a TCP or UDP protocol and the Virtual Server is using SNAT automap.

This behaviour can be seen in the packet capture (pcap). The packet capture will also show that the returning packet from the node is processed by another VLAN id.
The example below shows that the Virtual Server will receive the packet from VLAN id 80 and forwards it to the node with the same VLAN id 80. However the returning VLAN id is 500.
Client IP is 10.1.1.1
Virtual Server VIP is 10.1.1.255
Virtual Server SNAT is 192.168.86.254
Node (pool member) is 192.168.71.13

SourceDestinationProtocolIDInfo

192.168.86.254192.168.71.13DNS     80       OUT s1/tmm1 : Standard query 0xf5be A example.com

It is also noticed that not all VLANs on the BIG-IP has a floating self-IPs. In other words, not all non-floating self IPs have a floating self IP.

Environment
  • BIG-IP LTM
  • Packet from the node (pool member) will not be forwarded to the client
  • SNAT automap is used for the Virtual Server
  • Not all non-floating self-IPs will have a floating self-IP
  • The packet from the node will be processed by another VLAN id

Cause

When the node response comes back to the BIG-IP on a different VLAN id, the BIG-IP will reject the packet and will not proceed to process it.
This behaviour is seen because the BIG-IP does not have a floating self IP configured for the outgoing VLAN to the node thus the BIG-IP will choose a floating self IP from another VLAN. For the example above, it is VLAN 500.
Based on the example above, it results to the BIG-IP sending out the traffic via VLAN 80 but the source IP is part of VLAN 500.

Recommended Actions

To resolve the problem, create a floating self IP from the outgoing VLAN to the node (pool member).

  1. Login to the BIG-IP LTM Configuration Terminal.
  2. On the Main tab, click Network > Self IPs.
  3. Click Create. The New Self IP screen opens.
  4. In the Name field, type a unique name for the self IP address.
  5. In the IP Address field, type an IPv4 or IPv6 address. This IP address should represent the address space of the VLAN that you specify with the VLAN/Tunnel setting.
  6. In the Netmask field, type the full network mask for the specified IP address.
  7. From the VLAN/Tunnel list, select the VLAN to associate with this self IP address.
  8. From the Port Lockdown list, select Allow Default.
  9. From the Traffic Group list, choose traffic-group-1 (floating).
  10. Click Finished. The screen refreshes, and displays the new self IP address.
