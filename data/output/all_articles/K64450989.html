Topic

You should consider using this procedure under the following condition:

  • You want to encrypt a BIG-IP password that you use in a playbook.

Description

When you use F5 Modules for Ansible, you must provide a BIG-IP password in the password parameter or with the F5_PASSWORD environmental variable. If you use the parameter method and do not want to expose the password in your Ansible files, you can use the ansible-vault command to encrypt it.

The Ansible best practice for defining a password variable in an unencrypted file is to make its value another variable, which is defined in an encrypted file. This practice enables you to find and list all group variables for maintenance purposes, when necessary. When you only keep the password variable in an encrypted file, you cannot use tools to find it, such as grep. For more information about this best practice, refer to the Best Practices: Variables and Vaults section in the Ansible User Guide.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You configured a group in your inventory to which you can assign group variables.
  • Your tasks contain the BIG-IP password in plain text, or you defined a variable for the password, and the value is in plain text.
  • You read the User's Guide section in F5 Modules for Ansible Documentation.
  • You installed Ansible 2.5 or later on the control machine.
  • The devices in your device group are running BIG-IP 12.x or later

Procedures

The following examples show passwords exposed in plain text. These situations can be avoided by storing your BIG-IP password in an encrypted group variable file, as described in the procedure.

Examples

Password in plain text

In this example the password is secret, and it's exposed in plain text in a task:

- name: Create node1
  bigip_node:
      server: "{{ ansible_host }}"
      user: "admin"
      password: "secret"
      host: "10.10.10.10"
      name: "10.10.10.10"
      validate_certs: False
  delegate_to: localhost
  notify: Sync configuration from device to group

Password in a group variable

In this example the password is secret, and it's exposed in a group variable in a hosts file:

[my_dg:vars]
dg_name="my_spectacular_group"
dg_password="secret"

When you use this method, the password parameter in a F5 Module for Ansible task appears similar to the following example:

- name: Create node1
  bigip_node:
      server: "{{ ansible_host }}"
      user: "admin"
      password: "{{ dg_password }}"
      host: "10.10.10.10"
      name: "10.10.10.10"
      validate_certs: False
  delegate_to: localhost
  notify: Sync configuration from device to group

Storing your BIG-IP password in an encrypted group variable file

Use the following procedure to separate group variables into a different file in the group_vars directory.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. Review your hosts file to verify the name of the group in your inventory for which want to encrypt the variables.

    In the following example the group is named my_dg:

    [my_dg]
    bigip1.askf5team.local ansible_host=172.24.1.1
    bigip2.askf5team.local ansible_host=172.24.1.2

  3. If it does not already exist, create a directory called group_vars in your playbooks directory.
  4. Within the group_vars directory, create another directory with the group name.

    Using the example above, the directory name is my_dg.

  5. Create a file named vars.yml in which to store your group variables.

    In a later step, you use the ansible-vault command to create a second encrypted file named vault.yml for your BIG-IP password.

    The relative path for both files looks similar to the following:

    group_vars/my_dg/vars.yml
    group_vars/my_dg/vault.yml

  6. Move the group variables from your hosts file, or create them in the vars.yml file, including one for the BIG-IP password.

    The variable for the passwords points to another variable in the encrypted file, which you create in the next step.

    Note: You must use YAML syntax for this file. When you attempt to use the INI syntax that typically appears in hosts files, you encounter the following error:

    ERROR! failed to combine variables, expected dicts but got a 'dict' and a 'AnsibleUnicode'

    The file appears similar to the following:

    ---
    dg_name: "my_spectacular_group"
    dg_password: "{{ vault_dg_password }}"

  7. Ensure the working directory is your new group directory within group_vars.

    For example, the directory is group_vars/my_dg.

  8. Type the following command, which uses the ansible-vault command to create an encrypted file named vault.yml:

    ansible-vault create vault.yml

    You use this file for the actual password.

  9. When prompted to create a vault password, type a password and save it in a secure location.

    Your default text editor opens.

  10. Define your variable with the actual BIG-IP password as its value.

    Ensure the name of this variable matches the value of the password variable in the vars.yml file. For example:

    ---
    vault_dg_password: "secret"

  11. Save the file and close the editor.
  12. When you run F5 Modules for Ansible tasks on the group, if literal passwords appear, update the password parameters to use the variable in the vars.yml file.

    For example, using the example from the introduction, it appears similar to the following, except secret is now replaced by {{ dg_password }}:

    - name: Create node1
      bigip_node:
          server: "{{ ansible_host }}"
          user: "admin"
          password: "{{ dg_password }}"
          host: "10.10.10.10"
          name: "10.10.10.10"
          validate_certs: False
      delegate_to: localhost
      notify: Sync configuration from device to group

    Playbooks that use your group reference the new group variable files.

    For example, continuing with the example that uses the my_dg group, the beginning of the playbook appears similar to the following:

    ---
    - name: Create objects only on the active DG member
      hosts: my_dg
      gather_facts: False

  13. When you run the playbook, include the vault-id argument with the @prompt option, to prompt for the vault password you created in step 9.

    For example, you type the following:

    ansible-playbook --vault-id @prompt my_playbook.yml
