Description

  • Webui active alarms show a specific alarm that is stale or false.
  • The alarm CommunicationofFEPCPF is about the link between CPF and FEP.
  • Truncating the alarm from the Cassandra DB doesn't clear the alarm.
  • Checking the CPF and FEP in question show that they are connected hence the alarm is stale or false.

Environment

  • SDC 5.1
  • FEP, CPF, NMSAgent and Cassandra DB

Cause

The CPF holds a wrong state and updates the NMSAgent about it or the CPF keep its own alarm history and sends it to the NMSAgent upon reconnect. Hence, the alarm list is not correct.

 Recommended Actions

  • CPF restart will reset the FEP and CPF connection thus this action will update the connection state.
  • If we need further investigation on this we will need to collect packet captures.
  1. Stop ALL the NMSAgent components in the site.
  2. Start packet capture in one of the NMSAgent node.
  3. Start the NMSAgent in the same node.
  4. After the above collect packet capture and new set of TTA.
  5. After packet capture is completed, you can start the rest of the NMS
  6. Share the pcap to F5 support for further checking.
