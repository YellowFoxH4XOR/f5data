K13484: Disabling the BIG-IP ASM system marks the system offline

Issue

Old Behavior

Prior to BIG-IP ASM 11.0.0, you can disable or restart the BIG-IP ASM core services without affecting the overall system status.

New Behavior

Beginning in BIG-IP ASM 11.0.0, the status of the unit will be taken from Active or Inactive to Offline when the BIG-IP ASM bd process is stopped or restarted. The system returns to its Active or Inactive state, as defined by its configuration, once the BIG-IP ASM bd process is running.

You can check the status of the BIG-IP ASM bd process by using the bigstart status asm command.

When the BIG-IP ASM bd process is not running, the command displays a status that appears similar to the following example:

asm          down 16 seconds, normally up

In this state, the command line prompt displays a system status that appears similar to the following example:

[root@myASM:Offline]

A red status indicator displays at the top of the Configuration utility, along with the following corresponding system state:

OFFLINE

All virtual servers, including those that are not associated with the BIG-IP ASM system, are unable to process traffic when the status is Offline.

Impact

Disabling or restarting the BIG-IP ASM service disables traffic processing for the entire device while the service is marked Offline. If the unit is part of a high-availability cluster, this behavior causes a failover event.

Recommended Actions

F5 recommends that you keep the default behavior so that the system automatically fails over during the BIG-IP ASM process failure. However, you can restore the previous behavior. To do so, perform one of the following procedures:

BIG-IP ASM 11.4.0 and later

Impact of procedure: A BIG-IP ASM process failure will no longer automatically trigger a failover event.

  1. Log in to the BIG-IP command line.
  2. Disable the ha-daemon monitor for the BIG-IP ASM bd process, by typing the following command:

    tmsh modify /sys daemon-ha bd running disabled

  3. Save the change by typing the following command:

    tmsh save /sys config partitions all


BIG-IP ASM 11.3.0 and earlier

In BIG-IP 11.3.0 and earlier, due to an issue with saving the running attribute of the daemon-ha component, you must manually add this setting to the daemon-ha configuration stanza for the bd process in the configuration file. For information about this issue, refer to K13677: The BIG-IP system fails to save the running attribute of the daemon-ha component to the configuration file. To manually add this setting to the configuration file, perform the following procedure.

Impact of procedure: A BIG-IP ASM process failure will no longer automatically trigger a failover event.

  1. Log in to the BIG-IP command line.
  2. Make a backup copy of the /config/bigip.conf file by typing the following command:

    cp -p /config/bigip.conf /config/bigip.conf.sol13484

  3. Edit the /config/bigip.conf file using a text editor of your choice.
  4. Add the following daemon-ha configuration stanza for the bd process. If there is already an existing stanza due to a certain customized setting, add the running disabled setting to the stanza.

    sys daemon-ha bd {
        running disabled
    }

  5. Save the changes and exit the text editor.
  6. Load the configuration from the modified configuration file by typing the following command:

    tmsh load sys config
