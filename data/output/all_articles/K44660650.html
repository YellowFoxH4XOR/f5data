Topic

You should consider using this procedure under the following condition:

  • You want to mitigate UDP flood traffic through the BIG-IP system using connection rate limit.

Description

UDP is a standard protocol for communication across IP networks, but, since UDP packets are stateless, they require less error checking and validation in contrast to TCP. A UDP flood attack attempts to overload a server with requests by saturating the connection tables on every accessible port on a server.

Filling the connection table with these requests prevents valid requests from being served, and the server can become inaccessible to valid clients.

The virtual server connection rate limit is native a native feature with an optimized configuration which, compared to an iRules Rate Limit configuration, has less impact on the BIG-IP CPU and memory resource utilization.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the Configuration utility.
  • You have access to the Advanced Shell (bash).

Procedures

  • Using the Configuration utility to determine the connection rate limit value applied to a virtual server
  • Using tmsh to determine the connection rate limit value applied to a virtual server
  • Using BIG-IP Analytics to determine the connection rate limit value applied to the virtual server
  • Using the Configuration utility to configure the connection rate limit

Using the Configuration utility to determine the connection rate limit value applied to a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Reviewing the output of the Virtual Server Maximum Connection value over time provides an idea how many connections the virtual server experiences during high traffic events. This may also capture unexpected traffic spike values, so you should periodically assess the output of these statistics.

  1. Log in to the Configuration utility.
  2. Navigate to Statistics > Module Statistics > Local Traffic.
  3. For Statistics Type, click Virtual Servers.
  4. Review the values in the Connections column:
    • Current represents the number of currently open connections to the virtual server.
    • Maximum represents the maximum number of concurrent connections to the virtual server.
    • Total - Represents the cumulative number of connections to the virtual server.

Using BIG-IP Analytics to determine the connection rate limit value applied to the virtual server

Note: You must have the BIG-IP Application Visibility and Reporting module provisioned on your system to use this procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Statistics > Analytics > Virtual Servers > UDP.
  3. Review the graphical view of the UDP connections processed by the virtual servers with the a UDP profile over time. The Avg Active Connections graph provides an idea on the possible value of the virtual server connection rate limit. The Max Active Connections graph provides information about the UDP traffic spikes the BIG-IP system has recorded.

Plotting the virtual server Current connection and Maximum connection statistics over time provides a possible value for the connection rate limit.

For example:

Connections - Normal traffic statistics

  • Current 500
  • Maximum 2000

Connections - Unexpected increase traffic statistics

  • Current 1000
  • Maximum 20000

The Normal traffic statistics virtual server connection statistic may benefit from a connection rate limit value of 3000. This setting accommodates the normal traffic connection of 500 and the normal maximum connection of 2000. It also allows a buffer of an additional 1000 connections for traffic increase that is acceptable for the virtual server being configured.

Similarly, for the unexpected increase of traffic, the connection rate limit value of 3000 limits the connections on the virtual server, which also depend on the connection rate limit mode.

If Connection Rate Limit Mode is set to Per Virtual Server, the sample Connection Rate Limit value of 3000 limits the connections for the virtual server.

If Connection Rate Limit Mode is set to Per Virtual Server and Source Address, the sample Connection Rate Limit value of 3000 rate limits for source IP address with connections sharing the same subnet. The source mask is configured through the Connection Rate Limit Source Mask configuration as follows:

  • 192.0.2.1/32 - Connection Rate Limit Source Mask is set to 0. Connection Rate Limit is applied to the individual IP address.
  • 192.0.2.0/24 - Connection Rate Limit Source Mask is set to 24 - Connection Rate Limit is applied to IP addresses with source mask of /24.

Using the Configuration utility to configure the connection rate limit

Impact of procedure: Applying an incorrect value for Connection Rate Limit will cause unexpected limiting of connections to the Virtual Server being configured. Ensure that the value that will be configured is acceptable per normal traffic pattern of the Virtual Server and will accommodate expected increase of traffic.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the virtual server you want to rate limit.
  4. Set Configuration to Advanced.
  5. Set the Connection Rate Limit value as appropriate.
  6. For Connection Rate Limit Mode, click the appropriate setting. For example Per Virtual Server and Source Address.
  7. Set the Connection Rate Limit Source Mask if applicable.
  8. Click Update.
