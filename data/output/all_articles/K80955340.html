Known Issue

The VIPRION system may fail to merge a string type iStat keyspace across blades.

This issue occurs when all of the following conditions are met:

  • You install the VIPRION system with more than one blade.
  • You manually create a customized string type iStat keyspace on the system.
  • The value of the affected iStat keyspace is subsequently modified using the istats set command.

Impact

The value of the affected iStat keyspace is not consistent across the blades.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • After you run the istats set command, a subsequent istats get command runs on all the blades at the same time and presents different values.

    For example:

    Using the cluster shell (clsh) with the istats get command to view the affected iStat keyspace, you may observe that the values of the iStat keyspace are different across the two blades.

    === slot 2 addr 127.3.0.2 color green ===
    A
    === slot 3 addr 127.3.0.3 color blue ===
    === slot 4 addr 127.3.0.4 color blue ===
    === slot 1 addr 127.3.0.1 color green ===
    B

Resolution

Status

F5 Product Development has assigned ID 513916 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. Workaround

To avoid this issue, you can use the clsh when you need to run the istats set command on a string type iStat keyspace on a VIPRION system with more than one blade.
