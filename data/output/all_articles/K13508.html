Known Issue

Description

ConfigSync operations may fail to complete between device group members. This issue is caused by master key variations on the affected units.

This issue occurs when the following condition is met:

  • You performed an action that affected the master key on one or more device group members. For example, one of the following actions might have affected the master key on a BIG-IP device group member:
    • You added a passphrase encrypted SSL key to a BIG-IP device group member.
    • You imported a passphrase protected SSL key to one or more device group members.

Impact

You are unable to synchronize configuration objects to the device group.

 

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • ConfigSync operations fail to complete and generate messages that appear similar to the following example:

    Sync Failed
    Remote sync validation error

  • The system logs messages to the /var/log/ltm file that appear similar to the following example:

    01071027:5: Master key OpenSSL
    error: 5441:error:06065064:digital envelope routines:EVP_DecryptFinal_ex:baddecrypt:evp_enc.c:337:

Workaround

To work around this issue, you can replace the master key on all hosts in the device group. To do so, perform the following procedure:

Replacing the master key

Impact of workaround: None

  1. Select a passphrase as your master key. This passphrase should be long and contain both numbers and symbols.
  2. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.
  3. Type the following command:

    modify /sys crypto master-key prompt-for-password

  4. When prompted, enter your selected passphrase.
  5. Save the change by typing the following command:

    save /sys config

    Note: Saving the configuration automatically re-encrypts any encrypted-SSL-key passphrases, using the new master key, prior to saving them in the configuration file.

  6. Using the same passphrase, repeat the previous steps on each host in the device group.
  7. After all host master keys are updated, re-synchronize the BIG-IP hosts.
  8. After the BIG-IP hosts have been re-synchronized, back up the BIG-IP configuration files using the Configuration utility, or by using the following command syntax:

    tmsh save /sys ucs <path/to/UCS>

    Note: In configurations that contain encrypted-SSL-keys passphrases, this step ensures that you have a UCS file that you can restore using the new master key. If you want to load a UCS file that was created before you changed the master key, refer to K9420: Installing a UCS file containing an encrypted passphrase
