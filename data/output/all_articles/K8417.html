K8417: The User Session Lockout setting is not recognized by cluster load balancing

Topic

FirePass controllers can be configured to disallow new logins using the User Session Lockout feature. When the Lockout new user sessions check box is selected on the Device Management: Maintenance: User Session Lockout page, users attempting to load the login page of the FirePass controller will receive a web page with the text configured in the Default lockout message text box.

In a FirePass cluster, if a secondary node is configured to lock out new user sessions, the primary node will not be aware of the lockout configured on the secondary, and continue to send sessions to the secondary node if the primary is performing random load balancing. Users who are redirected to the unavailable secondary FirePass controller can reload the main URL for the FirePass cluster until they are placed on an available node in the cluster.

Note: The information presented on clustering in this Solution applies only to FirePass clusters using the native FirePass software clustering. This information does not apply to FirePass clusters load balanced using SSL offload with F5 Networks Local Traffic Manager.

Alternatively, the FirePass administrator can select the Allow optional manual logon to slave nodes from primary logon page check box on the Clustering: Settings page, and allow the users to choose the secondary node.

Another possibility is to force the cluster primary node to mark the secondary node as down, as displayed on the Clustering: Stats page.  When this occurs, the cluster primary stops redirecting logins to the secondary in the down state. To do this, you may set the Synchronization Interval to a high time value (the setting is measured in units of seconds) on the secondary node. The default synchronization interval is 30 seconds. When the cluster primary node does not receive a synchronization from a secondary for 300 seconds, the primary will mark the secondary node as down. Setting the interval to 100000 seconds, for example, will cause the secondary to be marked as a down node, and allow an administrator to perform maintenance on a running secondary node while users are not directed to it by the cluster primary node. Once maintenance is complete, the synchronization interval can be reset to the identical value of the other members of the cluster.  For more information about the mechanism by which a cluster secondary is taken offline by the cluster primary node, refer to K8409: Conditions for the cluster primary node to mark a secondary node down.

Changing the synchronization interval

Note: Changing the synchronization interval requires a soft reboot to take effect.

To change the synchronization interval, perform the following procedure:
  1. Log in to the Administrative Console of the secondary node which needs to disallow user logins.
  2. Click Device Management.
  3. Click Configuration.
  4. Click Clustering and Failover.
  5. Under the Cluster Synchronization Time Interval section, enter a number of seconds large enough to encompass your maintenance window.
  6. Click the Apply Clustering/Failover Settings button at the bottom of the page.
  7. When prompted to restart, click the link to restart the services.

    The FirePass controller secondary node will reboot.

On the primary node, the secondary will be marked down, and users will not be redirected to the secondary node.  When your maintenance is finished, use the procedure to reset the synchronization interval to the same as that on the primary node.
