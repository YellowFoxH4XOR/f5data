This article provides a general summary of the BIG-IP upgrade process and includes recommendations and considerations for planning a BIG-IP software upgrade. You can use this article as a guide to create an upgrade checklist for your specific upgrade scenario.

For detailed steps on preparing and upgrading BIG-IP systems, refer to the BIG-IP Upgrade guide:

  • K84205182:  BIG-IP update and upgrade guide | Chapter 1: Guide contents 

Keeping your BIG-IP installation up to date is critical to maintaining a healthy and secure system. F5 recommends that you upgrade your BIG-IP to the most recent maintenance and point release for BIG-IP 17.1.x.

Important: BIG-IP 15.1.x reached the End of Life (EoL) milestone on December 31, 2024.  BIG-IP 16.1.x reached EoL on July 31, 2025.  For additional information, refer to K000139937: BIG-IP 15.1.x and 16.1.x are reaching End of Technical Support and K5903: BIG-IP software support policy.

Prepare for a software upgrade

Successfully upgrading the BIG-IP system requires some planning and preparation, such as checking the current health of the system and backing up the configuration to a safe place on your network. Some steps are optional, but recommended, to ensure a better experience. Before you perform your software upgrade, F5 recommends that you make the preparations in the following table.

For complete details about preparing for a software upgrade, refer to K02693745: BIG-IP update and upgrade guide | Chapter 4: Prepare to update or upgrade the BIG-IP system.

HA recommendations

When you upgrade a high availability (HA) device group, take steps to maintain HA during the upgrade process. To do so, F5 recommends the following practices.

RecommendationDetailsResource
Upgrade the standby system first.When you upgrade a device group, F5 recommends that you upgrade the standby system first, and then boot it to the newly upgraded boot location. After you verify that the configuration loaded properly, you can force a failover to the newly upgraded system. Then, if traffic is flowing as expected, you can repeat the upgrade steps on the next system, which is now in standby mode.
  • K8665: BIG-IP redundant configuration hardware and software parity requirements.
Use network failover for the duration of the upgrade process.HA communication functions between major software branches using network failover. For example, a pair of BIG-IP systems running BIG-IP 15.1.2 and BIG-IP 16.0.1 can negotiate active-standby status using network failover.
  • K8665: BIG-IP redundant configuration hardware and software parity requirements.
Do not perform Configuration synchronization (ConfigSync) during the upgrade process.ConfigSync does not operate between different software branches. For example, you cannot synchronize configurations from a system running BIG-IP 15.1.2 to a system running BIG-IP 16.0.1. You must wait for both systems to upgrade and match the version numbers before the systems can use ConfigSync.
  • K13946: Troubleshooting ConfigSync and device service clustering issues.
If used, disable VLAN fail-safe for internal or HA communication between BIG-IP units.Not performing this step may trigger the VLAN fail-safe mechanism, causing the active BIG-IP to failover to the BIG-IP being upgraded, which might cause an outage. 
  • K000152325: Unexpected Failover of Active Unit to Standby During Upgrade
Disable the Automatic Sync.If enabled, in the Sync Type list, disable Automatic Sync for the device group to prevent any sync failures that may occur in the middle of an upgrade, when the device group devices run different versions.
  • Device Management > Device Groups.
  • tmsh cm modify device-group <device_group> auto-sync
(Optional) Set the standby BIG-IP system offline.For non-VIPRION systems, after you upgrade and before you reboot to the upgraded volume, it is good practice to set the Force Offline option. Doing so prevents the standby system from potentially becoming active and disrupting traffic in the process. After the BIG-IP reboots into the new boot location and loads the configuration, the system remains forced offline. At this point in time, check the output of tmsh show cm traffic-group on each BIG-IP. If they both agree that one is active and the other is forced offline, then it is likely that they will not go Active-Active after you release the BIG-IP from offline.
  • K15122: Overview of the Force Offline option for devices and traffic groups.

Upgrade vCMP hosts and guests independently of one another, and plan the order for host/guest upgrades according to the following guidance:
  • Plan the order for host/guest upgrades:
    • For vCMP host/guest compatibility, refer to K14088: vCMP host and compatible guest version matrix.
    • If you are upgrading the vCMP system to a version that would temporarily result in the vCMP host and guest running incompatible versions, F5 recommends that you upgrade the guest instance first and then activate the boot location for the newly upgraded guest. Next, on the vCMP host, set the upgraded guest to the Provisioned state. You can then safely upgrade the vCMP host to the new, compatible version. Once you have rebooted the host to the new version, set the vCMP guest to Deployed.
    • For other cases, F5 recommends that you upgrade the host first.

  • K44722602: Installing software image saved on vCMP host machine to vCMP guests.
Upgrade one vCMP guest, per slot, at a time.To avoid excessive disk and CPU usage, upgrade one vCMP guest, per slot, at a time. You can upgrade guests on separate slots at the same time.
  • K13748: Maintaining host resources when upgrading vCMP guests.
If you need to reactivate the license, reactivate it on the vCMP host only.Each guest inherits the license of the vCMP host, and the host license includes all BIG-IP modules available for use with vCMP guest instances. If you need to reactivate the license, reactivate it at the vCMP host only.

  • K15930: Overview of vCMP configuration considerations.

Upgrade the BIG-IP system

F5 suggests you upgrade the software on your BIG-IP appliances and VEs to optimize the security, performance, and total cost of ownership of your BIG-IP systems. At a minimum, F5 recommends that you upgrade your BIG-IP appliances to at least BIG-IP 14.1 and your BIG-IP VEs to at least BIG-IP 15.1.

Choose a volume for the installation

You must choose a volume for the BIG-IP installation. Multiple software installations can exist on the BIG-IP system, but only one is active. You can install the new version or hotfix to an existing volume, overwriting the currently installed software version for that volume, or to a new, empty volume that you create during installation. You can install software only on inactive volumes. To install software to the active volume, you must boot to a different volume.

RecommendationDetailsResource
Choose to install to an existing volume and overwrite...If you want to upgrade a BIG-IP version that is currently installed on an inactive volume and overwrite the existing installation.
  • System > Software Management > Image List.
  • tmsh show /sys software status
Choose to install to new volume...If you want to maintain the BIG-IP version that is currently installed on the inactive volume and perform the installation on a new volume.

Note: If there is not enough disk space to install a new BIG-IP software volume, you can delete an existing software volume to gain free space.

    Perform a clean software installation

    Optionally, you can perform a clean installation using a prepared USB mass storage device. This method wipes all data on the system and restores the BIG-IP system to factory defaults. After you complete this process, you can load a previously saved UCS archive to restore the configuration.

    RecommendationDetailsResource
    Consider performing a clean installation under any of the conditions in the Details column.
    • You want to completely reinstall a BIG-IP device by wiping all mass-storage devices and performing a clean installation from an installation ISO file.
    • You have a device that still boots to a boot location, and you want to perform a clean installation from an ISO file saved to the system.
    • You have a device that no longer boots from any of its boot locations, and you want to reinstall using one the methods in the article in the Resource column.
    		K13117: Performing a clean installation of BIG-IP 11.x - 16.x.

    Import the BIG-IP configuration

    By default, during the upgrade process, the BIG-IP system imports the current, running configuration from the active volume into the target volume. Using the Configuration utility, you can change the import options by going to System > Software Management > Boot Locations > <boot location name>, and configuring Install Configuration. F5 recommends using the import actions as described in the following table.

    RecommendationDetailsResource
    Set Install Configuration to No...If you have not made any configuration changes between the time you have installed an upgrade and boot into the volume, set Install Configuration to No. The software install process automatically installs the configuration from the currently active boot volume, by default, at the time of software install. The default option is No.
    • K64400324: Should I use Install Configuration when activating a new Boot Location?
    • K13438: Controlling configuration import when performing software installations.
    Set Install Configuration to Yes...If you modified the BIG-IP configuration after you installed the upgrade, set Install Configuration to Yes. For example, if you installed the upgrade and then added a new virtual server, setting the option to Yes updates the target software volume with the new virtual server configuration before you start the system.
    Note: This option is not available on VIPRION platforms or clustered vCMP guests.
    • K14704: Installing a configuration when activating a boot location.

    Verify the upgrade

    After you complete the upgrade process, verify that the expected local traffic objects are present and passing traffic. For HA environments, plan to move the upgraded system to Active state and verify client traffic.

    Check and test your upgrade

    RecommendationDetailsResource
    Allow enough time for the system to boot to the new volume.The first time you restart and boot to the new volume after the installation, the process can take up to 30 or more minutes, depending on the size of the configuration. If the installation fails, the tmsh load /sys config command may show an error, which helps troubleshooting.
    • K02091043: Error Message: The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.
    Confirm that the expected local traffic objects are present.Confirm virtual server status and verify that the pool health status matches other BIG-IP systems in an HA configuration.
    • Local Traffic > Network Map.
    • Local Traffic > Pools.
    • Local Traffic > Virtual Servers.
    Confirm that the expected network objects are present.Confirm network status and verify that the expected VLANs and interfaces are present, and that the interfaces are up.
    • Network > VLANs.
    • Network > Interfaces.
    • Network > Self IPs.
    • Network > Trunks.
    Move the upgraded system to Active state.Force the active BIG-IP system into Standby mode to move the upgraded system to the Active state.
    • K15455872: Forcing an active BIG-IP system into standby mode using tmsh.
    Verify client traffic to the upgraded BIG-IP system.Test the client traffic to the upgraded BIG-IP system to confirm that the system is processing traffic, as expected.
    • Use a web browser or a command line utility, such as cURL, to test client traffic to the site.

    Back out your software upgrade

    If a BIG-IP system fails to upgrade, and you cannot perform further troubleshooting due to time constraints, complete the following steps before reverting to the previous BIG-IP version.

    Note: If you do not perform troubleshooting before reverting changes, it may be difficult to determine a root cause for failure. If possible, contact F5 Support while the issue is occurring so you can perform relevant data gathering, such as creating a new QKView file.

    RecommendationDetailsResource
    Gather troubleshooting information.If you rebooted to the upgraded volume, you can determine what is causing the configuration load error by reviewing the log files and attempting to load the configuration.
    • K16197: Reviewing BIG-IP log files.
    • tmsh load /sys config
    Diagnose your system using qkview.Use the qkview utility to create a QKView diagnostics file, and upload it to F5 iHealth to help diagnose the problem.
    • K12878: Generating diagnostic data using the qkview utility.
    Reboot back to a previous software version.If you are not able to identify the issue with the upgraded volume, use the Configuration utility or tmsh to boot back to a previous software version.
    • System > Software Management > Boot Locations.
    • tmsh reboot volume <volume name>
