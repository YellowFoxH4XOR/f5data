Known Issue

A system reboot may not properly reset the CPU Time Stamp Counter (TSC).

This issue occurs when all of the following conditions are met:

  • The system is restarted with a warm/soft reboot.
  • This issue affects the following platforms, which have the affected Intel Xeon E5/E5v2 processors:

    • BIG-IP 10000 series platforms
    • VIPRION 2250 blade
    • Some non-F5 hypervisors (VMware, XenServer, and Linux KVM) hosting BIG-IP Virtual Edition (VE) guests or Enterprise Manager VE guests

      Note: This issue does not occur on Microsoft Hyper-V.

Impact

Affected systems may be unstable, possibly hang, or encounter a divide-by-zero panic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H500894 on the Diagnostics > Identified > High screen.
  • An affected platform may be unstable, possibly hang, or encounter a divide-by-zero panic.
  • An affected platform may exhibit various soft lockup symptoms very early in the warm/soft boot process.

Note: This is an intermittent issue.

Workaround

To work around this issue, instead of performing a warm/soft reboot, you can perform a cold/hard reboot by power cycling the system or by powering off/on the host subsystem using the Always-On Management (AOM) Command Menu. If powering off/on the subsystem in AOM is unsuccessful, you can use the R option in the AOM to perform a hardware reset.

For information about accessing the AOM Command Menu, refer to K14594: Accessing the AOM Command Menu.

Note: For BIG-IP VE guests or Enterprise Manager VE guests hosted on an affected non-F5 hypervisor, performing a cold reboot does not mitigate this issue. The affected hypervisor must be power cycled in order to properly reset the CPU TSC. Consult your hypervisor manual for more information and instructions.
