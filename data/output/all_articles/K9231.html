Topic

The BIG-IP system monitors the heartbeat signal of certain daemons that are critical for traffic processing and takes a failsafe action if the system detects a daemon heartbeat failure.

Description

Daemon heartbeat signals are recurring signals that the BIG-IP system monitors to ensure critical daemons are running. When a daemon's heartbeat signal is not received within the configured timeout period, the BIG-IP system performs a failsafe action and logs an error message to assist with troubleshooting. You can review the following topics to better understand daemon failsafe and if necessary, modify the BIG-IP system daemon heartbeat failsafe configuration.

  • Monitored daemons
  • Module specific daemons
  • Failsafe event log messages
  • View the failsafe configuration

Failsafe actions

The following table lists and describes the possible failsafe actions.

ActionDescription
RestartThe system restarts this system service
Restart All*The system restarts all system services
Reboot*The system reboots
Go Offline*The system goes offline
Go Offline Abort TM*The system goes offline and forces a core of the traffic management service before restarting it
Fail Over & Restart TM*The system fails over to the peer unit and restarts the traffic management service
Go Offline & Restart*The system goes offline and restarts the service
Go Offline & Down Links & restart*The system goes offline, brings down all links, and restarts the service
No ActionThe system takes no action

Note: For BIG-IP systems in a high availability (HA) configuration and Active for one or more traffic groups, this action will also cause a failover event.

Failsafe event log messages

When the BIG-IP system performs a failsafe action, to assist with troubleshooting, it logs a message to the /var/log/ltm file that appears similar to the following example:

01140029:5: HA daemon_heartbeat <daemon_name> fails action is restart.

For example, if the Traffic Management Microkernel (TMM) does not send a heartbeat signal within the two-second timeout period, the BIG-IP system performs a failsafe action and logs the following error message:

01140029:5: HA daemon_heartbeat tmm fails action is restart.

View the failsafe configuration

You can use the Configuration utility or TMOS Shell (tmsh) to view the current BIG-IP system daemon heartbeat configuration. Only tmsh allows you to view the configured timeout period. To view the BIG-IP system daemon failsafe configuration, perform one of the following procedures:

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > High Availability > Fail-safe > System.
  3. Under Name, select the monitored daemon.

tmsh 

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To list the failsafe configuration for a specific daemon, use the following command syntax:

    list sys daemon-ha <name> all-properties

    For example, to list the current failsafe configuration for the tmm daemon, enter the following command:

    list sys daemon-ha tmm all-properties

    The command output appears similar to the following example:

    sys daemon-ha tmm {
        description none
        heartbeat enabled
        heartbeat-action go-offline-downlinks-restart
        not-running-action go-offline-downlinks
        running enabled
        running-timeout 2
    }

    Note: The running-timeout value, which is different from the hard-coded heartbeat timeout, specifies how long a daemon can be absent from the process list before the not-running-action is initiated.

Modify the failsafe configuration

You can use the either the Configuration utility or tmsh to modify the BIG-IP system daemon heartbeat configuration. To modify the BIG-IP system failsafe configuration, perform one of the following procedures:

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > High Availability > Fail-safe > System.
  3. Under Name, select the monitored daemon.
  4. For Heartbeat, select either Enabled or Disabled.
  5. For Heartbeat Failure Action, select one of the available actions.

tmsh 

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the failsafe configuration for a specific daemon, use the following command syntax:

    modify sys daemon-ha <name> heartbeat <enable|disable> heartbeat-action <failsafe_action>

    For example, to change the failover action for the tmm daemon to reboot, enter the following command:

    modify sys daemon-ha tmm heartbeat-action reboot

  3. To save the configuration, enter the following command:

    save sys config

Troubleshoot daemon failsafe events

If a daemon fails to increment its heartbeat signal within the timeout period, it is often related to system resource issues. You can troubleshoot the issue by checking the following:

  • Review system log files

    Verify which daemon caused the failover action by reviewing the /var/log/ltm file. Locate the HA daemon_heartbeat message and review any relevant logging messages that occurred prior to the heartbeat failure. For assistance with reviewing BIG-IP system log files, refer to K16197: Reviewing BIG-IP log files.

  • Check for a daemon core file

    Determine whether the daemon produced a core file by checking the /var/core or /shared/core directory, and submit the core file to F5 Technical Support. For assistance with submitting core files, refer to K000090853: Exchange files with F5 Support using MyF5.

  • Check for system resource-related issues

    You can check for system resource-related issues by running commands, such as the top command. For assistance running the top command, refer to K16739: Understanding 'top' output on the BIG-IP system.

  • View the system HA table

    You can check the HA status of various processes by viewing the HA table from the command line. You can view the HA table by running the following tmsh command:

    tmsh show sys ha-status all-properties
