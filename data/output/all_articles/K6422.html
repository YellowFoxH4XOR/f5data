Known Issue

Note: This Solution only discusses a particular issue that arises when using the Stream profile to search and replace all occurrences of a string in HTTP responses. F5 recommends that you also refer to K8115: Overview of the Stream profile for a complete overview of the Stream profile.

This is the result of a known issue. The Stream profile performs a search and replace for all occurrences of a string in a data stream, and performs the search and replace with minimal buffering.

Using the Stream profile for string replacement of HTTP traffic can cause the BIG-IP system to alter the length of the HTTP content, and to not update the HTTP Content-Length header correctly. This issue causes a mismatch between the actual HTTP payload, and the specified Content-Length in the HTTP response header from the server. As a result, the client does not display all of the HTTP data for a request.

F5 Product Development tracked this issue as CR53771 and it was fixed in BIG-IP version 9.4.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

In cases where the HTTP responses from the server contain a Content-Length header, you can work around this issue by setting the chunking method to rechunk in the HTTP profile. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click the appropriate HTTP profile you are using with the Stream profile.
  5. Under Settings, choose Rechunk from the Response Chunking drop-down menu.
  6. Click Update.
