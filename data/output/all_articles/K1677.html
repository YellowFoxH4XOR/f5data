Topic

Note: For BIG-IP versions 9.x and later, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

Important: This solution applies only to 3-DNS when the 3-DNS Controller is used as part of a redundant pair. UCS files are never synchronized in the same way as other 3-DNS information is synchronized.

The BIG-IP and 3-DNS configuration database includes a number of keys that control which files are included in a UCS archive.

These keys are formatted as follows:

Common.Bigip.CS.sync.<id>.<attribute> = 'value'
Common.Bigip.CS.file.<id>.<attribute> = 'value'
Common.Bigip.CS.run.<id>.<attribute> = 'value'

The <id> field is a three-digit number that determines the processing order of the attributes for sync, save, and run actions. The <id> number needs to be the same in any set of keys that refer to the same file.

The attribute field specifies the action that is taken on the file and can be any of the following values.

  • file
  • dir
  • ignore
  • local
  • backup
  • recursive
  • begin
  • save_pre
  • save_post
  • inst_pre
  • and inst_post

The attributes are defined in the following table:

AttributeDescriptionPossible ValuesDefault Value
fileThe name of a file to perform an action onPath and file namenone
dirThe name of a directory to perform an action onPathnone
ignoreFiles to ignore (perform no actions)Path and file name or regular expressionnone
localDefines whether the file exists locally or on the peer unit<yes|no>no
backupControls whether or not the file is included in UCS archives<yes|no>no
recursiveDefines whether or not to act on files in sub-directories<yes|no>yes
beginDefines a script to run*Path and script namenone
save_preDefines a script to run before backing up the file*Path and script namenone
save_postDefines a script to run after backing up the file*Path and script namenone
inst_preDefines a script to run before restoring the file*Path and script namenone
inst_postDefines a script to run after restoring the file*Path and script namenone

* All scripts and commands must redirect any output to stderr instead of stdout, or they will cause problems when the sync command is invoked from the command line or the Configuration utility.

Examples

Following is an annotated copy of the bigdb keys used on a BIG-IP version 4.2 to illustrate basic configsync and configsync all functions. Output from other BIG-IP versions may vary from this example.

Priority 100 (Save and Run commands)

In the priority 100 section the file /config/bigip.conf is saved into the UCS and installed.

The .save_post command removes the temporary file after it is loaded.


Common.Bigip.CS.run.100.file = '/tmp/bigip.conf'

Common.Bigip.CS.run.100.inst_post = '(bigpipe load /tmp/bigip.conf 1>&2)'

Common.Bigip.CS.run.100.save_post = '(rm -f /tmp/bigip.conf)'

Common.Bigip.CS.run.100.save_pre = '(bigpipe save /tmp/bigip.conf 1>&2)'

Common.Bigip.CS.save.100.backup = 'yes'

Common.Bigip.CS.save.100.file = '/config/bigip.conf'

Common.Bigip.CS.save.100.inst_pre = 'cs_backup_remote'

Priority 100 (Sync command)

Priority 100 is the sync section with the command bigpipe config sync, the file /config/bigip.conf is saved to a UCS, and installed on the remote system.


Common.Bigip.CS.sync.100.backup = 'yes'

Common.Bigip.CS.sync.100.file = '/config/bigip.conf

Common.Bigip.CS.sync.100.inst_post = '(bigpipe load 1>&2)'Priority 101

Priority 101

In the priority 101 section the file /config/bigip_base.conf is backed up, but not copied over or installed, since it is marked as a local file.


Common.Bigip.CS.save.101.backup = 'yes'

Common.Bigip.CS.save.101.file = '/config/bigip_base.conf'

Common.Bigip.CS.save.101.local = 'yes'

Priority 104 and Priority 110

In the priority 104 and 110 section, the local files are backed up.


Common.Bigip.CS.save.104.file = '/config/default_base.conf'

Common.Bigip.CS.save.104.local = 'yes'

Common.Bigip.CS.save.110.file = '/config/bigip.license'

Common.Bigip.CS.save.110.local = 'yes'

Priority 120

In the priority 120 section, the /config/user.db file is ignored, so it is excluded from the backup and install process. The bigdb key is saved as the file /config/user.txt, which is saved and installed with the db_load command, and then the file is removed. The DB is saved as the file /config/user.txt, which is saved and installed with the db_load command, and then the file is removed.


Common.Bigip.CS.save.120.file = '/config/user.txt'

Common.Bigip.CS.save.120.ignore = '/config/user.db'

Common.Bigip.CS.save.120.inst_post = 'db_load'

Common.Bigip.CS.save.120.save_post = '(rm -rf /config/user.txt)'

Common.Bigip.CS.save.120.save_pre = '(bigpipe db dump /config/user.txt)'

Priority 160

In the priority 160 section, the BIG-IP runs the script /usr/local/lib/pingers/cs_eav_backup, and saves the health monitors in /var/tmp/cs_eav_tmp, which is then saved in the UCS, and installed with the script cs_eav_restore.


Common.Bigip.CS.save.160.dir = '/var/tmp/cs_eav_tmp'

Common.Bigip.CS.save.160.inst_post = 'cs_eav_restore'

Common.Bigip.CS.save.160.save_post = '(rm -rf /var/tmp/cs_eav_tmp)'

Common.Bigip.CS.save.160.save_pre = '/usr/local/lib/pingers/cs_eav_backup'

Priority 2xx

In the priority 2xx section the /config directory (including all subdirectories, but excluding the files and regular expression matches in the ignore commands) is backed up.

The openssl.conf file is local, so it is saved but not synced to the peer unit. The SSL certificates are saved to a temporary directory and installed with the scripts shown.


Common.Bigip.CS.save.200.dir = '/config'

Common.Bigip.CS.save.200.ignore = '(/config/.*[^/]*.backup$)'

Common.Bigip.CS.save.201.ignore = '/config/monitor_examples'

Common.Bigip.CS.save.210.file = '/config/bigconfig/openssl.conf'

Common.Bigip.CS.save.210.local = 'yes'

Common.Bigip.CS.save.214.ignore = '(/config/bigconfig/.*.tmpl$)'

Common.Bigip.CS.save.215.ignore = '(/config/bigconfig/.*.pristine$)'

Common.Bigip.CS.save.220.ignore = '(/config/bigconfig/ssl.crt/.*)'

Common.Bigip.CS.save.221.ignore = '(/config/bigconfig/ssl.key/.*)'

Common.Bigip.CS.save.222.ignore = '/config/bigconfig/httpd.conf'

Common.Bigip.CS.save.223.dir = '/var/tmp/cert_temp'

Common.Bigip.CS.save.223.inst_post = 'cert_inst_post'

Common.Bigip.CS.save.223.save_post = '(rm -rf /var/tmp/cert_temp)'

Common.Bigip.CS.save.223.save_pre = 'cert_save_pre'

Priority 7xx

In the priority 7xx section, user defined files are stored to avoid conflicts with future BIG-IP internal files. These user defined files are typically not saved in the /config directory during synchronization.


bigpipe db set 'Common.Bigip.CS.save.700.file = /home/string.class'

bigpipe db set 'Common.Bigip.CS.sync.700.file = /home/string.class'

Priority 8xx

In the priority 8xx section, the version information is updated to verify that the same version of BIG-IP was used to create and install the UCS.


Common.Bigip.CS.save.898.inst_pre = '(rm -f /config/ucs_version)'

Common.Bigip.CS.save.899.inst_post = '(/usr/local/lib/ucs_convert/fixup 1>&2)'

Common.Bigip.CS.save.899.inst_pre = '(rm -f /tmp/ucs_convert)'

Common.Bigip.CS.save.899.save_pre = '(cp -f /VERSION /config/ucs_version)'

Priority 9xx

In the priority 9xx section, the peer BIG-IP is instructed to load the new configuration files, new system variables, and reinitialize the system.


Common.Bigip.CS.save.900.inst_post = '(bigpipe load 1>&2)'

Common.Bigip.CS.save.901.inst_post = '(/bin/sh /etc/rc.sysctl)'

Common.Bigip.CS.save.999.inst_post = '(bigstart cs_reinit)'

Priority 100

Priority 100 is the sync section with the command, bigpipe config sync, the file /config/bigip.conf is saved to a UCS, and installed on the remote system.


Common.Bigip.CS.sync.100.backup = 'yes'

Common.Bigip.CS.sync.100.file = '/config/bigip.conf'

Common.Bigip.CS.sync.100.inst_post = '(bigpipe load 1>&2)'
