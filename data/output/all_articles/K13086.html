Known Issue

SMB traffic may bypass VPN tunnel when split tunneling is disabled.

This issue occurs when all of the following conditions are met:

  • Force All Traffic is enabled on the BIG-IP APM system or the FirePass Controller.
  • The user's operating system is Windows Vista or later.
  • The user establishes a connection to a file share before starting a Network Access session.
  • The IP address of the file share server routes to the user's default route, rather than to the VPN default route.

Starting in Windows Vista, changes made to the TCP/IP stack to enforce Strong Host Model routing can affect routing for VPN traffic. When the user encounters this issue, Network Access users who access a file share using SMB may attempt to connect to the resource directly, rather than routing through the BIG-IP APM system or FirePass controller. The expected behavior is for all Network Access traffic to route through the BIG-IP APM system or FirePass controller, unless split tunneling has been configured on the BIG-IP APM system or FirePass controller.

Impact

Users may be unable to access the resource they want.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Users may receive network timeout errors if the resource is not available from the Internet.
  • The SMB File Share server will show a session directly from the client IP address.
  • The client will show a session directly connected to the file share server IP address.
  • No traffic will be seen on the BIG-IP APM or FirePass Controller between the client and server.

Workaround

To work around this issue, you can either enable IP filtering or add a route for 0.0.0.0 to your client's routing table. The Integrated IP filtering engine option isolates the VPN traffic from outside traffic (traffic generated by network devices on the clients LAN) and it ensures that the VPN traffic is not leaked to the client's LAN. Alternatively, you can enable split tunneling and configure a route for 0.0.0.0/0.0.0.0. This will force all traffic from the client through the VPN tunnel. Split tunneling is generally considered the weaker security position. However, by adding a route for only 0.0.0.0 for split tunneling, all traffic will use the VPN tunnel and the risk is mitigated. To do so, perform one of the following two procedures for either the BIG-IP system or FirePass controller:

Impact of workaround: None

Important: You should complete only one of the workaround procedures. If you have both the Integrated IP filtering engine and Use split tunneling for traffic enabled options, the user may experience network connection failures after login.

FirePass

To enable IP filtering or add a route for 0.0.0.0 to your client's routing table, perform one of the following procedures:

Enabling IP filtering

  1. Log in to the FirePass Administrative Console.
  2. Navigate to the Network Access : Resources : Client Settings tab.
  3. Ensure that Allow local subnet access is not selected.
  4. Click the Policy Checks tab.
  5. Select the Enable integrated IP filtering engine option.

Adding a route for 0.0.0.0

  1. Log in to the FirePass Administrative Console.
  2. Navigate to Network Access : Resources : Client Settings tab.
  3. OPTIONAL: In the Connection name field, enter a name that the end user will see in the Favorites. If the Connection name box is empty, the link to Network Access coming from a given Resource group will be hidden.
  4. Enable Use split tunneling for traffic.
  5. In the LAN address space field, enter the following:

    0.0.0.0/0.0.0.0

  6. Click Update.

BIG-IP

To enable IP filtering or add a route for 0.0.0.0 to your client's routing table, perform one of the following procedures:

Enabling IP filtering

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Policy > Network Access > Network Access List.
  3. Click the Network Access resource you want to update.
  4. Click Network Settings.
  5. In the Client Side Security section, select Integrated IP filtering engine.

    Note: This step will automatically enable the Allow access to local DHCP server option. Clear this option if you do not want users connecting directly to a DHCP server.

  6. Click Update.

Adding a route for 0.0.0.0

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Policy > Network Access > Network Access List.
  3. Click the Network Access resource you want to update.
  4. Click Network Settings.
  5. In the Traffic Options section, enable the Use split tunneling for traffic option.
  6. In the LAN Address Space section, enter 0.0.0.0 in the IP address field.
  7. In the LAN Address Space section, enter 0.0.0.0 in the Mask field.
  8. Click Add.
  9. Click Update.
