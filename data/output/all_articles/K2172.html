K2172: HTTP header formatting problems that may cause rules, cookie persistence, or other delayed binding features to fail

Topic

HTTP communication between a client and the server consists of two parts: the Header, which contains communication control information, and the Body, which contains the content of the message. A blank line is used to indicate where the Header ends and the Body begins.

A blank line in HTTP communication consists of two characters, a Carriage Return (CR) followed by a Line Feed (LF). This is typically represented in text as CRLF or CR/LF. This blank line is required for effective HTTP communication.

The most common reason for a rule to fail is because it contains an incorrectly formatted POST or GET string that does not contain the required blank line. If the BIG-IP rules engine does not see a closing CR/LF, the rule will never finish. This will cause the rule to fail.

In this sample GET string output, the CR is represented in HEX with an 0d (marked in bold) and the LF is represented with an 0a (marked in bold). The last 0d0a marks the end of the Header. Notice how the dual CRLF combination marks the end of the headers. If the second 0d0a was not present, the BIG-IP rules engine would not know that the Header was complete and the rule would fail. Cookie persistence requires the same HTTP formatting and will also fail if the string is incorrectly formatted in this manner.

Note: For more information about HTTP specifications and requirements, refer to: RFC1945, RFC2068, and RFC2616.
