Description
After upgrading to 12.0.0 or later, you may notice your BIG-IP DNS configuration containing two GSLB pools with the same name; one type A and one type AAAA.

Environment

  • GSLB Pools configured with either at least one IPv4 and IPv6 member
  • GSLB Pools configured with no members at all

Cause

In versions prior to BIG-IP 12.0.0, BIG-IP DNS wide IPs answered DNS queries for the following record types:

  • A
  • AAAA
  • CNAME

Beginning in BIG-IP 12.0.0, BIG-IP DNS wide IPs answer DNS queries for the following additional record types:

  • MX
  • SRV
  • NAPTR

MX, SRV, and NAPTR records provide a different type of data than A, AAAA, and CNAME records. To better accommodate the different data types, GSLB pools and WideIP are now configured for each specific record type.

Prior to version 12.0.0, a pool could contain A and AAAA members along with CNAME records. In version 12.0.0 and later each record type must be in a distinct pool of that type. If during upgrade the GSLB pool is found to have mixed membership then a new pool with the same name is created for each of the record types. If during upgrade the pool is found to have zero members the type of the pool cannot be determined so both an A and AAAA version are created.

Recommended Actions

None

Additional Information

Note that if any GSLB pools which match the above criteria were associated with WideIPs prior to the upgrade, a version of each WideIP is also created, corresponding to the pool(s) created post upgrade. For example, a GSLB pool converted into an A and AAAA pool would have both an A and AAAA WideIP.
