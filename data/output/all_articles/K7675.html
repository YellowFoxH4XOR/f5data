Known Issue

This is a result of a known issue. The bigd process is responsible for handling the monitoring duties of the BIG-IP LTM nodes. When the bigd process handles deferred or failed SSL connections associated with an HTTPS monitor, it can crash.

Deferred SSL connections are connections where the bigd process has issued a close or FIN request for the connection, but the node has not responded to the request with its own close request. This behavior can lead to the bigd waiting up to 300 seconds before forcefully closing the connection. As a result, the bigd uses system resources until it is able to close the connection.

A failed shutdown of SSL connection is a connection where bigd was unable to successfully shut down the SSL connection between the BIG-IP LTM system and the node. As a result, the bigd process uses system resources until it is able to close the connection and the bigd crashes.

F5 Product Development tracked this issue as CR68296, CR68515, and CR67705 and it was fixed in BIG-IP LTM 9.1.3, 9.2.4, and 9.3. For information about upgrading, refer to the BIG-IP LTM Release Notes.
