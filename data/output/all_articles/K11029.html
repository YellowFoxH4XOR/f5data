Known Issue

This is the result of a known issue. When an Illegal HTTP status violation occurs, the BIG-IP ASM sends an HTTP blocking response page that includes the OWS Server header. The server information could be used by malicious users to profile your servers.

For example:

HTTP/1.1 200 OK
Server: Microsoft-IIS/5.1
Cache-Control: no-cache
Connection: close
Pragma: no-cache
Content-Length: 187

<html><head><title>Request Rejected</title></head><body>The requested URL was rejected. Please consult with your administrator.<br><br>Your support ID is: <Support ID Number></body></html>

Under normal conditions when a violation occurs, the BIG-IP ASM sends an HTTP blocking response page with the following headers and information:

HTTP/1.1 200 OK
Cache-Control: no-cache
Connection: close
Pragma: no-cache
Content-Length: 187

<html><head><title>Request Rejected</title></head><body>The requested URL was rejected. Please consult with your administrator.<br><br>Your support ID is: <Support ID Number></body></html>

F5 Product Development tracked this issue as CR132665, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

In version 10.1.x, you can work around this issue by silently discarding blocked requests. To do so, follow the procedure detailed in K11335: Change in Behavior: The BIG-IP ASM can now silently discard blocked requests.
