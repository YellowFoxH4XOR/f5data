Description

SFTP connection is unsuccessful when there is a mismatch between the default SFTP client ciphers and the SFTP server ciphers. 
This mismatch usually occurs when initiating SFTP connection from a recent version of BIG-IP towards a remote server, or when creating SFTP monitors.

Similar symptom occurs when the cipher is mismatched: 

# sftp root@10.10.10.16
Connecting to 10.10.10.16...
no matching cipher found: client aes128-cbc,aes256-cbc server chacha20-poly1305@openssh.com,aes128-ctr,aes192-ctr,aes256-ctr,aes128-gcm@openssh.com,aes256-gcm@openssh.com
Connection closed

Environment

SFTP 
Cipher Negotiation

Cause

Big-IP allows limited default ciphers on the SFTP client profile.

For Example,
The client in the below scenario is presenting the following ciphers:
client aes128-cbc,aes256-cbc

The server supports the following ciphers:
server chacha20-poly1305@openssh.com,aes128-ctr,aes192-ctr,aes256-ctr,aes128-gcm@openssh.com,aes256-gcm@openssh.com

Recommended Actions

An administrator may force the BIG-IP's SFTP client to use specific ciphers matching that of the server.
An administrator can select ciphers listed by the server, for instance, aes128-ctr, and force the client to use specified Ciphers using ssh-specific switch.

For example: 
# sftp -v -oCiphers=aes128-ctr 10.10.10.16
