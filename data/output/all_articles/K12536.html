Known Issue

This is the result of a known issue. The mkdisk utility fails to create a bootable thumb drive when the USB drive is missing the vendor or serial string descriptions. When this issue occurs, the mkdisk utility generates an error message on the console that appears similar to the following example:

Please select a device by index (1 - 25) --->15
error: could not find 'Vendor:' and 'Serial Number:' in /proc/scsi/usb-storage/4
Failed to create RemovableDevice object for device

For example, after inserting the USB drive into the Linux workstation or BIG-IP system, you can verify whether the drive is missing the vendor or serial string descriptions by checking the matching entry under /proc/scsi/usb-storage/. If either string is missing, the mkdisk utility fails to create the bootable drive. In the following example, the vendor string is missing from the USB drive description:

Note: The path to the USB drive may change slightly depending on the USB drive being used.

# cat /proc/scsi/usb-storage/4
Host scsi4: usb-storage
Vendor:
Product: DiskGO
Serial Number: 0784045C0494
Protocol: Transparent SCSI
Transport: Bulk
Quirks:

F5 Product Development tracked this issue as ID 211632 and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

Note: The mkdisk utility can be used to create a bootable USB thumb drive containing a BIG-IP installation image. The thumb drive can then be used as the installation source to install the software. For more information, refer to BIG-IP Systems: Getting Started Guide for BIG-IP 10.x, and to Release Note: Installing BIG-IP software from a USB Thumb Drive for BIG-IP 9.4.7 and 9.4.8.
