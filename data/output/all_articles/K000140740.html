Description

This article provides a step-by-step guide for gathering data to help you or F5 Support with troubleshooting undesired behavior experienced in the BIG-IP Access Policy Manager (APM) when using Kerberos authentication. This guide is intended to help you identify and resolve issues by enabling detailed logging, running a qkview, and capturing network traffic for further analysis.

Environment

  • BIG-IP APM
  • Kerberos

Cause

The cause of the issue is unknown.

Recommended Actions

This guide aims to help you collect data so you can identify and resolve potential causes. 

   1. Close all the browser tabs/windows/sessions using the affected application/website.

   2. Enable Debug Level Logging for the Access Policy in BIG-IP.

      a. Navigate to: Access → Overview → Event Logs → Settings.

      b. Create a new logging provider, check the Enable Access System Logs box.

      c. In the Access System Logs tab, set the logging level for Access Policy, Per-Request Policy and SSO to "Debug".

      d. In the Access Profiles tab, select the affected profile (move to the right).

   3. Modify tcpdump db keys via CLI in BIG-IP. Enter the following commands one by one in the CLI (bash):

      tmsh modify sys db tm.rstcause.pkt value enable

      tmsh modify sys db tm.rstcause.log value enable

      tmsh modify sys db tcpdump.sslprovider value enable

      tmsh modify sys db log.ssl.level value Debug

   4. Start the capture on the BIG-IP using the below filter, replace x.x.x.x with the testing client machine IP:

       tcpdump -ni 0.0:nnnp host <client_ip> --f5 ssl -s0 -vw var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)".pcap

   5. Start another concurrent packet capture on the BIG-IP filtering by the Kerberos Server (KDC):

       tcpdump -nnvi 0.0:nnnp -s0 host <kdc_ip> -w /var/tmp/"$HOSTNAME"_kdc_"$(date +%H-%M-%S-%d-%m-%y)".pcap

   6. Replicate the issue.

   7. Connect from the client device and take note of the APM session ID associated with the failed attempt. To find the Session ID in BIG-IP:

       Navigate to: Access → Overview → Access Reports. (you can find it by client IP)

   8. Generate a fresh qkview file:

      qkview -s0 -f /var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)".qkview

   9. Collect tarball of logs. In the bash shell, create a compressed file of all logs:

       tar -zcvf /var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)"_logs.tar.gz /var/log/*

      You can then download this compressed file to your computer using a tool like WinSCP.

   10. Revert the System Database Changes. To revert changes made in step 3, use the following commands:

      tmsh modify sys db tm.rstcause.pkt value disable

      tmsh modify sys db tm.rstcause.log value disable

      tmsh modify sys db tcpdump.sslprovider value disable

      tmsh modify sys db log.ssl.level value Warning

   You can also remove the debug logging provider.

   11. Open a Support Case with F5 Networks Support and provide all the collected data.
