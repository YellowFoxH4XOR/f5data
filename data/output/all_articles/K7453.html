Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following articles:

  • K13981: Restricting access to the Configuration utility using client certificate (11.x)

Important: To perform the following procedures, you must have a Certificate Authority certificate and the necessary client certificates already signed and installed.

BIG-IP 9.4.2 - 10.x

Note: Starting in BIG-IP 9.4.2, most Unix-based configurations must be performed using the bigpipe command or by editing the bigip_sys.conf file. This allows the configuration to be retained during system upgrades.

Setting up client certificate access control to the Configuration utility

  1. Place a copy of the CA certificate in the /config/httpd/conf/ssl.crt directory.

    Important: The certificate must be PEM encoded.

  2. Edit the /config/bigip_sys.conf file, and add an httpd include statement to the end of the file with the following options:

    Note: If the bigip_sys.conf file has an existing httpd include statement, you must add the SSL options to the existing httpd include statement.

    SSLCACertificatePath - Specifies the path to the CA certificate
    SSLCACertificateFile - Specifies the name of the CA certificate file
    SSLVerifyClient - Specifies to require a client certificate
    SSLVerifyDepth - Specifies the certificate depth

    For example, the following configuration specifies a CA file named widgetsCA.crt, and requires client certificate authentication, with a certificate depth of 10:

    httpd {
   include "SSLCACertificatePath /config/httpd/conf/ssl.crt
   SSLCACertificateFile /config/httpd/conf/ssl.crt/widgetsCA.crt
   SSLVerifyClient require
   SSLVerifyDepth  10"
}
  3. Save the changes and exit the file.
  4. Type the following command to load the configuration into memory:

    bigpipipe load
     

Optional configuration: Configuring the BIG-IP web server to use a Certificate Revocation List (CRL)

  1. Copy a PEM-encoded CRL file into the /config/httpd/conf/ssl.crl directory.
  2. Edit the /config/bigip_sys.conf file, and add the following options to the end of the httpd include statement:

    SSLCARevocationPath - Specifies the path to the CRL file.
    SSLCARevocationFile - Specifies the name of the CRL file.

    For example, the following configuration specifies a CRL file named widgets.crl:

    httpd {
    include "SSLCACertificatePath /config/httpd/conf/ssl.crt
    SSLCACertificateFile /config/httpd/conf/ssl.crt/widgetsCA.crt
    SSLVerifyClient require
    SSLVerifyDepth 10
    SSLCARevocationPath /config/httpd/conf/ssl.crl
    SSLCARevocationFile /config/httpd/conf/ssl.crl/widgets.crl"
    }
  3. Type the following command to load the configuration into memory:

    bigpipe load
     

BIG-IP 9.0.0 through 9.4.1

Note: The following changes are not carried over if the system is upgraded or a hotfix is applied that modifies the httpd.conf file. The changes are not synchronized and must be performed on each system in a redundant pair.

Setting up client certificate access control to the Configuration utility

  1. Place a copy of the CA certificate in the /config/httpd/conf/ssl.crt directory.

    Important: The certificate must be PEM encoded.

  2. Edit the ssl.conf file located in the /config/httpd/conf.d/ directory.

  3. Locate the following entries within the file

    #   Certificate Authority (CA):
#   Set the CA certificate verification path where to find CA
#   certificates for client authentication or alternatively one
#   huge file containing all of them (file must be PEM encoded)
#   Note: Inside SSLCACertificatePath you need hash symlinks
#         to point to the certificate files. Use the provided
#         Makefile to update the hash symlinks after changes.
#SSLCACertificatePath /etc/httpd/conf/ssl.crt
#SSLCACertificateFile /etc/httpd/conf/ssl.crt/ca-bundle.crt
#   Client Authentication (Type):
#   Client certificate verification type and depth.  Types are
#   none, optional, require and optional_no_ca.  Depth is a
#   number which specifies how deeply to verify the certificate
#   issuer chain before deciding the certificate is not valid.
#SSLVerifyClient require
#SSLVerifyDepth  10

  4. Edit the following Certificate Authority (CA) entries to point to the CA certificate that was loaded onto the system in step 1.

    Original CA entries:

    #SSLCACertificatePath /etc/httpd/conf/ssl.crt
#SSLCACertificateFile /etc/httpd/conf/ssl.crt/ca-bundle.crt

    Modified CA entries:

    SSLCACertificatePath /config/httpd/conf/ssl.crt
SSLCACertificateFile /config/httpd/conf/ssl.crt/<CA certificate name>.crt

  5. Edit the Client Authentication (Type) entries to specify the verification type and depth, as follows:

    SSLVerifyClient optionDescription
    NoneNo client Certificate is required. This is the default option.
    OptionalThe client may present a valid Certificate.
    RequireThe client must present a valid Certificate. This is the most secure option.
    optional_no_caThe client may present a valid Certificate but does not have to be (successfully) verifiable.
    SSLVerifyDepthThis option is a number that specifies the point at which the certificate issuers chain will be read in order to verify whether or not the certificate is valid.

    Original Type entries:

    #SSLVerifyClient require
#SSLVerifyDepth  10

    Modified Type entries:

    SSLVerifyClient require
SSLVerifyDepth  10
  6. Save the changes made to the ssl.conf file.

  7. Restart the Configuration utility web service by typing the following command:

    bigstart restart httpd

    Note: If there are any errors, such as incorrect syntax or if the BIG-IP system is unable to find the CA certificate, the errors will be reported to the command line or to the /var/log/httpd/http_error.log file.

  8. To test the configuration, try accessing the Configuration utility using a browser that has a signed client certificate installed and one that does not have a signed client certificate.

Optional configuration: Configuring the web server to use a Certificate Revocation List (CRL)

  1. Copy a PEM-encoded CRL file into the /config/httpd/conf/ssl.crl directory.

  2. Locate the following entry in the /config/httpd/conf.d/ssl.conf file:

    #   Certificate Revocation Lists (CRL):
#   Set the CA revocation path where to find CA CRLs for client
#   authentication or alternatively one huge file containing all
#   of them (file must be PEM encoded)
#   Note: Inside SSLCARevocationPath you need hash symlinks
#         to point to the certificate files. Use the provided
#         Makefile to update the hash symlinks after changes.
#SSLCARevocationPath /etc/httpd/conf/ssl.crl
#SSLCARevocationFile /etc/httpd/conf/ssl.crl/ca-bundle.crl

  3. Edit the Certificate Revocation Lists (CRL) entries to specify the CRL file in step 1:

    Original CRL entries:

    #SSLCARevocationPath /etc/httpd/conf/ssl.crl
#SSLCARevocationFile /etc/httpd/conf/ssl.crl/ca-bundle.crl

    Modified CRL entries:

    SSLCARevocationPath /config/httpd/conf/ssl.crl
SSLCARevocationFile /config/httpd/conf/ssl.crl/<CRL file name>.crl
  4. Save the changes made to the /config/httpd/conf.d/ssl.conf file.

  5. Restart the Configuration utility web server by typing the following command:

    bigstart restart httpd

    Note: If there are any errors, such as incorrect syntax or if the BIG-IP system is unable to find the CA certificate, they will be reported to the command line or to the /var/log/httpd/http_error.log file.

To configure additional security by further restricting by source IP address, refer to K7448: Restricting access to the Configuration utility by source IP address.
