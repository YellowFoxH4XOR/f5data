Known Issue

BIG-IP APM network access sessions may fail to establish for Windows users.

This issue occurs when all of the following conditions are met:

  • Users attempting to establish an access session are using a device running the Windows operating system.
  • The user does not have administrative privileges on the device.
  • The Connectivity profile associated with the access profile virtual server is configured with the Component Update setting enabled.
  • The BIG-IP APM access policy is configured with all of the following agents:
     
    • Firewall Check
    • Machine Info
    • Machine Cert Auth
    • Windows Cache and Session Control
    • Windows Protected Workspace
  • The BIG-IP APM access policy is configured with all of the following resource types:
     
    • Network Access
    • Optimized Application Tunnel
  • The user establishes an access session and F5 browser-based client components are automatically installed or updated.
  • The user clicks the network access icon to launch the network access session.
  • The user is prompted for the device administrator password when launching the network access session.
  • After supplying the device administrator password, the network access tunnel is established.
  • The user terminates their access session.
  • The user initiates a new access session to a BIG-IP APM system that has a newer version of the BIG-IP APM software than the previous BIG-IP APM system.
  • The user establishes an access session to a virtual server that has an identically configured access profile and access policy as the previous BIG-IP APM system.
  • The user clicks the network access icon to launch the network access session.

Impact

The network access session fails to establish.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After authentication to the access profile on the BIG-IP APM system running the newer version software, the browser-based F5 client components are not automatically updated.
  • When attempting to launch the network access session, the user is not prompted for the device administrator password, and the system displays an error message that appears similar to the following example:

    "Error downloading required files (-1)"
