Description

You have a L7 DoS profile attached to the virtual server with Automatic Threshold mode enabled for TPS-based detection. However, you observe that DoS TPS attacks are being triggered at relatively low TPS values. You would like to understand why these attacks are being detected at such low thresholds.

Environment

  • BIG-IP ASM/advanced WAF
  • Automatic threshold mode in L7 DoS profile for TPS based detection. 

Cause

When the Threshold Mode is set to Automatic, the system determines threshold values based on observed traffic patterns during normal operation. If traffic behaviour changes significantly, it's possible for these automatically calculated thresholds to remain low.

For example, if you're running a marketing campaign that results in a sudden increase in traffic, the system may still be using previously learned thresholds, which can trigger DoS alerts prematurely. Over time, BIG-IP ASM will adapt and adjust the thresholds to reflect the new traffic pattern, but there may be a delay during this learning period.

By default, for source IP-based detection, the automatically set TPS threshold can be as low as 5 TPS, with the range typically between 5 and 5000 TPS.

Recommended Actions

If you frequently observe attacks being logged at low TPS values and they appear to be false positives, it’s a good practice to increase the minimum TPS threshold from its default value to reduce unnecessary alerts.

Additional Information

In general, manually adjusting the threshold requires the administrator to have a good understanding of the application’s expected traffic patterns. As such, F5 Support does not provide specific recommendations for these values. However, you can use the command tmctl dosl7d_auto_thresh_top_ip to view the automatically calculated threshold values at a given time, which can help inform your tuning decisions.
