Known Issue

The BIG-IP APM rewrite process may incorrectly handle the eval() function.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for portal access.
  • The JavaScript code in the web application makes an indirect reference to the eval() function.

    For example:

    function f(n) {
      var e = eval;
      return e(n);
    }
    f(some_text)

In the previous example, the system will not rewrite the JavaScript code before sending it to the eval() function.

Impact

Web applications may malfunction or fail to render properly.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Web page content that invokes the eval() function does not render properly in web browsers.
  • Web applications may malfunction or fail to render properly.

Workaround

To work around this issue, you can identify the URI where the calls to the function eval () is made and use a custom iRule similar to the one in the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system. However, the iRule should be customized to your specific web application.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRules List.
  3. Click Create.
  4. In the Name box, type the name of the iRule.
  5. To enforce the system to rewrite the JavaScript code before sending it to the eval() function, use the following iRules syntax: 
    when HTTP_REQUEST {
    if { [HTTP::uri] contains "/location/where/the/eval/function/is/invoked" } {
        set a_pointer 1
    }
}
when REWRITE_REQUEST_DONE {
    if { [info exists a_pointer] } {
        REWRITE::post_process 1
        unset a_pointer
    }
}
when REWRITE_RESPONSE_DONE {
    set resp [REWRITE::payload]
    set start [ string first {,r=eval;} $resp ]
    if { ($start > 0) && ($start < [expr { [REWRITE::payload length] - 8 } ]) } {
        REWRITE::payload replace $start 8 ",r=function(n){return(F5_Invoke_eval(F5_window,n));};"
    }
}
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. Click the name of the affected virtual server.
  9. Click the Resources tab.
  10. In the iRules section, click Manage.
  11. Locate the newly created iRule in the Available column, and click the name of the iRule.
  12. To move the iRule to the Enabled column, click <<.
  13. Click Finished.
