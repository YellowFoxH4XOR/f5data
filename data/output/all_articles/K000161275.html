Description

When monitoring an ICAP over TLS (ICAPs) service from the BIG-IP, administrators may encounter the following:

A custom HTTPS monitor fails to correctly probe the ICAPS service, leaving pool members marked down.

Environment

  • BIG-IP LTM
  • LTM Health Monitors (HTTPS Monitor)
  • Protocol monitored: ICAPS
  • ICAPs Pool Members

Cause

Plain TCP monitor for ICAP TLS not sufficient as an application health check

Recommended Actions

Create a HTTPs monitor with a TLS profile attached. For example, if the service is listening on TCP 11344,

(tmos)# list ltm monitor https ICAP-HTTPS-MONITOR-TEST
    ltm monitor https ICAP-HTTPS-MONITOR-TEST {
    adaptive disabled
    defaults-from https
    destination *:*
    interval 5
    ip-dscp 0
    recv "ICAP/1.0 200 OK"
    recv-disable none
    send "OPTIONS icaps://icap.example.lab:11344/REQMOD ICAP/1.0\r\nHost: icap.example.lab\r\nConnection: close\r\n\r\n"
    ssl-profile /Common/serverssl
    time-until-up 0
    timeout 16
}

Additional Information

Key requirement: The ssl-profile field must be populated with a valid server SSL profile (e.g., /Common/serverssl). Without this, TLS negotiation will not occur and the monitor will fail.
