Description
When troubleshooting APM problems, it is useful to be able to identify the logs for the specific session that is impacted. Without this information it is impossible to focus in on issues that only impact some users or correlate session logs with other data that we may have collected like a packet capture or edge client logs.

Environment

  • Big-IP APM
  • Access Policy
  • Network Access
  • Edge Client

Cause

Recommended Actions

There are multiple places that the session ID can be identified. Under some circumstances it will be directly available to the user, and in other cases it can be identified using the "LastMRH_Session" cookie.
  1. If a user is failing to authenticate, the default error page includes the user's session ID. The page will include the line: "The session reference number:  4aaf845f"
  2. When connected to a VPN using the Edge Client, the connection details will include the user's Session ID
    1. Open the Edge Client main console
    2. Click "View Details"
    3. The Connection Details tab should be open
    4. The Session ID is listed in the Connection panel
  3. Most modern web browsers include dev tools that allow you to inspect HTTP details. In Chrome, this can be opened by pressing F12
    1. Before reproducing the issue, press F12 to open Chrome Web Tools
    2. Select the Network tab
    3. Access the affected virtual server
    4. One of the requests should be for "/my.policy". Select that request
    5. Review the Response headers for the Set-Cookie LastMRH_Session:
      1. "Set-Cookie: LastMRH_Session=f2eb09bf;path=/;secure"
