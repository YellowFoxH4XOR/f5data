Known Issue

The BIG-IP system may incorrectly authenticate users using the system's local password database when remote RADIUS authentication fails.

This issue occurs when the following conditions are met:

  • A user account that exists on the BIG-IP system also exists on the remote RADIUS server.
  • The BIG-IP authentication source is configured to Remote - RADIUS.
  • Remote RADIUS authentication fails for this user account.

Impact

The BIG-IP system incorrectly authenticates users using the system's local password database instead of denying access.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Users are incorrectly authenticated, although remote RADIUS authentication failed.
  • The /var/log/secure file reports that the BIG-IP system incorrectly authenticated the user although the remote RADIUS server failed to respond:

    err httpd[13810]: pam_radius_auth: RADIUS server 1.1.1.1 failed to respond
    err httpd[13810]: pam_radius_auth: RADIUS server 1.1.1.1 failed to respond
    err httpd[13810]: pam_radius_auth: RADIUS server 1.1.1.1 failed to respond
    notice httpd[13810]: 01070417:0: AUDIT - user User1 - RAW: httpd(mod_auth_pam): user=User1(User1) partition=[All] level=Resource Administrator tty=1 host=192.168.52.70 attempts=1 start="Thu Mar 8 15:56:15 2012".

Workaround

To work around this issue, you can delete the local user accounts that should be authenticated using the remote RADIUS authentication. To do so, perform the following procedure:

Impact of Workaround: None

  1. Log in to the Configuration utility.
  2. Navigate to System > Users > User List.
  3. Check on the usernames that should be authenticated using the remote RADIUS authentication.
  4. Click Delete to initiate the removal.
  5. Click Delete to confirm the removal.
