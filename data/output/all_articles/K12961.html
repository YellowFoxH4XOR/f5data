Known Issue

Invalidation of cached object residing on the Hot Cache fails for BIG-IP WebAccelerator-enabled virtual servers. This issue occurs when all of the following conditions are met:

  • The affected BIG-IP WebAccelerator-enabled virtual server is associated with a custom http-acceleration profile.
  • Invalidation of the cached object is triggered using either the configured Invalidation Rules in the acceleration policy or Invalidate Content in the Configuration utility.

Impact

The client may display stale or invalid cached content.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP WebAccelerator delivers stale or invalid cached content to the client.
  • The X-PvInfo code for the invalidated object displays S11101 instead of S10205.

    Note: S11101 code indicates that the object was served from the Hot Cache, while S10205 code indicates that the object was served from the origin web server (OWS) because the cached content on the BIG-IP WebAccelerator system was invalidated. For information about more X-PvInfo codes, refer to the Viewing X-PvInfo response headers section under the Using HTTP Headers to Configure chapter of the Policy Management Guide for the BIG-IP WebAccelerator System. For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

  • The custom http-acceleration profile shows an entry for the invalidated object after invalidation has been triggered. For example, the following output from the bigpipe profile http mycache ramcache entry show command displays the /test/leaf.jpg object residing in the mycache custom http-acceleration profile even after an invalidation has been triggered for this object:

    PROFILE HTTP mycache - Ramcache Entry:
    +-> Host: wam30-214.jh.es.example.com   URI: /test/leaf.jpg
        |     14 hits   Size: 3092   Rank: 1   Source: 0/0   Owner: 0/0
        |     Received: 2011-05-10 19:59:41   Last sent: 2011-05-10 20:01:50
        |     Expires: 2011-05-12 19:59:41   Vary: none   Vary count: 1
        |     Vary user agent: none   Vary encoding: none

Note: This issue does not affect BIG-IP WebAccelerator 11.x, due to architectural changes.

Workaround

To work around this issue, you can disassociate the custom http-acceleration profile and associate the default http-acceleration profile to the affected BIG-IP WebAccelerator-enabled virtual server. To do so, perform the following procedure:

Impact of workaround: The affected BIG-IP WebAccelerator-enabled virtual server may lose the HTTP profile customizations from the previously-applied custom http-acceleration profile if configured.

Important: F5 does not recommend modifying default profiles. Modifying the default http-acceleration profile will affect all virtual servers using that profile or child profiles.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the affected BIG-IP WebAccelerator-enabled virtual server.
  4. From the HTTP Profile menu, select http-acceleration.
  5. Click Update.
