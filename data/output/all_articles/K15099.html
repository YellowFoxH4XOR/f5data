Topic

This article applies to BIG-IP ASM 11.4.0 and later. For information about other versions, refer to the following article:

  • K9372: Configuring the BIG-IP ASM system in transparent bridge mode (9.4.x - 11.3.0)

You should consider using this procedure under the following condition:

  • You want to deploy the BIG-IP ASM system within an existing network without making changes to the network.

Description

Starting in BIG-IP ASM 11.4.0, you can use the local traffic policy feature to configure the BIG-IP ASM system in transparent bridge mode. This configuration allows you to deploy the BIG-IP ASM system within an existing network without making changes to the network, and allows unsecured traffic to pass through the BIG-IP ASM system.

Secure HTTP services

The following two options are available when securing HTTP services with a BIG-IP ASM system in bridge mode:

  • Process and protect all sites with a single wildcard virtual server
    • Advantage: If you are protecting a small quantity of individual sites, using a single virtual server and multiple local traffic policies to separate and direct the traffic to different security policies is easier to initially configure.
    • Disadvantage: If you are protecting a large quantity of individual sites, using a single virtual server and multiple local traffic policies to separate and direct the traffic to different security policies can quickly become overwhelming.
  • Process and protect individual sites with host-specific virtual servers and local traffic policies configured with the specific sites IP address
    • Advantage: Using multiple host-specific virtual servers and individual local traffic policies to protect traffic for individual sites allows the administrator to keep traffic separated and security policies manageable.
    • Disadvantage: Using multiple host-specific virtual servers and individual local traffic policies to protect traffic for a large quantity of individual sites introduces additional configuration steps to ensure that traffic is managed and passed correctly. For example, you must disable ARP on the virtual servers to prevent ARP overwrites and interruption of traffic flow.

Secure HTTPS services

You can use the previously-described options to manage HTTPS traffic if the system is licensed to allow termination of SSL traffic on the BIG-IP ASM system. To set up the system to manage and terminate SSL traffic, and allow the BIG-IP ASM system to manage SSL communication between itself and the client, you must take the following additional considerations into account:

  • Determine whether to create a wildcard virtual server or individual host-specific virtual servers.
  • Configure single or multiple Client SSL profiles. This option depends on the type of virtual server configuration you choose.
  • Determine if SSL will be terminated on the BIG-IP system itself. If security requirements specify that SSL communication must be terminated on the web server, then you must create a Client SSL profile and a Server SSL profile to allow the BIG-IP ASM system to decrypt and parse the content before re-encrypting and sending the information to the appropriate web server.

For the BIG-IP ASM system to manage and monitor HTTPS traffic, the system must be allowed to terminate SSL traffic. This type of configuration introduces challenges that must be addressed in order to properly secure, monitor, and direct traffic to the correct web server. The advantages and disadvantages for each configuration are listed as follows:

  • A single wildcard virtual server with a single Client SSL profile
    • Advantage: A single wildcard 0.0.0.0:443 virtual server with a single Client SSL profile is the simplest SSL configuration for the BIG-IP ASM system, allowing one certificate to manage all SSL requests received by the BIG-IP ASM system.
    • Disadvantage: While this is the simplest SSL configuration, this option requires that all web servers managed by the single virtual server must use the same SSL certificate. If all of the websites are within the same domain, the system can use a wild card certificate. This type of certificate allows multiple servers with the same domain name to be validated while allowing unique host names. If there are multiple web server domains, this is not the best method to use because user browsers/applications report certificate mismatch errors if the domain names do not match.
  • Individual host-specific SSL virtual servers and individual Client SSL profiles
    • Advantage: Individual web servers are managed by their own unique SSL virtual server, HTTP profile, and Client SSL profile. This option is easier to administer, as each site is managed by its own unique configuration and does not share profiles with other websites.
    • Disadvantage: This option requires an administrator to create individual virtual servers, HTTP profiles, and Client SSL profiles. For a large quantity of websites, this configuration can be tedious.
  • Re-encrypting communication to the web server using a Server SSL profile

    This option works with either of the previously-described configurations and shares the same advantages and disadvantages in either scenario. The only difference is the introduction of a Server SSL profile that allows the BIG-IP ASM system to re-encrypt the communication before it is sent to the web server.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP ASM system is properly licensed and configured with the BIG-IP ASM security policy that you want to associate with the virtual server. For more information about creating a security policy, refer to the Configuration Guide for BIG-IP Application Security Manager for BIG-IP ASM 11.4.x or the BIG-IP Application Security Manager: Getting Started guide for BIG-IP ASM 11.5.0.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  • If your network uses tagging, you know which 802.1q Virtual Local Area Network (VLAN) tag number to use.

    Important: If you use tagging within your network, you must re-tag and supply separate tags on the client and server-side VLANs.

  • You have an available IP address to deploy the BIG-IP ASM system with; this is required for configuring the self IP address.
  • You have an existing pool configured with the IP addresses and ports of the web services that the BIG-IP ASM system will secure.
  • If you plan to configure the BIG-IP ASM system to secure HTTPS services using a public SSL certificate, you must first create an SSL key, obtain an SSL certificate from a Certificate Authority (CA), and import these items to the BIG-IP ASM system. For information about creating and importing the SSL certificate/key pair to the BIG-IP ASM system, refer to K14620: Managing SSL certificates for BIG-IP systems.

Procedures

To configure the BIG-IP ASM system in transparent bridge mode, perform the following procedures:

  • Configure the VLAN Group
  • Optional: Specify the default gateway for use by the BIG-IP ASM system
  • Configure a local traffic policy (BIG-IP ASM 12.0.0 and later)
  • Configure a local traffic policy (BIG-IP ASM 11.4.0 - 11.6.5) 
  • Configure a Client SSL profile (for securing HTTPS services)
  • Configure a Server SSL profile (for securing HTTPS services)
  • Configure a single wildcard virtual server
  • Configure a host-specific virtual server

Configure the VLAN Group

To configure the VLAN Group, you must create both the client-side and server-side VLANs before including them in the VLAN Group, and then assign a self IP address to the VLAN Group. To do so, perform the following procedure:

Impact of procedure: Assigning the VLANs to the VLAN Group may form a network loop in some network environments. Ensure that the VLANs are properly configured for your network environment.

  1. Log in to the Configuration utility.
  2. Go to Network > VLANs > VLAN List.
  3. To create the client-side VLAN, select Create.
  4. Enter a Name for the VLAN. For example: clientside_vlan
  5. Select the interface to use for the client-facing VLAN.
  6. Optional: Select a VLAN tag.

    Note: This tag must differ from the tag used on the server-side VLAN.

  7. Select Finished
  8. To create the server-side VLAN, select Create.
  9. Enter a Name for the VLAN. For example: serverside_vlan
  10. Select the interface to use for the server-facing VLAN.
  11. Optional: Select a VLAN tag.

    Note: This tag must differ from the tag used on the client-side VLAN.

  12. Select Finished.
  13. Select VLAN Groups.
  14. To create the VLAN Group, select Create.
  15. Enter a Name for the VLAN Group. For example: client_server_group
  16. From the Available list, select the new client-side and server-side VLANs that you created in the previous steps and move it to the Members list.
  17. To specify that the system use Proxy ARP with Layer 3 forwarding, under Transparency Mode, select Translucent or Opaque (unless you have a specific requirement for Transparent mode).
  18. To allow the system to forward all frames, including non-IP traffic, select the Bridge All Traffic check box.
  19. Clear the Bridge in Standby check box.

    Note: This option is for redundant configurations to prevent the standby unit from passing traffic.

  20. Select Finished.
  21. Go to Network > Self IPs.
  22. To create a self IP for the new VLAN Group, select Create.
  23. Select the IP address and subnet mask for the BIG-IP ASM system to use.
  24. Select the new VLAN Group that you created in the previous steps.
  25. Select Finished.

Optional: Specify the default gateway for use by the BIG-IP ASM system

Specifying a default gateway on the BIG-IP ASM system is optional and used only for traffic that the BIG-IP ASM system generates locally. To configure this option, perform the following procedure:

Impact of procedure: Depending on your network environment, specifying a default gateway may potentially affect traffic flow through the BIG-IP ASM system. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Go to Network > Routes.
  3. Select Add.
  4. Specify the necessary information for the gateway that the BIG-IP ASM system should use.
  5. Select Finished.

Configure a local traffic policy (BIG-IP ASM 12.0.0 and later)

To configure a local traffic policy for the virtual server, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: This procedure assumes that you have already created a BIG-IP ASM security policy to associate with the virtual server. For more information about creating a security policy, refer to the BIG-IP Application Security Manager: Getting Started guide.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies.
  3. Select Create.
  4. Enter a Name for the local traffic policy.

    Note: Using the host name of the site which the security policy protects allows for easier administration. For example: www.askf5.com.

  5. For Strategy, select first.
  6. Select Create Policy.
  7. For Rules, select Create to add an ASM rule.
  8. Enter a Rule Name for the rule.

    Note: Using the host name of the site that the security policy protects as part of the rule name allows for easier administration. For example: www.askf5.com_asm_enable.

  9. For Match all of the following conditions, select the plus sign to add a new condition.
  10. Select HTTP Host host contains any of <host name> at request time.
    Note: for <host_name>, enter the host name of the site that the policy will protect in the text box and select Add. By default, this procedure rejects any traffic not destined for the host specified for this rule in this step.
  11. For Do the following when the traffic is matched, select the plus sign to add a rule action.
  12. Select Enable asm for policy <policy_name> at request time.
    Note: for <policy_name>, select an ASM security policy.
  13. Select Save.
  14. For Rules, select Create to add a default rule.
  15. For Rule Name, enter a name for the rule.

    Note: Using the host name of the site which the security policy protects as part of the rule name allows for easier administration. For example: www.askf5.com_default_reject.

  16. For Do the following when the traffic is matched, select the plus sign to add two rule actions.
  17. For the first rule action, select Disable asm at request time.
  18. For the second rule action, select Reset traffic connection at request time.
  19. Select Save.

    Note: Any HTTP traffic that does not match a local traffic policy is forwarded to the web server without inspection. To prevent this behavior, F5 recommends that you create a catch-all local traffic policy that either redirects or allows the BIG-IP ASM system to scan the content before forwarding to the server.

Configure a local traffic policy (BIG-IP ASM 11.4.0 - 11.6.5)

To configure a local traffic policy for the virtual server, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: This procedure assumes that you have already created a BIG-IP ASM security policy to associate with the virtual server. For more information about creating a security policy, refer to the Configuration Guide for BIG-IP Application Security Manager for BIG-IP ASM 11.4.x or the BIG-IP Application Security Manager: Getting Started guide for BIG-IP ASM 11.5.0.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies.
  3. Select Create.
  4. Enter a Name for the local traffic policy.

    Note: Using the host name of the site which the security policy protects allows for easier administration. For example: www.askf5.com.

  5. For Strategy, select first-match.
  6. For Requires , select http from the Available list and move it to the Selected list.
  7. For Controls, select asm and forwarding from the Available list and move them to the Selected list.
  8. For Rules, select Add to add a default rule.
  9. For Rule Name, enter a name for the rule.

    Note: Using the host name of the site which the security policy protects as part of the rule name allows for easier administration. For example: www.askf5.com_default_reject.

  10. For Conditions, no condition is required for the default rule.
  11. For Actions, to create the first rule action, for Target select asm and for Action select disable, then select Add to add the rule to the list.
  12. To create the second rule action, for Target, select forward and for Action, select reset, then select Add to add the rule to the list.
  13. Select Finished.
  14. Select the name of the new local traffic policy.
  15. For Rules List, select Add to add the ASM rule.
  16. Enter a Rule Name for the rule.

    Note: Using the host name of the site that the security policy protects as part of the rule name allows for easier administration. For example: www.askf5.com_asm_enable.

  17. For Conditions, select or enter the stated values for the following condition operands:
    • Operand: http-host
    • Selector: host
    • Condition: contains
    • Values: <host name of the site that the policy will protect>

      Note: For example, the Values option entry may appear similar to www.askf5.com.

  18. For Values, select Add to add your input to the Values list.
  19. For Conditions, select Add to add this condition to the Conditions list.

    Note: By default, this procedure rejects any traffic not destined for the host specified for this rule in this step.

  20. For Actions, select the stated values for the following action operands:
    • Target: asm
    • Action: enable
    • Parameters: <select an ASM security policy>
  21. For Parameters , for Value, select Add to add your selection in the Parameters list.
  22. For Actions list, select Add to add this action to the Actions list.
  23. To save the second rule, select Finished.
  24. For Rules, select Reorder and then drag the default rule (first configured rule) below the ASM rule (second configured rule).
  25. Select Update.

    Note: Any HTTP traffic that does not match a local traffic policy is forwarded to the web server without inspection. To prevent this behavior, F5 recommends that you create a catch-all local traffic policy that either redirects or allows the BIG-IP ASM system to scan the content before forwarding to the server.

Configure a Client SSL profile (for securing HTTPS services)

This procedure is only required if you are configuring the BIG-IP ASM system to secure HTTPS services. You can skip this procedure if you are configuring the BIG-IP ASM system to secure HTTP services only. To configure a Client SSL profile, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

For BIG-IP 11.5.0, select the Certificate Key Chain check box. For BIG-IP 11.4.0 through 11.4.1, select the Certificate and Key check boxes.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create
  4. Enter a Name for the new Client SSL profile.

    For example, if you create an individual Client SSL profile for a specific website, it may appear similar to the following: www.askf5.com

    Alternatively, if you create an individual Client SSL profile for multiple websites to use, with the same domain name but different host names, it may appear similar to the following askf5.com

  5. For Certificate, select the name of the SSL certificate to use for the website.
  6. For Key, select the name of the SSL key associated with the SSL certificate.
  7. Configure the remaining Client SSL profile settings as needed.
  8. Select Finished.

Configure a Server SSL profile (for securing HTTPS services)

This procedure is only necessary if you require the BIG-IP ASM system to re-encrypt the traffic to the web server. Configuring re-encryption requires the addition of a Server SSL profile. Additionally, you must configure the pool members with either port 443 or the appropriate SSL listening port. If the SSL port for the pool members is different than port 443, you must also configure the corresponding forwarding virtual server to use the same port. To create a Server SSL profile, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Server.
  3. Select Create.
  4. Enter a Name for the new Server SSL profile. For example, if you create an individual Server SSL profile for a specific website, it may appear similar to the following: www.askf5.com.

    Alternatively, if you create an individual Server SSL profile for multiple websites to use, it may appear similar to the following: askf5.com

  5. Configure the remaining Server SSL profile settings as needed.
  6. Select Finished.

Configure a single wildcard virtual server

You should perform this procedure only if you want a single wildcard virtual server to manage all requests. If you require individual host-specific virtual servers to manage requests for each individual web server, you should perform the Configure a host-specific virtual server procedure in this article. To configure a single wildcard virtual server, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select Create.
  4. Enter a Name for the new virtual server.
  5. For Destination, enter the network IP address/netmask.

    Note: For BIG-IP versions prior to 11.6.0, for Destination , for Type, select Network.

  6. For Destination, for Address, enter 0.0.0.0.
  7. For Destination Mask, enter 0.0.0.0.
  8. For Service Port, enter the listening port on the web server. For example, use 80 for non-SSL ports and use 443 for SSL ports.
  9. For HTTP Profile, select HTTP.
  10. For Resources, for Policies , select the appropriate local traffic policy that you configured in the previous procedure from the Available list and move the policy to the Enabled list.
  11. If you are securing HTTP services only, skip this step and proceed to the next step.

    If you are securing HTTPS services, for SSL Profile (Client) , select the Client SSL profile you want from the Available list and move it to the Selected list.

  12. If you are re-encrypting the traffic to the web server, for SSL Profile (Server) , select the server SSL profile you want from the Available list and move it to the Selected list.
  13. Select Finished.

Configure a host-specific virtual server

If you require individual host-specific virtual servers to manage requests for each individual web server, you must configure a unique host-specific virtual server for each web server. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create.
  4. Enter a Name for the new virtual server.

    Note: Using the host name of the site which the security policy protects allows for easier administration. For example: www.askf5.com.

  5. For Destination Address, enter the IP address of the web server which the BIG-IP ASM system secures.
  6. For Service Port, enter the listening port on the web server. For example, use 80 for non-SSL ports and use 443 for SSL ports.
  7. For Configuration, select Advanced.
  8. For HTTP Profile, select HTTP.
  9. Clear the Address Translation check box.
  10. For Resources, for Policies , select the appropriate local traffic policy from the Available list and move it to the Enabled list.
  11. If you are securing HTTP services only, skip this step and proceed to the next step.

    If you are securing HTTPS services, forSSL Profile (Client), select the Client SSL profile you want from the Available list and move it to the Selected list.

  12. If you are re-encrypting the traffic to the web server, for SSL Profile (Server) , select the Server SSL profile you want from the Available list and move it to the Selected list.
  13. Select Finished.
  14. Go to Local Traffic > Virtual Servers > Virtual Address List.

    Important: Steps 15 through 17 are important because they allow the BIG-IP ASM virtual servers to answer requests for the given IP address and port but prevent the virtual servers from advertising the IP address as belonging to the BIG-IP ASM MAC address, which allows the BIG-IP ASM system to be transparent with the devices in the network that it bridges.

  15. Select the IP address that was assigned to the virtual server that you created in the previous steps.
  16. Clear the ARP check box.
  17. Select Update.
  18. Repeat steps 15 through 17 for each additional virtual server you created while performing this procedure.
