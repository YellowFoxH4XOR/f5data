Known Issue

The BIG-IP APM rewrite profile may not properly process the HTTP Refresh header.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system provides access to a destination web application through a configured rewrite profile.
  • The destination web application inserts a Refresh header in HTTP response, similar to the following example:

    HTTP/1.1 200 OK
    Refresh: 5; url=http://www.example.com/
    Content-Type: text/html

Impact

Access to web application functionalities may be limited.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to access the destination resource, the page stops responding.
  • The destination resource web page content fails to render correctly.
  • The relative url value in the Refresh header is not available when the page refreshes, because it is rewritten as an empty string that appears similar to the following example:

    HTTP/1.1 200 OK
    Refresh: 5; url=
    Content-Type: text/html
  • If the url value in the Refresh header matches the rewrite profile bypass list, the rewrite process produces a core file to the /shared/core directory.
