Topic

This article applies to BIG-IP 11.x through 17.x. For information about other versions, refer to the following article:

  • K10819: Performing a clean installation of BIG-IP 10.x

You should consider using these procedures under any of the following conditions:

  • You want to completely reinstall a BIG-IP device by wiping all mass-storage devices and performing a clean installation from an installation ISO file.
  • You have a device that still boots to a boot location, and you want to perform a clean installation from an ISO file saved to the system.
  • You have a device that no longer boots from any of its boot locations, and you want to reinstall using one of the following methods:
    • Installing the BIG-IP software using a USB DVD or USB thumb drive
    • Installing the BIG-IP software using a PXE server

Important: The procedures in this article do the following:

  • Permanently destroy all information on the device
  • Delete all currently defined boot locations
  • Create a new single boot location
  • Perform a clean installation to that boot location

Note: For information about resetting a BIG-IP system's configuration to factory defaults without completely wiping and re-installing the software, refer to K13127: Restoring the BIG-IP configuration to factory default settings (11.x - 17.x).

Description

If your device is no longer able to boot from any of the defined boot locations, you need to perform the clean installation using a USB DVD, USB thumb drive, or PXE server.

General prerequisites

You must meet the following general prerequisites for the procedure you select to perform a clean installation of your BIG-IP device:

  • You can access the device serial terminal console.
  • You have administrative (root) permissions.

Procedures

  • Download the installation image
  • Install the software using an installation image saved on the system
  • Install the software using a USB DVD or USB thumb drive
  • Correct a failed DVD/USB installation due to a missing installation repository failure workaround
  • Install the software using a PXE server

Download the installation image

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the F5 Downloads site.
  2. Download the appropriate product ISO image and its corresponding verification files (PEM and SIG files or MD5 file).
    Note: For more information about the type of ISO image that is suitable for the task you are performing, refer to K03203114: Multiple F5 .iso images are available.
  3. Verify the downloaded ISO image using one of the following methods:
    • F5 recommends that you verify BIG-IP software images using SIG and PEM files. For more information, refer to K24341140: Verifying BIG-IP software images using SIG and PEM files.
    • You can verify all versions of BIG-IP images using an MD5 checksum. For more information, refer to K8337: Verifying the MD5 checksum for the downloaded F5 software file.

    Important: Ensure that you perform step 3 in this procedure. The installation procedures do not verify the validity of the downloaded image file. If you attempt to install using a corrupted ISO image, you may get unpredictable results.

    Important: Engineering hotfixes are not candidates for a clean installation procedure, ensure base product image is used. Otherwise system will refuse to install the software with a message similar to the following: Terminal error: /shared/images/Hotfix-BIGIP-13.1.3.4.0.38.5-ENG.iso is not a product image (type is: hotfix).

Install the software using an installation image saved on the system

If your system still boots to a boot location, and you are able to save the appropriate ISO installation image to the /shared/images directory, you can complete the following procedure to perform a clean installation:

Impact of procedure: This procedure permanently destroys all volume information on the device, creates a new single boot location, and performs a clean installation to that boot location.

  1. Log in to the system serial console (optional).
  2. Verify the downloaded ISO image using one of the following methods:
    • F5 recommends that you verify BIG-IP software images using SIG and PEM files. For more information, refer to K24341140: Verifying BIG-IP software images using SIG and PEM files.
    • You can verify all versions of BIG-IP images using an MD5 checksum. For more information, refer to K8337: Verifying the MD5 checksum for the downloaded F5 software file.

    Important: Ensure that you verify the ISO image. The installation procedures do not verify the validity of the downloaded image file. If you attempt to install using a corrupted ISO image, you may get unpredictable results.

  3. Use the image2disk utility to install the ISO installation image file using the following command syntax:

    Important: The following command deletes all boot locations, creates a new single boot location, and performs a clean installation to that boot location.

    image2disk --format=volumes --nosaveconfig /<path>/<installation ISO file name>

    For example:

    image2disk --format=volumes --nosaveconfig /shared/images/BIGIP-RECOVERY-17.5.0-0.0.15.iso

Install the software using a USB DVD or USB thumb drive

For USB mass storage-based installations (thumb drive), you must meet the following specific prerequisites:

  • For USB thumb drive installations, you have a USB mass storage device that is at least 2 GB in size.

    Important: This system has additional requirements that are described in K13164: Creating a bootable USB thumb drive.

  • For USB DVD-ROM-based installations, you can write the product ISO to DVD media.
    Note: For more information about the type of ISO image that is suitable for the task you are performing, refer to K03203114: Multiple F5 .iso images are available.
  • You have physical access to the device.
  • For USB thumb drive installations, you have a local workstation that has the required software to create a USB bootable drive.

    Note: Because all BIG-IP systems meet these requirements, you can create the bootable drive on another BIG-IP system, such as a high availability (HA) peer.

Impact of procedure: This procedure permanently destroys all information on the device.

  1. Prepare a DVD image by burning the product ISO image to the DVD, or image the USB thumb drive using the product ISO image file.
  2. Connect to the system serial console.

    Important: If you are reimaging a platform that uses the Always-On Management (AOM) subsystem, the serial port baud must match the AOM baud. For more information, refer to K10834: The serial port baud rate must match the Always-On Management baud rate.

    Note: For more information, refer to K7683: Connecting a serial terminal to a BIG-IP system.

  3. Connect the USB DVD-ROM drive containing the product ISO image or the bootable USB thumb drive to the device's USB port.
  4. Power cycle the device.

    Note: After you complete this step, the system boots into the Maintenance Operating System (MOS).

  5. Press Enter to use the default terminal setting of (vt100).

    Note: When you use a USB device, the device may display a manufacturing installation dialog. For more information, refer to K11686: When the BIG-IP system is booted from a USB removable media, a manufacturing installation dialog is automatically displayed.

  6. Complete steps 7 through 9 if you want to perform a custom installation using the diskinit and image2disk utilities. Otherwise, press Enter, follow the installation instructions that display, and skip to step 11.
  7. To continue the software installation by manually using the diskinit and image2disk utilities, to exit the installation script, press Ctrl + C.
  8. To wipe all mass-storage devices inside the device, enter the following command:

    diskinit --style volumes

    Note: RAID mirroring is automatically configured for BIG-IP 11.x and later multi-drive systems. For BIG-IP versions earlier than 11.x, refer to K10856: Hard drive mirroring (RAID) for BIG-IP 10.1.0 through 10.2.4.

    Important: Do not omit the --style option. When the --style option is omitted, the system wipes the drives but does not reformat them.

  9. The diskinit utility asks whether you want to proceed in wiping the drives. To continue, enter y and press Enter. Otherwise, enter n and press Enter.

    Important: This operation destroys all data on the system. Do not proceed with this step if you have data that you need to recover from the system. Using the MOS, you may be able to manually mount a partition or volume and recover such data.

  10. To install the software, enter the following command:

    Note: You may encounter an error when running the following command. To address it, you can state the repository when running the command. For more information, refer to ID 760570.

    image2disk --format=volumes --nosaveconfig --nosavelicense

  11. After installation is complete, disconnect any removable media from the device.
  12. To restart the device to the newly installed software, enter the following command:

    reboot

Correct a failed DVD/USB installation due to a missing installation repository

If the system displays a syntax error indicating that you did not specify the installation repository, it's likely that you did not correctly create or format the USB DVD-DVD ROM or USB thumb drive. In this case, you may be able to continue the installation by manually mounting the media and specifying a repository.

Impact of procedure: This procedure permanently destroys all information on the device.

  1. To create a directory into which to mount the device, enter the following command:

    mkdir /mnt/usb

  2. To mount the removable device, use the following command syntax:

    Note: You can use the fdisk -l command to view the name of the removable device.

    mount <removable-device> /mnt/usb

    For example:

    mount /dev/sdb1 /mnt/usb

  3. To list the contents of the removable device to verify the location of the ISO file, enter the following command:

    ls /mnt/usb

  4. To specify the path to the ISO file, use the following image2disk command syntax:

    image2disk --format=volumes --nosaveconfig --nosavelicense <path><installation ISO file name>

    For example:

    image2disk --format=volumes --nosaveconfig --nosavelicense /mnt/usb/BIGIP-RECOVERY-17.5.0-0.0.15.iso

  5. After you complete the installation, disconnect any removable media from the device.
  6. To restart the device to the newly installed software, enter the following command:

    reboot

Install the software using a PXE server

For PXE server installations, you must have the following specific prerequisites:

  • A workstation that resides on the same network segment as the system management network interface.
  • The ability to configure a workstation as a PXE server, that provide DHCP, Trivial File Transport Protocol (TFTP), and HTTP services.

    Important: The TFTP server must support the tsize option.

Impact of procedure: This procedure permanently destroys all information on the device.

Note: The ISO images no longer provide network installation services; therefore, you cannot use them to boot and automatically configure a workstation as a PXE server. However, the essential files are still included in the product ISO images. You can use these files to manually configure a workstation as a PXE server.

Important: You cannot use a PXE server to re-image a VIPRION platform. To perform a clean installation of BIG-IP 11.x or later on a VIPRION blade, choose one of the other installation methods.

  1. Configure a local workstation as your PXE server to provide TFTP, DHCP, and HTTP services (you can also set up the workstation as a virtual machine. Ensure that the PXE server is on the same network segment as the F5 system's management network interface).

    Note: The following steps are not exhaustive, and you should take them only as an example. Additionally, F5 Support cannot assist you in setting up your own PXE server.

    Note: The following steps include example configurations and commands specific to Linux operating systems. However, you can also set up a PXE server on other operating systems.

    Important: Ensure that no DHCP server is already present on the management network. If a DHCP server is already present, configuring a PXE server may interfere with the normal operation of your existing DHCP server and may cause traffic disruption.

  2. Configure the TFTP service to serve the contents of the /tftpboot/X86PC/UNDI/F5 directory, which is included in each product ISO file.
  3. Mount the product ISO file to a directory, and then copy the required files to your TFTP root directory.

    For example:

    mount -o loop /root/BIGIP-RECOVERY-17.5.0-0.0.15.iso /mnt/iso

  4. Copy the files from the mounted directory to your TFTP server's root directory:

    cp -LRv /mnt/iso/tftpboot/X86PC/UNDI/F5/* /tftpboot/

  5. Configure the DHCP server with the next-server and filename options.

    Note: The options define the IP address of your TFTP server and the file that the F5 system should retrieve.

    Following is an example PXE & DHCP server configuration:

    subnet 192.168.1.0 netmask 255.255.255.0 {
    range 192.168.1.100 192.168.1.200;
    option subnet-mask 255.255.255.0;
    option broadcast-address 192.168.1.255;
    next-server 192.168.1.1;
    filename "pxelinux.0";
    }

    Note: In the example, a single workstation provides all of the required services (TFTP, DHCP, and HTTP). The example IP address of the TFTP server (192.168.1.1) is also the IP address of the DHCP server.

  6. The HTTP server must serve the root directory of the product ISO file. You can mount the ISO file to a directory and then place a link to that directory in your www directory.

    For example:

    mount -o loop /root/BIGIP-RECOVERY-17.5.0-0.0.15.iso /mnt/iso
    cd /var/www/
    ln -sf /mnt/iso/ BIGIP_INSTALL

  7. The MOS asks you to specify the enter of terminal you are using. If you do not know what to specify, press Enter to use the default setting (vt100), which works in most cases.
  8. If the terminal displays an installation dialog, to exit the installation script, press Ctrl +C.
  9. To wipe all mass-storage devices inside the device system, enter the following command:

    diskinit --style volumes

    Note: RAID mirroring is automatically configured for BIG-IP 11.x and later multi-drive systems. For BIG-IP versions prior to BIG-IP11.x refer to: K10856: Overview of hard drive mirroring.

    Important: Do not omit the --style option. If you omit it, the system wipes the drives but does not reformat them.

  10. The diskinit utility asks whether you want to proceed in wiping the drives. To continue, enter y and press Enter. Otherwise, enter n and press Enter.

    Important: This operation destroys all data on the system. Do not proceed with this step if you have data that you need to recover from the system. Using the MOS, you may be able to manually mount a partition or volume and recover such data.

  11. To install the software image from the PXE server, use the following command syntax:

    image2disk --format=volumes --nosaveconfig --nosavelicense http://<SERVER_IP>/<PATH>

    For example, to install the ISO file you mounted in step 6, enter the following command:

    image2disk --format=volumes --nosaveconfig --nosavelicense http://192.168.1.1/BIGIP_INSTALL

    Note: You cannot install BIG-IP 11.x or later on a CompactFlash media drive. You must install using boot locations on the system's hard drive.

    Note: You must specify the --nosaveconfig option because the system does not have a configuration to save.

    Note: For more information about the image2disk utility, use the image2disk --h command to use Help.

  12. After you complete the installation, restart the device to the newly installed software by entering the following command:

    reboot
