Description

Commonly the two logging systems High Speed Logging and syslog-ng are mixed up on what they are for and it is not clear on which is applicable in which environment.

Environment

  • BIG-IP LTM
  • High Speed Logging
  • syslog-ng 

Cause

Expected behavior.

Answer/Recommended Actions

High-Speed Logging (HSL)syslog-ng
 Purpose: Designed for high-throughput, low-latency logging of BIG-IP events (such as LTM, ASM, APM, AFM logs) to remote servers.Handles standard Linux system logging, including OS-level events and messages from native Linux daemons.
How it works: Uses the BIG-IP Traffic Management Microkernel (TMM) and the errdefsd daemon to send logs. 
HSL can send logs via TMM data plane interfaces or, with special configuration, via the management interface.		syslog-ng is a user-space daemon that collects and forwards logs generated by the Linux OS and its services.
Configuration:Requires creation of log destinations (pool-based or management-port), log publishers, and log filters.
For management interface: You must use a log destination of type management-port (not pool-based).
See below: KB K50040950: Configuring the BIG-IP system to send high-speed logs through the management interface		Configured via /etc/syslog-ng/syslog-ng.conf (or via tmsh for remote destinations).
Supported interfaces:Can use both TMM (data plane) interfaces and the management interface (with correct configuration).Always uses the management interface for remote syslog destinations.
Use cases:Logging of BIG-IP module events (e.g., LTM, ASM, APM, AFM).
High-volume, structured logging.		Logging of system-level events, such as kernel messages, cron jobs, and output from the logger command.
Limitations:Does not handle native Linux system logs (e.g., messages from crond, systemd, or the logger command).Does not handle BIG-IP module logs (those are handled by errdefsd/HSL).
