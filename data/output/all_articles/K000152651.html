Description

When deploying a BIG-IP Virtual Server (VS) configured with Traffic Matching Criteria (TMC) together with persistence profiles (such as source address persistence), you may experience intermittent traffic forwarding issues.

Symptoms of this issue typically include:

  • BIG-IP receives ICMP or TCP packets but does not forward them to pool members.
  • Packet captures identify incoming client-side packets arriving at the BIG-IP without corresponding outgoing server-side communication.
  • Direct connectivity tests (such as ping from the BIG-IP CLI) to pool members succeed, confirming routing and basic network reachability are intact.
  • Intermittent connectivity failures observed—certain connections work normally, while others fail unexpectedly.
  • Virtual server statistics indicate zero packets processed for affected flows, such as the output of tmsh show virtual_server_stat

Environment

  • LTM
  • Virtual Server using traffic-matching-criteria (TMC)
  • Persistence profile applied (e.g., source address persistence)

Cause

This issue is due to a known incompatibility (Bug ID 912293: Persistence might not work properly on virtual servers that utilize address lists) between TMC-based Virtual Servers and persistence profiles. TMC creates multiple listeners in TMM; without "match-across-virtuals" enabled on the persistence profile, persistence lookups can fail or behave inconsistently across listeners. This leads to intermittent failures where certain flows are not forwarded as expected.

Recommendations

  • Avoid applying persistence profiles to TMC-based Virtual Servers unless "match-across-virtuals" is enabled in the persistence profile.
  • If session persistence is not required, remove any persistence profiles from TMC-based Virtual Servers.
  • Use packet captures and virtual server statistics to monitor for abnormal flow behavior.
  • There is currently no plan for a code change; this behavior is inherent to how TMC operates on BIG-IP.
