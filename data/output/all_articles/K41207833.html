Description

A list of attack signatures and the attack signature sets can be displayed in the Configuration Utility (GUI/WebUI). This can be useful when comparing signatures and/or sets between production and QA. By comparing the difference in signature sets, an administrator may prevent duplicates in signature names or applying signatures that already exist on both systems.

Prerequisites

You must meet the following prerequisite to use these procedures:
  • You have access to the BIG-IP ASM/AdvWAF Configuration Utility.
Procedure

The steps are virtually the same for versions 13.x to 16.x to view the Attack Signature Sets. What is displayed is the same from version 13.1.x to 15.1.x. Starting in version 16.1.x the format and the information provided has changed.

  1. To view the Sets go to Security  ››  Options : Application Security : Attack Signatures : Attack Signature Sets
    1. From there you can choose which set to view by clicking on the name of the set.
    2. When the name has been click on a break down of the set will display.
  • Signature Set Properties
    • Name: Displays the name of the signature set.
    • Type: Indicates that the system created this signature set by using the filter options
    • Default Blocking Actions: Displays the default Learn, Alarm, and Block settings for attack signatures included in the signature set.
      • For Blocking:
        • Yes specifies the system blocks all requests that match a signature, and provides the client with a support ID number
        • No specifies the system accepts those requests.
    • Assign To Policy By Default: Indicates whether the system assigns this signature set to a new created security policy by default (Yes), or does not (No).
  • Signatures Filter
    • Signature Type: Displays what the signatures in the signature set are configured to inspect: requests (Request), responses (Response), or both (All).
    • Attack Type: Displays what the signatures in the signature set provide protection against. Whether that is specific or all.
    • Systems: Displays which systems (for example, operating systems, web servers, languages, frameworks, applications, and database servers) the signatures in the signature set provide protection against. Whether that is specific or all.
    • Accuracy: Displays whether the signatures in the signature set provide protection with a specific accuracy level of identifying attacks (Low, Medium, High) or provide protection against all attacks (All).
    • Risk: Displays whether the signatures in the signature set protect against attacks of a specific comparison type (Less Than, Equal to, or Equals), and a risk level (Low, Medium, High), or provide protection against all attacks regardless of their risk levels (All).
    • User-defined: Displays whether the signatures in the signature set are only system-defined signatures, only user-defined signatures, or both (All).
    • Update Date: Displays whether the signatures in the signature set are limited to those updated before or after a specific date, or not limited by updated date (All).
  • Signatures
    • The list of signatures assigned to the set.
Note: There is an option here to 'Delete"  sets. When attempted the system prompts you to confirm the deletion. You cannot remove a system-supplied signature set. This function only works with custom sets.To create a set consult the applicable manual chapter for the version in use.

The list of attack signatures is accessed much the same way but has several filtering options. Here, also, starting in version 16.1.x the format has been updated and includes additional information.
  1. To view the list of attack signatures go to Security  ››  Options : Application Security : Attack Signatures : Attack Signature List
    1. In the basic view there is a list of signatures with a dropdown available that provides some simple categorization that can be used to search on.
    2. There are several other options to refine the search. Those can be accessed by either choosing "Advanced Filter" in the dropdown or by clicking the "Show Filter Details" link next to the dropdown window.
      1. When using the Advanced Filter options you can refine the search based on...
  • Containing String: Specifies whether the screen displays signatures based on a specified string found in the signature name.
  • Signature ID: Specifies whether the screen displays signatures based on their ID number. (The system automatically provides the signature ID which cannot be changed.)
  • Signature Type: Specifies what type of signatures the system displays:
    • All: Specifies all signatures, which is the default.
    • Request: Specifies that signatures that are configured to inspect the client request.
    • Response: Specifies signatures that are configured to inspect the server response.
  • Signature Scope: Specifies whether the system displays all signatures, or only those that do, or do not, apply to parameters, cookies, XML documents, JSON data, GWT data, headers, URI content, and request or response content.
  • Attack Type: Specifies whether the screen displays signatures based on their attack type.
  • Systems: Specifies whether the screen displays signatures based on the system for which they were configured. The list of systems includes operating systems, web servers, languages, frameworks, applications, and database servers.
  • Accuracy: Specifies how the screen displays signatures based on their accuracy level. Select how the signature relates to an accuracy association from the first list, and select an accuracy level from the second list.
    • All: Specifies signatures that match all accuracy levels, which is the default.
    • Equals: Specifies signatures whose accuracy levels exactly the accuracy level you set.
    • Greater Than/Equal To: Specifies signatures whose accuracy levels are more precise than, or the same as, the accuracy level you set.
    • Less Than/Equal To: Specifies signatures whose accuracy levels are less precise than, or the same as, the accuracy level you set.
    • Accuracy level:
      • Low indicates a high likelihood of false positives.
      • Medium indicates some likelihood of false positives.
      • High indicates a low likelihood of false positives.
  • Risk: Specifies how the screen displays signatures that protect against attacks of a specific risk level. Select how the signature relates to a risk association from the first list, and select a risk level from the second list.
  • User-defined: Specifies whether the screen displays signatures based on who created them.
  • Update Date: Specifies whether the screen displays signatures based on the date the signature was changed.
  • References
Note: There is an option here to 'Delete" signatures. When attempted the system prompts you to confirm the deletion. In addition, after clicking Delete you have the option to Auto apply signatures configuration after delete. If you enable this option, the system automatically applies this signature’s configuration to all active security policies that have signature sets assigned to them that contain this signature. The default setting is disabled. You can remove only user-defined signatures.
