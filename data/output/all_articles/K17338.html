Known Issue

Extra periods ".." or a dash "-" in SSL certificate/key names may cause a configuration load failure after you upgrade.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration contains a Secure Socket Layer (SSL) profile that uses a certificate/key pair that has an extra period or a dash in the name.

    For example:

    ltm profile client-ssl myclientssl1 {
        app-service none
        cert default..crt
        defaults-from clientssl
        key default..key
    }

    or

    ltm profile client-ssl myclientssl2 {
        app-service none
        cert default-test.crt
        defaults-from clientssl
        key default-test.key
    }

  • You upgrade the BIG-IP system from BIG-IP 11.4.1 or earlier to BIG-IP 11.5.x or 11.6.x.

In BIG-IP versions before 11.5.0, the ClientSSL profile only supports one SSL certificate/key pair. Beginning in 11.5.0 you can configure multiple SSL certificate/key pairs with the ClientSSL profile. When the 11.5.x and 11.6.x upgrade script processes an 11.4.1 or earlier configuration the system creates a cert-key-chain object in the profile configuration and gives the object an object name. However, if the certificate or key have and extra period ".." or a dash "-" in the name, the upgrade script will fail to create an object name for the cert-key-chain object. As a result, the configuration fails to load.

Impact

The BIG-IP configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After upgrading to BIG-IP 11.5.x or 11.6.x, the configuration fails to load.
  • A user configuration set (UCS) file from BIG-IP 11.4.1 or earlier fails to load on BIG-IP 11.5.x.
  • You receive an error message similar to the following example:

    Syntax Error:(/config/bigip.conf at line: 111) one or more configuration identifiers must be provided.

Workaround

Recovering from the issue

You can recover from the issue by manually editing the /config/bigip.conf file, modifying the affected Client SSL profile, and reloading the configuration again. To do so, perform the following procedure:

Impact of workaround: Because the BIG-IP system failed to load the configuration, the system should be in INOPERATIVE mode at this stage. Therefore, performing this procedure should not have any further impact on the BIG-IP system.

  1. Log in to the BIG-IP system command-line prompt.
  2. Create a backup copy of the /config/bigip.conf configuration file by typing the following command:

    cp -a /config/bigip.conf /var/tmp/sol17338_backup_bigip.conf

  3. Use a text editor of your choice to modify the /config/bigip.conf configuration file, and locate the cert-key-chain object within the configuration stanza of the affected Client SSL profile.

    For example:

     ltm profile client-ssl /Common/myclientssl {
            app-service none
            defaults-from /Common/clientssl
            cert-key-chain {
                 {                
                    cert /Common/mycert..crt
                    key /Common/mycert..key
                }
            }

  4. Modify the cert-key-chain object within the stanza and insert a name for the cert-key-chain object similar to the following example:

    Note: In the following example, a cert-key-chain object with the name mycertchain was inserted into the configuration stanza.

    ltm profile client-ssl /Common/myclientssl {
            app-service none
            defaults-from /Common/clientssl
            cert-key-chain {
                 mycertchain {               
                    cert /Common/mycert..crt
                    key /Common/mycert..key
                }
            }

  5. Save the changes and exit the text editor.
  6. Reload the configuration by typing the following command:

    tmsh load sys config

  7. Optional: After the BIG-IP system has successfully loaded the configuration, you may revisit the affected Client SSL profile to make the appropriate changes to the certificate and key being used so they do not contain a double period ".." or a dash "-".

Avoiding the issue

To avoid this issue, before you attempt to upgrade to 11.5.x/11.6.x or install an affected 11.4.1 or earlier configuration on a boot location running 11.5.x or 11.6.x, re-import the affected SSL certificate and key pair with a name that does not include a double period ".." or a dash "-", then re-configure the affected Client SSL profile to use the renamed SSL certificate and key pair.

Impact of workaround: Performing this procedure may affect the incoming traffic to the virtual servers that are using the affected Client SSL profile. F5 recommends that you perform this procedure during a scheduled maintenance period.
