K06002086: Azure did not move IPs between NICs during failover

Description

When BIG-IP in Azure attempted to failover, the standby became active but did not move IPs between Azure NICs. We see the following error message in /var/log/restnoded/restnoded.log:

Tue, 28 Sep 2021 18:11:50 GMT - finest: [f5-cloud-failover] Function error, retrying: connect ECONNREFUSED 52.127.3.211:443 Retries left: 0
Tue, 28 Sep 2021 18:11:55 GMT - severe: [f5-cloud-failover] Failover initialization failed: connect ECONNREFUSED 52.127.3.211:443 Error: connect ECONNREFUSED 52.127.3.211:443

Environment

  • Azure
  • BIG-IP Virtual Edition
  • Cloud Failover Extension

Cause

It's likely BIG-IP is not allowing outbound connection via TCP port 443 to 52.127.3.211.
IP 52.127.3.211 belongs to Azure and these are likely Azure API endpoint which BIG-IP needs to communicate to. (could be any other Public IP)
 

Recommended Actions

  1. Check the the routing configuration on BIG-IP:
    [root@BIG-IP16-APM:Active:Standalone] config # ip route
    default via 10.154.191.254 dev mgmt  metric 4096  mtu 1500
    3.3.3.8/30 dev ha  proto kernel  scope link  src 3.3.3.9
    10.1.10.0/24 dev external  proto kernel  scope link  src 10.1.10.35
    10.1.20.0/24 dev internal  proto kernel  scope link  src 10.1.20.35
    10.154.128.0/18 dev mgmt  proto kernel  scope link  src 10.154.132.123
     
  2. As the output above shows it does not have a route for 52.127.3.211
     
  3. Try adding static route to 52.127.3.211 via mgmt interface on BIG-IP (provided that there's unrestricted outbound Internet access from mgmt subnet).
    From the bash you can run:
    tmsh create /sys management-route <name> network <destination network>/<netmask> gateway <management gateway>
    i.e.
    tmsh create sys management-route New_route network 52.127.3.211/255.255.255.255 gateway Your_GW_IP

    More information  K13284: Overview of management interface routing (11.x - 16.x)
     
  4. If this won't help, please provide tcpdump from BIG-IP showing communication with 52.127.3.211 and fresh QKView from HA peers after triggering failover.
    tcpdump -vni eth0 host Management_IP or host 52.127.3.211 -s0 -w /var/tmp/K06002086.pcap

    More information K411: Overview of packet tracing with the tcpdump utility to monitor the communication.
     
  5. If you need help please contact F5 Support and provide the information from K2633: Instructions for submitting a support case to F5
