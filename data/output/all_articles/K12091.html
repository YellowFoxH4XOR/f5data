Known Issue

This is the result of a known issue. When the MultiConnect feature is applied to a relative link in a web application, and the base URI for the link contains an encoded character, the BIG-IP WebAccelerator system may fail to un-encode the character when rewriting the link. This behavior may cause the BIG-IP WebAccelerator system to send non-compliant URLs to the client, and may result in page load issues.

For example, a site may serve a page (http://www.siterequest.com/index.htm) that consists of an absolute link to an image file as follows:

<html>
<body>
<p><img src=/myImages/image.jpeg></p>
</body>
</html>

When MultiConnect is enabled for an acceleration policy, the BIG-IP WebAccelerator correctly rewrites the link before sending it to the client as follows:

<html>
<body>
<p><img src=http://wa1.www.siterequest.com/myImages/image.jpeg></p>
</body>
</html>

However, the page may contain a relative link to the image file as follows:

<html>
<body>
<p><img src=image.jpeg></p>
</body>
</html>

If the base path to the image file contains a URL-encoded character (for example, the image file resides in a directory called /my@Images), the BIG-IP WebAccelerator system rewrites the link as follows:

<html>
<body>
<p><img src=http://wa1.www.siterequest.com/my@Images/image.jpeg></p>
</body>
</html>

RFC1738 specifies that certain characters are reserved and must be encoded in the URL. For example, the at ( @ ) symbol is a reserved character and must be encoded in the URL as %40. As a result, when the client attempts to access an image file using above non-compliant URL, the request fails.

F5 Product Development is tracking this issue as ID 336893 and was fixed in version 11.0.0 of WebAccelerator

Workaround

You can work around this issue by disabling the MultiConnect feature for the node matching the rewritten page. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. In the navigation pane, expand WebAccelerator and click Policies.

    The Policies screen displays a list of existing acceleration policies.
  3. Click the appropriate acceleration policy.
  4. On the Policy Tree, click the node for which you want to disable the MultiConnect feature.
  5. Select Acceleration Rules from the drop-down menu.
  6. Click the Assembly tab.
  7. Clear the Enable MultiConnect check box.
  8. Click Save.
