K10182: The X-PvInfo header may be inserted when the BIG-IP WebAccelerator is not enabled

Known Issue

This is the result of a known issue. When the BIG-IP WebAccelerator class is not enabled on a virtual server, the X-PvInfo header should not appear in the response. However, when RAM Cache is enabled, the X-PvInfo header may still appear in responses served by RAM Cache.

Note: The X-PvInfo header is inserted into HTTP responses to requests processed by the BIG-IP WebAccelerator. The X-PvInfo header contains information used to identify the nature of the response. For more information, refer to the Using X-PvInfo response headers section of the Configuration Guide for the BIG-IP WebAccelerator System.

F5 Product Development tracked this issue as CR120629 and it was fixed in BIG-IP WebAccelerator version 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing 10.x hotfixes on a Logical Volume Management (LVM) disk-formatted system, refer to in K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about installing 10.x hotfixes on a partitioned system, refer to K9819: Installing a BIG-IP version 10.x hotfix on a partitioned system.

Workaround

You can work around this issue by restarting the system. To do so, type the following command at the BIG-IP command line:

bigstart restart
