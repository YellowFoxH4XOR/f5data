Description

When running DNS query for SOA record with  DNSsec, you may find that the serial number is different with BIND.

Environment

  • BIG-IP DNS

  • DNSSEC

  • BIND

Cause

It is expected to see a different SOA serial number with BIND when you enable the zone transfer for the DNSsec zone.
The DNSSEC signing module keeps a separate SOA serial number for each configured zone, because it must update this number when DNSSEC records change (i.e., key rollover) and there is no mechanism to communicate such changes to the backend system. The backend system may be DNSX, local BIND, or a pool member that points to an external DNS server.The serial number updated only when changes done on the zone  in BIND. so you can see the xfr-primary-soa-serial and xfr-soa-serial out of sync quickly after configure.

tmsh list ltm dns dnssec zone
/Common/example.com {
    ds-algorithms { sha1 }
    keys {
        /Common/example.com_ksk
        /Common/example.com_zsk
    }
    xfr-primary-soa-serial 2021091110
    xfr-soa-serial 2021061739
}

 xfr-primary-soa-serial: The learned zone SOA serial number from the primary server.
 xfr-soa-serial:The advertised zone SOA serial number to all clients.
Recommended Actions

No action needed, it is expected behavior.
