Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when load balancing traffic to an unreachable pool member.

This issue occurs when the following conditions are met:

  • The virtual server references an iRule that selects the destination resource based on the IP tuple. For example, the node, or virtual iRule commands.
  • The selected resource is not on a directly connected network, and not currently reachable by the BIG-IP system.

Impact

The BIG-IP system is unable to process traffic while the TMM process restarts and the system fails over if it is configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process restarts, and the BIG-IP system temporarily fails to process traffic.
  • The BIG-IP system sends a SIGSEGV signal to TMM, resulting in a stack trace and core file.
  • The system logs the stack trace to the /var/log/tmm file.

Workaround

To work around this issue, you can verify that the BIG-IP system can correctly route to all destination resources.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
