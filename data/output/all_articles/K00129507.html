K00129507: Unable to pass ssh over cloud based IPsec tunnel in 1-arm setup

Description
Network protocol SSH (port 22) is not passed into an IPsec tunnel when 1-arm cloud deployments.

A tcpdump packet capture on the mgmt interface (eth0) shows TCP SYN packets arriving from the client, However, tcpdump on tmm (0.0) shows no SSH packets and the IPsec tunnel will not start, or will not encapsulate SSH over the established tunnel.
 

Environment

  • 1-arm cloud deployment.
  • BIG-IP terminates an IPsec tunnel.
  • A host inside the public cloud wants to SSH to a remote network via the BIG-IP's IPsec tunnel
 

Cause
By default ports 22 (SSH) and 8443 (HTTPS) are used by for management purposes and are handled differently when used in a 1-arm (single interface) deployment. This also means that traffic over port 8443 (the web UI management HTTPS port) is similarly affected.
 

Recommended Actions

Any one of the following workarounds will solve this problem:
  1. Change the default port used for SSH and/or HTTPS management, described in K27312387.
  2. Configure a virtual server and pool to listen on a non-standard port and translate to the standard port before passing into the IPsec tunnel.
  3. Deploy a BIG-IP image that has multiple interfaces (ie. do not use 1-arm).
