Description

You can configure the BIG-IP to send traffic to a specific pool member(s) (standby pool). The BIG-IP would only send traffic to this pool member(s) when the active pool member(s) goes down.

This article will discuss configuring a pool with 1 high priority pool member (active) and 1 lower priority pool member (standby).

Your pool can certainly have more than 2 members. You will need to assign the priority group as needed. More on that can be found in the About priority-based member activation section of the About Pools chapter of the BIG-IP Local Traffic Management: Basics manual.

Environment

  • BIG-IP
  • Active/Standby Pool Members
  • Priority Group

Recommended Actions

  1. Go to Local Traffic > Pools > Pool List.
  2. Select the pool name.
  3. Select Members.
  4. Next to Load Balancing Method, select a method from the drop-down menu. For more information about which one to choose, refer to K42275060: There are several Load Balancing Methods. Which one is best for your environment?.
  5. Next to Priority Group Activation, select Less than... from the drop-down menu, then type 1, next to Available Members. This indicates that the group must have a minimum of 1 available member before using the next priority group.
  6. Select Update.
  7. Under Current Members, select the pool member that you want to be the high priority pool member.
  8. In the Configuration section of the page, next to Priority Group, change the value to 10.
  9. Select Update.
  10. Return to the pool configuration and select pool member that you want to be the lower pool member. You can leave the default value 0 for Priority Group.

    Note: The numbers used for Priority Group are only used to designate which group of servers should be used first, beginning with the highest number values. For example, a pool of 10 servers (pool members) could have 3 pool members with a Priority Group of 15, 3 pool members with a Priority Group of 10, and 4 pool members with a Priority Group of 2. If Priority Group Activation is set to less than 2, then as long as there are at least 2 pool members in Priority Group 15 that are accepting traffic, none of the rest of the pool members in the other 2 groups will receive traffic from the virtual server. If the number of available servers in Priority Group 15 drops below 2, then all of the pool members in Priority Group 10 will become eligible to receive traffic from the virtual server, based on the load balancing algorithm of the pool, but none of the pool members in Priority Group 2 will receive traffic. In order for pool members in Priority Group 2 to receive traffic, groups 15 and 10 combined would need to have less than 2 available pool members.

Additional Information

About Priority Group Activation:

Specifies whether the system load balances traffic according to the priority number assigned to the pool member. The default is Disabled. Once you enable this setting, you can specify pool member priority when you create a new pool or on a pool member's properties screen. The system treats same-priority pool members as a group. To enable priority group activation, select Less than from the list, and in the Available Member(s) field, type a number from 0 to 65535 that represents the minimum number of members that must be available in one priority group before the system directs traffic to members in a lower priority group. When a sufficient number of members become available in the higher priority group, the system again directs traffic to the higher priority group.

About Priority Group Numbers:

Using the priority group feature, you can assign a priority number to the pool member. The BIG-IP system then distributes traffic in the pool according to the priority number that you assigned to the pool member.

For example, pool members assigned to group 3, instead of pool members in group 2 or group 1, normally receive all traffic. Thus, members that are assigned a high priority receive all traffic until the load reaches a certain level or some number of members in the group become unavailable. If either of these events occurs, some of the traffic goes to members assigned to the next higher priority group.

This setting is used in tandem with the pool feature known as priority group activation. You use the priority group activation feature to configure the minimum number of members that must be available before the BIG-IP system begins directing traffic to members in a lower priority group.
