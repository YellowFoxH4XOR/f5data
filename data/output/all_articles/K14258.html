Known Issue

Under rare conditions, the umem (variable) memory statistics may continually grow to high values over time. The system's method to increment and decrement umem memory statistics is flawed.

Impact

Over time, the system may become unresponsive or reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H412406 on the Diagnostics > Identified > Medium screen.
  • The system reports high memory utilization for the umem (variable) subsystem.

    For example:

    tmsh show /sys memory |grep umem

    name                 allocated    max_allocated   held     size  tot_allocs   cur_allocs
    ------------------- ----------   -------------   --------- ----- ------------ ----------
    umem (variable)      1502546096    1502549968     188263     1    61808437     1528631

  • Once memory utilization reaches the defined high-water mark, the system reports error messages to the /var/log/ltm file.

    The error messages appear similar to the following example:

    tmm warning tmm[8075]: 011e0002:4: sweeper_update: aggressive mode activated. (221088/260096 pages)
    tmm warning tmm[8075]: 011e0002:4: sweeper_update: aggressive mode deactivated. (221080/260096 pages)
  • Over time, the system becomes unresponsive or reboots due to memory exhaustion.

Workaround

To temporarily work around this issue, you can restart the TMM process. To do so, perform the following procedure:

Impact of workaround: Restarting TMM interrupts traffic processing, and you should perform this task in a maintenance window. In addition, restarting TMM temporarily mitigates the issue.

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    bigstart restart tmm
