Known Issue

This is the result of a known issue. If you configure a virtual server to use a SIP, RADIUS, or Diameter profile, and the virtual server sends traffic to a pool configured to use a load balancing mode other than Round Robin, the virtual server may send most of the requests to one server in the pool.

F5 tracked this issue as ID 291695 (formerly CR128272) and it was fixed in BIG-IP LTM version 11.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by using the Round Robin load balancing mode for pools to which SIP, RADIUS, or Diameter requests are load balanced.
