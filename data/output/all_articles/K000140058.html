K000140058: F5 DNS HTTPS monitor does not send client certificate chain

Type
Support Solution
Published
2024-06-19
Updated
2024-06-19
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.1
Source
https://my.f5.com/manage/s/article/K000140058

Description

Sending a client certificate chain is not supported when using the HTTPS monitor under DNS -> GSLB -> Monitors.


Environment

An F5 DNS configured to use a HTTPS monitor.


Cause

The native F5 DNS HTTPS monitor does not support sending a client certificate chain. The F5 DNS uses big3d to implement monitors and probers for its GLSB configuration objects. This does not apply to F5 BIG-IP monitors which uses bigd and can be configured using an LTM server SSL profile.



Recommended Actions

When the HTTPS monitor requirement needs a full client certificate, the F5 DNS can still use customized external monitors to implement a monitor that sends a full client certificate chain.


Here is an example of an external monitor (EAV) that uses curl to send a full chain to the monitored server along with the client certificate.


#!/bin/sh

# (c) Copyright 1996-2007 F5 Networks, Inc.

#

# @(#) $Id: http_monitor_cURL+GET,v 1.0 2007/06/28 16:10:15 deb Exp $

# (based on sample_monitor,v 1.3 2005/02/04 18:47:17 saxon)

#

# these arguments supplied automatically for all external monitors:

# $1 = IP (IPv6 notation. IPv4 addresses are passed in the form

#             ::ffff:w.x.y.z

#             where "w.x.y.z" is the IPv4 address)

# $2 = port (decimal, host byte order)

#

# Additional command line arguments ($3 and higher) may be specified in the monitor template

# This example does not expect any additional command line arguments

#

# Name/Value pairs may also be specified in the monitor template

# This example expects the following Name/Vaule pairs:

# URI = the URI to request from the server

# RECV = the expected response (not case sensitive)

#

# remove IPv6/IPv4 compatibility prefix (LTM passes addresses in IPv6 format)

IP=`echo ${1} | sed 's/::ffff://'`

PORT=${2}


PIDFILE="/var/run/`basename ${0}`.${IP}_${PORT}.pid"

# kill of the last instance of this monitor if hung and log current pid

if [ -f $PIDFILE ]

then

  echo "EAV exceeded runtime needed to kill ${IP}:${PORT}" | logger -p local0.error

  kill -9 `cat $PIDFILE` > /dev/null 2>&1

fi

echo "$$" > $PIDFILE


# send request & check for expected response

#curl -fNs http://${IP}:${PORT}${URI} | grep -i "${RECV}" 2>&1 > /dev/null

curl -vkfNs --tlsv1.2 --http1.1 https://${IP}:${PORT}${URI} --cert-type PEM -E /var/tmp/chain/allchain.pem --cacert /var/tmp/chain/allchain.pem | grep -i "${RECV}" 2>&1 > /dev/null



# mark node UP if expected response was received

if [ $? -eq 0 ]

then

  rm -f $PIDFILE

  echo "UP"

else

  rm -f $PIDFILE

fi

exit
