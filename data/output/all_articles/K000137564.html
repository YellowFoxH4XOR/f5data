Description

When processing input from a client request, iRules should validate the input to check it is a reasonable size before performing operations that may use significant levels of CPU and take excessive time. If an operation exceeds the tmm heartbeat timeout, tmm may be restarted.

TCL regular expressions are a common cause of issues, due to the length of time it can take to prepare the regular expression for use.

 

Environment

  • BIG-IP LTM
  • iRule processing on incoming requests

Cause

Customer iRules need to check untrusted input from requests and avoid operations that require CPU and could cause tmm to restart or a HA failover.

 

Recommended Actions

Always validate client-supplied data for reasonable length.

For example: HTTP::host is commonly referenced in HTTP_REQUEST events. RFC9110 does not specify a maximum length for the HTTP Host header.
A valid FQDN (which the host header is expected to contain) can be a maximum of 255 characters. Addition of a port specifier to the host header would lead to a maximum length of 261.

when HTTP_REQUEST {
  if { string length [HTTP::header] <= 1024 } {
    # host header is a reasonable length
    <perform operations including HTTP::header>
  } else {
   # drop the request because of excessive input in the Host header
  drop
  }
}
