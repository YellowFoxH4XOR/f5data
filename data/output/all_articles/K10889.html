Known Issue

This is the result of a known issue. The cmp processor option is not a valid option for the bigpipe virtual command. Beginning in BIG-IP version 9.4.0 with the introduction of CMP, the manual page for the bigpipe virtual command erroneously indicates the cmp processor option may be used to specify and display the processor BIG-IP is using to process this virtual server's traffic, and the bigpipe command appears to accept the cmp processor option. However the command fails silently, displays inaccurate information, or produces a bigpipe parsing error message.

For example, using a cmp processor command that appears similar to the following example to force processing to one processor command fails silently, and traffic is still processed by all processors:

bigpipe virtual vs_test cmp processor 1.1

The documentation indicates that you can display the processor responsible for processing traffic for a virtual server using a command that appears similar to the following example:

bigpipe virtual vs_test cmp processor show

When this command is issued prior to a cmp processor command assigning a processor to a virtual server, output that appears similar to the following example is displayed, correctly indicating that the virtual server is not pinned to a specific processor, and traffic is being managed by all processors:

VIRTUAL vs_test - CMP Processor: none

However, when the cmp processor show option is executed after a cmp processor command assigning a processor to a virtual server, output that appears similar to the following example is displayed, incorrectly indicating that the virtual server is pinned to the specified processor:

VIRTUAL vs_test - CMP Processor: 1.1

The documentation further indicates that you can reset the cmp processor option to the default value of none using a command that appears similar to the following example:

bigpipe virtual test_vs cmp processor none

However, instead of restoring the default value, the command produces the following error message:

BIGpipe parsing error:
012e0022:3: The requested value (processor none) is invalid (show | enable | disable) for 'cmp' in 'virtual'

F5 Product Development is tracking this issue as ID 248952 (formerly CR97141).

Workaround

The mechanics of CMP processor assignment for virtual servers was automated before the product was released, and the need for the cmp processor command was deprecated before it was fully implemented. You may use the cmp and cmp mode options instead to enable and disable CMP, and to display the CMP status or mode of the virtual servers configured on the system.

  • To enable or disable CMP processing for a virtual server or for all virtual servers, use the following syntax:

    bigpipe virtual [VS_NAME | all] cmp [enable | disable]
  • To display the CMP status (enabled or disabled) for a virtual server or for all virtual servers, use the following syntax:

    bigpipe virtual [VS_NAME | all] cmp show
  • To display the CMP mode for a virtual server or for all virtual servers, use the following syntax:

    bigpipe virtual [VS_NAME | all] cmp mode show
