Topic

The BIG-IP OneConnect feature can increase network throughput by efficiently managing connections created between the BIG-IP system and back end nodes. OneConnect allows the BIG-IP system to minimize the number of server-side TCP connections by making existing idle connections available for reuse by other clients. The OneConnect source prefix length setting (source mask) manages connection reuse, and is applied to the server-side source IP address of a request to determine its eligibility for connection reuse.

Overview of the OneConnect source prefix length (source mask)

OneConnect applies the source prefix length or mask (much like applying an independent subnet mask) to client source IP addresses on server-side connections. This mask determines the availability of an existing idle TCP connection for the request on the selected destination server. The following list displays the idle TCP port reuse behavior. To simplify things, regarding these explanations, F5 assumes that a previous TCP request has established a connection on the destination server, the connection is idle, and the same destination server has been selected for a subsequent client request.

Note: If SNAT is configured, the BIG-IP system performs SNAT address translation on the source IP address, and then applies the OneConnect source prefix length to the translated SNAT IP address to determine whether it is eligible to reuse an existing idle connection. For more information about the OneConnect profile and SNATs, refer to K7208: Overview of the OneConnect profile.

OneConnect source prefix length (GUI/tmsh)OneConnect masking behavior
32 / 255.255.255.255

The entire client IP address is evaluated. A request from the same address reuses an established idle TCP connection.

24 / 255.255.255.0Octets 1-3 are evaluated client addresses matching this subset and reuse an existing idle TCP connection.
16 / 255.255.0.0Client addresses are evaluated based on the first and second octets when selecting an idle TCP connection for reuse.
8 / 255.0.0.0Only the first octet of a client IP address is evaluated when selecting an idle TCP connection for reuse.
0 / 0.0.0.0The all zeros mask (the default setting) looks for any open idle TCP connection on the destination server. The main difference is OneConnect does not attempt to group the request based on octets matched, but uses open idle TCP connections in a highly efficient manner.

Note: Using a broad mask may skew server-side statistical data. For example, when you use the mask 0.0.0.0, requests from multiple clients may appear as though they are originating from a single IP address.

Effects of modifying the source prefix length

The following three scenarios describe the effects of using different source prefix length values:

  • Using a OneConnect profile with a 0.0.0.0 source prefix length
  • Using a OneConnect profile with a 255.255.255.0 source prefix length
  • Using a OneConnect profile with a 255.255.255.255 source prefix length

Using a OneConnect profile with a 0.0.0.0 source prefix length

A OneConnect profile with a mask of 0.0.0.0 shares idle connections across all client requests in the following manner:

  • Client A with source IP address 10.10.10.10 connects to a virtual server.
  • The BIG-IP system load-balances the connection and applies the mask to the request on the server-side flow, finds no suitable connection for reuse, and creates a TCP connection to server A in the pool.
  • Client B with source IP address 10.20.20.20 connects to the same virtual server.
  • The BIG-IP system load-balances the connection, applies the mask to the server-side flow, and finds an eligible idle TCP connection.
  • The BIG-IP system aggregates the request from client B over the existing TCP connection that was created for client A.

Using a OneConnect profile with a 255.255.255.0 source prefix length

A OneConnect profile with a mask of 255.255.255.0 aggregates connections from client IP addresses sharing the same first 3 octets in the following manner:

  • Client A with a source IP address of 10.10.10.10 connects to a virtual server.
  • The BIG-IP system load-balances the connection and applies the mask to the request on the server-side flow, finds no suitable connection for reuse, and creates a TCP connection to server A in the pool.
  • Client B with a source IP address of 10.10.10.100 connects to the same virtual server.
  • The BIG-IP system load-balances the connection, applies the mask to the server-side flow, and finds an eligible idle TCP connection.
  • The BIG-IP system aggregates the request from client B over the existing TCP connection created for client A.
  • Client C with source IP address 10.10.20.10 connects to the same virtual server.
  • The BIG-IP system load-balances the connection, applies the mask to the server-side flow, and finds no suitable connection for reuse.
  • The BIG-IP system creates a new TCP connection to the selected pool member.

Using a OneConnect profile with a 255.255.255.255 source prefix length

A OneConnect profile with a mask of 255.255.255.255 will only aggregate connections originating from the same server-side client IP address.

Modifying the OneConnect source prefix length

Using the Configuration utility to modify the source prefix length

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Other > OneConnect.
  3. Select Create.
  4. Type a name for the OneConnect profile.
  5. Select the check box to customize the Source Prefix Length setting.
  6. For Source Prefix Length select Specify.
  7. Next to Specify, select IPv4 or IPv6.
  8. Enter the prefix length that you want to use as the source mask. The length must be the number of set bits in a bitmask between 0 and 128 for IPv6 or between 0 and 32 for IPv4.
  9. Select Finished.

You must now associate the new OneConnect profile with the virtual server.

Using tmsh to modify the source mask

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Create a new OneConnect profile from the default template, modifying the OneConnect mask using the hexadecimal format for IPv6 and the dotted decimal format for IPv4, by using the following command syntax:

    create /ltm profile one-connect <new-oneconnect-profile-name> defaults-from oneconnect source-mask <mask-preference>

    For example:

    create /ltm profile one-connect example defaults-from oneconnect source-mask 255.255.255.0

  3. Save the change by typing the following command:

    save /sys config

You must now associate the new OneConnect profile with the virtual server.
