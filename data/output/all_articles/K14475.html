Issue

Error Message

SNMP TRAP: omTransactionsRaise (430) : The switch has detected more outstanding configuration database transaction(s) than the configured threshold. These transaction(s) have been open for a period of time.

Message Location

You may encounter this message in the following location:

  • In the ARX syslog

Description

This message occurs when the following condition is met:

  • The configuration database has kept at least 100,000 transactions in memory over the last 30 minutes, indicating that an internal process is holding a transaction open for an excessive period of time.

Impact

Database performance slows and as the objMgr.db file footprint grows.  If the objMgr database continues to grow, the ARX system forcefully reboots and generates core files.

Recommended Actions

If the omTransactionsRaise error message continues in excess of seven days, rebuild the objmgr.db using one of the following procedures:

Rebuilding the objmgr.db

Impact of procedure:  Device and services will be unavailable during the procedure.

Important: You must complete this procedure on the standby ARX system to minimize downtime.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Save the startup configuration for recovery purposes, using the following command syntax:

    copy startup-config configs [filename].cfg

    For example:

    copy startup-config configs recovery_startup.cfg

  4. Save the global configuration as a precaution using the following command syntax:

    copy global-config configs [filename].cfg

    For example:

    copy global-config configs recovery_global.cfg

  5. Delete the system configuration by typing the following command:

    delete startup-config

  6. Reboot the ARX system by typing the following command:

    reload

  7. Configure the base ARX system using the saved running configuration file, by typing the following command syntax:

    run configs <running-config-name>

    For example:

    run configs recovery_startup.cfg

  8. To re-license the ARX system, refer to K12800: Overview of ARX licensing.
  9. Wait for switch replacement rendezvous and HA Pairing to complete.

    Note: After the rendezvous completes, the global configuration will synchronize to the standby system.

    .

Rebuilding the objmgr.db in ARX 6.1.1.HFRU-11

In ARX 6.1.1.HFRU-11, F5 has internal commands that will rebuilt the objmgr.db after an ARX system reboot. Contact F5 support to open a case and reference bug ID 420225.

Impact of procedure:  Device and services will be unavailable during the procedure.
