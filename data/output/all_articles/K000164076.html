Details

Description

The F5OS dashboard indicates that both tenant memory and global platform memory are operating near maximum capacity

Example Scenario: Active tenant memory consumption has peaked at 99%, while overall host platform memory allocation has reached 74%.

Figure:  Memory utilisation from the F5OS dashboard

 

 

Environment

  • F5OS-A
  • BIG-IP tenant on r-Series device
  • F5OS dashboard memory views: Tenant and System

Cause

 This is expected behaviour and does not indicate an issue. The memory utilisation shown on the F5OS dashboard reflects the memory allocated to the tenant, not the memory the tenant is actually using.

On the r-series platform, the maximum memory reserved for tenants is based on the model. If your tenant is configured to use the full Memory reserved for tenants, the dashboard will show 99-100% utilization.

Recommended Actions

To see actual memory utilisation, please check from within the tenant itself rather than from F5OS.

 

  1. Log into the F5OS CLI with admin access and run show commands to verify the allocated memory for the tenant device

        #show tenants

       Sample output. Look into the state memory value from the output

               state memory 24576     <<<< Allocated Memory for the Tenant

 

  1.  Log in to the Tenant CLI and run the command below to verify memory use

        #tmsh show sys memory

        Sample output,

Sys::System Memory Information

 ------------------------------------------------------------

Sys::Host Memory (bytes) 

------------------------------------------------------------

 Host: 0

Available 23.5G     <<<<< Allocated Memory for the HOST

Used 9.3G           <<<< Utilized Memory 

  1. If you compare the state memory with the sys memory, you will see that the high memory utilization in the output is caused by the maximum memory being allocated to the tenants, not by actual consumption.
