Description

You observed there were packets with source ip 127.0.0.1 sent out from BIG-IP system. From the packet capture, all the abnormal packets were DNS response packets.

Environment

  • BIG-IP DNS
  • BIND

Cause

The root cause of the issue is related to the handling of DNS query packets when the query goes to BIND. When the default connection idle timeout of 5 seconds (the default timeout value in UDP profile) is reached, the connection flow is deleted from the system's connection table. If the BIND process takes more than 5 seconds to reply, the system sends the packet directly back to the client with source IP 127.0.0.1, leading to unexpected behavior.

Recommended Actions

Typically, the BIND wouldn't take more than 5 seconds to proceed the query, but not definitely. 

If you indeed see those packets and don't want them been sent to client, you can increase the timeout value for UDP profile in the listener.

#tmsh modify ltm profile udp udp_gtm_dns idle-timeout 15

Note: The value 15 is an example, you can modify the timeout value based on your scenario.

Additional Information

When a DNS query arrivers BIG-IP listener, if it has to go to BIND, the listener sends the query packet which the source ip is listener and destination ip is 127.0.0.1 to BIND. After the BIND proceeded this query, it sends the response packet with source ip 127.0.0.1 to listener. Then the listener translates the source ip as its own ip and sends the response to client.
