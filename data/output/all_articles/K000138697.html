K000138697: HA goes to Active-Active state after reboot

Type
Support Solution
Published
2024-03-06
Updated
2024-03-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.2
Source
https://my.f5.com/manage/s/article/K000138697

Description

BIGIP HA devices becomes Active-Active after rebooting one of the devices instead of an Active-Standby.

  • The devices are in an Active-Active state after rebooting one of the devices in the Sync-Failover Device Group.
  • Device Management --> Overview shows a red diamond on the peer device and Traffic Group state shows Initializing / Not Synced.
  • tmsh show cm traffic-group shows Next Active as Offline.
  • Device Management --> Devices --> Self --> Failover Network configuration only has a TMM interface for communication.
  • Network --> Self-IPs --> Self-IP configured in Failover Network, Port Lockdown settings is set to Allow None after establishing Failover Network communications.

Environment

  • BIGIP LTM HA Pair

Cause

After the failover network communications have been established, the communication channel will still be present even after changing the Port Lockdown settings to Allow None. Because of this, the HA Pair will still be able to do failover activities.

Recommended Actions

Configure the Port Lockdown settings to allow UDP port 1026 connection between the configured TMM interface. You can configure this by configuring the Port Lockdown settings to Allow Default which includes ports that are usually used by BIGIP devices. If there is a need for more stringent configuration, you can configure a customized Port Lockdown Settings but make sure to allow UDP Port 1026. for the failover communication.
 

It is advisable to adhere to F5's best practice in configuring one TMM interface and the management IP for failover network configuration so in case of reachability issues on the TMM interface, the communication between the management-ip addresses will still be there and maintain the Active-Standby state.
