K000138872: [F5OS-C] Interface not marked down after removing/brocken optic/cable on VELOS platform, if the interface is the part of LAGs, impacting BIG-IP tenant connectivity for entire LAGs.

Type
Support Solution
Published
2024-03-11
Updated
2024-04-10
Applies to
  • VELOS Platforms
  • F5OS
  • F5OS-C: 1.6.X, 1.6.1, 1.6.0, 1.6.2
Source
https://my.f5.com/manage/s/article/K000138872

Description

Removed optic or cable from interface which is a member of a LAG used in a BIG-IP tenant.

Tenant connectivity was impacted for 1 minute or more. For example, monitors failed and virtual servers were unreachable.

System recovered, but interface remains incorrectly UP when viewed from VELOS partition GUI or when using the show interfaces summary command.

Note: LACP, if enabled, correctly removes the link from the aggregation, but the interface remains UP.

Environment

  • F5OS-C v1.6.x
  • VELOS
  • Removing/broken optic or cable from interface which is a member of LAGs.

 

Cause

  • Bug ID 1559525

This issue occurs after generating a partition qkview. The system will no longer detect link state events correctly.

 

Recommended Actions

  • To recover from the problem state you must reboot all blades which are assigned to the partition in which a qkview was generated. This is traffic impacting.
  • To prevent this issue occurring, apply the workaround described in Bug ID 1559525.
