Topic

By default, the BIG-IP ASM configuration allows certain HTTP response codes to pass through the BIG-IP ASM system to the client.

Description

By default, BIG-IP ASM allows the following HTTP response codes to pass through the BIG-IP ASM system to the client.

HTTP response codeCode definition
100-199Informational codes
200-299Status codes
300-399Redirect codes
400Bad request
401Unauthorized
404Not found
407Proxy Authentication Required
417Expectation failed
503Service unavailable

Note: For more information about HTTP codes, refer to RFC 2616.

All other HTTP response codes are blocked by the BIG-IP ASM system.

When the BIG-IP ASM system receives an HTTP response code that is not allowed, the system logs an error message similar to the following example:

Illegal HTTP status in response

You can configure the BIG-IP ASM system to allow additional HTTP response codes by adding the codes to the Allowed Response Codes section of the policy properties page. To do so, perform the following procedure:

  1. Log in to the Configuration utility of the BIG-IP ASM system as the admin or security admin user.
  2. Go to Security > Application Security > Security Policies.
  3. Select the Security Policy Name that you want to modify.
    • Select General Settings (15.x and later).
    • Select Advanced (14.x and earlier).
  4. Enter the new HTTP code that you want to add to the allowed configuration in the
    • Allowed Response Status Codes setting (14.x and later).
    • New Allowed Response Status Code setting (13.x and earlier).

    Note: Response codes 100 through 399 are automatically allowed by the system.

  5. Select Add.

    (Repeat steps 4 and 5 for each HTTP status code that you want to allow.)

  6. Select Save.
  7. Select Apply Policy.

Note: Response code 0 may appear in the Application Event Logs. This indicates there was no server response to the request and is expected when a request is blocked.
