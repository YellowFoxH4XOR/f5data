Topic

You should consider using these procedures under the following condition:

  • You want to automate archival of user configuration set (UCS) files on the BIG-IP system.

Description

This article shows you how to automate backups of the BIG-IP configuration by using the crontab utility to create UCS files and the logrotate utility to rotate the files.

Note: For information about other methods to automating backups of the BIG-IP configuration, refer to K78344940: Schedule automated UCS backups on the BIG-IP system.

You can do one or both of the following:

  • Follow the written steps in the Procedures section.
  • Watch the following videos for a brief demonstration of each procedure.
    •   Automating a local UCS archive and sending a copy to a remote system.
    •  Creating a custom logrotate entry to rotate the UCS files.
    •  Creating a custom logrotate entry to rotate the UCS files using iControl REST.

Important: You must perform the logrotate procedure to prevent excessive disk space consumption from the accumulation of UCS files.

F5 recommends that you save archived UCS files offsite for secure disaster recovery methods and leave a small number of recent backup UCS files locally since they can be used for testing or they can allow quick access to backups. The crontab procedure shows an option for using scp to store a copy of the UCS file on a remote system.

Note: You can use BIG-IQ Centralized Management to save and store UCS files offsite for production implementations.

Saving multiple UCS files locally can consume available hard drive space, depending on the size and number of UCS files saved. The larger the files, and the more frequently the files are created, the faster the disk space is used. Excessive use of the hard drive can impact the functions of the BIG-IP system. The following utilities can lessen the impact of archiving UCS files on the local system:

  • crontab

    Use the crontab utility to control the UCS file-creation frequency.

  • logrotate

    Use the logrotate utility to rotate the UCS files to save disk space.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have Advanced Shell (bash) access to your BIG-IP system.
  • You are proficient using a Linux text editor.

Procedures

  • Automate a local UCS archive and optionally storing a copy to a remote system
  • Create a custom logrotate entry to rotate the UCS files
  • Create a custom logrotate entry to rotate the UCS files using iControl REST

Automate a local UCS archive and optionally storing a copy to a remote system

Important: The following procedures produce a configuration that may not survive a software upgrade. You may need to repeat the procedures after you perform a software upgrade. Alternatively, these changes may persist after an upgrade if you include the edited files in a UCS file collection. For more information about modifying the contents of UCS files, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line as the root user.
  2. Create a directory for storage of the UCS files in the /var/ucs/ directory, by entering the following command:

    Note: The logrotate utility is prevented from making changes to the /shared/ directory by SELinux; therefore, creating a directory in the /var/ directory is recommended.

    mkdir -p /var/ucs

  3. Edit the root crontab file by entering the following command:

    crontab -e

    Note: This command invokes the vi text editor.

  4. Select one of the following entries to add to the root crontab file, depending on the frequency for which the UCS backup files are created:

    Note: The $(/bin/hostname) command substitution includes the fully qualified domain name (FQDN) of the BIG-IP system in the file name. Additionally, after rotation of previous instances of the UCS file, logrotate creates a 0-byte new file, which the crontab utility overwrites with the new UCS of the same file name at the configured time. If you configure this filename to have a unique entry, such as the date, then logrotate only overwrites and rotates it one time. This may result in an excessive number of saved files that are never removed, because each unique filename is treated as a set.

    Daily backup

    The following entry creates a UCS backup every day at 4:15 AM:

    15 4 * * * tmsh save /sys ucs /var/ucs/$(/bin/hostname).ucs

    Weekly backup

    The following entry creates a UCS backup once a week on Sunday at 4:15 AM:

    15 4 * * 0 tmsh save /sys ucs /var/ucs/$(/bin/hostname).ucs

    Monthly backup

    The following entry creates a UCS backup once a month on the first day of the month at 4:15 AM:

    15 4 1 * * tmsh save /sys ucs /var/ucs/$(/bin/hostname).ucs

    (Optional) Copying the UCS to a remote system

    Important: You must rotate the UCS files on the remote system to avoid the files accumulating and consuming excessive disk space. Refer to the vendor documentation of your remote system for instructions describing how to perform this task.

    1. Ensure that you have public key-based authentication set up between the BIG-IP system and the remote system so the scp program can automatically log in. For more information, refer to K13454: Configuring SSH public key authentication on BIG-IP systems.
    2. To use scp to copy the UCS to a remote system after it has been generated, replace the command portion of the any of the previously shown crontab entries with the following command string:

      tmsh save /sys ucs /var/ucs/$(/bin/hostname).ucs && scp /var/ucs/$(/bin/hostname).ucs <remote user name>@<remote system IP address>:/<remote directory>/$(/bin/hostname)-$(date +\%Y-\%m-\%d).ucs

      For example:

      tmsh save /sys ucs /var/ucs/$(/bin/hostname).ucs && scp /var/ucs/$(/bin/hostname).ucs root@10.1.1.1:/root/$(/bin/hostname)-$(date +\%Y-\%m-\%d).ucs

      An example within the crontab file:

      15 4 * * 0 tmsh save /sys ucs /var/ucs/$(/bin/hostname).ucs && scp /var/ucs/$(/bin/hostname).ucs root@10.1.1.1:/root/$(/bin/hostname)-$(date +\%Y-\%m-\%d).ucs

      Note: The && characters in the command tell the shell to execute the next command after the first command successfully completes. The date command substitution includes the current date in the filename. The % characters are escaped in the date command to prevent crontab from converting them to newline characters.

  5. To enter insert mode, enter i in the editor.
  6. On a new line in the root crontab file, enter one of the options listed in step 4, or refer to the Creating a custom archive schedule procedure in this article to configure a custom schedule that meets your needs.

    For example:

    MAILTO=""
    1-59/10 * * * * /usr/bin/diskmonitor
    0 */4 * * * /usr/bin/diskwearoutstat
    59 03 * * * /usr/bin/updatecheck -a
    00 04 19 * * /usr/bin/phonehome_upload
    0 */6 * * * /usr/bin/coreexpiration
    54 * * * * /usr/bin/copy_rrd save

    15 4 * * 0 tmsh save /sys ucs /var/ucs/$(/bin/hostname).ucs

  7. Select the ESC key to exit from insert mode in the vi editor.
  8. Save the modifications and exit the vi editor by entering the following command and selecting the Enter key.

    :wq

  9. Confirm the changes to crontab by entering the following command:

    crontab -l

Create a custom logrotate entry to rotate the UCS files

You can configure the logrotate utility to rotate UCS archive files in addition to log files. The UCS archive files placed in the /var/ucs/ directory are rotated by logrotate and appended with a number that indicates the status of the file rotation. The rotate <count> option specifies the number of times log files are rotated before being removed. If the rotate option is omitted, files are archived for a period of 24 days by default and specified by the .1 through .24 extension appended to the file name. The current archive file does not contain a <number> extension. After 24 days, the last archive file is removed, and previous archive files are incremented by 1.

To configure log rotation, perform the following procedure:

Impact of procedure: Ensure you set the rotate <count> option to a number of file rotations that does not consume excessive disk space.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Edit the logrotate configuration by entering the following command:

    Note: The following command opens the logrotate configuration in the vi text editor:

    edit /sys log-rotate all-properties

  3. To enter insert mode, select the i key.
  4. Replace the syslog-include none line with the following:

    Note: The * in the filename tells logrotate to rotate all files ending with .ucs in the /var/ucs/directory. Rotated files are ignored since they end with a number such as .1.

    syslog-include "/var/ucs/*.ucs {
    nocompress
    missingok
    notifempty
    sharedscripts
    postrotate
    endscript
    rotate 2
    }"

    For example, the logrotate properties appear similar to the following example:

    modify log-rotate {
    common-backlogs 24
    common-include none
    description none
    include none
    mysql-include none
    syslog-include "/var/ucs/*.ucs {
    nocompress
    missingok
    notifempty
    sharedscripts
    postrotate
    endscript
    rotate 2
    }"
    tomcat-include none
    wa-include none
    }

  5. To exit from insert mode in the vi editor, select the Esc key.
  6. Save the modifications and exit the vi editor by entering the following command and select the Enter key:

    :wq

  7. A prompt similar to the following example gives you the option to save your modifications:

    Save changes? (y/n/e)

    Select the y key.

  8. Save the change by entering the following command:

    save /sys config

Create a custom logrotate entry to rotate the UCS files using iControl REST

Alternatively, you can configure the logrotate utility to rotate UCS archive files using iControl REST.

Impact of procedure: Ensure you set the rotate <count> option to a number of file rotations that does not consume excessive disk space.

  • To configure the syslog-include property with the example settings shown in step 4 of the previous procedure, use the following command syntax:

    curl -sku <user>:<passwd> https://<management interface>/mgmt/tm/sys/log-rotate -X PATCH -H "Content-type: application/json" -d '{ "syslogInclude": "/var/ucs/*.ucs {\n    nocompress\n    missingok\n    notifempty\n    sharedscripts\n    postrotate\n    endscript\n    rotate 2\n }"}'

    • <user>:<passwd> are the user credentials with permission to access the iControl REST API on the BIG-IP system.
    • <management interface> is the IP address or domain name of the target BIG-IP system.

    For example:

    curl -sku admin:admin https://172.16.1.1/mgmt/tm/sys/log-rotate -X PATCH -H "Content-type: application/json" -d '{ "syslogInclude": "/var/ucs/*.ucs {\n    nocompress\n    missingok\n    notifempty\n    sharedscripts\n    postrotate\n    endscript\n    rotate 2\n }"}'

  • To save the configuration change to disk, use the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/json" -X POST https://<target BIG-IP hostname or IP address>/mgmt/tm/sys/config -d '{"command":"save"}'

    For example:

    curl -sku admin:admin -H "Content-Type: application/json" -X POST https://172.16.1.1/mgmt/tm/sys/config -d '{"command":"save"}'

Creating a custom archive schedule

You can customize the archive schedule by setting specific values for the date and time fields in the crontab file. The first five columns in each line represent the time and date on which the action in the sixth column is executed. The time and date fields are as shown in the following table.

FieldPossible values
minute0 through 59
hour0 through 23
day of month1 through 31
month1 through 12, or the first three letters of the month (not case sensitive).
day of week0 through 7, or the first three letters of the day (not case sensitive). Sunday is numerically represented by both 0 and 7. Therefore, for Sunday, you can enter any of the following three values: 0, 7, or Sun.
  • A field may be an asterisk ( * ), which always stands for first through last.
  • Number ranges are allowed. Ranges are two numbers separated with a hyphen. The specified range is inclusive. For example, 8-11 for an hours entry specifies execution at hours 8, 9, 10, and 11.
  • Lists are allowed. A list is a set of numbers (or ranges) separated by commas. For example: 1,2,5,9 or 0-4,8-12.
  • You can use step values in conjunction with ranges. Following a range with /<number> specifies skips of the number's value through the range. For example, you can use 0-23/2 for hours to specify command execution every other hour. Steps are also permitted after an asterisk. Therefore, if you want to say every two hours, use */2
  • Ranges or lists of names are not allowed.
