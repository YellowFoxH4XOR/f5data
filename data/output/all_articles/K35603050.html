Topic

You should consider using this procedure under the following condition:

  • You want to configure the nameserver of the auto-generated zones for the BIG-IP DNS wide IPs.

Description

Starting in BIG-IP 14.1.0, you can configure the nameserver of the zones that are auto-generated whenever you create a wide IP on the BIG-IP DNS system. You can do so by setting the value of the Wide IP Zone Nameserver setting in the Configuration utility or the wideip-zone-nameserver setting in the TMOS Shell (tmsh) utility with the name you want. The default value of this setting is set to this.name.is.invalid. which is in accordance with the specifications in RFC 2606: Reserved Top Level DNS Names and RFC 6761: Special-Use Domain Names. If you perform a manual zone transfer using the dig utility, you will observe output similar to the following example:

# dig axfr @localhost f5networks.test
 
; <<>> DiG 9.11.19 <<>> axfr @localhost f5networks.test
; (1 server found)
;; global options: +cmd
f5networks.test. 500 IN  SOA this.name.is.invalid. hostmaster.this.name.is.invalid. 1 10800 3600 604800 60
f5networks.test. 0   IN  NS  this.name.is.invalid.
myhttp.f5networks.test.  0   IN  A   192.168.155.123
f5networks.test. 500 IN  SOA this.name.is.invalid. hostmaster.this.name.is.invalid. 1 10800 3600 604800 60
;; Query time: 0 msec
;; SERVER: 127.0.0.1#53(127.0.0.1)
;; WHEN: Mon Nov 23 23:10:58 PST 2020
;; XFR size: 4 records (messages 1, bytes 212)

Note in the previous example output that if you set the value of this setting with a trailing period(.), the system uses the value of this setting as is for the wide IP nameserver.

If you set the value of this setting without a trailing period(.), the wide IP zone nameserver will be a combination of the value you set and the zone name of the wide IP. For example, if you set the value of this setting to mytestns, and created a wide IP testhttp.example.test, then when queried, the system automatically responds with mytestns.example.test as the nameserver.

# dig axfr @localhost example.test  
 
; <<>> DiG 9.11.19 <<>> axfr @localhost example.test
; (1 server found)
;; global options: +cmd
example.test.        500 IN  SOA mytestns.example.test. hostmaster.mytestns.example.test. 1 10800 3600 604800 60
example.test.        0   IN  NS  mytestns.example.test.
mytestns.example.test.   0   IN  A   127.0.0.1
testhttp.example.test.   0   IN  A   50.50.155.123
example.test.        500 IN  SOA mytestns.example.test. hostmaster.mytestns.example.test. 1 10800 3600 604800 60
;; Query time: 0 msec
;; SERVER: 127.0.0.1#53(127.0.0.1)
;; WHEN: Mon Nov 23 23:18:21 PST 2020
;; XFR size: 5 records (messages 1, bytes 216)

Note that if you change the value of this setting after you have created your wide IPs, the system does not change the nameserver of the existing wide IP zones based on the new value and continues to base it on the value of the setting before you created the wide IP zones. Only newly created wide IP zones that were created after the change base their nameserver on the new value of the setting.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Have administrative access to either the Configuration utility or the tmsh utility.

Procedures

  • Configure the wide IP zone nameserver using the Configuration utility
  • Configure the wideip-zone-nameserver using the tmsh utility

Configure the wide IP zone nameserver using the Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to DNS > Settings > GSLB > General.
  3. Under the GSLB section, enter the value you want in the Wide IP Zone Nameserver setting.
  4. To save the changes, select Update.
  5. You can now create your new wide IP (zone).

Configure the wideip-zone-nameserver using the tmsh utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility.
  2. Modify the value of the wideip-zone-nameserver setting by entering the following command syntax:

    modify gtm global-settings general wideip-zone-nameserver <your desired nameserver name>

    For example, you would enter the following command to change the nameserver to mytestns.example.test.:

    modify gtm global-settings general wideip-zone-nameserver mytestns.example.test.

  3. Save your changes by entering the following command:

    save sys config

  4. To view the new value of the setting, enter the following command:

    list gtm global-settings general wideip-zone-nameserver

    The command should return output similar to the following example:

    gtm global-settings general {
        wideip-zone-nameserver mytestns.example.test.
    }
