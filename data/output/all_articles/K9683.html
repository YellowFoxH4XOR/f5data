Known Issue

This is the result of a known issue. When the 32 bit Linux uptime counter wraps around to 0 (zero) on a BIG-IP system licensed for the GTM or Link Controller modules, the communication between the lacpd process and TMM stops and never resumes. As a result, the gtmd, tmm, or bcm56xxd daemons may crash.

F5 Product Development tracked this issue as CR78692, and it was fixed in BIG-IP 9.4.2. For information about upgrading, refer to the BIG-IP LTM, GTM, or Link Controller Release Notes.

This issue has been fixed in Hotfix-BIG-IP-9.3.1-HF5 issued for BIG-IP 9.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K6845: Managing F5 product hotfixes.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Note: F5 Product Development is separately tracking the root cause of this issue, the Linux uptime counter wrap, as CR74550. For more information, refer to K7036: The Linux uptime counter wraps after 497 days.

Workaround

You can work around this issue when it is encountered on a system with an uptime of 497 days or more by rebooting the system. Alternatively, you can avoid this issue by rebooting the system prior to the 497 day counter wrap.

Note: For platforms with Switch Card Control Processor (SCCP), reboot the system using the full_box_reboot command.

To determine how long the system has been up, use the Linux uptime command. The uptime command produces output that appears similar to the following example:

19:52:48 up 20 days, 9:24, 1 user, load average: 0.09, 0.05, 0.11

Note: For platforms with SCCP, execute the uptime command while logged in to the SCCP.
