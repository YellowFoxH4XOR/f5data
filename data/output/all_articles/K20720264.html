Description

Saving BIG-IP archives off-box from the BIG-IQ fails

Environment

  • BIG-IQ with setting to archive backup files to an sftp server
  • BIG-IP ucs files
  • SFTP server

Cause

SFTP requires ciphers not offered by BIG-IQ
 

Recommended Actions

  1. Determine reason for failure by attempting to connect to the sftp server from the BIG-IQ manually (command line)
    1. from a BIG-IQ bash shell prompt. cd /shared/ucs_backups
    2. ls and pick an existing backup filename
    3. sftp (username@sftp server) - for example, sftp f5backup@10.10.10.10
    4. cd to the expected location on the sftp server (example, cd /backups)
    5. put <the filename you chose>
  2. Take note of the error.  It may be something like:
    no matching cipher found: client aes128-cbc,aes256-cbc server chacha20-poly1305@openssh.com,aes256-gcm@openssh.com,aes128-gcm@openssh.com,aes256-ctr,aes192-ctr,aes128-ctr Connection closed
  3. If the error listed in step 2 matches, edit /config/ssh/ssh_config on the BIG-IQ and remove these two lines:
    Ciphers aes128-cbc,aes256-cbc KexAlgorithms diffie-hellman-group14-sha1,ecdh-sha2-nistp256,ecdh-sha2-nistp384,ecdh-sha2-nistp521

Additional Information

Another error that can be seen is "Signature encoding error"

This happens because the SFTP server is using a key signature that the BIG-IQ java library does not support, such as rsa-sha2-256.  We recommend to use an ECDSA key on the SFTP server such as 

  • ecdsa-sha2-nistp256
  • ecdsa-sha2-nistp384
  • ecdsa-sha2-nistp521
