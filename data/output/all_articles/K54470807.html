Description

MS recently disclosed CVE-2022-41082 and CVE-2022-41040 related to Zero-day Vulnerabilities in Microsoft Exchange Server. F5 has released attack signatures update  "20221002_103111" that includes attack signatures 200103289 and 200018137 to mitigate these MS Exchange CVEs. 

Update: Attack signature update file "20221003_164058" improves attack signature 200103289 from recently discovered bypass/evasion attempts.

Environment

BIG-IP ASM Module provisioned 
ASM/Adv WAF Security Policy configured and applied to Virtual Server fronting MS Exchange 
Virtual Server fronting MS Exchange 

Cause

You are looking to mitigate CVE-2022-41082 and CVE-2022-41040 through the BIG-IP 

Recommended Actions

Update BIG-IP ASM / Adv WAF attack signatures and review if attack signatures 200103289 (for CVE-2022-41082 , Microsoft Exchange Powershell Remote Code Execution from Command Execution Signature Set) and 200018137 (for CVE-2021-34473, CVE-2022-41040, Microsoft Exchange ProxyShell SSRF from Other Application Attacks Signature Set) are included and in "Enforced" state in your Attack Signatures BIG-IP ASM Security policy configuration.

For procedure and guidance updating the attack signatures, refer to K82512024: Managing BIG-IP ASM Live Updates (14.1.x and later)

If your BIG-IP has no ASM/Adv WAF provisioned, you can apply an iRule to a Virtual Server fronting MS Exchange server to check and drop attempts to access URL containing the strings ".*autodiscover\.json.*\@.*Powershell.*" as per regular expression from the MSRC blog. 

Update: Recent mitigation bypass was discovered for the reference regex from the MSRC blog. ".*autodiscover\.json.*Powershell.*" is the suggested modified regex to address bypass. 
Update: Another bypass was discovered due to encoded URIs, therefore, the URI needs to be decoded before checking. See updated iRule snippet below which includes a URI::decode command and additional URI normalization.

The iRule from https://github.com/ashishmgupta/F5iRuleForProxyNotShell may be used.
Note: The reference iRule is community supported. It is recommended to test it per your needs. 

Update: Should you have used the reference iRule from the github page, the regex syntax needs to be updated.

if { [string tolower [URI::decode [HTTP::uri -normalized] ] ] matches_regex {.*autodiscover\.json.*powershell.*} }
