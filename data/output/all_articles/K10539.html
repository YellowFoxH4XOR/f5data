Known Issue

This is the result of a known issue. Since Domain Name System (DNS) names are case insensitive, the BIG-IP GTM system should preserve but ignore their case. For example, example.com should be treated the same as EXample.com. However, ZoneRunner does not compare wide IP names and zone names in a case-insensitive manner.

When a new wide IP is created, ZoneRunner checks whether the appropriate parent zone already exists. If the parent zone does not exist, it is automatically created and the wide IP is added as an A record under the zone. For example, if the wide IP www.example.com is created, ZoneRunner will automatically create the example.com parent zone (if it does not already exist) and then will add the www.example.com A record under it. However, if you create the EXample.com zone in ZoneRunner and then the www.example.com wide IP, instead of adding the www.example.com A record under the EXample.com zone, the BIG-IP GTM system will try to create the EXample.com zone. This will fail, because the named process correctly recognizes that EXample.com and example.com are identical.

ZoneRunner will also log an error message to the /var/log/gtm file that appears similar to the following example:

err zrd[1628]: 0115020b:3: Errors in config file named.conf:63: zone 'example.com': already exists previous definition: /tmp/named.conf.tmp.LKI7Hx:56.

This issue may possibly result in the issue described in K9595: Creating a wide IP without a first-level domain name may cause ZoneRunner to create a top-level domain entry in the BIND database. For example, if the EXample.com zone is created in ZoneRunner and then the example.com wide IP is created, ZoneRunner will not add the example.com A record under the EXample.com zone. ZoneRunner will instead create the .com parent zone, possibly resulting in an outage.

F5 Product Development tracked this issue as ID 247684 (formerly CR128286) and it was fixed in BIG-IP 10.2.1. For information about upgrading, refer to the BIG-IP GTM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP 10.2.0, and in Hotfix-BIGIP-10.1.0-3402.0-HF2 issued for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing a hotfix, refer to K10025: Managing BIG-IP product hotfixes (10.x).

Workaround

You can work around this issue by using consistent case between ZoneRunner and the wide IP section in the Configuration utility.
