Known Issue

The BIG-IP system may fail to attempt recovery of a stalled compression hardware device.

This issue occurs when all of the following conditions are met:

  • You are running one of the following:

    • The BIG-IP 5000, 7000, 10000, or 12000 series platforms.
    • The VIPRION chassis with B22xx blades.
  • Your BIG-IP system is configured with a virtual server with compression enabled.
  • The compression hardware device stalls while attempting to process compressed data (for example, while attempting to decompress and invalid compression stream).

Impact

Compression hardware remaining stalled may result in degraded performance or interruptions in traffic processing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the var/log/ltm file, you observe critical error messages similar to the following example:

    crit tmm[8971]: 01010025:2: Device error: n3-compress0 Nitrox 3, Hang Detected

  • Performance is degraded when connecting to the affected virtual server.

Workaround

To work around this issue, you can configure the BIG-IP system to perform only software compression so that TMM processes all hardware compression operations. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system's CPU usage may increase over time due to the additional processing handled by TMM. The full impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Configure the BIG-IP system to use software compression by typing the following command:

    modify /sys db compression.strategy value softwareonly

  3. Save the change by typing the following command:

    save /sys config
