Known Issue

Changing a virtual server's configuration may result in dropped packets. This issue is known to occur after changing the VLAN configuration for the DHCP Relay virtual server type.

Impact

The virtual server fails to pass traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H411063 on the Diagnostics > Identified > Medium screen.
  • The virtual server silently drops packets.
  • Packet captures indicate that the system receives the ingress packets, but does not send the egress packets to the server.

Workaround

To work around this issue, you can temporarily change the virtual server IP address and then change it back again. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the tmsh shell by entering the following command:

    tmsh

  2. To temporarily change the virtual server IP address, use the following command syntax:

    modify /ltm virtual <virtual_name> destination <new_IP:port>

    For example, to temporarily change the IP address for a DHCP Relay virtual server called DHCP_virtual (255.255.255.255:67), you would enter the following command:

    modify /ltm virtual DHCP_virtual destination 255.255.255.254:67

  3. Save the configuration by entering the following command:

    save /sys config

  4. To change the virtual server IP address back to the original, use the following command syntax:

    modify /ltm virtual <virtual_name> destination <orig_IP:port>

    For example, to change the IP address back to the original, you would enter the following command:

    modify /ltm virtual DHCP_virtual destination 255.255.255.255:67

  5. Save the configuration by entering the following command:

    save /sys config
