K000152860: Troubleshooting Azure BIG-IP HA Failover Issues

Type
Support Solution
Published
2025-08-02
Updated
2025-08-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000152860

Description

When performing a high availability (HA) failover on BIG-IP LTM devices deployed in Microsoft Azure, traffic may not shift to the new active device as expected after an upgrade or configuration change. This issue is often accompanied by errors in the /var/log/restnoded/restnoded.log such as:

severe: [f5-cloud-failover] Failover initialization failed: connect ECONNREFUSED <IP_ADDRESS>:443

severe: [f5-cloud-failover] This operation is not permitted as the blob is immutable due to one or more legal holds.

severe: [f5-cloud-failover] uploadDataToStorage error: This operation is not permitted as the blob is immutable due to one or more legal holds.

Symptoms include:

  • No traffic received on the newly active device after failover.
  • Packet captures show no incoming packets post-failover.
  • CFE (Cloud Failover Extension) logs indicate connectivity or storage errors.

Environment

  • Product: BIG-IP LTM Virtual Edition
  • Platform: F5-LTM-3G-PRM-SUB, BIG-IP running in Microsoft Azure
  • Software Versions: 16.1.3.x, 17.1.2.x (and possibly others)
  • Configuration: HA pair using Cloud Failover Extension (CFE) for Azure
  • Azure Storage Account used for CFE state tracking
  • Firewall rules controlling access to Azure management endpoints and storage accounts.

Cause

Common root causes identified include:

  • The Azure storage account used by CFE had a legal hold policy, making blobs immutable and preventing updates required for failover state tracking.
  • Required outbound access from BIG-IP to Azure management endpoints was blocked by firewall rules, preventing CFE from communicating with necessary APIs.
  • Outdated or misconfigured Cloud Failover Extension (CFE), including missing debug logging settings or incorrect declaration parameters.
  • After upgrading BIG-IP software, CFE may require reinstallation or reconfiguration to function properly.

Recommended Actions

  1. Remove Legal Hold Policy
    • Check that your Azure storage account does not have a legal hold or immutability policy that prevents blob updates.
    • Remove any such policies so that CFE can write its failover state.
  2. Whitelist Required Endpoints
    • Update firewall rules to allow outbound HTTPS (TCP/443) traffic from BIG-IP instances to all required Azure management endpoints (e.g., management.azure.com).
    • Test connectivity using curl https://management.azure.com/ -v --tlsv1.2 --resolve management.azure.com:<port>:<ip>, or telnet management.azure.com 443, commands from the BIG-IP shell.
  3. Update and Reinstall Cloud Failover Extension
    • Ensure you are running the latest supported version of CFE compatible with your BIG-IP release.
    • If issues persist after an upgrade, uninstall and reinstall CFE.
