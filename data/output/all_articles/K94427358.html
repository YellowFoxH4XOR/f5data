Topic

You should consider using this procedure under the following condition:

  • You are deploying or have deployed BIG-IQ Centralized Management Virtual Edition (VE) in an OpenStack environment.

Description

When you deploy BIG-IQ VE on OpenStack, BIG-IQ VE passes traffic through the tenant (or self-service) network. When performing this action, you should review some network considerations. In OpenStack networking, the Neutron service that takes care of the Layer 2 (L2) and Layer (L3) networking uses various types of overlay network technologies in the tenant network. Each type of overlay network has different protocol overheads. For example, the Virtual eXtended Local Area Network (VXLAN) has a protocol overhead of 50 bytes.

You may have to adjust the maximum transmission unit (MTU) on the ingress/egress interface/VLANs, depending on your model (simple, advanced, large-scaled, distributed management, and configuration) of BIG-IQ Centralized Management deployment to accommodate the protocol overhead of the overlay network. 

For example, if you are deploying the simple management and configuration model for BIG-IQ Centralized Management in an OpenStack environment using VXLAN, you need to configure the MTU size of the management interface on the BIG-IQ system to 1450 (assuming the physical network MTU size is 1500).

Conversely, if you are deploying the advanced or large-scaled distributed model for your BIG-IQ Centralized Management in a VXLAN OpenStack environment, you need to configure the MTU size of the management interface, in addition to the VLANs on BIG-IQ to 1450.

 

When deploying a BIG-IQ system in OpenStack, consider the following factors:

  • If your BIG-IQ system passes traffic through an OpenStack tenant network that uses some form of overlay network technologies such as virtual eXtended local area network (VXLAN), you may need to accommodate the overlay network protocol overhead by adjusting the maximum transmission unit (MTU) on the ingress/egress interface/VLANs. For more information, refer to K94427358: Configuring the MTU size on the BIG-IQ system when deploying in OpenStack.
  • If your BIG-IQ self IP address processes large data transfers while the router adjacent to the BIG-IQ system does not process IP fragments with both the Don't Fragment (DF) and More Fragment (MF) bits set, your BIG-IQ system may experience slowness in the data transfer or even data transfer failure. You may have to disable TCP segmentation offload (TSO) which is enabled by default using the command ethtool -K tmm tso off. For more information, refer to ID 875493 in Bug Tracker.

 

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have administrative access to the BIG-IQ command line and/or TMOS Shell.
  • You are planning to deploy or have deployed BIG-IQ 5.4.0 HF2 or later on the following OpenStack releases:
    • Pike
    • Ocata
    • Newton

Procedures

  • Configuring the MTU value of the management interface
  • Configuring the MTU of the VLAN

Configuring the MTU value of the management interface

You can configure the management interface MTU setting by adding the ifconfig command to the /config/startup file. To do so, perform the following procedure:

Note: You must use the ifconfig utility to change the MTU value for the management interface. You cannot change the MTU setting using tmsh.

Impact of procedure: The impact of the suggested workaround depends on the specific environment. F5 recommends testing the MTU change during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the BIG-IQ command line.
  2. To set the management interface to the desired MTU, use the following command syntax:

    /sbin/ifconfig eth0 mtu <mtu_value>

    For example, using the VXLAN overlay network protocol example, you would type the following command:

    /sbin/ifconfig eth0 mtu 1450

  3. Add the ifconfig command to the /config/startup file, which allows the MTU change to persist after a reboot.
    For information about configuring the BIG-IP system to execute a command at system startup, refer to K11948: Configuring the BIG-IP system to execute commands or scripts upon system startup.

Configuring the MTU of the VLAN

You can configure the MTU size of the desired VLAN using tmsh. To do so, perform the following procedure:

Impact of procedure: The impact of the suggested workaround depends on the specific environment. F5 recommends testing the MTU change during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To set the MTU value of the desired VLAN, use the following command syntax:

    modify /net vlan <vlan name> mtu <MTU size>

    For example, using the VXLAN overlay network protocol example, you would type the following command:

    modify /net vlan examplevlan mtu 1450

  3. Save the changes by typing the following command:

    save /sys config
