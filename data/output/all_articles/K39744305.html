Known Issue

If you attempt to modify the DNS options ndots:0 value, duplicate entries appear in the /etc/resolv.conf file.

This issue occurs when the following condition is met:

  • You attempt to modify the default DNS options nddots:0 value.

    For example, the issue occurs if you use any of the following commands:

    • tmsh modify sys dns include "options ndots:1"
    • bigpipe dns include '"options ndots:1"' (in 10.x only)

The options ndots:n value sets a threshold for the number of dots that must appear in a name before the system makes an initial absolute query. BIG-IP systems are configured with a default options ndots:0 value.

Impact

The system's DNS search domain behavior may be different than you expect with respect to ndots values.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system's DNS search domain behavior and resolutions may not perform as you expect.
  • It may appear that the system is ignoring DNS search domain lists.
  • If you attempt to modify the options ndots:0 value, the /etc/resolv.conf file displays duplicate ndots:n entries, and appears similar to the following example:

    #
    # THIS IS AN AUTO-GENERATED FILE -- DO NOT EDIT!!!
    #
    # Use the bigpipe shell utility to make changes to the system configuration.
    # For more information, see bigpipe dns help.
    #
    options ndots:0
    options ndots:1

Workaround

To work around this issue, you can manually update the ndots:n value in the /etc/resolv.conf and /defaults/config/templates/dns.tmpl files. To do so, perform the following procedure:

Impact of workaround: Performing the following workaround causes the sys-icheck -i command to fail with a security violation.

  1. Log in to the BIG-IP command line.
  2. Using a text editor such as vi or pico, open the /etc/resolv.conf file.
  3. Modify the options ndots:0 entry to use the value you want, such as options ndots:1.

    Note: If there are duplicate ndots:n entries, remove the duplicate entry.

  4. Save the /etc/resolv.conf file.

    Note: The /etc/resolv.conf file is an automatically generated file, and the system may overwrite the file when configuration changes occur. To ensure that any newly generated file will have the options ndots:n value you want, you must also edit the source template file (/defaults/config/templates/dns.tmpl).

  5. Mount the /usr filesystem with read/write permissions by typing the following command:

    mount -o remount,rw /usr

  6. Using a text editor such as vi or pico, open the /defaults/config/templates/dns.tmpl file.
  7. Modify the options ndots:0 entry to use the value you want, such as options ndots:1.
  8. Save the /defaults/config/templates/dns.tmpl file.
  9. Remount the /usr filesystem with read only permissions by typing the following command:

    mount -o remount,ro /usr
