K000153167: After an upgrade to 17.1.2.x "user <username> has reached maximum active login tokens".

Type

Published

Updated

Applies to

Source

Description

After an upgrade to 17.1.2.x authenticating via iControl REST fails and a 400 HTTP status is seen.

  • This error message is seen "user <username> has reached maximum active login tokens"
    • Example: user cd1b3f61-4b86-442a-8d65-fb2e3df4199f has reached maximum active login tokens

Environment

  • Upgrade to 17.1.2 to 17.1.2.x
  • Authenticating using iControl REST
    • Often done when using API calls for configuration updates and queries.

Cause

Auth tokens are exceeding limits. For non-admin logins the limit is 100 tokens.

While the bug, Bug ID 1787517, is specific to expired tokens the total number takes in both expired and active tokens.

Recommended Actions

When expired tokens are deleted a log entry in /var/log/restjavad.X.log should appear for each token...

[I][106312][21 Aug 2025 20:52:33 UTC][8100/shared/authz/tokens AuthTokenWorker] Message sent to mcpd to delete the token file.

You can also check for a specific user by following the steps found here...K000149679: REST API calls are failing after upgrade to 17.1.2

  1. Review log /var/run/pamcache.
    1. cd /var/run/pamcache
    2. ls -l
    3. There will be a count and list of the tokens.
  2. If you find too many:
    1. To delete active tokens run this command: restcurl -X DELETE /shared/authz/tokens
    2. To delete expired tokens run this command: rm -rf /var/run/pamcache/*
    3. Once either one or both of those have been run you will need to restart restjavad: bigstart restart restjavad
  3. The issue can re-occur unless it is fixed. The fix is to upgrade to at least 17.5.0.
