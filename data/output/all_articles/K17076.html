Known Issue

The BIG-IP system may translate an IPv6 File Transfer Protocol (FTP) EPSV command to an invalid IPv4 FTP PASV command.

This issue occurs when all of the following conditions are met:

  • An IPv6 FTP virtual server is configured to send traffic to an IPv4 FTP server.
  • An FTP client issues an EPSV command for a passive mode request, and the command includes an optional network protocol argument.

The IPv6 FTP EPSV command may contain an optional network protocol argument in the following format:

ESPV-whitespace-<network protocol>

However, the whitespace and network protocol portion is not valid for the IPv4 FTP PASV command. When translating an IPv6 FTP EPSV command to an IPv4 FTP PASV command, the BIG-IP system fails to remove the whitespace and protocol information, resulting in an invalid PASV command that the IPv4 FTP server will not process.

Impact

FTP clients cannot enter FTP passive mode.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The FTP client receives an error code from the server, similar to the following example:

    501 - Syntax error in parameters or arguments.

Workaround

To work around this issue, you can implement an iRule that collects and then removes the whitespace-<network protocol> argument from the EPSV command.

Impact of workaround: The impact of the suggested workaround depends on the specific environment; F5 recommends testing these changes during a maintenance window.

For example, you may be able to use an iRule similar to the following:

rule EPSV_not_allowed {
   when RULE_INIT {
      set DEBUG 1
      set sec_block_epsv_cmd 1
   }
   when CLIENT_ACCEPTED {
      if { $::DEBUG } { log local0. "client accepted" }
      TCP::collect 0 0
   }
   when CLIENT_DATA {
      if { $::DEBUG } { log local0. ----------------------------------------------------------" }
      if { $::DEBUG } { log local0. "payload [TCP::payload]" }
      set client_data [string trim [TCP::payload]]
      #---------------------------------------------------
      # Block or alert specific commands
      #---------------------------------------------------
      switch -glob $client_data {
         "EPSV*" {
         if { $::DEBUG } { log local0. "LOG: EPSV request detected" }
            if { $::sec_block_epsv_cmd  } {
               # to block use following 2 lines
               # TCP::respond "550 EPSV commands not allowed\r\n"
               # TCP::payload replace 0 [string length $client_data+2] ""

               # to remove argument, use following 2 lines
               TCP::payload replace 0 [string length $client_data] "EPSV"
            }
         }
      }
      TCP::release
      TCP::collect
   }
   when SERVER_CONNECTED {
      if { $::DEBUG } { log "server connected" }
         TCP::release
         TCP::collect
      }
   when SERVER_DATA {
      if { $::DEBUG } { log local0. "payload <[TCP::payload]>" }
         TCP::release
         TCP::collect
   }
   when CLIENT_CLOSED {
      if { $::DEBUG } { log local0. "client closed" }
   }
}
