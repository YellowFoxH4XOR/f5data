Where can I find technical information about CVE-2022-1388?

K23605346: BIG-IP iControl REST vulnerability CVE-2022-1388

    Are the changes in the 'Modify the BIG-IP httpd configuration' mitigation synchronized between high availability (HA) members?

    Yes. The httpd configuration is considered to be common in a device group setup and is synchronized during a configuration synchronization (ConfigSync) operation.

    Does this CVE impact the control or data (traffic) plane?

    This vulnerability may allow an unauthenticated attacker with network access to the BIG-IP system through the management port and/or self IP addresses to execute arbitrary system commands, create or delete files, or disable services. There is no data plane exposure; this is a control plane issue only.

    What is the difference between the control plane and the data plane?

    Control plane refers to management-related services and traffic flowing to them, such as the Configuration utility (TMUI), iControl REST, and SSH, either through the management IP address or a self IP address exposing the HTTPS or SSH ports (443 or 22). Data plane refers to any traffic handled by a virtual server, secure network address translation (SNAT), NAT, or other non-control-plane-traffic handler.

    Note: For more information, refer to the following articles:

    • K44525501: Overview of BIG-IP data plane and control plane
    • K15003: Data and control plane tasks use separate logical cores when the BIG-IP system CPU uses Intel Hyper-Threading Technology

    What steps should I take if I suspect that an attacker has exploited this vulnerability and compromised the BIG-IP system?

    Follow the guidance outlined in K11438344: Considerations and guidance when you suspect a security compromise on a BIG-IP system.

    What’s the best way to resolve this vulnerability?

    F5 recommends installing a fixed version as soon as possible to eliminate the risk posed by these vulnerabilities. In the interim, you can apply the mitigations documented in the security advisory listed in this article.

    Can you validate, verify, or provide a Proof of Concept to demonstrate my system is not vulnerable?

    To ensure you are protected from this vulnerability, verify that you are running one of the versions of software listed in the Fixes Introduced In column of K23605346: BIG-IP iControl REST vulnerability CVE-2022-1388.  

    F5 is committed to responsibly disclosing information that contains sufficient detail about the vulnerability in question. You can verify the status of your BIG-IP system by using the iHealth application. However, F5 does not provide the following information:

    • Example exploit code
    • Reproduction (Repro) information
    • Proof of Concept (PoC)

    For more information about using iHealth, refer to K27404821: Using F5 iHealth to diagnose vulnerabilities.

    I have applied mitigations 1 and 2 listed in the security advisory article. Should I apply all 3 mitigations?

    F5 recommends following the mitigation steps as documented in K23605346: BIG-IP iControl REST vulnerability CVE-2022-1388. If you have only applied mitigations 1 and 2, then you must assess whether you have limited your risk appropriately based on your environment and your organization's risk tolerance.

    Will the mitigation step in Modify the BIG-IP httpd configuration be enough?

    The purpose of the mitigation step in Modify the BIG-IP httpd configuration is to re-write the Connection header for any requests being handled by the control-plane httpd (Apache) daemon. In BIG-IP 14.x and later, the header is sanitized to either "Connection: keep-alive" or "Connection: close" depending on the originally supplied value, and in earlier versions always re-written to "Connection: close" regardless of the originally supplied value. In BIG-IP 14.x and later, there is no impact to either REST client or BIG-IP system, while in earlier versions there is the small possibility of a performance impact if the control plane is handling a very large volume of requests as each request will be forced into a new TCP connection.

    Important: As stated in K23605346, "Until it is possible to install a fixed version, you can use the following sections as temporary mitigations. These mitigations restrict access to iControl REST to only trusted networks or devices, thereby limiting the attack surface."

    Do I need to restart httpd (Apache) after applying the mitigation step detailed in Modify the BIG-IP httpd configuration?

    No. Simply saving the configuration will cause the mitigation to become effective immediately.

    Will the mitigation step detailed in Modify the BIG-IP httpd configuration survive after rebooting the BIG-IP system?

    Yes. The mitigation added to the httpd configuration from the reference procedure will survive a BIG-IP reboot. 

    Does the Port Lockdown setting 'Allow None' affect egress traffic such as BIG-IP monitors to nodes and/or pools?

    No. The Port Lockdown setting affects only ingress traffic to the associated self IP address. For more information, refer to K17333: Overview of port lockdown behavior (12.x - 17.x).

    What should I do if I am running an older platform, such as BIG-IP 6900, which is not compatible with the fixed software versions?

    Most older platforms currently in use are in extended support, as defined in K4309: F5 platform lifecycle support policy. If you are using such a platform, or one completely out of support, you should consider upgrading to a fully supported hardware platform.

    F5 will not release engineering hotfixes on maintenance or point releases that were current when a platform passed platform End of Service Date (EoSD) and entered extended support. However, since you are already running a platform that is not fully supported, you may consider updating to a software release with the fixes. F5 does not take steps to break updates for platforms in extended support. So, in general, F5 expects that later maintenance and point releases issued after the platform entered extended support should work normally. For example, a system that was running BIG-IP 12.1.3 when it entered extended support will likely run 12.1.5.3 without issue and updating will not change the support status. In the meantime, you can immediately apply the mitigations provided in the appropriate security advisory.

    Is there a way to determine whether this CVE has been exploited on my BIG-IP system?

    The Diagnostics tab within F5 iHealth contains several heuristic tests designed to look for possible evidence of malicious activity within an uploaded QKView file. Examples are unknown processes or logins from public IP addresses. F5 has iHealth heuristics designed to detect the following:

    • Unknown processes running (H511618)
    • When the Configuration utility iControl REST interface has been exposed to the Internet through the management interface (H444724)
    • When a self IP address has Port Lockdown set to Allow All (H458565)

    Note: For more information, refer to the following articles:

    • K12878: Generating diagnostic data using the qkview utility
    • K27404821: Using F5 iHealth to diagnose vulnerabilities

    Note: A lack of log entries or heuristic reports does not categorically indicate that a unit is not compromised. A skilled attacker can remove evidence of compromise, including log files, after successful exploitation.

    Note: F5 Support is not trained to conduct forensic examination, and it is outside of F5 Support's scope to check whether your system has been compromised due to any of the CVEs listed here.
