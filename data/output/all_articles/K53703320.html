K53703320: Unable to modify custom response blocking page. ''Save Changes'' hangs.

Type
Support Solution
Published
2020-11-27
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.X, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.8, 15.1.1, 15.1.0, 15.1.2
Source
https://my.f5.com/manage/s/article/K53703320

Description

  • Unable to modify custom response blocking page. "Save Changes" hangs.
  • The device is upgraded from a pre-15.1 release to an affected version. 
  • Error message displayed in browser console log:
    "TypeError: Cannot read property 'serverTechnologyName' of undefined
        at policiesComponents.component.controller.d.saveResponsePages (TsuiAngularPoliciesScripts.min.js?ver=15.1.0.0.0.6:14" 

Environment

  • BIG-IP ASM provisioned
  • ASM Response and Blocking page is configured

Cause

This is due to a known bug, ID837333

Recommended Actions

  1. To identify ID 837333, the above error can be found in internet browser console log.  See below for how-to.
    Firefox Mozilla
    - Ctrl+Shift+E to open developer tools-> Network.
    - Click on the clock icon inside the grid area to get it to capture
    - Check 'Persist Logs', 'Disable cache'. Under network
    - Check 'Persist Logs',  Under console
    - Clear FF Mozilla cache under 'history' -> 'clear recent history'  (this is the regular FF Mozilla menu under 'library'.)
    - Clear any capture with the 'garbage' icon on the right
    - Load the GUI manager of the BigIP, and make the change to the response change, to reproduce the issue.
       ? Observe that the error/warning "TypeError: Cannot read property 'serverTechnologyName' of undefined" is displayed in the browser console log.
     
  2. Once page loaded/hangs or error:
    - at the grid area, right click and 'save all as HAR'. (under Network tab)
    - go to 'console' tab, select all and copy, save to text file.
     
  3. Review the browser capture and verify if you see the error noted in this article description.
     
  4. If you find the error, follow bug ID article ID837333 to resolve this.
     
  5. Should you require F5 review, please open a case. Then upload HAR and Console files to supportfiles,  as well, fresh qkview to iHealth.
