K10343: A virtual server configured with a FastL4 profile and no available pool members will not send a reset packet

Known Issue

This is the result of a known issue. When a virtual server is configured with a FastL4 profile and all of the virtual server's associated pool members are not available, the virtual server will not issue a reset packet to the client request.

Note: This issue does not affect BIG-IP 9.4.0 and later.

F5 Product Development is tracking this issue as CR124808.

Workaround

If all pool members become unavailable, you can work around this issue by configuring the virtual server to use a standard TCP profile.
