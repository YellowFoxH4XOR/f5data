Known Issue

The HTTP profile Response Header Allowed option does not preserve the headers that you want.

This issue occurs when the following condition is met:

  • You have configured a custom HTTP profile to allow only specific HTTP response headers, using either the Response Headers Allowed option from the Configuration utility, or the response-headers-permitted option from the TMOS Shell (tmsh).

When you configure the profile option, it unexpectedly removes all HTTP response headers except for the following headers, which are acceptlisted by the BIG-IP system:

  • Connection
  • Content-Encoding
  • Content-Length
  • Content-Type
  • Host
  • Location
  • Proxy-Connection
  • Set-Cookie
  • Set-Cookie2
  • Transfer-Encoding

Impact

The system may unexpectedly remove headers from HTTP responses.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • F5 iHealth lists Heuristic H644964 on the Diagnostics > Identified > Medium screen. 
  • The client browser and the web application hosted by the BIG-IP virtual server may not interact as expected.

Workaround

To work around this issue, you can use the HTTP::headers sanitize iRules command to restrict headers. To do so, perform the following procedure:

Impact of workaround: The following iRules example may not apply to all environments. F5 recommends that you author an iRule that may work best for your application environment. Additionally, adding an iRule will increase the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name for your iRule.
  5. In the Definition box, use the following iRule syntax:

    when HTTP_RESPONSE {
        HTTP::header sanitize [header name]+
    }

    Note: The HTTP::header sanitize command accepts zero or more header names. If you do not provide any headers, then the system removes all header names, except those provided in the same accept list previously noted in the Known Issue section of this article.

    For example, to preserve server HTTP response headers named X-myApp-header-1 and X-myApp-header-2, enter the following text:

    when HTTP_RESPONSE {
        # Remove all headers except custom headers
        HTTP::header sanitize X-myApp-header-1 X-myApp-header-2
    }

  6. Click Finished.
  7. Assign the iRule to your virtual server.
