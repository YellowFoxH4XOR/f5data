Topic

Microsoft released the final (non-beta) release of Internet Explorer 8 (IE8) on March 19, 2009. FirePass versions 6.0.3 and older may have problems supporting IE8. For more information about IE8 support and hotfixes, refer to K9689: FirePass support for Microsoft Internet Explorer 8.0.

If a user accesses a FirePass controller that does not support IE8, features requiring FirePass client components may not function properly. Some examples of features requiring client components are pre-logon inspectors, Network Access, and Application Access.

If your organization has users running IE8, there are two options for remediation:

  • Inform users running IE8 to use Compatibility View when accessing FirePass. In preliminary testing, Compatibility View has been shown to be more compatible with FirePass than the native (default) IE8 view.

    Note: For instructions about using Compatibility View in IE8, refer to http://www.microsoft.com/windows/internet-explorer/features/enhanced-navigation.aspx.
     
  • Configure a pre-logon sequence that directs users connecting with IE8 to the Logon Denied page. Additionally, you can configure that Logon Denied page to display a custom message to indicate why the logon has been prevented and to list any remediation steps (such as using a different browser or uninstalling IE8).

Configuring a pre-logon sequence that prevents users from logging on with IE8

Note: Pre-logon sequences can also redirect users to other web pages with additional information and resources. For information about additional pre-logon sequence options, refer to the FirePass Controller Administrator Guide.

  1. Log in to the FirePass Administrative Console.
  2. Click Users.
  3. Click Endpoint Security.
  4. Click Pre-Logon Sequence.
  5. In the Create new sequence: field, enter a name for this pre-logon sequence.

    Important: If you have an existing pre-logon sequence, you can skip to Step 8 to edit your existing sequence. However, in order for the pre-logon sequence to work properly, you must add the new action to the beginning of the existing sequence. Some pre-logon inspectors use ActiveX controls, which are not compatible with IE8. You must redirect users running IE8 to the Logon Denied page prior to any ActiveX controls running.
     
  6. From the drop-down menu for the Based on: field, select template: Empty.
  7. Click the Create button.

    The new sequence appears in the Select Sequence to Use section.

  8. Click edit next to the sequence you just created.

    The Pre-Logon Sequence Editor opens.

  9. Mouse over the Go action.

    A plus (+) icon appears to the right of Go.

  10. Click the + icon..

    The Change Sequence panel opens.

  11. In the Using menu, select New action.
  12. Click the Apply changes button.

    The Edit Action panel opens.

  13. In the Name field, enter a name for this action.

    For example:
    Detect IE8

  14. Click the Update details button.
  15. Click the Close Panel link at the upper right of the panel.
  16. Mouse over the fallback link.

    A + icon appears to the left.

  17. Click the + icon.

    The Insert Rule Panel opens.

  18. Enter a name for the rule in the Name field.

    For example:
    If browser is IE8

  19. In the text field below the Name field, enter the following rule to detect IE8 User-Agent strings:

    session.browser.user_agent >= "Mozilla/4.0 (compatible; MSIE 8.0" AND session.browser.user_agent < "Mozilla/4.0 (compatible; MSIE 8.0~"

    Note: The rule shown above should match all IE8 User-Agent strings, with the exception of IE8 browsers using Compatibility View mode. If you want to match specific IE8 User-Agent strings, you can modify the rule to specify those User-Agent strings.

    For example:

    session.browser.user_agent == "Mozilla/4.0 (compatible; MSIE 8.0; Windows NT 5.1; Trident/4.0; .NET CLR 1.1.4322; InfoPath.2; MS-RTC LM 8; .NET CLR 2.0.50727; .NET CLR 3.0.4506.2152; .NET CLR 3.5.30729)" OR "Mozilla/4.0 (compatible; MSIE 8.0; Windows NT 6.0; Trident/4.0; SV1; SLCC1; .NET CLR 2.0.50727; MS-RTC LM 8; .NET CLR 3.5.30729; .NET CLR 3.0.30618; InfoPath.2)"

    To display the User-Agent string of a particular browser, enter the following text into the browser's address bar (JavaScript must be enabled in the browser):

    javascript:alert(navigator.userAgent)

  20. Click the Insert Rule button.

    The sequence should now update in the main panel. The main panel will display the new rule's name leading to the Logon Denied Page action, and a fallback branch leading to the Logon Allowed Page action.

    Note: Optionally, you may want to provide text on the Logon Denied page to inform users that IE8 is not a supported browser. To do so, click the Logon Denied Page action, enter your text in the Message for user field, then click the Update button.

  21. Click the Back to console link at the upper right of the panel.
  22. In the Select Sequence to Use section, select the option button next to the pre-logon sequence you just edited.
  23. Click the Apply button.

Users who attempt to log on to the FirePass controller with IE8 should now be directed to the Logon Denied page, and all other users should be directed to the Logon Allowed page.
