Known Issue

The ARX system may not process the PIDHigh portion of an SMB file operation request. As a result, file operation requests with a non-zero PIDHigh value will fail.

This issue has been reported to occur when all of the following conditions are met:

  • The client is using Mac OS X versions 10.6.x or 10.7.x
  • The issue can occur for any read or write operation, but it typically occurs when copying a folder containing a large number of files totaling greater than 2.5GB in size

The PID (process ID) is a 32-bit value transferred in two fields (PIDLow and PIDHigh) of the SMB header. In early versions of the SMB protocol, the PID value was a 16-bit value. Newer versions expended the PID value to 32-bits and introduced the PIDHigh field. Most clients only utilize the 16-bit PIDLow field and do not yet use the 16-bit PIDHigh field.

Impact

File read/write operations may fail for Mac OS X clients.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The file operation fails and the client receives an error message that appears similar to the following example:

    The Finder can't complete the operation because some data in "Folder Name" can't be read or written.
    (Error code -36)
  • The client's kernel.log file will contain a timeout error message that appears similar to the following example:

    kernel[0]: smb_iod_sendall: Timed out waiting on the response for 0xa2 mid = 0x7b

Workaround

To work around this issue, you can perform the desired file operation on a smaller group of files.

Impact of workaround: None.
