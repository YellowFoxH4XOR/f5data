K07037536: ASM XML Violation Malformed document - illegal encoding Encoding in prolig overrides BOM

Type
Support Solution
Published
2024-04-24
Updated
2025-04-02
Applies to
  • BIG-IP
Source

Description

You may consider the recommendation of this article to determine if ASM action to block an XML request with UFT16 is expected or not.

Environment

The BIG-IP ASM needs to be configured with the following:

  • A virtual server that has ASM security policy assigned.
  • Security policy is configured to forward the request in question to XML engine parser based on the value of the header Content-Type.

Cause

Per the XML specification, section 4.3.3, all entities encoded in UTF-16 must start with a byte order mark (BOM).  The hexidecimal representation of this character is 0xFEFF (big-endian) or 0xFFFE (little-endian).  URL-encoded, 0xFEFF becomes %FE%FF.  When the XML value starts with these characters, the XML parser knows to switch encodings.

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. Work with the application team to tag the request with a BOM (Byte Order Mark).
  2. Take a tcpdump capture to verify if the request in question starts with BOM.
  3. To allow this through ASM you may consider creating an explicit URL of the request in question and configure ASM to do nothing if the Content-Type value is *xml*.
