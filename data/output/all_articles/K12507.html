Known Issue

This is the result of a known issue. In BIG-IP version 10.0.1, an interface that has flow control enabled may not actually enable flow control when the device to which it is connected has also enabled flow control. This issue occurs after an interface with flow control enabled has had flow control disabled, and then subsequently re-enabled. This issue is only known to affect the following hardware platforms:

  • 1600
  • 3600
  • 6900
  • 8900

For example, the following configuration shows interface 1.2 is configured with flow control enabled, and set to pause tx/rx:

interface 1.2 {
prefer sfp
media none
media sfp auto
media fixed auto
enable
pause tx rx
link type auto
edge port true
auto edge enable
stp enable
}

The interface status shows that the operational status of interface 1.2 reports (none), meaning flow control is in fact disabled:

INTERFACE 1.2 00:01:D7:B0:7F:05 ENABLED up MTU 1500
| media auto (1000baseT full) aggregation: detached
| flow control tx rx (none)
| (pkts,bits,errs) in = (11663, 7.052M, 0), out = (0, 0, 0)
| (drop,mcast) in = (11663, 11663), out = (0, 0) coll = 0

F5 Product Development tracked this issue as ID 338263 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.
