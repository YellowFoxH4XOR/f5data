Environment

  • F5 host use Openstack cloud with SRIOV ports
  • Configured tx and rx are as follow: 
    config # tmctl -d blade tmm/iq_rx_stats | grep "^1" | awk -F" " '{print $3}' | sort -u | wc -l
16
config # tmctl -d blade tmm/iq_tx_stats | grep "^1" | awk -F" " '{print $3}' | sort -u | wc -l
1

Cause

TMM queue is 4 times larger than device queue as such we are bound to have drops if there is a lot of traffic egressing the device.

Recommended Actions

Note: Each modification to those values should be monitor after the new setting applied.
Increase "tx_iq_sz" to 2048 and monitor.
Increase "rx_iq_sz" to 2048 and monitor

  1. Increase the tx_iq_sz to 2048:
    Note: you may use vi option, or any editing option,  to modify the value. 
    # vi /config/tmm_init.tcl
ndal rx_iq_sz 1024     <-- Increase to 2048
ndal tx_iq_sz 1024     <-- Increase to 2048

  2. restart tmm with the following command:
    bigstart restart tmm
    Note: The  BIG-IP will have an impact while running this command

Additional Information

  1. There is only One internal tx queue by design:

    1.  Multiple internal Ingress queues allow multiple tmms to simultaneously disaggregate packets to the same target tmm without the need for locks (rx's).

    2. Only one egress queue is created (tx).

  2. The maximum value allow to increase is 4096 - this option will affect the system's memory, and will need to be done with monitoring the memory utilization
