Known Issue

The CACHE::enable iRules command may not cache content in an HTTP_RESPONSE event.

This issue occurs when the following conditions is met:

  • An iRule uses a CACHE::enable command within an HTTP_RESPONSE event.

Impact

The iRule fails to add the content to the HTTP cache.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The CACHE::enable command does not add content to the HTTP cache.

    For example, the following iRule will fail to cache the intended redirect responses:

    when HTTP_RESPONSE {
    if { [HTTP::status] == 301 }{
    CACHE::enable
    }
    }

Workaround

To work around this issue, you can avoid the use of the CACHE::enable command in the HTTP_RESPONSE event. If the CACHE::enable functionality is required, it should be called in the HTTP_REQUEST event instead. However, as demonstrated by the example iRule in this article, the condition upon which the caching decision is based may not be available until the HTTP_RESPONSE event. In such cases, there is no workaround.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure any modification is compatible with your environment.
