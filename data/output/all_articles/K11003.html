Topic

When Clustered Multiprocessing (CMP) is enabled, the BIG-IP system may modify the client source port for virtual server connections to ensure that both client-side and server-side flows are hashed to the same Traffic Management Microkernel (TMM) instance.

Most traffic is not negatively impacted when the BIG-IP system modifies the client's source port. However, this behavior can be problematic for certain types of traffic that require the source port to be preserved, such as nPath and some Session Initiation Protocol (SIP) implementations.

By default, the BIG-IP system attempts to preserve the client's source port when sending connections to the pool member. The following describes BIG-IP source port behavior and how to change the default behavior:

  • Preserve

    The system preserves the value configured for the source port unless the source port from a particular secure network address translation (SNAT) is already in use, in which case the system uses a different port. This is the default behavior.

  • Preserve Strict

    The system preserves the value configured for the source port. If the port is already in use by another connection, the system resets the client-side connection. To minimize the number of collisions resulting in resets, F5 recommends that you restrict the use of this setting to cases that meet at least one of the following conditions:

    • CMP is disabled.
    • The port is configured for User Datagram Protocol (UDP) traffic only (versions earlier than BIG-IP 11.3.0).
    • The port is configured for UDP or TCP for (BIG-IP 11.3.0 and later).
    • The system is configured for nPath routing or is running in transparent mode (there is no translation of any other layer-3 or layer-4 field).
    • There is a one-to-one relationship between virtual IP addresses and node addresses.

      Additionally, if the source IP is not being modified when it egresses to the server side, for example, there is no SNAT or self-IP translation, collisions should not occur because both the source IP address and source port ensure that the flow is unique. This contrasts with when you use SNAT. In this case, there is a very limited scope of source IP addresses, and the originating client chooses the source port. Preserve Strict for UDP and TCP connections results in the system always preserving the source IP address and source port towards the back-end server.

      Note: Return traffic from the back-end server may arrive at a different TMM than originally sent the traffic. This can result in the system using additional resources to switch the traffic back to the original TMM that received the traffic from the client.

  • Change

    The system always uses the next available port. No attempt is made to preserve the client source port. This setting ensures that a unique port is chosen for each new connection and may help avoid premature port reuse when load-balancing legacy systems use longer than usual TIME-WAIT windows.

The software needs to change the source port when all of the following conditions are met:

  • Translate-port is enabled on the virtual server.
  • The virtual server is listening to a port different from the port to which the pool member is listening.
  • The TMM number calculated by DAG hash formula over the source and destination ports on the client side is different from the TMM number calculated by the same formula over the ports on the server side in the assumption that the client port is preserved

In scenarios where the source port needs to be changed (as outlined above) the following behavior of the configuration settings be expected:

  • source-port change: The source port will be changed on the server side
  • source-port preserve: The source port will be changed on the server side (for the context where the source port needs to be changed as described in the earlier section)
  • source-port preserve-strict: The server-side connection will not be attempted, the client-side connection will be reset unless OneConnect is in use too. With OneConnect the concept of port preservation may no longer apply

Description

To edit the Source Port settings for a virtual server, perform one of the following procedures:

  • Using the Configuration utility to configure the Source Port settings for a virtual server
  • Using tmsh to configure the Source Port settings for a virtual server

Using the Configuration utility to configure the Source Port settings for a virtual server

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the virtual server for which you want to change the source port setting.
  4. For Configuration, select Advanced.
  5. For Source Port, select the value you want.
  6. Select Update.

Using tmsh to configure the Source Port settings for a virtual server

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To change the source port setting for the virtual server, use the following command syntax:

    modify /ltm virtual <virtual_server_name> source-port <change | preserve | preserve-strict>

  3. Save the change by entering the following command:

    save /sys config
