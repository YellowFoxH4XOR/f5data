Description

When accessing the BIG-IP APM webtop via browser, if you attempt to access a second resource (a 2nd tab, or modify the URL and attempt to access it) before the initially requested resource (logon page) has been accessed, You may get the following error message:

Access policy evaluation is already in process for your current session.
You may see this error message if you are on a different browser tab than the one where you started the access policy. Please continue to work in the previous browser tab and close this window immediately.
If you have reached this message due to some error, click button to create a new session.
[New session]

For example, a user accesses the APM logon page, then attempts to open a second tab or access a different URL on the same host before the logon process has completed.

Environment

  • BIG-IP APM
  • Virtual server
  • Access profile
  • Logon page
  • Browser

Cause

This is an expected result.

  1. An access policy consists of a start point, actions, and one or more endings. The access policy actions are stateful, not stateless. 
  2. When a user accesses the URL for the APM https://<IP/FQDN>/, APM will redirect to https://<IP/FQDN>/my.policy, and setup the cookie for the session, logon page displayed.
  3. At this point, the APM is looking for an HTTP request with the logon credentials (username/password).
  4. If the user doesn't complete the initial access policy, and instead attempts to access a different URL (https://<IP/FQDN>/foo), the APM interprets it as an unexpected HTTP request, and displays the pop-up error with this message.

Recommended Actions

This error can be ignored.

The following iRule can suppress the error. Refer to K50565834:  How to add an iRule to a Virtual Server and apply it if necessary.

when RULE_INIT {
    set static::ACCESS_LOG_PREFIX     "Duplicate:"
}
when HTTP_REQUEST {
  if { [HTTP::cookie exists "MRHSession"] && ([ACCESS::session exists -state_inprogress] || [ACCESS::session data get "session.policy.result"] == "not_started" ) && ! [string equal "[HTTP::uri]" "/my.policy"] } {
    log -noname accesscontrol.local1.err "$static::ACCESS_LOG_PREFIX [IP::remote_addr] access [HTTP::uri] with in_progress session, redirecting to logout URI"
    HTTP::close
    # here you can do whatever you want, easiest option is to simply 302 user to logout URI to delete apm cookie and start over
    HTTP::respond 302 Location "/my.logout.php3"
  }
}

Additional Information

If the user did not send out the unexpected HTTP request manually, contact F5 Support to further investigate it.
