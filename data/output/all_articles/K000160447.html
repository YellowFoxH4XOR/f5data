Description

VELOS uses chrony to synchronise time. This article is about where to look when troubleshooting the system time.

Environment

F5OS on VELOS

Overview

The controllers are in symmetric mode.

The Reference time in chrony command outputs does not display the current system time.

RFC5905

Reference Timestamp: Time when the system clock was last set or
corrected, in NTP timestamp format.

When looking at NTP packet captures, the Origin Timestamp may also appear strange (see below) but is not necessarily a problem indicator (ref: https://datatracker.ietf.org/doc/html/draft-ietf-ntp-data-minimization-04)</p><p>

Debug and Troubleshooting Commands

The following troubleshooting commands show examples from a healthy system.

chrony conf files are not collected in a qkview. Check:

- /etc/chrony.conf - should be the same on both controllers

- /etc/chrony.keys - should be empty

 

Check file permissions:

[root@controller-1(VEL410-R81-S7):Active ~]# ls -la /etc/chrony.keys
lrwxrwxrwx. 1 root root 39 Feb 24 19:29 /etc/chrony.keys -> /var/system/confgen-configs/chrony.keys

 

[root@controller-1(VEL410-R81-S7):Active ~]# ssh controller-2 'ls -la /etc/chrony.keys'
lrwxrwxrwx. 1 root root 39 Mar 2 13:16 /etc/chrony.keys -> /var/system/confgen-configs/chrony.keys

 

Verify port 123:

[root@controller-1(VEL410-R81-S7):Active ~]# nc -zvu controller-2.chassis.local 123
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connected to 100.65.3.52:123.
Ncat: UDP packet sent successfully
Ncat: 1 bytes sent, 0 bytes received in 2.09 seconds.

[root@controller-1(VEL410-R81-S7):Active ~]# ssh controller-2 'nc -zvu controller-1.chassis.local 123'
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connected to 100.65.3.51:123.
Ncat: UDP packet sent successfully
Ncat: 1 bytes sent, 0 bytes received in 2.08 seconds.

What a fail looks like (using port 124):

[root@controller-1(VEL410-R81-S7):Active ~]# ssh controller-2 'nc -zvu controller-1.chassis.local 124'
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connected to 100.65.3.51:124.
Ncat: No route to host.

 

Check iptables:

[root@controller-1(VEL410-R81-S7):Active ~]# iptables -L -n -v | grep -i 123

4945 375K ACCEPT udp -- * * 100.65.3.0/24 0.0.0.0/0 state NEW udp dpt:123

 

[root@controller-1(VEL410-R81-S7):Active ~]# ssh controller-2 'iptables -L -n -v | grep -i 123'

721 54749 ACCEPT udp -- * * 100.65.3.0/24 0.0.0.0/0 state NEW udp dpt:123

 

Check bindings:

 

[root@controller-1(VEL410-R81-S7):Active ~]# netstat -ulnp | grep chronyd

udp 0 0 0.0.0.0:123 0.0.0.0:* 28133/chronyd

udp 0 0 127.0.0.1:323 0.0.0.0:* 28133/chronyd

udp6 0 0 ::1:323 :::* 28133/chronyd

 

[root@controller-1(VEL410-R81-S7):Active ~]# ssh controller-2 'netstat -ulnp | grep chronyd'

udp 0 0 0.0.0.0:123 0.0.0.0:* 19412/chronyd

udp 0 0 127.0.0.1:323 0.0.0.0:* 19412/chronyd

udp6 0 0 ::1:323 :::* 19412/chronyd

 

ausearch is a tool to search the Linux Audit logs (part of the auditd).

[root@controller-1(VEL410-R81-S7):Active ~]# ausearch -m avc -ts recent | grep chrony

<no matches>

 

[root@controller-1(VEL410-R81-S7):Active ~]# ssh controller-2 'ausearch -m avc -ts recent | grep chrony'

<no matches>

...

[root@controller-1(VEL410-R81-S7):Active ~]# ssh controller-2 'journalctl -u chronyd | grep -Ei "peer|controller"'

Chrony Debug Script

The provided bash script dumps the chrony states for all controllers and blades. It should be run on one controller. The output is printed to screen and appended to logfile.

The script could use some improvement in detecting what blades are available before trying to connect repeatedly to them ( currently assumes 8 blades).

#!/bin/bash
# 
# 1. scp this script (chrony-interrogate.sh) on a controller
# 2. chmod 755 chrony-interrogate.sh
# 3. Set $logfile name if you want
# 4  Run ./chrony-interrogate.sh
# 4. Send logfile to support

logfile="chrony-interrogate.log"

for h in 1 2 3 4 5 6 7 8 50 51 52; do 
   for c in "date" "timedatectl status" "chronyc tracking" "chronyc sources -v" "chronyc sourcestats -v" "chronyc ntpdata"; do
   echo -e "\n10.65.3.$h | $c ********************\n"
      #echo -e "\n*** $c ***\n"
      ssh "100.65.3.$h" "$c"
   done | tee -a "$logfile"
done

echo
echo "Script finished, send $logfile to F5 support."

exit 0
