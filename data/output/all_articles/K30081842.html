Known Issue

The bigd process may generate a core file or produce corrupted MCP messages when using fully-qualified domain name (FQDN) nodes.

This issue occurs when all of the following conditions are met:

  • You configure a large number (approximately 1000, depending on platform capabilities) of FQDN nodes and/or pool members on the BIG-IP system.
  • You configure monitors to check the availability of the FQDN nodes and/or pool members.

Monitoring FQDN nodes and pool members generates a higher workload for the bigd process than monitoring nodes and pool members that are configured with static IP addresses. When the BIG-IP system monitors a large number of FQDN nodes and pool members, the higher load can overload the bigd process and cause it to restart or produce corrupted MCP messages.

Impact

Monitored FQDN nodes and pool members remain in the Checking state indefinitely. The bigd process may restart, causing a monitoring disruption.  

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The bigd process generates a core file to the /shared/core/ directory.
  • In the /var/log/ltm file, you observe messages similar to the following example:

    01070712:3: Caught configuration exception (0), Can't parse MCP message

  • Monitored FQDN nodes or pool members remain in the Checking state indefinitely.
  • The BIG-IP system experiences high CPU usage for the bigd process.

Workaround

To work around this issue, you can reduce the number of configured FQDN nodes or pool members, or covert them to use static IP addresses.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
