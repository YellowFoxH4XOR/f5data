K9312: The Big3d.CertificateDepth bigdb key is not synchronized to cluster members

Known Issue

This is the result of a known issue. The BIG-IP LTM and GTM systems use the Big3d.CertificateDepth bigdb variable to determine how far the big3d process searches through a certificate chain when validating the certificate of a connecting BIG-IP GTM device. The Big3d.CertificateDepth bigdb values can range from 0 (self-signed certificate) to 9.

In BIG-IP version 9.6.x, the Big3d.CertificateDepth bigdb key is defined with a local instead of a global realm, which prevents changes to the key from being synchronized to cluster members.

F5 Networks Product Development tracked this issue as CR92858 and it was fixed in version 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

This issue still exists in the BIG-IP LTM version 9.6 software branch.

Workaround

You can work around this issue by logging in to each blade and setting the Big3d.CertificateDepth bigdb key to the desired value by typing the following command:

bigpipe db Big3d.CertificateDepth <value>
