K11083: The hds_prune process may start up before the disk cache is available

Known Issue

This is the result of a known issue. The hds_prune process may start up before the disk cache is available. As a result, the script will use an improper start and stop pruning threshold of 0 bytes.

Note: For more information about the hds_prune process, refer to K9079: Overview of the BIG-IP WebAccelerator hds_prune process.

Due to the improper threshold values, the hds_prune script is launched after the disk cache grows larger than 6 GB and the script will spend a longer time determining what files need to be removed. The script may also launch more often to bring the size of the cache down.

Note: When properly running, the hds_prune process will attempt to keep the disk cache between 20 and 40 percent free. The disk cache should not grow to 6 GB under proper operation.

The hds_prune script causes high iowait as it performs a time check (last accessed time) of all the objects in the disk cache. The issue is further exacerbated since the disk cache has already exceeded its maximum recommended limit when pruning starts. On busy systems, the iowait will remain very high during peak traffic periods and overall system performance may be significantly degraded.

F5 Product Development tracked this issue as CR135250 and it was fixed in BIG-IP WebAccelerator 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about installing version 10.x hotfixes on systems with a partitioned disk-formatting scheme, refer to K9819: Installing a BIG-IP version 10.x hotfix on a partitioned system.

Workaround

If you can view that the disk cache exceeds 6GB and traffic is affected due to high iowait, restart hds_prune so it can recompute the start and stop threshold values. To do so, use the following command syntax from the command line:

bigstart restart hds_prune

Once the hds_prune script is restarted, it will recompute the pruning level threshold values using the available disk cache partition.
