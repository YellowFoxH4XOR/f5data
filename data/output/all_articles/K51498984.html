Known Issue

Secure Sockets Layer (SSL) connections from VIPRION systems may be delayed.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses a virtual server configured with an SSL profile.
  • A client connects to the system with an SSL session ID that is not in the cache, and the connection uses a specific format that causes the Traffic Management Microkernel (TMM) to associate the session ID with a non-existent blade.

Impact

SSL connection responses are delayed.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Some SSL connections are delayed by approximately five seconds. The delay occurs between the SSL Client Hello and the Server Hello responses from your BIG-IP system.

Workaround

To work around this issue, you can disable SSL session cache in the Client SSL profile. To do so, perform the following procedure:

Impact of workaround: SSL connections using the modified Client SSL profile will not be able to resume sessions and these connections require negotiation of a new SSL session each time.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Click the affected Client SSL profile.
  4. From the Configuration menu, click Advanced.
  5. In the Cache Size section, enter 0.
  6. Click Update.
