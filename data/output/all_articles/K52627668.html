K52627668: Expiration Date on Certificate list page shows incorrect for SSL Certificate

Type
Support Solution
Published
2021-11-17
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 14.1.X, 14.0.X, 14.1.5, 14.1.4, 14.1.3, 14.1.2, 14.X.X, 14.0.1, 14.0.0, 14.1.0
  • BIG-IP 5000 Series
  • BIG-IP 5250v
Source
https://my.f5.com/manage/s/article/K52627668

Description
The expiration date displayed on the certificates list page shows the wrong date.
The date shown is the of the previous same certificate before renewal, but when check the certificate details by going inside , it shows the correct date.
This Issue  was same when checked from the command line.
There is no functional impact but you will only not able to see the correct expiration dates which can lead to have false positive alerts for the certification expiry. 
Note: If you verify from the browser , you will be able to see the correct certificate.

Environment

  • BIG-IP LTM  
  • SSL Certificate
  • upgrade to 14 version

Cause
Unknown at time of publication

Recommended Actions
To work around this issue, you can re-import the SSL certificate. After re-importing the certificate you will be able to see the correct dates on certificate.
Alternatively you can remove the old certificate from the filestore and then re-import the current certificate. 

 

Additional Information
To confirm the validity if the certificate and other things like expiration date you can use the SSL shopper. Copy the respective certificate from the F5 box to  your desktop. Then open the SSL shopper Certificate decoder and verify all the certificate details.

To Check the SSL certificate from command line 

  •     Login into device via command line and Go to bash mode 
  •    Go to the directory  config/filestore/files_d/Common_d/certificate_d/
  •    verify if the Old and New cert is there. If both are there then expiration date will be showing of the Old one in certificate list page.


Note : When renewing an SSL certificate from a CA, F5 recommends that you generate a new certificate signing request (CSR) and private key. when device rebooted after upgrade shown the expiry date of the previous certificate as its still there in the Filestore and but it will not have any impact as the certificate used was the correct one.
