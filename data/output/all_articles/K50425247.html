Descriptions
This article provides details of historical measurements of CPU utilisation readily available as records in the RRD database maintained by the BIG-IP. These records are readily available with no preparation required and can be used for purposes of e. g. baselining, capacity planning, root cause analysis or troubleshooting

    Environment

    • CPU utilisation

    Cause
    BIG-IP keeps in RRD format historical records of its performance measurements over the last 30 days. The processing can be performed via third-party applications in a manner e. g. similar to performance graphs available in iHealth and the BIG-IP Configuration Utility dashboard.

    • Further information about iHealth graphs can be found at K38423488: Viewing iHealth performance graph
    • Further information about how the Configuration Utility dashboard displays the measurements in its graphs is outside the scope of this article

    Recommended Actions

    • Changing the configuration
    • Values tracked in RRD files blade<#>cpu
    • Values tracked in RRD planestat
    • Values tracked in RRD rollupcpu


    The RRD data is stored in database files under /var/rrd in a platform-dependent format documented at https://en.wikipedia.org/wiki/Round-Robin_Database
    The values saved are a subset of values available from tmctl as defined in configuration file /config/statsd.conf As you can see illustrated below, similar values are also available averaged over different periods. With the default monitoring period of 10 s the readings over the shorter periods are less complete, while the readings averages over the longer periods are less sensitive:

    Actual (real time) readings
    Actual (real time) readings taken every 10 s
    Average readings over 5 s taken every 10 s
    Average readings over 1 min. taken every 10 s
    Average readings over 5 min. taken every 10 s


    The records can be exported into a platform independent XML format to directory /var/tmp/qkview-rrd/ using BIG-IP CLI utility /usr/bin/rrd2xml

    Changing the configuration

    The default values are expected to meet the most common requirements. Still, if specific needs of your deployment require changes, they can be made by editing configuration file /config/statsd.conf and the restarting daemon statsd.
    E. g. for changing Rratio from its default value five_sec_avg.ratio:

    TMSOURCE "Rratio" {
    TMTABLE     "system_cpu_info_stat"
    TMCOLNAME   "five_sec_avg.ratio"
    TMTYPE     UNSIGNED
    TMROLLUP    0
}

    to one_min_avg.ratio the following steps can be performed in bash CLI:

    1. Create a backup copy of the current file /config/statsd.conf

      cp /config/statsd.conf /config/statsd.conf_K50425247
       
    2. Apply the change. Any plain text editor can be used
      • This illustration uses sed

        sed -i 's/TMCOLNAME   "five_sec_avg.ratio"/TMCOLNAME   "one_min_avg.ratio"/g' statsd.conf

      • This illustration uses gawk

        gawk '{if($0 ~ /TMCOLNAME +"five_sec_avg.ratio"/) {$NF = "\"one_min_avg.ratio\""} print}' statsd.conf_K50425247 > statsd.conf

    3. Confirm that the change was applied successfully

      # diff /config/statsd.conf /config/statsd.conf_K50425247
      4140c4140
      <     TMCOLNAME   "five_sec_avg.ratio"
      ---
      >     TMCOLNAME   "one_min_avg.ratio"

      #
       
    4. Restart statsd to load the new configuration

      bigstart restart statsd
