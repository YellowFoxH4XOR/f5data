Description

Backup archives (.ucs files) after deleting them from gui do not free diskspace causing /var/ partition to not have enough disk space and eventually showing errors:
011d0004:3: Disk partition /var has only 8% free.

After running command: lsof -ws | grep -i 'size\|deleted'
It can be found that backup .ucs files that should be deleted hold the disk space:

java      14352 14535      root  137r      REG             253,18   189784277      32851 /var/local/ucs/ucs_file_name.ucs (deleted)
java      14352 14539      root  119r      REG             253,18   175600317      32786 /var/local/ucs/ucs_file_name.ucs (deleted)
java      14352 14539      root  123r      REG             253,18   174088974      32868 /var/local/ucs/ucs_file_name.ucs (deleted)

Environment

  • BIG-IP 12.x, 13.x, 14.x, 15.x
  • BIG-IP has configured backup scripts using REST API
  • The requesting client does not complete the download.


Cause

Bug ID 767613: Restjavad can keep partially downloaded files open indefinitely

Recommended Actions

To fix this issue please upgrade to one of non-affected versions from ID767613

To workaround this issue:

Free the file handles with restarting restjavad:

tmsh restart sys service restjavad

Files that were deleted now have their space reclaimed.
