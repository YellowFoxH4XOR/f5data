Description

Standby BIG-IP is not responding to ARP requests for a non-floating (local traffic group) self IP, and ping from/to the BIG-IP is unsuccessful.

net self 172.16.1.101 {
    address 172.16.1.101/24
    traffic-group traffic-group-local-only
    vlan internal-vlan
}

Packet trace shows repeated ARP requests which are unresolved, similar to the following example:

00:50:56:bd:47:e0 → ff:ff:ff:ff:ff:ff    ARP IN  s1/tmm0 : Who has 172.16.1.101? Tell 172.16.1.254
00:50:56:bd:47:e0 → ff:ff:ff:ff:ff:ff    ARP IN  s1/tmm0 : Who has 172.16.1.101? Tell 172.16.1.254
00:50:56:bd:47:e0 → ff:ff:ff:ff:ff:ff    ARP IN  s1/tmm0 : Who has 172.16.1.101? Tell 172.16.1.254
00:50:56:bd:47:e0 → ff:ff:ff:ff:ff:ff    ARP IN  s1/tmm0 : Who has 172.16.1.101? Tell 172.16.1.254

ARP for all other self IP addresses is resolved as expected.

Environment

  • ARP
  • Self IP

Cause

IP address in question was previously defined as a SNAT translation IP, belonging to a floating traffic group:

ltm snat-translation /Commonl/172.16.1.101 {
    address 172.16.1.101
    inherited-traffic-group true
    traffic-group /Common/traffic-group-1
}

This is permitted, but disables ARP in TMM for the self IP that shares the same IP address.

When the SNAT translation is deleted, ARP is not re-enabled in TMM for the self IP. That behaviour is tracked as bug ID976853.

Recommended Actions

Restart TMM:

tmsh restart sys service tmm

Note: Restarting TMM should not be traffic impacting on a standby system, but a maintenance window is recommended.
