Description

On BIG-IP LTM systems, users may find that logs such as audit logs, LTM logs, VIP status changes, and pool member events are not visible at all. Standard log viewing commands (e.g., tmsh show /sys log audit, cat /var/log/ltm) return no output or errors, even though disk space is sufficient and syslog configuration appears normal. This might impact their ability to investigate or troubleshoot incidents.

Environment

  • BIG-IP LTM
  • Log Filters

Cause

A custom log filter with restrictive or incomplete settings—such as severity set to "Debug", source set to "all", message ID set to "none", and no log publisher specified—can suppress log output at the bash level for matching criteria.

GUI:

Recommended Actions

1. Review current log filter configurations:

tmsh list sys log-config filter

Look for any custom filters with restrictive settings.

sys log-config filter /Common/Test { }

2. Disable or remove problematic filters:

tmsh delete sys log-config filter <filter_name>

For example:

tmsh delete sys log-config filter Test

Or adjust the filter settings if needed, like adding the log publisher. 

For example: local-syslog-publisher

3. After making changes, verify that logs are now visible using standard commands (e.g., cat /var/log/ltm).

Note: Removing or disabling such a filter does not affect production traffic or device operation; it only restores expected logging visibility.
