K000151346: F5 BIG-IP device "Inoperative" after reboot

Type
Support Solution
Published
2025-05-15
Updated
2025-05-15
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.0.0, 16.0.X, 16.0.1, 16.X.X, 16.1.X, 16.1.6, 16.1.5, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0
Source
https://my.f5.com/manage/s/article/K000151346

Description

  • Device is in "inoperative" state after a reboot.
  • LTM errors seen in /var/log/ltm related to mcpd, but no clear cause is identified: 

diskmonitor[5326]: 011d0002:4: Cannot access the database because mcpd is not running.

mcpd[18743]: 01070995:4: get_tmstat: tmstat_sample not ready. Statsd may not be running.

  • Running the following command shows many services waiting on mcpd.
tmsh show /sys service all
keymgmtd     down, waiting for mcpd to release running semaphore
lacpd        down, waiting for mcpd to release running semaphore
lind         run (pid 18642) 17 hours, 1 start
localdbmgr   down, Not provisioned
logmysqld    down, Not provisioned
logstatd     down, waiting for mcpd to release running semaphore
mcpd         run (pid 18743) 17 hours, 1 start
mdmsyncmgr   down, Not provisioned
merged       down, waiting for mcpd to release running semaphore
mgmt_acld    down, waiting for tmm to release running semaphore
monpd        down, waiting for mcpd to release running semaphore

Environment

  • Upgraded recently to version 16 from version 14.
  • GUI inaccessible
  • CLI says device "inoperative"
  • /var/log/ltm seems to indicate problems with mcpd but no clear mcpd errors.
  • tmsh show sys service shows many services with "waiting for mcpd to release running semaphore"

 

Cause

Unknown

 

Recommended Actions

  • Inoperative state: Forceload mcpd by following this procedure: https://my.f5.com/manage/s/article/K13030
  • If device comes back up but this time in "Offline" state perform the following steps:
tmsh load sys config verify (check for any errors and fix them)
tmsh load sys config

Additional Information

None
