Issue

Starting in BIG-IP 10.2.0, last hop pools are no longer limited to two members when used in a firewall sandwich configuration to load balance stateful firewalls.

Previously, last hop pools were limited to two members when used in a firewall sandwich configuration to load balance stateful firewalls, which require connection rebinding. Implementations not requiring connection rebinding were not subject to this limitation. When connection rebinding was required and the last hop pool contained more than two members, upon the failure of one pool member, the BIG-IP system on either side of the firewalls could arbitrarily reselect different firewalls for existing connections. Rebinding the inbound and outbound streams to different firewalls resulted in asymmetric paths and termination of stateful connections.

F5 Networks tracked this enhancement as ID 250320 (formerly CR69976).

For BIG-IP 10.1.0 and earlier, you can provide scalability among a larger firewall deployment by configuring multiple service-specific virtual servers, with each virtual server configured to load balance to a maximum of two firewalls. For example, you can configure the BIG-IP system to load balance all HTTP traffic to firewalls 1 and 2, all SIP traffic to firewalls 2 and 3, and all other traffic to firewalls 3 and 4.
