Known Issue

The BIG-IP system may fail to load the configuration when using a user configuration set (UCS) file that contains a self IP address that references a non-default route domain.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system's existing configuration contains a Virtual Local Area Network (VLAN) and a self IP address that is associated to the VLAN, and both objects reference the default route domain ID of 0.
  • You attempt to load a UCS file that contains the same VLAN and self IP address object, and both objects reference a non-default route domain.

Impact

You are unable to load the BIG-IP configuration.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Your attempt to load the UCS file fails.
  • An error message, similar to the following example, may appear in the /var/log/ltm file:

    err mcpd[7269]: 01070978:3: The vlan (/Common/vlan1) for the specified self IP (10.10.10.14%100) must be one of the vlans in the associated route domain (/Common/100). Unexpected Error: Loading configuration process failed.

Workaround

To work around this issue, you can attempt to reload the configuration by performing a bigstart restart. To do so, perform the following procedure:

Impact of workaround: This procedure will temporarily interrupt traffic processing. You should perform the procedure during a maintenance window.

  1. Log in to the BIG-IP command-line prompt.
  2. Restart all BIG-IP processes by typing the following command:

    bigstart restart

  3. Reload the configuration by typing the following command:

    tmsh load /sys ucs <path/to/UCS>

    If you do not specify the path, the BIG-IP system performs as if the UCS archive file is located in the default /var/local/ucs directory.
