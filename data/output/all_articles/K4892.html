K4892: Clients may no longer receive cookies after they begin accessing a site through FirePass

Topic



By default, FirePass holds cookies for the client and provides them to the server as needed. This eliminates the potential security risks that are introduced when setting cookies directly on the client.

If a site uses JavaScript to create a cookie directly on the client, it can cause the following two issues:

  • If the JavaScript uses the internal network's domain name to set the cookie, it will not be compatible with FirePass; FirePass reverse proxy translates the domain name and the client uses the FirePass hostname, rather than the domain name of the server, to access the site. As a result, FirePass will not present cookies that are set directly on the client.

  • If the JavaScript sets a cookie using the FirePass host name, the cookie will be presented; however, FirePass will block it. To enable FirePass to pass this cookie to the server, you must disable cookie blocking.

Disable cookie blocking

To disable cookie blocking on FirePass, perform the following steps:

  1. Log in to the FirePass Administration Console.

  2. From the main navigation pane, click Portal Access.

  3. In the upper navigation pane, click Web Applications.

  4. From the menu, click Content Processing.

  5. Click the Global Settings tab.

  6. From the Web Applications Global Settings section, check the box titled Do not block cookies at FirePass....

  7. Click the Update button.

FirePass will no longer block cookies that are set on the client.
