Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K13946: Troubleshooting ConfigSync and device service clustering issues (11.x - 12.x)

The goal of the ConfigSync process is to keep the configuration of the redundant pair in parity so that the system failover is as seamless as possible, ensuring that each unit processes traffic in an identical fashion, regardless of which is currently active. The ConfigSync process collects the configuration files and directories from one unit of a redundant pair into a single archive file, transmits the archive file to the peer unit, and installs the shared configuration data on the peer, overwriting the existing shared configuration on the peer.

Important: Although the process name implies that the files and configurations will be synchronized, the process actually pushes the shared portion of the configuration from one unit to the other. As a result, if changes have been made to the shared configuration on both units, any changes that were made on the target unit will be lost when the shared configuration from the source unit is installed. Also, file deletions are not propagated; if a file in a synchronized directory is deleted, the corresponding file on the peer unit is not deleted by the ConfigSync process.

Primary activities of the ConfigSync process

For more details about the primary activities of the ConfigSync process, refer to the following sections:

ConfigSync addresses

By default, the BIG-IP system performs ConfigSync operations using the network mirroring IP addresses. In BIG-IP 9.4.2 and later, you can define explicit IP addresses for ConfigSync traffic; however, this is an optional configuration element.

Note: For more information about defining ConfigSync addresses, refer to K11736: Defining network resources for BIG-IP high availability features (9.x - 10.x).

Collection of files to transmit

The first step of the ConfigSync process is defining the collection of files to transmit to the peer system. The collection of files to transmit is determined in part by the requested command, and also by the associated files defined in the /usr/libdata/configsync/cs.dat file.

Note: For more information, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

The following table describes the ConfigSync related commands:

CommandAction
bigpipe config sync allThis command creates a temporary UCS file and transfers it to the peer BIG-IP system. Then, the command installs the UCS file on the peer BIG-IP system.
bigpipe config sync minThis command creates a temporary UCS file containing the /config/bigip.conf file only, and transfers it to peer BIG-IP system. Then, the command installs the UCS file on the peer BIG-IP system.

Note: This command is no longer supported beginning in BIG-IP 10.0.0.
bigpipe config sync pullThis command pulls the configuration from the peer BIG-IP system and installs it on the local device. This command creates a temporary UCS file on the peer BIG-IP system, then transfers the UCS file to the local system, and installs it on the local system.
bigpipe config sync showThis command displays the status of the configuration synchronization system and the date and time the last configuration change was made.

Both the collection and installation processes are entirely data driven. Definitions for each of the above commands exist in the database and determine the actual operation of the command. It is possible to completely redefine the operations by changing these definitions.

BIG-IP system files

Certain BIG-IP system files are considered to be common in a redundant setup and are synchronized during a ConfigSync operation, and other BIG-IP system files are considered to be local to one system in a redundant setup and are not synchronized during a ConfigSync operation. The following table summarizes the BIG-IP system files that are synchronized during a ConfigSync operation:

BIG-IP system fileConfigSync
/config/bigip.confyes
/config/bigip_local.confno
/config/bigip_sys.confyes
/config/bigip_base.confno

Encryption for ConfigSync

Enabling encryption for ConfigSync causes the BIG-IP system to encrypt the UCS file immediately prior to synchronization.

The encryption implementation used for ConfigSync is based on the GNU Privacy Guard (GnuPG), and the encryption protocol uses a 256-bit AES cipher for ConfigSync UCS file encryption.

Transport of the configuration set

The SOAP protocol provides the messaging framework for ConfigSync communication, and it uses HTTPS to securely transport the configuration data set to the peer BIG-IP system. During the ConfigSync process, the client connects to the peer machine and performs an SSL key exchange using the BIG-IP system web server certificate and key. The client system then performs authentication based on the web administrative username and password. After authentication is complete, the collection file is transported and installed on the peer system.

The collection package uses the system hostname to determine whether the installation is local or common. A local installation results in the installation of all files; a common installation will only install the files that can be shared between systems.

Installation on a remote machine

After the collection file is processed and transported from the local system to the peer, the peer system initiates the installation process. The installation process has been updated beginning with BIG-IP 9.4.0.

9.0.0 through 9.3.0

The collection file, referred to as a UCS (User Configuration Set), is an IM (Installation Manager) package with the pre- and post-scripting defined to perform the necessary actions related to configuration synchronization.

9.4.0 - 10.x

Installation and conversion scripts exist natively on the target BIG-IP system, not in the UCS file. Starting with BIG-IP 9.4.0, the installation related scripts are replaced by install_ucs.pm.

Auto-detection

The auto-detect feature automatically detects configuration status and displays that status on all Configuration utility screens. The configsync state daemon (cssd) is used to check the status of each unit.

Note: Some configuration changes, such as importing a new certificate or key, may not trigger the Sync Required message.

Relevant database entries

BigDB variables set the behavior for ConfigSync operation. To display the configsync BigDB variables for your version of BIG-IP, use the bigpipe db |grep -i configsync command. The following table outlines many of the relevant configsync BigDB variables:

Note: You can set most of the ConfigSync BigDB variables using the Configuration utility.

ConfigSync entriesDescriptionDefault
Configsync.UsernameThis entry represents the username used by ConfigSync to log on to the other unit.admin
Configsync.passwordThis entry represents the password used for ConfigSync operations. 
Configsync.portThis entry represents the port to contact for ConfigSync operations.443
Configsync.timediffThis entry represents the acceptable time difference between the two devices in the redundant pair.600 seconds
Configsync.PeerIpaddrThis entry contains the IP address of the peer system to be used for ConfigSync. If this key has not been set, StateMirror.PeerIpaddr is used for ConfigSync. 
StateMirror.PeerIpaddrThis entry contains the IP address for the peer system, and is used for state mirroring and ConfigSync operations. 
StateMirror.IpaddrThis entry contains the IP address for the local system. 

ConfigSync Debug Tool

csTest.pl is a troubleshooting and diagnostic tool for ConfigSync that queries peer data and checks several BigDB variables over the network. Beginning with BIG-IP 9.2.0, the csTest.pl utility helps identify issues with the system, network, and configuration.

csTest.pl command line options

The csTest.pl command line options are as follows:

  • --q

    Quiet (no informational output)
     
  • --v

    Verbose (extra informational output)
     
  • --help

    Print out this message

Running the csTest script

To run the csTest script, perform the following procedure:

  1. Log in to the command line.
  2. Type the following command to run the csTest tool:

    csTest.pl --v

  3. Running csTest in verbose mode will output the following ConfigSync debug information:
    • Status of daemons that should be running for ConfigSync to be operational
    • Configuration information used by ConfigSync, such as failover addresses, TCP ports, and ConfigSync accounts
    • Auto detect status
    • Network connection status
    • SOAP time difference check
    • Product version test and whether major and minor product versions are identical
