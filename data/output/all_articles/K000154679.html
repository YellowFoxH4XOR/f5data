K000154679: How to Keep Passive NGINX Node to become Active and Remain Active

Type
Support Solution
Published
2025-09-13
Updated
2025-09-13
Applies to
  • NGINX Products
  • NGINX Plus: R34, R33, R32, R31, R35
Source
https://my.f5.com/manage/s/article/K000154679

Description

  • In an NGINX Plus active-passive high availability (HA) setup using keepalived, the passive node will not automatically take over if the active node is unhealthy but still remains in the active state.
  • There may be a requirement to force the passive node to become active and prevent the original active node from resuming service until a manual failback is performed.

Environment

  • Product: NGINX Plus
  • High Availability configuration: Active-Passive
  • HA mechanism: keepalived
  • Node priorities: Active node (priority 100), Passive node (priority 99)

Cause

The active node remains in the active state despite being unhealthy, which prevents automatic takeover by the passive node. Manual intervention is required to change the state and allow failover.

Recommended Actions

To force the passive node to become active and keep it as active until a manual failback:

  1. On the primary (active) node, stop the keepalived service to force it into backup state:
    sudo service keepalived stop
  2. This action will allow the passive node to take over as the new active node.
  3. The original primary will remain in backup state until you manually restart keepalived on it.
  4. To manually fail back to the primary, restart keepalived on that server:
    sudo service keepalived start
  5. For more information, refer to official documentation:
    https://docs.nginx.com/nginx/admin-guide/high-availability/ha-keepalived/#forcing-a-state-changeNote: This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge.
