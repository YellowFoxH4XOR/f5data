Known Issue

An SNMP query for sysCpuSensorSlot may fail.

This issue occurs when the following condition is met:

  • You use an SNMP GET query for sysCpuSensorSlot 0 (slot 0).

The /usr/share/snmp/mibs/F5-BIGIP-SYSTEM-MIB.txt incorrectly specifies the sysCpuSensorSlot Object ID (OID) as an Integer that starts at 1. As a result, your attempt to query for slot 0 will fail. The valid integer range for this OID should start at 0 (zero) since system slot numbers for some platforms actually start at 0 (zero).

Impact

An SNMP GET query for sysCpuSensorSlot 0 specifically will fail with an Index out of range:0 error.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • An SNMP query for sysCpuSensorSlot 0 specifically will fail with an Index out of range:0 error.

    For example, the following snmpget command queries specifically for slot 0 and fails with the following error:

    snmpget -v 2c -c public localhost .1.3.6.1.4.1.3375.2.1.3.6.2.1.5.0.1

    .1.3.6.1.4.1.3375.2.1.3.6.2.1.5.0.1: Unknown Object Identifier (Index out of range: 0 (sysCpuSensorSlot))

Workaround

To work around this issue, you can use the snmpwalk command and walk the SNMP object hierarchy from the parent sysCpuSensorSlot OID.

Impact of workaround: Performing the recommended workaround should not have a negative impact on your system.

For example, you could use snmpwalk commands similar to the following:

snmpwalk -v 2c -c public localhost .1.3.6.1.4.1.3375.2.1.3.6.2.1.5

or

snmpwalk -v 2c -c public localhost sysCpuSensorSlot

These commands will produce results similar to the following example:

F5-BIGIP-SYSTEM-MIB::sysCpuSensorSlot.0.1 = INTEGER: 0
F5-BIGIP-SYSTEM-MIB::sysCpuSensorSlot.0.2 = INTEGER: 0
