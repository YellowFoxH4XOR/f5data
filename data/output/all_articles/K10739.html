Known Issue

This is the result of a known issue. Disabling RAM Cache while a stale document is being refreshed causes the document to become permanently stale.

While the BIG-IP WebAccelerator refreshes the status of a stale document, the system temporarily marks the document as incomplete. Once the system receives a 304 (Not Modified) response from the origin web server (OWS), the document status is restored to complete. If RAM Cache is disabled while the document is in an incomplete or stale state, the document remains in that state even after RAM Cache is re-enabled. Since the document status remains incomplete, all subsequent requests for the document will bypass the RAM Cache and be forwarded directly to the OWS.

F5 Networks Product Development tracked this issue as CR129416 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator Release Notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.
