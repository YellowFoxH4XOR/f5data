Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator pvac parser generates a large number of PvPezParser warnings that are logged to the /var/log/wa/pvac.log file.

The PvPezParser message is a debug messages generated when the pvac parser encounters incorrect HTML code. A larger number of the debug messages will result in excessive log file growth that leads to a high iowait value, as displayed in the top command output, as the system logs the information to disk. This may eventually lead to system instability.

The parser warnings are a result of the following:

  • Bad HTML
  • Commented entries in JavaScript being parsed

Bad HTML

If the HTML source for a web page is formatted incorrectly, the BIG-IP WebAccelerator may report a parse error.

For example, the following section of HTML is missing a closing tag for the image tag:

<html><body>
<h1>Bad HTML Example1</h1>
<img src="/icons/apache_pb2.png"
</body></html>

The incorrect HTML will result in the following PvPezParser warning logged to the /var/log/wa/pvac.log file:

debug WA Debug: [          PvPezParser.cxx:4789           parser_warn ] < ended tag instead of expected >

For an alternative example, the following HTML section includes an image tag that is missing a closing quote for the image source:

<html><body>
<h1>Bad HTML Example2</h1>
<img src="/icons/apache_pb2.png>
</body></html>

The incorrect HTML will result in the following PvPezParser warning logged to the /var/log/wa/pvac.log file:

debug WA Debug: [          PvPezParser.cxx:4789           parser_warn ] >LF ended attribute instead of expected end quote

Commented entries in JavaScript being parsed

The pvac parses information that is contained within comment tags and treats the information as though it was HTML.

For example, the BIG-IP WebAccelerator will incorrectly interpret the left angle bracket ( < ) in the Javascript's for statement as the start of a tag, even though the Javascript is enclosed in an HTML comment:

<html><body>
<script type="text/javascript">
<!-- hide script from older browsers
for (i=0; i<9; i++) {
document.write('<img src="/icons/pie'+i+'.gif">');
}
// -->
</script>
</body></html>

In this situation, the following PvPezParser warning would be logged to the /var/log/wa/pvac.log file:

debug WA Debug: [          PvPezParser.cxx:4789           parser_warn ] < ended tag instead of expected >

Note: For more information, refer to K10801: The BIG-IP WebAccelerator pvac parser incorrectly parses commands that are commented out in HTML.

F5 Product Development tracked this issue as CR123842 and it was fixed in BIG-IP WebAccelerator version 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

This issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about how to manage F5 product hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For a list of the latest hotfixes for each BIG-IP software branch, refer to K9502: BIG-IP hotfix matrix.

Workaround

To prevent excessive logging of the PvPezParser debug message, create a filter to filter out the PvPezParser messages.

Note: For more information, refer to K10534: Filtering BIG-IP WebAccelerator pvac log messages.

For example, you can copy and paste the following using the bigpipe shell utility from the command line:

bpsh <<END
syslog include "
filter f_pvac {
    facility(kern) and match(\"WA\") and not match(\"PvPezParser.cxx\");
};"
END

To restore the system to the original configuration, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. To remove any additional syslog entries, type the following command:

    bigpipe syslog include none
  3. Save the changes made to file by typing the following command:

    bigpipe config save
