Known Issue

Multiple browser tabs accessing the same BIG-IP APM access session may trigger a TCP reset.

This issue occurs when all of the following conditions are met:

  • A user's browser is configured to open multiple browser instances (home page tabs) that reference the same BIG-IP APM access profile.
  • The BIG-IP APM access policy is simultaneously run from multiple browser tabs before the session is fully established.

Impact

The client may not be authenticated as expected, and the BIG-IP APM system terminates the session.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users cannot access the BIG-IP APM system, or may experience traffic disruptions.
  • In the /var/log/ltm file, you may observe an error message similar to the following example:

    err tmm[<pid>]: 01230140:3: RST sent from <client_side_ip>:<port> to 127.1.1.5:<port>, [0x1a07c9a:2108] {peer} TCP RST from remote system
    err tmm[<pid>]: 01230140:3: RST sent from 127.1.1.5:<port> to 127.0.0.1:<port>, [0x1a07c9a:2108] {peer} TCP RST from remote system
    err tmm[<pid>]: 01230140:3: RST sent from <virtual_server_ip>:<port> to <client_side_ip>:<port>, [0x19fd874:459] Internal error (APM::RBA requested abort (trans end error))
