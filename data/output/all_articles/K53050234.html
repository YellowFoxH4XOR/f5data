Known Issue

The Traffic Management Microkernel (TMM) may leak memory in the Elastic Compute Manager subsystem.

This issue occurs when the following condition is met:

  • You import one or more Secure Sockets Layer (SSL) certificates to the BIG-IP system that has a name containing ca-bundle.crt, such as my-ca-bundle.crt.

Impact

Over time, the memory usage of your BIG-IP system grows and may lead to TMM restarting. The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The tmm process leaks memory each time you modify the configuration.
  • The BIG-IP system unexpectedly fails over to another BIG-IP system in the device group.
  • The amount of cur_allocs memory for the Elastic Compute Manager subsystem continually increases over time.

    The following example displays the memory allocation information and resulting output for the tmctl command:

    # tmctl -d blade memory_usage_stat -w 999 | grep "^name\|^ECM"
    name                            allocated max_allocated  size slop cur_allocs tot_allocs fail_allocs type caches_used
    ECM                                  3248          3248     1    0         10         14           0 var: 56:96:192:384:896

Resolution

Status

F5 Product Development has assigned ID 627898 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Workaround

To work around this issue, you can rename your SSL certificates so that their names do not contain the ca-bundle.crt string.

Impact of Workaround: Performing the suggested workaround should not have a negative impact on your system.
