K000154693: DNS resolution may fail with ASM's ICAP configuration

Type
Support Solution
Published
2025-09-15
Updated
2025-09-30
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K000154693

Description

DNS resolution may fail when fully-qualified domain names (FQDNs) are configured in the ASM ICAP configuration.

Errors similar to the following may appear in the /var/log/ts/bd.log file:

   ICAP|NOTICE|Sep 31 12:33:00.906|12345|src/utils.c:0198|get_addr_from_host: gethostbyname(icap-server.example.com) herrno Unknown server error errno Success
   ICAP|NOTICE|Sep 31 12:33:00.907|12345|icap_client.c:0550|Error getting icap server ip from host - maybe no DNS?

Environment

One of the following modules is provisioned:

  • ASM
  • AFM

Cause

This issue is tracked with ID1934277.

Recommended Action

Here are two workarounds:

1. Use an IP address instead of a FQDN in the ASM ICAP configuration.

2. To use FQDNs in the ASM ICAP configuaraton, add the ICAP server's hostname to the local host table.

Run the following command once (changing icap-server.example.com appropriately) from the CLI:

tmsh modify /sys global-settings remote-host add { asm_icap_server { hostname icap-server.example.com addr $(dig +short icap-server.example.com | head -n1) } }

The host entry can then be updated periodically (as with a cron job) to pick up address changes:

tmsh modify /sys global-settings remote-host modify { asm_icap_server{ hostname icap-server.example.com addr $(dig +short icap-server.example.com | head -n1) } }
