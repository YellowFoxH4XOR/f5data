Known Issue

Beginning in BIG-IP 10.1.0, the default Server SSL profile automatically references the default Secure Sockets Layer (SSL) key and certificate found on the BIG-IP system. Prior to version 10.1.0, the default Server SSL profile key and certificate fields specified None. The default SSL key and certificate are self-signed, used by the Configuration utility, or for general testing. Servers that are configured to request (but not require) certificates, but disallow a certificate that cannot be verified, may prevent further communication and prevent all virtual servers using a default Server SSL profile from passing traffic.

Impact

Virtual servers that use a Server SSL profile may fail to pass traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Virtual servers using a default Server SSL profile, prior to upgrading to version 10.1.0 or later, fail to pass traffic.
  • Back end servers log that they are unable to verify the SSL certificates they are receiving.
  • If new profiles are created that inherit from the default Server SSL profile, they will use the default certificate and key.

Workaround

You can prevent further disruption of traffic and correct all Server SSL profiles that inherit settings from the default Server SSL profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Server SSL.
  3. Click on the default Server SSL profile.
  4. Select None from the drop-down menu for both Certificate and Key.
  5. Click the Update button.

This change will occur immediately and all custom Server SSL profiles that inherit from the default Server SSL profile will be updated.

From 10.2.2 certificates will default to None and the above workaround is not necessary.
