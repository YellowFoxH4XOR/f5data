Topic

The BIG-IP APM access policy Endpoint Security Client-Side Capability checks populate BIG-IP APM session variables based on information that the system obtains from the connecting user's browser user-agent string to determine the browser's expected capabilities.

Description

The BIG-IP APM VPE Client-Side Capability checks and the Endpoint Security Server-Side option take values from the connecting user's browser user-agent string and sets session variables for the capabilities that the system expects the browser to have. Using the findings of the Endpoint Security Client-Side Capability checks, you can customize the access policy accordingly. Client-Side Capability checks populate the following BIG-IP APM session variables based on the information retrieved from a connecting user's browser.

session.client.js
session.client.activex
session.client.plugin

The session variables are set to the following Boolean values:

0 = failed
1 = passed

Important: The Client-Side Capability checks functionality simply retrieves these values and does not determine if the user's browser and operating system is actually able to execute the checked add-ons.

The default BIG-IP APM expression used by the Client-Side Capability checks action is as follows:

expr { [mcget {session.client.js}] == 1 && [mcget {session.client.activex}] == 1 || [mcget {session.client.js}] == 1 && [mcget {session.client.plugin}] == 1 }

The expression requires that the user's browser has JavaScript and ActiveX support or JavaScript and Netscape plugin support.

The BIG-IP APM system uses the information it obtains from the User-Agent (session variable session.user.agent), extracting the user's browser type and operating system. The system compares this information to an internal list to determine the appropriate session variable settings that the Client-Side Capability checks action uses.

The following example is a successful result of the Client-Side Capability checks:

Mozilla/5.0 (Windows NT 6.1; WOW64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/35.0.1916.114 Safari/537.36
session.client.js = 1
session.client.activex = 0
session.client.plugin = 1

Mozilla/4.0 (compatible; MSIE 8.0; Windows NT 6.1; WOW64; Trident/4.0; SLCC2; .NET CLR 2.0.50727; .NET CLR 3.5.30729; .NET CLR 3.0.30729; Media Center PC 6.0; .NET4.0C; .NET4.0E; InfoPath.3)
session.client.js = 1
session.client.activex = 1
session.client.plugin = 0

Mozilla/5.0 (X11: Linux x86_64: en-us: TB782B Build/Ice Cream) AppleWebKit/534.24 (KHTML%2c like Gecko) Chrome/11.0.696.34 Safari/534.24.
session.client.js = 1
session.client.activex = 0
session.client.plugin = 1

The following example is an unsuccessful result of the Client-Side Capability checks:

Mozilla/5.0 (iPhone: CPU iPhone OS 7_1 like Mac OS X) AppleWebKit/537.51.2 (KHTML%2c like Gecko) Version/7.0 Mobile/11D167 Safari/9537.53.
session.client.js = 1
session.client.activex = 0
session.client.plugin = 0

Opera/9.80 (X11; Linux x86_64; Edition Linux Mint) Presto/2.12.388 Version/12.16
session.client.js = 0
session.client.activex = 0
session.client.plugin = 0

Note: Platforms where you are unable to install the browser add-ons, such as certain Android and iPhone devices, as well as Microsoft Windows RT and Windows Internet Explorer native 64-bit browsers, will not pass the Client-Side Capability checks.
