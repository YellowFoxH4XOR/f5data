Known Issue

Users are unable to modify and delete a pool monitor in the same Traffic Management Shell (tmsh) transaction.

This issue occurs when one of the following conditions is met:

  • You attempt to perform the following tasks in the same tmsh transaction:
    • Create a pool member and associate it with a health monitor
    • Attempt to delete the monitor
  • You attempt to modify and delete a pool monitor using the iApp application
For example, the following tmsh command sequence cannot modify and delete a pool monitor if executed within the same tmsh transaction:

(tmos)# create ltm monitor http http1
(tmos)# create ltm pool pool1 monitor http1
(tmos)# create cli transaction
(tmos)# modify ltm pool pool1 monitor http
(tmos)# delete ltm monitor http http1
(tmos)# submit cli transaction

Impact

Attempts to perform multiple changes in a single transaction may fail. Additionally, configuration synchronization (ConfigSync) operations fail after attempts to modify a pool monitor in the iApp application.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Attempts to perform a ConfigSync operation fail when you modify a pool monitor in the iApp application.
  • In the /var/log/ltm file, you observe an error message that appears similar to the following example:

    err mcpd[1234]: 01070083:3: Monitor /Common/http1 is in use

Workaround

To work around this issue, you can use separate tmsh transactions to modify and delete a pool monitor.
