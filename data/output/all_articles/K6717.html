Known Issue

SNMP queries for BIG-IP GTM objects my result in the following error messages logged in the /var/log/gtm file:

gtmd: 011ac001:3: Application Context has no Application Namegtmd: 011af000:3: No DC Name specified in query_stat request for DCgtmd: 011af000:3: No Name specified in query_stat request for Poolgtmd: 011af000:3: No IP specified in query_stat request for Pool Membergtmd: 011af000:3: No Name specified in query_stat request for Rulegtmd: 011af000:3: No Name specified in query_stat request for Servergtmd: 011af000:3: No IP specified in query_stat request for Virtual Server

These error messages are logged because the SNMP agent that communicates with gtmd utility does not include an Application Context, Name, or IP address when it requests data from the gtmd utility. These are benign messages that do not indicate a specific issue with the BIG-IP GTM system.

The following Global Object Identifiers define where these error messages can occur (F5-BIGIP-GLOBAL-MIB):

-- bigipGlobalTMgtmApplications          OBJECT IDENTIFIER ::= { bigipGlobalTM 2 }gtmDataCenters           OBJECT IDENTIFIER ::= { bigipGlobalTM 3 }gtmPools                 OBJECT IDENTIFIER ::= { bigipGlobalTM 6 }gtmRules                 OBJECT IDENTIFIER ::= { bigipGlobalTM 8 }gtmServers               OBJECT IDENTIFIER ::= { bigipGlobalTM 9 }gtmVirtualServers        OBJECT IDENTIFIER ::= { bigipGlobalTM 11}--gtmApplicationsgtmApplicationStatus     OBJECT IDENTIFIER ::= { gtmApplications 2 }gtmAppContextStat        OBJECT IDENTIFIER ::= { gtmApplications 3 }--gtmDataCentersgtmDataCenterStat        OBJECT IDENTIFIER ::= { gtmDataCenters 2 }--gtmPoolsgtmPoolStat              OBJECT IDENTIFIER ::= { gtmPools 2 }gtmPoolMemberStat        OBJECT IDENTIFIER ::= { gtmPools 6 }--gtmRulesgtmRuleEventStat         OBJECT IDENTIFIER ::= { gtmRules 3 }--gtmServersgtmServerStat            OBJECT IDENTIFIER ::= { gtmServers 2 }--gtmVirtualServersgtmVirtualServStat       OBJECT IDENTIFIER ::= { gtmVirtualServers 3 }

F5 Product Development tracked this issue as CR66454 and it was fixed in BIG-IP GTM 9.3.0 and 9.4.0. For more information about upgrading, refer to the BIG-IP GTM Release Notes.
