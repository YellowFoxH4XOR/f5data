K000150152: Proxy Auto-Configuration (PAC) files with UTF-8 characters are not supported on BIG-IP APM

Description

 When using the APM Network Access with Chrome browser, traffic may bypass the configured proxy and go directly to the Internet.

Other browsers such as Edge and Firefox function correctly.

Chrome logs will indicate a PAC_JAVASCRIPT_ERROR caused by a special character at the beginning of the PAC file.

The issue is specific to Chrome's handling of PAC files.

Environment

  • APM Network Access with proxy pac defined in the Network Access resource 
  • PAC file uses UTF-8 characters

Cause

 As the PAC file was saved with UTF-8 present (due to the presence of non-ASCII characters, such as French or German accentuated characters), a Byte Order Mark (BOM) (EF BB BF) is added the beginning of the file. This BOM is invisible in most text editors but causes issues when processed by Chrome, which is stricter about JavaScript syntax in PAC files.

Recommended Actions

 You can use any of these actions to address the problem:

  • Ensure that the PAC file is saved in a way that will only retain ASCII characters
  • Avoid using non-ASCII characters in your PAC file
  • Manually Strip BOM Characters from PAC file using a shell command: sed -i '1s/^\xEF\xBB\xBF//' proxy_pac_example.pac
