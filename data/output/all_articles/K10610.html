K10610: The SSL session cache is not shared across multiple TMM instances on CMP systems in BIG-IP versions prior to 10.1.0

Topic

The BIG-IP SSL session cache allows clients to reuse SSL session ID information from previously negotiated SSL sessions. SSL session resumption increases performance by limiting processor-intensive SSL key exchange functions.

Note: For more information about the BIG-IP LTM SSL session cache, refer to K6767: Overview of the BIG-IP LTM SSL session cache.

Prior to BIG-IP version 10.1.0, the BIG-IP SSL session cache is not shared across multiple TMM instances on CMP systems. Therefore, a returning client may need to reestablish SSL key exchange parameters when the BIG-IP system distributes the connection to a different TMM instance.

For example, when a client connects to a Client SSL virtual server on a CMP system, the BIG-IP distributes the connection to an available TMM instance, such as TMM0. TMM0 stores the SSL session ID information in its session cache. The session ID is not shared across multiple TMM instances. If the client returns and the BIG-IP distributes the connection to a different TMM instance, such as TMM1, the new TMM instance is not aware of the previously negotiated session and forces SSL session resumption with the browser.

This issue may result in the following behaviors:

  • SSL persistence failure
  • Re-entering passwords when client certificates are used

F5 Product Development tracked a request for enhancement as CR123255 to implement a distributed SSL session cache and the feature was added in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.
