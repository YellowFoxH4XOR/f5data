K000160023: OCSP Proxy Configuration Sends Malformed Host Header Including Full URL Path in BIG-IP LTM

Type
Support Solution
Published
2026-02-17
Updated
2026-02-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160023

Description

When configuring OCSP (Online Certificate Status Protocol) validation on BIG-IP LTM using a proxy pool instead of a DNS resolver, HTTP requests sent to the OCSP responder include the full URL path in the Host header instead of only the hostname.

For example:

  • Actual (incorrect): Host: "hostname"."domain".net/oclisocsp/path-xxx/path-yyy
  • Expected (correct): Host: "hostname"."domain".net

This malformed Host header causes the backend OCSP responder to return HTTP 400 Bad Request errors, resulting in failed OCSP certificate status validation.

Environment

  • OCSP configuration using proxy-server-pool parameter in:
    • sys crypto cert-validator ocsp profile
    • ltm profile ocsp-stapling-params profile
  • LTM OCSP configuration (not APM OCSP)
  • APM module not provisioned

Cause

Bug ID 2220009: OCSP monitoring of traffic certificates using a proxy server sends malformed HTTP host header

Answer/Recommended Actions

Create a support case with the request for the Engineering Hotfix with fix for ID 2220009
