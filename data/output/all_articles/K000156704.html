Description

This article describes the issue while polling SNMP OIDs related to BGP objects under .1.3.6.1.2.1.15 OID. After you use the snmpwalk command to test the OID "snmpwalk -v2c -c public localhost .1.3.6.1.2.1.15", you receive following error message:

BGP4-MIB::bgp = No Such Object available on this agent at this OID

Environment

  • BIG-IP LTM,
  • Dynamic routing protocol like BGP,
  • Default route domain.

Cause

Most probably, the issue is caused by a disabled BGP protocol under specific default route domain.

Recommended Actions

To ensure that BGP is up and running, follow the steps below:

  1.  The tmrouted process must be running on the BIG-IP system in order for dynamic routing to function. To verify whether the tmrouted process is running, enter the following command at the command line:
    bigstart status tmrouted
    To start the tmrouted daemon, enter the following command:
    bigstart start tmrouted
  2. BGP must be enabled in ZebOS. To verify whether BGP is enabled in ZebOS, enter the following command at the command line:
    zebos check
    If BGP is enabled in ZebOS, the zebos check command returns output similar to the following:
    nsm is running [22319]
    imi is running [22317]
    bgpd is running [22320]
    If BGP is not enabled in ZebOS, refer to the following article for information about starting BIG-IP ARM:
    K13802: Enabling dynamic routing protocols for a route domain

Once the BGP is enabled, you can test OIDs with the command below:

snmpwalk -v2c -c public localhost .1.3.6.1.2.1.15

You should receive the following similar output:

BGP4-MIB::bgpVersion.0 = Hex-STRING: 10
BGP4-MIB::bgpLocalAs.0 = INTEGER: 0
BGP4-MIB::bgpIdentifier.0 = IpAddress: xx.xx.xx.xx
