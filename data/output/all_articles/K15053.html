Known Issue

The BIG-IP GTM system may incorrectly mark a resource down. This issue occurs when all of the following conditions are met:

  • The BIG-IP GTM system is configured to monitor the resource using the BIG-IP GTM HTTPS health monitor.
  • The resource is an HTTPS web server that does not support the SessionTicket Transport Layer Security (TLS) extension.

The SessionTicket TLS extension is typically included in the ClientHello message from a Secure Sockets Layer (SSL) client to indicate that it supports TLS session resumption without server-side state. For information about this mechanism, refer to RFC 5077: Transport Layer Security (TLS) Session Resumption without Server-Side State.

Impact

The BIG-IP GTM system marks available resources down.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A packet capture between the BIG-IP GTM system and the affected resource shows the BIG-IP GTM system sending the SessionTicket TLS extension in its ClientHello message, and the affected resource fails the TLS session with an Encrypted Alert (21) error.
  • The BIG-IP GTM system incorrectly marks an available resource down.

Workaround

To work around this issue, you can write an external script, similar to the following example. You can then import the script to the BIG-IP GTM system and configure the system to use this script as an external health monitor to monitor the affected resource instead of the BIG-IP GTM HTTPS health monitor:

#!/bin/sh
# these arguments supplied automatically for all external pingers:
# $1 = IP (nnn.nnn.nnn.nnn notation or hostname)
# $2 = port (decimal, host byte order)
# $3 and higher = additional arguments
#
# In this script, $3 is the directory to GET
# $4 is the regular expression to match
#

pidfile="/var/run/https_tls_sessionticket_workaround.$1..$2.pid"

if [ -f $pidfile ]
then
kill -9 `cat $pidfile` > /dev/null 2>&1
fi

echo "$$" > $pidfile

node_ip=`echo $1 | sed 's/::ffff://'`

curl -k https://$1/$3 2> /dev/null | grep -E -i $4 > /dev/null

status=$?
if [ $status -eq 0 ]
then
echo "up"
fi

rm -f $pidfile

# end of script

For more information about writing a customized external script for your application environment, refer to the following articles:

  • K7444: Requirements for external monitor output
  • K8154: The BIG-IP GTM EAV monitor considerations

Importing the script and configuring the system to use the script as an external health monitor

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Copy the external script to a text editor of your choice, and save it to your desktop.
  2. Upload the external script to the BIG-IP system using one of the procedures described in K13423: Importing external files to the BIG-IP system.
  3. When you have successfully uploaded the external script to the BIG-IP system, navigate to one of the following locations:
    • In BIG-IP 11.5.0 and later

      DNS > GSLB > Monitors
    • In BIG-IP 11.0.0 through 11.4.1

      Global Traffic > Monitors
  4. Click Create.
  5. In the Name setting box, type a name for the external health monitor.

    For example:

    SOL15053mon
  6. From the Type setting menu, select External.
  7. From the External Program setting menu, select the imported external script.
  8. Enter the combined send string (if any) and receive string (if any) from the BIG-IP GTM HTTPS health monitor that is assigned to the affected resource in the Arguments setting. Separate the two strings with a space.

    For example, if the send string is GET /myweb and the receive string is weareup, then you would type the following in the Arguments setting:

    myweb weareup
  9. Click Finished.
  10. Navigate to one of the following locations:
    • In BIG-IP 11.5.0 and later

      DNS > GSLB > Servers > Server List
    • In BIG-IP 11.0.0 through 11.4.1

      Global Traffic > Servers > Server List
  11. Click the name of the affected resource.
  12. Select the BIG-IP GTM HTTPS health monitor from the Selected list, and then click >> to remove it from the affected resource for the Health Monitors setting.
  13. Select the external health monitor created in previous steps from the Available list and click << to assign it to the affected resource for the Health Monitors setting.
  14. Click Update.
