Description

When troubleshooting PingAccess on the BIG-IP, the following outlines how to collect data and verify configuration.

Environment

  • BIG-IP

  • PingAccess

Cause

1. Verify Licensing

  • If you see errors like Ping Access encountered error: ERR_LICENSE in /var/log/paaensure you are not using an APM Lite license. PingAccess integration requires a full APM license.
    • See: KB K06669223: Error Message: err tmm[nnnn]: 019a0020:3: ... Ping Access encountered error: ERR_LICENSE

2. Validate Prerequisites and Configuration

  • Ensure you have downloaded the correct agent properties file from your PingAccess server.
  • If using SSL, the agent properties file should contain the PingAccess server’s SSL certificate. When importing, select the option to import the certificate so BIG-IP can create a server SSL profile.
  • If the certificate is not detected, manually import it and assign it to a server SSL profile.
  • Reference: Integrating APM with PingAccess (BIG-IP 17.x)

3. Configure Pools and Profiles

  • Create a pool of PingAccess servers (default port is 3030, but confirm your deployment).
  • Assign a health monitor (TCP or HTTP/HTTPS with GET /pa/heartbeat.ping\r\n).
  • Create a PingAccess profile in APM, referencing the agent properties and the pool.
  • Assign the PingAccess profile to the relevant virtual server.
  • Reference: Integrating APM with PingAccess (BIG-IP 17.x)

4. Troubleshoot Application Access

  • If backend applications are unreachable:
    • Capture packets (PCAP) on BIG-IP and backend servers.
    • Check for IP conflicts or ARP issues (e.g., SNAT pool IPs conflicting with Self IPs).
    • Validate MAC address mappings on backend devices.
    • See: KB K000152034: Troubleshooting Application Access Failure via BIG-IP Virtual Server (VIP)

5. Use iRules Events for Advanced Debugging

  • The PING_REQUEST_READY and PING_RESPONSE_READY iRules events can be used to insert custom headers or log data when requests/responses are sent to/from the PingAccess policy server.
    • See: PING_REQUEST_READY iRules API
    • See: PING_RESPONSE_READY iRules API

6. REST API and Profile Assignment

  • For advanced troubleshooting or automation, you can use the REST API to assign or remove PingAccess profiles and rewrite profiles from virtual servers.
    • See: Editing Virtual Server in Access (BIG-IQ API)

7. General Troubleshooting Steps

  • Check logs: /var/log/paa for PingAccess plugin errors.
  • Confirm all referenced pools, profiles, and certificates are correctly configured and assigned.

8. If issues persist, collect QKView and packet captures and open a support case with F5.

Please collect the following data while reproducing the issue:

  1. Close all sessions on the test client.
  2. Modifying APM logging for PingAccess profile
    * Note: Only the default-log-setting applies to PingAccess profile logging.
     
  3. SSH to log into the Advanced Shell (bash) prompt.
  4. Run the following command:
    tmsh modify sys db tcpdump.sslprovider value enable
  5. Start tcpdump on the BIG-IP with the following commands and replace <>'s with the valid information
    Capture traffic w/ --f5 ssl flag
    # tcpdump -s0 -nni 0.0:nnn --f5 ssl host <Client_IP> or host <ping Access mbr> or host <ping access mbr> or host <pool mbr> -vw /var/tmp/CaseNumber.pcap
  6. Please also start a Fiddler capture running on the client.
    You can download Fiddler via the link below.
    https://www.telerik.com/download/fiddler
    Within fiddler you will want to enable decryption: select Tools->Fiddler Options, and enable Decrypt HTTPS Traffic.
    Configure Fiddler to Decrypt HTTPS Traffic
    https://docs.telerik.com/fiddler/configure-fiddler/tasks/decrypthttps
  7. Reproduce the issue by attempting to connect through APM. Ctrl + C to stop the capture after the issue has been reproduced. Save the Fiddler trace as a .saz file
  8. Turn down access policy logging on the BIG-IP
  9. Please issue the below command from the  command line and you would have a file generated in /var/tmp folder, i.e. /var/tmp/$HOSTNAME-logfiles.tar.gz.
    tar -zcvf /var/tmp/$HOSTNAME-logfiles.tar.gz /var/log/*
  10. Generate a qkview, and collect the packet capture, pms, and tarball of log files from the system using Winscp or filezilla.
    Please upload all data directly to your support case, or to securefiles.f5.com per the following articles.

    K000138089: Security enhancements for F5 Secure Files
    K000090853: Exchange files with F5 Support
    K000138087: Give or receive access to a support case folder on Secure Files

Answer/Recommended Actions
Ensure PingAccess is configured correctly:

Part One:

  1. Install Java from Recommend version 17, 20+ seemed to fail for me ¯\(°_o)/¯:
    https://www.oracle.com/java/technologies/downloads/
  2. Go to PINGIdentity and setup an free account
  3. Download the PINGAccess Server from:
    https://www.pingidentity.com/en/resources/downloads/pingaccess.html
  4. Then you need to add the Environmental Variable 
    JAVA_HOME = <path_to_java>
     
  5. Reboot your Server to make variable take.
  6. Install PINGAccess on Server.
  7. Request a PINGAccess License for after install
    https://www.pingidentity.com/en/account/request-license-key.html
    ( It will appears in Your Licening Key in the Ping UI )
    https://support.pingidentity.com/s/manage-license-keys

Part Two:

  1. Login to your PINGAccess webui: https://<hostname>:9000
    Administrator/2Access
    Change your Password to Abc123!@
  2. Click on Agents → Add Agent
     

  3. Necessary Items to configure

    Namewhatever you want
    PINGACCES HOSTThis will be your Ping Server address and port 3030 (it can be either the hostname of the server or the IP address
  4. Click on Save and Download
    This file is the PINGAccess Agent properties file that we import into the BIG-IP.

  5. Click on Add Application
     

  6. Necessary Items to configure

    NAMEwhatever you want
    CONTEXT ROOT/
    VIRTUAL HOST(S)Click on +Create to create a new Host
    (All this will be is the Hostname of the Virtual Server and Port 443)
    DESTINATIONAgent
    AGENT<Name of Agent from #3>

Part Three

  1. Login to BIG-IP
  2. Create WebServer App Pool to protect on BIG-IP (Point at any IIS Server)
  3. Create Ping Pool pointing at the Ping Server on port 3030
  4. Create basic SSL Bridging VS and apply WebServer App pool W/O ping profile to test basic LTM setup
  5. Go to Virtual Server and make sure the IIS Web App is available.
  6. Configure the Ping Agent File
    Access  ››  Federation : PingAccess : Agent Properties → Click Create
  7. Name the profile and import the PAAgent_ag properties file from the PINGAccess Server
  8. Navigate to:
    Access  ››  Federation : PingAccess : Profiles → Click Create
  9. Name the profile – Select the PPA properties files – Select your Ping Pool – Use HTTPS – Choose ServerSSL Profile ( I used insecure-compatible ) – Click Finished
  10. Apply Ping Profile Virtual Server in Virtual Server Settings
  11. Select your SSL Bridging Virtual Server (the one you tested with basic LTM and IIS).
  12. Under the Access Policy or Access Profile section, assign the PingAccess profile you created earlier (the one referencing the imported agent properties and Ping pool).
  13. Save and update the configuration.
