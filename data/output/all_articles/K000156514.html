K000156514: CDN Static Content Not Cached Due to Set-Cookie Header

Type
Support Solution
Published
2025-09-17
Updated
2025-09-17
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000156514

Description

When using F5® Distributed Cloud CDN, static content may not be cached as expected. This results in a CDN cache hit ratio of 0%, causing all requests to be forwarded to the origin server.

Consequences include increased backend load, higher latency, and elevated infrastructure costs. HTTP response headers such as X-Cache-Status: MISS or Expired may be observed for static assets, and the CDN dashboard might not display expected cache statistics.

Environment

  • F5® Distributed Cloud CDN

Cause

The origin server sends a Set-Cookie header in HTTP responses for static content. By default, the presence of a Set-Cookie header instructs the CDN not to cache that content, since it is typically associated with dynamic or user-specific data. As a result, the CDN does not cache these assets and serves every request from the origin.

Answer/Recommended Actions

  • Update your CDN cache rules to disregard the Set-Cookie header for static or non-sensitive content. This enables caching even if the origin includes a Set-Cookie header.
  • Ensure that only static or non-sensitive content is routed through the CDN where possible. If separation is not feasible, configure explicit cache rules targeting only appropriate file types.
  • Review origin server response headers for static assets; avoid using directives like no-store, no-cache, or max-age=0 on resources intended for caching.
  • After updating cache rules, verify that requests return an X-Cache-Status: HIT header and confirm that relevant statistics appear in the F5 Distributed Cloud dashboard.
  • If WAF is enabled, ensure it does not block legitimate requests required by the CDN. For troubleshooting purposes and if security policy allows, consider temporarily setting WAF to monitoring mode.
  • Collect historical data (such as HAR files) when investigating unexpected caching behavior or changes in response headers.
  • If you have temporarily bypassed the CDN via route changes due to this issue, revert those changes after confirming proper caching functionality.
