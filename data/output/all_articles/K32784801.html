Known Issue

The Traffic Management Microkernel (TMM) may experience an out-of-memory state and restart when processing a high volume of Elliptic Curve Diffie-Hellman (ECDH) and ECHDHE ciphers.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system runs on a hardware platform.
  • Your configuration includes one or more virtual servers with an associated SSL profile.
  • Your BIG-IP system processes a high volume of SSL traffic using ECDH and ECDHE ciphers.

Impact

The BIG-IP system may temporarily fail to process traffic while TMM restarts. If the BIG-IP system is part of a redundant configuration, traffic fails over to the standby BIG-IP system while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you use the tmsh show sys memory | grep -iE 'SubSystem|ssl_hs' command, you observe the system's SSL memory statistics continually increasing, similar to the following output example:

    tmsh show sys memory | grep -iE 'SubSystem|ssl_hs'

    Sys::SubSystem Memory
    SubSystem                        Alloc (bytes)  Max Alloc (bytes)  Object Size
    ssl_hs                                       0                  0        12345
    ssl_hs_m                                     0                      0        12345
    ...
    Sys::SubSystem Memory
    SubSystem                        Alloc (bytes)  Max Alloc (bytes)  Object Size
    ssl_hs                                73262920           73262920        12345
    ssl_hs_m                             377262080              377262080        12345

  • Your BIG-IP system fails over to another system in the device group.
  • TMM produces a core file in the /var/core directory.
