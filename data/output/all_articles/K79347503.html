Known Issue

The BIG-IP AFM SSH proxy resets client connections when public keys contain trailing comments.

This issue occurs when the following conditions are met:

  • You have configured the BIG-IP AFM system with an SSH virtual server and an SSH proxy security profile.
  • The Real Server Auth section of your SSH proxy security profile public key contains a trailing comment, such as an email address.

    For example:

    ssh-rsa AskF53NzaC1yc2EAAAADAQABAAABAQCmE9f8b1PSHYiCbrdsnR53kJVO/nq+YzCgAV3StlSg+JZD8KxJlzY
    ecMMOnAjTPnUR4KXKIdIS22lTDwYFghHO3iTJeAJYbXU9bgk3PkUF2MzWXYgLICZ770F3+nvY8RstgJto616rLTRFsi
    uS5Eu3c/J2OXh4DZ/GFBYhSj61rZCaLvYgAQujZt1Qyctjat8gsjGeRYbyWzSr user@example.com

Impact

The system resets the client connection attempts before the connection is completed.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your SSH client reports an error message similar to the following example when attempting to connect:

    packet_write_wait: Connection to 10.11.12.100 port 22: Broken pipe

  • If you have configured the BIG-IP system to log TCP RST packets, the system logs messages similar to the following example to the /var/log/ltm file:

    err tmm2[]: 01230140:3: RST sent from 10.22.12.254:59292 to 10.22.12.1:22, [0x223c8e4:820] {peer} Internal error (AFM::SSH requested abort (error during the key_exchange_thread (or reexchange). see /var/log/sshplugin for more details. ))
    err tmm2[]: 01230140:3: RST sent from 10.11.12.100:22 to 10.11.12.1:59292, [0x223c8e4:820] Internal error (AFM::SSH requested abort (error during the key_exchange_thread (or reexchange). see /var/log/sshplugin for more details. ))

    Note: For more information regarding TCP RST logging, refer to K13223: Configuring the BIG-IP system to log TCP RST packets

  • If you have configured the database variable log.sshplugin.level with the value debug, the system logs messages similar to the following example to the /var/log/sshplugin file:

    debug : SSHPLUGIN: sshplugin_0|SSHPlugin|ssh_setup_serverside|Core|the backend ssh server does not have a public key that matches the configuration! (0) Erroring out of this connection.

    Note: For information regarding default log levels and how to modify them, refer to K13455: Overview of BIG-IP logging BigDB database keys (11.x - 12.x)

    Important: Always return logging values to the default settings when you have completed the troubleshooting. Leaving verbose logging enabled when the system is in normal production mode can cause poor system performance.

Workaround

To work around this issue, you can remove the comment from the end of the public key of the affected SSH proxy security profile. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Protocol Security > Security Profiles > SSH Proxy.
  3. Click the Name of the affected SSH proxy profile.
  4. Click the Key Management tab
  5. In the Real Server Auth section, edit the Public Key and remove ONLY the comment at the end of the line.

    Note: Removing any portion of the actual public key file, except for the trailing comment will result in the same errors indicated in the article description.

  6. At the top of the page, click Commit Changes to System.
