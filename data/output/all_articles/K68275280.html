Known Issue

Symmetric Deduplication v3 (SDD v3) may experience degraded performance after a high availability (HA) failover event.

This issue occurs when all of the following conditions are met:

  • The BIG-IP AAM systems are configured to perform Symmetric Deduplication (SDD) using the SDD v3 Codec between two HA clusters.
    • A local (client side) HA cluster of BIG-IP AAM systems.
    • A remote (server side) HA cluster of BIG-IP AAM systems.
  • The BIG-IP AAM systems have processed traffic and populated the cache with deduplicated data.
  • The remote (server side) BIG-IP AAM HA cluster experiences a failover event.
  • Clients attempt to download files that had been previously transferred before the failover event.

After a failover event on the remote (server side) BIG-IP AAM HA cluster, deduplication begins performing poorly for requests of previously cached objects. Requests that previously resulted in cache hits now result in cache misses. However, deduplication functions normally for objects that were not cached before the failover event occurred.

Impact

After a failover event on the remote (server side) BIG-IP AAM HA cluster, symmetric deduplication performance is severely degraded for requests of previously cached objects.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice that SDD v3 deduplication performance is degraded for some file transfers after a failover event.
  • You notice a poor hit rate for SDD v3 deduplication objects after a failover event.

Workaround

To recover from this issue, you must restart the Active system for the local (client side) BIG-IP AAM HA cluster. To do so, perform the following procedure:

Impact of workaround: The bigstart restart command will cause a failover and temporarily interrupt traffic processing. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the command line of the Active system for the local (client side) BIG-IP AAM HA cluster.
  2. Restart the BIG-IP system by typing the following command:

    bigstart restart
