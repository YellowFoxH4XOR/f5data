K13657: The AVR::DISABLE iRule command may be ignored for subsequent HTTP requests on a single TCP connection

Known Issue

 

Description

The BIG-IP iRules parser might ignore the AVR::DISABLE iRule command for multiple HTTP requests on a single TCP connection.

This issue occurs when all of the following conditions are met:

  • An iRule uses the AVR::ENABLE and AVR::DISABLE command to control AVR processing.
  • An HTTP request triggers the AVR::ENABLE command.
  • Subsequent HTTP requests arrive on the same TCP connection and match the conditions required to trigger the AVR::DISABLE command.

Impact

AVR may process more connections than intended, resulting in increased system load.

Symptoms

As a result of this issue, you might encounter the following symptom:

  • BIG-IP iHealth lists Heuristic H385434 on the Diagnostics > Identified > Low screen.
  • Connections that match the AVR::DISABLE command conditions will be incorrectly processed by the AVR module.

Workaround

To work around this issue, you can reduce the AVR sampling rate. To do so, perform the following procedure:

Impact of workaround: None

While you cannot work around the cause of this issue, if you are using the AVR::DISABLE command to reduce the amount of data processed by the AVR module, you can achieve the same result by reducing the number of transactions the AVR module samples.

  1. Log in to the Configuration utility
  2. Navigate to the Local Traffic > Profiles > Analytics screen.
  3. Select the appropriate Analytics profile for your application.
  4. Set the Traffic Sampling Ratio value to a lower ratio of sampling.
  5. Click Update.
