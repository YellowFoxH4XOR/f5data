Known Issue

This is the result of a known issue. If the expiration date for an SSL certificate is set to a date later than January 18, 2038, the certificate expiration date is displayed incorrectly in the Configuration utility, and also when verifying the certificate using the checkcert utility. For example, if the expiration date is September 1, 2039, the Configuration utility displays the expiration date as Dec 31, 1969, and the output of the checkcert utility appears similar to the following example:

01380001:4: Certificate 'host.domain.com' in file host.crt expired on Wed Dec 31 23:59:59 1969 GMT

This issue is cosmetic only. OpenSSL properly recognizes the certificate, and SSL transactions using the certificate and key pair are successful.

F5 Product Development is tracking the Configuration utility display issue as ID 262985, ID 249519, and ID 304746 (formerly CR53523).

F5 Product Development tracked the checkcert utility display issue as ID 223259 (formerly CR128520) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Note: Using a self-signed SSL certificate with an extended expiration date increases the vulnerability window for the certificate because self-signed SSL certificates cannot be revoked through methods, such as Certificate Revocation List (CRL).

Workaround

You can work around this issue by entering the openssl x509 command to display the expiration date of the certificate in question. For example, to display the expiration date of certificate for the host.domain.com host, which is stored in the host.crt file, you would type the following command:

openssl x509 -in /config/ssl/ssl.crt/host.crt -text -noout

The Validity section of the command output displays the correct expiration date.

For example:

Validity
Not Before: Sep 1 01:01:01 2009 GMT
Not After : Sep 1 16:20:00 2039 GMT
