Known Issue

A Client SSL profile in a non-default partition loses the cert-key-chain configuration when only the /Common partition is loaded.

This issue occurs when all of the following conditions are met:

  • A user creates a Secure Sockets Layer (SSL) profile, key, and certificate in a partition other than /Common.
  • The BIG-IP system configuration is loaded using the tmsh load sys config partitions { Common } command.

Client connections use the BIG-IP system's default certificate and key during the SSL handshake instead of the intended site certificate and key.

Impact

The BIG-IP system does not use the expected certificate, and users receive a browser warning message indicating a host name mismatch or different website address.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Secure client connections to the BIG-IP system use the wrong certificate.
  • Users receive a browser warning message that indicates a host name mismatch or different website address.
  • When you use the Traffic Management Shell (tmsh) to list the affected profile, no key or certificate is displayed.

Workaround

To work around this issue, you can load all partitions. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To load all partitions, type the following command:

    load sys config partitions all
