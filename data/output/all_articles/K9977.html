Known Issue

Note: This issue was introduced in BIG-IP WebAccelerator 9.4.5-HF2.

This is the result of a known issue. When the BIG-IP WebAccelerator Intelligent Browser Referencing (IBR) feature re-writes the URL for an object, the inserted pv tag may include an invalid prefix. The inserted pv tag should have a prefix of ;pv. However, under rare conditions, the BIG-IP WebAccelerator will instead insert a prefix consisting of 3 different characters. The incorrect URL causes the client to receive an HTTP 404 Not Found response when requesting the object, which prevents the page from displaying properly.

In the following example, the pv tag inserted for the image_1.gif object has the correct pv tag prefix of ;pv and the object will display correctly. However, the pv tag inserted for the image_2.gif object has an invalid pv tag prefix of xyz, and the object will not display correctly:

<html>
<body>
This is test 1.
<img src="/pictures/image_1.gif;pv12345">
<br>
This is test 2.
<img src="/pictures/image_2.gifxyz54321">
</body>
</html>

Note: For information about the IBR feature, refer to the Specifying content assembly options section of the Configuring Assembly Rules chapter in the Policy Management Guide for the BIG-IP WebAccelerator System.

F5 Product Development tracked this issue as CR116819, and it was fixed in BIG-IP 9.4.8 and 10.0.1. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

This issue has been fixed in a hotfix available for BIG-IP WebAccelerator 9.4.6 and also in a hotfix available for BIG-IP WebAccelerator 9.4.7. To request a hotfix, contact F5 Technical Support and reference this Solution and CR number.
