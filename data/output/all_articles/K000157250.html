K000157250: VS is not sending SNI on Client Hello even after enabling default-sni on profile and serverssl-use-sni enabled on VS for Cloudfare

Type
Support Solution
Published
2025-10-30
Updated
2025-11-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000157250

Description

When configuring a BIG-IP LTM virtual server to proxy HTTP connections and perform HTTP-to-HTTPS translation, you may encounter issues connecting to backend servers (such as those hosted on Cloudflare) that require the Server Name Indication (SNI) extension in the TLS Client Hello. Even with "default-sni" enabled on the server SSL profile and "serverssl-use-sni" enabled on the virtual server, SNI may not be sent as expected, resulting in connection failures or errors such as Cloudflare 525.

 

Environment

Product: BIG-IP LTM

Version: v17, v16, v15

Server SSL profile with "default-sni" enabled

Virtual server with "serverssl-use-sni" enabled

Backend servers (e.g., Cloudflare) requiring SNI in the TLS Client Hello (or other Backend servers that require SNI)

 

Cause

The server SSL profile does not automatically use the HTTP Host header as the SNI value in the Client Hello. The "default-sni" option alone is insufficient; you must explicitly set the "server-name" field in the server SSL profile or use an iRule to dynamically inject the Host header as SNI for backend connections.

 

 

Recommended Actions

For a single backend hostname, set the "server-name" field in the server SSL profile to match the required hostname.

For multiple backend hostnames:

Create separate server SSL profiles for each hostname and assign them accordingly, or

Use an iRule to extract the Host header from client requests and inject it as SNI during backend TLS handshakes.

Refer to F5 article K41600007 for guidance on injecting SNI based on HTTP Host headers using an iRule.

 

Additional Information

Cloudflare and similar providers require a valid SNI value in TLS Client Hello messages for successful connections. Without this, errors such as Cloudflare 525 can occur. Using an iRule allows dynamic handling of multiple domains without creating numerous server SSL profiles.
