K000129993: Using header information as input for rate limiting on KIC ingress resource

Type
Support Solution
Published
2022-12-14
Updated
2023-08-07
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 2.1.0
Source
https://my.f5.com/manage/s/article/K000129993

Description

If you are trying to use ingress resources to turn on and off rate-limiting depending on http headers that you send in, this solution will help you.
While customizing the ingress template to add functionality for rate-limiting we have added the following code to our configMap. 
    {{- if eq (index $.Ingress.Annotations "custom.nginx.org/rate-limiting") "on"}}
    {{- $rate := index $.Ingress.Annotations "custom.nginx.org/rate-limiting-rate"}}
    {{- $customHeader := index $.Ingress.Annotations "custom.nginx.org/rate-limiting-custom-header"}}
    {{- if and (eq (index $.Ingress.Annotations "custom.nginx.org/rate-limiting-criteria") "client-id") (or (eq (index $.Ingress.Annotations "custom.nginx.org/jwt-validation") "on") (eq (index $.Ingress.Annotations "custom.nginx.org/jwt-introspection") "on"))}}
    limit_req_zone $jwt_client_id zone={{$.Ingress.Namespace}}-{{$.Ingress.Name}}:10m rate={{if $rate}}{{$rate}}{{else}}1r/s{{end}};
    {{- else if eq (index $.Ingress.Annotations "custom.nginx.org/rate-limiting-criteria") "custom-http-header"}}
    map $http_{{if $customHeader}}{{$customHeader}}{{else}}test_header{{end}} $limit}} {
    default "";
    "~.+" $binary_remote_addr;
    }
    limit_req_zone $limit zone={{$.Ingress.Namespace}}-{{$.Ingress.Name}}:10m rate={{if $rate}}{{$rate}}{{else}}1r/s{{end}};
    {{- else}}
    limit_req_zone $binary_remote_addr zone={{$.Ingress.Namespace}}-{{$.Ingress.Name}}:10m rate={{if $rate}}{{$rate}}{{else}}1r/s{{end}};
    {{- end}}
    {{- end}}
Then we add annotations as below to our ingress resource manifest 
custom.nginx.org/rate-limiting: "on"
custom.nginx.org/rate-limiting-burst: "1"
custom.nginx.org/rate-limiting-criteria: custom-http-header
custom.nginx.org/rate-limiting-custom-header: x_custom_header
custom.nginx.org/rate-limiting-no: "3"
custom.nginx.org/rate-limiting-rate: 1r/m
Which results in the following changes in nginx.conf 
map $http_x_custom_header $limit {
default "";
"~.+" $binary_remote_addr;
}
limit_req_zone $limit zone=default-cafe-ingress:10m rate=1r/m;
But, if you create more than 1 ingress resource, this config will add more of the map declarations. One per instance of your ingress. This leads to unintended values for $limit variable in the limit_req_zone directive.
 

Environment

  • NGINX Ingress Controller
  • rate-limit
  • Custom Ingress template

Cause

NGINX rules run all of the map statements first in order, then run the limit_req_zone statements once done. 
 

 Recommended Actions

Replace the $limit with a variable that you send in with a header 
    {{- if eq (index $.Ingress.Annotations "custom.nginx.org/rate-limiting") "on"}}
    {{- $rate := index $.Ingress.Annotations "custom.nginx.org/rate-limiting-rate"}}
    {{- $customHeader := index $.Ingress.Annotations "custom.nginx.org/rate-limiting-custom-header"}}
    {{- if and (eq (index $.Ingress.Annotations "custom.nginx.org/rate-limiting-criteria") "client-id") (or (eq (index $.Ingress.Annotations "custom.nginx.org/jwt-validation") "on") (eq (index $.Ingress.Annotations "custom.nginx.org/jwt-introspection") "on"))}}
        limit_req_zone $jwt_client_id zone={{$.Ingress.Namespace}}-{{$.Ingress.Name}}:10m rate={{if $rate}}{{$rate}}{{else}}1r/s{{end}};
    {{- else if eq (index $.Ingress.Annotations "custom.nginx.org/rate-limiting-criteria") "custom-http-header"}}
    {{- $customLimitName := index $.Ingress.Annotations "custom.nginx.org/limit-name"}}
    map $http_{{if $customHeader}}{{$customHeader}}{{else}}test_header{{end}} ${{$customLimitName}} {
    default "";
    "~.+" $binary_remote_addr;
    }
    limit_req_zone ${{$customLimitName}} zone={{$.Ingress.Namespace}}-{{$.Ingress.Name}}:10m rate={{if $rate}}{{$rate}}{{else}}1r/s{{end}};
    {{- else}}
    limit_req_zone $binary_remote_addr zone={{$.Ingress.Namespace}}-{{$.Ingress.Name}}:10m rate={{if $rate}}{{$rate}}{{else}}1r/s{{end}};
    {{- end}}
    {{- end}}
Change the ingress yaml to include the new header, this cannot contain '_' or '-' 
  annotations:
    custom.nginx.org/rate-limiting: "on"
    custom.nginx.org/rate-limiting-burst: "1"
    custom.nginx.org/rate-limiting-criteria: custom-http-header
    custom.nginx.org/rate-limiting-custom-header: x_custom_header
    custom.nginx.org/rate-limiting-rate: 1r/m
    custom.nginx.org/limit-name: "one"
