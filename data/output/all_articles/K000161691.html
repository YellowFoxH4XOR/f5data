Description

On a BIG-IP VE  instance running in a virtualized environment, no traffic inbound/outbound is observed in tcpdump caused connectivity issues through specific interfaces.

Environment

  • BIG-IP LTM Virtual Edition
  • SR-IOV NIC: Intel XXV710 25GbE (i40e driver, version 2.26.8)
  • BIG-IP VE 'ixlv' driver
  • Kubernetes/Robin.io

Cause

An Unknown internal communication failure during BIG-IP VE instance spinning causing the sys db variable 'tmm.threadsactual' to be set to 0 instead of the actual TMM thread value (e.g., 16). This abnormal value indicates TMM threads did not initialize correctly, preventing TMM from processing incoming traffic and causing traffic to fail through specific interfaces.

Answer/Recommended Actions

  1. Log in to the affected BIG-IP VE instance.
  2. Run:
    tmsh list sys db tmm.threadsactual
  3. If the value is 0, the instance has experienced the abnormal startup condition.
  4. Reboot or redeploy the affected BIG-IP VE instance.
  5. After reboot, verify tmm.threadsactual is set to the expected value (e.g., 16) which should be equivalent to the actual tmm threads running in the VE which can be confirmed with "ps aux | grep tmm"
  6. Confirm tcpdump now shows the packet going out or coming in through all interfaces.

Additional Information

  • The sys db tmm.threadsactual value is calculated at runtime and populated during service startup. A value of 0 on a running device is abnormal and indicates a startup-time internal communication failure.
  • Interface-level counters may increment even when TMM is not processing traffic, as these reflect NIC-level reception.
  • This issue may affect only a single instance due to a runtime initialization problem, not configuration or hardware.
