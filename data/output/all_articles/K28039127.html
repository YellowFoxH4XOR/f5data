Description

When you are creating objects in a partition other than /Common you may receive an error message saying " can only be created in /Common".

  • The configuration object will fail to be created and an error message will appear. This error message and its slight variants will appear in various places.
  • The error message will be similar to, and as an example SNMP configuration will be used, to this in the GUI:
Exception caught in Management::urn:iControl:Management/SNMPConfiguration::set_readonly_community()
Exception: Common::OperationFailed
primary_error_code : 17242074 (0x010717DA)
secondary_error_code : 0
error_string : 010717da:3: Object (/partition>/<object> of type: community) can only be created in /Common.
  • In /var/log/ltm it may appear as:
Feb 18 07:47:23 <HOSTNAME> err mcpd[4435]: 010717da:3: Object (/<partition>/<object> of type: community) can only be created in /Common.
  • In /var/log/webui.log it may appear as:
error_string : 010717da:3: Object (/<partition>/<object> of type: community) can only be created in /Common.
Environment

Relevant environmental factors specific to the topic

  • The use of multiple partitions is in place.
  • The object to be created is a community object.

Cause

Some configuration objects are community objects. This means they are used system wide in the the BIG-IP. When this is the case, and an attempt is made to create something outside of /Common, it will not be allowed. This is by design and most often due to how the object itself works.

For example SNMP traps are community objects. A SNMP trap is triggered via an Object ID (OID). These entries work in a more generic form mostly from system log entries.

Recommended Actions

  1. Create the object in /Common
