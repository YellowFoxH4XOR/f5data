K000162983: Preventing syslog-ng Memory Growth on BIG-IP LTM

Type
Support Solution
Published
2026-08-19
Updated
2026-08-19
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162983

Description

BIG-IP LTM can experience severe physical-memory depletion when syslog-ng processes excessive locally generated log messages. Symptoms include rapid syslog-ng resident-memory growth, low free memory, and REST-service errors such as:

PubSubModule failed to publish request

connect ECONNREFUSED ...:8100

org.apache.thrift.transport.TTransportException:

java.net.ConnectException: Connection refused

Environment

  • Product: BIG-IP LTM
  • Local logging is processed by syslog-ng.
  • High-volume messages can originate from APM, LTM, ASM, or other BIG-IP subsystems.
  • restjavad may also consume excessive memory because of an API statistics memory leak.

Cause

Excessive local log generation places sustained memory pressure on syslog-ng. The resulting system load can affect restjavad and restnoded, causing REST communication failures.

The restjavad API statistics memory leak associated with ID 1826505 can further increase memory consumption, particularly on systems that operate in high-availability configurations.

Recommended Actions

  1. Investigate the sources of the increased log volume. Review APM, LTM, ASM, and other subsystem messages for configuration or traffic conditions that generate repeated errors.
  2. Move high-volume logging to an off-box High-Speed Logging (HSL) destination to reduce the memory burden of local syslog-ng processing.
  3. Clear the restjavad API statistics memory leak by following Procedure A in the related KB:
    bigstart stop restjavad
    truncate -s 0 /var/log/restjavad-api-usage.json
    ls -l /var/log/restjavad-api-usage.json
    bigstart start restjavad
    If iAppsLX or Guided Configuration is in use, restart restnoded approximately 15 seconds after restarting restjavad.
  4. Save the configuration:
    tmsh save sys config
  5. Monitor the following:
    • Free physical memory
    • syslog-ng resident memory
    • restjavad memory usage
    • restnoded and restjavad connection errors
    • Log volume and message frequency

Important: Perform configuration changes and service restarts during a maintenance window. Provisioning changes and restarts can disrupt services and may trigger an HA failover if performed while the system is active.

Additional Information

  • Repeated log messages should be investigated at their source instead of being suppressed without determining why they occur.
  • Common contributing messages can include:
    • APM LDAP errors caused by invalid encrypted credentials.
    • LTM TCL errors caused by references to nonexistent pools.
    • ASM incidents involving malicious or disallowed sources.
    • Memory-allocation failures in security enforcement processing.
  • Increasing restjavad provisioning is a stopgap measure and does not replace moving high-volume logging off-box.
  • A fix is available for the restjavad API statistics memory leak.
