K000161830: AFM Firewall Rule Requirements for BIG-IP Listeners (Self IPs and Virtual Servers)

Type
Support Solution
Published
2026-06-22
Updated
2026-06-22
Source
https://my.f5.com/manage/s/article/K000161830

Topic

You should consider using this procedure under one of the following conditions:

  • You have provisioned AFM and traffic to a Virtual Server is rejected or dropped.
  • You have provisioned AFM and traffic to a selfIP (BGP, OSPF, IGMP,...) is dropped even when it is specifically allowed by 'allow-service' configuration option in the self IP.

Description

When AFM is provisioned then the firewall engine starts to control the access to the configured listeners in the device, this includes SefIPs and Virtual Servers. Depending on the configuration we could find that traffic is not allowed to listeners when we expected to be allowed.

Environment

  • BIG-IP with AFM provisioned.
  • Firewall policy allowing the specific traffic applied to route domain or/and global contexts.
  • Self IP 'allow-service' configuration set to 'All' or 'Default'.
  • sys db tm.fw.defaultaction set to 'Drop' or 'Reject'
  • No explicit AFM firewall policy applied to the affected Self IP or Virtual Server.

Cause

This will happen if DB key tm.fw.defaultaction is configured to 'Drop' or 'Reject'. This DB key controls the default action of the firewall at listener contexts and it is commonly configured as a clean-up rule to disallow all traffic that it is not allowed explicitly by a previous firewall rule.

This configuration has precedence over LTM configuration objects. This means that even if we have a Virtual Server listening for specific traffic service, unless we have a firewall rule explicitly allowing this traffic then it will not be allowed. The same happens for Self IPs configuration, regardless if we have a protocol allowed through 'allow-service' option if we don't have a firewall allowing it then it will not be allowed, what it applies to dynamic routing protocols for example.

Recommended Actions

In case of a Virtual Server listener, create a firewall policy allowing the service traffic and attach it to the virtual server.

In case of a SelfIP, create a specific firewall policy allowing this traffic and attach it to the selfIP, or create and attach a firewall policy using the built-in _sys_self_allow_defaults rule list to the selfIP requiring this type of traffic:
