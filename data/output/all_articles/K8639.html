K8639: Data Guard does not match some Korean credit card numbers

Updated

Applies to

  • BIG-IP ASM: 9.4.4, 9.4.3, 9.4.2
Source

Topic

The BIG-IP ASM Data Guard feature allows you to configure response scrubbing for sensitive user information, such as credit card numbers or social security numbers. When Data Guard accumulates a response for the purpose of data scrubbing, the system applies certain criteria to determine whether a credit card number exists in the response.

Note: For more information about the Data Guard credit card matching algorithm, refer to K8638: Data Guard credit card matching.

Once the Data Guard locates a pattern matching a credit card number, the BIG-IP ASM will apply the Luhn algorithm (MOD 10) to the number. If the number is a valid Luhn number, and the length and prefix matches a valid credit card number, the data is blocked or scrubbed by the Data Guard.

Korean credit cards starting with the following groups of digits are not verified by the Luhn algorithm, and will not be scrubbed by the Data Guard feature:

  • 9410
  • 9435
  • 9439
  • 9436
  • 9415
  • 9460
  • 9420
  • 9430

To determine whether Korean credit card numbers starting with the above group of digits are not being scrubbed by the Data Guard feature, you can trigger an information leakage violation when the BIG-IP ASM locates the numbers in a server response. To do so, perform the following procedure:
  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click the relevant security policy.
  4. From the Advanced menu, select Data Guard .
  5. In the Data Guard box, click Enable Custom Patterns.
  6. Add the following string to the New Pattern box:

    (?:9410|9435|9439|9436|9415|9460|9420|9430)(?:(?:-|\.|=|\\|/|\s)?[0-9]{4}){3}
  7. Click Add.
  8. Click Save.
  9. Click Apply Policy.
