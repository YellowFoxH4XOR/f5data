Description

  • You note the BIG-IP ASM log frequently logs 'event code P265 / P302' message in /var/log/asm

 emerg perl[26116]: 01310003:0: ASM out of memory error: event code P265 / P302

  • You also note a related message ' total_umu_max_size reaches configured total_umu_max_size limit, in  asm and bd file

IO_PLUGIN|ERR |Apr 26 06:02:31.495|26328|plugin_common.c:0266|trans_open: Not enough UMU memory to start a new trans.
IO_PLUGIN|ERR |Apr 26 06:04:50.680|26328|plugin_common.c:0266|trans_open: Not enough UMU memory to start a new trans.

Environment

  • ASM
  • BIG-IP

Cause

  • total_umu_max_size memory allocation has been reached

Recommended Actions

  • The ASM out of memory error: event code P265 / P302 corresponds to this memory exhaustion
  • Increase memory allocation for variable total_umu_max_size

    Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. While the asm process restarts, it interrupts traffic. Additionally, when the BIG-IP ASM system is in a device group, it fails over to the next available member.

    • Log in to the Configuration utility.
    • Navigate to Security > Options > Application Security > Advanced Configuration > System Variables.
    • filter  and click the variable  total_umu_max_size 
    • change Parameter Value for the value you wish to change in KBytes and Update

Additional Information

  • You should also check if response features are enabled on configured policies,; any response feature enabled can consume lots of UMU memory and The BIG-IP may record the below warring message .

warning perl[14348]: 01310014:4: ASM filtered HTML exceeded limit: event code C190 Filtered Response HTML exceeded max limit
