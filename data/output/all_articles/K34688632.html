Known Issue

Route pool members that are not directly connected to the BIG-IP system may cause the Traffic Management Microkernel (TMM) to exit and produce a core file.

This issue occurs when all of the following conditions are met:

  • Route pools have been configured to use pool members that are not directly connected to the BIG-IP system.
  • The BIG-IP system includes a configuration that causes TMM to initiate traffic, rather than proxy traffic. An example of this behavior is an sFLOW configuration.

    Note: This issue does not occur in configurations where the BIG-IP system is only used to proxy traffic.

Impact

The BIG-IP system temporarily fails to process traffic while the TMM process restarts. If the BIG-IP system is configured for high availability (HA), it fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily stops processing traffic when configured to fail over to a peer device.
  • The BIG-IP system generates a TMM core file in the /shared/core/ directory.
  • The BIG-IP system logs a message to the /var/log/LTM file that appears similar to the following example:

    notice sod[]: 01140045:5: HA reports tmm NOT ready.

Status

Workaround

There is no workaround for this issue. However, you can mitigate this issue by configuring route pool members that are directly connected to the BIG-IP system.
