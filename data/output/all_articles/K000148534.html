Description

  • OAuth and OpenID scope request modification to remove offline_access from introspection

Environment

  • APM
  • OAuth
  • OpenID

Cause

  • OpenID adds the scope of offline_access to the request so the application can communicate with authorization server regardless of activity on the application or not by the user

Recommended Actions

  • Custom session variable containing list of desired scopes and then two custom OAuth requests in which standard scope parameter replaced by custom scope parameter referencing that variable...

Example syntax:

apm aaa oauth-request /Common/CustomOktaAuthRedirectRequest {
method get
parameters {
client_id {
type client-id
}
redirect_uri {
type redirect-uri
}
response_type {
type response-type
}
scope {
value "%{session.custom.scopeList}"
}
}
type auth-redirect-request
}
apm aaa oauth-request /Common/CustomOktaTokenRequestByAuthzCode {
parameters {
client_id {
type client-id
}
client_secret {
type client-secret
}
grant_type {
type grant-type
}
redirect_uri {
type redirect-uri
}
scope {
value "%{session.custom.scopeList}"
}
}
type token-request
}

The session variable assigned the desired scope list
apm policy agent variable-assign /Common/test_act_variable_assign_ag {
variables {
{
expression "return {openid scope1 scope2}"
varname session.custom.scopeList
}
}
}

OAuth Scope policy item using the two custom OAuth requests described above

apm policy agent aaa-oauth /Common/test_act_oauth_client_ag {
auth-redirect-request /Common/CustomOktaAuthRedirectRequest
openid-connect enabled
token-request /Common/CustomOktaTokenRequestByAuthzCode
}
