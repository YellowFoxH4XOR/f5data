Description

With vlan failsafe configured, it is possible that when the link(s) supporting a vlan go down, then failsafe is triggered early by up to half of the configured timeout interval. eg: with a 20s failsafe timeout, the interval between link down and vlan_fs trigger could be 10 seconds.

With reference to article K13297. With default failsafe configuration the timeout is 90s, each tmm will monitor the vlan for the presence of either arp or icmpv6 traffic. If at 50% of the timeout (ie: 45s), one tmm has not seen any arp or icmpv6 packets it will send probes to test for the liveliness of the vlan. If the failing interface goes down before a response can be gathered, then the vlan fs mechanism will wait another 45s (to complete the 90s) and then trigger the failsafe action. This means that it is possible to see failsafe being triggered before the timeout interval. With the 1s timestamp granularity in /var/log/ltm it might be even 1s less than that. eg: with default values, timeout occurred within 45s  

Mar 29 09:35:06 LTM1.local info bcm56xxd[8198]: 012c0015:6: Link: 1/1.1 is DOWN

Mar 29 09:35:51 LTM1.local warning sod[6170]: 01140029:4: HA vlan_fs /Common/test-vlan fails action is failover.

Environment

  •  Vlan-group with failsafe configured

Cause

Interface going down (or similar) to trigger failsafe

Recommended Actions

This is working as designed, be aware that failsafe is monitored per tmm.

However, if you wish to check for suitable traffic that will reset the failsafe timeout timer, this can be done with

  tcpdump -ni <vlan>:nnn -s0 -w <file> arp or icmp6

Additional Information

If you want to reset the timer on any frame (not just arp or icmpv6) then set sys db failover.vlanfailsafe.resettimeronanyframe to true (default false).
