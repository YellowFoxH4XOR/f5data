Description

  • Global SNAT connections do not reset upon timeout
  • Client and server unnecessarily keep the connection open.

Environment

  • LTM
  • Global SNAT

Cause

Seen behavior is caused by a known issue tracked with the Bug ID 756647

Recommended Actions

Upgrade to a software version not affected by Bug ID 756647. As workaround you can use a forwarding virtual server with a SNAT pool instead of a global SNAT.

  1. Connect to GUI
  2. Go to Local Traffic  >  Address Translation > SNAT Pool List
  3. Click Create
  4. Assign a name and add IP addresses to the Member list
  5. Click Finished
  6. Assign newly created SNAT pool to forwarding VS. See K7595
