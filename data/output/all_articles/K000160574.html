Description

When switching SSL client profiles on BIG-IP LTM virtual servers to use certificates stored on an external Hardware Security Module (HSM), the main website and related services become unreachable. Users experience browser errors such as "ERR_CONNECTION_CLOSED".

BIG-IP System logs (/var/log/ltm) show errors indicating SSL profiles cannot load the required key, certificate, or chain files, resulting in messages like "invalid profile unknown" and failed SSL handshakes. Example log entries include: 

Profile /Common/hsm.example.com - cannot load key/cert/chain: ... Not found.
Connection error: hud_ssl_handler:1315: alert(40) invalid profile unknown on VIP ...

Environment

  • Product: BIG-IP LTM
  • External HSM integration enabled (pkcs11_nethsm feature active)
  • One or Multiple virtual servers with client SSL profiles referencing HSM-stored certificates
  • Migration / Integration to Physical/Cloud HSM for SSL profiles

Cause

The cause of this behavior could be related to Bug ID 748529 where after initial integration of a physical or cloud HSM, the Traffic Management Microkernel (TMM) process must be restarted to properly load HSM-stored certificates and keys. Without this restart, SSL profiles referencing HSM certificates may fail, causing the website to become unreachable. 

Answer/Recommended Actions

 After integrating the External HSM and attaching HSM-backed SSL profiles, restart all TMM processes on the BIG-IP LTM to ensure proper loading of certificates and keys from the HSM. In this regard, you can run the below command:

# bigstart restart tmm

Important: Restarting TMM services leads to service disruption and unexpected failover. So, perform this activity under a planned Maintenance Window.

If the issue persists after restarting TMM:

    • Verify certificate, key, and chain file paths as described in F5 Knowledge Article K000135775.
    • Ensure all referenced files are accessible and correctly configured in the SSL profiles.

Additional Information

  • Restarting only the "pkcs11d" or "httpd" services is not sufficient; a full TMM restart is necessary.
  • This behavior is expected after first-time HSM integration and should be resolved by restarting TMM.
