Description

For prerequisites, considerations, videos, alternative scenarios and methods, detailed instructions, etc, refer to the aforementioned articles. Finding the serial number of your BIG-IP system

Command line

  1. Log into the BIG-IP system
  2. Enter the following command:
    tmsh show sys hardware

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Device.
  3. Select General.
  4. Under Properties and Operations, locate the Chassis Serial Number.

For more information, refer to K3782: Finding the serial number or registration key of your BIG-IP system.

Backing up and restoring BIG-IP configuration files with a UCS archive

Backing up the configuration from the command line

  1. Log into the BIG-IP command line
  2. Enter the following command:
    tmsh save sys ucs $(echo $HOSTNAME | cut -d'.' -f1)-$(date +%H%M-%m%d%y)
  3. Locate the UCS file in the /var/local/ucs directory.
  4. Copy the UCS file to another system.

Backing up the configuration from the configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > Archives.
  3. To initiate the process of creating a new UCS archive, select Create.
  4. In the File Name box, enter a name for the file.
    Important: You must use a unique file name. If a file with the same name already exists, the system does not create the UCS archive file and displays a warning message that appears similar to the following example: The file already exists on the system.
  5. Optional: If you want to exclude SSL private keys from the UCS archive, for Private Keys, select Exclude. For example, exclude the private keys if you are sending the UCS to F5 Support.
  6. To create the UCS archive file, select Finished.
    When the system completes the backup process, examine the status page for any reported errors before proceeding to the next step.
  7. To return to the Archive List page, select OK.
  8. Copy the UCS file to another system.

Restoring the configuration from the command line

Impact of procedure: The BIG-IP system replaces any existing configuration with the UCS archive file configuration. Specific system services restart, and the device may temporarily lose network failover connectivity if it is a member of a device group. F5 recommends that you perform this procedure during a maintenance window and when the system is a member of a device group when it is in the standby state.

  1. Log into the BIG-IP command line.
  2. Restore the UCS archive file by using the following syntax:
    tmsh load sys ucs <path/to/UCS>
    If you do not specify the path, the BIG-IP system performs as if the UCS archive file is located in the default /var/local/ucs directory.

If restoring a UCS on a replacement RMA unit, follow these steps

  1. Activate the license on the device according to the steps detailed in K7752: Licensing the BIG-IP system
  2. Manually copy the UCS archive file to the target system.
  3. Use the following syntax:
    tmsh load /sys ucs <path/to/UCS> no-license
    If you do not specify the path, the BIG-IP system performs as if the UCS archive file is located in the default /var/local/ucs directory.

Restore the configuration from the Configuration utility

Impact of procedure: The BIG-IP system replaces any existing configuration with the UCS archive file configuration. Specific system services restart, and the device may temporarily lose network failover connectivity if it is a member of a device group. F5 recommends that you perform this procedure during a maintenance window and when the system is a member of a device group when it is in the standby state.

  1. Log in to the Configuration utility.
  2. Go to System > Archives.
  3. Select the link of the UCS archive you want to restore.
  4. To initiate the UCS archive restore process, select Restore.
  5. When the system completes the restore process, examine the status page for any reported errors before proceeding to the next step.
  6. To return to the Archive List page, select OK.
  7. If necessary, reactivate the license according to the steps detailed in K7752: Licensing the BIG-IP system

For more information, considerations, and details about different back up and restore scenarios refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

Generating diagnostic data using the qkview utility

Running the qkview utility from the command line

Impact of procedure: The qkview utility runs a large number of commands when collecting information. This behavior may cause an additional performance burden on systems that are already under heavy load.

  1. Log in to the command line
  2. To run the qkview utility, enter the following command:
    qkview
    The output file name displays after the command has completed.
  3. Collect the output file from the /var/tmp/ directory by copying the file to an external host using a utility such as ftp or scp.

Running the qkview utility from the Configuration utility

Impact of procedure: The qkview utility runs a large number of commands when collecting information. This behavior may cause an additional performance burden on systems that are already under heavy load.

  1. Log in to the Configuration utility.
  2. Go to System > Support.
  3. Select New Support Snapshot.
  4. For Health Utility, select Generate QKView.
  5. Select Start.
  6. To download the output file, select Download.

For more information, refer to K12878: Generating diagnostic data using the qkview utility.

Producing a TMM diagnostic core file

Impact of procedure: The BIG-IP system will temporarily fail to process traffic as it recovers from TMM restarting, and devices configured as a high availability (HA) pair may fail over. Additionally, on platforms with a large memory capacity, the system will respond slowly while it writes several gigabytes of data to the disk and compresses the core file. This process may take several minutes to complete. When the core file compression is complete, the unit returns to normal operation and restarts the TMMs.

  1. Disable the watchdog process per K13539: Disabling the watchdog process to perform a core dump (11.x - 15.x)
  2. Log in to the BIG-IP command line.
  3. To determine which TMM processes are running on the system, enter the following command:
    ps ax | grep -i tmm
    Note: Most BIG-IP platforms are enabled with Clustered Multiprocessing (CMP) and run multiple TMM instances.
  4. Use the killall command to signal the TMM process to produce a diagnostic core file for each instance. To do so, use the following command syntax:
    killall -v -s 6 <tmm.#> <tmm.#> ...
    Replace the <tmm.#> placeholders with the TMM instances from step 3. For example, to signal both tmm.0 and tmm.6 to produce diagnostic core files in the /shared/core directory, enter the following command:
    killall -v -s 6 tmm.0 tmm.6
    When you produce a diagnostic core file on a chassis-based system, you may want to simultaneously produce core files on all blades using the clsh command:
    clsh killall -v -s 6 $(pgrep -l 'tmm\.[0-9]' | awk '{print $2}')
  5. Check for the diagnostic core files in the /shared/core directory. The file names appear similar to the following examples: 
    tmm.0.bld0.0.606.core.gz
    tmm.6.bld0.0.606.core.gz
    Note: It may take several minutes for the system to complete writing the core files to disk.
  6. Once the diagnostic core file creation has completed, re-enable the watchdog process per K13539: Disabling the watchdog process to perform a core dump (11.x - 15.x)

For more information about generating core files for other BIG-IP daemons, refer to K13002225: Producing diagnostic core files to F5 Support.
