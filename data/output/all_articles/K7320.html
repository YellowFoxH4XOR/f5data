K7320: The BIG-IP LTM aborts the connection when it receives HTTP chunk headers with the Carriage Return/Linefeed (CR/LF) split across multiple packets

Known Issue

This is the result of a known issue. The BIG-IP LTM system aborts connections containing HTTP chunk headers where the Carriage Return/Linefeed (CR/LF) is split across multiple packets. In the following example, the client sends chunked data with the CR/LF split across frames 67 and 68, and the BIG-IP LTM system replies with a TCP reset to close the connection:

Frame 67 from the client contains the trailing '\r' (carriage return) character at the end of the chunked payload:\r\n0fe8\rFrame 68 from the client contains the '\n' (newline) character:\nFrame 70, from the LTM Resets the server-side connection

F5 Networks Product Development is tracking this issue as CR74928, and it was fixed in BIG-IP LTM version 9.3 and 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To work around this issue, configure an iRule that disables chunking for the virtual server. To do so, perform the following procedure:

Note: The following iRule forces HTTP connections to use HTTP/1.0 on the server side in order to disable chunking. This configuration can have a performance impact for connections to the virtual server.

  1. Log in to the Configuration utility.
  2. Click Local Traffic, then click iRules.
  3. Click Create.
  4. Type a name for the iRule.
  5. Enter the following iRule text in the Definition box: 
    when HTTP_REQUEST {   if { [HTTP::version] eq "1.1" } {     if { [HTTP::header is_keepalive] } {         HTTP::header replace "Connection" "Keep-Alive"     }     HTTP::version "1.0"   } }
  6. Click Finished.

You must now associate the iRule with the virtual server.
