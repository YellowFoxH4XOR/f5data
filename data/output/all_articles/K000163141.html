Security Advisory Description

NLnet Labs Unbound up to and including version 1.25.0 has a denial of service vulnerability in the DNSSEC validator that can lead to a crash given malicious upstream replies. When Unbound constructs chase-reply messages for validation, the code uses the wrong counter to calculate write offsets for ADDITIONAL section rrsets. DNAME duplication could increase the ANSWER section count and authority filtering could decrease the AUTHORITY section count and create an uninitialized array slot. Combining these two, the validator later dereferences this uninitialized pointer, causing an immediate process crash. An adversary controlling a DNSSEC-signed domain can trigger this bug with a single query by configuring a DNAME chain with unsigned CNAMEs and a response containing unsigned AUTHORITY records alongside signed ADDITIONAL glue records. Unbound 1.25.1 contains a patch with a fix to use the proper counters to calculate the write offsets. (CVE-2026-42959)

Impact

This vulnerability allows an attacker, who has control of a DNSSEC-signed zone configured with a DNAME chain with unsigned CNAMEs on an upstream DNSSEC server, to construct a response that contains unsigned AUTHORITY records alongside signed ADDITIONAL glue records. As a result, a BIG-IP DNS system configured to send DNS queries to the compromised upstream DNSSEC server may experience a denial-of-service (DoS).

Mitigation

BIG-IP Next

To mitigate this vulnerability, you can implement one or more of the following as appropriate for your environment:

  • Restrict upstream DNS servers: Configure BIG-IP Next DNS cache resolvers to forward only to trusted, controlled upstream DNS servers (not open recursion to the Internet). This configuration reduces the likelihood of encountering attacker-controlled DNSSEC-signed domains.
  • Use network-level filtering: Limit which upstream DNS servers BIG-IP Next can communicate with through network policies and firewall rules.
  • Limit DNS features: Disable DNSSEC validation on BIG-IP Next DNS cache resolvers if operationally feasible; this prevents the vulnerable validator code path from being exercised. However, this mitigation reduces DNS security posture.
  • Monitor for Traffic Management Microkernel (TMM) interruptions: Set up alerting on TMM restart events to detect active exploitation attempts.

BIG-IP

To mitigate this vulnerability, you should ensure that your BIG-IP device is configured to send DNS queries only to trusted upstream DNSSEC servers. Alternatively, you can configure the BIG-IP DNS system to use BIND by setting Use BIND Server on BIG-IP to Enabled in the affected DNS profile. However, you must ensure your BIG-IP DNS device is running BIG-IP DNS 21.1.0, 17.5.1.7, or 17.1.3.3 to avoid the BIND vulnerability described in K000162286: BIND vulnerability CVE-2026-1519.
