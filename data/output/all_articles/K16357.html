Known Issue

Traffic Management Microkernel (TMM) may exit and restart when the Security Assertion Markup Language (SAML) Single Logout (SLO) response is received on the SLO request URL.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured as an SAML Identity Provider (IdP).
  • The external SAML Service Provider (SP) connector is configured with SLO request and response URLs.
  • The external SP responds to the SLO request from the BIG-IP APM system by sending the response to the URL configured in the Single Logout Request URL connector setting.

For example, the SLO request URL in the following IdP connector configuration is https://sso.example.com/saml/idp/slo:

apm aaa saml-idp-connector /Common/example_IdP {
entity-id https://sso.example.com/idp/internal
idp-certificate /Common/saml_idp_cert.crt
single-logout-response-uri https://sso.example.com/saml/idp/slr
single-logout-uri https://sso.example.com/saml/idp/slo
sso-uri https://sso.example.com/saml/idp/sso
want-authn-request-signed true
}

The BIG-IP APM system is set up to receive responses to SLO requests on the URL configured in the Single Logout Response URL setting for the external SP connector. If the BIG-IP APM system receives the response to a SLO request on this URL, the TMM process may exit and generate a core file.

Impact

The BIG-IP APM system is unable to process traffic while the TMM process restarts, and the system fails over if it is configured for high-availability.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to access the BIG-IP APM system or experience a traffic disruption.
  • The TMM process generates a core file to the /shared/core directory.
  • The system generates a SIGSEGV fault to the /var/log/tmm file, similar to the following example:

    notice ** SIGSEGV **
    <snip>
    notice RIP=0x2b4882fdcdc7

Workaround

To work around this issue, you should reconfigure the external SAML SP to send SLO responses to the URL configured in the SLO response URL setting in the BIG-IP APM system.
