K000134762: chmand in a restart loop after upgrade or after reloading the configuration

Type
Support Solution
Published
2023-05-24
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP LTM: 12.1.2
Source
https://my.f5.com/manage/s/article/K000134762

Description

Chmand might be restarting in a loop in the CLI after an upgrade or configuration reload. When chmand runs into this state, other processes are forced to restart as well which results in an inoperative state of the device. /var/log/ltm shows similar lines:


err chmand[13959]: 012a0003:3: Bad tmm count (0).

err chmand[13959]: 012a0003:3: unexpected init failure : std::exception

crit chmand[13959]: 012a0002:2: critical platform initialize failure. exiting...


Environment

  • chmand restarting
  • software upgrade or configuration reload

Cause

Corruption of /config/BigDB.dat.

 Recommended Actions

(a) Make /config/BigDB.dat writable:


# chmod u+w /config/BigDB.dat

 

(b) Edit /config/BigDB.dat and delete any corrupted lines (marked with an arrow below) then save the file:

 

[TM.TcpMemoryPressure.Hiwater]

default=90

type=unsigned_integer

min=86

max=95

realm=common

scf_config=false

display_name=TM.TcpMemoryPressure.Hiwater

[TM.TcpMemor=86 <------ !!

max=95 <------ !!

realm=common <------ !!

scf_config=false <------ !!

display_name=TM.TcpMemoryPressure.Hiwater <------ !!

[TM.TcpMemoryPressure.Lowater]

default=80

type=unsigned_integer

min=75

max=85

realm=common

scf_config=false

display_name=TM.TcpMemoryPressure.Lowater

 

(c) Save config:


# tmsh save sys config

 

(d) At this stage, file /config/BigDB.dat should be OK. Edit again and check if lines deleted on point (b) are still deleted or not. They should be deleted, but this step is simply to confirm. If for some reason not deleted, then repeat all steps. Only proceed to the step below once it is confirmed the lines from point (b) are deleted properly.

 

(e) If you noticed this issue after an upgrade, delete any boot locations which were failing before. These are corrupted and should not be re-used. Install desired ISO onto a new boot location.


(f) If you are unable to find the corrupted lines in /config/BigDB.dat and chmand is restarting with similar logs in /var/log/ltm, please contact F5 Support.


Additional Information
