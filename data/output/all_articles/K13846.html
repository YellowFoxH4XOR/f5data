Topic

You should consider using this procedure under the following condition:

  • Always-On Management (AOM) displays a CFE> prompt on the serial console.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have a serial console connection.

Description

When the AOM lights out management system fails to boot, or is interrupted at boot time, you may be presented with a CFE> prompt on the serial console. Failure of the AOM to boot does not stop the BIG-IP system from operating, as the AOM and the BIG-IP system are two separate devices that run independently of one another.

Note: Type the passthru command at the CFE> prompt at any time to access the BIG-IP system, even if the AOM is not fully booted.

Procedures

To attempt to recover the AOM so it boots, complete the following procedures in the order provided:

  • Manually starting the AOM boot process
  • Booting AOM backup kernel 1
  • Booting AOM backup kernel 2
  • Re-flashing the AOM kernel
  • Performing a clean install of the BIG-IP system

Manually starting the AOM boot process

If the AOM boot process was interrupted, you can manually start the boot process.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. At the CFE> prompt, type the following command:

    STARTUP

  2. If the AOM boots properly, you can disregard the remaining procedures.
  3. If the AOM fails to boot, please proceed to the Booting AOM backup kernel 1 procedure.

Booting AOM backup kernel 1

If the AOM does not boot after manually starting the boot process, attempt to boot from the first backup kernel.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. At the CFE> prompt, press the F1 key.
  2. If the AOM boots to the first backup kernel, proceed to the Re-flashing the AOM kernel procedure.
  3. If the AOM fails to boot, proceed to the Booting AOM backup kernel 2 procedure.

Booting AOM backup kernel 2

If the AOM does not boot after booting from the first backup kernel, attempt to boot from the second backup kernel.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. At the CFE> prompt, press the F2 key.
  2. If the AOM boots to the second backup kernel, proceed to the Re-flashing the AOM kernel procedure.
  3. If booting this backup kernel does not work, please proceed to the Performing a clean install of the BIG-IP system procedure.

Re-flashing the AOM kernel

Once you have booted into a working backup kernel, you must re-flash the AOM.

Impact of procedure: This procedure reboots only the AOM; it does not reboot the BIG-IP system.

  1. At the CFE> prompt, type the following command to connect to the BIG-IP system.

    passthru

  2. Log in to the BIG-IP system as root.
  3. To change directories to the /opt/F5/aom directory, type the following command:

    cd /opt/F5/aom

  4. To re-flash the AOM kernel, type the following command:

    ./aom_flash -kernel -force f5aom-kernel.bin

  5. The output of the command appears similar to the following example:

    Flashing AOM kernel image - DO NOT POWER OFF
    Unlocking linux ...
    Writing from /tmp/f5aom-kernel.bin to linux ... [w]
    aom_flash: succeed to flash firmware!
    1+0 records in
    1+0 records out
    MTD MD5SUM check succeeded.
    Resetting the AOM...
    The system is going down NOW!] aom #
    Sending SIGTERM to all processes
    Sending SIGKILL to all processes
    Requesting system reboot

  6. If the AOM fails to boot after the re-flash, please proceed to the Performing a clean install of the BIG-IP system procedure.

Performing a clean install of the BIG-IP system

If the AOM fails to boot from a backup kernel, or the re-flash fails, re-image the BIG-IP system with a clean installation.

Impact of procedure: The BIG-IP system goes offline during the re-imaging process.

  1. Refer to the articles in the Supplemental Information section for resources on how to perform a clean install on your version of the BIG-IP system.
  2. If re-imaging the system does not result in a functional AOM, please contact F5 technical support.
