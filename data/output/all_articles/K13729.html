Known Issue

The BIG-IP system may fail to advertise routes for virtual servers that are configured with a connection limit.

This issue occurs when the following conditions are met:

  • The Route Advertisement setting is enabled for the virtual address object
  • The Connection Limit setting is configured for the virtual server
  • The number of concurrent connections to the virtual server has reached the connection limit

When the virtual server reaches its connection limit, the BIG-IP system changes the virtual server status to Unavailable (yellow). This issue occurs because the tmrouted process currently only advertises routes for virtual servers that have the status of Available (green), or Unknown (blue), not Unavailable.

Note: The BIG-IP system will begin re-advertising the dropped route after the number of concurrent connections to the virtual server drops below the connection limit.

Impact

Existing connections to the virtual server that depend on the route may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system fails to properly advertises routes as expected
  • Existing connections to the virtual server that depend on the route may fail

Workaround

To work around this issue, you can disable the connection limit setting for the virtual server. To do so, perform the following procedure:

Impact of workaround: The system will no longer enforce a connection limit for the virtual server.

Disabling connection limits for the virtual server

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click the virtual server object for which you want to disable connection limits.
  5. Change the Connection Limit setting to zero (0).
  6. Click Update.
