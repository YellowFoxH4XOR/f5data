Description

Installing nShield netHSM client software 12.81.2 on BIG-IP DNS results in errors or improper operation.

To install nShield client on BIG-IP LTM with external RFS, see K000151794: nShield HSM 12.60+ Client installation for BIG-IP LTM

Environment

  • BIG-IP DNS
  • RFS installed on BIG-IP DNS
  • Client software 12.81.2
  • nShield netHSM
  • Sync group
  • DNSSEC

Cause

Multiple ID's have been identified that can result in failed installation or improper operation:

ID1168237
ID1137569
ID966461

Recommended Actions

At the time of writing, 15.1.x, 16.1.x and 17.1.x will require an EngHF for:

  • ID1137569

A workaround for ID1168237 will need to be applied as per the instructions in step 3 below.

The following steps have been used to install the 12.81.2 client software on 2x BIG-IP DNS devices in a gtm sync group with the EngHF installed, working with a single external netHSM device for test purposes.

Note: Additional steps will be required for your specific implementation in a production environment as part of your organisation's design requirements. Refer manual chapter and HSM vendor documentation for details.

 

1. Copy files from vendor supplied CD /linux/amd64/nfast/ to nfast directory on BIG-IP:

ls -la /shared/thales_install/amd64/nfast/

total 337076
drwxr-xr-x. 2 root root 4096 May 4 05:48 .
drwxr-xr-x. 3 root root 4096 May 4 05:48 ..
-r--r--r--. 1 root root 51150199 Apr 13 06:16 ctd.tar.gz
-r--r--r--. 1 root root 157509101 Apr 13 06:16 ctls.tar.gz
-r--r--r--. 1 root root 4647262 Apr 13 06:16 devref.tar.gz
-r--r--r--. 1 root root 103229522 Apr 13 06:16 hwsp.tar.gz
-r--r--r--. 1 root root 5727443 Apr 13 06:16 javasp.tar.gz
-r--r--r--. 1 root root 7300746 Apr 13 06:16 jd.tar.gz
-r--r--r--. 1 root root 15191211 Apr 13 06:16 ncsnmp.tar.gz
-r--r--r--. 1 root root 385979 Apr 13 06:16 raserv.tar.gz

2. Uninstall existing software from both BIG-IP DNS devices:
nethsm-thales-install.sh -u

The following commands will remove any remaining traces of the client software:

rm -f /etc/init.d/nc_hardserver

rm -f /opt/nfast

rm -rf /shared/nfast

rm -rf /dev/nfast

userdel nfast

groupdel nfast


3. Workaround for ID1168237 to ensure rfs-sync work correctly. Check which device has value 0 and install RFS on that device
tmsh list sys db gtm.peerinfolocalid

Example output:

sys db gtm.peerinfolocalid {
    value "0"
}

Install RFS on that device, replacing <HSM_IP> and <NETHSM_VLAN> with actual values:
nethsm-thales-rfs-install.sh --hsm_ip_addr=<HSM_IP> --rfs_interface=<NETHSM_VLAN>

See article on how to configure the peer leader on BIG-IP DNS: K16504523: Configuring a specific DNS synchronization group member to perform DNSSEC key generation


4. On RFS BIG-IP, install security world files as per HSM vendor documentation.

5. Add BIG-IP DNS device IP's to RFS configuration, replacing <RFS_SELF_IP> and <PEER_SELF_IP> with actual values:

/opt/nfast/bin/rfs-setup --force -g --write-noauth <RFS_SELF_IP>
/opt/nfast/bin/rfs-setup --force -g --write-noauth <PEER_SELF_IP>

Ensure these IP addresses have network connectivity and operate in the <NETHSM VLAN>

6. Workaround for read permission error - client installation error message (when this step is ommitted):

Unable to query generation file: ServerAccessDenied
ERROR: RFS sync failed.

with --verbose=999
Unable to read directory:kmdata-local: AccessDenied

Edit config file:

vi /opt/nfast/kmdata/config/config

Search for "kmdata-local"
If "remote_ip" matches any BIG-IP interface then proceed with next step.
Edit the "native_path" value and substitute opt with shared
Repeat until you reach the end of file.
Save file before exiting once complete.

Example:

[remote_file_system]

...

remote_ip=10.0.0.1
remote_esn=
keyhash=0000000000000000000000000000000000000000
native_path=/opt/nfast/kmdata/local
volume=kmdata-local
allow_read=yes
allow_write=yes
allow_list=yes
is_directory=yes
is_text=no

With

remote_ip=10.0.0.1
remote_esn=
keyhash=0000000000000000000000000000000000000000
native_path=/shared/nfast/kmdata/local < --- Please note /shared/ instead of /opt/
volume=kmdata-local
allow_read=yes
allow_write=yes
allow_list=yes
is_directory=yes
is_text=no

Restart services:
/etc/init.d/nc_hardserver restart
bigstart restart pkcs11d tmm

7. Install client software and complete installation:

On RFS BIG-IP:
nethsm-thales-install.sh --hsm_ip_addr=<HSM_IP> --rfs_interface=<NETHSM_VLAN> --hsm_partition_name="loadshared accelerator"

On Peer BIG-IP, if previous command was successful on RFS BIG-IP:

Follow steps 1 and 2 if not completed already, before installing client software:
nethsm-thales-install.sh --hsm_ip_addr=<HSM_IP> --interface=<NETHSM_VLAN> --rfs_ip_addr=<RFS_SELF_IP> --hsm_partition_name="loadshared accelerator"

8. Run pkcs11d test on each BIG-IP (some tests may fail if not supported on HSM):
pkcs11d_test_suite

 

9. Create dnssec key for further testing
