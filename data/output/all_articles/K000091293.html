K000091293: NGINX Controller, Auth Provider in "Connection Failed" status

Type
Support Solution
Published
2022-03-01
Updated
2022-03-01
Source
https://my.f5.com/manage/s/article/K000091293

Description

When configuring an Auth Provider on NGINX Controller the Connection Status shows Connection Failed. The correct status should be Bound.

NGINX Controller UI: Platform > Auth Providers > Overview > Auth Providers

 

There could be not enough description for the cause of the error, not even in the logs.

 

 Environment

  • NGINX Controller 3.22.0
  • Auth Providers

 Cause

There might be a misconfiguration, like an URI not resolving.

 

 Recommended Actions

Debug logs on platform-mgr Kubernetes pod may reveal more information and the reason for the failed state.

 

Enable DEBUG on platform-mgr pod

kubectl patch cm `kubectl get cm | grep platform-mgr | sed 's/ .*//'` -p '{"data": {"LOG_LEVEL": "DEBUG" }}'

 

Reset the pod by deleting it

kubectl delete pod -l app=platform-mgr

 

Watch the logs generated by the pod in real-time

kubectl logs -l app=platform-mgr -f

 

Then try to apply the Auth Provider again, while monitoring the logs.

 

Rollback debug logs on platform-mgr pod

kubectl patch cm `kubectl get cm | grep platform-mgr | sed 's/ .*//'` -p '{"data": {"LOG_LEVEL": "INFO" }}'

kubectl delete pod -l app=platform-mgr

 

 Additional Information

None.
