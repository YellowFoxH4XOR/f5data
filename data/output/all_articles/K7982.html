Known Issue

Note: This behavior only occurs when mirroring Layer 7 connections.

This is the result of a known issue. Congested Layer 7 connection flows may cause TMM to panic when mirrored. When a mirrored Layer 7 connection flow becomes congested, the congestion windows on both the active and standby system can diverge to a point where the standby flow receives a partial ACK response for data that has not yet been transmitted. This divergence between the active and standby connection flows causes TMM to panic. As a result, the system may crash.

F5 Product Development tracked this issue as ID 248130 (formerly CR67185 and CR74705) and the affected bandwidth delay logic was removed from TMM in BIG-IP 9.4.2. For information about uprading, refer to the BIG-IP release notes.

Workaround

You can work around this issue by disabling the Bandwidth Delay option in the TCP profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles
  4. Select TCP from the Protocol menu.
  5. Select the TCP profile or the custom TCP profile for which you want to disable the Bandwidth Delay option.
  6. Clear the Bandwidth Delay check box.
  7. To save the changes, select Update.

This workaround will prevent the congestion windows from diverging on both the active and standby systems.
