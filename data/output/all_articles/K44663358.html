Description

After upgrading to version 13.1.5, 14.1.4.6, 15.1.5.1, or 16.1.2.2, API platforms, such as Postman, are getting 401 responses when a token is reused.

You have the following scenario

  1. Create a token using postman
  2. Use postman to call transaction endpoint using the created token (this works)
  3. Use the same token from another postman to create a transaction (this fails)
    • You take packet captures for REST calls following article K23227510, however, you do not see any 401 response. All the transactions captured are responded with 200 OK.
    • You enabled http debug, but there are no errors on HTTPD logs.
    • No point of failure found on RESTJAVAD.audit.log file

Environment

  • BIG-IP version 13.1.5, 14.1.4.6, 15.1.5.1 or 16.1.2.2
  • Getting 401 when a token is reused
  • No http errors are seen when enabling httpd debug
  • Packet capture does not show any 401 response from the BIG-IP

Cause

httpd.matchclient variable was added in version 13.1.5, 14.1.4.6, 15.1.5.1, and 16.1.2.2. This variable prevents the reuse of a token in different postman applications.

Recommended Actions

  1. Generate a token for each postman, do not reuse.
  2. If it is necessary to reuse the token, change httpd.matchclient variable to false.
tmsh modify sys db httpd.matchclient value false
tmsh save sys config
  1. httpd must be restarted in order for the change to take effect
bigstart restart httpd
