Description

Some virtual addresses become temporarily unreachable from the network after a failover event.
 

Environment

  • BIG-IP virtual address with arp enabled
  • a static or dynamic /32 route for the same virtual address
  • BIG-IP configured in HA
  • Failover event


Cause

A virtual address configured on the BIG-IP is commonly configured to respond to ARP requests.

ltm virtual-address /Common/192.168.1.10 {
address 192.168.1.10
arp enabled
mask 255.255.255.255
server-scope none
traffic-group /Common/traffic-group-1
}

A /32 route for a virtual address will override the Gratuitous ARP that occurs during failover, as the route implies that the address is the responsibility of another device.
Traffic will continue to be sent to the previously Active device until the switch ARP entry times out and a new ARP requests gets the MAC address of the current Active BIG-IP.

These /32 routes may be in the form of a static route entry:

net route /Common/192.168.1.10 {
  description 192.168.1.10
  gw 192.168.1.1
  network 192.168.1.10/32
}

Or a routing table entry learned from dynamic routing protocols such as BGP or OSPF, among others:

# tmsh show /net route
...
192.168.1.10/32          192.168.1.10/32          gw          192.168.1.1                             dynamic              0


Recommended Actions

Ensure that Virtual Addresses on the BIG-IP do not have /32 routes defined or learned via routing protocols to avoid overriding GARPs from being sent during failover.
