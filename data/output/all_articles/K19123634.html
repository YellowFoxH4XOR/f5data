Known Issue

User access sessions may restart when accessing the root URI (/).

This issue occurs when all of the following conditions are met:

  • The user establishes an access session with the BIG-IP APM system and is assigned a webtop.
  • The user browses to the root URI (/) either directly or by opening a new browser tab or browser window.

Impact

The BIG-IP APM system deletes the existing access session and starts a new session.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • In the /var/log/apm file, you notice an error message similar to the following example:

    notice tmm[4841]: 01490567:5: /Common/access_profile:Common:9494c15a: Session deleted (internal_cause).

Workaround

There is no workaround for this issue.  However, fixed versions include a new log message that now reads Session deleted (restarted). When you see this message, it indicates that the previous session was deleted and a new session started because the BIG-IP APM end user accessed the root URI when there was a webtop assigned to that BIG-IP APM end user. This might occur when the BIG-IP APM end user with the assigned webtop opens a new browser tab or new browser window, or otherwise visits the root URI ( / ).
