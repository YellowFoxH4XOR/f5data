Known Issue

The BIG-IP system may erroneously allow you to configure the Domain Name System (DNS) server residing in a non-default route domain.

This issue occurs when all of the following conditions are met:

  • You want to configure a DNS server to resolve host names on your BIG-IP system.
  • The DNS server resides in a non-default route domain.
The BIG-IP system uses two sources of information to resolve host names: the hosts file and DNS. The BIG-IP system first refers to the local /etc/hosts file. If the host name is not found in the /etc/hosts file, the BIG-IP system then uses DNS if configured to do so. The configuration of the DNS server is located under System > Configuration > Device > DNS in the Configuration utility.

Impact

The BIG-IP system may fail to resolve DNS host names.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When performing a DNS lookup from the BIG-IP system, the DNS query fails with an error message that appears similar to the following example:

    ?[root@bigip:Active:Standalone] config # nslookup www.example.com
    ;; Got recursion not available from 127.0.0.1, trying next server
    ;; Got recursion not available from 127.0.0.1, trying next server
    Server: ::1
    Address: ::1#53

    ** server can't find www.example.com: REFUSED?

Workaround

There is no workaround for this issue. To avoid this issue, you should configure only DNS servers that are available in the default route domain. For more information, refer to K13205: Configuring the BIG-IP system to resolve DNS hostnames (11.x and later).

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
