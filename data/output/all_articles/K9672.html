K9672: Windows Vista clients cannot access external sites when using Windows logon integration with split tunneling

Topic

Starting in Windows Vista, Windows automatically disables the default routes of LAN interfaces when a Windows-based VPN client establishes a connection. If the VPN connection does not receive a default route, for example when split tunneling is enabled, the user is unable to access sites which do not route through the Network Access connection. This behavior does not occur in previous versions of Microsoft Windows, such as Windows XP and Windows 2000.

Note: For more information about this behavior, refer to http://technet.microsoft.com/en-us/magazine/2007.09.cableguy.aspx.

When this behavior occurs, and a user attempts to ping a host that does not route through the Network Access connection, an error message that appears similar to the following example is displayed:

PING: transmit failed, error code 1231.

The FirePass Windows logon integration (GINA) component is installed as a Windows-based VPN client so that the FirePass VPN adapter can be selected at the Windows logon screen. As a result, if split tunneling is configured for the Network Access connection, users running Vista with Windows logon integration cannot access sites that do not route through the Network Access connection. When a user establishes a Network Access connection using the FirePass webtop or standalone VPN client, Vista does not disable the default routes of LAN interfaces; therefore, external sites can be accessed.

If users only need to access particular external hosts or subnets, you can work around this issue by specifying those hosts or subnets in the Subnets to exclude field in the Network Access connection configuration.

Note: The Subnets to exclude field is located on the Network Access : Resources page under the Client settings tab. This field only appears if the Exclude subnets check box is selected.

If users need to access a wide variety of external hosts, users can work around this issue by performing one of the following two actions:

  • Running the following command on the client system after establishing the Network Access connection:

    netsh interface ipv4 set interface "[InterfaceName]" ignoredefaultroutes=disabled

    The InterfaceName section should be the name of the interface on which the default route is configured.

    For example:

    netsh interface ipv4 set interface "Local Area Connection" ignoredefaultroutes=disabled

    Important: Running the netsh command may require administrative privileges on the Vista client system.
     
  • Opening a Network Access connection using the FirePass webtop or standalone VPN client instead of the Windows logon integration component.
