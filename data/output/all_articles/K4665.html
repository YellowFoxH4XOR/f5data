K4665: IP filters that allow established connections only apply to TCP connections

Known Issue

This is the result of a known issue. Prior to BIG-IP versions 4.5.11 and 4.6.3, when you apply a rule that uses the established directive, BIG-IP denied all packets by default and allowed established connections for any protocol to pass.

Beginning in versions 4.5.11 and 4.6.3, the established rule directives allow only TCP connections. As a result, ICMP connections, including ICMP health checks, will fail if you have configured an established rule.

F5 Networks Product Development tracked this issue as CR47979 and CR47981.

Workaround

To work around this issue, perform the following steps:

Important: After you edit the ipfw.conf file from the command line, the IP filter configuration may no longer parse from the Configuration utility. When this occurs, the Configuration utility reports an Error 331786 -- File parse error when you attempt to view the IP filters. Do not use the Configuration utility to modify IP filters that you added through the command line; it may delete or overwrite the existing filters.

  1. Log in to the command line.
  2. Back up the /config/ipfw.conf file, by typing the following command:

    cp /config/ipfw.conf /config/ipfw.conf.org

  3. Using a text editor, edit the /config/ipfw.conf file.
  4. Locate the rule that begins with tcp && established and contains additional arguments within brackets.
  5. Immediately after the closing bracket ( } ), add the following text:
    icmp
{
   accept;
}

    Note: The blank space before accept; is a tab.

  6. Save the file and exit the editor.
  7. Compile the new IP filters by typing the following command:

    ipfwcmp -o /config/ipfw.filt /config/ipfw.conf

  8. Load the new IP filters by typing the following command:

    /etc/bigstart/scripts/ipfw-ctrl restart

BIG-IP will now use the new IP filters and will allow ICMP traffic.
