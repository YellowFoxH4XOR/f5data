Known Issue

This is the result of a known issue. It is possible for the BIG-IP LTM to forward a retransmitted packet to an incorrect client if the following scenario occurs:

  • Client A sends a request to a FastHTTP virtual server.
  • The BIG-IP LTM then sends the request to a server.
  • The server sends a response to client A through the BIG-IP system.
  • The BIG-IP LTM then sends the response to client A.
  • Client B sends a request to the FastHTTP virtual server.
  • Client A sends an ACK packet, acknowledging the response was received.
  • The BIG-IP LTM combines both the ACK packet from client A and the request from client B into one packet and sends the REQ+ACK packet to the server.

If this REQ+ACK packet is lost, the server will retransmit the response that was previously sent to client A, but the BIG-IP LTM will send the retransmitted response to client B.

Note: The TCP sequence numbers will always be inappropriate for client B, so this is not a true data-crossing risk. Under normal conditions, client B will retransmit its request, which will be processed as usual.

F5 Product Development tracked this issue as CR69272 and CR69459 and it was fixed in BIG-IP LTM versions 9.1.3, 9.2.5, 9.3.0, and 9.4.0. For information about upgrading, refer to the BIG-IP LTM release notes.
