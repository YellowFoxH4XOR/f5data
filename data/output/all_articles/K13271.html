K13271: New option to select an Active Directory query type

Issue

Old Behavior

FirePass used the LDAP_MATCHING_RULE_IN_CHAIN OID to perform recursive lookups in Active Directory queries. This type of query adds additional search overhead and may cause significant wait times for Active Directory queries to complete.

New Behavior

Beginning in FirePass version 7.0.0 HF-70-4.1-1 and FirePass version 6.1.0 HF-610-7, the Use LDAP_MATCHING_RULE_IN_CHAIN option has been added to allow users to select a method when querying Active Directory.

F5 Product Development is tracking this change as ID 344987.

Impact

Selecting the Use LDAP_MATCHING_RULE_IN_CHAIN option may increase the query completion time, slowing user logins. If the user does not select the Use LDAP_MATCHING_RULE_IN_CHAIN option, the search may fail if the group name and the pre-Windows 2000 group name do not match in Active Directory. For more information, refer to K11648: Active Directory group mapping fails when using nested groups.

Recommended Actions

The new option is located on the Active Directory mapping method screen, under the Users : Groups : Dynamic Group Mapping, Group Mapping Methods tab. Selecting the Check nested groups while mapping check box will enable a new option, Use LDAP_MATCHING_RULE_IN_CHAIN to search nested groups. Enabling this option will change the search behavior described in K13350: Change in Behavior: Active Directory queries now use the LDAP_MATCHING_RULE_IN_CHAIN OID.
