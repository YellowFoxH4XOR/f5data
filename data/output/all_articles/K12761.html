Known Issue

This is the result of a known issue. If a host makes an SNMP query to a BIG-IP system IPv6 or route domain address residing on any route domains except route domain 0, the snmpd process receives the request but is unable to send a response through that address. Additionally, the snmpd process does not send SNMP traps through the BIG-IP system IPv6 or route domain address.

F5 Product Development tracked this issue as ID 343037 and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about downloading software from F5, refer to K167: Downloading software and firmware from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by configuring an IPv4 address residing in route domain 0 on the BIG-IP system for the snmpd process to receive SNMP queries and to send SNMP responses or traps. For information on how to do so, refer to the TMOS Management Guide for BIG-IP Systems guide.
