K04199440: UDP Connections go to the wrong virtual server

Type
Support Solution
Published
2021-06-22
Updated
2023-01-09
Applies to
  • BIG-IP LTM: 16.X.X
Source
https://my.f5.com/manage/s/article/K04199440

Description

UDP traffic goes to the wrong virtual server

Environment

  • BIG-IP LTM

Cause

UDP sessions will continue to connect to a previous virtual server, despite config being modified, due to long UDP timeout, or rapid UDP data that doesn't get a chance to reach idle timeout.

TCP and UDP sessions will always continue to use the config that was in place when the session was created. The new config is only used for new connections.

This is by design, as the BIG-IP needs to maintain a connection table for UDP sessions, so when the return traffic comes back to the BIG-IP, the BIG-IP knows which connection they originated from, so they can be returned back to the correct Client Side connection.

This tends to happen more with UDP than TCP, as UDP often create long lasting session using the same source port, especially syslog connections. This issue can also occur with TCP, but normally TCP will periodically delete sessions and create new sessions, which will pick up the new config.

Recommended Actions

Delete the entries from the connection table after modifying the Virtual server. In some scenarios, stopping the ingress UDP traffic altogether, is also required.

For example, If your connections are destined for the IP Address 10.128.20.188, then you can show these connections as follows:

# tmsh show sys connection cs-server-addr 10.128.20.188

Sys::Connections
10.128.20.18:12345  10.128.20.188:514  10.128.10.148:12345  10.128.10.204:514  udp  23  (tmm: 0)  none  none
Total records returned: 1

This connection can be delete with:

# tmsh delete sys connection cs-server-addr 10.128.20.188
