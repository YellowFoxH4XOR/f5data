Known Issue

This is the result of a known issue. Enterprise Manager 1.0 through 1.7 uses the f5emsvr user account to authenticate to BIG-IP 9.1.2 through 10.1.0 systems. The account is automatically created when the BIG-IP software is installed. If you restore a configuration archive (UCS) file from a system or version that did not contain the user account f5emsvr, the account is removed. As a result, Enterprise Manager is unable to authenticate to the BIG-IP system, and logs the following message in the /var/log/em file:

Apr 16 09:46:38 big-ip discoveryd[1879]: 04030112:3: [0d982bb0] Could not get device information for address: 10.10.10.1: getUsersInfo: iControl error: 'iControl::OperationFailed - primary code:16908342(0x1020036) secondary code: 0(0x0) string: 01020036:3: The requested userdb_entry (f5emsvr) was not found.'

F5 Product Development is tracking this issue as CR82704 for the BIG-IP 9.4.x software branch. The issue was resolved for the 10.x software branch when the requirement for the account was removed in Enterprise Manager 1.8.

Workaround

You can work around this issue by restoring the missing user account as detailed in K9851: Error message: The requested userdb_entry (f5emsvr) was not found.
