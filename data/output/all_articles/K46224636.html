Topic

The dns_fwd profile is a predefined profile that the BIG-IP system creates to preserve certain 10.x resolution behavior when you upgrade BIG-IP GTM from 10.x to 11.x. The default DNS profile is the parent profile for dns_fwd.

Description

In BIG-IP 10.x and earlier, if a listener object does not match a self IP address, local BIND resolution is disabled and query forwarding is enabled.

Note: In BIG-IP 10.x and earlier, if the listener object matches a self IP address, then local BIND resolution is automatically enabled.

In BIG-IP 11.x and later, the Use BIND Server on BIG-IP option in the DNS profile dictates local BIND resolution. If the option is Disabled, and the listener does not match a self IP address, then query forwarding is enabled; however, the default setting of the profile option is Enabled and thus after an upgrade to 11.x, it alters the resolution behavior of listeners that do not match a self IP address.

During an upgrade from 10.x to 11.x, to preserve the query forwarding behavior on listeners configured this way, the BIG-IP system creates the dns_fwd profile where the Use BIND Server on BIG-IP option on the profile is set to the non-default value Disabled and assigns it to these listeners. Queries that don't match a wide IP or other resolution option directed toward the listeners are forwarded that replicates the 10.x behavior. The profile will remain in the configuration through an upgrade from 11.x to 12.x and beyond, unless you manually delete it. You can replace or modify the profile as needed.

For example, the following 10.x listener object does not match a self IP address and forwards queries that do not match a wide IP or another resolution option:

ltm virtual vs_10_1_1_1_53_gtm {
    destination 10.1.1.1:domain
    ip-protocol udp
    mask 255.255.255.255
    profiles {
        dns { }
        udp_gtm_dns { }
    }
    translate-address disabled
    translate-port disabled
}

The same listener appears similar to the following example after an upgrade to 11.x. With the dns_fwd profile applied, there is no change in behavior:

ltm virtual vs_10_1_1_1_53_gtm {
    destination 10.1.1.1:domain
    ip-protocol udp
    mask 255.255.255.255
    profiles {
        dns_fwd { } 
        udp_gtm_dns { }
    }
    source 0.0.0.0/0
    translate-address disabled
    translate-port disabled
    vs-index 5
}

Note: You cannot upgrade BIG-IP GTM from 10.x to BIG-IP DNS 12.x. For more information, refer to K17158: Upgrading directly from BIG-IP 10.x to 12.x is not supported when the GTM module is provisioned.

Recommendations

After upgrading the BIG-IP GTM from 10.x to 11.x, make sure to apply the dns_fwd profile to any listener objects that do not match a self IP address.
