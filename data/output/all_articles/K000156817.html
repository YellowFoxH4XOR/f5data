K000156817: Unable to reach BIG-IP after ova deployment and setting OAM IP

Type
Support Solution
Published
2025-10-06
Updated
2025-10-06

Source

Description

After deploying BIG-IP Virtual Edition (VE) with only a single network interface (NIC) and assigning an OAM (management) IP, the system does not respond to ping (ICMP) requests on the management IP after boot. ICMP packets are observed arriving at the system, but no replies are sent.

Additionally, HTTP and SSH connections also do not work. Pinging local network devices via console results in 100% packet loss, but if you view a tcpdump while sending the pings you may see both the requests and replies.

A tcpdump may also show packets leaving and arriving to a numbered interface (such as "1.0") instead of mgmt.

 

Environment

Product: BIG-IP LTM Virtual Edition (VE)

Deployment Platform: Virtual Machine

Initial Configuration: Only a single network interface attached to the VM

Management Access: OAM IP configured via console during setup

 

Cause

When only a single NIC is attached to the BIG-IP VE VM, all network traffic—including management—is handled by the data plane interface (such as "1.0") instead of a dedicated management interface ("mgmt"). If TMM (Traffic Management Microkernel) is not set up or provisioned for this configuration, there is no process listening for or responding to traffic on the data plane interface, resulting in no response to management protocols such as ICMP.

 

Recommended Actions

  • Deploy BIG-IP VE with at least two network interfaces:
    • One mapped as the dedicated management interface ("mgmt")
    • One or more mapped as data plane interfaces ("1.x", etc.)
  • Confirm correct NIC mapping in your hypervisor before powering on the VM.
  • After adding required interfaces, reboot the VM and verify management access via ping, HTTPS, or SSH.
  • Refer to official F5 documentation for BIG-IP VE network interface requirements and deployment best practices.
    • https://my.f5.com/manage/s/article/K82540512

 

 

Additional Information

This issue appears similar to Bug ID 1295217 - however, the "provision.1nic" is set to the default of "disable".

For proper steps to configure a single-NIC VE, follow steps outlined here: https://clouddocs.f5.com/cloud/public/v1/vmware/vmware_users.html#about-single-nic-and-multi-nic-configurations
