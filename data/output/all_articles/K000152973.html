K000152973: understanding of support and impacts of DHE2048

Type
Support Solution
Published
2025-08-12
Updated
2025-08-12
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000152973

Description:


When configuring SSL profiles on BIG-IP LTM version 17.1.2, it may be necessary to disable support for 1024-bit Diffie-Hellman Ephemeral (DHE1024) key exchange and ensure only 2048-bit (DHE2048) and higher key sizes are used. This is required to comply with security standards and policies. Improper configuration may result in negotiation of weaker DHE ciphers.

Environment:

  • Product: BIG-IP LTM
  • Version: 17.1.2
  • Platforms: F5-BIG-LTM-R2600, C130
  • SSL profiles using default or custom cipher groups
  • DHE key exchange required for compliance or security policy

Cause:


By default, BIG-IP LTM may allow negotiation of 1024-bit DHE ciphers unless explicitly disabled. The system-wide DB variable tmm.ssl.dh1024 controls whether 1024-bit DHE is permitted.

Recommendations:

  1. Disable 1024-bit DHE System-Wide:
  • Set the DB variable tmm.ssl.dh1024 to disable:
    • tmsh modify sys db tmm.ssl.dh1024 value disable
  1. Create a Cipher Rule to Exclude DHE1024:
  • Navigate to Local Traffic > Ciphers > Rules.
  • Create a new rule (e.g., exclude-dhe1024).
  • In the DH Groups field, specify FFDHE1024 to exclude 1024-bit DHE.
  1. Create a Custom Cipher Group:
  • Go to Local Traffic > Ciphers > Groups.
  • Create a new group (e.g., f5-default-no_dhe1024).
  • In "Allow the following", add the pre-built f5-default cipher rule.
  • In "Exclude the following from the Allowed List", add your custom exclude-dhe1024 rule.
  1. Assign the Custom Cipher Group to SSL Profiles:
  • Navigate to Local Traffic > Profiles > SSL > Client (or Server).
  • Edit the relevant SSL profile.
  • Under Configuration, select Advanced.
  • For Ciphers, choose Cipher Group and select your new group (f5-default-no_dhe1024).
  1. Performance Considerations:
  • Larger DHE key sizes increase CPU usage.
  • Monitor CPU utilization and SSL transactions per second before/after changes.
  • Review memory usage and SSL session cache statistics for impact assessment.
