Description

When configuring a webtop link to launch from the APM webtop, the new tab opened might not display the application or you might see an error.

The error would be similar to this:

Uncaught DOMException: Blocked a frame with origin "<website address>" from accessing a cross-origin frame.

Environment

  • APM Configured
  • Webtop Link Configured

Cause

The code for the webtop link uses window.open to launch the website in a new window. Using window.open you need to have "noreferrer" as an option to avoid the CORS error.

See https://developer.mozilla.org/en-US/docs/Web/API/Window/open#noreferrer for more information on how window.open works.

Recommended Actions

To workaround this issue an iRule can be used.

when CLIENT_ACCEPTED {
	ACCESS::restrict_irule_events disable
}
 
when HTTP_REQUEST {
	if { [HTTP::path] ends_with "/vdesk/webtop.eui"} {
		set match 1
	} else {
		set match 0
	}
}
 
when HTTP_RESPONSE {
	if {$match == 1} {
		if { [HTTP::header exists "Content-Length"] and [HTTP::header "Content-Length"] <= 1048576 } {
			HTTP::collect [HTTP::header Content-Length]
		} else {
			HTTP::collect 2097152 ;# 2MB
		}
	}
}
 
 
when HTTP_RESPONSE_DATA {
	if {$match == 1} {
		set from1 {"_blank" , ""}
		set to1 {"_blank" , "noreferrer"}
		regsub -all $from1 [HTTP::payload] $to1 result
		set content_len [string length [HTTP::payload]]
		HTTP::payload replace 0 $content_len $result
		HTTP::release
	}
}
