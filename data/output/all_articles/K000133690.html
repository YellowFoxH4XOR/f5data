K000133690: Manually created GTM virtual server not getting correct status from LTM

Type
Support Solution
Published
2023-04-27
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP DNS: 13.1.4
Source
https://my.f5.com/manage/s/article/K000133690

Description

  • Manually created GTM virtual server is not getting the correct monitor status from LTM
  • For example, GTM server says UP, but LTM status for same IP:Port says DOWN

Environment

  • GTM virtual server is manually created because auto-discovery is not possible - address translation in use

Cause

When GTM server is manually created, big3d process does the best it can to match the correct LTM virtual server status to the GTM server, but it may fail to make a good match.

 

 Recommended Actions

  1. Check with iqdump to see what the LTM is actually sending - use iqdump -s <DNS sync group name> <server object address of the LTM>
    1. Example: iqdump -s my_dns_sync_group 10,10,10,10
  2. See that there is a mismatch between the DNS server name and the ltm_name that big3d is trying to match:  
    <vip>   
     <name>
          <![CDATA[George_server1-monitor]]>
     </name>   
     <ltm_name>
         <![CDATA[/Common/Henry_server1-monitor]]>
     </ltm_name>   
     <ip>::ffff:192.168.1.10</ip>  
     <target_ip>::ffff:10.205.125.253</target_ip>   
     <port>443</port>   
     <target_port>60123</target_port>
    Here you can see that the DNS virtual server is named "George_server1-monitor" but big3d is matching data from LTM virtual server "Henry_server1-monitor". You can verify that the ip and port are those that were configured as the translation address on the DNS unit and the target_ip and target_port are the match to the LTM virtual server (which is the incorrect match).
  3. Once you verify that the issue is an incorrect match on behalf of big3d, you can correct it to match to the correct LTM object but adding a ltm-name tag to the DNS virtual server.  
    tmsh modify /gtm server <server name> virtual-servers modify { <virtual server 1> { ltm-name /<partition>/<virtual server 1> } }
    For example:  
    tmsh modify /gtm server my_ltm_paira-b virtual-servers modify { George_server1-monitor { ltm-name /Common/George_server1-monitor}}

This will now force big3d to match the proper DNS virtual server to the proper LTM virtual server.
