K3068: Upgrading to version 4.5 may fail due to lack of disk space

Type
Knowledge
Published
2006-02-17
Updated
2023-02-21
Status
Legacy Content
Applies to
  • Legacy Products
  • 3-DNS: 4.6.4
  • BIG-IP 4.X: 4.6.4
Source
https://my.f5.com/manage/s/article/K3068

Topic

256MB CompactFlash cards tend to run at about 93% (or more) capacity on the / partition.

To work around this space limitation, you can remove the following files prior to running the upgrade IM process to provide you with enough space to complete the IM upgrade.

  • Files ending in .core
  • Extra UCS backup files
  • PDF manuals from the local file system
  • openssh-3.7.1p1.tar.gz source files
  • Local big3d agent copies
  • Unused kernels

Important: F5 Networks recommends that you delete the specified files (just prior to upgrading the system) with the IM upgrade saved on a memory file system, as specified in the BIG-IP and 3-DNS Release Notes.

Files ending in .core

To remove files ending in .core, perform the following steps:

  1. Search the system for the core files, by typing the following command:

    shimon:~# find / -name "*.core"

    The output should appear similar to the following:

    /var/core/bigd.core

    Note: Be sure to check the /var/crash and /var/core, directories as they may contain core files. You can safely remove any files found in those directories unless you are actively working with F5 Technical Support to resolve an issue.

  2. Remove the files, by typing the following command:

    rm -f /path/to/corefile.core

Extra UCS backup files

Important: Before you remove any UCS files, you must back them up to a remote location.

Remove all UCS backup files from the /usr/local/ucs directory except for the following files:


config_skel.tgz

Setup_backup.ucs

last_boot.ucs

var_skel.tgz

PDF manuals from the local file system

Note: You can also download the BIG-IP and 3-DNS manuals in PDF format from the following locations:

  • BIG-IP Manuals
  • 3-DNS Manuals

To remove PDF manuals from the local file system, perform the following steps:

  1. Search the system for the PDF files, by typing the following command:

    find / -name "*.pdf"

    The output should appear similar to the following:

    
/usr/local/www/doc/3dns_admin.pdf

/usr/local/www/doc/3dns_ref.pdf

/usr/local/www/doc/bigip_halbadmin.pdf

/usr/local/www/doc/bigip_ref.pdf

/usr/local/www/doc/lc_solutions.pdf

/usr/local/www/doc/ssl.pdf

  2. Remove the files, by typing the following command:

    rm -f /usr/local/www/doc/*.pdf

openssh-3.7.1p1.tar.gz source files

You can delete the openssh-3.7.1p1.tar.gz source files, which are included to build open SSH on a UNIX workstation, without affecting how SSH works on BIG-IP.

To remove the openssh-3.7.1p1.tar.gz source files, type the following command:


rm -f /usr/contrib/openssh/unix/openssh-3.7.1p1.tar.gz

Local big3d agent copies

Because BIG-IP and 3-DNS share the same operating system and file structure, many files that are not used by BIG-IP are stored on the drive. This includes the library of big3d agents that are used only if the BIG-IP systems is functioning as a 3-DNS Controller. You can safely remove these files.

To remove the local big3d agent copies, perform the following steps:

  1. Search the system for the big3d agent files, by typing the following command:

    find /usr/local -name "big3d*"

    The output should appear similar to the following:

    
/usr/local/3dns/store/big3d45.gz

/usr/local/3dns/store/big3d4502.gz

/usr/local/3dns/store/big3d4504.gz

/usr/local/3dns/store/big3d4508.gz

/usr/local/3dns/store/big3dredhat61.gz

/usr/local/3dns/store/big3dredhat70.gz

  2. Remove the file, by typing the following command:

    rm -f /usr/local/3dns/store/big3d*

Unused kernels

Warning: It is important that you do not delete the active bsd kernel because it is linked to /bsd.

In the following example, you can delete the bsd.generic and bsd.anip kernels, but do not delete bsd.smp, which is linked to bsd @->.

To list the kernels, type the following command:

ls -la /bsd*

The output should appear similar to the following:


 lrwxr-xr-x  1 root  wheel        7 Mar 11 16:22 /bsd@ -> bsd.smp

-rwxr-xr-x  1 root  wheel  2854453 Feb 18 17:18 /bsd.generic*

-rwxr-xr-x  1 root  wheel  2854993 Feb 18 17:19 /bsd.anip*

-rwxr-xr-x  1 root  wheel  2854453 Feb 18 17:19 /bsd.smp*

To delete unused kernels that are not linked to /bsd@ type the following command for each kernel you want to delete:

rm -f /bsd.<extension>

Where <extension> is generic, ANIP, SMP kernels that are not linked to /bsd@.
