Description
Starting on macOS Big Sur or later, macOS does not rely on and/or update /etc/resolv.conf unlike the way in previous macOS versions.

Instead of /etc/resolv.conf, macOS Big Sur uses scutil tool for DNS name resolution and utilize it to name resolution. Thus, the nslookup utility tool does not work after getting connected to the APM Network Access/VPN. Even so, the client can get connected to the host with a Fully Qualified Domain Name (FQDN), name resolution works.

From the manpage of Big Sur or later, nslookup is described as:

macOS NOTICE
       The nslookup command does not use the host name and address resolution
       or the DNS query routing mechanisms used by other processes running on
       macOS.  The results of name or address queries printed by nslookup may
       differ from those found by other processes that use the macOS native
       name and address resolution mechanisms.  The results of DNS queries may
       also differ from queries that use the macOS DNS routing library.

This change in macOS Big Sur's DNS name resolution behavior is recorded in F5 as Bug ID 972685: /etc/resolv.conf file is not updated on macOS Big Sur.

Recommended Actions

  • To check the list of DNS server(s) in macOS Big Sur or later version with APM Network Access or VPN, use 'scutil --dns'
For example:  
taccount@MacK ~ % scutil --dns

resolver #1
  nameserver[0] : 172.16.100.251 <== The DNS server configured on the NIC (= Local DNS)

  nameserver[0] : 192.168.100.1  <== The DNS server supplied by the access policy (= Behind the APM)
  if_index : 20 (utun2)
  flags    : Scoped, Request A records
  reach    : 0x00000002 (Reachable)
