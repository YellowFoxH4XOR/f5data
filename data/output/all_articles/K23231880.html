Topic

You should consider using this procedure under the following condition:

  • You configured attack signatures in your BIG-IP ASM security policy.
  • You want to enable and disable attack signatures using iControl REST.

Description

You can enable and disable specific BIG-IP ASM attack signatures using the iControl REST interface on the BIG-IP system. 

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You licensed, provisioned, and configured the BIG-IP ASM module on your BIG-IP system.
  • You configured your BIG-IP system with a management IP address.
  • You have administrative access to the BIG-IP Configuration utility.
  • You have command line access to a Linux system that has the curl utility, and optionally the jq utility, installed.

Procedures

  • Determining the security policy ID
  • Determining the attack signature ID
  • Enabling and disabling attack signatures

Determining the security policy ID

Each BIG-IP ASM security policy configured on the system includes a unique MD5 hash that identifies the security policy. You use the MD5 hash identifier to specify the security policy when managing attack signatures using the iControl REST API. To determine the MD5 hash identifier for the BIG-IP ASM security policy, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities.
  2. Use the following command syntax to determine the MD5 hash identifier for the security policy:

    curl -ksu <username:password> 'https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies?$filter=name%20eq%20<security_policy_name>&$select=name,id' | jq '.'

    For example, the system sends the following command to the host ltm1.example.com and filters for the security policy named asmpol1:

    curl -ksu admin:admin 'https://ltm1.example.com/mgmt/tm/asm/policies?$filter=name%20eq%20asmpol1&$select=name,id' | jq '.'

    The response contains the name of the security policy (asmpol1) and the corresponding hash identifier (FpUrTM3Za6zcos25HquN0g):

    {
      "kind": "tm:asm:policies:policycollectionstate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies?$select=name%2Cid&ver=16.0.0&$filter=name%20eq%20asmpol1",
      "totalItems": 1,
      "items": [
        {
          "kind": "tm:asm:policies:policystate",
          "selfLink": "https://localhost/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g?ver=16.0.0",
          "name": "asmpol1",
          "id": "FpUrTM3Za6zcos25HquN0g"
        }
      ]
    }

Determining the attack signature ID

After you determine the unique hash identifier for the security policy, you can use it to locate the attack signature MD5 hash identifier. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities.
  2. Use the following syntax to determine the hash identifier for the attack signature:

    curl -ksu <username:password> 'https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies/<security_policy_MD5hash>/signatures?$select=signatureReference,id,enabled' | jq '.' | grep -A 6 <attack_signature_name>

    Using the policy hash ID from the above example, locate the hash identifier for the attack signature named example_sig using the following command:

    curl -ksu admin:admin 'https://ltm1.example.com/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g/signatures?$select=signatureReference,id,enabled' | jq '.' | grep -A 6 example_sig

    In the following example, the hash ID for the attack signature is NjGb4S0qK-e26ODogweKsw and the signature is currently enabled:

            "name": "example_sig",
            "tag": "",
            "signatureId": 300000000
          },
          "id": "NjGb4S0qK-e26ODogweKsw",
          "enabled": true
        },

Enabling and disabling attack signatures

After you determine the hash identifiers for the security policy and the attack signature, you can use them to manage the attack signature for that specific security policy. This allows you to enable and disable specific attack signatures for individual security policies. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities.
  2. Use the following command syntax to enable or disable the attack signature:

    curl -ksu <username:password> -H "Content-Type: application/json" -X PATCH https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies/<security_policy_MD5hash>/<attack_sig_MD5hash> -d '{"enabled":"<true|false>", "performStaging":"<true|false>"}' | jq '.'
    Note: When enforcing or disabling an attack signature, make sure the key "performStaging" is set to false. 

    For example, using the hash signatures from the examples above, you can disable the attack signature with the following command:

    curl -ksu admin:admin -H "Content-Type: application/json" -X PATCH https://ltm1.example.com/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g/signatures/NjGb4S0qK-e26ODogweKsw -d '{"enabled":"false", "performStaging":"false"}' | jq '.'

    The system response is similar to the following example:

    {
      "lastUpdateMicros": 1595017197000000,
      "kind": "tm:asm:policies:signatures:signaturestate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g/signatures/NjGb4S0qK-e26ODogweKsw?ver=16.0.0",
      "signatureReference": {
        "link": "https://localhost/mgmt/tm/asm/signatures/C-caMHDgc8GnmxbXq7B9HQ?ver=16.0.0",
        "isUserDefined": true,
        "name": "my_curl",
        "tag": "",
        "signatureId": 300000000
      },
      "isPriorRuleEnforced": false,
      "alarm": true,

      "block": true,
      "performStaging": true,
      "learn": true,
      "enabled": false
    }

  3. Apply the changes to the security policy using the following syntax:

    curl -ksu <username:password> -H "Content-Type: application/json" -X POST https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/tasks/apply-policy -d '{"policyReference":{"link":"https://localhost/mgmt/tm/asm/policies/<security_policy_MD5hash>"}}' | jq '.'

    For example, to apply changes to the security policy named asmpol1, specify its hash identifier FpUrTM3Za6zcos25HquN0g using the following command:

    curl -ksu admin:admin -H "Content-Type: application/json" -X POST https://ltm1.example.com/mgmt/tm/asm/tasks/apply-policy -d '{"policyReference":{"link":"https://localhost/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g"}}' | jq '.'

    The system response is similar to the following example:

    {
      "kind": "tm:asm:tasks:apply-policy:apply-policy-taskstate",
      "selfLink": "https://localhost/mgmt/tm/asm/tasks/apply-policy/UylKZCnnyvKEq7wkaMLUVQ?ver=16.0.0",
      "policyReference": {
        "link": "https://localhost/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g?ver=16.0.0",

  4. Using the hash identifiers for the security policy and the attack signature, you can check the status of the attack signature using the following command:

    curl -ksu admin:admin 'https://ltm1.example.com/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g/signatures/NjGb4S0qK-e26ODogweKsw' | jq '.'
