K000151895: AVR alerts are being triggered when there is no rule being breached

Type
Support Solution
Published
2025-06-20
Updated
2025-06-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000151895

Description

AVR alerts has been configured to be triggered when Average Server Latency is above 60 ms for 300 seconds in a Pool Member. As per checking the logs, alerts had been triggered even though the threshold is less than the configured.

May 22 16:36:46 warning monpd[13458]: 01540001:4: AVR Alert alert2: profile /Common/Analytics1 - pool-member <pool memberip:portnumber> exceeding the configured threshold the lower value of 60 with a value of 73.16

May 22 16:37:47 warning monpd[13458]: 01540001:4: AVR Alert alert2: profile /Common/<Analytics> - pool-member<pool memberip:portnumber> exceeding the configured threshold the lower value of 60 with a value of 71.87

May 22 16:46:27 warning monpd[13458]: 01540001:4: AVR Alert alert2: profile /Common/Analytics1 - pool-member <pool memberip:portnumber> dropping below the configured threshold the lower value of 60 with a value of 0.00

May 22 16:47:28 warning monpd[13458]: 01540001:4: AVR Alert alert2: profile /Common/Analytics1 - pool-member <pool memberip:portnumber> dropping below the configured threshold the lower value of 60 with a value of 0.00

Environment

  • BIG-IP LTM
  • AVR

Cause

This is by design.

Recommended Actions

No action is required. AVR triggered alerts when threshold is not breached can be considered as a clear alert showing that the delay is now clear. 

Additional Information

None
