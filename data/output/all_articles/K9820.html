K9820: The BIG-IP ASM may fail to send some log requests to the remote logging server

Known Issue

This is the result of a known issue. A logging profile determines which requests the BIG-IP ASM system logs for a web application. When using a TCP remote logging profile, the BIG-IP ASM maintains a connection with the remote logging server. By default, after a 5-minute window during which the web application receives no requests that generate logging, the BIG-IP ASM times out the TCP connection to the logging server.

When the web application receives requests that generate logging following a 5-minute timeout period, the first several log requests may not be sent to the remote logging server. After re-establishing the connection to the logging server, the BIG-IP ASM resumes normal logging.

When this issue occurs, an error message is logged to the /var/log/asm file that appears similar to the following example:

ASM configuration error: event code L877 Failed to write to remote logger account: 0

F5 Product Development tracked this issue as ID222093 (formerly CR112391) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes on systems with a logical volume management (LVM) disk-formatting scheme, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about installing version 10.x hotfixes on systems with a partitioned disk-formatting scheme, refer to K9819: Installing a BIG-IP version 10.x hotfix on a partitioned system.

Workaround

If the remote logging server supports the UDP protocol, you may be able to work around this issue by changing the protocol for the logging profile to UDP. To change the protocol for the logging profile to UDP, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Web Applications.
  4. Click the relevant Web Application name.
  5. From the Application Security tab, click Options.
  6. Click the Logging Profiles tab.
  7. Click the relevant logging profile name.
  8. Select UDP from the Protocol drop-down menu.
  9. Click Update.
  10. From the Application Security tab, click Policy.
  11. Click Apply Policy.

Important: Implementing this workaround may result in loss of remote logging capabilities available only when using TCP, such as extended message lengths.
