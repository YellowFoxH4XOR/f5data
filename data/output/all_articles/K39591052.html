Description

Why the below warning message is logged in /var/log/messages?

warning kernel: [*.*]: systemd-journald[pid]: Failed to read ACL on /var/log/journal/<directory_name>/user-<number>.journal, ignoring: Operation not supported
 

Environment

  • BIG-IP
  • v14.* and avobe
  • Upgraded from 13.* or before 

Cause

Bug ID 766321
 

Recommended Actions

At this moment, this is only cosmetic message, you can simply ignore.
If you still want to stop logging this, then clean install after taking UCS backup. Follow to restore the UCS archive: K13132: Backing up and restoring BIG-IP configuration files with a UCS archive


If you want to surpress the message with possible unknown sideeffects, follow the procedure below
  1. check the /var/log is mapped to which filesystem
    df /var/log
    Filesystem                      1K-blocks   Used Available Use% Mounted on
    /dev/mapper/vg--db--vda-dat.log   2958224 362672   2425568  14% /var/log
     
  2. then run
    tune2fs -o user_xattr,acl <Filesystem_name>

    e.g. with above example
    tune2fs -o user_xattr,acl /dev/mapper/vg--db--sda-dat.log

    NOTE: This will remove the two file system options from the list of default mount options. Next time the system is rebooted it will be mounted without these options and the "Failed to read ACL" messages will come back.
     

Additional Information

None.
