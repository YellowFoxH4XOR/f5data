Security Advisory Description

ICMP information such as (1) netmask and (2) timestamp is allowed from arbitrary hosts. (CVE-1999-0524)

Impact

This vulnerability allows unauthorized disclosure of information.

Security Advisory Status

To determine if your release is known to be vulnerable, the components or features that are affected by the vulnerability, and for information about releases or hotfixes that address the vulnerability, refer to the following table.

Important: This vulnerability is caused by a basic functionality of the ICMP protocol. F5 does not consider this vulnerability to pose a significant risk and believes a viable mitigation is available. F5 has no plans to address this vulnerability. There will be no further updates to this article, unless new information is discovered.

Security Advisory Recommended Actions

BIG-IP

To mitigate this vulnerability on BIG-IP version 14.1.x and later, you can use packet filtering on the BIG-IP system to drop ICMP type 13 (timestamp) requests on both the BIG-IP management interface and the Traffic Management Microkernel (TMM) Self IP addresses. To do so, perform the following procedures:

Note: ICMP type 17 (netmask) requests are deprecated by RFC 6918 and these requests are dropped by default in BIG-IP versions 14.1.x and later. This link takes you to a resource outside of MyF5. The third party could remove the document without our knowledge.

Important: Packet filters can provide protection against known types of traffic but F5 recommends that you avoid exposing your management interface to the internet, either directly or through an intermediate NAT device or firewall, when there are no operational requirements for such access.

  • Drop ICMP type 13 (timestamp) requests for TMM self IP addresses
  • Drop ICMP type 13 (timestamp) requests for the BIG-IP management IP address

Drop ICMP type 13 (timestamp) requests for TMM self IP addresses

Impact of action: Incorrect packet filter configuration can prevent you from accessing the BIG-IP system. F5 recommends that you perform this procedure during a maintenance window and that you have a current backup of your BIG-IP configuration.

  1. Log in to the Configuration utility as the administrative user.
  2. Go to Network > Packet Filters > General.
  3. From the drop-down menu next to Packet Filtering, select Enabled, then select Update.
  4. Go to the Rules tab and select Create.
  5. Enter a name for the rule, for example, drop_icmp_timestamp.
  6. Select the rule order from the drop-down menu next to Order.

    Note: If this is the first packet filter that has been created, the only option for Order will be First.

  7. In the Action drop-down menu, select Discard.
  8. In the Filter Expression Method drop-down menu, select Enter Expression Text.
  9. In the field next to Filter Expression, enter the following text:

    icmp && icmp[0] = 13

  10. After configuring any additional parameters, select Finished.

Drop ICMP type 13 (timestamp) requests for the BIG-IP management IP address

Depending on your BIG-IP version, you may need to perform an additional step in order to drop ICMP type 13 (timestamp) requests on the management interface. To determine if your version requires this extra step, refer to the Fixed In versions in Bug ID 760355: Firewall rule to block ICMP/DHCP from 'required' to 'default'.

Impact of action: Incorrect packet filter configuration can prevent you from accessing the BIG-IP system. F5 recommends that you perform this procedure during a maintenance window and that you have a current backup of your BIG-IP configuration.

  1. If your BIG-IP version is listed in the Fixed In section of Bug ID 760355, skip this step and proceed to step 3.

    Log in to the Advanced Shell (bash) of the BIG-IP system as the root user.

  2. Move the iptables ICMP rule from the f5required chain to the f5default chain, using the following commands:

    /sbin/iptables -D f5required -j ACCEPT -p icmp
    /sbin/iptables -A f5default -j ACCEPT -p icmp
    iptables-save > /etc/sysconfig/iptables

  3. Log in to the Configuration utility as the administrative user.
  4. Go to System > Platform, then select the Security tab.
  5. To create a new rule, select Add.
  6. Enter a name for the new rule, for example, drop_icmp_timestamp.
  7. Select the Auto Generate UUID checkbox.
  8. From the Protocol drop-down menu, select ICMP.
  9. Next to ICMP Message, from the Type drop-down menu, select Timestamp (13).
  10. From the Action drop-down menu, select Drop.
  11. After configuring any additional parameters, select Finished.

All other products

To mitigate this vulnerability for all other products, use an external packet filtering device such as the BIG-IP Advanced Firewall Manager (AFM) to filter out ICMP type 13 requests from unknown or untrusted hosts.
