Known Issue

This is the result of a known issue. The bigpipe tmm show all command can be used to display statistics about the Traffic Management Microkernel (TMM) daemon.

When you run the bigpipe tmm show all command on a VIPRION system, the BIG-IP system only reports the output for TMM 1.0 (TMM id 0), and does not show the specific ID numbers for all TMM instances. For example, the following bigpipe tmm show all command output displays only TMM 1.0 (TMM id 0) instances:

TMM 1.0 process 0 on CPU 0 TMM id 0 Total TMMs = 0
| client (cur, max, limit, tot) = (2, 6, 0, 35784)
| client (pkts,bits) in = (221354, 348.7M), out = (4, 3136)
| server (cur, max, limit, tot) = (2, 6, 0, 35784)
| server (pkts,bits) in = (221354, 348.7M), out = (4, 3136)
| TMM cycles (total, idle, sleep) = (12.63P, 27.85T, 12.56P)
| denials (maint, addr full, serv full) = (0, 0, 0)
| (no serv, no listen, no mem, no lic) = (0, 14009, 0, 0)
| memory (total, used) = (6.016G, 115.8M)
| packets (drop, err in, err out) = (0, 0, 0)
| HTTP requests = 0
| Conn re-directed = 0

Note: This is a display issue only; other TMM instances function correctly.

F5 Product Development tracked this issue as CR102474 and it was fixed in BIG-IP 10.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.
