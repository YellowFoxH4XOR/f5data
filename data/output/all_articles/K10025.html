Overview of the hotfix functionality

F5 periodically releases cumulative hotfixes that contain fixes for software defects that may need to be addressed between minor or maintenance BIG-IP software releases. You can download cumulative hotfixes from the F5 Downloads site.

Note: This article does not address Engineering hotfixes, which are provided only by way of a support case. For information about managing Engineering hotfixes, and whether a specific Engineering hotfix will be included in the next cumulative hotfix, contact F5 Support and reference the appropriate case number.

Hotfix management has changed significantly in BIG-IP 10.x. The functionality provided for managing hotfixes includes the following:

  • Hotfixes are managed using either the Configuration utility or the bigpipe software command

    BIG-IP 10.x hotfix management is performed using the Software Management screen in the Configuration utility or the bigpipe software command. Using the Software Management screen or the bigpipe software command allows you to import hotfix files to an image library on the BIG-IP system, where the hotfixes can be installed on an inactive boot location, when needed.

  • Hotfixes must be managed on each member of a redundant pair

    A ConfigSync operation does not synchronize a hotfix to a redundant system.

  • Hotfixes are installed differently depending on the disk-formatting scheme

    BIG-IP 10.x systems can use only the LVM disk-formatting scheme. However, BIG-IP systems containing both 9.x and 10.x installations (and 10.x only systems that followed that upgrade path) use a partitioned disk-formatting scheme. The Installing a hotfix section, following, lists articles containing detailed installation instructions for each combination of version and formatting scheme.

  • Hotfixes are installed to an inactive boot location

    In most cases, when installing a BIG-IP 10.x hotfix, you must run the hotfix installation from a boot location (install volume) other than the target boot location. Refer to the Installing a hotfix section for detailed installation instructions. 

    This behavior allows you to prepare an inactive boot location in advance by installing the necessary software image and hotfix, and then boot to the new location when you are ready to run the configuration. For example, if the BIG-IP system is running 10.0.1 HF1 on the active boot location (for example, HD1.1) and you want to install HF2, prepare an inactive boot location for the installation (for example, HD1.2). If the inactive boot location is running an older software version, such as 10.0.0, you must first install the base version 10.0.1 ISO image to the inactive boot location, and then install HF2 (if the inactive boot location is already running 10.0.1, you can install HF2). The configuration and license from the current boot location is copied to the target install location. During the maintenance window, you can then designate HD1.2 as the active boot location and boot the system to it. If you need to revert to the previous hotfix version, you can boot to the formerly-active boot location containing the hotfix (HD1.1 in this example).

  • Hotfixes are cumulative

    Every time a cumulative hotfix is produced, all packages from previously generated hotfixes for that product on that branch are automatically included in the cumulative hotfix. The most recently created hotfix for each product contains all previously issued hotfixes for that product.

  • Hotfixes have a version number

    Each cumulative hotfix has a version number. You can use the Software Management screen in the Configuration utility or the bigpipe software command to display the version of the cumulative hotfix installed on the system.

  • Hotfixes uninstall packages are no longer available

    In BIG-IP 10.x, you no longer use a hotfix uninstall package to remove a hotfix installation. Instead, you can boot to a slot location containing a previous hotfix installation, or use the Configuration utility or the bigpipe software command to change the revision level of the 10.x image location to a higher or lower revision.

Backing up existing BIG-IP configuration data

Before you install a hotfix, you should save your BIG-IP configuration data. Backing up your configuration prevents loss of data if the hotfix installation is not successful.

You can collect and archive the BIG-IP configuration files by entering the following command from the BIG-IP system command line:

bigpipe config save /config.ucs

Determining the appropriate hotfix for a corresponding BIG-IP release

To determine the appropriate hotfix to install on the system, you should review the latest available hotfixes for corresponding BIG-IP releases by referring to K9502: BIG-IP hotfix matrix.

Downloading the hotfix files

After you save the existing configuration, download the hotfix files from the F5 Downloads site to your local workstation or network share. The following three types of files exist for each hotfix:

  • ISO files

    BIG-IP 10.x hotfix files are now ISO archive files. For example, the following file is the ISO installation file for Hotfix-BIGIP-10.0.0-5514.0-HF2:

    Hotfix-BIGIP-10.0.0-5514.0-HF2.iso

  • MD5 files

    The ISO installation file has a corresponding MD5 file for checking the integrity of the ISO file. For example, the following is the MD5 file for the Hotfix-BIGIP-10.0.0-5514.0-HF2 installation ISO file:

    Hotfix-BIGIP-10.0.0-5514.0-HF2.iso.md5

  • Hotfix release note / readme files

    The ISO installation file has a corresponding Hotfix release note. You should always read the Hotfix release note before you install a hotfix. This file contains important notes about each particular hotfix. For example, the following is the readme file for Hotfix-BIGIP-10.0.0-5514.0-HF2:

    HotfixNotes-BIGIP-10.0.0-5514.0-HF2.htm

Note: For information about downloading files from the F5 Downloads site, refer to K167: Downloading software and firmware from F5.

Download the following files for the hotfix you want to install to your local workstation:

  • Download the hotfix installation ISO file:

    Hotfix-BIGIP-10.x.x-HFyy.iso

    This file is the hotfix installation ISO file. The 10.x.x part of the file name denotes the software version. The HFyy part of the file is the cumulative hotfix number.
  • Download the corresponding MD5 files:

    Hotfix-BIGIP-10.x.x-HF2.yy.md5

    This file is the hotfix installation MD5 file. The 10.x.x part of the file name denotes the software version. The HFyy part of the file is the cumulative hotfix number.

Importing the hotfix files to the BIG-IP system

To import the hotfix files using the Software Management interfaces or an alternate method, use one of the following methods:

Using the Software Management interface to import the hotfix files to the BIG-IP system

Once the hotfix and MD5 files are downloaded to your local workstation, you can use the Software Management interface in the Configuration utility to import the files to the BIG-IP system. The Software Management interface automatically installs the hotfix file to the image library (the /shared/images/ directory) on the BIG-IP system. The hotfix can then be installed on an inactive boot location when needed.

To use the Software Management interface to import the hotfix files to the BIG-IP system, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to System > Software Management.
  3. Select the Hotfix List tab.
  4. Select Import.
  5. Select Browse.
  6. Go to the location on your local drive where the hotfix ISO file resides.
  7. Highlight the hotfix ISO file and select Import.

Note: For BIG-IP 10.2.2, 10.2.3, or 10.2.4 systems, F5 recommends that you use an alternate method to import the hotfix files to the BIG-IP system. For more details, refer to K13587: Importing a BIG-IP product or hotfix ISO image file may fail.

Using an alternate method to import the hotfix files to the BIG-IP system

If you use an alternate method, such as SCP, to copy the hotfix files to the BIG-IP system, you should make sure that the files are installed to the /shared/images/ directory.

Note: You can use the bigpipe software command to add hotfix files to the image library. For example, the following command moves the Hotfix-BIGIP-10.0.0-5514.0-HF2.iso hotfix file from the /root/ file to the /shared/images/ directory:

bigpipe software image /root/Hotfix-BIGIP-10.0.0-5514.0-HF2.iso add

Verifying the MD5 checksum of the hotfix files

After the hotfix files are installed on the BIG-IP system, and before you perform the installation, F5 recommends that you test the integrity of the ISO file to ensure file quality. To run the test, enter the following command, where <Hotfix-BIG-IP-10.x.x-HFyy.iso> is the name of the upgrade file you have downloaded:

md5sum Hotfix-BIG-IP-10.x.x-HFyy.iso
cat Hotfix-BIG-IP-10.x.x-HFyy.iso.md5

The two MD5 hash values should be identical. Ensure that the output matches the contents of the corresponding MD5 file. If the output matches, install the file. If the output does not match, download the file again and repeat the process.

Note: The MD5 checksum hash reported by the md5sum command will differ from the hash reported for the ISO file by the Configuration utility under Software Management. This behavior occurs because the hash reported when you run the md5sum command is the checksum for the ISO file itself, and is used to verify the integrity of the ISO file after downloading it from the F5 Downloads site. The hash reported by the Configuration utility under Software Management is the iframeded MD5 checksum contained in the ISO file.

Verifying the hotfix installation

After installing a hotfix, you can verify the installation using one of the following methods:

  • Using the Configuration utility
  • Using the switchboot command
  • Using the tmsh utility

Using the Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > Software Management.
  3. Note the following categories for the Installed Images section.
  • Install Status - Display indicates whether the software installation process is complete or in progress.
  • Version - Displays the F5 product version number related to the software image.
  • Build - Displays the F5 build number related to the installed software image.

    Note: To determine the software hotfix version, note the numeric value of the build and compare this to the build value of the downloaded hotfix image.
    In the example "Build 864.0" shares the same build number of the hotfix image Hotfix-BIGIP-10.2.4-864.0-HF11.iso.

  • Installed Status - Displays the status of the installation operation of the associated image. During in-progress installation operations, this column displays a progress bar with the percent complete for the installation in progress. Next to the progress bar is a "Details..." link which links to a page with more information about the installation that is in progress. If an installation fails, the system posts a Failed warning and a Troubleshooting link, which links to a page with details about the failure.

Using the switchboot command

  1. Log in to the command line of the BIG-IP device.
  2. Enter the following command:

    switchboot -l

    Example output:

    Current boot image:
        HD1.2 - title BIG-IP 10.2.4 Build 577.0
    Default boot image:
        HD1.2 - title BIG-IP 10.2.4 Build 577.0
    Available boot image(s):
        HD1.1 - title BIG-IP 10.2.4 Build 864.0
        HD1.2 - title BIG-IP 10.2.4 Build 577.0

    Note: To determine the software hotfix version, note the numeric value of the build and compare this to the build value of the downloaded hotfix image.
    In the example "Build 864.0" shares the same build number of the hotfix image Hotfix-BIGIP-10.2.4-864.0-HF11.iso.

  3. To exit the command line shell, enter the following command:

    exit

Using the tmsh utility

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  2. Enter the following command:

    show /sys software

    Example output:

    Sys::Software Status
    Volume  Product  Version  Build  Active    Status
    -------------------------------------------------
    HD1.1    BIG-IP   10.2.4  864.0      no  complete
    HD1.2    BIG-IP   10.2.4  577.0     yes  complete

    Note: To determine the software hotfix version, note the numeric value of the build and compare this to the build value of the downloaded hotfix image.
    In the example, "Build 864.0" shares the same build number of the hotfix image Hotfix-BIGIP-10.2.4-864.0-HF11.iso.

  3. To exit the tmsh utility enter the following command:

    quit

Reverting to a previous hotfix version

In BIG-IP 10.x, you no longer use a hotfix uninstall package to remove a hotfix installation. Instead, if you need to revert to the previous hotfix version, you can boot to the formerly active boot location containing the previous hotfix installation. For example, if you installed BIG-IP 10.2.2 HF3 on an inactive boot location from a 10.2.2 HF1 boot location and you want to revert from HF3 to HF1, you would boot back to the 10.2.2 HF1 boot location. To do so using the Configuration utility, browse to System > Software > Boot Locations and activate the desired boot location.
