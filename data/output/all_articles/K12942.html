Topic

The VIPRION platform has specific requirements for running the EUD, as documented in the End-User Diagnostics release notes and EUD Field Testing VIPRION Hardware guide. If you fail to observe these requirements, the Internal Packet Path test may generate false positive results. This may occur under the following conditions:

  • You run the EUD on one blade in the chassis while other blades are processing traffic
  • You fail to disconnect all network cables from the system prior to running the EUD
  • You run simultaneous instances of the EUD utility on different blades in a VIPRION chassis

For example, if you have a VIPRION chassis containing two blades and run the EUD on blade 1 while blade 2 is processing production traffic, the Internal Packet Path Test may fail and generate false positive messages that appear similar to the following examples:

Test Complete: Testing Mezzanine to Primary Fabric: FAILED
Test Complete: Internal Packet Path Test: FAILED
Test Complete: Internal Packet Path Test: FAILED
Overall Test Result: FAILED

Note: The EUD Internal Packet Path Test verifies the status of the Ethernet interfaces in the system. This test sends payload packets from the mainboard Ethernet interface back to the mezzanine Ethernet interface. After the test completes successfully, you see the following message:

Test Complete: Internal Packet Path Test: PASSED
