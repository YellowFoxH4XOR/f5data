Description

In BIG-IP Application Security Manager (ASM), the Event Log may display "Applied Blocking Settings: Learn Alarm Block" for the violation:

Bad multipart parameters parsing / Closing multipart boundary is not found

even when this violation is configured with Block disabled in the security policy.

This behavior may suggest that the request was blocked due to this violation. However, the blocking action is typically triggered by a different violation in the same request, such as:

Unparsable request content / Request Content-Length differs from actual request body length

The "Applied Blocking Settings" field reflects the enforcement applied to the entire request, not to individual violations.

Environment

  • BIG-IP ASM, version 17
  • Scenario characteristics:
    • HTTP request includes:
    • Content-Type: multipart/form-data
    • Mismatch between declared Content-Length and actual request body length
    • Missing or incomplete multipart boundary
  • Violation configuration:
    • Unparsable request content → Block enabled
    • Bad multipart parameters parsing → Block disabled

Cause

The "Applied Blocking Settings" field in the Event Log represents the request-level enforcement mode. When multiple violations are detected:

  • If any violation is configured with Block and triggers enforcement,
  • The request is blocked, and
  • The Event Log displays "Learn Alarm Block" for all violations associated with that request

As a result, violations that are not configured to block may still appear with "Learn Alarm Block" in the log. This behavior is specific to violations within the HTTP Protocol Compliance Failed category.

 

Answer/Recommended Actions

  • Interpret "Applied Blocking Settings" as a request-level indicator, not a per-violation result
  • Review all violations listed in the event details to identify the violation responsible for the block
  • Verify which violations have the Block setting enabled (for example, Unparsable request content)
  • Do not assume that a violation displayed with "Learn Alarm Block" caused the blocking action if its Block setting is disabled

Additional Information

  • This behavior applies to violations under the HTTP Protocol Compliance Failed category
  • Other violation categories (for example, Illegal meta character in header) typically reflect their individual enforcement settings in the Event Log
  • The Event Log entry indicates the overall enforcement applied to the request, not the specific violation that triggered the block
