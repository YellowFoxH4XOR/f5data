Description

After upgrading BIG-IP, a client can not see all of webtop menu.

This does not have all account.

 

Environment

  • BIG-IP APM
  • After upgrade
  • Webtop menu
  • Blowser

 

Cause

  • Browser cache.

 

Recommended Actions

Please remove browser's cache.

Select

  • Time range: All time.

Check in

  • Cookies and other site data
  • Cached images and files


And try to log in again.

 

Additional Information

After removing browser cache, still having the issue, then please gather following, and escalate the case to F5 Support.

1. Enable Debug Level Logging for the Access Policy:

  1. Navigate to: Access → Overview → Event Logs → Settings.
  2. Create a new logging provider, check the Enable Access System Logs box.
  3. In the Access System Logs tab, set the logging level for Access Policy to "Debug".
  4. In the Access Profiles tab, select the affected profile (move to the left, and remove current log profile: move to right)

 

2. tcpdump on the Active unit CLI after changing db value to get proper information.

tmsh modify sys db tm.rstcause.pkt value enable
tmsh modify sys db tm.rstcause.log value enable
tmsh modify sys db tcpdump.sslprovider value enable
tmsh modify sys db log.ssl.level value Debug

 

then start tcpdump

tcpdump -s0 -ni 0.0:nnnp -w /var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)".pcap --f5 ssl -vv host <client_public_IP>

NOTE: Replace <client_public_IP> with the public IP address of the client machine that is observed by BIG-IP during session establishment.

 

3. start developer tool on chrome and type URI and login, and if it is possible save video for the desktop

Once issue occurs, save the har file

 

4. Get session ID for this client.

 

5. terminate tcpdump (press [Ctrl]+[C] )

 

6. then take qkview

qkview -s0 -f /var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)".qkview

 

7. just in case tarball for /var/log

tar -czpf /var/tmp/"$HOSTNAME"_logfiles.tar.gz /var/log/*

 

8. revert back the db value

tmsh modify sys db tm.rstcause.pkt value disable
tmsh modify sys db tm.rstcause.log value disable
tmsh modify sys db tcpdump.sslprovider value disable
tmsh modify sys db log.ssl.level value Warning

 

9. We will need to have the qkview from the latest

 

Below data should be uploaded to the support case.

  • tcpdump took when issue is occuring.
  • session ID when issue is occuring
  • developper tool file (har file) took when issue is occuring.
  • video took when it is not working (if you can record)
  • qkview from upgraded version
  • tar ball of /var/log in upgraded version
  • Optional: qkview or UCS file from old version
