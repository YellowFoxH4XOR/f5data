Topic

I am receiving corrupt compact flash drive error messages on the console and in the /var/log/messages file. Following is an example of the type of error message I am receiving:
Apr 12 15:55:41 bip2 kernel: wd0g: hard error reading fsbn 34624 of 34624-34655 
 (wd0 bn 449344; cn 624 tn 1 sn 16) status 51 error 4
 Apr 12 15:55:41 bip2 kernel: wd0: resetting controller

To repair a failing BIG-IP 5000, BIG-IP 2000, or BIG-IP Link Controller compact flash drive, use the cfrepair utility that is included on the following versions of BIG-IP.

Note: If you are running a version of BIG-IP that includes the cfrepair utility and you are not upgrading to a more recent PTF, skip directly to the section titled Running the cfrepair utility without upgrading.

There are two ways to run the cfrepair utility:

  • Install the BIG-IP upgrade from a network boot installation and initiate the cfrepair utility.

  • Run the recovery utility from the command-line if you are currently running a version of BIG-IP that includes the cfrepair utility.

Note: BIG-IP versions 4.5 through 4.6.4 do not contain a useable version of cfrepair on the CD; you will need to use the Single user mode instructions to utilize the cfrepair utility.

Network boot installation

A network boot installation allows you to perform a full installation or upgrade, or run the repair utility, from a remote host in the event that the compact flash drive is unbootable or if you are unable to install the upgrade due to disk problems. This procedure will not alter or damage the remote host. The server is used to temporarily provide an image to the BIG-IP unit, nothing is written to the hard drive. For specific instructions, refer to K1494: Reinstalling BIG-IP or 3-DNS software from a network boot server.

If you are not going to install the upgrade, but want to repair the compact flash drive, type Control-c to get a standard command prompt, and follow the steps in the section titled Running the cfrepair utility without upgrading.

Running the cfrepair utility after upgrading

After you perform an upgrade, perform the following steps to run the cfrepair utility.

Note: There are just over 500,000 sectors that are scanned on the compact flash drive. Running the cfrepair utility takes approximately 40 minutes.

  1. From the BIG-IP, type the following command:

    cd /cdrom/downloads/cfrepair

  2. Run the cfrepair utility by typing the following command:

    ./cfrepair wd0

  3. When the cfrepair utility is complete, type the following command:

    umount /mnt

  4. Run a file system consistency check for /dev/wd0a and /dev/wd0g by typing the following commands:

    fsck -y /dev/wd0a
    fsck -y /dev/wd0g

  5. Type the following commands to mount the drives:

    mount /dev/wd0a /mnt
    mount /dev/wd0g /mnt/var

  6. Run the im utility to verify the installed files, by typing the following command:

    im -V -x -p -r /

Reapplying missing or broken packages

If you locate missing or broken packages, use the following steps to reapply these packages:

  1. Type the following command:

    cd /cdrom

  2. Type the command appropriate to the version of BIG-IP you are running:

    • If you are installing a 4.2 upgrade from CD-ROM, type: cd BIGIP42
    • If you are installing a 4.1.1 upgrade from CD-ROM, type: cd BIGIP411
    • If you are installing a 4.5 upgrade from CD-ROM, type: cd BIGIP45

  3. Type the following command to reapply a missing or broken package, where <package_name.im> is the missing or broken package:

    im -force -r /mnt <package_name.im>

    Repeat this command for each broken or missing package.

  4. Type the following commands to unmount the drives:

    umount /mnt/var
    umount /mnt

  5. Reboot BIG-IP.

Restoring configuration

To restore your previous configuration after upgrading and running the cfrepair utility, perform the following steps:

  1. Reinstall the UCS file. If your file is not stored locally, copy the file to the /usr/local/ucs/ directory.

  2. Restore the configuration by typing the following command, where <config.ucs> is the name of the saved the configuration file:

    bp config install <config.ucs>

Running the cfrepair utility without upgrading

If you are currently running a version of BIG-IP that includes the cfrepair utility, or if you are able to boot from the BIG-IP, perform the following steps to run the cfrepair utility from the command-line:

Note: There are over 500,000 sectors that are scanned on the compact flash drive. Running the cfrepair utility takes approximately 40 minutes.

  1. Boot BIG-IP.

  2. At the 4 3 2 1 countdown, press the Enter key to interrupt the boot.

  3. Boot to single-user mode by typing the following command at the boot prompt:

    bsd -s

  4. Press the Enter key when prompted for the pathname for shell.

  5. Mount the disk partitions by typing the following command:

    mount -a

  6. Type the following command:

    cd /sbin/hwtest

  7. Run the cfrepair utility by typing the following command:

    ./cfrepair wd0

  8. Run the im utility to verify the installed files, by typing the following command:

    im -V -x -p -r / 

Reapplying missing or broken packages

If you have located any missing or broken packages use the following steps to reapply the packages:

  1. Perform the steps in the K1494: Reinstalling BIG-IP or 3-DNS software from a network boot server up to step 3. Stop when you see the following prompt:

    BIG-IP Install
     Local Boot
     DOS

  2. Do not perform an upgrade, but press Control-c at the menu to get a command prompt.

  3. After you have completed the Network boot installation instructions and are booted from the remote PXE server, type the following command:

    mount /dev/wd0g /mnt/var

  4. Type the following command:

    cd /cdrom

  5. Type the command appropriate to the version of BIG-IP you are running:
    • If you are installing a 4.2 upgrade from CD-ROM, type: cd BIGIP42
    • If you are installing a 4.1.1 upgrade from CD-ROM, type: cd BIGIP411
    • If you are installing a 4.5 upgrade from CD-ROM, type: cd BIGIP45

  6. Type the following command to reapply a missing or broken package, where <package_name.im> is the missing or broken package:

    im -force -r /mnt <package_name.im>

    Repeat this command for each broken or missing package.

  7. Type the following commands to unmount the drives:

    umount /mnt/var
    umount /mnt

  8. Reboot BIG-IP.

Restoring configuration

To restore your previous configuration after upgrading and running the cfrepair utility, perform the following steps:

  1. Reinstall the UCS file. If your file is not stored locally, copy the file to the /usr/local/ucs/ directory.

  2. Restore the configuration by typing the following command, where <config.ucs> is the name of the saved the configuration file:

    bp config install <config.ucs>
