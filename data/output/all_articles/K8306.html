Topic

Beginning in BIG-IP 9.4.4, you can configure the BIG-IP system to send a maximum syslog message size of 64,000 bytes using an iRule. Previous versions of BIG-IP limit the maximum message size sent using an iRule to 1,024 bytes.

F5 Product Development tracked this Requet for Enhancement as ID 296613 (formerly CR73440) and it was added to BIG-IP 9.4.4. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, and WebAccelerator release notes.

This enhancement was added in Hotfix-BIG-IP-9.4.3-HF4, issued for BIG-IP 9.4.3. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Configuring the BIG-IP system to support larger message sizes sent to remote syslog servers

Important: The increased size limits apply only to messages sent to remote syslog server using an iRule and egressing a TMM interface. Messages sent to a remote syslog server directly from syslog will continue to be limited to 1024 bytes.

After upgrading, you can enable the syslog enhancement. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. To allow the BIG-IP system to send larger message sizes to remote syslog servers, modify the following BigDB key:

    bigpipe db Tmm.MaxRemoteLogLength <size>

    Note: The default message size is 1,024 bytes, and the value can range from 1,024 bytes to 65,507 bytes. Changes take effect immediately and will persist through restarts and reboots of the BIG-IP System.

  3. Configure an iRule that redirects messages to a remote syslog server.

    For example, use the following syntax, where <ip_addr> is the IP address of the remote syslog server, and <message> is the intended message:

    when HTTP_REQUEST {
       log <ip_addr> local0. <message>
    }

    Note: You must include the log facility in the iRule. If the log facility is left out, the iRule parser will interpret the IP address as the log facility and produce an error.
