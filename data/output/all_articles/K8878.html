Known Issue

This is the result of a known issue. The bigd process incorrectly bases ICMP monitor timeouts on previous ping time instead of using the next ping that falls within the monitor's timeout limit.

To view the default values of a 5 second interval and a 16 second timeout, refer to the following tables.

BIG-IP 9.0.3 through 9.4.4

To view the default values of a 5 second interval and a 16 second timeout, refer to the following table:

Time in SecondsDefault values of a 5 second interval and a 16 second timeout
0 secondsSends a ping to a node

Note: The initial ping is sent to the node when the ICMP monitor is associated with the node. This initial ICMP request is not used as part of the monitoring. It is only used to establish the nodes' entry in the monitor table.

0.1 secondsThe node responds
5 secondsSends a ping to a node. The bigd process begins the ICMP monitor check and issues three additional ICMP requests at 5 second intervals within the 16 second timeout limit.
10 secondsSends a ping to a node
15 secondsSends a ping to a node
20 secondsSends a ping to a node
21 secondsThe node is marked down correctly as three checks occurred with no response


BIG-IP 9.4.5, 9.6, and 9.6.1

To view the default values of a 5 second interval and a 16 second timeout, refer to the following table:

Time in secondsDefault values of a 5 second interval and a 16 second timeout
0 secondsSends a ping to a node

Note: The initial ping is sent to the node when the ICMP monitor is associated with the node. This initial ICMP request is incorrectly used as part of the monitoring, rather than the desired behavior to use the next ICMP request at 5 seconds.

0.1 secondsThe node responds
5 secondsSends a ping to a node
10 secondsSends a ping to a node
15 secondsSends a ping to a node
16 secondsThe node is marked down, but is based on the initial ICMP check issued at 0 seconds, instead of using the ICMP check that started at 5 seconds

The desired behavior is for the bigd process to use the next ping or ICMP check that is contained within the timeout interval specified. This behavior allows four checks to occur, along with the initial monitor ping, followed by three additional pings.

F5 Product Development tracked this issue as CR100734 and it was fixed in BIG-IP 9.4.6 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, or WebAccelerator Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP 9.4.5, and in Hotfix-BIG-IP-9.6.1-HF2, issued for BIG-IP 9.6.1. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.
