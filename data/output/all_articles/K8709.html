K8709: An SSL resumed session can stall when the SSL handshake record packet contains application data

Known Issue

This is the result of a known issue. When a Secure Sockets Layer (SSL) client resumes a session with a Client SSL virtual server, and sends a packet containing both an SSL handshake record and application data, the connection stalls. For example, if the client resumes an SSL session and sends application data in the same packet as the SSL Finished handshake record, the packet is not passed to the pool member by the BIG-IP system.

F5 Product Development tracked this issue as CR94408 and it was fixed in BIG-IP 9.4.5. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix BIGIP-9.3.1-HF3 issued for BIG-IP 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).

Workaround

You can work around this issue by changing the default SSL cipher for the Client SSL virtual server. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the SSL menu, select Client.
  4. Click the relevant Client SSL profile.

    Note: F5 recommends that you create a child profile based on the default parent profile, rather than edit the default profiles on the BIG-IP system.

  5. From the Configuration menu, select Advanced.
  6. Enter the following string in the Cipher field:

    ALL:!NATIVE

  7. Click Update.
