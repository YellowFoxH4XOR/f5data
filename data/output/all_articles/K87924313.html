K87924313: BIG-IQ Service Catalog Templates to be deprecated

Type
Knowledge
Published
2021-02-24
Updated
2023-02-21
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.0.0
Source
https://my.f5.com/manage/s/article/K87924313

Topic

The BIG-IQ Service Catalog Templates feature, while still functional in BIG-IQ 8.0.0, is planned to be deprecated in a future BIG-IQ release. F5 recommends that you use the F5 Application Services 3 (AS3) application template for deploying new applications.

Description

Both Service Catalog Templates and AS3 Templates are BIG-IQ-supported application templates that allow users to templatize and deploy applications through the BIG-IQ user interface. However, F5 is no longer enhancing the Service Catalog Templates as they are entering the deprecation phase.

Recommended Actions

New Application Services

When you create new application services with the BIG-IQ system, F5 recommends that you use the BIG-IQ AS3 templates. For information about deploying applications with BIG-IQ AS3, refer to the Using AS3 with BIG-IQ section of the AS3 User Guide on F5 CloudDocs.

Note: To onboard BIG-IP Virtual Editions (VE), F5 recommends that you use BIG-IQ Declarative Onboarding (DO). For more information, refer to the Using DO on BIG-IQ section of the F5 DO documentation on F5 CloudDocs.

Existing Application Services

If you have an existing application deployed with a BIG-IQ Service Catalog Template, you can convert it to a Legacy Application Service by deleting the Service Catalog Application Service on the BIG-IQ system using the AS3 force-delete API and create a Legacy Application Service with the existing objects on the target BIG-IP device. To do so, perform the following procedure:

Note: For information about the BIG-IQ legacy application service, refer to K02142132: Requirements and recommendations for creating a BIG-IQ application service with existing device configurations.

Impact of procedure: This procedure forces the delete of the service catalog application from only the BIG-IQ system. The related objects from the BIG-IP system are not removed. F5 recommends that you use this procedure only for certain recovery cases that require the forced removal of an application from only the BIG-IQ system.

  1. Log in to the BIG-IQ command line.
  2. Create the /home/admin/f5_remove_app_tags.py file using a text editor of your choice.

    For example, if you are using the vi text editor, enter the following command:

    vi /home/admin/f5_remove_app_tags.py

  3. Enter the following code in the text editor:

    #!/usr/bin/env python

    import requests
    import json
    import argparse

    class Cleanup:
        def get_arguments(self):
            parser = argparse.ArgumentParser(description='Remove Tags from Config tab in BIG-IQ.')
            parser.add_argument("--configSetName", type=str, help="The Application Service ConfigSet name.")

            return parser.parse_args()


        def delete_tags(self, configSetName):
            url = 'http://localhost:8100/shared/index/config?$filter=tags/value%20eq%20%27' + str(configSetName) + '%27+and+kind+ne+%27cm:global:tasks:snapshot-config:snapshottaskstate%27&$select=kind,selfLink&$orderby=kind'
            response = requests.get(url)
            jData = json.loads(response.content)

            if(response.ok):
                print("The response contains {0} properties".format(len(jData['items'])))
                print("\n")
                for item in jData['items']:
                    itemUri = item['selfLink'].replace('https://localhost/mgmt', 'http://localhost:8100')
                    itemResponse = requests.get(itemUri, auth=('admin', ''))
                    itemData = json.loads(itemResponse.content)
                    print(item['selfLink'])
                    tags = itemData['tags']
                    for i in xrange(len(tags)):
                        if tags[i]["name"] == "BIGIQ_configSetName":
                            tags.pop(i)
                            break

                    for i in xrange(len(tags)):
                        if tags[i]["name"] == "BIGIQ_templateResourceName":
                            tags.pop(i)
                            break

                    itemData['generation'] = 0
                    itemData['lastUpdateMicros'] = 0
                    data = {"tags":tags}
                    patchRequest = requests.patch(itemUri, data=json.dumps(data), auth=('admin', ''))
                    print(patchRequest)

            else:

                response.raise_for_status()


        def main(self):
            args = self.get_arguments()
            print(args)
            self.delete_tags(args.configSetName)

    if __name__ == "__main__":

        cleanup = Cleanup()
        cleanup.main()

  4. Save the changes and exit the editor.
  5. To force-delete the service catalog application service, use the following command syntax:

    restcurl -X POST /cm/global/tasks/force-delete -d '{"configSetName": "<application_name>"}'

    For example, the following command deletes the service catalog application named example_app:

    restcurl -X POST /cm/global/tasks/force-delete -d '{"configSetName": "example_app"}'

    Note: You can check the force-delete task status with the task ID in the API response using the following command syntax:

    restcurl /cm/global/tasks/force-delete/<task_ID>

  6. To remove the tags on the objects deployed with a service catalog template using the previously created python script, enter the following commands:

    cd /home/admin/
    chmod +x f5_remove_app_tags.py
    ./f5_remove_app_tags.py --configSetName <application_name>

    For example, the following commands remove the tags associated with the application named example_app:

    cd /home/admin/
    chmod +x f5_remove_app_tags.py
    ./f5_remove_app_tags.py --configSetName example_app

  7. Log in to the BIG-IQ user interface.
  8. Go to Devices > BIG-IP DEVICES.
  9. Select the box for the BIG-IP devices that were previously associated with the service catalog application.
  10. Select More.
  11. Select Re-discovery and Re-import.
  12. For Name, enter a name you would like to use for this task.
  13. Select Create.
  14. To create a legacy application service, go to Applications > APPLICATIONS.
  15. Select Create.
  16. For Application Name, enter a name you would like to use for the application.
  17. For Application Service Method, select Using Existing Device Configuration.
  18. For Application Service Name, enter a name you would like to use for the application service.
  19. For BIG-IP, select the device that was previously re-imported.
  20. For Application Service Type, select the appropriate service type.
  21. For Virtual Servers, select and move the virtual servers you would like to include in the application service.
  22. Select Create.
