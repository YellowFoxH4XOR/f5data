Topic

Beginning in BIG-IP APM 11.3.0, administrators can use the apm.xframeoptions database key to control how the BIG-IP APM system utilizes the X-Frame-Options HTTP response header.

Description

You can use the X-Frame-Options header in an HTTP response to indicate if a page in a <frame> or <iframe> should render in the browser. By inserting an X-Frame-Options header into an HTTP response, the BIG-IP APM system can defend against clickjacking attacks by instructing the browser not to render frames from other domains. The value in the header field directs the browser to render or not render the frame, based on the origin. 

You can define the value the BIG-IP APM system inserts in the X-Frame-Options header field using the following database key values:      

Database keyValuesDescription
apm.xframeoptionsallow_fromWhen this value is set, the value configured in the apm.xframeoptions.allowfrom database key determines other allowed origins for frames. The X-Frame-Options: ALLOW-FROM <URL> header is inserted into the response.  
denyThe X-Frame-Options: DENY header is inserted, instructing the browser not to render content in frames (default).
noneNo X-Frame-Options header is inserted
same_originThe X-Frame-Options: SAMEORIGIN header is inserted, instructing the browser to only render page content in frames from the same origin as the content.
apm.xframeoptions.allowfrom<origin>Used in conjunction with the apm.xframeoptions allow_from setting, this key specifies the URL to match when the origin is not the same as the content. The default setting is <null>.

The default value for the apm.xframeoptions database key is deny, which instructs the browser not to render pages in frames, even if they are from the same origin as the content. 

Recommendations

When configuring the apm.xframeoptions database keys, you should consider the following factors:

  • The BIG-IP APM system inserts the X-Frame-Options: DENY response header by default. Use caution when changing the apm.xframeoptions database key from its default setting to prevent exposure to clickjacking vulnerabilities.
  • Setting the apm.xframeoptions database key to none will prevent the BIG-IP APM system from inserting the X-Frame-Options header, possibly exposing clickjacking vulnerabilities.
  • You can set the apm.xframeoptions database key value to same_origin if you want to allow frames using the same origin as the base page. If you want to allow frames from other origins, you can configure the apm.xframeoptions database key in conjunction with the apm.xframeoptions.allowfrom database key. For example, to configure the BIG-IP APM system to allow frames from https://www.example.com, you could use the following commands:
     
    • tmsh modify /sys db apm.xframeoptions value allow_from
    • tmsh modify /sys db apm.xframeoptions.allowfrom value https://www.example.com
