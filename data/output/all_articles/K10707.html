Known Issue

This is the result of a known issue. The TM.MaxRejectRate db key regulates the number of TCP RSTs or ICMP unreachable packets that the BIG-IP system sends in response to incoming connections that cannot be matched with virtual server connections. When the TM.MaxRejectRate threshold has been exceeded, the BIG-IP system logs an error message.

Note: For more information, refer to K9259: Limiting the rate at which the BIG-IP system issues TCP RSTs or ICMP unreachable packets.

The TM.MaxRejectRate bigdb variable message counting is off by one, and begins counting at zero instead of one. As a result, when the TM.MaxRejectRate threshold is exceeded, the BIG-IP system correctly applies rate limiting to TCP RSTs or ICMP unreachable packets. However, the system does not generate an error message as expected.

For example, if the TM.MaxRejectRate bigdb variable is set to the default value of 250, and the threshold is exceeded for TCP, the BIG-IP system correctly stops sending TCP RST packets in response to unmatched packets. However, the system does not log the following error message until the count reaches 251:

tmm tmm[1609]: 011e0001:4: Limiting closed port RST response from 299 to 250 packets/sec

F5 Product Development is tracking this issue as ID 223783 (formerly CR131872).

Note: The limiting ICMP ping response error message does not honor the 1-second limit. For more information, refer to K10709: The 'limiting ICMP ping response' error message does not honor the 1-second limit.
