K000160695: "Fraudulent" or "Custom-coded" QSFP modules may result in QUALIFIED_MODE_MISMATCH on F5OS hardware.

Source

Description

Interface state shows "QUALIFIED_MODE_MISMATCH" and ports remain down when 40G QSFP+ optics are inserted into F5 rSeries platforms. The error appears in the output of show portgroups or system logs, accompanied by abnormal interface counter values. The portgroup mode is set to 40GbE and both ports in the pair are populated with optics.

Symptoms:

  • Interface state: optic-state QUALIFIED_MODE_MISMATCH
  • Interface operational status: DOWN
  • Abnormal interface counters (e.g., very large numbers or all zeros)
  • System log messages such as:
    • Optic inserted does not match portgroup mode configuration
    • media Unknown
  • Issue persists after reboot and after replacing optics

Environment

  • Product: F5OS (BIG-IP rSeries)
  • Version: 1.8.3
  • Platform: F5-BIG-IP rSeries
  • Portgroups configured for MODE_40GB
  • Both ports in the portgroup populated with optics
  • All front panel ports enabled
  • Unsupported QSFP module installed
    • portgroups portgroup 1
       state vendor-name      "F5 NETWORKS INC."             <------ "Fraudulent" or spoofed vendor name.
       state vendor-oui       44d5a5
       state vendor-partnum   "F5UPGQSFP+BDAO "           <----- This example show a non-genuine part number. The genuine part number would be F5UPGQSFP+BD (without the "AO")
       state vendor-revision  A1
       state vendor-serialnum "AN300PD9G686"                   <------This example show a non-genuine serial number. This is possibly an Arista Networks serial number
       state transmitter-technology "850 nm VCSEL"
       state media            Unknown
       state optic-state      QUALIFIED_MODE_MISMATCH

Cause

The root cause is the use of non-F5-qualified 40G QSFP+ optics that are not recognized as supported by the F5 rSeries platform. These modules may not be genuine F5 parts or may not be listed in the official F5 supported optics documentation. As a result, the system cannot bring the interface up and reports a mode mismatch, even if the portgroup mode is correctly set.

Some 3rd-party vendors false claim that their SFP/QSFP modules are compatible with F5 hardware. Unfortunately, we cannot support non-genuine parts.

Answer/Recommended Actions

  1. Verify Portgroup Mode and Optic Compatibility
    • Use the CLI command show portgroups and show running-config portgroups to confirm both the portgroup mode and the inserted optic type.
    • Ensure the portgroup mode matches the optic speed (e.g., MODE_40GB for 40G QSFP+).
  2. Check Supported Optics
    • Confirm the optic part number is listed in F5's supported optics documentation (see K6097: Specifications of the Fiber Gigabit Ethernet SFP, XFP, SFP+, QSFP+, and QSFP28 module ports on BIG-IP system platforms).
    • Supported 40G optics include F5-UPG-QSFP+BD (OPT-0043-01) and F5-UPG-QSFP28-SRBD.
  3. Replace Unsupported Optics
    • Remove any third-party or unlisted optics.
    • Install only F5-qualified and supported optics in both ports of the portgroup.
  4. Reboot if Necessary
    • After replacing optics and confirming portgroup mode, reboot the system to clear any stale interface states.
  5. Verify Interface Status
    • After reboot and optic replacement, use show portgroups and show interfaces to confirm:
      • optic-state is QUALIFIED
      • oper-status is UP
      • Interface counters are normal
  6. Additional Configuration Checks
    • Ensure all front panel ports are enabled, even if not in use.
    • Both ports in a portgroup pair (e.g., 1.0 & 2.0) must be configured identically and populated with matching, supported optics.

Additional Information

  • F5 platforms (especially rSeries and VELOS) strictly enforce the use of F5-qualified optics. Third-party modules, even if previously functional on other F5 platforms, may not work and are not supported.
  • Abnormal interface counters (e.g., extremely large numbers or all zeros) are indicative of register read errors, often caused by unsupported or incompatible optics.
  • Changing portgroup mode will trigger a system reboot and may remove stale interface configurations. Plan changes during a maintenance window.
  • For more information on supported optics and third-party hardware policies, refer to the articles below.
