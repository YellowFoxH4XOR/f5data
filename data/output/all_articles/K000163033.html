Description

This article provides an overview of the tools available for an F5 Distributed Cloud (F5XC) Customer Edge (CE) Site under the Tools tab.

These tools provide visibility into CE traffic, routing, connectivity, services, system health, and other operational information. The Site CLI Command tool also provides access to supported serviceability commands for additional troubleshooting.

The available tools and commands can vary depending on the CE software version, operating system version, deployment type, and node capabilities.

Environment

  • F5 Distributed Cloud Services

  • Customer Edge (CE) Sites

Cause

You want to use the available tools on the F5XC console to troubleshoot or monitor your site's health.

Answer/Recommended Actions

Site Tools

The following tools are available from the Tools tab depending on the CE Site and software version.

ToolPurpose
Flow tableDisplays traffic flows associated with the selected CE node. Flow information can include source and destination IP addresses, ports, TCP flags, packet counts, and other traffic details.
LogRetrieves logs for a selected service from a specific CE node. This can help troubleshoot service, platform, or node-related issues.
Show routesDisplays routing information from the selected CE node. This can be used to determine whether the CE has a route toward a particular network or destination.
Show services statusDisplays the operational status of services running on the selected CE node.
Show USB devicesDisplays USB devices detected by the CE node and their identifying information.
Show USB rulesDisplays the USB enablement rules applicable to the CE node.
Status objectsDisplays operational status information associated with resources on the CE Site.
Site CLI CommandProvides access to supported CE serviceability commands for network, routing, system, container, and dataplane troubleshooting.
PingSends ICMP echo requests from the selected CE node to test basic IP connectivity to a hostname or IP address.
TcpdumpCaptures network packets on a selected CE node and target/interface. This can be used to examine traffic entering or leaving the CE and troubleshoot network connectivity.
TracerouteDisplays the network path from the selected CE node toward a destination.
Collect Log bundleCreates a diagnostic bundle containing CE logs and system information that can be used for detailed troubleshooting.
Reboot devicePerforms a complete reboot of the selected CE node. This operation can temporarily interrupt traffic handled by the node.
Soft restartRestarts F5XC software components without performing a complete operating-system reboot. This operation can temporarily affect services on the node.

Site CLI Command

The Site CLI Command tool allows supported serviceability commands to be executed against a selected CE node directly from the F5 Distributed Cloud Console.

The commands available in the selector can vary depending on the CE software version and node configuration.

Network Troubleshooting Commands

CommandPurpose
chronyc-sourcesDisplays the Network Time Protocol (NTP) sources used by the CE and their synchronization status.
curl-hostRuns a curl request from the CE host operating-system context. This can be used to test DNS resolution and HTTP/HTTPS connectivity.
curl-vegaRuns a curl request from the CE Vega environment. This can be used to test connectivity from the CE application/networking context.
digPerforms DNS queries from the CE node and can be used to verify hostname resolution.
dropstatsDisplays dataplane packet-drop counters, including counters with zero values.
dropstats-non-zeroDisplays only dataplane packet-drop counters with non-zero values, making active drop conditions easier to identify.
flow-lDisplays flow and forwarding information from the CE dataplane.
flow-l-matchDisplays CE dataplane flows matching a specified IP address or IP address and port.
ipProvides access to Linux IP networking information, such as interfaces, IP addresses, routes, and neighbor information.
ip-link-setChanges the state or properties of a network interface. Because this can affect node connectivity, this command should be used with caution.
ip-link-showDisplays link-layer and network-interface information for the CE node.
ipsec-statusDisplays IPsec tunnel status for the CE node.
ipsec-statusallDisplays more detailed IPsec tunnel and security-association information for the CE node.
iptables-VDisplays version information for the iptables implementation available on the CE node.
netstatDisplays network connections, sockets, and listening services on the CE node.
nhDisplays dataplane next-hop information used to determine where traffic is forwarded.
rtDisplays dataplane routing information used by the CE when forwarding traffic.
show-ip-bgpDisplays Border Gateway Protocol (BGP) routing information known by the CE node.
show-ip-bgp-neighborsDisplays detailed information about BGP neighbors and their sessions.
show-ip-bgp-neighbors-advertised-routeDisplays routes advertised by the CE node to its BGP neighbors.
show-ip-bgp-summaryDisplays a summary of BGP neighbors and session status.
vifDisplays information and statistics for Vega virtual interfaces used by the CE dataplane.

systemctl-restart-kubeletRestarts the Kubernetes kubelet service. This can temporarily affect Kubernetes operations on the node.

Important Considerations

Most Site Tools and Site CLI commands are intended to display operational or diagnostic information. However, some commands can change node state or temporarily affect connectivity and services.

Examples include:

  • ip-link-set

  • systemctl-restart-NetworkManager

  • systemctl-restart-crio

  • systemctl-restart-kubelet

  • Soft restart

  • Reboot device

Review the purpose and potential impact of these operations before executing them.

Additional Information

The command list available through Site CLI Command can vary between CE software releases. The commands displayed in the Site CLI selector reflect the commands available for the selected CE node.

Console-based Site Tools operate against the selected CE node and require the node to maintain the connectivity necessary to communicate with the F5 Distributed Cloud platform.
