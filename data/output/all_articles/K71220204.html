Known Issue

Request logging may not log all configured response log template data.

This issue occurs when all of the following conditions are met:

  • You create a Request Log profile that is configured with Response Logging enabled.
  • The Response Settings Template is configured to log the pool name of the virtual server.

    The following is an example Request Log profile:

    ltm profile request-log log_pool_path {
    app-service none
    defaults-from request-log
    response-log-pool syslog-pool
    response-log-template "Path is $HTTP_PATH, Pool is $VIRTUAL_POOL_NAME"
    response-logging enabled
    }

  • You apply the Request Log profile to a HTTP virtual server.
  • You configure the HTTP virtual server with a BIG-IP APM access profile.

Impact

The system inconsistently logs the pool name.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view log data that the Request Log profile processes, the virtual server pool name is sporadically absent.
  • If you remove the BIG-IP APM access profile from the virtual server, the system consistently logs the virtual server pool name.
