K000146722: What should I do when I have multiple domains behind one Load Balancer?

Description

You have multiple domains (one.example.com & hello.example.com) behind one Load Balancer and want to route the traffic correctly.

Environment

  • F5® Distributed Cloud HTTP Load Balancer

Cause

A custom route is not configured when hosting multiple domains behind one HTTP Load Balancer and the origin pool uses one DNS name, resulting in the host header in the HTTP request not being passed correctly to the origin server.

Answer/Recommended Actions

In order to achieve that you have to setup Routes.

Route configuration is optional, but if you are deploying an HTTP LB that hosts more than one domain, and the origin pool uses one DNS Name, a custom route will need to be configured to ensure the host header in the HTTP request gets passed to the origin server.

In general, the route object is used to configure L7 routing decisions. Routes are made of three things.

  1. Match condition for incoming request
  2. Actions to take if the match is true
  3. Whether custom HTTP processing is enabled for this route match.

In other words, each rule has match condition to match incoming requests and actions to take on matching requests. Routes allow us to define match conditions on a path and/or HTTP method to either send matching traffic to the origin pool or redirect matching traffic to a different URL o respond directly to matching traffic.
