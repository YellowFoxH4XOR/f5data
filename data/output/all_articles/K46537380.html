Description

In some cases where Mac Process Checker is configured in the VPE to check for some process that is running on the Mac OS clients, it fails to detect the process and the user is denied logon to the APM.

In policyserver.log on the Mac OS client, for example, if the process that we're checking for is qualys-cloud-agent we can see logs similar to the following:
2021-06-28,15:28:15:957, 24105,175967,, 0,,,, Started in privileged mode
2021-06-28,15:28:15:957, 24105,175967,, 48, /main.cpp, 122, , Policyserver version=7211.2021.0107.1
2021-06-28,15:28:16:093, 24105,175967,, 0,,,, Checking for processes...
...
021-06-28,15:28:16:094, 24105,175967,, 48, /ProcessCheckerInspector.cpp, 32, [ProcessCheckerInspector::CheckItem],  process NOT found!
2021-06-28,15:28:16:094, 24105,175967,, 1, /ProcessChecker.h, 49, DoRun(), Failed

So in this example, the process that we're checking for is qualys-cloud-agent

Environment

  • BIG-IP APM with a Mac Process Check configured in the VPE to check for some process running on the Mac OS clients

Cause

This issue is due to an Apple MacOS security change that now limits the length of the returned process name (excluding location directory). If the Process Check string is 17-bytes or more (e.g. qualys-cloud-agent, 18-bytes long), it fails the comparison with the system returned value. This has been filed as bug ID 1033869

Recommended Actions

  1. Use a pattern that is not more than 17-bytes for the Mac Process Checker expression. In the case of the qualys-cloud-agent process, we can use "qualys-cloud-age*" for the pattern, and this will now match.

Additional Information

As this is caused by a change of behaviour by Apple, there will be no fix for ID 1033869.
