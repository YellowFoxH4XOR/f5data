Topic

You should consider using this procedure under the following condition:

  • You need to debug SQL monitor connections on the BIG-IP system.

Description

Starting in BIG-IP 11.6.0, BIG-IP includes a SQL monitor diagnostic utility that checks the status of SQL monitor connections. For example, if you need to diagnose an unresponsive SQL monitor, you can use the utility to check the status of SQL monitor pings in progress and open cached monitor connections. The command supports the following syntax:

/usr/share/monitors/DB_monitor cmd status [RD] [debug]

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have access to the BIG-IP (bash) command line.

Procedures

Determining the SQL monitor status using the Traffic Management Shell

Before you run the SQL monitor debugging utility you should check the monitor status using the Traffic Management Shell (tmsh). If the monitor is marking the resource down, the tmsh show /ltm monitor command output will report an error message that may help diagnose the issue. To check the monitor status using the tmsh utility, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh
  2. To check the SQL monitor status, use the following command syntax:

    show /ltm monitor <sql_type> <monitor_name>

    For example, the following command checks the status of the mysql monitor named mysql-mon:

    show /ltm monitor mysql mysql-mon

    The following example output indicates that the mysql-mon monitor is marking the destination resource down due to receiving no successful response:
     

    ---------------------------------
    LTM::Monitor /Common/mysql_mon
    ---------------------------------
    Destination: 10.11.16.252:3306
    State time: down for 0hr:1min:13sec
    | Last error: No successful responses received before deadline. @2015.11.18 10:11:55


Debugging the SQL monitor using the DB_monitor utility

The DB_monitor utility report debugging information for SQL monitor types running on the system. To debug SQL monitor connections on the BIG-IP system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To check the SQL monitor, use the following command syntax:

    /usr/share/monitors/DB_monitor cmd status [RD] [debug]

    For example, to check SQL monitor connections in route domain 2 with the debug option enabled, type the following command:

    /usr/share/monitors/DB_monitor cmd status 2 debug
  3. View the debug log file by typing the following command:

    cat /var/log/monitors/DB_.cmd-0..0...log

    The output appears similar to the following example:
     

    ********** Debugging session beginning at: Tue Nov 17 13:33:41 2015

    Arguments 1-4:
    cmd
    status
    0
    debug

    Environment variables:
    --
    TMOS_RD: 2 (2)
    Daemon port: 1521
    Command: cmd status 2 debug
    Recvd: 'SQL monitor daemon status
    '
    Recvd: 'Pingers: 0
    '
    Recvd: 'Cached connections: 1
    '
    Recvd: ' - jdbc:mysql://10.11.16.252:3306/: com.mysql.jdbc.JDBC4Connection@7cf6b73d, use count: 103
    '
    Recvd: '
    '
    Recvd: 'end status'

  4. If you need further assistance debugging the SQL monitor issue, provide the /var/log/monitors/DB_.cmd-0..0...log file to F5 Technical Support.
