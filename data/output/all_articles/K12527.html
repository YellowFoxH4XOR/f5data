Known Issue

This is the result of a known issue. In BIG-IP versions 9.3.1 and later, if the BIG-IP system time is adjusted backwards, the mcpd process may report the adjustment as a configuration change. If the Detect ConfigSync Status feature is enabled, the ConfigSync status will report as Sync Recommended for the members of a high availability pair.

No manual intervention is needed for this condition to occur. For example, if the ntp process adjusts the system time backwards, messages that appear similar to the following example will be written to the /var/log/daemon.log file:

ntpd[28613]: time reset -3.241022 s

The message indicates that the time was adjusted backwards by 3.241022 seconds. After which, the Configsync status will report as Sync Recommended in the Configuration utility.

To verify the sync state from the BIG-IP command line interface, type the following command:

bigpipe db Configsync.State

If the BIG-IP considers itself to be out of synchronization with its peer, the following status will be returned:

Configsync.State = 1 - Local config modified, recommend configsync to peer

If the BIG-IP considers itself to be synchronized with its peer, the following status will be returned:

Configsync.State = 0 - Synchronized

F5 Product Development is tracking this issue as ID 315570 (formerly CR105327).

Note: This issue does not apply to BIG-IP version 11.x and later due to architectural changes to the ConfigSync feature.
