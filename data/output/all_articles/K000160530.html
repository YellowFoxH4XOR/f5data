K000160530: AS-path modifications do not trigger route-map updates

Type
Support Solution
Published
2026-03-30
Updated
2026-03-30
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000160530

Description

Modifications to an AS-path access-list in BGP (Border Gateway Protocol) configurations do not automatically trigger updates or refreshes to any associated route-maps.  To ensure the changes take effect and are correctly applied to routes exchanged with upstream Autonomous Systems (AS), the user must first make the desired modifications to the AS-path access-list and then manually clear or refresh the BGP session. This step forces the router to re-evaluate and update the routing information, preventing issues like stale filters or incorrect route advertisements.

Environment

  • imish
  • BGP

Cause

Functions as Designed and a common behavior in BGP (Border Gateway Protocol) configurations.

Answer/Recommended Actions

BGP needs to cleared either via soft graceful restart or hard restart using the following commands.  

If BGP has been configured to allow soft restarts issue the following command in enabled mode of imish.  This will for the route-map to be read and re-evaluate the AS-path to publish route to, non-destructively.

clear ip bgp * soft

If BGP has not been configured for soft restarts issue the following command in enabled mode of imish.  Note this will force all BGP neighbors to remove routes that the BigIP is injecting possible causing route failure while BGP reconvergence happens.

clear ip bgp *
