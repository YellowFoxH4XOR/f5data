Description

When accessing Web Application behind BIG-IP, images/icons fail to load on your application even after applying the workaround iRule in KB article K05194774: Images are not returned correctly when accessing virtual server

  • Images/icons failed to load
  • Frontend traffic via HTTPS (443)
  • Backend traffic via HTTP (80)

Environment

  • BIG-IP LTM
  • Virtual Server HTTPS (443)
  • Pool Member HTTP (80)
  • iRule
  • Image format in SVG

Cause

  • SVG (Scalable Vector Graphic) is a graphics file format based on XML text.
  • Which mean the format relies on text to describe lines, curves, colors, and other physical attributes of an image.
  • Hence, iRule in KB K05194774 are defined to match text file content will match the SVG file and modify the and redirected HTTP to HTTPS
    e.g: "xmlns="http://www.w3.org/2000/svg"" rewrite to "xmlns="https://www.w3.org/2000/svg"" 

Recommended Actions

There's 3 options available to resolve this issue:

  1. Remove iRule from KB article K05194774 and as well stream profile from VS object
  2. Replace SVG image file with a Raster graphic such as PNG or JPEG
  3. Add in an additional iRule TCL code "elseif" to the iRule of KB article K05194774 to prevent http response with "content-type: image/svg+xml" from rewritten to HTTPS.
    when HTTP_REQUEST {
    log local0. [HTTP::uri]
            STREAM::disable
            HTTP::header remove "Accept-Encoding"
            }

    when HTTP_RESPONSE {
            if { [HTTP::header value Content-Type] contains "text"} {
               STREAM::expression {@http://@https://@}
               STREAM::enable
            }
            elseif { [HTTP::header value Content-Type] contains "image/svg+xml"} {
                    STREAM::disable
            }
    }
