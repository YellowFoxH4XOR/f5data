Description

By default, Use BIND Server on BIG-IP is enabled in DNS profile. In the event that all pool members configured under wideip pool are down. BIG-IP DNS will provide response to the querier based on the records of the same zone defined in Zonerunner (Local BIND).

Note: These local BIND records are automatically created when creating wider ip and assign a pool to it.

Environment

  • BIG-IP DNS
  • GSLB
    • Wide ip is configured
    • DNS Pool is down
  • DNS profile
    • Use BIND Server on BIG-IP
    • RCODE

Cause

If all pool members are down when Use BIND Server on BIG-IP and RCODE are disabled, BIG-IP DNS will not be able to forward the query to BIND to provide a best effort resolution. As a result, timeout will occur. In some environments, this may trigger DNS flood as the client and upstream resolver will keep retrying.

Recommended Actions

  1. On BIG-IP, though this is considered function as expected. Utilizing RCODE may prevent the resolver from getting timeout. Alternatively, setting Fallback to an IP address can workaround this issue.
  2. Ideally, limiting the numbers of retry attempt on client or resolver will also help prevent the flooding.
