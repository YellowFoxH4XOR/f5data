Description

User's APM sessions are deleted unexpectedly with error message Session deleted (restarted)

  • Sessions are deleted at some point after policy evaluation has completed successfully. 
  • User-Agent is redirected to start a new session
  • APM log records Session deleted (restarted)

Environment

  • BIG-IP APM

Cause

  • When a BIG-IP APM client goes through the access policy evaluation, BIG-IP APM tracks its progress and exactly which item(s) has been evaluated. If the client makes a request to perform the same evaluation (e.g. if it is trying to do the same checks it already passed), the existing session is deleted and a new one restarted and the error message is logged.
  • User-Agent sends an old or invalid value for MRHSession cookie. The first 24 characters of the MRHSession cookie value are rotated with each response during policy evaluation. If an old value for MRHSession cookie is sent during policy evaluation or even after the policy has completed to an 'allow' state, the session will be deleted. 

For a specific use case and example, refer to K19123634: User access sessions may restart when accessing the root URI (/)

Recommended Actions

This error message and its cause can be the result of a number of reasons including but not limited to the following:

  • Users accessing a BIG-IP APM virtual server through bookmarks even after a BIG-IP APM session has already established.
  • Use case where users switch from thick clients to browser clients (client apm session cookie sharing) when accessing the BIG-IP APM virtual server.
  • Misconfiguration: iRule
  • Misconfiguration: redirection in SAML 
  • Misconfiguration: External logon page. K30503342: APM Logon Page loop with error Session Deleted (restarted)

To identify the specific root cause, use a HTTP debug tool such as fiddler, HTTPwatch, Chrome developer tools to analyse and track the client URL and apm cookies that the client is sending to BIG-IP APM.
