K000151700: BIG-IP VE failed to upgrade due NUMA node limit

Type
Support Solution
Published
2025-06-05
Updated
2025-06-05
Source
https://my.f5.com/manage/s/article/K000151700

Description

When upgrading or deploy BIG-IP LTM Virtual Edition (VE)  on cloud-based virtual machines, the upgrade or deployment may fail if the underlying VM is configured with more than one NUMA (Non-Uniform Memory Access) node. The device may become inoperative, with TMM (Traffic Management Microkernel) repeatedly restarting and failing to load the configuration. System logs may display errors such as:

Multiple NUMA nodes usage is unsupported.
Error: Specified driver (dpdk) is unavailable
Error: Unable to attach to xnet dev
Error: Unable to initialize device
tmm numa check failure needs a more precise error path.
Error: Restarting TMM
Initiating TMM shutdown.

Environment

  • BIG-IP LTM VE
  • NUMA Nodes 
  • Auzre
  • AWS

Cause

BIG-IP VE supports only a single NUMA node for its operation. When deployed on VMs or cloud instances configured with multiple NUMA nodes, TMM fails its internal NUMA check and cannot initialize properly, resulting in repeated restarts and an unusable system state.

Recommended Actions 

There is no supported method within BIG-IP OS/TMOS to disable or limit the number of visible NUMA nodes; this must be managed at the hypervisor or cloud instance selection level. To resolve the problem please follow below steps:

1.Roll back to the previous working version.

2. Migrate the BIG-IP VE deployment to a supported instance type with only one NUMA node before attempting another upgrade.

Note: Consult your cloud or hypervisor  provider’s documentation or support resources to confirm which instance types use a single NUMA domain. 

 

You can use below commands to verify the NUMA nodes on BIG-IP:

lscpu

numactl --hardware
