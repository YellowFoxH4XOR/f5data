Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP APM system is configured with any of the following access policy types:
    • Application access policy
    • Per-request policy
    • Portal access policy
  • You want to automatically terminate an access session when access to a specific file name is processed by the access session, for example, any URI that ends with a unique file name such as logout.php or terminate.html. 

Description

In some environments, you may want the ability to automatically terminate (log out) an access session based on the intended URI selection. The following procedure creates an iRule that you can apply to a BIG-IP APM virtual server. The iRule triggers when a request successfully passes any configured access ACLs and the requested URI ends with a specific file name, allowing for instances of the file name to be located in various URI paths. Note that configured ACLs are not required for the iRule to function.

Note: The referenced URI file name does not need to exist on the application. The file name reference is used as a trigger in determining wheter the access session should be terminated.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Configuration utility.
  • You have a general understanding of iRules.

Procedures

Creating the automatic logout iRule

The following procedure creates an iRule that can be applied to a BIG-IP APM virtual server. 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Enter a name for the new iRule.
  5. Enter the following iRule stanza in the Definition box.
    when HTTP_REQUEST {
  if { ([string tolower [HTTP::uri]] contains "closeconnection.aspx"
    || [string tolower [HTTP::uri]] contains "signout.aspx")
    && [ACCESS::session exists -state_allow -sid [HTTP::cookie MRHSession]] } {
      HTTP::respond 200 content {<html><body><h1>You are now logged out.</h1></body></html>}\
      "Set-Cookie" "F5_ST=deleted;expires=Thu, 01-Jan-1970 00:00:01 GMT;path=/"\
      "Set-Cookie" "MRHSHint=deleted;expires=Thu, 01-Jan-1970 00:00:01 GMT;path=/"\
      "Set-Cookie" "F5_HT_shrinked=deleted;expires=Thu, 01-Jan-1970 00:00:01 GMT;path=/"\
      "Set-Cookie" "F5_fullWT=deleted;expires=Thu, 01-Jan-1970 00:00:01 GMT;path=/"\
      "Set-Cookie" "LastMRH_Session=deleted;expires=Thu, 01-Jan-1970 00:00:01 GMT;path=/"\
      "Set-Cookie" "MRHSession=deleted;expires=Thu, 01-Jan-1970 00:00:01 GMT;path=/"

      ACCESS::session remove
      log local0. "iRule logout triggered: Removing access session for [ACCESS::session sid]"
      # disable HTTP_REQUEST events for all other iRules
      event disable
  }
}

    Note: Modify <filename> to match the intended logout file name for your environment.

  6. Click Finished.

Applying the iRule to the BIG-IP APM virtual server

The following procedure steps assigns the new iRule to the virtual server. When the BIG-IP APM system processes access session traffic matching the iRule definitions, the system terminates the session.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the virtual server to which you want to assign the iRule.
  4. Click the Advanced Resources tab.
  5. Under iRules, click Manage.
  6. In the Available list, select the iRule and move it to the Enabled list.
  7. Click Finished.
