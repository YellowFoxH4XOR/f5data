K40326169: F5 BIG-IP inserting P3P header

Description:

The BIG-IP inserts one or more empty Platform for Privacy Preferences Project (P3P) headers into HTTP responses.

Environment:
  • Bot Defense profile or DoS profile on a virtual server

Cause:

To allow the cross-domain cookies the Bot Defense feature adds a P3P header when Set-Cookie headers are being sent in its response.

The P3P header is required for Internet Explorer 11 browser to support Cross-Domain cookies that are inserted by the above profiles. Without this header, any Set-Cookie response header is ignored by Internet Explorer 11 if it comes from a request to a different domain than that of the main page (such as within an iFrame, or an image or other resource to another domain).

Recommended Actions:

Microsoft announced the end of support for Internet Explorer on June 15, 2022 and so support for it has also ended on BIG-IP systems. You should use supported browsers such as Edge, Firefox or Chrome. Use the following procedure only if you must support IE in the short term.

Note: the P3P header is deprecated, and should only be used if it is required to support Internet Explorer 11.

If you do not require the P3P header, It is also possible to set the value to "<null>" and thus avoiding this P3P header from appearing.

The value of the P3P header is globally configurable in the DB variable dosl7.p3p_header.

# modify sys db dosl7.p3p_header value "<null>"
# list sys db *p3p*
sys db dosl7.p3p_header {
    value "<null>"
}

However, setting this value to null may cause legitimate Internet Explorer 11 browsers to be blocked from accessing the web application.

Alternatively, an irule can be used to remove P3P headers from HTTP responses. To do so you can use an iRule similar to the following:

when HTTP_REQUEST {
  set IE11 0
  if { [HTTP::header "User-Agent"] contains "Mozilla/5.0 (Windows NT 6.3; Trident/7.0; rv:11.0) like Gecko"} {
    set IE11 1
  }
}
when HTTP_RESPONSE_RELEASE {
   if {not $IE11 == 1} {
      HTTP::header remove "P3P"
   }
}
