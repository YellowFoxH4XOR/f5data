Description

After RMA replacement of a unit belonging to a device-group, Config-Sync fails with similar to below message in /var/log/ltm:

01071488:3: Remote transaction for device group <device_group_name> to commit id <id> <peer_unit_hostname> 0 failed with error 01070712:3: Caught configuration exception (0), Error importing FIPS140 key (<fips_key_name>) to hardware...

You can also see this message on the GUI of the replacement peer device:

01070712:3: Caught configuration exception (0), FIPS 140 operations not available on this system.

Environment

  • BIG-IP with FIPS 140 hardware security module (HSM)
  • Unit replaced in device-group for Config-Sync

Cause

HSM is not initialized on the replacement unit. HSM is not synchronized in Security Domain.

Recommended Actions

  1. Follow the manual for Initializing the HSM in <your_platform> in Manual Chapter: BIG-IP FIPS Platform Setup on the replacement device.
  2. Fully boot the replacement device.
  3. Log into the command line of the source BIG-IP system.
  4. Copy the SIM master key on the source BIG-IP system to the destination BIG-IP system by using the following command syntax, where <IP address> refers to the management IP or Self IP of the destination BIG-IP system:

    # fipscardsync <IP address>

    Note: The BIG-IP system uses the SIM master key to encrypt keys residing on the FIPS card. It also allows the BIG-IP system to decrypt keys being imported into the FIPS card from another unit with the same Security Domain (SO).

    Note: While running the command, you may face the below error, to fix it, reboot the RMA device.
    root@(fips2)(cfg-sync Disconnected)(Active)(/Common)(tmos)# fips-card-sync <ip_address>
    Enter FIPS Security Officer password for the local device:
    Enter FIPS Security Officer password for the remote device
    or press <ENTER> if same as the local one:
    Connecting to <ip_address> as user root ...
    ERROR: Synchronization failed.       <---reboot the RMA devices fixes this issue
    Password:
    ERROR: Read error

    Important: The source BIG-IP system must be able to communicate with the destination BIG-IP system by way of ssh, using the desired IP address. If the destination BIG-IP system has not been set up with any IP address, refer to K15040 for configuring management IP or the BIG-IP TMOS: Routing Administration for configuration Self IP Addresses on the destination BIG-IP system.
  5. Now you can proceed to configure the replacement unit by loading a UCS or initiating Config-Sync from the peer Active unit.

Additional Information

Manual Chapter : BIG-IP FIPS Platform Setup says:

Before you synchronize the HSMs

Before you can synchronize the FIPS hardware security modules (HSMs), you must ensure that the target HSM:

  • Is already initialized
  • Has an identical security domain name
  • Does not contain existing keys
  • Is the same hardware model contains the same firmware version

    NOTE: Following firmware versions are exception for this limitation:
         CN16XX-NFBE-FW-2.1-110015
         CN16XX-NFBE-FW-2.2-130013
