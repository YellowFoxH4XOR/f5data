Known Issue

The TMM process may produce a core file and restart when processing DNS iRule commands.

This issue occurs when all of the following conditions are met:

  • A TCP virtual server is configured with a DNS profile
  • An iRule that uses a DNS event/command is associated with the virtual server

Impact

If the BIG-IP system is a member of a redundant configuration, traffic will fail over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic will be interrupted until TMM restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H465128 on the Diagnostics > Identified > Medium|High screen.
  • The BIG-IP system generates a TMM core file to the /shared/core directory
  • The BIG-IP system fails over to another host in the device group
  • You find an error message in the /var/log/ltm file that appears similar to the following example:

    err tmm3[9988]: 01220001:3: TCL error: /Common/rule <DNS_REQUEST> - bad option "option": must be -all, -index, -element, -name, or -value while executing "class match"

Workaround

To work around this issue, you can disable the DNS queuing. To do so, perform the following procedure:

Impact of workaround: Performance may be significantly impacted by disabling the DNS queuing.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Disable DNS queuing by typing the following command:

    modify sys db dns.queuing value disable

  3. Save the changes by typing the following command:

    save /sys config

  4. To exit tmsh, type the following command:

    quit
