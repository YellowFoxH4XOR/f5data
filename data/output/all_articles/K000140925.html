K000140925: Session DB memory usage may increase over time when MRF Diameter session persist timeout is large

Support Solution
Published
2024-09-03

Status

Applies to

Source

Description

When MRF Diameter session persistence timeout is set to a high value such as more than 5 days, BIG-IP memory usage may increase over time causing connection reaping events.

ltm message-routing diameter profile session diametersession {
  persist-timeout 18000
}
err tmm2[22008]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (2000000000000) (global memory) 1 Connections killed

Although remote Diameter peers sends either Credit-Control-Request (CCR-T) or Abort-Session-Request (ASR) to BIG-IP, the total number of session persistence records remains high.

 

Environment

  • MRF Diameter

Cause

Bug ID1018285

Recommended Actions

To workaround the high session memory usage over time:

  1. Avoid using a high session persist timeout value
  2. If a high session persist timeout value is needed, please use DIAMETER::persist to persist or delete session according to CCR request type.
