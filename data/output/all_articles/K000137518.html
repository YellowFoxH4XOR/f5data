Description

ASM Event log suggest that "Unparsable Request Content : Request Content-Length differs from actual request body length"

 

Environment

  • BIG-IP
  • ASM
  • Advanced WAF

 

 

Cause

  1. Mismatch in advertised content-length with the payload length

  2. HTTP protocol compliance violation

 

Recommended Actions

Request customer to send the Event logs which contains the violation details.
Check the content length in the request received and seen by ASM.

=== It will look like below =======

Original Request
Request actual size: 1263261 bytes.
Request was truncated.

POST
xxx HTTP/1.1
Host: xxx.xxx.co.id
Connection: keep-alive
Content-Length: 4378521 <<----


The Content length in header is 4MB but the request receive and seen by ASM is only 1 MB. So payload is truncated ( to see full payload we need a decrypted capture of request sent by client ) 

 

Above proves that client is not acting correctly and ASM is correctly blocking the request. If customer wish ASM not to check for content length header with the actual payload length then Disable the violation from the policy, Otherwise ASM is functioning correctly .

 

Additional Information


By disabling violation we will lose the violation protections with sub-violations as indicated in https://my.f5.com/manage/s/article/K44162352
