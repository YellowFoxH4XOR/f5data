K92893202: SAML BIG-IP as IdP - Single Logout Request resulting in a reset

Type
Support Solution
Published
2022-12-01
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 16.1.2
Source
https://my.f5.com/manage/s/article/K92893202

Description

BIG-IP IdP sends a reset packet to the client when a SAML Logout Request is sent without an MRHSession cookie.

Environment

  • BIG-IP APM
  • BIG-IP as SAML Identity Provider IdP
  • 3rd Party - Multi-Domain Service Provider SP not using Cross-Origin Resource Sharing CORS

Cause

The cause of this issue was that the SP was passing the SAML Logout Request from one host to a different host before the IdP but does not support CORS. This caused the latter host to drop the MRHSession cookie before sending the request to the BIG-IP causing the reset.

Recommended Actions

The recommend action is to have the SP update their application code to support CORS so the MRHSession cookie is sent with the SLO Request
If the customer cannot do so, they can apply the following iRule to the BIG-IP IdP Virtual Server

  1. Login to the BIG-IP
  2. Navigate to Local Traffic  ››  iRules : iRule List
  3. Click Create...
  4. Name the iRule: 
    SLO_redirect_iRule
  5. Update the following code where the host is https://sp.apmsupport.local to the SP that is sending the logout request 
    This updates the Referrer header to trigger the iRule
    when CLIENT_ACCEPTED {
        ACCESS::restrict_irule_events disable
    }
     
    when HTTP_REQUEST {
        set referer_host [HTTP::header value "Referer"]
     
    if { ([HTTP::uri] equals "/saml/idp/profile/post/sls") && ($referer_host equals "https://sp.apmsupport.local") } {
        log local0. "SLO REQUEST triggered"
            HTTP::respond 302 noserver "Location" "/vdesk/hangup.php3" "Content-Type" "text/html" "Cache-Control" "no-cache, must-revalidate" Set-Cookie "MRHSession=deleted;expires=Thu, 01-Jan-1970 00:00:10 GMT;domain=[HTTP::host];path=/" Set-Cookie "LastMRH_Session=deleted;expires=Thu, 01-Jan-1970 00:00:10 GMT;domain=[HTTP::host];path=/"
            log local0. "Session removed"
        if { ([ACCESS::session exists -sid $apm_cookie]) } {
            ACCESS::session remove
            log local0. "Access Session Removed"
            }
        }
    }
  6. Apply the iRule to the IdP Virtual Server and test

Additional Information

Internet Explorer will not be affected but this as it does not enforce CORS by default
