K000160194: Resolving "Unable to contact BIG-IP device" Errors in BIG-IP Web UI Due to restjavad Overload

Type
Support Solution
Published
2026-03-02
Updated
2026-09-03
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000160194

Description

The BIG-IP Web UI displays frequent "Unable to contact BIG-IP device" errors. The error occurs randomly, often when accessing management or statistics pages. The issue may be accompanied by log messages such as:

  • "SEVERE: Servlet.service() for servlet [org.apache.jsp.tmui.overview.welcome.introduction_jsp] in context with path [/tmui] threw exception"
  • "AUTHCACHE Error processing cookie ... Cookie impersonation detected"
  • "gui session Id ... is not valid"
  • Various httpd, tomcat, and restjavad errors and restarts

Symptoms include random GUI disconnects, sometimes recoverable by clicking "Continue" without re-login, and delayed responses in the Web UI.

Environment

  • Possible conditions:
    • Modules: LTM, BIG-IP ASM, BIG-IP Analytics (issue observed on devices with and without BIG-IP ASM), and DNS
    • Management access via jump host
    • Multiple concurrent GUI sessions/tabs
    • Configuration changes: Increased memory provisioning for restjavad, tomcat, and main mgmt
    • Use of external management tools (BIG-IQ, later removed)
    • Occasional off-box logging and syslog configuration
    • No evidence of network issues; issue is internal to BIG-IP
    • Statistics gathering.

Cause

The issue is caused by overloading the restjavad service due to a high number of concurrent requests, typically when multiple GUI tabs are opened and clicked in quick succession. This results in delayed responses and intermittent GUI errors. The coloradvisory probe timeout in the Web UI is too short to accommodate the overloaded service, leading to frequent disconnects.

Answer/Recommended Actions

To mitigate the issue, increase the timeout values for the coloradvisory probe in the Web UI:

  1. Remount the /usr partition as read-write:mount -o remount,rw /usr
  2. Edit the file /usr/local/www/xui/framework/scripts/variables.js and change the following variables:var time_updateXui = 5; var timeout_status = 30;
    To:
    var time_updateXui = 30; var timeout_status = 90;
  3. Remount the /usr partition as read-only:mount -o remount,ro /usr
  4. Restart associated daemons:bigstart restart httpd
    bigstart restart tomcat
    bigstart restart restjavad

Additional recommended actions:

  • Avoid opening multiple GUI tabs or making rapid requests to the BIG-IP Web UI.
  • Ensure external management tools (such as BIG-IQ) are not generating excessive API or tmsh requests.
  • Increase memory provisioning for restjavad and tomcat if persistent errors are observed:
    tmsh modify sys db provision.extramb value 3000
    tmsh modify sys db provision.restjavad.extramb value 2227
    tmsh modify sys db provision.tomcat.extramb value 512
    bigstart restart restjavad && sleep 20 && bigstart restart restnoded
    tmsh save sys config
    • These are examples only. The setting for your network is based on the available resources and the amount needed to correct an issue. It may be a good idea to review K16419: Overview of BIG-IP memory usage prior to using these settings.
    • It may take some testing to find the right setting for your network.
  • If using off-box logging, ensure syslog configuration is not contributing to management subsystem overload.

Additional Information

  • The workaround increases the coloradvisory probe timeout, allowing the system to handle requests without disconnecting the user.
  • The issue is not caused by network problems but by internal service overload.
  • If the issue persists on other devices after applying the workaround, further investigation may be required as it could indicate a separate issue.
