K000156977: Monitor flapping after configure packet filter for vlan-group

Applies to

Source

Description

After configuring a packet filter for a VLAN group on BIG-IP LTM, the standby device experienced health monitor flapping. ICMP monitor probes intermittently failed, resulting in pool member status down and HA failover warnings. Packet captures and logs revealed that ICMP monitor requests and replies began traversing different VLANs, causing monitor traffic to be dropped due to packet filter rules. The root technical issue was that ARP replies were received on an unexpected VLAN, which triggered a dynamic FDB (Forwarding Database) entry change on the standby device. This led to subsequent monitor traffic being sent via the wrong VLAN, resulting in monitor failures. The issue was resolved by removing the packet filter or by configuring a static ARP entry on the upstream switch to prevent MAC/FDB flapping.

Environment

  • Product: BIG-IP LTM
  • Configuration: VLAN group with packet filter applied; HA pair (active/standby)
  • Monitors: ICMP (gateway_icmp)
  • Issue observed on standby device in HA setup

Cause

Monitor flapping was caused by ARP replies arriving on the wrong VLAN, which updated the FDB entry for the monitored IP address to the external VLAN. This caused subsequent ICMP monitor traffic to be sent via the external VLAN, where it was dropped by the packet filter on the active device. The FDB entry change was triggered by unexpected ARP/ICMP traffic flow, and static FDB configuration was not possible on the platform.

Recommended Actions

  • When using packet filters with VLAN groups in HA environments, monitor ARP and ICMP traffic to ensure replies are received on the expected VLAN.
  • Use packet captures and FDB/ARP table monitoring to correlate monitor flapping events with FDB entry changes.
  • If static FDB configuration is not supported on your platform, configure a static ARP entry for the monitored IP address on the upstream switch to prevent MAC/FDB flapping.
  • Consider packet filter exemptions for ARP and ICMP traffic, or adjust filter rules to ensure monitor traffic is not inadvertently blocked.
  • If possible, review VLAN group transparency mode (Transparent vs. Translucent) and Proxy Exclusion List settings to minimize misdirected monitor traffic.
  • Removing the packet filter or implementing static ARP on the switch resolved the issue in this scenario.
