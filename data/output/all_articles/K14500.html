Known Issue

The BIG-IP system may fail to trigger the PERSIST_DOWN iRule event when a pool member is down. This issue occurs when all of the following conditions are met:

  • The pool member has an existing persistence record owned by a TMM process.
  • A new client request is processed by another TMM process that does not own the persistence record.

Impact

The iRule may not work as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The PERSIST_DOWN iRule event does not trigger.
  • The BIG-IP system does not process any iRule commands authored in this event.
