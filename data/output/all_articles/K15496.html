Topic

You should consider using this procedure under the following conditions:

Note: The following conditions include BIG-IP Virtual Edition (VE) and BIG-IP tenants on the F5 VELOS and F5 rSeries platforms.

  • You want to upgrade one or more BIG-IP devices to a new BIG-IP platform.
  • You want to migrate the current configuration to the new BIG-IP platform.
  • You want to test the configuration on the new BIG-IP platform before retiring the older BIG-IP devices.

F5 does not recommend using the procedure in this article to migrate BIG-IP configurations that include hardware-specific features like hardware DOS support or Packet Velocity ASIC (PVA) and other L2 specific features, which may give rise to compatibility issues between different hardware. For more information about BIG-IP resources that are not synchronized during a ConfigSync operation, refer to K21259300: BIG-IP items that are not synchronized between device group members during a ConfigSync operation.

In such cases, the F5 Journeys App (BIG-IP Migration Tool) can help you find out from a UCS or QKView file if the source BIG-IP configuration contains any potential sync blocker. You can also use the tool to migrate your BIG-IP system without using the DSC functionality. For more information refer to K000137313: F5 Journeys - BIG-IP upgrade and migration utility.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrator access to all BIG-IP platforms.
  • You understand the device service clustering (DSC) architecture and have determined the necessary IP addresses for configuration synchronization (ConfigSync) and failover.
  • You have installed the new BIG-IP system and configured the necessary elements, such as Virtual Local Area Networks (VLANs), self IP addresses, routes, and licensing.

Description

Starting in BIG-IP 11.4.0, the BIG-IP system supports high availability (HA) features, such as ConfigSync and failover, between different platforms.

By allowing HA functionality between different platforms, newer platforms only need to join the current device group to receive the older platform's configuration.

Note: If an older platform does not support the newer version of software, you should install an older software version that both systems support, synchronize the configuration, and then upgrade the newer platforms.

For example, you can configure a new VIPRION 4400 blade to share the current device group with an existing pair of BIG-IP 3900s.

  • You can synchronize the BIG-IP 3900's configuration data to the new VIPRION 4400 blade chassis.
  • You can maintain active and standby states, which allows for failover and easier configuration testing.
  • You can remove the older devices from the trust domain and device group.

Note: You cannot synchronize BIG-IP Virtual Edition (VE) with hardware until BIG-IP 11.5.0. For more information, refer to K41493503: BIG-IP VE may fail to synchronize the configuration to a BIG-IP hardware platform.

Note: You can sync hardware security module (HSM) keys between BIG-IP platforms of the same HSM hardware family in separate data centers or device service clusters. For more information, refer to K42565270: FIPS manual HSM sync process between BIG-IP platforms in separate data centers or DSCs.

Note: Connection and persistence mirroring does not work between dissimilar platforms. For more information, refer to K13828: Error Message: 01340004:3: HA Connection detected dissimilar peer.

Note: Product licensing and module provisioning do not synchronize by design. New devices that you add to the trust domain and device group should be licensed and provisioned for the configured features.

Important: Network layer objects such as VLANs and route domains do not synchronize, by design. ConfigSync fails if the network layer object is not configured on the new BIG-IP device added to the device group, and objects such as virtual servers or floating self IP addresses reference the network layer object in the configuration.

If you want to upgrade your existing platforms and migrate the configuration from the existing device group members to the new devices, you can perform the following procedures.

Procedures

To perform a platform migration using device groups, perform the following procedures:

  • Add an NTP server on the new BIG-IP system
  • Configure the ConfigSync and failover IP addresses on the new BIG-IP system
  • Add the new BIG-IP system to the existing device trust
  • Add the new BIG-IP system to the existing device group
  • Fail over to the new BIG-IP system
  • Verify traffic on the new BIG-IP system
  • Remove old BIG-IP systems from the device trust and device group (optional)

Add an NTP server on the new BIG-IP system

ConfigSync operations may not function properly if an NTP server is not configured on all the devices in a device group.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You should perform the following procedure on each BIG-IP system that you are adding to the device group.

  1. Log in to the Configuration utility of the new BIG-IP system.
  2. Go to System > Configuration > Device > NTP.
  3. Under Properties for Address, enter the IP address of the NTP server and select Add.
  4. Repeat step 3 to add all NTP servers.
  5. Select Update.

Configure the ConfigSync and failover IP addresses on the new BIG-IP system

To configure the ConfigSync and failover addresses on the new BIG-IP system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You should perform the following procedure on each BIG-IP system that you are adding to the device group.

  1. Log in to the Configuration utility of the new BIG-IP system.
  2. Go to Device Management > Devices.
  3. Select the host name of the local device designated with (Self).
  4. To ensure the device does not take the active role throughout the subsequent procedure, select Force Offline, and select OK to confirm.

    Important: The forced offline state disables connectivity to self IP addresses on VIPRION systems and vCMP guests on VIPRION or VELOS hypervisors, which prevents device group communication. To place these systems offline while maintaining self IP address connectivity, refer to the procedure for using the Minimum Blades Up setting in K15122: Overview of the Force Offline option.

  5. Select the ConfigSync tab.

    Note: For BIG-IP 12.1.6 and earlier, on the Device Connectivity tab, select ConfigSync.

  6. Select the self IP address that you want to use for ConfigSync.
  7. Select Update.
  8. Select the Failover Network tab.

    Note: For BIG-IP 12.1.6 and earlier, on the Device Connectivity tab, select Failover Network. For BIG-IP 11.5.6 and earlier, on the Device Connectivity tab, select Network Failover.

  9. Select Add.
  10. In the Address list, select the name of the self IP address you want to use for failover. The default port is 1026 (UDP).
  11. Select Repeat.
  12. Select the Management Address to use for failover. The default port is 1026 (UDP).
  13. Select Finished.

    Important: Leave the device in the forced offline state until instructed to do otherwise later in this article.

Add the new BIG-IP system to the existing device trust

To add the new BIG-IP system to the existing device trust, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You should perform the following procedure on each BIG-IP system that you are adding to the device group.

  1. Log in to the Configuration utility of the existing or older BIG-IP system.
  2. To add a peer to the current device trust, go to Device Management > Device Trust > Device Trust Members.

    Note: For BIG-IP 12.1.6 and earlier, go to Device Management > Device Trust > Peer List.

  3. Select Add.
  4. For Device IP Address, Administrator Username, and Administrator Password, enter the management IP address and administrator credentials of the new BIG-IP device.
  5. Select Retrieve Device Information.
  6. Verify that the information under Device Certificate matches the device certificate of the new system and add the new BIG-IP system by selecting Device Certificate Matches and then selecting Add Device.

    Note: For BIG-IP 12.1.6 and earlier, select Finished.

  7. Go to Device Management > Device Trust.
  8. Under Trust Information, verify that Status is set to In Sync.

Add the new BIG-IP system to the existing device group

To add the new BIG-IP system to the existing device group and sync the configuration, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You should perform the following procedure on each BIG-IP system that you are adding to the device group.

  1. Log in to the Configuration utility of the existing or older BIG-IP system.
  2. Go to Device Management > Device Groups.
  3. Select the appropriate device group.

    Note: To allow both ConfigSync and failover, the device group must be set to Sync-Failover.

  4. To ensure the Network Failover option is selected, set Configuration to Advanced and select the Network Failover option.

    Note: For BIG-IP 12.1.6 and earlier, select the Failover tab and make sure the Enabled box for Network Failover is selected.

    Note: Network failover is required for more than two BIG-IP devices in a device group.

  5. Select the Properties tab.
  6. For Members, in the Available list, select the new BIG-IP system that you want to add to the device group and move it to the Includes list.
  7. Select Update.
  8. Go to Device Management > Overview.
  9. Under Device Groups, select the appropriate device group.
  10. Under Devices, select the hostname of the existing BIG-IP system with the configuration for which you want to migrate to the new BIG-IP system. This is typically the hostname designated by (Self).
  11. To sync the configuration to the new platform, under Sync Options, select Push the selected device configuration to the group.

    Note: For BIG-IP 12.1.6 and earlier, select Sync Device Group and select the Overwrite Configuration box.

    Note: The BIG-IP system may detect that the new device has a more recent configuration. The Overwrite Configuration option overrides this condition.

  12. Select Sync.
  13. The Sync Summary status should show In Sync.

Fail over to the new BIG-IP system

To make the new BIG-IP system the active device, perform the following procedure:

Impact of procedure: Failing over to a new BIG-IP system may cause service disruptions if the upstream switch or router is unable to quickly update either the Content Addressable Memory (CAM) table or Address Resolution Protocol (ARP) for the new MAC address. The F5 MAC masquerade feature can help with this condition. For more information about configuring MAC Masquerade, refer to K13502: Configuring MAC masquerade (11.x - 16.x).

Note: You should perform the following procedure on each BIG-IP system that you have added to the device group.

  1. Log in to the Configuration utility of the new BIG-IP system.
  2. Go to Device Management > Devices and select the local BIG-IP system designated with (Self).
  3. Select Release Offline.
  4. To determine the traffic group's Current Device and Next Active Device, go to Device Management > Traffic Groups and select traffic-group-1.
  5. If the new BIG-IP system is listed as the Next Active Device, skip to step 9.
  6. Log in to the Configuration utility of the BIG-IP system listed as Next Active Device.
  7. Go to Device Management > Devices and select the local device designated with (Self).
  8. Select Force Offline. The new BIG-IP system should now be listed as the Next Active Device.
  9. To make the new BIG-IP system active, log in to the BIG-IP system listed as Current Device.
  10. Go to Device Management > Devices and select the local BIG-IP system designated with (Self).
  11. Select Force to Standby. The new BIG-IP system should now be the Current Device.

Verify traffic on the new BIG-IP system

To verify that the new BIG-IP system is successfully passing application traffic, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You should perform the following procedure on each BIG-IP system added to the device group.

  1. Log in to the Configuration utility of the new BIG-IP system.
  2. Go to Statistics > Performance and select the Connections and Throughput tabs to confirm that the statistics match those of the old BIG-IP system.
  3. You should also test connectivity using the appropriate client software for your applications.
  4. If there are connectivity issues through the new BIG-IP system and you need to fail back, go to Device Management > Traffic Groups and select traffic-group-1.
  5. Fail over to the existing device by selecting Force to Standby. The existing BIG-IP should now be active.

Remove old BIG-IP systems from the device trust and device group (optional)

To remove old BIG-IP systems from the device trust and device group, perform the following procedure:

Impact of procedure: You should perform this procedure only once the new BIG-IP system or pairs are successfully processing application traffic.

  1. Log in to the Configuration utility of the new BIG-IP system.
  2. Go to Device Management > Device Groups and select the appropriate device group.
  3. For Members, in the Includes list, select the existing devices and move them to Available.
  4. Select Update.
  5. Go to Device Management > Device Trust > Peer List.
  6. From Peer Authority Devices, select the boxes of the existing devices.
  7. Select Delete.

    Note: The deleted devices still attempt to communicate with the new devices. To resolve this issue, continue to step 8.

  8. Log in to the Configuration utility of the existing or older BIG-IP devices and repeat this procedure.
