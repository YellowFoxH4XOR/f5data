Description
  • What is the advanced option SSL Configuration Bypass on Client Certificate Failure?
  • Are you failing to get a client certificate, requested by the server, and you need to mitigate the situation to allow the SSL traffic to bypass the BIG-IP system?
Environment
  • SSL Handshakes are failing due to client certificate issues.
  • Configuration objects involved are the SSLO virtual and the applicable SSL Profile.
Cause
  • Bypass on Client Certificate Failure feature is disabled (default)
Recommended Actions
  1. Navigate to SSL Orchestrator > Configuration > 
  2. Click applicable topography to modify or create a new one
    1. If you are modifying a current topography click on the pencil icon for SSL Configuration
    2. When you are creating a new topology step two is to Create the SSL Configuration
  3. Click Show Advanced Setting
  4. Check/uncheck the box next to Bypass on Client Certificate Failure.
For outbound scenarios an option to enable or disable SSL forward proxy bypass, when failing to get a client certificate that the server (pool member) asks for, is available…Bypass on Client Certificate Failure.  This setting allows the underlying SSL Forward Proxy process to bypass SSL decryption if it detects a Certificate request message from the server, as in when a server requires mutual certificate authentication.
Additional Information

It is recommended to leave this disabled. When the above bypass option is used in conjunction with Bypass on Handshake Alert it can create a security vulnerability. If a colluding client and server can force an SSL handshake error, or force client certificate authentication, they can effectively bypass SSL inspection. It is recommended that these settings be left disabled.
 
If the issue is with the SSL Handshake on the Client-side, such as a bad CA certificate, the handshake will still fail, and a reset will be sent to the Client.
