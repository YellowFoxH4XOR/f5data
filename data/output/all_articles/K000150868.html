K000150868: Updating an Expired Certificate within a Certificate Bundle within the CLI

Type
Support Solution
Published
2025-04-15
Updated
2025-04-15
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.5
Source
https://my.f5.com/manage/s/article/K000150868

Description

An expired certificate in the certificate bundle is causing the BIG-IP to close connections doe to a bad SSL certificate.

Environment

BIG-IP LTM 16.1.5

Cause

Expired Certificate in a bundle

Recommended Actions

Identify the certificate and location within the bundle using the following command:

openssl crl2pkcs7 -nocrl -certfile <replace_with_certificate> | openssl pkcs7 -print_certs -text -noout | less

Then using either a text editor within the CLI such as VI, or by exporting the certificate bundle and opening it up, locate the expired certificate and replace the old certificate with the new certificate.

Save the updated bundle or import the updated bundle into the GUI.

To check that the certificate successfully was updated with either the above command or check through the GUI under System>Certificate Management> Traffic Certificate Management>SSL Certificate List to see the expiration date has updated.
