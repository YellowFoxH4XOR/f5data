K50600670: Error Message: primary shard is not active Timeout

Type
Support Solution
Published
2021-08-03
Updated
2023-10-13
Applies to

Source

Description

The DCD experiences an out-of-memory condition causing instability to the Elasticsearch cluster.

The Elasticsearch log file, /var/log/elasticsearch/eslognode.log contains repeated "primary shard is not active Timeout" messages similar to the following:

org.elasticsearch.action.UnavailableShardsException: [access-utility_2020-11-07t18-47-39+0100][0] primary shard is not active Timeout: [1m],

Environment

  • BIG-IQ
  • DCD cluster
  • Elasticsearch

Cause

Out of memory conditions resulted in orphaned Elasticsearch indices.

Recommended Actions

Note: In steps 2 and 3 omit -k and https:// for BIG-IQ 7.x also note that the + is URL encoded as %2B

  1. Identify the orphaned indices reported in the log messages by reviewing the /var/log/elasticsearch/eslognode.log file.

    less /var/log/elasticsearch/eslognode.log

    Enter q to quit out of less

  2. View the orphaned indices using the following syntax:

    curl -k https://localhost:9200/<index name>

    For example:

    curl -k https://localhost:9200/access-utility_2020-11-07t18-47-39%2B0100

  3. Delete the orphaned indices using the following syntax:

    curl -k -X DELETE https://localhost:9200/<index name>

    For example:

    curl -k -X DELETE https://localhost:9200/access-utility_2020-11-07t18-47-39%2B0100
