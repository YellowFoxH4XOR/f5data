K44502103: Application loading very slow, connection stall, HTTP response not returned to client - after upgrade to 16.x

Type
Support Solution
Published
2021-07-19
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.X.X, 16.0.X, 16.1.0, 16.0.1, 16.0.0, 16.1.X, 16.1.2, 16.1.1, 16.1.3
Source
https://my.f5.com/manage/s/article/K44502103

Description

Application loading very slow when accessed through a BIG-IP virtual server.

Packet trace shows the BIG-IP doesn't forward a HTTP response from the pool member to the client - connection is stalled.

TCP Zero Window observed between the BIG-IP and pool member.

Environment

  • OneConnect profile applied

Cause

Bug ID 1020549

Recommended Actions

An immediate workaround is to remove the OneConnect profile. in most cases there is no impact from this, but if the virtual server is configured to load balance per HTTP request (for example, based on Host header or persistence cookies), you may need to use an iRule with LB::detach to avoid the behaviour described in K7964.

There is no permanent fix for ID 1020549 at the time of this article's publication, but an engineering hotfix can be requested by opening a service request with F5 Support.
