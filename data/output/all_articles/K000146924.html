What Happened?

Health monitor marked endpoint as down.

  • Packet capture shows three way handshake.
  • HTTP GET and Receive string is fine.
  • Standard health monitor works and ICMP too. 
  • Firewall allows traffic. 

This article addresses a solution for advance HTTP health monitor:

  • Endpoint is marked as down only when using HTTP health monitor with send/receive strings.
  • ICMP, Standard HTTP health monitor works as expected.
  • cURL tool, using same send string works fine. HTTP Status code "200 OK" is received. 

Environment

  • F5 Distributed Cloud DNS
  • F5 Distributed Cloud DNS Load Balancer

Cause

  • Carriage Return (CR) and Line Feed (LF) termination characters are key to the accurate construction and parsing of HTTP requests, regardless of the HTTP version. 
  • One of the LF \n or CR \r termination characters may be missing in the send string.  (used to construct monitor Send Strings).

Resolution/Answer

Send string to fix the issue:

Depending on the HTTP version, there are requirements to make the health monitor work.

For HTTP 1.1 , follow:

Use the following send string. It will fix the config -

  GET /status HTTP/1.1\r\nHost: \r\nConnection: Close\r\n\r\n

Example of missing \r\n:

Note the missing \r\n in below health monitor -not working- config.  Keep in mind, below probe string will be sent to every pool member to decide whether the pool member is marked as down or up.  

As a note, there are double backslash (\) due to the JSON format.

== JSON snippet ==

"spec": {
   "http_health_check": {
     "send": "HEAD / HTTP/1.0\\r\\n",
     "receive": "HTTP/1.",
     "health_check_port": 443
   }
}
