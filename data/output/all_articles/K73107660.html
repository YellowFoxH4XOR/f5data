Known Issue

An iControl REST Worker may become unstable following a REST call that ended in error.

This issue occurs when the following condition is met:

  • An iControl REST Worker processes specific REST calls that end in error, such as creating a new active policy.

Note: When you use iControl REST, you should create policies as inactive and then activate them through the apply-policy task.

Impact

You may experience unreliable behavior from the ASM REST API.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You are unable to create or modify BIG-IP ASM configuration objects.
  • iControl REST API tasks such as apply-policy occasionally do not run.
  • REST calls that end in error are not correctly rolled back on the system.

Workaround

When the issue occurs as you are creating a policy, you can prevent the issue by making the policy inactive by using the "active" : false setting and activating it with the apply-policy task on a subsequent REST call. When the issue occurs as a result of other conditions, you can recover from the issue by restarting restjavad. You can perform these tasks as follows:

Prevent the issue by making a policy inactive upon creation

The following two example curl command strings enable you to prevent the issue:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Creating an inactive policy

  1. Log in to the command line of the BIG-IP system.
  2. To create an inactive policy, use the following command syntax:

    curl -s -k -u admin:admin -X POST -H "Content-type: application/json" -d '{ "name" : "example_policy", "virtualServers" : [], "active" : false, "enforcementMode" : "transparent", "learningMode" : "manual" }' https://mybigip/mgmt/tm/asm/policies

Activating the policy after you have created it

  1. Log in to the command line of the BIG-IP system.
  2. To activate the policy after you have created it, use the following command syntax:

    curl -s -k -u admin:admin -X POST -H "Content-type: application/json" -d '{ "policyReference": { "link":"https://localhost/mgmt/tm/asm/policies/nOUSf2xHk_PIET_Rm5N8YA" }}' https://mybigip/mgmt/tm/asm/tasks/apply-policy

Recover from the issue by restarting restjavad on the BIG-IP system

To recover from this issue, you can restart restjavad. To do so, perform the following procedure:

Impact of workaround: The iControl REST interface is unavailable while the restjavad process restarts.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the restjavad process, type the following command:

    restart /sys service restjavad
