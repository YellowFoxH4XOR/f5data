K000092429: Regular expressions with "?!" are not supported in VirtualServer

Type
Support Solution
Published
2022-10-07
Updated
2022-10-07
Source
https://my.f5.com/manage/s/article/K000092429

Description

When attempting to create a Virtualserver resource with a regex path that uses the "?!" negative lookahead syntax, you'll encounter an error similar to the following:

Invalid value: "~ ^/path/(?!.*\/value)(.*)": must be a valid regular expression: error parsing regexp: invalid or unsupported Perl syntax: `(?!`

 

 Environment

Kubernetes
Nginx+ Ingress Controller
Custom Resource Definition(CRD) Virtualserver
golang

 Cause

The golang regex libraries used to validate the regex input into our Ingress Controller do not recognize "?!" as a valid syntax string. This is known issue documented here:
https://github.com/nginxinc/kubernetes-ingress/issues/797

Here is a resource that shows the syntax as currently "NOT SUPPORTED" in golang:
https://github.com/google/re2/wiki/Syntax
   "(?!re) before text not matching re (NOT SUPPORTED)"

 
Recommended Actions

First, lets take a quick look at what this "?!" negative lookahead syntax does.
The "?!" is used in Perl Compatible Regular Expressions(PCRE) to negate a preceding value as mentioned in the above google github link
In short though, the "?!" negates the value following it, so if the value is present the regex won't match.

Example:

  • regex: ~*^/path/((?!ABC123)[^/]*)(.*\.json.*)
    •  would match on "/path/DEF456/foo.json"
    • but would NOT match on "/path/ABC123/foo.json"

 

Either alter your regex to avoid using the "?!" if possible, or try using multiple paths in your yaml definition to create separate Nginx Location directives like the following example:

apiVersion: k8s.nginx.org/v1
kind: VirtualServer
metadata:
  name: regex-vs
spec:
  host: webapp.example.com
  upstreams:
  - name: webapp1
    service: webapp1-svc
    port: 80
  - name: webapp2
    service: webapp2-svc
    port: 80	
  routes:
  - path: ~*^/path/ABC123/(.*\.json.*)
    action:
      pass: webapp1
  - path: ~*^/path/([^/]*)(.*\.json.*)
    action:
      pass: webapp2
