Topic

When configured for NT LAN Manager (NTLM) Pre-Authentication, Internet Explorer (IE) may not include POST data on a subsequent request following client authentication. As a result, credentials submitted using the Logon Page may not be transmitted to the BIG-IP APM system.

Beginning from June 15, 2022, Microsoft announced the end of support for the Internet Explorer browser. As a result, BIG-IP APM  no longer supports Microsoft Internet Explorer. If you are using Internet Explorer as described in this article, F5 recommends configuring your environment to use a supported browser. For more information, refer to K12501517: BIG-IP APM support Microsoft Internet Explorer.

Description

After receiving a 401 Unauthorized response with header WWW-Authenticate: NTLM from the server, NTLM authentication conducts the following three-way handshake:

1) Type1: client sends a NEGOTIATE_MESSAGE
2) Type2: server responds with a CHALLENGE_MESSAGE
3) Type3: client responds with an AUTHENTICATE_MESSAGE

When NTLM Pre-Authentication is enabled, IE caches credentials after receiving a CHALLENGE_MESSAGE message, and the credentials are used for subsequent requests. IE initiates subsequent requests with a NEGOTIATE_MESSAGE message. If the request is a POST, IE does not include POST data within the NEGOTIATE_MESSAGE; POST data is included only in the AUTHENTICATE_MESSAGE message. IE uses this functionality to save bandwidth.

As a result, while authenticating through a Logon Page, if IE sends a POST NEGOTIATE_MESSAGE message without POST data, the BIG-IP APM system cannot populate session variables. This situation does not occur if the POST request follows another HTTP request in the same TCP connection. This time the POST message is not sent with a NEGOTIATE_MESSAGE and includes the POST data.

To prevent IE from sending a POST without POST data, you can disable Pre-Authentication in IE by referencing the following Microsoft article 251404.
