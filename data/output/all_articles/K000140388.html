Description

BIG-IP DNS monitored objects may be marked down and back up, however the returned status message indicates (state: success)

  • Monitored objects flap
  • Error messages logged in /var/log/gtm

alert gtmd[PID]: 011a4003:1: SNMP_TRAP: Pool <pool name> member <virtual server> (ip:port=IP_Address:port) state change green --> red ( Monitor <monitor name> from gtmd : state: success)

 

Environment

  • BIG-IP DNS managing DNS objects
  • BIG-IP any module with monitored resources

 

Cause

The cause of the issue is incorrect BIG-IP gtm server object where the devices communicate with other BIG-IP gtm servers located in remote datacenters. The incorrect configuration entails configuration gtm server object with both address and translation address defined. Both address and translation address will be defined as self IPs resulting in both addresses establishing iQuery connections. If a probe response matches the IP address defined as address gtmd will no send the response as address is not supposed to be directly connected. The IP address defined as address if there is translation is generally a public IP address which should be NATed by firewalls etc., to the defined translation address.

 

Recommended Actions

  1. If BIG-IP gtm server is to communicate with other BIG-IP servers in remote datacenters, configure address as the IP address reachable by remote BIG-IP servers.
  2. Note that the IP address defined as address MUST not have a corresponding self IP address.
  3. If the IP address configured as address for the device has a corresponding self IP address, delete the self IP address.
  4. Define the translation address which MUST have a corresponding self IP address.

 

Additional Information

Sample configuration showing incorrect configuration which will result in monitored objects flapping as well as correct configuration to avoid monitored objects flapping.

 

Incorrect configuration

---------------------------------

gtm server dnsnat.example.com {

  addresses {

    203.0.113.1 {

      device-name dnsnat.example.com

      translation 192.0.2.1

    }

    2001:0DB8:8000:6::6 {

      device-name dnsnat.example.com

      translation 2001:0DB8:8000:6::7

    }

  }

  datacenter Example_DC

  devices {

    dnsnat.example.com {

      addresses {

        203.0.113.1 {

          translation 192.0.2.1

        }

        2001:0DB8:8000:6::6 {

          translation 2001:0DB8:8000:6::7

        }

      }

    }

  }

  monitor bigip

  product bigip

}

 

net self /Common/pub_IPv6_self {

  address 2001:0DB8:8000:6::6/32

  allow-service {

    tcp:4353

  }

  traffic-group /Common/traffic-group-local-only

  vlan /Common/external_vlan

}

 

net self /Common/translation_IPv6_self {

  address 2001:0DB8:8000:6::7/32

  allow-service {

    tcp:4353

  }

  traffic-group /Common/traffic-group-local-only

  vlan /Common/external_vlan

}
