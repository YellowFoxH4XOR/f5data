K50146301: HTTPS monitor attached to a DNS virtual server object fails

Type
Support Solution
Published
2021-02-26
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP DNS: 15.X.X, 15.0.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.X, 15.1.1, 15.1.0, 15.0.1, 15.0.0, 15.1.2
Source
https://my.f5.com/manage/s/article/K50146301

Description

Applying an HTTPS health monitor to a Generic Host configured on BIG-IP DNS marks the resource as unavailable.
  • Messages similar to the following is observed from /var/log/gtm:
      01333001:3: SSLConnect: SSL error:14094410:SSL routines:ssl3_read_bytes:sslv3 alert handshake failure

  Environment
  • BIG-IP DNS
  • Generic Host server object
  • GTM/ DNS HTTPS health monitor attached

Cause

Possible mutual authentication issues between the server being monitored and the BIG-IP device tasked to probe the server object.

Recommended Actions

Make sure that if the virtual server is configured with client authentication that the GTM / DNS HTTPS health monitor used is not the default one but rather a custom HTTPS monitor that has the required certificate and key configured for the health monitoring to succeed.
