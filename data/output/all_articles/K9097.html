K9097: Realm administrators are redirected to the primary cluster node when logging on to the webtop

Topic

By default, in a load-balanced cluster configuration, FirePass redirects realm administrators to the primary (master) cluster node when they log on to the FirePass webtop. This behavior is by design, since the Admin Console link on the webtop links to the FirePass controller, to which the realm administrator is connected. Most FirePass configuration settings are synchronized from the primary cluster node to the secondary (slave) cluster nodes, which overwrites the settings on the secondary cluster nodes. Therefore, you should perform most configuration tasks on the primary cluster node. For a list of settings that are not synchronized from the primary cluster node to the secondary cluster nodes, refer to K8816: Configuration parameters that are not synchronized between members of a cluster.

If the Allow optional manual logon to slave nodes from master logon page check box is selected on the Clustering: Settings page, realm administrators can work around this behavior by manually selecting the desired secondary cluster node from the Preferred node menu on the master logon page.

Note: The Allow optional manual logon to slave nodes from master logon page check box only appears if load balancing is enabled on the Clustering: Settings page.

Additionally, starting in FirePass 6.0.2, you can change the default behavior by selecting the Do not redirect realm administrators from cluster slave to cluster master check box on the Device Management: Security: Administrative Realms page.
