Description

This article may help determine why a Virtual server isn't available by users connected to the BIG-IP via an APM VPN tunnel

Environment

  • APM
  • VPN
  • Virtual server(s) with limited VLAN/Tunnel listeners

Cause

When the connectivity profile isn't included in the "VLANs and Tunnels" list on the virtual server it won't listen for traffic from any VPN users connected to the APM via that connectivity profile

Recommended Actions
Include the connectivity profile in the "VLANs and Tunnals" for the virtual server(s) that aren't responding to requests:

  1. Identify the connectivity profile of the VPN users
    a) Find the virtual server used for the VPN connection from "Local Traffic >> Virtual Servers"
    b) Scroll down to the "Access Policy" section and note the "Connectivity Profile"
  2. Adjust the virtual server(s) that aren't responding
    a) Find the virtual server(s) from "Local Traffic >> Virtual Servers"
    b) In the "Configuration" section find the "VLANs and Tunnels"
    Note: If your virtual server is configured with the "VLAN and Tunnel Traffic" set to "All VLANs and Tunnels" then the connectivity failure is unlikely to be caused by this specific configuration object.
    c) Include the previously noted "Connectivity Profile" in the "Selected" section
