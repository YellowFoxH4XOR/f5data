Description

Error when updating ACLs for SNMP Access

Exception caught in Management::urn:iControl:Management/SNMPConfiguration::set_client_access() Exception: Common::OperationFailed primary_error_code : 17237778 (0x01070712) secondary_error_code : 0 error_string : 01070712:3: unable to open file: /tmp/confpp.dat

Environment

  • BIG-IP VE
  • found in v13.0.0

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have serial console access to the BIG-IP system.
  • You have administrative or root user access to the command line.

Cause

  • Disk space issue or corrupt file system

Recommended Actions

  1. Check available disk space, you can use the df -h command.

    Note: On a multi-blade VIPRION system, you should run the commands from each blade. To connect to the terminal of a blade from another blade, use the ssh slot<slot number> command syntax.

    For example, the df -h command may produce the following output, which indicates that the root file system is at 100 percent usage:

    Filesystem      Size  Used Avail Use% Mounted on
    /dev/md4        427M  427M     0 10% /
    none             24G  2.2M   24G   1% /dev/shm
    /dev/md6        3.2G   76M  2.9G   3% /config
    /dev/md5        3.3G  2.5G  636M  80% /usr
    /dev/md7        3.0G  2.6G  0.4G  95% /var
    /dev/md1         30G  3.9G   25G  14% /shared
    /dev/md2        6.9G  192M  6.4G   3% /var/log
    none             24G   54M   24G   1% /shared/rrd.1.2
    none             24G   21M   24G   1% /var/tmstat

    Note: It is normal for /usr to show high disk space usage. For more information, refer to  K23607394: The /usr partition shows high disk space usage

  2. In many cases, non-critical maintenance files are apparent and can be safely removed. For example, you should delete old tcpdump, qkview, and core files from the system or move them to a network share. You can use the find command to locate old maintenance-related files. For example, to locate the 20 largest files on the system, use the following command syntax:

    find <dir> -xdev -type f -exec du {} \; | sort -rn | head -20

    For example, the following find command is used to locate the 20 largest files (measured in KB) in the /shared partition, some of which you can safely remove, such as the 2 GB (2189582 KB) tcpdump file, and the 18 MB (18460 KB) core file:

    Note: The following output indicates that the /shared/images directory contains two ISO installation files.
    You can safely remove older installation files from the system.
    However, do not remove installation images for versions that are currently running on the system.

    find /shared/ -xdev -type f -exec du {} \; | sort -rn | head -20

    Example output :
    2189582 /shared/tcpdump.cap
    1277060 /shared/images/BIGIP-11.3.0.2806.0.iso
    1186512 /shared/images/BIGIP-11.2.1.797.0.iso
    18460 /shared/core/mcpd.bld3341.0.core.gz
    5200 /shared/rrd.1.2/endpisession

  3. F5 recommends that you use the following guidelines to maintain adequate disk space on the system, Delete files that are no longer needed.

  4. Creating a forcefsck file in the root directory

    This procedure allows you to schedule a file system check during the next reboot of the system by creating a blank file, named forcefsck, that resides in the / directory. The presence of the /forcefsck file causes the system to perform a file system check the next time the system boots. To do so, perform the following procedure:

    Impact of procedure: Rebooting the BIG-IP system in a standalone configuration will interrupt traffic processing. If the system is configured as part of a high-availability (HA) pair, the device may fail over. F5 recommends that you perform this procedure during a maintenance window.

  5. Log in to the command line.
  6. To create the /forcefsck file, type the following command:

    touch /forcefsck

    During the next reboot, the /forcefsck file causes the system to perform a file system check.

  7. If you want to reboot the system at this time, type the following command:

    reboot

    The system reboots and performs the fsck file system check. Once the fsck operation has finished checking the file systems, the system continues to boot normally into the proper run levels.

    Note: The /forcefsck file is deleted as the system boots and does not remain for subsequent reboots.
