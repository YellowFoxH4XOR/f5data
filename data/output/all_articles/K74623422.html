Description

You have a custom HTTP or HTTPS monitor send string which is not working and BIG-IP receives a 403 Forbidden response from backend server

Environment

  • HTTP or HTTPS Health Monitor
  • You have a send string monitor like "GET / HTTP/1.1\r\nHost: www.exampledomain.com\r\nConnection: Close\r\n\r\n"
  • ?????You test the 'Send String' using openssl s_client (follow article K81239024)
  • The response/result is similar to below output: 
    [root@bigip:Active:Standalone] config # (echo -e "GET / HTTP/1.1\r\nHost: www.exampledomain.com\r\nConnection: Close\r\n\r\n";sleep 1) | openssl s_client -connect www.exampledomain.com:443
---
HTTP/1.1 403 Forbidden
Server: nginx
Date: Fri, 03 Jun 2022 06:29:11 GMT
Content-Type: text/html
Content-Length: 118
Connection: close
Strict-Transport-Security: max-age=31536000
Permissions-Policy: interest-cohort=()

<html>
<head><title>403 Forbidden</title></head>
<body>
<center><h1>403 Forbidden</h1></center>
</body>
</html>
read:errno=0

Cause

In some application, User-Agent header is required to be included in the HTTP Request. You need to include it also in the monitor Send String.

Recommended Actions

Use a similar Send String like below:

GET / HTTP/1.1\r\nHost: www.exampledomain.com\r\nUser-Agent: Mozilla/5.0 (Windows NT 5.1; rv:2.0.1) Gecko/20100101 Firefox/4.0.1\r\nConnection: Close\r\n\r\n
