K000092951: How to change the setting for ENABLE_LEGACY_FSGROUP_INJECTION

Type
Support Solution
Published
2022-12-02
Updated
2023-07-18
Applies to
  • Aspen Mesh: 1.11, 1.9
Source
https://my.f5.com/manage/s/article/K000092951

Description

In Kubernetes versions 1.18 and older the “ENABLE_LEGACY_FSGROUP_INJECTION” setting was required. By default, Istio uses the UID of 1337 which can overlap with other application containers. On Kubernetes 1.19 and newer, the setting the “ENABLE_LEGACY_FSGROUP_INJECTION” is not required.
 

Environment

  • Aspen Mesh: 1.9.x, 1.11.x
  • Kubernetes: 1.17.x - 1.22.x
  • Red Hat OpenShift: 4.6.x - 4.8.x
 

Cause

By default, OpenShift does not allow containers running with user ID 1337. You must enable containers running with UID 1337 for Istio’s service accounts by running the command below.
 

Recommended Actions

Make sure to replace istio-system if you are deploying Istio in another namespace: 

oc adm policy add-scc-to-group anyuid system:serviceaccounts:istio-system


Add the following configuration to the Aspen Mesh values file for istiod and run a helm upgrade. It will apply to the configuration. 

## Discovery Settings 
pilot: 
  #Insert after pilot setting 
  env: 
    ENABLE_LEGACY_FSGROUP_INJECTION: "false"


For example:

helm upgrade istiod ${aspenmesh_folder}/manifests/charts/istio-control/istio-discovery --namespace istio-system -–values aspenmesh-values.yaml


To view the values file run the command:  

helm get values istiod -n istio-system


Additional Information

The fsGroup is a security context setting that defines a group in which Kubernetes will change the permissions of all files in volumes to when volumes are mounted by a pod.
