Source

Description

  • Unable to create new ASM security policy
  • On GUI an error message similiar to the following appears:

    Could not update policy; Error: DBD::mysql::db begin_work failed: Already in a transaction at /usr/local/share/perl5/F5/ASMConfig/Handler/SetActive.pm line 118.

  • The following error message can be seen on /var/log/asm

    Nov 30 17:56:06 ASM1.example.com crit g_server_rpc_handler.pl[11894]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): DBD::mysql::db begin_work failed: Already in a transaction at /usr/local/share/perl5/F5/ASMConfig/Handler/SetActive.pm line 118.

Environment

  • ASM provisioned
  • ASm security policy

Cause

A configuration update had a lock on some tables in the database.

Recommended Actions

Restart the asm process

Impact: Restarting asm will cause a brief traffic disruption, hence we recommend to perform below procedure during a maintenance window

  1. Connect to CLI
  2. Restart asm

    bigstart restart asm
