Topic

BIG-IP Microsoft Remote Desktop (MSRDP) persistence may not function in an environment where the destination MSRDP servers reside in a route domain.?

Description

When Session Directory creates an encrypted Microsoft Terminal Services cookie to send to an MSRDP user, it is not aware of the BIG-IP route domain configuration requirements, and the server IP address contained in the cookie does not include BIG-IP centric route domain syntax. The BIG-IP system can parse Session Directory cookies, but the system is unable to modify the contents of the encrypted cookie. The cookie is passed to the connected MSRDP user. Subsequent requests from the MSRDP user, connecting to a virtual server configured with the MSRDP persistence profile, present the Microsoft Terminal Services cookie and then the BIG-IP system attempts to determine the IP address of the destination resource held in the cookie. The IP address obtained by the BIG-IP system from the MSTS cookie does not contain route domain information and may not match the configured members of the virtual server associated pool. When the BIG-IP system is unable to find a matching IP address, the connection is load balanced as a new connection request.

F5 Product Development tracked this issue as ID 655724, and it was fixed in BIG-IP 13.1.0. For information about upgrading, refer to the BIG-IP release notes.

Recommendations

To work around this limitation, you can use an alternate form of persistence such as source address affinity (source_addr).

Impact of workaround: User connections will be persisted to MSRDP servers based on the source IP address of the user.
