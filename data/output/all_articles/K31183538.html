Known Issue

iRules may appear to be associated with the incorrect administrative partition.

This issue occurs when all of the following conditions are met:

  • The virtual server resides in a non-default partition (a partition other than the Common partition).
  • iRules from different partitions are associated with the virtual server.
  • You modify the order of the associated iRules.

If multiple iRules are associated to a virtual server, the BIG-IP system groups the iRules by the partition that they are associated with. When a virtual server uses iRules from different partitions, and a user changes the order of the iRules listed for the virtual server, the partition labels are not immediately updated. As a result, the iRule from one partition now appears to be under a different partition.

Impact

None. This issue is cosmetic; the iRule is actually still associated with the correct partition.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Immediately after you change the order of the iRules, the affected iRule appears to be associated with an incorrect partition.

    Note: After you click Finish to save your changes, the Configuration utility displays the Resources screen. If you click Manage, the system displays the order of iRules that you specified, as well as the iRules listed under the correct partition names.

Workaround

To work around this issue, you can edit the virtual server and restore the name to the correct partition location in the list. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.
  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Select the affected virtual server.
  4. Click Resources.
  5. Click Manage.

    The system now lists iRules under the correct partition names.
  6. Click Cancel.
