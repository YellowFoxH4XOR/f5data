K12362: VIPRION systems may assign an all-zero MAC address to a VLAN when the 'vlan.assignment' DB variable is set to 'global'

Known Issue

This is the result of a known issue. If you set the bigpipe vlan.macassignment DB variable to global on a BIG-IP VIPRION system, the system may assign an all-zero MAC address to one ore more VLANs. For example:

[root@VIP-001:/S1-green-P:Active] config # ifconfig -a | grep HWaddr
eth0 Link encap:Ethernet HWaddr 00:01:D7:74:17:80
eth0:clst Link encap:Ethernet HWaddr 00:01:D7:74:17:80
eth0:mgmt Link encap:Ethernet HWaddr 00:01:D7:74:17:80
eth2 Link encap:Ethernet HWaddr 00:00:00:00:00:00
external Link encap:Ethernet HWaddr 00:00:00:00:00:00
internal Link encap:Ethernet HWaddr 00:00:00:00:00:00
mgmt_bp Link encap:Ethernet HWaddr 00:01:D7:74:17:81
tmm_bp Link encap:Ethernet HWaddr 02:01:23:45:00:FE
tmm0 Link encap:Ethernet HWaddr 00:98:76:54:32:10
[root@VIP-001:/S1-green-P:Active] config #

An all-zero MAC address is an invalid source MAC address. As a result, traffic fails to pass over the affected VLANs.

To determine the current value of the vlan.macassignment DB variable, type the following command:

bigpipe db vlan.macassignment

For example:

[root@VIP-001:/S1-green-P:Active] config # bigpipe db vlan.macassignment
Vlan.MacAssignment = unique
[root@VIP-001:/S1-green-P:Active] config #

F5 Product Development tracked this issue as ID 340651 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by setting the vlan.macassignment DB variable to the default value of unique. This value instructs the BIG-IP system to assign a unique MAC address to each VLAN. To set the DB variable to unique, type the following command from the BIG-IP command line:

bigpipe db vlan.macassignment unique

Note: The above command takes effect immediately. You do not need to restart the system or any services.
