K84967514: Logging levels for access policy components can now be configured on a per-policy basis

Issue

Old Behavior

In versions prior to 12.0.0, the logging verbosity of a BIG-IP APM component can only be configured globally and is applied to all access policies.

New Behavior

Beginning in BIG-IP APM 12.0.0, the logging levels for access policy components can be configured separately for each access policy. You can create a custom logging profile and then add the logging profile to the desired access policy. This configuration method offers the advantage of keeping the quantity of log information low because verbose logging can be applied to specific access policies as needed.

The log levels for following access policy items can be specified within the APM logging profile:

  • Access Policy
  • Per-Request Policy
  • ACL
  • Single sign-on (SSO)
  • Secure Web Gateway
  • ECA

Impact

Logging levels for affected BIG-IP APM components are now configured using the Configuration utility rather than the Traffic Management Shell (tmsh).

Recommended Actions

You can configure log settings for an access policy by using the Configuration utility. To do so, perform the following procedures:

  • Configuring an access system logging profile
  • Applying the logging profile to an access profile
  • Removing a logging profile from an access profile

You must meet the following prerequisite to use these procedures:

  • You have administrative access to the Configuration utility.

Procedures

Configuring an access system logging profile

This procedure creates a custom logging profile in which you can specify the desired logging levels for the BIG-IP APM components.

Impact of procedure: You should only select the Debug log level on a production system if advised to do so by F5 Technical Support. The Debug log level produces large amounts of data, which may negatively impact performance.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Overview > Event Logs > Settings.
  3. Click Create.
  4. Type a name for the new profile.
  5. Select the Enable Access System Logs check box.
  6. Click Access System Logs to configure the log settings.
  7. For Publisher, verify that the correct publisher is listed.
  8. Configure the log levels for the BIG-IP APM components.

    Important: To ensure BIG-IP APM session reports are populated, you must ensure the logging profile is configured to log at the Notice level or higher. For more information, refer to K44555523: APM Session Reports require the APM access policy log level to be configured for Notice or higher.

  9. Click OK.

Applying the logging profile to an access profile

After you have a BIG-IP APM logging profile configured with the desired logging levels, you can apply the profile to the access policy.

Impact of procedure: Performing this procedure increases the quantity of information recorded to the /var/log/apm file.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies)
  3. Click the access profile for which you want to apply the logging profile.
  4. Click the Logs tab.
  5. In the Available list, select the logging profile you want and move it to the Selected list.
  6. Click Update.

Removing a logging profile from an access profile

Important: To ensure that the Notice level log data is recorded in the /var/log/apm file, you must keep the default-log-setting profile applied to each access profile.

Impact of procedure: Performing this procedure reduces the quantity of log data recorded in the /var/log/apm file.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies)
  3. Click the access profile from which you want to remove the logging profile.
  4. Click the Logs tab.
  5. In the Selected list, select the logging profile you want to remove from the access profile and move it to the Available list.
  6. Click Update.
