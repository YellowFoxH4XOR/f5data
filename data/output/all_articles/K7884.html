Known Issue

This is a result of a known issue. The f5passwd command line utility, which is used to change user passwords and update the configsync database, incorrectly sets the password as $2 instead of the user specified password.

F5 Product Development tracked this issue as CR80412, and it was fixed in BIG-IP versions 9.3.1 and 9.4.2. For information about upgrading, refer to the LTM, GTM, ASM, Link Controller, or WebAccelerator release notes.

Workaround

You can work around this issue by directing the f5passwd utility to correctly use the password specified by the user that is held by the variable $2, and write the correct password to file. To do so, perform the following procedure:

Important: The following workaround requires making changes to the f5passwd utility script. F5 recommends that you make a backup copy of the script before making any changes.

  1. Log in to the command line.
  2. Back up the current f5passwd script by typing the following command:

    cp /usr/bin/f5passwd /usr/bin/f5passwd.original

  3. Use a text editor to edit the /usr/bin/f5passwd script.
  4. Locate the following block of code within the script:

    # check and see if we were given a password on the cmdline
    if [ -z "$2" ] ; then
    echo "Changing password for user $theuser."
    # we weren't supplied a password, so read the password.
    read -s -r -p "New BIG-IP password: " newpassword
    echo
    read -s -r -p "Retype new BIG-IP password: " newnewpassword
    echo
    if [ "X$newpassword" != "X$newnewpassword" ] ; then
    echo "Passwords do not match."
    exit 1
    fi
    else
    newpassword='$2'
    fi

  5. Locate the following line:

    newpassword='$2'

  6. Change the line to the following:

    newpassword="$2"

  7. Save the changes.
