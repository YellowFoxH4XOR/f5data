K000160002: Kerberos authentication not working

Type
Support Solution
Published
2026-02-13
Updated
2026-02-13
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160002

Description

Kerberos authentication on BIG-IP APM may fail for end users after a service account password change in Active Directory. Users are unable to authenticate, and the following error messages appear in the /var/log/apm` log file:

  • AD module: authentication with '<username>' failed: Preauthentication failed, principal name: <username>@DOMAIN. Invalid user credentials. (KRB5KDC_ERR_PREAUTH_FAILED)
  • AD module: krb5_get_init_creds_password(): Preauthentication failed, principal name: <username>@DOMAIN. Invalid user credentials. (KRB5KDC_ERR_PREAUTH_FAILED)

This issue typically occurs when the Kerberos keytab file on the BIG-IP APM system is not updated after the Active Directory service account password has been changed.

Environment

  • BIG-IP APM with Kerberos end-user logon authentication configured
  • Windows Active Directory as the Key Distribution Center (KDC)
  • Service account password recently changed in Active Directory
  • Keytab file not regenerated or updated after password change

Cause

When a service account password is changed in Active Directory, the key version number (KVNO) is incremented and the encryption keys stored in the KDC are updated. The keytab file on the BIG-IP APM system contains the previous encryption keys and KVNO. This mismatch between the keytab file on BIG-IP and the current service account credentials in Active Directory causes authentication failures with "Preauthentication failed" errors.

Answer/Recommended Actions

To resolve this issue, regenerate and upload a new keytab file to the BIG-IP APM system:

  1. Regenerate the keytab file on the Windows Domain Controller using the ktpass command with the current service account password:

    ktpass -princ HTTP/<hostname>@REALM -mapuser <service_account> -crypto AES256-SHA1 -ptype KRB5_NT_PRINCIPAL -pass <current_password> -out <filename>.keytab

  2. Verify the keytab file contents using:

    ktpass /in <filename>.keytab

  3. Upload the new keytab file to BIG-IP APM:
    • Navigate to Access > Authentication > Kerberos (or Access Policy > AAA Servers > Kerberos for versions prior to 13.x)
    • Click on the Kerberos server object name
    • For Keytab File, click Upload New File
    • Browse to and select the newly generated keytab file
    • Click Update
  4. Verify the KVNO matches between Active Directory and the BIG-IP:
    • On Active Directory, retrieve the KVNO using PowerShell:

      import-module ActiveDirectory

      get-aduser <service_account> -property msDS-KeyVersionNumber | Fl

    • On BIG-IP UI, navigate to Access > Authentication > Kerberos and verify the KVNO displayed under Keytab File Details
  5. Test authentication to confirm users can successfully authenticate.

Additional Information

  • The key version number (KVNO) increases whenever a new keytab is generated or when the service account password is changed in Active Directory.
  • It is critical to regenerate and upload the keytab file immediately after any service account password change to prevent authentication failures.
  • The "Preauthentication failed" error message can indicate multiple issues including invalid credentials, expired keytab, time synchronization problems, or encryption type mismatches. However, when this error occurs immediately after a password change, an outdated keytab is the most likely cause.
  • For enhanced troubleshooting, enable debug logging using: tmsh modify sys db log.rba.level value debug
