Description:

MAC client is not able to establish a VPN connection with a NATed VPN virtual server. F5's VPN application on the client will crash when launching a VPN tunnel.

Environment:
  • BIG-IP system
  • APM module
  • VPN/Network Access full tunnel/split tunnel
  • NAT is in front of VPN virtual server
  • macOS or OSX
Cause:

Here's the scenario for example:
  • There is a VPN virtual server listening on A.A.A.A:443.
  • You have created an access policy which only allows authenticated user to connect to network access resource (VPN) and assigned to this virtual server.
  • You have a firewall in the DMZ zone facing the Internet, it will NAT B.B.B.B:8443 to A.A.A.A:443.
  • After the authentication stage passed, the client is going to establish a PPP tunnel.
  • The VPN virtual server will ask the client-side application to connect tunnel server A.A.A.A:443 (if you didn't enable DTLS)
...
<tunnel_host0>A.A.A.A</tunnel_host0>
<tunnel_port0>443</tunnel_port0>
...
  • The client-side application will then try establishing the tunnel with B.B.B.B:443
  • Since having a firewall that is doing NAT, accessing B.B.B.B:443 may be led to another service.
  • In this way, the connection will be reset or other unexpected errors may happen.
Recommended Actions:

Keep the same port as VPN virtual server on the public-facing socket.
