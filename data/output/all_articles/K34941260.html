K34941260: How to re-add a managed device into BIG-IQ CM and reinitiate the trust establishment via REST without using the GUI

Type
Support Solution
Published
2021-10-07
Updated
2025-03-17
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K34941260

Description
A managed device lost the trust with the BIG-IQ CM. This will happen if you run "clear-rest-storage" on the managed device.

Environment

  • Message on BIG-IQ CM GUI "Error getting resource provisioning from /mgmt/tm/sys/provision on <deviceName> (x.x.x.x), Authorization failure - you may need to remove the device from BIG-IQ and add it again to reestablish trust"
  • Managed devices

Cause
You run "clear-rest-storage" on the managed device.

Recommended Actions

  1. Using the BIG-IQ GUI, you can remove the device and re-add it.
     
  2. Use REST calls to re-establish the trust on the managed device.
    F5 support always recommends you backup the CM (Configuration Manager) and managed device config before making changes.

 
Note: When you see  [replace_with_BigIP_IP]  in the commands below. You will want to replace with the BIG-IP IP addresses.
Note: When you see  [replace_with_admin_credential] and [replace_with_BigIP_User] within the commands below. You will want to insert the user credentials for BIG-IP.

(1) Locate, then delete and check that BIG-IP is removed successfully from BIG-IQ device group:
===================================================================================================================
(1.1) Identify machineID/selfLink of BIG-IP from device-group "cm-bigip-allBigIpDevices". Do note, machineID and selfLink should match.
# restcurl /shared/resolver/device-groups/cm-bigip-allBigIpDevices/devices | jq -r '.items[] | .address, .machineId, .selfLink' | grep -i "[replace_with_BigIP_IP]" -A 2

(1.2) Delete BIG-IP from device group "cm-bigip-allBigIpDevices":
# restcurl -X DELETE /shared/resolver/device-groups/cm-bigip-allBigIpDevices/devices/[replace_with_machineId_derived_from_Step_1.1]

(1.3) Verify BIG-IP has indeed been removed from device group "cm-bigip-allBigIpDevices" by re-executing the command from Step 1.1. Command output should be empty.
===================================================================================================================

(2) Locate, delete and check that BIG-IP is removed successfully from "cm-adccore-allbigipDevices" device group:
===================================================================================================================
(2.1) Identify machineID/selfLink of BIG-IP from device-group "cm-adccore-allbigipDevices". Do note, machineID and selfLink should match.
# restcurl /shared/resolver/device-groups/cm-adccore-allbigipDevices/devices | jq -r '.items[] | .address, .machineId, .selfLink' | grep -i "[replace_with_BigIP_IP]" -A 2

(2.2) Delete BIG-IP from device group "cm-adccore-allbigipDevices":
# restcurl -X DELETE /shared/resolver/device-groups/cm-adccore-allbigipDevices/devices/[replace_with_machineId_derived_from_Step_2.1]

(2.3) Verify BIG-IP has indeed been removed from device group "cm-adccore-allbigipDevices" by re-executing the command from Step 2.1. Command output should be empty.
===================================================================================================================

(2.4) If the BIG-IP is in any other device clusters (for example, you used a cluster display name when adding the device initially), you will also need to remove it from that device group with similar steps:

# restcurl /shared/resolver/device-groups/cm-bigip-cluster_MYDEVICECLUSTER/devices | jq -r '.items[] | .address, .machineId, .selfLink' | grep -i "[replace_with_BigIP_IP]" -A 2

(2.5) Delete BIG-IP from device group "cm-bigip-cluster_MYDEVICECLUSTER":
# restcurl -X DELETE /shared/resolver/device-groups/cm-bigip-cluster_MYDEVICECLUSTER/devices/[replace_with_machineId_derived_from_Step_2.1]

(3) Re-add BIG-IP into CM and reinitiate the trust establishment with the following REST call:
===================================================================================================================
# restcurl -X POST /cm/global/tasks/device-trust -d '{"address":"[replace_with_BigIP_IP]","httpsPort":443,"userName":"[replace_with_BigIP_User]","password":"[replace_with_BigIP_User_password]","clusterName":"cm-bigip-cluster_MYDEVICECLUSTER","useBigiqSync":false,"deployWhenDscChangesPending":false,"name":"trust_[replace_with_BigIP_IP]"}'
===================================================================================================================

(4) Navigate to GUI (Devices >> Big-IP Devices), search for BIG-IP and perform a rediscovery. Once succeeded, repeat Step 1 to 3 on BIG-IP-2 before rediscovery.
