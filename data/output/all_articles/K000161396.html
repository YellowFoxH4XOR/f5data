K000161396: SSH Daemon Fails to Start After Upgrading BIG-IP LTM to Version 17.5.1.6 on iSeries Appliances

Description

After upgrading a BIG-IP LTM iSeries appliance to version 17.5.1.6-0.0.25, the SSH daemon (sshd) fails to start, resulting in loss of SSH access to the management interface. All other management and data-plane functions (GUI access, configuration loading, routing) remain operational. You may see the below Symptoms:

  • SSH service is in a stopped/failed state after boot
  • SSH is not listening on port 22
  • Manual attempts to start the SSH service fail or are non-persistent
  • System logs show errors such as:
sshd: no hostkeys available -- exiting.

touch: cannot touch '/var/ssh/ssh_host_ed25519_key.pub': No such file or directory
touch: cannot touch '/var/ssh/ssh_host_ed25519_key': No such file or directory
touch: cannot touch '/var/ssh/ssh_host_ecdsa_p384_key.pub': No such file or directory
touch: cannot touch '/var/ssh/ssh_host_ecdsa_key.pub': No such file or directory
touch: cannot touch '/var/ssh/ssh_host_rsa_key.pub': No such file or directory
touch: cannot touch '/var/ssh/ssh_host_rsa_key': No such file or directory
touch: cannot touch '/var/ssh/ssh_host_dsa_key.pub': No such file or directory
touch: cannot touch '/var/ssh/ssh_host_dsa_key': No such file or directory

perl: warning: Falling back to the standard locale ("C").

systemd[1]: sshd.service failed.
systemd[1]: Unit sshd.service entered failed state.
systemd[1]: sshd.service: main process exited, code=exited, status=1/FAILURE
  • Based on the command output for "df -h", the '/usr' partition may be at 100% utilization:
/dev/mapper/vg--db--sda-set.1._usr   6.5G   6.5G     0  100% /usr

Environment

  • Product: BIG-IP LTM
  • Affected version: 17.5.1.6-0.0.25 (upgrade from earlier versions like 17.5.1.3)
  • Platform: iSeries Appliances
  • Deployment: vCMP Host

Cause

A known software bug (Bug ID 2291757) affects iSeries platforms running BIG-IP version 17.5.1.6. The bug prevents sshd from starting after upgrade due to missing SSH host key files, which is further exacerbated by the '/usr' partition being full. This results in the inability to generate or access required SSH host keys, causing the SSH service to fail.

Answer/Recommended Actions

For further details and complete steps of workaround, as well as the considerations for each scenario and platform type, please review the reference KB "K000161170". 

Additional Information

  • The upgrade itself may complete successfully — the system boots cleanly, the full configuration loads, and the device comes online normally. The issue is isolated to the SSH service only.
  • GUI access and all data-plane/management-plane functions remain unaffected.
  • The /usr partition reaching 100% capacity exacerbates the issue by preventing SSH host key file creation, but the underlying cause is the known bug in version 17.5.1.6 on iSeries platforms.
