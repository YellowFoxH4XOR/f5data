K11337: An interim upgrade is required for both systems of a redundant pair when upgrading from version 2.7.x to 5.x

Topic

The ARX Release Notes for version 5.x indicate an upgrade can be applied to various 3.x or later versions. Therefore, when upgrading a standalone system from an earlier release, such as 2.7.x, you must first perform an interim upgrade to a supported 3.x/4.x release. However, when upgrading a redundant pair of ARX version 2.7.x systems, you must first upgrade both peers to the supported interim 3.x/4.x version before upgrading them to the final 5.x release.

When upgrading a redundant pair of ARX version 2.7.x systems, if one system is upgraded to the interim version and then to the final 5.x release while the peer system remains at version 2.7.x, when the upgraded system attempts to go active, it will reboot multiple times, dump policy cores, and issue SNMP traps that appear similar to the following example:

REDUNDANCY requires this switch to reboot.
Reason: Resource 'dnas_policy_svc-2' has failed/exited.

When the system reaches the reboot threshold, the system will stop rebooting and both systems will remain in an inoperable state.

Note: The default reboot threshold is 3.

To prevent this condition, you must first upgrade both ARX systems in the redundant pair to the supported interim 3.x/4.x release before upgrading the system to version 5.x.

Note: For upgrade installation instructions, refer to the Upgrading Software chapter in the ARX CLI Maintenance Guide and the ARX Release Notes for the desired version.

Recovery

To recover from an inoperable state, contact F5 Networks Technical Support for assistance.
