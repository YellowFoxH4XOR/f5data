Known Issue

The BIG-IP ASM bd process may leak memory.

This issue occurs when the following condition is met:

  • A security policy is missing a content profile necessary to parse an HTTP POST request.

As a result of this issue, many parameter violations are triggered.

Impact

The system memory usage and swap memory usage increases over time. This may lead to the kernel running out of memory and eventually restarting the BIG-IP ASM bd process.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ts/bd.log file, you may observe repeated entries of an error similar to the following example, indicating a request with many parameter violations:

    attack_patterns_funcs.cpp:0617|Report attack sig to protobuf failed

  • In the /var/log/kern.log file, you may observe errors similar to the following example, indicating that the BIG-IP ASM bd process has been restarted due to high memory usage:

    err kernel: Out of memory: Kill process <pid> (bd) score 253 or sacrifice child
    err kernel: Killed process <pid>, UID 0, (bd) total-vm:<memory size>, anon-rss:<memory size>, file-rss:<memory size>

Workaround

To work around this issue, you should identify the content in the HTTP POST request and apply the appropriate content profile to the affected security policy. For example, if the HTTP POST request contains XML, you should apply the XML content profile to the affected security policy.
