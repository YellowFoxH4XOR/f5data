Known Issue

Note: The High-Speed Bridge (HSB) is the interface used on certain BIG-IP platforms to connect the switch fabric to the host subsystem. On those platforms that employ this technology, one or more HSBs may be present.

Note: A runt frame is an Ethernet frame that is less than the minimum length of 64 bytes. Network devices generally discard runt frames.

Note: A jumbo frame is an Ethernet frame with a payload (MTU) greater than 1500 bytes. The BIG-IP system does not support jumbo frames. For more information, refer to K6399: Support for jumbo Ethernet frames.

This is the result of a known issue. The HSB(s) on the following platforms do not correctly handle runt and jumbo frames:

  • BIG-IP 8900
  • BIG-IP 8950
  • BIP-IP 11050
  • PB200 VIPRION blade

This issue may cause the following undesired effects:

Note: The following list of effects is not exhaustive.

  • HSB lockups
  • TMM crashes
  • System reboots
  • Ethernet frames being transmitted on the wrong interface (this can cause switches to learn incorrect MAC addresses and result in communication failures)
  • Ethernet frames being excessively padded (this can cause the BIG-IP system to transmit jumbo frames on the network)

When this issue occurs, HSB-related error messages that appear similar to the following example may be logged to the /var/log/ltm file:

01230112:2: Interface 0.3: soft resetting due to transmitter failure.
01010025:2: Device error: hsb interface 2 soft resetting due to transmitter failure
01230112:2: Interface 0.7: soft resetting due to transmitter failure.
01010025:2: Device error: hsb interface 6 soft resetting due to transmitter failure
01010025:2: Device error: hsb interface 2 disable tx ring 0 timed out
01010025:2: Device error: hsb interface 6 disable tx ring 0 timed out
01010025:2: Device error: hsb interface 2 disable tx ring 1 timed out

In addition, error messages that appear similar to the following example may be logged to the /var/log/tmm file:

notice hsb2: tx watchdog check 4
notice hsb2: tx watchdog check 5
notice hsb interface 2 soft resetting due to transmitter failure
notice *** TMM 2 - PDE 2 - transmitter failure ***
notice ifdown failed to disable hsb2. Rebooting
notice hsb2: No.1 reset due to transmitter failure.
notice hsb2 warning: lost 25 consecutive loopback packets
notice hsb interface 2 soft resetting due to receive failure
notice stat: e728 status_flags

Workaround

On BIG-IP versions that include the fix for CR119615 (9.4.8-HF3, 10.0.1-HF4 and 10.1.0-HF1), you can work around this issue by configuring the BIG-IP system to perform Ethernet frame padding in software. To do so, perform the following procedure:

  1. Log on to the BIG-IP system command line.
  2. Use a text editor to open the /config/tmm_init.tcl file.

    Note: If the file does not exist, create it.

    Note: On VIPRION systems, the contents of the /config directory are synchronized across all blades. Therefore, you only need to edit the /config/tmm_init.tcl file on the primary blade.
  3. Add the following line to the end of the file:

    HSB::software_min_padding yes
  4. Save the file and exit the editor.
  5. Restart the services by running the following command:

    bigstart restart

    Important: Restarting the services will temporarily interrupt traffic processing. Additionally, if the BIG-IP system is the active member of a redundant pair, the system will failover.

    Important: On VIPRION systems, enter the clsh bigstart restart command instead. This command is the equivalent of running bigstart restart on every blade.
  6. This step is optional. You can perform this step to confirm that the workaround took effect. Type the following command:

    grep 'min packet padding workaround' /var/log/tmm*

    The presence of the following message in the logs is indication that the workaround took effect:

    local/bigip1 notice The min packet padding workaround is turned on in software.

Important: If the BIG-IP system has already experienced the issue described in this Solution and the HSB(s) are now frozen, the system may not return to a functional state until it is restarted by executing the reboot command.
