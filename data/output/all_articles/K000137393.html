Description

Security policies configured with the data-guard feature block a server response logging the following log message:

"attack_type":"Abuse of Functionality,Information Leakage,Other Application Activity"

Environment

  • NGINX App Protect

Cause

Default behavior of Data-Guard.

Data-guard analyses server responses for patterns that resemble credit card or SSN information.
When there is a pattern match the request is blocked due to VIOL_RATING_THREAT being triggered.
 

Recommended Actions

The default policy enforces violations by Violation Rating, the App Protect computed assessment of the risk of the request based on the triggered violations.
  • 0: No violation
  • 1-2: False positive
  • 3: Needs examination
  • 4-5: Threat

The default policy enables most of the violations and signature sets with Alarm turned ON, but not Block. These violations and signatures, when detected in a request, affect the violation rating. By default, if the violation rating is calculated to be malicious (4-5) the request will be blocked by the VIOL_RATING_THREAT violation. This is true even if the other violations and signatures detected in that request had the Block flag turned OFF. It is the VIOL_RATING_THREAT violation having the Block flag turned ON that causes the response to be blocked.

However, indirectly the combination of all the other violations and signatures in Alarm caused the request to be blocked. 

You can change the default behavior. For example, if you want to add blocking on a violation rating of 3 as well, enable blocking for the VIOL_RATING_NEED_EXAMINATION violation. Additionally if the violation is being triggered by a false positive from number patterns that appear to be credit card numbers but are not credit card numbers you can disable the credit card number checks in the policy.

Example Data-Guard policy:

{
    "policy" : {
        "name": "example_guard_policy_no_ccn",
        "template": { "name": "POLICY_TEMPLATE_NGINX_BASE" },
        "data-guard" : {
            "enabled" : true,
            "creditCardNumbers" : false
        }
    }
}
