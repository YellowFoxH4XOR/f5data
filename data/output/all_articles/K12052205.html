Description
Violations may be present for F5 Anti-Bot Mobile SDK integrated applications when connecting to a virtual server with a Bot Defense profile attached.  The default behavior for an Illegal Mobile App when the SDK is functional will be to block the client and classify them as a Malicious Bot.

If the F5 Anti-Bot Mobile SDK is not functioning properly or not integrated in the mobile app, the client will be categorized as an Unknown bot in most cases unless the User-Agent of the app matches a known browser then it will usually be categorized as a suspicious browser. The default handling of Unknown bots is to rate limit to 30 transactions per second.

The details may be expanded under Bot Details and Mobile categories in the event log.

Environment

  • BIG-IP Advanced WAF
  • Bot Defense Profile applied to Virtual Server
  • Mobile application client with F5 Anti-Bot Mobile SDK integrated with Appdome.
  • Detected Anomalies "Disallowed Mobile App Features"

Cause
If the SDK is functioning properly an Illegal Mobile App categorization will provide detail on the status of the client device and app in Security  ››  Event Logs : Bot Defense : Bot Requests.  The Mobile category in the bot defense logs will display these details including Mobile Application Name, Mobile OS, Mobile App Emulation Mode, Mobile App Jailbroken/Rooted, and Mobile Device Debugger Mode.

If the mobile settings of the Bot Defense Profile are configured to disallow clients with any of these values then a "Disallowed Mobile App Features" anomaly will be raised and the profile mitigation settings for Malicious Bot will apply.

Recommended Actions

  1. Review event logs for the client in question.
  2. Compare the Bot Details and Mobile sections of the event log against the bot defense profile and confirm appropriate action was taken based on the configuration.  
    Security  ››  Bot Defense : Bot Defense Profiles.
    Select the appropriate bot defense profile.
  3. Review Mobile Applications tab of the bot defense profile configuration and adjust allowed or disallowed features as necessary for security and client environment.
  4. If this is believed to be a false positive, confirm behavior with a known-good testing device with the SDK integrated app installed.  

Additional Information
Mobile clients may represent a wide range of devices and environments.  Allowing or disallowing features such as jailbroken or debugger enabled devices should be considered on an app by app basis.  Establishing the prevalence of these clients may help determine the impact of disallowing these features for your mobile client base.
