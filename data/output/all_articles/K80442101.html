Description

  • You are using a reverse monitor but are having unexpected results
  • Reverse monitor will not mark down a resource

Environment

Relevant environmental factors specific to the topic

  • Conditions
  • Configuration objects and settings
  • Products and features

Cause

Incorrect configuration of the reverse monitor or misunderstanding of the limitations of the feature.

Recommended Actions

None

Additional Information

Conditions that will cause a reverse monitor to mark a resource down.

  1. When it receives the string. For example it receives the "Error" string.
  2. When it receives an empty string or rather no string is sent.
  3. When it receives ANY strings based on a long delay.

Two caveats:

  1. Note both a send and a receive string must be configured in order for the reverse monitoring to work as expected.
  2. When the send string in the monitor is incorrectly formatted the monitor will not work as expected. Review the following articles for how to format the send string correctly:
    • K2167: Constructing HTTP requests for use with the HTTP or HTTPS application health monitor
    • K13397: Overview of HTTP health monitor request formatting for the BIG-IP DNS system
