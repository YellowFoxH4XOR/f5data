K000150599: Disabling ipv6 via sys db variable "ipv6.enabled" doesn't also disable ipv6-over-ipv4 tunnelled traffic

Source

Description

Disabling ipv6 by setting sys db variable "ipv6.enabled" to "false" doesn't also disable ipv6-over-ipv4 tunnelled traffic, by design.

From an LTM perspective, to specifically block ipv6-over-ipv4 traffic, we first need to identify what type of tunnelling is being used, and then the available options would have to be based on that.

A perhaps better approach might be to simply apply profiles to all VSs so that only specific protocols, eg. TCP and UDP, will pass over the IPv4 VSs, so GRE and traffic that isn't actually tunnelled over the specified protocols (eg. TCP and UDP) would all automatically be blocked by virtue of not matching any existing VSs.

 

Environment

BIG-IP LTM

 

Cause

"tmsh modify /sys db ipv6.enabled value false" will disallow ordinary IPv6, however IPv6 encapsulated in an IPv4 packet is seen as IPv4, so this DB key should not disable IPv6 encapsulated in IPv4. ​

The normal methods to encapsulate ipv6 over ipv4 involve either using a GRE tunnel (inside which ipv6 is then encapsulated), or else to use "6in4" ( https://datatracker.ietf.org/doc/html/rfc4213 ) or "6over4" ( https://datatracker.ietf.org/doc/html/rfc2529 ), or "6to4" ( https://en.wikipedia.org/wiki/6to4 ), all of which describe scenarios where an IPv6 packet is transmitted inside an IPv4 packet with the IPv4 "Protocol Type" value set to "41".

A GRE packet over IPv4 should generally have the IPv4 "Protocol Type" value set to 47. Further to that, when the GRE payload is IPv6, the "Protocol Type" field inside the GRE header is supposed to be set to 34525 ( 86DD in hex).

 

Recommended Actions

The best approach is probably to simply apply profiles to all VSs so that only specific protocols, eg. TCP and UDP, will pass over the IPv4 VSs, so GRE and traffic that isn't actually tunnelled over the specified protocols (eg. TCP and UDP) would all automatically be blocked by virtue of not matching any existing VSs.

Alternatively, an iRule could be written which checks the IPv4 header for the "Protocol Type" field, and block if the value is 41 or 47 - this should block all "normally encapsulated" ipv6-over-ipv4 traffic, but would also block all GRE traffic as a side effect.

To allow all GRE traffic, but to block only ipv6-over-GRE traffic, the above iRule would have to be modified to further look inside the GRE header if the IPv4 "Protocol Type" is 47, to check if the GRE "Protocol Type" is also set to 34525 (or 0x86DD in hex), and only block if that is true (ie. IPv4 protocol 47 and GRE protocol 34525). As can be seen, this is quite involved and would require a lot of CPU resources.
