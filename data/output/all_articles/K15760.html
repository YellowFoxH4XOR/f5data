Known Issue

Virtual servers that reference a FastL4 profile with the Loose Initiation and Loose Close options enabled may produce Traffic Management Microkernel (TMM) core files.

This issue occurs when the following conditions are met:

  • The virtual server processes a TCP FIN packet that is not associated with an existing connection.

Impact

The TMM process may produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H486230 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system sends a SIGSEGV signal to the TMM, resulting in a stack trace and core file.
  • The BIG-IP system temporarily fails to process traffic.

Workaround

To work around this issue, you can disable the Loose Close and Loose Initiation options in the FastL4 profile. To do so, perform the following procedure:

Impact of workaround: The virtual server will not process asymmetric traffic.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Use the following command syntax to create a new FastL4 profile in which the Loose Close and Loose Initiation options are disabled:

    create /ltm profile fastl4 <profile name> loose-close disabled loose-initialization disabled

  3. Associate the custom FastL4 profile with the affected virtual server and remove any existing TCP profile that is already associated with the virtual server by using the following command syntax:

    modify /ltm virtual <virtual server name> profiles delete {<existing TCP profile> } profiles add { <custom fastL4 profile> }

  4. Save the configuration by typing the following command:

    save /sys config
