K10604227: vmtoolsd leaks memory, potentially causing OOM

Type
Support Solution
Published
2022-11-08
Updated
2025-04-02
Applies to
  • BIG-IP
  • Virtual Editions
  • Vmware ESXI and vCloud Director
Source
https://my.f5.com/manage/s/article/K10604227

Description

  • vmtoolsd leaks memory
  • It may presents with following oom-killer (out of memory) in /var/log/kern.log

bigip.example.com err kernel: Out of memory: Kill process 509 (vmtoolsd) score 95 or sacrifice child

  • vmtoolsd will not be restarted automatically after the process being killed.
  • If vmtoolsd process is still running, you may notice vmtoolsd consuming high amount memory usage  ( > few hundreds of MB) and increasing.

Environment

  • Big-IP Virtual Edition
  • VMware hypervisor.
  • VMware Tools daemon (vmtoolsd), versions 11.1.0 to 11.1.5.
[root@bigip.example.com] # vmtoolsd -v
VMware Tools daemon, version 11.1.5.22735 (build-16724464)
  • VM running on openstack hypervisor and using vmtoolsd.
  • VM disk device configured as IDE, SATA or SAS (LSI Logic SAS)

Cause

vmtoolsd memory leak

Recommended Actions

1. If possible, change the VM's disk configuration to other than IDE, SATA or SAS (LSI Logic SAS).  The problem will go away after making this change.
2. If changing the VM's disk configuration is not possible, create the file /etc/vmware-tools/tools.conf and add the following: 
[guestinfo]

# disable scan for disk device info
diskinfo-report-device=false
3. This will stop the leak, but the memory already allocated to vmtoolsd will not be freed.
4. To free up the memory used by vmtoolsd, it needs to be restarted: 
systemctl restart --ignore-dependencies vmtoolsd

Additional Information

If you issue persist, please contact F5 Support.
