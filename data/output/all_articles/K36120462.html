Description

BIG-IQ Centralized Manager doesn't show Server Side Round-Trip Time  for TCP Application configured with AVR Analytics Profile assigned

Example of the configuration:

ltm virtual test_tcp_vs.8080 {
    connection-limit 200000
    description
    destination 10.0.0.100:8080
    ip-protocol tcp
    mask 255.255.255.255
    persist {
        source_addr {
            default yes
        }
    }
    pool test_pool
    profiles {
        custom.tcp-analytics { }
        test.fastL4 { }
    }
    rate-limit 2500
    source 0.0.0.0%11/0
    translate-address enabled
    translate-port enabled
    vs-index 68
}

ltm profile tcp-analytics custom.tcp-analytics {
    app-service none
    collect-city disabled
    collect-continent enabled
    collect-country enabled
    collect-nexthop disabled
    collect-post-code disabled
    collect-region disabled
    collect-remote-host-ip disabled
    collect-remote-host-subnet enabled
    collected-by-client-side enabled <<<<!!!!!
    collected-by-server-side enabled<<<<!!!!
    collected-stats-external-logging disabled
    collected-stats-internal-logging enabled
    external-logging-publisher none
}

As you can see in the configuration above, these two options are enabled:

collected-by-client-side enabled
collected-by-server-side enabled

Environment

  • BIG-IQ Data Collection Cluster
  • Stats Collection Enabled
  • AVR TCP Analytics profile assigned to Virtual Server
  • FastL4 Virtual server Configured on BIg-IP

Cause
RTT not enabled in appropriate FastL4 profile

Recommended Actions

To view RTT statistics for Layer 4 traffic managed using a FastL4 profile, you also need to enable RTT from Client and RTT from Server (as appropriate) in the FastL4 profile.
 
SettingDefault valueDescription
RTT from ClientDisabledWhen this option is enabled, the system uses TCP timestamp options to measure the round-trip time to the client.
RTT from ServerDisabledWhen this option is enabled, the system uses TCP timestamp options to measure the round-trip time to the server.

Important: It is not recommended to modify the "default" profiles.  Instead create a custom profile, modify this profile as needed, then assign to the Virtual Server(s).
