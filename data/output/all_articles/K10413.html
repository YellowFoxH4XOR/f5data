Known Issue

This is the result of a known issue. If the RAM Cache is in the process of removing a cached entry and the request is aborted, the system may attempt to remove the cached entry after it has already been removed. As a result, TMM will core and the system will failover or restart.

When this issue occurs, an error message that appears similar to the following example is reported to the /var/log/tmm file:

notice panic: ../modules/hudfilter/ramcache/store.c:1267:
Assertion "Resource count not zero when freed!" failed.

F5 Product Development tracked this issue as ID 208611 (formerly CR122658-1) and ID 327275 (formerly CR122658), and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.0.1-342.0-HF1, which has been issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
