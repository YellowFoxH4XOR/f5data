Known Issue

A Virtual Clustered Multiprocessing (vCMP) guest may fail to process traffic after the mcpd process restarts on the vCMP hypervisor.

This issue occurs when all of the following conditions are met:

  • You have provisioned the vCMP module on a VIPRION platform.
  • You have deployed one or more vCMP guests.
  • The mcpd process restarts on one of the vCMP hypervisor's blades.

Impact

vCMP guests may fail to process client traffic or accept connections to self IP addresses.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H518719 on the Diagnostics > Identified > Medium page.
  • On the vCMP guest, the following command shows that the Clustered Multiprocessing (CMP) transition states do not match on all blades. In the following example, the CMP state of blade 3 does not match that of the other blades:

    clsh "grep 'CMP transition' /var/log/tmm | tail -n 1"
    === slot 2 addr 127.3.0.2 color green ===
    18:35:49 slot2/example1 notice CMP transition complete, transitioning dissaggregator to state 0xf
    === slot 3 addr 127.3.0.3 color green ===
    18:25:28 slot3/example1 notice CMP transition complete, transitioning dissaggregator to state 0xe
    === slot 4 addr 127.3.0.4 color green ===
    18:35:49 slot4/example1 notice CMP transition complete, transitioning dissaggregator to state 0xf
    === slot 1 addr 127.3.0.1 color green ===
    18:35:49 slot1/example1 notice CMP transition complete, transitioning dissaggregator to state 0xf

  • If you run the tmsh show net interface -hidden command on the vCMP guest, the results show a different set of 0.x interfaces than when you run the tmsh show vcmp guest all-properties command on the vCMP hypervisor for that guest's slot.

Workaround

To work around this issue, you can re-deploy the vCMP guest using the Configuration utilty or the TMOS Shell (tmsh). To do so, perform one of the following procedures:

Impact of workaround: The vCMP guest will be unavailable to process traffic while being re-deployed.

Using the Configuration utility to re-deploy a vCMP guest

  1. Log in to the Configuration utility of the vCMP host.
  2. Navigate to vCMP > Guest List.
  3. Select the check box to the left of the affected guest.
  4. Select the Disable option.
  5. Once the Requested State changes to Configured, select the check box to the left of the affected vCMP guest.
  6. Select the Deploy option.
  7. Once the Requested State changes to Deployed, the vCMP guest should be available for processing traffic.

Using tmsh to re-deploy a vCMP guest

  1. Log in to the command line of the vCMP host, and log in to tmsh by typing the following command:

    tmsh

  2. To list all available guests, type the following command:

    show vcmp guest

  3. To disable the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state configured

    For example, to disable a vCMP guest named vcmp_one, type the following command:

    modify vcmp guest vcmp_one state configured

  4. To ensure that the affected vCMP guest is disabled, use the following command syntax:

    Note: The vCMP guest will not appear once it is completely disabled.

    show vcmp guest [Name]

    For example, to ensure that the vCMP guest named vcmp_one is disabled, type the following command:

    show vcmp guest vcmp_one

  5. To deploy the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state deployed

    For example, to deploy a vCMP guest named vcmp_one, type the following command:

    modify vcmp guest vcmp_one state deployed

  6. To verify that the vCMP guest is deployed, use the following command syntax:

    Note: The vCMP guest Status will change to running and the Requested State will change to deployed.

    show vcmp guest [Name]

    For example, to verify that the vCMP guest named vcmp_one is deployed, type the following command:

    show vcmp guest vcmp_one
