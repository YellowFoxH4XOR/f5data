Description

The dosl7d process may stop running and being in a restart loop as below:

dosl7d       run (pid 8953) 0 seconds, 2 starts, 13750 restarts
dosl7d_attack_monitor down, waiting for dosl7d to release running semaphore

In addition, the dosl7d process shows as down in tmsh command line prompt 

Environment

  • BIG-IP ASM/AWAF
  • dosl7d

Cause

There is a syntax error in dosl7d logger configuration file: /etc/dosl7/logger.cfg, for example:

MODULE = ALL;
LOG_LEVEL = TS_ERR | TS_CRIT | TS_NOTICE  ; <<<< Notice the extra space before the semicolon.
FILE = 2;

Recommended Actions

You may modify /etc/dosl7/logger.cfg to enable dosl7d debug log for troubleshooting. However if there is any syntax error in the file content, dosl7d won't be able to up again and only showing the following logs in /var/log/dosl7/dosl7d.log:

DIDDB_UPGRADE|Mar 01 17:38:33.802|Starting.
DIDDB_UPGRADE|Mar 01 17:38:33.808|Existing DB version: 2
DIDDB_UPGRADE|Mar 01 17:38:33.810|Current  DB version: 2
DIDDB_UPGRADE|Mar 01 17:38:33.815|Done.

New ALL module: ALL
New ALL level: TS_ERR
New ALL level: TS_CRIT
New ALL level: TS_NOTICE
Error

You may compare the /etc/dosl7/logger.cfg file content with the ones on the other BIG-IP device in order to fix the syntax error. You may also contact F5 support for further assistance. 

Example incorrect and correct configurations:

== Incorrect ==
MODULE = ALL;
#LOG_LEVEL = TS_ERR | TS_CRIT | TS_NOTICE;
LOG_LEVEL = TS_ERR | TS_CRIT | TS_NOTICE | TS_DEBUG;
FILE = 2;
============
? Note that the commented line "#LOG_LEVEL = TS_ERR | TS_CRIT | TS_NOTICE;" cannot be placed after the line 
  "MODULE = ALL;"

== Correct ==
MODULE = ALL;
LOG_LEVEL = TS_ERR | TS_CRIT | TS_NOTICE | TS_DEBUG;
FILE = 2;

#MODULE = ALL;
#LOG_LEVEL = TS_ERR | TS_CRIT | TS_NOTICE;
#FILE = 2;
============
