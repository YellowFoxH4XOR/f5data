K000139457: FastL4 VS with PVA none does not forward TCP SYN retransmissions to pool members

Type
Support Solution
Published
2024-05-07
Updated
2024-05-09
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.4
Source
https://my.f5.com/manage/s/article/K000139457

Description

Client syn retransmissions are not forwarded by BIG-IP

 

Environment

  • FastL4 server configured with PVA none
  • Server sends syn/ack response to initial syn back through BIG-IP, but this is not received by client
  • Server does not re-transmit syn/ack when 3whs is not completed by ack from client

Cause

In this scenario, as BIG-IP has seen the syn and syn/ack response, it will not forward further syn retransmissions from the client unless it see's syn/ack retransmitted by the pool member (server). The connection will be terminated or reset when the handshake timeout expires.

 

This is working as expected. For security and stability reasons, this behaviour will not be changed.

 

Recommended Actions

  • Resolve network issues causing the syn/ack not to reach the client and/or the pool member not to retransmit the syn/ack
  • Restore hardware PVA

Additional Information

  • Enabling loose-init or disabling sys db tm.dupsynenforce will not change or workaround this behaviour.
