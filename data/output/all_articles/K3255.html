Important: This Solution applies only to patches that are supplied as new kernels. If you received an IM package, new proxyd binary, or any other type of patch, contact F5 Technical Support for installation instructions.

In order to install a kernel patch on a 3-DNS or a BIG-IP system you will need to download the hotfix and verify its integrity. Every kernel hotfix should be distributed with the md5 sums of the new kernels.

Transferring the kernel patch files

In most cases, the kernel patch files are stored on the dropbox.f5.com server in a case-specific subdirectory.

In the following example, the case number is c777777 and the associated CR is CR88888.

Note: This procedure requires a reboot of the 3-DNS or BIG-IP system and should be scheduled during a maintenance window.

Important: The filenames bsd.smp-HOTFIX-CR88888, bsd.anip-HOTFIX-CR88888 and hotfix.md5 are provided as examples. F5 Networks Technical Support will provide you with the names of the files specific to your patch. Replace the filenames bsd.smp-HOTFIX-CR88888, bsd.anip-HOTFIX-CR88888 and hotfix.md5 with the filenames provided by F5 Support.

  1. Connect to your BIG-IP/3-DNS through SSH or log in through the serial console.
  2. Change directories to the var/tmp directory by typing the following command:

    cd /var/tmp

  3. Connect to dropbox.f5.com by typing the following command:

    ftp dropbox.f5.com

    Note: When prompted, use your case number as the username and the email address of the user associated with that case as the password.

  4. Download the kernel patch files by typing the following commands:

    • binary

    • hash

    • get bsd.smp-HOTFIX-CR88888

    • get bsd.anip-HOTFIX-CR88888

    • get hotfix.md5

    • quit

    Note: Replace the filenames bsd.smp-HOTFIX-CR88888, bsd.anip-HOTFIX-CR88888 and hotfix.md5 with the filenames provided by F5 Support.

  5. Display the contents of the md5 checksum file distributed with the patch by typing the following command:

    cat /var/tmp/hotfix.md5

    Note: Replace the filename hotfix.md5 with the filename provided by F5 Support.

    The output should appear similar to the following:

    75f74a47330a2c2e041780d15232802e bsd.smp-HOTFIX-CR88888
    b0b55f22ad4acbb152f0f2536623b5e9 bsd.anip-HOTFIX-CR88888 

    The first column of the output displays the checksum value for the filename listed in the second column.
     
  6. Verify the integrity of the kernel patch file by comparing the output of the following commands to the corresponding checksum value displayed in step 5:

    • md5 bsd.smp-HOTFIX-CR88888

    • md5 bsd.anip-HOTFIX-CR88888

      Note: Replace the filenames bsd.smp-HOTFIX-CR88888 and bsd.anip-HOTFIX-CR88888 with the filenames provided by F5 Support.

    Important: If the md5 sums for the patch do not match those distributed with the patch, contact F5 Networks Technical Support.

  7. Back up the existing kernel by typing the following commands:

    • cd /

    • cp bsd.smp bsd.smp.orig

    • cp bsd.anip bsd.anip.orig

  8. Install the kernel patch by typing the following commands:

    • mv -f /var/tmp/bsd.smp-HOTFIX-CR88888 bsd.smp

    • mv -f /var/tmp/bsd.anip-HOTFIX-CR88888 bsd.anip

    • chmod 755 bsd.*

      Note: Replace the filenames bsd.smp-HOTFIX-CR88888 and bsd.anip-HOTFIX-CR88888 with the filenames provided by F5 Support.

    Note: If the root partition of your file system is not large enough to store both kernels, only install the kernel patch for the kernel you intend to run. For example, if you are running the SMP kernel, do not copy the ANIP kernel from the /var/tmp directory to the / directory, and do not rename the /bsd.anip file to /bsd.anip.orig.

    The /bsd directory should contain the symlink to the kernel you intend to boot, either SMP or ANIP. Verify that the kernel is appropriately named as an executable file, by typing the following command:

    ls -l /bsd*

    The output should appear similar to the following:

    lrwxr-xr-x 1 root wheel 7 Jul 8 11:15 /bsd@ -> bsd.smp
    -rwxr-xr-x 1 root wheel 2859140 Jul 8 11:15 /bsd.anip*
    -rwxr-xr-x 1 root wheel 2875126 Apr 15 13:54 /bsd.anip.orig*
    -rwxr-xr-x 1 root wheel 1255028 Oct 10 2000 /bsd.generic*
    -rwxr-xr-x 1 root wheel 2861749 Jun 24 09:29 /bsd.smp*
    -rwxr-xr-x 1 root wheel 2859111 Apr 15 13:54 /bsd.smp.orig*

  9. Reboot your BIG-IP or 3-DNS system to activate the kernel patch.
  10. After the system reboots, type the following command to verify the version of kernel patch:

    b version

    The output should appear similar to the following:

    b version | head -2
    Kernel:
    BIG-IP Kernel 4.5.10 HOTFIX-CR88888

Troubleshooting

Booting with the original kernel

If you are unable to boot your system with the kernel patch, you can boot the original kernel by interrupting the boot sequence and typing the kernel-appropriate command when prompted.

If you are running the SMP kernel, the command is:

bsd.smp.orig

If you are running the ANIP kernel, the command is:

bsd.anip.orig

Reinstalling the original kernel

If you encounter issues with the kernel patch, you can restore the original kernel. To do this, perform the following steps:

  1. Boot the system using the default kernel.
  2. Move the kernel patch back to the /var/tmp directory by typing the following commands: 
     

    • mv /bsd.smp /var/tmp/bsd.smp-HOTFIX-CR88888

    • mv /bsd.anip /var/tmp/bsd.anip-HOTFIX-CR88888

    Note: Replace the filenames bsd.smp-HOTFIX-CR88888 and bsd.anip-HOTFIX-CR88888 with the filenames provided by F5 Support.

  3. Restore the original kernels by typing the following commands:

    • mv /bsd.smp.orig /bsd.smp

    • mv /bsd.anip.orig /bsd.anip
