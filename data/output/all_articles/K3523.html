Topic

A Media Access Control (MAC) address is a hardware address assigned to a network interface. This address consists of six hexadecimal bytes, typically presented in one of the following two forms:

  • 00:00:00:00:00:00
  • 00-00-00-00-00-00

MAC addresses can be either universally administered or locally administered. In either case, each device's MAC address must be unique on the Layer 2 network segment on which it communicates.

Universally administered MAC addresses are those burned in by the hardware vendor. The first half of the burned-in address consists of the IEEE vendor code of the hardware manufacturer, and the remainder of the address is the vendor-unique serial number of the device. Together they provide a globally unique address for any Ethernet hardware device.

Note: You can view a public listing of registered vendors by going to the following link: Wireshark - OUI Lookup Tool. This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

Locally administered MAC addresses are assigned to a network interface by a network administrator, overriding the burned-in address. Locally administered addresses are distinguished by the value of the locally administered bit, which is the second-to-last bit of the first byte of the address. If the value of this bit is 1, the address is locally administered.

Using the MAC address 02-XX-XX-XX-XX-01 as an example, the first byte is 02h. The bits making up that byte are 00000010. Since the second-to-last bit has a value of 1, the address is a locally administered address.

The user-defined, locally administered MAC address (otherwise known as MAC masquerade address) is typically used to optimize the flow of traffic upon failover of a redundant BIG-IP pair.

Determining an appropriate and unique value for your MAC masquerade address

Note: A custom MAC masquerade address configured on a redundant system is used only by the active unit; the standby unit uses the system's actual interface's MAC address. Beginning in version 11.0.0, the BIG-IP system associates a MAC masquerade address with a traffic group. For more information, refer to K13145: The BIG-IP system now associates masqueraded MAC address with traffic group.

When you configure a custom MAC masquerade address for an interface, you must use a MAC address that is unique to the Layer 2 network segment on which the device communicates. If the MAC address is not unique, a conflict occurs and traffic does not flow across the network segment as expected. F5 recommends that you construct MAC masquerade addresses by following the IEEE locally administered addressing scheme and flipping the locally administered bit in the existing burned-in MAC address. Since this method bases the locally administered MAC address on the already-unique universally administered MAC address, locally administered addresses derived in this manner always create a set of unique addresses that never conflict with each other or with any universally administered MAC addresses.

Important: On VELOS and rSeries platforms, MACs using 02:F5:F5 OUI (i.e. any address of the form 02:F5:F5:xx:xx:xx) are internally reserved by F5OS for the L2 learning service. These MAC addresses should not be used for MAC masquerade, as this will lead to traffic degradation. See Bug ID 2399785 for more information.

You can convert the pre-assigned MAC address to a locally administered MAC address by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Identify a pre-assigned MAC address on the BIG-IP system.

    For example, you can determine the base MAC address for the BIG-IP system by entering following command:

    tmsh show sys hardware | grep -i "base mac"

    Note: You can use any pre-assigned MAC address on the system as a base address for creating a unique locally administered MAC address. Enter tmsh list net interface mac-address to view the pre-assigned MAC addresses on the system.

  2. Convert the first byte of the address to binary.
  3. Change the second-to-last bit from 0 to 1 to indicate it is locally administered.
  4. Convert the binary value back to hexadecimal.
  5. Replace the first byte of the original MAC address with the new hexadecimal value.
  6. Use this new MAC address when configuring MAC masquerade. For information about configuring MAC masquerading, refer to K13502: Configuring MAC masquerade (11.x - 17.x)

Note: A shorthand method to the same result is to add 02h to the first byte of the pre-assigned MAC address.
