K000138473: Issues when the route couldn't be found when client connects to the ingress-gw via IPv6

Type
Support Solution
Published
2024-02-02
Updated
2024-02-02
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000138473

Description

Ingress gateway is configured for dual-stack.
Service behind the gateway is only listening on IPv4 or IPv6, but is NOT a dual-stack service. For example:

1.           (Client makes IPv4 request) -> Ingress gateway (Dual stack) -> Service listens on IPv6
2.           (Client makes IPv6 request) -> Ingress gateway (Dual stack) -> Service listens on IPv4

In this example, the ingress gateway reports a 4xx/5xx error back to the client as it cannot fulfill the request.


Environment

Aspen Mesh 1.14.6-am3

Ingress gateway is configured for dual-stack


Cause

Software bug in Aspen Mesh 1.14.6-am3


Recommended Actions

Upgrade to Aspen Mesh 1.14.6-am4
 

Additional Information

The following use cases would still work in am3 and earlier:

1. (Client makes IPv6 request) -> Ingress gateway (Dual stack) -> Service listens on IPv6
2. (Client makes IPv4 request) -> Ingress gateway (Dual stack) -> Service listens on IPv4

The cases mentioned in the description were fixed in Aspen Mesh 1.14.6-am4. Therefore even if the backend service is listening on a different IP family than the request it would still be satisfied.
