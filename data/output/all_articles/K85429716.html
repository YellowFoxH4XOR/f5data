Description

  • Pool monitor stuck on "state checking"
  • provision.tmmcount changed from default
  • No monitor probes sent to pool members

Environment

  • BIG-IP VE 
  • DB key provision.tmmcount

Cause

Changing provision.tmmcount from the default of 0 requires a full reboot. Changing the value will trigger a restart of TMM but the Bigd process will still be trying to communicate with potentially non-existent TMM's and so never gets to send out monitor probes.

Recommended Actions

After changing DB key provision.tmmcount, reboot the VE fully.

Additional Information

Changing the DB key provision.tmmcount is not recommended unless for a specific reason. Best left at 0 to allow the system to determine the required TMM count based on resource.
