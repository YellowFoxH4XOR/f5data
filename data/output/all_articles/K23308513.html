K23308513: Unable to Login to OWA 2016 mail servers after applying Microsoft patches for KB5005043 and/or KB5004779

Published

Source

Description
After downloading and applying Microsoft's patches for KB5005043 and/or KB500477, you can no longer log in to Outlook 2016. The login page is displayed, the credentials are entered, and then the user is returned to the login screen over and over.
The initial BIG-IP deployment was made using the F5 iApp MS Exchange template.

Environment

  • iApp MS Exchange template
  • Microsoft security patches.
  • Persistence profiles.

Cause
By default, there is no persistence requirement for MS exchange. The F5 iApp MS Exchange template has no persistence setting by default. But, can be manually added after the initial build.
It seems that after applying Microsoft's security patch on the MS exchange servers,  the MS exchange server cluster behavior has changed. Now a user is required to be load balanced to the same server all the time. A source address persistence setting on the F5 virtual server is required to fix the MS exchange login error.

Recommended Actions

Enable a persistence profile so that the user is always communicating with the same backend server.
  1. Since the deployment was made through an iapp, follow the instructions in article K51033596 to enable modifications in the iApp.
  2. Enable persistence on the Virtual server
    1. In the GUI, go to Local Traffic  ››  Virtual Servers : Virtual Server List  ››  << MS Exchange Virtual Server>>
    2. Click on the tab Resources.
    3. Under the section Load Balancing, there is a Default persistence Profile section, select the most appropriate persistence option for your deployment.
Note: For more information on each of the persistence options, review the article in the Related Content section.
  1. Re-enable strict updates on the iApp, by checking back the checkbox from step 1.
