K000163648: HA synchronization failure caused by a non-existent Self-IP

Type
Support Solution
Published
2026-10-10
Updated
2026-10-10
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163648

Description

BIG-IP LTM HA Device Service Clustering synchronization fails with the error:

0107146f:3: Self-device unicast source address cannot reference the non-existent Self IP (<IPAddress>); Create it in the /Common folder first.

The issue can also occur when you reinitiate the trust between HA pairs.

Environment

  • BIG-IP LTM
  • HA pairs
  • Network failover and ConfigSync configured.

Cause

A DSC device object retains a reference to a Self-IP after the Self-IP has been deleted or is no longer available. During synchronization, the receiving device validates its local DSC configuration and rejects the transaction because the referenced address does not exist.

Answer/Recommended Actions

1. Identify the invalid reference.

Run:

show /cm device

Review the following fields for each device:

  • Configsync Ip
  • Mirroring IP
  • Mirroring Secondary IP
  • Failover Unicast IP(s)

Then verify the local Self IP objects:

tmsh list net self all-properties

Compare every DSC address with the local /Common Self IP list.

2. Remove or replace the stale address:

Use the BIG-IP Configuration utility:

  1. Go to Device Management > Devices.
  2. Select the affected local device.
  3. Open Failover Network.
  4. Review Failover Unicast Configuration.
  5. Remove the stale address or replace it with an existing valid /Common Self IP.
  6. Review the ConfigSync and Mirroring settings as well.
  7. Click Update and save the configuration.
