K000134712: Prometheus is not able to scrape endpoints within the mesh

Type
Support Solution
Published
2023-05-19
Updated
2023-05-19
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000134712

Description

Can't scrape the application metric endpoints with Prometheus while using Aspen Mesh. Prometheus is not able to reach the endpoint displaying the error message "connection reset by peer".


Environment

Aspen Mesh 1.14.x


Cause

In Aspen Mesh, each component exposes an endpoint that emits metrics. Port 15090 is used to expose Envoy Prometheus telemetry only whereas port 15020 exposes merged Prometheus telemetry from Istio agent, Envoy, and application if enabled in the overrides value file with

meshConfig:
  enablePrometheusMerge: true

Prometheus needs to be configured to scrape either of these ports based on your needs.


Recommended Actions

The following example located in the file prometheus-operator.yaml in the samples/addons/extras folder of the Aspen Mesh package could be used to set up Prometheus to scrape Aspen Mesh merged metrics (:15020/stats/prometheus).

apiVersion: monitoring.coreos.com/v1
kind: PodMonitor
metadata:
  name: envoy-stats-monitor
  namespace: istio-system
  labels:
    monitoring: istio-proxies
    release: istio
spec:
  selector:
    matchExpressions:
    - {key: istio-prometheus-ignore, operator: DoesNotExist}
  namespaceSelector:
    any: true
  jobLabel: envoy-stats
  podMetricsEndpoints:
  - path: /stats/prometheus
    interval: 15s
    relabelings:
    - action: keep
      sourceLabels: [__meta_kubernetes_pod_container_name]
      regex: "istio-proxy"
    - action: keep
      sourceLabels: [__meta_kubernetes_pod_annotationpresent_prometheus_io_scrape]
    - sourceLabels: [__address__, __meta_kubernetes_pod_annotation_prometheus_io_port]
      action: replace
      regex: ([^:]+)(?::\d+)?;(\d+)
      replacement: $1:$2
      targetLabel: __address__
    - action: labeldrop
      regex: "__meta_kubernetes_pod_label_(.+)"
    - sourceLabels: [__meta_kubernetes_namespace]
      action: replace
      targetLabel: namespace
    - sourceLabels: [__meta_kubernetes_pod_name]
      action: replace
      targetLabel: pod_name
---
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: istio-component-monitor
  namespace: istio-system
  labels:
    monitoring: istio-components
    release: istio
spec:
  jobLabel: istio
  targetLabels: [app]
  selector:
    matchExpressions:
    - {key: istio, operator: In, values: [pilot]}
  namespaceSelector:
    any: true
  endpoints:
  - port: http-monitoring
    interval: 15s

 

Additional Information

The above recommended action is only an example and it's not meant to cover all scenarios. For more information regarding Prometheus configuration please go to this link. For more information regarding the Prometheus operator please go to this link.
Prometheus is an open source monitoring system and time series database. You can use Prometheus with Aspen Mesh to record metrics that track the health of Aspen Mesh and of applications within the service mesh.
The Aspen Mesh support team does not support Prometheus or its configuration however they can provide limited guidance based on the documentation available.
