Known Issue

This is the result of a known issue. ZoneRunner can cause an error message to be generated after a hotfix is installed. The error message is reported in the /var/log/gtm file when the configuration is loading and is attempting to match a zone to a wide IP.

For example:

Mar 6 17:24:20 big-ip2 big3dshim: 01320000:3: big3dshim started ===============================
Mar 6 17:24:44 big-ip2 zrd: 01150331:3: Error creating zone gtm2.net., zone file /var/named/config/namedb/db.external.gtm2.net. already exists
Mar 6 17:24:44 big-ip2 gtmd: 011ae020:5:
Connection in progress to 10.1.1.2
Mar 6 17:24:44 big-ip2 gtmd: 011ae01b:5: Failed to connect to remote site 10.1.1.2: Transport endpoint is not connected
Mar 6 17:24:44 big-ip2 zrd: 01150331:3: Error creating zone gtm2.net., zone file /var/named/config/namedb/db.external.gtm2.net. already exists

As a result, no zones will be displayed in ZoneRunner after the BIG-IP GTM reboots. The wide IPs are not affected.

F5 Product Development tracked this issue as CR76376 and it was fixed in BIG-IP 9.4.2. For information about upgrading, refer to the BIG-IP GTM release notes.
