Topic

DNS Queries over HTTPS (DoH) is a protocol that uses HTTPS and allows a client to:

  • Send DNS queries to a DoH server.
  • Get DNS responses back from a DoH server.
This protocol ensures that communication between the client and resolver is authenticated and encrypted, thereby preventing DNS spoofing. The specific details about this protocol are defined in the Internet Engineering Task Force (IETF) RFC 8484:DNS Queries over HTTPS (DoH).

Description

Starting in BIG-IP 16.1.0, the BIG-IP supports DoH in the following modes:

  • BIG-IP DoH proxy—A passthrough proxy that proxies the client’s DoH request to a backend DoH server and the backend DoH server’s response back to the DoH client.
  • BIG-IP DoH server—The server translates the client’s DoH request into a standard DNS request and forwards the DNS request using TCP or User Datagram Protocol (UDP) to the configured DNS server, such as the BIG-IP named process and the BIG-IP DNS cache feature. When the BIG-IP system receives a response from the configured DNS server, it translates the DNS response into a DoH response before sending it to the DoH client.

DNS and HTTP behaviors

The BIG-IP DoH listeners exhibit the following behaviors with DNS and HTTP, as defined in the IETF RFC 8484: DNS Queries over HTTPS (DoH):

  • The BIG-IP DoH listeners always return a successful HTTP response with a 2xx status code as long as there is a DNS response, even if the DNS response contains a failure status, such as SERVFAIL or NXDOMAIN.
  • An HTTP response with a non-successful HTTP status code does not contain replies to the original DNS question from the DoH client request.
  • The HTTP content type supported by DoH is application/dns-message, which contains a single message of the DNS format defined by IETF RFC 1035.
  • When using the HTTP GET method, the DNS message must be base64url encoded with a valid URI dns-query and variable dns.

    For example, the following code represents a base64url encoded query for www.f5.com:

    dns-query?dns=AAABAAABAAAAAAAAA3d3dwJmNQNjb20AAAEAAQ

    Additionally, the HTTP GET request must have the following HTTP header:

    accept: application/dns-message

  • When using the HTTP POST method, you cannot encode the DNS message. You must use DNS wire format (as defined in IETF RFC 1035) in the HTTP message body and the URI dns-query.

    Additionally, the HTTP POST method must have the following HTTP headers:

    Content-Type: application/dns-message and accept: application/dns-message.

  • The maximum size of a DNS message supported by DoH protocol is 65535 bytes.

Configuration

You can locate the configuration of the BIG-IP DoH proxy and DoH server on the DNS > Delivery > Listeners > DoH Proxy Listeners page and the DNS > Delivery > Listeners > DoH Server Listeners page, respectively.

The following lists the profiles required for each of these DoH listeners.

BIG-IP DoH proxy listener

  • TCP (client) and TCP (server)
  • ClientSSL and ServerSSL

    Note: If you attempt to associate ClientSSL and ServerSSL profiles that have the Renegotiation setting enabled, the system returns an error that it is incompatible with the default HTTP/2 profile. This is because the default HTTP/2 profile has the Enforce TLS Requirements setting enabled.

  • HTTP
  • HTTP/2 (client) and HTTP/2 (server)
  • HTTP router
  • DNS

    Note: If you attempt to associate a DNS profile that has the DNS IPv6 to IPv4 setting enabled with a DoH proxy, the system returns the following error:

    01070734:3: Configuration error: DNS profile with DNS64 enabled is disallowed in doh-proxy-listener

  • DoH proxy

BIG-IP DoH server listener

  • TCP (client)
  • TCP (server) or UDP (server)
  • ClientSSL

    Note: If you attempt to associate a ClientSSL profile that has the Renegotiation setting enabled, the system returns an error that it is incompatible with the default HTTP/2 profile. This is because the default HTTP/2 profile has the Enforce TLS Requirements setting enabled.

  • HTTP
  • HTTP/2 (client)
  • DNS
  • DoH server

The BIG-IP system has strict validations to enforce the inclusion of these profiles for these two DoH listeners. If you attempt to remove any of these profiles from existing DoH listeners, the BIG-IP system returns an error.

Limitations

At this time of publication, note the following limitations:

  • The BIG-IP system does not provide statistics, such as DoH queries and responses for doh-server and doh-proxy profiles. As a result, you must use the DNS and HTTP/2 profiles associated with the DoH proxy or server to gather the necessary statistics.
  • The BIG-IP DoH listeners support only the DNS message HTTP media type (application/dns-message) and do not support the JSON content type. The JSON content type is supported by certain public DoH resolvers such as Cloudflare and Google.
  • The BIG-IP DoH listeners do not support HTTP freshness lifetime (Cache-Control: max-age=<RRsets TTL>) for HTTP GET method when the DNS sources are DNS Express and DNS cache. The HTTP cache controls are supported when the DNS sources are WideIPs and BIG-IP bind server.

Recommendations

When deploying a BIG-IP DoH proxy or server, consider the following factors:

  • The client browsers that support DoH typically require that DoH servers have a valid SSL certificate, which they verify with their certificate bundles. When they fail verification, the client browsers may display the error ERR_NXDOMAIN for a page load failure.
  • If you are deploying a BIG-IP DoH listener for your organization to use internally, consider deploying the DoH listener SSL certificate and/or certificate chain to your DoH client browsers.
  • If you are deploying a public facing BIG-IP DoH listener, consider deploying the DoH listener with an SSL certificate signed by a public certification authority (CA).
  • If the deployed BIG-IP DoH listener does not appear to be serving DNS queries, check the following:
    • Verify that the DoH listener is online.
    • Verify the statistics of the profiles associated to the DoH listener in the following order to determine the layer experiencing an issue:
      • TCP
      • ClientSSL
      • HTTP/2
      • DNS
