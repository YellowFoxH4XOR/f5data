K000136206: Exclude Multus CNI interfaces from istio-proxy traffic interception

Description

Pod iptables are modified to exclude the net1 interface added by Multus CNI from istio-proxy traffic interception:

:ISTIO_REDIRECT - [0:0]
:ISTIO_IN_REDIRECT - [0:0]
:ISTIO_OUTPUT - [0:0]
-A PREROUTING -i net1+ -j RETURN
-A PREROUTING -p tcp -j ISTIO_INBOUND
-A OUTPUT -o net1+ -j RETURN
-A OUTPUT -p tcp -j ISTIO_OUTPUT
-A ISTIO_INBOUND -p tcp -m tcp --dport 15008 -j RETURN
-A ISTIO_INBOUND -p tcp -m tcp --dport 22 -j RETURN
-A ISTIO_INBOUND -p tcp -m tcp --dport 15020 -j RETURN
-A ISTIO_INBOUND -p tcp -m tcp --dport 15021 -j RETURN

-A ISTIO_IN_REDIRECT -p tcp -j REDIRECT --to-ports 15006
-A ISTIO_OUTPUT -p tcp -m tcp --dport 15020 -j RETURN
-A ISTIO_OUTPUT -s 127.0.0.6/32 -o lo -j RETURN

-A ISTIO_OUTPUT -m owner --uid-owner 1337 -j RETURN
-A ISTIO_OUTPUT ! -d 127.0.0.1/32 -o lo -m owner --gid-owner 1337 -j ISTIO_IN_REDIRECT
-A ISTIO_OUTPUT -o lo -m owner ! --gid-owner 1337 -j RETURN

-A ISTIO_OUTPUT -d 10.42.0.0/16 -j RETURN

COMMIT


Environment

Aspen Mesh 1.11.x, Aspen Mesh 1.14.x, Multus CNI
 

Cause

Custom/third party application running in the pods modifies the iptables to exclude the net1 interface because Aspen Mesh 1.11.x or 1.14.x cannot modify the iptables to exclude an interface.
 

Recommended Actions

A possible workaround in Aspen Mesh 1.11.x or 1.14.x is to use the traffic.sidecar.istio.io/excludeOutboundIPRanges annotation.


Additional Information

The istio-init container or istio-cni node daemon set up iptables in the pod to intercept and redirect all traffic i.e. the outbound traffic is diverted from its original destination to the proxy, and inbound traffic arrives at the proxy before the application has a chance to handle the incoming request. More information on this link https://github.com/istio/istio/wiki/Understanding-IPTables-snapshot .

The feature to exclude an interface from traffic interception was added in Istio 1.15 (non Istio-CNI plugin) and Istio 1.17 (Istio-CNI plugin) by using the traffic.sidecar.istio.io/excludeInterfaces annotation.

Multus CNI is a container network interface (CNI) plugin for Kubernetes that enables attaching multiple network interfaces to pods. Typically, in Kubernetes each pod only has one network interface (apart from a loopback) -- with Multus you can create a multi-homed pod that has multiple interfaces. This is accomplished by Multus acting as a "meta-plugin", a CNI plugin that can call multiple other CNI plugins.
 

You can the review the IPtables following this procedure:

  1. Identify a node that is running a pod with a istio-proxy injected.
  2. Login into that node
  3. Identify the PID: [node]$ sudo ps auxf | grep envoy or [node]$ sudo ps auxf | grep IpAddressOfThePod
  4. Get the iptables using the PID: [node]$ sudo nsenter -t ${PROXY_PID} -n iptables-save
