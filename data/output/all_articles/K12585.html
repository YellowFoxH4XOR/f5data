Known Issue

This is the result of a known issue. When you enable the Verified Accept option for a TCP profile that is assigned to an IPv6 virtual server, the TMM process will core upon completing a TCP three-way handshake. This issue occurs when both the virtual server and pool member are configured with an IPv6 IP Address.

Note: The Verified Accept TCP profile option is available in version 10.x and disabled by default. When enabled, the system verifies that the pool member is available to accept the connection by sending the server a SYN before responding to the client's SYN with a SYN-ACK.

For example, the following will produce the TMM crash:

profile tcp va_tcp {
defaults from tcp
verified accept enable
}

virtual ipv6_http_virtual {
pool ipv6_http_pool
destination 3ffe:501:ffff:100:0:1:30:15.http
ip protocol tcp
profiles va_tcp {}
}

pool ipv6_http_pool {
monitor all http
members 3ffe:501:ffff:100:0:1:30:180.http {}
}
