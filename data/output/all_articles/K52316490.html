Topic

This article discusses the expected behavior regarding the order of precedence when the RADIUS profile persistence is used together with other persistence profiles. This article also provides examples on identifying the persistence mode using the Traffic Management Shell (tmsh).

Description

When you configure the Persist Attribute setting in a Remote Authentication Dial-In User Service (RADIUS) profile and associate it with a virtual server, the BIG-IP system forwards client-initiated RADIUS messages to the backend RADIUS servers and persists them to the appropriate servers based on the configured Persist Attribute setting. The following tmsh show ltm persistence persist-records all-properties command output shows the persistence record for a RADIUS client connection in this scenario, where the Mode is displayed as universal (which is the default):

Sys::Persistent Connections
universal - 10.50.50.161:1812 - 172.50.50.171:1812
--------------------------------------------------
   TMM           0
   Mode          universal
   Value         test
   Age (sec.)    2
   Virtual Name  /Common/radius-vs1
   Virtual Addr  10.50.50.161:1812
   Node Addr     172.50.50.171:1812
   Pool Name     /Common/radius-pool1
   Client Addr   10.50.50.176
   Owner entry

When you also associate a persistence profile other than type Hash or Universal to the RADIUS virtual server, the persistence profile takes precedence over the persistence from the RADIUS profile. The following tmsh show ltm persistence persist-records all-properties command output shows the persistence record for a RADIUS client connection when a virtual server is associated with both a RADIUS profile and a source address persistence profile; note that the Mode is displayed as source-address:

Sys::Persistent Connections
source-address - 10.50.50.161:1812 - 172.50.50.171:1812
-------------------------------------------------------
   TMM           1
   Mode          source-address
   Value         10.50.50.176
   Age (sec.)    36
   Virtual Name  /Common/radius-vs1
   Virtual Addr  10.50.50.161:1812
   Node Addr     172.50.50.171:1812
   Pool Name     /Common/radius-pool1
   Client Addr   10.50.50.176
   Owner entry 

The exception to this is when you associate a Hash or Universal persistence profile, which changes the persistence from the RADIUS profile to use the persistence profile method on the value of the configured Persist Attribute setting from the RADIUS profile. For example, a Hash persistence profile causes the value of the configured Persist Attribute setting from the RADIUS profile to be hashed. The following tmsh show ltm persistence persist-records all-properties command output shows the persistence record for a RADIUS client connection when a virtual server is associated with both a RADIUS profile and a hash persistence profile; note that although the Mode is displayed as hash, the persistence is based on the hashed value of the configured Persist Attribute setting from the RADIUS profile:

Sys::Persistent Connections
hash - 10.50.50.161:1812 - 172.50.50.171:1812
---------------------------------------------
   TMM           0
   Mode          hash
   Value         3632233996
   Age (sec.)    1
   Virtual Name  /Common/radius-vs1
   Virtual Addr  10.50.50.161:1812
   Node Addr     172.50.50.171:1812
   Pool Name     /Common/radius-pool1
   Client Addr   10.50.50.176
   Owner entry
