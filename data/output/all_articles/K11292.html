K11292: ICMP monitors may generate numerous entries in the connection table

Published

  • BIG-IP LTM: 9.4.8, 9.4.6, 9.4.5, 9.4.4, 9.4.3, 9.4.2, 9.4.7, 9.4.0, 9.3.1, 9.3.0, 9.4.1
Source

Topic

Starting in BIG-IP version 9.3.0, BIG-IP assigns a unique ICMP ID to each ICMP request it sends to a monitored node, resulting in a new connection table entry for each request. These entries remain in the connection table for up to five minutes. As a result, a five-second polling interval results in 60 connections for each monitored node. These additional connections must be taken into account when viewing connection statistics such as the Active Connections graph or the output of the b conn command.

Note: This behavior does not apply to BIG-IP version 10.x. Although BIG-IP version 10.x assigns a unique ICMP ID to each ICMP request, the connections time out after 10 seconds.

Note: For BIG-IP version 9.3.0, this behavior was introduced by CR61990 in HF2.

F5 Product Development is considering a request for enhancement (RFE) for the 9.4.x software branch to implement a shorter timeout value for ICMP monitor connection entries. F5 Product Development is tracking this RFE as CR87483.
