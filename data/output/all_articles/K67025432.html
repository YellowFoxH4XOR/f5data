Topic

Starting with BIG-IP 13.0.0 you can configure the BIG-IP system to use authentication fallback when the BIG-IP is configured for system user remote authentication.

Note: Fallback is disabled by default to preserve the behavior from previous BIG-IP releases.

You should consider using this procedure when your BIG-IP system is configured for remote authentication for BIG-IP system users.

  • You want a local users to be able to access the BIG-IP system when the remote authentication server is unavailable.
  • You want a local users to be able to access to the BIG-IP system when the users are locally configured on the BIG-IP and are not configured on the remote authentication server.
  • You want local or remote users to access to the BIG-IP system through SSH using SSH public key authentication.

Description

There are three categories of the types of configured users for a BIG-IP system:

  • Local-only users: Only two users currently belong to this category and are hard-coded into the BIG-IP configuration: root and admin. These users are never authenticated remotely and only the locally defined password or the SSH public key for the users is used to allow remote logins. This category of users is not affected by this procedure.
  • Local users: These users are defined locally on the BIG-IP system and use either a locally-defined password or an SSH public-key to allow remote logins. However, when a remote authentication method is defined on the BIG-IP system, the locally-defined password ceases to work and only the remote authentication server can grant access. This behavior is the subject of this procedure.
  • Remote-only users: These users are defined only on the remote authentication server and are assigned a role on the BIG-IP system based on the Remote Role Group configuration or the defaults configured for external users in the remote authentication settings. This category of users is not affected by this procedure.

Note: The authentication fallback option applies only if a remote authentication source is configured for use by the BIG-IP system.

Note:  If SSH Public-key authentication is enabled on the user, the remote authentication will not be used for SSH access.

Expected fallback behavior

The following table shows the expected behavior by user type when fallback is enabled or disabled.

Note: The information in this table is for BIG-IP systems that are already configured for remote authentication.

User typeFallback option de-selected (default)Fallback option selected
Local-only (root, admin)
  • Access the device using local device authentication.
  • Access the device using SSH public-key authentication.
  • Access the device using local device authentication.
  • Access the device using SSH public-key authentication.
Local, with remote counterpart
  • Access the device using remote authentication.
    Login is denied if a remote authentication server is not available.
  • Access the device using SSH public-key authentication.
  • Access the device using remote authentication when available.

  • Access the device using SSH public-key authentication.
  • Access the device using local device authentication when remote authentication server is unavailable.

  • Access the device using remote authentication.
    Access is denied when remote authentication is not available.

Procedures

  • Configuring fallback authentication using the Configuration utility
  • Configuring fallback authentication using tmsh

Configuring fallback authentication using the Configuration utility

Note: The following procedure assumes that the BIG-IP device is already configured for remote authentication.

Impact: Performing the following procedure enables local authentication for BIG-IP system users in the event that remote authentication is unavailable.

  1. Log in to the Configuration utility.
  2. Go to System > Users > Authentication.
  3. Select Change.
  4. Select the Fallback to Local check box.

    Note: This option is not available for User Directory types Local or Remote - APM Based.

  5. Select Finished.

Configuring fallback authentication using tmsh

Note: The following procedure assumes that the BIG-IP device is already configured for remote authentication.

Impact: Performing the following procedure enables local authentication for BIG-IP system users in the event that remote authentication is unavailable.

  1. Log in to the TMOS Shell (tmsh).
  2. Enter the following command:

    tmsh modify auth source fallback true

  3. Save the configuration change by entering the following command:

    tmsh save sys config

  4. To exit tmsh, enter the following command:

    quit
