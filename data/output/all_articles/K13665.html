Issue

Old Behavior

Previously, when you used the bigpipe command to assign multiple persistence profiles to a BIG-IP virtual server, the BIG-IP system automatically listed them in an alphabetical order and designated the first persistence profile in the list as the default.

New Behavior

Beginning in BIG-IP 10.1.0, you can use the Traffic Management Shell (tmsh) to designate a persistence profile to be the default when you assign multiple persistence profiles to a BIG-IP virtual server. If you do not specify a persistence profile as the default, the BIG-IP system will automatically designate the first persistence profile in an alphabetically ordered list as the default.

F5 Product Development tracked this change as ID 291394 (formerly CR116612).

Impact

The tmsh utility allows you to designate a default persistence profile when assigning multiple persistence profiles to a virtual server.

Recommended Actions

If you want a certain persistence profile to be used, you can designate the persistence profile as the default in a multiple persistence profile configuration. To do so, use the following tmsh command syntax:

tmsh modify ltm virtual <virtual server name> persist replace-all-with { <persistence profile 1> { default [yes|no] } <persistence profile 2> { default [yes|no] } }

For example, you can designate the ssl persistence profile as the default when assigning a cookie and ssl persistence profile to the virtual server http-vs by entering the following tmsh command:

tmsh modify ltm virtual http-vs persist replace-all-with { cookie { default no} ssl { default yes } }

Alternatively, you can use the iRules persist command to control the application of persistence profiles to certain traffic. For more information about the iRules persist command, refer to the following persist wiki on the DevCentral Website:

https://devcentral.f5.com/wiki/iRules.persist.ashx
