Description

This article explains why users may observe different values for new connections per second and other statistics when comparing the BIG-IP device statistics dashboard and performance report graph (GUI) with values obtained via CLI commands. This situation often arises during monitoring or troubleshooting, where GUI and CLI output tmsh show sys performance connections do not exactly match.

Environment

  • Device statistics dashboard (GUI)
  • Performance report graph (GUI)
  • CLI analytics and performance commands
  • Key Commands:
    • tmsh show sys performance connections

Cause

  • The differences between GUI and CLI statistics are expected due to:
    • Different data collection mechanisms and polling intervals:
      - GUI (dashboard) stats are polled every 3 seconds directly from tmctl tables (via rtstats).
      - CLI stats are polled every 10 seconds from RRD files updated from tmctl tables (via statsd).
    • Scope of displayed data:
      - Both the GUI and CLI aggregate entire device connections as seen by TMM (tmctl table: tmm_stat client_side_traffic.tot_conns).
    • Averaging over different time ranges:
      - GUI and CLI typically use different averaging windows.
    • Traffic distribution differences:
      - If one device receives more ingress traffic than another, their connection rates will differ.

Recommended Actions

  • Recognize that minor discrepancies between GUI and CLI statistics are normal due to differences in polling intervals, data sources, and averaging methods.
  • When comparing statistics:
    • Ensure you reference the same time period and scope for both interfaces.
  • Use timestamps to align comparisons as closely as possible.
  • To validate traffic distribution across devices:
    1. Check raw ingress packet rates on each device.
    2. Compare "new connections per second" with ingress packet rates for consistency.
    3. Verify upstream routing is distributing traffic evenly.
  • For further analysis or persistent unexplained discrepancies:
    • Generate QKView files from both devices at the same time for upload to F5 iHealth (https://ihealth.f5.com) .
    • Collect screenshots/CLI outputs with timestamps for support review.

Additional Information

  • These observed differences are by design due to how BIG-IP collects and presents statistical data; they do not indicate a product defect.
  • While values should be close under normal conditions, exact matches are not expected given the system architecture.
  • If one device consistently receives more traffic than another in a round-robin configuration, check network routing/load balancing upstream.
