K000138093: F5 licensing SSL traffic blocked by Azure Firewall due to lack of SNI

Type
Support Solution
Published
2023-12-31
Updated
2025-02-07
Applies to
  • Public Cloud
  • BIG-IP
  • Microsoft Azure
Source
https://my.f5.com/manage/s/article/K000138093

Description

BIG-IP VE deployments behind the Azure Firewall may fail to connect to F5's license server.


Environment

This affects BIG-IP VE deployments deployed behind an Azure Firewall


Cause

The Azure Firewall requires SNI (server Name Indication) when evaluating SSL traffic. When acquiring a license, F5 TMOS will open an SSL connection to F5's license server using SSL. However, this SSL connection to the license server does not add SNI to the ClientHello message, and this causes Azure Firewall to block this traffic.


Recommended Actions

In order to ensure proper licensing operations, you may request more information form Microsoft support to explore options about how to allow SSL traffic without SNI though the Azure firewall.


If there is no possibility to fix the problem at the source, you may want to try to work around the problem with a hotfix that adds SNI to the SSL traffic when F5 requests a license.

This feature is tracked as ID 1291217. To use this feature, please open an F5 support case to request a hotfix that contains ID 1291217.
