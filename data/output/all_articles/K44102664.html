Description

IPsec tunnel negotiation problems occur often after reboot, when the BIG-IP is configured to terminate both IKEv1 and IKEv2 tunnels using the same local IP address.

Tunnels may sometimes work and sometimes fail particularly after a TMM or BIG-IP restart.

In such a situation, racoon.log may report errors in the ISAKMP payload when an IKEv2 packet is misdirected to the IKEv1 handler:

2018-03-11 02:04:23: ERROR: invalid flag 0x08.
At startup, the ltm log will contain the following message:
 
Sep 21 13:12:43 cli_50 err tmm2[25182]: 017c0003:3: Listener binding ERR=12 (DUPLICATE) v1 listener $_ike_2a3e6_in_10.1.1.10 10.1.1.10:500 FAIL
Sep 21 13:12:43 cli_50 notice tmm2[25182]: 017c0004:5: NOTE: Avoid common IPsec v1 and v2 tunnel local addr

This ltm log message above can sometimes fire in false-positive circumstances. If the configuration is correct but this log message still occurs, then it can be safely disregarded.
 

Environment

  • The BIG-IP is configured with both IKEv1 and IKEv2 IPsec tunnels.
  • The same local IP is used on both an IKEv1 and an IKEv2 tunnel.

Cause

The listeners in TMM for catching ISAKMP are not able to distinguish the IKE version. The packet is then internally misdirected.
IKEv1 tunnels must use a different local address to the IKEv2 tunnels. IKEv1 and IKEv2 may separately use multiple or re-use local IPs for multiple tunnels, but there must be no re-use of the local IPs between the two IKE versions.
 

Recommended Actions

Use local IP address "A" for IKEv1 tunnels and IP address "B" for all IKEv2 tunnels.

In IPsec tunnel mode, the local IP is configured in the ipsec-policy configuration object. Note in the following example, tunnel-local-address is different:
 
net ipsec ipsec-policy ipsec-8-0-7-1 {
    ike-phase2-auth-algorithm aes-gcm128
    ike-phase2-encrypt-algorithm aes-gcm128
    mode tunnel
    tunnel-local-address 172.16.8.1
    tunnel-remote-address 172.16.7.1
}
net ipsec ipsec-policy ipsec-8-0-7-2 {
    ike-phase2-auth-algorithm aes-gcm128
    ike-phase2-encrypt-algorithm aes-gcm128
    mode tunnel
    tunnel-local-address 172.16.8.2
    tunnel-remote-address 172.16.7.2
}

In IPsec interface mode, the local IP is specified on the tunnel configuration object. Note in the following example, local-address is different:
 
net tunnels tunnel ipsec-tunnel-3-0-6-1 {
    local-address 172.16.3.1
    profile ipsec-interface-3-0-6-1
    remote-address 172.16.6.1
}
net tunnels tunnel ipsec-tunnel-3-0-6-2 {
    local-address 172.16.3.2
    profile ipsec-interface-3-0-6-2
    remote-address 172.16.6.2
}

The IKE version itself is configured in the ike-peer configuration but has been omitted in these examples.
 

Additional Information

  • IKEv2 was first introduced in 11.6.0 and this limitation has existed in all BIG-IP software versions since then.
  • The local IPs used by IKEv1 and IKEv2 must be existing self IPs on the BIG-IP.
  • The local IPs can be floating self IPs, but not Virtual Addresses.
