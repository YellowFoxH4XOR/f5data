Known Issue

Buffer overflow for large MPI session messages may cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • You have a multi-bladed VIPRION system.
  • The system sends an MPI message larger than 64 k between blades.

    For example, an MPI message contains a session database variable set by an iRule, or the system uses other features that heavily use session database variables.

VIPRION systems use the MPI channel to exchange messaging information between primary and secondary blades.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high-availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Functionality that uses the affected MPI messages may not function as expected.
  • The BIG-IP system may log an error message to the /var/log/ltm file that appears similar to the following example:

    err tmm1[PID]: 01340003:3: Cluster error: max MPI data length exceeded

  • The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart.
  • Devices configured as an HA pair may fail over.
