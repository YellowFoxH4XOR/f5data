K000147400: How do I set up HTTP Idle Timeout?

Description

  • What are the instructions to set up HTTP idle Timeout on the Origin Pool?

Environment

  • F5® Distributed Cloud Console  

Cause

The HTTP Idle Timeout setting is required to control how long an idle HTTP connection to an origin server is kept open before being closed. This helps manage resources efficiently and prevents unnecessary open connections, which could otherwise lead to resource exhaustion or connection issues.

Recommended Actions

1. Go to Manage > Load Balancers 

2. Click Origin Pools

3. Select the origin pool one you want to manage the configuration for

4. Click on the 3 dots next to Manage Configuration

5. Click Edit Configuration in the upright corner

6. Go to Other Settings

7. Click Configure

8. Set up the time for HTTP Idle Timeout

Additional Information

  • HTTP Idle Timeout on the Origin Pool pertains to pooled upstream connections.  This is the max time interval for which an upstream pooled connection may stay open without HTTP activity over it.  Note that this is very much about pooled/reused/shared connections, so might not have anything to do with a specific client's activity.
  • HTTP Idle Timeout on Origin Pool should be set to a lower value than the equivalent timeout (may be called idle timeout or keepalive timeout) on the actual upstream endpoint.  This is because XC, not the upstream endpoint, should be responsible for closure of idle connections.
  • The setting is specifically premised on pooled upstream connections with Connection Reuse in effect (as is the default), controlling the time a reusable but idle connection can remain open.  If Connection Reuse is disabled, the setting is of lesser consequence as it no longer pertains to shared connections.
  • Protocols such as Websockets that cannot reuse upstream connections are exempt from this timeout.
