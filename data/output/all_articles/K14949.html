Known Issue

A newly created AAA server may use the wrong pool after an mcpd restart.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP APM system with several AAA servers.
  • You have configured the AAA servers with pools.
  • After you have restarted mcpd or the BIG-IP APM system, you created or edited an AAA server that is configured with a pool.

This issue occurs when the BIG-IP system has multiple AAA servers, each configured to use a pool of servers. If you create or edit a AAA server that is configured with a pool after you restart the BIG-IP system or mcpd, the AAA server may intermittently use the pool of an existing AAA server instead of its own pool.

Impact

Authentication requests for the newly-added AAA server are intermittently sent to the wrong pool of servers.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H440744 on the Diagnostics > Identified > Medium screen.
  • Users are unable to authenticate through the BIG-IP APM system.
  • Statistics indicate existing AAA server pools receive more authentication traffic than normal.

Workaround

To work around this issue, you can reload the configuration using the Traffic Management Shell (tmsh) utility. To do so, perform the following procedure:

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Load the configuration in all partitions by typing the following command:

    load /sys config partitions all
