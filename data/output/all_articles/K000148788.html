Description

This article addresses a scenario where an application hosted behind a Virtual Server with a configured server SSL profile is not working. Packet capture analysis reveals that the Self IP resets the connection after receiving the Server Hello packet from the pool member (back-end server). You may also observe a TLS handshake failure alert sent from the Self IP.

  • Alert (Level: Fatal, Description: Handshake Failure)

Environment

  • BIG-IP LTM
  • Server SSL profile
  • ca-file configured

Cause

The cause of this issue may be the server SSL profile on the BIG-IP being configured to expect different TLS information or receiving incorrect data in the Server Hello. In this case, the problem is related to the server SSL profile on the affected Virtual Server, which has a ca-file configured. 

 

ltm profile server-ssl /Common/serverssl-example {
  (...)
  c3d-ca-cert none
  c3d-ca-key none
  c3d-cert-extension-includes { basic-constraints extended-key-usage key-usage subject-alternative-name }
  c3d-cert-lifespan 24
  ca-file /Common/ca-bundle.crt <----------!!!!!
  cache-timeout 3600
  cert none
  chain none
  (...)

 

Ca-file specifies the certificate authority file name. Configures certificate verification by specifying a list of client or server CAs that the traffic management system trusts. The default value is none.

Recommended Actions

One of the verification steps is to gather packet capture to analyze the Server Hello packet. This helps confirm the TLS version used by both parties and whether a compatible Cipher Suite has been selected. Following this, check the certificate sent by the pool member and verify if it is included in the ca-bundle.crt file. The file should be placed in the following path config/ssl/ssl.crt/ca-bundle.crt. Each certificate presented in Server Hello should be also configured in the certificate bundle file, if any of certificate is missed the BIG-IP will reset the connection. You can check whether all certificates are presented in the file based on a unique serial number that should be visible in the file and packet trace under certificate details. 

After you confirm some certificate is missing in the bundle file, you can follow K60612439 to manually add the missing one and check the connection.
