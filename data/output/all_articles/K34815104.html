Description

Upgrading r5000 and r10000 series appliances os from 1.0.x to 1.1.0 or higher results tenant to be in inoperative state.
/var/log/ltm may show

systemd[1]: Started Chassis Management Daemon.

chmand is not starting service and mcpd is waiting for chmand to start, and try to generate qkview cause crash with core.

bigstart status chmand
chmand is stopped

bigstart status mcpd
mcpd                  down, Waiting for chmand start: 181 seconds

qkview
terminate called after throwing an instance of 'std::runtime_error'
  what():  error connecting to local mcp
Aborted (core dumped)
 

Environment

  • F5OS-A
  • rSeries r5000/r10000 series appliances
  • Upgrade from 1.0.x

Cause

  • Bug ID 1076949

Recommended Actions

Before upgrade, set Tenants to Provision State.
If the tenant is already upgraded and in an inoperative state,  move the tenants to Provision mode and then back to Deploy mode
