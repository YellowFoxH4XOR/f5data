Description

With Bug ID705818 fix, when virtual server does not have default pool but its load-balancing pool is to be selected by indirect traffic policy rule, GUI Network Map page should display pool members of the virtual server.


Here is example configuration and GUI Network Map screenshot without issue. On "policy_vs" virtual server, Traffic policy dynamically selects "p1", "p2", and "p3" pools based on request http-uri value. On GUI Network Map page, all these 3 pools are displayed.

ltm pool /Common/p1 {
    members {
        /Common/192.168.10.54:80 {
            address 192.168.10.54
        }
    }
    monitor /Common/tcp
}
ltm pool /Common/p2 {
    members {
        /Common/192.168.10.55:80 {
            address 192.168.10.55
        }
    }
    monitor /Common/tcp
}
ltm pool /Common/p3 {
    members {
        /Common/192.168.10.56:80 {
            address 192.168.10.56
        }
    }
    monitor /Common/tcp
}
ltm policy /Common/my_policy {
    controls { forwarding }
    requires { http }
    rules {
        1st_rule {
            actions {
                0 {
                    forward
                    select
                    pool /Common/p1
                }
            }
            conditions {
                0 {
                    http-uri
                    path
                    starts-with
                    values { /1st }
                }
            }
        }
        2nd_rule {
            actions {
                0 {
                    forward
                    select
                    pool /Common/p2
                }
            }
            conditions {
                0 {
                    http-uri
                    path
                    starts-with
                    values { /2nd }
                }
            }
            ordinal 1
        }
        3rd_rule {
            actions {
                0 {
                    forward
                    select
                    pool /Common/p3
                }
            }
            conditions {
                0 {
                    http-uri
                    path
                    starts-with
                    values { /3rd }
                }
            }
            ordinal 2
        }
        default {
            actions {
                0 {
                    shutdown
                    connection
                }
            }
            ordinal 3
        }
    }
    strategy /Common/first-match
}
ltm virtual /Common/policy_vs {
    destination /Common/10.1.1.164:80
    ip-protocol tcp
    mask 255.255.255.255
    policies {
        /Common/my_policy { }
    }
    profiles {
        /Common/http { }
        /Common/tcp { }
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
}

 

Figure: Network Map displays virtual server's pool members, which are selected by traffic policy.

 

 

However, Bug ID1223589 can affect such type of virtual server as well and can prevent pool members from being displayed.
For example, when following virtual server (which triggers Bug ID1223589) was additionally configured, GUI Network Map page does not properly load "policy_vs" virtual server pool members.

ltm node /Common/192.168.10.154:53 {
    address 192.168.10.154
}
ltm pool /Common/dns_pool {
    members {
        /Common/192.168.10.154:53:53 {
            address 192.168.10.154
        }
    }
}
ltm virtual /Common/dns_vs {
    destination /Common/10.1.1.161:53
    ip-protocol udp
    mask 255.255.255.255
    pool /Common/dns_pool
    profiles {
        /Common/dns { }
        /Common/udp { }
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
}

 

Figure: Network Map does not display virtual server's pool members under specific condition.

 

Environment

  • Affected virtual server does not have default pool. Affected virtual server is configured with traffic policy which selects load-balancing pool based on policy conditions/actions.
  • There is a node object whose node name is "<IPv4>:<port>" format. And the other virtual server uses the offending "<IPv4>:<port>" node object as a pool member.

 

Cause

Bug ID1223589.

 

Recommended Actions

Apply Bug ID1223589 workaround. Avoid using "<IPv4>:<port>" name node object (i.e., rename such node object with "IPv4" address only).

### before ID1223589 workaround applied ###
ltm node /Common/192.168.10.154:53 {
    address 192.168.10.154
}
ltm pool /Common/dns_pool {
    members {
        /Common/192.168.10.154:53:53 {
            address 192.168.10.154
        }
    }
}

==>

### after ID1223589 workaround applied ###
ltm node /Common/192.168.10.154 {
    address 192.168.10.154
}
ltm pool /Common/dns_pool {
    members {
        /Common/192.168.10.154:53 {
            address 192.168.10.154
        }
    }
}
