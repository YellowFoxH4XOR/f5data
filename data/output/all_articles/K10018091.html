Known Issue

The BIG-IP system may unexpectedly close Secure Sockets Layer (SSL) connections during secure renegotiation.

This issue occurs when all of the following conditions are met:

  • Your client and server are configured with Secure Renegotiation and Session ticket options.
  • Your BIG-IP system uses a virtual server with Proxy SSL enabled.

The Transport Layer Security (TLS) Session Ticket option is not supported when the Proxy SSL option is enabled. Therefore, endpoints are able to negotiate this extension. However, if a renegotiation is initiated, an SSL alert is generated and the connection is closed.

Impact

The BIG-IP system generates an SSL alert and closes the connection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system generates an SSL alert and closes the connection.
  • The BIG-IP system logs a SSL codec alert messages to the /var/log/tmm file that appears similar to the following example:

    ERROR: ssl_hs_change_codec:773: out of order messages

Workaround

To work around this issue, you can disable the TLS Session Ticket option in the server configuration.

Impact of workaround: The SSL client and server will not be able to use session tickets for TLS session resumption. The server may fall back to use an SSL session cache, or may cause the client to go through the full handshake process for each new connection.
