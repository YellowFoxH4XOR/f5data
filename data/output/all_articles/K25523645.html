Topic

You should consider using this procedure under the following condition:

  • Your environment includes multiple Cisco Web Service Application (WSA) proxies.
  • You want to load balance web proxy request across the WSA servers in a fault-tolerant configuration.

Description

You can configure the BIG-IP system to load balance Cisco WSA proxy requests across a pool of WSA proxy servers. Additionally, you can configure the pool of WSA proxy servers with a health monitor to ensure request are load balanced to an available WSA proxy server. You can perform the following procedures to create the required components for load balancing WSA proxy request.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You've deployed WSA proxy servers and your BIG-IP system can access them.
  • You have administrative access to the BIG-IP Configuration utility.

Procedures

  • Creating a custom WSA health monitor
  • Creating a custom HTTP profile with the Insert X-Forwarded-For option enabled
  • Creating a pool of WSA proxy servers
  • Creating the WSA virtual server

Creating a custom WSA health monitor

To create a BIG-IP system health monitor for monitoring the WSA servers, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. Enter a name for the monitor.
  5. For Type, select TCP Half Open.
  6. Under Configuration, leave Interval set to 5 and Timeout set to 16.
  7. Select Finished.

Creating a custom HTTP profile with the Insert X-Forwarded-For option enabled

Important: The procedure below only works when the BIG-IP system terminates the SSL connection, so it has access to the unencrypted HTTP data, otherwise, the WSA servers (nodes/backend servers) will not be able to see the real client IP address as it will see the NATed IP address on the BIG-IP
For more details refer to K4816: Using the X-Forwarded-For HTTP header to preserve the original client IP address for traffic translated by a SNAT object .

Note: Another option is to disable SNAT and change your routing configuration to ensure that the response to the client returns through the BIG-IP.
For more details refer to K47059113: Disable NAT/SNAT on a specific Virtual Server (VS) when NAT/SNAT is configured on F5 BIG-IP.


To configure the BIG-IP system to insert the original client IP address in an X-Forwarded-For HTTP header, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles.
  3. For Services, select HTTP.
  4. Select Create.
  5. Enter a name for the HTTP profile.
  6. For Insert X-Forwarded-For, select the Custom check box and select Enabled.
  7. Select Finished.

Creating a pool of WSA proxy servers

To configure a pool containing the destination WSA proxy servers, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools.
  3. Select Create.
  4. Enter a name for the pool.
  5. For Health Monitor, in the Available list, select the monitor you previously created and move it to the Active list.
  6. Under Resources, for Load Balancing Method, select the preferred method.

    Note: F5 recommends using the Least Connections (member) option in environments where the BIG-IP system also load balances other services to the WSA proxy servers, such as FTP, HTTPS, or SOCKS.

  7. In New Members, for Address, enter the IP address of the first WSA proxy server, and for Service Port, enter the TCP port configured on the WSA servers (typically port 3128).
  8. Select Add.
  9. Repeat Steps 7 and 8 to add more WSA proxy servers.
  10. Select Finished.

Creating the WSA virtual server

To create the wildcard port virtual server, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select Create.
  4. Enter a name for the virtual server.
  5. For Type, select Standard.
  6. For Destination Address/Mask, select Host and enter the virtual IP address for load balancing request to the WSA server pool.
  7. For Service Port, select Port and enter the TCP port that the WSA proxy receives on (typically port 3128).
  8. For Configuration, select Advanced.
  9. For VLAN and Tunnel Traffic, select Enabled on.
  10. For VLAN List, in the Available list, select the VLAN from which the WSA proxy clients connect and move it to the Selected list.
  11. For Source Address Translation, select Auto Map.
  12. For Default Pool, select the WSA proxy pool you previously created.
  13. For Persistence, select None.
  14. Select Finished.
