K2564: Reasons why BIG-IP still directs traffic to nodes on which the SNMP_DCA monitor threshold has been exceeded

Topic

When using Dynamic Ratio load-balancing mode, BIG-IP bases the node selection on the specific metrics supplied. You can use the SNMP_DCA monitor to configure the threshold for these metrics.

When SNMP traffic between BIG-IP and a node is monitored and the value returned by the node exceeds the configured threshold, traffic is still load balanced to it. This occurs because BIG-IP assigns a dynamic ratio to each node expressed as a fraction. If the configured threshold is exceeded, the dynamic ratio for that node is set to 1. This does not stop traffic from being sent to the node.

For example, if a pool contains two nodes, both of which have a current dynamic ratio of 1, BIG-IP will round robin connections between them.

You can observe the load balancing ratios that BIG-IP assigns to nodes by typing the following command:

bigpipe node <ip address> dynamic_ratio show

Note: Dynamic Ratio is not a method you should use to determine server availability; health monitoring is a more effective measure of server health. For information about configuring health monitors, refer to the BIG-IP manual.
