K000160261: F5 BIG-IP APM OAuth Client Fails to Communicate with Internal VIP When IPv6 Is Disabled

Type
Support Solution
Published
2026-03-06
Updated
2026-04-21
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160261

Description

OAuth authentication requests fail with HTTP 503 errors during the token exchange process. The APM OAuth Client attempts to communicate with an internally configured OAuth Authorization Server via a virtual server (VIP) on the same BIG-IP device, but the requests do not reach their destination. APM logs show repeated HTTP 503 errors with "Connect failed" messages. DNS resolution and SSL certificate validation are confirmed to be working correctly.

Environment

  • Product: BIG-IP APM
  • Version: 17.5.1
  • Platform: F5-VEL-BTA-CX410-AC, F101
  • Configuration:
    • OAuth Authorization Server configured as an internal VIP on the same BIG-IP device
    • APM OAuth Client agent configured to use the internal VIP for backchannel token requests
    • DNS resolution and SSL certificate validation confirmed operational
    • IPv6 disabled on the BIG-IP system (ipv6.enabled = false)
  • All relevant virtual servers and access policies are in the same partition and route domain

Cause

The root cause is the BIG-IP system's IPv6 functionality being disabled (ipv6.enabled = false). The APM OAuth Client relies on IPv6 for internal communication with the OAuth Authorization Server's VIP. Disabling IPv6 prevents these internal requests from being routed correctly, resulting in HTTP 503 errors and failed authentication.

Answer/Recommended Actions

To resolve the issue:

  1. Enable IPv6 on the BIG-IP system:
    tmsh modify sys db ipv6.enabled value true
  2. Verify that internal communication between the APM OAuth Client and the OAuth Authorization Server VIP is restored.
  3. Confirm successful OAuth authentication and token exchange after enabling IPv6.

Note: It is by design that internal renderers and communication within BIG-IP use IPv6 addresses. Disabling IPv6 will break this internal communication. There is no supported method to force these communications to use IPv4 only.

Additional Information

  • Using the VIP's IP address instead of its FQDN, or removing ASM/security profiles, does not resolve the issue if IPv6 is disabled.
  • This behavior is expected; IPv6 must be enabled for proper internal communication between APM OAuth Client and internal VIPs.
  • If there is no specific reason to keep IPv6 disabled, it should remain enabled for APM OAuth functionality.
