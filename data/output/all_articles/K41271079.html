Description

In rare cases when the there is an interruption of the BIG-IP system during an update of the localdbmgr the BIG-IP APM Local User DB can lose data.  This data can be restored from a BIG-IP archive file (UCS).

Environment

  • BIG-IP APM
  • Populated Local User DB
  • Recent UCS Archive

Cause

None

Recommended Actions
If you have a CSV backup of the local user database you can import the data using this process 

  • K15266: Creating a new BIG-IP APM local user database by importing a CSV file
If you do not have a CSV backup, but you have a UCS file from the Active device from an HA pair or one from a Standalone device you can follow this process
  1. Using an extraction tool of your choice (7-zip, Winrar, etc) open the UCS archive.
  2. Open the .im file inside the same tool
  3. Navigate to /var/apm/localdb
  4. Decompress restore.sql 
  5. Place the restore.sql file on the Active or Standalone BIG-IP device you wish to restore.  The /var/tmp (symlink of /shared/tmp) generally has the most available space.  This can be done with scp (WinSCP is a common client used for windows)
  6. Clear the partial user database.  This can be done with a select all and delete from the Local DB User List (Access >> Authentication >> Local User DB >> Users)
  7. Use the ldbutil to restore the file using this command:
    ldbutil --restore --file=restore.sql
    Additional information regarding ldbutil can be found here:
    K59100837: Backing up and restoring the BIG-IP APM local user database
  8. If in an HA Pair, the standby device will need to be restarted to sync the Local User DB
