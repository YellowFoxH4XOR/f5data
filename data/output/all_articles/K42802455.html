Known Issue

The configuration fails to load after you upgrade when the system uses an Analytics profile.

This issue occurs when the following condition is met:

  • An Analytics profile contains a configuration option that was valid in a previous BIG-IP version, but is no longer valid in the newly upgraded version. For example, if an Analytics profile alert level is defined with the pool-member granularity option, the configuration will load in BIG-IP 12.0.0, but will not load in BIG-IP 12.1.0, because you must set granularity at the virtual-server level.

Impact

The BIG-IP configuration will not load after you upgrade the system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • In the /var/log/ltm file, you observe a message similar to the following example:

    01071ac1:3: Non-Comulative metric (max-request-throughput) cannot be calculated per single entity (pool-member). Unexpected Error: Validating configuration process failed.

Workaround

To work around this issue, you can remove or modify the affected alert configuration. For example, in the pool-member granularity example, you can check all of your Analytics profiles for the granularity pool-member option, and either remove the alert or modify it to instead use the granularity virtual-server option.

Impact of workaround: Performing the suggested procedure should not have a negative impact on your system. However, if you modify the alert configuration, you should test it in the appropriate environment to determine if the modified configuration provides the expected results.
