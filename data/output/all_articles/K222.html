K222: Client MSS is not provided to the node when syncookie processing is enabled

Type
Knowledge
Published
2006-02-17
Updated

Status
Legacy Content
Applies to

  • BIG-IP 4.X: 4.6.4
Source
https://my.f5.com/manage/s/article/K222

Topic

There are two known issues that can cause this:
  • If an MSS TCP option is not specified, Microsoft Windows 98 systems will use an MSS of 32 bytes. As per the applicable RFCs, the minimum MSS for any system is 536 bytes. If a 32 byte MSS is used, packets will be so small that most data transfers will never complete. If a larger MSS is used, but it is larger than what the client can accept, the packets will either be dropped or will be fragmented by a router on the customer network.
  • When SYN cookies are used, BIG-IP cannot coordinate the client's MSS for the client with the node.

F5 Product Development tracked this issue as CR26567 and CR41773.

Workaround

You can work around these issues by changing the internal variable so that BIG-IP inserts a custom MSS for SYN cookie node-side connections.

Important: Before setting any internal variable, refer to K920: Overview of internal variables.

To specify an MSS that BIG-IP can advertise to the nodes, perform the following steps:

  1. Log in to the command line.
  2. Set the MSS, by typing the following command, replacing <bytes> with the MSS size that you want to specify:

    Note: The default value is 1460 bytes.

    bigpipe internal set syncookie_inbound_mss = <bytes>
