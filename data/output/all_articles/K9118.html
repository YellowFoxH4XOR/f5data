Topic

The sys-icheck utility is used to find file system changes that have occurred since initial installation and provide information about their status.

Note: The sys-icheck utility is called and used by the sys-reset utility. For more information, refer to K7550: Resetting the BIG-IP system configuration to the factory default settings (9.3.x - 9.4.x).

The sys-icheck utility is only available from the command line, and can be accessed by typing the sys-icheck command.

The sys-icheck utility command options

To view the available options for the sys-icheck utility, type the sys-icheck -h command.

Output will appear similar to the following example:

Usage: sys-icheck [options]
Find filesystem changes since install.
By default, report only errors.
Options:
    -h show help
    -w report WARN issues, as well as ERROR issues
    -i report INFO and WARN issues, as well as ERROR issues

The default behavior of the sys-icheck utility is to only report errors; the additional -w and -i flags allow the utility to display warning or informational issues.

The file verification process

The sys-icheck utility uses the RedHat Package Manager (RPM) to verify specific configuration and non-configuration files against a set of package repositories that were created during the installation and saved in the /usr/share/defaults/fs directory. For each difference detected, the utility prints a line specifying the name and location of the affected file and its status.

The sys-icheck command output

The sys-icheck command provides output in the following format:

<File status: ERROR/WARN/INFO> <Verification> <File type> </path/to/filename> (no backup)

Note: The (no backup) segment is only displayed when the file status is reported as an ERROR and no backup of that file exists in a .rpmbackup located in the /usr/share/defaults/fs directory.

The <File status: ERROR/WARN/INFO> field

If changes are detected and the status flag is set, the system uses the following criteria to determine how the file should be flagged:

If the file is a configuration file

An ERROR message is reported if the following are true:

  • If the verify option fields show missing
  • If there is no .rpmbackup file located in the /usr/share/defaults/fs directory and the verify options show S or 5

    Note: When no backup file exists, the error message will report (no backup) following the path and filename. The utility will also report this as an unrecoverable error, as it cannot be restored using the sys-reset utility.

A WARN message is reported if the following are true:

  • If there is an .rpmbackup file and the verify options are M, D, L, U, or G.
  • If there is not an .rpmbackup file located in the /usr/share/defaults/fs directory and the verify options are not M, D, L, U, or G.

An INFO message is reported If there is an .rpmbackup file located in the /usr/share/defaults/fs directory and the verify options are not M, D, L, U, or G.

If the file is not a configuration file

An ERROR message is reported if the following are true:

  • If the verify option fields show missing
  • If the S or 5 verify options are set, or if the verify options do not show missing, S or 5 (this is a recoverable error that can be fixed with sys-reset)

    Note: This type of error may be reported as an unrecoverable error if no backup exists in the package store. If a backup does exist then it will be reported as a recoverable error.

    Important: Errors reported by sys-icheck do not necessarily indicate an issue with the system due to a file reporting to be in error. It is possible for some files to be updated or modified by a hotfix, or regenerated such as ssh keys, authorization files, or public keys for which sys-icheck will report as an error. This does not mean that the system will fail to function properly and there is no need to run the sys-reset utility to repair the error. If the system is not functioning properly and their are multiple errors reported by the utility, contact technical support for troubleshooting before running the sys-reset utility as this utility will remove all configuration information and reset the system back to factory default.

The <Verification> field

The verification field is composed of the following eight characters, which represent the following attributes that are used by the verification against the original or backup file:

CharacterAttribute
Sfile Size differs
MMode differs (includes permissions and file type)
5digest (formerly MD5 sum) differs
DDevice major/minor number mismatch
LreadLink(2) path mismatch
UUser ownership differs
GGroup ownership differs
TmTime differs
PcaPabilities differ

Note: The T character, in the second to last character in the field, will always be displayed as a period ( . ) since the utility ignores the time difference listed on the file. A period in place of a character indicates that the attribute passed verification.

The <File Type> field

The file type field will either be listed as a c (indicating the file is a configuration file) or blank (indicating it is a not a configuration file).

The </path/to/filename> field

The last field in the sys-icheck output displays the path or directory where the filename is located and the name of file that was checked against the package store.
