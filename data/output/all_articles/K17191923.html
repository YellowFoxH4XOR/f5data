Topic

This article provides a list of security violations that are not learnable by the BIG-IP ASM Traffic Learning feature.

Description

The BIG-IP ASM Traffic Learning feature helps you build and refine a security policy, and it is especially useful if you are doing so manually. BIG-IP ASM does this by presenting you with learning suggestions based on requests and responses the system has analyzed.

The system suggests adding legitimate entities to your policy that often appear in requests or updating the policy due to violations; however, there are certain violations that the system does not learn.

BIG-IP ASM does not generate learning suggestions for the following violations:

Note: Not all of the violations listed here exist in every version of BIG-IP software.

Note: OpenAPI enforcement violations are not learnable because the OpenAPI file is authoritative; therefore, learning suggestions do not modify it's settings (administrators can override the settings in the policy itself if necessary). The violations specific to OpenAPI are noted in the following list.

CSRF Protection

  • CSRF attack detected

Content Profiles

  • GraphQL disallowed pattern in response
  • GraphQL introspection query
  • JSON data does not comply with JSON schema* (When a JSON schema file is attached to the policy, it's considered authoritative and thus not modified by learning.)

General Settings

  • Blocking Condition Detected
  • Failed to convert character (Learnable in BIG-IP 13.x)
  • Violation Rating Need Examination detected
  • Violation Rating Threat detected

Headers

  • Host name mismatch
  • Illegal host name

HTTP protocol compliance failed

  • Bad HTTP version
  • Null in request
  • Unparsable request content

IP addresses and Geolocations

  • Access from malicious IP address
  • Bad Actor Detected
  • IP is blacklisted

Parameters

  • DataSafe Data Integrity
  • Illegal parameter array value*
  • Illegal parameter location*
  • Mandatory parameter is missing*
  • Server-side access to disallowed host

Sessions and Logins

  • Access from disallowed User/Session/IP/Device ID
  • Bad Actor Convicted
  • Brute Force: Maximum login attempts are exceeded
  • Leaked Credentials Detection

URLs

  • Disallowed file upload content detected in body
  • Mandatory request body is missing* (The Learn check box is included in BIG-IP 15.x due to a known issue.)

WebSocket Protocol Compliance

  • Null character found in WebSocket text message
*OpenAPI enforcement violation

Recommendations

View non learnable violations

Violations that are not learnable do not have a Learn check box associated with them on the Learning and Blocking Settings page. To view non learnable violations, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to the Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Select your policy from the list on the left side of the page.
  4. If necessary, select Advanced to display the Policy Building Settings.
  5. Expand Policy Building Settings to view all violations.
  6. Look for violations that do not have a Learn check box associated with them.

View logged violations

To view violations that the BIG-IP ASM logged, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You must apply a log profile must to the virtual server to log requests in the BIG-IP ASM event logs. For more information refer to K85229446: BIG-IP ASM security policy is not logging any requests in the Event Logs.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Event Logs > Application > Requests.

    Stop at this point if you only want to browse the list of requests. Otherwise, continue to the next step.

  3. Select the filter icon. This is a magnifying glass in BIG-IP 13.x and a funnel in BIG-IP 14.x through 17.x.
  4. Select IP / Username / URL (BIG-IP 13.x through 16.x) or select BASIC (BIG-IP 17.x).
  5. For Violation, enter the violation name.
  6. Select Apply Filter (BIG-IP 13.x through 14.x) or Apply (BIG-IP 15.x through 17.x).
