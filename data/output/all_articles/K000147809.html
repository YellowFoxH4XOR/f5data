K000147809: How to use a Trusted Client IP Header value as Source IP on the HTTP Load Balancer?

Applies to

  • F5 Distributed Cloud Web App & API Protection
Source

Description

  • You want to see Client IP as Source IP on the Load Balancer but are using an external CDN provider.
  • One or more additional trusted proxies are in the data path between the client and XC LB.

Environment

  • Content Delivery Networks - CDN
  • F5® Distributed Cloud HTTP Load Balancer
  • CDN is downstream of an XC LB

Cause

By default, the layer 3 source IP address is used as the client IP address. However, if the XC load balancer is behind a CDN or other internet proxy then the layer 3 IP address will be the IP of the CDN/proxy provider, not the original client. To resolve this, CDNs and proxy providers typically embed the original client IP address in an HTTP header.

 

Answer/Recommended Actions

  • A CDN or other proxy typically inserts a HTTP header containing the IP address of the connecting client, traditionally X-Forwarded-For (XFF).  The header name is defined at the CDN and should be customized accordingly.
  • For the purposes of this example we assume the header name is X-F5-True-Client-IP (this is the default header name used by F5 XC CDN).
  • The header name should be configured as the Trusted Client IP Header in the Load Balancer configuration that is located under Other Settings > Trusted Client IP Headers

  • The effect of this configuration is that the RIGHTMOST IP value found in the named header will be considered the true source-ip by the XC LB, for the purposes of:
    • Logging
    • IP-based security controls such as IP ACLs
    • User ID policy and its dependent functions such as rate limiters
    • Heuristic calculations

Additional Information

  • Any HTTP header can be trivially spoofed.  Therefore, XFF (or other named header) cannot always be trusted.
  • The following conditions apply to trustworthiness of XFF (or other named header) values:
    • The header can be trusted only with assurance that it was put there by a trusted proxy
    • Only the rightmost value can be trusted
  • The Trusted Client IP Headers setting should only ever be enabled when there's a trusted proxy such as CDN downstream of XC in the data path.
  • We assume that the customer trusts the downstream CDN or proxy service.  For assurance that the header was put there by the CDN it is strongly recommended to enact IP-based security controls restricting access to the XC LB from only the CDN's documented IP ranges.
