Description

dest-addr-limit-mode defines how destination address affinity persistence manages its persistence records.

By default, dest-addr-limit-mode has a value of timeout. This means each persistence record will timeout after reaching "idle timeout" as defined in the persistence profile.

Default settings:

(/Common)(tmos)# list /ltm persistence global-settings all-properties

ltm persistence global-settings {

  description none

  dest-addr-limit-mode timeout

  dest-addr-max 2048

  proxy-group /Common/aol

}

If you set dest-addr-limit-mode to max-count and dest-addr-max is reached, an error message may appear when a new destination affinity persistence record needs to be created. Refer to documentation.

Example non-default settings:

(/Common)(tmos)# list /ltm persistence global-settings

ltm persistence global-settings {

  dest-addr-limit-mode max-count

  dest-addr-max 2

}

When these settings are used, the BIG-IP system does not enforce timeout value of the destination affinity persistence profile, but it only holds up to the maximum of the specified number of destination affinity persistence records. When the system reaches the maximum, making further requests that requires adding a new destination address persistence record will fail, and the client connection will be reset.

The following error may be logged in /var/log/ltm:

notice tmm[<pid>]: 01010200:5: Reached maximum number of persisted destination addresses. <destination_address> not persisted.

If you take a capture, you can see the RST:

7 13:50:30 <destination_addr> <dest_port> <source_addr> <src_port> 0 0 OUT s1/tmm0 : 80 → 35078 [RST, ACK] Seq=1 Ack=75 Win=0 Len=0 [F5RST: internal error in hudproxy (persist)]

If you use these type of non-default settings, and you encounter the above message, you will need to either increase dest-addr-max or delete some destination address persistence records to make room for a new record.

Environment

  • BIG-IP
  • destination affinity persistence
  • dest-addr-limit-mode set to max-count (non-default value)

Cause

None. This article is Informational.

Recommended Actions

Before using "dest-addr-limit-mode timeout", ensure its behavior suits your use case.

Additional Information

These settings apply to destination affinity persistence only. Other types of persistence (for example: source address affinity, universal etc) are not affected and timeout is enforced as usual.
