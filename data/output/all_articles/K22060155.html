Issue

You should consider using these procedures under the following conditions:

  • The BIG-IP system experiences a significant increase in traffic, called a traffic spike, that is beyond the usual traffic pattern.
  • You want to investigate and possibly determine the source IP addresses contributing to the traffic spike.

Symptoms

As a result of the significant traffic spike, you may encounter the following symptom:

  • The BIG-IP performance graphs page shows spikes in various graphs such as System CPU Usage, Active Connections, and so on, although you observe no interruption to service.

Recommended Actions

If, by observing the various performance graphs, you notice an ongoing traffic spike that is significantly larger than existing traffic, you may want to investigate which virtual server is contributing to the traffic spike and the top contributing source IP addresses before the traffic spike becomes an issue and interrupts your application environment.

If you have network traffic monitoring deployed in your application environment, you may want to start collecting information there. The best way to identify network traffic and its source is by using tools such as netflow analyzers.

There are many open source and commercial netflow analyzers available, and you can use them to collect IP based network traffic by monitoring the ingress and egress of data. These analyzers help check on the source and destination of network traffic, the class of service, and possible reasons of congestion, thus making network traffic management easier.

If you don't have a network traffic monitoring system available in your application environment, you can use the BIG-IP Analytics module to help collect some of this data.

Note: Your BIG-IP system must be provisioned with the BIG-IP Analytics module before the system experiences the traffic spike you want to investigate.

Note: TCP and HTTP Analytics profiles are the only ones available for configuring client IP addresses collection in BIG-IP Analytics. For non-TCP traffic, you should consider using network packet analysis tool such as Wireshark to collect the network capture for analysis.

Procedures

When observing spikes in the various performance graphs, you can use the following troubleshooting steps to determine the possible source IP addresses contributing to the traffic spike:

  • Identify the virtual server that receives most of the traffic spike
  • Configure a TCP Analytics profile for the desired virtual server
  • Identify the source IP addresses from TCP statistics
  • Configure an HTTP Analytics profile for the virtual server
  • Identify the source IP addresses from HTTP statistics

Identify the virtual server that receives most of the traffic spike

At the time of the traffic spike, you can use the bigtop command line utility that displays real-time statistical information for BIG-IP LTM system objects such as virtual servers and nodes to help identify the destination of the F5 IP address. 

You don't need to configure an Analytics profile for your virtual servers prior to performing this procedure; however, your BIG-IP system must be provisioned with the BIG-IP Analytics module before the system experiences the traffic spike you want to investigate.

To identify the virtual server that receives most of the traffic spike, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility
  2. Go to Statistics > Analytics > Virtual Servers > Traffic Details.
  3. Select the Bits tab and observe the Client Side Bits In per Virtual Server graph. The Details table under the graph sorts the virtual servers on the BIG-IP system according to the amount of Client Side Bits In (bit/s), with the virtual server receiving the highest amount of bits at the top of the table by default. Note the top virtual server in this category.
  4. Select the Packets tab and observe the Client Side Packets In per Virtual Server graph. The Details table under the graph sorts the virtual servers according to the number of Client Side Packets In (pkt/s), with the virtual server receiving the highest number of packets at the top of the table by default. Note the top virtual server in this category.
  5. Select the Connections tab and observe the Client Side Connections per Virtual Server graph. The Details table under the graph sorts the virtual servers according to the number of Client Side Connections (conn/s) with the virtual server receiving the highest number of connections at the top of the table by default. Note the top virtual server in this category.
  6. Based on the statistics from the previous steps, you should be able to determine which virtual server is getting most of the traffic spike.

    Note: You may be able to get similar statistics by going to Statistics > Module Statistics > Local Traffic > Virtual Servers; however, the statistics on this page are accumulated values and don't show the detail that the Statistics > Analytics > Virtual Servers > Traffic Details page does.

Back-out procedure

None

Configure a TCP Analytics profile for the virtual server

A TCP Analytics profile directs the BIG-IP system to store TCP statistics about specific entities that you can use in diagnosing network problems.

The BIG-IP Analytics module includes a default TCP Analytics profile called tcp-analytics. You should create a new TCP Analytics profile using the default tcp-analytics profile as a parent.

You must have the BIG-IP Analytics module prior to performing this procedure. To configure a TCP Analytics profile, perform the following procedure:

Impact of procedure: Depending on your application environment, enabling a TCP Analytics profile may increase the load on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Analytics > TCP Analytics.
  3. Select Create.
  4. Enter a name for your TCP Analytics profile.
  5. Under General Configuration, ensure that Statistics Logging Type is set to Internal and Statistics Collection is set to Client side.
  6. For Associated Virtual Servers, select Add and select the virtual servers you have identified from the previous procedure. Then select Done.
  7. For Statistics Gathering Configuration, ensure that the Collected Entities has *Remote Host IP Address selected.

    Note: If you want to list the source IP address Country and/or Continent that contributed to the traffic spike you can select Country and/or Continent.
    Important: Selecting multiple Collected Entities in the Statistics Gathering Configuration section can impact the performance of the BIG-IP system.

  8. Select Finished.

    Note: It may take up to 10 minutes for the charts to reflect the new data.

Back-out procedure

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Analytics > TCP Analytics.
  3. Select the check box for the TCP Analytics profile you created.
  4. Select Delete, and then select OK to confirm the deletion.

Identify the source IP addresses from TCP statistics

Ensure that you have configured a TCP Analytics profile, as described in the previous procedure. One way to identify the remote source IP from the TCP statistics collected is to refer to the Average Goodput Sent (bps) per remote host IP address. Goodput is the total data delivered to the upper layer, aggregated for all connections on all configured entities, measured in bits per second. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Statistics > Analytics > TCP > Goodput.
  3. For View By, select Remote Host IP Addresses.
  4. The list of source IP addresses is sorted by the highest contributor, based on the Avg Connection Goodput Sent (bps). The top source IP address contributor is at the top of the table by default.

Back-out procedure

None

Configure an HTTP Analytics profile for the desired virtual server

If the virtual server you identified in the Identify the virtual server that receives most of the traffic spike procedure processes HTTP traffic, you can also configure an HTTP Analytics profile to collect data about the source IP addresses.

An HTTP Analytics profile directs the BIG-IP system to store HTTP statistics about specific entities that can be used in diagnosing network problems. The BIG-IP Analytics module includes a default HTTP Analytics profile called analytics. You should create a new HTTP Analytics profile using the default analytics profile as a parent. Note that you must have provisioned the BIG-IP Analytics module prior to performing this procedure.

To configure an HTTP Analytics profile, perform the following procedure:

Impact of procedure: Depending on your application environment, enabling an HTTP Analytics profile may increase the load on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Analytics > HTTP Analytics.
  3. Select Create.
  4. Enter a name for your HTTP Analytics profile.
  5. Under General Configuration, ensure that Statistics Logging Type is set to Internal.
  6. For Associated Virtual Servers, select Add and select the virtual servers you have identified from the Identify the virtual server that receives most of the traffic spike procedure. Then select Done.
  7. For Statistics Gathering Configuration, ensure that the Collected Entities has * Client IP Addresses selected.

    Note: The more entities you enable, the greater the impact on system performance.

  8. Select Finished.

    Note: It may take up to 10 minutes for the charts to reflect the new data.

  9. Go to Statistics > Analytics > HTTP > Custom Page.

    Note: For BIG-IP 12.x, go to Statistics > Analytics > HTTP > Overview.

  10. Select Add Widget.
  11. For Page, select Request Throughput.
  12. For View, select Client IP Addresses.
  13. For Date range, select Last Hour.
  14. In the Available measurements list, select Avg Request Throughput (bps) and move it to the Select measurements to display list.
  15. For Data visualization, select Line chart.
  16. Select Done.

Back-out procedure

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Analytics > HTTP Analytics.
  3. Select the check box for the HTTP Analytics profile you created.
  4. Select Delete, and then select OK to confirm the deletion.

Identify the source IP addresses from HTTP statistics

Ensure that you have configured an HTTP Analytics profile described in the previous procedure. To identify the source IP addresses, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Statistics > Analytics > HTTP > Custom Page.

    Note: For BIG-IP 12.x, go to Statistics > Analytics > HTTP > Overview.

  3. Locate the Top Client IP Addresses by Avg Request Throughput (bps) / Avg Request Throughput per Client IP Address widget you created in the previous procedure.
  4. From the graph, you should be able to identify the top client IP addresses; if the Auto Refresh setting is enabled (disabled by default), the system refreshes the chart according to the interval you have selected.

    Note: The time stamp on the report reflects a publishing interval of five minutes; therefore, a time period request of 12:40-13:40 displays data between 12:35-13:35. By default, the BIG-IP system displays one hour of data.

Back-out procedure

None
