Issue

You should consider using this procedure under the following conditions:

  • The BIG-IP system is configured to use the TACACS+ protocol for authenticating BIG-IP administrative users.
  • Administrative user accounts defined on the remote TACACS+ server are unable to log in to the BIG-IP system.

Note: If the remote user accounts are unable to log in to the BIG-IP system, the locally defined user accounts, such as the default administrator account and the root command line account, will be able to log in to the system.

Symptoms

As a result of TACACS+ authentication failures, you may encounter the following symptoms:

  • The login process fails for BIG-IP administrative users.
  • The BIG-IP system logs error messages related to TACACS+ login failures for administrative users.

Recommended Actions

You can change the authentication source for BIG-IP administrative users from using the local database to using an external authentication source, such as TACACS+. Configuring the remote TACACS+ authentication source specifies that the system uses a remote TACACS+ server to authenticate administrative users.

The TACACS+ protocol provides access control for network devices using one or more centralized servers. TACACS+ operates over TCP and provides separate authentication, authorization, and accounting (AAA) services. By separating the AAA services, TACACS+ allows the components to be segregated and handled on separate servers. If you use TACACS+ authentication for BIG-IP administrative users, you should be aware of the following basic TACACS+ settings:

  • Secret: The secret key is a shared secret text string used between the BIG-IP system and the TACACS+ server. The systems use the text string to encrypt passwords and exchange responses.
  • Encryption: Determines whether the system is configured to encrypt the entire body of the authentication packet before sending authentication requests to the remote TACACS+ server.
  • Service Name: The service name that the user is requesting authorization to use.
  • Protocol Name: The protocol associated with the specified service name.

There may be times when you need to troubleshoot TACACS+ authentication, or connections to the remote TACACS+ server.

Procedures

When experiencing TACACS+ authentication issues, you can use the following troubleshooting steps to determine the root cause:

  • Verifying the TACACS+ configuration
  • Verifying TACACS+ server availability
  • Reviewing TACACS+ log messages
  • Enabling debug logging for Remote-TACACS+ authentication
  • Packet tracing TACACS+ traffic

Verifying the TACACS+ configuration

To verify the TACACS+ configuration, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility using the administrator account.
  2. Navigate to System > Users > Authentication.
  3. Verify that the following BIG-IP TACACS+ settings match the TACACS+ servers:
    1. Secret: Verify that the secret key is the same for the BIG-IP and the TACACS+ servers. In addition, verify that the pound sign ( # ) is not used as part of the secret key string.
    2. Encryption: Verify the encryption settings for the BIG-IP and TACACS+ servers. By default, the BIG-IP system is configured to encrypt the TACACS+ authentication packets.
    3. Service Name: Verify the service name setting is correct. The majority of TACACS+ implementations use the ppp service type.
    4. Protocol Name: Verify the protocol setting is correct. The majority of TACACS+ implementations use the ip protocol type.

Verifying the TACACS+ server availability

When experiencing TACACS+ authentication issues, you should first verify that the BIG-IP system can access the TACACS+ servers on the network. Usually the TACACS+ servers reside on the BIG-IP system's management network. However, it is possible that the servers reside on a TMM network. To verify the TACACS+ server availability, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line using the root account.
  2. To determine the IP addresses of the defined TACACS+ servers, type the following command:

    tmsh list /auth tacacs servers

    For example:

    auth tacacs system-auth {
       servers { 172.24.17.1 }
    }

  3. Use a utility, such as Ping or Traceroute, to verify network availability of the remote TACACS+ server.

    For example:

    ping <tacacs_server_ip>

Reviewing TACACS+ log messages

If the TACACS+ servers are available on the network, but fail to authenticate users, you may need to review the BIG-IP log files for relevant TACACS+ messages. To review the TACACS+ log messages, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line using the root account.
  2. Use a Linux text utility to review the /var/log/secure file.

    For example:

    tail -f /var/log/secure

  3. Review the log entries for error messages related to TACACS+ login failures.

When reviewing the log entries for TACACS+ login failures, you may view messages related to the following categories:

  • Bad username or password: When an administrative user attempts to log in using a bad username or password, the system logs a message similar to the following example:

    err httpd[14274]: pam_tacplus: auth failed: Login incorrect

  • Encryption incompatibility: When encryption is required on the TACACS+ server, and the encryption setting is disabled on the BIG-IP system, the system logs error messages similar to the following:

    warning httpd[23170]: _tac_crypt: using no TACACS+ encryption
    err httpd[23170]: tac_authen_pap_read: invalid reply content, incorrect key?
    err httpd[23170]: pam_tacplus: auth failed: Authentication error, please contact administrator

  • Invalid or incorrect secret key: When the BIG-IP system is configured to use an invalid or incorrect secret key, the system logs error messages similar to the following:

    err httpd[24087]: tac_authen_pap_read: invalid reply content, incorrect key?
    err httpd[24087]: pam_tacplus: auth failed: Authentication error, please contact administrator

  • Server refuses TACACS+ connections: When the IP address defined as the TACACS+ server is incorrect, or the server is not accepting connections on port 49, the system logs error messages similar to the following:

    err httpd[21514]: pam_tacplus: connection failed srv 0: Connection refused
    err httpd[21514]: pam_tacplus: no more servers to connect

Enabling debug logging for Remote-TACACS+ authentication

You can enable debug logging for TACACS+ authentication, attempt to log in using remote user accounts, and then review the debug log files. To do so, perform the following procedure:

Impact of procedure:F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor performance.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To enable debug logging, type the following command:

    modify /ltm auth tacacs all debug enabled

  3. Test TACACS+ authentication by attempting to log in using remote user accounts.
  4. After testing TACACS+ authentication, disable debug logging by typing the following command:

    modify /ltm auth tacacs all debug disabled

  5. Review the /var/log/secure file for debug log messages.

Packet tracing TACACS+ traffic

You may need to run tcpdump packet captures to troubleshoot TACACS+ sessions. When reviewing TACACS+ tcpdump output, it is helpful to understand the TACACS+ protocol header.

TACACS+ packets always begin with a 12-byte header. The header is clear text and contains the following fields:

  • major_version: Indicates the major TACACS+ version number.
  • minor_version: Indicates the minor TACACS+ version number.
  • type: Indicates the TACACS+ packet type. Since the AAA services may be handled by different servers, you should be aware of the legal field values:

    TAC_PLUS_AUTHEN := 0x01 (Authentication)
    TAC_PLUS_AUTHOR := 0x02 (Authorization)
    TAC_PLUS_ACCT := 0x03 (Accounting)

  • seq_no: When reviewing TACACS+ sessions, it is helpful to know that clients (such as a BIG-IP) should send packets containing odd-numbered TCP sequence numbers, and TACACS+ daemons should send packets containing even-numbered TCP sequence numbers.
  • flags: The flag field contains various bitmapped flags.

    TAC_PLUS_UNENCRYPTED_FLAG := 0x01: The unencrypted flag bit indicates whether the body of the TACACS+ packet is encrypted. If the flag is set, the packet is not encrypted. If the flag is cleared, the packet is encrypted.

  • session_id: The Id for the TACACS+ session. The session ID should be randomly chosen, and should not change for the duration of the TACACS+ session.
  • length: The total length of the TACACS+ packet body.

To packet trace TACACS+ traffic, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. You can capture TACACS+ traffic by running one of the following tcpdump captures:
    1. If the TACACS+ server is reachable on the management network, use the following syntax:

      tcpdump -s0 -ni eth0 port 49 -vw /shared/tmp/tac.pcap

    2. If the TACACS+ server is reachable on a TMM network, use the following syntax:

      tcpdump -s0 -ni <vlan> port 49 -vw /shared/tmp/tac.pcap

      Note: The -vw switches will write the output to /shared/tmp/tac.pcap and it will also start a packet counter to show if any packets are being written to the file.

  3. You can view the capture file in packet analysis program for further debugging.
