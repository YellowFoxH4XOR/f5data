Known Issue

Error when resetting statistics on global server load balancing (GSLB) pool members.

This issue occurs when the following condition is met:

  • You attempt to reset the statistics for pool members using the Configuration utility by navigating to Statistics > Module Statistics > DNS > GSLB and then clicking Pool Members from the Statistics Type list.

Note: This only occurs with pool member statistics; other types of statistics are unaffected.

Impact

You cannot use the Configuration utility to reset statistics for BIG-IP DNS pool members.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you attempt to reset the GSLB statistics for BIG-IP DNS pool members, the Configuration utility displays an error message similar to the following example: 

    An error has occurred while trying to process your request.

Workaround

To work around this issue, you can reset the GSLB pool member statistics using the Traffic Management Shell (tmsh). To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. List BIG-IP DNS pools and their corresponding members by typing the following command:

    tmsh list gtm pool

    Command output appears similar to the following example:

    # tmsh list gtm pool
    gtm pool a dns_test_pool {
    members {
    member-order 0
    Example:/Common/http-virtual {
    }
    }
    monitor bigip
    }

  3. Use the following command syntax to reset the pool member statistics:

    tmsh reset-stats gtm pool <record type> <pool name> members { <server_object>:<member> }

    Command output appears similar to the following example:

    # tmsh reset-stats gtm pool a dns_test_pool members { Example:/Common/http-virtual }
