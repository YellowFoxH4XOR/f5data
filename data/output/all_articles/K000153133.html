Description

When deployed on GCP (Google Cloud Platform), F5 Distributed Cloud CE instances show L2 connectivity not completed, ARP resolution fails (as seen in packet captures), and IPs on the same subnet are unreachable via ping.

Environment

  • Product: F5 Distributed Cloud
  • Platform: Google Cloud Platform (GCP)

Cause

F5 Distributed Cloud CE deployments on GCP may show apparent ARP resolution failures due to GCP’s abstracted L2 model, but connectivity isn’t the issue. Pings fail because the necessary GCP firewall rule to allow traffic is not in place.

Recommended Actions

 

  1. Firewall Rules:
    • Ensure that GCP VPC firewall rules allow all required traffic (all protocols/ports/IPs as needed) between CE instances across relevant VPCs.
    • Without these permissive rules, both ICMP/ping and intra-cluster traffic will fail.
  2. VM Sizing:
    • For production or high-throughput environments, deploy CEs with at least 8 vCPUs and 32 GB RAM (e.g., n4-standard-8, t2d-standard-8, or a2-highgpu-2g). Avoid using minimal CPU/memory configurations.
  3. Deployment Best Practices:
    • Follow F5 Distributed Cloud documentation for proper interface setup and static IP configuration in GCP environments.
    • Adhere strictly to both F5 and GCP guidelines regarding multi-interface VM deployments.
