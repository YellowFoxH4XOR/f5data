Topic

As part of F5's ongoing security improvements, we will be disabling weak SSL/TLS cipher algorithms across F5 Secure Files (securefiles.f5.com). This change will ensure that all customer connections use industry-standard, secure encryption. The update will be implemented on 13th February 2026.

Description

Encryption algorithms, also known as ciphers, play a crucial role in securing communication over the internet. They protect data from malicious actors and unauthorized access. However, older or weak cipher algorithms can pose serious security risks. These ciphers can be exploited by attackers using advanced tools and techniques, leading to data breaches, compromised systems, or unauthorized data access.

To maintain the highest level of security and comply with modern security standards and best practices, we strongly encourage all customers to disable the use of weak cipher algorithms.

  • List of Disabled Weak Cipher Algorithms
  • Transition to Strong and Recommended Cipher Suites

List of Disabled Weak Cipher Algorithms

  • Key exchange algorithms: The following algorithms are considered outdated and have known vulnerabilities in cryptographic security:
    • diffie-hellman-group1-sha1
    • diffie-hellman-group14-sha1
  • MAC algorithms: Message Authentication Code (MAC) algorithms help verify data integrity during transmission. The following weak and deprecated MAC algorithms will be disabled:
    • All hmac-md5 algorithms
    • All hmac-sha1 algorithms
    • hmac-sha2-256-96 — Weak/deprecated. Truncated MAC
    • hmac-sha2-512-96 — Weak/deprecated. Truncated MAC
  • Ciphers (Encryption Algorithms): The following encryption algorithms are considered weak or deprecated due to known vulnerabilities, outdated standards, or compromised integrity:
    • 3des-cbc
    • All arcfour algorithms
    • cast128-cbc
    • blowfish-cbc
    • aes128-cbc — Weak/deprecated. CBC has known issues in SSH.
    • aes192-cbc — Weak/deprecated
    • aes256-cbc — Weak/deprecated
    • twofish128-cbc — Legacy/weak
    • twofish192-cbc — Legacy/weak
    • twofish256-cbc — Legacy/weak

Transition to Strong and Recommended Cipher Suites

Going forward, only strong and modern cipher suites will be supported. These cipher suites align with industry-recognized security standards and best practices, offering improved encryption and resilience against attacks. The following lists the following supported algorithms:

  • Supported Key Exchange algorithms:
    • curve25519-sha256@libssh.org
    • diffie-hellman-group-exchange-sha256
    • ecdh-sha2-nistp256
    • ecdh-sha2-nistp384
    • ecdh-sha2-nistp521
  • Supported Server Host Key Algorithms:
    • rsa-sha2-256
    • rsa-sha2-512
    • ssh-rsa
    • ecdsa-sha2-nistp384
    • ecdsa-sha2-nistp256
  • Supported Encryption Algorithms:
    • aes128-ctr
    • aes192-ctr
    • aes256-ctr
  • Supported MAC Algorithms:
    • hmac-sha2-256
    • hmac-sha2-512
    • hmac-sha2-256-etm@openssh.com
    • hmac-sha2-512-etm@openssh.com

Additional Information

Potential impact

Once the listed deprecated algorithms are disabled, you may experience the following:

  • SSH/SFTP connection failures
  • Errors such as:
    • no matching key exchange method found
    • no matching cipher found
    • Unable to negotiate with host
  • Automated jobs, scripts, or integrations using older SSH/SFTP clients may stop working
  • Legacy systems or appliances that do not support modern ciphers will be unable to connect

This change does not impact you when you are already using modern SSH/SFTP clients with strong cipher suites.

Troubleshooting

Use the following procedures to troubleshoot issues:

  • How to check your current SSH/SFTP configuration
  • Lists algorithms supported by the client
  • Test connections with strong algorithms explicitly
  • How to update to strong cipher suites

How to check your current SSH/SFTP configuration

To check your SSH client version, enter the following command on your client system:
ssh -V

You may observe the following:
OpenSSH_7.4p1, OpenSSL 1.0.2k-fips

If the version is older than OpenSSH 7.x, it is very likely using weak algorithms by default.

Test connections with strong algorithms explicitly

To test the connections, enter the following:

ssh -vvv user@hostname

Look for lines similar to:
kex: algorithm: curve25519-sha256
cipher: aes256-ctr
MAC: hmac-sha2-256

For example: 
debug1: kex: algorithm: ecdh-sha2-nistp256
debug1: kex: host key algorithm: ecdsa-sha2-nistp256
debug1: kex: server->client cipher: aes128-ctr MAC: hmac-sha1 compression: none
debug1: kex: client->server cipher: aes128-ctr MAC: hmac-sha1 compression: none

If the negotiation fails, the client is incompatible.

How to update to strong cipher suites

Upgrade your SSH/SFTP client (Recommended). Upgrade to a modern OpenSSH version using your OS package manager:

  • Linux (RHEL / CentOS / Rocky / Alma)
    yum update openssh
  • Ubuntu / Debian
    apt update && apt install openssh-client
  • Windows
    • Use Windows OpenSSH (latest)
    • Or tools like WinSCP / PuTTY (latest versions)

To support the strong ciphers outlined while avoiding those flagged as weak, use only client versions later than the following:
•    OpenSSH: 7.6+ 
•    FileZilla: 3.16.0+ 
•    PuTTY: 0.74+
•    WinSCP: Latest version recommended

It's critical that you check the version of your SSH or SFTP clients and update to these minimum recommended versions where necessary. This will ensure compatibility with the server's configuration and avoid connection issues when weak ciphers are disabled.
