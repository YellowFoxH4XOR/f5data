Issue

Error Message

emerg alertd[<PID>]: 01100048:0: Log disk usage still higher than <percent>% after logrotate and <#> times log deletion

In this error message, note the following:

  • <PID> is the process ID for the alertd process.
  • <percent> is a percentage value of the disk usage.
  • <#> is the number of previous log deletion operations attempted.

For example:

emerg alertd[4849]: 01100048:0: Log disk usage still higher than 80% after logrotate and 24 times log deletion

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when all of the following conditions are met:

  • Disk utilization for the /var/log file system surpasses the value configured for the logcheck.warnthres database key (default = 80%).
  • The logrotate utility makes multiple attempts to compress or delete older log files.

Impact

Lack of available disk space on the BIG-IP system may impair logging functionality and other functions that require additional disk space.

Recommended Actions

This message indicates that available disk space is low. When the system generates this message, consider the following:

  • Review the /var/log/ directory and delete any unnecessary, large files and older log files that you no longer need.
  • Ensure that the Monitor Logging feature is not enabled for pool members or nodes. Monitor logging can log excessive amounts of data to the /var/log/monitors directory; you should disable the feature after troubleshooting.
  • Ensure logging levels for the BIG-IP system are not set to debug. The debug log level produces large amounts of data, and you should use it only when you are troubleshooting. Return log levels to their default values once you have completed troubleshooting.
  • Run the following command from CLI:
    logrotate -f /etc/logrotate.conf
