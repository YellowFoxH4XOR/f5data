Known Issue

This is the result of a known issue. Switching from a FastL4 profile to another profile, such as User Datagram Protocol (UDP) or TCP, causes the virtual server to drop fragment packets.

For example, if you switch between a FastL4 and a UDP profile, the BIG-IP system sets the Don't reassemble fragments bit, which causes the virtual server to drop new UDP fragments. Similarly, if you switch between a TCP and a FastL4 profile, the BIG-IP system sets the Don't proxy MSS bit, which causes Path MTU to fail for new TCP connections.

F5 Product Development tracked this issue as CR70936, and CR70966 and it was fixed in BIG-IP LTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
