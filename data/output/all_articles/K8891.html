K8891: The formula used to calculate the TTL for cached content when using the Maximum Age Use HTTP Lifetime Heuristic setting

Topic

The system uses the Maximum Age setting to specify the amount of time that the BIG-IP WebAccelerator or BIG-IP Advanced Acceleration Manager (AAM) system will serve content from the cache before requesting fresh content from the origin web server. When you select the Use HTTP Lifetime Heuristic option for the Maximum Age setting, the BIG-IP system uses the specified heuristic percentage value and the Last_Modified HTTP Response header to compute content expiration TTL (Time-to-Live) values for cached content.

When you select the Use HTTP Lifetime Heuristic option, the more time that has elapsed since the content was last modified, the longer the content will be cached. For example, if you modified content 10 hours ago, the system will cache the content with a 5 hour TTL.  While with content that you modified 10 days ago will be cached with a 5 day TTL.

The system uses the following formula to calculate content expiration for cached content:

((current time - Last_Modified time ) * (Heuristic % value)) + (current time) = content expiration.

Example 1:

Current time: 11 a.m.
Last modified time: 1 a.m.
Heuristic value: 50%
Calculated content expiration = 4 p.m.

((11 - 1) * (50%)) + (11) = 16

((10 hours) * (50%)) = 5 hours   +  (11 a.m.) = 4 p.m.

Example 2:

Current time: Jan 11th
Last modified time: Jan 1st
Heuristic value: 50%
Calculated content expiration = Jan 16th

((11 - 1) * (50%)) + (11) = 15

((10 days) * (50%)) = 5 days   +  (Jan 11th) = Jan 16th

Important: If the server response contains an HTTP Last_Modified header and an HTTP Lifetime header, such as cache-control: max-age, then the HTTP Lifetime header takes precedence, and the system does not use  the HTTP Lifetime Heuristic percentage to calculate content expiration.

Note: Setting the %Heuristic value to 0 (zero) disables the Use HTTP Lifetime Heuristic setting.
