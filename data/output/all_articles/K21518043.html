Known Issue

Network access may fail if the client is unable to resolve DNS hostnames.

This issue occurs when all of the following conditions are met:

  • Your network access profile specifies a URL for a proxy auto-config (PAC) file in the Client Proxy Autoconfig Script setting.
  • The PAC file contains a JavaScript DNS resolution function.

For example, a PAC file may contain code that appears similar to the following example:

function FindProxyForURL(url, host)
{
var ip = dnsResolve(host);
if (isInNet(ip, "10.0.0.0", "255.0.0.0")) {
return "DIRECT";
}
return "PROXY 4.5.6.7:8080";
}

If a client using this PAC file attempts to establish a network access session while local DNS resolution is temporarily unavailable, the TunnelServer client component may exit unexpectedly.

Impact

The TunnerServer client component exits, preventing the client from establishing a Virtual Private Network (VPN) session.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Clients using the PAC file are unable to maintain or reconnect to network access sessions when experiencing local DNS resolution failures.
  • The webtop reports Disconnected and Internal error messages on the client.
  • The BIG-IP Edge Client logs messages at the time of the event that appear similar to the following example:

Workaround

To work around this issue, you can ensure proper DNS functionality at the client or discontinue DNS resolution JavaScript functions in PAC files.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.
