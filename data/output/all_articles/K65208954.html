Description

When the following command is run in CLI to get report for a time period:

# tmsh show analytics http report view-by client-ip measures {max-tps transactions} range 06/23/2021":"00:00--06/23/2021":"23:59

it gives the below error:

"Data Input Error: Measure max-tps is non-cumulative and cannot be used in this context"


Environment

  • Able to get records in earlier version


Cause

This is caused by Bug ID 933777: Context use and syntax changes clarification

The calculation method for 'max-tps' has changed  from cumulative to commutative.


Recommended Actions

Use the following steps to edit the file /etc/avr/monpd/monp_http_measures.cfg  to workaround the issue.
  1. Create a backup of the file /etc/avr/monpd/monp_http_measures.cfg

    #cp /etc/avr/monpd/monp_http_measures.cfg /etc/avr/monpd/monp_http_measures.cfg_original
     
  2. Using any editor open the file /etc/avr/monpd/monp_http_measures.cfg
     
  3. Search for the following two sections

    comulative=false
    merge_formula=SUM(max_tps)

    Change the above two as the following:

    comulative=true              
    merge_formula=MAX(max_tps)
     
  4. Verify the changed text:

    #sdiff -s /etc/avr/monpd/monp_http_measures.cfg /etc/avr/monpd/monp_http_measures.cfg_original
     
    Output should look like:

    comulative=true                              |    comulative=false
    merge_formula=MAX(max_tps)
     
  5. Restart monpd for the changes to take effect.
 #tmsh restart sys service monpd
 

Additional Information

If only the LTM module is provisioned but AVR and ASM modules are licensed, the command:

#tmsh show analytics http report view-by client-ip measures {max-tps transactions} range 06/23/2021":"00:00--06/23/2021":"23:59

will not run and will throw below error: 

Syntax Error: "analytics" unexpected argument

Therefore, AVR and ASM module must be provisioned for the command to work.
