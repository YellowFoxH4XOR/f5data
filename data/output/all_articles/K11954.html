Topic

The Linux kernel defines the maximum buffer size needed to hold a network interface name. In both 2.4 and 2.6 kernel versions, the maximum buffer size is set to 16 bytes (or characters). However, the BIG-IP system allows for much longer Virtual Local Area Network (VLAN) names. This article describes how the system maps long VLAN names to interface names that the kernel understands. It is important to know how the Linux host subsystem refers to long VLAN names when you work with certain command line utilities. For example, if you want to run the tcpdump or ssldump utility so that it listens only on a given interface, then understanding system behavior is important.

Note: To avoid possible issues or confusion, F5 recommends that you choose VLAN names that are as short as possible.

BIG-IP 10.0.x
BIG-IP 9.x

BIG-IP 10.1.0 and later

BIG-IP 10.1.0 and later behave similar to BIG-IP 10.0.x, except with BIG-IP 10.1.0 and later, interface names are truncated after the thirteenth character in the output of the ifconfig utility.

For example, if a BIG-IP system is configured with the internal, internal-dev, and internal-staging VLANs, note the information in the following table:

VLAN nameifconfig outputifconfig interface argumenttcpdump -issldump -i
internalinternalinternalinternalinternal
internal-devinternal-devinternal-devinternal-devinternal-dev
internal-staginginternal-stag~1internal-stag~1internal-staginginternal-staging

BIG-IP 10.0.x

Depending on the length of the VLAN name, the Linux host subsystem refers to VLANs as follows:

  • For VLAN names up to 15 characters long, BIG-IP 10.0.x behaves exactly like BIG-IP 9.x.
  • If a VLAN name is longer than 15 characters, the following is true:

    The ifconfig utility uses the following syntax for the interface name:

    <VLAN name truncated after the thirteenth character><tilde><single digit>

    The interface name is still truncated after the ninth character in the output of the ifconfig utility.

    When you invoke the tcpdump or ssldump utility with the -i option (listen on interface), the interface argument is the full VLAN name.

    For example, if a BIG-IP system is configured with the internal-staging-A and internal-staging-B VLANs, note the information in the following table:
    VLAN nameifconfig outputifconfig interface argumenttcpdump -issldump -i
    internal-staging-Ainternal-internal-stag~1internal-staging-Ainternal-staging-A
    internal-staging-Binternal-internal-stag~2internal-staging-Binternal-staging-B

    Note: For BIG-IP 10.x, you can use the bigpipe vlan command to determine the interface name to pass as an argument to the ifconfig utility. For example, the first line of the following output indicates that the ifconfig utility expects the internal-stag~1 interface name for the internal-staging-A VLAN:

    VLAN internal-staging-A (internal-stag~1) tag 1000 00:01:D7:B0:90:83 MTU 1500
    +-> VLAN MEMBER internal-staging-A/1.2 tagged
    +-> INTERFACE 1.2 00:01:D7:B0:90:85 ENABLED down MTU 1500
    | media auto (none) aggregation: detached
    | flow control tx rx (none)
    | (pkts,bits,errs) in = (0, 0, 0), out = (0, 0, 0)
    | (drop,mcast) in = (0, 0), out = (0, 0) coll = 0

    Note: For BIG-IP 11.x and later, you can use the following command to view a table of the VLAN name and the ifconfig VLAN name:

    guishell -c 'select VNAME,IFNAME from vlan;'

    The output will appear similar to the following example:

    ------------------------------------------------
    | VNAME | IFNAME |
    ------------------------------------------------
    | /Common/HA | HA |
    | /Common/external | external |
    | /Common/internal | internal |
    | /Common/internal-staging-A | internal-stag~1 |
    ------------------------------------------------

BIG-IP 9.x

Depending on the length of the VLAN name, the Linux host subsystem refers to VLANs as follows:

  • If a VLAN name is nine characters or less, then the VLAN name and the interface name are the same. The ifconfig utility displays and accepts the full VLAN name. When you invoke the tcpdump or ssldump utility with the -i option (listen on interface), the interface argument is the full VLAN name.

    For example, if a BIG-IP system is configured with the internal VLAN, note the information in the following table:
    VLAN nameifconfig outputifconfig interface argumenttcpdump -issldump -i
    internalinternalinternalinternalinternal
  • If a VLAN name is 10 to 15 characters, then the interface name is truncated after the ninth character in the ifconfig output. However, the ifconfig utility still accepts the full VLAN name as the interface argument. When you invoke the tcpdump or ssldump utility with the -i option (listen on interface), the interface argument is the full VLAN name.

    For example, if a BIG-IP system is configured with the internal-dev and internal-test VLANs, note the information in the following table:
    VLAN nameifconfig outputifconfig interface argumenttcpdump -issldump -i
    internal-devinternal-internal-devinternal-devinternal-dev
    internal-testinternal-internal-testinternal-testinternal-test
  • If a VLAN name is longer than 15 characters, then the kernel names the corresponding interface vlan<tag>, where <tag> is the tag of the VLAN.

    For example, if a BIG-IP system is configured with the internal-staging VLAN, and the VLAN is assigned the 1002 tag, note the information in the following table:
    VLAN nameifconfig outputifconfig interface argumenttcpdump -issldump -i
    internal-stagingvlan1002vlan1002vlan1002vlan1002

    Note: Even if a VLAN is assigned to untagged interfaces exclusively, it still has a VLAN tag. If you do not explicitly assign a tag to a VLAN, then the BIG-IP system assigns a tag automatically. For more information, refer to the Configuring VLANs and VLAN Groups section of the BIG-IP Network and System Management Guide.

    Note: Because vlan1002 is also a valid VLAN name, it is understandable that using long VLAN names can lead to confusion and unexpected issues.
