Description

SNMPD service stuck in restart phase when snmp configuration is invalid. The following SNMP configuration object is invalid since the IP address specified does not belong to BIG-IP:

tmsh list sys snmp
...
agent-addresses { 172.31.1.1 }
...

Example Error messages

/var/log/daemon.log

 err snmpd[25430]: getaddrinfo("172.31.1.1", NULL, ...): Address family for hostname not supported
 err snmpd[25430]: Error opening specified endpoint "172.31.1.1"
 err snmpd[25430]: Server Exiting with code 1


Environment

  • BIG-IP
  • Invalid SNMP configuration

Cause

Agents are client-side SNMP components which collects SNMP data and sends to the SNMP managers, so these should be agent addresses owned by the BIG-IP.
The system default agent addresses are defined as per below:

agent-addresses { tcp6:161 udp6:161 }

Refer to documentation on configuring SNMP for details on configuration items:

tmsh help sys snmp

agent-addresses
     Indicates that the SNMP agent is to listen on the specified
     address. F5 Networks recommends that you do not change this
     setting without fully understanding the impact of the change.

Recommended Actions

You can revert the configuration back to system default by running the following commands:

tmsh modify sys snmp agent-addresses replace-all-with {tcp6:161 udp6:161 }
tmsh save sys config
tmsh restart sys service snmpd
