Known Issue

The bigd process may repeatedly restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • A very large number of health monitors are configured.
  • The system runs out of file descriptors following a bigd process restart.

The bigd monitor daemon provides system health checks. When thousands of monitors are configured on the system, and the bigd process is restarted, the process can run out of file descriptors. As a result, the bigd process may produce a core file, restart, and repeat.

Impact

The system does not perform a health check, and available pool members may be marked as down.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Available pool members are incorrectly marked as down.
  • The bigd process continually restarts.
  • The bigd process produces a core file in the /shared/core directory.
  • The /var/log/ltm log may contain error messages similar to the following example:

    socket error: Too many open files.

Workaround

To work around this issue, you may be able to reduce the number of configured monitors.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your specific environment.
