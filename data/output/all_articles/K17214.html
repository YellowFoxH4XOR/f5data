Known Issue

Uploading a sdconf.rec file to the BIG-IP APM system may cause the mcpd process on the secondary blade to restart.

This issue occurs when all of the following conditions are met:

  • You provision BIG-IP APM on a chassis system with two or more blades installed.
  • You attempt to upload a sdconf.rec file for a SecurID AAA server.

Impact

The mcpd process on the secondary blade restarts, causing a temporary traffic disruption and failover if configured as part of a high availability (HA) system, and the sdconf.rec file is not synchronized to the secondary blade. As a result, the secondary blade will not have the correct configuration should it become primary in the cluster.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP iHealth lists Heuristic H528964 on the Diagnostics > Identified > Medium screen.
  • You view messages in the /var/log/ltm file that appear similar to the following example:

    slot2/<hostname> err mcpd[<PID>]: 01070712:3: Caught configuration exception (0), failed in syscall link(/config/filestore/files_d/Common_d/securid_server_config_file_d/:Common:<AAA_server_name>::sdconf.rec_100795_6, /config/filestore/.trash_bin_d/.current_d/Common_d/securid_server_config_file_d/:Common:<AAA_server_name>::sdconf.rec_100795_6) errno=(No such file or directory).

    slot2/<hostname> err scriptd[<PID>]: 014f0004:3: Lost connection to mcpd
    slot2/<hostname> notice scriptd[<PID>]: 014f0002:5: exiting
    slot2/<hostname> err csyncd[<PID>]: 013b0004:3: IO error on recv from mcpd - connection lost
  • The mcpd process restarts, which results in a failover if the system is configured for HA.
  • The sdconf.rec file is not synchronized to the secondary blade after uploading.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to reference the new SecurID configuration file, which will propagate the change across blades. To do so, perform the following procedure:

Impact of workaround: The initial SecurID configuration will be replaced with the contents of the new SecurID configuration file.

  1. Use secure shell (SSH) to upload the new SecurID configuration file to the BIG-IP APM system.

    Note: This step requires administrative console access.

    For example:

    scp <securid_file> root@<apm_hostname or IP address>:/<path>
  2. Log in to the tmsh utility by typing the following command:

    tmsh
  3. To reference the new SecurID configuration file, use the following command syntax:

    modify /apm aaa securid <securid profile name> config-files modify { sdconf.rec { local-path /<path>/sdconf.rec } }
  4. Save the configuration change by typing the following command:

    save /sys config
  5. To exit the tmsh utility, type the following command:

    quit
