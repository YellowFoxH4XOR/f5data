Description

Recently upgraded vCMP Guest to v14+, observing an issue with using the management interface eth0 as a Unicast Failover IP for HA link.

Recently implemented workaround for Bug ID 780857, but this does not resolve the issue.

Example output for tmsh show cm failover-status, where 192.168.1.101 is the manegement IP:

--------------------
CM::Failover Status
--------------------
Color    gray
Status   STANDBY
Summary  1/1 standby
Details

Local Failover Address  Remote Device                            Packets  Transitions  Received Last Packet  Status
-------------------------------------------------------------------------------------------------------------------
192.168.1.101:1026      <HA_peer_name>  0        1            -                      Error
10.101.10.22:1026       <HA_peer_name>  152379   3            2021-May-02 09:30:53   Ok
10.101.20.22:1026       <HA_peer_name>  152374   3            2021-May-02 09:30:53   Ok

Warning(s):
Only receiving failover updates from <HA_peer_name> on 2 failover interfaces, out of 3.

Environment

  • vCMP Guest on VIPRION chassis
  • Management interface used for failover unicast

Cause

There is another BUG ID causing this issue:

Bug ID 969105: HA failover connections via the management address do not work on vCMP guests running on VIPRION

Recommended Actions

Apply the workaround suggested for ID 969105 on above link. The status with tmsh show cm failover-status, will be corrected after it:
