Description

How to enforce BIG-IP ASM attack signatures via Rest API call

Environment

  • BIG-IP ASM
  • iControl representation state transfer (REST)
  • Attack signatures

Cause

None

Recommended Actions

  • List of attack signatures "Ready To Be Enforced"
  • List of attack signatures "Not Enforced And Have suggestion"
  • Apply attack signatures "Ready To Be Enforced"

Additional Information

Obtaining the BIG-IP ASM security policy REST ID.
curl -ksu admin:<password> https://<BIG-IP IP>/mgmt/tm/asm/policies?\$select=name,id | jq -M . | egrep '"name":|"id":'
 
Example:
    "name": "abc_policy",
      "id": "zzwGjZQz9ah6JFN244DP9Q"
      "name": "xyz_policy",
      "id": "7xCx7CHC8EgHBVIwR9bccQ"

Note: The characters between the quotes to the right of "id": is the REST ID for that security policy.
Note: Replace <BIG-IP ASM IP> with the IP address of the BIG-IP ASM device, replace <password> with the user password.

======================================
list of "Ready To Be Enforced"
======================================

BIG-IP CLI will work for this, but we recommend a Linux client as well.
curl -ksu admin:admin https://<mgmt IP>/mgmt/tm/asm/policies/<policy REST ID>/signatures/?\$filter=hasSuggestions+eq+false+AND+wasUpdatedWithinEnforcementReadinessPeriod+eq+false | jq .

You can use | less  to view the list.

If you want to view the list in a more compact way:
curl -ksu admin:admin https://<MGMT IP>/mgmt/tm/asm/policies/<policy REST ID>/signatures/?\$expand=signatureReference\&\$select=signature/name,signature/signatureId,hasSuggestions,wasUpdatedWithinEnforcementReadinessPeriod,performStaging\&\$filter=hasSuggestions+eq+false+AND+wasUpdatedWithinEnforcementReadinessPeriod+eq+false | jq -r '.items[] | "ID: \(.signature.signatureId) \(.signature.name) Has Suggestions: \(.hasSuggestions) Updated during Readiness Period: \(.wasUpdatedWithinEnforcementReadinessPeriod) Staging: \(.performStaging)"'

==============================
apply "Ready To Be Enforced"
==============================

This is the same list as the first set of commands with the PATCH command and a JSON payload:
curl -ksu admin:admin --request PATCH -H "Content-Type: application/json" --data '{"performStaging":false}' https://<MGMT IP>/mgmt/tm/asm/policies/<policy REST ID>/signatures/?\$expand=signatureReference\&\$select=signature/name,signature/signatureId,hasSuggestions,wasUpdatedWithinEnforcementReadinessPeriod\&\$filter=hasSuggestions+eq+false+AND+wasUpdatedWithinEnforcementReadinessPeriod+eq+false | jq .
Note: We recommend using "| less" at the end when viewing the command output.


========================
Apply a policy Via REST
========================

curl -ksu admin:admin -H "Content-Type: application/json" --data '{"policyReference": {"link": "https://localhost/mgmt/tm/asm/policies/<policy REST ID>" } }' --request POST https://<MGMT IP>/mgmt/tm/asm/tasks/apply-policy/ | jq .
Note: Replace the link with the REST API policy reference and the IP address with the mgmt of the BIG-IP (or localhost if run from the BIG-IP's CLI).  Change the -u to be <admin user>:<admin password>.

Once that's done, wait a little bit and then give the output from.
curl -k -s -u admin:admin https://<MGMT IP>/mgmt/tm/asm/tasks/apply-policy/ | jq .
