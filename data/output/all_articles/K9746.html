K9746: The BIG-IP GTM marks the BIG-IP redundant pair Available when it can only communicate with one unit

As long as the BIG-IP GTM system can maintain iQuery communications with one unit in a BIG-IP high availability pair, the BIG-IP GTM will set the status of the BIG-IP object to Available. The status of the individual objects hosted by the BIG-IP pair is based on the iQuery status reported to the BIG-IP GTM by the active BIG-IP unit. If the BIG-IP GTM can communicate with the active unit, the status of the objects hosted by the pair will be accurately reflected. If the BIG-IP GTM cannot communicate with the active system, the status of all objects hosted by the pair will be Offline.

A common cause of iQuery communications failure is unsuccessful SSL certificate authentication between the BIG-IP GTM and the BIG-IP objects in its configuration. To avoid false outages due to certificate problems, F5 Networks makes the following recommendations:

  • When adding a BIG-IP high availability pair to a BIG-IP GTM configuration, each BIG-IP GTM system in the synchronization group must exchange SSL certificates with both units of the BIG-IP pair
  • Certificates must be updated on all existing systems before expiring, and redistributed upon update

F5 Product Development is considering a request for enhancement (RFE) to display status of each redundant pair BIG-IP member independently. F5 Product Development is tracking this RFE as ID 273723 and ID 221923.
