Known Issue

You may be unable to query the SNMP agent using SNMPv3 access record credentials after a configuration is loaded or a ConfigSync is performed.

This issue occurs when the following condition is met:

  • The authentication and/or privacy passwords in an SNMPv3 access record are greater than 29 characters.

When a configuration is saved, the BIG-IP system encrypts the authentication and privacy passwords in an SNMPv3 access record. If the passwords exceed 29 characters, the encryption process will corrupt the passwords.

Impact

You are unable to query the SNMP agent using the affected SNMPv3 access record credentials.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After loading a configuration, or performing a ConfigSync, you are unable to access to the BIG-IP system through the affected SNMPv3 access record.
  • When attempting to view the SNMPv3 access records, the BIG-IP Configuration utility displays the following error message:

    General database error retrieving information.

Workaround

To work around this issue, you can use authentication and privacy passwords 29 characters or shorter when creating SNMPv3 access records.

To recover from this issue, you must change the passwords for the affected SNMPv3 access records by performing the following procedure:

Impact of workaround: None

  1. Log in to the BIG-IP command line.
  2. List the configured SNMPv3 access records (users) by typing the following command:

    tmsh list sys snmp users

    The output of the command appears similar to the following example:

    sys snmp {
        users {
            iuser1_1 {
                auth-password-encrypted "ZUaW=>l8M5hH\?bl6M[[NS:a678k6Qai8;^l>g9^.-ec>Cb8"
                auth-protocol md5
                oid-subset .1
                privacy-password-encrypted "a].ULckP`pEP8Ecb@HP>Xmnb^sH>JDdblKM.llY^dRDPV\\o"
                privacy-protocol des
                security-level auth-privacy
                username user1
            }
            iuser2_1 {
                auth-password-encrypted "TMc\\NT^WRIRCH6ZiRq[gG[WIXIrGX30_=[Le:N<[>K[U76c"
                auth-protocol md5
                oid-subset .1
                privacy-password-encrypted "ELXKlkjZRLqthWfQm=C,0Y\\(JVc<I/CfV8:<fLAJ@]L^.CL"
                privacy-protocol des
                security-level auth-privacy
                username user2
            }
        }
    }

  3. Change the password for the affected user using the following command syntax:

    tmsh modify sys snmp users modify { <record_name> {auth-password <password> privacy-password <password>}}

    In the previous command syntax, note the following:
    • <user> is the name assigned to the SNMPv3 access record
    • <password> is a password between 8 and 29 characters
    For example, to change the password for the SNMPv3 access record named iuser1_1, type the following command:

    tmsh modify sys snmp users modify { iuser1_1 {auth-password mysecret privacy-password mysecret}}
  4. Repeat step 3 for all affected SNMPv3 access records.
  5. Save the configuration by typing the following command:

    tmsh save sys config

Note: If this system is part of a redundant pair, you can apply this change to the peer system by performing a ConfigSync.
