Known Issue

Configurations may fail to load when the default network route name is an IP address.

This issue occurs when all of the following conditions are met:

  • The BIG-IP configuration (11.3.0 or earlier) contains a default network route, where the name is an IP address.

    For example, the following command output shows an affected default network route that is named /Common/10.10.10.1:

    tmsh list /net route

    net route /Common/10.10.10.1 {
        gw 10.10.10.1
        network default
    }

  • You have performed one of the following actions:

    • You have upgraded the software to BIG-IP 11.3.0 or later.
    • You have installed a user configuration set (UCS) file (version 11.3.0 or earlier) on an 11.3.0 or later BIG-IP system.

Impact

The software upgrade succeeds, but the configuration fails to load properly. If you manually install the UCS file, the configuration files install successfully, but the configuration fails to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H435090 on the Diagnostics > Identified > High screen.
  • After you successfully upgrade the software, the configuration fails to properly load.
  • When you manually install the UCS file, the configuration files install successfully, but the configuration fails to load, and an error message similar to the following example appears:

    ERROR: UCS installation failed.
    Operation aborted.
    /tmp/configsync.spec: Error installing package
    Config install aborted.
    Unexpected Error: UCS loading process failed.

  • In the Configuration utility, a warning message similar to the following example appears:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

  • An error message similar to the following example logs to the /var/log/ltm log file:

    0107162b:3: Self IP (/Common/10.10.10.1) is missing a netmask
    Unexpected Error: Loading configuration process failed.

Workaround

To avoid this issue, you can rename the affected route object before you perform an upgrade.

To recover from this issue, you can use a text editor to rename the affected route object in the /config/bigip.conf file, and then manually load the configuration. To do so, perform the following procedure:

Note: You cannot rename a network route object using the Traffic Management Shell (tmsh) or Configuration utility. To rename the affected route object, you must use a text editor to manually modify the /config/bigip.conf file.

Impact of workaround: F5 recommends that you perform this procedure only if the configuration fails to load after you perform an upgrade or manually install the configuration UCS file due to this issue. Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system command line prompt.
  2. Back up the /config/bigip.conf file by typing the following command:

    cp -af /config/bigip.conf /var/tmp/bigip.conf.sol14795

  3. Using the text editor of your choice to edit the /config/bigip.conf file, locate the net route stanza of the affected default network route object.
  4. Modify the name of the affected network route object to an alphanumeric naming format.

    For example, the affected network route object may appear similar to the following:

    net route /Common/10.10.10.1 {
         gw 10.10.10.1
         network default
    }

    After modification, the network route object may appear similar to the following:

    net route /Common/ExternalDefault {
         gw 10.10.10.1
         network default
    }

  5. Save the changes and exit the text editor.
  6. Load the configuration by typing the following command:

    tmsh load /sys config
