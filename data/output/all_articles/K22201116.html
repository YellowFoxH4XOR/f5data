Description

Upgrading a Unit after deleting uneeded EPSEC Files can cause the Configuration Load to Fail on the new version.
Configuration does not load successfully after upgrading.
The status of the appliance goes into disconnected state.
Accessing the GUI would requiere default key instead of known users.
The following log will indicate an error during configuration loadup on /var/log/ltm:

Loading schema version: 13.1.4 01070712:3: Failed: name (/Common/epsec-1.0.0-433.0.iso) Cache path (/config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-433.0.iso_70251_1) does not exist and there is no copy in trash-bin to restore from. Unexpected Error: Validating configuration process failed.

Environment

  • Upgrading to target Version.
  • EPSEC Package files.
  • BIG-IP LTM.

Cause

The bigip.conf file may contain the deleted EPSEC packages written into the code.

Recommended Actions

Comment all the epsec lines in the bigip.conf, for an example please follow the Additional information section.

Additional Information

Upon upgrade you may encounter the following issue:

01070712:3: Failed: name (/Common/epsec-1.0.0-433.0.iso) Cache path (/config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-433.0.iso_70251_1) does not exist and there is no copy in trash-bin to restore from.

To resolve this issue, you would first need to backup your bigip.conf file.

cp /config/bigip.conf /config/bigip.conf.K22201116

Locate the EPSEC files that were deleted, for example:

apm epsec epsec-package /Common/epsec-1.0.0-928.0.iso {
    cache-path /config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-928.0.iso_61984_1
    oesis-version 4.3.1453.0
    revision 1
    version 1.0.0-928.0
}

 

And then comment the lines:

#apm epsec epsec-package /Common/epsec-1.0.0-928.0.iso {
#   cache-path /config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-928.0.iso_61984_1
#   oesis-version 4.3.1453.0
#   revision 1
#   version 1.0.0-928.0
#}

 

After commenting the EPSEC lines, save the file

wq!

And re-load the configuration:

tmsh load sys config
