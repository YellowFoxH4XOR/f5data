Description

The BNK/CNF `f5-tmm-routing` container uses ZebOS for dynamic routing like BGP. ZebOS can load configuration from a ConfigMap mounted into the pod. The official documentation states:

"The CNFs Controller detects modifications made to the ConfigMap file, and applies the updates to the running f5-tmm-routing container."

However, this dynamic update capability applies only when using a custom (user-created) ConfigMap referenced via the `configMapName` Helm value. There is an important behavioral distinction between two ConfigMap types:

  • Auto-generated (by Helm) -  `f5-tmm-dynamic-routing-template` -  Changes are NOT dynamically applied — pod restart required
  • Custom (user-created) -  User-defined (e.g., `spk-bgp`, `cnf-bgp`) - Changes ARE dynamically detected and applied by the Controller 

Additionally, ZebOS uses a non-declarative (additive) configuration model. This means:

  • Adding a configuration line: works with dynamic updates.
  • Removing a configuration line: simply deleting it from the ConfigMap will not remove it from the running config. You must explicitly use the `no <command>` form (e.g., `no neighbor <IP>`).

Environment

  • Product:  F5 SPK (Service Proxy for Kubernetes) / BIG-IP Next for Kubernetes (Host) / CNF (Cloud-Native Network Functions)
  • Versions: SPK 1.7.x, BNK/CNF 2.x and later
  • Component: `f5-tmm` pod / `f5-tmm-routing` container / ZebOS BGP daemon

Cause

Editing the Auto-Generated ConfigMap

Editing the auto-generated ConfigMap (`f5-tmm-dynamic-routing-template`) does not trigger dynamic updates. The Controller only monitors custom ConfigMaps referenced via the `configMapName` Helm value. This is Functions As Designed (FAD) per Bug ID 1612521.

ZebOS Non-Declarative Configuration Model

ZebOS does not support declarative (diff-based) configuration. When a ConfigMap change is applied, ZebOS processes the updated file as additive — new lines are added, but deleted lines are not automatically removed from the running config. To remove a configuration element, the `no <command>` equivalent must be explicitly present in the ConfigMap.

Recommended Actions

Use a Custom ConfigMap for Dynamic Updates to enable live configuration updates without a pod restart

1. Create a custom `ZebOS`  ConfigMap - spk-bgp

kubectl apply -f spk-bgp-configmap.yaml

2. Reference the custom ConfigMap in your Helm values file before installing the Controller:  

 tmm:
     dynamicRouting:
       enabled: true
       configMapName: "spk-bgp"

3. Deploy SPK.

 

Removing a Configuration Element (Using "no" Commands)

Because ZebOS is non-declarative, to **remove** an existing configuration element, you must explicitly add a `no <command>` line to the ConfigMap rather than simply deleting the line.

Example — Removing a BGP neighbor:

Instead of deleting the neighbor line, add the `no` equivalent:

no neighbor <OLD_NEIGHBOR_IP>

Edit ConfigMap , add no 

# kubectl edit cm spk-bgp

    router bgp 2202
      !
      bgp router-id %%POD_IP%%
      bgp log-neighbor-changes
      bgp graceful-restart restart-time 120
      bgp max-paths 4
      no bgp default ipv4-unicast
      no network 22.26.22.222/32
      redistribute kernel
      !
      no neighbor 22.22.22.101 remote-as 2201 <======= type no
