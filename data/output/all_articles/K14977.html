Topic

You should consider using this procedure under the following condition:

  • You want to configure high availability (HA) for BIG-IP Link Controller systems.

Description

Configuring HA for BIG-IP Link Controller systems provides features such as synchronization of configuration data and HA failover between multiple BIG-IP Link Controller devices.

This article describes how to configure an active-standby pair of BIG-IP Link Controller systems using the Configuration utility and the TMOS Shell (tmsh).

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP Link Controller systems.
  • You have configured a management IP address, network time protocol (NTP) servers, and licensing and provisioning.

Procedures

Configuring an HA pair of BIG-IP Link Controller systems requires you to perform the following procedures in the sequence shown on the appropriate systems.

Note: This article refers to the primary BIG-IP Link Controller as the "local" system and the secondary BIG-IP Link Controller as the "peer" system.

If you choose, you can perform most of the configuration using the Configuration utility; however, if you are running BIG-IP 12.1.2 or earlier, the procedure for creating or modifying the redundant server object requires using tmsh on the local BIG-IP Link Controller system.

Using the Configuration utility to configure an HA pair of BIG-IP Link Controller systems

Creating VLANs

F5 recommends that you configure the following three Virtual Local Area Networks (VLANs) on both the local and peer BIG-IP Link Controller systems:

  • A VLAN for processing external traffic
  • A VLAN for processing internal traffic
  • A VLAN for processing HA traffic such as failover traffic
  1. Log in to the Configuration utility of the local BIG-IP Link Controller system.
  2. Navigate to Network > VLANs.
  3. Select Create.
  4. Type a name for the VLAN. For example, external.
  5. Define the remaining VLAN settings, as needed.
  6. Select Repeat steps 1 through 5 to configure the remaining VLAN addresses.
  7. Select Finished.
  8. Repeat these steps on the peer BIG-IP Link Controller system.

Creating non-floating self IP addresses

You must define non-floating self IP addresses for each of the three VLANs on the local and peer BIG-IP Link Controller systems.

  1. Log in to the Configuration utility on the local BIG-IP Link Controller system.
  2. Navigate to Network > Self IPs.
  3. Select Create.
  4. Enter the name, IP address, and netmask for the self IP address.
  5. From the VLAN menu, select the appropriate VLAN for the self IP address.
  6. From the Port Lockdown menu, select Allow Default.
  7. From the Traffic Group menu, select traffic-group-local-only (non-floating).
  8. Select Repeat and follow steps 1 through 6 for the remaining self IP addresses.
  9. Select Finished.
  10. Repeat these steps on the peer BIG-IP Link Controller system.

Creating floating self IP addresses

You must define one floating self IP address for each of the three VLANs on the local BIG-IP Link Controller system.

Note: You will synchronize the floating self IP addresses to the peer BIG-IP Link Controller system later.

  1. Log in to the Configuration utility on the local BIG-IP Link Controller system
  2. Navigate to Network > Self IPs.
  3. Select Create.
  4. Type the Name, IP Address, and Netmask for the self IP address.
  5. Select the appropriate VLAN for the self IP address.
  6. For Port Lockdown, select Allow Default.
  7. For Traffic Group, select traffic-group-1 (floating).
  8. Select Repeat steps 2 through 7 for the remaining floating self IP addresses.
  9. Select Finished.

Creating the default gateway pool

The BIG-IP Link Controller system requires a default gateway pool to load balance traffic across different routers. When you configure the default gateway pool, add the IP addresses associated with the routers that the system uses to handle the network's inbound and outbound traffic.

Note: Configure the default gateway pool on the local BIG-IP Link Controller. You will synchronize the pool to the peer BIG-IP Link Controller system later.

  1. Log in to the Configuration utility on the local BIG-IP Link Controller system.
  2. Navigate to Local Traffic > Pools.
  3. Select Create.
  4. Type a name for the pool.
  5. For Health Monitor, in the Available list, select the gateway_icmp monitor and move it to the Active list.
  6. For New Members, add the IP addresses associated with each router and select All Services for the Service Port.
  7. Select Finished.

Setting the default gateway pool as the default route

After you create the default gateway pool, you must set the pool as the default route on the local BIG-IP Link Controller system.

Note: You will synchronize the default route to the peer BIG-IP Link Controller system later.

  1. Log in to the Configuration utility on the local BIG-IP Link Controller system.
  2. Navigate to Network > Routes.
  3. Select Add.
  4. Enter a name for the route.
  5. For Destination, type 0.0.0.0.
  6. For Netmask, type 0.0.0.0.
  7. For Resource, select Use Pool.
  8. For Pool, select the default gateway pool.
  9. Select Finished.

Configuring ConfigSync and failover settings

You must define the IP addresses for ConfigSync and network failover communication between the local and peer BIG-IP Link Controller systems.

  1. Log in to the Configuration utility on the local BIG-IP Link Controller system.
  2. Navigate to Device Management > Devices. 
  3. Select the host name of the local device, indicated with (Self).
  4. Select the ConfigSync tab.

    Note: For BIG-IP 11.5 - 12.x, hover over the Device Connectivity tab and select ConfigSync.

  5. For Local Address, select the self IP address that you assigned to the VLAN that the system uses to process HA traffic.
  6. Select Update.
  7. Select the Failover Network tab.

    Note: For BIG-IP 11.5 - 12.x, hover over the Device Connectivity tab and select Failover Network.

  8. For Failover Unicast, select Add. You can also optionally configure Failover Multicast.
  9. Select the self IP address that you assigned to the VLAN the system uses to process HA traffic. For Port, keep the default 1026 value.
  10. Select Finished.

    Note: F5 recommends that you optionally add the management address as an additional unicast failover address.

  11. Repeat these steps on the peer BIG-IP Link Controller system.

Adding the peer BIG-IP Link Controller system to the trust domain

You must add the peer BIG-IP Link Controller system to the local trust domain to establish a trust relationship. The BIG-IP Link Controller devices can then exchange their device properties and device connectivity information.

Adding the peer device in BIG-IP 13.0.0 and later

  1. Log in to the Configuration utility. 
  2. Navigate to Device Management > Device Trust > Local Domain.
  3. Select the Device Trust Members tab.
  4. Select Add.
  5. For Device Type, select Peer.
  6. Type the management IP address, administrator user name, and administrator password for the peer BIG-IP Link Controller system, and then select Retrieve Device Information.
  7. Verify that the certificate and the peer device name are correct, and then select Device Certificate Matches.
  8. Select Add Device.

Adding the peer device in BIG-IP 12.1.2 and earlier

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Device Trust > Local Domain.
  3. Select the Peer List or Subordinate List tab.
  4. Select Add.
  5. Type the management IP address, administrator user name, and administrator password for the peer BIG-IP Link Controller system, and then select Retrieve Device Information.
  6. Verify that the certificate and the peer device name are correct, and then select Finished.

Creating a device group

After you add the peer BIG-IP Link Controller system to the local trust domain, you must create a device group to share configuration data.

Note: The device group synchronizes to the peer system automatically.

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Device Groups.
  3. Select Create.
  4. Type the name for the device group.
  5. For Group Type, select Sync-Failover.
  6. For Configuration, select Advanced.
  7. For Members, In the Available list, select the BIG-IP Link Controller members that you want to add to the device group and move them to the Includes list.
  8. To configure device failover to occur over the network, select the Network Failover check box.
  9. Confirm the group settings, and then select Finished.

Performing a ConfigSync to the device group

After you configure the device group, you can perform a synchronization to the device group.

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Overview on the local BIG-IP Link Controller system.
  3. Under Device Groups, select the name of the device group you want to synchronize.
  4. Under Devices, select the name of the local BIG-IP Link Controller system indicated with (Self) to perform the synchronization.
  5. To synchronize the configuration, use one of the following methods, as appropriate for your system version:
    • For BIG-IP 13.0.0 and later, for Sync Options, select Push the selected device configuration to the group.
    • For BIG-IP 12.1.2 and earlier, for Sync Options, select Sync Device to Group.
  6. Select Sync.

Creating or modifying the redundant server object (BIG-IP 12.1.2 and earlier)

For Link monitors to function correctly, you must define a server object in the local BIG-IP Link Controller configuration to represent the system and its peer system. To do this, you must create a redundant server object that contains the non-floating self IP addresses from both BIG-IP Link Controller systems.

Important: In BIG-IP 13.0.0 and later, the BIG-IP Link Controller system correctly modifies the server object as long as you have set the default gateway pool as the default route and have created the sync-failover device group.

Note: You must use tmsh to configure and view the redundant server object.

Note: You will synchronize the server object to the peer system later.

  1. Log in to tmsh on the local BIG-IP Link Controller system by typing the following command:

    tmsh

  2. Verify that a server object exists by typing the following command:

    list /gtm server

    If a server object exists, skip to step 4. Otherwise, continue to step 3.

  3. If no server object exists, create one using the following command syntax:

    create /gtm server <redundant_device_group_name> datacenter Default_DC addresses add { <self_ip> { device-name <device_name> } <self_ip> { device-name <peer_device_name>} } virtual-server-discovery enabled product redundant-bigip

    For example, the following command creates a redundant server object named lc1.example.com with appropriate self IP addresses:

    create /gtm server lc1.example.com datacenter Default_DC addresses add { 192.168.20.1 { device-name lc1.example.com } 192.168.20.2 { device-name lc2.example.com} } virtual-server-discovery enabled product redundant-bigip

    After you have created a server object, go to step 5.

  4. To modify the server object to classify it as redundant and to contain the non-floating self IP addresses, use the following command syntax:

    modify /gtm server <server_name> product redundant-bigip addresses add { <self_ip> { device-name <device_name> } <self_ip> { device-name <peer_device_name>} }

    For example, the following command modifies a server object named lc1.example.com with the redundant-bigip product type and the appropriate self IP addresses:

    modify /gtm server lc1.example.com product redundant-bigip addresses add { 192.168.20.1 { device-name lc1.example.com } 192.168.20.2 { device-name lc2.example.com} }

  5. Save the configuration by typing the following command:

    save /sys config gtm-only

Enabling Synchronization and Synchronize DNS Zone Files options

When you enable the Synchronization and Synchronize DNS Zone Files options, the local BIG-IP Link Controller system periodically queries other systems in the synchronization group to obtain and distribute the BIG-IP Link Controller configuration objects and metrics collection updates.

Note: You will synchronize the server object to the peer system later.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Link Controller.
  3. Select the Synchronize and Synchronize DNS Zone Files check boxes.
  4. Select Update.

Running gtm_add on the peer BIG-IP Link Controller system

You use the gtm_add script to copy the configuration from the local BIG-IP Link Controller system to the peer system.

Important: Do not perform the following procedure on the local BIG-IP Link Controller system. You must perform this procedure on the peer BIG-IP Link Controller system.

  1. Log in to the Advanced Shell (bash) of the peer BIG-IP Link Controller system.
  2. To update the local BIG-IP Link Controller configuration, use the following command syntax:

    gtm_add <master self_IP>

    For example, the following command copies the configuration from a local BIG-IP Link Controller system with IP address 192.168.10.1 to the peer BIG-IP Link Controller:

    gtm_add 192.168.10.1

Configuring HA using tmsh

You can perform the BIG-IP Link Controller HA configuration using only tmsh. Prior to beginning the procedure, it may be helpful to have Secure Shell (SSH) access to each of the BIG-IP Link Controller systems you intend to use in your HA configuration.

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Creating VLANs

F5 recommends that you configure the following three Virtual Local Area Networks (VLANs) on both the local and peer BIG-IP Link Controller systems:

  • A VLAN for processing external traffic
  • A VLAN for processing internal traffic
  • A VLAN for processing HA traffic such as failover traffic
  1. Log in to tmsh on the local BIG-IP Link Controller system by typing the following command:

    tmsh

  2. Use the following command syntax to create the three VLANs:

    create /net vlan <name> interfaces add { <interface> }

    For example, the following commands create VLANs named External, Internal, and HA:

    create /net vlan External interfaces add { 1.1 }
    create /net vlan Internal interfaces add { 1.2 }
    create /net vlan HA interfaces add { 1.3 }

  3. Save the configuration by typing the following command:

    save /sys config

  4. Repeat these steps on the peer BIG-IP Link Controller system.

Creating non-floating self IP addresses

You must define a non-floating self IP address for each of the three VLANs on each BIG-IP Link Controller system.

  1. Using tmsh, create the non-floating self IP addresses on the local BIG-IP Link Controller system using the following command syntax:

    create /net self <self_ip> address <mask> allow-service default vlan <vlan>

    For example, the following commands create static self IP addresses on VLANs External, Internal, and HA:

    create /net self 10.1.216.20 address 10.1.216.20/24 allow-service default vlan External
    create /net self 10.2.216.20 address 10.2.216.20/24 allow-service default vlan Internal
    create /net self 10.3.216.20 address 10.3.216.20/24 allow-service default vlan HA

  2. Save the configuration by typing the following command:

    save /sys config

  3. Repeat these steps on the peer BIG-IP Link Controller system.

Creating floating self IP addresses

You must define one floating self IP address for each of the three VLANs on the local BIG-IP Link Controller system.

Note: You will synchronize the floating self IP addresses to the peer BIG-IP Controller system later.

  1. Using tmsh, create the floating self IP addresses using the following command syntax:

    create /net self <self_ip> address <mask> allow-service default vlan <vlan> traffic-group <floating_traffic_group>

    For example, the following command creates floating self IP addresses using traffic-group-1 on VLANs External, Internal, and HA:

    create /net self 10.1.216.21 address 10.1.216.21/24 allow-service default vlan External traffic-group traffic-group-1
    create /net self 10.2.216.21 address 10.2.216.21/24 allow-service default vlan Internal traffic-group traffic-group-1
    create /net self 10.3.216.21 address 10.3.216.21/24 allow-service default vlan HA traffic-group traffic-group-1

  2. Save the configuration by typing the following command:

    save /sys config

Creating the default gateway pool

The BIG-IP Link Controller system requires a default gateway pool to load balance traffic across different routers. When you configure the default gateway pool, add the IP addresses associated with the routers that the system uses to handle the network's inbound and outbound traffic.

Note: Configure the default gateway pool on the local BIG-IP Link Controller system. You will synchronize the pool to the peer BIG-IP Link Controller system later.

  1. Using tmsh, create the default gateway pool using the following command syntax:

    create /ltm pool <pool_name> members add { <router_ip>:any <router_ip>:any } monitor gateway_icmp

    For example, the following command creates a default gateway pool called default_gw_pool with router IP addresses of 10.1.216.29 and 10.2.216.29:

    create ltm pool default_gw_pool members add { 10.1.216.29:any 10.2.216.29:any } monitor gateway_icmp

  2. Save the configuration by typing the following command:

    save /sys config

Setting the default gateway pool as the default route

After you create the default gateway pool, you must set the pool as the default route on the local BIG-IP Link Controller system.

Note: You will synchronize the default route to the peer BIG-IP Controller system later.

  1. Using tmsh, set the default gateway pool as the default route using the following command syntax:

    create /net route <route_name> network 0.0.0.0/0.0.0.0 pool <pool>

    For example, the following command creates a route named lc_default_gateway with a default gateway pool named default_gw_pool:

    create net route lc_default_gateway network 0.0.0.0/0.0.0.0 pool default_gw_pool

  2. Save the configuration by typing the following command:

    save /sys config

Configuring the ConfigSync and failover settings

You must define IP addresses for ConfigSync and network failover communication between the local and peer BIG-IP Link Controller systems.

  1. Using tmsh, configure the ConfigSync and failover settings using the following command syntax:

    modify /cm device <device_name> configsync-ip <self_ip>
    modify /cm device <device_name> unicast-address {{ effective-ip <self_ip> ip <self_ip> } { effective-ip <self_ip> ip <self_ip> }}

    For example, the following commands configure the synchronization and failover settings on a BIG-IP Link Controller system named LC1.example.com:

    modify cm device lc1.example.com configsync-ip 10.3.216.20
    modify cm device lc1.example.com unicast-address {{ effective-ip 10.3.216.20 ip 10.3.216.20 } { effective-ip 172.24.64.39 ip 172.24.64.39 }}

  2. Save the configuration by typing the following command:

    save /sys config

  3. Repeat these steps on the peer BIG-IP Link Controller system.

Adding the peer Link Controller system to the trust domain

You must add the peer BIG-IP Link Controller system to the local trust domain to establish a trust relationship. The BIG-IP Link Controller devices can then exchange their device properties and device connectivity information.

  1. Using tmsh, add the peer BIG-IP Link Controller device to the local trust domain using the following command syntax:

    modify /cm trust-domain /Common/Root ca-devices add { <mgmt_ip_address> } name <device name> username <admin_username> password <admin_password>

    For example, the following command adds a peer device called LC2.example.com with the management IP address of 172.24.64.40, and the administrator user name admin and password admin to the local system's trust domain:

    modify /cm trust-domain /Common/Root ca-devices add { 172.24.64.40} name lc2.example.com username admin password admin

  2. Verify that all devices have other devices in the trust domain by typing the following command:

    show /cm device-group device_trust_group

  3. Save the configuration by typing the following command:

    save /sys config

Creating a device group

After you add the peer BIG-IP Link Controller system to the local trust domain, you must create a device group to share configuration data.

Note: You will synchronize the device group to the peer BIG-IP Link Controller system later.

  1. Using tmsh, create a device group and add the peer device to the device group using the following command syntax:

    create /cm device-group <device_group_name> devices add { <local_device_name> <remote_device_name> } type <device_group_type>

    For example, the following command creates a sync-failover device group named lc_device_group, which contains the local device lc1.example.com and remote device lc2.example.com:

    create cm device-group lc_device_group devices add { lc1.example.com lc2.example.com } type sync-failover network-failover enabled

  2. Save the configuration by typing the following command:

    save /sys config

Performing a ConfigSync to the device group

After you have configured the device group, you can perform a synchronization to the device group.

  1. Using tmsh , run the ConfigSync process using the following command syntax:

    run /cm config-sync <sync_direction> <sync_group>

    For example, the following command pushes the local device's configuration to peer systems in the lc_device_group device group:

    run /cm config-sync to-group lc_device_group

  2. After you perform a ConfigSync, you can check the synchronization status by typing the following command:

    show /cm sync-status

    Output appears similar to the following:

    -------------------------
    CM::Sync Status
    -------------------------
    Color green
    Status In Sync

Note: If you experience problems synchronizing the configuration between the BIG-IP Link Controller systems, refer to K13946: Troubleshooting ConfigSync and device service clustering issues (11.x - 13.x).

Creating or modifying the redundant server object

For Link monitors to function correctly, you must define a server object in the local BIG-IP Link Controller configuration to represent the system and its peer system. To do this, you must create a redundant server object that contains the non-floating self IP addresses from both BIG-IP Link Controller systems.

Important: In BIG-IP 13.0.0 and later, the BIG-IP Link Controller system correctly modifies the server object as long as you have set the default gateway pool as the default route and have created the sync-failover device group.

Note: You must use tmsh to configure and view the redundant server object.

Note: You will synchronize the server object to the peer system later.

  1. Using tmsh on the local BIG-IP Link Controller system, verify that a server object exists by typing the following command:

    list /gtm server

    If a server object exists, skip to step 4. Otherwise, continue to step 3.

  2. If no server object exists, create one using the following command syntax:

    create /gtm server <redundant_device_group_name> datacenter Default_DC addresses add { <self_ip> { device-name /<partition_name>/<device_name> } <self_ip> { device-name /<partition_name>/<peer_device_name>} } virtual-server-discovery enabled product redundant-bigip

    For example, the following command creates a redundant server object named lc1.example.com with appropriate self IP addresses:

    create /gtm server lc1.example.com datacenter Default_DC addresses add { 10.1.216.21 { device-name /Common/lc1.example.com } 10.2.216.21 { device-name /Common/lc2.example.com} } virtual-server-discovery enabled product redundant-bigip

    After you create the sever object, save the configuration with the following command:

    save /sys config gtm-only
     

  3. To modify the server object to classify it as redundant and to contain the non-floating self IP addresses, use the following command syntax:

    modify /gtm server <server_name> product redundant-bigip addresses add { <self_ip> { device-name /<partition_name>/<device_name> } <self_ip> { device-name /<partition_name>/<peer_device_name>} }

    For example, the following command modifies a server object named lc1.example.com with the redundant-bigip product type and the appropriate self IP addresses:

    modify /gtm server lc1.example.com product redundant-bigip addresses add { 10.1.216.21 { device-name /Common/lc1.example.com } 10.2.216.21 { device-name /Common/lc2.example.com} }

  4. Save the configuration by typing the following command:

    save /sys config gtm-only

Enabling the Synchronization and Synchronize DNS Zone Files options

When you enable the Synchronization and Synchronize DNS Zone Files options, the BIG-IP Link Controller system periodically queries other systems in the synchronization group to obtain and distribute the BIG-IP Link Controller configuration objects and metrics collection updates.

Note: You will synchronize the server object to the peer system later.

  1. Using tmsh, enable the Synchronization and Synchronize DNS Zone Files options by typing the following command:

    modify /gtm global-settings general synchronization yes synchronize-zone-files yes

  2. Save the configuration by typing the following command:

    save /sys config

Running gtm_add on the Link Controller system

You use the gtm_add script to copy the configuration from the local BIG-IP Link Controller system to the peer system.

Important: Do not perform this procedure on the local BIG-IP Link Controller system. You must perform this procedure on the peer BIG-IP Link Controller system.

  1. Log in to tmsh of the peer BIG-IP Link Controller system.
  2. To update the local BIG-IP Link Controller configuration, use the following command syntax:

    gtm_add <master self_IP>

    For example, the following command copies the configuration from a local BIG-IP Link Controller system with IP address 192.168.10.1 to the peer BIG-IP Link Controller:

    gtm_add 192.168.10.1
