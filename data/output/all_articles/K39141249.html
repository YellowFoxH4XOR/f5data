Description

If you would like to limit TACACS+ remote user or a group to specific partitions, you can configure the remote role group in TACACS+ configuration and on BIG-IP.
Note: BIG-IP TACACS+ CLI configuration applies to BIG-IQ.

Environment

  • TACACS+
  • AAA Protocol
  • TCP or UDP

Cause

None

Recommended Actions

For instance, to configure user group, Administrator (adm) to access all partitions, and Operator (ops) to access the partition ' partition1 ', follow the below procedure to configure. 

  • Assign the appropriate user role value to the group
  • Configure BIG-IP to access the remote role configuration
  • Enable authentication source in BIG-IP

Assign the appropriate user role value to the group

The configuration looks similar to:

group = adm {
    service = ppp {
      protocol = ip {
        set F5-LTM-User-Info-1 = adm
        set F5-LTM-User-Console = 1
        set F5-LTM-User-Role = 0
        set F5-LTM-User-Partition = all
      }
    }
  }
  group = ops {
    service = ppp {
      protocol = ip {
        set F5-LTM-User-Info-1 = ops
        set F5-LTM-User-Console = 1
        set F5-LTM-User-Role = 400
        set F5-LTM-User-Partition = partition1
      }
    }
  }
Note: The above configuration should be updated in TACACS+ configuration file tac_plus.

Configure BIG-IP to access the remote role configuration:

After the TACACS+ configuration is complete, BIG-IP needs to be configured to access the service. 

To update the configuration from tmsh follow the below steps. 

  1. Update the configuration.

    tmsh modify auth remote-role description <description of name> role-info add { <role name> { attribute <attribute_name> role <user role> line-order <line order value > console <0/1> user-partition <partition name >  } }

    Example:
    tmsh modify auth remote-role description admingroup role-info add { adm { attribute F5-LTM-User-Info-1 role administrator line-order 1 console tmsh user-partition All } }

  2. List the current properties

    tmsh list auth remote-role all-properties

  3. Save configuration

    tmsh save sys config    

    This configuration should look similar to:

auth remote-role {
  role-info {
    adm {
      attribute F5-LTM-User-Info-1=adm
      console %F5-LTM-User-Console
      line-order 1
      role %F5-LTM-User-Role
      user-partition %F5-LTM-User-Partition
    }
    ops {
      attribute F5-LTM-User-Info-1=ops
      console %F5-LTM-User-Console
      line-order 4
      role %F5-LTM-User-Role
      user-partition %F5-LTM-User-Partition
    }

For additional information refer K8811 to configure TACACS+ authentication for BIG-IP administrative users using the configuration utility.

Note: Since each remote role behavior is configured in tac_plus by using ‘ % ’, these configurations need not redefine in BIG-IP. If you prefer to do so, you may refer to the below example.

    adm {
      attribute F5-LTM-User-Info-1=adm
      console enabled
      line-order 1
      role administrator
      user-partition All
    }

Enable authentication source in BIG-IP

In the final step, enable the authentication source on BIG-IP to TACACS+ server.

To update the configuration from tmsh follow the below steps.

  1. Update the configuration:

    tmsh modify auth tacacs all debug enabled protocol ip secret <TACACS+ shared key>  servers add { server ip } service ppp

    Example:

    tmsh modify auth tacacs all debug enabled protocol ip secret Secret123  servers add { 192.168.6.10 } service ppp 

  1. Set the authentication source type to Tacacs:

     tmsh modify auth source type tacacs

 

  1. List the current properties:
    tmsh list auth tacacs all-properties

  2. Save configuration:

    tmsh save sys config


This configuration should look similar to:

auth source {
  type tacacs
}
auth tacacs system-auth {
  debug enabled
  protocol ip
  secret $M$2w$jT3pHxY6dqGF1tHKgl4mWw==
  servers { 192.168.6.10 }
  service ppp
}
