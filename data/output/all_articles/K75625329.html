Description

BIG-IP appears to be sending packets to a remote host and the source IP may be a known hosts.

  • BIG-IP forwards a known IP address (source IP) to destination (downstream).
  • In some situation, when the known host and BIG-IP are connected to the same downstream network switch, network switch may detect different MAC address from different ports for the same IP address.


Environment

  • BIG-IP LTM
  • IP forwarding wildcard virtual server


Cause

BIG-IP may unexpectedly accepts and forwards packets to destination host.

You have an IP forwarding wildcard virtual server.

ltm virtual /Common/vs_wildcard_forwarding {
    destination /Common/0.0.0.0:0
    ip-forward
    mask any
    profiles {
        /Common/my_route_friendly_fastl4 { }
    }
    source 0.0.0.0/0
   source-port preserve-strict
    translate-address disabled
    translate-port disabled
}


Refer below as an example, BIG-IP unexpectedly forwards ICMP echo request to destination IP address 172.16.10.1.

Packet captured using tcpdump command.

tcpdump -s0 -ni 0.0:nnnp -v -w /var/tmp/capture.pcap host 172.16.10.1


In packet #2, BIG-IP accepts packet from source IP 10.10.10.1

2    08:40:19.359    4.169    10.10.10.1    172.16.10.10    ICMP    218                        IN  s1/tmm11: Echo (ping) request  id=0x0003, seq=6470/17945, ttl=126 (no response found!)


In packet #3, BIG-IP forwards packet to destination IP 172.16.10.1

3    08:40:19.359    0.000    10.10.10.1   172.16.10.10    ICMP    218                        OUT s1/tmm11: Echo (ping) request  id=0x0003, seq=6470/17945, ttl=125 (reply in 4)


Select one of the packet captured, check the Low Details under F5 Ethernet Trailer Protocol, you may find the Virtual Server name that accepts the traffic.

Recommended Actions

This is an expected behavior of a IP forwarding wildcard virtual server. This configuration accepts traffic and forwards it using the information contained in the system routing table.
