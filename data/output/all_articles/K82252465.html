Source

Description
The ASM bd daemon is constantly restarting and possibly creating bd cores after cleaning up disk space in /var 

Examaple log messages:
/var/log/ltm
diskmonitor[5086]: 011d0004:3: Disk partition /var has only 0% free

/var/log/messages
notice logger[XXXX]: Started writing core file: /var/core/bd_io_plug_0.bld0.46.11.core.gz for PID <PID>
notice logger[XXXX]: Finished writing 110753236 bytes for core file: /var/core/bd_io_plug_0.bld0.46.11.core.gz for PID <PID>

The bd process implements the BIG-IP ASM security policy on the HTTP requests it receives from TMM.    The device is marked offline, and no traffic passes. Failover event is triggered for HA redundant systems.    

bd log file: /var/log/ts/bd.log

Environment

  • ASM provisioned
  • BD restarting and coring
  • /var was full and recently cleaned up

Cause
Bug ID 712336: bd daemon restart loop

Recommended Actions

A) Make a spurious change in a policy and apply it.
OR
B) Restart ASM

Bash shell:
# bigstart restart asm

TMSH shell:
(tmos)# restart sys service asm

Additional Information

Fixed In: 15.0.0, 14.1.4.4, 12.1.5.3
