Topic

The BIG-IP 3-DNS system can delegate the responsibility of performing Extended Content Verification (ECV) monitoring to any active F5 system running the big3d agent.

However, the format of the HTTP or HTTPS requests generated by ECV varies depending on the version of BIG-IP software.

BIG-IP 9.2.2 through 9.4.8

When a 3-DNS system delegates an HTTP or HTTPS ECV monitor to a BIG-IP system running version 9.2.2 or later, and invokes the big3dshim process to perform the ECV monitor, the format of the HTTP requests are pre-1.0 HTTP, which appears similar to the following example:

GET /

BIG-IP 9.0.0 through 9.2.1

BIG-IP versions 9.0.0 through 9.2.1 do not perform the ECV monitor properly. The ECV marks the server up, without performing any actual verification.

Note: For more information, refer to K9021: The big3dshim process fails to send ECV monitors.

F5 recommends that you configure the 3-DNS system to avoid delegating ECV monitors to any BIG-IP versions 9.0.0 through 9.2.1 systems by performing the procedure in the following workaround.

BIG-IP 4.x

When a 3-DNS or BIG-IP version 4.x system performs an HTTP or HTTPS ECV monitor, the HTTP requests are formatted as a fully formed HTTP 1.0 request, which appears similar to the following example:

GET / HTTP/1.0
User-Agent: F5 service probe
Host: sol8931.ask.f5.com
Accept: */*
Accept-Language: en
Accept-Charset: iso-8859-1,*,utf-8

Workaround

In most cases, an HTTP server will answer either format of request; therefore, the monitor will succeed properly regardless of the version of the BIG-IP system performing it. However, if an HTTP server requires a fully formed HTTP 1.0 request, then the monitor will succeed only when it is performed by BIG-IP version 4.x systems. Conversely, if an HTTP server does not support HTTP 1.0 requests, then the monitor will succeed only when it is performed by BIG-IP version 9.x systems. If possible, reconfigure the web server to support both types of requests.

If you cannot reconfigure the web server to support both types of requests, you can configure the 3-DNS system to avoid delegating ECV monitors to certain BIG-IP version 4.x or version 9.x systems. For BIG-IP systems that do not perform ECV monitors, set the number of ECV Factories to 0 (zero) on the 3-DNS system by performing the following procedure:

  1. From the navigation pane of the 3-DNS Configuration utility, click Servers.
  2. Click BIG-IP.
  3. Click the name of the BIG-IP system in question.
  4. In the Factories section, clear the ECV check box.
  5. Click Update.

Important: If certain BIG-IP systems in the 3-DNS configuration are unable to reach other servers that are monitored, this workaround may uncover that issue and cause ECVs to fail. Contact F5 Technical Support for assistance diagnosing any unexpected side effects of implementing this workaround.
