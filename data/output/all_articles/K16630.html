Known Issue

Deleting an AAA object may cause synchronization to fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM configuration includes an AAA Active Directory (AD) profile that references a pool.
  • You use the Traffic Management Shell (tmsh) to delete a server object from that pool.
  • You attempt to synchronize the modified configuration to a device group using the Full Sync method.

Impact

Synchronizations fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to synchronize the local BIG-IP APM configuration to the device group, the system displays an error message similar to the following example:

    Sync error on <device group member>: Load failed from <local device> 01070712:3: Caught configuration exception (O), Values (<aaa pool name>) specified for AAA active directory domain controller (reference_<aaa pool name> <deleted aaa object name): foreign key index (<deleted aaa object>_FK) do not point at an item that exists in the database..
    Recommended action: Review the error message and determine corrective action on the device
  • When you attempt to synchronize the local BIG-IP APM configuration to the device group, the system logs an error message similar to the following example to the /var/log/apm file:

    err mcpd[8047]: 01070712:3: Caught configuration exception (0), Values (/<partition>/<aaa profile>) specified for AAA active directory domain controller (/<partition>/<aaa profile> <hostname>): foreign key index (<aaa ad server>_FK) do not point at an item that exists in the database.

Workaround

To recover from this issue, you can restart the mcpd process. For more information about restarting the mcpd process, refer to K13030: Forcing the mcpd process to reload the BIG-IP configuration.

To work around this issue, you can use the Configuration utility or guishell command to remove AAA server objects. To do so, perform one of the following procedures:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Using the Configuration utility to delete an AAA AD server object

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > AAA Servers > Active Directory.
  3. Click the name of the Active Directory Servers profile
  4. In the Domain Controllers list, select the AAA server.

    Note: At least one server address should remain in the Domain Controllers list.

  5. Click Delete.
  6. Click Update.

Using the guishell command to delete an AAA AD server object

  1. Delete the AAA AD server object by using the following guishell command syntax:

    guishell -c "delete from aaa_active_directory_domain_controller where aaa_active_directory_server_name='/<partition>/<ad aaa profile name>' and fqdn='ad server name'

    Note: At least one server address should remain in the Domain Controllers list.

  2. To view the AD AAA profile configuration, use the following command syntax:

    guishell -c "select * from aaa_active_directory_domain_controller where aaa_active_directory_server_name='/<partition>/<ad aaa profile name>'"
