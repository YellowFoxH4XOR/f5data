Issue

Description

Configuration fails to load after an upgrade to 13.0.0 or later.

The following log message will be found in /var/log/ltm:

"/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- Loading schema version: 12.1.5 Loading schema version: 13.1.3.2 01071008:3: Provisioning failed with error 1 - 'Memory limit exceeded. 8018 MB are required to provision these modules, but only 7974 MB are available.' . Unexpected Error: Loading configuration process failed

Environment

2000s/2200s/vCMP/Virtual Edition with 8GB of memory, Upgrade to 13.0.0 or later fails due to memory limit exceeded

AFM provisioned

This issue occurs when LTM + AFM + ASM module combination is provisioned together. Before 13.0.0 this combination is allowed. Since the 13.0.0 AFM module requires 1058MB as opposed to 756MB in pre-13 releases.

 

Recommended Actions

If the upgrade has not yet been performed, or a rollback has been done, disable one of the two extra modules before the upgrade.

Refer to the following article for information about how to unprovision BIG-IP modules.

K12111: Provisioning licensed BIG-IP modules
If the upgrade has already been done, and a rollback is not possible, manually edit the configuration file to change the provisioning level, then reload the configuration.

Create a backup of the bigip_base.conf configuration file:
cp bigip_base.conf bigip_base.conf.backup

Open bigip_base.conf with a text editor
vi bigip_base.conf

Navigate to the 'sys provision' section
Change 'level <level>' to 'level none' to disable unwanted modules
Save the file
Reload the configuration:
tmsh load sys config

Verify that the configuration has loaded successfully:
tmsh show sys mcp-state
