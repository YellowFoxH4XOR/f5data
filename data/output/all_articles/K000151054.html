K000151054: BIG-IP device starts flapping between offline and standby status after deleting a user account

Type
Support Solution

Applies to

Description

On BIG-IP HA systems, deleting a user account via TMSH or the GUI may cause the MCPD process to crash and generate a core dump. This results in all processes continuously restarting, HA status flapping between offline and standby on the peer BIG-IP, and the standby device potentially going offline. A core file such as mcpd.bld0.0.15.core.gz may be generated in /var/core. The /var/log/ltm log messages may include:

Environment

  • Delete user account
  • MCPD crash
  • BIG-IP HA

Cause

This issue is caused by a software bug (ID1303873) where the presence of the /etc/passwd.lock file during user creation or deletion operations leads to MCPD crashing. The /etc/passwd.lock file is normally created temporarily by user management commands (such as useradd, userdel, usermod, passwd, vipw, or vigr) to prevent concurrent writes to /etc/passwd. If this lock file remains present (for example, due to an interrupted or failed user management operation), subsequent user management actions can cause MCPD to crash, especially in HA environments with auto-sync enabled.

Recommended Actions

Avoid editing /etc/passwd directly. Always use BIG-IP TMSH or the GUI to manage users.
If the issue occurs and the device is offline or MCPD is crashing, check for the presence of /etc/passwd.lock on the affected device. If found, remove or rename the file to restore normal operation:
# ls -lZ /etc/passwd.lock
# cd /etc
# mv passwd.lock passwd.lock.backup
After removing the lock file, user management operations via TMSH or GUI should function normally.
There is currently no software fix available for bug ID1303873. The probability of this issue occurring is low, but if it recurs, apply the above workaround.
