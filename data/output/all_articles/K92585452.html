Known Issue

Secure Sockets Layer (SSL) handshakes using a softcard-protected certificate or key pair may fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to use a Thales hardware security module (HSM) to protect SSL keys.
  • You enable softcard-protection and disable the Token (OCS) key protection method.
  • You use the fipskey.nethsm utility to generate a softcard-protected key.
  • The Client SSL profile references the softcard-protected certificate or key pair configured on the Thales HSM.

Impact

The SSL handshake fails using the affected certificate or key pair.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You cannot establish an SSL connection on a virtual server that is associated with a Client SSL profile that references the affected certificate or key pair that is configured on the Thales HSM.
  • In the /var/log/ltm file, you observe log messages similar to the following example:

    warning tmm2[<pid>]: 01260036:4: FIPS acceleration device error: fips_poll_completed_reqs: req: 22 status: 0x1 : Cancel
    warning pkcs11d[<pid>]: 01680022:4: Crypto operation [2] failed.
