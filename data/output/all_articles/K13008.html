Issue

Error Message

SECURITY_CLI-0-NOTE-ADAUTH_NO_ARX_GROUPS:: User <user id> has no AD group from DC <IP address> corresponding to any ARX group.

In this error message, note the following:

  • <user id> is the username for an administrative user being authenticated to access the ARX CLI or ARX Manager GUI.
  • <IP address> is the Domain Controller IP address.

For example:

SECURITY_CLI-0-NOTE-ADAUTH_NO_ARX_GROUPS:: User jdoe has no AD group from DC 192.168.65.50 corresponding to any ARX group

Message Location

You may encounter this message in the following location:

  • syslog file

Description

This message occurs when one of the following conditions are met:

  • The user is not a member of an Active Directory group that corresponds to a group defined on the ARX.
  • The group defined on the ARX does not match the case of the corresponding group defined in Active Directory.
    For example, the group is defined on the ARX system as usergroup1 and the group that is defined in Active Directory is Usergroup1.
  • The user is a member of a nested group in Active directory and the group defined on the ARX matches the parent group. (The ARX does not recognize Active Directory group nesting to grant privileges.)
  • The list of Active Directory groups returned from the domain controller for the user does not contain the group defined on the ARX within the first 1,000 groups.

Impact

The user will not be authenticated and the system will not grant access to the ARX.

Recommended Actions

For an Active Directory user to successfully authenticate to the ARX, an ARX group must be defined so it correlates to an Active Directory group of which the user is a member. For information about configuring Active Directory authentication, refer to the Configuring Management Access chapter of the ARX Network Reference Guide.

You can verify group names configured on the ARX using the show group roles command. Confirm that the group configured on the ARX exactly matches the group configured in Active Directory.

You can verify if the Active Directory group is included within the user's first 1,000 Active Directory groups returned from the domain controller by enabling debug logging for the SECURITY_CLI component. To enable debug logging for the SECURITY_CLI component, use the following procedure:

Impact of procedure: The ARX system may experience a slight performance impact as a result of the increased logging.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Enter configuration mode by typing the following command:

    config

  4. Set the logging level for the SECURITY_CLI component to debug by typing the following command:

    logging level SECURITY_CLI debug

Once the logging level for the SECURITY_CLI component has been set to debug, when an Active Directory user attempts to authenticate, the ARX will log the domain controller's response that includes the user's Active Directory group membership details. The message is logged to the syslog file and appears similar to the following:

SECURITY_CLI-0-DBG-MSG7:: DC at <IP address> says <ID> belongs to these <#> groups: <group list>

In this error message, note the following:

  • <IP address> is the Domain Controller IP address.
  • <ID> is the username being authenticated.
  • <#> is the number of Active Directory groups the user is a member of.
  • <group list> is a list of Active Directory group names the user is a member of.

For example:

SECURITY_CLI-0-DBG-MSG7:: DC at 192.168.65.50 says jdoe belongs to these 3 groups: RESARXADMINS,ARXAdmins,Domain Users

Important: For a user that is a member of more than 1,000 Active Directory groups, the group configured on the ARX must be one of the first 1,000 groups listed in this response from the domain controller.

Once the user's Active Directory group membership has been verified, you should disable debug logging for the SECURITY_CLI component, by typing the following command:

no logging level SECURITY_CLI
