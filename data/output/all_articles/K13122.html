Known Issue

Share removal operations fail if the share being removed has a path greater than 4,096 characters in length.

This issue occurs when either of the following conditions is met:

  • You attemp to remove the share from a managed volume using the remove-share command from the ARX CLI.
  • You attempt to remove the share from a managed volume using the ARX Manager GUI.

Note: A share path greater than 4,096 characters in length is most likely the result of an unintentional operator action.

Impact

The user will be unable to remove the share from a managed volume.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The remove-share command fails with an error message that appears similar to the following example:

    % ERROR: STORAGE_REMOVE_FAILED (41353519): Storage remove for namespace 'basic_nfs_udp', volume '/vol1', share 'second' failed 'Internal Error: "Buffer too small" (-11)'

  • When attempting to remove the share using the ARX Manager GUI, the share removal operation ends without an error message, but the share is not removed.
  • Storage removal error messages that appear similar to the following example are logged to the syslog file:

    :DNAS_PGRP-2-ERR-MSG3:: Internal Error: PSLK: dld_get_path_by_did_wdc failed for did 0x200000000006e: "Buffer too small"
    :L2SW_LVL7-0-NOTE-MSG5:: SNMP TRAP: shareRemoveFail (700) shr 'namespace:/vol1:share_nfs1', name 'filer-name', ip '192.168.10.5', : Internal Error: "Buffer too small" (-11)
    :MGT_DNAS_CONFIG-2-WARN-STORAGE_REMOVE_ERROR:: An error occurred removing the filer 'filer-name' path '/vol/vol1/filershare1' bound to share 'namespace:/vol1:share_nfs1' in volume '/vol1', namespace 'namespace': Buffer too small [-11].
    :CLI-0-ERR-STORAGE_REMOVE_FAILED:: Storage remove for namespace 'namespace', volume '/vol1', share 'share_nfs1' failed 'Internal Error: "Buffer too small" (-11)'.

Workaround

To work around this issue, you must rename or move the directory structure in order to shorten the path name to be fewer than 4,096 characters. To do so, perform one of the following methods:

  • Shorten the path through the ARX virtual server.
  • Shorten the path through the file share directly.

Shorten the path through the ARX virtual server

Impact of workaround: The directory structure changes may impact some applications or users by changing the location of desired files.

If possible, you should perform the directory structure changes by way of the ARX virtual server. Making the changes by way of the virtual server prevents metadata inconsistencies and allows the volume to remain online.

The method used for shortening the path name is unique to your specific environment. One method may be to shorten the directory names at or near the beginning of the path.

For example, if the affected directory structure started with the following:

/mnt/share1/directory1/directory2/directory3/directory4/directory5/directory6/...

You could rename the beginning directories to be similar to the following:

/mnt/share1/1/2/3/4/5/6/...

You must do this until the path is shorter than 4,096 characters.

Note: You must modify the directory names at the beginning of the path because you will be unable to modify the directory structure at the end of the path beyond the 4,096 maximum path limit.

Shorten the path through the filer share directly

Impact of workaround: Modifying the filer share directly results in metadata inconsistencies and requires that you re-import the volume shares. Reimporting the volume disrupts all clients using the volume.

If you are unable to access the share through the virtual server (for example, if the share is offline), you must rename or move the directory structure through the filer share directly. After the filer share's directory structure has been modified to ensure all paths are less than 4,096 characters long, you must reimport the volume using the following nsck command syntax:

Important: Rebuilding the volume using the nsck command disrupts all clients using the volume.

nsck <namespace> rebuild volume <volume>

Note: For information about the nsck command, refer to the ARX CLI Reference Guide.
