K000130618: Device forced offline when running 'tmsh run /cm watch-trafficgroup-device'

Type
Support Solution
Published
2023-01-17
Updated
2023-10-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 16.1.2
Source
https://my.f5.com/manage/s/article/K000130618

Description

  • BIG-IP in force offline state.
  • In /var/log/ltm 
    Jan 16 11:19:54 BIP01.example.net notice sod[7611]: 010c0044:5: Command: go offline all tmsh
Jan 16 11:19:54 BIP01.example.net notice sod[7611]: 010c0055:5: Forced offline for traffic group traffic-group-1
Jan 16 11:19:54 BIP01.example.net notice sod[7611]: 010c003f:5: Forced offline
  • In /var/log/audit 
    Jan 16 11:19:54 BIP01.example.net notice scriptd[12511]: 014f0006:5: AUDIT - non-config DB script content name=cmd_sod args="cmd_sod"
Jan 16 11:19:54 BIP01.example.net notice scriptd[12511]: 014f0006:5: AUDIT - proc script::run {} { tmsh::run sys failover offline }
Jan 16 11:19:54 BIP01.example.net notice scriptd[12511]: 014f0005:5: AUDIT - user=root action="run stand-alone script: cmd_sod" status="OK"Symptoms
  • The audit log for the run cm watch-trafficgroup-device command appears after quitting the watch-trafficgroup-device utility, and Force offline messages are written. The user who issued the command is also logged. For example, in the following scenario, the user who ran the command is example_user. 
    Jan 16 11:20:30 BIP01.example.net notice tmsh[13891]: 01420002:5: AUDIT - pid=13891 user=example_user folder=/Common module=(tmos)# status=[Command OK] cmd_data=run cm watch-trafficgroup-device

Environment

  • BIG-IP
  • tmsh run cm watch-trafficgroup-device

Cause

Run the following command in TMSH: run /cm watch-trafficgroup-device, and press Enter twice while the device is highlighted.

 Recommended Actions

This is by design. To quit from watch-trafficgroup-device utility, press Ctrl+C.

Additional Information


A dialog window is available for selecting the failover state.
