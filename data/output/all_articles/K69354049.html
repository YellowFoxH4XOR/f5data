Restricting access to the BIG-IP management interface for Configuration utility and iControl REST services using iptables

Description

You can use the iptables utility to restrict access to the BIG-IP management interface by protocol, port, or IP address. You can do this to limit access to TCP port 443 of the BIG-IP management interface, which the Configuration utility (TMUI) and iControl REST use.

Environment

  • BIG-IP 13.1.x, 12.1.x, or 11.6.x1
  • BIG-IP LTM is provisioned
  • BIG-IP AFM is not licensed or provisioned1
  • Appliance Mode is not in use2

1For BIG-IP 14.1.x and later, or If BIG-IP AFM is licensed and provisioned, refer to K46122561: Restricting access to the management interface using network firewall rules

2 For more information, refer to K12815: Overview of Appliance mode.

Cause

Using the iptables utility to secure the BIG-IP management interface TCP port 443 because this is used by BIG-IP services such as the Configuration utility and iControl REST. This configuration is independent from the tmsh sys httpd command to limit IP address access to the TCP port 443 based BIG-IP services.

Recommended Actions

Prerequisites

  • You have access to the BIG-IP command line
  • Appliance mode is not in use

Additionally, before proceeding, consider the following:

  • The iptables rules do not sync through a ConfigSync, so you must apply the iptables rules on each BIG-IP device.
  • The iptables rules do not persist after an upgrade, so you must re-apply the iptables rules if you perform the upgrade on a version prior to BIG-IP 14.1.0. If devices are upgraded to 14.1.0 or later, then you must re-configure the rules by making use of the network firewall rules described within K46122561: Restricting access to the management interface using network firewall rules.
  • For devices in a ConfigSync cluster, you need to add the peer BIG-IP management IP to the ruleset.
  • Blocking 443 prevents re-establishment of device trust and iControl REST synchronization.
  • If you're managing BIG-IP systems directly using BIG-IQ, you need to account for multiple subnets and/or hosts. (BIG-IQ manages BIG-IP systems using iControl REST).
  • Adding multiple subnets and/or hosts requires that you insert additional before the general drop at the end. (Getting the ordering wrong drops legitimate connections.)
  • The iptables rules are ineffective for accepting or rejecting traffic to-or-from a self IP address. When it comes to restricting access to a particular self IP address, F5 recommends you make use of packet filters within Network > Packet Filters in the Configuration utility.

Procedures

  • Use the iptables utility on the BIG-IP system to limit access to TCP port 443, the Configuration utility, and iControl REST on the BIG-IP management interface
  • Delete an iptables rule

To watch a video demo of these procedures, go to  Use iptables to restrict access to the BIG-IP management interface.

Use the iptables utility on the BIG-IP system to limit access to TCP port 443, the Configuration utility, and iControl REST on the BIG-IP management interface

You can use the iptables utility on the BIG-IP system to limit access to TCP port 443, the Configuration utility, and iControl REST. You should take care in defining the source IP network in the iptables command syntax because it may be possible to lock out access to TCP port 443. Prepare alternative access to your BIG-IP device's console session for access recovery in case of accidental access lockout.

ip6tables -A INPUT -s <IPV6 address or subnet> -i mgmt -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection mgmt" -j ACCEPT

For example:

ip6tables -A INPUT -s 2001:db8::1 -i mgmt -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection mgmt" -j ACCEPT

ip6tables -A INPUT -s <IPV6 address or subnet> -i eth0 -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection eth0" -j ACCEPT

For example:

ip6tables -A INPUT -s 2001:db8::1 -i eth0 -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection eth0" -j ACCEPT

#----- add here additional IP address/networks that need access to BIG-IP management interface ----#

ip6tables -A INPUT -s <IPV6 address or subnet> -i mgmt -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection from automation systems IPv6 address" -j ACCEPT

For example:

ip6tables -A INPUT -s 2001:db8::1 -i mgmt -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection from automation systems IPv6 address" -j ACCEPT

ip6tables -A INPUT -s <IPV6 address or subnet> -i eth0 -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection from automation systems IPv6 address " -j ACCEPT

For example:

ip6tables -A INPUT -s 2001:db8::1 -i eth0 -p tcp --dport 443 -m comment --comment "Allow ingress mgmt connection from automation systems IPv6 address " -j ACCEPT

#----- add additional IP address/networks that need access to BIG-IP management interface ----#

# execute these iptables rules after intended source IP/networks are added, these are the general Drop rules

ip6tables -A INPUT -s ::/0 -i mgmt -p tcp --dport 443 -m comment --comment "Drop ingress mgmt connections mgmt" -j DROP

ip6tables -A INPUT -s ::/0 -i eth0 -p tcp --dport 443 -m comment --comment "Drop ingress mgmt connections eth0" -j DROP

  1. Log in to the BIG-IP bash CLI session using an administrator or root account.
  2. Use the following command syntax to apply the following iptables rules, executing them one at a time, replacing IPv4 subnet with the actual source IPv4 address (example: 172.16.0.10) or subnet (example: 172.16.0.0/16) that requires access to the BIG-IP management interface.

    Note: Lines that starts with # are comments, not iptables commands.

    iptables -A INPUT -s <IPV4 address or subnet> -i mgmt -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection mgmt"

    For example:

    iptables -A INPUT -s 10.154.210.131 -i mgmt -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection mgmt"

    iptables -A INPUT -s <IPV4 address or subnet> -i eth0 -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection eth0"

    For example:

    iptables -A INPUT -s 10.154.210.131 -i eth0 -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection eth0"

    #----- add additional IP address/networks that need access to BIG-IP management interface ----#

    iptables -A INPUT -s <IPV4 address or subnet> -i mgmt -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from BIG-IQ"

    For example:

    iptables -A INPUT -s 10.154.210.131 -i mgmt -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from BIG-IQ"

    iptables -A INPUT -s <IPV4 address or subnet> -i eth0 -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from BIG-IQ "

    For example:

    iptables -A INPUT -s 10.154.210.131 -i eth0 -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from BIG-IQ "

    iptables -A INPUT -s <IPV4 address or subnet> -i mgmt -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from Automation systems"

    For example:

    iptables -A INPUT -s 10.154.210.131 -i mgmt -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from Automation systems"

    iptables -A INPUT -s <IPV4 address or subnet> -i eth0 -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from Automation systems "

    For example:

    iptables -A INPUT -s 10.154.210.131 -i eth0 -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from Automation systems "

    #----- add additional IP address/networks that need access to BIG-IP management interface ----#

    # execute these iptables rules after intended source IP/networks are added, these are the general drop rules

    iptables -A INPUT -s 0.0.0.0/0 -i mgmt -p tcp --dport 443 -j DROP -m comment --comment "Drop ingress mgmt connections mgmt"

    iptables -A INPUT -s 0.0.0.0/0 -i eth0 -p tcp --dport 443 -j DROP -m comment --comment "Drop ingress mgmt connections eth0"

  3. Save runs for IPv4 iptables rules by entering the following command:.

    iptables-save > /etc/sysconfig/iptables

  4. If you are using IPv6 networks to access the BIG-IP management interface, see the example iptables command.
  5. Save rules for IPv6 ip6tables rules by entering the following command

    ip6tables-save > /etc/sysconfig/ip6tables

Delete an iptables rule

To delete a rule, enter the following command syntax as appropriate:

iptables -D <chain> <ipv4tables rule>

ip6tables -D <chain> <ipv6tables rule>

For example:

iptables -D INPUT -s 10.154.210.131 -i mgmt -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from BIG-IQ"

iptables -D INPUT -s 10.154.210.131 -i eth0 -p tcp --dport 443 -j ACCEPT -m comment --comment "Allow ingress mgmt connection from peer BIG-IQ "

  • Save rules for IPv4 or IPv6 iptables rules:

    To save rules for IPv4 iptables rules, enter the following command:

    iptables-save > /etc/sysconfig/iptables

    To save rules for IPv6 ip6tables rules, enter the following command:

    ip6tables-save > /etc/sysconfig/ip6tables

Additional Information

For BIG-IP 11.6.x, BIG-IP 12.1.x, and BIG-IP 13.1.x with BIG-IP AFM provisioned, the configuration procedure in K46122561: Restrict access to the BIG-IP management interface using network firewall rules (for BIG-IP 14.x and later) are applicable because the Configuration utility options in System > Platform > Security > Management Port and the tmsh security management-ip commands are similar.

When adding a rule for the management port context firewall policy from the Configuration utility, the Security > Network Firewall > Active Rules > New Rule page opens to continue the configuration.

For BIG-IP 14.x and later, with BIG-IP AFM provisioned, accessing the management port context firewall policy from Security > Network Firewall > Active Rules page in the Configuration utility redirects to System > Platform > Security > Management Port page the and configuration procedure in Restrict access to the BIG-IP management interface using network firewall rules is applicable.
