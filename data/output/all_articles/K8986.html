Overview of F5 product support policies

F5 product support policies help you plan and prepare for your organization's support needs. Support for F5 products is based on a common model that defines milestones that span the lifecycle of its products.

F5 products have general and product-specific support policies.

There are three general categories of F5 products:

  • Hardware products
  • Software products
  • Service products (SaaS and managed services)

Within the framework of each of these categories, individual F5 products have policies that address the specific needs of each product.

General hardware product support policy

The following illustration and milestones define the general hardware product support policy.

Ensure you also reference the following resources when planning the support needs for the lifecycle of your hardware product:

  • Specific support policy for your hardware product
  • General software product support policy
  • Specific support policy for your software product
  • K9476: The F5 hardware/software compatibility matrix

Figure: General hardware product support milestones

Hardware product support milestones:

  1. Introduction: limited and general availability
  2. End of Sale (EoS)
  3. End of New Software Support (EoNSS)
  4. End of Software Support (EoSS)
  5. End of Support Contract Renewal (EoSCR)
  6. End of RMA (EoRMA)
  7. End of Technical Support (EoTS)
  8. End of Life (EoL)

After F5 issues an EoS announcement for a hardware product, but before the hardware product reaches EoL, if a unit fails, F5 may not replace the unit with an identical hardware product. You can return failed system components, such as a solid state drive, to manufacturing through the standard Return Materials Authorization (RMA) process, and F5 will replace the components with a functionally equivalent replacement unit.

End of hardware product support for a software version

At the EoNSS date for a hardware system, the hardware system is unsuited to run new major/minor software product versions.

At the EoSS date for a hardware system, F5 no longer provides major, minor, maintenance, point, or engineering hotfix (EHF) releases for the system.

After EoSS, F5 continues to provide technical support for the hardware system until it reaches EoTS.

Software product versioning

Not all F5 software products follow the same semantic versioning system. Typically, F5 software products use a system that includes the following three-part version number:

  • <major release>.<minor release>.<maintenance release>

However, the BIG-IP version schema can have the addition of a point release digit:

  • <major release>.<minor release>.<maintenance release>.<point release>

For example, for BIG-IP 17.5.1.8, the major release is 17, the minor release is 5, the maintenance release is 1, and the point release is 8.

To see the version schema and definitions for each part of the schema for any product, refer to the policy for that product, which you can find in K39757430: F5 product and services lifecycle policy index.

Definitions for parts of the version number for most F5 products and BIG-IP
Release typeDefinition
MajorIncludes significant changes in behavior, added functionality, significant increases in performance, new hardware product support, and/or significant architectural changes.
MinorIncludes added functionality, improved performance, new hardware support, and addresses software product defects.
MaintenanceContains all previous point releases and addresses additional software product defects, new hardware support, and security fixes. This part has a value of 1 or higher; a value of 0 indicates there is not yet a maintenance version.
PointIs a full release that addresses product defects, including the hardening and refining of existing features and security fixes, and may contain minor functional improvements; however, it will not introduce a change in existing default behavior.

Point releases end in x.x.x.x. Major versions automatically encompass the point releases associated with them; you do not need to reactivate a license when updating to a point release.

F5 periodically provides point releases for:
  • Major releases within their Standard Support phase.
  • The latest maintenance release of each Long-Term Support (LTS) release.
These releases include multiple fixes for significant software defects discovered between minor releases or maintenance releases. These releases receive the same level of testing as maintenance releases and are available on the MyF5 Downloads page for all F5 customers to download.

EoL for software product feature support

F5 may choose, at its discretion, to discontinue support for features contained within a particular software product. Typically, these features are either unused by customers or the software product has new functions that replace them. F5 communicates EoL for major features by posting software product notices on AskF5.

When you choose to continue using a previous software product version because it includes an obsolete or changed feature, F5 provides reasonable-effort technical support after software support for that software product version expires.

General service product support policy (SaaS and managed services)

F5 has software as a service (SaaS) and managed services offerings. While these service products typically do not require customers to manage the support lifecycle, F5 does introduce and retire service products over time, as represented in the following illustration.

When F5 issues an EoS announcement, the communication includes the service contract renewal milestones, indicating when you can conduct the last term renewal. This announcement prevents customers from renewing a service product for a term that extends beyond the life of that service product.

For more information about support for your service product, refer to the support policy for the service family to which your service product belongs.

Multiple support policies and their order of precedence

Customer solutions from F5 often span two or more product categories, such as a hardware system that runs a software product and uses a service product. Therefore, it helps to understand the general support policies for the products you have and how they work together.

The following rules generally apply:

    • Hardware product support lifecycle milestones supersede software product support lifecycle milestones.
    • Software product support lifecycle milestones supersede service product support lifecycle milestones.

Figure: General support policies order of precedence

If you are a customer with F5 hardware products, F5 recommends that you track the hardware product support lifecycle as the primary lifecycle for your F5 products.

The following examples illustrate how the general support policies interact and how the hardware support lifecycle has precedence.

Examples of how general policies for hardware, software, and service products interact
ExampleDescription
You have BIG-IP software running on a BIG-IP 5200 system platform.

When your platform reaches EoNSS, you cannot upgrade to new major or minor software product versions.

  • Your BIG-IP 5200 platform can run newer major or minor versions of BIG-IP software products until it reaches the EoNSS milestone. After that, F5 continues to support the hardware product with newer maintenance versions of the BIG-IP software product it is running, until that software product reaches EoSS.

    During and after that time, F5 continues to release new major, minor, and maintenance versions of BIG-IP software products. While your BIG-IP 5200 hardware product does not support all of these releases, other hardware products support them, such as newer hardware systems, Virtual Editions (VEs), and/or cloud marketplace images.
When your software product reaches EoSD, but your hardware product has not reached EoNSS, you can still upgrade your software product.

  • If your BIG-IP 5200 hardware product has not reached EoNSS, and you are running an earlier version of a BIG-IP software product that reaches EoSD, as long as that hardware product remains under an F5 support contract, you can upgrade to a newer version of a BIG-IP software product that has not yet reached EoSD.

You have a BIG-IP software product running on a BIG-IP VE Version Plus offering.

Your BIG-IP VE Version Plus instance defines the software product versions you can use and retires when the last version of those software products retires.

  • When you purchase a BIG-IP VE Version Plus 18 instance, you can run any software product version between BIG-IP 12.1.0 and 18.1.x. If you are running BIG-IP 12.1.0 and it reaches EoSD, you can upgrade to any available newer software product version, up to BIG-IP 18.1.x, as long as your VE instance remains under an F5 support contract. However, because you cannot run any software product later than BIG-IP 18.1.x, the hardware product support lifecycle ends when the BIG-IP 18.1.x lifecycle ends.
