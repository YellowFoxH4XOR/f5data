K000137978: ASM out of memory error and connection reset errors from asm logs

Type
Support Solution
Published
2023-12-20
Updated
2023-12-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000137978

Description

  • Clients connections getting terminated by ASM with a reset
  • ASM out of memory errors similar to the following are logged on /var/log/asm

     emerg perl[28070]: 01310003:0: ASM out of memory error: event code P297
     emerg perl[14803]: 01310003:0: ASM out of memory error: event code P297

  • Not enough UMU memory error messages are logged on /var/log/ts/bd.log

     IO_PLUGIN|ERR |Nov 17 12:22:10.062|14344|plugin_common.c:0298|trans_open: Not enough UMU memory to start a new trans.
     IO_PLUGIN|ERR |Nov 17 12:22:10.104|14343|plugin_common.c:0298|trans_open: Not enough UMU memory to start a new trans.

Environment

  • BIG-IP ASM
  • ASM Out of memory error
  • Connection resets
  • Learning from responses enabled on ASM policy

Cause

Response accumulation happens if one of following features are enabled on the ASM.

  • Learn from Responses in the Policy Builder settings <-- can disable this after the initial policy building. do not leave this enable
  • DataGuard <-- disable if not needed
  • Dynamic Parameters Extraction
  • Login Page Detection
  • Server Technologies <-- can disable this after the initial policy building. do not leave this enable
  • Attack Signatures in the Response <-- disable if not needed
  • Dynamic Session ID in URL

When 'Learn from responses' is enabled asm will buffer the response and this increases the asm memory consumption. When the following error message are logged the connections are terminated with RST.

IO_PLUGIN|ERR |Nov 17 12:22:12.843|14342|plugin_common.c:0298|trans_open: Not enough UMU memory to start a new trans.

Recommended Actions

Disable Learn from responses.

1. Go to Security ›› Application Security : Policy Building : Learning and Blocking Settings.
2. Select policy in question
3. Expand Policy Building Process
4. Uncheck the \"learn from response\"
5. Save and apply the policy
