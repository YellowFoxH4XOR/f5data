Description

If "Trigger ASM iRule Events Mode" is disabled in your BIG-IP ASM (Application Security Manager) security policy, all ASM-specific iRule events and related custom logic will be ignored. Only standard LTM iRule events will be processed, and you will not be able to use iRules to interact with ASM-specific context, such as unblocking requests, customizing blocking pages, or logging ASM violations.

Environment

  • BIG-IP ASM 
  • Security policy with "Trigger ASM iRule Events Mode" setting

Cause

When "Trigger ASM iRule Events Mode" is disabled:

  • ASM-specific iRule events (such as ASM_REQUEST_DONE, ASM_REQUEST_BLOCKING, ASM_REQUEST_VIOLATION, etc.) are not triggered.
  • Any iRule logic that depends on these events will not execute.
  • ASM iRule commands (e.g., ASM::unblock, ASM::raise, ASM::support_id) will not function and may result in errors or be ignored.
  • Only standard LTM iRule events (e.g., HTTP_REQUEST, HTTP_RESPONSE) will be processed, but these cannot interact with ASM-specific features.

Recommended Actions

  • Enable "Trigger ASM iRule Events" if you have written iRules that use ASM events and want to process ASM-specific logic (such as custom blocking pages, exception handling, or advanced logging).
  • Leave it disabled if you do not use ASM iRules, to avoid unnecessary processing overhead.

Impact : Enabling or disabling the "Trigger ASM iRule Events Mode" setting in your BIG-IP ASM security policy does not interrupt or drop active traffic. This is a configuration change at the policy level and does not cause a service restart or traffic outage. However If you enable this option and have iRules with errors or logic that could disrupt traffic (for example, iRules that improperly reject or reset connections), then those iRules could impact traffic. Always validate and test your iRules before enabling this feature in production.

Steps to Enable:

  1. Go to Security > Application Security > Security Policies > Policies List.
  2. Select the policy you want to edit.
  3. Go to the General Settings tab.
  4. Set Trigger ASM iRule Events Mode to Normal (or the appropriate mode for your use case).
  5. Save and apply the policy.

Additional Information

When enabled, the system activates ASM iRule events. When disabled, the system does not activate ASM iRule events. Enable this option if you have written iRules that process ASM iRule events, and assigned them to a specific virtual server. The default setting is disabled.

  • disabled: Leave this option disabled if you either have not written any ASM iRules.
  • enabled-normal: The system invokes the event ASM_REQUEST_DONE after the system completes processing each request, regardless of whether the request triggered violations.
  • enabled-compatibility: The system invokes the event ASM_REQUEST_VIOLATION after the system completes processing each request that triggered a violation.
