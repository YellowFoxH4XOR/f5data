K000160472: Handling URL Path Normalization for Encoded Slashes (%2f) in F5 Distributed Cloud Routing and WAF

Type
Support Solution
Published
2026-03-26
Updated
2026-06-12
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000160472

Description

When the forward slash ("/") is URL-encoded as "%2f" in HTTP requests, routing and security policies (such as Bot Defense and WAF) may not behave as expected. Requests with "%2f" in the path are not routed to the intended origin or security cluster, service policies intended to block or match "%2f" in the path do not trigger, and requests with "%2f" may bypass certain protections or be routed directly to the origin.

Environment

  • Product: F5 Distributed Cloud (XC)
  • Features: HTTP Load Balancer, Web App & API Protection (WAAP), Bot Defense, WAF
  • Configuration objects: Service Policies, Routing Rules (Regex-based), Load Balancers
  • Example affected path: /some%2flibrary/common.js

Cause

Routing decisions in XC are made based on the original, non-normalized path. Normalization (conversion of "%2f" to "/") occurs after routing, which can result in encoded slashes not matching expected routing or security rules.

Answer/Recommended Actions

  1. Routing for Encoded Slashes:
    • Use a regex route that matches both "/" and "%2f" to ensure requests with encoded slashes are routed correctly.
    • Example regex for route matching:

    (?i).*(?:/|%2f)library(?:/|%2f)common\.js

    • (?i) makes the regex case-insensitive.
    • (?:/|%2f) matches either a literal slash or "%2f".
  2. Forcing Traffic Through the Load Balancer:
    • To ensure all requests with "%2f" are processed by the load balancer (and thus WAF), use a broader regex:

    (?i)^/(?:.*%2f)?.*

    • This matches any path starting with "/" and optionally containing "%2f".
  3. WAF and Service Policy Behavior:
    • WAF rules are applied after normalization. Once the request reaches WAF, "%2f" is already converted to "/".
    • Service policies cannot directly block "%2f" in the path before normalization; use routing regex as above to ensure such requests are handled by WAF.
  4. Blocking Requests with Encoded Characters:
    • Service policies can block requests with "%" in the path, but "%2f" specifically may not be blocked due to normalization timing.
    • For other encoded characters, blocking on "%" may be effective.
  5. Feature Request:
    • If routing based on the normalized path is required, submit a feature request through your F5 Account Manager or Customer Success Manager.

Additional Information

  • This behavior is due to the order of operations in XC: routing is performed on the original path, and normalization occurs afterward.
  • WAF and Bot Defense protections are applied after normalization, so attacks relying on encoded slashes can be mitigated if routing is configured to capture such requests.
