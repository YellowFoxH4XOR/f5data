Description

Enabling zone-sync in NGINX Ingress Controller(NIC) with '-disable-ipv6=true' causes VirtualServer resources to become invalid due to an "unexpected ';'" error in nginx.conf.

Environment

  • NIC
  • OIDC

Cause

This is a confirmed bug in NGINX Ingress Controller, where enabling 'zone-sync' in the configmap with '-disable-ipv6=true' generates an invalid nginx.conf with an extra semicolon, causing reload failure.

Answer/Recommended Actions

1. Remove 'zone-sync' from the ConfigMap and add the zone-sync configuration under 'stream-snippets', and manually create the required headless service; bug fix to be included in a future release

kind: ConfigMap
apiVersion: v1
metadata:
  name: nginx-config
data:
  zone-sync: "true"   <<=== !!! Remove this line

  --- Add a stream-snippets below ---
  stream-snippets: |
    server {
        listen 12345;
        zone_sync;
        zone_sync_server nginx-ingress-headless.nginx-ingress.svc.cluster.local:12345 resolve;
    }
  resolver-addresses: kube-dns.kube-system.svc.cluster.local
  resolver-valid: 5s

2. Ensure the required headless service exists, manually create it with the following YAML (adjust namespace and selector as needed).

apiVersion: v1
kind: Service
metadata:
  name: nginx-ingress-headless
  namespace: <namespace>
spec:
  clusterIP: None
  selector:
    app.kubernetes.io/name: nginx-ingress

3. Apply the updated ConfigMap and Service.
