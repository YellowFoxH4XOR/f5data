Known Issue

The Traffic Management Microkernel (TMM) may produce a core file and restart when you view the connection table.

This issue occurs when all of the following conditions are met:

  • You configure a NAT on the BIG-IP system.
  • You configure an AFM reject rule or packet filter for ICMP.
  • The NAT processes an ICMP Type 11 packet from a backend server.
  • You view the connection table using the Traffic Management Shell (tmsh) utility.

Under very rare conditions, TMM may produce a core file and restart when you view the connection table using the tmsh utility.

Impact

If the BIG-IP system is a member of a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until the TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily fails to process traffic.
  • The BIG-IP system may unexpectedly fail over to another system in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

To work around this issue, you can avoid using the tmsh utility to view the connection table.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
