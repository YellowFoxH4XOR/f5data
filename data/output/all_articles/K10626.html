Known Issue

This is the result of a known issue. Passive FTP data connections handled by a virtual server on the BIG-IP system may fail intermittently. This issue is a side effect of recent improvements to the FTP profile, aimed at supporting passive FTP data connections through multi-core BIG-IP systems. When the BIG-IP system receives an FTP 227 (Entering Passive Mode) response from a pool member, TMM may change the port number chosen by the pool member for the data connection, if that port number is not available as an ephemeral listener on the virtual server. After the client has opened the data connection to the virtual server using the port specified by TMM, the BIG-IP system must proxy that connection on its server-side using the port originally specified by the pool member in its Entering Passive Mode response. This may not happen every time; TMM may try to open a server-side connection using the same port that it had chosen for the client-side. At this point the server will reset the connection, as it does not expect a connection on that port. Finally, the BIG-IP system will forward the reset to the client. As a result, that FTP connection will fail.

Similarly, for Active FTP connections, the BIG-IP system may translate the PORT value received by the FTP client but fail to translate that value for the server-side connection.

F5 Product Development is tracking this issue as ID 333014 (formerly CR128104).

This issue does not affect the BIG-IP 10.x software branch.

This issue has been fixed in BIGIP-9.4.8-396.1-HF3, which has been issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Note: After installing the hotfix, ensure that Port translation is enabled for the virtual server.
