Issue

When an NFS client specifies an incorrect export when attempting to mount an ARX VIP, the mount will fail and the ARX system will log an error message that appears similar to the following example:

: Client <client IP address> specified invalid front-end path <virtual server IP address>:/nfsexportnoslash

For example:

: Client 192.168.10.50 specified invalid front-end path 172.30.60.10:/nfsexportnoslash

To troubleshoot and find out why the NFS client is unable to mount the VIP, you can compare the export specified in the error message to the NFS section of the ARX global-config to determine whether the client and ARX system are using the same export name.

Note:  A forward slash ( / ) is a common reason for this type of failure.

For example:

  • An NFS client fails to mount an ARX VIP using the following command:

    mount 172.30.60.10:/nfsexportnoslash /home/user1/

    The client receives the following error message:

    mount.nfs: access denied by server while mounting 172.30.60.10:/nfsexportnoslash

    The ARX system logs an error message that appears similar to the following example:

    : Client 192.168.10.50 specified invalid front-end path 172.30.60.10:/nfsexportnoslash

    The NFS section of the ARX global-config indicates that the ARX is actually exporting the VIP as nfsexportnoslash:

    Note: Observe that nfsexportnoslash does not contain a leading slash.

    ;================================== nfs ==================================
      nfs nfs1.dsforest1.com
        export nfs1 /nfsvolume as nfsexportnoslash access-list ALL
        enable
        exit

  • From the client, display the VIP export list as presented by the ARX system using the following showmount command:

    showmount -e 172.30.60.10

    The showmount command output appears as follows:

    Export list for 172.30.66.12:
    nfsexportnoslash *(rw,no_root_squash)

    The ARX system is exporting the VIP as nfsexportnoslash (notice no leading slash).
  • Determine the source using the correct export--the client or the ARX system.
  • If the client is attempting to mount an incorrect export, change the mount command issued by the NFS client to match the export format on the ARX system.
     
    For example, the client can issue the following mount command:

    mount 172.30.60.10:nfsexportnoslash /home/user1/    

    Notice that the leading slash is removed from the command to match the export configured on the ARX system.

If the client is using the correct/desired export (/nfsexportnoslash with the leading slash), you can update the ARX NFS configuration and add a leading slash to the beginning of the export. To do so, perform the following procedure:

  1. Enable privileged mode by typing the following command:

    enable

  2. Enter global mode by typing the following command:

    global

  3. Enter the nfs configuration mode for the nfs-service by typing the following command:

    nfs nfs1.dsforest1.com

  4. Remove the incorrect export by typing the following command:

    no export nfs1 /nfsvolume as nfsexportnoslash access-list ALL

  5. Add the correct export by typing the following command:

    export nfs1 /nfsvolume as /nfsexportnoslash access-list ALL

  6. Enable the NFS service by typing the following command:

    enable

  7. Exit the nfs configuration mode and return to privileged mode by typing the following command:

    end

    The NFS entry in the global-config will now be:
    ;================================== nfs ==================================
      nfs nfs1.dsforest1.com
        export nfs1 /nfsvolume as /nfsexportnoslash access-list ALL
        enable
        exit

    The mount command used by the NFS client will now mount the ARX VIP.
