Description

In BIG-IP ASM Bot Defense, the "Session Opening" anomaly detects unusual behavior indicative of browser masquerading or automated malicious bots. Specifically, it triggers when a browser generates an excessive number of new sessions within a short period of time.


This article explains where to find the default detection timers for the "Session Opening" anomaly, how to interpret them, and how to modify these values if required to reduce false positives.


Environment

  • BIG-IP ASM / Advanced WAF
  • Bot Defense Profile configured
  • "Session Opening" anomaly enabled


Cause

The "Session Opening" anomaly was triggered because the system observed a pattern consistent with bot behavior — a large number of new sessions being initiated in a short timeframe. This anomaly helps detect automated clients that attempt to mimic browsers but fail to replicate human-like browsing patterns.


By default, the system uses the following thresholds:

  • Detection Threshold: 50 new sessions
  • Detection Time: 60 seconds
  • Mitigation Time: 600 seconds

These values define how aggressively the system identifies and mitigates potential bots.


Recommended Actions

If the detected behavior is legitimate — you may consider adjusting the anomaly detection thresholds to reduce the likelihood of false positives.


To view or modify the default timers for the "Session Opening" anomaly:

  1. Navigate to: Security > Bot Defense > Profiles > [Your Bot Profile]
  2. Click: Bot Mitigation Settings
  3. In section: Mitigation Settings Exception add exception for "Session Opening"
  4. Adjust the following settings:
  • Mitigation Action
  • Mitigation Time: Duration (in seconds) the anomaly stays in mitigation mode
  • Detection Threshold: Number of sessions to trigger the anomaly
  • Detection Time: Time window (in seconds) for evaluating the threshold

Additional Information

Adjusting thresholds should be done carefully to avoid weakening bot protections. Monitor anomaly logs after changes to validate effectiveness.
