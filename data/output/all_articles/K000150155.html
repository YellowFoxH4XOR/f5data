K000150155: F5OS 1.8.0 interface alarms not automatically clearing

Type
Support Solution
Published
2025-02-28
Updated
2026-04-13
Applies to
  • F5OS Products
  • F5OS-A: 1.8.X, 1.8.0
  • F5OS-C: 1.8.X, 1.8.0
Source
https://my.f5.com/manage/s/article/K000150155

Description

There is a known issue in F5OS where alarms on interfaces don't auto-clear, so any temporary  fluctuation will stay on the alert dashboard until manually cleared. This issue is tracked as ID1812665. Please note, alarms can also be triggered even on disabled interfaces (ID1812541).

Environment

  • F5OS 1.8.0

Cause

Bug ID 1812541: DDM system alarms triggered when interface is disabled D1812665

Recommended Actions

To clear stale alarms on Controller: 

On controllers, alarms seen in `show system alarms` comes  from "alert-service" service  and could be cleared using sendAlert utility. 

Example log entry:

262402 Portgroup 2 txBias ASSERT ERROR "Lanes: <1,2,3, or 4> Transmitter bias low alarm" "2025-03-04 05:11:14.593333144 UTC"

Login to the active controller:

docker exec alert-service /confd/test/sendAlert -i 262402 -r clear -n txBias -s "Portgroup 2"

where:

-i is the ID of the alert, -s is the source, and -n is the abbreviated error code you see in the show alarm output.

To clear stale alarms on Partition: 

On partitions, alarms seen in `show system alarms` comes  from "partition_alert_service" service  and could be cleared using sendAlert utility. 

Example log entry:

262401 Portgroup 1/1 WARNING Lanes: 4 Receiver power low warning 2026-01-21 07:17:28.298639129 UT

Note: To run the commands, please SSH into one of the partition blades from Velos controller.  If partition is deployed on blades 1 & 2, choose one of those, and run "ssh blade-X" where X is blade number. 

#ssh blade-1

[root@blade-1 ~]# docker exec partition_alert_service /confd/test/sendAlert -i 262401 -r clear -n rxPwr -s "Portgroup 1/1"

This should clear the alarm at the partition level.
