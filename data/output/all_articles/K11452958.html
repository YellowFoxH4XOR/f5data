Description

Replacing a FIPS device after a Return Materials Authorization in a High Availability Configuration with UCS archive.

Environment

  • FIPS Device
  • High Availability 

Cause

None

Recommended Actions

  1. Configure the management-ip and default route.

  2. Login to the WebUI. The setup utility will initiate

    1.  Activate the license.

    2. Configure the hostname and set root and admin passwords.

    3. Click the finish button.

  3. Force the device offline tmsh run /sys failover offline, AskF5 article K15122.

  4. Install Master key see AskF5 article K9420 for instructions.

  5. Upload UCS archive file System Archives + upload, AskF5 article K13132.

  6. Load the UCS Archive file with the no-license option tmsh load sys ucs < filename> no-license, AskF5 article K13132

    Note: Since the fips-card-sync has not been initiated yet, the UCS file will fail to fully load the configuration. However, the base configuration, including the self-IP address, should still load. You may encounter a similar error:   
    failed. -- 01070712:3: unable to synchronize FIPS key (/Common/<keyname.key) Unexpected Error: Loading configuration process failed.

  1. Verify the device is still in forced offline state if not run tmsh run sys failover offline. 

  2. On replacement, device reset the fips card to factory default tmsh run util fips-util reset.

    Example:

    tmsh  run util fips-util reset
    WARNING: This command removes all keys from the FIPS device
    and resets it to factory default state. Previously exported
    keys cannot be imported back to the device after the reset.
    Any configuration objects dependent on FIPS keys will cause
    the configuration to fail to load.
    Press <ENTER> to continue or Ctrl-C to abort:

    Device is now in factory default state

  3. Initialize fips on the replacement device using the same fips password and domain that are used on the peer device with the tmsh run util fips-util init command.

    Example:

# tmsh run util fips-util init
NFB Initialization Process

WARNING - all private keys in NFB will be erased after SO password is entered!
Any configuration objects dependent on FIPS keys will cause the configuration fail to load.
Passwords must be at least 7 characters in length.
Enter no password if you instead wish to cancel.

New SO Password:
Re-enter new SO Password:

Initializing NFB...
The security domain name must be the same on all FIPS machines.
Please enter your security domain name:<enter security domain name>
The FIPS device has been initialized.
Restart all services (in tmsh "restart sys service all"
or reboot the unit in order to allow the system to use the FIPSdevice.
NOTE:
Restarting services will disrupt load-balanced traffic and may
terminate remote login sessions to the device.

  1. After initializing fips you need to reboot or restart all services with the command tmsh restart sys service all and wait for device to become operational before proceeding to the next step. The replacement device should now report standby and in a disconnected state. It will take a few minutes for services to restart and you might need to reconnect to the cli if you are not using console.

    Example:

    prompt: root@(<Hostname>)(cfg-sync Disconnected)(Standby)(/Common)(tmos)#

  2. Synchronize the fips card, the following command is executed on the active device specifying the IP address of the replacement. tmsh run util fips-card-sync < replacement device self IP> and specify the root password

    Example:

    # tmsh run util fips-card-sync  <replacement device IP>
    Connecting to 192.168.1.2 as user root ...
    Password:
    Security Domains synchronized.

  3. Issue the command tmsh load sys config on the replacement device. You might see this message The connection to mcpd has been lost, try again. If you see this message run tmsh load sys config  a second time, it should work. 

    1. If the above still returns a FIPS config load failure, the following steps can be taken as an alternate method of resetting & initializing the FIPS card.
      Stop all services and reset the FIPS card on the replacement BIG-IP:
      # bigstart stop
      # fipsutil -f -v reset
      Then repeat steps 9 & 10 to Initialize the FIPS card again.
      On the Active BigIP, initiate a FIPS card sync to the replacement BIG-IP:
      # tmsh run fips-card-sync -v <MGMT IP of replacement BigIP>
      And follow the prompts.
      If a Host Key Error is returned, make a copy of "/root/.ssh/known_hosts" using:
      # cp /root/.ssh/known_hosts /var/tmp/known_hosts
      Then VI the file to edit it's contents:
      # vi /root/.ssh/known_hosts
      Place the VI cursor at the beginning of the line that contains the IP address of the replacement BIG-IP and highly the entire line/row, including the SSH Key string, and delete it with by typing "dd". Save the file and exit with the below:
      # :wq!
      Then repeat the below command again:
      # tmsh run fips-card-sync -v <MGMT IP of replacement BigIP>
       

  4. On the active device synchronize the configuration to the replacement device which is now standby with the command tmsh run cm config-sync force-full-load-push to-group <device group name>

  5. Verify the devices are now in sync and the fips keys were copied over to the standby device by running the following commands:

    tmsh show cm sync-status
    tmsh list sys crypto key
