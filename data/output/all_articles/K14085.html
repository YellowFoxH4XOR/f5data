Known Issue

A memory leak in the OpenSSL library may cause the bigd and big3d processes to core and restart.

This issue occurs when the following condition is met:

  • An HTTPS monitor is configured to supply a client certificate to a back end server.

Each time the HTTPS monitor supplies a client certificate to the backend server being monitored, a small amount of allocated memory is not released.

Impact

Performance may degrade over time and the system may eventually become unresponsive due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Error messages may be logged in the /var/log/kern.log file. For example:

    err kernel: Out of memory: kill process 15967 (mysqld) score 51410 or a child

  • Random services may restart.
  • The bigd or big3d process may core and restart.
  • If a swap partition is defined, memory may be swapped out to the swap partition.
  • The system performance may degrade.
  • Pool members may be incorrectly marked up or down.

Workaround

If the back end server is not configured to require a client certificate, you can configure the HTTPS monitor to not provide a client certificate. Alternatively, you can periodically restart the bigd and big3d processes. To do so, perform one of the following procedures:

Removing the client certificate from the HTTPS monitor

Impact of workaround: The HTTPS monitor will not supply a client certificate to the backend server being monitored.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Monitors.
  4. Click the name of the monitor to edit.
  5. From the Configuration menu, select Advanced.
  6. From the Client Certificate menu, select None.
  7. From the Client Key menu, select None.
  8. Click Update.

Restarting the bigd and big3d process

This workaround only recovers the memory lost form the memory leak and will need to be performed on a regular basis to recover memory.

Impact of workaround: Restarting the bigd process will temporarily interrupt the BIG-IP LTM monitor processing. Restarting big3d monitoring will temporarily interrupt BIG-IP GTM metrics collection.

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    bigstart restart bigd big3d
