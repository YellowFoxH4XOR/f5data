Known Issue

The Configuration utility may become unreachable when synchronizing access policies.

This issue occurs when all of the following conditions are met:

  • You have a large number of BIG-IP APM systems in a Sync-Only device group.
  • You attempt to synchronize access policies using the Policy Sync feature.

This issue is more likely to occur when syncing to a large number of devices in a device group or when syncing to devices with less processing power. Additionally, large access policies and access policies containing hosted content files can also exacerbate the issue.

Impact

Administrators are temporarily unable to access the Configuration utility. In some cases, the Configuration utility is unable to reconnect and manual intervention is required to recover.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility becomes unavailable during access policy synchronization.
  • The BIG-IP system generates messages to the /var/log/httpd/httpd_errors file that appear similar to the following example:

    err httpd[<PID>]: [error] (111)Connection refused: proxy: AJP: attempt to connect to 127.0.0.1:8009 (*) failed
    err httpd[<PID>]: [error] proxy: AJP: failed to make connection to backend: localhost

Workaround

To work around this issue, you can log in to the command line and restart the tomcat process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM command line.
  2. To restart the tomcat process, type the following command:

    tmsh restart /sys service tomcat

  3. Log back in to the Configuration utility once the tomcat process has restarted.
