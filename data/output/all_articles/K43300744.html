Topic

This article applies to BIG-IP 13.x - 21.x. For information about other versions, refer to the following article:

  • K25311653: Adding BIG-IP LTM to a network with BIG-IP DNS (11.x - 12.x)

You should consider using these procedures under the following condition:

  • You want to integrate BIG-IP LTM systems into a network with one or more existing BIG-IP DNS systems.

Description

You can add BIG-IP LTM systems to a network in which BIG-IP DNS systems are already present. To do so, you must enable communications between the BIG-IP LTM and BIG-IP DNS systems by performing the following procedures on one of the BIG-IP DNS sync group members:

  • Add BIG-IP server objects to the BIG-IP DNS configuration
  • Run the bigip_add script

Note: In BIG-IP DNS 12.1.2 and earlier, if you add a BIG-IP server object that contains more than two device group members to the BIG-IP DNS configuration and enable the Virtual Server Discovery feature, the DNS system may not discover all virtual server objects defined in the Sync-Failover device group of the BIG-IP systems. Starting in BIG-IP DNS 13.0.0, you can add BIG-IP server objects that contain more than two device group members to the BIG-IP DNS configuration, and the Virtual Server Discovery feature discovers all virtual servers defined in the Sync-Failover device group of the BIG-IP systems.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You can access the Configuration utility or TMOS Shell (tmsh).
  • You have configured the following objects on the BIG-IP DNS system:
    • One or more Data Center objects
    • A server object to represent the BIG-IP DNS system

Note: If you are using third-party device certificates for your BIG-IP devices, you may want to refer to K7717: BIG-IP DNS and Link Controller support for third-party SSL device certificates for the requirements on device certificates. Additionally, for information about the deprecation of clientAuth EKU for public certificates generated by Public Key Infrastructure (PKI) certificate authorities (CA) and what you can do to prepare, you may want to refer to the F5 DevCentral article: The End of ClientAuth EKU…Oh Mercy…What to do?.

Procedures

Add BIG-IP server objects to the BIG-IP DNS configuration

When you define the BIG-IP LTM system as a BIG-IP DNS server object, you configure settings that the BIG-IP DNS systems use to communicate with the BIG-IP LTM system. For example, when defining the BIG-IP LTM server object, you must specify one or more self IP addresses for the BIG-IP LTM system; doing so allows the DNS sync group members to establish an iQuery session with the BIG-IP LTM device.

When defining multiple BIG-IP LTM devices that reside in a Sync-Failover device group, define one device per BIG-IP LTM device. You should not use one device name to represent the whole group and add all external self IP addresses in it.

devices {
    device1 {
        addresses {
            10.11.16.34 { }
        }
    }
    device2 {
        addresses {
            10.11.16.37 { }
        }
    }
    device3 {
        addresses {
            10.11.16.43 { }
        }
    }
}

To define the BIG-IP LTM system, perform one of the following procedures:

Use the Configuration utility to add BIG-IP server objects to the DNS configuration

  1. Log in to the Configuration utility.
  2. Go to DNS > GSLB > Servers > Server List.
  3. Select Create.
  4. Enter a name for the server object.
  5. For Product, select BIG-IP System.
  6. For Data Center, select the appropriate data center.
  7. For Prober Preference, select the appropriate prober types.
  8. For BIG-IP System Devices, select Add to create a device (server) and perform the following actions:
    1. Enter a Device Name.
    2. For Address, enter an external (public) IP address.
    3. Optionally: If you use network address translation (NAT), for Translation, enter an internal (private) IP address and select Add.
    4. Select Add.
    5. Select OK.
  9. Repeat step 8 for each device group member in the Sync-Failover device group.
  10. For Health Monitors, in the Available list, select the bigip monitor and move it to the Selected list.
  11. For Virtual Server Discovery, select Enabled or Enabled (No Delete).

    Note: If you select the Enabled (No Delete) setting, the BIG-IP GTM system automatically adds and modifies virtual server settings in the configuration but does not delete them if they are removed from the BIG-IP system. This option is useful when you regularly take virtual servers in and out of service.

  12. For Link Discovery, select how you want link objects to be added to the system. For example, select Enabled if you want the system to automatically add and delete links.
  13. Complete the remaining configuration sections.
  14. Select Finished.

Use tmsh to add BIG-IP server objects to the DNS configuration

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create the server object by using the following command syntax:

    create /gtm server <server_name> devices add { <BIG-IP_name> { addresses add { <self_IP> } } } datacenter <datacenter_name>

    For example, the following command creates a server object named My_Server in the My_DC data center that contains a BIG-IP device named BIGIP_1:

    create /gtm server My_Server devices add { BIGIP_1 { addresses add { 10.10.1.1 } } } datacenter My_DC

  3. Save the configuration by entering the following command:

    save /sys config

Run the bigip_add script

The bigip_add script exchanges Secure Sockets Layer (SSL) certificates with the remote BIG-IP LTM system. The bigip_add script appends the local BIG-IP DNS system's SSL certificate to the remote BIG-IP LTM system's list of authorized certificates (located in the /config/big3d/client.crt file). The script then appends the remote BIG-IP system's iQuery SSL certificate to the BIG-IP DNS system's local list of authenticated iQuery SSL certificates (located in the /config/gtm/server.crt file).

Note: You should only need to run the bigip_add script on one of the BIG-IP DNS sync group members. The remaining sync group members then attempt to connect to the big3d agent on the BIG-IP LTM system and copy their certificates to the BIG-IP LTM system. If other sync group members cannot connect to the BIG-IP LTM system's big3d agent, the BIG-IP DNS system in which you ran the bigip_add script relays the certificates from the other BIG-IP DNS sync group members to the newly added BIG-IP LTM system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP DNS command line as the root user.
  2. Use the following command syntax:

    bigip_add <BIG-IP_LTM_IP_address>

  3. Repeat step 2 for each device group member in the BIG-IP LTM Sync-Failover device group.
  4. (Optional) You can check iQuery connection status using the following command:

    tmsh show gtm iquery

After running the bigip_add script, all DNS sync group members should be able to establish iQuery connections to the BIG-IP LTM system.
