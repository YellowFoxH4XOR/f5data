Topic

This article discusses the different device group synchronization statuses and device states displayed in the various command lines, Advanced Shell (bash) and TMOS Shell (tmsh).

Note: This article does not cover all device group statuses and device states; it provides a general overview and is not intended to be an extensive troubleshooting document.

Description

The BIG-IP and BIG-IQ systems have various command lines, such as the bash and the tmsh utilities. You can use these command line utilities for configuring objects, monitoring, and troubleshooting the systems. Similar to the Configuration utility, they provide the state of the system (such as active or offline) and the synchronization status of the device group to which the system belongs. The various prompt files residing in the /var/prompt directory read the state and status displayed in these command lines. The promptstatusd process from various sources, such as the mcpd process, collate these files.

Note: If you have determined that the promptstatusd process is unresponsive, you can restart the process by typing the following command in the bash utility:

kill -9 $(pidof promptstatusd)

A typical bash prompt has the following format:

[<login user>@<device hostname>:<device state>:<device group sync status>]

For example:

[root@mybigip:Active:In Sync]

A typical tmsh utility prompt has the following format:

<login user>@(<device hostname>)(cfg-sync <device group sync status>)(<device state>)

For example:

root@(mybigip)(cfg-sync In Sync)(Active)

The following table includes some of the more commonly encountered device group synchronization statuses, as well as their respective descriptions and recommendations.

Note: This table does not list all statuses of a device group and it does not cover all possible scenarios that put the device group in that status.

Device group synchronization statusDescriptionRecommendation
StandaloneThe device is a standalone device and is the only member of the local trust domain.None
Awaiting Initial SyncOne or more devices has been added to the device group and is awaiting either to sync its configuration to the device group or receive configuration from the device group.Sync the device with the most current configuration to the device group. For more information, refer to K13920: Performing a ConfigSync using the Configuration utility.
SyncingThe device group is undergoing a configuration synchronization operation.None
In SyncAll devices in the device group have the most current configuration.None
Changes PendingOne or more devices in the device group has its configuration changed and has yet to synchronize its configuration to other members of the device group.Sync the device with the most current configuration to the device group. For more information, refer to K13920: Performing a ConfigSync using the Configuration utility.
Not All Devices SyncedOne or more devices in the device group does not have the current configuration from the device group.Sync the device with the most current configuration to the device group. For more information, refer to K13920: Performing a ConfigSync using the Configuration utility.
UnknownThe status of the device group cannot be determined. It is possible that:
  • The trust relationships between devices are not properly established.
  • The local device is not a member of the selected device group.
  • You are not logged in to the primary cluster member.
Refer to the troubleshooting steps described in K13946: Troubleshooting ConfigSync and device service clustering issues (11.x - 13.x)
DisconnectedThe iQuery communication channel between the devices was terminated or disrupted. This may be a result of one of the following:
  • The disconnected device is not a member of the local trust domain.
  • The disconnected device does not have network access to one or more device group members.
Refer to the troubleshooting steps described in K13946: Troubleshooting ConfigSync and device service clustering issues (11.x - 13.x)

The following table includes some of the more commonly encountered device states, as well as their respective descriptions and recommendations.

Note: This table does not list all states of a device and it does not cover all possible scenarios that put the device in that state.

Device stateDescriptionRecommendation
ActiveIf the device is a standalone, the device is operational and running.

If the device is configured as part of a device group, it is the currently active device.

None
StandbyThe device is currently the standby device in a device group. None
INOPERATIVEThe device is not in a functional state and needs further investigation to determine the cause.Review the /var/log/ltm file on the affected device to determine the possible cause.
LICENSE INVALIDThe license on the device is invalid.Verify the license using K9245: Verifying that a BIG-IP license is valid. Additionally, you can review the /var/log/ltm file on the affected device to determine the license issue and reactivate the license as needed. For information about reactivating the license, refer to the following articles appropriate for your device:
  • K7752: Licensing the BIG-IP system
  • K15094: Licensing the BIG-IQ system
NO LICENSEThere is no license activated on the device.Obtain the appropriate license for your device and activate the license as needed. For information about reactivating the license, refer to the following articles appropriate for your device:
  • K7752: Licensing the BIG-IP system
  • K15094: Licensing the BIG-IQ system
Module Not LicensedAn unlicensed module was provisioned on the device.Unprovision the module if not needed.
<process> DOWNThe <process> on the device is not running as expected. For example, avrd DOWN means the BIG-IP Analytics process is not running as expected.Review the appropriate log file for the affected process and restart it using the command syntax:

bigstart restart <process>

OfflineThe device is in an Offline state and does not process traffic.

For BIG-IP ASM devices, the BIG-IP ASM device goes offline when the BIG-IP ASM bd process has stopped running. For more information, refer to K13484: Disabling the BIG-IP ASM system marks the system offline.

Review the appropriate log file(s) as needed to determine the potential cause(s) if this state is unexpected.
Forced OfflineThe device has been put into the Forced Offline state and does not process traffic.Release the device from the Forced Offline state when you are ready to put the device back into operation.
Peer Time Out of SyncThe date/time between the devices in the device group may not be in sync or the device(s) has lost communication with the configured NTP server(s).Verify the date/time between the devices in the device group and adjust as appropriate. For more information, refer to K3381: Setting the time and date on the BIG-IP system.

If the date/time between the devices in the device group are in sync, verify the network connectivity to the configured NTP server(s). For more information, refer to K10240: Verifying NTP peer server communications.
