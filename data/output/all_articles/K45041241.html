Description

In this configuration, one pool member will take all the traffic until it is marked offline, at that time the secondary pool member will begin to process traffic. 

Environment

  • BIG-IP LTM
  • Pools
  • Priority Groups

Cause

N/A

Recommended Actions

  1. Create the pool
  2. Select the desired Load Balancing Method. For information about the various load balancing methods, refer to the following articles:
    • K02024845: BIG-IP LTM load balancing | BIG-IP LTM-DNS operations guide
    • K42275060: There are several Load Balancing Methods. Which one is best for your environment?
  3. Change the 'Priority Group Activation' drop down to 'Less than' and configure a minimum value of at least 1. A Value of 0 will not work.
  4. When adding the pool members, define the desired priority. The higher priority value will take precedence over the lower value. 

Additional Information

Here is an example of what the config would look like. The 10.0.0.45 pool member will take the traffic as it has the higher priority value. When this pool member fails, or is marked offline, the 10.0.0.46 pool member will begin to take the traffic, until the 10.0.0.45 comes back online.

ltm pool Priority_Group_Pool {
    members {
        10.0.0.45:http {
            address 10.0.0.45
            priority-group 20
            session monitor-enabled
            state up
        }
        10.0.0.46:http {
            address 10.0.0.46
            priority-group 10
            session monitor-enabled
            state up
        }
    }
    min-active-members 1
    monitor http
}
