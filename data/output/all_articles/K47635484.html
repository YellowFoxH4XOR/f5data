Known Issue

The BIG-IP system may fail to boot when syslog-ng is not running.

This issue occurs when all of the following conditions are met:

  • You are running BIG-IP 11.5.4 with HF2 or later installed (or are running one of the other versions listed in Applies to (see versions) box, located in the upper-right corner of this article).
  • During the BIG-IP system boot process, the syslog-ng process fails to start properly.

For example, if you insert a VIPRION blade into a different slot than the one in which it last ran, the BIG-IP system may detect that it needs to install software to the selected boot location and automatically perform the installation. When this issue occurs, the syslog-ng.conf file is not written correctly during the installation process. This prevents the syslog-ng daemon from starting properly and causes the BIG-IP system to fail to respond during the boot process.

Impact

The BIG-IP system fails to respond during the boot process.  The relocated blade fails to properly join the cluster.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The VIPRION blade goes offline during the boot process.
  • The BIG-IP system fails to respond and displays the following message when you attempt to start the httpd process:

    Starting httpd:

Workaround

To work around this issue, you can correct any errors in the syslog-ng.conf file and restart the syslog-ng daemon. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced shell (bash).
  2. To back up the /etc/syslog-ng/syslog-ng.conf file, type the following command:

    cp /etc/syslog-ng/syslog-ng.conf /etc/syslog-ng/syslog-ng.conf.K47635484

  3. Use a text editor to open the /etc/syslog-ng/syslog-ng.conf file for editing.
  4. Correct any errors in the configuration file. For example, you may need to correct the IP address in the following code:

    source s_cluster {
       udp(ip(127.3.0.4) port(514));
    };

  5. Save the changes and exit the editor.
  6. To restart the syslog-ng daemon, type the following command:

    bigstart restart syslog-ng
