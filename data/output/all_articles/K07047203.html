Description

With large config SNMP response times may be long due to processing burden of requests

  • snmpd improvement is needed to process requests to large tables in a more efficient way
  • Slow responses/timouts to snmp queries
  • Increased mcpd CPU utilization

Environment

  • Large config (1000+ pools, pool members or virtual servers)
  • SNMP queries that result in processing the entire table of pools, pool members, or virtual servers

Cause

With large config SNMP response times may be long due inefficient processing requests.  This issue is tracked with F5 bug ID 801525.

Recommended Actions

The only current mitigation is to reduce the volume of GetBulk and SNMP queries to large tables (typically, pool-member related queries).
