K000160887: AFM event log shows the "PPS" value as per-TMM value for DoS vector - TCP half open.

Type
Support Solution
Published
2026-04-20
Updated
2026-04-24
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160887

Description

When the AFM DoS protection mitigates the TCP half open vector, in the AFM evet log (GUI) you will see the PPS value as per-TMM based value.

  • The displayed PPS value could mislead you to think the mitigation threshold is not yet reached.
  • AFM event log shows increment in the "drops" while the PPS can be lower than the configured mitigation threshold.

Environment

  • Product: BIG-IP AFM
  • Virtual server context - AFM DoS profile applied on virtual server.

Cause

The AFM DoS event log (GUI) may show a PPS that is lower than the configured value while the mitigation (drops count) increases, this is due to the GUI layout and this AFM TCP half open DoS vector works differently as other DoS vectors, hence the displayed value is different.

 

Answer/Recommended Actions

The AFM TCP half open vector is different from other vectors, the mitigation is done on each TMM, so when you configured a mitigation threshold 1000, while you have 4 TMMs, each TMM mitigates the TCP half open vector when the PPS exceeds 250, thus you may see a PPS of 251 showing in the GUI AFM event log when the mitigation started.
