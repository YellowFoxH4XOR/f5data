Topic

The ipsec.if.checkpolicy database key is introduced in BIG-IP 12.0.0 and is enabled by default. If you disable it, an IPsec tunnel in interface mode ignores any policy check against the associated traffic selector. This situation allows you to associate an arbitrary traffic selector with an IPsec tunnel interface without the IPsec packet handling logic dropping any packets.

Description

Interface mode always requires a traffic selector. The IPsec tunnel interface enforces the traffic-selector policy on its internal traffic. That is, the source and destination addresses of the packet going through the tunnel must comply with the traffic selector that is associated with the tunnel; otherwise, the packet will be dropped. Sometimes such policy enforcement is too restrictive and it is necessary to use an IPsec tunnel interface as a secure transport for disparate private networks or dynamic routing . You can accomplish this by disabling policy checking with the ipsec.if.checkpolicy database key.

Note: There is no implicit 0.0.0.0/0 “allow all traffic” traffic selector applied by default. A traffic selector is always required, including when you configure routes using the tunnel interface for a route-based Virtual Private Network (VPN). 

There are two common use cases for disabling the ipsec.if.checkpolicy database key:

  • When implementations use dynamic routing over IPsec tunnels.
  • When non-consecutive private networks are required over an IPsec interface mode tunnel. The IPsec interface mode is currently limited to one traffic selector per interface.

To be clear: The database key has no influence on IPsec tunnels in "tunnel mode" (sometimes called "policy mode"). Interface or tunnel mode is a part of the ipsec-policy configuration.

Recommendations

To configure the ipsec.if.checkpolicy database key, perform the following procedure:

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Specify a new value for the database key using the following command syntax:

    modify /sys db ipsec.if.checkpolicy value <enable|disable>

    For example:

    modify /sys db ipsec.if.checkpolicy value enable
