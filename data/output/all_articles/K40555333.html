Description
In the BIG-IP Configuration Utility, the SSL Certificate List page, found by navigating to System > File Management : SSL Certificate List, can hang and show only a blank page whereas there should be a listing of certificates. This issue may seem to affect multiple users on the same device or DSC cluster. This problem does not affect the ability to manage certificates and keys via other methods such as tmsh, BIG-IQ, REST API, or AS3.

Environment

  • BIG-IP
  • SSL Certificate / Key Management
  • Single device or DSC cluster
  • Managed using Configuration Utility

Cause

An incongruity between certificate or key file objects in TMOS and the actual contents of the filestore on disk may cause a problem with list generation in the Configuration Utility. For example, a certificate file and key file on disk may have been aberrantly deleted, and now the tmos object points to a non-existent resource.

In the /var/log/tomcat/catalina.out file, you may see errors messages like such, when visiting the broken page:
"ERROR [TP-Processor2] ssl_005fcertificate.import_jsp:_jspService     - Exception caught in Management::urn:iControl:Management/KeyCertificate::get_certificate_list_v2"

Recommended Actions
We do not recommend manually manipulating files in the BIG-IP filestore. If disk corruption is suspected, consider running a file system check.

Consider restoring the device from an archive taken prior to the start of the issue. If this is not possible or not feasible, the recommendation is to identify which object/file is incongruous and remove the invalid object(s). Unfortunately the error message does not identify which object(s) are the cause, so in order to identify them you may use the following process:

  1. Enter the Advanced Shell (bash mode) by running the following command:
    run /util bash

  2. Generate a listing of certificate / key files in the filestore, by performing the following commands:
    ls -lR /config/filestore/files_d/*/certificate_d > /var/tmp/filestore_cert_list.txt
    ls -lR /config/filestore/files_d/*/certificate_key_d/ > /var/tmp/filestore_key_list.txt

  3. Generate a listing of certificate / key files in tmos, by performing the following commands:
    guishell -c 'select name,cache_path,system_path from certificate_file_object' > /var/tmp/cert_file.txt
    guishell -c 'select name,cache_path,system_path from certificate_key_file_object' > /var/tmp/key_file.txt

  4. Assemble the data into a format which can be manipulated using the following commands:
    cat /var/tmp/cert_file.txt | awk -F \| '{print $3}' | awk -F \: '{print ":"$2":"$3}' | sort -u > /var/tmp/cert_file_sort.txt
    cat /var/tmp/key_file.txt | awk -F \| '{print $3}' | awk -F \: '{print ":"$2":"$3}' | sort -u > /var/tmp/key_file_sort.txt
    cat /var/tmp/filestore_cert_list.txt | awk '{print $9" "}' | sort  -u > /var/tmp/filestore_cert_sort.txt
    cat /var/tmp/filestore_key_list.txt | awk '{print $9" "}' | sort -u > /var/tmp/filestore_key_sort.txt

  5. Create a comparison report for objects that exist in tmos but not in the filestore by paying special attention to the lines that begin with left angle bracket '<' signifying that tmos expects this file but the filestore does not contain it.
    diff /var/tmp/cert_file_sort.txt /var/tmp/filestore_cert_sort.txt
    diff /var/tmp/key_file_sort.txt /var/tmp/filestore_key_sort.txt

  6. Fix the tmos reference by either deleting the object which references the missing filestore file, or by manually replacing the file back into the proper location in the filestore if available:
    tmsh delete sys crypto cert <objectname>
    tmsh delete sys crypto key <objectname>
