Known Issue

Note: Beginning in BIG-IP version 10.2.0, when you boot the BIG-IP system from a USB removable media, the system automatically displays a manufacturing installation dialog. For more information, refer to K11686: Change in Behavior: When the BIG-IP system is booted from a USB removable media, a manufacturing installation dialog is automatically displayed.

This is the result of a known issue. After booting the BIG-IP system from a USB removable device, exiting the manufacturing installation dialog will cause any ensuing software installations to fail.

For example:

  • You have booted a BIG-IP system from a USB thumb drive containing the version 10.2.0 software installation image. The BIG-IP system displays a manufacturing installation dialog that appears similar to the following example:

    info: Using repository; /cdserver
    info: manufacturing plan for C106:
    info:  --- boot volume set is HD1.1
    info:  --- HD1.1 => BIG-IP 10.2.0 LTM.ROS.SAM.TS.WA.WOC
    info:  --- HD1.2 => BIG-IP 10.2.0 LTM.ROS.SAM.TS.WA.WOC
    This is the manufacturing installation!
    If you want to retain ANY data present on this system, do not continue.
    Use <ctrl-c> to enter a Bash shell.
    Press [Enter] to begin installation.
  • You press Ctrl+C to exit the manufacturing installation dialog and access the bash shell:

    Press [Enter] to begin installation. <------ Ctrl+C is pressed
    bash (try 'info') / >
  • You type start and press Enter to display the manufacturing installation dialog again.
  • You press Enter to begin the manufacturing installation.
  • The installation terminates abruptly and returns an error message that appears similar to the following example:

    error: sfdisk failed; bc_ratio=504, total_KiB=8257032, total_cyl=16383
    Can't save log permanently; no boot volume available.
    Log saved to /tmp/install.log

This issue occurs because the manufacturing installation dialog mounts the boot partition in order to inspect it. When you press Ctrl+C to exit the manufacturing installation dialog, the boot partition remains mounted. This behavior causes any ensuing installations to fail.

Note: The same issue also occurs if you attempt to perform a custom installation of BIG-IP version 10.x from the bash shell instead of using the manufacturing installation dialog.

Note: If for some reason the manufacturing installation dialog cannot mount the boot partition, then this issue does not occur. For example, if the mass-storage devices in the BIG-IP system have already been wiped, then this issue does not occur.

F5 Product Development is tracked this issue as ID 225020 (formerly CR138343) and it was fixed in BIG-IP versions 10.2.4 and 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Note: The above ID also tracks other failure scenarios which are slightly different from the one discussed in this article. For example, terminating the installer process mid-install may also leave the boot partition mounted and cause any ensuing software installations to fail.

Workaround

You can work around this issue by manually unmounting the boot partition before performing a software installation. To do so, perform the following procedure:

  1. After you have quit the manufacturing installation dialog, run the df command to inspect the mounted filesystems and determine the device name for the boot partition.

    For example:

    bash (try 'info') / > df
    Filesystem           1K-blocks      Used Available Use% Mounted on
    /dev/scd0               799914    799914         0 100% /cdserver
    /dev/hda1               110142     70186     39956  64% /mnt/tm_install/1689.rNoPG8
  2. Unmount the boot partition by running the following command:

    umount <device name>

    For example:

    umount /dev/hda1
  3. You can now install BIG-IP version 10.x by using the diskinit and image2disk utilities or by starting the manufacturing installation dialog again.
