K000160708: BIG IQ CM GUI is not coming up - restjavad down, waiting for tokumon.js to begin

Type
Support Solution
Published
2026-04-10
Updated
2026-04-10
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.0
Source
https://my.f5.com/manage/s/article/K000160708

Description

On BIG-IQ CM, the Configuration Manager (CM) GUI may become unavailable, displaying the message "Waiting for BIG-IQ services to become available." This issue is characterized by:

  • The restjavad service is down and waiting for tokumon.js to begin.
  • The tokumond service is down for an extended period, when it is normally expected to be running.
  • Disk space on /var and /var/log is currently not an issue, but it was prior the issue occured.
  • /var/log/tokumon/current contains: [{"type":"cluster_block_exception","reason":"blocked by: [FORBIDDEN/12/index read-only / allow delete (api)];"}],"type":"cluster_block_exception","reason":"blocked by: [FORBIDDEN/12/index read-only / allow delete (api)];"},"status":403}',

Environment

  • Product: BIG-IQ
  • Standalone Active configuration (not HA)
  • Key services involved: tokumond, restjavad, elasticsearch (searchd)
  • Disk usage: /var and /var/log was full and has been cleaned up

Cause

The root cause of the issue was that the searchd (Elasticsearch) service entered read-only mode due to a disk space event, and this persisted even after space was freed. 

Answer/Recommended Actions

To resolve the issue and restore the BIG-IQ GUI, follow these steps:

  1. Check tokumond logs for root cause:
    tail -100 /var/log/tokumon/current
    Look for errors indicating why tokumond is down and related to searchd - port 9210.

  1. Remove the read-only flag from searchd, by running the following script:
    for idx in $(curl -ks http://localhost:9210/_cat/indices | awk '{print $3}'); do if [ $idx != ".opendistro_security" ]; then curl -k -u admin:admin -X PUT "http://localhost:9100/$(echo $(echo $idx | cut -d\+ -f1)*)/_settings?pretty" -H 'Content-Type: application/json' -d'{"index.blocks.read_only_allow_delete": false}'; fi; done

           From CLI level execute a command: reboot
