Description

DNS service may show random failure with symptoms below:

  • Dig test fails with below output:

#  dig +norec +dnssec  soa www.test.com @192.168.200.1
;; Truncated, retrying in TCP mode.
;; communications error to 192.168.200.1#53: connection reset

  • Warning messages observed in /var/log/daemon.log:

    Jun  9 17:27:55 DNS1 warning named[<PID>]: 09-Jun-2022 17:27:55.272 client: warning: client @0x5cfc07b8 (no-peer): TCP client quota reached: quota reached

Environment

  • BIG-IP DNS
  • Named
  • BIND

Cause

The DNS response is too large and retrying with TCP mode, but fails to get DNS response due to "the max simultaneous client TCP connections" has reached limit of bind DNS server.

Recommended Actions

  1. Reduce the idle-timeout setting of the TCP profile for the DNS server, the default setting is 300s, it is too long and hold many idle connections.
  2. Increase, or define tcp-clients in your named.conf file:

named.conf
 options {
...(SNIP)...
      tcp-clients <NUMBER_OF_MAX_CLIENT>;
};
