Description


This article helps to determine if the sync failure is due to ID 1136081 or a general sync failure
 

Environment

  • BIG-IP FIPS
  • BIG-IP HA
  • Hardware replacement (RMA)

Cause

Bug ID 1136081: HSM sync issue in high availability (HA) setups
 

Recommended Actions

 

FIPS HSM sync issues in HA setups may occur due to changes in the FIPS HSM internal configuration (specifically the KeyExport setting) introduced by previous software updates. 

If the KeyExport status is not consistent between HA peers or if the RMA device is initialized on a different version of TMOS, synchronization will fail. 

 

The change of enabled to disabled for the FIPS KeyExport state was introduced in BugID 1023341, described in K000135551: Resolving FIPS HSM sync failures.

The sync issues resulted from syncing devices with or without the change is tracked on Bug ID 1136081 

The KeyExport status will only change when FIPS is initialized; it doesn't change automatically during an upgrade. 

Note: No command exist to identify the version of TMOS FIPS was initialized on. 

 

To identify if the sync failure is due to ID 1136081  follow either of the below recommendations: 

 

  • The best method is to check the KeyExport status using the n3fipsutil utility, which is available for download on myf5.com.
    The n3fipsutil -exportKeyCheck command can be used to check the KeyExport status (enabled/disabled), but it does not reveal the TMOS version used for FIPS initialization.

    Note: You may encounter the error "KeyExport : Unknown" when checking export status.

The error "KeyExport : Unknown" from n3fipsutil -exportKeyCheck occurs if no keys are present in the HSM. Creating a FIPS key will resolve the Unknown status.
# tmsh create sys crypto key test security-type fips

 

  • There is no clear log message that directly indicates BugID 1136081. However, enabling f5km debug and reviewing /var/log/daemon.log can reveal f5km_key_import returning -18 (HSM vendor error), which is symptomatic of this bug and indicates HSM domain mismatch.

Enable debug:
# tmsh modify sys syslog daemon-from debug

Disable debug
# tmsh modify sys syslog daemon-from notice

 

Additional Information

The license file (/config/bigip.license) can show when the device was first licensed and on what version, but this does not confirm the FIPS initialization version.
