Known Issue

If you create a UCS file using the bigpipe config save command from the command line rather than from the Configuration utility, the system does not restore access policy customizations from the UCS file. The customizations that are not restored are the parameters that an administrator defines within an Action box. This issue occurs because the permissions on the UCS file prevent the BIG-IP APM from correctly loading the file. The system uses the default customizations instead of the customizations that you configured before creating the UCS file. As a result, access policies that use administrator-defined parameters fail to run and users may be unable to access resources appropriately.

This issue occurs when the following conditions are met:

  • You created the UCS file from the command line using the command: bigpipe config save.
  • The BIG-IP APM system does not have the access policy customizations before doing a restore. This might happen, for example, when restoring the configuration to a new system, or when restoring the configuration to an existing system after you have created a UCS file and deleted the customizations.

Impact

This issue may cause authentication and resource assignment failures with configurations that use access policies.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Users may experience authentication failures.
  • Users may experience resource assignment failures.
  • Access policies may fail unexpectedly.
  • Visual inspection of access policies show that previously-configured customizations are gone.

Workaround

To work around this issue, you can use the Configuration utility to generate the UCS file. To do so, perform the Backing up configuration data using the Configuration utility procedure from K11318: Backing up and restoring BIG-IP version 10.x configuration files.
