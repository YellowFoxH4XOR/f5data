Known Issue

The BIG-IP ASM system may erroneously reset connections identified by the Brute Force Attack Prevention feature while the security policy is in transparent mode.

This issue occurs when all of the following conditions are met:

  • The affected security policy is configured with aggressive thresholds for the Brute Force Attack Prevention feature.
  • The Operation Mode setting of the Brute Force Attack Prevention feature is configured with alarm and block mode.
  • The Enforcement Mode setting of the affected security policy is set to transparent mode.
  • The BIG-IP ASM system detects the connections as a brute force attack based on the aggressive thresholds configured for the feature.

Impact

Affected traffic is unexpectedly disrupted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP ASM system appears to reset traffic unexpectedly.
  • If you configured the system to log TCP RST packets, the system logs the following message to the /var/log/ltm file:

    Internal error (ASM requested abort (plugin abort error))

    Note: For information about configuring the system to log TCP RST packets, refer to K13223: Configuring the BIG-IP system to log TCP RST packets.

Workaround

To work around this issue, you can modify the Operation Mode setting of the Brute Force Attack Prevention feature to alarm mode only, while the Enforcement Mode setting of the security policy is in transparent mode. However, you must change the Operation Mode setting back to alarm and block mode when you change the Enforcement Mode setting of the security policy to blocking, if you intend to have the system prevent brute force attacks. To modify the Operation Mode setting, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Anomaly Detection > Brute Force Attack Prevention.
  3. Select the desired policy from the Current edited policy setting.
  4. Click on the name of the desired login URL from the Login URLs table.
  5. For the Operation Mode setting, select Alarm.
  6. To save the change, click Save.
  7. To activate the change in the security policy, click Apply Policy.
  8. When prompted to confirm the activation, click OK.
