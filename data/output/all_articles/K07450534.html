Known Issue

Monitor logging fails for pool members you created using iApp.

This issue occurs when all of the following conditions are met:

  • You enable the Monitor Logging option for a pool member.
  • You created the pool using an iApp application service with Strict Updates disabled.

Impact

The system fails to create the member-specific monitor logging file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system does not perform member-specific logging after you enable the Monitor Logging option for the pool member.
  • In the /var/log/ltm file, the system logs messages similar to the following example:

    info bigd[6700]: Couldn't open logging file for monitor /Common/http_app.app/http_app_http_monitor on node /Common/192.168.0.11.

Workaround

To work around this issue, you can temporarily enable debug logging for the bigd process that is responsible for managing BIG-IP health monitor instances.

Impact of workaround: Debug logging for the bigd process is verbose; it logs multiple messages for every monitor attempt. Use caution when you enable debug logging on an active system that has many monitors configured, especially one in production. Logging for extended periods of time under such conditions may result in disk exhaustion and failover. Bigd log files are not rotated.

You can enable or disable debug logging for the bigd process from the BIG-IP command line or from within the Traffic Management Shell (tmsh).

  • To enable debug logging for the bigd process, type the following command:

    tmsh modify sys db bigd.debug value enable

  • To disable debug logging for the bigd process, type the following command:

    tmsh modify sys db bigd.debug value disable

  • To permanently save the changes to persist through a restart, type the following command:

    tmsh save sys config

The bigd process logs its messages to the /var/log/bigdlog file.
