Description

Bot defense request logs are only visible for a short period of time.

Additionally, messages like the following can be seen in /var/log/ts/asmlogd.log:

Dropping protobuf file /var/asmdata1/request_log/0000080571
289118948 Bot Defense records handled since startup (last Bot Defense support id handled = 8927839959374328613, skipped 78634542 Bot Defense requests due to rate limit)

Environment

  • Bot defense
  • Local logging

Cause

Bot defense logs are rotated out very quickly when the rate of request logging is very high.

Recommended Actions

Reduce the rate of excessive bot defense logging. You may need to review the most-used security log profiles and which options they have enabled under Bot Defense.

Additional Information

Bot defense entries are limited to 100000 rows/entries, this is defined in /etc/ts/tools/asmlogd_clean_db.yaml:

tables:
  PRX.REQUEST_LOG:
    row_limit: 3000000
  PRX.REQUEST_LOG_SYNC_FILES:
    row_limit: 1000
  PRX.BRUTE_FORCE_ATTACK_LOG:
    row_limit: 20000
  PRX.BRUTE_FORCE_LOGIN_PAGE_STATUS:
    row_limit: 20000
  PRX.BOT_DEFENSE_EVENT_LOG:
    row_limit: 100000               <------

Compare this to ASM request logs, where 30 times as many logs are allowed by default.

Request logs are written to the disk and mysql database by the asmlogd daemon. This process is limited to 1500 requests per 5 seconds by default, as defined in /etc/ts/tools/asmlogd.cfg:

local_insert_rate_limit_count=1500
local_insert_rate_limit_interval=5
local_insert_bot_defense_rate_limit_count=1500        <------
local_insert_bot_defense_rate_limit_interval=5

The asmlogd process periodically logs the number requests have been rate limited since the process started, to /var/log/ts/asmlogd.log.

In the example below, 78 million bot defense logs have been rate limited:

289118948 Bot Defense records handled since startup (last Bot Defense support id handled = 8927839959374328613, skipped 78634542 Bot Defense requests due to rate limit)

Note: It is not recommended to increase the PRX.BOT_DEFENSE_EVENT_LOG row limit, or increase the value of local_insert_bot_defense_rate_limit_count. This may result in significant performance issues.

For extensive logging needs, we recommend logging remotely.
