K000163183: SAML POST Auth Response to APM SP fails with 'Invalid request received from remote client'

Type
Support Solution
Published
2026-09-03
Updated
2026-09-03
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163183

Description

POST SAML Auth Response sent by SAML IdP to APM SAML SP is not parsed by APM.

In the apm log file, you can see an error similar to this, with X the HTTP Content-Length header of the incoming HTTP Request:

err apmd[16253]: 01490092:3: 00000000: Invalid request received from remote client. content-length from header: X

That error means APM rejected an incoming HTTP Request because its content-length was greater than the allowed value (by default 64000 bytes).

In a tcpdump, you can see an "HTTP/1.0 500 Error" response after sending the POST SAML Auth Resp to APM.

Environment

APM deployed as SAML SP

Cause

APM has defined 64000 bytes as Maximum Content-Length value for incoming HTTP Requests.

If the SAML Assertion includes lots of Groups, probably it will exceed 64000 bytes and APM will reject the HTTP POST Request that includes the "SAMLResponse", with the SAML Assertion, in the body.

Recommended Actions

Check in apm log files which is the maximum content-length rejected by APM, filtering with "Invalid request received from remote client. content-length from header":

grep "Invalid request received from remote client. content-length from header" apm*

Set db variable "tmm.access.maxrequestbodysize" with a value greater than the maximum content-length rejected.

For example, if maximum content-length rejected is 75000 bytes:

err apmd[16253]: 01490092:3: 00000000: Invalid request received from remote client. content-length from header: 75000

you can set db value to 100000 bytes:

tmsh modify sys db tmm.access.maxrequestbodysize value 100000

tmsh save sys config
