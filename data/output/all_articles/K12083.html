K12083: The HTTP::Header sanitize iRule command may cause TMM to become unresponsive

Known Issue

This is the result of a known issue. You can use the HTTP::header sanitize iRule command to remove headers from HTTP requests. Certain HTTP traffic patterns may cause TMM to become unresponsive if the virtual server references an iRule that contains the HTTP::header sanitize command.

For example, the following iRule uses the HTTP::header sanitize command:

when HTTP_REQUEST {
if { [HTTP::uri] contains "error.html" } {
HTTP::header sanitize "Host"
}
}

F5 Product Development tracked this issue as ID 339379 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by removing the HTTP::header sanitize statement from the iRule.
