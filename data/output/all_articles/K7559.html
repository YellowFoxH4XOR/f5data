Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following articles:

  • K70025261: Overview of the TCP profile (12.x)
  • K13924148: Overview of the TCP profile (11.x)

The TCP profile allows an administrator to specify how a BIG-IP virtual server processes TCP traffic. You can use the TCP profile alone, to manage traffic, or in conjunction with other profiles, such as the HTTP profile for processing Layer 7 (L7) traffic, or the SSL profile for processing SSL traffic.

The TCP profile is located in the Configuration utility, under Local Traffic > Profiles > Protocol > TCP.

Note: F5 recommends that you create a custom TCP profile instead of modifying the default TCP profile. Creating a custom TCP profile allows you to associate a custom profile, which contains specific settings, with individual or groups of virtual servers.

Settings and definitions in the TCP profile

SettingDefault ValueDescription
Reset on TimeoutEnabledThe system sends a reset (RST) and deletes the TCP connection when the connection exceeds the idle timeout value. If disabled, the system will delete the TCP connection when it exceeds the idle timeout value, but will not send an RST to the client.

Note: This setting can cause the client (if Reset on Timeout is disabled) to assume that the connection is still valid long after it has been removed from the BIG-IP LTM system.

TIME/WAIT RecycleEnabledThe system will recycle or reuse the connection when a SYN packet is received in a TIME/WAIT state. This option allows the system to better optimize system resources by reusing a connection in a TIME/WAIT state when a SYN packet is received, instead of creating a new connection.

Note: If disabled, the system will establish a new connection instead of reusing a connection that is in a TIME/WAIT state.

Delayed ACKsEnabledThis setting allows the system to send fewer than one ACK (acknowledgment) segment per data segment received. This is part of TCP congestion control that is defined in RFC 1122: Requirements for Internet Host and RFC 2581: TCP Congestion Control.

Note: F5 recommends that you keep this setting enabled as it allows the application to update the TCP window and send an immediate response if required. This setting also reduces the number of segments sent by the server.

Proxy Maximum SegmentDisabledThis setting specifies that the system advertises the same maximum segment size (MSS) to the server as that of the client.
Proxy OptionsDisabledThis setting specifies that the system advertises an option (such as time stamps) to the server only when the option is negotiated with the client.

Note: This setting allows any additional TCP options sent by the client to be proxied across to the server.

Proxy Buffer Low4096 bytesThis setting specifies the proxy buffer level (in bytes) at which the receive window is opened.

Note: Increasing the buffer size will result in more memory usage per connection. For more information, refer to K3422: Overview of content spooling.

Proxy Buffer High16384 bytesThis setting specifies the proxy buffer level, in bytes, at which the receive window is closed.

Note: Increasing the buffer size will result in more memory usage per connection. For more information, refer to K3422: Overview of content spooling.

Idle TimeoutSpecify : 300 secondsAvailable options:
  • Specify: User-specified amount of time (in seconds) that the connection can remain idle before the connection is eligible for deletion.
  • Indefinite: Specifies that the connection can remain idle indefinitely.

Note: Take caution when adjusting idle times, as each TCP connection requires resources to track and maintain. Leaving TCP connections for long periods of time uses more resources that can be better used for new connections.

Zero Window Timeout
(10.2.0 and later)		Specify : 20000 millisecondsAvailable options:
  • Specify: User-specified amount of time (in milliseconds) that the TCP connection can receive zero-length window probes before the system closes the connection.

    Note: The timeout starts when the peer advertises a zero length TCP window or when enough data has been sent to fill the previously advertised window. The timer is cancelled when a non-zero length window is received.

    Note: The BIG-IP system honors timeout values in multiples of 5000 (for example: 5000 ms, 10000 ms, and 20000 ms). This behavior accounts for the minimal time required for CPU timers and round trip time (RTT) of packets to ensure that when a zero window size update is received, the system allows the counter to start and TCP window probes are sent to query whether there is a window size change on the receiver. If you enter a value that is not a multiple of 5000, the system rounds the value up to the next multiple of 5000. For example, if a 0 is entered, the system rounds up to 5000 ms. If 7000 is entered, the system rounds up to 10000 ms.
  • Indefinite: Specifies that the system does not delete TCP connections based on zero-length window.
TIME/WAITSpecify : 2000 millisecondsAvailable options:
  • Specify: User-specified amount of time (in milliseconds) that a TCP connection remains in the TIME/WAIT state before the system closes it.
  • Immediate: Specifies that the system closes the connection immediately after the connection enters the TIME/WAIT state.
  • Indefinite: Specifies that TCP connections can remain in the TIME/WAIT state indefinitely.
FIN WAITSpecify : 5 secondsAvailable options:
  • Specify: User-specified amount of time (in seconds) that a TCP connection is in the FIN/WAIT or CLOSING state before closing.
  • Immediate: Specifies that the TCP connection closes immediately after entering the FIN/WAIT or CLOSING state.
  • Indefinite: Specifies that TCP connections in the FIN/WAIT or CLOSING state do not quit.
Note: In BIG-IP 9.x, this setting applies to TCP connections in either FIN/WAIT-1 or FIN/WAIT-2 state. However, in BIG-IP 10.x, this setting applies only to TCP connections in FIN/WAIT-1 state. TCP connections in FIN/WAIT-2 state are handled by the Idle Timeout setting.
Close WaitSpecify : 5 secondsAvailable options:
  • Specify: User-specified amount of time (in seconds) that a TCP connection remains in the LAST/ACK state before quitting.
  • Immediate: Specifies that the TCP connection closes immediately after entering the LAST/ACK state.
  • Indefinite: Specifies that TCP connections in the LAST/ACK state do not close until they meet the maximum retransmissions timeout.
Send Buffer8192 bytes (9.0.0 - 9.1.3)
32768 bytes (9.2.0 - 10.x)		This setting specifies the size (in bytes) of the SEND window.

Note: Increasing the Send Buffer size allows the BIG-IP system to output more data each time, but also increase memory usage for each connection.

Receive Window16384 bytes (9.0.0 - 9.1.3)

Note: Increasing the Receive Window size allows the BIG-IP system to receive more data each time, but also increase memory usage for each connection.

Keep-Alive Interval1800 secondsAvailable options:
  • Specify: User-specified amount of time (in seconds) that the system sends data over an idle TCP connection to determine whether the connection is still valid.
  • Indefinite: Specifies that the system does not send Keep-Alive communications.
Maximum Syn Retransmissions4 (9.0.0 - 9.3.0)
3 (9.4.0 - 10.x)		This setting specifies the maximum number of times the system resends a SYN when it does not receive a corresponding SYN/ACK.
Maximum Segment Retransmissions8This setting specifies the maximum number of times the system resends data segments.
IP ToS0This setting specifies the Layer 3 (L3) Type of Service (ToS) level that the system inserts in the TCP packets destined for clients.

Available options (10.x):
  • Specify: Specifies the IP ToS setting that the system inserts in the IP packet header. You can specify a number between 0 and 255.
  • Pass Through: Specifies that the IP ToS setting remains unchanged.
  • Mimic: Specifies that the system sets the ToS level of outgoing packets to the same ToS level of the most-recently received incoming packet. For example if the most-recently received packet had a ToS level of 3, the system sets the ToS level of the next outgoing packet to 3.
The IP ToS is part of the TCP/IP and is primarily used for ToS Application Routing, which is supported by OSPF and IS-IS. This setting allows the administrator to specify the importance and routing preference the packet should be given on a supported network. For more information regarding ToS Precedence values and a description of ToS Application Routing, refer to the following RFCs:
  • RFC 791: INTERNET PROTOCOL
  • RFC 1583: OSPF Version 2
  • RFC 2474: Definition of the Differentiated Services Field (DS Field) in the IPv4 and IPv6 Headers
Link QoS0This setting specifies the Layer 2 (L2) Quality of Service (QoS) level that the system inserts in the TCP packets destined for clients.

The Link QoS is used to specify the QoS level that the system assigns to the TCP packets when sending to a client. These values are similar to IP ToS, but are applied to the link layer or L2. For more information regarding QoS, refer to the following RFCs:
  • RFC 2474: Definition of the Differentiated Services Field (DS Field) in the IPv4 and IPv6 Headers
  • RFC 2697: A Single Rate Three Color Marker
  • RFC 2597: Assured Forwarding PHB Group
  • RFC 2598: An Expedited Forwarding PHB
Selective ACKsEnabledThis setting specifies that the system processes data using selective ACKs in order to improve system performance.

Note: F5 recommends that you do not disable this option. Selective ACKs (SACK) improves performance by explicitly listing which packets, messages, or segments in a stream are acknowledged. This lets the sender know specifically what information is missing, so that it only retransmits the missing information. SACK is detailed in RFC 2018: TCP Selective Acknowledgment Options.

Extended Congestion NotificationDisabledThis setting specifies that the system uses the TCP flags CWR (Congestion Window Reduced) and ECE (ECN-Echo, used to indicate that the TCP peer is Explicit Congestion Notification capable during the three-way handshake) to notify its peer of congestion and congestion counter-measures.

Note: When this option is enabled, it is used only when two hosts signal that they want to use it. It allows a host to set the ECN bit within the IP header to notify the transmitter that the link is congested.

Extensions for High Performance (RFC 1323)EnabledThis setting specifies that the system uses the timestamp and window scaling extensions for TCP, as specified in RFC 1323, to enhance high-speed network performance. The timestamp option allows for accurate Round Trip Time Measurement, in addition to simplifying window calculations for the sender. The window scale options allow for TCP to indicate preparedness to both send and receive window scaling, and communicate a scale factor to be applied to its received window.

Note: F5 recommends that you do not disable this option, as it enhances network performance.

Limited Transmit RecoveryEnabledThis setting specifies that the system uses limited transmit recovery revisions for fast retransmits, as specified in RFC 3042: Enhancing TCP's Loss Recovery Using Limited Transmit to reduce the recovery time for connections on a lossy network.
Slow StartEnabledThis setting specifies that the system uses larger initial window sizes, as specified in RFC 3390: Increasing TCP's Initial Window, to help reduce round trip times. TCP slow-start congestion avoidance is a method of converging on the right amount of data to put on the link without overloading the link in order to prevent packets from being dropped.
Deferred AcceptDisabledThis setting specifies that the system defers allocation of the connection chain context until the system has received the payload from the client. Enabling this setting is useful in dealing with three-way handshake denial-of-service attacks.
Verified Accept
(10.0.0 and later)		DisabledWhen enabled, the system verifies that the pool member is available to accept the connection by sending the server a SYN before responding to the client's SYN with a SYN-ACK.
Bandwidth Delay
(9.0 - 9.4.2)		EnabledThis setting specifies that the system attempts to calculate the optimal bandwidth to use on the client, based on throughput and round-trip time, without exceeding the available bandwidth. This option is used by the system to determine the bandwidth delay for each connection in order to ensure optimal throughput.

Note: The Bandwidth Delay feature was removed in BIG-IP 9.4.2. However, the setting was not removed from the UI as a TCP profile option until version 11.0.0. For more information, refer to K13292: The Bandwidth Delay setting was not removed from the TCP profile.
Nagle's AlgorithmEnabledThis setting specifies that the system applies Nagle's algorithm to reduce the number of short segments on the network. Detailed in RFC 896: Congestion Control in IP/TCP Internetworks, the Nagle Algorithm is a TCP optimization that makes the stack wait until all data is acknowledged on a connection before sending more data. This process, called nagling, increases the efficiency of a network application system by decreasing the number of packets that must be sent.

Note: In some highly interactive client/server environments, the use of Nagle's Algorithm might cause undesired behavior and should be disabled.

Acknowledge on PushDisabledThis setting improves performance to Windows and Mac OS peers writing out on a small send buffer.
MD5 Signature
(9.2.0 and later)		DisabledUse RFC 2385 TCP-MD5 signatures to protect TCP traffic against intermediate tampering.

Note: When the MD5 Signature and MD5 Signature Passphrase are enabled, they protect BGP sessions from being tampered with, as BGP utilizes TCP as its transport. MD5 Signature provides enhanced security between BGP endpoints.
MD5 Signature Passphrase
(9.2.0 and later)		BlankType the plain-text passphrase (from 1 to 80 characters in length) that is used in a shared-secret scheme to implement the spoof-prevention parts of RFC 2385.

Note: When the MD5 Signature and MD5 Signature Passphrase are enabled, they protect BGP sessions from being tampered with, as BGP utilizes TCP as its transport. MD5 Signature provides enhanced security between BGP endpoints.
Congestion Control
(9.4.0 and later)		New Reno (9.4.x)


High Speed (10.x )		Available options:
  • None: No congestion control algorithm implemented.
  • High Speed: A more aggressive, loss-based algorithm.
    RFC 3649: HighSpeed TCP for Large Congestion Windows.
  • New Reno: A modification to the Reno algorithm that responds to partial acknowledgments when selective acknowledgments (SACK) are unavailable.

  • Reno: An implementation of the TCP Fast Recovery algorithm, based on the implementation in the BSD Reno release.

  • Scalable: A TCP algorithm modification that adds a scalable, delay-based and loss-based component into the Reno algorithm. This option is used in conjunction with the Appropriate Byte Counting.
Congestion Metrics CacheEnabledThis setting specifies that the system uses a cache for storing congestion metrics.
Appropriate Byte Counting (RFC 3465)EnabledThis setting increases the congestion window by basing the increase amount on the number of previously-unacknowledged bytes that each ACK covers.
D-SACK (RFC 2883)DisabledThis setting specifies the use of the Selective ACKs (SACK) option to acknowledge duplicate segments. RFC 2883 specifies an extension to Selective Acknowledgements, known as D-SACK. Using D-SACK blocks, a receiver can notify its peer when it receives multiple copies of data, thus warning the sender of in-band network replication of segments, or causing the peer to scale back in its re-sending speed.

Note: F5 recommends that you do not enable this option unless the peer device communicating with the BIG-IP system also supports D-SACK.

Packet Lost Ignore Rate
(10.0.0 and later)		0Specifies the threshold of packets lost per million at which the system performs congestion control. Valid values range from 0 to 1,000,000. The default is 0, meaning the system performs congestion control if any packet loss occurs. If you set the ignore rate to 10 and packet loss for a TCP connection is greater than 10 per million, congestion control occurs.
Packet Lost Ignore Burst
(10.0.0 and later)		0Specifies the probability of performing congestion control when multiple packets are lost, even if the Packet Loss Ignore Rate was not exceeded. Valid values range from 0 to 32. The default is 0, meaning that the system performs congestion control if any packets are lost. Higher values decrease the chance of performing congestion control.
