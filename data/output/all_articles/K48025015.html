Description

The CPU on the TMM cores are high and remains high even when the device is made standby

Environment

  • Client SSL Profile
  • CPU

Cause

When on the client ssl profile alert timeout is configured this may create zombie flow which keeps the CPU busy causing the tmm cores to use CPU even when there is no traffic passing through the device.

This is tracked under the Bug ID 1088597: TCP keepalive timer can be immediately re-scheduled in rare circumstances

Recommended Actions

   To workaround the immediate issue please follow the below steps:
  1. Set the Alert Timeout as default, which is indefinite
  2. Restart TMM
bigstart restart tmm
 

Bug ID 1088597 isn't fixed in an official release at the time of this article's publication. However, an engineering hotfix may be requested by opening a Service Request with F5 Support and referencing this article.
