K55215015: Oracle monitor traffic is not detected when troubleshooting monitor issues

Type
Support Solution
Published
2022-04-08
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.3
Source
https://my.f5.com/manage/s/article/K55215015

Description

When troubleshooting an Oracle monitor issue, there appears to be no monitor traffics captured between the BIG-IP Self-IP and the monitored pool members.

Environment

Relevant environmental factors specific to the topic

  • BIG-IP
  • Oracle monitor
  • Oracle Pool members redirect connection request to a real Oracle server.
  • TCP

Cause

The first Oracle monitor request will be sent to a pool member, and then this pool member redirects the request to a real oracle server. After that the Self-IP will established a long-lived TCP connection with real Oracle server for the Oracle monitor, subsequent monitor traffic will go over the established TCP connection.

Recommended Actions

We need to capture the network traffic from Self-IP to the pool members, and then from the Self-IP to real Oracle server ip address.
 

Additional Information

Monitor request to pool members are redirected to the real Oracle server and the original monitor TCP connection is closed. After this event there is no new monitor traffic between the BIG-IP Self-IP and pool member until the redirect established long lived TCP connection is closed.

Example:
ltm pool /Common/test_01 {
    members {
        /Common/192.168.1.3:7000 {
            address 192.168.1.3   <===========  redirect  192.168.4.3 real oracle server
        }
        /Common/192.168.1.4:7000 {
            address 192.168.1.4   <===========  redirect  192.168.4.4 real oracle server
        }
    }
    monitor min 1 of { /Common/oracle_monitor }
}
ltm monitor oracle /Common/oracle_monitor {
    count 0
    database "(DESCRIPTION=(ADDRESS_LIST=(ADDRESS=(PROTOCOL=TCP)(HOST=%node_ip%)(PORT=%node_port%)))(CONNECT_DATA =(SERVICE_NAME = ORAC)))"
    debug yes
    defaults-from /Common/oracle
    destination *:*
    interval 1
    password ***scrubbed***
    recv Jack
    send "select * from BS_users"
    time-until-up 0
    timeout 4
    username f5mon
}
