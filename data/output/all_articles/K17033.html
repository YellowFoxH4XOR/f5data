Known Issue

The Configuration utility does not provide an option to use the supported AES192 or AES256 encryption algorithms. However, you can configure these algorithms by using the Traffic Management Shell (tmsh).

This issue occurs when the following condition is met:

  • From the Configuration utility, you attempt to create or modify an IPsec peer by using the AES192 or AES256 phase 1 algorithms.

Impact

If you have configured the AES192 or AES256 encryption algorithms from the tmsh utility, you may inadvertently revert to the DES algorithm by clicking the Configuration utility Update button after an update.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You cannot select the AES192 or AES256 encryption algorithms for your IPsec configuration.
  • Your IPsec configuration reverts back to the DES encryption algorithm after an unrelated IPsec configuration change from the Configuration utility.

Workaround

To work around this issue, you can create the IPsec configuration by using the Configuration utility, and then modify the encryption algorithm by using the tmsh utility. To modify the Internet Key Exchange (IKE) encryption algorithm by using the tmsh utility, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Modifying the phase-1-encrypt IKE algorithm setting for an IPsec peer

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Change the phase-1-encrypt algorithm setting by using the following command syntax:

    modify net ipsec ike-peer <my-ike-peer> phase1-encrypt-algorithm <aes-algorithm>

    In this command syntax, <my-ike-peer> is the name of your configured IPsec peer, and
    <aes-algorithm> is either aes256 or aes192.

    For example:

    modify net ipsec ike-peer my-ike-peer phase1-encrypt-algorithm aes256
  3. Save the change by typing the following command:

    save /sys config
