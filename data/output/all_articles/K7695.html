Known Issue

This is the result of a known issue. The SSL filter does not validate the SSL record version against the negotiated protocol version before passing it to the Cavium processor. This issue allows SSL records with incorrect protocol versions to be processed. As a result, the Cavium processor can stall when you attempt to process the data containing the wrong SSL record version. Additionally, the virtual server may no longer handle traffic as requests are queued in an attempt to send them to the Cavium processor.

Note: This issue only affects virtual servers using an SSL profile. The TCP or FastL4 profile that passes SSL traffic directly to the server does not use the Cavium processor.

When an incorrect SSL record is detected, the BIG-IP LTM system should drop the connection immediately (SSLv2/SSLv3) or drop the offending packet (TLSv1).

F5 Product Development tracked this issue as CR82219 and CR81463 and it was fixed in BIG-IP LTM 9.3.1 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.
