Description

You want to know if Silverline WAF protects against Slow HTTP Denial-of-Service (DoS) type attacks.

 

Environment

  • Silverline WAF
  • Proxy/Proxies
  • WAF Policy/Policies

 

Answer/Recommended Actions

Silverline WAF protects customer applications against Slow HTTP attacks such as Slow HTTP POST, Slow HTTP Headers, and Slowloris.  There is no specific configuration required, as the mitigation for such attacks is inherent in the platform architecture.

These types of Slow HTTP attacks operate by sending many incomplete HTTP requests, hoping to force the victim server to hold connections and processing threads open waiting to receive the complete request.  This can result in a DoS as the victim exhausts its available resource pool in servicing the bogus incomplete requests.

In the Silverline Proxy Architecture, HTTP clients do not connect directly to the application/web server, but rather connect first to the Silverline proxy for inspection.  A slow HTTP type attack targeted at a Silverline proxy could only be effective if it were able to consume the Silverline platform's resource pool of connections/threads.  By design, Silverline's resource pool is more than sufficient to withstand any such attacks without impact.  Silverline will not forward incomplete HTTP requests to the origin server. 

 

 

Additional Information

Effects of a Slowloris attack on a BIG-IP virtual server configured with an HTTP profile

A virtual server which uses an HTTP profile will only open connections and proxy requests to pool members once a complete and valid HTTP request has been received. Since the principle of the Slowloris attack is to never complete any request, no connections are ever opened nor any data sent to the pool members.

The attack consumes connections on the BIG-IP system, rather than the web servers in the pool. When the total size of the headers sent by the Slowloris attack exceeds the maximum header size configured in the HTTP profile, the BIG-IP system resets the connection, recovering the TCP socket and removing the connection from the connection table. As the Slowloris attack continues to open new connections, the BIG-IP virtual server continues to reap them in this manner. This renders the Slowloris attack ineffective against web servers which are load balanced by a BIG-IP virtual server configured with an HTTP profile.
