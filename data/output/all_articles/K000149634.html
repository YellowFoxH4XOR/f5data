Supply chain

OWASP LLM supply chain covers the risks associated with the integrity of code, training data, models, and entities in the deployment platform. This is dependent on the security of the entire process when creating, training, deploying, and maintaining large language models (LLMs) and can include any of the following through the LLM lifecycle:

  • Processes (development, deployment, operational, and maintenance)
  • Hardware and software components (Client devices, servers, operating system, software libraries, and so on)
  • Third-party and other LLMs and adapters
  • Data (users, training, third-party, and so on)
  • Licenses management(hardware, software, third-party, and so on)

Depending on the vulnerable or compromised component, the impact may range from biased outputs to security breaches and even complete system failures.

Supply chain attack scenario

A well-known supply chain attack is the OpenAI data breach, in which an attacker exploits a Python library. LLM software developers unknowingly download the library, resulting in data breaches. Sensitive data such as system information of the client devices the developers use may be compromised.

Security best practices to protect against supply chain attacks

To mitigate this vulnerability, you should identify all vulnerable components in your LLM supply chain by creating a threat model based on your environment. For example, refer to LLM Threat supply chain on Github. Then implement robust policies and security measures to manage the risk posed by each vulnerable component.

Secure against supply chain attacks using defense-in-depth strategies with F5

As the scope of supply chain attacks is wide, there isn't a single product that can protect against them. You can use F5 products in a layered defense strategy to mitigate the threats at different parts of the threat model.

Figure: Defense-in-depth with F5 products

Using F5 products and a defense-in-depth security strategy for your LLM applications can help reduce the likelihood of OWASP LLM vulnerabilities. This approach involves using multiple layers of security to protect your accounts, workloads, data, and assets. By doing so, you can ensure that if one security measure is compromised, additional layers can effectively help isolate threats and manage security events. You can enhance security and resilience by integrating various strategies, including F5 services and solutions, at each layer.

API and app security

The most common ways users, administrators, and other components interact with LLMs are through API requests and responses. It is therefore essential to review the API OWASP Top 10 for your LLM environment. For more information on how F5 products can do that, refer to K000135973: OWASP API Top 10 2023 Operations Guide Introduction and contents.

Infrastructure

Vulnerable and outdated components

Mitigating supply chain attacks is similar to mitigating vulnerable and outdated components in the OWASP Top 10 2021. Supply chain attacks target both your infrastructure that includes client and server side components. You can use the following F5 products to mitigate these attacks:

  • BIG-IP APM to validate the security posture of incoming web connections accessing your LLM environment. For example, by securing the client devices that developers and system administrators use to manage your LLM infrastructure, you mitigate the impact of untrusted or compromised third-party components.
  • Configure the WAF policies in BIG-IP Advanced WAF/BIG-IP ASM, NGINX App Protect, and F5 Distributed Cloud with appropriate attack signatures, server technologies, and vulnerability assessment policies for protection at different locations of the network layer.

For more information, refer to K17045144: Vulnerable and outdated components (A6) | Secure against the OWASP Top 10 for 2021, taking care to identify, manage, and patch all vulnerable components including third-party ones.

BIG-IP Advanced Firewall Manager (AFM)

Network infrastructure security can be enhanced through internal network segmentation using firewalls, creating distinct security zones across your LLM supply chain. This approach limits the impact of a breach in any component in the supply chain by confining potential compromises to a single segment, thereby establishing a layered defense. Use the following BIG-IP AFM features to implement this in your LLM environment.

    Integration with OAuth providers

    Implement IAM security for API access to your LLMs.

    BIG-IP APM integrates with your OAuth provider to implement secure authentication. Depending on your application logic, configure the following agents in a per-request policy:

    • An OAuth Client agent in a per-request policy with OpenID Connect to authenticate API requests with your OAuth provider.
    • An OAuth Scope agent in a per-request policy to validate tokens issued by your OAuth provider.

    You can configure the BIG-IP APM to validate JWT tokens either internally or externally. In both configurations, implement the following to add a layer of protection:

    • Access token expiry
    • Access token denylist
    • Validate that the access token is signed with a secure signing algorithm

    Summary

    The LLM OWASP supply chain has one of the widest scopes, covering hardware, software (development, deployment, and operational) processes, inventory management, and in particular third-party components in the threat model. From there, you can implement security measures including those discussed in this article to mitigate each threat.
