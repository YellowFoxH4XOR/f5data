Topic

The error message Error getting auth token from login provider can be caused by a variety of different issues and primarily leads to the BIG-IP Configuration utility (GUI) unable to load properly and displaying the error as a banner at the top of the screen.

Start with this article when you want to troubleshoot this error message.

Description

The error message Error getting auth token from login provider is generally caused by specific configurations made in the BIG-IP system. To troubleshoot the issue, use the following suggestions and table:

  1. First, review the first 4 issues (rows) in the table which are a result of specific configurations made in the BIG-IP system. Rule these issues out by verifying that your system does not contain any of the specific configurations.
  2. When none of the issues are applicable, refer to the last issue (row) which describes a general root cause.

Recommended Actions

Upgrade to a fixed BIG-IP version or perform the applicable workaround described in the table.

Impact of workarounds

Where the workarounds require restarting restjavad/restnoded, refer to the following impact:

Restarting restjavad or restnoded affects the control plane. While the data plane is not impacted, in rare situations where system resources (CPU, memory) are exhausted, the system may experience service restarts or even reboot and unable to process traffic. Services that rely on the service include the following:

  • REST API calls
  • BIG-IQ communications
  • BIG-IP configuration utility, in particular when loading or deploying SSL Orchestrator, Guided Configuration, iApps LX pages and configurations.
  • Device statistics collection with AVR provisioning
  • Automation toolchain (Application Services 3 (AS3), Declarative Onboarding (DO), Telemetry Streaming (TS))
  • any automation, scripts that you may have configured using the services listed above. 

In most environments, the daemons can typically be restarted with momentary impact on the services listed. Depending on your environment, when automation is a critical part, F5 recommends to restart restjavad in a scheduled maintenance window.

In addition, note that REST API calls are not limited to external communications with external devices (e.g. management devices), internal API calls that load the Configuration utility and configurations also rely on restjavad and restnoded daemons.

Additional Information

In most situations, performing the workarounds to restart the daemons should resolve the issue. However, in limited cases, when a BIG-IP system contains a very large number of configurations (e.g. 75,000 records in an iApp), F5 Support may request that you increase the timeout values for restjavad, restnoded, icrd. To do so, refer to K94602685: REST API occasionally times out.
