K000156959: How to enable JWT Claim as User Identification Policy

Source

Description

To enable JWT Claim as User Identification Policy, you need to configure first JSON Web Key Set (JWKS) and then set User Identification Policy.

if you set up only User Identification Policy with JWT Claim without JWKS, option will not work.

Environment

  • F5® Distributed Cloud HTTP Load Balancer
  • User Identification Policy
  • JWT
  • JWT Claim
  • JWT Claims validation

Cause

JWT is a JSON signed by an authority. If JWT validation is not enabled, anyone can send any JSON with random data, which defeating the purpose of user identification. Only valid signed tokens verified by JSON Web Key Set are considered as valid source of user identification. 
If token is not valid or missing, we will use different user identification methods e.g. IP, JA4 etc.  

Answer/Recommended Actions

To enable JWT Claim as User Identification Policy:

  1. Enable JWT Claims validation - K000147610: How to Validate JWT Claims
  2. Enable JWT User Identification Policy:
    1. Go to the LB details and click Edit config.
    2. In Common Security Controls find User Identifier.
    3. Change User Identifier to User Identification Policy.
    4. Create new policy, click Add item:
    5. Name policy and create User Identification Rules by clicking Configure:  
       
    6. Provide list of identifiers types with JWT Claim type:
       

    7. You can provide more then one identifier. User identification use an ordered list of rules that are evaluated sequentially against the input fields extracted from an API request in order to determine a user identifier. Evaluation of the rules is terminated once a user identifier has been extracted e.g. if JWT Claim with "jti" name will be found in valid JWT token, we will use that as user identification and will skip rest of the checks. 
        
    8. Save user identification policy and LB settings. 

Additional Information

To verify if policy works, you can check your logs send via GLR ("user" column/JWT colums) or in LB request details. To check it via console:

  • Go to your LB requests:

  • Choose request and switch to JSON view:
     

    Note: JWT processing details and JWT user identification are only visible now in JSON view. "Information" tab will not show these details.  
  • When JWT validation and user identification policy is enabled, you can find in request JSON entries like: 

"jwt_status" - show status of provided JWT token. Example values are: "OK", "Jwt is expired", "Jwt is missing".

"jwt_mode" - shows mode of JWT token validation. Can be in "Report" or "Block" mode. 

"jwt_action" - shows JWT action for request, if it's "Allowed" or "Blocked".

"user" - this is standard column that shows user identification value. When JWT claim user identification is active and works (token is valid and contains parts set in policy), it will contain "JWTClaim" in value with information which part is extracted and it's value, example: "user": "JWTClaim-jti-7381156b-0718-4".

 

If you have any problems e.g you don't see JWT columns or users are still identified as IP etc. please open a ticket to our Distributed Cloud support.
