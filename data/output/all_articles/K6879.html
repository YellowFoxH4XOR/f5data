Known Issue

This is the result of a known issue. When the OneConnect Transformations setting is enabled in the HTTP profile and the server sends an HTTP 4XX response, the BIG-IP LTM system does not transform the HTTP/1.1 Connection headers in HTTP responses to HTTP/1.0 Keep-Alive headers as expected by the HTTP/1.0 client, and may prematurely detach or close the serverside connection.
 
When the OneConnect Transformations setting is enabled, the BIG-IP LTM system should perform the following actions:
  • Transforms clientside HTTP/1.0 Keep-Alive headers in HTTP requests to HTTP/1.1 Connection headers before sending the request to the server
  • Transforms serverside HTTP/1.1 Connection headers in HTTP responses to HTTP/1.0 Keep-Alive headers before sending the response to the client
  • Prevents detachment of the serverside connection when the server sends an HTTP 401 response, in support of NTLM authentication transactions

However, for HTTP 4xx responses, the Connection headers are not transformed, and the serverside connection is detached. If the server sends a Connection header containing the close token, the serverside connection will also be closed.

F5 Product Development tracked this issue as CR66220 and CR66133, and it was fixed in BIG-IP LTM 9.2.5, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
