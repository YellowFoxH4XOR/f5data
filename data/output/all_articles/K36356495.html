Description

There is a change of the management IP and now the peers show In Sync but HA is not working.

  • Packet captures are run and it there is no apparent issue.
  • In var/log/ltm there are log entries indicating that the failover messages have not been received...
warning sod[<PID>]: 010c0083:4: No failover status messages received for 3.100 seconds, from device bigip1.com (192.168.1.1) (unicast: -> 192.168.1.2)
warning sod[<PID>]: 010c0083:4: No failover status messages received for 3.100 seconds, from device bigip2.com (192.168.1.2) (unicast: -> 192.168.2.2).

Environment

  • The management IP was changed on one or both peers. For example when moving one device to a different location, booting it up, and then having to change the management IP.
  • High Availability, Management IP, Configsync
  • When a packet capture is run it will show the correct source IPs. However, in the UDP payload is what is referred to as the HA message. The HA message is not readily identifiable (that contains the peer management IP) because it is embedded in the UDP payload and cannot be seen without the proper F5 Wireshark dissector.

Cause

When the management IP is changed on one or both peers it may cause HA to not function properly. This is due to how the management address is used as an identifier of the system for network HA. Thus changing it can be problematic.

sod, The switch over (failover) daemon causes the unit to become active or standby, and provides failover capability through a high-availability table. When the management IP is changed the table may not get updated.

Recommended Actions

  1. The easiest way to identify the issue is via the LTM logs entries. As seen above the IPs for the bigip2 with bigip1, and one of the IPs is in a different subnet.
  2. To correct this restart sod...
Run the command: tmsh
Then run: restart sys service sod.
Note: A restart of the sod daemon will cause a failover.
