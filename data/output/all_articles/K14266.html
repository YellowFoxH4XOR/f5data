Known Issue

The gencert command does not overwrite existing self-signed certificate/key pairs. In BIG-IP 11.x, the SSL profile certificate and keys are referenced in the /config/filestore/files_d/<partition_name>_d/certificate_d/ and /config/filestore/files_d/<partition_name>_d/certificate_key_d/ directories, respectively.

Important: F5 recommends you use the BIG-IP Configuration utility when creating SSL keys, X509 certificates, and certificate signing requests. For specific instructions, refer to the Configuration Guide for BIG-IP Local Traffic Management.

Impact

  • The gencert command will not overwrite existing self-signed certificate/key pairs.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H381089 on the Diagnostics > Identified > Low screen.
  • When attempting to overwrite existing self-signed certificate/key pairs, the following error message may display:

    The requested unknown (/Common/<cert/key-name>) already exists in partition Common.
  • If the certificate or key was deleted prior to running the gencert command, an error message will display when you attempt to associate the self-signed certificate/key pair with a profile. The error message will appear similar to the following example:

    Error reading key PEM file /config/filestore/files_d/Common_d/certificate_key_d/:Common:<cert-name_X> for profile /Common/<profile-name>: error:0B080074:x509 certificate routines:X509_check_private_key:key values mismatch

Workaround

To work around this issue, you can renew the certificate using the Configuration utility. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the Configuration utility.
  2. Navigate to System > File Management.
  3. From the SSL Certificate List, select Certificate Name.
  4. Click Renew.
  5. Update the Certificate Properties as needed.
  6. Click Finished.

If renewing the certificate using the Configuration utility is not an option, you can delete the self-signed certificate/key pair and then re-run the gencert command. To do so, perform the following procedure:

Impact of workaround: Before performing the following procedure, you need to disassociate the self-signed certificate/key pair from any SSL profile.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Delete the existing self-signed certificate/key pair by using the following syntax:

    delete sys file sys ssl-cert <cert-name>
    delete sys file sys ssl-key <key-name>
  3. Save the change by typing the following command:

    save /sys config
  4. Run the gencert command to generate a new self-signed certificate/key pair.

    You can now associate the new self-signed certificate/key pair with an SSL profile.
