Known Issue

This is the result of a known issue. The ARX system sends an erroneous DNS PTR query when you use the show redundancy command on an ARX system that is configured with an NFS quorum disk. The show redundancy command attempts to resolve and display the hostname for the IP address of the NFS quorum disk. However, the DNS PTR query that the system sends to the DNS server is not for the IP address of the quorum disk, but for an unrelated IP address. The query fails, and the actual IP address of the quorum disk displays in the show redundancy command output.

For example, on a redundant ARX system configured with a quorum disk IP address of 10.10.1.10, the output of the show redundancy command correctly displays the IP address of the quorum disk in output that appears similar to the following example:

                                               Transitions
Node Switch/Quorum Disk   Status     Role    Total Last (UTC)
---- -------------------- ---------- ------- ----- -------------------
*1   ARX1                 Up         Active  Never -
 2   ARX2                 Up         Backup  1     21:19:17 12/16/2010
 QD  10.10.1.10           Up         Quorum  1     21:19:07 12/16/2010

However, the DNS PTR query that the system sent to the DNS server is for an unrelated IP address, so the query fails, and displays output that appears similar to the following example:

  1   0.000000 192.168.10.33 -> 10.10.1.29   DNS Standard query PTR 53.46.48.49.in-addr.arpa
  2   0.000455   10.10.1.29 -> 192.168.10.33 DNS Standard query response, Server failure
  3   0.000512 192.168.10.33 -> 10.10.1.29   DNS Standard query PTR 53.46.48.49.in-addr.arpa
  4   0.000753   10.10.1.29 -> 192.168.10.33 DNS Standard query response, Server failure

Note: These queries do not harm the DNS server and you can safely ignore the queries.

F5 Product Development tracked this issue as ID 344788, and it was fixed in ARX version 6.0.0. For information about upgrading, refer to the ARX release notes.
