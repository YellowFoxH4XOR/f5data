Description

This article addresses the case sensitivity mismatch that can occur when configuring LDAP (LDAPS) authentication for administrative access to F5OS rSeries appliances using Microsoft Active Directory (AD) as the backend.

Environment

  • F5OS rSeries appliances
  • F5OS 1.8.x (and possibly earlier/later)
  • Microsoft Active Directory via LDAPS

Cause

Microsoft Active Directory treats usernames as case-insensitive, so "John" and "john" are considered equivalent during login. However, the nslcd daemon used by Linux-based systems like F5OS is case-sensitive by default, requiring an exact match between the entered username and its representation in AD.

As a result, if a user attempts to log in with "john" but their account was created as "John" in AD, authentication will fail unless special configuration is applied.

Example log excerpt:

nslcd: [3c9869] <authc="i522062a"> DEBUG: myldap_search(base="...", filter="(sAMAccountName=john)")
nslcd: [3c9869] <authc="john"> username changed from "john" to "John"

This behavior has been identified and tracked under Bug ID1591549.

Recommended Actions

Option 1: Enforce Exact Username Case at Login

Instruct users to always enter their username exactly as it appears in Active Directory (matching upper/lowercase). This approach may be impractical for large organizations or where usernames have inconsistent casing.

Option 2: Configure F5OS to Ignore Case During LDAP Authentication (Recommended) F5OS provides an option to make LDAP authentication case-insensitive:

  • Login to F5OS appliance CLI using admin credentials.
  • Enter configuration mode and set: 'system aaa authentication ldap ignore-case true' allowing users to authenticate regardless of letter casing in their username input.
  • commit your changes.
  • Test login using different cases (e.g., both “John” and “john” should now succeed).

Additional Information

  • This Option2 is available starting from F5OS-A version 1.8.3.
  • If you are running an earlier version, consider upgrading or instructing users about strict casing requirements.
