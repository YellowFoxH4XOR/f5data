Known Issue

This is the result of a known issue. When FastHTTP is used and the HTTP request headers are split across multiple packets, the FastHTTP parser incorrectly writes information used to track the partial headers for reassembly. The TMM crashes when attempting to read this information, due to the corrupted information.

The occurrence of this issue is rare, as the HTTP request must be split across the multiple packets in a specific way.

F5 Product Development tracked this issue as CR71972, CR72101, and CR72102, and it was fixed in BIG-IP LTM versions 9.1.3, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM release notes.
