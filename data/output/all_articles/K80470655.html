Known Issue

BIG-IP Virtual Edition (VE) erroneously spawns multiple Traffic Management Microkernel (TMM) processes when using a non-default tmm.threads database value.

This issue occurs when the following condition is met:

  • You set the tmm.threads database variable on BIG-IP VE to a non-default value; the default value is zero (0).

BIG-IP VE should run with only one TMM process and all TMMs should run as threads in that single process. Setting the tmm.threads database variable causes BIG-IP VE to launch multiple TMM processes.

Impact

BIG-IP VE spawns additional TMM processes that do not pass network traffic. As a result, performance is degraded for the assigned number of cores on BIG-IP VE.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP VE performance is degraded.
  • BIG-IP VE logs critical messages in the /var/log/ltm file that appear similar to the following example:

    tmm1[<PID>]: 01230017:2: Unable to attach to PCI device 13:00.00 for Interface 1.2
    tmm1[<PID>]: 01230017:2: Per-invocation log rate exceeded; throttling

Workaround

To recover from this issue, you should set the tmm.threads database variable back to the default value of 0.

Note: Changes to the database variable will take effect only after you reboot BIG-IP VE.

Impact of workaround: Rebooting BIG-IP VE temporarily interrupts traffic processing. If the system is configured as part of a high availability (HA) pair, the device may fail over. F5 recommends that you perform the suggested workaround during a scheduled maintenance window.
