Description

TMM may immediately re-use a source port for a fastL4 virtual server with a default fastL4 profile

  • TCP connection may fail with backend server sending a challenge ACK.
  • Server ACK will have an acknowledgement number from the previous connection on the same socket

Environment

  • Fastl4 virtual server with default source port setting set to preserve
  • Default fastL4 profile or fastL4 profile with default TIME_WAIT timeout setting of zero
  • SNAT pool or SNAT AUTO MAP attached to the fastL4 virtual server

Cause

Cause is attributed to a client immediately re-using a previously used source port or another client immediately using a source port which was just in use by another client. TMM will try and preserve the source port as such will re-use previously used source port on the server side. If the previous connection is still in TIME_WAIT state on the server and the BIGIP uses an ISN value lower than the last ACK from the backend server then the backend server responds with a challenge ACK.

Recommended Actions

The issue can be resolved by taking on of the below measures:

  1.  Change the virtual server source port option from "preserve" to "change", see K01155812
  2. Set the fastL4 profile "TIME_WAIT" timeout to 2 seconds, see K09948701
