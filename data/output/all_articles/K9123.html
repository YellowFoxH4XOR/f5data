  • K9403: Overview of the Always-On Management (AOM) subsystem

When deploying devices remotely, F5 recommends completing the following tasks:

  • Configuring serial console access to the unit
  • Configuring the management port on a separate secure management network
  • Configuring the SCCP or AOM with an additional IP address on the same network as the management port
  • Configuring a PXE server on the management network

Configuring serial console access to the unit

Serial console access provides the most highly available method of access to the device. In the event that network access is impaired, the serial console may be the only way to access the device. F5 recommends that you perform all installations and upgrades using the serial console. These procedures require reboots; therefore, network connectivity will be temporarily lost. Performing upgrades and installations using the console allows you to accurately track the progress of the installation, and help prevent interruptions. Additionally, the serial console is the most robust method to secure access during configuration lockout situations.

Note: For diagnostic purposes, F5 may request serial console output. Some system events that do not log to the file system may log to the serial console.

Console access is provided by a terminal server, which usually contains several serial interfaces used to connect to the serial console outputs of devices. These devices typically consist of a PC with a single or multi-port serial interface card, or specialized hardware made for this specific purpose. Consult your solution's documentation for assistance with the configuration.

Note: For more information about the settings required for accessing the serial console, refer to K7683: Connecting a serial terminal to a BIG-IP system.

A null modem cable is required to connect to the serial console.

Note: For more information about the serial terminal cable requirements, refer to K587: Pinouts for serial terminal cables used to connect to F5 products.

Note: Each BIG-IP system ships with a serial terminal cable and a failover cable. The failover cable is used to connect a redundant pair of BIG-IP systems; this cable has custom pinouts and cannot be used for connecting to the serial console of a BIG-IP system.

Configuring the management port on a separate secure management network

F5 recommends configuring the management port on a secure network. The management port is the only port that is PXE enabled; therefore, it is vital to any recovery attempts. In addition, access to the management port is completely separate, and is not reliant on the Traffic Management Microkernel (TMM) or the main switchboard, which can be useful in certain troubleshooting situations.

Note: For more information, refer to K7312: Overview of the management port.

Configuring the SCCP or AOM with an additional IP address on the same network as the management port

F5 recommends that you allocate an additional IP address on the same network as the management port for the SCCP or AOM. If providing serial console access through a console server is unattainable, F5 strongly recommends configuring an IP address for the SCCP or AOM. In the event that the host subsystem becomes unreachable, but network connectivity using the management network is still available, you may gain partial access to the unit using the SCCP or AOM. At this point, you can perform a number of important recovery actions using the hostconsh command.

Note: For more information, refer to the following Solutions:

  • K3454: Overview of the SCCP
  • K3753: Configuring the switch card control processor so that it can be accessed over the network
  • K9403: Overview of the Always-On Management (AOM) subsystem

Configuring a PXE server on the management network

In the event of an unrecoverable file system or image corruption, F5 may request a clean installation of the operating system. If the device is located remotely and someone is not readily available with a USB device, a PXE installation is a fast, reliable way to provide installation services.

Note: Once the remote system has been re-imaged, refer to the user documentation available for the version you have installed to continue configuring the system.

BIG-IP 9.x

The PXE installation requires a second machine other than the BIG-IP device to perform the installation. The second machine boots off of a CD created using the BIG-IP ISO image to provide an installation server for the BIG-IP device to access. Usually, this second machine is a laptop or other device on the network, but if the BIG-IP device is remotely located, you may use a generic VMware Linux host image. The VMware Linux host image’s interface is bridged to the management network, which can then be dynamically brought up and down as needed. Using a VMware host also allows you to mount and boot from the ISO images directly without having to burning a CD first.

Note: For detailed information about performing a clean installation of BIG-IP 9.x, refer to the BIG-IP LTM, ASM, PSM, GTM, Link Controller, or WebAccelerator Release Notes for the version you are installing.

Note: For more information, refer to K3525: Configuring the BIG-IP LTM, GTM, or ASM to boot from a network boot server and K3359: Network interface cards supported by the F5 PXE network boot server.

BIG-IP 10.x

Beginning in BIG-IP 10.0.0, ISO images no longer provide network installation services; therefore, they cannot be used to boot and automatically configure a workstation as a PXE server. However, the essential files are still included in the product ISO images. You can use these files to manually configure a workstation as a PXE server.

Note: For detailed information about performing a clean installation of BIG-IP 10.x, refer to K10819: Performing a clean installation of BIG-IP 10.x or Enterprise Manager 2.x.
