Description

After upgrading to version 14.1 or later, external monitor (EAV) scripts that send and receive UDP data using the nc (netcat) utility may no longer work.

Debug logs suggest that no reply is received from the monitored target.

Packet captures show that the target sent a reply, but BIG-IP responded with an ICMP unreachable message.

Environment

  • LTM external monitors that use the nc command to send UDP probes

Cause

Starting with BIG-IP 14.1, the underlying TMOS base operating system was upgraded to CentOS 7.x, which replaced the netcat utility with ncat. Both utilities are invoked using the "nc" command.

The ncat utility behaves slightly differently from netcat. Most importantly, ncat closes the UDP socket as soon as the input stream closes.

Therefore, when data is piped to "nc" command, ncat sends the data and exits immediately without waiting for a response. This differs from netcat, which waits for the duration specified by the -w option.

With ncat, the -w option specifies only the connection timeout. Because UDP is connectionless, this option does not keep the UDP socket open while waiting for a response.

For example:

BIG-IP 13.x using netcat:

echo "test" | nc -u -w10 10.0.0.1 8888

This command sends test over UDP to the target and waits up to 10 seconds for a response.

BIG-IP 14.1 or later using ncat:

echo "test" | nc -u -w10 10.0.0.1 8888

This command sends test over UDP to the target and exits immediately without waiting for a response.

Answer/Recommended Actions

Modify the external monitor scritp to use "socat" command instead of "nc". The behavior of socat is consistent across BIG-IP TMOS versions.

For example:

echo "test" | socat -t 10 - UDP:10.0.0.1:8888

This command sends test over UDP to the target and waits up to 10 seconds for a response.

Alternatively, prevent standard input (STDIN) from closing immediately by adding a "sleep" command. The "echo" and "sleep" commands must be grouped in a subshell using parentheses:

(echo "test"; sleep 10) | nc -u 10.0.0.1 8888
