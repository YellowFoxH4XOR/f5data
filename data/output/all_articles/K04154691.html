Description

BIG-IP does not send SNMP traps configured for dosl7d logs.
 

Environment

  • Custom OID created in /config/user_alert.conf

    For example:

    alert DoSL7_Attack "ADM ATTACK START(.*)" {
       snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.301"
    }
     
  • "ADM ATTACK START" event is listed correctly in the dosl7d log


Cause

SNMP traps rely on the syslog facility, however, the dosl7d daemon writes directly to its log file ( /var/log/dosl7/dosl7d.log ) rather than using syslog facilities.

This means that the messages dosl7d daemon issues do not pass through the syslog pipe that is the source for almost everything in the syslog-ng configuration.

As a result, the alertd daemon is unable to see the dosl7d messages, therefore, is unable to act on them and trigger SNMP traps.

Note: The article K14397: Running a command or custom script based on a syslog message also makes a reference to this:

Messages generated by the dosl7d process in BIG-IP ASM 11.3.0 and later are not processed by the alertd SNMP process. Layer 7 (L7) denial of service (DoS) messages,therefore, cannot be used for triggering commands or custom scripts.


Recommended Actions

It is possible to have BIG-IP send the dos logs to remote logging server ( using the logging profile with dos enabled ).

This remote logging server should have syslog-ng configured as logger and alertd to make traps from it.
