Known Issue

The BIG-IP system may reboot after verifying a configuration file. This issue occurs when all of the following conditions are met:

  • You verify the configuration file using the tmsh load sys config verify file <configuration file> command.
  • The configuration file contains provisioning configuration for the vCMP module that differs from the running provisioning configuration.

    For example, the configuration file contains no vCMP provisioning configuration while the running provisioning configuration contains the following vCMP provisioning:

    sys provision vcmp {
        level dedicated
    }

The tmsh load sys config verify file <configuration file> command validates the specified configuration file without changing the running configuration.

Impact

The BIG-IP system reboots unexpectedly causing traffic disruptions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H425762 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system reboots unexpectedly.
  • After running the tmsh load sys config verify file <configuration file> command, you observe log messages that appear similar to the following example:

    emerg vcmpd_on_provision: Restarting system for VCMP provisioning change.

Workaround

To work around this issue, you must ensure that the configuration file you want to verify contains the same vCMP provisioning configuration as the running provisioning configuration. For example, if the running provisioning configuration contains the following vCMP provisioning, then the configuration file you want to verify must contain the same vCMP provisioning configuration.

sys provision vcmp {
    level dedicated
}

Alternatively, you can create an empty /shared/noupgrade file before performing the tmsh load sys config verify file <configuration file> command. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. Create an empty /shared/noupgrade file by typing the following command:

    touch /shared/noupgrade

  3. Verify the configuration file using the tmsh load sys config verify file <configuration file> command.
  4. When you are done with the previous step, remove the empty /shared/noupgrade file by typing the following command:

    rm /shared/noupgrade
