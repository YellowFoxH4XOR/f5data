Known Issue

The Online Certificate Status Protocol (OCSP) responses may cache indefinitely when the response contains an error.

This issue occurs when all of the following conditions are met:

  • You configure an OCSP stapling profile and associate it with a clientSSL profile.
  • Your BIG-IP virtual server is configured with the clientSSL profile.
  • The OCSP responder returns an OCSP response that indicates an error.

Impact

The OCSP responses are cached indefinitely.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe OCSP responses that indicate that an error is cached indefinitely. For example, an unauthorized response from the OCSP responder.

Workaround

To work around this issue, you can delete the OCSP responses from the cache, forcing the BIG-IP system to obtain new OCSP responses. To do so, perform the following procedure:

Impact of workaround: This procedure forces the client application to obtain new OCSP responses by sending the OCSP response in the status_request TLS Certificate Status Request extension during the SSL/TLS handshake. The client application can then verify the SSL certificate's revocation status.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Delete the OCSP responses from the cache using the following command syntax:

    delete ltm clientssl ocsp-stapling-responses virtual <virtual_name> clientssl-profile <profile_name>

    For example, to delete all of the cached OCSP responses for the virtual server named example_ocsp_vip referencing the Client SSL profile named example_ssl_profile, type the following command:

    delete ltm clientssl ocsp-stapling-responses virtual example_ocsp_vip clientssl-profile example_ssl_profile
