Description

Processes gtmd and big3d are in a restart loop

Environment

  • BIG-IP LC, GTM or DNS
  • BIG-IP LTM

  • Messages like the following are logged in /var/log/gtm

crit gtmd[…]: 011ae0f1:2: iqmgmt_SSL_init failure: failure to open cert file /config/httpd/conf/ssl.crt/server.crt
crit gtmd[…]: 011ae0f1:2: iqmgmt_SSL_init failure: failure during attempt to use SSL key file /config/httpd/conf/ssl.key/server.key

accompanied by:

notice gtmd[28021]: 011a0007:5: /usr/sbin/gtmd started
notice gtmd[28021]: 011a0051:5: gtmd shutting down.

  • When viewing the status of the gtmd process the restart count continually increases.

  • When viewing the status of the big3d process the restart count continually increases.

  • The BIG-IP DNS/GTM system logs repeating messages to the /var/log/daemon.log file:
    emerg logger: Re-starting gtmd

Cause

  • Corrupt file server.crt
  • Corrupt file server.key
  • Owner and/or group of the file(s) is not root

Recommended Actions

  1. Check that the owner and the group of the files are set to root

    ls -ltra /config/httpd/conf/ssl.crt/server.crt
    ls -ltra /config/httpd/conf/ssl.key/server.key

    If necessary, change the owner and/or the group to root:

    • For server.crt

      chown root /config/httpd/conf/ssl.crt/server.crt
      chgrp root /config/httpd/conf/ssl.crt/server.crt

    • For server.key

      chown root /config/httpd/conf/ssl.key/server.key
      chgrp root /config/httpd/conf/ssl.key/server.key
       

  2. Follow K13349: Verifying SSL certificate and key pairs from the command line to confirm that the certificate and the key match. If necessary, replace the server certificate and the key
