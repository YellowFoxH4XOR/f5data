K000140163: Client drops packets after upgrade to version ≥17.1 due to invalid TCP timestamps

Type
Support Solution
Published
2024-06-27
Updated
2026-03-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.X.X, 17.0.0, 17.0.X, 17.1.0, 17.1.1, 17.1.X
Source
https://my.f5.com/manage/s/article/K000140163

Description

Connection broken due to client dropping packets from BIG-IP fastl4 virtual server (VS)

Environment

  • BIG-IP running 17.1.x

  • Fastl4 VS with embryonic PVA offload configured (default)
  • AFM enabled on BIG-IP
  • TCP timestamps used by client and server

Cause

Incorrect TCP timestamp TSval sent by BIG-IP (such as jumping backwards in time) making the packet unacceptable to the client.

Bug ID 1325681

Recommended Actions

Any of the following will resolve the issue:

  • Disable timestamp cookies under AFM (global command)

tmsh modify security dos device-config dos-device-config dos-device-vector { tcp-ack-ts { tscookie disabled }}

tmsh save sys config

  • Set the fastl4 profile to offload to PVA when the TCP connection is established  (tcp-pva-whento-offload established)
  • Set the fastl4 to rewrite the timestamp (will disable PVA acceleration)

Additional Information

K41305885: BIG-IP AFM DoS vectors

TCP ACK (TS) attack vector was introduced in BIG-IP AFM 17.1.0 and has TS cookie disabled by default when installing AFM from scratch.
