Known Issue

This is the result of a known issue. When accessing SharePoint or another site that uses NTLM authentication through a BIG-IP WebAccelerator, some pages may not load properly and the browser displays an HTTP 400 (Bad Request) response if the <enableAutoNTLMAuth> setting in the /config/wa/pvsystem.conf file is set to true.

The <enableAutoNTLMAuth> setting allows the BIG-IP WebAccelerator to generate a secure session cookie following a successful NTLM authentication on a particular domain for a specific client. The session cookie can be used for future requests from that same client to fetch authenticated content from the BIG-IP WebAccelerator cache, even if an NTLM back-end connection is not currently established.

The BIG-IP WebAccelerator uses the following two cookies for tracking NTLM details:

  • pv_ntlm_session cookie
  • pv_ntlm_auth cookie

The pv_ntlm_auth cookie is added when the <enableAutoNTLMAuth> setting is enabled. Due to corrupted offsets in the code that handles these cookies, a pv_ntlm_auth cookie with a control character (ASCII values 0 to 31) can be presented to the OWS. In reference to RFC2616, this behavior is not permissible, and IIS will return an HTTP 400 (Bad Request) response to the BIG-IP WebAccelerator.

F5 Product Development tracked this issue as ID 327078 and ID 327077 (formerly CR115544 and CR115025) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP release notes.

Workaround

The BIG-IP WebAccelerator uses the pv_ntlm_session and pv_ntlm_auth cookies, not the OWS. To configure the BIG-IP WebAccelerator server-side iRule to remove these cookies from the server-side request, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Back up the original /config/profile_base.conf file by typing the following command:

    cp /config/profile_base.conf /config/profile_base.conf.sol10578

  3. Open the /config/profile_base.conf in a text editor.
  4. Locate the _sys_WA_serverside iRule, which begins with the following line:

    rule _sys_WA_serverside {

  5. Add the following code to the bottom of the HTTP_REQUEST event: 

      if {[HTTP::cookie exists "pv_ntlm_session"]} {
          HTTP::cookie remove "pv_ntlm_session"
        }
        if {[HTTP::cookie exists "pv_ntlm_auth"]} {
          HTTP::cookie remove "pv_ntlm_auth"
        }

  6. Save and close the profile_base.conf file.
  7. Reload the configuration by typing the following command:

    bigpipe load

  8. Clear the BIG-IP WebAccelerator cache by typing the following command:

    wa_clear_cache

    Important: Clearing the cache on the BIG-IP WebAccelerator system will temporarily increase traffic to the origin web servers until the BIG-IP WebAccelerator system repopulates its cache.
