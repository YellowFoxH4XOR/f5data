Description

This article is an aid in creating iRule code for redirecting HTTP/HTTPS requests from the original URL to an alternate URL path based on the host and path of the original request.

Environment

  • BIG-IP
  • Virtual server
  • iRule
  • HTTP profile is required.

Cause

None

Recommended Actions

The following iRule stanza can be used for redirecting to another URL based on a URL path:

when HTTP_REQUEST {
  if { [HTTP::host] equals "host1"} {
    if { [HTTP::path] equals "/path1" } {
      HTTP::redirect "http://host2/path2"
    }
  }
}

For example, when the browser URL path is http://www.example.com/path1 and you want to redirect to http://secure.example2.com/path2, you can use the following code:

when HTTP_REQUEST {
  if { [HTTP::host] equals "www.example.com"} {
    if { [HTTP::path] equals "/path1" } {
      HTTP::redirect "http://secure.example2.com/path2"
    }
  }
}

The following iRule stanza can be used to redirect URL http://host1/path1 it to http://host1/path2 and when URL is http://host2/path3 it will be redirected http://host3/path4:

when HTTP_REQUEST {
  if { ([string tolower [HTTP::host]] eq "host1") and ([string tolower [HTTP::uri]] eq "/path1") } {
        HTTP::redirect "http://host1/path2"
    } elseif { ([string tolower [HTTP::host]] eq "host2") and ([string tolower [HTTP::uri]] eq "/path3") } {
        HTTP::redirect "http://host3/path4"
    }
}

For example, the URL http://www.example.com/path1,  will be redirected to http://www.example.com/path2 while the URL http://secure.example.com/path3 will be redirected to http://secure2.example.com/path4.

when HTTP_REQUEST {
  if { ([string tolower [HTTP::host]] eq "www.example.com") and ([string tolower [HTTP::uri]] eq "/path1") } {
        HTTP::redirect "http://www.example.com/path2"
    } elseif { ([string tolower [HTTP::host]] eq "secure.example.com") and ([string tolower [HTTP::uri]] eq "/path3") } {
        HTTP::redirect "http://secure2.example.com/path4"
    }
}

Note: HTTP requests that do not match the specified host declaration (in the example "www.example.com") and path are not redirected and instead are processed by the virtual server that is configured with the iRule. 
Important: Use a Fully Qualified Domain Name (FQDN) in the redirect hostname.
