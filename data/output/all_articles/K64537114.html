Known Issue

The syslog-ng process experiences high CPU use.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system remote logging configuration includes a destination remote log server that is not available.
  • The BIG-IP system attempts to send the remote log server syslog messages.

Impact

The syslog-ng process uses additional CPU cycles.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • CPU use of the syslog-ng process spikes to 100 percent.

Workaround

To work around this issue, remove unavailable remote log servers from the syslog configuration. To do so, perform one of the following procedures:

  • Removing the log server from a typical remote log server setup
  • Removing the log server from a customized remote log server setup

Removing the log server from a typical remote log server setup

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs > Configuration > Remote Logging.
  3. Under Remote Syslog Server List, click on the affected configuration line; the affected line will be highlighted.
  4. Click Delete.
  5. Click Update.

Removing the log server from a customized remote log server setup

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To remove the unavailable log server that is referenced in the customized syslog configuration, type the following command:

    edit /sys syslog all-properties

    Note: The syslog configuration opens in the vi text editor mode.

  3. Search for the remote log server configuration stanza that contains the IP address of the unavailable log server. The remote log server configuration may appear similar to the following example:

    destination d_remote_loghost {
        tcp(\"10.11.16.253\" port(514));
        udp(\"10.11.16.252\" port(514));
        }    ;

  4. Remove the line that contains the unavailable log server. For example, the remote log server configuration in step 3, should appear similar to the following configuration after removing the unavailable log server with IP address of 10.11.16.253:

    destination d_remote_loghost {
        udp(\"10.11.16.252\" port(514));
        };

  5. To exit the text editor, type the following key sequence:

    :wq!

  6. At the following prompt, type y to save the changes to the file:

    Save changes? (y/n/e)

    Note: The BIG-IP system should save the changes and return you to the tmsh prompt. If the syslog configuration contained syntax errors, tmsh does not allow the changes to be saved and you have to continue editing and fix the errors before proceeding to the next step.

  7. Save the configuration by typing the following command:

    save /sys config
