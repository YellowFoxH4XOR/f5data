Known Issue

This is the result of a known issue. The primary VIPRION cluster may prematurely mark the secondary cluster availability status as red. If a secondary clusterd process loses communication with the primary for more than the heartbeat timeout (currently 10 seconds), the primary clusterd marks the secondary as failed, and secondary cluster availability state becomes red. If the secondary has not crashed, and eventually sends another packet that is received by the primary clusterd process, the secondary availability state returns to green. However, the MCP connection between the primary and secondary clusters is not reestablished when the secondary clusterd state returns to green.

F5 Product Development is tracking this issue as CR117365.

This issue was fixed in BIGIP-9.6.1-839.0-HF3, which has been issued for BIG-IP version 9.6.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
