K71538673: BIG-IQ Fails to Assign License to BIG-IP that had a License Revoked

Type
Support Solution
Published
2021-04-27
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IQ
  • BIG-IQ Centralized Management: 6.X.X, 5.X.X, 7.X.X, 8.X.X
Source
https://my.f5.com/manage/s/article/K71538673

Description

When licensing a BIG-IP that had a license revoked or expired earlier, BIG-IQ tries to assign the license, but it fails after a minute. License Status shows "Installation Failed".

/var/log/ltm on BIG-IP contains log messages similar to this when a license is revoked.

err mcpd[6504]: 01070356:3: vlan failsafe feature not licensed.
err tmsh[9129]: 01420006:3: Loading configuration process failed.
emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all base " - failed. -- 01070356:3: vlan failsafe feature not licensed. Unexpected Error: Loading configuration process failed.
err mcpd[6504]: 01070422:3: Base configuration load failed.

MCP state on BIG-IP shows "base-config-load-failed" as follows.

# tmsh show sys mcp-state
-------------------------------------------------------
Sys::mcpd State:
-------------------------------------------------------
Running Phase                   platform
Last Configuration Load Status  base-config-load-failed

Environment

  • BIG-IP had a valid license earlier and the license has been revoked
  • BIG-IP is configured with a configuration objects that requires a specific license (e.x. VLAN failsafe)
  • BIG-IP is running TMOS version prior to v13.1 (the issue is fixed on v13.1 and later)

Cause

After a license is revoked on BIG-IP, it tries to reload the configuration.

However, the config load fails on BIG-IP because it finds a configuration object in configuration files that requires a specific license.

This is a known limitation of BIG-IP versions prior to v13.1.

Recommended Actions

A possible workaround is to use the iControl REST API to assign a license to an unreachable device.

Following procedure describes how to create a license file on BIG-IQ and manually transfer the license file to the BIG-IP device.

  1. Get the name of the license pool in the BIG-IQ (use appropriate path depending on the type of license pool)

[BIG-IQ] # restcurl -u admin:password /mgmt/cm/device/licensing/pool/purchased-pool/licenses/ | jq -r '.items[0].name'
[BIG-IQ] # restcurl -u admin:password /mgmt/cm/device/licensing/pool/regkey/licenses/ | jq -r '.items[0].name'
[BIG-IQ] # restcurl -u admin:password /mgmt/cm/device/licensing/pool/utility/licenses/ | jq -r '.items[0].name'

<sample output>
reg-key-pool

  1. Get the MAC address of the BIG-IP

[BIG-IP] # tmsh show sys hardware field-fmt |grep base-mac
<sample output>
    base-mac xx:xx:xx:xx:xx:xx

  1. Get the management-ip of the BIG-IP

[BIG-IP] # tmsh list sys management-ip
<sample output>
sys management-ip yy.yy.yy.yy/zz { }

  1. Create/assign an "UNREACHABLE" type license on the BIG-IQ using info found in; create a variable "taskid" with a value of "id"

[BIG-IQ] # taskid=$(restcurl -u admin:password /mgmt/cm/device/tasks/licensing/pool/member-management -d '{"licensePoolName":  "reg-key-pool" , "command": "assign", "address" : "yy.yy.yy.yy" , "macAddress" : "XX:XX:XX:XX:XX:XX" , "hypervisor": "vmware" , "assignmentType": "UNREACHABLE"}' | jq -r '.id')

  1. Get the license text into a file

[BIG-IQ] # restcurl -u admin:password /mgmt/cm/device/tasks/licensing/pool/member-management/${taskid} | jq -r ".licenseText" > bigip.license.out

  1. Check the license file

[BIG-IQ] # less bigip.license.out

  1. Copy the file to BIG-IP

[BIG-IQ] # scp bigip.license.out root@yy.yy.yy.yy:/config/bigip.license

  1. Reboot BIG-IP so that all daemons are aware of the new license

[BIG-IP] # shutdown -r now

Once BIG-IP boots up, it should be able to load config with a valid license.

BIG-IP will function as expected, but it will leave BIG-IQ managing the BIG-IP license with "Device Type: Unreachable".

This means BIG-IQ is not connected to the specific BIG-IP device and some features like Change License and Refresh are not available to use.

If changing "Device Type" from "Unreachable" to "Unmanaged" is required, complete the rest of steps.

  1. Revoke the license from the same BIG-IP that is "Device Type: Unreachable" via GUI (it will not erase license file on BIG-IP)

  2. Assign an appropriate license again via GUI
