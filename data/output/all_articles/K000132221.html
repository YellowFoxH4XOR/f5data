K000132221: Communication between pods returns http2.remote_reset

Type
Support Solution
Published
2023-01-24
Updated
2023-02-10
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K000132221

Description

After TCP Three Way Handshake, the first HTTP2 request returns a 200 OK but the subsequent HTTP2 request returns “http2.remote_reset”

[2023-01-10T14:11:54.569Z] "GET /path/GET HTTP/2" 200 - via_upstream - "-" 0 500 281 280 "-" "user-agent" "a0243ba7-d7df-4e39-8779-db72cccc39d9" "10.130.2.25:30010" "10.130.2.25:30010" outbound|30010||*.example.com 10.128.2.102:42412 10.130.2.25:30010 10.128.2.102:45382 - default

[2023-01-10T14:11:54.857Z] "POST /path/POST HTTP/2" 0 - http2.remote_reset - "-" 309 0 6180 - "-" "user-agent" "a0243ba7-d7df-4e39-8779-db72cccc39d9" "10.130.2.25:30010" "-" outbound|30010||*.example.com - 10.130.2.25:30010 10.128.2.102:45382 - default



Environment

  • Openshift 4.7
  • Aspen Mesh 1.11.x
 

Cause

Two ServiceEntries resources with different IP and same port were used causing Aspen Mesh to try to load balance to an invalid IP.

- apiVersion: networking.istio.io/v1beta1
  kind: ServiceEntry
  metadata:
    name: se-30010
    namespace: ns1
  spec:
    addresses:
    - 10.130.2.25
    endpoints:
    - address: 10.130.2.25
      ports:
        egress: 30010
    hosts:
    - '*.example.com'
    location: MESH_EXTERNAL
    ports:
    - name: egress
      number: 30010
      protocol: HTTP2
    resolution: DNS

- apiVersion: networking.istio.io/v1beta1
  kind: ServiceEntry
  metadata:
    name: se1-30010
    namespace: ns1
  spec:
    addresses:
    - 10.131.2.11
    endpoints:
    - address: 10.131.2.11
      ports:
        egress: 30010
    hosts:
    - '*.example.com'
    location: MESH_EXTERNAL
    ports:
    - name: egress
      number: 30010
      protocol: HTTP2
    resolution: DNS


Recommended Actions

ServiceEntries (SE) with static IP and wildcard host could cause this problem if there's more than one defined in the namespace with the same TCP port; i.e. TCP port should be unique.

Delete one of the SE or use a unique TCP port per IP.

Likewise, reducing the scope of the ServiceEntry by using the exportTo: "." field making this SE applicable only to the current namespace instead of the whole cluster.

- apiVersion: networking.istio.io/v1beta1
  kind: ServiceEntry
  metadata:
    name: se-30010
    namespace: ns1
  spec:
    addresses:
    - 10.130.2.25
    endpoints:
    - address: 10.130.2.25
      ports:
        egress: 30010
    hosts:
    - '*.example.com'
    exportTo:
    - "."
    location: MESH_EXTERNAL
    ports:
    - name: egress
      number: 30010
      protocol: HTTP2
    resolution: DNS
