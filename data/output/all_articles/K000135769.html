Broken authentication attacks

Authentication is the process of validating a person or entity's identity. Your APIs can be vulnerable to broken authentication when authentication mechanisms are lacking or not implemented correctly, allowing attackers to assume other users' identity temporarily or permanently. Attacks that target authentication endpoints include brute-force, credential stuffing, and credential cracking. This can also occur when an API endpoint requires a JSON Web Token (JWT), but there is no mechanism to validate the token.

Depending on the business and application logic, this can lead to attackers gaining control of other users' account in the system, gain access to sensitive personal information, and perform privileged actions on their behalf.

Broken authentication attack scenario

Common attack scenarios for broken authentication include credential stuffing, brute force authentication, and credential cracking. In the following scenario, an attacker performs credential stuffing attacks against different API endpoints. Two authentication endpoints do not have proper authentication mechanisms implemented.

  1. The attacker obtains a password database from a hacker forum.
  2. Since a weak hashing algorithm was used to encrypt passwords, the attacker can expose the user credentials.
  3. The attacker uses credential stuffing tools to test credential pairs on different API endpoints.
  4. If the login is successful, the attacker knows they have a set of valid credentials.

Secure your APIs against broken authentication attacks with F5 products

To protect your APIs, best practices recommend that you use industry standard authentication mechanisms that include multi-factor, brute force protection, and account lockout to secure all API endpoints and authentication flows.

Use BIG-IP APM to mitigate broken authentication attacks

To secure your APIs against broken authentication attacks, you should use industry standard authentication methods. Your authentication mechanism should also be able to implement step-up authentication when the conditions or criteria for authentication changes. BIG-IP APM supports the following authentication types for step-up authentication:

  • Multi-factor authentication through RADIUS authentication
  • Certificate-based authentication
    • On-Demand certificate authentication - BIG-IP APM re-negotiates the SSL connection, requesting and validating the certificate.
    • CRLDP - When coupled with on-demand certificate authentication, Certificate Revocation List Distribution Point (CRLDP) authentication verifies that the certificate is still valid.
    • OCSP - When coupled with on-demand certificate authentication, Online Certificate Status Protocol (OCSP) authentication verifies that the certificate is still valid.
  • Password-based authentication. BIG-IP APM supports the following password-based authentication types:
    • Active Directory
    • HTTP
    • LDAP
    • Local Database
    • RADIUS

  • Access token denylist
