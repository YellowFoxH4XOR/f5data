Known Issue

The TMM process may leak small amounts of memory every time an iRule is triggered from a BIG-IP AFM Access Control List (ACL) rule.

This issue occurs when all of the following conditions are met:

  • The BIG-IP AFM system has been provisioned
  • One or more iRules are triggered from BIG-IP AFM ACL rules.

Impact

TMM memory may eventually become exhausted and may result in the system producing a core file. The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM memory consumption steadily increases over time. You can monitor TMM memory usage using the tmstat command or the following tmsh command:

    tmsh show sys memory

  • TMM (sweeper) starts aggressively ending the connections, due to lack of memory. In the /var/log/ltm file, you may observe error messages similar to the following example:

    warning tmm5[14313]: 011e0003:4: Aggressive mode sweeper: 1 Connections killed
    warning tmm1[14313]: 011e0003:4: Aggressive mode sweeper: 1 Connections killed

  • If configured as a high-availability pair, the BIG-IP system fails over to the standby system.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
