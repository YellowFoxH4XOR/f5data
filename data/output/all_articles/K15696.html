Known Issue

iRules may fail when you invoke the HTTP::path command within the REWRITE_REQUEST_DONE event.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP APM access policy for portal access with Full Patching enabled.
  • You have not configured single sign-on (SSO) in the access policy.
  • You have invoked the HTTP::path command within a REWRITE_REQUEST_DONE event block in an iRule.

For example, the following iRule code may trigger this issue:

when REWRITE_REQUEST_DONE {
if { [HTTP::path] equals "/" } {
# Found the file we wanted to modify
REWRITE::post_process 1
}
}

Impact

The client request hangs and the requested pages do not display.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H478802 on the Diagnostics > Identified > Low screen.
  • Web applications hang or freeze when accessed using BIG-IP APM portal access.
  • Requested pages fail to display when using portal access.

Workaround

To work around this issue, you can invoke the HTTP::path command from the HTTP_REQUEST event. For example, you could replace the previous iRule code with the following code:

Impact of workaround: You should thoroughly test any changes to iRules before placing into production.

when HTTP_REQUEST {
set http_path [HTTP::path]
if { $http_path equals "/" } {
set some_flag 1
} else {
set some_flag 0
}
}

when REWRITE_REQUEST_DONE {
if { $some_flag == 1 } {
# Found the file we wanted to modify
REWRITE::post_process 1
}
}
