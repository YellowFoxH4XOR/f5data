Description

After upgrading BIG-IP APM, users might encounter errors when loading configurations in F5 APM. The errors are as follows:

APM Network Access (/PROD/SAMPLE_Network_Access) DNS name (site1.example.com, site2.example.com, site3.example.com) is not a valid domain name.

Unexpected Error: Loading configuration process failed.

You may see following error in BIG-IP APM GUI:

The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

Environment

  • BIG-IP APM
  • Network Access (VPN) configuration load
  • Special characters used in Network Access DNS Address Space
  • Upgrade to 17.x

Cause

The error occurs due to the presence of non compliant characters (comma in this example) in the DNS Address Space field of the Network Access resource configuration. The field "DNS Address Space" requires domain names not separated with non compliant characters like period, comma, semicolon, colon:

(site1.example.com, site2.example.com, site3.example.com)

Fields should be space delimited:

(site1.example.com site2.example.com site3.example.com)

Recommended Actions

  1. Navigate to Access ›› Connectivity / VPN : Network Access (VPN) : Network Access Lists ›› Network_Access_Resource_Name
  2. Open the Network Settings tab
  3. Locate the field DNS Address Space
  4. Remove any additional special characters and leave only the appropriate Fully Qualified Domain Name(s) (FQDN(s)) that correspond to the IP address, such as dns1.local or dns2.local, depending on your network configuration
    After adjustment the format of DNS Address Space list should look: (site1.example.com site2.example.com site3.example.com)
  5. Test the connection using the FQDN
  6. Attempt to load the config again

Additional Information

Even if you are currently using Full Tunnel mode which does not require DNS Address Space, change temporarily to 'Use split tunneling for traffic' and under Client Advanced Settings check if DNS Address Space does not include any non compliant characters. If yes delete them and switch back to 'Force all traffic through tunnel' mode. Load the config again.
