K000152834: How to Change VLAN IDs on a vCMP Guest

Description

This article describes the process for changing VLAN IDs on a vCMP guest (BIG-IP instance). It outlines the necessary preparation, the importance of updating the vCMP host before the guest, and the steps to ensure a smooth transition without network disruption.

 

Environment

  • Product: BIG-IP LTM (vCMP guest)
  • Platform: vCMP (Virtual Clustered Multiprocessing)
  • Configuration: VLANs configured on both vCMP host and guest, with VLANs potentially shared across route domains and interfaces.

 

Cause

Changing a VLAN ID on a vCMP guest without first allowing the new VLAN ID on the vCMP host can result in a VLAN allowed mismatch. This can cause network connectivity issues for the guest, as the host will not pass traffic for VLANs it does not recognize or allow. The system may log warnings such as "Vlan allowed mismatch found: hypervisor (Example_VLAN:Example_VLAN_ID), guest (/Common/Example_VLAN:Example_VLAN_New_ID)" if the host and guest VLAN configurations are not synchronized.

 

Recommended Actions

  • Preparation
    • Schedule a maintenance window, as changing VLAN IDs can impact network connectivity.
    • Notify relevant teams and take a backup of your configuration (such as a UCS or qkview).
  • Check Host/Hypervisor Configuration
    • Before making changes on the vCMP guest, verify that the new VLAN ID is allowed and properly trunked on the vCMP host (hypervisor).
    • Review system logs for warnings about VLAN mismatches.
  • Update VLAN Configuration on the vCMP Host
    • On the vCMP host, ensure the new VLAN tag (for example, 123 instead of 321) is configured and allowed on the relevant interfaces or trunks.
    • Note: This step is critical to avoid mismatch errors and loss of connectivity.
  • Change VLAN ID on the vCMP Guest
    • Log in to the vCMP guest (the BIG-IP instance).
    • Navigate to Network > VLANs in the GUI, or use the following tmsh command to modify the VLAN tag:
      • tmsh modify net vlan <vlan_name> tag <new_vlan_id>
        • Example:
        • tmsh modify net vlan Example_VLAN tag 123
    • Save the configuration:
      • tmsh save sys config
  • Verify and Test
    • Check the system logs for any warnings or errors after the change.
    • Test connectivity for services using the modified VLAN.
    • Ensure that all self IPs, virtual servers, and route domains referencing the VLAN are still correct.
  • Monitor
    • Continue to monitor the system for any issues or unexpected behavior.

 

Additional Information

If the new VLAN ID is not allowed on the vCMP host, the guest will not be able to use it, and you will see mismatch warnings as shown in your logs.

Always make the change on the host first, then on the guest.
