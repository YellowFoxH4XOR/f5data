K000135430: X-Forwarded Headers don't show DNS SAN custom fields

Type
Support Solution
Published
2023-07-14
Updated
2023-09-20
Applies to
  • Aspen Mesh: 1.11, 1.14
Source
https://my.f5.com/manage/s/article/K000135430

Description

Aspen Mesh Citadel creates X.509 certificates with SAN DNS and URI entries for workloads based on annotations added in service accounts.
After adding the annotation and bouncing the pod to get the new certificate the custom fields are not present in the XFCC headers:

apiVersion: v1
kind: ServiceAccount
metadata:
  name: sleep
  annotations:
   "certificate.aspenmesh.io/customFields": '{ "SAN": { "DNS": [ "test.example.com" ], "URI": [ "urn:com.example.com.fnType": "TEST" ] } }'

{
  "headers": {
    "Accept": "*/*",
    "Host": "httpbin:8000",
    "User-Agent": "curl/8.1.2",
    "X-B3-Parentspanid": "24c7d95859ce1d7a",
    "X-B3-Sampled": "0",
    "X-B3-Spanid": "f136025472cb9e54",
    "X-B3-Traceid": "2c6d0e90667fadb924c7d95859ce1d7a",
    "X-Envoy-Attempt-Count": "1",
    "X-Forwarded-Client-Cert": "By=spiffe://cluster.local/ns/default/sa/httpbin;Hash=518b097cac1e1c024e403fa3d4a56d2fde0c69eee8fef829fdcb0fd2e122e16f;Subject=\"\";URI=spiffe://cluster.local/ns/default/sa/sleep"
  }
}

Even when inspecting the certificate, the custom fields are not added:

➜  aspenmesh-carrier-grade-1.14.6-am3 export POD=$(kubectl get pod -l app=sleep -o jsonpath='{.items[0].metadata.name}')

➜  aspenmesh-carrier-grade-1.14.6-am3 istioctl proxy-config secret $POD -o json | jq '.dynamicActiveSecrets[0].secret.tlsCertificate.certificateChain.inlineBytes' -r | base64 -d | openssl x509 -noout -text | grep -A2 "Subject Alternative Name"
            X509v3 Subject Alternative Name: critical
                URI:spiffe://cluster.local/ns/default/sa/sleep
    Signature Algorithm: sha256WithRSAEncryption

 

Environment

Aspen Mesh 1.14.x, 1.11.x
Certificates created by Citadel with SAN DNS and URI extensions.
 

Cause

Incorrect JSON syntax when adding the custom fields
Looking at the istio-proxy container logs the following log is shown:

➜  aspenmesh-carrier-grade-1.14.6-am3 k logs sleep-557747455f-4kj5t -c istio-proxy | grep -iC1 "annotation"
2023-07-14T18:39:22.832986Z    info    ads    All caches have been synced up in 121.512127ms, marking server ready
2023-07-14T18:39:22.833386Z    warn    cache    could not use customFields annotation: CERTIFICATE_CUSTOM_FIELDS env is not valid json: invalid character ':' after array element
2023-07-14T18:39:22.833402Z    info    sds    SDS server for workload certificates started, listening on "./var/run/secrets/workload-spiffe-uds/socket"

 

Recommended Actions

Change to a JSON valid syntax
For this example, we made the change below because the quotes from the URI were causing a conflict:
from: 

"certificate.aspenmesh.io/customFields": '{ "SAN": { "DNS": [ "test.example.com" ], "URI": [ "urn:com.example.com.fnType": "TEST" ] } }'

to:

"certificate.aspenmesh.io/customFields": '{ "SAN": { "DNS": [ "test.example.com" ], "URI": [ "urn:com.example.com.fnType: TEST" ] } }'

 

Additional Information

After adding the valid JSON syntax, the custom fields are seen in the XFCC header:
