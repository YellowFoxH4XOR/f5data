Known Issue

This is the result of a known issue. If the BIG-IP WebAccelerator receives a non-HTTP response to an accelerated HTTP request, the BIG-IP WebAccelerator may exhaust memory resources and dump core.

This issue is known to occur when the client and server are using the ICY protocol. The ICY protocol is a superset of the HTTP protocol where a client sends an HTTP request and the server responds with a non-HTTP streaming data response. The BIG-IP WebAccelerator attempts to buffer the response looking for HTTP content. The BIG-IP WebAccelerator memory usage will increase until either the stream terminates or the BIG-IP WebAccelerator memory resources are exhausted, causing the BIG-IP WebAccelerator to dump core.

F5 Product Development tracked this issue as CR118238 and CR119969 and it was fixed in BIG-IP 9.4.8 and 10.0.1. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

You can work around this issue by bypassing the BIG-IP WebAccelerator for connections that result in a non-HTTP response from the server. If the HTTP request contains an ICY protocol header, an iRule can be used to bypass the BIG-IP WebAccelerator when the HTTP request contains an ICY protocol header. Additionally, the BIG-IP WebAccelerator's acceleration policy can be configured to bypass the WebAccelerator for URL's known to use a non-HTTP response.
