Description

When deploying SAML on the BIG-IP as the Service Provider, APM sessions are getting crossed.

Environment

  • BIG-IP APM
  • SAML Service Provider (SP) Also applies to Oauth connections as a username is not set
  • Crossed user sessions

Cause

When a user login into the BIG-IP it assigns the session variable 'session.logon.last.logonname' This session variable is what tracks the users session. The absence of a login page where this variable is assigns causes the username to be blank.

Recommended Actions

A username must be assigned in the Access Policy once the SAML Attribute is received from the IdP.

  1. Login to the BIG-IP, Navigate to the Access Policy and edit with the Visual Policy Editor.
  2. Just after the SAML Auth action - create a new Variable Assign
  3. On the left choose Custom Variable (Unsecure) with value of: session.logon.last.logonname
  4. On the right choose Session Variable and your incoming SAML Attribute per the session variables, the default is: session.saml.last.nameIDValue
     
  5. Save and Apply Access Policy and test.  
    Notes: session.logon.last.username/session.logon.last.logonname are interchangeable when assigning the username.
    (You can use other SAML Attributes as well, check the session variables session.saml.last.attr.name.* in the active sessions.)
