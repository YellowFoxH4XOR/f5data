Description

Log messages about status changes of virtual server monitors may include an IPv6 address, even though the monitor is for an IPv4 virtual server.
 

Environment

  • BIG-IP GTM
  • BIG-IP DNS

Cause

Log messages about the status change of a virtual server include both the IP and port of the monitor, as well as the IP address of the iQuery connection that the monitor response was received on. Because IPv4 monitor requests are not limited to IPv4 iQuery channels, an IPv6 address may be logged as the source of the monitor down message:

May 27 06:39:12 GTMEXAMPLE01.mgmt alert gtmd[13369]: 011a4003:1: SNMP_TRAP: Pool /tenant01/www.sample.application.g.f5.com member pol_sample_vs (ip:port=10.20.30.40:8080) state change green --> red ( Monitor /Common/mon_sample_application from fe80:dead:beef:feed::1 : state returned down: disabled directly)

This occurs because the gtmd process may choose an IPv6 iQuery channel to send the monitor request over, even if the monitor request is for an IPv4 virtual server, as long as the BIG-IP GTM server object does have an IPv4 selfIP address. The IPv6 address in the log message is the address of the selfIP that big3d received the monitor request on.
