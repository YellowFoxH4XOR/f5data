K42308420: single or dual core vCMP guests may experience high load if spread across multiple blades

Type
Support Solution
Published
2026-08-14
Updated
2026-08-14
Applies to
  • VIPRION Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K42308420

Description
A single or two core vCMP guest spread across multiple cores may experience high CPU.

Environment

  • This is unique to a Viprion Chassis system with multiple blades running vCMP

Cause
While traffic processing is shared between blades via the disagreggator, and logs and statistics are synced between blades, each guest on each blade is an independent vCMP guest and does not share memory or processing power with its peers on other blades.  This means that a single core or dual core (which shares a single logical core) vCMP guest is effectively underpowered for many use cases.  When that guest is then spanned across multiple blades, large amounts of the guest's limited processing power is spent sending and receiving statistical and logging date between the blades.

Recommended Actions

It is recommended that you either run a single or dual core guest on a single blade, or allocate four or more cores per guest if you will have the guest spanning multiple blades.
