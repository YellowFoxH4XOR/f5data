K000163584: PLM vs NIC/WAF CRDs version mismatch.

Published
2026-10-08

Description

Questions arose around the differences between CRDs provided by PLM(Policy Lifecycle Management) Helm chart and and those provided by NIC(Nginx Ingress Controller) Helm chart.
The main concern is that PLM owns the 'appprotect.f5.com/v1' CRDs  while 3 of those are also included in the NIC chart, but in NIC they are versioned as v1beta1 and in PLM they are v1.
Therefore, when the PLM gets installed with it's v1 CRDs and after that NIC chart is installed together with the default CRDs from the crd/ folder, the installation gets into conflict as beta version cannot replace v1. 

Environment

-NIC 5.6.1
-PLM 5.15.0

Cause

N/A - this is informational only.

Answer/Recommended Actions

Depending on your scenario you need to take a specific action while handling PLM, and NIC CRDs:

1) If this is a new installation NIC+PLM, you need to skip CRDs in Flux/Helm; PLM provides appprotect, crds.yaml provides the rest.
In Helm this can be achieved with '--skip-crds', for Flux it can be achieved with 'spec.install.crds: Skip'

2) Existing NIC+WAF to PLM - follow the upgrade doc, CRD addition is safe and non-breaking: 
https://docs.nginx.com/nginx-ingress-controller/install/plm-upgrade/ 

3) NIC+WAF, no PLM - nothing changes; chart CRDs are correct as shipped

4) Two NIC deployments, one with PLM one without, same cluster - not supported: CRDs are cluster-scoped, so both would be forced onto PLM's v1

Additional Information

The versioning might be confusing but its actually adjusted to support multiple deployment types.

NIC 5.6.1 still supports and ships with "v1Beta1" CRDs which are different and older than "v1" CRDs shipped with PLM as non-PLM WAF deployments is still a supported use-case.

Example of such use-case is: https://docs.nginx.com/nginx-ingress-controller/integrations/app-protect-waf/configuration/

Objects like 'APUserSig' use v1beta1 crds:

apiVersion: appprotect.f5.com/v1beta1
kind: APUserSig

That's why both CRDs versions are required.
