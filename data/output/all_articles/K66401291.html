K66401291: Recreating VCMP Guest from UCS archive

Type

Applies to

Source

Description
In some occasions, there is a need to re-deploy VCMP Guest from archive, either when blade was replaced or guest is not responding and the fastest way is to bring it back from UCS backup.

Environment

  • VCMP Guest rebuild from UCS archive

Cause
Need to re-deploy the guest. 

Recommended Actions

Before re-deploying the guest:

- Make sure you have master-key in case if guest is not in HA/sync cluster.
- If you do not have master-key saved but VCMP Guest was running in HA/sync with other peer, obtain and note the master-key from its peer by typing the following command:
  #f5mku -K

Follow steps to re-build VCMP guest: 

1) Disable affected Guest
   - change the state of the guest to Configured

2) Remove the virtual disk on the affected slot:
   - go to 'Virtual Disk List'
   - wait for a minute so that the status of vdisk will change from 'in use' to 'ready' and delete it

Note: If you are rebuilding Guest and you do not have its virtual disk - in case blade was replaced, proceed with next step:

3) Review base image and hotfix version used in VCMP Guest configuration on VCMP host:

VCMP guests list > click on name of guest and select images matching the last used by VCMP Guest and update VCMP Guest configuration.

4) Change state to provisioned, this will create new virtual image for guest:
   - change the state of the guest to Provisioned

5) Enable guest
   - change the state of the guest to Deployed

6) Log in to vcmp guest and install the master key that you obtained before recreating the guest:
   #f5mku -r <key_value>

6) Restore the config from backup
