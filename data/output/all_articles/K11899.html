Issue

Beginning in BIG-IP 10.1.0, log messages that report a pool status change are no longer throttled.

In versions prior to BIG-IP 10.1.0, log messages that report a pool status change can exceed logging rate limits when a large number of pools suddenly become unavailable. When this event occurs, the BIG-IP system logs a message to the /var/log/ltm file that appears similar to one of the following two examples:

  • BIG-IP 10.0.x:

    01010028:6: Per-invocation log rate exceeded; throttling.

  • BIG-IP 9.4.x:

    01010028: repeated 1 time

Note: For more information about the version 10.0.x error message and a description of throttling, refer to K10524: Error Message: Per-invocation log rate exceeded.

The former behavior may hide critical information from log sifting utilities. For example, if ten different pools simultaneously become unavailable, the BIG-IP system is likely to log only five pool status change messages and one log rate exceeded message. As a result, the logs do not show which additional pools have also become unavailable.

F5 Product Development tracked this change in behavior as ID 205674 (formerly CR115752).
