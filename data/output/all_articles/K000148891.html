K000148891: Websockets are not supported with ASM or AWAF policies configured with APM VDI configurations.

Type
Support Solution
Published
2024-12-06
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP APM
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000148891

Description

Applying a security policy to a virtual server that processes VDI traffic with a websocket and access profile is not supported.

 

Environment

  • Virtual server
  • Security policy
  • Websocket and Access profile

Cause

Using a security policy, access profile and websocket profile for VDI traffic is not officially supported though it may be possible to get working in some rare scenarios.

 

The following iRule effectively bypasses some of the AWAF/ASM functionality when using APM, use of this should be evaluated based on desired overall security policy. As usual, custom iRule changes are not officially supported.

 

Recommended Actions

While it is not recommended it may be possible to use an iRule to disable ASM on websockets requests. The below iRule can be used to disable ASM in requests that have the HTTP header "upgrade" and value of "websocket". You do need to replace "<asm_policy_name>" with the name of the related security policy.

 

-iRule Example to Disable ASM on Requests with Targeted Header:

 

priority 1
when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable 
}

when HTTP_REQUEST {
    if {([string tolower [HTTP::header value \"upgrade\"]] contains \"websocket\")} {
       log local0. \"Websocket found - ASM Disabled!\"
       ASM::disable
       }
    else {
       ASM::enable \"/Common/<asm_policy_name>"
       }
}
