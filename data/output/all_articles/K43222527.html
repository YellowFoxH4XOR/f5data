K43222527: UCS creation fails on Standby BIG-IQ instance

Type
Support Solution
Published
2020-08-05
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K43222527

Description
UCS generation or creation on Standby instance of a BIG-IQ pair can fail with the following error message:

SystemError: Could not save 'bigiq_localhost.ucs', rc=1, error=Password:
Waiting for process config_save (pid:22985) to complete.
Error, waiting for process config_save (pid:22985) took too long.
Unexpected Error: UCS saving process failed.

Environment

  • BIG-IQ
  • Creating UCS

Cause
This is expected behavior as the expected reconstruction mode for a secondary unit is not to restore a UCS file but rather to go through the initial setup wizard then allow the database to sync over.

Recommended Actions

The expectation is that a secondary BIG-IQ instance is rebuilt by connecting it to it's respective primary instance, and not to do any kind of restoration

Additional Information
If your BIG-IQ system is part of an HA pair, create a backup schedule only for the active
Backing up the standby BIG-IQ system in a HA configuration is not supported. To recover the secondary BIG-IQ, you would synchronize from the active BIG-IQ. In the unlikely event that the active and standby BIG-IQ systems fail, use the backup to restore the active BIG-IQ and then synchronize with the standby BIG-IQ.
