Description

  • You are unable to discover a BIG-IP Next instance with BIG-IP Central Manager
  • After attempting to connect to a BIG-IP Next system, Central Manager reports "unable to login to instance with user admin, returned 401"
  • Attempting all known passwords fails.

Environment

  • One or more BIG-IP Next instances
  • BIG-IP Central Manager

Cause

  • The BIG-IP Next admin password that was provided is incorrect.

Recommended Actions

First determine if the BIG-IP system is available without using BIG-IP Central Manager.

curl -sk -XGET https://$IP:5443/api/v1/login -u 'admin:admin' | jq 

You are expecting a JSON response that contains a bearer token.  But you may receive a connection unreachable, connection reset, a 503 internal server error, or a 401 not authorized.

  • Connection unreachable:  most likely, the management IP address of the BIG-IP Next system is not online.  You may need to log into the VM console of the BIG-IP Next VM to determine if networking has been started.  Make sure you are using cloud-init to configure networking on first system boot.
  • Connection Reset:  the BIG-IP Next system is not fully running.  Connections are reset when the f5-csm-api-engine pod is not running.  This is one of the last pods to start because it checks that all other components in the system are running first.  If you encounter a connection reset, you should log into the system console and use Linux and kubectl  commands to determine why the system is not online.
  • 503 internal server error:  This usually means that the system is about to come online.  Keep checking the API endpoint.  If you continue to get 503 internal server errors, one of the BIG-IP Next pods in Kubernetes may be failing to start.  The procedure to troubleshoot this would be the same as for connection resets.
  • 401 Not Authorized:  the username or password is incorrect.
    • The default password is admin/admin.  If the password is incorrect or you need to reset it, you can do so by running 'setup' from the command prompt.  
    • If you are still unable to determine what you set the admin password to, you may need to delete the BIG-IP Next instance and create a new one.
