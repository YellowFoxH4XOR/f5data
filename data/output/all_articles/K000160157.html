K000160157: High-Speed Logging fails to send logs and there is failure publishing errdefs configuration

Type
Support Solution
Published
2026-02-25
Updated
2026-02-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000160157

Description

A BIG-IP device configured for High-Speed Logging (HSL) fails to send logs to remote syslog servers even though the HSL configuration has been verified as correct. Error messages similar to the following appear in /var/log/ltm:

01940010:3: errdefs: failed to add splunk destination /Common/splunk_destination -- the delivering destination /Common/hsl probably doesn't exist or contains errors.

01940014:3: errdefs: failed to associate destination /Common/local-syslog with publisher /Common/local-syslog-publisher -- the destination's configuration likely contains errors.

01940014:3: errdefs: failed to associate destination /Common/splunk_destination with publisher /Common/logging-filter -- the destination's configuration likely contains errors.

01940013:3: errdefs: failed to add filter /Common/logging-filter; configuration rejected

01940015:3: errdefs: failure publishing errdefs configuration.

Environment

BIG-IP

Cause

The errdefsd daemon fails to parse or apply the HSL logging configuration during startup even though the configuration itself is syntactically correct.

Answer/Recommended Actions

Restart the errdefsd process:

tmsh restart sys service errdefsd

Note: Restarting errdefsd should not cause traffic disruption.

Additional Information

The errdefsd daemon is responsible for moving logs from TMM to userland applications and forwarding logs to logging publishers.
