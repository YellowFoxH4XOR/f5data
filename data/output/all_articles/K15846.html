Known Issue

Virtual network interfaces may be re-ordered for BIG-IP Virtual Edition (VE) systems running on VMware ESXi.

This issue occurs when all of the following conditions are met:

  • You create a new virtual machine for the BIG-IP VE system using any of the affected versions on the VMware ESXi.
  • After adding additional virtual network interfaces, up to a total of five or more, you start up the BIG-IP VE system for the first time.

Impact

The network interface identifiers (1.1, 1.2, 1.3, etc.) are mapped to a different pairing order with the MAC addresses on every reboot of the BIG-IP VE system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When reviewing the network interface identifiers and the MAC addresses on the BIG-IP VE system, they appear in a different pairing order on every reboot.
  • A Virtual Local Area Network (VLAN) configured with a network interface identifier before the reboot, changes to a different network interface identifier after the reboot and causes network traffic to be sent to the wrong network interface and wrong VLAN.
  • You cannot boot the BIG-IP VE system to the same network interface identifiers and MAC address pairing order again.

Workaround

To avoid this issue, you should start up the BIG-IP VE system without adding any additional network interfaces first, then add the additional network interfaces as described in K12149: Adding TMM interfaces to the BIG-IP Virtual Edition running on VMware ESXi.
