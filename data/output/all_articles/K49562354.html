Known Issue

The BIG-IP system may produce multiple orphaned bigd instances.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to run a multi-process bigd configuration.
  • The bigd.NumProcs database variable is set to two or higher.
  • You have system monitors with long timeouts of approximately 183 seconds or more.

Impact

The duplicate orphaned bigd processes may become suspended and consume excessive memory and CPU resources, or continue running, resulting in double monitoring.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Multiple bigd processes with the same name appear in the process table. For example, an orphaned bigd.1 will appear alongside the active bigd.1.

Workaround

To work around this issue, you can configure bigd to run as a single process, or shorten the monitor timeouts greater than 183 seconds. To do so, perform one of the following procedures:

  • Configuring bigd to run as a single process
  • Shortening monitor timeouts greater than 183 seconds

Impact of workarounds: Performing the following procedures should not have a negative impact on your system.

Configuring bigd to run as a single process

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To set the bigd.numprocs database variable to one, type the following command:

    modify sys db bigd.numprocs value 1

Shortening monitor timeouts greater than 183 seconds

  1. Log in to the Configuration utility as the administrative user.
  2. Navigate to Local Traffic > Monitors.
  3. Select the child monitor you want to modify.
  4. Change the timeout value to a number lower than 183 seconds.
  5. Click Update.
