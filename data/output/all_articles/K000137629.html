Description

When the BIG-IP APM system logs the warning message "Multidomain SSO enabled for profile: No matching domain found for request host: .", this indicates that a multidomain Single Sign-On (SSO) profile is enabled, but the request host does not match any configured domains. The example log:

warning tmm1[<PID>]: 01490525:4: Multidomain SSO enabled for profile: /Common/<Access profile>. No matching domain found for request host: .

Environment

  • BIG-IP APM
  • Virtual server
  • Access profile
  • Multidomain SSO enabled in the access profile 

Cause

The root cause of this issue is that the access profile is configured with multidomain SSO, but the request host does not match any of the configured domains in the SSO settings. This can occur if the HTTP request is sent using HTTP 1.0, which might not properly include the Host header, or if the Host header is empty or incorrect.

Recommended Actions

  1. Verify SSO Configuration:

Ensure that all required domains are correctly configured within the access profile’s SSO settings.

Confirm that the domain-cookie and domain-groups settings in the APM profile include all necessary domains.

  1. Check Client Requests:

Ensure that clients are sending requests using HTTP 1.1 or later, which properly supports the Host header.

  1. Modify client behavior:

If identified that clients are sending HTTP 1.0 requests, update the client configuration to use HTTP 1.1 or later.
