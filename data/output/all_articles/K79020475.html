Topic

You should consider using this procedure under all of the following conditions:

  • Your BIG-IP Cloud Virtual Edition (VE) is deployed on Amazon Web Services (AWS) using F5 AWS CloudFormation v2.0 on GitHub.
  • You made a change in the configuration of your F5 AWS CloudFormation 2.0 stack and plan to update the stack to apply the change.
Important: Some deployments in F5 AWS CloudFormation v2.0, for example the Example Quickstart deployment, does not support managing the entire deployment exclusively via the template's Update-Stack function. For such cases, this article does not apply.

Description

When you deploy your BIG-IP VE in AWS through F5 AWS CloudFormation v2.0 on GitHub, the configurations are contained in template files. The F5 AWS CloudFormation 2.0 templates consist of the parent template, which takes the name of the Stack. The parent template deploys and contains links to other nested templates and a BIG-IP configuration file. The nested templates provision network and other AWS resources required to get traffic to the BIG-IP VE.

The following example illustrates the hierarchy of the templates of a CloudFormation Stack that deploys an auto-scaling group named BigIp-Autoscale-WAF-Examplename:

Note: The number of nested templates may differ for each deployment. For example, the BigIp-Autoscale-WAF-Examplename-BigipAutoscale-xxxxxx template exist only for BIG-IP auto-scaling group deployments.

Parent template:
BigIp-Autoscale-WAF-Examplename

Nested templates:

BigIp-Autoscale-WAF-Examplename-Access-xxxxxx
BigIp-Autoscale-WAF-Examplename-Network-xxxxxx
BigIp-Autoscale-WAF-Examplename-Function-xxxxxx
BigIp-Autoscale-WAF-Examplename-Dag-xxxxxx
BigIp-Autoscale-WAF-Examplename-Application-xxxxxx
BigIp-Autoscale-WAF-Examplename-BigipAutoscale-xxxxxx

BIG-IP configuration file:

runtime-init-conf-payg.yaml

If you made a change to any one of the files, you need to update the AWS CloudFormation stack to apply the change. For instance, if you modified runtime-init-conf-payg.yaml to add an additional virtual server to the BIG-IP system, you need to update the AWS CloudFormation stack to apply the change. This article describes the procedure to update your AWS CloudFormation stack deployed through F5 AWS CloudFormation v2.0.

Prerequisites

You must meet either one of the following prerequisites to use this procedure:

  • You have access to AWS console and AWS Cloudshell.
  • You have your own client system.
    • You have the AWS Command Line Interface (CLI) version 2 tool installed on your client system.
    • You have run aws configure to configure the tool on your client system.

Procedures

The following procedure illustrates an example where you have an updated runtime-init-conf-payg.yaml file and want to update the AWS stack to use this new configuration. Perform the following procedures to update apply the change.

  • Check for drifts
  • Update the CloudFormation stack
    • Use the AWS Management Console
    • Use the aws tool on the CLI

Check for drifts

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Before updating the stack, you should check for drifts to determine whether the stack has drifted from its expected parameter and template configuration. You can do so from either the AWS Management Console or aws tool. For more information on the procedure, refer to Detect drift in the AWS documentation.

In addition to drifts, you should also note that AWS CloudFormation uses the values you define in the Parameters section ahead of the values in the template file. If you do not define any values for the parameters, AWS CloudFormation uses the default values defined in the template file. Therefore, your existing configuration may differ from those defined in the template files.

  • Update the CloudFormation stack
  • Use the AWS Management Console

Perform the following procedure on AWS Management Console to update your AWS CloudFormation stack.

Impact of procedure: Depending on your change, AWS may destroy and launch a new BIG-IP instance resulting in disruption in services.

  1. Log in to the AWS Management Console.
  2. Go to Services > CloudFormation > Stacks.
  3. Select the parent template.
  4. Select Update.
  5. Select Next to use the Use current template option.
  6. Make a change in one of the fields. For example, for BIG-IP Runtime Init config, enter the URL to the new runtime-init-conf-payg.yaml file. For example:

    https://raw.githubusercontent.com/exampleuser1/exampleReponame/main/runtime-init-conf-payg-v200.yaml

  7. Select Next.
  8. Select Next.
  9. Select the two check boxes to acknowledge the changes that AWS CloudFormation will make.
  10. Select Update stack.
  11. Monitor the events in the Events table of the parent template for the progress.

Use the aws tool on the CLI

You can use the update-stack command in the aws tool to update your stack. When you use the update-stack command to do so, AWS CloudFormation uses the values you define in the --parameters switch ahead of the values in the template file. If you do not define any values for the parameters, AWS CloudFormation uses the default values defined in the template file. Therefore, the actual parameters CloudFormation uses may differ from those you defined in the template files. Perform the following procedure to update your stack using the aws tool either on AWS Cloudshell or on your client system with the tool installed:

Impact of procedure: Depending on your change, AWS may destroy and launch a new BIG-IP instance resulting in disruption in services.

  1. Log in to AWS Cloudshell or your client system with the aws tool installed.

  2. To get a list of all the current parameters in use by CloudFormation, use the following command syntax:

    aws cloudformation describe-stacks --region <region> --stack-name <stackname>

    For example, enter the following command:

    aws cloudformation describe-stacks --region us-east-1 --stack-name BigIp-Autoscale-WAF-Examplename

  3. Create a file to define your parameters. You can define the values for the --parameters switch in a file, for example, param.json. The following example sets the bigIpRuntimeInitConfig parameter to a URL with your new runtime-init-conf-payg.yaml file. The remaining four parameters are required by F5 AWS CloudFormation v2.0.

    Example: param.json

    [
        {
            "ParameterKey": "bigIpRuntimeInitConfig",
            "ParameterValue": "https://raw.githubusercontent.com/exampleuser1/exampleReponame/main/runtime-init-conf-payg-v200.yaml"
        },
        {
            "ParameterKey": "restrictedSrcAddressMgmt",
            "ParameterValue": "10.0.0.0/0"
        },
        {
            "ParameterKey": "restrictedSrcAddressApp",
            "ParameterValue": "0.0.0.0/0"
        },
        {
            "ParameterKey": "notificationEmail",
            "ParameterValue": "john@example.com"
        },
        {
            "ParameterKey": "sshKey",
            "ParameterValue": "mykey"
        }
    ]

  4. To update the CloudFormation stack with the new configuration, use the following command syntax:

    Note: If you need to retrieve the <parent template URL> for your stack, go to the AWS Managment Console > Services > Amazon S3 > <name of bucket> > Objects.

    aws cloudformation update-stack --region <region> --stack-name <stackname> --template-url <parent template URL> --parameters <parameter file URL>

    For example, enter the following command:

    aws cloudformation update-stack --region us-east-1 --stack-name BigIp-Autoscale-WAF-Example --template-url https://cf-templates-xxxxxx-us-west-2.s3.us-west-2.amazonaws.com/autoscale.yaml --parameters file://param.json

  5. The command should exit without errors. In addition, you should also monitor the event logs on AWS Management Console for errors during the update./li>

Additional Information

To retrieve the parent template for your AWS CloudFormation stack, you can go to the Template section of your stack on AWS console or performing the following procedure using the aws tool:

  1. Log in to AWS Cloudshell or your client system with the aws tool installed.
  2. To get the existing parent template of the CloudFormation stack, use the following command syntax:

    aws cloudformation get-template --region <region> --stack-name <stackname> --output text > <output_filename>

    For example, enter the following command to retrieve the template for an existing auto-scaling group:

    aws cloudformation get-template --region us-east-1 --stack-name BigIp-Autoscale-WAF-Example --output text > autoscale.yaml

    You may observe the following three lines the AWS command appended to the end of the template. Remove them.

    STAGESAVAILABLE Original
    STAGESAVAILABLE Processed

  3. Optional: If you made any changes, upload the new template to AWS S3 and obtain the S3 URL to the file. For more information, refer to Uploading objects in the AWS documentation in the AWS documentation.
