Description

  • Deleted an IP entry from 'Shared Objects ›› Address Lists ›› *_auto_http_white_ips_list'
  • Initiated a Sync from this Device to its Peer.
  • The IP address was not removed from the Peer device 'Shared Objects ›› Address Lists ›› *_auto_http_white_ips_list'.
  • Both devices show In-Sync

Environment

  • BIG-IP ASM
  • Entry deleted from Shared Objects ›› Address Lists ›› *_auto_http_white_ips_list'

Cause
An IP Address is listed under a security dos profile's ip-whitelist (deprecated) and also "Shared Objects ›› Address Lists ›› *_auto_http_white_ips_list".

Two examples how this can occur:

  • After upgrading to v13.x or higher, a security dos profile's ip-whitelist is automatically converted to a http_white_ips_list.
  • Manually add an IP address to the security dos profile's ip-whitelist.

  For example:
      # modify security dos profile <security dos profile> application modify { <sub-profile-name> { ip-whitelist add { 1.1.1.1 }}}

      [api-status-warning] security/dos/profile/application, properties : deprecated : ip-whitelist
      There were warnings:
      Attribute ip-whitelist is deprecated; consider using http-whitelist instead

After running the command to add an IP address to the deprecated ip-whitelist attribute, the IP address is automatically added to "Shared Objects ›› Address Lists ›› <security dos profile>_auto_http_white_ips_list"
Bug ID1070077 has been opened to track a fix for this issue.

Recommended Actions

As ip-whitelist is deprecated, removing the entire list will avoid this issue. 
# tmsh
# modify security dos profile <security dos profile> application modify { <sub-profile-name> { ip-whitelist none }}

When adding/removing IP address, it is recommended to do this through *_auto_http_white_ips_list
