Description

Shortly after you supply a declaration via Declarative Onboarding (DO), the BIG-IP reboots unexpectedly.

In /var/log/restnoded/restnoded.log , you may notice the following messages:

<date, time> - fine: [f5-declarative-onboarding: doUtil.js | <taskID>] DO state indicates reboot required
<date, time> - info: [f5-declarative-onboarding: restWorker.js | <taskID>] Reboot required. Rebooting...

Environment

  • BIG-IP
  • Declarative Onboarding (DO) 1.46.0 or earlier

Cause

The declaration supplied does not explicitly provide a value for these 4 files (/config/httpd/conf/ssl.crt/server.crt, /config/httpd/conf/ssl.key/server.key, /config/big3d/client.crt, /config/gtm/server.crt), thus DO will use the original value (saved during initial onboarding). As DO finds that one of the files currently on the BIG-IP differs from its original, DO restores the original and reboots BIG-IP for it to take effect.

Recommended Actions

This is an expected behavior. No additional action is needed.

Starting DO 1.47.0, given the same situation, DO will restart some services instead of rebooting the BIG-IP.

Additional Information

For each declaration submitted (task performed), DO runs the following 4 diff commands internally to determine if any of the 4 files has changed.

diff /config/httpd/conf/ssl.crt/server.crt /config/httpd/conf/ssl.crt/server.crt.DO.orig
diff /config/httpd/conf/ssl.key/server.key /config/httpd/conf/ssl.key/server.key.DO.orig
diff /config/big3d/client.crt /config/big3d/client.crt.DO.orig
diff /config/gtm/server.crt /config/gtm/server.crt.DO.orig

You can check the result of these commands in /var/log/restnoded/restnoded.log to determine if the any of the files has changed.

Example 1

<date, time> - fine: [f5-declarative-onboarding: restWorker.js | <taskID>] {"kind":"tm:util:bash:runstate","command":"run","utilCmdArgs":"-c \"diff /config/httpd/conf/ssl.crt/server.crt /config/httpd/conf/ssl.crt/server.crt.DO.orig\"","commandResult":"<a long string>\n"}

The presence of a long string in "commandResult" indicates that this file has changed. DO will reboot BIG-IP to complete this task.

Example 2

<date, time> - fine: [f5-declarative-onboarding: restWorker.js | <taskID>] {"kind":"tm:util:bash:runstate","command":"run","utilCmdArgs":"-c \"diff /config/httpd/conf/ssl.key/server.key /config/httpd/conf/ssl.key/server.key.DO.orig\""}

The absence of "commandResult" indicates that this command did not return any output, and the file has not changed.

Example 3

<date, time> - fine: [f5-declarative-onboarding: restWorker.js | <taskID>] {"kind":"tm:util:bash:runstate","command":"run","utilCmdArgs":"-c \"diff /config/gtm/server.crt /config/gtm/server.crt.DO.orig\"","commandResult":"diff: /config/gtm/server.crt: No such file or directory\ndiff: /config/gtm/server.crt.DO.orig: No such file or directory\n"}

The "commandResult" indicates that this file does not exist, and will be ignored by DO.
