K000151382: Configuration sync issues and loss of SSH access

Description

BIG-IP LTM systems may experience configuration sync issues and loss of SSH access when the /var partition becomes full. Common error messages include:

  • "Can't create temp directory, [errno 28] No space left on device"
  • "Sync error: Load failed from <path> 010716ca:3: External datagroup file write error (<path>)"

Attempts to generate QKView files or delete images via the GUI may also fail with similar disk space errors.

Environment

  • Product: BIG-IP LTM
  • Platform: F5-BIG-LTM-I5600, C119

Cause

The /var partition is filled due to frequent or scheduled UCS backups accumulating over time without removal. This results in no available disk space, which disrupts system operations such as SSH access, configuration synchronization, and file management.

Recommended Actions

  1. Identify Large Files in /var:
    Run the following command to locate the largest files consuming space in the /var partition:
    find /var -xdev -type f -exec du {} \; | sort -rn | head -20
  2. Delete Old or Unnecessary Files:
    Remove outdated UCS backup files or other large unnecessary files from /var to free up disk space.
    Example:
    rm <file_path>
    *Be sure to retain only recent and necessary backups.*
  3. Verify System Functionality:
    After freeing up disk space:
    • Confirm that SSH access is restored.
    • Ensure that configuration sync between devices is working.
    • Check for resolution of any "no space left on device" errors.
  4. Review Backup Scheduling Practices:
    • Adjust automated UCS backup schedules and retention policies to prevent excessive accumulation.
    • Implement scripts or scheduled tasks to automatically remove old backup files as needed.
  5. General Best Practices:
    • Regularly monitor disk usage across all BIG-IP partitions.
