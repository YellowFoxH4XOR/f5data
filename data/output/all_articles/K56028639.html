Description

  • Device will not boot up properly due to configuration load failure
  • A banner that says "The configuration has not yet loaded. If this message persists, it may indicate a configuration problem." might be visible from the Configuration Utility (GUI)
  • Peer device will show as "Disconnected"
  • Messages similar to the following is observed in /var/log/ltm, where xxxxx_x is the certificate revision number:

01070712:3: Failed: name (/Common/fqdn.hostname.big.ip) Cache path (/config/filestore/files_d/Common_d/certificate_d/:Common:certificate.name._xxxxx_x) does not exist and there is no copy in trash-bin to restore from.

Environment

  • BIG-IP system
  • part of device group
  • reboot or restart of services
  • restoration of configuration

Cause

  • HA pair is configured to use auto sync
  • save on auto sync is not enabled
  • the standby device fails or needs to restart/ reboot for any reason
  • reference to certificate file revision number is not in sync with the contents of the filestore, most likely due to auto sync only saving in memory and not on disk

Recommended Actions

Note: Manually editing the BIG-IP configuration files can result in configuration loss if not done correctly. Please be careful when editing configuration files and always make a backup copy before performing revisions.

1. Make a backup copy of the /config/bigip.conf file. 
2. Run the command tmsh load sys config verify and take note of the certificate name on the error message.
3. Run the command ls /config/filestore/files_d/Common_d/certificate_d/ and compare the revision number in the error message from the previous step.
4. Edit /config/bigip.conf using your favorite text editor and change the certificate name to match what is saved in the filestore.
5. Save the file and run tmsh load sys config verify
6. Repeat steps 3-5 if similar errors are still observed. 
7. If there are no errors found after running the last command, load the config fully by running tmsh load sys config
8. Once configurations are fully loaded, run tmsh save sys config to write the config to disk.


Additional Information

While the above steps pertain specifically to errors referencing the ssl cert lines of the bigip.conf file, the process can be adapted to errors observed with the device trust certificate configuration lines of the bigip_base.conf as well.
