Description

This article is intended to prevent issues when upgrading to BIG-IP versions 16.x or above if you have legacy Application Acceleration Manager (AAM), Web Accelerator Manager (WAM) configurations in place. The scripts below are meant to apply to an entire device, including all partitions, to ensure complete removal of objects that will impede a successful upgrade. The system's configuration parsing process cannot handle these objects, resulting in halted processing and loading failures. Symptoms may include error messages such as:

  • vCMP Guest INOPERATIVE state
  • Configuration load failures
  • Configuration load failures
  • Application not working
  • Profile not found errors

Environment

  • Upgrading to 16.x or above
  • Legacy AAM/WAM/WOM configurations
  • BIG-IP systems with WAM applications deployed
  • AAM module provisioned (whether licensed or not)

Cause

The incompatibility arises due to deprecated AAM and WAM objects in BIG-IP versions 16.x or above. The configuration parser fails to recognize legacy objects during upgrades, resulting in system failures.

Procedures/Recommended Actions

In order to quickly identify and address the modifications needed, you will be using the advanced shell(bash) to run a series of tmsh commands on your system.  The account used needs to have admin permissions across all partitions.
To address and prevent these issues, follow these steps:

  • HA System Procedure
  • Identify Virtual Servers with profiles that need to be removed or updated
  • Identify iApps that are in scope that will prevent the commands from modifying/deleting objects
  • Configuring iApps that are in scope to allow modification and deletion of objects 
  • Configuring Virtual Servers to use Optimized TCP profiles using tmsh
  • Configure TCP Profiles to use Optimized TCP profiles using tmsh
  • Remove AM applications from web acceleration profiles using tmsh
  • Remove AM application using tmsh
  • Command Index
    • Discovery/inventory
    • Modify/Delete

HA System Procedure

The following steps are ONLY for when you are in your change window and you are about to perform the steps to modify and delete elements of your config.
Impact of procedure: Performing the following procedure will disable automatic synchronization and save the running config to disk.

  1. Disable Auto Sync (if enabled).  See Managing configuration synchronization and scroll to section on Enabling and disabling full sync.
  2. If working on the standby device, pull the configuration from the active device. See Managing configuration synchronization and scroll to the section on Manually synchronizing the BIG-IP configuration.
  3. Verify that the configuration does not contain any errors.  
    tmsh load sys config verify partitions all
  4. Save your configuration to disk.  
    tmsh save sys config
  5. Perform all of the commands in the Modify/Delete index (you will execute 7 commands in order).
  6. Verify that all modify and delete commands were completed successfully by re-executing the Discovery/Inventory index (you will execute 10 commands in order).
    1. If there are any of the inventory commands that return data, ensure that you align the findings with the matching Modify/delete commands to remove these issues.
  7. Deprovision AAM. 
    tmsh modify sys provision am level none
  8. Save the config to disk.  
    tmsh save sys config
  9. You may be prompted to reboot the system, perform that at this time. 
    reboot
  10. Once the system is back up and online, force the Active node to Standby.
  11. Test your applications.
  12. If the applications work as expected, then sync the config from the active to the standby node.
  13. Perform steps 7, 8, and 9 on the standby device.
  14. License Activation may be required before a software upgrade.

Identify Virtual Servers with profiles that need to be removed or updated.

In this step, you will execute tmsh commands from bash to list and document the virtual servers and profiles that need to be changed. 
Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Discovery/Inventory - This tmsh command will list all the profiles that were created from the default wam/wom/webacceleration profiles from all partitions.
    ##1 Command to Identify ALL Profiles with WAM/WOM-Based Parent Profiles 
tmsh -c 'cd /; list ltm profile recursive one-line' | grep -E "defaults-from.*(wam|wom|webacceleration)" | awk '{print "/" $4}'
  2. Discovery/Inventory- This tmsh command will list all the virtual servers in all partitions that were created with custom wam/wom/webacceleration profiles:
    ##2 Command to Identify ALL Virtual Servers with WAM/WOM-Based Parent Profiles 
PROFILES="wam-tcp-lan-optimized|wam-tcp-wan-optimized|wom-tcp-lan-optimized|wom-tcp-wan-optimized|"$(tmsh -c 'cd /; list ltm profile recursive one-line' | grep -E "defaults-from.*(wam|wom|webacceleration)" | awk '{print $4}' | tr '\n' '|' | sed '$s/.$/\n/') 
tmsh -c 'cd /; list ltm virtual recursive one-line' | grep -E "(profiles.*($PROFILES))" | awk '{print "/" $3}'
  3. Discovery/Inventory - This tmsh command will list all the virtual servers in all partitions that were created with the default wam/wom tcp profiles(this is for the next step and is a subset of the Virtual Servers).
    ##3 Command to Identify Virtual Servers with default WAM/WOM-Based Profiles 
TCPPROFILES="wam-tcp-lan-optimized|wam-tcp-wan-optimized|wom-tcp-lan-optimized|wom-tcp-wan-optimized" 
tmsh -c 'cd /; list ltm virtual recursive one-line' | grep -E "(profiles.*($TCPPROFILES))" | awk '{print "/" $3}'

Identify iApps that are in scope that will prevent the commands from modifying/deleting objects

If you did not see ".app/" in the results earlier, you can proceed to Configuring Virtual Servers to use Optimized TCP profiles.
If you did see ".app/" in the results earlier, then iApps are present. It is not possible to modify objects directly when they were created by an iApp due to the Strict Updates setting. This is the default setting and can be disabled for each deployed application service.
In this procedure, you will execute tmsh commands from bash to list the iApps and Virtual Servers with wam and wom specific profiles and identify the iApps with Strict Updates enabled.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, it is recommended that you create a backup and perform these action during a maintenance window.

  1. Discovery/Inventory - This tmsh command will list all the iApps and virtual servers in all partitions that were created with custom wam/wom/webacceleration profiles.
    ##4 Command to Identify ALL Virtual Servers built with iApps that are in scope for changes 
## Due to strict-updates being enabled by default, we must use the all-properties directive to list it in the output.
PROFILES="wam-tcp-lan-optimized|wam-tcp-wan-optimized|wom-tcp-lan-optimized|wom-tcp-wan-optimized|"$(tmsh -c 'cd /; list ltm profile recursive one-line' | grep -E "defaults-from.*(wam|wom|webacceleration)" | awk '{print $4}' | tr '\n' '|' | sed '$s/.$/\n/') 
tmsh -c 'cd /; list ltm virtual recursive one-line all-properties' | grep -E "(profiles.*($PROFILES))" | grep -v "app-service none" | awk '{print "iApp " $10 " | Virtual Server /" $3 }'
  2. Discovery/Inventory - This tmsh command will list all the iApps that have Strict Updates enabled in all partitions that were created with custom wam/wom/webacceleration profiles.
    ##5 Command to Identify ALL iApps that have WAM/WOM objects defined and have strict updates set. 
## To allow the scripts in this article to work properly, we must these identify these iApps for this additional step.
## Due to strict-updates being enabled by default, we must use the all-properties directive to list it in the output.
PROFILES="wam-tcp-lan-optimized|wam-tcp-wan-optimized|wom-tcp-lan-optimized|wom-tcp-wan-optimized|"$(tmsh -c 'cd /; list ltm profile recursive one-line' | grep -E "defaults-from.*(wam|wom|webacceleration)" | awk '{print $4}' | tr '\n' '|' | sed '$s/.$/\n/') 
inScopeiApp=$(tmsh -c 'cd /; list ltm virtual recursive one-line all-properties' | grep -E "(profiles.*($PROFILES))" | grep -v "app-service none" | awk '{print $10 }' | tr '\n' '|' | sed '$s/.$/\n/')
tmsh -c 'cd /; list sys application service recursive one-line all-properties' | grep -E "strict-updates enabled" | awk '{ print "/" $4 }' | grep -E $inScopeiApp

Configuring iApps that are in scope to allow modification and deletion of objects

If you did not see ".app/" in the results earlier, you can proceed to Configuring Virtual Servers to use Optimized TCP profiles.
If you did see ".app/" in the results earlier, then iApps are present. It is not possible to modify objects directly when they were created by an iApp due to the Strict Updates setting. This is the default setting and can be disabled for each deployed application service.
In this procedure, you will execute tmsh commands from bash to modify the iApps with wam and wom specific Profiles to disable Strict Updates.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, it is recommended that you create a backup and perform these action during a maintenance window.

  1. Use the following commands to disable Strict Updates in the iApps with wam and wom specific profiles.
    ###1 Command to Modify ALL iApps that have WAM/WOM objects defined and have strict updates set. 
## To allow the scripts in this article to work properly, we must these identify these iApps for this additional step.
## Due to strict-updates being enabled by default, we must use the all-properties directive to list it in the output.
## ***IMPORTANT NOTE - This script aims to specifically target ONLY the iApps needed for the steps below to succeed.  
## Once Strict updates are disabled and changes made to the objects, you can no longer update or use the Reconfigure screen in the GUI.
PROFILES="wam-tcp-lan-optimized|wam-tcp-wan-optimized|wom-tcp-lan-optimized|wom-tcp-wan-optimized|"$(tmsh -c 'cd /; list ltm profile recursive one-line' | grep -E "defaults-from.*(wam|wom|webacceleration)" | awk '{print $4}' | tr '\n' '|' | sed '$s/.$/\n/') 
inScopeiApp=$(tmsh -c 'cd /; list ltm virtual recursive one-line all-properties' | grep -E "(profiles.*($PROFILES))" | grep -v "app-service none" | awk '{print $10 }' | tr '\n' '|' | sed '$s/.$/\n/')
tmsh -c 'cd /; list sys application service recursive one-line all-properties' | grep -E "strict-updates enabled" | awk '{ print "/" $4 }' | grep -E $inScopeiApp | xargs -t -I iAppname tmsh modify sys application service iAppname strict-updates disabled

Configuring Virtual Servers to use Optimized TCP profiles using tmsh

Before upgrading to BIP-IP versions 16.x and above, Virtual Servers that use the TCP profiles wam-tcp-lan-optimized or wam-tcp-wan-optimized have to be modified to use Optimized TCP profiles.  The wam and wom based TCP profiles will not be present in version 16 and above because the conf file(/defaults/wam_base.conf) is removed.
In this procedure, you will execute tmsh commands from bash to list and modify the Virtual Servers using the wam and wom specific TCP Profiles.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, it is recommended that you create a backup and perform these action during a maintenance window.
Note: If the Virtual Server was created using an iApp, you must first disable strict updates before proceeding with the removal steps provided in this section. For detailed instructions on modifying or deleting an iApp, refer to https://my.f5.com/manage/s/article/K51033596  

  1. Discovery/Inventory - This tmsh command will list the Virtual Servers that use default WAM/WOM based TCP profiles.
    ##6 Command to Identify ALL Virtual Servers that have default WAM/WOM TCP profiles set. 
TCPPROFILES="wam-tcp-lan-optimized|wam-tcp-wan-optimized|wom-tcp-lan-optimized|wom-tcp-wan-optimized" 
tmsh -c 'cd /; list ltm virtual recursive one-line' | grep -E "(profiles.*($TCPPROFILES))" | awk '{print "/" $3}'
  2. Use the following commands to modify the TCP Profiles used in the Virtual Servers.  Due to Client side and Server side contexts for the TCP Profiles, we have to handle each context on its own.
    Note: The xarg command will output every command issued.
    1. LAN or Server Side:
      ###2 Command to Modify Virtual Servers with WAM/WOM-Based TCP Profiles (LAN Context)
tmsh -c 'cd /; list ltm virtual recursive one-line' | grep -E "(profiles.*(w(a|o)m-tcp-lan*))" | awk '{print "/" $3}' | xargs -t -I vsName tmsh modify ltm virtual vsName profiles add { f5-tcp-lan { context serverside } } profiles delete { wam-tcp-lan-optimized }
    2. WAN or Client Side:
      ###3 Command to Modify Virtual Servers with WAM/WOM-Based TCP Profiles (WAN Context)
tmsh -c 'cd /; list ltm virtual recursive one-line' | grep -E "(profiles.*(w(a|o)m-tcp-wan*))" | awk '{print "/" $3}' | xargs -t -I vsName tmsh modify ltm virtual vsName profiles add { f5-tcp-wan { context clientside } } profiles delete { wam-tcp-wan-optimized }

Configure TCP Profiles to use Optimized TCP profiles using tmsh

Before upgrading to BIP-IP versions 16 and above, TCP profiles that inherit settings from wam-tcp-lan-optimized or wam-tcp-wan-optimized have to be modified to use Optimized TCP profiles.  The wam and wom based TCP profiles will not be present in version 16 and above because the conf file(/defaults/wam_base.conf) is removed. 
In this procedure, you will execute tmsh commands from bash to list and modify the TCP Profiles that are using the wam and wom specific TCP Profiles.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, it is recommended that you create a backup and perform these action during a maintenance window.
Note: If the TCP Profile was created using an iApp, you must first disable strict updates before proceeding with the removal steps provided in this section. For detailed instructions on modifying or deleting an iApp, refer to https://my.f5.com/manage/s/article/K51033596  

  1. Discovery/Inventory - These tmsh commands will list the TCP Profiles that have a parent profile based on WAM/WOM based TCP profiles. 
    ##7 Command to Identify TCP Profiles with WAM/WOM-Based Parent Profiles (LAN Context)
tmsh -c 'cd /; list ltm profile tcp recursive one-line' | grep -E "defaults-from.Common.w(a|o)m-tcp-lan*" | awk '{ print "/" $4 }'
##8 Command to Identify TCP Profiles with WAM/WOM-Based Parent Profiles (WAN Context) 
tmsh -c 'cd /; list ltm profile tcp recursive one-line' | grep -E "defaults-from.Common.w(a|o)m-tcp-wan*" | awk '{ print "/" $4 }'
  2. Use the following commands to modify the defaults-from aka Parent Profile of the TCP Profiles to use Optimized TCP Profiles.  Due to Client side and Server side contexts for the TCP Profiles, we have to handle each context on its own.
    Note: The xarg command will output every command issued.
    1. LAN or Server Side:
      ###4 Command to Modify TCP Profiles with WAM/WOM-Based Parent Profiles (LAN Context)
tmsh -c 'cd /; list ltm profile tcp recursive one-line' | grep -E "defaults-from.Common.w(a|o)m-tcp-lan*" | awk '{ print "/" $4 }' | xargs -t -I tcp_profile tmsh modify ltm profile tcp tcp_profile defaults-from f5-tcp-lan
    2. WAN or Client Side:
      ###5 Command to Modify TCP Profiles with WAM/WOM-Based Parent Profiles (WAN Context)
tmsh -c 'cd /; list ltm profile tcp recursive one-line' | grep -E "defaults-from.Common.w(a|o)m-tcp-wan*" | awk '{ print "/" $4 }' | xargs -t -I tcp_profile tmsh modify ltm profile tcp tcp_profile defaults-from f5-tcp-wan

Remove AM applications from web acceleration profiles using tmsh

When WAM/AAM is provisioned, the LTM based Web Acceleration profiles gain the ability to define and add an Acceleration Manager Application.  These AM Applications need to be decoupled and deleted entirely for a successful upgrade.
In this procedure, you will execute tmsh commands from bash to list and modify the web acceleration profiles to remove AM Applications.
Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, it is recommended that you create a backup and perform these action during a maintenance window.
Note: If the Web Acceleration Profile was created using an iApp, you must first disable strict updates before proceeding with the removal steps provided in this section. For detailed instructions on modifying or deleting an iApp, refer to https://my.f5.com/manage/s/article/K51033596

  1. Discovery/Inventory - This command will list the web acceleration profiles with AM Applications in them. 
     
    ##9 Command to Identify Web-acceleration Profiles with AM (Acceleration Manager) Applications defined 
tmsh -c 'cd /; list ltm profile web-acceleration recursive one-line' | grep -E "applications {" | awk '{ print "/" $4 }'
  2. Use the following command to remove the AM Applications from all web acceleration profiles in all partitions.
    ###6 Command to Modify Web-acceleration Profiles with AM (Acceleration Manager) Applications defined and remove the AM Applications
tmsh -c 'cd /; list ltm profile web-acceleration recursive one-line' | grep -E "applications {" | awk '{ print "/" $4 }' | xargs -t -I wa_profile tmsh modify ltm profile web-acceleration wa_profile applications none

Remove AM applications using tmsh

When WAM/AAM is provisioned, certain configurations will add an Acceleration Manager Application.  These AM Applications need to be decoupled and deleted entirely for a successful upgrade.
In this procedure, you will execute tmsh commands from bash to list and remove AM Applications.
Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, it is recommended that you create a backup and perform these action during a maintenance window.
Note: If the AM application was created using an iApp, you must first disable strict updates before proceeding with the removal steps provided in this section. For detailed instructions on modifying or deleting an iApp, refer to https://my.f5.com/manage/s/article/K51033596  

  1. Discovery/Inventory - This command will list the AM Applications in all partitions. 
    ##10 Command to Identify AM (Acceleration Manager) objects
tmsh -c 'cd /; list wam application recursive one-line' | awk '{ print "/" $3 }'
  2. Use the following command to remove the AM Applications from all partitions. 
    ###7 Command to Delete AM (Acceleration Manager) objects
tmsh -c 'cd /; list wam application recursive one-line' | awk '{ print "/" $3 }' | xargs -t -I wam_app tmsh delete wam application wam_app

Additional Information

In 2005, F5 bought Swan Labs Corporation to integrate their WAN and web acceleration products into BIG-IP. Originally F5 sold the WAN optimization devices under the WanJet name. Later, the WanJet code base was integrated into TMOS and was sold as WOM. The Web acceleration code was integrated into TMOS and sold as WAM. In 2014 the WOM and WAM modules were combined under the Marketing SKU AAM(Application Acceleration Manager). In April of 2018, the EOS(End of Sale) was announced for AAM and started the clock on the EOSD that culminated in its removal from the TMOS code base with version 16 and higher.

AAM/WAM was most frequently deployed/configured via the now deprecated iApp templates.
