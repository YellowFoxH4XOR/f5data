K000138184: When using traffic.sidecar.istio.io/excludeInterfaces to exclude multus interface, the traffic is still captured.

Type
Support Solution
Published
2024-01-15
Updated
2024-01-15
Source
https://my.f5.com/manage/s/article/K000138184

Description

You cannot exclude interface from k8s node iptables using the 'traffic.sidecar.istio.io/excludeInterfaces' annotation.

 

Environment

Aspenmesh 1.14.6-am3

Openshift 4.12.29

 

Cause

It's not possible to modify interface exclusion from iptables using 'traffic.sidecar.istio.io/excludeInterfaces' annotation for istio below version 1.15.

This feature was added for istio above 1.14.

 

Recommended Actions

There are two possible solutions:

 

1) Wait for AM 1.18 release which includes Istio 1.18. (ETA is 12.23 or 01.24)

2) One possible workaround would be to create an additional container that will manually change iptables after istio-init container is launched and executed. (eth0@if28 is the interface you want to exclude)

Deployment code available below:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: sleep
spec:
  replicas: 1
  selector:
    matchLabels:
      app: sleep
  template:
    metadata:
      labels:
        app: sleep
    spec:
      terminationGracePeriodSeconds: 0
      serviceAccountName: sleep
      containers:
      - name: sleep
        image: curlimages/curl
        command: ["/bin/sleep", "3650d"]
        imagePullPolicy: IfNotPresent
        volumeMounts:
        - mountPath: /etc/sleep/tls
          name: secret-volume
      - name: netshoot
        image: nicolaka/netshoot
        imagePullPolicy: IfNotPresent
        command: ["/bin/bash", "-c"]
        args:
        - >
          sleep
          365d &&
          iptables -A INPUT -i eth0@if28 -j DROP
        securityContext:
          allowPrivilegeEscalation: true
          capabilities:
            add: ["NET_ADMIN", "SYS_TIME", "SYS_ADMIN", "NET_RAW" ]
      volumes:
      - name: secret-volume
        secret:
          secretName: sleep-secret
          optional: true
