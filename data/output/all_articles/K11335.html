K11335: BIG-IP ASM can now silently discard blocked requests

Issue

In versions prior to 10.1.0, when BIG-IP ASM blocks a request, it automatically sends a blocked request response page to the client. Although the page can be customized, it cannot be suppressed.

Beginning in BIG-IP ASM 10.1.0, you can silently discard blocked requests using the new ASM_REQUEST_BLOCKING iRule event.

Note: The ASM_REQUEST_BLOCKING iRule event is triggered before the BIG-IP ASM generates the blocked request response page, providing an opportunity to modify the response before it is sent. For more information, refer to the DevCentral ASM_ REQUEST_ BLOCKING wiki page. A separate DevCentral login is required to access this content.

To silently discard blocked requests without sending a response in BIG-IP ASM 10.1.0, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to the Policy List.
  3. Select the policy you want to modify.
  4. From the Configuration menu, select Advanced.
  5. Select the Trigger ASM iRule event check box.
  6. Save the policy by clicking the Save button.
  7. Apply the policy.
  8. Create an iRule similar to the following example, and apply it to the BIG-IP ASM virtual server:

    when ASM_REQUEST_BLOCKING {
    # log local0. "Request from [IP::client_addr] blocked: [HTTP::uri]"
    discard
    }

    Note: Uncomment the log line to log each blocked request to the BIG-IP ASM log.
