Known Issue

After an upgrade, when you apply more than one HTTP Class profile to a virtual server, the BIG-IP configuration may fail to load.

This issue occurs when all of the following conditions are met:

  • You perform an upgrade from BIG-IP 10.x to 11.0.0 - 11.3.0 and roll forward the configuration, or you install a 10.x user configuration set (UCS) file to a BIG-IP system running 11.0.0 - 11.3.0.
  • A virtual server is configured with more than one HTTP Class profile.
  • The same virtual server is configured with one of the following pre-configured HTTP profiles:
    • http-acceleration
    • http-lan-optimized-caching
    • http-wan-optimized-compression
    • http-wan-optimized-compression-caching

The BIG-IP system fails to properly convert the pre-configured HTTP profiles leading to the configuration load failure.

Note: In BIG-IP 11.x, the compression and RAM Cache features of the HTTP profile were moved into their own separate profiles, named HTTP Compression and Web Acceleration respectively. Prior to BIG-IP 11.x, compression and caching configurations were managed through the HTTP profile.

Impact

The BIG-IP configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H372219 on the Diagnostics > Identified > High screen.
  • The Configuration utility displays a message indicating that the configuration has not yet loaded.
  • In the /var/log/ltm file of the affected system, you may observe messages similar to the following example:

    err load_config_files: "/usr/libexec/bigpipe load" - failed. -- BIGpipe virtual server profile creation error:    01020036:3: The requested profile (http-wan-optimized-compression-caching) was not found.

Workaround

After the configuration has failed to load following an upgrade or UCS install, you can modify the virtual server profile configuration by editing the /config/bigpipe/bigip.conf file, and performing a manual configuration conversion, and reload to recover. Alternatively, to prevent the configuration load failure from occurring, you can remove all but one HTTP Class profile from virtual servers before you upgrade. The latter procedure requires that you re-add the HTTP Class profiles once the upgrade is complete. To recover from or prevent the issue, perform one of the following procedures:

Note: As part of the upgrade process, the BIG-IP system converts the 10.x configuration to the 11.x style configuration. The system stores copies of a modified 10.x configuration in the /config/bigpipe directory on the 11.x system. These files are used only as the source for conversion and are not used for any other function on the system.

  • To recover from the issue, modify the virtual server profile configuration in the /config/bigpipe/bigip.conf file, and perform a manual configuration conversion and reload.
  • To prevent the issue, remove all but one HTTP class profile from virtual servers before upgrading.

To recover from the issue, modify the virtual server profile configuration in the /config/bigpipe/bigip.conf file, and perform a manual configuration conversion and reload

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Make a copy of the /config/bigpipe/bigip.conf file by typing the following command:

    cp /config/bigpipe/bigip.conf /config/bigpipe/bigip.conf.sol80098353

  3. Use a text editor such as vi or pico to edit the /config/bigpipe/bigip.conf file.
  4. Locate the virtual stanza and the profiles stanza within it.

    For example:

    virtual exampleVip {
       destination 10.1.1.1:http
       ip protocol tcp
       httpclass {
          exampleClass
          exampleClass2
       }
       profiles {
          http-wan-optimized-compression-caching { }
          tcp {}
       }
    }
  5. Add the default HTTP profile to the top of the list within the profiles stanza using the following syntax:

    http {}

  6. Replace the 10.x pre-configured HTTP profile with the new 11.x pre-configured HTTP Compression and Web Acceleration profiles per the following table:
    10.x Pre-Configured HTTP Profile11.x Replacement Pre-Configured Profile
    http-accelerationoptimized-acceleration
    http-lan-optimized-cachingoptimized-caching
    http-wan-optimized-compressionwan-optimized-compression
    http-wan-optimized-compression-cachingwan-optimized-compression
    optimized-caching
  7. Review the modifications. After performing steps 5 and 6, the virtual stanza should appear similar to the following example:

    virtual exampleVip {
       destination 10.1.1.1:http
       ip protocol tcp
       httpclass {
          exampleClass
          exampleClass2
       }
       profiles {
          http {}
          wan-optimized-compression { }
          optimized-caching { }
          tcp {}
       }
    }

  8. Repeat steps 4 - 7 for all affected virtual servers.
  9. Save changes to the file, and exit the text editor.
  10. Perform a manual conversion and reload of the configuration by typing the following command:

    Important: You should use the following command only when instructed to do so in an article or by F5 Technical Support.

    /usr/libexec/bigpipe daol

  11. Save the configuration using the Traffic Management Shell (tmsh), by typing the following command:

    tmsh save sys config partitions all

  12. Reload the configuration using the tmsh utility by typing the following command:

    tmsh load sys config partitions all

To prevent the issue, remove all but one HTTP class profile from virtual servers before upgrading

Impact of workaround: The actions of the HTTP class profiles you remove will no longer be performed on virtual server traffic. You will need to re-add the HTTP class profiles after you have completed the upgrade procedure to restore the functionality.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the virtual server you want to modify
  4. Click Resources.
  5. Click Manage to the right of HTTP Class Profiles.
  6. Take note of the HTTP Class profiles you remove, as you need to re-add them after the upgrade.
  7. Select the HTTP Class profile you want to remove.
  8. Click the >> button to move the profile from the Enabled list to the Available list.
  9. Repeat steps 7 an 8 until one profile is left in the Enabled list.
  10. Click Finished.
  11. Repeat steps 3 - 10 for all affected virtual servers.
  12. Proceed with the upgrade.
  13. Once the upgrade has completed, re-add the HTTP class profiles by moving the items you removed in step 8 from the Available list to the Enabled list, using the << button.
