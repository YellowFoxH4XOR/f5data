Known Issue

Executing a TMOS Shell (tmsh) transaction may trigger the apmd process to produce a core file and restart.

This issue occurs when the following condition is met:

  • You use a tmsh transaction to modify and then delete an access policy agent object.

Impact

You are unable to establish an access session while the apmd process restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The apmd process produces a core file in the /shared/core/ directory.
  • The system logs messages to the /var/log/apm file that appear similar to the following example:

    err apmd[<pid>]: 01490000:3: AccessPolicyProcessor/AccessV2Agent.cpp func: "policyItemAgentJoinChange()" line: 306 Msg: EXCEPTION AccessPolicyProcessor/AgentClass. cpp line:89 function: createAgent - initInstance() failed for agent /<partition>/<access policy agent name> type (11)
    err apmd[<pid>]: 01490000:3: AccessPolicyProcessor/AgentPluginHostAPIImpl.cpp func: "getObjectConfigDataImpl()" line: 49 Msg: EXCEPTION
    err apmd[<pid>]: 01490000:3: 27965 skipping recovery from signal 6 apmsig_recover_level :0
    crit apmd[<pid>]: 01490000:2: ** SIGABRT **

Resolution

Status

F5 Product Development has assigned ID 614643 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release13.0.0K2200: Most recent versions of F5 software
HotfixNoneNone

Workaround

To work around this issue, you can use tmsh to modify and then delete the access policy agent manually.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
