Description
In the main device list, the BIG-IP DNS device is showing a green status. But the status for a BIG-IP DNS Sync Group member is showing Blue in the BIG-IQ DNS Sync Groups section of the GUI. Details about the status show that a required service is not running.

To see this is the GUI:
DEVICES -> DNS Sync Groups -> DNS Sync Groups (health shows blue) -> <sync_group_nane>
     Select  <BIG-IP DNS Device Name> that is showing blue status -> HEALTH
         In the Required Services Running section see:
              Status:
                  - Collecting DATA
                  - <BIG-IP DNS Device Name> Waiting for initial data collection

  • Data Collection for the BIG-IP DNS device is working

Environment

  • BIG-IQ managing BIG-IP DNS devices that are in a GTM Sync Group

Cause
This can be caused by failing requests to the REST endpoint /mgmt/tm/services on the BIG-IP. 
To determine if this endpoint is functioning attempt the following request locally on the BIG-IP CLI:
    curl -s -u admin: http://localhost/mgmt/tm/services | jq

Any HTTP response code other than a Status: 200 is a failure.

This can be caused by a service in a failed or non-running state. The error message returned with the endpoint request may contain clues about what service is causing the problem. 

For example:
# curl -s -u admin: http://localhost/mgmt/tm/services | jq
{
  "code": 400,
  "message": "There was a problem parsing the service string: fslogd       finish (pid 1699) 67 days, 1 start, 21533 restarts",
  "referer": "127.0.0.1",
  "restOperationId": 301437195,
  "kind": ":resterrorresponse"
}

The above error call out the fslogd service. tmsh show sys service shows the following status for that service:
tmsh show sys service fslogd
fslogd       finish (pid 1699) 66 days, 1 start, 21533 restarts
    
In the above case stopping and starting fslogd got it back into a good running status and this allowed the REST endpoint /mgmt/tm/services succeed and also resolved the status issue for the BIG-IQ. 

Recommended Actions
If you suspect that the BIG-IQ status for a GTM Sync Group is being affected by this use the following step to narrow the issue. If the issue cannot be resolved by a simple restart of a service contact F5 Support for additional guidance. 

  1. Check to see if requests to the BIG-IP REST endpoint /mgmt/tm/services are failing:
    On BIG-IP CLI:
        curl -s -u admin: http://localhost/mgmt/tm/services | jq .
  2. If the response in the previous step is anything other than "code": 200 the request is failing. 
  3. Attempt to address any services that are not running or in a failed state that should be running on the BIG-IP.
    Use the following command to view the service statuses on the BIG-IP:

    tmsh show sys service

    Note: If unable to resolve a service issue open a BIG-IP case with F5 support for additional assistance.
