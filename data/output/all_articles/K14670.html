Known Issue

sFlow HTTP sampling may cause the Traffic Management Microkernel (TMM) to exit and produce a core file.

This issue occurs when all of the following conditions are met:

  • A virtual server has sFlow sampling configured with non-zero Polling-Interval and Sampling Rate values.
  • You have an sFlow receiver configured.

Impact

The BIG-IP system may exit and fail over to another system in the device group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H429384 on the Diagnostics > Identified > Medium|High screen.
  • You observe an error message in the /var/log/tmm file that appears similar to the following example:

    panic: ../modules/hudfilter/http/http_sflow.c:307: Assertion "len is valid" failed.
  • The TMM process produces a core file in the /shared/core directory.

Workaround

To work around this issue, you can disable sFlow HTTP sampling. To do so, perform the following procedure:

Impact of workaround: You will be unable to use sFlow monitoring.

  1. Log in to the Configuration utility as an administrative user.
  2. Expand the System menu.
  3. Navigate to sFlow > Global Settings.
  4. Click http.
  5. Change the Polling Interval and Sampling Rate values to zero (0).
  6. Click Update.
