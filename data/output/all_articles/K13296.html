Topic

You should consider using this procedure under the following condition:

  • You want to change the value of an access policy session variable using an iRule.

Description

The BIG-IP APM policy daemon (apd) maintains a session cache in its own memory. All sessions variables modified through the apd service's agents sync with the session variables in the Traffic Management Microkernel (TMM) session database (memcache). However, the apd session cache does not update when you modify a session variable using the ACCESS::session data set iRules command.

Note: Attempting to directly change an BIG-IP APM session variable using an iRule has no effect because the iRule does not update the data cached by apd, but instead populates values in memcache.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Your BIG-IP system is configured with BIG-IP APM.

Procedures

  • BIG-IP 12.1.0 and later
  • BIG-IP 12.0.0 and earlier

BIG-IP 12.1.0 and later

You can update a session variable in BIG-IP 12.1.0 and later by assigning it a value in an iRule and retrieve the value directly in a Variable Assign policy item with the mcget -nocache command. The following procedures show an example of setting the session.logon.last.username variable in an access policy to the value 'testuser' with an iRule.

Note: You do no have to use an ACCESS_POLICY_AGENT_EVENT; the mcget -nocache command can directly access information in memcache.

Configuring the iRule

This procedure shows an example of configuring an iRule to set the value of a session variable in memcache. This example sets the session.logon.temp.username variable in the iRule to the value 'testuser' that passes back to the access policy.

Impact of procedure: Performing the suggested procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type APMvariable.
  5. In the Definition box, enter the following text:

    when ACCESS_SESSION_STARTED {
        #Set session variable in memcache to the value 'testuser'
        ACCESS::session data set session.logon.temp.username "testuser"
    }

  6. Click Finished.    

Associating the iRule to the BIG-IP APM virtual server

After you have created the APMvariable iRule, you must associate the iRule with the virtual server that uses the APM access policy. To do so, perform the following procedure:

Impact of procedure: Performing the suggested procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the appropriate virtual server.
  4. Click the Resource tab.
  5. Under iRules, click Manage.
  6. In the Available box, click the iRule that you created in the previous procedure and move it to the Enabled box.
  7. Click Finished.

Configuring an access policy to update the session variable from an iRule variable

This procedure demonstrates an example of configuring an access policy to set the value of the session.logon.last.username variable to a value assigned by an iRule using a temporary variable.

Impact of procedure: Performing the suggested procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles.
  3. In the Access Policy column, click the Edit link on the access profile you want to modify.
    The Visual Policy Editor opens.
  4. Click the (+) on the fallback branch where you want to change the session variable value.

    The Add item window opens.

  5. Click the Assignment tab.
  6. Click the Variable Assign policy item.
  7. Click Add Item.

    The variable assign properties window opens.

  8. Click Add new entry.
  9. Click change.
  10. In the Custom Variable box, type or enter session.logon.last.username.
  11. In the Custom Expression box, type or enter return "[mcget -nocache {session.logon.temp.username}]".
  12. Click Finished.
  13. Click Save.
  14. Select the check box next to the name of the access policy you modified.
  15. Click Apply Access Policy.
  16. Click Close.

BIG-IP 12.0.0 and earlier

You can update a session variable in BIG-IP 12.0.0 and earlier by creating a new temporary session variable on which to assign the value in the iRule and set the original session variable in the access policy to the new value. The following procedures show an example of setting the session.logon.last.username variable in an access policy to the value 'testuser' with an iRule.

Configuring the iRule

This procedure shows an example of configuring an iRule to create a temporary session variable that can be passed to the access policy. This example sets the session.temp_username variable in the iRule to the value 'testuser' that is passed back to the access policy.

Impact of procedure: Performing the suggested procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type APMvariable.
  5. In the Definition box, enter the following text:

    when ACCESS_POLICY_AGENT_EVENT {
      if { [ACCESS::policy agent_id] eq "change_username" } {
           #Set a temporary session variable to the value 'testuser'
           ACCESS::session data set session.temp.username "testuser"
      }
    }

  6. Click Finished.    

Associating the iRule to the BIG-IP APM virtual server

After you have created the APMvariable iRule, you must associate the iRule with the virtual server that uses the BIG-IP APM access policy. To do so, perform the following procedure:

Impact of procedure: Performing the suggested procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the appropriate virtual server.
  4. Click the Resource tab.
  5. Under iRules, click Manage.
  6. In the Available box, click the iRule that you created in the previous procedure move it to the the Enabled box.
  7. Click Finished.

Configuring an access policy to update the session variable from an iRule variable

This procedure demonstrates an example of configuring an access policy to set the value of the variable session.logon.last.username to a value assigned by an iRule using a temporary variable.

Impact of procedure: Performing the suggested procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles.
  3. Click Create.
  4. In the Name box, type iRulevar.
  5. Click Finished.
  6. Click Edit next to the iRulevar access policy.

    An empty access policy opens.

  7. Click (+) on the fallback branch.
  8. Click the iRule Event policy item.
  9. Click Add Item.

    The iRule Event properties window opens.

  10. In the ID box, type change_username.
  11. Click Save.

    The iRule Event policy item is inserted into the access policy.

  12. Click the (+) on the fallback branch of the iRule Event action.

    The Add item window opens.

  13. Click the Variable Assign policy item.
  14. Click Add Item.

    The Variable Assign properties window opens.

  15. Click Add new entry.
  16. Click change.
  17. In the Custom Variable box, type or enter session.logon.last.username.
  18. In the Custom Expression box, type or enter return "[mcget {session.temp.username}]".
  19. Click Save.
  20. Click Apply Access Policy.
  21. Click Close.
