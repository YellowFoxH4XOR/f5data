Description

When a client presents a revoked certificate during a TLS 1.3 handshake with BIG-IP configured for client authentication, the TLS alert sent by BIG-IP is expected to be "certificate revoked" (or "handshake failure" in case generic alert is enabled).

In version 17.1.2, this is the observed behavior:

curl: (56) OpenSSL SSL_read: error:0A000414:SSL routines::sslv3 alert certificate revoked, errno 0

 

However, when 17.5 or other non-17.1.2 version is used, client is unable to decrypt the alert due to "Bad Record MAC":

curl: (56) OpenSSL SSL_read: error:0A000119:SSL routines::decryption failed or bad record mac, errno 0

 

LTM log on both versions indicates the certificate is revoked:

Apr 1 09:00:08 <redacted> warning tmm[16283]: 01260006:4: Peer cert verify error: certificate revoked (depth 0; cert /C=NA/ST=NA/O=NA/OU=NA/CN=NA

 

Environment

  • BIG-IP LTM VE
  • Configuration:
    • TLS 1.3 enabled
    • Client authentication enabled
    • Client presents a revoked certificate
    • Certificate Revocation List (CRL) in use

Cause

The difference in behavior is a result of ID1596637 fix, which was introduced in 17.1.2. The fix was originally targeting other issue, but resolved this one as well.

 

Recommended Actions

Note: Overall, the issue is not disrupting service as the handshake should be failing anyway (as certificate is revoked)

If it crucial to decrypt the alert properly on the client, please create support case and request for Engineering HotFix for ID1596637 (if customer is running version different from 17.1.2).
