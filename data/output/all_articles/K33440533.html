Security Advisory Description

When receiving a unauthenticated client request with a maliciously crafted URI, a BIG-IP Advanced WAF or ASM virtual server configured with a DoS profile with Proactive Bot Defense (versions prior to 14.1.0), or a Bot Defense profile (versions 14.1.0 and later), may subject clients and web servers to Open Redirection attacks. (CVE-2021-22984)

Impact

When a virtual server that has Bot Defense enabled processes the type of request described in this security advisory, the Bot Defense feature incorrectly generates a HTTP 307 status code (Temporary Redirect). As a result, the client experiences an unexpected HTTP redirection, which can potentially be used for a phishing scam or stealing user credentials. In addition, the site in the client request URI unexpectedly receives the redirected request.

Security Advisory Recommended Actions

Workaround

To work around this issue, you can block the type of request described in this security advisory using an iRule. In addition, ensure that the associated Bot Defense profile or DoS profile has the Cross Domain Requests setting configured to the value of either Allow all requests or Allow configured domains; validate in bulk.

To do so, perform the following procedures.

Create and enable the iRule

Impact of workaround: The following iRule may not apply to all environments. F5 recommends authoring an iRule that works best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, the iRule may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. In Name, enter a name for the iRule.

    For example, you enter K33440533workaround.

  5. In Definition, enter an iRule similar to the following example:

    when HTTP_REQUEST {
        log local0. "uri is [HTTP::uri]"
        if { ([HTTP::uri] starts_with "/TSPD/") &&
            ( ([HTTP::uri] contains "orig_host=") || ([HTTP::uri] contains "orig_url_path=") ) }
            {
                HTTP::respond 200 content "blocked\n"
            }
    }

  6. Select Finished.
  7. Go to Local Traffic > Virtual Servers > Virtual Server List.
  8. Select the affected virtual server.
  9. Select the Resources tab.
  10. In the iRules section, select Manage.
  11. Under Available, select the iRule you just created, and then select Move Left (<<).
  12. Select Finished.

Configure the 'Cross Domain Requests' setting

Ensure that you configure the the Cross Domain Requests setting in the associated Bot Defense profile or DoS profile to the value of either Allow all requests or Allow configured domains; validate in bulk. Depending on your BIG-IP ASM version, perform one of the following procedures:

  • BIG-IP ASM 14.1.0 and later
  • BIG-IP ASM versions prior to 14.1.0

BIG-IP ASM 14.1.0 and later

  1. Go to Security > Bot Defense > Bot Defense Profiles.
  2. Select the associated Bot Defense profile.
  3. Under Bot Profile Configuration, select Browser Verification.
  4. On the Cross Domain Requests list, select Allow all requests or Allow configured domains; validate in bulk.

    When you select Allow configured domains; validate in bulk, the Related Site Domains and Related External Domains settings display. Ensure you add the relevant domains to the Related Site Domains setting and the Related External Domains setting remains empty.

  5. Select Save if you made changes to the profile.

BIG-IP ASM versions prior to 14.1.0

  1. Go to Security > DoS Protection > DoS Profiles.
  2. Select the associated DoS profile.
  3. Select the Application Security tab.
  4. Under Application Security, select Proactive Bot Defense.
  5. In the Cross Domain Requests row, select Edit, and then in the list that displays, select either Allow all requests or Allow configured domains; validate in bulk.

    When you select Allow configured domains; validate in bulk, the Related Site Domains and Related External Domains settings display. Ensure you add the relevant domains to the Related Site Domains setting and the Related External Domains setting remains empty.

  6. Select Close.
  7. Select Update if you made changes to the profile.
