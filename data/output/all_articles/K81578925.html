K81578925: Response from REST API slow after upgrade to 14.1.5.1, 15.1.6.1, or 16.0.0 and later

Type
Support Solution
Published
2022-09-20
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IP
  • BIG-IP LTM: 16.0.X, 16.1.0, 16.0.1, 16.0.0, 15.1.7, 15.1.6, 16.X.X, 14.1.5, 16.1.3, 16.1.2, 16.1.1, 15.1.5, 16.1.X
Source
https://my.f5.com/manage/s/article/K81578925

Description

REST API response is very slow after upgrade.

For example:

[root@ltm1:Active:Standalone] config # time curl -sku admin:<pass> https://<mgmt IP>/mgmt/tm/cm/device -o /dev/null

real    0m40.353s       <-- big delay
user    0m0.062s
sys     0m0.021s

No slowness is seen when using localhost instead of the IP address:

[root@ltm1:Active:Standalone] config # time curl -sku admin:<pass> https://localhost/mgmt/tm/cm/device -o /dev/null

real    0m0.185s        <-- very fast
user    0m0.066s
sys     0m0.011s

Environment

  • Version with the fix for ID862693
  • REST API

Cause

Bug ID 1146373

REST supplies PAM with a client IP of null due to the fix for ID 862693, and PAM attempts to resolve null as an FQDN via DNS, which fails repeatedly.

Recommended Actions

Upgrade to a fixed version.

There is no fixed version at the time of this article's publication, so open a service request with F5 Support and request an engineering hotfix for bug ID 1146373.

As a workaround, you can add a static hosts entry for null:

tmsh mod sys global-settings remote-host add { null { hostname null addr 127.0.0.1 } }
