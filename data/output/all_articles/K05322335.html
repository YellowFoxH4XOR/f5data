Topic

You should consider using this procedure under the following condition:

  • F5 Support provided you with a hotfix for iWorkflow.

Description

F5 may provide you with a hotfix for iWorkflow to meet a need or resolve an issue unique to your environment. The process is different for standalone versus clustered iWorkflow configurations.

Prerequisites

You must meet the following prerequisites to perform these procedures:

  • You must have administrative rights on the iWorkflow system.
  • You have a recent user configuration set (UCS) backup of the iWorkflow instance and copied it to a remote secure server for storage.
  • You have confirmed adequate disk available to complete the hotfix installation.
  • You have copied the iWorkflow hotfix ISO to the target iWorkflow instance under the /shared/images directory.
  • You have the target iWorkflow base ISO available under the /shared/images directory.

Procedures

Installing a hotfix on an iWorkflow cluster

F5 recommends that you run iWorkflow in a cluster. When applying a hotfix to an iWorkflow cluster, you must first evict the peers from the cluster and then apply the hotfix to each instance before recreating the cluster. To do so, perform the following procedures, as needed.

  • Breaking the iWorkflow cluster
  • Installing a hotfix on a standalone iWorkflow system
  • Recreating the iWorkflow cluster

Breaking the iWorkflow cluster

When breaking the iWorkflow cluster, removed peers are returned to a default state. All configuration with the exception of management IP details and licensing are removed.

If your environment runs a single iWorkflow server, it is considered a standalone system. If you are running a standalone system, proceed to the Installing a hotfix on a standalone iWorkflow instance procedure.

Impact of procedure: Data stored on the peer that is evicted from the cluster will be lost.

  1. Log in to the iWorkflow administrative user interface with your administrator username and password.
  2. Select the System module from the Top navigation menu.     
  3. Under the iWorkflow cluster panel, double click on the peer you want to remove.

    Note: localhost is the iWorkflow instance you are logged in to directly.

  4. In the Properties panel, to remove the peer you want to evict from the cluster, click Remove.
  5. Repeat steps 2 through 4 for each peer that you want to evict.

    Note: iWorkflow will report the cluster size as unsupported once you remove the first peer until the leader is a standalone instance.

Installing a hotfix on a standalone iWorkflow system

If your environment runs a single iWorkflow server, it is considered a standalone instance. Ensure that you have completed the prerequisites before performing the following procedure.

Important: If you are installing a hotfix on an iWorkflow cluster, you must first break the cluster before installing the hotfix on each iWorkflow instance. If you have an iWorkflow cluster, first perform the Breaking the iWorkflow cluster procedure prior to performing this procedure.

Impact of procedure: While the iWorkflow server is updating, it will be unavailable for administrative access. You will not be able to make updates, changes, or additions to any of the managed BIG-IP systems. Traffic flow on the BIG-IP systems will not be impacted by this work.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Check the status of the currently installed iWorkflow software by typing the following command:

    show /sys software

    The command output appears similar to the following example:

    ------------------------------------------------------
    Sys::Software Status
    Volume    Product  Version     Build  Active    Status
    ------------------------------------------------------
    HD1.1   iWorkflow    2.0.0  0.0.9631     yes  complete
    HD1.2   none            none   none          no   complete

  3. Install the iWorkflow hotfix onto an existing inactive volume using the following command syntax:

    install /sys software hotfix <iworkflow-hotfix.iso> volume <inactive volume>

    In this command, note the following:

    • <iworkflow-hotfix.iso> is the name of the hotfix file
    • <inactive volume> is the name of the inactive volume

    The command output appears similar to the following example:

    install /sys software hotfix Hotfix-iWorkflow-bigiq-mgmt-2.0.0.9999.9999-ENG.iso volume HD1.2

  4. Optional: Create a new volume and install iWorkflow into the new location and automatically reboot when complete using the following command syntax:

    install /sys software hotfix <iworkflow-hotfix.iso> create-volume volume <new volume> reboot

    In this command, note the following:

    • <iworkflow-hotfix.iso> is the name of the hotfix file
    • <new volume> is the name of the new volume

    For example:

    install /sys software hotfix Hotfix-iWorkflow-bigiq-mgmt-2.0.0.9999.9999-ENG.iso create-volume volume HD1.3

  5. Exit the tmsh utility by typing the following command:

    quit

  6. Monitor the installation process by typing the following command:

    Note: By default, the watch command will automatically refresh every 2 seconds.

    watch tmsh show /sys software

    The command output displays similar to the following example:
    -------------------------------------------------------------------
    Sys::Software Status
    Volume    Product  Version      Build  Active                Status
    -------------------------------------------------------------------
    HD1.1   iWorkflow    2.0.0   0.0.9631     yes              complete
    HD1.2   iWorkflow    2.0.0   0.0.9631      no  installing 0.000 pct

    Note: If tmsh appears to stall and reports a waiting for product image message, confirm that you have the base ISO image available in the /shared/images directory.  

Recreating the iWorkflow cluster

You can create a cluster from any iWorkflow instance. However, the peers that will join the cluster should be clean builds. The cluster creation process does not support importing existing configurations from an existing iWorkflow system.

Impact of procedure: When a peer joins the cluster, all existing data stored on the iWorkflow node will be lost. Only the configuration information stored on the lead or initiating iWorkflow instance will be maintained.

  1. Log in to the iWorkflow administrative user interface with your administrator username and password.
  2. Select the System module from the Top navigation menu.
  3. Click the plus (+) icon located in the iWorkflow Cluster header.
  4. In the New iWorkflow Cluster Member panel, enter the peer IP address, admin username, and admin password.
  5. Acknowledge the data on the peer will be overwritten warning message by clicking OK.
  6. Repeat steps 3 through 5 for the third iWorkflow member in the cluster.
