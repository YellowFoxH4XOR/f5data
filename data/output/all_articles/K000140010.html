Description

This article addresses an issue where SNMP requests do not function as expected, resulting in the error message "security service 3 error parsing ScopedPDU". Despite following guidance from other sources, such as K15540412, K000136118, and K15681, the problem persists. This article provides additional insights and solutions to help resolve the error and ensure proper SNMP communication. 

  • Receiving "security service 3 error parsing ScopedPDU" error even if credentials are correct.

Environment

You have configured SNMP, especially version 3.

  • BIG-IP
  • SNMPv3
  • Followed K15540412, K000136118, K15681 and it doesn't help,

Cause

The issue may be caused by the SNMP EngineID. This problem affects aspects beyond those covered in the referenced articles. The EngineID may not be unique, or it could be using an outdated value, leading to the "security service 3 error parsing ScopedPDU" error. Ensuring that the EngineID is unique and correctly updated can help resolve this issue.

Recommended Actions

  1. Log in to the CLI.
  2. Create a new engine ID in hexadecimal value.
    echo -n "anystring" | xxd -p
    Important: You can put any string shorter than 14 characters
  3. Change Engine ID with new one:
    tmsh modify sys snmp include "engineID output_string" 
  4. Restart snmp daemon:
    bigstart restart snmpd
  5. Check whether SNMPv3 is working now using snmpget:
    snmpget -v 3 -u user -a SHA -A "password" -x AES -X "password" -l authPriv 127.0.0.1 .1.3.6.1.2.1.1.3.0

If you still receive the error please follow the below:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click SNMP.
  4. For Agent, click Access (v3).
    The SNMP Access (v3) records are displayed.
  5. Select the check box for all of the SNMP Access (v3) records.
  6. Click Delete.
  7. To confirm the deletion, click Delete.
  8. Log in to the BIG-IP command line.
  9. Stop the snmpd daemon, by typing the following command:bigstart stop snmpd
  10. Change to the /config/net-snmp directory, by typing the following command:cd /config/net-snmp
  11. Using a text editor, edit the snmpd.conf file.
  12. Remove the engineBoots and oldEngineID lines that appear similar to the following examples:
    engineBoots 12
    oldEngineID 0x80000d2f0430783830303031663838384045656137626134373230353032363636
  13. Replace all old values of engine ID in lines such below:
    usmUser 1 3 0x80000d2f0430783830303031663838384045656137626134373230353032363636 0x7361612d75736572 0x7361612d75736572 NULL .1.3.6.1.6.3.10.1.1.3 0xb0fd640d81c449dfa5ba38d9d3f84e7d1a649178 .1.3.6.1.6.3.10.1.2.4 0x19e09bb1909d9f09eb91bc358458b40d138da1d7 "" 0x2f436f6d6d6f6e2f697361615f757365725f3100 

    0x80000d2f0430783830303031663838384045656137626134373230353032363636 <-- Old value
    Replace all old engine values as the upper one with a newly created value from the echo command. 

  14. Save the snmpd.conf file.
  15. Start the snmpd process, by typing the following command:bigstart start snmpd
  16. Recreate the SNMP Access (v3) records that were deleted in step 6 of this procedure.

Now the SNMP should work correctly.

Additional Information

When addressing the "security service 3 error parsing ScopedPDU" issue, remember that creating a new EngineID should result in less than 14 characters long. Although it is essential to verify if the following articles can resolve your issue first: K15540412, K000136118, and K15681, here are additional points to consider:

  1. Verify Unique EngineID: Ensure that the SNMP EngineID is unique and correctly updated. An outdated or non-unique EngineID can cause the parsing error.
  2. Editing Configuration Files: Be cautious when editing configuration files directly. This can be risky and might result in further issues if not done correctly. Also, note that configurations may change after system upgrades.
  3. Backup and Testing: Always back up your current configuration before making any changes and test changes in a staging environment if possible.

By following these guidelines, you can better manage SNMP issues and ensure a stable configuration.
