Description

In certain circumstances a BIG-IP health monitor will fail when you include special characters anywhere in the send string.

Environment

HTTP or HTTPS monitor with a URL or possibly headers that contain one or more special characters.

Cause

In certain cases a special character in the Send String field of a monitor will need to be URL encoded. If the monitor is failing when you expect it to work, try URL encoding the special characters.

For example, both ? and # are reserved characters in the URL. The ? is used to mark the start of query parameters and # is used for referencing anchors within a page, but if the filename contains these characters, the following send strings may lead to a 400 client side HTTP error code:

  • GET /web?page HTTP/1.1\r\nHost: www.example.com\r\n\r\n
  • GET /web#[page] HTTP/1.1\r\nHost: www.example.com\r\n\r\n

A space is considered an unsafe character in a URL and could also result in a 400 HTTP error code. For example:

  • GET /web page HTTP/1.1\r\nHost: www.example.com\r\n\r\n

If you have "200 OK" in the receive string, the 400 response will trigger the BIG-IP to mark the pool down.
These characters can be URL encoded so that the web server understands them. The following list shows sends strings with ?, #, and space URL encoded.

  • GET /web%3Fpage HTTP/1.1\r\nHost: www.example.com\r\n\r\n
  • GET /web%23[page] HTTP/1.1\r\nHost: www.example.com\r\n\r\n
    Note: Both the characters [ and ] are also reserved, but not all special characters need to be URL encoded. It depends on your web server.
  • GET /web%20page HTTP/1.1\r\nHost: www.example.com\r\n\r\n

Recommended Actions

  1. Use a free online URL encoder such as URLEncoder to convert special characters in the send string.
