K000152526: TMM restart loop after upgrade to 17.5.1 on BIG-IP in Azure cloud

Type
Support Solution
Published
2025-07-11
Updated
2025-10-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000152526

Description

  • After upgrading BIG-IP Virtual Edition (VE) to version 17.5.1 on Microsoft Azure, the Traffic Management Microkernel (TMM) process fails to start and enters a continuous restart loop.
  • The following error messages may be observed in the TMM logs:

dpdk: Error: DMA mapping of application heap failed with rte_error Operation not supported 
dpdk: Error: app_heap_dma_map: app heap DMA mapping failed with rte_errno Operation not supported 
dpdk: Error: Removing heap memory (0x400082e00000, 134217728 bytes): Device or resource busy 
xnet_lib [vmbus:eth2]: Error: Failed to initialize driver 
xnet[00:e2.0]: Error: Unable to attach to xnet dev 
xnet(1.2)[00:e2.0]: Error: Unable to initialize device 
ndal Error: Restarting TMM
Initiating TMM shutdown. 

  • The output of lspci -nn on the affected system shows Mellanox Technologies MT27500/MT27520 Family [ConnectX-3/ConnectX-3 Pro Virtual Function] network interfaces.
  • For example
    • [root@bigip:INOPERATIVE:Disconnected] core # lspci -nn
      0002:00:02.0 Ethernet controller [0200]: Mellanox Technologies MT27500/MT27520 Family [ConnectX-3/ConnectX-3 Pro Virtual Function] [15b3:1004]
      0003:00:02.0 Ethernet controller [0200]: Mellanox Technologies MT27500/MT27520 Family [ConnectX-3/ConnectX-3 Pro Virtual Function] [15b3:1004]

Environment

  • Product: F5 BIG-IP Virtual Edition (VE)
  • Version: 17.5.1
  • Platform: Microsoft Azure
  • Network Interface Card (NIC): Mellanox Technologies MT27500/MT27520 Family [ConnectX-3/ConnectX-3 Pro Virtual Function]
  • Azure Feature Enabled: Accelerated Networking

Cause

Bug ID 1977037

The issue is caused by incompatibility between the DPDK/xnet driver stack introduced in BIG-IP 17.5.1 and the Mellanox ConnectX-3 network interface card (NIC), resulting in TMM failing to initialize and entering a restart loop.

Recommended Actions

  • Workaround if you want to use  [ConnectX-3/ConnectX-3 Pro Virtual Function]
    echo 'device driver vendor_dev f5f5:f550 sock' > /config/tmm_init.tcl

reboot
  • If possible, use Azure VM instance types that provide Mellanox ConnectX-4 or ConnectX-5 NICs.

Additional Information

  • Disabling/re-enabling Accelerated Networking or resizing the VM may result in a different NIC model being assigned; however, this is not guaranteed and can change again if the VM is deallocated and restarted.
  • Restarting guestOS inside the guest system (eq. upgrade BIG-IP version, reboot BIG-IP) the NIC card should be the same. 
  • NIC models used in Linux VM change randomly
