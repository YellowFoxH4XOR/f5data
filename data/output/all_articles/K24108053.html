K24108053: Configuring BIG-IP APM Access Profile Same-Site Cookie option

Type
Support Solution
Published
2021-05-06
Updated
2023-12-15
Applies to
  • BIG-IP
  • BIG-IP APM: 16.X.X, 16.1.X, 16.0.X, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 16.0.1, 16.0.0
Source
https://my.f5.com/manage/s/article/K24108053

Description

BIG-IP APM Access Profile Samesite Cookie option is available beginning v16.0.0 BIG-IP Software version.
With the Same-Site cookie attribute, browsers can be controlled whether cookies are sent along with the request initiated by third-party websites.

Environment

  • BIG-IP APM Access Profile
  • Beginning BIG-IP v16.0.0

Cause

Same-Site cookie attribute requirement for APM session cookie (MRHSession cookie)

Recommended Actions

  1. Same-Site cookie attribute can be configured under the selected APM Profile , SSO / Auth Domains section.

Samesite: Enable this setting to add the samesite attribute to the session cookie. This attribute enforces same-site usage and prevents the cookie from being included with cross-site requests. The attribute can have one of three values:

  • Strict: Only include the cookie with requests originating from the same site as the cookie.

Lax: Include the cookie with same-site requests and with top-level cross-site navigations that use a safe HTTP method. The cookie is not sent with cross-site sub-requests such as calls to load images, but is sent when a user navigates to the URL from an external site, such as by following a link.

If you are on a version that does not support the SameSite option for the APM Policy, it is recommended that you upgrade to v16+, which supports this. If this is not possible at this time, then you can try adding the following iRule:

when RULE_INIT {
    set static::apm_cookies { "F5_fullWT" "F5_HT_shrinked" "F5_ST" "LastMRH_Session" "MRHSequence" "MRHSession" "MRHSHint" "TIN" "F5_VdiUserClientChoicecitrix" "F5_VdiUserClientChoicevmware_view" }
}

when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable
}

when HTTP_RESPONSE_RELEASE {
    if { [HTTP::has_responded] } { return };    # Exit if there was a previous HTTP::(respond|redirect|retry)
    foreach apm_cookie ${static::apm_cookies} {
        if { [HTTP::cookie exists ${apm_cookie}] } {
            HTTP::cookie attribute ${apm_cookie} insert "SameSite" None
                if  { ![HTTP::cookie attribute ${apm_cookie} exists "secure"] } {
                        HTTP::cookie attribute ${apm_cookie} insert "Secure"
                }
        }
    }
}

Additional Information

Bug ID 761049: APM does not support adding SameSite cookie attribute to APM cookies.
