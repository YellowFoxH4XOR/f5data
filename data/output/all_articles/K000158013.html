K000158013: Error Publish config via NIM after upgrade 2.20

Type
Support Solution
Published
2025-12-01
Updated
2026-11-18
Applies to
  • NGINX Products
  • NGINX Instance Manager: 2.20.0
Source
https://my.f5.com/manage/s/article/K000158013

Description

Publishing configuration changes via NGINX Instance Manager (NIM) 2.20 fails with deployment errors and missing deployment IDs after the upgrade, preventing config push to NGINX instances.

Environment

NIM

Cause

The db table, 'dpm-queue', is corrupted.

Recommended Actions

1. Make sure all the NMS-based services are running

2. Run this command and make sure `dpm-queue` is present in the list

#nats consumer ls DEPLOYMENTS --server "nats://127.0.0.1:9100"

3. Run this command to delete the queue 

#nats consumer delete dpm-queue DEPLOYMENTS --server "nats://127.0.0.1:9100"

4. Ensure that the `dpm-queue` has been successfully deleted and no longer appears in the list. Run this command to verify.

#nats consumer ls DEPLOYMENTS --server "nats://127.0.0.1:9100"

5. Once verified, restart nms

#systemctl restart nms

6. Wait for some time after the restart, then run this command to check the status; a new `dpm-queue` should be recreated.

#nats consumer ls DEPLOYMENTS --server "nats://127.0.0.1:9100"

7. Check the Configuration Publishing feature again and contact F5 support if the issue persists.
