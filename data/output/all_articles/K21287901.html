K21287901: BIG-IQ/BIG-IP: TACACS+ secret key with pound sign (#) causes authentication failure for administrative accounts (root/admin)

Type
Support Solution
Published
2020-06-24
Updated
2025-07-08
Applies to
  • BIG-IP
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K21287901

Description

  • Unable to login to BIG-IQ/BIG-IP Configuration Utility (aka GUI)


Environment

  • BIG-IQ/BIG-IP
  • Configuration Utility authentication configured with TACACS+
  • TACACS+ key contains the pound sign (#)


Cause

The TACACS+ secret key must not contain the number sign (#). If you configure a Terminal Access Controller Access-Control System Plus (TACACS+) profile for application authentication, and the TACACS+ shared key secret contains a number sign (#), authentication fails. In addition, if you configure TACACS+ authentication to authenticate BIG-IQ/BIG-IP administrative users, and the TACACS+ shared key secret contains a number sign, authentication fails for all administrative accounts including the local root and admin accounts.
 

Recommended Actions

If you configured a TACACS+ profile for application authentication, you can work around this issue by configuring a TACACS+ shared secret that does not contain a number sign. You must make this change on both the BIG-IQ/BIG-IP system and the TACACS+ server. This option only applies if you are still logged in to the BIG-IQ/BIG-IP system.

If you configured TACACS+ authentication for BIG-IQ/BIG-IP administrative users, and you can no longer log in to the BIG-IQ system, restore access by performing the following procedure:

   Reverting to local authentication by booting into single user mode
   Important: The BIG-IQ system is unavailable for the duration of the following procedure. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Connect to the console of the BIG-IQ/BIG-IP VE from the hypervisor management system
  2. Boot the system in single user mode.
        Note: For instructions about booting in single user mode, refer to K4178: Booting the BIG-IP system in single-user mode (GRUB 0.97) and K14662: Restarting the BIG-IP system in single-user mode (GRUB2)
  3. After the device boots into single user mode, a command prompt appears similar to the following example:
        sh-3.2#   
  4. Run "crontab -e", add the line below     */2 * * * * tmsh modify auth source type local
  5. Double-check with "crontab -l" to make sure the line has been added
  6. (Optional) Reset root password using "passwd root"
  7. Restart the BIG-IQ system by typing the following command:     reboot
  8. After the reboot, wait for at least 2 minutes and then login with the root password (or the password set in step #6)
  9. Run "crontab -e", remove the previously added line
