Topic

You should consider using this procedure under the following condition:

  • You want to configure the BIG-IP system to advertise routes for virtual server addresses using the Open Shortest Path First (OSPF) routing protocol.

Description

You can configure Route Health Injection (RHI) for a virtual address so that the BIG-IP system advertises the availability of the address as a host route. When the virtual address is available, the BIG-IP system sends the address information to the neighboring router device, which periodically propagates the virtual address availability according to the RHI information it receives.

For example, if you enable route advertisement for the virtual address 192.168.10.100 and configure OSPF to redistribute kernel routes, the system sends an LS update packet with the LS age timer set to 1 second to advertise the host route to OSPF neighbors. The transaction is shown in the following figure.

Figure: BIG-IP OSPF route advertisement for virtual address 192.168.10.100

If the virtual address becomes unavailable, the BIG-IP system withdraws the route by sending an link state (LS) update packet with the LS age timer set to 3600 seconds. This tells the router to immediately flush the route from its database. The transaction is shown in the following figure.

Figure: BIG-IP OSPF route withdrawal for virtual address 192.168.10.100

When configuring route advertisement for a virtual address, choose the appropriate option to specify the conditions under which the system advertises the routes. To do so, refer to the following table.

SettingDescription
AlwaysThe BIG-IP system always advertises the route for the virtual address, regardless of availability status. This requires an enabled virtual address.
EnabledThe BIG-IP system advertises the route when the virtual address is available.
Disabled (default)The BIG-IP system does not advertise the route for the virtual address, regardless of the availability status.
SelectiveThe BIG-IP system advertises the route for the available virtual address based on the calculation method in Availability Calculation.
AnyThe BIG-IP system advertises the route for the virtual address when any virtual server is available.
AllThe BIG-IP system advertises the route for the virtual address when all virtual servers are available.

To configure the BIG-IP system to advertise routes for virtual server addresses using OSPF, perform the following procedures:

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Your BIG-IP system is licensed to include the OSPF routing protocol.
  • Your BIG-IP system is configured as a OSPF peer with the upstream routers.

Procedures

  • Configuring route advertisement for the virtual server address using the Configuration utility
  • Configuring route advertisement for the virtual server address using tmsh
  • Configuring OSPF to redistribute kernel routes
  • Verifying that the BIG-IP system is advertising the routes using OSPF

Configuring route advertisement for the virtual server address using the Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Address List.
  3. Select the virtual address for which you want to enable route advertisement.
  4. Under Configuration, select one of the following options for Route Advertisement:
    • Always
    • Enabled
    • Selective
    • Any
    • All
  5. Select Update.

Configuring route advertisement for the virtual server address using tmsh

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To configure route advertisement, use the following command syntax:

    modify ltm virtual-address <IP address> route-advertisement <value>

    In the previous example, <value> is one of the following options:

    • Always
    • Enabled
    • Selective
    • Any
    • All

    For example, to enable route advertisement for virtual server address 192.168.10.100, enter the following command:

    modify ltm virtual-address 192.168.10.100 route-advertisement enabled

  3. To save the configuration, enter the following command:

    save sys config

Configuring OSPF to redistribute kernel routes

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To access the IMI shell (imish), enter the following command.

    imish

  3. To enter enable mode, enter the following command:

    enable

  4. To enter configuration mode, enter the following command:

    configure terminal

  5. To enable the OSPF routing process, use the following command syntax, where <ID> is the router ID:

    router ospf <ID>

  6. To configure OSPF to redistribute kernel routes, enter the following command:

    redistribute kernel

  7. Exit the current mode by entering the following command:

    end

  8. Save the configuration by entering the following command:

    copy running-config startup-config

  9. Log out of the imish by entering the following command:

    exit

Verifying that the BIG-IP system is advertising the routes using OSPF

To display routes for virtual addresses that the BIG-IP system has advertised to other routers on the network, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To enter imish, enter the following command.

    imish

  3. To enter enable mode, enter the following command:

    enable

  4. To display routes that the system is advertising or learning, enter the following command:

    show ip route

    For example, the following output indicates that the BIG-IP system is advertising the 192.168.10.100 and 192.168.10.103 virtual server addresses using OSPF:

    Note: The advertised virtual server addresses appear as kernel routes (K) because of the way the Traffic Management Microkernel (TMM) injects the routes into tmrouted.

    K       192.168.10.100/32 [0/0] is directly connected, tmm
    K       192.168.10.103/32 [0/0] is directly connected, tmm
