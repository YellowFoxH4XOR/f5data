Known Issue

This is the result of a known issue. When the response size exceeds the max_filtered_html_length parameter, the BIG-IP ASM fails to pass the response to the client.

The max_filtered_html_length defines the maximum response size that the BIG-IP ASM can accumulate for the purpose of checking or extracting data from the response. By default, the parameter is set to 50MB; if the response size (including the response headers) exceeds the 50MB value, the BIG-IP ASM stops accumulating the response, and logs an error message that appears similar to the following examples to the /var/log/asm file:

01310014:4: ASM filtered HTML exceeded limit: event code C174 Filtered Response HTML exceeded max limit

01310013:6: ASM bad response: event code I1673 Stopped response accumulation / extraction for support id: <14427041639732084746>

F5 Product Development tracked this issue as ID 205836 (formerly CR116240) and it was fixed in BIG-IP 9.4.7 and 10.1.0. For information about upgrading, refer to the BIG-IP ASM Release Notes.

Workaround

You can work around this issue by increasing the max_filtered_html_length parameter. For more information about increasing the max_filtered_html_length parameter, refer to K5979: The BIG-IP ASM does not parse HTTP responses longer than 50 MegaBytes.
