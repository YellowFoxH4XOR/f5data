Known Issue

This is the result of a known issue. A VIPRION platform running BIG-IP version 9.6.x that is upgraded for the first time to BIG-IP version 10.0.x will fail to install the new BIOS if a version 10.0.x hotfix is also installed at this stage. When this behavior occurs, the VIPRION platform will log the following error message on the console during the first boot from BIG-IP version 10.0.x:

Updating BIOS to /usr/firmware/puma-bios-461.rom
Updating BIOS... DO NOT POWER DOWN
sh: /bin/bios_update: No such file or directory
BIOS update failed. Check /var/log/ltm for errors

Additionally, since the BIOS was not upgraded, you may also experience the issue described in K10016: A VIPRION kernel panic occurs following an upgrade to BIG-IP version 10.0.0. In order to run BIG-IP version 10.0.x on the VIPRION platform, the BIOS version must be build 461 or later. If necessary, a new BIOS is installed automatically during the upgrade to BIG-IP version 10.0.x.

The new BIOS is not installed when a BIG-IP Administrator uses one of the following installation methods to upgrade to BIG-IP version 10.0.x and a hotfix in a single step (without booting the VIPRION platform from the 10.0.x destination volume before the hotfix is installed):

  • Using the Software Management section in the Configuration utility
  • Using the bigpipe software command
  • Using the image2disk utility

F5 Product Development is tracking this issue as ID 329845 (formerly CR128577).

Workaround

In order to avoid this issue, you must install BIG-IP version 10.0.x to a destination volume of your choice, and boot the VIPRION platform from the chosen volume at least once before installing a hotfix.

Important: The first time you boot from the version 10.0.x destination volume, all management interfaces will have to be disconnected or the VIPRION platform may encounter a kernel panic before the BIOS upgrade can occur.

If you have already experienced this issue, you will most likely experience the issue described in SOL10016. You can work around this issue by performing the following procedure:

  1. Power off the VIPRION platform.
  2. Disconnect the network cable from all management interfaces.

    Note: This step prevents the issue described in SOL10016 from occurring during the next boot.
  3. Power the VIPRION platform back on.
  4. After all the blades have finished booting, you may reconnect the network cable to the management interfaces, if needed.
  5. Using an installation method of your choice, install BIG-IP version 10.0.x to any destination volume. Do not install a hotfix at this time.
  6. After the installation has completed on all blades, disconnect the network cable from all management interfaces.
  7. Boot the VIPRION from the destination volume where you just installed BIG-IP version 10.0.x. The BIOS will be upgraded, and you will not experience the issue described in SOL10016 because the management interfaces are disconnected.
  8. After all the blades have booted and have upgraded their BIOS, you may reconnect the management interface cables and also install a version 10.0.x hotfix.
