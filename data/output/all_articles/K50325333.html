Known Issue

The BIG-IP Analytics profile with High Speed Logging (HSL) remote logging may fail to generate external reports after the BIG-IP system is rebooted.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is provisioned with the BIG-IP Analytics module.
  • A virtual server is associated with an Analytics profile that includes the following properties:
    • The Traffic Capturing Logging Type setting is set to Internal and External.
    • The Statistics Logging Type setting is set to Internal and External.
    • The Publisher is set to the Log Destination where the associated Log Publisher type is set to Remote High-Speed Log.
  • The BIG-IP system is being rebooted.

Impact

The BIG-IP system does not publish external reports and statistics logs by way of HSL.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H566419 on the Diagnostics > Identified > Medium page.
  • After the BIG-IP system reboots, the Application Visibility and Reporting (AVR) external logging is not functioning as expected.
  • In the /var/log/avr/avrd.log file, you observe error messages similar to the following examples:

    AVRD_GENERAL|NOTICE|Jul 30 14:58:50.014|11081|lib/avrpublisher/infrastructure/avr_publishing_hq.cpp:0048|Starting thread: [istats]
    AVRD_GENERAL|NOTICE|Jul 30 14:58:50.014|11081|lib/avrpublisher/infrastructure/avr_publishing_hq.cpp:0206|AVR Daemon started
    AVRD_GENERAL|NOTICE|Jul 30 14:58:50.014|11081|lib/avrpublisher/infrastructure/avr_publishing_hq.cpp:0063|Waiting for thread: [istats]...
    AVRD_CONFIG|ERROR|Jul 30 14:58:50.045|14205|lib/avrpublisher/infrastructure/avr_sender_hsl.cpp:0079|Failed to open HSL publisher [/Common/local-db-publisher]

Workaround

To recover from this issue, you can manually restart the avrd process when the BIG-IP system resumes to ready status after it was rebooted.

To restart the avrd process, type the following command:

tmsh restart /sys service avrd
