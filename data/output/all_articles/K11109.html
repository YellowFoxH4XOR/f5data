Topic

Persistence record timer behavior differs between the following BIG-IP version ranges:

BIG-IP versions 9.0 through 9.4.8 and versions 10.1.0 and later

In BIG-IP versions 9.0 through 9.4.8 and versions 10.1.0 and later, the BIG-IP resets a connection's persistence record timer to 0 (zero) for each packet the system receives for the existing connection. If the BIG-IP does not receive any packets within the persistence time specified, the BIG-IP clears the persistence record from memory.

When the BIG-IP receives a packet for an existing connection through the virtual server with the following configuration, the BIG-IP will reset the persistence timer:

  • The default TCP profile with a 300-second idle timeout
  • Simple Persistence with a 180-second idle timeout

For example:

virtual 172.17.1.200:http node 10.10.10.100:http age 0sec

If the BIG-IP does not receive any packets within the 180-second idle timeout period, the BIG-IP removes the persistence record from memory. If the BIG-IP receives a packet within the 300-second idle timeout specified by the TCP profile, but after the BIG-IP has removed the persistence record, the BIG-IP will create a new persistence record after making a load balancing decision.

BIG-IP versions 9.6 through 10.0.1

In BIG-IP versions 9.6 through 10.0.1, the BIG-IP only updates the persistence record timer for a connection when the BIG-IP removes the existing connection or establishes a new connection within the same persistence session.

When the BIG-IP receives a packet for an existing connection through a virtual server with the following configuration, the BIG-IP will not reset the persistence timer:

  • The default TCP profile with a 300-second idle timeout
  • Simple Persistence with a 180-second idle timeout

For example:

virtual 172.17.1.200:http node 10.10.10.100:http age 300sec

The persistence record age will continue to increment past the persistence idle timeout value, until one of the following conditions is met:

  • A new connection matching the persistence record is opened, resetting the persistence record timer to 0.
  • The last connection matching the persistence record is removed from the connection table, resetting the persistence record timer to 0.
  • The persistence record timer has reached the persistence idle timeout, and no matching entries remain in the connection table. At that time, the persistence record is removed from the persistence table.

Therefore, regardless of the age displayed for a persistence entry, persistence will remain in effect until the entry is removed from the persistence table as described above.

Note: The persistence record timer behavior in BIG-IP versions 9.6 through 10.0.1 was intended to more effectively support persistence records for CMP enabled virtual servers. However, the behavior resulted in the BIG-IP not calculating persistence record ages consistently between TMMs on CMP systems. The 9.6 through 10.0.1 behavior was reverted back to the 9.x behavior in BIG-IP version 10.1.0 and later. For more information, refer to K11399: The BIG-IP does not calculate persistence record ages consistently between TMM instances.
