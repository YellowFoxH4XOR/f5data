K37140051: GUI node monitor reporting non-accurate time stamp after disabling it or put it in force offline status

Type
Support Solution
Published
2021-06-18
Updated
2023-02-21
Source
https://my.f5.com/manage/s/article/K37140051

Description

When the node is disabled or put offline by user, the gui management interface is going to tag this node status with the message "user disabled, or forced offline" with the related time stamp. If that node has a monitor and the actual physical node is still responding to monitor, it will show the status as available also. If that node flapped up and down, the gui will still show the message of user disabled, but the time stamp will reflect the last change tagged by monitor, which will confuse the administrator as he is going to think that the user was disabled at that tagged time stamp while this time stamp reflect later change due to monitor flapping. For example on the below logs the node was disabled manually one time and stayed disabled. The first log indicate the time that the node was disabled, the second log indicate the time after monitor flapped up and down.

Available (Disabled) - Pool member is available, user disabled 2020-05-20 07:08:42
Available (Disabled) - Pool member is available, user disabled 2020-05-20 07:10:47

This behavior is confusing to the user as it kind of referring on the second log that the node was disabled at the second log time stamp while it was disabled before.

Environment

  • Node or pool member configured with monitor.
  • Node or pool member is manually disabled or forced offline.
  • Monitor flap/change status while the node tagged as disabled.

Cause

The GUI management interface tag the time stamp of most recent activity with the current status of the node/pool member.

Recommended Actions

Look for the actual event history on the audit log under /var/log/audit for the accurate time stamp history for related events.
