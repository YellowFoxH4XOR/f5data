Description

The BIG-IP user interface (UI) becomes unresponsive or locks up when making changes or viewing APM configurations. Symptoms include:

  • The UI disconnects and attempts to reconnect when editing APM policies
  • The tmsh (Traffic Management Shell) hangs until services are reestablished
  • The "New Support Snapshot" (QKView) button in the UI is grayed out
  • Log messages in /var/log/messages indicate repeated process restarts and memory exhaustion, such as:
    • OOM (Out-of-Memory) killer events
    • Swap exhausted: Free swap = 0kB
    • Processes killed: icrd_child, java (tomcat/restjavad), tmsh
    • Example log:

    notice syslog-ng[3577]: Configuration reload request received, reloading configuration;

    ...

    free:22974 free_pcp:0 free_cma:0

    ...

    1319 113][HTTP::respond 429 content "Request Denied: Exceeded requests/sec limits"

Environment

  • Product: BIG-IP APM (Access Policy Manager)
  • Product Group: BIG-IP
  • Configuration: APM policies, BIG-IP LTM virtual servers
  • Management daemons: restjavad, restnoded, tomcat, icrd_child
  • Swap and memory exhaustion observed in system logs

Cause

Root Cause: OOM-Killer and Swap Exhaustion

  • The system experienced severe memory exhaustion, leading the Linux kernel's OOM killer to terminate critical management processes (restjavad, tomcat, icrd_child, tmsh) to free memory.
  • This resulted in management UI lockups, tmsh hangs, and inability to generate QKView from the UI.

Answer/Recommended Actions

To resolve the issue, increase the memory allocation for management processes and restart the affected daemons. Follow these steps:

  1. Increase management memory (TRAFFIC-IMPACTING – schedule a maintenance window):
    tmsh modify sys db provision.extramb value 3072
  2. Increase restjavad heap (start conservatively, increase if needed):
    tmsh modify sys db provision.restjavad.extramb value 1024
  3. Increase tomcat heap:
    tmsh modify sys db provision.tomcat.extramb value 256
  4. Save the configuration:
    tmsh save sys config
  5. Restart management daemons sequentially (NOT traffic-impacting):
    bigstart restart restjavad
    sleep 20
    bigstart restart restnoded
    bigstart restart tomcat
  6. Operational Notes:
    If performed on the active BIG-IP, this will interrupt traffic. It is recommended to start with the standby unit, perform a failover, and repeat the procedure on the other unit. Fail back as needed.

Additional Information

  • The issue is directly related to insufficient memory for management processes, not a software bug or configuration error.
  • The inability to generate QKView from the UI is a symptom of memory exhaustion.
  • After increasing memory allocations and restarting daemons, the system should return to normal operation.
  • Always monitor system memory usage after making these changes to ensure stability.
