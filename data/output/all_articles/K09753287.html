Description

Attempts to create a new DNS Resource Record in ZoneRunner fail and display an error message similar to:

01150403:3: Server failure during update


The same message can also be found in the /var/log/gtm log file:

Jan 01 12:00:00 bigip1 err zrd[5046]: 01150403:3: Server failure during update


Logs similar to the following can be found in the /var/log/daemon.log: 
Jan 01 12:00:00 bigip1 err named[10598]: 01-Jan-2022 12:00:00.000 general: error: db.external.5.100.70.in-addr.arpa..jnl: create: permission denied
Jan 01 12:00:00 bigip1 err named[10598]: 01-Jan-2022 12:00:00.000 general: error: the working directory is not writable
Jan 01 12:00:00 bigip1 err named[10598]: 01-Jan-2022 12:00:00.000 general: error: db.external.yourdomain.org..jnl: create: permission denied
Jan 01 12:00:00 bigip1 err named[10598]: 01-Jan-2022 12:00:00.000 general: error: the working directory is not writable
Jan 01 12:00:00 bigip1 err named[10598]: 01-Jan-2022 12:00:00.000 general: error: error writing NTA file for view 'external': permission denied

Environment

  • BIG-IP DNS
  • ZoneRunner

Cause
These errors are usually the result of incorrect file or directory ownership permissions. This can occur, if you have made changes directly to the zone files from within the bash command line. The error messages indicate that either the /var/named/config/namedb directory or the individual zone files have incorrect permissions.
 

[Active:In Sync] config # cd /var/named/config
[Active:In Sync] config # ls -lZ
-rw-------. named named system_u:object_r:named_zone_t:s0 bind.keys
drwxr-xr-x. root  root  unconfined_u:object_r:named_zone_t:s0 namedb       <-- user and group should not be root/root. SELinux user shoud not be 'unconfined_r'.
-rw-------. named named system_u:object_r:named_zone_t:s0 named.conf
-rw-------. named named system_u:object_r:named_zone_t:s0 named.conf~
-rw-------. named named system_u:object_r:named_zone_t:s0 rndc.key
 

Recommended Actions

Change the owner and group of the zone files within the namedb directory to "named/named", with following procedure:

chown named:named /var/named/config/namedb/*
chmod 700 /var/named/config/namedb/*

chcon system_u:object_r:var_t:s0 named.conf
chcon system_u:object_r:named_zone_t:s0 namedb
 

Change the ownership of the namedb directory:
chown named:named /var/named/config/namedb/
chmod 775 /var/named/config/namedb/
