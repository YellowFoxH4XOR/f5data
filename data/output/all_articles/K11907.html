Known Issue

This is the result of known issue. When configuring a Network Access tunnel on a BIG-IP APM system in which the configuration uses linked virtual servers with Datagram Transport Layer Security (DTLS) enabled, the resulting configuration will generate large packets, causing IP fragmentation. In configurations in which a virtual server directs traffic to a second virtual server and the ClientSSL profile (DTLS) is configured on the first virtual server, and the connectivity profile (Point-to-Point Protocol (PPP)) is configured on the second virtual server, the PPP Maximum Receive Unit (MRU) calculation occurs on the second virtual server and does not account for DTLS overhead, resulting in large packet size. As a result, this issue causes IP fragmentation of the network access tunnel traffic.

F5 Product Development tracked this issue as ID 227033 (formerly CR142585) and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP APM or Edge Gateway release notes.

This issue has been fixed in Hotfix-BIGIP-10.2.0-1755.1-HF1 for BIG-IP version 10.2.0. You may download this hotfix or a later version of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

You can work around this issue by ensuring that the DTLS and PPP protocols are configured on a single virtual server.
