Known Issue

This is the result of a known issue. If you configure multiple instances of the same filer, and multiple volumes use the same metadata share and directory on that filer, destaging a volume may result in metadata loss for other volumes.

For example:

  • A single filer has the IP addresses 192.168.1.1 and 192.168.1.30.
  • On the ARX system, you configure one filer named MyNetApp, which points to 192.168.1.1 and a second filer named SomeNetApp, which points to 192.168.1.30.
  • You then configure volume /vol1 to store its metadata on /share1/directory1 on MyNetApp, and volumes /vol2 and /vol3 to store their metadata on /share1/directory1 on SomeNetApp.
  • If you destage /vol1, and no other volume references MyNetApp /share1/directory1 for metadata, the ARX system deletes the entire /share1/directory1/.acopia directory from the filer. Since MyNetApp is the same device as SomeNetApp, /vol2 and /vol3 also lose their metadata.

When this issue occurs, the affected volumes go offline until the ARX system automatically reimports the metadata.

F5 Product Development tracked this issue as ID 30601 and it was fixed in ARX 5.2.0. For information about upgrading, refer to the ARX release notes.

Workaround

To prevent this issue from occurring, do not configure multiple instances of the same filer.
