Known Issue

This is the result of a known issue. The Stand-in Period cache setting for a BIG-IP WebAccelerator acceleration policy is not honored if all pool members are marked down by a monitor.

The Stand-in Period cache setting communicates to the BIG-IP WebAccelerator system when to stop serving expired content from the cache when the content has expired, but the origin web server is not responding to requests. However, if all pool members are marked down, the BIG-IP WebAccelerator sends a TCP Reset response to the client, and the request is not processed by the BIG-IP WebAccelerator.

Note: The Stand-in Period cache setting is unconfigured in the default acceleration policy configuration.

F5 Product Development is tracking this issue as ID 248955 (formerly CR97158).

Workaround

You can work around this issue and force the Stand-in Period cache setting to be honored by forcing an HTTP 404 Not Found response from an alternate webserver when all members of the OWS poos are unavailable. To do so, perform the following procedure:

  1. Create a pool named ForceStandin that contains at least one active webserver. The webserver need not host any specific content, but simply respond with an HTTP 404 Not Found status to all requests sent to the WebAccelerator enabled virtual server.
  2. Associate the following iRule with the WebAccelerator enabled virtual server:

    Note: Replace OWS_pool with name of the pool containing your OWS(s).

    when HTTP_REQUEST {
      if { [active_members OWS_pool ] !=0 } {
        pool OWS_pool
      } else {
        pool ForceStandin 
      }
    }

When all members of the OWS pool are Unavailable, instead of sending a Reset response to the client, the iRule selects the ForceStandin pool and the request will be processed. The alternate webserver sends an HTTP 404 Not Found response for all requests. If the request is for a previously cached object and the Stand-in Period setting has not expired, the object is served from cache.

Note: For information about creating pools and iRules, refer to the BIG-IP LTM Configuration Guide.
