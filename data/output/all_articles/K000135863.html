K000135863: Low throughput performance for standard VS with ssl encryption on VE platform

Type
Support Solution
Published
2023-08-18
Updated
2023-08-18
Applies to
  • Virtual Editions
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000135863

Description

Low performance throughput using standard virtual server (VS) compared with a fastl4 VS. For example, expected throughput might be that standard VS is 50% of the fastl4 VS. However, large data download is taking 5 or more times as long via the standard VS.

Environment

  • Virtual edition (VE) platform running on any hypervisor
  • Standard virtual server with either or both clientssl and serverssl profiles
  • Large amounts of data are being downloaded or uploaded by client

Cause

The virtualised machine is not using the native (or passthrough) processor emulation. Instead a generic emulation has been configured and a "lowest common denominator" set of processor instruction capabilities are being used.

Recommended Actions

Check the cpu model assigned to your guest system.

For a generic emulation, you will see something similar to the following:

# cat /proc/cpuinfo | grep -E "model name" | head -n 1

model name :QEMU Virtual CPU version 2.5+

 

For a native (or passthrough) emulation, depending on the hardware cpu will show something like:

# cat /proc/cpuinfo | grep -E "model name" | head -n 1

model name : Intel(R) Xeon(R) Gold 6248 CPU @ 2.50GHz

 

If performance is an issue, the recommendation is to use the "best" cpu available, which should be the native cpu.

 

Additional Information

With a native cpu, there will be limitations as to dynamic scheduling. Check with hypervisor documentation.
