Known Issue

The BIG-IP system may reject incoming Session Initiation Protocol (SIP) REGISTER messages.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server with SIP Message Routing Framework (MRF) functionality.
  • The virtual server receives a SIP REGISTER message.
  • A SIP Contact header with an expires value that is set to zero is not the last attribute listed.

    For example:

    Contact: <sip:+414000400@10.0.0.42:5060>;expires=0;q=0.1

Impact

The BIG-IP system unexpectedly terminates SIP connections.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Client SIP connections are prematurely disconnected.
  • When you view packet captures taken with the tcpdump utility, you observe that SIP REGISTER messages are rejected with an error message similar to the following example:

    13    11.425449    10.0.0.42    5060    10.0.0.175    5060    SIP    4094    532    IN  s1/tmm0 : Request: REGISTER sip:bpack.orange.pl  (remove 1 binding) |
    14    11.425508    10.0.0.175    5060    10.0.0.42    5060    SIP    4094    519    OUT s1/tmm0 : Status: 400 Bad request |

    For more information regarding the tcpdump utility, refer to K411: Overview of packet tracing with the tcpdump utility.
