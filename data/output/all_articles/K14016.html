Known Issue

ConfigSync between device group members may fail.

This issue occurs when all of the following conditions are met:

  • You have two or more BIG-IP devices in a device group
  • A virtual server is configured in a partition that is assigned to a traffic-group-local-only (non-floating) traffic group, or to a sync-only device group
  • A persistence profile that is configured in a partition assigned to a floating traffic group is associated with this virtual server

Impact

ConfigSync operations in this device group will fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H379827 on the Diagnostics > Identified > Medium screen.
  • A ConfigSync to a host will fail and log error messages in the /var/log/ltm file. The error messages will appear similar to the following examples:

    On the master host:

    err mcpd[<pid>]: 01020036:3: The requested virtual server (/<partition>/<virtualserver>) was not found.
    err mcpd[<pid>]: 01071488:3: Remote transaction for device group /Common/<devicegroup> to commit id 103 5814107614756942551 /Common/remotehostname.domain.com failed with error

    On the subordinate host:

    notice mcpd[<pid>]: 010714a0:5: Sync of device group /Common/<devicegroup> to commit id 1 5814076926716791809 /Common/andre.emealab.domain.com from device /Common/hostname.f5.com complete.
  • When performing a manual ConfigSync the following error message will display in the BIG-IP Configuration utility on the master host:

    Group Config Sync Status
    Status Sync Failed
    Summary remote sync validation error
    Details [sync error on /Common/remotehostname.domain.com]: Load failed from /Common/hostname.domain.com

Workaround

To work around this issue, you can create a new persistence profile in the same partition as your virtual server. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the BIG-IP Configuration utility.
  2. Select the partition on which your virtual server resides.
  3. Click Local Traffic.
  4. Click Profiles.
  5. Click Persistence.
  6. Create a new persistence profile identical to the one you are replacing.
  7. Assign the persistence profile to the virtual server in the local traffic group.
