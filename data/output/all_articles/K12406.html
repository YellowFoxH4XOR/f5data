Known Issue

This is the result of a known issue. The tmsh list /ltm pool <pool_name> all-properties command displays the pool member's state property only when the pool member is forced down. The command does not display other possible state properties for pool members.

A pool member's state reflects the current pool member status. The state changes depending on whether the member is available to process connections, marked down by a monitor, or disabled or forced down by a user. When you run the tmsh list ltm pool <pool_name> all-properties command, the output should show configuration elements for the pool, as well as the state property for each of the pool members in the pool.

Note: For more information about BIG-IP pool status, refer to K10516: Overview of BIG-IP pool status.

If you set the pool member state to Forced Offline (Only active connections allowed), the tmsh list /ltm pool <pool_name> all-properties command correctly displays the state as down. However, if the pool member is marked down by a monitor, or set to Disabled (Only persistent or active connections allowed) by a user, the state property is not reflected by the tmsh list /ltm pool <pool_name> all-properties command.

F5 Product Development tracked this issue as ID 225524, and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway Release Notes.

Workaround

You may work around this issue and view the current pool member state by running the following tmsh command:

tmsh show /ltm pool <pool_name> detail

Note: For more information about the Traffic Management Shell (tmsh), refer to K12029: Accessing the Traffic Management Shell.
