Policy Information

Important: The F5 software lifecycle support policy outlined in this article has been superseded for all products except FirePass. The FirePass product will continue to use the policy outlined in this article. For information about the current lifecycle support policy, refer toÂ K8986: F5 product support policies.

Note: The F5 software lifecycle policy described in this article also applies to Virtual Edition (VE) releases of the software.

The F5 software lifecycle support policy defines the stages of the software lifecycle from initial release through retirement. The intent of this policy is to provide consistent documentation that aids customers in planning and preparing for their organization's support needs.

F5 software uses a three-digit software version schema, as follows:

Software Family

The Software Family recognizes the general architecture on which the software is based. The introduction of a new Software Family version indicates a significant core architectural change to the product software.

Major Version

The Major Version recognizes the category of software being released. F5 BIG-IP software has two different categories of software: Feature Release Software and Maintenance-Only Software.

  • Feature Release Software is characterized by the introduction of new features and typically also includes security updates and stability improvements. You can identify feature release software by the Major Version (the second digit), which is an even number; for example, 4.6.2.
  • Maintenance-Only Software offers customers a defined feature-set, and is ideal for customers who need consistent behavior and minimal changes. F5 will introduce no new features into Maintenance-Only Software. All Maintenance-Only Software is identified by the Major Version (the second digit) being an odd number; for example, 4.5.11.

Customers should choose their Major Version based on their organization's needs.

Minor Version

The Minor Version is used to signify a package of software updates to a Major Version. The first Minor Version release begins with 1 and then progresses in a standard numerical fashion; for example, 1, 2, 3, 4, 5, etc.

Software End of Life

As new software is released, previous software versions will begin their lifecycle retirement process. F5 strives to ensure that the following software End of Life policy is consistently applied to all product families:

Feature Branch End of Life Rules:

  • Development Support is provided for the current software version plus one version back.
  • Development Support will end 90 days after the release of the maintenance branch of the major version or the release of a new minor version, whichever comes first.

Maintenance Branch End of Life Rules:

  • Development Support is provided for the current software version plus two versions back.
  • Development Support will end one year after the release of the maintenance branch of the subsequent major version.

Scenario 1: New Maintenance Version Announcement

To illustrate the End of Support announcement process for a New Maintenance Version, assume a new Major Maintenance Version (an odd number version, such as 10.3) was announced on June 1, 2006. On the same day, F5 would announce End of Major Maintenance Version Support for version 10.1, stating that support for version 10.1, and its associated hotfix releases (for example, 10.1.1, 10.1.2 and 10.1.3), will end on June 1, 2007. Additionally, on this same day, F5 would announce End of Major Feature Version Support for version 10.2, stating that support for 10.2, and its associated hotfix releases (for example, 10.2.0, 10.2.1 and 10.2.2), will end in 90 days, or on August 30, 2006.

Scenario 2: New Feature Version Announcement

To illustrate the End of Support announcement process for a New Feature Version, assume a new Major Feature Version (an even number version, such as 10.2.0) was announced on September 1, 2006. This Feature Version will be supported until a corresponding Maintenance Version is announced. For this scenario, assume that version 10.2.0 matures into the Maintenance Version 10.3.0, and version 10.3.0 is released on December 31, 2006. Additionally, on this same day, F5 would announce End of Major Feature Version Support for 10.2.0, stating that support for 10.2.0 and associated hotfix releases (for example, 10.2.0, 10.2.1 and 10.2.2), will end on April 1, 2007.

End of Major Version Support

As new Major Versions of software are released, previous Major Versions will begin the retirement process. To allow our customers adequate time to transition to the latest Major Version, F5 will make a pre-announcement of the End of Major Version Support.

The pre-announcement will be made on the AskF5 website and emailed to the F5 TechNews mailing list. To sign up for this mailing list, go to the AskF5 Publication Preference Center page. The time between pre-announcement and retirement will differ slightly for Feature Release Software and Maintenance-Only Software as detailed in the table below:

Type of softwareMinimum notification time
Feature Release Software (for example, 4.6.x)90 days
Maintenance-Only Software (for example, 4.5.x)1 year

Customers with little flexibility for upgrading are encouraged to utilize the Maintenance-Only Software versions.

For a list of the software versions currently supported by F5, refer to K8986: F5 product support policies.

CERTs and Hotfixes

Occasionally, F5 will release software packages between minor versions. For example, a software package may be released in response to a CERT, or when F5 provides customers with a temporary product solution, such as a hotfix. The F5 policy for these types of releases states that, at a minimum, F5 will produce a software package that is compatible with the current version release and two minor versions prior to the current version release for a maintenance branch, or one minor version prior to the current version release for a feature branch. For example, if the current maintenance branch version release is 9.1.2, F5 will at least provide CERTs or hotfixes for versions 9.1.2, 9.1.1, and 9.1. If the current feature branch version release is 4.6.4, F5 will at least provide CERTs or hotfixes for versions 4.6.4, and 4.6.3. F5 makes every effort to support earlier versions with these CERTs or hotfixes; however, you may be required to upgrade in order to utilize the packages. This policy is the same for either Feature Release Software or Maintenance-Only Software versions.
