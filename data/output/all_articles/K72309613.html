K72309613: Health Monitor is up when IIS site is offline

Description

Health Monitor not reporting when server is offline
Pool member not marked down when site is taken offline (different than stopping the service)

Environment

  • Big IP LTM
  • v11.6.4
  • IIS backend

Cause

When Site is stopped in IIS and not the IIS service, the IIS Start page is returned instead. This still returns a "200 OK" which the standard monitor marks up.

Recommended Actions

By running a tcpdump from BIG-IP, or a "curl -i" command, you can observe the response from the pool member. 
Create reverse monitor with the same send string, but set the receive string to "iisstart.png".
  1. Create new monitor
  2. Set parent to "HTTP"
  3. Set Send string -
    Example: GET / HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n
  4. Set Receive string to look for "iisstart.png"
  5. Monitor should be reverse by setting the radio button to "Yes"
  6. Click "Finished"
  7. Apply the newly created monitor as secondary monitor to the pool
  8. Click "Update"
???Additional Information

Reverse Monitor: With the Reverse setting set to Yes, the monitor marks the pool, pool member, or node down when the test is successful. For example, if the content on your web site home page is dynamic and changes frequently, you may want to set up a reverse Extended Content Verification (ECV) service check that looks for the string "Error". A match for this string means that the web server was down.
