Description

A SSH host key that is used to uniquely identify a device is displayed when you attempt to establish an SSH connection to that device for the first time. If you have access to the remote device, you can verify its key fingerprint before you attempt to establish an SSH connection to the remote device from your BIG-IP system.

Environment

  • Access to BIG-IP system command line
  • Access to remote device command line

Cause

None

Recommended Actions

Note: This procedure assumes the remote device has a Linux-based command line.

  1. Login to the remote device command line.
  2. Display the SSH key fingerprint of the remote device by entering the following command syntax:

    ssh-kengen -l -f <path/to/SSH public key file>

    For example, ssh-keygen -l -f /etc/ssh/ssh_host_ecdsa_key.pub

    Note: The above example assumes that the SSH server uses ECDSA public key in the /etc/ssh directory.

    The command should return an output in the following format:

    256 SHA256:<key fingerprint> <hostname> (<key type>)

    For example,

    256 SHA256:HG96rrH7I4IHCmpd+vVo0V7ycDp4eBfx5EOieuwPBiw localhost.localdomain (ECDSA)

  3. Next, login to the BIG-IP system command line.
  4. If you are connecting to the remote device from the BIG-IP system for the first time, the SSH command should prompt you that the authenticity of the host can’t be established, and the command should present you the SSH key fingerprint from the remote device. Compare this with the one obtained in step 2 to verify that the remote device is authentic.
  5. Alternatively, prior to connecting to the remote device from the BIG-IP system, you can check the key fingerprint of the remote host by entering the following command syntax:

    ssh-keyscan -t <key type> <remote device IP> | ssh-keygen -lf -

    For example,

    ssh-keyscan -t ecdsa 192.168.61.168 | ssh-kegen -lf -

    The command should return an output in the following format:

    # <remote device IP>:<SSH port> <SSH server version>
    256 SHA256:<key fingerprint> <hostname> (<key type>)

    For example,

    # 192.168.61.168:22 SSH-2.0-OpenSSH_7.4
    256 SHA256:HG96rrH7I4IHCmpd+vVo0V7ycDp4eBfx5EOieuwPBiw 192.168.61.168 (ECDSA)

  6. Compare the key fingerprint obtained in step 2 with that in step 5. If they match, the remote device is authentic.
