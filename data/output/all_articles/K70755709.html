K70755709: Upgrading past version 14.1.x, irules with SSL::cert commands within HTTP event may fail.

Type
Support Solution
Published
2021-06-10
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K70755709

Description

When upgrading to a version past 14.1.x, if you have irules assigned to different Virtual Servers and if the irules contain SSL::cert commands within HTTP events such as HTTP_REQUEST, the Virtual Servers may fail. Upon upgrade past a version from 14.1.x, alerts like the ones below could be seen on the /var/ltm/log:

month day hh:mm:ss appliance_hostname err tmm1[17562]: 01220001:3: TCL error: /Common/*irule_name* <HTTP_REQUEST> - Error using <Certificate> (line 3) invoked from within "X509::subject $client_cert"

month day hh:mm:ss appliance_hostname err tmm2[12322]: 01220001:3: TCL error: /Common/*irule_name* <HTTP_REQUEST> - Error using <Certificate> (line 3) invoked from within "X509::subject [SSL::cert 0]"

The iRule identified in the previous logs, would have a configuration similar to the one below:

when HTTP_REQUEST {                       
set client_cert [SSL::cert 0]             
log local0. "SSL-Parameter: [SSL::sessionid] Session ID"
log local0. "SSL-Parameter: [X509::subject $client_cert] ClientCert [X509::not_valid_after $client_cert] ExpiryDate [X509::subject_public_key_RSA_bits $client_cert] SSLCertBits"

Environment

  • BIG-IP
  • Upgrade to a version past 14.1.x.
  • iRules with SSL::cert commands within HTTP events.

Cause

After upgrading to version 14.1.x, if the iRule is using an HTTP_REQUEST event instead of the CLIENTSS_CLIENTCERT event and if Retain certificate is disabled, this feature will not retrieve the certificate

Recommended Actions

  1. Identify the problematic irule from the above logs
  2. Run the following command to find what virtual server it is attached to.
    tmsh list ltm virtual rules | grep <irule_name>
  3. From the GUI, identify the Client SSL profile that the virtual server, from the previous step, is using
  4. From the GUI, enable the retain-certificate option in the Client SSL profile that was identified in the previous step.
