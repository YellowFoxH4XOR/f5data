K000161300: BIG-IP APM Incorrectly Detects Android Device OS as "Linux" while connecting to VPN

Type
Support Solution
Published

  • APM Clients

Description

 

When connecting to VPN through BIG-IP APM using Chrome or the native browser on an Android tablet or Mobile phone, APM may incorrectly identify the device's operating system as Linux instead of Android. This results in session denial if the access policy blocks Linux devices. 

 

Environment

  • Product: BIG-IP APM
  • APM Edge Client:  All versions
  • Browser: Google Chrome or native browser with Desktop Mode enabled
  • Access Method: Browser-based VPN or F5 Access app

 

Cause

When Desktop Mode is enabled in Chrome on Android, the browser alters its User-Agent string to mimic a Linux desktop environment (e.g., "X11; Linux x86_64"). BIG-IP APM relies on the User-Agent string for client OS detection and, therefore, classifies the session as Linux, resulting in policy denial.

 

Recommended Actions

Disable Desktop Mode on the Android Device 

  1. Open Chrome on the Android tablet.
  2. Tap the three-dot menu (⋮) in the top-right corner.
  3. Uncheck or disable "Desktop site" or "Request desktop site".
  4. Retry the VPN connection.

Chrome will then send the correct Android User-Agent, and APM will detect the OS as Android, allowing access if permitted by policy.

 

Additional Information

  • EPSEC pop-up not appearing on Android devices is expected behaviour — endpoint inspection (EPSEC) is not supported on Android, unlike on Windows machines. This is not a defect.
  • BIG-IP APM reads and acts on the User-Agent string as presented by the browser. The misidentification is due to browser behaviour, not an APM defect.
