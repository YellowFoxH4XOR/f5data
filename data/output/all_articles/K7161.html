K7161: A virtual server using a BIG-IP ASM HTTP class does not send the Connection: Close header to the client correctly

Known Issue

When a virtual server uses a BIG-IP ASM HTTP class and a client requests a keep-alive connection, the Connection: Close header sent from the server to the client is translated to X-Cnection: Close if the server does not support keep-alive connections. The browser does not recognize the X-Cnection: Close header, and maintains the keep-alive connection. As a result, subsequent requests from the client are sent to the same member, which creates an unintentional persistent connection.

F5 Product Development tracked this issue as CR75534 and it was fixed in BIG-IP ASM 9.3.0 and 9.4.1. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

Note: The following procedure requires issuing the bigstart restart command, which restarts all processes. This command will cause a failover if it is performed on an active system. F5 recommends that you perform this procedure on the standby unit, and then failover once you have completed the procedure. If you are using a standalone system, F5 recommends you perform this procedure during a maintenance window to prevent disruption to client connections.

You can work around this issue by preventing the X-Cnection: Close header from being sent to the client's browser, which will allow the correct Connection: Close header to pass through to the client. To do so, perform the following procedure:

  1. Log in to the BIG-IP ASM command line.
  2. Create a backup of the /config/profile_base.conf file by typing the following command:

    cp /config/profile_base.conf /config/profile_base.original

  3. Edit the /config/profile_base.conf file.
  4. Locate the following line in the HTTP_CLASS_SELECTED priority 750 event of the _ASM_clientside iRule:

    if {([lindex $tmm_ts_lb 0] ne [lindex $tmm_ts_lbserver 0]) ||

    Change to the following:

    if {(($tmm_ts_httpclass_selected != 0) && ($tmm_ts_ntlm == 0)) ||([lindex $tmm_ts_lb 0] ne [lindex $tmm_ts_lbserver 0]) ||
  5. Save the changes to the /config/profile_base.conf file.
  6. Restart the BIG-IP ASM process by typing the following command:

    bigstart restart
