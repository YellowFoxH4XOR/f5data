Topic

In BIG-IP versions prior to the fixed versions listed in the security advisory K51213246: BIG-IP APM AD authentication vulnerability CVE-2021-23008, Active Directory (AD) authentication is vulnerable to a remote attacker hijacking a Key Distribution Center (KDC) connection using a spoofed AS-REP response. Beginning in the BIG-IP versions listed in the fixed column of the security advisory K51213246: BIG-IP APM AD authentication vulnerability CVE-2021-23008, you can now configure KDC validation in the AD Authentication agent of your access policy.

Description

You can configure the BIG-IP APM system to validate the KDC using a keytab file generated at the domain controller in AD authentication.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have an existing access policy with AD authentication working.
  • You have administrative privileges on both the BIG-IP APM system and Windows Domain Controller.

Procedures

Perform the following procedures to configure KDC validation in your BIG-IP access policy:

  • Create a new keytab file with the ktpass command
  • Optional: Merge keytab files
  • Configure the AD Authentication resource to validate the KDC

Create a new keytab file with the ktpass command

Create a keytab file that you will use to validate the KDC by performing the procedure on the Windows DC:

Impact of procedure: Using the ktpass command with certain parameters on a domain controller may modify the AD service account. F5 recommends that you perform this procedure during a scheduled maintenance window for the specific service.

  1. Log in to the Windows DC as an administrator.
  2. Open Active Directory Users and Computers and create a new user account for each HTTP service account. For example, you can create the new account with the following values:

    Note: For security purposes, F5 recommends selecting the This account supports Kerberos AES 256 bit encryption check box on the Account tab in the user Properties after the account is created.

    • First name: firstname_app1
    • Full name: http_app1
    • User logon name: upn_app1
    • User logon name (pre-Windows 2000): samaccountname1
    • Account tab > This account supports Kerberos AES 256 bit encryption check box selected.
  3. Open a command prompt and create a new keytab file using the following syntax:

    ktpass -princ <userPrincipalName> -mapuser <service account distinguishedName> crypto <encryption type> -ptype KRB5_NT_PRINCIPAL -pass <password> -out <keytab filename>

    For example:

    Important: The following command uses AES256-SHA1 encryption. You must therefore select the This account supports Kerberos AES 256 bit encryption check box for the user you created in step 2.

    ktpass -princ HTTP/app1.example.com@EXAMPLE.COM -mapuser http_app1 crypto AES256-SHA1 -ptype KRB5_NT_PRINCIPAL -pass pass1234 -out app1example.keytab

    Note: The -princ parameter is case-sensitive. app1.example.com is the URL that you enter into the browser to access the HTTP service. For more information, refer to ktpass. This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

    In this example, the ktpass command performs the following changes to the account specified by the -mapuser parameter:

    • Overwrites the original user principal name (UPN) value, upn_app1, with HTTP/app1.example.com
    • Adds HTTP/app1.example.com to the list of service principal name (SPN) of the service account
    • Sets the password of the account
    • Increases the key version number (KVNO) of the account by 1
    • Generates a keytab file app1example.keytab that supports the AES256-SHA1 encryption type
  4. Review the contents of the keytab file using the following command syntax:

    ktpass /in <keytab filename>

    For example:

    ktpass /in app1example.keytab

  5. You can repeat steps 2 and 3 to create another keytab file for another AD service account for another application.

Optional: Merge keytab files

If you need to merge keytab files to accommodate multiple services, refer to the Merging the keytab files with the ktutil utility procedure in K01716018: Configuring Kerberos end-user logon authentication for multiple applications by merging keytab files.

Configure the AD Authentication resource to validate the KDC

After generating the keytab file in the previous procedure, download it to your computer. To upload it to the AD Authentication resource and configure KDC validation, perform the following procedure:

Impact of procedure: Configuring KDC validation may cause user logins to fail. F5 recommends performing this during a scheduled maintenance.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Access > Authentication > Active Directory.

    Note: For versions prior to BIG-IP 13.x, go to Access Policy > AAA Servers > Active Directory.

  3. Select the name of the AD server
  4. For KDC Validation, select the Enabled checkbox. Doing this reveals two additional parameters, Service Name and Keytab File.
  5. For Service Name, enter:

    Note: This must match the -princ value you used in the ktpass command in the previous procedure.

    HTTP/app1

  6. For Keytab File , select Upload New File .
  7. Select Browse, then browse to and choose the keytab file you created in the previous procedure.
  8. Select Update.
  9. Verify the keytab file information in the Keytab File Details.

Troubleshooting

To troubleshoot you should perform the following procedures:

  • Verify the service account name configuration on the AD/KDC
  • Use the klist command to verify the contents of a keytab file on the BIG-IP APM system

For more information on the procedures, refer to K01716018: Configuring Kerberos end-user logon authentication for multiple applications by merging keytab files.

As stated in the prerequisites section of this article, you must already have a working set up of AD authentication in your access policy. This assumes that basic Kerberos requirements such as clock synchronization, DNS configurations, and so on are all met.
