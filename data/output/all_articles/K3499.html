Topic

This article describes how to back up and restore your BIG-IP 9.x configuration data using a user configuration set (UCS) configuration archive. The UCS archive contains all files required to restore your current configuration to a new system unless your configuration has been customized to run programs that are not normally supported on the BIG-IP system.

This article applies to BIG-IP 9.x. For information about other versions, refer to the following articles:

  • K11318: Backing up and restoring BIG-IP configuration files (10.x)
  • K13132: Backing up and restoring BIG-IP configuration files (11.x)

Note: The F5 Enterprise Manager product facilitates the configuration management process for multiple systems. For more information, refer to the Enterprise Manager product documentation.

Note: If you want to back up or restore BIG-IP configuration files before you replace an RMA unit, refer to K8086: Replacing a BIG-IP system in a redundant pair without interrupting service. For versions 9.4.5 and later, refer to K9420: Installing UCS files containing encrypted passwords or passphrases.

Note: For more information about UCS archive files, refer to K4423: Overview of UCS archives.

The .ucs file contains the following configuration data:

  • All BIG-IP-specific configuration files
  • BIG-IP product licenses
  • User accounts and password information
  • Domain Name System (DNS) zone files
  • Installed Secure Socket Layer (SSL) certificates and keys

Note: For more information about the contents of a UCS archive file, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

Backing up configuration data using the Configuration utility

To create a UCS archive using the Configuration utility, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Archives.
  4. Click Create.
  5. In the File Name box, type a name for the file.

    Note: You can supply a path for the file, but the file does not appear in the Archive List. Only files stored in the default /var/local/ucs path appear in the Archive List.

  6. Optional: To encrypt the UCS archive file, select Enabled from the Encryption menu.

    Note: If you enable encryption, enter a passphrase to protect the encrypted UCS archive file. You must supply this passphrase to restore the encrypted UCS archive.

  7. Optional: To exclude SSL private keys from the UCS archive, select Exclude from the Private Keys menu.

    Note: The option to exclude SSL private keys from a UCS archive was added to the Configuration utility beginning in BIG-IP 9.2.0.
     
  8. Click Finished.
  9. Click OK.

Restoring configuration data using the Configuration utility

 

Important: The UCS restore operation restores the full configuration only if the host name of the target system matches the host name where the UCS archive was created. If the host name does not match, only the shared configuration is restored. You can set the host name of the BIG-IP system on the System > Platform screen of the Configuration utility, or by using the bigpipe system host name command at the BIG-IP command line.

To restore a configuration in a UCS archive using the Configuration utility, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Archives.
  4. From the Archive List, click the name of the UCS archive to restore.

    Note: If the UCS archive is encrypted, you must type the passphrase for the encrypted UCS archive file in the Restore Passphrase box.

  5. Click Restore.
  6. Click OK.

Backing up configuration data from the command line

To back up your current configuration data from the command line, perform the following procedure:

  1. Log in to the command line.
  2. Save the configuration into a UCS archive by typing the following command:

    bigpipe config save <filename>

    Replace <filename> with the filename of your choice.

    Alternatively, to create an encrypted UCS archive from the command line, use the following command syntax:

    bigpipe config save <filename> passphrase <passphrase>

    Replace <filename> with the filename of your choice. Replace <passphrase> with a password to protect the archive file. You must supply this passphrase to restore the encrypted UCS archive.

    By default, the BIG-IP system saves the UCS archive file in the /var/local/ucs directory.

    Note: With both commands, you can specify a full path to the archive file and the system saves the file to the specified location. If you do not include a path, the system saves the file to the default /var/local/ucs archive directory. Archives located in a directory other than the default do not appear in the list of available archives when you use the Configuration utility to restore a configuration.

    Note: F5 recommends that you include the BIG-IP host name as part of the file name for ease of identification.

    Note: In BIG-IP 9.0.5 and later versions, you can exclude SSL private keys from a UCS archive by adding the support option when running the bigpipe config save command; for example, bigpipe config support save <filename>. Additionally, the option to exclude SSL private keys from a UCS archive was added to the Configuration utility beginning in BIG-IP 9.2.0.

  3. Copy the .ucs file to another system.

    Note: For instructions about copying files to and from the BIG-IP system, refer to K175: Transferring files to or from an F5 system.

Important: In addition to user accounts, passwords, and critical system files, the UCS archive file contains the SSL private keys that are used with your SSL proxies. It is important to store the backup UCS archives in an environment that is as secure as where you store your private keys.

Note: You can automate the backup process described here by using a cron job and secure shell (SSH) login without password protection to a remote system. For sample scripts and instructions, refer to the F5 DevCentral codeshare: BIGIPBackupScripts, LTM_Backup_Shell_Script. A separate login is required to access this content.

Restoring configuration data from the command line

To restore the BIG-IP system configuration from the command line, perform one of the following two procedures:

  • Restoring the configuration data for a system that is currently running system software
  • Installing the operating system and restoring the configuration data to a new system

Restoring the configuration data for a system that is currently running system software

 

Important: If you install a UCS archive that contains configurations for an add-on module, such as BIG-IP WebAccelerator or BIG-IP ASM, the installation fails if the system is not licensed for the module. If you restore a UCS archive that contains configurations for a module, you must ensure that the system has a valid license before you install the UCS archive. For information about licensing, refer to K7752: Overview of licensing the BIG-IP system. Additionally, it is important to back up the existing system license before you restore a UCS archive. For more information about UCS installation and licensing behavior, refer to K10245: BIG-IP UCS installation and licensing behavior.

If you are using a system that already has system software running, and you do not want to reinstall the software, perform the following procedure:

  1. Optional: Back up the existing license file to the /var/tmp/ directory before you install the UCS, by typing the following command:

    cp /config/bigip.license /var/tmp

  2. Copy the UCS archive file you want to restore to the BIG-IP filesystem.

    Note: For instructions about copying files to and from the BIG-IP system, refer to K175: Transferring files to or from an F5 system.

  3. Set the host name of the system to match the host name of the system where the UCS archive was created, by typing one of the following commands:
    • BIG-IP system 9.4.2 and later:

      bigpipe system hostname <hostname>

    • BIG-IP system 9.4.1 and earlier:

      hostname <hostname>

    Important: If you do not set the host name to match the original host name, only the shared portion of configuration is installed.

  4. Restore the configuration from the UCS archive by typing the following command, replacing <filename> with the name of your UCS archive file:

    bigpipe config install <filename>

    Note: If the UCS archive is not located in the default directory, include the path to the file. For some versions, you must specify an absolute path. For more information, refer to K9446: Explicit pathname to UCS archive is required with the 'bigpipe config install' command

    Note: If the UCS archive file specified was encrypted, you must enter the passphrase for the archive file.

    Important: If you are restoring the backup on a different device from the system where the backup was created, such as an RMA system, the configuration load may fail with a license error. As a result, a BigDB.dat load error message that appears similar to the following example displays:

    b config install /var/local/ucs/backup.ucs
    Installing full configuration on host bigip1.askf5.com
    Saving active configuration...
    Creating UCS for config save request...
    Dec 8 12:00:00 bigip1 mcpd[2395]: 01070608:0: License is not operational
    (expired or digital signature does not match contents).
    Loading the new /config/BigDB.dat failed.
    01080023:3: Error return while getting reply from mcpd: 0x1070370,
    01070370:3: Failover (redundant mode) is not licensed.
    After updating your license, run
    loaddb -local /config/BigDB.dat.cs

    Note: If you did not receive this error message when installing the UCS archive, you can skip to Step 8.

    Important: Encrypted passphrases for SSL private keys used in the configuration cannot be decrypted, and an error message that appears similar to the following example displays:

    BIGpipe client SSL profile creation error:
    01070937:3: Master Key decrypt failure - decrypt failure

    Note: If you receive this error message when installing the UCS archive, refer to K9420: Installing a UCS file containing an encrypted passphrase. If you do not receive this error message, skip to Step 8.

  5. If you are running BIG-IP 9.x software on a 1500, 3400, 4100, 6400, 6800, or 8400 hardware platform, type the following command to verify that the new or replaced SSH keys from the UCS file are synchronized between the BIG-IP system and the Switch Card Control Processor (SCCP):

    keyswap.sh sccp

    Note: For more information about synchronizing SSH keys, refer to K3759: Synchronizing SSH keys between the BIG-IP host system and the SCCP.

  6. Reboot the system by typing the following command:

    reboot

    If you install this system on the same device where the backup was created, it loads the restored configuration after the system reboots. However, if you restore the backup on a different device and receive the errors noted in Step 3, you must perform Steps 7 through 9.
  7. Relicense the system.

    Note: For information about licensing, refer to K7752: Overview of licensing the BIG-IP system.

  8. Finish loading the BigDB.dat information by typing the following command:

    Note: You can skip this step if you did not receive the license error listed in Step 3.

    loaddb -local /config/BigDB.dat.cs

  9. Synchronize the BIG-IP system clock with the restored time zone configuration by typing the following command:

    Note: You can skip this step if you are using versions 9.4.2 and later. As of version 9.4.2, the tw_activate_keys command is not used.

    tw_activate_keys ntp.timezone

Note: If you restore a system that contains the FIPS 140 HSM, you must configure the FIPS 140 HSM Security World after you complete this procedure.

Note: For additional information about recovering FIPS information after a system recovery, refer to the Recovering FIPS information after a system failure section in Configuring and Maintaining a FIPS Security Domain.

 

Installing the operating system and restoring the configuration data to a new system

 

Important: It is important to back up the existing system license before you restore a UCS archive. For more information about UCS installation and licensing behavior, refer to K10245: BIG-IP UCS installation and licensing behavior.

To install the operating system and restore configuration data to a new system, perform the following procedure:

  1. Optional: Back up the existing license file to the /var/tmp/ directory before you install the UCS by typing the following command:

    cp /config/bigip.license /var/tmp

  2. Network boot the system software from the CD-ROM drive.

    Note: For instructions, refer to K4411: Reinstalling BIG-IP or 3-DNS system software from a network boot server.

  3. After the system software installs, reboot the system by typing the following command:

    reboot

  4. Connect to the serial port.
  5. From the command line, type the following command:

    config

  6. Follow the prompts to configure the system with an IP address.
  7. Copy the UCS archive file to the system.

    Note: For instructions about copying files to and from the BIG-IP system, refer to K175: Transferring files to or from an F5 system.

  8. Set the host name of the system to match the host name of the system where the UCS archive was created, by typing one of the following commands:
    • BIG-IP system 9.4.2 and later:

      bigpipe system hostname <hostname>

    • BIG-IP system 9.4.1 and earlier:

      hostname <hostname>

      Important: If you do not set the host name to match the original host name, only the shared portion of the configuration is restored.

  9. Restore the configuration from the UCS archive, by typing the following command, replacing <filename> with the name of your UCS archive file:

    bigpipe config install <filename>

    Note: If the UCS archive is not located in the default directory, include the path to the file. For some versions, you must specify an absolute path. For more information, refer to K9446: Explicit pathname to UCS archive is required with the 'bigpipe config install' command.

    Note: If the UCS archive file specified was encrypted, you are prompted to enter the passphrase for the archive file.

    Important: If you restore a backup from version 9.4.5 or later after you reinstall the operating system, replace a failed system with a new system, or move an existing configuration to a new system, the encrypted passphrases for SSL private keys used in the configuration cannot be decrypted and an error message that appears similar to the following example displays:

    b config install /var/local/ucs/backup.ucs
    Installing full configuration on host bigip1.askf5.com
    Saving active configuration...
    Creating UCS for config save request...
    Dec 8 12:00:00 bigip1 mcpd[2395]: 01070608:0: License is not operational
    (expired or digital signature does not match contents).
    Loading the new /config/BigDB.dat failed.
    01080023:3: Error return while getting reply from mcpd: 0x1070370,
    01070370:3: Failover (redundant mode) is not licensed.
    After updating your license, run
    loaddb -local /config/BigDB.dat.cs

    Note: If you did not receive this error message when installing the UCS archive, you can skip to Step 13.

    Important: If you restore a backup from version 9.4.5 or later after you reinstall the operating system, replace a failed system with a new system, or otherwise moving an existing configuration to a new system, the encrypted passphrases for SSL private keys used in the configuration cannot be decrypted, and an error message that appears similar to the following example will display:

    BIGpipe client SSL profile creation error:
    01070937:3: Master Key decrypt failure - decrypt failure

    Note: If you receive this error message when installing the UCS archive, refer to K9420: Installing a UCS file containing an encrypted passphrase.

  10. If you are running BIG-IP 9.x software on a 1500, 3400, 4100, 6400, 6800, or 8400 hardware platform, type the following command to verify that the new or replaced SSH keys from the UCS file are synchronized between the BIG-IP system and the SCCP:

    keyswap.sh sccp

    Note: For more information, refer to K3759: Synchronizing SSH keys between the BIG-IP host system and the SCCP.

  11. Reboot the system by typing the following command:

    reboot

    If you install this system on the same device where the backup was created, after the system reboots, it loads the restored configuration; however, if you restore the backup on a different device and you receive the errors noted in Step 9, then perform Steps 12 through 14.
  12. Relicense the system.

    Note: For more information about licensing, refer to K7752: Overview of licensing the BIG-IP system.

  13. Finish loading the BigDB.dat information by typing the following command:

    Note: You can skip this step if you did not receive the license error listed in Step 9.

    loaddb -local /config/BigDB.dat.cs

  14. Synchronize the BIG-IP system clock with the restored time zone configuration, by typing the following command:

    tw_activate_keys ntp.timezone

Note: You can skip this step if you are using versions 9.3.x or 9.4.2 and later. As of version 9.3 and 9.4.2, the tw_activate_keys command was included in the ConfigSync script.

Note: If the system you have restored contains the FIPS 140 HSM, you must now configure the FIPS 140 HSM Security World.

Note: For more information about recovering FIPS information after a system recovery, refer to the Recovering FIPS information after a system failure section in Configuring and Maintaining a FIPS Security Domain.
