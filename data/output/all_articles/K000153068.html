K000153068: SSL TPS calculation

Type
Support Solution
Published
2025-08-19
Updated
2025-08-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000153068

Description:


When using RSA keys of 4096 bits or greater on BIG-IP LTM, the system may display the error message:


"SSL transaction (TPS) rate limit reached."


This occurs when the number of new SSL connections in any 10ms window exceeds the allowed threshold based on the system's licensed SSL TPS.


Environment:


Product: BIG-IP LTM

Version: 17.1.2

Platform: F5-BIG-LTM-I4800, C115

Licensed SSL TPS: 6500

Number of TMMs: 11

HTSplit: Enabled (×2)

SSL profile configured with RSA certificate key size: 4096 bits or greater

Cause:


For RSA keys ≥4096 bits, BIG-IP enforces a limit of 20% of the total system-wide SSL TPS. The total SSL TPS is calculated as:


Licensed TPS × Number of TMMs × HTSplit (if enabled).


The system uses a sliding 10ms window (1/100 of a second) to enforce this limit. If the number of new SSL connections in any 10ms window exceeds 1/100 of the effective TPS limit, the error message is triggered. Enforcement is system-wide, not per TMM.


Recommendations:


Calculate the total system-wide SSL TPS:

Licensed TPS × Number of TMMs × HTSplit

Example: 6500 × 11 × 2 = 143,000

For RSA keys ≥4096 bits, apply the 20% rule:

Effective TPS limit = Total System-Wide SSL TPS × 20% Example: 143,000 × .20 = 28,600

The threshold for triggering "SSL transaction (TPS) rate limit reached" is:

Effective TPS limit ÷ 100 per any rolling/sliding 10ms window Example: 28,600 ÷ 100 = 286 new connections in any single rolling/sliding 10ms window

Ensure that your traffic patterns do not exceed this threshold to avoid triggering rate limiting.

Refer to official F5 documentation for further details on how licensing and enforcement work for high key sizes and multi-TMM platforms.
