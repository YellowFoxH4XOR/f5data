Description

Server-side connections are not reused even when configured with a OneConnect profile.

Environment

  • A virtual server is configured with a OneConnect profile.
  • The backend server responds with a HTTP response code other than 200, 206, or 3xx.

Cause

When a backend server sends a HTTP response code other than 200, 206, or 3xx the connection is not eligible for reuse using the OneConnect profile.

Recommended Actions

Any one of the following will ensure that connections are eligible for OneConnect:

  1. Configure the backend server to send a HTTP response code of either 200 or 206 for successful responses.
  2. If running version 14.0 or above, configure allowed HTTP response codes allowed by the OneConnect profile in HTTP profile, using the setting ‘oneconnect-status-reuse’. The allowed range of values are status codes of the format 2xx and 4xx.
  3. Apply an iRule to the virtual server to force the connection to be eligible for OneConnect: 
    when HTTP_RESPONSE {
    ONECONNECT::reuse enable
}
  4. Disable the default behavior of OneConnect when it does NOT receive a HTTP response code of 200 or 206 (default value is true): 
    tmsh modify sys db tmm.http.oc.droponerror value false
    Note: This impacts all virtual servers configured with a OneConnect profile.
    Important:  F5 does not recommend changing this value to false, as then even 5xx responses will allow connection reuse.
