Topic

Starting in BIG-IP 10.0.0, the hash persistence profile can perform a pool member selection using a stateless hash algorithm based on the Cache Array Routing Protocol (CARP). Additionally, starting in BIG-IP 10.2.0, the source address affinity and destination address affinity persistence profiles can also perform pool member selection using a stateless hash algorithm based on CARP. The CARP algorithm was originally described in an IETF draft, which is available at the following location:

http://tools.ietf.org/html/draft-vinod-carp-v1-03

The CARP algorithm provides the following advantages over stateful persistence methods:

  • No memory storage required

    The CARP algorithm uses a stateless selection; therefore, it does not use the persistence table, which is stored in memory.

    Note: Since the CARP algorithm does not store persistence records, commands such as tmsh show /ltm persistence persist-records and bigpipe persist show all cannot be used to monitor CARP persistence.

  • No timeout

    Since the CARP algorithm does not use the persistence table, there is no timeout associated.

  • Failover without mirroring

    Since the CARP persistence method uses a stateless election, no mirroring of persistence data is required in order to maintain persistence after a failover event.

  • Automatic redistribution

    Since the CARP algorithm is based on available pool members, the algorithm automatically adjusts as pool members become available or unavailable, and has the benefit of reducing the percentage of cache misses compared with the default hash algorithm. For example, if you have a pool of four HTTP cache servers, and one server goes offline, the CARP algorithm will redistribute those requests to the remaining servers. Therefore, only connections that were going to that one server will be redistributed. Additionally, when that server is brought back online, only those requests that were originally sent to that server will be directed back. In the case of the default hash algorithm, all requests will be randomly redistributed across the remaining servers each time a server transitions from offline to online.

CARP is an excellent choice for load balancing a pool of HTTP cache proxies, when used in combination with the HTTP and OneConnect profiles. However, the CARP algorithm is not limited to HTTP traffic. Other applications which are compatible with stateless persistence may also benefit from the advantages listed above.

Note: The CARP hash algorithm is not fully compatible with the Match Across settings documented in K5837: Match Across options for session persistence. It can work with Match Across Services and Match Across Virtual Servers only if the profile is applied to virtual servers which share a single pool.

Using the CARP algorithm with the source address affinity or destination address affinity persistence profiles

To enable the CARP algorithm for a source address affinity or destination address affinity persistence profile, select CARP from the Hash Algorithm menu when configuring the persistence profile. If the Hash Algorithm menu is set to Default, CARP hash persistence is not performed and persistence entries are stored in the persistence table.

Using the CARP algorithm with the hash persistence profile

To enable the CARP algorithm for a hash persistence profile, you must configure an iRule with the persist command and associate that iRule with the hash persistence profile. The iRule will enable the CARP algorithm and determine the basis for the persistence. An example iRule is provided in the Implementing the CARP algorithm for HTTP traffic using the hash persistence profile section.

Note: If you choose the default algorithm in the profile, you can use either the persist hash or the persist carp command in the iRule to control the hash algorithm used.

After you configure the iRule, configure a hash persistence profile with the following settings:

  • Hash Algorithm: CARP
  • iRule: Select the iRule you created that contains the persist carp command.

When configuring the virtual server, you must configure the hash persistence profile as the default persistence profile.

Implementing the CARP algorithm for HTTP traffic using the hash persistence profile

To use the CARP algorithm with the hash persistence profile to load balance HTTP traffic across to a pool of HTTP servers or proxies, configure the following objects:

  • iRule
  • Hash persistence profile
  • OneConnect profile (optional)
  • Virtual server

iRule

Configure an iRule with the persist carp command to associate with the hash persistence profile. The iRule will determine the basis for the persistence.

Example iRule that provides CARP URI based persistence:

when HTTP_REQUEST {
   persist carp [HTTP::uri]
}

Example iRule that provides CARP XFF HTTP header based persistence:

ltm rule /Common/xff_carp_persistence {
    when HTTP_REQUEST { 
    if { [HTTP::header exists X-Forwarded-For] } { 
    persist carp [HTTP::header X-Forwarded-For] } 
    }
}

Important: The example iRules, when applied to a virtual server, require that the virtual server be configured with a CARP hash based persistence profile.

Note: For information about configuring iRules, refer to the F5 DevCentral website. A DevCentral login is required to access this content.

Hash persistence profile

Configure a hash persistence profile with the following settings:

  • Hash Algorithm: CARP
  • iRule: Select the iRule you created previously, as described in the iRules section.

When configuring the virtual server, you must configure this profile as the default persistence profile.

Note: For detailed instructions about configuring a persistence profile, refer to the Configuration Guide for the BIG-IP product you are configuring.

OneConnect profile (optional)

Without a OneConnect profile, HTTP traffic is load balanced once per TCP connection. If you want every HTTP request to be load balanced, you must apply a OneConnect profile to the virtual server.

The BIG-IP system provides a default OneConnect profile named oneconnect. If you want to configure different settings, create a new OneConnect profile with the desired settings.

Note: For more information about OneConnect, refer to K7208: Overview of the OneConnect profile.

Note: For detailed instructions about configuring a OneConnect profile, refer to the Configuration Guide for the BIG-IP product you are configuring.

Virtual server

To enable CARP hash persistence on a virtual server, configure the following virtual server settings:

  • Select an HTTP profile from the HTTP Profile menu.
  • Optionally, if you want to load balance each HTTP request, select a OneConnect profile from the OneConnect Profile menu.
  • Select the hash persistence profile from the Default Persistence Profile menu.

    Important: Ensure that the hash persistence profile you select is configured as described in the Hash persistence profile section.

Note: For detailed instructions about configuring a virtual server, refer to the Configuration Guide for the BIG-IP product you are configuring.
