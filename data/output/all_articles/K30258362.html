K30258362: WSL2 Doesn't Always Work with Edge Client or other VPN Software

Type
Support Solution
Published
2021-10-09
Updated
2023-01-09
Applies to
  • BIG-IP
  • BIG-IP APM
  • APM Clients
Source
https://my.f5.com/manage/s/article/K30258362

Description

Window Sub-systems for Linux version 2 may not work as expected when VPN software is also used on same Windows System at the same time.

  • Launching WSL2 and then VPN software on the same Windows 10 device.
  • WSL2 instance is not able to access network or internet.

Environment

Running Windows with both VPN and WSL2 at the same time.

  • Using both Edge Client or other VPN software and WSL2 on a Windows system.
  • Windows 10 OS with WSL2 and Edge Client
  • Edge Client VPN software
  • 172.16.0.0/12 subnet defined in network access resource.

Cause

WSL2 and BIG-IP Edge Client can have an overlap in specific IP address subnets as WSL2 uses 172.16.0.0/12 and in the network access resource. If Edge Client is launched after WSL2 it will overwrite the routes used by the WSL2 instance.

Recommended Actions

Launch the Edge Client software prior to launching WSL2 on your Windows system.

Another option may be to enable the "Allow Local Subnet" setting within the Network Access Resource.

 

Additional Information

If problem remains after Recommended Actions, please open a support case by contacting F5 Networks Support.
