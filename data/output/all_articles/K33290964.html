Known Issue

The BIG-IP system may truncate SNMP object identifiers (OIDs) inconsistently.

This issue occurs when the following condition is met:

  • Long string values for an SNMP OID exceed 128 characters and require truncation.

The long string values that trigger this issue are typically a result of long, user-supplied names for objects in the BIG-IP configuration. When generating an SNMP OID for these objects, the BIG-IP system truncates the SNMP OID so the OID does not exceed a 128 character limit. However, when the BIG-IP system truncates these SNMP OIDs, the truncated OID is not always consistent or unique.

Impact

The commands SNMP get, getnext, and set may fail, or the system might perform the commands on an incorrect object.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the BIG-IP system truncates an SNMP OID to stay within the OID max length limit of 128, the truncated OID is not always consistent or unique.
  • The commands SNMP get, getnext, and set may fail, or the system might perform the commands on an incorrect object.

Workaround

To work around this issue, you may be able to reconfigure affected configuration objects to use shorter names.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your specific environment.
