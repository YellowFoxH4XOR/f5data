Known Issue

Using the Traffic Management Shell (tmsh) to delete a server-side Point-to-Point Tunneling Protocol (PPTP) Generic Routing Encapsulation (GRE) flow may cause the Traffic Management Microkernel (TMM) to restart.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP system to use the Source Address option for the CMP Hash setting on the ingress Virtual Local Area Network (VLAN).
  • You have configured the BIG-IP system to use the Destination Address option for the CMP Hash setting on the egress VLAN.
  • You have configured a Large Scale Nat (LSN) pool with very few translation addresses on the egress VLAN.
  • You use the tmsh utility to delete a PPTP GRE server-side flow.

    For example:

    tmsh delete sys conn ss-client-addr 192.168.10.100 ss-client-port 12345 ss-server-addr 172.16.10.100 ss-server-port 34567

Impact

TMM may restart and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H515888 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.
