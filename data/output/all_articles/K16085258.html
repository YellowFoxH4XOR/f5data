Description

Added a second blade, then assigned the 2 slots to the Guest in the configuration to increase the available memory, but memory usage kept at the same level

Environment

  • VIPRION platform

Cause

Adding a second blade to the Guest configuration adds redundancy in case of a failure in any of the blades, it does not add more CPU resources

The guest uses the same amount of CPU cores in all blades

Please refer to the Manual in the Additional Information section where next statement is presented:

"It is important to understand that the total amount of memory available to a guest is only as much as the host has allocated to each slot."

To increase memory an CPU resources more cores should be added to the Guest, again following statement from the document:

"If you instruct the host to allocate a total of two cores per slot for the guest (for example, 6 GB of memory depending on blade model) and you configure the guest to run on four slots, the host does not aggregate the 6 GB of memory on each slot to provide 24 GB of memory for the guest. Instead, the guest still has a total of 6 GB of memory available."

Recommended Actions

 Increase the number of CPU cores assigned to the Guest

Additional Information

Manual Chapter : Flexible Resource Allocation
