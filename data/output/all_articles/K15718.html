Known Issue

Ended connections with a suspended DNS iRule may leak memory.

This issue occurs when all of the following conditions are met:

  • You are using the DNS_REQUEST or DNS_RESPONSE iRule events.
  • The system suspends and then ends commands, for example, when the system reaches a timeout.

Impact

The BIG-IP system will gradually slow down and then fail over to another system in the device group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H485223 on the Diagnostics > Identified > High screen.
  • The libldns variable continually grows until all memory is exhausted. You can query this variable by using the following command:

    tmctl memory_usage_stat | egrep 'libldns|allocated'

    The output looks similar to the following example:

    name allocated max_allocated size slop cur_allocs
    libldns 70664960 70664960 1 0 846203

    The cur_allocs field continually grows until it reaches the allocated memory for this variable.

  • In the /var/log/ltm file, you may observe messages similar to the following example, which indicate that DNS connections for an iRule have ended:

    info tmm1[<pid>]: 01220009:6: Pending rule /Common/<irule_name> <DNS_RESPONSE> aborted for <ip_address>:<port> -> <ip_address>:<port>

  • The BIG-IP system slows and eventually fails over to another system in the device group.
