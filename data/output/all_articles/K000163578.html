K000163578: WAF Method Restriction Bypass via HTTP Method Override

Type
Support Solution
Published
2026-10-07
Updated
2026-10-07
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163578

Description

BIG-IP ASM blocks direct DELETE and PATCH requests but may allow a POST request containing X-HTTP-Method-Override: DELETE or X-HTTP-Method-Override: PATCH. If the application honors the header, it can process the request using the overridden method while ASM evaluates only the outer POST method. Override requests may reach the application and return 401 Unauthorized.

Environment

  • BIG-IP ASM
  • Security policy restricting DELETE and PATCH methods
  • Application configured to process the X-HTTP-Method-Override header
  • Virtual server handling the affected application traffic

Cause

ASM evaluates the outer HTTP method, such as POST, while the application honors X-HTTP-Method-Override and processes the request as DELETE or PATCH. This difference allows the effective method to bypass the WAF restriction.

Answer/Recommended Actions

If the application does not require HTTP method override functionality, remove the header at the affected virtual server before the request reaches the application.

  1. Create or use an iRule assigned to the affected virtual server:

    when HTTP_REQUEST {
        if { [HTTP::header exists "X-HTTP-Method-Override"] } {
            HTTP::header remove "X-HTTP-Method-Override"
        }
    }

  2. Deploy the iRule in a controlled test or maintenance window.
  3. Test the following request types:
    • Direct DELETE
    • Direct PATCH
    • POST with X-HTTP-Method-Override: DELETE
    • POST with X-HTTP-Method-Override: PATCH
  4. Confirm that requests containing the override header are no longer processed by the application as DELETE or PATCH.
  5. Verify that legitimate application traffic continues to function as expected.
  6. If the application requires method override functionality, do not remove the header without assessing application dependencies. Instead, configure the application and WAF policy so that the effective method is consistently enforced and inspected.

Additional Information

  • Removing the header prevents the application from using it to change the effective HTTP method.
  • Clients that legitimately depend on X-HTTP-Method-Override may be affected.
  • Validate the change before production deployment, particularly for applications using method override functionality.
