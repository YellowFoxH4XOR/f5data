Issue

Old Behavior

In F5 iWorkflow 2.2.0 and earlier, communication between the Application Policy Infrastructure Controller (APIC) and BIG-IP devices is direct and does not take advantage of the iWorkflow representational state transfer (REST) proxy. In these versions, the generated device package leverages the iControl Simple Object Access Protocol (SOAP) interfaces on BIG-IP devices to push configuration updates.

New Behavior

In iWorkflow 2.3.0, the APIC cloud connector relies on the Virtual Clustered Multiprocessing (vCMP) connector to manage vCMP guest instances using the vCMP host.

iWorkflow 2.3.0 creates device packages that take advantage of the REST proxy functionality provided by iWorkflow. Communication between APIC and the BIG-IP system is proxied by iWorkflow. Requests sent by APIC to iWorkflow, to manage vCMP guests, leverage the vCMP Host connector to complete the requests. The iWorkflow administrator must create a vCMP cloud connector for APIC to communicate with guests located on a vCMP host.

F5 Product Development tracked this change as ID 676691.

Impact

iWorkflow administrators must create a vCMP cloud connector prior to creating the APIC cloud connector and downloading the device package to import into APIC. After the vCMP cloud connector is created, iWorkflow automatically discovers the vCMP host followed by vCMP guest instances. If the vCMP connector is not created before APIC sends REST calls to the iWorkflow proxy, requests fail to reach the vCMP host and guests.

Recommended Actions

After upgrading to iWorkflow 2.3.0, you must create a new vCMP cloud connector, if one does not already exist, and download a new device package from the APIC cloud connector. If you do not complete these steps, APIC continues to use the SOAP interfaces on the BIG-IP system instead of the REST proxy on iWorkflow. For more information about updating the APIC device package, refer to K44010954: Updating or creating an F5 iWorkflow APIC device package.
