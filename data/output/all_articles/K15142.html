Known Issue

BIG-IP APM Network Access may fail when Windows clients connect using Transport Layer Security (TLS) protocol 1.2.

This issue occurs when all of the following conditions are met:

  • The virtual server providing network access is configured with a Client SSL profile.
  • The Client SSL profile configuration contains AES128-SHA256 and/or AES256-SHA256 SSL ciphers.
  • The browser is configured to allow TLS 1.2.

If the browser session negotiates to use either AES128-SHA256 or AES256-SHA256 SSL ciphers, the BIG-IP APM system authenticates the user, but fails to establish Network Access.

Impact

Users are unable to establish a Network Access session.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H426301 on the Diagnostics > Identified > Medium|High screen.
  • Users are unable to connect to BIG-IP APM Network Access and are redirected to the logout page.
  • Network Access tunnel creation fails with a message that appears similar to the following example:

    Failed to download configuration

Workaround

You may be able to work around this issue by altering the cipher strength in the Client SSL profile to prevent selection of the AES128-SHA256 or AES256-SHA256 SSL ciphers. For more information about configuring the cipher strength for SSL profiles, refer to K13171: Configuring the cipher strength for SSL profiles (11.x).
