Description

This article describes how to use the iControl REST API to retrieve all of the Virtual Servers that have a BIG-IP ASM Policy applied to it. There are multiple field names that will provide this information for you and we go through them both in this article.

Environment

  • One or more ASM policy configured
  • Virtual Server configured with either of the following:
    • Local Traffic Policy (consisting of at least one rule with ASM control)
    • ASM Policy
  • Optional: REST API client such as Postman API or Advanced REST Client.

Cause
None

Recommended Actions

Use iControl REST API to List all Virtual Servers with an ASM Policy associated:

Query the following iControl REST API Endpoint:

/mgmt/tm/asm/policies?$select=name,virtualServers,manualVirtualServers

For Example:

curl -k https://10.0.0.1/mgmt/tm/asm/policies?$select=name,virtualServers,manualVirtualServers

Additional Information

The following REST API endpoint query is typically used for retrieving the list of virtual servers that have a security policy applied to it:

/mgmt/tm/asm/policies?$select=name,virtualServers

In the above select statement, it was only returning virtual servers associated to the virtualServers field. The Virtual Servers in this list are ones that have a security policy directly associated to them under the virtual server's Security > Policies configuration tab within the GUI. After doing this, a corresponding LTM policy gets created with a naming convention of asm_auto_l7_policy__<virtual-server> with a default rule that ASM policy enabled for all traffic. Any further modification made to this LTM policy (for e.g. adding an additional rule or two) will result in the security policy under Security > Policies tab for the VIP to be displayed as Manual Configuration (Advanced).

However, the above REST API query doesn't account for virtual servers that have Manual Configuration (Advanced) LTM policy configuration which, in turn, have rule(s) built with ASM control actions enabled. That config is in fact maintained under a field called manualVirtualServers. Given this wasn't part of our initial query, it wouldn't returning all the virtual server objects that were using an ASM policy.  Instead, it would omit any ASM policy that is manually attached to a LTM policy under Local Traffic > Policies section. For these scenarios, we see that a REST API endpoint query such as the following that returns all the virtual servers list:

/mgmt/tm/asm/policies?$select=name,virtualServers,manualVirtualServers
