Description

The Sender Protection Framework (SPF) resource record type is defined in RFC 7208, where it is noted that this resource record type is considered deprecated and you should use the TXT record type instead. 

So BIG-IP DNS system does not support the SPF resource record type and as described in K75451742: Support for the SPF resource record type, you set the DNS query type as TXT and get corresponding answer for the queried domain name.

For example, when using dig to get the TXT resource record from BIG-IP DNS for mail.example.com, you will get answer below:

;; ANSWER SECTION:

mail.example.com.          10      IN      TXT    "v=spf1 ip4:192.168.111.111 -all"

While in some cases, such like your mail server requires SPF resource record but not TXT, and you want BIG-IP DNS to return SPF resource record.

For example, when using dig to get the SPF resource record from BIG-IP DNS for mail.example.com, you want to get answer below:

;; ANSWER SECTION:

mail.example.com.          10      IN      SPF     "v=spf1 ip4:192.168.111.111 -all"

But you'll get no answer under this condition. 

Environment

  • BIG-IP DNS
  • SPF
  • iRule

Cause

As described in the beginning, BIG-IP DNS only supports TXT type SPF resource record.

Recommended Actions

You can follow procedures below to meet your requirement.

  1. Navigate to DNS >> Delivery >> iRules >> iRule List and create a new iRule with following command syntax:

    when DNS_REQUEST {
    # Log query details
    log local0. "\[DNS::question name\]: [DNS::question name],\[DNS::question class\]: [DNS::question class],\[DNS::question type\]: [DNS::question type]"

    if {([string tolower [DNS::question name]] equals "<domain name>") and ([DNS::question type] equals "SPF")} {
        # Generate an answer with SPF record
        DNS::answer insert "[DNS::question name]. <integer value of TTL> [DNS::question class] [DNS::question type] \"<SPF record text>\""

        # Stop further processing of the query after this iRule and send the answer to the client
        DNS::return
    }
    }

  2. Associate the new created iRule to all your BIG-IP DNS listeners by navigating to DNS >> Delivery >> Listeners >> Listener List >> your listener. In the iRules configuration panel, click Manage, then select the new created iRule in the Available column and move it to the Selected column and finally click Update.

Additional Information

For example, if the domain name you want to set DNS query is mail.example.com with SPF resource record "v=spf1 ip4:192.168.111.111 -all" and TTL 10 seconds, then the iRule should be:

when DNS_REQUEST {
# Log query details
log local0. "\[DNS::question name\]: [DNS::question name],\[DNS::question class\]: [DNS::question class],\[DNS::question type\]: [DNS::question type]"

if {([string tolower [DNS::question name]] equals "mail.example.com") and ([DNS::question type] equals "SPF")} {
    # Generate an answer with SPF record
    DNS::answer insert "[DNS::question name]. 10 [DNS::question class] [DNS::question type] \"v=spf1 ip4:192.168.111.111 -all\""

    # Stop further processing of the query after this iRule and send the answer to the client
    DNS::return
}
}

This time, you will get the SPF resource record that you want for mail.example.com.
