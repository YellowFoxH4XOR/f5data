Known Issue

This is the result of a known issue. The Maximum Addresses Returned setting is missing from the BIG-IP Link Controller Configuration utility. An omission in a BIG-IP feature flag prevents the Maximum Addresses Returned setting from displaying and operating properly.

The feature, which was previously named Round Robin LDNS, allows an administrator to specify the number of A or AAAA DNS records returned by the Link Controller system when a DNS query matches a wide IP.

F5 Product Development tracked this issue as CR59781, CR59786 and CR67966, and it was fixed in BIG-IP Link Controller 9.3 and 9.4. For information about upgrading, refer to the BIG-IP Link Controller Release Notes.

Note: The Maximum Addresses Returned setting was added to the Configuration utility in BIG-IP Link Controller 9.4. The feature also exists in version 9.2.4, however, it is only configurable from the command line in version 9.2.4. In BIG-IP Link Controller 9.2.4, the change must be made to the /config/gtm/wideip.conf file under the pool properties as follows:

// *** Pool Definitions (1) ***

pool {
   name           "www.site.net"
   ttl            30
   preferred      rr
   alternate      null
   fallback       null
   rr_ldns_limit  2  <== Setting for maximum number of addresses returned

   member         10.24.2.105:80
   member         10.24.2.106:80
}

To set this feature, perform the following procedure from the command line:

  1. Change directories to the /config/gtm/wideip.conf directory by typing the following command:

    cd /config/gtm/

  2. Create a backup of the wideip.conf file by typing the following command:

    cp wideip.conf wideip.conf.original

  3. Using a text editor, edit the wideip.conf file.
  4. Locate the Pools Definitions header.
  5. Locate the pool or pools to which you want to add the maximum addresses, and add the following line after the load balancing method:

    rr_ldns_limit #

    Replace the pound sign ( # ) with the number of addresses you want the Link Controller to return.

  6. Save the configuration change.
  7. Ensure that the configuration file is syntactically correct by typing the following command:

    gtmparse

  8. If step 7 did not return any errors, load the new changes by typing the following command:

    gtmload
