K000151525: BIG-IP LTM sync status always shows "Changes Pending" after manual sync Due to CIS Integration and Static Route Automation

Type
Support Solution
Published
2026-08-31
Updated
2026-08-31
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000151525

Description

BIG-IP LTM devices configured in a high availability (HA) pair may continuously display a "changes pending" status, even after performing manual configuration syncs. System audit logs reveal repeated creation and deletion of static routes, often within partitions managed by F5 Container Ingress Services (CIS). The following log messages may be observed:

AUDIT - client tmsh, user admin - create { route_static_entry ... }

AUDIT - client tmsh, user admin - obj_delete { route_static_entry ... }

Unable to do incremental sync, reverting to full load for device group ...

Environment

  • Two BIG-IP LTM devices in HA with manual sync
  • Integration with F5 Container Ingress Services (CIS), which manages specific partitions
  • Static routes are automatically managed by CIS

Cause

  • F5 Container Ingress Services (CIS) automatically creates and deletes static routes in the partitions it manages.
  • CIS monitors its managed partitions and re-applies its configuration if any changes are detected—including those resulting from HA config sync.
  • Manual or external changes (including HA sync) in CIS-managed partitions are overwritten by CIS, resulting in continuous configuration changes and a persistent "changes pending" status.

Recommended Actions

Increase Incremental-config-sync-size-max parameter for the device group to prevent incremental sync failures:


modify cm device-group <device_group_name> incremental-config-sync-size-max <value>

     

    Please note also that CIS monitors and manages its assigned partitions and will overwrite any manual or external changes.
    F5 strongly advised against making manual changes or syncing configuration in partitions managed by CIS, as this can cause unexpected behavior or service disruption.
