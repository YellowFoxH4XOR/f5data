Description

Control-Plane CPU may increase for short periods of time at regular intervals, ranging from one to several days. 

 

Environment

  • BIG-IP LTM

 

Cause

Long-running Java processes (such as restjavad) will run a Garbage Collection routine that increases control-plane CPU while it executes.

In particular, a Full Garbage Collection process will run at regular intervals - this interval is determined by Java itself, and depends on the allocation and freeing of objects within the Java process itself.

 

Recommended Actions

No action needs to be taken - this is expected behaviour, and is not detrimental to the running of the BIG-IP. 
The data-plane processing will have priority for CPU time, so Java Full Garbage Collection will not adversely affect network traffic.

We can see the priority of the restjavad process is 0 (normal).

  1. # top -n | grep "top\|CPU" -A 2 |grep -v "Tasks\|Cpu"
  2. --------------
  3. top - 14:13:40 up 885 days, 4 min, 1 user, load average: 4.27, 2.05, 1.10
  4. --
  5. PPID PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND P SWAP
  6. 6515 6535 root 20 0 673300 516552 3504 S 309.4 1.6 50954:50 java 5 6972
  7.                  ^^

If the Full Java Garbage Collection occurs at an inconvenient time, restarting restjavad will reset the time that this process starts.

 

tmsh restart /sys service restjavad

Note: This will affect the WebUI as restjavad restarts.

 

Additional Information

Determining when the Full Garbage Collector is running can be difficult:

If we look at the logs for Full GC and also filter on a specific day (2024-03-22) we can see that there are 308 logs recorded:

  1. /var/log$ zgrep "2024-03-22.*Full GC " * | wc -l
  2. 308

If you can see the CPU utilization graph, you can determine the time of the CPU use of concern.
For this example, the CPU peak occurred between 14:00 and 15:00.


Filter on that time period: "2024-03-22T14.*Full GC "

  1. /var/log$ zgrep "2024-03-22T14.*Full GC " * | wc -l
  2. 303

We see that 303 of 308 Garbage Collection events occurred in that time period.

Use head, and tail to see when those events started and finished:

  1. /var/log$ zgrep "2024-03-18T14.*Full GC " * | head -1
  2. restjavad-gc.log.0:2024-03-18T14:12:10.334+0800: 76118411.290: [Full GC 382973K->254321K(382976K), 0.7690730 secs]
  3. /var/log$ zgrep "2024-03-22T14.*Full GC " * | tail -1
  4. restjavad-gc.log.1.current:2024-03-22T14:18:41.964+0800: 76464402.919: [Full GC 265213K->243652K(383744K), 0.9187440 secs]

So Full Garbage collection started at 14:12 and ended at 14:18 - six minutes.

Further analysis allows determination of the Full Garbage Collection period:

Very few Garbage collection events occurred on the previous day 2024-03-21 :

  1.  /var/log$ zgrep "2024-03-21.*Full GC " * | wc -l
  2. 8

We see another run (smaller) of Full Garbage Collection on 2024-03-20 between 14:00 and 15:00, starting at 14:12 and ending at 14:54

  1. /var/log$ zgrep "2024-03-20.*Full GC " * | wc -l
  2. 149
  3. /var/log$ zgrep "2024-03-20T14.*Full GC " * | wc -l
  4. 140
  5. /var/log$ zgrep "2024-03-20T14.*Full GC " * | head -1
  6. restjavad-gc.log.0:2024-03-20T14:12:10.164+0800: 76291211.119: [Full GC 262519K->257495K(378368K), 0.7833160 secs]
  7. /var/log$ zgrep "2024-03-20T14.*Full GC " * | tail -1
  8. restjavad-gc.log.0:2024-03-20T14:54:58.467+0800: 76293779.423: [Full GC 385761K->242726K(388608K), 0.7027010 secs]

This pattern can be seen to be repeated in the logs.
