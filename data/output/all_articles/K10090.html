Known Issue

The csyncd process exists to replicate portions of the filesystem between cluster members on VIPRION systems.

When a file name containing whitespace or certain characters is present in an area to be synchronized to another blade, such as the /shared/images directory, the file will not synchronize and an error message is logged to the /var/log/ltm or /var/log/daemon.log file.

Note: This issue can occur with a filename containing whitespace, or other characters with special meaning to the shell, such as the following:

  • 0x20 (space)
  • 0x22 (double quote)
  • 0x24 (dollar symbol)
  • 0x26 (ampersand)
  • 0x27 (single quote)
  • 0x28 (left parenthesis)
  • 0x29 (right parenthesis)
  • 0x3b (semicolon)
  • 0x3c (less than)
  • 0x3e (greater than)
  • 0x5b (left bracket)
  • 0x5c (backslash)
  • 0x5d (right bracket)
  • 0x60 (back tick)
  • 0x7b (left brace)
  • 0x7c (vertical bar)
  • 0x7d (right brace)

BIG-IP 10.x

For example, if the foo bar.txt file exists in the /shared/images directory on the VIPRION system, the file will not synchronize among cluster members, and an error message that appears similar to the following example is repeatedly logged to the /var/log/ltm file:

csyncd[2309]: 013b0005:4: Command failed: cmd=rsync -qa --timeout=15 --bwlimit=5000 rsync://127.3.0.1/csync/shared/images/foo /shared/images/foo, rc=23

BIG-IP 9.6.x

For example, if the foo bar.txt file exists in the /shared/images directory on the VIPRION system, the file will not synchronize among cluster members, and an error message that appears similar to the following example is repeatedly logged to the /var/log/daemon.log file:

rsync: link_stat "/shared/images/foo" (in csync) failed: No such file or directory (2)
rsync error: some files could not be transferred (code 23) at main.c(670) [sender=2.6.9]

Note: The displayed error message does not contain the part of the file name following the whitespace.

Workaround

If a file on the VIPRION system does not synchronize because the file name contains whitespace or other characters, you can work around the issue by renaming the offending file and removing the whitespace or special character from the file name. F5 recommends that you use the cluster shell (clsh) command in clustered systems if you need to move or delete a file that simultaneously runs the command on multiple blades.

For example:

# clsh mv /shared/images/myfile.iso /shared/images/BIGIP-11.6.0.0.0.401.iso
