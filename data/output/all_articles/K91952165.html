K91952165: Can't access Azure F5 BIG-IP, GUI whitelisted public IP changed

Type
Support Solution
Published
2022-09-27
Updated
2025-02-07
Applies to
  • Public Cloud
  • BIG-IP
  • BIG-IP Cloud Edition
  • Microsoft Azure
Source
https://my.f5.com/manage/s/article/K91952165

Description

Unable to access to the BIG-IP VE hosted on Azure because of previously trusted/whitelisted public IP changed and no longer accessible, and got prompt error:

Access forbidden!
You don't have permission to access the requested object.

Error 403

Environment

  • BIG-IP
  • Virtual Edition
  • Microsoft Azure
  • Public IP
  • Trusted/Whitelisted IP list

Cause

Change of environment where public IP needed to be changed to a new set of subnet range, and forgot to update the BIG-IP trusted/whitelisted public IP list before lost access to the existing public IP on new set of public IP subnet

Recommended Actions

There are two option you may approach in this cases as below.

  • Access via Azure serial console to the hosted BIG-IP and remove/update the public IP details
  • If Azure serial console is not possible for some reason, then, you may try follow steps below:
    1. First, please follow KB article to try reset the Azure hosted BIG-IP VE local user (root/admin)
      https://clouddocs.f5.com/cloud/public/v1/shared/azure_passwordreset.html
       
    2. If that failed, then, please refer to Microsoft Azure documentation attached to manually create a Rescue VM to be used to create a duplicate copy of the running Azure hosted BIG-IP snapshot so that we can mounted the BIG-IP LVM "/config" onto the Rescue VM to allow us to remove/modify the "bigip_base.conf".
      https://docs.microsoft.com/en-us/troubleshoot/azure/virtual-machines/chroot-environment-linux
      Notes: If you need help on above steps, please engage Microsoft Azure TAC for assistant.
      Note: This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.
       
      • Steps listed below is an example once you have successfully attached the Azure hosted BIG-IP snapshot duplicate copy onto the Rescue VM.
      • You should see similar output below as an example:
        BIG-IP LVM:
        sdx
        |- sdx1
        |- sdx2
        |- sdx3
        ...
            |- vg--db--sdx-set.1.root
            |- vg--db--sdx-set.1._usr
            |- vg-db-sdx-set.1._config
            |- vg-db-sdx-set.1._var
        ...
            |- vg--db--sdx-set.2.root
            |- vg--db--sdx-set.2._usr
            |- vg-db-sdx-set.2._config
            |- vg-db-sdx-set.2._var
        notes: x = drive character
         
      • Following the Microsoft Azure documentation above, below are the example steps to mount the "/config" folder
        # mkdir /rescue
        # mount /dev/mapper/vg-db-sda-set.1._config /rescue/config
         
      • Once done, you may proceed to edit the bigip_base.conf to remove/update the trust/whitelisted public IP
        # vim /rescue/config/bigip_base.conf, and then look for below entry and remove/update accordingly:
        sys httpd {
            allow { x.x.x.x y.y.y.y }     <<<< either modify the list IP address entry or remove this line entirely.
        ...
         
      • Once done remove/updated the whitelisted public IP, follow the steps listed in the Microsoft Azure documentation (item 6 onwards)
         

Additional Information

If happen to have missed place the root/admin password to login via Azure serial console, please follow documentation attached to reset the password.
https://clouddocs.f5.com/cloud/public/v1/shared/azure_passwordreset.html
