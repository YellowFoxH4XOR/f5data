K000163795: How to Identify and Address NGINX Plus Automatic JWT Renewal Failure

Type
Support Solution
Published
2026-10-20
Updated
2026-10-20
Applies to
  • NGINX Products
  • NGINX Plus
Source
https://my.f5.com/manage/s/article/K000163795

Description

NGINX Plus automatic JWT renewal may not complete when the renewed token cannot be retrieved, validated, applied, or saved to the configured state location. The previous license remains active, and the error log may contain messages such as:

new license token was received

"/var/lib/nginx/state/nginx-mgmt-license" failed (13: Permission denied)
license will expire in <number> days
license expired; the grace period will end in <number> days
license expired

Environment

  • NGINX Plus R35 or later
  • Direct communication with the F5 licensing endpoint
  • Usage reporting enabled and able to complete successfully
  • Term subscription eligible for automatic JWT renewal
  • Configured state_path, with the default location typically being /var/lib/nginx/state
  • NGINX management module configured through the top-level mgmt {} block

Cause

Automatic JWT renewal requires successful usage reporting, a supported subscription type, and the ability to save the renewed token to the configured state location.

The renewed token is stored in the NGINX state location and does not replace the original license.jwt file. If NGINX cannot write to the state location, the renewed token is not applied. NGINX continues using the previous license and may later log license-expiration or grace-period warnings.

Automatic renewal is not supported when:

  • A term subscription changes to the Flexible Consumption Program.
  • A Flexible Consumption Program subscription renews as another Flexible Consumption Program subscription.

Recommended Actions

  1. Verify that usage reporting is enabled and completes successfully.
  2. Confirm that the subscription is eligible for automatic JWT renewal.
  3. Confirm that NGINX can reach the F5 licensing endpoint.
  4. Verify that the NGINX service has permission to write to the configured state_path.
  5. Review /var/log/nginx/error.log for renewal, state-file, and license-expiration messages.
  6. Check the NGINX Plus License API active_till value to confirm the active license expiration time.
  7. Allow subsequent usage-report cycles to retry the renewal. Usage reporting normally occurs hourly and can be adjusted with the usage_report interval setting.
  8. Treat the following message as confirmation that NGINX received, parsed, and saved the renewed token locally: 
    new license token was received
  9. If activation must be deferred, configure the license_pending_token directive to save the renewed token to a specified file. Manual action is required to complete the update.
  10. If the JWT is within the 90-day grace period and all prerequisites are satisfied, a successful usage-report cycle can retrieve and apply the renewed token.
  11. If the JWT is beyond the 90-day grace period and no usable renewed license state exists, manually replace the JWT before starting NGINX.

Additional Information

  • The JWT and package-repository credentials serve different purposes:
    • The JWT controls whether NGINX Plus can start and process traffic.
    • Repository certificate and key files control access to the NGINX Plus package repository.
  • A valid repository certificate and key must be available before upgrading NGINX Plus. JWT automatic renewal does not authorize package downloads or automate the package upgrade process.
  • A successful usage report from an earlier release should not be assumed to satisfy all renewal prerequisites after an upgrade. The upgraded instance must be able to complete a successful usage report.
  • The active license should be verified using both the License API active_till value and /var/log/nginx/error.log.
  • No separate renewal-status indicator is required for this behavior.
  • If the state location is not writable, NGINX continues using the previous license until it expires or reaches the end of the applicable grace period.
