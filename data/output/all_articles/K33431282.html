Topic

BIG-IP Cloud Edition provides traffic management and security application services on a per-application basis using BIG-IP LTM and Advanced WAF, respectively, to isolate workloads and for better manageability.

In addition, you can auto-scale application services based on predefined thresholds.

To further enhance manageability, BIG-IP Cloud Edition enables network and security operations teams to provide application teams with self-service deployment of application services in public and private clouds.

BIG-IP Cloud Edition is a solution package comprised of the BIG-IQ system, BIG-IP Per-App Virtual Edition (VE), and other supporting components. This article describes all the components in the package and provides references for more information about each component.

Note: You can currently auto-scale per-app virtual edition instances on Microsoft Azure, Amazon Web Services (AWS), and VMWare.

Description

The BIG-IP Cloud Edition consists of the following components:

  • BIG-IQ Centralized Management
  • Data Collection Devices in BIG-IQ Centralized Management
  • BIG-IP Per-App VE
  • Load balancer for auto-scaling

BIG-IQ Centralized Management

BIG-IQ Centralized Management administers all your BIG-IP devices from a single location. BIG-IP Cloud Edition includes BIG-IQ Centralized Management 6.0.0 and later.

This release introduces auto-scaling using the service scaling group feature, which enables administrators to configure the BIG-IQ system to scale-out or scale-in BIG-IP virtual edition instances based on scaling rules, such as CPU and memory use or throughput.

You define new BIG-IP virtual edition instances using device templates. These templates enable device instantiation, licensing, provisioning, and networking for scaling-out. You define pools of IP addresses and licenses in device templates, which the BIG-IQ system distributes. Device templates handle the base configuration while application templates handle high-level configuration.

Application templates enable you to define the BIG-IP LTM and Advanced WAF configurations that the system deploys to the service scaling group or individual BIG-IPs. As a BIG-IQ administrator, you can configure default template features and then expose a limited set of options for application owners to use when they create an application. You create custom application roles to give application owners access to specific templates. The system also has predefined application templates that cover common deployment scenarios.

BIG-IQ Cloud Edition 6.0.0 also introduces an enhanced BIG-IQ dashboard and analytics.

Your purchasing option for BIG-IQ Centralized Management is a perpetual license.

Important: You cannot upgrade an existing BIG-IQ configuration to BIG-IQ 6.0.0; it requires a clean install. Additionally, BIG-IQ 6.0.0 is available as a VE product only.

Data Collection Devices in BIG-IQ Centralized Management

BIG-IQ's Data Collection Device is a BIG-IQ system that you provision to store alerts, events, and statistics from one or more BIG-IP systems. This feature offloads collection and storage tasks from BIG-IQ Centralized Management, referred to as the BIG-IQ console in the context of an implementation with a Data Collection Device.

The role the BIG-IQ system performs is called the system personality, and you choose BIG-IQ Centralized Management or the Data Collection Device during BIG-IQ initial setup. You can navigate to the BIG-IQ setup wizard using the following URL:

https://<MGMT_IP>/ui/setup

To collect data from the managed BIG-IPs, you add Data Collection Devices in a cluster of at least two devices. The BIG-IQ console then accesses the data stored on the Data Collection Devices for the BIG-IQ administrator to search and display.

Remote storage device

When you want to back up the data that the Data Collection Devices collect or retain the data after an upgrade, you need to allocate remote storage for the Data Collection Device cluster.

BIG-IP Per-App VE

F5 introduced BIG-IP Per-App VE with BIG-IP 13.1.0.2; however, you must have BIG-IP 13.1.0.5 for compatibility with BIG-IQ 6.0.0. For compatibility between The BIG-IQ system and other BIG-IP versions, refer to K34133507: BIG-IQ Centralized Management compatibility matrix. These BIG-IPs have a reduced disk image size and faster boot up time. The single slot images reduce the disk size even further. This type of image is suited for the "nuke and pave" deployment workflow.

BIG-IP Per-App VE supports BIG-IP LTM and Advanced WAF modules, and you can deploy each instance with either a 25 megabits per second (Mbps) or 200 Mbps throughput rate license limit. You have subscription, enterprise licensing agreement, or perpetual licensing purchase options with these devices.

Finally, BIG-IP Per-App VE is designed to provide application services for a single application; therefore, you can configure each instance with only one virtual address and up to three virtual servers using different ports. Providing application services to a single application isolates maintenance and troubleshooting. For example, you don't have to take into consideration impacts to unrelated applications when you upgrade the BIG-IP system or perform diagnostic tasks on the BIG-IP system for troubleshooting.

Load balancer for autoscaling

When you deploy BIG-IP virtual editions in a service scaling group, you must use two tiers of load balancing. This configuration distributes traffic to the dynamically created and deleted BIG-IP virtual edition instances, which then distribute traffic to your application servers. In this configuration, Tier 1 is a device that performs Layer 4 (L4) load balancing and Tier 2 is the group of per-app virtual editions in your service scaling group that perform more advanced load balancing and application services.

The Tier 1 load balancer in AWS is the Elastic Load Balancer (ELB) Classic, in Azure it is a Basic Load Balancer, and in VMWare it is a BIG-IP service scaler. The BIG-IP service scalar is a specialized virtual edition that performs up to L4 functionality only. You have the option of provisioning BIG-IP AFM for L4 distributed denial of service (DDoS) protection and firewall functions.
