Topic

Use this guide to identify the information you need to gather for your F5 product when opening a support case.

Description

As of March 2023, this one article replaces several individual articles. Each of the individual articles contained the information F5 Support requests in a support case for an individual product. Now, that product-specific information for support cases is in this article.

Describe the issue

Before you open a support case, gather the following required information:

  • Symptoms of the issue, including a brief description of any systems related to the configuration.
  • Approximate time the issue first occurred.
  • Number of times the issue recurred.
  • Error output provided by the system.
  • Steps to reproduce the issue.
  • Changes you made to the system before the issue first occurred.
  • Steps you took to resolve the issue.
  • Note if you are using a new implementation.
  • Links to QKView files if you uploaded QKView files to iHealth (for BIG-IP products)

Most of the remaining information you collect is contained in files that you give to F5 Support. To learn how, refer to K000090853: Exchange files with F5 Support.

Collect BIG-IP- and BIG-IQ-related information about the issue (for BIG-IP and BIG-IQ products but not BIG-IP Next products)

When you gather the following BIG-IP- and BIG-IQ-related information, F5 Support may be able to resolve your case more quickly.

Client-specific information

When your issue is specific to a particular client, you need the following information:

  • Operating system, version, and patch level
  • Browser type and version
  • SSL VPN client log file information

To get the SSL VPN client log information, perform one of the procedures in the following table.

ClientProcedures
Microsoft Windows systemsUse one of the following procedures:

Use the Client Troubleshooting Utility
Important: F5 recommends that you use this procedure to gather diagnostic information. The Client Troubleshooting Utility (CTU) takes into account unique installation and configuration parameters and paths that cannot be anticipated for all deployments when manually gathering these details. F5 also recommends that you use this procedure when you are using browser-based access.
  1. Download and run the Client Troubleshooting Utility.

    For more information, refer to K12444: Overview of the Client Troubleshooting Utility for Windows.

  2. Select File.
  3. Select Generate Report.
  4. Select the Text option.
  5. Select Save As.
  6. Enter a path and file name where you want to save the report.
  7. Select Save.
  8. When the report completes, select Cancel.
When you are using the BIG-IP Edge Client for Microsoft Windows, you can also obtain a diagnostic report by doing the following:
  1. Open the BIG-IP Edge Client.
  2. Select View Details. 
  3. Select Diagnostic Report, select the location where you want to save the file, and select Save.

Copy the log files from the client system
If you cannot run the CTU, collect the log files by performing the following procedure:
  1. From the client machine, Select Start.
  2. Select Run.
  3. In the Open: field, enter %temp%.
  4. Select OK.
  5. Copy all files that start with characters f5.

    For example:

    f5dskctl.txt, f5InspectionUser.txt, f5Install.txt

  6. Copy the logterminal.txt file.

Enable logging for the F5 Access client on Windows 10
You can enable logging for the F5 Access client on Windows 10 through the Event Viewer by doing the following:
  1. From the client machine, select Start.
  2. Enter Event Viewer and press Enter.
  3. Go to the following directories:
    • Event Viewer (Local) > Applications and Services Logs > Microsoft . Windows > Vpn Plugin Platform > Operational
    • Event Viewer (Local) > Applications and Services Logs > Microsoft . Windows > Vpn Plugin Platform > OperationalVerbose
  4. Select and hold (right-click) Value and select Properties.
  5. Select the Enable Logging check box.
  6. Select OK.
Apple Mac OS X systems
  1. Log in to the command line.
  2. To go to the ~/Library/Logs/F5Networks directory, enter the following command:

    cd ~/Library/Logs/F5Networks

    Note: Older versions of the Apple MAC OS X client save log files in the /Library/Internet Plug-Ins/f5_sslvpn.bundle/var/log/ directory.

  3. To view the svpn.err file, enter the following command:

  4. Copy and save all the information for your case.
  5. Gather Network Access debugging information.

    For more information, refer to K12321: Enabling Network Access debugging for Mac OS X and Linux.

  1. Log in to the command line.
  2. Go to the /usr/local/lib/F5Networks/SSLVPN/var/log/ directory, enter the following command:

  3. To view the svpn.ERR log, type the following command:

    more svpn.ERR

  4. Copy and save all the information for your case.
  5. Gather Network Access debugging information.

    For more information, refer to K12321: Enabling Network Access debugging for Mac OS X and Linux

Windows Mobile devices
  1. Go to the following files:
    • \Temp\f5SSLVPNlog.txt
    • \Temp\comdriverlog.txt
  2. Copy and save the information from these log files for your case.

  2. Select the Settings icon.
  3. Select Support.

  5. In To, enter the email address to which you want to send the logs.
  6. Select Send.
Android devicesOn Android devices using the F5 Access Client app, you can email the client files to your own email address. You must have an email account on your Android device.

To do so, do the following:
  1. On the Android device, open the F5 Access Client app.
  2. Select the Settings icon.
  3. Select Diagnostics.
  4. Select the Bug icon in the upper right corner.

    A Collecting Data message displays temporarily while the F5 Access logs are collected into an F5AccessReport.zip file.

    A Send log screen presents a list of apps available on your device that you can use to transfer the file.

  5. Select the email app.

    An email window displays with the F5AccessReport.zip file attached.

  6. In the To field, enter the email address to which you want to send the logs.
  7. Select Send.
Chrome OS systems

Note: The previous link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.
Packet traceTo perform the packet trace on the BIG-IP ASM system:
  • Enter the following command syntax :

    tcpdump –nni 0.0:nnn –s 0 host <VIP> or host <pool_member1> or host <pool_member2> and port <port_number> –w /var/tmp/tcpdump.pcap

For information about performing packet traces, refer to K4714: Performing a packet trace and providing the results to F5 Support.

Tips:
  • The packet trace may be verbose, depending on how much traffic is passing through the BIG-IP ASM system. You can use additional filters to limit the hosts captured, but ensure you do not filter out the affected traffic.
  • When you provide the packet trace, provide the IP addresses involved in it (for example, the client IP, virtual server IP, and pool members IP).
  • If the affected traffic is encrypted, decrypt the packet trace using the ssldump utility. For more information about decrypting, refer to K10209: Overview of packet tracing with the ssldump utility.
Security policyProvide an example of the:
  • Request that triggers the problem.
  • Corresponding Support ID.
  • Affected security policy.
To export the affected security policy, do the following:
  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Security Policies.
  3. Select the policy you want to export.
  4. Select Export.
  5. Follow the steps to download the policy.
XML profilesIf the issue involves XML profiles, provide the XML schema files, such as WSDL and XSD.

BIG-IP SSL Orchestrator

InformationDetails
DebuggingBefore you collect log files, you must enable debug logging and reproduce the issue.

Tips:
  • Debug logging in Per-Request policies can be verbose. Depending on your environment, you may plan to perform this procedure either during off peak hours or during a scheduled maintenance window.
  • Depending on your system, debug logging may quickly increase the file size of the log files. After reproducing the issue, revert the change by immediately turning debug logging off.
To enable debug logging, do the following:
  1. Log in to the Configuration utility.
  2. Go to SSL Orchestrator  >  Configuration.
  3. Select the name of your topology.
  4. Select Log Settings.
  5. For Per-Request Policy and SSL Orchestrator Generic, select Debug.
  6. Select Save & Next.
  7. Select Deploy.
Objects and configurationsBeginning in SSL Orchestrator 9.0, you can generate an iFile that captures SSL Orchestrator objects and configurations.

To do so, do the following:
  • Enter the following command:

    restcurl -X POST -d '{"operation": "read"}' https://127.0.0.1/mgmt/shared/iapp/f5-iappslx-ssl-orchestrator/mcpBlockIO -u : > /var/tmp/"$HOSTNAME"_ifile

    The system names the file "$HOSTNAME"_ifile and locates it in the /var/tmp directory.

Web browserWhen an issue occurs while the user performs API calls using a supported web browser with RESTful ability to interact with the BIG-IQ system, you are required to provide the following information:
  • Type and version of the web browser
  • Error reported on the Developer Tool Console
  • Screen capture of the error returned from the BIG-IQ system (if available)
This information is required because the errors generated from an issue in the JavaScript console exist in the user's web browser and cannot be captured by the BIG-IQ system.

Supported web browsers include:
  • Microsoft Edge
  • Mozilla Firefox
  • Google Chrome.
To retrieve the required information, do the following:
  1. To locate your web browser version, do the one that applies to your browser:
    • For Microsoft Edge, go to Settings and more (...) > Settings and select About Microsoft Edge.
    • For Mozilla Firefox, press the Alt or F10 key (for users with the hidden Firefox menu bar), and go to Help > About Firefox or Firefox > About Firefox on MacOS.
    • For Google Chrome, in the URL bar, enter chrome://version, and press Enter.
  2. To access the Developer Tools Console and capture any logged error messages when you reproduce the issue, do the one that applies to your browser:
    • For Microsoft Edge, go to Settings and more (...) > More Tools > Developer Tools.
    • For Mozilla Firefox, press the Alt or F10 key (for users with the hidden Firefox menu bar), and go to Tools > Browser Tools > Web Developer Tools.
    • For Google Chrome, select Options and go to Tools > Developer tools or More tools > Developer tools.
  3. Save a screen capture of the fully expanded error message returned by the BIG-IQ system (if available).

Blueprint hashTo get the blueprint hash, do the following:
  1. Log in to the command line.
  2. Go to ~/files.
  3. To generate the secret, run the following script:

    ./signature_maker.sh

    Output appears similar to the following example:

    Secret `signature_list_25_10_2018_12_55_58` created

  4. To extract the blueprint hash from the secret, use the following command syntax:

    vnfm secret get <secret>

    For example, to extract to blueprint hash from the secret signature_list_25_10_2018_12_55_58, you type the following command:

    vnfm secret get signature_list_25_10_2018_12_55_58

  1. Log in to the VNF Manager Web UI.
  2. Go to Deployments.
  3. Locate the main Gi solution deployment, and then select one of the following blueprints, depending on the virtual infrastructure manager (VIM) platform you deployed.
    • OpenStack-F5-VNF-Service-Layer-xxxx
    • vSphere-F5-VNF-Service-Layer-xxxx
  4. Locate the Deployment Inputs section, and then retrieve the inputs information.

VELOS and rSeries systems

InformationDetails
Configuration, diagnostic, and logsFor information about creating a QKView file containing this information for the VELOS or rSeries systems, refer to one of the following articles:
  • K02521182: Generating diagnostic data for the VELOS system using the qkview utility.
  • K04756153: Generating diagnostic data for rSeries systems using the qkview utility.
LogsThe system may truncate large log files included in a QKView file. To ensure you provide the latest version of all log files in the system, you can create a TAR archive that contains all files in the /var/log directory.

To do so, do the following:
Tenant
  1. Log in to the command line of the BIG-IP tenant.
  2. Enter the following command:

    tar -czpf /var/tmp/tenant_logs.tar.gz /var/log/*

    The system names the archive tenant_logs.tar.gz and locates it in the /var/tmp directory.

F5OS System Controller
  1. Log in to the command line of the F5OS system controller
  2. Enter the following command:

    tar -czpf /var/tmp/f5os_logs.tar.gz /var/F5/system/log /var/log/*

    The system names the archive f5os_logs.tar.gz and locates it in the /var/tmp directory.

Packet traceWhen the issue involves the network, do one of the following:
  • Perform a packet trace while the issue is occurring and provide the packet trace when you open the case. For more information, refer to one of the following articles:
    • For VELOS systems: K12313135: Overview of the tcpdump utility on the VELOS system
    • For rSeries systems: K80685750: Overview of the tcpdump utility on rSeries systems
    • For BIG-IP tenant systems: K411: Overview of packet tracing with the tcpdump utility.
  • When the issue involves encrypted traffic, do the following:
    • Decrypt the packet trace using the ssldump utility. For more information, refer to K10209: Overview of packet tracing with the ssldump utility.
