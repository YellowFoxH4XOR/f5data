Known Issue

This is the result of a known issue. When at least one attack signature is completely disabled in the ASM security policy, some of the attack signatures contained in the current signature sets will not be enforced by the BIG-IP ASM. For example, if one attack signature is disabled in the security policy, and that signature is not explicitly re-enabled for a parameter or within an XML profile, a random list of attack signatures contained in the signature set(s) will not be enforced by the BIG-IP ASM system even though those signatures are enabled in the policy.

Note: When this issue occurs, the number of attack signatures that the system does not enforce will be less than 50; however, you cannot determine which signatures the system is not enforcing. In addition, the signatures the system does not enforce may change each time the signature sets are updated.

F5 Product Development tracked this issue as CR118376 and it was fixed in BIG-IP ASM 9.4.8 and 10.0.1. For information about upgrading, refer to the BIG-IP ASM release notes.
