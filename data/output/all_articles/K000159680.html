Description

Java applications experience intermittent SSL handshake failures when connecting through BIG-IP APM with the following symptoms:

  • Error Message: javax.net.ssl.SSLException: Tag mismatch or javax.crypto.AEADBadTagException: Tag mismatch
  • SSL Alert: Fatal Handshake Failure (Alert 40) during TLSv1.3 handshakes
  • Behavior: Connections fail intermittently during PublishSubscribe operations
  • Root Cause Indicator: Packet captures show the server sending a "DOWNGRD" sentinel (444f574e47524401) in the Server Hello Random field

This issue occurs when BIG-IP cipher groups are configured with ordering strength, causing the system to offer FFDHE4096 as the Diffie-Hellman group, which triggers a known compatibility issue with Java/OpenJDK clients.

Environment

  • Product: BIG-IP APM
  • Version: 17.1.2 (affects v17.x)
  • Platform: F5-BIG-VE-BT-200MV18, BIG-IP
  • Configuration:
    • Cipher group with ordering strength setting
    • TLSv1.3 handshakes
    • Cipher suite: TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384 (0xc030)
  • Client: Java/OpenJDK applications

Cause

When ordering strength is configured on a BIG-IP cipher group:

  • BIG-IP evaluates all allowed ciphers and Diffie-Hellman groups
  • It ranks them by cryptographic strength (key size, algorithm strength, etc.)
  • It offers the strongest option (FFDHE4096) to the client
  • Java clients accept FFDHE4096 but fail during the key exchange due to a known compatibility issue
  • The client sends a Fatal Handshake Failure alert and terminates the connection
  • This manifests as the javax.crypto.AEADBadTagException: Tag mismatch error

The backend server responds with a "DOWNGRD" sentinel in the Server Hello, indicating a potential downgrade attack. Java clients perform a security check, detect the sentinel, and terminate the connection as a security precaution.

Recommended Actions

Option 1: Modify Existing Cipher Group (Recommended)

  1. List your current cipher group for full details:
    tmsh list /ltm cipher group <cipher-group-name> all-properties
  2. Modify the cipher group to use ordering default:
    tmsh modify ltm cipher group <cipher-group-name> ordering default
  3. Save the configuration:
    tmsh save sys config

Option 2: Create a New Cipher Group for Testing

  1. List your current cipher group:
    tmsh list /ltm cipher group <cipher-group-name> all-properties
  2. Create a new cipher group with ordering default:
    tmsh create ltm cipher group /Common/ { allow replace-all-with { /Common/f5-secure } exclude replace-all-with { /Common/RSA /Common/SSLv3 /Common/TLSv1 /Common/TLSv1_1 } ordering default description "Custom Hardened Suite" }
  3. List the new cipher group to verify:
    tmsh list /ltm cipher group <new-name> all-properties
  4. Save the configuration:
    tmsh save sys config
  5. Apply the new cipher group to your SSL profiles for testing

Why This Works:

With ordering default, BIG-IP uses F5's recommended ordering that prioritizes compatibility alongside security. BIG-IP will typically offer X25519 (elliptic curve) or FFDHE2048 instead of FFDHE4096. These groups are fully compatible with Java/OpenJDK clients, allowing the handshake to complete successfully.

Additional Information

Packet Capture Analysis:

When troubleshooting this issue, filter packet captures using:

tls.alert_message.level == 2

Look for TLSv1.3 Record Layer Alert messages with:

  • Level: Fatal (2)
  • Description: Handshake Failure (40)

The Server Hello Random field will contain the "DOWNGRD" sentinel (444f574e47524401) when the issue is present.

Security Considerations:

The ordering default setting maintains strong security while ensuring compatibility. F5's default ordering is designed to balance cryptographic strength with real-world client compatibility, making it suitable for production environments with diverse client types.
