Issue

The unit ID setting specifies a number for a unit in a redundant pair. Valid values are 1 and 2. The default value is 1.

BIG-IP 9.4.2 through 9.4.8

In BIG-IP 9.4.2 through 9.4.8, when a BIG-IP system is configured as the member of a redundant pair and is designated with a unit ID, one of the following sections is immediately added to the /config/bigip_base.conf file:

failover {
   unit 1
}

failover {
   unit 2
}

In addition, the output of the bigpipe failover list or bigpipe base list commands includes the unit ID setting.

BIG-IP 10.0.0 and later

Beginning in BIG-IP 10.0.0, if the Configuration utility is used to designate a BIG-IP system with a unit ID of 1, the unit ID designation is no longer added to the /config/bigip_base.conf file. This is expected behavior. In addition, the output of the bigpipe failover list or bigpipe base list commands no longer includes the unit ID setting.

Note: You can still use the bigpipe failover list all and bigpipe base list all commands to display the unit ID setting from the command line.

If the Configuration utility is used to designate a BIG-IP system with a unit ID of 2, the behavior is the same as in versions 9.4.2 through 9.4.8, and the unit ID designation is saved to the /config/bigip_base.conf file.

The system behaves differently when the unit ID is set to 1 because 1 is the default value; therefore, writing the setting to the /config/bigip_base.conf file is superfluous. These changes are cosmetic. The unit ID setting works and is retained as intended in BIG-IP 10.0.0 and later.

Note: If the unit ID is configured from the command line (using either the bigpipe or tmsh shell), the setting will be included in the /config/bigip_base.conf file. In addition, carrying out specific operations may also result in the inclusion of the unit ID setting in the /config/bigip_base.conf file. These behaviors are also expected.
