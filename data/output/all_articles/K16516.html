Known Issue

Restoring a UCS file with no custom partition may fail on a BIG-IP system that has GTM objects defined in a custom partition.

This issue occurs when all of the following conditions are met:

  • When a user configuration set (UCS) file is saved with the default partition only.
  • You restore a UCS file on a BIG-IP system that has any GTM objects configured in custom partition.

The BIG-IP system automatically creates a default partition named Common when you first install the BIG-IP system. This partition contains certain objects that the system automatically creates during installation, such as the admin user account, the default profiles, and the preconfigured health and performance monitors. An administrator can also create custom partitions, providing granular control to manage BIG-IP system objects in other partitions. This situation occurs when the BIG-IP system attempts to delete the custom partition without first deleting the GTM objects during a UCS restore operation. To proceed with UCS restore operation, you must delete all GTM objects from a custom partition before you delete the partition.   

Impact

The BIG-IP system fails to restore a UCS file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system logs error messages to the /var/log/ltm file that appear similar to the following example:

    ....
    err load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all base" - failed. -- Loading
    system configuration...   /defaults/asm_base.conf   /defaults/config_base.conf   /defaults/low_profile_base.conf   
    /defaults/policy_base.conf   /defaults/wam_base.conf Loading configuration...   /config/bigip_base.conf   /config/bigip_user.conf
    0107082a:3: All objects must be removed from a partition (partition1) before the partition may be removed, type ID (2682)
    Unexpected Error: Loading configuration process failed.
    err mcpd[6894]: 01070422:3: Base configuration load failed.
    ....
  • You may observe error messages similar in the BIG-IP command line that appear similar to the following example:

    ....
    Configuration loading error: base-config-load-failed
    For additional details, please see messages in /var/log/ltm
    ....
    ERROR: UCS installation failed.
    Operation aborted.
    /var/tmp/configsync.spec: Error installing package
    Config install aborted.
    Unexpected Error: UCS loading process failed.
    ....

Workaround

To work around this issue, you can delete all the GTM objects in a custom partition prior to loading a UCS file. To do so, perform the following procedure before you restore a UCS file:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system command line.
  2. Delete all GTM objects in a custom partition using the following command syntax:

    rm -f /config/partitions/<partition_name>/bigip_gtm.conf

    For example:

    rm -f /config/partitions/partition1/bigip_gtm.conf
  3. Load the GTM configuration using the following tmsh command:

    tmsh load /sys config gtm-only partitions all
  4. Restore your saved UCS file by typing the following tmsh command:

    tmsh load /sys ucs /shared/example.ucs

    For example:

    tmsh load /sys ucs /shared/my.ucs
