Description

Your application is not working and pcap shows the BIG-IP LTM is sending a RST after the client sends a HTTP request. Refer to the example below where client IP is 10.0.0.100 and the Virtual Server VIP is 192.168.0.100.
    2 580.092704 580.092704 3120  10.0.0.100 → 192.168.0.100 52 57414 8500 TCP IN  s1/tmm1 : 57414 → 8500 [SYN] Seq=0 Win=65535 Len=0 MSS=1360 WS=256 SACK_PERM=1
    3 580.092799 0.000095 3120 192.168.0.100 → 10.0.0.100  52 8500 57414 TCP OUT s1/tmm1 : 8500 → 57414 [SYN, ACK] Seq=0 Ack=1 Win=13600 Len=0 MSS=1460 WS=1 SACK_PERM=1
    4 580.095978 0.003179 3120  10.0.0.100 → 192.168.0.100 40 57414 8500 TCP IN  s1/tmm1 : 57414 → 8500 [ACK] Seq=1 Ack=1 Win=262144 Len=0
    5 580.096370 0.000392 3120  10.0.0.100 → 192.168.0.100 907 57414 8500 HTTP/XML IN  s1/tmm1 : GET /1.1
    6 580.096383 0.000013 3120 192.168.0.100 → 10.0.0.100  40 8500 57414 TCP OUT s1/tmm1 : 8500 → 57414 [ACK] Seq=1 Ack=868 Win=14467 Len=0
    7 592.095723 11.999340 3120 192.168.0.100 → 10.0.0.100  40 8500 57414 TCP OUT s1/tmm1 : 8500 → 57414 [RST, ACK] Seq=1 Ack=868 Win=0 Len=0        <==!!!

Further check shows that the Virtual Server is not initiating server side connection to the pool member (node) but instead to the same Virtual Server VIP. A pcap or a tmsh show sys connection will show this.

Below is a tmsh show sys connection output which shows that the pool member (node) IP is the same as the Virtual Server VIP.
10.0.0.100:57825  192.168.0.100:80  172.16.100.100:57825  192.168.0.100:80  tcp  1  (slot/tmm: 1/0)  none  none

Environment

  • BIG-IP LTM
  • Server side connection is being established to the Virtual Server VIP instead to the pool member (node)

Cause

Address translation is disabled on the Virtual Server.

Recommended Actions

You will need to enable address translation on the Virtual Server settings.

  1. Login to the BIG-IP GUI
  2. Navigate to Local Traffic  > Virtual Servers > Virtual Server List
  3. Click on the Virtual Server name
  4. Under Configuration:, change Basic to Advanced
  5. Under Address Translation, select the Enable option
  6. Click Update

Additional Information

This is an example of a Virtual Server which has the address translation disabled.

ltm virtual /Common/Virtual_Server_Example {
    destination /Common/192.168.0.100:80
    ip-protocol tcp
    mask 255.255.255.255
    pool /Common/Virtual_Server_Example_Pool
    profiles {
        /Common/tcp { }
    }
    source 0.0.0.0/0
    source-address-translation {
        pool /Common/SNAT_POOL
        type snat
    }
    translate-address disabled   → Note the setting is disabled
    translate-port disabled
}
