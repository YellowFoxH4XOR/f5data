K000150724: PlatformStatsBridge high memory consumption

Type
Support Solution
Published
2025-04-04
Updated
2026-04-01
Applies to
  • F5OS
  • F5OS-C: 1.6.4, 1.6.X, 1.6.2, 1.6.1, 1.6.0
  • F5OS-A: 1.5.X, 1.5.4, 1.5.3, 1.5.2, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000150724

Description

  • High memory consumption observed on the VELOS and rSeries platforms, specifically with the PlatformStatsBridge process.
  • Memory usage reaches approximately 80% on controllers or rSeries appliances, with PlatformStatsBridge being the top consumer.
  • Memory statistics:

    ps_mem.py
    476.4 MiB + 4.8 MiB = 481.2 MiB docker-containerd-shim-current (122)
    485.8 MiB + 81.0 KiB = 485.9 MiB vcc-partition-agent
    527.7 MiB + 166.5 KiB = 527.8 MiB platform-diag-agent
    1.0 GiB + 852.0 KiB = 1.0 GiB switchd
    1.2 GiB + 6.2 MiB = 1.2 GiB etcd (2)
    1.2 GiB + 1.6 MiB = 1.2 GiB system_service (2)
    1.4 GiB + 89.0 KiB = 1.4 GiB vcc-ha
    2.7 GiB + 17.5 MiB = 2.8 GiB openshift (3)
    5.6 GiB + 201.0 KiB = 5.6 GiB PlatformStatsBridge (2)

Environment

  • Velos
  • F5OS-C v1.6.x
  • rSeries
  • Controller
  • Memory

Cause

The issue is caused by a known bug identified as Bug ID1587837 in the PlatformStatsBridge process, which leads to excessive memory consumption due to repeated SNMP stats requests.

Recommended Actions

The bug has been resolved since F5OS-C 1.6.3 and above and F5OS-A 1.8.0 and 1.5.3.

Temporary Workaround:

Restarting the PlatformStatsBridge container can temporarily reduce memory usage without impacting traffic or production services:

  1. Connect to Controller CLI
  2. Run

    docker restart system_platform-stats-bridge
