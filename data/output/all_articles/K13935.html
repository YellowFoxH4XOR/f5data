Known Issue

iRules using the TCP::release command in the LB_SELECTED iRule event may cause TMM to crash.

This issue occurs when the following conditions are met:

  • The virtual server referencing the iRule processes connections.

Impact

TMM may crash and fail to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The system sends a SIGFPE signal to TMM, resulting in an assertion panic string. The panic string is logged to the /var/log/tmm file and may appear similar to the following example:

    panic: ../modules/hudproxy/hudproxy.c:1008: Assertion "connect_data is NULL" failed
  • TMM may crash and fail to process traffic

Resolution

Status

Workaround

To work around this issue, you can modify the iRule and use the TCP::release command in an iRule event other than LB_SELECTED. For example, you may be able to modify the iRule and use the TCP::release command in the CLIENT_DATA event. For information about creating iRules, refer to the DevCentral site. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

Impact of workaround: Slight modification of the iRule code.
