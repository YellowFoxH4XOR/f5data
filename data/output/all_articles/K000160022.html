K000160022: Cookie impersonation detected from remote IP when "auth-pam-validate-ip" is set to "off"

Description

After upgrading to BIG-IP version 17.5.0, the customer continued to experience unexpected session logouts due to "cookie impersonation detected from client IP" errors, even though the "auth-pam-validate-ip" option was set to "off" as recommended. This issue was believed to be resolved in ID1350717, but the problem persisted.


 

Environment

- running version 17.5.0 or later

- sys httpd configuration with "auth-pam-validate-ip off"

- Users accessing the BIG-IP GUI/API via proxy (frequent client IP changes)


 

Cause

The issue persisted because existing session cookies, created before "auth-pam-validate-ip" was set to "off," retained the requirement for IP validation. As a result, sessions were invalidated when the client IP changed, despite the configuration change. This behavior is consistent with the fix described in Bug ID 1350717, which embeds the IP validation requirement in the cookie file at creation time.


 

Answer/Recommended Actions

- Identify and delete any session cookie files (in the /var/run/pamcache directory) for users that fail due to IP validation.

- After deletion, new session cookies will be created with the correct setting (no IP validation), resolving the logout issue for users with changing IP addresses.

- No further configuration changes are required if "auth-pam-validate-ip" is already set to "off."
