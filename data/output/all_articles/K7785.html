Known Issue

This is the result of a known issue. The system_check script may trigger a slow memory leak to occur within the snmpd process. The memory leak is slow and accumulates over a long period of time. Using SNMP, the system_check script checks fan speed, CPU temperature, and power supply status every two minutes. If the values gathered exceed healthy thresholds, the scripts logs these events through syslog. These log messages are used to generate the corresponding SNMP traps of these events.

F5 Networks Product Development is tracking this issue as CR76335.

Workaround

The following options are available to prevent this issue from consuming system resources:

  • Disable the system_check script. f
    Note: For more information, refer to K4202: Disabling the system_check script.
  • Restart the snmpd process weekly or monthly using a cron job.
    F5 Networks recommends this method, which allows the system_check script to provide information about changes that may issue alerts.

To restart the snmpd process, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Using a text editor, edit the /etc/crontab file.
  3. Add a line to the end of the file, depending on whether you want to restart the snmpd process weekly or monthly.

    For example, to restart the snmpd once a week on Friday at midnight, add the following line:

    0 0 * * 5 root /sbin/bigstart restart snmpd 2>&1

    For example, to restart the snmpd process once a month on the first of each month, add the following line:

    0 0 1 * * root /sbin/bigstart restart snmpd 2>&1

  4. Save the file and exit the text editor.
