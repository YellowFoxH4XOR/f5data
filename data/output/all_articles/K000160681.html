K000160681: Slow Download Speeds Through BIG-IP LTM Explicit Forward Proxy Virtual Server

Type
Support Solution
Published
2026-04-08
Updated
2026-04-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160681

Description

When using a BIG-IP LTM explicit forward proxy virtual server, download speeds may be significantly slower than those of direct connections or other datacenters with similar configurations. Downloads through the proxy (Affected BigIP) may be much slower, while direct downloads (Bypassing the BigIP) or downloads through other proxies achieve the expected speed.

The issue is persistent and reproducible only when traffic traverses the affected proxy.

 

Environment

  • BIG-IP LTM Virtual Edition (VE) on VMware vCenter
  • Version: 17.5.1
  • Explicit forward proxy virtual server configuration:
    • Client-side TCP profile: f5-tcp-progressive
    • Server-side TCP profile: f5-tcp-wan (initially)
    • HTTP explicit proxy profile attached
  • 4 vCPUs, 8 GB RAM, proper CPU/memory reservation
  • Issue isolated to one datacenter; other datacenters with a similar setup perform as expected

 

Cause

Using the f5-tcp-wan profile as the server-side TCP profile on the explicit forward proxy virtual server led to suboptimal TCP behavior in this use case, resulting in slow data transfer rates.

Switching to the f5-tcp-progressive profile on both client and server sides resolved the performance issue.

 

Answer/Recommended Actions

  1. On the affected explicit forward proxy virtual server, change the server-side TCP profile from f5-tcp-wan to f5-tcp-progressive.
  2. Save the configuration.
  3. Verify download speeds after the change to confirm resolution.
  4. For similar proxy deployments, ensure that both client and server sides use the f5-tcp-progressive profile unless a specific use case requires otherwise.

 

Additional Information

After reactivating the throughput license, no rate-shaper messages appeared, confirming the license was not the cause.

Packet captures showed the BIG-IP forwarded and acknowledged packets with negligible delay; the bottleneck was due to TCP profile selection.

Direct downloads bypassing the proxy were fast, confirming that the backend server and general network were not the limiting factors.
