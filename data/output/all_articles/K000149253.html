Description

Including unknown attributes in API calls can cause failures, complicating API usage and centralized management, especially as those attributes might change with version upgrades and enhancements being added. This strict validation disrupts operations, making it difficult for users to handle attribute mismatches effectively.

Environment

  • Adv.WAF
  • REST APIs

Cause

Starting with v13 and onward, the recommended practice has shifted to ignoring unrecognized attributes. This means the PATCH command will still be effective for valid, recognized attributes, while unknown attributes are disregarded without causing the operation to fail.

Recommended Actions

  1. Upgrade to v13 or Later: Ensure your system is using v13 or a newer version to take advantage of the updated behavior.
  2. Validate Configuration Echo: After making a PATCH request, review the echoed configuration to confirm the changes.
  3. Monitor Logs for Unrecognized Attributes: Use local log file [asm_config_server.log] to track any unrecognized attributes included in requests. This can help identify common issues or mistakes in API usage.
