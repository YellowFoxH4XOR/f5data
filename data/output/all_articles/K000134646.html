Description

BIG-IPs can connect two separated networks over a WAN using an IPsec tunnel. If the traffic is not always up, it could happen that at a certain point some of the clients and servers are not able to send traffic when they suddenly need to, but a problem with the the IPsec tunnel might have happened minutes or even hours before. To make troubleshooting easier, a precise timeline is helpful surrounding events where tunnel service is interrupted.

The procedure below will create a regular traffic flow that will traverse the IPsec tunnel. When this traffic is interrupted, a log entry in LTM logs will be created and the precise time when the traffic through the tunnel started to fail can be deduced. 

Environment

  • IPsec tunnel between two BIG-IP devices (similar procedure can be applied if only one end is a BIG-IP)
  • Traffic through the tunnel is not constant
  • The tunnel itself is not marked down, but the traffic can not pass through the tunnel most likely due to a WAN issue 

Cause

Not necessarily it is a fault in the BIG-IP or clients, most likely it is a fault in the WAN but in order to provide better troubleshooting we can configure a monitor so we can analyze the logs or debugs knowing the precise time the problem started.

Recommended Actions

  1. On BIG-IP B configure a Virtual Server with a destination IP address belonging to the destination B range in the traffic selector associated to the tunnel
  2. On BIG-IP A configure a pool member pointing to the Virtual Server just created
  3. Be sure the pool is configured with a default ICMP monitor 



Now the LTM logs will have an indication of the health of the traffic through the tunnel based on the health monitor of the Pool member on BIG-IP A.
