K99140252: Remote desktop resource configurations use native RDP as the client type by default in BIG-IP APM 15.1.0

Type
Knowledge
Published
2020-04-03
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.0
Source
https://my.f5.com/manage/s/article/K99140252

Issue

Old Behavior

In BIG-IP APM 13.0.0 through 15.1.0, Native RDP, ActiveX, and Java-based remote desktop resources are supported and appear as options in the Client Type setting of the remote desktop configuration.

Due to the waning support for ActiveX and browser plugins, F5 recommends that you use the Native RDP type for these BIG-IP versions when configuring remote desktop resources. Beginning in BIG-IP APM 14.1.0, the ActiveX and Java-based options are deprecated and not recommended for use.

New Behavior

Beginning in BIG-IP APM 15.1.0, Native RDP is the only configurable client type for a remote desktop resource. The deprecated ActiveX and Java options are removed. The Client Type setting is also removed since it it no longer needed. When you configure an RDP type remote desktop resource, there is no Client Type setting, and the remote desktop uses Native RDP by default.

F5 Product Development tracked this change as ID 721274.

Impact

ActiveX and Java-based remote desktop resources are no longer supported. By default, the system uses Native RDP, and the Client Type setting no longer appears in the RDP remote desktop configuration.

Recommended Actions

When you upgrade from older BIG-IP APM versions, which have support for ActiveX or Java RDP resources, the system takes the following actions for ActiveX and Java-based RDP resources in the configuration:

  • Converts the ActiveX and Java-based RDP resources to native RDP resources.
  • Removes the converted resources from the Resource Assign and Advanced Resource Assign policy items. These are the only policy items that currently have RDP resources.

F5 removed the converted native RDP resources from the policy items because native RDP requires additional configuration, such as a Server SSL profile, when it is used in a policy. After the upgrade, you must manually add the converted RDP resources back to the Resource Assign and Advanced Resource Assign policy items, along with required profiles, in order to make them available to BIG-IP APM end users.
