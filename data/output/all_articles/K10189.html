K10189: Users may be logged out of FirePass when running Internet Explorer 8 with Compatibility View enabled

Topic

When enabled, the Compatibility View feature of Internet Explorer 8 (IE8) displays websites as they would be viewed in Internet Explorer 7. However, when Compatibility View is enabled, IE8 may send inconsistent User-Agent strings. Since FirePass tracks User-Agent strings as an anti-spoofing mechanism, this IE8 behavior may result in a user's session being terminated by the FirePass controller.

Note: User-Agent is an HTTP header field sent by the user's browser, which contains a text string that identifies the browser.
 
For example, when accessing a web page in Compatibility View, the User-Agent string reported by IE8 typically begins with MSIE 7.0. If the user right-clicks a link and selects Save Target As..., the User-Agent string reported by IE8 typically begins with MSIE 8.0 even if Compatibility View is enabled.
 
When a user logs on to the webtop, FirePass records the User-Agent string reported by the user's browser. If the reported User-Agent string changes during the user's session, FirePass detects this change as an attempt by a potential attacker to spoof the user's session. As a result, FirePass terminates the session and logs a message similar to the following example on the Reports: System Logs page:
 
[jsmith@Default] Possible intrusion attempt detected against account jsmith from source IP address 192.168.0.94 for URI=[/vdesk/vpn/](USER-AGENT changed.[Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 5.1; Trident/4.0)->Mozilla/4.0 (compatible; MSIE 8.0; Windows NT 5.1; Trident/4.0)]. )
 
To prevent this issue from occurring, users can disable Compatibility View.
