K000160417: IPv6 Traffic Disruption After BIG-IP Failover with BGP Routing and Connection Mirroring

2026-03-22

2026-03-22
Applies to

Description

After a failover in a BIG-IP LTM HA cluster using BGP for routing, IPv6 UDP response traffic is dropped by the new active device for all clients whose traffic are mirrored. The connection table shows zero "Packets Out" for affected flows, the "Lasthop" field displays all ff's (ff:ff:ff:ff:ff:ff) instead of the correct MAC address, and the NDP table contains incomplete entries for link-local IPv6 addresses. Clearing the connection table or disabling mirroring temporarily resolves the issue, but it recurs on subsequent failovers.

 

Environment

  • IPv6 environment
  • Mirroring is enabled
  • AutoLastHop is disabled
  • HA cluster with two BIG-IP devices in separate L2 domains and IPv6 subnets towards upstream devices
  • Using BGP for failover routing

Cause

When the upstream router uses a link-local IPv6 address as the BGP next-hop, the mirrored connection context includes this address and the VLAN object ID. Upon failover, the new active device attempts to resolve the link-local address in its own VLAN, resulting in incomplete NDP entries. Packets are dropped when the MAC address for that next-hop IPv6 link-local could not be resolved in the new active device's upstream network. The issue is triggered by the combination of BGP routing with link-local next-hop addresses and connection mirroring.

 

Answer/Recommended Actions

 

On BIG-IP, use a BGP route-map to override the IPv6 next-hop in received BGP updates with the local global IPv6 address of the router interface:

 

Example configuration on BIG-IP ZebOS:

    address-family ipv6
    neighbor <peer_global_ipv6> route-map replace-ll in
    !
    route-map replace-ll permit 10
    set ipv6 next-hop local <peer_global_ipv6>
    set ipv6 next-hop <peer_global_ipv6>

 

This has to be done on members of the HA cluster.
