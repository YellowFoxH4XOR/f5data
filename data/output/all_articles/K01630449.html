Description

After an upgrade to v15, you start receiving an overload of emails similar to:

Subject: Cron <root@BIG-IP> nice -n 19 ionice -c 3 /usr/bin/rest_logintegrity
Body: '14353restnoded_log_pattern': No such file or directory'

Environment

  • Logintegrity script
  • System emails

Cause

Bug ID 959629: Logintegrity script for restjavad/restnoded fails

Recommended Actions

To workaround this issue, modify the syntax errors caused by Bug ID 959629 on the rest_logintegrity cronjob script:

  1. Remount /usr as read-write filesystem with command:

    mount -o remount,rw /usr
     
  2. Make a copy of original script with command:

    cp /usr/bin/rest_logintegrity /root/rest_logintegrity_original
     
  3. Change permissions to allow modifications:

    chmod +w /usr/bin/rest_logintegrity
     
  4. Edit file /usr/bin/rest_logintegrity to make the following changes:

    On the following line remove the extra "$" sign:

    wc_restnoded=$(find $$restnoded_log_pattern -cnewer $filename | wc -l)

    It should look like:

    wc_restnoded=$(find $restnoded_log_pattern -cnewer $filename | wc -l)

    On the following lines remove the extra "." :

    restjavad_log_pattern=/var/log/restjavad*.[1-9]*.log
    restnoded_log_pattern=/var/log/restnoded/restnoded.[1-9]*.log

    It should look like:

    restjavad_log_pattern=/var/log/restjavad*[1-9]*.log
    restnoded_log_pattern=/var/log/restnoded/restnoded[1-9]*.log

  5. Save the changes
     
  6. Revert permissions of the file:

    chmod -w /usr/bin/rest_logintegrity
     
  7. Remount /usr as read-only filesystem with command:

    mount -o remount,ro /usr

Note: Reboot may be required if you still receive emails or errors documented in K60914243 after following the steps above.

Also note that if /var/log/restnoded/restnoded.log has not been rotated, it may be the only restnoded file in the directory, and you may observe the following error:
find: '/var/log/restnoded/restnoded[1-9]*.log': No such file or directory

To address this, create a dummy file with the following command and re-run the script again:

touch /var/log/restnoded/restnoded1.log

Additional Information
IMPORTANT: Running this workaround on a BIG-IP running in FIPS or Common Criteria mode will cause the BIG-IP to fail its integrity check on boot.  This will prevent the BIG-IP from booting until the system is reverted.  See: K25205233: BIG-IP System halted while booting. Halt at boot after FIPS Integrity Check Result FAIL
