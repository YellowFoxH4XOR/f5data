Topic

You should consider using this procedure under the following conditions:

  • You use a platform with an Always-On Management (AOM) subsystem.
  • You have been advised by F5 Technical Support to use another AOM firmware version to overcome an issue.

    Important: You should perform this procedure only under the specific direction of F5 Technical Support.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have BIG-IP host access through the management IP address using secure shell (SSH).
  • You have command line access to the BIG-IP system.
  • You have obtained the copy of the desired AOM firmware version .im file through F5 Technical Support.

Description

The AOM subsystem has a separate operating system that may be upgraded during a BIG-IP version upgrade, or a direct upgrade only for the AOM subsystem. On rare occasions, a downgrade is required as a recommendation by F5 Technical Support to overcome an issue.

Procedure

Downgrading of the AOM subsystem software

Impact of procedure: The process of installing AOM subsystem firmware causes service interruption on the BIG-IP system. F5 recommends performing this procedure during a maintenance window.

  1. Connect to the BIG-IP command line using SSH through its management IP address.
  2. To verify the current AOM version, type the following command:

    ssh aom flashver

    For example, the command output may appear similar to the following:

    AOM Flash Component Version Information

    Boot loader nub: V1.5.1                Tue Aug 26 11:04:50 PDT 2008
    Boot loader A:   V1.5.1                Tue Aug 26 11:04:57 PDT 2008
    Boot loader B:   V1.5.1                Tue Aug 26 11:05:05 PDT 2008
    Kernel1 image:   V10.1.11.359.0        Thu Oct 20 17:59:38 PDT 2011
    Kernel2 image:   V10.1.9.353.0         Tue Jul 26 14:53:43 PDT 2011

  3. To verify the existing version of the AOM firmware package file installed on the BIG-IP host, type the following command:

    rpm -qva | grep aom-firmware

    For example, a system with AOM firmware package version 10.1.8 may display output that appears similar to the following example:

    aom-firmware-1.4-10.1.8.348.0

  4. If the version you want to downgrade is older than this version, you must remove the files and the existing package related files using the following command syntax:

    rpm --nodeps -ev <Existing-AOM-firmware-package-name>

    For example, to remove an existing AOM firmware package named aom-firmware-1.4-10.1.8.348.0, you would type the following command:

    rpm --nodeps -ev aom-firmware-1.4-10.1.8.348.0

  5. Transfer the target AOM firmware .im file from your local workstation to the BIG-IP system into the /shared/tmp folder. You can perform the file transfer using tools, such as WINSCP or secure FTP. For more information about file transfers, refer to K175: Transferring files to or from an F5 system.
  6. After successfully transferring the .im file, change directories to the /shared/tmp directory by typing the following command:

    cd /shared/tmp/

  7. Install the target AOM firmware .im package file using the following command syntax:

    im <Target-AOM-firmware-im-package-filename>

    For example, to install the AOM firmware package named aom-firmware-1.4-10.1.5.326.0.i686.im, you would type the following command:

    im aom-firmware-1.4-10.1.5.326.0.i686.im

  8. After successfully installing the AOM firmware package, change directories to the /opt/F5/aom directory by typing the following command:

    cd /opt/F5/aom/

  9. Install the target AOM firmware package by typing the following command:

    ./aom_flash -kernel -force f5aom-kernel.bin

    This process automatically transfers and installs the target firmware into the AOM subsystem. Upon completion, it will display that AOM is being reset. Wait approximately 2 to 3 minutes for the AOM subsystem to boot up. Thereafter, you can verify the version of the AOM subsystem installed.
