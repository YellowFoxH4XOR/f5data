K000129996: All LDAP users are able to login to BIG-IP GUI/SSH even with configured "Remote Role Groups"

Type
Support Solution
Published
2022-12-20
Updated
2025-02-07
Status
Final
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000129996

Description

Customer BIG-IP facing issue with remote LDAP/AD authentication, where all LDAP users were able to login despite them configured the Remote Role Groups.

 

Environment

  • BIG-IP
  • Remote LDAP/AD

Cause

Reason why all LDAP user is able to login is because of "BIG-IP GUI > System > Users > Authentication > External Users" were configured with below setup.

  • Role: Administrator
  • Terminal Access: tmsh

Hence, with External Users Role/Terminal Access configured, the BIG-IP will allow any remote LDAP user to login to the BIG-IP.

Recommended Actions

1. Disable "BIG-IP GUI > System > Users > Authentication > External Users" Role and Terminal Access

-- Role: No Access
-- Terminal Access: Disabled

Additional Information

Please take note that:
1. "Local User" configured "role" will take precedence over "Other External Users" configured "role"
2. "Other External Users" configured "role" will take precedence over "Remote Role Groups" configured "role"

For example:
LDAP user id: f5ops (member of Group_F5_Operator)
LDAP group: Group_F5_Operator

Scenario 1:
BIG-IP:
- Add "Remote Role Groups"
Note: GUI > System > Users > Remote Role Groups
# tmsh list auth remote-role
auth remote-role {
    role-info {
        Grooup-F5UI-operators {
            attribute memberOf=CN=Group_F5_Operator,CN=Users,DC=domain,DC=com
            console tmsh
            line-order 1002
            role operator
            user-partition All
        }
...

-- Hence, login to BIG-IP with userid "f5ops", BIG-IP will assigned it with role "Operator"
LTM logs:
Jan 01 00:00:00 bigip.domain info httpd(pam_audit)[1203]: user=f5ops(f5ops) partition=[All] level=Operator tty=(unknown) host=x.x.x.x attempts=1 start="Thu Jan 01 00:00:00 1970" end="Thu Jan 01 00:00:00 1970".

Scenario 2:
BIG-IP
- Add "Other External Users" role "Manager"
Note: GUI > System > Users>  Authentication > Change > External Users
# tmsh list auth remote-user
auth remote-user {
    default-role manager
}

-- Hence, login to BIG-IP with userid "f5ops", BIG-IP will assigned it with role "Manager"
LTM logs:
Jan 01 00:00:00 bigip.domain info httpd(pam_audit)[1203]: user=f5ops(f5ops) partition=[All] level=Manager tty=(unknown) host=x.x.x.x attempts=1 start="Thu Jan 01 00:00:00 1970" end="Thu Jan 01 00:00:00 1970".

Scenario 3:
BIG-IP
- Add "Local user" "f5ops"
Note: (GUI > System > Users>  User List)
# tmsh list auth user f5ops
auth user f5ops {
    description f5ops
    encrypted-password "truncated"
    partition Common
    partition-access {
        all-partitions {
            role auditor
        }
    }
    session-limit -1
    shell none
}

-- Hence, login to BIG-IP with userid "f5ops", BIG-IP will assigned it with role "Auditor"
LTM logs:
Jan 01 00:00:00 bigip.domain info httpd(pam_audit)[1203]: user=f5ops(f5ops) partition=[All] level=Auditor tty=(unknown) host=x.x.x.x attempts=1 start="Thu Jan 01 00:00:00 1970" end="Thu Jan 01 00:00:00 1970".
