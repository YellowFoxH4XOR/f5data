Known Issue

When a pool member receives Session Initiation Protocol (SIP) monitor messages with the same branch parameters from multiple BIG-IPs, pool members flap.

This issue occurs when all of the following conditions are met:

  • You configure SIP monitors in a BIG-IP high availability (HA) pair.
  • An HA failover event occurs.
  • A pool member receives SIP messages that contain the same branch parameters on their Via headers from both BIG-IP systems.

Impact

The pool members erroneously send the response to the wrong BIG-IP system in the HA pair, and they start flapping on both BIG-IP systems.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe that your pool members flap.
  • After a failover event, the pool member sends the response to the incorrect BIG-IP, because it receives duplicate branch parameters on its Via headers from both BIG-IP systems.

    For example, your SIP messages appear similar to the following message:

    Session Initiation Protocol (OPTIONS)
        Request-Line: OPTIONS sip:172.26.2.10:5060 SIP/2.0
        Message Header
            From: sip:anonymous@xxx_F5_LB1.site;tag=6594f623
            Call-ID: 000047605941de24@xxx_F5_LB1.site
            CSeq: 1497488932 OPTIONS
            Via: SIP/2.0/UDP 172.26.2.4:38939;rport;branch=z9hG4bKf5s1pw+eb07dP
            Via: SIP/2.0/UDP SCBHILIF_PLRF_F5_LB1.site:5060;branch=z9hG4bK59689376
            Max-Forwards: 1
            To: sip:172.26.2.10
