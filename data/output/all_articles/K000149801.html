Description

SSL scanner reports missing certificates in the certificate chain.

Environment

  • LTM
  • Virtual server configured with SSL offloading or bridging

Cause

The certificate chain installed on the BIG-IP includes incorrect certificates.

Recommended Actions

  1. Go to bash.
  2. Use openssl to verify the certificate:
openssl s_client -connect <virtual_server_ip>:<port>

If your virtual server has TLS SNI feature enabled, use the following command instead:

openssl s_client -connect <virtual_server_ip>:<port> -servername <server_name>
  1. If the certificate is signed by CA, the verify return code for a correct chain should be 0 (ok). If the virtual server uses a self-signed intermediate or root certificates, seeing error 19: self signed certificate in the chain is expected.
  2. If the verify return code is 21 (unable to verify the first certificate), it may signify that the intermediate certificate is missing or is incorrect. To solve the issue, add the correct intermediate certificate to the chain. Verify with the same openssl command if you can see a different return code.
  3. If the verify return code is 20 (unable to get local issuer certificate), it may signify that the root certificate is missing or incorrect. Add the correct root certificate to the chain and verify the return code again with the same openssl command. 

Additional Information

F5 recommends verifying the certificate using openssl certificate verification after each certificate renewal to avoid potential issues related with the use of incorrect intermediate or root certificates.
