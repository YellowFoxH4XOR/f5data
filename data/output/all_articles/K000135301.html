Description

The synchronization issue between two BIG-IP devices stems from an error where the system couldn't locate a specified route domain.

Sync error on Device_1_name: Load failed from /Common/Device_2_name 01070277:3: The requested route-domain (X) was not found.

The error message indicates that during the attempt to synchronize configuration between devices, one of the devices references a route domain that doesn't exist on the other device. This is critical, as consistent route domain configurations are essential for the proper functioning of a BIG-IP cluster. Inconsistency in route domains can cause synchronization to fail or not work as expected.
 

Environment

  • BIG-IP
  • Sync-Failover and Sync-Only device groups


Cause

This issue arises because route domains are not synchronized or configured during the synchronization process. They are part of an independent configuration that must be identically defined on both BIG-IP systems. The synchronization process does not overwrite or configure this aspect. Therefore, for successful synchronization, both devices must have matching configurations, including the route domains. It’s essential to manually ensure that the route domains are consistent across the BIG-IP systems involved in synchronization.
 

Recommended Actions

It is essential to ensure that all settings associated with route domains are either identical or appropriately configured on both BIG-IP devices. One way to check and compare the route domain configurations is by using the command tmsh list net route-domain on both devices. This will help to ascertain whether the route domains are configured consistently across the systems. Additionally, you can inspect the configuration files /config/bigip_base.conf and /config/bigip.conf on both devices for a more comprehensive examination. Making sure that the route domain configurations align on both devices is crucial for ensuring successful synchronization.

At times, synchronization issues may arise if partitions have different default route domains set on each BIG-IP device.

Example of incorrect config:

BIG-IP 1:
---------------------------
auth partition Common {
    default-route-domain 0
    description \"Descriprion\"
}
auth partition Internal {
    default-route-domain 1 <---------
    description none
}

BIG-IP 2:
---------------------------
auth partition Common {
    default-route-domain 0
    description \"Descriprion\"
}
auth partition Internal {
    default-route-domain 0 <--------
    description none
}
------------------------------

In this case, each device needs to have the same default route domain assigned to the specific partition. Change the default route domain for one of the devices to bring back synchronization to work.
