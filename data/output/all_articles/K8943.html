Known Issue

This is the result of a known issue. The VIPRION system does not load balance certain UDP connections properly when the virtual server is configured as follows:

  • A UDP profile is defined
  • Connection mirroring or a persistence profile is defined

When you use this configuration for the virtual server, one of the following three conditions may result in a connection leak, causing UDP connections to stall:

  • A packet arrives for the flow while the system is waiting for a persistence look up
  • A CLOSED iRule event performs a persistence look up and the look up fails
  • When the virtual server connection receives a packet containing a bad checksum

F5 Product Development tracked this issue as CR98591 and it was fixed in BIG-IP 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue has been fixed in BIGIP-9.6.1-839.0-HF3, which has been issued for BIG-IP 9.6.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.


For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You can work around this issue by configuring the virtual server to use the FastL4 profile.
