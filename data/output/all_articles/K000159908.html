K000159908: F5 recommends removing orphaned configuration objects but they are grayed out

Type
Support Solution
Published
2026-02-05
Updated
2026-02-05
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000159908

Description

When F5 iHealth recommends removing orphaned configuration objects such as unused monitors and SSL certificates, these objects may appear grayed out in the BIG-IP Configuration utility (GUI) and cannot be deleted. This situation occurs when attempting to clean up configuration items identified by iHealth diagnostics under "F5 recommends removing orphaned configuration objects," including:

  • Unused monitors not attached to any pool or node
  • SSL certificates not currently in use by any virtual server
  • SSL certificates attached to profiles that are not used by any virtual server

The GUI prevents deletion of these objects even though they appear to be orphaned, and standard deletion attempts fail.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1 (and other versions)
  • Platform: F5-BIG-LTM-R4600, C131 (and other platforms)
  • Configuration objects involved:
    • Unused monitors
    • SSL certificates not assigned to virtual servers
    • SSL certificates attached to unused profiles
    • Profiles not used by any virtual server
  • iHealth diagnostic report recommending removal of orphaned objects

Cause

Objects appear grayed out in the GUI because they are still referenced by other configuration objects, even if not actively used by virtual servers. Common causes include:

  • Certificates still associated with HTTPS monitors (even if not visible in GUI)
  • Certificates attached to SSL profiles that are not assigned to virtual servers
  • Profiles referenced by iRules or other indirect dependencies
  • Monitor associations not visible in the GUI but present in the configuration

Answer/Recommended Actions

Important: Create a UCS backup before making any configuration changes.

Step 1: Create a Configuration Backup

tmsh save sys ucs backup_before_cleanup

Step 2: Identify Dependencies Using tmsh

  1. Log in to tmsh:

    tmsh

  2. Check for SSL profile references to certificates:

    list ltm profile client-ssl all-properties | grep -i cert

    list ltm profile server-ssl all-properties | grep -i cert

  3. Check for HTTPS monitor associations with certificates:

    list ltm monitor https all-properties | grep -E "cert|key"

  4. Check for pool and node monitor associations:

    list ltm pool all-properties | grep -A 20 "monitor"

    list ltm node all-properties | grep -A 10 "monitor"

Step 3: Remove Certificate Associations from HTTPS Monitors

If certificates are associated with HTTPS monitors, remove them using tmsh:

  1. Clear the certificate configuration:

    modify ltm monitor https <monitor_name> cert none

  2. Clear the key configuration:

    modify ltm monitor https <monitor_name> key none

  3. Save the configuration:

    save sys config

Step 4: Delete Unused SSL Profiles

Before deleting certificates, remove unused SSL profiles that reference them:

delete ltm profile client-ssl <profile_name>

delete ltm profile server-ssl <profile_name>

save sys config

Step 5: Delete Orphaned Monitors

Once all dependencies are cleared, delete the orphaned monitors:

delete ltm monitor <monitor_type> <monitor_name>

save sys config

Step 6: Delete Orphaned Certificates and Keys

After removing all references, delete the certificates and keys:

delete sys crypto cert <certificate_name>

delete sys crypto key <key_name>

save sys config

Step 7: Verify Deletion

Confirm the objects have been removed:

list sys crypto cert

list sys crypto key

list ltm monitor

Additional Information

  • Objects grayed out in the GUI typically indicate they are still referenced somewhere in the configuration, even if not actively used.
  • Do not delete default certificates, profiles, or objects referenced by iRules without careful review.
  • Certificates attached to profiles that are not used by virtual servers require the profile to be deleted first before the certificate can be removed.
  • In BIG-IP version 13.1.0 and later, HTTPS monitors use Server SSL profiles instead of direct certificate/key associations. Monitors created in earlier versions may still have legacy certificate associations that are not visible in the GUI.
  • Always verify that objects are truly orphaned before removal to avoid service disruption.
  • If you encounter errors during deletion, the object may have additional hidden dependencies that need to be identified and removed first.
