Description

Depending on the situation there are a few checks that can be performed on a BIG-IP device. Do note that this article is specifically related to device health checks and not other things to consider before performing an upgrade. To prepare for an upgrade please refer to K84205182.

Environment

Device Health Checks

Cause

None

Recommended Actions

Health checks can be split into two categories. Pre-upgrade health checks and Other/Optional health checks.

Health Checks

Before performing an upgrade there are two recommended actions to take.

  1. QKView Diagnostics - Generate a QKView and upload it to iHealth. In the Diagnostics section of iHealth there is a lot of useful information regarding potential problems. K12878: Generating diagnostic data using the qkview utility
  2. A review of the logs is a must. In particular /var/log/ltm. There are many others to review also. Many are based on the modules that are provisioned. Look for things in the logs listed as CRITICAL or Failed. Not all will be something that will need to be addressed, but a search of MYF5 doing a copy/paste of the log entry will many times provide you with a quick answer with any you may be concerned with. If you do not find an answer the next step would be to open a case with F5 Support.
  3. Configuration Check - Perform a configuration check using the command below. This will go through the configuration and show any irregularities, such as links to non-existent configuration objects. Warnings can usually be ignored, but any errors must be fixed first before any upgrade is performed. Many of these can be found with a search on  MYF5 tmsh load sys config verify

Other/Optional Health Checks

Other checks that can be performed, but are not necessarily pre-upgrade checks can be the following:

  1. EUD Checks - EUD checks scan the hardware for any potential issues. If there are any FAILED results in the checks then it is advised to immediately open a new case to investigate what is causing the EUD to fail. You can refer to K7172: Overview of the End User Diagnostics software for more information about EUDs and how to perform them.
    1. Not all platforms use the EUD check. Please review K7172, and the applicable platform guide, to verify if your platform supports an EUD.
  2. CPU/Memory Checks - It is also a good idea to regularly check the CPU and memory graphs. If they often go (and remain for some time) above 80% then it may be a good idea to open a case with F5 Support to troubleshoot the issue. Alternatively K40472403: Collecting relevant data to troubleshoot high CPU utilization can be used for an initial evaluation.
