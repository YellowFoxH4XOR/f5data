Description

After upgrading BIG-IP LTM from version 17.1.3 to 17.1.3.1 and AS3 from 3.53 to 3.55, environments integrating with OpenShift (OCP) and using the F5 Container Ingress Services (CIS) may experience failures where virtual servers (VIPs) do not come up after OpenShift pods are restarted. The core symptom is persistent "403 Forbidden" errors on REST API calls from the CIS controller to BIG-IP, preventing dynamic pool member updates. As a result, VIPs associated with restarted pods remain down with outdated pool member IP addresses.

Error/Log Messages:

  • icontrol.exceptions.iControlUnexpectedHTTPError: 403 Unexpected Error: Forbidden
  • Access forbidden! You don't have permission to access the requested object.
  • REST API authentication failures (401/403) for CIS service accounts when accessing management IP or specific AS3 endpoints
  • CIS controller logs show: Failed to refresh Token from BIGIP or REST call error

Environment

  • Products: BIG-IP LTM, AS3, F5 Container Ingress Services (CIS)
  • Versions: BIG-IP 17.1.3.1, AS3 3.55, OpenShift OCP 4.18.9
  • Configuration:
    • Integration with OpenShift for dynamic pool member management via CIS/AS3
    • REST API calls from CIS controller to BIG-IP for pool member updates
    • sys httpd "allow" list controls REST API access
    • CIS controller source IP subnet not included in BIG-IP httpd allow list
  • Recent Actions:
    • Upgrade of BIG-IP from 17.1.3 to 17.1.3.1 and AS3 from 3.53 to 3.55
    • Restart of OpenShift pods, resulting in new pool member IP assignments

Cause

The root cause is that the source IP subnet of the CIS controller was not included in the BIG-IP sys httpd "allow" list. After the upgrade to BIG-IP 17.1.3.1, the system enforces stricter REST API access controls, requiring explicit inclusion of the CIS controller's source subnet in the httpd allow list. This change blocks REST API calls from the CIS controller, resulting in 403 Forbidden errors and preventing pool member updates. The upgrade introduced enhanced security hardening for REST API access that was not present in earlier versions.

Answer/Recommended Actions

To resolve REST API 403 Forbidden errors and restore CIS/AS3 integration after upgrading to BIG-IP 17.1.3.1:

  1. Identify the Source IP/Subnet of the CIS Controller:
    • Determine the IP address or subnet used by the CIS controller when making REST API calls to BIG-IP.
    • Check CIS controller logs or network configuration to identify the source subnet.
  2. Update the sys httpd Allow List:
    • Log in to the BIG-IP Traffic Management Shell (tmsh):

      tmsh

    • Add the CIS controller's source subnet to the httpd allow list:

      modify /sys httpd allow add { <CIS_controller_subnet>/xx }

    • Example:

      modify /sys httpd allow add { 10.47.78.0/23 }

    • Save the configuration:

      save /sys config

  3. Verify the Configuration:
    • List the current httpd allow list to confirm the entry was added:

      list /sys httpd allow

  4. Test REST API Access:
    • Use curl or similar tools from the CIS controller host to verify successful authentication and access to the BIG-IP REST API endpoints.
    • Example test command:

      curl -ku /<username>:<password> https:/

  5. Verify Pool Member Updates:
    • Restart affected OpenShift pods and confirm that VIPs and pool members are updated and come up as expected.
    • Check that pool member IP addresses reflect the current pod assignments.
  6. If Issue Persists:
    • Confirm REST API authentication works for the CIS service account from both localhost and the management IP.
    • If still unresolved, follow Option 2 from K000132348 to reset REST framework state.
    • Provide a pre-upgrade UCS for further analysis if needed.
    • Engage F5 escalation or product development for deeper investigation if REST API access remains blocked after all configuration and permission checks.

Additional Information

  • After upgrading to BIG-IP 17.1.3.1, the system enforces stricter REST API access controls through the sys httpd allow list, requiring explicit entries for all source subnets needing API access.
  • The CIS controller may reside on the same subnet as the BIG-IP management interface due to OpenShift routing requirements; ensure this subnet is included in the allow list.
  • REST API access may work via localhost but fail via management IP if the allow list is not properly configured.
  • This behavior differs from previous BIG-IP versions (such as 17.1.3), where such explicit allow-list entries were not required for local or management subnets.
  • The issue manifests only after pod restarts because that is when CIS attempts to update pool member IP addresses via REST API calls.
  • Multiple AS3 reinstallation attempts will not resolve the issue if the underlying httpd allow list configuration is missing the CIS controller subnet.
