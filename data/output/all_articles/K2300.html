Known Issue

This is the result of a known issue. Interfaces on BIG-IP or 3-DNS might become unresponsive for several reasons; however, an issue with interrupt coalescing on INTEL Gigabit Ethernet NICs is the most common.

F5 Product Development tracked this issue as CR25823, CR28334 and CR35291.

CR25823 resolved this issue for the ANIP kernel, and introduced functionality which enabled the workaround described below for the SMP kernel. CR25823 was fixed in version 4.5-PTF04.

CR28334 introduced functionality which allowed the device to reset itself and recover from this condition. The device timeout message will still be logged, but the interface reset should recover the device and allow it to continue passing traffic. CR28334 was fixed in version 4.5-PTF08.

To resolve this issue for the ANIP kernel, or enable the workaround below for the SMP kernel, upgrade to the latest version of BIG-IP or 3-DNS. For information about upgrading, refer to the BIG-IP and 3-DNS Release Notes.

Note: If you experience this issue in BIG-IP 4.5.9 or later, please contact F5 Technical Support for assistance. F5 Product Development tracked this issue in BIG-IP 4.5.9 or later as CR35291.

Workaround

If you are using the SMP kernel on BIG-IP or 3-DNS running version 4.5PTF-04, or later, you can perform the following steps to work around this issue:

Important: This following fix prevents the NIC from becoming unresponsive, but may cause a significant performance loss due to increased interrupts. High frame rates will increase the likelihood of a performance impact.

  1. Log in to the command line.
  2. Using a text editor, such a vi or pico, edit the /etc/boot.default file.

    At the bottom of the file, add the following line:

    -wxnointaggr
  3. Save the file and exit the editor.
  4. Reboot the system by typing the following command:

    reboot
