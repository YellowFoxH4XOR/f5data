Known Issue

This is the result of a known issue. When attack signatures are updated, the updated signatures are automatically removed from blocking mode and placed into staging mode without alerting the administrator of the change.

F5 occasionally updates the BIG-IP ASM attack signatures. The update contains both new signatures and updated signatures. New signatures are automatically added to the staging mode in order to verify false positives. The new signatures are removed from staging mode after you click the Enable button (for versions 9.4.2 through 9.4.4) or the Enforce Signatures button (for versions 9.4.5 and later).

Signatures that are updated are automatically placed into staging mode without any notification to the administrator. This behavior may result in lost protection for a signature that was in blocking mode, as it is now in a staging mode after being updated.

Important: Review all signatures in staging mode following an update to prevent any loss of protection due to updated signatures being removed from blocking to staging mode.

Note: For more information about attack signature staging, refer to the Configuration Guide for BIG-IP Application Security Manager.

Note: For more information about removing attack signatures from staging, refer to K8517: Enabling attack signatures that were not triggered during the staging process.

F5 Product Development tracked this issue as ID 224643 (formerly CR137081) and it was fixed in BIG-IP ASM version 11.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.
