K000151909: Things to know when using variable to select different upstream servers in $proxy_pass

Description

You want to use variables in the $proxy_pass to forward the request to different upstream servers or URIs dynamically, and get a 4xx response code from the upstream.

  • ”1.2.3.4 - - [01/01/2025:13:14:15 +0000] "GET /your-request-uri HTTP/1.1" 403 182 "-" "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/116.0.5845.180 Safari/537.36"“

Environment

  • NGINX Plus or NGINX OSS

Cause

You can use variables as/or a part of an upstream name to forward requests to different upstream servers dynamically. Whenever a variable is used in proxy_pass, it will pass what is defined in proxy_pass and replace the original request URI.

Here is an example:

Request: http://www.exmaple.com/fruits/apple

The forwarded request will be http://backend_1.com/fruits/apple with the normal configuration as below:

http {
  server {
    listen 80;
    server_name www.example.com; 

    location /fruits {
      proxy_pass http://backend_1.com/fruits;
    }
  }
}

The forwarded request will be http://backend_fruit.com/fruits without '/apple' as it's defined in the proxy_pass, and this may cause a 4xx error response code from the upstream server.

http {
  map $uri $selected_backend {
    ~^/fruits/ backend_1.com; #URI starts with "/fruits/" will go to backend_1.com
    ~^/veg/    backend_2.com; #URI starts with "/veg/" will go to backend_2.com
  }

  server {
    listen 80;
    server_name example.com; 

    location /fruits {
      proxy_pass http://$selected_backend/fruits;
    }
  }
}

Recommended Actions

Use the $uri to have the full request URI.

location /fruits {
  proxy_pass http://$selected_backend$uri;
}
