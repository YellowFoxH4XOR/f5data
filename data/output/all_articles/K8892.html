Topic

This article applies to BIG-IP 9.x through 10.1.0. For information about other versions, refer to the following article:

  • K49022416: Overview of failover capabilities in the event of a FIPS hardware failure (10.2.x - 12.x)

BIG-IP 9.2.4 introduced failover capabilities in the event of a FIPS kernel driver failure or FIPS hardware failure. This feature is enabled by default on all BIG-IP LTM devices that use FIPS cards; you cannot disable this feature.

The fipsutil monitor is the daemon responsible for monitoring and resetting the FIPS card in the event of a failure. In the event of a failure, the fipsutil sends the following message to syslog, logs the message in the /var/log/daemon.log file, and resets the BIG-IP system:

FIPS halted, re-attaching...

You can view the FIPS device failover properties by typing the bigpipe ha table command from the command line. The FIPS listing in the high availability table appears similar to the following example:

HIGH AVAILABILITY TABLE
Feature Key Action En? Act Proc Time Data
SSL accelerator FIPS device fail&restart yes no tmm 0 0

Note: Failover and restart is the only available action for the FIPS device.

A bigpipe db variable controls the amount of time the FIPS card can be non-responsive before failover is initiated. You can access the bigpipe db variable by typing the following command from the command line:

bigpipe db SSL.FIPS.FailureTimeout

The output will appear similar to the following example:

SSL.FIPS.FailureTimeout = 60

The default timeout value for the example FIPS card is 60 seconds. The timeout value indicates that the FIPS card can be non-responsive for 60 seconds; after 60 seconds, the fipsutil will issue an error message. Additionally, if a partner system is configured, the system will fail over.
