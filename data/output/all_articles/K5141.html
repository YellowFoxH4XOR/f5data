Known Issue

This is the result of a known issue. When the following sequence of events occurs, the BIG-IP system may fail to forward retransmissions from the node:

  1. The client connects to a virtual server that uses a delayed binding feature (such as an iRule, header insert, or cookie persistence) and establishes an HTTP keep-alive session.
  2. The client sends a request.
  3. The BIG-IP system directs the request to a node.
  4. The node responds to the request.
  5. The BIG-IP system receives the last response packet from the node.
  6. A packet containing part of the request is dropped between the BIG-IP system and the client.
  7. The client re-acknowledges the packet it received prior to the dropped packet.
  8. The BIG-IP system passes the acknowledgement to the node.
  9. The node retransmits the dropped packet.
  10. The BIG-IP system does not forward the dropped packet to the client.

Because the BIG-IP system has received the full node response before the packet that is destined for the client is dropped, the BIG-IP system will not forward the retransmission. However, if a packet is dropped before the BIG-IP system has received the full node response, the BIG-IP system will allow the retransmission to proceed normally.

F5 Networks Product Development tracked this issue as CR33744 and CR42010.
