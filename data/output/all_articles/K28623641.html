K28623641: Wrong IP address is getting assigned to the mgmt interface after BIG-IP VE deployment

Type
Support Solution
Published
2022-09-06
Updated
2026-02-06
Applies to
  • Public Cloud
  • BIG-IP
  • BIG-IP LTM
  • Google Cloud
Source
https://my.f5.com/manage/s/article/K28623641

Description

  • After deploying a new BIG-IP VE on Google Cloud using Terraform, you are unable to access the management IP address via GUI or SSH.
  • You notice the wrong IP address is associated with the interface you assigned for management during your deployment.

Environment

  • BIG-IP VE deployed on Google Cloud
  • Terraform used for deployment
  • Multi-NIC configuration

Cause

The management interface has been bridged to eth0 whereas the environment requires a different interface (such as eth1 for example). 
You can use the brctl show command to check what interface the management interface has been bridged to. The example below shows the mgmt interface is bridged to eth0.
brctl show
bridge name   bridge id       STP enabled    interfaces
mgmt          8000.xxxxx             no                  eth0

Recommended Actions

Management traffic goes through eth0 by default; therefore, if your environment requires management traffic to go through a different interface, you must change the NIC used for BIG-IP VE management.
Follow the steps in the link below to change the NIC used for management to the appropriate one:
https://clouddocs.f5.com/cloud/public/v1/shared/change_mgmt_nic_google.html

Additional Information

The startup-script.tpl for Terraform deployment available on Github suggests the management interface is bridged to eth1; therefore, if you see eth0 while facing this issue, try changing to eth1 as this may resolve the issue. You can refer to the Terraform module information by clicking the links below:

  • https://github.com/F5Networks/terraform-gcp-bigip-module
  • https://github.com/F5Networks/terraform-gcp-bigip-module/blob/main/startup-script.tpl
