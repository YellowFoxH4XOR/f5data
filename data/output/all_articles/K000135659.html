Description

After a user successfully authenticates via remote TACACS server, BIG-IP responds with "code": 500, "message": "MCP Session terminated" for iControl REST requests coming from that user even when using valid auth token. Sample request/response may look similar to the following:

curl -sk https://${BIGIP_ADDR}/mgmt/tm/sys/file/ssl-cert/ -H "X-F5-Auth-Token: ${AUTH_TOKEN}" | jq .
{
 "code": 500,
 "message": "MCP Session terminated",
 "errorStack": [],
 "apiError": 32768003
}


With the sys db variable systemauth.primaryadminuser being set to default, ruling out ID1012493, this same error also occurs due to a mismatch in the attributes that TACACS sends in the response and what attributes are configured in the BIG-IP's remote role group.

An indicator for mismatched TACACS attribute string despite being successfully authenticated would be the log entries in /var/log/secure similar to the following:

notice pam-authenticator[4260]: pam_tacplus: pam_tacplus: user test1 successfully authenticated
info rest(pam_audit)[4260]: user=test1(test1) partition=(unknown) level=(unknown) tty=(unknown) host=... . . . ...

Notice that the partition and level are both unknown.

In contrast, a successful auth with matching TACACS and remote role group configuration would log the following entries in /var/log/secure:

notice pam-authenticator[8774]: pam_tacplus: pam_tacplus: user test1 successfully authenticated
notice pam-authenticator[8774]: pam_bigip_authz: authenticated user test1 with role 500 (Certificate Manager) in partition [All]
info rest(pam_audit)[8774]: user=test1(test1) partition=[All] level=Certificate Manager tty=(unknown) host=... . . . ...
info rest(pam_audit)[8774]: 01070417:6: AUDIT - user test1 - RAW: rest(pam_audit): user=test1(test1) partition=[All] level=Certificate Manager tty=(unknown) host=... . . . ...


When attributes match, the correct partition and access level are set.

 

 

Environment

  • BIG-IQ
  • Remote authentication
  • iControl REST API

 

Cause

Mismatched attribute/value pair between the configured remote role group versus what the TACACS is sending in the response.

 

Recommended Actions

Ensure that the remote role group configuration or the TACACS server configuration for the attribute/value pairs of the user or the group match. See K01055692 for a guide.
