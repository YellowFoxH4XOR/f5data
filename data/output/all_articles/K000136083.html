K000136083: BIG-IP doesn't trust SMTP server certificate

Type
Support Solution
Published
2023-09-04
Updated
2023-11-21
Source
https://my.f5.com/manage/s/article/K000136083

Description

You receive an error when enabling TLS for SMTP. The BIG-IP does not trust the server certificate, ending the TLS handshake with error "Unknown CA". After checking the APM logs, you see the following error message:

 

Aug 10 17:20:37 err apmd[8917]: 01490194:3: /Common/apm:Common: Email Agent: Message send message send failed. SSL certificate problem: self signed certificate in certificate chain

 

Environment

SMTP

TLS

APM

Cause

Self signed certificate

Recommended Actions

Add the self signed certificate to ca-bundle.crt via the CLI:

 

1. Change directories to the /config/ssl/ssl.crt/ directory by typing the following command under bash:

cd /config/ssl/ssl.crt/

 

2. Copy ca-bundle.crt

cp ca-bundle.crt ca-bundle.crt.original

 

3. Using a text editor, open the ca-bundle.crt file

4. Copy & paste self signed certificate into the file

5. Save & exit text editor 

6. To force the mcpd process to reload the configuration, enter the following command:

touch /service/mcpd/forceload

 

On VIPRION systems, enter the following command to run this on all blades:

clsh touch /service/mcpd/forceload

 

7. To restart the BIG-IP system, enter the following command:

reboot

 

Important: This command interrupts traffic while the BIG-IP system either fails over to a peer system or completes the restart process.
