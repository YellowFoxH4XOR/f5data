Description

You're trying to load a UCS from VIPRION/Appliance to a Virtual Edition using 'platform-migrate' and you encountered the similar error below:

01080023:3: Error return while getting reply from mcpd: 0x107178a, 0107178a:3: Modifying license.maxcores to a value other than 2 is not allowed.
Error 0x107178a occurred: 0107178a:3: Modifying license.maxcores to a value other than 2 is not allowed.
Post-processing...
usermod: no changes
Restarting tmrouted...
Reloading License and configuration - this may take a few minutes...
....

WARNING: There were one or more errors detected during installation.
         Check the error messages and take the proper actions if needed.
ERROR: UCS installation failed.
Operation aborted.
Unexpected Error: UCS loading process failed.

Environment

  • BIG-IP VE
  • Loading UCS from a VIPRION/Appliance using 'platform-migrate' option

Cause

License has an attribute limiting the maximum number of cores, and the incoming UCS has a value of the DB variable 'license.maxcores' that contradicts this.
This is related to ID 675742. 

Recommended Actions

Since 'license.maxcores' value is ignored on hardware devices, we can modify and set this to the required value on the VIPRION/Appliance before saving the UCS and loading it to the VE.

From the VIPRION/Appliance:

# tmsh modify sys db license.maxcores value <value>

# tmsh save sys ucs <filename>

Use this UCS (with updated DB key value) to migrate config to the BIG-IP VE using platform-migrate.
