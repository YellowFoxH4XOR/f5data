Description

This article will explain how to pull an attribute from Active Directory and check if it is less than 30 days before allowing users to login.

Environment

  • BIG-IP APM
  • Active Directory
  • Do not allow users to connect if it has been more than 30 days since last login

Cause

Recommended Actions

To accomplish this you will need to check the lastLogon attribute from Active Directory.

  1. Login to the BIG-IP GUI
  2. Create an Access Policy in the Visual Policy Editor to resembles the following:
  1. The flow must have the AD Query and iRule Event before the AD Auth is necessary as if it is prior, the lastLogon Attribute would be updated when they hit the AD Auth rather the last time they logged in
  2. In the AD Query - add in the lastLogon in the Required Attributes that resembles the following:
  1. Create the following iRule and assign it to the Virtual Server:
when ACCESS_POLICY_AGENT_EVENT {
    if { [ACCESS::policy agent_id] eq "lastLogon" } {
        set 30days 2592000
        set offset 11644473610
        set username "[ACCESS::session data get session.logon.last.username]"
        set adtime "[ACCESS::session data get session.ad.last.attr.lastLogon]"
        set millisecs [expr {$adtime / 10000000}]
        set lastlogintime [expr {$millisecs - $offset}]
        set now [clock seconds]
        set diff [expr {$now - $lastlogintime}]
            log local0. "$diff seconds since $username last logged in."
        
        if { $diff > $30days } {
            ACCESS::session data set session.custom.lastLogonWithin30days 0
            
        } else {
            ACCESS::session data set session.custom.lastLogonWithin30days 1
        }
    }
}
  1. Update the iRule Event in the VPE to point at lastLogon
  2. ​​​​​​​Create the Within 30 days box using the Empty object in the VPE
  3. Add branches to check the session.custom.lastLogonWithin30days variable, if it returns a 1 - it allow the user:
  4. Add any expression (we will update it) --> Click on Advanced --> Update the Expression to: 
expr {[mcget {session.custom.lastLogonWithin30days}] == 1}
  1. From here you can begin your Policy with users who have logged in within the last 30 days, AD Auth is shown as an example.
