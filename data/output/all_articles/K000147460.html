K000147460: How to configure Header Transformation on F5® Distributed Cloud?

Type
Support Solution
Published
2024-11-08
Updated
2026-01-01
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud DNS Load Balancer
Source
https://my.f5.com/manage/s/article/K000147460

Description

  • You have configured the Origin to send HTTP Response Headers in a specified proper case but the end-user continues to receive them in lowercase (they have been manipulated), causing the application to malfunction. 
  • The Header "Content-Type" is being transformed to "content-type"
  • You want the end-user to receive the HTTP Response Headers as originally configured, without manipulation when passing through XC.

Environment

  • F5® Distributed Cloud (XC)
  • HTTP LB

Cause

XC may manipulate HTTP request and response header cases depending on the configuration. 

Recommended Actions

Note: We preserve headers when received from the client. For header manipulation (when headers are added on the LB), it is not currently supported.

In order to configure Header Transformation, you will need to go into the Origin Pool and LB settings within XC:

  • XC currently supports 2 Header transformation methods:
    • Default - Normalize the header to lower-case
    • Proper Case - The first character and any character following a special character will be capitalized. Example: "content-type' becomes "Content-Type"
    • Preserve Case - preserves the original case of headers without any modification

  • Request Header Transformation - Origin Pool Configuration

    1. Configure HTTP1.1 in the Origin Pool (This must be configured)
      • Select your Origin Pool -> Click Edit Configuration
         
      • Scroll to the bottom of the page to Other Settings -> Click Configure
         
      • Scroll down to Miscellaneous Options -> HTTP Protocol Configuration and toggle to HTTP/1.1
         
    2. Configure the Header Transformation choice under Miscellaneous Options as above 
      • Toggle between Default, Proper Case and Preserve Case
         
      • With Default as the header transformation, if a header "Test-teSt:VoLterra" is sent in the request, it is received by the upstream as "test-test:volterra"
      • With Proper Case as the header transformation, if a header "test-test:VoLterra" is sent in the request, it is received by the upstream as "Test-Test:Volterra"
      • With Preserve Caseas the header transformation, if a header "Test-teSt:VoLterra" is sent in the request, it is received by the the upstream as "Test-teSt:VoLterra"

  • Request Header Transformation - Load Balancer Configuration

    1. Also change the setting on the Load Balancer side to keep the setting the same with the origin pool. You can change the setting on LB through the below page: 

  • Response Header Transformation - Load Balancer Configuration (Note: This is hidden in the UI for HTTPS auto and HTTPS custom cert LBs, so this is configured in JSON)

    1. Option 1) Configure Proper Case header transformation in the Load Balancer

      • Go to the Load Balancer settings and switch to JSON
         
      • Add the JSON code below
         
        "header_transformation_type": {
        "proper_case_header_transformation": {}
      },
              "http_protocol_options": {
        "http_protocol_enable_v1_only": {}
      }
    2. Option 2) Configure Default header transformation in the Load Balancer  Add the JSON code below                 Add the JSON code below 
      "header_transformation_type": {  
              "default_header_transformation": {}        
             },       
             "http_protocol_options": {
               "http_protocol_enable_v1_only": {}
             }
    3. Option 3) Configure Preserve Case header transformation in the Load Balancer 
      • Add the JSON code below
         
        "header_transformation_type": {
        "preserve_case_header_transformation": {}
      },
      "http_protocol_options": {
                "http_protocol_enable_v1_only": {}
              }

Additional Information

  • Downstream - Connection from Client to our LB
  • Upstream - Connection from LB to the Origin Server endpoint
  • Request Headers - Headers that are sent to the upstream server
  • Response Headers - Headers that are sent to the downstream client
  • Request Header transformation is done on the Origin Pool configuration
  • Response Header transformation is done on the HTTP/HTTPS-Auto/HTTPS-Custom LB configuration
  • For header transformation, HTTP1.1 must be forced upstream or downstream depending on where the user wants to do the transformation
