K10555124: URLF filtering subscription expiry (SSL Orchestrator)

Type
Support Solution
Published
2022-04-06
Updated
2023-02-21
Applies to
  • F5 App Protect
  • F5 SSL Orchestrator: 15.X.X, 15.0.X, 15.1.1, 15.1.0, 15.1.X, 15.0.0
Source
https://my.f5.com/manage/s/article/K10555124

Description

URLF filtering subscription expiry resulting in SSL Orchestrator traffic flow impact with critical URL Classification query log messages similar to the example below logged to the /var/log/apm log file.

Apr  2 06:36:25 <hostname> crit tmm15[31056]: 01790602:2: [C] x.x.x.x:52726 -> x.x.x.x:443: (ERR_REJECT) Error processing URL Classification query from CatEngine
Apr  2 06:36:25 <hostname> crit tmm25[31056]: 01790602:2: [C] x.x.x.x:53970 -> x.x.x.x:443: (ERR_LICENSE) URL category lookup failed

Environment

  • URLF subscription (Expired).

  • SSL Orchestrator security policy configuration with reference(s) to Pre-configured subscription URLDB categories.

Cause

The URLDB category lookup engine fails to locate Pre-configured subscription categories. SSL Orchestrator cannot use the URL database (URLDB) for URL categorizations due to URLF license expiry.

Recommended Actions

F5 recommends you work with your sales account manager to renew your URLF subscription.

Additional Information

As a temporary work around to this issue, one can carry out either of the following procedures:

  1. Remove SSL Orchestrator security policy configuration references to Pre-configured subscription URLDB categories allowing traffic flow to resume.
    or
  2. Access the "Per Request Policy" VPE editor area for the impacted security policy and for any associated "Category Lookup" objects, set "Reset on Failure" to "Disabled".

Note: The "Per Request Policy" VPE change requires "strict updates" to first be disabled. To modify SSL Orchestrator configurations in ways that are not supported by the SSL Orchestrator interface, you must first disable Strict Updates. This allows you to change the configuration of the objects that are deployed by iAppLX template. However, if you later need to modify those SSL Orchestrator objects, you first have to re-enable Strict Updates to correctly deploy those changes. Re-enabling Strict Updates overwrites without warning any earlier changes made that required you to disable it.

If you need to disable Strict Updates, make sure to document the change in case you need to change the configuration later. After you make a change to the SSL Orchestrator, you should go back and verify that your earlier modifications to the underlying objects still exist and, if they don't, you should re-implement the removed or modified objects.

There is a Request Feature Enhancement for this:
RFE: 1101489 [SSLO][RFE] Allow "reset on failure" to be controlled from within sslo
 

SSL Orchestrator uses the URL category database to make TLS decrypt (intercept) and bypass decisions. URL category entries can come in two forms:

  • Subscription categories – URL categorization data is provided by a separate URL database subscription. This database contains close to 400 consistently updating categories of URLs maintained by Forcepoint. Subscription categories are most useful (for example, when TLS bypass decisions are required for specific categories of sites, like financial and healthcare related, and any sites that may convey personally identifiable information (PII)). These are usually mandated by corporate policy or government compliance and regulations to bypass decryption.

  • Custom categories – Custom categories are containers of URLs that you create and maintain but do not require a subscription to use.
