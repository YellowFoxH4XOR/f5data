Known Issue

Attempts to initiate an access session may cause BIG-IP APM user access to fail and display a configuration warning.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is deployed for high availability (HA), and uses hardware that consists of chassis with multiple slots.
  • One of the following events occurs:

    • You disable a slot on one of the chassis
    • A blade of the secondary chassis experiences a tmm core
    • You reboot one of the chassis in the HA pair

Impact

Users cannot access an access session.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When a user attempts to access an access profile, the system displays a warning message similar to the following example:

    Your session could not be established.

    The session reference number : <session id>

    Access policy configuration has changed on gateway.

    Please login again to comply with new access policy configuration

Workaround

To work around this issue, you can restart the apd process on the primary blade of the active chassis. To do so, perform the following procedure:

Impact of workaround: Traffic is briefly disrupted while the apd process restarts.

  1. From the primary blade of the active chassis, log in to the command line.
  2. Restart the apd process by typing the following command:

    bigstart restart apd
