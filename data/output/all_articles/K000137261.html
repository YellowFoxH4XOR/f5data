Description

Beginning in BIG-IP 13.1.0, or BIG-IP 12.0.0 for Virtual Edition, the db variable tm.tcplargereceiveoffload is enabled by default. This reports to "LRO" feature. LRO works at the NIC level by aggregating multiple incoming packets within a buffer before passing them up. This process helps reduce CPU usage by eliminating CPU from having to process the incoming packets.

On certain configurations, LRO might aggregate the ACK from the TCP3WHS with the first data packet and TMM will therefore also "skip" the ACK from TCP3WHS (and send the data packet piggybacked onto the ACK from the TCP3WHS). While this behavior is permitted per RFC, it might "confuse" some servers out there which expect a bare ACK on the TCP3WHS.

 

Environment

BIG-IP, LRO enabled.

Certain configurations such as FastL4 and vlan-groups are susceptible to this.

Cause

BIG-IP merges the ACK from the TCP3WHS with the data packet due to LRO (ingress). When sending traffic onwards (egress) TMM sends the packets as they arrived (data packet piggybacked onto the ACK from the TCP3WHS).

 Recommended Actions

If the above behavior is causing problems, then LRO can be disabled:

 

# tmsh modify sys db tm.tcplargereceiveoffload value <enable | disable>

# tmsh save sys config

 

Note: After modifying the tm.tcplargereceiveoffload database variable, you must restart the Traffic Management Microkernel (TMM) daemon by running the 'bigstart restart tmm' command. Restarting TMM temporarily interrupts traffic processing. F5 recommends that you run this command only during a maintenance window.
