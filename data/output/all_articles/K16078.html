Known Issue

When you remove a BIG-IQ system from a high availability (HA) active-active peer group, the system will no longer synchronize configuration data when you add it back to an HA peer group.

This issue occurs when all of the following conditions are met:

  • You configure a BIG-IQ system in an HA active-active peer group.
  • You remove the BIG-IQ system from the HA active-active peer group.
  • You add the BIG-IQ system back to an HA active-active peer group.

Impact

The BIG-IQ system is unable to perform as a redundant or backup device.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Configuration data does not synchronize to the BIG-IQ system that you have added back to the HA peer group.

Workaround

To work around this issue, you can remove only the BIG-IQ configuration to have a clean REST database. You can then add the BIG-IQ system back to the HA peer group. To do so, perform the following procedure:

Impact of procedure: This procedure deletes all items in the BIG-IQ REST database, which includes the discovered devices, high availability pairing data, and tenant-specific data. The procedure is not reversible. Consider carefully before proceeding.

  1. Log in to the BIG-IQ system command line.
  2. To stop the restjavad process, type the following command:

    tmsh stop /sys service restjavad
  3. To remove the existing BIG-IQ configuration, type the following command:

    rm -rf /var/config/rest
  4. To start the restjavad process, type the following command:

    tmsh start /sys service restjavad

    You are not required to reboot the BIG-IQ system because the REST database will rebuild to a clean state when the restjavad process starts in Step 4.
  5. You can now add the BIG-IQ system back into the HA peer group.
