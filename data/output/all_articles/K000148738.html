Description

The installed telemetry affects the loading of SSLO after a reboot.

SSLO Configuration will stuck for long duration and then stops at error state "SSL Orchestrator is not initialized. Open the TMSH/ssh shell and review errors in /var/log/resnoded/restnoded.log. Resolve all errors before restarting the initialization process by selecting the re-trigger icon. If this is HA setup then do not trigger ConfigSync till issue is resolved. Additional configuration changes are not allowed until the configuration is fully initialized."

Environment

SSLO (SSL Orchestrator)

Telemetry Streaming

 

Cause

The issue is caused by the behavior of the Telemetry package settings, which limit Restnoded sockets to five. This restriction leads to socket exhaustion, preventing Restnoded from processing SSLO requests efficiently.

RFE ID 1735077 is created to trace this issue.

 

Recommended Actions

1. Modify /var/config/rest/iapps/f5-telemetry/nodejs/restWorker.js to increase the http.globalAgent.maxSockets and https.globalAgent.maxSockets values to 50.

 

   // configure global socket maximum

   http.globalAgent.maxSockets = 50;

   https.globalAgent.maxSockets = 50;

 

2. Restart restnoded: 

 

bigstart restart restnoded

 

And then observe that SSLO page opens without issues.

This will work even after reboot and restart of restnoded.
