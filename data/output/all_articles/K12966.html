Topic

You should consider using this procedure under the following conditions:

  • You want the BIG-IP APM system to use the origin web server (OWS) to authenticate each user's credentials using an HTTP form
  • You want the BIG-IP APM system to inspect the response for the OWS for a specific string in a hidden parameter to determine if the authentication attempt was successful

Description

Some organizations may want to have a web server perform user authentication and then set a hidden parameter to a specific string if the authentication was successful. The BIG-IP APM system is able to prompt the users for their credentials, pass those credentials back to the web server, and then inspect the response from the web server to see if the hidden parameter is set to the expected value. If the expected string is present, the BIG-IP APM system will see that the user is authorized to use the system and will grant access.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The web server is configured to authenticate users
  • The web server is configured to set a hidden parameter with a specific string if the user is authenticated

    Note: For information regarding configuring your web server, see your web server vendor documentation.

Procedures

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuring HTTP form based authentication using string matching

To configure HTTP form based authentication using cookie matching, perform the following three procedures:

  • Creating the HTTP AAA server
  • Creating the access profile
  • Applying the access profile to your virtual server

Creating the HTTP AAA server

  1. Log in to the BIG-IP system.
  2. On the navigation pane, go to the following location:
    • 13.0.0 and later: Select Access > Authentication > HTTP
    • 12.1.2 and earlier: Expand Access Policy, AAA servers, and click HTTP
  3. Click Create.

    The New Server screen opens.

  4. Type a name for your server.
  5. From the Authentication Type field, select Form Based.
  6. Optionally specify a Start URI.
  7. Specify the HTTP Form method configured on the web server.
  8. In the Form Action field, enter the complete URL that sets the hidden parameter value. Make sure to include the protocol, server, and port.

    For example:

    http://10.10.10.10/auth.php

    Note: If your configuration requires that you use HTTPS, you will need to configure a layered virtual server that listens for the server IP address and port (80), uses a Server SSL profile, and has a pool with your HTTPS AAA server as a pool member.

  9. In the Hidden Form Parameters/Values field, enter the string that is expected.
  10. In the Number of Redirects to Follow field, enter the number 1.

    Note: If your configuration requires more than one redirect, change this number accordingly.

  11. From the Successful Logon Detection Match Type drop-down menu, select By Specific String in Response.
  12. In the Successful Logon Detection Match Value field, enter the value of the string that is expected.
  13. Click Finished.

Creating the access profile

  1. On the navigation pane, expand Access Policy.
  2. Click Access Profiles.
  3. Click Create.

    The New Profile screen opens.

  4. Enter a name for your access profile.
  5. Click Finished.

    The Access Profiles List screen opens.

  6. Click the Edit link for the access profile you just created.
  7. Click the (+) after the Start box.
  8. Under General Properties, select Logon Page.
  9. Click Add Item.
  10. Review the prepopulated fields for the log on page and make any needed changes.
  11. Click Save.
  12. Click the (+) after the Logon Page action.
  13. Under Authentication, select HTTP Auth.
  14. Click Add Item.
  15. Select the AAA server you created from the drop-down menu.
  16. Click Save.
  17. Click on the ending action box of the Successful branch (it will be set to Deny by default).
  18. Select Allow.
  19. Click Save.
  20. Click Close.

    The Access Profiles List screen opens.

  21. Select the access profile you just created.
  22. Click Apply Access Policy.

Applying the access profile to your virtual server

  1. On the navigation pane, expand Local Traffic.
  2. Click Virtual Servers.
  3. Click on the virtual server for which you want to use HTTP authentication.
  4. Under Access Policy, select your newly created access profile from the drop-down menu.
  5. Click Update.
