Known Issue

The BIG-IP ASM system may leak memory when you assign a remote logging profile to a virtual server.

This issue occurs when all of the following conditions are met:

  • You assign a logging profile with Application Security enabled to the virtual server.
  • You select Remote Storage for the logging profile's storage destination.
  • You configure a WebSocket profile on the same virtual server.

Impact

The BIG-IP ASM system memory use increases over time. This behavior may cause host memory exhaustion and the BIG-IP ASM bd process may restart. If you have configured the BIG-IP system as a device group member, the device may fail over to a peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system repeatedly logs an error message in the /var/log/ltm file that appears similar to the following example:

    01310003:0: ASM out of memory error: event code P232

  • The system logs error messages in the /var/log/ts/bd.log file that appear similar to the following example:

    IO_PLUGIN|ERR   |Aug 30 11:40:20.669|21148|plugin_common.c:0233|trans_open: Not enough UMU memory to start a new trans.

  • The BIG-IP ASM system generates a bd core file to the /shared/core directory.

Workaround

To work around this issue, you can remove the ASM remote logging profile from the affected virtual server. To do so, perform the following procedure:

Impact of workaround: After you perform the following procedure, the BIG-IP ASM system will not log security event unless a local logging profile is configured.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the virtual server associated with ASM remote logging profile that you want to remove and navigate to Security > Policies.
  4. Under Log Profile, move the remote logging profile from Selected to Available.
  5. Click Update.
