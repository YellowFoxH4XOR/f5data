K000141087: Configuration is not loading after upgrade to 16.1.5

Type
Support Solution
Published
2024-09-22
Updated
2024-09-22
Source
https://my.f5.com/manage/s/article/K000141087

Description

After upgrading to BIG-IP v16.1.5, device remains offline. The device remains offline because the configuration doesn't load.

tmsh load sys config verify gives the error below:
"/config/ssh/sshd_config line 22: Bad SSH2 mac spec 'hmac-sha1,hmac-ripemd160'"

Environment

BIG-IP LTM v16.1.5 in FIPS mode
Recently upgraded
Custom SSH ciphers are being used.

Cause

Most likely because the ciphers aren't supported

Recommended Actions

  • To fix the issue, the offending MACs ciphers need to be removed from the config.
  • Use vi or nano to edit the bigip_base.conf
# nano /config/bigip_base.conf
(OR)
# vi /config/bigip_base.conf
  • Then remove the MACs line having the ciphers. Example below:
sys sshd {
allow { ALL }
banner disabled
banner-text none
description none
inactivity-timeout 0
include "Ciphers aes128-cbc,aes128-ctr,aes192-ctr,aes256-ctr,arcfour128,arcfour256,arcfour
MACs hmac-sha1,hmac-ripemd160 <=======================================!
KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384"
log-level info
login enabled
port 22
}
  • Comment or remove entire MACs line.
  • Save the changes. Then load the config again and it should load without issue.
  • If device continues to be offline, check the mcp-state.
# tmsh show sys mcp-state

If "Last Configuration Load Status" shows full-config-load-succeed, then perform an mcpd forceload. For steps please refer Forcing the mcpd process to reload the BIG-IP configuration

Additional Information

To find out and add the MACs that are supported in currently running version, please use the command below to find from bash

# ssh -Q mac

From the above list add required MACs to the sshd config. For steps please refer K80425458: Modifying the list of ciphers and MAC and key exchange algorithms used by the SSH service on the BIG-IP or BIG-IQ systems
