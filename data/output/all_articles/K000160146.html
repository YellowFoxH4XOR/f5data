K000160146: Adding BIG-IP to Device Trust Members fails with error message: "[xmlHelpers.cpp:90 getXPathValue] expected 1 node for //faultstring, got 0"

Applies to

Source
https://my.f5.com/manage/s/article/K000160146

Description

You are unable to add peer BIG-IP to Device Trust Members. You get below error message:

[xmlHelpers.cpp:90 getXPathValue] expected 1 node for //faultstring, got 0

Environment

  • BIG-IP version 17.5.1.4
  • Custom httpd allow list
  • Httpd allow list is not in its default allow "All" setting

Cause

As part of fixing ID944817 (BIG-IP 17.5.1.4 Fixes and Known Issues | BIG-IP Documentation), if peer device management IP address is not allowed in the httpd allow list, adding Device Trust Members will fail. This is a new expected behavior.

Answer/Recommended Actions

Add peer device management IP address in httpd allow list of all BIG-IPs which needs to be part of cluster. Follow K13309: Restricting access to the Configuration utility by source IP address.

Additional Information

This issue is not observed when upgrading to 17.5.1.4. It is specifically when you forming HA for first time by adding Device Trust Members (maybe as part of migration) or rebuilding HA in 17.5.1.4.

By default below is the setting. In bigip_base.conf file you will not see any list or "All" keyword when in default setting.

# tmsh list sys httpd allow
sys httpd {
    allow { All }
}
