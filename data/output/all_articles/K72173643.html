Issue

Old Behavior

In versions prior to BIG-IP 12.0.0, BIG-IP DNS wide IPs answered DNS queries for the following record types:

  • A
  • AAAA
  • CNAME

New Behavior

Beginning in BIG-IP 12.0.0, BIG-IP DNS wide IPs answer DNS queries for the following additional record types:

  • MX
  • SRV
  • NAPTR

BIG-IP DNS now supports wide IPs of MX, SRV, and NAPTR resource record types. By adding global server load balancing (GSLB) support for these new record types, BIG-IP DNS can now load balance queries whose responses contain content other than IP addresses. This allows GSLB for responses that are DNS names to other objects in the DNS hierarchy. This new record support is in addition to the already supported wide IP record types: A, AAAA, and CNAME.

A, AAAA, and CNAME pools are created during the upgrade using the same pool name for each record type.  When the original pool has IPv4 members, an A record type pool is created. The same process is performed when the original pool contains IPv6 members a poor for the record type AAAA is created. This is also true for CNAME members of the original pool in which a CNAME pool is created. 

When the pre-upgrade pool is attached to a wide IP, a wide IP is created for each record type based pool created by the upgrade process. In the event that a pre-upgrade pool does not contain any members, an A and an AAAA record type pool is created, and associated wide IPs for the pools are created. Additionally, A and AAAA record pools can be created if IPv6 response is configured for a pool containing IPv4 members.

Impact

After upgrading to BIG-IP DNS 12.0.0 or later, you may notice your BIG-IP DNS configuration contains three wide IPs with the same name: one type A, one type AAAA, and one type CNAME.
