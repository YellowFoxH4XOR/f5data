Description

A virtual server for HTTPS is not triggering the iRule. Traffic is confirmed as passing through the virtual server, but none of the HTTP events in the iRule appear to be working.


Environment

Relevant environmental factors specific to the topic

  • LTM Virtual Server
  • HTTPS
  • iRules with HTTP events.

Cause

For the iRule to correctly process HTTP events, there must be a HTTP profile applied to the virtual server, however if the virtual server is processing HTTPS traffic, then there must also be a Client SSL profile. Without the Client SSL profile, the BIGIP will not be able to decrypt the HTTPS packets, and validate the HTTP content to pass it to the iRule.

If the virtual server is configured without the SSL profile, then it just acts as a TCP proxy and forwards the encrypted payload to the chosen pool member


Recommended Actions

  1. Apply a Client SSL profile to the virtual server
  2. If the pool is also HTTPS, then you must apply a Server SSL profile to the virtual server.
