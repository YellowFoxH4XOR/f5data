Topic

You should consider using this procedure under the following condition:

  • You want to enable logging for Border Gateway Protocol (BGP) neighbor status changes.

Description

When troubleshooting BGP neighbor adjacency issues, you may need to configure the BIG-IP system to log neighbor status events to the system log files. The status changes include some of the following events:

  • BGP notification received
  • Erroneous BGP update received
  • User reset request
  • Peer time-out
  • Peer closing down the session
  • Interface flap
  • Router ID changed
  • Neighbor deleted
  • Member added to peer group

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP system is licensed for the BGP advanced routing module.
  • You are familiar with the Virtual TeletYpe Terminal (VTY) command line shell.
  • You have BGP routing protocol enabled on the system.
  • You have command line access to the BIG-IP system.

Procedures

Enable the log-neighbor-changes BGP command

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To access the VTY command line shell, enter the following command:

    imish

  3. To enter enable mode, enter the following command:

    enable

  4. From the prompt, to enter configuration mode, enter the following command:

    config terminal

  5. To include the log priority, enter the following command:

    log record-priority

  6. Enable the BGP routing process by typing the following command:

    router bgp <ID>

    In this command, note the following:

    • <ID> is the autonomous system (AS) number.
  7. Enable log-neighbor-changes by typing the following command:

    bgp log-neighbor-changes

  8. Leave the current mode by typing the following command:

    end

  9. Save the configuration by typing the following command:

    copy running-config startup-config

  10. Log out of vtysh by typing the following command:

    exit

Enable syslog logging for BGP

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Determine if the system has an existing syslog include configuration by typing the following command:

    list /sys syslog include

  3. Edit the syslog configuration by typing the following command:

    Note: The edit command opens the syslog configuration using the vi text editor.

    edit /sys syslog all-properties

  4. Replace the include none line with the following syslog configuration:

    Note: If the system has an existing syslog include configuration, you must integrate the existing configuration with the following configuration:

    include "filter f_bgp_user {
    facility(user) and level (info,debug,warn,crit,alert,error,notice..emerg) and (match(\"NSM\") or match(\"BGP\"));
    };
    destination d_file {
    file(\"/var/log/zebos/bgp.log\" create_dirs(yes));
    };
    log {
    source(local);
    filter(f_bgp_user);
    destination(d_file);
    };"

  5. Save the changes and exit the vi editor using the following command sequence:

    :wq!

  6. At the prompt, enter y to save the changes.
  7. Save the change by typing the following command:

    save /sys config

Enable log rotation for the /var/log/zebos/bgp.log file

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Edit the log-rotate configuration by typing the following command:

    Note: The edit command opens the syslog configuration using the vi text editor.

    edit /sys log-rotate all-properties

  3. Replace the include none line with the following log-rotate configuration:

    Note: If the system has an existing log-rotate include configuration, you must integrate the existing configuration with the following configuration.

    include "/var/log/zebos/bgp.log
    {
    compress
    missingok
    notifempty
    sharedscripts
    postrotate
    endscript
    copytruncate
    }"

  4. Save the changes and exit the vi editor using the following command sequence

    :wq!

  5. At the prompt, enter y to save the changes.
  6. Save the change by typing the following command:

    save /sys config

View BGP logging

In the event that a BGP neighbor becomes unavailable, the BIG-IP system creates the /var/log/zebos/bgp.log file and generates neighbor status events. To review the log file, use a Linux command, such as cat or less.
