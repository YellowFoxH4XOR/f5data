While creating a new F5 SSL Orchestrator L2 service on the BIG-IP Configuration utility, in the Internal IP Offset list, you observe a value not displayed or available for selection.

This issue occurs when all of the following conditions are met:

  • You previously encountered an error while creating an SSL Orchestrator L2 service and went on to delete that L2 service.
  • You attempt to create a new L2 service.

For more information on creating a SSL Orchestrator L2 service, refer to the SSL Orchestrator deployment guide .

Impact

You are unable to select your desired Internal IP offset value when creating a new L2 service.

Symptoms

As a result of this issue, you may encounter one or more of the following symptom:

  • When creating a new SSL Orchestrator L2 service on the Configuration utility, you observe in the Internal IP Offset list, a value is not available for selection.

Workaround

To work around this issue, you can delete the errored L2 service then restart the restnoded service before creating the new L2 service again. To do so, perform the following procedure:

Impact of workaround: The restnoded daemon provides control-plane access to the BIG-IP system using an http REST api. Administrators or scripts accessing the system through REST may lose temporary access.

  1. Delete the errored SSL Orchestrator L2 service.

    Note: To delete an SSL Orchestrator L2 service, it should not be referenced by a service chain or in used by a topology. If your L2 service is referenced by a service chain, go to the appropriate service chain at SSL Orchestrator > Configuration > Service Chains to de-reference it first.

    1. Login to the Configuration utility.
    2. Go to SSL Orchestrator > Configuration.
    3. Select the Services tab.
    4. Select the check box next to the name of the L2 Service you want to delete.
    5. Select Delete.
    6. Select Ok.
       
  2. Restart restnoded daemon.
    1. Log in to the TMOS Shell (tmsh) by entering the following command:
      tmsh
    2. Restart the restnoded services by entering the following commands:
      restart sys service restnoded
  3. Attempt to create the L2 service again.
