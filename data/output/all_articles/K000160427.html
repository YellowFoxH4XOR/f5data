K000160427: Automating Modification of BIG-IP ASM JSON Profile Length and Structure Settings via API and Declarative WAF

Applies to

Description

BIG-IP ASM JSON content profiles have maximum length and structure settings (such as maximum length, array length, and structure depth) that default to "Any" and require modification. This article explains how to automate these changes using REST API and Declarative WAF, and how to ensure consistent enforcement when importing OpenAPI (Swagger) specification files.

Environment

  • BIG-IP ASM (Application Security Manager)
  • JSON content profiles
  • API Security policies
  • OpenAPI (Swagger) specification files
  • REST API access
  • Declarative WAF

Cause

Manual changes to JSON profile settings in the GUI do not persist after re-importing or updating the OpenAPI file. These settings must be defined in the OpenAPI schema or updated programmatically after import.

Answer/Recommended Actions

To automate the modification of JSON profile length and structure settings:

Option 1: Define Constraints in OpenAPI Specification

  • For API Security–type policies, when the OpenAPI specification file is parsed and imported, the JSON profile enforcement is derived directly from the imported JSON Schema definitions. Within the schema, you can enforce length constraints using validation keywords such as maxLength (and minLength) to control the allowed size of string values.

    For more information about structural validation keywords, refer to “A Vocabulary for Structural Validation” in the JSON Schema specification:

    https://json-schema.org/draft/2020-12/json-schema-validation#section-6

Option 2: Update via REST API

  1. Find the Policy ID:
    POLICY_ID=`curl -k -u ${BIGIP_USER}:${BIGIP_PASSWORD} https://${BIGIP}/mgmt/tm/asm/policies | jq -r --arg POLICY_NAME ${POLICY_NAME} '.items[] | select(.name == $POLICY_NAME) | .id'`
  2. Find the JSON Profile ID:
    PROFILE_ID=`curl -k -u ${BIGIP_USER}:${BIGIP_PASSWORD} https://${BIGIP}/mgmt/tm/asm/policies/$POLICY_ID/json-profiles | jq -r --arg PROFILE_NAME ${PROFILE_NAME} '.items[] | select(.name == $PROFILE_NAME) | .id'`
  3. Update the profile using PATCH:
    curl -k -u ${BIGIP_USER}:${BIGIP_PASSWORD} https://${BIGIP}/mgmt/tm/asm/policies/$POLICY_ID/json-profiles/$PROFILE_ID -X PATCH -d '{
    "defenseAttributes": {
    "maximumTotalLengthOfJSONData": 30000,
    "maximumArrayLength": 3000,
    "maximumStructureDepth": 20,
    "maximumValueLength": 200,
    "tolerateJSONParsingWarnings": false
    }
    }'

Note: You must change the entire defenseAttributes property of the profile. You need to include the entire object, not just changes.

Option 3: Use Declarative WAF

  • Create a Declarative Policy JSON file that imports the OpenAPI file and applies modifications in one operation. Example:

{
"policy": {
"name": "d_test_1",
"template": { "name": "POLICY_TEMPLATE_API_SECURITY" },
"open-api-files": [
{ "link": "http://example.com/openapiwaf_1.yml" }"
]
},
"modifications": [
{
"entityChanges": {
"metacharOverrides": [
{ "isAllowed": true, "metachar": "0x2d" },
{ "isAllowed": true, "metachar": "0x20" }
],
"defenseAttributes": {
"maximumTotalLengthOfJSONData": 30000,
"maximumArrayLength": 3000,
"maximumStructureDepth": 20,
"maximumValueLength": 200,
"tolerateJSONParsingWarnings": false
}
},
"entity": { "name": "json_POST_~sample_endpoint" },
"entityType": "json-profile",
"action": "update-append",
"description": "Allow the matched Meta Character on the matched Content Profile"
}
]
}

  • Import the Declarative Policy using:

curl -ksu admin:admin https://${BIGIP}/mgmt/tm/asm/tasks/import-policy -H "Content-Type: application/json" -d '{"fileReference": {"link": "http://example.com/DeclarativePolicy.json"}}"'
Note: Manual changes must be reapplied after each OpenAPI re-import unless handled via automation.

Additional Information

  • When using OpenAPI import, always define constraints in the schema for consistent enforcement.
  • Any manual changes to JSON profile settings will be overwritten by subsequent OpenAPI imports unless automated.
  • Refer to the JSON Schema specification for structural validation keywords.
