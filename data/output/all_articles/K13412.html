Summary

Topology is a proximity based load balancing mode that allows you to direct traffic by defining topology records and selecting the Topology load-balancing mode for the wide IP or pool. The Topology mode bases the distribution of requests on the topology records and the weighted scores configured for each record. The topology records direct DNS queries to the closest virtual server, based on geographical information. The BIG-IP DNS system is designed to support an unlimited number of topology records. The only limit is the amount of memory available to the gtmd process.

Description

To understand topology records, read the following sections:

Topology record format

Topology records are stored in the bigip_gtm.conf file on the BIG-IP DNS system and are used to match a local domain name system (LDNS) request with a specific destination object. A topology record has the following fields: an LDNS request source statement, a destination statement, an operator, and a weight.

LDNS request source

The LDNS request source statement defines the origin of a name resolution request. For example, the topology statement can be defined to direct an LDNS request from a particular source to a desired destination. The LDNS source can be any of the following elements:

  • Continent
  • Country
  • ISP
  • IP subnet (CIDR format)
  • Region (user-defined)
  • State
  • Geolocation ISP (12.0.0 and later)

Destination

A destination statement defines the resource to which the BIG-IP DNS system directs the incoming DNS request. For example, the topology statement can be defined to direct an LDNS request that originates from a particular source to any of the following destination elements:

  • Continent
  • Country
  • Data center *
  • ISP
  • IP subnet (CDIR format)
  • Pool of virtual servers
  • Region (User-defined)
  • State
  • Geolocation ISP (BIG-IP 12.0.0 and later)

Note: When using the topology load balancing method at a wide IP level with topology records that have a destination other than pool, the topology record has no effect. This is because load balancing at a wide IP level selects between BIG-IP DNS pools, and BIG-IP DNS pools do not have a data center or subnet associated with them, which is required for all other destination types. Such topology records only have an effect when using the topology load balancing method at the pool level.

Operator

An operator statement indicates whether the name resolution request matches the statement. You can select an operator for both a request source and a destination statement. For example, an operator statement can be one of the following:

  • is
  • is not

Weight (score)

The weight specifies the score that will be given to a destination object which matches the topology record. If a name resolution request matches more than one topology record, the BIG-IP DNS system uses the destination object with the highest weight to determine which statement it uses to load balance the request.

The following is an example topology configuration:

gtm topology ldns: region /Common/user.UserRegion server: pool /Common/Pool_A {
order 1
score 50
}
gtm topology ldns: isp /Common/ChinaEducationNetwork server: continent AS {
order 2
score 10
}
gtm topology ldns: continent AF server: subnet 1.1.1.32/32 {
order 3
score 10
}
gtm topology ldns: not region /Common/user.UserRegion server: pool /Common/Pool_B {
order 4
score 50
}

Topology records matching modes and the importance of order

A common misunderstanding is that BIG-IP DNS iterates through the topology records from the top down, stopping when a match is found (much like a firewall would do when matching rules). In fact, the system iterates through all pools (or pool members, depending on where the topology load balancing is applied) applying a score to each pool or pool member based on the matching topology records. The pools, or pool members with the highest score wins. In other words, if two or more pools return the same highest score, the system uses *all* to create DNS responses in a round-robin manner. Likewise, if using the Topology method to load balance members within a pool and two or more pool members return the same highest score, the system returns all matching records to create DNS responses in a round-robin manner (if the Maximum Answers Returned setting uses the default of 1, the system returns 1 record, but uses round-robin to distribute records for subsequent requests).

Multiple matching records, different pools

ldns: 10.0.0.0/24     server: pool_a    score 100
ldns: 10.0.0.0/24     server: pool_b    score 100

These topology records apply a score of 100 to both pool_a and to pool_b. Both pools are used to create DNS responses in a round-robin manner.

Multiple matching records, same pool

ldns: 10.0.0.0/24     server: pool_a    score 100
ldns: 10.0.0.1/32     server: pool_a    score 200

If longest-match is disabled and the order is set as shown previously, pool_a gets a score of 100.

Multiple matching records, multiple pools

ldns: 10.0.0.0/24     server: pool_a    score 100 
ldns: 10.0.0.1/32     server: pool_a    score 200
ldns: 10.0.0.1/32     server: pool_b    score 100

In this case, If longest-match is enabled, pool_a scores 200 and pool_b scores 100. Therefore, pool_a wins.

If longest-match is disabled and the order is set as shown previously, pool_a scores 100, and pool_b also scores 100. pool_a and pool_b are equal and are both used in a round-robin manner.

Troubleshoot topology load balancing decisions

To configure BIG-IP DNS to log the details of load balancing decisions, perform the following procedure:

  1. If necessary, create a log publisher by entering the following command:

    tmsh create sys log-config publisher local-syslog destinations add { local-syslog }

  2. Create a DNS logging profile and configure it to use the log publisher by entering the following command:

    tmsh create ltm profile dns-logging dns-logger log-publisher local-syslog

  3. Modify your dns profile to enable logging and point it to the DNS logging profile by entering the following command:

    tmsh modify ltm profile dns mydnsprofile enable-logging yes log-profile dns-logger

  4. Enable decision logging on the wide IP address that you want to troubleshoot by entering the following command syntax:

    tmsh modify gtm wideip a www.example.ord load-balancing-decision-log-verbosity { pool-selection pool-traversal pool-member-selection pool-member-traversal }

    Log output is sent to the specified log publisher. In the previous syntax, this is the ltm log.

    Output appears similar to the following:

Topology record creation

To create topology records, perform the appropriate procedure for your environment:

BIG-IP GTM 11.5.0 and later

  1. Log in to the Configuration utility.
  2. Go to DNS > GSLB > Topology > Records.
  3. Select Create.
  4. On the Topology Record Builder page, for Request Source, select the appropriate resource and is/is not statement.
  5. For Destination, select the appropriate resource and is/is not statement.
  6. Select Create.

BIG-IP DNS 11.0.0 through 11.4.1

  1. Log in to the Configuration utility.
  2. Go to Global Traffic > Topology > Records.
  3. Select Create.
  4. On the Topology Record Builder page, for Request Source, select the appropriate resource and is/is not statement.
  5. For Destination, select the appropriate resource and is/is not statement.
  6. Select Create.

Recommendations

When planning topology load balancing, consider that the BIG-IP DNS system looks up topology records in the order they appear in the Configuration utility and the configuration file. As a result, you should place more-specific topology records toward the top of the topology statement and less-specific records toward the end of the topology statement. You can change the order of existing topology records by selecting Change Order on the Topology Records page.
