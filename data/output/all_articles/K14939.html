Known Issue

The BIG-IP system may falsely report 100 percent CPU utilization messages. This issue occurs when all of the following conditions are met:

  • The system records a significant amount of total idle time across all CPU cores after certain uptime.

    Note: The time needed for this issue to occur is different on each platform and is inversely related to the number of CPU cores and proportional to the time spent idle. For example, it has been observed that a typical BIG-IP 4000 with eight CPU cores may falsely report 100 percent CPU utilization after approximately 36 days of uptime with about 87 percent of total idle time.
  • The BIG-IP cpu.logthreshold database variable is set to a value greater than zero.

The cpu.logthreshold database variable provides a configurable value for the CPU utilization threshold. When the CPU utilization exceeds this configured value, the chmand process logs a warning message in the /var/log/ltm file. By default, the cpu.logthreshold database variable value is set to 0 (zero) for all platforms except for certain platforms, such as the BIG-IP 2000s and 4000s, where this database variable is set to 80 by default.

Important: F5 recommends that you avoid changing the default values for this database variable unless otherwise instructed by F5 Support or an AskF5 article.

Impact

This issue is cosmetic and does not affect BIG-IP system performance.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H442475 on the Diagnostics > Identified > Low screen.
  • The chmand process logs a message to the /var/log/ltm file, every five minutes, that appears similar to the following example:

    012a0005:5: Cpu utilization over 300 seconds is 100%, exceeded log level 80%
  • You observe that the actual CPU utilization is much lower in graphs or the top utility.

Workaround

There is no work around for this issue. However, you can mitigate this issue by turning off CPU utilization threshold monitoring. To do so, perform the following procedure:

Impact of workaround: Turning off CPU utilization threshold monitoring may prevent the chmand process from reporting CPU utilization exceeding threshold messages when the actual CPU utilization exceeds the configured threshold.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Turn off CPU utilization threshold monitoring by typing the following command:

    modify /sys db cpu.logthreshold value 0
  3. Save the change by typing the following command:

    save /sys config
