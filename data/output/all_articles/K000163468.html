Description

When configuring port groups for a 4x25G breakout on a VELOS chassis connecting to an upstream switch (such as Cisco Nexus or ACI), you may experience the following symptoms:

  • Interfaces come up briefly but flap randomly and continuously.
  • The peer switch shows the interface as not connected.
  • Traffic counters remain near zero even during the brief periods the link shows as UP.
  • The system generates multiple optical alarms on the affected lanes in the VELOS Dashboard (Active Alarms) or via the CLI.

When you run the show system alarms command, you may observe logs similar to the following:

Environment

  • VELOS CX410 chassis (also applies to other VELOS platforms)

  • Port groups configured as 4x25G breakout
  • Upstream switch using 25G SFP modules (e.g., Cisco Nexus or ACI)

Cause

This issue occurs when the Forward Error Correction (FEC) setting on the upstream switch does not match the required configuration for the VELOS 25G link. Specifically, the upstream switch may be configured to use CL91 FEC instead of the required CL108 (RS-FEC).

Recommended Actions

To resolve this issue, you must modify the FEC configuration on the upstream switch side to use the correct protocol.

Ensure the upstream switch ports connected to the F5 breakout cable are configured to enable Forward Error Correction (FEC) CL108 (also known in some switch operating systems as RS_IEEE_FEC or RS_FEC_IEEE) instead of CL91.

Note: Depending on the switch vendor, you may need to administratively shut down the port on the switch first, change the FEC setting to CL108, and then bring the port back up for the changes to negotiate properly.
