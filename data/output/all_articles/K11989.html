Issue

In BIG-IP versions prior to 10.1.0, a known issue allowed the use of the HTTP::uri, HTTP::path, HTTP::query, and HTTP::host commands in invalid contexts.

For example, in BIG-IP 10.0.0, although the HTTP::host command was never intended to be valid in HTTP response events, the HTTP::host command could be used in the HTTP_RESPONSE event, and no error is generated. If no Host header exists in the server response, no value is returned. If the response included a Host header, the header value is returned.

Note: For more information, refer to K11988: The MCPD parser does not generate error messages when certain HTTP iRule commands are used in invalid contexts.

In BIG-IP 10.1.0, the known issue documented in SOL11988 was fixed, resulting in a change in behavior for these commands in some contexts. This was an intentional design decision, since those data are only relevent within the request context. However, iRules that loaded and ran without error on previous versions may now generate errors. When restoring a UCS archive from a previous version, these error messages may prevent the configuration from loading.

For example, begining in BIG-IP 10.1.0, attempting to save an iRule which uses the HTTP::host command in the HTTP_RESPONSE event generates an error message that appears similar to the following example:

01070151:3: Rule [log_http_host] error: line 7: [command is not valid in current event context (HTTP_RESPONSE)] [HTTP::host]

To avoid any issues upon upgrade, restrict the use of the HTTP::uri, HTTP::path, HTTP::query, and HTTP::host commands to the HTTP_REQUEST, HTTP_REQUEST_DATA, HTTP_REQUEST_SEND, HTTP_CLASS_SELECTED, HTTP_CLASS_FAILED events, and then only when an HTTP profile is active on the virtual server.
