Topic

This article covers how to create your own local Root CA to sign the certificate for the Configuration utility. To create a certificate signed by your organization's CA for the Configuration utility instead, refer to the following article:

  • K51035715: Replace the Configuration utility's self-signed device certificate with a certificate signed by your organization's CA

You should consider using this procedure under the following conditions:

  • You want to avoid SSL certificate alert messages when connecting to the Configuration utility.
  • You have a Certificate Authority (CA)-signed SSL certificate or want to create a local CA to sign SSL certificates.

Description

The Configuration utility uses a self-signed SSL device certificate by default. When you access the Configuration utility, most web browsers generate an alert message and pause the connection until a web browser security exception is made. You can make a single security exception and access the Configuration utility without future alerts. The web browser security icon continues to show the Configuration utility as an insecure site. However, if you prefer to not make a web browser security exception and have the web browser security icon indicate a secure site, you can do the following:

  • Replace the Configuration utility's self-signed device certificate with a CA-signed SSL certificate.
  • Import the CA signing certificate into the client Web browser's Trusted Root CA certificate store.

Note: If you already have the CA-signed certificate and chain certificate (when required) from a Trusted Root CA, read through the first procedure to ensure that the SSL certificate properties are configured correctly.

Note: If your BIG-IP system is managed by a BIG-IQ system, replacing the BIG-IP Configuration utility's self-signed SSL certificate does not affect the trust between the managed BIG-IP system and the BIG-IQ system.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Have access to either a workstation with the OpenSSL package installed or access to the Advanced Shell (bash).
  • Are familiar with basic Linux commands.

Procedures

  • Create a local Root CA and sign a new SSL certificate
  • Replace the BIG-IP system self-signed device certificate
  • Update the web browser Trusted Root CA certificate store

Create a local Root CA and sign a new SSL certificate

This procedure uses OpenSSL to help you create a local Root CA and sign an SSL device certificate that the Configuration utility uses. You can use the Root CA to create signed SSL certificates for multiple BIG-IP systems.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the workstation command line or bash.
  2. To create a working directory to store the CA Root certificate and key, use the following command syntax:

    mkdir <directory_name>

    For example, to create a directory named bigip_ca, enter the following command:

    mkdir bigip_ca

  3. To change into the directory, use the following command syntax:

    cd <directory_name>

    For example, to change into the bigip_ca directory, enter the following command:

    cd bigip_ca

  4. To determine the OpenSSL configuration directory, enter the following command:

    openssl version -a

    In the following example, the OpenSSL configuration directory is in /etc/pki/tls directory:

    OPENSSLDIR: "/etc/pki/tls"

  5. To copy the OpenSSL configuration file, openssl.cnf, to the current working directory, bigip_ca, use the following command syntax:

    cp </path>/openssl.cnf .

    For example, to copy the openssl.cnf file to your working directory using the path /etc/pki/tls, enter the following command:

    cp /etc/pki/tls/openssl.cnf .

  6. Using a text editor, edit the copy of openssl.cnf in your bigip_ca directory to update the existing configuration to match the following modified directives. The following example does not show the entire OpenSSL configuration file so the [section] information is included to help you navigate the file. Do not remove any of the existing configuration directives.

    Note: To avoid encoding issues, F5 recommends that you manually edit the openssl.cnf file rather than using copy / paste.

    Important: The CA certificate and private_key are created in step 11. If you prefer a different name than bigip_ca, modify the configuration file accordingly and use the same names in step 11.

    [ CA_default ]
    dir             = .                                               
    certificate     = $dir/bigip_ca.crt                                                  
    private_key     = $dir/bigip_ca.key  
    new_certs_dir   = $dir

    default_days = 3650 
    default_md   = sha256

    policy = policy_anything

    [ policy_anything ]
    countryName             = optional
    stateOrProvinceName     = optional
    localityName            = optional
    organizationName        = optional
    organizationalUnitName  = optional
    commonName              = supplied
    emailAddress            = optional

    [ req ]
    default_bits            = 2048
    default_md              = sha256
    ...

  7. (Optional) To restrict the usage of certificates you sign, you can uncomment the extendedKeyUsage directive in the [ usr_cert ] section in your copy of openssl.conf and specify purposes. Otherwise you can leave the directive commented out so the certificate defaults to all purposes except time stamp signing.
  8. (Optional) To include SAN details when signing a CSR, add the sections below to the end of the  [ usr_cert ] section in your copy of the openssl.conf file using the following command syntax:

    Important: Specify the fully-qualified domain name (FQDN) of your BIG-IP as the first name in the alt_names section then add your alternative names. Additionally, you need to update the names or comment out the subjectAltName directive for each new certificate you sign depending on the requirements.

    subjectAltName = @alt_names

    [ alt_names ]
    DNS.1 = <FQDN 1>
    DNS.2 = <FQDN 2>
    DNS.3 = <FQDN 3>
    ...
    DNS.x = <FQDN x>
    ...
    IP.1 = <IP_addr 1>
    IP.1 = <IP_addr 2>
    IP.1 = <IP_addr 3>
    ...
    IP.x = <IP_addr x>

    For example:

    subjectAltName = @alt_names

    [ alt_names ]
    DNS.1 = www.example.com
    DNS.2 = test.example.com
    DNS.3 = mail.example.com
    IP.1 = 192.0.2.1
    IP.2 = 198.51.100.254
    IP.3 = 2001:DB8::1

  9. Save the file.
  10. To create the necessary CA serial and index.txt files, enter the following commands:

    Note: The index.txt file contains the list of signed SSL certificates. The serial file is the source of the SSL certificate serial number. The number increments by 1 with each signing.

    echo 100000 > serial
    touch index.txt

  11. To create the Root CA certificate and key, use the following command syntax:

    openssl req -new -x509 -newkey rsa:<Key Size> -keyout <key_name>.key -out <cert_name>.crt -days 3650 -config ./openssl.cnf

    For example, to create a Root CA certificate named bigip_ca.crt with RSA key size of 4096 and a key named bigip_ca.key, enter the following command:

    Note: This command requires that you answer the questions in the following table.

    openssl req -new -x509 -newkey rsa:4096 -keyout bigip_ca.key -out bigip_ca.crt -days 3650 -config ./openssl.cnf

    QuestionDescriptionExample
    Enter PEM pass phrase:The pass phrase used to protect the CA key. This pass phrase is required each time you sign a certificate. Store it in a safe place.Choose a strong passphrase
    Country NameA two-letter abbreviation for your country.US
    State or Province Name The full state or province name where your organization is located. Washington
    Locality NameThe full city name where your organization is located.Seattle

    Organizational Unit NameOptional for additional organization information.BIG-IP Admin

  12. To create a directory to store the new signed SSL device certificate and key, use the following command syntax:

    Note: Separate directories are helpful when you manage SSL keys and certificates for multiple BIG-IP systems.

    mkdir <name>

    For example, to create a directory that stores the SSL device certificate and key for a BIG-IP system named bigip1.example.com, enter the following command:

    mkdir bigip1.example.com

  13. To create a certificate signing request (CSR) and key in the proper directory, use the following command syntax:

    openssl req -new -nodes -out <directory>/<request_name>.req -keyout <directory>/<key_name>.key -config ./openssl.cnf

    For example, to create a CSR named bigip1_device.req and an SSL key named bigip1_device.key in the directory bigip1.example.com, enter the following command:

    Note: This command requires that you answer the questions in the following table. When prompted for a challenge password, select Enter for no password.

    Important: The Common Name must match what you enter in the Web browser's URL box when accessing the Configuration utility.

    openssl req -new -nodes -out bigip1.example.com/bigip1_device.req -keyout bigip1.example.com/bigip1_device.key -config ./openssl.cnf

    An optional company name:Not required.Enter
  14. To sign the CSR with the Root CA certificate, use the following command syntax:

    openssl ca -out <directory>/<cert_name>.crt -config ./openssl.cnf -infiles <directory>/<request_name>.req

    For example, to sign a request named bigip1_device.req in the bigip1.example.com directory, enter the following command:

    Note: You must provide the CA private key pass phrase. Answer Y to the questions that follow.

    openssl ca -out bigip1.example.com/bigip1_device.crt -config ./openssl.cnf -infiles bigip1.example.com/bigip1_device.req

    The command output appears similar to the following example:

    Enter pass phrase for ./bigip_ca.key:

    Certificate is to be certified until Jan 01 12:34:56 2030 GMT (3650 days)

    Sign the certificate? [y/n]:y

    1 out of 1 certificate requests certified, commit? [y/n]y

  15. You can repeat steps 7 and 8 followed by 12 through 14 for additional BIG-IP systems. Be certain to create a separate directory and change the Common Name for each of the BIG-IP systems. Once completed, continue to the next procedure.

Replace the BIG-IP system self-signed device certificate

You can use this procedure to back up and replace the BIG-IP system's self-signed device certificate. In this procedure, F5 assumes that you are working remotely and have SSH access to the BIG-IP system being updated. Working remotely allows you to update multiple systems from one local Root CA.

If the target device is a BIG-IP DNS system, connectivity between remote BIG-IP systems fail until the new signed certificate is exchanged. You should perform this procedure during a planned maintenance period. For more information on exchanging certificates, refer to the DNS sync group peer procedures of K16951115: Changing the BIG-IP DNS system device certificate using the Configuration utility.

Note: SSL certificates signed by a third-party CA must include both the client authentication (clientAuth) and server authentication (serverAuth) extended key usage (EKU) extensions, to allow use by both server and client applications. For example, the big3d process operates as a server (serverAuth), while the gtmd process operates as a client (clientAuth). For information, refer to K7717: BIG-IP DNS and Link Controller support for third-party SSL certificates.

Note: For information about the deprecation of clientAuth EKU for public certificates generated by Public Key Infrastructure (PKI) certificate authorities (CA) and what you can do to prepare, you may want to refer to the F5 DevCentral article: The End of ClientAuth EKU…Oh Mercy…What to do?.

Impact of procedure: Communication with other BIG-IP devices fail until the new certificate is exchanged. There is no impact to high availability (HA) features such as traffic groups and device groups.

  1. From the workstation command line or bash, change into the directory that you created for the BIG-IP system that is being updated, using the following command syntax:

    cd <directory>

    For example, to change into the directory for the BIG-IP system named bigip1.example.com, created in step 10 of the previous procedure, enter the following command:

    cd bigip1.example.com

  2. Back up the current BIG-IP system self-signed device certificate and key to the local system because you overwrite them in the next step. To back up, use the following command syntax:

    Note: Ensure you include the dot (.) which represents the current working directory.

    scp <admin_user>@<IP_address>:/config/httpd/conf/ssl.crt/server.crt .

    scp <admin_user>@<IP_address>:/config/httpd/conf/ssl.key/server.key .

    For example, to save the current SSL certificate and key from a BIG-IP system with IP address 192.168.10.100 using the root account, enter the following command:

    scp root@192.168.10.100:/config/httpd/conf/ssl.crt/server.crt .

    scp root@192.168.10.100:/config/httpd/conf/ssl.key/server.key .

  3. When replacing the device certificate in this step, you overwrite the default self-signed device certificate files, /config/httpd/conf/ssl.crt/server.crt and /config/httpd/conf/ssl.key/server.key. Overwriting the files ensures the system is compatible with iQuery and ensures there are no ConfigSync conflicts. To overwrite the existing self-signed SSL certificate and key with the new CA-signed SSL certificate, key, and when applicable copy a chain certificate, on the BIG-IP system, use the following command syntax: 

    scp <cert_name>.crt <admin_user>@192.168.10.100:/config/httpd/conf/ssl.crt/server.crt
    scp <key_name>.key <admin_user>@192.168.10.100:/config/httpd/conf/ssl.key/server.key
     

    In versions 13.1.x and earlier:

    scp <chain_cert_name>.crt <admin_user>@192.168.10.100:/config/httpd/conf/ssl.crt/  

    In versions 14.1.x and later:

    scp <chain_cert_name>.crt <admin_user>@192.168.10.100:/config/httpd/conf/ssl.crt/chain.crt

    For example, to upload the new CA-signed SSL certificate and chain certificate named bigip1_device.crt, bigip1_device.key, and bigip1_device-chain.crt to a BIG-IP system with IP address 192.168.10.100, using the root account, enter the following command:

    scp bigip1_device.crt root@192.168.10.100:/config/httpd/conf/ssl.crt/server.crt
    scp bigip1_device.key root@192.168.10.100:/config/httpd/conf/ssl.key/server.key
     

    In versions 13.1.x and earlier:

    scp bigip1_device-chainfile.crt root@192.168.10.100:/config/httpd/conf/ssl.crt/bigip1_device-chainfile.crt
     

    In versions 14.1.x and later:

    scp bigip1_device-chainfile.crt root@192.168.10.100:/config/httpd/conf/ssl.crt/chain.crt

    Note: The SSL chain certificate chain is not a required component unless you are configuring in an environment that requires a chain certificate such as a BIG-IP DNS environment.

  4. Log into the BIG-IP command line.
  5. If applicable, for proper iQuery communication you must append any chain or root certificates in the /config/httpd/conf/ssl.crt/server.crt file. To do so, use the following command syntax:

    cat /config/httpd/conf/ssl.crt/<chain_cert_name>.crt >> /config/httpd/conf/ssl.crt/server.crt

    For example:

    cat /config/httpd/conf/ssl.crt/bigip1_device-chainfile.crt >> /config/httpd/conf/ssl.crt/server.crt
    (this step is only required in v13.1.x and earlier)

  6. If applicable, configure httpd to use the new combined chain certificate file to secure the Configuration utility. To do so, use the following command syntax:

    In versions 13.1.x and earlier:

    tmsh modify sys httpd ssl-certchainfile /config/httpd/conf/ssl.crt/server.crt

    In versions 14.1.x and later:

    tmsh modify sys httpd ssl-certchainfile /config/httpd/conf/ssl.crt/chain.crt

  7. Restart the httpd process to load the new certificates into the running configuration. To do so, use the following command syntax:

    tmsh restart sys service httpd

Update the web browser Trusted Root CA certificate store

Before you connect to the Configuration utility, you must import the BIG-IP Root CA certificate into the Web browser's Trusted Root CA certificate store. The steps to accomplish this may vary depending upon the type of Web browser in use. 

Note: The following procedures describe third-party software and may change without our knowledge. Refer to each browser's documentation for more information.

Note: You do not need to complete the following steps when the BIG-IP certificate modifications include the use of a chain certificate that ultimately references a browser-Trusted Root CA.

Impact of procedure: Performing either of the following procedures should not have a negative impact on your system.

Microsoft Edge

  1. Copy the BIG-IP CA Root certificate to your workstation.
  2. Open the web browser.
  3. Enter edge://settings in the browser address bar.
  4. Select Privacy, search, and services.
  5. Under Security, select Manage Certificates.
  6. Select the Trusted Root Certificate Authorities tab.
  7. Select Import.
  8. Browse to and select the BIG-IP Trusted Root CA certificate.

    Note: If the file does not appear, change Certificate Files to All Files.

  9. The BIG-IP Trusted Root CA certificate should be placed in the Trusted Root Certificate Authorities store.
  10. Select Next.
  11. Select Yes to install the Root certificate.
  12. Select OK.

Chrome

  1. Copy the BIG-IP CA Root certificate to your workstation.
  2. Open the web browser.
  3. Enter chrome://settings in the browser address bar.
  4. Select Privacy and Security.
  5. Select Security.
  6. Select Manage Certificates.
  7. Select the Trusted Root Certificate Authorities tab.
  8. Select Import.
  9. Browse to and select the BIG-IP Trusted Root CA certificate.

    Note: If the file does not appear, change Certificate Files to All Files.

  10. The BIG-IP Trusted Root CA certificate should be placed in the Trusted Root Certificate Authorities store.
  11. Select Next.
  12. Select Yes to install the Root certificate.
  13. Select OK.

Firefox

  1. Copy the BIG-IP CA Root certificate to your workstation.
  2. Open the web browser.
  3. Enter about:preferences#privacy as the browser address.
  4. Under Security, for Certificates, select View Certificates.
  5. Select the Authorities tab.
  6. Select Import.
  7. Browse to and select the BIG-IP Trusted Root CA certificate.

    Note: If the file does not appear, change Certificate Files to All Files.

  8. Select the Trust this CA to identify Websites check box.
  9. Select OK.

Internet Explorer

Note: Microsoft announced the end of support for Internet Explorer on June 15, 2022. You should use supported browsers such as Microsoft Edge, Google Chrome, or Mozilla Firefox.

  1. Copy the BIG-IP CA Root certificate to your workstation.
  2. Open the Web browser.
  3. Go to Tools > Internet Options.
  4. Select the Content tab.
  5. Select Certificates.
  6. Select the Trusted Root Certification Authorities tab.
  7. Select Import and Next.
  8. Browse to and select the BIG-IP Trusted Root CA certificate.

    Note: If the file does not appear, change Certificate Files to All Files.

  9. Select Open.
  10. Select Next.
  11. Select Next.
  12. Select Finished.
