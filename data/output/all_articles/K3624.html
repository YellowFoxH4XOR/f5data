Topic

This article applies to BIG-IP 4.5.1 through 9.4.1 For information about other versions, refer to the following articles:

  • K13205: Configuring BIG-IP to resolve DNS hostnames (11.x and later)
  • K8437: Configuring BIG-IP to resolve DNS hostnames (9.x - 10.x)

You must enable DNS name resolution in order to use DNS names at the command line, or to use some optional configurations, such as email delivery.

BIG-IP and 3-DNS use two sources of information to resolve DNS names: the local hosts file and DNS. BIG-IP and 3-DNS use the local hosts file first and, if the names cannot be resolved, they use DNS.

Note: For information about configuring DNS name resolution for BIG-IP 9.4.2 and later, refer to K8437: Configuring BIG-IP to resolve DNS hostnames (9.x - 10.x).

Note: For information about configuring local host name resolution, refer to K3625: Configuring local host name resolution for BIG-IP (4.5.x - 9.4.1).

To configure DNS name resolution, perform the following procedure:

  1. Log in to the command line.
  2. Test the DNS server that you want to add by typing the following command:

    dig @<DNS Server IP Address>

    For example:

    dig @172.16.81.50

    If the test is successful, you will receive output similar to the following example:

    ; <<>> DiG 9.2.2 <<>> @172.16.81.50
    ;; global options: printcmd
    ;; Got answer:
    ;; -<<HEADER>>- opcode: QUERY, status: NOERROR, id: 55803
    ;; flags: qr rd ra; QUERY: 1, ANSWER: 13, AUTHORITY: 0, ADDITIONAL: 0
    ;; QUESTION SECTION:
    ;. IN NS
    ;; ANSWER SECTION:
    . 518108 IN NS a.root-servers.net.
    . 518108 IN NS b.root-servers.net.
    . 518108 IN NS c.root-servers.net.
    . 518108 IN NS d.root-servers.net.
    . 518108 IN NS e.root-servers.net.
    . 518108 IN NS f.root-servers.net.
    . 518108 IN NS g.root-servers.net.
    . 518108 IN NS h.root-servers.net.
    . 518108 IN NS i.root-servers.net.
    . 518108 IN NS j.root-servers.net.
    . 518108 IN NS k.root-servers.net.
    . 518108 IN NS l.root-servers.net.
    . 518108 IN NS m.root-servers.net.
    ;; Query time: 7 msec
    ;; SERVER: 172.16.81.50#53(172.16.81.50)
    ;; WHEN: Mon Nov 29 17:26:59 2004
    ;; MSG SIZE rcvd: 228

    If the test is unsuccessful, you will receive output similar to the following example:

    ; <<>> DiG 9.2.2 <<>> @172.16.81.50
    ;; global options: printcmd
    ;; connection timed out; no servers could be reached

    If the test is unsuccessful, you will need to troubleshoot your configuration to determine why the BIG-IP or 3-DNS cannot reach your DNS server before you proceed to Step 3.
  3. Using a text editor, edit the /etc/resolv.conf file.
  4. Add the following line to the top of the file:

    nameserver <DNS Server IP Address>

    For example:

    nameserver 172.16.81.50

    You can add multiple DNS servers by adding multiple lines.

    For example:

    nameserver 172.16.81.50
    nameserver 172.16.81.51
    nameserver 172.16.81.52
  5. Save the file and exit the editor.

Testing DNS name resolution

To test DNS name resolution, use the following command syntax, replacing <name> with the DNS name of a server on your network:

host <name>

For example:

host www.askf5.com

If the test is successful, you will receive a response similar to the following example:

www.askf5.com has address 10.90.101.200

If the test is not successful, you will receive a response similar to the following example:

Host www.askf5.com not found: 3(NXDOMAIN)

The controller is now capable of resolving DNS names.
