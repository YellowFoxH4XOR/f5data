Known Issue

This is the result of a known issue. Beginning with BIG-IP ASM 9.4.0, security policy history information is stored on the BIG-IP ASM system and then synchronized between BIG-IP ASM units during a configsync operation. If the unified computing system (UCS) file does not contain a policy version history file, configsync fails, and the following error messages display on the system console:

Loading the configuration ...Loading ASM configuration...Can't call method "policy_name" on an < value at /ts/packages/PolicyHistory.pm line 71.ERROR: Failed during loading ASM configuration.Warning: There were one or more errors detected during installation.   Check the error messages and take the proper actions if needed.ERROR: UCS installation failed.Operation aborted./tmp/cofigsync.spec: Error installing package Config install aborted.Error running config sync pull.BIGpipe unknown query error:  01110001:3: Error running config sync pull

F5 Product Development tracked this issue as CR75012 and it was fixed in BIG-IP ASM 9.4.2. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

You can work around this issue by ensuring that the BIG-IP ASM system has created a version history for each security policy and marking each policy on the system as active. To mark the security policies as active, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Web Applications.
  4. Select the web application name for which you want the security policy to be active.
  5. In the Web Application Properties section, select the Active Policy check box.
  6. Click Update.

Repeat the above steps for each security policy configured on the BIG-IP ASM system.
