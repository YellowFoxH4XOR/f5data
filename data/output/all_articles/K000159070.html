Description

The administrtator is not able to access the tenant which was repeatedly and quickly provisioned and deployed

Repeated rapid deleting and re-creation of the tenant with the same name will result in the subsequent access failure to the tenant.

When the issue is happened, the following symptoms will be seen.

　1. Affected tenant state will show "running" and the running-state will show "deployed"

　 2. There is no actual VM running.

 

At affected environment, the following example may be seen.

appliance-1# show tenants

tenants tenant tenantname

state unit-key-hash xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx==

state type BIG-IP

state image BIGIP-15.1.8.1-0.0.3.T4-F5OS.qcow2.zip.bundle

state mgmt-ip 1.2.3.4

state prefix-length 24

state dag-ipv6-prefix-length 128

state gateway 1.2.3.5

state vlans [ 1 2 3 4 ]

state cryptos enabled

state vcpu-cores-per-node 26

state memory 93696

state storage size 142

state running-state deployed 　　　　　　　=============> Shows deployed

state appliance-mode disabled

state status Running 　　　　　　　　　　　　=============> Shows running

 

If the administrator attempt to re-create the same named tenant within 120 seconds, api-svc-gateway module of the platform log will record the log similar to the following example.

 

/qkview/subpackages/host-qkview/qkview/filesystem/var/F5/system/log$ more platform.log | grep api-svc-g

YYYY-MM-DDTHH:MM:SS.XXXXXX+00:00 appliance-1 api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000021 msg="delete api_client" tenant="tenantname".

YYYY-MM-DDTHH:MM:SS.XXXXXX+00:00 appliance-1 api-svc-gateway[12]: priority="Err" version=1.0 msgid=0x5804000000000002 msg="Client Subscription failed:" ERRMSG="Tenant client for the tenant "tenantname" no longer subscribed.".

YYYY-MM-DDTHH:MM:SS.XXXXXX+00:00 appliance-1 api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000004 msg="Platform-Tenant connection API:" MSG="End of tenant client subscription for the tenant "tenantname"".

YYYY-MM-DDTHH:MM:SS.XXXXXX+00:00 appliance-1 api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000004 msg="Platform-Tenant connection API:" MSG="Tenant client tenantname deregistration in progress".

YYYY-MM-DDTHH:MM:SS.XXXXXX+00:00 appliance-1 api-svc-gateway[12]: priority="Err" version=1.0 msgid=0x5804000000000003 msg="Client Deregistration failed:" ERRMSG="Tenant client tenantname not registered.".

 

Environment

Affected Product(s): F5OS F5OS-A

Known Affected Versions: F5OS-A 1.5.0, F5OS-A 1.5.1, F5OS-A 1.5.2, F5OS-A 1.5.3, F5OS-A 1.5.4, F5OS-A 1.7.0, F5OS-A 1.8.0, F5OS-A 1.8.1, F5OS-A 1.8.2, F5OS-A 1.8.3

 

Cause

F5 tracks this behavior as ID1342353

 

Recommended Actions

F5 recommend the workaround to wait at least 120 seconds between deletion and re-creation of tenant.

Re-creation of tenant should be use different tenant name.
