Known Issue

This is the result of a known issue. The /proc/ directory on a BIG-IP system contains a number of process directories in which information about a running process is stored. Process directories are named after a program's process ID (PID).

The following ls command output displays some of the process directories on a BIG-IP system:

ls -las /proc/
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 1
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 10
0 dr-xr-xr-x 3 mysql mysql 0 Dec 10 07:59 943
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 1008
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 1009
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 1011
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 1014
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 1019
0 dr-xr-xr-x 3 root root 0 Dec 10 07:59 1023

On some occasions, a running process disappears from the process table, and its corresponding process directory disappears from /proc/. When this issue occurs, the ps or top commands do not list a PID for the process, however the bigstart status command may indicate that it is running. Other observed symptoms differ depending on the missing process.

For example, if the mysqld process disappears from the BIG-IP ASM (or BIG-IP WebAccelerator) process table, and you attempt to perform a configsync operation, the configsync will fail, and error messages that appear similar to the following example are displayed on the console:

Loading ASM configuration...
/etc/rc.d/init.d/mysql: line 174: kill: (12428) - No such process
DBI connectmysql','root',...) failed: Can't connect to local MySQL server through socket '/var/lib/mysql/mysql.sock' (2) at /ts/tools/set_db_users.pl line 50
Can't call method "do" on an undefined value at /ts/tools/set_db_users.pl line 25.
DBI connect('DCC','root',...) failed: Can't connect to local MySQL server through socket '/var/lib/mysql/mysql.sock' (2) at /ts/packages//DbUtils.pm line 236
Can't call method "do" on an undefined value at /ts/tools/ts_configsync.pl line 141.
ERROR: Failed during loading ASM configuration.

If the mcpd process disappears from the process table on a BIG-IP system, attempting to install a UCS archive file will fail, and error messages that appear similar to the following example are displayed on the console:

Saving active configuration...
Current configuration backed up to /var/local/ucs/cs_backup.ucs.
Hostname of UCS file is bigip1.test.com, local hostname is bigip2.test.com
Installing shared configuration on host bigip2.test.com
Installing...
WARNING: Common DB data not merged.Reloading configuration... It may take a few minutes...

F5 Networks Product Development tracked this issue as CR101194 and it was fixed in BIG-IP version 9.4.6. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, WebAccelerator, and PSM Release Notes.
