Topic

Note: The behavior described in this article is the standard for all BIG-IP versions in the Applies to (see versions) list at the top of this page and for future versions of the BIG-IP software. This article will not be updated for future versions unless new information is discovered.

By default, the BIG-IP system accepts a TCP RST only when the sequence number in the RST packet matches the last acknowledged sequence number. For example, when an RST packet sent by a client matches the last acknowledged sequence number, the BIG-IP system accepts the RST packet and removes the connection from its connection table.

Description

When an RST packet sent by a client does not match the last acknowledged sequence number, but matches a sequence number in the receive window, the BIG-IP system drops the RST packet and does not remove the connection from its connection table. As a result, the connection can become stale, and may be used by a future connection attempt to the virtual server.

According to RFC793, an RST packet containing any sequence number in the receive window is acceptable. However, implementing larger window sizes makes it easier for remote attackers to guess TCP sequence numbers and cause a denial of service to TCP connections.

Note: For more information about the implications of using larger TCP window sizes, refer to CVE-2004-0230.

Beginning in BIG-IP 10.0.0, the tm.tcpallowinsecurerst database variable is added to allow you to configure the BIG-IP system to permit insecure TCP RST behavior and accept RST packets that match the sequence numbers in the receive window. Note: The tm.tcpallowinsecurerst database variable does not apply to FastL4 virtual severs.

Important: If you enable the tm.tcpallowinsecurerst database variable, the BIG-IP system is exposed to the security vulnerability described in K3126: Large TCP window sizes may make it easier to predict sequence numbers - CVE-2004-0230. F5 recommends that you leave the tm.tcpallowinsecurerst variable disabled to prevent the BIG-IP system from being exposed to this security vulnerability.

The BIG-IP system now processes TCP RST packets with sequence numbers in the receive window.
