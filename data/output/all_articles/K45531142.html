Description
OCSP gives error try again later.

When using SSL Forward Proxy (commonly used with SSL Orchestrator), BIG-IP staples an OCSP response to the certificate it creates with code tryLater.

Mozilla Firefox clients may show an error page indicating the following:

  • The OCSP server suggests trying again later.
  • Error code: SEC_ERROR_OCSP_TRY_SERVER_LATER

Environment

  • SSL Forward Proxy enabled
  • Server certificate validation disabled
    • On the Server SSL profile: Server Authentication -> Server Certificate set to ignore
  • OCSP configured for the Server SSL profile
  • ???????Trusted Certificate Authorities configured for Server SSL profile does not contain the CA of the certificate received from the server

Cause
When SSL Forward Proxy is configured with OCSP, it handles a TLS handshake where the client requests OCSP stapling using the Certificate Status Request extension, and the server either staples an OCSP response using a Certificate Status message or offers a certificate with AIA, BIG-IP attempts to generate an OCSP response for the client corresponding to the generated certificate.

If it fails to validate the certificate and response but still accepts the certificate (which occurs when server certificate validation is disabled), it generates an OCSP tryLater response, indicating a temporary failure.

Essentially, this OCSP status means SSL Forward Proxy received an untrusted certificate but is continuing anyway.

Recommended Actions

  • If the server's CA is untrusted, no action is required.
    • You may consider changing Server Certificate to require so that connections to untrusted servers fail.
  • If the server's CA should be trusted, add it to the bundle used for Trusted Certificate Authorities.
