Description

Unable to establish a connection when implementing a virtual server with Client Certificate Constrained Delegation (C3D).

Connection fails in a manner similar to the following example:

10.10.10.1 → 10.10.10.5 TLSv1   IN  s1/tmm2 : Client Hello
10.10.10.5 → 10.10.10.1 TLSv1.2 OUT s1/tmm2 : Server Hello
10.10.10.5 → 10.10.10.1 TLSv1.2 OUT s1/tmm2 : Certificate, Server Key Exchange, Certificate Request, Server Hello Done
10.10.10.1 → 10.10.10.5 TLSv1.2 IN  s1/tmm2 : Certificate, Client Key Exchange, Certificate Verify, Change Cipher Spec, Encrypted Handshake Message
10.10.10.5 → 10.10.10.1 TLSv1.2 OUT s1/tmm2 : Alert (Level: Fatal, Description: Unknown CA)

Transport Layer Security
    TLSv1.2 Record Layer: Alert (Level: Fatal, Description: Unknown CA)
        Content Type: Alert (21)
        Version: TLS 1.2 (0x0303)
        Length: 2
        Alert Message
            Level: Fatal (2)
            Description: Unknown CA (48)

Need to verify the C3D configuration.

Environment

  • Virtual Server
  • C3D
  • SSL/TLS

Cause

SSL handshake is failing client-side because BIG-IP is unable to validate the received certificate against its configured trusted CA.

Recommended Actions

C3D creates a forged copy of a received client certificate and sends it to the backend server during the server-side SSL handshake. A successful SSL handshake must first complete on the client-side of the connection before any server-side C3D operations can take place.

If Client Certificate is set to Require in the clientssl profile, then a client certificate is requested, and any certificate received must be valid. If Request is used, a client certificate is also requested, and the system will attempt to validate it, but the handshake will continue even if the certificate is not considered valid. It is recommended to use Require.

To configure C3D, first install a CA bundle that contains the necessary CA certificates needed to validate any expected client certificates. This is configured under Trusted Certificate Authorities in the clientssl profile, part of subsection Client Authentication.

Once the client-side handshake can be completed successfully, the C3D configuration will be used as configured. Refer to the following article for configuring elements of C3D:

  • K14065425: Configuring Client Certificate Constrained Delegation (C3D)

Additional Information

Here is an example C3D configuration:

ltm profile client-ssl /Common/test_clientssl {
    app-service none
    authenticate always
    ca-file /Common/main-clientCA <-------- Validates client certificate
    cert /Common/default.crt
    cert-key-chain {
        default {
            cert /Common/default.crt
            key /Common/default.key
        }
    }
    client-cert-ca none         <---------- This option is not required
    defaults-from /Common/clientssl
    inherit-ca-certkeychain true
    inherit-certkeychain false
    key /Common/default.key
    peer-cert-mode require      <---------- Client certificate required
    ssl-c3d enabled             <---------- C3D enabled
}
ltm profile server-ssl /Common/test_serverssl {
    app-service none                        For forged certificates:
    c3d-ca-cert /Common/test-clientCA      <-------- Signing CA cert
    c3d-ca-key /Common/test-clientCA-key   <-------- Signing CA key
    cert /Common/default.crt
    defaults-from /Common/serverssl
    key /Common/default.key
    ssl-c3d enabled             <---------- C3D enabled
}
