Known Issue

Description

HTTP pipelined POST connections to a virtual server may cause connections to fail.

This issue occurs when all of the following conditions are met:

  • An HTTP virtual server references an iRule that uses the HTTP::collect function
  • The client sends a subsequent pipeline HTTP POST request to the configured virtual server
  • The initial request and client reply is interceded by a client POST sent through a pipelined HTTP connection

The pipelined POST data will appear to be part of the client's initial request by the iRule. This will cause the iRule's HTTP::collect counter to increment. The BIG-IP LTM will drop the HTTP connection if the specified iRule data collect value is reached before the BIG-IP LTM receives the client's response for the initial request.

Impact

The BIG-IP LTM may drop the client's HTTP connection.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H380587 on the Diagnostics > Identified > Low screen.
  • Client HTTP requests may fail.
  • The client may need to resend the HTTP request.
  • An error message is present in the /var/log/ltm file. The message appears similar to the following example:

    Invalid action EV_FLUSH_PIPELINE during ST_HTTP_STOP_COLLECTING
