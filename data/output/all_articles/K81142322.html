Description

You disable all of the pools on a WideIP for a maintenance task. However the BIG-IP DNS provides dns responses for the disabled objects.
Note: To disable pools:  DNS > GSLB > Pools. 

Example:
The WideIP www.example.com has a single pool with two pool members, 192.168.0.100 and 192.168.0.200.
When this pool is manually disabled, the BIG-IP DNS still returns a reply to the DNS query:

# dig +short @10.0.0.1 www.example.com
192.168.0.100
192.168.0.200

Note: This also happens when all of the two pool members in this pool are disabled.

Environment

  • BIG-IP DNS/GTM
  • Bind
  • DNS profile
  • WideIP Pool

Cause

Functioning as design.
When you create a WideIP all pool members are added in the BIND configuration as A Record for the WideIP name. By default the DNS profile sets Unhandled Query Actions as allow, and Use BIND Server on BIG-IP as enabled. In this case, BIG-IP DNS will query local BIND with such configuration and returns all of the records in local BIND database.

Recommended Actions

You can configure how a WideIP responds to dns queries when all its pools are disabled. Please refer to the steps below:

  1. DNS > GSLB > Wide IPs > Wide IP List and click the wideip name
  2. Switch to the Advanced View and set enable on Return Code On Failure
  3. You may control what type of DNS response a BIG-IP DNS is going to return, for example, set NOERROR in RCODE
  4. Update to save the change

After the change, The BIG-IP will now return NOERROR response with empty DNS records.

Note:  The Load Balancing Methods used must allow the queries to fall through.  For example using Drop packet or Fallback IP would not respond with the configured Return Code.
