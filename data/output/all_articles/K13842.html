Known Issue

An iRule associated with a UDP virtual server using a server-side event may cause TMM to core.

This issue occurs when the following condition is met:

  • The iRule contains a DROP or REJECT statement within a server-side event in which the client-side connection may have already been closed.

Impact

TMMs may restart, causing BIG-IP system traffic to be disrupted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM processes generate core files.
  • The TMM log file contains a panic string similar to the following example:

    notice panic: ../dev/tcl/tcl.c:160: Assertion "tclrule ctx not in progress" failed.

Workaround

You may be able to work around the issue by modifying the iRule to avoid a scenario in which server-side information may be required after the client-side connection is closed.

For example, if a DROP or REJECT statement is used in an iRule, it should be under a client-side event, such as CLIENT_ACCEPTED, rather than a server-side event, such as LB_SELECTED.
