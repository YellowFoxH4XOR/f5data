Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K16932: Configuring the BIG-IP system to suppress sending SSL access and request messages to remote syslog servers

Note: Beginning in BIG-IP 11.0.0, the peer iControl SSL access and request messages discussed in this article are suppressed from local log files by default.

If a BIG-IP high-availability redundant pair has the Detect ConfigSync Status feature enabled, each unit in the pair sends periodic iControl queries to its peer to determine if the redundant pair configuration is synchronized. These iControl requests occur approximately every 30 seconds on each unit. Each inbound request generates an entry in both the local /var/log/httpd/ssl_access_log file and the /var/log/httpd/ssl_request_log file, which appears similar to the following examples, where 10.0.0.1 is the management IP address of the peer:

  • /var/log/httpd/ssl_access_log entry:

    logger: [ssl_acc] 10.0.0.1 - admin [04/Sep/2007:06:00:25 +0200] "POST /iControl/iControlPortal.cgi HTTP/1.1" 200 437

  • /var/log/httpd/ssl_request_log entry:

    logger: [ssl_req][04/Sep/2007:06:00:25 +0200] 10.0.0.1 TLSv1 DHE-RSA-AES256-SHA "POST /iControl/iControlPortal.cgi HTTP/1.1" 437

Note: The BIG-IP system also logs all Secure Sockets Layer (SSL) connections to the Configuration utility to these log files.

BIG-IP 9.4.2 and later

In BIG-IP 9.4.2 and later, you can customize the existing syslog configuration to filter out the log messages for iControl access from the peer, making it easier to find log messages from clients other than the peer.

Note: This procedure suppresses only locally logged messages. If you have configured a remote syslog server using the bigpipe syslog remote server <IP address> add command, the remote syslog server will continue to receive the log entries, although they are no longer logged locally. To suppress the log messages from being sent to the remote syslog server, perform the procedure described in K11723: Filtering log messages sent to remote syslog servers (9.4.x - 10.x), replacing the filter f_remote_loghost with the two filters stanzas defined in step 2.

Important: The following procedure will filter all access requests originating from the peer IP address. When you troubleshoot the communication state between units of a redundant pair, you should remove the filters to prevent filtering out useful debugging information. The steps for backing out the changes are included at the end of the procedure.

You can customize the syslog-ng configuration by performing the following procedure:

  1. Log in to the command line.
  2. To configure a syslog include entry, type the following command, replacing 10.0.0.1 with the peer IP address, as reported in the log messages you want to filter:

    Important: Running the following command overwrites the previous syslog include entry, if configured. If you want to maintain the current syslog include entry, combine the new and old entry into a single syslog include statement. To determine whether a syslog include entry is already configured, run the bigpipe syslog include command. Additionally, note the use of the single quotes used in this syntax.

    bpsh <<END
    syslog {
       include "

    log {
    source(s_syslog_pipe);
    filter(f_ssl_acc);
    destination(d_httpd_ssl_acc);
    };

    filter f_ssl_acc {
    not (facility(local6) and level(info) and match\\[ssl_acc\\]')) and
    not (facility(local6) and level(info) and match('\\[ssl_req\\]'));
    };


    filter f_local6_httpd_ssl_acc {
       facility(local6)
       and match('\\[ssl_acc\\]') and not match('\\] 10.0.0.1
    };

    log {
    source(s_syslog_pipe);
    filter(f_ssl_req);
    destination(d_httpd_ssl_req);
    };

    filter f_ssl_req {
    not (facility(local6) and level(info) and match('\\[ssl_req\\]')) and
    not (facility(local6) and level(info) and match('\\[ssl_acc\\]'));
    };


    filter f_local6_httpd_ssl_req {
       facility(local6)
       and match('\\[ssl_req\\]') and not match('\\] 10.0.0.1
    };

    "
    }
    END

  3. If the new logging configuration is working as expected, issue the following command to save the change:

    BIG-IP 10.2.2 and later

    bigpipe save all

    BIG-IP 9.4.2 through 10.2.1

    bigpipe save

    If the new logging configuration is not working as expected, return to step 2 and adjust the bpsh command to modify the logging options as necessary. Then proceed to step 3.

To remove all syslog include entries, run the following commands:

bigpipe syslog include none
bigpipe save

BIG-IP 9.0.0 through 9.4.1

In BIG-IP 9.0.0 through 9.4.1, you can customize the existing syslog configuration to filter out the log messages for iControl access from the peer, making it easier to find log messages from clients other than the peer.

Important: The following procedure will filter all access requests originating from the peer IP address. When troubleshooting the communication state between units of a redundant pair, the filters should be removed to prevent filtering out useful debugging information. The steps for backing out the changes are included at the end of the procedure.

You can customize the syslog-ng configuration by performing the following procedure:

  1. Log in to the command line.
  2. Change directories to the syslog-ng directory by typing the following command:

    cd /etc/syslog-ng/

  3. Back up the syslog.ng.conf file:

    cp syslog-ng.conf syslog-ng.conf.SOL9442

  4. Using a text editor, open the syslog-ng.conf file for editing.
  5. Locate the following filter definitions for SSL access and SSL request logging:

    filter f_local6_httpd_ssl_acc {
       facility(local6) and match("\\[ssl_acc\\]");
    };

    filter f_local6_httpd_ssl_req {
       facility(local6) and match("\\[ssl_req\\]");
    };

  6. Replace the middle line of each stanza with a similar filter, adding a no match condition for the peer IP address, as follows:

    filter f_local6_httpd_ssl_acc {
    ###   facility(local6) and match("\\[ssl_acc\\]");
       facility(local6) and match("\\[ssl_acc\\]") and not match("\\] 10.0.0.1");
    };

    filter f_local6_httpd_ssl_req {
    ###   facility(local6) and match("\\[ssl_req\\]");
       facility(local6) and match("\\[ssl_req\\]") and not match("\\] 10.0.0.1");
    };

  7. Close and save the file.
  8. Restart the syslog-ng process by typing the following command:

    bigstart restart syslog-ng

    Note: You can revert to the original configuration by copying the configuration backup file over the working configuration file and restarting the syslog-ng process.
