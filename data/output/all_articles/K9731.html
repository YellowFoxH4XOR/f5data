Known Issue

This is the result of a known issue. If you select the Auto-logon to applicable Terminal Servers using FirePass user logon credentials check box for a master group on the on the Application Access : Terminal Servers : Master Group Settings page, users in that master group are not automatically logged on to a Microsoft Terminal Server favorite if the Java client option is enabled for that favorite. 

Note: The Microsoft Terminal Services Java client was introduced in FirePass version 6.0.3.
 
Note: You can configure Terminal Server favorites on the Application Access: Terminal Servers: Resources page in the FirePass Administrative Console.
 
F5 Product Development tracked this issue as ID 296173 (formerly CR109323) and it was fixed in FirePass version 6.1.0. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue was fixed in cumulative hotfix HF-603-1 issued for FirePass version 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
 
For a list of current hotfixes, refer to K10322: FirePass hotfix matrix.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

 
Workaround
 
You can work around this issue by clearing the Java client check box in the Terminal Server favorite configuration, which enables the ActiveX version of the Microsoft Terminal Services client. The ActiveX client supports the auto-logon feature; however, it only supports Microsoft Window systems. Do not perform this workaround if you need to support Linux or Mac OS X client systems.
 
As an alternative, users can work around this issue by manually entering their logon credentials after launching a Java-based Microsoft Terminal Server favorite.
