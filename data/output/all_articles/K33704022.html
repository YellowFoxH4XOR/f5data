K33704022: How to collect supporting data for a BIG-IQ support case

Type
Support Solution
Published
2022-12-21
Updated
2025-03-04
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K33704022

Description

When facing issues with Device Discovery, Stats Collection, Backups, Application deployment and many more it is good to have collected proper data to speed up resolution of the service request.

Environment

  • BIG-IQ Centralized Management Cluster ( Centralized Management and Data Collection Devices)
  • BIG-IP Managed by BIG-IQ Centralized Management

Cause

None.

Recommended Actions

  • Discovery Issues of BIG-IPs or other issues like establishing HA and operations done on CM
  • Stats Collection issues
  • AS3 issues

 

  • For discovery issues of BIG-IPs or other issues like  establishing HA and operations done on CM ( Import, Discovery, Deployment etc ) following initial data set is required:
    • Note: All data should be collected just after reproducing the issue.  In specific situations we would like to have rest pcaps collected on loopback interface to see internal communication inside of a REST  ( Syntax for BIG-IQ Devices: 

      tcpdump -envi lo -s0 -A 'tcp port 8100' -w /var/tmp/bigiq_rest.pcap

      Syntax for BIG-IP Devices:

      tcpdump -vi lo -s0 -w /var/tmp/rest.pcap port 8100 

    • Qkview from BIG-IQ CM device ( use qkview command from bash terminal)
    • Qkview from affected BIG-IP device 
    • Collect screenshots of the issue ( Not only the error message but also whole BIG-IQ GUI screen where issue occurred)
    • Please use the following command at the command line to gather all of the log files into a single “tarball” file:
      BIG-IP and BIG-IQ:
      tar zcvf /var/tmp/"$HOSTNAME"_"$(date +%d-%m-%y)"_logs.tar.gz /var/log/* 

Note: BIG-IQ CM qkview usually contains full DB which helps reproducing issues internally or at least see similar error as end user experiencing 

  • For issues related to stats collection we should also include DCD qkviews and set of data would be following:
    • Qkview from BIG-IQ CM  and all DCDs ( use qkview command from bash terminal)
    • Qkview from affected BIG-IP device ( if the problem exists only on few devices not for all BIG-IQ cluster)
    • output of telnet showing that BIG-IQ Cluster communication is working and its not blocked (K15612: Connectivity requirements for the BIG-IQ system)
      • Full mesh communication on port 9300:
        • telnet <Data Collection IP Address> 9300  ( This should be verified in both directions from each CM and DCD)
      • DCD - BIG-IP communication on port 443 
        • telnet <discoveryIP> 443

 

  • For AS3 issues the same set of data is required as  in For discovery issues of BIG-IPs or other issues like  establishing HA and operations done on CM.  Its also good to have:
    • declaration used for deployment
    • output from curl -sk -u admin:<password> https://<BIG-IP IP address>/mgmt/shared/appsvcs/declare

 

Additional Information

In rare situations F5 support will require enabling REST debug according to K22244445: Enabling debug logging for restjavad in BIG-IQ
