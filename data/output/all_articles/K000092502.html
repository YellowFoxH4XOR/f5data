Cause
You usually get this error for one of two reasons. The first is that the owners of the webserver have properly set up access permissions and that you’re really not allowed access to the resource. The second reason is that the owners of the webserver have improperly set up permissions and you’re getting denied access when you really shouldn’t be.
Recommended Actions
  1. In previous cases most of the customers have resolved the issue immediately after "Disabling the security banner on the VMWare config"
  2. One specific customer said there was a change made recently on our Horizon View server to "enable Advanced Authentication (2-Factor Auth) with Radius for Duo integration". Obviously this change has added some extra login prompts/banners where you're prompted for Duo MFA options. 
    The following Duo article that explains how to integrate Duo with F5 APM: https://duo.com/docs/f5bigip

    After reviewing the View iApp's Reconfigure options, there does appear to be a section titled as follows:
    "Should the BIG-IP system support SecurID or RADIUS with AD two-factor authentication?"


    In the above screenshot of the iApp Reconfigure options shows the aforementioned option enabled, which then has some RADIUS option fields that need to be entered.
    Configure the iApp to enable the RADIUS option, there will be a new radius option added in the VPE workflow of my APM Access Policy, and that should solve the issue.
