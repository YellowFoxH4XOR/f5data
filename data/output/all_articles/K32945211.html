K32945211: BIG-IQ - Importing config stuck ''waiting for the cluster to sync'' in GUI

Type
Support Solution
Published
2022-09-16
Updated
2023-02-21
Applies to
  • BIG-IQ Platforms
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.X.X, 7.X.X, 6.X.X
  • BIG-IQ 7000
Source
https://my.f5.com/manage/s/article/K32945211

Description

Importing 2 devices into a silo - one device imports without issue. Other fails with credential failure. The imported device is now "Waiting for the cluster to sync", and due to this task running you are unable to address the credential failure for the failed device.
  • Yellow banner with warning 'The discovery process failed for 1 Device - View Details"
  • In the BIG-IQ GUI you see the following message under Services "Waiting for the cluster to sync"

Environment

Importing BIG-IP configurations into the BIG-IQ

  • BIG-IP HA Pair
  • BIG-IP HA that has already been discovered and re-importing or updating configurations on the BIG-IP

Cause

One of the BIG-IP HA members fails to import due to out of date or changed administrative password that has been changed on the BIG-IP and the BIG-IQ needs to be updated to use the new Admin password.

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. In the GUI of the BIG-IQ CM remove the BIG-IP's services
  2. Remove the 2-BIG-IP's from the BIG-IQ
  3. From the CLI (bash) of the BIG-IQ CM run the following command
       # bigstart restart restjavad
     
  4. On the Two BIG-IP's from the CLI (bash) run
       # tmsh restart restjavad noded
     
  5. From the BIG-IQ CM make sure to enter the updated password on the BIG-IQ for the BIG-IP's to be imported again
  6. From the BIG-IQ CM re-discover the two BIG-IP's and add services back
  7. Import configs
