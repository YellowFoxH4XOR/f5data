Description

Sometimes it is necessary to verify that a user provided password remains unchanged throughout Access Policy execution, when troubleshooting authentication failures suspected to be caused by a bad password being provided to the AAA  server.
The below process can be implemented in order to use mcget -secure {session.logon.last.password} Variable Assign and a Message Box to decrypt and display a password at different points in the Access Policy, while it's being executed for troubleshooting authentication issues

Example error messages:

Jan 30 15:53:40 BIG-IP-01 err apmd[xxxx]: 01490108:3: /Common/AccessPolicy:Common:12345678: RADIUS module: authentication with 'JohnSmith' failed: Access-Reject packet from host 10.10.10.10:1812
Jan 30 15:53:40 BIG-IP-01 info apmd[xxxx]: 01490058:6: /Common/AccessPolicy:Common:12345678: RADIUS agent: (logon attempt:0) authenticate with 'JohnSmith' failed

Environment

  • BIG-IP APM Access Policy that performs authentication using user supplied credentials.
  • Authentication failures suspected to be due to password corruption during Access Policy execution.

Cause

This document is provided to help determine the cause of authentication failures suspect to be due to password corruption during Access Policy processing.

Recommended Actions

Below is the process for creating a Variable Assignment object that creates a new Session Variable containing the decrypted form of the user provided password. And a Message Box to pause Access Policy processing and display the user's password as currently stored in the Session Variable session.logon.last.password. 

IMPORTANT! The objects created in the following instructions should NOT be left in place in a Production environment. Additionally you should review your security policies to ensure configuring these objects will not result in non-compliance of any such policy.

  1. Log in to the Configuration utility
  2. Navigate to the appropriate Access Profile/Policy and open the Policy in the VPE (Visual Policy Editor). 
  3. Just after the Logon Page object where the user enters their credentials, insert a new Variable Assign object with the following logic:  
    Customer Variable: session.custom.pass    =    Custom Expression: mcget -secure {session.logon.last.password}

  4. Then click OK to add the new Variable Assign object to the Access Policy.
  5. Just after the new Variable Assign object, insert a new Message Box object with the following logic: 
     Message: MB1 password: %{session.custom.pass}

  6. Then click OK to add the new Message Box object to the Access Policy.

Note: The above steps 2-5 should be performed to add additional instance of the Variable Assign & Message Box objects at various critical points in the Access Policy, such as just before any AAA Auth objects. Just be sure to use slightly different variable custom variable names to ensure that the Access Policy is not referencing variables stored earlier on in the Access Policy.

Once this has been completed. Apply the Access policy and a new APM Session can be initiated by the affected user. When the Access Policy reaches each Message Box, it will pause and display that Message Box and it's contents to the user who can verify whether or not the password still matches what they entered.
 


Clicking "Click here to continue" will resume the Access Policy execution until the next Message Box is reached, or the Access Policy completes. 
 

Additional Information

This can be done multiple times within the Access policy if necessary. Just make sure you use different variables or you will just present the same results.
