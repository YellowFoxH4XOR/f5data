Known Issue

In BIG-IP ASM 10.2.1, if you upgrade or reinstall the software, the configuration for BIG-IP ASM-enabled virtual servers may become corrupt.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM configuration has a User Defined Attack Signature Set assigned to a security policy.
  • A BIG-IP ASM configuration is either upgraded or reinstalled.
  • The pre-upgrade version of the configuration is one of the following versions:
    • BIG-IP-10.2.1
    • Hotfix-BIGIP-10.2.1-473.0-HF1
    • Hotfix-BIGIP-10.2.1-496.0-HF2
  • The target version of the reinstall or upgrade operation is one of the following versions:
    • BIG-IP-10.2.1
    • Hotfix-BIGIP-10.2.1-473.0-HF1
    • Hotfix-BIGIP-10.2.1-496.0-HF2

Impact

The BIG-IP ASM-enabled virtual servers will not pass traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Virtual servers with the BIG-IP ASM system enabled will not pass traffic.
  • The following two commands may return a different number of records in the account_id field:

    mysql -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "SELECT distinct(account_id) from DCC.ACCOUNTS;"

    mysql -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "SELECT distinct(account_id) from DCC.ACCOUNT_BLOCKING;"


    On an affected unit, the results of the previously-listed commands may return output that appears similar to the following examples:

    +------------+
    | account_id |
    +------------+
    | 1 |
    | 2 |
    | 3 |
    +------------+

    +------------+
    | account_id |
    +------------+
    | 1 |
    +------------+



    Notice that each command returns a different number of records in the account_id field.

Workaround

To work around this issue, you can re-apply all BIG-IP ASM polices, or restore the configuration from a unified computing system (UCS) archive. To do so, perform one of the following three procedures:

Impact of workaround: The system will apply any changes to the BIG-IP ASM policies that you have staged but not yet applied. You may lose any unsaved changes if you are restoring BIG-IP ASM policies from a previous UCS archive.

Re-apply BIG-IP ASM policies by using the Configuration utility

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to the Policies List screen in the Application Security menu.
  3. Select a policy from the Security Policies list.
  4. Click Apply Policy.
  5. If additional Web Applications exist, select the next item in the Change edited web application to drop-down menu, and the appropriate corresponding policy in the Change edited policy to drop-down menu.
  6. Click Go.
  7. When the Current edited policy is field displays the new policy name, click Apply Policy.
  8. For any additional web applications, repeat Steps 5 through 7.

Re-apply BIG-IP ASM policies by using the command line

  1. Log in to the BIG-IP ASM command line interface.
  2. Type the following command:

    for pl in $( mysql --batch -N -uroot -p`perl -MF5::GenUtils -e "print get_mysql_password.qq{\n}"` -e 'select active_policy_id from DCC.ACCOUNTS;' ); do echo "Setting active policy $pl" && /usr/share/ts/bin/set_active.pl -p $pl >/dev/null; done

Restore the configuration from a UCS archive

If you have a UCS archive that you created before you completed the upgrade operation, you can restore the configuration by installing that UCS archive on the affected system. For complete instructions for this process, refer to K11318: Backing up and restoring BIG-IP configuration files (10.x).
