Known Issue

A virtual server that uses TCP connection queuing and OneConnect may miscount for a pool with connection limits enabled.

This issue occurs when all of the following conditions are met:

  • Your configuration contains a virtual server that uses a pool with at least one pool member, which has a connection limit set, and also has the Request Queueing feature enabled.
  • The affected virtual server is configured with a OneConnect profile.
  • Incoming connection requests to the affected virtual server exceed the pool member connection limit.

Impact

All subsequent connection requests to the affected virtual server fail to connect, even when there are no connections in the queue.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H484966 on the Diagnostics > Identified > Medium screen.
  • Pool member connection limits are not properly counted, affecting incoming connection requests and the connection queue.
  • The connection count of pool members increments when the connection limit is reached and connections are queued. All subsequent connection requests to the affected virtual server fail.
  • After reaching the connection limit, the affected virtual server does not accept subsequent connection requests, permanently, even when the connection queue is empty.
