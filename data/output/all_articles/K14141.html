Known Issue

The BIG-IP ASM system may experience a memory leak in the asm_config_server process. This issue occurs when the following condition is met:

  • The BIG-IP ASM system is configured as a member of a device group

This issue occurs because the asm_config_server process sends large policy history files during synchronization and fails to release memory when it has completed.

Impact

Over time, you may see the system performance degrade and the system may eventually become unresponsive or reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H405694 on the Diagnostics > Identified > High screen.
  • The asm_config_server process memory allocation grows over time. You can monitor the memory usage for the asm_config_server process using the top utility. For example, the following top -p `pidof asm_config_server.pl` command output illustrates that the asm_config_server process memory allocation grew from 71.1 MB to 1.8 GB:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ P COMMAND
    12974 root 20 0 86.6M 71.1M 11.7M S 0.0 0.8 00:00:01.48 0 asm_config_serv

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ P COMMAND
    12974 root 25 5 2.6G 1.8G 3.3M S 0.0 23.0 01:44:01.71 0 asm_config_serv
  • The system swap file usage may increase as the asm_config_server process memory allocation grows. You can monitor the system swap file usage using the top utility.
  • Due to excessive memory usage, the asm_config_server process may produce a core dump.
  • In the event of severe system memory exhaustion, the Linux kernel may restart multiple processes and log error messages to the /var/log/kern.log file. The error messages appear similar to the following example:

    kernel: Out of memory: kill process 4515 (httpd) score 26667 or a child
    kernel: Out of memory: kill process 3225 (su) score 42812 or a child
  • The application security policies and configurations fail to be synchronized between members of an Application Security Device Group.

Workaround

To recover from this issue, you can restart the asm_config_server process. Restarting the asm_config_server process does not disrupt traffic processing by the BIG-IP ASM system. If the system is already experiencing severe memory exhaustion, you must reboot the system to recover it.

Restarting the asm_config_server process

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Restart the asm_config_server process by typing the following command:

    /usr/share/ts/bin/kill_asm_config_server.pl

Rebooting the BIG-IP ASM system

Impact of workaround: Rebooting will trigger a failover to the remaining members of the device group.

  1. Log in to the BIG-IP command line.
  2. Reboot the system by typing the following command:

    reboot
