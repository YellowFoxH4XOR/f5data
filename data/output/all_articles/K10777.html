Known Issue

This is the result of a known issue. When running a saved configuration file, a CIFS quorum disk configuration may fail to load with an error message that appears similar to the following example:

% ERROR: PASSWORD_LENGTH_TOO_LONG (38011091):
  The entered password was too long. The password must be 28 or less characters.

Additionally, an error message is logged to the error.log file that appears similar to the following message:

CLI-0-ERR-PASSWORD_LENGTH_TOO_LONG::The entered password was too long. The password must be 28 or less characters.

This issue will occur when the configuration contains a CIFS quorum-disk definition that has an encrypted-password value greater than 28 characters. For example:

quorum-disk \\192.168.10.1\vol1 cifs DOMAIN1\test encrypted-password G2kZIXM2vyqFJK3o1w351XyJ3t0KNYPR5k8oAc+FHam9noJRfieNWA==

The quorum disk password is encrypted when stored in the configuration file; therefore, the encrypted-password value may be more than 28 characters when the actual password is less than 28 characters.

Note: Configurations with an NFS Quorum disk definition are not affected by this issue.

F5 Product Development tracked this issue as ARX ID 31861 and it was fixed in ARX version 5.0.6. For information about upgrading, refer to the ARX release notes.

Workaround

Use the quorum-disk command to manually configure the CIFS quorum disk using the actual quorum disk password. For information about the quorum-disk command, refer to the ARX CLI Reference Guide.
