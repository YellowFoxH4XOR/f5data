When running BIG-IP version 9.4.x, the WebAccelerator module may not receive a sufficient allocation of memory resources in the default provisioning scenario. F5 recommends assigning additional memory resources to the host subsystem when running WebAccelerator version 9.4.x.

The following table lists the recommended additional amount of memory (in megabytes) that should be made available to the host subsystem:

PlatformRecommended additional amount of memory
3600 (C103)1536 MB

Note: Due to a known issue, the BIG-IP 3600 platform does not use all of the installed RAM when running version 9.4.7 or 9.4.8. The value displayed in this cell accounts for the aforementioned know issue. For more information, refer to K10600: The BIG-IP 1600 and 3600 platforms do not use all of the RAM installed.
3900 (C106)4096 MB
4500 (D43)no change needed
6400 (D63)2048 MB
6800 (D68)2048 MB
6900 (D104)4096 MB
8400 (D84)2048 MB
8800 (D88)2048 MB
8900 (D106)4096 MB

 Provisioning additional memory resources to the host subsystem

  1. Log in to the BIG-IP system command line.
  2. Modify the Provision.ExtraMB bigpipe database variable by typing the following command:

    bigpipe db Provision.ExtraMB <extra amount>

    For example:

    bigpipe db Provision.ExtraMB 1536
  3. Reboot the BIG-IP system by typing the following command:

    reboot

Important: If you plan to upgrade the BIG-IP system to version 10.x and roll forward your existing configuration, you should set the Provision.ExtraMB bigpipe database variable back to its default value of zero (0) before upgrading. The memory provisioning scheme was changed in BIG-IP version 10.x. As a result, any change made to the Provision.ExtraMB bigpipe database variable in version 9.4.x is not compatible with version 10.x, and may cause memory-related issues after upgrading to BIG-IP version 10.x. For more information, refer to K9985: Adjusting the memory allocation for the Linux host in BIG-IP version 9.x causes memory-related issues after upgrading to version 10.x.
