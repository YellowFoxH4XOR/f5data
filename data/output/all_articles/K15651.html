Known Issue

The DNAT utility (dnatutil) reports inconsistent results when parsing log files which contain information from multiple Traffic Management Microkernels (TMMs).

This issue occurs when the following condition is met:

  • The /var/log/ltm file contains messages from multiple TMMs for a particular Deterministic NAT (DNAT) subscriber connection.

    For example:

    err tmm[11787]: 01670019:3: DNAT configuration: src: 10.10.0.0/15
    err tmm[11787]: 01670019:3: DNAT configuration: dst: 10.100.112.0/22
    err tmm6[10943]: 01670019:3: DNAT configuration: src: 10.10.0.0/15
    err tmm6[10943]: 01670019:3: DNAT configuration: dst: 10.100.112.0/22

Impact

The dnatutil results are not consistent, and may contain duplicate reports for the same time stamp.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system produces inconsistent results when using dnatutil to parse logs.

Workaround

To work around this issue, you can remove all non-TMM0 log entries from the /var/log/ltm file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system.
  2. Filter the log messages in the /var/log/ltm file and send the results to a new log file, by using the following command syntax:

    # cat /var/log/ltm | grep 'tmm\[' > [file_name]

    For example, to remove all non-TMM0 log entries and send the results to file name dnat_tmm0 in /var/log, use the following command:

    # cat /var/log/ltm | grep 'tmm\[' > /var/log/dnat_tmm0
  3. Parse the new log file using dnatutil.
