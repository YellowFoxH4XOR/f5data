Known Issue

BIG-IP APM local user database accounts may be able to reauthenticate using invalid credentials.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy uses a local user database for authentication.
  • The user of a local user database authenticates using a case variation that does not match the case of their local user database user name.
  • The local user database account is deleted or the user's password is updated.

    When the user of a local user database authenticates to a BIG-IP APM access profile, the system stores the authenticated case-sensitive user name and password in cache. The system checks subsequent authentication attempts against the cache for a match before checking the local user database. When you delete or modify an account, the system purges instances of the case-sensitive user name from the cache. This behavior creates a scenario in which a user authenticates to an access profile using a case combination that differs from that of the configured user name in the local user database. Subsequent modifications to the user's account may not affect cached authentication information.

Impact

The user may be able to log on using invalid credentials.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H471257 on the Diagnostics > Identified > High screen.
  • A user with a deleted account cannot log on with their originally defined user name and password.
  • A user with a deleted account can authenticate when using the previously cached case variation of their user name and password.
  • A user with a password-updated account cannot log on with their defined user name and original password.
  • A user with a password-updated account can authenticate using the previously cached case variation of their user name and password.
  • When viewing local user database users, a previously deleted user is not listed.

Workaround

To work around this issue, you can normalize all user names to lowercase characters. To do so, perform the following procedure:

Impact of workaround: This procedure will disrupt traffic on your device. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Local User DB.
  3. Select the affected local user database.
  4. Ensure that user names are configured in all lowercase characters by deleting and recreating any user name that includes uppercase or mixed case characters.
  5. Navigate to Access Policy > Access Profiles > Access Profiles Lists.
  6. Open the visual policy editor by clicking Edit to the right of the Access Profile name.
  7. Click the + to the right of the Logon Page box.
  8. Select the Assignment tab.
  9. Click Variable Assign.
  10. Click Add Item.
  11. Click Variable Assign.
  12. Click the change link for rule one.
  13. Select Custom Variable.
  14. Enter the following text in the Custom Variable text box:

    session.logon.last.username

  15. Enter the following text in the Custom Expression text box:

    expr { [string tolower [mcget {session.logon.last.username}]] }

  16. Click Finished.
  17. Click Save.
  18. Click Apply Access Policy in the upper left corner of the visual policy editor.
  19. Log in to the command line of the affected BIG-IP APM system.
  20. To clear cached user name information, you can restart the TMM process by typing one of the following commands:
  • Restarting the TMM process with the bigstart command:

    bigstart restart tmm

  • Restarting the TMM process by rebooting the BIG-IP APM system:

    full_box_reboot
