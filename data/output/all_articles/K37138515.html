Known Issue

In certain scenarios, the Traffic Management Microkernel (TMM) restarts when the BIG-IP system erroneously sends packets that are not intended for the IPsec tunnel.

This issue occurs when the following condition is met:

  • Your BIG-IP system is configured with an IPsec tunnel.

This issue occurs because the system incorrectly associates internal packets with the IPsec tunnel as a nexthop.

Impact

TMM may restart without producing a core file, and fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H581073 on the Diagnostics > Identified > High screen.
  • In the /var/log/ltm file, you observe messages similar to the following example:

    notice mcpd[1234]: 01070406:5: Removed publication with publisher id TMM3
    crit tmm3[4567]: 01010020:2: MCP Connection expired, exiting
    warning tmm[4567]: 01230002:4: Interface 0.1: link is down
    notice promptstatusd[6269]: 01460006:5: semaphore tmm.running(1) held

  • In the /var/log/daemon.log file, you observe messages similar to the following example:

    emerg logger: Re-starting tmm
