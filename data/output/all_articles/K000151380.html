Description

On BIG-IP LTM devices configured in a high-availability (HA) device group, configuration synchronization (config sync) may fail with an error similar to:

A validation error occurred while syncing to a remote device - Sync error on <device>: Load failed from <peer> 01070110:3: Node address '<node>' is referenced by a member of pool '<pool>'.

The sync status displays "Sync Failed" and the error message indicates that a node address is still being referenced by one or more pool members.

Environment

  • BIG-IP LTM
  • pool using FQDN pool members (autopopulate enabled)

Cause

This issue is caused by a configuration mismatch between HA devices.

On LTM-1 node 10.10.10.10 was deleted, but this change wasn't synchronized and on the LTM-2 device this node is still existing.

When you created the FQDN pool member example.com, it was resolved to the same IP address as the one used used by deleted node - 10.10.10.10.  As a result, on LTM-1, new "_auto_10.10.10.10:port" pool member was created, but on the LTM-2, existing node has been used. Pool member on LTM-2 is "10.10.10.10:port".

When you try to synchronize configuration from LTM-1 to the group, it is not possible, because LTM-2 cannot delete node 10.10.10.10. It is currently used by a pool member.

Recommended Actions

To resolve the issue:

1) Disable auto-sync, if enabled.

2) Remove fqdn pool member example.com from LTM-2. As a result, pool member 10.10.10.10 will be deleted automatically.

3) Manually synchronize configuration from LTM-1.

Once done, ltm node 10.10.10.10 should be deleted successfully from LTM-2, and fqdn pool member example.com should be recreated (as it exists on LTM-1). A moment later you should also see a pool member "_auto_10.10.10.10:port" created on LTM-2.
