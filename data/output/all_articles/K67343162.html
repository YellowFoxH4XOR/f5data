Known Issue

 When SNMP traps are configured, the BIG-IP configuration may fail to load after an upgrade.

This issue occurs when all of the following conditions are met:

  • You have configured one or more SNMP trap destinations on a 10.2.x BIG-IP system.
  • You upgrade from 10.2.x to a version listed in the Applies to (see versions) box and roll forward the 10.2.x configuration, or you install a 10.2.x user configuration set (UCS) file to a BIG-IP system running a version listed in the Applies to (see versions) box.

Impact

The BIG-IP configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H608967 on the Diagnostics > Identified > High screen.
  • The Configuration utility displays a message indicating that the configuration has not yet loaded.
  • In the /var/log/ltm file of the affected system, you observe messages similar to the following example:

    localhost emerg load_config_files: "/usr/libexec/bigpipe base daol" - failed. -- BIGpipe parsing error (/config/bigpipe/bigip_sys.conf Line 81):    012e0010:3: The requested value (i192_168_1_1_1 {) is invalid (<trapsess list> | none) [add | delete]) for 'trapsess' in 'snmpd'

Workaround

After the configuration has failed to load following an upgrade or UCS install, you can remove the SNMP trap destination configuration by editing the /config/bigpipe/bigip_sys.conf file, and performing a manual configuration conversion and reload to recover. Alternatively, to prevent the configuration load failure from occurring, you can remove the SNMP trap destination configuration before you upgrade. Both procedures require that you re-create the SNMP trap destination configuration once the upgrade and/or configuration load are complete. To recover from or prevent the issue, perform one of the following procedures:

Note: As part of the upgrade process, the BIG-IP system converts the 10.x configuration to the 12.x style configuration. The system stores copies of a modified 10.x configuration in the /config/bigpipe directory on the 12.x system. These files are used only as the source for conversion and are not used for any other function on the system.

  • To recover from the issue, remove the SNMP trap destination configuration from the /config/bigpipe/bigip_sys.conf file, and perform a manual configuration conversion and reload
  • To prevent the issue, remove the SNMP trap destination configuration prior to upgrading

To recover from the issue, remove the SNMP trap destination configuration from the /config/bigpipe/bigip_sys.conf file, and perform a manual configuration conversion and reload

Impact of workaround: The system resets the SNMP trap destinations settings to the default values.

  1. Log in to the BIG-IP command line.
  2. To make a copy of the /config/bigpipe/bigip_sys.conf file, type the following command:

    cp /config/bigpipe/bigip_sys.conf /config/bigpipe/bigip_sys.conf.sol67343162

  3. Use a text editor to edit the /config/bigpipe/bigip_sys.conf file.
  4. Locate the snmpd stanza and the trapsess stanza within the file.

    For example:

     trapsess {
          i192_168_1_1_1 {
             auth password none
             auth protocol NONE
             community "example"
             engine id none
             host "192.168.1.1"
             port 162
             privacy password none
             privacy protocol NONE
             security level noAuthNoPriv
             security name none
             version 2c
          }
          i192_168_1_2_1 {
             auth password none
             auth protocol NONE
             community "example2"
             engine id none
             host "192.168.1.2"
             port 162
             privacy password none
             privacy protocol NONE
             security level noAuthNoPriv
             security name none
             version 2c
          }
       }

  5. Note the settings, as you will need to re-create the SNMP trap destinations after the configuration loads.
  6. Remove the entire trapsess stanza from trapsess to the stanza's close brace ( } ).

    Important: Make sure that you delete the correct closing brace for the entire trapsess stanza, or the conversion process will fail.

  7. Save changes to the file, and exit the text editor.
  8. To perform a manual conversion and reload of the configuration, type the following command:

    Important: You should use the following command only when instructed to do so in an article or by F5 Technical Support.

    /usr/libexec/bigpipe daol

  9. To save the configuration using the Traffic Management Shell (tmsh), type the following command:

    tmsh save sys config

  10. To reload the configuration using the tmsh utility, type the following command:

    tmsh load sys config

  11. Once the configuration has loaded, re-create the SNMP trap destinations using the settings previously noted in step 5.

To prevent the issue, remove the SNMP trap destination configuration prior to upgrading

Impact of workaround: The system will reset the SNMP trap destinations settings to the default values.

  1. Log in to the Configuration utility.
  2. Navigate to System > SNMP > Traps > Destination.
  3. Note the settings, as you will need to re-create the SNMP trap destinations after the upgrade.

    Note: You may need to use the command b snmpd trapsess list from the BIG-IP command line to display any non-default settings not shown in the Configuration utility.

  4. Select the check box at the top left corner of the list to select all SNMP trap destinations listed, and click Delete.
  5. Proceed with the upgrade.
  6. Once the upgrade has completed, re-create the SNMP trap destinations using the settings noted in step 3.
