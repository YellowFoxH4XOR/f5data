Description

There are a range of issues that can occur with an application when a bot defense profile is configured on a virtual server:

  • App flow issues like blank page is shown or error page.
  • User experience is affected like image are not shown or look-and-feel changes
  • Errors in the validation of the user input

Environment

  • Bot Defense profile
  • Application issues

Cause

None

Recommended Actions

1- Test different browsers and OS to check if a particular browser is affected like Safari, Chrome, Firefox, mobile OS, Windows, Linux or MacOS. Remember the bot-defense profile is designed to protect an app which clients use the most popular browsers. Not well-known are not tested and then, we cannot guarantee all security features work in those browsers.

2- Narrow the issue by determine which feature is causing the problem. Browser verification and Device ID Mode tend to be the most disruptive features for apps, this is caused by javascript (JS) code injected into the pages which may cause an erratic behaviour. Some apps don't support JS injections, it's recommended license anti-bot mobile application SDK or create a bot signature for the User-Agent in the request with Bot Category as Mobile App without SDK.

Please note, Mobile App without SDK uses User-Agent header to create a bot signature and this header can be spoofed easily, this is an insecure method to detect a mobile app. Then, the best solution is to license anti-bot mobile application SDK

About anti-bot mobile application SDK
https://techdocs.f5.com/en-us/bigip-17-0-0/big-ip-asm-implementations/working-with-the-anti-bot-mobile-application-sdk.html

3- Collect a HAR file in the browser and capture the browser console before and after the bot-defense profile is configured:

  • K10370211: Generate an HTTP Archive using a browser

4- A screenshot when the issue happens will point the exact request is being affected. A good example is the issue caused by ID795497 which non-english characters are displayed as gibberish because the meta tag <meta charset="utf-8"/> is included after the JS challenge. Then, characters are interpreted as ASCII, the error appeared either in the browser console or the HAR file:

  • Bug ID 795497: Wrong encoding of HTML when Bot Defense profile in use

5- Have a look Bot Requests in Security > Event logs > Bot Defense to see if any blocked request or alarm has been raised. In some occasions, some requests are blocked but are not shown to the user as they are executed in the background like AJAX requests, then, it should be determined if the app is a single page application and configure in the Browsers section:

  • K42323285: Overview of the unified Bot Defense profile
