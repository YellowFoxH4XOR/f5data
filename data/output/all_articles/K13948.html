Topic

This article applies to BIG-IP 11.x through 15.x. For information about other versions, refer to the following article:

  • K6064: Overview of the BIG-IP Path MTU Discovery (9.x - 10.x)

You can configure the BIG-IP system to participate in path maximum transmission unit (PMTU) Discovery, enforce PMTU, or obtain the maximum transmission unit (MTU) from route metrics.

Description

PMTU Discovery allows the BIG-IP system to send an Internet Control Message Protocol (ICMP) notification when the system requires packet fragmentation in order to pass through a link. Path MTU is defined as the smallest MTU for all of the links in a path.

The full path a packet takes may contain different segments with different MTUs specified. If a packet is larger than the MTU specified for the link and the Don't Fragment (DF) bit is set, the network device that received the packet drops the packet and issues an ICMP Fragmentation Needed message (Type 3 Code 4) to the sending device. This message contains the MTU size and instructs the sending device to send a smaller packet than the advertised MTU. The sending device then sends packets with the new MTU size, or smaller. The packet with the new MTU can then reach the client.

Note: You may be able to determine the Path MTU size of the hops along the path to a destination by using the tracepath -n <destination address> Linux command.

Path MTU Discovery on the BIG-IP system

By default, the BIG-IP system discovers the MTU that it can send over a path, without fragmenting packets. This feature is controlled by the TM.PathMTUDiscovery database variable and can be disabled. To do so, enter the following command from the command line:

tmsh modify sys db tm.pathmtudiscovery value disable

Path MTU enforcement for downstream devices

By default, the BIG-IP system proactively enforces PMTU on behalf of downstream network devices. When the BIG-IP system receives an ICMP Fragmentation Needed message, the system generates an ICMP Fragmentation Needed message on behalf of the downstream device and sends the message to the server.

When the BIG-IP system receives an ICMP Fragmentation Needed message (Type 3 Code 4) for an existing connection from a network device, the system updates the MTU for only that existing connection. The system does not update any other existing connections from the same device with the new MTU. The BIG-IP system updates the MTU for each of the existing connections only when it receives an ICMP Fragmentation Needed message from the network device for each connection. This behavior is by design.

Note: If an upstream device has been configured to block or rate limit ICMP packets including the ICMP Fragmentation Needed message and the BIG-IP system does not receive that message, the affected connection will appear to stall or time out. The BIG-IP system must receive the ICMP Fragmentation Needed messages for a connection it is handling in order to update the MTU for that connection.

Disabling Path MTU enforcement

The tm.enforcepathmtu database variable controls the PMTU enforcement feature on the BIG-IP system. When disabled, the BIG-IP system no longer observes ICMP Fragmentation Needed messages and continues to send oversized packets to endpoints that are unable to process the packets. To disable the PMTU enforcement feature and configure the system to transparently forward ICMP Fragmentation Needed messages and only generate ICMP Fragmentation Needed messages for packets that are too large for the BIG-IP system's configured MTU on the receiving interface, enter the following command:

Important: Disabling the BIG-IP system's PMTU enforcement may have adverse effects on traffic handling that requires a smaller MTU. Do not disable this setting unless F5 Technical Support recommends that you do so.

tmsh modify sys db tm.enforcepathmtu value disable

When the PMTU enforcement feature is disabled, the Route.Metrics.MTU database variable should also be disabled to prevent the BIG-IP system from obtaining MTU information from route metrics.

Managing MTU information from route metrics

Beginning in BIG-IP 11.0.0, you can obtain the current MTU size for a host by querying the route metric cache on the BIG-IP system. To do so, enter the following command:

tmsh show net cmetrics

You can also delete an entry from the route metrics on the BIG-IP system if you have determined that the MTU size is not optimal for a host. To do so, enter the following command:

tmsh delete net cmetrics dest-addr <host IP address>

To prevent the BIG-IP system from obtaining MTU information from route metrics, enter the following command:

tmsh modify sys db route.metrics.mtu value disable

This command is useful for routers that use NATs for multiple connections. Disabling route metrics prevents the BIG-IP system from assigning the same, or lower, MTU to all of the connections coming from the address that uses NAT, even though all of the connections through NAT can have various MTUs. The BIG-IP system can negotiate MTU requirements of each connection, separately.

Note: If the system prevents ICMP messages from reaching the offending host by not forwarding ICMP Fragmentation Needed messages, client or server application failures may occur.
