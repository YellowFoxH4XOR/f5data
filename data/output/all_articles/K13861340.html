K13861340: Relocating Elasticsearch data directory from /opt to /data

Published

Applies to

Source

Description

Relocating Elasticsearch data directory to /data partition from /opt partition.

  • Root partition disk usage is growing faster than expected and fill the disk space.

Environment

EMS

Cause

Due to the high volume of TDR or TRACE records, elasticsearch indexes can grow faster and fill the disk space.

Recommended Actions

Reconfigure the elasticsearch "data.path" to /data partition which has more disk space.

1. Stop elasticsearch service in EMS node.
#monit summary 
Take the correct naming from above output and replace the name when stop the service.
#monit stop <hostname>_elasticsearch_data
#monit stop <hostname>_elasticsearch_master

2. Makesure the services were stopped
#tail -f /var/log/elasticsearch_master/elasticsearch.log 
#monit summary

3. Move the /opt/elk to /data directory 
#mv /opt/elk/ /data/

4. Replace "path.data" in following configuration files
Edit the file and find "path.data" and change from /opt/elk/ to /data/elk/
#vi /srv/salt/<version>/elk/elasticsearch/elasticsearch_config_data 
#vi /srv/salt/<version>/elk/elasticsearch/elasticsearch_config_master 

#vi /etc/elasticsearch/elasticsearch_master/elasticsearch.yml 
#vi /etc/elasticsearch/elasticsearch_data/elasticsearch.yml 

Line 79, or find the line which has "/opt/elk" and replace to /data/elk
#vi /srv/salt/<version>/removeApplication/elk/undoInstall.sls 

Search "/opt/elk" and replace /data/elk (there will be two occurrences)
#vi /srv/salt/<version>/elk/install.sls 

5. Start service
monit start <hostname>_elasticsearch_data
monit start <hostname>_elasticsearch_master

6. Make sure the service started
#tail -f /var/log/elasticsearch_master/elasticsearch.log 
#monit summary

7. Repeat the above steps on second EMS node.
