Known Issue

The BIG-IP Virtual Edition (VE) instance may fail to retrieve the Instance Identity Document (IID) from the Amazon Web Services (AWS) metadata service.

This issue occurs when any of the following conditions is met:

  • Network traffic is blocked during the BIG-IP VE instance bootup; the traffic could be blocked by firewall rules on the instance.
  • The AWS metadata service may be temporarily unavailable.

Impact

The IID file is missing from the BIG-IP VE instance. If you are using the AWS Advanced HA iApp on your BIG-IP VE instance, the iApp fails to work as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The /shared/vadc/aws/iid-document file is missing from the BIG-IP VE instance.
  • The AWS Advanced HA iApp fails to work properly and logs error messages similar to the following example in the /var/log/ltm file:

    err aws_advanced_failover: Could not find value for instanceId in IID dictionary Failed to complete failover.
    err aws_advanced_failover: An exception of type instance with message 1 Failed to complete failover.

  • In the /var/log/ltm file, you observe error messages similar to the following example:

    err logger: /usr/libexec/aws/aws-failover-tgactive.sh (traffic-group-1): /shared/vadc/aws/iid-document is invalid. Re-download it from http://169.254.169.254/latest/dynamic/instance-identity/document
    err logger: /usr/libexec/aws/aws-failover-tgactive.sh (traffic-group-1): Instance sanity check failed with error:
    err logger: /usr/libexec/aws/aws-failover-tgactive.sh (traffic-group-1): Missing argument for option:region (use -h for usage)

Workaround

To work around this issue, you can manually run the /etc/vadc-init/aws-init script from the command line of the affected BIG-IP VE instance after you ensure that network traffic is not blocked and that the AWS metadata service is available. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP VE instance using a privileged account (for example, root).
  2. To run the script, type the following command:

    /etc/vadc-init/aws-init
