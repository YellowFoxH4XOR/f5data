Known Issue

The BIG-IP system does not back up performance graph data if the /shared/rrd.backup directory already exists. Therefore, if the system discovers that /var/rrd/*.info files are corrupt after a statsd process restart, the system does not perform a backup of the performance graph data as expected. As a result, the BIG-IP system starts over with new performance graphs and the previous data is irrecoverably lost.

This issue occurs when all of the following conditions are met:

  • One or more /var/rrd/*.info files are corrupt.
  • The /shared/rrd.backup directory exists.
  • The statsd process restarts for reasons such as a system restart, a system error, or manual intervention.

Impact

The system does not display the previous performance graph data, and you are unable to manually recover the data because it is no longer available.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Performance graphs display data that is available only since the last system restart or restart of statsd.
  • Performance graphs show no data after an upgrade.

Workaround

There is no workaround for this issue. However, you can view previous performance graph data from a qkview file if you generated the file before the /var/rrd/*.info file corruption and statsd restart. For more information, refer to K12878: Generating BIG-IP diagnostic data using the qkview utility.
