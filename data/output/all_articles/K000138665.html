K000138665: BlackHoleCluster logs when executing cross-namespace tests with sidecar injection enabled

Type
Support Solution
Published
2024-02-26
Updated
2024-02-26
Source
https://my.f5.com/manage/s/article/K000138665

Description

When trying cross-namespace communication with sidecar injection enabled in both namespaces (Eg. sleep.default -> httpbin.istio-sidecar2), the test fails, and the following logs are seen in the source pod: 

➜   kubectl exec -it sleep-5cc5b5cbf9-675vq -- curl -I http://httpbin.istio-sidecar2.svc.cluster.local:8000
curl: (56) Recv failure: Connection reset by peer
command terminated with exit code 56

[2024-02-26T22:19:55.983Z] "- - -" 0 UH - - "-" 0 0 0 - "-" "-" "-" "-" "-" BlackHoleCluster - 10.96.92.95:8000 10.244.1.40:57616 - -
[2024-02-26T22:32:25.257Z] "- - -" 0 UH - - "-" 0 0 0 - "-" "-" "-" "-" "-" BlackHoleCluster - 10.96.92.95:8000 10.244.1.40:40902 - -

Environment

1.14.x

Cause

One possible reason is that discoverySelectors is enabled in the mesh and the destination namespace (istio-sidecar2) is not labeled correctly.

By default, Istio watches all Namespaces, Services, Endpoints and Pods in a cluster. Starting with Istio 1.10, discoverySelectors was added as an option to MeshConfig, The discoverySelectors configuration enables users to dynamically restrict the set of namespaces that are part of the mesh.

For this test discoverySelectors was added in the override values file, the below means all namespaces that we want to make part of our mesh need to have the "istio-discovery: enabled" label in place:

meshConfig:
    discoverySelectors:
      - matchLabels:
          istio-discovery: enabled

Looking at the labels of istio-sidecar2, we don't see the label in place:

➜  kubectl get namespace --show-labels
NAME                 STATUS   AGE   LABELS
...
istio-sidecar2       Active   31m   istio-injection=enabled,kubernetes.io/metadata.name=istio-sidecar2

And if we inspect the listeners available to the sleep pod, we don't see any listeners with port 8000 (httpbin svc port):

➜  istioctl pc listeners sleep-5cc5b5cbf9-675vq | grep 8000
➜

Recommended Actions

Add the "istio-discovery: enabled" to the namespaces that you want to track in the mesh:

➜ kubectl label namespace istio-sidecar2  istio-discovery=enabled
namespace/istio-sidecar2 labeled

Additional Information

After labeling the namespace you should be able to see the port 8000 listener and the test should be successful:

➜ kubectl exec -it sleep-5cc5b5cbf9-675vq -- curl -I http://httpbin.istio-sidecar2.svc.cluster.local:8000
HTTP/1.1 200 OK

➜ istioctl pc listeners sleep-5cc5b5cbf9-675vq | grep 8000
0.0.0.0 8000  ALL                                                                      Route: 8000
