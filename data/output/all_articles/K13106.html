Known Issue

The BIG-IP system does not save the local IP option for the remote syslog server configuration into the /config/bigip_sys.conf file. This issue occurs when any of the following conditions are met:

  • You configure a remote syslog server with the local IP option using the bigpipe syslog remote server <name> { host <remote server IP> local ip <source IP> } command, followed by the bigpipe save command to save the configuration modification

    For example, you can configure the mysyslog remote syslog server with IP address 172.28.31.40 and source IP 192.168.1.1 by using the bigpipe syslog server mysyslog { host 172.28.31.40 local ip 192.168.1.1 } command, followed by the bigpipe save command to save the configuration modification

  • For BIG-IP versions 10.1.0 through 10.2.1, you configure a remote syslog server with the local IP option using the tmsh modify sys syslog remote-servers add { <name> { host <IP address> local-ip <source IP address> }} command, followed by the tmsh save sys config command to save the configuration modification

    For example, you can configure the mysyslog remote syslog server with IP address 172.28.31.40 and source IP 192.168.1.1 by using the tmsh modify sys syslog remote-servers add { mysyslog { host 172.28.31.40 local-ip 192.168.1.1 }} command, followed by the tmsh save sys config command to save the configuration modification

The local IP option allows the BIG-IP system to bind to the IP address when defined and use it as the source IP address when sending logs to the remote syslog server. When this issue occurs, the local IP option configured will not exist at the next configuration reload or a reboot.

Impact

The BIG-IP system sends logs to the remote syslog server using an unexpected administrative IP address.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system sends logs to the remote syslog server using any of the configured administrative IP addresses instead of the configured local IP address
  • The /config/bigip_syslog.conf file does not contain the local IP entry in the syslog configuration stanza
  • The remote syslog server configuration is missing the local IP option after the BIG-IP system is rebooted or the BIG-IP configuration is reloaded

Workaround

There is no workaround to this issue. However, if the local IP option is missing following a reboot or configuration reload, you can restore the configuration by performing the following procedure:

Impact of workaround: Since the local IP option does not persist across reboot or configuration reload, you have to re-perform this procedure after every reboot or configuration reload.

  1. Log in to the command line.
  2. Restore the local IP option by typing the following command:

    • tmsh command (BIG-IP versions 10.1.0 through 10.2.1)

      tmsh modify sys syslog remote-servers modify { <name> { local-ip <IP address> }}

      For example, you can restore the 192.168.1.1 local IP for the mysyslog remote syslog server by typing the following command:

      tmsh modify sys syslog remote-servers modify { mysyslog { local-ip 192.168.1.1 }}
    • bigpipe command

      bigpipe syslog remote server <name> { host <remote server IP> local ip <source IP> }

      For example, you can restore the local IP 192.168.1.1 for the mysyslog remote syslog server by typing the following command:

      bigpipe syslog remote server mysyslog { local ip 192.168.1.1 }
