Description

VIPRION host system is reporting that vCMP guest is low on disk space or no space.
Checking the vCMP guest does not show any low disk issues.


HOST /var/log/ltm:

err diskmonitor[14584]: 011d0004:3: Virtual Disk <guest name>.img/3 has only 24% free
or 
err diskmonitor[14584]: 011d0004:3: Virtual Disk <guest name>.img/2 has only 0% free

This message repeats every 10 mins.

Environment

  • VIPRION
  • vCMP guest
  • diskmonitor error message

Cause

Bug ID 771137

Recommended Actions

Attempt to resolve the diskmonitor messages by using the --sparse option against the specified image in the error message. In the above example - guest.img on blade 3

Note: Shutdown your vCMP guest before proceeding with the steps below and then re-deploy afterwards.

1. Copy the vmdisk image with --sparse option:
cp --sparse=always <guest_name>.img <guest_name_recover>.img
2. Take note of the file ownership and permissions:
ls -l <guest_name>.img
3. Make sure that the <guest_name_recover>.img file owner and permission are the same as with <guest_name>.img with chmod and chown commands
4. Delete the existing vmdisk file or to be on a safer side, download before deleting it:
rm -f <guest_name>.img
5. Rename the <guest_name_recover>.img to <guest_name>.img

Additional Information

It's important to know that a vCMP host deploys a sparse disk. As the disk usage grow on guest, so does the amount of physical space the disk occupies. Later in time when the disk space is reduced on guest, host would still hold the same disk space.
When you use the --sparse=always option with the cp command, it instructs cp to create sparse copies of files when possible.
It means that if the source file contains large sections of zeros, the destination file will be created as a sparse file, using the same zero-filled regions without actually allocating disk space for them.
This can save disk space, especially for large files that have empty or zero-filled sections.
