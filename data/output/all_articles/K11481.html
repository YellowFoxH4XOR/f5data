Known Issue

This is the result of a known issue. When configuring a Secure Sockets Layer (SSL) profile on the BIG-IP LTM system, you can use the default cipher string, DEFAULT, or you can specify a custom cipher list.

If you specify a custom cipher list, and the list exceeds 256 characters, the list is truncated after the 256th character and SSL handshake failures will occur.

For example, the following Client SSL profile contains a cipher string with 498 characters. The BIG-IP system loads the cipher string; however, SSL handshakes specifying any ciphers after the 256th character will fail. In the following configuration, SSL handshakes specifying ciphers following ADH-RC4-MD5 may fail:

profile clientssl client_ssl_test {
defaults from clientssl
key "default.key"
cert "default.crt"
ciphers "DHE-RSA-AES256-SHA:AES256-SHA:DH-RSA-AES256-SHA:DHE-RSA-AES128-SHA:RC4-SHA:AES128-SHA:DH-RSA-AES128-SHA:DHE-RSA-DES-CBC3-SHA:DES-CBC3-SHA:DH-RSA-DES-CBC3-SHA:RC4-MD5:DHE-RSA-DES-CBC-SHA:DES-CBC-SHA:DH-RSA-DES-CBC-SHA:ADH-AES256-SHA:ADH-RC4-MD5:ADH-AES128-SHA:ADH-DES-CBC3-SHA:ADH-DES-CBC-SHA:EXP1024-RC4-SHA:EXP1024-DES-CBC-SHA:EXP1024-RC4-MD5:EXP1024-RC2-CBC-MD5:EXP-EDH-RSA-DES-CBC-SHA:EXP-DES-CBC-SHA:EXP-DH-RSA-DES-CBC-SHA:EXP-RC4-MD5:EXP-RC2-CBC-MD5:EXP-ADH-DES-CBC-SHA:EXP-ADH-RC4-MD5:!SSLv2"
}

Resolution

F5 Product Development tracked this issue as IDs 435965 and 247986 (formerly CR140378). Beginning in BIG-IP 11.5.0, the limit has been increased to 768 characters. In addition, BIG-IP iHealth may list Heuristic H530599 on the Diagnostics > Identified > Medium screen. 

Note: For information about using SSL ciphers with the BIG-IP system, refer to K8802: Using SSL ciphers with BIG-IP Client SSL and Server SSL profiles.

Workaround

You can work around this issue by making sure the cipher list is less than 256 characters.
