Description

When BIG-IP is standby,  TMM core0 CPU is higher than other TMM. This doesn't occur on peer device when peer is standby.

  • TMM core0 CPU (20%-30%) higher than other TMM core (CPU lower than 15%)
  • DNS traffic distribution among all TMMs on standby device are even, so this is not related with traffic pattern
  • no error messages can be seen 

Environment

  • BIG-IP HA 
  • LTM and DNS provisioned for both devices
  • DNS traffic hits non-floating self IP

Cause

HA devices use different license. For instance, one uses 4600 license, and the other uses 4800 license. With 4600 license restrictions for CPU are set to 1200MHz, and it is expected to see TMM0 used a little bit more CPU than other cores. We can confirm this in lab. 

Recommended Actions

This is expected behavior when licenses are different on HA pair. As a matter of fact, this is an incorrect deployment. Refer to K13946: Troubleshooting ConfigSync and device service clustering issues, Device group members must have the same product licensing and module provisioning.
To rectify this situation, please use the same license for your HA pair.
