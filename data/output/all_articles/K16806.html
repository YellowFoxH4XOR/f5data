Topic

The BIG-IP APM system provides various functionalities for resetting Microsoft Active Directory (AD) passwords.

Description

The BIG-IP APM system supports the following functionalities for resetting AD user passwords:

  • The built-in AD Auth and AD Query functionalities for resetting expired AD user passwords
  • The option to change passwords from the logon page for resetting a password by user request

    Note: In the visual policy editor, the logon page policy item provides a check box with a Change Password label for display on the logon page. For more information on configuring the Change Password option see: K15676 Configuring the BIG-IP APM system to allow users with Active Directory to change passwords.

  • The ability to configure the maximum number of password reset attempts by using the Max Password Reset Attempts Allowed property of the AD Auth/AD Query agent in the visual policy editor

The password reset process in the BIG-IP APM system works in the following sequence:

  1. The BIG-IP APM system uses the client's user name and password to authenticate against the Microsoft AD server on behalf of the client.
  2. If the user password on the AD server has expired, or if the user selected the password change option in the logon page, the BIG-IP APM system returns a new logon screen to the user, requesting that the user change the password.
  3. If the Complexity check for Password Reset setting is enabled in the AD Auth/AD Query action of the access policy, the BIG-IP APM system must retrieve all related password policies from the domain to perform the appropriate verifications for the new password.
  4. After the user submits the new password, if the Complexity check for Password Reset setting is enabled, the BIG-IP APM system will first verify the new password against the previously retrieved AD password policy requirements.
  5. Next, the BIG-IP APM system attempts to change the password on the AD server. If this attempt is successful, the user's authentication is validated. If the password change attempt fails, the new password likely does not comply with the AD password policy.

Considerations for the 'Complexity check for Password Reset' setting

When the Complexity check for Password Reset setting is enabled, the BIG-IP APM system will use a Lightweight Directory Access Protocol (LDAP) searchRequest packet to attempt to retrieve the user's Distinguished Name (DN) by using the sAMAccountName attribute as a filter (sAMAccountName=<user name>). Therefore, if the user name (CN) entered in the BIG-IP APM system (during the login attempt) does not match the sAMAccountName attribute, the LDAP searchRequest packet will fail when retrieving the user DN.

As a result, the user cannot change their password and the BIG-IP APM system logs messages similar to the following example to the /var/log/apm file:

Session variable 'session.ad.last.errmsg' set to 'Password policy check error: can't get required user attribute'

Note: Enabling the Complexity check for Password Reset setting also significantly increases overall authentication traffic, because the BIG-IP APM system must retrieve password policies and user information by using the LDAP protocol to perform the appropriate verifications on the new password.

Recommendations

F5 recommends using the same value for the User login name (CN) and User login name (pre-Windows 2000) (sAMAccountName) attributes in AD.
