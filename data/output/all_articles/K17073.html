Issue

You should consider using this procedure under the following condition:

  • You suspect the BIG-IP system is experiencing a bridging loop. For example, you may have identified symptoms that indicate a possible bridging loop, such as saturated links, high backplane usage, redundant packets, and system instability.

Symptoms

As a result of a bridging loop, you may encounter the following symptoms:

Note: Any one of the following symptoms may indicate that a different issue exists. However, when multiple symptoms are observed at the same time, it is likely that the systems are experiencing a bridging loop.

  • One or more BIG-IP interfaces or trunks are saturated.
  • Your BIG-IP system is experiencing high backplane usage.
  • Your BIG-IP system is experiencing instability issues such as high CPU utilization.
  • Packet captures indicate redundant packets on the affected interfaces.

Recommended Actions

A bridging loop can occur when there are redundant paths between two network devices. Since Layer 2 (L2) bridging does not have any mechanism to track whether a network device forwards a packet multiple times, only one path should exist between two devices in the same L2 domain. In cases where redundant paths exist between L2 devices, the systems will forward the same packets to each other continuously, eventually causing the network to fail.

There are various issues that may cause a bridging loop, such as cabling or other hardware issues, a software misconfiguration or defect, or redundant network paths that exist between the devices. In most cases you can resolve issues related to redundant paths by configuring the Spanning Tree Protocol (STP).

The STP blocks redundant paths on a network, preventing bridging loops. If a blocked path is needed later because another path has failed, STP can clear the path again for traffic. The BIG-IP system supports the following STP protocols: Spanning Tree Protocol (STP), Rapid Spanning Tree Protocol (RSTP), and Multiple Spanning Tree Protocol (MSTP). When you enable an STP protocol on the BIG-IP system, the system sends bridge protocol data units (BPDUs) to peer devices for the purpose of learning the redundant paths and updating their L2 forwarding tables, accordingly. The systems elect a root bridge, build a spanning tree, and notify each other about changes in interface status. By default, the BIG-IP system uses Pass Through STP mode, which indicates that the system is not part of any spanning tree.

In most deployment scenarios, the BIG-IP system does not forward L2 traffic like a switch and will not cause a bridging loop. However, the BIG-IP system forwards L2 traffic in the following scenarios:

  • VLAN groups: A Virtual Local Area Network (VLAN) group is a feature that includes two or more distinct VLANs in the VLAN group. A VLAN group load balances traffic in a Layer 2 network. When using VLAN groups, you should verify that the VLAN group settings are defined correctly for your environment.
  • Forwarding (Layer 2) virtual server: The forwarding (Layer 2) virtual server evaluates the packet for processing and forwards the packet based on routing information.
  • Forwarding multicast / broadcast packets across VLAN interfaces: The BIG-IP system forwards multicast / broadcast packets across interfaces in the same VLAN. As a result, connecting two or more untrunked interfaces to the same VLAN may cause a bridge loop if STP is configured in Pass Through mode.

To identify symptoms related to bridging loops, and troubleshoot bridging loop issues, refer to the following sections:

Procedures

When experiencing bridging loop issues, you can use the following troubleshooting steps to determine the root cause:

  • Identifying a bridging loop
  • Breaking the bridging loop
  • Determining the cause of the loop

Identifying a bridging loop

Accurately identifying a bridging loop can help you more quickly resolve the issue and restore communication between network devices. To identify that a bridging loop is occurring, perform the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Reviewing system performance statistics

A bridging loop will have performance implications on the BIG-IP system and connected network devices. The performance issues should be noticeable when viewing statistics on the systems. For example, if a bridging loop is occurring on the network, the BIG-IP CPU utilization may near capacity.

You can view BIG-IP CPU statistics by running the following commands:

  • tmsh show /sys cpu
  • tmsh show /sys performance system

Reviewing interface and backplane statistics

If the BIG-IP system is being impacted by a bridging loop, you may observe an increasing number of output drops and collisions when viewing interface and backplane statistics. On VIPRION platforms, if the backplane is overrun with traffic, the system may experience issues with intra-blade communication which may result in failover events, reboots, or loss of traffic. To review the BIG-IP interface and backplane statistics, run the following command:

  • tmsh show net interface all-properties -hidden

Performing packet captures

To accurately identify a bridging loop, you may need to perform captures on the BIG-IP interfaces and look for signs of redundant packets on the affected interfaces. For example, if the system is experiencing an ICMP6 neighbor advertisement packet storm caused by incorrect cabling, the interfaces may be flooded with redundant packets that appear similar to the following example:

10:48:30.300120 IP6 FE82::222:E9FF:FE4D:D43 > FF02::1: ICMP6, neighbor advertisement, tgt is FE82::222:E9FF:FE4D:D43, length 32
10:48:30.300121 IP6 FE82::222:E9FF:FE4D:D43 > FF02::1: ICMP6, neighbor advertisement, tgt is FE82::222:E9FF:FE4D:D43, length 32
10:48:30.300122 IP6 FE82::222:E9FF:FE4D:D43 > FF02::1: ICMP6, neighbor advertisement, tgt is FE82::222:E9FF:FE4D:D43, length 32
10:48:30.300123 IP6 FE82::222:E9FF:FE4D:D43 > FF02::1: ICMP6, neighbor advertisement, tgt is FE82::222:E9FF:FE4D:D43, length 32

Use the following tcpdump syntax to specify an interface:

  • tcpdump -ni <interface>

Use the following tcpdump syntax to specify a VLAN:

  • tcpdump -ni <vlan>

For more specific examples and information about running tcpdump on the BIG-IP system, refer to K411: Overview of packet tracing with the tcpdump utility.

Breaking the loop

After you have established that the BIG-IP systems are experiencing a bridging loop, the next step is to break the loop and restore the network operation. To break the loop, you should look at the interface statistics and identify the interfaces with an increasing number of output drops and collisions. After you have identified the affected interfaces, you can perform one of the following actions to break the bridging loop:

  • Disconnect the cables from the affected interfaces.
  • Disable the affected interfaces.

    For example, use the following TMOS Shell (tmsh) syntax to disable the BIG-IP interface:

    tmsh modify /net interface <interface_number> disabled

Determining the cause of the loop

After you have stopped the bridging loop by disconnecting or disabling the affected interfaces, you can look for the root cause of the loop. To do so, use the following guidelines:

  • Review the network topology and look for any issues that may cause redundant paths. For example, cabling two or more untrunked interfaces to the same VLAN will likely cause a bridging loop if STP is configured in Pass Through mode.
  • If your environment requires Spanning Tree, verify that you have configured STP for the proper interfaces, and the systems are properly exchanging BPDUs. Also, verify that the systems have agreed on a common STP root.
  • Verify whether VLAN groups or Forwarding (Layer 2) virtual servers are configured on the BIG-IP systems. If so, you should confirm that the settings are defined correctly for your environment.
