K000141348: TMM goes into a restart loop and fails to start due to a failed initialization of the DPDK driver

Type
Support Solution
Published
2024-10-05
Updated
2024-10-05
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000141348

Description

TMM goes into a restart loop and fails to start.

tmctl tmm/xnet/device_probed indicates the dpdk driver failed initialization.

$ tmctl tmm/xnet/device_probed
id           available_drivers driver_selected driver_in_use       
------------ ----------------- --------------- --------------------------
0000:05:00.0 sock, dpdk,       dpdk            No (initialization failed)

/var/log/tmm keep showing the error log messages indicates the MTU is out of bounds.

notice EAL: PCI device 0000:05:00.0 on NUMA socket 0
notice EAL:   probe driver: 1af4:1041 net_virtio
notice dpdk[0000:05:00.0]: DPDK internal port_id 0
notice xnet_lib [pci:0000:05:00.0]: Device attach complete (MAC: 00:00:5E:00:53:00 Queues: 4/4)
notice xnet_lib [pci:0000:05:00.0]: Queue configuration complete (rx: 2/256 tx: 2/256)
notice virtio_mtu_set(): MTU should be between 68 and 1500
notice dpdk[0000:05:00.0]: Error: rte_eth_dev_set_mtu failed: err=-22
notice xnet[05:00.0]: Error: Command 0 failed: 5
notice xnet_lib [pci:0000:05:00.0]: Queue configuration complete (rx: 0/0 tx: 0/0)
notice xnet(1.2)[05:00.0]: Error: rx queue activation failed - cnt: 0 sz: 0
notice xnet(1.2)[05:00.0]: Waiting for tmm1 to reach state 4...
notice xnet_lib [pci:0000:05:00.0]: Error: Queues being cleared but not already configured
notice xnet_lib [pci:0000:05:00.0]: Error: Invalid queue configuration
notice xnet_lib [pci:0000:05:00.0]: Error: Queue configuration failed
notice xnet[05:00.0]: Error: Command 2 failed: 3
notice xnet_dev [0000:05:00.0]: Kernel driver successfully unbound
notice xnet_dev [0000:05:00.0]: Kernel driver successfully bound
notice ndal Error: Restarting TMM
notice Initiating TMM shutdown.

Environment

  • BIG-IP VE

Cause

This is caused by ID1492337 

Recommended Actions

You may consider the workaround below: 

  • Create or modify the file /config/tmm_init.tcl
  • Add below into the file /config/tmm_init.tcl
    • ndal mtu 1500 1af4:1041
  • Reboot
