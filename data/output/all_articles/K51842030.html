Description

  • You are trying to access an application through the Virtual Server address,  and it responds with "Connection Refused" even when all pool members attached to the Virtual Server are available
  • After disabling and re-enabling the Virtual Server, or applying any change to it, and updating, the issue gets fixed but it happens again randomly
  • You can see logs with the Virtual Server IP address related to possible address conflict, similar to this:
    warning tmm[PID]: 01190004:4: address conflict detected for <VS_IP_address> (00:aa:bb:cc:dd:cc) on vlan <vlan_ID>

Environment

  • Virtual Server
  • Address Conflict

Cause
SNAT address configured on another BIG-IP using the same address as Virtual Server that is refusing connections.
Note: The conflict IP can also be duplicated elsewhere, not only as a SNAT address, even other non F5 hardware

Recommended Actions

  1. Find the device causing the IP conflict with the MAC address shown on previous logs, you can do this with: tmsh show /sys mac-address
  2. Change the SNAT address on the other BIG-IP or other hardware to avoid the IP conflict.
