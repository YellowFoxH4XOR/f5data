Topic

You should consider using this procedure under the following condition:

  • You want to configure SYN cookie protection for the BIG-IP system.

Description

The BIG-IP SYN cookie feature protects the system against SYN flood attacks. The use of SYN cookies allows the BIG-IP system to maintain connections when the SYN queue begins to fill up during an attack. When the SYN Check Activation Threshold value is reached, the BIG-IP system responds to SYN requests by sending the SYN-ACK response that contains an encoded secret back to the client. The system then discards the SYN queue entry and waits for the ACK from the client. Certain BIG-IP platforms can perform hardware SYN cookie protection, while other platforms perform software-only SYN cookie protection.

Note: You must enable autolasthop for hardware SYN cookie protection to function. For more information, refer to K16887: Autolasthop must be enabled for hardware SYN cookie protection to function.

When you configure SYN Cookie protection, you may need to perform one or more of the following procedures:

Configuring SYN cookie protection

  • Modifying the SYN Check Activation Threshold setting
  • Modifying SYN cookie protection for a protocol profile
  • Modifying SYN cookie for collaborative hardware/software protection

Related actions

  • Verifying the SYN cookie status for a virtual server
  • Reviewing SYN cookie threshold log messages

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You can access the Configuration utility or TMOS Shell (tmsh).

Procedures

Modifying the SYN Check Activation Threshold setting

The SYN Check Activation Threshold setting indicates the number of new or untrusted TCP connections (those that have not yet completed the three-way TCP handshake) that can be initiated before the BIG-IP system activates the SYN Cookie authentication method for subsequent TCP connections. The default SYN Check Activation Threshold is 16,384 connections. To adjust the setting, perform one of the following procedures:

Using the Configuration utility to modify the SYN Check Activation Threshold

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Local Traffic > General.
  3. Under Properties, for SYN Check Activation Threshold, enter the value you want.
  4. Select Update.

Using tmsh to modify the SYN Check Activation Threshold

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the SYN Check Activation Threshold, use the following command syntax:

    modify /sys db connection.syncookies.threshold value "<value>"

    For example, to change the SYN Check Activation Threshold to 16000, enter the following command:

    modify /sys db connection.syncookies.threshold value "16000"

Modifying SYN cookie protection for a protocol profile

The following protocol profiles support SYN cookie protection:

  • TCP: Hardware SYN cookie protection is enabled by default in the TCP profile. If the platform does not support hardware SYN cookie protection, or hardware SYN cookie protection is disabled in the profile, the system uses software SYN cookie protection, which cannot be fully disabled.
  • FastL4: Hardware SYN cookie protection is enabled by default in the FastL4 profile. If the platform does not support hardware SYN cookie protection, or hardware SYN cookie protection is disabled in the profile, the system uses software SYN cookie protection. The FastL4 profile also allows SYN cookie protection to be fully disabled.
  • FastHTTP: Hardware SYN cookie protection is disabled in the FastHTTP profile, and the system uses software SYN cookie protection by default.

Important:  Software SYN cookie protection cannot be fully disabled for Standard type virtual servers as these do not support FastL4 profiles.

To modify the SYN cookie protection setting in the protocol profiles, perform one of the following procedures:

Using the Configuration utility to modify the SYN cookie protection setting in protocol profiles

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles.
  3. Select the Protocol tab and select one of the following protocols: FastL4, Fast HTTP, or TCP.
  4. Select the profile name.

    Note: F5 recommends that you create a custom profile rather than edit a default profile.

  5. Modify the SYN Cookie Protection setting by selecting or clearing the check box:

    For FastL4, Fast HTTP, and TCP: Clear the Hardware SYN Cookie Protection check box to disable hardware SYN cookie protection.

    For FastL4 profile only: Clear the Hardware SYN Cookie Protection and Software SYN Cookie Protection check boxes to completely disable SYN cookie protection.

  6. Select Update.

Using tmsh to modify the SYN cookie protection setting in protocol profiles

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the SYN cookie protection settings for a protocol profile, use the following command syntax:

    modify /ltm profile <protocol_profile> <profile_name> hardware-syn-cookie | software-syn-cookie enabled | disable

    FastL4, Fast HTTP and TCP profiles: To disable hardware SYN cookie protection for the TCP profile named tcp_custom, enter the following command:

    modify /ltm profile tcp tcp_custom hardware-syn-cookie disable

    FastL4 profile only: To disable software SYN cookie protection for the FastL4 profile named fastL4_custom, enter the following command:

    modify /ltm profile fastL4 fastL4_custom software-syn-cookie disable

  3. Save the configuration by entering the following command:

    save /sys config

Modifying SYN cookie for collaborative hardware/software protection

In BIG-IP 11.3.0 and later, the SYN cookie feature uses collaborative hardware/software SYN cookie protection for platforms that contain the High-Speed Bridge (HSB) chip. When the hardware SYN cookie feature is active, the system monitors relevant virtual servers and determines when to enable SYN cookie protection. You can configure this feature by modifying the pvasyncookies database variable. Perform the following procedure to modify the pvasyncookie variable. To configure other details of this feature and for more information about the pvasyncookies variable, refer to K14779: Overview of BIG-IP SYN cookie protection (11.3.x - 12.x)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the pvasyncookies variable, use the following command syntax:

    modify /sys db pvasyncookies.enabled value "<value>"

    For example, to enable the pvasyncookies variable, enter the following command:

    modify /sys db pvasyncookies.enabled value true

Note: The pvasyncookies.enabled setting reverts to its default value after you reboot or restart the mcpd process. If you modify its value to false, after each reboot or mcpd process restart, you must perform this procedure. For more information, refer to Bug ID 675431: Non-default value in db variable pvaSynCookies.enabled reverts to default value after reboot or mcpd restart.

Verifying the SYN cookie status for a virtual server

You can monitor the SYN cookie status for a virtual server, and determine whether the system has activated hardware or software SYN cookies by checking the Syncookie Status value for the virtual server. The possible values are as follows:

  • Off: The SYN cookie feature is not currently active for the virtual server.
  • Full Hardware: The SYN cookie feature is currently active for the virtual server, and the system uses the HSB chip to process the SYN cookies.
  • Software Syncookie Only: The SYN cookie feature is currently active for the virtual server, and the system uses the software to process the SYN cookies.

To verify the SYN cookie status for the virtual server, perform one of the following procedures:

Using the Configuration utility to verify the SYN cookie status for a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the virtual server name.
  4. Under General Properties, verify the current SYN cookie status.

Using tmsh to verify the SYN cookie status for a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To verify the SYN cookie status for a virtual server, use the following command syntax:

    show /ltm virtual <virtual_server_name> all-properties

    For example, to show the virtual server status for the virtual server named MyVirtual, enter the following command:

    show /ltm virtual MyVirtual all-properties

Reviewing SYN cookie threshold log messages

The BIG-IP system may log one or more error message that relates to SYN cookie protection to the /var/log/ltm file. To review the log messages, run the cat /var/log/ltm command from the BIG-IP command line. SYN cookie protection appears as follows:

  • When the SYN Check Activation Threshold is exceeded for a virtual server, the system logs an error message similar to the following example:

    warning tmm5[18388]: 01010038:4: Syncookie threshold 0 exceeded, virtual = 10.11.16.238:80

  • When hardware SYN cookie mode is active for a virtual server, the system logs an error message similar to the following example:

    notice tmm5[18388]: 01010240:5: Syncookie HW mode activated, server = 10.11.16.238:80, HSB modId = 1

  • When hardware SYN cookie mode is de-activated for a virtual server, the system logs an error message similar to the following example:

    notice tmm5[18388]: 01010241:5: Syncookie HW mode exited, server = 10.11.16.238:80, HSB modId = 1 from HSB
