K000135826: ICMP Echo option set to Selective still responds to ICMP Echo requests when the Virtual Server is unavailable

Type
Support Solution
Published
2023-09-20
Updated
2023-09-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000135826

Description

You have a Virtual Server with Notify Status to Virtual Address enabled and you are trying to control the response of one of your Virtual Servers to ICMP echo requests by changing the configuration from Local Traffic  ››  Virtual Servers: Virtual Address List  ››  My_Virtual_Server. On the Configuration menu, you configure ICMP Echo from Always to Selective as you want your Virtual Server to send ICMP Echo replies based on its availability.

When you try to simulate this Virtual Server going down by disabling its pool members and sending ICMP Echo requests for testing, you notice that you are still receiving Echo Replies from it (although the Virtual Server is unavailable). You change the ICMP Echo setting to different values and after clicking on Update you do not notice any change in this behavior.
 

Environment

  • Virtual Server, Virtual Address, ICMP Echo
  • LTM

Cause

This issue is due to Bug ID671261
 

Recommended Actions

The workaround can be found by following the steps described in K3230623: MCP does not recognize the 'Notify Status to Virtual Address' option when using the 'Selective' setting of ICMP echo

To further investigate, perform the following steps before submitting for Support:
  1. Connect to CLI.
  2. Take a packet capture and filter by the client IP address you are using for testing the behavior: tcpdump -nnvi 0.0:nnnp -s0 host <client_ip> -w /var/tmp/casenumber_$(date +%d_%b_%H_%M_%S)_$HOSTNAME.pcap
  3. Reproduce the issue once.
  4. Stop the packet capture by CTRL+C.
  5. Generate a fresh qkview file.
  6. Open a support case from the https://my.f5.com Support Portal and provide those pieces of data.
