Known Issue

The sod process monitors only the first 12 Traffic Management Microkernel (TMM) instances. If the thirteenth or greater TMM instance enters an indefinite loop, the sod process does not detect this fault, and the TMM continues to loop indefinitely.

Impact

Some TMM instances may loop indefinitely. The BIG-IP system may stop processing traffic, and neglect to fail over to another system in the device group.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H439239 on the Diagnostics > Identified > High screen.
  • The BIG-IP system stops processing traffic.

Workaround

To work around this issue, you can modify the daemon.conf file to activate monitoring on the thirteenth TMM process and processes thereafter. To do so, perform the following procedure:

Important: You must edit the daemon.conf file on one blade and then manually synchronize it to the other blades in the cluster. This configuration change will persist beyond a reboot, but will not persist beyond an upgrade.

Impact of workaround: The BIG-IP system temporarily goes offline; you should perform this procedure during a maintenance window.

Note: This procedure requires that you temporarily remount the /usr file system in read-write mode. For more information, refer to the Supplemental Information section at end of this article.

  1. Log in to the BIG-IP command line as the root user.
  2. Determine the number of TMM instances and their statuses by typing the following command:

    tmsh show sys ha-status all-properties | grep "daemon-heartbeat" | grep tmm

    1 daemon-heartbeat tmm23 restart no no no 2.1K tmm23 0

    This example shows 24 TMM instances in total, of which only the first 12 have the go-offline-downlinks-restart feature enabled.

  3. Remount the /usr file system in read-write mode on all the active blades by typing the following command:

    clsh mount -o remount,rw /usr

    Note: The cluster shell command (clsh) is used to execute a single command across all blades in a VIPRON device.

  4. Use a text editor, such as vi editor, to modify the /defaults/daemon.conf file and locate the entry that looks similar to the following example:

    sys daemon-ha tmm11 {
    heartbeat enabled
    heartbeat-action go-offline-downlinks-restart
    running enabled
    running-timeout 2
    }

  5. After the previously-described entry, add a new entry for each additional TMM from tmm12 to the maximum number of TMMs available on your system. For this example, creating entries for tmm12 through tmm23 appears similar to the following example:

    sys daemon-ha tmm12 {
    heartbeat enabled
    heartbeat-action go-offline-downlinks-restart
    running enabled
    running-timeout 2
    }

    sys daemon-ha tmm13 {
    heartbeat enabled
    heartbeat-action go-offline-downlinks-restart
    running enabled
    running-timeout 2
    }

    Add a new entry for each TMM up to and including tmm23.
  6. Save the changes in your editor.
  7. Determine the number of active blades in the cluster by typing the following command.

    tmsh show sys cluster | grep running

    For example:

    # tmsh show sys cluster | grep running

    | 1 10.10.10.9 available enabled true active running Run
    | 2 10.10.10.8 available enabled true active running Run
    | 3 10.10.10.7 available enabled true active running Run
    | 4 10.10.10.6 available enabled true active running Run

  8. Copy the modified /defaults/daemon.conf file to all active blades in the cluster by using the following command syntax:

    for i in {<#>..<#>}; do scp /defaults/daemon.conf slot$i:/defaults/daemon.conf; done

    Replace the <#> with the beginning and ending blade IDs. For example:

    for i in {1..4}; do scp /defaults/daemon.conf slot$i:/defaults/daemon.conf; done

  9. Remount the /usr file system in read-only mode on all the active blades by typing the following command:

    clsh mount -o remount,ro /usr

  10. From the BIG-IP command line, activate the changes by typing the following command:

    tmsh load /sys config partitions all
