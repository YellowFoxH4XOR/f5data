Known Issue

The BIG-IP system erroneously allows you to create an invalid interface. The interface does not exist physically, and you should not use it to configure any VLANs or trunks.

This issue occurs when any of the following conditions are met:

  • You use command syntax similar to the following:

    bigpipe interface <x>/<y.z> <option>

    In the previous example, note the following:

    • <x> is an invalid slot number
    • <y.z> is an invalid interface number
    • <option> is an available option for the bigpipe interface command

    For example:

    bigpipe interface 9/10.11 media 100baseTX full

  • The invalid interface configuration stanza exists in the /config/bigip_base.conf file. This issue usually occurs if you save the running configuration after creating the invalid interface using the command described previously.

    For example:

    interface 9/10.11 {
    media 100baseTX full
    }

Impact

If the invalid interface is assigned to a VLAN or trunk, the interface does not pass traffic. If the invalid interface is not assigned, you can safely ignore this issue.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Running the bigpipe interface command displays the invalid interface in the list of interfaces.
  • The invalid interface shows up on the Network > Interfaces > Interface List page in the Configuration utility.

Resolution

Status

Note: The issue described in this Solution does not apply to BIG-IP version 11.x, as the bigpipe command has been removed beginning in version 11.0.0.

Workaround

To recover from this issue, you can remove the invalid interface and reboot the BIG-IP system. To do so, perform the following procedure:

Impact of workaround: If the BIG-IP system is the active member of a redundant system, rebooting causes a failover. If the BIG-IP system is a standalone unit, rebooting interrupts traffic processing.

  1. Log in to the command line.
  2. Edit the /config/bigip_base.conf file using a text editor of your choice.
  3. Remove the invalid interface configuration stanza, if one exists, and save the modifications.

    Using the example in the Description section, you would remove the following configuration stanza:

    interface 9/10.11 {
    media 100baseTX full
    }

  4. Create a null file with the filename forceload in the /service/mcpd directory by entering the following command; this forces the mcpd process to reload the configuration:

    touch /service/mcpd/forceload

  5. Reboot the BIG-IP system by entering the following command:

    reboot
