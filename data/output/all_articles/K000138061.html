Policy Information

F5 is committed to responding quickly to software issues in F5 products. F5 may provide temporary code patches or engineering hotfixes to address issues between normal new Major, Minor, and Patch software releases. F5 produces engineering hotfixes only for customers who have active contracts with F5 Global Support or F5 Premium Plus Support. While F5 endeavors to release the most stable code possible, engineering hotfixes do not undergo the extensive QA assessment of scheduled software releases. F5 offers engineering hotfixes with no warranty or guarantee of usability.

The issues addressed by engineering hotfixes are included in the next software release of the affected product if the hotfix has completed a full QA regression analysis. Once F5 has included a fix in released code, any engineering hotfix already coded will be available for 30 days after the release date of the release containing the fix. F5 will not produce new engineering hotfixes for a software defect that has already been addressed in a software release.

F5 recommends that customers update or upgrade software to take advantage of CVE fixes, hardening, and new functionality included in the released version. An update involves installing a more recent patch release on the same code branch (for example, updating from F5OS-C 1.6.0 to 1.6.1). An upgrade involves installing a more recent code branch (for example, upgrading from F5OS-C 1.5.1 to 1.6.1).

Supported Major, Minor, and Patch releases within their Standard Support Phase are eligible for the critical issue hotfix process. For more information about Major, Minor, and Patch release numbering, refer to K21501912: Software lifecycle policy for F5OS.

Note: Engineering hotfixes will be created for only the most recent patch release of the eligible versions.

F5 reserves the right to decline requests for the creation of an engineering hotfix without citing cause. The only issues that F5 considers for the critical issue hotfix process are those that do not possess simple configuration workarounds and demonstrate definite impact on customers' business.

F5 endeavors to create engineering hotfix packages that address as many issues as possible at the time of creation for a specific product. Cumulative hotfixes for F5OS software branches are roll-ups of all available hotfixes that are considered stable.

For information about F5 supported hardware and software versions, refer to the following articles:

  • K86001294: F5OS hardware/software support matrix
  • K21501912: Software lifecycle policy for F5OS

For information about software issues that affect the security of an F5 product, such as CERT advisories, refer to K4602: Overview of the F5 security vulnerability response policy.
