Description

If you configure ZebOS in one of the HA pair and sync the configuration to the peer device, the ZebOS config fails to sync to the peer device. 

Environment

  • Configured device trust.
  • Configured  Sync Failover group.
  • ZebOS

Cause

Active/Standby pairs are typically configured as 2 separate routers for dynamic routing which means that the ZebOS configuration file /config/ZebOS.conf typically contains per-unit configuration items (e.g. router-id) and synchronization with peer is undesirable.


Recommended Actions

  1. To view the configuration in ZebOS:
    imish -e 'show run'
  2. To view the configuration in tmsh, type:
    tmsh list net routing
  3. To ensure that the routes made their way into ZebOS:
    imish -e 'show ip route'
  4. To verify that you are once again in an established state with the neighbor:
    tmsh show net routing
  5. To save the configuration in ZebOS:
    imish -e 'write memory'

Additional Information

BIG-IP 11.x software introduced the device group feature. A device group is a collection of BIG-IP devices that are configured to securely synchronize their BIG-IP configuration data, and fail over when needed. A Sync-Failover device group contains devices that synchronize configuration data and support traffic groups for failover purposes.

However, not all device configuration will sync over automatically, some configuration object needs be configure individually per a device.

For example, when you enable dynamic routing on a specific route domain, the BIG-IP system creates a dynamic routing instance. This dynamic routing instance is made up of the core dynamic routing daemons (imi and nsm), as well each relevant dynamic routing protocol daemon. Thus, each dynamic routing instance for a route domain has a separate configuration. You manage a dynamic routing configuration using the IMI shell (imish).

If you don't configure each units individually, you may run into issue during failover, where newly active unit fail to establish peer relationship with peer and hence start dropping the traffic or may route them incorrectly because it didn't have the saved zebos routing configuration. 

In order to prevent this, you need to ensure routes are configured individually per a device, and saved.
