Known Issue

Captive portal detection may disconnect network access sessions if a client proxy is configured.

This issue occurs when all of the following conditions are met:

  • Network access is configured to route all client IP traffic to a network access tunnel using one of the following options in the network settings:
    • The Force all traffic through tunnel option is enabled.
    • The Use split tunneling for traffic option is enabled and configured with a wildcard address space, such as 0.0.0.0/0.0.0.0.
  • The proxy configured in the network access network settings redirects requests to http://www.f5.com/apps/all/avail.txt and http://www.msftncsi.com/ncsi.txt.

Impact

The BIG-IP Edge Client incorrectly detects the presence of a captive portal and may periodically disconnect the active Network Access session.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are disconnected repeatedly from active network access sessions.
  • You view messages in the BIG-IP Edge Client report logs that appear similar to the following example:

    f5Report.html:2014-03-11,10:16:34:393, 5944,3840,Standalone, 48, , 2095, CStandaloneDoc::OnFavoriteReconnect, Detecting captive portal
    f5Report.html:2014-03-11,10:16:35:496, 5944,3840,Standalone, 0,,,, Temporarily disconnecting resource /Common/apm_network_access in order to show captive portal page
    f5Report.html:2014-03-11,10:16:35:790, 5944,3840,Standalone, 0,,,, Resource /Common/apm_network_access disconnected, going to show captive portal page
    f5Report.html:2014-03-11,10:17:22:959, 5944,3840,Standalone, 0,,,, Detected captive portal

  • Traffic captures show unsuccessful requests from the client to http://www.f5.com/apps/all/avail.txt or http://www.msftncsi.com/ncsi.txt.

Resolution

Status

F5 Product Development has assigned ID 425377 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles

Workaround

To work around this issue, you can configure the proxy to allow requests to http://www.f5.com/apps/all/avail.txt and http://www.msftncsi.com/ncsi.txt, or disable BIG-IP Edge Client captive portal detection on the client. To disable captive portal detection, refer to K14766: Disabling BIG-IP Edge Client captive portal detection.
