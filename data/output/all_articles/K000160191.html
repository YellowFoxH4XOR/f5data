K000160191: Intermittent HTTPS Health Monitor Failures on BIG-IP LTM v17.5.1.3

Type
Support Solution
Published
2026-03-01
Updated
2026-03-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160191

Description

Intermittent failures occur with HTTPS health monitors on BIG-IP LTM pools, causing pool members to remain in a DOWN state even though backend services are confirmed operational. The issue is temporarily resolved by switching the health monitor to TCP_HALF_OPEN and then reverting back to HTTPS, which brings pool members to an UP state.

Environment

  • Product: BIG-IP LTM
  • Product Group: BIG-IP
  • Version: 17.5.1.3 Build 0.1.19
  • Health monitor type: HTTPS (443)
  • Recent actions: Manual change of health monitor from HTTPS to TCP_HALF_OPEN and back to HTTPS to restore pool member status

Cause

Bug ID 1987309

Answer/Recommended Actions

  • Upgrade BIG-IP LTM systems to a version containing a fix for Bug ID 1987309.
    • Review monitor configuration and logs for any additional symptoms or patterns if the issue persists after upgrade.
  • If immediate upgrade is not possible, use the following temporary workaround:
    1. Change the health monitor for affected pool members to TCP_HALF_OPEN.
    2. Confirm pool members transition to UP state.
    3. Revert the monitor back to HTTPS.

Additional Information

  • The issue is related to the bigd process potentially getting stuck in legacy mode, causing HTTPS monitors to fail until the monitor is detached and re-attached.
  • The workaround resets the monitoring process, but the upgrade is the permanent solution.
