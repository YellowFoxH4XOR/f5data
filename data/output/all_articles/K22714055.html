Issue

Description

CPU usage is categorized per plane by data plane (Traffic Management Microkernel), control plane, and analysis plane. The amount of CPU consumption categorized to the data plane is correct, as is the sum of CPU consumption for the control and analysis planes. The ratio of CPU consumption between the control and analysis planes may not always appear accurate because the statistics are designed to show consumption by CPU.

Environment

CPU per plane categorization, which includes analysis plane, is present in the following BIG-IP device configurations:

  • vCMP not provisioned
  • vCMP guests

vCMP hosts do not have per-plane CPU usage as their resources are provided to vCMP guests. BIG-IP Virtual Edition (VE) does not currently have per-plane CPU usage.

Cause

Every CPU core is designated as data, control, or analysis with all of its usage placed into the core's designated category. Every even-numbered core is designated data plane, every odd-numbered core is designated control plane, and the highest odd-numbered core analysis plane. Analysis plane-related processes are generally pinned to the highest odd-numbered core and no control or analysis process have access to the even cores. The processes pinned to the analysis plane typically consume all available CPU cycles when running, which is why they are assigned to a single, specific core.

The lower the number of cores in the BIG-IP system, the higher the probability that unpinned control plane processes can run on the highest odd-numbered core, resulting in their CPU usage being tracked as analysis plane. Any analysis plane-related processes which are not pinned to the highest odd-numbered core may run on the control plane designated core(s), resulting in their CPU usage being tracked as control plane.

Because the goal of the statistics is to show consumption per CPU, any processes consuming cycles on the CPU labeled analysis are still consuming cycles on that CPU, and, therefore, the total amount of usage for that CPU is shown rather than just the usage on that CPU solely by analysis plane processes.

Recommended Actions

Use the per-plane CPU statistics to determine which plane and which CPUs are being heavily consumed for troubleshooting purposes as well as future capacity planning. Monitor the aggregate of control and analysis planes to determine total Linux userland CPU consumption. Examine CPU usage per process for more detailed CPU consumption at process level.
