Description

Responses to DNS queries for wideips may return a NXDOMAIN or some other unexpected response when multiple GTM pools are associated with the wideip object.

This is due to the way GTM load balancing operates when selecting a member from a GTM pool.  The load balancing method on the pool is first considered, and if no pool member is found using that method, then the 'alternate' method will be used (default 'none'), and finally the 'fallback' method.    The default fallback-mode is 'Return to DNS', which passes the query to the local bind server for resolution.  This causes that pool to succeed as far as load balancing is concerned, even if the answer it returns from bind is NXDOMAIN or some other unexpected response, and because LB was successful, no further GTM pools associated with the wideip would be considered.

In order to consider pool members from all pools associated with the wideip, the fallback mode on each pool must be set to 'none'.  This will cause the wideip to iterate through each pool using the wideip's load balancing method (default is round-robin)

Environment

  • BIG-IP DNS
  • Wide IP round robin load balancing Pools
  • A GTM Pool goes down (no available members)
  • "Return to DNS" fallback method is configured on the pool

Cause

As the default fallback method is 'return to DNS', by default, only the first pool selected by the wideip will be considered.  This is working as configured, though potentially not as desired.  

Recommended Actions

Set the fallback method on the Pools to "none", so that subsequent GTM pools are considered by the wideip.
