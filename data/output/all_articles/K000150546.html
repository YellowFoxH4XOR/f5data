Topic

The security log profile allows a firewall administrator to configure the BIG-IP AFM system to forward firewall events to different locations. In this article we will describe the default storage format when these firewall events are directed to BIG-IP local syslog server. This article assumes that the administrator has not customised the firewall event fields in the security log profile. The following table lists the storage format fields and descriptions in the same order we will see them in a firewall event.

Note: Due to the possible verbosity of firewall event data, F5 highly recommends that you use a remote log server for storing the AFM security related events. 

Description

The following table list the storage format fields that the system uses for local syslog logging when reporting BIG-IP AFM network firewall events.

Field NameDescription
management_ip_addressThe configured management IP address of the BIG-IP AFM system.
bigip_hostnameHost name of the BIG-IP system.
context_typeThe context to which the applied rule is applied (Virtual Server, Self IP, Global).
context_namePartition in which the virtual server resides and name of virtual server.
src_geoThe packet geographic location of the event to which the rule applies.
src_ipThe source IP address of the event to which the rule applies.
dest_geoThe packet destination location of the event to which the rule applies.
dest_ipThe destination IP address of the event to which the rule applies.
src_portThe source port of the event to which the rule applies.
dest_portThe destination port of the event to which the rule applies.
vlanThe vlan of the event to which the rule applies.
protocolThe corresponding numeric protocol value that was used in the connection, as specified in the rule.
route_domainThe route domain on which the policy rule was applied.
translated_src_ip

The translated source IP address of the event to which the rule applies.

translated_dest_ipThe translated destination IP address of the event to which the rule applies.
translated_src_portThe translated source port of the event to which the rule applies.
translated_dest_portThe translated destination port of the event to which the rule applies.
translated_vlanThe translated vlan of the event to which the rule applies.
translated_ip_protocolThe translated destination IP protocol of the event to which the rule applies.
translated_route_domainThe translated route domain of the event to which the rule applies.
acl_policy_typeThe type of acl policy (Enforced, Staged).
acl_policy_nameThe policy name where a rule of the policy triggered an event.
acl_rule_nameThe rule name of a policy where the rule triggered an event.
acl_rule_uuidThe assigned Universally Unique Identifier (UUID) to the connection where a rule of the policy triggered an event.
actionThe action taken or reported (None, Drop, Allow, Reject).
drop_reasonThe reason why the connection was dropped. For example: Policy, Connection Flow Miss, Bad TCP checksum.
sa_translation_typeSource address translation type used (automap, pool) for translation.
sa_translation_poolThe source address translation pool name used for translation.
flow_idThe ID of the flow as inserted in the connection table.
source_userThe subscriber (user) that was identified through the Subscriber-awareness feature.
source_user_groupThe subscriber (group) that was identified through the Subscriber-awareness feature.
source_fqdnDNS mapping of the source IP address (when configured).
dest_fqdnDNS mapping of the destination IP address (when configured).
send_to_vsThe virtual server where traffic is forwarded.
src_zoneThe firewall source zone of the event to which the rule applies.
dest_zoneThe firewall destination zone of the event to which the rule applies.
dest_vlanThe destination VLAN of the event to which the rule applies.
source_ipint_categoriesThe source IP address category match from the IP address intelligence categories.
dest_ipint_categoriesThe destination IP address category match from the IP address intelligence categories.


Note: Some of the above described fields could be missed in a firewall event, this depends on the configuration of your firewall. When there is not information for a field due to specific configurations then we can see just an empty field, or depending on the field we can read 'unknown' or 'No-lookup'.
