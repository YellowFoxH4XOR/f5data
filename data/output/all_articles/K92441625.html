Description

When trying to run the nethsm-thales-install.sh script to install the HSM on your viprion blades, it successfully installs it on the primary blade, but on the secondary blade it fails with an error similar to the following:

Installing on secondary slot 2 ...
ERROR: Install failed on slot 2.
ERROR: Install failed.  Attempting to clean-up ...

Also, when the installation fails on the secondary slot, the pkcs11d process continuously restarts which could affect other processes in the blade. The process restarts can be seen as message on the cli prompt:

logger[18651]: Re-starting pkcs11d
 

Environment

  • BIG-IP
  • VIPRION Platforms
  • Thales/nCipher/Entrust netHSM

Cause

The issue is that when we try to install the client on secondary blades we run thales-sync.sh and create a temporary log file as following:

    ssh slot$slot_id "thales-sync.sh -v" | tee $tmp_file
    tmp_file=$tmp_file.$current_time'.log'
    tmp_file="/tmp/tmp-hsm"
    current_time=$(date "+%Y.%m.%d-%H.%M.%S")

This creates a temporary log file in /tmp/tmp-hsm/$(date "+%Y.%m.%d-%H.%M.%S.log

The underlying problem is that there is no folder tmp-hsm in /tmp.

Recommended Actions

To workaround it, you can create the folder in the secondary blade with the following bash commands:

    ssh slotX. Where X is the number of the secondary slot.
    mkdir -p /tmp/tmp-hsm
    exit
