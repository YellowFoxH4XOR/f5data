Description

The BIG-IP system allows the user to execute su command to switch between user accounts. However, you can restrict the use of su command for security reasons.

Environment

  • BIG-IP LTM
  • su command
  • TMOS

Cause

None

Recommended Actions

To restrict a user from executing su command, please follow the below procedure.
Impact of procedure: Running this procedure should not have a negative impact on the traffic. 

  1. Log in to the command line.

  2. Navigate to the /etc/pam.d directory
    # cd /etc/pam.d

  3. Edit the PAM configuration file for su at /etc/pam.d/su 
    # vi su

  4. Click insert(i) and add the comment by inserting # at the beginning of the lines as shown below
    #%PAM-1.0
    #auth           sufficient      pam_rootok.so
    # Uncomment the following line to implicitly trust users in the "wheel" group.
    auth            sufficient      pam_wheel.so trust use_uid
    # Uncomment the following line to require a user to be in the "wheel" group.
    #auth           required        pam_wheel.so use_uid
    #auth           substack        system-auth
    #auth           include         postlogin
    #account        sufficient      pam_succeed_if.so uid = 0 use_uid quiet
    #account        include         system-auth
    #password       include         system-auth
    #session        include         system-auth
    #session        include         postlogin
    #session        optional        pam_xauth.so

  5. Save the file by pressing the ESC key and :wq and type enter.


Additional Information

sudo -- runs a single command with root privilege with the logged in user only required to enter their password. This prevents the need for users to know the root password in order to perform administrative tasks.

su -- switches to the super user – or root user – when executed with no additional options, or to a specified user, requires knowledge of the root password or the user account. The disadvantage is that you get more people knowing the root password for privileged administrative tasks than is otherwise necessary, also requires that when the password is changed, it has to be communicated to all. With more people knowing the root password it becomes difficult narrowing down the perpetrator in a security breach. Both of these commands give root privilege on a system, but the security implication is that if a user account is compromised, with sudo an attacker can go on to execute commands with root privilege or even gain a full interactive root shell with:

# sudo -i
