Environment

  • F5OS 
  • BIGIP Tenant
  • Changing vCPUs

Cause

This is caused by multus continuing to use a service account token past its expiry date.

This issue is being tracked by F5 as ID1694481.

Recommended Actions

In order to fix the issue, you can delete the multus pod by logging into the system as root and running the following command:

kubectl -n kube-system delete pod -l app=multus

The system will delete the running multus pod and create a new one, which will refresh the token for another year. 

No impact is expected from the above procedure.

After this the affected tenant should be able to start.
