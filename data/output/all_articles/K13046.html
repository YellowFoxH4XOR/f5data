Known Issue

When you attempt to run any item from the EUD menu, the EUD may exhibit the following behaviors:

  • The EUD logs errors and fails to complete the EUD item.
  • The EUD stops processing and may not respond to any keystrokes.

This issue occurs when all of the following conditions are met:

  • The EUD that you booted is version 11.4.0.4.0.
  • EUD version 11.4.0.4.0 is locally installed on the BIG-IP system.
  • You have installed or upgraded to a version shown in the Applies To box on the BIG-IP 1500, 3400, 6400, 6800, 8400, or 8800 platform.

Impact

You may not be able to determine hardware failures on the BIG-IP 1500, 3400, 6400, 6800, 8400, or 8800 platforms.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Before presenting the EUD menu, the EUD logs an error message that appears similar to the following example:

    scp: /tmp/./ppc_snake: No space left on device

  • When you attempt to run any EUD item, the EUD logs error messages that appear similar to the following example:

    awk: cmd. line:1: (FILENAME=- FNR=5) warning: error writing standard output (No space left on device)
    awk: cmd. line:1: (FILENAME=- FNR=8) warning: error writing standard output (No space left on device)
    ssh: connect to host sccp port 22: Connection refused

  • The EUD item that is run may appear to hang and does not respond to any interactive input.

Workaround

If you run an EUD item on your BIG-IP system, and the system is not responding, you need to perform a power cycle on the affected unit for recovery purpose.

To work around this issue, you can boot the EUD from a USB device and run EUD items from there. To do so, perform the procedures described in the EUD 11.4 Field Testing BIG-IP Hardware Supplemental Document.

Impact of workaround: The BIG-IP system does not process traffic when it is booted into the EUD.

Alternatively, you can modify the bootloader to include the serial baud for the EUD entry. To do so, perform the following procedure:

Impact of workaround: Modifying the bootloader inappropriately may render the BIG-IP system unbootable.

  1. Log in to the BIG-IP command line.
  2. Mount the boot partition and create a temporary grub.conf file for editing by typing the following command:

    grub_open

    The output of the command will provide the path and file name of the temporary grub.conf file created.

    For example:

    /var/run/grub.conf.mdfy.15952
  3. Edit the temporary grub.conf file created using a text editor of your choice.
  4. Locate the following line:

    kernel /vmlinuz.eud root=/dev/ram0 rw console=ttyS0 quiet

  5. Add the serial baud 19200 to the parameter console=ttyS0.

    For example:

    kernel /vmlinuz.eud root=/dev/ram0 rw console=ttyS0,19200 quiet

  6. Save the modification and exit the text editor.
  7. Update the original bootloader with the modified temporary grub.conf file, delete the temporary grub.conf file and unmount the boot partition by typing the following command:

    grub_close
  8. It is important that you power cycle or reboot the BIG-IP system with the following command:

    full_box_reboot
  9. Select the End User Diagnostics entry from the GRUB menu during bootup.
