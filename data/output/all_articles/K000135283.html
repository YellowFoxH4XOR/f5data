K000135283: Configuring Valid FQDN(s )in BIG-IP AFM DNS NXDOMAIN query Attack Type

Type
Support Solution
Published
2023-06-28
Updated
2023-06-28
Source
https://my.f5.com/manage/s/article/K000135283

Description

Valid FQDN(s) configuration in BIG-IP AFM DNS NXDOMAIN query Attack Type can be configured. This allows an administrator to create a whitelist of valid fully qualified domain names. Packets from a valid FQDN added in the configuration is not dropped by the DNS NXDOMAIN query Attack Type during a DNS NXDOMAIN response flood.

Environment

AFM provisioned
DNS NXDOMAIN query Attack Type configured in Device Protection or DNS enabled Protection Profile under DoS Protection

Cause

Allow Valid FQDN packets while DNS NXDOMAIN query Attack Type is detecting and mitigating a DNS NXDOMAIN response flood.

Recommended Actions

To allow Valid FQDN packets during DNS NXDOMAIN response flood, configure the DNS NXDOMAIN query Attack Type Valid FQDN

BIG-IP AFM Configuration Utility
1. In the BIG-IP AFM Configuration Utility, go to Security > DoS Protection > Device Protection or DNS enabled Protection profile and open the DNS NXDOMAIN query Attack Type properties
2. In the Valid FQDN(s): section, type in the valid fully qualified domain name to be allowed, click Add.
3. To confirm or check the FQDN is added to the dos dns whitelist, type in the valid FQDN and click Check,  this message is returned with a slight difference depending on which configuration it was checked on:
DNS enabled Protection profile
The full qualified domain name(FQDN) <FQDN> is found in the dos dns whitelist database for Protection Profile <DNS enabled Protection profile>
Device DoS
The full qualified domain name(FQDN) <FQDN> is found in the dos dns Whitelist database.

tmsh

To add a valid FQDN in the DNS NXDOMAIN query Attack Type configuration, run the tmsh command:

For Device Protection 
tmsh modify security dos device-config dos-device-config { dos-device-vector { dns-nxdomain-query { valid-domains add { <Valid FQDN> } } } }
For DNS enabled Protection profile 
tmsh modify security dos profile <DNS enabled Protection profile> { protocol-dns modify { all { dns-query-vector add { nxdomain { valid-domains add { <Valid FQDN> } } } } } }

To check if the FQDN is added to the dos dns whitelist, run the tmsh command:

For Device Protection 
tmsh list security dos device-config dos-device-vector { dns-nxdomain-query { valid-domains } }
security dos device-config dos-device-config {
    dos-device-vector {
        dns-nxdomain-query {
            valid-domains { meme[.]meme789[.]loc }
        }
    }
}

For DNS enabled Protection Profile 
tmsh list security dos profile <DNS enabled Protection Profile> { protocol-dns { all { dns-query-vector { nxdomain { valid-domains } } } } }
security dos profile <DNS enabled Protection Profile> {
    protocol-dns {
        dns-dos-protect {
            dns-query-vector {
                nxdomain {
                    valid-domains { site1[.]meme789[.]loc site2[.]meme789[.]loc }
                }
            }
        }
    }
}
 

Additional Information

During a DNS NXDOMAIN response flood, review the detected Domain Names during the detected NXDOMAIN Query attack and locate the instance of the valid FQDN. A lower number of Attacks and Drop stats or none will be recorded for the Valid FQDN.
