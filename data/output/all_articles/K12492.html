Known Issue

This is the result of a known issue. Due to a limitation in the version of the ntpd process included in BIG-IP versions 10.1.0 through 10.2.0, a configuration with a large number of self IP addresses will cause the ntpd process to crash. This issue is observed in configurations that have 250 or more self IP addresses. Queries may fail using the ntpq command line interface, and the ntpd process may experience a segmentation fault and dump core.

For example, the BIG-IP system writes messages to the /var/log/daemon.log file that appear similar to the following example:

ntpd[20325]: segfault at 00000000f8073008 rip 00000000f7f7bc75 rsp 00000000fff08d10 error 6

The ntpq -np command will not display the NTP server's known peers and state for a system with a correctly configured NTP server.

For example:

# ntpq -np

ntpq: read: Connection refused

F5 Product Development tracked this issue as ID 340696 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, and Edge Gateway release notes.
