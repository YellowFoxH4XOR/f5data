K000136034: GTM pool member deleted but DNS record still exists in ZoneRunner

Type
Support Solution
Published
2023-08-30
Updated
2023-08-30
Applies to
  • BIG-IP
  • BIG-IP DNS: 15.1.6, 15.1.8
Source
https://my.f5.com/manage/s/article/K000136034

Description

After removing all the pool members from a WideIP pool, the BIG-IP returns an incorrect IP. 

Environment

  • WideIP
  • Pool assigned to the WideIP
  • Pool members removed from the WideIP pool
  • ZoneRunner records exist for the pool members

Cause

A stale ZoneRunner resource record for this hostname. There are multiple scenarios which can cause this issue and are discussed in K5738 (linked below). However, also occurs if the ZoneRunner resource record is created manually. Usually this record is auto-added or auto-deleted when the pool member is added to or removed from the WideIP. Whereas, a resource record that is manually created remains until it is manually deleted. This record is only referenced as the fallback method when there are no available pool members.

Recommended Actions

Delete the incorrect resource record from ZoneRunner (via the WebUI). Perform these same steps for any incorrect records.

DNS > Zones > ZoneRunner > Resource Record List > Check/Enable the incorrect resource record > Delete

If "Synchronize DNS Zone Files" is enabled in the GSLB settings (DNS > Settings > GSLB > General) then these changes will sync to the other GTM/DNS devices. Otherwise, these ZoneRunner updates will need to be performed on each GTM/DNS in the cluster.
