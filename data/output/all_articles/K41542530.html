Known Issue

BIG-IP APM HTTP authentication may fail under heavy load.

This issue occurs when all of the following conditions are met:

  • The access policy is configured with an HTTP auth agent.
  • The AAA HTTP Server is configured in Form based or Custom body mode.

Impact

User authentication fails for the access profile.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The apmd/apd process produces a core file in the /shared/core/ directory, similar to the following example:

    apd.bld690.0.core.gz

  • The system logs messages in the /var/log/apm file that correlate with the time that the apmd core file in the /shared/core directory was created. These messages appear similar to the following example:

    notice apmd[<pid>]: 01490000:5: ** SIGSEGV **
    notice apmd[<pid>]: 01490000:5: fault addr: 0x3
    notice apmd[<pid>]: 01490000:5: fault code: 0x1
    notice apmd[<pid>]: 01490000:5: fault time: <date and time of event>

Workaround

There is no work around for this issue. However, you can alternatively use the Basic/NTLM mode in the AAA Server instead of Form Based or Custom Post.
