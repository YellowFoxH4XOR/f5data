Topic

You should consider using this procedure under the following condition:

  • You want to enable message-based load balancing (MBLB) mode instead of connection-based load balancing mode for the following protocols:
    • Session Initiation Protocol (SIP)
    • Radius
    • Diameter

Description

The BIG-IP system provides a Messaging Proxy component to support virtual servers that service message-based protocols with a large number of outstanding requests to virtual servers. You configure the Messaging Proxy by enabling the MBLB profile. The current protocols that interface with the Messaging Proxy and MBLB profile are SIP, Radius, and Diameter.

Note: Don't configure both MBLB and DatagramLB on the same virtual server. It's not a valid configuration and may cause the Traffic Management Microkernel (TMM) to become overloaded when attempting to process it.

The mblb profile options

  • The app-service setting specifies the name of the application service to which the profile belongs.
  • The defaults-from setting specifies the profile that you want to use as the parent profile.
  • The description setting is a user-defined description of the profile.
  • The Egress settings control the number of messages that the system queues before throttling outgoing messages:

    Note: You can configure the egress-high and egress-low settings starting in BIG-IP 11.5.0.

    • The egress-high setting specifies the high water mark for the egress message queue.
    • The egress-low setting specifies the low water mark for the egress message queue.
  • The Ingress settings control the number of messages that the system queues before throttling incoming messages:
    • Ingress high controls the number of queued messages that trigger congestion control on the client.
    • Ingress low controls the number of queued messages that the queue must fall back to before the system disables congestion control.
  • The Isolate settings control how connection termination affects related connections:
    • The isolate-abort setting controls whether a client connection is disabled when a reset occurs on a server-side connection, or any connections associated with the client. The Enabled setting (default) prevents the system from closing client connections and other related server-side connections.
    • The isolate-client setting, when enabled, prevents the system from closing server-side connections in the event of a client termination. This setting is disabled by default.
    • The isolate-expire setting behaves similarly to isolate-abort, but affects how clients are affected by timeouts to server connections. The default is enabled, so by default, if a server connection times out, the system does not terminate the client connection.
    • The isolate-server setting behaves similarly to isolate-abort, but affects how clients are affected by orderly closes to server connections. The default is enabled, so by default, if a server connection is closed gracefully, the system does not terminate the client connection. If you would prefer the system to terminate the client connection when the server connection is closed, set isolate-server to disabled.
  • The min-conn setting controls how many total connections are made to pool members. This setting is effective only if the value is greater than the number of pool members. For example, if there are five pool members and min-conn is set to 10, each pool member manages two connections.

    Note: The Min Conn setting is not supported in BIG-IP 10.1.0.

  • The shutdown-timeout setting delays sending FIN when the BIG-IP system receives the first FIN packet from either the client or the server.
  • The tag-ttl setting controls the Time-to-live for the messages tag.

Default mblb profile configuration

BIG-IP 11.5.1 and later

ltm profile mblb mblb {
app-service none
defaults-from none
description none
egress-high 50
egress-low 5
ingress-high 50
ingress-low 5
isolate-abort enabled
isolate-client disabled
isolate-expire enabled
isolate-server enabled
min-conn 0
shutdown-timeout 5
tag-ttl 60
}

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have command-line access.
  • You have an existing SIP/Radius/Diameter virtual server configured on the BIG-IP system.

Procedures

You can configure a virtual server with an mblb profile by performing either of the following procedures:

  • Configuring a virtual server with an MBLB profile using tmsh (11.x)
  • Configuring a virtual server with an MBLB profile using the bigpipe command (10.x)

Configuring a virtual server with an MBLB profile using tmsh (11.x)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. To create a new MBLB profile based on the parent profile, and set the values for each parameter, use the following command syntax:

    tmsh create ltm profile mblb <profile name> { [ingress-high <value>] [ingress-low <value>] [isolate-abort <enable|disable>] [isolate-client <enable-disable>] [isolate-expire <enable|disable>] [isolate-server <enable|disable>] [min-conn <value>] }

    For example, to create a new MBLB profile mymblb with an ingress high of 1000 and ingress low of 500, and a minimum connections setting of 10, enter the following command:

    tmsh create ltm profile mblb mymblb { ingress-high 1000 ingress-low 500 min-conn 10 }

  3. To verify the new profile settings, enter the following command syntax:

    tmsh list ltm profile mblb <profile name>

  4. To associate the new profile with the desired virtual server, use the following command syntax:

    tmsh modify ltm virtual <vs name> {profiles add { <mblb profile name> }}

    For example, to add mymblb profile to sip_example virtual server, enter the following command:

    tmsh modify ltm virtual sip_example {profiles add {mymblb}}

  5. To verify that the MBLB profile is assigned to the virtual server, enter the following command syntax:

    tmsh list ltm virtual <vs name>

Configuring a virtual server with an MBLB profile using the bigpipe command (10.x)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line
  2. To create a new MBLB profile based on the parent profile, and set the values for each parameter, enter the following command syntax:

    bigpipe profile mblb <profile name> { [ingress high <value>] [ingress low <value>] [isolate abort <enable|disable>] [isolate client <enable-disable>] [isolate expire <enable|disable>] [isolate server <enable|disable>] [min conn <value>] }

    For example, to create a new MBLB profile mymblb with an ingress high of 1000 and ingress low of 500, and a minimum connections setting of 10, enter the following command:

    bigpipe profile mblb mymblb { ingress high 1000 ingress low 500 min conn 10 }

  3. To verify the new profile settings, enter the following command syntax:

    bigpipe profile mblb <profile name> list

  4. To associate the new profile with the desired virtual server, use the following command syntax:

    bigpipe virtual <vs name> { profiles <mblb profile name> add }

    For example, to add mymblb profile to sip_example virtual server, enter the following command:

    bigpipe virtual sip_example { profiles mymblb add }

  5. To verify that the MBLB profile is assigned to the virtual server, enter the following command syntax:

    bigpipe virtual <vs name> list
