Topic

This article describes the DNS proxy service functionality of F5 Access on Windows. For the DNS relay proxy service on MacOS, refer to K000152990: DNS relay proxy service functionality on MacOS.

Description

The BIG-IP DNS relay proxy runs as a Windows service and is an optional component in the BIG-IP Edge Client package. It provides the following functionality:

  • It enforces DNS search order on accounts with limited privileges on the Windows system. Without the DNS relay proxy service, those using accounts with limited rights may see a pop-up message indicating that administrative rights are required in order for the Elevation Helper to patch the DNS settings.
  • It implements DNS scope when the network access is configured with split tunneling, using the DNS address space and DNS Exclude Address Space settings.

There is currently no matching functions for MacOS and Linux clients.

Logging

The DNS relay proxy logs its activities in the following log files:

  • %TEMP%\logterminal.txt
  • C:\Windows\Temp\FltRedirSrv.txt

Functionality

In BIG-IP APM network access, the system can analyze DNS request resolution by determining the following criteria:

  • DNS requests are resolved by entries in the host file.
  • DNS requests are routed to the VPN tunnel or outside of the tunnel.
  • DNS requests are sent to the client's locally configured DNS server or to the DNS server configured in BIG-IP APM network access.

To determine this, the DNS relay proxy relies on the following settings that you configure in your BIG-IP APM network access:

  • DNS Exclude Address Space
  • Allow Local DNS Servers
  • IPv4 LAN Address Space
  • Enforce DNS Search Order
  • DNS Default Domain Suffix
  • Static Hosts

DNS Exclude Address Space

When you configure a domain name in the DNS Exclude Address Space, the DNS relay proxy attempts to resolve the names you defined in the exclude address space to an IP address using the client's locally configured DNS server.

The DNS relay proxy adds the resolved IP addresses to the clients route table, thereby routing requests destined for the those IP addresses outside the VPN tunnel.

For example, if you add docs.example.com in the DNS Exclude Address Space configuration, the system routes the DNS request to the client's locally configured DNS server and adds the resolved IP address 192.0.2.2 to the client's route table. Allow Local DNS Servers

When you enable the Allow Local DNS Servers setting, DNS relay proxy directs DNS requests included in the DNS Exclude Address Space to the client's local DNS server. This is achieved by adding a route in the route table of the client system. As a result, the DNS requests destined for the client's local DNS servers do not enter the VPN tunnel.

IPV4 LAN Address Space

You configure a list of internal IP addresses or internal network addresses in this setting. Any traffic destined for the address(s) in this setting does so through the VPN tunnel.

To accomplish this, these addresses are added to the client's route table after VPN is established. When the DNS relay proxy processes a request that you included in the DNS Address Space, you may observe output similar to the following in the C:\Windows\Temp\FltRedirSrv.txt file:

Enforce DNS Search Order

When you enable this setting, the system enforces the DNS servers defined in the network access configuration to be used before the client's locally defined DNS servers. After network access is established, the DNS servers configured in the network access configuration may be added to the client's local interfaces. To show this, enter the ipconfig /all command. The Enforce DNS Search Order setting and the DNS relay proxy service determine whether the system adds the DNS server configured in network access configuration to the client's local network interface:

  • When Enforced DNS Search Order is disabled, the system does not add DNS servers defined in the network access configuration to the client's local interface.
  • When Enforced DNS Search Order is enabled and DNS relay proxy is not running, the system adds the first primary DNS server defined in network access configuration to the client's local interface and gives it the highest priority.
  • When Enforced DNS Search Order is enabled and DNS relay proxy is running, the system does not place DNS servers in the network access configuration on the local interfaces of the client system. Instead, the service intercepts traffic and uses the DNS servers in the network access configuration.

DNS Default Domain Suffix

You configure a list of DNS suffixes here to append to the name of DNS queries. The DNS relay proxy adds the names in the list to the registry only when Enforce DNS Search Order is enabled and in the following registry locations:

  • HKEY_LOCAL_MACHINE\SYSTEM\ControlSet001\Services\Tcpip\Parameters
  • HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters

Static Hosts

The system uses the entries defined in the host file of the network access configuration first. During domain name resolution, the Windows system appends the suffix you defined in the search list to the DNS request. Subsequently, when the DNS relay proxy receives a DNS request, it strips the suffixes defined in the search list from the DNS request and then verify if there is a match in the host file.
