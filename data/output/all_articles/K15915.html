Topic

You should consider using these procedures under the following condition:

  • You want to reallocate disk resources when upgrading a BIG-IP Virtual Clustered Multiprocessing (vCMP) host.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have access to the TMOS Shell (tmsh) or the Advanced Shell (bash) command line.

Description

After you perform an upgrade on a BIG-IP vCMP host, the system may report a disk space allocation error message in the /var/log/ltm file that appears similar to one of the following examples:

12.x and later:

warning Provisioning: Over allocation of disk has been detected. Future upgrades or provisioning attempts may fail. See SOL15915.

11.x:

emerg Provisioning: Over allocation of disk has been detected. Please check for unused application volumes.

The BIG-IP system generates this error message when the 'vg-free' disk attribute is less than the 'vg-reserved' attribute. This most commonly occurs when vCMP is provisioned on the BIG-IP system, and you perform a software upgrade; when vCMP is first provisioned, the system creates an application volume 'vmdisks' that consumes the remaining available disk space 'vg-free' minus 'vg-reserved'. The next action that requires additional disk space, such as a software upgrade, will cause the free space to dip below the reserved space, resulting in the error message.

There is no immediate impact to the BIG-IP system. However, the error may indicate that future attempts to create additional software volumes or upgrade existing volumes to later software versions may fail unless you take steps to reallocate disk resources before performing the next software upgrade. To reallocate disk resources on the vCMP system, perform one of the following procedures:

  • Resizing the vg_reserved volume
  • De-provisioning vCMP from the system, deleting the vmdisks application volume, and re-provisioning vCMP
  • Using the lvreduce command to reduce the size of the vmdisks application volume

Procedures

You can reallocate disk resources on the vCMP system by performing any of the following procedures:

Resizing the vg_reserved volume

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Use the following command syntax to display the disk properties on the BIG-IP system:

    list /sys disk logical-disk <logical disk name>

    For example, the BIG-IP system returns the properties of its HD1 disk when you type the following command:

    list /sys disk logical-disk HD1/1

    Note: HD1/1 is a reference to the disk and the blade on the BIG-IP multiple-blade system, where the first number denotes the disk and the second number denotes the blade. You will see HD1 on non-blade systems.

    The following output example shows the vg_reserved volume is currently allocated with 20,480 MB:

    sys disk logical-disk HD1/1 {
    mode mixed
    size 102400
    vg-free 33052
    vg-in-use 68084
    vg-reserved 20480
    }

  3. Use the following command syntax to resize the vg_reserved volume:

    Important: Do not resize the vg_reserved volume to a value below 10,000 MB.

    modify /sys disk logical-disk <storage name> vg-reserved <new size>

    For example, type the following command to resize the vg_reserved volume to 10,000 MB on the HD1 disk:

    modify /sys disk logical-disk HD1 vg-reserved 10000

    Note: The system automatically saves any modifications that this command initiates, and the modifications take effect immediately.

De-provisioning vCMP, deleting the vmdisks application volume, and re-provisioning vCMP

De-provisioning vCMP, deleting the vmdisks, and re-provisioning vCMP will allow the new vmdisks volume to be recreated using less disk space. To de-provision vCMP on the system, delete the vmdisks application volume, and re-provision vCMP, perform the following steps:

Impact of procedure: This procedure will delete all vCMP guests and guest configurations that are defined on the system. To back up the vCMP guest configuration, you must create a user configuration set (UCS) archive for the guest instances that you want to save. In addition, the procedure will automatically reboot the BIG-IP system after steps 2 and 5.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To de-provision vCMP on the system, type the following command:

    Note: The BIG-IP system will automatically reboot after this step.

    modify /sys provision vcmp level none

  3. After the reboot, log in to tmsh and delete the vmdisks application volume by typing the following command:

    delete /sys disk application-volume vmdisks

  4. To re-provision vCMP on the system, type the following command:

    Note: The BIG-IP system will automatically reboot after this step.

    modify /sys provision vcmp level dedicated

  5. You can now create the appropriate vCMP guests and restore the desired UCS archives that were previously saved from the vCMP guest.

Using the lvreduce command to reduce the size of the vmdisks application volume

You can also reallocate disk resources on the vCMP system by using the lvreduce command to reduce the size of the vmdisks application volume. To do so, perform the following procedures:

  • Deleting unused virtual disks that are not attached to any guest (optional)

    Note: Deleting unused virtual disks does not reallocate the disk resources unless you also use the lvreduce command to reduce the size of the vmdisks application volume.

  • Using the lvreduce command to reduce the size of the vmdisks application volume

    Note: Resizing of vmdisks application volume requires that all vCMP guests be gracefully shut down by setting the requested state to Configured, one guest at a time.

Impact of procedure: F5 recommends creating a UCS archive for the vCMP guest instances that you want to save prior to performing this procedure. Using the lvreduce command to shrink a logical volume may destroy the file system located on that volume if you do not make appropriate preparations; you must verify that the file system on the vmdisks volume has enough free space to accommodate the amount of space that you want to reclaim using the lvreduce command. Running lvreduce command will also require that vmdisks application volume be unmounted, and hence all vCMP guests must be gracefully shut down, one guest at a time. This will disrupt traffic processing and should only be performed during a maintenance window.

Deleting unused virtual disks that are not attached to any guest (optional)

Note: If the system does not have any unused virtual disks, you can proceed to the lvreduce command procedure.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To show the available vCMP virtual disks, type the following command:

    show vcmp virtual-disk detail

    For example, the following output indicates that the host-1.img virtual disk instances are 'in-use' and attached to a vCMP guest:

    -----------------------------------------------------------------
    Sys::Vcmp::VirtualDisk
    Name Slot ID Operating System Status Disk Use (bytes)
    -----------------------------------------------------------------
    MULTI.img 1 tmos ready 3.8G
    MULTI.img 4 tmos ready 3.8G
    MULTI.img 3 tmos ready 3.9G
    MULTI.img 2 tmos ready 3.9G
    guest1.img 1 tmos ready 4.1G
    guest1.img 2 tmos ready 4.1G
    helpsasa.img 1 tmos ready 8.1G

    host-1.img 1 tmos in-use 3.8G
    test.img 4 tmos ready 4.8G
    test.img 3 tmos ready 4.8G
    test.img 2 tmos ready 4.7G

  3. To delete unused virtual disks that are not attached to any guest, use the following command syntax:

    delete vcmp virtual-disk <virtual_disk>

    For example, to delete the virtual disk named my_vdisk, type the following command:

    delete vcmp virtual-disk my_vdisk

Using the lvreduce command to reduce the size of the vmdisks application volume

Important: Prior to 11.6.0 HF6, this command may not work as expected. For more information, refer to K46535012: Reclaiming unused disk resources may fail on a vCMP system.

  1. Log in to the BIG-IP bash command line.
  2. Determine the space used and the name of the vmdisks volume by typing the following command:

    lvscan | grep vmdisks

    For example, the following output indicates that the /dev/vg-db-sda/app.vcmp.dat.vmdisks volume is using 255.84 G:

    ACTIVE '/dev/vg-db-sda/app.vcmp.dat.vmdisks' [255.84 GiB] inherit

  3. Verify that the file system on the vmdisks volume has at least enough free space to accommodate the amount of space that you want to reclaim, by typing the following command:

    df -h /shared/vmdisks

    For example, the following output indicates that the vmdisks volume is 255 G with 227 G of free space available:

    Filesystem Size Used Avail Use% Mounted on
    /dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks
    255G 16G 227G 7% /shared/vmdisks

  4. Shut down all vCMP guests one at a time using the following command syntax:

    Note: The vCMP guest may take a long period of time to shut down gracefully.

    tmsh modify vcmp guest <guest_name> state <vcmp_state>

    For example, the following command will shut down vCMP guest host-1:

    tmsh modify vcmp guest host-1 state configured

  5. Verify that you have shut down all vCMP guests by typing the following command:

    Note: The output of this command will display vCMP guests that are still active.

    tmsh show vcmp guest

    For example, the following output shows that the guest host-1 is still in the process of shutting down:

    Note: Proceed to the next step only after host-1 has been shut down.

    tmsh show vcmp guest

    ------------------------------------------------------------------------

    Vcmp::Guest

    Name Slot ID Status Requested Request Retries Uptime Comment

    State Complete

    ------------------------------------------------------------------------

    host-1 2 stopping configured false 0 ---

  6. Decide how much space you want to reclaim using the lvreduce command. You can then use the following command syntax to reduce the volume size:

    Note: Verify that the amount of space you reclaim does not exceed the free space on the disk. F5 recommends that you start by reclaiming a small amount of space, such as 10 G.

    lvreduce --resizefs --size -<size_to_reduce> <vmdisks_volume_name>

    For example, the following command reduces the volume named vg--db--sda-app.vcmp.dat.vmdisks by 10 G:

    lvreduce --resizefs --size -10G /dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks
    Do you want to unmount "/shared/vmdisks"? [Y|n] y
    fsck from util-linux-ng 2.17.2
    /dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks: 21/4356016 files (0.0% non-contiguous), 4353733/67065856 blocks
    resize2fs 1.41.12 (17-May-2010)
    Resizing the filesystem on /dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks to 64444416 (4k) blocks.
    The filesystem on /dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks is now 64444416 blocks long.

    Reducing logical volume app.vcmp.dat.vmdisks to 245.84 GiB
    Logical volume app.vcmp.dat.vmdisks successfully resized

  7. Verify that the file system on the vmdisks volume has been reduced by the desired amount by typing the following command:

    df -h /shared/vmdisks

    For example, the following output indicates that the vmdisks volume has been reduced by 10 G and is now 245 G, with 217 G of free space available:

    Filesystem Size Used Avail Use% Mounted on
    /dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks
    245G 16G 217G 7% /shared/vmdisks

  8. Start vCMP guests one at a time using the following command syntax:

    tmsh modify vcmp guest <guest_name> state <vcmp_state>

    For example, the following command will power up vCMP guest host-1:

    tmsh modify vcmp guest host-1 state deployed
