Known Issue

The BIG-IP system may fail to properly dissociate a self IP from a VLAN. This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured as part of a high-availability system.
  • The affected self IP is initially configured as a non-floating self IP for the VLAN.
  • Another self IP is configured as a non-floating self IP for the same VLAN.
  • The affected self IP is then reconfigured as a floating self IP.

    For example, self IP1 and self IP2 are initially configured as the non-floating self IP addresses for VLAN A. Self IP1 is then reconfigured as a floating self IP address for VLAN A. The BIG-IP system continues to use the now floating self IP1 instead of the non-floating selfIP2 for monitoring traffic on VLAN A.

Impact

The BIG-IP system may experience traffic disruption.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The health monitor continues to send probes to the pool members or nodes using the affected self IP, even when the self IP is reconfigured as a floating self IP.
  • After failover, the peer system responds to the ARP request for the affected self IP, resulting in the system incorrectly marking down pool members. Depending on the pool configuration, this may affect connectivity to the associated virtual server.
  • The Linux command ifconfig <vlan name> continues to report the affected self IP as the IP address associated with the VLAN.

Workaround

There is no workaround for this issue. For a BIG-IP system that has already encountered this issue, you can recover the affected BIG-IP system by rebooting the system. To do so, perform either of the following procedures:

Note: Deleting the affected self IP from the system does not resolve this issue. The only way for the BIG-IP system to completely dissociate the affected self IP from the VLAN is to reboot the system.

Impact of workaround: The BIG-IP system may temporarily fail to process traffic and fail over to the peer system during the reboot.

Rebooting the system using the Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > General.
  3. To initiate a system reboot, click the Reboot button (on a VIPRION system, it is the Reboot Chassis button).
  4. To confirm the reboot, click OK.

Rebooting the system using the command line

  1. Log in to the command line.
  2. Reboot the system by typing the following command:

    reboot
