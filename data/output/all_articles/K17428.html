Known Issue

The HTTP::retry iRules command may cause the Traffic Management Microkernel (TMM) process to produce a core file.

This issue occurs when the following condition is met:

  • You have an iRule that uses the HTTP::retry command. For more information, refer to HTTP::retry command page on F5 Cloud Docs.

    Note: A DevCentral login is required to access this content.

  • The client closes its side of the TCP connection before the HTTP::retry command is triggered.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • The BIG-IP system logs messages to the /var/log/ltm file that appear similar to the following example:

    notice sod[8810]: 01140045:5: HA reports tmm NOT ready.

  • The BIG-IP system logs messages to the /var/log/messages file that appear similar to the following example:

    notice logger: Started writing core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897
    notice logger: Finished writing 236194271 bytes for core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897

  • The BIG-IP system generates TMM core files to the /var/core directory with a time stamp that correlates to the traffic interruption, similar to the following example:

    -rw-r--r-- 1 root root 226M Apr 13 15:09 tmm.0.bld2384.0.core.gz
