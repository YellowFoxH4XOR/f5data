Known Issue

This is the result of a known issue. When a backup file is restored on the active unit of a failover pair or on the primary unit of a cluster, some settings of the restored configuration are not synchronized to the standby unit of the failover pair or secondary unit(s) of a cluster.

This failure occurs even though synchronizations are reported as successful on the Failover: Settings page or on the Clustering: Stats page. Synchronization is working in general, but certain configuration settings that are susceptible to this issue may not be synchronized. Typically, these are settings applied on a per-master group basis. When settings are out of synchronization, the difference may not be reflected in the Administrative console, depending on the setting.

F5 Product Development tracked this issue as CR83317 and it was fixed in FirePass 6.0.2. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass version 5.x branch.

This issue was fixed in cumulative hotfix HF-552-11 issued for FirePass version 5.5.2, and in cumulative hotfix HF-601-5 issued for FirePass version 6.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by restoring the correct settings and permitting the synchronization of the settings in the future or by changing the parameter that has failed to synchronize.

Restoring the backup to the standby unit or cluster secondary

Important: To ensure that the system does not lose any data, you should use a backup that is as recent as possible when restoring a backup from an active unit or cluster primary to a standby unit or cluster secondary. If possible, perform a backup from one FirePass controller that you can immediately restore to the other.

Important: You should limit the scope of the restore operation to only those settings that are affected by this issue. Typically, these settings are restored by selecting the Restore Users and Groups settings check box. You should not select the Restore Networking Configuration check box unless you are familiar with the consequences of restoring Networking Configuration and have prepared for your standby unit or secondary unit to be separated from your network and from the active unit or cluster primary.

Important: Under normal circumstances, making any configuration change (including restoration of configuration settings using a backup) on a standby unit of a failover pair is not supported in any version of FirePass software. However, restoring a backup on the standby unit is acceptable for the purpose of addressing this issue.

To restore the backup to the standby unit or cluster secondary, perform the following procedure:

  1. Log in to the administrative console of the standby FirePass controller.
  2. Click Device Management.
  3. Click Maintenance.
  4. Click Backup/Restore.
  5. Under Restore FirePass controller configuration from a previous backup, enter the path to the backup file.
  6. Click the Restore your saved configuration link.

    The FirePass controller displays a page with current settings and settings in the backup file.

  7. Select the check box next to the Restore Users and Groups settings.

Changing the parameter that failed to synchronize

On the active unit of the failover pair or on the cluster primary, change the parameter that failed to synchronize to the standby unit, then change the parameter back to the value that you want.
