Topic

  • K14324: Using F5 vendor-specific attributes with RADIUS authentication (11.x - 12.x)

Starting in BIG-IP 10.0.0, the BIG-IP system supports F5 vendor-specific attributes (VSAs) for use with RADIUS authentication. To use these attributes, you must perform the following three procedures:

  • Add the F5 dictionary file to the RADIUS server
  • Configure the RADIUS accounts
  • Configure authorization for the remote accounts

Add the F5 dictionary file to the RADIUS server

To use the F5 VSAs, the attributes must be defined on the RADIUS server. Add the following RADIUS dictionary file to your RADIUS server:

Important: The format of the RADIUS dictionary file varies by vendor. Refer to your RADIUS software documentation for the appropriate formatting.


VENDOR        f5                3375
BEGIN-VENDOR    f5

ATTRIBUTE       F5-LTM-User-Role                    1       integer
ATTRIBUTE       F5-LTM-User-Role-Universal       2       integer  # enable/disable
ATTRIBUTE       F5-LTM-User-Partition              3       string
ATTRIBUTE       F5-LTM-User-Console               4       integer  # enable/disable
ATTRIBUTE       F5-LTM-User-Shell                   5       string   # supported values are disable, tmsh and bpsh
ATTRIBUTE       F5-LTM-User-Context-1           10      integer
ATTRIBUTE       F5-LTM-User-Context-2           11      integer
ATTRIBUTE       F5-LTM-User-Info-1                12      string
ATTRIBUTE       F5-LTM-User-Info-2                13      string
ATTRIBUTE       F5-LTM-Audit-Msg                  14      string

VALUE    F5-LTM-User-Role  Administrator                              0
VALUE    F5-LTM-User-Role  Resource-Admin                          20
VALUE    F5-LTM-User-Role  User-Manager                             40
VALUE    F5-LTM-User-Role  Auditor                                     80
VALUE    F5-LTM-User-Role  Manager                                    100
VALUE    F5-LTM-User-Role  App-Editor                                 300
VALUE    F5-LTM-User-Role  Advanced-Operator                     350
VALUE    F5-LTM-User-Role  Operator                                   400
VALUE    F5-LTM-User-Role  Firewall-Manager                        450
VALUE    F5-LTM-User-Role  Fraud-Protection-Manager           480
VALUE    F5-LTM-User-Role  Certificate-Manager                    500
VALUE    F5-LTM-User-Role  IRule-Manager                           510
VALUE    F5-LTM-User-Role  Guest                                      700
VALUE    F5-LTM-User-Role  Web-Application-Security-Administrator 800
VALUE    F5-LTM-User-Role  Web-Application-Security-Editor           810

Configure the RADIUS accounts

On the RADIUS server, configure the user accounts that will have access to the BIG-IP system.

The following example was taken from a server running FreeRADIUS:

jsmith Cleartext-Password := "test"
   Service-Type = Framed-User,
   Framed-Protocol = PPP,
   Framed-Routing = Broadcast-Listen,
   Framed-Filter-Id = "std.ppp",
   Framed-MTU = 1500,
   Framed-Compression = Van-Jacobsen-TCP-IP,
   F5-LTM-User-Role = 400,
   F5-LTM-User-Info-1 = db-ops,
   F5-LTM-User-Partition = db-part,
   F5-LTM-User-Shell = tmsh

Important: You must set the F5-LTM-User-Role attribute to one of the integers defined in the RADIUS dictionary file. For example, use the value 0 for administrator, and the value 400 for operator.

Ensure that the RADIUS server is returning the attributes correctly.

For example, the previous configuration was verified by running the radtest command on the RADIUS server:

# radtest jsmith test 192.168.1.100 0 secret
Sending Access-Request of id 187 to 192.168.1.100 port 1812
        User-Name = "jsmith"
        User-Password = "test"
        NAS-IP-Address = 192.168.1.100
        NAS-Port = 0
rad_recv: Access-Accept packet from host 192.168.1.100 port 1812, id=187, length=112
        Service-Type = Framed-User
        Framed-Protocol = PPP
        Framed-Routing = Broadcast-Listen
        Filter-Id = "std.ppp"
        Framed-MTU = 1500
        Framed-Compression = Van-Jacobson-TCP-IP
        F5-LTM-User-Role = Operator
        F5-LTM-User-Info-1 = "db-ops"
        F5-LTM-User-Partition = "db-part"
        F5-LTM-User-Shell = "tmsh"


Configure authorization for the remote accounts

On the BIG-IP system, configure authorization for the remote accounts using the bigpipe command.

Note: For syntax information for the remoterole command, refer to the Bigpipe Utility Reference Guide. For a complete description of how to use the remoterole command to assign authorization properties to groups of remotely stored user accounts, refer to BIG-IP Local Traffic Manager Implementations.

For example:

remoterole {
   role info operator-databaseops {
         attribute "F5-LTM-User-Info-1=db-ops"
         console "%F5-LTM-User-Shell" 
         line order 1001
         role "%F5-LTM-User-Role"
         user partition "%F5-LTM-User-Partition"
      }
}

Additionally, if the BIG-IP system is not currently using RADIUS authentication, configure RADIUS authentication on the System > Users screen under the Authentication menu.

Note: For detailed instructions on how to configure remote user authentication, refer to the TMOS Management Guide for BIG-IP Systems.

Using the previous example with the RADIUS account example in the Configure the RADIUS accounts section, the user jsmith would be assigned the following access to the BIG-IP system:

  • The role group operator-databaseops, since the value db-ops is returned for the attribute F5-LTM-User-Info-1.
  • The role of operator, since the value 400 is returned for the attribute F5-LTM-User-Role.
  • The db-part partition, since the value db-part is returned for the attribute F5-LTM-User-Partition.
  • The Traffic Management Shell, since the value tmsh is returned for the attribute F5-LTM-User-Shell.
