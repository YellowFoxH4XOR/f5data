K000152784: NDP table shows a persistent "incomplete" status for certain IPv6 virtual server addresses on the active BIG-IP device.

Type
Support Solution
Published
2025-07-28
Updated
2025-07-28
Applies to
  • BIG-IP

Source
https://my.f5.com/manage/s/article/K000152784

Description

On BIG-IP LTM systems, IPv6 virtual server (VS) addresses may appear with an "incomplete" status in the Neighbor Discovery Protocol (NDP) table. The output of show /net ndp all displays entries similar to:


Net::Ndp Name Address HWaddress Vlan Expire-in-sec Status

<ip_address> <ip_address> incomplete <vlan> 0 incomplete


This occurs even when the virtual server is active and reachable, and persists despite successful pings to the affected address.



Environment

BIGIP LTM

IPV6

VS- forwarding-IPV6


Cause

When traffic is sent to a VS IP address on a port that is not configured for any existing VS, it is processed by a forwarding virtual server. As part of this process, BIG-IP attempts to resolve the MAC address for the destination IP using NDP. Since the VS IP is not bound to a local interface (unlike a self IP), BIG-IP sends Neighbor Solicitation messages for its own VS IP but does not receive a Neighbor Advertisement response. This results in persistent "incomplete" entries in the NDP table for those IPs.


Recommended Actions

Review network traffic to ensure only intended ports are used when accessing VS IPs. Prevent traffic from reaching these addresses on unconfigured ports.
