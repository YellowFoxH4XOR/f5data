K47233334: Source address persistence supersedes cookie persistence

Type
Support Solution
Published
2021-10-28
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K47233334

Description

For certain cases, you will find a virtual server configured with both cookie persistence and source address persistence.  This is not only unnecessary, but in certain circumstances can cause uneven load balancing.

Environment

  • A HTTP virtual server, or a HTTPS virtual server with SSL offloading
    • Note: FastL4 virtual servers cannot use cookie persistence, as cookies are implemented at a higher layer than OSI Layer 4.
  • Both cookie and source address persistence are configured for the related pool 

Cause

This is by design.  

Source address persistence will persist on the incoming source address immediately on receiving a TCP connection.  Cookie persistence, on the other hand, relies on return HTTP traffic - and will inject the cookie into the HTTP response sent back to the client.  If a given connection is a brand new connection (and, therefore, does not have a persistence cookie), then source address persistence will immediately apply.  To this same end, a cookie will be injected into the response even so; this is usually merely redundant, but the side effect is that the cookie will be targeted to favor the pool member that was favored with source address persistence.

Recommended Actions

If you have a NAT in front of the virtual server, remove source address persistence and either wait for the persistence table to level out or clear the persistence table manually.

If you do not have a NAT in front of your virtual server, then simply select either cookie persistence or source address persistence.
