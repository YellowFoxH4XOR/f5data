Known Issue

When an external service provider (SP) canonicalizes authentication requests with the use of inclusive namespaces, the BIG-IP system as a Security Assertion Markup Language (SAML) Identity Provider (IdP) may in some cases ignore the inclusive namespaces when processing the authentication request.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured as a SAML IdP.
  • Users perform SP-initiated SAML SSO.
  • An external SAML SP sends signed authentication request, in which canonicalization uses inclusive namespaces.
During canonicalization, among other operations, white spaces between tags may be removed and namespace references may be sorted while redundant ones are eliminated. When inclusive namespaces are ignored by the IdP, an invalid message digest can be produced, which may cause verification of the SAML authentication to fail.
 

Impact

Users are unable to perform SAML SSO with certain external service providers.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The SAML SSO login fails and logs errors similar to the following in the /var/log/apm file:

    err tmm1[13063]: 014d0002:3: <apm sessionID>: SSOv2 Digest from SAML message is invalid
    err tmm1[13063]: 014d0002:3: <apm sessionID>: SSOv2 Error(12) Signature verification failed for SAML Authentication
