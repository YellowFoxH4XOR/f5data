Description

After migrating two BIG-IP devices configured in High Availability (HA) to new rSeries R4600 appliances, multiple issues may prevent successful HA configuration, including:

  • Management IP displayed as "none" or "local address" in the GUI after UCS migration
  • System > Platform page inaccessible after migration
  • Management interfaces not accessible via SSH or GUI  after tenant reboot
  • Tenants displaying inconsistent/different times, which can impact HA operations and ConfigSync

Environment

  • Product: BIG-IP LTM
  • Platform: rSeries
  • Two rSeries tenants configured for HA following UCS migration from previous BIG-IP devices
  • NTP servers not configured or unreachable on the tenants

Cause

Management IP initialisation failure was caused by improper mcpd service handling after UCS migration, requiring a manual restart to reinitialise management IPs.

Answer/Recommended Actions

Address each issue in the following order:

Issue 1: Management IP displayed as "none" or "local address" in the GUI after UCS migration

  1. If management IP is still  accessible restart mcpd on CLI , if not connect to each tenant via console.
  2. Restart the mcpd service on each tenant by running:
    restart sys service mcpd
  3. Verify that management IP is restored and both tenants are accessible via SSH and GUI.

Issue 2: Device Trust Establishment Failure

  1. Once the management IP is properly initialised and access regained proceed to reestablish device trust and Verify that device trust is successfully established between both tenants and that HA is configured:

     K42161405: Rebuilding device trust using the Configuration utility

    K40832524: Rebuilding device trust using tmsh (11.x - 17.x)

Issue 3: Time Synchronization Discrepancy Between Tenants

Once device trust is established if you face  HA pair Peer Time Out of Sync, check if ntp servers are configured and reachable. 

  1. Confirm if valid ntp server is configured 
  2. Verify NTP server communication on both tenants:  K10240: Verifying NTP peer server communications 
    ntpq -p    
  3. If NTP is not configured configure reachable NTP servers on all HA tenants. K3122: Using the BIG-IP Configuration utility to add an NTP server ,  K13380: Configuring the BIG-IP system to use an NTP server from the command line (11.x - 16.x)

Additional Information

  • Rebooting tenants alone after UCS migration while the management IP is not properly initialized may result in the loss of management IP access requiring  console access to the tenant to restart  mcpd service.
  • Time synchronisation between HA peers is critical for ConfigSync operations. Ensure NTP servers are configured and reachable on all tenants before finalising HA setup. K10240: Verifying NTP peer server communications
