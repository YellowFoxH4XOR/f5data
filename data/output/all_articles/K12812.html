Known Issue

In BIG-IP version 10.x, the Configuration utility and the Traffic Management Shell (tmsh) incorrectly allow the creation of profile object names that begin with a numeral or with any of the non-alphabetic characters that are otherwise allowed in profile object names.

Object names beginning with a numeral or special character are not supported in the BIG-IP configuration file and will cause the configuration to fail to load. This may leave the device in an impaired state after an intentional configuration reload operation, ConfigSync, UCS restore, reboot, or unexpected system reset.

In addition to numerals, profile names may incorectly be created with the following special characters as the first character:

  • period (.)
  • asterisk (*)
  • forward slash (/)
  • dash (-)
  • colon (:)
  • question mark (?)
  • equal (=)
  • at sign (@)
  • comma (,)
  • ampersand (&)
  • space ( )

The Configuration utility and tmsh are known to allow creation of these illegally named objects on the following profile object types:

  • Services: FTP, RTSP, Radius, Diameter, XML
  • Protocols: fastHTTP
  • SSL: ClientSSL
  • Authentication Profiles: CRLDP, Kerberos, SSL Client Certificate, SSL OCSP, TACACS+, RADIUS
  • Authentication Configurations: CRLDP
  • Other profiles: OneConnect

Impact

The configuration may fail to load, and as a result, the system may not process traffic as expected.

Symptoms

As a result of this issue, the BIG-IP system may experience the following symptoms:

  • The system may not process traffic as expected following a reboot, bigpipe load, UCS restore, or ConfigSync operation
  • Messages similar to the following example will be written to the command line interface following an attempt to load the configuration:

    BIGpipe parsing error (/config/bigip.conf Line 7):
    012e0020:3: The requested item (1xml {) is invalid (<profile arg> | show | list | edit | delete | stats reset) for 'profile'.

Workaround

To work around this issue, you can use the Configuration utility to delete the offending profile(s), and recreate it with a valid name.

Alternatively, you can modify the offending profile object name by manually editing the configuration file. This may be more efficient if you have several profile names to modify, and want to commit the changes to all of them with one edit. To manually edit the configuration file and change the profile name, perform the following procedure:

Impact of Workaround: In order for the changes to take effect, the device will require a configuration reload, which may result in a brief interruption in traffic processing.

  1. Log in to the BIG-IP command line.
  2. Create a back up of the configuration file by typing the following command:

    cp /config/bigip.conf /var/tmp/bigip.conf.original
  3. Open the /config/bigip.conf file for editing using the text editor of your choice. Pico and vi are both included on the BIG-IP system.
  4. Locate the profile object name that is causing the issue.

    For example, the object that caused the error message displayed in the Symptoms section above would be:

    profile xml 1xml {
    defaults from xml
    }

  5. Change the object so that the name no longer begins with a numeral.

    For example:

    profile xml my_xml_profile {
    defaults from xml
    }
  6. Search for all additional instances of the old profile name and replace with the new profile name.
  7. Save the file and exit the text editor.
  8. To verify that the configuration will load, type the following command:

    bigpipe verify load

    If there are no errors reported, proceed to step 9. If there are further errors reported, repeat steps 3 through 7 for any additonal profile names that require modification.
  9. Load the configuration into memory with the following command:

    bigpipe load
