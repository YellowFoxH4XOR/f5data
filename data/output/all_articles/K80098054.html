Topic

You should consider using this procedure under the following condition:

  • You want to configure the NGINX Controller to protect your APIs using the request rate limiting feature.

Description

APIs, like web applications, are susceptible to distributed denial-of-service (DDoS) or denial-of-service (DoS) attacks. One way to mitigate these attacks is to use the request rate limiting feature. You can use the NGINX Controller to configure request rate limiting for each of your published API on your deployed NGINX instance(s).

Rate limiting settings

The following table describes the settings available for configuring request rate limiting on the NGINX Controller.

SettingDescription
KeyThe request variable used to apply the rate limit. The more commonly used variables are the following:
  • Client IP Address: The source address for the client request.
  • Authenticated Client: This variable is only available if you have enabled Authentication for your published API.
  • URI: The requested URI; note that this limits all requests for the same URI.
You can also apply rate limit based on other request variables by selecting Other (NGINX variable) and specifying the NGINX variable name.
RateThe number of requests per period, where period is set in the Units setting. By default, the rate is specified in requests per second. If you require a rate that is lower than one request per second, then you should specify the rate in requests per minute. For example, you should configure the Rate as 30 and the Units as Requests per minute if you are looking to specify 0.5 request per second.
UnitsThis setting is used in conjunction with Rate. The options are the following:
  • Requests per minute
  • Requests per second
Excess Request ProcessingThis is an optional setting. The values are the following:
  • Reject immediately
  • Delay

Reject immediately is the equivalent of nodelay for the limit_req directive in NGINX. This allows your NGINX instance to immediately reject excessive requests; if Ignore Initial N Requests is set to a non-zero value, then Reject Immediately allows excessive requests within the value set in Ignore Initial N Requests to be immediately served and requests over the value to be immediately rejected.

Delay works in conjunction with Ignore Initial N Requests. When Ignore Initial N Requests is set to non-zero, Delay allows excessive requests to be queued where the size of this queue is equivalent to the value set for Ignore Initial N Requests. The requests in this queue are delayed and processed within the configured rate. Requests exceeding the queue size are rejected.

Ignore Initial N RequestsThis is an optional setting. It is the equivalent of burst for the limit_req directive in NGINX and works in conjunction with Excess Request Processing.
Reject Status CodeThe HTTP status code to return to the client when rejecting the request. The default value is 429, which is the standard HTTP response code for Too Many Requests per RFC 6586, typically use for rate limiting.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the NGINX Controller.
  • You have configured your published API on your deployed NGINX instance(s).

Procedures

Configure request rate limiting for your published API

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your NGINX Controller user interface as the administrative user.
  2. Select the NGINX Controller menu and select Services.
  3. Select APIs and the NGINX Controller user interface displays the list of configured API Definitions.
  4. Select an existing API definition you want to enable request rate limiting. The NGINX Controller user interface displays the API version(s) as well as their Published APIs associated with the API definition.
  5. For Published API, select Edit. If you have more than one version of the Published API, select Edit for the version on which you want to enable request rate limiting.
  6. Select Routing; the NGINX Controller user interface displays the page for Unrouted and Components.
  7. For the Security Settings of the published API component, select Edit. If you have not enabled any security settings for the published API component, you see the No Security Settings label next to the shield icon.
  8. Under SECURITY, select Rate Limiting.
  9. Select Enable Rate Limiting; the NGINX Controller user interface displays the rate limiting settings discussed in the Description section of this article.
  10. Configure the rate limiting settings as needed for your published API.
  11. Select Submit; the NGINX Controller user interface returns to the published API Routing page and you should see the Rate Limiting label for the component instead of the No Security Settings label described in step 7. This indicates that rate limiting is enabled for this published API.
  12. Select Submit.
