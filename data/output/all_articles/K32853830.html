Description

High Availability (HA) is down between BIG-IQ peer devices. Secondary UI login access may also be denied periodically displaying "Waiting for BIG-IQ services to become available".
  • BIG-IQ Systems Panel BIG-HA status reports 'Down' state.
    • 'Secondary TokuMX (x.x.x.x) reporting down'
  • /var/log/tokumx.log
    • Mon Jan 1 01:01:01.001 [rsHealthPoll] replSet member x.x.x.x:27017 is now in state FATAL
Environment
  • Two BIG-IQ systems in a high availability (HA) configuration
  • BIG-IQ 5.4.0
Cause

A firewall or network issue blocking TCP port 27017 communication between the two peers.

Recommended Actions
  • Verify and correct any TCP connectivity issues taking place over the Management IP address or internal self IP address for TCP port 27017 between the two BIG-IQ devices.
     
  • On the primary BIG-IQ, use the "Force database synchronization" button forcing a manual repair of the secondary database.
  1. Log in to the primary BIG-IQ system, using administrator credentials.
  2. From the BIG-IQ main list, select System.
  3. On the BIG-IQ Systems panel, expand BIG-IQ HA.
  4. Select BIG-IQ HA Settings.
  5. Click 'Repair Secondary Database'.  

Additional Information

With BIG-IQ high availability, the BIG-IQ system replicates the configuration database over TCP port 27017 using the mongod process from the primary peer to the secondary to keep the two systems synchronized. If a bidirectional communication issue exists over TCP port 27017 between the two peers than an HA status of 'Secondary TokuMX (x.x.x.x) reporting down' is reported within the UI as well as under the BIG-IQ HA Settings section of both peers. Secondary UI login access may also be denied periodically displaying "Waiting for BIG-IQ services to become available".

NOTE: If the connectivity issue extends longer than 2 hours then TokuMX can result in a 'FATAL' state requiring a repair. 

Viewing the current HA State in the UI:
  1. Log in to the primary BIG-IQ system, using administrator credentials.
  2. From the BIG-IQ main list, select System.
  3. On the BIG-IQ Systems panel, expand BIG-IQ HA.
  4. Select BIG-IQ HA Settings in order to view the HA Pair State.
Verifying TCP connectivity issues taking place over the Management IP address or internal self IP address for TCP port 27017 between the peers of the BIG-IQ's using the tcpdump utility:
  1. Log in to the command line interface.
  2. To start tcpdump, use the following example command syntax:

    tcpdump -ni <interface> port 27017 -W 10 -C 100 -w /var/tmp/test.pcap

           Note: The tcpdump utility does not print data to the screen while it is capturing to a file.

        3. After the issue you're troubleshooting occurs, press Ctrl+C to stop the capture.

You can now analyze the collected binary packet capture files. For information about using the tcpdump utility to read and analyze your capture files, refer to K411: Overview of packet tracing with the tcpdump utility and K1893: Packet trace analysis.
