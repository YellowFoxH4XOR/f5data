K000135232: Software upgrade rollback from 15.1.x to 13.1.x results in BIG-IP stuck in inoperative state

Type
Support Solution
Published
2023-06-26
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.3
Source
https://my.f5.com/manage/s/article/K000135232

Description

After rolling back an upgrade from 15.1.6.1 to 13.1.3.4, mcpd is down, and the device is in an inoperative state.

You may see messages similar to the following in the ltm log.

 

<Date and time> ltm1.host warning promptstatusd[3166]: 01460005:4: mcpd.running(1) held, wait for mcpd
<Date and time> ltm1.host info overdog[3163]: 01140100:6: Overdog daemon startup.
<Date and time> ltm1.host notice overdog[3163]: 01140103:5: Watchdog touch enabled with 40 seconds.
<Date and time> ltm1.host warning diskmonitor: 011d0002:4: Cannot access the database because mcpd is not running.

 

Environment

  • Modified startup script
  • Upgrade rollback

Cause

The startup script was modified in preparing the upgrade from 13.1.x  to 15.1.x using  K11948.

The  wait_bigip_ready statement in version prior to 15.1.x can cause a deadlock which prevents BIG-IP from booting up correctly.

In versions before 15.1.x init and rc are used to start services, including runit which starts BIGIP processes like mcpd. The services start in alphabetical order. local waits for mcpd and mcpd waits for local, creating a deadlock.

In 15.1.x and above BIG-IP uses systemd where things are not started serially like with rc and the runit service has no dependency on local.

Recommended Actions

Remove the statement wait_bigip_ready from the startup script in versions before 15.1.x

Additional Information

Attempting a clean install and a UCS restoration works at first; however, on the next reboot, mcpd will become deadlocked due to the startup script.
