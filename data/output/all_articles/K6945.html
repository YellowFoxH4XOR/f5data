Known Issue

This is the result of a known issue. FirePass does not currently support the Server Message Block (SMB) protocol directly over TCP/IP.

Portal Access Windows Files Favorites connect to networked file shares using the SMB protocol, layered on top of the NetBIOS over TCP/IP protocol. This configuration ensures compatibility with file servers using older operating systems. SMB can also be layered on top of TCP/IP directly, without using the NetBIOS protocol as an intermediate layer. This is called direct hosting of SMB over TCP/IP. By default, Microsoft Windows-based operating systems and many other operating systems are configured to use both methods of file sharing, when acting as a networked file server.

If a networked file server is configured to only use direct hosting of SMB, FirePass will be unable to connect to the file server, and Windows File Favorites will show empty directory listings for shares from that file server. A network packet dump or inspection of the configuration of your file server can be used to determine whether this symptom is the result of the file server not using NetBIOS over TCP/IP.

F5 Product Development tracked this issue as CR70436 and it was fixed in version 6.0.3. For information about upgrading, refer to the FirePass release notes.

Note: For more information about upgrading to version 6.0.3 or later, refer to K8444: The FirePass pre-upgrade checklist.

This issue still exists in the FirePass version 5.x branch.

Workaround

You can work around this issue by configuring your file server to use NetBIOS over TCP/IP. For information about NetBIOS and SMB over TCP/IP, and other related networking information for Microsoft Windows, refer to the Microsoft documentation. If you are using a non-Windows based operating system, consult documentation for your operating system.
