K48201023: Host entries are being added to the Windows host file for the VPN SSL Tunnel

Description

Host entries are being added to the Windows host file for the VPN SSL Tunnel

For example:
192.168.1.1           vpn.website.com #ADDED BY F5 NETWORKS SSL TUNNEL - ORIGINAL RECORD#
192.168.1.1           vpn #ADDED BY F5 NETWORKS SSL TUNNEL - ORIGINAL RECORD#

Environment

  • APM
    • Network Access Tunnel configured
  • Client connecting to the Network Access Tunnel

Cause

The host entries are being added by design as the Edge Client is writing these host entries.  Host entries are the virtual server address, sometimes also static DNS hosts added to the tunnel.  

Static hosts entries can be found under:
Access Policy -> Network Access -> Network Access List ->  the name of your network access ->  On the tab "DNS/Hosts" and then in the section labeled "Static Hosts".  

Note: These entries should be removed when the edge client connection is closed, however some scenarios like a crash or a privilege change can prevent these entries from being removed.

Recommended Actions

We have created a new feature to no longer write host entries called the DNS Relay Proxy service:
You can use the DNS Relay Proxy service to avoid these entries from being written.  

Download the DNS Relay Proxy service:
Navigate to Access  ->  Secure Connectivity ->  Select Connectivity profile -> Customize Package button at the bottom and make sure "DNS Relay Proxy Service" is selected and then "Download".

Additional Information

K9694: Overview of the Windows DNS Relay Proxy service

You can install the DNS relay proxy service, an optional Windows component, for DNS management. The service provides kernel integration with the Windows operating system to perform rule-based DNS resolution without the use of the host file. This avoids conditions where an administrator permission-level is required to patch the host file. In Full Tunnel mode, the service intercepts all DNS requests and forwards them to the DNS server(s) configured in the Network Access resource (Primary / Secondary Name Server). In Split Tunnel mode, the DNS relay proxy intercepts all DNS requests but only forwards those matching the DNS Address Space to the DNS server(s) configured in the Network Access resource.
