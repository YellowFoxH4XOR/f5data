Description

Low space on /usr causes failed '(RPM transaction failure)' when installing upgrade and/or hotfix

Environment

  • BIG-IP
  • EHF installation
  • Low disk space

Cause

/usr is running low on space

Recommended Actions

This problem occurs because the apmclients and epsec RPM packages install their contents to the /usr/apm/images directory, which fails if there is insufficient space in the /usr volume for the temporary files created during RPM package installation.

Your /usr filesystem is nearly full:

df -h | grep /usr

/dev/mapper/vg--db--sda-set.1._usr 6.0G 5.5G 224M 97% /usr <<<<<<<<< 97% used !

To work around this issue:

1. Install the BIG-IP Release version to the desired volume set (e.g. HD1.3).

For example:

-- from a bash command prompt:

tmsh install sys software image BIGIP-17.1.1.4-0.0.9.iso volume HD1.3

2. Increase the size of /usr volume in the target volume set (e.g., HD1.3).

For example, from a bash command prompt:

lvextend -L+500M --resizefs /dev/mapper/vg--db--sda-set.3._usr (change to match your filesystem naming if it's different from this example)

Important: you must do this after you install the base software on the new partition, and before installing the EHF on the same partition.

3. Install the BIG-IP Engineering Hotfix to the target volume set (e.g. HD1.3).

For example:

-- from a bash command prompt:

tmsh install sys software hotfix Hotfix-BIGIP-17.1.1.4.0.96.9-ENG.iso volume HD1.3
