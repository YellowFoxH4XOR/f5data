K000138777: Scanner HTTP requests redirect to /vdesk/hangup.php3

Type

Published
2024-02-29
Updated
2024-02-29
Source

Description

When performing a scan of a BIG-IP APM Virtual Server (e.g., with nmap or similar) you may notice many HTTP requests receive 302 Redirect responses and are redirected to /vdesk/hangup.php3.

 

Environment

  • BIG-IP APM
  • nmap, Nessus or similar scan of HTTP resources

Cause

F5 BIG-IP APM issues HTTP 302 Redirect responses and redirects the client to /vdesk/hangup.php3 when the received HTTP request contains a Host header value that does not match the configuration of the APM Virtual Server or if the client session has not passed the APM policy (VPE).

The script at /vdesk/hangup.php3 is intended to clear the users session and cookies in response to such an invalid request as outlined above.

This behavior is by design and is intended to enhance security by ensuring that any browser client issuing an invalid request (which does not match the APM configuration) results in the session being cleared.

Scanners such as nmap will send a large number of requests without consideration for the configuration of the target system unless otherwise instructed, and this will result in each request receiving a 302 Redirect response. This can be ignored and does not consistute a security risk.

Recommended Actions

None.
