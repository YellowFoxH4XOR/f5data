Topic

Beginning in BIG-IQ 7.1.0, you can create an application service configuration using existing device configurations. The application service deployed in this fashion is called a legacy application service and is denoted with LEGACY in the Application Service Dashboard on BIG-IQ. This feature gives the BIG-IQ administrator and the application owner access to the Application Dashboard to view analytics data and ability to enable or disable virtual servers and pool members.

Description

Requirements for deploying a legacy application service

  • The BIG-IQ has a data collection device (DCD) cluster configured.
  • The BIG-IQ DCD cluster has enough disk space for collecting data from the managed devices. For more information about estimating disk space requirements, the BIG-IQ DCD sizing tools, and details such as the maximum number of application services supported, refer to BIG-IQ: Sizing Guidelines.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  • Statistics collection is enabled for each managed BIG-IP device. Refer to the Enabling statistics collection for a managed BIG-IP device procedure later in this article.
  • Network connectivity functions between the managed BIG-IP devices and the BIG-IQ DCDs. For more information about this topic and the f5-bigiq-connectivityChecks tool, refer to K15612: Connectivity requirements for the BIG-IQ system.
  • To view the analytics data for the application service, the managed BIG-IP device must meet the following criteria:
    • The system is running BIG-IP 13.1.0.5 at minimum; F5 recommends running BIG-IP 13.1.2 or later.
    • The system has the F5 Application Visibility and Reporting module provisioned. The Application Visibility and Reporting module sends statistics data to the BIG-IQ DCD cluster.

      Note: On BIG-IP VE systems, you may need to extend disk space to provision the Application Visibility and Reporting module. For more information, refer to the Extending disk space for provisioning multiple modules section in K14952: Extending disk space on BIG-IP.

    • An F5 Analytics profile is applied to each virtual server that you want to use with the application service configuration.

Important: BIG-IP devices send Analytics data to the DCD cluster, where you can view it on the BIG-IQ system. The data is not viewable on the BIG-IP system. For more information, refer to K42361146: Analytics page on the BIG-IP system does not display data.

Note: For more information about the change in behavior with how DCDs collect data from managed BIG-IP systems and for troubleshooting steps, refer to K96505382: The BIG-IP system now pushes statistics data to BIG-IQ DCD.

Recommendations for deploying a legacy application service

Deploying a legacy application service increases the resource usage of the BIG-IP and BIG-IQ systems. Determine the baseline of resource consumption on the BIG-IP and BIG-IQ systems before provisioning the Application Visibility and Reporting module on the BIG-IP system. Additionally, determine the baseline after provisioning Application Visibility and Reporting but before creating a legacy application service. To avoid overwhelming the systems, deploy changes incrementally. Start with a single managed BIG-IP device and a batch of no more than 10 legacy application services (starting with fewer is better) and observe the resource impact to the BIG-IP system, the BIG-IQ system, and DCDs. After you understand the impact, either stop to ensure devices maintain an acceptable resource consumption or, if there are plenty of resources available after your first batch, continue deploying another batch. Repeat the process on subsequent managed BIG-IP devices.

The impact of running Application Visibility and Reporting and allowing statistics collection on the BIG-IP depends on its resource level, configuration size, the traffic load, the number of provisioned modules, and other factors. The System > Resource Provisioning page shows you the minimum required memory and disk for Application Visibility and Reporting. Other provisioned modules allocations will be adjusted lower to accommodate Application Visibility and Reporting provisioning. If necessary, to reduce the effect of statistics collection on the BIG-IP system, refer to, K91114310: Reducing the performance impact of BIG-IQ statistics gathering on managed BIG-IP systems.

Note: You can configure a maximum of five virtual servers for each legacy application service.

When creating a legacy application service, F5 strongly recommends that you configure virtual servers with their own pools. If a legacy application's virtual server shares a pool with other virtual servers, this may affect certain data parameters that appear in your analytics data in the Application Dashboard.

Enabling statistics collection for a managed BIG-IP device

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ user interface.
  2. Go to Devices > BIG-IP DEVICES.
  3. In the inventory list, select the BIG-IP host name on which you want to enable statistics collection.
  4. Select STATISTICS COLLECTION.
  5. Select the check box for Collect Statistics Data.
  6. Ensure that the check boxes for BIG-IP Device and Local Traffic Manager are selected.
  7. Configure the other properties as needed then select Save & Close.

Displaying BIG-IQ system statistics

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ user interface.
  2. Go to System > THIS DEVICE > Statistics and select the statistics to display.

    Note: You can view system-wide resource usage by selecting items under the Statistics category or view BIG-IQ process specific resource usage by expanding BIG-IQ Metrics and selecting items in this category.

Displaying BIG-IQ DCD statistics

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ user interface.
  2. Go to System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Devices.
  3. Select a DCD that you want to view the statistics for.
  4. Select Health.

Displaying managed BIG-IP statistics

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ user interface.
  2. Go to Monitoring > DASHBOARDS > Device > Health.

    This view displays combined statistics for all managed devices. To display statistics for a single device, continue with the following steps.

  3. If the filter frame is not already expanded, select the arrow ( < ) to expand it.
  4. Select BIG-IP Host Names to expand the filter list.
  5. Select a BIG-IP host name to view only statistics from that BIG-IP system.
  6. Select the funnel icon to clear the filters.

Displaying managed BIG-IP statistics from the Application Dashboard

After you have enabled F5 Application Visibility and Reporting on the managed BIG-IP system and created a legacy application service, you can view the statistics for the managed BIG-IP device from the Application Dashboard.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ user interface
  2. Go to Applications.
  3. Select your application followed by your application service on the subsequent page.
  4. Select Environment.
  5. Select CPU Usage and Device Memory to view resource usage.

Provisioning the F5 Application Visibility and Reporting module on a managed BIG-IP system from the BIG-IQ

You can use the Script Management feature to provision the F5 Application Visibility and Reporting module on a managed BIG-IP device. Ensure that Advanced Shell (bash) access is enabled for the admin account on the managed device. For more information, refer K12029: Accessing the TMOS Shell.

Impact of procedure: Performing the following procedure causes a temporary traffic disruption while the BIG-IP restarts processes to complete provisioning. You should perform this procedure only during a scheduled maintenance period.

  1. Log in to the BIG-IQ user interface.
  2. Go to Devices > SCRIPT MANAGEMENT > Scripts.
  3. Select Add.
  4. Enter a name and optionally a description.
  5. For Script, enter the following two commands, each on its own line as follows:

    tmsh modify /sys provision avr level nominal
    tmsh save /sys config

  6. Select Save & Close.
  7. On the Scripts page, select the check box next to the script you created and select Run.
  8. Enter a name and optional description for the script execution task.
  9. For Devices, move the devices you want to run this script on from the Available list to the Selected list.
  10. Select Run.
  11. The Script Log typically reports Failed to download files from <device name> for the task because provisioning a new module involves restarting daemons which interrupts the BIG-IQ from gathering command output. However, you can confirm successful provisioning by the presence of statistic data for the device in the Device Health Dashboard. To locate the dashboard, refer to the Displaying managed BIG-IP statistics procedure.
