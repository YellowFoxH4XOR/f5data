Known Issue

This is the result of a known issue. BIG-IP systems in a redundant pair with transparent or translucent Virtual Local Area Network (VLAN) groups configured do not remove dynamic forwarding database (FDB) entries after failover. As a result, if a failover is initiated, traffic passing through the VLAN group may be blocked for up to 2 minutes, depending on the lower-level network configuration.

Removal of the FDB entries after failover is necessary because the switch fabric on the standby unit learns host MAC addresses on all VLANs in the VLAN group from the active system's proxy Address Resolution Protocol (ARP) broadcasts. When the standby system transitions to Active, FDB entries for some hosts are incorrect and point to the wrong physical port.

F5 Product Development tracked this issue as ID 242715 (formerly CR134651) and it was fixed in BIG-IP 11.5.0 and BIG-IP 11.4.1 HF6. For information about upgrading, refer to the BIG-IP LTM release notes.

In addition, BIG-IP iHealth may list Heuristic H461171 on the Diagnostics > Identified > High screen.

Workaround

You may work around this issue by performing one of the following two procedures:

Impact of workaround: Configuring a MAC masquerade address for a traffic group can temporarily disrupt traffic on the associated VLAN, while the surrounding network devices learn the new hardware address association. F5 strongly recommends that you perform this procedure during a scheduled maintenance window.

  • Configuring the systems to delete FDB entries upon failover
  • Reconfiguring the transparency mode for the VLAN group to opaque, and defining MAC Masquerading for the VLAN

Configuring the systems to delete FDB entries upon failover

To configure the systems to delete FDB entries upon failover, type the following command from the command line:

echo "tmsh delete /net fdb vlan all all-records" >> /config/failover/active

Note: The /config/failover/active script is executed upon system failover, and the tmsh delete /net fdb vlan all all-records command clears the FDB entries automatically when a unit goes from Standby to Active.

Note: If you are currently experiencing this issue and the system is not passing traffic, you can manually clear the FDB by typing the tmsh delete /net fdb vlan all all-records command.

Reconfiguring the transparency mode for the VLAN group to opaque, and defining MAC Masquerading for the VLAN

If you do not have command line access, you may be able to work around this issue by reconfiguring the transparency mode for the VLAN group to opaque, and defining MAC Masquerading for the VLAN. To do so, perform the following procedure:

Note: The MAC Masquerade configuration is not synchronized between BIG-IP systems. You must define the MAC Masquerade address on both the active and the standby system in a redundant pair. For information about the MAC Masquerade feature, refer to K13502: Configuring MAC masquerade (11.x - 14.x) and K7214: Configuring MAC masquerade (9.x - 10.x).

  1. Log in to the Configuration utility.
  2. For BIG-IP 11.3.0 and later, click Device Management.

    For BIG-IP 11.0.0 through 11.2.1, click Network.

  3. Click Traffic Groups.
  4. Select the traffic group for which you want to assign a MAC masquerade address.
  5. In the MAC Masquerade Address box, type the unique MAC address.
  6. Click Save Changes.
