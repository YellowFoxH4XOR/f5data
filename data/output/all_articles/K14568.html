Topic

    You should consider using these procedures under the following conditions:

    • You want to revert BIG-IP software back to an older version.
    • The desired BIG-IP software version is not installed on an alternate boot location.

    Description

    Downgrading BIG-IP software refers to performing a fresh installation and reverting software back to an older version. You may need to perform a downgrade if the desired BIG-IP software version is no longer installed on an alternate boot location. Consider the following information when deciding whether to perform a downgrade:

    • Performing a downgrade does not roll back the BIG-IP configuration.

      Performing a downgrade overwrites BIG-IP configuration information on the partition you are downgrading. No supported method exists to automatically roll back the BIG-IP configuration when you reinstall an earlier version of the software.

    • Performing a downgrade may require you to manually rebuild the configuration.

      Unless you have a user configuration set (UCS) archive file that was generated on the version to which you are downgrading, you must manually rebuild the BIG-IP configuration after you perform a downgrade. For example, if you downgrade from 17.5.1 to 17.1.1.4, you must restore a 17.1.1.4 UCS archive file after you downgrade. You cannot restore a UCS archive that was saved on BIG-IP 17.5.1 on the system after you downgrade to 17.1.1.4.

    • Downgrading should not be necessary on multi-partition systems.

      Multi-partition BIG-IP systems support simultaneous software installations. When you plan a software upgrade, F5 recommends that you install the new software on a target partition and retain the previous software version and configuration on the alternate partition until you verify proper operation of the new software. Using this method allows you to revert back to the previous software version and configuration by rebooting to the partition containing the previous version.

      For example, if you are running an older version of BIG-IP software on the active partition and want to upgrade the system to a newer BIG-IP version, you should install the newer version of the BIG-IP software on an inactive partition and reboot to the partition when you are ready to run the newer version of BIG-IP software. This action retains the older instance of the BIG-IP software installation on an inactive boot location while running the newer version of BIG-IP software on the active boot location. If you decide to revert back to the previous software version, you can reboot the system to the boot location that contains the older version of BIG-IP software.

    Prerequisites

    You must meet the following prerequisite to use these procedures:

    • You have downloaded the desired software image to the BIG-IP system.

    Procedures

    • Downgrade BIG-IP base and point release software
    • Downgrade BIG-IP hotfixes

    Downgrade BIG-IP base and point release software

    To revert back to a previously installed base or point release software installation that no longer exists on another boot location, you must reinstall the base version or point release to an inactive boot location.

    Note: Point release software versions are available for BIG-IP 11.5.5, 11.6.3, 12.1.3, and 13.1.0 and later.

    To reinstall the software to an inactive boot location, perform the following procedure:

    Configuration utility

    Impact of procedure: Performing a downgrade overwrites BIG-IP configuration information on the partition you are downgrading.

    1. Log in to the Configuration utility.
    2. Go to System > Software Management > Image List.
    3. Select the check box next to the desired base software image.
    4. Select Install.
    5. Select the volume set name for which you want to perform the installation.
    6. Select Install.

    Command line

    1. Log in to the tmsh (tmos) shell.
    2. Use the following command syntax to install an available image to an existing volume:

      install sys software image <BIG-IP image ISO name> volume <volume name>

      For example, to install the BIGIP-16.1.4.1-0.0.5.iso image to HD1.2, you enter the following command:

      install sys software image BIGIP-16.1.4.1-0.0.5.iso volume HD1.2

    After the installation is complete, you can activate the downgraded boot location and the system reboots to the newly installed slot. You can then rebuild the configuration or install a UCS file that matches the downgraded software version.

    Downgrade BIG-IP hotfixes

    To revert back to a previously installed hotfix that no longer exists on another boot location, you must first reinstall the base version to an inactive boot location, and then install the desired hotfix. To reinstall the base BIG-IP software and hotfix to an inactive boot location, perform the following procedure:

    Impact of procedure: Performing a downgrade overwrites BIG-IP configuration information on the partition you are downgrading.

    Configuration utility

    1. Log in to the Configuration utility.
    2. Perform the previous Downgrade BIG-IP base and point release software procedure.
    3. Go to System > Software Management > Hotfix List.
    4. Select the check box next to the desired hotfix image.
    5. Select Install.
    6. Select the volume set name for which you want to perform the installation.
    7. Select Install.

    Command line

    1. Log in to the tmsh (tmos) shell.
    2. Perform the previous Downgrade BIG-IP base and point release software procedure.
    3. Use the following command syntax to install an available hotfix image to an existing volume:

      install sys software hotfix <BIG-IP hotfix image ISO name> volume <volume name>

      For example, to install the Hotfix-BIGIP-16.1.4.1.0.13.5-ENG.iso image to HD1.2, you enter the following command:

      install sys software hotfix Hotfix-BIGIP-16.1.4.1.0.13.5-ENG.iso volume HD1.2

    After the installation is complete, you can activate the downgraded boot location and the system reboots to the newly installed slot. You can then rebuild the configuration or install a UCS file that matches the downgraded software version.
