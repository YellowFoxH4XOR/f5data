K000141295: Not be able to forward traffic to upstream using Openshift Route hostname

Description

Not be able to connect and forward traffic to an upstream server using Openshift Route hostname

Environment

  • NGINX Plus
  • Openshift Route 

Cause

To connect to an server using Openshifit Route hostname, it's a must to set the request Host header value as the Openshifit Route hostname. However, NGINX has no variable to get the selected upstream server hostname.

Recommended Actions

Here is a workaround to set the request Host header as the selected Openshifit Route hostname by following the steps below:

  1. Create an upstream block for each upstream server (Openshifit Route hostname)
  2. Split the traffic evenly to the defined upstreams via the split_clients directive
  3. Set the host header and then forward traffic to the upstream server(Openshifit Route hostname) accordingly

An example configuration is as follows:

http {
    resolver <your_dns_server>;

    # Create an upstream block for each Openshifit Route hostname
    # make sure the upstream block name is the same as the Openshift Route hostname
    upstream openshift-upstream.example.one {
        server openshift-upstream.example.one resolve;
    }

    upstream openshift-upstream.example.two {
        server openshift-upstream.example.two resolve;
    }

    # Split the traffic evenly to the defined upstreams.
    split_clients $request_id $backend {
        50%  openshift-upstream.example.one;
        *    openshift-upstream.example.two;
    }

    # Set the host header and forward the traffic to the upstream server accordingly 
    server {
        listen 80;
        server_name example.com;
        location / {
            proxy_set_header Host $proxy_host;
            proxy_pass http://$backend;
        }
    }
}
