Description

After changing the Kerberos Account Password Kerberos SSO starts to fail. 

  • Kerberos SSO authentication fails
  • APM logs will have a Permission denied (13) error messages after the following scenarios:
    • Restarting WebSSO
    • Reboot 
    • A user attempts to authenticate through the Access Policy
  • A similar error message will appear in /var/log/apm
    • err websso.3[12003]: 014d0056:3: (null):Common:00000000:Kerberos: can't init kerb_context - Permission denied (13)
  • Examples of incorrect file permissions:
    • ----------. 1 root root 619 Feb 28 12:49 /etc/krb5.conf
    • ----r--r--. 1 root root 619 Feb 28 12:49 /etc/krb5.conf
    • --w-r--r--. 1 root root 619 Feb 28 12:49 /etc/krb5.conf

Environment

  • Kerberos SSO profile
  • Access Policy using Kerberos SSO
  • Device Group with Auto-Sync Enabled

Cause

This issue is related to the Owner file permissions of the /etc/krb5.conf not having Read/Write permissions set.
The cause of the krb5.conf file permission change is unknown at this time. 

Recommended Actions

Perform the following step to verify and resolve the file permission issues.
The correct file permissions of /etc/krb5.conf should appear as:

-rw-r--r--. 1 root root 619 Feb 28 12:49 /etc/krb5.conf

  1. SSH into the BIG-IP
  2. At the (tmos) prompt run:
    • run /util bash
  3. Verify that you are seeing the Permission denied (13) error messages
    • grep -i "permission denied" /var/log/apm
  4. If there are Permission denied (13) error messages, verify the krb5.conf file permissions
    • ll /etc/krb5.conf
  5. If the file permissions are not -rw-r--r--. run the following to fix the file permissions
    • chmod 644 /etc/krb5.conf
  6. Verify that the krb5.conf file is now showing the correct permissions
    • ll /etc/krb5.conf
