K000133165: AspenMesh - Accessing External Services.

Type
Support Solution
Published
2023-04-14
Updated
2023-04-14
Applies to
  • Aspen Mesh: 1.14, 1.5, 1.6, 1.9, 1.11, 1.X.X
Source
https://my.f5.com/manage/s/article/K000133165

Description

All TCP outbound connections from a POD being part of Istio mesh is being redirected to istio-proxy sidecar. This includes DNS over TCP connections and connections from init-containers. UDP traffic is not being intercepted and proxied by Istio sidecar.

To improve security Aspenmesh is by default configured with default-deny outbound traffic policy to block all outgoing traffic from the POD to external services. To allow the connectivity to external services, users have to explicitly specify the service they want to connect to by creating ServiceEntry object.

Istio opensource distribution uses different approach and it allows all outbound traffic from the POD.

The global traffic policy is configured in Aspenmesh and Istio via meshConfig.outboundTrafficPolicy.mode parameter. In this article we will describe how to disable the default outbound policy globally, on a specific namespace or on PODs with specific labels.

Environment

  • Kubernetes: 1.17x -1.24.x 
  • Aspen Mesh: 1.9.x, 1.11.x, 1.14.x  

Cause

In case the external service has not been configured with ServiceEntry and is not added to Istio Service Registry then the traffic will be blocked by istio-proxy sidecar and users will receive "502 Bad gateway" error message for HTTP services and TCP RST for TCP services.

Example of istio-proxy Access Logs indicating the application trying to connect to unknown external service:

Recommended Actions

Global and default outbound traffic policy is controlled by Helm override values.yaml file used to install istiod chart.
Here is the default policy present in the pre-configured values.yaml file attached to istiod chart: 
meshConfig:
  # services or ServiceEntries for the destination port
  # REGISTRY_ONLY - restrict outbound traffic to services defined in the service registry
  outboundTrafficPolicy:
    mode: REGISTRY_ONLY

To change the global policy to ALLOW_ANY and to allow outbound connections to all services we have to change the policy like below:

# aspen-mesh-override-values.yaml file
meshConfig:
  outboundTrafficPolicy:
    mode: ALLOW_ANY

and run helm upgrade command:
 

helm upgrade istiod manifests/charts/istio-control/istio-discovery -n istio-system --values aspen-mesh-override-values.yaml


To control the default outbound policy for a specific namespace or for PODs having specific labels we can use Sidecar CRD.
Example 1: default outbound policy for all PODs with sidecars deployed in a namespace  <namespace>

apiVersion: networking.istio.io/v1beta1
kind: Sidecar
metadata:
  name: allow-any-namespace
  namespace: <namespace>
spec:
  outboundTrafficPolicy:
    mode: "ALLOW_ANY"


Example 1: default outbound policy for all PODs with sidecars deployed in a namespace  <namespace> and with label 'policy: allowany'

apiVersion: networking.istio.io/v1beta1
kind: Sidecar
metadata:
  name: allow-any-selector
  namespace: <namespace>
spec:
  workloadSelector:
    labels:
      policy: allowany
  outboundTrafficPolicy:
    mode: "ALLOW_ANY"
