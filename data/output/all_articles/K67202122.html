Topic

The maximum number of cached entries in Kerberos single sign-on (SSO) is currently 20,000.

Description

BIG-IP APM provides Kerberos SSO for seamless authentication to application web servers. When a client accesses an application that requires a Kerberos ticket, the system first looks into the ticket cache before sending a query to the Key Distribution Center (KDC). Currently, the maximum number of cached entries is set at 20,000. When the number of unique concurrent users exceeds 20,000, the number of ticket requests to the KDC increases in the network. The new tickets are saved in cache and the older ones are evicted. Under heavy load, when the number of users continues to increase further, the system can enter a state in which it continuously evicts old cached entries and saves new ones. This leads to high CPU usage, causing a decrease in the performance of the BIG-IP APM system in handling HTTP requests. As a result, users may experience increased latency when accessing applications.

For more information about Kerberos credential caching, refer to the Kerberos Single Sign-On Method chapter of the BIG-IP Access Policy Manager: Authentication and Single Sign-On manual.
