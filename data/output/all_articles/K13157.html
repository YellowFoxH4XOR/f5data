Known Issue

When a file lock is encountered during a directory delete operation, the ARX may encounter a rare race condition and fail to completely remove all records for a deleted shadow volume directory. As a result, if a subsequently enabled shadow-copy-rule encounters the remnants of that directory, the shadow copy operation fails with Invalid Compression Format error messages.

This issue occurs when all of the following conditions are met:

  • The ARX encounters a file lock when initially attempting to delete the directory
  • After the file lock has cleared, the directory is deleted but not completely removed from an internal ARX database
  • A subsequently enabled shadow-copy-rule attempts to shadow the directory that had been previously deleted

Impact

Shadow copy operations may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The shadow copy report will contain error messages that appear similar to the following example:

    : Target ARX2: CIFS-NS:/TARGET_VOL/ reported error:
    : % ERROR: (13):
    : Directory[] Synchronize failed; DNAS error -104; Invalid Compression Format
  • The ARX will log Invalid Compression Format error messages that appear similar to the following example:

    :DNAS_PGRP-1-INFO-MSG6:: Failed to retrieve entry attributes unexpectedly for d:0x100000000007b f:0 v:0: Invalid Compression Format
    :DNAS_PGRP-1-ERR-MSG3:: DFM_FILE_ASSERT: "Invalid Compression Format" : dnasdfmcompress.c:dfm_get_entry_flags():357
