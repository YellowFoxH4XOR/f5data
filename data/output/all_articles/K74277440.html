K74277440: BIGIP FPS stopped working after FPS signature update

Type
Support Solution
Published
2020-07-29
Updated
2023-02-21
Applies to
  • Virtual Editions
  • Legacy Products
  • BIG-IP Platforms
  • F5 WebSafe
Source
https://my.f5.com/manage/s/article/K74277440

Description

BIGIP FPS  fails to inject Javascript in protected sites after the FPS Signature update. You may notice the below error message in the log file. 
 
<13> Feb 20 01:24:52 LTM1.example.com notice FPM - fpm.c:6570 Not enough memory to seal json config.
<13> Feb 20 01:24:52 LTM1.example.com notice FPM - fpm.c:6983 fpm_securemsg_config failed, err = 18
<13> Feb 20 01:24:52 LTM1.example.com notice FPM - fpm.c:6860 Server response parsing failed err=18

Environment

  • BIGIP  FPS
  • Version 12
  • Websafe 
  • Singature Update

Cause

In BIG-IP V12.1.2 default value of antifraud.globalbuffersize DB Key is set to 15360 and when the FPS signatures are updated, and the size of the updated signatures is above the buffer limits the javascript injection fails.

LTM1.example.com# tmsh list sys db antifraud.globalbuffersize all-properties
sys db antifraud.globalbuffersize {
    default-value "15360"
    scf-config "true"
    value "15360"
    value-range "unsigned integer min:64 max:100000"
}

Recommended Actions

To work around the issue, increase the default value of the DB Key to a higher value. 
  1. Increase the default value of the DB Key 
    # tmsh modify sys db antifraud.globalbuffersize  value 50000
  2.  Save the updated values
    # tmsh save sys config
  3. Update the FPS signature and verify the javascript injection is working as expected.
