Description

After replacing the Device Certificate with a CA signed cert, you find the Configuration Utility (GUI) is unavailable

When accessing the CLI, you constantly see messages indicating big3d is restarting

You see the below lines repeat constantly in /var/log/gtm:

Apr 16 12:11:49 bigip1 notice big3d[24359]: 012b0000:5: big3d Version <Your BIG-IP version> started ===============================
Apr 16 12:11:49 bigip1 notice big3d[24359]: 012b700b:5: Route Domain support detected.
Apr 16 12:11:49 bigip1 err big3d[24359]: 012b3001:3: Private key /config/httpd/conf/ssl.key/server.key did not load  <<<<<<<<<<<<<<
Apr 16 12:11:49 bigip1 err big3d[24359]: 012b3003:3: CreateSSL_CTX: SSL error:0B080074:x509 certificate routines:X509_check_private_key:key values mismatch  <<<<<<<<<<<<<
Apr 16 12:11:49 bigip1 notice big3d[24459]: 012b0014:5: Current executable path is /usr/sbin/big3d. Checking for existence of /shared/bin/big3d.
Apr 16 12:11:49 bigip1 notice big3d[24459]: 012b001f:5: Modification time(1610735847) is Fri Jan 1 00:13:08 2021 for executable '/usr/sbin/big3d'.
Apr 16 12:11:49 bigip1 notice big3d[24459]: 012b001f:5: Modification time(1610735847) is Fri Jan 1 00:13:08 2021 for executable '/shared/bin/big3d'.
Apr 16 12:11:49 bigip1 notice big3d[24459]: 012b0020:5: Executable /shared/bin/big3d timestamp is newer than (or the same as) /usr/sbin/big3d.
Apr 16 12:11:49 bigip1 notice big3d[24459]: 012b0021:5: Executable /usr/sbin/big3d version 'big3d Version <Your BIG-IP version>'.
Apr 16 12:11:49 bigip1 notice big3d[24459]: 012b0021:5: Executable /shared/bin/big3d version 'big3d Version <Your BIG-IP version>'.
Apr 16 12:11:49 bigip1 notice big3d[24459]: 012b0018:5: Respawning to run /shared/bin/big3d.

Environment

  • BIG-IP
  • After replacing BIG-IP Device Certificate

Cause

From these error messages, it shows the new Device CA Certificate does not match the private key, or that the private key is missing

Recommended Actions

If you find that the key and certificate don't match, or that the key is missing, you may try uploading a fresh copy of the key to the device and running the verification in 

  1. Confirm the new Device Certificate and Key match.
    • K13349: Verifying SSL certificate and key pairs from the command line (11.x - 16.x) 
      # openssl x509 -in <path_to_device_cert>/<cert_name> -pubkey -noout | md5sum
# openssl <rsa|dsa|ec> -in <path_to_device_key>/<key_name> -pubout | md5sum

If these still don't validate, you will need to get a new CA signed certificate from the previous CSR. The steps below to restore access to the Configuration Utility

  1.   Stop the big3d process with the following command: 
          bigstart stop big3d
  2. To re-gain access to the Configuration Utility, you can generate new self-signed certs.
    • K9114: Creating a new SSL device certificate and key pair
       
  3. Once this is done, you will need to restart http process as well as restart the big3d process: 
          bigstart restart httpd

          bigstart start big3d
  4. Once access is restored, follow the steps to replace the device Certificate
    • K16951115: Changing the BIG-IP system device certificate using the Configuration utility
