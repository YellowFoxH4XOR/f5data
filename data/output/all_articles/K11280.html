K11280: The BIG-IP WebAccelerator erroneously applies pv tags to frame and iframe objects that do not reference IBR-eligible objects

Known Issue

This is the result of a known issue. If a frame or iframe object contains no links for which IBR (Intelligent Browser Referencing) rewrites are required, the system erroneously assigns a pv tag to the frame or iframe object itself and populates it within the etag cache. As a result, frame or iframe objects containing dynamically generated HTML may be cached and served inappropriately.

Note: The Enable Intelligent Browser Referencing check box is located on the Acceleration Rules > Assembly tab.

Note: Frame and objects are the objects defined within an HTML tagset beginning with <frame src="..."> or <iframe src="...">.

With IBR enabled, eligible objects other than HTML, such as CSS, JavaScript, and images, are assigned a pv tag and populated into the etag cache. HTML objects containing links to such eligible objects are rewritten so that each link references the cached version of the object, but are not intended to be pv tagged.

Since frame and iframe objects typically contain only HTML, their embedded objects should be eligible for IBR when it is enabled, and the frame/iframe object should be rewritten to include pv tagged links for such objects. However, if a frame or iframe object contains no IBR eligible links, and is not rewritten, the system pv tags the frame itself and populates it within the etag cache.

F5 Product Development tracked this issue as CR123166, and it was fixed in BIG-IP WebAccelerator version 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

You can work around this issue by configuring the pages containing problematic frames/iframes for the always proxy option on the Acceleration Rules > Proxying tab. This action does not turn off the IBR rewriting of the frame to include pv tags for eligible embedded objects, but it prevents the frame itself from being pv tagged.
