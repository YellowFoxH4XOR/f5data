Known Issue

Authentication against Oracle Access Manager (OAM) through the BIG-IP APM system redirects the user to an OAM error page.

This issue occurs when all of the following conditions are met:

  • The OAM Support feature is enabled on the virtual server.
  • The AccessGate setting on the virtual server is set to something other than Default

Impact

Users cannot access OAM protected resources through the BIG-IP APM system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • User receives the following error:

    Oracle Access Manager Operation Error

    Access to the URL / has been denied.
    Contact your website administrator to remedy this problem.

  • The system logs the following error in the /var/log/apm file.

    err eam: 01490000:3: : ctx: 0x5a6a5688, host header validation check failed, access denied, status: 32

Workaround

To work around this issue, you can set the Access Gate back to default. To do so, perform the following procedure:

Impact of workaround: There will be a brief interruption in OAM authentication when the eam daemon restarts. Using the default access gate may limit redundancy.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click the name of the virtual server that contains the OAM AccessGate.
  5. In the Access Policy section, from the AccessGate menu, select Default.
  6. Click Update.
  7. Log in to the command line.
  8. Type the following command:

    bigstart restart eam
