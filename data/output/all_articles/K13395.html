Known Issue

The session inactivity time-out expiration time is not updated by network traffic flowing through the network access tunnel.

This issue occurs when the following condition is met:

  • The Session Update Window parameter is set to a value of less than 2.
  • The Session Update Threshold parameter is set to a value greater than 0.

An Access Policy Manager (APM) network access resource has an option to extend the session inactivity time-out if the network traffic exceeds the threshold defined in the resource. There are two parameters that are defined in the network access resource: Session Update Threshold and Session Update Window. The Session Update Window, along with the volume of network traffic, are used in an Exponential Moving Average (EMA) algorithm and compared to the Session Update Threshold to determine if the inactivity timeout time should be extended. The Session Update Threshold works in conjunction with the Inactivity Timeout, so the traffic needs to both fall below the specified Session Update Threshold and exceed the Inactivity Timeout (default value 900 seconds) for the connection to close. 

Due to the way the algorithm calculates the window, a window smaller than two will result in a value of 0 for traffic volume. Additionally, the sample window is taken at five-second intervals, resulting in a network traffic sample size that is five times greater than the sample rate used in the calculations.

Note: HTTP traffic is calculated separately and properly updates the session expiration time.

Impact

The inactivity timeout counter does not get reset correctly, and user sessions may terminate prematurely.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • User sessions terminate prematurely.
  • The Expiration time is not updated in the session report. The reports can be viewed in the following locations:
    • BIG-IP 13.x:

      Access > Overview > Active Sessions

    • BIG-IP 11.x through 12.x:

      Access Policy > Manage Sessions

    • BIG-IP 10.x

      Access Policy > Reports > Current Sessions

Workaround

To work around this issue, you can set the Session Update Window to a value greater than 1 and set the Session Update Threshold to five times the desired value. To do so, perform the following procedure for your version:

  • Updating BIG-IP 13.x and later
  • Updating BIG-IP 10.x through 12.x

Updating BIG-IP 13.x and later

Impact of workaround: Performing the following procedure should not have a negative impact on your system

  1. Log in to the Configuration utility.
  2. Go to Access >  Connectivity / VPN > Network Access Lists.
  3. Select the name of the Network Access resource to edit.
  4. Select the Network Settings tab.
  5. For General Settings, select Advanced.
  6. For Session Update Threshold, enter the number of bytes, multiplied by five, for the threshold.
  7. For Session Update Window, enter a window size to an average that is 2 or greater.
  8. Select Update.

Updating BIG-IP 10.x through 12.x

Impact of workaround: Performing the following procedure should not have a negative impact on your system

  1. Log in to the Configuration utility.
  2. Go to Access Policy > Network Access.
  3. Select the name of the Network Access resource to edit.
  4. Select the Network Settings tab.
  5. For General Settings, select Advanced.
  6. For Session Update Threshold, enter the number of bytes, multiplied by five, for the threshold.
  7. For Session Update Window, enter a window size to an average that is 2 or greater.
  8. Select Update.
