Issue

Old Behavior

Note: BIG-IP WebAccelerator and BIG-IP WOM were combined to create BIG-IP AAM in 11.4.0.

In versions prior to BIG-IP WebAccelerator 11.0.0,  when the Intelligent Browser Referencing (IBR) feature processes an object, the system appends a unique tag to both absolute and relative URIs that are embedded within that object.

For example:

Review the following example response from the origin server:

<html><body>
this is an image link:<br>
<img src=../myimage.jpg>
</body></html>

With IBR enabled, this response would be rewritten as follows:

<html><body>
this is an image link:<br>
<img src=../myimage.jpg;pv8fe8f6f4496837da11cad298f0a4fdef>
</body></html>

The URI is not modified, but a pv tag is appended.

New Behavior

Beginning in BIG-IP WebAccelerator 11.0.0 and Application Acceleration Manager 11.4.0, if an object is processed by IBR, and the object contains a link to a relative URL, the BIG-IP WebAccelerator rewrites the link to an absolute URL and then appends the unique IBR tag to the URL.  If an object processed by IBR contains a link to an absolute URL, the BIG-IP WebAccelerator does not rewrite the URL prior to appending an IBR tag.

The following response contains a link to a relative URL and is used in all of the following examples:

<html><body>
this is an image link:<br>
<img src=../myimage.jpg>
</body></html>

IBR rewriting for HTTP traffic

If the BIG-IP WebAccelerator system receives the previous example request with IBR enabled, the BIG-IP WebAccelerator rewrites the relative URL similar to the following example:

<html><body>
this is an image link:<br>
<img src=http://hostname.domain.com/<path_segment>/myimage.jpg;wad0c540d091d9ab1e>
</body></html>

In the previous example, note the following:

  • <path_segment> is the path segment from the original HTTP request

IBR rewriting for HTTPS traffic

If the BIG-IP WebAccelerator virtual server is using a client Secure Socket Layer (SSL) profile for SSL offloading, relative URLs processed by IBR are correctly rewritten with the https:// protocol even though the origin web server is receiving an http:// request.  Absolute URLs are not rewritten with https:// before appending an IBR tag.

Using the previous relative URL example, a BIG-IP WebAccelerator virtual server configured with a client SSL profile for SSL offloading, produces a response that appears similar to the following example:

<html><body>
this is an image link:<br>
<img src=https://hostname.domain.com/<path_segment>/myimage.jpg;wad0c540d091d9ab1e>
</body></html>

In the previous example, note the following:

  • <path_segment> is the path segment from the original HTTP request

IBR rewriting when an upstream device performs an SSL offload

If a BIG-IP WebAccelerator system receives HTTP requests from an external host performing SSL offloading, the BIG-IP WebAccelerator system does not rewrite relative or absolute URLs using https://.

Using the previous relative URL example, a BIG-IP WebAccelerator virtual server with SSL offloading performed by an external host would produce a response that appears similar to the following example:

<html><body>
this is an image link:<br>
<img src=http://hostname.domain.com/<path_segment>/myimage.jpg;wad0c540d091d9ab1e>
</body></html>

F5 Product Development tracked this change as ID 409312.

Impact

Embedded links in an accelerated object may point to the incorrect URL when using an external SSL offload device, or when the links use absolute URLs and the BIG-IP system handles the SSL offloading.

Recommended Actions

When using an upstream device for SSL offload, you may need to configure the SSL offload device to pass SSL traffic to the BIG-IP WebAccelerator system with a Client SSL profile enabled.

Note: If the upstream SSL offload device is a BIG-IP system, configure the upstream BIG-IP system to do SSL offload; for additional information, refer to K14294: Configuring the BIG-IP WebAccelerator system to use an upstream BIG-IP LTM system to perform an SSL offload.
