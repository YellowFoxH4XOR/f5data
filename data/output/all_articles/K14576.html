Known Issue

In rare occasions, the VIPRION blade may fail to update the Host PIC firmware.

This issue occurs when all of the following conditions are met:

  • The VIPRION blade is one of the following types:
    • B4100 (A100)
    • B4200 (A107)
    • B4300 (A108)
  • The VIPRION blade is attempting to install a newer Host PIC firmware version

The system performs a firmware update when it determines that the firmware installed on the Host PIC is older than the firmware included in the system during boot time. Depending on the firmware version included in BIG-IP versions of different builds/hotfixes, switchbooting between them may trigger a firmware update.

Impact

The VIPRION blade is unable to boot properly and fails to join the cluster.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H426994 on the Diagnostics > Identified > High page.
  • The VIPRION blade is unable to boot properly.
  • The Host PIC is in an inoperative state, which prevents the VIPRION blade from starting properly. In addition, you observe error messages during the boot process that appear similar to the following example:

    read boot ver failed. Cand status(11) PIC Program Boot Command Failed
    get pic ids failed. Cand status(4) Bad Can Id/Port
    PIC bootloader mode failed. Cand status(5) CAN request Timeout

    Starting cand: unable to obtain slot (CAN status:4)
    error: unable to obtain slot over CAN : Unable obtain slot - reply status error
    /etc/rc3.d/S13cand: line 24: [: : integer expression expected
    unable to obtain slot (CAN status:4)

  • In the /var/log/ltm file, you observe an error message that appears similar to the following example:

    PIC is DOWN. Unable to contact after programming.

Resolution

Status

F5 Product Development has assigned ID 389257 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the top right corner of the article. Workaround

The VIPRION blade is typically capable of recovering the Host PIC from an inoperative state automatically. However, it is possible that the VIPRION blade may fail to recover the Host PIC automatically due to other issues. When this occurs, you must perform a clean installation on the affected VIPRION blade using BIG-IP 11.3.0 to recover the blade. To do so, perform the procedures described in K13117: Performing a clean installation of BIG-IP 11.x - 13.x or Enterprise Manager 3.x.

Impact of workaround: Performing a clean installation on the affected blade will destroy all information on that blade and should be performed during a maintenance window if the affected blade is the only blade in the VIPRION system.
