Topic

You should consider using this procedure under the following condition:

  • You want to change the IP addresses on a BIG-IP Link Controller system when moving the system from one network to another; for example, moving the system from a test environment to a production environment.

Description

When you move a BIG-IP Link Controller system from one network to another, you should always add the new self IP addresses to the system before removing the existing self IP addresses, and then update the configuration with the new self IP addresses. Performing the desired change in this sequence allows the BIG-IP Link Controller system to successfully establish the iQuery connections and properly rediscover the servers for the configuration. This applies to BIG-IP Link Controller systems in a high availability (HA) configuration.

Note: If you delete the existing network configuration before adding the new network configuration, the iQuery connections fail to establish and the BIG-IP Link Controller system does not function as expected.

Additionally, the BIG-IP Link Controller Configuration utility does not provide any means of modifying the server objects in the configuration. As a result, you have to manually modify the server objects in the configuration using the TMOS Shell (tmsh) utility.

Note: In the following procedures, F5 assumes that the HA configuration is functional throughout. If the self IP address that is currently used for the HA configuration needs to be changed, then you must ensure that the HA configuration is up and running before proceeding with the following procedures.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must perform this procedure during a maintenance window; many of the required steps will affect traffic processing.
  • You must have administrative access to the BIG-IP Link Controller system.
  • You must have tmsh access for BIG-IP Link Controller systems that are in a HA configuration for 12.1.2 and earlier.

Required Steps

  1. Adding the new self IP addresses
  2. Adding the new gateways to the gateway pool
  3. Updating links with the new gateway IP addresses
  4. Removing the old gateways from the gateway pool
  5. Adding the new listeners and removing the old listeners on the BIG-IP Link Controller
  6. Updating the HA configuration (applicable for systems in an HA configuration)
  7. Removing the previous self IP addresses
  8. Syncing the configuration to the peer system (applicable for systems in an HA configuration)
  9. Updating the BIG-IP Link Controller configuration with the new self IP addresses (12.1.2 and earlier)
  10. Updating the pools by adding pool members with the new IP addresses before removing the existing ones
  11. Updating the virtual servers with the new IP addresses
  12. Updating the wide IPs with the virtual servers that have new IP addresses

Step 1: Adding the new self IP addresses

Before you remove the existing network information, you must first add the new self IP addresses. 

  1. Log in to the Configuration utility.
  2. Navigate to Network > Self IPs.
  3. Click Create.
  4. Enter the new network information, such as Name, IP Address, and Netmask, as appropriate.
  5. From the VLAN/Tunnel box, select the appropriate VLAN.
  6. From the Port Lockdown box, select the appropriate option that allows the system to establish iQuery communications through TCP port 4353, for example, Allow Default.
  7. From the Traffic Group box, select the traffic-group-local-only (non-floating) item for the self IP address local to the system.
    For floating self IP addresses, from the Traffic Group box, select the appropriate floating traffic group, for example, traffic-group-1 (floating).
  8. Configure the remaining settings, as required.
  9. Click Finished.
  10. Repeat Steps 3 through 9 for each new self IP address.
  11. If the system is part of an HA pair, repeat these steps on the peer system.

Step 2: Adding the new gateways to the gateway pool

After adding the new self IP addresses, you should proceed to update the gateway pool with the new gateways before removing the old ones. 

  1. From the Configuration utility, navigate to Local Traffic > Pools > Pool List.
  2. Click the name of the gateway pool.
  3. Click the Members tab.
  4. Click Add.
  5. In the Address box, enter the new gateway IP address, as appropriate.
  6. Click the *All Services from the Service Port box.
  7. Configure the remaining settings, as appropriate, for your environment.
  8. Click Finished.
  9. Repeat Step 5 through 8 for each new gateway.

Step 3: Updating links with the new gateway IP addresses

When you have added the new gateways to the gateway pool, you must update the links with the new IP addresses. You need to perform this procedure on only one system, even if it is part of an HA pair, as the BIG-IP Link Controller configuration will automatically synchronize. 

  1. From the Configuration utility, navigate to Link Controller > Links > Link List.
  2. Click the link to be modified.
  3. In the Router Address box, type the new gateway IP address.
  4. Click Update.
  5. Repeat Steps 2 through 4 for each new link.

Step 4: Removing the old gateways from the gateway pool

After you have updated the Links configuration, you can remove the old gateway from the gateway pool.

  1. From the Configuration utility, navigate to Local Traffic > Pools > Pool List.
  2. Click the name of the gateway pool.
  3. Click the Members.
  4. Select the check boxes for the old gateways and click Remove.

Step 5: Adding the new listeners and removing the old listeners on the BIG-IP Link Controller (optional)

Before removing the old self IP addresses, you should update the listeners with the new IP addresses, if applicable.

  1. From the Configuration utility, navigate to Link Controller > Listeners.
  2. Click Create.
  3. In the Destination box, enter the listener IP address.
  4. Configure the remaining settings, as appropriate, for your environment.
  5. Click Finished.
  6. Repeat Steps 3 through 6 for each new listener.
  7. Select the check boxes for the old listeners and click Delete.
  8. To confirm removal, click Delete.
  9. If the system is part of an HA pair, before proceeding to the next procedure, perform a configuration synchronization to the peer system using the Step 8: Syncing the configuration to the peer system.

Step 6: Updating the HA configuration (applicable for systems in an HA configuration)

Before removing the old self IP addresses, you should update the high availability configuration to use the new self IP addresses if applicable. 

  1. From the Configuration utility, navigate to Device Management > Devices > Device-Name (Self).
  2. Click the Device Connectivity > ConfigSync tab.
  3. Select the new IP address from the Local Address drop-down.
  4. Click Update.
  5. Click the Device Connectivity > Failover tab or Network Failover tab for devices running 11.5.0 and later.
  6. Check the old IP address and click Delete.
  7. Click Add.
  8. Select the new IP address from the Address drop-down.
  9. Click Finished.
  10. Click the Device Connectivity > Mirroring tab.
  11. Select the new IP address from the Primary Local Mirror Address drop-down.
  12. Click Update.
  13. If the system is part of an HA pair, repeat these steps on the peer system.

Step 7: Removing the previous self IP addresses

When you have updated the listeners, you can proceed to remove the old self IP addresses.

  1. From the Configuration utility, navigate to Network > Self IPs > Self IP List.
  2. Select the check boxes for the previous floating self IP addresses, and click Delete.
  3. To confirm removal, click Delete.
  4. Select the check boxes for the previous local self IP addresses, and click Delete.
  5. To confirm removal, click Delete.
  6. If the system is part of an HA pair, before repeating these steps to remove the previous self IP addresses on the peer system, perform a configuration synchronization to the peer system using Step 8: Syncing the configuration to the peer system.

Step 8: Syncing the configuration to the peer system (applicable for systems in an HA configuration)

You should always perform the configuration synchronization from the system with the latest changes.

BIG-IP 11.2.1 and later

  1. From the Configuration utility of the system with the latest changes, navigate to Device Management > Overview.
  2. Under Device Groups, select the name of the device group containing the HA pair.
  3. Under the Devices section, select the device on which you made the changes, indicated by (self).
  4. From the Sync box, select Sync device to group or Push the selected device configuration to the group for devices running 13.0.0 and later.
  5. To sync the changes to the peer system, click Sync.

BIG-IP 11.0.0 through 11.2.0

  1. From the Configuration utility of the system with the latest changes, navigate to Device Management > Device Groups > Device Group List.
  2. Click the name of the device group containing the HA pair.
  3. Click the ConfigSync tab.
  4. To sync the changes to the peer system, click Synchronize To Group.

Step 9: Updating the BIG-IP Link Controller configuration with the new self IP addresses (12.1.2 and earlier)

After syncing the configuration, proceed to update the Link Controller configuration replacing the previous self IP addresses with the new self IP addresses. You need to perform this procedure on only one system even if it is part of an HA pair, as the Link Controller configuration will synchronize automatically. 

Important: As of BIG-IP 13.0.0 and later, the BIG-IP Link Controller system will correctly modify and synchronize the BIG-IP Link Controller configuration, provided the default gateway pool members and HA configuration have been updated.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Update the server object in the Link Controller configuration with the new self IP addresses by typing the following command syntax:

    modify gtm server <Link Controller system name> addresses replace-all-with { <unit 1 self IP 1> <unit 1 self IP 2>...{ device-name <device A name> } <unit 2 self IP 1> <unit 2 self IP 2>...{ device-name <device B name> } }

    For example, you would enter the following command to update the server object lc1.example.com with the new self IP addresses 192.168.50.14, 192.168.60.14 for device lc1.example.com and 192.168.50.15, 192.168.60.15 for device lc2.example.com:

    modify gtm server lc1.example.com addresses replace-all-with { 192.168.50.14 192.168.60.14 { device-name lc.example.com_1 } 192.168.50.15 192.168.60.15 { device-name lc.example.com_2 } }

  3. Save the changes by typing the following command:

    save sys config gtm-only

Step 10: Updating the pools by adding pool members with the new IP addresses before removing the existing ones

If you require the pool members to change IP addresses after you have successfully performed all of the previous procedures, you can now proceed to update the pool members through the Configuration utility. 

  1. From the Configuration utility, navigate to Local Traffic > Pools > Pool List.
  2. Click the name of the desired pool.
  3. Click the Members tab.
  4. Click Add.
  5. In the Address box, enter the new IP address, as appropriate.
  6. In the Service Port box, enter the appropriate service port number.
  7. Configure the remaining settings, as appropriate, for your environment.
  8. To save the changes, click Finished.
  9. Repeat Step 5 through 9 for each member with the new IP address.
  10. Select the check boxes for the old pool members and click Remove.

Step 11: Updating the virtual servers with the new IP addresses

If you require the virtual servers to change IP addresses after you have successfully performed all of the previous procedures, you can now proceed to update the virtual servers through the Configuration utility. 

  1. From the Configuration utility, navigate to Local Traffic > Virtual Servers > Virtual Server List.
  2. Click the name of the desired virtual server.
  3. In the Destination Address box, enter the new IP address.
  4. Click Update.
  5. Repeat Steps 2 to 5 for each virtual server with a new IP address.
  6. If the system is part of a HA pair, before performing the next procedure, perform a configuration synchronization to the peer system using the Syncing the configuration to the peer system procedure.

Step 12: Updating the wide IPs with the virtual servers that have new IP addresses

If you have updated the virtual servers with new IP addresses, the BIG-IP Link Controller system will automatically remove the virtual servers from their wide IP assignments. You must manually reassign the virtual servers to the wide IPs through the Configuration utility. You need to perform this procedure on only one system, even if it is part of a HA pair, as the Link Controller configuration will synchronize automatically. 

  1. From the Configuration utility, navigate to Link Controller > Inbound Wide IPs > Wide IP List.
  2. Click the name of the desired wide IP.
  3. Click the Members tab.
  4. Click Manage.
  5. From the Virtual Server box, select the desired virtual server, and click Add.
  6. Repeat Step 6 for each virtual server that needs to be assigned to the wide IP.
  7. Click Finished.
