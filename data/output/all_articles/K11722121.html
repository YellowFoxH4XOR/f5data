K11722121: Portal Access split tunneling with a bypass list requires a non-empty rewrite list

Type
Support Solution
Published
2022-07-01
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K11722121

Description

When you enable Split Tunneling for Portal Access in the Rewrite profile and you create one or more entries in the Bypass List, you must also create entries in the Rewrite List.
With Split Tunneling enabled, the BIG-IP APM only rewrites links to URIs that match entries in the Rewrite List.

Environment

  • BIG-IP APM
  • Portal Access
  • Rewrite profile

Cause

When matching URIs in Bypass and Rewrite Lists, the BIG-IP APM system matches as follows:

  • The BIG-IP APM system first attempts to match against entries in the Bypass List.  The BIG-IP APM system does not rewrite links for URIs that match entries in the Bypass List. 
  • URIs that do not match any entries in the Bypass List are then compared to entries in the Rewrite List.  If the URI matches entries in the Rewrite list, the URI links are rewritten. If there are no matches, the links are not rewritten. 
  • If the URI matches entries in neither the Bypass List nor the Rewrite List,  and the host name in the URI uses the short name, or partially-qualified domain name (PQDN), rather that the fully-qualified domain name (FQDN) of the host, the BIG-IP APM system rewrites links for that URI.
  • If the Rewrite List is empty, no URIs will match and no links will be rewritten unless the host name in the URI uses the short name.

In the following example Rewrite profile, the Bypass List has one entry, http://www.example.com*, and rewrite-list is set to none indicating the Rewrite List is empty:

 ltm profile rewrite example_rewrite {
    app-service none
    bypass-list { http://www.example.com* }
    client-caching-type cache-css-js
    defaults-from rewrite
    location-specific false
    response {
        rewrite-content enabled
        rewrite-headers enabled
    }
    rewrite-list none
    rewrite-mode portal
    split-tunneling true
...
}

Use the two links from above as an example:

  • <a href="//host1.example.com/index.html">
  • <img src="/images/sample.png">

The system would not rewrite either link with this configuration. However, the following link would be rewritten, because it does not match any entries in the Bypass List or the Rewrite List (empty), and the host name in the URI uses the short name:

  • <a href="//host1/index.html">

Recommended Actions

Adding the expressions http://* and https://* to the Rewrite List allows the system to rewrite other example links:

 ltm profile rewrite example_rewrite {
    app-service none
    bypass-list { http://www.example.com* }
    client-caching-type cache-css-js
    defaults-from rewrite
    location-specific false
    response {
        rewrite-content enabled
        rewrite-headers enabled
    }
    rewrite-list { http://* https://* }
    rewrite-mode portal
    split-tunneling true
...
}

The BIG-IP system does not rewrite URI links that do not match entries in the Rewrite List unless the host name in the URI uses the short name.  If no entries exist in the Rewrite List, the system rewrites only URI links that use the short name for the host name.
