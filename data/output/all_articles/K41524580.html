Known Issue

The BIG-IP configuration with mismatched management IP and unicast failover IP will fail to load after you perform an upgrade.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP system with a high availability (HA) configuration that uses the management IP address as the unicast failover IP address for network failover.
  • You change the management IP address of the BIG-IP system without updating the unicast failover IP address in the network failover configuration.
  • You attempt to upgrade the system to BIG-IP 11.3.0 through 11.6.1.

It is a best practice to have both the management IP address and a Traffic Management Microkernel (TMM) network address configured in the network failover settings, to ensure a more stable network failover configuration. However, a change in the management IP address does not automatically update the network failover settings. If the unicast failover IP address is not updated accordingly, it will result in a mismatched configuration that will cause subsequent software upgrades to fail.

Important: Changing the management IP address for BIG-IP 11.x and later will cause the device trust for device group members to be reset and may result in a disruption of network failover traffic. For more information, refer to K7312: Overview of the management port.

Impact

The BIG-IP configuration fails to load after you upgrade the BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H62673 on the Diagnostics > Identified > Medium screen.
  • When the BIG-IP system boots into the upgraded software volume, you notice an error message similar to the following example when the system attempts to load the BIG-IP configuration:

    0107146f:3: Self-device unicast source address cannot reference the non-existent Self IP ( 192.168.1.245 ); Create it in the /Common folder first.

Workaround

There is no workaround for this issue. However, before you perform the software installation again, you can recover from this issue by rebooting the BIG-IP system back into the original boot location to fix the mismatched configuration. To do so, perform the following procedures:

Rebooting the BIG-IP system back into the original boot location

Impact of procedure: Performing the following procedure makes the BIG-IP system unavailable for traffic processing while the system reboots. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Configuration utility.
  2. Navigate to System > Software Management > Boot Location.
  3. Click the original boot location (for example: HD1.1).
  4. Click Activate.
  5. To reboot the system into the original boot location, click OK.

Changing the unicast failover IP address

To change the unicast failover IP address to match the existing management IP address, perform the following steps:

Impact of procedure: Performing the following procedure may make the BIG-IP system unavailable for traffic processing if the unicast IP address has not been configured correctly. F5 recommends that you perform this procedure during a scheduled maintenance period.

BIG-IP 11.x:

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Devices.
  3. Click the hostname of the affected device.
  4. Click the Device Connectivity tab.
  5. Click Failover Network.
  6. Select the check box next to the obsoleted management IP address.
  7. To remove the obsoleted management IP address, click Delete.
  8. Click Add.
  9. Select the current management IP address from the list.
  10. Click Finished.

BIG-IP 10.x:

  1. Log in to the Configuration utility.
  2. Navigate to System > High Availability > Network Failover.
  3. Click the entry with the obsoleted management IP address in the Unicast field.
  4. Click Edit.
  5. Update the Local Address to the current management IP address.
  6. Click Add.
  7. To save the modifications, click Update.
  8. Repeat steps 1 to 7 on the peer redundant system, and in step 5, update the Remote Address box instead of Local Address box.
