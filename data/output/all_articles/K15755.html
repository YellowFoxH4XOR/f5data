Known Issue

If a gateway fail-safe pool is disabled using a Traffic Management Shell (tmsh) command, all peer devices will show the pool as active in the high availability (HA) table.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is part of a high-availability configuration.
  • You have an existing gateway fail-safe pool with at least one member.
  • You disable BIG-IP gateway fail-safe with tmsh command syntax similar to the following example, where the gateway-failsafe-device option is set to none:

    tmsh modify ltm pool <pool_name> gateway-failsafe-device none
  • The pool's min-up-members value is greater than zero.

Impact

The BIG-IP system may unintentionally fail over when a gateway pool goes down.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The tmsh show sys ha-status command shows the gateway fail-safe as active, but the Configuration utility does not show the gateway fail-safe as active.
  • The BIG-IP system unexpectedly fails over when the gateway fail-safe pool goes down.

Workaround

To work around this issue, you can use the Configuration utility to make the change, or use an alternate tmsh command to set the min-up-members value to 0. To do so, perform the following procedure:

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

Setting a pool's min-up-members value to 0

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Use the following command syntax to set the pool's min-up-members value to 0:

    modify ltm pool <pool_name> gateway-failsafe-device none min-up-members 0
