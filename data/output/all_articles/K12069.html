Known Issue

This is the result of a known issue. The BIG-IP httpd allow list does not support the use of the asterisk (*) character as a wildcard character; however the bigpipe db Service.httpd.Allow and bigpipe httpd allow commands allow you to enter asterisk characters. As a result, BIG-IP administrators may believe that they have configured access to the Configuration utility, when access has not actually been configured. For example:

bigpipe httpd allow 10.1.*.* add

If you type the example command, the entry 10.1.*.* appears on the httpd allow list; however, users on the 10.1.0.0/16 network will receive an HTTP 403 Forbidden error response when attempting to access the Configuration utility.

F5 Product Development is tracking this issue as ID 222136 and 249265 (formerly CR113812).

Workaround

You can work around this issue by deleting the HTTP allow entries containing an asterisk character, and then re-adding those entries using a valid format. To determine which entries are currently configured, use the bigpipe httpd allow command. For example:

[root@B8800:Active] config # bigpipe httpd allow
HTTPD - HTTPD Allow:
10.1.*.*
192.168.*.*
[root@B8800:Active] config #

Delete all entries containing asterisk characters using the bigpipe httpd allow <entry> delete command. For example:

bigpipe httpd allow 10.1.*.* delete

When re-adding the network entry, omit octets from the network address instead of using wildcard characters. For example, to allow access to 10.1.0.0/16, you would type the following command:

bigpipe httpd allow 10.1 add

Alternatively, you can enter the network address followed by the netmask. For example:

bigpipe httpd allow 10.1.0.0/255.255.0.0 add

Note: For more information about using the bigpipe httpd allow command, refer to K7448: Restricting access to the Configuration utility by source IP address.
