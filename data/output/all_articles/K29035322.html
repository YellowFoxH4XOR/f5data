Description

HTTP POST request is not passed by ASM - BIG-IP closes the connection before forwarding request to the backend server.

Environment

  • ASM policy
  • Large HTTP request

Cause

Server has closed the server-side connection during the time ASM is processing the request, resulting in the attached client-side flow being closed, as well, without forwarding the request to a pool member.

This might happen if the request follows a preceding request in the same connection, takes time to process, and the server is enforcing a HTTP Keep-Alive timeout.

For example:

  1. Client opens a connection and sends a HTTP request.
  2. BIG-IP load balances this request to a server, receives a response.
  3. In the response, the server returns the Keep-Alive: timeout=5 header, indicating that it will close the connection after 5 seconds if it does not receive a subsequent HTTP request.
  4. The response is sent to the client.
  5. The next request from the client is a large one. It takes 3 seconds to arrive, then a further 3 seconds for ASM to parse the request.
  6. At this point, at least 5 seconds have elapsed, so the server close the server-side connection. This results in the client-side connection being closed, as well (without sending the request to a pool member).

Recommended Actions

Use a OneConnect profile, or an iRule with LB::detach. This will cause the server-side flow to be detached from the client side, allowing the HTTP request to be sent over a new or existing connection, even if the server closed the original connection.

Alternatively, increase the Keep-Alive timeout parameter configured on the server-side.

Preventing ASM from parsing the request body (in the Allowed URL's Header-Based Content Profile) can also speed up the time it takes for ASM to process requests.

Additional Information

One way to determine if this issue is at play is to use an iRule that logs events such as: HTTP_REQUEST, ASM_REQUEST_DONE, and SERVER_CLOSED. A packet trace is the best way.
