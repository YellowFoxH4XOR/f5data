Description

Configured ASM policy on the virtual server. The policy is working as expected in Transparent mode. When we attach the ASM policy to the Virtual server, we cannot see the notification popup on the application, this is a notification message which will be shown when the user updates the information into the applications. The popup(notification) will show as "Application successfully updated".

When we enable the ASM policy to the virtual server that pop is not shown in the application and users would need that popup/notification to be shown when they update any information.

Cause

PD has determined that the cookie is not built correctly based on the  RFC 2965/RFC6265.

According to RFC 6256, there are two values present in cookie format.

 cookie-value      = *cookie-octet / ( DQUOTE *cookie-octet DQUOTE )
 cookie-octet      = %x21 / %x23-2B / %x2D-3A / %x3C-5B / %x5D-7E

 Within the cookie-value, the "*" (without the quotes) in front of cookie-octet means you can have any number of cookie octets OR have one that's of this format:

     DQUOTE *cookie-octet DQUOTE  ---------------> " * "

The above format states that the single double-quote is followed by all your cookie-octets and then another single double-quote. DQUOTES can only be used once and in a pair.

In our case, since one more DQUOTE(") was added before __json_message,  ASM is looking for the end of DQUOTE and truncating the remaining value.

xxxxxxxxxxxxxxxxxxx $[[\"__json_message\"\0540\05420\054\"Application Status Updated Successfully\"]]

Recommended Actions

Workaround1:-

If user wants to use the original GET request with additional DQUOTE(") in the cookie, then you can use the following workaround solution to send the cookie directly

This db key being enabled (default) means that ASM has to parse the entire cookie header to strip out the TS cookies and re-assemble the cookie header before sending it to the backend.
 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

1.Log in to the TMOS Shell (tmsh) by typing the following command:
#tmsh
2.To modify the system database variable and allow ASM cookies to pass to OWS, type the following command:
#modify /sys db asm.strip_asm_cookies value false
3.To verify the modified system database variable, type the following command:
#list /sys db asm.strip_asm_cookies


Workaround2:-

Use the below iRule  to modify the cookies

when HTTP_REQUEST {
set cookie_mod 0
  if { [HTTP::cookie exists "messages"] } {
     set tmp_cookie [HTTP::cookie value "messages"]
     HTTP::cookie remove "messages"
     set cookie_mod 1
  }
}
when HTTP_REQUEST_SEND {

   if {$cookie_mod == 1} {
      HTTP::cookie insert name "messages" value $tmp_cookie
      set cookie_mod 0
   }
}
