Description

/var/log partition reaches 100% utilization when logrotate fails to parse invalid syntax in sys log-rotate configuration.

Common symptoms include:

  • /var/log showing 100% utilization.

Environment

  • Product: BIG-IP
  • Custom sys log-rotate configuration with invalid syntax

Cause

When a sys log-rotate has incorrect syntax, logrotate process exits with an error everytime it runs, as described in K13367: Managing log files on the BIG-IP system (11.x - 17.x). As a result of failure in log rotations and removal of old log files overtime /var/log/ partition keep filling up the disk space.

Below is one such example with incorrect syntax.

 

# tmsh list sys log-rotate

sys log-rotate {
    include "/var/log/zebos/bgp.log
            compress
            missingok
            notifempty
            sharedscripts
            postrotate
            endscript
    }"  <<------  Notice, there is no open curly braces for this.
}

Recommended Actions

  • Review the log rotate configuration and correct any syntax error or remove custom log-rotate config if no longer needed.

    For example: Above shown syntax error should be corrected as below

# tmsh list sys log-rotate all-properties


sys log-rotate {
    common-backlogs 24
    common-include none
    description none
    ilx-include none
    ilx-rotations 10
    ilx-schedule daily
    ilx-size 10240
    include "/var/log/zebos/bgp.log {
            compress
            missingok
            notifempty
            sharedscript
            postrotate
            endscript
    }"
    max-file-size 1024000
    mysql-include none
    syslog-include none
    tomcat-include none
    wa-include none
}

 

  • Force log rotate after correcting the configuration and verify that log files have been rotated.
    #logrotate -f /etc/logrotate.conf
  • Verify that no syntax errors or abnormal-exit messages are reported in /var/log/messages.
  • If /var/log/ partition is still 100% and if any file is consuming more space, empty the file using below command.
    #truncate -s0 /path/to/file/<filename>
