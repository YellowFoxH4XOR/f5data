Known Issue

This is the result of a known issue. The pvad process creates objects in its memory to represent the IP address and port of pool members participating in Packet Velocity ASIC (PVA) accelerated flows. An issue was discovered with the manner in which the pvad process counts these objects, which may lead to the process leaking memory.

Note: The pvad process only runs on BIG-IP platforms equipped with a PVA. For more information, refer to K4832: Overview of PVA Acceleration features and sub features.

F5 Product Development tracked this issue as ID 333013 (Formerly CR128047-1) for the BIG-IP 9.x software branch and it was fixed in cumulative hotfix BIGIP-9.4.8-396.1-HF3, which has been issued for BIG-IP 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).

This issue still exists as ID 211569 (formerly CR128047) for the BIG-IP 10.x and 11.x software branches.

Workaround

To determine how much memory the pvad process is using, run the ps -auxwf command from the BIG-IP command line and examine the Virtual Set Size (VSZ) of the /bin/pvad command.

Note: The VSZ value is shown in KB.

Under normal conditions, the pvad process utilizes between 10 MB and 15 MB of memory. If you see larger values, you may be affected by this issue. For example, the following output of the ps -auxwf command (cut for brevity) shows that the pvad process has grown to approximately 320 MB:

USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND

root 1661 0.0 0.0 1372 292 ttyS0 S 2008 0:00 \_ runsv pvad
root 1951 1.1 4.7 328188 18244 ttyS0 S 2008 4896:25 | \_ /bin/pvad

When this issue occurs, the Host may start swapping memory causing system-wide performance degradation.

It is impossible to prevent this issue from occurring; however, if you have determined to be affected, you may restart the pvad process to flush its memory. To do so, run the bigstart restart pvad command. This will not prevent the issue from reoccurring.

Important: Restarting the pvad process will cause a brief traffic disruption.
