Description

The information exchange between the BIG-IP DNS and BIG-IP LTM systems begins with a request (referred to as a probe request) that is sent by the gtmd process to a big3d process to retrieve the status of a specific object. The probe request instructs the big3d process regarding the performance of the probe, including the timeout, and for some monitors, the timing of multiple probes. The big3d process uses iQuery to broadcast its response to the requester and to any of its sync group members that have an established iQuery connection.

However, the big3d only responds to probe request that matches either the virtual server or the VIP:port (not the translation address and port). With big3d not responding, the message "Offline (enabled) No reply from big3d: timed out" will be shown for the virtual server in GTM/DNS.


Environment

  • BIG-IP GTM/DNS and LTM
  • iQuery (gtmd and big3d)
 

Recommended Actions

When manually adding virtual servers in GTM/DNS, make sure to either match the virtual server (including the partition name such as /Common/) or the VIP:port.

Example:

In GTM/DNS:  
/Common/VS_https {                     <==== either VS name
     destination 10.100.0.10:443       <==== or VIP:port should match on what is in the LTM
     monitor /Common/bigip
     translation-address w.x.y.z       <==== this will not be checked by the big3d in LTM
     translation-port 443              <==== this will not be checked by the big3d in LTM
}

 

In LTM:
ltm virtual /Common/VS_https {            <==== VS name
    creation-time 2021-06-10:17:05:23
    description "Test Virtual Server"
    destination /Common/10.100.0.10:443   <==== VIP:port
    ip-protocol tcp
    last-modified-time 2021-06-10:17:05:57
    mask 255.255.255.255
    pool /Common/POOL_https
 <...snipped...>
}
