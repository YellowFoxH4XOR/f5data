Known Issue

This is the result of a known issue. The module resource provision scheme does not distribute memory correctly, favoring TMM and providing more memory to TMM when other modules are starved.

Beginning in BIG-IP version 10.0.0, the memory provisioning scheme changed to provision memory based on total physical memory and the modules licensed. However, the method for which the ratio scheme was devised causes the LTM module (effectively TMM) to receive additional memory.

The memory partition system, depending on the provisioning level, will first try and satisfy the minimum memory requirements for the provisioned modules. Once the minimum levels are met and if additional memory is left, the remaining memory will be given to each module proportionally based on the configured provisioning ratios.  Unfortunately, the way the ratios were defined favor the LTM module (effectively TMM) causing it to receive a majority of the remaining memory than the rest of the rest of the system, which includes the Linux host and other modules.

This behavior can cause modules such as WebAccelerator, ASM and the Linux host to run out of memory under load. While the majority of the memory allocated to TMM sits idle and unused since it cannot be addressed by the other modules. For BIG-IP WebAccelerator configured as dedicated, the memory starvation results in excessive disk swap usage further degrading the system.

The following example is a BIG-IP WebAccelerator version 10.1.0 running on a 4500 platform:

Total memory: 8 GB
Module Provision: WAM
Level: Dedicated

# b provision list
provision wam {
   level dedicated
}

The following example illustrates the bigpipe memory output showing memory being used by the system:

# b memory
MEMORY STATISTICS --
|    (Host) Total = 7.822GB   Used = 6.421GB
|    (TMM)  Total = 3.522GB   Used = 16.63MB

The following example illustrates the bigpipe db output for memory provisioning:

Note: The example is truncated to show only the amount of memory allocated to LTM.

# bigpipe db show | grep -i provision.memory
Provision.Memory.LTM = 5644

Notice that LTM is provisioned for 5.5 GB (5644) but the system is only able to address 3.5 GB (b memory output). The remaining 2 GB that is allocated is wasted, sitting idle and not accessible by the Linux host or the WebAccelerator module.

F5 Product Development tracked this issue as CR133853 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, or WAN Optimization release notes.

In addition, BIG-IP iHealth may list Heuristic H649447 on the Diagnostics > Identified > High screen.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP version 10.0.1 and in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
