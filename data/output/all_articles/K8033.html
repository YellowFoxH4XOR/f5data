Known Issue

This is the result of a known issue. When load balancing fails to a selected member, the iRule LB::reselect command repeatedly attempts to connect to the unavailable member, rather than selecting the next available pool member. As a result, TMM will loop.

When the following example iRule is associated with a virtual server and pool, it should trigger when a load balance attempt fails to a selected pool member that is unavailable or down, and instruct the BIG-IP LTM to select another pool member. However, due to the known issue, the following iRule will repeatedly attempt to connect to the unavailable member:

rule reselect_irule {
when LB_FAILED {
LB::reselect
}
}

F5 Product Development tracked this issue as CR85186 and it was fixed in BIG-IP LTM version 9.3.1 and 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.3-HF4, issued for BIG-IP version 9.4.3. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
