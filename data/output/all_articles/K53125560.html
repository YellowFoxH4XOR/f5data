Topic

Beginning in BIG-IP 13.0.0, the BIG-IP system keeps historical records of changes made to certain configuration files. These historical records are also included in QKView diagnostic files.

Description

When you save the BIG-IP configuration using the tmsh save /sys config command or by saving changes using the Configuration utility, the system runs the generate_config_diffs.sh shell script. The generate_config_diffs.sh script uses the cmp utility to perform a byte-by-byte comparison of the following configuration files, and their last-saved versions:

  • bigip.conf
  • bigip_base.conf
  • bigip_gtm.conf
  • bigip_script.conf
  • bigip_user.conf
  • BigDB.dat

Note: The script searches for these configuration files in the /config directory, as well as any /config/partitions/* directories, if they exist.

If the system detects any changes between the current configuration file and the last saved file, the system uses the diff utility to generate a patch file, which contains the differences. Patch files are stored in the /config/.diffVersions directory. The patch file contains the sections of the configuration that have changed, as well as three lines of unchanged content. Modified content is identified by either a plus (+) or a minus (-) at the beginning of the line, indicating that the line must be either added or removed from the current configuration to return to the previous state.

For example, consider the following scenario:

  1. You have an existing pool configured with one pool member, similar to the following example:

    ltm pool /Common/pool_http {
        members {
            /Common/192.0.2.1:80 {
                address 192.0.2.1
            }

  2. Using the Configuration utility, you add a second pool member, 192.0.2.2:443.
  3. You type the following ls command: 

    # ls -l /config/.diffVersions/config/bigip.conf/

    A new patch file is generated, as follows:

    total 16
    -rw-r--r--. 1 root root  548 2018-03-15 14:10 1.patch
    -rw-r-----. 1 root root 2979 2018-03-15 14:10 bigip.conf

  4. You type the following cat command: 

    # cat /config/.diffVersions/config/bigip.conf/1.patch

    The patch file contents appear similar to the following example:

    --- /config/bigip.conf  2018-03-15 14:10:05.000000000 -0700
    +++ /config/.diffVersions//config/bigip.conf/bigip.conf 2018-03-15 14:08:29.000000000 -0700
    @@ -18,17 +18,11 @@ ltm default-node-monitor {
     ltm node /Common/192.0.2.1 {
         address 192.0.2.1
     }
    -ltm node /Common/192.0.2.2 {
    -    address 192.0.2.2
    -}
     ltm pool /Common/pool_http {
         members {
             /Common/192.0.2.1:80 {
                 address 192.0.2.1
             }
    -        /Common/192.0.2.2:443 {
    -            address 192.0.2.2
    -        }
         }
         monitor /Common/tcp
     }

    In the previous output, you can see that a new node has been added for 192.0.2.2, and a new pool member has been added for 192.0.2.2:443. The minus (-) sign at the beginning of the line indicates those sections have to be removed from the current bigip.conf file to return the configuration to its previous state.

  5. Using a text editor, you directly edit the /config/bigip.conf file and replace the 192.0.2.2:443 pool member with 192.0.2.2.80.
  6. You load the new bigip.conf file using the tmsh load /sys config command, and save the configuration using the tmsh save /sys config command.
  7. You type the following ls command:

    ls -l /config/.diffVersions/config/bigip.conf/

    A new patch file is generated:

    total 24
    -rw-r--r--. 1 root root  548 2018-03-15 14:10 1.patch
    -rw-r--r--. 1 root root  391 2018-03-15 14:11 2.patch
    -rw-r-----. 1 root root 2978 2018-03-15 14:11 bigip.conf

  8. You type the following cat command: 

    cat /config/.diffVersions/config/bigip.conf/2.patch

    The patch file content appears similar to the following example:

    --- /config/bigip.conf  2018-03-15 14:11:18.000000000 -0700
    +++ /config/.diffVersions//config/bigip.conf/bigip.conf 2018-03-15 14:10:05.000000000 -0700
    @@ -26,7 +26,7 @@ ltm pool /Common/pool_http {
             /Common/192.0.2.1:80 {
                 address 192.0.2.1
             }
    -        /Common/192.0.2.2:80 {
    +        /Common/192.0.2.2:443 {
                 address 192.0.2.2
             }
         }

    In this output, you can see:

    • The minus (-) sign at the beginning of the /Common/192.0.2.2:80 line, which indicates this line was added to the configuration in the last save.
    • The plus (+) sign at the beginning of the /Common/192.0.2.2:443 line, which indicates this line was removed from the configuration in the last save.

Recommendations

When you use historical information as part of the troubleshooting process, consider the following factors:

  • This process can occur without the user's knowledge, because the tmsh save /sys config command is called by other commands, as needed.
  • The generate_config_diffs.sh script is configured to keep only the most recent 250 patch files; it then begins to age out the oldest versions.
