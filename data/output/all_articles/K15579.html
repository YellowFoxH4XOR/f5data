Known Issue

On rare occasions, the Traffic Management Microkernel (TMM) process may resume a suspended iRule on the wrong connection flow.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses Clustered Multiprocessing (CMP), and runs multiple TMM processes.
  • The system configuration includes a virtual server associated with an iRule that uses commands that may resume a suspended iRule (for example, the iRule table command).

If you use certain iRule commands to access information that is external to the current connection flow, the iRule becomes suspended until the iRule command accessing the external command completes processing. For more information, refer to the iRules Concepts: Connection States and Command Suspension DevCentral article.

Impact

The TMM process may produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H459764 on the Diagnostics > Identified > Medium|High screen.
  • The TMM memory utilization graph constantly grows.
  • The TMM process creates a core file and restarts.
  • A failover occurs if the system is configured with high availability (HA).
