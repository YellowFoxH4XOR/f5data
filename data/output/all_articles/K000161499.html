K000161499: SSLO deployment in error state after manual modification of iAppsLX JavaScript files

Type
Support Solution
Published
2026-08-26
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP SSL Orchestrator
Source
https://my.f5.com/manage/s/article/K000161499

Description

Editing or deploying a security policy in F5 SSL Orchestrator may fail with errors such as "Expected an identifier and instead saw '#'" or "Invalid or unexpected token" if a JavaScript file (e.g., orchestratorConfigProcessor.js) within the iAppsLX package is manually modified using an invalid comment character (such as '#' instead of '//').

This results in the configuration being locked or in an error state, and the security policy cannot be edited or loaded until the syntax error is fixed.

Environment

  • F5 SSL Orchestrator

  • Manual modification of iAppLX JavaScript files (e.g., orchestratorConfigProcessor.js)

  • Attempt to update configuration parameters by editing JavaScript source files directly

Cause

Manual edit to a JavaScript file in the iAppLX package using an invalid comment character ('#' instead of '//'), resulting in a JavaScript syntax error that prevents the application from loading or being modified.

Recommended Actions

  1. Do not manually edit JavaScript files within the iAppLX package. Use the supported Guided Configuration interface or follow official F5 procedures for configuration changes.

  2. If a manual edit has already been made and the UI is in an error state:

    • Review /var/log/restnoded/restnoded.log and LoaderWorker/JSHINT logs for syntax errors referencing unexpected tokens (such as '#').

    • Locate the offending line in the JavaScript file and correct the comment syntax by replacing '#' with '//'.

    • Save the file and restart the restnoded service:
      bigstart restart restnoded

    • Alternatively, revert the file to its original state or redeploy the iAppLX package to restore the default code.

    • After correcting the syntax, verify that the UI loads and the security policy can be edited.

  3. Always back up the system before making any changes to system files.

  4. If the issue persists, consider removing and reinstalling the iAppLX package as a last resort.

Additional Information

Manual edits to iAppLX JavaScript files are unsupported and can lead to application failures.

JavaScript uses '//' for single-line comments and '/* ... */' for block comments.

Using '#' as a comment character will cause syntax errors and prevent the application from functioning.
