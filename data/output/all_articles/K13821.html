Known Issue

An HTTP monitor that is configured to send authentication information may fail if a pool member requires NTLM authentication.

This issue occurs when all of the following conditions are met:

  • You are using an HTTP monitor under the following conditions:
    • The user and password fields are populated.
    • The send string has a trailing \r\n.
  • Pool members require NTLM authentication.

This issue occurs when the BIG-IP system incorrectly adds an extra CRLF prior to the NTLM Authorization header.

Impact

Pool members are incorrectly marked down.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP HTTP monitors may incorrectly mark down pool members that require NTLM authentication.
  • Packet captures of monitor traffic show a double \r\n instead of just a single \r\n at the end of the send sequence, indicating to the server that the header data has ended prematurely.
  • Packet captures show server response of HTTP Error 400 - Bad request.

Resolution

Status

Workaround

To work around this issue, you can omit the trailing \r\n from the send string of any HTTP monitor which authenticates against a server with NTLM authentication.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
