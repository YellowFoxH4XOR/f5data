K000156812: "HTTP::version" iRule command does not return "HTTP/2" on HTTP/2 connection when "-string" option is used together.

Source

Description

"HTTP::version -string" command does not return HTTP/2 even though BIG-IP is running on v16.x/v17.x which should have fix for Bug ID842053.

ltm rule /Common/http-version-logging {
   when HTTP_REQUEST {
      log local0.notice "MYDEBUG: client HTTP version is [HTTP::version -string]"
   }
}

 

With above iRule, when client sends HTTP/2 request to virtual server with the above iRule, following debug message is written to ltm log file. Version is logged as "HTTP/1.1", as shown below.

Oct  6 06:25:02 bigip.local notice tmm3[12098]: Rule /Common/http-version-logging <HTTP_REQUEST>: MYDEBUG: client HTTP version is  HTTP/1.1

 

Environment

  • HTTP/2 virtual server.
  • "HTTP::version -string" iRule command.

 

Cause

"-string" option is used together with "HTTP::version" command.

 

Recommended Actions

To get HTTP version 2.0 logged on "HTTP::version" command, do not use "-string" option.

ltm rule /Common/http-version-logging {
   when HTTP_REQUEST {
      log local0.notice "MYDEBUG: client HTTP version is [HTTP::version]"
   }
}

 

With the above iRule, "HTTP::version" command returns "2.0", as shown below.

Oct  6 06:27:20 bigip.local notice tmm10[12098]: Rule /Common/http-version-logging <HTTP_REQUEST>: MYDEBUG: client HTTP version is 2.0

 

Note: "HTTP::version" command with "-string" option returns exact version string seen on HTTP communication. TMM internally translates HTTP/2 request to HTTP/1.1 and iRule with "-string" option returns this translated version string "HTTP/1.1". Meanwhile, without "-string" option, "HTTP::version" command returns HTTP version information which TMM interpreted. TMM knows client side connection is HTTP/2 even though it's internally/temporarily translated to HTTP/1.1. Therefore, without "-string" option, "2.0" is returned.
