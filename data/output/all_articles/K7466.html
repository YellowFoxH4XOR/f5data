Topic

The BIG-IP GTM uses iQuery to monitor the status of BIG-IP LTM systems. iQuery uses the SSL certificate to authenticate the session as it accesses information through the secure management web server running on the BIG-IP LTM. In BIG-IP versions 9.0.0 through 10.0.0, the default validity length for BIG-IP SSL device certificates is one year. When the SSL certificate expires, this issue causes iQuery requests from the BIG-IP GTM to the BIG-IP LTM to fail because the certificate is no longer valid. As a result, the BIG-IP GTM marks the BIG-IP LTM down, along with all of the objects configured.

F5 Product Development tracked an enhancement to allow for increasing the default validity length device certificates, and to add the ability to specify the length of time for which the SSL certificate is valid. The enhancement was tracked as CR58788 and it was included in BIG-IP version 10.0.0.

Workaround

To work around this issue, you can renew the BIG-IP LTM certificate and then run the bigip_add script. To do so, perform the appropriate procedures (according to your version) below.

(Option One) Renewing the BIG-IP LTM certificate for another year for BIG-IP versions 9.0.0 through 9.1.2

Important: If any information is updated other than validity date, you must re-import the certificate into the BIG-IP GTM. Otherwise, the certificate is considered invalid because it does not match the certificate on the BIG-IP GTM.

  1. Log in to the BIG-IP LTM Configuration utility.
  2. Select System.
  3. Select Platform.
  4. Select Web Server Certificate.
  5. Select Renew.
  6. Change Issuer from Certificate Authority to Self.

    Note: As an optional step, you may choose to update any information at this point.
  7. Click Finished.

(Option Two) Renewing the BIG-IP LTM certificate for another year for BIG-IP versions 9.2.0 through 9.6.1

Important: If any information is updated other than validity date, you must re-import the certificate into the BIG-IP GTM. Otherwise, the certificate is considered invalid because it does not match the certificate on the BIG-IP GTM.

  1. Log in to the BIG-IP LTM Configuration utility.
  2. Select System.
  3. Select Device Certificates.
  4. Select Renew.
  5. Change Issuer from Certificate Authority to Self.

    Note: As an optional step, you may choose to update any information at this point.
  6. Click Finished.

(Option Three) Renewing the BIG-IP LTM certificate for longer than one year

Note: Beginning in BIG-IP version 10.0.0, self-signed device certificates validity can be adjusted within the Configuration utility. For more information, refer to K10233: Change in Behavior: Self-signed device certificates lifetime value can be configured within the Configuration utility.

To renew the BIG-IP LTM certificate for more than one year, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /config/httpd/conf/ssl.crt directory by typing the following command:

    cd /config/httpd/conf/ssl.crt

  3. Convert the server.crt certificate to a certificate signing request .csr by typing the following command:

    openssl x509 -x509toreq -in server.crt -out server.csr -signkey /config/httpd/conf/ssl.key/server.key

  4. Using the new CSR, specify the number of days for which the certificate should be valid by typing the following command:

    openssl x509 -req -in server.csr -signkey /config/httpd/conf/ssl.key/server.key -days <# of days> -out server.crt

    Replace <# of days> with the number of days in year increments for which you want the certificate to be valid.

    For example, if you want to make the certificate valid for a year, type the following command:

    openssl x509 -req -in server.csr -signkey /config/httpd/conf/ssl.key/server.key -days 365 -out server.crt

  5. Restart the web server daemon by typing the following command:

    bigstart restart httpd

Running the bigip_add script

After you have renewed the SSL certificate, you must run the bigip_add script on the BIG-IP GTM system so it can add the SSL certificate. Failure to run the script prevents the BIG-IP GTM from communicating with the BIG-IP LTM system.

Note: If the BIG-IP GTM systems are in a synchronization group, you only need to perform this procedure on one BIG-IP GTM system. If the BIG-IP GTM systems are not in a synchronization group, you must perform this procedure on each BIG-IP GTM system that communicates with a BIG-IP LTM system that had its SSL certificate updated or changed.

This procedure authenticates, copies, and adds the certificate to the /config/gtm/server.crt file, which allows the BIG-IP GTM system to authenticate the certificate each time it communicates with the BIG-IP LTM system. To run the bigip_add script, perform the following procedure:

  1. Log in to the BIG-IP GTM command line.
  2. Enter the following command:

    bigip_add <remote_ltm_system>
  3. Enter the root password of the remote BIG-IP LTM system when prompted.
