Known Issue

Lightweight Directory Access Protocol (LDAP) authenticated secure shell (SSH) connections to the BIG-IP system may fail authentication or be assigned unexpected role permissions.

This issue occurs when all of the following conditions are met:

  • The user is logging in to the BIG-IP system using SSH.
  • The BIG-IP system is configured to use remote LDAP authentication for BIG-IP administrative users.
  • The LDAP authentication server returns a username attribute with a character case that does not match the character case of the user logging in.

Note: This issue does not affect administrative users logging in to the BIG-IP Configuration utility.

LDAP is generally case-insensitive, and the LDAP attributes returned by the LDAP server may be mixed-case and not match the character case of the user logging in. As a result, the username attribute received by the Pluggable Authentication Module (PAM) for LDAP authentication (pam_ldap) from the LDAP server may not match the character case with the username used to log in.

When an LDAP authenticated user logs in to the BIG-IP system using SSH, the pam_ldap module will pass a username credential to the pam_unix module. The pam_ldap module will use the character case of the username as returned by the LDAP server in the username attribute instead of using the character case of the username used to log in.

For example, a username of f5user is configured on the BIG-IP system. A user logs in as f5user and is successfully authenticated by the LDAP server. However, if the username attribute returned by the LDAP server was changed to F5USER, pam_ldap will pass a username credential of F5USER (instead of f5user) to pam_unix for SSH logon. As a result, SSH login authentication may fail and erroneously report that the account has expired, or the user may be authenticated and assigned unexpected role permissions.

Impact

Note the following when you log in with a username that does not match the character case of the username attribute that the LDAP server returned.

For example, you log in as f5user, and the LDAP server returns a username attribute of F5USER:

  • If the LDAP authentication server returns a username attribute that does not match the character case with a username configured on the BIG-IP system, authentication fails with a user account has expired error.

    For example, you log in with a username of f5user, the username attribute returned by the LDAP authentication server is F5USER, the BIG-IP system has a username of f5user configured but does not have a username of F5USER configured, then authentication fails with a user account has expired error.

    Note: If the remote user accounts are unable to log in to the BIG-IP system, the locally defined user accounts, such as the default administrator account and the root command line account, can log in to the system.

  • If the LDAP authentication server returns a username attribute that matches the character case of a different user (other than the user logging in), authentication will succeed and the system will assign the user permissions based on the role of the matched username instead of the role of the username used to log in.

    For example, you log in with a username of f5user, the username attribute returned by the LDAP authentication server is F5USER, the BIG-IP system has a username of f5user configured with an assigned role of Operator, and a username of F5USER configured with an assigned role of Administrator, authentication will succeed and the user will be assigned permissions of the Administrator role instead of the expected Operator role.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The administrative user account authenticated by a remote LDAP server is refused SSH access to the BIG-IP system, with a user account has expired error message.
  • The administrative user account authenticated by a remote LDAP server is assigned unexpected role permissions when logging in to SSH on the BIG-IP system.

Workaround

To work around this issue, you can ensure that usernames used for login, those configured on the BIG-IP system, and those returned from LDAP, all use the same character case.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
