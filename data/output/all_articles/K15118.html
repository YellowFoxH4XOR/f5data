Known Issue

The HTTP::retry iRule command may fail when triggered within an HTTP_RESPONSE event.

This issue occurs when all of the following conditions are met:

  • You configure a virtual server to use an iRule.
  • The iRule is configured with an HTTP::retry command within an HTTP_RESPONSE event.
  • The virtual server processes a client request, which triggers the HTTP:retry iRule command before the back-end server receives the entire response.

If the HTTP_RESPONSE event fires due to the server sending an early response (for example, an error in response to a POST request expecting an HTTP 100 Continue) the HTTP::retry command may fail.

Impact

The BIG-IP system resets the client and server connections.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system abruptly terminates the connection after forwarding the server response by sending an RST packet in both directions.
  • The system logs an error message to the /var/log/ltm file that appears similar to the following example:

    tmm[2850]: 011f0007:3: http_process_state_early_100continue - Invalid action EV_SINK_HEADER during ST_HTTP_EARLY_100CONTINUE (Server side: vip=test-vip profile=http pool=test-pool)
  • The HTTP::retry command does not function as expected.

Resolution

Status

F5 Product Development has assigned ID 434517 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
ReleaseNoneNone

Workaround

To work around this issue, you may be able to modify your iRule to use either the HTTP::respond or HTTP::redirect command instead of the HTTP::retry command.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure modifications are compatible with your environment.

For more information about iRule commands, refer to the iRules Home.
