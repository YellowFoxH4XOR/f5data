K82130557: BIG-IP ASM 12.1.0 and later assigns a logging profile to 'local-storage' or 'remote-storage' but not both

Type
Knowledge
Published
2019-05-06
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP ASM: 14.X.X, 13.X.X, 14.1.X, 14.0.X, 13.1.X, 13.0.X, 12.1.X, 14.1.5, 14.1.4, 14.1.3, 14.1.2, 14.1.0, 14.0.1, 14.0.0, 13.1.5, 13.1.4, 13.1.3, 13.1.1, 13.1.0, 13.0.1, 13.0.0, 12.1.6, 12.1.5, 12.1.4, 12.1.3, 12.1.2, 12.1.1, 12.1.0
Source

Issue

Old Behavior

In versions prior to BIG-IP ASM 12.1.0, you can configure the BIG-IP ASM logging profile to save logs for both local and remote storage.

New Behavior

In BIG-IP ASM 12.1.0 and later versions, you configure the logging profile to store logs in either local or remote storage.

Impact

In versions prior to BIG-IP ASM 12.1.0, when you configure the BIG-IP ASM logging profile to save logs for both local and remote storage, and then you upgrade to BIG-IP 12.1.0 or later, the system creates two logging profiles, one of which ends with the follow extension:

  • _local

For example, in versions prior to BIG-IP ASM 12.1.0, you can view the logging configuration using the following Traffic Management Shell (tmsh) command syntax:

tmsh list security log profile <logging profile name>

Note: When you run the tmsh command, replace <logging profile name> with the logging profile name you use in your configuration.

The system displays output similar to the following example:

security log profile test_logging_profile {
app-service none
application {
"/Common/Log illegal requests tosyslog" {
local-storage enabled
...
remote-storage remote
...
}

In BIG-IP ASM 12.1.0 or later, you can view the logging configuration using the same command syntax:

tmsh list security log profile <logging profile name>

Note: When you run the tmsh command, replace <logging profile name> with the logging profile name you use in your configuration.

However, the system displays output for either a remote or local profile, similar to one of the following examples. The local profile and has the _local extension.

security log profile test_logging_profile {
app-service none
application {
test_logging_profile {
...
local-storage disabled
...
remote-storage remote
...
}
security log profile test_logging_profile_local {
app-service none
application {
test_logging_profile_local {
...
local-storage enabled
...
remote-storage none
...
}

Recommended Actions

To log to local and remote storage, configure two separate logging profiles and assign both the logging profiles to the BIG-IP ASM-enabled virtual server.
