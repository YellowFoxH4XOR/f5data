Description

On F5OS-C VELOS systems, a controller may become unreachable and fail to rejoin the OpenShift cluster after reboots. The issue is characterized by:

  • Controller repeatedly becomes unreachable (cannot ping or SSH)
  • Controller drops out of the OpenShift cluster and fails to recover after hard and soft reboots
  • Recurring error messages in system logs:

diag-agent[8]: nodename=controller-1 priority="Err" msgid=0x0981000000000005 msg="DIAG_AGENT unable to get platform hal information" error="LOPd Communication Error: LOP USB Device is not present at either: /dev/ttyAOM or /dev/ttyACM0" interface="psf-diag-agent"


  • System health shows diag-agent service as unhealthy with errors related to service:hal:connection
  • USB device ID shows as f5f5:df11 instead of the expected f5f5:3000 when running lsusb command

$ lsusb

Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub

Bus 001 Device 002: ID f5f5:df11. #### ---- wrong

Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub


Environment

  • Product: F5OS-C (VELOS Chassis)
  • Symptoms:
    • Controller unreachable via ping/SSH
    • OpenShift cluster shows controller as not ready
    • Diag-agent unable to communicate with platform-hal
    • USB device firmware in bootloader mode (ID f5f5:df11)


Cause

ID1134613

The root cause is corruption or mismatch in the LOP (Lights-Out Processor) chassis controller USB device firmware. The USB device shows as f5f5:df11 (bootloader/DFU mode) instead of the expected f5f5:3000 (normal operational mode). This prevents proper communication between the diag-agent service and platform-hal, leading to controller unreachability and cluster instability.



Answer/Recommended Actions

Workaround of ID1134613 says "locate the most recent firmware for the LOP" and reflash the firmware, while in some cases , there is only one firmware version and reflash with the same firmware version is also helpful.


1. get the firmware version and location


#docker exec platform-fwu find / -name "*lop-chassis-controller*.dfu" 2>/dev/null

/usr/lib/firmware/prgmbldr-lop-chassis-controller-v1.02.1019.0.1.dfu


2. reflash the firmware


#docker exec -it platform-fwu dfu-util -D /usr/lib/firmware/lop-chassis-controller-v2.01.1282.0.1.dfu


3. restart diag-agent if seeing "Diag-agent is able to communicate with platform-hal unhealthy " in "show system health" report after reflashing the firmware.


From bash of the affected controller

#docker container restart diag-agent
