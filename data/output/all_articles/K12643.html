Known Issue

Traffic Management Microkernel (TMM) may restart and produce a core file when an iRule uses suspending command in the CLIENT_CLOSED event.

This issue occurs when the following conditions are met:

  • You have configured a User Datagram Protocol (UDP) virtual server that uses an iRule
  • The iRule uses suspending command in the CLIENT_CLOSED event that temporarily suspends iRules processing
  • When iRule returns from a suspended state to a flow that has closed

For example, if an iRule uses the table command in the CLIENT_CLOSED event to update an existing record, the BIG-IP system suspends iRule execution for that connection until the operation completes, i.e. when the table session record is updated. When the iRule execution resumes, the connection entry has been removed from the connection table, and TMM may produce a core file.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high-availability pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to another host in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system temporarily fails to process traffic while TMM restarts.
