Known Issue

An iSession endpoint connection may fail to recover after the remote endpoint restarts.

This issue occurs when the following condition is met:

  • The remote iSession tunnel endpoint that performs symmetric deduplication is restarted.

When an established outgoing deduplication control connection is aborted, the deduplication peer context is set to a PEER_PENDING_CONNECT state. However, on rare occasions during recovery and re-establishment of the deduplication control connection, the deduplication peer context remains in the pending state.

Impact

Deduplication fails to occur after remote endpoints restart.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Deduplication does not occur after remote endpoints restart.

Workaround

To work around this issue, you can restart the remote endpoint system again.

Impact of workaround: Restarting the remote endpoint system temporarily disrupts traffic processing.
