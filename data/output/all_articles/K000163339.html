Description

  • You are interested in understanding the changes related to IPv6 in F5® Distributed Cloud since the September release

Environment

  • F5® Distributed Cloud

  • Load Balancers

Cause

  • Starting with our September 2026 release, F5® Distributed Cloud now supports advertising on IPv6-only or dual-stack (IPv4 + IPv6) — letting you serve both modern IPv6-native clients and legacy IPv4 clients from a single load balancer configuration, with no change to your origin pool or routing rules. 

Answer/Recommended Actions

Pre-Requisites

  • Have IPv6 add-on enabled for the tenant
    • If not currently enabled for your tenant, please contact support to request the feature to be enabled

  • Have Specified Public IPs (either IPv6 or dual-stack) added to the tenant

    • If required, please contact support to add more Public IP Objects to your tenant.   

Caveats

  • Default tenant IPv6 and dual-stack advertisement (without a named Public IP object) will be enabled for configuration in a future release
  • IPv6 is supported only on Regional Edges (RE)
    • Support for Customer Edges (CE) will be enabled for configuration in a future release
  • IPv6 is supported only on Downstream (client to XC).
    • Upstream IPv6 (Origin) will be enabled for configuration in a future release
  • CDN is currently not available on Load Balancers with IPv6 enabled.
    • CDN for load balancers configured with IPv6 and/or Dual-stack will be enabled for configuration in a future release
  • BYOIP (also known as Bring your own VIP) for load balancers is currently limited to IPv4 only
    • Support for IPv6 BYOIP/BYOVIP for Load Balancers will be enabled for configuration in a future release

Changes from September 2026

IPv6 is now in Limited Availability (LA). These are the changes implied:

  1. A single Public IP object can now carry: 

    1. An IPv4 address only 

    2. An IPv6 address only 

    3. Both — for dual-stack 

  2. Additional dedicated public IPs (IPv4 or IPv6) are assigned on request
    1. Contact F5® support or your account team to obtain them
    2. Once assigned, they appear in your Public IP Addresses list. 

  3. Advertising a Load Balancer over IPv6 or Dual Stack
    1. For IPv4, options like “Internet” and “Internet (Specified)” were already available to advertise the load balancer using either the tenant default IPv4, or a specified (additional) IPv4 
    2. With the introduction of IPv6 on the F5® Distributed Cloud Regional Edges, two additional advertisement policies are available: 

      1. Internet (Specified IPv6)

      2. Internet (Specified Dualstack) 

    3. The former Internet (Specified) was renamed to Internet (Specified IPv4) to avoid presenting ambiguous alternatives. 

  4. Advertising an IPv6-ONLY HTTP/HTTPS Load Balancer:
    1. To create and advertise a load balancer only on IPv6, follow the steps in Create HTTP Load Balancer, and then select Internet (Specified IPv6) as the Advertisement Policy.
    2. The system will ask you to select an IPv6-only public IP object to create the advertisement

  5. Advertising a dual-stack (IPv4+IPv6) HTTP/HTTPS Load BalancerThe system will ask you to select a Public IP including both IPv4 and IPv6 addresses to create the advertisement
    1. To create and advertise a load balancer on both IPv4 and IPv6, follow the steps in Create HTTP Load Balancer, and then select Internet (Specified Dualstack) as the Advertisement Policy

 

Additional Information

  • A tenant can have a single default public IP (also known as tenant IP or default tenant IP), and multiple additional public IPs, referred to in the advertisement policies as Specified IPs. 
  • Every tenant is automatically assigned a default public IPv4 VIP (the IPv4 address your internet-advertised load balancers listen on by default).
    • You can view it under Administration → Tenant Settings → Tenant Overview.
  • For more control, additional Public IP objects can be requested from F5®.
    • Those Public IPs are visible under Administration → Tenant Settings → Public IP Addresses.
  • Advertisement Policies tell the platform where and how to advertise the configured IPs to the internet
    • Think of it as a publishing setting: it controls which network locations your load balancer is exposed on, and what IP address (or addresses) clients use to reach it
