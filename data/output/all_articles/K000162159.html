K000162159: BIG-IP APM Intune (MDM/EMS) integration fails to retrieve non-compliant devices with a 403 "Signature fields not well formed" error

Type
Support Solution
Published
2026-07-13
Updated
2026-07-13
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000162159

Description

BIG-IP APM devices integrated with a Microsoft Intune Endpoint Management System (EMS/MDM) fail to retrieve the list of non-compliant devices. Azure Blob Storage rejects the request with an HTTP 403 error, and device-compliance data can no longer be synchronized from Intune.

You may observe the following symptoms:

  • The Intune EMS shows an Authentication error status, and non-compliant device data is no longer synchronized.
  • The /var/log/apm file shows an authentication error, for example:

err mdmsyncmgr[<pid>]: 019dffff:3: (null)::00000000: {} /Common/<ems-name>: Error during updating device details: Authentication error (Authentication error for get all non compliant devices request)

Environment

  • BIG-IP APM
  • Microsoft Intune Endpoint Management System (EMS/MDM) integration

Cause

This is a known software defect in the BIG-IP APM tracked under Bug ID 2365469.

Recommended Actions

If you are affected:

  1. Open an F5 Support case and request the fix for bug ID 2365469 for your specific BIG-IP version.
  2. Provide F5 Support with a packet capture of the Intune traffic and a qkview. 

Additional Information

In early April 2026, Microsoft Intune began including two additional HTTP headers in the 303 redirect response that points BIG-IP to Azure Blob Storage. These extra headers increased the size of the redirect response (a data length of approximately 1515 bytes was observed, with roughly 15 bytes truncated from the end). BIG-IP then followed the redirect with an incomplete SAS signature, and Azure Blob Storage correctly rejected the request with HTTP 403.
