Published
2021-11-24
Updated

Applies to

Source

Description

Referrals are a feature of LDAP servers that indicate the contacted server cannot or will not preform the requested action and that one or more other servers may be able to. Partitioned or read only LDAP servers are possible scenarios where an LDAP client might need to chase referrals to complete a search or update a record and a client can chose to support or refuse to chase referrals as well.
 
If BIG-IP is configured to authenticate against LDAP or Active Directory(AD) servers, the BIG-IP is an LDAP client and by default will attempt to chase referrals. However, if the BIG-IP cannot contact the referral servers because of firewall rules or missing DNS configurations authentication could hang and prevent login using valid credentials.
 

Environment

  • BIG-IP
  • Lightweight Directory Access Protocol (LDAP)
  • Active Directory (AD) authentication.

Cause

Default configuration of LDAP or AD authentication attempts to chase referrals. Disabling chase referrals and contacting an unpartitioned LDAP or Global catalog server should allow authentication to be successful.

  • F5OS for LDAP or AD authentication, chase referrals is an option when configuring LDAP binding information.
  • BIG-IP devices v17.x and below please refer to K17311: Globally disable LDAP referrals for the BIG-IP system

3. ) Another parameter we often see in LDAP queries is "shadowAccount".

Querying the shadowAccount is not particular to the referral feature and performed in order to potentially validate additional attributes for accounts where these attributes are stored under the shadow account. ShadowAccount is like a wrapper for password aging and for encryption. If the Account has an object class called shadow account, then make sure the record is present in /etc/shadow and the password is not expired. When shadowAccount is not present, BIG-IP treats it as authentication success after all other attributes have been validated.
