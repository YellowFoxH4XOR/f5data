Issue

3-DNS and BIG-IP 4.x systems communicate using the original iQuery protocol. BIG-IP 9.0.0 introduced a new version of the iQuery protocol, which operates using Secure Socket Layer (SSL).

To facilitate iQuery communication between systems that run different versions of the iQuery protocol, BIG-IP 9.0.0 through 10.0.1 versions run the big3dshim daemon, which translates iQuery messages between different versions.

In BIG-IP 10.1.0, the base O/S for the BIG-IP host system was upgraded to a new kernel that is not compatible with the big3dshim daemon. As a result, iQuery communication is not supported between BIG-IP or 3-DNS 4.x and BIG-IP 10.1.0 and later versions.

Important: Enterprise Manager 1.8.0 and later versions install the version 10.1.0 (or later) big3d process onto managed devices. As a result, this change may also affect BIG-IP systems that run versions prior to BIG-IP 10.1.0 that are managed by Enterprise Manager.

If you attempt to run big3d_install to copy the big3d process from a BIG-IP GTM 10.1.0 system to a remote BIG-IP or 3-DNS 4.x system, the following output displays on the BIG-IP GTM console:

Unsupported 4.x version

If you plan to migrate BIG-IP or 3-DNS 4.x systems so that the 3-DNS and BIG-IP GTM infrastructures overlap for a period of time, you must ensure that the BIG-IP GTM and LTM systems are running version 10.0.1 or earlier so that iQuery communication continues to operate during the migration process.

Note: For more information about issues related to BIG-IP 3-DNS to GTM migration, refer to K12874: 3-DNS to BIG-IP GTM migration issues.
