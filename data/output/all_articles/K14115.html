Known Issue

AOM firmware upgrade using the AOM IM installation file may fail for some BIG-IP and Enterprise Manager platforms.

This issue occurs when one of the following conditions is met:

  • The BIG-IP platform 11050/11050N is running on BIG-IP 10.2.0 or 10.2.1, and you attempt to upgrade AOM to 10.1.7 through 10.1.13 using the AOM IM installation file.
  • The BIG-IP platform 11000/11050/11050N is running on BIG-IP 10.2.2 through 11.2.0, and you attempt to upgrade AOM to 10.1.9 through 10.1.12 using the AOM IM installation file.
  • The BIG-IP platform 1600/3600/3900 is running on BIG-IP 9.4.8, 10.0.0, or 10.0.1, and you attempt to upgrade AOM to 10.1.13 using the AOM IM installation file.
  • The Enterprise Manager platform 4000 is running on Enterprise Manager 2.0.0, 2.1.0, or 2.2.0, and you attempt to upgrade AOM to 10.1.13 using the AOM IM installation file.

The following systems and versions are able to upgrade to AOM 10.1.13 directly using the IM installation file:

  • For BIG-IP systems running 10.2.2 through 11.2.0, you can upgrade to AOM 10.1.13 using the IM installation file.
  • For Enterprise Manager systems running 2.3.0 or 3.0.0, you can upgrade to AOM version 10.1.13 using the IM installation file.

Impact

AOM firmware upgrade using the AOM IM installation file may fail.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Upgrading the AOM firmware using the IM file will result in errors, with an error message that appears similar to the following example:

    Platform not supported: AOM firmware update cancelled

Workaround

To work around this issue, you can mount the AOM's IM installation file, manually install the AOM firmware RPM file, and choose one of the methods to upgrade the AOM subsystem. To do so, perform the following procedure:

Impact of workaround: The procedure involves upgrading the AOM firmware. F5 recommends performing this procedure during a maintenance window.

  1. Download the desired AOM IM installation file to the affected system.
  2. Create a temporary directory to use as a mount point for the IM installation file.

    For example, create a temporary directory named /tmp/aom-10.1.12 by entering the following command:

    mkdir /tmp/aom-10.1.12
  3. Mount the IM installation file system to the directory created in Step 2 using the following command syntax:

    mount -o loop <AOM-Firmware-IM-File> <Temporary-Directory-Mount-Point>

    For example, if the AOM IM installation file is aom-firmware-1.4-10.1.12.370.0.i686.im and the temporary directory name is /tmp/aom-10.1.12, you can mount the IM installation file to a directory by entering the following command:

    mount -o loop aom-firmware-1.4-10.1.12.370.0.i686.im /tmp/aom-10.1.12
  4. Install the AOM firmware RPM file into the system using the following command syntax:

    rpm -Uvh <Temporary-Directory-Mount-Point>/RPMS/i686/<Aom-Firmware-RPM-File>

    For example, if the temporary directory is /shared/tmp/aom-10.1.12 and the AOM firmware RPM file is called aom-firmware-1.4-10.1.12.370.0.i686.rpm, you can install the AOM RPM file by entering the following command:

    rpm -Uvh /tmp/aom-10.1.12/RPMS/i686/aom-firmware-1.4-10.1.12.370.0.i686.rpm
  5. After installing the RPM, you may choose one of the following options:
    • Option A: Reboot the system and let the next boot up sequence upgrade the AOM firmware automatically.
    • Option B: Manually upgrade the AOM firmware using the aom_flash command.
    If Option A is your choice, you may skip Step 6 and proceed to Step 7.
    If Option B is your choice, proceed to Step 6.
  6. Manually upgrade the AOM firmware by entering the following command:

    /opt/F5/aom/aom_flash -kernel

    This process will automatically transfer and install the target firmware into the AOM subsystem. Upon completion, it will display that AOM is being reset. Wait approximately 2 to 3 minutes for the AOM subsystem to boot up. Thereafter, you may verify that the AOM subsystem installed by entering the following command:

    ssh aom flashver
  7. Remove the file system of the IM installation file mounted on the temporary directory created in Step 2 using the following command syntax:

    umount <Temporary-Directory-Mount-Point>

    Using the previous example, the directory name is /tmp/aom-10.1.12. To remove the file system mounted on the temporary directory, you would enter the following command:

    umount /tmp/aom-10.1.12
  8. Remove the temporary directory created in Step 2 using the following command syntax:

    rmdir <Temporary-Directory-Mount-Point>

    Using the previous example, the directory name is /tmp/aom-10.1.12. To remove the temporary directory that is no longer needed, you would enter the following command:

    rmdir /tmp/aom-10.1.12
  9. If you have chosen Option B in Step 5, you have completed your workaround procedure.
    If you have chosen Option A in Step 5, you may reboot your system and let the AOM firmware upgrade perform automatically on the next system boot sequence. After the next system boot sequence has completed, you may verify the AOM subsystem installed by entering the following command:

    ssh aom flashver
