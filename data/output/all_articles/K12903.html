Known Issue

The BIG-IP system may dereference a null pointer when reselecting non-local pool members during a configuration reload, causing TMM to become unresponsive.

This issue occurs when all of the following conditions are met:

  • A pool is configured with pool members in a non-directly-connected network segment
  • The pool has the Action on Service Down option set to Reselect
  • A virtual server has open connections to the non-local pool members
  • The configuration is reloaded (as a result of a UCS installation, ConfigSync, or bigpipe load command)

Impact

The BIG-IP may temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process dumps core, creating files in the /var/core/ directory. The files have names similar to the following example:

    tmm.0.bld1789.0.core.gz

  • The system may write log entries in the /var/log/tmm file. The log entries appear similar to the following example:

    slot1/host1 notice ** SIGSEGV **
