K000160659: F5OS-C/VELOS: Interface Up/Down Enterprise SNMP Traps Not Firing

Source

Description

On F5OS-C/VELOS platforms, F5OS-C enterprise SNMP traps are not sent when an interface goes down or comes up.

up  .1.3.6.1.4.1.12276.1.1.1.263168
down .1.3.6.1.4.1.12276.1.1.1.263169

Generic traps are sent successfully.

linkDown .1.3.6.1.6.3.1.1.5.3
linkUp .1.3.6.1.6.3.1.1.5.4

Environment

  • VELOS
  • F5OS-C
  • SNMP

Cause

ID 2225577

Answer/Recommended Actions

As a workaround, restart the alert service on the active controller, the affected partition, and all blades. The following steps assume controller-1 is the active controller and partition1 is the affected partition.

Step 1:
(config)# system diagnostics os-utils docker restart node controller-1 service alert-service
Restarting container affects configuration and data path. Do you want to proceed? [yes/no] yes

Step 2:
(config)# system diagnostics os-utils docker restart node controller-1 service partition1_alert_service
Restarting container affects configuration and data path. Do you want to proceed? [yes/no] yes

Step 3:
(config)# system diagnostics os-utils docker restart node blade-1 service partition_alert_service
Restarting container affects configuration and data path. Do you want to proceed? [yes/no] yes

Step 4:
(config)# system diagnostics os-utils docker restart node blade-2 service partition_alert_service
Restarting container affects configuration and data path. Do you want to proceed? [yes/no] yes

Repeat step 4, or step 3, if the VELOS has more than two blades.

Additional Information

This issue has the same root cause as K000160104 (ID 2225577), but the symptoms and workaround are different.
