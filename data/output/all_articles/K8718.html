Known Issue

This is the result of a known issue. An eXtremeDB error message may be reported when a monitor send or receive string contains certain special characters. The issue occurs under the following two conditions:

  • When the monitor send or receive string starts with any of the following unescaped characters:

    • plus ( + )
    • asterisk ( * )
    • question mark ( ? )
  • When the monitor send or receive string contains any of the following bracket characters and does not subsequently contain the corresponding close bracket:

    • open parenthesis ( ( )
    • open brace ( { )
    • open square bracket ( [ )

When loading a configuration that contains a monitor configured in this fashion, an error message similar to the following is displayed:

BIGpipe: monitor parameter creation error:
01031000:3: eXtremeDB - data validation failed

F5 Product Development is tracking this issue as CR91966.

This issue does not exist in BIG-IP version 9.4.0 or later.

Workaround

You may be able to work around this issue by escaping the offending characters with a backslash immediately preceding them. For example, to use the literal string really? as a monitor receive string, you should configure the Receive String value as:

really\?

If escaping a character does not resolve the issue, you can work around this issue by replacing each offending character with its hexadecimal value equivalent using the C-style \x notation used for character constants.

The following table lists the corresponding hexidecimal representation for each character:

CharacterHexadecimal Equivalent
plus ( + )\x2B
asterisk ( * )\x2A
question mark ( ? )\x3F
open parenthesis ( ( )\x28
open brace ( { )\x7B
open square bracket ( [ )\x5B

For example, to represent the hexadecimal equivalent of + using the \x notation, replace the + character with the following string:

\x2B
