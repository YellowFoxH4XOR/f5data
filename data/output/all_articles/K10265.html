Known Issue

Important: The recommended installation method for BIG-IP version 10.x is to use a logical volume management (LVM) partitioning scheme. However, BIG-IP version 10.x allows installation using the previous partitioning scheme applied by version 9.x, which allows both version 9.x and 10.x to be installed on different partition slots. Therefore, if version 10.x is installed using the partitioning employed by version 9.x, the 3400 platforms running version 10.x will be affected by this issue.

This is the result of a known issue. A 3400 platform with a 20 GB hard drive may fail to boot to the End-User Diagnostics (EUD) software when EUD version 11.1.0 is installed on a system that is not using the logical volume management (LVM) disk formatting partitioning scheme.

This issue occurs because the EUD is not able to correctly identify the /shared partition of the hard drive, preventing the EUD from swapping the SSH keys between the host and the SCCP when booting.

This issue only affects 3400 (C62) platforms that contain one of the following 20 GB hard drives:

  • HTS424020M9AT00
  • HDS728080PLAT20
  • HTE721060G9AT00
  • HTE726060M9AT00
  • IC25N020ATMR04-0

You can check if your 3400 platform is affected by this issue by identifying the hard drive installed. To do so, run the following command from the command line:

dmesg | grep ATA

For example, the following command output displays that two hard drives are installed on the platform. The drive listed as hda is a compact flash drive, the secondary drive identified as hdc is the hard drive to look for and match against the affected hard drive list. In this example, hdc shows the serial number of HTS424020M9AT00 as one of the affected hard drives:

hda: SILICONSYSTEMS INC 512MB, ATA DISK drive
hdc: HTS424020M9AT00, ATA DISK drive

F5 Product Development tracked this issue as PDT956 and it was fixed in EUD versions 11.2 and later.

Important: Due to separate issue affecting the BIG-IP 3400 (C62) platform for EUD versions 11.2 and later, F5 recommends that you install a previous version of EUD as detailed in the following workaround section.

Workaround

To work around this issue, obtain a previous version of the EUD and start it from a USB thumb drive.

Requirements

  • EUD-11.0.3.3.0.im file (Contact F5 Technical Support to obtain the file)
  • USB thumb drive (1 GB or larger)

Important: You must have direct access to a BIG-IP platform, as the steps in the following procedures require that you use the BIG-IP system to format and copy the EUD utility to the USB thumb drive.

Once you have obtained the appropriate EUD file from F5 Technical Support, perform the following procedures.

Load the EUD onto a USB Mass storage device

You can load a USB mass storage device from a BIG-IP system by mounting the IM file. To create a USB mass storage device on a BIG-IP system to startup the EUD, perform the following procedure:

  1. Download the IM file to the /var directory.
  2. Loopback mount the IM file by typing the following command:

    mkdir /tmp/eud; mount -o ro,loop /var/EUD-11.0.3.3.0.im /tmp/eud

  3. Insert a USB mass storage device into the platform on which you mounted the IM file.
  4. Type the following command to run the mkdisk utility:

    cd /tmp/eud; ./mkdisk

  5. After you have completed the installation, remove the USB mass storage device from the BIG-IP system.

Startup the EUD from a USB mass storage device

You must use this method to run the EUD if you loaded a USB mass storage device.

  1. If the system is turned on, turn it off.
  2. Plug in the USB mass storage device.
  3. Turn on the system.
    The EUD boots.
  4. When the EUD starts, the EUD menu displays.
