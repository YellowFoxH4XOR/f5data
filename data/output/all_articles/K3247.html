Issue

Under some circumstances, when a virtual server is configured to use active HTTP cookie persistence, an error message that appears similar to the following example is logged to the /var/log/bigip file:

Mar  3 12:00:01 bigip1 kernel: http: parsed node 10.10.10.10:80 
is not in vip 192.0.2.1:80 (client 10.0.0.1:1656)

The Parsed node is not in VIP message is informational only. It indicates that when a client connected to the virtual server and supplied a cookie, the cookie referenced a node that is no longer eligible to service the connection. This behavior can occur under any of the following circumstances:

  • The node was removed from the pool
  • The node IP address or port number has changed
  • The node is marked down
  • The node is disabled

When a client references a cookie for a node that is not eligible to service a connection, the BIG-IP system chooses a new node for the client and sends the connection. When the server responds, the BIG-IP system inserts a new cookie to replace the old (invalid) cookie that the client originally provided. This process will not cause a loss of service and is transparent to the end user.

If the servers that provide content for your site are rotated in and out of service frequently, F5 recommends that you remove the expiration for the Active HTTP Cookie so that the browser identifies the cookie as a session cookie, and discards it when the browser is closed.

To do so, perform the following procedure:

  1. From the Configuration utility, click Pools.
  2. Click on the pool name that you want to modify.
  3. Click the Persistence tab.
  4. Delete the numbers in the Expiration fields of the Active HTTP Cookie section.
  5. Click Apply.
