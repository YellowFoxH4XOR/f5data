K10781: Logon may fail if the Cluster/Failover Global ID setting does not match across cluster nodes

Topic

When configuring a FirePass cluster, the Cluster/Failover Global ID setting located on the Device Management: Configuration: Clustering and Failover page should be configured identically across all cluster nodes. If the setting is not configured identically and the cluster is load-balanced by a BIG-IP LTM system, users may receive an error message that appears similar to the following example when they attempt to log on to FirePass: 

my.activation.php3 - client data is invalid ! (2) checkToken() failed - wrong signature

FirePass cluster nodes use the Cluster/Failover Global ID setting to generate and verify token signatures for user sessions. If the BIG-IP LTM persistence timeout is reached prior to user logon, BIG-IP LTM may load balance the user’s logon request to a different cluster node. If that cluster node has a different Cluster/Failover Global ID setting than the original cluster node, token verification will fail and logon access is denied.

To avoid this behavior, ensure that the Cluster/Failover Global ID field is identical across all cluster nodes.

Note: For more information about configuring a FirePass cluster, refer to the FirePass Controller Administrator Guide.
