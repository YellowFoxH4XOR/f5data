Issue

The BIG-IP SSL proxy attempts to parse the headers for all HTTP transactions that it passes. Occasionally, the BIG-IP system is unable to parse the data in an HTTP transaction and the following message is logged as a result:

internal error: aborted parsing of stream to client

Two common reasons that prevent the BIG-IP system from parsing the HTTP headers include the following:

  • HTTP 1.0 transactions lack a Content-Length or Connection header
  • HTTP 1.1 transactions contain more data in the body of a server response than specified in the Content-Length header

In environments where clients use many different browsers, it is normal to see this message occasionally. This log message does not necessarily indicate a problem; however, if you are using rewrite redirects, this message may indicate that the rewrite failed.

If you are using rewrite redirects and parsing failed before the BIG-IP system read the Location header that is supposed to be rewritten, the rewrite will not occur.

If you are not using rewrite redirects, you can safely ignore this message.
