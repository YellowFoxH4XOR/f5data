K000153052: When using DNS Resolver for CRL, validation Fails

Type
Support Solution
Published
2026-02-20
Updated
2026-02-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.0
Source
https://my.f5.com/manage/s/article/K000153052

Description

When using DNS Resolver for CRL validation within SSL client profiles for mutual authentication, the SSL handshake fails with the following error messages in /var/log/ltm:

  • Connection error: ssl_hs_do_crl_validation:7278: alert(46) unknown certificate error
  • Invalid CRL distribution point from the certificate
  • SSL Handshake failed for TCP

The issue occurs when the client certificate contains a CRL Distribution Point (CRLDP) with an LDAP URI, or when multiple CRLDPs are present with LDAP listed first. The BIG-IP system does not attempt DNS resolution for the CRLDP and immediately rejects the handshake. When a static CRL file is used instead of dynamic CRL validation, authentication succeeds.

# openssl x509 -in mycrl.crt -text | grep -A 4 "X509v3 CRL Distribution Points"
            X509v3 CRL Distribution Points:
                Full Name:
                                      URI:ldap:///CN=crldp,DC=f5ss,DC=local
                Full Name:
                  URI:http://testurl.f5ss.local/mycrl.crl

Environment

SSL client profile configured with:

  • DNS resolver configured for CRLDP resolution
  • Client certificate authentication enabled (authenticate always or request)

Cause

By design, dynamic CRL validation on BIG-IP supports only HTTP URI CRLDPs for client certificate validation. Additionally, when multiple CRLDPs are present in a client certificate, only the first CRLDP entry is parsed and evaluated. If the first CRLDP is an LDAP URI, the validation fails immediately without attempting to use subsequent HTTP URIs.

Client certificates containing:

  • LDAP URI in CRL Distribution Points extension
  • Multiple CRLDPs with LDAP URI listed before HTTP URI

Recommended Actions

Choose one of the following solutions:

Option 1: Use Static CRL Files:

  • Download the CRL file from the certificate authority
  • Import the CRL file to the BIG-IP system
  • Configure the client SSL profile to use the static CRL file via the crl-file parameter
  • Note: This requires periodic manual updates as CRLs expire

Option 2: Modify Client Certificates (if possible)

  • Request certificates from the CA with only HTTP CRLDP URIs
  • If multiple CRLDPs are required, ensure the HTTP URI is listed first in the certificate extension given that only the first entry is evaluated by the BIG-IP.
  • Verify certificate CRLDP configuration using: openssl x509 -in <cert> -text | grep -A 4 "X509v3 CRL Distribution Points"
