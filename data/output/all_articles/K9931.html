Known Issue

This is the result of a known issue. Loosely-typed objects that do not support partitioning must reside in the Common partition. However, it is possible to edit the configuration file directly and move such objects into a specific partition other than the Common partition. The resulting configuration will load without an error or warning message, but further modifications made in the Configuration utility to the migrated object will be lost when the configuration is saved to disk. As a result, the configuration changes are not saved, and related features may no longer function as expected.

For example, you could edit the /config/bigip.conf file directly, moving the configsync stanza to a partition other than the Common partition. The modified configuration would load without error. You could then modify the configsync settings, such as the configsync user's password, in the Configuration utility without error. However, examination of the bigip.conf file would reveal that the password change was not retained, and as a result, configuration synchronization would fail.

F5 Networks Product Development is tracking this issue as CR117049.

Workaround

You can avoid this issue using the Configuration utility or the appropriate bigpipe commands to modify the partition for objects that support partitioning.
