Description

The legacy (non-tmm) HTTPS monitor does not provide support for sending SNI (Server Name Indication) in the TLS handshake for monitor probes, but this limitation can be worked around by using an external monitor that runs curl to monitor the status of pool members that require the SNI extention in the TLS handshake.

Note that if "in-tmm" monitoring is enabled, SNI can be defined in the ssl-profile associated with the HTTPs monitor - see K65219243

Environment

  • BIG-IP LTM / DNS (GTM)
  • External SNI monitor
  • Curl 

Cause

None

Recommended Actions

Follow the below procedures to configure a custom external monitor using Curl. 

  1. Save the script (shown below) into a file using any text editor such as notepad. example, myExtMon.txt 
    #!/bin/sh
# these arguments supplied automatically for all external pingers:
# $1 = IP (::ffff:nnn.nnn.nnn.nnn notation or hostname)
# $2 = port (decimal, host byte order)
#
if [ -z "${RECV}" ]
then
   RECV="html"
fi
if [ -z "${MON_NAME}"]
then
   MON_NAME="MyExtMon$$"
fi
# Name of the pidfile
pidfile="/var/run/$MON_NAME.$1..$2.pid"

# 1 = debug on
DEBUG=0

# Send signal to the process group to kill our former self and any children
# as external monitors are run with SIGHUP blocked
if [ -f $pidfile ]
then
   kill -9 -`cat $pidfile` > /dev/null 2>&1
fi

echo "$$" > $pidfile

# Remove the IPv6/IPv4 compatibility prefix
node_ip=`echo $1 | sed 's/::ffff://'`

#set hostname with ip for now but SSL SNI will fail
hostn=${node_ip}

# Get the hostname for $node_ip
if [ -n "${POOL}" ]
then
   for val in ${POOL}; do
      if [[ ${val} == "${node_ip}:"* ]]
      then
         hostn=`echo "${val}"|cut -d':' -f2`
         break
      fi
   done
   # Using the curl utility to get data from the server.
   # Search the data received for the expected expression.
   # Check `man curl` for more details regarding this
   curl -lvk --resolve ${hostn}:${2}:${node_ip} https://${hostn}:${2}/${URI} | grep -E -i ${RECV} > /dev/null 2>&1
   status=$?
fi

# Remove the pidfile before the script ends
rm -f $pidfile > /dev/null 2>&1

if [[ $status -eq 0 ]]
then
# Remove the pidfile before the script echoes anything to stdout and is killed by bigd
    echo "up"
fi

# For troubleshooting, enable debugging
if [ ${DEBUG} -eq 1 ]
then
echo "Debugging on..."
echo "SNI=${hostn}"
echo "RECV=${RECV}"
echo "URI=${URI}"
echo "IP=${node_ip}"
echo "PORT=${2}"
echo "MON_NAME=${MON_NAME}"
echo "POOL=${POOL}"
echo "curl -lvk --resolve ${hostn}:${2}:${node_ip} https://${hostn}:${2}${URI} | grep -E -i ${RECV} > /dev/null 2>&1"
fi
  2. Navigate to "System  ››  File Management: External Monitor Program File List". Import the file created in step 1 and name the External Monitor Program. example, myExtMonProg
  3. Navigate to "Local Traffic  ››  Monitors" and create an external health monitor type with the following options:
Name                  : <put a name>.
External Program: the program that was created in step 2.
Add the below variables:
    Name  =    Value
    RECV  =  <receive string>
    URI  =  <uri to monitor>
    POOL  =  (format is IP address1:hostname1 address2:hostname2 ... addressN:hostnameN)
    MON_NAME  =  <put the name of the monitor> (this is optional. the monitor will still work even without this variable/value)

    Additional Information

    If after applying the external monitor seems like it is not running, particularly if messages like 'EAV execve: No such file or directory' are seen in /var/log/bigdlog when bigd.debug=enable, it may be due to windows line feeds in the file. Please refer to K41251003: External monitor fails to run as extra line feed characters may be added when saving files on Windows.
