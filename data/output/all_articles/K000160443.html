Description

This article explains each field displayed in the output of the tmsh show sys license command on BIG-IP systems. Understanding these fields is essential for license management, upgrade planning, and support contract validation.

 

Environment

  • BIG-IP (all platforms and versions)
  • BIG-IP Virtual Edition (VE)
  • rSeries (BIG-IP tenant)
  • VELOS (BIG-IP tenant)
  • VIPRION (BIG-IP blade)
  • Command Line Interface (CLI) / tmsh

 

Cause

Administrators may be unfamiliar with the meaning of individual fields in the tmsh show sys license output, particularly the distinction between date fields such as Licensed On, Service Check Date, and License End Date, which are frequently misinterpreted.

Identity & Key Fields

Field

 Description

Licensed VersionThe BIG-IP version running at the time the unit was first licensed. This is a semi-static value — it does not update on software upgrade or license reactivation. It only changes after an allow-move operation. Do not interpret this as the currently running software version.
Registration Keyhe 27-character base registration key in the format AAAAA-BBBBB-CCCCC-DDDDD-EEEEEEE. This key is used to activate the license against the F5 license server and is tied to the platform.
Platform IDAn F5 internal code identifying the hardware platform (for example, C62, Z100k, C113). Used by F5 to validate that the license is appropriate for the hardware.
Appliance Serial NumberThe hardware serial number of the device (e.g., f5-xxxx-xxxx). Ties the license to a specific physical or virtual unit.

 

Date Fields

Field

Description

Licensed OnThe date the license was first activated on this unit. Semi-static — does not change on reactivation or upgrade. Only updates after an allow-move. In the GUI, this same field is labeled "Licensed Date". It's for F5 internal use only. It is not used by BIG-IP to deliver any product functionalities and can be ignored.
License Start DateThe date from which the license is valid (typically one day before "Licensed On").
License End DateThe date the license expires. For perpetual licenses this may be far in the future. For subscription/Demo licenses, this is the hard expiry. Monitor this to avoid unexpected outages.
Service Check Date  ⚠️    The most operationally important date.
This will be updated every time to the date you reactivate the license (provided an active support contract exists), if not it will show the date the support contract expires. This date must be ≥ the License Check Date of any BIG-IP software version you want to upgrade to.

Note: The Service Check Date and the License Check Date are two distinct values that are frequently confused:

  • The Service Check Date is stored in the license file on the device and is visible in tmsh show sys license.
  • The License Check Date is a static date embedded in each BIG-IP software ISO at the time of its release.
  • If the Service Check Date is earlier than the License Check Date of the target software version, the upgrade will be blocked and configuration may not be loaded.

     Service Check Date examples:

Scenario Result
Service contract ends 2024/12/31, license reactivated 2024/06/30Service Check Date = 2024/06/30 (reactivation date is earlier)
Service contract ends 2024/06/30, license reactivated 2024/12/31Service Check Date = 2024/06/30 (contract expiry is earlier)

 

Virtual Edition and Subscription-Specific Fields

FieldDescription
Permitted Versions

Present on VE licenses only. Specifies the range of BIG-IP software versions permitted under this license (for example, 5.*.* - 17.*.*). Attempting to run a version outside this range will result in a license validation failure.

Daily Renewal Notification DaysThe number of days before license expiry at which the system begins generating daily renewal warning notifications.

Additional Information

The license file is stored at /config/bigip.license and can be inspected directly using grep or cat.

To request a product license profile (entitlement summary, serial number, service contract dates) from F5, use the F5 Product Information Request portal.

If your system is nearing end of support entitlement, a banner warning will appear in F5 iHealth on the main Status page.
