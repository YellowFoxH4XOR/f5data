Known Issue

HTTP 2.0 responses with multiple duplicate headers are incorrectly concatenated as single headers.

This issue occurs when all of the following conditions are met:

  • A BIG-IP virtual server is configured with an HTTP/2 profile.
  • The HTTP/2 virtual server is attached to a pool consisting of HTTP/1.1 members.

Prior to draft 14 of RFC 7540, every HTTP header was to appear only once (no duplicate header names). If multiple occurrences of a header field with the same name were required, the ordered values of those headers were concatenated into a single value using a null character (\0) as a delimiter. In draft 14 and later, this restriction no longer exists.

If an HTTP/2 request received by the BIG-IP system, forwarded to an HTTP/1.1 pool member, produces a response that has the same header occurring more than once, the HTTP/2 response will be encoded incorrectly by the BIG-IP system, and the HTTP/2 browser may not process it correctly.

Impact

An HTTP/2 browser may not be able to correctly process the HTTP responses.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Multiple duplicate headers, such as the Set-Cookie header, are concatenated into a single header in the response, which the client then fails to recognize.
