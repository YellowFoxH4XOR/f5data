Known Issue

Restoring a BIG-IP 10.x user configuration set (UCS) to BIG-IP 11.4.x - 12.x incorrectly retains the 10.x ca-bundle.crt certificate bundle.

This issue occurs when one of the following conditions are met:

  • Your BIG-IP system is upgraded from version 10.x to 11.4.x - 12.x.
  • A version 10.x UCS is restored on BIG-IP  11.4.x - 12.x.

Note: Installing a BIG-IP 10.x UCS on version 13.x, or upgrading directly from 10.x to 13.x is not supported.

Impact

The ca-bundle.crt is not copied during a configuration synchronization (ConfigSync) operation, so non-deterministic behavior can occur if peer devices in a high availability (HA) configuration have different versions of the ca-bundle.crt. For example, you may have two BIG-IP systems in a HA configuration where one of the BIG-IP systems contains an older version of ca-bundle.crt. The configuration also contains a Client SSL profile with a ca-bundle.crt designated as the chain certificate. When the BIG-IP system with the current ca-bundle.crt constructs and sends a full certificate chain in an SSL Server Hello, the peer BIG-IP system with the older ca-bundle.crt file might be unstable to construct the full certificate chain.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Inconsistent CA certificate chain creation occurs against the /config/ssl/ssl.crt/ca-bundle.crt certificate bundle.

Workaround

To work around this issue, you can manually copy the correct certificate bundle to /config/ssl/ssl.crt/ca-bundle.crt. To do so, perform the following procedure:

Impact of workaround: Performing this procedure requires a reboot of the BIG-IP system. Rebooting disrupts traffic processing until the system is back up, or until the peer in an HA configuration has taken over.

  1. Log in to the BIG-IP command line.
  2. To create a backup copy of the current ca-bundle.crt file, type the following command:

    cp /config/ssl/ssl.crt/ca-bundle.crt /config/ssl/ssl.crt/ca-bundle.crt.K15645547

  3. To copy the ca-bundle.crt file for your BIG-IP version, type the following command:

    cp /usr/share/defaults/fs/config/ssl/ssl.crt/ca-bundle.crt.rpmbackup /config/ssl/ssl.crt/ca-bundle.crt

  4. To force the mcpd process to reload the configuration, type the following command:

    touch /service/mcpd/forceload

    On VIPRION systems, type the following command to run this on all blades:

    clsh touch /service/mcpd/forceload

  5. To reboot the BIG-IP system, type the following command:

    Important: This command will interrupt traffic while the BIP-IP system either fails over to a peer system or completes the reboot process.

    reboot

    On VIPRION systems, type the following command to run this on all blades:

    clsh reboot

  6. After reboot, to verify that the ca-bundle.crt.rpmbackup and ca-bundle.crt files match, type the following command:

    md5sum /usr/share/defaults/fs/config/ssl/ssl.crt/ca-bundle.crt.rpmbackup /config/ssl/ssl.crt/ca-bundle.crt

    The output should look similar to the following example:

    95f4a935a58e9d69d21d239e46b7045f /usr/share/defaults/fs/config/ssl/ssl.crt/ca-bundle.crt.rpmbackup
    95f4a935a58e9d69d21d239e46b7045f /config/ssl/ssl.crt/ca-bundle.crt
