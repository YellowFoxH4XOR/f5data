Known Issue

The traffic group definition may be missing from the / and /Common partitions and objects that inherit the settings of the partitions.

This issue occurs when one of the following conditions is met:

  • You upgrade a BIG-IP redundant pair from 10.x to an affected version.
  • You restore a user configuration set (UCS) of a redundant pair from 10.x to an affected version.
  • You remove a device from the Sync-Failover device group; this condition applies to only BIG-IP 11.2.1.

The upgrade triggers trust formation between the two units. During this process, the system incorrectly deletes the traffic group entries for the / and /Common folders.

A traffic group represents a collection of shared configuration objects that are configured on a BIG-IP device. When a BIG-IP device becomes unavailable, a traffic group and associated configuration objects can fail over to another device in the device group.

Impact

The affected configuration objects may fail to process traffic as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H406699 on the Diagnostics > Identified > High screen.
  • Affected configuration objects such as Secure Network Address Translations (SNATs) and virtual servers fail to process traffic as expected.
  • The BIG-IP system generates duplicate IP address messages for affected configuration objects to the /var/log/ltm file. The messages appear similar to the following example:

    01190004:4: address conflict detected for 192.168.1.1 (00:01:D7:C6:77:81) on vlan ext
    01190004:4: address conflict detected for 192.168.1.2 (00:01:D7:C6:77:81) on vlan ext
    01190004:4: address conflict detected for 192.168.1.3 (00:01:D7:C6:77:81) on vlan ext
  • The traffic-group for the / and /Common folders is set to none.

    For example, output from the tmsh list /sys folder /Common / command appears similar to the following example:

    # tmsh list /sys folder /Common /

    sys folder / {
    device-group Common/device-group-failover-newgroup
    traffic-group none
    }

    sys folder /Common {
    device-group Common/device-group-failover-newgroup
    inherited-devicegroup true
    inherited-traffic-group true
    traffic-group none
    }

Resolution

Status

F5 Product Development has assigned ID 402394 and ID 425028 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release11.5.0*
11.3.0*		K2200: Most recent versions of F5 software
Hotfix11.4.1 HF2*
11.2.1 HF8*		K9502: BIG-IP hotfix matrix

* Important: The traffic group definitions that were incorrectly deleted are no longer in the BIG-IP configuration file. Upgrading the affected BIG-IP system to a fixed version does not recover the affected traffic group definitions. To recover the traffic group definitions and prevent this issue from manifesting in future upgrades, you must upgrade the affected system to a fixed version, and perform the procedure discussed in K08114320: Configuring traffic group definition for various objects and folders/partitions.

Workaround

To recover from this issue, you can configure the appropriate traffic group definition for each affected folder and failover object. To do so, refer to the procedure in K08114320: Configuring traffic group definition for various objects and folders/partitions.
