Description

With BIG-IP APM configured to send OTP code through email, users are not receiving those OTP codes on their mobile devices.
As such, users cannot comply out with APM AccessPolicy and cannot successfully authenticate.

Looking at the O365 Exchange console, you can see messages, about the email format:
we're seeing bare line feed [LF] but no carriage return [CR]

Environment

  • BIG-IP APM
  • Access Policy is using an "email" agent, that sends email as per the System >> SMTPD configuration
  • Users' mailboxes are hosted online

Cause

O365 Exchange is rejecting the emails from BIG-IP APM because those later are written using "LineFeed [LF]" characters, when they should use both "LineFeed [LF]" and "Carriage Return [CR]" characters, as stressed by RFC5322.
If you are experiencing this it is due to a misconfiguration

Recommended Actions

Change the configuration of the "Email" agent in the VPE.  Please put one and only one line in the agent (you can use session variable, too).
