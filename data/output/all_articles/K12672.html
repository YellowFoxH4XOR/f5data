Known Issue

This is the result of a known issue. BIG-IP WebAccelerator removes linear white space (LWS) between cookie names when sending requests to the origin web server (OWS). This behavior may cause issues with the request if the OWS or logging server requires white space between cookie instances.

Note: RFC 2616 permits the use of LWS (or no LWS) between two adjacent words in the header.

For example, the following request contains a cookie header with three cookies separated by white space:

GET /test/index1.html HTTP/1.0
Connection: Keep-Alive
User-Agent: curl/7.19.7 (i486-pc-linux-gnu) libcurl/7.19.7 OpenSSL/0.9.8k zlib/1.2.3.3 libidn/1.15
Host: wam234.jh.es.example.com
Accept: */*
Cookie: COOKIE1=1; COOKIE2=2; COOKIE3=3
Accept-Encoding: identity

The BIG-IP WebAccelerator system processes the request and strips the white space between the cookies before sending the request to the OWS, as displayed in the following example:

GET /test/index1.html HTTP/1.0
Connection: Keep-Alive
User-Agent: curl/7.19.7 (i486-pc-linux-gnu) libcurl/7.19.7 OpenSSL/0.9.8k zlib/1.2.3.3 libidn/1.15
Host: wam234.jh.es.example.com
Accept: */*
Cookie: COOKIE1=1;COOKIE2=2;COOKIE3=3
Surrogate-Capabilities: WA="ESI/1.0", WA="ESI-Inline/1.0"
Accept-Encoding: identity
X-Remote-Addr: 192.168.48.52
X-Client: WA
X-PvMAC: 00:90:0B:0C:2A:56

F5 Product Development tracked this issue as ID 341876, and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.
