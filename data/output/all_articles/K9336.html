Known Issue

This is the result of a known issue. If a Microsoft Windows 2000 client launches a Network Access connection, and the client receives a large packet (greater than 1400 bytes) through the VPN tunnel, the Network Access connection remains connected but stops passing traffic.

Important: This issue occurs only in FirePass 6.0.2 after installing cumulative hotfix HF-602-6, HF-602-7, or HF-602-7.2.

F5 Product Development tracked this issue as CR109359 and it was fixed in FirePass 6.1.0. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue has been fixed in cumulative hotfix HF-602-8 issued for FirePass 6.0.2, cumulative hotfix HF-603-1 issued for FirePass 6.0.3, and BIGIP_SAM-8.0.0-1560.0-HF1 issued for BIG-IP SAM 8.0. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

Important: An auto-update issue exists for Windows 2000 clients. Windows 2000 clients that already have FirePass Network Access client components installed will not receive updated components after installing cumulative hotfix HF-602-8 or cumulative hotfix HF-603-1. Users can work around this issue by removing the old client components before logging in to the FirePass controller. The auto-update issue was also tracked as CR109359, and it was fixed in cumulative hotfix HF-602-9 for FirePass 6.0.2 and cumulative hotfix HF-603-2.1 for FirePass 6.0.3.

Workaround

Users can work around this issue by disconnecting and reconnecting the Network Access connection.
