Known Issue

The block-device-image option may incorrectly use the software image file residing on the Virtual Clustered Multiprocessing (vCMP) guest to perform a software installation.

This issue occurs when all of the following conditions are met:

  • You attempt to perform a software installation on an existing vCMP guest using the TMOS Shell (tmsh).
  • The vCMP host and vCMP guest have a copy of a software image file with the same product, version, and build in their /shared/images directories.
  • During software installation you specify the block-device-image option for the vCMP host software image file using the following command syntax:

    tmsh install /sys software block-device-image <software image file> volume <software volume>

You can use the block-device-image command option on the vCMP guest to perform software installation from the software image file residing on the vCMP host. However, if the software image file on the vCMP guest is damaged, the software installation fails. When this happens, it may seem as though the software image file on the vCMP host is damaged rather than the one on the vCMP guest, and this may cause you to misdiagnose the issue.

Impact

Software installation on the vCMP guest fails.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • If you enable debugging on the lind process on the vCMP guest, you notice that the software installation runs without mounting the software image file from the vCMP host, indicated by messages in the /var/log/ltm file which appear similar to the following example:

    info lind[<PID>]: 013c0007:6: Attempt to upgrade volume HD1.1 from // to BIG-IP/12.1.2/0.0.249
    debug lind[<PID>]: 013c0008:7: Execute installer

    When you specify the block-device-image install option, messages in the /var/log/ltm file should appear similar to the following example:

    info lind[<PID>]: 013c0007:6: Attempt to upgrade volume HD1.1 from // to BIG-IP/12.1.2/0.0.249
    debug lind[<PID>]: 013c0008:7: Going to launch install with /dev/cdrom
    debug lind[<PID>]: 013c0008:7: Inserting device: /dev/cdrom:51d914bb-7d84-56ac-a640-818af64a054b
    debug lind[<PID>]: 013c0008:7: Execute installer

    Note: Keeping debug logging running over time may cause disk space exhaustion. F5 recommends that you only enable debug logging while actively troubleshooting an issue and disable debug logging after you finish troubleshooting.

Workaround

There is no workaround for this issue; however, before performing software installation using the block-device-image option, you can delete the software image file on the vCMP guest so that the software image file only exists on the vCMP host. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line on the vCMP guest.
  2. Delete the software image file using the following command syntax:

    tmsh delete /sys software image <software_image_file>

    For example, to delete the software image file BIGIP-12.1.2.0.0.249.iso, type the following command:

    tmsh delete /sys software image BIGIP-12.1.2.0.0.249.iso

  3. Save the configuration by typing the following command:

    tmsh save /sys config

  4. Perform the software installation.
