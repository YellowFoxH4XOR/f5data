K78416643: vCMP guest inoperative after vCMP host software upgrade

Type
Support Solution
Published
2022-03-03
Updated
2025-03-19
Applies to
  • VIPRION Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K78416643

Description

vCMP guests started up after their vCMP host has been upgraded may be inoperative.
The clusterd process continually restarts and error messages similar to the following are logged to /var/log/ltm:

err mcpd[6519]: 0107146f:3: Self-device state mirroring address cannot reference the non-existent Self IP ([IP address]); Create it in the /Common folder first

Environment

  • vCMP guest with vCMP host upgrade
  • Mirroring IP configured on vCMP guest

Cause

Bug ID 935633

Recommended Actions

If you experienced this issue on your vCMP guest, you may want to perform the following procedure to recover from this issue:

  1. Log in to the vCMP host Configuration utility.
  2. Go to vCMP > Guest List.
  3. Select the name of the affected vCMP guest.
  4. In the Properties tab, locate the Requested State setting and set the value to Configured. This will shutdown the vCMP guest.
  5. Select Update to save the change. The Configuration utility will return to the Guest List page. Wait for the vCMP guest to complete transition to the Configured state; the Configuration utility will display a grey diamond in the Status column when the vCMP guest is in the Configured state.
  6. Select the name of the same affected vCMP guest.
  7. In the Properties tab, locate the Requested State setting and set the value to Deployed. This will start up the vCMP guest.
  8. Select Update to save the change. The Configuration utility will return to the Guest List page. Wait for the vCMP guest to complete transition to the Deployed state; the Configuration utility will display a green circle in the Status column when the vCMP guest is in the Deployed state.
  9. SSH to the vCMP guest.
  10. Review the /var/log/ltm file and confirm the following is no longer present or happening after the reboot of the vCMP guest:
    1. Confirm "Self-device state mirroring address cannot reference the non-existent Self IP" message is no longer present.
    2. Confirm clusterd is no longer restarting.
  11. If the issue persists, contact F5 Support for assistance specific to the vCMP guest. Alternatively, you can attempt to delete and recreate the vCMP guest; for information about recreating a vCMP guest, refer to K66401291: Recreating VCMP Guest from UCS archive.

Additional Information
To proactively avoid reaching this situation in a software version which is affected by ID935633, perform the following prior to starting the vCMP host upgrade process:

  1. Ensure all vCMP guests are Deployed and functional
  2. Perform the following on each vCMP Guest:
    1. Examine partitions and ensure /var has 25-30% free space, correcting if needed
    2. Issue "tmsh save sys config"
    3. Issue "ls /var/db/mcp*" and confirm presence of mcpdb.bin and mcpdb.info in /var/db directory
    4. Contact F5 support if files are not present
  3. Shutdown all vCMP guests as normal
  4. Upgrade vCMP host as normal
