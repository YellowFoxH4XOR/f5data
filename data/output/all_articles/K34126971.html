Description
In case you are running out of space on /var and getting the following messages:

  • Disk partition /var (slot #) has only 0% free
  • UCS archives may fail to generate or restore.

Environment

  • BIG-IP appliance
  • /var directory is full or nearly full when viewed with 'df -h'

Cause

  • Sometimes this is caused by large hosted files stored in APM configuration or old EPSEC files. 
  • This also could be caused due to a large firewall policy in AFM, which in the latest versions (17.1.0, 16.1.4, 15.1.9) could reach until 8G.
  • UCS archives are stored in the /var filesystem   ( /var/local/ucs)

Recommended Actions

  1. Verify the software volume using the tmsh command: 
    root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# show sys software

    Example:
    -----------------------------------------------------
    Sys::Software Status
    Volume  Product  Version      Build  Active    Status
    -----------------------------------------------------
    HD1.1    BIG-IP   12.1.1  1.125.196      no  complete
    HD1.3    BIG-IP   12.1.1  1.125.196     yes  complete
     

  2. Verify the available free space on the BIG-IP using either the vgs or vgdisplay command in the Linux command line.

    Option 1: using the vgs command, for example,

    [root@bigip1:Active:Standalone] config # vgs

    Example:
      VG        #PV #LV #SN Attr   VSize   VFree 
      vg-db-sda   1  17   0 wz--n- 931.51g 22.05g             <<<< 22 GB of available free space!

    Option 2: using the vgdisplay command, for example,

    [root@asm13:Active:Standalone] config # vgdisplay

    Example
      --- Volume group ---
      VG Name               vg-db-sda
      System ID
      Format                lvm2
      Metadata Areas        1
      Metadata Sequence No  18
      VG Access             read/write
      VG Status             resizable
      MAX LV                0

      Open LV               8
      Max PV                0

      PE Size               4.00 MiB
      Total PE              20935
      Alloc PE / Size       15289 / 59.72 GiB
      Free  PE / Size       5646 / 22.05 GiB             <<<< 22 GB of free available space!
     

  3. Find the /var logical volume created for the new software volume using the df and lvdisplay commands. This will change by platform, but it should be end in set.XXX._var, where XXX is equal to the part after HD1. or MD1. Locate the /var logical volume using the df -h command, for example, 
    [root@bigip1:Active:Standalone] # df -h

    Example:
    Filesystem            Size  Used Avail Use% Mounted on
    /dev/mapper/vg--db--sda-set.2.root
                          427M  272M  133M  68% /
    none                  3.9G  2.3M  3.9G   1% /dev/shm
    <<SNIPPET>>
    /dev/mapper/vg--db--sda-set.1._usr
                          4.0G  3.1G  684M  83% /usr
    /dev/vg-db-sda/set.1._var
                          3.0G  855M  2.0G  30% /var
    /dev/mapper/vg--db--sda-dat.share
                           20G  9.0G  9.8G  48% /shared
    /dev/mapper/vg--db--sda-dat.log
                          2.9G  179M  2.6G   7% /var/log
    /dev/mapper/vg--db--sda-dat.appdata
                           25G  1.9G   22G   8% /appdata
    <<SNIPPET>>
     

    Based on this example output, you can use the follwing command syntax to list out the details of the /var logical volume:

    lvdisplay <logical volume path>

    For example,

    [root@bigip1:Active:Standalone] config # lvdisplay /dev/vg-db-sda/set.1._var

    The command should return an output similar to the following example:

      --- Logical volume ---
      LV Path                /dev/vg-db-sda/set.1._var
      LV Name                set.1._var
      VG Name                vg-db-sda
      LV UUID                bVdT2O-G19D-cQSS-B36v-fXGl-NQok-rDulXF
      LV Write Access        read/write
      LV Creation host, time bigip1.lab.darby, 2017-04-05 10:32:22 -0700
      LV Status              available
      # open                 0
      LV Size                3.00 GiB
      Current LE             768
      Segments               1
      Allocation             inherit
      Read ahead sectors     auto
      - currently set to     256
      Block device           253:7
     

  4. Resize the logical volume to add 5G using the following command syntax:

    lvresize <logical volume path> -L +<integer amount to increase in GB> --resizefs

    For example,

    [root@bigip1:Active:Standalone] config # lvresize /dev/vg-db-sda/set.1._var -L +5G  --resizefs
  5. Confirm the new value using the following command syntax:

    lvdisplay <logical volume path>

    For example,

    [root@bigip1:Active:Standalone] config # lvdisplay /dev/vg-db-sda/set.1._var

    The command should return an output similar to the following example:

      --- Logical volume ---
      LV Path                /dev/vg-db-sda/set.1._var
      LV Name                set.1._var
      VG Name                vg-db-sda
      LV UUID                bVdT2O-G19D-cQSS-B36v-fXGl-NQok-rDulXF
      LV Write Access        read/write
      LV Creation host, time bigip1.lab.darby, 2017-04-05 10:32:22 -0700
      LV Status              available
      # open                 0
      LV Size                8.00 GiB
      Current LE             2048
      Segments               2
      Allocation             inherit
      Read ahead sectors     auto
      - currently set to     256
      Block device           253:7
     

  6. Reboot the BIG-IP. 
    [root@bigip1:Active:Standalone] config # reboot
  7. On VIPRION systems, you will need to repeat the same steps on each slot.

    Note: By default, the /var partition is set to 3.1 GB in versions prior to BIG-IP 16.0.0, and 4.7 GB in BIG-IP 16.0.0 and later. If you have previously increased the size of /var, an upgrade will reset it to the default value for that version.

    Note: There is no supported method to shrink the /var partition. Perform an upgrade or reinstallation to revert the changes, which will reset to the default size.
