Description

Aspen Mesh Metrics Collector is an integrated part of Aspen Mesh package and is installed by default with other components of the cluster. Metrics Collector is a Prometheus instance customized for Aspen Mesh needs and used for collecting metrics from all mesh cluster components. Metrics-collector manifests are bundled into aspen-mesh-metrics-collector sub-chart and we can control it’s configuration using overrides Helm values file. In addition to Prometheus aspen-mesh-metrics-collector sub-chart deploys Alertmanager in the cluster. 

Official documentation for Prometheus and Alertmanager are here:

  • Prometheus Alertmanager
  • Overview of Prometheus

In this article we document what metrics are scraped by aspenmesh-metrics-collector and how to customize and configure metrics-collector Prometheus instance.

Additional Information

Aspen Mesh metrics-collector is a sub-chart of istio-control Helm chart (typically installed as istiod). Most of (but not all) default configuration options for aspen-mesh-metrics-collector are split into global and sub-chart values yaml files located in the install tar ball file:

manifests/charts/istio-control/istio-discovery/charts/aspen-mesh-metrics-collector/values.yaml
manifests/charts/istio-control/istio-discovery/values.yaml

Default configuration should be treated as a reference configuration and every change should be applied using override global values yaml file specified for istio-control chart.

To modify any default configuration field for metrics-collector we must add a new aspen-mesh-metrics-collector section. Below is the example showing how to modify the size of the persistent volume used by Prometheus to store metrics and how to modify retention time for metrics.

$ cat values-override.yaml
aspen-mesh-metrics-collector:
  server:
    retentionTime: "10h"
    persistentVolume:
      size: 15Gi 

retentionTime field is an example of a field not specified in the sub-chart values.yaml file. If this field is missing, then the Prometheus will use default retention time for metrics which is 14 days.

  serviceImage: metrics-collector-service-1.9.5-am1
  server:

As we see above Aspen Mesh Metrics Collector and Alertmanager are enabled by default. All data collected by Prometheus and Alertmanager are stored in Kubernetes PersistentVolumes (10 Gi and 2Gi).  Thanks to string the data in the persistent storage, metrics are not removed in case of the POD restart or crash. Prometheus container resource limits ar aspenmesh-carrier-grade-1.9.8-am1 e set to 512 Mi of memory and 500m of CPU.

For more information about the meaning of configuration options please look at comments in values yaml files, official aspenmesh.io documentation or open a support ticket.

Metrics Collector Prometheus configuration is stored in aspen-mesh-metrics-collector ConfigMap:

$ kubectl get cm c -n istio-system
NAME                           DATA   AGE
aspen-mesh-metrics-collector   2      32d

Metrics targets discovery is done using kubernetes_sd_config plugin. Targets are grouped into 5 main jobs:

  • job_name: 'aspen-mesh-control-plane'
    • all pods with “app: aspen-mesh-control-plane” label from istio-system namespace
    • metrics path: /metrics
  • job_name: 'jaeger-cassandra'
    • all pods with “app: jaeger-cassandra” label from istio-system namespace
    • metrics path: /metrics
  • job_name: 'envoy-stats'
    • all PODs with containers port name “.*-envoy-prom” label from any namespace
    • metrics path: /stats/prometheus on port 15090
  • job_name: 'pilot'
    • all Istiod PODs 
    • metrics path: /metrics

More information about Prometheus configuration can be found on the official documentation.

Aspen Mesh metrics collector by default is configured to collect Prometheus metrics from all Control Plane PODs (those which expose metrics) and from all PODs being the part of the mesh. Every envoy istio-proxy container, injected to every mesh POD, is exposing a set of metrics on container port 15090 and URI /stats/prometheus. The number of metrics created by istio-proxies depends on the size of the mesh and the type of traffic being sent between PODs. 

All metrics collected by Aspen Mesh Metrics Collector can be retrieved.

Metrics collected by Aspen Mesh Metrics Collector can be retrieved by using Prometheus Web UI or by running API query. Metrics collector data can be used by visualization systems like Grafana as a data source by using aspen-mesh-metrics-collector.istio-system service and 19090 port.

To open Prometheus web UI we can expose port 9090 using Kubernetes external service or by opening kubectl port-forward.

For example:

kubectl -n istio-system port-forward aspen-mesh-metrics-collector-6ccc79b6c9-bhb7l 9091:9090

Having port-forward opened for localhost we can query Prometheus API using PromQL:

curl -s --data-urlencode 'query=topk(20,scrape_samples_scraped)' -o topk_scrape_samples_scraped http://localhost:9090/api/v1/query

More information about querying metrics can be found on official Prometheus documentation.
