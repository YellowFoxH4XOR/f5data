Topic

You should consider using this procedure under the following conditions:

  • You are experiencing FIPS HSM sync failures.
  • You want to verify that FIPS HSM key export is disabled and restore FIPS HSM synchronization.

Description

ID1023341 introduced a FIPS HSM configuration change, set during initialization, to disable key export. A side-effect of this change breaks syncing in some high availability (HA) pairs, depending on when the FIPS HSMs were last initialized. 

For example, the following table shows the sync status of two BIG-IP systems, BIG-IP A and BIG-IP B.

 BIG-IP A FIPS HSM key export enabledBIG-IP A FIPS HSM key export disabled
BIG-IP B FIPS HSM key export enabledSync worksSync does not work
BIG-IP B FIPS HSM key export disabledSync does not workSync works

The change was introduced in the following versions and affects these and all later versions on the given branch.

BranchBIG-IP version
17.0.x17.0.0
16.1.x16.1.1
15.1.x15.1.5.1
14.1.x14.1.4.6
13.1.x13.1.5

Note: The issue depends on the version of software the system was running at the time the FIPS HSMs were last initialized and not the version currently installed. To determine the status of the FIPS HSM, see the procedure Determine the current status, following.

Platforms

This issue affects only the following platforms containing the Cavium Nitrox III FIPS HSM: 

  • 10350v-F
  • i5820-DF
  • i7820-DF
  • i15820-DF

The rSeries r5920-DF and r10920-DF are supported only on software versions with the change. Therefore, it is not possible to experience this issue between rSeries units. 

This issue does not affect older platforms containing the Cavium Nitrox XL FIPS HSM. See the F5 Certifications page for more information.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have root access, using SSH or console, to the Advanced shell (bash). This procedure is not supported in appliance mode.
  • Have the FIPS HSM Security Officer (SO) password.
  • Have both your BIG-IP systems upgraded to the same software version containing the fix for ID 1023341, as previously noted.

Procedures

Review all of the following steps before attempting to perform the procedures.

Important: Perform the following procedures during a maintenance window, as it may cause traffic disruption. The process requires disabling services on both devices at different points, before syncing, and, therefore, HA is restored. It is likely that the sole active device will be offline for a period during this process. F5 recommends that you create a UCS backup and store it off the BIG-IP system before beginning the procedure. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

  • Determine the current status
  • Back up Source system HSM Partition
  • Restore Target system HSM Partition
  • Sync FIPS keys

Determine the current status

The first step is to determine which BIG-IP system should be the Source and which should be the Target. This involves installing and running a utility and noting the resulting output. To do so, perform the following procedure on both BIG-IP systems:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To download the utility, go to https://my.f5.com/manage/s/downloads and sign in using your MyF5 account.
  2. For Group, select Hardware-Specific.
  3. For Product Line, select FIPS_UTIL.
  4. For Select a product container, select n3fipsutil_v1.8.
  5. For Select a download file, select n3fipsutil.
  6. For Download locations, select a download location.
  7. To download the file, select Download.

    To download the md5 file, repeat steps 5 -7 selecting n3fipsutil.md5 in step 5. You can then verify the file using the steps in K8337: Verifying the MD5 checksum for the downloaded F5 software file.

  8. Transfer the n3fipsutil file to the /var/tmp/ directory on the BIG-IP system using the instructions in K175: Transferring files to or from an F5 system.
  9. Log in to the BIG-IP system as root.
  10. Set execute permissions on the /var/tmp/n3fipsutil file by entering the following command:

    chmod 755 /var/tmp/n3fipsutil

  11. Check the FIPS HSM to see if it has been initialized with the key export or not by entering the following command:

    /var/tmp/n3fipsutil -exportKeyCheck

    Note the resulting output. It will be either KeyExport: Enabled or KeyExport: Disabled.

    If both systems have the same status, syncing should be functional. However, if the two systems have different results you need to continue with the following procedures to restore syncing functionality.

    If you do not need to perform additional procedures, you may remove the utility from the system by entering the following command:

    rm /var/tmp/n3fipsutil.

    Note: If both BIG-IP systems show KeyExport: Enabled, F5 recommends that you follow the Apply The Fix procedure in K000135566: Disabling Cavium Nitrox III HSM key export  to apply the fix and disable key export.

    Important: Presuming you need to continue with the procedure, the BIG-IP system with KeyExport: Disabled is your Source system, while the system with KeyExport: Enabled is your Target system.

    Note: When using vCMP, you must perform the following procedures individually on each guest pair. Before beginning, you must log in to each vCMP Guest as root, then from that shell, SSH into the vCMP Host to ensure the SSH keys are exchanged, as the tool requires them when it runs. Once this is complete, you can exit the Host SSH session to drop back to the root shell on the Guest.

Back up Source system HSM Partition

Impact of procedure: Perform the following procedure during a maintenance window, as it may cause a traffic disruption.

  1. Log in to the Source BIG-IP system as root.

    Note: If the n3fipsutil utility is not installed, you can follow the steps in the Determine the current status procedure above to install it.

  2. Verify that you are on the Source system by entering the following command:

    /var/tmp/n3fipsutil -exportKeyCheck

    The output should be KeyExport: Disabled for the Source system. If the output is KeyExport: Enabled, you are on the Target system and need to log in to the other system.

  3. Create a temporary directory for the key backups by entering the following command:

    mkdir /var/tmp/fipsbackup

  4. Stop the running services by entering the following command:

    tmsh stop sys service all

  5. Back up the FIPS HSM by entering the following command:

    /var/tmp/n3fipsutil -backup /var/tmp/fipsbackup -c [-n <partition_name>] [-host <mgmt_ip>]

    In the command, note the following:

    • The -c option must be specified as you are only backing up the configuration.
    • [-n <partition_name>] is optional and applicable only in the case where the system has custom partition names, such as in vCMP.
    • [-host <mgmt_ip>] is optional and must only be used from a vCMP Guest where <mgmt_ip> is the management IP address of the Host.
  6. Restart services by entering the following command:

    tmsh restart sys service all

  7. Create a tar file of the directory for export by entering the following command. The resulting file will be named /var/tmp/fipsutilbackup.tgz:

    tar -czvf /var/tmp/fipsbackup.tgz /var/tmp/fipsbackup

  8. Copy the /var/tmp/fipsutilbackup.tgz file to your workstation.
  9. Pause here and perform the Restore Target System HSM Partition procedure and the Sync FIPS keys procedure in that order.
  10. Once you have completed the Target System HSM Partition Restore procedure and the Sync FIPS keys procedure, remove the key backup from the system by entering the following command:

    rm -rf /var/tmp/fipsbackup

  11. Remove the n3fipsutil utility and tar file from the system by entering the following command:

    rm /var/tmp/n3fipsutil /var/tmp/fipsbackup.tgz

Note: The backup contains the encrypted configuration data of FIPS card partition, as well as the keys okbk.key and pokbk.key, which are generated during the backup process. You should consider the contents of this directory as highly sensitive. When you copy the backup off the BIG-IP system, secure it using the best security practices.

Restore Target system HSM Partition

Impact of procedure: Perform the following procedure during a maintenance window, as it may cause a traffic disruption.

  1. Log in to the Target BIG-IP system as root.

    Note: If the n3fipsutil utility is not installed, you can follow the previous steps in the Determine the current status procedure to install it.

  2. Verify that you are on the Target system by entering the following command:

    /var/tmp/n3fipsutil -exportKeyCheck

    The output should be KeyExport: Enabled for the Target system. If the output is KeyExport: Disabled you are on the Source system and need to log in to the other system.

  3. Copy the fipsbackup.tgz file from your workstation system to the BIG-IP system in the /var/tmp/ directory.
  4. Change to the /var/tmp/ directory by entering the following command:

    cd /var/tmp/

  5. Untar the fipsbackup.tgz file and create the fipsbackup directory by entering the following command:

    tar -xzvf fipsbackup.tgz

  6. Stop the running services by entering the following command:

    tmsh stop sys service all

  7. Restore the FIPS HSM by entering the following command:

    /var/tmp/n3fipsutil -restore /var/tmp/fipsbackup -c [-n <partition_name>] [-host <mgmt_ip>]

    In the command, note the following:

    • The -c option must be specified as you are only backing up the configuration.
    • [-n <partition_name>] is optional and applicable only in the case where the system has custom partition names, such as in vCMP.
    • [-host <mgmt_ip>] is optional and must only be used from a vCMP Guest where <mgmt_ip> is the management IP address of the Host.
  8. Reset the FIPS HSM login by entering the following command:

    fipsutil loginreset -r

    Note: Some versions of the fipsutil utility do not support the loginreset option; you may skip this step if this applies to your version.

  9. Restart the services by entering the following command:

    tmsh restart sys service all

  10. Verify that the system now returns KeyExport: Disabled to validate that the process has succeeded by entering the following command:

    /var/tmp/n3fipsutil -exportKeyCheck

    The output should be KeyExport: Disabled.

  11. Remove the key backup from the system by entering the following command:

    rm -rf /var/tmp/fipsbackup

  12. Remove the n3fipsutil utility and tar file from the system by entering the following command:

    rm /var/tmp/n3fipsutil /var/tmp/fipsbackup.tgz

  13. Remove the fipsbackup.tgz file from your workstation system.

Note: The backup contains the encrypted configuration data of FIPS card partition, as well as the keys okbk.key and pokbk.key, which are generated during the backup process. Consider the contents of this directory as highly sensitive. When you copy the backup off the BIG-IP system, secure it using the best security practices.

Sync FIPS keys

Impact of procedure: Perform the following procedure during a maintenance window, as it may cause a traffic disruption.

Note: You must sync from the BIG-IP system with the keys you want to preserve. If you sync from the wrong system, you may irrevocably delete your keys, as this action overwrites the keys on the target system with the keys from the source system.

  1. Log in to the BIG-IP system with the FIPS keys you want to preserve as the root user.
  2. Confirm that the configured FIPS keys are correct by observing the output of the following command:

    tmsh show sys crypto fips key

    Record the output for use in step 6.

  3. Sync the FIPS keys by entering the following command:

    fips-card-sync -v -u root <IP_of_other_BIG-IP_system>

  4. Force a ConfigSync operation by following the steps in K13887: Forcing a BIG-IP device group member to initiate a ConfigSync operation.

    For example:

    tmsh run cm config-sync force-full-load-push to-group <group_name>

  5. Log in to the other BIG-IP system as root.
  6. Confirm that the sync was successful by entering the following command:

    tmsh show sys crypto fips key

    Compare the output with the output from step 2 to confirm the sync was successful.

Upon completion of this procedure, both systems will have KeyExport: Disabled, as introduced by ID1023341, and syncing will function correctly.

Important: Downgrading to an earlier version of TMOS and reinitializing the FIPS HSM will remove the fix, re-enabling key export. Downgrading TMOS without reinitializing the FIPS HSM alone will not re-enable key export.
