Important: This Solution applies to versions of FirePass software prior to FirePass version 6.0.2 with Cumulative Hotfix HF-602-2. If you are running FirePass version 6.0.2 with Cumulative Hotfix HF-602-2 or a later version of the Cumulative Hotfix, refer to K8258: Configuring dynamic group mapping using the LDAP Group Object mapping method.

In some LDAP schemas, group membership is defined by a user object attribute. In the following example, Linda Carry’s group membership is defined by the memberOf attribute in the cn=Linda Carry,ou=people,dc=siterequest,dc=com user object:

dn: cn=Linda Carry,ou=people,dc=siterequest,dc=com
cn: Linda Carry
objectClass: person
sn: Carry
memberOf: cn=sales,ou=groups,dc=siterequest,dc=com

In other LDAP schemas, group membership is defined by a group object attribute. In the following example, John Smith’s group membership is defined by the memberUid attribute in the cn=sales,ou=groups,dc=siterequest,dc=com group object:

dn: cn=sales,ou=groups,dc=siterequest,dc=com
cn: sales
objectClass: posixGroup
userPassword: {crypt}*
gidNumber: 100
memberUid: jsmith
memberUid: rjones
memberUid: fterry

If your LDAP schema defines group membership using a group object attribute, you would typically use the FirePass LDAP Group Object mapping method to configure dynamic group mapping. In some configurations, the LDAP Group Object mapping method may not be compatible with your LDAP schema.

For example, if you are using a static group attribute, such as memberOf or memberUid, the FirePass LDAP Group Object mapping method requires that the attribute value contains a full user DN.

For example:

memberUid: uid=jsmith,ou=people,dc=siterequest,dc=com

If your group object attribute contains a Relative DN (RDN) or other data instead of a full user DN, and you are running a version of FirePass software prior to FirePass version 6.0.2 with Cumulative Hotfix HF-602-2, you cannot use the FirePass LDAP Group Object mapping method to configure dynamic group mapping.

For example:

memberUid: jsmith

If you need to query an LDAP group object attribute, but the FirePass LDAP Group Object mapping method is incompatible with your LDAP schema, you may be able to perform dynamic group mapping using the FirePass LDAP User Object mapping method instead.

Configuring dynamic group mapping using the LDAP User Object mapping method with an LDAP group object attribute

Because LDAP implementations and schemas vary widely, replace the objects and attributes in the following examples with the objects and attributes used in your LDAP schema:

dn: uid=jsmith,ou=people,dc=siterequest,dc=com
objectClass: inetOrgPerson
objectClass: posixAccount
cn: John Smith
givenName: John
sn: Smith


dn: cn=sales,ou=groups,dc=siterequest,dc=com
cn: sales
objectClass: posixGroup
userPassword: {crypt}*
gidNumber: 100
memberUid: jsmith
memberUid: rjones
memberUid: fterry

To configure dynamic group mapping using an LDAP group object attribute with the FirePass LDAP User Object mapping method, perform the following procedure:

  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Users: Groups: Dynamic Group Mapping page.
  3. Select the Determine the user's master group dynamically using the master group mapping table check box, located under the Group Mapping Sequence tab.
  4. Navigate to the Users: Groups: Master Groups page.
  5. Click the Create new group button.
  6. In the New Group name field, enter the name of the new Master Group.

    For example:

    Sales
  7. In the Users in group menu, select External.
  8. In the Authentication method menu, select LDAP.
  9. Click the Create button.

    You are redirected to the Master Group configuration page.
  10. Under the General tab, select the Allow users to be assigned to this master group using dynamic master group mapping check box.
  11. Click the Authentication tab.
  12. For the Host, Port, Use SSL connection, Protocol version, and Follow referrals options, configure the settings required for your LDAP server.

    Note: The Follow referrals option appears in FirePass version 6.0.2 and later.
  13. Click the Lookup user's DN using template button.
  14. In the User DN template field, enter the DN template.

    For example:

    uid=%logon%,ou=people,dc=siterequest,dc=com
  15. Click the Save Settings button.
  16. Click the Test button.
  17. Enter a valid LDAP username and password in the Username and Password fields, and then click the Test button.
  18. If the LDAP test passed, proceed to the next step. If the LDAP test failed, compare the information you entered in Steps 11 through 17 with your LDAP server configuration and schema, and adjust the FirePass configuration as necessary.
  19. Navigate to the Users: Groups: Dynamic Group Mapping page.
  20. Click the Group Mapping Methods tab.
  21. In the Mapping methods drop-down menu, select LDAP (user object).
  22. Click the Add mapping method button.
  23. Click the Configure link next to the LDAP (user object) mapping method.
  24. For the LDAP Server, LDAP Port, Use SSL connection, Protocol version, and Follow referrals options, configure the settings required for your LDAP server.

    Note: The Follow referrals option appears in FirePass version 6.0.2 and later.
  25. In the User DN field, enter the LDAP bind DN.

    For example:

    cn=Manager,dc=siterequest,dc=com
  26. In the User password field, enter the password for the LDAP bind DN.
  27. Select the Get user DN using query button.
  28. In the Search Base DN field, enter the base DN for your LDAP query.

    For example:

    dc=siterequest,dc=com
  29. In the Query template field, enter the LDAP group object attribute name that defines group membership and its corresponding value. The value must contain the user's FirePass logon in the form of the %logon% variable.

    For example:

    memberUid=%logon%
  30. In the Attributes to map group field, enter the group object attribute that identifies the group.

    For example:

    cn

    Note: Enter only the attribute name in the Attributes to map group field, and not the value. The value will be mapped in the Master group mapping table.
  31. Click the Update button.
  32. Click the Master group mapping table tab.
  33. Select LDAP (user object) from the Master group mapping table drop-down menu.
  34. Click the Add button.
  35. In the Attribute column, select the attribute you configured in Step 30.
  36. In the Attribute value column, enter the value of the attribute you configured in Step 30.

    For example:

    sales
  37. In the FirePass Group column, select the name of the Master Group you configured in Step 6.

    For example:

    Sales
  38. Click the Add button.
  39. Enter a valid LDAP username and password in the User name and Password fields, and then click the Test button.

If the LDAP group mapping test passed, the procedure is complete. If the LDAP test failed, compare the information you entered in Steps 19 through 39 with your LDAP server configuration and schema, and adjust the FirePass configuration as necessary.
