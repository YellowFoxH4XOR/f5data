Topic

ARX generates core files when a system fault occurs. Core files contain debugging information that can help F5 Technical Support determine why the fault occurred. However, core files can be large in size and should be deleted when they are no longer required.

Note: Certain diagnostics commands run by F5 Technical Support may also generate core files to be used for troubleshooting purposes.

To view the core files on an ARX system, use the show cores command. Output will appear similar to the following example example:

  cores
      core-0001.dmp           Sep 25 16:27  412 MB
      core-0002.dmp           Sep 30 18:05  641 MB
      core-0003.dmp           Sep 30 18:26  641 MB
      core-0004.dmp           Sep 30 19:03  644 MB
      core-0005.dmp           Sep 30 19:12  644 MB

If an old core file has already been submitted to F5, or if you do not plan to submit the core file to F5, you can delete the file using the delete cores command. For example:

ARX01# delete cores core-0001.dmp

If you are unsure whether to delete a core file, you can archive the file in an alternate location prior to deletion. To do so, use the copy cores command. For example:

ARX01# copy cores core-0002.dmp ftp://ftpuser@192.168.1.50/var/ArxCores/core-0002.dmp
Password: ****

Note: Previous core files will not be deleted to make room for a new core file. If the ARX does not have sufficient space or too many previous core files, a new core file may not be saved. For information refer to K13039: The ARX may not save a core file.

Note: For more information about the commands provided in this Solution, refer to the ARX CLI Reference Guide.
