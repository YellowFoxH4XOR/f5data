Known Issue

The BIG-IP system may not allocate swap space after you perform an upgrade or fresh install. This issue occurs when all of the following conditions are met:

  • You install or upgrade to a BIG-IP software version listed in the Applies To box of this article.
  • The BIG-IP system is using the partitions disk formatting scheme.
  • You boot the BIG-IP system into the slot containing the affected version.

Impact

The BIG-IP system may fail to process traffic under a high load situation, and you may not be able to perform some administrative tasks from the Configuration utility.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP system performance is degraded under high load situations.
  • Qkviews generated from the Configuration utility may have a file size of 0 bytes and a date of Wed Dec 31 16:00 PST 1969.

    Note: If you are unable to generate a qkview file from the Configuration utility, you can generate one from the command line. For instructions, refer to the Running qkview from the command line section of K12878: Generating BIG-IP diagnostic data using the qkview utility (10.x - 11.x).

  • Processes on the BIG-IP system restart under high load situations.
  • The BIG-IP host subsystem shows no trace of a partition enabled for swap space in the /proc/swaps file.

    For example, if you type the cat /proc/swaps command, the command does not return output when a partition is not enabled. When a partition is enabled, the command returns the following partition and usage information for swap space:

    Filename Type Size Used Priority
    /dev/hda6 partition 3176040 816 -1
    /dev/hda11 partition 3176040 0 -2

  • The output from the free command displays 0 for the Swap entry instead of the usage information, similar to the following example:

    Swap: 0 0 0

    When a partition is enabled for swap, the Swap entry from the output of the free command displays the usage information of the swap space, similar to the following example:

    Swap: 6352080 816 6351264

Workaround

To work around this issue, you can enable the partition for swap space. To do so, perform the following procedure:

Impact of workaround: The procedure requires that you reboot the BIG-IP system, which results in a service interruption.

  1. Log in to command line.
  2. Back up a copy of the /etc/sysconfig/init file by typing the following command:

    cp –p /etc/sysconfig/init /var/tmp/init.sol13061

  3. Edit the /etc/sysconfig/init file using a text editor of your choice.
  4. Locate the AUTOSWAP=no option.
  5. Modify the AUTOSWAP option to the value of yes as follows:

    AUTOSWAP=yes

  6. Save the modifications, and exit the text editor.
  7. To start up your changes, reboot the BIG-IP system by typing the following command:

    reboot
