Known Issue

This is the result of a known issue. The hds_prune script incorrectly calculates the start and stop pruning thresholds for the BIG-IP WebAccelerator disk cache.

The hds_prune script incorrectly bases the calculation of the maximum size of the disk cache on the size of the partition the disk cache resides on (/wam), and not on the 6GB limit configured in the /config/wa/pvsystem.conf file.

As a result, pruning may start before the disk cache is fully populated, it may not start when 20 percent of the disk cache is available, and it may not stop when 40 percent has been freed.

Note: For more information regarding hds_prune, refer to K9079: Overview of the BIG-IP WebAccelerator hds_prune process.

F5 Product Development tracked this issue as CR135252 and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP 10.0.1, and BIGIP-10.1.0-3372.0-HF1 for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
