Description
If you are using rest tokens for automation (such as with curl, python, iControl, Big-IQ management etc) then when a user logs in to the gui you may observe the below message in /var/log/httpd/httpd_errors

MMM DD HH:MM:SS bigip.f5.net warning httpd[11125]: [auth_pam:warn] [pid 11125] [client <IP Address>:<port>] AUTHCACHE Error processing cookie RWMHTK7Q6X24J5BWMVNJQVFNWO - Failed Read: User, referer: https://10.10.10.10/tmui/login.jsp?msgcode=2&

Environment

  • BIG-IP
  • 13.1.5
  • 14.1.4.6
  • 15.1.5.1
  • 16.1.2.2
  • 17.0.0
  • iControl REST
     

Cause
Tokens that are created by the GUI are written in a different format than tokens that are created by rest. When you login to the gui it creates a token for your user after it opens the existing tokens to see if one already exists. When it hits a token with a format that it doesn't understand, such as one created by rest, then it logs this message.

 

Recommended Actions

  • This log message is strictly cosmetic
