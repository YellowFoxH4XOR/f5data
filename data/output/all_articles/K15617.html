Known Issue

The BIG-IP system may erroneously overwrite the custom SMTP profile.

This issue occurs when all of the following conditions are met:

  • You modify the default SMTP profile to enabled in the Protocol Security setting and save the change.
  • You configure a custom SMTP profile with following settings and save the profile:

    • The modified default SMTP profile is set as its parent profile
    • The Protocol Security setting is set to disabled instead of inherited from the parent profile
  • The system then performs one of the following processes:

    • The configuration reloads
    • The license reactivates

Impact

Unexpected SMTP profile behavior occurs after the system reloads the configuration or reactivates the license.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After the system reloads the configuration, the custom SMTP profile's Protocol Security setting will be set to enabled.
  • After the system reactivates the license, the custom SMTP profile's Protocol Security setting will be set to enabled.

Workaround

To prevent this issue from occurring, you should always leave the default SMTP profile with default settings and configure the custom SMTP profile with your desired settings.

To recover from this issue, you can manually modify the custom SMTP profile to disable in the Protocol Security setting. To do so, perform the following procedure:

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > SMTP.
  3. Click the name of the affected custom SMTP profile.
  4. Select the Protocol Security setting's Custom box if it is not already selected.
  5. To disable the profile, clear the Protocol Security setting's Enabled check box.
  6. To save the changes, click Update.
