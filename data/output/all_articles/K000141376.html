Description

When trying to access another partition that was created for a FAST template you are not allowed to.

Environment

BIG-IP FAST templates are in use.

Cause

There are intended restrictions in regards to partition access as designated by the user assignments. Other than the "Administrator" the user of the FAST template can only access the assigned partition. This is done to enhance security by minimizing access.

Recommended Actions

  1. With FAST how does access for users with restricted access to partitions work? For example say they have access only to the QA partition and they need access to Common or any other partition to update or add an ssl profile cert for FAST. How would that work?
    1. For example if the user access is enabled only with QA partition, by default he will not have access to other partitions including Common. If the user is Administrator, by default he will have access to all partitions.
  2. Since FAST uses a partition for each FAST template deployed what happens if there is a custom profile in another partition they need to use when that question is asked as part of the FAST template?
    1. Only the Administrator can access the objects configured in other partitions.
  3. Per BIG-IP AS3 Frequently Asked Questions (FAQ)

Does BIG-IP AS3 support multi-tenancy?

  • Yes, BIG-IP AS3 creates and uses additional partitions to enable multi-tenancy
  • BIG-IP AS3 ONLY writes to the Common partition when you specifically use the Common tenant with the Shared application (/Common/Shared); see the next FAQ entry
  • BIG-IP AS3 writes to the Common partition as required for some GSLB configurations
  • BIG-IP AS3 does NOT have access to tenants/partitions other than those it creates and /Common

A review of BIG-IP AS3 Frequently Asked Questions (FAQ) will provide further information on this subject.
