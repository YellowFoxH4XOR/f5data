K15041916: BIG-IP doesn't log monitor down event on /var/log/ltm

Type
Support Solution
Published
2022-03-25
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K15041916

Description
You don't find monitor down logs on /var/log/ltm when the monitor is down.

Environment

  • Monitor.
  • log.mcpd.level is set to a nondefault logging level

Cause
The monitor down is logged by mcpd.

Example with the log level of notice:

bigip notice mcpd[7300]: 01070638:5: Pool /Common/my_https_pool member /Common/10.0.12.10:443 monitor status down. [ /Common/https: down; last error: /Common/https: Unable to connect @2021/08/26 15:15:28.  ]  [ was up for 0hr:1min:31sec ]
 

Recommended Actions

You may want to check the log level of log.mcpd.level. The log level should be Notice, Informational or Debug to see monitor down logs.
sys db log.mcpd.level {
    default-value "notice"
    scf-config "false"
    value "warning"
    value-range "alert crit debug emerg err error info notice panic warn warning"
}
Note:  for more information refer to: K5532: Configuring the level of information logged for Traffic Management-related events.
