Source

Description

This article addresses an issue where the BIG-IP ASM module fails to start, with the bd process entering a continuous loop. The following error messages are observed in the bd log:

ECARD_POLICY|CRIT  |Dec 18 22:31:37.966|15280|attack_patterns.cpp:0190|PolicySigCollectionTable::add_rdas Failed to allocate rdas struct
ECARD|ERR   |Dec 18 22:31:37.966|15280|table.h:0551|KEY_PUT: Failed to PUT data
ECARD_POLICY|NOTICE|Dec 18 22:31:37.966|15280|table_funcs.cpp:1471|handle_table_dynamic CONFIG_TYPE_ACCOUNT_NEGSIG_COLLECTIONS res:[-1]
BD_MISC|ERR   |Dec 18 22:31:37.966|15280|temp_func.c:2299|CONFIG_TYPE_PROTOBUF_FILENAMES message had parsing error: could not parse protobuf message

Environment

  • Product: BIG-IP ASM
  • Affected database table: ACCOUNT_NEGSIG_COLLECTIONS

Cause

Corruption in the ASM database table ACCOUNT_NEGSIG_COLLECTIONS, which prevents proper loading of signature collections and causes the bd process to fail and loop.

Recommended Actions

To resolve this issue, perform the following steps:

1.Stop the ASM process:

    • bigstart stop asm

2.Collect the names of affected ASM policies:

    • mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "SELECT sig.policy_name_crc, sig.response_sig_collection_filename, pl.name FROM DCC.ACCOUNT_NEGSIG_COLLECTIONS sig JOIN PLC.PL_POLICIES pl ON sig.policy_name_crc = pl.policy_name_crc;"

3.Delete the signature collection table:

    • mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "use DCC; delete from ACCOUNT_NEGSIG_COLLECTIONS"

4.Move related files to a shared directory(The signature collection name can be different than the one below):

    • mv /ts/var/account/negsig/collection.fb92105af0428b1d0a56216145f29d9c /shared/

5.Reboot the system:

    • reboot

6.Make a change related to signature (add/remove sig_set, set a sig staging/enforced, etc.) for previously listed policies so that 'Apply Policy' triggers repopulation of deleted database rows.

7.Restart ASM to verify resolution:

    • bigstart restart asm
