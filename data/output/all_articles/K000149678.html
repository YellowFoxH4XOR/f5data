K000149678: APM Edge Client with Windows Pre-Logon integration may fail to connect if the VPN hostname does not resolve directly to the VPN virtual server

Type
Support Solution
Published
2026-08-26
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000149678

Description

When users attempt to connect to the VPN hostname for Windows Pre-Logon integration, they may experience a failure to connect, either resulting in a 'Error 702' message or another generic connection failure message.

Environment

Big-IP APM

Edge Client Windows Logon Integration

Cause

This can occur if the VPN hostname is used in DNS for GSLB and load balances between different APM virtual servers.

When configuring the Edge Client and APM for Windows Pre-Logon Integration, the server hostname configured in the Connectivity Profile server list, must be the direct hostname of the network access APM virtual server.

Recommended Actions

Only use the direct hostname of the network access Virtual Server used for the APM VPN connections, when configuring the server list in the Connectivity Profile.

Do not use a DNS GSLB hostname, used for load balancing between APM data centers.
