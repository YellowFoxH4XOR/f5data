Excessive data exposure

Excessive data exposure typically occurs because the API is designed to expose all properties of an object without considering the sensitivities of each property. The design assumption relies on the client side to perform the data filtering before displaying the results to the end user. This leads to the API returning more data than required by the end user, thereby increasing the risk of exposing sensitive data.

Excessive data exposure common weakness enumeration (CWE)

The following common weaknesses may increase the likelihood of attacks against your APIs:

  • CWE-213: Exposure of Sensitive Information Due to Incompatible Policies

Excessive data exposure attack scenario

Common attack scenarios for excessive data exposure usually involve an attacker sniffing the traffic and gaining access to all data returned by the API, including sensitive data. With some analysis, the attacker can exploit the sensitive data discovered and potentially make further in-roads to compromising other systems or controls.

For example, an API endpoint that allows a mobile app to retrieve a user’s profile from the backend returns personal information, including the user’s stored payment information, like a credit card number and card verification value (CVV) code, while relying on the mobile app to mask these sensitive data on the front end. An attacker who manages to bypass the mobile app and query the API directly gains access to these sensitive data, thereby compromising the user’s personal data.

In another example, an API endpoint in a CCTV app returns the entire list of camera endpoints for a building while relying on the app to filter the cameras that a user can view based on their access permissions. An attacker who bypasses the app and queries the API directly will have access to the full list of cameras for the building, thereby bypassing the access control mechanism.

Secure your API against excessive data exposure attacks with F5 products

Most traditional security tools lack the capability to identify which data is sensitive from the legitimate data returned by the API. Some tools may be able to detect and mask or block well-defined sensitive data types, such as credit card numbers (CCNs) or social security numbers (SSNs). When designing an API, best practices recommend that you never rely on the client side to filter sensitive data and always review the responses directly from the API to make sure they contain only legitimate, required data. For example, ensure that the API returns specific properties that are required instead of all properties.

Using F5 BIG-IP Advanced WAF and BIG-IP ASM to mitigate excessive data exposure attacks

Advanced WAF and BIG-IP ASM provide mechanisms to mitigate and protect against attacks that attempt to exploit excessive data exposure, especially in the case of well-defined sensitive data types, such as CCNs or SSNs.

The Advanced WAF and BIG-IP ASM systems provide the following controls to protect your API against excessive data exposure attacks.

Table 3.1 Advanced WAF and BIG-IP ASM controls that protect against excessive data exposure attacks
Advanced WAF and BIG-IP ASM protectionRecommendationsResource
Data GuardIf your API responses contain well-defined sensitive data, such as CCNs or SSNs, you can configure the Advanced WAF and BIG-IP ASM Data Guard to mask these data in the API responses by replacing them with asterisks prior to forwarding them to the client side.The Protecting Sensitive Data with Data Guard chapter of the BIG-IP Application Security Manager: Implementations manual
