Description

When working with the TCP profile it can be difficult to understand at what point the different timeouts will being counting down. This state diagram attempts to illustrate when they will being. After the packet is sent then the side that sent the packet will enter the indicated state. For example after the SYN is sent then each side enters the SYN_SENT state. Whichever side sends the tcp packet with the FIN flag set first will enter FIN_WAIT_1.

Environment

  • Any virtual server with a tcp profile applied.

Cause

This diagram is using the labels on the far left and right side to indicate what state in the TCP flow that the conversation is in. The values in green align with the common names for the timeout values that you can find in the TCP profile overview that aligns with your version. This diagram is most easily understood by assuming that the device that sends the first tcp packet with a SYN flag set is the client for the duration of the conversation regardless if it's a server device or not.
