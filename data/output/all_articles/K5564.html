Topic

F5 products come in a variety of hardware configurations. While many models have a significant amount of free disk space, some models, such as BIG-IP and 3-DNS switch appliances and server appliances that are equipped with a solid state disk, do not have enough free space to store a large tcpdump file.

You can perform a tcpdump on a system with minimal disk space, using one of the following processes:

  • Create a RAM file system and write the tcpdump directly to memory

  • Perform the tcpdump remotely through SSH and write the output to the client system

Creating a RAM file system and writing the tcpdump file directly to memory

Important: F5 advises you to perform this procedure at your own risk. Performing this procedure can cause memory shortage on the BIG-IP system, as there are no mount options for the Random Access Memory File System (RAMFS) that allow you to limit the size of the tcpdump file.

To create and use a memory file system and write the tcpdump file directly to memory, from the command line, perform the following procedure:

  1. To create the temporary directory for the mount point, type the following command:

    mkdir /var/ramfs

  2. To create the mount point, type the type the following command:

    mount -t ramfs none /var/ramfs

  3. Write the file to the memory file system, using the following command syntax:

    tcpdump -ni <vlan_name> -c <packet_count> -s0 -w /var/ramfs/mytcpdump.bin

    Replace <vlan_name> with the name of the VLAN.

    Replace <packet_count> with the packet count value.

    Note: Make sure to use tcpdump -c <packet count> command with this process. The -c option forces tcpdump to exit after receiving the designated number of packets. For example, if you run the following command, tcpdump exits after receiving 500 packets:

    tcpdump -c 500

Performing the tcpdump remotely through SSH and writing the output to the client system

You can use SSH to save the tcpdump file remotely to the client's memory file, by performing the following procedure:

  1. Connect to the client system using SSH.

  2. Write the file to the client system using the following command syntax:

    ssh <user>@<remotehost> 'eval $(which tcpdump) -c<packets>-s0 -w- -i interface' > <filename>

    Replace <user> with the user on the remote system.

    Replace <remotehost> with the hostname or IP address of the BIG-IP.

    Replace <packets> with the number of packets you wish to capture.

    Replace <filename> with the name you want used for the tcpdump binary file.

    For example:

    ssh root@bigip1.askf5.com 'eval $(which tcpdump) -c10000 -s0 -w -i internal' >mytcpdump.bin

    This command is executed on the BIG-IP system, but writes the mytcpdump.bin output file to the client system.

Important: The tcpdump output is buffered. If you issue CTRL-C on the system from which you are running the commands, it will terminate SSH, not the remote tcpdump, resulting in an incomplete or useless tcpdump collection; therefore, it is important to wait for the tcpdump process to complete collecting the specified number of packets.
