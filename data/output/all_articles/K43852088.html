K43852088: Not able to specify source IP when DNS cache resolver sends request on v15.1.2

Type
Support Solution
Published
2021-12-17
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP DNS: 15.1.2
Source
https://my.f5.com/manage/s/article/K43852088

Description
After upgrade to v15.1.2, may not able to specify source IP when DNS cache resolver send DNS requests.

Environment

  • DNS
  • Cache resolver

Cause

  • This is caused  by Known Issue ID982361.
  • Below is the similar config that after upgrade to v15.1.2, SNAT pool IP not been used when DNS cache resolver send DNS requests.
     
# tmsh list ltm virtual
ltm virtual MyListener {
    creation-time 2021-01-05:13:28:07
    destination 10.200.169.171:domain
    ip-protocol udp
    last-modified-time 2021-01-05:13:37:27
    mask 255.255.255.255
    profiles {
        CacheOnly { }
        udp_gtm_dns { }
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    translate-address disabled
    translate-port disabled
    vs-index 2
}
ltm virtual vs_forwarding {
    creation-time 2021-01-05:14:16:04
    destination 0.0.0.0:any
    ip-forward
    ip-protocol udp
    last-modified-time 2021-01-05:14:16:04
    mask any
    profiles {
        fastL4 { }
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    source-address-translation {
        pool MyPool
        type snat
    }
    translate-address disabled
    translate-port disabled
    vs-index 3
}

# tmsh list ltm snat-translation
ltm snat-translation 10.201.31.180 {
    address 10.201.31.180
    inherited-traffic-group true
    traffic-group traffic-group-1
}


# tmsh list ltm snatpool
ltm snatpool MyPool {
    members {
        10.201.31.180
    }
}

# tmsh list ltm dns cache resolver
ltm dns cache resolver MyResolver {
    route-domain 0
}

# tmsh list ltm profile dns Cac*
ltm profile dns CacheOnly {
    app-service none
    cache MyResolver
    defaults-from dns
    enable-cache yes
    enable-dns-express no
    enable-dnssec no
    enable-gtm no
    use-local-bind no
}

# tmsh list sys db dnscache.match*
sys db dnscache.matchwildcardvip {
    value "true"
}

Recommended Actions

Software upgrade to v16.1 or above to resolve this known issue.
