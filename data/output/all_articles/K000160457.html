K000160457: F5OS System Health Summary: Unhealthy

Published

Source

Description

On F5OS-A 1.8.3, the "System Health Summary" may display an "Unhealthy" state with error or warning severities due to latched RX-Power and TX-Power alarms on multiple optics/portgroups. These alarms are historical, persist after OS upgrades, and typically affect interfaces that are intentionally unused or have no cables connected. The alarms do not indicate a current hardware fault and are cosmetic in nature.

Environment

  • F5OS-A version 1.8.3
  • rSeries platform
  • Multiple portgroups/interfaces with no cables connected (intentionally unused)
  • Historical RX/TX power alarms present in system health and alarm logs

Cause

  • Software defect (Bug ID 1812665 and Bug ID 1812541) causes RX/TX power alarms on optics to remain latched in hardware registers after temporary power fluctuations or when interfaces are disabled.
  • These alarms do not auto-clear, even after an OS upgrade, and persist until manually cleared.
  • The issue is cosmetic and does not impact system functionality.

Answer/Recommended Actions

  1. Manually clear the latched alarms using the following commands via SSH on each affected unit:
    • For each portgroup with a latched alarm, run:

      docker exec alert-service sendAlert -n "txPwr" -s "Portgroup <number>" -i <alerts_id_number> -d "Lanes: <alerts_lanes> Transmitter power low alarm" -r clear -se ERROR

      For example:

      1. Confirm current alarms with "show system alarms" 

        ID      RESOURCE      SEVERITY  TEXT                                     TIME CREATED                       
------------------------------------------------------------------------------------------------------------
xxxxxx  Portgroup y  ERROR     Lanes: a,b,c,d Receiver power low alarm  yyyy-dd-mm hh:mm:ss.ms UTC
      2. Issue below command to clear the alarms
        docker exec alert-service sendAlert -n "rxPwr" -s "Portgroup y" -i xxxxxx -d "Lanes: a,b,c,d Receiver power low alarm" -r clear -se ERROR

  2. After running the commands, verify alarm clearance with:

    show system health

    show system alarms

  3. No further action is required for unused interfaces; the alarms are cosmetic.
  4. For future prevention, consider upgrading to a version where the bug as listed in the bug tracker.
