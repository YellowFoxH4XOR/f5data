Description

When using NGINX Plus as a load balancer in front of NGINX Ingress Controller (NIC) for TCP stream traffic, you may encounter connection failures if SSL-encrypted traffic from clients is not properly encrypted when forwarded to upstream NIC pods. Specifically, if the upstream NIC expects SSL/TLS traffic but the NGINX Plus stream configuration does not enable SSL proxying, the connection will fail due to an encryption mismatch.

Environment

  • NGINX Plus R31
  • Stream module enabled
  • NGINX Ingress Controller (NIC) as upstream
  • Clients connect using SSL/TLS
  • NIC upstream expects SSL/TLS traffic

Cause

The root cause is the absence of the proxy_ssl on; directive in the NGINX Plus stream configuration. Without this directive, NGINX Plus forwards unencrypted traffic to the upstream NIC pods, which expect SSL/TLS-encrypted traffic, resulting in failed connections.

Recommended Actions

To resolve the issue, enable SSL proxying in the NGINX Plus stream configuration by adding the proxy_ssl on; directive within the relevant server block. Below is a complete configuration example:

stream {
server {
listen 443;
proxy_pass nic_upstream:443;
proxy_ssl on;
proxy_ssl_server_name on;
proxy_ssl_verify off;
}
}

This configuration ensures that SSL-encrypted traffic from clients is properly re-encrypted when forwarded to the NIC upstream, matching the expected protocol and preventing connection failures.

Additional Information

  • The proxy_ssl on; directive enables SSL/TLS encryption for traffic sent to the upstream server in the stream context.
  • Other useful directives for SSL proxying in stream configurations include proxy_ssl_server_name on; and proxy_ssl_verify off;, which control SNI and certificate verification behavior, respectively.
  • For more details, refer to the official NGINX documentation.
