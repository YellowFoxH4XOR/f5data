Description

You can configure BIG-IP to load balance FTPS traffic and this article will show you how to do so. The configuration you create in the procedures is designed to support FTPS passive mode transfers, Explicit FTPS, and works with the Allow or Require options of FTPS mode.

Procedures

  • Create an FTPS aware FTP profile
  • Create a pool
  • Create a virtual server
  • Create a wildcard virtual server

Create an FTPS aware FTP profile

Create an FTP profile and enable FTPS mode. FTPS mode only supports passive mode connections.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Profiles.
  2. In the Services drop down menu choose FTP.
  3. Select Create...
  4. Enter a name for the profile.
  5. Check the Custom box next to FTPS Mode and select Allow or Require in the drop down menu.
  6. Configure other settings as needed and then select Finished.

Create a pool

Create a new pool with your servers for FTPS loadbalancing.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Pools.
  2. Select Create...
  3. Enter a name for the pool.
  4. Add a health monitor by moving one from the Available list to the Active list.
  5. Create a new node by selecting either New Node or New FQDN Node or choose an existing node from the Node List.
  6. If creating a new node, in Node Name enter the node name or leave blank and use the IP address for the name.
  7. If creating a new node, in Address enter the IP address or in FQDN enter the FQDN for your FTP server. Otherwise select an existing node.
  8. Select FTP for the port
  9. Configure other member settings as needed and select Add.
  10. Repeat steps 5 to 9 for the other members of the pool.
  11. Configure other settings as needed then select Finished.

Create an FTP virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers.
  2. Select Create...
  3. Enter a name for the virtual server.
  4. Ensure the Type is Standard.
  5. For Destination Address/Mask enter an IP address and enter the mask if it's any value other than /32. Otherwise you can omit the mask.
  6. For Service Port select FTP.
  7. Ensure the Protocol setting is TCP and the tcp profile is applied.
  8. For FTP Profile select the profile you created previously.
  9. Choose the desired setting for Source Address Translation. In most environments this is Auto Map.
  10. For Default Pool select the pool you created previously.
  11. Configure other settings as needed then select Finished.

Create a wildcard virtual server

Per K08859735: Overview of the FTP profile (14.x - 17.x) when you use Allow or Require, FTPS negotiation transitions the virtual server to Pass Through mode and encrypts traffic. After this transition, the BIG-IP system can no longer inspect FTPS traffic. After a connection transitions to explicit FTPS, the BIG-IP system only supports Passive mode data connections. To support Passive mode connections, there must be a wildcard virtual server that is the listener for the data connections.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers.
  2. Select Create...
  3. Enter a name for the virtual server.
  4. Ensure the Type is Forwarding IP.
  5. For Destination Address/Mask enter 0.0.0.0/0.
  6. For Service Port select * All Ports.
  7. Configure other settings as needed then select Finished.

Note: You must configure routing in your environment to send the data connection to the wildcard virtual server.

Note: If the FTP virtual server has source address translation, the wildcard virtual server must have the same configuration. If you configure a Large Scale NAT (LSN) pool on the FTP virtual server, the wildcard virtual server must use the same LSN pool, and you must enable persistence on the LSN pool. The system disables connections for any security profile on the virtual server, such as BIG-IP ASM policies and firewall rules, when it transitions to explicit FTPS.

Note: You may want to limit your servers' exposure to non-FTP traffic by limiting the ports your FTP server listens on for passive connections, or by implementing port-based packet filtering anywhere in the packet stream. For example, you may be able to configure a firewall upstream to restrict both the destination ports allowed to reach the virtual server, and also configure the FTP server to listen only on ports > 1023 for the related passive data connections. Configuration of those options is beyond the scope of this document.
