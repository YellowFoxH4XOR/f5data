K18834453: Portal Access with ''.test'', ''.onion'' or ''.invalid'' in FQDN is not being resolved by BIG-IP APM

Source

Description


BIG-IP APM is not performing DNS resolution of Portal Access resource when the application URI or hostname comes with ".test", ".onion" or ".invalid" on the top-level domain (TLD) of the FQDN.

For example: myapp.example.test
This behavior happens even when manual DNS resolution from BIG-IP APM works, like testing with nslookup tool.
Following logs could be seen on /var/log/apm:

01490504:5: /Common/MyAccessPolicy:Common:<sessionID>: myapp.example.test can not be resolved.

Environment

  • Portal Access resource
  • Server FQDN with ".test", ".onion" or ".invalid" on TLD

Cause
Working as designed to comply with RFC7686 and RFC6761.

 

Recommended Actions

There are two options to fix this issue:

  1. Modify your DNS names to comply with RFC limitations. Avoid using ".test", ".onion" or ".invalid" on TLD.
  2. As a workaround, configure the Portal Access resource with IP address instead of FQDN.
