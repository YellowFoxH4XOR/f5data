Description

  • You are unable to connect via Network Access and BIG-IP Access Policy Manager (APM).
  • You are unable to Access resources after getting connected to the BIG-IP APM VPN.

Environment

  • Network Access
  • BIG-IP Edge Client
  • Browser Client

Cause

Unknown

Recommended Actions

Collecting data from the BIG-IP APM.

Changing logging levels
For instructions on enabling Debug logging for Access policy, refer to K45423041: Enabling APM debug logging.

Creating and adding an iRule to allow decryption of packet capture
Create an iRule to record the SSL session IDs and session secrets and assign it to the virtual server which will allow decrypted review of the collected packet captures. Please refer to K12783074: Decrypting SSL traffic using the SSL::sessionsecret iRules command (12.x and later) for detailed instructions on how to do this.

Collecting Network captures
Start tcpdump on the BIG-IP by logging into the Command line utility and typing the following commands and replace <>'s with the valid information. For more detailed instruction about performing tcpdump on the BIG-IP please refer to K411: Overview of packet tracing with the tcpdump utility.

This first argument should be used if your users are unable to connect at all. This will capture the communication between the BIG-IP APM and the client.
  # tcpdump -ni 0.0:nnn -s0 host <Client IP> or host <Virtual Server IP> -vvv -w /shared/tmp/Client_side.pcap
  
The following argument should be used if your user is able to connect but cannot access any resources once connected:
  # tcpdump -ni <connectivity profile name(like /Common/My_connectivity_profile)>:nnn -s0 host <lease pool IP> or host <Destination Server IP> -vvv -w /shared/tmp/Connectivity_Profile_Server_side.pcap

For example:
# tcpdump -ni 0.0:nnn -s0 host 10.10.10.10 or host 10.90.100.1 -vvv -w /shared/tmp/Client_side.pcap
  
# tcpdump -ni /Common/My_apm_connectivity_profile:nnn -s0 host 172.16.1.20 or host 172.17.1.100 -vvv -w /shared/tmp/Connectivity_Profile_Server_side.pcap


While the tcpdump is running, reproduce the issue by attempting to connect to the APM.

Stop the tcpdump with ctrl+c

Producing a Master Secret log file using the sed command. 

On the BIG-IP command line, type the following command:
sed -e 's/^.*\(RSA Session-ID\)/\1/;tx;d;:x' /var/log/ltm > /var/tmp/decryptable.pms


Don't forget to remove the iRule from your virtual server and turn down access policy logging on the BIG-IP.

Generate a qkview and note which username and sessionID that was used in the test.

qkview -s 0

Additional Information

Collecting Data from the client
Depending on the client your user is using you will want to collect the appropriate data from your client machine as well. Please reference K11898: Information required when opening a support case for BIG-IP APM or the links in the related content section for instructions for collecting logs from the various clients.
