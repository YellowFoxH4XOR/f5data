Known Issue

The Traffic Management Microkernel (TMM) process may produce a core file and restart when processing an FTP connection.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server with an FTP profile.
  • The client establishes an FTP session to the FTP virtual server.
  • The FTP session transitions to the time-wait state.
  • The BIG-IP system receives a retransmission for the FTP session in time-wait state.

Impact

If the BIG-IP system is a member in a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until the TMM process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H459680 on the Diagnostics > Identified > Low|High screen.
  • The BIG-IP system sends a SIGFPE signal to the TMM process, resulting in a stack trace and core file.
  • The BIG-IP system logs an error message to the /var/log/tmm file that appears similar to the following example:

    notice panic: ../modules/hudproxy/bigproto/bigproto.c:4041: Assertion "syncookie" failed
    notice ** SIGFPE **
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system fails over to the peer system in a high-availability configuration.
  • The BIG-IP system temporarily fails to pass traffic.
