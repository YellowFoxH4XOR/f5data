Known Issue

VMware View portal sessions that connect through the BIG-IP APM system may fail when receiving a chunked response from the VMware View resource.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with a portal access profile for VMware View.
  • The initial server VMware View resource response includes an HTTP Transfer-Encoding header for chunking.

The issue triggers when the client receives the HTTP Transfer-Encoding header, initially sent by the VMware View resource. When the HTTP content has been processed by the BIG-IP APM portal, it is no longer chunked. The Transfer-Encoding header that the client receives erroneously informs the client that the HTTP content is chunked when it is not, and causes the session to fail.

Impact

Clients cannot access the portal VMware View resource.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The portal cannot access the VMware View resource.
  • When attempting to access the VMware View resource, using the BIG-IP APM VMware View portal, the VMware View client receives errors similar to the following:

    The View Connection Server authentication failed.

    The server returned an invalid or unrecognized response.

Workaround

To work around this issue, you can use an iRule to remove the HTTP Transfer-Encoding header. To do so, perform one of the following procedures:

For an iRule to remove the HTTP Transfer-Encoding header, the iRule must be able to access the HTTP headers of the session packets. To do so, the BIG-IP APM system must perform Proxy SSL for the VMware View portal virtual server. Depending on your portal virtual server configuration, perform one of the following procedures:

  • For configurations where the VMware View portal virtual server is already configured with a clientssl, serverssl, and HTTP profiles functioning as a Proxy SSL:

    VMware View portal virtual server that performs Proxy SSL
  • For configurations where the VMware View portal virtual server does not perform a Proxy SSL function:

    VMware View portal virtual server that does not perform Proxy SSL

VMware View portal virtual server that performs Proxy SSL

For a configuration where the VMware View portal virtual server is already configured with a clientssl, serverssl, and HTTP profiles functioning as a Proxy SSL, you can use an iRule with the existing VMware View portal virtual server to remove the HTTP Transfer-Encoding header by performing the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule, similar to the following example:

    remove_transfer-encoding_header_sol14868
  6. In the Definition box, type the following iRule syntax:

    when HTTP_RESPONSE_RELEASE
    {
    HTTP::header remove "Transfer-Encoding"
    }
  7. Click Finished.
  8. Assign the new iRule to the BIG-IP APM portal virtual server.
  9. Click Local Traffic.
  10. Click Virtual Servers.
  11. Select the virtual server that the BIG-IP APM portal references for VMware View resources.
  12. Click the virtual server's Resources tab.
  13. In the iRules section, click Manage.
  14. Select the remove_transfer-encoding_header_sol14868 iRule and move to the Enabled box.
  15. Click Finished.

VMware View portal virtual server that does not perform Proxy SSL

For configurations where the VMware View portal virtual server does not perform a Proxy SSL function, you must create an iRule that targets another virtual server as the destination resource. The layered virtual server implements Proxy SSL and allows the iRule access to the HTTP headers. The virtual server references the original VMware View portal virtual server as a destination resource within the iRule.

Impact of workaround: You must modify the original VMware View portal virtual server IP address to allow the new layered Proxy SSL virtual server to utilize the IP address.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule, similar to the following example:

    remove_transfer-encoding_header_layered_sol14868
  6. In the Definition box, copy the following iRule syntax, replacing <Original_VMware_View_portal_virtual_server_name> with the name of the virtual server currently used for the VMware View portal:

    when HTTP_REQUEST
    {
    virtual <original_VMware_View_portal_virtual_server_name>
    }
    when HTTP_RESPONSE
    {
    HTTP::header remove "Transfer-Encoding"
    }
  7. Click Finished.
  8. Use the following profiles to create a new Proxy SSL virtual server:

    • HTTP profile: Create a new HTTP profile using the default HTTP profile as the parent profile with no modifications.
    • SSL Profile (Client): Create a custom client SSL profile using the default clientssl profile selecting the appropriate SSL configuration options for your deployment.
    • SSL Profile (Server): Create a custom server SSL profile using the default serverssl profile as the parent; for most deployments, no modifications are required.
    • SNAT Pool: Select Auto Map.

      This virtual server intends to decrypt the session packets and enable the BIG-IP APM system to access the unencrypted HTTP headers, removing the Transfer-Encoding header before re-encrypting the packets sent to the VMware View client.

      For more information about creating a virtual server, refer to the Implementing Proxy SSL on a Single BIG-IP System chapter of the BIG-IP Local Traffic Manager: Implementations guide.

      Note: The virtual server configuration does not require a pool or persistence destination selection, and is handled by the remove_transfer-encoding_header_layered iRule.
  9. Assign the new iRule to the newly created BIG-IP APM VMware View portal virtual server.
  10. Click Local Traffic.
  11. Click Virtual Servers.
  12. Select the virtual server that the BIG-IP APM portal references for VMware View resources.
  13. Click the virtual server's Resources tab.
  14. In the iRules section, click Manage.
  15. Select the remove_transfer-encoding_header_layered_remove_transfer-encoding_header_sol14868 iRule and move to the Enabled box.
  16. Click Finished.
