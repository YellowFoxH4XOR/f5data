K21455531: When logging use https,ssh or console the device show very slow

Type
Support Solution
Published
2022-06-14
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.0
Source
https://my.f5.com/manage/s/article/K21455531

Description

  • While logging use https (WebUI), ssh or console, the device performance very slow (https hanged after 2 minute logging)
  • Global CPU graph shows normal use
  • Plane CPU usage shows Analysis plan getting high frequently (Reaching above 70%)
  • Using top command and ordered by %CPU, shows mysql using the most of the CPU resources
  • In /var/log/restjavad:
    [SEVERE][ ][DATE][8100/tm/analytics/application-security/generate-report/f2b8fa87-0d7a-47e7-b488-f0c7888f73b1/worker AvrGenerateReportTaskWorker] Failed to communicate with reporting server: org.apache.thrift.transport.TTransportException

Environment

  • BIG-IP provisioned with LTM, ASM and AVR
  • Per ID773925 - Workaround already implemented 

Cause

AVR's performance reflected by Analysis plan from Plane CPU usage. As a result of intensive workload with AVR, it causing slow with logging the device.
 

Recommended Actions

Resetting the BIG-IP Analytics statistics database

Impact of procedure: The following procedure removes all Application Visibility and Reporting data and resets the MySQL database.

  1. Log in to the BIG-IP command line
  2. Create the /var/avr/init_avrdb file by entering the following command:

    touch /var/avr/init_avrdb

  3. Restart the monpd process by entering the following command:

    tmsh restart /sys service monpd

You can now log in to the Configuration Utility and verify that the Application Visibility and Reporting statistics database is reset.
