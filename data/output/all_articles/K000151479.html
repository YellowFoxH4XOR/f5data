Description

After increasing memory or changing the resource plan for BIG-IP Virtual Edition (VE) appliances running on KVM, devices may fail to start correctly. Common symptoms include continuous process restarts, inability to generate qkview files, and persistent errors in system logs such as:

warning diskmonitor[14277]: 011d0002:4: Cannot access the database because mcpd is not running.
err iControlPortal.cgi[13999]: icontrol_portal:Error waiting for MCP
chmand[4342]: 012a0003:3: smbios parsing failed, unable to publish UUID
err chmand[13802]: 012a0003:3: smbios parsing failed, unable to publish UUID
notice mcpd[10658]: 01071bef:5: Unknown cloud platform (HYPERVISOR=0) detected.
info kernel: mcpd[29681]: segfault at 0 ip 00000000f08b05fb sp 00000000ffc999c0 error 4 in libstdc++.so.6.0.19[f07ff000+df000]
info chmand[4342]: 012a0006:6: MCP connection lost.

Environment

  • BIG-IP Virtual Edition
  • KVM/QEMU/OpenStack hypervisors

Cause

BIG-IP VE relies on reading BIOS information provided by the underlying hypervisor via SMBIOS/DMI tables during startup and operation. If this information is missing or malformed—often due to how KVM presents it after a resource change—the appliance cannot initialize critical processes (mcpd, chmand), resulting in repeated restarts and failure to load full configurations.

Recommended Actions

  • Ensure your KVM hypervisor is configured to present complete and compatible SMBIOS/DMI data to guest VMs.
  • Avoid changing CPU/memory resources while the VE is running; always shut down the VM before making such changes.
  • On affected BIG-IP VEs, move /shared/vadc/.hypervisor_type to a temporary directory and reboot.

# mv /shared/vadc/.hypervisor_type /tmp/
# reboot

  • If the issue persists, redeploy the virtual machine and recover from a UCS file.
