Topic

Certain network time protocol (NTP) advanced features, such as NTP authentication, are not natively supported in the Configuration utility or the TMOS Shell (tmsh). As a result, these features must be configured manually using the methods described in the following sections.

Description

NTP is a protocol for synchronizing the clocks of computer systems over the network. On BIG-IP systems, accurate time stamps are essential to guarantee the correct behavior of a number of features. While in most cases it is sufficient to configure a couple of time servers that the BIG-IP system will use to update its system time, it is also possible to define more advanced NTP configurations on the BIG-IP system.

Note: For more information about configuring NTP servers on the BIG-IP system, refer to K3122: Using the BIG-IP Configuration utility to add an NTP server and K13380: Configuring the BIG-IP system to use an NTP server from the command line (11.x - 16.x).

Important: By changing the default NTP configuration, the BIG-IP system may become vulnerable to certain remote attacks that would normally not affect the BIG-IP system. For more information, refer to the following list of articles (note that this list is non-exhaustive):

  • K44942017: NTP vulnerability CVE-2014-5209
  • K09940637: NTP vulnerability CVE-2019-11331
  • K44305703: NTP vulnerability CVE-2020-11868
  • K55376430: NTP vulnerabilities CVE-2020-13817

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have expert knowledge of NTP and can validate configuration in ntp.conf.
  • You have command line access.
  • You are familiar with a text editor in the Linux environment.

Symmetric key authentication

Some of the following procedures involve authenticating NTP packets. Authentication support allows the NTP client to verify that servers are known and trusted, and not intruders intending to masquerade as a legitimate server. You must complete this section before implementing any of the configurations described in this article that involve authentication.

Note: This article only describes one authentication method, which is based on symmetric key cryptography; however, you should be aware that other authentication methods are also available.

You must complete this section before implementing any of the configurations described in this article that involve authentication:

Impact of procedure: Configuring the NTP server with key authentication will require the remaining NTP peers to have the same key.

  1. Log in to the BIG-IP command line.
  2. Choose a passphrase and define it in the /etc/ntp/keys file by using the following command syntax:

    Note: NTP keys are specified in the /etc/ntp/keys file. Each line in this file consists of three fields: the key identifier, the key type, and the passphrase or key itself.

    echo "1 M <passphrase> #MD5 Key" >> /etc/ntp/keys

    For example:

    echo "1 M mypassphrase #MD5 Key" >> /etc/ntp/keys

    Note: MD5 and SHA1 are the only encryption algorithms supported at this time.

  3. Restart the ntpd service by entering the following command:

    tmsh restart /sys service ntpd

  4. Make sure this key is installed on all the NTP servers and clients participating in the NTP time synchronization.
  5. Ensure this key will be backed up in a UCS archive by adding this key as an entry to the UCS archive entry. You can do so by following the procedure documented in the Adding a UCS archive entry section in K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive
  6. Optional: You can verify if the NTP authentication is working properly through packet captures by observing that the key IDs are similar for requests, as well as responses and that the MAC fields are filled.

Note: For more information regarding Symmetric key NTP authentication, refer to K30653031: NTP Authentication Passphrase Criteria.

Configure the BIG-IP system as an NTP server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Ensure that the self IP on which you want to listen for NTP requests is configured to accept UDP traffic on port 123. If required, adjust the Port Lockdown setting of the self IP by navigating to Network > Self IPs in the Configuration utility.

    Note: For more information about configuring port lockdown setting of the self IP, refer to K17333: Overview of port lockdown behavior (12.x - 21.x). If you have configured your BIG-IP as an NTP server on the management interface, you must configure the management port firewall to allow inbound access to UDP port 123. For more information, refer to K46122561: Restricting access to the management interface using network firewall rules.

  2. Log in to tmsh by entering the following command:

    tmsh

  3. To configure an access restriction, use the following command syntax:

    modify /sys ntp restrict add { <name> { address <network> mask <mask> no-trap enabled no-modify enabled } }

    For example, to configure an access restriction named ntp_restriction for the 192.168.1.0/24 subnet with no-trap and no-modify enabled, enter the following command:

    modify /sys ntp restrict add { ntp_restriction { address 192.168.1.0 mask 255.255.255.0 no-trap enabled no-modify enabled } }

  4. Save the configuration to memory by entering the following command:

    save /sys config

Configure the BIG-IP system to synchronize with an NTP server only if authentication is successful

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Ensure that you have set up NTP authentication as described in the Symmetric key authentication section.
  2. Log in to tmsh by entering the following command:

    tmsh

  3. Determine if the system has an existing ntp include configuration by entering the following command:

    list /sys ntp include

  4. Edit the ntp configuration by entering the following command:

    Note: The edit command opens the ntp configuration using the vi text editor.

    edit /sys ntp all-properties

  5. Replace the include none line with the following ntp configuration:

    Note: If the system has an existing ntp include configuration, you must integrate the existing configuration with the following configuration. There must be a carriage return/line feed section in configuration mode.

    include "server <ntp server> key <trusted key number> iburst
    trustedkey <trusted key number>"

    For example:

    include "server 192.168.1.10 key 1 iburst
    trustedkey 1"

    If you want to include multiple NTP servers, refer to the following example:

    include "server 1.1.1.1 key 1 iburst
    server 2.2.2.2 key 8 iburst
    trustedkey 1 8"

    Note: Include statements may clash with configuration elements already added through tmsh or the Configuration utility. In particular, you should not add the server statement for a particular NTP server IP using tmsh or Configuration utility and then add it again in the include stanza as a modified copy. The server entries entered using tmsh or the Configuration utility are for unencrypted NTP and need to be removed if present.

  6. Save the configuration to memory by exiting the vi editor. To do so, enter the following command:

    :wq!

  7. The vi editor will prompt you with a confirmation to save the changes. Enter y to confirm. For example:

    Save changes? (y/n/e) y

  8. Save the configuration by entering the following command:

    save /sys config

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Ensure that the self IP on which you want to listen for NTP requests is configured to accept User Datagram Protocol (UDP) traffic on port 123. If required, adjust the Port Lockdown setting of the self IP by navigating to Network > Self IPs in the Configuration utility.

    Note: For more information about configuring port lockdown setting of the self IP, K17333: Overview of port lockdown behavior (12.x - 21.x).If you have configured your BIG-IP as an NTP server on the management interface, you must configure the management port firewall to allow inbound access to UDP port 123.   2. Ensure that you have set up NTP authentication as described in the Symmetric key authentication section.
  3. Log in to tmsh by entering the following command:

    tmsh

  4. Install a multicast route for the Virtual Local Area Network (VLAN) by executing the following command:

    create net route <multicast IP address> interface <vlan>

    Note: If the system has an existing ntp include configuration, you must integrate the existing configuration with the following configuration.

    include "broadcast <multicast IP address> key <trusted key number>
    trustedkey <trusted key number>"

    For example:

    include "broadcast 224.0.1.1 key 1
    trustedkey 1"

Other NTP configurations and the ntp-keygen utility

This article only discusses some of the advanced NTP configurations that you can implement on the BIG-IP system. For example, instead of using symmetric key authentication, you may configure NTP to use the Autokey security protocol, which is based on public key cryptography.

When defining other advanced NTP configurations, you may be required to use the ntp-keygen command line utility, but that command may generate the following error message:

RAND_load_file /root/.rnd not found or empty

This error message indicates that the /root/.rnd random seed file is missing. The /root/.rnd file is used to randomize the entropy seed to initialize the internal pseudo-random number generator, which is used by the OpenSSL library routines. You may generate the missing file by executing the following command:

dd if=/dev/random of=/root/.rnd bs=512 count=1
