K000148624: Configuring SNMP Traps for SSL Certificate Expiration

Type
Support Solution
Published
2024-11-29
Updated
2025-12-04
Source
https://my.f5.com/manage/s/article/K000148624

Description

This article includes additional information to K15288: Sending an advance email alert for impending SSL certificate expiration. It provides guidance on configuring SNMP traps for SSL certificate expiration without email alerts. The instructions assume that a server is already configured to receive SNMP traps. The article outlines how to configure BIG-IP to send SNMP traps when an SSL certificate is nearing expiration, using a custom trap definition when expiration is within 30 days. The check-cert utility performs this check weekly, which examines the expiration date of each locally created or imported SSL certificate. 

Environment

  • BIG-IP LTM

Cause

By default, BIG-IP does not send SNMP traps for SSL certificate expiration. Custom traps are required to enable this functionality and alert administrators proactively.

Recommended Actions

1. Back up the Configuration File

Before making changes, back up the user_alert.conf file:

cp /config/user_alert.conf /config/user_alert.conf.bak

2. Edit the Configuration File

Add a custom SNMP trap for certificate expiration alerts by editing the /config/user_alert.conf file:

vi /config/user_alert.conf

Add a new SNMP trap using the following format:

Note: The following alert definitions specify a custom SNMP object ID ending in .300. Each custom alert definition should use a unique object ID. If you already have a custom alert definition that uses the .300 object IDs, you should use the next available unique object ID.

Note: The following alert definitions rely on certificate expiration messages logged to the /var/log/ltm file. If syslog-ng is not running, or if the certificate expiration messages are not logged to the /var/log/ltm file, an SNMP trap will not be triggered.

alert <alert_name> "<matched message>" { 
   snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.XXX" 
} 

i.e:
alert CERTIFICATE_EXPIRATION "Certificate (.*) in file (.*) will expire on (.*)" {
   snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.300"
}

Note: Replace XXX with a number unique to this object ID. You can use any object ID within the following range:
.1.3.6.1.4.1.3375.2.4.0.300 through .1.3.6.1.4.1.3375.2.4.0.999

3. Restart the Alert Service

Apply the changes by restarting the alertd service:

tmsh restart sys service alertd
