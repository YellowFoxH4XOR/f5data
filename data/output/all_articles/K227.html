For information about TCP and UDP ports on BIG-IP LTM versions 9.x - 11.x, refer to the following solutions:

  • K7317: Overview of port lockdown behavior (9.x)
  • K13250: Overview of port lockdown behavior (10.x - 11.x)

The BIG-IP will drop most packets that arrive at an external interface with a destination of the BIG-IP self IP address.

By default, the following ports are open and listening on BIG-IP external interfaces:

  • TCP port 22 (ssh)
  • TCP port 53 (dns)
  • TCP port 179 (bgp)
  • TCP port 443 (https)
  • UDP port 53 (dns)
  • UDP port 123 (ntp)
  • UDP port 161 (snmp)
  • UDP port 162 (snmp_trap)
  • UDP port 520 (route)

Depending upon the configuration and version of your BIG-IP system, the following ports may also be open:

  • TCP port 683 (unencrypted iControl)
  • TCP port 684 (encrypted iControl)
  • TCP port 4353 (iQuery)
  • UDP port 4353 (iQuery)
  • UDP port 245 (iQuery)
  • TCP port 23 (Telnet)
  • TCP ports 20 and 21 (FTP)
  • UDP port 1026 (network failover)
Note: The output of netstat may show ipv4/ipv6 ephemeral udp ports in use by a Big-IP system. For example:

netstat -ltu
udp 0 0 0.0.0.0:48712 0.0.0.0:* 
udp 0 0 0.0.0.0:48732 0.0.0.0:* 
udp6 0 0 :::44468 :::* 
udp6 0 0 :::48571 :::* 

Some F5 daemons such as sod (network failover) use a udp ephemeral port to send traffic to report HA status between devices in an HA pair. Connectionless protocols such as UDP will show open UDP sockets as listening.  You can confirm the process using these ports is a valid Big-IP daemon (e.g. sod, bd, alertd, etc) by adding the -p flag to the netstat command. For example:

netstat -ulnp | grep -i sod
udp        0      0 0.0.0.0:57233           0.0.0.0:*                           25597/sod
udp        0      0 10.155.91.207:1026      0.0.0.0:*                           25597/sod
udp        0      0 10.0.115.87:1026        0.0.0.0:*                           25597/sod
udp        0      0 0.0.0.0:60421           0.0.0.0:*                           25597/sod

In the output above you will notice that the same process (sod) is listening on two interface IPs and has chosen two ephemeral ports for sending HA status traffic. This is normal for two Big-IPs configured as an HA pair.
