K58541720: Failover not happening due to the network firewall blocking the failover interface IP or Region

Type
Support Solution
Published
2022-08-15
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP AFM: 13.1.3
  • BIG-IP LTM: 13.1.3
Source
https://my.f5.com/manage/s/article/K58541720

Description

In an HA cluster, BIG-IP is unable to receive updates from peer devices through a failover interface due to the network firewall blocking the IP used for the failover.

Output when running tmsh show /cm failover-status:

<IP used for failover>:1026 <Failover peer hostname> 0 1 - Error

Similar log in /var/log/restjavad:

[WARNING][491712][09 Mar 2022 11:34:45 UTC][8100/tm/shared/bigip-failover-state BigipFailoverStateWorker] Failed to discover <IP used for failover>: java.lang.IllegalStateException: Could not connect to host <IP used for failover>. Please ensure there are no licensing, firewall, port lockdown or network connectivity issues. Error: Device request timed out.


Environment

  • BIG-IP AFM provisioned
  • BIG-IP LTM Provisioned
  • Failover cluster configured

Cause

  • Network Firewall has an active rule blocking the IP for the failover
  • Failover IP is not specified in the Network Firewall rules and therefore it is being rejected by the default rule.

Recommended Actions

  1.  Change the rule action to Accept-decisively to the failover IP address range/region if exists.
  2.  Add failover IP address range/region to source and peer failover IP address/region to destination.
  • Select range port that includes 1026 or any
  • Action: Accept-decisively

Additional Information

None.
