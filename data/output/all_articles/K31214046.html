Description

Sharepoint document could not be edited with APM after upgrade to V14.1x

Environment

  • Sharepoint (LTM+APM) mode
  • APM upgraded to V14.1.x above
  • Multi-domain SSO Enabled

Cause

In MS OFBA internal iRule _sys_APM_MS_Office_OFBA_Support, the path /f5networks-sso-resp should be added to the "MS_OFBA_PASSTHROUGH_URI_LIST", along with two more paths, on line 56:
        set static::MS_OFBA_PASSTHROUGH_URI_LIST {$static::MULTI_DOMAIN_AUTH_RESP_URI "/my.status.eps" "/my.report.eps"}

But it seems that the variable name $static::MULTI_DOMAIN_AUTH_RESP_URI is added instead of the value of the variable

Recommended Actions

To workaround the issue, create a copy of the _sys_APM_MS_Office_OFBA_Support iRule, replace the variable with /f5networks-sso-resp, and apply the iRule copy to the SharePoint virtual server:

  1. Go to Local Traffic > iRules > iRule List
  2. Copy the contents of iRule _sys_APM_MS_Office_OFBA_Support
  3. Create a new iRule, giving it a Name that says it is a copy of _sys_APM_MS_Office_OFBA_Support
  4. Paste the iRule contents into the "iRule copy"
  5. Go to line 56
  6. Replace to look like this:
    set static::MS_OFBA_PASSTHROUGH_URI_LIST {"/f5networks-sso-resp" "/my.status.eps" "/my.report.eps"}
  7. Click Finished
  8. Apply this new iRule to the SharePoint virtual server
