K10718: Reuse of server-side Keep-Alive connections

Type
Knowledge
Published
2009-11-04
Updated

Status

Applies to

  • BIG-IP WebAccelerator: 10.0.0, 10.0.1

Issue

When a BIG-IP WebAccelerator 9.x system is enabled for a virtual server, but a OneConnect profile is not configured, the BIG-IP WebAccelerator does not pool and reuse server-side Keep-Alive connections. Even though the requests from the pvac process and the responses from the OWS contain the appropriate Keep-Alive headers, the BIG-IP WebAccelerator system closes each connection after the initial response is sent. This behavior occurs regardless of the Connections settings in the BIG-IP WebAccelerator policy. As a result, every HTTP request results in a new connection to the OWS. If a OneConnect profile is configured on the virtual server, Keep-Alive connections are used as expected.

Beginning in BIG-IP WebAccelerator 10.0.0, BIG-IP WebAccelerator pools and reuses server-side Keep-Alive connections as expected, regardless of whether a OneConnect profile is configured on the virtual server.

Note: The 9.x behavior is an artifact of the VIP sandwich architecture that was required to accommodate BIG-IP WebAccelerator traffic flows in BIG-IP 9.x.The migration to the BIG-IP WebAccelerator plugin architecture in 10.x lifts this architectural constraint.
