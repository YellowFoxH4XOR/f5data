Issue

In Hotfix-BIG-IP-9.4.4-HF1, the default settings have changed for two of the deployment scenarios in the Deployment wizard, as documented in the BIG-IP Application Security Manager: Implementations, version 9.4.4 guide. The affected deployment scenarios are Production Site (Untrusted Traffic), and QA Lab (Trusted Traffic).

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Changes that affect the Production Site deployment scenario

The following table lists the changes to the default settings for the production site deployment scenario:

Affected setting 9.4.4 default 9.4.4-HF1 default
Enforcement modeBlockingTransparent
Violations for which Block flag is enabled in blocking policyIllegal object type, Non-existent object, Illegal parameterIllegal object type, Non-existent object, Illegal parameter, HTTP protocol compliance, Illegal cookie length, Illegal header length, Illegal dynamic parameter value
Policy Builder templateTypical
Basic
Finalization processRemoves match all (*) wildcard characters for object types, objects, and parametersRemoves match all (*) wildcard characters only for object types and parameters.

Once you apply the 9.4.4-HF1 hotfix, the production site deployment scenario no longer initiates the blocking enforcement mode. As a result, F5 recommends that you evaluate and process any learning suggestions that your traffic generates until you see no false positive alarms. At that point, you can change the enforcement mode to blocking.

Note: For more information about working with learning suggestions, the enforcement mode, and the blocking policy, refer to the Configuration Guide for BIG-IP Application Security Management, version 9.4.4.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.
