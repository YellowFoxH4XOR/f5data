Known Issue

This is the result of a known issue. In BIG-IP versions prior to 9.3.0, it was possible to use the bigpipe conn command with a filter to display or delete connections based on server-side flow information, such as the address of the node selected for the load balanced connection. The ability to filter on server-side flow details was inadvertently removed from BIG-IP in 9.3.0.

F5 Product Development tracked this issue as ID 246931and ID 307782 (formerly CR105333) and it was fixed in BIG-IP version 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

Note: In BIG-IP version 9.4.8, and in BIG-IP versions 10.1.0 and later, you can use the ss client and ss server parameters with the bigpipe conn command to filter the connections. For example:

[root@ltm01:Active:avc(0)] config # b conn ss client 10.4.4.4 show all
VIRTUAL 10.2.2.60:http <-> NODE 10.4.4.14:http TYPE any 1/0
CLIENTSIDE 10.2.2.20:40243 <-> 10.2.2.60:http
(pkts,bits) in = (2, 112) out = (1, 64)
SERVERSIDE 10.4.4.4:40243 <-> 10.4.4.14:http
(pkts,bits) in = (1, 64) out = (2, 116)
PROTOCOL tcp UNIT 1 IDLE 71 (300) LASTHOP external 00:30:48:57:15:95
VIRTUAL 10.2.2.60:http <-> NODE 10.4.4.15:http TYPE any 1/0
CLIENTSIDE 10.2.2.20:40244 <-> 10.2.2.60:http
(pkts,bits) in = (2, 112) out = (1, 64)
SERVERSIDE 10.4.4.4:40244 <-> 10.4.4.15:http
(pkts,bits) in = (1, 64) out = (2, 116)
PROTOCOL tcp UNIT 1 IDLE 58 (300) LASTHOP external 00:30:48:57:15:95
[root@ltm01:Active:avc(0)] config #

Note: For more information about the bigpipe conn command, refer to the Bigpipe Utility Reference Guide.

Workaround

You can display a subset of the connection table based on server-side flow information by using the grep command to filter the connection table. For example, to display connections sent to a specific node, use a command similar to the following example, substituting the address of the node whose connections you would like to see:

bigpipe conn show | grep 192.168.1.1

As an alternative, you could use the following command for more verbose output:

bigpipe conn show all | grep -A5 192.168.1.1

Note: If the connection table contains a large number of connections, the results of either command may take an extended period of time to return, and in some cases may not return at all.

There is no similar workaround for applying a server-side filter to the bigpipe conn delete command.
