K11177: The initial ICMP response to a ping from the ARX mgmt port may not be received

Topic

When you use the ping command to send an ICMP request that will be routed through the mgmt port, you must specify the management IP address as the source address; otherwise, the ARX system does not receive the initial ICMP response.

The ping command output indicates that packet loss was encountered; the output appears similar to the following example:

Note: For the following examples, the ARX mgmt IP address is 172.28.4.166.

ARX-166# ping 172.28.4.254 count 3
8 bytes from 172.28.4.254: icmp_seq=2 ttl=64 time=1 ms. from 1.1
8 bytes from 172.28.4.254: icmp_seq=3 ttl=64 time=543 ms. from 1.1

-------172.28.4.254 ping statistics
3 packets transmitted, 2 packets received, 33% packet loss
round-trip min/avg/max 1/272/543 ms

This behavior is by design and does not indicate a failure or indicate that packet loss is occurring on the mgmt interface.

To allow the ping command to work without the appearance of packet loss, you can specify the source IP address of the mgmt port.

For example:

ARX-166# ping 172.28.4.254 source 172.28.4.166 count 3
PING 172.28.4.254 (172.28.4.166) 0 data bytes
8 bytes from 172.28.4.254: icmp_seq=1 ttl=64 time=1 ms. src addr 172.28.4.166
8 bytes from 172.28.4.254: icmp_seq=2 ttl=64 time=1 ms. src addr 172.28.4.166
8 bytes from 172.28.4.254: icmp_seq=3 ttl=64 time=<1 ms. src addr 172.28.4.166

-------172.28.4.254 ping statistics
3 packets transmitted, 3 packets received, 0% packet loss
round-trip min/avg/max 0/0/1 ms
