Known Issue

The ospfd process may leak memory when configured to use a distribute-list filter.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration uses the Open Shortest Path First (OSPF) dynamic routing protocol.
  • Your OSPFv2 configuration includes a distribute-list filter.
  • The Routing Information Base (RIB) contains IP address prefixes that are filtered by the distribute-list filter when a link-state advertisement (LSA) occurs.

The ospfd process fails to release memory when LSAs are filtered by the distribute-list filter. Eventually the ospfd process may consume enough memory that the Linux OOM killer will attempt to free memory by restarting the ospfd process.

Impact

OSPFv2 dynamic routing is interrupted while the ospfd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The ospfd process size continues to increase in memory.
  • The ospfd process restarts and OSPFv2 dynamic routing is interrupted.
  • The system may experience an interruption in traffic.

Workaround

To work around this issue, you can place the BIG-IP system in the network so that LSAs do not need to be filtered using a distribute-list filter (for example, in a stub area).

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.
