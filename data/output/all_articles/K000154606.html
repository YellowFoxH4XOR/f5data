K000154606: ZoneRunner Fails to Start and Displays "Error Trying to Access the Database" Due to Missing Zone Files on BIG-IP DNS

Description

DNS services on BIG-IP DNS (ZoneRunner) may become unavailable, resulting in inability to access the ZoneRunner GUI and displaying the error: "Error trying to access the database" under DNS > Zones > ZoneRunner > Resource Record List. System logs may show repeated zrd restarts, such as:

Emergency logger: Re-starting zrd

Running:

named-checkconf -j -z -t /var/named

can reveal errors indicating missing zone files:

loading from master file db.external`.<zone>.failed: file not found
zone <zone>/IN: not loaded due to errors.
external/<zone>/IN: file not found

Environment

  • ZoneRunner Load Failure

Cause

ZoneRunner and BIND fail to start or operate correctly when one or more referenced zone files are missing from the filesystem. This leads to repeated zrd restarts and database access errors in the GUI.

Recommended Actions

Impact of Workaround: While zrd and BIND are stopped/frozen, any services reliant on them will not be available. It is therefore advised to perform this during a maintenance window.

This PoA applies when backup files (usually identified with a `~` suffix) exist. In case they do not exist, alternative solutions should be considered (e.g. finding the zone files in previous UCS backups, creating them again from scratch or even considering removing the zone completely from the named.conf file.)

  1. Identify Missing Zone Files:
    Run the following command to check for missing zone files and configuration errors:
    named-checkconf -j -z -t /var/named
    Review output for "file not found" or "not loaded due to errors" messages.
    loading from master file db.external`.<zone>.failed: file not found
    zone <zone>/IN: not loaded due to errors.
    external/<zone>/IN: file not found
  2. Stop Services:
    Stop the zrd process
    bigstart stop zrd
    Freeze BIND during restoration.
    rndc freeze
  3. Restore Zone Files from Backup:
    Identify the backup files (usually with a `~` suffix) for the missing zones and make a copy of them without the `~`. For example:
    cp /var/named/db.example.com~ /var/named/db.example.com
  4. Restart Services:
    After restoring zone files, restart BIND:
    rndc thaw
    and zrd:
    bigstart start zrd
    Confirm that ZoneRunner/DNS services are operational and GUI error is resolved.
