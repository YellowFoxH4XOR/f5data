Topic

Microsoft introduced several changes to Windows XP with the release of Windows XP SP2. These included changes to the number of registry settings that limit access to the applications that communicate with client systems using the Remote Procedure Call (RPC) network protocol. This is the protocol that Outlook uses.

FirePass Application Tunnels direct clients, such as Outlook, to make RPC calls to the loopback interface before forwarding them to the remote server. Windows XP SP2 limits these RPC calls by requiring remote connection authentication.

Because FirePass sends a connection to the local loopback before connecting to the remote server, RPC attempts to authenticate on the local system rather than the remote system. Since the authentication credentials are not, in most cases, the same on the local and remote systems, the authentication fails.

In light of these issues, F5 Networks recommends that you consider the implications of installing Windows XP SP2 and extensively test the impact that it will have on your configuration before fully deploying it to your network. For more information, refer to K3289: FirePass compatibility with Windows XP Service Pack 2 clients.

Workaround

To work around this issue and successfully use FirePass Application Tunnels with Outlook and Windows XP SP2, perform the following steps on each client system:

  1. Install the Microsoft hotfix, KB884020, which is available at: http://support.microsoft.com/?id=884020
  2. Run the Microsoft regedit program located at C:\Windows\regedit.exe.

    Warning: If you make an error while editing the Windows registry settings, you can create severe problems that can be solved only by reinstalling the operating system. Use the registry editor with extreme caution.

  3. From the left tree view, navigate to HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows NT\RPC.

    Some of the keys in this path may not yet exist. If you are able to navigate successfully to RPC, go directly to Step 5.

  4. Create the Windows NT key, by performing the following steps:

    1. Right-click the Microsoft key.
    2. Click New
    3. Click Key
    4. Name the key Windows NT.
  5. Create the RPC key, by performing the following steps:
    1. Right-click the Windows NT key.
    2. Click New
    3. Click Key
    4. Name the key RPC.
  6. Right-click the RPC key.
  7. Click New.
  8. Click DWORD.
  9. Name the new DWORD RestrictRemoteClients.

    The value of the DWORD should be set to 0, which is the default.

  10. Repeat Steps 1-8 on each client system.

Once completed, Outlook should function over Application Tunnels without requesting local authentication.

If this procedure does not work immediately, reboot the system. If this does not help, double-check the registry key changes.

If these steps do not resolve the problem, contact F5 Networks Technical Support for assistance.
