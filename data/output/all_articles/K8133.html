Known Issue

This is the result of a known issue. If a Mac OS X or Linux client launches a Network Access connection from the FirePass webtop, the Network Access window may display the status as Queued even after the Network Access connection is established. This issue occurs when the following two conditions are met:

  • The Present the user with a message box after successfully connecting Network Access client check box is selected on the Network Access: Resources page under the Customization tab.
  • The browser on the client system is configured to block pop-up windows.


F5 Networks Product Development tracked this issue as CR89738 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Additionally, cumulative hotfix HF-601-9 has been issued for FirePass version 6.0.1 and cumulative hotfix HF-602-8 has been issued for FirePass version 6.0.2 . You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by clearing the Present the user with a message box after successfully connecting Network Access client check box on the Network Access: Resources page, under the Customization tab. Additionally, users can work around this issue by modifying their browser configuration to allow the FirePass controller to open pop-up windows.
