Description

  • Applications stop loading or partially loading intermittently post upgrade.
  • Violation detected despite having no relevant configuration to learn/block/alarm.
  • The below error appears:
    Nov 11 22:51:22 slot2/Bigip1 crit g_server_rpc_handler_async.pl[2815]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): DBD::mysql::st execute failed: Cannot add or update a child row: a foreign key constraint fails (`DCC`.`HSL_DATA_PROFILES`, CONSTRAINT `HSL_DATA_PROFILES_ibfk_1` FOREIGN KEY (`hsl_profile_id`) REFERENCES `HSL_PROFILES` (`hsl_profile_id`) ON DELETE CASCADE) at /usr/local/share/perl5/F5/Hsl.pm line 318.

Environment

  • ASM Security Policy associated with the application

Cause

This issue is caused by the BIG-IP system running out of disk space during the upgrade leading to missing data including the active policy data and the empty HSL_PROFILES table.

Recommended Actions

To resolve this issue you may use the below workaround OR export and re-import the faulty policy to the BIGIP:

  1. Run this perl one-liner to re-populate DCC.HSL_PROFILES:

    perl -MF5::DbUtils -MF5::Hsl::Populate -MF5::PrepareConf::Hsl -MF5::LWP::UserAgent -e 'my $dbh = F5::DbUtils::get_dbh(database_username => "root"); fatal_error("DBI->connect".$DBI::errstr) unless $dbh; F5::Hsl::Populate::populate_defaults(dbh => $dbh, plc_dbname => "PLC", dcc_dbname => "DCC", logger => $logger,); my $prepare_hsl = F5::PrepareConf::Hsl->new(dbh => $dbh); $prepare_hsl->prepare(hsl_profile_id => FTP); $prepare_hsl->prepare(hsl_profile_id => SMTP);'

  2. Restart the asm process to trigger generating DCC.HSL_DATA_PROFILES:

    bigstart restart asm
