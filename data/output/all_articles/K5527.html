Topic

This article applies to BIG-IP 9.x. For information about other versions, refer to the following article:

  • K13080: Configuring the BIG-IP system to log to a remote syslog server (10.x - 12.x)

The syslog-ng utility (a third-party logging utility that the BIG-IP system uses in place of the standard UNIX/Linux syslog utility) offers a number of more granular options for syslog message management.

BIG-IP 9.4.2 through 9.4.8

In BIG-IP 9.4.2 through 9.4.8, you must use the bigpipe syslog command to create custom syslog configurations.

To configure the BIG-IP system to send all messages to a remote server, for version 9.4.2 through 9.4.8, perform the following procedure:

  1. Log in to the command line.
  2. To configure the remote syslog server, type the following command:

    bigpipe syslog remote server <IP_address>

    For example:

    bigpipe syslog remote server 192.168.15

  3. To save the configuration, type the following command:

    bigpipe save

Note: To remove the remote syslog server, use the bigpipe syslog remote server none command.

Note: In BIG-IP 9.4.2 through 9.4.8, the bigpipe syslog command allows the addition of only one remote syslog server. However, the syslog-ng facility allows for multiple remote syslog servers. For more information and additional configuration examples, refer to K8259: The bigpipe syslog remove server command may only be used to add a single remote UDP syslog server and the LTM 9.4.2+: Custom Syslog Configuration DevCentral article. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

BIG-IP 9.0.0 through 9.4.1

You can configure the BIG-IP system to log to a remote syslog server by performing one of the following three procedures:

  • Configuring the BIG-IP system to send all messages to a remote server.
  • Configuring the BIG-IP system to send all messages to multiple remote servers.
  • Configuring the BIG-IP system to send specific logs to remote servers.

Note: In the following procedures, the BIG-IP system is configured to send messages using UDP, although it is also possible to use TCP. If using TCP, you must ensure that your remote syslog server is configured to accept remote log messages from the BIG-IP system over the selected protocol.

Note: The following configurations will send all BIG-IP log messages to the remote syslog server unencrypted. For more information about encrypted remote logging, refer to the Logging BIG-IP system Events chapter of the BIG-IP Network and System Management Guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Configuring the BIG-IP system to send all messages to a remote server

Note: While it is possible to send all messages to a remote server and prevent the messages from being logged locally, F5 does not recommend this configuration as it can prevent a timely resolution of any problems if the log information is not readily available to F5 Support Engineers. The qkview script automatically collects all logs on the system, and is a primary troubleshooting utility used by F5 Support Engineers.

The following procedure configures a filter that the system uses to send all messages that the syslog-ng utility handles to a remote server without disrupting local logging.

  1. Log in to the command line.
  2. Change directories to the /etc/syslog-ng/ directory by typing the following command:

    cd /etc/syslog-ng/

  3. Back up the current syslog-ng.conf file by typing the following command:

    cp syslog-ng.conf syslog-ng.conf.original

  4. Using a text editor, open the syslog-ng.conf file.
  5. Add the following to the end of the syslog-ng.conf file:

    Note: Replace x.x.x.x with the IP address of the remote log server.

    # Direct all log information to remote syslog server
    destination remote_server {
    udp("x.x.x.x" port (514));
    };
    filter f_alllogs {
    level (debug...emerg);
    };
    log {
    source(local);
    filter(f_alllogs);
    destination(remote_server);
    };

  6. Save the changes to the file.
  7. Restart the syslog-ng utility by typing the following command:

    bigstart restart syslog-ng

Note: To restore the original syslog-ng configuration, restore the original configuration file and restart the syslog-ng service by typing the following commands:

   cp syslog-ng.conf.original syslog-ng.conf
   bigstart restart syslog-ng

Configuring the BIG-IP system to send all messages to multiple remote servers

  1. Log in to the command line.
  2. Change directories to the /etc/syslog-ng/ directory by typing the following command:

    cd /etc/syslog-ng/

  3. Back up the current syslog-ng.conf file by typing the following command:

    cp syslog-ng.conf syslog-ng.conf.original

  4. Using a text editor, open the syslog-ng.conf file.
  5. Add the following line to the end of the syslog-ng.conf file:

    Note: Replace x.x.x.x, y.y.y.y, and z.z.z.z with the IP addresses of the remote log servers.

    # Direct all log information to multiple remote syslog servers
    destination remote_server {
    udp("x.x.x.x" port (514));
    udp("y.y.y.y" port (514));
    udp("z.z.z.z" port (514));
    };
    filter f_alllogs {
    level (debug...emerg);
    };
    log {
    source(local);
    filter(f_alllogs);
    destination(remote_server);
    };

  6. Save the changes to the file.
  7. Restart the syslog-ng utility by typing the following command:

    bigstart restart syslog-ng

Note: To restore the original syslog-ng configuration, restore the original configuration file and restart the syslog-ng service by typing the following commands:

   cp syslog-ng.conf.original syslog-ng.conf
   bigstart restart syslog-ng

Configuring the BIG-IP system to send specific logs to remote servers

You can specify which log files you want the syslog utility to send to remote servers (rather than sending all traffic to a remote syslog server and parsing out only the log files you want to capture). This configuration reduces filtering overhead if you require only specific log filters.

To configure the BIG-IP system to send specific logs to remote servers, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /etc/syslog-ng/ directory by typing the following command:

    cd /etc/syslog-ng/

  3. Back up the current syslog-ng.conf file by typing the following command:

    cp syslog-ng.conf syslog-ng.conf.original

  4. Using a text editor, open the syslog-ng.conf file.
  5. Locate the syntax in the file that appears similar to the following example, which is located before the various log files and their options:

    options {
    dir_perm(0755);
    perm(0644);
    chain_hostnames(no);
    keep_hostname(yes);
    stats(0);
    log_fifo_size(2048);
    };
    source local {
    unix-stream("/dev/log");
    pipe("/proc/kmsg");
    udp(ip(127.0.0.1) port(514));
    udp(ip(127.2.0.2) port(514));
    internal();
    };

  6. Add the following destination entry on a new line after the syntax in Step 5:

    Note: Replace x.x.x.x with the IP address of the remote log server.

    destination remote_server { udp("x.x.x.x" port (514)); };

  7. Locate the specific message section that contains the information for the log files that you want to send to a remote server, and update the destination option.

    For example, to add a remote destination server so the system records all log information for the /var/log/ltm file and then sends the information to a remote server, you would do the following:

    Locate the /var/log/ltm entry in the syslog-ng.conf file that appears similar to the following example:

    # local0.*          /var/log/ltm
    filter f_local0 {
    facility(local0) and level(debug..emerg);
    };
    filter f_no_audit {
    not match("AUDIT");
    };
    destination d_ltm {
    file("/var/log/ltm" create_dirs(yes));
    };
    log {
    source(local);
    filter(f_local0);
    filter(f_no_audit);
    destination(d_ltm);
    };

    Change the destination entry located under the log section to include the new destination filter created in Step 6, similar to the following example:

    # local0.*          /var/log/ltm
    filter f_local0 {
    facility(local0) and level(debug..emerg);
    };
    filter f_no_audit {
    not match("AUDIT");
    };
    destination d_ltm {
    file("/var/log/ltm" create_dirs(yes));
    };
    log {
    source(local);
    filter(f_local0);
    filter(f_no_audit);
    destination(d_ltm);
    destination(remote_server);
    };

  8. Repeat Step 7 for each log file that you want the syslog utility to send to a remote log server.
  9. Save the changes you made to the syslog-ng.conf file.
  10. Restart syslog-ng with the following command:

    bigstart restart syslog-ng 

Note: To restore the original syslog-ng configuration, restore the original configuration file and restart the syslog-ng service by typing the following commands:

cp syslog-ng.conf.original syslog-ng.conf
bigstart restart syslog-ng
