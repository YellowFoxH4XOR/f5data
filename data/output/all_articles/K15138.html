Known Issue

The binary scan iRule command fails to perform boundary checking, which may cause the iRule to read an out-of-bounds memory location.

This issue occurs when the following condition is met:

  • The iRule command uses a format string that causes the scan to begin at a point greater than the amount of data being scanned.

For example, when using the following iRule command:

binary scan [TCP::payload] @${offset_num}c var1

The @${offset_num}c format string means to "move the cursor forward to this many bytes" before starting the scan. If the offset_num value is larger than the payload buffer length, the scan attempts to begin from an out-of-bounds memory location, and causes the Traffic Management Microkernel (TMM) to restart.

Impact

TMM may produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H453729 on the Diagnostics > Identified > Medium|High screen.
  • TMM produces a core file and temporarily fails to process traffic.

Workaround

To work around this issue, you can ensure your iRule compares the payload length to the offset value before moving the cursor.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
