Topic

You can use the Receive Disable String (RECV drain string) advanced configuration setting to disable a pool member or node based on the response the monitor receives from the server.

To watch a video demo of this procedure, go to  Use the Receive Disable String advanced configuration setting.

Description

The Receive Disable String setting applies to the following monitors:

  • HTTP
  • HTTPS
  • HTTP/2
  • TCP
  • UDP

Note: For more information regarding monitors and configuring monitors, refer to the configuration manual for your specific BIG-IP product.

These monitors use the Receive Disable String value in conjunction with the Receive String value to determine one of the following three states for a monitored pool member or node:

  • Up (enabled) - The pool member or node is available to receive new connections.
  • Up (disabled) - The pool member or node allows existing connections until they are completed or timed out. However, the pool member or node is not available to receive new connections.
  • Down - The pool member or node is not available to receive new connections. For any existing connections to the pool member or node, the behavior is controlled by the pool's Action On Service Down setting. For more information on the Action On Service Down setting, refer to K15095: Overview of the Action On Service Down feature. The default action is None, which allows the existing connections to continue, if possible, until the connection terminates on its own or due to TCP idle timeout being reached. If the action is set to Reject or Drop, the BIG-IP system immediately terminates the connection.

When you configure both the Receive String and Receive Disable String settings, the status of the monitored pool member or node is determined by whether the monitor response contains a match to either or both of the specified strings. The monitored pool member or node status results in one of the combinations listed in the following table.

Note: If you have set the Reverse setting to Yes, the Receive Disable String setting becomes unavailable, and, when the response value matches the Receive String value, the monitor marks the pool, pool member, or node as down.

Using the Receive Disable String setting to disable or mark down a pool member

The Receive Disable String setting allows you to use built-in monitors instead of custom Extended Content Verification (ECV) monitors, as required in previous versions, to perform maintenance on a server or group of servers. The setting provides an alternative method to disable or mark down a pool member or node without having to provide administrative access to the BIG-IP system to disable or mark down the pool member or node.

The following steps illustrate a simple example use case in which you configure the Receive Disable String:

  1. Configure an HTTP monitor to query a file named serverstat.html on the server.

    The serverstat.html file contains one of two entries: Server Operational or Maintenance.

  2. Set the Receive String option to Server Operational.
  3. Set the Receive Disable String to Maintenance.
  4. Apply the HTTP monitor to the pool members.
  5. When the pool member is queried and replies with Server Operational, the pool member is marked up and available.

    If the monitor does not receive a response, then the pool member is marked down and is not available.

  6. If you want to perform maintenance on a pool member, you can change the value in the serverstat.html file from Server Operational to Maintenance.
  7. After the monitor detects the Maintenance response, it marks the pool member up and disabled.

    This allows the pool member to continue serving existing, established, connections and prevents the BIG-IP system from using the pool member for new connections. After all of the existing connections are drained from the pool member, you can begin to perform maintenance work.

    Note: When a pool member is marked as disabled by the receive disable string it will generate an LTM log similar to notice mcpd[4651]: 01070639:5: Pool /Common/example member /Common/10.10.10.211:80 session status disabled.
