Known Issue

The BIG-IP system may not properly migrate an HTTP Class profile referencing pool to an equivalent local traffic policy. This issue occurs when all of the following conditions are met:

  • The HTTP Class profile and the referenced pool reside in an administrative partition other than the Common partition.
  • The configuration is migrated from BIG-IP 10.x to a BIG-IP version listed in the Applies To box, located in the upper-right corner of this article.
  • The BIG-IP system migrates the configuration containing this HTTP Class profile during either an upgrade or a UCS archive restoration.

When the BIG-IP system migrates the configuration containing the affected HTTP Class profile, the system generates a local traffic policy rule that references the pool without the appropriate administrative partition. As a result, the mcpd process fails to load the configuration due to invalid pool names. For example, the following test_pool_ref HTTP Class profile references the test_pool pool, which resides in the myexample administrative partition in BIG-IP 10.x:

ltm profile httpclass test_pool_ref {
defaults-from httpclass
pool test_pool
redirect none
}

After the migration, the local traffic policy generated by the system based on this HTTP Class profile has the following rule, which references the test_pool pool instead of the /myexample/test_pool pool:

policy base /myexample/test_pool_ref {
controls { forwarding }
requires { http }
strategy /Common/first-match
rules {
test_pool_ref_policy_rule {
ordinal 1
actions {
1 {
target forward
pool test_pool
action select
}
}
}
}
}

Impact

The BIG-IP system fails to load the configuration and is unable to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H457560 on the Diagnostics > Identified > High screen.
  • The BIG-IP system fails to load the configuration and is unable to process traffic after an upgrade or a UCS archive restoration.
  • In the /var/log/ltm file, you observe an error message that appears similar to the following example:

    010716e5:3: Policy '/myexample/test_pool_ref', rule 'test_pool_ref_policy_rule'; action refers to an invalid pool 'test_pool'.

Workaround

To prevent this issue, you must upgrade the BIG-IP 10.x system to any version from BIG-IP 11.0.0 through 11.3.0, and then upgrade to either BIG-IP 11.4.0 or 11.4.1. The intermediate upgrade will ensure the pool names contain the administrative partition.

To work around this issue, you can add the appropriate partition name to the affected pool object referenced by the system-generated local traffic policy by editing the /config/bigpipe/bigip.conf file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected system.
  2. Back up the /config/bigpipe/bigip.conf file by entering the following command:

    cp -p /config/bigpipe/bigip.conf /var/tmp/bigip.conf.sol15197
  3. Edit the /config/bigpipe/bigip.conf file using a text editor of your choice.
  4. Locate the local traffic policy generated by the system based on the affected HTTP Class profile.
  5. Add the appropriate administrative partition to the affected pool referenced in the local traffic policy rule. Using the example in the Description section, you would rename test_pool to /myexample/test_pool.
  6. Save the changes and exit the text editor.
  7. Reload the configuration by entering the following command:

    Important: You should use the following command only when instructed in an article or by F5 Support.

    /usr/libexec/bigpipe daol
  8. Save the configuration using the tmsh utility by entering the following command:

    tmsh save sys config partitions all
  9. Reload the configuration using the tmsh utility by entering the following command:

    tmsh load sys config partitions all
