Known Issue

Cross-site request forgery (CSRF) Protection injects custom JavaScript that may interfere with some HTTP responses.

This issue occurs when all of the following conditions are met:

  • CSRF Protection is enabled.
  • The HTTP response contains the meta header X-UA-Compatible.
  • The client browser is Internet Explorer 8.

Impact

Web resources may fail to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Web resources do not load.
  • Internet Explorer 8 reports various JavaScript-related errors.

Resolution

Status

Important: For versions 10.2.3, and all HF versions, additional steps are required to implement the fix for this ID after upgrading/installing the software. This procedure is not required for BIG-IP ASM 11.1.0.

In order to enable the fix provided in the above software versions, add the smart_inject internal parameter by performing the following procedure:

  1. Log in to the BIG-IP ASM command line.
  2. Add the smart_inject internal parameter by typing the following command:

    /usr/share/ts/bin/add_del_internal add smart_inject 1
  3. Restart the BIG-IP ASM service to commit the change by typing the following command:

    Important: This step causes a brief interruption to the BIG-IP ASM service, during which traffic is not processed.

    bigstart restart asm

Workaround

To work around this issue, you can disable CSRF Protection, or use another browser.

Impact of workaround: Disabling CSRF Protection decreases the security of a web application.

For details on the CSRF Protection feature, refer to the Configuration Guide for BIG-IP Application Security Manager.
