Topic

This article covers the compatibility of F5 iWorkflow with BIG-IP, Cisco APIC, and VMware NSX releases.

Description

F5 iWorkflow releases include the Cloud and Device modules. Beginning in BIG-IQ 4.6.0, F5 removed the Cloud module from the BIG-IQ product line. For more information about this change, refer to K05211126: BIG-IQ product offerings after version 4.5.0. F5 limits upgrade support for iWorkflow to two previous versions, for any given release. For example, to upgrade to iWorkflow 2.3.0, you must currently be running iWorkflow 2.1.0.

Managing the VIPRION chassis

Starting with iWorkflow 2.3.0, customers can leverage multiple slots in a VIPRION chassis. In addition, iWorkflow 2.3.0 also supports Virtual Clustered Multiprocessing (vCMP) guests that can span multiple slots.

iWorkflow 2.2.0 supports a single, populated slot in a VIPRION chassis; iWorkflow 2.2.0 does not support populating a VIPRION chassis with more than one blade. iWorkflow can provision vCMP guests onto a VIPRION chassis and deploy services to those devices. iWorkflow can also discover existing vCMP guests on a vCMP host and manage those devices.

iWorkflow 2.0.0 through 2.1.0 does not support a non-vCMP VIPRION chassis. iWorkflow 2.0.0 through 2.1.0 can support a vCMP guest, when you deploy it to a single slot. By using the vCMP connector, you can provision a vCMP guest onto a VIPRION chassis that is running the vCMP module (vCMP host).

iApp compatibility

The preferred iApp to use with iWorkflow is the Application Services Integration iApp. Other F5 iApps may also work with iWorkflow, and you can create your own custom iApps. For information about using iApps with iWorkflow, refer to the iWorkflow user guide on F5 Cloud Docs.

To learn more about which versions of iWorkflow are supported, review the Application Services Integration iApp release notes.

BIG-IP, Cisco APIC, and VMware NSX compatibility
