Description

BIG-IP GTM/DNS https monitor is only initiating TLS1.1 connection to the server. The https monitor will not initiate TLS1.2 connection to the same server.

When using this same https monitor for another server, this https monitor will initiate TLS1.2 connection.

For example, the https monitor is https-monitor-example and it will only initiate TLS1.1 to server-1. At the same time https-monitor-example initiates TLS1.2 to server-2.

When the https monitor initiate TLS1.1 to the server, it does not necessary cause any issue. The issue will come when the server only allows TLS1.2 connection (disable TLS1.1). At this point the https monitor will mark the server as down as it is not able to initiate TLS1.1 connection with the server.

Environment

  • BIG-IP GTM/DNS
  • https monitor
  • https monitor only initiates TLS1.1 connection to the server
  • the same https monitor will initiate TLS1.2 connection to another server
  • https monitor will wrongly mark server down when the server is configured to accept only TLS1.2 (while https monitor uses TLS1.1)

Cause

By default, BIG-IP GTM/DNS https monitor will start with TLS1.2 when monitoring a server. At any one time during the probing, if TLS1.2 monitor fails, the https monitor will switch to TLS1.1 for that same server. All subsequent probes after that will be sent using TLS1.1 even though TLS1.2 is valid for the server. This issue is related to bug ID853581.

This is why the same https monitor initiates TLS1.1 for a specific server but not for all servers.

There is no option to force the https monitor to use only TLS1.2 connection. This feature has been requested and will be released in future BIG-IP GTM/DNS software releases. There is currently no timeline for this release.

Recommended Actions

You will need to restart big3d and the https monitor will re-initiate TLS1.2 connection to the server.

  1. Login to the Command Line.
  2. Restart big3d with the following command:
    bigstart restart big3d
    Impact: When restarting big3d, no statistic collection or auto-discovery will be captured
  3. Verify that the https monitor is initiating TLS1.2 connection to the server.
