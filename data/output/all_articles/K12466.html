Known Issue

This is the result of a known issue. The Configuration utility fails to process digital certificates with a Subject field greater than 1024 bytes. If such a digital certificate is uploaded onto the BIG-IP system, certain Configuration utility screens will no longer render and will display the following error message:

An error has occurred while trying to process your request.

As a result of this issue, you may encounter the following symptoms:

  • You will be locked out of the following BIG-IP Configuration utility screens until you remove the digital certificate:
    • Local Traffic > SSL Certificates
    • Local Traffic > Profiles > SSL > Client > Create
    • Local Traffic > Profiles > SSL > Server > Create
  • If an Enterprise Manager system attempts to discover a BIG-IP system with an affected certificate, discovery will fail and the Enterprise Manager system will log error messages to the /var/log/em file. For example:

    err emdeviced[10438]: 04010568:3: Error found on device 172.24.20.16 (UID: 0): iControl error: 'iControl::char*:SOAPException: 'Error while parsing SOAP XML payload: not well-formed (invalid token)''
    err emdeviced[10438]: 04072112:3: Could not get device information for address: 172.24.20.16: Failed to Retrieve Device Information.

F5 Product Development tracked this issue as ID 347025 and it was fixed in BIG-IP 10.2.2 and 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator release notes. In addition, BIG-IP iHealth may list Heuristic H379769 or H379769-1 on the Diagnostics > Identified > Medium screen.

Additional information

Digital certificates with a Subject field greater than 1024 bytes are not common. This issue was discovered in a customer environment in which a digital certificate contained more than one common name (CN). The presence of multiple CNs in the digital certificate pushed the Subject field above 1024 bytes, causing the issue described in this Solution.

Although digital certificates can specify multiple CNs, most SSL implementations were written with the assumption that only one will be present. At the time of writing, F5 is not aware of any browser supporting digital certificates with multiple CNs. F5 recommends that you create digital certificates containing only one CN. If you want a digital certificate to be valid for the authentication of multiple domain names, these should be included in the Subject Alternative Name extension field. Alternatively, if the domain names allow it, you can create a wildcard digital certificate.

Workaround

If the digital certificate causing this issue is valid and you must use it, you can associate it to a Client SSL or Server SSL profile from the command line by using either the bigpipe utility or the tmsh shell. However, the affected Configuration utility screen will remain inaccessible.

Note: For more information, refer to the Bigpipe Utility Reference Guide and the Traffic Management Shell (tmsh) Reference Guide.

Alternatively, if you want to regain access to the affected Configuration utility screens, you must remove the offending digital certificate from the /config/ssl/ssl.crt/ directory. To do so, type the following command from the BIG-IP command line:

mv /config/ssl/ssl.crt/<certificate> /var/tmp/

For example:

mv /config/ssl/ssl.crt/askf5.crt /var/tmp/
