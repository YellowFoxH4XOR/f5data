Topic

Summary

A change in the Red Hat Linux Remote Procedure Call (RPC) service may cause over consumption of ARX Network Services Module (NSM) resources.

Description

Introduced in Red Hat RHEL 6.3, clients can dynamically allocate resources for RPC requests.

In versions prior to 6.3 the number of RPC requests were limited to a default of 16 RPC requests, with a maximum of 128 in-flight requests. The change allows clients to handle a significantly higher number of in-flight RPC requests as long as the ARX system continues to respond to the TCP segment of the request. This, in turn, allows a Red Hat client to flood the ARX system with RPC requests. As the number of outstanding requests grow, the ARX propkt service will begin to reach its resource threshold and eventually the service will core.

If the propkt service reaches the resource consumption threshold, you may see some of the following symptoms:

  • The ARX syslog will log NSM resource threshold messages that appear similar to the following examples:

    • Example messages on an ARX 1500 or 2500 platform:

      SNMP TRAP: nsmResourceThreshold (<pid>)  : resource:propkt threshold:100 slot:2 proc:12

      SNMP TRAP: systemResourceThresholdClear (<pid>)  : resource:memory threshold:90 slot:1 proc:1

      nsmResourceThreshold (<pid>) name 'Packet Buffers'

      systemResourceThresholdRaise (<pid>) : resource:CPU threshold:80 slot:1 proc:3
    • Example messages on an ARX 500, 1000, 4000, or 6000 platform:

      The fastpath Packet Buffers resource is at 75% utilization level.

      SNMP TRAP: systemResourceThresholdRaise (<pid>)  : resource:CPU threshold:80 slot:1 proc:3

      nsmResourceThreshold (<pid>)  : resource:propkt  threshold:100 slot:2 proc:1

      systemResourceThresholdClear (<pid>)  : resource:memory threshold:90 slot:1 proc:1
  • The ARX system may produce an NSMD core file and log an error message similar to the following:

    nsmd[<pid>]: [E:1] Writing core file.
  • When this issue occurs, you may see the following behaviors when reviewing network captures:

    • The client flooding the ARX system with NFS requests and retransmissions.
    • No response, or a long response time (greater than 1 second), from the ARX system.

Recommendations

When using Red Hat clients 6.3 and greater, you can limit the number of RPC calls that the client is allowed to make by making the following configuration changes on the clients:

Impact of recommendation: The suggested adjustment is a client-based change and may affect your clients in a manner that F5 is not aware of. Contact your Linux client vender or administrator for assistance.

  1. Log in to the Linux device CLI as an administrator.
  2. Change directories to the modprode.d directory by using the following command:
    cd /etc/modprobe.d
  3. Locate the sunrpc.conf file using the ls command.
  4. If the file does not exist, create the sunrpc.conf file in the /etc/modprobe.d directory with the following parameter within the file:

    options sunrpc tcp_max_slot_table_entries=16
  5. Verify the file contents of the sunrpc.conf file by using the cat command:

    For example:
    cat /etc/modprobe.d/sunrpc.conf
    options sunrpc tcp_max_slot_table_entries=16
  6. Restart your client device to ensure that the changes take effect.
