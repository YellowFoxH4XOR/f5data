Topic

F5 Product Development recommends using a wide range of characters in passwords that you define for F5 product user accounts. Together with alphanumeric characters, the following is a list of allowed characters you can use for your passwords:

  • !
  • @
  • #
  • $
  • %
  • ^
  • &
  • *
  • (
  • )
  • `
  • ~
  • -
  • +
  • =
  • [
  • ]
  • {
  • }
  • ;
  • ’
  • :
  • "
  • '
  • .
  • /
  • <
  • >
  • |
  • \
  • ?
  • _

Known Issues

If you encounter an error, refer to the following use cases:

Known issueDescription
Escaping and using quotes on the command lineSome special characters are valid but have special meaning on the command line. When using these special characters to set your password, use the backslash (\) escape character, or quotes (') and (") as appropriate.

For example, use the single quote character when setting the following password on the TMSH (tmos) shell:

modify auth user admin password 'abc!@#$%7;'

save sys ucs encrypted.ucs passphrase !#&*()-_=+[]<>:\?

In the above example the actual passphrase is: !#&*()-_=+[]<>:?

The '\' is used to allow a '?' symbol as a part of a passphrase.

ID 940757The semicolon (;) character is not allowed in password with BIG-IP APM.

Note also the characters that are not allowed in Microsoft Azure Active Directory when setting passwords.

For example, the @ character is not allowed when setting the password for UserPrincipalName when you configure Kerberos. For more information, Password policies and account restrictions in Azure Active Directory on microsoft.com.
