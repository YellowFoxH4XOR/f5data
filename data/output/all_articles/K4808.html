Known Issue

This is the result of a known issue. NTLM authentication will fail under the following conditions:
  • An HTTP site is accessed through a virtual server that uses delayed binding features.
  • The node returns a 100 (continue) message, followed by a 302 (redirect) message.

If both of the above conditions are met, the BIG-IP will close the connection and open a new connection for subsequent requests. This action prevents the application of NTLM authentication following the redirect.

F5 Networks Product Development tracked this issue as CR50387 and CR50712 and it was fixed in BIG-IP version 4.5.13 for the 4.5 software branch. For information about upgrading, refer to the BIG-IP Release Notes.

This issue still exists in the 4.6 software branch.
