Topic

The BIG-IP system processes the local traffic policies before evaluating an iRule. 

Description

The BIG-IP system processes the local traffic policy rule (that pertains to HTTP events) before evaluating iRule HTTP events and commands. This behavior is by design and cannot be modified or reverted.

For example, assume you have a virtual server configured with an iRule and a local traffic policy. The local traffic policy is configured to forward requests to pool_A when the HTTP Host header value matches www.example.com, and as a catch-all forward all other requests to pool_B:, similar to the following example:

    rules {
        rule_example {
            actions {
                0 {
                    forward
                    select
                    pool pool_A
                }
            }
            conditions {
                0 {
                    http-host
                    host
                    values { www.example.com }
                }
            }
        }
        rule_catchall {
            actions {
                0 {
                    forward
                    select
                    pool pool_B
                }
            }
            ordinal 1
        }
    }

The iRule is configured to trigger on the HTTP_REQUEST event, and modify the HTTP Host header value of the request to www.example.com if the original Host header value is example.com, similar to the following:

when HTTP_REQUEST {
  if { [HTTP::host] starts_with "example.com" } {
    HTTP::header replace "Host" "www.example.com"
  }
}

Because the local traffic policy rules are evaluated before the iRule, requests with an HTTP Host header value of example.com are not changed to www.example.com by the iRule before matching the rule_catchall local traffic policy rule. As a result, the request is forwarded to pool_B.

Recommendations

When using local traffic policies with iRules, depending on your application environment, F5 recommends that you convert your iRule HTTP functions to use the Local Traffic Policies feature whenever possible. For a list of common HTTP use cases (such as simple HTTP-to-HTTPS redirection or load balancing multiple pools), refer to the Supplemental Information section.
