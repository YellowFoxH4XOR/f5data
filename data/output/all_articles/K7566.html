Topic

This article applies to BIG-IP 9.x - 10.x. For information about other versions, refer to the following article:

  • K13310: Disabling nodes or pool members for maintenance (11.x - 13.x)

The BIG-IP Configuration utility designates two terms for network devices to which a BIG-IP system load balances traffic: nodes and pool members. A node is identified as the network device's IP address, such as 10.10.10.10. A pool member is identified as the network device's IP address, the service port on which the pool member is listening, and the name of the pool to which it belongs. For example: myPool:10.10.10.10:80.

You can set the node and pool members to a Disabled or Forced offline state. When you interrupt access to a network device (such as a server) for maintenance, you should change the state of the node to Disabled or Forced Offline. If the node is set to Disabled or Forced offline, any pool member in the BIG-IP configuration that uses that same IP address is also set to Disabled or Forced offline. Alternatively, when you disrupt only some services on a device, you should change the state of the affected pool members to Disabled or Forced offline. For example, if you want to change the state of the HTTP, HTTPS, and FTP pool members using the server IP 10.0.0.10, you should disable or force the 10.0.0.10 node offline. If you want to only change the state of the HTTP pool members running on address 10.0.0.10 and port 80, you should disable or force all 10.0.0.10:80 pool members offline.

When set to Disabled, a node or pool member continues to process persistent and active connections. It can accept new connections only if the connections belong to an existing persistence session.

When set to Forced Offline, a node or pool member allows existing connections to time out, but no new connections are allowed.

Procedures

To disable a node, perform one of the following procedures:

  • Setting the node state to Disabled using the Configuration utility
  • Setting the node state to Forced Offline using the Configuration utility
  • Setting the node state to Disabled using the command line
  • Setting the node state to Forced Offline using the command line
  • Deleting existing connections to the Disabled or Forced Offline node (Optional)

To disable a pool member, perform one of the following procedures:

  • Setting the pool member state to Disabled using the Configuration utility
  • Setting the pool member state to Forced Offline using the Configuration utility
  • Setting the pool member state to Disabled using the command line
  • Setting the pool member state to Forced Offline using the command line
  • Deleting existing connections to the Disabled or Forced Offline pool member (Optional)

Setting the node state to Disabled using the Configuration utility

Impact of procedure: Nodes that have been disabled will only accept new connections that match an existing persistence session.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Nodes > Node List.
  3. Select the node you want to set.
  4. Change the node state to:
    • For BIG-IP 9.3.0 and later

      Disabled (Only persistent or active connections allowed)

    • For BIG-IP 9.1.x through 9.2.x

      Only persistent or active connections allowed

  5. Click Update.

Setting the node state to Forced Offline using the Configuration utility

Impact of procedure: Nodes that have been forced offline will not accept any new connections, even if they match an existing persistence session.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Nodes > Node List.
  3. Select the node you want to set.
  4. Change the node state to:
    • For BIG-IP 9.3.0 and later

      Forced Offline (Only active connections allowed)

    • For BIG-IP 9.1.x through 9.2.x

      Only active connections allowed

  5. Click Update.

Setting the node state to Disabled using the command line

Impact of procedure: Nodes that have been disabled will only accept new connections that match an existing persistence session.

  1. Log in to the BIG-IP command line.
  2. Set the node state to Disabled by using the following command syntax:

    • For BIG-IP 10.2.x

      bigpipe node <node name> session user disabled

      For example:

      bigpipe node 10.10.10.211 session user disabled

    • For BIG-IP 9.x through 10.1.0

      bigpipe node <node name> session disable

      For example:

      bigpipe node 10.10.10.211 session disable

  3. Save the configuration change by typing the following command:

    bigpipe save all

Setting the node state to Forced Offline using the command line

Impact of procedure: Nodes that have been forced offline will not accept any new connections, even if they match an existing persistence session.

  1. Log in to the BIG-IP command line.
  2. To set the node state to Forced Offline, use the following command syntax:

    bigpipe node <node name> down

    For example, to set the state of the node 10.10.10.211 to Forced Offline, you would type the following command:

    bigpipe node 10.10.10.211 down

  3. Save the configuration change by typing the following command:

    bigpipe save all

Deleting existing connections to the Disabled or Forced Offline node (Optional)

If after disabling or forcing the node offline, you want to delete all connections to that node, perform the following procedure.

Impact of procedure: This procedure deletes all connections to the node's specific IP and every possible service port.

Note: Connections to nodes are on the server side of the BIG-IP connection. Connections to virtual servers are on the client side of the BIG-IP connection.

  1. Log in to the BIG-IP command line.
  2. To delete all connections to the node, use the following command syntax:

    bigpipe conn ss server <node IP address> delete

    For example, to delete all connections to the node 10.10.10.211, you would type the following command:

    bigpipe conn ss server 10.10.10.211 delete

Setting the pool member state to Disabled using the Configuration utility

Impact of procedure: Pool members that have been disabled only accept new connections that match an existing persistence session.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Select the name of the pool that contains the pool member you want to disable.
  4. Click the Members tab.
  5. Select the pool member you want to disable:
    • For BIG-IP 9.3.0 and later

      In the General Properties box, change the pool member state to Disabled (Only persistent or active connections allowed).

    • For BIG-IP 9.1.x through 9.2.x

      In the General Properties box, change the pool member state to Only persistent or active connections allowed.

  6. Click Update.

Setting the pool member state to Forced offline using the Configuration utility

Impact of procedure: Pool members that have been forced offline will not accept any new connections, even if they match an existing persistence session.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Select the name of the pool that contains the pool member you want to set.
  4. Click the Members tab.
  5. Select the pool member you want to set:
    • For BIG-IP 9.3.0 and later

      In the General Properties box, change the pool member state to Forced Offline (Only active connections allowed).

    • For BIG-IP 9.1.x through 9.2.x

      In the General Properties box, change the pool member state to Only active connections allowed.

  6. Click Update.

Setting the pool member state to Disabled using the command line

Impact of procedure: The pool members that have been disabled only accept new connections that match an existing persistence session.

  1. Log in to the BIG-IP command line.
  2. Set the pool member state to Disabled by using the following command syntax for your version:

    • For BIG-IP 10.2.x

      bigpipe pool <pool name> member <pool member name:port> { session user disabled }

      For example:

      bigpipe pool http-pool member 10.10.10.211:http { session user disabled }

    • For BIG-IP 9.x through 10.1.0

      bigpipe pool <pool name> member <pool member name:port> { session disable }

      For example:

      bigpipe pool http-pool member 10.10.10.211:http { session disable }

  3. Save the configuration change by typing the following command:

    bigpipe save all

Setting the pool member state to Forced Offline using the command line

Impact of procedure: Pool members that have been forced offline do not accept any new connections, even if they match an existing persistence session.

  1. Log in to the BIG-IP command line.
  2. To set the pool member state to Forced Offline, use the following command syntax:

    bigpipe pool <pool name> member <pool member name:port> down

    For example, to set the state of the pool member 10.10.10.211:http in pool http-pool to Forced Offline, you would type the following command:

    bigpipe pool http-pool member 10.10.10.211:http down

  3. Save the configuration change by typing the following command:

    bigpipe save all

Deleting existing connections to the Disabled or Forced Offline pool member (Optional)

If after disabling or forcing the pool member offline, you want to delete all connections to that pool member, perform the following procedure.

Impact of procedure: This command deletes all connections to the pool member's specific IP and service port.

Note: Connections to pool members are on the server side of the BIG-IP connection. Connections to virtual servers are on the client side of the BIG-IP connection.

  1. Log in to the BIG-IP command line.
  2. To delete all connections to the pool member, use the following command syntax:

    bigpipe conn ss server <member IP address:port> delete

    For example, to delete all port 80 connections to the pool member 10.10.10.211:http, you would type the following command:

    bigpipe conn ss server 10.10.10.211:80 delete
