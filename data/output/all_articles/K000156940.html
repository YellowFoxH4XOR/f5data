K000156940: VELOS partition 'show system events' has stopped registering new events

Type
Support Solution
Published
2025-10-08
Updated
2025-10-08
Applies to
  • F5OS
  • F5OS-C: 1.6.0, 1.8.X, 1.6.X, 1.8.1, 1.8.0, 1.6.2, 1.6.1
Source
https://my.f5.com/manage/s/article/K000156940

Description

Unable to see new events when reviewing the output of show system events at the partition level.

Environment

  • VELOS partition
  • Partition recently failed over

Cause

Bug ID 2087761: A partition's "show system events" no longer updates after multiple partition failovers

Recommended Actions

To fingerprint this issue, you can check the open file descriptors for the partition's alert-service process on the controller that is running-active for the partition.

For example:

# Note: the file descriptor pointing to a deleted file is key.

[root@controller-1(VEL410):Active ~]# ID=2 ALERT_SERVICE_PID=$(docker exec partition${ID}_alert_service pgrep alert_service)
[root@controller-1(VEL410):Active ~]# docker exec partition${ID}_alert_service ls -l /proc/${ALERT_SERVICE_PID}/fd | grep event-log
lrwx------. 1 root root 64 Oct  1 03:10 40 -> /var/F5/partition/events/.event-log.log.3dUnnS (deleted)

# In this example, alert-service has the correct file open and the issue is not present.

[root@controller-1(VEL410):Active ~]# docker exec partition${ID}_alert_service ls -l /proc/${ALERT_SERVICE_PID}/fd | grep event-log
lrwx------. 1 root root 64 Oct  1 05:01 40 -> /var/F5/partition/events/event-log.log

To recover from this issue, restart the partition's alert_service container on the controller that is running-active for the partition:

docker container restart partition<id>_alert_service

Additional Information

The issue will typically appear after multiple partition failovers.

The events in question can still be reviewed in the velos.log for the partition.
