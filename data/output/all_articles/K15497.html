Topic

This article applies to BIG-IP 11.x through 21.x. For information about other versions, refer to the following article:

  • K5962: Configuring a secure password policy for the BIG-IP system (9.x - 10.x)

You should consider using this procedure under the following condition:

  • You want to implement a secure password policy on the local user directory of the BIG-IP system.

Note: The local user directory described in this article is different from the local user database in the BIG-IP APM system. For more information about configuring and administering the BIG-IP APM local user database, refer to the Local User Database chapter of the BIG-IP Access Policy Manager: Authentication Methods manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

Description

You have the option to create a security policy for generating passwords for local BIG-IP system user accounts. A secure password policy ensures that BIG-IP system users who have local user accounts create and maintain passwords that are as secure as possible. The secure password policy feature includes two distinct types of password restrictions:

  • Enforcement restrictions are character restrictions that you can enable or disable. They consist of the minimum password length and the required character types (numeric, uppercase, lowercase, and other kinds of characters). When you enable them, the system applies enforcement restrictions to all user accounts.
  • Policy restrictions represent the minimum and maximum lengths of time that passwords can be active. This type of policy restriction also includes values for the number of days prior to password expiration on which the system warns users and the number of previous passwords that the BIG-IP system stores to prevent users from reusing former passwords. When you configure policy restrictions using the Configuration utility, policy restrictions apply to all user accounts. These restrictions are always enabled, although the default values provide a minimal amount of restriction.

The secure password policy feature affects passwords for the BIG-IP system's local user accounts only. Passwords for remotely stored user accounts are not subject to this local password policy but may be subject to a remote system's separate password policy.

Note: You can configure only one user authentication scheme for the system. When you select a remote authentication source, the page displays relevant configuration options.

Configuration settings

The Authentication page contains several settings that you can configure to implement a password policy. These settings, their descriptions, and default values are the following:

  • Secure Password Enforcement enables or disables enforcement (character) restrictions, and a policy for minimum password length and required characters. When you enable this setting, the Configuration utility displays the Minimum Length and Required Characters settings. The default value is Disabled prior to BIG-IP 14.0.0 and Enabled after BIG-IP 14.0.0.
  • Minimum Length specifies the minimum number of characters required for a password. The default value is 6, and the system allows the range of values from 6 through 255. This setting appears in the Configuration utility, and the system only enforces it when you enable the Secure Password Enforcement setting.
  • Required Characters specifies the number of numeric, uppercase, lowercase, and other characters required for a password. The default value for each character type is 0, and the system allows the range of values from 0 through 127. This setting appears in the Configuration utility, and the system only enforces it when you enable the Secure Password Enforcement setting.
  • Password Memory specifies, for each user account, the number of former passwords that the BIG-IP system retains to prevent the user from reusing a recent password. The default value is 0, and the system allows the range of values from 0 through 127.
  • Minimum Duration specifies the minimum number of days before users can change their password. The default value is 0, and the system allows the range of values from 0 through 255.

    Note: As an administrator, you cannot reset passwords using the Configuration utility while inside the Minimum Duration window.

  • Maximum Duration specifies the maximum number of days that users' passwords are valid. The default value is 99999, and the system allows the range of values from 1 through 99999. If users do not change their passwords by the time they reach the maximum duration, in versions prior to BIG-IP 13.1.0, an administrator must change the users' passwords, and in BIG-IP 13.1.0 and after, users can reset their own passwords.
  • Expiration Warning specifies the number of days prior to password expiration that the system sends a warning message to users. The default value is 7, and the system allows the range of values from 1 to 255.
  • Maximum Login Failures specifies the number of consecutive unsuccessful login attempts the system allows before locking out the user. The default value is 0, which indicates the setting is disabled. The valid range is from 0 through 65535. Locked out users must contact a system administrator to reinstate their access. For more information about managing locked out user accounts, refer to K34556595: Managing the login failures for a local user account on the BIG-IP system.
  • User Lockout (15.x and later) specifies whether to manually reinstate locked out users or automatically reinstate users after a configured number of seconds. The default setting is to manually reinstate locked out users.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have the administrator role or root user access to the BIG-IP system.
  • You have access to the Configuration utility or the TMOS Shell  tmsh.
  • You have command-line access to a Linux system (or an alternate BIG-IP system) that has the curl and jq (command-line JSON processor) utilities installed.

Configuring the password policy using the Configuration utility

To use the Configuration utility to configure the password policy for BIG-IP local user accounts, perform the following procedure:

Impact of procedure: After enforcing new changes to the BIG-IP password policy, attempt to verify the changes using at least one of the affected user accounts, and ensure the system is appropriately enforcing the changes you made to the secure password policy for your environment. When you change the secure password policy, the new configuration values, such as password expiration, do not apply to passwords that were created prior to the policy change. The new policy takes effect when the user changes passwords.

  1. Log in to the Configuration utility.
  2. Go to System > Users > Authentication.
  3. Under Password Policy, locate the Secure Password Enforcement setting and configure it to meet your needs.

    For example, if you want to enable character restrictions, select Enabled in the Secure Password Enforcement list. This extends the setting for the Minimum Length and Required Characters on the configuration page. Retain or change the values for these settings as required.

    If you do not want to enable character restrictions, configure the Secure Password Enforcement setting to its default value, Disabled.

  4. Retain or modify the values for all other settings on Password Policy according to your organization's internal security requirements.
  5. Select Update.

Configuring the password policy using tmsh

To use tmsh to configure the password policy for BIG-IP local user accounts, enter the following commands, as required:

Impact of procedure: After enforcing new changes to the BIG-IP password policy, attempt to verify the changes using at least one of the affected user accounts, and ensure the system is appropriately enforcing the changes you made to the secure password policy for your environment. When you change the secure password policy, the new configuration values, such as password expiration, do not apply to passwords that were created prior to the policy change. The new policy takes effect when the user changes passwords.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. You can modify the following authentication settings to enforce the required secure password policy according to your organization's internal security requirements:
    • To enable or disable the password policy enforcement, use the following command syntax:

      modify /auth password-policy policy-enforcement <enabled | disabled>

      Note: You must enable policy-enforcement for the BIG-IP system to enforce the values you set for password minimum length and/or required characters.

    • To specify the minimum number of characters in a valid password, use the following command syntax:

      modify /auth password-policy minimum-length <value>

    • To specify the settings for required characters, set the value using the following command syntax:
      • For required lowercase characters:

        modify /auth password-policy required-lowercase <value>

      • For required uppercase characters:

        modify /auth password-policy required-uppercase <value>

      • For required numeric characters:

        modify /auth password-policy required-numeric <value>

      • For required special characters:

        modify /auth password-policy required-special <value>

    • To specify the maximum number of days a password is valid, use the following command syntax:

      modify /auth password-policy max-duration <value>

    • To specify the minimum number of days a password is valid, use the following command syntax:

      modify /auth password-policy min-duration <value>

    • To specify the maximum number of login failures before the system locks out the user, use the following command syntax:

      modify /auth password-policy max-login-failures <value>

    • User Lockout (15.x and later). In BIG-IP 15.x and later you can specify whether to manually reinstate locked out users, which is the default setting, or automatically reinstate users after a configured number of seconds. To do either, refer to the following steps.
       
      • To configure the BIG-IP to automatically reinstate users after a configured number of seconds, use the following command syntax:

        modify /auth password-policy lockout-duration <value>
        modify /sys db systemauth.disablemanualunlock value <true | false>

        For example:

        modify /auth password-policy lockout-duration 300
        modify /sys db systemauth.disablemanualunlock value true
         
      • To configure the BIG-IP to manually reinstate users, use the following command syntax:

        modify /sys db systemauth.disablemanualunlock value <true | false>
        modify /auth password-policy lockout-duration <value>

        For example:

        modify /sys db systemauth.disablemanualunlock value false
        modify /auth password-policy lockout-duration 0
         
    • To display the tmsh password policy configurable items, enter the following command:

      modify /auth password-policy ?

  3. To review the full list of settings configured on the BIG-IP password-policy, enter the following command:

    list /auth password-policy all-properties

  4. To save your changes, enter the following command:

    save /sys config

  5. To exit tmsh, enter quit.

Configuring the password policy using iControl REST

To use iControl REST to configure the password policy for BIG-IP local user accounts, you can use the PATCH method to send the JSON data in the following syntax to the /mgmt/tm/auth/password-policy endpoint:

{
  "policyEnforcement": <string>,
  "expirationWarning": <number>,
  "minimumLength": <number>,
  "requiredLowercase": <number>,
  "requiredUppercase": <number>,
  "requiredNumeric": <number>,
  "requiredSpecial": <number>,
  "maxDuration": <number>,
  "maxLoginFailures": <number>,
  "minDuration": <number>
}

Note: Use camel case for the names in the name value pairs to represent the associated tmsh commands. For example, represent policy-enforcement as policyEnforcement. For more information about each name, refer to the related tmsh help entries. Surround the <string> value with quotation marks. For example, "disabled". The <number> value does not require quotation marks.

When you send the JSON data, you can omit properties that you do not need to change from the current configuration. For example, if you set policyEnforcement to "enabled" and this is the only property you want to change, then use the PATCH method to send the following JSON data to disable the password policy:

{
   "policyEnforcement": "disabled"
}

To configure the password policy using iControl REST, perform the following procedure:

Impact of procedure: After enforcing new changes to the BIG-IP password policy, attempt to verify the changes using at least one of the affected user accounts, and ensure the system is appropriately enforcing the changes you made to the secure password policy for your environment. When you change the secure password policy, the new configuration values, such as password expiration, do not apply to passwords that were created prior to the policy change. The new policy takes effect when the user changes passwords.

  1. Log in to the command line of the system with the curl and jq utilities installed.
  2. Use the following command syntax to view the current password policy configuration:

    curl -ksu admin:<password> -H "Content-Type: application/json" -X GET https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/auth/password-policy | jq '.'

    For example:

    curl -ksu admin:testing -H "Content-Type: application/json" -X GET https://ltm1.example.com/mgmt/tm/auth/password-policy | jq '.'

    For example:

    {
      "kind": "tm:auth:password-policy:password-policystate",
