Known Issue

This is the result of a known issue. With certain configurations of RADIUS authentication and dynamic group mapping, when the Session Variable Dump is activated, a user's pre-logon sequence session variables will not be displayed on the Reports: Logons page, under the user's login entry. The Session Variable Dump is activated by selecting the Save user's session variables to Logon Reports check box, which is located on the Device Management: Maintenance: Troubleshooting Tools page.

Typically, when the Session Variable Dump is activated, the entire list (several dozen) of a user's session variables will be seen when an administrator goes to the Reports: Logons page, then clicks on a username in the Logon column. Session variables that are associated with pre-logon sequences and with group mapping are displayed. However, the pre-logon sequence session variables will not display in the Reports: Logons page when all of the following conditions are met:

  • User's login is dynamically mapped through RADIUS in the master group mapping table
  • User's master group from the dynamic group mapping uses RADIUS authentication
  • The RADIUS server for authentication uses the same configuration (name or IP address, port, shared secret) as the RADIUS server that performed the dynamic group mapping

F5 Networks Product Development tracked this issue as CR88976 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Additionally, this issue was fixed in cumulative hotfix HF-601-9 issued for FirePass version 6.0.1 and in cumulative hotfix HF-602-2 issued for FirePass version 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.
