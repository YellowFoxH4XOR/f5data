K6771: NTLM authentication fails when BIG-IP ASM httpclass references a pool

Known Issue

This is the result of a known issue. NTLM-authenticated connections require a private, persistent connection to the backend server. When NTLM authentication requests are processed by a BIG-IP ASM virtual server with httpclasses that contain a referenced pool, the NTLM CHALLENGE packet cannot be forwarded to the client side. As a result, the NTLM authentication process will stall.

F5 Product Development tracked this issue as CR70278, CR70692, and CR70700 and it is fixed in BIG-IP 9.2.4, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP ASM Release Notes.
