Topic

High availability is a built-in feature of the 3-DNS Controller, making it possible to take down a 3-DNS Controller without disrupting service to the wide IP; however, to avoid delays perform the following steps on the 3-DNS Controller before taking the system offline:
  1. Lower the name server TTLs on the NS and A records and allow time for this change to propagate.
  2. Remove the NS record in the parent domain.

Following is a basic interpretation (from DNS & Bind, by O'Reilly) of what happens in DNS (or the 3-DNS Controller) if a server is abruptly taken offline:

Note: In the following example, there are two authoritative nameservers, (ns1 and ns2) at domain.com.

When a DNS is abruptly taken offline, the client makes a recursive query to its local DNS server (LDNS) for the server foo.domain.com.The parent domain returns a list of authoritative name servers for domain.com (ns1 and ns2) to LDNS.

LDNS starts a query with the first NS in the list, for example, ns1. The NS (ns1) responds to the query stating that foo.domain.com is 10.1.1.10. The result is returned to the client. In the meantime, ns2 goes offline.

The client then makes a recursive query to the LDNS for bar.domain.com. The LDNS has cached the IP addresses for ns1 and ns2, and has a round trip time of X for ns1, and 0 for ns2 (since it has not communicated with it yet).

The LDNS tries the authoritative NS with the fastest round trip time, which is ns2. A timeout elapses (usually around 4 seconds) because ns2 is down, then it tries ns1. If ns1 times out as well, the timeout is doubled and the process loops.
