K000161475: iRule with ASM::geo_disable procedure ends up with error in BIG-IP ASM/advanced WAF

Type
Support Solution
Published
2026-07-16
Updated
2026-07-16
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000161475

Description

An iRule using the command ASM::geo_disable returns the following error when applied:

01070151:3: Rule [/Common/bypass_geo_for_specific_url] error: error: [undefined procedure: ASM::geo_disable]

Environment

  • BIG-IP ASM
  • ASM geolocation enforcement
  • Configuration:
    • iRule attached to a virtual server attempting to bypass geolocation enforcement for a specific URI

Cause

The ASM::geo_disable command is not supported in BIG-IP ASM. Geolocation enforcement is configured globally within the ASM security policy and cannot be disabled for individual URIs using iRules.

Recommended Actions

To apply different geolocation behavior to a specific URI, use a separate ASM policy with geolocation checks disabled and select that policy based on the request.

  1. Clone the existing ASM security policy. See the referenced KB for cloning procedure.
  2. Disable geolocation checks in the cloned policy.
  3. Use an LTM traffic policy to select the cloned ASM policy for the required request path.
  4. Alternatively, use an iRule to select the appropriate ASM policy. For example:

    when HTTP_REQUEST {
    if { [string tolower [HTTP::path]] eq "/your-specific-url" } {
    ASM::enable /Common/policy_without_geolocation
    }
    }

  5. If using an LTM traffic policy:
    • Disable the application security policy from the virtual server’s Security > Policies configuration.
    • Attach the LTM traffic policy that performs the ASM policy manipulation.
    • Ensure the traffic policy condition matches the complete path, such as /your-specific-url.
  6. Test and evaluate the configuration in a non-production environment before deployment.
  7. Prefer LTM traffic policies over iRules for better performance and resource management.

Additional Information

  • Geolocation enforcement is global to the selected ASM security policy, not configurable on a per-URI basis within that policy.
  • Selecting a cloned policy changes the security policy applied to the matching request. Ensure all other required security settings are equivalent between the policies.
  • All configuration changes should be thoroughly tested before production deployment.
