K36385016: Inbound ISP link load balancing will use pool members for only one ISP link per data center

Type
Policy
Published
2016-03-04
Updated
2023-03-24
Applies to
  • BIG-IP
  • BIG-IP Link Controller: 12.1.0, 11.6.1, 11.5.4
  • BIG-IP DNS: 12.1.0
  • BIG-IP GTM: 11.6.1, 11.5.4
Source
https://my.f5.com/manage/s/article/K36385016

Policy Information

Important: The new behavior described in this article is the standard behavior for the subsequent major branch. There will be no further updates, unless new information is discovered.

Old Behavior

In BIG-IP Link Controller and GTM 11.5.3, 11.6.0 and prior versions, and BIG-IP DNS 12.0.0, the in-bound ISP link load balancing functionality uses pool members for more than one ISP link per data center.

New Behavior

Beginning in BIG-IP Link Controller and GTM 11.5.4, 11.6.1, and BIG-IP DNS 12.1.0, the ISP link load balancing functionality will use pool members for only one ISP link per data center for each pool.

The link that is associated with the first configured and available pool member within each data center will determine the link that will be used for the data center. The system will use only pool members associated with that link.

F5 Product Development tracked this change as ID 557221.

Impact

The system uses pool members from only one ISP link per data center for each pool. If a pool has multiple members that use different ISP links within a data center, the system uses only pool members associated with the ISP link of the first available pool member.

The system marks pool members associated with subsequent ISP links as unavailable (grey).

If you want to use multiple ISP links per data center in BIG-IP Link Controller and BIG-IP GTM 11.5.4 and later, you may be able to install a software patch by performing the following procedure.

Procedure

Note: Existing customers within the United States who used these EoL load balancing features prior to January 26, 2016, may be eligible to re-enable the functionality. Contact F5 Support to open a case and determine eligibility for acquiring a software patch.

Existing customers outside of the United States should contact F5 Support and open a case to activate this patch if needed.

This patch applies to the following versions of BIG-IP: BIG-IP DNS 12.0.0 and later; BIG-IP Link Controller 11.6.0 HF3, 11.5.1 HF6, or 11.4.1 HF6 and later; and BIG-IP GTM 11.6.0 HF3, 11.5.1 HF6, 11.4.1 HF6 and later.

Once you have acquired the software patch from F5 Support, please complete the following procedures to apply the patch:

Impact of procedure: The BIG-IP system is unable to process traffic while the unit is rebooting.

  1. Copy the patch to the /var/tmp/ directory on the BIG-IP system.
  2. Log in to the BIG-IP command line.
  3. To change directories to the /var/tmp/ directory, type the following command:

    cd /var/tmp/

  4. To install the patch, type the following command:

    im /var/tmp/linkcost.im

    Note: For VIPRION systems, you must run the im command on each individual blade in the VIPRION chassis.

  5. To enable the gtm.loadlinkcost database variable, type the following command:

    tmsh modify /sys db gtm.loadlinkcost value enable

    Notes: For VIPRION systems, you must perform this step from the primary blade in the VIPRION chassis.

Post-patch installation considerations

After installing the linkcost patch, you should be aware of the following maintenance considerations:

  • The patch and database variable setting persist through BIG-IP software upgrades and hotfix installations.
  • If you replace an appliance or VIPRION blade (due to RMA or for some other reason), you will need to perform the following tasks to enable these features on the new unit:
    1. Reapply the patch by running the im command.

      For example:

      im /var/tmp/linkcost.im

      Note: For VIPRION systems, you need to run the im command only on the replacement blade.

    2. After reapplying the patch, type the following commands:

      tmsh modify /sys db gtm.loadlinkcost value disable

      tmsh modify /sys db gtm.loadlinkcost value enable

      Note: For VIPRION systems, you must perform this step from the primary blade in the VIPRION chassis.

      Note: You can alternatively reboot the unit or replacement blade to enable the patch.

      Important: When implementing the patch for vCMP guest instances and the host device, both the vCMP guest instances and the host device will require a reboot.

  • If you add a new blade to your VIPRION chassis, you will need to perform the following tasks to reapply the patch on the new blade:
    1. Reapply the patch by typing the im command on the new blade.

      For example:

      im /var/tmp/linkcost.im

    2. After you reapply the patch, type the following commands on the primary blade in the VIPRION chassis:

      tmsh modify /sys db gtm.loadlinkcost value disable

      tmsh modify /sys db gtm.loadlinkcost value enable

      Note: You can alternatively reboot the replacement blade to enable the patch.
