Description

BIG-IP system is not resetting the client connections while virtual server is reported Offline or Unavailable and Virtual Server property 'Immediate Action On Service Down' is configured to reset. 

Environment

  • BIG-IP LTM
  • Virtual Server
  • CLI

Cause

If tm.rejectunmatched is set to false, the system silently drops unmatched packets (nothing will be write to the log and no RST packet will be sent, it will just drop the packet) or in another words it will respond as in case of drop.

By default, the tm.rejectunmatched BigDB variable is set to true.

Recommended Actions

Set the database variable 'tm.rejectunmatched' to 'true' using below command.

tmsh modify /sys db tm.rejectunmatched value true

Additional Information

The BIG-IP system closes a TCP connection by sending a TCP RST packet to a client when virtual server is reported Offline or Unavailable, if virtual server property 'Immediate Action On Service Down' is configured to reset.
