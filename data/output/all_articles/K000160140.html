K000160140: HA Pairing Failure Between BIG-IPs Due to Incorrect Subnet IP Assignment

Type
Support Solution
Published
2026-05-25
Updated
2026-05-25
Applies to
  • BIG-IP
Source

Description

When building a High Availability (HA) cluster an issue may occur where HA pairing fails due to incorrect subnetting. Specifically, if the HA IP addresses assigned to the devices are not valid host addresses within the subnet (for example, if one device is assigned the network or broadcast address in a /30 subnet), the device will become unreachable and HA communication will fail.

Typical symptoms include:

  • Peer device interfaces repeatedly transitioning from UP to initializing during HA setup.
  • Network connectivity (such as ping) between devices dropping once HA configuration is initiated, even if connectivity was previously confirmed.
  • Devices appearing as Offline in the GUI and HA synchronization not completing.

Environment

  • Product: BIG-IP LTM
  • Network Configuration: HA IP addresses assigned to the devices are not valid host addresses within the subnet

Cause

The HA IP addresses assigned to the system, for example, if both within the same /30 subnet, with one device configured with an invalid host address. In a /30 subnet:

  • Network:   10.0.0.10/30
  • HostMin:   10.0.0.9
  • HostMax:   10.0.0.10
  • Broadcast: 10.0.0.11

The issue comes when one device has assigned an IP address that was not a valid host address within the subnet, causing one device to become offline and preventing proper HA communication between the guests.

Recommended Actions

When configuring HA between BIG-IP systems, ensure proper network connectivity exists between the devices, including:

  • Management and failover VLANs are properly configured
  • No network filtering (firewall, VLAN, or switch ACLs) blocks HA-related traffic
  • Required ports for HA communication are accessible (ICMP, TCP/UDP ports 4353, 6699)

Note: Device trust must be properly established with device certificates imported before attempting HA configuration.

  1. Verify the HA IP address assignments on both BIG-IP systems to ensure they are valid host addresses within the configured subnet
  2. For example, a /30 subnet, only two valid host IP addresses are available (HostMin and HostMax)
  3. Correct the HA IP addresses to use the valid host addresses, considering previous example:
    • Device 1: 10.0.0.9
    • Device 2: 10.0.0.10
  4. After correcting the IP addresses, rebuild the HA configuration
  5. Perform HA sync between the devices
  6. Verify and modify VLANs on the new unit to match those configured on the active unit to ensure successful synchronization
