Known Issue

The BIG-IP system may drop IPSec Encapsulating Security Payload (ESP) response packets due to non-matching Security Parameter Index (SPI). This issue occurs when all of the following conditions are met:

  • A client uses an IP forwarding virtual server to establish an IPsec tunnel connection through the BIG-IP system.
  • The BIG-IP system is not configured to be an IPsec SA endpoint.

When the BIG-IP system forwards an IPsec ESP connection through a forwarding virtual server, Traffic Management Microkernel (TMM) may not identify the response packets. TMM uses the ESP SPI in the connection flow hash to uniquely identify the connection. However, the SPI is not symmetric, and it is likely not the same from client to server as from server to client. If the SPI is changed, TMM will not identify the response as matching existing traffic flow, and TMM will drop the packet.

Impact

Clients are unable to establish an IPsec ESP tunnel connection through the BIG-IP system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Clients are unable to establish an IPsec ESP tunnel connection through the BIG-IP system.
  • The BIG-IP system will drop IPSec ESP response packets.

Resolution

Status

F5 Product Development has assigned ID 373093 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the top right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release11.2.0*K2200: Most recent versions of F5 software
Hotfix11.1.0 HF3*None

*Note: In fixed versions, you can disable IPsec SPI lookup in order to allow the response packets with a non-matching SPI to be passed back to the client. IPsec SPI lookup is disabled by default in 11.1.0 HF3. For information, refer to K14169: Passing IPsec ESP traffic through an IP forwarding virtual server.

Workaround

To work around this issue without disabling IPsec SPI lookup, you can configure an additional IP forwarding virtual server that will accept the response packets as a new connection flow.
