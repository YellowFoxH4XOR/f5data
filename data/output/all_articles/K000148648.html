K000148648: NGINX Rewrite to Disable URI Decoding

Type
Support Solution
Published
2024-12-18
Updated
2025-03-24
Applies to
  • NGINX Products
  • NGINX Plus: R32
Source
https://my.f5.com/manage/s/article/K000148648

Description

You are encountering an issue where, by default, NGINX decodes the URI when passing it to the upstream group. However, you want the original, undecoded URI to be passed to the upstream server. Your goal is to configure NGINX to pass the original URI to the upstream server, maintaining its encoded form.

For example:

  • An incoming end-user request is: https://example.com/hello/sso/verify/%5Btenant%5D
  • You want the final request URI, after rewriting, to be passed to the upstream server as: /sso/verify/%5Btenant%5D

 

Environment

  • NGINX Plus
  • Rewrite Directive
  • Map Variable

 

Cause

By default, NGINX decodes the URI when sending the request to the upstream or backend server. This behavior can cause issues if the original, encoded URI is required by the upstream server for proper processing.

 

Recommended Actions

You can achieve this by using either of the following methods: two rewrite directives or defining a map variable.

  • Using Two Rewrite Directive
server {

  rewrite ^ $request_uri;

  location /<custom_path> {
        rewrite /<custom_path> $1 break;
        proxy_pass http://<upstream_group>$1;
     }
}
  • Defining a map variable
map $request_uri $extracted_path {
    ~^/<custom_path> $1;
}

server {
    ....
    location /<custom_path> {
        proxy_pass http://<upstream_group>$extracted_path;
    }
}
