Known Issue

The BIG-IP high availability (HA) peer device displays fully-qualified domain name (FQDN) ephemeral nodes in the Offline state.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP devices are configured for HA.
  • The synchronization device group is configured with automatic synchronization.
  • You configure an FQDN node on the active BIG-IP device.
  • The FQDN ephemeral node is populated and displays as Available.
  • You set the FQDN node to the Force Offline state.
  • You enable the FQDN node.

Impact

The standby BIG-IP HA device displays the FQDN ephemeral node as Offline.

Note: This issue corrects when the standby BIG-IP HA device becomes the active BIG-IP HA device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing the FQDN ephemeral node state using the Configuration utility or the TMOS Shell (tmsh), the node state on the standby BIG-IP device is Offline. 
  • When viewing the FQDN ephemeral node state using the Configuration utility or tmsh, the node state on the active BIG-IP device is Available.
  • After a failover event to the BIG-IP standby device, the FQDN ephemeral node state changes to Available when the device becomes active.

Workaround

To work around this issue, you can set the FQDN node to the Disabled state rather than the Force Offline state. Alternatively, you can configure the node without using the Address FQDN setting. 

Impact of workaround: Performing the suggested workaround will require a static IP address for the new node configuration when using the Address setting (the node address will not be dynamically acquired through DNS).
