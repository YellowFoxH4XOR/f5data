Description

Saving the UCS file fails with the error:

Waiting for process config_save (pid:<num>) to complete.

In this error message, <num> is the number of process IDs (PIDs) running on the BIG-IP system.

Environment

  • No orphaned UCS save processes
  • Process Id <num> does not exist but saving the UCS file still fails with the same error.
  • Zombie processes are running
You can see the zombie state process count by the following 'top' command:

top - 09:44:48 up 25 min,  1 user,  load average: 0.78, 0.60, 0.60
Tasks: 344 total,   2 running, 338 sleeping,   0 stopped,   4 zombie 
%Cpu(s):  6.5 us, 12.9 sy,  0.0 ni, 80.6 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
KiB Mem :  8177364 total,    58448 free,  7048648 used,  1070268 buff/cache
KiB Swap:  1023996 total,  1022556 free,     1440 used.   757156 avail Mem

Cause

The zombie process exists and causes UCS save process stuck.

Recommended Actions
Please find out which daemon is zombie process and restart it to release zombie statue, perform the following procedure:

Impact of workaround: Restarting/killing any daemon on the BIG-IP system may cause service disruption, and F5 recommends performing this procedure only during a scheduled maintenance period.

1. Verify the zombie process and PID its parent process using the following command:
Note: you might see the pid:<num> matches the defunct process ID(ex: 16672). In most cases, tmsh daemon is a zombie process and its parent process is syscalld. 

  • Check zombie process : 
    • ps aux| grep -i defunct

You might see the output such as below:
root     16672  0.0  0.0      0     0 ?        Z    13:28   0:00 tmsh <defunct>

  • Check parent process of zombie process: 
    • ps --forest | grep -B1 <process name>*defunct

For example:
ps --forest | grep -B1 tmsh.*defunct

2. Kill the zombie process and see if it clears the defunct and restart the daemon. <pid> is zomibe proecess or its parent process.

  • kill -9 <pid> 

for example:
kill -9 16672 
kill -9 <its parent pid>

  • ps aux| grep -i defunct

3.  If you still see the defunct process and restart is not working properly, please restart the associated daemon using the following commands: 

  •  tmsh restart /sys service <service daemon> 

for example:
tmsh restart sys service syscalld 

4. If you can not point out the parent process of the zombie process, you can restart all services or Reboot the system.
