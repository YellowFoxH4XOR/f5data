K000139614: The limit_except directive breaks if conditions in a location block

Published
2024-05-14

  • NGINX Open Source
  • NGINX Plus: R13, R14, R15, R16, R17, R18, R19, R20, R21, R22, R23, R24, R25, R26, R27, R28, R29, R31, R30
Source

Description

An if directive within a location block does not execute during request processing when a limit_except directive is implemented within the same location block. Example configuration: 

server {
  ...
  location ~* /test {
    limit_except OPTIONS {
      # nothing
    }
    if ( $request_uri = "/test1" ) {
      proxy_pass {scheme}://test1_upstream;
    }
    proxy_pass {scheme}://test2_upstream;
  }
}

With the above configuration a request with uri /test1 (and any request method other than OPTIONS) should go to test1_upstream as the if directive would evaluate to true. However, with the presence of the limit_except directive the if directive does not get processed and the request actually goes to test2_upstream.

Environment

NGINX [Plus]

Cause

Rewrite module directives, such as if, rewrite, set, etc., are not inherited into the limit_except block

Recommended Actions

Avoid implementing if + limit_except directives within a location block. For example, following the example above, replace the if directive with mapping:

map $request_uri $backend {
  /test1    test1_upstream;
  default   test2_upstream;
}
server {
  ...
  location ~* /test {
    limit_except OPTIONS {
      # nothing
    }
    proxy_pass {scheme}://$backend;
  }
}
