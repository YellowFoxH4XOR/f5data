Description

You have an r2000 or r4000 series appliance which has CPU cores shared by the F5OS host and by the running tenants. You want to monitor CPU usage via SNMP to catch instances of CPU starvation with potential impact to host and tenant.

Environment

  • r2000 or r4000 series appliances
  • F5OS-A
  • SNMP CPU monitoring

Cause

None

Recommended Actions

Monitoring F5-PLATFORM-STATS-MIB:cpuCoreStatsTable is better able to highlight CPU contention but does not necessarily indicate impact.

Monitoring F5-PLATFORM-STATS-MIB:cpuUtilizationStatsTable on the other hand will hide instances of heavy contention (on an 8-core system, 4 cores at 100% and 4 cores at 0% will show up as 50% usage) but will be more indicative of an actual issue if cpuTotal1minAvg approaches 100%.

If the intention is to gather statistics for historical logging then capturing both cpuTotal1minAvg and coreTotal1minAvg will maximise the amount of data available to correlate against.

If the intention is to raise actionable alerts then monitoring coreTotal1minAvg as it approaches 100% will help to reduce alert noise.

Occasional 100% CPU usage does not always indicate impact. Customers interested in measuring impact should define what the indicators of impact relevant to their application(s) are (ie. throughput, latency, time to first byte, etc) and monitor those metrics directly rather than rely on F5OS CPU utilisation as an indicator of impact.
