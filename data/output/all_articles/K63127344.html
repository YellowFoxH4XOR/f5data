Description
After upgrading to specific BIG-IP versions, existing public key authentication (passwordless login) from a ssh client with DSA key fails when attempt to log into the BIG-IP.

Environment

  • Configured public key authentication between a ssh/sftp client and the BIG-IP using DSA key type.
  • Upgrading to the BIG-IP version that has a fix for CVE-2020-5917.  See the fixed version in K43404629.

Cause
Due to the known vulnerability CVE-2020-5917 (K43404629), 1024-bit digital signature algorithm (DSA) keys was disabled in specific BIG-IP versions, which causes the previously working public key authentication with DSA key to fail.

Recommended Actions

  • 1024-bit DSA keys are no longer considered secure.  F5 strongly recommends using RSA keys that are 2048-bit or longer.  Please consider re-configure public key authentication using RSA 2048-bit keys.
     
  • If reconfiguring public key authentication with a new RSA key is not an option and if you still want to use the existing DSA key that is insecure, you can follow the steps below;

    1.  Log in to tmsh by entering the following command:

      tmsh


    2.  Modify sshd configuration to add dsa key types using the following command:

         modify sys sshd include "pubkeyacceptedkeytypes +ssh-dss"


    3.  List sshd configuration to confirm dsa key type has been added:

         list sys sshd all-properties


    The command output appears similar to the following example:

    (tmos)# list sys sshd all-properties
    sys sshd {
        allow { ALL }
        banner disabled
        banner-text none
        description none
        fips-cipher-version 0
        inactivity-timeout 0
        include "pubkeyacceptedkeytypes +ssh-dss"
        log-level info
        login enabled
        port 22
    }


    4.  restart sshd using the following command:

         restart sys service sshd


    Existing public key authentication with DSA key should work after following the steps above.
