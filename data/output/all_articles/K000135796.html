K000135796: pkcs11d does not initialise after upgrade

Type
Support Solution
Published
2023-08-09
Updated
2026-01-30
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000135796

Description

pkcs11d does not initialise after upgrade.
In the ltm logs, the following was seen:

Re-starting pkcs11d
Attach error.
pkcs11d daemon initialization error.

Environment

  • Using Luna Safenet HSM
  • Upgraded from 15.1.6.1 to 15.1.9.1
  • Before upgrade, vendor was changed to "auto" in HSM configuration

Cause

Before the upgrade, due to some issues, vendor was switched to auto.
After upgrade, the bigip.conf was updated to:

sys crypto fips external-hsm {
num-threads 20
pkcs11-lib-path /usr/safenet/lunaclient/lib/libCryptoki2_64.so
vendor auto
}

The upgrade script checks the value of "vendor" and if it is correctly set to "safenet" it creates some files and directories. If it is set to "auto" these files do not exist after upgrade.

Recommended Actions

Option 1:

  1. Rollback to the previous version
  2. Set the "vendor safenet"
  3. Upgrade again

Option 2:

  • Reinstall Safenet Luna client software after upgrade
