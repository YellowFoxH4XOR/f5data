Known Issue

TMM may restart and produce a core file when a FastL4 virtual server has connection mirroring enabled.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured to use a FastL4 profile.
  • The virtual server has connection mirroring enabled.

Impact

Service will be interrupted as TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H493226 on the Diagnostics > Identified > Medium|High screen.
  • The BIG-IP system may fail to process traffic for a brief period.
  • The BIG-IP system may fail over to another host in the device group.
  • TMM generates a core file in /var/core.

Workaround

To work around this issue, you can change the virtual server type to either Forwarding (Layer 2) or Standard. To do so, perform the following procedure:

Impact of workaround: This procedure could impact traffic processing and should be performed only during a maintenance period.

  1. Log in the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Select the FastL4 virtual server by name.
  4. Under the General Properties section, change the type to either Forwarding (Layer 2) or Standard.
  5. Select Finished.

For more information about virtual server types, refer to K14163: Overview of BIG-IP virtual server types (11.x).
