Known Issue

Standard virtual servers may not properly close TCP connections that are closed simultaneously.

This issue occurs when the following condition is met:

  • The configuration contains a Standard virtual server with a TCP profile.
  • The BIG-IP system and the remote endpoint simultaneously close a TCP connection.

Due to this issue, during a simultaneous close, the BIG-IP system may send a second FIN after receiving a FIN from a client or server. A network device that strictly enforces Internet Engineering Task Force (RFC 793) behavior may reject the second FIN, which may prevent the connection from closing cleanly.

According to RFC 793, a simultaneous close occurs when both endpoints of a TCP connection send a FIN before receiving a FIN from the other. After this, each endpoint should send only an ACK.

Impact

The client connection may be terminated without a clean connection closure.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H429340 on the Diagnostics > Identified > Medium screen.
  • From a traffic capture, you observe that when simultaneously closing TCP connections, the BIG-IP system responded with a FIN-ACK, to a FIN that it received from the client, followed by a subsequent FIN.
  • The client connection is terminated without a clean connection closure.

Workaround

There is no workaround for this issue. However, depending on your application environment, you may be able to mitigate this issue by changing the affected virtual server from a Standard virtual server to a virtual server type that uses a FastL4 profile instead of a TCP profile. F5 recommends that you test changes during a maintenance window, and consider the possible impact on your specific environment.

  • For more information about when to use the different virtual server types, refer to BIG-IP Local Traffic Manager: Implementations.
