Topic

You should consider using this procedure under the following condition:

  • You want to configure NT LAN Manager (NTLM) single sign-on (SSO) to authorize BIG-IP APM users to access protected resources.

Description

In NTLM SSO, the BIG-IP APM system first authenticates users by requesting their credentials once and thereafter reusing the cached identity to seamlessly log the user in to the secured web applications. The main components of NTLM SSO on the BIG-IP APM system, apart from the virtual server, are the following:

  • An NTLM SSO configuration object
  • An initial authentication mechanism to first identify the user. For example a logon page with Active Directory (AD) authorization.
  • A resource that calls the NTLM SSO object. For example, an access profile, an iRule (WEBSSO::select command), a portal access resource, an Exchange profile, and so on.

    This article describes how to configure a portal access resource to call the NTLM SSO object.

  • An SSO credential mapping assignment in an access policy

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility of the BIG-IP APM system.

Procedures

  • Create an NTLM SSO object
  • Create a portal access resource with NTLM SSO
  • Create an access profile with an access policy with SSO credential mapping
  • Create a virtual server
  • Enable NTLM authentication on your web application

To watch a video demo of some of these procedures, go to  Configure BIG-IP APM NTLM SSO for portal access.

Create an NTLM SSO object

In BIG-IP APM, you can create either an NTLMv1 or NTLMv2 SSO object. If your application server supports both, F5 recommends using NTLMv2 as it is more secure than NTLMv1. To create an NTLMv2 object, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Single Sign-On > NTLMV2.

    Note: For BIG-IP 12.x, go to Access Policy > SSO Configurations > NTLMV2.

  3. Select Create.
  4. Enter a name for the object.
  5. For Username Conversion, select the Enable check box if your users are entering PREWIN2k/UPN username formats in a logon page. For example, enabling this converts domain\username or username@domain to username.
  6. For NTLM Domain, enter the domain. For example:

    example.com

  7. Select Finished.

Create a portal access resource with NTLM SSO

In this article, you are configuring a portal access resource with the NTLM SSO resource. Note that you can also call the NTLM SSO resource by associating it to your access profile or using an iRule. To configure the portal access resource, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Connectivity / VPN > Portal Access > Portal Access Lists.

    Note: For BIG-IP 12.x, go to Access Policy > Portal Access > Portal Access List.

  3. Select Create.
  4. Enter a Name for the resource.
  5. For Link Type, select Application URI
  6. For Application URI, enter the URI of the web application on your server. For example:

    https://exchange.example.com/owa

  7. Select Create
  8. For Resource Items, select Add to add the NTLM SSO object you created in the previous procedure as a resource item.
  9. Under New Resource Item, for Link Type, select Paths.
  10. For Destination, for Host Name enter either the application server's hostname or IP address. For example:

    exchange.example.com

    Note: If you enter an FQDN, it must be resolvable by DNS on the BIG-IP system.

  11. For Paths, enter a path or list of paths separated with spaces that you want the BIG-IP APM system to trigger NTLM SSO. For example:

    /owa*

  12. For SSO Configuration, select the NTLM SSO object you created earlier.
  13. Select Update/Finished.
  14. Create a webtop to host the portal access resource by navigating to Access > Webtops > Webtop Lists.

    Note: For BIG-IP 12.x, go to Access Policy > Webtops.

  15. Select Create.
  16. Enter a name for the webtop.
  17. For Type, to host a portal access resource, select either Full or Portal Access. Select Full when you need to host other resources on the webtop.

    Note: If you select Portal Access, for Link Type, select Application URI and enter the the URI you used in step 6.

  18. Select Finished.

Create an access profile with an access policy with SSO credential mapping

In SSO, the BIG-IP APM system caches credentials in an APM session variable. To enable this, you need to include the SSO credential mapping assignment object in your access policy. For more information refer to K11629: Configuring single sign-on credentials using session variables from the Logon page.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Profiles / Policies > Access Profiles (Per-Session Policies).

    Note: For BIG-IP 12.x, go to Access Policy > Access Profiles > Access Profiles List.

  3. Select Create
  4. Enter a name for the access profile.
  5. For Profile Type, select All.
  6. Under Language Settings, select one or more languages in the Factory Builtin Languages list and move it to the Accepted Languages list.
  7. Select Finished.
  8. For the access profile you just created, in the Per-Session Policy column, select Edit to modify the policy in the Visual Policy Editor (VPE).
  9. On the fallback branch, select the Add icon (+).
  10. On the Logon tab, select Logon Page and select Add Item.
  11. Make any changes appropriate for your environment, and select Save.
  12. On the fallback branch of the Logon Page policy item, select the Add icon (+).
  13. Select the Authentication tab and add an appropriate authentication mechanism. For example, AD Auth.
  14. Select Add Item, make any appropriate configuration changes to the properties, and then select Save.
  15. On the Successful branch of your authentication policy agent, select the Add icon (+).
  16. Select the Assignment tab, select SSO Credentials Mapping , and select Add Item.
  17. Do not implement any change to the properties, and then select Save.
  18. On the Successful branch of your SSO Credential Mapping policy agent, select the Add icon (+).
  19. Select the Assignment tab, select Advanced Resource Assign , and select Add Item.
  20. Select Add new entry, then select Add/Delete.
  21. Select the Webtop tab and select the webtop you created earlier.
  22. Select the Portal Access tab and select the portal access resource that you created earlier.
  23. Select Update then select Save.
  24. On the fallback branch of the Advanced Resource Assign policy item, select the Deny endpoint, select Allow and select Save.
  25. Select Apply Access Policy .

Create a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create, and enter a name for the profile.
  4. For Destination Address/Mask, type the virtual server IP address.
  5. For Service Port, type 443 or select https.
  6. For the SSL Profile (Client) and SSL Profile (Server), select the appropriate profiles. For example, clientssl and serverssl.
  7. For HTTP Profile, select an appropriate HTTP profile. For example, http
  8. For Source Address Translation, select Auto Map if your environment requires it.
  9. For Rewrite Profile, select rewrite.
  10. Under Access Policy , for Access Profile, select the access profile you created in the Creating an access profile with an access policy with SSO credential mapping procedure.
  11. For Connectivity Profile, select an appropriate profile. If you do not have one, select the + icon to create a new one.
  12. Select Finished.

Enable NTLM authentication on your web application

For the BIG-IP APM system to authenticate on your behalf with your web server application, you need to enable NTLM authentication on your web application. For example, on Microsoft IIS server, you need to enable Windows Integrated Authentication with Negotiate and/or NTLM for the virtual directory of your web application. Depending on your web application, the steps may differ. For example, in Microsoft Outlook Web Access (OWA), it is recommended that you make the changes using Exchange Control Panel (ECP). For the specific steps to enable NTLM authentication, refer to your Microsoft documentation.
