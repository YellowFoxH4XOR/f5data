Issue

Error:  {"code":404,"message":"01020036:3: The requested self IP (/Common/<self_IP_name>) was not found.","errorStack":[],"apiError":3}

In this error message, note the following:

  • <self_IP_name> is the name of an affected self IP. 
For example:
Error: {"code":404,"message":"01020036:3: The requested self IP (/Common/<self_1>) was not found.","errorStack":[],"apiError":3}
Error in failover: {"code":404,"message":"01020036:3: The requested self IP (/Common/<self_1>) was not found.","errorStack":[],"apiError":3}

Message Location

You may encounter this message in the following location[s]:

  • /var/log/cloud/azure/cluster.log

Description

This message occurs when the following condition is met:

  • You fail to assign a self IP address to the BIG-IP device, because you made an error in assigning the time zone in the deployment template.

    Before you deploy your BIG-IP device, when you select an invalid time zone in the deployment template, you fail to assign a self IP address to the BIG-IP device. You can select an invalid time zone by doing one of the following:

    • You enter an incompatible time zone into the deployment template field for TIMEZONE.
    • You use the incorrect case when you enter the time zone into the deployment template field for TIMEZONE.

    When you enter an invalid time zone, it may result in an network time protocol (NTP) failure, which causes the system to fail to assign the self IP address to the BIG-IP device. As a result, you may encounter additional error messages similar to the following in the /var/log/cloud/azure/onboard.log and /var/log/ltm files:

    Note: In these error messages, <TIMEZONE> is the time zone that you entered incorrectly in the deployment template.

    • debug: [pid: 18059] [lib/bigIp.js] modify 10.10.10.10 /tm/sys/ntp {"servers":["0.pool.ntp.org"],"timezone":"<TIMEZONE>"}
    • info: [pid: 18059] [scripts/onboard.js] Setting up NTP. verbose: [pid: 18059] [lib/util.js] tryUntil error: 01070920:3: Application error for confpp: <TIMEZONE> is not a valid time zone.
    • debug: [pid: 18059] [lib/bigIp.js] modify 10.10.10.10 /tm/sys/ntp {"servers":["0.pool.ntp.org"],"timezone":"<TIMEZONE>"}
    • verbose: [pid: 18059] [lib/util.js] tryUntil error: MCP Session terminated tries left: 89
    • err mcpd[4939]: 0107146f:3: Self-device config sync address cannot reference the non-existent Self IP (10.10.10.10); Create it in the /Common folder first.

Impact

When you deploy your BIG-IP device and enter an invalid time zone, it may cause an NTP failure and the system may not properly assign the self IP address. The missing self IP address may cause the high availability (HA) failover functionality to fail in the deployment.

Recommended Actions

  • Find the desired time zone from https://github.com/F5Networks/f5-azure-arm-templates/blob/master/azure-timezone-list.md
  • Update the deployment template with a valid time zone and redeploy the BIG-IP instance.
    Note: The time zone is case sensitive.
