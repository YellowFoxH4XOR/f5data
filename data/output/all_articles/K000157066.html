K000157066: WHAT ARE EFFECTS OF PREFECTH FEATURE ON CPU, AND HOW CAN PERFORMANCE BE BENCHMARKED

Type
Support Solution
Published
2025-10-20
Updated
2025-10-20
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.2
Source
https://my.f5.com/manage/s/article/K000157066

Description:


Enabling the DNS Prefetch feature on BIG-IP DNS systems can affect CPU and memory utilization. The Prefetch function proactively refreshes DNS cache entries before their TTL expires, aiming to reduce DNS resolution latency and increase cache hit rates. In high-traffic environments or on VIPRION platforms with multiple blades, enabling DNS Prefetch may result in higher than expected CPU usage. No specific error messages are generated, but performance metrics such as TMM CPU and memory utilization may increase.

Environment:

  • Product: BIG-IP DNS
  • Version: 17.1.2
  • Hardware: VIPRION 4450 Blades, VIPRION 2250 Blades
  • Feature: DNS Prefetch enabled in DNS cache profile
  • Typical deployment: Multi-blade VIPRION chassis, high DNS query volume

Cause:


Enabling DNS Prefetch causes the system to proactively refresh cached DNS records when a query is received within the last 10% of the record’s TTL. On VIPRION systems with two or more blades, this can lead to increased CPU usage due to how DNS cache synchronization and processing are handled across blades.

Recommendations:

  • Enable DNS Prefetch initially on a test or non-production system to evaluate impact.
  • Monitor TMM CPU and memory utilization, as well as DNS cache hit rates, before and after enabling Prefetch.
  • Use built-in BIG-IP statistics and graphs to track performance metrics:
    • TMM CPU: <70% (normal), 70–85% (medium), ≥85% (critical)
    • TMM memory: <85% (normal), 80–95% (medium), ≥95% (critical)
  • Adjust DNS cache size as needed. Start with a few hundred MB, monitor cache hit rates, and avoid over-provisioning to prevent unnecessary memory consumption.
  • Be aware of the known issue where using DNS cache on VIPRION systems with multiple blades can cause higher than expected CPU usage.
  • If performance degradation is observed, consider reducing cache size, disabling Prefetch, or further segmenting DNS workloads.
  • Regularly review system resource usage during peak traffic periods.
