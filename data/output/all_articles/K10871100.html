K10871100: Configuration fails to load when default clientssl profile contains cert-key-chain default_default

Type
Knowledge
Published
2019-07-24
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.0, 12.1.2, 11.5.4
  • BIG-IP APM: 12.1.2, 11.5.4, 13.1.0
Source
https://my.f5.com/manage/s/article/K10871100

Issue

Description

Configuration (bigip.conf file) fails to load when default clientssl profile contains cert-key-chain default_default. The following error displays:

010717e1:3: Client SSL profile cannot contain more than one set of same certificate/key type

You may encounter this message in the following locations:

  • /var/log/ltm
  • console

Environment

  • /var/log/ltm error
  • bigip.conf file
  • Client SSL profile

Cause

This error occurs when the default Client SSL profile chain is modified with the following command syntax:

tmsh modify ltm profile client-ssl clientssl chain <new certificate chain cert>.crt

Recommended Actions

Examining the default Client SSL profile

  1. Enter the following command on the BIG-IP system:

    tmsh list ltm profile client-ssl clientssl

  2. Verify the default Client SSL profile contains the following syntax:

    cert-key-chain {
            default_default {
                cert default.crt
                chain <certificate file>.crt
                key default.key
            }
        }
        chain <certificate file>.crt

  3. If you see default_default, perform the following steps to recover:
    1. Create backup of /config/bigip.conf file using the following command syntax:

      cp /config/bigip.conf /config/bigip.conf<solution article number>
      vi /config/bigip.conf

    2. Modify default_default to default using the following command syntax:

      delete chain /Common/<certificate file>.crt
      delete chain <certificate file>.crt

    3. Exit and save the edited file using the following command:

      wq

    4. Enter tmsh load sys config to verify error is gone.

Additional Information??????

The previously described error can occur with other certificates, not just the default.  If it occurs with other certificates, you can adjust the process to the relevant certificate.  The following example uses the certificate globalsign_20190222_globalsign_20190222.

  1. Using CLI, create backup of /config/bigip.conf file using the following command:

    cp /config/bigip.conf /config/bigip.confK10871100

  2. Edit configuration file using the following command:

    vi /config/bigip.conf

  3. Find ltm profile client-ssl /Common/profile_clientssl_example. For example:

    replace globalsign_20190222_globalsign_20190222 with globalsign_20190222
    delete chain /Common/globalsign_20190222.crt
    delete cert /Common/globalsign_20190222.crt
    delete key /Common/globalsign_20190222.key

  4. Exit and save the edited file using the following command:

    wq

  5. Using CLI, load configuration using the following command:

    tmsh load sys config

  6. Try to load the certificate chain again.
