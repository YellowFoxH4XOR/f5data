Description

You upload a yaml file with custom responses but APM sends the default response when you access the APM VS.

Environment

APM deployed with API Protection.

Cause

The start line of an HTTP response (Status Line) contains the protocol version, status code and status text.

Per RFC7230, that Status Line should be one line (HTTP-version SP status-code SP description CRLF)

Adding "|" as first character in the description inside the yaml file makes openapi parser on APM to save the Description object using multi-lines instead of one line.

This makes "http_parse_response" on APM to fail with an Illegal value error when building the response so it sends the default response instead.

    401:
     description: |
      _Unauthorized_
      <ul>
      <li>No authentication token provided</li>
      </ul>
     content: {}

Recommended Actions

Removing all "|" in the response Description object inside the yaml file.
