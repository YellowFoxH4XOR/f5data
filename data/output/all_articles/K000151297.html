Security Advisory Description

On BIG-IP systems, undisclosed traffic can cause data corruption and unauthorized data modification in protocols which do not have message integrity protection. (CVE-2025-58424)

Impact

This vulnerability may allow a remote, unauthenticated attacker to inject malicious data into active TCP connections which do not have message integrity protections, such as Transport Layer Security (TLS). There is no control plane exposure; this is a data plane issue only.

Security Advisory Status

F5 Product Development has assigned ID 1617249 (BIG-IP) to this vulnerability. This issue has been classified as CWE-340: Generation of Predictable Numbers or Identifiers.

To determine if your product and version have been evaluated for this vulnerability, refer to the Evaluated products box. Security Advisory Recommended Actions

If you are running a version listed in the Versions known to be vulnerable column, you can eliminate this vulnerability by installing a version listed in the Fixes introduced in column and enabling the tm.tcpstopblindinjection database variable. If the Fixes introduced in column does not list a version for your branch, then no update candidate currently exists for that branch and F5 recommends that you upgrade to a version with the fix (refer to the tables) and enable the tm.tcpstopblindinjection database variable.

If the Fixes introduced in column lists a version prior to the one you are running, in the same branch, then your version should have the fix, however, you still need to enable the tm.tcpstopblindinjection database variable to mitigate the issue.

Mitigation

To mitigate this issue, in addition to installing a fixed version, you must also enable the tm.tcpstopblindinjection database variable. This database variable implements Request for Comment 5961 (RFC5961) section 5 protection but is disabled by default. To enable the database variable, perform the following procedure:

Impact of action: Enabling the tm.tcpstopblindinjection database variable may slightly increase latency and CPU usage on Traffic Management Microkernel (TMM) during typical traffic levels but could further increase under high connection rates or heavy traffic flow.

Important: F5 Product Engineering has identified an issue that affects some connection types like SMTP where the server side sends data first, causing the server data to be dropped. F5 has assigned ID 2132165 to this issue. If you experience connection issues after enabling this DB key, F5 recommends disabling it until the fix is available.

  1. Log in to the TMOS Shell (tmsh) by entering the following command from the Advanced Shell (bash):

    tmsh

  2. To enable the tm.tcpstopblindinjection database variable, enter the following command:

    modify /sys db tm.tcpstopblindinjection value enable

  3. Verify the change by entering the following command:

    list /sys db tm.tcpstopblindinjection

    Output should appear similar to the following example:

    sys db tm.tcpstopblindinjection {
    value "enable" }

To further mitigate this vulnerability for affected F5 products, you should ensure TCP connections in the data plane are protected using protocols that provide message integrity, such as TLS. For more information about securing data plane traffic, refer to the following articles:

  • K000133414: Best practices for maintaining secure SSL/TLS deployments
  • K01770517: Configuring the cipher strength for SSL profiles (14.x - 17.x)
