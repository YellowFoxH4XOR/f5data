K000164292: Incorrect X-Forwarded-For Values in ASM Remote event log

Type
Support Solution
Published
2026-11-18
Updated
2026-11-23
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.3, 17.5.1, 21.1.0
Source
https://my.f5.com/manage/s/article/K000164292

Description

When you use ASM remote logging and enabled the x_forwarded_for_header_value field, the Syslog message can show the X-Forwarded-For (XFF) value from a previous HTTP request instead of N/A when the current request has no XFF header.

  • Trigger: A request containing an X-Forwarded-For header is followed by a request without one.
  • Expected behavior: The x_forwarded_for_header_value field is logged as N/A.
  • Actual behavior: The XFF value from the preceding request is logged.

Example remote Syslog entry showing the issue (addresses masked):

ASM:"2026-11-17 17:30:34","passed","16874577007315255320","/Common/HTTP_VS","/Common/ASM_policy",...,"GET /index.html HTTP/1.1 ... (no X-Forwarded-For header) ...","/index.html","<previous XFF value>","404"

Environment

  • Product: BIG-IP ASM
  • Version: BIG-IP 17.5.1.11
  • Feature: Security log profile (remote logging) with x_forwarded_for_header_value in the format fields, logger-type remote, remote-storage remote, protocol udp
  • Client traffic: HTTP requests with and without an X-Forwarded-For header in sequence

Cause

Bug ID 2547761: ASM remote logging may record the X-Forwarded-For value from a previous request.

Recommended Actions

No workaround prevents the issue in the remote logging path. A fix is available through an engineering hotfix (EHF) for Bug ID 2547761. Contact F5 Support to request the EHF for your version.

The following mitigation was validated :

  1. Enable the Insert X-Forwarded-For option in the HTTP profile used by the virtual server.
  2. Keep the remote log profile with the x_forwarded_for_header_value field as configured.
  3. Verify the Syslog output. Requests that already contain an XFF header have the client source IP appended to it. Requests without an XFF header have the header inserted with the client source IP. In both cases, the logged value is correct.

Side effect: The X-Forwarded-For header may contain multiple comma-separated IP addresses. Use the first IP address in the list as the originating client IP when parsing logs.

Additional Information

  • Expected behavior: The x_forwarded_for_header_value field shows N/A when the request has no XFF header.
  • Actual (defective) behavior: The field shows the XFF value from the previous request.
  • Affected versions: The issue affects later releases beginning with 17.1.3.5 and 17.5.1.9. Verify against the Bug ID 2547761 bug tracker entry for the specific version.
  • Side effect of the mitigation: Multiple IPs in the XFF header; use the first IP as the client reference.
