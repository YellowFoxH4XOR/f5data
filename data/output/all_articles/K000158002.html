K000158002: After Update to 17.x iRules containing only comment lines (#) will be empty

Type
Support Solution
Published

Applies to

  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000158002

Description

After upgrading BIG-IP LTM systems to version 17.5.1.3, iRules that contain only comment lines (lines beginning with "#") may become empty and are no longer visible in the GUI or via tmsh. iRules containing both comments and executable code retain their content as expected. This issue is particularly relevant for environments using comment-only iRules for documentation or change tracking.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1.3 (and likely other 17.x releases)
  • Configuration: iRules used for documentation purposes (comment-only)
  • Condition: Occurs after software upgrade or configuration load

Cause

Bug ID 490139

Recommended Actions

To prevent comment-only iRules from being emptied during upgrades or configuration loads, add a minimal event block to each affected iRule:

  1. Edit each comment-only iRule to include the following at the end:

    # comment 
    # comment 
    when RULE_INIT { return } 

  2. Save and deploy the updated iRule.

Note: The RULE_INIT event is executed only once when the iRule is loaded and does not introduce runtime overhead for each connection.

Additional Information

  • Comment-only iRule content may still exist in the configuration file (/config/bigip.conf) after upgrade but will not be displayed in GUI or tmsh unless this workaround is applied.
  • Only comment-only iRules are affected; those with executable code remain intact.
  • The recommended workaround preserves documentation without impacting system performance.
