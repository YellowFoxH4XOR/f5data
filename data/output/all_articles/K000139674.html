Description

A virtual-server making use of httprouter and http2 profiles is meant to load-balance http requests (including http2) to a pool of servers.

There are situations where uneven load-balancing will occur - so some pool members might receive a lot more traffic than others.


Environment

One example of the above problem is when a single client sends towards the virtual-server many http2 requests under the same TCP connection. Even though the virtual-server might point to a pool with many pool members, only a single pool member will receive all traffic.


Cause

The BIG-IP load-balances based on TCP connection rather than on HTTP request.

With http1 it is possible to make the BIG-IP load-balance based on HTTP request (rather than TCP connection) via oneconnect profile (or LB::detach command, under an iRule) but this is not compatible with httprouter/http2.

An RFE exists for this (ID1018265).


Recommended Actions

Wen using multiple clients, this problem won't be visible as connections will eventually be load-balanced evenly (client1 perhaps goes to poolmember1, client2 perhaps goes to poolmember2, client3 perhaps goes to poolmember1, and so on).

It might however be possible to load-balance based on HTTP request with a custom iRule. Bear in mind that F5 Support does not officially provide iRules to customers. Even though such iRule was tested internally by Support Engineers and deemed to work without issues, it was subject to limited testing. If wanting to try such iRule, please ensure to test it thoroughly.


when HTTP_REQUEST {

 set available_pool_member [active_members -list pool-01]

 set random_pool_member [lindex [lindex $available_pool_member [expr {int(rand()*[llength $available_pool_member])}]] 0]

 pool pool-01 member $random_pool_member

}


What the iRule does is:

  • upon each HTTP_REQUEST it will create a list with available pool members from pool "pool-01" (line 2)
  • then it will chose a random pool member from the list created above (line 3)
  • then it will load-balance this specific HTTP request to the chosen pool member (line 4)

So each HTTP request will be load-balanced individually to a random (available) pool member from pool "pool-01".

Please ensure to change "pool-01" on lines 2 and 4 with the correct pool name.

And beware that load-balancing won't be 100% even. Because it is random, you might achieve slight unbalance.

Bear in mind as well that such iRule does not have in account persistence.
