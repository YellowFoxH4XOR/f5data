K000161941: BIG-IP GUI Is Inaccessible Due to a Stale Tomcat Process Holding Listener Ports

Type
Support Solution
Published
2026-08-26
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000161941

Description

BIG-IP GUI may become inaccessible or unstable when the Tomcat service repeatedly restarts due to a stale/orphaned Tomcat Java process continuing to hold listener ports. This prevents new Tomcat instances from binding to ports 8005, 8009, and 9832, resulting in repeated startup failures and associated "BindException" or "Address already in use" errors in logs.

Environment

  • BIG-IP LTM on iSeries platform
  • Management access via GUI and SSH
  • Tomcat service is used for the BIG-IP Configuration utility
  • Diagnostic commands include bigstart status, ps, netstat, lsof, and review of /var/log/tomcat/catalina.out

Cause

A stale or orphaned Tomcat Java process fails to terminate properly and continues listening on ports 8005, 8009, and 9832. This blocks new Tomcat instances from binding to these ports, leading to repeated restarts and GUI unavailability.

Recommended Actions

  • Check the status of relevant services:

bigstart status | grep -E "httpd|tomcat|restjavad|restnoded"

 

  • Examine Tomcat logs for bind errors:

tail -200 /var/log/tomcat/catalina.out

grep -i "BindException\|Address already in use" /var/log/tomcat/catalina.out

 

  • Identify duplicate or stale Tomcat Java processes:

ps auxww | grep -i tomcat

 

  • Confirm which processes are using the critical ports:

netstat -tulnp | grep -E "8005|8009|9832|8100"

lsof -i :8005

lsof -i :8009

lsof -i :9832

 

  • If a stale Tomcat process is found holding any of the ports, terminate it:

kill -9 <PID>

 

  • Restart Tomcat cleanly after removing the stale process:

bigstart restart tomcat

 

  • Verify successful startup and restore of GUI access.

Note: A reboot may temporarily restore GUI access, but the recommended resolution is to identify and terminate the stale Tomcat Java process holding the required ports, then restart Tomcat.

Additional Information

Review /var/log/tomcat/catalina.out for bind failures such as:

SEVERE: StandardServer.await: create[localhost:8005]:

java.net.BindException: Address already in use (Bind failed)

SEVERE: Failed to initialize end point associated with ProtocolHandler ["ajp-bio-127.0.0.1-8009"]

java.net.BindException: Address already in use (Bind failed) /127.0.0.1:8009

SEVERE: Failed to initialize end point associated with ProtocolHandler ["http-bio-:127.0.0.1-9832"]

java.net.BindException: Address already in use (Bind failed) /127.0.0.1:9832
