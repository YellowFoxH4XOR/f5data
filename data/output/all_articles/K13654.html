Known Issue

Replacing a hard drive in the right disk bay may cause a reboot loop on the BIG-IP system.

This issue occurs when all of the following conditions are met:

  • You replaced a hard drive on a BIG-IP 6900, 8900, or 8950 platform.
  • The replacement hard drive had been previously installed on a similar F5 device, which had been configured with a volume group name that currently exists on the system with the failed hard drive.
  • The replacement hard drive was inserted into the disk bay on the right side.
  • The system was turned off when the replacement hard drive was inserted, and then turned on.

Note: This issue will not occur when you install a replacement drive that has been procured from F5 as a Return Materials Authorization (RMA) replacement.

Impact

When the BIG-IP system is turned on, the system enters an unexpected reboot loop.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H398378 on the Diagnostics > Identified > High screen.
  • The system starts in a reboot loop.
  • The system displays an error message on the console screen before restarting. The error message may appear similar to the following example:

    Red Hat nash version 5.1.19.6 starting
      Reading all physical volumes.  This may take a while...
      Found volume group "vg-db-sdb" using metadata type lvm1
      Found volume group "vg-db-sdb" using metadata type lvm1
      Found volume group "vg-db-hda" using metadata type lvm1
      6 logical volume(s) in volume group "vg-db-sdb" now active
      6 logical volume(s) in volume group "vg-db-sdb" now active
      1 logical volume(s) in volume group "vg-db-hda" now active
    mdadm: no devices found for /dev/md0
    mdadm: no devices found for /dev/md1
    mdadm: no devices found for /dev/md2
    mdadm: no devices found for /dev/md3
    mdadm: no devices found for /dev/md4
    mdadm: no devices found for /dev/md5
    EXT3-fs: unable to read superblock
    mount: error mounting /dev/md2 on /sysroot as ext3: Invalid argument
    umount /sysroot failed: Invalid argument
    mount: could not find filesystem  '/dev/root'
    Kernel panic - not syncing: Attempted to kill init!

Workaround

To work around this issue, you can swap the hard drives after encountering the reboot loop. To do so, perform the following procedure:

Note: This workaround requires physical access to the system.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. If the BIG-IP system is in a reboot loop, you will not have access to the BIG-IP command prompt to perform a shutdown. F5 recommends that you log in to the Always-On Management (AOM) menu to use the Power off Host subsystem option.

    Alternatively, you can use the front panel X button to turn off the system.

  2. Swap the original working hard drive and the new replacement hard drive bay locations by moving the working hard drive to the right disk bay and moving the replacement hard drive to the left drive bay.
  3. Ensure the hard drives for both disk bays are seated properly.
  4. Turn on the system.
  5. Log in to the BIG-IP command line.
  6. To view the status of the hard drives, type the following command:

    tmsh show /sys raid disk

    A disk summary similar to the following example appears:

    Sys::Raid::Disk
    Name Serial Number Array Member Array Status
    ------------------------------------------------------
    CF1 C932427402720909XX02 no undefined
    HD1 WD-WCAT12345687 yes ok
    HD2 WD-WCAT12345768 yes undefined

    The status of the replacement hard disk drive is undefined, and the serial number should match that of the replacement drive. From the example output, HD2 is the hard drive that is undefined to the RAID configuration. 
  7. Add the replacement drive to the RAID array by using the following command syntax:

    tmsh modify /sys raid array MD1 add <raid-disk-name>

    For example, to add the replacement drive with raid disk name HD2 to the RAID array, you would type the following command:

    tmsh modify /sys raid array MD1 add HD2

     
  8. To monitor the progress while the RAID rebuilds the array, you can use the array command. The array command output appears similar to the following example:

    # array
    Bay  name    t/s/r count         state         Serial Number       
    ---  ----    -------------       -----         -------------       
    1    HD2     17/1/16             replicating   WD-WCAT12345768    
    2    HD1     17/17/0             ok            WD-WCAT12345687    

    (Legend: t = total, s = synchronized, r = replicating)

    9. When rebuilding the RAID has completed, output appears similar to the following example:

    # array
    Bay  name    t/s/r count         state         Serial Number       
    ---  ----    -------------       -----         -------------       
    1    HD2     17/17/0             ok            WD-WCAT12345768    
    2    HD1     17/17/0             ok            WD-WCAT12345687   

    (Legend: t = total, s = synchronized, r = replicating)
