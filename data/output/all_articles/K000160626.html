K000160626: Understanding Trunk ID 65535 Displayed on BIG-IP tenant

Type
Support Solution
Published
2026-04-06
Updated
2026-04-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source

Description

On the tenant, trunk IDs may be displayed as 65535 instead of sequential trunk IDs (such as 1, 2, etc.). This behavior can occur when TMOS does not receive or persist the correct LAG (Link Aggregation Group) ID from F5OS at that time of trunk creation or migration, even though the underlying F5OS LAG remains valid and operational.


eg.)

net trunk trunk01 {

...

 id 65535

...

}


Environment

Platform: R2600/ F5OS-A v1.8.0

BIG-IP Tenant v17.1.1

Multiple trunks configured


Impact

No traffic impact. Trunk remains operational as traffic forwarding uses the valid F5OS LAG ID. 


Cause

The trunk ID 65535 in TMOS is an internal artifact indicating an "invalid/uninitialized trunk ID." This occurs when TMOS does not receive or persist the correct LAG (Link Aggregation Group) ID from F5OS during trunk creation or migration. The underlying F5OS LAG remains valid and operational.

Known scenarios where this can occur include:

- Trunk creation while tenant provisioning is still in progress

- F5OS control-plane services restarting

- System upgrade or reboot in progress

- Trunk migration from an older TMOS/F5OS version or from a UCS where the ID was not populated


Answer/Recommended Actions

- No immediate action is required. The trunk ID 65535 is a cosmetic issue in TMOS and does not affect traffic forwarding or the operational state of the trunk, as F5OS uses the correct LAG IDs at the hardware level.

- If cosmetic consistency is desired, consider recreating the trunk during a planned maintenance window.

- Monitor the system for any operational issues, but trunk ID 65535 alone does not indicate a functional problem.
