Known Issue

Description

Low memory condition caused by long-lived SSL connections may result in TMM core.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured with an SSL profile.
  • There are multiple connections to the SSL-enabled virtual server.
  • The BIG-IP system has high memory consumption.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restart. If configured as a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system fails over to the standby system.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • Messages that appear similar to the following examples are observed in the /var/log/ltm file:

    err tmm1[7380]: 01010004:3: Memory allocation failed: ssl_session
    err tmm1[7380]: 01010004:3: Memory allocation failed: ssl_bulk_crypto_ctx
    info tmm1[7380]: 01010004:6: Per-invocation log rate exceeded; throttling.
    warning tmm1[7380]: 011e0001:4: Limiting open port RST response from 251 to 250 packets/sec
    err tmm[7379]: 01340002:3: HA Connection with peer 192.168.154.234:32768 lost.
    err tmm[7379]: 01340002:3: HA Connection with peer 192.168.154.226:32768 lost.
    notice sod[4957]: 01140045:5: HA reports tmm NOT ready.
