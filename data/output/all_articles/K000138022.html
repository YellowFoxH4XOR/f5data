K000138022: HTTP explicit proxy may fail to forward traffic to virtual server configured on same BIG-IP device

Type
Support Solution
Published
2023-12-22
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.5
Source
https://my.f5.com/manage/s/article/K000138022

Description

  • A virtual server may be configured as an explicit HTTP proxy to leverage a DNS resolver for name resolution
  • The resolved IP of the DNS lookup may be configured as a virtual server on the same BIG-IP as the proxy virtual server
  • An explicit proxy virtual server may return HTTP 503 Service Unavailable response for proxied non-CONNECT method HTTP requests as it is unable to send proxied requests to the HTTP-tunnel
  • HTTPs proxy requests use the CONNECT method and are forwarded over the HTTP-tunnel

Environment

  • HTTP explicit proxy
  • DNS resolver for name resolution
  • Virtual server configured as proxy
  • Virtual server configured with IP returned in DNS name resolution

Cause

  • This is expected.
  • With HTTP explicit proxy mode, HTTP non-CONNECT requests are forwarded out via the appropriate route, and will not be intercepted by any virtual server that is listening on the tunnel.

Recommended Actions

  • An example iRule to forward the proxied request to the desired virtual server may be used
when HTTP_REQUEST {
   if {[HTTP::header exists "Proxy-Connection"] and [HTTP::method] != "CONNECT"}{
   virtual <virtual_server>
   }
}
