Description

From BIG-IP TMOS versions 15.1 and later, the IKE version cannot both be version 1 and version 2. In previous versions, the IKE version could be 1, 2 or both.

In the web UI (Network  ››  IPsec : IKE Peers), the IKE version has changed from a checkbox to a radio button that permits only one option.

In tmsh, the TMOS command line, adding two versions will now fail as so:

(tmos)# create net ipsec ike-peer my-remote-peer remote-address 192.0.2.1 my-id-value 192.0.2.1 peers-id-value 198.51.100.1 version add { v1 v2 }
01070734:3: Configuration error: Ike peer version can take only one value


Environment

IPsec is used to connect remote networks together.
 

Cause

When IKEv2 was implemented in version 11.6.0, the intention was to allow the BIG-IP to adapt to the version configured on the peer. However, there were several caveats on the behaviour that lead to the BIG-IP being unable to predict the correct version to use with the remote peer. This behaviour has been deliberately deprecated due to the unpredictability of the feature and because customers do not use or need it.

IPsec tunnels require the BIG-IP administrator to know several critical aspects of the tunnel in advance of configuring it. This includes encryption and authentication algorithms along with authentication methods and traffic selectors. The IKE version must now also be known in advance.

 

Recommended Actions

Specify the correct IKE version to use with the remote peer.

(tmos)# create net ipsec ike-peer <name> remote-address <local-ip> my-id-value <local-ip> peers-id-value <remote-peer-ip> traffic-selector add { <selector-name> } version add { v2 }

For example:

(tmos)# create net ipsec ike-peer my-remote-peer remote-address 192.0.2.1 my-id-value 192.0.2.1 peers-id-value 198.51.100.1 traffic-selector add { my-traffic-selector } version add { v2 }
