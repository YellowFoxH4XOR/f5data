Topic

This article explains the conditions in which the BIG-IP system sends or does not send a gratuitous address resolution protocol (ARP) requests.

Description

The BIG-IP system uses gratuitous ARP requests to alert neighboring devices of the active IP addresses and related MAC addresses it owns.

Under normal conditions, the BIG-IP system sends gratuitous ARP requests as follows:

  • When the BIG-IP system starts, it sends gratuitous ARP requests for non-floating self IP addresses.
    Note: On devices where the Traffic Management Microkernel (TMM) starts before the interfaces are brought online, the BIG-IP system does not send gratuitous ARP requests for the non-floating self IP addresses. After the BIG-IP system is fully started and interfaces are online, you can force a gratuitous ARP by selecting the non-floating self IP address in the Configuration utility and then selecting Update (without making any changes).
  • When the BIG-IP system becomes active, gratuitous ARP requests are also sent for floating self IP addresses and virtual IP addresses.
  • Performing actions such as adding, modifying, or deleting a BIG-IP virtual IP address object (such as a virtual server, self IP address, VLAN, SNAT, or NAT) may also cause the BIG-IP system to re-send gratuitous ARP requests.

However, the BIG-IP system will purposely not send gratuitous ARP requests under the following conditions:

  • For a floating self IP address on a traffic group that is not active.
  • For a network virtual IP address (network virtual server).
  • For a virtual IP address that has been configured with ARP disabled.
  • For a virtual IP addresses that rely on gateways that are located in networks that are not directly connected.

    Note: For more information on network virtual servers refer to: K7595: Overview of IP forwarding virtual servers.
