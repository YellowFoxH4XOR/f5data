K000092904: Creating Active Health Checks for Aspen Mesh

Description

Aspen Mesh and Istio provide configuration for a passive health check that is configurable by using outlierDetection within a destination Rule. However, to have an active health check, this needs to be configured independently on the istio-proxy which uses Envoy. Whereas the passive health check is looking for a response to the client’s request, the active health check is actively and constantly checking the endpoints.

Environment

  • Redhat Openshift: 4.6x, 4.7.x, 4.8.x, 4.9.x and 4.10.x 
  • Kubernetes: 1.17x,1.18.x,1.19.x,1.20.x, 1.21.x, 1.22.x, 1.23.x 
  • Aspen Mesh: 1.6.x,1.9.x,1.11.x,1.14.x

Cause

By default, the istio-proxy does not perform any health checks against the upstream services or service entries.

Recommended Actions

Envoy (the istio-proxy) can be configured to actively test hosts with Health Checking, and it is defined on a per cluster (or service) basis. The simplest health check, or L3/L4 check, just ensures each endpoint (i.e., port on a host or container) is available, and it does not depend on any application logic. Because the IP and port are already specified as part of the endpoint, setting up a Health Check does not even require service-specific information.  

apiVersion: networking.istio.io/v1alpha3 
kind: EnvoyFilter 
metadata: 
  name: health-check 
spec: 
  workloadSelector: 
    labels: 
      app: httpbin 
  configPatches: 
  - applyTo: CLUSTER 
    match: 
      context: SIDECAR_OUTBOUND 
      cluster: 
        service: httpbin.default.svc.cluster.local 
    patch: 
      operation: MERGE 
      value: 
        name: envoy.filters.http.health_check 
        health_checks: 
        - timeout: 10s 
          unhealthy_threshold: 3 
          healthy_threshold: 1 
          interval: 2s 
          always_log_health_check_failures: true 
          event_log_path: /dev/stdout 
          http_health_check: 
            host: httpbin.default.svc.cluster.local 
            path: / 
        typed_config: 
          "@type": "type.googleapis.com/envoy.extensions.filters.http.health_check.v3.HealthCheck" 
          pass_through_mode: true 
          cache_time: 2s

Note:  The envoyFilter CRD exposes an opaque patching mechanism for customizing Envoy configuration beyond what Aspen Mesh or Istio expose natively. This feature is additive and must be used with care, as incorrect configurations could potentially destabilize the entire mesh. 

Certain fields are required for health_checks:

  • Timeout: The time to wait for a health check response. If the timeout is reached the health check attempt will be considered a failure.
  • Interval:  The interval between health checks.
  • Unhealthy_threashold: The number of unhealthy checks required before a host is marked unhealthy.
  • Healthy_threashold:  The number of healthy checks required before a host is marked healthy.  

Fields required under the http_health_check:  

  • Path: Specifies the HTTP Path that is requested during the health check.

Read more about these values on the envoyproxy.io documentation for health_check and http_health_checks.
