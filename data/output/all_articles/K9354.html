Known Issue

This is the result of a known issue. Running the tcpdump command on an interface in which port mirroring is enabled, and then deleting the interface from the existing port mirror may leave the mirror-to port in an inoperable state. The port mirroring feature allows you to copy traffic from any port or set of ports to a separate port where a sniffing device is attached.

Note: For more information, refer to K8573: Overview of port mirroring and clone pools.

For example, the following command creates a port mirror, where interface 1.1 is the mirror-to port, and interfaces 1.2, 1.3, and 1.4 are the mirror-from ports. All traffic processed by the interfaces 1.2, 1.3, and 1.4 is mirrored to the interface 1.1:

bigpipe mirror 1.1 interface 1.2 1.3 1.4

Running the tcpdump command on the mirror-to port (interface 1.1), and then removing the interface from the existing port mirror, may leave interface 1.1 inoperable.

F5 Product Development is tracking this issue as ID 303434 (formerly CR82208).

Note: Once implemented, CR82208 will prevent future versions of BIG-IP from running tcpdump on a mirror-to interface.

Workaround

You can restore functionality to the interface by running the bigstart restart command.
