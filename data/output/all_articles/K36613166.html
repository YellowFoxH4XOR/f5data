Description

  • Unit became unresponsive
  • MCPD restarting in loop
  • BigDB.dat file is not 0 (Zero) bytes in size
  • ltm log shows similar to the following:

    LTM1.com err mcpd[24196]: 01070047:3: DB variable dosl7.allowed_origins's data type [stri] is invalid. Valid data types are: integer, unsigned_integer, string, ipaddress, enum.      
    LTM1.com err mcpd[24196]: 01070734:3: Configuration error: MCPProcessor::initializeDB (2):
    LTM1.com err mcpd[24196]: 01070596:3: An unexpected failure has occurred,  - sys/validation/DbVariable.cpp, line 1618, exiting...
    LTM1.com info chmand[31691]: 012a0006:6: MCP connection lost.
    LTM1.com notice chmand[31691]: 012a0005:5: resetting chmand services
    LTM1.com notice root[24555]: -bash  ==> /bin/bigstart stop ecmd

Environment

  • Hardware BIG-IP platform
  • File system corrupted 

Cause

File named: Bigdb.dat got corrupted and could not read the variables, causing mcpd to restart in loop 

Recommended Actions

To work around this issue:

  1. Rename BigDB.dat as follow:
    mv /config/BigDB.dat /config/BigDB.dat.corrupt.TEMP
  2. Restart mcpd process:
    bigstart restart mcpd
  3. To make sure the unit is back to stable state, reboot the unit:
    reboot  

Usually, when the unit become unresponsive, it will create a core file - check if exist and open a new Service Request:
Run the following command to check it:
ls -lstr /var/core/

None.
