Issue

Note: This change in behavior only applies to platforms that include a Packet Velocity ASIC (PVA) chip. For more information about the PVA chip, refer to K4832: Overview of Packet Velocity ASIC (PVA) Acceleration.

The PVA chip accelerates Layer 4 connections for virtual servers that use the FastL4 profile. Within this profile, an idle timeout can be configured to specify how long the profile should wait before closing an idle connection.

The default timeout value listed in the FastL4 profile is 300 seconds, or 5 minutes. This timeout value can be changed if a longer idle timeout period is required.

The FastL4 profile does not place a restriction on the maximum idle timeout value; however, the PVA chip does have a maximum idle timeout value. The following table lists the PVA chip maximum idle timeout values:

VersionPlatformMaximum Idle Timeout
PVA1240065,527 seconds
PVA23400, 6400, 680065,527 seconds
PVA108400, 880032,760 seconds


Important: The table lists the correct maximum idle timeout for PVA1 and PVA2 chips. However, due to a known issue, some BIG-IP versions use a wrong value for the maximum idle timeout. For more information, refer to K10533: PVA version 1 and 2 chips may prematurely delete FastL4 profile connections configured with a large idle timeout.

In BIG-IP 9.0 through 9.2.5, if the idle timeout value specified in the FastL4 profile exceeds the maximum idle timeout value allowed by the PVA chip, idle connections may be closed before either the PVA chip maximum idle timeout or the FastL4 profile timeout value is reached.

This behavior changed beginning in BIG-IP 9.3. If the idle timeout value specified in the FastL4 profile exceeds the maximum idle timeout value that the PVA chip is capable of handling, the Traffic Management Microkernel (TMM) demotes PVA acceleration from Full to either Assisted mode or None. This demotion is a two-step process:

  1. When TMM detects the FastL4 profile used by a virtual server is attempting to set an idle timeout greater than the maximum idle timeout value allowed by the PVA chip, TMM sets the acceleration for that virtual server to Assisted mode. The virtual server shows PVA acceleration assist when running the bigpipe virtual show all command.
  2. TMM examines and treats each connection hitting the virtual server independently. TMM honors that level of acceleration only if another configuration object, such as an iRule or a SNAT, lowers the idle timeout of the connection to a value that the PVA chip can support. If this is the case, the connection is partially accelerated. Otherwise, TMM must further demote the acceleration for that connection to None. Connections that are not accelerated are handled at the software level by TMM, which enables an idle timeout value greater than what the PVA chip supports. It is important to consider that because this second demotion is dynamically performed against every connection, the virtual server still shows PVA acceleration assist when running the bigpipe virtual show all command. This behavior maximizes efficiency because rather than demoting all connections to None, the BIG-IP system attempts to partially accelerate those connections that will ultimately have an idle timeout supported by the PVA chip. As a result of this behavior, it may be possible for a BIG-IP Administrator to see a virtual server in Assisted mode whose statistics show no PVA assisted connections.
