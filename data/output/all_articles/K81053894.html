Topic

In Secure Web Gateway (SWG) transparent forward proxy or transparent forward proxy in inline mode deployments, you configure your internal network to forward web traffic to the BIG-IP APM SWG, which acts as the forward proxy. Before deployment, you should understand the redirection that occurs in the traffic flow.

Description

The following example sequence describes the series of redirection that occurs when a user first connects to the SWG to access https://www.f5.com.

  1. The user accesses https://www.f5.com from a browser.

    GET https://www.f5.com

  2. The client browser receives an HTTP 302 redirect to the captive portal.

    302 https://captiveportal.example.com/F5Networks-SSO-Req?SSO_ORIG_URI=aHR0cHM6Ly93d3cuZjUuY29tLw%3d%3d

    In this example:

    • The captive portal is captiveportal.example.com.
    • The value of SSO_ORIG_URI is aHR0cHM6Ly93d3cuZjUuY29tLw%3d%3d, which is the base64 encoding of https://www.f5.com, the original URL the user attempted to access.
  3. After the captive portal, the user is then redirected to /my.policy?ORIG_URI=xxxxx, where the access policy that you configured for the virtual server will start.

    302 https://www.f5.com//my.policy?ORIG_URI=295b4733

  4. The BIG-IP APM SWG redirects the browser to /vdesk/policy_done.php3?ORIG_URI=xxxxx, where the access policy evaluation is completed.  

    302 https://www.f5.com/vdesk/policy_done.php3?ORIG_URI=295b4733

  5. The last redirect takes the user to the landing page or the page the user requested at the beginning of the sequence.

    302 https://www.f5.com

If the user fails to gain access to the captive portal in step 2, the user is first redirected to the landing URL and then redirected again to the /vdesk/hangup.php3 logout page.

302 https://www.f5.com
302 https://www.f5.com/vdesk/hangup.php3

The first redirect to the landing URL is necessary. When the user fails to gain access at the captive portal, a subordinate virtual server redirects the user to a dominant virtual server to complete the access policy, accounting for the first redirect. After the access policy is completed, the dominant virtual server redirects the user back to the subordinate virtual server, which enforces the result of the access policy.

Recommendations

When planning to deploy SWG transparent forward proxy, consider the following factors:

  • The client must be able to follow HTTP 302 redirects.
  • The certificate you configured in the Client SSL profile for your transparent forward proxy virtual server should be trusted by the client. You should install the certificate in the Trusted Root Certification Authorities store on all client devices.
  • If you configured a separate virtual server for a captive portal, the certificate in the Client SSL profile for this virtual server should be trusted by the client and should match the fully qualified domain name (FQDN) configured in the SWG-Transparent access profile to avoid security warnings.
