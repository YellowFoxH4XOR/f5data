Recommended Actions

  • Determine existing Portal Access performance

Determine existing Portal Access performance

  1. Gathering an HTTPWatch capture.  Use the following procedure to capture session traffic to the BIG-IP APM system:
    Note:  If you do not have HTTPWatch installed, you can download the free basic version to capture traffic.
    1. Open a browser and ensure that your Home page is not part of the application. If it is, you can temporarily change it.
    2. Open the HTTPWatch control panel and clear the cookies and cache by using the HTTPWatch toolbar to navigate to Tools and clicking Clear Cache and All Cookies.
    3. Close the browser to clear cached data, and then relaunch the browser.
    4. Start HTTPWatch and start recording.
      Note: Do not select the Automatically Record when IE or Chrome Starts option. This option creates a separate file for each browser window.
    5. To access the site through the BIG-IP APM system, type its name into the address bar.
    6. Perform the actions required to reproduce the issue in the application.
    7. Stop HTTPWatch and save the recording using the HTTPWatch Log File(*.hwl) file type option.
       
  2. Enable Access profile debug log and review the APM logs
    1. Log in to the Configuration utility (GUI).
    2. Go to Access Policy > Access Profiles > Access Profiles List.
    3. Click the Access Profile for which you want to apply the logging profile.
    4. Click the Logs tab.
    5. In the Available list, select the logging profile you want and move it to the Selected list.
    6. Click Update.
    7. Enable re-write debug log, this has to be perform on CLI by the following command:

      tmsh modify sys db log.rewrite.level { value Debug }


Optimizing the Portal Access performance

  1. Enable the Web Acceleration profile to improve performance with the RAM Cache.
    NOTE: depending on the website, this may cause prevent user to access to certain site. Please test before you enable web acceleration profile.
    To associate the Web Acceleration profile with the APM-enabled virtual server, perform the following procedure:
    1. Log in to the Configuration Utility (GUI).
    2. Go to Local Traffic > Virtual Servers > Virtual Server List.
    3. Select the APM-enabled virtual server with which you want to associate the Web Acceleration profile.
    4. In the Acceleration section, select the name of the Web Acceleration profile from the Web Acceleration Profile list.
      For example:  MyAccelerationProfile
    5. Click Update.
       
  2. HTTP Compression profile
    To associate the HTTP compression profile with the APM-enabled virtual server, perform the following procedure:
    1. Log in to the Configuration Utility (GUI).
    2. Go to Local Traffic > Virtual Servers > Virtual Server List.
    3. Select the APM-enabled virtual server with which you want to associate the HTTP Compression profile.
    4. In the Acceleration section, select the name of the HTTP Compression profile from the HTTP Compression profile list.
    5. Click Update.
       
  3. Enabling Cache
    1. Log in to the Configuration Utility (GUI).
    2. Go to Access > Connectivity/VPN > Portal Access > Portal resource
    3. Click on the Portal Access resource item
    4. Change the Client cache setting to Default
    5. Click Update
    6. Go to Access > Connectivity/VPN > Portal Access > rewrite
    7. Click the Rewrite profile applied to the APM-enabled virtual server
    8. Change the Cache setting to Preserve
    9. Click Update
       
  4. Disabling the Portal Access Debugging (which was enabled when Determine existing Portal Access performance) 
    • Disable Access profile debug log 
      1. Log in to the Configuration utility (GUI).
      2. Go to Access Policy > Access Profiles > Access Profiles List.
      3. Click the Access Profile for which you want to disable the logging profile.
      4. Click the Logs tab.
      5. In the Selected list, select the logging profile you want and move it to the Available list.
      6. Click Update.
    • Disable re-write debug log, this has to be perform on CLI by the following command:
      modify sys db log.rewrite.level { value Notice }
       

Additional Information

When you configure the Web Acceleration profile for a virtual server, you should consider the following factors:

  • Caching is useful for frequently requested content; for example, caching can be used if the site has periods of high demand for specific content. When you configure a Web Acceleration profile for a virtual server, the content server only has to serve the content to the BIG-IP system once per expiration period.
  • Caching is useful if a site contains a large amount of static content such as CSS files, JavaScript files, or images.
  • For compressible data, the cache feature can store data for clients that accept compressed data. When used with the compression feature on the BIG-IP system, the cache takes stress off of the BIG-IP system and the content servers.
  • Exclusion is useful because some URI or file types might already be compressed. F5 recommends that you do not use CPU resources to compress already-compressed data, because the cost of compressing the data usually outweighs the benefits. Examples of regular expressions that you might want to specify for exclusion are .*\.pdf, .*\.gif, or .*\.html.

Clearing RAM Cache:

  • To delete a specific cache entity of a specific Web Acceleration profile, use the following tmsh command syntax:

    tmsh delete /ltm profile ramcache <profilename> host <virtual server address> uri /<object name>

    For example:

    tmsh delete /ltm profile ramcache my_cache_profile host 192.168.0.10 uri /f5.jpg

    Note: When a path is supplied but no specific object name all cached objects of the path will be removed from the cache.
     
  • To delete all HTTP cache entries for a specific Web Acceleration profile, use the following tmsh command syntax:

    tmsh delete /ltm profile ramcache <profilename>

    For example:

    tmsh delete /ltm profile ramcache my_cache_profile
