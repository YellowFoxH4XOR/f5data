Description

Extracting the value of the X-Forwarded-For header and storing it in a variable causes the iRule to fail if it contains more than one IP:

err tmm[XXXX]: 01220001:3: TCL error: /Common/iRule <HTTP_RESPONSE> - bad option "x.x.x.x": must be any, virtual, service, or pool while executing "persist add uie $clientip 3600"
 

Conditions

  • Using an iRule to extract the value of the XFF header.
  • Storing the XFF header in a variable, for example: set clientip [HTTP::header "X-Forwarded-For"] 
            

Cause

When extracting the value of the X-Forwarded-For header to store it in a variable, the iRule may fail if XFF contains several values as it expects only a single value.
For example, the following header contains two IPs separated by a white space:

> HEAD / HTTP/1.1
> Host: 10.102.150.163
> User-Agent: curl/7.58.0
> Accept: */*
> X-Forwarded-For: 192.168.0.2 192.168.0.3

May  3 17:08:14 C3564996-v13-bigip1 err tmm[19400]: 01220001:3: TCL error: /Common/v13_test <HTTP_RESPONSE> - bad option "192.168.0.3": must be any, virtual, service, or pool     while executing "persist add uie $clientip 3600"
 

Recommended Actions

Pick the last value of the XFF header and store it in the variable:

Note: The following iRule statements use lindex to select elements from a list. By using the keyword, end, it selects the last IP address from the list. For more information on using lindex, refer to lindex in the TCL documentation.
  1. If the XFF header contains various IPs separated by comma use the following syntax:
set clientip [lindex [ split [lindex [HTTP::header values X-Forwarded-For] 0] "," ] end]
  1. If the XFF header contains various IPs separated by white spaces use the following syntax:
set clientip [lindex [ split [lindex [HTTP::header values X-Forwarded-For] 0] " " ] end]
