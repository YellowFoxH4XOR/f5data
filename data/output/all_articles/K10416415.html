K10416415: Debug distroless Images in Aspen Mesh

Description

Aspen Mesh has been in the direction of moving its Istio and Envoy components to distroless images for enhanced security. Since these images do not have shells or any other components besides the necessary software, it can be challenging to debug this at times. Enabling ephemeral debug containers is one way to use known tools to troubleshoot this if needed.
 

Environment

Aspen Mesh:  1.14.5
 

Cause

Distroless images contain only what's necessary for enhanced security therefore enabling ephemeral debug containers is needed to troubleshoot.
 

Recommended Actions

To enable this feature, you would need to enable EphemeralContainers as a feature in your cluster. For more information, refer to the Debugging Distroless Images chapter of the Aspen Mesh guide. Once you enable the EphemeralContainers feature, you would be able to spin up ephemeral containers in a running pod.

Perform the following procedure to debug distroless images:

Make sure you have enabled process namespace sharing in your pod spec.shareProcessNamespace: true. This allows processes in a container to be visible to all other containers in that pod.

apiVersion: v1
kind: Pod
metadata:
name: sleep
spec:
  shareProcessNamespace: true
  containers:
  - name: nginx
 <TRUNCATED>


Use the following example kubectl debug command in your sleep pod which has istio-proxy as a sidecar. This is a distroless image. You will use your Ubuntu image which has all the familiar tools needed for debugging. 
kubectl debug -it sleep-6d5779dc54-77xgh  --image=ubuntu --target=istio-proxy --image-pull-policy='Always'

This creates a debug container which is ephemeral, and you can run ps -ef to view processes running from other containers.
