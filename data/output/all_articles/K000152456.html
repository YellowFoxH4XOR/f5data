Description

NGINX Plus Docker Agent container fails to connect to NGINX Instance Manager's APIGW service and the following error, or similar, is reported:

ERRO[0007] Unable to create command channel: rpc error: code = Unavailable desc = connection error: desc = "transport: Error while dialing: dial tcp: lookup (apigw_hostname) on (dns_server_ip):53: no such host"

Environment

NGINX Instance Manager

NGINX Plus Docker Agent

Cause

This issue can occur when the NGINX Plus Docker Agent containerized system cannot resolve the APIGW hostname.

Recommended Actions

Ensure the APIGW hostname is correct. For example, assuming the Kubernetes cluster is implementing the default domain name, cluster.local, then the Kubernetes hostname for the APIGW service would be apigw.<namespace>.svc.cluster.local.

 

Ensure the DNS server specified in the NGINX Plus Docker Agent containerized system can resolve the APIGW service hostname. For example, if the Kubernetes hostname for the APIGW service is used, then create the Agent container with the kube-system/kube-dns ip address. For example:

docker run --dns="(kube-dns_ip_address)" -d agent_image

When implementing an Agent container from a Docker image obtained from the F5 NGINX private registry, use the following command:

docker run \
--env=NGINX_AGENT_SERVER_GRPCPORT=443 \
--env=NGINX_AGENT_SERVER_HOST=apigw.<namespace>.svc.cluster.local \
--env=NGINX_AGENT_TLS_ENABLE=true \
--env=NGINX_AGENT_TLS_SKIP_VERIFY=false \
--restart=always \
--runtime=runc \
--dns="(kube-dns_ip_address)" \
-d <my-docker-registry>/nginx-plus/agent:<my-version-tag>
