Issue

In the BIG-IP Network Firewall, BIG-IP AFM, you can configure policies to validate traffic against an IP intelligence database. Such traffic can be handled automatically if it originates from known-bad or questionable IP addresses.

An IP intelligence database is a list of IP addresses with questionable reputations. IP addresses gain a questionable reputation and are added to the database as a result of having performed exploits or attacks, or these addresses might represent proxy servers, scanners, or systems that have been infected. You can prevent system attacks by excluding traffic from malicious IP addresses. The IP Intelligence database is maintained online by a third party.

You can control the actions for each denylist (blacklist) category by specifying those actions in a policy, and you can configure default action and default logging for each policy. Furthermore, you can configure logging and actions per category. You can apply IP Intelligence policies at the global context, to a virtual server, or on a route domain.

Note: Hardware acceleration for IP Intelligence denylists only occurs for source IP addresses and not destination IP addresses. IP Intelligence for denylists with destination IP addresses occurs in software.

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

IP intelligence feed lists

A feed list retrieves deny lists and allow lists from specified URLs. You can use a feed list to dynamically update deny lists and accept lists (white lists). A feed list can retrieve multiple feeds from FTP, HTTP, or HTTPS addresses. You can specify whether a feed is a deny list or accept list, and the default category for the feed list. You can also configure a polling interval.

After a deny list or accept list is defined in a feed list, you add the feed list to an IP Intelligence policy. The list is then used by the policy to retrieve feeds and dynamically adjust the deny list and accept list policy.

Environment

  • BIG-IP AFM is provisioned.
  • The system must have an IP Intelligence license.

Cause

Traffic from malicious sources is suspected to be hitting the F5 virtual server.

Recommended Actions

Creating a feed list

You can add accept list and deny list IP addresses to your configuration automatically by setting up feeds and capturing them with a feed list.

  1. Go to Security > Network Firewall > IP Intelligence > Feed Lists.
  2. Select Create to create a new IP Intelligence feed list. Enter a name for the feed list.
  3. Configure Feed URLs with an HTTP, HTTPS, or FTP URL, the list type, the deny list category, and the polling interval. Specify a username and password, if required to access the feed list.

    A feed URL includes the actual URL to the text file, and information about the defaults for that file. Within the feed file, however, any URL can be configured to be an accept list or deny list entry, and assigned to a denylist category.

  4. Select Add to add a feed URL to the feed list.
  5. Select Finished. The list page and the new items display.

Configuring and assigning IP intelligence policies

An IP intelligence policy combines combines feed lists, default actions, logging settings, and actions for denylist categories into a container that you can apply to a virtual server or route domain.

Configuring a policy to check addresses against IP intelligence

You can verify IP addresses against the pre-configured IP Intelligence database, and against IPs from your own feed lists, by creating an IP Intelligence policy.

  1. Go to Security > Network Firewall > IP Intelligence > Policies.
  2. Select Create to create a new IP Intelligence policy.
  3. Enter a name for the IP intelligence policy.
  4. To add feed lists to the policy, Select the name of an available feed list, and then add it to the Selected list.
  5. Set the Default Action for the policy to Accept or Drop.
    • Select Accept to allow packets from categorized addresses that have no action applied on the feed list.
    • Select Drop to drop packets from categorized addresses that have no action applied on the feed list.

      The default action applies to addresses that are not assigned a denylist category in the feed list. The IP Intelligence feature uses the action specified in a feed list entry, when available.

  6. Set the Default Log Actions.
    • Log Whitelist Overrides specifies the default log action (Yes or No) for acceptlist (whitelist) matches that override denylist (blacklist) matches.
    • Log Blacklist Category Matches specifies the default log action for denylist (blacklist) matches, when the category does not have a specified log action in the denylist matching policy. Set to Yes affords visibility into denylist matches and logs all packets, but provides no hardware acceleration. Limited logs statistics every 256 packets and includes hardware acceleration. Set to No does not log denylist matches but provides the highest performance with hardware acceleration.
    • Select both Log Black List Category Matches and Log White List Overrides to log all deny list (black list) matches, and all accept list (white list) matches that override denylist matches.

      Note: Acceptlist matches always override denylist matches.

  7. To configure matching actions and logging for custom denylist categories, select the Blacklist Category in the Blacklist Matching Policy area. Select a category from the list of predefined and user-defined denylist categories, and set the default action and default logging action for the category, then Select Add to add the denlist category to the policy.
  8. In the Blacklist Matching Policy area, select default actions for the selected denylist (blacklist) category.

    When you define a denylist category and add it to the IP intelligence policy, matches for that category use the default actions specified for the category, and override the policy defaults.

    • For Blacklist Category, select the category for which to configure the settings
    • For Action, select Use Policy Default to use the default policy action for this category. Select Drop or Accept to override the default action.
    • For Log Blacklist Category Matches, specify the action for denylist (blacklist) matches for this category. Select Use Policy Default to use the default log action for denyist matches. Set to Yes, affords visibility into denylist matches and logs all packets, but provides no hardware acceleration. Limited logs statistics every 256 packets and includes hardware acceleration. Set to No, does not log denylist matches but provides the highest performance with hardware acceleration.
    • For Match Override, select the matching criteria that overrides a denylist match. You can require a source match, a destination match, or both a source and destination match to override a denylist match with an acceptlist.
    • Select Add to add the customized denylist matching policy to the IP intelligence policy. The matching policy for the denylist category is added to the list.
    • To replace a denylist category matching policy, select the entry and Select Replace.
  9. To remove a customized category from the policy, select the category in the Blacklist Matching Policy area and Select Delete.
  10. Select Finished. The list page and the new items display.

Assigning a global IP Intelligence policy

You can assign an IP Intelligence policy globally, to apply denylist and acceptlist matching actions and logging to all traffic.

  1. Go to Security > Network Firewall > IP Intelligence > Policies.
  2. From the Global Policy list, select the IP Intelligence policy to apply to all traffic on the BIG-IP system.
  3. Select Update. The list page and the updated item are displayed.

The specified IP Intelligence policy is applied to all traffic.

Assigning an IP Intelligence policy to a virtual server

You can assign an IP Intelligence policy to a virtual server, to apply denylist and acceptlist matching actions and logging to traffic on that virtual server only.

  1. Go to Local Traffic > Virtual Servers . The Virtual Server List page opens.
  2. Select the name of the virtual server you want to modify.
  3. For Security, select Policies.
  4. Next to IP Intelligence, select Enabled, then select the IP intelligence policy to apply to traffic on the virtual server.
  5. Select Update.
  6. The list page and the updated item display.

    The specified IP Intelligence policy is applied to traffic on the selected virtual server.

Assigning an IP Intelligence policy to a route domain

You can assign an IP Intelligence policy to a route domain, to apply denylist and acceptlist matching actions and logging to route domain traffic.

  1. Go to Network > Route Domains.
  2. In the Name column, Select the name of the relevant route domain.
  3. From the IP Intelligence Policy list, select an IP Intelligence policy to enforce on this route domain.
  4. Select Update.
  5. The system displays the list of route domains on the BIG-IP system.

    The specified IP Intelligence policy applies to traffic on the route domain.

Note: To learn more about the IP Intelligence feature in BIG-IP AFM, refer to K10354610: BIG-IP AFM operations guide | Chapter 3: Firewall rules.

Sample IP Intelligence policy

From the BIG-IP bash prompt, run the tmsh list security ip-intelligence policy <AFM IP Intelligence Policy name> command:

tmsh list security ip-intelligence policy afm-ip-intel 

security ip-intelligence policy afm-ip-intel {
    app-service none
    blacklist-categories {
        botnets {
            action use-policy-setting
            app-service none
            description none
            log-blacklist-hit-only use-policy-setting
            log-blacklist-whitelist-hit use-policy-setting
            match-direction-override match-source
        }
        windows_exploits {
            action use-policy-setting
            app-service none
            description none
            log-blacklist-hit-only use-policy-setting
            log-blacklist-whitelist-hit use-policy-setting
            match-direction-override match-source
        }
    }
    default-action drop
    default-log-blacklist-hit-only limited
    default-log-blacklist-whitelist-hit no
    description none
    feed-lists none
    partition Common
}

Sample IP Intelligence policy configuration applied to a virtual server

From the BIG-IP bash prompt, run the tmsh list ltm virtual <Virtual Server Name with IP Intelligence Policy> command:

tmsh list ltm virtual webtop_search_url_vs
ltm virtual webtop_search_url_vs {
    destination 172.16.7.90:http
    ip-intelligence-policy afm-ip-intel
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
        http { }
        ppp { }
        rba { }
        rewrite { }
        serverssl-insecure-compatible {
            context serverside
        }
        tcp { }
        test-conn-profile {
            context clientside
        }
        websso { }
        webtop_home_toolbar_v2 { }
    }
    security-log-profiles {
        afm-ip-intelligence-logging
    }
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
    vs-index 20
}
