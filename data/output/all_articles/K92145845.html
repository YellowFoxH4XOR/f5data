Description
The BIG-IP is not able to connect to the NTP server and is routed through the TMM interfaces.

The NTP stay in INIT state and looks like the NTP server is down or the port down.

ntpq -pn
    remote          refid       st t when poll reach   delay   offset  jitter
==============================================================================
<ntp_server_ip>     .INIT.      16 u  -   1024    0    0.000   0.000   0.000


Does not have any restrict settings in ntp config: K91402225: NTP daemon stuck in 'INIT' state

Performed tcpdump to validate if the Big-IP was sent the NTP requests

tcpdump -s0 -ni mgmt host <ntp_server_ip> and  port 123 -vv
 
0 packet captured
0 packets received by filter
0 packets dropped by kernel


Also we made a netcat to validate if the NTP server was reachable and the port was available and was it.
 

nc -s <self_ip> -zv -u <ntp_server_ip> 123
Connection to <ntp_server_ip> 123 port [udp/ntp] succeeded!


 

Environment

  • BIG-IP
  • HA
  • NTP
     

Cause

BIG-IP  was sent the NTP request through the TMM interface, instead of the Management Route.
take tcpdump on tmm interface, you can see traffic:

tcpdump -ni0.0:nnn host <ntp_server_ip> and port 123 -s0
 

Recommended Actions

Add a Management route to the NTP servers: K13284: Overview of management interface routing
