Known Issue

This is the result of known issue. If a user selects a Portal Access web application favorite from an Intranet webtop, and the user connected to the FirePass controller using a mobile browser, FirePass injects a Back and Logout link at the bottom of each web page accessed through the favorite. If the user selects the injected Back link, FirePass terminates the user’s session instead of returning the user to the previous web page. In addition, FirePass displays an error message that appears similar to the following example:

You are not authorized to access FirePass Webtop.

Note: FirePass does not inject the Back link when a user connects to the FirePass controller using a full-featured browser.

F5 Product Development tracked this issue as CR132952 and it was fixed in FirePass version 7.0.0. For information about upgrading, refer to the FirePass release notes.
