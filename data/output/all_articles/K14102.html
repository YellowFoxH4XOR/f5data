Known Issue

An incoming HTTP URI longer than 65535 bytes may cause the TMM process to stop responding.

This issue occurs when all of the following conditions are met:

  • The virtual server is configured with an HTTP profile with the following settings:

    • RAM Cache is enabled
    • The Maximum Header Size is set to a value greater than 65535
  • The inbound HTTP request has a URI longer than 65535 bytes.

This issue occurs due to a buffer overrun, which may cause the TMM kernel to stop responding.

Impact

The BIG-IP system may temporarily stop processing traffic during failover to the standby system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H380541 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system may stop responding and fail over to the standby system.
  • You may view TMM core files in the /var/core directory.

Workaround

To work around this issue, you can reduce the maximum header size to 65535 or less. To do so, perform the following procedure:

Impact of workaround: The system will drop HTTP requests with a URI greater than 65535 bytes, and send a TCP RST to the client. This behavior may affect applications that rely on URIs larger than 65535 bytes.

  1. Log in to the BIG-IP configuration utility as the admin user.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click Services.
  5. Click HTTP.
  6. Select the HTTP profile in use and modify the Maximum Header Size to 65535 or less.
  7. Click Update.
