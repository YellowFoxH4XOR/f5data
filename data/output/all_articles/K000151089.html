Description

  • I am moving from Silverline to F5 Distributed Cloud (XC) and just added a domain to an XC Load Balancer
  • I want to reduce any potential outage or misconfiguration before the DNS cutover
  • I want to test that the domain correctly resolved to the CNAME generated by XC.
  • Domain is still pointing to Silverline or any other third party proxy which is being decommissioned
  • I have added the domain to an F5 XC Load Balancer and now you want to test that the domain resolves correctly before rerouting traffic 

Environment

  • F5® Distributed Cloud (XC)
  • Migration from Silverline or any other third party HTTP load balancer

Answer/Recommended Actions

Steps to locally test DNS resolution to a new domain configured in F5 Distributed Cloud HTTP Load Balancer: 

  1. Get the Load Balancer VIP. 
    1. Go to the F5XC Console -> Load Balancer -> Manage configuration -> DNS information
    2. Copy the IP shown.
  2. Edit your host file. This forces your machine to resolve the domain to the VIP.
    1. sudo vim /private/etc/hosts directory (Mac OS)
    2. Open hosts file As Administrator (Windows)
  3. Open the domain in your browser
    1. Visit the domain: https://new-domain.example.com
    2. Open Developer tools (F12) -> Network tab
    3. Click any request to the domain and check remote address under Header
  4. Confirm the public IP
    1. the remote address should match your Load Balancer VIP.
  5. remote the host file entry.
    1. once confirmed, delete the entry to return to normal DNS behavior.

Additional Information

You can also use cURL to test DNS resolution without editing the host file.

You can override DNS resolution for a domain using the --resolve or even --connect-to flag. i.e:

curl --resolve new-domain.example.com:443:203.0.113.10 https://new-domain.example.com

Explanation:

  • new-domain.com - the domain you are testing
  • 443 - the port the origin server(s) listen to
  • 203.0.113.10 - the Load Balancer IP you want to test
  • https://new-domain.example.com - the actual request being made

This tells cURL: If you are making a request to new-domain.example.com on port 443, send it to 203.0.113.10 instead of looking up DNS.
