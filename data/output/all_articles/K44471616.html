Description

You are experiencing any of the following:

  • Your client side connection is returning wrong data.
  • Your client side connection is RST, because the server side connection is RST.
  • Your server side connection is connecting to the wrong server, the server is not in the pool.
This can be erratic and can occur without warning.

Environment

  • More that one Virtual Server with a specific source address persistence profile applied.

Cause

The Source address persistence has any of the match-across options enabled:

ltm persistence source-addr /Common/<profile name> {
    app-service none
    defaults-from /Common/source_addr
    match-across-pools enabled  
    match-across-services enabled 
    match-across-virtuals enabled 
    mirror enabled
    timeout 7200
}

The match-across-services option allows the session information to be shared between the virtual servers with the same IP address but have different services specified and ensures that the client is directed to the same pool member.

The match-across-pools option allows the BIG-IP system to use a pool that contains a persistence record for a specific client, regardless of the virtual being connected to.

The match-across-virtuals option is similar to match-across-services, but it does not require the virtual servers to share the same IP address. This configuration allows clients to access different virtual servers, regardless of their IP address, and still access the same pool member.

Recommended Actions

  1. Review your requirements for persistence.
  2. Remove persistence profile from the Virtual Servers where this behavior is not desired or edit settings to match your desired behavior.
