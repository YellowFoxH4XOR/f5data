Known Issue

The Session Initiation Protocol (SIP) monitor may erroneously mark resources down.

This issue occurs when the following condition is met:

  • The SIP monitor is configured to use User Datagram Protocol (UDP).

Note: Configuring Secure Network Address Translation (SNAT) automap may exacerbate the issue.

By default, the BIG-IP LTM system attempts to preserve the originating source port when sending load-balanced or monitor traffic. However, in some cases where a source port is already in use, the BIG-IP system changes the source port to an ephemeral port. Under these circumstances, the BIG-IP system does not update the sent-by value in the top VIA header field with the new source port. As a result, the receiving server uses the incorrect source port when responding to UDP requests.

Impact

This issue may negatively impact SIP traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H450963 on the Diagnostics > Identified > Medium screen.
  • The SIP monitor erroneously marks down a node in a pool.
  • A packet trace of SIP monitor traffic reveals one or more of the following:

    • The source port listed in the sent-by value, in the top VIA header field, does not match the source port of the SIP monitor request.
    • There are two or more sequential UDP requests sent to the same node without a corresponding response in between the requests.

Workaround

Depending on your environment, you may be able to work around the issue by specifying TCP as the protocol for the SIP monitor. Alternatively, you could use another monitor type, such as Internet Control Message Protocol (ICMP) or gateway_icmp, to monitor the node.

Note: Using this workaround on BIG-IP 11.4.0 requires HF3 or later to be installed.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
