Known Issue

Portal access sessions may not properly use conditional caching HTTP headers.

This issue occurs when all of the following conditions are met:

  • BIG-IP APM portal access sessions process content that includes the following HTTP cache header types:
    • If-Modified-Since or If-None-Match request headers
    • Last-Modified or ETag response headers
  • You modify the portal access settings or upgrade your BIG-IP APM software.

Impact

The BIG-IP system may not correctly render content.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system renders content that references stale cache objects.
  • Rendered content produces JavaScript errors.

Resolution

Workaround

To work around this issue, you can create and apply an iRule to remove the If-Modified-Since and If-None-Match headers from requests. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform the following procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the new iRule Name box, type a name for the iRule.
  5. In the Definition box, enter the following text:

    when REWRITE_REQUEST_DONE {
    HTTP::header remove "If-None-Match"
    HTTP::header remove "If-Modified-Since"
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the name of the portal access virtual server that is affected by this issue.
  9. Click the Resources tab.
  10. In the iRules section, click Manage.
  11. From the Available column, select the iRule you previously created.
  12. Click << to move the iRule to the Enabled column.
  13. Click Finished.
