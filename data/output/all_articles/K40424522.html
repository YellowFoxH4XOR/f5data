Known Issue

The BIG-IP system may fail to process Secure Sockets Layer (SSL)/Transport Security Layer (TLS) handshake correctly if the client application uses Microsoft Secure Channel (Schannel) TLS library.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured with a Client SSL profile.
  • You attempt to access the virtual server with a client application (for example, Internet Explorer 10.x or 11.x) that uses the Schannel TLS library.
  • The BIG-IP system selects a cipher suite that uses the ephemeral Diffie-Hellman (DHE) key exchange when performing SSL/TLS handshake.

    Note: The issue does not apply to Elliptic Curve Ephemeral Diffie-Hellman (ECDHE) key exchange.

The client application, such as Internet Explorer using the Schannel TLS library, may experience TLS handshake failures while accessing a virtual server configured with a Client SSL profile. When the client and server select a TLS ciphersuite that uses DHE key exchange, the BIG-IP system sends a ServerKeyExchange message with DH parameters to the client. For a subset of the generated parameters (approximately 1 in 128 for 1024-bit DH parameters), the length of the encoded dh_Ys parameter is less than the length of the encoded dh_P parameter. As a result of that encoding combined with an issue with the Schannel TLS library, the client experiences a fatal error and is unable to complete the TLS handshake.

Impact

You are not able to connect to the affected virtual server from a client application that uses the Schannel TLS library.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You experience TLS handshake failures while accessing the affected virtual server from a client application that uses the Schannel TLS library.

    Note: The client application is unable to complete TLS handshakes with one or more (potentially only one) TMMs on a system for up to one hour until a set of new DH parameters are generated.

  • Other client connections are unaffected.

Resolution

Status

F5 Product Development has assigned ID 517202 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table.

Type of fixFixes introduced inRelated articles
Release12.0.0K2200: Most recent versions of F5 software
Point release/hotfix11.6.3.2K9502: BIG-IP hotfix and point release matrix

Note: The BIG-IP system now ensures that the encoded Diffie-Hellman parameters (dh_p and dh_Ys) in TLS ServerKeyExchange are always the same length by padding dh_Ys with leading 0x00 bytes.

Workaround

To work around this issue, you can disable the use of DHE ciphersuites from the Client SSL profile. To do so, perform the following procedure:

Impact of Workaround: The impact of the following workaround will depend on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Click on the affected Client SSL profile.
  4. From the Configuration menu, select Advanced.
  5. To disable the use of DHE ciphersuites from the Client SSL profile, replace the text strings in the Ciphers section with a text string that appears similar to the following example:  

    DEFAULT:!EDH

  6. Click Update.
