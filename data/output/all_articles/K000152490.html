K000152490: Setting up Primary Key on F5OS unit fails with status "ABORTED"

Type
Support Solution
Published
2025-07-09
Updated
2025-12-18
Applies to
  • F5OS
  • F5OS-C: 1.8.2, 1.8.0, 1.8.1
  • F5OS-A: 1.8.3, 1.8.0
Source
https://my.f5.com/manage/s/article/K000152490

Description

When attempting to set or rotate the system primary key on F5OS-Appliance (rSeries) using the system aaa primary-key set command, the operation fails with a status similar to:

system aaa primary-key state status "ABORTED Initiated: <timestamp>"

This occurs even when valid passphrase and salt values are used, regardless of whether special characters are present.

Environment

  • F5OS
  • Software Version: 1.8.x
  • LDAP authentication enabled with TLS certificate and key configured

Cause

The presence of an LDAP TLS certificate and key in the F5OS configuration causes the system primary key migration process to abort. The operation cannot complete successfully if these encrypted values are present during the attempt.

This issue is tracked under Bug ID 1976833.

Recommended Actions

To resolve this issue you may use below workaround:

Impact of workaround: You will temporarily lose LDAP authentication while its certificate/key is removed from configuration.

  1. Backup LDAP TLS Certificate and Key:
    Ensure you have access to the unencrypted LDAP TLS certificate and key currently configured on your device.
  2. Remove LDAP TLS Certificate and Key from Configuration:
    Temporarily remove the LDAP TLS certificate and key entries from your F5OS configuration.
  3. Set or Rotate System Primary Key:
    Execute system aaa primary-key set and follow prompts for passphrase and salt as required.
  4. Review the Status of the Key Rotation:
    show system aaa primary-key state status
  5. Restore LDAP TLS Certificate and Key:
    Once the primary key operation completes successfully, re-add your original LDAP TLS certificate and key back into the configuration.

Ensure you deleted the LDAP authentication cert/key and not the HTTPS cert/key. This is visible in the config utility, but the LDAP settings may not appear in the output of the CLI show system aaa command, use show running-config system aaa authentication ldap and review the full system aaa section.
