Known Issue

Modifications to a default Client Secure Sockets Layer (SSL) profile do not sync to other devices in a device group.

This issue occurs when all of the following conditions are met:

  • You have modified the Certificate Key Chain section of a default (a pre-configured profile supplied by the system) Client SSL profile.
  • You attempt to sync the changes from the device with the modified profile to the device group in a configuration synchronization (ConfigSync) operation.

Impact

Changes to default Client SSL profiles do not synchronize.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Default Client SSL profiles remain out of sync after a ConfigSync operation.

Workaround

F5 recommends that you do not modify default profiles. To work around this issue, you can manually undo the changes to the default Client SSL profile on all devices in the device group, and then re-attempt a ConfigSync operation. Once the devices are in sync, you can create a new custom Client SSL profile using the default profile as a parent. To manually undo the changes to the default profile, perform the following procedure:

Impact of workaround: You will lose any customized settings made in the default profile. Additionally, performing a configuration reload on an active device group member may cause a service disruption of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the BIG-IP command line of a device group member.
  2. Before editing the /config/bigip.conf file, perform a backup of the existing copy by typing the following command:

    cp -a /config/bigip.conf /config/bigip.conf_SOL75309122_backup

  3. Using your preferred text editor, load the /config/bigip.conf file for editing.
  4. Locate the affected default Client SSL profile stanza. It will appear similar to the following example:

    ltm profile client-ssl /Common/clientssl-insecure-compatible {
        app-service none
        cert /Common/default.crt
        cert-key-chain {
            default {
                cert /Common/default.crt
                chain /Common/test.crt
                key /Common/default.key
            }
        }
        chain /Common/test.crt
        ciphers !SSLv2:ALL:!DH:!ADH:!EDH:@SPEED
        defaults-from /Common/clientssl
        inherit-certkeychain false
        key /Common/default.key
        passphrase none
        renegotiation enabled
        secure-renegotiation request
    }

  5. Remove the entire affected default Client SSL profile stanza.

    Note: Removing the modified profile from the /config/bigip.conf file will not remove the system-supplied default profile.

  6. When you have finished editing the /config/bigip.conf file, save the changes and exit the text editor.
  7. Manually load the configuration by typing the following command:

    tmsh load sys config

    Note: Loading the configuration will update the commit ID time of the device. You must select the Overwrite Configuration box on the Device Management > Overview screen if the device is a member that will receive a ConfigSync.

  8. Repeat these steps for each device in the device group.
