Description

When deploying PLM with F5 WAF for NGINX 5.15.0, the waf-seaweedfs-operator may fail to create SeaweedFS resources in a Kubernetes cluster enforcing restrictive Kyverno policies.

The admission webhook may return errors similar to:

admission webhook "validate.kyverno.svc-fail" denied the request

Privilege escalation is disallowed.

Containers must drop ALL capabilities.

Root filesystem must be read-only.

Running as root is not allowed.

The compiler service may start successfully while the policy controller remains unable to connect to the S3 endpoint because the SeaweedFS storage resources were not created.

Environment

  • F5 WAF for NGINX 5.15.0
  • PLM deployed with the F5 WAF policy controller
  • waf-seaweedfs
  • waf-seaweedfs-operator
  • Kubernetes cluster using Kyverno admission policies that require:
    • allowPrivilegeEscalation: false
    • All Linux capabilities to be dropped
    • Non-root container execution
    • A read-only root filesystem

Cause

The SeaweedFS resources dynamically generated by waf-seaweedfs-operator did not include the security-context settings required by the cluster’s Kyverno policies.

Configuring the Helm chart’s security context did not necessarily apply those settings to StatefulSets created dynamically by the operator.

Recommended Actions

Upgrade to F5 WAF for NGINX 5.16.0, which includes a fix for the waf-seaweedfs-operator security-context configuration.

After upgrading:

  1. Upgrade or reinstall the PLM deployment.
  2. Confirm that the generated SeaweedFS pods and StatefulSets include:
    • allowPrivilegeEscalation: false
    • Dropped ALL capabilities
    • runAsNonRoot: true
    • A read-only root filesystem
  3. Verify that the SeaweedFS storage service is available.
  4. Confirm that the policy controller can connect to the configured S3 endpoint.

If the upgrade cannot be performed, consult the cluster security-policy administrators about a temporary exception that complies with the organization’s security requirements.

Additional Information

The F5 waf-seaweedfs and waf-seaweedfs-operator projects are F5-modified projects and are not direct mirrors of the upstream SeaweedFS projects. The operator includes F5-specific changes and should not be assumed to be interchangeable with the upstream seaweedfs-operator.

NGINX Ingress Controller 5.7.0 implements F5 WAF for NGINX 5.16.0.
