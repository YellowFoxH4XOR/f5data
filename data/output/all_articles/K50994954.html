Source

Description
You wish to verify the Attack Signature False Positive Mode state for a security policy using the iControl REST API

Environment

  • BIG-IP ASM version 15.1 or later

Cause

Monitoring the Attack Signature False Positive Mode configuration, particularly on versions listed as vulnerable in K47204506: BIG-IP Advanced WAF and ASM bd vulnerability CVE-2022-41836

Recommended Actions

Locate the security policy MD5 hash identifier

BIG-IP ASM security policies have a unique MD5 hash identifier that represents the policy name. You must determine the MD5 hash identifier for the policy before you can display security policy configuration using the iControl REST API. After you have located the policy MD5 hash identifier, you include the hash value when you define the URI to retrieve the configuration elements. To determine the MD5 hash identifier for the specific policy, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to determine the MD5 hash identifier for the policy name:

    curl -sku <username:password>  https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies?\$select=name,id | jq '.'

    For example, the following command returns two security policies, parent_policy and child_policy1, and related MD5 hash identifiers (id) for host BIGIP.example.com:

    curl -sku admin:admin  https://BIGIP.example.com/mgmt/tm/asm/policies?\$select=name,id | jq '.'

    {
          "kind": "tm:asm:policies:policystate",
          "selfLink": "https://localhost/mgmt/tm/asm/policies/2fFJIXo8nnfwGG9O78o3ig?ver=15.1.0",
          "name": "parent_policy",
          "id": "2fFJIXo8nnfwGG9O78o3ig"
        },
        {
          "kind": "tm:asm:policies:policystate",
          "selfLink": "https://localhost/mgmt/tm/asm/policies/FYHvhp8R1wYalvLTjXeKoA?ver=15.1.0",
          "name": "child_policy1",
          "id": "FYHvhp8R1wYalvLTjXeKoA"
        }

Check the attackSignatureFalsePositiveMode state

For each security policy, use the MD5 hash in the endpoint URL to verify the Attack Signature False Positive configuration. The values which are vulnerable to CVE-2022-41836 are "detect-and-allow" and "detect" on the affected versions.
 
  1. Use the following command syntax to determine the MD5 hash identifier for the policy name:
    curl -sku <username:password> https://BIGIP.example.com/mgmt/tm/asm/policies/<policy ID md5 hash>/signature-settings?\$select=attackSignatureFalsePositiveMode | jq .

    For example, the following command shows the Attack Signature False Positive Mode in disabled state for this security policy:
    curl -sku admin:admin https://BIGIP.example.com/mgmt/tm/asm/policies/FYHvhp8R1wYalvLTjXeKoA/signature-settings?ver=15.1.0\&\$select=attackSignatureFalsePositiveMode | jq .
    {
      "kind": "tm:asm:policies:signature-settings:signature-settingstate",
      "selfLink": "https://BIGIP.example.com/mgmt/tm/asm/policies/FYHvhp8R1wYalvLTjXeKoA/signature-settings?$select=attackSignatureFalsePositiveMode&ver=15.1.0",
      "attackSignatureFalsePositiveMode": "disabled"
    }

Additional Information
It is recommended that you implement an iControl REST API solution to suit your needs. However, you can do a simple check for any security policies on a local system with the following procedure. It will list the names of policies using Attack Signature False Positive mode and then the Attack Signature FPM setting. If the output is empty then there are no policies that use Attack Signature False Positive Mode.

  1. Put the iControl REST user's password in an environment variable
    read -s RESTPASSWORD
     
  2. Get a REST API auth token and check the False Positive Mode for each policy on the system. Security policies with the feature disabled will not be shown. You need to replace the <brackets> with your REST API username.
    TOKEN=$(curl -sk https://localhost/mgmt/shared/authn/login -X POST -d "{\"username\": \"<REST username>\", \"password\": \"$RESTPASSWORD\", \"loginProviderName\": \"tmos\"}" | jq -r .token.token); for i in $(curl -sk -H "X-F5-Auth-Token: $TOKEN" https://localhost/mgmt/tm/asm/policies?\$select=id | jq -r '.items[].id'); do curl -sk -H "X-F5-Auth-Token: $TOKEN" https://localhost/mgmt/tm/asm/policies/$i | jq -r '.name'; curl -sk -H "X-F5-Auth-Token: $TOKEN" https://localhost/mgmt/tm/asm/policies/$i/signature-settings?\$select=attackSignatureFalsePositiveMode | jq -r '.attackSignatureFalsePositiveMode'; done | grep -B1 'detect'
