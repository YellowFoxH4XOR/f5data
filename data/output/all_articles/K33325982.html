Description

Portgroup change will cause Vlan config changed blades need to be rebooted to reflect the change. 
Any prerequisites or caution?  
 

Environment

  • VELOS, F5OS-C
  • any version
  • Portgroup
  • multi-blade
  • Partition
     

Cause

none.

Recommended Actions

Preparation 1

Check if any of tenants are affected by Bug ID 950901.
Portrgoup change will reboot blades and this may trigger tenant's inter-blade communication issue.
K45993455: Velos Tenant management port access GUI CLI is intermittent, after upgrade / one of blade is rebooted.

Preparation 2
Check if your unit is affected by  Bug ID 1045177
Also read: K51909962: F5OS-C Velos Aftre changing Port Speed from 40G to 100G, the partition is not working
IMPORTANT: Upgrade to 1.3.* and later will not clean the faulty situation. Even the version is 1.3.x or later, this is recommended to check.

How to change PortGroup settings
  1. Take UCS backup and save in safe remote location
  2. Make all tenants on the partition to provisioned state.
  3. Checking current portgroup status before you change transceiver
    On Partition CLI run:
    show portgroups
    portgroups portgroup 1/1
     state vendor-name      "F5 NETWORKS INC."  <-- We only support genuine F5 transceiver
     state vendor-oui       009065
     state vendor-partnum   "OPT-0031        "
     state vendor-revision  A1
     state vendor-serialnum "X61ANPX         "
     state transmitter-technology "850 nm VCSEL"
     state media            40GBASE-SR4                       
     state optic-state      QUALIFIED            <-- The optic *must* show as 'QUALIFIED'.
    ...

    If optic-state is not QUALIFIED, then before you make any change, troubleshoot.
     
  4. Change transceiver to appropriate one.
    Optical transceiverWhat "portgroup state media" haveValid portgroup mode
    QSFP28100GBASE-SR4MODE_100GB
    MODE_4x25GB
    QSFP+40GBASE-SR4MODE_40GB
    MODE_4x10GB
    Then run again
    show portgroups
    portgroups portgroup 1/1
     state vendor-name      "F5 NETWORKS INC."  <-- We only support genuine F5 transceiver
     state vendor-oui       009065
     state vendor-partnum   "OPT-0030        "
     state vendor-revision  A1
     state vendor-serialnum "X45LTDS         "
     state transmitter-technology "850 nm VCSEL"
     state media            100GBASE-SR4                       
     state optic-state      QUALIFIED_MODE_MISMATCH  <-- This is expected as setting is 40G but Optic is 100G
    ...
     
  5. Change the setting as you need on Partition GUI or Partition CLI:
    e.g.
    # config
    (config)# portgroups portgroup 1/1 config mode MODE_4x25GB
    (config-portgroup-1/1)# exit
    (config)# portgroups portgroup 1/2 config mode MODE_4x25GB
    (config-portgroup-1/2)# commit

    The following warnings were generated:
      'portgroups portgroup': Blade(s) 1 will reboot
    Proceed? [yes,no]
    Type yes will cause all blades changed will be reboot.

  9. Change the tenant 's mode to *Deployed* mode.
     
  10. After you change a portgroup's mode, its interface objects will be removed and new ones created once the blade boots.
    This will wipe out any interface-specific settings that you had, along with other configurations that reference those interfaces, including:
  • Interface VLAN tags
  • LAG membership
  • Interface Spanning Tree settings
  • Interface LLDP settings

    For example. if you are changing the interfaces in a LAG from 40G to 100G, they will be removed from the LAG when the portgroup mode is changed and you will have to add them back. Similarly, if an interface had a set of trunk vlans applied, those will have to be added back too.
