Description

Using 'lindex' to parse a string within an iRule may now return a trailing } character.

Environment

  • LTM v15, v16
  • iRule
  • Datagroup

Cause

There was a  change of behavior starting in v15. For example, when parsing an IP address from a DNS response with the following code:

  when DNS_RESPONSE {
   set response [split [DNS::answer] ]
   set request [ lindex $response 4 ]
   ...etc.
In v12-14 that code will return a list similar to this example output: 
  \{testdom.com. 1 IN A 172.16.125.188 \}

Starting in v15, the TCL list is formatted without a trailing space character after the IP address: 
  \{testdom.com. 1 IN A 172.16.125.188\}
There was a change in behavior for v15. The difference is the space before the ending bracket. So instead of getting an IP with a space and then }, we now see in v15 the IP address includes a trailing } character. Any data group checking that IP will not match.

Recommended Actions

  1. You can modify the iRule code to strip off the trailing } character, by using the getfield function:
  when DNS_RESPONSE {
   set response [split [DNS::answer] ]
   set request [ lindex $response 4 ]
   set ipansweraddr [ getfield $request "\}" 1 ]

That final string will extract the IP address without the } character attached. The data group match should now work.
