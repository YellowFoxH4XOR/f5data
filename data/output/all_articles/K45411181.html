Topic

You should consider using this procedure under the following condition:

  • You have provisioned DNS Express to act as a high-speed, authoritative secondary DNS server.
  • You have a large number of DNS zones to import into the DNS Express engine.
  • You want to configure the BIG-IP system using the TMOS Shell (tmsh).

Description

The DNS Express engine is a high-speed, authoritative secondary DNS server. Using DNS Express, the BIG-IP system can answer remote client DNS queries, respond to zone transfer requests from authoritative DNS nameservers and secure zone transfers using transaction signature (TSIG) keys. You can fully configure DNS Express using tmsh Using tmsh can be helpful when a large number of DNS zones must be transferred from an authoritative DNS server. To configure DNS Express and the BIG-IP system as a secondary DNS server, create the necessary objects in the following order.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to tmsh.
  • Optional: You have obtained the TSIG key from the master DNS server.

Procedures

  • Creating a TSIG object (optional)
  • Creating a nameserver object
  • Creating a zone object
  • Creating a DNS request virtual server
  • Creating notify virtual servers (HA)

Creating a TSIG object (optional)

The TSIG object contains an authoritative DNS server's TSIG key and specifies the key's hash message authentication code (HMAC) algorithm. Each nameserver or zone object, created in the next procedures, can reference the TSIG object to perform secure zone transfers. Once you have obtained the authoritative DNS server's TSIG key and HMAC, create the TSIG key object by performing the following procedure:

Important: The TSIG key object name must be the same on both the BIG-IP system and the authoritative DNS server.

Impact of procedure: Performing the following option procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create the TSIG key object, use the following command syntax:

    create ltm dns tsig-key <key name> algorithm <hmac> secret <TSIG key>

    For example, to create a TSIG key named example.com.key created using the MD5 HMAC, type the following command:

    create ltm dns tsig-key example.com.key algorithm hmacmd5 secret p4wLo78ir1zTTmkYaEARs5DhS6K0aKxQZ3Y2GzHEMgk=

  3. Save the configuration by typing the following command:

    save sys config

Creating a Nameserver object

The BIG-IP system nameserver object defines an authoritative DNS server's IP address and the optional TSIG key. Each zone object, created in the next procedure, requires a nameserver object. To create a nameserver object, perform the following procedure:

Important: The authoritative DNS server must allow zone transfers from the BIG-IP system self IP address. Bind DNS servers use allow-transfer to restrict zone transfers.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create the nameserver object, use the following command syntax:

    create ltm dns nameserver <name> address <IP address> tsig-key <key name>

    For example, to create a nameserver object named ns.example.com with IP address 192.168.10.100 and the optional TSIG key named example.com.key, type the following command:

    create ltm dns nameserver ns.example.com address 192.168.10.100 tsig-key example.com.key

  3. Save the configuration by typing the following command:

    save sys config

Creating a zone object

The zone object represents a DNS zone on an authoritative DNS server. Once you create the zone object, DNS Express transfers the zone from the authoritative DNS server. To create a zone object and verify the zone transfer, perform the following procedure:

Important: This zone object name must be the same on both the BIG-IP system and the authoritative DNS server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create the zone object, use the following command syntax:

    create ltm dns zone <zone domain> dns-express-server <DNS server>

    For example, to create the zone object for a DNS zone named example.com and associate the nameserver object ns.example, type the following command:

    create ltm dns zone example.com dns-express-server ns.example

  3. Save the configuration by typing the following command:

    save sys config

  4. To verify the status of the zone transfer, use the following command syntax:

    show ltm dns zone <zone domain> | grep -A 3 Status

    For example, to view the status of the zone transfer for the example.com zone, type the following command:

    show ltm dns zone example.com | grep -A 3  Status

    In the following example, the example.com zone status indicates the zone is available and DNS Express performed a successful transfer:

      Status
        Availability : available
        State        : enabled
        Reason       : Successful AXFR

    If the zone transfer fails, the command output appears similar to the following example:

      Status
        Availability : offline
        State        : enabled
        Reason       : Failed transfer query
     

Creating a DNS request virtual server

You must create a UDP virtual server with an associated DNS profile to process remote client DNS resolution requests. If this is a standalone BIG-IP system, DNS notify messages from an authoritative DNS server can be processed as well. However, if your BIG-IP system is in a high availability (HA) configuration, you must create additional local-only virtual servers using the Creating notify virtual servers (HA) procedure to ensure all BIG-IP systems in the HA configuration receive and respond to DNS notify messages.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create the DNS request virtual server, use the following command syntax:

    create ltm virtual <name> destination <IP address>:53 profiles add { udp dns }

    For example, to create the DNS request virtual server named listen_example using IP address 192.168.10.200 and DNS port 53, type the following command:

    create ltm virtual listen_example destination 192.168.10.200:53 profiles add { udp dns }

  3. Save the configuration by typing the following command:

    save sys config

  4. To verify DNS resolution, use the following command syntax:

    dig @<IP address> <DNS domain>

    For example, to test DNS resolution for the example domain ns.example.com using the UDP virtual address 192.168.10.200, type the following command:

    dig @192.168.10.200 ns.example.com +short

    In the following example, the command output displays the correct IP address 192.168.10.100 for the example domain name ns.example.com:

    192.168.10.100

    If there are connectivity issues between the DNS client and the BIG-IP system listener, the response will appear similar to the following example:

    ; <<>> DiG 9.8.1-P1 <<>> @192.160.10.200 example.com
    ; (1 server found)
    ;; global options: +cmd
    ;; connection timed out; no servers could be reached

Creating notify virtual servers (HA)

If your BIG-IP systems are in an HA configuration, zone transfer updates will not be processed by standby BIG-IP systems when using only the DNS request virtual server. As a result, newly active BIG-IP systems may respond to DNS requests using stale DNS zone information. A UDP local-only virtual server must be created on each BIG-IP system in the HA configuration to respond to DNS notify requests from an authoritative DNS server. To create and test local-only virtual servers, perform the following procedure on all BIG-IP systems in the HA configuration:

Important: The destination IP addresses used for the local-only virtual servers must be the notify IP addresses used by the authoritative DNS server. Bind DNS servers use also-notify to determine which secondary DNS servers receive zone updates.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. 

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create the local-only virtual-address, use the following command syntax:

    Note: Defining a local-only virtual-address ensures a virtual server using this IP address will process notify messages in standby state. The virtual-address will not sync to other BIG-IP systems.

    create ltm virtual-address <IP address> traffic-group traffic-group-local-only

    For example, to create a local-only virtual address using IP address 192.168.10.201, type the following command:

    create ltm virtual-address 192.168.10.201 traffic-group traffic-group-local-only

  3. To create a virtual server with a destination IP address of the local-only virtual address to process DNS notify messages, use the following command syntax:

    create ltm virtual <name> destination <IP address>:53 profiles add { udp dns }

    For example, to create a virtual server named notify_example using IP address 192.168.10.201, type the following command:

    create ltm virtual notify_example destination 192.168.10.201:53 profiles add { udp dns }

  4. Save the configuration by typing the following command:

    save sys config

  5. To verify transfers for a particular zone are successful, determine the serial number of a zone file in DNS Express using the following command syntax:

    show ltm dns zone <name> | grep Serial

    For example, to determine the serial number of the zone named example.com, type the following command:

    show ltm dns zone example.com | grep Serial

    In the following example, the serial number for the example.com zone is 2017012345:

    Serial       : 2017012345

  6. On the authoritative DNS server, modify the serial number of a zone file and reload the DNS database to trigger a DNS notify message.
  7. Verify the serial number for the zone in DNS Express matches the serial number of the authoritative DNS server zone file:

    show ltm dns zone example.com | grep Serial

    In the following example, the serial number for the example.com zone is now 2017012346, indicating the notify message was successfully processed.

    Serial       : 2017012346

  8. Repeat these steps on each BIG-IP system in the HA configuration.
