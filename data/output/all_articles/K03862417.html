K03862417: CLEAR ERROR ''Fault detected in the AOM''

Type
Support Solution
Published
2022-04-15
Updated
2026-10-26
Applies to
  • VELOS Platforms
  • F5OS Products
Source
https://my.f5.com/manage/s/article/K03862417

Description

In the VELOS, or rSeries, device, the System Controller screen has an alarm that is coming and going, complaining of an AOM fault.

In the log file /var/log_controller/events/event-log.log, these logs can be seen:
65543 controller-2 aom-fault ASSERT ERROR "Fault detected in the AOM"
65543 controller-2 aom-fault EVENT NA "LOP Runtime fault detected: LOP is not receiving health reports from all installed VFC cards" 
65543 controller-2 aom-fault CLEAR ERROR "Fault detected in the AOM" 
65543 controller-2 aom-fault EVENT NA "No LOP Runtime fault detected: LOP is not receiving health reports from all installed VFC cards" 
--repeating--
 

Environment

  • F5OS/VELOS 1.1.2

Cause

No special conditions cause the transient error report for an AOM/LOP not receiving health reports from all installed fantrays and PSU controllers. It may occur at any time. These transient error reports do not indicate an AOM/LOP fault and can be safely ignored.
 

Recommended Actions

You can clear an AOM Fault using the following steps:

  1. Restart the alert-service by typing the following command:
    docker restart alert-service
  2. Send a clear command for the AOM Fault:
    docker exec alert-service /confd/test/sendAlert -n "AOM Fault" -s "appliance" -r clear -se error -i 65543 -d "Fault detected in the AOM"
  3. Send a clear command for the hardware fault (example for fan 9 and fan 10):
    docker exec alert-service /confd/test/sendAlert -n "HWfault" -s "fan-9" -r clear -se critical -i 65536 -d "Hardware device fault detected"
    docker exec alert-service /confd/test/sendAlert -n "HWfault" -s "fan-10" -r clear -se critical -i 65536 -d "Hardware device fault detected"

These commands will clear the AOM Fault and associated hardware faults. Ensure you verify the system health after performing these steps.
