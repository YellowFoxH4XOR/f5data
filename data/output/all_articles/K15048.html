Known Issue

The BIG-IP system ignores the tm.rejectunmatched db key and fails to send a TCP Reset (TCP RST) to packets that do not match a virtual server or an existing flow.

By default, the tm.rejectunmatched db key is set to true and the BIG-IP system should send a TCP RST in response to packets that do not match a virtual server or an existing flow. If the tm.rejectunmatched db key is set to false, the system silently drops unmatched packets.

Impact

The BIG-IP system fails to send a TCP RST to packets that do not match a virtual server or an existing flow.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When performing packet capture on the affected traffic, you observe that the BIG-IP system fails to respond to the unmatched packet with a TCP RST. The expected behavior is that the system responds to the unmatched packet with a TCP RST.
