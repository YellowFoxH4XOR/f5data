Topic

The BIG-IP ASM forensics screens may display up to 20,000 requests processed by the BIG-IP ASM. The ASM process, also known as bd, periodically cleans old requests from the forensics tables and archives them to the total_bad_msg.log system security log file. The BIG-IP ASM occasionally purges the total_bad_msg.log log file in order to preserve disk space.

You may want to view past requests from the archived security logs. For detailed information, you may also want to decode the information in the total_bad_msg.log file.

Viewing archived forensics information on the BIG-IP ASM system

To view archived forensics information on the BIG-IP ASM system, perform the following procedure:

  1. Log in to the BIG-IP ASM command line.
  2. Change directories to the BIG-IP ASM log file directory by typing the following command:

    cd /ts/log/

  3. To view the archived security log, type the following command:

    less total_bad_msg.log

Decoding the fields in the total_bad_msg.log file

Some of the fields in the total_bad_msg.log file are encoded. For detailed information, you may want to decode the fields in the total_bad_msg.log file.

To decode the fields in the total_bad_msg.log file, perform the following procedure:

  1. Log in to the BIG-IP ASM command line.
  2. To decode the encoded fields in the total_bad_msg.log file, type the following command:

    /ts/off_tools/decode_badmsg.pl -f /ts/log/total_bad_msg.log

  3. To change to the BIG-IP ASM log file directory, type the following command:

    cd /ts/log/

  4. To view the decoded total_bad_msg.log file, type the following command:

    less total_bad_msg.log.decoded

The information contained in the decoded log file is described in the following table:

Log entryDescription
<BAD_MSG>This log entry represents request information.
<account_id>4</account_id>This log entry represents information on the web application ID. This is how the web application is referenced within the database.
<all_status>141500000</all_status>This log entry represents an internal code of the request status.
<app_id>0</app_id>This log entry represents information on the web application ID and how it is referenced in the database.
<flg_blocked>1</flg_blocked>This flag indicates whether the request was blocked. A value of zero (0) indicates the request was not blocked.
<flg_truncated>0</flg_truncated>This flag indicates whether the request was truncated.
<method_code>2</method_code>This log entry represents the Internal code of the method which was used.
<obj_crc>1532874149771799972</obj_crc>This log entry represents the object checksum
<raw_request>POST /post.php.my2 HTTP/1.1This flag represents the raw request or the way the request was passed on the wire.

Host: 10.24.2.99
Connection: Keep-Alive
Content-Length: 4
0123
<req_end_offset>618</req_end_offset>This log entry indicates the length of request in bytes.
<response_code>0</response_code>This log entry indicates the response code of the web server.
<src_ip>fe02180a</src_ip>This log entry indicates the encoded source IP address of the client.
<status>141500000</status>This log entry indicates the internal status code.
<support_id>14353745265456840727</support_id>This log entry represents the unique support ID which was associated with the request.
<time>Wed Jan 10 09:32:51 2007</time>This log entry represents the date encoded.
<ts_cookie_name>TSe8652a</ts_cookie_name>This log entry represents the ASM cookie
<uri>/post.php.my2</uri>This log entry represents the URI requested encoded.
<request-violations>This section contains detailed information about the request violation.
<description>ILLEGAL_FILE_TYPE</description>This log entry describes the violation.
<extension>my2</extension>This log entry describes the POST file
<post_len>4</post_len>This log entry describes the POST length
<query_len>0</query_len>This log entry describes the query length
<status_code>100000000</status_code>This log entry represents the internal status code of the violation.
<uri_len>13</uri_len>This log entry describes the URI length
</BAD_MSG>This log entry indicates the end of information for this request.
