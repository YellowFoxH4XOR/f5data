K54751711: The Enable Port Remap feature in F5 SSL Orchestrator

Type
Knowledge
Published
2021-11-16
Updated
2023-02-21
Applies to
  • F5 App Protect
  • F5 SSL Orchestrator: 16.1.1
Source
https://my.f5.com/manage/s/article/K54751711

Topic

Most modern security products define a set of default actions for traffic arriving on different known ports. For example, a product assumes that traffic arriving on port 80 is unencrypted HTTP traffic and inspectable. However, the product assumes that port 443 is encrypted HTTPS traffic, so the product does not inspect it. If the SSL Orchestrator system decrypts HTTPS traffic and continues to send that unencrypted traffic on port 443 to the inline service, that service may continue to ignore it.

The Enable Port Remap setting provides a mechanism to temporarily remap the destination port of decrypted HTTPS traffic passing across this service. For example, you might use this setting to remap HTTPS traffic to port 8080 to allow the service to see this as inspectable HTTP traffic.

Description

In versions prior to BIG-IP 16.1.1 and SSL Orchestrator 9.1.0, when you configure Enable Port Remap for your services, the system remaps the port number while sending traffic to services for HTTP and HTTPS traffic. In some cases, the system remaps the port number for traffic that is not intercepted, which is SSL bypass.

Beginning in BIG-IP 16.1.1 and SSL Orchestrator 9.1.0, the system remaps the port number for only intercepted HTTP traffic. This change in behavior applies to only HTTP, HTTPS, and FTP protocol traffic.

Verify Enable Port Remap settings for a service

  1. Log in to the Configuration utility.
  2. Go to SSL Orchestrator > Configuration.
  3. Select Services.
  4. Review the Enable Port Remap settings for each service in the Port Remap column.

Verify whether traffic is intercepted or bypassed

  1. Log in to the Configuration utility.
  2. Go to SSL Orchestrator > Configuration.
  3. Select Security Policies.
  4. Select the security policy.
  5. Review the rules to determine if traffic is intercepted or bypassed.

Enable Port Remap requires matching L7 profile

When you enable the Enable Port Remap, a matching L7 profile is required for Interception Rules. For example, for HTTP traffic, an HTTP profile is required. This also applies to SMTP, FTP, IMAP, and so on. To verify whether your interception rule has a matching L7 profile, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to SSL Orchestrator > Configuration.
  3. Select Interception Rules.
  4. Select the name of a rule to verify.
  5. Expand Interception Rules by selecting it.
  6. Verify that the L7 Profile Type and L7 Profile has a matching L7 profile configured.

Additional Information

This change in behavior introduces a new setting named Connect on Data in the connector profile. A connector profile is associated with a virtual server for the SSL Orchestrator service and defines the Entry Virtual Server for that service. The Connect on Data parameter is automatically set when you configure the Enable Port Remap setting for the service on SSL Orchestrator Guided Configuration. You should not need to make changes manually in a connector profile. F5 recommends making changes through the SSL Orchestrator Guided Configuration.
