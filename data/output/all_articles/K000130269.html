K000130269: SSL Anonymous Cipher Suites Supported vulnerability

Type
Support Solution
Published
2022-12-19
Updated
2022-12-19
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.3
Source
https://my.f5.com/manage/s/article/K000130269

Description

When running a vulnerability scan of the BIG-IP against the virtual server IP, the SSL Anonymous Cipher Suites Supported vulnerability is getting flagged.


Environment

  • Vulnerability scan
  • ADH cipher


Cause

The configured cipher string in use on the clientSSL profile/s, which are attached to the concerned virtual server/s, is using the Anonymous Diffie Hellman (ADH) cipher.


Note: The DEFAULT cipher suite does not use the ADH cipher. So most likely, you're using a custom cipher string (other than DEFAULT) in your clientSSL profile; hence you're running in to this Anonymous Cipher Suites vulnerability.


 Recommended Actions

1. To view the list of cipher suites supported by the configured cipher string, run this command:

# tmm --clientciphers '<cipher_string'>

 

For example, if the cipher string is HIGH:!RSA:!DES:!TLSv1:!TLSv1_1:!SSLv3:!ECDHE-RSA-AES256-CBC-SHA, the command will be:

# tmm --clientciphers 'HIGH:!RSA:!DES:!TLSv1:!TLSv1_1:!SSLv3:!ECDHE-RSA-AES256-CBC-SHA'


In this case, since we're specifically looking for ADH, we can further filter the results by doing a grep for ADH:

# tmm --clientciphers 'HIGH:!RSA:!DES:!TLSv1:!TLSv1_1:!SSLv3:!ECDHE-RSA-AES256-CBC-SHA' | grep ADH



2. To address this vulnerability, append :!ADH to the existing cipher string to block the ADH cipher. The 'modified' cipher string will look like the below:


HIGH:!RSA:!DES:!TLSv1:!TLSv1_1:!SSLv3:!ECDHE-RSA-AES256-CBC-SHA:!ADH


For more information/examples on how to configure the cipher string, refer to K01770517
