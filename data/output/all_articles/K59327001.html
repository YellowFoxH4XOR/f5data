Known Issue

When you enable SSL Persistence, the BIG-IP system does not properly reassemble fragmented SSL ClientHello messages.

This issue occurs when all of the following conditions are met:

  • You have enabled SSL Persistence.
  • There is no Client SSL or Server SSL profile configured with the virtual server.
  • The BIG-IP device receives fragments of a ClientHello message (typically 11 bytes each) from an SSL front-end client.

Impact

The parser fails to reassemble the fragmented ClientHello messages before passing them on to the back-end server.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The back-end server rejects the incomplete ClientHello message, rejects the SSL handshake, and terminates the connection.

Workaround

To work around this issue, you can disable SSL Persistence.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
