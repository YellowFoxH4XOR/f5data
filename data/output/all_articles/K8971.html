Topic

A transparent health monitor forces the BIG-IP system to ping through a transparent network device with which it is associated (usually a firewall) to a destination device. This behavior allows the transparent device to be tested, and, if there is no response from the destination device, the BIG-IP system marks the transparent device down.

Note: The BIG-IP system does not require a specific route to the destination device. However, the transparent device must be on a network adjacent to the BIG-IP system, and it must be able to route to the destination device. If the transparent device is not on a network adjacent to the BIG-IP system, the BIG-IP system use its default gateway (if any) to reach the destination. Therefore, there is a possibility of the system marking a non-adjacent destination as up if the system receives a successful response through the default gateway.

Description

Transparent ICMP monitors

Transparent Internet Control Message Protocol (ICMP) monitors are useful if you want to use ICMP to make a simple node check through a transparent network device to the destination device without specifying a service port for the destination device. Create a transparent ICMP monitor if you want to associate the monitor with a node only.

Note: You can associate a transparent ICMP monitor with a node only, and not a pool member.

For example, you may want to check the status of a transparent firewall 10.0.2.101, which is a defined node on the BIG-IP system, by pinging through the firewall to destination router 10.51.100.1. To do this, create an ICMP monitor in which you specify 10.51.100.1 as the monitor Alias Address, and set the Transparent setting to Yes. You can then associate the monitor with the transparent node, 10.0.2.101.

  • Use the Configuration utility to create a transparent ICMP monitor
  • Use tmsh to create a transparent ICMP monitor

Use the Configuration utility to create a transparent ICMP monitor

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. Enter a name for the monitor.
  5. For Type, select ICMP.
  6. For Configuration, select Advanced.
  7. For Transparent, select Yes.
  8. For Alias Address, enter the IP address of the destination device. For example, 10.51.100.1.
  9. Select Finished.

You should now associate the transparent ICMP monitor with the transparent node that you want the BIG-IP system to monitor.

Use tmsh to create a transparent ICMP monitor

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Create the transparent ICMP monitor using one of the following command syntaxes:

    BIG-IP 11.0.0 and later

    create /ltm monitor icmp <monitor_name> defaults-from /Common/icmp destination <IP address> transparent enabled

    For example:

    create /ltm monitor icmp my_icmp defaults-from /Common/icmp destination 10.51.100.1 transparent enabled

    BIG-IP 10.0.0 through 10.2.4

    create /ltm monitor icmp <monitor_name> defaults-from icmp destination <IP address> transparent enabled

    For example:

    create /ltm monitor icmp my_icmp defaults-from icmp destination 10.51.100.1 transparent enabled

  3. Save the change by entering the following command:

    save /sys config

You should now associate the transparent ICMP monitor with the transparent node that you want the BIG-IP system to monitor.

Transparent gateway ICMP monitors

Transparent gateway ICMP monitors are useful if you want to use ICMP to check the network path through a network device configured as a pool member, to a remote end-point that will respond to the ICMP monitor. Create a transparent gateway ICMP monitor if you want to associate the monitor with a pool or pool member.

For example, you may want to check the status of a transparent firewall 10.0.2.101, which is a defined pool member on the BIG-IP system, by pinging through the firewall to destination router 10.51.100.1. To do this, create a gateway ICMP monitor in which you specify 10.51.100.1 as the monitor Alias Address, and set the Transparent setting to Yes. You can then associate the monitor with the transparent pool member.

  • Use the Configuration utility to create a transparent gateway ICMP monitor
  • Use tmsh to create a transparent gateway ICMP monitor

Use the Configuration utility to create a transparent gateway ICMP monitor

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. Enter a name for the monitor.
  5. For Type, select Gateway ICMP.
  6. For Configuration, select Advanced.
  7. For Transparent, select Yes.
  8. For Alias Address, enter the IP address of the destination device. For example, 10.51.100.1.
  9. Leave the Alias Service Port setting as * All Ports.
  10. Select Finished.

You should now associate the transparent gateway ICMP monitor with the pool or pool member that you want the BIG-IP system to monitor.

Use tmsh to create a transparent gateway ICMP monitor

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create the transparent gateway ICMP monitor using one of the following command syntaxes:

    BIG-IP 11.0.0 and later:

    create /ltm monitor gateway-icmp <monitor_name> defaults-from /Common/gateway_icmp destination <IP address:port> transparent enabled

    For example:

    create /ltm monitor gateway-icmp my_gateway_icmp defaults-from /Common/gateway_icmp destination 10.51.100.1:* transparent enabled

    BIG-IP 10.0.0 through 10.2.4:

    create /ltm monitor gateway-icmp <monitor_name> defaults-from gateway_icmp destination <IP address:port> transparent enabled

    For example:

    create /ltm monitor gateway-icmp my_gateway_icmp defaults-from gateway_icmp destination 198.51.100.1:* transparent enabled

  3. Save the change by entering the following command:

    save /sys config

You should now associate the transparent gateway ICMP monitor with the pool or pool member that you want the BIG-IP system to monitor.
