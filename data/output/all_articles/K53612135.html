Known Issue

By default, the system assumes that URL Filtering or Secure Web Gateway (SWG) is licensed and provisioned. However, if URL Filtering or SWG is not provisioned or the license is expired, then the policy does not forward any traffic. This article describes how to use SSL Orchestrator without licensing URL Filtering or SWG.

Impact

If URL Filtering is not licensed, the default security policy does not pass HTTPS traffic.

Workaround

Impact of workaround: When you change configuration of certain objects, the system re-deploys the various BIG-IP objects to match your new configuration. This re-deployment overwrites any existing BIG-IP objects without warning about existing changes. Before performing this procedure, you must first refer to the warnings and directions in the Disabling Strict Updates section of K00805840: SSL Orchestrator known issues and workarounds.

Note: If URL Filtering or SWG is not enabled, you can only filter based on custom URL categories.

Modifying the per-request policy to process custom categories only

  1. Navigate to SSL Orchestrator > Policies > Access Per-Request Policies.
  2. Find ssloP_<chain name>_prpTcp.

    Note: You can filter by typing the policy name in the box and clicking Search.

  3. Under Per-Request Policy, click the + icon next to Show All.
  4. Click ssloP_<chain name>_prpTcp.

    The Visual Policy Editor opens.

  5. In the Categorization macro, open each of the Category Lookup Policy items and verify that the Category Lookup Type is set to Process custom categories only.
  6. Click Save for each policy item if you're making a change.
  7. Click Close.
