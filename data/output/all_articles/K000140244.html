Description

BIGIP APM administrator may notice the below errors in CTU report under logterminal.txt log file and wondered what triggered the error:

2024-06-28,10:03:58:655, 10204,10832,DIALER, 48, \UFilterService.cpp, 191, UFilterService::Connect(), Connected to F5 DNS Relay Proxy service.
2024-06-28,10:03:58:655, 10204,10832,DIALER, 48, \URDialer.cpp, 5046, CURDialer::PatchDNSSettings(), DNS Servers and Access Patterns, 10.1.1.1, test
2024-06-28,10:03:58:731, 10204,10832,DIALER, 48,,,, UFilterService::SetVPNDNSAccessPattern(), Access pattern set. dns_address=10.1.1.1, pattern=test
2024-06-28,10:03:58:732, 10204,10832,DIALER, 1,,,, UFilterService::DynamicUpdatePacketFilterSet:Run-time exception.Exception code=0x6B5
2024-06-28,10:03:58:732, 10204,10832,DIALER, 1, \URDialer.cpp, 5145, CURDialer::DynamicUpdatePacketFilterSet, CURDialer::DynamicUpdatePacketFilterSet failed (error 1717)

Environment

  • APM

  • VPN

Cause

The error happens due to improper value placed in 'DNS Address Space' setting under network-access resource.  The network-access resource with incorrect entry which resulted to the above error may look like the below configuration:

apm resource network-access na_res {

[...]

    address-space-include-dns-name { test } <--- (!) incorrect, must be fqdn entry (for example, test.com or *.com)

[...]

    dns-primary 10.1.1.1

[...]

    split-tunneling true

}

Recommended Actions

Make sure that unqualified hostname entries are not put under 'DNS Address Space' setting (aka 'address-space-include-dns-name' as per CLI).
