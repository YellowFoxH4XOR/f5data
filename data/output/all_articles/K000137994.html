K000137994: ASM might stop processing the traffic after removing ASM license and provisioning and then again restoring ASM license and provisioning

Type
Support Solution
Published
2023-12-21
Updated
2026-02-25
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.X, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000137994

Description

  • No Security Event Report logs are generated
  • ASM is not processing the traffic

Logs similar to following can be found in var/log/ts/bd.log

IO_PLUGIN|NOTICE|Oct 27 15:28:02.184|14948|io_plugin.c:0900|Stop Full HTTP license_mode.
IO_PLUGIN|NOTICE|Oct 27 15:28:02.184|14950|io_plugin.c:0900|Stop Full HTTP license_mode.
IO_PLUGIN|NOTICE|Oct 27 15:28:02.184|14951|io_plugin.c:0900|Stop Full HTTP license_mode.
IO_PLUGIN|NOTICE|Oct 27 15:28:02.184|14949|io_plugin.c:0900|Stop Full HTTP license_mode.

Environment

  • ASM is licensed and provisioned.
  • Remove ASM license and provisioning.
  • Restore ASM license and provisioning.

Cause

The exact root cause is undetermined. A similar issue was previously tracked under Bug ID 555912 and was addressed in version 12.1.0. No confirmed recurrence or direct relationship has been established in later versions such as 17.1.x.

https://cdn.f5.com/product/bugtracker/ID555912.html

For version v17.x, we have opened ID1975909 to track this issue. You can find more details here: https://cdn.f5.com/product/bugtracker/ID1975909.html.

Recommended Actions

  1. Capture fresh qview before taking any other actions
  2. To resolve the issue restart ASM  - # tmsh restart sys service asm
  3. Open service request to F5 Support and provide qkview generated

Impact of workaround: ASM restart will cause traffic processing disruption. It is recommended to schedule a Maintenance Window for this activity.

Additional Information

With the qkview taken when the issue is present F5 Support can continue to identify the root cause of the issue.
