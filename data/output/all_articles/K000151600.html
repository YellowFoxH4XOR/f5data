K000151600: System Controller Fails to Complete Upgrade and stuck In-Progress

Type
Support Solution
Published
2025-05-30
Updated
2025-06-03
Applies to
  • F5OS
  • F5OS-C: 1.6.0, 1.6.2, 1.6.1, 1.6.X, 1.8.X, 1.8.1, 1.8.0
Source
https://my.f5.com/manage/s/article/K000151600

Description

After upgrading an F5 VELOS Chassis from F5OS version 1.6.2 to 1.8.0, a system controller may remain in an "In Progress" state for an extended period and fail to complete the upgrade or join the cluster.

Following error messages may be observed in /var/log/sw-util.log  

   Failed to create LV for partition 1.
   Failed to create LV for partition 2.
   docker container doesn't exist container_name="part_2_part_vers_1.8.0-26321_vers"
   Error syncing module iso_imports (return code 10)
   Error syncing module os_imports (return code 10)
   Error syncing module services_imports (return code 10)
   Error syncing module eventLog (return code 10)

 

Additionally, the partition_image volume may be missing on the affected controller, and attempts to upgrade or recreate the partition may fail.



 

Environment

  • F5OS version 1.8.0 (upgrade from 1.6.2)
  • Configuration: Multi-controller chassis with partitions
  • Symptom occurs during or after system upgrade

 

Cause

Bug ID 1827869: Partition upgrade or creation fails on controller

 

Recommended Actions

 

1.) Force Reboot of Affected Controller

Attempt a force reboot using sysrq commands as described in F5 article K000130542:

echo s > /proc/sysrq-trigger

echo u > /proc/sysrq-trigger

echo b > /proc/sysrq-trigger

Wait at least 10 minutes for the controller to restart.

 

2.) Check ISO Files and Manually Trigger Upgrade

  • Verify correct .iso files are present under the directory (e.g. /var/export/chassis/import/iso/).
  • Manually trigger software upgrade:

/usr/share/sw-mgmt/sw-util.sh switch_agnostic_os <version>

tail -f /var/log/sw-mgmt/sw-util.log # Look for "Update complete" message

reboot

/usr/share/sw-mgmt/sw-util.sh switch_agnostic_services <version>

 

3.) Manual Partition Volume Creation Script

If logical volumes cannot be created (errors like "Failed to create LV for partition X"), run a script provided by F5 Support on the affected controller to wipe and recreate partition_image. For script, contact F5 Support for the latest version and guidance.

  • The script must be run as root on the affected controller.
  • After running the script, reboot the controller and attempt to recreate the partition.

4.) PXE Boot Recovery

If the above steps do not resolve the issue, perform a PXE boot of the affected controller to reinstall the system image.

  • PXE boot will result in a clean installation; configuration and partitions must be restored from backup.
  • After recovery, verify presence of the partition_image volume and restore configuration/BIG-IP partition backups as needed.

 

5.) Post-Recovery Actions

  • After recovery, verify presence of the partition_image volume.
  • Restore configuration/BIG-IP partition backups as needed.

 

6.) Upgrade Recommendation

  • This bug is fixed in future releases; plan to upgrade when a fixed version is available.

 

Additional Information

  • This issue is rare and may not occur on all upgrades.
  • The workaround may require assistance from F5 Support, especially for the script and PXE boot steps.
  • The root cause is a metadata mismatch during LVM to VDO conversion, which prevents the partition_image volume from being created on the affected controller.
