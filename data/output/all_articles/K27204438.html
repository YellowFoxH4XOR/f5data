Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when an iRule uses a parking command.

This issue occurs when one of the following conditions are met:

  • A virtual server is configured with a OneConnect profile and an iRule configuration, which contains one of the following:
    • Commands that may temporarily suspend iRule processing.
    • The tcl catch command in the client side or server side context, where the commands that are run within the peer context raise an error.
  • A virtual server is configured with a NT LAN Manager (NTLM) profile. The NTLM profile also utilizes parking.

    Note: The NTLM profile might be deployed automatically if you are using a SharePoint iApp.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high-availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H560494 on the Diagnostics > Identified > Medium screen. 
  • Your BIG-IP system fails over to the standby system if configured for HA.
  • Your BIG-IP system generates TMM core files to the /shared/core directory, with a time stamp that correlates to the traffic interruption, similar to the following example:

    tmm.0.bld3.36.412.core.gz
