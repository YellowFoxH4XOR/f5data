Description

Your URL ends with a segment containing a period (e.g., /foo/abd.def), but the text following the period is part of the URL path, not a file type. You are getting Illegal file type violation triggered for these requests. This behaviour is by design and aligns with the HTTP standard. ASM treats the string following the last period in a URL as the file type.

Environment

  • BIG-IP ASM
  • Illegal File Type Violation

Cause

None, expected behaviour.

Recommended Actions

There are few possible options we can think of.

  1. Check with application team on adjusting the URLs to standard guidelines, few examples below. (Recommended approach)
    • Use the name as a parameter rather than a part of the URL 
      • Existing: /foo/abd.def
      • Modified: --> /foo?param=abd.def
    • Remove the period(.) character and use different character
      • Existing: /foo/abd.def
      • Modified: --> /foo/abd_def
  2. If the application changes take time, a possible workaround would be to create a wildcard (*) file type in the policy. Requests of these kind will be matched accordingly.
    • Security ›› Application Security : Security Policies : Policies List ›› <Policy Name>: HTTP Message Protection:File Types ›› Create allowed File Type ›› Wildcard (*)

Note: Keep this in staging for a period of time and ensure no false positive violations occur for other traffic, then you can change this to enforced.
