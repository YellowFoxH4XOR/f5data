K000139870: Troubleshoot the OpenShift cluster installation in F5OS-C

Published
2024-06-04

Applies to

  • F5OS-C: 1.6.2, 1.6.1, 1.6.0
Source

Description

It may be necessary for F5OS-C to rebuild the OpenShift cluster as part of a install process. Apart from that, you may also need to do so manually to resolve issues such as:

K64001020: Certificates on VELOS blades expire after one year and cause blades and tenants to go offline

To manually trigger a cluster rebuild, you enter the following command:
touch /var/omd/CLUSTER_REINSTALL

The process typically takes around 90-110 mins. To troubleshoot any issues, use the show cluster command on confD. You may observe any of the following messages:

  • cluster orchestration-manager cluster-initialized false
    cluster orchestration-manager cluster-ready false

  • controller-1.chassis.local  true      false    false    true  true  Not In Cluster
    controller-2.chassis.local  true      false    false    true  true  Not In Cluster

  • cluster cluster-status summary-status "OpenShift cluster is NOT initialized."

These message indicate a cluster re-installation may already be in progress or the operation encountered an issue and require manual intervention. Use the recommendations in this article to troubleshoot cluster issues.

Environment

  • OpenShift cluster reinstall
  • F5OS-C system, manual triggered cluster reinstall
  • Tenants on F5OS-C cannot deploy

Cause

The OpenShift cluster reinstall can encounter issues due to a variety of reasons.
Note: While hardware faults may cause issues, in most cases the issues are software related and can be resolved by performing the verifications described in the following section.

Recommended Actions

Preparation

Perform the following to prepare the reinstallation on your F5OS-C system:

  • As tenants on F5OS-C are down during the process, you should perform this only during a scheduled maintenance window.
  • Ensure you have a backup of your VELOS chassis, partition data and all tenants. Refer to K50135154: Back up and restore the F5OS-C configuration on a VELOS system
  • Shutdown all tenants in all partitions on the F5OS-C system by setting their running-state to provisioned.
  • Perform procedures on the active controller by using the management floating IP address. For example, you enter touch /var/omd/CLUSTER_REINSTALL only on the active system controller to start the reinstallation process

Verification

Perform the following verifications before you reinstall the cluster. Alternatively, if the reinstall process has already begun and there are issues, use the following section to troubleshoot.

  • Verify the management IP address is accessible for both system controllers. Display the management IP address by entering the following command on confD:
    show system mgmt-ip

    To configure the management IP address, refer to K000132218: [F5OS] Initial configuration of management IP via CLI on an rSeries/VELOS system

  • Verfiy root and admin credentials
    • Verify you can login as root on the CLI with the same password to both system controllers and all partitions.
    • Verify you can login as admin on the GUI with the same password to both system controllers and all partitions.
    • Verify that you can login to all blades: ssh blade-X

  • Ensure high availability is configured and working for both controllers. Refer to K21130014: Managing high availability for the VELOS system controllers

  • Use the following commands to verify the health of the system:
    Note: When cluster reinstallation is in progress, nodes and pods may not be ready.
    • oc get nodes
    • kubectl get pods --all-namespaces

Troubleshooting

  • Follow the installation progress using the following commands
    • tail -f /var/log/openshift.log
      You may observe the system logging a large number of entries into this file during the cluster installation process. To get a summary of the status use the following commands:
      • tail -f /var/log/openshift.log | grep -A10 "INSTALLER STATUS"
      • grep -A10 "INSTALLER STATUS" /var/log/openshift.log
    • On confD, use show cluster. For the full output of a healthy VELOS system, refer to K27427444: Viewing the status of a VELOS system using the CLI
      In particular, review the output of show cluster cluster-status, for the following:
      • the sequence of events in the cluster installation process
      • the time it takes for each process and the total time taken

  • The /var/<directory>/omd directory contains files that indicate the status of the cluster. For example,
    • /var/omd/CLUSTER_INSTALLED: the cluster is installed.
    • /var/omd/MULTUS_INSTALLED: MULTUS is installed
    • /var/omd/CLUSTER_REINSTALL: touch this file for manual reinstall
    • /var/omd/MULTUS_REINSTALL: touch this file for manual reinstall
    • /tmp/omd/pause: Reinstallation is paused. For more information, refer to K000132473: [F5OS-C] Openshift rebuild/reinstall does not start.

  • Review /var/log/message on the affected system controller or blade when they are unable to join the cluster.
    Reboot the affected system controller or blade.

  • Reseat the affected system controller controller or blade.
    The reinstallation process typically takes around 90-110 mins. If you observe from /var/log/openshift.log, that the process continues to run significantly longer than that (2.5 hours or more for example) and the output of show cluster cluster-status indicate either the system controller or blade unable to join the cluster, review the list of verifications listed above again. In rare cases, you may need to reseat the system controller or blade that requires reinitialization.

After the cluster reinstall is complete, you should disable and re-enable all chassis partitions before setting the running-state of all tenants back to deployed to ensure they have restarted correctly after the cluster rebuild.
