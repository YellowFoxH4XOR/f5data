Description

A user is getting a Support ID that when checked in the Bot Event Logs shows the violation is due to Browser verification timed out .

Environment

  • When using any browser the webpage does not load or login fails with a Support ID provided.
  • AdvWAF Bot Defense Browser Challenge

Cause

The system detects a possible Malicious Bot due to a an identified anomaly...Browser verification timed out. This happens when a client browser fails to complete the browser challenge in the specified time period. This can happen one of 2 ways...

  1. By default there is a 30 second time limit for the verification to take place. This is done by injecting a TSPD_101 cookie that sets a time limit.
  2. In some cases this is set up to use Captcha. In that case there is a 120 second time out default value.

Answer/Recommended Actions

There are 5 possible ways to deal with this when it happens.

  1.  Leave it as is. This could be a real attempt to try and find a way into your network. 
  2. There are some db variables that can be adjusted.
    1. You could increase the 30 second time out value using botdefense.max_js_verification_seconds 
      1. This is a system wide setting and would effect all policies and all traffic.
    2. Increase the amount of time for the Captcha to take place if that anomaly is set to use it. That takes place using dosl7.max_captcha_solution_time 
      1. This is a system wide setting and would effect all policies that use a Captcha setting and all traffic. 
      2. By default the Suspicious Browser setting is Captcha. But some settings within that are more restrictive. Browser verification timed out is one of those. By default it is set to block.
  3. Set the Browser Verification to None.
    1. This is done by going in the Policy itself Security >> Bot Defense >> <bot policy> :: Browsers :: Browser Verification.
    2. This would effect all browser verification for the policy. You can review all of the setting choices here... K42323285: Overview of the unified Bot Defense profile :: Browser Verification
  4. Whitelist the URL, IP, or Geolocation...Configuring Bot Defense
    1. This would effect only the specific policy but it would effect all traffic that uses that URL, IP, or Geolocation.
  5. Create a Bot Mitigation Setting
    1. This is done by going into the Policy itself Security >> Bot Defense >> <bot policy> :: Bot Mitigation Settings :: Mitigation Settings Exceptions.
    2. Click on "Add Exception" and then search for Browser verification timed out. Check the box and then click Add.
    3. In the dropdown there are 7 settings you can choose from 
      1. They are explained in  K42323285: Overview of the unified Bot Defense profile :: Mitigation Settings
    4. Then click Save to add it to the policy.
      1. This is the least invasive way to deal with this. It would only effect that anomaly for this policy.
