Description

A BIG-IP LTM tenant remains in Pending status and cannot start. The deployment reports:

Insufficient available cpus on node, retrying tenant deployment

This can occur when a tenant’s effective runtime CPU allocation is higher than its configured vcpu-cores-per-node value, leaving insufficient CPU capacity for another tenant.

Environment

  • F5OS system hosting multiple BIG-IP LTM tenants.
  • Multiple tenants share the available CPU resources.
  • One tenant configured with:
    • vcpu-cores-per-node: 2
    • Memory: 7680 MB
    • running-state: deployed
  • Another tenant was provisioned with four vCPU cores and was later configured for two vCPU cores.

Cause

A tenant was provisioned with four vCPU cores and then changed to two vCPU cores while provisioning was in progress. The effective runtime allocation did not initially match the updated configuration and consumed CPU resources required by another tenant.

Relevant log messages included:

new-vcpu=4

Tenant field changed ... oldval="4" newval="2"

Insufficient available cpus on node, retrying tenant deployment

The orchestration logs also reported a tenant configuration sequence mismatch and a subsequent virtual machine patch.

Recommended Actions

  1. Set the affected tenants to the Provisioned state in the F5OS WebUI.
  2. Wait until the tenants stop completely (about 3 - 5 minutes).
  3. Change the tenant’s CPU allocation from two to four vCPU cores.
  4. Wait for the configuration change to complete.
  5. Change the CPU allocation back from four to two vCPU cores.
  6. Verify that the effective runtime allocation is two vCPU cores and matches the tenant configuration.
  7. Deploy the affected tenants again.
  8. Verify that the tenants reach the running state and that the insufficient-CPU message is no longer reported.

Additional Information

  • Avoid changing tenant CPU or memory allocations while tenant provisioning is in progress.
  • After changing resource allocations, verify that the effective runtime values match the configured values before deploying additional tenants.
