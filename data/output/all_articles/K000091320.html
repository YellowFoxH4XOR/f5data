K000091320: Failing SSO with Azure when APP protect is ON

Support Solution
Published
2022-03-12
Updated

Status

Applies to

  • NGINX App Protect WAF: 3.5.0
Source
https://my.f5.com/manage/s/article/K000091320

Description

subrequest errors seen when accessing /_jwks_uri which is part of the OpenID Connect (OIDC) implementation, similar to:

... failed to fetch JWK set, client: 10.0.0.1, server: localhost, request: "GET / HTTP/1.1", subrequest: "/_jwks_uri", host: "datagateway.example.com", referrer: "https://login.microsoftonline.com/"

Environment

NGINX+
NGINX App Protect
subrequest directive used in same server block as app_protect_enable on;

Cause

The OIDC works with subrequests to get auth tokens against IdP (authentication sake).
The app_protect doesn’t work well with subrequest when both enabled on the same location.

Recommended Actions

Split the app_protect_enable and the auth_request directives to two servers.

Additional Information

This is an example of unsupported configuration:
https://docs.nginx.com/nginx-app-protect/configuration-guide/configuration/#unsupported-configuration

Please see online documentation about this and possible workarounds:
https://docs.nginx.com/nginx-app-protect/configuration-guide/configuration/#configure-client-authorization
