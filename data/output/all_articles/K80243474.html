Description

When navigating to the ASM Security Policies list, a message is displayed:

ASM Critical Warning
An upgrade process was interrupted. It is very likely that ASM will start with a severe inconsistent internal state and critical errors.
 

It is also not possible to import a policy onto the system.

Environment

  • Security Policies List
  • GUI

Cause

This message has various root causes, but typically appears when a UCS load operation was unsuccessful, and the ASM security policy configuration was lost. It is most common for this to occur if something went wrong with a software upgrade.

Recommended Actions

It is usually sufficient to restore the configuration by loading a known good UCS file, as explained in:

  • K14164332: ASM Critical Warnings : An upgrade process was interrupted. It is very likely that ASM will start with a severe inconsistent internal state and critical errors.

However, in some cases the original cause of the message may be due to a UCS or configuration load/save stalling, and that process may still be running. In this scenario, it may not be possible to save or load a UCS file.

Verify if there are any stalled attempts to save or load the configuration, by reviewing the output of the ps aux command:

ps aux | grep -E 'PID|tmsh (save|load)'

Under normal operating conditions you will see a single process returned - the grep. If there are other processes, it is possible they are stalled and will hinder attempts to resolve the issue.

Use the kill command to kill the stalled processes. Alternatively use killall:

killall -9 tmsh

Note: This might disconnect you from the command line.

Once the stalled processes have been killed, it should be possible to load a UCS file. Alternatively, if an upgrade was performed you can roll back to the previous volume and try again.
