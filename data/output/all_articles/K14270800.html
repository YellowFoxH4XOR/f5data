Description

The Azure BIG-IP VM deletes configuration after a reboot. This can break password based SSH connectivity as the default config load wipes out the MCPD configuration.

A "load sys config default" is reported in /var/log/ltm that wasn't initiated by the user manually.

Environment

  • BIG-IP is running in Azure.

  • Known affected versions: 12.1.0, 12.1.0 HF1, 12.1.0 HF2, 12.1.1, 12.1.1 HF1, 12.1.1 HF2, 12.1.2, 12.1.2 HF1, 12.1.2 HF2, 12.1.3, 12.1.3.1, 12.1.3.2, 12.1.3.3, 12.1.3.4, 12.1.3.5, 12.1.3.6, 12.1.3.7, 12.1.4, 12.1.4.1, 12.1.5, 12.1.5.1, 12.1.5.2, 12.1.5.3, 12.1.6, 13.0.0, 13.0.0 HF1, 13.0.0 HF2, 13.0.0 HF3, 13.0.1

Cause

Bug ID 709471: Azure: A failure to load mcpd configuration during the startup triggers "load sys config default" after an hour, if the config load failure is not corrected.
 

Recommended Actions

  1. If the user has access to the BIG-IP, they should try to fix the "load sys config" failure manually by modifying the mcpd configuration in /config/*.conf files. This would prevent the eventual "load sys config default".

  2. If the user doesn't have access to the BIG-IP, there isn't really a workaround for this issue, but to restore the backup of the Azure instance, if not possible a new instance will be required.
