Known Issue

A simultaneous stats query and pool configuration change causes the mcpd process to restart on the secondary blades.

This issue occurs when all of the following conditions are met:

  • The affected VIPRION system has two or more blades installed.
  • You perform parallel operations in the Traffic Management Shell (tmsh) and Configuration utility or multiple tmsh operations on pool objects.

    For example, running the tmsh show ltm pool <pool_name> command while simultaneously editing the pool in the Configuration utility.

Impact

The VIPRION system temporarily fails to process traffic while the mcpd process restarts on all secondary blades.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H509300 on the Diagnostics > Identified > High page.
  • Traffic processing may be disrupted temporarily on the affected VIPRION system.
  • The mcpd process on all secondary blades restarts and logs error messages to the /var/log/ltm file.

    For example:

    err mcpd[1234]: 01070734:3: Configuration error: Configuration from primary failed validation: 01020036:3: The requested pool (/Common/pool1) was not found.
    notice mcpd[6789]: 0107092a:5: Secondary slot 1 disconnected.

Workaround

To work around this issue, you can use the absolute name of the pool (/partition_name/pool_name) in tmsh commands.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
