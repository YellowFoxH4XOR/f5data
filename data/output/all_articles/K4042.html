Topic

The L2TP/IPSec VPN client uses IP Security Protocol (IPSec) in transport mode with an Encapsulating Security Payload (ESP) header but no Authentication Header (AH). AH includes integrity protection over the IP header, while ESP does not. This means that changing the destination IP address (for example, when a virtual server translates the destination address from the virtual server address to the node address) will not cause an L2TP/IPSec connection to fail.

L2TP/IPSec connections fail during ISAKMP Phase 2, when IP addresses are exchanged and used to create dynamic IPSec filter entries at the ISA Server. The client receives the real server address in this exchange and since this does not match the configured destination address (the BIG-IP virtual address), the client will reject the connection, suspecting a man-in-the-middle attack.

One way to work around this is configure clients to use NAT traversal (NAT-T). NAT traversal makes both parties NAT aware, encapsulating IPsec within a UDP wrapper on port 4500 and correcting TCP or UDP header checksums that would otherwise be invalidated by translation.
