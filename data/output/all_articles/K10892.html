Known Issue

This is the result of a known issue. If you enable the Delete FirePass account if user is not in LDAP option for the LDAP dynamic group mapping method, the FirePass controller does not delete local user accounts when the corresponding external user accounts are removed from the LDAP server.

Note: The Delete FirePass account if user is not in LDAP option only appears if the Synchronize FirePass user database with LDAP check box is selected for the LDAP dynamic group mapping method.

F5 Product Development tracked this issue as CR134072 and it was fixed in FirePass controller 7.0.0. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue has been fixed in cumulative hotfix HF-610-1, which has been issued for FirePass 6.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by manually deleting obsolete user accounts on the Users: User Management page.
