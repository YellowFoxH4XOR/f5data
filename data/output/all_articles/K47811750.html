Description

When ASM Sync is enabled, a Changes Pending state automatically returns, seconds after performing a ConfigSync.

On one device in the group, you observe messages similar to the following example in /var/log/asm shortly after each sync:

info perl[25593]: 01310053:6: ASMConfig change: Security Policy /Common/sec_policy_prod [add]: Parent Policy was set to /Common/web_security_parent.
info perl[25593]: 01310053:6: ASMConfig change: Security Policy /Common/sec_policy_prod [delete] { audit: component = tsconfd }

The security policy itself doesn't appear to exist on any device when reviewing the ASM configuration, and might have been manually deleted some time ago.

Environment

  • ConfigSync

Cause

One or more devices in the group has an mcpd configuration stub for this security policy in /config/bigip.conf:

asm policy /Common/sec_policy_prod {
    encoding utf-8
    parent-policy /Common/web_security_parent
    policy-template POLICY_TEMPLATE_FUNDAMENTAL
}

Recommended Actions

Perform a full sync to the device group, using the force-full-load-push option, from a device where the mcpd stub for the policy does not exist in /config/bigip.conf:

tmsh run cm config-sync to-group <group> force-full-load-push

Additional Information

This article describes one of various reasons why a Changes Pending state might return shortly after performing a ConfigSync.

Another common cause is using the Session Awareness feature, or using Automatic Learning mode. See the following articles for more information:

  • K92462725: BIG-IP ASM HA devices constantly showing "changes pending", even after performing a sync
