K000161980: Stale "Cluster update failed" and "AddingBlade Failed" Status After Blade Removal on F5OS VELOS Chassis

Type
Support Solution
Published
2026-07-02
Updated
2026-07-02
Applies to

Source
https://my.f5.com/manage/s/article/K000161980

Description

After physically removing BX110 blades from an F5OS VELOS chassis and reassigning their slots to the "none" partition, a persistent "Cluster update failed" error and a stale "AddingBlade Failed" status may appear in the controller CLI. System logs may show repeated attempts to re-add the physically removed blades to the cluster, even though they are no longer present. Despite these errors, the chassis and tenant traffic continue to operate normally.

Environment

  • Product: F5OS (Chassis/VELOS)
  • Version: 1.8.2
  • Hardware: BX110 blades
  • Actions: Blades reassigned from active partitions to "none" and then physically removed

Cause

Bug ID 2354405/Bug ID 2230293

Answer/Recommended Actions

To clear the stale status and resolve the "Cluster update failed" error:

  1. Access bash on the active controller.
  2. Run the following command:
    docker exec vcc-confd confd_cmd -f rw -c 'mset /cluster/install-progress/install-progress{AddingBlade}/status Done'
  3. This command updates the internal status and removes the cosmetic error message.

No further action is required unless the management plane remains unhealthy or additional symptoms appear. Tenant traffic and data plane operation are not affected by this issue.

This issue is cosmetic and limited to the management plane. The system may temporarily attempt to re-add a blade that has already been physically removed, leaving a stale status behind. All traffic and services should continue to function normally.
