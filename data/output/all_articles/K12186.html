Topic

The high availability (HA) table includes a number of features that are specific to VIPRION systems.

Description

The HA table can be viewed by running tmsh show sys ha-status (11.x and later) or bigpipe ha table (9.x - 10.x.) The features and their functions are listed below in the edited example Traffic Management Shell (tmsh) output:

Sys::HA Status
Slot  Feature               Key       Action                        Fail
------------------------------------------------------------------------
1     cluster-mbr-disabled  clusterd  go-offline-downlinks          no
1     cluster-time-sync     clusterd  reboot                        no
1     daemon-heartbeat      clusterd  go-offline-downlinks-restart  no
1     min-up-cluster-mbr    clusterd  failover                      no
1     mpi-failsafe          tmm       go-offline-downlinks          no
1     proc-run              clusterd  go-offline-downlinks          no
1     wait-primary-sod      sod       none                          no

Cluster Mbr Disabled

When a member of the cluster is disabled, the clusterd daemon requests the blade to go offline.

Cluster Time Sync

If the cluster time is too far out of sync to correct, the default action is to reboot to bring the cluster back into sync.

Daemon Heartbeat (clusterd)

If the heartbeat for the clusterd daemon times out, the default action is to go offline, down all links, and restart the process.

Min Up Cluster Mbr

If the number of cluster members drops below the minimum configured value, the default action is to fail over to the high availability peer.

MPI Failsafe

If the MPI channel which Traffic Management Microkernels (TMM) use to exchange messages fails, the default action is to go offline and down all links.

Proc Run (clusterd)

If the clusterd daemon stops running, the default action is to go offline and down all links.

Note: proc-run appears as Daemon Running in bigpipe output.

Wait Primary Sod

When the VIPRION system boots up, each blade's sod process will remain in the offline state until the primary blade's sod process has been started. The feature aids with proper communication establishment from the secondary blades to the failover peer.

Note: A different fail-safe action is not configurable for any of the aforementioned features.

Recommendations

When administering a VIPRION system, you should consider the following:

  • Run the tmsh show sys ha-status or bigpipe ha table commands on the primary blade, to display the high availability table of each blade. The number in the Slot or Sl column indicates which blade each line refers to.
  • Review the Fail or Act column of the HA table output to determine which feature has been triggered by a failsafe event. This will often indicate why a device is offline, rebooting or failing over.
