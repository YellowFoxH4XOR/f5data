Known Issue

This is the result of a known issue. When the BIG-IP ASM processes a request from a client, the system performs an HTTP validation check to ensure that the request is formatted properly. If the request is not compliant with the blocking properties specified on the HTTP Protocol Compliance page, the BIG-IP ASM blocks the request and logs an HTTP protocol compliance failed violation, and corresponding sub-violation to the Reporting page. For example, if the Bad HTTP version setting is enabled on the HTTP Protocol Compliance page, and the system processes an HTTP request containing an invalid HTTP version, the BIG-IP ASM system logs an HTTP protocol compliance failed violation, and a Bad HTTP version sub-violation to the Reporting page.

When the Null in request setting is enabled on the HTTP Protocol Compliance page, and the system processes an HTTP POST request containing a Null value in the message body, the BIG-IP ASM system logs an HTTP protocol compliance failed violation, but fails to generate a Null in request sub-violation to the Reporting page.

Note: The BIG-IP ASM system generates a sub-violation when the Null value appears in the URL.

F5 Product Development tracked this issue as CR107815 and it was fixed in BIG-IP ASM version 10.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.
