K000137928: "my.logout.php3 errorcode=19" error due to a wrong validation with your user-agent

Type
Support Solution
Published
2023-12-19
Updated
2023-12-19
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000137928

Description

Getting the following errors when an Access Policy is applied to a Virtual server:


In Wireshark:


"GET /my.logout.php3?errorcode=19 HTTP/1.1\r\n"


In /var/log/apm:


 apm  Notice <device> tmm[PID]: 01490500:5: /Common/<Access Profile>:<Session ID>: New session from client IP 54.84.138.60 (ST=Virginia/CC=US/C=NA) at VIP 10.128.101.133 Listener /Common/<Virtual Server> (Reputation=Unknown)

 apm  Notice <device> tmm[PID]: 01490506:5: /Common/<Access Profile>:<Session ID>: Received User-Agent header: S2%20Integration%20by%20Envoy.

 apm  Notice <device> tmm[PID]: 01490502:5: /Common/<Access Profile>:<Session ID>: Session deleted due to user inactivity.

 apm  Notice <device> tmm[PID]: 01490521:5: /Common/<Access Profile>:<Session ID>: Session statistics - bytes in: 0, bytes out: 0


Environment

  • BIG-IP APM.
  • TMSH/Bash.
  • Wireshark capture.

Cause

Unknown at the time of publication


Recommended Actions

Disable the "Secure" cookie option:


  1.  Log in to the GUI.
  2. Navigate to Local Traffic ›› Profiles : Persistence ›› <Select the profile>
  3. Disable the "Secure Attribute".
  4. Update.

None
