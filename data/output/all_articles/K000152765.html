K000152765: Traffic group status is inconsistent in HA cluster

Type
Support Solution
Published
2025-07-27
Updated
2025-07-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000152765

Description

In BIG-IP high-availability (HA) clusters with three or more devices, traffic-group status may become inconsistent if HA order changes are made on a device which is standby for that particular traffic-group and configuration is not synced before the auto-failback-time expires. This can result in a traffic-group appearing as "active" on multiple devices, or as "standby" on other devices.

For example where auto-failback-time is set as 5 seconds:

Shorten output of tmsh list cm traffic-group from BIG-IP-A.

cm traffic-group /Common/traffic-group-1 {
    auto-failback-enabled true
    auto-failback-time 5
    ha-order {
        /Common/BIG-IP-A.bigip    ---> Current Active
        /Common/BIG-IP-B.bigip
        /Common/BIG-IP-C.bigip
    }
}

From BIG-IP-B, HA order change as been made.

cm traffic-group /Common/traffic-group-1 {
    auto-failback-enabled true
    auto-failback-time 5
    ha-order {

        /Common/BIG-IP-B.bigip    ---> New Active
        /Common/BIG-IP-A.bigip
        /Common/BIG-IP-C.bigip
    }
}

You are syncing the configuration changes after 5 seconds, BIG-IP-B goes active and BIG-IP-A staying standby will assert it wants to be active. You end up with multiple device showing active for same traffic-group (tmsh show cm traffic-group). You will also see below log message in ltm logs.

010c006b:5: Configuration CRC values agree amongst peers.

Environment

  • BIG-IP LTM
  • Multi-device HA clusters (three or more devices)
  • Traffic-groups configured with ha-order and auto-failback enabled
  • Configuration changes to traffic-group HA order

Cause

Changing the HA order for a traffic-group from a device that is not currently active for that traffic-group and not syncing the configuration before the auto-failback-time expires, can trigger a known issue ID1971973. This causes multiple devices to advertise themselves as "active" for the same traffic-group. Further configuration changes after the initial incorrect change can worsen the inconsistency.

Recommended Actions

  • Perform HA order changes from device that is currently active for that traffic-group and/or sync changes before the auto-failback-timer expires.
  • If an inconsistent state occurs (multiple actives), restart the 'sod' process on affected cluster members or all cluster members to bring it a clean slate. 
    Note: Perform this action during a maintenance window, as it may cause temporary service disruption.
    bigstart restart sod
  • After recovery, verify each traffic-group is active on only one device and that all BIG-IPs are in sync.

Additional Information

You can use below commands to check the HA order and status of traffic-group in each BIG-IPs in cluster.

tmsh list cm traffic-group all-properties
tmsh show cm traffic-group
tmsh show cm failover-status
