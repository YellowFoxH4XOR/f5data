Description

Before and After upgrade/downgrade F5OS-A, how to check the system status?

Environment

  • F5OS-A
  • rSeries
  • Upgrade
  • Downgrade

Cause

  • n/a

Recommended Actions

1. Log in to CLI as root and verify the pod status:

kubectl get pod --all-namespaces

Then check the output and verify all Namespaces are "Running" state
NOTE: If it is in backoff status then please gather qkview with Max File Size 1000, and escalate the issue to F5 Support.

If any tenant is deployed status you will have similar to below output

NAMESPACE  NAME                                              READY STATUS   RESTARTS   AGE
...
default    virt-launcher-<tenant_name>-<number of node>-...  1/1   Running  0          39d

All tenants should be provisioned or Configured mode. If you find it then make it provisioned status

su admin
config
tenants tenant <tenant_name> config running-state deployed
##repeat above command if you have multiple tenant in deployed status##
commit and-quit

 

2. Check F5OS-A image status in Confd: the below command should show all columns filled and STATUS are "ready".

su admin
show system image

                                           IN
VERSION OS   STATUS  DATE        SIZE      USE
--------------------------------------------------
1.3.2-13054  ready   2023-01-26  922.16MB  false
1.3.1-8863   ready   2022-11-06  922.16MB  true

VERSION                                  IN
SERVICE      STATUS  DATE        SIZE    USE
------------------------------------------------
1.3.2-13054  ready   2023-01-26  0.38GB  false
1.3.1-8863   ready   2022-11-06  0.19GB  true
1.3.0-8327   ready   2022-11-06  2.15GB  false

                                         IN
VERSION ISO  STATUS  DATE        SIZE    USE
------------------------------------------------
1.3.2-13054  ready   2023-01-26  4.04GB  false
1.3.1-8863   ready   2022-11-06  3.85GB  false
NOTE: If the any column is missing, please gather the below information and escalate the issue to F5 Support with the below information.

- qkview with Max File Size 1000
- /var/import/import.json
- out put of the below command in bash (log in as root):

ls -al /var/import/

 

3. Check Tenant OS status: make sure all are verified.

show images

                                                IN
NAME                                            USE    STATUS
--------------------------------------------------------------------------
BIGIP-15.1.7-0.0.6.ALL-F5OS.qcow2.zip.bundle    false  verified
BIGIP-15.1.8-0.0.7.ALL-F5OS.qcow2.zip.bundle    true   verified
BIGIP-15.1.8.1-0.0.3.ALL-F5OS.qcow2.zip.bundle  true   verified
NOTE: If you see similar to below output, you can safely ignore, as EngHF should be uploaded inside of Tenant.
Hotfix-BIGIP-15.1.8.1.0.52.3-ENG.iso            false  verification-failed
You can remove it by

config
images remove name <filename of invalid software>

 

4. Check system health, and anything "unhealthy"

show system health | include unhealthy

If there is, check what is unhealthy by running 

show system health

NOTE: You find anything unhealthy status, please get qkview with Max File Size 1000, and escalate the issue to F5 Support.
If memory/hardware issue is suspected, please run the below command, please run the below command in bash (log in as root) and add to the case.

dmidecode > /var/tmp/dmidecode_"$(date +%d-%m-%y)".txt

 

5. Check memory health

zgrep -a -i "mce" /var/log/message* | grep -i "error"

NOTE: If you see any output, then please generate fresh qkview with Max File Size 1000, and escalate the issue to F5 Support.
