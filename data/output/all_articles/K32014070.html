Known Issue

Using the Configuration utility to create an HTTP profile may fail with a No Access error when you attempt to change the Parent Profile setting to a non-default value.

This issue occurs when all of the following conditions are met:

  • You use Firefox 29 through 32 or Palemoon 24 to access the Configuration utility.
  • You attempt to create a new HTTP profile using the Configuration utility.
  • You attempt to change the Parent Profile setting of the HTTP profile to a non-default value.

Impact

When using the Configuration utility to create an HTTP profile, users are unable to modify the Parent Profile setting to a non-default value.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you select a non-default value for the Parent Profile setting of a new HTTP profile, the BIG-IP system displays a No Access error in the Configuration utility and cancels the profile.

Workaround

To work around this issue, you can use a newer version of Firefox or Palemoon, use a different browser, or create the new HTTP profile using the Traffic Management Shell (tmsh.) For the last option, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility of the BIG-IP device by typing the following command:

    tmsh

  2. Create the HTTP profile with a non-default value for the parent profile, using the following command syntax:

    create /ltm profile http <name> { defaults-from <parent_profile> }

    For example, the following command creates an HTTP profile named example, and uses the req_erase_http system-supplied profile as its parent:

    create /ltm profile http example { defaults-from req_erase_http }

  3. Save the configuration by typing the following command:

    save /sys config
