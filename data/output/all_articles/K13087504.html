Description

An ASM support case may be opened for a number of reasons regarding High CPU utilisation.
 

Environment

  • After Upgrade
  • ASM module provisioned
  • Added a new Policy
  • Learning Enabled
  • Behavioural Detection enabled on Dos Profile
  • Bot Defense Profile applied
  • ASM sync enabled on device group
  • Remote Logging of Request logs applied
  • Signature Checking enabled
  • Large POST requests
  • Traffic Increase


Cause

Most of the reasons mentioned in the environment, high CPU utilisation is expected.

Key thing to be aware is that CPU seen on the BIG-IP's GUI dashboard is an aggregate of all the CPU cores and in actual fact the CPU usage may be lower.

It must also be known to the observer that the ASM processes are operating on the odd cores ( control plane ). Furthermore, there are certain ASM processes that are pinned to the highest-numbered logical CPU core.

K16469: Certain BIG-IP ASM control plane processes are now pinned to the highest-numbered logical CPU core


Recommended Actions

Following are some of the areas to review to find the cause of the increased CPU utilisation:
  • Datasync Obfuscation Schedule
  • Number of Pending Suggestions
  • Number of ASM policies
  • Signature Checking Context; Request & Response
  • Number of Parameters ( an or explicit URLs ) configured
  • Whether All Requests are sent to the Remote logger
  • How large the Policy Configuration is
  • How busy the Virtual Server is to which the ASM policy is applied
There can be several other reasons such as unknown issue, bugs, vulnerabilities, other modules provisioned.
