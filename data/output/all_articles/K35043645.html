K35043645: High CPU utilization 90% and above

Type
Support Solution
Published
2022-02-10
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K35043645

Description
BIG-IP shows sustained periods of high CPU utilization, traffic flow much lower than device capacity

  • The Inet port exhaustion messages are observed in /var/log/ltm:
Jan 20 03:52:29 example.f5.com crit tmm4[15601]: 01010201:2: Inet port exhaustion on x.x.x.x to x.x.x.x:31600 (proto 17)
Jan 20 04:01:08 example.f5.com crit tmm[15601]: 01010201:2: Inet port exhaustion on x.x.x.x to x.x.x.x:28522 (proto 17)
Jan 20 05:25:38 example.f5.com crit tmm8[15601]: 01010201:2: Inet port exhaustion on x.x.x.x to x.x.x.x:22710 (proto 17)
Jan 20 05:29:25 example.f5.com crit tmm3[15601]: 01010201:2: Inet port exhaustion on x.x.x.x to x.x.x.x:28803 (proto 17)
  • Idle Enforcer messages are observed in /var/log/kern.log:
Jan 20 14:40:30 example.f5.com info kernel: ltm driver: Idle enforcer starting - tid: 4966 cpu: 15/15
Jan 20 14:40:30 example.f5.com info kernel: ltm driver: Idle enforcer exiting - tid: 4966 cpu: 15
Jan 20 14:40:30 example.f5.com info kernel: ltm driver: Idle enforcer starting - tid: 4967 cpu: 19/19
Jan 20 14:40:30 example.f5.com info kernel: ltm driver: Idle enforcer exiting - tid: 4967 cpu: 19
Jan 20 14:40:30 example.f5.com info kernel: ltm driver: Idle enforcer starting - tid: 4968 cpu: 15/15

Environment

  • Fast L4 Wildcard Virtual Server
  • Protocol set to * All Protocols
  • Protocol Profile (Client) uses default fastL4 profile
  • SNAT pool configured

    Cause
    This issue has potentially two causes:

    • SNAT pool exhaustion
    • UDP traffic to the Virtual Server suffering from longer timeouts from the idle timeout value set in the default fastL4 profile

    Recommended Actions

    1. Add additional IP space to the SNAT pool:
      1. The available port space in the SNAT pool is divided between TMMs. 
      2. The port find behaviour is based on tm.portfind.linear and tm.portfind.random, which means there only needs to be 32 ports in use for a given port find to fail.
      3. Not all possible ports in the SNAT pool (/23 = ~32M available ports) are searched.
      4. Adding additional IP space should solve the Inet port exhaustion condition.
    2. Separate the UDP traffic out to a separate UDP Virtual Server with lower Idle Timeout values in a custom fastL4 UDP profile
