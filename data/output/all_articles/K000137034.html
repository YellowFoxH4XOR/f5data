Description

HTTP/2 follows a different structure than HTTP/1.x

To allow for backward compatibility with HTTP/1.x monitor-type regex matching, HTTP/2 response frames are converted to HTTP/1.x plain text so that the response can be parsed similarly to match HTTP/1.x style recv-string.

Example: When http2 monitor is configured with a HTTP/1.1 style recv-string: 


ltm monitor http2 test {
   recv "HTTP/1.1 200 OK"

}

 

The transformation of HTTP/2 response frame to HTTP/1.1 plain-text message allows following HTTP2 response frame to be considered a valid response for recv-string configured above.

Recommended Actions

Following are some example string that monitors an index.html  for  host.domain.com expecting a '200 OK' response

HTTP1.0

GET /index.html HTTP/1.0\r\nHost: host.domain.com
200 OK


HTTP1.1

GET /index.html HTTP/1.1\r\nHost: host.domain.com\r\nConnection: Close\r\n\r\n
200 OK


HTTP2.0

GET /index.html HTTP/2.0\r\nHost: host.domain.com\r\nConnection: Close\r\n\r\n
200 OK


It's recommended to include the version information as it indicates the client's intention to use specified protocol version and its adherence to its specification.
