Topic

The BIG-IP APM local user database consists of the local user database instance and local user data. You can back up and restore the user data of the BIG-IP APM local user database using either one of the following methods: 

  • Exporting and importing user data in a CSV file using the Configuration utility
  • Backing up and restoring the local user database using the ldbutil command line utility

During a BIG-IP upgrade operation, the local user database is automatically included in the UCS archive and restored in the upgraded BIG-IP version.

Description

Backing up and restoring user data in the local user database using ldbutil

ldbutil is a command-line utility that interacts directly with the local user database. You can use it to back up and restore user data in the local user database.

For a comprehensive list of ldbutil operations and arguments, enter the following command:

ldbutil --help

  • Backing up user data in the local user database using ldbutil
  • Restoring user data in the local user database using ldbutil

Backing up user data in the local user database using ldbutil

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line as the root user.
  2. To back up all database records, use the following command syntax:

    ldbutil --backup --file=<filename>

    For example, to back up all user records into the file /shared/tmp/backup_date.sql, enter the following command:

    ldbutil --backup --file=/shared/tmp/backup_date.sql

Restoring user data in the local user database using ldbutil

Impact of procedure: Restoring local user records permanently overwrites existing user settings. If restoring the local user records is required, you should back up the current database before performing this procedure.

  1. Log in to the BIG-IP command line as the root user.
  2. To back up all database records, use the following command syntax:

    ldbutil --restore --file=<filename>

    For example, to restore user records from the file /shared/tmp/backup_date.sql, enter the following command:

    ldbutil --restore --file=/shared/tmp/backup_date.sql

Exporting and importing user data to a CSV file using the Configuration utility

  • Exporting user data to CSV using the Configuration utility
  • Importing user data from a CSV file to the local user database using the Configuration utility

Exporting user data to CSV using the Configuration utility

You can back up the local user database records by exporting the user data into a comma-separated value (CSV) file.

Note: Dynamically created users are not included in the CSV file that you export to back up user data.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Authentication > Local User DB > Users.
  3. Select Export to CSV.

A CSV file containing the user data downloads.

Importing user data from a CSV file to the local user database using the Configuration utility

Note: New user records on the BIG-IP APM local user database are not removed when you import the local user database. Only user data with a record match in the CSV file are overwritten. Passwords are not overwritten.

Impact of procedure: Importing users permanently overwrites existing user settings. This action cannot be undone. If required, you should back up the current database.

  1. Log in to the Configuration utility.
  2. Go to Access > Authentication > Local User DB > Users.
  3. Select Import from CSV.
  4. Select the CSV file containing the user data.

    A warning message box appears.

  5. If you want to permanently overwrite existing user settings, select Yes.

Upgrading considerations

During a BIG-IP version upgrade, the BIG-IP system saves a copy of the local user database and includes it as part of the UCS archive.

After booting into a new partition during upgrade, the system extracts the local user database from the UCS archive and saves it in the /var/apm/localdb/restore.sql file. When the localdbmgr daemon starts, the system notices the presence of the restore.sql file and uses it to populate the records of the local user database in the new partition.

Note: The local user database is included in the UCS archive during an upgrade operation and it is then restored. In any other situation, such as if the administrator creates a UCS archive file during normal maintenance, the UCS archive includes the local user database (the restore.sql file), but the system does not restore the local user data per design.
