Issue

When the number of connections to a network share or tree reaches the maximum value set by the SessConns setting on a filer, the filer may report insufficient resources to the ARX system. When the filer reports insufficient resources, client access to the requested files through the ARX system will fail and the ARX system will log STATUS_INSUFF_SERVER_RESOURCES messages to the syslog file that appear similar to the following example:

:VCIFS-1-DBG-FILERCONNTREE:: Filer: connecting to '\\filer1\share1'.
:VCIFS-1-DBG-SMBSTATUS:: Received STATUS_INSUFF_SERVER_RESOURCES in response to command TREE_CONNECT_ANDX. <User> - STATUS_INSUFF_SERVER_RESOURCES.
:S-1-INFO-FILERTREEFAIL:: Failed to connect to share '<SHARE>' at filer 10.10.1.1 for user
:VCIFS-1-DBG-FILERCONNLOGOFF:: Filer: logging off user <User> uid 4171.
:VCIFS-1-INFO-FILERLOGOFF:: User <User> logged off from filer 10.10.1.1.
:VCIFS-1-WARN-DIROPENFAIL:: Can't open directory /managedvolume01/ share '<SHARE>' - STATUS_INSUFF_SERVER_RESOURCES.

F5 Product Development tracked a request for enhancement (RFE) as ID 343244 to introduce an option to limit the number of SMB sessions per TCP connection used by the control plane, in order to reduce the impact on filer resources. Beginning in ARX version 6.0.0, the ARX will add additional TCP connections as needed to support a large number of tree connections. For information about upgrading, refer to the ARX release notes.

Additionally, this enhancement was included in ARX versions 5.1.9 HF4 (build-12110) and 5.2.2 HF1 (build-12684). For more information, refer to K12766: ARX hotfix index.
