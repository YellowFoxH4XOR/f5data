K11772: Pairing fails if the redundancy protocol command is applied to multiple interfaces

Topic

The redundancy protocol command designates an interface as one end of an ARX redundant-pair link. You should not configure this command for multiple interfaces on an ARX system. If the redundancy protocol command is enabled on multiple interfaces, pairing fails and log messages that appear similar to the following example are repeatedly logged:

arx-01:1-1-ACM-1828:SQMD-0-NOTE-MSG5:: Peer switch 'arx-02' is now online
arx-01:1-1-ACM-1828:SQMD-0-NOTE-MSG5:: Peer switch 'arx-02' is now offline
arx-01:1-1-ACM-1828:SQMD-0-NOTE-MSG5:: Peer switch 'arx-02' is now online
arx-01:1-1-ACM-1828:SQMD-0-NOTE-MSG5:: Peer switch 'arx-02' is now offline

If you want multiple interfaces to participate in the redundant-pair link, configure a multi-port channel and enable the redundancy protocol on that channel. For example:

channel 1
    members 1/1
    members 1/2
   redundancy protocol
    exit

For more information about configuring a channel as a redundant-pair link, refer to the ARX CLI Network-Management Guide.
