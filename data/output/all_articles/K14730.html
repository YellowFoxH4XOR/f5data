Known Issue

Applying a BIG-IP ASM-enabled HTTP Class to a virtual server does not force invalidation of the WebAccelerator cache.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with a WebAcceleration profile that has a WebAccelerator application enabled
  • An HTTP Class with BIG-IP ASM enabled is applied to the virtual server

Impact

Potentially malicious or sensitive content may be served from the BIG-IP WebAccelerator cache.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Objects may be served from the BIG-IP WebAccelerator cache without revalidation with the origin web server (OWS).

Workaround

To work around this issue, you can force the invalidation of the WebAccelerator cache by re-applying the BIG-IP ASM policy. To do so, perform the following procedure:

Impact of workaround: Any saved changes will be applied to the policy. Objects in the WebAccelerator cache will have to be revalidated against the OWS.

Applying a BIG-IP ASM policy

  1. Log in to the BIG-IP Configuration utility.
  2. Click Application Security.
  3. Click Policy.
  4. In the Current edited policy list, select the policy you want to apply.
  5. Click Apply Policy.
  6. Accept the confirmation pop-up.
