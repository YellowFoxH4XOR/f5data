Topic

FirePass licenses are based on the number of concurrent user sessions. Each session counts toward the limit specified in the license, including multiple logins by the same user. When the concurrent session limit of the license is reached, no further logins are permitted. Because some organizations have more users than the number of concurrent user sessions in their FirePass license, managing logins efficiently can be the key to ensuring that resources are available for the user community.

The FirePass controller provides two methods for managing logins that can conserve the number of available sessions. First, the FirePass controller provides limits on the number of concurrent logins for an individual user and on users within a master group. The second function is account inactivity detection, either globally applied (all users) or to users on a per master group basis.

Concurrent Login Limits

You can configure a limit to concurrent logons for the same username. User-based limits are configured on the Device Management: Security: User Access Security page, under the  Concurrent logons section, through the Maximum number of concurrent sessions for the same Username drop-down menu. Once configured, this setting would limit the maximum number of concurrent sessions a user would be permitted to create on the FirePass controller with the same username.

You can also configure a limit to concurrent logons for the users in each master group. Master group-based limits are configured on the Users: Groups: Master Groups page, under the General tab, by selecting the Limit the number of concurrent sessions for this group check box and entering a number for the limit in the Enter a positive integer field.

Account Inactivity Detection

You can configure a server-side session inactivity timeout. The FirePass controller maintains a timer for each session that will log off a user when their session has been inactive for the configured maximum amount of time. Inactivity is measured by network traffic through the FirePass controller. The server-side timeout can be configured globally (all users) or on a per master group-basis on the Device Management: Security: Timeouts page. If both global and master group timeouts are used, the master group settings take precedence.

Note: For more information, refer to K3106: Configuring server-side session timeouts.

You can also configure a client-side inactivity timeout. The client receives an ActiveX control or Plugin that maintains a timer for each session which will log off a user when their session has been inactive for the configured maximum amount of time. Inactivity is measured by user input (keystrokes and mouse movements). The client-side timeout can be configured on a per master group-basis on the Users: Endpoint Security: Post-Logon Actions page by selecting the Inject ActiveX/Plugin to clean-up client browser web cache check box, then selecting a timeout using the Terminate users' sessions when they are inactive drop-down menu.

Note: For more information, refer to K8243: User inactivity timeout mechanisms for an overview of differences between server-side and client-side timeouts.

Note: Client-side inactivity timeouts are only available in FirePass software version 6.0.1 and later and only for Microsoft Windows 2000, XP, or Vista operating systems.

Additionally, you can configure an inactivity detection feature to detect sessions that have shut down abnormally or without the user explicitly logging out.  The inactivity detection can be configured on a per master group-basis on the Users: Endpoint Security: Post-Logon Actions page by selecting the Force FirePass 4100 session termination if the browser or Webtop is closed check box.

By using one or more of these options, user sessions can be optimized to ensure maximum availability of FirePass controller resources.
