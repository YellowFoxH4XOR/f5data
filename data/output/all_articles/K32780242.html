Known Issue

A virtual server may incorrectly display an Available (Enabled) state even though all the pool members are disabled.

This issue occurs when all of the following conditions are met:

  • You manually disable all of the pool members associated with a virtual server.
  • You view the state of the virtual server using either the Configuration utility or the Traffic Management Shell (tmsh).

When all of the pool members are disabled, the virtual server status should indicate that the parent object has been disabled. In this case, the BIG-IP system erroneously displays an Available (Enabled) state for the affected virtual server.

Impact

Although the BIG-IP system incorrectly displays the virtual server state, the system correctly processes network traffic. Since all of the pool members have been disabled, the system does not accept any new incoming connections, but allows persistent and active connections to be processed.

Symptoms

As a result of this issue, you may encounter all of the following symptoms:

  • All pool members associated with the affected virtual server have been manually disabled. The pool configuration may appear similar to the following example:

    ltm pool testpool {
        members {
            10.10.10.123:http {
                address 10.10.10.123
                session user-disabled
                state up
            }
        }
    }

  • The Configuration utility displays the virtual server status with a green colored icon in the Available (Enabled) state, instead of the grey-colored icon with the Available (Disabled Parent) state.
  • The virtual server status may appear similar to the following tmsh output:

                            
      Availability     : available
      State            : enabled   
      Reason           : The virtual server is available
      CMP              : enabled   
      CMP Mode         : all-cpus  
      Destination      : 192.168.1.123:80

    By right, the virtual server state should instead be set to disabled-by-parent.

  • A new connection to a virtual server that has all associated pool members disabled must complete a 3-way TCP handshake, and allow the client to send an initial packet before resetting the connection with a reset cause of No pool member available.

    For example:

    C  > VS --- Syn
    VS > C  --- Syn / Ack
    C  > VS --- Ack
    C  > VS --- Data Packet
    VS > C  --- Ack
    VS > C  --- Reset (rst_cause=No pool member available)
