Description
When db gtm.debugprobetuninginterval is enabled to gather statistics on big3d for debug purposes, many other related log messages may be generated in /var/log/gtm as well. While the other log messages have value, administrators may wish to hide them if they are unwanted.

Environment

  • BIG-IP DNS/GTM provisioned

Cause
When db gtm.debugprobetuninginterval is enabled by being set to a non-zero value (with 20 being the minimum allowed), every [value] seconds logs like the following will be written to /var/log/gtm:

Each unique GSLB monitor will receive a log message in the Monitor Statistics section, each BIG-IP big3d participating in the iQuery mesh will receive a log message in the LTM Server Statistics and each non-BIG-IP type GSLB server will recieve a log message in the Host Server Statistics. In environments with many monitors and/or servers configured, this can result in hundreds or thousands of unwanted log messages every time the logs are generated. 

Recommended Actions

If desired, all logs which are written to /var/log/gtm by enabling db gtm.debugprobetuninginterval can be filtered so they are no longer written log by altering the default syslog configuration. Typically the most useful of those log messages are the big3d statistic messages. The below procedure shows how to alter the default syslog configuration so only the big3d statistic messages from the db gtm.debugprobetuninginterval logging are written to /var/log/gtm and all other normal /var/log/gtm logs still remain.

Note: this change does not persist through an upgrade and will need to be made again in the new software partition after upgrading.
  1. Capture normal /var/log/gtm syslog messages to generate baseline expected logging
  2. Remount /usr as read+write:
    mount -o rw,remount /usr
  3. Make a backup copy of the syslog default template:
    cp /usr/share/defaults/config/templates/syslog.tmpl /usr/share/defaults/config/templates/syslog.tmpl.orig
  4. Add write permissions to the template:
    chmod +w /usr/share/defaults/config/templates/syslog.tmpl
  5. Open syslog.tmpl for edit:
    vi /usr/share/defaults/config/templates/syslog.tmpl
  6. Locate the /var/log/gtm filter and update
    1. Locate the line "facility(local2);"
    2. Replace the line with "facility(local2) and not (message("011af001:5:") and not message("monitor_q"));"
    3. (Optional) Above the line you can add the following comments if they would be helpful:
      # Edited per F5 K12117053 to suppress all "011af001:5:"
      # messages besides those containing "monitor_q" while allowing
      # all other DNS module-related messages to continue to log normally.
      # "011af001:5:" logs are written when db gtm.debugprobetuninginterval
      # is set to a non-zero value.
  7. Save and quit the file
  8. Remount /usr as read-only
    mount -o ro,remount /usr
  9. Apply the changes to syslog filtering by toggling logging level
    tmsh modify /sys syslog daemon-from info
    tmsh modify /sys syslog daemon-from notice
  10. Review /var/log/gtm messages and ensure they continue to match baseline from step 1
  11. Enable gtm.debugprobetuninginterval logging (30 second interval is recommended)
    tmsh modify sys db gtm.debugprobetuninginterval value 30
  12. Review /var/log/gtm and locate 5 messages (one per BIG-IP) similar to below every 30 seconds
    Jun 17 04:48:31 bigip2 notice gtmd[18047]: 011af001:5: GTM /Common/dc1 /Common/bigip1 10.50.5.42 cpu 0 VS: up 0 down 0 Big3d: monitor_q 0 snmp_q 0 path_q 0 probes downed by this big3d 1
  13. Confirm no additional log messages are present and all expected log messages are still generated.
