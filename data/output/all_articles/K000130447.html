K000130447: Duplicate signature sets are created after ASM security policy import

Type
Support Solution
Published
2023-01-04
Updated
2026-09-10
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.X.X, 16.X.X, 17.0.X, 17.0.0, 16.1.X, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 16.0.X, 16.0.1, 16.0.0
Source
https://my.f5.com/manage/s/article/K000130447

Description

Duplicate signature sets are created when importing or cloning an ASM policy. The duplicated signature set names are appended with _?, where ? is a number starting from 1, for example:

custom_signatures_1

You may see a message similar to the following in the GUI when importing the policy:

The operation was completed successfully

The signature set that was imported, Unix/Linux Signatures (High/Medium Accuracy), has a different configuration than Unix/Linux Signatures (High/Medium Accuracy) currently on this system. Therefore, the imported signature set Unix/Linux Signatures (High/Medium Accuracy) was renamed to Unix/Linux Signatures (High/Medium Accuracy)_2

Environment

  • AWAF/ASM

Cause

This is due to a known bug tracked in Bug ID1133997

Recommended Actions

Upgrade to a fixed version documented in ID1133997. Alternatively, apply the following workaround:

1. Run the following command to log in to the MySQL database::

mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'`

2. Once you are in the database, run the following SQL statement:

UPDATE PLC.NEGSIG_SET_FILTERS SET sig_tag_val = NULL where sig_tag_val = '' or sig_tag_val like 'HASH(%)';

Note: This SQL statement works for newly exported/imported policies, so duplicate sets are no longer created. You may delete the existing duplicated signature sets manually. If a large number of duplicate signature sets already exist on the system, contact F5 Support to obtain a script that can automate the deduplication process.
