K000163729: NGINX One Security Dashboard fails to Render Security Events from Managed NGINX Instances

Type
Support Solution
Published
2026-10-15
Updated
2026-10-15
Applies to
  • NGINX Products
  • NGINX One Console
Source
https://my.f5.com/manage/s/article/K000163729

Description

NGINX Agent logs:

Found available local NGINX App Protect syslogserver configured on port 1514

However, the agent does not generate an active security-log receiver or logs pipeline, and no process listens on TCP port 1514. As a result, NGINX App Protect WAF security violations do not appear in the NGINX One security dashboard.

Environment

  • NGINX Agent
  • NGINX App Protect WAF
  • NGINX One security monitoring
  • secops_dashboard security log profile
  • Linux-based NGINX host

Symptoms

  • The generated OpenTelemetry Collector configuration has one or more of the following conditions:
    • Only the metrics pipeline is present.
    • No syslog or security-log receiver is configured.
    • No logs pipeline is configured.
    • The securityviolationsfilter/default processor exists but is not referenced by an active pipeline.
    • TCP port 1514 is not listening.
    • WAF security events are generated but do not appear in the NGINX One security dashboard.
  • A separate syslog service listening on another port can receive WAF events successfully. This does not confirm that the NGINX Agent security-monitoring pipeline is active.

Cause

The secops_dashboard security log profile is not correctly associated with the NGINX configuration, or the NGINX Agent security-logging capability is not active. Consequently, the embedded OpenTelemetry Collector does not create the receiver, listener, and logs pipeline required to process WAF security events.

Recommended Actions

  1. Associate the secops_dashboard security log profile with the applicable NGINX configuration.
  2. Configure the profile to send WAF security events to the local TCP listener on port 1514:

    app_protect_security_log_enable on;
    app_protect_security_log <secops_dashboard-profile> syslog:server=127.0.0.1:1514;

  3. Ensure that no other service is using TCP port 1514.
  4. Verify that the NGINX Agent security-logging capability, including logs-nap where applicable, is enabled in the agent configuration.
  5. Restart or reload NGINX Agent and NGINX according to the approved operational procedure.
  6. Verify that the collector is listening on port 1514:
    sudo ss -ltnp | grep ':1514'
  7. Review the generated OpenTelemetry Collector configuration. Confirm that it contains:
    • A syslog or security-log receiver bound to port 1514.
    • An active logs pipeline.
    • The securityviolationsfilter/default processor referenced by that pipeline.
  8. Generate a controlled WAF security event and verify the following flow:

NGINX App Protect WAF

→ local TCP syslog listener on port 1514
→ NGINX Agent OpenTelemetry Collector
→ NGINX One security dashboard

Verification

Use the following command to confirm that the listener is active:

sudo ss -ltnp | grep ':1514'

If the command returns no result, review the NGINX Agent configuration, generated collector configuration, and agent logs. Confirm that the security log profile is associated with the active NGINX configuration and that the security-logging capability is enabled.
