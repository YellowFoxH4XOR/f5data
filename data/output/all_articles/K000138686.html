Description

You may get the error message like below when you run the tcpdump command from the F5 rSeries platforms:
errbuf ERROR:partition configuration changed, added interface: <Interface namber> slot: 1, client can be restarted

In this error message, note the following: 

<Interface namber> is the interface number you are running the tcpdump command.

For example, you are capturing the interface 1.0 traffic by the command: system diagnostics tcpdump interface 1.0 outfile test.pcap, but if you disable or enable any of the interfaces from GUI, then you may get the below error message, the tcpdump would also be terminated:

# system diagnostics tcpdump interface 1.0 outfile test.pcap
Capture file size will be limited to 71380236 1K blocks.
running /usr/sbin/tcpdump -nnn  "-i" "1.0" "-w" "/var/F5/system/shared/tcpdump/test.pcap" -W 1 -C 73093
tcpdump: listening on 1.0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
 errbuf ERROR:partition configuration changed, added interface: 1.0 slot: 1, client can be restarted
tcpdump: pcap_loop: partition configuration changed, added interface: 1.0 slot: 1, client can be restarted
8 packets captured
8 packets received by filter
0 packets dropped by kernel
# 

Note: You need the admin credential to log in to the command line first, then you can run the tcpdump command. For running the tcpdump command on the F5  rSeries platform you can refer to the K80685750.

Environment

  • F5OS-A
  • system diagnostics tcpdump
  • Disable and enable an interface from the GUI
  • rSeries 5000
  • rSeries 10000
  • rSeries 12000

Cause

We are tracking this issue from the known bug: Bug ID 1322685: Tcpdump sessions are terminated when interfaces are enabled or disabled.

Recommended Actions 

Please do not make modifications to interfaces when the tcpdump sessions are active.
