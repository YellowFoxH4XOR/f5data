Known Issue

The Traffic Management Microkernel (TMM) may restart when executing HTTP::cookie commands in an iRule.

This issue occurs when the following conditions are met:

  • Your BIG-IP system uses iRules that include HTTP::cookie commands.
  • You have not supplied the required arguments for the iRule command.

    For example, you must format the HTTP::cookie sanitize command in either of the following forms:

    • HTTP::cookie sanitize <name> [attribute]
    • HTTP::cookie sanitize <-attributes|-names>
    You must provide at least one of the name, -names, or -attributes values after the sanitize command.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the BIG-IP system is configured as part of a high availability (HA) group, a device failover may occur.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if the system is configured for HA.
  • The BIG-IP system generates TMM core files to the /shared/core directory.
  • You observe messages similar to the following example in the /var/log/ltm log file:

    notice sod[7056]: 01140045:5: HA reports tmm NOT ready.

Workaround

There is no workaround for this issue. You can mitigate this issue by ensuring that all HTTP::cookie iRule commands have been configured with the appropriate arguments.
