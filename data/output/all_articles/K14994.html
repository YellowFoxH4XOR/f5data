Topic

After upgrading to BIG-IP 11.x from earlier versions, your BIG-IP system may fail to load configurations that contain custom HTTP profiles with either "-compression" or "-cache" appended to the profile name.

Description

Starting in BIG-IP 11.x, the compression and caching features of the HTTP profile exist in their own separate profiles. During upgrades from versions prior to BIG-IP 11.x, for any existing custom HTTP profiles, the system automatically creates two new profiles with the base name of the custom profile, along with "-compression" and "-cache," respectively, appended to the end of the custom profile name, regardless of the original profile name.

For example, if your BIG-IP 10.x HTTP profile is named my_test_http, upgrading to BIG-IP 11.x results in the following three profiles:

  • my_test_http
  • my_test_http-cache
  • my_test_http-compression

Under certain conditions, this may cause a naming conflict during an upgrade. For example, if you have a BIG-IP 10.x profile named my_test_http-cache or my_test_http-compression, the system encounters a naming conflict when attempting to create the new BIG-IP 11.x profiles.

As a result, the configuration may fail to load, and a message similar to the following example appears in the Configuration utility:

The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

The system may also generate messages in /var/log/ltm file that appear similar to the following examples:

err mcpd[5587]: 01070293:3: The profile name (/Common/my_test_http-compression) is already assigned to another profile.

err load_config_files: "/usr/libexec/bigpipe load" - failed. -- BIGpipe HTTP compression profile creation error: 01070293:3:
The profile name (/Common/my_test_http-compression) is already assigned to another profile.

Recommendations

When planning a system upgrade to BIG-IP 11.x, you should rename any HTTP profiles that have "-cache" or "-compression" appended to the profile name.
