K000139138: APM: How to verify that oAuth Discovery is running in logs

Type

Published
2024-04-01
Updated

Status

Source

Description

BIGIP APM administrator may want to verify in logs that oAuth Discovery is running correctly and as configured.

Environment

  • APM

  • oAuth Discovery

  • Azure (Entra ID)

Cause

None

Recommended Actions

BIGIP APM administrator may want to verify that oAuth Discovery is running correctly in logs in /var/log/restjavad*. For example, in lab:

1) oAuth provider 'oauth-aad' (the provider is Azure aka Entra ID) related configuration where oAuth Discovery frequency is set to 1 day (1440mins):

# tmsh list apm aaa oauth-provider oauth-aad
apm aaa oauth-provider oauth-aad {
    authentication-uri https://login.microsoftonline.com/<microsoft_tenant_id>/oauth2/v2.0/authorize
    auto-jwt-config-name auto_jwt_oauth-aad
    discovery-interval 1440 <--- (!) oAuth Discovery frequency set to 1 day
    introspect supported
    last-discovery-time 2024-03-31:14:41:28
    openid-cfg-uri https://login.microsoftonline.com/<microsoft_tenant_id>/v2.0/.well-known/openid-configuration
    token-uri https://login.microsoftonline.com/<microsoft_tenant_id>/oauth2/v2.0/token
    trusted-ca-bundle ca-bundle.crt
    type ms-identity-platform2
    userinfo-request-uri https://graph.microsoft.com/oidc/userinfo
}
