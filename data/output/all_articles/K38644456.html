Known Issue

SNMP trap configuration may save the community string incorrectly.

This issue occurs when all of the following conditions are met:

  • You use the Traffic Management Shell (tmsh) snmp v1-traps or v2-traps command syntax to configure your BIG-IP system with a destination trap server.

    For example:

    tmsh modify /sys snmp v1-traps add { v1trap { host 10.0.0.90 community public } }
    tmsh modify /sys snmp v2-traps add { v2trap { host 10.0.0.90 community public } }

  • The BIG-IP system sends an SNMP trap to the destination SNMP host.

Impact

The SNMP traps are sent with an incorrect community string. 

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When analyzing the SNMP trap sent from the BIG-IP system, you notice that the community string of the trap is sent with quotation marks. For example, public is sent as "public".

Workaround

To work around this issue, you can configure the destination SNMP trap host using a different tmsh command syntax. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Use the following configuration syntax to create the destination SNMP trap host:

    modify sys snmp traps add { hosttrap { host <destination IP address> community <string> } }

    Note: Modify the command syntax replacing <destination IP address> with your destination SNMP trap server and <string> with the expected community string for your environment.

  3. Save the configuration by typing the following command:

    save /sys config

  4. To exit tmsh, type the following command:

    quit
