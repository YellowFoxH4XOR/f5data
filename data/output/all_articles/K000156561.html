Description

On F5OS version 1.8.0 running on F5OS-A or F5OS-C, the following error message may be repeatedly logged by the l2-agent process, particularly after an upgrade or during SNMP polling operations involving LAG (Link Aggregation Group) interfaces:

 

l2-agent[<pid>]: priority="Err" version=1.0 msgid=0x208000000000047 msg="Failed to receive interface counters for SNMP."

 

This error occurs when SNMP bulk queries (such as snmpbulkget or snmpget on multiple OIDs) are performed, especially targeting LAG interfaces. Additionally, SNMP queries may return noSuchObject or noSuchInstance for certain OIDs.

Environment

  • F5OS-A/F5OS-C running F5OS version with ID1615917 fix
  • LAG (Link Aggregation Group) interfaces configured
  • SNMP polling (snmpget, snmpwalk, snmpbulkget) targeting IF-MIB OIDs, including those associated with LAG members

Cause

This issue is caused by a known software defect in F5OS-A/C (Bug IDs 1615917 and 1789117):

  • The original defect (ID1615917) resulted in the l2-agent crashing when SNMP bulk queries were performed on LAG interfaces.
  • Fix in ID165917 prevents the crash, however l2-agent will log "Failed to receive interface counters for SNMP."
  • The underlying problem—SNMP queries for LAGs returning incomplete or inconsistent statistics—remains unresolved in version 1.8.0.
  • The complete resolution is included in F5OS-A 1.8.3 and later releases.

Recommended Actions

Upgrade to F5OS-A version 1.8.3 or newer release to fully resolve this issue and restore correct SNMP statistics retrieval for LAG interfaces. Alternatively, please open a F5 support case to request for the EHF.
