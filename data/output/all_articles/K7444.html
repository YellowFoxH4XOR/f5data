Topic

Custom external monitors must observe the following output requirements:

  • If a server meets the external monitor criteria, the external monitor must send data to stdout.

    Note: Any data on stdout results in an Available status. The data does not have to be specific to the condition of the server.

    Note: Any standard output stops the script from running. To ensure that the necessary operations occur, F5 recommends that you clean up any temporary files, perform logging, etc., before the system performs the standard output operation.

  • If a server fails to meet the external monitor criteria, the external monitor must not send any data to stdout.

If you create an external monitor that displays a node as up, but it also displays the status as down, the bigd interprets both responses as up.

When running an external monitor, whether a script or a compiled program, the bigd health-checking daemon uses the stdout pipe to determine whether the health check was successful. If the monitor outputs any data to stdout, the bigd process marks the associated server object as Available (up). If the monitor does not output any data to stdout, bigd marks the node as Unavailable (down).

For example, if you write a monitor that returns up or down on stdout to report the actual status of the server, the bigd process may mark servers that are down as Available (up), since the monitor outputs data on stdout in both cases.

Note: A sample external monitor is available in the /usr/bin/monitors/sample_monitor file.

Note: For more information about external monitor implementation, refer to the Template For External Monitors article on DevCentral.
