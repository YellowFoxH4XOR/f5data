Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K13380: Configuring the BIG-IP system to use an NTP server from the command line (11.x - 13.x)

Description

In BIG-IP 9.4.1 and earlier, you can configure network time protocol (NTP) servers from the command line by editing the /etc/ntp.conf file. However, beginning in BIG-IP 9.4.2, the /etc/ntp.conf file is an auto-generated file and should not be manually edited. In BIG-IP 9.4.2 through 10.x, you can use the bigpipe ntp command to configure NTP servers from the command line.

Configuring the BIG-IP system to use an NTP server from the command line

  1. Log in to the command line.
  2. Use the following command syntax to configure an NTP server on the BIG-IP system:
    • The following command adds an NTP server to the existing NTP configuration:

      bigpipe ntp servers <ip_addr> add

      For example, to add the NTP server with the IP address of 192.168.1.245 to the existing NTP configuration, type the following command:

      bigpipe ntp servers 192.168.1.245 add

    • The following command replaces the existing list of NTP servers with a specified server:

      bigpipe ntp servers <ip_addr>

      For example, the following command replaces the existing list of NTP servers with a single host, time.example.com:

      bigpipe ntp servers time.example.com

  3. Save the configuration by typing the following command:

    bigpipe save

Additional commands

  • To display the configured NTP servers, type the following command:

    bigpipe ntp servers show

  • To delete a single configured NTP server, use the following command syntax:

    bigpipe ntp servers <ip_addr> delete

  • To delete all configured NTP servers, type the following command:

    bigpipe ntp servers none

Note: You may need to modify the routing configuration on the BIG-IP system to ensure the NTP traffic is routed correctly. For more information, refer to K10239: Traffic originating from management processes may not use the intended management address or management routes.
