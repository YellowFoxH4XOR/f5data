Topic

You can configure an XML profile within the BIG-IP ASM security policy to protect XML-based web traffic. When you create the XML profile, you define the validation configuration by importing an XML-based schema file into the profile. The XML profile then protects XML applications by validating whether the incoming traffic complies with the predefined schemas or WSDL documents.

If the XML profile processes a request where the XML data is not formatted according to the XML specification, the following violation is logged to the /var/log/asm file and to the Violations screen in the Configuration utility:

Malformed XML data

Note: The Reporting section of the BIG-IP ASM Configuration utility provides the location where the issue is occurring within the XML message.

Example: Incorrect tag ordering

In the following example, the </function0> tag is used when the most recent unmatched start tag is <function1>. This structure is not well formed and would generate the Malformed XML data violation.

<function0><function1> Value0 </function0> Value1 </function1>

Example: Unicode compatibility characters

The Unicode standard describes a certain subset of characters as compatibility characters. These are characters that would not otherwise be encoded except for compatibility and round trip convertibility with other existing standards.

The use of compatibility characters is discouraged in XML 1.0, and as such the BIG-IP ASM system does not support these characters. If the blocking mask is enabled for Malformed XML data, and an XML message is received that contains compatibility characters, the BIG-IP ASM system generates a Malformed XML data violation.

This behavior is by design.
