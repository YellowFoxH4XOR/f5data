Description

An SQL injection (SQLi) attack is a common attack against a web application that targets information stored in a database. SQLi can be done in many ways, depending on the SQL server type. The SQL server type dictates the syntax of the type of the executed SQLi attack. SQLi can also include evasion techniques employed by attackers to bypass WAF filters such as BIG-IP ASM.

Environment

  • Application is under an SQLi attack
  • BIG-IP ASM 11.x
  • A security policy is assigned to the virtual server
  • The BIG-IP ASM request log is enabled by default to illegal request

Cause

None

Recommended Actions

The BIG-IP ASM system can mitigate SQLi attacks using the attack signature feature or defined meta-characters on parameter value. The following procedures list the steps needed to mitigate SQLi using the attack signatures because this is the fastest and easiest configuration. The procedures include instructions for assigning the relevant attack signature set, enabling it, and configuring it to mitigate SQLi attacks. The final step is the mitigation verification, where the administrator can see the SQLi being blocked.

Note: Default configuration means any of the BIG-IP ASM security policy templates with transparent and staging period on for the policy.

Impact of procedures: Adding attack signatures to the security policy can generate false positives. In these cases, you should remove false positives using the learning page. Adding the SQL Injection Signatures attack signatures set includes various types of SQL servers, which allows the protection regardless of the backend database server.

  • Adding the SQLi signatures to the security policy
  • Switching the security policy enforcement mode to Blocking
  • Verifying the SQLi attack is being blocked

Adding the SQLi signatures to the security policy

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Attack Signatures > Attack Signatures Configuration.
  3. In the Current edited policy list, select the desired security policy.
  4. In the Available Signature Sets list, select SQL Injection Signatures, and move it to the Assigned Signature Sets table.
  5. For Signature Staging, clear the Enabled check box.
  6. Select Save, and then select Apply Policy.

Switching the security policy enforcement mode to Blocking

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Blocking > Settings.
  3. In the Current edited policy list, select the desired security policy.
  4. For Enforcement Mode, select Blocking.
  5. Select Save, and then select Apply Policy.

Verifying the SQLi attack is being blocked

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Event Logs >  Application > Requests.
  3. Select Show Filter Details.
  4. For Violation, select Attack signature detected, and then select Go.

    The blocked request with SQLi should be listed in the request log.

    Note: In the request log, the attack type name will be SQL injection.
