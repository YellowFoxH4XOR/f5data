K10055223: Changes to an Access Policy do not prompt for the Access Policy to be applied.

Type
Support Solution
Published
2022-01-20
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K10055223

Description

  • You make changes to an Access Policy or Virtual Policy Editor
  • After saving or updating changes in the Admin GUI you are not prompted to Apply the Access Policy.
  • To verify changes made the Access Policy you should look for the following log messages in /var/log/apm:
debug apmd[26921]: 01490266:7: (null):Common:00000000: AccessPolicyProcessor/AccessPolicyProcessor.cpp: 'dispatchEvent()': 1177: Processing MCP notification for object: "/Common/<access_policy_name>" class: "7871" operation: "2908" localTx: 1

notice apmd[26921]: 01490100:5: 00000000: Access profile: /Common/<access_policy_name> configuration changes need to be applied for the new configuration to take effect.

notice apmd[26921]: 01490101:5: 00000000: Access profile: /Common/<access_policy_name> configuration has been applied. Newly active generation count is: 22


In the examples above the first log messages indicates the mcdp process sent a notification to the apmd process. The second log message indicates the Access Policy has changed and needs to be applied. The third log messages indicates that the Access Policy has been applied and creates a new snapshot.

Environment

  • Changes are made to an Access Policy or in the Virtual Policy Editor.
  • Access Policy, Virtual Policy Editor
  • Access Policy Manager (APM)

Cause

If you do not see the above log messages a communication error between the mcpd and apmd processes has occurred.

Recommended Actions

Manually apply the Access Policy.

  1. Login to the Admin GUI.
  2. ?????Navigate to Access>Profiles / Policies >Access Profiles (Per-Session Policies)
  3. Select the checkbox to the left of the Access Policy name.
  4. Scroll to the bottom of the GUI.
  5. Click the "Apply" button.

Reboot the Big-IP device.

  1. Login to the CLI.
  2. At the bash prompt enter the command, "reboot."
