Description

This article documents common issues and useful commands for troubleshooting Thales/nCipher/Entrust netHSM.  This does not include Safenet devices.

Checklist:

  • Verify nCipher client software and firmware is compatible with your BIG-IP software version

    /opt/nfast/bin/enquiry

  • Check network connectivity with netHSM:

    netstat -natp | grep 9004

    tcp        0      0 0.0.0.0:9004                0.0.0.0:*                   LISTEN      1410/../sbin/hardsever
    tcp        0      0 10.2.3.1:32927           10.2.3.3:9004            ESTABLISHED 1410/../sbin/hardsever

  • If you have upgraded BIG-IP, you must reinstall the Thales HSM client using nethsm-thales-install.sh.  See Manual Chapter. See special instructions for client version 12.81.2 in Related Content. 
  • Review /var/log/ltm and perform search in the knowledge base on any unexpected error messages.
  • Tcpdump traces should show both TLS handshake and connection between BIG-IP and netHSM. There should be a heartbeat sent every 10s and additional request after Client Key Exchange

    tcpdump -nnvi 0.0:nnn -s0 -w /shared/tmp/$HOSTNAME-`date +%Y%m%d-%H%M%S`.pcap port 9004

  • RFS-SYNC not working - rfs-sync may be stuck and locked permanently by a process

    Example:

    rfs-sync --who-has-lock
    RFS lock file owned by task ID 60db3cc3.fdb8dc623ca86104.
    Key management data generation is #871: in progress.

    To remove the lock run:

    rfs-sync --kill-lock

Environment

  • BIG-IP
  • XC/nShield Connect

Cause

None

Recommended Actions

If you are unable to resolve the issue, open a service request and provide the following data for investigation:
  1. Collect the following output:

    /opt/nfast/bin/enquiry
    /opt/nfast/bin/nfkminfo
    /opt/nfast/bin/nfkminfo -l
    /opt/nfast/bin/ckinfo ls -lZ
    /opt/nfast/kmdata/local/

  2. Enable Debug logging for pkcs11d:

    tmsh modify sys db log.pkcs11d.level value debug

  3. Edit /opt/nfast/cknfastrc and set CKNFAST_DEBUG=11

  4. bigstart restart pkcs11d

  5. Reproduce the problem
  6. Run the following diagnostic tool:

    /opt/nfast/bin/nfdiag

    Note: This command should produce a nfdiag.zip archive file that contains information such as health check of the netHSM, the version of the Security World software and the netHSM firmware.

  7. Disable Debug logging:

    tmsh modify sys db log.pkcs11d.level value Error

  8. Edit /opt/nfast/cknfastrc and set CKNFAST_DEBUG=0

  9. bigstart restart pkcs11d

  10. Generate QKView

    qkview -s0

Additional Information

  1. RFS:
    The Thales nShield Connect architecture includes a component called the Remote File System (RFS) that stores and manages the encrypted key files.
    The RFS can be installed on the BIG-IP system or on another server on your network. Other devices will sync keys from the RFS using the rfs-sync command.

  2. nfast:
    nfast is the directory under which the Thales HSM files are installed. 

    This directory is initially created under /shared/thales_install/amd64/nfast/... and client installation files are copied from vendor supplied CD.

  3.  nethsm-thales-install.sh:
    This is the script that is run to install the Thales HSM client. The installation process requires a prior enrollment of BIG-IP IP Address on the Thales HSM.

    When the installation completes, the client software files are installed under /opt/nfast/...

  4. pkcs11d:
    pkcs11d is the service that manages connectivity between all network HSM (Thales and Safenet). 

    If the pkcs11d service is not running, there will be no connectivity to the net HSM. 

    pkcs11d can be restarted with: tmsh restart sys service pkcs11d 

  5. enquiry:
    enquiry is the command that should be run to verify that the Thales HSM client is correctly installed.

    the full command is: /opt/nfast/bin/enquiry
