Topic

Beginning in BIG-IP 16.0.0, F5 adds functionality to support the WebSocket compression extension in accordance with RFC 7692. This adds to the existing WebSocket functionality previously introduced in BIG-IP 12.1.0. You can go to the WebSocket profile on the Configuration utility at Local Traffic > Profiles > Services > WebSocket to configure WebSocket compression.

Description

BIG-IP 16.0.0 enables a WebSocket client and a peer WebSocket server to negotiate and determine the parameters required to configure the compression algorithm during the WebSocket handshake. In earlier versions of the BIG-IP system, you are able to configure Masking in a WebSocket profile. You need to be familiar with how the Masking setting functions in the BIG-IP system before reviewing this article. To do so, refer to K14754: BIG-IP support for the WebSocket protocol.

New WebSocket compression settings

When masking and compression are enabled, for incoming traffic, the BIG-IP system identifies whether the WebSocket message is marked as compressed, and if so, decompresses the message payload (after it is unmasked, if applicable). The system BIG-IP recompresses the message (and then remasks the message, if applicable) before the message leaves the system. When you enable WebSocket compression, additional system resources (CPU and memory) are required. Beginning from BIG-IP 16.0.0, the following settings are added to enable you to configure WebSocket compression: 

  • Compress Mode: Set to Preserved or Typed. In Preserved, the system performs no compression operations. This corresponds to the existing WebSocket behavior. When set to Typed, compression is possible and you have three additional settings available to configure how the system performs compression.
  • Compression: Set to Enabled or Disabled to determine whether compression is negotiated with the client and server endpoints. On the client side, the BIG-IP system includes the permessage-deflate extension in the negotiation responses only when the client requests it. On the server side, this means including permessage-deflate in the BIG-IP system's request to the server.
  • Maximum Window Size: Set to an integer between 8 and 15 to determine the maximum sliding window size negotiated and allowed in the connection with the client and server endpoints.
  • No delay: Set to Enabled or Disabled. When Enabled, the system processes all data is processed as fast. When set to Disabled, the system may momentarily buffer some data mid-stream for efficient compression.

Recommendations

Configuration

When configuring WebSocket compression, you should consider the following factors, in particular the Masking settings in the WebSocket profile:

  • When masking support is not configured, you cannot enable compression support. You cannot configure Typed for Compress Mode when Masking is set to Preserve. Trying to do so causes the system to return an error similar to the following:

    01071a73:3: Invalid masking and compress mode value for profile /<profile_name>. Unexpected value.

  • If BIG-IP ASM is configured on the virtual server, you should configure Selective for Masking and leave Compression Mode at Preserved. BIG-IP ASM support for WebSocket compression is currently not available in BIG-IP 16.0.0.

  • The following table summarizes the masking and compression behavior of the BIG-IP system when configuring the WebSocket profile.

    MaskingCompression modeBehavior
    PreservePreservedPerforms neither masking nor compression 
    TypedInvalid configuration
    UnmaskPreservedUnmasks with no compression
    TypedUnmasks and compresses. When BIG-IP ASM is configured, unmasks only
    RemaskPreservedRemasks with no compression
    TypedRemasks and compresses. When BIG-IP ASM is configured, remasks only
    SelectivePreservedWhen BIG-IP ASM is configured, masks as described in K14754. Does not compress
    TypedWhen BIG-IP ASM is configured, masks as described in K14754. Does not compress

Troubleshooting

When troubleshooting, you should consider the following:

  • The BIG-IP system logs WebSocket information and errors to the /var/log/ltm and /var/log/tmm files.
  • You can enter the following command to view WebSocket statistics and compression/decompression bytes and failures :

    tmsh show ltm profile websocket my_websocket
