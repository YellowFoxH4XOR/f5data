Description

This article clarifies the definition and scope of "incomplete HTTP transactions" as reported in BIG-IQ analytics when monitoring BIG-IP Advanced WAF. An incomplete transaction occurs when the entire HTTP request-response exchange does not finish successfully. This metric can be observed in BIG-IQ under Applications > Application Name > Application HTTP Service in the HTTP Transaction Outcomes chart. Understanding when transactions are marked as incomplete helps with accurate troubleshooting and identifying whether issues are client-side or server-side.

Environment

  • HTTP Analytics profile enabled on BIG-IP
  • TCP analytics enabled for monitoring packet loss and retransmissions

Cause

None

Recommended Actions

Understanding Incomplete Transactions:

An incomplete transaction in BIG-IQ analytics represents any HTTP transaction where the entire request-response exchange did not complete successfully. The WAF considers the transaction complete only when full request- response is complete starting from the Request sent from Client to the Server and Response sent from Server to the Client.

Both of the following scenarios result in incomplete transactions:

  1.  The WAF sends a request to the backend server but does not receive a response
    • Client → WAF → Load Balancer → Server
    • Client ← WAF ✗ Load Balancer ← Server (response not received by WAF)
  2.  The WAF receives a response from the backend server but cannot deliver it to the client
    • Client → WAF → Load Balancer → Server
    • Client ✗ WAF ← Load Balancer ← Server (response not delivered to client)
