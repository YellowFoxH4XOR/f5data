Known Issue

VIPRION systems may experience Session Initiation Protocol (SIP) traffic disruptions.

This issue occurs when all of the following conditions are met:

  • The VIPRION chassis has more than one B2100 blade installed.
  • One or more of the blades is disabled.
  • You configure a virtual server that references a SIP profile.
  • You modify the default setting of the VIPRION cluster UDP hash algorithm from port to ipport.

    For example:

    tmsh list /sys db udp.hash
    sys db udp.hash {
        value "ipport"
    }
  • You enable the DAG Round Robin feature.
  • The virtual server is actively processing SIP UDP traffic.
  • You subsequently enable another blade on the active unit.

Impact

SIP traffic is temporarily disrupted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice that SIP traffic is temporarily disrupted immediately after enabling a blade on the active unit.

Workaround

There is no workaround for this issue. However, you can avoid this issue by not enabling a blade in an active VIPRION cluster while the system is actively processing SIP UDP traffic.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
