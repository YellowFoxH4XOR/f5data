Topic

Summary

A Virtual Clustered Multiprocessing (vCMP) guest does not support Virtual Local Area Network (VLAN) tag modifications on a VLAN inherited from its vCMP host.

Description

In a BIG-IP system that uses vCMP, the VLANs for the vCMP guests are always managed on the vCMP host. Any VLAN changes made to the vCMP host will propagate to the respective vCMP guests automatically. However, if you change the VLAN tag for a VLAN on the vCMP guest, the vCMP guest will lose network connectivity on that VLAN. F5 recommends all changes to a VLAN on a vCMP guest be performed on its vCMP host.

To recover network connectivity for that VLAN, you can restore the vCMP guest configuration from a user configuration set (UCS) archive saved prior to the VLAN tag change, if available. To do so, perform the Restoring your BIG-IP system configuration procedure from K13132: Backing up and restoring BIG-IP configuration files (11.x).

If a UCS archive is not available, you can recover the network connectivity by deleting the affected VLAN on the vCMP guest, then remove and re-add the VLAN to the vCMP guest on the vCMP host. If you have one or more self IPs assigned to the affected VLAN, you can create a dummy VLAN and re-assign the self IPs to the dummy VLAN temporarily until the VLAN recovers.

Recommendations

To recover network connectivity without restoring from a UCS archive, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the affected vCMP guest.
  2. Navigate to Network > VLANs > VLAN List.
  3. Optional: If you have self IPs assigned to the affected VLAN, click Create to create a dummy VLAN and complete the optional process by performing the following steps:
    1. In the Name setting, type a name for the dummy VLAN (for example: Dummy), and then click Finished.
    2. Navigate to Network > Self IPs.
    3. Click the name of the affected self IP.
    4. For the VLAN / Tunnel setting, select the previously created dummy VLAN.
    5. Click Update.
    6. Navigate back to Network > VLANs > VLAN List.
  4. To delete the VLAN from the vCMP guest, select the check box for the affected VLAN, and then click Delete.
  5. Click Delete again.
  6. Log in to the Configuration utility of the vCMP host.
  7. Navigate to vCMP > Guest List.
  8. Click the name of the affected vCMP guest.
  9. Select the affected VLAN in the Selected section for the VLAN List setting, and then click >> to move it to the Available section.
  10. Click Update.
  11. Select the affected VLAN in the Available section for the VLAN List setting, and then click << to move it to the Selected section.
  12. Click Update.
  13. Log in to the Configuration utility of the affected vCMP guest if you have not logged in already.
  14. Navigate to Network > VLANs > VLAN List.
  15. Verify that the affected VLAN is properly propagated with the expected VLAN configuration on the vCMP guest.
  16. Optional: If you created a dummy VLAN in step 3 of this procedure, re-assign and delete the dummy VLAN by completing the following optional process:
    1. Navigate to Network > Self IPs.
    2. Click the name of the re-assigned self IP.
    3. For the VLAN / Tunnel setting, select the desired VLAN.
    4. Click Update.
    5. Navigate to Network > VLANs > VLAN List.
    6. Select the check box for the dummy VLAN, and then click Delete.
    7. Click Delete again.
