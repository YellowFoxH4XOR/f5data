Known Issue

The BIG-IP system may experience a kernel panic when processing internal TSO frames.

When processing application traffic, the BIG-IP system can employ TCP segment offload (TSO) when communicating with virtual network interface card (VNIC) drivers. On rare occasions, TMM can send TSO frames greater than or equal to 64 kilobytes, which can cause the Linux kernel to panic. While this tends to be associated with large volumes of traffic, this issue may also be seen with lower traffic levels.

Impact

The BIG-IP system silently reboots due to a Linux kernel panic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H500490 on the Diagnostics > Identified > Low screen.
  • The BIG-IP system reboots without warning and fails over to the standby system if configured for high availability.
  • The BIG-IP system posts a message similar to the following example:

    emerg kernel: Kernel panic - not syncing: Fatal exception

  • In the /var/log/kern.log file, you may observe messages similar to the following example:

    alert kernel: BUG: unable to handle kernel paging request at 000000000001000a
    alert kernel: IP: [<ffffffffa0408e32>] cb_memcpy_to_iovec+0x29/0x54 [vnic]
    warning kernel: PGD 1ba2e0067 PUD 1bbdf0067 PMD 0
    emerg kernel: Oops: 0002 [#1] SMP
