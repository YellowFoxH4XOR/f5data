Known Issue

Online Certificate Status Protocol (OCSP) stapling may cause the Traffic Management Microkernel (TMM) process to restart and produce a core file.

This issue occurs when all of the following conditions are met:
  • You have a virtual server associated with a Client SSL profile that is configured with an OCSP stapling profile.
  • The BIG-IP system initiates an OCSP request for an SSL handshake to the virtual server.
  • Before the OCSP request is answered, a configuration change is made, causing the SSL handshake to abort.
  • The OCSP responder subsequently returns an OCSP response that indicates an error (non-200 status code).

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high-availability pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:
  • The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart.
  • If configured for high availability (HA), the affected BIG-IP device fails over to a configured peer device.
  • The BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp that correlates with the traffic interruption.

Workaround

There is no workaround for this issue. However, you more likely to encounter this rare race condition when performing a configuration update (including a ConfigSync operation from a high-availability peer) on a heavily loaded system. You may be able to reduce the likelihood of encountering this issue by performing configuration updates during a lower traffic period.
