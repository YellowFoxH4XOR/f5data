Known Issue

This is the result of a known issue. The /config/ssl/ssl.crt/ca-bundle.crt file incorrectly includes an X.509 certificate which is meant for client browsers only. The details of the certificate are as follows:

Common Name = VeriSign Class 3 Public Primary Certification Authority - G5
Serial Number = 18:DA:D1:9E:26:7D:E8:BB:4A:21:58:CD:CC:6B:3B:4A
SHA1 Fingerprint = 4E:B6:D5:78:49:9B:1C:CF:5F:58:1E:AD:56:BE:3D:9B:67:44:A5:E5
Valid From = Tue November 07 2006
Valid To = Wed July 16 2036

The fact that the certificate is included in the file means that virtual servers using VeriSign Extended Validation (EV) certificates may not work as intended on older browsers that do not support EV functionality. Specifically, some of the VeriSign non-EV intermediate certificates do not get passed to the client, which prevents older browsers from being able to verify the chain of trust.

F5 Product Development tracked this issue as ID 338848 and it was fixed in BIG-IP 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

Additional Information

For more information about the certificate and how VeriSign signs their EV certificates, refer to the following articles. The following links take you to resources outside of AskF5, and it is possible that the documents may be removed without our knowledge.

  • http://www.verisign.com/support/roots.html

Workaround

You can work around this issue by manually removing the offending certificate from the file. To do so, perform the following procedure:

  1. Log in to the BIG-IP system command line.
  2. Change directories to the /config/ssl/ssl.crt/ directory by typing the following command:

    cd /config/ssl/ssl.crt/

  3. Back up the original ca-bundle.crt file by typing the following command:

    cp ca-bundle.crt ca-bundle.crt.SOL12753

  4. Using a text editor, open the ca-bundle.crt file.
  5. Search the file for the Common Name of the offending certificate.
  6. Once you have located the offending certificate, remove it from the file by deleting the following lines, and all lines in between:

    Certificate:

    to

    -----END CERTIFICATE-----

    If you have not previously modified the file, these are lines 9375 to 9462, inclusive.
  7. Save the file and exit the editor.
  8. Type the following command to reload the configuration from disk:

    bigpipe load

Note: If the BIG-IP system is a member of a high availability (HA) pair, you must replicate the changes you made to the ca-bundle.cert file on the peer system. To do so, you can either repeat the procedure on the peer system, or perform a ConfigSync to the peer system. For 10.x, the ca-bundle.cert file is included when you sync the configuration to a peer system.

Note: If the affected platform is a VIPRION system, replicate the changes you made to the ca-bundle.crt file on all other blades. For convenience, you may transfer the updated file to the other blades using Secure Copy (SCP).
