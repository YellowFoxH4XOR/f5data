K11876: The BIG-IP WebAccelerator may send an HTTP 503 status response when the parsing queue is full

Known Issue

This is the result of a known issue. If a valid response is received from the origin web server (OWS), but the system is overloaded and the parsing queue used by the pvac process is full, the OWS response is discarded, and the BIG-IP WebAccelerator system responds to the request with an HTTP 503 Server Busy status response. The expected behavior is for the BIG-IP WebAccelerator to send the OWS response directly to the client.

When a parsing queue overflow occurs, error messages that appear similar to the following example are logged to the /var/log/wa/pvac.log file:

debug WA Debug (25904): [ PvSysApp.cxx:671 store_in_cache ] Error adding to Queue

Note: Since the condition occurs under heavy load and each time a response results in a queue overflow, this error message may be logged repeatedly.

F5 Product Development tracked this issue as ID 243307 (formerly CR136257) and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

You may be able to work around this issue in one of the following ways:

  • Reducing the value of the maxResponseDataSize setting
  • Increasing the size of the parser queue

Reducing the value of the maxResponseDataSize setting

Depending on your response traffic profile, you may be able to work around this issue by modifying the maxResponseDataSize setting to use a smaller value. The maxResponseDataSize setting limits the size of the largest response you want the BIG-IP WebAccelerator to parse. Responses that are larger than the value of the maxResponseDataSize setting will be proxied instead. The default value of the maxResponseDataSize setting is 67,108,864 bytes (64 MB). If your WebAccelerator system is processing many files that are larger than the average file size but smaller than 64 MB, you may be able to reduce the number of requests flowing through the parser queue by reducing the value of the maxResponseDataSize setting. To do so, perform the following procedure:

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Change directories to the /config/wa directory by typing the following command:

    cd /config/wa
  3. Back up the original pvsystem.conf file by typing the following command:

    cp pvsystem.conf pvsystem.conf.sol11876
  4. Open the pvsystem.conf file in a text editor.
  5. Locate the maxResponseDataSize entry:

    <maxResponseDataSize>67108864</maxResponseDataSize>
  6. Edit the maxResponseDataSize entry to the desired value.  For example, the following line in the pvsystem.conf file causes the BIG-IP WebAccelerator system to proxy all responses that are 56 MB or larger:

    <maxResponseDataSize>58720256</maxResponseDataSize>
  7. Save the pvsystem.conf file.
  8. Restart the BIG-IP WebAccelerator process by typing the following command:

    bigstart restart pvac

Increasing the size of the parser queue

You may also be able to work around this issue by increasing the size of the parser queue. However, increasing the queue size may reduce resources available to other processes, and may negatively impact system performance. For assistance with determining the appropriate course of action, contact F5 Technical Support.
