Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP system experienced an unexpected failover.
  • You want to determine the date and time of the failover event.

Description

A BIG-IP failover occurs when an active BIG-IP system in a device group becomes unavailable, causing a peer device to become active and begin processing traffic. A failover event can be the result of routine maintenance performed by an administrator or an unexpected issue that triggers the failover, such as resource or network-related problems. When investigating a BIG-IP failover you may want to determine the date and time of the failover event.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • The BIG-IP systems are configured in a sync-failover device group.

Procedures

Display how long the BIG-IP system has been in the current failover state

To display the current failover state of the BIG-IP system (active, standby, offline, forced_offline) and how long it has been in that state, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the TMOS shell by entering the following command:

    tmsh

  2. To display the current failover state of the BIG-IP system and how long it has been in that state, enter the following command:

    show /sys failover

    For example, the following command output indicates the system has been in standby failover status for 2:58:17 (2 hours, 58 minutes and 17 seconds):

    Failover standby for 0d 02:58:17

  3. Repeat step 2 for other device group members.

Determine the failover date and time

You can determine the failover date and time by reviewing the system log files. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the BIG-IP command line.
  2. To display log messages related to the system transitioning to an active or standby state, search for certain patterns in the /var/log/ltm file similar to the following example:

    egrep -i 'active|standby' /var/log/ltm
    For example, the following log entries indicate device bigip1.int transitioned from Standby to Active state at 01:17:22:
    Apr 23 01:17:22 bigip1.int notice sod[7679]: 010c006d:5: Leaving Standby for Active: Next Active, peers agree on config.
    Apr 23 01:17:22 bigip1.int notice sod[7679]: 010c0053:5: Active for traffic group traffic-group-1.
    Apr 23 01:17:22 bigip1.int notice sod[7679]: 010c0019:5: Active

  3. Repeat step 2 for other device group members as needed.
