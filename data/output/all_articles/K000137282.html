Description

Running tcpdump under certain conditions might cause services to restart.

Environment

BIG-IP

Running tcpdump under certain conditions such as:

  • wide-open captures (that capture all packets traversing the device)
  • captures not filtered to something specific (e.g., tailored to capture only a specific client or a specific IP address)
  • captures that are filtered to capture something specific but still capture a very large amount of traffic
  • heavily loaded systems

Cause

Tcpdump captured packets are sent by TMM towards the tcpdump process via a virtual NIC interface. This same interface is used for other purposes such as MCPD to TMM communication. If this interface is clogged due to too much traffic, MCPD and TMM might lose communication which will cause services to restart (as a failsafe mechanism). If that's the case, you will see logs such as:

 

<13> Oct 16 12:22:11 <hostname> notice Initiating TMM shutdown.

<13> Oct 16 12:22:11 <hostname> notice MCP connection aborted, exiting.

 

 Recommended Actions

If needing to run packet captures on the BIG-IP device, ensure to use relevant filters to capture only needed traffic (e.g., specific client IP).

The BIG-IP system is designed as an application delivery network platform and not as a packet capture device. If you intend to capture traffic under high load conditions, F5 recommends that you mirror traffic to a dedicated sniffing device.
