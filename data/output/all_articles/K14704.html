Topic

You should consider using this procedure under the following condition:

  • You have rolled back to a previous version after an upgrade and have update the configuration, or configuration has been updated since rollback, and you want to boot into the new version again.
  • When activating a boot location, you want to install the configuration from a boot location other than the boot location being activated.

Important: This option is not available on VIPRION platforms or clustered vCMP guests. For more information about copying a configuration between boot locations on VIPRION platforms, refer to K14724: Using the cpcfg command to copy a configuration from one boot location to another.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • The version of the boot location being activated must be equal to or greater than the version of the boot location selected as the configuration source.

Description

Beginning in BIG-IP 11.4.0, when activating a boot location, the Install Configuration option allows you to select a configuration to be installed from a boot location other than the boot location being activated.

Procedures

Installing the configuration from a boot location other than the boot location being activated

Impact of procedure: When the new boot location is confirmed, the BIG-IP system immediately reboots into the new partition.

  1. Log in to the Configuration utility as an administrative user.
  2. Navigate to System > Software Management > Boot Locations.
  3. Click the boot location you want to activate.
  4. From the Install Configuration list, click Yes.
  5. From the Source Volume list, select the SOURCE boot location configuration to be installed. Use default value to install the current running Boot Location.

    Note: Only boot locations with a version equal to or greater than 11.4.0 are available.

  6. Click Activate.
  7. To confirm that you want to boot in another volume, click OK.

Important: If the version of the boot location being activated is earlier than the version of the boot location selected as the configuration source, the activation fails. Also, you might observe an error message similar to the following example:

info: New version (11.x.x) is not >= originating version (11.y.y); configuration is not compatible. configuration roll-forward desired but not compatible.
