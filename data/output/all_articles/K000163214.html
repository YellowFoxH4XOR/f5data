Description

After a VELOS blade reboot, deployed tenants may remain pending or enter Tenant deployment failed with:

Not ready: containers with unready status: [compute]

Multus/CNI logs (/var/log/messages) may contain:

failed to lookup master "team0.<VLAN>": Link not found

The missing team0.<VLAN> interface prevents the tenant management network from being attached, so the tenant does not reach the Running state.

Environment

  • VELOS chassis running F5OS-C
  • BIG-IP tenants
  • Multiple tenants configured with management VLANs
  • Tenants deployed during a blade reboot
  • Tenant management networks using VLAN subinterfaces on the blade team0 interface
  • Multus and CNI used for tenant network provisioning

Cause

Bug ID 2449101

When a blade is rebooted while multiple management-VLAN tenants are deployed, Multus may fail to recreate the tenant management-network attachment. The required team0.<VLAN> interface is unavailable, causing tenant network provisioning to fail and preventing the tenant from starting.

Recommended Actions

Recover an affected tenant

  1. Confirm that the tenant is affected and that the logs contain an error similar to:

    failed to lookup master "team0.<VLAN>": Link not found

  2. Confirm that the affected blade and partition services are healthy and ready.
  3. Change the tenant running state from Deployed to Configured.
  4. Change the tenant running state from Configured back to Deployed.
  5. Confirm that the tenant reaches the Running state and that the compute container is ready.

Prevent recurrence during a planned reboot

  1. Change tenants using management VLANs from Deployed to Configured before rebooting the blade.
  2. Reboot the blade.
  3. Wait for the blade and partition services to return to a healthy and ready state.
  4. Return the tenants to Deployed.
  5. Confirm tenant management-network connectivity and tenant status.

Apply the fix

Upgrade to a software release containing the fix for Bug ID 2449101, or install the applicable engineering fix when provided by F5.

Additional Information

If the issue recurs, collect diagnostic data from the Controller, affected Partition, and affected tenant while the failure is active. Review the logs for:

  • Multus/CNI network-attachment errors
  • Missing team0.<VLAN> interfaces
  • kube-multus errors
  • Blade readiness or reachability events
  • tmstat-rsync failures
  • Tenant status and management-VLAN assignments
