Known Issue

Requests that match a wildcard cookie may generate excessive entries in the BIG-IP ASM request database

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM policy contains an allowed wildcard cookie with tightening enabled
  • The learn flag is disabled for the modified domain cookie violation
  • A request contains a cookie that matches the affected wildcard cookie definition

This combination of settings will cause records that do not contain learning suggestion data to be unnecessarily written to the BIG-IP ASM request database. As the request database is shared by all active web applications and has a hard limit for request storage, writing records to the database that are not necessary and for which no suggestions are desired may waste space that can be used for logging legitimate requests

Impact

Excessive unnecessary records may cause the BIG-IP ASM system to rotate legitimate learning suggestions out of the database too quickly.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system removes learning suggestions from the Application Security > Policy Building > Manual screen faster than expected, based on observed rate of requests that should be generating learning suggestions and violations

Workaround

To work around this issue, you can properly configure the BIG-IP ASM policy. Tightening and learning for allowed wildcard domain cookies should either both be enabled or both disabled, depending on whether you want to receive learning suggestions for requests that match the defined wildcard cookie. To disable learning, you must also disable tightening. To generate learning suggestions, you must enable learning. To correctly configure your policy for either option, perform the procedure appropriate for your requirements:

Disable tightening

Impact of workaround: None.

If you do not want to receive learning suggestions for requests as a result of wildcard cookie tightening (for example, the modified domain cookie violation does not have the learn flag enabled), you should disable tightening as well. To disable tightening, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to the Application Security > Headers > Cookies > Allowed Cookies screen.
  3. Ensure that the Current edited policy menu is set to the appropriate security policy.
  4. Click on the name of the affected wildcard cookie.
  5. Disable the Perform Tightening option.
  6. Click Update.
  7. Click Apply Policy.

Enable learning

Impact of workaround: Learning will be enabled for all domain cookies processed by the BIG-IP ASM security policy.

If you want to receive tightening and learning information for wildcard cookies, you should enable learning in addition to tightening. To enable learning, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to the Application Security > Policy screen.
  3. Ensure that the Current edited policy menu is set to the appropriate security policy.
  4. From the Blocking tab, choose Settings.
  5. Enable the learn option for the Modified Domain Cookies violation.
  6. Click Save.
  7. Click Apply Policy.
