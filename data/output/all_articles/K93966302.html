K93966302: Routes of Linux host being lost may cause node/pool member down

Type
Support Solution
Published
2020-12-18
Updated
2025-07-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K93966302

Description

If a route of Linux host is lost, no matter its interface route (directly connected), or static route (created by tmsh), monitor traffic might not be sent out and then node/pool member might be down.
On Linux host, the bigd monitor daemon provides system health checks, and it relies on these routes to send monitor traffic, so if the route is lost, the node/pool member might be down.

Environment

  • Linux

  • Health Monitor

Cause

Someone mistakenly deletes route on Linux host.

Recommended Actions

To resolve this issue, you need to delete and re-create the routing object (e.g. interface route or a static route) in tmsh.
Note:  It's not recommended to operate on routes of Linux host, and all route-related operation, including delete/add/modify, should be done in tmsh.

Additional Information

When a self IP or static route is created in tmsh, a corresponding route will be created on Linux host like this:

Flags mean the following:
U : This flag signifies that the route is up
G : This flag signifies that the route is to a gateway. If this flag is not present then we can say that the route is to a directly connected destination
H : This flag signifies that the route is to a host which means that the destination is a complete host address. If this flag is not present then it can be assumed that the route is to a network and destination would be a network address.
Sometimes you may find an interface route or static route lost on host, but in tmsh show net route it's still there.
