K312: Equivalence operators in production rules must be separated on either side with a space

Known Issue

This may be the result of a known issue. A production rule must contain a space on both sides of the operator, or it will not allow equivalence checks.

For example, the following simplified statement will work:

A = A

The following statements will not work:

A=A
A =A
A= A

If this is the reason for the failure, the production rule will fail silently when the configuration is loaded and the 3dparse command will not report an error.

F5 Networks Product Development tracked this issue as CR18008 and CR41809.

Workaround

To work around this issue, modify the production rule statement so that it contains a space on both side of the operator.
