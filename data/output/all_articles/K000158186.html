Description

The NGINX Loadbalancer for Kubernetes (NLK) project has been archived and moved from nginxinc/nginx-loadbalancer-kubernetes to nginx/nginx-loadbalancer-kubernetes. This KB provides step-by-step guidance for migrating your installation, including required changes to your ConfigMap and NodePort definitions.

Environment

NGINX Ingress Controller combined with NGINX Loadbalancer for Kubernetes (NLK) and NGINX on Load Balancer servers

Cause

You have used the archived nginxinc/nginx-loadbalancer-kubernetes github repo to install NLK onto your NGINX Ingress Controller cluster and would now like to migrate this installation to the new nginx/nginx-loadbalancer-kubernetes repo.

Recommended Actions

  • Update the NLK ConfigMap

The ConfigMap for the NLK Controller must be updated to match your NGINX Loadbalancing Server(s). Change the nginx-hosts IP address to match your NGINX Loadbalancing Server IP(s). If you have multiple servers, separate them with a comma. Ensure the port number for the Plus API endpoint and the /api URL are correct.

Example:

apiVersion: v1
kind: ConfigMap
data:
 nginx-hosts:
  ["http://<your-nginx-plus-server1-ip>:9000/api","http://<your-nginx-plus-server2-ip>:9000/api"] # Update IP(s) as needed
metadata:
 name: nlk-config
 namespace: nlk
  • Update the NLK Deployment

Change your deployment manifests to reference the new image location from the new repository.

Example:

apiVersion: apps/v1
kind: Deployment
metadata:
 annotations:
  meta.helm.sh/release-name: nlk
  meta.helm.sh/release-namespace: nlk
 generation: 1
 labels:
  app: nlk
  app.kubernetes.io/managed-by: Helm
 name: nlk-deployment
 namespace: nlk
spec:
 progressDeadlineSeconds: 600
 replicas: 1
 revisionHistoryLimit: 10
 selector:
  matchLabels:
   app: nlk
 template:
  metadata:
   labels:
    app: nlk
  spec:
   containers:
   - env:
    image: registry-1.docker.io/nginx/nginxaas-loadbalancer-kubernetes:1.2.4
    imagePullPolicy: Always
    livenessProbe:
     failureThreshold: 3
     httpGet:
      path: /livez
      port: 51031
      scheme: HTTP
     initialDelaySeconds: 5
     periodSeconds: 2
     successThreshold: 1
     timeoutSeconds: 1
    name: nginxaas-loadbalancer-kubernetes
    ports:
    - containerPort: 51031
     name: http
     protocol: TCP
    readinessProbe:
     failureThreshold: 3
     httpGet:
      path: /readyz
      port: 51031
      scheme: HTTP
     initialDelaySeconds: 5
     periodSeconds: 2
     successThreshold: 1
     timeoutSeconds: 1
    resources: {}
    terminationMessagePath: /dev/termination-log
    terminationMessagePolicy: File
    volumeMounts:
    - mountPath: /etc/nginxaas-loadbalancer-kubernetes
     name: config
   dnsPolicy: ClusterFirst
   restartPolicy: Always
   schedulerName: default-scheduler
   securityContext: {}
   serviceAccount: nlk-nginxaas-loadbalancer-kubernetes
   serviceAccountName: nlk-nginxaas-loadbalancer-kubernetes
   terminationGracePeriodSeconds: 30
   volumes:
   - configMap:
     defaultMode: 420
     name: nlk-nginxaas-loadbalancer-kubernetes-nlk-config
    name: config
  • Update the NIC nodePort

The NodePort service manifest must use the correct port name format and annotation for NLK compatibility.

The port name should be in the format: http-<upstream-block-name>

Add the required annotation: nginx.com/nginxaas: nginxaas

Example:

apiVersion: v1
kind: Service
metadata:
 name: nginx-ingress
 namespace: nginx-ingress
 annotations:
  nginx.com/nginxaas: nginxaas
spec:
 type: NodePort
 ports:
 - port: 443
  targetPort: 443
  protocol: TCP
  name: http-cluster1-https
 selector:
  app: nginx-ingress
