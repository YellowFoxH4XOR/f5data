Known Issue

The TMM process may core if an existing FTP flow is reselected due to a pool member failure.

This issue occurs when the following conditions are met:

  • A pool with the following configuration:
     
    • Reselect for Action on Service Down
    • Priority Group Activation is enabled
  • The pool is assigned as the Last Hop Pool to a virtual server configured with an FTP profile.
  • Client establishes an FTP session to the FTP virtual server.
  • The Last Hop Pool member handling the connection goes down.

Impact

Traffic will be interrupted until TMM restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The TMM process restarts and writes a core file to the /shared/core directory.
  • FTP client traffic is interrupted or stalls.
  • The BIG-IP system fails over to the standby system.

Workaround

To work around this issue, you can set Action on Service Down to Reject on the pool that is configured as the Last Hop Pool. To do so, perform the following procedure:

Impact of workaround: The Reject option will send a RST immediately to force the client to reconnect when a pool member becomes unavailable.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Click the name of the pool that is configured as the Last Hop Pool.
  4. From the Configuration box, select Advanced.
  5. From the Action on Service Down box, select Reject.
  6. To save the changes, click Update.
