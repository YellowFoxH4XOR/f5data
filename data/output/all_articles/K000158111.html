K000158111: After upgrading, the dig command takes longer to retry unavailable nameservers. EAV scripts using dig can mark pool members down

Type
Support Solution
Published
2025-12-08
Updated
2025-12-08
Applies to
  • BIG-IP
Source

Description

After upgrading BIG-IP TMOS to the following versions:

16.1.6, 17.1.2, 17.1.3, 17.5.0, 17.5.1, 21.0.0

...the dig command takes longer to retry queries to an unavailable name server.

For example, if the first configured DNS resolver is unavailable, dig will take 15 seconds to decide to retry the next one.

The following example scenario shows you have two name servers, and one of them is unavailable.

# cat /etc/resolv.conf
nameserver   10.1.2.3 # <- name server is down
nameserver   10.100.100.100 # <- name server is available

The following shows that the dig command uses 3 retries, each at 5 seconds, for a total of 15 seconds before returning a result:

# time dig somedomain.there
;; communications error to 10.1.2.3#53: timed out
;; communications error to 10.1.2.3#53: timed out
;; communications error to 10.1.2.3#53: timed out

; <<>> DiG 9.18.37 <<>> somedomain.there

...

real  0m15.215s

This would guarantee a timeout for any EAV monitors that uses the dig script, even when the name is resolved properly by the second name server.

This results in the following symptoms:

  • EAV scripts that use the dig command may fail or time out longer as dig takes longer to time out when a nameserver fails to respond.
  • Pool members that uses the dig command may be marked down indefinitely as it times out even when other name servers are available.

 

Environment

This affects configurations that uses the BIG-IP's dig command in custom scripts and EAVs.

  • A script, EAV, or other automated method uses the dig command
  • The script relies on the dig command's timeout values for detecting availability

 

Cause

The dig command is part of the third party Bind 9 package that gets upgraded regularly to keep up with security updates and fixes. The change of behavior affected the dig command between Bind 9.16.x and Bind 9.18.x.

Recommended Actions

When using Bind 9 version 9.18.x, use the dig options +retry=1 and +timeout=1 to shorten the dig timeout in your scripts.

For example, in your EAV script, you might be using dig like this:

 

QUERY=www.example.net

dig {QUERY} | egrep -v '^|^;' | grep ${node_ip} > /dev/null 2>&1

if [ $? -eq 0 ]

then

echo "UP"

fi

 

After upgrading, use the +retry and +timeout options to shorten the amount of time dig takes to decide if the query has failed.

 

dig {QUERY} +retry=1 +timeout=1 | egrep -v '^|^;' | grep ${node_ip} > /dev/null 2>&1

 

In this example, the dig command only takes 2 second instead of 15 when a nameserver is unavailable:

# time dig somedomain.there +retry=1 +timeout=1
;; communications error to 10.1.2.3#53: timed out
;; communications error to 10.1.2.3#53: timed out

real  0m2.044s
