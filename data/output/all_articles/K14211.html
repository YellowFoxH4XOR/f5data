Topic

This article applies to BIG-IP ASM 11.x. For information about other versions, refer to the following articles:

• K9388: Using an iRule to parse post-ASM responses (9.4.x - 10.x)

Purpose

You should consider using this procedure under the following conditions:

  • You want the iRule to parse/modify the HTTP request when the BIG-IP ASM system is about to release HTTP data on the serverside of the connection.
  • You want the iRule to parse/modify the HTTP response when the BIG-IP ASM system is about to release HTTP data on the clientside of the connection.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have determined the HTTP request/response data that you want the iRule to parse
  • You must have access to the BIG-IP ASM Configuration utility

Description

The HTTP_REQUEST_RELEASE iRule command allows the system to parse the HTTP requests when the BIG-IP ASM system is about to release HTTP data on the serverside of the connection. For example, if you want the system to modify an HTTP header sent to the server after BIG-IP ASM processing has transpired, you can use the HTTP_REQUEST_RELEASE iRule command.

The HTTP_RESPONSE_RELEASE iRule command allows the system to parse the HTTP response when the BIG-IP ASM system is about to release HTTP data on the clientside of the connection. For example, if you want the system to modify an HTTP header sent to the client after BIG-IP ASM processing has transpired, you can use the HTTP_RESPONSE_RELEASE iRule command.

Procedures

Using an iRule to parse post-ASM requests

Impact of procedure: None.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Define an iRule using the HTTP_REQUEST_RELEASE command.

    For example, the following iRule parses the post-ASM request and logs the cookie to the /var/log/ltm file:

    when HTTP_REQUEST_RELEASE {
    # Define the post-ASM request action
    set myValues [HTTP::header values Cookie]
    log local0. "\[HTTP::header values Cookie\]: $myValues"
    }
  5. Click Finished.

Using an iRule to parse post-ASM responses

Impact of procedure: None.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Define an iRule using the HTTP_RESPONSE_RELEASE command.

    For example, the following iRule parses the post-ASM response and logs the cookie to the /var/log/ltm file:

    when HTTP_RESPONSE_RELEASE {
    # Define the post-ASM response action
    set myValues [HTTP::header values Set-Cookie]
    log local0. "\[HTTP::header values Set-Cookie\]: $myValues"
    }
  5. Click Finished.
