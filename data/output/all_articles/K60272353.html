Description

Prior to version 14.x, BIG-IP ASM/AWAF has no wildcard option for disallowed URLs. However you may want to block requests to some wildcard URLs, for example, /training/lorem_page_*.html. 

Environment

  • BIG-IP version prior to 14

  • BIG-IP ASM

  • Wildcard disallowed URLs

Cause

None

Recommended Actions

You may want to block wildcard URLs with the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.

  2. Go to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.

  3. In the Current edited policy list, verify that the listed security policy is the one you want to work on.

  4. Select Create.

  5. Switch to Advanced settings

  6. In the URL section, define the URL properties, as follows:

  • From the menu, select Wildcard.

It indicates that the URL name will contain one or more wildcard characters; any URL that matches the wildcard expression is considered legal. For example, /training/lorem_page_*.html.??

  • From the menu, select HTTP or HTTPS.

  • Enter the name for the URL.

  1. If you want the system to place the URL in staging, leave the Perform Staging check box selected. When staging is enabled for a URL, the system logs learning suggestions to the Learning screen and does not block requests for the URL.

  2. In the Methods Enforcement tab, check the box of Override policy allowed methods.

  3. From the list, select HEAD, POST and GET, and move them left into the Overridden Security Policy Settings. This will put these three allowed methods into Disallowed state, which will disallow all possible methods, in order to block wildcard URLs.

  4. Select Create and Apply Policy.

Additional Information

Alternatively, you may use custom attack signatures to implement the same request. Please refer to this link for more details: K52413835
