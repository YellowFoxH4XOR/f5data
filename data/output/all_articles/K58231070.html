Known Issue

The BIG-IP system may fail to load the configuration after you reboot to an upgraded slot.

This issue occurs when all of the following conditions are met:

  • You have provisioned the BIG-IP system with BIG-IP Analytics.
  • The BIG-IP system is running 11.0.0, 11.1.0, or 11.2.0.
  • You have configured the BIG-IP system with two or more partitions.
  • You have configured two Analytics profiles with the Traffic Capturing Logging Type setting set to External in different partitions.
  • You have configured two Analytics profiles with the Remote Server IP address settings pointing to the same IP address.
  • You have upgraded the BIG-IP system to an affected version listed in the Applies To box and rebooted to the upgraded slot.

Impact

Upon booting up the BIG-IP system, it is unable to load the configuration in the upgraded slot.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you boot up the BIG-IP system, it is unable to load the configuration in the upgraded slot.
  • When you attempt to load the configuration, the BIG-IP system reports an error message that appears similar to the following example:

    0107003a:3: Pool member node (/analytic-test/192.168.5.50) and existing node (/Common/192.168.5.50) cannot use the same IP Address (192.168.5.50). Unexpected Error: Loading configuration process failed.

Workaround

There is no workaround for this issue. You can recover from this issue by booting to the previous slot, removing the affected Analytics profiles, upgrading the system again, and then reconfiguring the Analytics profiles in the upgraded system. For information about reconfiguring the Analytics profiles in the upgraded system, refer to the Configuring Remote High-Speed Logging chapter of the BIG-IP TMOS: Implementations guide.
