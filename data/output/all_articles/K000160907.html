K000160907: NGINX Instance Manager UI Displays "Last Usage sent: Invalid Date" After Migration or License Update

Type
Support Solution
Published
2026-04-20
Updated
2026-04-20
Applies to
  • NGINX Products
  • NGINX Instance Manager: 2.21.0
Source
https://my.f5.com/manage/s/article/K000160907

Description

When using NGINX Instance Manager version 2.21.0, the UI may display the message "Last Usage sent: Invalid Date" after migrating managed NGINX instances from a previous deployment or after replacing an expired license. This occurs when attempting to send usage reports from the new installation. System logs indicate that entitlements are present and valid, but the UI does not reflect the correct last usage report submission date.

  • UI shows: Last Usage sent: Invalid Date
  • Usage report submission and acknowledgment process does not update the reporting period as expected
  • System logs include:

    Entitlements already present, resetting check attempts and returning true

Environment

  • Product: NGINX Instance Manager
  • Version: 2.21.0
  • Managed NGINX instances migrated from a previous deployment
  • Usage reporting attempted in both disconnected and connected modes
  • License replacement scenarios

Cause

Unknown at time of publication.

Answer/Recommended Actions

  1. Upgrade to NGINX Instance Manager 2.22 or Later:
    • Starting with version 2.22, the licensing and aggregated usage reporting mechanism is replaced with a new reporting approach.
    • The UI will be updated to reflect the new reporting format and resolve the "Invalid Date" display.
  2. Monitor Release Notes:
    • Review the release notes for NGINX Instance Manager 2.22 and later for details on the new reporting process and any required migration steps.
  3. No Further Troubleshooting Required for 2.21.0:
    • If you encounter this issue in version 2.21.0, upgrading to the latest version is the recommended solution.

Additional Information

  • The error does not impact entitlement validation or the ability to manage NGINX instances.
  • The issue is cosmetic and related to the reporting UI, not to license enforcement.
