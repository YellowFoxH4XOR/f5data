Description

When copying SNMPv3 user configuration containing SecureVault-protected passwords (values starting with "$M$...") from one BIG-IP device to another that does not share the same SecureVault master key, the Management Control Plane Daemon (MCPD) becomes unstable. This results in MCPD failing to load the configuration and entering a continuous restart loop. Error messages are logged in /var/log/ltm and the affected BIG-IP devices become inoperative, causing application downtime.

Environment

  • BIG-IP
  • SNMPv3
  • MCPD

Cause

Copying SecureVault-protected SNMPv3 password values (those beginning with "$M$...") from one BIG-IP device to another with a different SecureVault master key causes MCPD to fail to decrypt the password. The system currently accepts such configurations at config time, but fails to load them after a restart, resulting in MCPD instability and a restart loop.

Recommended Actions

  1. Do not copy SecureVault-protected password values (e.g., "$M$...") between BIG-IP devices unless they share the same SecureVault master key.
  2. When configuring SNMPv3 users on a new device, use plain text passwords or re-enter the password manually instead of copying the encrypted value from another device.
  3. If the configuration has already been applied and the device is inoperative, revert to a known good configuration or manually edit the configuration to remove or correct the problematic SNMPv3 user entries. Remember to create a backup copy of /config/bigip_base.conf.

Note: The provided commands automatically takes care of this via the .bkp extension.

You can use this command to clear whole SNMP configuration:
sed -i.bkp '/sys snmp {/,/^}/d' /config/bigip_base.conf 

 

If you want to specify which SNMP entries you want to remove (i.e. the ones where you copied SecureVault password), please check following example:

Example SNMP entries you want to remove:

        /Common/test_1 {
            auth-password ***scrubbed***
            auth-password-encrypted ***scrubbed***
            auth-protocol sha
            oid-subset .1
            privacy-password ***scrubbed***
            privacy-password-encrypted ***scrubbed***
            privacy-protocol aes
            security-level auth-privacy
            username test_user
        }
        /Common/example_1 {
            auth-password ***scrubbed***
            auth-password-encrypted ***scrubbed***
            auth-protocol sha
            oid-subset .1
            privacy-password ***scrubbed***
            privacy-password-encrypted ***scrubbed***
            privacy-protocol aes
            security-level auth-privacy
            username example_user
        }

You can modify following command:
sed -i.bkp -e '/\/<partition>\/<user/trap/other entry> {/,/^[[:space:]]*}/d' -e '/\/<partition>\/<user/trap/other entry> {/,/^[[:space:]]*}/d' /config/bigip_base.conf

 

Example:
sed -i.bkp -e '/\/Common\/test_1 {/,/^[[:space:]]*}/d' -e '/\/Common\/example_1 {/,/^[[:space:]]*}/d' /config/bigip_base.conf


If the system does not recover automatically, restart MCPD or reboot the device once.
