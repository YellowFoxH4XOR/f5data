K000161968: WAF Block Event Appears in Requests Dashboard but Not in Security Analytics in F5 Distributed Cloud

Type
Support Solution
Published
2026-06-29
Updated
2026-06-29
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud WAF
Source
https://my.f5.com/manage/s/article/K000161968

Description

A WAF block event is visible in the Requests dashboard but does not appear in Security Analytics. The expected security event (secevent) for a blocked request is missing, even though the request was blocked by the WAF.

Environment

  • F5 Distributed Cloud Web App & API Protection
  • Observed in Requests and Security Analytics dashboards

Cause

The missing security event was a one-off anomaly. Access logs are sampled, while security events are generally not sampled except under extreme load. Rare mismatches may occur due to transient factors such as network hiccups, race conditions, or momentary errors.

Answer/Recommended Actions

  • Monitor the relationship between request events and security events. If significant or recurring deviations are observed, collect examples and contact F5 support for further investigation.
  • For extended log retention and centralized visibility, enable Global Log Receiver (GLR) to stream logs to your SIEM. GLR extends retention beyond the default 7 days for access logs and 30 days for security events, but is subject to the same sampling as the console.

Additional Information

  • The XC console retains Request/Access logs for 7 days and Security Events for 30 days.
  • Security events are not sampled under normal conditions, but access logs are.
  • Rare mismatches between request and security events may occur due to sampling or transient system factors.
