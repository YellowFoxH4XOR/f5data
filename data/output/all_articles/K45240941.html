Known Issue

BIG-IP AAM and BIG-IP WebAccelerator may occasionally set Intelligent Browser Referencing (IBR) tags to all zeroes.

This issue occurs when all of the following conditions are met:

  • BIG-IP AAM or BIG-IP WebAccelerator makes a conditional request to the origin web server (OWS) to refresh expired content in its cache. 
  • The response from the OWS lacks a Content-Length header and is deemed uncacheable (S10206) by BIG-IP AAM or BIG-IP WebAccelerator.
Requests with invalid IBR tags should still succeed allowing the related page to load. However, as a result of the invalid IBR tags, clients may needlessly generate requests for unchanged cached content.

Impact

Clients experience undesirable caching behavior. 

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Client requests have an empty IBR tag appended to the URL.

    For example:

    ;wa0000000000000000
