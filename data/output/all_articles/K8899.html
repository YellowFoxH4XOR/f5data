Known Issue

This is the result of a known issue. When a floating point number is entered as the coefficient or threshold value in an SNMP DCA or SNMP DCA Base monitor, the value is incorrectly parsed as an additional OID to poll, and the monitor is prevented from correctly gathering the statistics required to calculate the dynamic ratio of the pool member.

F5 Product Development tracked this issue as ID 246732 and it was fixed in BIG-IP 11.6.0. For information about upgrading, refer to the LTM, ASM, or Link Controller release notes.

Workaround

To work around this issue, specify the values for the coefficient and the threshold as integers rather than floating point numbers when defining the monitor.

The following example will fail to calculate the proper dynamic ratio value for the pool member, since the USEROID_COEFFICIENT value has been specified as the floating point value 2.0:

monitor snmp_base_bad {
defaults from snmp_dca_base
USEROID ".1.3.6.1.2.1.25.3.3.1.2.1"
USEROID_COEFFICIENT "2.0"
USEROID_THRESHOLD "90"
}

To prevent the monitor from incorrectly parsing the coefficient value as OID, specify the coefficient value as the integer value of 2:

monitor snmp_base_good {
defaults from snmp_dca_base
USEROID ".1.3.6.1.2.1.25.3.3.1.2.1"
USEROID_COEFFICIENT "2"
USEROID_THRESHOLD "90"
}
