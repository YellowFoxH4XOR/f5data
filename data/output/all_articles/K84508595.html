K84508595: Different SSL protocols for different servers

Type
Support Solution
Published
2020-01-15
Updated
2025-04-01
Applies to
  • NGINX Products
  • NGINX Plus: R19, R18, R17, R16, R20, R14, R13, R15
Source
https://my.f5.com/manage/s/article/K84508595

Description

  • Due to security reasons, you have to use strict ssl_protocols TLSv1.2; for the particular server, but ssl_protocols TLSv1 TLSv1.1 TLSv1.2; for the rest.
  • No errors are reported, but all the servers are reachable over TLSv1, TLSv1.1 and TLSv1.2.

Environment

  • NGINX Plus configured to perform SSL termination

Cause

There is a concept of a listening socket in NGINX and underlying operating system. All listen directives for the same IP:PORT pair refer to a single listening socket object.

The ssl_protocols directive works for the listen socket instead of a particular virtual server. In turn, different server blocks always use the same set of SSL protocols.

Thus, ssl_protocols takes effect only when defined for a default server (the very first in configuration or explicitly marked with default_server option) for a specific IP:PORT pair and affects all servers listening on the same socket.

Recommended Actions

There are two possible approaches for implementing the desired behavior, each has its trade-off:

  1. You can use another IP address or TCP port for the server that requires alternative set of SSL protocols: 
    server {
    listen 192.0.2.1:443 ssl;
    ssl_protocols TLSv1 TLSv1.1 TLSv1.2;
    ...
}

server {
    listen 192.0.2.2:443 ssl;
    ssl_protocols TLSv1.2;
    ...
}

server {
    listen 192.0.2.2:4443 ssl;
    ssl_protocols TLSv1.1 TLSv1.2;
    ...
}

    Note: Usage of non-standard TCP ports may look confusing from clients' perspective.

  2. You can allow all protocols but restrict some of them after actual handshake happens with using of built-in $ssl_protocol variable: 
    map $ssl_protocol $denied_protocol {
    TLSv1.2  0;  # allowed
    default  1;  # all the rest is denied
}

server {
    listen 443 ssl default_server;
    ssl_protocols TLSv1 TLSv1.1 TLSv1.2;

    # here a permissive list of protocols is allowed
    ...
}

server {
    listen 443 ssl;

    # here only TLS 1.2 is allowed

    if ($denied_protocol) {
        return 444;  # drop the connection
    }

    ...
}

    Note: This way you always allow clients to perform a handshake with protocols from the permissive list, but then drop the connection if its SSL protocol is not allowed.
