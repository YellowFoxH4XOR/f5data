Known Issue

This is the result of a known issue. If a BIG-IP version 9.x installation is aborted, or an invalid installation of BIG-IP version 4.x on a BIG-IP 9.x platform was attempted, the Master Boot Record (MBR) may be left in an unknown state.

If the installation script is unable to interpret the MBR properly, invalid parameters are passed to sfdisk. Then, creation of the file system used for the host operating system fails, resulting in a failed installation.

Although the installation has failed, several programs will operate properly. For example, the SCCP boots properly allowing users to access the SCCP and the host file system containing the grub loader allows the initial stages of the boot process.

However, without the host operating system, the system appears to hang after the BIOS messages on the host display. The host actually remains stuck at the grub command prompt, which is not visible from the SCCP.

Subsequent reinstallation attempts to restore the BIG-IP system into a working state fail.

Note: These symptoms may be misinterpreted as a Compact Flash (CF) or hard drive failure.

Terminal logs from the installation attempt may contain messages similar to the following examples:

F5 Product Development tracked this issue as CR57971 and it was fixed in BIG-IP versions 9.1.2 and 9.2.3. For information about upgrading, refer to the LTM, GTM, ASM, or Link Controller Release Notes.

Workaround

To work around this issue you must clear the MBR of the Compact Flash drive or the hard drive. This will allow the BIG-IP installation script to correctly repartition the drive during installation. To clear the MBR, refer to K6346: Recovering from a corrupt drive partition.
