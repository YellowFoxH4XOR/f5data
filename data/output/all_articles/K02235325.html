Description
An error message similar to "signature-set cannot be deployed because it includes factory signatures that don't exist on the device. Please consider updating the BIG-IP to the latest signature file." may be displayed when attempting to Evaluate ASM configuration on BIG-IPs after they have had an Attack Signature Update (ASU) file installed.

Environment

  • BIG-IQ
  • BIG-IP with ASM module provisioned and ASM services configured in BIG-IQ
  • ASU file installed on BIG-IP

Cause
ASU files contain new Attack Signatures, modify existing Attack Signatures and can also delete existing Attack Signatures. BIG-IQ intentionally does not delete Attack Signatures so that it can provide backwards-compatibility for all ASMs it is managing, including rollback operations. After an ASU is installed on a BIG-IQ it also does not alter any existing ASM configuration, once again for backwards-compatibility.

A situation can occur where an ASU deployed to a BIG-IP deletes Attack Signature(s) referenced by Signature Set(s) on the BIG-IQ which are currently deployed or desired to be deployed to said BIG-IP. When attempting to Evaluate or Deploy to that BIG-IP the error message noted above will be raised because the BIG-IQ Signature Set references Attack Signature(s) not present on the BIG-IP (because they were deleted via the ASU). While the error message will reference updating to the latest ASU, that is not the correct action in this circumstance.

Recommended Actions

  1. Review all Attack Signatures noted in the error message and either remove them from the Signature Set attempting to be deployed to the BIG-IP, or create a new Signature Set without those Attack Signatures and associate that with the BIG-IP instead
  2. Before subsequent ASU updates, review the Readme.txt associate with the ASU update and note all Attack Signatures deleted between the current ASU and the desired ASU (since ASU updates are cumulative), cross-reference those deleted Attack Signatures with all Signature Sets that are/will be associated with the target BIG-IP(s) and reconcile the Signature Sets appropriately
