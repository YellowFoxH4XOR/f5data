Description
BIG-IP System may incorrectly remove Routing Header extensions in IPv6 Packets. For example, here is the packet reaching the BIG-IP system interface:

Internet Protocol Version 6, Src: fc00::613:176, Dst: fc00::1455:ff04
    0110 .... = Version: 6
    .... 0000 0000 .... .... .... .... .... = Traffic Class: 0x00 (DSCP: CS0, ECN: Not-ECT)
    .... .... .... 0000 0000 0000 0000 0000 = Flow Label: 0x00000
    Payload Length: 44
    Next Header: Routing Header for IPv6 (43)
    Hop Limit: 64
    Source: fc00::613:176
    Destination: fc00::1455:ff04
    Routing Header for IPv6 (Source Route)
        Next Header: Routing Header for IPv6 (43)
        Length: 0
        Type: Source Route (0)
        Segments Left: 0
        Reserved: 00000000
    Routing Header for IPv6 (Source Route)
        Next Header: ICMPv6 (58)
        Length: 0
        [Length: 8 bytes]
        Type: Source Route (0)
        Segments Left: 0
        Reserved: 00000000
Internet Control Message Protocol v6
    Type: Echo (ping) request (128)
    Code: 0
    Checksum: 0x4ab4 [correct]
    Identifier: 0x0000
    Sequence: 0
    Data (20 bytes)

When the packet is captured on interface 0.0, it is rewritten to the following:

Internet Protocol Version 6, Src: fc00::613:176, Dst: fc00::1455:ff04
    0110 .... = Version: 6
    .... 0000 0000 .... .... .... .... .... = Traffic Class: 0x00 (DSCP: CS0, ECN: Not-ECT)
    .... .... .... 0000 0000 0000 0000 0000 = Flow Label: 0x00000
    Payload Length: 28
    Next Header: Routing Header for IPv6 (43)
    Hop Limit: 64
    Source: fc00::613:176
    Destination: fc00::1455:ff04
    Routing Header for IPv6 (Unknown type 74)
        Next Header: ICMPv6 (58)
        Length: 0
        Type: Unknown (74)
        Segments Left: 180
        Type-Specific Data: 00000000
Internet Control Message Protocol v6
    Type: Unknown (73)
    Code: 80
    Checksum: 0x5636 incorrect, should be 0x20f3
    Data: 5f50524f544f434f4c5f544553544552

As a result, this packet will be dropped.

Note: The aforementioned rewrite behaviour may be different if AFM is provisioned and the IPv6 Duplicate Extension Header option in Device Protection configuration is enabled, but the packet may not be properly forwarded.
 

Environment

This symptom occurs when an IPv6 packet with multiple Routing Header extensions hits a BIG-IP system.
 

Cause
This symptom has been identified as ID 977153 and ID 985925.

Recommended Actions

Engineering hotfix is needed to solve the issue.
