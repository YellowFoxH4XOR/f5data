K000148619: Missing HSTS Header in HTTP Responses generated by an iRule on a Virtual Server

Type
Support Solution
Published
2024-11-27
Updated
2025-12-02
Source
https://my.f5.com/manage/s/article/K000148619

Description

When configuring iRule code on an F5 BIG-IP system, unexpected behavior can sometimes occur, such as HTTP headers not appearing in the response. A common scenario is when the Strict-Transport-Security (HSTS) header fails to appear in HTTP responses after applying a response-modifying iRule. 

Environment

  • BIG-IP LTM

Cause

The iRule applied to the virtual server overrides the HTTP profile's default settings, which include HSTS. In the BIG-IP system, the response generated by the iRule does not automatically inherit headers from the associated HTTP profile, resulting in the HSTS header not being included in the HTTP responses.

Recommended Actions

Modify the iRule to Include HSTS

To address this issue, modify the iRule applied to the virtual server to explicitly insert the Strict-Transport-Security header. Below is an example of the iRule:

when HTTP_REQUEST {
    HTTP::respond 302 Location "<New/Temp Location>" \
        Strict-Transport-Security "max-age=16070400; includeSubDomains"
}
  • Log in to the BIG-IP Configuration Utility.
  • Navigate to Local Traffic > iRules.
  • Click Create and define the new iRule with the provided code.
  • Associate the iRule with the affected virtual server by updating its configuration under Resources.
