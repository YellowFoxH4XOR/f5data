Description

  • The High Availability (HA) status of vCMP guest that are in a Device Group changes to Disconnected
  • No issue in communication on ConfigSync vlan is found between the guests (for example, ping of HA self-ips is successful)
  • Rebuilding of Device Trust between the guests still leaves the guests in Disconnected state
    • After rebuilding the Device Trust, the device information won't be fully populated on the peer/remote device (for example, if guest1 adds guest2 as peer, guest2 will not have the full device information for guest1)
  • Seeing similar log messages on the vCMP host
    • slot1/<hostname> crittmm[20786]: 01010025:2: Per-invocation log rate exceeded; throttling.
    • slot4/<hostname> info bcm56xxd[14701]: 012c0012:6: Trunk default member mod 1 port 0 slot 0; CMP state changed from 0x0 to 0x1
  • Seeing similar log messages on the vCMP guest
    • slot1/<hostname> warning tmm[6636]: 01260006:4: Peer cert verify error: self signed certificate in certificate chain (depth 1; cert /CN=6f58333d-575c-4b0a-90290023e939d109)

Environment

  • VIPRION provisioned as vCMP host
  • vCMP guests configured for ConfigSync/Failoever

Cause

The issue is caused by a known bug (ID 587821) in which occurs when the mcpd process on the host crashes or restarts on one or more blades. The guests running on the affected blades may not re-establish full communication with the host, resulting in loss of network connectivity on the guest - including ConfigSync/failover communication.

 Recommended Actions

  1. Log in to the Configuration utility of the vCMP host.
  2. Navigate to vCMP > Guest List.
  3. Select the check box to the left of the affected guest.
  4. Select the Disable option.
  5. Once the Requested State changes to Configured, select the check box to the left of the affected vCMP guest.
  6. Select the Deploy option.
  7. Once the Requested State changes to Deployed, the vCMP guest should be available for processing traffic.
