Description

You have URLDB and SSLO modules provisioned and there are no debug log levels configured on the unit. However, you observed the /var/log/apm is filling with a lot of urldb debug logs

 

Following are an example:

debug urldb[13684]: 01760006:7: 00000000: URL lookup test complete.
debug urldb[13684]: 01760018:7: 00000000: Number of categorized URLs: 1
debug urldb[13684]: 01760019:7: 00000000: Number of uncategorized URLs: 0
debug urldb[13684]: 01760020:7: 00000000: Number of address error URLs: 0
debug urldb[13684]: 01760021:7: 00000000: Number of failures: 0
debug urldb[13684]: 01760022:7: 00000000: Host: www.example.com
debug urldb[13684]: 01760023:7: 00000000: File:
debug urldb[13684]: 0176000f:7: 00000000: URL: https://www.example.com/
debug urldb[13684]: 01760010:7: 00000000: Original IP: 192.0.2.1

 

Environment

URLDB module is provisioned
SSL Orchestrator module is provisioned
 

Cause

urldb doesn't have any db variables to control the log level. ID 1205381 was created to track this issue.

 

Recommended Actions

To work around the issue, you can perform the following procedures to filter urldb debug logs:

1) Open /etc/syslog-ng/syslog-ng.conf

2) Look for "filter f_urldb" and put the addition code as bolded below

 

filter f_urldb {

  facility(local1) and message(": 0176[0-9a-fA-F]{4}:");

 level(warning..emerg);

};

 

3) Save the file.

4) Execute the following command to restart the logging utility syslog service.

bigstart restart syslog-ng
