Known Issue

IP fragmentation may occur between iSession peers.

This issue occurs when all of the following conditions are met:

  • An iSession connection is configured between BIG-IP AAM systems.
  • An optimized virtual server is processing traffic traversing the iSession connection.

Impact

IP fragmentation may negatively impact performance across the iSession connection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Values for Transmitted Packets or Received Packets increase when you view them using the tmsh show /sys ip-stat command.
  • You see fragmented IP packets when you use a traffic analysis tool such as tcpdump to view the traffic.

Workaround

You may be able to work around this issue by disabling the tm.tcpsegmentationoffload database key.  To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will cause a brief traffic disruption while the tmm process restarts.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. You can enable and disable the tm.tcpsegmentationoffload database key using the following command syntax:

    modify /sys db tm.tcpsegmentationoffload value <enable | disable>

    To disable the tm.tcpsegmentationoffload key, type the following command:

    modify /sys db tm.tcpsegmentationoffload value disable

  3. Restart the tmm process by typing the following command:

    restart /sys service tmm
