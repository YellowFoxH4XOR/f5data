K85539421: Configure Azure sentinel or other telemetry consumer integration with BIG-IP

Type
Support Solution
Published
2020-10-16
Updated
2023-09-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.0
Source
https://my.f5.com/manage/s/article/K85539421

Description

You want to configure Telemetry Streaming with Azure Sentinel or another supported system as a data collector. For more information about supported Telemetry Streaming consumers refer to Using Telemetry Streaming.

Environment

  • BIG-IP version 14.x and higher.
  • Data collector system account. Azure account with running Sentinel can be found on marketplace.
  • Connectivity between BIG-IP and data collector on tcp/6514 is allowed.

Cause

None

Recommended Actions

  • Install the Telemetry Streaming iControl LX Extension
  • Create the iRule that sends traffic to the internal telemetry listener
  • Create a pool to handle telemetry traffic
  • Create a virtual server to listen for Telemetry traffic
  • Create a request-log profile
  • Check for previous or existing Telemetry Declarations
  • Create a Telemetry Streaming declaration
  • Deploy the Telemetry declaration
  • Confirm the results via the logs

Install the Telemetry Streaming iControl LX Extension
Note: For devices in a HA cluster, this step needs to be done manually on each device.

  1. Download the RPM from F5 GitHub: https://github.com/F5Networks/f5-telemetry-streaming/releases
  2. Log in to the BIG-IP GUI and remain logged in for the rest of the procedures.
  3. Go to iApps > Package Management LX.
  4. Import and upload the RPM.
  5. To verify if the Telemetry Streaming plugin was installed.
curl -sku <username>:<password> https://<BIG-IP mgmt address>/mgmt/shared/telemetry/info
or
From Postman: GET  https://<BIG-IP mgmt address>/mgmt/shared/telemetry/info

Successful response: 

200 OK {
    "nodeVersion": "v8.11.1",
    "version": "1.32.0",
    "release": "2",
    "schemaCurrent": "1.32.0",
    "schemaMinimum": "0.9.0"
}

Create the iRule that sends traffic to the internal telemetry listener
Note: For devices in a HA cluster, this step will be done by Config Sync.

  1. Go to Local Traffic > iRules > Create.
  2. Create a rule named telemetry_local_rule with the following code:
    when CLIENT_ACCEPTED { 
        node 127.0.0.1 6514
    }

Create a pool to handle telemetry traffic
Note: For devices in a HA cluster, this step will be done by Config Sync.

tmsh create ltm pool telemetry monitor tcp members replace-all-with { 255.255.255.254:6514 }
tmsh save sys config

Or from the Configuration Utility:

  1. Go to Local Traffic > Pools > Create.
  2. Create a pool named telemetry with 255.255.255.254:6514 as the pool member and a tcp monitor.
    The configuration output should appear similar to the following example:

ltm pool telemetry {
    members {
        255.255.255.254:syslog-tls {
            address 255.255.255.254
        }
    }
    monitor tcp
}

Create a virtual server to listen for Telemetry traffic
Note: For devices in a HA cluster, this step will be done by Config Sync.
This virtual server will be the pool member in the telemetry pool from the previous step.

tmsh create ltm virtual telemetry_local destination 255.255.255.254:6514 rules { telemetry_local_rule } profiles replace-all-with { f5-tcp-progressive } source-address-translation { type automap } persist replace-all-with { source_addr { default yes }}
tmsh save sys config

Or from the Configuration Utility:

  1. Go to Local Traffic > Virtual Servers > Create.
  2. Create a virtual server named telemetry_local with the destination address and port of 255.255.255.254:6514.
  3. Also apply the telemetry_local_rule and enable SNAT Automap in the Source Address Translation setting.

Verify at this point that the pool, telemetry you created in the previous step is up. If not, test connectivity to it and/or create a network route with the following configuration so that the pool monitor traffic can reach the virtual server you just created.

traceroute 255.255.255.254
tmsh create net route telemetryRoute gw <next hop IP> network 255.255.255.254
tmsh save sys config

The network route configures all traffic destined for 255.255.255.254/32 to use a VLAN that the virtual server is listening on. Since the virtual server is in this procedure is listening on all VLANs, you can use an existing VLAN, for example an internal VLAN in your environment.

Create a request-log profile
Note: For devices in a HA cluster, this step will be done by Config Sync.

tmsh create ltm profile request-log telemetry_traffic_log_profile request-log-pool telemetry request-log-protocol mds-tcp request-log-template event_source=\"request_logging\",hostname=\"$BIGIP_HOSTNAME\",client_ip=\"$CLIENT_IP\",server_ip=\"$SERVER_IP\",http_method=\"$HTTP_METHOD\",http_uri=\"$HTTP_URI\",virtual_name=\"$VIRTUAL_NAME\",event_timestamp=\"$DATE_HTTP\" request-logging enabled
tmsh save sys config

Or from the Configuration Utility:

  1. Go to Local Traffic > Profiles > Other > Request Logging > Create.
  2. Create a request-log profile named telemetry_traffic_log_profile.
  3. In Request Settings, enable Request Logging, set HSL Protocol to TCP, and the Pool Name to telemetry.
  4. In the Template section enter a request log template. You can use the following example:
    event_source="request_logging",hostname="$BIGIP_HOSTNAME",client_ip="$CLIENT_IP",server_ip="$SERVER_IP",http_method="$HTTP_METHOD",http_uri="$HTTP_URI",virtual_name="$VIRTUAL_NAME",event_timestamp="$DATE_HTTP"
    Note: For more request logging parameters, refer to the Configuring Request Logging chapter of the External Monitoring of BIG-IP Systems: Implementations manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.
Options for the request-logging profile:
  1. Go to Local Traffic > Profiles > Other > Request Logging > telemetry_traffic_log_profile > edit
  2. In Response Settings, enable Response Logging and set HSL Protocol to TCP, and the Pool Name to telemetry.
  3. In the Template section enter a response log template. You can use the following example:
    event_source="response_logging",hostname="$BIGIP_HOSTNAME",client_ip="$CLIENT_IP",server_ip="$SERVER_IP",http_method="$HTTP_METHOD",http_uri="$HTTP_URI",virtual_name="$VIRTUAL_NAME",event_timestamp="$DATE_HTTP",http_statcode="$HTTP_STATCODE",http_status="$HTTP_STATUS",response_ms="$RESPONSE_MSECS"

Attach the request logging profile to the virtual server
Note: For devices in a HA cluster, this step will be done by Config Sync.
This allows the virtual server to send statistics to the Telemetry Streaming consumer:

tmsh modify ltm virtual telemetry_local profiles add { telemetry_traffic_log_profile { context all } }
tmsh save sys config

Or from the Configuration Utility:

  1. Go to Local Traffic > Virtual Servers and select the virtual server you want to update.
  2. Change the configuration view from Basic to Advanced if necessary.
  3. For Request Logging Profile select telemetry_traffic_log_profile.
  4. Select Update.

Check for previous telemetry declarations
This can only be performed from a qkview using the following command.
Note: Copy and paste doesn't work. Manually type the command.

grep telemetry var/tmp/storage_text_dump.txt | grep _data_ | jq '.|{last:.lastUpdateMicros,data:._data_}' -c | sort | tail -n1| jq .data -r | jq .

Check for current Telemetry declarations
From Postman

GET https://<BigIP-mgmt-IP>/mgmt/shared/telemetry/declare

Create the Telemetry Streaming declaration
Note: For devices in a HA cluster, this step needs to be done manually on each device.
The declaration example and steps below are specific to Azure Sentinel; however, you can create a declaration and tailor it for any of the supported telemetry consumers. For more information refer to Using Telemetry Streaming. This procedure creates the Telemetry Listener that the telemetry_local_rule points.

  1. Use a text editor to create a declaration on your workstation.
  2. With the Azure_Log_Analytics consumer, use your workspace ID for the workspaceId property and refer to Workspace ID and key in Microsoft Docs if needed.
  3. For cipherText, use your primary key. Refer to the aforementioned Microsoft guide if needed.
  4. For region ensure you enter your region where LogAnalytics workspace resides.
  5. Configure other properties as needed. Note: Only use "debug" for troubleshooting purpose; default value "info".
    The declaration should appear similar to the following example:

{
  "class": "Telemetry",
  "controls": {
    "class": "Controls",
    "logLevel": "info",   
    "debug": true
  },
  "My_System": {
    "class": "Telemetry_System",
    "trace": "/var/tmp/telemetry_trace.log",
    "systemPoller": {
      "interval": 60
    }
  },
  "My_Listener": {
    "class": "Telemetry_Listener",
    "port": 6514
  },
  "My_Consumer": {
    "class": "Telemetry_Consumer",
    "type": "Azure_Log_Analytics",
    "workspaceId": "<custom workspaceID here>",   
    "passphrase": {
      "cipherText": "<custom Primary Key here>"  
    },
    "useManagedIdentity": false,
    "region": "<Region where LogAnalytics workspace resides>"  
  }
}

Deploy the declaration

  1. Log in to the command line of your workstation or Postman and send a POST request with the declaration. If deploying with curl, use the following syntax: 
    curl -ku <username>:<password> -H 'Content-Type: application/json' https://<BIG-IP mgmt address>/mgmt/shared/telemetry/declare --data-raw \
<declaration in JSON>

    For example:
    curl -ku admin:admin -H 'Content-Type: application/json' https://1.1.1.1/mgmt/shared/telemetry/declare --data-raw \
            '{

  "class": "Telemetry",
  "controls": {
    "class": "Controls",
    "logLevel": "debug",
    "debug": true
  },
  "My_System": {
    "class": "Telemetry_System",
    "trace": "/var/tmp/telemetry_trace.log",
    "systemPoller": {
      "interval": 60
    }
  },
  "My_Listener": {
    "class": "Telemetry_Listener",
    "port": 6514
  },
  "My_Consumer": {
    "class": "Telemetry_Consumer",
    "type": "Azure_Log_Analytics",
    "workspaceId": "<custom workspaceID here>",
    "passphrase": {
      "cipherText": "<custom Primary Key here>"
    },
    "useManagedIdentity": false,
    "region": "<Region where LogAnalytics workspace resides>"
  }
}'

Check the logs to confirm results

  1. Log in to the command line of the BIG-IP and enter the following command: 
    grep -i success /var/log/restnoded/restnoded.log
    A successful restnoded.log example: 
    Fri, 07 Aug 2022 14:07:20 GMT - finest: [telemetry.Azure_Log_Analytics.My_Consumer] success

Additional Information

DevCentral: Integrating the F5 BIGIP with Azure Sentinel

For more information about setting up additional BIG-IP logging components refer to: Configuring the rest of the logging components

The Microsoft Sentinel logging destination (workspaceId.ods.opinsights.azure.com) is not currently configurable in Telemetry Streaming.  To manually send telemetry to a specific destination, consider using OpenTelemetry or Syslog telemetry consumers.
