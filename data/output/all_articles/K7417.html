Topic

In cases where the BIG-IP system is load balancing traffic over a WAN link, you may want to enhance the performance of data compression by configuring a WAN-optimized HTTP compression profile and associating it with your virtual server.

Note: Configuring a WAN-optimized HTTP compression profile is only an option when the system is licensed for HTTP compression.

To create a custom HTTP compression profile, with settings optimized for WAN-based traffic, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Services menu, select HTTP.
  4. Click Create.
  5. Type a name for the profile.
  6. From the Parent Profile menu, select http.
  7. Edit the profile as shown in the following table:

    SettingValueDescription
    CompressionEnabledThis setting enables the HTTP compression feature.
    Compression Buffer Size131072This setting is the maximum number of compressed bytes that the BIG-IP system buffers before deciding whether or not to preserve a Content-Length header for the response to the client. The Content-Length header indicates the size of the compressed content. Therefore, when the BIG-IP system is compressing content, it must retain the HTTP headers and wait until the entire response is compressed before rewriting the headers and sending the content to the client. If the compression buffer size is exceeded, the Content-Length header is deleted and the BIG-IP system inserts a Connection: Close header into the stream.
    HTTP/1.0 RequestsEnabledThis setting enables the compression of responses to HTTP/1.0 client requests.
    gzip Compression Level1-Least Compression (Fastest)This setting indicates the amount and rate of compression that is applied to the connection. The lowest value is one and the highest value is nine. A lower number provides a lower, but faster, compression ratio.
    gzip Memory Level16This setting specifies the amount of memory that the BIG-IP system uses for internal compression buffers when compressing a server response. Increasing the gzip Memory Level can increase the speed of the compression process over a WAN link.
    gzip Window Size64This setting indicates the amount of memory in the window size that the BIG-IP system uses when compressing a server response. Like the gzip Memory Level setting, sites that serve larger files over a WAN link may benefit from increasing this value.
    Vary HeaderEnabledThis setting enables the insertion of a Vary header into cacheable server responses.
    Response ChunkingSelectiveThis setting specifies how to handle chunking for HTTP responses. The possible values are Unchunk, Rechunk, Selective, and Preserve.
  8. Click Finished.

You must now associate the HTTP profile with the virtual server.

Note: Increasing the HTTP profile compression values can cause the BIG-IP system to use more memory per HTTP connection.
