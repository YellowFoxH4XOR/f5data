Issue

Error Message

err statsd[<PID>]: 011b0826:3: Cluster collection start error.Exitting.

In this error message, note the following:

  • <PID> is the process ID.

For example:

err statsd[6523]: 011b0826:3: Cluster collection start error.Exitting.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file
Description

This message occurs when one of the following conditions is met:

  • The /config/statsd.conf file is invalid or is unreadable.
  • Resource exhaustion on the BIG-IP system depletes all available file descriptors or system memory.

Impact

The statsd process is unable to read the /config/statsd.conf file and configure itself for statistics collection. No historical information is collected for reporting by the Configuration utility and various Traffic Management Shell (tmsh) commands.

Recommended Actions

To work around this issue, you can verify the permissions for the /config/statsd.conf file, verify the file contents, and verify adequate system resources are available. To do so, perform the following procedure:

Impact of workaround: Statistical data collection is not available while the statsd process restarts.

  1. Log in to the BIG-IP system command line as root.
  2. Check the file permissions by typing the following command:

    ls -al /config/statsd.conf

    Command output for a file with default permissions appears similar to the following example:

    -rw-r--r--. 1 root root 217439 2016-03-26 09:59 /config/statsd.conf
     
  3. If file permissions are incorrect, restore them to the default settings by typing the following command:

    chmod 644 /config/statsd.conf
     
  4. Verify the /config/statsd.conf file by parsing the contents using the following command:

    /usr/bin/statsd -p

    The contents of the file should be listed in the command output. If there is no output, the command could not parse the file. Correct any problems with the file content and run the command again to ensure the file can be parsed. 
  5. Verify the number of open file descriptors by typing the following command:

    sysctl fs.file-nr

    Output appears similar to the following example, with numbers varying by platform and usage:

    fs.file-nr = 3840       0       3297048

    In the example output, note the following:

    • 3840 is the number of allocated file handles.
    • 0 is the number of unused allocated handles.
    • 3297048 is the total number of file handles that can be allocated system-wide.
  6. Verify available system memory by using the top command. For more information about using the top command, refer to K16739: Understanding 'top' output on the BIG-IP system.
  7. Restart the statsd process by typing the following command:

    bigstart restart statsd
