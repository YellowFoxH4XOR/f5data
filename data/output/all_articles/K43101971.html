Description

When deploying a BIG-IP in VMware there are some settings when allocating the CPU resources that cause confusion and if wrongly set can cause undesired behaviors

  • Failover
  • Reboot
  • VM completely hang until turned off/on from the hypervisor
  • Multiple and frequent errors like
ltm 2021-12-22 15:30:17.000 -08:00 Warn 01010040: [device] tmm[pid] Clock has unexpectedly adjusted by 226 ms
ltm 2021-12-22 15:30:15.000 -08:00 Warn 01010040: [device] tmm6[pid] Clock has unexpectedly adjusted by 951 ms
ltm 2021-12-27 06:25:55.000 -08:00 Notice 01010029: [device] tmm1[pid] Clock advanced by 399 ticks
ltm 2021-12-27 06:25:55.000 -08:00 Notice 01010029: [device] tmm[pid] Clock advanced by 358 ticks

Environment

  • BIG-IP VE in VMware

Cause

Confusion regarding the settings when allocating CPU resources to a BIG-IP Virtual Machine 

In VMware there are at least 3 parameters that can be configure when allocating CPU resources to a VM

Reservation: Guaranteed CPU allocation for this virtual machine. Reservation is a guarantee for clock cycles. You define the reservation in MHZ. If you give a virtual machine a reservation it means the vmkernel CPU scheduler will give it at least that amount of resources. If a virtual machine is not using its resources the CPU cycles are not wasted on the physical host. Other machines can use it. What you do with CPU reservations is making sure that a VM will always get access to physical CPU in a committed environment. 

Limit: Upper limit for this virtual machine’s CPU allocation. Select Unlimited to specify no upper limit. The limit defines how much access a virtual CPU can get on a physical CPU (core). This is used to make sure a virtual machine is not using too much resources on a host. By limiting the vCPU you essentially also limits the performance of the virtual machine. Even though capacity is available on the ESXi host the limit will still be enforced.

Shares: CPU shares for this virtual machine in relation to the parent’s total. Sibling virtual machines share resources according to their relative share values bounded by the reservation and limit. Select Low, Normal, or High, which specify share values respectively in a 1:2:4 ratio. Select Custom to give each virtual machine a specific number of shares, which express a proportional weight. Shares is a different approach to performance tuning in a virtual environment. Shares define how much access you get to a resource compared to something else. Every virtual machine has 1000 shares configured pr. vCPU as a default. So you are already using them! All virtual machine are equal from a hypervisor perspective unless you change the shares and tell it which machines are really more important.

Even though the VMware documentation indicates those settings apply only in contention situations (meaning when you have high utilization), BIG-IP VM requires real time access to the CPU even when the CPU utilization is really low, so the settings should be as if BIG-IP VM is using 100% of the configured vCPU. 

Recommended Actions

Use the following settings:

  1. Reservation - [<NumberOfCores> * <Max_Ghz>]
    1. i.e:  4 (cores) * 2.1Ghz = 8.4Ghz
  2. Limit - Unlimited
  3. Shares - High
