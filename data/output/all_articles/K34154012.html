You should consider using this procedure under the following condition:

  • You want to use the Data Guard feature to configure:
    • Custom patterns that protect sensitive information.
    • Exception patterns that recognize information that is not sensitive.

Description

The Data Guard feature can prevent responses from exposing sensitive information by scrubbing them and masking the data. Data Guard scans text in responses, looking for the types of sensitive information that you specify.

With Data Guard, you can configure custom patterns using Perl-Compatible Regular Expressions (PCREs) to protect sensitive information and indicate exception patterns to consider as not sensitive.

For example, you can design a custom pattern to match a string of sensitive data sent by the web server and mask the data before returning it to the client.

You can also design an exception pattern to match a sub-string of the data string to be masked. When the system finds the sub-string, it marks the entire data string as not sensitive, and then returns the unmasked data to the client.

Note: You can validate PCREs with the RegExp Validator. Go to Security > Options > Application Security > RegExp Validator.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.

Procedures

Configure Data Guard detection patterns (16.1.0 - 17.x)

To configure a custom pattern to protect sensitive information and indicate an exception pattern to treat as not sensitive, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies list.
  3. Select the policy you want to update.
  4. Expand the Advanced Protection menu.
  5. Select Data Guard.
  6. In the upper right, select the toggle switch to turn on the feature.
  7. To mask data in a response, in Mask Sensitive Data, ensure Enabled is selected.

    This selection tells Data Guard to replace sensitive data with asterisk characters, such as replacing 123456789 with *********.

  8. To allow responses with masked data, instead of blocking responses with sensitive data as Data Guard does in Blocking mode, do the following:
    • Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
    • For Data Guard: Information leakage detected violation, clear the Block check box.
  9. To configure a custom detection pattern that masks or blocks sensitive data do the following:
    • In the Custom Patterns section, select Detect.
    • Enter a PCRE pattern in the field.

      For example, to create a custom pattern in a response that matches an account number with four letters, a dash, four numbers, a dash, and then four numbers, you add the following expression:

      [A-Z]{4}-\d{4}-\d{4}

    • Select Add.
  10. To configure an exception detection pattern that prevents masking or blocking of data that would otherwise be masked or blocked by a built-in pattern or a custom pattern:
    • In the Exception Patterns section, select Detect.
    • Enter a PCRE pattern in the field.

      For example, to create an exception pattern that allows Data Guard to return to the client account numbers beginning with a Z in their entirety, add the following expression:

      Z[A-Z]{3}-\d{4}-\d{4}

    • Select Add.
  11. Select Save.
  12. Select Apply Policy.
  13. If prompted, select OK.

Configure Data Guard detection patterns (12.x - 16.0.0)

To configure a custom pattern to protect sensitive information and indicate an exception pattern to treat as not sensitive, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Data Guard.
  3. In Data Guard, select Enabled.
  4. To mask data in a response, in Mask Data, ensure Enabled is selected.

    This selection replaces sensitive data with asterisk characters, such as replacing 123456789 with *********.

  5. To allow responses with masked data, instead of blocking responses with sensitive data as Data Guard does in Blocking mode, do the following:
    • Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
    • For Data Guard: Information leakage detected violation, clear the Block check box.
  6. To configure a custom detection pattern that masks or blocks sensitive data:
    • In the Custom Patterns section, select Enabled.
    • Enter a PCRE pattern in the New Pattern field.

      For example, to create a custom pattern in a response that matches an account number with four letters, a dash, four numbers, a dash, and then four numbers, you add the following expression:

      [A-Z]{4}-\d{4}-\d{4}

    • Select Add.
  7. To configure an exception detection pattern that prevents masking or blocking of data that would otherwise be masked or blocked by a built-in pattern or a custom pattern:
    • In the Exception Patterns section, select Enabled.
    • Enter a PCRE pattern in the New Pattern field.

      For example, to create an exception pattern that allows Data Guard to return to the client account numbers beginning with a Z in their entirety, add the following expression:

      Z[A-Z]{3}-\d{4}-\d{4}

    • Select Add..
  8. Select Save.
  9. Select Apply Policy.
  10. If prompted, select OK.
