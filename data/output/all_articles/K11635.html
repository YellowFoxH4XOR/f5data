Known Issue

This is the result of a known issue. Traffic Management Shell (tmsh) commands defined in a crontab file will fail to execute if the REMOTEUSER session variable is not set in the crontab file. When this issue occurs, an error message that appears similar to the following example is logged to the /var/log/ltm file:

tmsh[16503]: 01420001:2: the REMOTEUSER environment variable is not set : framework/UserCredentials.cpp, line 79

F5 Product Development tracked this issue as ID 224430 (formerly CR136167) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, APM, ASM, Edge Gateway, GTM, Link Controller, PSM, WebAccelerator, or WOM release notes.

Workaround

You can work around this issue by setting the REMOTEUSER environment variable in the crontab file. To do so, enter the following syntax before the first tmsh command, where <user name> is the user executing the script:

REMOTEUSER = <user name>

For example, if you are editing root's crontab file or the system /etc/crontab file, you would add the following command:

REMOTEUSER = root

If the REMOTEUSER command appears after one or more tmsh commands, those commands will not execute. In the following example, only the third tmsh command will execute:

45 3 * * * /usr/bin/tmsh modify /gtm pool pool1 disabled
45 3 * * * /usr/bin/tmsh modify /gtm pool pool2 disabled
REMOTEUSER = root
45 3 * * * /usr/bin/tmsh modify /gtm pool pool3 disabled

Note: For more information about the crontab program and file, type man crontab at the command line.
