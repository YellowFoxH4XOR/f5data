K12322: Provisioning requirements for BIG-IP redundant pairs in which the BIG-IP GTM module is licensed on only one of the units

Topic

Note: The information in this article replaces the information that was previously found in SOL10156.

Note: In BIG-IP 11.x, resource provisioning is no longer synchronized between redundant pair members during ConfigSync operations. For more information, refer to K13533: The BIG-IP GTM module can be licensed and provisioned on one of the devices in a redundant pair.

If you have a BIG-IP redundant pair configuration in which both units are licensed and provisioned for BIG-IP LTM and only one of the units is licensed and provisioned for BIG-IP GTM, you must make sure to provision the BIG-IP GTM module on both units. If you do not provision BIG-IP GTM on both units, you may experience issues in which the resource provisioning configuration for one unit is synchronized to the other unit.

For example, if you have a BIG-IP redundant pair in which BIGIP-1 (the active unit) is licensed and provisioned for BIG-IP LTM and BIG-IP GTM, and BIGIP-2 (the standby unit) is licensed and provisioned for BIG-IP LTM only, and you run ConfigSync from BIGIP-2 to BIGIP-1, BIGIP-1 will inherit BIGIP-2's BIG-IP GTM provisioning level of None (Disabled). When the BIGIP-1 unit loses its BIG-IP GTM provisioning configuration, the module is non-functional on the unit.

Important: Licensing the GTM module on only one unit of a BIG-IP redundant pair is not a recommended configuration. On asymmetrically licensed systems, the non-floating self-IP of the unit on which GTM is licensed is defined as the listener, and will accept queries regardless of the host unit’s failover state. However, if the unit on which GTM is licensed becomes unavailable or the listener address becomes unreachable, the GTM module will be unable to answer queries for WideIPs or DNS names. To avoid a name resolution outage when this occurs, F5 recommends configuring a GTM sync group which includes at least two BIG-IP systems licensed for the GTM module.

This can be further explained in the following scenarios:

Results of synchronizing non-identically provisioned units

A BIG-IP system running both BIG-IP LTM and GTM would typically be configured with module resource provisioning for both BIG-IP LTM and GTM set to either Minimum or Nominal, which allows the modules to share the available system resources. A BIG-IP system running only one module, such as BIG-IP LTM, would be configured with module resource provisioning for BIG-IP LTM set to Dedicated. It is possible to license and run a module on only one unit of a redundant pair. However, if both BIG-IP LTM and GTM are licensed and provisioned on one unit, but only BIG-IP LTM is licensed and provisioned on the other unit, synchronizing the configuration may produce unexpected results.

Synchronizing from a BIG-IP LTM-only unit to a BIG-IP LTM/GTM combination unit

If the configuration is initially synchronized from a BIG-IP LTM-only unit to a BIG-IP LTM/GTM combination unit, the provisioning configuration is synchronized and module resource provisioning for BIG-IP GTM is now configured as None on both systems. When the synchronized configuration is loaded on the BIG-IP LTM/GTM combination unit, the gtmd process is not initialized, and the bigstart status gtmd command displays the following output:

gtmd down, Not provisioned

As a result, the BIG-IP GTM unit is effectively disabled on the redundant system.

Note: Synchronizing the configuration back does not clear the condition. The initial synchronization overwrote the original provisioning configuration.

Synchronizing from a BIG-IP LTM/GTM combination unit to a BIG-IP LTM-only unit

If the configuration is initially synchronized from a BIG-IP LTM/GTM combination unit to a BIG-IP LTM-only unit, the provisioning configuration is synchronized and module resource provisioning for BIG-IP GTM is now configured as Nominal or Minimum on both systems. As a result, system resources previously available to the BIG-IP LTM module on the BIG-IP LTM-only unit are no longer available, and BIG-IP LTM performance on the BIG-IP LTM-only unit may be degraded.

Recommendations

If you have a BIG-IP redundant pair configuration in which both units are licensed and provisioned for BIG-IP LTM and only one of the units is licensed and provisioned for BIG-IP GTM, you must complete the following steps to provision the BIG-IP GTM module on the BIG-IP LTM-only system:

  1. Log in to the Configuration utility on the system that is licensed and provisioned for BIG-IP LTM only.
  2. Click System.
  3. Click Resource Provisioning.
  4. In the Resource Provisioning (Unlicensed Modules) section, select the same provisioning level that is set for the BIG-IP LTM/BIG-IP GTM system from the Global Traffic (BIG-IP GTM) drop-down menu (for example, Nominal).
  5. Click Update.

Note: After you provision the BIG-IP GTM module on the BIG-IP LTM-only system, the Global Traffic screens appear in the Configuration utility. However, since the system does not have an active BIG-IP GTM license you will be unable to configure and save BIG-IP GTM configuration. Additionally, the system will display the status of ModuleNotLicensed in its command line prompt when it receives the provisioning configuration from the combo box during a ConfigSync operation.
