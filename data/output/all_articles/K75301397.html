Description

After upgrading the BIG-IP VE to v15.x, or higher, GUI access may become slow/sluggish when more than one (1) user is accessing the GUI/SSH at the same time.

Access may improve when all users exit GUI/SSH leaving only a single user accessing the GUI, the performance may be significantly faster.

However, the Network Map can still show No objects in this partition even with only one (1) user accessing the GUI.

This BIG-IP VE will have more than one (1) module provisioned and will have 16 GB or less memory allocated to it.

Further check will generally show that SWAP memory is significantly higher than it was when running the older software version.

Environment

  • BIG-IP Virtual Edition
  • BIG-IP upgraded to v15.x or higher
  • BIG-IP provisioned with more than one (1) module
  • BIG-IP have 16GB RAM or less RAM allocated
  • GUI slow/sluggish when more than one (1) user accessing the GUI
  • Error No objects in this partition when accessing the Network Map
  • SWAP memory is high immediately after booting up new software.

Cause

High constant SWAP memory is an indication that the BIG-IP is in resource starvation. This is because the higher software version requires more resources (memory) as it has more features.

Recommended Actions

You will need to allocate more memory to the BIG-IP VE. Add an additional 2 GB to the BIG-IP and check if the issue is resolved. Increment an additional 2 GB if needed.

Note: You will need to have administrative access to the hypervisor to add the additional memory

Once you have resolved the slow/sluggish issue but still seeing No objects in this partition when in the network map, refer to K95023305. (This article points to Bug ID 717174 which involves an issue with Auth-token. Which you may or may not be experiencing. It also contains the steps to restart a list of processes that may help if they are applied even if there is no Auth-Token issue detected.) 

After allocating more memory to the BIG-IP VE, you might want to consider applying some of that directly to the Management using K26427018.
