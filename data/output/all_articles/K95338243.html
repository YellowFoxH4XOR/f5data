Description

You want to forward the Client Certificate to the backend server, by inserting it into a HTTP header using an iRule.

Environment

  • Client Certificate Authentication enabled on Client SSL profile
  • Virtual Server with SSL re-encryption
  • iRules

Cause

None

Recommended Actions

Follow these steps to configure the Virtual Server to forward the Client Certificate to the backend server:

  1. Make sure the Client SSL profile has Client Authentication enabled.
    Important: The Client Authentication setting for Client Certificate must be configured with request or require in order to obtain the client certificate for the request.
    For more details of this configuration refer to:
    K12140946: Configuring the BIG-IP system to perform two-way SSL authentication
    K14499: Using OpenSSL to create CA and client certificates (11.x - 14.x)
     
  2. Create an iRule similar to the following example and attach it to the Virtual Server:
    when HTTP_REQUEST {
       HTTP::header insert X-Client-Cert [b64encode [SSL::cert 0]]
    }
    Note: The SSL::cert command can be used directly within the HTTP_REQUEST event on an iRule. In this example, X-Client-Cert is the name of the header to be inserted.

Additional Information

To check if the client certificate is being inserted correctly, you can take a decryped capture and view the HTTP headers on server side connection. You can compare the certificate inserted on the header X-Client-Cert with the original client certificate on client side and it should be the same, as shown on example below:
