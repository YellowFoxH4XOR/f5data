Description
The BIG-IP REST API interface may suddenly start responding to client requests with 400 Bad Request or 401 Unauthorized HTTP status codes instead of expected response and 200 OK code.

Environment

  • BIG-IP
  • REST API interface utilized

Cause
Sometimes a synchronous REST API call will time out, commonly due to requesting a very large amount of data or many concurrent REST API requests. This is most likely to occur in environments with a very large BIG-IP configuration and lots of REST activity. Due to ID769169 it is possible that iControl will not gracefully handle the API call timeout and instead it's icrd_child processes will enter a restart loop, resulting in an inability to perform REST API calls.

Recommended Actions

The following steps identify if icrd_child processes are in a restart loop and restart restjavad which then allows icrd_child processes to be created normally and functionality to be restored.
  1. Review the /var/log/restjavad.0.log file for frequent occurrences of icrd_child processes being killed like "[I][254][10 Aug 2020 19:48:58 UTC][ChildWrapper] Killing IcrdChild process 18941"
  2. Restart restjavad process
    This will cause Java to restart on the BIG-IP, impacting all Java communication however that communication is currently impacted due to ID769169.
    bigstart restart restjavad
  3. Wait for restjavad to complete start up
  4. Confirm REST API calls are once again successful and /var/log/restjavad.0.log shows expected log messages

Additional Information

  • ID769169: BIG-IP system with large configuration becomes unresponsive with BIG-IQ monitoring
