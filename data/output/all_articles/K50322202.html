Description
A message appears in the Device Management section of the GUI stating  "System Times of Device Do Not Match".

  •     You may be experiencing an issue with ConfigSync or you may simply be getting a Proactive message.
  •     A message may appear in the GUI...
System Times of Devices Do Not Match

One or more system times of the devices in the device trust do not match the system time of the local device. Auto or manual device group sync operations may fail.

Verify that the NTP Settings on all devices are properly configured and that the system times are equal.

/<partition>/<hostname of peer> is <number of> seconds ahead

 

Error messages will be written to /var/log/ltm log file on both HA devices when system time got out of sync between HA devices. 

Jul 11 06:27:51 [hostname-of-HA-unit2] err mcpd[8437]: 01071aed:3: Peer [ip-addr-of-HA-unit1] time exceeds threshold 3 sec - difference -41 sec

Jul 11 06:27:10 [hostname-of-HA-unit1] err mcpd[8446]: 01071aed:3: Peer [ip-addr-of-HA-unit2] time exceeds threshold 3 sec - difference 41 sec


Environment

  • BIG-IP / BIG-IQ
  • Device Trust
  • System time
  • Sync
  • NTP
     

Cause

One or more of the devices has time discrepancy
Those devices in the device trust may not synced with the NTP time source.


Recommended Action

Perform the following procedures to troubleshoot NTP peering issues:
IMPORTANT: NTP configuration change is recommended to do in the maintenance window.

  • Configure additional NTP servers
  • Verify NTP peer server communications using ntpq
  • Restart the ntpd daemon

Configure additional NTP servers
If the device is configured with a single NTP server, configure additional NTP servers. It is recommended to use at least three NTP servers.
Refer to the following articles to configure additional NTP servers:

  • K3122: Using the BIG-IP Configuration utility to add an NTP server
  • K13380: Configuring the BIG-IP system to use an NTP server from the command line
  • K16309: Using the BIG-IQ user interface to add an NTP server

Configuring additional NTP servers reduces the likelihood of an issue occurring if one NTP peer is not trusted or unreachable.

Verify NTP peer server communications using ntpq
The NTP Query (ntpq) program may be used to verify communications to the NTP peers
Refer to the following article for information about using the ntpq program:

  • K10240: Verifying NTP peer server communications

Restart the NTP daemon on the affected systems
Restarting ntpd forces the NTP process to attempt resynchronization with the configured NTP servers.
Use the following command to restart ntpd:

tmsh restart /sys service ntpd

You may also follow:
  • K78084428: How to force ntp sync to a specific NTP server
  • K10240: Verifying NTP peer server communications



Additional Information
 

The ntpd daemon and NTP protocol are particular about which servers they peer with by design.

Debug output from ntpq indicates whether an NTP server is peered with the system.

  • K16735023: Enable NTP debugging
