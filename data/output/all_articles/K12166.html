Known Issue

This is the result of a known issue. When mapping a resource group using dynamic mapping with an Advanced Session Variable and the Map verbatim option enabled, the mapping will fail.

F5 Product Development is tracking this issue as ID 327658. 

This issue has been fixed in cumulative HF-70-1 issued for FirePass version 7.0.0 and in HF-610-4 for FirePass version 6.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K10322: FirePass hotfix matrix.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Note: For more information about Advanced Session Variables and the Map verbatim option, refer to K10108: Overview of Advanced Session Variables and K12165: Overview of the dynamic group mapping Map verbatim option.

Troubleshooting the Map verbatim option

  1. Log on to the FirePass Administrative Console.
  2. Navigate to Device Management : Maintenance : Troubleshooting Tools.
  3. Under the Session Variable Dump section, select the Save user's session variables to Logon Reports check box.
  4. Log on using a user account configured to use map verbatim mapping.
  5. Log the user off.
  6. Return to the Administrative Console.
  7. Navigate to Reports : Logons.
  8. Click the user name you used in Step 4 from the Logon column.
  9. Scroll down the report until you find the following content:

    Resource group mapping in the master group  On
    Checking session variables...
    Looking for matches in mapping table...
     

    Priority Source External group FirePass group Result
    1 (%session.asv.yourASV%)MAP VERBATIM No

    Resource groups available for user     
     

    The Result column in this example displays No, and the resource groups available for user entry do not display the group. This example indicates the report did not match the group and assign it to the user.

    When the mapping is working properly, you will receive a result of Found, and the resource groups available for the user will display the name of the assigned resource group.

    For example:

    Resource group mapping in the master group  On
    Checking session variables...
    Looking for matches in mapping table...

    Priority Source External group FirePass group Result
    1 (%session.asv.yourASV%)MAP VERBATIM Found

    Dynamically mapped in the master group to resource group(s)     session_resource (asv value)
    Resource groups available for user      session_resource
