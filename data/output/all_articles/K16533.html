Known Issue

If iRule commands that need to suspend processing are evaluated within the content of an expr block, the Traffic Management Microkernel (TMM) may produce a core file.

This issue occurs when the following condition is met:

  • You are using the table, session, after, sideband, or persist command inside an expr block within an iRule.

    For example:

    set time [expr 10 - {[table lookup http1]}]

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • The BIG-IP system generates TMM core files to the /shared/core directory, with a time stamp that correlates to the traffic interruption.

Workaround

To work around this issue, you can separate the expr from the context of the suspending command by wrapping braces around the command that is suspending processing.

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

For example:

when HTTP_REQUEST {
table set "http1" 180
}

when CLIENT_CLOSED {
set t { [table lookup http1] }
set time [expr 10 - $t]
}
