Known Issue

An iRule may process a CLIENT_ACCEPTED event twice.

This issue occurs when all of the following conditions are met:

  • A Standard virtual server is associated with a TCP profile that has the Verified Accept option enabled.
  • The virtual server is configured with an iRule that uses the CLIENT_ACCEPTED iRules event.
  • The client sends the initial data within the ACK packet of the three-way TCP handshake.

Impact

The CLIENT_ACCEPTED iRules event is triggered twice. In some scenarios, a connection may reset.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system triggers the CLIENT_ACCEPTED iRules event twice.
  • If the iRule uses commands that suspend processing, your BIG-IP system stops accepting connections to virtual servers that have Verified Accept enabled.
  • The affected connection unexpectedly resets.

Workaround

To work around this issue, you can disable Verified Accept in the TCP profile. Alternatively, you can modify the iRule to run the commands in the CLIENT_ACCEPTED event once by setting a variable and checking to see whether the variable has been set on subsequent runs.

Impact of workaround: The impact of the suggested workarounds depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
