Known Issue

The Traffic Management Microkernel (TMM) may restart and produce a core file when you use an iRule virtual command.

This issue occurs when the following condition is met:

  • The iRule uses the virtual command within an ACCESS_SESSION_CLOSED event.

    For example:

    when ACCESS_SESSION_CLOSED {
        puts "virtual = [virtual name]"
    }

Note: This event is triggered outside of flow context (similar to RULE_INIT) when a session goes away. The iRule commands that require a flow context (for example, TCP, HTTP, and SSL commands) cannot be used in this event.

Impact

The BIG-IP system may temporarily fail to process traffic, as it recovers from the TMM restarting. If configured as a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to another system in the device group.
  •  In the /var/log/ltm file, you may see error messages that appear similar to the following example:

    err tmm5[12345]: 01220001:3: TCL error: /Common/access_session_virtual <ACCESS_SESSION_CLOSED> - current context is not ready to run virtual command (line 1)     invoked from within "virtual name

  • The BIG-IP system generates TMM core files in the /shared/core directory, and the time stamp of the files correlates to the time of the traffic interruption.
