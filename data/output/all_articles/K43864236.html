Description

While uploading a qkview to iHealth, sometimes iHealth will give "the qkview file is corrupted".

Environment

  • Uploading Qkview
  • iHealth Diagnostic

Cause

Unknown at the time of publication. 

Recommended Actions
Please follow the steps below to gather more data for troubleshooting with F5 Support.

  1. Use -v modifier with the following command via SSH to provide verbose output of the qkview.
    # qkview -v

    Once this has file has been generated you should expect to see the following in your SSH session:

    Diagnostic information has been saved in:
    /var/tmp/<name of qkview file>.qkview
    Please send this file to F5 support.
     
  2. Verify the generated qkview file on BIG-IP.
    # tar -ztvf BIG-IP-A.f5.com.qkview

    Then check the output.
    # tar -ztvf SGB-INT-G08-LB01.dox.isddc.men.maxis.com.my.qkview | more
    -rw-r--r-- root/root  31023132 2018-12-26 21:34 proc_module.xml

    gzip: stdin: invalid compressed data--format violated
    tar: Unexpected EOF in archive
    tar: Error is not recoverable: exiting now

    If the tar command returns Unexpected EOF in archive or Error is not recoverable: exiting now.  The qkview is likely corrupted.
     
  3. If the verbose output is showing some module taking longer than 360 seconds, and the tar command verify the qkview is corrupted, try to extend the module timeout and see if the issue persist.
    # qkview -v -t 3600
     
  4. If the issue persist, collect the verbose output, and the tar command output and provide these files to F5 support online or via phone.


Additional Information

None at the time of publication.
