K31005704: Upgrade SSL Orchestrator from 9.1.70 to 9.2.47 is creating duplicate SSL settings

Type
Support Solution
Published
2022-02-18
Updated
2026-07-17
Status
Legacy Content
Applies to

Source
https://my.f5.com/manage/s/article/K31005704

Description

After upgrading SSL Orchestrator from 9.1.70 to 9.2.47 you notice within one of the topologies that is showing a little "i" icon next to topology name and in the SSLO Configuration of the topology's Interception Rule you see the warning as below:

 "Redeploying topology sslo_example_tcp will overwrite changes made in Interception Rule sslo_example_tcp-in-t-4 (property: SSL Configuration)."


The deploy button is greyed out and it doesn't allow to do re-deploy even simply make some changes on the Interception Rule page, changing Label, Description, Source/Destination Address, VLANs, etc. The "Save & Next" button always greyed out.

On the SSL Configurations two "ssloT..." SSL profiles were created in the same name.

Environment

  • Upgrade SSL Orchestrator 9.1.70 to 9.2.47
  • SSL settings

Cause

Bug ID 1073833 SSL Orchestrator upgrade from 9.1 to 9.2 is creating duplicate SSL Settings. 

Recommended Actions

We can workaround it to clear the warning message and the "i" icon next to topology name.
  1. Fetch the dependency graph. Save this in text file or keep open in browser because we need this to figure out the incorrect block.
https://<MGMT-IP>/mgmt/shared/iapp/blocks/?$filter=name%20eq%20%27f5-ssl-orchestrator-dg-data%27
  1. To get the duplicate block ID use below url. and note down the ID of both the block
https://<MGMT-IP>/mgmt/shared/iapp/blocks/?$filter=name%20eq%20%27<SSL configuration>%27

   **Note: Replacing <MGMT-IP> with the management IP of the SSL Orchestrator unit and <SSL configuration> with the SSL configuration name while removing the "<>" from the command.

For example you would see these IDs and there are in the same name from the content
 
id: 2428350c-1188-4393-8817-588b9a2ca63a
name: ssloT_example_tcp

id: ecbf5b6c-b574-4f0f-92d9-e5e9e9dac5b7
name: ssloT_example_tcp
  1. Check above IDs in the dependency graph (just do the string search), one will not be there . Note down the ID which is not there in the dependency graph. Let's say it is "2428350c-1188-4393-8817-588b9a2ca63a"
  2. Delete the duplicate block.

restcurl -X DELETE /mgmt/shared/iapp/blocks/2428350c-1188-4393-8817-588b9a2ca63a -u admin:<admin password>

 **Note: Replacing <admin password> with the admin password while removing the "<>" from the command.
  1. Go back to SSLo UI, click on Topology in question(e.g: sslo_example_tcp). Simply edit and put something on the Description box or make some changes, press "Save & Next" and Deploy.
