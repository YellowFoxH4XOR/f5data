Description
  • An HA pair getting constantly disconnected
  • The system logs messages to the /var/log/ltm file similar to the following example:
    <date> <slot#>/<bigip> warning tmm[12688]: 011e0003:4: Aggressive mode sweeper: /Common/default-eviction-policy (0) (global memory) <#> Connections killed
  • The system logs messages to the /var/log/tmm file similar to the following example:
    <date> <slot#>/<bigip> notice mcp error: 0x1020004 at ../mcp/db_connection.c:693
    <date> <slot#>/<bigip> notice mcp error: 0x1020031 at ../mcp/mcp_config.c:591
Note: CMI is also referred to as device service clustering (DSC).

Environment
  • BIG-IP HA
  • No object is using the default-eviction-policy
  • The BIG-IP HA is experiencing frequent disconnections ~minute
  • TMM memory increased exponentially.
  • Example of the TMM percentage of memory (pagemem) used
name      used  avail
------- ------ ------
pagemem 652840 665600

(used / avail) * 100 = percentage used
(652840/665600) * 100 = 98.08%
 
Cause
Please refer to K15740, it states: "If the global eviction policy is triggered from memory utilization, and the connection flows selected for removal include HA and mirroring connections, the system logs messages similar to the following example:"
warning tmm[<pid>]: 011e0003:4: Aggressive mode sweeper: /Common/Custom_Water_Mark (1) (global memory) 1 Connections killed
notice mcpd[<pid>]: 0107143a:5: CMI reconnect timer: disabled, all peers are connected
notice mcpd[<pid>]: 01071451:5: Received CMI hello from /Common/v11-2.wehrman.com
notice mcpd[<pid>]: 0107143c:5: Connection to CMI peer 10.21.15.2 has been removed
notice mcpd[<pid>]: 0107143a:5: CMI reconnect timer: enabled
notice mcpd[<pid>]: 01071431:5: Attempting to connect to CMI peer 10.21.15.2 port 6699
notice mcpd[<pid>]: 01071432:5: CMI peer connection established to 10.21.15.2 port 6699

Recommended Actions
Impact of workaround: Traffic processing is temporarily interrupted during an mcpd restart and may trigger a failover if the device is the active member in the high-availability configuration. You should perform this procedure during a maintenance window.
  1. Logon to the Traffic Management Shell (tmsh)
  2. Restart the mcpd daemon by running the following command:
    restart /sys service mcpd
  3. Refer to the (pagemem) used again to validate if the percentage used decreased:

    BIG-IP 13.x and later

    tmctl -d cluster page_stats

    BIG-IP 11.6.0 - 12.x

    tmctl -d blade tmm/pagemem
