Description

  • The Standard virtual server type with non-default Protocol Profile (Client) shows that default tcp profile is being used from the Configuration Utility (GUI).
  • Similarly if you virtual server type is Performance (Layer 4) for example, if non-default profile is used for Protocol Profile (Client), GUI will show as fastl4 profile.
  • In CLI you see correct or intended TCP profile is attached to the virtual server.

    Virtual Server typeGUICLI
    Standard

    Go to Local Traffic > Virtual Servers > Virtual Servers List. Select the virtual server. On the Properties tab, for Protocol Profile (Client), tcp is selected.

    		[root@bigip:Active:Standalone] config # tmsh list ltm virtual standard_vs
    ltm virtual standard_vs {
        destination 192.0.2.10:http
        ip-protocol tcp
        mask 255.255.255.255
        profiles {
            customtcp { }
        }
        serverssl-use-sni disabled
        source 0.0.0.0/0
        translate-address enabled
        translate-port enabled
        vs-index 4
    }
    Performance (Layer 4)

    Go to Local Traffic > Virtual Servers > Virtual Servers List. Select the virtual server. On the Properties tab, for Protocol Profile (Client), fastL4 is selected.

    		[root@bigip:Active:Standalone] config # tmsh list ltm virtual vs_fastl4
    ltm virtual vs_fastl4 {
        destination 0.0.0.0:any
        ip-protocol tcp
        mask 255.255.255.255
        profiles {
            customl4 { }
        }
        serverssl-use-sni disabled
        source 0.0.0.0/0
        translate-address enabled
        translate-port disabled
        vs-index 3
    }

Table: Comparison between GUI and CLI virtual server profile settings.
Note: In addition to TCP profile, same problem can occur with UDP or fastL4 profile.

Environment

  • BIG-IP
  • Virtual servers (including iApps)
  • Protocol Profile (Client) - TCP or UDP or fastL4 Profile

Cause

This issue is caused by Bug ID 914493, which causes the GUI to display the wrong Protocol Profile (Client) profile

Recommended Actions

Request for EHF (Engineering Hotfix) from F5 Technical Support.

Additional Information

  • You can continue to make changes from GUI even though after applying the changes, the client TCP profile "visually" shows as default profile is being used.
    IMPORTANT: If you wish to update VS settings from GUI, make sure the correct TCP/UDP/fastL4 is selected before clicking "Update", otherwise the default profile gets pushed to the configuration, silently overwriting the intended setting along with any other changes being made

  • To verify GUI changes have taken place correctly you can run below command:
    tmsh list ltm virtual <virtual server name>

  • Alternatively, you can make changes through CLI by using below syntax:
    tmsh modify ltm virtual <Enter virtual server name> profiles delete { <Enter the current TCP profile attached> } profiles add { <Enter the TCP profile you want to attach> }

    For example, if you want to replace default TCP profile to custom TCP profile named custom_tcp for a virtual server named vs_http, command will be as follows:
    tmsh modify ltm virtual vs_http profiles delete { tcp } profiles add { custom_tcp }

  • You can use the iControl REST command to view the TCP profile configured for the virtual server.
    curl -sku <username>:<password> -X GET -H "Content-Type: application/json" https://<device management IP address>/mgmt/tm/ltm/virtual/<virtual server name>/profiles | jq -M .
