K000160886: Unable to re-configure BIG-IQ HA autofailover to restore HA after failover has occurred

Type
Support Solution
Published
2026-04-19
Updated
2026-04-19
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.X, 8.4.X, 8.3.0, 8.4.1, 8.4.0
Source
https://my.f5.com/manage/s/article/K000160886

Description

After running ha_reset on BIG-IQ systems, attempts to re-create the HA autofailover configuration fails when adding the quorum device. The process consistently fails with permission denied errors during the firewall rules save operation, preventing the HA cluster from being re-formed.

 

Environment

  • BIG-IQ versions 8.3, 8.4.0, and 8.4.1
  • HA autofailover configuration with quorum DCD
  • ha_reset executed on all HA devices (primary CM, secondary CM, quorum DCD)
  • SELinux enabled

 

Cause

Running ha_reset -f changes the SELinux security context of /etc/sysconfig/iptables and /etc/sysconfig/ip6tables (and their .save files) from system_u:object_r:system_conf_t:s0 to an incorrect context (such as unconfined_u:object_r:etc_t:s0). This incorrect context causes permission denied errors when saving firewall rules, preventing HA autofailover re-configuration.

 

This is due to an upstream RedHat bug https://bugzilla.redhat.com/show_bug.cgi?id=1733542 for SELinux package which we are also using in the BIG-IQ.

 

F5 is tracking this under Bug ID2284309.

 

Answer/Recommended Actions

After running ha_reset -f on the HA devices (CM1, CM2, Quorum), manually restore the SELinux context for the affected files before attempting HA reconfiguration using these Bash commands on CM1, CM2, and Quorum DCD:

 

restorecon -v /etc/sysconfig/iptables /etc/sysconfig/ip6tables

restorecon -v /etc/sysconfig/iptables.save /etc/sysconfig/ip6tables.save

 

or

 

chcon system_u:object_r:system_conf_t:s0 /etc/sysconfig/iptables{,.save}

chcon system_u:object_r:system_conf_t:s0 /etc/sysconfig/ip6tables{,.save}

 

Proceed with the HA autofailover re-configuration after restoring the SELinux context.
