Description

Trying to install a new BIGIP version in a new boot location fails.

 

Environment

BIG-IP LTM

v15.x

Create new boot location fails

Cause

/var/log/liveinstall.log:

error: tm_install::Process::Process_full_install -- predicted size for BIGIP17114 is 14875024 and vg has 14733312 remaining.

Terminal error: Disk full (volume group). See SOL#10636

Recommended Actions

Run the following command to display the volume size:

Step 1:

vgdisplay -vA:

Output:

--- Logical volume ---

LV Path /dev/vg-db-sda/dat.appdata

LV Name dat.appdata

VG Name vg-db-sda

LV UUID

LV Write Access read/write

LV Creation host, time

LV Status available

# open 1

LV Size 341.44 GiB      <---See condense step 2. Full article is K74200262 to reduce the size of appdata volume.

 

Step 2:

Reduce the appdata volume.

NOTE: It can be 40G or any other size you prefer to accommodate the new boot location. Make the size at least 20G. 

NOTE: The INOPERATIVE mode doesn't affect running lvreduce.

 

root@f5mgmt:INOPERATIVE:Standalone] core # lvreduce --resizefs --size -40G /dev/vg-db-sda/dat.appdata

Do you want to unmount "/appdata"? [Y|n] Y

umount: /appdata: target is busy.

(In some cases useful info about processes that use

the device is found by lsof(8) or fuser(1))

fsadm: Cannot proceed with mounted filesystem "/appdata"

fsadm failed: 1

Filesystem resize failed.

 

Workaround:

  1. If reducing the dat.appdata fails and/or get target is busy, try to unmount /appdata using the following command:
    umount /appdata
  2. Try again running the previous command to reduce the appdata volume:
    lvreduce --resizefs --size -40G /dev/vg-db-sda/dat.appdata

NOTE: If unmount doesn't work, reboot the BIGIP device by running:

reboot

 

After the reboot, you should be able to run again: lvreduce --resizefs --size -40G /dev/vg-db-sda/dat.appdata

 

Try again installing and creating a new boot location.
