Issue

If an iRule calls an HTTP class that is not configured in the virtual server, the first time a connection is established and the iRule directs the connection to use the HTTP class, the connection will fail. When this occurs, in the /var/log/ltm file you may observe an error message similar to the following example:

tmm tmm[23141]: 01220001:3: TCL error: Rule <iRule_Name> 
<HTTP_REQUEST> - Illegal argument (line 3) invoked from
within "HTTP::class select $<http_class_name>"

For example, connections will fail for the following configuration where the iRule is configured to direct traffic to an HTTP class and the class is not associated with the virtual server:

   virtual auction_vip {
      destination 1.1.1.10:http
      snat automap
      ip protocol tcp
      profile http tcp
      pool auction_pool
      rule select_httpclass_rule
      httpclass /Common/http_class_1
   }

   rule select_httpclass_rule {
      when HTTP_REQUEST {
         HTTP::class select /Common/$http_class_2   <==== http_class_2 is not configured as a virtual server resource
      }
   }

The connection fails under these circumstances because, unlike pools, HTTP classes are not a global resource. HTTP classes must be assigned to the virtual server for the virtual server, or an iRule that is assigned to the virtual server, is allowed to use the HTTP class.

To prevent this error from occurring, ensure that all HTTP classes that are referenced by the iRule are configured on the virtual server. Ensure that the HTTP class is referenced using the entire path (/<Partition>/<class>).
