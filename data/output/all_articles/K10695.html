Known Issue

This is the result of a known issue. The following wide IP and pool configuration will result in the BIG-IP GTM system failing to return NOERROR responses and instead dropping DNS IPv6 requests:

  • A Last Resort pool is defined for the wide IP
  • The IPv6 NoError Response setting is enabled for the wide IP
  • The Fallback load-balancing method for the pool is set to None

Note: The IPv6 NoError Response setting specifies whether the BIG-IP GTM system returns a NOERROR response to IPv6 wide IP requests. If the setting is enabled, the BIG-IP GTM responds faster to IPv6 requests for which it does not have AAAA records configured. For more information, refer to K7851: Configuring the BIG-IP GTM or Link Controller systems to provide NOERROR responses for IPv6 queries.

F5 Product Development tracked this issue as CR96029, and it was fixed in BIG-IP GTM and Link Controller versions 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP GTM or Link Controller release notes.
