Topic

Note: This article applies to BIG-ASM 9.4.2 and earlier. For information about BIG-IP 9.4.3 and later, refer to K8216: Configuring RAM Cache for use with a BIG-IP ASM enabled virtual server.

To enable RAM Cache for multimedia files on a BIG-IP ASM-enabled virtual server, you must perform the following procedures:

  • Configuring a BIG-IP ASM-disabled HTTP class profile for multimedia URIs
  • Configuring a BIG-IP ASM-enabled HTTP class profile for all other URIs
  • Associating HTTP class profiles with the virtual server
  • Ensuring the images Data Group contains desired file types
  • Creating an iRule to cache file types listed in the images Data Group
  • Associating the iRule with the virtual server
  • Enabling Ram Cache on the HTTP profile associated with the virtual server

Configuring a BIG-IP ASM-disabled HTTP class profile for multimedia URIs

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Classes.

    The HTTP Class Profiles screen opens.
  3. Click Createbutton.

    The New HTTP Class Profile screen opens.
  4. Type a name for the HTTP class profile.
  5. Select Disabled from the Application Security drop-down menu.
  6. Select Match only from the URI Paths drop-down menu.

    The URI Path List expands.
  7. In the URI Path box, type a regular expression that matches only file extensions for files that contain static content.

    For example, to match .jpeg, .bmp and .gif files, you would type the following regular expression:

    (?i)\.(jpg|gif|bmp)$ Note: Using this regular expression in the HTTP class profile may allow certain requests to be sent directly to the web server.

    For an alternate method of bypassing the BIG-IP ASM system for static content, such as media files that are too large for RAM cache, refer to K7616: Configuring static web content to bypass the BIG-IP ASM in BIG-IP version 9.x.
  8. Select Regular Expression from the Entry Type drop-down menu.
  9. Click Addbutton to add the regular expression to the URI Path List.
  10. Select Pool from the Send To drop-down menu.

    The Pool drop-down menu appears.
  11. Select the appropriate pool for the web application from the Pool drop-down menu.
  12. Click Finished.

    The screen refreshes, and you see the new HTTP class in the HTTP class profile list.

Configuring a BIG-IP ASM-enabled HTTP class profile for all other URIs

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Classes.

    The HTTP Class Profiles screen opens.
  3. Click Create.

    The New HTTP Class Profile screen opens.
  4. Type a name for the HTTP class profile.
  5. From the Application Security drop-down menu, select Enabled.
  6. From the Send To drop-down menu, select Pool.

    The Pool drop-down menu appears.
  7. Select the appropriate pool for the web application from the Pool drop-down menu.
  8. Click Finished.

    The screen refreshes, and you see the new HTTP class in the HTTP class profile list.

Associating HTTP class profiles with the virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the virtual server that you want to configure.

    The Properties screen for the virtual server opens.
  4. Click Resources from the top menu bar.

    The Resources screen for the virtual server opens.
  5. Click Manage for the HTTP Class Profiles section.

    The Resource Management screen opens.
  6. From the Available section, select the HTTP class profile created for multimedia URIs.
  7. Click <<.

    The HTTP class profile created for multimedia URIs will be moved to the Enabled section.
  8. From the Available section, select the HTTP class profile created for all other URIs.
  9. Click <<.

    The HTTP class profile created for all other URIs will be moved to the Enabled section.
  10. Use the Up and Down buttons below the Enabled list to ensure the HTTP class profile for multimedia URIs is listed first.

    Note: The system applies the HTTP classes in the order they are listed.
  11. Click Finished.

Ensuring that the image Data Group contains the correct file types

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Data Group List from the menu bar.
  4. Click the images' Data Group List.
  5. Verify that the file types listed are the same as the file types you configured for the BIG-IP ASM-disabled HTTP class profile.
  6. Click Update.

Creating an iRule to cache file types listed in the images Data Group

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Type a name for the iRule.
  5. Type the following iRule definition:

    when HTTP_REQUEST {
    if { [matchclass [HTTP::path] ends_with $::images] } {
    CACHE::enable
    }
    else {
    CACHE::disable
    }
    }
  6. Click Finished.

Associating the iRule with the virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the virtual server that you want to configure.

    The Properties screen for the virtual server opens.
  4. Click Resources from the top menu bar.

    The Resources screen for the virtual server opens.
  5. Click Manage for the iRules section.

    The Resource Management screen opens.
  6. From the Available section, select the iRule created to cache image file types.
  7. Click <<.

    The iRule will be moved to the Enabled section.
  8. Click Finished.

Enabling Ram Cache on the HTTP profile associated with the virtual server

Note: F5 recommends that you create a new profile with desired custom settings, rather than modify a default HTTP profile.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Select the HTTP profile used by the virtual server.
  4. From the RAM Cache drop-down menu, select Enabled.
  5. Click Update.
