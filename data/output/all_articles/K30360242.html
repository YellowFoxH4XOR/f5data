Description
There are multiple VPN servers distributed to different geographic sites, and they are load balanced by GTM.
 

Environment

  • BIG-IP APM
  • BIG-IP GTM
  • VPN

Cause
You experience slowness while trying to connect to the VPN, or after you have connected you are randomly disconnected for no apparent reason.
The reason for this, behavior is when you initiate a connection to the VPN server, you use the hostname "vpn.mycomany.com", your GTM server load balances this between site1 and site 2. On the initial connection you are given the IP Address of site 1, and connect to the VPN at site1.
When you are connected your Client PC queries the DNS again for "vpn.mycomany.com" but is now given the IP Address for site 2, and so the VPN tunnel starts directing VPN packets towards site 2, but there is no established tunnel there and no session, so the connection fails.
 

Recommended Actions

  1. The VPN server at each site should have a unique name as well as a common name for all VPN servers at all sites.
  2. After the initial connection to the VPN server, and before authentication has occurred, you should force a redirection back to the same VPN site using its unique name. This will maintain persistence to the same site regardless of any change in IP address by the GTM load balancer.
