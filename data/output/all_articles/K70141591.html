Description

Most retransmissions are for TCP FIN.

Environment

Relevant environmental factors specific to the topic

  • BigIP version with the fix for K63086108: Health monitor connections may remain in the open connection state after server side termination
  • BigD SSL monitors. ( e.g. https monitor.) are used.
  • Server sides / pool members send Application Data (eg. 200OK) and "Encrypted Alert" in different packets to close the connection immediately.

Cause

The reason is the fix of ID409340.

    1. When BigIP processes "Application Data" and does not see "Encrypted Alert" at the same time, BigIP will send an Encrypted Alert to close the connection. ( Nothing wrong till now.)

2. After BigIP sends an "Encrypted Alert"

- Bigd will not wait for the alert from the other side. ( All the following packets from server side are ignored, including Alert and ACKs.. This is WRONG, ID1059245 is filed.)
- The second FIN is ACKed (Quick ack mode activated by upper protocol layer).
- Bigd sends its own FIN after 1 second.

3. This behavior is to prevent the case that Server side does NOT send "Encrypted Alert" and cause monitor connections hanging for a long time till an idle timeout.

   While it causes retransmissions when Encrypted Alert was sent in an other packet.

    Impact

    Additional re-transmission is seen during connection closure. This has no major impact on the probe processing.

    This is not compatible with TLS 1.3 half-close. 
    Workaround

Consider switching to in-tmm monitors.
More info about in-tmm monitor K11323537: Configuring In-TMM monitoring
