Known Issue

Content-based routing saves XML variables globally, rather than on a per-connection basis.

This issue occurs when all of the following conditions are met:

  • The XML_CONTENT_BASED_ROUTING iRules event is triggered
  • The iRule executes an operation based on the values of any of the following variables:
     
    • $XML::count
    • $XML::queries
    • $XML::values

Content-based routing requires the variables for a given connection to be unique to that connection. However, the iRules engine incorrectly saves XML::namespace variables in the XML_CONTENT_BASED_ROUTING event as global variables. Therefore, the variable values may be shared across multiple instances of the rule concurrently.

For example if a content-based routing iRule is designed to evaluate the USERNAME XML element and send connections with a value of username1 to the load balancing pool pool_1, and send connections with the value of username2 to the pool pool_2, due to this issue the values username1 and username2 may be incorrectly shared globally between instances of the iRule. As a result, a connection with the value of username1 may be load balanced to pool_2.

Note: This variable data is only incorrectly evaluated across connections within the iRules parser. The actual XML payload data is not modified before it is sent to the pool member.

Impact

Content-based routing may not function as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • F5 iHealth lists Heuristic H381323 on the Diagnostics > Identified > Medium screen.
  • iRules operations based on XML_CONTENT_BASED_ROUTING variable values may not function as expected.
  • The $XML::count, $XML::queries, and $XML::values variables for a given connection may be populated with values from a different, concurrent connection.
