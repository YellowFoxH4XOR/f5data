Known Issue

This is the result of a known issue. When Client Certificates is set to Require in the client SSL profile, the BIG-IP LTM does not properly verify client SSL certificates.

According to RFC2246, a certificate verify message will be sent by the client to provide verification of the certificate it is presenting to the server. The certificate verify message immediately follows the client key exchange message during the SSL handshake.

When a client SSL profile is configured to require client certificates, the BIG-IP LTM incorrectly accepts a connection to a client SSL virtual server from a client that presents a signed client SSL certificate, but does not generate a certificate verify message.

F5 Product Development tracked this issue as CR93894 and CR124436 and it was fixed in BIG-IP LTM version 9.4.8. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF2 issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

To work around this issue, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. From the SSL menu, select Client.
  5. Click the relevant client SSL profile.
  6. Enter COMPAT in the ciphers box.
  7. Click Update.

Important: Configuring the SSL profile to use the COMPAT SSL stack may have a performance impact on the virtual server.
