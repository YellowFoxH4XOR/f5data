Topic

You should consider using this procedure under the following condition:

  • You want to determine if a security vulnerability affects a specific F5 product or version.

Description

F5 investigates and reports potential security vulnerabilities based on the security vulnerability response policy defined in K4602: Overview of the F5 security vulnerability response policy.

F5 software uses either a three-digit or four-digit software version schema in the format major.minor.patch or major.minor.maintenance.point-release.

Note: NGINX Plus follows a release model: Long-Term Support (LTS) and Continuous Releases (CR). For more information, refer to NGINX Plus Releases.

Note: NGINX Open Source Subscription is distributed in two versions: stable and mainline. For more information, refer to the NGINX Open Source download page and the Stable and mainline versions section of the Installing NGINX Open Source page.

Software release typeDescriptionRequirements
Major releaseSignificant new functionality and changes to default behaviorUpgrade required to move to new major releases
Minor releaseMaterial new functionality and changes to default behaviorUpgrade required to move to new minor releases
Maintenance or patch releaseNo changes to default behavior

Includes only vulnerability fixes, defect fixes, potentially new diagnostic supportability improvements, minor functional improvements, and new hardware support

Update required to move to new maintenance releases
Point releaseNo changes to default behavior

Includes only vulnerability fixes, defect fixes, potentially new diagnostic supportability improvements, minor functional improvements, and new hardware support

Update required to move to new point releases

Note: The four-digit format including point release was first introduced December 19, 2017 with the release of BIG-IP 13.1.0.1. Point release replaces the previous method of using HF to note the hotfix version. For example, a hotfix previously designated as BIG-IP 13.1.0 HF1, is now designated as BIG-IP 13.1.0.1. Security advisory status tables may include both formats, depending on the BIG-IP versions affected. A point release is a full release that addresses product defects, including the hardening and refining of existing features and security fixes, and may contain minor functional improvements. For information about the definitions for major, minor, maintenance, and point and their differences, refer to K8986: F5 product support policies.

The F5 security advisory article contains the following components to determine the vulnerability of each product:

  • The Evaluated products section lists all of the products evaluated by F5 Product Development.

    Note: The Evaluated products field in security advisory articles is interpreted differently than the Applies to field seen in other knowledge articles. The Applies to field is meant to convey that the content of the knowledge article applies to all products and versions listed in that field. The Evaluated products field in security advisories is meant to convey that all of the products and versions listed have been evaluated by Product Development for the specific vulnerability.

  • The Security Advisory Status section lists what products, if any, are vulnerable and whether any fixes are introduced. When at least one F5 product contains a vulnerable version of code, F5 products is grouped into separate status tables in the Security Advisory Status section of the article to provide the vulnerability status for each F5 product.

    Note: If no F5 products are affected by the vulnerability described in the security advisory article, the Security Advisory Status section of the article will not include a table.

    When status tables are provided in the Security Advisory Status section, the following columns determine how each product is affected:

    • Product: F5 product with product modules grouped in parentheses. For example: BIG-IP (LTM, APM, ASM).
    • Branch: The major branch for the specified product. For example, 17.x or 16.x.
    • Versions known to be vulnerable: The range of product versions within each branch that are confirmed by F5 Product Development as vulnerable. Point releases and hotfixes are not listed in this column, unless a vulnerability is specifically introduced in a given point release or hotfix. Vulnerable versions include all point releases or hotfixes for a given software version. For example, if BIG-IP 16.1.0 is listed as vulnerable, then BIG-IP 16.1.0.1 and 16.1.0.2 are also considered vulnerable if neither of those point releases are listed in the Fixes introduced in column. Similarly, if BIG-IP 12.1.1 is listed as vulnerable, then BIG-IP 12.1.1 HF1 and HF2 are also considered vulnerable if neither of those hotfix versions are listed in the Fixes introduced in column.
    • Fixes introduced in: This column indicates when one of the following types of fixes has been introduced:
      • A major release is introduced that contains a fix in the initial x.0.0 release. For example, no vulnerable versions are listed for the BIG-IP 17.x branch, but BIG-IP 17.0.0 is listed because a fix was introduced in the initial BIG-IP 17.0.0 release.

        Note: If a fix is introduced in BIG-IP 17.0.0, then no subsequent BIG-IP 17.x releases will be listed in the Fixes introduced in column.

      • A minor release is introduced that contains a fix in the initial x.1.0 release. For example, no vulnerable versions are listed for the BIG-IP 17.x branch, but BIG-IP 17.1.0 is listed because a fix was introduced in the initial BIG-IP 17.1.0 release.

        Note: If a fix is introduced in BIG-IP 17.1.0, then no subsequent BIG-IP 17.1.x releases will be listed in the Fixes introduced in column.

      • A maintenance release is introduced that fixes all versions for a given minor release. For example, BIG-IP 17.1.1 is released, which fixes all future releases in the BIG-IP 17.1.0 minor release branch.

        Note: If a fix is introduced in BIG-IP 17.1.1, then BIG-IP 17.1.2 and any subsequent BIG-IP 17.1 release is not listed in the Fixes introduced in column.

      • A point release or hotfix is introduced that fixes all versions for a given maintenance release. For example, if a fix is introduced in BIG-IP 17.1.0.1, this fix is included in all future point releases for BIG-IP 17.1.0, which would include BIG-IP 17.1.0.2 and 17.1.0.3. Similarly, when a fix is introduced in BIG-IP 12.1.1 HF1, this fix is included in all future hotfix versions of BIG-IP 12.1.1, which would include BIG-IP 12.1.1 HF2 and 12.1.1 HF3.

        Note: If a fix is introduced in BIG-IP 17.1.0.1, then BIG-IP 17.1.0.2 and any subsequent BIG-IP 17.1.0 point releases are not listed in the Fixes introduced in column. Similarly, if a fix is introduced in BIG-IP 12.1.1 HF1, then BIG-IP 12.1.1 HF2 and any subsequent BIG-IP 12.1.1 hotfixes are not listed in the Fixes introduced in column.

    • Severity: The severity listed applies to those versions listed in the Versions known to be vulnerable column. If there are no vulnerable versions for any branch of the product, the product severity is Not vulnerable.

      Note: For information about how vulnerability severity is determined, refer to K4602: Overview of the F5 security vulnerability response policy.

    • CVSS 3.1 score: F5 uses CVSS 3.1 as the primary scoring standard. A CVSS 4.0 score may be included as an informational addendum. If a CVSSv3.1 score is listed, the score applies to those versions listed in the Versions known to be vulnerable column. This base score is linked to the Common Vulnerability Scoring System Version 3.1 Calculator, which can be used to interpret the provided score.

How do I know if my version is vulnerable?

Three points of reference are used to determine whether a product version is vulnerable:

  1. Is the product version listed in the Evaluated products section of the article?

    If the version is not listed, it has either not been evaluated for this vulnerability, or it was fixed in a previous version, and the article will not be updated.

  2. Is the version included in the Versions known to be vulnerable column of the product status table, either specifically or within a range of versions?

    If the version is listed in the Evaluated products section of the article but is not included in Versions known to be vulnerable, that version has been evaluated and found to be not vulnerable.

  3. Refer to the Fixes introduced in column to determine if a fix has been released for the software branch.

"Final" article disclaimer

Once all supported F5 product versions are addressed in a security advisory, the following disclaimer appears at the top of the article:

The security issue described in this article has either been resolved or does not affect any F5 products. There will be no further updates, unless new information is discovered.

"Will not fix" status for a product version

There may be several reasons why a particular product version is set to Will not fix in the Fixes introduced in column of the status table.

For example:

    • The third-party upstream software provider will not provide a fix for the software.
    • Providing a fix will break expected functionality or behavior of one or more other features of the system.
    • Substantial system changes are required to accommodate or allow for a fix, which precludes the feasibility of a fix.
    • The product version has reached its End of Software Development (EoSD) stage, as defined in K8986: F5 product support policies.

Your options when a fix is unavailable:

    • Upgrade/update to a supported product version that includes a fix for this vulnerability (recommended).
    • Follow the available mitigation procedure, if one exists.
