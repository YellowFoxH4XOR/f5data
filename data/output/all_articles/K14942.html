Topic

You should consider using this procedure under the following condition:

  • You need to import existing Secure Sockets Layer (SSL) keys, which the BIG-IP system can use, to a Thales nShield Connect external hardware security module (HSM).

Description

Starting in BIG-IP 11.2.0, the BIG-IP system supports the import of SSL keys into the Thales nShield Connect external HSM, and the use of the SSL keys stored on the Thales external HSM by various BIG-IP features, such as BIG-IP SSL profile. This feature is available to all BIG-IP platforms, including the BIG-IP Virtual Edition. When an SSL key is imported to the Thales external HSM, the system generates a pseudo key file for the BIG-IP system to import, together with its corresponding SSL certificate. To activate this feature, perform the following procedures.

Note: You must perform the following procedures for each SSL key that you want to import into the Thales external HSM.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Properly install the Thales nShield Connect external HSM, and ensure that the BIG-IP system on your network can reach it.
  • Configure the Thales nShield Connect external HSM to allow the BIG-IP system to perform crypto operations.

    Note: For information about configuring the Thales external HSM, refer to the documentation provided by your vendor.
  • License the BIG-IP system with the External Interface and Network HSM license option.
  • Install the BIG-IP system with the Thales nShield Connect components, and configure the system to communicate with the Thales nShield Connect external HSM by way of the Thales Remote File System (RFS).

    Note: For information about installing the Thales components and configuring the BIG-IP system to communicate with the external HSM, refer to the About external HSMs and LTM chapter of the BIG-IP Platform: FIPS Administration guide.

    Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

  • Ensure that you have administrative access to the BIG-IP system command line.

Procedures

  • Uploading a copy of the SSL certificate and key
  • Importing the SSL key into the Thales nShield Connect external HSM
  • Importing the SSL certificate and pseudo key into the BIG-IP system using the tmsh utility
  • Removing the SSL certificate and key files

Uploading a copy of the SSL certificate and key

If the desired SSL certificate and key to be imported to the Thales external HSM do not already exist on the BIG-IP system, you must upload a copy of these items to the BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Use Secure Copy (SCP) to transfer the existing SSL certificate and key files to the /var/tmp directory on the BIG-IP system.

    Note: For more information about transferring files to the BIG-IP system, refer to K175: Transferring files to or from an F5 system.
  2. Ensure the uploaded SSL key file is set with adequate permissions so other users on the BIG-IP system do not have the permissions to view the SSL key file.

    For example, you would type the following command to allow read and write permission for the owner of the exthsmexample.key file in the /var/tmp directory:

    chmod 600 /var/tmp/exthsmexample.key

Importing the SSL key into the Thales nShield Connect external HSM

After you have uploaded the SSL certificate and key files to the /var/tmp directory on the BIG-IP system, proceed to import the SSL key into the Thales external HSM by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line, if you have not already logged in.
  2. Import the SSL key into the Thales external HSM using the Thales nShield Connect generatekey utility.

    For example, type the following command:

    /opt/nfast/bin/generatekey --import pkcs11 certreq=yes

  3. The utility provides a series of interactive prompts for information during the SSL key import; the following three information prompts require manual input:
    • pemreadfile: This information prompt requests that the system import the full path to the SSL key. Using the same example in step 2 of the Uploading a copy of the SSL certificate and key procedure, the full path is  /var/tmp/exthsmexample.key
    • iframesavefile: This information prompt requests the full path of the output file to which the pseudo key is written by the utility. For example, /var/tmp/exthsmexample_hsm.key.

      Note: F5 recommends that you use the /var/tmp directory for better file manageability.

    • plainname: This information prompt requests the name of the SSL key that is associated with the Thales RFS. For example exthsmexample.

    For the remaining information prompts, you can either enter the desired values or leave the default values.  Once the system has successfully imported the SSL key into the Thales external HSM, the utility reports the status of the key import, as well as the path for the key file created on the Thales RFS.

    For example:

    Key successfully imported.
    Path to key: /opt/nfast/kmdata/local/key_pkcs11_uced028e5251b7b6891e7e59dec5428d871f92241b-c70e6451e8d793ca80a497267ccb9bc73bd55edb

  4. Change the owner and permissions of the Thales RFS key file that was created in step 2 by entering the following commands:

    chown nfast:nfast <Thales RFS key file path>
    chmod 755 <Thales RFS key file path>

    Using the example Thales RFS key file, you would enter the following commands:

    chown nfast:nfast /opt/nfast/kmdata/local/key_pkcs11_uced028e5251b7b6891e7e59dec5428d871f92241b-c70e6451e8d793ca80a497267ccb9bc73bd55edb
    chmod 755 /opt/nfast/kmdata/local/key_pkcs11_uced028e5251b7b6891e7e59dec5428d871f92241b-c70e6451e8d793ca80a497267ccb9bc73bd55edb

    Note: If this step is omitted, the rfs-sync utility in the next step fails and reports a permission denied error.

  5. Sync the Thales-generated pseudo key to the RFS by typing the following commands:

    rfs-sync --update
    rfs-sync --commit

    Note: If the BIG-IP system that this procedure is performed on is also the RFS, the previous rfs-sync commands report 0 committed. This is expected behavior, as the SSL key imported in step 3 is automatically stored in the RFS directory.

    For example, both commands complete the sync and report that the system has committed no files.

    # rfs-sync --update
    Starting synchronisation, task ID 52cef442.a2adc2d8b21917b5
    Finished synchronisation: 0 files updated, 0 committed.

    # rfs-sync --commit
    Starting synchronisation, task ID 52cef44c.1d1e9d32a1f2a9a4
    Finished synchronisation: 0 files updated, 0 committed.

Importing the SSL certificate and pseudo key into the BIG-IP system using the tmsh utility

After you have successfully imported the SSL key to the Thales external HSM, you must proceed to import both the Thales-generated pseudo key and the corresponding SSL certificate into the BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Import the Thales-generated pseudo key file into the BIG-IP system by typing the following command:

    install /sys crypto key <key name> from-local-file <path/to/pseudo key file>

    The Thales-generated pseudo key file is the full path that you have entered for the iframesavefile information prompt in step 1 of the Importing the SSL key into the Thales nShield Connect external HSM procedure. Using the example in step 1 of that procedure, you would enter the following command:

    install /sys crypto key exthsmexample.key from-local-file /var/tmp/exthsmexample_hsm.key

  3. Import the corresponding SSL certificate file into the BIG-IP system by entering the following command:

    install /sys crypto cert <cert name> from-local-file </path/to/certificate file>

    For example:

    install /sys crypto cert exthsmexample.crt from-local-file /var/tmp/exthsmexample.crt

  4. Save the change by typing the following command:

    save /sys config

  5. Optional: If you need to import more SSL certificates and keys, repeat all preceding procedures and steps for each certificate and key pair.

Removing the SSL certificate and key files

Once you have successfully imported the pseudo key and its corresponding SSL certificate to the BIG-IP system, you can safely remove the copy of these files that you have uploaded in the Uploading a copy of the SSL certificate and key procedure. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line, if you have not already logged in.
  2. List the key and certificate files that you have uploaded or generated in the preceding procedures by typing the following command:

    ls -al /var/tmp/<key filename>*

    Using the examples from preceding procedures, the following command lists four files:

    ls -al /var/tmp/exthsmexample

    -rw------- 1 root root 1545 Dec 18 17:53 /var/tmp/exthsmexample.crt
    -rw------- 1 root root 1679 Dec 18 17:53 /var/tmp/exthsmexample.key
    -rw------- 1 root root 1196 Dec 18 17:55 /var/tmp/exthsmexample_hsm.key
    -rw------- 1 root root 1001 Dec 18 17:55 /var/tmp/exthsmexample_hsm_req.key

    The first two files, exthsmexample.crt and exthsmexample.key, are uploaded in the Uploading a copy of the SSL certificate and key procedure, while the remaining two files, exthsmexample_hsm.key and exthsmexample_hsm_req.key, are generated by the generatekey utility in step 1 of the Importing the SSL key into the Thales nShield Connect external HSM procedure.
  3. Remove these files by typing the following command:

    rm /var/tmp/<key filename>*

    Using examples from previous steps, you would type the following command:

    rm /var/tmp/exthsmexample*

    Note: You can also use the shred utility to delete SSL key files in a secure manner to reduce the probability of recovering the SSL key files from disk. For information about using the shred utility, refer to the shred manpage by entering man shred in the command line.
