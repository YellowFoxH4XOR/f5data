Topic

When you launch a Network Access Favorite using the Safari or Firefox browsers from a Mac OS X 10.5 (Leopard) client, and the FirePass controller is version 6.0.2 or earlier, the Network Access pop-up window will indicate that you are connected to the VPN. However, you will then receive a browser pop-up window with the following error message:

FirePass Server closed connection (code 38)

Subsequently, you will receive a second browser pop-up window with one of the following two error messages:

  • Connection dropped

  • pppd daemon did not start

In addition to the Network Access client failing, other potential consequences exist that can disrupt network connectivity. The following possibilities can occur:

  • The /etc/resolv.conf file that contains the DNS servers may not be restored to the original state prior to starting Network Access. If your Leopard client cannot access sites in a browser or other applications using a DNS name, you can type the following command from a Terminal application (Terminal.app):

    cat /etc/resolve.conf

    If the /etc/resolv.conf  file does not exist or is empty, you must restore the /etc/resolv.conf file in order to restore name resolution service. If the Leopard client uses DHCP, renewing the DHCP lease usually restores the /etc/resolv.conf file.

  • As a result of starting Network Access, a pppd process was initiated, but not terminated. If your Leopard client has lost general network connectivity, type the following command from a Terminal application (Terminal.app):

    ps -elf  | grep pppd

For a leftover pppd process, you can see a listing within the process labeled pppd call FirePass, with the following example:

0   691     1    4102   0  31  0    75600    964 -      Ss+  2050078 ttys000    0:00.07 pppd call FirePass/

You can terminate the leftover pppd process by typing the kill command with the process ID of the pppd process. For example, the pppd process ID is 691. In the Terminal application, you can type the following command:

kill 691

Starting in FirePass version 6.0.3 and in FirePass version 6.0.2 with cumluative hotfix HF-602-2, FirePass supports clients running Mac OS X 10.5.

Note: For more information about FirePass support for Mac OS X version 10.5, refer to K8076: FirePass support for Mac OS X version 10.5.

For earlier FirePass versions without support for Mac OS X version 10.5, F5 Networks recommends using either a pre-logon sequence or a protected resource to prevent Leopard clients from attempting to use Network Access Favorites. Alternatively, users may be able to run virtualization software under OS X 10.5, which creates a virtual machine capable of running an operating system that supports Network Access.
