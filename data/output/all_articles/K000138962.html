K000138962: Problem with iQuery synchronization between Link Controllers

Type
Knowledge
Published
2024-03-26
Updated
2024-03-26
Applies to
  • BIG-IP
  • BIG-IP Platforms
  • VIPRION Platforms
  • BIG-IP DNS
  • BIG-IP Link Controller
Source
https://my.f5.com/manage/s/article/K000138962

Description

Your Link Controllers are not in iQuery synchronization anymore.

Environment

  • BIG-IP LC
  • iQuery synchronization
  • performing actions to synchronize Link Controller devices through iQuery

Cause

Configuration was lost or impossible to recover.

Recommended Actions

Proceed with the article K45907236: Overview of BIG-IP DNS synchronization but in a different way. From there, we know that we need to create gtm datacenter, gtm server and run gtm_add script. There is no way to do that in LC GUI, so all needs to be performed in CLI. You may want to configure more options than in the example, the provided articles have more details about each action.

 

  1. Create Datacenter referring to gtm datacenter on F5 Cloud docs: 
    tmsh create datacenter <name>
    For example, the following command creates gtm datacenter ONE: 

    tmsh create datacenter ONE

  2. Create Server for both devices referring to gtm server on F5 Cloud Docs: 
    tmsh create gtm server <server name> datacenter <name> devices add { <device name> { address add {self IP}}}

    For example, the following commands create gtm server Example1 in datacenter ONE, with self IP address 1.1.1.1, with bigip monitor applied and product type bigip.

    tmsh create gtm server EXAMPLE1 datacenter ONE devices add { EXAMPLE1-bigip1 { addresses add { 1.1.1.1 } } } monitor bigip product bigip

     

    The following commands create gtm server Example2 in datacenter ONE, with self IP address 1.1.1.2, with bigip monitor applied and product type bigip.

    tmsh create gtm server EXAMPLE2 datacenter ONE devices add { EXAMPLE2-bigip2 { addresses add { 1.1.1.2} } } monitor bigip product bigip

  3. Run gtm script on peer/remote device.
    gtm_add <existing_LC_IP_addres> 

    Example:

    On bigip1 run:

    gtm_add 1.1.1.2

Impact of gtm_add command: The following procedure replaces the configuration from the BIG-IP DNS system on which it is run, with the configuration of the remote BIG-IP DNS system in the specified synchronization group.
