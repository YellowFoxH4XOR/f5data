Known Issue

When the BIG-IP Traffic Management Microkernel (TMM) process starts up, it establishes a connection to an internal interface on the switch hardware. During some instances when TMM is starting, TMM fails to handshake properly with the interface, causing the interface to intermittently lose connectivity.

Important: This issue affects all platforms; it is a result of a software driver, not defective hardware.

This issue may occur when either of the following conditions is met:

  • The BIG-IP system was rebooted.
  • The TMM process was restarted.

Impact

The affected BIG-IP system may not be able to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When this behavior occurs, you may observe an error message indicating that the internal interface transitioned from an up/down state in the /var/log/ltm file. The log entries may appear similar to the following example:

    Note: You may observe several entries over the course of an hour.

    10.x

    Feb 19 05:08:06 local/tmm1 warning tmm1[2252]: 01230001:4: Interface 0.2: link is up, 1000Mbps Full Duplex
    Feb 19 05:58:19 local/tmm1 warning tmm1[2252]: 01230002:4: Interface 0.2: link is down
    Feb 19 05:58:20 local/tmm1 warning tmm1[2252]: 01230001:4: Interface 0.2: link is up, 1000Mbps Full Duplex
    Feb 19 06:12:01 local/tmm1 warning tmm1[2252]: 01230001:4: Interface 0.2: link is up, 1000Mbps Half Duplex


    9.4.x

    Nov 18 19:40:36 tmm1 tmm1[2240]: 01230002:4: Interface 0.2: link is down
    Nov 18 19:40:37 tmm1 tmm1[2240]: 01230001:4: Interface 0.2: link is up, 1000Mbps Full Duplex
    Nov 18 21:14:47 tmm1 tmm1[2240]: 01230001:4: Interface 0.2: link is up, 1000Mbps Half Duplex
    Nov 18 21:14:48 tmm1 tmm1[2240]: 01230001:4: Interface 0.2: link is up, 1000Mbps Full Duplex

  • You can see messages that appear similar to the following examples, indicating that the handshake failed in the /var/log/tmm file:

    10.x

    Jan 29 15:20:36 local/<BIG-IP NAME> notice bge1: firmware handshake timed out


    9.4.x

    Nov 18 18:12:13 <BIG-IP NAME> bge1: firmware handshake timed out

Workaround

To work around this issue, you can restart the affected TMM process. To do so, perform the following procedure:

Impact of workaround: Restarting the affected TMM process will interrupt traffic processing on the BIG-IP system.

  1. Log in to the BIG-IP command line.
  2. To restart the TMM process, type the following command:

    bigstart restart tmm

  3. Once TMM has restarted, check the /var/log/ltm and /var/log/tmm files for any reports of an interface 0.x reporting that the link is up/down or a firmware handshake timed out message.

Note: If the workaround did not resolve the issue, contact F5 Technical Support. For information about contacting F5 Technical Support, refer to K2633: Instructions for submitting a support case to F5 .
