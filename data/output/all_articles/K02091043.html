Issue

Error Message

The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

The previous error may be accompanied by the following error when you log in to the Configuration utility:

This BIG-IP system has encountered a configuration problem that may prevent the Configuration utility from functioning properly.

Output of the tmsh show sys mcp-state command reports an error similar to the following:

-------------------------------------------------------
Sys::mcpd State:              
-------------------------------------------------------
Running Phase                   platform
Last Configuration Load Status  base-config-load-failed
End Platform ID Received        true

Note: If mcp-state does not show base-config-load-failed, the error likely indicates a transitory state and you can ignore it.  If the error persists, follow the suggestions outlined in this article.

Important: Do not make any changes to the configuration in the failed state because you can overwrite the configuration.

Message Location

You may encounter this message in the following location:

  • The Configuration utility

Description

This message occurs when one of the following conditions are met:

  • The BIG-IP configuration has failed to load after an upgrade or restart due to an error in the configuration.
  • The BIG-IP configuration has failed to load after an upgrade or restart due to a known issue.
  • If license enforcement fails during an upgrade, the configuration may fail to load when booting to the new volume.

There are numerous causes for configuration errors, and the causes depend on your environment. For more information about some of configuration errors or known issues that lead to a configuration load failure, refer to the following articles:

  • K67343162: When SNMP traps are configured, the BIG-IP configuration may fail to load after an upgrade
  • K19415206: The BIG-IP configuration fails to load if a duplicate SNAT translation object exists
  • K23934354: Cache path (/config/filestore/files_d/<Partition>_d/ifile_d/:<Partition>:<Filename>_<revision number>) does not exist and there is no copy in trash-bin to restore from.
  • K04249440: Configuration fails to load due to missing file or directory
  • K27193232: Monitor <monitor name> address type requires a port error leads to loading configuration process failed error
  • K33233632: After upgrade and reboot with Install Configuration set to Yes, the BIG-IP appears to have hung or lost all configuration and mcpd, gtmd, named and others are in a restart loop
  • K31992159: After upgrading to 13.1.x you are not able to see configuration objects on the BIG-IP due to a configuration load failure

Impact

The BIG-IP device status is INOPERATIVE and does not process any traffic.

Recommended Actions

To watch a video demo of this procedure, go to Troubleshoot and fix a BIG-IP configuration file when the configuration does not load.

Reactivate the license if necessary

If license enforcement is the condition causing the load failure, you need to reactivate the license to ensure that the service check date is later than the license check date. F5 recommends performing this action before an upgrade; however, in most cases, reactivating the license from the command line on the newly upgraded device while it's in the INOPERATIVE state triggers the configuration to reload successfully. For more information refer to K2595: Activating and installing a license file from the command line and K7727: License activation may be required before a software upgrade for the BIG-IP or Enterprise Manager system.

Determine the configuration objects causing the load failure and investigate a resolution

If the license is active, another issue is causing the configuration load failure. To determine the specific configuration object or objects that are causing the configuration to fail to load, perform the following procedure:

Impact of procedure: Take care when editing configuration files because incorrect edits can lead to additional errors. When you get the configuration to load, the device becomes available, and it is possible the device can take the active role; therefore, you should schedule the procedure for a maintenance window in case of the potential failover event.

  1. Log in to the BIG-IP command line.
  2. Attempt to manually load the configuration by entering the following command:

    tmsh load sys config

    If the configuration loads, then you have resolved the issue. If the configuration fails to load, the command reports the configuration object or line in the affected file that is causing the issue. For example:

    01070712:3: Failed: name (/Common/dtca-bundle.crt) Cache path (/config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca-bundle.crt_63010_4) does not exist and there is no copy in trash-bin to restore from.
    Unexpected Error: Loading configuration process failed.

    In the previous example, the configuration object in question is /Common/dtca-bundle.crt.

  3. If you are comfortable and familiar with troubleshooting the BIG-IP system, perform the following steps. Otherwise, stop here, note the configuration object, and contact F5 Support.

    Note: After you resolve the error with the initial configuration object, the configuration may fail to load again if there are more errors with other configuration objects.

  4. If necessary, search the configuration files to determine which file contains the object with the issue by entering the following command syntax:

    grep -r <object> /config/*

    For example:

    grep -r /Common/dtca-bundle.crt /config/*

    Note: The object itself appears in the results, as well as references to the object. The object also appears in backup files that have the extension .bak and in any copies of the files you made.

  5. Display the configuration object by viewing the file with cat or less. To do so, enter the following command syntax:

    less <file>

    For example:

    less bigip.conf

    Examine the configuration object and research the error to determine how to fix the issue.

  6. If the working directory is not /config, change to /config by entering the following command:

    cd /config

  7. Make a backup copy of the file you are going to edit by entering the following command syntax:

    cp <original configuration file> <copy of configuration file>

    For example:

    cp bigip_base.conf bigip_base.conf.K02091043

  8. Manually edit the file to correct any issue using a text editor of your choice. For example, if you use vi, the command to open the file for editing is the following:

    vi bigip_base.conf

  9. Save the file and quit the text editor. For example, if you use vi, the command sequence is the following:

    :wq

  10. Manually load the configuration again and fix any additional issues using the previous steps.
