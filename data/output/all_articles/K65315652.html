Known Issue

Server-side iRules may parse HTTP cookies incorrectly when cookie values are empty.

This issue occurs when all of the following conditions are met:

  • An iRule associated with a virtual server uses the HTTP::cookie command in server-side events.
  • A server response contains a Set-Cookie or Set-Cookie2 header with a cookie that has an empty value string.

For example, the session cookie in the following HTTP response header has an empty value, which may cause server-side iRules to interpret the expires attribute as another cookie:

Set-Cookie: SESSION=; expires=Mon, 14-Mar-2016 22:00:00 GMT; path=/; HttpOnly

Impact

The iRule may parse the cookie name, value, and attributes incorrectly, causing the iRule to malfunction.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • iRules using the HTTP::cookie command on server-side events malfunction or fail to parse cookies correctly.
  • The system generates Tool Command Language (TcL) error messages to the /var/log/ltm file that appear similar to the following example:

    err tmm[<PID>]: 01220001:3: TCL error: /Common/ <HTTP_RESPONSE> - Illegal argument. Missing argument (line 2) invoked from within "HTTP::cookie
