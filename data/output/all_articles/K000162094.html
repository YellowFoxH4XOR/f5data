Description

Disabling the Behavioural DoS (BaDOS) engine via the BIG-IP ASM GUI did not fully disable the backend configuration, leaving BaDOS active and causing persistent mitigation even after the attack ended. 

Environment

  • Product: BIG-IP ASM
  • Behavioural & Stress-based DoS Detection (BaDOS)
  • TPS-based DoS Detection

Cause

The BaDOS engine remained enabled in the backend configuration because disabling via the GUI only set the outer “Operation Mode” to off, but does not clear the inner dos-detection flag in the configuration. This leaves the behavioural engine active, resulting in persistent mitigation.

Recommended Actions

To fully disable BaDOS, both the operation mode and the dos-detection flag must be explicitly set to “off/disabled” using the CLI:

  1. Run:
tmsh modify security dos profile <profile_name> application modify { <profile_name> { stress-based { behavioral { dos-detection disabled signatures disabled } } } }

tmsh save sys config

 

  2. Verify the configuration:

tmsh list security dos profile <profile_name>

 

Confirm that dos-detection disabled appears in the output.

Additional Information

For environments with planned DDoS simulations or maintenance, set a finite “Prevention Duration” in the DoS profile to prevent persistent mitigation after the event.
