Description

Configured an Explicit Proxy Virtual Server, and virtual servers listening on the tunnel for port 443 and port 80.

Connection works for HTTPS using the CONNECT method.

Non-CONNECT HTTP requests are forwarded straight out of the system, and not picked up by the port 80 virtual server listening on the tunnel.

Environment

  • Explicit Proxy
  • HTTP

Cause

This is expected.

With HTTP explicit proxy mode, HTTP non-CONNECT requests are forwarded out via the appropriate route, and will not be intercepted by any virtual server that is listening on the tunnel.

Recommended Actions

If the default behaviour is not to your liking, you can control the routing, if necessary, by using an iRule with the nexthop command in the HTTP_REQUEST event.

For example, this iRule sends the traffic via the 10.10.2.251 gateway in VLAN Internal:

when HTTP_REQUEST {
     nexthop Internal 10.10.2.251
}

Alternatively, you can use a default pool on the explicit proxy virtual server, and call HTTP::proxy disable in the HTTP_PROXY_REQUEST event, if the request method is non-CONNECT.

when HTTP_PROXY_REQUEST {
    if {!([string toupper [HTTP::method]] eq "CONNECT") } {
        HTTP::proxy disable
    }
}

These iRules are offered as examples only.
