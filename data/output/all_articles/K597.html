Topic

For information about how to set the time and date in BIG-IP 9.x - 11.x, refer to K3381: Setting the time and date on the BIG-IP system.
 
The BIG-IP and 3-DNS Controller use the following two clocks to keep track of time:
 
  • Hardware clock

    The hardware clock tracks time even when the unit is unplugged and it is used only to initialize the operating system clock when the unit is booted. The hardware clock is configured to save the time in UTC (the GMT time zone).
  • Operating system clock

    The operating system clock is a software clock that is used when the system is running. This clock stores time in the local time zone that you configure when setting up the system.

You can set the time forward when the system is running. You cannot set the time back while the system is in multi-user mode, as this is a potential security risk. Additionally, you cannot set the time back on a 3-DNS unit that is part of a synchronization group until you remove the 3-DNS from the group, since any other controller in the group with a more advanced time will synchronize its time to the other members.

Setting the time forward

To set the time forward on a BIG-IP or 3-DNS Controller, type the following command from the command line:

Change the time, using the following command syntax:

date <year><month><day><hour><minute>.<second>

The specific format is as follows:

date YYYYMMDDHHMM.SS

For example, to set the time to noon on January 1, 2005, you would use the following command:

date 200501011200.00


Setting the time back

To set the time back, perform the following procedure specific to your configuration:

  • BIG-IP and 3-DNS Controllers that are not members of a synchronization group
  • 3-DNS Controller that is a member of a synchronization group

BIG-IP and 3-DNS Controllers that are not members of a synchronization group

Important: Do not perform this procedure on an evaluation version of the BIG-IP or 3-DNS Controller, because it will cause your license to expire and deactivate.

To set the time back on a BIG-IP or 3-DNS Controller that is not a member of a synchronization group, perform the following procedure:

  1. Reboot the controller and start it in single-user mode. For specific instructions, refer to the version-specific Solution:
    • For versions 4.0 through 4.6.4, refer to K2230: Booting BIG-IP or 3-DNS into single user mode.
    • For versions 3.0 through 4.0.1, refer to K1099: Booting the 3-DNS Controller into single user mode.
  2. Change the time, using the following command syntax:

    Important: You must enter the time in UTC format when the system is in single-user mode. Enter the current time in GMT, rather than your local time zone.

    date <year><month><day><hour><minute>.<second>

    The specific format is as follows:

    date YYYYMMDDHHMM.SS

    For example, to set the time to noon on January 1, 2005, you would type the following command:

    date 200501011200.00
  3. Reboot the system by typing the following command:

    reboot

    When the system reboots, it will use the new time.
     

3-DNS Controller that is a member of a synchronization group

Perform the following procedure on all 3-DNS Controllers in the synchronization group:

Important: Before setting the time backward on a 3-DNS Controller that participates in a 3-DNS sync group, it is important to make sure that all 3-DNS units are removed from the sync group. This is so that the sync group members do not attempt to update any of the other 3-DNS Controllers while the time is being adjusted.

  1. Log in to the Configuration utility.
  2. Click 3-DNS Sync.
  3. From the Synchronization page, click the Remove button next to each of the 3-DNS Controllers in the sync group, and click the OK button when prompted.
  4. Click Servers > 3-DNS, and remove all the 3-DNS server definitions to prevent iQuery messages between the 3-DNS units containing incorrect timestamps.

    Note    : F5 Networks recommends taking note of the 3-DNS servers configuration so that you can add them back later.
  5. Repeat Steps 1 through 4 for each 3-DNS Controller in the sync group.
  6. Verify the following check list for all 3-DNS sync group members:
    • All 3-DNS members have been removed from the sync group on each 3-DNS Controller.
    • All the 3-DNS server definitions have been removed on each 3-DNS system.
    • iQuery synchronization should now be disabled between the 3-DNS Controllers.
  7. Reboot the controller and start it in single-user mode. For specific instructions, refer to the version-specific Solution:
    • For versions 4.0 through 4.6.4, refer to K2230: Booting BIG-IP or 3-DNS into single user mode.
    • For versions 3.0 through 4.0.1, refer to K1099: Booting the 3-DNS Controller into single user mode
  8. Change the time, using the following command syntax:

    Important: You must enter the time in UTC format when the system is in single-user mode. Enter the current time in GMT, rather than your local time zone.

    date <year><month><day><hour><minute>.<second>

    The specific format is as follows:

    date YYYYMMDDHHMM.SS

    For example, to set the time to noon on January 1, 2005, you would type the following command:

    date 200501011200.00
  9. Reboot the controller by typing the following command:

    reboot

    When the system reboots, it will use the new time.
  10. Repeat Steps 7 through 9 for each system in the synchronization group.
  11. When you have changed the date on every system in the synchronization group, redefine the 3-DNS server definitions for each controller, and then recreate the sync group and add each 3-DNS unit as a sync group member.
