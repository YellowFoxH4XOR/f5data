Description

After upgrading BIG-IP LTM, iRules that use static variables for certificate issuer validation are not working as expected.

Affected virtual server is configured with the /Common/test-irule, that contains the below event:

when RULE_INIT {
set static::issuer "C=US, O=Example Company, CN=Example Company Test"
}

and during CLIENTSSL_CLIENTCERT event, the irule checks for match against provided issuer and statis issuer set in RULE_INIT.

Even if the cert details sent by the Client match the "issuer" value, the connection to the virtual server fails.

Environment

  • BIG-IP LTM
  • software upgrade
  • Multiple iRules using the RULE_INIT event to set static variables

Cause

The RULE_INIT event in iRules is global in scope on BIG-IP devices. Static variables defined in this context (such as static::issuer in the above example) are shared across all iRules on the system and reside in a common namespace. If multiple iRules define a static variable with the same name but assign different values, the previously set value can be overwritten — regardless of which iRule is being executed during a connection or transaction.

Following an upgrade or reboot, the order of initialization can change; thus, an unexpected value may be present in one or more iRules at runtime, resulting in mismatches during certificate validation logic.

Recommended Actions

Verify the configuration and depending on your needs:

option 1) Use unique names for static variables within each iRule’s RULE_INIT block (e.g., static::issuer_gp, static::issuer_test) to prevent collisions.

option 2) If several iRules must share the same value for a variable like issuer CN, ensure all use exactly the same value.
