K5113: BIG-IP version 9.x does not persist clients to the same node address when persisting across pools with different services

Known Issue

New behaviors associated with the following persistence profile attributes cause persisted connections to be sent to a pool member not in the virtual server's load balancing pool, and client connections not to be persisted to a pool member in the virtual server's load balancing pool. The new persistence profile attributes are as follows:

  • Match Across Pools (new in version 9.x)
  • Match Across Services (Persist Across Services in version 4.x)
  • Match Across Virtual Servers (Persist Across Virtual Servers in version 4.x)
Match Across Pools

BIG-IP 9.x introduces a new persistence profile attribute, Match Across Pools.

When the Match Across Pools attribute is enabled, the BIG-IP system will always persist a client connection to the pool member indicated by a matching persistence record for the client, even if the pool member in the persistence record is not a member of the current virtual server's load balancing pool. The connection will be sent to the IP address and Service (port) of the pool member in the persistence record.

The introduction of Match Across Pools, however, has resulted in a change of behavior for the Match Across Services and Match Across Virtual Servers profile attributes when Match Across Pools is disabled.

In BIG-IP version 4.x, when Persist Across Services or Persist Across Virtual Servers persistence attributes are enabled, BIG-IP will only use the IP address of the pool member when searching the current pool to match a pool member indicated by a matching persistence record. The existing persistence record is used, and the connection will be sent to the IP address and port of the pool member in the current pool.

BIG-IP version 9.0 through 9.1 has new behavior. When Match Across Services or Match Across Virtual Servers attributes of a persistence profile are enabled, the BIG-IP system will use both the IP address and port of the pool member when searching the current pool to match a pool member indicated by a matching persistence record. If the client connection has changed ports (Match Across Services), this will result in no match found. The connection is load balanced to a new pool member of the current pool, and a new persistence record is made. The connection is not persisted.

F5 Networks Product Development tracked this issue as CR52069 and CR52093 and it was fixed in BIG-IP versions 9.1.1 and version 9.2. For information about upgrading, refer to the BIG-IP LTM Release Notes

Workaround

If upgrading is not an immediate option, depending on your configuration it may be possible for you to work around this issue by enabling Match Across Pools, and disabling port translation for the relevant virtual servers affected by this issue. This will cause the BIG-IP system to send the server side connection to the virtual server service and disregard the pool member service.

Enabling Match Across Pools in the persistence profile

To enable the Match Across Pools attribute in the persistence profile from the Configuration utility, perform the following steps:

  1. From the Configuration utility, click Local Traffic.
  2. Click Profiles.
  3. Click the Persistence tab.
  4. Select the Profile to modify.

    The Profile Configuration screen displays.

  5. Check the Match Across Services and/or Match Across Virtual Servers boxes, as desired.
  6. Check the Match Across Pools box.
  7. Click Update.

Disabling port translation for the relevant virtual servers

Disabling port translation for the relevant virtual servers allows the server side connections to inherit the virtual server's service, regardless of the services the pool members are configured with in the selected load balancing pool.

To disable port translation for the relevant virtual servers, perform the following steps:

  1. From the Configuration utility, click Local Traffic.
  2. Click Virtual Servers.
  3. Select the desired Virtual Server.

    This will display the Virtual Server Configuration page.

  4. Select Advanced from the Configuration dropdown menu.
  5. Uncheck Port Translation.
  6. Click Update.
  7. Repeat this procedure for each of the relevant Virtual Servers.
