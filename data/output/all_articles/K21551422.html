Known Issue

The BIG-IP system may not propagate configuration changes to UNIX daemons during a reboot.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system reboots.
  • The system parses configuration changes or other configuration elements early in the boot process.

The system invokes the confpp script during the boot process to pass TMOS configuration information to the UNIX daemons.  If the BIG-IP system parses TMOS configuration elements or configuration changes early in the boot process, the information may not be properly distributed to UNIX daemons, resulting in unexpected behavior.  For example, the syslog-ng configuration may not be updated to include logging directives on the primary blade in a VIPRION chassis.

Impact

The system does not propagate the expected configuration settings to the UNIX daemons.  

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The syslog-ng configuration is not updated to reflect the selection of the primary blade in a VIPRION chassis.
  • UNIX configuration files are missing or are misconfigured following a system reboot.
  • The remote server section of the syslog-ng configuration file is missing following a system reboot.

Workaround

To work around this issue, you can trigger the confpp script to run and update the configuration files by modifying an appropriate database variable. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To modify the log.clusterd.level database variable from its default value of Notice, type the following command:

    modify /sys db log.clusterd.level value Informational

  3. To return the log.clusterd.level database variable to its default value, type the following command:

    modify /sys db log.clusterd.level reset-to-default

To avoid this issue, you can force the mcpd process to reload the configuration from the configuration file rather than from the binary database.  To do so, refer to the procedures listed in K13030: Forcing the mcpd process to reload the BIG-IP configuration.
