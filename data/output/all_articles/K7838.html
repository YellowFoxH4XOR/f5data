Known Issue

This is the result of a known issue. Each VLAN inherits the MAC address of its lowest-numbered member interface. However, when the interface is removed from the VLAN, the VLAN MAC address does not change. As a result, if the same interface is assigned to another VLAN, both VLANs may use the same MAC address.

Note: This behavior is benign if each VLAN is connected to a different Layer 2 (L2) network segment. However, if both VLANs are connected to the same L2 segment, ARP conflicts may arise and L2 flooding may occur on some L2 switches.

For example:

  • Create VLAN A and add interface X as a member (X is not a member of any other VLAN).
  • Remove interface x from VLAN A.
  • VLAN A retains the MAC address of interface X.
  • Add interface Y to VLAN A (Y is a not a member of any other VLAN).
  • VLAN A still retains the MAC address of interface X.
  • Create VLAN B and add interface X as a member.
  • VLANs A and B now both use the MAC address of interface X.

F5 Product Development is tracking this issue as CR75974 for the BIG-IP 9.3.x software branch. This issue does not affect the 9.4.x or 10.x software branches.

Workaround

If this behavior occurs, you can correct the VLAN MAC address assignment by rebooting the BIG-IP LTM.
