K40472403: Collecting relevant data to troubleshoot high CPU utilization

Description

If your BIG-IP system is experiencing unexplained high CPU utilization, collecting the correct data to determine the cause is essential.

Environment

  • You are using a BIG-IP system.
  • Graphs are showing high CPU utilization.
  • The dashboard is showing high CPU utilization.

Cause

Multiple potential causes.

Recommended Actions

Collect and analyze data from the top, tmsh, and tmctl output over a fixed period of high CPU utilization

Note: The following must be performed during a time of reported high CPU utilization.

  1. Log into the Advanced Shell (bash)
  2. Modify top output
    1. Run the top command.
    2. Press 1 to get multiple CPU info.
    3. Press f to add fields.
    4. Optional: Press j to add last processor used (SMP).
    5. Press p to add swap size.

      Output appears similar to the following:
      Current Fields:  AEHIOQTWKNMbcdfgJPlrsuvyzX  for window 1:Def
      Toggle fields via field letter, type any other key to return

      * A: PID        = Process Id
      * E: USER       = User Name
      * H: PR         = Priority
      * I: NI         = Nice value
      * O: VIRT       = Virtual Image (kb)
      * Q: RES        = Resident size (kb)
      * T: SHR        = Shared Mem size (kb)
      * W: S          = Process Status
      * K: %CPU       = CPU usage
      * N: %MEM       = Memory usage (RES)
      * M: TIME+      = CPU Time, hundredths
        b: PPID       = Parent Process Pid
        c: RUSER      = Real user name
        d: UID        = User Id
        f: GROUP      = Group Name
        g: TTY        = Controlling Tty
      * J: P          = Last used cpu (SMP)  <<<<<
      * P: SWAP       = Swapped size (kb)    <<<<<
        l: TIME       = CPU Time
        r: CODE       = Code size (kb)
        s: DATA       = Data+Stack size (kb)
        u: nFLT       = Page Fault count
        v: nDRT       = Dirty Pages count
        y: WCHAN      = Sleeping in Function
        z: Flags      = Task Flags <sched.h>
      * X: COMMAND    = Command name/line

    6. Press enter to go back.
    7. Press W (upper case) to permanently save these options.
    8. Press q to quit top.
  3. Copy and paste the following script into the advanced shell (bash) and press enter.

    Note: Due to the vast amount of information it is collecting as well as depending on the load of your BIG-IP system, this may take more than 30 minutes to complete. It will stop automatically when it completes the iterations stipulated in the MAXCOUNT variable.

    # Change these to your liking.
    # This configuration will run once per second configured in the DELAY variable
    # for 1800 iterations configured in MAXCOUNT variable (1800 seconds == 30 minutes)
    COUNT=0
    MAXCOUNT=1800
    DELAY=1
    FILENAME=/shared/tmp/$(echo $HOSTNAME).`date +"%Y.%m.%d.%H:%M:%S"`.topoutput.log
    touch ${FILENAME}
    echo "Output: ${FILENAME}"
    while [ ${COUNT} -le ${MAXCOUNT} ]
    do
      (
        date
        top -cbn 1
        tmsh -c "show sys tmm-info; show sys memory"
        bigtop -once
        tmctl -a
        echo "###################"
      ) >> ${FILENAME}
      (( COUNT++ ))
      sleep ${DELAY}
    done

  4. When complete, run the following command to unset local variables:

    unset COUNT MAXCOUNT DELAY

  5. The resulting file is dynamic and stored in /shared/tmp/$HOSTNAME...topoutput.log.
  6. Review the resulting file to determine the offending process.
  7. If you require further assistance, open a new Support Request with F5 Support.

Note: In general extra information as above is only needed in unusual cases or as requested by F5 Support on systems running TMOS 12.0 and later.  When enlisting the assistance of F5 Support, it is best to supply a qkview taken at a time when CPU utilization is high.  Even better is to supply two qkviews bracketing a period of high CPU, for example an hour or so apart.

Additional Information

Can we keep the script running when we close the SSH session?

Yes you can use a text editor such as vi to copy and paste the script code into a file in /shared/tmp and then execute the script in the background. For example if the script is named tshoot-high-cpu.bash, the command will look like the following (note the & at the end to run the command in the background): 

bash /shared/tmp/tshoot-high-cpu.bash &

You can exit the shell at this point. When you log in again, you can check if the process is running and get the process ID (pid) with top, ps, or pstree. If you need to cancel it before the loop ends, just kill the process with this syntax: 

kill -9 <pid>
