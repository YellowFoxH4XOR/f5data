Known Issue

The BIG-IP GTM and BIG-IP DNS systems do not provide the resources to create data groups using the Configuration utility or Traffic Management Shell (tmsh) command.

This issue occurs when all of the following conditions are met:

  • The BIG-IP GTM or BIG-IP DNSsystem is licensed and provisioned with BIG-IP GTM only.
  • You attempt to author a BIG-IP GTM iRule that references a data group.

Impact

Users may not be able to create data groups on a BIG-IP GTM or BIG-IP DNS standalone system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility does not contain a menu that allows you to create data groups.
  • The Traffic Management Shell (tmsh) utility does not provide the resources to create data groups under the BIG-IP GTM context.

Workaround

To work around this issue, you can create a data group under the BIG-IP LTM context in the tmsh utility and reference it in a BIG-IP GTM iRule. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Create a data group under the BIG-IP LTM context by using the following command syntax:

    create ltm data-group <external|internal> <datagroup name> type <integer|ip|string> <external-file-name <path/to/external/file> | records add { <record name> { data <value> } }>

    For example, to create an internal data group dg-391879 with IP address 20.20.20.156, you would type the following command:

    create ltm data-group internal dg-391879 type ip records add { 20.20.20.156 { data 20.20.20.156 } }

  3. Verify that the data group has been created by using the following command syntax:

    list ltm data-group <external|internal> <datagroup name>

    Using the example in step 2, the command list ltm data-group internal dg-391879 returns command output that appears similar to the following example:

    ltm data-group internal dg-391879 {
    records {
    20.20.20.156/32 {
    data 20.20.20.156
    }
    }
    type ip
    }

  4. Reference the data group in the BIG-IP GTM iRule.

    For example:

    gtm rule rule-391879 {
    when DNS_REQUEST {
    set LDNS [IP::client_addr]
    set myNet [class match -value $LDNS equals "/Common/dg-391879" ]
    log -noname local0. "$LDNS matches myNet: $myNet"
    }
    }

  5. Save the change by typing the following command:

    save sys config
