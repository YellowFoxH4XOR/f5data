Description

The root directory (/) is 100% full on the DCD.

In /var/log/ltm, a lot of these logs can be seen:

Jan 09 03:31:02 bigiq1.example.com err diskmonitor[18912]: 011d0004:3: Disk partition / has only 0% free

 

Running the df -h command, you observe that / is 100% used.

Running the find / -xdev -type f | xargs du | sort -rn | head -20 command to list down the top 20 largest files in the / directory doesn't really help, as the output returned contains system files, which shouldn't be deleted.

However, a manual check of the /tmp directory will show many 'small-sized' hs_err_pidxxxx.log files (about 27KB each) that are present in that directory, which otherwise shouldn't be there.

Environment

  • BIG-IQ DCD

Cause

There are too many hs_err_pidxxxx.log files in the /tmp directory. These files get created when the Java process crashes. As it exits, those files are left behind.

There are times when a Java core dump in /var/core is also created when the Java process crashes

 

Note: it is completely safe to delete these log files. They do not impact the system's performance.

 

Recommended Actions

To free up disk space on the DCD, either move those files to a different directory (other than /tmp) OR delete them. You can use this command to delete those files:

 

# rm -rf /tmp/hs_err_pid*
