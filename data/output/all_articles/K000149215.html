Description

This article describes how to implement longer timeframe request limits (hourly/daily), when NGINX Plus native rate-limiting functionality only supports shorter timeframes (requests per second or minute).

Environment

NGINX Plus or NGINX Open Source

Cause

The "limit_req" module in NGINX is designed for short-term rate limiting and does not natively support long-range intervals. Its algorithm is not optimized for such use cases.

Recommended Actions

There are several ways to approach this:

  1. Use NGINX JavaScript (njs) or Lua scripts to implement custom rate-limiting logic implementing a fixed window rate-limiting mechanism as a starting point. The implementation is not suitable for clustered environments or for persisting rate limits across NGINX restarts.
  2. For persistence in clustered setups, use the "keyval" module instead of "js_shared_dict".
  3. For clustered environments or more complex requirements, we recommend reaching out to NGINX Professional Services. They can assist with designing and implementing a tailored solution.
  4. If possible, implement business-specific rate limiting at the application layer instead of within NGINX. This approach may offer more flexibility and control.
