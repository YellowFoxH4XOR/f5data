Known Issue

An iRule with a suspending command may cause TMM to produce a core file.

This issue occurs when all of the following conditions are met:

  • The configuration contains an iRule event with a suspending command. For example, the after command is a suspending command.
  • The affected iRule contains CLIENT_CLOSED or SERVER_CLOSED events.
  • The BIG-IP system with an iRule-suspended TCP connection receives a TCP RST packet from the remote peer.

Impact

The BIG-IP system may temporarily fail to process traffic while TMM restarts. If the system is configured as part of a high-availability system, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • F5 iHealth lists Heuristic H456689 on the Diagnostics > Identified > Medium|High screen.
  • The BIG-IP system fails over to another system in the device group.
  • The BIG-IP system fails over to the peer system in a high-availability configuration.
  • The TMM process produces a core file with a SIGFPE.
  • The BIG-IP system generates a TMM core file in the /var/core directory.
  • The BIG-IP system logs an error message to the /var/log/tmm file. The error message appears similar to the following example:

    notice panic: freed invalid pcb magic
    notice ** SIGFPE **

Workaround

There is no workaround for this issue. To mitigate the issue, avoid using the CLIENT_CLOSED or SERVER_CLOSED events on an iRule-suspended TCP connection.
