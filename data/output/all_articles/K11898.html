Topic

Overview

F5 Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration. To help gather all of the required information, use the following guidelines to prepare for opening a case:

  • General information
  • Product-specific information
    • QKView files
    • Log files
    • Access profiles
    • Packet traces
  • Client-specific information
    • Microsoft Windows systems
    • Apple Mac OS X systems
    • Linux systems
    • Windows Mobile devices
    • Apple iOS devices
    • Android devices
    • Chrome OS systems

General information

Provide the following information when you open a case with F5 Support:

  • A full description of the issue, including the following details:
    • Symptoms of the issue.
    • The approximate time the issue first occurred.
    • The number of times the issue recurred.
    • Any error output the system provides.
    • Steps to reproduce the issue.
    • Any changes you made to the system before the issue first occurred.
    • Any steps you took to solve the issue.
    • A brief network description for the involved machines, including which equipment is traversed between the client, the BIG-IP device, and any other destinations that may be involved.
    • Screenshots of any error messages, client configurations, and BIG-IP APM configurations, including the access policy, back-end server configuration, and a working example of connecting directly to the back-end server.
  • A description of the impact the issue is having on your site, using the following definitions:
    • Site Down

      All network traffic has ceased, causing a critical impact to your business.

    • Site at Risk

      The primary unit failed, resulting in no redundancy. The site is at-risk of going down.

    • Performance Degraded

      Network traffic is partially functional, and, as a result, you can't reach some applications.

    • General Assistance

      Questions you have regarding configurations, troubleshooting non-critical issues, or requests for product functionality that are not part of your current product feature set.

  • The hours that you are available to work on the issue and any alternative contacts who can work on the issue if you are not available.
  • Remote access information, if possible.

    Remote access to your network environment is important because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Support can work directly with you to resolve the issue over the phone. However, this method can often be more time consuming and require file transfers, replication, and additional testing.

Product-specific information

Collect the following information from the affected systems and provide it when you open the case:

  • QKView files
  • Log files
  • Access profiles
  • Packet traces
     

QKView files

A QKView contains the configuration files that F5 Support most frequently needs when troubleshooting an issue. The system encrypts sensitive information, such as passwords and shared secrets, so that you can send the file over unsecured channels. You can provide the QKView diagnostic file to F5 Support by uploading it to the F5 iHealth website. iHealth allows you to quickly diagnose the health and proper operation of your BIG-IP system.

For more information about QKView, refer to the following articles:

Note: F5 Support may request a QKView with no file size limit. To generate a QKView with no file size limit, use the qkview -s0 command, as explained in the following article:

  • K12878: Generating BIG-IP diagnostic data using the qkview utility

Log files

For information about configuring log levels, refer to the Logging and Reporting chapter of the Configuration Guide for BIG-IP Access Policy Manager.

Notes:

  • For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.
  • Beginning in BIG-IP 10.0.0, the qkview utility automatically gathers up to 5 megabytes (MB) of log files and includes them with QKView in a TAR output.

The QKView file contains the log files for the last day. If the issue exists for more than a day, or if the log file is too large, provide all the log files on the system by performing the following procedure:

  1. Log in to the command line.
  2. Create a .tar archive named logfiles.tar.gz in the /var/tmp directory that contains all the files in the /var/log directory by typing the following command:

    tar -czpf /var/tmp/logfiles.tar.gz /var/log/*

Access profiles

You should also provide BIG-IP APM access profiles to F5 Support when troubleshooting BIG-IP APM issues. Exported access profiles are saved as files with the .conf extension.

To export an access policy, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to the Access Profiles page for your version:
    • For BIG-IP 13.x and later, navigate to Access > Profiles/Policies.
    • For BIG-IP 12.x and earlier, navigate to Access Policy > Access Profiles.
  3. Click the Export link for the profile you want to export.
  4. Specify a location and save the file.
  5. Repeat steps 3 and 4 for each profile you want to export.

For more information, refer to the Creating Access Profiles and Access Policies chapter of the Configuration Guide for BIG-IP Access Policy Manager.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Packet traces

If the issue involves the network, perform a packet trace while the issue is occurring, and provide the packet trace when you open the case. A packet trace is particularly helpful for troubleshooting authentication issues when you capture traffic between the BIG-IP device and the authentication server.

For more information about performing packet traces with tcpdump and ssldump, refer to K4714: Performing a packet trace and providing the results to F5 Support and K10209: Overview of packet tracing with the ssldump utility.

Client-specific information

When the issue is specific to a particular client, you need the following information:

  • Operating system, version, and patch level
  • Browser type and version
  • SSL VPN client log file information
    For more information on obtaining client specific information refer to: K00819308: 

To collect the SSL VPN client log file, perform the procedure specific to your operating system:

  • Microsoft Windows systems 
  • Apple OS X systems
  • Linux systems
  • Windows Mobile devices
  • Apple iOS devices
  • Android devices
  • Chrome OS systems

Microsoft Windows systems

To collect the necessary files on a Microsoft Windows system, perform one of the following procedures:

Client Troubleshooting Utility

  1. Download and run the Client Troubleshooting Utility. For more information, refer to K12444: Overview of the Client Troubleshooting Utility for Windows.
  2. Click File.
  3. Click Generate Report.
  4. Click the Text option.
  5. Click Save As.
  6. Enter a path and file name where you want to save the report.
  7. Click Save.
  8. When the report completes, click Cancel.
  9. Provide a copy of the generated report to F5 Support through My Support.

    Note: An active support contract is required to contact F5 Support.
    Note: When using the BIG-IP Edge Client for Microsoft Windows, you can obtain a diagnostic report from the BIG-IP Edge Client.
    Open BIG-IP Edge Client, click View Details, click Diagnostic Report, select the download location on your local device, and click Save.
    Important: When using browser based access use the Client Troubleshooting Utility to gather diagnostic and log information.

Copying the log files from the client system

If you cannot run the Client Troubleshooting Utility, collect the log files by performing the following procedure:
Important: F5 recommends using the Client Troubleshooting Utility (CTU) to gather diagnostic information. The CTU takes into account unique installation and configuration parameters and paths that cannot be anticipated for all deployments when manually gathering these details.  

  1. From the client machine, click Start.
  2. Click Run.
  3. Enter %temp% in the Open: field.
  4. Click OK.
  5. Copy all files that start with characters f5.

    For example:

    f5dskctl.txt, f5InspectionUser.txt, f5Install.txt

  6. Copy the logterminal.txt file.
  7. Provide a copy of files to F5 Support .
Windows 10 using the F5 Access client

You can enable logging for the F5 Access client on Windows 10 through the Event Viewer by performing the following procedure:

  1. From the client machine, click Start.
  2. Enter Event Viewer and press Enter.
  3. Navigate to the following directories:

    Event Viewer (Local) > Applications and Services Logs > Microsoft . Windows > Vpn Plugin Platform > Operational
    Event Viewer (Local) > Applications and Services Logs > Microsoft . Windows > Vpn Plugin Platform > OperationalVerbose

  4. Right-click on Value and select Properties.
  5. Select the Enable Logging check box.
  6. Click OK.

Apple Mac OS X systems

To collect the SSL VPN client log file for Mac OS X systems, perform the following procedure:

  1. Log in to the command line.
  2. To navigate to the ~/Library/Logs/F5Networks directory, type the following command:

    cd ~/Library/Logs/F5Networks

    Note: Older versions of the Apple MAC OS X client save log files in the following directory:

    /Library/Internet Plug-Ins/f5_sslvpn.bundle/var/log/

  3. To view the svpn.err file, type the following command:

    more svpn.err

  4. Cut all of the information and paste it into your email or case notes.
  5. Gather Network Access debugging information. For more information, refer to K12321: Enabling Network Access debugging for Mac OS X and Linux.

Linux systems

To collect the SSL VPN client log file for Linux systems, perform the following procedure:

  1. Log in to the command line.
  2. To navigate to the /usr/local/lib/F5Networks/SSLVPN/var/log/ directory, type the following command:

    cd /usr/local/lib/F5Networks/SSLVPN/var/log/

  3. To view the svpn.ERR log, type the following command:

    more svpn.ERR

  4. Cut all of the information and paste it into your email or case notes.
  5. Gather Network Access debugging information. For more information, refer to K12321: Enabling Network Access debugging for Mac OS X and Linux.

Windows Mobile devices

On Windows Mobile devices, the SSL VPN client log files reside in the following locations:

  • \Temp\f5SSLVPNlog.txt
  • \Temp\comdriverlog.txt
  • Cut all of the information from these log files and paste it into your email or case notes.

Apple iOS devices

On Apple iOS devices, using the F5 Access Client App or the BIG-IP Edge Client app, you can email the client files to your own email address. To do so, perform one of the following procedures:

Note: You must have an email account on your Apple iOS device to perform these procedures.

F5 Access Client App

  1. On the Apple iOS device, open the F5 Access Client app.
  2. Select the Settings icon.
  3. Select Support.
  4. Select Email Logs.

    An email window displays and attaches the F5AccessReport.zip file.

  5. In the To field, enter the email address that you want to send the logs.
  6. Select Send.

    After you receive the email, you can then attach the files to your F5 Support case using My Support.

    Note: You must have an active support contract with F5 to open a support case.

Android devices

On Android devices, using the F5 Access Client app or the BIG-IP Edge Client app, you can email the client files to your own email address. To do so, perform one of the following procedures:

Note: You must have an email account on your Android device to perform these procedures.

F5 Access Client App

  1. On the Android device, open the F5 Access Client app.
  2. Select the Settings icon.
  3. Select Diagnostics.
  4. Select the Bug icon in the upper right corner.

    A Collecting Data message displays temporarily while the F5 Access logs are collected into an F5AccessReport.zip file.

    A Send log screen presents a list of apps available on your device that you can use to transfer the file.

  5. Select the email app.

    An email window displays with the F5AccessReport.zip file attached.

  6. In the To field, enter the email address to which you want to send the logs.
  7. Select Send.

    After you receive the email, you can attach the files to your F5 Support case using My Support.

    Note: You must have an active support contract with F5 to open a support case.

Chrome OS systems

To collect the diagnostic files on a Chrome OS system, perform the following procedure:

  1. On the Chrome OS system, open the F5 Access app.
  2. Click the Diagnostics tab.
  3. To save the diagnostic information into an archive (.zip) file, click the download icon at the top-right of the screen.

    A download window displays with an auto-generated filename in the following format:

    f5access.YYYY-MM-DD_HH-MM-SS.zip

    For example:

    f5access.2017-03-29_23-59-59.zip

  4. Click Save.

    An email window displays.

  5. To select the diagnostic archive file and attach it to the email, in the lower left of the screen, click the File Attachment icon.
  6. In the To field, enter the email address to which you want to send the diagnostic archive file.
  7. Click Send.
