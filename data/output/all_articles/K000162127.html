Description

False SNMP alerts for a virtual server (VIP) reported as "down" were generated by SolarWinds monitoring, despite the VIP's pool members having been persistently offline for an extended period.

Environment

  • BIG-IP Advanced WAF
  • SNMP monitoring  
  • Affected virtual server configured with a TCP monitor and a pool containing two members, both persistently offline

Cause

The root cause was a combination of mcpd database connection drops and a known admd memory leak (Bug 2347029), which led to temporary loss of monitor state and false SNMP trap generation. When mcpd lost and regained its database connection, it misinterpreted queued monitor results, resulting in false down/up transitions for pool members and triggering SNMP alerts, even though the members' actual state had not changed. It sees monitor results arriving without a corresponding "was up" record, so it treats them as transitions from unknown/down → up or up → down.

Answer/Recommended Actions

  • Apply the ' bigstart restart admd cron ' workaround as recommended for Bug 2347029 to mitigate admd memory leak and prevent mcpd stress events.
  • Review and update the SNMP allowed addresses list to ensure legitimate monitoring systems are not refused.
  • Monitor for further occurrences and confirm that the workaround prevents future false alerts.
  • Coordinate with SolarWinds administrators to verify alert logic and ensure it aligns with the actual BIG-IP state.

Additional Information

  • The admd or Anomaly Detection Module Daemon is responsible for DoS profile functionality. Its memory leak can lead to OOM events and process restarts, which are not expected behavior.
