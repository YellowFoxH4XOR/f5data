Topic

Important: A known issue exists regarding installation of 10.2.0 HF2 on a partitioned system with 10.2.0 HF1 installed. For more information, refer to K12618: Installing 10.2.0 HF2 on a partitioned system with HF1 installed may make the 10.2.0 partition unable to boot.

This article describes the procedures for installing a BIG-IP 10.1.x or 10.2.x hotfix on a BIG-IP system that uses the partitions disk formatting scheme. You cannot use the Configuration utility to install a BIG-IP 10.x hotfix on a system using partitions. Instead, perform one of the following command line procedures to install the hotfix:

  • Installing a 10.1.x or 10.2.x hotfix on a partitioned system when all other partitions are running 9.x
  • Installing a 10.1.x or 10.2.x hotfix on a partitioned system when another partition is running 10.x

Note: To determine whether the BIG-IP system is using the partitions disk formatting scheme, refer to K10817: Determining the disk-formatting scheme used by a BIG-IP version 10.x system. A BIG-IP system that hosts both 10.x and 9.x boot images must use a partitioned disk-formatting scheme.

Important: Before following the procedures detailed in this article, you should review the information in K10025: Managing BIG-IP product hotfixes (10.x).

Note: For information about installing a 10.0.x hotfix, or installing a hotfix on a 10.x system using the logical volume management (LVM) disk formatting scheme, refer to the appropriate article from the Installing a hotfix section in K10025: Managing BIG-IP product hotfixes (10.x).

Note: If you are installing a BIG-IP 10.1.x hotfix from a 10.0.0 partition, you may need to re-install the BIG-IP software on the partition from which you plan to perform the hotfix installation. For more information, refer to K10063: BIG-IP 10.0.0 hotfix installations do not apply a configuration or license to the target installation location.

Note: For information about managing BIG-IP 9.x hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).

Important: F5 recommends that you install hotfixes using the serial console or an SSH connection to the management port IP address.

Installing a 10.1.x or 10.2.x hotfix on a partitioned system when all other partitions are running 9.x

  1. Log in to the command line.
  2. Download the 10.1.x or 10.2.0 hotfix ISO and MD5 files to the /shared/images/ directory.

    Note: BIG-IP 10.x installation files are ISO archive files and use the .iso file extension.

  3. Verify the MD5 checksum for the hotfix.

    Note: For information about verifying the MD5 checksum for BIG-IP installation files, refer to K8337: Verifying the MD5 checksum for the downloaded F5 software file .

  4. Determine the partition on which the image you wish to upgrade is installed by typing the following command:

    switchboot -l

    For example, the following switchboot -l command output indicates that the 10.1.0 installation resides on the HD1.1 partition:

    Current boot image:
        HD1.1 - title BIG-IP 10.1.0 Build 3341.0
    Default boot image:
        HD1.1 - title BIG-IP 10.1.0 Build 3341.0
    Available boot image(s):
        HD1.1 - title BIG-IP 10.1.0 Build 3341.0
        HD1.2 - title BIG-IP 9.4.8 Build 355.0

  5. Determine the device name that hosts the /shared directory by typing the following command:

    df -h

    For example, the following df -h command output indicates that the device named hdc1 hosts the /shared directory:

    Filesystem            Size  Used Avail Use% Mounted on
    /dev/hdc10            2.9G  194M  2.6G   7% /
    /dev/hdc12            2.9G   69M  2.7G   3% /config
    /dev/hdc14            2.9G  992M  1.8G  36% /usr
    /dev/hdc13             18G  2.3G   15G  14% /var
    /dev/hdc1              15G   11G  3.8G  74% /shared
    /shared/.LoopbackLogFS
                          6.6G   73M  6.2G   2% /var/log
    none                 1007M  408K 1006M   1% /dev/shm
    none                 1007M  6.5M 1000M   1% /var/tmstat
    none                 1007M  1.1M 1006M   1% /var/run
    prompt                4.0M   12K  4.0M   1% /var/prompt

  6. Connect a terminal to the BIG-IP serial console, and log in as root.

    Note: Alternatively, you may SSH to the SCCP or AOM subsystem, and from there connect to the Host console. For more information, refer to K3454: Overview of the SCCP or K9403: Overview of the AOM subsystem.

  7. Reboot into MOS by typing the following command:

    mosreboot

    Important: Due to a known issue, if BIG-IP 9.x was installed after 10.x, executing the mosreboot command will return the following error:

    error: boot entry st.mos does not exist

    For more information, refer to K11774: The GRUB entry for MOS is removed during an installation of BIG-IP 9.x.

  8. When you are prompted to enter the terminal type, press the Enter key.
  9. Create the temporary /hotfix directory by typing the following command:

    mkdir /hotfix

  10. Mount the device hosting the /shared directory determined in Step 5 to the /hotfix directory by typing a command similar to the following:

    mount /dev/hdc1 /hotfix

    Note: Replace hdc1 with the name of the device hosting the /shared directory.

  11. Copy the hotfix installation image to /tmp by typing a command similar to the following:

    cp /hotfix/images/Hotfix-BIGIP-10.1.0-3372.0-HF1.iso /tmp

    Note: Replace Hotfix-BIGIP-10.1.0-3372.0-HF1.iso with the name of the hotfix .iso file.

  12. Unmount the device hosting the /shared directory by typing the following commands:

    cd /
    umount /hotfix

  13. Change directories to the /tmp directory by running the following command:

    cd /tmp

  14. Install the 10.1.x or 10.2.x hotfix by using the following command syntax:

    image2disk --hotfix --nosaveconfig --instslot=<version_10.x_slot> <HF.iso>

    For example, if you are installing 10.1.0 HF-1 to the HD1.1 partition, you would type the following command:

    image2disk --hotfix --nosaveconfig --instslot=HD1.1 Hotfix-BIGIP-10.1.0-3372.0-HF1.iso

  15. Reboot the system by typing the following command:

    full_box_reboot

    Note: The system reboots to the boot location that was active at the beginning of this procedure.

Installing a 10.1.x or 10.2.x hotfix on a partitioned system when another partition is running 10.x

Important: Do not use the image2disk utility to install the hotfix. Doing so results in an error message that appear similar to the following example:

Terminal error: SVM (Software Volume Management) is available, and this is not a format request.
Please use SVM, or include '--force' if you are sure you want to proceed.

If you receive the previous error, do not use the image2disk utility with the --force option; it will render your system non-functional. Instead, use the bigpipe software command to install the hotfix as described below.

  1. Log in to the command line.
  2. Determine the 10.x partition from which you will run the hotfix installation, and the 10.1.x or 10.2.x partition on which the hotfix will be installed.

    Note: When installing a 10.x hotfix on a partitioned system, you must run the hotfix installation from a partition other than the target partition.

    To determine the partition on which each installation resides, type the following command:

    switchboot -l

    For example, the following switchboot -l command output indicates that a 10.1.0 installation resides on the HD1.1 partition, and a 10.0.1 installation resides on the HD1.2 partition:

    Current boot image:
        HD1.1 - title BIG-IP 10.1.0 Build 3341.0
    Default boot image:
        HD1.1 - title BIG-IP 10.1.0 Build 3341.0
    Available boot image(s):
        HD1.1 - title BIG-IP 10.1.0 Build 3341.0
        HD1.2 - title BIG-IP 10.0.1 Build 354.0

  3. Set the default boot image to a location other than that on which the hotfix will be installed, using the following command syntax:

    switchboot -b <location>

    For example, to set the default boot image location to the 10.0.1 partition in the previous example, type the following command:

    switchboot -b HD1.2

  4. Reboot the system to the installation location by typing the following command:

    reboot

  5. After the system boots, log in to the command line.
  6. Change directories to the /shared/images/ directory by typing the following command:

    cd /shared/images/

    Note: If the /shared/images/directory does not exist, you must create it by using the mkdir /shared/images/ command.

  7. Download the hotfix ISO and MD5 files to the /shared/images/ directory.

    Note: BIG-IP 10.x installation files are ISO archive files and use the .iso file extension.

  8. Verify the MD5 checksum for the hotfix.

    Note: For information about verifying the MD5 checksum for BIG-IP installation files, refer to K8337: Verifying the MD5 checksum for BIG-IP installation files.

  9. Use the bigpipe software command to install the hotfix image using the following syntax:

    bigpipe software desired <partition> product BIG-IP version <version_number> build <build_number>

    Note: The software version and the build number can be found in the ISO file name. For example, the Hotfix-BIGIP-10.1.0-3372.0-HF1.iso file contains BIG-IP 10.1.0, Build 3372.0.

    For example, to install BIG-IP 10.1.0 HF-1 on the HD1.1 partition, type the following command:

    bigpipe software desired HD1.1 product BIG-IP version 10.1.0 build 3372.0

  10. To monitor the status of the hotfix installation from the command line, type the following command:

    watch bigpipe software status show

    The following sample command output from the bigpipe software status show command indicates that the installation status is 27.62 percent complete:

    SOFTWARE - Status:
    +-> SOFTWARE STATUS
    |   Key   Slot Product Version Build  Active Status
    |   HD1.1    0 BIG-IP  10.1.0  3372.0 no     installing 27.620 pct
    |   HD1.2    0 BIG-IP  10.0.1   354.0 yes    complete

    Note:  If you see the status 'waiting for image' , refer to K12126: When attempting to install a hotfix, the BIG-IP system may report a misleading message.

  11. After the hotfix installation has completed, set the default boot image to the hotfixed 10.1.x or 10.2.x installation location using the following command syntax:

    switchboot -b <10.1.x_location>

  12. Reboot the system to the hotfixed 10.1.x or 10.2.x installation by typing the following command:

    full_box_reboot
