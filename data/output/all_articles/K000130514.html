K000130514: Device configuration is not loading after increasing the resources like CPU and RAM from hypervisor.

Description

Configuration load fails with the error "No user configuration is found"

  • All services stopped working
  • Failed access through TMUI (Graphical User interface)
  • In /var/log following errors are observed
  • 01420006:3: No user configuration is found. Loading process is aborted.
  • /usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- Unexpected Error: No user configuration is found. Loading process is aborted.
  • 01070422:3: Base configuration load failed.
  • While validating configuration you may observe following output
  • tmsh load sys config verify
  • Validating system configuration...
  • <..snip..>
  • Validating configuration...
  • Unexpected Error: No user configuration is found. Validating process is aborted
 

Environment

  • None of the following files does exists or their size are 0 bytes
  • /config/bigip_base.conf
  • /config/bigip_user.conf
  • /config/bigip.conf
 

Cause

Either of the reasons below might cause the issue

  • Defective file system or damaged hard drive
  • Files were deleted or modified
  • Files might get corrupted after increasing resources to BIG-VE from the hypervisor.
 

Recommended Actions

Step 1:

# cp /config/bigip_base.conf.bak /config/bigip_base.conf

# cp /config/bigip_user.conf.bak /config/bigip_user.conf

# cp /config/bigip.conf.bak /config/bigip.conf

Step 2: Refer the following article to force mcpd reload configuration K13030: Forcing the mcpd process to reload the BIG-IP configuration 

Step 3: Once the device comes up online, reactive the device license.
