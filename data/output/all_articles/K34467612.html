Topic

This article discusses the BIG-IP Edge Client autoconnect's location awareness.

Description

The BIG-IP Edge Client autoconnect provides location awareness. To learn how to enable or disable location awareness, refer to K40314933: Enabling or disabling autoconnect in the BIG-IP Edge Client on Windows. When autoconnect is enabled, an Auto-Connect button displays on the BIG-IP Edge Client. When you select Auto-Connect, location awareness determines when you are outside of the corporate network and automatically connects to a VPN. In this way, with a corporate laptop, you can move from a corporate office with a secured wireless or wired network connection to an offsite location with a public wireless network connection and maintain a seamless connection to allowed corporate resources.

Location detection mechanism

As a BIG-IP APM administrator, you can specify the networks that are considered in-network by adding DNS suffixes to the connectivity profile on the BIG-IP APM. For example, you can specify in.example.com and internal.com as DNS suffixes for your corporate network.

The sequence in which BIG-IP Edge Client detects network locations is as follows:

  1. It compares the DNS suffix list on adapters with the configured network location. To detect if the device is connected to corporate, we match the DNS suffix present in the regkey to the one present on the network adapter.

    You should set up the connection DNS suffix of the client device using Dynamic Host Configuration Protocol (DHCP) when the network adaptor obtains its IP address as it connects to the corporate network. For example, on a Windows client device, after successful connection to the corporate network you can view the Connection-specific DNS Suffix value by typing the ipconfig command. Output appears similar to the following:

    Windows IP Configuration
    Ethernet adapter OfficeNet:
       Connection-specific DNS Suffix  . : in.example.com
       Link-local IPv6 Address . . . . . : fe80::74b0:cb17:9bb:78d8%17
       IPv4 Address. . . . . . . . . . . : 192.0.0.2

    Only if the DNS suffix does not match, the BIG-IP Edge Client performs the next two checks.

    Note: Checking the domain controller or resolving the DNS name is only performed if the VPN is not already connected.

  2. It resolves the DNS name of the Active Directory server for the domain by sending SRV request for _ldap._tcp.dc._msdcs.<suffix>. 

Note: During a network switch, such as changing WiFi connections, BIG-IP Edge Client's network location awareness must detect whether the new connection is local or remote. During this brief time period, as it switches networks, BIG-IP Edge Client does not block certain external websites and can be reached.

The BIG-IP Edge Client re-evaluates the current location each time the IP address table is changed. Any of the following can cause this change:

  • Connecting or disconnecting an Ethernet cable
  • Connecting or disconnecting a wireless link
  • Removing or inserting a network adapter
  • Disabling or enabling a network interface
  • Modifying the IP address of a network interface, using DHCP or manually
  • Resuming the system after suspension or hibernation

When a network event such as the previously listed ones occurs, the BIG-IP Edge Client waits around 10 seconds for the connection to settle down (IP address assignment, DNS server assignment, verify domain assignment, and so on) before using the network location awareness feature to detect its location.

Logging

Network location awareness events are logged for troubleshooting. Logs are located in the %TEMP%\logterminal.txt file in Windows and in the ~Library/Logs/F5Networks/edge.log in Mac OS X.

For example, Windows logs describe the following sequence of events, in which you previously configure in.example.com and internal.com as the DNS suffix of the corporate network:

  1. Auto-Connect is selected.
  2. Network location awareness test starts.
  3. The BIG-IP Edge Client tries and fails to match the connection-specific DNS Suffix in.example.com.
  4. The DNS resolution of the active directory name in.example.com test starts but fails.
  5. You also configured internal.com DNS suffix in the connectivity profile. The same tests are performed.
  6. The DNS resolution for internal.com passes and the location is determined to be within the local network.
  7. VPN stays disconnected.

Recommendations

When planning network location awareness, consider that autoconnect with network location awareness is not a security feature intended to enforce VPN connectivity. The DNS suffix on a client device can be manually configured, and you can select Connect or Disconnect to connect or disconnect from the VPN, regardless of the network location.
