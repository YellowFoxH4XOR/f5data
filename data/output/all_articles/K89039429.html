Description

After a successful TCP handshake, Virtual Server doesn't respond to Client Hello in SSL/TLS handshake from client and eventually times out with TCP FIN.
TLS connection to virtual server fails for approximately 5 seconds and recovers without any intervention until the next configuration change occurs and causes TMM to start up another 5-second timer.

As a result of this issue, you may encounter one or more of the following symptoms:

  • Once the SSL profile is updated, TLS connection to respective Virtual Server fails for few seconds.
  • BIG-IP system logs below message in /var/log/ltm :

    01260009:4: Connection error: hud_ssl_handler:910: invalid profile (40)

Environment

  • BIG-IP 13.1.x version
  • Modifying SSL profiles which are in use by Virtual Server.
  • Clicking on 'update' button even without making any changes on SSL profile.
  • A full config sync is configured in HA.

Cause

Bug ID 758904: After full config sync or modifications to SSL profiles, new SSL/TLS handshakes will fail for at least 5 seconds

Recommended Actions

  1. Create a new SSL profile that has same configuration as a SSL profile currently in use (i.e., create a copy of the currently used SSL profile).
  2. Modify any parameters on the new SSL profile as you like.
  3. Assign the new SSL profile to the Virtual Server, and remove the old one.
  4. Once the new SSL profile is successfully attached to the Virtual Server, you may want to the delete old SSL profile.
It is also recommended to upgrade to 14.x or later versions to fix it.
