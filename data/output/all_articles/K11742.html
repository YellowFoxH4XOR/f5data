Topic

Some HTML pages contain the deprecated refresh meta tag. For example:

<META http-equiv="refresh" content="5;http://www.example.com/redirected.html">

The presence of this tag causes the browser to re-validate all content on the target page specified in the content tag. This tag will override Intelligent Browser Referencing (IBR) and any Minimum Age setting configured in the Lifetime >> Client Cache settings, as well as any cache control directives which would otherwise prevent the objects from being prematurely re-requested. As a result, when the target page is refreshed, the OWS may respond with multiple 304 Not Modified responses, one for each object on the target page.

Note: The HTTP meta refresh tag is a deprecated method of redirecting browsers to alternate or updated content once they have retrieved the originally requested page. For more information, refer to the following link, which will take you to a resource outside of AskF5. It is possible that the document may be removed without our knowledge:

W3C specification.

For optimal performance, F5 Networks recommends eliminating the refresh tags from HTML pages for which you want to configure IBR or the Minimum Age validation parameter. Replace HTTP_Refresh With HTTP Redirect

Note: In version 9.4.x, the HTTP_REQUEST_DATA event fires after the pvac process performs compression. As a result, if compression is required in these versions, the BIG-IP LTM must perform the compression, rather than the BIG-IP WebAccelerator. You can offload compression to the BIG-IP LTM by disabling compression in the BIG-IP WebAccelerator policy and enabling it in the appropriate HTTP profile.

Beginning in version 10.0.0, the HTTP_RESPONSE_DATA event fires before pvac processing and compression can still be performed by the BIG-IP WebAccelerator.

F5 Networks is tracking a request as CR99807 to include this iRule functionality in the BIG-IP WebAccelerator.
