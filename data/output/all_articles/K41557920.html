Description

Virtual server has LTM policy configured with first match, and there are multiple set of action and conditions.

If a condition is matches, cookie persistence is enabled and forward to a specific pool which has multiple pool members

First time HTTP request went to pool member as cookie persistence value.
Subsequent HTTP request with different cookie value inserted by upper stream but and ltm policy was properly selected, however it does not forwarded to the pool member which cookie value pointed.

Environment

  • BIG-IP
  • any version
  • Virtual server
  • LTM policy
  • HTTP cookie persistence
     

Cause

In the first HTTP request, the virtual server has already load balanced and connection table is not removed by forcing load balance.
HTTP profile does not support content switching, and in policy re-load balance based on the HTTP content is not supported.
 

Recommended Actions

Add OneConnect profile which support content switch.
 

Additional Information

K7208: Overview of the OneConnect profile
