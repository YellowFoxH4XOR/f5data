Known Issue

If SNAT is enabled in SSL Orchestrator, it is globally enabled for both inbound and outbound traffic; however, the SNAT addresses are only on the outbound side of the system. If both inbound and outbound traffic are configured, the inside systems do not have a direct route to these addresses, which prevents traffic from returning.

Note: If SSL Orchestrator is set up to handle only inbound or outbound traffic, or if SNAT is not configured, this issue does not apply.

Impact

SNAT is configured by default for inbound and outbound traffic and you cannot turn it off in one direction without performing this workaround.

Workaround

The following solution manually creates a SNAT pool and enables SNAT on inbound virtual servers.

Impact of workaround: When you change configuration of certain objects, the system re-deploys the various BIG-IP objects to match your new configuration. This re-deployment overwrites any existing BIG-IP objects without warning about existing changes. Before performing this procedure, you must first refer to the warnings and directions in the Disabling Strict Updates section of K00805840: SSL Orchestrator known issues and workarounds.

Setting up the SNAT pool

  1. Navigate to Local Traffic > Address Translation > SNAT Pool List.
  2. Click Create.
  3. For Name, type sslo_inbound_snat.
  4. For Members List, add the SNAT addresses you want to use to the pool.
  5. Click Finished.

Unlocking the application

  1. Navigate to SSL Orchestrator > Deployment > Deployment Settings.
  2. For Description, add MOD:INBOUND_SNAT to the end of the description.

    Note: This description tells F5 Technical Support that you are using the official modification for this workaround..

  3. Under General Properties, clear the Strict Update check box.
  4. Click Finished.

Apply the rules to the virtual servers

  1. Navigate to Local Traffic > Virtual Servers.
  2. Click the virtual server which has the same name as the inbound rule.
  3. Under Configuration, for Source Address Translation, click SNAT and for SNAT Pool, click the SNAT pool you created earlier.
  4. If necessary, repeat these steps for other inbound virtual servers.
