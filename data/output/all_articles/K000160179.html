Description

This article addresses an issue where the dosl7d (Layer 7 DoS) process on BIG-IP systems exhibits persistent high CPU utilization and regular CPU spikes. The problem is observed in environments where BIG-IP is integrated with Kubernetes using CIS (Container Ingress Services) and AS3 (Application Services 3 Extension), resulting in frequent configuration updates. Symptoms include:

 

  • CPU usage by dosl7d process consistently spiking to high levels (90–100%)
  • Performance degradation on both active and standby BIG-IP devices
  • Frequent incremental configuration syncs and AS3-driven changes
  • Log messages indicating rapid and repeated configuration updates, often triggered by Kubernetes CIS

Environment

  • BIG-IP LTM, versions 17.1.3 and 17.5.1.4
  • ASM (Application Security Manager) and DoS (dosl7d) modules enabled
  • Integration with Kubernetes via CIS and AS3
  • Frequent AS3 API calls from Kubernetes, resulting in rapid configuration changes

Cause

Bug ID2221781

Answer/Recommended Actions

  • Apply the Engineering Hotfix (EHF) that addresses Bug ID2221781 for your BIG-IP version (available for 17.1.3.1 and 17.5.1.4). This hotfix prevents dosl7d from acquiring unnecessary configuration write locks during unrelated MCP updates.
  • Reduce the frequency of AS3 API calls from Kubernetes CIS to minimize configuration churn and lower CPU load.

Additional Information

The dosl7d process was found to acquire configuration write locks for any unrelated MCP update, which, when combined with frequent AS3-driven configuration changes, resulted in excessive CPU utilization.
