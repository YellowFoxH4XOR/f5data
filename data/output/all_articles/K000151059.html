K000151059: BIG-IP ASM device is offline and not returning to online

Type
Support Solution
Published
2025-05-22
Updated
2026-03-29
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.X, 17.1.2, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000151059

Description

BIG-IP ASM device is offline and not returning to online for long time

Following logs are noted in /var/log/ts/bd.log contains events reporting PCRE compilation failure.

ECARD|ERR   |Jan 23 10:16:59.036|14826|regexp_table_management.cpp:0057|key crc xxxxxxxx PCRE compilation failed at offset 3: PCRE does not support \L, \l, \N{name}, \U, or \u

Environment

  • BIG-IP ASM device is offline and not returning to online
  • BIG-IP ASM device upgraded to version 17.1.2/17.1.2.1
  • BIG-IP ASM device is went to offline after applying ASM policy
  • Above logs noted in  /var/log/ts/bd.log when BIG-IP ASM device is offline

Cause

Bug ID 1848541

Recommended Actions

1. Login into BIG-IP ASM device using root

2. Check /var/log/ts/bd.log messages to get the decimal CRC value of the problem regex:
# printf "%d\n" 0x`zgrep 'ECARD|ERR' /var/log/ts/bd.log* | grep -B 3 -A 3 regex | grep crc | awk '{print $7}' | uniq` 

3. Identify the actual string:
#  mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'select * from  DCC.GLOBAL_PARAM_REG_EXPS where reg_exp_crc = value_from_step2;'

(replace value_from_step2 with the actual values returned in step #2, one at a time)

4. Clear the problem regex entries
#  mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'delete from  DCC.GLOBAL_PARAM_REG_EXPS where reg_exp_crc = value_from_step2;'
#  mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'delete from  DCC.ACCOUNT_PARAM_REG_EXPS where reg_exp_crc = value_from_step2;'

(replace value_from_step2 with the actual values returned in step #2, one at a time)

5. Restart ASM
# bigstart restart asm

6. Allow some time for device to come online. If there are still issues, repeat the steps until all problem regex are removed.

Additional Information

To fix the regex without deleting it completely, first boot back to the previous version and then run the command below to find in which ASM policy object the regex is used. After modifying the regex via the GUI, boot back to the new software versions with "Install Configuration" checked.


# mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'set @CRC="value_from_step2"; select T3.name policy_name, PARAMG.name parameter_name, T3.regexpr_values from (select id, name, regexpr_values from (select PARAM.id, POL.name, PARAM.regexpr_values from PLC.PL_PARAM_ATTRIBUTES PARAM INNER JOIN PLC.PL_POLICIES POL ON PARAM.policy_id=POL.id) AS T2 where regexpr_values in ( select reg_exp from DCC.ACCOUNT_PARAM_REG_EXPS where reg_exp_crc = @CRC )) AS T3 INNER JOIN PLC.PL_GLOBAL_PARAMS PARAMG ON T3.id=PARAMG.param_attrib_id;select T4.policy_name, T4.name parameter_name, OBJS.uri, T4.regexpr_values from ( select T3.name policy_name, PARAMO.name, PARAMO.obj_id, T3.regexpr_values from (select T2.id, T2.name, T2.regexpr_values from (select PARAM.id, POL.name, PARAM.regexpr_values from PLC.PL_PARAM_ATTRIBUTES PARAM INNER JOIN PLC.PL_POLICIES POL ON PARAM.policy_id=POL.id) AS T2 where regexpr_values in ( select reg_exp from DCC.ACCOUNT_PARAM_REG_EXPS where reg_exp_crc = @CRC )) AS T3 INNER JOIN PLC.PL_OBJECT_PARAMS PARAMO ON T3.id=PARAMO.param_attrib_id) AS T4 INNER JOIN PLC.PL_OBJECTS OBJS ON T4.obj_id=OBJS.id;'

(replace value_from_step2 with the actual values returned in step #2, one at a time)
