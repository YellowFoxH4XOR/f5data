Description

BIG-IQ cluster re-import/synchronization of BIG-IP LTM configuration can fail with an HTTP 500 validation error when a BIG-IP LTM virtual server uses mixed IP address families between the source and destination.

Example error:

Failed to synchronize clustered devices; reason: Worker ... failed validation with status 500: java.lang.IllegalArgumentException: The sourceAddress ::/0 and destination address ... must be the same format type

The error typically identifies the offending Traffic Management Object and virtual server.

Environment

  • BIG-IQ Centralized Management
  • BIG-IP LTM devices
  • LTM virtual server configured with IPv6 source address (example: ::/0) and IPv4 destination address
  • Clustered device re-import / rediscover & re-import / cluster synchronization in BIG-IQ

Cause

A BIG-IP LTM virtual server is configured with mismatched IP address formats (IPv6 source and IPv4 destination). BIG-IQ validation requires the source and destination addresses on a virtual server to use the same address family (both IPv4 or both IPv6). The mismatch triggers java.lang.IllegalArgumentException and blocks cluster sync.

Recommended Actions

  1. Identify the virtual server referenced in the BIG-IQ validation error.
  2. On the BIG-IP device, update (or remove) the offending virtual server so that source and destination use the same IP address family (both IPv4 or both IPv6).
  3. In BIG-IQ, perform a rediscovery (and re-import if applicable) of the affected BIG-IP device(s) after making the BIG-IP change.
  4. Re-run the cluster sync / re-import workflow and confirm it completes successfully.

Additional Information

This issue can be encountered even if the affected virtual server is offline; BIG-IQ validation still processes the object during import/sync.
