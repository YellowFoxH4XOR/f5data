Description

Tenants may become unreachable via their main IP addresses, while remaining accessible through management ports. The partition manager GUI can become slow and unresponsive, with frequent hanging. System interactions may produce errors such as:

Failure for data/openconfig-system:system/f5-system-redundancy-details:redundancy-details/state/hardware API. The server or an underlying service is unreachable.

Request failed with status code 500

Network Error

Affected tenants show TMM not ready status, and logs include:

SDAG CDP ERROR: Error - SDAGLIB context request expired

Couldn't bulk write DagState for tenant ... confd_errno=45 confd_errstr="Lost connection to ConfD"

DB waiting for ready NAME="CdbDagStateWriter"

Environment

  • Product: F5OS - Chassis (VELOS)
  • Configuration: Multi-slot chassis with multiple tenants, partition manager, dual system controllers
  • Extended uptime (controllers/blades >500 days)

Cause

The root cause is high memory utilization and a memory leak in NetworkManager after prolonged uptime (Bug ID 1926585), resulting in out-of-memory (OOM) state on controller-1 and loss of confd connectivity. Additional triggers include partition Qkview generation causing connectivity issues (Bug ID 1559525) and duplicate MAC addresses on different tenants (Bug ID 1576241). All these bugs affect F5OS-C version 1.6.2-22734.

Recommended Actions

  1. Stop All Tenants:
    Stop all tenants before proceeding.
  2. Reboot Controllers:
    Reboot the standby controller (controller-1) using either:
    system reboot controllers controller standby
    or SSH to controller-1 and run
    reboot from bash.
    Once controller-1 is online, fail over to it and reboot controller-2.
  3. Apply Workaround for Bug ID 1559525:
    On each blade, run:

    for layer in $(docker inspect partition_fpga | jq --join-output '.[0].GraphDriver.Data | .LowerDir, ":", .MergedDir' | tr ':' ' '); do
      if [ -f "$layer/etc/qkview-collect/fpgatoolFpgaVqfSnapshotCmds.txt" ]; then
        sed -i 's/^linkscan/#linkscan/g' $layer/etc/qkview-collect/fpgatoolFpgaVqfSnapshotCmds.txt
      fi
    done

  4. Reboot Blades:
    Use one of the following methods:
    From the partition:
    cluster nodes node <blade> reboot
    From bash on the blades:
    reboot
    Or from controller:

    for i in blade-{1,2,3}; do ssh $i 'shutdown -r +1'; done

  5. Verify Blade Status:
    Use show cluster and show system redundancy in the partition to confirm:
    • Each blade reaches running-state 'running'
    • Status of each blade is 'replica'
    • fpga-state is 'FPGA_RDY'
    • dma-agent-state is 'DMA_AGENT_RDY'
  6. Start Tenants: Restart tenants once blades are fully operational.
  7. Upgrade Recommendation: Upgrade to a later F5OS-C version (e.g., 1.8.1 or newer) to prevent recurrence of these issues.

Impact of workaround: The system will not be available while performing multiple restarts.
