Known Issue

An iRules response to a DNS request triggers the Traffic Management Microkernel (TMM) to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • You configure your BIG-IP DNS system (formerly known as BIG-IP GTM) with a wide IP that uses an iRule.
  • The iRule uses the DNS_REQUEST event command with the pool command.
  • The iRules pool address and port are separated by white space.

    The following iRules syntax is an example of the above conditions:

    gtm rule pool_member_selection {
        when DNS_REQUEST {
            LB::status pool pool-one member 10.0.0.10 80
        }
    }

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H641723 on the Diagnostics > Identified > Medium page.
  • Your BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as an HA pair may fail over.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

To work around this issue, you can modify the iRules definition to reference the IP address and port using different syntax. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > Delivery > iRules > iRule List.
  3. Click the name of the affected iRule.
  4. Modify the LB::status pool member reference using one of the following syntax methods:
    • Replace the white space between the member IP address and port with a Colon character.

      For example, when this is the original syntax:

      LB::status pool pool-one member 10.0.0.10 80

      This is the modified syntax:

      LB::status pool pool-one member 10.0.0.10:80

    • Replace the pool member reference IP and port with the pool member name.

      For example, when this is the original syntax:

      LB::status pool pool-one member 10.0.0.10 80

      This is the modified syntax:

      LB::status pool pool-one member <path><virtual server pool member name>

      In the example above, note that <path><virtual server pool member name> is the partition and name of the pool member virtual server. The following syntax contains examples of these:

      LB::status pool pool-one member /Common/vs_abc

  5. Click Update.
