K000133305: Configuration pushes to NGINX+ agents fail unexpectedly

Published

Applies to

Source

Description

Submitting configuration updates via components or gateways fails unexpectedly. NGINX+ agent could be reporting unexpected nginx configuration check errors such as ‘duplicate locations’, ‘host not found’, ‘upstream not found’, etc. This can occur if dpm cache is corrupt. DPM cache is built based on the configuration within config db. DPM cache is updated upon configuration changes and rebuilt when dpm cache is reset/deleted.

Environment

NGINX Controller

Cause

DPM cache is corrupt

Recommended Actions

Reset dpm cache

/opt/nginx-controller/helper.sh reset --reload-configs=false

  • When the reset command completes the following message appears in stdout:
Successfully reset DPM.
  • If this message doesn't appear then check the declarative and dpm logs as something went wrong

Delete the dpm pod

kubectl delete pod -l app=dataplane-manager

Confirm the dpm pods come up

watch -n1 'kubectl get po| egrep "declarative|dataplane"'

(Optional) Output dpm cache to file

Run this script on NGINX Controller

#!/bin/bash
# Get the dpm certs from secrets
name=dataplane-manager-certs
filter=".items | map(select(.metadata.name | startswith(\"$name-\"))) | sort_by(.metadata.creationTimestamp) | last.metadata.name"
s=$(kubectl get secret "$(kubectl get secret -o json | jq -r "$filter")" -o json)
for n in ca.crt client.crt client.key; do jq -r ".data | .[\"$n\"]" <<<"$s" | base64 -d >"$n"; done
dpmfile="dataplane-mgr-$(date -Isec).json"
touch $dpmfile
# Dump dpm node cache
name=dataplane-manager
port=8443
podip=$(kubectl get pod -l app=$name -o jsonpath='{.items[0].status.podIP}')
echo "Dumping DPM cache to: $dpmfile"
curl -fsSL --cacert ./ca.crt --cert ./client.crt --key ./client.key --resolve $name.nginx-controller.svc.cluster.local:$port:$podip -X GET https://$name.nginx-controller.svc.cluster.local:$port/api/v1/internal/dataplane-manager/dumps | jq >> $dpmfile

The dpm cache output file 'dataplane-mgr-$(date -Isec).json' is located in the same location as the script is run in
