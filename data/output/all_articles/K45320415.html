Known Issue

Using the TMOS Shell (tmsh) to view access information may cause the Traffic Management Microkernel (TMM) to leak memory.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an access profile.
  • You view access information by typing the following command:

    tmsh show /apm access-info all-properties

Impact

Running the specific tmsh command causes the TMM process to retain a small amount of memory that is not returned to the BIG-IP APM system. Extensive use of the tmsh command can ultimately exhaust memory resources. If the BIG-IP APM system is a member in a device group, traffic may fail over to another device group member. If the BIG-IP system is not part of a device group, traffic is interrupted until the mcpd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The amount of memory allocated for and used by the TMM process increases over time.
  • Over time, the TMM process exhausts memory resources. As a result, system performance degrades and the system eventually becomes unresponsive.
  • The TMM process restarts and generates an mcpd core file to the /shared/core directory.
  • The BIG-IP system unexpectedly fails over to another system in the device group.
