Description

The SSL handshake failures may occur on BIG-IP LTM systems, with error messages such as
"SSL Handshake failed for TCP <ip>:<port> -> <ip>:443"
"Connection error: ssl_null_parse:3779: alert(40) hs msg overflow"
appearing in the logs. One possible reason for these SSL handshake failures is that the total size of handshake messages exceeded the allowed buffer, resulting in a "handshake message overflow." This can occur, for example, if a client SSL profile receives a client authentication certificate or if the backend server sends large SSL certificate files.  Packet captures may show abrupt TLS handshake terminations, and the handshake does not complete successfully. 

 

Environment

  • BIG-IP LTM
  • HTTPS Virtual Server
  • SSL Profile
     

Cause

The total size of SSL handshake messages—including Client Hello, Server Hello, Certificate, Server Key Exchange, Certificate Request, Server Hello Done, Certificate, Client Key Exchange and Certificate Verify , and associated data—exceeded the buffer limit defined by "tmm.ssl.maxhandshakesize". This is typically triggered by a large CA bundle or long certificate chains that increase the size of handshake messages beyond the configured buffer.

The default SSL handshake buffer size is 32KB (32,768 bytes). In this scenario is set to 40,000 bytes:

sys db tmm.ssl.maxhandshakesize {
default-value "32768"
scf-config "true"
value "40000"
value-range "unsigned_integer min:32768 max:2091752"
}

 

Recommended Actions

Calculate SSL handshake buffer by using one of the command below:
 tshark -r SSLfailure23rdJune.pcap -Y "tls.handshake and tcp.stream eq <stream number>" -T fields -e frame.number -e ip.src -e ip.dst -e _ws.col.Protocol -e frame.len -e _ws.col.Info -e tls.handshake.length

Additional Information

When analyzing SSL handshake failures using Wireshark, if you observe an "Alert (Level: Fatal, Description: Handshake Failure)" message at any point during the handshake process, you should calculate the cumulative size of all handshake messages exchanged up to and without the packet where this alert occurs. This total represents the effective buffer usage at the point of failure and is critical for diagnosing buffer overflow issues.
