Known Issue

The BIG-IP system may intermittently reset FTP connections. This issue occurs when all of the following conditions are met:

  • You associate an FTP virtual server with an iRule that uses the FTP::port iRules command.
  • The back-end FTP server sends a PASV FTP command with a selected port.

Typically, you can use the FTP::port iRules command to perform a passive mode port change selection. For more information about the FTP::port iRules command, refer to FTP::port on F5 Cloud Docs.

Impact

FTP clients are unable to retrieve data from the back-end FTP server using the BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • An FTP client is unable to retrieve data from the back-end FTP server using the BIG-IP system.
  • A packet capture on the affected traffic shows the system resets the passive FTP data connection when the back-end FTP server sends a PASV FTP command.
  • If you enable the TM.RstCause.Log database variable during troubleshooting, you observe an error message in the /var/log/ltm file that appears similar to the following example:

    01230140:3: RST sent from <source IP:port> to <destination IP:port>, [0x1b3a831:864] FTP error (Out of ports)
