Topic

F5 iWorkflow can act as a remote proxy for representational state transfer (REST) calls to a BIG-IP device. This capability can remove the need to send REST requests directly to a BIG-IP device.

You should consider using these procedures under the following conditions:

  • You have an iWorkflow system available within your network, and the system can communicate with the BIG-IP device directly.
  • You have BIG-IP devices within your environment that you want to manage from a central point.

Description

REST calls can be proxied to BIG-IP devices via iWorkflow. To use the REST proxy for a BIG-IP device, you must enable that feature in the iWorkflow object reference for that BIG-IP device. This feature is disabled by default and may not be present on the iWorkflow instance for a BIG-IP device. iWorkflow administrators can enable this feature during the discovery process or post-discovery of a BIG-IP device.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • The iWorkflow device must have network connectivity to the BIG-IP management (MGMT) interface.
  • The iWorkflow user must have administrative privileges on the BIG-IP device.

Procedures

Enabling iWorkflow as a REST proxy during the BIG-IP discovery process

This procedure creates a JSON payload file, which is a text file that includes the BIG-IP MGMT IP address, the admin user name and password, the directive to update the REST framework, and the directive to enable the REST proxy feature. The following options are used with the cURL command:

  • -k
    Ignores Secure Sockets Layer (SSL) certificate warnings.
  • -s
    Enables silent mode. With this option, the cURL command does not show the progress meter or error messages.
  • -u admin:admin
    The admin:admin values in the cURL command are used to authenticate to iWorkflow and not the BIG-IP device targeted for discovery.
  • -X POST
    Changes the request method from the default of GET, to an HTTP POST.
  • -d@filename
    Allows the cURL command to load data from the given file name, URL-encode the contents, and pass the contents on in the POST.

In the following JSON sample file, the BIG-IP MGMT IP address is 10.10.99.2, and the administrative user name and password is admin/admin. The automaticallyUpdateFramework attribute is set to true, and the isRestProxyEnabled directive is set to true.

Note: The automaticallyUpdateFramework attribute is required because the REST framework on the BIG-IP device must be the same as the version on the iWorkflow system.

{
"address": "10.10.99.2",
"userName": "admin",
"password": "admin",
"automaticallyUpdateFramework": "true",
"properties": {
"isRestProxyEnabled": "true"
}
}

Impact of procedure: The iWorkflow system communicates with the restjavad interface on the BIG-IP device, and this process restarts when the REST framework is updated. This update does not affect traffic that traverses the BIG-IP system. Enabling the REST proxy feature for a BIG-IP device on iWorkflow does not affect iWorkflow.

  1. Log in to the iWorkflow command line.
  2. Navigate to the /var/tmp directory by typing the following command:

    cd /var/tmp
  3. Use a text editor such as 'vi' to create a text file named discover_and_enable_proxy.json.

    For example:

    vi discover_and_enable_proxy.json
  4. Add the syntax provided above, using the BIG-IP IP address, user name, and password values to reflect your environment.

    Note: Alternatively, you can create the JSON file externally and then use the scp utility to copy the file to your iWorkflow host.
  5. Use the cURL utility to enable the REST proxy feature on your BIG-IP device, by typing the following command:

    curl -k -s -u admin:admin -X POST -d@discover_and_enable_proxy.json https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices

    Note: Because you are logged into the iWorkflow instance, you can direct the cURL commands to localhost. However, you can run this command from another host, assuming there is network connectivity between both devices. To do so, you can replace localhost with the iWorkflow IP address or network resolvable name.

    The iWorkflow system should return the newly created object details, including the universally unique identifier (UUID) associated with the discovered BIG-IP device, similar to the following example:

    Note: The example output indicates a state of 'PENDING' during the discovery process, and changes to 'ACTIVE' after the discovery process has completed.

    {"uuid":"05eb0e2a-b39d-46ae-a33d-68cbb50eaad2","deviceUri":"https://10.10.99.2:443","machineId":"05eb0e2a-b39d-46ae-a33d-68cbb50eaad2","state":"PENDING","address":"10.10.99.2","httpsPort":443,"properties":{"isRestProxyEnabled":"true"},"automaticallyUpdateFramework":true,"groupName":"cm-cloud-managed-devices","generation":31,"lastUpdateMicros":1473787566605075,"kind":"shared:resolver:device-groups:restdeviceresolverdevicestate","selfLink":"https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices/05eb0e2a-b39d-46ae-a33d-68cbb50eaad2"}

  6. Take note of the UUID value in the output from step 5, as you will use the value in the next step.
  7. Confirm that the BIG-IP device was discovered and that the REST proxy feature has been enabled, by using the following syntax, where <uuid> is the UUID value you noted in step 6:

    curl -k -s -u admin:admin https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices/<uuid>

Enabling iWorkflow as a REST proxy after BIG-IP discovery is complete

If the BIG-IP devices were previously discovered and do not have the REST proxy feature enabled, you can update the devices after discovery is complete. The following procedure adds or updates the value using the cURL utility and the appropriate JSON payload.

Impact of procedure: Enabling the REST proxy feature for a BIG-IP device on iWorkflow does not affect iWorkflow unless properties, found in the existing properties, are not included in the POST payload.

  1. Log in to the iWorkflow command line.
  2. Discover the UUID and defined properties for the BIG-IP device that you want to update (with the REST proxy feature) by typing the following command:

    curl -k -s -u admin:admin https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices

    The output returns all iWorkflow-discovered devices and can be challenging to search through when locating a single device. However, you can use JSON formatting utilities or common UNIX tools to expedite the searches by using the following methods:
  • Redirect the output through the json-format utility, and then to the less utility, where you can search the output for the IP address associated with the BIG-IP device, by typing the following command:

    curl -k -s -u admin:admin https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices | json-format | less

    Note: To exit the less utility, type q.
  • Redirect the output to a file, to search through the text using the tool of your choice. The following example redirects the output to a file named iworkflow-devices.txt, located in the /var/tmp directory:

    curl -k -s -u admin:admin https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices | json-format > /var/tmp/iworflow-devices.txt
  1. Once you find the UUID and currently discovered properties of a specific BIG-IP device, using your preferred text editor, create a text file named enable_proxy.json that contains the currently defined properties for the BIG-IP device, and add the isRestProxyEnabled attribute with a value of true. In the following example, the payload already has two other properties set, and you are adding the isRestProxyEnabled attribute. Your environment may have similar properties, or others also defined:

    {
    "properties": {
    "isRestProxyEnabled": "true",
    "shared:resolver:device-groups:discoverer": "7345e107-d4f8-43a7-b3f6-22f44d11b2c8",
    "dmaFinished": "true"
    }
    }

    Important: When updating a previously discovered BIG-IP device, you must include all of the values, found in the current configuration, in your payload syntax, along with the new attributes that you are adding. Any omitted properties are removed from the configuration and may cause adverse side effects.

  2. Update the desired BIG-IP device using the following cURL command syntax. Replace <uuid> with the UUID of the BIG-IP device that you want to update:

    curl -k -s -u admin:admin -X POST -d@enable_proxy.json https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices/<uuid>

    For example, to update a BIG-IP device with a 05eb0e2a-b39d-46ae-a33d-68cbb50eaad2 UUID, type the following command:

    curl -k -s -u admin:admin -X POST -d@enable_proxy.json https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices/05eb0e2a-b39d-46ae-a33d-68cbb50eaad2
  3. Confirm the update is in place by using the cURL utility again to retrieve the list of attributes defined, which the BIG-IP device just updated. For example, the following command uses the same UUID as in step 4:

    curl -k -s -u admin:admin https://localhost/mgmt/shared/resolver/device-groups/cm-cloud-managed-devices/devices/05eb0e2a-b39d-46ae-a33d-68cbb50eaad2
