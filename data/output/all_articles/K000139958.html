Description

You may see some Disk usage Alerts on your Monitoring Tools for the below Partitions:

  • /opt/.sdm/usr
  • /opt/.sdm/lib
  • /opt/.sdm/lib64

For example, below is a sample Alert message for one of those Partitions generated on the Monitoring Tools. But there is no similar log on BIG-IP:

Alert : /opt/.sdm/usr: Disk space is critically low (used > 80%)

 

Environment

  • BIG-IP is monitored by a Monitoring Tool (like Zabbix)
  • High Disk usage for the partition "/usr"

Cause

Running the below command indicates that both the mentioned directories "/opt/.sdm/lib" and "/opt/.sdm/lib64" mounted on the partition "/usr".

# df -h /opt/.sdm/lib*

The directory "/opt/.sdm/usr" is also mounted on the partition "/usr". You can run the below command to see further details of all the mounted directories:

# df -ah

On the other hand, running the below command on BIG-IP may show that the partition "/usr" is used more than 80%:

# df -h /usr
Filesystem                                                Size     Used     Avail      Use%     Mounted on
/dev/mapper/vg--db--sda-set.1._usr     6.2G    5.0G      846M     86%       /usr

Recommended Actions

The partition "/usr" can show high Disk space usage, and It can even go up more than 90% upon installation of system files, and normally mounted as read-only. This is an Expected behavior, and there is no problem on F5-side, and this will NOT Impact performance.

There is NO need to Monitor the partition "/usr" in any Monitoring Tool as this is an Expected behavior.
