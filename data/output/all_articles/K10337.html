Known Issue

This is the result of a known issue. Simultaneously changing the BIG-IP GTM monitor's timeout and interval values results in the host status changing to a down state immediately followed by an up state. This issue is known to occur with large BIG-IP GTM configurations.

When this issue occurs, status messages that appear similar to the following example are logged to the /var/log/gtm file:

gtmd[6785]: 011ae0f2:1: Monitor instance my_tcp 10.0.0.1:80 UP --> DOWN from gtmd (no reply from big3d: timed out)
gtmd[6785]: 011a6006:1: SNMP_TRAP: VS vs_host11 (ip:port=10.0.0.1:80) (Server host11) state change green --> red (VS vs_host11: Monitor my_tcp from gtmd : no reply from big3d: timed out)
gtmd[6785]: 011a5004:1: SNMP_TRAP: Server host11 (ip=10.0.0.1) state change green --> red (Server host11: No enabled VS available)
gtmd[6785]: 011a4003:1: SNMP_TRAP: Pool pool1 member vs_host11 (ip:port=10.0.0.1:80) state change green --> red (Pool pool1 member vs_host11:VS vs_host11: Monitor my_tcp from gtmd : no reply from big3d: timed out)
gtmd[6785]: 011ae0f2:1: Monitor instance my_tcp 10.0.0.1:80 DOWN --> UP from 10.0.0.11 (state: success)
gtmd[6785]: 011a6005:1: SNMP_TRAP: VS vs_host11 (ip:port=10.0.0.1:80) (Server host11) state change red --> green
gtmd[6785]: 011a5003:1: SNMP_TRAP: Server host11 (ip=10.0.0.1) state change red --> green
gtmd[6785]: 011a4002:1: SNMP_TRAP: Pool pool1 member vs_host11 (ip:port=10.0.0.1:80) state change red --> green

F5 Product Development is tracking this issue as ID 246769 (formerly CR101679).

Workaround

F5 recommends changing the BIG-IP GTM monitor's timeout and interval values at alternating times. If you plan to use larger values, change the timeout first; if you plan to use smaller values, change the interval first.
