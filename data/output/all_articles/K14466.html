Issue

Error Message

CHASS_LIB-0-ERR-MSG3:: chassis_system: command '/usr/bin/fbstat -u sysdba -p masterkey /acopia/config/usr/objMgr.db ` grep -B2 'Data pages:' > /acopia/config/usr/fbstat.out 2> /dev/null' exited due to signal 9

Message Location

You may encounter this message in the following location:

  • Error.log

Description

This message occurs when one of the following conditions are met:

  • Excessive objmgr.db size
  • Configuration transactions are locking the database from the database cleaning utility

Impact

Database performance slows and as the objMgr.db file footprint grows. If the objMgr database is allowed to continue its growth, the ARX system will forcefully reboot and generate core files.

Recommended Actions

If the error message continues in excess of 7 days, rebuild objmgr.db by performing one of the following procedures:

Rebuilding the objmgr.db

Impact of workaround: Device and services will be unavailable.

Important: You must complete this procedure on the standby ARX to minimize downtime.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:
  3. enable
  4. Save the startup configuration for recovery purposes using the following command syntax:

    copy startup-config configs [filename].cfg

    For example:

    copy startup-config configs recovery_startup.cfg
  5. Save the global configuration as a precaution using the following command syntax:

    copy global-config configs [filename].cfg

    For example:

    copy global-config configs recovery_global.cfg
  6. Delete the system configuration by typing the following command:

    delete startup-config
  7. Reboot the ARX system by typing the following command:

    reload
  8. Configure the base ARX system using the saved running configuration file by typing the following command syntax:

    run configs <running-config-name>

    For example:

    run configs recovery_startup.cfg
  9. To re-license the ARX system, refer to K12800: Overview of ARX licensing
  10. Wait for switch replacement rendezvous and HA pairing to complete.

    Note: After the rendezvous completes the global configuration will synchronize to standby system.

Rebuilding the objmgr.db in ARX version 6.1.1.HFRU-11

In ARX 6.1.1.HFRU-11, F5 support has internal commands that will rebuild the objmgr.db after an ARX system reboot with less impact. Contact F5 support to open a case and reference ID 420225.

Impact of workaround: Device and services will be unavailable while the system is rebooting.
