Topic

This article applies to BIG-IP DNS (formerly BIG-IP GTM) 11.x through 21.x. For information about other versions, refer to the following article:

  • K8195: Overview of the BIG-IP GTM big3d_install, bigip_add, and gtm_add utilities (9.x - 10.x)

Note: Beginning in BIG-IP 21.0.0, the Link Controller module is no longer available.

When deploying BIG-IP DNS, one of the steps includes configuring the different BIG-IP systems with which the BIG-IP DNS system interacts when managing DNS traffic.

Description

The BIG-IP DNS configuration scripts allow you to establish communications between the BIG-IP DNS systems and other external BIG-IP systems. Before you run any of the BIG-IP DNS configuration scripts, you should be aware of the following:

  • Use the BIG-IP DNS Configuration utility to define any remote BIG-IP systems (including other BIG-IP DNS systems) with which BIG-IP DNS will communicate.
  • To successfully use the big3d_install, bigip_add, and gtm_add utilities, the local BIG-IP system must be able to route to the destination BIG-IP system and access port 22 (SSH) on the destination device. (In addition to allowing firewall communication between the initiating and target devices on port 22, both device's port lockdown settings and sshd settings need to be configured correctly to ensure access to port 22 is allowed.)
  • Each DNS configuration script has an intended purpose and use case. To prevent unexpected results, F5 recommends reviewing the below information before running the scripts.

After you have defined the other systems with which the BIG-IP DNS system will communicate, you may need to run one or more of the BIG-IP DNS configuration scripts. The BIG-IP DNS configuration scripts are defined as follows:
 

DNS scriptDescriptionProtocolWhen to useRunning the script
gtm_add
  • The gtm_add script is used to integrate a new BIG-IP DNS system into an existing DNS sync group.
  • The script replaces the current configuration files (bigip_gtm.conf, named.conf, and named zone files) on BIG-IP DNS on which it runs with the configuration of the remote BIG-IP DNS system in the specified sync group.
  • The BIG-IP DNS system on which you run the gtm_add script must be running the same version as the remote BIG-IP DNS system's sync group. If not, the gtm_add script may fail to properly add the BIG-IP DNS system.
  • The gtm_add script uses the secure shell (SSH) protocol to copy the remote BIG-IP DNS system's Secure Sockets Layer (SSL) certificates to the local BIG-IP DNS system and iQuery over TCP port 4353 to synchronize the configuration.
  • The gtm_add script no longer supports SSH to synchronize the configuration as a backup if the iQuery connection fails.
  • Use the gtm_add script to integrate a new BIG-IP DNS system into an existing synchronization group that has one or more remote BIG-IP DNS Controllers.
  • For information about running the gtm_add script and integrating a new BIG-IP DNS system into an existing DNS synchronization group, refer to the following article: K45907236: Overview of BIG-IP DNS synchronization
  • For detailed syntax information, run the 'man gtm_add' command.
  • You run the gtm_add script on the new BIG-IP DNS system that you are integrating within a network with one or more existing BIG-IP DNS systems. The new BIG-IP DNS system needs to be defined in the existing BIG-IP DNS system's configuration prior to running the gtm_add script. To run the gtm_add script, log in with root privileges to the command line of the BIG-IP DNS system and use the following command syntax:
    • gtm_add <existing_DNS_IP_address>
      or
    • gtm_add <username>@<existing_DNS_IP_address>
  • The gtm_add script defaults to using the login name of the currently logged-in user to connect to the remote system. To specify a specific login name use the syntax username@ip.address , for example:
    • gtm_add <username@BIG-IP_IP_address>
      gtm_add user@10.0.0.1
      gtm_add root@10.0.0.1
  • If the remote user's shell is tmsh (this will always be the case if the remote device is running in 'appliance mode'), you must also specify the -a switch, to tell gtm_add to use tmsh commands to exchange certificates.  Since the 'root' user is not accessible in appliance mode, a username must also be specified if the -a (appliance mode) switch is used.
    • gtm_add -a user@x.x.x.x
big3d_install
  • The big3d process runs on all BIG-IP systems and provides metrics collection data for BIG-IP systems. The big3d_install script is an interactive script that allows you to install the current version of the big3d process on remote F5 systems. If a newer version of the big3d process is running on the remote BIG-IP system, the script skips installation for that BIG-IP system.
  • The big3d_install script also copies the trusted device certificate from the local BIG-IP DNS system to the /config/big3d/client.crt file on the remote BIG-IP system and the trusted server certificate from the remote BIG-IP system to the /config/gtm/server.crt file on the local BIG-IP DNS system.
  • The big3d_install script initially attempts to use iQuery over TCP port 4353 to copy the big3d process to the remote BIG-IP system. If the iQuery connection fails, or the -use_ssh option is specified, big3d_install attempts to use the Secure Copy (SCP) protocol over TCP port 22 to exchange SSL certificates and copy the big3d process to the remote BIG-IP system.
  • Use the big3d_install script to install the current version of the big3d process on remote F5 systems. You may want to run the script when devices in the iQuery mesh are running different versions of the big3d agent.
  • For information about big3d version management, refer to: K13703: Overview of big3d version management.
  • For detailed syntax information, run the 'man big3d_install' command.
  • To run the big3d_install utility, log in with root privileges to the command line of the BIG-IP DNS system and use the following command syntax:
    • big3d_install <BIG-IP_IP_address>
    • Note: If you do not specify an IP address, the script attempts to install the current version of the big3d process on all the BIG-IP controllers ('gtm server' objects) listed in the bigip_gtm.conf file.
    • Note: This command restarts the big3d process on the device being updated, which momentarily interrupts gtm monitoring, and may result in services briefly being marked down.
    • Note: After installing a new big3d version, the Local big3d version reported in the output of tmsh show gtm iquery command may not be updated until gtmd is restarted on the recently updated device using tmsh restart sys service gtmd.
bigip_add
  • The bigip_add script is an interactive script that enables iQuery communication between the BIG-IP DNS sync group members and the remote BIG-IP LTM system. The bigip_add script appends the local BIG-IP DNS system's SSL certificate to the remote BIG-IP system's list of authorized certificates (contained in the /config/big3d/client.crt file). The script then appends the remote BIG-IP system's iQuery SSL certificate to the BIG-IP DNS system's local list of authenticated iQuery SSL certificates (/config/gtm/server.crt).
  • The bigip_add script uses the SSH protocol to exchange iQuery SSL certificates with the remote BIG-IP system.
  • Use the bigip_add script to enable iQuery communication between a BIG-IP LTM system and BIG-IP DNS systems, and integrate the BIG-IP LTM system into a network with existing BIG-IP DNS systems.
  • For information about running the bigip_add script and integrating a BIG-IP LTM into a network with BIG-IP DNS, refer to: K43300744: Adding BIG-IP LTM to a network with BIG-IP DNS (13.x - 17.x).
  • For detailed syntax information, run the 'man bigip_add' command.
  • Run the bigip_add script from the local BIG-IP DNS system when adding a BIG-IP LTM system to the wide IP configuration. To run the bigip_add script, log in with root privileges to the command line of the BIG-IP DNS system and use the following command syntax to a BIG-IP LTM Self-IP address:
    • bigip_add <BIG-IP_IP_address>
      or
    • bigip_add <username>@<existing_DNS_or_LTM_IP_address>
  • The bigip_add script defaults to using the login name of the currently logged-in user to connect to the remote system. To specify a specific login name use the syntax username@ip.address , for example:
    • bigip_add <username@BIG-IP_IP_address>
      bigip_add user@10.0.0.1
      bigip_add root@10.0.0.1
  • If the remote user's shell is tmsh (this will always be the case if the remote device is running in 'appliance mode'), you must also specify the -a switch, to tell bigip_add to use tmsh commands to exchange certificates.  Since the 'root' user is not accessible in appliance mode, a username must also be specified if the -a (appliance mode) switch is used.
    • bigip_add -a user@x.x.x.x

Recommendations

  • To prevent unexpected results, F5 recommends following the use case and specific guidance for each DNS configuration script.
