Description

Low available memory on an F5 BIG-IP device can lead to various issues, one of which is the Out of Memory (OOM) killer being triggered. The OOM killer is a process that forcibly terminates other processes to free up memory when the system runs low on resources. This can sometimes cause a failover if a critical process is killed, impacting the overall performance and stability of the device.

Environment

  • BIG-IP LTM
  • Or multiple modules provisioned

Cause

The most common reasons for the OOM killer being triggered include insufficient memory on the device or an imbalance in memory allocation between TMM and the system management processes. If too much memory is allocated to TMM, and there is not enough left for the system to operate smoothly, problems arise. This is especially important when multiple modules are provisioned, as they consume significant system memory. In environments with low traffic, TMM may not need a large amount of memory, while the system and other modules may require more.

Recommended Actions

To prevent this issue, you need to check the available memory on the device and adjust the allocations as needed.

1. Run the following command to view memory usage:

tmsh show sys memory

Example output:

------------------------------------------------------------
Sys::Host Memory (bytes)
------------------------------------------------------------
Host: 0
Available 15.7G
Used 10.1G
-------------------------------------------------------
Sys::TMM Memory (bytes)
-------------------------------------------------------
TMM: 0.0
Available 4.9G
Used 742.4M 

Host Available: This indicates the total memory available for use by the device, for example,15.7G.

TMM Available: This is the memory allocated specifically for TMM (e.g., 4.9G). It’s important to note that system management cannot use the memory allocated to TMM.

2. Analyze Memory Allocation: 

Subtract the TMM allocated memory (4.9G) from the Host Available memory (15.7G). This leaves 10.8G for system use. Check the Host Used memory. If it’s high, such as 10.1G, this means only 0.7G of memory is left, which might not be enough for certain operations, potentially triggering the OOM killer.

3. Adjust Memory Allocation

In this scenario, too much memory is allocated to TMM. In this case you should consider increasing the memory available to the management system. Please follow the instructions in the article below to allocate extra memory for management and adjust the memory size as needed: K26427018: Overview of Management provisioning

By reallocating memory and ensuring a balanced distribution, you can prevent the OOM killer from being triggered and improve the overall performance of your BIG-IP device.
