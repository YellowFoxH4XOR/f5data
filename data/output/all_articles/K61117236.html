K61117236: After BIG-IQ upgrade, have observed frequent root logins from some services even if no one logs in to devices

Type
Support Solution
Published
2021-10-20
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IQ Platforms
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K61117236

Description

After upgrading BIG-IQ to 7.1 software version or higher, you may start seeing root login attempts from the secondary system every 10 minutes:
 
Jun 25 13:00:03 <hostname> info sshd(pam_audit)[23621]: 01070417:6: AUDIT - user root - RAW: sshd(pam_audit): user=root(root) partition=[All] level=Administrator tty=ssh host=<secondary_ip_addr> attempts=1 start="<start_date>" end="<end_date>".
Jun 25 13:10:02 <hostname> info sshd(pam_audit)[25790]: 01070417:6: AUDIT - user root - RAW: sshd(pam_audit): user=root(root) partition=[All] level=Administrator tty=ssh host=<secondary_ip_addr> attempts=1 start="<start_date>" end="<end_date>".

Environment

  • BIG-IQ upgrade to 7.1 or higher
  • BIG-IQ HA

Cause

In BIG-IQ version 7.1, the database has been converted and it's necessary to ensure that the primary BIG-IQ does not run out of space in /var because of a build-up of the database write ahead logs (WAL).
There is a script executed every ten minutes via cron on both the primary and secondary, but the secondary needs to login to the primary to get some of the information. The code checks to see if it is the primary device and if not uses ssh to get the current space of /var on the primary BIG-IQ.

Recommended Actions

The behavior seen is expected by design. However, we strongly recommend to keep monitoring secure logs for potential unexpected / unwanted login attempts.
