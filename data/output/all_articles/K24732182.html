K24732182: Network route matching management network is not honored after software upgrade

Type
Support Solution
Published
2021-03-31
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K24732182

Description

If there is a tmm route that matches the management network, the traffic which was routed to management route before upgrade will be routed to tmm route after upgrading to 12.1.3.2 or later.

Environment

  • You have a tmm route created in 12.1.3.1 or earlier software version, which matches management network. 

    For example;

    sys management-ip 10.1.1.241/24 {
        description configured-statically
    }
    net route test {
        gw 10.1.20.254
        network 10.1.1.0/24
    }

    The route defined by ‘test’ above sends any traffic to 10.1.1.0/24 via a TMM interface to the gateway 10.1.20.254 prior to upgrade.
     

    # ip -f inet route show
    10.1.1.0/24 via 10.1.20.254 dev internal
     

  • Upgraded software version to 12.1.3.2 or later

 

Cause

This behavior change after upgrade is due to the fix of Bug ID 645723.

Recommended Actions

  1. Avoid a tmm route that matches management network.

  2. Define a tmm route that is more specific than management network. 

    For instance, if the management network is 10.1.1.0/24, it is possible to define a more specific tmm route 10.1.1.0/25 in the example above.

Additional Information

  • After upgrading software to 12.1.3.2 or later,  the traffic to 10.1.1.0/24 is sent via management interface.

    # ip -f inet route show
    10.1.1.0/24 dev eth0  proto kernel  scope link  src 10.1.1.241
     
  • Also, attempting to create a route matching management network results in a warning message on 12.1.3.2 or later.

    # tmsh create net route test gw 10.1.20.254 network 10.1.1.0/24
    There were warnings:
    The route (10.1.1.0/24) matches management network for 10.1.1.241/24, not adding it to the kernel.
