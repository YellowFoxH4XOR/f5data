Topic

This article describes the new BIG-IP SSL/TLS intelligent rate-limiting feature. F5 product development tracks this as ID 1935053.

Description

Beginning from the following BIG-IP versions, F5 introduces a new BIG-IP SSL/TLS intelligent rate-limiting feature:

  • 21.0.0
  • 17.5.1.3
  • 17.1.3
  • 16.1.6.1

SSL connections are susceptible to sudden SSL connection spikes and crypto queue saturation. This could lead to degraded service availability due to SSL handshake disruptions. The new SSL/TLS intelligent rate-limiting feature protects TMM (Traffic Management Microkernel) from SSL/TLS crypto queue exhaustion during high load conditions. 

  • Operation behavior
  • Configuration parameters

Operation behavior

The system monitors pending crypto operations and handshake completion rates to detect and mitigate overload situations as follows:

  • Stage 1: Normal Operation
    When pending crypto operations remain below the configured threshold (2048), the system operates normally with no restrictions.

  • Stage 2: Queue Overflow Detection
    When the pending crypto operations exceeds tmm_ssl_crypto_queues_max* the system:
    • Records the current timestamp.
    • Captures a snapshot of total handshakes completed.
    • Enters monitoring mode for the configured grace period tmm.ssl.cryptoexceedtime* (1 second).
    • No connections are rejected during this initial grace period.
    *For more information, refer to the Configuration Parameters section.
  • Stage 3: Sustained Overload Analysis
    After the grace period expires, if the queue remains overloaded, the system:
    • Calculates the handshake completion rate where:
      Completion rate = (Handshakes completed since overflow) / (Time elapsed)
    • Compares the completion rate against a health threshold where:
      Threshold = Current active handshakes / 100 (1% of active handshakes)

  • Stage 4: Protection Action
    If the completion rate falls below a 1% threshold, the system:
    • Determines that TMM is experiencing crypto starvation
    • Rejects new SSL/TLS connections with SSL_A_INTERNAL_ERROR
    • Logs a diagnostic message in /var/log/ltm containing the following:
      • Current pending crypto operations count
      • Per-TMM queue limit
      • Handshake completion rate
      • Current active handshakes count
    If the completion rate exceeds the 1% threshold, the system:
    • Determines TMM is recovering.
    • Resets the monitoring state.
    • Resumes normal operation.
  • Stage 5: Automatic Recovery
    When pending crypto operations drop below the threshold, the system:
    • Resets the monitoring state immediately.
    • Resumes normal operation.
    • Accepts new connections normally.

Configuration parameters

The new feature introduces 2 new database variables:

  • sys db tmm.ssl.cryptoqueuemax (default: 2048)
    Maximum allowed pending crypto operations per TMM instance before triggering overload detection.
  • sys db  tmm.ssl.cryptoexceedtime(default: 1 second)
    Grace period to wait after queue overflow is detected before evaluating.

For more information on configuring BIG-IP Database Variables, refer to K16953: BIG-IP system database variables are automatically saved when modified.
