K000161160: False Interface Error Alarms Triggered by Incorrect SNMP OID Monitoring on BIG-IP LTM

Type
Support Solution
Published
2026-05-07
Updated
2026-05-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161160

Description

Persistent interface error alarms are reported by a third-party monitoring tool when monitoring a BIG-IP LTM device. No actual interface errors or service impact are observed. The monitoring tool is configured to use the SNMP OID for interface operational status (ifOperStatus), which is not intended for monitoring interface errors or drops. This misconfiguration leads to false alarms.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1
  • Monitoring Tool: VUNET systems (third-party)
  • SNMP OID used: IF-MIB::ifOperStatus
  • No observed service impact or actual interface errors

Cause

The monitoring tool is using the SNMP OID for interface operational status (ifOperStatus), which only provides the current operational state of the interface (e.g., up, down, testing) and does not track interface errors or drops. The tool misinterprets status changes as error events, resulting in false alarms.

Answer/Recommended Actions

  1. Update the monitoring tool configuration to use the correct SNMP OIDs for interface error and drop counters, not ifOperStatus.
  2. If monitoring interface operational status is required, ensure the tool interprets the OID as a status indicator (not as a counter).
  3. If the tool cannot be reconfigured to interpret the OID correctly, switch to monitoring the appropriate SNMP OIDs for packet drops/errors.
  4. No changes are required on the BIG-IP device itself.

Additional Information

  • The restjavad-api-usage.json file may grow large and cause issues with SNMP and CPU usage. Clearing this file as per F5 article K000153118 is recommended if you encounter related restjavad issues. There is no adverse effect from clearing this log file.
  • The absence of interface events in qkview logs after a certain date may be due to log truncation or suppression, but no service impact was observed.
