K50114129: BIG-IQ remote authenticated users are unable to log in for thirty minutes after the RADIUS server is unavailable

Type
Knowledge
Published
2019-07-15
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K50114129

Issue

Description

BIG-IQ remote authenticated users are unable to log in to the BIG-IQ user interface when the RADIUS authentication provider (server) is unavailable. When the RADIUS server becomes available, the BIG-IQ users continue to experience login errors similar to the following example:

All radius servers are unavailable.

Environment

  • BIG-IQ runs versions prior to 5.3.0
  • Configuration uses one or more RADIUS authentication providers
  • All configured RADIUS authentication providers are unavailable at some point

Cause

When a RADIUS server fails to respond to an authentication attempt, the BIG-IQ system stops trying that server until the retry timer expires. The default timeout is thirty minutes. This setting is not configurable from the BIG-IQ user interface.

Recommended Actions

The retry timer is set by the failBackIntervalMinutes variable via the iControl REST API. You can modify this variable to a value appropriate for your environment using iControl REST. To do so, perform the following procedure:

  1. Log in to the command line of the BIG-IQ system.
  2. Determine the value set for the failBackIntervalMinutes variable by locating it in the RADIUS configuration using the iControl REST command:

    restcurl /cm/system/authn/providers/radius

    Output appears similar to the following example:

    In this example, note the failBackIntervalMinutes variable is set to 30 minutes. Also, note the selfLink variable for the configured RADIUS server ("selfLink": "https://localhost/mgmt/cm/system/authn/providers/radius/fb6d6083-5fa5-4d6a-8025-3a62eb247496") which you would need to set the failBackIntervalMinutes variable for the next step.

  3. Modify the value of the failBackIntervalMinutes variable as needed by using the following iControl REST command syntax:

    restcurl -X PATCH -d '{"failBackIntervalMinutes": <desired timeout value in minutes>}' <selfLink for the RADIUS server object>

    Using the example output from the previous step, enter the following iControl REST command to set the variable to zero (0) minutes:

    restcurl -X PATCH -d '{"failBackIntervalMinutes": 0}' /cm/system/authn/providers/radius/fb6d6083-5fa5-4d6a-8025-3a62eb247496

    Verify from the output that the variable has been set to your desired value.

Additional Information

Due to a refactor of the authentication provider feature in ID 652270, the previous behavior where the BIG-IQ system stops trying an unavailable RADIUS server until the retry timer expires will no longer be valid in BIG-IQ 5.3.0 and later. As a result, the failBackIntervalMinutes variable no longer exists in these later versions. You should not attempt the procedure in the Recommended Actions section on BIG-IQ 5.3.0 and later.
