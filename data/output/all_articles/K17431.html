Known Issue

Secure Web Gateway (SWG) may stop processing traffic when the urldb plug-in is unavailable.

This issue occurs when all of the following conditions are met:

  • The SWG system is configured as an explicit proxy with URL categorization.
  • The plug-in channels used for URL categorization internal communication are unable to activate properly.

Impact

The SWG system stops processing traffic and resets active connections.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users lose connectivity to resources when traversing the SWG system.
  • Messages appear in the /var/log/ltm file similar to the following example:

    err tmm[11998]: 01480024:3: Can't bind the flow, waiting for config response on channel mem://urldb0

Workaround

To work around this issue, you can edit the /etc/bigstart/scripts/urldb file and restart the urldb process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line interface.
  2. Use the vi editor to modify the /etc/bigstart/scripts/urldb file by typing the following command:

    vi /etc/bigstart/scripts/urldb
  3. Locate the following line of code:

    TMPLUGIN_SCHEDULER=`getdb tmplugin.scheduler`
  4. While in the vi editor mode, change the code from step 3 to the following:

    #TMPLUGIN_SCHEDULER=`getdb tmplugin.scheduler`
    TMPLUGIN_SCHEDULER="hrsleep"
  5. To save your change and exit the vi editor, type the following command:

    :wq!

    Note: This command requires you to type the colon (:) character, enter the wq! string and then press the Enter key.
  6. Restart the urldb process by typing the following command:

    bigstart restart urldb
