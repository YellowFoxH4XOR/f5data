Description

SAML authentication fails with a time skew error message.

  • Users fail SAML authentication.
  • You observe the following error in /var/log/apm:
SAMLAgent:/Common/<access_policy_name>_act_saml_auth_ag SAML assertion is invalid, error:Date/Time verification failed.Check assertion date/time values and clock skew between IDP and SP

Environment

  • Access Policy Manager (APM)
  • APM configured as Service Provider (SP) or Identity Provider (IdP).
  • External SP or IdP.

Cause

The cause of this issue is the time skew between the SP and IDP is greater or less than the value that is configured in the assertion for the NotOnOrAfter or NotBefore attributes.The SAML response will have a similar line with these configured values:

<saml:Conditions NotBefore="2014-07-17T01:01:18Z" NotOnOrAfter="2024-01-18T06:21:48Z">


Recommended Actions

1. Login to the Big-IP via console.
2. Verify the time with date;hwclock command: 

[root@apm88:Active:Standalone] config # date;hwclock
Wed Sep 18 19:29:35 PDT 2019
Wed 18 Sep 2019 12:29:36 PM PDT  -0.005422 seconds

3. Verify NTP is functioning correctly using the ntpq -np command:

[root@apm88:Active:Standalone] config # ntpq -np
     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
 172.24.101.216  .XFAC.          16 u    - 1024    0    0.000    0.000   0.000

4. Set the time with the ntpdate -bu command:

[root@apm88:Active:Standalone] config # ntpdate -bu 10.154.165.94
18 Sep 19:35:03 ntpdate[23273]: step time server 10.154.165.94 offset 26.063097 sec

5. If no NTP servers can be successfully reached manually set the time with the date command:

date <month><day><hour><minute><year>.<second>

Additional Information

On VIPRION systems with multiple blades, make sure that date is same on all blades.
