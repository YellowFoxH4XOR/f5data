K62336401: REST API calls fail with 401 Authentication Failed with LDAP User Template

Type
Support Solution
Published
2021-03-31
Updated
2025-04-02
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K62336401

Description
Starting in version 14.1.0, all REST API calls made using token-based authentication with LDAP (or Active Directory) remote authentication utilizing a User Template fail, reporting 401 Authentication failed. All versions except 14.1.3.x and 16.0 also experience the same failure for REST API calls made using basic authentication as well.

Configuration Utility (GUI) and shell access is not affected by this specific bug.

Environment

  • BIG-IP version 14.1.0 and later
  • LDAP (or AD) remote authentication configured with User Template
  • REST API calls with basic or token-based authentication

Cause
Due to changes in the underlying components in 14.1.0, LDAP/AD remote authentication with User Template can no longer successfully authentication and authorize REST API calls. This applies to both basic authentication and token-based authentication modes for REST API. This is documented in ID 872165. When a REST API call is made with under this specific condition, it will fail receiving a 401 Authentication failed message. /var/log/restjavad.x.log may report messages similar to the following:
-- [I][1978][26 Mar 2021 13:23:36 UTC][8100/shared/authn/login AuthnWorker] User remoteuser failed to login from 192.0.2.1 using the tmos authentication provider
-- [WARNING][807][26 Mar 2021 14:43:24 UTC][RestOperationIdentifier] Failed to validate Authentication failed.

When this occurs, SSH/shell and Configuration Utility (GUI) logins will be unaffected and work successfully.

Recommended Actions

  1. Change the LDAP/AD Remote authentication from using a User Template to using a Bind account instead
  2. Create local user accounts for each user that will make REST API calls, with the proper role for that user configured in the local account

Additional Information
REST API basic authentication can work in this configuration for 14.1.3.x and 16.0 however due to the presence of this bug utilizing this configuration is not recommended. Instead, one of the two workarounds should be utilized to ensure a consistent experience across all software versions 14.1.0 and later.
