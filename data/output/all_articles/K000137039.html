K000137039: Ingress Gateway shows IPv4 instead of IPv6

Type
Support Solution
Published
2023-09-29
Updated
2023-09-29
Applies to
  • Aspen Mesh: 1.14
Source

Description

IPv4 address shows up first in the Service description output instead of the IPv6 address when using Aspen Mesh with dual-stack enabled.
 

Environment

Aspen Mesh 1.14.6-x, Dual-Stack enabled, Dual-Stack Ingress Gateway
 

Cause

ipFamilies order in the Service spec dictates what IP is used for .spec.ClusterIP
 

Recommended Actions

Change the order of the IP families in the service.yaml template file located at aspenmesh-carrier-grade-1.14.6-am*/manifests/charts/gateways/istio-ingress/templates/service.yaml by inverting the order of the ipFamilies:

##Original##
spec:
{{- if .Values.global.ingressGatewayDualStack }}
  ipFamilyPolicy: RequireDualStack
  ipFamilies:
  - IPv4
  - IPv6

##Change it to##
spec:
{{- if .Values.global.ingressGatewayDualStack }}
  ipFamilyPolicy: RequireDualStack
  ipFamilies:
  - IPv6
  - IPv4

 

Additional Information

RequireDualStack - Allocates Service .spec.ClusterIPs from both IPv4 and IPv6 address ranges.

  • Selects the .spec.ClusterIP from the list of .spec.ClusterIPs based on the address family of the first element in the .spec.ipFamilies array.

If you would like to define which IP family to use for single stack or define the order of IP families for dual-stack, you can choose the address families by setting an optional field, .spec.ipFamilies, on the Service.

Note: The .spec.ipFamilies field is conditionally mutable: you can add or remove a secondary IP address family, but you cannot change the primary IP address family of an existing Service.


You can set .spec.ipFamilies to any of the following array values:

  • ["IPv4"]
  • ["IPv6"]
  • ["IPv4","IPv6"] (dual stack)
  • ["IPv6","IPv4"] (dual stack)

The first family you list is used for the legacy .spec.ClusterIP field.
