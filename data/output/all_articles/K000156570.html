K000156570: Unable to log into rSeries appliance and tenants down - messages.log at extremely large file size

Type
Support Solution
Published
2025-09-22
Updated
2025-09-22
Applies to
  • F5OS
  • F5OS-A: 1.7.X, 1.7.0
Source
https://my.f5.com/manage/s/article/K000156570

Description

After a reboot, an rSeries appliance may become partly inaccessible with users not being being able to log into the unit via the web gui or the cli, with only the "root" account being able to log in; and the tenants are also down.

Environment

  • Product: F5OS - Appliance
  • Platform: rSeries

Cause

If /var/log/messages.log is inadvertently selected as a source for system logging host-logs, a logging loop can occur that causes the messages.log file to grow uncontrollably. This fills up the filesystem and renders the system unusable with needed services unable to start. This issue is related to Bug ID 1296997 and Bug ID 1588093.

Recommended Actions

  1. Check Log File Size:
    Verify the size of /var/log/messages.log. If it is excessively large (e.g., >80GB), it is safe to delete this file to free up space.
  2. Remove Problematic Logging Configuration:
    Ensure that /var/log/messages is not configured as a source for system logging host-logs. Remove or correct any such configuration.
  3. Clear the Log File:
    If possible, log in as root (may require disabling appliance mode) and delete or truncate the messages.log file.
    If unable to log in normally, boot into single user mode and manually delete the log file which will be located in /sysroot/sysroot/ostree/deploy/velocity/var/log.
  4. Monitor System State:
    After the log file is deleted, the system should come up by itself with no further action, deploy the tenants and monitor.
