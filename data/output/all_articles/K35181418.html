K35181418: How to restrict SSH access to the F5OS

Description

Important: The content in this article applies to earlier F5OS-C and F5OS-A versions that have reached End of Technical Support (EoTS). For information about restricting SSH access to F5OS systems using the Allow IP Addresses feature, refer to the following articles:

  • K000138750: Configure the Allowed IP Addresses on the VELOS system
  • K000134482: Configure the Allowed IP Addresses on the F5 rSeries system

There is not a way to restrict SSH access to the F5OS so far.
SSH port (22) does not exist in the Allow List (WebUI: SYSTEM SETTINGS-> Allow List).

Environment

  • F5OS

Cause

This is by design.

Recommended Actions

We have a workaround.

The suggestion is to use the /etc/hosts.allow and /etc/hosts.deny config files to restrict the addresses that sshd will accept connections from.

VERY IMPORTANT:
  1. You must not block ssh from connecting from the localhost over the loopback interface (for both ipv4 and ipv6) (that's what the ALL EXCEPT line in hosts.deny is for)
  2. You must not apply this workaround to a VELOS chassis - this will only work for rSeries (vanquish) devices.

For example, if you wants to restrict ssh access to devices on these three subnets:

   10.50.0.0/16
   192.168.0.1/24
   1.2.3.0/24

Then you should log in as root to their rSeries device, and edit the following files.

   /etc/hosts.allow
   sshd:  10.50.0.0/16 192.168.0.1/24 1.2.3.0/24                 # Allow SSH from these subnets

   /etc/hosts.deny
   sshd: ALL EXCEPT 127. [::1]/128                               # Deny from ALL other sources, EXCEPT for ipv4/ipv6 loopback

If you accidentally block ssh access to themselves, they can log in as root via the console cable to fix it.
