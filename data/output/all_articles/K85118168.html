Description

OneConnect profile does not work properly if the server actively closes the connection.

Environment

  • LTM virtual server 
  • OneConnect profile enabled

Cause

The OneConnect feature can increase network throughput by efficiently managing connections established between the BIG-IP system and back-end pool members. The OneConnect feature utilizes HTTP keep-alive to minimize the number of TCP connections to servers by making existing connections available for reuse by other clients.

For example, when a client initiates a new connection to a BIG-IP virtual server configured with a OneConnect profile, the BIG-IP system parses the incoming HTTP request, selects a server based on the configured pool load-balancing method, and establishes a new connection to the selected server only if no suitable idle connection exists. After the client’s HTTP request is completed, the BIG-IP system keeps the existing server-side TCP connection idle and ready for reuse by subsequent client requests.

However, if the server actively closes the TCP connection—by initiating TCP FIN or sending a TCP reset—the BIG-IP system cannot reuse this connection. As a result, performance might degrade under certain circumstances, as the expected benefit of connection reuse cannot be achieved.

Recommended Actions

When using the OneConnect profile on a BIG-IP virtual server, ensure the back-end server is configured to avoid actively closing connections. Servers should honor HTTP keep-alive connections and rely upon the BIG-IP system to handle idle connection management.
