K000161894: Clone Pool Behavior with SSL Offloading vs. SSL Bridging on BIG-IP LTM

Type
Support Solution
Published
2026-06-25
Updated
2026-06-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000161894

Description

Clone pool members on BIG-IP LTM receive decrypted traffic when the virtual server is configured for SSL offloading, but receive encrypted traffic when the virtual server is configured for SSL bridging. 

Environment

  • Product: BIG-IP LTM
  • Virtual servers configured for SSL offloading and SSL bridging
  • Clone pool configured for both types of virtual servers

Cause

This behavior is by design. When a virtual server is configured for SSL bridging, the server-side connection remains encrypted, and the traffic copied to the clone pool is also encrypted. For SSL offloading, the traffic is decrypted before being sent to the clone pool.

Answer/Recommended Actions

  • No standard configuration change is available to alter clone pool behavior for SSL bridging.

Additional Information

  • BIG-IP copies traffic to the clone pool from TMM when it is ready to be sent to the backend server. If the server-side connection is encrypted (SSL bridging), the copied traffic remains encrypted.
  • This is expected behavior and not a defect or misconfiguration.
