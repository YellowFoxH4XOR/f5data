K000149701: Allow Local Subnet feature may not work properly if clients use non-private IP addresses as Local NIC IP addresses

Type
Support Solution
Published
2025-02-12
Updated
2025-07-13
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP APM: 17.0.0, 17.1.1, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2
Source
https://my.f5.com/manage/s/article/K000149701

Description

Network Access Allow Local Subnet feature may not work properly if clients use non-private IP addresses as Local NIC IP addresses. During this problem, the below kind of logs will be observed in client-side logs (%temp%\logtermainal.txt):

The connected network is vulnerable of tunnel crack as LocalIP falls under the public IPs 
IP VulnerableIP Property NetworkVulnerableIPv4Addresses1 and IPAddress = <IP address>
AllowLocalSubnet = FALSE, Vulnerable Local interface IP is part of Vulnerable list, so do not add allow local subnet entry for it, <IP address>

Please note that the VPN tunnel establishment process should be completed successfully.

Environment

BIG-IP APM

APM Client 7246 or later

Network Access resource configured with Allow Local Subnet option enabled (this is disabled by default)

Cause

The issue occurs due to a security enhancement addressing the TunnelCrack vulnerability (CVE-2023-43124). In newer APM client versions, stricter checks are applied to prevent local subnet traffic from bypassing the VPN tunnel unless explicitly allowed.

Answer/Recommended Actions

If clients have private IP addresses (RFC 1918) as local NIC IP addresses, the Allow Local Subnet feature should have no problem.

If clients have non-private IP addresses as local NIC IP addresses and the APM administrator wants to use the Allow Local Subnet feature, disable the check by following steps:

(1) Download the connectivity content profile by navigating to Navigate to https://apm-vs-fqdn/pre/config.php?version=2.0 (e.g. using a browser or the curl command => You will get the XML payload. (use your VPN FQDN in place of the placeholder "apm-vs-fqdn")

[Quick Linux command example]
curl -k https://apm-vs-fqdn/pre/config.php?version=2.0 -o original-cp.xml
cp original-cp.xml modified-cp.xml

(2) Modify the XML payload [modified-cp.xml] by inserting the below tags (Just before "</FEATURES></PROFILE>" string):

<LocalNetCheck><LocalNetCheckEnabled>False</LocalNetCheckEnabled></LocalNetCheck></FEATURES></PROFILE>

The final modified XML payload will look like this:

<?xml version="1.0" encoding="utf-8"?>
<PROFILE VERSION="2.0">

[ ... snip ... ]

<FEATURES><HEADER_COOKIE>YES</HEADER_COOKIE><LocalNetCheck><LocalNetCheckEnabled>False</LocalNetCheckEnabled></LocalNetCheck></FEATURES></PROFILE>

(3) Create an iRule:

when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable
}
 
when HTTP_REQUEST {
    if { [HTTP::uri] contains "pre/config" } {
        # replace "XML_Modified_Payload" with the content of the modified XML file from step (2) 
        # or the customer can simply use the modified file of step (3) (will be a bit ugly code)
        set xmlPayload1 {XML_Modified_Payload}  
 
        set xmlPayload $xmlPayload1
        HTTP::respond 200 content \
        $xmlPayload \
        "Content-Type" "application/xml"
    }
}

(4) Attach the above iRule to the APM virtual server.
