Topic

You should consider using this procedure under the following condition:

  • You want to disable an attack signature for a URL using an iRule.

Description

In some cases you may want to disable an attack signature for a URL and forward the request to the origin web server (OWS). For example, while building the security policy, you may want to disable a specific attack signature for a URL while leaving the signature enabled for other URLs. To do so, you can use the ASM::unblock iRules command.

Beginning in BIG-IP 13.x, you can disable an attack signature for a URL using the Configuration utility. For more information, refer to K8866: Disabling attack signature checks for specific objects.

The following applies to using the ASM::unblock iRules command:

  • Violations from an unblocked request do not generate learning suggestions.
  • The ASM::unblock iRules command applies only to requests.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.
  • You have identified the specific attack signature that you want to forward to the OWS.

Procedures

  • Enable BIG-IP iRules events
  • Determine the attack signature name and ID
  • Define the iRule to disable a specific attack signature for a URL

Enable BIG-IP iRules events

Before you configure the iRule to disable a specific attack signature for a URL, you must enable BIG-IP ASM iRules events for the security policy. To do so, perform one of the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Enable BIG-IP ASM iRules events (BIG-IP 15.1.x and later)

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the policy that you want to edit.
  4. Select the General Settings tab.
  5. For Trigger ASM iRule Events Mode, select Normal.
  6. Select Save.
  7. Select Apply Policy.

Enable BIG-IP ASM iRules events (BIG-IP 14.x and later)

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the policy that you want to edit.
  4. On the Policy Properties tab, select Advanced.
  5. For Trigger ASM iRule Events, select Normal Mode.
  6. Select Save Changes.
  7. Select Apply.

Enable BIG-IP ASM iRules events (BIG-IP 12.x through 13.x)

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy > Policy Properties.
  3. Verify that the policy you want to edit displays in the list below the tabs.
  4. Set the policy properties view to Advanced.
  5. For Trigger ASM iRule Events, select Enabled.
  6. Select Save.
  7. Select Apply Policy.

Determine the attack signature name and ID

To determine the signature name and ID, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule list.
  3. Select Create.
  4. Enter a name for the iRule.
  5. For Definition, enter the following iRules code:

    when ASM_REQUEST_DONE {
    log local0. "ids=[ASM::signature ids] names=[ASM::signature names]"
    }

  6. Select Update.
  7. Associate the iRule with the appropriate virtual server.
  8. Send a request to the virtual server that triggers the attack signature.
  9. Log in to the BIG-IP command line and search for the name of the signature.

    For example:

    grep -i signature /var/log/ltm

    The following log entry shows an example of a signature ID and name:

    info tmm[25875]: Rule /Common/signature_name <ASM_REQUEST_DONE>: ids=200021075 names={Automated client access ""curl""}

  10. After you determine the signature ID and name, you can remove the previously described iRule from the virtual server configuration.

Define the iRule to disable a specific attack signature for a URL

To disable a specific signature for a URL using an iRule, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule list.
  3. Select Create.
  4. Enter a name for the iRule.
  5. Define the iRule that disables the attack signature for the URL.

    For example, the following iRule disables the attack signature ID 200021075 (Automated client access "curl") for URLs containing /index.php:

    when ASM_REQUEST_DONE {
    if {[ASM::violation names] contains "VIOLATION_ATTACK_SIGNATURE_DETECTED" and [string tolower [HTTP::uri]] contains "/index.php" and [ASM::violation details] contains "200021075"}
    {
    ASM::unblock
    log local0. "ASM unblocking [HTTP::uri]"
    }
    }

  6. Select Create.
  7. Associate the iRule with the virtual server.
