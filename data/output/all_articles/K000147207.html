K000147207: What to suspect when 503 errors occur upon migration to F5® Distributed Cloud load-balancer

Type
Support Solution
Published
2024-11-08
Updated
2024-11-08
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000147207

Description

  • After migrating a web service to F5® Distributed Cloud load-balancers, every request ends up in a 503 error.
  • In analytics, logs say upstream_reset_before_response_started{connection failure} for every request, or at least for all the requests targeting an origin pool.

Environment

  • Distributed Cloud (SaaS)
  • F5® Distributed Cloud load-balancer

Cause

Although there may be multiple reasons, a common one for these symptoms is a TLS handshake problem between the load-balancer and the origin web server. The load-balancer is using higher security settings by default (either TLS version or Cipher suites), and that breaks the negotiation with the origin web server.

Resolution

  • Visit the load-balancer configuration (in "Apps" tab, choose the matching namespace, then navigate to "Manage > Load-balancer > HTTP Load-balancer"), and find the origin pool(s) that it's attached to.
  • Now that you have identified the origin pool(s), visit its configuration ("Manage > Load-balancer > Origin pools" in the same namespace), and find the section "TLS configuration".
  • By default, the parameter "TLS Configuration for Origin Servers" is set to High, change it to "Medium", then click on "Save and exit".
  • Try to reproduce the request that failed. If it still fails, find out what version of TLS and what Cipher suites the origin server supports, and adjust the setting accordingly, using the "Custom" option if necessary.

More information on what Cipher suite is supported as part of any of these levels in the F5® Distributed Cloud TLS reference.
