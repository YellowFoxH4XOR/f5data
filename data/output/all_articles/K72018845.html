Description

How to block an ASM request with a certain violation rating

Environment

  • BIG-IP ASM  version 14.x+

Cause

This feature is not currently available via Configuration Utility (GUI) or TMSH.  It can be accomplished by iRule in v14.0.0+.

Recommended Actions

Note: The violation rating should be interpreted as a confidence score not a measure of severity thus a request with a rating of 1 could be more impacting than a request with a rating of 5 in a certain environment.

  1. Enable ASM iRule events for the ASM policy:
    • Security ›› Application Security : Security Policies : Policies List :: Policy Properties tab >> "Trigger ASM iRule Events" :: Normal Mode
       
  2. Create a User-Defined Violation for violation rating exceptions:
    • Security  ››  Options : Application Security : Advanced Configuration : Violations List  >>   User-Defined Violations :: Create...
    • Violation Name: VIOLATION_RATING_EXCEEDED
    • Violation Title: Violation Rating Exceeded
    • Type: Unspecified
    • Severity:  Alert
    • Attack Type: Other Application Activity
    • Description:  <As desired>
       
  3.  Set appropriate Alarm and Blocking settings for the new custom violation in the ASM policy:
    • Security  ››  Application Security : Policy Building : Learning and Blocking Settings  >>  Custom Violations
       
  4. Reference the following example iRule:

    when ASM_REQUEST_DONE {
        if {([ASM::violation rating] > 3)}{
            ASM::raise VIOLATION_RATING_EXCEEDED
        }
    }
     
  5. Apply the iRule to the virtual server.

Additional Information

  • ltm rule event ASM REQUEST DONE
  • ltm rule command ASM violation
  • ASM::severity
  • ASM::raise
  • Bug ID 691664: Violation rating is not exposed to the iRules
