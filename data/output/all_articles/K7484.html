Known Issue

The RAM Cache feature resets the resource Vary header values on HTTP 304 responses when Compression is enabled. The Vary header is used to determine which headers should be used to create the cache key. When the Vary header is reset, the RAM Cache may insert a Content-Encoding header into HTTP 304 responses when the RAM Cache receives a request with the If-Modified-Since header.

F5 Product Development tracked this issue as CR62309 and CR78821 and it was fixed in BIG-IP LTM 9.1.3, 9.3.1, and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You can use an iRule to disable RAM Cache when the BIG-IP LTM system receives a request with the If-Modified-Since header, and to ensure the If-Modified-Since header will be sent back to the server. To do so, create the following iRule:

when HTTP_REQUEST {
if { [HTTP::header exists If-Modified-Since] } {
CACHE::disable
}
