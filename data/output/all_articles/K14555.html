Topic

F5 has recently discovered and corrected a number of issues that affect customers who are running ARX 6.4.0. F5 recommends that all customers who are currently running ARX 6.4.0 install the latest cumulative rollup hotfix.

The following table lists the rollup hotfixes available for ARX 6.4.0. Each hotfix lists the ID number and description for the issues fixed by the hotfix:

Note: These rollup hotfixes are cumulative; each hotfix contains the fixes included in the previous hotfixes.

ARX VersionID NumberDescription

477263 When processing TREE_DISCONNECT and logoff requests in SMBv2, a transaction record lookup engaged SMBv1 database and caused NSM to dump core. The problem has been fixed.

463789When the SNMP Server Traps were not configured, a regression caused the system to not send most SNMP traps. The problem has been fixed. 
474478When processing a QUERY_PATH_INFO  request with a filer response of Not Found, an internal transaction was deleted prematurely and caused NSM to produce a core file. This problem has been fixed. 
474874A race condition in packet buffer memory allocation and de-allocation caused NSM to produce a core file. This problem has been fixed.

455979

458293
Fixed a problem where shadow copy failed and the policy daemon produced a core file because of an internal database sync error.
460101
A large number of snapshots hit an internal lock table limit and, as a result, caused degraded dNAS performance.  This problem has been fixed.
463300In the MPNS (multi-protocol namespace), a CIFS “delete directory” where the directory is a symlink to another directory caused DNAS to produce a core file. This problem has been fixed.
463811The Active Count in the output of CLI command “show active-directory status detailed” has been deprecated and removed.
   
**6.4.0 HFRU5
(build-15227)		384729 An OM_RECORD_READ_FAILED error was hit in the operation of “remove cluster-config”, due to a Database table synchronization issue. This problem has been fixed. 
441105 Fixed a problem where disabled “group snapshot” in an email-event was restored erroneously after the switch reboot.  
443070 When an SMBv2 Tree-Connect error was returned from the filer, it was not handled properly and that resulted in a Session ‘double free’ which caused NSM to produce a core file. This problem has been fixed.
443983During the process of an SMBv2 compound request for Query-Info, some internal records were not cleaned up completely, which caused NSM to produce a core file. This problem has been fixed.

446494 Creating a new share with an already existing share name in the volume resulted in a misleading error message FILER_CHANGE_WRONG_STATE.  This has been fixed to show FILER_ERR_DUPLICATE_SHARE_NAME for both CLI and GUI.

448986 In a destructive file rename operation of SMBv2, where the target name already existed, the operation failed and DNAS produced a core file. This problem has been fixed.
450039 The watchdog timeout logic for the NSM send packet buffer has been enhanced to avoid potential NSM coring.
   
**6.4.0 HFRU4
(build-15226)		432055When the ARX is under heavy load, disk I/O for Kerberos credentials could become the performance bottleneck. This problem has been fixed.
436625Due to lack of proper verification, an invalid session ID in a SMB2 connection was processed and caused NSM to produce a core file. This problem has been fixed.
436748Fixed a race condition in which two threads referenced the same pointer and caused dNAS to produce a core file.
438337The policy schedule “start” command did not adjust for daylight saving time correctly. This problem has been fixed.
442621A failure of IPC subsystem caused the NSM stats daemon to create a core file. This failure has been addressed.
   
**6.4.0 HFRU3
(build-15224)		415875 VCIFS could send an empty NOTIFY response to the client when there is no actual change made by the client. This problem has been fixed.
420764 Fixed the RON status page problem in the GUI where storage was erroneously displayed as degraded.
423285 An optimization change was made to improve the responsiveness of a CIFS directory listing.
425280 The policy process was failing to assign a share farm index when shares were re-imported, which was breaking file-constraints and directory-constraints. This problem has been fixed.
428848There was a packet buffer leak associated with certain SMB2 operations, which caused high NSM usage and NSM produces a core file.  This problem has been fixed.
429852 A firewall rule ‘add’ or ‘delete’ could fail due to a transient system error. A delay and retry mechanism has been added to prevent this from happening.
432684Some shortcomings in the IPC subsystem, which were used by the snapshot daemon, have been fixed to prevent potential snapshot failures.
   
**6.4.0 HFRU2
(build-15222)		411627Fixed a problem in the GUI where editing a place rule could result in a null pointer exception error.
420150 An option has been added to allow the Domain Controller health check to use In-Band IP instead of Proxy IP (XIP).
421140 Fixed a procdat message where shares are displayed in reverse order when root backing is promoted.
421753 Fixed a timing issue in the configuration database that can lead to Object Manager transaction leaks.
422834 NSM code has been enhanced to avoid an assertion failure and a core dump when an internal database object is corrupt.
422937 NSM encountered an assertion failure when trying to insert a CIFS transaction record into an internal database. NSM has been enhanced to avoid creating a core file in this scenario.
423185 A logic error that caused afnrootd to produce a core file has been fixed.
423461 A logic error in Network Lock Manager (NLM) could cause files to be locked by the NFS service for a long time. This problem has been fixed.
424144 An error in the calculation of message block size in NSM that could produce a core file has been fixed.
426182 The removal of a CIFS export could collide with an incoming connection request and result in an NSM core. This problem has been fixed.
428366Users experienced errors when changing the name of a file or directory using SMBv2. This problem has been fixed. 
428824 When a tentative migration fails, the total number of files and total size of the files in the file set are not reported. An option has been added that ignores the migration failure and allows the total number of files and total size of files to be calculated and reported.

(build-15220)		419045
A log handle leak problem that caused resource exhaustion and krbconfd to create a core file has been fixed.
419052
A race condition in the NSM between the filer reply process and an internal IPC thread could cause NSM to create a core file. This problem has been fixed.
419966

420465

420922
The dNAS code for multi-protocol namespace (MPNS) was updated to improve resiliency in the event of internal inconsistency.
420993
The virtual snapshot time-out did not use the value provided by term debug command ‘mgmt-cmd-timeout’. This has been fixed.
422346
In the NFS packet header parsing, the NSM failed to check the boundary properly when a packet contained more than two GIDs and caused NSM to produce a core file. This problem has been fixed.
422421
Using the GUI, it was possible to submit a Domain Join request without selecting any Delegation. This causes afnrootd to produce a core file. This problem has been fixed.
423365

423565When SMB2 is used in multi-protocol namespace (MPNS) and with directories containing NFS symbolic links, false metadata skews are reported in syslogs and in autosync reports.
423667
If a directory is removed at the same time the policy is evaluating a rule against it with SMB2, the policy can loop and result in high CPU usage and slow performance. This problem has been fixed.
424453
A client could encounter a network error when dragging and dropping a large number of files. This problem has been fixed.
