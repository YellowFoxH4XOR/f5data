Description

How to packet capture dns query and responses for a particular fqdn udp payload


Environment

DNS


Cause

How to Query the payload "ac-vpn" from ac-vpn.example.com


Recommended Actions

 

The UDP header is 8 bytes. Then on the UDP payload (actual DNS packet) we have transaction ID (2 bytes), flags (2 bytes), count (8 bytes). Only then starts the first query (QNAME, with label). Which is what we're interested to capture. (You can see this from wireshark as well.)


The offset for the QNAME (hostname) is at 20 bytes

Bearing in mind that tcpdump only allows to define 1, 2 or 4 bytes, so to capture any DNS queries and replies which hostname starts with "ac-vpn." we need to do the following;

# tcpdump -s0 -nni 0.0:nnn 'udp[20:4] = 0x0661632d and udp[24:4] = 0x76706e08'


 

0x0661632d -> ac-


0x76706e08 --> vpn

 

Can run a rotating tcpdump, by followng the method from https://my.f5.com/manage/s/article/K65251607.

Please note that running tcpdump might cause a spiked cpu usage and hence please be aware of https://my.f5.com/manage/s/article/K6546 for more info.

 

Another option is to use iRules to log DNS queries/responses - please refer https://my.f5.com/manage/s/article/K10554155 for some good info. Just bear in mind that, while you could attach an iRule directly to the WideIP (and not on the virtual-server), such iRules on WideIP do not support DNS_RESPONSE events. Only DNS_REQUEST. To log both DNS_REQUEST and DNS_RESPONSE, then you would need to create an iRule to be used at LTM level (virtual-server). Something such as:

 

when DNS_REQUEST {

 if { [DNS::question name] starts_with "ac-vpn" } {

   log local0. "LTM irule: DNS Request [DNS::question name] with record type of [DNS::question type] seen from [IP::client_addr]"

 }

}

when DNS_RESPONSE {

 if { [DNS::question name] starts_with "ac-vpn" } {

   log local0. "LTM irule: Client was provided with response [DNS::answer]"

 }

}

 

However, if this is to be used, then HSL would be a must (see https://clouddocs.f5.com/api/irules/HSL__open.html - namely, the two examples from "Examples" section). Basically replace the "log local" above with HSL method. Do *not* log locally. This option (iRule above + HSL) would also carry a small CPU increase. All options will. But this is actually quite a good option to perform such troubleshooting as we believe any CPU increase to be minimal/negligible.


Additional Information


To pull off any hostname starting with "ac-vpn" , can use the below syntax ;

# tcpdump -s0 -nni 0.0:nnn 'udp port 53 and udp[21:1] = 0x61 and udp[22:2] = 0x632d and udp[24:2] = 0x7670 and udp[26:1] = 0x6e'
