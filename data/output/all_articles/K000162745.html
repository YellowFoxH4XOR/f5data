K000162745: Mutual TLS (mTLS) connections can fail when the trusted CA bundle used by an SSL profile (client/server-SSL profile or both ) contains the intermediate CA certificate but not the corresponding root CA certificate

Applies to

Description

Mutual TLS (mTLS) connections can fail when the trusted CA bundle used by an SSL profile contains the intermediate CA certificate but not the corresponding root CA certificate.

Typical log messages include:

Unable to get certificate for peer cert issuer

Peer cert verify error: unable to get issuer certificate

Connection error: ssl_shim_vfycerterr:4514: alert(48) unable to get issuer certificate

The issue can cause invalid client-certificate handshakes and failed mTLS connections.

Environment

  • Product: BIG-IP LTM, v17.1.3.4 or v17.5.1.8
  • Feature: SSL/TLS certificate validation
  • Client SSL profile with peer-cert-mode set to require
  • Trusted CA bundle configured through the profile’s ca-file setting
  • Trusted CA bundle contains the intermediate CA that signed the client certificate
  • Corresponding root CA is not included
  • The behaviour can also affect Server SSL profiles when BIG-IP validates certificates presented by backend servers

Cause

A software issue can require the trusted CA bundle used for certificate validation to include the root CA in addition to all required intermediate CA certificates.

Answer/Recommended Actions

  1. Identify the trusted CA bundle configured on the affected SSL profile.
  2. Update the bundle to include:
    • The root CA certificate.
    • All required intermediate CA certificates in the trust chain.
  3. Save the updated bundle and associate it with the affected SSL profile.
  4. If backend certificate validation is enabled, make the equivalent update to the bundle used by the applicable Server SSL profile.
  5. Apply the configuration and test a new mTLS connection.
  6. Confirm that the following messages no longer occur:
    • unable to get issuer certificate
    • Unable to get certificate for peer cert issuer
  7. If updating the CA bundle is not acceptable, contact F5 Support to request an engineering fix.

Additional Information

  • The trust-bundle requirement can apply to both client-side and server-side certificate validation.
  • A CA bundle containing only an intermediate CA may not be sufficient for the affected validation behavior.
  • Ensure that the root CA is the correct trust anchor for the certificate chain presented by the client or backend server.
