Description

TCP connections are reset with a cause of F5RST: TCP closed, similar to the following example:

198.51.100.1 → 192.0.2.1 75 443 30659 TCP OUT s1/tmm0 : 443 → 30659 [RST, ACK] Seq=1 Ack=1 Win=0 Len=35 [F5RST: TCP closed]

Environment

  • TCP Standard virtual server

Cause

Bug ID 812693

A SYN connection attempt from a client matches a closed flow for that client in the connection table on the same port, and the server-side is in FIN/WAIT 2 state or in other words the server-side has not successfully closed the connection yet.

Recommended Actions

  • The first action would be to reduce the TCP profile option fin-wait-2-timeout to lower value.
    tmsh modify ltm profile tcp <tcp-profile-name> fin-wait-2-timeout <lower value>
  • Research known issues for your version of BIG-IP software
  • Open a case with F5 Support if you are unable to identify the issue

Additional Information

This should never occur under normal conditions, and when server side connections are closed in timely manner. Connections are cleared from the connection table when closed.

This is not exactly an issue on BIG-IP but rather on backend server for not closing its side of connection.
