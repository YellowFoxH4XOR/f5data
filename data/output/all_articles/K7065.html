Topic

You should consider using this procedure under the following conditions:

  • You want the BIG-IP system to use alternate servers when pool members are unavailable.

Description

Procedures

Using pool member priority groups

Use pool member priority groups to configure a pool with an alternate server or group of servers using a lower priority value than the primary server's priority values.

  • Set the Priority Group Activation setting to Less than, and then enter the number of members below which the system activates the group.

    When the number of available members in the highest priority group drops below the minimum number, the BIG-IP system distributes traffic to the next higher priority group as well.

    Note: With multiple priority groups enabled the traffic will be processed by all available members of  all enabled priority groups.

    Note: When the BIG-IP system activates a lower priority group and its pool members are processing connections, active and persisted connections continue to use the lower priority group pool members after a higher priority group becomes available. Connections to the lower priority group pool members continue until the connection has completed or the configured persistence timeout is reached.

Using iRules

Using iRules on the BIG-IP system provides great flexibility because you can select where it sends traffic under various conditions.

  1. To determine whether traffic should be sent to an alternate pool when the number of active members in the primary pool is less than you want, use the active_members command.

    For example, the following iRule uses the active_members command:

    when HTTP_REQUEST {
    if { [active_members http_pool] >= 2 } {
      pool primary_pool }
    else {
      pool alternate_pool }
    }

  2. To redirect HTTP traffic to an alternate location when the connection fails and the primary pool has no available members, create an iRule that uses the HTTP::fallback command.

    For example, the following iRule uses the HTTP::fallback:

    when LB_FAILED {
      if { [active_members [LB::server pool]] != 0 } {
    }
    else {
      HTTP::fallback "http://www.alternate_location.com"  }
    }

    For more information about the iRules, refer to active_members, HTTP::fallback, and LB::server.
