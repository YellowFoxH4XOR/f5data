Description

If you want to limit SSH access to the BIG-IP system by blocking SSH login attempts

Environment

BIG-IP

Cause

You want to prevent access to BIG-IP via SSH on any interface other than management.

Recommended Actions

Follow K17333: Overview of port lockdown behavior (12.x - 17.x) as guidance on how to adjust port lockdown settings on Self IP's to block port 22.

 

  1. Log in to the Configuration utility.
  2. Go to Network > Self IPs. 
  3. Select the relevant self IP address.
  4. For Port Lockdown, choose the setting you want to use.
  5. Select Update.

 

The Allow Default setting for port lockdown allows access for a pre-defined set of network protocols and services that are typically required in a BIG-IP deployment, which includes SSH on port 22.

 

The Allow None setting specifies that no connections are allowed on the self IP address, regardless of protocol or service. However, ICMP traffic is always allowed, and if the BIG-IP systems are configured in a redundant pair, ports that are listed as exceptions are always allowed from the peer system.  This will block SSH and all other services (except ICMP), but will also interfere with Failover communication.

 

Configure port lockdown settings for network failover in a High Availability device group.

 

For optimal security, when configuring for high availability (HA) network failover, F5 recommends the following when configuring the Port Lockdown setting:

 

Note: When BIG-IP devices are configured in a synchronization group, peer devices communicate using Centralized Management Infrastructure (CMI) on tcp:4353 on the self IP address, regardless of the port lockdown settings. Refer to the Port lockdown exceptions section of this article for additional information.

 

  • Use Allow Default if HA network failover is required. For more information, refer to K2397: Comparison of hardwired failover and network failover features.
  • Using the Allow Default configuration for any self IP address that is not used for HA network failover may expose unnecessary protocols or services and may constitute a security risk.  Alternatively, use Allow Custom and configure it to allow the UDP protocol on port 1026.
  • When hardwired failover is available and HA network failover is not required, use Allow None.

In conclusion, you should use the most restrictive port lockdown settings available depending on what is required in your environment.  If using HA network failover, you can select Allow Custom and block access to TCP Protocol on port 22.  If using hardwired failover and you don't require any other ports open on the Self IP in question, you may choose Allow None.
