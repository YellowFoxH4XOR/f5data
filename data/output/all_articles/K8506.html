In GTM versions prior to BIG-IP GTM 9.3.1 HF2 and BIG-IP GTM version 9.4.7, the default behavior of the BIG-IP GTM was to immediately mark all virtual servers hosted on a BIG-IP system as Unavailable if iQuery communication failed or if even a single iQuery update was lost due to a network outage. This default behavior causes the BIG-IP GTM to direct traffic away from the BIG-IP system for even a brief network outage, lasting for less than the configured timeout settings of the BIG-IP monitor used by the BIG-IP GTM. Once iQuery communications are restored, the affected objects are updated appropriately.

The GTM.VsDependsServerState database variable, introduced in BIG-IP GTM 9.3.1 HF2 and BIG-IP GTM version 9.4.7 as CR91809, allows an administrator to specify whether the virtual server status depends on the current state of an iQuery connection to the BIG-IP LTM device hosting the virtual servers. The GTM.VsDependsServerState variable is enabled by default, and the BIG-IP GTM will mark down all virtual servers that are hosted on a BIG-IP system if the BIG-IP GTM loses iQuery communication with that BIG-IP system. If the GTM.VsDependsServerState variable is set to disable, the default behavior is disabled, and the BIG-IP GTM keeps the affected virtual servers in an Available status if iQuery communication is interrupted.

Setting the GTM.VsDependsServerState variable 

You can modify the default behavior by setting the GTM.VsDependsServerState variable to disable. To do so, perform the following procedure:

  1. Log in to the command line with root privileges.
  2. To disable the default behavior, use the following command syntax:

    bigpipe db GTM.VsDependsServerState disable

When the GTM.VsDependsServerState variable is set to disable and iQuery communication is lost, a state change will be logged in the /var/log/gtm file for the BIG-IP device, but the status of all related virtual servers is unaffected. This allows the BIG-IP GTM to continue to direct traffic to the virtual servers although iQuery communication has been interrupted. The timeout value of the monitor assigned to the virtual server on the BIG-IP GTM is then used to determine whether the BIG-IP GTM system should mark individual virtual servers as Unavailable.
