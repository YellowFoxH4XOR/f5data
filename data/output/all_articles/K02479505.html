Topic

You should consider using this procedure under the following conditions:

  • You want to prevent malicious traffic with certain HTTP request values because they indicate an application or distributed Denial of Service (DoS) attack.
  • You want to prevent unexpected traffic from a certain geolocation or source IP address.
  • You want to use a local traffic policy.
  • Your BIG-IP system is licensed and provisioned only with BIG-IP LTM, not BIG-IP ASM.
  • An IP Intelligence license is available for the BIG-IP device on which you want to block known malicious IP addresses.

Description

In certain situations, you may need to block HTTP traffic, source IP, or geolocation when the traffic hits a virtual server. For example, a customer determines the traffic is part of a distributed Denial of Service (DDoS) or application attack, normally observed for HTTP based applications. The Local Traffic Policy feature sets configurable traffic conditions and if matched, an applicable action executes against the matched traffic.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You provisioned BIG-IP LTM.
  • Malicious traffic is using TCP as the transport protocol.

Procedures

To configure a local traffic policy, perform the following procedure:

Configuring a local traffic policy

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies > Policy List > Policy List.
  3. Select Create and provide a name for the draft policy.
  4. Go to the Local Traffic > Policies > Policy List > Draft Policy > <name of draft policy>.
  5. Select Create and provide a name for the rule.
  6. Configure the following conditions and actions:
    • Set the conditions in the Match all of the following conditions section by selecting the add icon (+). 

      For example, to configure the condition to match a TCP request from a specific IP address, perform the following steps:

      • For Available, select TCP followed by address.
      • For matches any of, provide an IPv4 address and select Add.

        Note: For the same example condition in BIG-IP 13.x and later, you can define the address match as a single IP address or from a data group that you can preconfigure by going to Local Traffic > iRules > Data Group List.

      • For at time, select request.

    • Set the actions in the Do the following when the traffic is matched section by selecting the add icon (+).

      For example, to configure the action to log the source IP address and reset the TCP connection, perform the following steps:

      • Select Log from the list and, for message, add a simple log message or use Tool Command Language (Tcl) expressions.

        For example:

        tcl:the blacklisted IP [IP::client_addr] is blocked 

        Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

      • For at time, select request.

      • Add another action by selecting the add icon and selecting Reset traffic.

  7. To save the configured rule, select Save.
  8. To use or publish the configured draft policy, under General Properties, for Save Draft, select Save and Publish Policy. 
  9. To apply the configured local traffic policy to a virtual server, go to Local Traffic > Virtual Servers > Virtual Server List > <name of virtual server> > Resources.
  10. Under Policies, select Manage.
  11. Select the configured local traffic policy from the Available list move it to the Enabled list.
  12. To save the changes, select Finished.

    You can now monitor the /var/log/ltm file for logs generated by the configured local traffic policy when the traffic condition matches.

    For example:

    Dec 20 16:23:27 f5 info tmm[22487]: [/Common/block_ip_ltm_pol/block_ip_ltm_pol_1]: the blacklisted IP 172.16.4.21 is blocked

Example local traffic policies

For more information, refer to the following example local traffic policy configurations that reset TCP traffic based on different conditions, in addition to their respective log messages and tcpdump snippets.

Note: If you have enabled the TCP RST cause information in the TCP RST packet payload and you perform a traffic capture when the configured local traffic policy has a match and executes the configured reset action, you should be able to observe the reset cause information in the packet capture similar to the following example: 

rst_cause="[0x22c6b1a:1513] reset by policy"

For more information about enabling TCP RST cause information, refer to K13223: Configuring the BIG-IP system to log TCP RST packets.

  • Resetting HTTP traffic based on HTTP query string information
  • Resetting TCP traffic based on source IP information
  • Resetting TCP traffic based on geolocation
  • Resetting traffic based on IP reputation

Resetting HTTP traffic based on HTTP query string information

ltm policy block_malicious_query_string {
    controls { forwarding }
    last-modified 2018-12-20:13:20:30
    requires { http }
    rules {
        "block malicious value in http query string" {
            actions {
                0 {
                    log
                    write
                    facility local0
                    message "tcl:Request blocked! http query string [HTTP::query] contains an illegal value"
                    priority info
                }
                1 {
                    forward
                    reset
                }
            }
            conditions {
                0 {
                    http-uri
                    query-string
                    contains
                    values { maliciousvalue }
                }
            }
        }
    }
    status published
    strategy first-match
}

Resetting TCP traffic based on source IP information

ltm policy block_source_ip {
    last-modified 2019-02-20:22:55:25
    requires { http tcp }
    rules {
        block_source_ip {
            actions {
                0 {
                    shutdown
                    connection
                }
                1 {
                    log
                    write
                    facility local0
                    message "tcl:IP [IP::client_addr] is blocked by LTM Policy"
                    priority info
                }
            }
            conditions {
                0 {
                    tcp
                    address
                    matches
                    values { 172.16.8.79 }
                }
            }
        }
    }
    status published
    strategy first-match
}

Resetting traffic based on IP reputation

Note: The IP reputation option requires the IP Intelligence license.

ltm policy IP_Intel_block {
    description "block using IP intelligence"
    last-modified 2018-12-27:01:32:20
    requires { http }
    rules {
        block_known_malicious_sources_using_ip_intellgence {
            actions {
                0 {
                    log
                    write
                    facility local0
                    message "tcl:Detected IP [IP::client_addr] as [IP::reputation [IP::client_addr]]. Blocking!"
                    priority info
                }
                1 {
                    shutdown
                    connection
                }
            }
            conditions {
                0 {
                    iprep
                    values { BotNets "Windows Exploits" }
                }
            }
        }
    }
    status published
    strategy first-match
}

Note: The IP reputation option is available in the BIG-IP LTM policy rule configuration starting BIG-IP 13.1.x. For BIG-IP 12.1.x and earlier, use a similar iRule, as referenced in IP:: reputation on F5 CloudDocs. Apply the iRule on the affected BIG-IP virtual server to mitigate attack traffic from IP addresses with bad reputations.

#Drop the packet after initial TCP handshake if the client has a bad reputation
when CLIENT_ACCEPTED {

    # Check if the IP reputation list for the client IP is not 0
    if {[llength [IP::reputation [IP::client_addr]]] != 0}{

        # Drop the connection
        drop
    }
}
