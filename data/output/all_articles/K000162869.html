K000162869: ICMP Echo response state does not update after virtual server or pool availability changes

Type
Support Solution
Published
2026-08-11
Updated
2026-08-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162869

Description

A virtual address configured with ICMP Echo setting such as Selective or All can retain a stale ICMP response state when the virtual server becomes unavailable. The virtual address may continue responding to ICMP requests despite that, even with all members within the pool associated to the virtual server become unavailable (either marked down by a monitor or forced offline).

Conversely, after the virtual server returns to an available state, the virtual address may remain unresponsive.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1.7 (LA) and 17.5.1.8
  • Virtual address configuration:
    • A virtual address is configured with an ICMP Echo mode that permits responses, such as Selective or All.
  • Virtual server configuration:
    • The virtual server contributes its availability status to the associated virtual address.
  • Triggering conditions:
    • All pool members are forced offline or become unavailable through monitor status.
    • Pool members later return to an available state.

Cause

This is a stale ICMP-state processing issue tracked under Bug ID2449661. The virtual address may retain a stale ICMP Echo response state after the associated virtual server changes availability:

  • It may continue responding to ICMP Echo requests after the virtual server becomes unavailable.
  • It may remain unresponsive after the virtual server returns to an available state.
  • ICMP-based monitoring may therefore report a virtual address state that does not reflect the current status of the virtual server.
  • Reapplying the ICMP Echo configuration may be required to restore the expected behavior.

Answer/Recommended Actions

Toggle and reapply the virtual address’s ICMP Echo configuration with the following two-step process:

  • Change the ICMP Echo setting to Disabled.
  • Change it back to its original mode, such as Selective or All.

This rebuilds the ICMP response state and restores behavior consistent with the current virtual server status.
