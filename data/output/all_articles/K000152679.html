Description

After deploying a second NGINX Ingress Controller (NIC) in a containerization cluster, such as a Kubernetes cluster, that has an existing (first) NIC, the second NIC is configured with the existing Virtual Server/Virtual Server Route (VS/VSR) resources that are deployed for and on the first NIC.

Environment

NGINX Ingress Controller

Existing NIC with VS/VSR resources deployed

Second NIC with it's own VS/VSR resources deployed

  • Both NICs implement different ingress class resources
  • Both NICs are deployed in different namespaces
  • The VS/VSR resources are deployed in different namespaces

Cause

Each NIC deployment will implement VS/VSR resources deployed in any namespace by default.

Recommended Actions

Implement one or both of the following solutions

  • Implement the same ingress class resource, that the corresponding NICs are configured with, to the respective VS/VSR resources. For example:
    • If NIC-1 is configured with IngressClass resource IR-1 then configure VS/VSR resources VS-1/VSR-1 with IngressClass resource IR-1
    • If NIC-2 is configured with IngressClass resource IR-2 then configure VS/VSR resources VS-2/VSR-2 with IngressClass resource IR-2
  • Implement command line argument watch-namespace to each NIC, specifying the namespaces in which the respective VS/VSR resources are deployed in. For example:
    • If VS/VSR resources VS-1/VSR-1 are in namespace NS-1 then implement command line argument watch-namespace with value NS-1 to NIC-1
    • If VS/VSR resources VS-2/VSR-2 are in namespace NS-2 then implement command line argument watch-namespace with value NS-2 to NIC-2

Additional Information

To implement command line argument watch-namespace to NIC deployments using Helm, implement chart parameter controller.watchNamespace with the respective namespace value or values.
