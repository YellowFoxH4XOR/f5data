K91094026: Updating an LTM policy using ''load /sys config replace''

Published

Description:

An existing, published LTM policy must be modified by directly updating its raw configuration instead of using the GUI.
The update involves completely replacing the current policy rules with a new rule set, including new rule names, while preserving the policy object.
This approach is typically used for automated workflows, bulk rule updates, or configuration management scenarios where direct policy definition control is required.

Environment:

  • LTM traffic policy.
  • tmsh load sys config verify

Cause:

Routine configuration update

Recommended Actions:

Backup Configuration

    • Always take a backup of the existing configuration before making any changes to ensure you have a recovery option:
tmsh save /sys ucs /var/local/ucs/pre-policy-change.ucs

 

Check for Existing Drafts

    • If a draft already exists for the policy, you must delete it before creating a new draft:
tmsh delete ltm policy <policy name> draft

 

Create a New Draft Policy

    • Use the following command to create a draft:
modify ltm policy <policy name> create-draft

 

Load the Replacement Configuration

    • Use the replace keyword to load the new configuration:
load /sys config from-terminal replace

Paste the replacement configuration directly into the terminal, then press <ctrl-d> to indicate the end of input.

 

Publish the Draft Policy

    • After loading the new configuration, publish the draft to make it active:
modify ltm policy <policy name> publish

 

Save the Modified Configuration

    • Save the configuration to persist your changes:
save sys config

 

Verify the Policy

    • Check the policy and configuration for errors:
tmsh load sys config verify
tmsh list ltm policy <policy name>

 

Example Configuration

The following example demonstrates how the policy configuration should look when replacing the rules:

 

ltm policy ltm_test {

    draft-copy Drafts/ltm_test

    last-modified 2026-01-27:00:59:47

    requires { tcp http-connect }

    rules {

        test_new {

            conditions {

                0 {

                    tcp

                    proxy-connect

                    address

                    matches

                }

            }

        }

    }

    status published

    strategy first-match

}
