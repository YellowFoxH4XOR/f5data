Known Issue

The system may not properly add a BIG-IP device to a device service clustering (DSC) trust domain.

This issue occurs when the following condition is met:

  • The system adds the BIG-IP device to the trust domain as a subordinate non-authority device.

A DSC trust domain is a collection of BIG-IP devices that trust one another, but may synchronize and possibly fail over their BIG-IP configuration data. To establish device trust, you can designate each BIG-IP device as either a Certificate-signing Authority (CA) or a subordinate non-Certificate-signing Authority (non-CA).

You must properly associate a BIG-IP system with a trust domain before the system can participate successfully as a member of a device group and synchronize its configuration.

Impact

The discovered BIG-IP device cannot successfully synchronize its configuration with the other device group members.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H445899 on the Diagnostics > Identified > Medium screen.
  • The discovering BIG-IP device (the device from which you are attempting to add the new trust domain member) repeatedly logs error messages to the /var/log/ltm file, where you may observe error messages similar to the following example:

    info tmm[27357]: CMI peer 192.168.1.1 certificate rejected, error 19: self signed certificate in certificate chain

  • The discovered device (the device that the BIG-IP system is discovering to add to the trust domain) logs error messages to the /var/log/ltm file, where you may observe error messages similar to the following example:

    err mcpd[5366]: 010716b1:3: Removing self device (/Common/host1.test.net) from trust domain (/Common/Root) is not allowed.
    err mcpd[5366]: 01071488:3: Remote transaction for device group /Common/device_trust_group to commit id 16 5912833472506769962 /Common/host2.test.net 0 failed with error 010716b1:3: Removing self device (/Common/host1.test.net) from trust domain (/Common/Root) is not allowed..
    notice mcpd[5366]: 0107143a:5: CMI reconnect timer: disabled, all peers are connected
    warning chmand[5694]: 012a0004:4: SIO_VBAT = 2670 out of range 2700/3300

  • You can add the discovered device to the sync-failover device group, but synchronization fails, and in the /var/log/ltm file, you may observe error messages similar to the following example:

    err mcpd[5366]: 010716b1:3: Removing self device (/Common/host1.test.net) from trust domain (/Common/Root) is not allowed.
    err mcpd[5366]: 01071488:3: Remote transaction for device group /Common/device_trust_group to commit id 26 5912839356284764649 /Common/host2.test.net 0 failed with error 010716b1:3: Removing self device (/Common/host1.test.net) from trust domain (/Common/Root) is not allowed.

  • After you upgrade, the configuration fails to load due to a pre-existing trust domain object, which defines one or more non-CA device, similar to the following example:

    cm trust-domain /Common/Root {
    ca-cert /Common/dtca.crt
    ca-cert-bundle /Common/dtca-bundle.crt
    ca-devices { /Common/F5A.internal.company.domain.com }
    non-ca-devices { /Common/F5B.internal.company.domain.com }
    status initialized trust-group /Common/device_trust_group
    }

Workaround

To work around this issue, you can add the new device to the trust domain as a CA. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the discovering device.
  2. On the Main tab, click Device Management > Device Trust > Peer List.
  3. In the Peer Authority Devices area, click Add.
  4. Type the device IP address, administrator user name, and administrator password for the remote BIG-IP device with which you want to establish trust. The IP address you specify depends on the type of BIG-IP device you are adding:
    • If the BIG-IP device is a non-VIPRION device, type the management IP address for the device.
    • If the BIG-IP device is a VIPRION device that is not licensed and provisioned for Virtual Clustered Multiprocessing (vCMP), type the primary cluster member management IP address for the cluster.
    • If the BIG-IP device is a VIPRION device that is licensed and provisioned for vCMP, type the cluster member management IP address for the guest.
    • If the BIG-IP device is an Amazon Web Services EC2 device, type one of the private IP addresses created for this EC2 instance.
  5. Click Retrieve Device Information.
  6. Verify that the displayed information is correct.
  7. Click Finished.

After you perform this procedure, the local device and the device that you specified in this procedure have a trust relationship, and you can successfully add the devices to a device group, including the default synchronization group.
