Description

Interfaces on a vCMP host show a number instead of the expected name or interface.

On a vCMP host, the internal switch chip can be viewed with the following command:

tmsh show /net fdb all-records

Some of the entries will display with a number rather than the expected entry, like the following:
show /net fdb all-records
------------------------------------------------------------------------------------------
Net::FDB
Vlan                            Mac Address        Member                          Dynamic
------------------------------------------------------------------------------------------
/Common/Vlan1         0:0:5E:0:53:0        interface:Trunk1             yes
/Common/Vlan2        0:0:5E:0:53:01       interface:Trunk1             yes
/Common/Vlan1        0:0:5E:0:53:02       interface:Trunk1             yes
/Common/Vlan2        0:0:5E:0:53:04       interface:33                    yes
/Common/Vlan1        0:0:5E:0:53:12       interface:33                    yes

The number after the interface or trunk (depending on version) is the virtual ID of the guest, which is automatically assigned by the system.  The internal switch on the vCMP host doesn't know anything about the MAC addresses the guest uses, it only knows that certain MAC addresses belong to certain virtual IDs. In our example above, a packet inbound for 0:0:5E:0:53:04 would be destined for the guest with virtual ID 33. 

Environment

You must be on a vCMP host and viewing the fdb (Forwarding Database) table.

Cause

This is how the vCMP host's internal Layer 2 switch sends traffic on to the vCMP guest without having to communicate all possible or available MAC addresses between the vCMP host and the vCMP guest. 

Recommended Actions

No action is required
