Topic

You should consider using this procedure under the following condition:

  • You want to configure virtual servers to share the same virtual addresses across multiple partitions.

Description

When you configure a virtual server, the BIG-IP system creates two objects: a virtual server and a virtual address. A virtual server and corresponding virtual address both reside in the partition in which the virtual server was initially created. For example, if you create a virtual server of 172.0.0.10:80 in the default /Common partition, the virtual address 172.0.0.10 also resides in the default partition.

When creating virtual servers that share the same resources across multiple administrative partitions you should be aware of the following:

  • Virtual addresses that reside in the default /Common partition:

    A virtual address that resides in the default partition can be referenced by a virtual server in any other partition. For example, if virtual server 172.0.0.10:80 and virtual address 172.0.0.10 reside in the /Common partition, you can create a virtual server such as 172.0.0.10:22 in a non-default partition, such as /MyPartition-1, and a virtual server such as 172.0.0.10:8080 in a non-default partition, such as /MyPartition-2.

    To ensure that the virtual address is in the /Common partition, the first virtual server created for the address must be created in the /Common partition.

  • Virtual addresses that reside in a non-default partition:

    A virtual address that resides in a non-default partition can only be referenced by virtual servers that reside in the same partition. For example, if virtual server 172.0.0.10:80 and virtual address 172.0.0.10 reside in a non-default partition such as /MyPartition, other virtual servers such as 172.0.0.10:22 must also reside in the same non-default partition. In order for virtual servers in different non-default administrative partitions to share the same virtual address, the virtual address must reside in the /Common partition so it can be referenced by each of the non-default administrative partitions where the virtual servers reside.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility or the TMOS Shell (tmsh).

Procedures

Configuring virtual servers to use the same virtual address across multiple partitions

To configure virtual servers to use the same virtual address across multiple partitions, you must create the first virtual server object in the default /Common partition. You can then create subsequent virtual servers in non-default partitions that share the virtual address in /Common. To do so, perform one of the following procedures:

Note: For multiple virtual servers to share the same destination address, source address, and service port, you must specify unique VLANs for which the virtual servers are enabled.

Using the Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Verify you are in the default administration partition by selecting Common in the Partition list at the top of the screen.
  3. Navigate to Local Traffic > Virtual Servers.
  4. Click Create.
  5. For Name, enter a name for the virtual server.
  6. For Destination Address/Mask, enter the virtual address you want to be available across multiple partitions.
  7. For Service Port, enter the destination port for the virtual server.
  8. Configure the other settings as needed and click Finished.
  9. Change to the non-default partition by selecting it from the Partition list.
  10. Navigate to Local Traffic > Virtual Servers.
  11. Click Create.
  12. For Name, enter a name for the virtual server in the non-default partition.
  13. For Destination Address/Mask, enter the virtual address you entered for the previous virtual server above.
  14. For Service Port, enter the destination port for the virtual server in the non-default partition.
  15. Configure the other settings as needed and click Finished.

Using tmsh

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To verify that you are in the default administrative partition, type the following command:

    cd /Common

  3. To create the virtual server using the virtual address that you want to be available across multiple partitions, use the following command syntax:

    create virtual <Virtual_Name> { destination <IP_Addr>:<port> pool <Pool_Name> }

    For example, the following command creates a virtual server (MyVirtual-1) and associated virtual address in the /Common partition:

    create /ltm virtual MyVirtual-1 { destination 172.0.0.10:80 persist replace-all-with { source_addr } pool MyPool-1 }

  4. Change to the non-default partition by using the following syntax:

    cd /<Non-Default_Partition>

    For example:

    cd /MyPartition

  5. To create the virtual server in the non-default partition using the same virtual address that you specified above, use the following command syntax:

    create virtual <Virtual_Name> { destination <IP_Addr>:<port> pool <Pool_Name> }

    For example, the following command creates a virtual server (MyVirtual-2) using the same virtual address in the /MyPartition partition:

    create /ltm virtual MyVirtual-2 { destination 172.0.0.10:22 persist replace-all-with { source_addr } pool MyPool-2 }

  6. Save the change by typing the following command:

    save /sys config partitions all
