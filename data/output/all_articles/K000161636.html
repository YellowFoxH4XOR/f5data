K000161636: Port Allocation Conflict When Enabling HTTP-to-HTTPS Redirect on Multiple HTTP Load Balancers with Same Domain and IP

Type
Support Solution
Published
2026-06-08
Updated
2026-06-12
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000161636

Description

Enabling the HTTP Redirect to HTTPS option on more than one HTTP Load Balancer configured with the same domain and IP address results in a port allocation conflict error. The error message is:

Failed transaction handling virtual host: Failed to update virtual-range-index <lb-name>:

Port allocation for &Allocation{VirtualHosts:[]*ObjectRefType{...},

Range:[]*Range{&Range{Start:80,End:80,},},

Domains:[example.com],ProxyType:HTTP_PROXY,} conflict with existing virtual_host

Environment

  • Product: F5 Distributed Cloud
  • Feature: HTTP Load Balancer – HTTP Redirect to HTTPS option
  • Configuration: Multiple HTTP Load Balancers with the same domain and IP, different ports, HTTP Redirect to HTTPS enabled on more than one LB

Cause

When HTTP Redirect to HTTPS is enabled, the platform automatically creates a listener on port 80 for the domain and IP combination. Only one port 80 allocation is allowed per unique domain and IP. Enabling this option on multiple LBs with the same domain and IP causes a conflict.

Answer/Recommended Actions

  • Identify all HTTP Load Balancers sharing the same domain and IP.
  • Ensure only one LB has the HTTP Redirect to HTTPS option enabled.
  • Disable the redirect option on all other LBs with the same domain and IP.
  • Save and apply the configuration.

If LBs have the same domain but different IPs, each can have HTTP Redirect to HTTPS enabled without conflict.

Additional Information

  • This is a platform-enforced restriction, not a bug.
  • Only one HTTP-to-HTTPS redirect listener on port 80 is permitted per domain and IP combination.
  • Consolidate routes for the same domain into a single HTTP Load Balancer when possible.
