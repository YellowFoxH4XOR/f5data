Known Issue

A rewrite profile might cause the Traffic Management Microkernel (TMM) to restart when the system attempts to rewrite the Set-Cookie field in the HTTP response header.

This issue occurs when the following condition is met:

  • The system uses a rewrite profile to rewrite the path and / or domain within the Set-Cookie field of an HTTP response header.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the BIG-IP system is configured as part of a high-availability (HA) group, a device failover may occur.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if the system is configured for HA.
  • The BIG-IP system generates TMM core files to the /shared/core directory.
  • You observe messages similar to the following example in the /var/log/ltm log file:

    notice sod[7056]: 01140045:5: HA reports tmm NOT ready.

  • The BIG-IP system logs a message similar to the following example in the /var/log/tmm* files:

    notice 2: lib/c/xbuf.c:930: xbuf_subtract: Assertion `valid xfrag subtraction' failed.
