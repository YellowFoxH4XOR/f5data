Known Issue

Note: For more information about configuring gateway fail-safe, refer to the BIG-IP System: Essentials guide.

This is the result of a known issue. A BIG-IP system configured with a gateway fail-safe pool may log an error message when the configuration is loaded. The error message is logged to the /var/log/ltm file and appears similar to the following example:

local/bigip1 err mcpd[1760]: 01070712:3: Caught configuration exception (0), Unable to initiate HA action on pool gateway_failsafe_pool, status 18087954 - Pool.cpp, line 317.

The error message is logged because of a race condition that occurs when the configuration is loaded. At this time, the system may try to update the high availability table with the status of the gateway fail-safe pool before the high availability table has been informed of the existence of the pool.

You can safely ignore this error message, as the high-availability table resumes updating correctly as soon as it has learned of the existence of the gateway fail-safe pool. Even if a BIG-IP system has logged this error message, it will perform the predefined fail-safe action if the number of available gateway pool members drops below the designated threshold.

F5 Product Development is tracking this issue as ID 291546 (formerly CR122288).

Workaround

 

If the above error message persists, you can re-generate the binary mcpd data. To do so, perform the following procedure:

Impact of workaround: The bigstart restart command will temporarily interrupt traffic processing, and you should perform the command during a maintenance window.

 

  1. Log in to the command line.
  2. Remove the binary mcpd data by entering the following command:

    rm -f /var/db/mcpdb.*
  3. Restart the system services and re-generate the binary mcpd data by entering the following command:

    bigstart restart
