Description

Traffic is being balanced to single pool member while source address persistence is set as primary and destination address persistence is set as fallback persistence. 

Environment

Source address persistence set as primary persistence and destination address persistence set as fallback persistence.

Cause

This is expected behavior. If primary source address persistence will not work, secondary persistence will be used. If all incoming traffic will be directed to the same destination address, all session will be assigned to single pool member.

Important: If Fallback persistence becomes the chosen persistence method, a Default persistence entry will not be created for the client connection until the Fallback persistence idle timeout period expires. Because of this, Fallback persistence may appear to override Default persistence and may not be a good choice. See Recommendations, following, for additional information from article below:
K30483109: Overview of Fallback Persistence

Recommended Actions

  1.  Remove destination address fallback persistence for affected virtual server, and monitor behavior to see if load balancing works as expected
  2.  If issue is still existing after removing fallback persistence, review persistence table for more information. 
Please note: Persistence entries may be kept for long time on F5 LTM instance, to reset table follow article below:
K55632517: Delete persistence entry
