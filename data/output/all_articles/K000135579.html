Description

PAGE_STATS table in "tmctl -a blade" might show one tmm interface using more memory than others

 

Environment

  • PEM
  • LTM

 

Cause

Client side and server side throughput spiked as seen in performance graphs.

 

Recommended Actions

Can use below command to check pagemem utilisation from CLI;

 

tmctl -d blade page_stats -s pages_used,pages_avail | grep -P "\d+" | awk '{{used += $1} {total += $2}} END {print 100*used/total"%"}'

 

To check individual usage percentage , need to print the rows using $ sign;

 

Example;

Go to bash prompt

# tmctl -d blade page_stats -s tmid,pages_used,pages_avail | grep -P "\d+" | while read -r line ; do echo $line ; done | awk '{print $1, $2, $3, 100*$2/$3"%"}'


0 59864 435712 13.7394%

1 48346 436736 11.0698%

 

Need to check if any spike in Client side and server side throughput as well.

 

Check PEM_GX_STATS table and see if it shows a lot of retries/sess_prov_pend around the same time. Which could be an indicative of network issue on the Gx side;

 

Below is an example of the tmctl snapshots ;

Go to bash prompt

# tmctl -d blade pem_gx_stat -w100

 

Check if there was any anomaly happening in the network leading to the PCRF server, as it could be a network issue .
