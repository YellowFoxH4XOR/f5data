Description

After an upgrade to a version prior to 15.1.0 and although the configuration has been loaded successfully, TMM is crashing and BIG-IP status reverts to Offline

In /var/log/tmm, logs similar to one below may be observed and the instruction pointer value ( RIP ) may have the same value as the one which is highlighted below:

notice ** SIGSEGV **
notice Fault address: 0xd8
notice Fault code: 0x1
notice Register dump:
notice RAX: 0x00000000000000c2 RBX: 0x000056000a0a3e80 RCX: 0x0000000000000047
notice RDX: 0x0000560001f8b800 RSI: 0x0000000000000047 RDI: 0x0000000000000000
notice RBP: 0x00005600003fc0c0 R8 : 0x000056000a0a3e80 R9 : 0x0000000000000047
notice R10: 0x0000000000000000 R11: 0x0000000000000047 R12: 0x0000000000000047
notice R13: 0x0000560009bf0e08 R14: 0x000056000a0a3ec0 R15: 0x00005600003fc3c0
notice RSP: 0x00005600003fc000
notice RIP: 0x00000000006df750 EFLAGS: 0x0000000000013246
notice CS: 0x0033 FS: 0x0000 GS: 0x0000
notice Trap: 0x0000000e Error: 0x00000006 OldMask: 0x00000000 CR2: 0x000000d8
notice FPUCW: 0x0000037f FPUSW: 0x00000000 TAG: 0x00000000
notice RIP: 0x00000000 RDP: 0x00000000

On the system in question, 'persist none' command is used in order to disable persistency before an HTTP_REQUEST event ( meaning on events like FLOW_INIT, CLIENT_ACCEPTED etc ).

Environment

  • BIG-IP
  • iRules

Cause

Bug ID 831161: An iRule before HTTP_REQUEST calling persist none can crash tmm

Recommended Actions

You can either upgrade into a version on which BUG ID 831161 is resolved or contact the F5 support in order to investigate if an EHF is possible on the version which you are upgrading to.
