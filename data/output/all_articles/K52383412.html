Description
When Virtual Servers are offline, you may expect connections to get reset (and error messages to get displayed).
But as an APM AccessProfile is attached to the Virtual Server, users are actually prompted with a logon page coming from the APM Access Policy.

Environment

  • You have Virtual Servers with APM AccessProfile attached to them;
  • The Virtual Server(s) status is "offline" (red diamond icon);
  • Users initiate connections to the Virtual Server(s).

Cause
This is expected behaviour.
Even though the VIP is set as "offline", TMM does not stop processing traffic to/from this VIP.
The VIP does reflect the status from the attached pool members.
The document K16008 states: "The pool member accepts new connections with a persistence record, and continues to serve existing connections".
As such, because requests from the clients are still being processed, APM may still display any logon page we may have in the AccessPolicy.

Recommended Actions

Should those connections to APM be a source of concern, we potentially have options to prevent APM to kick in.
One of them could be an iRule. Here is an example:
##### BEGIN
when HTTP_REQUEST {
  # Check if the default pool has less than one active member
  if { [active_members [LB::server pool]] < 1 } {
    log local0. "No active members ..."
    HTTP::respond 200 content "<HTML><p>Service is currently down ...</p></HTML>"
  } else {
    log local0. "At least one active members ..."
  }
}
##### END
