Known Issue

BIG-IP Virtual Edition (VE) installation may fail when targeting a second boot location.

This issue occurs because the OVA file allows for two virtual disks; the second disk was designed as a disk for the datastor process, and does not contain enough disk space for a full Traffic Management Operating System (TMOS) installation.

Impact

BIG-IP VE installations fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP VE installation to the second boot location fails.
  • The tmsh show /sys software status command returns a (Disk full (volume group) error message.

    The following output indicates that the BIG-IP VE installation failed on the second boot location, HD1.2:

    -------------------------------------------------------------------------------------------
    Sys::Software Status
    Volume Product Version Build Active Status
    -------------------------------------------------------------------------------------------
    HD1.1 BIG-IP 11.5.1 0.0.110 yes complete
    HD1.2 BIG-IP 11.5.0 0.0.221 no failed (Disk full (volume group). See SOL#10636)

Workaround

To work around this issue, you can manually delete the second boot location and then restart the installation.

Impact of workaround: If the BIG-IP system is the active member of a redundant system, rebooting will cause a failover. If the BIG-IP system is a standalone unit, rebooting will interrupt traffic processing.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Manually delete the second boot location by typing the following command:

    delete sys software volume HD1.2

    If the delete operation fails, you may need to perform a system reboot before proceeding to the next step.
  3. Restart the software installation by using the following command syntax:

    install sys software image <imported_ISO_image> create-volume volume <volume_name>
