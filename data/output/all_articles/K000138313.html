K000138313: Unable to ping backend server from the Standby BIG-IP

Type
Support Solution
Published
2024-01-22
Updated
2024-01-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000138313

Description

The Standby BIG-IP is unable to ping a directly connected server. ARP is resolved, ICMP is allowed. The problem goes away after failover, but then the new Standby has the same problem.

Example setup:

Active BIG-IP non-floating self-IP:

net self 10.68.163.130/27 {
address 10.68.163.130/27
allow-service all
traffic-group traffic-group-local-only
vlan Internal
}

Standby BIG-IP non-floating self-IP:

net self 10.68.163.129/27 {
address 10.68.163.129/27
allow-service all
traffic-group traffic-group-local-only
vlan Internal
}

SNAT pool containing IPs which are local-only self-IPs:

ltm snatpool test {
members {
10.68.163.129
10.68.163.130
}
}

When pinging a directly connected Linux server 10.68.163.131 from the Active, there is a response:

[root@bigip1.local:Active:In Sync] config # ping 10.68.163.131
PING 10.68.163.131 (10.68.163.131) 56(84) bytes of data.
64 bytes from 10.68.163.131: icmp_seq=1 ttl=64 time=0.623 ms
64 bytes from 10.68.163.131: icmp_seq=2 ttl=64 time=0.438 ms
64 bytes from 10.68.163.131: icmp_seq=3 ttl=64 time=0.504 ms
^C
--- 10.68.163.131 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2000ms
rtt min/avg/max/mdev = 0.438/0.521/0.623/0.080 ms
[root@bigip1.local:Active:In Sync] config #

But when pinging the same server from the Standby - there is no response:

[root@bigip2.local:Standby:In Sync] config # ping 10.68.163.131
PING 10.68.163.131 (10.68.163.131) 56(84) bytes of data.
^C
--- 10.68.163.131 ping statistics ---
5 packets transmitted, 0 received, 100% packet loss, time 3999ms
[root@bigip2.local:Standby:In Sync] config #

Environment

  • BIG-IPs configured in HA
  • No response while pinging the server from the Standby
  • SNAT pool IPs are the same as local-only self-IPs

Cause

SNAT pool overlaps the non-floating self-IPs.

Recommended Actions

Use different IPs in the SNAT pool, or recreate local-only self-IP with a different IP address. The first option in preferred one.

Additional Information

None.
