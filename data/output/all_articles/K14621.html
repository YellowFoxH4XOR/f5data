Known Issue

The BIG-IP APM system does not process Security Assertion Markup Language (SAML) EncryptedData when the Id attribute is not present.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM policy has been configured to act as the SAML service provider (SP).
  • The BIG-IP APM system receives an EncryptedData SAML assertion without the Id attribute.

Impact

Authentication fails for the session.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H442269 on the Diagnostics > Identified > High screen.
  • Clients cannot establish a session with the BIG-IP APM system.

Workaround

There is no workaround for the BIG-IP APM system. However, to mitigate this issue, you may be able to modify the configuration of the Identity Provider (IdP) to ensure that the SAML assertion will function with the BIG-IP APM system. To do so, perform one of the following options on the IdP server:

Note: To implement either of these mitigation options, refer to the IdP server configuration documentation.

  • Configure IdP to include the Id attribute in the EncryptedData assertion.

    For example:

    <saml2:EncryptedAssertion xmlns:saml2="urn:oasis:names:tc:SAML:2.0:assertion">
    <xenc:EncryptedData xmlns:xenc="http://www.w3.org/2001/04/xmlenc#" Id="<value>" Type="http://www.w3.org/2001/04/xmlenc#Element">

  • Disable encryption of the SAML assertion sent by the IdP.
