Known Issue

BIG-IP Virtual Edition (VE) may fail to process traffic after upgrading the VMware ESXi 6.7 host to Update 2 (or later).

This issue occurs when all of the following conditions are met:

  • You upgrade an existing VMware ESXi hypervisor to 6.7 Update 2 (or later), or deploy the BIG-IP VE system to a VMware ESXi hypervisor already running version 6.7 Update 2 (or later).
  • BIG-IP VE uses the vmxnet3 network interfaces driver.

    Note: BIG-IP VE uses the VMXNET3 network interface driver by default.

Impact

BIG-IP VE system fails to process traffic through non-management interfaces.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP VE does not process traffic when deployed on a VMware ESXi 6.7 Update 2 (or later) hypervisor.

Workaround

Until this issue is fixed in a point release for your software branch, you can contact F5 Support to obtain an engineering hotfix to address the issue.

To work around this issue, you can configure BIG-IP VE to use the SOCK driver (BIG-IP 14.1.0 and later) or UNIC driver (BIG-IP 13.1.0 through 14.0.0) instead of the default VMXNET3 driver. To do so, perform the following procedure:

Impact of workaround: The following procedure requires you to edit the /config/tmm_init.tcl file and restart the Traffic Management Microkernel (TMM). Network traffic is disrupted while TMM restarts.

Important: The /config/tmm_init.tcl file is not included with a configuration synchronization (ConfigSync); you must perform the procedure on each device individually. For members of a high availability (HA) device group, you must perform the following procedure on each member of the device group. Additionally, the procedure must be performed for each boot location you wish to boot to.

  1. Log in to the BIG-IP command line.
  2. Enter the following command for your version to append the line to the /config/tmm_init.tcl file:

    Note: If the /config/tmm_init.tcl file does not already exist, this command creates it and adds the following line, depending on version.

    BIG-IP 14.1.0 and later

    echo "device driver vendor_dev 15ad:07b0 sock" >> /config/tmm_init.tcl

    BIG-IP 14.0.0 and earlier

    echo "device driver vendor_dev 15ad:07b0 unic" >> /config/tmm_init.tcl 

  3. Restart TMM to reload the driver by entering the following command:

    bigstart restart tmm

  4. After TMM restarts, confirm the driver in use by examining the output of the following command:

    tmctl -d blade tmm/device_probed

    Output appears similar to the following example:

    pci_bdf      pseudo_name type      available_drivers     driver_in_use

    0000:0b:00.0 1.1         F5DEV_PCI sock, vmxnet3, unic,  sock
