Issue

While you are connect to the serial console of a BIG-IP system, you may see a warning message that appears similar to the following example when the BIG-IP system undergoes a cold boot (or a full box reboot):

Warning: dp83815#0 MAC addresses don't match:
Address in SROM is 00:01:D7:48:09:80
Address in environment is 00:A0:10:03:00:2A
Hit any key to stop autoboot: 5

This warning message indicates that the uboot environment ethaddr variable does not match the MAC address in the interface's Serial Read Only Memory (SROM). If this is the case, the BIG-IP system will display a warning message during system start up indicating that the MAC addresses do not match.

The warning message is benign and does not indicate a failure.

F5 Networks recommends setting the ethaddr environment variable to match the MAC address in SROM to eliminate the warning, and prevent the incorrect MAC address from being used. To do so, perform the following procedure:

  1. Access the SCCP.

    For information about accessing the SCCP, refer to K3454: Overview of the SCCP.
  2. From the SCCP command line, set the ethaddr variable to the MAC address in SROM, by typing the following command:

    ubootenv ethaddr=<SROM_MAC_Address>

    For example:

    ubootenv ethaddr=00:01:D7:45:09:80
  3. Save the ethaddr variable, by typing the following command:

    savenv
  4. Log on to the BIG-IP system command line.
  5. Reboot the BIG-IP system by entering the following command:

    full_box_reboot

    The SCCP should no longer return the warning message when booting.
