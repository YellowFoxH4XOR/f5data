K11020710: APM policy ending in redirects after BIG-IP upgrade

Type
Support Solution
Published
2023-01-05
Updated
2023-01-05
Applies to
  • BIG-IP
  • BIG-IP APM: 17.X.X, 16.1.X, 15.1.X, 15.1.0, 17.0.0, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 15.1.8, 17.0.X, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 15.1.7
Source
https://my.f5.com/manage/s/article/K11020710

Description
In some occasions after upgrading BIG-IP device, there may be large time skew observed [more than 300 seconds], in /var/log/ltm log. For example, a message similar to the following:
 
warning tmm[24369]: 01010040:4: Clock has unexpectedly adjusted by 696754 ms

This time skew can result in APM policy ending in redirects, with messages similar to the following found in the /var/log/apm file:

Aug 23 05:05:09 apm1 err apmd[14426]: 014902bc:3: Agent initialization failed: name: /Common/agent1_check_user_valid_end_allow_ag, type: agent_ending_allow, error: -200
Aug 23 05:05:09 apm1.internal.com err apmd[14426]: 01490000:3: AccessPolicyProcessor/AgentPluginHostAPIImpl.cpp func: "getAllObjectsConfigDataImpl()" line: 95 Msg: Thread unwind EXCEPTION occured.EXCEPTION
Aug 23 05:05:09 apm1.internal.com err apmd[14426]: 01490000:3: modules/EndingAgents/Allow/AllowAgent.cpp func: "createResourceList()" line: 1088 Msg: Thread unwind EXCEPTION occured.unknown exception
Aug 23 05:05:09 apm1.internal.com err apmd[14426]: 01490000:3: modules/EndingAgents/Allow/AllowAgent.cpp func: "initInstance()" line: 2185 Msg: Thread unwind EXCEPTION occured.unknown exception
Aug 23 05:05:31 apm1.internal.com notice apmclient_mount[26467]: 014902c7:5: run_tmm_samclientversion: /usr/bin/tmm_samclientversion.php complete. 

Environment

  • BIG-IP APM
  • After updating or upgrading

Cause
NTP time skew of 300 seconds can cause the THREAD Unwind exception in APM related processes. Causes for NTP skew might be related to unexpected NTP update. During short time when TMM interfaces are offline, the BIG-IP can use management interface to update time from different source than normally it is syncing with.

Recommended Actions

Impact of procedure: The following procedure requires a reboot of the system. Restarting services causes a brief traffic disruption.
 

  1. If observed behavior was noticed, simple reboot can help.
  2. Review NTP servers, check each one of them for precision.
    K10240: Verifying NTP peer server communications
  3. If NTP is not updating by its own, follow article on force sync:
    K78084428: How to force ntpd to sync to a specific NTP server
