Description

Before relicensing the BIG-IP, there are several steps to follow beforehand to address any existing issues and to minimize down time.

Environment

  • BIG-IP license update

Cause

When updating the license on a a BIG-IP, the configuration reloads. Unfortunately, if there are any errors, the configuration won't load afterwards. Additionally, any unsaved updates from the command line, including dynamic routing and API changes, are lost. Fortunately, we can check for these errors and save the configuration beforehand!

  • Unsaved configuration updates from command line (including API and dynamic routing updates)
  • Existing errors in the configuration

Recommended Actions

  1. Open proactive service ticket.
  2. Create and upload a Qkview to the service ticket.​ The qkview collects the configuration and diagnostic information from BIG-IP or BIG-IQ systems and provides a repository of data should any issue arise during the maintenance window.
  3. Book a maintenance window as updating the license impacts traffic​.
  4. Check configuration for errors
    • For DNS/GTM: tmsh load sys config gtm-only verify
    • For all other modules: tmsh load sys config partitions all verify
      • Resolve any errors that are returned either using knowledge articles in Myf5 or opening a support case.​
  5. Archive the configuration and transfer it off the BIG-IP. By default, changes made from the WebUI are saved, but any updates from the command line, including tmsh, API, and dynamic routing changes, aren't saved.
  6. If in an HA pair, begin with the standby device then failover to test all modules
    • Apply license via BIG IQ: Change license offering for BIG-IP VE from BIG-IQ
    • Apply license via MyF5 Self Service: Licensing the BIG-IP system
