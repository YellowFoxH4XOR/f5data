K51235631: BIG_IP not dropping packets when content-length is missing in SIP over TCP

Type
Support Solution
Published
2022-01-16
Updated
2023-02-21
Applies to
  • BIG-IP LTM: 16.X.X
Source
https://my.f5.com/manage/s/article/K51235631

Description

When BIG-IP receives a SIP request with no Content-Length header over a TCP stream it forwards the request to the backend server.

SIP Requests that don't contain a content_length header are accepted and forwarded by the BIG-IP to the server.

SIP Responses that don't contain a content_length header are accepted and forwarded to the client.

Per RFC 3261 this is non-compliance:

20.14 Content-Length
The Content-Length header field indicates the size of the message-body, in decimal number of octets, sent to the recipient. Applications should use this field to indicate the size of the message-body to be transferred, regardless of the media type of the entity.  If a stream-based protocol (such as TCP) is used as transport, the header field MUST be used.

The size of the message-body does not include the CRLF separating header fields and body.  Any Content-Length greater than or equal to zero is a valid value.  If nobody is present in a message, then the Content-Length header field value MUST be set to zero.

Environment

  • BIG-IP LTM
  • SIP(Session Initiation Protocol)
  • TCP

Cause
Per RFC 3261 this is non-compliance. 

There is no header flag available or set for the content_length header to indicate that the content_length header is required for a request.

Recommended Actions
