Known Issue

This is the result of a known issue. When a monitor based on the WMI template is applied to a Windows 2008 pool member running IIS 7, the monitor always assigns a dynamic ratio of 1 to the pool member.

When the BIG-IP sends the monitor requests for GetCPUInfo, GetDiskInfo, and GetOSInfo, it sends the request including the following HTTP POST data:

RespFormat=HTML

The server is able to respond to the request for GetCPUInfo as expected:

POST /scripts/F5Isapi.dll?GetCPUInfo HTTP/1.1
Authorization: Basic YWRtaW5pc3RyYXRvcjphYmMxMjMhQA==
User-Agent: Mozilla/4.0 (compatible: MSIE 5.0; Windows NT)
Host: 10.10.192.55
Accept: */*
Content-Length: 16
Content-Type: application/x-www-form-urlencoded

RespFormat=HTML.

HTTP/1.1 200 OK
Cache-Control: private
Content-Type: text/html; charset=utf-8
Server: Microsoft-IIS/7.0
X-AspNet-Version: 2.0.50727
X-Powered-By: ASP.NET
Date: Thu, 17 Jul 2008 17:45:59 GMT
Content-Length: 253

<html><head><title>F5 ISAPI Extension</title></head><body><H2>CPU Information</H2><p>CPU: CPU0<br>Manufacturer: GenuineIntel x64 Family 15 Model 4 Stepping 8<br>ClockSpeed: 3004 Mhz<br>LoadPercentage: 8 percent<br>L2CacheSize: 0 Kb<br><br></body></html

However, the server returns an HTTP 500 error message that appears similar to the following example in response to the GetDiskInfo and GetOSInfo:

POST /scripts/F5Isapi.dll?GetDiskInfo HTTP/1.1
Authorization: Basic YWRtaW5pc3RyYXRvcjphYmMxMjMhQA==
User-Agent: Mozilla/4.0 (compatible: MSIE 5.0; Windows NT)
Host: 10.10.192.55
Accept: */*
Content-Length: 32
Content-Type: application/x-www-form-urlencoded

RespFormat=HTML

HTTP/1.1 500 Internal Server Error
Cache-Control: private
Content-Type: text/html; charset=utf-8
Server: Microsoft-IIS/7.0
X-AspNet-Version: 2.0.50727
X-Powered-By: ASP.NET
Date: Thu, 17 Jul 2008 17:53:16 GMT
Content-Length: 2950

*****including relevant HTTP Payload only***** à see <\\athens\siteconfig\C447652\iis7_wmi.cap> for full tcpdump
[Exception]: 'HTML.................' is an unsupported format.

As a result, the monitor always assigns a dynamic ratio of 1 to the pool member.

F5 Product Development tracked this issue as CR103310, and it was fixed in BIG-IP 10.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.
