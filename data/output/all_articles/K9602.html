Known Issue

This is the result of a known issue. If the SSL::enable iRule command is executed in a server side context, the BIG-IP system fails to send the Client Hello to the server, resulting in a stalled server-side SSL handshake.

The issue may be confirmed by examining a packet trace on the server side of the conversation for incomplete SSL handshake sequences, followed by an RST packet from BIG-IP when the TCP timeout expires.

F5 Product Development tracked this issue as CR112807 and it was fixed in BIG-IP version 9.4.8 and version 10.1.0. For information about upgrading, refer to the BIG-IP ASM or LTM release notes.

Note: For more information about the SSL::enable command, refer to the iRules wiki page on the F5 DevCentral site, at the following location:
