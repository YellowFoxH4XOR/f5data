K000154550: Unable to view NGINXaaS access logs

Type

Published

2025-08-30
Applies to

Source

Description

  • You have configured and deployed NGINXaaS for Azure
  • You configured the details of diagnostic setting to include "Logs Analytics workspace" to allow use of “NGXOperationLogs” table
  • With the above, you were able to successfully retrieve error log by querying "NGXOperationLogs" table.
  • However, when tried to query "NGXOperationLogs" table for NGINX Access log using the below syntax, no results were returned.
              NGXOperationLogs
              | where FilePath == "/var/log/nginx/access.log"
              | sort by TimeGenerated asc
              | take 100
  • You want to know, why there are no results for NGINX Access log. 

Environment

  • NGINXaaS for Azure
  • Access Log
  • Error Log
  • NGXOperationLogs
  • Azure
  • Logs Analytics workspace

Cause

  • NGINXaaS does not generate or export access or error logs unless the access_log directive is explicitly defined in the NGINX configuration.
  • By default, logging is disabled, so no log data is sent to Log Analytics Workspace if this directive is missing from configuration.

Recommended Actions

  • Verify that diagnostic settings are configured to send logs to your desired Log Analytics Workspace.
  • Add an access_log directive to your NGINX configuration file to enable access logging, for example:
             access_log /var/log/nginx/access.log;
  • Save and apply the updated configuration.
  • Once enabled, new log entries will be generated and exported; queries against NGXOperationLogs will then return results.

Additional Information

  • For logs to show up in “NGXOperationLogs” table, the diagnostic setting destination details MUST include "Logs Analytics workspace".
