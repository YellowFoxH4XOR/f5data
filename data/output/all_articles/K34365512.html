Description

If the customer upgrades to 14.1 from 12.x, 13.x or 14.0, and then rolls back, on some platforms localdb remains DOWN

  • CLI prompt shows localbd:DOWN
  • /var/log/mysql.out shows 
    error: status 8192 returned by command: mount -onoatime /dev/vg-db-sdb/mdm.app.ASWADB.set.2.mysqldb /var/lib/mysql
info: >++++ result:
info: mount: unknown filesystem type 'linux_raid_member'

Environment

  • System is a RAID platform, with an an earlier style RAID configuration such as the following:
       + 10000s / 10200v
       + 10050s / 10250v
       + 10055s / 10255v
  • System has been upgraded to 14.1 and then rolled-back to prior version
  • Modules that rely on mysql (APM, ASM, AVR)

Cause

Some platforms running BIG-IP create raid sets consisting of raided volumes, as opposed to a single whole-disk raid set containing multiple volumes.
mdadm assigns device numbers based on the  _preferred_minor_number_ setting

Because these numbers changed in version 14.1, it is possible that following the installation of 14.1, when the system is rolled back to the prior version, mdadm allocated the same /dev/md<device_number> to multiple partitions with different UUIDs. This prevents the disk mounting script from successfully mounting some volumes, preventing mysql-based services from starting.

Recommended Actions

You should delete the upgraded 14.1 boot location and reboot.   For information about deleting a boot location, refer to K33265170:  Deleting a boot location volume to free up disk space
