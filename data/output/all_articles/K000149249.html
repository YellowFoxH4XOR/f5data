Description

When renew BIGIP devices certificate which running BIG-IP DNS to existing device sync groups, the devices fail to sync properly. The issue is related to SSL certificate verification failures. Error logs indicate SSL verification failures during the certificate exchange process between BIG-IP DNS systems.

Environment

  • BIG-IP DNS
  • All software versions
  • Renew certificate with using third-party CA certificates
  • GSLB

Cause

The root cause of the issue is expired or stale SSL certificates in the Trusted Device Certificates and Trusted Server Certificates directories on the BIG-IP DNS systems. Additionally, the third-party CA certificates may need to be correctly imported into the Trusted Server Certificates section if secure connections within GSLB are being used.

Recommendations

  1. Remove Old Certificates:
  • Log in to the Configuration utility of the BIG-IP DNS device where you installed the new device certificate.

  • Navigate to the Certificate Management Section:

    • In the navigation menu, go to System > Certificate Management > Traffic Certificate Management > SSL Certificates.
    • A list of all installed certificates will be displayed.

  • Identify and Delete the Old Certificate:

    • Locate the certificate you wish to remove.
    • Ensure the certificate is not currently in use by any SSL profiles or services. The BIG-IP system will prevent deletion of certificates that are in use.
    • Select the certificate and click Delete.
    • Confirm the deletion when prompted.

      2.Import New Certificates:

  • Navigate to the respective sections mentioned above.
  • Select Import and choose the new device certificate. Ensure the Import Method is Append.
  • Import any third-party CA certificates if applicable.

       3.Restart Services:

  • Restart big3d and gtmd services to reinitialize the iQuery connection:
    • tmsh restart sys service gtmd
    • tmsh restart sys service big3d

       4.Verify iQuery Communication:

  • Log in to the Configuration utility of any DNS sync group member.
  • Navigate to DNS > GSLB > Servers and verify that the iQuery communication status is Available (green).

       5.Update Trusted Certificate Stores on Remote Peers:

  • Ensure that the Trusted Device Certificates and Trusted Server Certificates stores on each DNS sync group member contain the new device certificate and any third-party CA certificates.

      6.Long-term Certificate Management:

  • If your BIG-IP system is part of a DNS sync group, consider renewing the device certificate for 10 years to avoid unexpected iQuery failures caused by expired certificates.

      7.Import Third-Party CA Certificates for GSLB:

  • If you are using secure connections within GSLB, ensure the third-party CA certificates are imported into the Trusted Server Certificates section:
    • Navigate to GSLB > Servers > Trusted Server Certificates.
      • Ensure the CA matches the issuer of the server certificate you're trusting.
    • Click Import and choose the CA certificate file.
