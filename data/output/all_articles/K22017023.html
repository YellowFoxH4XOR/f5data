Description

You want configure a custom ASM Blocking Response page and add extra information like URL or client IP without using Javascript or Jquery. You can configure a custom ASM Blocking Response Page using an iRule.

Environment

  • BIG-IP ASM Response Page

Cause
None

Recommended Actions

To configure a custom Blocking Response Page using an iRule, perform the following procedure:
  1. Make sure that "Trigger ASM iRule Events" option is enabled in the policy properties. (for version 15.1.x and later)
    1. Navigate to Security  ››  Application Security  ››  Security Policies  ››  Policies List          and here select the Security Policy you want to work with 
    2. On the Security Policy Configuration, go to General Settings and then to Advanced Settings  section and here look for  Trigger ASM iRule Event Mode   configuration, select Normal
    3. save the changes, and apply the policy.
  2. Create an iRule with content similar to the following (add/delete fields as needed): 

    when HTTP_REQUEST {
       # Other HTTP values can be added here 
       set requri "http://[HTTP::host][HTTP::uri]"
    }
      when ASM_REQUEST_DONE {
         set asm_support_id [ASM::support_id]
      }

      when ASM_REQUEST_BLOCKING {           
   
        HTTP::header remove Content-Length
        HTTP::header insert header_1 value_1
        set client_ip [IP::client_addr]

        set response "<html>
                        <head>
                           <title>Request Rejected</title>
                        </head>
                        <body>
                            The requested URL was rejected. Please consult with your administrator.<br><br>
                            Your support ID is: $asm_support_id<br><br><a href='javascript:history.back();'>Go Back</a><br><br>
                            Your URL is: $requri<br><br>
                            Your client IP is: $client_ip

                        </body>
                    </html>"
        ASM::payload replace 0 [ASM::payload length] ""
        ASM::payload replace 0 0 $response

      }

This iRule will produce a blocking page with HTML output similar to the following: 
<html>
     <head>
        <title>Request Rejected</title>
     </head>
     <body>
         The requested URL was rejected. Please consult with your administrator.<br><br>
         Your support ID is: 8583895893751628044<br><br><a href='javascript:history.back();'>Go Back</a><br><br>
         Your URL is: http://www.example.com/test/demo
         Your client IP is: 192.168.100.1
      </body>
 </html>

Additional Information

Since ASM has absorbed other functions other ASM events could be triggered when an ASM blocking is produced, if the event ASM_REQUEST_BLOCKING is not triggered, you can try with the ASM_REQUEST_VIOLATION event, which event is triggering the blocking depends on your security policy.
