K000132647: BIG-IP may advertise IPv6 subnet-router anycast address which is not configured on BIG-IP

Type
Support Solution
Published
2023-02-27
Updated
2023-02-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.3
Source
https://my.f5.com/manage/s/article/K000132647

Description

BIG-IP may advertise IPv6 address (ends in :0) which is not configured on BIG-IP.

Self IP within the same IPv6 prefix is configured on BIG-IP.
For example
vlan-test is associated with interface 00:00:5E:00:53:53. 
net self xxxxxipv6 {
    address 2001:DB8:3333:f222::1:2f/112
    traffic-group /Common/traffic-group-local-only
    vlan /xxxx/vlan-test            
}

2001:DB8:3333:f222::1:0 is not configured on this BIG-IP.
BIG-IP may advertise IPv6 Address 2001:DB8:3333:f222::1:0. 
07:15:06.381932 2001:DB8:3333:f222::1:1 ff01::0:0 ICMPv6 197 IN s1/tmm0 : Neighbor Solicitation for 2001:DB8:3333:f222::1:0 from 00:00:5E:00:53:8E
07:15:06.381945 2001:DB8:3333:f222::1:2f 2001:DB8:3333:f222::1:1 ICMPv6 197 OUT s1/tmm0 : Neighbor Advertisement 2001:DB8:381d:f2c7::1:0 (rtr, sol) is at 00:00:5E:00:53:53


Environment

  • LTM
  • IPv6
  • Self IP


Cause

IPv6 Address (ends in :0) is 'Subnet-Router anycast address' and the definition is in RFC 4291 :
  1. The "subnet prefix" in an anycast address is the prefix that identifies a specific link.  This anycast address is syntactically the same as a unicast address for an interface on the link with the interface identifier set to zero.
  2. Packets sent to the Subnet-Router anycast address will be delivered to one router on the subnet.  All routers are required to support the Subnet-Router anycast addresses for the subnets to which they have interfaces.

BIG-IP systems are functioning as a router from the perspective of network and offer proxy services. Therefore, according to RFC 4861 , section 7.2.3 and 7.2.4, BIG-IP systems are allowed to respond.

Hence, BIG-IP as a router, may advertise Subnet-Router anycast address (ends in :0) via NDP.


Recommended Actions

This behavior should be expected.
