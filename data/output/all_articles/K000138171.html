Description

Network location awareness (NLA) is a process to determine if the computer running EC is inside the corporate network (local)
Both machine tunnels (MT) and user tunnels (EC) run NLA.

In some cases, when MT is up, EC incorrectly detect network as local because it is using the MT to access internal DNS server which can resolve domain controller (DC) SRVs (domain check)

Environment

APM deployed with Network Access (NA)
Windows computer deployed with MT and EC

Cause

The sequence in which EC detects network locations is as follows:
1. It compares the DNS suffix list on adapters with the configured network location.
2. It resolves the DNS name of the Active Directory server for the domain by sending SRV request for "_ldap._tcp.dc._msdcs.<domain suffix>". 

If both MT and EC are up, EC can resolve SRV for "_ldap._tcp.dc._msdcs.<domain suffix>" trough MT

Recommended Actions

Apply this configuration in order SRV _ldap._tcp.dc._msdcs.<domain suffix>. not to be resolved through MT, so domain check will fail.

In this example domain suffix is "lab.lan"

apm resource network-access /Common/NA-For-MT {
    address-space-exclude-dns-name { _ldap._tcp.dc._msdcs.lab.lan }
    address-space-include-dns-name { *.lab.lan }

apm resource network-access /Common/NA-For-EC {
    address-space-include-dns-name { *.lab.lan }

If MT is up, it will not resolve "_ldap._tcp.dc._msdcs.lab.lan" because an external DNS server has not a record for it.
