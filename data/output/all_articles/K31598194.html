Description

Application sends a redirection to the client using a 200 OK response type, with a hex encoded location in the body, similar to the following:

Note: In this example, the server instructs the client-side application to access www.example.com using port 5000.

url:'http\x3a\x2f\x2ewww\x2eexample\x2ecom\x3a5000'

Environment

  • SSL offload
  • HTTP
  • Redirection in 200 OK response

Cause

Application redirects via a 200 OK in HTTP body, so traditional HTTP to HTTPS redirection methods cannot be used.

Recommended Actions

Construct an iRule and Stream profile to rewrite the body of the server's response, similar to the following example:/p>

Note: In this example, http\x3a is rewritten to https\x3a, and x3a5000 is rewritten to x3a443.

when HTTP_REQUEST {
    STREAM::disable
    HTTP::header remove "Accept-Encoding"
}
when HTTP_RESPONSE {
    if { [HTTP::header value Content-Type] contains "text"} {
       STREAM::expression {@http\\x3a@https\x3a@ @x3a5000@x3a443@}
       STREAM::enable
   }
}
when STREAM_MATCHED {
  log local0.info "Stream matched: [STREAM::match]"
}

The STREAM_MATCHED event will log which strings are matched in HTTP responses to /var/log/ltm. Once the iRule is confirmed as working, this event should be removed to prevent excessive logging. Example logs:

Rule /Common/rewrite_https_5000 <STREAM_MATCHED>: Stream matched: http\x3a
Rule /Common/rewrite_https_5000 <STREAM_MATCHED>: Stream matched: x3a5000

Important: This iRule should be considered an example only and is likely to require modification, depending on your exact requirements and traffic.

Additional Information

Traditional HTTP and HTTPS rewrite methods such as the Redirect Rewrite option of the HTTP profile rely on the redirection being issued as a 300 type response.
