Topic

You should consider using this procedure under the following conditions:

  • You want to configure remote syslog servers on the VELOS system controllers.
  • You want to configure remote syslog servers on a VELOS partition.

Description

You can use either the webUI or the CLI to configure a remote syslog server on the VELOS system controllers and VELOS partition with the following customizations:

  • Remote syslog server IP address or Fully Qualified Domain Name (FQDN)
  • Remote syslog server port
  • Remote syslog server protocol (TCP or UDP)
  • Severity of the log messages to send to the remote syslog server; log messages of the selected severity level and higher are sent.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • To configure remote syslog servers on the VELOS system controllers, you must have administrative access to the VELOS system controllers.
  • To configure remote syslog servers on the VELOS partition, you must have administrative access to the VELOS partition.
  • The remote syslog server is accessible from your VELOS system/partition.
  • To use an FQDN for the syslog servers, configuring DNS servers on the VELOS system/partition is required.

Procedures

Note: The steps for configuring, modifying, and removing a remote syslog server on the VELOS system controller are the same as those on the VELOS partition. The following procedures apply to both the VELOS system controller and partition.

  • Add a remote syslog server using the webUI
  • Add a remote syslog server using the CLI
  • Modify a remote syslog server configuration using the webUI
  • Modify a remote syslog server configuration using the CLI
  • Remove a remote syslog server configuration using the webUI
  • Remove a remote syslog server configuration using the CLI

Add a remote syslog server using the webUI

To add a remote syslog server using the webUI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To perform this procedure at the system controller level, log in to the webUI of the VELOS chassis as the chassis administrator. To perform this procedure at the partition level, log in to the webUI of the partition as the partition administrator.
  2. Go to SYSTEM SETTINGS > Log Settings.
  3. Under the Remote Log Servers section, select Add.
  4. Enter either the IP address or the FQDN of the remote syslog server in the Host setting.
  5. Enter the listening port of the remote syslog server in the Port setting.
  6. Depending on the protocol supported by your remote syslog server, select either TCP or UDP for the Protocol setting.
  7. Select local0 for the Facility setting.

    Note: Only the LOCAL0 logging facility is supported at this time.

  8. Select your desired minimum severity level of log messages to send to the remote syslog server in the Severity setting.
  9. To save the changes, select Save & Close.

Add a remote syslog server using the CLI

To add a remote syslog server using the CLI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To perform this procedure at the system controller level, log in to the CLI of the floating management IP address as the chassis administrator. To perform this procedure at the partition level, log in to the CLI of the partition’s floating management IP address as the partition administrator.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. To add a remote syslog server, use the following command syntax:

    system logging remote-servers remote-server <IP address or FQDN> config proto <TCP or UDP> remote-port <listening port>

    For example, to add a remote syslog server 192.168.61.132 listening on UDP port 514, enter the following command:

    system logging remote-servers remote-server 192.168.61.132 config proto udp remote-port 514

  4. To configure the severity level of log messages to send to this remote syslog server, use the following command syntax:

    selectors selector LOCAL0 <severity>

    Using the example from the previous step, enter the following command to configure the log message severity level of ERROR and higher to send to the remote syslog server:

    selectors selector LOCAL0 ERROR

  5. To save the configuration, enter the following command:

    commit

  6. Exit the configuration mode terminal by entering the following command twice:

    exit

  7. To verify the remote syslog server configuration you configured, enter the following command:

    show running-config system logging remote-servers

    The command output appears similar to the following example:

    system logging remote-servers remote-server 192.168.61.132
     config remote-port 514
     config proto udp
     selectors selector LOCAL0 ERROR
    !

Modify a remote syslog server configuration using the webUI

To modify a remote syslog server configuration using the webUI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To perform this procedure at the system controller level, log in to the webUI of the VELOS chassis as the chassis administrator. To perform this procedure at the partition level, log in to the webUI of the partition as the partition administrator.
  2. Go to SYSTEM SETTINGS > Log Settings.
  3. Select the IP address or FQDN of the desired remote syslog server under the Host column of the Remote Log Servers section.
  4. Modify the desired settings as appropriate. For example, if you want to change the severity level of log messages to send to the remote syslog server to ERROR and higher, select ERROR for the Severity setting.
  5. To save your changes, select Save & Close.

Modify a remote syslog server configuration using the CLI

To modify a remote syslog server configuration using the CLI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To perform this procedure at the system controller level, log in to the CLI of the floating management IP address as the chassis administrator. To perform this procedure at the partition level, log in to the CLI of the partition’s floating management IP address as the partition administrator.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. Depending on your desired change, perform one of the following actions:
    • To modify the listening port of the remote syslog server configuration, use the following command syntax:

      system logging remote-servers remote-server <IP address or FQDN> config remote-port <new listening port>

    • To modify the protocol of the remote syslog server configuration, use the following command syntax:

      system logging remote-servers remote-server <IP address or FQDN> config proto <TCP or UDP>

    • To modify the log message severity of the remote syslog server configuration, you must first remove the existing log message severity configuration before adding the desired severity:

      no system logging remote-servers remote-server <IP address or FQDN> selectors selector LOCAL0 <severity level>
      system logging remote-servers remote-server <IP address or FQDN> selectors selector LOCAL0 <severity level>

    For example, to change the log message severity level from ERROR to DEBUG, enter the following command:

    no system logging remote-servers remote-server 192.168.61.132 selectors selector LOCAL0 ERROR
    system logging remote-servers remote-server 192.168.61.132 selectors selector LOCAL0 DEBUG

  4. To save the configuration, enter the following command:

    commit

  5. Exit the configuration mode terminal by entering the following command twice:

    exit

  6. To verify the remote syslog server configuration you configured, enter the following the command:

    show running-config system logging remote-servers

    The command output appears similar to the following example:

    system logging remote-servers remote-server 192.168.61.132
     config remote-port 514
     config proto udp
     selectors selector LOCAL0 DEBUG
    !

Remove a remote syslog server configuration using the webUI

To remove a remote syslog server configuration using the webUI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To perform this procedure at the system controller level, log in to the webUI of the VELOS chassis as the chassis administrator. To perform this procedure at the partition level, log in to the webUI of the partition as the partition administrator.
  2. Go to SYSTEM SETTINGS > Log Settings.
  3. Check the desired remote syslog server entry from the list of remote syslog servers under Remote Log Servers section.
  4. To initiate the removal, select Delete.
  5. To confirm the deletion, select OK.

Remove a remote syslog server configuration using the CLI

To remove a remote syslog server configuration using the CLI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To perform this procedure at the system controller level, log in to the CLI of the floating management IP address as the chassis administrator. To perform this procedure at the partition level, log in to the CLI of the partition’s floating management IP address as the partition administrator.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. To remove a remote syslog server configuration, use the following command syntax:

    no system logging remote-servers remote-server <IP address or FQDN>

    Using the example from previous procedure, enter the following command to remove the remote syslog server 192.168.61.132:

    no system logging remote-servers remote-server 192.168.61.132

  4. To save the configuration, enter the following command:

    commit

  5. Exit the configuration mode terminal by entering the following command twice:

    exit
