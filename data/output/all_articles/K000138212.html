K000138212: [F5OS] SNMP log reports "v2" for v3 trap

Type
Support Solution
Published
2024-01-22
Updated
2024-01-22
Source
https://my.f5.com/manage/s/article/K000138212

Description

F5OS sent snmpv3 trap, however, log says

RSeries_appliance# file show log/system/snmp.log

<INFO> 12-Jan-2024::14:22:16.378 appliance-1 confd[117]: snmp snmpv2-trap reqid=1727951570 x.x.x.x:162 (TimeTicks sysUpTime=554350788)(OBJECT IDENTIFIER snmpTrapOID=linkUp)(INTEGER ifIndex.0.=33554435)(INTEGER ifAdminStatus.0.=2)(INTEGER ifOperStatus.0.=1)

<INFO> 12-Jan-2024::14:22:16.769 appliance-1 confd[117]: snmp snmpv2-trap reqid=1727951571 x.x.x.x:162 (TimeTicks sysUpTime=554350828)(OBJECT IDENTIFIER snmpTrapOID=linkDown)(INTEGER ifIndex.0.=33554435)(INTEGER ifAdminStatus.0.=2)(INTEGER ifOperStatus.0.=2)

 

Environment

  • rSeries / Velos
  • F5OS-A / F5OS-C
  • SNMPv3
  • log
 

Cause

  • By design: ConfD snmp agent treats snmpv2-traps and snmpv3-traps the same at code level.
 From RFC3584
"   SNMPv3 also uses the SNMPv2 definitions of RFCs 3416 through 3418 and
   the SMIv2 definitions of 2578 through 2580 described above.  Note
   that text throughout this document that refers to SNMPv2 PDU types
   and protocol operations applies to both SNMPv2c and SNMPv3.
"

RFC3416  Section: 4.2.6 describes the snmpv2 trap format.
 

Recommended Actions

SNMPv3 log is recorded as "snmpv2-trap".

You can check it is sending as snmpv3 on wire:

[root@appliance-1(RSeries_appliance) ~]# tcpdump -s0 port 162 -vv
