Known Issue

The BIG-IP APM local user database dynamic user records may remain cached.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy uses a local user database for authentication.
  • Users attempting to authenticate are dynamically created in the local user database.

Dynamic users' entries in the memcached/Session database should be removed after their corresponding records are deleted from the MySQL database. However, a race condition might occur when identifying dynamic users in MySQL and removing entries from memcached. As a result, dynamic users' entries will remain in memcached until reboot.

Impact

When authenticating dynamic users, the BIG-IP APM system uses stale and erroneous user information from the cache.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Dynamic users attempting to log in to the BIG-IP APM access profile are denied access.
  • Dynamic users remain locked out until reboot.
  • Locked out dynamic users' entries are not visible in the BIG-IP APM Configuration utility (Access Policy > Local User DB).
