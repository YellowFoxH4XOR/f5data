K000149760: Client Certificate Authentication with Edge Client and Mac OS

Type
Support Solution
Published
2025-02-12
Updated
2025-02-12
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000149760

Description

Using On Demand Client Certificate Authentication OR Certificate Inspection fails

  • Mac OS does not send a certificate when using edge client
  • APM follows the fallback branch of either Certificate Inspection or On Demand Certificate Authentication
  • Cert auth fails and follows fallback branch. Recent versions of Bigip now has the ability to "Log SSL Client Authentication Events" in the clientssl profile. In the case of Client Certificate Inspection, LTM log will log a message "No cert found"

Environment

Relevant environmental factors specific to the topic

  • APM
  • On Demand Certificate Authentication OR Certificate Inspection configured in the VPE

Cause

The identify preference is not set properly in the Mac keychain. Starting in Mac OS Big Sur, the format of the identity preference changed


Recommended Actions

On Demand Certificate Authentication

  1.  Local Traffic -> Profiles -> SSL -> Client -> <profile name> -> Client Authentication set "Client Certificate" to "Ignore"
  2. In the mac keychain, find the certificate and set the identity preference
    1. find the client certificate in question (This can be in the System keychain or Login keychain)
    2. Right click the certificate and select to add a "New Identity Preference"
    3. In the Location or Email Address: prompt, enter the url for the hostname that users use to access the Virtual Server with a path of my.policy followed by a space and (com.f5networks.EdgeClient)
      1. ex: https://<users.hostname.com>/my.policy (com.f5networks.EdgeClient)
    4. Click Add.


Client Certificate Inspection

  1. Local Traffic -> Profiles -> SSL -> Client -> <profile name> -> Client Authentication set "Client Certificate" to "Request"
  2. In the mac keychain, find the certificate and set the identity preference
    1. find the client certificate in question (This can be in the System keychain or Login keychain)
    2. Right click the certificate and select to add a "New Identity Preference"
    3. In the Location or Email Address: prompt, enter the url for the hostname that users use to access the Virtual Server with a path of my.policy followed by a space and (com.f5networks.EdgeClient)
      1. ex: https://<users.hostname.com>/ (com.f5networks.EdgeClient)
    4. Click Add


Additional Information

  1. The identity preference will show up under the All Items tab within Keychain Access and the specified keychain (Login or System)
  2. The only difference between On Demand and Client Certificate Inspection is C where On Demand has my.policy in the path. This is because Client Certificate inspection happens at the ClientSSL profile (/) whereas On Demand starts when the object is hit in the policy (/my.policy).
  3. Setting Client Certificate to require may be good when testing and may work to get past the client certificate request of the clientssl profile but starting edge client will fail with an authentication error in the edge log OR client side checks may hang
