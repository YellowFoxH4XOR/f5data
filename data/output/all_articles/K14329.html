Known Issue

BIG-IP systems may experience higher CPU utilization when configured to use cookie encryption.

This issue occurs when all of the following conditions are met:

  • Virtual servers use an HTTP profile configured to use cookie encryption
  • The BIG-IP system experiences a reboot, failover, or restart of TMM

Following a reboot, failover, or restart of TMM, the BIG-IP must generate a new key to decrypt the cookie. The BIG-IP system should then cache the key internally. However, when TMM performs subsequent lookups for the key, the lookups will fail. As a result, TMM regenerates and caches those keys continuously.

Impact

The BIG-IP experiences a higher than normal CPU utilization.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H417271 on the Diagnostics > Identified > Medium screen.
  • Performance of virtual servers configured with cookie encryption can be impacted.
  • CPU statistics for the BIG-IP are higher than the trended average.
  • Running the tmctl -w 200 tmm_aes_stat command will show an unusually high number of keys_derived and keys_evicted.

    For example:

    keys keys_cached keys_evicted keys_found keys_reused keys_derived
    ---- ----------- ------------ ---------- ----------- ------------
    8192 8192 942528 24 0 950712

Workaround

To work around this issue, you can disable HTTP cookie encryption. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system will no longer encrypt cookies for the affected HTTP profile.

Important: When a client HTTP request contains an encrypted cookie, the BIG-IP LTM system will re-load balance the request. For subsequent requests, the BIG-IP system will not attempt to decrypt the cookie and will treat a returning client request as a new request and re-load balance it. To offset the impact of changing the cookie encryption to disabled, you can enable source address fallback persistence on the affected virtual server. F5 recommends that you enable the fallback persistence well in advance (at least five minutes) before disabling cookie encryption.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To disable cookie encryption for the desired HTTP profile, use the following command syntax:

    modify ltm profile http <http-profile-name> encrypt-cookies none
  3. To save the configuration, type the following command:

    save /sys config
