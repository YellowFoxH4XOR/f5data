K9816: Using BIG-IP LTM to load-balance a BIG-IP ASM system may result in misleading source IP addresses in the BIG-IP ASM request logs

Topic

Using a BIG-IP LTM virtual server to load-balance HTTP traffic to a BIG-IP ASM system may cause requests from multiple HTTP clients to be aggregated into a single server-side connection established by the BIG-IP LTM to the BIG-IP ASM virtual server. As a result, the IP address recorded in the BIG-IP ASM request logs may not match that of the original client. If you are inserting an X-Forwarded-For header in the BIG-IP LTM virtual server, you may also notice that the X-Forwarded-For IP address does not match the IP address recorded in the BIG-IP ASM logs.

Note: For more information about X-Forwarded-For header behavior, refer to K8010: The BIG-IP ASM does not support the use of the X-Forwarded-For header for logging purposes.

This issue occurs when the BIG-IP LTM virtual server is configured to use a OneConnect profile that specifies the default mask of 0.0.0.0, and does not have SNAT enabled.

Applying a OneConnect profile with a 0-bit mask (0.0.0.0) to a virtual server allows any other client to reuse any existing server-side connections once the connection goes idle. Since the server-side connection is maintained with the original source address for the life of the connection, any request made over that connection will appear to be made by the same client. If SNAT is not enabled, all requests aggregated on that connection will appear to originate from the client source IP address for which the server-side connection was originally established. If SNAT is enabled along with OneConnect, server-side connections will still be shared by multiple clients, but the source address for all connections to the BIG-IP ASM virtual server will be the BIG-IP LTM SNAT address.

Note: For more information about this behavior, refer to K5911: Managing connection reuse using OneConnect source mask.

To mitigate this issue, you may enable SNAT on the BIG-IP LTM virtual server, disable OneConnect on the BIG-IP LTM virtual server, or configure the OneConnect profile to use a 32-bit netmask (255.255.255.255). Using a host netmask will limit the reuse of existing server-side connections to the same real client source IP for which they were originally established, which is also described in SOL5911.

Note: For more information about configuring OneConnect, refer to K7208: Overview of the OneConnect profile.
