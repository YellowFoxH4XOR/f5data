Known Issue

The BIG-IP system fails to share the active FTP control connection's last hop information with the related active FTP data connection. This issue occurs when the following condition is met:

  • The FTP virtual server has the Auto Last Hop setting enabled.

    Note: By default, the FTP virtual server has the Auto Last Hop setting set to default, which inherits the Virtual Local Area Network (VLAN) object Auto Last Hop setting as well as the Global Auto Last Hop setting (which is enabled by default). For more information, refer to K13876: Overview of the Auto Last Hop setting (11.x - 12.x).

When an FTP client establishes an active FTP control connection, to a backend FTP server through an FTP virtual server, the backend FTP server creates the corresponding data connection. With the Auto Last Hop setting enabled (by default), the FTP virtual server is expected to return this data connection through the same next hop that the FTP client connection originated from. As a result of this issue, the FTP virtual server fails to return the data connection to the FTP client through the same next hop, and instead resets the FTP server data connection (due to the lack of an FTP client route).

Impact

FTP clients fail to establish active FTP data connections to the FTP servers.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H546194 on the Diagnostics > Identified > Medium screen. 
  • FTP clients receive an FTP 425 (Can't open data connection) error message.
  • A packet capture of the affected traffic indicates that the BIG-IP system is sending an RST packet right after it receives a SYN packet from the backend FTP server.
  • The BIG-IP system logs a TCP RST message similar to the following example:

    01230140:3: RST sent from 192.168.1.9:39272 to 192.168.254.254:20, [0x271b66d:2648] No route to host

Workaround

To work around this issue, you can add an explicit route to the FTP client on the affected BIG-IP system. To do so, perform the following procedure:

Impact of workaround: To avoid traffic disruption, you should ensure that the new route to the FTP client does not overlap or take precedence over existing routes.

  1. Log in to the Configuration utility.
  2. Navigate to System > Routes.
  3. Click Add.
  4. In the Name box, type a name for the new route.
  5. For the Destination, Netmask, and Gateway Address settings, enter the route to the FTP client.
  6. Click Finished.
