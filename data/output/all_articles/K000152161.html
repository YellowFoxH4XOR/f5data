K000152161: OCSP Verification issue after upgrade

Description:

After upgrading BIG-IP APM from version OCSP and CRLDP verification may fail for client certificates during authentication in Access Policy Manager.

Typical error messages observed include:

OCSP Auth agent: Failure status 'Response Verify Failure'
CRLDP Auth agent: CRL lookup failed for LDAP url <url> reason ''
Peer cert verify error: unable to get issuer certificate (depth 1; cert /C=NL/O=QuoVadis Trustlink B.V./CN=QuoVadis Qualified Web ICA G2)

This problem is especially prominent with certificates issued by QuoVadis (DigiCert public PKI), but can affect other certificate authorities as well.

 

Applies To:

  • Product: BIG-IP Access Policy Manager (APM)
  • Configuration: APM Access Policies using OCSP and/or CRLDP Auth agents for client certificate validation
  • CA bundle configured in the OCSP/CRLDP Auth agent
  • Client certificates issued by public CAs such as QuoVadis, DigiCert, etc.

Cause

The OCSP and CRLDP Auth agents require that the full certificate chain—including the root CA certificate—be present in the CA bundle specified in their configuration settings. If the root CA is missing from this bundle, OCSP and CRLDP verification will fail with "unable to get issuer certificate" errors even if intermediate certificates are present or network-level checks appear successful. This stricter enforcement was not present in previous versions.

 

Recommendations:

  • Edit the CA bundle file referenced by your OCSP and/or CRLDP Auth agent configuration so it contains all necessary certificates:
    • All intermediate CAs
    • The root CA for each relevant issuing authority
  • You can validate your bundle using OpenSSL in the BIG-IP CLI: 
    • openssl verify -crl_check -CRLfile <crl_file.pem> -CAfile <ca_bundle.crt> <client_cert.pem>
  • If you see "unable to get issuer certificate," add the missing root CA(s) to your bundle.
  • After updating the CA bundle, reload or reapply your configuration on BIG-IP.
  • For environments using multiple CAs, ensure every required root/intermediate is included.
  • Confirm that any referenced OCSP or CRL URLs are reachable from BIG-IP and correctly configured.
