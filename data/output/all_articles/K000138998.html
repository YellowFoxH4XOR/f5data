Description

After upgrading to a fixed version of ID 774617 you're still seeing following logs in remote syslog server.

debug snmpd[##}: truncating integer value > 32 bits

Same logs are not seen on BIG-IP system in /var/log/daemon.log file.

Environment

  • BIG-IP unit with a fixed version of ID 774617.
  • Remote Syslog configured.
  • SNMP

Cause

  • Fix introduced for ID 774617 also changes log level from error to debug.
  • Default log level for daemon doesn't include debug, so logs are not seen in /var/log/daemon.log file.
  • However when there is a remote syslog config without a include filter, all logs - including 'debug' daemon logs are sent to syslog server ( See K13333 )
  • Finally the reason for error logs, could be because of SNMP polling/query to a generic OID - which are based of counter32 while BIG-IP uses counter64

Recommended Actions

  • Verify with your SNMP admin for which OID SNMP polling is performed and check if it can be changed to counter64 type.

       Note: Please refer to additional information section for one of such example and related section for a knowledge guide - K13322 on BIG_IP SNMP MIB files.

  • If it is confirmed that SNMP polling is to counter32 OID, you can either change related OID of contuner64 or you can filter out those reported logs to syslog server as described in Knowledge guide - K60431538: Debug snmpd[##]: truncating integer value > 32 bits messages appearing in syslog.
