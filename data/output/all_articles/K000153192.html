Description

If you are using AS3 addressDiscovery Consul Pool update, then you may need to know how these pools react to different HTTP failures

When a BIG-IP sends an HTTP Request for a Consul Pool Update, we can expect the following conditions:

 

  1. No response. In this case, for what ever reason, the request is dropped at some point, so no response is received. This would cause a Timeout, so if no response is received within 60 seconds, no change is made, and it then waits for the check interval before retrying.
  2. If an HTTP Response is received, it will then check if the HTTP Status Code is 200 OK. If it is anything other than a 200 OK, ie 3xx, 4xx or 5xx, no change is made, and it then waits for the check interval before retrying.
  3. If the HTTP Status code is 200 OK, it then checks if a JSON array with 1+ IP Addresses is received. If it is, it then checks if the IP's in the JSON array differ from the current pool members and will update the pools members if they are different, and then it waits for the check interval before retrying.
  4. If the JSON array does not contain IP Addresses, it will then check if the array is empty, and if so, no change is made, and it then waits for the check interval before retrying.
  5. If the JSON array is no empty, but does not contain IP Addresses, it will then delete the pool members from the FQDN, and then it waits for the check interval before retrying.
