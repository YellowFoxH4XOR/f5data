Description

Self IPs serve as in-band IP addresses on the BIG-IP device's VLANs (internal, external, HA, etc.), enabling communication between the device and systems on those networks. The Allow Service (or Port Lockdown) setting determines whether other hosts on the VLAN have access to the BIG-IP itself, affecting services like SSH, GUI, or sync/mirror/iQuery connections. This setting does not control traffic destined for virtual servers (VIPs). Allowing unnecessary access to self IPs can expose the device to security risks. This article outlines how to identify and mitigate such exposure.

Environment

  • BIG-IP systems
  • Self IP configuration
  • Access settings controlled via Allow Service
  • Environments using VLANs for internal, external, or HA traffic

Cause

Unnecessary access occurs due to permissive Allow Service settings on self IPs, such as All, Default, or custom lists that include admin or unused ports (e.g., 22, 443).

Answer/Recommended Actions

  1. Check the configuration via GUI:
    1. Navigate to Network > Self IPs.
    2. For each self IP, review the Allow Service setting and flag any of the following:
      • All
      • Default (if not required)
      • Custom lists including admin ports (SSH 22, TMUI/HTTPS 443) or other services not in use.
    3. Note the VLANs associated with each self IP for exposure analysis.
  2. Check via CLI:
    1. Run tmsh list net self one-line for a quick summary or tmsh list net self all-properties for detailed information.
    2. Look for entries such as allow-service all, allow-service default, or custom configurations listing unnecessary ports (e.g., tcp:4353 tcp:1028 udp:1026).
  3. Double-check from the network:
    • From a host on the same VLAN as a self IP, test access via https:// for GUI access and ssh for SSH exposure.
    • Perform a light port scan using tools like nmap to identify reachable services.
  4. Adjust self IP settings:
    1. Plan a change window to avoid disruption.
    2. If possible, use the management network for trust, sync, and failover operations to allow setting Allow None on traffic VLAN self IPs.
    3. If certain ports (e.g., iQuery for GTM/DNS or HA clustering) must be allowed, employ a custom list with explicit rules. Sample tmsh commands:
      • Set to none: tmsh modify net self allow-service none
      • Set custom list (example): tmsh modify net self allow-service { tcp:4353 tcp: udp: }
      Replace and with ports documented for your setup.
    4. Use dedicated HA/mirror VLANs for clustering and restrict port allowances to those VLAN self IPs.

Additional Information

  • Locking down self IPs does not impact GUI/SSH access via the management interface.
  • For enhanced control, configure firewall rules using BIG-IP AFM if available, but ensure proper Allow Service settings on self IPs.
  • Maintain an inventory of self IPs, VLANs, and allowed services, documenting the purpose of each setting.
  • After changes, re-test exposure using SSH/HTTPS or nmap scans from the VLAN.
