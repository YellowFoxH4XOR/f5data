Topic

The BIG-IP ASM system checks HTTP requests for unparsable content as part of HTTP compliance enforcement. When the HTTP parser cannot parse part of an HTTP request, the system triggers a Unparsable request content subviolation and provides details about the kind of parsing error that the system encountered.

For example, if the system determines that a HTTP chunk transmission is not properly terminated, you may observe the following violation information in the Event logs:

ViolationHTTP compliance sub-violationDetails
HTTP protocol compliance failedUnparsable request contentThe chunk is not terminated by an empty line (CRLF)


This article describes the Unparsable request content subviolation, and provides details about the possible parsing errors that the system may report.

Description

The following table provides violation details that the BIG-IP ASM system reports for the Unparsable request content subviolation.

Accumulated chunked length: "length" exceeds internal limitThe chunk length exceeded the internal bd limit.

Recommendations

When you encounter an HTTP protocol compliance failure due to an unparsable request content subviolation, F5 recommends that you review the violation details with consideration of your organization's security policy settings and the intended application interaction. When necessary, you can modify the associated security policy in order to avoid false-positive violations. BIG-IP ASM cannot learn HTTP protocol compliance violations, and in most cases they indicate a problem with the HTTP request.
