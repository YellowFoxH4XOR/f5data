Known Issue

The VLAN failsafe feature may cause TMM to crash with a SIGABRT.

This issue occurs when the following conditions are met:

  • The VLAN failsafe feature is enabled.
  • The IPv6 neighbor discovery table is populated with a high number of entries.
  • The VLAN failsafe feature initiates aggressive mode (3/4 of the VLAN failsafe timeout period expires).

VLAN failsafe is a high-availability feature that allows the BIG-IP system to monitor for network failure and take appropriate action when no traffic is detected on a VLAN. When VLAN failsafe does not detect network traffic on the VLAN after 3/4 of the timeout period, it enters aggressive mode. During this phase, if IPv6 entries exist in the neighbor discovery table, the system initiates ICMPv6 neighbor discovery probes. The TMM process may crash when hundreds of entries exist in the neighbor table, and the system hashes to entries to the same value.

Impact

The TMM process crashes and the BIG-IP system fails over to the standby system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • TMM crashes with a SIGABRT.
  • The BIG-IP system fails over to the standby system.
  • The system generates a TMM core file to the /shared/core directory.
  • The system logs daemon heartbeat action error messages to the /var/log/ltm file that appear similar to the following example:

    sod[4977]: 01140029:5: HA daemon_heartbeat tmm1 fails action is go offline down links and restart.
  • The neighbor discovery table contains hundreds of neighbor entries

    For example, the tmsh show /net ndp all command may display several hundred entries.

Workaround

You may be able to mitigate this issue by enabling the failover.vlanfailsafe.resettimeronanyframe database variable. To do so, perform the following procedures:

Enabling the failover.vlanfailsafe.resettimeronanyframe database variable

When the failover.vlanfailsafe.resettimeronanyframe database key is set to true, the BIG-IP system resets the timeout counter upon reception of any frame on the VLAN, including responses to BIG-IP monitor traffic.

Impact of workaround: Enabling the database variable will make it more likely that the BIG-IP system detects traffic on the VLAN and resets the VLAN failsafe timer before initiating aggressive mode.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  2. Set the DB key to either True or False, by using the following command syntax:

    modify /sys db failover.vlanfailsafe.resettimeronanyframe value true

  3. Save the change by typing the following command:

    save sys config
