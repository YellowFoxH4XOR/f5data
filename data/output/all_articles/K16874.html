Topic

You should consider using this procedure under the following condition:

  • You would like to delineate your access policy actions based on client device types not natively supported on the BIG-IP APM system.

Description

New devices are introduced to the market on a regular basis. Typically there is a lag time between the introduction of a new device and the ability to identify these natively within the BIG-IP APM access policy. In the event you would like your access policy to determine policy actions based on a new device type, you can configure the BIG-IP APM access policy to be able to identify the device.

The BIG-IP APM access policy will detect the device type agent string when the device attempts to access an access profile.

The following table lists new device types and agent strings:

Client TypeAgent String
Microsoft Windows 10Windows NT 10.0

Note: This table will be updated as new clients are identified.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have administrative access to the BIG-IP APM Configuration utility.
  • Have an existing access profile and access policy.

Procedures

Adding a unique device check to the access policy

You can add device detection as a unique action of the access policy. To do so, perform the following procedure.

Impact of procedure: The BIG-IP APM system applies policy actions of the branch to all devices that match the configured device type.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Profiles > Access Profiles List.
  3. To the right of the name of the access policy to edit, click Edit.
  4. Click the (+) symbol to the right of the action to which you want to add to the new device detection branch.
  5. Click the General Purpose tab.
  6. Select the action Empty, and click Add Item.
  7. In the Name box, type the name of the new action.

    For example:

    Windows 10 Device

  8. Click the Branch Rules tab.
  9. Click Add Branch Rule.
  10. In the Name box, type a logical name for the branch.

    For example:

    Windows 10 Device

  11. Click Change.
  12. Click the Advanced tab.
  13. Paste the following text in the text box:

    expr { [mcget { session.user.agent}] contains "<new_device_type>;" }

  14. Replace <new_device_type> with the appropriate detection text of the new device.

    For example:

    expr { [mcget { session.user.agent}] contains "Windows NT 10.0;" }

  15. Click Finished.
  16. Click Save.
  17. To apply additional policy actions for this device type, configure the detection and fallback branches of the access policy action.
  18. Click Apply Access Policy.
  19. Click Close.

Adding a new device to the access policy Client OS detection action

For access policies that currently use Client OS detection, you can add new devices as part of this action.

Impact of procedure: The BIG-IP APM system applies policy actions of the branch to all devices that match the configured device type.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Profiles > Access Profiles List.
  3. Next to the name of the access policy to edit, click Edit.
  4. Locate and click the Client OS box.
  5. Click the Branch Rules tab.
  6. Click Add Branch Rule.
  7. In the Name box, type a name for the new branch rule.

    For example:

    Windows 10 Device

  8. Click the change link of the new branch rule.
  9. Click the Advanced tab.
  10. In the Advanced box, enter the following syntax:

    expr { [mcget { session.user.agent}] contains "<new_device_type>;" }

    In the previous syntax, replace <new_device_type> with the appropriate detection text of the new device.

    For example:

    expr { [mcget { session.user.agent}] contains " Windows NT 10.0;" }

  11. Click Finished.
  12. Click Save.
  13. To apply additional policy actions for this device type, configure the detection and fallback branches of the access policy action.
  14. Click Apply Access Policy.
  15. Click Close.
