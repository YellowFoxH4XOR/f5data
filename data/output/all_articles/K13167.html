Topic

F5 has recently discovered and corrected a number of issues that affect customers running ARX version 6.1.0. F5 recommends that all customers currently running version 6.1.0 install the latest cumulative rollup hotfix available.

The following table lists the rollup hotfixes available for ARX version 6.1.0. Each hotfix lists the ID number and description for the issues fixed by the hotfix:

Note: These rollup hotfixes are cumulative; each hotfix contains the fixes included in the previous hotfixes.

ARX VersionID NumberDescription
*6.1.0 HFRU2
(build-14076)		366235Add a 2 minute timeout between the data plane and control plane for the internal CIFS path-cache.
367301NFS connections to filers could fail due to bad handling of error conditions around NFS keepalive messages.
369267Addressed an issue creating snapshots on Windows filers.  An error from the filer was not being handled properly causing retries to fail.
369429The ARX 1500 and ARX 2500 now properly reject HTTP requests to the ARX VIP.
369688Fixed a problem with slow failover recovery in namespaces using NFS metadata.
370559NLM client callbacks now originate from the first VIP that the client has connected to.
372101A problem that caused snapshot creation to fail on Windows servers using UTC as their timezone has been fixed.
   
*6.1.0 HFRU1
(build-14074)		358181The CIFS protocol specification requires that filer-assigned tree connection identifiers be unique across a single tree connection.  Several filers violated this rule, causing the ARX to be unable to connect more than one user session to any given share. The ARX has been changed to be less sensitive to strict protocol adherence in this regard.
366051Corrected an issue where an unexpected error on an NFS metadata connection resulted in a namespace restarting.
367924ARX 2000s and ARX 4000s could experience problems with vlan tagging when connected to newer upstream switches.  When this problem is present, all tagged packets will be dropped by the upstream switch.
368040If an ARX 1500 or ARX 2500 booted up with a configuration in which VLAN 1 was used and all interfaces were used as members of channels, the ARX would generate a core file and reboot.
368412Increase the size of the ARP cache on the ARX1500 and ARX2500 to allow for larger non-routed networks.
368437Corrects the manner in which available memory in the system is calculated.
368456Fixes a problem that prevents a replacement ARX from joining with the existing redundant peer.
369319Addressed an issue with NLM configurations that could result in an ARX running out of internal resources.
369794Fixes a deadlock condition in the inode allocation software that would result in a VPU eventually becoming unresponsive.

*To request this hotfix, contact F5 Technical Support.
