Description

When a redundant BIG-IP system moves to active status for a traffic group, the system broadcasts a series of gratuitous ARP (GARP) packets to the network to update ARP tables on directly connected network devices or hosts.

Devices limiting the rate of ARP packets or network loss can cause some devices to miss the GARP packets, resulting in a situation in which a virtual server or floating self IP address on an active BIG-IP system becomes unreachable due to network devices or hosts sending packets to the wrong device or to the standby BIG-IP system.

If this is a recurring issue due to ARP rate-limiting on a receiving upstream network device or host, consider modifying the BIG-IP system to send GARPs at a slower rate. For more information, refer to K11985: Overview of the arp.gratuitousrate and arp.gratuitousburst database variables. Slowing the GARP rate increases the amount of time it takes the system to complete the full GARP.

If you want to minimize ARP communication during failover events, consider configuring MAC masquerade on the traffic group which allows a MAC address to be shared between BIG-IP systems. For more information, refer to K13502: Configuring MAC masquerade (11.x - 17.x).

Environment

  • BIG-IP system

Cause

None

Recommended Actions

  • BIG-IP versions 14.x and later
  • BIG-IP versions prior to 14.x

BIG-IP versions 14.x and later

For BIG-IP VE

Option 1

  1. Create a trunk that includes no interfaces.
  2. Create a dummy VLAN and associate the newly created trunk to it.
  3. BIG-IP system will advertise gratuitous ARPs.
  4. Delete the dummy VLAN.
  5. Delete the newly created trunk.

Option 2

  1. Create a trunk that includes a UP physical interface.
  2. BIG-IP system will advertise gratuitous ARPs.
  3. (Optional) Remove that UP physical interface from this new-created trunk.
  4. (Optional) BIG-IP system will also advertise gratuitous ARPs.
  5. Delete the newly created trunk.

Option 3

  1. Disable any of UP interface (Preferably the one not being used for service traffic).
  2. Re-enable the interface.
  3. BIG-IP system will advertise gratuitous ARPs.

For BIG-IP 2000/4000 series

Option 1

  1. Create a trunk that includes no interfaces.
  2. Create a dummy VLAN and associate the newly created trunk to it.
  3. BIG-IP system will advertise gratuitous ARPs.
  4. Delete the dummy VLAN.
  5. Delete the newly created trunk.

Option 2

  1. Disable a UP interface that is not currently used (Using a UP interface that is currently in use will prevent GARPs to go out from the interface when enabled).
  2. Re-enable the interface.
  3. BIG-IP system will advertise gratuitous ARPs.

For BIG-IP i850/i2000/i4000 series

Option 1

  1. Create a trunk that includes a UP physical interface.
  2. BIG-IP system will advertise gratuitous ARPs.
  3. (Optional) Remove that UP physical interface from this new-created trunk.
  4. (Optional) BIG-IP system will also advertise gratuitous ARPs.
  5. Delete the newly created trunk.

Option 2

  1. Disable any interface (You may use Down or Unpopulated interfaces; Using a UP interface will prevent GARPs to go out from the interface when enabled).
  2. Re-enable the interface.
  3. BIG-IP system will advertise gratuitous ARPs.

For other BIG-IP appliances and VIPRION systems with switch chips

  1. Create a trunk that includes a UP physical interface.
  2. BIG-IP system will advertise gratuitous ARPs.
  3. (Optional) Remove that UP physical interface from this new-created trunk.
  4. (Optional) BIG-IP system will also advertise gratuitous ARPs.
  5. Delete the newly created trunk.

For BIG-IP tenants on r2000/r4000 series

  1. Disable any of UP interface inside a BIG-IP tenant (Preferably the one not being used for service traffic).
  2. Re-enable the interface.
  3. BIG-IP system will advertise gratuitous ARPs.

For BIG-IP tenants on r5000/r10000 series and VELOS

  1. Disable and enable all TMM interfaces inside a BIG-IP tenant. To do that, run the following command.
    tmsh modify net interface all no-mgmt disabled ; tmsh modify net interface all no-mgmt enabled
  2. BIG-IP system will advertise gratuitous ARPs.

For all platforms

  1. Force device offline.
  2. Release from offline.
  3. BIG-IP system will advertise gratuitous ARPs for floating self IPs and listener IPs such as virtual addresses, NAT, and SNAT.

For specific virtual-address all platforms

Disable/Enable specific virtual-addresss

1. Access F5 WebGUI
2. Local Traffic > Virtual Address List > select specific Virtual Address 
3. Change State from "Enabled" > "Disable" and uncheck the ARP section
For example
 
4. Click "Update" (Green circle will change to Grey circle)
5. Wait for 5 second, then Enable it again
 

6. Then "Update", BIG-IP will advertise GARP only specific IP address

 

BIG-IP versions prior to 14.x

To force the BIG-IP system to resend GARP packets by creating and deleting a temporary new VLAN and self IP address. The creation and deletion of a single new self IP address is sufficient to cause all self IP and active virtual addresses to resend GARP packets.

Impact of procedure: As long as you choose a VLAN name and self IP address that are not already in use, performing this procedure should not negatively impact traffic.

  1. Log in to bash.
  2. Create a temporary VLAN using the following command:

    tmsh create /net vlan vlan_temp

  3. Create a corresponding self IP address by entering the following command:

    tmsh create /net self self_temp address 198.51.100.1/32 vlan vlan_temp

  4. Delete the temporary self IP address by entering the following command:

    tmsh delete /net self self_temp

  5. Delete the temporary VLAN by entering the following command:

    tmsh delete /net vlan vlan_temp
