Topic

This article applies to BIG-IP GTM version 9.x through 10.x. For information about other versions, refer to the following article:

  • K13347: Overview of the BIG-IP GTM configuration file (11.x)

A BIG-IP GTM configuration is comprised of the different components that make up the physical and logical segments of the network. These components are stored in the BIG-IP GTM configuration files and represent the configuration that the BIG-IP GTM uses to direct DNS traffic to the best available resource.

The following BIG-IP GTM configuration files are located in the /config/gtm/ directory:

  • wideip.conf
  • region.ACL
  • region.user
  • topology.inc

Note: F5 recommends using the Configuration utility to configure the BIG-IP GTM system. However, if you edit any of the BIG-IP GTM configuration files directly, you should check the syntax after saving the changes by running the gtmparse command, and then re-loading the configuration files to memory by running the gtmload command.

The wideip.conf file

The wideip.conf file is the main BIG-IP GTM configuration file. It contains the components that comprise the physical network, such as data centers, servers, and links, and the components that comprise the logical network, such as wide IPs, pools, and global settings. Most of the configuration components you build using the Configuration utility are saved to the wideip.conf file.

The following sections of the wideip.conf file are described below:

  • Globals
  • Data Center Definitions
  • Monitor Definitions
  • Link Definitions
  • Server Definitions
  • Pool Definitions
  • Wide IP Definitions
  • Application Definitions

Globals

The globals section of the wideip.conf file contains global variables for the BIG-IP GTM system, including load-balancing, metrics collection, and general configuration parameters. Global variables are configured in the Configuration utility under System > General Properties (Configuration in version 10.x) > Global Traffic.

Note: The globals section of the wideip.conf file displays global parameters that have been changed from the default setting to a new value. Parameters that remain at the default setting are not displayed in the wideip.conf file.

For example, the following globals section of the wideip.conf file shows the global parameters that have been changed from the default setting:

globals {
   probe_protocol {
      dns_dot
      dns_rev
      icmp
   }
   sync_group "syncgroup1" // Default="default"
   fb_respect_depends         yes               // Default=no
   gtm_sets_recursion         yes               // Default=no
   rtt_timeout                5                 // Default=3
   autosync                   yes               // Default=no
   time_tolerance             20                // Default=10
   certificate_depth          1                 // Default=0
}

Note: For a description of BIG-IP GTM global variables, refer to K9629: Overview of BIG-IP GTM global variables.

Data Center Definitions

A data center defines the physical network components such as the servers (GTMs, LTMs, hosts), and links that share the same subnet on the network.

For example, the following data center section of the wideip.conf file shows the number of servers and links contained in each data center:

// *** Data Center Definitions (2) ***
datacenter { // 1 server(s)
   name     "Los Angeles"
   location "Wilshire Blvd. Facility"
   contact  "user@askf5.com"
   server "bigip2"
   link "Los Angeles"
}
datacenter { // 3 server(s)
   name     "New York"
   location "Madison Avenue Facility"
   contact  "user@askf5.com"
   server "bigip1"
   server "cache1"
   server "cache2"
}

The data center parameters are defined in the following table:

Data center parameterDescription
nameDefines the name of the data center.
locationDefines the physical location of the data center.
contactDefines the administrator of the data center.
serverDefines the server objects that reside in the data center.
linkDefines the link objects that reside in the data center.

Monitor Definitions

BIG-IP GTM monitors check the status of a pool or virtual server at a set interval.

For example:

// *** Monitor Definitions (1) ***
monitor "icmp_mon" {
   defaults from "icmp"
   interval 30
   timeout 120
   probe_interval 1
   probe_timeout 5
   probe_num_probes 3
   probe_num_successes 1
   dest *
   partition "Common"
}

Monitor parameterDefinition
intervalIndicates how often a probing request will be sent out from the gtmd process to the big3d process.
timeoutIndicates how long the gtmd process waits for a monitor response before timing out.
probe_intervalIndicates how long the big3d process will wait before sending out another probe attempt for a simple monitor.
probe_timeoutIndicates how long the big3d process will wait for a response from a probe target before timing out the probe attempt.
probe_num_probesIndicates how many probe attempts the big3d process will make before considering a probe target down.
probe_num_successesIndicates how many probe successes big3d requires for the target to be considered up.

Link Definitions

A link is a BIG-IP GTM or BIG-IP Link Controller object that defines a physical connection to the Internet. A link is associated with one or more routers on the network that provide a path to the Internet.

For example, the following link definition resides in the New York data center and contains a link and uplink address:

// *** Link Definitions (1) ***
link { // datacenter=New York
   name        "New York"
   address     10.10.0.254
   uplink_address 172.20.11.254
}

Link parameterDefinition
nameDefines the name of the link.
addressDefines the router IP address on the network that provides a path to the Internet.
uplink addressDefines the router IP address on the ISP side of the link.

Server Definitions

A server defines a specific system on the network. In the BIG-IP GTM configuration, servers contain the virtual server objects to which name resolution requests are load-balanced.

For example, the following server definition resides in the New York data center, and contains two virtual servers.

// *** Server Definitions (11) ***
server { // datacenter=New York, #VS=2
   name            "bigip1"
   type            bigip
   box {
      address 172.20.11.86 translates to 10.10.0.86
      unit_id 2
   }
   box {
      address 172.20.11.87 translates to 10.10.0.87
      unit_id 2
   }
   autoconf        enable
   monitor "icmp_mon"
   allowed_monitors {
      svc_check        no
   }
   vs {
      address         172.20.11.1:80 // http
      translates to 10.10.0.1:80
   }
   vs {
      address         172.20.11.2:80 // http
      translates to 10.10.0.2:80
   }
}

Server parameterDefinition
nameDefines the server name.
typeDefines the server type.
boxDefines the server IP address, address translation information, and unit_id.
autoconfIndicates that Virtual Server Discovery is enabled for the server object.
monitorDefines the monitor that is configured for the server.
vsDefines the virtual servers and vs IP addresses that are configured for the server.

Note: The unit_id parameter in the wideip.conf file indicates the order in which the gtmd process input the server IP addresses when the server object was created. The wideip unit_id does not relate to and is not the same as the high availability Unit ID setting configured on redundant BIG-IP LTM devices.

Pool Definitions

A pool contains one or more virtual servers that share a common role on the network.

For example:

// *** Pool Definitions (11) ***

pool {
   name           "origin"
   limit {
      bits_per_sec  1.2 Gbps
   }
   ttl            30
   preferred      rr
   partition "Common"
   member         172.24.100.1:80
   member         172.30.11.1:80
   member         172.20.11.1:80
   member         172.24.0.5:80
}

Pool parameterDefinition
nameDefines the pool name.
limitThe resource thresholds the GTM uses to take pools in and out of service based on virtual server load.
ttlThe number of seconds that the resolution request can be cached by the client.
preferredThe pool load balancing mode that the system tries first.
memberThe virtual server IP addresses and service ports.

Wide IP Definitions

A wide IP is a mapping of a fully-qualified domain name (FQDN) to a group of virtual servers that host the domain’s content.

For example, the following wide IP definition uses topology load-balancing to distribute connections between two pools:

// *** Wide IP Definitions (1) ***

wideip {
   name         "cdnbridge.siterequest.com"
   pool_lbmode  topology
   partition "Common"
   pool         "origin"
   pool         "cdn"
}

wide IP parameterDefinition
nameThe name of the wide IP.
pool_lbmodeThe load balancing method gtmd uses to select a wide IP pool.
partitionThe administrative partition in which the object resides.
poolThe load-balancing pools configured for the wide IP.

Application Definitions

A distributed application is a collection of wide IPs that serve as a single application to a site visitor.

For example:

// *** Application Definitions (1) ***
application {
   name          "cdn_app"
   wideip        "cdnbridge.siterequest.com"
   wideip        "ecommerce.siterequest.com"
   availability  server
   partition "Common"
}

Application parameterDefinition
nameThe name of the distributed application.
wideipThe wide IPs that are in the configuration.
availabilityThe status of the distributed application.

The region.ACL file

The region.ACL file contains the addresses and network segments for which the BIG-IP GTM system does not collect metrics information. You define the address exclusion list in the Configuration utility under System > General Properties (Configuration in version 10.x) > Global Traffic > Metrics Collection > Address Exclusions.

For example, the following region.ACL file excludes three networks from BIG-IP GTM metrics collection:

region_db ACL {

   region {
      name   "metrics_acl"
      65.33.0.0/16
      64.12.0.0/16
      204.162.8.0/24
   }
}

The region.user file

The region.user file contains a customized collection of topology regions used for topology load balancing. You define the topology regions in the Configuration utility under Global Traffic > Topology > Regions.

For example:

region_db user {

   region {
      name   "Spanish-Speakers"
      continent."South America"
      country."MX"
      country."ES"
   }

   region {
      name   "English-Speakers"
      country."AU"
      country."NZ"
      country."US"
      country."GB"
      country."CA"
   }
}

The topology.inc file

A topology is one or more characteristic that identifies the origin of a given name resolution request. You can define topologies that belong to one of several categories. You define the topology records in the Configuration utility under Global Traffic > Topology > Records.

For example:

// server        ldns        score
   pool."es"             user."Spanish-Speakers"     100
   pool."en"             user."English-Speakers"     100
   172.16.120.0/24       continent."Asia"          60
   172.16.120.0/24       continent."Australia"      60
   pool."origin"         continent."Europe"        40
   pool."origin"         continent."South America"      40
   pool."origin"         continent."North America"      40
   pool."en"             !user."Spanish-Speakers"      50
   172.16.100.0/24       !continent."Australia"      60
   172.16.110.0/24       !continent."Australia"      60
   172.16.100.0/24       !continent."Asia"         60
   172.16.110.0/24       !continent."Asia"         60
   pool."cdn"            !continent."Europe"       40
   pool."cdn"            !continent."South America"      40
   pool."cdn"            !continent."North America"      40
}
