Description
Failover fails to move/activate virtual address on peer BIG-IP VE instance which is located in another Availability Zone (AZ).
Log message similar to the following are logged to in /var/log/ltm :

err logger[<PID>]: /usr/libexec/aws/aws-failover-tgrefresh.sh (traffic-group-1): Encountered an error while parsing the network description: Unable to locate ENI for instance <instance id> on subnet <subnet id>

info logger[<PID>]: /usr/libexec/aws/aws-failover-tgrefresh.sh (traffic-group-1): IP address specified during HA takeover is not assigned to any interface. instance-id: <instance id>. IP address: <virtual address>

Environment

  • AWS
  • BIG-IP VE 
  • HA pair
  • Instances across different Availability Zones (AZs)
  • Failover

Cause

For an HA pair that spans across different AZs in AWS, there will be a single EIP bound to the virtual address for each BIG-IP VE instance; namely one EIP bound to two virtual addresses. On failover, the EIP will remap to the virtual address on the other VE instance. AWS itself is what controls a failover in this type of deployment and this is why you have two virtual servers for one application.

But by default, virtual address belongs to traffic-group-1 and it tries to float to the Active HA peer when a failover happens.

Recommended Actions

Execute the following commands from the BIG-IP VE command line to set traffic group for all virtual addresses to "none":

# tmsh
tmsh modify /ltm virtual-address all traffic-group none
tmsh save /sys config
tmsh run /cm config-sync to-group <device group for synchronization>
Note: Replace <device group for synchronization> with the name of the device group of your BIG-IP pair.
