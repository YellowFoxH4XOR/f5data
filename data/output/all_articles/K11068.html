Known Issue

This is the result of a known issue. An iRule containing a RULE_INIT event that references a Data Group may fail to initialize. This issue occurs after the TMM process is restarted or after a system reboot, and does not typically occur when the iRule is first created.

Upon restart, TMM processes MCP messages related to iRules before processing messages related to Data Groups. As a result, an iRule containing a RULE_INIT event that references a Data Group is unable to access the Data Group logic after TMM restarts. When this occurs, the iRule does not initialize and an error message is logged to the /var/log/tmm file that appears similar to the following example:

1031000 in mcpmsg_to_database

Important: The Message Security Module (MSM) uses an iRule containing a RULE_INIT event and Data Group reference. When TMM is restarted on a system licensed for MSM, the iRule does not initialize and any connections to a virtual server using the MSM iRule will trigger a TCL runtime error and reset.

F5 Product Development tracked this issue as CR132122 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, and WebAccelerator release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP version 10.0.1 and in Hotfix-BIGIP-10.1.0-3372.0-HF1 issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes on systems with a logical volume management (LVM) disk-formatting scheme, refer to K10025: Managing BIG-IP product hotfixes (10.x).

Workaround

You may be able to temporarily work around this issue by deleting and recreating the iRule; however, the next time TMM restarts, the iRule will fail to initialize.

Note: This workaround does not apply to the MSM iRule.
