Known Issue

This is the result of a known issue. When the Least Connections (node) load balancing mode is enabled for a pool, the BIG-IP system always selects the same pool member among equivalent candidate pool members.

For example, if the pool contains three members and each node has one current connection, the BIG-IP LTM will always send the next connection request to a particular pool member in the pool. As a result, the BIG-IP LTM has a load balancing bias (in terms of number of requests) to specific pool members.

Note: When members in a Least Connections (node) pool are tied with an equal and fewest number of connections, the BIG-IP should attempt to distribute subsequent requests evenly among those members.

F5 Networks Product Development tracked this issue as CR113057, and it was fixed in BIG-IP version 9.4.8 and version 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Note: The Least Connections (member) load balancing mode selects the first pool member among equivalent candidate members. For more information, refer to K7979: The Least Connections (member) load balancing mode always selects the first pool member among equivalent candidate members.
