Known Issue

This is the result of a known issue. When 3-DNS uses UDP iQuery to probe a BIG-IP through two different routes, auto_lasthop should track each UDP stream and return the response to the same router on which the request arrived.

In BIG-IP versions 9.0.0 through 9.1.0, auto_lasthop does not work correctly with UDP. Instead of tracking separate connections for each UDP stream, BIG-IP treats both streams as one connection because they both have the same source address. Since both streams are treated as one connection, BIG-IP returns all response packets to 3-DNS through the route that was first used as a last hop address for the connection. As a result, some of the UDP iQuery responses are sent through the incorrect route and do not reach 3-DNS. When 3-DNS does not receive a response, it marks BIG-IP as down.

F5 Product Development is tracking this issue as CR45496.

Workaround

You can work around this issue by using TCP iQuery instead of UDP iQuery. TCP iQuery connections work correctly with auto_lasthop.
