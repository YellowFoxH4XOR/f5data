K000164029: Data for the external data group does not propagate to the Traffic Management Microkernel (TMM)

Type
Support Solution
Published
2026-10-28
Updated
2026-10-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000164029

Description

After adding/deleting an entry in external data group, the data for the external data group does not propagate to the Traffic Management Microkernel (TMM).

This issue occurs when all of the following conditions are met:

  • You added/deleted an existing external data group.
  • You then imported a new data group or edit an existing data group.
  • The ltm log shows "update queued" without a matching "update finished"
    run grep -i "<datagroup name>" /var/log/ltm | grep -i update 
    Oct 28 16:26:04 bigip1-B.local notice tmm[1075]: 01010259:5: External Datagroup (/Common/<datagroup name>) queued for update.
    Oct 28 16:26:04 bigip1-B.local notice tmm2[1075]: 01010259:5: External Datagroup (/Common/<datagroup name>) queued for update.
    Oct 28 16:26:04 bigip1-B.local notice tmm1[1075]: 01010259:5: External Datagroup (/Common/<datagroup name>) queued for update.
    Oct 28 16:26:04 bigip1-B.local notice tmm[1075]: 01010259:5: External Datagroup (/Common/<datagroup name>) update finished.
    Oct 28 16:26:04 bigip1-B.local notice tmm2[1075]: 01010259:5: External Datagroup (/Common/<datagroup name>) update finished.
    Oct 28 16:26:04 bigip1-B.local notice tmm1[1075]: 01010259:5: External Datagroup (/Common/<datagroup name>) update finished.
  • run tmctl ext_class_stat | grep -i <datatgroup name> and the total_entries column does not reflect the changes.

 

Environment

BIG-IP

 

Cause

Uncertain but likely a corrupted binary configuration image.

 

Recommended Actions

  • To work around this issue, you can force the mcpd process to reload the BIG-IP configuration. Refer to:

K13030: Forcing the mcpd process to reload the BIG-IP configuration
https://my.f5.com/manage/s/article/K13030
