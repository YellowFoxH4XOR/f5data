Description

  • log messages pertaining to /var/log exceeding threshold even after log rotation is routinely observed
  • error messages look similar to the one below appear in /var/log/ltm
           alertd[pid]: 01100046:4: Warning: /var/log disk usage is more than 80%

Environment

  • BIG-IP
  • manual syslog configuration that points to a local file as a destination for the logs
i.e.
}
sys syslog {
    include "
    filter loghost {
        facility(local0) and
        level(emerg..info);
    };
    destination local_file {
        file(/var/log/my_local_file);
    };
    log {
        source(s_syslog_pipe);
        filter(loghost);
        destination(local_file);
    };
    "
}
 

Cause

The local file is not included in the logrotation script by default and it can fill up the /var/log directory.

Recommended Actions

  1. Review your configuration to verify the need to log locally. The BIG-IP is not designed to be a logging server so logging to a remote server is preferred.
  2. In the event that logging to a local file is required, then configure log rotation to include said file. The steps are as follows. Copy and paste the commands per line item. You can modify the individual logrotate parameters before pasting the configuration.
1. tmsh
2. save sys ucs filename.ucs
3. load sys config merge from-terminal
4. sys log-rotate include "/var/log/my_local_file {
      compress
      missingok
      notifempty
      daily
      rotate 5
      size 1M
      maxsize 1024000k
      create
}
"
5. tmsh save sys config


To rollback:

1. tmsh modify sys log-rotate include none
2. tmsh save sys config

Note that these changes might need to be done on both devices in an HA pair and will not survive upgrades. For further information on the 'logrotate' utility, you can consult the Linux manpages.
