Description

How to correctly monitor the used memory of the BIG-IP with SNMP

Environment

  • BIG-IP
  • SNMP
  • Solarwinds / MRTG / Cacti / PRTG or other SNMP tool

Cause

High memory usage is observed on your SNMP tool, even though your BIG-IP is not under load.

Recommended Actions

When monitoring the Memory usage of the BIG-IP, do not use the Standard Linux MIB Library, you will have inaccurate and incorrect information. The BIG-IP does not manage its memory in a way that can be recognised by the Standard MIBs.

Before you begin, you must understand how the memory of the BIG-IP is set out. The memory is proportioned out for "TMM" use and "Other" use. When the BIG-IP is initially provisioned, a portion of memory is designated exclusively for TMM, and the remaining memory is designated for other processes not related to TMM. These are handled and managed independently by the BIG-IP. The TMM memory is managed exclusively by BIG-IP TMOS, and Other memory is managed by the Linux kernel.

The standard OID will accurately report the total memory, but will give a false reading on the used memory, often it can be somewhere between 90% and 95% on a relatively quiet device.

The correct OID for used memory can also give a false reading, despite accurately reporting how much is used out of the total memory. Assume you have a system with 16Gb of total memory. Typically 10Gb would be for TMM memory, while 6Gb would be used for Other memory. If the SNMP OID reports that 12Gb is used, this means you have 4Gb free. You might think that this is satisfactory; however, it might be that 9.5Gb of the TMM memory is used, while 2.5Gb of Other memory is used. So this means that TMM memory is actually approaching a critical state, while Other memory is OK; therefore, you must monitor both parts of the memory independently to get accurate information.

There are OIDs for TMM total memory, and TMM used memory, Other total memory, and Other used memory.There are also OIDs for device total memory, and device used memory. The MIB files for these can be obtained by using the procedures in the following article K13322: Overview of BIG-IP MIB files.

You will observe that TMM total memory + Other total memory = device total memory, just as TMM used memory + Other used memory = device used memory.

F5 recommends that you monitor BIG-IP memory utilization by using the TMM total and used memory together, and Other total and used memory together.

OIDs that output memory size in bytes

The following OID are 64 bit counters and return the memory size in bytes:

This OID is used to get the size of total TMM memory:

snmpget -Of -c public -v2c localhost .1.3.6.1.4.1.3375.2.1.1.2.21.28.0
.iso.org.dod.internet.private.enterprises.f5.bigipTrafficMgmt.bigipSystem.sysGlobals.sysGlobalStats.sysGlobalTmmStat.sysGlobalTmmStatMemoryTotal.0 = Counter64: 11706302464

This OID is used to get the size of used TMM memory:

snmpget -Of -c public -v2c localhost .1.3.6.1.4.1.3375.2.1.1.2.21.29.0
.iso.org.dod.internet.private.enterprises.f5.bigipTrafficMgmt.bigipSystem.sysGlobals.sysGlobalStats.sysGlobalTmmStat.sysGlobalTmmStatMemoryUsed.0 = Counter64: 653726352

This OID is used to get the size of total Other memory:

snmpget -Of -c public -v2c localhost .1.3.6.1.4.1.3375.2.1.1.2.20.44.0
.iso.org.dod.internet.private.enterprises.f5.bigipTrafficMgmt.bigipSystem.sysGlobals.sysGlobalStats.sysGlobalHost.sysGlobalHostOtherMemoryTotal.0 = Counter64: 5122105344

This OID is used to get the size of used Other memory:

snmpget -Of -c public -v2c localhost .1.3.6.1.4.1.3375.2.1.1.2.20.45.0
.iso.org.dod.internet.private.enterprises.f5.bigipTrafficMgmt.bigipSystem.sysGlobals.sysGlobalStats.sysGlobalHost.sysGlobalHostOtherMemoryUsed.0 = Counter64: 3419271168
