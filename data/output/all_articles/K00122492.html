Description

When using on-demand authentication with a hardware based user certificate, the connection is failing.
In some situations you may experience that the user had presented the card, where it failed, and that a subsequent attempt to login actually works, because the on-demand authentication is working from the cached information of the previous attempt.

Environment

  • APM
  • On-demand certificate authentication
  • Hardware based certificates 

Cause

When the request is made by APM for an On-demand certificate, and the user has a certificate that is in embedded hardware, for example a smart card. The SSL handshake is required to complete within 10 seconds (default timeout), so if the user is unable to present the smart card and enter the validation code within this default timeout period of 10 seconds the SSL handshake will fail.

 

Recommended Actions

The default SSL handshake timeout is 10 seconds.
If 10 seconds is not enough time for your users, then you can extend the handshake timeout period on the client SSL profile used by the virtual server that the APM policy is attached to.
  1. Navigate to:
    Local Traffic -> Profiles ->  SSL -> Client
    and click on the appropriate SSL profile.
  2. Expand the SSL profile display to show ADVANCED configuration.
  3. Scroll down to Handshake Timeout .
  4. Check the box on the right side of the screen beside Handshake Timeout.
  5. Increase the default value of 10 seconds to a longer time period more suitable for your users.
  6. Click Update

You may also find it useful to modify the Access Policy in the VPE, so that it displays a message box with a warning, just be the On-demand cert activity, and that it advises the user to be prepared to present their hardware user certificate, and that they only have "n seconds" to present this otherwise authentication will fail, and then they will be required to click continue when they are ready.
