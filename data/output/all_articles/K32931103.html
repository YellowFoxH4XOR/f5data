K32931103: Importing AGC configurations from non-source BIG-IP APM systems may cause BIG-IQ deployments to fail

Topic

You can import Access Guided Configuration (AGC) objects to the BIG-IQ system. If you import AGC configuration objects to the BIG-IQ system from a non-source BIG-IP APM system, subsequent BIG-IQ deployments may fail. 

Description

AGC was introduced in BIG-IP APM point release 13.1.0.8. It provides a simplified user interface in the Configuration utility to configure the BIG-IP APM system for certain use cases. You can use the BIG-IQ system to manage BIG-IP APM systems by importing the APM configuration objects.  

If you import AGC configuration objects to the BIG-IQ system from a non-source BIG-IP APM system, subsequent deployment attempts may fail.  This issue occurs because the BIG-IQ system attempts to remove the AGC objects from the non-source BIG-IP APM system and fails. The AGC objects on the BIG-IP APM systems have Strict Mode enabled by default and cannot be deleted. As a result, the BIG-IQ deployment fails with a message that appears similar to the following example:

Worker http://localhost:8100/cm/access/working-config/apm/profile/access failed validation with status 500.java.lang.illegaStateException: Modify is not allowed because /Common/example.app/example is in use by application service object /Common/example with strict updates enabled.

Recommendations

When importing AGC objects to the BIG-IQ system, you can avoid this issue by considering the following options:

  • Do not import AGC objects from a non-source BIG-IP APM system.
  • Prior to deployment, on BIG-IP APM non-source systems, disable Managed Mode of the AGC app by clicking the app's lock icon in the AGC configuration section. This action will disable Strict Mode in all related AGC objects. Alternatively, you can disable the parent AGC app's Strict Mode attribute or manually disable the object's app service attribute.
