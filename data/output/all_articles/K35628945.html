Issue

Error Message

failed POST "https://<hostname>:8443<path>", exception: "HTTPSConnectionPool(host='<hostname>', port=8443): Max retries exceeded with url: <path> (Caused by SSLError(SSLError(1, u'[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed (_ssl.c:727)'),))"

In this error message, note the following:

  • <hostname> is the fully qualified domain name (FQDN) of the NGINX Controller.
  • <path> is the requested HTTP path of the Controller Agent Receiver API.

For example:

failed POST "https://controller.example.net:8443/1.4/1f4ae1658ce6e151cc743dcbb4e23b84/agent/", exception: "HTTPSConnectionPool(host='controller.example.net', port=8443): Max retries exceeded with url: /1.4/1f4ae1658ce6e151cc743dcbb4e23b84/agent/ (Caused by SSLError(SSLError(1, u'[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed (_ssl.c:727)'),))"

Message Location

You may encounter this message in the following location:

  • The /var/log/nginx-controller/agent.log file on the Controller Agent installed NGINX Plus system.

Description

This message occurs when all of the following conditions are met:

  • The SSL/TLS certificate used to connect to NGINX Controller does not include complete certificate chain.
  • You attempt to install a new Controller Agent on the NGINX Plus instance.

Starting in NGINX Controller 3.2, server certificate verification is enabled by default. If you choose to provide your own SSL/TLS certificate during the NGINX Controller installation process, a complete certificate chain file must be presented. If an intermediate certificate authority (CA) certificate is required to complete the certificate chain, it must be appended to the server certificate file.

Important: To create a complete certificate chain, the intermediate CA certificate needs to be appended to the server certificate; the server certificate must appear before the chained certificates in the combined file.

Note: For more information about certificate chains, refer to SSL certificate chains in the NGINX documentation.

Impact

The newly installed Controller Agent can't connect to the NGINX Controller due to the failed certificate verification. Communication is not initiated between the NGINX Controller and the NGINX Plus instance, including configuration changes and metric collections.

Note: Beginning in NGINX Controller 3.3, the SSL/TLS certificate is verified during the Controller Agent installation process. The installation can't be completed without providing a valid certificate with a complete certificate chain.

Recommended Actions

You can update the existing SSL/TLS certificate using the helper.sh utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Upload the new certificate and key pair to the NGINX Controller system using a file transfer client, such as WinSCP.
  2. Log in to the command line of the NGINX Controller system.
  3. To update the SSL/TLS certificate, use the following command syntax:

    /opt/nginx-controller/helper.sh configtls <cert_file> <key_file>

    For example, to update the certificate and key pair with example.crt and example.key files, enter the following command:

    /opt/nginx-controller/helper.sh configtls example.crt example.key
