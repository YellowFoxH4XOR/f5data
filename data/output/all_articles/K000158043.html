Description

This article provides tips and best practices to ensure your endpoints are set up for optimal security and functionality.

Environment

  • F5® Distributed Cloud

  • Bot Defense

Cause

Protecting incorrect endpoints may cause unexpected behavior or functionality issues.
Common Entry Points to Protect:

  • Login (e.g., /signin)
  • Forgot Password
  • Credit Card Check
  • Account Sign-Up

Recommended Actions

Entry Endpoint

  • This refers to the starting point where users or systems access your web application, such as the homepage or a landing URL (e.g., https://example.com).

What is an Endpoint?

  • An endpoint is a specific URL where a web service or application performs a particular function. For instance, an endpoint could be used to fetch user details or submit a form. e.g: https://api.example.com/users/123 retrieves information for user #123.

To confirm you’ve identified the correct endpoint:

  • Look for query string parameters or body parameters tied to the data entered in the HTML form.
  • Check the HTTP headers for the Referer field. For example, it might point to a URL like https://example.com/signin.
  • Inspect the transaction flow in browser developer tools or a local proxy.

Best Practices for endpoint configuration

  • Decide Your Protection Flow
    • Focus on key flows like login, signup, or payment-related processes.
    • Identify the first POST request following a form submission or key user activity.
  • Use the Right Placement for Bot Defense Script
    • Recommendation: Place the JavaScript After <head> in your HTML. This allows the Bot Defense JavaScript to execute early, avoiding conflicts and loading properly before scripts that render the rest of the page.
  • Set Up Domain and Path Rules
    • Domain Matchers: Specify domains to protect using exact values, suffix values, or regex.
    • Path Matchers: Define the paths to protect using:
      • Exact Path Match: e.g., /login
      • Prefix Match: e.g., /user
      • Regex Match: Bot Defense only supports JS regex and does not support inline modifiers. To create a regex that will work with Distributed Cloud you can use the following web app. Please selecting the Golang syntax: https://regex101.com/
  • Avoid Common Configuration Issues
    • Incorrect Prefix Use: Avoid using prefixes like /* to protect all URI paths. Use the Regex matcher if wildcards are required.

    • Bot Defense does protect GET requests; however, this protection might depend on specific deployment settings and configurations. For detailed steps on identifying and configuring GET request protection, refer to Protect Web Endpoints
