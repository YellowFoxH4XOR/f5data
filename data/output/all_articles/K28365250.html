K28365250: Unable to delete image in rSeries

Type
Support Solution
Published
2022-07-07
Updated
2026-11-14
Applies to
  • rSeries Platforms
  • F5OS
  • F5OS-A: 1.1.X, 1.1.1, 1.1.0
Source
https://my.f5.com/manage/s/article/K28365250

Description

Unused F5OS-A ISO images cannot be removed on an rSeries system. Running system image remove iso <version> from the CLI returns Error: application communication failure. In the GUI, removal requests return HTTP 500, and confd logs no registration found for callpoint host_image_remove/action.
confd --status shows host_image_remove ** not registered, while the imageaction and host-image-state handlers remain registered.

For example:
appliance-1(config)# system image remove iso 1.0.1-14867
Error: application communication failure

Environment

  • F5OS-A

Cause

Bug ID 1116185 

User could also run into this on the bug fixed version, a host_image_remove action may return external_timeout with a RESTCONF response of about 181.9 seconds. The removal callpoint may then appear as not registered. the RCA is unknown, but the workaround solution still applicable.

Recommended Actions

  1. Confirm the image inventory before removing anything:
    show system image
    Do not remove the image that shows USE as true, which is the running image.
  2. Remove unused ISO images from the CLI. Enter configuration mode and run the removal command for each unused version:
    config
    system image remove iso <ISO image file version and build>
    exit
    For example:
    appliance-1(config)# system image remove iso 1.1.1-9159
    If the command returns Error: application communication failure, continue to step 3. If it returns any other error, capture the full output.
  3. Restart the image agent container from an administrative advanced shell (bash) session:
    docker container restart system_image_agent
    Check that the container is running:

    [admin@appliance-1 ~]# docker inspect -f '{{.State.Status}}' system_image_agent

    running

  4. Retry the removal from the GUI or the CLI.
  5. If GUI removal still returns HTTP 500 and the confd log shows no registration found for callpoint host_image_remove/action, check the callpoint registration:
    /confd/bin/confd --status
    Confirm that host_image_remove is registered and does not show not registered. Restarting system_image_agent may restore GUI removal. Capture the confd status output if the state persists.
  6. If the failure persists, collect a new QKView and share the exact error text with F5 Support.
