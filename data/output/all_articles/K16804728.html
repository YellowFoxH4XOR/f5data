Known Issue

Replacing the HTTP payload may trigger the Traffic Management Microkernel (TMM) process to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP virtual server is configured with an iRule.
  • The server HTTP response is not chunked.
  • The HTTP packet does not contain a Content-Length header.
  • The iRule uses the HTTP::payload replace command.
  • The replacement content length is smaller than the original body length.
  • The iRule adds a Content-Length header.

Impact

The BIG-IP system may temporarily fail to process traffic as the TMM process produces a core file and restarts, and systems configured as part of a high availability (HA) group may fail over to a peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system logs a message to the /var/log/tmm file that appears similar to the following example:

    notice ** SIGSEGV **

  • The BIG-IP system generates TMM core files to the /var/core directory with a time stamp that correlates to the traffic interruption, similar to the following example:

    rw-r--r-- root root 310151719 2017-05-09 00:05:01 tmm.bld0.239.249.core.gz
