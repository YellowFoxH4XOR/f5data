Topic

There are significant differences between the 4.x versions of BIG-IP and 3-DNS and the 9.x and 10.x versions of BIG-IP LTM and GTM.

If you are planning to migrate from BIG-IP and 3-DNS 4.x to BIG-IP LTM and BIG-IP GTM 9.x or 10.x, F5 recommends that you complete a clean cut-over migration process. Specifically, F5 does not test or recommend that you complete a migration plan, in which the BIG-IP or 3-DNS 4.x systems and the BIG-IP LTM and BIG-IP GTM 9.x or 10.x infrastructures overlap for a period of time.

However, if your migration plan includes a period of time in which the BIG-IP or 3-DNS 4.x systems and the BIG-IP LTM and BIG-IP GTM 9.x or 10.x infrastructures overlap, you should be aware of the following topics:

  • F5 does not support iQuery communication between BIG-IP or 3-DNS 4.x and BIG-IP LTM or BIG-IP GTM 10.1.0 and later. For more information, refer to K11106: iQuery incompatibility between BIG-IP or 3-DNS 4.x and BIG-IP LTM or GTM 10.1.0 or later.
  • F5 recommends that you run a big3d version that is equal to or greater than the BIG-IP GTM version that is installed in your network (provided that the BIG-IP GTM system is running big3d version 9.0.0 through 10.0.1). For example, if the BIG-IP GTM system is running software version 10.0.0, F5 recommends that the system run big3d version 10.0.0 or 10.0.1.
  • You should not configure the 3-DNS and BIG-IP GTM to monitor the same BIG-IP LTM when a 3-DNS configuration contains no defined factories for the BIG-IP LTM object.

    If you have configured a 3-DNS and BIG-IP GTM to monitor the same BIG-IP LTM resource, and the 3-DNS configuration contains no defined factories for the BIG-IP LTM (meaning the system should not perform probes), the 3-DNS may incorrectly increment the factory count and force the BIG-IP LTM system to perform probes.
