Description

Deployed tenant is not reachable when attempting to reach the management IP of the tenant.

The problem does not follow a particular tenant.

Environment

  • rSeries tenant
  • Management access

Cause

Switch connected to rSeries appliance has port security features that restrict the number of  MAC addresses per port.

On the switch port that the rSeries management port is connected to look for these settings:

switchport port-security maximum <value>

The command switchport port-security maximum <value> sets the maximum number of MAC addresses allowed on a switch port for port security.  When attaching to the rSeries host this needs to be a value larger than the number of anticipated tenants plus 1 (for the rSeries host).

switchport port-security maximum <value> vlan access

The command switchport port-security maximum vlan access command is used to limit the number of MAC addresses that can be learned on an access port (a port configured to be in access mode and associated with a single VLAN).  When attaching to the rSeries host this needs to be a value larger than the number of anticipated tenants plus 1 (for the rSeries host), as each tenant as well as the rSeries host will attach to the management VLAN with a separate and unique MAC address.

Recommended Actions

Update the switch configuration to allow additional MAC addresses on the port.

Note: Each rSeries tenant will have a different MAC address.

Additional Information

When this issue happens, a capture taken on the rSeries mgmt interface will show ARP requests are leaving the system for all tenants but no ARP response is returning from the switch , indicating the problem is external.

tcpdump -nni mgmt -s0 arp or icmp -w /var/tmp/${SYS_CONFIG_HOSTNAME%%.*}_mgmt.pcap

Additionally, it will be possible to virtctl console to the tenant, and the tenant will appear functional, but will be unable to ping its default gateway.
