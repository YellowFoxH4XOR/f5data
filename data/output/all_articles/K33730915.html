Topic

This article provides a description of the anacron utility behavior on BIG-IP systems.

Note: In version 12.0.0 and later, the BIG-IP system uses the anacron utility to manage certain scheduled jobs. For more information, refer to K70264550: The BIG-IP system uses anacron to manage scheduled jobs for daily, weekly, and monthly tasks.

Description

The BIG-IP system uses the anacron utility to schedule periodically executed tasks defined in the /etc/anacrontab configuration file. The anacron utility can schedule tasks for the system to execute, based on a specified number of days or at daily, weekly, monthly, or yearly intervals.

Additionally, the BIG-IP system uses the cron utility to manage tasks that occur at intervals of less than one day. Beginning in BIG-IP 12.0.0, jobs are no longer configured in the /etc/crontab configuration file. Instead, the BIG-IP system uses the /etc/cron.d/0hourly file to configure hourly tasks.

Unlike cron, which runs as a system service, anacron by default runs only when the system starts and then exits after executing its tasks. The BIG-IP system uses a cron task configured in the /etc/cron.hourly/0anacron file to ensure that the anacron utility runs daily without requiring a system restart.

On BIG-IP systems, anacron and cron use the run-parts utility, which executes all files within a directory. This configuration makes the anacron and cron configuration files smaller and easier to maintain because, instead of maintaining individual configuration items in the /etc/crontab file, the system separates scheduled tasks into the following four directories, relatively specifying the hourly, daily, weekly, and monthly intervals. The run-parts utility executes all scripts in those directories at the scheduled intervals:

  • /etc/cron.hourly
  • /etc/cron.daily
  • /etc/cron.weekly
  • /etc/cron.monthly

The BIG-IP system /etc/anacrontab file appears similar to the following example:

# /etc/anacrontab: configuration file for anacron

# See anacron(8) and anacrontab(5) for details.

SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
# the maximal random delay added to the base delay of the jobs
RANDOM_DELAY=45
# the jobs will be started during the following hours only
START_HOURS_RANGE=3-22

#period in days   delay in minutes   job-identifier   command
1       5       cron.daily              nice run-parts /etc/cron.daily
7       25      cron.weekly             nice run-parts /etc/cron.weekly
@monthly 45     cron.monthly            nice run-parts /etc/cron.monthly

In the previous example, the configuration file has three directives configured using the run-parts utility, which specify the daily, weekly, and monthly directories. Additionally, the nice utility lowers the priority of the scheduled tasks to decrease performance impact on the BIG-IP system.

The anacron utility uses the following values in the /etc/anacrontab file to determine when scheduled tasks run:

Configuration objectDescription
RANDOM_DELAYSpecified in minutes, when set, this variable adds a random number of minutes to the startup delay of all tasks, between 0 and the delay value you set. For example if you set the value at 45, the variable adds a random number between 0 and 45 minutes to the configured delay time already set for each individual task.
START_HOURS_RANGESpecifies the valid ranges of hours on a 24 hour clock in which to start jobs. For example, if you specify 3-22, jobs can start between the hours of 3am and 10pm.
period in daysSpecifies a number of days or one of the following intervals: @daily, @weekly, @monthly, @yearly, or @annually. @annually and @yearly are the same.
delay in minutesSpecifies the number of minutes that the anacron utility waits before executing a specified task after starting.

When the anacron utility starts, it evaluates date-stamped files located in the /var/spool/anacron directory to determine when it should execute a specific task. After it completes the task, it evaluates the next task in the list. After it evaluates all tasks, the anacron utility exits.

The /etc/cron.d/0hourly configuration file that cron uses appears similar to the following example:

SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
HOME=/
01 * * * * root run-parts /etc/cron.hourly

In this example, there is one directive configured using the run-parts utility, specifying the /etc/cron.hourly directory.

The cron utility uses the following schedule syntax in the /etc/cron.d/0hourly configuration file:

 

* * * * * command to be executed
- - - - -
| | | | |
| | | | +----- day of week (0 - 6) (Sunday=0)
| | | +------- month (1 - 12)
| | +--------- day of month (1 - 31)
| +----------- hour (0 - 23)
+------------- min (0 - 59)

Using the previous examples of anacron and cron configuration, the BIG-IP system executes scripts in each of the four directories at the following intervals:

DirectoryUtilityScheduleRun time
/etc/cron.hourlycron01 * * * *First minute of every hour, every day. For example, 01:01.
/etc/cron.dailyanacron1, 5 (plus 0 - 45 minute delay)Once a day, between 5 and 50 minutes after anacron runs.
/etc/cron.weeklyanacron7, 25 (plus 0 - 45 minute delay)Once a week, between 25 and 70 minutes after the anacron utility runs.
/etc/cron.monthlyanacron@monthly, 45 (plus 0 - 45 minute delay)Once a month, between 45 and 90 minutes after the anacron utility runs.

The schedule variance ensures that the BIG-IP system doesn't execute the hourly, daily, weekly, and monthly tasks at the same time. To see a list of all the scheduled tasks on the BIG-IP system, type the following command:

ls -l /etc/cron.*

For more information about anacron and cron configuration syntaxes, refer to the anacrontab man page by typing man 5 anacrontab or refer to the crontab man page by typing man 5 crontab.
