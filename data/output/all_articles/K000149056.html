K000149056: Advanced WAF Features That Affect Transactions in Transparent Mode

Type
Support Solution
Published
2024-12-19
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP ASM
Source

Description

You observe that ASM or Adv. WAF security features modify or impact traffic while in Transparent mode.

Transparent mode is a non-blocking mode that will not block traffic based on violations. The system logs security violations without enforcing blocking actions in this mode. Security features are in place with Transparent Mode and can have various effects on traffic including adding feature cookies, inserting JavaScript, dropping transactions, resetting connections, and more. It is important to note that Transparent Mode does not override system-level behaviors or conditions that may lead to dropped or reset connections.

 

Environment

Advanced WAF / ASM

Cause

There are several ASM features which introduce JavaScript injection, including:

 Bot Defense (JS challenges, DeviceID, Browser verification)
 CSRF Protection
 Brute Force Protection (DeviceID and Client Side Integrity Defense mitigations)
 Client Fingerprinting with Session Tracking (particularly the 'Session Hijacking by Device ID Tracking' option), described in K19556739: Overview of BIG-IP ASM client fingerprinting
 AJAX Response Page

 

There are scenarios where traffic may still be dropped or reset irrespective of the security policy's enforcement mode. These behaviors are generally tied to system-level constraints or unexpected conditions during request/response processing. 

This includes the following situations: 

  1. The system may terminate connections when a transaction exceeds the configured thresholds for slow transaction protections. This is controlled by system variables rather than policy violations per K14199: Logs indicate BIG-IP Advanced WAF has detected and prevented a Slow HTTP transaction DDoS attack.
  2. Resource limitations like high concurrent long requests or insufficient memory (e.g. UMU or XML pool exhaustion)
  3. Situations like incomplete server responses or internal errors during processing can trigger connection resets. These often result in logs indicating a reset cause such as "ASM requested abort (open error)"

The transparent mode governs blocking decisions based on violations but does not prevent traffic drops/resets caused by underlying system conditions.

Recommended Actions

None, this is informational only

Additional Information

This is not a comprehensive list of every scenario in which ASM can drop, reset, or modify traffic. When resets occur, they often include a generic reset cause (e.g., "ASM requested abort"). Identifying the root cause in such cases typically requires further investigation of the specific traffic or system logs.
