Topic

You should consider using this procedure under the following conditions:

  • You are unable to query BIG-IQ Centralized Management for statistics data.
  • One or more logging services, such as audit logger, is not running.
  • You are unable to add or remove a data collection device from BIG-IQ Centralized Management.
  • The system fails to get a list of indices.

Description

When you experience data collection issues with BIG-IQ Centralized Management, it is helpful to remove the data collection device (DCD) information and start with a clean re-association.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have an account with administrative privileges on BIG-IQ Centralized Management.
  • You have access Advanced Shell (bash) command-line access.

Procedures

Unpair a BIG-IQ HA pair, then reset the local data collection cluster configuration to factory defaults and delete the Elasticsearch data. Then, reset the data collection cluster configuration on the HA peer and each of the DCDs before attempting to re-discover and re-configure them. To do so, perform the following procedure:

Note: Resetting the data collection cluster configuration does not affect the external storage configuration.

Impact of procedure: The BIG-IQ Centralized Management data collection and search services become temporarily unavailable during this process. Unpairing the HA pair temporarily breaks the HA configuration between the instances.  During the time it takes to reset the data cluster association, both the primary and secondary BIG-IQ Centralized Management systems will operate as a standalone device.

  1. Log in to the Advanced Shell (bash) as an administrator on the primary BIG-IQ in the pair
  2. Unpair the BIG-IQ HA pair by entering the following command syntax:

    ha_reset -f <discovery_address>

    Note: <discovery address> is the local IP address used to create HA between BIG-IQ systems

  3. Reset the data collection cluster configuration by entering the following command:

    reset-data-collection-cluster

    You may append the command with the flags listed in the following table, as needed.

    FlagDescription
    -hDisplays the help instructions for reset-data-collection-cluster
    -eskeeps Elasticsearch data (deleted by default)
    This option was deprecated in Big-IQ V8.0, Using it will not cause an error, although all DCD data will be removed
    -lRemoves Elasticsearch logs

    Output appears similar to the following:

    Note: The responses within braces ({ })may or may not appear, depending on the flags you used in the command.

    Stopping the restjavad and appiq services
    Stopping the elasticsearch service
    Deleting data collection cluster configuration
    Removing the platform logging group
    Removing module specific logging groups
    Removing the statistics configuration
    Deleting the elasticsearch data
    Deleting /var/config/rest/elasticsearch/data/a5232f01-76c6-4180-897f-ccdc12e9edaf
    Deleting /var/config/rest/elasticsearch/data/f1cf4496-c2d3-47ef-92a6-3ddcbefc1dee
    {Deleting the elasticsearch logs}
    Starting the elasticsearch service
    Starting the restjavad service

  4. Repeat step 1 through 3 on the other member of the BIG-IQ HA pair.
  5. Log in to bash as an administrator on one of the DCDs.
  6. Reset the data collection cluster configuration on the DCD by entering the following command:

    reset-data-collection-cluster

  7. Repeat steps 5 and 6 on each of the remaining DCDs.
  8. Log in to the user interface of the primary member of the BIG-IQ HA pair. A message similar to the following appears on the Status section on the BIG-IQ Data Collection Cluster Summary page in the BIG-IQ user interface:

    There are no data collection devices configured. Click here to configure. 
    Please note that it may take several minutes for newly added data collection devices to become ready.

  9. Re-discover the DCDs from the BIG-IQ user interface by selecting the Click here link displayed in message or by going to System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Devices and select Add.

    For detailed steps, refer to the Planning and Implementing a Centralized Management Deployment chapter of the Planning and Implementing an F5 BIG-IQ Centralized Management Deployment manual.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  10. Pair the BIG-IP Centralized Management systems again by going to System > BIG-IQ HA and selecting Add Secondary
  11. If necessary re-enable statistics collection on the managed BIG-IP devices by going to Devices > BIG-IP DEVICES and selecting Disabled under the Stats Collection Status column for each device.
  12. Check the Elasticsearch cluster health by going to System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Cluster > SUMMARY > Status.
