K000139089: Forwarding to wrong VIP

Type
Support Solution
Published
2024-03-28
Updated
2024-10-10
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.2
Source
https://my.f5.com/manage/s/article/K000139089

Description

F5 is processing traffic on the wrong Virtual Server.

Traffic that is meant for Virtual Server 1 is being processed by the wildcard forwarder Virtual Server (destination 0.0.0.0:0)

 

Environment

  • A wildcard Virtual Server listening on 0.0.0.0:0 and on any VLAN.
  • Multiple VLANs within the F5.
  • Virtual Server that is supposed to handle the specific traffic has VLANs enabled and a specific VLAN marked.
  • Some or all endpoints attempting to connect to the Virtual Server instead connect to the wildcard VS.

Cause

VLANs configured on Virtual Servers will restrict those servers to only accept traffic from sources within that VLAN.

Recommended Actions

Ensure the endpoints sending traffic to the Virtual Server are within the VLAN configured on that server.

OR

Turn off "Enable VLANs" on the Virtual Servers.

OR

Change the VLANs on the Virtual Servers to include the VLAN the sending endpoints reside in.

Additional Information

May also need to remove connections from the connection table after modifying the Virtual Server.

For example, If your connections are destined for the IP Address 10.128.20.188, then you can show these connections as follows:

# tmsh show sys connection cs-server-addr 10.128.20.188

Sys::Connections

10.128.20.18:12345 10.128.20.188:514 10.128.10.148:12345 10.128.10.204:514 udp 23 (tmm: 0) none none

Total records returned: 1

This connection can be delete with:

# tmsh delete sys connection cs-server-addr 10.128.20.188
