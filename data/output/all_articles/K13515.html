Topic

Access Control Lists are not supported for connections between Virtual Private Network (VPN) network access clients. As long as IP addresses assigned to clients are not in an excluded address space, a client can send traffic to another client that is connected to a network access tunnel. The same is true for server to client traffic, where a server could initiate a connection to a client.

Connections originating from a network access tunnel apply an Access Control List to an internal forwarding virtual server, as long as no other virtual server matches the destination address and port more specifically. If there is a more specific virtual server, the traffic is routed through that virtual server and the Access Control List check is bypassed. For each tunnel, there is an internal forwarding virtual server that uses the IP address assigned to the client. This virtual server always catches traffic to the client. This virtual is created at the time the network access tunnel connects and is not accessible by the admin, nor can an Access Control List be applied to the virtual server.

F5 Product Development is considering a Request for Enhancement (RFE) to add support for applying Access Control Lists on network access tunnels. F5 Product Development is tracking this RFE as ID 366149.

Workaround

You can work around this issue by creating a split tunnel, and excluding the IP lease pool addresses. To do so, perform the following procedure:

Impact of workaround: This workaround blocks only IP addresses. You cannot block ports or protocols with this method.

  1. Log in to the Configuration utility.
  2. Click Access Policy.
  3. Click Network Access.
  4. Click the name of the network access resource you want to edit.
  5. Click the Network Settings tab.
  6. Select the Use split tunneling for traffic option.
  7. Enter 0.0.0.0 in the IPV4 LAN Address Space field.
  8. Enter 128.0.0.0 in the Mask field.
  9. Click Add.
  10. Enter 128.0.0.0 in the IPV4 LAN Address Space field.
  11. Enter 128.0.0.0 in the Mask field.
  12. Click Add.
  13. Select Advanced from the Client Settings drop-down menu.
  14. Enter the lease pool IP address range in the IPV4 Exclude Address Space section, IP Address field.
  15. Enter the appropriate subnet mask for the lease pool IP address range in the IPV4 Exclude Address Space section, Mask field.
  16. Click Add.
  17. Click Update.
