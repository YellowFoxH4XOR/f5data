Description

When trying to power cycle a velos tenant to rule out any other issues, it doesn't appear to fully reboot.

  • The reboot is done by issuing a reboot command from tenant.
  • Though the tenant appears to go down, the tenant actually doesn't.
  • There's virtually no ping loss when there's a constant ping setup to the management IP.

Environment

  • F5OS-C or Velos chassis with multiple blades.
  • BIG-IP v17.x tenant that spans across multiple blades.

Cause

When we issue a reboot command from within tenant, it only reboots the active blade. While the active blade goes down for a reboot, other blade takes over as active immediately and the tenant doesn't go down for a reboot as expected.

Recommended Actions

This behaviour is expected because in a tenant that runs across multiple blades. There are two ways to do this. First method is recommended, as it restarts more services (including some services at the F5OS level). But if that's not feasible, try the second method with correct command.

Method one (Recommended):

  1. From the F5OS partition, set the tenant to provisioned state.
  2. Wait for few minutes
  3. Put the tenant back to deployed.

For steps refer to K21121803

Method two:

  1. From within tenant use the bash command below:
    # clsh reboot
