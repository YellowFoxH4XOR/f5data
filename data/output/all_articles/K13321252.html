Topic

You should consider using this procedure under the following condition:

  • You want to enable BIG-IQ 6.1.0 through 7.0.0 to support a different instance type of BIG-IP Virtual Edition (VE) on the Amazon AWS or Microsoft Azure cloud environment.

Description

The BIG-IQ system supports multiple public cloud providers, and occasionally you may be required to customize support of a new BIG-IP VE image version or a different instance type.

For BIG-IQ 7.1.0 or later, refer to K97233143: Adding a new instance type for the AWS or Azure cloud environment on the BIG-IQ system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a valid AWS or Azure cloud environment configuration on the target BIG-IQ system.
  • You are using the BIG-IQ system to deploy a new BIG-IP VE device to the AWS or Azure cloud environment.
  • You have Advanced Shell (bash) access to the BIG-IQ system with administrator credentials.

Procedures

Before adding the new instance types to the restjavad properties file, you must validate that the current copy of the file has the existing configuration stanzas for customizing the AWS or Azure environment on the instance types.

Validating the existing configuration stanza

For BIG-IQ 6.1.0 through 7.0.0, the system has a list of pre-populated instance types for AWS and Azure for BIG-IP VE. You can view them using the following commands from bash on the BIG-IQ system:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

If you are unable to view the list of supported instance types for AWS or Azure in the bash commands, you may have an old version of the restjavad.properties.json file, possibly due to an upgrade of the BIG-IQ system from 6.0.0 to 7.0.x. For more information, refer to Bug ID 820949. To obtain a newer version of the restjavad.properties.json file, refer to the Workaround section in K02972920: The restjavad.properties.json file is not updated with latest version after upgrading the BIG-IQ system.

The restjavad.properties.json file with the AWS and Azure configurations are available from the ISO file of BIG-IQ 7.0.0 or 7.0.0.1. You must have the file that contains the required configuration stanza before performing the next procedure.

Adding a new AWS instance type

You can customize the restjavad properties file to support a new instance type for the AWS BIG-IP VE on the BIG-IQ system. To modify the file, perform the following procedure:

Impact of procedure: You must restart the restjavad process after you modify the property file as it will cause interruptions to BIG-IQ services. F5 recommends performing this procedure only during a scheduled maintenance period.

  1. Log in to bash on the BIG-IQ system.
  2. Save a back-up copy of the restjavad property file by entering the following command:

    cp -a /var/config/rest/config/restjavad.properties.json /shared/tmp/restjavad.properties.json.bkp1_K13321252

  3. Use a file editor to edit the /var/config/rest/config/restjavad.properties.json property file.
  4. Look for the aws section, locate the list of supported instance types, and the instanceTypes line:

    For example:

    "aws" :
{
    "images" :
    {
    ...
    }
    "instanceTypes" : {
        "ltm" : [
    	    "t2.medium",
             ...
            "c5.9xlarge",
            "cc2.8xlarge"
        ],
        "waf": [
            "t2.medium",
             ...
            "c5.9xlarge",
            "cc2.8xlarge"
        ]
    }
}
  5. To add a new AWS instance type called c5n.4xlarge for BIG-IP LTM, add the new instance type in its own line directly after the ltm line:

    Important: You must include the trailing comma ( , ). Each instance type in the AWS configuration has a trailing comma, except for the last entry, which ends with a closing bracket ( ] ).

    For example:

    "aws" :
{
    "images" : 
    {
     ... 
    }
    "instanceTypes" : {
        "ltm" : [
            "c5n.4xlarge",
    	    "t2.medium",
             ...
            "c5.9xlarge",
            "cc2.8xlarge"
        ],
        "waf": [
            "t2.medium",
             ...
            "c5.9xlarge",
            "cc2.8xlarge"
        ]
    }
}
  6. After you save the changes, you must refresh the system. To restart the restjavad service, enter the following command:

    tmsh restart /sys service restjavad

    Once the BIG-IQ system resumes service, when you create a new cloud environment for AWS and select the BIG-IP Image Name drop-down list, you should see your newly added instance type for AWS BIG-IP VE.

Adding a new Azure instance type

You can customize the restjavad properties file to support a new instance type for Azure BIG-IP VE on the BIG-IQ system. To modify the file, perform the following procedure:

Impact of procedure: You must restart the restjavad process after you modify the property file as it will cause interruptions on the BIG-IQ services. F5 recommends performing this procedure only during a scheduled maintenance period.

  1. Log in to bash on the BIG-IQ system.
  2. Save a back-up copy of the restjavad property file by entering the following command:

    cp -a /var/config/rest/config/restjavad.properties.json /shared/tmp/restjavad.properties.json.bkp2_K13321252

  3. Use a file editor to edit the /var/config/rest/config/restjavad.properties.json property file.
  4. Look for the azure section, locate the list of supported instance types, and the instanceTypes line:

    For example:

    "azure" :
{
    "ssgMonitoring" :
     ...
    "instanceTypes" : {
        "ltm" : [
            "Standard_A4",
            "Standard_A6",
            "Standard_A7",
            "Standard_D4",
            "Standard_DS12_v2",
            "Standard_DS13_v2",
            "Standard_DS3",
            "Standard_DS3_v2",
            "Standard_DS4_v2",
            "Standard_DS5_v2"
        ],
        "waf" : [
            "Standard_A7",
            "Standard_DS13_v2",
            "Standard_DS4_v2",
            "Standard_DS5_v2"
        ]
    },
    "images" :
    {
     ...
    }
}
  5. To add a new Azure instance type called Standard_DS11_v2 for BIG-IP LTM, add the new instance type in its own line directly after the ltm line:

    Important: You must include the trailing comma ( , ). Each instance type in the Azure configuration has a trailing comma, except for the last entry, which ends with a closing bracket ( ] ).

    For example:

    "azure" :
{
    "ssgMonitoring" :
     ...
    "instanceTypes" : {
        "ltm" : [
            "Standard_DS11_v2",
            "Standard_A4",
            "Standard_A6",
            "Standard_A7",
            "Standard_D4",
            "Standard_DS12_v2",
            "Standard_DS13_v2",
            "Standard_DS3",
            "Standard_DS3_v2",
            "Standard_DS4_v2",
            "Standard_DS5_v2"
        ],
        "waf" : [
            "Standard_A7",
            "Standard_DS13_v2",
            "Standard_DS4_v2",
            "Standard_DS5_v2"
        ]
    },
    "images" :
    {
     ...
    }
}
  6. After you save the changes, you must refresh the system. To restart the restjavad service, enter the following command:

    tmsh restart /sys service restjavad

    Once the BIG-IQ system resumes service, when you create a new cloud environment for Azure and select the BIG-IP Image Name drop-down list, you should see your newly added instance type for Azure BIG-IP VE.
