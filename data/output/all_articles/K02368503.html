Description

This article outlines generic steps for resetting completely corrupted sslo installs, regardless of the cause of the corruption. The reset methods given below will delete the entire LTM config, as well as the SSLO config, after which the admin will need to manually re-create the config from scratch (or else load a previously saved UCS from when the box or HA pair were known to be in a perfect state with no corruption). Thus, the procedure below only needs to be used as a last resort if ordinary deletion of the SSLO topology/topologies and IappsLX objects did not recover the install.
 

Environment

SSLO 6.x and 7.x
 

Cause

The most common cause of corruption/deployment issues on SSLO boxes is due to a mismatch between the restdb config and the ltm objects present on the box.
Note: Even if an admin opts to move to a newer TMM version without enabling config carry-forward, that setting only results in the BIG-IP not moving/carrying over the MCP objects. The REST database is still carried forward to the new partition, therefore the REST DB must be cleaned either by an SSLO uninstall, or by a 'clear-rest-storage -d' before the software build is installed into the new partition.

Recommended Actions

To save time in most situations, you can try the "quick reset" steps below, and if the corruption persists, then you can try the "full reset" set below that instead.

Quick reset steps

  1. 1. Break HA pair and reset device trust. Ensure both boxes are showing status "Standalone".
  2. 2. On each box, type "clear-rest-storage -d" and type "yes" when prompted to reset all config to defaults. The management IP/mgmt route will be retained.
  3. 3. Rejoin HA pair, while making sure not to even accidentally navigate to the SSLO menu page in admin GUI before the HA pair is set up (as that would save some SSLO configuration in RESTDB, and the HA pair needs to be set up before that happens).
  4. 4. Confirm issue is gone by browsing to SSLO menu on active box and setting up SSLO.

Full reset steps

  1. 1. Break HA pair and reset device trust. Ensure both boxes are showing status "Standalone".
  2. 2. Go to SSLO main page on each box and click the "trash" button to clean config. Confirm that it reports config clean worked fine.
  3. 3. Uninstall the SSLO RPM from both the boxes.
  4. 4. Verify that all SSLO-related MCP objects were deleted, using the CLI command "tmsh list sys application service" (or check the iAppsLX page in admin GUI, if it's enabled). If any SSLO-related MCP objects remain for some reason even after the SSLO uninstall, manually delete them. The SSLO uninstall should generally delete all SSLO-related MCP objects automatically.
  5. 5. Issue "clear-rest-storage -d" on both boxes. type 'yes' when prompted to reset all config to defaults. The management IP/mgmt route will be retained.
  6. 6. Install new software build (eg. v15.1.0.2) into a new partition. Make sure not to even navigate to the SSLO menu page in admin GUI (as that would save some SSLO configuration in RESTDB, and the HA pair needs to be set up before that happens).
  7. 7. Boot up into new partition.
  8. 8. Rejoin HA.
  9. 9. On the active box, navigate to the SSLO menu page to automatically trigger the SSLO config process on both boxes.
  10. 10. Configure and deploy SSLO on the active box (it should auto-propagate to standby box via gossip).
