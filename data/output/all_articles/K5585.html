K5585: Conditions that trigger failover in a redundant pair

Topic

Failover from the active FirePass controller to the standby may occur in a redundant pair under the following two conditions:

  • The standby unit does not receive the heartbeat signal
  • External IP address monitoring fails

The standby unit does not receive the heartbeat signal

The active and standby controllers communicate with each other using a heartbeat. The heartbeat is a signal sent at 100-millisecond intervals that notifies the standby node that the active node is running. If the standby node does not receive a heartbeat within three seconds of the expected arrival time, the standby node considers its peer inactive, assumes its virtual IP address, and becomes the active member of the pair.

Note: For more information about FirePass redundant pairs, refer to the FirePass Controller Administrator Guide.

External IP address monitoring fails

When External IP Address Monitoring is configured, the active controller pings the monitored IP address(es) once per second. For FirePass versions 6.0.0 and earlier, if a response is not received by one or more of the IP addresses for 60 seconds, the active controller switches to standby mode. For FirePass version 6.0.1 and later, if a response is not received by one or more of the IP addresses for 30 seconds (three attempts with an attempt once every 10 seconds), the active controller switches to standby mode. For all versions of FirePass software, if neither FirePass controller can reach all of the configured IP addresses, both controllers switch to standby mode.
