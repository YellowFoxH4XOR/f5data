K000134586: Upgrade from 15.1.8, 15.1.8.1, 15.1.8.2, or 15.1.9 to 16.1.x or 17.0.x fails, and leaves device INOPERATIVE

Type
Support Solution
Published
2023-06-13
Updated
2023-08-10
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8, 15.1.9
Source
https://my.f5.com/manage/s/article/K000134586
Description
  • Upgrade from BIG-IP 15.1.8, 15.1.8.1, 15.1.8.2, or 15.1.9 to 16.1.x or 17.0.x fails, and leaves device INOPERATIVE. Upgrades to 17.1.x are not affected.
  • The device is left in an INOPERATIVE state.
  • Configuration fails to load.
Environment
  • Attempting to upgrade from BIG-IP 15.1.8, 15.1.8.1, 15.1.8.2, or 15.1.9 to 16.1.x or 17.0.x.
Cause

This issue is caused by bug ID 1161913 .

Recommended Actions

Use the workaround below.

Workaround
  1. On the currently running version, please log in to CLI and navigate to the /var/tmp directory:
    cd /var/tmp
  2. Create a script file (for example script.sh) and copy the code below to it. You can use nano or vi editor. Please avoid using external text editors (Windows).
    #!/bin/sh
    ### BEGIN COMMANDS
    (shopt -s nullglob; sed -E -i.workaround.bak -e '/dag-adjustment /d' /config/bigip_base.conf /config/partitions/*/bigip_base.conf)
    (shopt -s nullglob; sed -E -i -e '/^KEYWORD dag-adjustment/d' -e '/^KEYWORD nti/d' /var/libdata/tmsh/syntax/15.1.{8,9}*/auto_schema_data_net_cli.dat)

    for dir in /var/libdata/tmsh/syntax/15.1.{8,9}*; do
        [ -d "$dir" ] || continue
        mv "$dir"/auto_schema_data_security_cli.dat{,.workaround.bak}
        awk '
            /^<REF_CMD fw-protected-zone / { refcmd=1; depth=1; next }
            /^<CMD fw-protected-zone/ { cmd=1; depth=1; next }
            /^<ASSOCIATION.*fw-protected-zone/ { depth=depth+1; next }
            /^>/ {
                if (refcmd || cmd) {
                    if (!--depth) {
                        refcmd = 0;
                        cmd = 0;
                    }
                    next;
                }
            }
            /.?/ {
                if (refcmd || cmd) next
                print
            }' < "$dir"/auto_schema_data_security_cli.dat.workaround.bak > "$dir"/auto_schema_data_security_cli.dat
        rm "$dir"/auto_schema_data_security_cli.dat.workaround.bak
    done
    ### END COMMANDS
  3. Add execute permissions to this script file:
    chmod 744 script.sh
  4. Boot to upgraded (inoperative) volume and navigate to /var/tmp:
    cd /var/tmp
  5. Execute script using command:
    ./script.sh
    If it executes properly, move to the next step.
  6. Execute command:
    tmsh load sys config
    If it executes properly, move to the next step.
  7. Execute the command:
    tmsh save sys config
