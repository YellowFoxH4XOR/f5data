Topic

You should consider using this procedure under the following condition:

  • You want to deploy a BIG-IP virtual server to load-balanced Linux very secure FTP (VSFTP) servers for FTPS passive request.

Description

You can configure your BIG-IP LTM and/or BIG-IP AFM system to load balance active or passive FTPS requests to a pool of VSFTP servers.

This article details the BIG-IP configuration steps to deploy FTPS for VSFTP servers, with a subsection about configuring the BIG-IP AFM firewall in conjunction with the load-balanced configuration.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Administrative access to the VSFTP servers.
  • Administrative access to the BIG-IP Configuration utility.

Procedures

  • Configuring the required vsftpd.conf variables
  • Configuring the BIG-IP system to load balance the FTPS request
  • Configuring the BIG-IP AFM firewall to permit the FTPS request

Configuring the required vsftpd.conf variables

To configure the VSFTP server(s) to process passive SSL/TLS request sent by the BIG-IP virtual server the following configuration values must be added or modified in the server /etc/vsftpd.conf file.

Note: The following variables are not inclusive of all the variable required to configure the VSFTP server and assumes that the minimum installation vsftpd.conf exists on the server.

Impact of procedure: Performing the following procedure could not have a negative impact on your VSFTP system when variables are incorrectly stated or the assigned value does not match an expected value. Attempting to configure the VSFTP server to process standard FTP and FTPS request can be problematic.

Note: For more information about the vsftpd.conf file and available variables refer to: Man page of SFTPD.conf.

Configuring FTPS passive

The following vsftp.conf file variables are specific to configuring the VSFTP server for passive connection request.

  • pasv_enable=YES
  • pasv_address=<virtual server ip address>
  • pasv_address_resolve=YES

Note: Set the variable pasv_address to the BIG-IP virtual server IP address or resolvable FQDN. When using the FQDN set the variable pasv_address_resolve to YES.

Important: The VSFTP server must be able to resolve the FQDN to the same IP address used by the BIG-IP virtual server.

For example:

pasv_address=172.16.1.65

or

pasv_address=ftps.example.com
pasv_address_resolve=YES

When using a FQDN, set the following in the vsftpd.conf file as well, pasv_address_resolve=YES.

Important: When using a FQDN for the pasv_address variable, the FTPS server must resolve the FQDN name to the virtual server address. Additionally for SSL security the FQDN of the certificate must match the FQDN used to access FTPS services. 

Limiting the data ports used by the VSFTP server

The following vsftp.conf file variables are specific to configuring the available ports used for VSFTP for passive connection request.

  • pasv_min_port=<starting port allowed>
  • pasv_max_port=<highest port allowed>

For example, the following variable settings will allow the ports 10000 (<starting port allowed>) through 10100 (<highest port allowed>) for data connections.

  • accessing tpasv_max_port=10100
  • pasv_min_port=10000

Configuring the VSFTP server to use SSL certificate and key for encrypted connections

The following vsftp.conf file variables are specific to configuring the VSFTP server to use SSL encryption.

  • rsa_cert_file=<path and file name of your public SSL certificate>
  • rsa_private_key_file=<path and file name of your public SSL key>

For example, the following will use the same certificate and key used for SSL by the NGINX web server:

  • rsa_cert_file=/etc/nginx/ssl/server.crt
  • rsa_private_key_file=/etc/nginx/ssl/server.key

Limiting the types of encryption and ciphers allowed when accessing the VSFTP server

The following vsftp.conf file variables are specific to configuring the VSFTP server permitted encryption ciphers.

  • ssl_tlsv1=YES
  • ssl_sslv2=NO
  • ssl_sslv3=NO

Note: Setting YES to ssl_tlsv1, ssl_sslv2 or ssl_sslv3 will enable clients to use the cipher type when connecting to the VSFTP server.

  • ssl_ciphers=HIGH

Note: You can use the ssl_ciphers option to select which SSL ciphers vsftpd will allow for encrypted SSL connections. HIGH specifies key lengths larger than 128 bits, and some cipher suites with 128-bit keys.

Allowing only SSL connections

The following vsftp.conf file variable configured the VSFTP server to only accept encrypted requests. Using the variable require_ssl_reuse may have limitations depending on your deployment environment.

  • implicit_ssl=YES

    Note: When implicit_ssl is configured with YES, an SSL handshake is expected on all connections.

  • require_ssl_reuse=YES

    Important: When require_ssl_reuse is configured with YES, all SSL data connections are required to exhibit SSL session reuse. Some FTPS clients are not compatible with this feature.

  • listen_port=990

    Note: When the listen_port variable is not configured, connections will be processed on port 21; the expected port for FTPS is 990.

  • force_local_data_ssl=NO

    Note: When force_local_data_ssl is configured with YES, all non-anonymous logins are forced to use a secure SSL connection to send and receive data on data connections.

  • force_local_logins_ssl=NO

    Note: When force_local_logins_ssl  is configured with YES, all non-anonymous logins are forced to use a secure SSL connection to send the password.

Example simplified vsftp.conf file

The following example is a simplified vsftpd.conf file for a VSFTP server that is restricted to processing FTPS request.

Note: In the example, the IP address 172.16.1.65 is the virtual server IP address. All variables preceded with the number sign ( # ) are unused/unmodified variables or comments.

#  base configuration
pam_service_name=vsftpd
listen=YES
listen_ipv6=NO
max_per_ip=25
anonymous_enable=NO
idle_session_timeout=300
data_connection_timeout=15
async_abor_enable=NO
local_enable=YES
write_enable=YES
dirmessage_enable=YES
delete_failed_uploads=YES
use_localtime=YES
xferlog_enable=NO
xferlog_file=/var/log/vsftpd.log
ftpd_banner=Welcome to VSFTP FTPS service.
ls_recurse_enable=YES
secure_chroot_dir=/var/run/vsftpd/empty

#  passive configuration
pasv_enable=YES
pasv_address=172.16.1.65
#pasv_address_resolve: set to YES when pasv_address is a fqdn
#example pasv_address=ftps.example.com
#pasv_addr_resolve=YES
pasv_max_port=10100
pasv_min_port=10000

#  ssl configuration
rsa_cert_file=/etc/nginx/ssl/server.crt
rsa_private_key_file=/etc/nginx/ssl/server.key
ssl_enable=YES
force_local_data_ssl=NO
force_local_logins_ssl=NO
ssl_request_cert=NO
ssl_tlsv1=YES
ssl_sslv2=NO
ssl_sslv3=NO
listen_port=990
implicit_ssl=YES
require_ssl_reuse=YES
ssl_ciphers=HIGH

Configuring the BIG-IP to load balance the FTPS request

The following procedure creates a load-balanced FTPS virtual server with persistent connections.

Important: The following configuration assumes that all the intended destination FTPS servers are configured to use the BIG-IP system as the default gateway.

  • Creating the FTPS outbound SNAT
  • Creating the persistence profile
  • Creating the FastL4 profile
  • Creating the FTPS health monitor
  • Creating the FTPS server pool
  • Creating the FTPS virtual server
     

Creating the FTPS outbound SNAT

A SNAT is required to translate the IP address of outbound active connections from the FTPS server to the address of the virtual server. To configure the SNAT, perform the following procedure:

Impact of procedure: Performing the following procedure will translate the FTPS server requests/responses to the IP address of the virtual server when packets traverse a VLAN other than the local network/VLAN of the servers.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Address Translation > SNATs.
  3. Click Create.
  4. Type a name for the SNAT.
  5. From the Translation menu, select IP Address.
  6. Enter the IP address of the FTPS virtual server.
  7. From the Origin menu, select Address List.
  8. Enter the IP addresses for each of the intended FTPS servers that will be used to fulfill request.
  9. From the VLAN Traffic menu, select Enabled on.
  10. In the VLAN List section, select the VLAN where the pool members reside from the Available list.
  11. Move the VLAN to the Selected list by clicking <<.
  12. Click Finished.

Creating the persistence profile

Source address persistence is the recommended persistence method for FTPS. To configure the persistence profile, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click the Persistence tab.
  5. Click Create.
  6. Type a name for the profile.
  7. From the Persistence type menu, select Source Address Affinity.
  8. Select the Custom check box next to Timeout.
  9. In the Timeout box, set the timeout value to be equal to the value for idle_session_timeout in the vsftpd.conf file.
  10. Click Finished.

Creating the FastL4 profile

Create a Performance (Layer 4) profile by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. From the Protocol menu, select FastL4.
  5. Click Create.
  6. Type a name for the profile.
  7. Select the Custom check box next to Idle Timeout, set the timeout value equal to the value for idle_session_timeout in the vsftpd.conf file.
  8. Type an appropriate value for the timeout.
  9. Click Finished.

Creating the FTPS health monitor

Create a custom TCP health monitor specifying the port to test on the FTPS servers by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Monitors.
  4. Click Create.
  5. Type a name for the monitor.
  6. From the Type menu, select TCP.
  7. From the Configuration menu, select Advanced.
  8. In the Alias Service Port box, enter the value of the listen_port (typically 990) variable in the vsftpd.conf file.
  9. Click Finished.

Creating the FTPS server pool

To configure a pool containing the FTPS servers, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Pools.
  4. Click Create.
  5. Type a name for the pool.
  6. In the Health Monitor section, select the monitor you created above from the Available window.
  7. Move the monitor to the Active window by clicking <<.
  8. In the Address box, enter the IP address of the first FTPS server.

    Important: The following configuration assumes that all the intended destination FTPS servers are configured to use the BIG-IP system as the default gateway.

  9. From the Service Port menu, select * (* All Services).
  10. Click Add.
  11. Repeat Steps 8 through 10 for the remaining FTPS servers.
  12. Click Finished.

Creating the FTPS virtual server

The FTPS virtual server receives requests on a range of ports as specified by the vsftpd.conf variables listen_port, pasv_max_port and pasv_min_port. To limit access to undesired port,s refer to the Configuring the BIG-IP AFM firewall to permit FTPS request section, or refer to the Packet Filters chapter of the BIG-IP LTM BIG-IP TMOS: Routing Administration guide. 

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

To create the wildcard port virtual server, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click Create.
  5. Type a name for the virtual server.
  6. In the Destination section, select Host.
  7. Enter the virtual IP address assigned to the FTPS virtual server.
  8. Set the Service Port to 0 (* All Ports).
  9. From the Configuration menu, select Advanced.
  10. From the Type menu, select Performance (Layer 4).
  11. From the Protocol Profile (Client) menu, select the custom FastL4 profile you previously created.
  12. From the VLAN Traffic menu, select Enabled on.
  13. In the VLAN List section, from the Available window, select the VLAN on which the FTPS virtual server resides.
  14. Move the VLAN to the Selected window by clicking <<.
  15. From the Default Pool menu, select the pool of FTPS servers you previously created.
  16. From the Default Persistence Profile menu, select the custom source address persistence profile you previously created.
  17. Click Finished.

    Important: Due to the nature of the FTPS protocol connection request process involving the BIG-IP system and the destination, you cannot perform a secure network address translation (SNAT) on servers.

Configuring the BIG-IP AFM firewall

You can configure the BIG-IP AFM firewall with a policy that can be applied to a specific virtual server. The following procedure creates a policy that contains two rule sets. The first rule set allows access to the FTPS port and data ports. The second rule set denies access to all ports. Request that match the configured ports are passed to the load-balanced FTPS server.

Note: The following procedures are not required to have a functional FTPS virtual server, and are only available for BIG-IP systems licensed and provisioned with BIG-IP AFM.

  • Creating the allowed FTPS rule
  • Creating the block-all firewall rule
  • Creating the firewall logging profile
  • Creating the virtual server firewall policy
  • Configuring the virtual server security policy

Creating the allowed FTPS rule

To create a firewall rule to allow the configured ports used in the vsftp.conf file, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security Network Firewall > Rule Lists and click Create.
  3. Enter a Name for the rule set.
  4. Click Finished.
  5. Click the rule set Name link.
  6. Click Add.
  7. Enter a Name for the rule.
  8. Set Order to First.
  9. Set State to Enabled.
  10. In the Source section set VLAN/Tunnel to the VLAN of the virtual server.
  11. In the Destination section for Address/Region select Address.
  12. Enter the IP address of the virtual server.
  13. In the Port section add the required FTPS port using the Port and/or Port Range options.
  14. Enter the desired numeric port or port ranges.

    Note: To add a port range enter the first numeric port value immediately followed with a (-) dash with the ending numeric port value.

    For example to add the port range 10000 through 10100 enter 10000-10100.

  15. Click Add.
  16. Repeat steps 12-14 for all desired ports.
  17. Set Action to Accept Decisively.
  18. Set Send to Virtual to the name of the FTPS virtual server.
  19. Set Logging to Enabled.
  20. Click Save.

Creating the block-all firewall rule

The following procedure will create a firewall rule that will block/reject all connection request.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log on to the Configuration utility.
  2. Go to Security Network Firewall > Rule Lists and click Create.
  3. Enter a Name for the rule set.
  4. Click Finished.
  5. Click the rule set Name link.
  6. Click Add.
  7. Enter a Name for the rule.
  8. Set Order to Last.
  9. Set State to Enabled.
  10. In the Source section set VLAN/Tunnel to the VLAN of the virtual server.
  11. Leave Destination objects set to Any.
  12. Set Action to Reject.
  13. Set Send to Virtual to the name of the FTPS virtual server.
  14. Set Logging to Enabled.
  15. Click Save.

Creating the firewall logging profile

The following procedure will create a firewall logging profile.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log on to the Configuration utility.
  2. Go to Security > Event Logs > Logging Profiles.
  3. Click Create.
  4. Enter a Name for the logging profile.
  5. Select the Enabled check box for Network Firewall.
  6. Set Publisher to local-db-publisher.

    Note: For external logging options (recommended) refer to the Setting Up Secure Remote Logging chapter of the External Monitoring of BIG-IP Systems: Implementations guide.

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  7. In the Network Firewall sections select the desired logging options.
  8. Set Storage to the desired logging format.

    Note: Requires additional configuration to select Items for Storage Format.

  9. Click Create.

Creating the virtual server firewall policy

The following procedure will utilize the previously created firewall rules in to a firewall policy.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security Network Firewall > Policies and click Create.
  3. Enter a Name for the rule set.
  4. Click Finished.
  5. Click the Name link of the new policy.
  6. On the right hand side click the << to expand the Shared Objects pop-out.
  7. Click Rule List.
  8. Scroll down the available rules and locate the FTPS ports allow rule set.
  9. Click the rule set and drag it into the Policy page.
  10. Scroll down the available rules and locate the block all rule set.
  11. Click the rule set and drag it into the policy page underneath the vsftp ports allow rule set.
  12. Click Commit Changes to System.

Configuring the virtual server security policy

To apply the firewall policy created in the previous set to the FTPS virtual server, perform the following procedure:

Impact of procedure: Performing the following procedure will apply the firewall policy to the selected virtual server.

  1. Log in to the Configuration utility.
  2. Click Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the Name link of the FTPS virtual server.
  4. Click the Security tab and select Policies.
  5. In Network Firewall set Enforcement to Enabled.
  6. Set Policy to the policy created in the previous procedure.

    Note: For testing purposes set Staging to Enabled, this will allow connections to be processed unimpeded while logging policy violations. 

  7. Click Update.
