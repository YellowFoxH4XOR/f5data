Topic

This article provides steps on configuring the fully-qualified domain name (FQDN) ephemeral node feature to autopopulate BIG-IP pools using the tmsh utility.

Description

You can configure the BIG-IP device to automatically populate node and pool member lists by using FQDNs. Depending on the number of IP addresses returned by the DNS server, the BIG-IP device creates an ephemeral pool member for each IP address returned in the DNS response. You may want to refer to the list of articles in the Related Content section at the bottom of this article for information about the behavior, limits and considerations when using the FQDN ephemeral node feature on the BIG-IP device.

Prerequisites

  • You must have administrative access to the tmsh utility on your BIG-IP device.
  • Your BIG-IP device must be configured with a DNS server to handle DNS lookups. Additionally, you should ensure that your DNS server is not configured for round robin DNS resolutions; instead, your DNS server should return all available IP addresses in a DNS resolution. For information about configuring BIG-IP device to resolve DNS, refer to K13205: Configuring the BIG-IP system to resolve DNS hostnames (11.x and later).

Procedures

  • Creating a node using the FQDN ephemeral node feature
  • Configuring a pool using the FQDN ephemeral node feature
  • Disabling/enabling a FQDN pool member

Creating a node using the FQDN ephemeral node feature

Prior to configuring a pool that uses this feature to auto-populate the pool members, you should create the node(s) relevant to the pool. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the tmsh utility on your BIG-IP device as the administrative user.
  2. Create a node by entering the following tmsh command syntax:

    create ltm node <node name> fqdn { name <node FQDN> autopopulate < enabled | disabled > interval < [integer value] | ttl > }

    Note: The interval setting can either be a static integer value you configure or the TTL value obtained from the DNS response if configured with ttl. This setting affects how frequent the BIG-IP device sends DNS queries and repopulate the ephemeral nodes when the autopopulate is set to enabled.

    For example,

    create ltm node node-test-autodns fqdn { name test.myf5.lab autopopulate enabled interval ttl }

  3. Repeat the previous step for creating the remaining node(s) if any.
  4. Verify the FQDN node has been created by entering the following tmsh command syntax:

    list ltm node <node name>

    For example,

    list ltm node node-test-autodns

    Using the previous example, the BIG-IP device should return an output similar to the following:

    ltm node node-test-autodns {
        fqdn {
            autopopulate enabled
            interval ttl
            name test.myf5.lab
        }
        state fqdn-up
    }

Configuring a pool using the FQDN ephemeral node feature

To configure a pool using the FQDN ephemeral node feature, you should add the FQDN node(s) created from the previous procedure as pool member(s). To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the tmsh utility on your BIG-IP device as the administrative user.
  2. Configure a pool by entering the following tmsh command syntax:

    create ltm pool <pool name> monitor <monitor name> members add { <node1 name>:<port> { fqdn { autopopulate < enabled | disabled > } } … }

    For example,

    create ltm pool pool-test-autodns monitor mon-http-test members add { node-test-autodns:8001 { fqdn { autopopulate enabled } } node-test-autodns:8002 { fqdn { autopopulate enabled } } }

  3. Verify the pool has been configured by entering the following tmsh command syntax:

    list ltm pool <pool name>

    For example,

    list ltm pool pool-test-autodns

    Using the previous example, the BIG-IP device should return an output similar to the following:

Disabling/enabling a FQDN pool member

You can disable a FQDN pool member when you want the pool member to stop accepting new connections but complete the existing persistent and active connections. This is useful when you want to perform maintenance on the pool member. Note that the BIG-IP device does not allow modifications made to the individual FQDN ephemeral pool member, you can only make changes to the parent FQDN pool member. If you attempt to modify the individual FQDN ephemeral pool member, the BIG-IP device does not allow the modification and reports an error similar to the following example:

01071c39:3: Modify of ephemeral pool member (pool /Common/pool-test-autodns member /Common/192.168.40.131) is not permitted.

When you disable/enable the parent FQDN pool member, all the child FQDN ephemeral pool members will be disabled/enabled. To disable/enable a FQDN pool member, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the tmsh utility on your BIG-IP device as the administrative user.
  2. To disable a FQDN pool member, enter the following tmsh command syntax:

    modify ltm pool <pool name> members modify { <pool member name>:<port> { session user-disabled } }

    For example,

    modify ltm pool pool-test-autodns members modify { node-test-autodns:8001 { session user-disabled } }

  3. Verify the status of the pool members by entering the following tmsh command syntax:

    list ltm pool <pool name>

    For example,

    list ltm pool pool-test-autodns

    The command should return an output similar to the following example:

    For example,
