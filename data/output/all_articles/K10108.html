Topic

This Solution provides an overview of the FirePass Advanced Session Variable feature, along with two specific configuration examples:
 
  • Configuring a dynamic name for a Web Application favorite based on the day of the week
  • Configuring a dynamic subnet exclusion list for a Network Access favorite based on the client IP address
 
Overview
 
Introduced in FirePass version 6.0.3, the Advanced Session Variable feature allows FirePass administrators to define their own unique session variables. Advanced Session Variables (ASVs) provide flexible mechanisms such as regular expressions and concatenation operators for manipulating the values of FirePass session variables. Using ASVs, regular session variable values can be tested using comparison operators, logical operators, and functions. Based on results of these tests, session variable values or fragments of session variable values (extracted through regular expressions) can be combined together to form the value of an ASV.
 
ASVs can be used anywhere in the FirePass configuration where a regular session variable can be used, with the following two exceptions:
  • Within a pre-logon sequence.
    For example, you cannot use an ASV in a pre-logon rule.
  • Within a protected configuration.
    For example, you cannot use an ASV in a custom check expression.
 
ASVs are configured on the Users : Session Variables page in the FirePass Administrative Console. When defining an ASV, you must enter a unique name in the Name field. To refer to that ASV within the FirePass configuration, prepend the ASV name with session.asv. and enclose it within percent (%) characters. For example, if your ASV name is MyASV, you would refer to it as follows:
 
%session.asv.MyASV%
 
Important: ASV names are case-sensitive. Therefore, if you configured an ASV with the name MyASV, you would refer to it as %session.asv.MyASV%, and not %session.asv.myasv%.
 
When configuring an ASV that references one or more regular session variables, it is important to ensure that the session variables you reference are defined at user logon. Most session variables are created when a specific action occurs, such as a pre-logon sequence is initiated, a dynamic group mapping process occurs, or an authentication process occurs. If your ASV references a session variable that is created during the pre-logon sequence, but no pre-logon sequence is enabled, that session variable is undefined.
 
Important: ASVs are evaluated at runtime at the moment they are needed. If the ASV references an undefined session variable, an empty string is used for the value of the undefined session variable.

If you want to view all session variables assigned to a user, temporarily enable the Save user's session variables to Logon Reports setting on the Device Management : Maintenance : Troubleshooting Tools page. The next time the user logs on to FirePass, you can view the users's session variables by selecting the user’s logon name on the Reports : Logons page.
 
Important: Enabling the Save user's session variables to Logon Reports setting will increase the load on the FirePass controller. This setting should only be enabled temporarily for troubleshooting purposes.
 
ASVs can be as simple or as complex as the requirement at hand. For example, a simple ASV could be configured to reflect the day of the week. If the day of the week is a weekday, the ASV can be set to weekday and if the day of the week is a weekend, the ASV can be set to weekend. A more complex example would be to configure an ASV that extracts a user’s credentials from a one time password (OTP) using a regular expression, and then modifying the extracted value into a format suitable for single sign-on (SSO) purposes.
 
For a list of ASV operators and functions, click the Help link on the Users : Session Variables page in the FirePass Administrative Console.
 
Configuring a dynamic name for a Web Application favorite based on the day of the week
 
The following procedure configures a dynamic name for a Web Application favorite based on the day of the week. Using an ASV, the Web Application favorite name is displayed as Help Desk during the week and Weekend Help Desk during the weekend.
 
  1. Log on to the FirePass Administrative Console.
     
  2. Navigate to the Users: Session Variables page.
     
  3. Click the Add New Session Variable link.
     
  4. In the Name field, enter a unique name for the advanced session variable.

    For example:

    HelpDeskResName

    Note: The name must start with a letter or digit, and it can contain one or more of the following characters: letters, digits, hyphens ( - ) and underscores ( _ ).
     
  5. In the Description field, optionally enter a description that will help you remember the purpose of this advanced session variable.

    For example:

    Return "Help Desk" if Mon - Fri, or "Weekend Help Desk" if Sat - Sun.

  6. Click the plus icon (+) to the right of the Comment field.
     
  7. In the Condition field in the first row, enter the following text:

    (session.datetime.dayofweekstr == "Sat") OR (session.datetime.dayofweekstr == "Sun")
     
  8. In the Expression field in the first row, enter the name of the weekend resource.

    For example:

    "Weekend Help Desk"
     
    Important: You must include the starting and ending quotation marks, or you'll receive a syntax error when saving the ASV.
     
  9. In the Expression field in the second row (there should be no Condition field in this row), enter the fallback name of the resource (i.e. the name that will be returned if the day of the week does not match Sat or Sun).

    For example:

    "Help Desk"

    Important: You must include the starting and ending quotation marks, or you'll receive a syntax error when saving the ASV.
     
  10. Click the Save and Test button.

    Your screen should now appear similar to the following:

     
     

    If you received any error messages when saving the ASV, resolve all errors before proceeding to the next step. Ensure that the text in the Condition field is identical to the text provided in Step 7, and that you included starting and ending quotation marks in the Expression fields.

  11. In the Enter values for session variables section, enter Mon (with no quotation marks) in the session.datetime.dayofweekstr text field.
     
  12. Click the Save and Test button.

    Variable value is displayed as Help Desk.
     
  13. In the Enter values for session variables section, enter Sat (with no quotation marks) in the session.datetime.dayofweekstr text field.
     
  14. Click the Save and Test button.

    Variable value is now displayed as Weekend Help Desk.
     
  15. Navigate to the Portal Access: Resources page.
     
  16. In the Resource Group menu, select the name of the resource group you want to configure.
     
  17. Click the Add New Favorite link.
     
  18. In the Name field, enter the name of the advanced session variable you just created.

    For example:

    %session.asv.HelpDeskResName%

    Note: ASVs use the format session.asv.<name> where name is the unique name you configured for the ASV. Additionally, ASV names are case-sensitive. Therefore, if you entered HelpDeskResName in Step 4, you must enter %session.asv.HelpDeskResName%, and not %session.asv.helpdeskresname%.
     
  19. Configure the remaining fields as appropriate for the Web Application favorite.

    Note: For detailed instructions about configuring Web Application favorites, refer to the FirePass Controller Administrator Guide or click the Help link on the Portal Access: Resources page.
     
  20. Click the Save button.

    The session.datetime.dayofweekstr session variable referenced in Step 7 is set during the pre-logon sequence. If you already have a pre-logon sequence enabled on the Users : Endpoint Security : Pre-Logon Sequence page, this procedure is complete. If you do not have a pre-logon sequence enabled, perform the following steps to configure and enable an empty pre-logon sequence.
     
  21. Navigate to the Users : Endpoint Security : Pre-Logon Sequence page.
     
  22. In the Create new sequence field, enter empty-asv.
     
  23. In the Based on menu, select template: Empty.
     
  24. Click the Create button.

    The pre-logon sequence empty-asv now appears in the Select Sequence to Use section of the page.
     
  25. Select the option button to the left of empty-asv.
     
  26. Click the Apply button to enable the pre-logon sequence.

The name of the Web Application favorite will now be displayed as Help Desk if a user logs in to FirePass on Monday through Friday, and it will be displayed as Weekend Help Desk if a user logs in to FirePass on Saturday or Sunday.
 

Configuring a dynamic subnet exclusion list for a Network Access favorite based on the client IP address
 
The following procedure configures a dynamic list for the Network Access Subnets to exclude setting based on the client IP address. For the examples provided in the procedure, the value of the Subnets to exclude field will be set as follows:
 
  • If the client IP address belongs to 10.0.5.0/24 or 10.0.6.0/24, the Subnets to exclude field will be set to 10.0.1.1,10.0.1.2.
  • If the client IP address belongs to any other subnet within 10.0.0.0/16, the Subnets to exclude field will be set to 10.0.0.1,10.0.0.2,10.0.0.3.
  • If the client IP address does not belong to the 10.0.0.0/16 network, the Subnets to exclude field will be left blank.
 
Note: The Subnets to exclude field is located on the Network Access : Resources page under the Client Settings tab. This field only appears if the Exclude subnets check box is selected.
 
  1. Log on to the FirePass Administrative Console.
     
  2. Navigate to the Users: Session Variables page.
     
  3. Click the Add New Session Variable link.
     
  4. In the Name field, enter a unique name for the advanced session variable.

    For example:

    SubnetExclusion

    Note: The name must start with a letter or digit, and it can contain one or more of the following characters: letters, digits, hyphens ( - ) and underscores ( _ ).
     
  5. In the Description field, optionally enter a description that will help you remember the purpose of this advanced session variable.

    For example:

    Populate Network Access "Subnets to exclude" field based on client IP.
  6. Click the plus icon (+) to the right of the Comment field.
  7. Click the plus icon (+) a second time to open an additional row.
  8. In the Condition field in the first row, enter the first network you want to match using the following syntax:

    IN_SUBNET(session.network.client.ip,"<Network>/<Netmask>")

    The <Network> section is the network address and <Netmask> is the subnet mask in CIDR notation. You can enter multiple networks separated by commas.

    For example:

    IN_SUBNET(session.network.client.ip,"10.0.5.0/24","10.0.6.0/24")
     
  9. In the Expression field in the first row, enter the corresponding subnet exclusion list.

    For example:

    "10.0.1.1,10.0.1.2"
     
    Important: You must include the starting and ending quotation marks, or you will receive a syntax error when saving the ASV.
  10. In the Condition field in the second row, enter the second network you want to match using the following syntax:

    IN_SUBNET(session.network.client.ip,"<Network>/<Netmask>")

    The <Network> section is the network address and <Netmask> is the subnet mask in CIDR notation.

    For example:

    IN_SUBNET(session.network.client.ip,"10.0.0.0/16")
     
  11. In the Expression field in the second row, enter the corresponding subnet exclusion list.

    For example:

    "10.0.0.1,10.0.0.2,10.0.0.3"
     
    Important: You must include the starting and ending quotation marks, or you will receive a syntax error when saving the ASV.
     
  12. Click the Save and Test button.

    Your screen should now appear similar to the following:

     

    If you received any error messages when saving the ASV, resolve all errors before proceeding to the next step. Ensure that the text in the Condition fields use the syntax provided in Step 7, and that you included starting and ending quotation marks in the Expression fields.

  13. In the Enter values for session variables section, enter 10.0.5.10 (with no quotation marks) in the session.network.client.ip text field.
  14. Click the Save and Test button.

    Variable value is displayed as 10.0.1.1,10.0.1.2.
     
  15. In the Enter values for session variables section, enter 10.0.0.10 (with no quotation marks) in the session.network.client.ip text field.
     
  16. Click the Save and Test button.

    Variable value is now displayed as 10.0.0.1,10.0.0.2,10.0.0.3.
     
  17. In the Enter values for session variables section, enter 192.168.0.10 (with no quotation marks) in the session.network.client.ip text field.
  18. Click the Save and Test button.

    Variable value is now empty, since no conditions were specified for the 192.168.x.x network, and no fallback value was configured in the Expression field in the third row.
     
  19. Navigate to the Network Access: Resources page.
     
  20. In the Resource Group menu, select the name of the resource group you want to configure.
     
  21. Under the Client Settings tab, select the Exclude subnets check box if it is not already selected.
     
  22. In the Subnets to exclude field, enter the name of the advanced session variable you just created.

    For example:

    %session.asv.SubnetExclusion%

    Note: ASVs use the format session.asv.<name> where name is the unique name you configured for the ASV. Additionally, ASV names are case-sensitive. Therefore, if you entered SubnetExclusion in Step 4, you must enter %session.asv.SubnetExclusion%, and not %session.asv.subnetexclusion%.
     
  23. Configure the remaining fields as appropriate for the Network Access favorite.

    Note: For detailed instructions on configuring Network Access favorites, refer to the FirePass Controller Administrator Guide or click the Help link on the Network Access: Resources page.
     
  24. Click the Save button.
     
  25. The session.network.client.ip session variable referenced in Step 7 is set during the pre-logon sequence. If you already have a pre-logon sequence enabled on the Users : Endpoint Security : Pre-Logon Sequence page, this procedure is complete. If you do not have a pre-logon sequence enabled, perform the following steps to configure and enable an empty pre-logon sequence.
     
  26. Navigate to the Users : Endpoint Security : Pre-Logon Sequence page.
     
  27. In the Create new sequence field, enter empty-asv.
     
  28. In the Based on menu, select template: Empty.
     
  29. Click the Create button.

    The pre-logon sequence empty-asv now appears in the Select Sequence to Use section of the page.
     
  30. Select the option button to the left of empty-asv.
     
  31. Click the Apply button to enable the pre-logon sequence.

The user's subnet exclusion list will now be dynamically set based on the client IP address.
