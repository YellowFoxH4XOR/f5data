Known Issue

The Traffic Management Microkernel (TMM) may stop responding when you use a suspending iRule command with Datagram LB. This issue occurs when all of the following conditions are met:

  • Datagram LB is enabled in a User Datagram Protocol (UDP) profile for the affected virtual server.
  • You use an iRule command that suspends the response in an iRule associated with this virtual server (for example, the after command).
  • More than one response is received from the pool member for a request.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability (HA) pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H426640 on the Diagnostics > Identified > Low|High screen.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system fails over to the standby system, if configured as an HA pair.
  • Error messages similar to the following example are logged to any of the /var/log/tmm* files:


    notice ** SIGSEGV **
    notice fault addr: 0x78
    notice fault code: 0x1

Workaround

There is no workaround. However, you can avoid this issue by omitting suspending iRule commands when using iRule events that may trigger multiple times, such as the DNS_RESPONSE event.
