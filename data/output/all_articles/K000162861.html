Description

  • BIG-IQ UCS backups for managed BIG-IP devices fails during transfer to BIG-IQ with HTTP 429 errors
  • logs similar to this example can be seen from the httpd log file

Aug 7 06:03:01 bigip.hostname err httpd[12345]: [qos:error] [pid 12345:tid 3856567104] [client ip:port] mod_qos(067): access denied, QS_ClientEventLimitCount rule: event=QS_EVENT, max=150, current=150, age=1, c=<ip>, id=6G9Yy2ZYBgBTQQABVwXXXECL3uVe6XR8, referer: com.f5.rest.common.RestFileReceiver

  • logs similar to this example can be seen from the restjavad log file:

[WARN][07 Aug 2026 06:03:01 NZST][/cm/system/backup-restore/f14d4121-720c-4414-a53f-faeb8753731d/worker UcsBackupRestoreTaskWorker] UCS backup with id f14d4121-720c-4414-a53f-faeb8753731d, name daily-1400_bigip.hostname_20260807060000.ucs, and referer http://localhost:8100/shared/group-task failed: status:429, body:<html...>
[WARN][07 Aug 2026 06:03:01 NZST][/cm/shared/event/alerts AlertCollectionWorker] There was a failure when creating a backup. Additional information: UCS backup with id f14d4121-720c-4414-a53f-faeb8753731d, name daily-1400_bigip.hostname_20260807060000.ucs, and referer http://localhost:8100/shared/group-task failed: status:429, body:<html...>

Environment

  • BIG-IQ version 8.4.0 managing BIG-IP devices.
  • Affected BIG-IP devices running version 21.1.0.1
  • UCS backups initiated from BIG-IQ and transferred through the BIG-IP REST interface.
  • BIG-IP UCS creation succeeded locally; failure occurs during transfer to BIG-IQ.

Cause

The BIG-IP httpd API request rate limit is set to 150 requests by default. The BIG-IQ UCS transfer exceeded this limit, causing mod_qos to deny REST file-transfer requests and return HTTP 429 responses. This prevents the REST API from successfully retrieving the locally generated UCS files.

Answer/Recommended Actions

• On each affected BIG-IP device, increase the API request limit to 200:

# tmsh modify sys httpd api-ratelimit 200

# tmsh save sys config

 

• Review the security implications of changing the API rate limit and use appropriate HTTP access controls or allow-lists when applicable.

Additional Information

The rate limit is not a universal value for all environments. The setting should be increased only as needed and should be reviewed against individual management-plane security requirements.
