K000150573: Troubleshooting Slowness Issues for VIPs on BIG-IP

Support Solution
Published
2025-06-12

Applies to

  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000150573

Description

When trying to connect to VIP, there is a delay loading the web page. The delay occurred after the three-way handshake (3WHS) when initiating HTTP GET requests. In one instance, a 9-second delay was noted, and in another, a 17.5-second delay was observed before the GET request was sent.

Packet captures revealed that delays occurred after completing the TCP three-way handshake but before sending HTTP GET requests.

For example:

10    7.748692    10.20.30.40    1.2.3.4    TCP    201    IN  s1/tmm0 : 50411 → 80 [ACK] Seq=1 Ack=1 Win=2102272 Len=0
32    25.377222    10.20.30.40    1.2.3.4    HTTP    1267    IN  s1/tmm0 : GET /example/csp/sys/example.csp HTTP/1.1 

Environment

  • LTM
  • Virtual Server on port 443
  • Slowness

Cause

There could be couple possible causes of the issue:

  1. Delay originating from the client itself during request initiation.
  2. Network congestion between the client and the F5 device.

Recommendations

To resolve or further investigate similar issues, follow these steps:

  • Verify Network Path: Check for potential network congestion or latency between the client and the F5 device by analyzing intermediate network devices and paths.
  • Capture Traffic Data: Collect detailed traffic data using packet captures (PCAP) and HAR files:

                   Use this command on BIG-IP to capture traffic:

    • tcpdump -nni 0.0:nnnp -s0 -vw /var/tmp/<filename>.pcap host <VIP_IP>
    • Generate a HAR file from your browser while reproducing the issue.
  • Compare Configurations: Compare configurations of affected and unaffected VIPs to identify any discrepancies that might contribute to performance differences.
  • Backend Analysis: Investigate backend server processing times for delays in responding to requests routed through affected VIPs.
  • Additional: If no issues are found in steps above:
    • Test with alternate clients or networks to rule out client-side delays.
    • Monitor resource utilization on both F5 and backend servers during periods of slowness.
