Topic

Important: The information in this article applies to BIG-IP 11.6.x and earlier. In BIG-IP 12.0.0 and later, the FTP profile has FTPS support and therefore the procedures in this article are not necessary. For more information about the FTP profile, refer to K08859735: Overview of the FTP profile (14.x - 17.x).

In 11.6.x and earlier you cannot configure the BIG-IP LTM system to terminate FTPS connections and offload Secure Sockets Layer (SSL) processing. You can configure the BIG-IP LTM system to load balance FTPS traffic using passthrough encryption.

In BIG-IP 12.0.0 and later, the FTP profile has FTPS support and therefore the procedures in this article are not applicable.

FTP mechanics and the challenge of load balancing FTPS

The data connection for a passive FTP transfer is established inbound by the client to a destination port chosen and communicated to the client by the FTP server. The data connection for an active FTP transfer is established outbound by the FTP server to a destination port chosen and communicated to the FTP server by the client.

For unencrypted FTP traffic, you can simply apply the built-in FTP profile to a standard virtual server. The virtual server performs the required address translation. The FTP profile examines the exchange on the FTP control connection, then when an FTP data connection is required, the FTP profile sets up a temporary listener on the appropriate address and port. For active transfers, the FTP profile also modifies the destination address in the FTP control connection to reflect the virtual server address.

However, when using FTPS, the control connection may be encrypted, preventing the FTP profile from inspecting and modifying the FTP control connection data and setting up the listener. To load balance FTPS traffic with an encrypted control connection, you can instead configure a wildcard port virtual server to load balance all FTP connection requests (encrypted or unencrypted, control or data) to the pool members, and secure network address translation (SNAT) the FTP servers to the virtual server address. The virtual server will listen on all ports, and the FTPS servers will host or masquerade the virtual server address, so address translation for inbound connections and control connection data inspection/modification are not required. The SNAT performs the required address translation for outbound connections.

Note: An FTP profile will interfere with the traffic flows that the system intended this configuration to manage; do not configure an FTP profile on the virtual server.

FTPS server prerequisites

To support this configuration, each FTPS server pool member must reflect the FTPS virtual server address when communicating with the client, ensuring that all connections requests are directed to the virtual server address.

The simplest way to ensure this is to configure each FTPS server to use the virtual server address as a masquerade address. A masquerade address is the address the FTP server will insert into messages sent on the control channel. Packets are sent from the real server's IP address. Most FTP server software supports this option. Refer to the documentation for your FTPS server software for configuration details.

If configuring a masquerade address is not possible, you may be able to configure the server to use the IP address of the virtual server by binding the virtual server address to a network interface. If bound to an interface other than the loopback interface, you must disable ARP replies for this address to prevent interference with the Address Resolution Protocol (ARP) replies from the virtual server. This option requires that the FTPS servers and the BIG-IP system reside on a common Virtual Local Area Network (VLAN). Refer to the documentation for your host operating system for configuration details.

Configuring the BIG-IP LTM to support passthrough FTPS load balancing

To support passthrough FTPS load balancing on the BIG-IP LTM, you must perform the following procedures:

  • Configuring a SNAT
  • Configuring the source address persistence profile
  • Creating a FastL4 profile with a custom timeout
  • Creating a custom TCP health monitor specifying the port to test on the FTPS servers
  • Configuring the FTPS server pool
  • Configuring the wildcard port virtual server

Important: While server response traffic can follow the lasthop path and may not require IP routing, outbound active data connections require an IP route back to the client. You must configure a default route or other routes supporting connections to any client that may connect to the FTPS virtual. For more information about configuring routes on the BIG-IP system, refer to the BIG-IP Network and System Management Guide.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Configuring a SNAT

A SNAT is required to translate the IP address of outbound active connections from the FTP server to the address of the virtual server. To configure the SNAT, perform the following procedure:

Note: Traffic cannot asymmetrically go around the BIG-IP system, as it needs to go through the BIG-IP system to make use of the proposed OUTBOUND SNAT

  1. Log in to the Configuration utility.
  2. Go to the following page that applies to your version:
    • 11.3.0 and later:

      Local Traffic > Address Translation > SNATs

    • 10.x through 11.2.1:

      Local Traffic > SNATs

  3. Select Create.
  4. Enter a name for the SNAT.
  5. For Translation, select IP Address.
  6. Enter the IP address of the FTPS virtual server.
  7. For Origin, select Address List.
  8. If your FTPS servers have been configured to masquerade using the virtual server address, enter the real IP addresses of each of the FTPS servers. If you have bound the virtual server address to an interface on the FTPS servers, enter only the FTPS virtual server IP address.
  9. For VLAN Traffic, select Enabled on.
  10. For VLAN List section, select the VLANs containing the pool members from the Available list and move them to the Selected
  11. Select Finished.

Configuring the source address persistence profile

Source address persistence ensures that passive data connections are directed to the same pool member as the control connection. To configure the persistence profile, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select the Persistence tab.
  5. Select Create.
  6. Enter a name for the profile.
  7. For Persistence type, select Source Address Affinity.
  8. Select the Custom check box next to Timeout.
  9. For Timeout, enter an appropriate value.

    Note: The persistence timeout should match the idle timeout on the virtual server.

  10. You can optionally select the Custom check box next to Mirror Persistence and select the Mirror Persistence check box.

    Note: If you intend to mirror connections in a redundant pair for more seamless failover, you should also enable persistence mirroring. If connections will not be mirrored, do not mirror persistence.

  11. Select Finished.

Creating a FastL4 profile with a custom timeout

Create a Performance (Layer 4) profile with a custom timeout by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. For Protocol, select FastL4.
  5. Select Create.
  6. Enter a name for the profile.
  7. Select the Custom check box next to Idle Timeout.
  8. Enter an appropriate value for the timeout.

    Note: The idle timeout should be at least as long as the idle timeout that you have configured on your FTP server and the maximum amount of time that you would expect a file transfer to take.

  9. Select Finished.

Creating a custom TCP health monitor specifying the port to test on the FTPS servers

Create a custom TCP health monitor specifying the port to test on the FTPS servers by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Monitors.
  4. Select Create.
  5. Enter a name for the monitor.
  6. For Type, select TCP.
  7. For Configuration, select Advanced.
  8. For Alias Service Port, enter a port on which the FTPS servers respond to a TCP connection request.
  9. Select Finished.

Configuring the FTPS server pool

To configure a pool containing the FTPS servers, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Pools.
  4. Select Create.
  5. Enter a name for the pool.
  6. For Health Monitor, select the monitor you created and move it to the Active list.
  7. For Address, enter the IP address of the first FTPS server.
  8. For Service Port, select * All Services.
  9. Select Add.
  10. Repeat Steps 8 through 9 for the remaining FTPS servers.
  11. Select Finished.

Configuring the wildcard port virtual server

The FTPS virtual server answers on all ports and will use the persistence profile, protocol profile, and pool you created in the previous sections. To configure the wildcard port virtual server, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select Create.
  4. Enter a name for the virtual server.
  5. For Destination, select Host.
  6. Enter the virtual IP address assigned to the FTPS virtual server.
  7. Set the Service Port to *.

    Note: The asterisk character ( * ) refers to All Ports.

  8. For Configuration, select Advanced.
  9. For Type, select Performance (Layer 4).
  10. For Protocol Profile (Client), select the custom FastL4 profile you previously created.
  11. For VLAN Traffic, select Enabled on.
  12. For VLAN List, in the Available list, select the VLAN on which the FTPS virtual server resides and it to the Selected list.
  13. You can optionally mirror the connection information for this virtual server to the failover partner, by selecting the Connection Mirroring check box.
  14. If you have configured an interface on your pool members with the IP address of your FTPS virtual server, disable address translation by clearing the Address Translation Enabled check box. (If you have configured your FTPS servers to masquerade as the FTPS virtual server address, leave address translation enabled.)
  15. For Default Pool, select the pool of FTPS servers you previously created.
  16. For Default Persistence Profile, select the custom source address persistence profile you previously created.
  17. Select Finished.

Note: A wildcard port virtual server accepts any traffic addressed to the virtual server's IP address, regardless of destination port, and load balances to the servers on the same destination port. For example, if a connection request arrives for port 88 on the wildcard port forwarding virtual server address, the request will be load balanced to a pool member on port 88. You may want to limit your servers' exposure to non-FTP traffic by limiting the ports your FTP server listens on for passive connections, or by implementing port-based packet filtering anywhere in the packet stream. For example, you may be able to configure a firewall upstream to restrict both the destination ports allowed to reach the virtual server, and also configure the FTP server to listen only on ports > 1023 for the related passive data connections. Configuration of those options is beyond the scope of this document.
