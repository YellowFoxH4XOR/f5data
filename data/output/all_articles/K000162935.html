Description

F5 Distributed Cloud (XC) supports streaming telemetry (request logs, security events, audit logs, DNS logs) to external destinations using the Global Log Receiver (GLR). This article describes how to forward XC logs to Microsoft Sentinel using Azure Event Hub as the intermediary transport.

The data path is:

F5 XC (GLR) —AMQP→ Azure Event Hub → Log Analytics Workspace → Microsoft Sentinel

Note: XC does not have a native Sentinel destination type. Azure Event Hub is the supported and validated method for delivering XC logs into Sentinel.

Environment

  • F5 Distributed Cloud (XC)
  • Global Log Receiver (GLR)

Step 1: Prepare the Azure Event Hub

  1. In the Azure Portal, create an Event Hubs namespace (e.g., f5xc-sentinel-hub).
  2. Inside the namespace, create an Event Hub (e.g., f5xc-logs).
  3. Open Shared access policies for that Event Hub and add a policy (e.g., glr-send) with the Send claim enabled.
  4. Copy the primary connection string (or SAS key) — you will paste this into the F5 XC GLR configuration.

For details on locating and formatting the connection string, see: Get an Event Hubs connection string (Microsoft Docs).

• (Recommended) In Microsoft Sentinel, enable the Azure Event Hubs data connector and point it at this

Event Hub so Sentinel begins listening for incoming messages.

Step 2: Create the Global Log Receiver in F5 XC

F5 Distributed Cloud — Global Log Receiver to Microsoft Sentinel Page 1In the F5 XC Console, navigate to either of these (both are valid config surfaces):

• Shared Config → Manage → Global Log Receiver, or

• Multi-Cloud Network Connect → Manage → Log Management → Global Log Receiver

Click Add Global Log Receiver and configure:

Save the GLR. F5 XC auto-provisions a delivery pipeline for your tenant that pushes the selected logs to the Event Hub via AMQP.

Full GLR reference: Global Log Streaming (F5 XC Docs).

Step 3: Verify Ingestion in Microsoft Sentinel

  1. In the Azure Portal, open your Log Analytics workspace (linked to Sentinel).
  2. Go to Logs and query the table receiving Event Hub data (for example, a custom table such as tsglr_CL — the exact name depends on your connector/parsing rule).

Parsing the log payload (important)

Special characters: F5 XC delivers logs as JSON, and some XC field keys contain special characters (such as @ and_). 
Microsoft Sentinel cannot map these directly to native column names, so the raw payload lands in a single field (e.g., RawData). 
Use parse_json() in KQL to extract the fields you need.

tsglr_CL
| extend parsed = parse_json(RawData)
| project TimeGenerated,
  App = parsed.app,
  Source_IP = parsed.src_ip,
  City = parsed.city,
  Country = parsed.country,
  Response_Code = parsed.rsp_code,
  Original_Payload = parsed
| order by TimeGenerated desc

Adjust the projected fields (app, src_ip, rsp_code, etc.) to match the log type you selected in Step 2. You can save this query as a KQL parser function to reuse across analytics rules and workbooks.
