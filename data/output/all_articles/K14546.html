Known Issue

Redistribution of OSPFv3 routes may use incorrect metrics.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is a member of a redundant configuration.
  • OSPFv3 is configured with redistribution from another protocol using a non-default metric or metric type.

When a BIG-IP system experiences a failover from active to standby, the metric or metric-type are not preserved and the OSPFv3 routes may be redistributed using incorrect metrics.

Impact

Depending on your environment, the network routing may not function as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H425756 on the Diagnostics > Identified > Medium screen.
  • OSPFv3 configured with a non-default metric/metric-type on a redistribute statement does not show the non-default metric/metric-type in the OSPF running configuration.
  • The running ZebOS configuration on the standby unit does not match the actual configuration in the ZebOS.conf file.
  • The standby unit OSPFv3 redistributes routes using incorrect metrics.

Workaround

To work around this issue, you can restart the tmrouted process on the standby unit to reload the correct configuration. To do so, perform the following procedure:

Impact of workaround: Restarting the tmrouted process will cause all dynamically learned routes to be temporarily unavailable.

  1. Log in to the command line of the affected BIG-IP system, which is currently the standby unit.
  2. To restart the tmrouted process, type the following command:

    bigstart restart tmrouted
