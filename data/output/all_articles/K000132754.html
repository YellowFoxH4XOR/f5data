K000132754: Virtual Address ARP entry showing incomplete on Active Box

Type
Support Solution
Published
2023-02-24
Updated
2023-07-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000132754

Description

Incomplete ARP entry for Virtual address on the Active device.

Environment

  • BIG-IP LTM and BIG-IP DNS provisioned on the same system
  • BIG-IP DNS Data Center:Server configured to point at the local LTM instance
  • That same Data Center:Server is configured with a non-standard health monitor (e.g. tcp_half_open instead of bigip) and virtual server discovery is enabled.

Cause

Possible misconfiguration. This can happen when the LTM being monitored has virtual servers that don't all match the monitor type that was chosen at the BIG-IP DNS level.

For example, if the DNS -> LTM monitor is setup with tcp_half_open but the LTM has both TCP and UDP virtual servers, it can cause strange behavior (like a self-ip sending out ARP requests for an ip address that is configured as a virtual address on the same system).

Alternatively, an incomplete ARP entry may be the result of a bit flip issue. For information refer to K32545132: ARP entry in BIG-IP stays incomplete . 

Recommended Actions

Configure the BIG-IP DNS to use the standard bigip monitor. If more detailed monitoring is needed it should be setup on the downstream BIG-IP LTM system (in this case, the same host). The bigip monitor enables the downstream BIG-IP LTM to report the status of its own monitors for virtual servers back to the BIG-IP DNS.
