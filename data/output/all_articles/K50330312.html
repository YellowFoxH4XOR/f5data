Description

A generic host virtual server or pool monitor in BIG-IP DNS will fail with a reason of (no route) when the address to be monitored is in the same subnet as the sys management-ip or when no route exists from a BIG-IP to the server.

For Example:

alert gtmd[<PID>]: 011ae0f2:1: Monitor instance <instance_name> <instance_IP>:<instance_PORT> UP --> DOWN from <big-ip_self-ip> (no route)

In this error message, note the following:
  • <PID> is the process ID for gtmd process.
  • <instance_name> is the name of the monitor instance.
  • <instance_IP> is the IP Address of the monitor instance.
  • <instance_PORT> is the Port of the monitor instance.
  • <big-ip_self-ip> is the Self-IP Address of the BIG-IP which hosts the big3d agent initiating the probe.
For Example:

alert gtmd[21714]: 011ae0f2:1: Monitor instance /Common/generichost.example.com 192.168.1.10:443 UP --> DOWN from 10.10.10.1 (no route)

Environment

  • BIG-IP DNS
  • Generic Host with monitor configured.
  • Generic Host IP Address in same subnet as sys management-ip or when no route exists from a BIG-IP to the server

Cause

This behavior is by design

Recommended Actions

Create a more specific route or use Prober Pools
