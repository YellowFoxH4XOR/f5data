K12043: The BIG-IP WebAccelerator system may not recognize the pv tag in an encoded URL for an Intelligent Browser Referencing object

Known Issue

This is the result of a known issue. When the BIG-IP WebAccelerator system rewrites a URL for an Intelligent Browser Referencing (IBR) object, it appends a three-character prefix followed by 16 hexadecimal digits. By default, the three-character prefix is ;pv.

Web servers that link to the IBR object may encode the semicolon ( ; ) character, changing the prefix from ;pv to %3Bpv. As a result, when a browser requests the object using the encoded URL, BIG-IP WebAccelerator does not recognize the pv tag. When BIG-IP WebAccelerator forwards the request with the mangled URL to the origin web server (OWS), the OWS typically responds with a 404 Not Found response.

For example, the following hit log entry shows an HTTP GET request with the prefix %3Bpv appended to the file name style.css, and a 404 Not Found response from the OWS:

10.1.0.240 - - [02/Sep/2010:09:23:23 -0700] "GET /style.css%3Bpv84b720597dca68a5 HTTP/1.0" 404 306 "-" "Mozilla/5.0 (Windows; U; Windows NT 5.1; en-US; rv:1.9.2.8) Gecko/20100722 Firefox/3.6.8" "-" 404 - "Pages" pr 11

Note: The formatting and content of hit logs vary based on the logging options you configure. Additionally, hit logs are not enabled by default.

F5 Networks Product Development is tracking this issue as ID 339186.

Workaround

To prevent this issue from occurring, change the default IBR prefix to an alternate three-character prefix, such as #pv.

Note: For information about modifying the IBR prefix, refer to K11120: Changing the prefix used by the BIG-IP WebAccelerator system for Intelligent Browser Referencing objects.
