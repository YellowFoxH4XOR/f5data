Known Issue

This is the result of a known issue. The TCP monitor incorrectly marks pool members down before the timeout elapses. If the TCP monitor is configured without Send String and Receive String parameters, it will incorrectly mark pool members down after the interval time has elapsed, rather than after the timeout has elapsed.

F5 Networks Product Development tracked this issue as CR99754 and it was fixed in BIG-IP LTM version 9.4.6. For information about upgrading, refer to the BIG-IP LTM, Link Controller, WebAccelerator, or ASM Release Notes. 

This issue was fixed in Hotfix-BIG-IP-9.4.5-HF2, which has been issued for BIG-IP version 9.4.5, and in Hotfix-BIG-IP-v9.6.1-HF1, issued for BIG-IP version 9.6.1. You may download one of these hotfixes or later versions of the hotfixes from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

For information about managing F5 Networks product hotfixes, refer to K6845: Managing F5 Networks product hotfixes.

Workaround

You can work around this issue by defining the Send String and Receive String parameters for the TCP monitor. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Monitors.
  4. Click the appropriate TCP monitor.
  5. Enter the Send String and Receive String parameters for the monitor.
  6. Click Update.
