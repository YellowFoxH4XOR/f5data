Description

On an NGINX [PLus] server with Agent running, a configuration file or files have been removed. The following message may appear in the NGINX Agent logs (/var/log/nginx-agent/agent.log):

time="<timestamp>" level=info msg="Deleting file: /path/to/nginx/file"

Environment

NGINX Instance Manager

Cause

This behavior and log message may occur when:

  • NGINX [Plus] configuration file or files are deleted from NIM Config ui and the configuration is published
  • NGINX [Plus] configuration file or files are deleted directly from a standalone instance (not part of an Instance Group) and the configuration is then published from NIM
  • An instance is added to an existing instance group

Additional Information

In regards to a standalone instance (not a member of an instance group), when NGINX [Plus] configuration file or files are deleted directly from that instance, NIM will be updated of the configuration change, regardless of Agent restart. When that configuration is then published from NIM to the NGINX [Plus] instance, NIM notifies Agent that file or files have been deleted, even though they are already gone the instance. This is because when Agent updates NIM that a file or files have been deleted from the instance, NIM's data plane manager (DPM) is updated of the configuration change. Upon the next Publish event, DPM sends Agent the configuration changes it has, including the previously deleted file or files.
