K000150490: Health monitoring 'bigd' daemon uses only specific SSL settings from the Server SSL profile in HTTPs monitor.

Type
Support Solution
Published
2025-03-20
Updated
2026-05-20
Applies to

  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source

Description

Health monitoring 'bigd' daemon uses only specific SSL settings from the Server SSL profile in HTTPs monitor.  When bigd handles the HTTPS monitor probe, it uses the OpenSSL library to perform the TLS handshake. The critical limitation is: bigd reads only the cipher string from the Server SSL profile. The options list is largely NOT honoured by bigd.

Environment

BIG-IP LTM

Cause

  • The 'Expired Certificate Response Control' and 'Untrusted Certificate Response Control' settings are not utilized by the bigd process. Other settings within the Server SSL profile are only applied when In-TMM monitoring is enabled.
  • Protocol version options (no-tlsv1, no-tlsv1.1, no-tlsv1.2, etc.) are NOT enforced by bigd.
  • Other SSL profile settings (such as SNI, and most workaround flags) are also not utilized by bigd.

Recommended Actions

To take full advantage of Server SSL profile options in node health monitoring, switch to 'In-tmm Monitoring' as described in K11323537 article.
