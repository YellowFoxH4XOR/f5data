Known Issue

When the BIG-IP ASM system blocks a request, the administrator has the option of redirecting the user to a different page or serving a pre-configured page.

The default behavior is to serve a pre-configured error page to the user without a no-cache directive. This default behavior can cause issues if a caching proxy exists between the user and the BIG-IP ASM, as the caching proxy can cache the error page response from the BIG-IP ASM. Caching error pages causes subsequent requests. As such, other users behind the same caching proxy may receive the error page instead of the correct content, regardless of whether the error still exists.

F5 Product Development tracked this issue as CR73776 and it was fixed in BIG-IP ASM 9.4.1. For information about upgrading, refer to the BIG-IP ASM Release Notes.
