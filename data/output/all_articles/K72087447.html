Issue

This article applies to BIG-IP 11.x and later. For information about other versions, refer to the following article:

  • K6065: Error Message: HA Connection with peer <address:port> lost (9.x - 10.x)

Error Message

err tmm[PID#]: 01340002:3: HA Connection with peer [address:port] for traffic-group /Common/[traffic-group_name] lost.

In this error message, note the following:

  • [PID#] is the process ID number of the reporting Traffic Management Microkernel (TMM) process
  • [address:port] is the IP address:port of the mirroring connection to the peer BIG-IP system
  • [traffic-group_name] is the name of the affected traffic group

For example:

err tmm[18353]: 01340002:3: HA Connection with peer 172.16.1.253:32768 for traffic-group /Common/traffic-group-1 lost.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file
Description

This message occurs when the following condition is met:

Note: When the mirroring connection is successfully re-established, the system logs a message similar to the following example:

notice tmm[PID#]: 01340001:5: HA Connection with peer [address:port] for traffic-group /Common/[traffic-group_name] established.

  • The connection used for high availability (HA) features, such as persistence and connection mirroring between peer members of a device group, encounters an interruption.

    Note: This message could be a result of an expected interruption, such as a system restart of a device group member.

Impact

Mirroring information for established connections may not be mirrored to the peer systems. As a result, in the event of a failover, connections may not continue or persist as expected.

Note: If the error message is the result of an expected mirroring connection interruption, you can safely disregard the message.

Recommended Actions

If the error message is the result of an unexpected mirroring connection interruption, you need to determine the cause of the mirroring connection interruption. Performing the following actions may help you identify the cause:

  • Verify the IP addresses used for network mirroring.
  • Verify that port lockdown on the HA Virtual Local Area Networks (VLANs) is set to allow the appropriate ports. For more information, refer to the following articles:
    • K17333: Overview of port lockdown behavior (12.x - 17.x)
    • K13250: Overview of port lockdown behavior (10.x - 11.x)
    • K14894: The BIG-IP system establishes a separate mirroring channel for each traffic group
  • Verify other network devices the HA connection may transit between the device group members.

Verify the IP addresses used for network mirroring

You can verify that each member of the device group is configured with the desired network mirroring IP addresses. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to System > High Availability > Device Connectivity > Network Mirroring.
  3. Verify the Primary Local Mirror Address field contains the expected IP address.
  4. Optional: Verify the Secondary Local Mirror Address field contains the expected IP address.
  5. Repeat steps 1 through 4 for each member of the device group.
