Issue

Error Message

Source Template Has Changed

Message Location

You may encounter this message in the following location:

  • The Configuration utility iApps > Application Services page, under the Template Validity column of the affected application service

In the Template Validity column of the affected application service, where a yellow triangle symbol with an exclamation point (!) character appears, you can use the mouse cursor to pause on the symbol, and a warning message box displays with the Source Template Has Changed warning message.

Description

This message occurs when all of the following conditions are met:

  • The system uses a configured application service.
  • MCPD loads configurations from files instead of a binary image. Examples include:
    • The BIG-IP configuration is rolled forward when the system is upgraded to a newer version.
    • After forcing the MCPD to load the configurations from files per K13030.
    • After making a change in Virtual Edition's hardware. BIG-IP detects the hardware change with the following message.

      notice chmand[<PID>]: 012a0005:5: Hardware/Chassis change detected. Forcing db load from file


For example, if you have a system that runs BIG-IP 17.1.0, and the configuration includes an application service, and then you upgrade to BIG-IP 17.5.1, the error message appears for the affected application service.

Note: Versions affected by this error message are listed in the Applies to (see versions) box, located in the upper-right corner of this article.

Impact

There is no impact. The configuration of the affected application service remains unchanged

Recommended Actions

To clear the error message, you can reconfigure the affected Application Service. To do so, perform the following procedure:

Impact of procedure: The impact of reconfiguring the application service depends on whether you have made additional configuration changes since the application service was initially deployed. If you have made no additional configuration changes, then performing the following procedure should have no negative impact. However, if you have made additional configuration changes outside of the application service, the impact is also affected by the Strict Updates setting. If the Strict Updates setting is enabled (default value), any additional configuration changes that you made will also be applied, and there will be no negative impact. If the Strict Updates setting is disabled, any additional configuration changes that you made may be lost.

  1. Log in to the Configuration utility.
  2. Navigate to iApps > Application Services.
  3. Click the affected application service.
  4. Click the Reconfigure tab.
  5. Without changing the application service configuration, click Finished.
  6. Confirm that the error message is cleared by navigating to iApps > Application Services.

Alternatively, you may use the Traffic Management Shell (tmsh) to reconfigure the affected Application Service. To do so, perform the following procedure:

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Reconfigure the affected Application Service, using the following command syntax:

    modify /sys application service <application_name> execute-action definition

    For example:

    modify /sys application service my_app.app/my_app execute-action definition

  3. Save your changes by typing the following command:

    save /sys config partitions all
