K000149885: Vips not passing traffic - collecting data for further investigation

Type
Knowledge
Published
2025-02-20
Updated
2025-03-14
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000149885

Description

 

Unexpected traffic flow behavior was observed on an F5 BIG-IP LTM device. Packets were sent to the back-end servers, and responses were received; however, application issues persisted when connecting to virtual IPs (VIPs). The issue mitigated after a fail-over to the standby device. 

 

Environment

 

BIG-IP LTM

 

Cause

 

The root cause could not be determined due to insufficient diagnostic data from the affected device's logs during the incident. 

 

Recommended Actions

Gather important data while the issue is occurring to provide to F5 support for further assistance. Below are the steps you can take to gather packet capture, full logs file and QKview from the device experiencing the issue.

  1. If this is SSL traffic, please do the following steps
    1. Enable Debug
      1. tmsh modify sys db tcpdump.sslprovider value enable
      2. tmsh modify sys db log.ssl.level value debug
      3. tmsh save sys config
    2. Start tcpdump
      1. tcpdump -ni 0.0:nnnp -s0 -w /var/tmp/verify_ssl_error.pcap --f5 ssl host XXX.XXX.XXX.XXX -vvv
        1. Note: Replace X's to match IP address of affected virtual server
    3. Generate traffic from a test machine
      1. Stop tcpdump after you generate traffic
    4. Generate a new qkview
    5. Generate a full log export
      1. tar -zcvf /var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)"_logs.tar.gz /var/log/*
    6. Disable Debug
      1. tmsh modify sys db tcpdump.sslprovider value disable
      2. tmsh modify sys db log.ssl.level value warning
      3. tmsh save sys config
    7. Upload QKview, Tar file and pcap to the case
  2. If this is not SSL traffic
    1. Start tcpdump
      1. tcpdump -ni 0.0:nnnp -s0 -w /var/tmp/verify_error.pcap host XXX.XXX.XXX.XXX -vvv
        1. Note: Replace X's to match IP address of affected virtual server
    2. Generate traffic from a test machine
      1. stop tcpdump after you generate traffic
    3. Generate a full log export
      1. tar -zcvf /var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)"_logs.tar.gz /var/log/*
    4. Generate a new QKview
    5. Upload QKview, Tar file and pcap to the case.

 

Additional Information

You can fail-over if you have this device in a device service cluster after the above steps are taken if necessary. Rebooting the affected device may resolve the issue, but this is not guaranteed without identifying the root cause and should be done when it is the standby device if possible.
