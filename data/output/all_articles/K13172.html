Known Issue

The BIG-IP incorrectly marks down nodes and pool members monitored by the Server Message Block (SMB) monitor. This issue occurs when the following condition is met:

  • The SMB monitor is assigned to a pool or a node.

The SMB monitor uses the smb_client utility to connect to hosts when the SMB monitor is assigned to a pool or a node. However, the smb_client utility is removed from the BIG-IP system beginning in BIG-IP 10.1.0 for security enhancements.

Impact

The BIG-IP system fails to distribute traffic to the affected nodes.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H380473 on the Diagnostics > Identified > Medium screen.
  • The pool or node that is assigned an SMB monitor is marked down by the BIG-IP system.

    For example:

    The BIG-IP system logs a message that appears similar to the following example when it marks the pool member down:

    01070638:5: Pool member <ServerIP_port> monitor status down

    The BIG-IP system logs a message that appears similar to the following example when it marks the node down:

    01070640:5: Node <ServerIP> monitor status down

  • The BIG-IP system logs messages that appear similar to the following example to the /var/log/SMB_<name>.<IP address>.<port>.log file:

    execvp() failure: No such file or directory
    read error on pipe: Interrupted system call
    Failed to connect...

    In this error message, note the following:

    • <name> is the name of the SMB monitor.
    • <IP address> is the IP address of the affected pool member or node.
    • <port> is the port number of the affected pool member or node.

Workaround

To work around this issue, you can assign a custom TCP monitor, instead of an SMB monitor, to the affected pool or node. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Monitors > Monitor List.
  3. Click Create to create a new monitor.
  4. Type a name for the monitor in the Name box, for example, mySMBTCPmon.
  5. Click TCP.
  6. Configure the remaining options, as needed, for your environment.
  7. Click Finished to save the changes.
  8. Navigate to Local Traffic > Pools > Pool List.
  9. Click the name of the affected pool.
  10. Click the newly-created TCP monitor in the Available list and move it to the Selected list.
  11. Click Update to save the changes.

Alternatively, you can author an external monitor that uses the smbget utility on the BIG-IP system. For more information about authoring an external monitor, refer to the following Windows File Share Monitor SMB CIFS on DevCentral.
