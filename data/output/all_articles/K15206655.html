Description

When using zonerunner to searching for resource records, and specifying a particular view, the records returned may come from a different view from the one selected.

This can result from an overly broad setting of the "match-clients" setting when creating a new view


Environment

  • Multiple DNS views are defined

  • The views' match-clients setting selects addresses in the 127.10.0.0/16 range, for example through the use of the 'any;' keyword.

Cause

DNS views are created by associating a list of subnets or access lists to the view. Requests from those subnets will return records from the associated view. 

A typical deployment of DNS views would be to select one group of subnets for one view, perhaps a second group of subnets for a second view, and then everything else ('any') for a third view.  Views are processed in the order they are defined, and results are returned from the first matching view 

Zonerunner adds the special acl "zrd-acl-###-###" to each created view, and associates that acl with the source IP 127.10.###.###. When the BigIP administrator selects a particular view, the source address associated with that view is used to make the DNS request to bind, in order to solicit results from that view.

If an acl has been configured in an earlier view than the one selected, which matches the 127.10.x.x range, then bind will return results from that view, even though the BigIP GUI will show the selected view in the table results.    
 
Example - in this example, regardless of the view selected in zonerunner, records will always be returned from the first view "external" due to the presence of "any;" in the match-clients setting. 
 
acl "zrd-acl-000-000" { 127.10.0.0; };
acl "zrd-acl-000-001" { 127.10.0.1; };
 
view "external" {
    match-clients {
        "zrd-acl-000-000";
        any;                              Note: "any" matches all source IP addresses
    };
    zone "example.org." {
        type master;
        file "db.external.example.org.";
        allow-update {
            localhost;
        };
    };
};
 
view "view1" {                           Note: Records will never be returned from this view.
    match-clients {
        "zrd-acl-000-001";
        any;
    };
    zone "example.org." {
        type master;
        file "db.view1.example.org.";
        allow-update {
            localhost;
        };
    };
};

As a result of this configuration, DNS requests, both from clients, and from the zonerunner GUI, will receive records from the external view, as all source addresses match the "any" acl used in that view's match-clients stanza.

Recommended Actions

When creating DNS views in zonerunner, ensure that all DNS views, other than the last,  do not match source addresses in the range 127.10.0.0/16.  Take particular care when using the built-in acls "localhost" and "any", both of which will match 127.10.0.0/16.  The order that DNS views are defined is important, and the zonerunner allows you to re-order DNS views to ensure the correct answer is provided.
 

Determining which view bind used:

 

If zonerunner is displaying records from an unexpected view, you can verify which zone bind returns the results form by enabling query logging (see K14680), viewing the record in zonerunner, and then reviewing /var/log/daemon.log


For example,  the following DNS query matched view "external"
Oct 17 19:55:37 gtm-1212-103 info named[26778]: 17-Oct-2018 19:55:37.091 queries: info: client 127.10.0.0#54341 (www.example.org): view external: query: www.example.org IN A +E (127.0.0.1)
If this is not the view you expected the record to be returned from, then you should review the match-clients setting for each view.
