Description

  • tmsh show sys cluster incorrectly reports the HA status of a blade as "Active" instead of "Standby".

   The issue can be seen with blade 3 in the example below.

(/S2-green-P::Standby)(/Common)(tmos)# show sys cluster

  --------------------------------------------------------------------------------------------------------------------
  | Sys::Cluster Members
  | ID  Address               Availability     State   Licensed    HA           Clusterd      Reason
  --------------------------------------------------------------------------------------------------------------------
    1   10.10.10.10         available        enabled   true      standby          running       Run
    2   10.10.10.11         available        enabled   true      standby          running       Run
    3   10.10.10.12         available        enabled   true      Active           running       Run    <<<<<<<<<<<<<<<<<<<<<<<<<<<<<
    4   10.10.10.13         available        enabled   true      standby          running       Run

 

  • A clusterd partition event is observed in the /var/log/ltm file prior to the issue
err clusterd[28278]: 013a0004:3: Marking slot 3 SS_FAILED due to partition detected on mgmt_bp from peer 2 to local 3
err clusterd[28278]: 013a0004:3: Marking slot 3 SS_FAILED due to partition detected on mgmt_bp from peer 4 to local 3

Environment

  • BIG-IP LTM
  • Viprion
  • Multi Blades
  • After Failover or Change of primary blade

Cause

ID 1306981

Answer/Recommended Actions

Restart the clusterd service on the affected blade:

  1. Identify the blade reporting the incorrect HA state.
    tmsh show sys cluster

  2. SSH directly into the affected blade.

  3. Use the command below to restart the clusterd service.
    bigstart restart clusterd

 

Note: This issue is cosmetic and does not impact traffic processing or actual HA functionality.
