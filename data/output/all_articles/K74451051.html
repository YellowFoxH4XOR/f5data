Topic

You should consider using these procedures under the following conditions:

  • You want to configure SYN cookie protection on a virtual server.
  • You want to configure SYN cookie protection on a VLAN.

Description

The BIG-IP SYN cookie feature protects the system against SYN flood attacks. SYN cookies allow the BIG-IP system to maintain connections when the SYN queue begins to fill up during an attack.

The BIG-IP system uses the Global SYN Check Threshold setting to indicate the maximum number of allowed connections in the SYN queue. If that limit is reached, the BIG-IP system responds to SYN requests by sending the SYN-ACK response, containing an encoded secret, back to the client. The system then discards the SYN queue entry and waits for the ACK from the client.

The software-syn-cookie and hardware-syn-cookie options are deprecated and replaced with the syn-cookie-enable option, for more information refer to K00164450: The syn-cookie-enable option replaces SYN Cookie Protection options.

You can configure SYN cookie protection on a BIG-IP system using the following methods:

  • Global SYN cookie check threshold per TMM—Configure the global SYN cookie activation threshold per Traffic Management Microkernel (TMM).
  • Virtual server-based SYN cookie protection—Configure the SYN cookie activation threshold per virtual server.
  • Protocol profile-based SYN cookie protection—Configure SYN cookie protection per protocol profile in the TCP and FastL4 profiles.
  • VLAN-based SYN cookie protection—On certain FPGA platforms, enable hardware SYN cookie protection per Virtual Local Area Network (VLAN) instead of per virtual server.

    Use the per-VLAN SYN cookie protection option if you want to enable SYN cookies on all virtual servers and secure network address translation (SNATs) on one or more VLANs. You can use the Hardware VLAN SYN Cookie Protection global setting to enable and disable the feature on all relevant VLANs, rather than reconfiguring every VLAN when you want to enable or disable the feature for those VLANs.

Modify the Global SYN Check Threshold setting

The Global SYN Check Threshold setting specifies the number of new or untrusted TCP connections that can be established before the system activates the SYN Cookies authentication method for subsequent TCP connections, system wide. You specify the global SYN cookie activation threshold per TMM here. To modify the Global SYN Check Threshold setting, perform the following procedure:

Use the Configuration utility to modify the Global SYN Check Threshold

Note: If your BIG-IP system is not licensed and/or provisioned with Local Traffic (LTM), the System > Configuration > Local Traffic menu may not show up in the Configuration utility. However, you can still use the tmsh utility to modify the setting.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Local Traffic > General.
  3. Under Properties, enter the value you want for Global SYN Check Threshold.
  4. Select Update.

Use tmsh to modify the Global SYN Check Threshold

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the Global SYN Check Threshold, use the following command syntax:

    modify /ltm global-settings connection global-syn-challenge-threshold <value>

    For example, to change the Global SYN Check Threshold to 16000, enter the following command:

    modify /ltm global-settings connection global-syn-challenge-threshold 16000

Modify the Default Per Virtual Server SYN Check Threshold setting

You can use the Default Per Virtual Server SYN Check Threshold setting to modify the default value of per-virtual server SYN Cookie activation threshold per chassis.

Note: The default-vs-syn-challenge-threshold value needs to account for the number of TMMs on the unit. For example if the BIG-IP is running 4 TMMs, then the configured value for default-vs-syn-challenge-threshold for each virtual will be default-vs-syn-challenge-threshold / number of TMMs = per virtual threshold to view the count of TMMs on the unit, you can run the following command:
tmsh show sys tmm-info | grep "TMM Count"

You can use the following procedure to view and modify the default value for this setting:

Using the Configuration utility to modify the Default Per Virtual Server SYN Check Threshold

Note: If your BIG-IP system is not licensed and/or provisioned with Local Traffic (LTM), the System > Configuration > Local Traffic menu may not show up in the Configuration utility. However, you can still use the tmsh utility to modify the setting.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Local Traffic > General.
  3. To change the default value, enter the value you want for Default Per Virtual Server SYN Check Threshold under Properties.
  4. Select Update.

Use tmsh to modify the Default Per Virtual Server SYN Check Threshold

Impact of procedure: Performing the following procedure should not have a negative impact on your system

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view the default value for Default Per Virtual Server SYN Check Threshold, use the following command:

    list ltm global-settings connection default-vs-syn-challenge-threshold

    The system displays output similar to the following example:

    ltm global-settings connection {
        default-vs-syn-challenge-threshold infinite
    }

  3. To modify the Default Per Virtual Server SYN Check Threshold default value, use the following command syntax:

    modify ltm global-settings connection default-vs-syn-challenge-threshold <value>

    For example, to change the Default Per Virtual Server SYN Check Threshold to 128, enter the following command:

    modify /ltm global-settings connection default-vs-syn-challenge-threshold 128


Modify SYN cookie protection for a protocol profile

The setting SYN Challenge Handling in the TCP and FastL4 profiles is used to specify the default number of embryonic connections (if no denial-of-service [DoS] profile is associated) that are allowed on any virtual server, before SYN Cookie challenges are enabled for that virtual server.

To modify the SYN cookie protection setting in the protocol profiles, perform the following procedure:

Use the Configuration utility to modify the SYN cookie protection for a protocol profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Protocol.
  3. Select either TCP or the FastL4 profile currently assigned to the virtual server to which you want to allow SYN cookie protection.
  4. Specify an appropriate setting for the SYN Challenge Handling:

    a: Nominal: Initiates SYN cookie challenges after a relatively low number of embryonic connections. This is the default setting.

    b: Challenge and Remember: Specifies whether SYN packets subsequent to a successful challenge response, from the same Source IP address, should be challenged or allowed to pass unchallenged (up to some timeout period). Enabling this feature prevents hardware acceleration for SYN challenges, but may be needed/useful in some deployments (for example, direct server return (DSR) mode or when no hardware acceleration is available). Essentially, Challenge and Remember adds the packet's TCP address to the SYN Cookie White List.

    c: Disable Challenges: Does not initiate SYN Cookie challenges, regardless of the number of embryonic connections.

  5. Select Update.

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

Use tmsh to modify the SYN cookie protection for a protocol profile

You can use the tmsh syn-cookie-whitelist option to modify the Syn Challenge Handling setting for TCP or a FASTL4 profile. By default, the syn-cookie-whitelist option is disabled; it means the Syn Challenge Handling is set to Nominal. You can use the following procedure to enable this option that sets the setting to Challenge and Remember:

Impact of procedure: Performing the following procedure should not have a negative impact on your system

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the syn-cookie-whitelist option, use the following command syntax:

    modify /ltm profile <protocol_profile> <profile_name> syn-cookie-whitelist default-value | disabled | enabled

  3. For example, to enable the syn-cookie-whitelist settings for the FastL4 profile named test_fastl4 , enter the following command:

    modify /ltm profile fastl4 test_fastl4 syn-cookie-whitelist enabled

  4. Save the configuration by entering the following command:

    save /sys config

Modify the syncookie-enable option for a protocol profile

The syn-cookie-enable option enables SYN cookie protection for the protocol profile. The option is available in tmsh and is enabled by default. To enable the option, perform the following procedure.

Impact of procedure: Performing the following procedure enables SYN cookie protection for the specified protocol profile.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Use the following command syntax to view the status of the syn-cookie-enable option:

    list /ltm profile <protocol_profile> <profile_name> syn-cookie-enable

    For example, you can use the following command to view the setting for the FastL4 profile named test_fastl4:

    list /ltm profile fastl4 test_fastl4 syn-cookie-enable

    The system displays output similar to the following example:

    ltm profile fastl4 test_fastl4 {
        syn-cookie-enable enabled
    }

    You can use the following procedure to enable the syn-cookie-enable option if it is not already enabled:

  3. To modify the syn-cookie-enable option for a protocol profile, use the following command syntax:

    modify /ltm profile <protocol_profile> <profile_name> syn-cookie-enable default-value | disabled | enabled

    For example, to enable the syn-cookie-enable settings for the FastL4 profile named test_fastl4 , enter the following command:

    modify ltm profile fastl4 test_fastl4 syn-cookie-enable enabled

  4. Save the configuration by entering the following command:

    save /sys config

Modify a VLAN to configure global hardware SYN cookie protection

On certain FPGA platforms, you can enable the hardware SYN cookie protection per VLAN instead of per virtual server.

Use the Configuration utility to modify the hardware SYN cookie protection for a VLAN

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility
  2. Go to Network > VLANs
  3. Select the desired VLAN in the Name column
  4. Select Advanced from the Configuration list
  5. Select the check box for the Hardware SYN Cookie setting.

    Note: When you enable this setting, the BIG-IP system triggers hardware SYN cookie protection for this VLAN. Enabling this setting causes additional settings to appear. These settings appear on specific BIG-IP platforms only.

  6. For the Syncache Threshold setting, enter the desired value
  7. For the SYN Flood Rate Limit setting, enter the desired value
  8. Select Update

Use tmsh to modify the hardware SYN cookie protection for a VLAN

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view the default value of the hardware-syncookie setting of a VLAN, use the following command syntax:

    list /net vlan <VLAN name> hardware-syncookie

    For example, you can use the following command to view the setting for the internal VLAN:

    list /net vlan internal hardware-syncookie

    The system displays an output similar to the following example:

    net vlan internal {
        hardware-syncookie disabled
    }

  3. To modify the default value of the hardware-syncookie setting of a VLAN, use the following command syntax:

    modify /net vlan <VLAN name> hardware-syncookie <enabled | disabled>

    For example, you can use the following command to enable the setting for the internal VLAN:

    modify /net vlan internal hardware-syncookie enabled

  4. To view the default value of the syncache-threshold setting of a VLAN, use the following command syntax:

    list /net vlan <VLAN name> syncache-threshold

    For example, you can use the following command to view the setting for the internal VLAN:

    list /net vlan internal syncache-threshold

    The system displays an output similar to the following example:

    net vlan internal {
        syncache-threshold 6000
    }

  5. To modify the default value of the syncache-threshold setting of a VLAN, use the following command syntax:

    modify /net vlan <VLAN name> syncache-threshold <integer value>

    For example, you can use the following command to modify the value of the syncache-threshold setting to 7000 for the internal VLAN:

    modify /net vlan internal syncache-threshold 7000

  6. To view the default value of the syn-flood-rate-limit setting of a VLAN, use the following command syntax:

    list /net vlan <VLAN name> syn-flood-rate-limit

    For example, you can use the following command to view the setting for the internal VLAN:

    list /net vlan internal syn-flood-rate-limit

    The system displays an output similar to the following example:

    net vlan internal {
        syn-flood-rate-limit 1000
    }

  7. To modify the default value of the syn-flood-rate-limit setting of a VLAN, use the following command syntax:

    modify /net vlan <VLAN name> syn-flood-rate-limit <integer value>

    For example, you can use the following command to modify the value of the syn-flood-rate-limit setting to 2000 for the internal VLAN:

    modify /net vlan internal syn-flood-rate-limit 2000

  8. To save the changes, enter the following command:

    save /sys config

Configure global hardware VLAN SYN cookie protection settings

By default, the global hardware VLAN-based SYN cookie setting is enabled on the BIG-IP system.

Note: If your BIG-IP system is not licensed and/or provisioned with Local Traffic (LTM), the System > Configuration > Local Traffic menu may not show up in the Configuration utility. However, you can still use the tmsh utility to modify the setting.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Use the Configuration utility to enable the global hardware VLAN SYN cookie protection setting

To make sure this setting is enabled on your BIG-IP system, perform the following procedure using the Configuration utility:

  1. Log in to the Configuration utility

  2. Go to System > Configuration > Local Traffic > General

  3. To enable Hardware VLAN SYN Cookie Protection settings, select the check box

  4. Select the Update

Use tmsh to enable the global hardware VLAN SYN cookie protection setting

To make sure this setting is enabled on your BIG-IP system, perform the following procedure using the tmsh utility:

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable the global hardware VLAN SYN cookie protection on the BIG-IP system, enter the following command:

    modify ltm global-settings connection vlan-syn-cookie enabled

Use the Configuration utility to disable global hardware SYN cookie protection

  1. Log in to the Configuration utility

  2. Go to System > Configuration > Local Traffic > General

  3. To  disable Hardware VLAN SYN Cookie Protection settings, de-select the check box

  4. Select the Update

Use tmsh to disable the global hardware VLAN SYN cookie protection

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To disable the global hardware VLAN SYN cookie protection on the BIG-IP system, enter the following command:

    modify ltm global-settings connection vlan-syn-cookie disabled

Verify the SYN cookie status for a virtual server

You can monitor the SYN cookie status for a virtual server and determine whether the system has activated hardware or software SYN cookies by checking the Syncookie Status value for the virtual server. The possible values are as follows:

Syncookie Status

Description

Inactive

The Global SYN Check Threshold value has not been reached, and the SYN cookie feature is not currently active for the virtual server
Note: The tmsh utility uses not-activated to indicate this status.

Full Hardware

The Global SYN Check Threshold has been reached, and the SYN cookie feature is currently active for the virtual server. The system uses the HSB chip to process the SYN cookies

Software Syncookie Only

The Global SYN Check Threshold has been reached, and the SYN cookie feature is currently active for the virtual server. The system uses the software to process the SYN cookies

To verify the SYN cookie status for the virtual server, perform one of the following procedures:

Use the Configuration utility to verify the SYN cookie status for a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.

  2. Go to Local Traffic > Virtual Servers.

  3. Select the virtual server name.

  4. Under General Properties, verify the current SYN cookie status.

Use tmsh to verify the SYN cookie status for a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To verify the SYN cookie status for a virtual server, use the following command syntax:

    show /ltm virtual <virtual_server_name> all-properties

    For example, to show the virtual server status for the virtual server named MyVirtual, enter the following command:

    show /ltm virtual VIP-syn-cookie-test all-properties

Review SYN cookie threshold log messages

The BIG-IP system may log one or more error message to the /var/log/ltm file that relates to SYN cookie protection. To review the log messages, run the cat /var/log/ltm command from the BIG-IP command line. SYN cookie protection appears as follows:

  • When the SYN Check Activation Threshold is exceeded for a virtual server, the system logs an error message similar to the following example:

    warning tmm5[18388]: 01010038:4: Syncookie counter 66 exceeded vip threshold 64 for virtual = 10.0.11.115:80

  • When hardware SYN cookie mode is active for a virtual server, the system logs an error message similar to the following example:

    notice tmm5[18388]: 01010240:5: Syncookie HW mode activated, server = 10.11.16.238:80, HSB modId = 1

  • When hardware SYN cookie mode is de-activated for a virtual server, the system logs an error message similar to the following example:

    notice tmm5[18388]: 01010241:5: Syncookie HW mode exited, server = 10.11.16.238:80, HSB modId = 1 from HSB
