Description

SNMP is not working on F5OS-A.

 

Environment

  • F5OS-A
  • rSeries
  • SNMP

Cause

  • management port 161 is not opened by default, needed to add the server in allow lists. Please follow: rSeries F5OS-A SNMP Monitoring and Alerting

 

Recommended Actions

If it is not still working

1. take tcpdump on SNMP server, and figure it out where it is sending

Sometimes there is switch/firewall etc between SNMP server and F5O, and those are dropping the packet. Make sure it arrives to F5OS.

2. Once it is confirmed the switch and firewall are sending the packet from the SNMP server to F5OS, then take tcpdump on F5OS on bash mode.

tcpdump -ni mgmt0-system port 161 or port 162 -w /var/tmp/snmp.pcap
NOTE: R2R4 does not have ability to take tcpdump on F5OS: K000132908: [F5OS-A] running tcpdump in bash shell on rSeries r2000/4000 

3. while above is running, on SNMP server, take tcpdump on the SNMP server or switch/Firewall. and then initiate SNMP request.

4. Once all tcpdump is captured and terminated, create qkview on F5OS. 

and then escalate the case to F5 Support.
