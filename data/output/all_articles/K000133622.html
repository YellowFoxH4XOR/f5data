User Experience Changes When Performing Endpoint Inspection

With the change in 'Edge Client for Mac' as a result of K000132932 there are a number of notable changes of behaviour. When running on Mac OS 13.3 or later, Edge Client on now uses the F5 Endpoint Inspection app.

The article K15302:  "Understanding BIG-IP Edge Client Component Update behavior for Windows, macOS, and Linux CLI" describes how the Component Update setting can be used to block the client applications auto-update capability, and the Enterprise then needs to have a system for manually or automatically (MDM) deploying the client software to end devices.
As a result of increasing security by Apple and F5 there have been a number of changes in the number of dialogs the end user needs to interact with.

Change 1 - Trusted Sites prompt when performing endpoint inspection

Previously with Edge Client when it called the Plugin to perform the inspection check, it was using a site location from the bookmarked sites built into Edge Client. The Endpoint Helper App runs as a separate process and has a different way of keeping a list of "Trusted Sites". It keeps a list of sites, and when connecting to a new site it presents this dialog:



Selecting the first option adds the site to the file list, and so you are not prompted again for the same site. Selecting the second option allows the inspection to proceed, and does not remember the site. The third option does not perform the inspection, and so the policy check will fail and the connection will be blocked. We recommend the users to click on "Always allow inspection from this site" option, doing this will not present the prompt again unless users switch to a new VS which is not presented in the trusted_sites.xml file.

If you deploy the Edge Client to end devices with a MDM, you can pre-populate this file so the end users do not have to make a selection.
Workaround: Adding APM virtual servers to the trusted sites will suppress the prompt. The trusted_sites.xml file should be located in /Users/<username>/Library/F5Networks/trusted_sites.xml. If the trusted_sites.xml file is corrupted or located elsewhere, such as in the /Library/F5Networks/ directory, the prompt will be shown to the user. Selecting the Always allow inspection from this site option creates a new /Users/<username>/Library/F5Networks/trusted_sites.xml file.

<?xml version="1.0" encoding="utf-8"?>
<version>1.0</version>
<sites>
<site>http://VIRTUAL_SERVER_ADDRESS1</site>
<site>http://VIRTUAL_SERVER_ADDRESS2</site>
</sites>

Change 2 - Downloading endpoint inspection updates

Previously the Endpiont Inspection was done in the background,without notification, with the Helper Apps a dialog like this is shown (note that the Component Update setting has no effect on updating the Endpoint Inspection (aka OPSWAT OESIS sdk)

Workaround: Customers can preinstall EPSEC package on client machines after deploying the BIGIP EHF by following the steps described in "Additional Information" section of https://my.f5.com/manage/s/article/K26349235

Fix Plan: a future EHF will revert the previous behaviour, and perform these updates without a progress dialog.

Change 3  - EPI Helper Apps Installed before Endpoint Inspection is Triggered

When endpoint inspection helper applications are already installed before Edge Client launches and requests endpoint inspection there will not be any additional prompts. Users may notice a minor change as the endpoint inspection is carried in a separate helper application which will launch and then quit, but there is no significant change in user experience as they see the status of the checks in Edge Client. Change 4 - EPI Helper Apps Not Installed by the time Endpoint Inspection is Triggered

When Engineering Hotfix with fix is deployed but endpoint inspection helper application is not installed on client machine users will see noticeable behavior changes as they are prompted with a message box to download endpoint inspection helper applications.

 

When Users clicks on download, there will be an external web browser window that is opened to download helper apps. Download progress can be monitored in the progress bar (highlighted in top right corner)

If your default browser is set to chrome/edge/firefox you will see a different details but the installer will be in your usual download file location.

 

Once the download is complete, users can locate mac_f5epi.pkg file in downloaded folder and can install it by double clicking. Once the installation is complete users can click on "More Options" button shown on below screen.
