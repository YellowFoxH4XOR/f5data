Known Issue

Configuration synchronization (ConfigSync) may fail when using the management IP address.

This issue occurs when all of the following conditions are met:

  • BIG-IP Sync-Only or Sync-Failover device group members are configured to use the management IP addresses for ConfigSync.
  • Imported external file types similar to the following need to be synchronized to the other device group members:
    • External data group files
    • External monitor program files
    • SSL certificate files
  • The ConfigSync operation attempts to sync the imported file object.

When performing a ConfigSync by way of the management IP address, the rsync process is unable to connect and transfer files.

Note: By default, the management address is not available for ConfigSync communication. For the BIG-IP system to use the management IP address for synchronization, you must have manually enabled the configsync.allowmanagement db variable.

Impact

BIG-IP Sync-Only or Sync-Failover device group members are unable to sync configurations.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H417287 on the Diagnostics > Identified > Low screen.
  • ConfigSync reports as failed with a Sync Summary that appears similar to the following:

Workaround

To work around this issue, you must configure the device group members to use a self IP address for ConfigSync traffic. F5 recommends that you use the self IP address of an internal VLAN for ConfigSync traffic. To do so, perform the following procedure:

Impact of workaround: None. The procedure must be performed on each member of the Sync-Failover device group.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. List the devices configured for the affected device group by using the following command syntax:

    list cm device-group <device_group_name> devices

    For example:

    list cm device-group ltm-ha-group devices

    A list of devices in the device group is displayed and appears similar to the following example:

    cm device-group ltm-ha-group {
    devices {
    ltm1.example.com { }
    ltm2.example.com { }
    }
    }

  3. Update the ConfigSync IP address for each of the devices listed in Step 2. To do so, use the following command syntax:

    modify cm device <device_name> configsync-ip <self_IP_address>

    For example, to update the ConfigSync IP address for the example in step 2, you would type commands similar to the following:

    modify cm device ltm1.example.com configsync-ip 172.16.10.1
    modify cm device ltm2.example.com configsync-ip 172.16.10.2

  4. Disable the configsync.allowmanagement db key by typing the following command:

    modify sys db configsync.allowmanagement value disable

  5. Save the configuration by typing the following command:

    save /sys config

  6. Repeat this procedure for each member of the affected device group.
  7. After you have completed this procedure on all members of the affected device group, log in to the tmsh utility of the device group member that has the desired configuration.
  8. Synchronize the configuration to other members of the device group by using the following command syntax:

    run /cm config-sync to-group <device_group>

    For example:

    run /cm config-sync to-group ltm-ha-group
