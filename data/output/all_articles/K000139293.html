Known Issue

VELOS system controller and chassis partition software may incorrectly start allocating the same MAC addresses to different objects in chassis partitions. In the worst case, this can result in multiple tenants using the same MAC addresses on the same VLAN, resulting in traffic disruptions for those tenants.

This issue occurs when the following conditions are met:

  • You are running F5OS-C 1.6.x software on the F5 VELOS system controllers.
  • The system controllers restarted simultaneously, such as during an out-of-service upgrade or power outage.
  • The F5 VELOS system controllers then fail over.

After this occurs, the VELOS system controller loses track of which MAC addresses have been allocated to chassis partitions, setting up a situation where creating new tenants or chassis partitions may re-use MAC addresses already allocated to objects on the system. Once a system is affected, upgrading to a version or engineering hotfix (EHF) that contains the fix for ID1576241 does not resolve the issue; manual intervention is also required to fix the issue.

Impact

Duplicate MAC addresses on the same VLAN segment cause a traffic disruption.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe logs similar to the following in the /var/log_controller/velos.log file:

    vcc-partition-agent[10]: priority="Warn" version=1.0 msgid=0x2301000000000025 msg="Partition UUID verification shows stale partition data, remove op data for partition:" partitionId=2
    vcc-partition-agent[10]: priority="Warn" version=1.0 msgid=0x2303000000000024 msg="Error MAC and offset from basemac not from this pool" offset=133 mac="14a9d02670cb".
    vcc-partition-agent[10]: priority="Err" version=1.0 msgid=0x2303000000000004 msg="Error restoring MAC allocation from partition_macs database entries" mac="14:a9:d0:26:70:1c".
    vcc-partition-agent[10]: priority="Crit" version=1.0 msgid=0x2303000000000019 msg="Error duplicate MAC not in free pool, already allocated" mac="14:a9:d0:26:70:1d".

  • You observe logs similar to the following in the partition logs /var/F5/partition<#>/log/velos.log:

    network-manager[14]: nodename=controller1 priority="Err" version=1.0 msgid=0x1802000000000011 msg="Attempt to free mac not in allocated block" MAC="00:0a:49:xx:xx:xx"

  • You observe duplicate MAC addresses in the same VLAN.

Symptoms of this issue are more likely to occur under either of the following conditions:

  • You configure multiple chassis partitions on the F5 VELOS system.
  • Tenants on the F5 VELOS system are allocated with either Small, Medium, or Large MAC Block Sizes, instead of the default setting of One, which allocates a single MAC address to a tenant. For more information, refer to K000133655: MAC address assignment in VELOS and rSeries systems.

Workaround

If a system is affected by this issue and has allocated duplicate MACs, there is not a straightforward recovery mechanism. Remediation requires a maintenance window and F5 Support will need to assist you. The chassis partitions need to be rebuilt, which involves deleting and recreating tenants.

You can check to see if your system is affected by this issue by downloading and running a diagnostic script on the VELOS system controller. The script checks for instances of duplicate MAC addresses and reports the findings. To download and run the script, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the F5 VELOS system controller CLI as root.
  2. Download the diagnostic script using the following command:
    Note: The script can only be run on F5OS-C 1.6.0 or later, where the MAC block size allocation feature was first introduced. The state cannot be fully checked on older versions. Do not use the script on prior versions.

    curl -s https://raw.githubusercontent.com/askf5/K000139293/main/id1576241-velos-duplicate-macs.py -O

  3. Enter the following command to run the script:

    python3 ./id1576241-velos-duplicate-macs.py
