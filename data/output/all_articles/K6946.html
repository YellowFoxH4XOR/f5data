Known Issue

This is the result of a known issue. Email announcements are not sent to FirePass users in the first master group in the drop-down menu for the To: field on the Users: Announce page. This issue only affects FirePass controllers that are not licensed for Desktop Access. A FirePass controller that is not licensed for Desktop Access does not have a Desktop Access link in the main menu on the left side of the Admin Web UI. The Desktop Access feature has been deprecated, so newer FirePass controllers will not be licensed for Desktop Access.

When an administrator needs to contact FirePass users, email can be sent from the FirePass administrative account to all FirePass users, or to users in a specific master group (assuming the user has an email address associated with their account). The To: field on the Users: Announce page provides a drop-down menu to select either All FirePass users, or a specific master group.

If the FirePass controller is not licensed for Desktop Access, and you select the first master group listed after the ----- Users from the groups ------ delimiter, the email will not be sent, and no error message will be generated. If you perform a network packet trace, you will see no packets from the FirePass to the SMTP server configured on the Device Management: Configuration: SMTP Server page.

F5 Product Development tracked this issue as CR73305, and it was fixed in FirePass version 6.0.1. For information about upgrading, refer to the FirePass release notes.
