Issue

There are two common reasons for SIP persistence failure:

  • Call-ID Field with variable case
  • Header IP Address issues

Call-ID Field

Many clients send a Call-ID header. Some clients (for example, Pingtel version 1.2.4) send a Call-ID header that is of variable case. This would include content such as: Call-Id (notice the lower-case d).

In BIG-IP version 1.8.3 through 4.2 PTF-04, SIP persistence was case-sensitive and a Call-ID field containing variable case would not function correctly. (This issue was tracked as CR21338.) If SIP persistence is failing due to this issue, update BIG-IP to version 4.2 PTF-05 or later.

Header IP Address

Some servers (for example, the Cisco AS5300) verify that the IP addresses throughout the request header (within the UDP payload of the packet) correspond to the address on which the server is receiving the packet. These servers expect the To: field to contain their server's IP address; however, if you are load balancing SIP, the To: field will contain the virtual server address. This will cause the server to reject the connection.

If you are experiencing SIP persistence issues due to this problem, you can use a hostname instead of an IP address; therefore, instead of connecting to the virtual server with an IP address such as: SIP://192.168.1.1/, you would create an entry in DNS that refers to this address.

For example:

siphost.domain.com

The DNS entry will direct the client to connect to SIP://siphost.domain.com/, instead of directly to the IP address.

Alternatively, you can simulate the same behavior by adding an entry to the client's hosts file.

Note: On UNIX machines the hosts file is commonly located in /etc/hosts. On Windows PCs, it is commonly located in C:\WINNT\System32\drivers\etc\hosts.

The format for this file is as follows, where the IP address is followed by any number of spaces or tabs (white space), and the hostname you want to associate with the IP address:

192.168.1.1 siphost.domain.com

Once you have saved this information into the hosts file, refer to this hostname on your client as though it existed in DNS.

For example:

SIP://siphost.domain.com/

Following is an example SIP INVITE request header as a general reference:

INVITE sip:13122249505@10.20.16.100 SIP/2.0
From: sip:4444@10.30.0.27;tag=1c41
To: sip:13122249505@10.20.16.100
Call-Id: call-1020201058-6@10.30.0.27
Cseq: 1 INVITE
Contact: sip:4444@10.30.0.27
Content-Type: application/sdp
Content-Length: 193
Accept-Language: en
Allow: INVITE, ACK, CANCEL, BYE, REFER, OPTIONS, NOTIFY, REGISTER, SUBSCRIBE
Supported: sip-cc, sip-cc-01, timer
User-Agent: Pingtel/1.2.4 (WinNT)
Via: SIP/2.0/UDP 10.30.0.27
