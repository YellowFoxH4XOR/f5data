K86026120: The SNAT Automap self IP address selection for different traffic groups

2021-11-16

Applies to

Description

By default BIG-IP on have one Traffic Group which is traffic-group-1.

When client traffic goes to the Virtual Server VIP, SNAT Automap will select the best self IP address based on K7336.

However when a Self IP's Traffic Group has been changed, Self IP selection will not follow K7336. Navigate to Network  >  Self IPs to change the Self IP's Traffic Group.

This article explains SNAT Automap Self IP address selection when the Virtual Server's Virtual Address and Self IP address are configured to a different Traffic Group.

Environment

  • BIG-IP
  • Self IP Traffic Group has been changed
  • Virtual Server's Virtual Address is traffic-group-1

Cause

SNAT Automap will only use a floating Self IP address which is in the same Traffic Group as the Virtual Server's VIP. The decision is otherwise based on K7336.

An issue will arise when changing the Self IP address' Traffic Group but Virtual Server's Virtual Address did not change the Traffic Group.
For example:

  1. Self IP A is selected as SNAT Automap for Virtual Server Test-A and both are using the same Traffic Group which is traffic-group-1.
  2. Self IP A' Traffic Group changes to traffic-group-2.
  3. Virtual Server Test-A will no longer select Self IP A for SNAT Automap but will use another Self IP in traffic-group-1.
  4. This might cause an outage for the application as the SNAT Automap is using another Self IP address which might not be able to communicate with the pool member (node).

When using multiple Traffic Groups, production traffic can improve load distribution across the device group. In other words, more than one BIG-IP device can process traffic at the same time.


SNAT Automap will use Self IPs of the same Traffic Group to ensure the client to Virtual Server's ARP request and floating IP (Self IP address) to pool member (node) are handled by the same BIG-IP device (Traffic Group). Only Active BIG-IP device of a traffic group answers the packet of the Virtual Server's VIP and floating IP (Self IP address).
 

Recommended Actions

If there is an issue after changing the Self IP's Traffic Group, you need to change the Virtual Address Traffic Group of the impacted Virtual Server resolve it.

  1. Login to the Configuration Terminal
  2. Navigate to Local Traffic > Virtual Servers > Virtual Address List
  3. Click on the Virtual Address associated with the impacted Virtual Server
  4. Under Traffic Group select the newly created Traffic Group.
  5. Click Update
