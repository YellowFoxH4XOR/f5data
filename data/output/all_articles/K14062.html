Issue

Error Message

SNAPD-0-ERR-SNAP_CONN_ERR:: Connection error when trying to connect to external filer <filer name>. The error was 'The request timed out on the server. Reason: The WS-Management service cannot complete the operation within the time specified in OperationTimeout. HTTP Status: 500.'.

In this error message, note the following:

  • <filer name> is the remote filer that the ARX system is attempting to contact to initiate the snapshot request.

For example:

SNAPD-0-ERR-SNAP_CONN_ERR:: Connection error when trying to connect to external filer 'example_filer'. The error was 'The request timed out on the server. Reason: The WS-Management service cannot complete the operation within the time specified in OperationTimeout. HTTP Status: 500.'.

Message Location

You may encounter this message in the following locations:

  • ARX syslog
  • ARX traplog

Description

ARX systems use Windows Remote Management (WinRM) to create, list, and remove snapshots from Windows servers. Due to the complexity of the requests, the ARX WinRM request may exceed the timeout configured on the windows filer, causing the request to fail.

This message occurs when all of the following conditions are met:

  • The ARX system initiates a WinRM command to invoke a snapshot on the Windows filer.
  • The default WinRM timeout setting on the Windows filer is 60 seconds.

You will view additional log messages that appear similar to the following example, along with the identified error message:

SNAPD-0-ERR-SNAP_CREATE_FAILED:: Snapshot create failed for namespace [Example-NS] volume [/data] snapshot rule [snap-data-daily] virtual snapshot [snap-data-daily0].

SNAPD-0-ERR-SNAP_CREATE_FAILED_MSGS:: Snapshot create failed message for namespace [Example-NS] volume [/data] snapshot rule [snap-data-daily] virtual snapshot [snap-data-daily0] message [Connection error when trying to connect to external filer 'Example-Filer'. The error was 'The request timed out on the server. Reason: The WS-Management service cannot complete the operation within the time specified in OperationTimeout.   HTTP Status: 500.'.]).

SNMP TRAP: snapshotOpFail (585) create operation, nsp 'Example-NS', vol '/data', snapshot rule 'snap-data-daily': snapshot create operation for this volume failed

Impact

The ARX system will fail to create the snapshots, causing a lack of updated snapshot copies that the system can retrieve filers/folders from.

Recommended Actions

F5 recommends that you increase the WinRM timeout value from 60 seconds to 300 seconds on the Windows filer.

  • To check the currently configured timeout setting, enter the following command on the Windows filer CLI:

    winrm get winrm/config
  • Review the output for the MaxTimeoutms= option

    Note: The default the entry is MaxTimeoutms = 60000.
  • To set the WinRM timeout setting to 300 seconds, enter the following command on the Windows filer CLI:

    winrm set winrm/config@{MaxTimeoutms=300000}
