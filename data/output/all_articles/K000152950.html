Description

Sometimes an application works fine when accessed directly, but fails or behaves unexpectedly when the traffic goes through BIG-IP. This usually indicates a configuration, network, or server communication issue.

Environment

  • BIG-IP LTM

Cause

The most common reasons are:

  • Incorrect virtual server or pool configuration (IP/port mismatch, wrong profiles).
  • Pool members marked down due to failed health monitors.
  • Routing or VLAN misconfiguration preventing return traffic.
  • Source address translation (SNAT) not configured properly.
  • SSL handshake issues caused by missing or mismatched certificates.
  • Application server issues unrelated to BIG-IP.
  • Security profiles (ASM, DoS, Bot Defense) blocking traffic.

Recommended Actions

1. Verify Virtual Server configuration: Ensure the virtual server is configured to match the application requirements.

  • Confirm the destination IP/port matches client requests.
  • Check if the correct profiles (TCP, HTTP, SSL, etc.) are attached.
  • Validate SNAT settings (automap, pool, or none) based on your environment.

2. Check Pools and Members: The most common reason for failure is that pool members are down or unreachable.

  • Make sure the virtual server points to the correct pool.
  • Confirm health monitors are correct and that servers respond properly.
  • Validate member status:
    • tmsh show ltm pool <pool-name>

3. Review Network Configuration: Misconfigured VLANs or routing can stop traffic from reaching the backend.

  • Verify the virtual server is listening on the correct VLAN.
  • Check static routes or default gateway for proper server-side reachability.
  • Confirm no duplicate IP addresses exist on the network.

4. Capture Traffic: A packet capture helps confirm whether BIG-IP is passing traffic to the server.

tcpdump -ni 0.0:nnn host <client-ip> or host <server-ip> -w /var/tmp/capture.pcap

If the traffic is encrypted, please follow the steps in this article to capture and decrypt the traffic: K31793632: Creating a decrypted tcpdump capture without using an iRule

5. Check the logs: Review /var/log/ltm for errors or dropped traffic messages.

6. Check Firewalls: Firewalls upstream (before BIG-IP) or downstream (between BIG-IP and servers) can silently block or drop traffic.

7. Validate Application Servers: Sometimes the issue is unrelated to BIG-IP. Test the servers directly. If the issue occurs outside BIG-IP, troubleshoot the server or application.

8. If ASM is provisioned: check and disable ASM, DoS, or Bot Defense profiles temporarily, then review logs and tune policies if they block traffic.
