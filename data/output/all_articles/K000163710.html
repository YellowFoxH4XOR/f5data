Security Advisory Description

BIND may accept incorrect child-zone NSEC3 records as valid, which could allow an attacker to forge authenticated NXDOMAIN responses. This issue affects BIND 9 versions 9.18.0 through 9.18.50, 9.20.0 through 9.20.24, 9.21.0 through 9.21.23, 9.11.3-S1 through 9.18.50-S1, and 9.20.9-S1 through 9.20.24-S1. (CVE-2026-10723)

Impact

This vulnerability allows an attacker to cause BIND to accept an invalid child-zone NSEC3 record as proof that a name in a sibling zone does not exist. When BIG-IP DNS is configured as a recursive resolver with BIND enabled, an attacker controlling or spoofing a suitable authoritative DNS response may cause BIND to return a false, DNSSEC-authenticated NXDOMAIN for a name that actually exists. This compromises DNS answer integrity.

Mitigation

To mitigate this issue, you can disable BIND, or disable recursion when not required.

  • Disable the Use BIND Server on BIG-IP option in the DNS profile
  • ⁠Restrict DNS recursion on the BIG-IP DNS system

Disable the Use BIND Server on BIG-IP option in the DNS profile

Important: Disabling the BIND server can affect DNS configurations that use BIND as a fallback method (return to DNS) for resolution.

  1. Log in to the Configuration utility.
  2. Go to one of the following locations:
    • Local Traffic > Profiles > Services > DNS.
    • DNS > Delivery > Profiles > DNS.
  3. Select the applicable DNS profile.
  4. For Use BIND Server on BIG-IP, select Disabled.
  5. Select Update.

Restrict DNS recursion on the BIG-IP DNS system

Refer to the Restricting DNS recursion on the BIG-IP DNS system procedure in K7055: Enabling DNS recursion in the named configuration on a BIG-IP DNS system.
