Description

FIPS integrity checks failed due to missing critical files on a multi bladed VIPRION chassis. The following files are deleted from the secondary blades after rebooting:

  • /root/.ssh/authorized_keys
  • /root/.ssh/known_hosts

Environment

  • VIPRION Platform with two or more blades configured

  • FIPS140-2 FIPs integrity check enabled

Cause

FIPS integrity checks failed due to missing critical files. You may encounter Terminal output similar to the following example:

# /usr/libexec/sys-eicheck.py

BIG-IP Integrity Check Report
- Non-critical file modifications do not result in failure.
- Critical file modifications result in failure.

=======================================================

0 non-critical files(s) missing

=======================================================
SM5....T.  c /etc/hosts
S.5..UGT.  c /var/lib/ntp/drift
S.5....T.  c /var/antserver/wsgsdk/config/ddscomm/aci.cfg
S.5....T.  c /var/antserver/wsgsdk/config/ddscomm/ae.cfg
......
......
SM5......  c /config/bigip/auth/pam.d/local/system-auth
SM5....T.  c /config/bigip/auth/pam.d/httpd
S.5....T.  c /var/dnscached/config/named.conf

20 non-critical files(s) modified

=======================================================
missing     /root/.ssh/authorized_keys
missing     /root/.ssh/known_hosts

2 critical file(s) missing                                                                          

=======================================================

0 critical file(s) modified

=======================================================

Integrity Check Result: [ FAIL ]                                                                    
Contact F5 Networks Technical Support.

Recommended Actions

Copy the missing files from the primary blade to the secondary blade.
From the primary blade, issue the following command towards the secondary blade(s).

# rsync -avz -e ssh /root/.ssh/* root@<Secondary Blade>:/root/.ssh/
