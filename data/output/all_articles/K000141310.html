K000141310: BGP traffic may fail on version 17.1 with AFM provisioned

Type
Support Solution
Published
2024-10-10
Updated
2024-10-16
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.X, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000141310

Description

BIG-IP's running version 17.1.0 and higher may impact BGP traffic while the tscookie feature is enabled within the AFM DoS vector, "TCP ACK TS".

One or more of the following may be observed on the BIG-IP: 

  • BGP traffic fails after upgrading to BIG-IP 17.1.x
  • BGP SYN packets are not being replied to on 17.1.x
  • BGP traffic fails to establish on 17.1.x

Environment

  • BIG-IP with AFM provisioned
  • BGP configured
  • BIG-IP version 17.1.0 or higher

Cause

Beginning in version 17.1.0, the TCP ACK (TS) vector was introduced. When this vector has the tscookie feature enabled it changes timestamps when forwarding packets.

BGP authentication relies on computing a checksum of the entire TCP segment, which includes the timestamp in TCP options. This feature (tscookie) is incompatible with BGP authentication, since the computed checksum is no longer valid once the timestamp is changed.

Recommended Actions

Disable the "tscookie" feature within the tcp-ack-ts vector.
This can be accomplished with the commands below:

1. Change tscookie to disabled

tmsh modify security dos device-config dos-device-config dos-device-vector { tcp-ack-ts { tscookie disabled }}

2. Confirm config was changed

tmsh list security dos device-config dos-device-config dos-device-vector { tcp-ack-ts }

3. Save the configuration

tmsh save sys config
