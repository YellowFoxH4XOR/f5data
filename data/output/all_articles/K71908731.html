K71908731: Microsoft Teams and Skype may fail to respect split-tunneling rules

Type
Support Solution
Published
2023-04-28
Updated
2023-04-28
Applies to
  • BIG-IP
  • F5 Access
  • BIG-IP APM: 14.1.2
  • APM Clients
Source
https://my.f5.com/manage/s/article/K71908731

Description
When using split-tunneling to route traffic for Microsoft Teams applications around your VPN, you may see traffic from the teams application sent through the tunnel regardless of that configuration. The routing table on the client will update correctly, and we may be able to route traffic to the same IP space using tracert or other utilities.

Environment

  • APM Network Access
  • Split tunneling
  • Microsoft Teams
  • Skype for Business
  • Edge Client

Cause
Microsoft Teams and other conference applications will try to use every available egress interface for this traffic, regardless of what the routing table would otherwise tell it to do. As such, our tunnel interface may take priority over the intended egress route.

Recommended Actions

  1. Use an ACL to block traffic for these IP spaces when routed through the tunnel. The application should retry using other egress interfaces.
  2. Open a case with Microsoft to determine if this can be changed.

Additional Information
While troubleshooting this issue, we can review the session logs from our APM to confirm that the access profile is completing successfully, and review the client logs to see our routing table updates happening successfully. The key behavior that separates this from other causes was that when using another tool to send traffic to the same destination IP (specifically tracert) we would see it route as expected and bypass the VPN.
