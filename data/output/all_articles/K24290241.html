F5 added a new feature to manage core files using the TMOS Shell (tmsh). This feature lets you manage the retention of core files in the /shared/core directory to keep important core files and at the same time maintain adequate disk space on the file system.

F5 introduced the enhanced core file creation feature in BIG-IP 15.0.0.This feature allows per process core dump control, a core file sweeper, and logic regarding when to overwrite or skip core file creation by specifying a maximum number of core files that the system creates. Before F5 introduced this feature, the system could have overwritten a core file each time a process generated a core dump, and as the first core file was overwritten, you lost useful troubleshooting information that helped determine the root cause of a failure.

Recommendations

Consider using the core file retention policy when F5 Technical Support asks you to generate a diagnostic core as part of the troubleshooting process. When configuring core file retention policies, you should consider the following factors:

  • Verify that you have an adequate amount of available disk space on your system. If there is not enough disk space to contain a core file, you risk causing system instability and producing a truncated and useless core file. For more information about maintaining disk space, refer to K14403: Maintaining disk space on the BIG-IP system.

Procedures

  • Verify the existing core file policy configurations
  • Configure the core file retention period
  • Manage mcpd, tmm, and bigd core files

Verify the existing core file policy configurations

To view the existing core file policy settings, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view the existing policy settings, enter the following command:

    list sys core

    The following example output lists the default settings:

    sys core {
        bigd-action rotate
        bigd-manage false
        bigd-max 1
        mcpd-action rotate
        mcpd-manage false
        mcpd-max 1
        retention 30
        tmm-action rotate
        tmm-manage false
        tmm-max 1
    }

Configure the core file retention period

The retention value lets you configure the number of days to retain core files in the /shared/core directory, and you can set it to an integer value between 1 and 365. The default setting is 30 days and the value is implemented using crontab, which runs a job to delete old files with file names *core.* in the /shared/core directory every 6 hours. To configure the retention period, perform the following procedure:

Impact of procedure: Ensure that you have sufficient disk space on your system. If you increase the retention period, you risk keeping more core files and you may run out of disk space, causing system instability and a truncated, useless core file. F5 recommends that you revert to the default settings once troubleshooting is complete.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the retention period, use the following command syntax:

    modify sys core retention <number of days>

    For example, to delete core files older than 20 days, enter the following command:

    modify sys core retention 20

Manage mcpd, tmm, and bigd core files

The mcpd, tmm, and bigd core policy gives you finer control over the number of core files that you retain for each process. For example, to enable the tmm core file policy, and retain a maximum of three tmm core files, perform the following procedure:

Impact of procedure: Ensure that you have sufficient disk space on your system. If you increase the number of core files in the file system, you risk running out of disk space, causing system instability and a truncated, useless core file. F5 recommends that you revert to the default settings once troubleshooting is complete.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Enable the specific core policy by using the following command syntax:

    modify sys core <bigd-manage | mcpd-manage | tmm-manage> <true|false>

    For example, to enable the tmm core policy, enter  the following command:

    modify sys core tmm-manage true

    When you set the command to false, the system ignores the <process>-action and <process>-max settings. For example, if tmm-manage is false, the system ignores tmm-action and tmm-max.

  3. To configure the maximum number of core files for each process, use the following command syntax:

    modify sys core <bigd-max | mcpd-max | tmm-max> <max_number>

    For example, to retain a maximum of three tmm core files, enter the following command:

    modify sys core tmm-max 3

  4. To configure the retention policy for the core files, use the following command syntax:

    modify sys core <bigd-action | mcpd-action | tmm-action> <skip|rotate>

    • skip: When you set tmm-action to skip, the system skips creating a core file at the next core when the number of existing core files equals the max set in step 3. For example, if you set tmm-max to be 3, tmm-action to skip and 3 TMM core files already exist, the system does not create a fourth one at the next core event.
    • rotate: When you set tmm-action to rotate, the system keeps the max number of core files set in step 3 by deleting the oldest file and generating a new one. For example, if you set tmm-max to be 3, tmm-action to rotate, and three TMM core files already exist, the system deletes the oldest TMM core file and creates a new one, maintaining the total at three.

    For example, to configure core file rotation, enter the following command:

    modify sys core tmm-action rotate

    The system adds the epoch timestamp to the file name. For example, you may observe a TMM  core file generated with a file name similar to the following example:

    tmm.0.bld0.0.3.1556182348.core.gz

Logging

The enhanced core file retention feature logs core file activities like core file writing, deletion, rotation, skipping, and other useful information in the /var/log/messages file.
