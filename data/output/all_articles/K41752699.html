Description
Adding a source address list to a virtual server in a partition with a non-default route domain fails with an error similar to:

0107176c:3: Invalid Virtual Address, the IP address 192.168.0.1%2 already exists.

Environment

  • BIG-IP LTM
  • Virtual Server
  • Route Domains
  • Shared Address List

Cause

ID1006857
 

Recommended Actions

1. Delete all virtual servers you want to use the address-list on.
2. Ensure that the virtual-address does not exist in the Virtual-address list after deleting all virtual server instances
3. Create your Address-List under Shared Objects in the WebUI
4. Create the traffic-matching-criteria via the CLI (make sure you are in the correct partition)

# tmsh
# cd /<partition name> (optional, skip if you are configuring the object in /Common)
# create ltm traffic-matching-criteria <virtual server name>_VS_TMC_OBJ { destination-address-inline <virtual address> destination-port-inline <virtual server port> protocol <virtual server protocol> route-domain <route-domain> source-address-list <address list> }

For Example: Assuming the virtual server name is 'F5_example' listening on 192.168.0.1 on port 80 with protocol TCP in route domain 'F5_RD', and assuming you created the shared object source address list with a name of 'allowed_sources' 

# create ltm traffic-matching-criteria F5_example_VS_TMC_OBJ { destination-address-inline 192.168.0.1 destination-port-inline 80  protocol tcp route-domain F5_RD source-address-list allowed_sources }
# save sys config

5. Recreate the virtual server (s) that was (were) removed in step 1, using the Address-List as the Source
