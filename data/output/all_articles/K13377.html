Known Issue

Description

The BIG-IP WebAccelerator may not update expiration timers for cached objects.

This issue occurs when all of the following conditions are met:

  • A request is matched on an incoming BIG-IP WebAccelerator policy leaf node and is cached with a max-age of 0
  • The response from the origin web server (OWS) matches a different BIG-IP WebAccelerator leaf node with a non-zero max-age
  • The object has expired in the BIG-IP WebAccelerator cache

The sequence of events which may lead to this issue are as follows:

  • A request comes in to the BIG-IP WebAccelerator and is matched by a leaf node with a max-age of 0
  • The response matches a different leaf node with a non-zero max-age
  • The BIG-IP WebAccelerator caches and serves the object until it expires
  • After expiration, an S10202 (proxied due to expired cache) code is sent to the client as expected, and a conditional GET is sent to the OWS to check if the object has been updated with a corresponding HTTP 304 Not Modified response
  • All subsequent requests for this object are incorrectly served with an S10202 response and conditional GET requests to the OWS with a corresponding HTTP 304 Not Modified response
  • If the object on the OWS is updated or the cache is cleared, the BIG-IP WebAccelerator correctly updates the object in its cache, and resets the expiration timer for this object

No loss of data or stale objects are served when this issue is encountered.

Impact

The OWS may experience additional load due to the extra conditional GET requests being sent and responded to.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Excessive conditional GET requests from the BIG-IP WebAccelerator and corresponding HTTP 304 Not Modified responses from the OWS.
  • The BIG-IP WebAccelerator will respond to the client with a cached version of the object and an S10202 X-PvInfo (version 10.x) or X-WA-Info (version 11.x) header.

Workaround

To prevent this issue from occurring, you can modify the policy. To recover from this issue once you are affected, you can clear the cache.

Modifying the policy

Impact of workaround:  With careful consideration and analysis of your policy, there should be no impact.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Main >> WebAccelerator >> Policies.
  3. Modify the matching rules in your policy so that both the request and the response are matched by the same leaf node.

Clearing the BIG-IP WebAccelerator cache

Clearing the BIG-IP WebAccelerator cache is only a temporary measure. The issue will re-occur when the conditions which triggered this issue are met again.

Impact of workaround: The WebAccelerator module will temporarily stop processing traffic while the cache is cleared.  Additionally, the OWS may experience a temporary increase in load while new objects are re-cached.

  1. Log in to the command line as the root user.
  2. Type the following command to clear the BIG-IP WebAccelerator disk cache:

    wa_clear_cache
