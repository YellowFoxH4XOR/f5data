K000156661: Observing Excessive logging to remote syslog

Source
https://my.f5.com/manage/s/article/K000156661

Description

BIG-IP LTM devices may generate excessive syslog messages, including debug level logs that are forwarded to remote syslog servers such as Splunk. This can result in log overload, high storage consumption, and potential performance degradation on the logging infrastructure. Example log entries include:

debug statsd[4180]: 011b090e:7: getTMValueUNKeyed start.
debug statsd[4180]: 011b090c:7: tmstat_query_rollup on table tmmdns_zone_stat called.
debug statsd[4180]: 011b0233:7: CACHE MISS during rollup, prev=(null), curr=tmmdns_zone_stat.

 

Environment

  • BIG-IP LTM 
  • Version 17.x
  • Logging configuration using "sys log-config filter and publisher for forwarding logs to remote destinations (e.g., Splunk)

Cause

The syslog filter named Splunk_Filter was found to be configured without a defined severity level (level property). As a result, it matched and forwarded all log severities (including debug, info, notice, warning, error, and critical) to the designated remote syslog destination.

# tmsh list sys log-config filter /Common/Splunk_Filter
sys log-config filter Splunk_Filter {
    publisher Splunk_Publisher
}

This indicates that the filter was operating in its default configuration, which does not restrict log severity or source. Consequently, it ingested and forwarded logs from all sources and severity levels, potentially increasing log volume and impacting downstream log processing or storage.

Recommended Actions

  • Restrict the log severity in the syslog filter by specifying the desired minimum severity level (e.g., warn to forward only warning and higher severity logs).
# tmsh modify sys log-config filter /Common/Splunk_Filter level warn
  • If a syntax error occurs due to the absence of the level property in the existing syslog filter configuration, delete the current filter and recreate it with the appropriate severity level defined:
# tmsh delete sys log-config filter Splunk_Filter
# tmsh create sys log-config filter Splunk_Filter level warn publisher Splunk_Publisher
# save sys config
  • To confirm that the syslog filter has been correctly configured with the desired severity level, use the following tmsh command:
 # tmsh list sys log-config filter Splunk_Filter

This command will display the current configuration of the specified filter. A properly configured filter should include the level property, indicating the minimum severity of logs that will be forwarded. For example, if the filter is set to forward logs with severity warn and above, the output should resemble:

sys log-config filter Splunk_Filter {
    level warn
    publisher Splunk_Publisher
}

Please Note: Changing or recreating a syslog filter is non-intrusive and does not affect traffic or disrupt services.

Additional Information

Acceptable values for level are:

debug
info
notice
warn
err
crit
alert
emerg
