K000163506: Upgrade to F5OS 2.0 may result in a failed platform-services-deployment.service

Type
Support Solution
Published
2026-10-01
Updated
2026-10-01
Source
https://my.f5.com/manage/s/article/K000163506

Description

After triggering the installation of F5OS 2.0, the system service platform-services-deployment.service may fail and the installation will stall. Running the following shows a failed platform-services-deployment.service:

[root@appliance-1:Platform deployment failed] ~ # systemctl status -l platform-services-deployment.service
● platform-services-deployment.service - Launch platform service containers through Docker Compose
   Loaded: loaded (/usr/lib/systemd/system/platform-services-deployment.service; static; vendor preset: disabled)
   Active: failed (Result: exit-code) since Wed 2026-09-30 21:58:38 PDT; 1h 3min ago
 Main PID: 6100 (code=exited, status=1/FAILURE)

Environment

  • Upgrade to F5OS 2.0
  • rSeries

Cause

None

Answer/Recommended Actions

  1. Determine if the issue is due to a missing /var/docker/config/env_var.MFST softlink: 
    [root@appliance-1:Active] ~ # journalctl --boot --unit platform-services-deployment.service --no-pager | grep -ai "env_var.MFST not found"

    Sep 30 21:58:04 appliance-1.chassis.local platform-deployment[9514]: 2026-09-30 21:58:04 WARNING: env_var.MFST not found; MFST_* image variables may use fallback values. 

    Sep 30 21:58:04 appliance-1.chassis.local platform-deployment[6100]: WARNING: env_var.MFST not found; MFST_* image variables may use fallback values.
  2. If you see the above log, determine if the following softlink exists: 
    [root@appliance-1(R10900-R86-S35):Platform deployment failed] ~ # ls -ld /var/docker/config/env_var.MFST

    ls: cannot access '/var/docker/config/env_var.MFST': No such file or directory
  3. If the soft link does not exist, create it using the following step: 
    [root@appliance-1:Platform deployment failed] ~ # ln -s /var/docker/config/appliance/2.0.0-25885/env_var.MFST /var/docker/config/env_var.MFST
  4. Confirm that the softlink is created: 
    [root@appliance-1:Platform deployment failed] ~ # ls -l /var/docker/config/env_var.MFST

    lrwxrwxrwx. 1 root root 53 Sep 30 23:06 /var/docker/config/env_var.MFST -> /var/docker/config/appliance/2.0.0-25885/env_var.MFST
  5. Restart the service platform-services-deployment.service: 
    [root@appliance-1:Platform deployment failed] ~ # systemctl restart platform-services-deployment.service
  6. Determine that the platform-services-deployment.service is "active (exited)": 
    [root@appliance-1:Active] ~ # systemctl status -l platform-services-deployment.service

    ● platform-services-deployment.service - Launch platform service containers through Docker Compose

       Loaded: loaded (/usr/lib/systemd/system/platform-services-deployment.service; static; vendor preset: disabled)

       Active: active (exited) since Wed 2026-09-30 23:07:55 PDT; 27ms ago

      Process: 27209 ExecStart=/usr/libexec/platform-deployment start (code=exited, status=0/SUCCESS)

     Main PID: 27209 (code=exited, status=0/SUCCESS)

        Tasks: 0 (limit: 1646004)

       Memory: 0B

       CGroup: /system.slice/platform-services-deployment.service
