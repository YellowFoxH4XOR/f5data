K000162090: IP Intelligence Feed List Not Updating Automatically When Using iRule-Based Custom Feed on BIG-IP AFM

Type
Support Solution
Published
2026-07-06
Updated
2026-07-06
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.5.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000162090

Description

When using a custom IP Intelligence feed list published via a BIG-IP Virtual Server and controlled by an iRule, updates to the feed (such as adding or removing records in the iRule) are not reflected in IP Intelligence as expected. The changes only take effect after manually restarting the `dwbld` process. Log entries in `/var/log/dwbl/dwbld.log` show messages such as:


- `File was not updated`

- `States are (current:new)=(2:0)`


Attempts to force cache updates by adding HTTP headers (e.g., `Last-Modified`) in the iRule do not resolve the issue.


Environment

- Product: BIG-IP AFM

- Version: 17.5.0 and later

- Configuration:

 - Custom IP Intelligence feed list published via a BIG-IP Virtual Server

 - Feed content served by an iRule


Cause

Bug ID2339769


Answer/Recommended Actions

The issue is caused by Bug ID2339769, where the `dwbld` process does not detect updates to the feed content when served via an iRule, and thus does not refresh the cache automatically.

As a workaround, manually restarting the `dwbld` process (`bigstart restart dwbld`) will force the feed to update.


Additional Information

The issue is consistently observed during deployment of the virtual server and only resolved by restarting the `dwbld` process.
