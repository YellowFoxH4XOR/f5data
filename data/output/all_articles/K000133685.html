Description

  • NGINX reads client body in chunks into memory buffer.
    • Nginx memory buffer allocation is finite, limited in size and dependent on the host system.
    • If NGINX exceeds its memory allocation, it writes any overflowing request to a temp file on a filesystem [disk].
    • As a result, NGINX has high level of tolerance when it comes to memory exhaustion through large file uploads.
  • client_max_body_size and resource consumption, are relative and subjective to each other due to the presence of several environment specific variables like traffic load as well as actual physical resource available to Nginx including memory and hard-disk space.

Environment

  • Nginx Plus
  • client_max_body_size

Cause

  • None

Recommended Actions

  • By limiting the file size uploads, you can prevent some types of Denial-of-service (DOS) attacks as well as a few other.
  • NGINX limits/manages large HTTP request bodies by setting client_max_body_size directive value to 1M.
  • Based on the above discussion, if one wishes to increase to a higher value,  this is attainable

Additional Information

  • Since NGINX is a proxy, one must consider the impact of passing a request with increased body size to an upstream.
  • These and other factors including security and memory/disk utilization on the backend server must also be considered.
