Known Issue

The TMOS Shell (tmsh) memory usage grows over time when saving the configuration.

This issue occurs when one of the following condition is met:

  • You use iCall or a CLI script to save the BIG-IP configuration.
  • A BIG-IQ device manages and backs up your BIG-IP configuration.

Impact

The iControlPortal.cgi and scriptd process memory usage increases over time. This behavior may cause the host to exhaust its memory. As a result, the BIG-IP system processes restart and disrupt traffic. If you have configured your BIG-IP system as a device group member, the device may fail over to a peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The top command indicates that the iControlPortal.cgi process is consuming excessive memory.

    For example, the following top output displays that the iControlPortal.cgi process is consuming 3.9 GB of memory:

    PID UID Priority    Nice    Size    Resident    Shared  State   %CPU    %MEM    Runtime CPU #   Swap    Command line
    12345   root    20      0   3.9G    3.7G    17.8M   S   0.1 23.5    01:05:15.29 1   0   /usr/local/www/iControl/iControlPortal.cgi

  • The scriptd process memory allocation grows over time.
  • In the /var/log/kern.log file, you observe error messages that appear similar to the following examples:

    err kernel: Out of memory: Kill process 12345 (iControlPortal.) score 104 or sacrifice child
    err kernel: Killed process 12345, UID 0, (iControlPortal.) total-vm:738856kB, anon-rss:520688kB, file-rss:17404kBolPortal.) score 104 or sacrifice child

Workaround

To work around the issue, avoid saving BIG-IP configurations using iCall, a CLI script, or BIG-IQ.

To temporarily recover from this issue, you can restart the scripd and httpd services. To do so, perform the following procedure:

Impact of workaround: The BIG-IP Configuration utility is not accessible while the httpd service is restarting.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To restart the scriptd and httpd services, type the following command:

    restart /sys service scriptd httpd
