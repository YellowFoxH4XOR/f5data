Topic

You should consider using this procedure under the following condition:

  • You want to configure idle timeout for webUI, CLI or SSH sessions on the VELOS or rSeries system.

Description

The VELOS or rSeries system uses different settings to control the idle timeout for webUI, CLI and SSH sessions. The following table summarizes these settings:

Session typeConfiguration settingDescription
F5OS-C/A webUI session

restconf-token lifetime

  • CLI
    • operational mode command:

      show system aaa restconf-token state lifetime

    • configuration mode command:

      system aaa restconf-token config lifetime <value>

  • API
    • operational mode command:

      /api/data/openconfig-system:system/aaa/f5-aaa-confd-restconf-token:restconf-token/state/lifetime

    • configuration mode command:

      /api/data/openconfig-system:system/aaa/f5-aaa-confd-restconf-token:restconf-token/config -d '{ "config": { "f5-aaa-confd-restconf-token:lifetime": <value> } }'

  • webUI:

    AUTHENTICATION & ACCESS > Authentication Settings > Token Lifetime
  • The restconf-token lifetime setting determines how long the authentication token for webUI session is inactive before a user is logged out of the webUI session. When a client has a token, and is active on the webUI, the token is renewed when there is less than 1/3 of the token lifetime remaining. At this time, a new token is issued. The renewal limit is 5 after which the user will be logged out.

    For instance, when the restconf-token lifetime setting is set to 1 minute, a token can be renewed between 40 - 60 seconds after it is issued. When the first token gets renewed after 45 seconds for example, a second token is issued. When this (second) token is  renewed after 46 seconds, a third token is issued and so on. This renewal can happen up to 5 times.

  • When the value for the restconf-token lifetime setting is updated, the new value will apply to the next token refresh or when a new session is established; the timeout for the existing session is not affected.
  • The range of values allowed for the restconf-token lifetime setting is 1 through 1440 minutes. The default value is 15 minutes.
F5OS-C/A CLI session

idle-timeout

  • CLI
    • operational mode command:

      show system settings state idle-timeout

    • configuration mode command:

      system settings config idle-timeout <value>

  • API
    • operational mode command:

      /api/data/openconfig-system:system/f5-system-settings:settings/state/idle-timeout

    • configuration mode command:

      /api/data/openconfig-system:system/f5-system-settings:settings/config -d '{ "config": { "idle-timeout": "<value>" } }'

  • webUI:

    SYSTEM SETTINGS > System Security > CLI Idle Timeout

The idle-timeout setting determines how long the CLI session is inactive before a CLI user is logged out of the CLI session. For a CLI session established over SSH, the user is logged out based on the lower value between the idle-timeout setting and the sshd-idle-timeout setting. For example, if the sshd-idle-timeout setting value is 2 minutes while the idle-timeout setting value is 3 minutes, then the sshd-idle-timeout setting value will kick in first and the user is logged out after 2 minutes. The range of values allowed for the idle-timeout setting is 0 (zero) through 4294967 seconds for VELOS as well as r12000/r10000/r5000 series hardware products. For r4000/r2000 series hardware products, the range of values allowed for the idle-timeout setting is 0 (zero) through 8192 seconds. A value of 0 (zero) sets the time to infinity which means the system never logs out the user. By default, the system logs out a user after 1800 seconds if no value is configured for this setting.
F5OS-C/A SSH session

sshd-idle-timeout

  • CLI
    • operational mode command:

      show system settings state sshd-idle-timeout

    • configuration mode command:

      system settings config sshd-idle-timeout <value>

  • API
    • operational mode command:

      /api/data/openconfig-system:system/f5-system-settings:settings/state/sshd-idle-timeout

    • configuration mode command:

      /api/data/openconfig-system:system/f5-system-settings:settings/config -d '{ "config": { "sshd-idle-timeout": "<value>" } }'

  • webUI: Not configurable in webUI.
The sshd-idle-timeout setting determines how long the SSH session is inactive before a user is logged out of the SSH session. This setting covers both CLI and bash shell access* through SSH session. For CLI access through SSH session, the user is logged out based on the lower value between the idle-timeout setting and the sshd-idle-timeout setting. For example, if the sshd-idle-timeout setting value is 2 minutes while the idle-timeout setting value is 3 minutes, then the sshd-idle-timeout setting value will kick in first and the user is logged out after 2 minutes. The range of values allowed for the sshd-idle-timeout setting is 0 (zero) through 4294967 seconds for VELOS as well as r12000/r10000/r5000 series hardware products. For r4000/r2000 series hardware products, the range of values allowed for the sshd-idle-timeout setting is 0 (zero) through 8192 seconds. A value of 0 (zero) sets the time to infinity which means the system never logs out the user. By default, the system logs out a user after 1800 seconds if no value is configured for this setting.

*There is no setting to timeout bash shell access through serial console in currently released F5OS-C/A versions.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You must have administrative access to  the management interface (webUI/CLI/REST API) of the VELOS chassis/partition or rSeries system.
  • If you intend to use the REST API procedures, you should have a workstation with the curl utility installed.
  • If you intend to use the CLI procedures, you should have a workstation with either the ssh utility installed or have console access to the VELOS chassis/partition or rSeries system.

Procedure

  • Configure idle timeout for webUI session
  • Configure idle timeout for CLI session
  • Configure idle timeout for SSH session

Configure idle timeout for webUI session

To configure the idle timeout for webUI session, perform the steps in one of the following procedures:

Impact of procedure: Performing this procedure should not have an impact on your VELOS chassis/partition or rSeries system. Note that the new value will apply to the next token refresh or when a new session is established.

  • Using webUI
  • Using CLI
  • Using API

Using webUI

  1. Login to the webUI of the VELOS chassis/partition or rSeries system as the admin user.
  2. Go to AUTHENTICATION & ACCESS > Authentication Settings.
  3. Enter a value you want in minutes for the Token Lifetime setting.
  4. Select Save to save the changes.

Using CLI

  1. Login to the CLI of the VELOS chassis/partition or rSeries system as the admin user.
  2. To display the existing value for the restconf-token lifetime setting, enter the following command:

    show system aaa restconf-token state lifetime

    The command should return an output similar to the following example:

    system aaa restconf-token state lifetime 15

  3. To modify the restconf-token lifetime setting, you must first enter into the configuration mode by entering this command:

    config

    Then enter the following command syntax:

    system aaa restconf-token config lifetime <value in minutes>

    For example,

    system aaa restconf-token config lifetime 18

  4. To save the change, enter the following command:

    commit and-quit

  5. To verify the change, enter the following command:

    show system aaa restconf-token state lifetime

Using API

  1. Login to a workstation with curl utility installed.
  2. To display the existing value for the restconf-token lifetime setting, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address>/api/data/openconfig-system:system/aaa/f5-aaa-confd-restconf-token:restconf-token/state/lifetime"

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X GET "https://192.168.80.7/api/data/openconfig-system:system/aaa/f5-aaa-confd-restconf-token:restconf-token/state/lifetime"

    You should observe the command returning an output similar to the following example:

    {
      "f5-aaa-confd-restconf-token:lifetime": 15
    }

  3. To modify the restconf-token lifetime setting, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X PATCH "https://<management IP address>/api/data/openconfig-system:system/aaa/f5-aaa-confd-restconf-token:restconf-token/config" -d '{ "config": { "f5-aaa-confd-restconf-token:lifetime": <value in minutes> } }'

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X PATCH "https://192.168.80.7/api/data/openconfig-system:system/aaa/f5-aaa-confd-restconf-token:restconf-token/config" -d '{ "config": { "f5-aaa-confd-restconf-token:lifetime": 18 } }'

    The command does not return an output. To verify if the command is processed successfully, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address>/api/data/openconfig-system:system/aaa/f5-aaa-confd-restconf-token:restconf-token/state/lifetime"

    You should observe the command returning an output similar to the following example:

    {
      "f5-aaa-confd-restconf-token:lifetime": 18
    }

Configure idle timeout for CLI session

To configure the idle timeout for CLI session, perform the steps in one of the following procedures:

Impact of procedure: Performing this procedure should not have an impact on your VELOS chassis/partition or rSeries system. 

  • Using webUI
  • Using CLI
  • Using API

Using webUI

  1. Login to the webUI of the VELOS chassis/partition or rSeries system as the admin user.
  2. Go to SYSTEM SETTINGS > System Security.
  3. Enter a value you want in seconds for the CLI Idle Timeout setting.
  4. Select Save to save the changes.

Using CLI

  1. Login to the CLI of the VELOS chassis/partition or rSeries system as the admin user.
  2. To display the existing value for the idle-timeout setting, enter the following command:

    show system settings state idle-timeout

    The command should return an output similar to the following example:

    system settings state idle-timeout 300

    Note: If no value is configured after the initial deployment of the VELOS or rSeries system, the command would return "% No entries found." but the idle timeout is the default value of 1800 seconds.

  3. To modify the idle-timeout setting, you must first enter into the configuration mode by entering this command:

    config

    Then enter the following command syntax:

    system settings config idle-timeout <value in seconds>

    For example,

    system settings config idle-timeout 120

  4. To save the change, enter the following command:

    commit and-quit

  5. To verify the change, enter the following command:

    show system settings state idle-timeout

Using API

  1. Login to a workstation with curl utility installed.
  2. To display the existing value for the idle-timeout setting, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address>/api/data/openconfig-system:system/f5-system-settings:settings/state/idle-timeout"

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X GET "https://192.168.80.7/api/data/openconfig-system:system/f5-system-settings:settings/state/idle-timeout"

    You should observe the command returning an output similar to the following example:

    {
      "f5-system-settings:idle-timeout": "300"
    }

    Note: If no value is configured after the initial deployment of the VELOS or rSeries system, the command would return an error message "uri keypath not found" but the idle timeout is the default value of 1800 seconds.

  3. To modify the idle-timeout setting, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X PATCH "https://<management IP address>/api/data/openconfig-system:system/f5-system-settings:settings/config" -d '{ "config": { "idle-timeout": "<value in seconds>" } }'

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X PATCH "https://192.168.80.7/api/data/openconfig-system:system/f5-system-settings:settings/config" -d '{ "config": { "idle-timeout": "120" } }'

    The command does not return an output. To verify if the command is processed successfully, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address>/api/data/openconfig-system:system/f5-system-settings:settings/state/idle-timeout"

    You should observe the command returning an output similar to the following example:

    {
      "f5-system-settings:idle-timeout": "120"
    }
