Description

This article addresses the scenario where BIG-IP systems log persistent errors such as:

011b0600:3: Error 'mmaping file '<path>' Invalid argument' during rrd_update for rrd file '<path>'

This error is commonly associated with the endpisession RRD file and may continue even after standard remediation steps (stopping statsd, deleting the main RRD files, restarting statsd) are performed. The issue persists if a backup copy of the corrupted file remains in the /shared directory.

Environment

  • BIG-IP platforms (including LTM, vCMP guests, iSeries appliances)
  • All supported software versions
  • Use of statsd service for performance statistics
  • Issue typically involves files such as endpisession, but may affect other RRD files

Cause

Corruption or truncation of an RRD statistics file (e.g., endpisession). If a backup copy exists in /shared, it can restore the corrupted state when statsd restarts, causing errors to persist.

Recommended Actions

  1. Stop the statsd daemon:
    bigstart stop statsd
  2. Confirm that statsd has stopped:
    bigstart status statsd
  3. Navigate to the RRD directory and remove problematic files:
    cd <path_to_rrd_directory>
    rm -f endpisession
    rm -f endpisession.info
    ls -ltr <path_to_rrd_directory>
  4. Check for backup copies in /shared and remove them if present:
    ls -ltr /shared/rrd.1.2.perm
    If backup was not removed, delete it
    rm -f /shared/rrd.1.2.perm/endpisession
  5. Restart the statsd daemon:
    bigstart start statsd
    bigstart status statsd
  6. Monitor logs to confirm resolution:
    tail -100 /var/log/ltm | grep rrd_update

Note: If you are troubleshooting a different RRD file, substitute its name for endpisession in all commands above.

Additional Information

  • Statistics collection will pause briefly while statsd is stopped/restarted; no other service impact is expected.
  • This step is not included in some public F5 KBs but is essential for complete remediation.
