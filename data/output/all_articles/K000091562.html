K000091562: GUI shows "Unable to contact BIG-IP device" or a Web GUI error and becomes unresponsive

Published

Updated

Source

Description

The BIG-IP LTM Web GUI shows "Unable to contact BIG-IP device" or a Web GUI error and becomes unresponsive. The httpd service restarts repeatedly, and QKView generation from the GUI fails. The Tomcat log shows java.lang.OutOfMemoryError: Java heap space followed by repeated Tomcat restarts, and httpd logs AJP connection errors.

Symptoms and log messages:

  • Tomcat heap exhaustion with at least 500 instances of:
    • java.lang.OutOfMemoryError: Java heap space
    • -XX:OnOutOfMemoryError="/usr/bin/restart_tomcat" followed by repeated Tomcat restarts
  • httpd AJP errors when Tomcat is unavailable:
    • AH00957: AJP: attempt to connect to localhost:8009 failed
    • AH00959: ap_proxy_connect_backend disabling worker for (localhost)
    • AH00896: failed to make connection to backend: localhost
    • AH00992: ajp_read_header: ajp_ilink_receive failed
  • High CPU usage caused by the restjavad process continually crashing and restarting (see Bug ID 894593).
  • GUI errors during long operations, such as saving a UCS file, which can time out after 5 minutes (see Bug ID 796605).

Environment

  • BIG-IP LTM version 14.1.4
  • High-availability (HA) device pair
  • AVR module provisioned, which may consume additional memory
  • Large configuration, where UCS saves from the GUI take longer than 5 minutes

Relevant database variables, with values observed on the affected system before changes:

VariableDefaultObserved valueAllowed range
provision.tomcat.extramb050integer 0 to 1024
restjavad.useextrambfalsefalsefalse, true
provision.extramb00integer 0 to 8192

Cause

  • Tomcat heap exhaustion: The Tomcat process ran out of Java heap space. Its OnOutOfMemoryError handler restarted Tomcat repeatedly, which caused the AJP connection failures in httpd. See K9719: Error Message: java.lang.OutOfMemoryError.
  • restjavad instability: Bug ID 894593 describes restjavad becoming unstable when the memory it requires exceeds the memory allocated to it. Continuous restarts drive up CPU usage and degrade system performance.
  • GUI timeouts: Bug ID 796605 describes the GUI returning an error when a UCS save or other operation takes more than 5 minutes.

Hypothesis (unconfirmed): The provision.tomcat.extramb value of 50 may be insufficient for this system's workload.

Answer/Recommended Actions

  1. Confirm the Tomcat memory error. On the device, check whether the Tomcat log contains repeated java.lang.OutOfMemoryError entries. Check the httpd error log for the AJP errors listed in the Description section.
  2. Review Tomcat memory provisioning. Check the current value with tmsh list sys db provision.tomcat.extramb. Refer to K9719: Error Message: java.lang.OutOfMemoryError for guidance on adjusting this value. Make changes in a maintenance window.
  3. Review restjavad memory settings. Check the following values:

    tmsh list sys db restjavad.useextramb

    tmsh list sys db provision.extramb

    Apply the changes described in Bug ID 894593 and restart restjavad. Then confirm that CPU usage has dropped and the GUI remains responsive.
  4. Generate QKView from the CLI if the GUI is unavailable. Run qkview -s0 from the command line.
  5. Save large UCS files from the CLI. Until Bug ID 796605 is resolved, use the tmsh command save sys ucs <name> instead of saving from the GUI.
  6. Plan the HA sync after restjavad changes. Restarting restjavad can leave the HA pair out of sync. The GUI sync warning may state that the active device goes offline for several minutes, so schedule any manual sync in a maintenance window.
  7. Plan the upgrade. Confirm the fixed versions for Bug ID 796605 and Bug ID 894593 in the bug tracker before choosing a target version. Check the hardware and software compatibility and upgrade paths for the target version before upgrading.

Additional Information

  • Expected behavior: The AJP connection errors in httpd are expected while Tomcat is down or restarting. They are a symptom, not the root cause.
  • Unexpected behavior: Tomcat restarting repeatedly with OutOfMemoryError entries is not normal operation.
  • Record the before and after values for any change to the database variables listed in the Environment section.
