Description

  • After upgrading from version 12 to 14 can results in HTTPs monitors not working
  • One may see 502 HTTP error from the host

Environment

  • LTM
  • HTTPs monitor

Cause

  • Change of behavior as stated in article K51131340: SSL settings used by an HTTPS monitor are now configured using a Server SSL profile
  • For example, if monitor was using the 'ALL' optionin the cipher, like shown below, it could result in configuration load error after upgrade 
    • ALL: !EXPORT:!RC4:!DES:!ADH:!EDH:!SSLv3:!TLSv1:!RC4:!DES:!ADH

Recommended Actions

  • Create and associate new https monitor with exact cipher selection but substituting  'ALL' for 'DEFAULT'
  • Example
    • DEFAULT,RC4-SHA,AES128-SHA,AES256-SHA,DES-CBC3-SHA:!RC4:!DES:!ADH:!EDH:!SSLv3:!TLSv1:!RC4:!DES:!ADH
