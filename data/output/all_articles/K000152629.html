K000152629: F5OS - After upgrade tenant fail to start with error "Storage size(76) must be greater than or equal to 142"

Type
Support Solution
Published
2025-07-18
Updated
2026-08-26
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.8.0
Source
https://my.f5.com/manage/s/article/K000152629

Description

After upgrading an F5OS appliance from version 1.7 to 1.8.0, BIG-IP tenants may fail to start with errors such as:

  • "Allocating resources to tenant is in progress."
  • "Resource allocation failed - Node is up but Platform services not responding."
  • Additionally, when attempting to provision a tenant, the following error may appear: "Storage size(76) must be greater than or equal to 142"

Environment

  • Product: F5OS - Appliance or Velos
  • Version: 1.8.0 (upgrade from 1.7.0)
  • BIG-IP tenants using T4 disk images
  • Tenants originally created on F5OS-A 1.1.0 with storage size below the minimum required for T4 images

Cause

A validation bug in F5OS-A 1.1.0 allowed creation of BIG-IP tenants with T4 disk images and a storage size below the required minimum (142 GB). This issue is documented in F5 Bug ID1161557. While F5OS 1.7.0 and later enforce the minimum disk size for newly created tenants, the validation does not retroactively check tenants created on earlier, affected versions. As a result, after upgrading to F5OS 1.8.0, tenants with insufficient storage fail to start and display the error: "Storage size(76) must be greater than or equal to 142".

Recommended Actions

  • Before upgrading F5OS, verify that all BIG-IP tenants meet the minimum required disk size for their image type. For T4 images, the minimum is 142 GB.
  • If a tenant fails to start after upgrade due to insufficient storage, set the tenant to "configured" mode, increase the storage allocation to meet or exceed the minimum requirement, and redeploy the tenant.
  • if the tenant is already on deployed state and you are not able to set the tenant to "configured" mode, set it to "configured" and provision the disk size on the same command; for example:  
    tenants tenant <tenant name> config running-state configured storage size 142 ; top
    commit
  • Refer to F5 article K000140343 for the minimum and maximum virtual disk size requirements for BIG-IP tenants.
