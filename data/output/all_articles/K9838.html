Topic

When the BIG-IP client_ssl profile is configured to require client certificate authentication, and the client sends a certificate message that does not contain a certificate, the SSL handshake fails and BIG-IP terminates the connection normally without sending a fatal handshake failure alert.

This behavior has been observed when iPhone HTTP clients connect to BIG-IP virtual servers.

The BIG-IP system's behavior complies with RFC2246 section 7.4.6, which specifies not only that a fatal handshake failure alert from the server is optional, but that the client should have already sent its certificate.

F5 Product Development tracked a Request For Enhancement to send a fatal handshake failure alert when no client certificate is presented as CR116339, and this functionality was added in BIG-IP version 10.1.0. There are no plans to add this functionality to the BIG-IP version 9.4.x branch.
