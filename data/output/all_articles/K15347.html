Known Issue

An IP tunnel object may intermittently fail to pass traffic. This issue occurs when all of the following conditions are met:

  • The affected IP tunnel object has its Remote Address configured with the value of Any; making this IP tunnel object a wildcard IP tunnel.
  • The affected IP tunnel object has its Encapsulation Type configured with the value of either gre or ipip.

Impact

Application traffic traversing the IP tunnel is disrupted.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H451357 on the Diagnostics > Identified > High screen.
  • A packet capture on the affected traffic shows the decapsulated packet sent to a different TMM process, instead of the TMM process that handled the IP tunnel packet.
  • Another connection flow was handled on an incorrect TMM process when you attempt to view the connection table using the tmsh show sys connection all-properties command.

    For example, the tmsh show sys connection all-properties command shows two connection entries handled by different TMM processes; TMM0 handles the GRE IP tunnel packets while TMM1 handles the decapsulated packets:

Workaround

To work around this issue, you can configure the IP tunnel object with an explicit remote address instead of a wildcard. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you configure an IP tunnel that works best for your environment, and testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Tunnels > Tunnel List.
  3. Click on the name of the desired IP tunnel object.
  4. Select Specify for the Remote Address setting and enter an explicit IP address for the remote end of the IP tunnel object.
  5. To save the changes, click Update.
