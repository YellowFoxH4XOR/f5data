Introduction

The following video demonstrates the entire upgrade.

Upgrading BIG-IP VIPRION systems.

There are three parts to this upgrade:

  • Upgrading the first system
  • Changing the first system from standby to active
  • Upgrading the second system

Updating or upgrading standard VIPRION systems

These procedures upgrade an HA pair of standard, or "bare metal," VIPRION systems, which means they do not use the Virtual Clustered Multiprocessing (vCMP) feature. For information about upgrading VIPRION vCMP systems, refer to Chapter 11: Update or upgrade BIG-IP VIPRION systems (vCMP).

Leaving the system that you're updating or upgrading in Standby status instead of forcing it offline

When you are upgrading VIPRION systems, there are multiple reasons to leave the VIPRION system that you are upgrading in Standby status.

First of all, it is the easiest approach, given the Force Offline behavior of VIPRION systems.

Also, during the upgrade, when you reboot the standby system to the volume with the new software, it goes offline briefly. This period of time offline is shorter than when you force the peer system offline for the entire installation and rebooting process.

Lastly, should an event arise on the active system that prevents it from processing traffic, it can fail over to the one you are upgrading. The secondary system can process traffic while it is installing the upgrade.

For more information about the Force Offline behavior of VIPRION systems, refer to K15122: Overview of the Force Offline option for devices and traffic groups.

Upgrade vs. update

This chapter may use the word upgrade to refer to either a software upgrade or update. For a definition of that explains the difference between the two terms, refer to Upgrading vs. updating in the Introduction.

Prerequisites

Complete the following tasks before you start upgrading your VIPRION systems:

  • Verify that the management interface for each slot is physically wired to an external switch, so that you can maintain connectivity to the management port if the primary blade designation changes after you reboot to the boot location with the new upgrade.
  • Consult K9476: The F5 hardware/software compatibility matrix to ensure you upgrade to a BIG-IP version that is compatible with your VIPRION platform.
  • Consult K13845: Overview of supported BIG-IP upgrade paths and an upgrade planning reference to identify the BIG-IP versions that you can upgrade to from your current version of BIG-IP.
  • Review the release notes for the version you want to install.
  • F5 recommends that you reactivate the license before you upgrade. However, you can verify the service check date for the license to see if you need to reactivate it. For more information, refer to K7727: License activation may be required before a software upgrade for BIG-IP.
  • Consult K02251382: B2250 VIPRION Fails to boot After Upgrade to 13.1.3.3 or 13.1.3.4 if you have a VIPRION B2250 blade and you are upgrading your host to BIG-IP 13.1.3.3 or 13.1.3.4.

Update or upgrade the first system

Prepare to update or upgrade the first system

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Verify the configuration

Use the command line to verify the configuration of the system you are upgrading. If you are connecting to the main management IP address, ensure you are performing procedures on the primary slot.

  1. Log in to the command line for the system you are upgrading.
  2. Enter the following command:

    tmsh

  3. Enter the following command:

    load /sys config verify

  4. Check the output for any errors that indicate problems with the configuration.

Verify the service check date

Check the service check date on your BIG-IP license, if you have not done so already. For more information, watch the following video or refer to K7727: License activation may be required before a software upgrade for BIG-IP.

To watch a video demo of this procedure, go to Verifying the service check date and reactivating your BIG-IP license.

If you have automatic sync, and your devices report they are already in sync, you can skip this procedure.

  1. Log in to the Configuration utility for the system you are not upgrading.
  2. Go to Device Management > Overview.
  3. Under Device Groups, select the device group you want to sync.
  4. Under Devices, select the device with the most recent changes.
  5. Under Sync Options, select Sync Device to Group.
  6. Select Sync.

Create a UCS archive file

  1. Log into the Configuration utility for the system you are upgrading.
  2. Go to System > Archives > Add (+).
  3. Enter a name for the archive (UCS) file.
  4. Select Finished.
  5. Select OK.

Disable automatic sync

  1. Go to Device Management > Device Groups.
  2. Select the device group.
  3. Under Configuration, clear the Automatic Sync check box, if it is selected.
  4. Select Update.

Ensure the clusters are enabled and available

You can perform this procedure using the Configuration utility or the command line.

Using the Configuration utility

  1. Go to System > Clusters.
  2. At the bottom of the page, in the Status column, ensure the status for each slot displays as green.

Using the command line

  1. Enter the following command:

    tmsh

  2. Enter the following command:

    show /sys clu

  3. In the output, ensure the following:
    • Each address in the Address column is unique.
    • Items in the Availability column display available.
    • Items in the State column display enabled.

Import the software image

Import the software image for your upgrade into the BIG-IP system. For more information, watch the following video or refer to the Importing a new software image to the BIG-IP system section in K34745165: Managing software images on the BIG-IP system.

To watch a video demo of this procedure, go to Importing a software image into the BIG-IP system.

Ensure the software image is synchronized across all slots

  1. Enter the following command:

    clsh ls -1 /shared/images

    The system displays each slot.

  2. Ensure that the ISO file you just imported displays under each slot.

Updating or upgrading the first system

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Install the update or upgrade (new software)

You can perform this procedure using the Configuration utility and monitor the progress of the upgrade with the Configuration utility or command line.

Using the Configuration utility

  1. Go to System > Software Management > Image List.
  2. Under Available Images, select the ISO file you just imported.

    Note: F5 recommends that you upgrade to a version of BIG-IP that is no earlier than BIG-IP 14.1.2.6.

  3. Select Install.
  4. In Volume set name, enter a boot location for the upgrade or select an existing boot location from the list.
  5. Select Install.

    Under Installed Images, in the Install Status column, you can watch the progress of the overall upgrade.

  6. To see the installation progress on each blade, in the Install Status column, select Details.

    Under Image Installation Status, in the Progress column, you can watch the progress on each blade.

Using the command line to monitor the progress of the update or upgrade

  1. Enter the following command:

    watch "tmsh show sys sof status"

    In the Status column, you can watch the status of your upgrade on each slot.

  2. Select Ctrl+C to exit the watch command.

Verify the update or upgrade

To watch a video demo of this procedure, go to Upgrading BIG-IP VIPRION vCMP systems.

After the system finishes the installation, verify that the system installed the upgrade completely and across all slots in the chassis. You can perform this procedure using the Configuration utility or the command line.

Using the Configuration utility

  1. Log in to the Configuration utility for the system you are upgrading.
  2. Go to System > Software Management > Image List.
  3. Under Installed Images, in the row for the upgrade you just installed, under Install Status, ensure that the status displays as complete.
  4. To verify that the system installed the upgrade on all the slots, go to System > Disk Management.

    Note the tabs at the top of the page and that you are on the Slot 1 page.

  5. Select HD1.
  6. Under Contained Software Volumes, in the Version column, locate the upgrade you just installed.
  7. In the same row, under Status, ensure the status displays as complete.
  8. For each additional slot, select Disk Management again, select the tab for the slot, and repeat the previous three steps.

Using the command line

  1. Log in to the command line for the system you are upgrading.
  2. Enter the following command:

    tmsh

  3. Enter the following command:

    show /sys sof status

  4. In the output, in the Version column, ensure the upgrade you installed displays for all your slots.

Reboot to the volume with the update or upgrade (the updated or upgraded boot location)

  1. Go to System > Software Management > Boot Location.
  2. Under Boot Locations, select the location that has your new upgrade.
  3. Select Activate, and then select OK.

    The system restarts. If you are using a console to connect to each blade and you want to monitor the reboot, you can now establish each connection and log in to the command line.

Verify the boot location

Verify that the boot location is running the new software and functioning properly. You can perform this procedure using the Configuration utility or the command line.

Using the Configuration utility

  1. Log in to the Configuration utility for the system you are upgrading.
  2. Go to System > Software Management.
  3. Under Installed Images, in the row for the upgrade you just installed, under Active, ensure the system displays Yes.
  4. Select Local Traffic > Virtual Servers.
  5. Ensure the status for each virtual server displays as green.

    This status indicates the virtual servers are available, the monitors are working and sending out probes, and the nodes in your pool are responding and available.

  6. Go to System > Clusters.
  7. At the bottom of the page, in the Status column, ensure the status for each slot that you are using displays as green.
  8. Select the Management IP Addresses tab.
  9. In Cluster Member IP Address, ensure the IP addresses display correctly.

Using the command line

  1. Log in to the command line for the system you are upgrading.
  2. Enter the following command:

    tmsh

  3. Enter the following command:

    show /sys mcp-state

  4. In the system output, next to Last Configuration Load Status, ensure the system displays full-config-load-succeed.
  5. To check the clusters, enter the following command:

    show /sys clu

  6. Under Address, ensure the IP addresses display correctly and, under State, ensure the system displays enabled for each cluster.

Changing the updated or upgraded system from standby to active

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Fail over to the updated or upgraded system

Change the first system from standby to active by failing over to the upgraded system.

  1. Open the Configuration utility for the system you did not upgrade.
  2. Go to Device Management > Traffic Groups.
  3. Select the traffic group you want to force to Standby status, and then select Force to Standby.
  4. Under Force to Standby Options, in Target Device, ensure the system you upgraded displays, and then select Force to Standby.

    When the page refreshes, the system status displays as STANDBY.

Verify the updated or upgraded system is managing traffic

To ensure that traffic is flowing and applications are working on the system you upgraded, check traffic statistics.

  1. Open the Configuration utility for the system you upgraded.
  2. Go to Statistics > Module Statistics > Traffic Summary, and monitor the activity to ensure the system is passing traffic.
  3. Select the Local Traffic tab.
  4. Under Local Traffic Summary, ensure your objects display in the Available column.
  5. Under Display Options, in the Statistics Type list, select Virtual Servers.
  6. In the Connections column, ensure the virtual servers you expect to take traffic have current connections.

Updating or upgrading the second system

After you upgrade your first system and then make it the active system, upgrade the second system.

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Repeat the updating or upgrading process

  • Repeat all the steps you performed to upgrade the first system on the second system, except for the following steps:
    • Ensuring your devices are in sync
    • Disabling auto synchronization

Synchronize the configuration

To synchronize the systems after you upgrade, push the system configuration with them most recent changes to the group.

  1. Open the Configuration utility for the second system you upgraded.
  2. Go to Device Management > Overview.
  3. Select Sync.

Restore automatic sync

If you used the option to automatically sync your systems before the upgrade, restore the setting.

  1. Go to Device Management > Device Groups.
  2. Select the device group.
  3. Under Configuration, on the Sync Type list, select Automatic with Incremental Sync.
  4. Select Update.
