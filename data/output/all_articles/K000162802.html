K000162802: FTP LIST or MLSD requests may fail with TCP reset when FTP Protocol Security is enabled

Type
Support Solution
Published
2026-08-05
Updated
2026-09-10
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.0, 17.1.2, 17.1.1, 17.1.X, 17.5.X, 21.1.X, 21.1.0, 17.5.1, 17.5.0, 17.1.3
Source
https://my.f5.com/manage/s/article/K000162802

Description

 

When FTP Protocol Security is enabled in an LTM FTP profile associated with an FTP Virtual Server, FTP clients may be unable to complete passive-mode directory listing operations.

 

The FTP client may successfully establish the FTP control connection and authenticate, but directory listing commands such as LIST or MLSD may fail after the client enters passive mode.

 

Affected clients may report errors similar to:

 

  • Transfer connection interrupted: ECONNABORTED - Connection aborted
  • Failed to retrieve directory listing
  • 425 Error writing to file: ECONNABORTED - Connection aborted

A packet capture taken on BIG-IP may show BIG-IP sending a TCP reset with a message similar to:

 

  • Internal error (PSM::FTP requested abort (plugin abort error))

In another affected state, FTP connections may fail before login, and bd.log may contain:

 

  • HSL_PLUGIN|ERR|...|event_open: ***ERROR: Cannot get data profile info from DB

 

When FTP Protocol Security is disabled, the same FTP server and client may successfully complete the operation:

 

PASV

227 Entering Passive Mode (...)

 

MLSD

150 About to start data transfer.

226 Operation successful

 

or

 

LIST

150 About to start data transfer.

226 Transfer complete.

 

Environment

 

This issue may occur under the following conditions:

 

  • BIG-IP Advanced WAF / ASM is provisioned.
  • An FTP Virtual Server uses an LTM FTP profile.
  • Protocol Security is enabled in the LTM FTP profile.
  • An FTP Protocol Security profile is associated with the LTM FTP profile.
  • The FTP client uses passive FTP mode (PASV).
  • The client performs a directory listing or file transfer operation, such as:
    • LIST
    • MLSD
    • RETR
    • STOR
  • The LTM FTP profile has Inherit Parent Profile enabled.
  • Or, Protocol Security was disabled on an FTP profile, ASM was restarted while Protocol Security was disabled, and Protocol Security was re-enabled later.

 

 

Cause

 

This behavior can be caused by either of the following known issues.

 

  • Bug ID 700992.
    • FTP Protocol Security in PASV mode may send an unexpected TCP reset when the FTP profile inherits its parent settings.

 

  • Bug ID 2390849.
    • After Protocol Security is disabled on an FTP profile, ASM is restarted, and Protocol Security is re-enabled, the internal Virtual Server-to-FTP-profile association may not be restored. This can leave Protocol Security in an inconsistent configuration state and produce the following error:
      • HSL_PLUGIN|ERR|...|event_open: ***ERROR: Cannot get data profile info from DB

 

Answer/Recommended Actions

 

Apply the workaround that matches the observed condition.

 

1.- Disable parent profile inheritance

 

For the condition described in Bug ID 700992, disable Inherit Parent Profile on the affected LTM FTP profile.

 

Using tmsh:

 

tmsh modify ltm profile ftp <ftp_profile_name> inherit-parent-profile disabled

tmsh save sys config

 

For example:

 

tmsh modify ltm profile ftp ftp_security_profile inherit-parent-profile disabled

tmsh save sys config

 

Verify the configuration:

 

tmsh list ltm profile ftp <ftp_profile_name> all-properties

 

The output should include:

 

inherit-parent-profile disabled

security enabled

 

After the change, retest the FTP client connection and passive-mode directory listing operation.

 

2.- Reattach the FTP Protocol Security profile to the Virtual Server

 

For the condition described in Bug ID 2390849, reattach the FTP Protocol Security profile to the affected Virtual Server after Protocol Security is re-enabled.

Using the Configuration utility:

 

  1. Go to Local Traffic > Virtual Servers.
  2. Select the affected FTP Virtual Server.
  3. Select the Security tab.
  4. Under Protocol Security, select the applicable FTP Protocol Security profile.
  5. Click Update.
  6. Retest FTP connectivity and FTP data-channel operations.

 

This action repopulates the required Virtual Server-to-profile association used by FTP Protocol Security.

 

3.- Validate the result

 

After applying the applicable workaround, test with an FTP client using passive mode.

 

A successful sequence should include a passive-mode response followed by a successful completion response:

 

PASV

227 Entering Passive Mode (...)

 

MLSD

150 About to start data transfer.

226 Operation successful

 

or

 

LIST

150 About to start data transfer.

226 Transfer complete.

 

If the issue continues, collect the following information and contact F5 Support:

 

  • A qkview
  • /var/log/ts/bd.log
  • An FTP client log
  • A packet capture showing the FTP control connection and the passive FTP data connection
  • Output of:
    • tmsh list ltm profile ftp <ftp_profile_name> all-properties

 

 

 

Additional Information

 

FTP uses separate control and data connections.

  • The control connection commonly uses TCP port 21 and carries commands such as USER, PASS, PASV, LIST, and MLSD.
  • The data connection carries the directory listing or file content.
  • In passive mode, the server returns a 227 Entering Passive Mode response, and the client establishes the data connection to the advertised port.

The response:

 

150 About to start data transfer.

 

is an intermediate response. It does not indicate that a directory listing or file transfer completed successfully. A successful operation requires a final completion response, typically:

 

226 Transfer complete.

 

or:

 

226 Operation successful.

 

The informational bd.log message below only reports the number of active Protocol Security Manager jobs and is not, by itself, an error condition:

 

BD_MISC|NOTICE|...|PSM jobs: ftp <number> smtp <number>

 

The following message is significant and can indicate the missing internal FTP Virtual Server-to-profile association described in Bug ID 2390849:

 

HSL_PLUGIN|ERR|...|event_open: ***ERROR: Cannot get data profile info from DB
