K46666053: Missing BIG-IQ Web Application Security Events (ASM) Logging Data - Troubleshooting

Type
Support Solution
Published
2021-07-13
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K46666053

Description

A check list guide for troubleshooting missing BIG-IQ Web Application Security (ASM) events logging Data.

Environment

  • BIG-IQ CM
  • Data Collection Device
  • Managed ASM BIG-IP device
  • BIG-IQ Web Application Security (ASM) events logging collection enabled

Cause

None

Recommended Actions

  • Check the BIG-IQ cluster health status of the ElasticSearch (ES) service
  • Validate BIG-IQ ASM remote storage logging profile configuration(s) and the DCD server addresses selected for data collection
  • Identify the DCD device(s) configured for ASM Web Application Security events data collection while ensuring activated WAS services
  • Ensure all DCD device(s) with Web Application Security service (WAS) activated have a listening TCP port of 8514
  • Check the avrd config settings of the managed ASM device
  • Check the netstat table of the managed BIG-IP ASM device
  • Check for the existence of the 'asmindex_writer' record within the BIG-IQ ElasticSearch aliases table
  • Check ElasticSearch asmindex record 'docs.count' values for indicators of successful data logging processing
  • Deactivate / Activate Web Application Security service for all DCD devices
  • Tcpdump data collection

Check the BIG-IQ cluster health status of the ElasticSearch (ES) service  

Important: On BIG-IQ v8.0 and newer, we have enabled TLS encryption between ElasticSearch nodes in the cluster. This means that you'll need to add the "-k" flag to the curl command, and prepend "https://" to the URL.

  1. On the Main tab of the BIG-IQ, click System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Cluster > Summary > Status.

           To obtain cluster health status information using TMSH, enter the following command:

            # curl -s localhost:9200/_cluster/health?pretty
        or
      # curl -s -u admin:admin -k https://localhost:9200/_cluster/health?pretty 
  
Note: The cluster health status is: green, yellow or red. On the shard level, a red status indicates that the specific shard is not allocated in the cluster, yellow means that the primary shard is allocated but replicas are not, and green means that all shards are allocated. A red cluster status requires immediate attention for resolution..

Validate BIG-IQ ASM remote storage logging profile configuration(s) and the DCD server addresses selected for data collection

  1. On the Main tab of the BIG-IQ, click Configuration >  Web Application Security > Shared Security >  Logging Profiles.
  2. The Logging Profiles list screen opens.
  3. Access the properties of a Logging Profile Name.
  4. Select the Application Security option on the left hand column.

Identify the DCD device(s) configured for ASM Web Application Security events data collection while ensuring activated WAS services

BIG-IQ Centralized Management requires Web Application Security service activation to be enabled for viewing Web Application Security event logs. 

  1. At the top of the screen of the BIG-IQ, click System, then, on the left, click BIG-IQ DATA COLLECTION >>  BIG-IQ Data Collection Devices.
       The BIG-IQ Data Collection Devices screen opens listing the data collection devices in the cluster. The Services column lists the BIG-IP services monitored by each DCD.
  2. Access the properties of the desired DCD device(s) by selecting on the Device Name.
       The properties screen for the data collection device opens.
  3. Select the SERVICES option on the left hand column. 
       The screen displays a listing of available services.
  4. For the Web Application Security (WAS) service, confirm that the Listener Address and Listener Port are correctly set and activated.

Ensure all DCD device(s) with Web Application Security service (WAS) activated have a listening TCP port of 8514 

  1. Log in to the DCD Advanced Shell (bash) as an administrator.
  2. Review the results of the netstat command in search of listing TCP port of 8514. 

  # netstat -pant |grep 8514

  Proto Recv-Q Send-Q Local Address           Foreign Address                 State       PID/Program name
  tcp        0      0 :::8514                     :::*                        LISTEN      4845/java

   
Note: If the DCD is listening on TCP port 8514 but with no established connections from one or more BIGIP ASM device(s) then please ensure that TCP port 8514 is allowed between all intermediate Firewall devices. 

Established connection(s) over TCP port 8514 seen from one or more managed BIGIP ASM devices to the target DCD device(s) are good indicators of successful establishments:

# netstat -pant |grep 8514

Proto Recv-Q Send-Q Local Address           Foreign Address                 State       PID/Program name
tcp        0      0 :::8514                     :::*                        LISTEN      4845/java
tcp        0      0 ::ffff:10.155.24.120:8514   ::ffff:10.155.24.106:46948  ESTABLISHED 4845/java <=== Connected ASM BIG-IP device
 

Check the avrd config settings of the managed ASM device

Note: The example BIG-IP ASM configuration below indicates this device as being managed by BIG-IQ. The offbox-tcp-addresses indicates the DCD node IP address where the ASM events log data are sent for processing.

# tmsh list analytics global-settings

[api-status-warning] analytics/global-settings, properties : deprecated : ecm-port
analytics global-settings {
    avrd-interval 30
    ecm-port 443
    enable-bigiq-configuration enabled
    offbox-protocol https
    offbox-tcp-addresses { 10.155.24.120 } <===!!!
    offbox-tcp-port 443
    source-id 11be9916-2cf9-403c-b215-442decc808f5_10.155.24.106
    use-offbox enabled
}

Check the netstat table of the managed BIG-IP ASM device 

  1. Log in to the BIG-IP ASM Advanced Shell (bash) as an administrator.
  2. Review the results of the netstat command in search of an Established connection to the target DCD device over TCP port 8514. 

# netstat -pant |grep 8514

Proto Recv-Q Send-Q Local Address           Foreign Address         State       PID/Program name
tcp6       0      0 10.155.24.106:46948     10.155.24.120:8514      ESTABLISHED 20506/./bd

Check for the existence of the 'asmindex_writer' record within the BIG-IQ ElasticSearch aliases table

Note: There should only exist one 'asmindex_writer' record. There can exist one or more 'asmindex' records. 

# curl -s localhost:9200/_cat/aliases?v |grep -i asm
  or
# curl -s -u admin:admin -k https://localhost:9200/_cat/aliases?v |grep -i asm

asm-correlation            asm-correlation_2020-04-21t04-23-25-0700     -      -             -
asm-correlation_writer     asm-correlation_2020-04-21t04-23-25-0700     -      -             -
asmindex                   asmindex_2020-04-21t04-24-12-0700            -      -             - <----!!!! System reads from. 
asmindex_writer            asmindex_2020-04-21t04-24-12-0700            -      -             - <----!!!! System writes to.


Note: The asmindex_writer points to the latest asmindex record. In the example above, the latest asmindex recorder written to by the Elasticsearch service is: asmindex_2020-04-21t04-24-12-0700

Check ElasticSearch asmindex record 'docs.count' values for indicators of successful data logging processing

In the example below, the 7th column displays a docs.count value of 12 for the asmindex_2020-04-21t04-24-12-0700 record. The docs.count value should be seen increasing in value should one continue to iterate through the same curl command frequently. 

# curl -s localhost:9200/_cat/indices?v |grep -i asmindex_2020-04-21t04-24-12-0700 
  or
# curl -s -u admin:admin -k https://localhost:9200/_cat/indices?v |grep -i asmindex_2020-04-21t04-24-12-0700 

health status index                                        uuid                   pri rep docs.count docs.deleted store.size pri.store.size
yellow open   asmindex_2020-04-21t04-24-12-0700            clL-xdqeQi2spGOAemejKg   5   1         12            0    200.8kb        200.8kb

Deactivate / Activate Web Application Security service for all DCD devices

  1. At the top of the screen of the BIG-IQ, click System, then, on the left, click BIG-IQ DATA COLLECTION >>  BIG-IQ Data Collection Devices.
    The BIG-IQ Data Collection Devices screen opens listing the data collection devices in the cluster. The Services column lists the BIG-IP services monitored by each DCD.
  2. Access the properties of the desired DCD device(s) by selecting on the Device Name.
    The properties screen for the data collection device opens.
  3. Select the SERVICES option on the left hand column. 
     The screen displays a listing of available services.
  4. For the Web Application Security (WAS) service, click Deactivate.

Note. Once the WAS service has been deactivated, check the netstat table against all DCD devices ensuring no listening TCP ports of 8514. Once confirmed, activate the WAS service for all DCD devices ensuring a returned listening TCP port of 8514.. 

# netstat -pant |grep 8514

Tcpdump data collection

Obtain concurrent captures from both a BIG-IP ASM device as well as from the target DCD device it will send the events to.

# tcpdump -s0 -nni <vlan_name> port 8514 -s0 -w /var/tmp/$HOSTNAME_WAS.pcap -v
