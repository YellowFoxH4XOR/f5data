Description

Configuration failed to load, with one or more of the following errors when issuing a load sys config:

01070920:3: Application error for confpp: Starting syslog-ng: Job for syslog-ng.service failed because the control process exited with error code. See "systemctl status syslog-ng.service" and "journalctl -xe" for details.

Error: failed to reset strict operations; disconnecting from mcpd. Will reconnect on next command.

Data Input Error: 01070734:3: Configuration error: Current folder /<folder> has been removed. Exit session.

The syslog-ng process does not start successfully, so no log files contain useful information, but reviewing the systemd journal with journalctl reveals errors similar to the following:

syslog-ng[<pid>]: [<time>] Error opening control socket, bind() failed; socket='/var/lib/syslog-ng/syslog-ng.ctl', error='No such file or directory (2)'
syslog-ng[<pid>]: [<time>] Error creating persistent state file; filename='/var/lib/syslog-ng/syslog-ng.persist-', error='No such file or directory (2)'
systemd[1]: syslog-ng.service: main process exited, code=exited, status=2/INVALIDARGUMENT
systemd[1]: Failed to start System Logger Daemon.
systemd[1]: Unit syslog-ng.service entered failed state.
systemd[1]: syslog-ng.service failed.
systemd[1]: syslog-ng.service holdoff time over, scheduling restart.

Environment

  • syslog-ng
  • Configuration load

Cause

syslog-ng is unable to write to /var/lib/syslog-ng.

Recommended Actions

Investigate why syslog-ng is unable to write to the /var/lib/syslog-ng directory. Permissions or security contexts may be incorrect, or the directory may not exist at all.

The directory can be recreated if it does not exist:

mkdir -v /var/lib/syslog-ng
chcon system_u:object_r:syslogd_var_lib_t:s0 /var/lib/syslog-ng

However, investigation should be performed into how and why this directory was modified or removed. If the root cause is not known, a clean install may be the best option, in case there are other important files altered or missing on the filesystem.

Additional Information

This issue could occur even with no non-default syslog configuration defined.

The output of systemctl status syslog-ng will be similar to the following example when this issue occurs:
