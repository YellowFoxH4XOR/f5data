Topic

This article applies to WebAccelerator 9.4 through 11.3.0 . For information about Application Acceleration Manager , refer to the following article:

  • K14453: Information required when opening a support case for BIG-IP Application Acceleration Manager

Note: For information about the information required when opening a support case for other F5 products, refer to K2633: Instructions for submitting a support case to F5.

F5 Technical Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration. To help you gather all the required information, use the following guidelines to prepare for opening a case:

General Information

Provide the following information when you open a case with F5 Technical Support:

  • A full description of the issue, including the following:

    • The symptoms of the issue
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the WebAccelerator appliance
    • Steps to reproduce the issue
    • Any changes you made to the WebAccelerator appliance before the issue first occurred
    • Any steps you have taken in an attempt to resolve the issue
  • A description of the impact that the issue is having on your system and site, using the following definitions:

    • Site Down

      Your network or application is down or critical business functions have stopped due to the issue.

    • Site at Risk

      Your network or application is severely and negatively impacted by the issue.

    • Performance Severely Degraded

      The performance of your network or application has been severely reduced due to the issue.

    • Performance Impaired

      Your network or application is suffering from reduced performance, but otherwise continues to work as expected.

    • General Assistance Required

      The subject of the case does not currently impact your network or application.

  • The hours that you are available to work on the issue with an F5 Technical Support Representative, and any alternative individuals to contact who are aware of the issue, in the event you are unavailable.
  • Remote access information, if possible.

    Note: Remote access to your network environment is important, because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access information, F5 Technical Support will work directly with you to resolve the issue over the phone; however, this method can often be more time consuming and may require file transfers, replication, and additional testing.

Product-specific information

Collect the following information from the affected system and provide it when you open the case. For information about sending this information to F5 Technical Support, refer to K2486: Providing files to F5 Technical Support.

  • A tech.out file

    A tech.out file contains the configuration files that F5 Technical Support most frequently needs when troubleshooting an issue. A tech.out file is produced by the qkview utility and the terms tech.out and qkview may be used interchangeably.

    Note: Additional BIG-IP WebAccelerator information is included in the tech.out file when the qkview utility is performed from the command line. F5 Technical Support requests a tech.out file be obtained using the command line method for BIG-IP WebAccelerator issues.

    Note: For more information about qkview, refer to the following articles:

    K1858: Overview of the qkview utility (9.x)

    K12878: Generating BIG-IP diagnostic data using the qkview utility (10.x - 11.x)

  • Provide an explanation of the BIG-IP WebAccelerator deployment topology (asymmetrical or symmetrical including number of accelerators). A Visio network diagram is preferable.
  • Provide any tcpdump information taken from the command line of the impaired traffic and of the normal traffic, if possible, if the issue involves network traffic. Similar session captures from tools like Mozilla LiveHTTPHeaders or Simtec's HTTPWatch are recommended, as well.
  • Provide an XML export of any relevant policies. Policies can be exported individually from the Polices page of the Admin Tool Web UI.
  • On v9.x and v10.x, perform and provide a dump of the WebAccelerator database.

    Note: For more information, refer to K6711: Dumping the WebAccelerator database for use in a support case.

  • For BIG-IP WebAccelerator 9.4.x and 10.x systems, provide the following configuration, log, and performance report data files:

    • /config/wa/*
    • /var/log/wa/*
    • /var/lib/mysql/WA/PERFMONITOR_DATA.MYD
    • /var/lib/mysql/WA/PERFMONITOR_DATA.MYI
    • /var/lib/mysql/WA/PERFMONITOR_DATA.frm
    • /var/log/tomcat*

    You can collect the previously-listed files into a single tar file by typing the following command:

    Note: The following command should be typed in one continuous string; it has been split into two lines in this article for formatting purposes only.

    tar czvpf /var/tmp/wa.config-data.tgz /config/wa /var/lib/mysql/WA/PERFMONITOR_DATA.* /var/log/wa /var/log/tomcat*

  • If the WebAccelerator pvac (v9.x/v10.x)  or wamd (v11.x) daemon is experiencing performance issues, provide the result of a continuous top command. Type the following command, and provide the file produced:

    top -cbn 10 -d 1 > /var/tmp/top_output.sol6705.txt

  • On V9.x and V10.x BIG-IP hosts, provide a snapshot of WebAccelerator-specific SNMP information from the system. Type the following command, and provide the /var/tmp/snmpwalk_output.sol6705.txt file produced:

    Note: The following command should be typed in one continuous string; it has been split into two lines in this article for formatting purposes only.

    /usr/bin/snmpwalk -M /usr/local/wa/mib/ -v 2c -c public localhost:12406 .1.3.6.1.4.1.3375.14.4 > /var/tmp/snmpwalk_output.sol6705.txt

You can transfer files from the BIG-IP WebAccelerator to another system using either the ftp or scp utilities.
