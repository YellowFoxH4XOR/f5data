Topic

This article applies to BIG-IP 12.x through 21.x. For information about other versions, refer to the following article:

  • K13250: Overview of port lockdown behavior (10.x - 11.x)

For information about port lockdown on the BIG-IQ system, refer to K39403510: Managing the port lockdown configuration on the BIG-IQ system.

Port lockdown is a BIG-IP security feature that allows you to specify particular protocols and services from which the self IP address defined on the BIG-IP system can accept traffic.

Description

The port lockdown feature allows you to secure the BIG-IP system from unwanted connection attempts by controlling the level of access to each self IP address defined on the system. Each port lockdown list setting, defined later in this document, specifies the protocols and services from which a self IP can accept connections. The system refuses traffic and connections made to a service or protocol port that is not on the list.

Port lockdown exceptions

  • TCP mirroring ports: The BIG-IP system maintains a separate mirroring channel for each traffic group. The port range for each connection channel begins at TCP 1029 and increments by one for each new traffic group and channel created. The BIG-IP system allows TCP ports 1029 through 1155.
  • TCP port 4353: When BIG-IP devices are configured in a synchronization group, peer devices communicate using Centralized Management Infrastructure (CMI) on tcp:4353 on the self IP address, regardless of the port lockdown settings.

    Note: CMI uses the same port as iQuery tcp:4353 but is independent of iQuery and the port configuration options available for the port. Because :4353 traffic is always permitted to the configured ConfigSync IP address, this also allows iQuery traffic (if iQuery is configured to connect to the ConfigSync IP address). In all other cases, in order for iQuery to be able to connect, you must specifically permit tcp/4353 in the port lockdown settings.

  • ICMP: Internet Control Message Protocol (ICMP) traffic to the self IP address is not affected by the port lockdown list and is implicitly allowed in all cases.
  • Defined Virtual Servers override port lockdown setting for the traffic that they service.

Note: In most cases, it is not possible to ping self IP addresses across VLANs. For more information, refer to K3475: The BIG-IP system may not respond to requests for a self IP address.

Port lockdown setting definitions

Allow Default

This option allows access for a pre-defined set of network protocols and services that are typically required in a BIG-IP deployment.

The Allow Default setting specifies that connections to the self IP address are allowed from the following protocols and services.

tmsh list net self-allow

The output appears similar to the following example:

Allow All

This option specifies that all connections to the self IP address are allowed, regardless of protocol or service.

Note: F5 recommends avoiding the use of Allow All because this setting increases the security risk to the system. Instead, it is recommended to use Allow Custom if you are requiring additional ports to be permitted.

Allow None

This option specifies that no connections are allowed on the self IP address, regardless of protocol or service. However, ICMP traffic is always allowed, and if the BIG-IP systems are configured in a redundant pair, ports that are listed as exceptions are always allowed from the peer system.

Allow Custom

This option allows you to specify the protocols and services for which connections are allowed on the self IP address. However, ICMP traffic is always allowed, and if the BIG-IP systems are configured in a redundant pair, ports that are listed as exceptions are always allowed from the peer system.

Allow Custom (Include Default)

This option allows you to specify the protocols and services for which connections are allowed on the self IP address, in addition to the default protocols and services. However, ICMP traffic is always allowed, and if the BIG-IP systems are configured in a redundant pair, ports that are listed as exceptions are always allowed from the peer system.

Default port lockdown setting

When creating self IP addresses using the Configuration utility or the TMOS Shell (tmsh), the default port lockdown setting is Allow None.

Procedures

To watch a video demo of this procedure, go to Modify Port Lockdown settings for self IPs to Allow Default.

Use the Configuration utility to modify port lockdown settings for a specific self IP

  1. Log in to the Configuration utility.
  2. Go to Network > Self IPs.
  3. Select the relevant self IP address.
  4. For Port Lockdown, choose the setting you want to use.
  5. Select Update.

Use tmsh to modify port lockdown settings

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the port lockdown settings for a self IP address, use the following command syntax:

    modify /net self <self_IP_name> allow-service <option>

    For example, to change the port lockdown setting for self IP address 10.10.10.1 to default, enter the following command:

    modify /net self 10.10.10.1 allow-service default

    Note: If you named your self IPs as opposed to using the IP address for the name, they must be referenced by name. You can find the names of your self IPs using the following command:
    list /net self
    This will result in output that appears similar to the following:
    net self internal {
        address 10.10.10.1/24
        allow-service all
        traffic-group traffic-group-local-only
        vlan internal_vlan
    }
     In this example your modify command is:
    modify /net self internal allow-service default

  3. Save the change by entering the following command:

    save sys config

Important: If ltm nat (but not ltm snat) is configured to translate a self IP address, the translation address unconditionally accepts traffic and delivers it to the Linux host, regardless of port lockdown settings. Although function is by design, BIG-IP administrators may not expect this behavior. For more information, refer to K49217123: The use of "ltm nat" can unexpectedly allow traffic to reach the Linux host.

Recommendations

For optimal security, F5 recommends that you use the port lockdown feature to allow only the protocols or services required for a self IP address.

If you must expose protocols or services on your self IP addresses but want to restrict access to specific IP ranges, you may consider using the packet filtering functionality built in to the BIG-IP system. For more information, refer to K13383: Configuring CIDR Network Addresses for the BIG-IP packet filter

Configure port lockdown settings for network failover in a High Availability device group

For optimal security, when configuring for high availability (HA) network failover, F5 recommends the following when configuring the Port Lockdown setting:

Note: When BIG-IP devices are configured in a synchronization group, peer devices communicate using Centralized Management Infrastructure (CMI) on tcp:4353 on the self IP address, regardless of the port lockdown settings. Refer to the Port lockdown exceptions section of this article for additional information.

  • Do not use Allow All.
  • Use Allow Default if HA network failover is required. For more information, refer to K2397: Comparison of hardwired failover and network failover features.
  • Using the Allow Default configuration for any self IP address that is not used for HA network failover may expose unnecessary protocols or services and may constitute a security risk.
  • Alternatively, use Allow Custom and configure it to allow the UDP protocol on port 1026.
  • When hardwired failover is available and HA network failover is not required, use Allow None.
