Known Issue

BIG-IP APM Security Assertion Markup Language (SAML) service provider (SP) access profile Identity Provider (IdP) authentication may fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM virtual server references an access profile configured as a SAML SP.
  • The BIG-IP APM configured virtual server receives an IdP initiated assertion.

Impact

SP authentication may fail for the IdP assertion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H486399 on the Diagnostics > Identified > High screen.
  • When an IdP sends an assertion to the BIG-IP APM SP-configured virtual server, the system returns an error message similar to the following example:

    "Your session could not be established."

  • When you view the HTTP events for the IdP's first attempt to send an assertion to the BIG-IP APM system, the system returns the following 302 response:

    Redirection to: /vdesk/hangup.php3" ia received from the BIG-IP APM in the "HTTP 302 response" to "GET /my.policy"

  • In the /var/log/apm file, you see messages similar to the following example, for the session attempt, when the service apd is set to debug mode:

    notice tmm[9931]:01490500:5: f1d98ef3: New session from client IP 192.168.0.131 (ST=WA/CC=US/C=US) at VIP 172.16.2.5 Listener /Common/sp.somesite.com (Reputation=Unknown)
    debug apd[6307]: 01490000:7: modules/Authentication/Saml/SamlSPAgent.cpp func: "SamlSPAgentexecuteInstance()" line: 811 Msg: IdP Initiated: SAMLResponse: [...]
    info apd[6307]: 01490004:6: f1d98ef3: Executed agent '/Common/test-saml_act_saml_auth_ag', return value 0
    debug apd[6307]: 01490000:7: ./AccessPolicyProcessor/SessionState.h func: "clearTempSessionAgentState()" line: 86 Msg: Agent did not initiated the scheduled agent
    debug apd[6307]: 01490000:7: AccessPolicyProcessor/AccessPolicy.cpp func: "execute()" line: 290 Msg: Let's evaluate rules, total number of rules for this action=2
    debug apd[6307]: 01490000:7: AccessPolicyProcessor/AccessPolicy.cpp func: "execute()" line: 296 Msg: Rule to evaluate = "expr {[mcget {session.saml.last.result}] == 1}"
    debug apd[6307]: 01490000:7: AccessPolicyProcessor/AccessPolicy.cpp func: "execute()" line: 296 Msg: Rule to evaluate = ""
    notice apd[6307]: 01490005:5: f1d98ef3: Following rule 'fallback' from item 'SAML Auth' to ending 'Deny'

  • A second attempt by the IdP to send the assertion to the BIG-IP APM SP-configured virtual server is successful.
  • When you view the HTTP events for the IdP's second attempt to send an assertion to the BIG-IP APM system, the system returns the following 302 response:

    Redirection to: the appropriate web resource redirection is sent in the BIG-IP APM "HTTP 302 response" to "GET /my.policy".

  • In the /var/log/apm file, you see messages similar to the following example, for the session attempt, when the service apd is set to debug mode:

    notice tmm[9931]: 01490500:5: b7a5d327: New session from client IP 192.168.0.131 (ST=WA/CC=US/C=US) at VIP 172.16.2.5 Listener /Common/sp.somesite.com (Reputation=Unknown)

Resolution

Status

F5 Product Development has assigned ID 457925 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release11.6.0K2200: Most recent versions of F5 software
Hotfix11.5.1 HF5
11.4.1 HF6		K9502: BIG-IP hotfix matrix

Workaround

To work around this issue, you can configure authentication to be SP initiated. For additional information, refer to the Using APM as a SAML Service Provider chapter of the BIG-IP Access Policy Manager: Authentication and Single Sign-On guide.
