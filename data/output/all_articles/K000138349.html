K000138349: Import of security policy in xml may fail because of <sig_tag_policy_val/>

Type
Support Solution
Published
2024-04-29
Updated
2024-08-26
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.0, 17.1.1
Source
https://my.f5.com/manage/s/article/K000138349

Description

After an upgrade to 17.1.x.x importing ASM policy in XML format fails.

In the ASM logs you may see log entries similar to the following:

The security policy file does not conform to the schema and cannot be imported. (line 3444: element sig_tag_policy_val: Schemas validity error : Element 'sig_tag_policy_val': This element is not expected.

line 3471: element sig_tag_policy_val: Schemas validity error : Element 'sig_tag_policy_val': This element is not expected.

line 3498: element sig_tag_policy_val: Schemas validity error : Element 'sig_tag_policy_val': This element is not expected.

Environment

  • After upgrade to 17.1.x.x
  • Importing ASM policy in XML format
  • A Filter-based type user defined signature set is in use.

Cause

Bug ID 1382365: XML policy import fails due to corrupted user-defined Signature Set definition

Recommended Actions

  • Check the that ASM policy contains

$ cat <ASM_policy_name>.xml | egrep 'sig_tag_policy_val'

<sig_tag_policy_val/>
<sig_tag_policy_val/>
<sig_tag_policy_val/>

  • Delete '<sig_tag_policy_val/>' on the xml file.

$ sed '/sig_tag_policy_val/d' <ASM_policy_name>.xml > <ASM_policy_name>_validated.xml

  • Double-check the tags are gone :

$ egrep -i 'sig_tag_policy_val' <ASM_policy_name>_validated.xml | wc -l

0 <---

  • Re-import the policy
