K000160841: BGP routes installed into kernel routing table on BIG-IP when you expect not to be installed

Type
Support Solution
Published
2026-04-17
Updated
2026-04-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 17.1.2, 17.1.1, 17.5.X, 17.1.X, 17.5.1, 17.5.0, 17.1.3
Source
https://my.f5.com/manage/s/article/K000160841

Description

BGP routes are installed into the kernel routing table or TMM routing table when you expect not to be installed.

Example

On a device, a subset of BGP routes are installed into the kernel routing table and visible using the following commands:

ltm.lab.com[0]# show ip bgp | begin Network
...skipping
   Network            Next Hop            Metric     LocPrf     Weight Path
  *>i10.104.87.128/27 10.104.87.162          0        100            0 i
Total number of prefixes 1

[admin@ltm:Active:Standalone] ~ # ip route | grep zebra
10.104.87.128/27 via 10.10.126.5 dev External  proto zebra

[admin@ltm:Active:Standalone] ~ # tmsh show net route | grep dynamic
10.104.87.128/27      10.104.87.128/27      gw         10.10.126.5           dynamic

A default route is configured via TMM and a BGP neighbor is reachable via this default route:

[admin@ltm:Active:Standalone] ~ # tmsh list net route default_route
net route default_route {
    gw 10.10.126.5
    network default
}

BGP neighbor summary:

ltm.lab.com[0]# show ip bgp summary | begin Neighbor
...skipping
Neighbor        V    AS MsgRcvd MsgSent   TblVer  InQ OutQ Up/Down  State/PfxRcd
10.104.87.162   4   200      21      20        2    0    0 00:08:49        1
Total number of neighbors 1

Additionally, a static route is also configured via the same gateway as the default route for the BGP neighbor, making it explicitly resolvable:

net route static {
    gw 10.10.126.5
    network 10.104.87.162/32
}

Environment

  • BIG-IP LTM
  • Advanced Routing Module (ARM) licensed

Cause

The presence of a static route to the BGP next-hop allows the next-hop to be explicitly resolved, resulting in BGP routes being installed into TMM.
Without this static route, BGP routes remain only in the BGP table and are not installed into the kernel routing table.

Recommended Action

To control whether BGP routes are to be installed into the kernel routing table you can perform either of the following:

 

  1. Remove the static route to the BGP neighbor/next-hop IP address.
    # tmsh delete net route <route_name>
# tmsh save sys config
  2. If a static route is needed and you still need to block BGP route installation, a route-map deny inbound statement in BGP could help.

    For example: 
    ltm.lab.com[0]# show running-config access-list
!
access-list 1 permit 10.104.87.162
!
ltm.lab.com[0]# show running-config route-map
!
route-map BLOCK_from_10_104_87_162 deny 10
 match ip address 1
!
ltm.lab.com[0]# show running-config bgp
!
router bgp 200
 bgp router-id 10.1.1.1
 bgp log-neighbor-changes
 bgp graceful-restart restart-time 120
 neighbor 10.104.87.162 remote-as 200
 neighbor 10.104.87.162 route-map BLOCK_from_10_104_87_162 in
!

Note: If your configuration or services rely on BGP routes being installed into TMM, review dependencies before removing static routes or filtering routes at BGP.
