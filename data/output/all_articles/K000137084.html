Description

Sometimes, when vCMP guests are started after the vCMP host or guest has been upgraded, the guests may enter an unhealthy state due to clusterd constantly restarting.

Environment

  • BIG-IP
  • vCMP guest
  • vcmp HOST or vcmp GUEST upgrade

Cause

Bug ID 935633: The vCMP guests may experience constant clusterd restart after vCMP host upgrade

Recommended Actions

To prevent this issue from occurring in the vCMP GUEST, after the vCMP HOST upgrade:

1. Prior to shutting down vCMP guests before vCMP host upgrade, ensure guests have free space in the /var partition.

2. Issue 'tmsh save sys config' on the vCMP guest.

3. Issue 'ls /var/db/mcp*' and confirm the presence of mcpdb.bin and mcpdb.info in the /var/db directory.

4. Proceed with vCMP guest shutdown and vCMP host upgrade as per standard F5 recommended process.

 

To prevent this issue from occurring in the vCMP GUEST, after the vCMP GUEST upgrade, remove the mirror-ip from the guest before upgrading, and add it back after the upgrade:

From GUI set the Mirror Address to None before the upgrade, and back to desired self IP after the upgrade:
1. Device Management  ››  Devices  ››  <name> ›› Mirroring
2. Primary Local Mirror Address: None
3. Secondary Local Mirror Address: None

From CLI:
1. Check the settings of mirror IP:
list cm device <name> mirror-ip
list cm device <name> mirror-secondary-ip

2. Remove the mirror-ip:
modify cm device <name> mirror-ip any6
modify cm device <name> mirror-secondary-ip any6
save sys config

3. Confirm there is no mirror ip configured:
list cm device <name> mirror-ip
cm device name {
    mirror-ip any6
}

list cm device <name> mirror-secondary-ip
cm device name {
    mirror-secondary-ip any6
}

4. After the upgrade, set the mirror ip back:
modify cm device <name> mirror-ip <ip>
save sys config

5. confirm mirror ip configured:
list cm device <name> mirror-ip
cm device name {
    mirror-ip x.x.x.x
}

To mitigate after the issue has been experienced on a vCMP GUEST:

1. Set the vCMP guest to the Configured state and wait for it to complete transition to Configured.

2. Set vCMP guest to Deployed state.

3. Review boot up log and confirm 'Self-device state mirroring address cannot reference the non-existent Self IP' message is no longer present.

4. Review /var/log/ltm and confirm clusterd is no longer restarting.

5. If issue persists, delete and recreate the vCMP guest
