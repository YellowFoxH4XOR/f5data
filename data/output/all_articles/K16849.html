K16849: Unprovisioning the BIG-IP AFM module leaves Firewall Mode as last configured

Topic

On the BIG-IP AFM system, if you configure the default firewall action for the Virtual Server & Self IP Context feature to use the Reject or Drop settings, and subsequently unprovision the AFM module, the BIG-IP system does not remove the default firewall action for the Virtual Server & Self IP Context configuration and continues to reject or drop traffic. This behavior is by design for the purpose of securing the device as configured.

The default firewall action for the Virtual Server & Self IP Context feature can be configured from the Configuration utility's Security > Options > Network Firewall > Firewall Options menu. This menu is only accessible when the BIG-IP system has the AFM module licensed and provisioned.

For more information about configuring the BIG-IP Network Firewall with the Virtual Server & Self IP Context feature, refer to the About the Network Firewall chapter of the BIG-IP Network Firewall: Policies and Implementations guide.

Recommendations

When the AFM module is not provisioned on the BIG-IP system, you cannot view or modify the Network Firewall options from the Configuration utility. However, you can view the default firewall action of the BIG-IP system by using the following Traffic Management Shell (tmsh) command:

list /sys db tm.fw.defaultaction

You can also modify the default firewall action on the BIG-IP system by using a tmsh command. If the default firewall action was previously set to Reject or Drop, you can set it back to Accept by using the following tmsh command:

modify /sys db tm.fw.defaultaction value accept
