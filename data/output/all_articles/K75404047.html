Known Issue

Access sessions established with HTTP/2 may unexpectedly terminate.

This issue occurs when all of the following conditions are met:

  • You configure a virtual server with an access profile and an HTTP/2 profile.
  • A user establishes an access session with an HTTP/2-enabled browser.
  • The user is actively using the access session (traffic is being processed).

Impact

The access session unexpectedly terminates.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The access session terminates even when it is processing traffic.
  • From the Configuration utility, when you navigate to Access Policy > Manage Sessions, you notice that access session Bytes In / Bytes Out values never increment (they stay at zero).
  • When the access session terminates, you observe log messages in the /var/log/apm file that appear similar to the following example:

    notice tmm1[<pid>]: 01490502:5: /<partition>/<access profile name>:<partition>:<sessionid>: Session deleted due to user inactivity.
    notice tmm1[<pid>]: 01490521:5:/<partition>/<access profile name>:<partition>:<sessionid>: Session statistics - bytes in: 0, bytes out: 0
