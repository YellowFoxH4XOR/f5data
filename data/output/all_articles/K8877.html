K8877: The global server FQDN domain extension must match the Windows Active Directory domain

Topic

The ARX global server Fully Qualified Domain Name (FQDN) domain extension must match the Microsoft Windows Active Directory (AD) domain. If the ARX global server name is not an FQDN, or does not match the Microsoft Windows AD domain, clients cannot create new Access Control Entries (ACEs) on files and folders accessed with that global server. Client access with the global server may appear to function normally. However, when a client attempts to use Windows Explorer to add an ACE to a file or folder, the list of locations from which to select users and groups will not contain the appropriate AD hierarchy.

For example, if the ARX CIFS service joined the askf5.com domain, the ARX global server name must be an FQDN within the askf5.com domain, such as arxgs.askf5.com. Clients cannot create new ACEs on files and folders accessed with the global server if the ARX global server name is not an FQDN (such as arxgs), or is an FQDN for a different domain (such as arxgs.notaskf5.com).

If the ARX global server name is not an FQDN, or is an FQDN for a different domain, you cannot rename the global server. You must create a new global server using an FQDN within the Windows domain joined by the CIFS service.

Note: For more information, refer to the CLI Storage Management Guide.
