Known Issue

Keep-Alive packets may fail to resume after a failover event.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured as a high-availability pair.
  • The virtual server has connection mirroring enabled.
  • The associated FastL4 profile is configured with the TCP Keep Alive Interval option.
  • A failover occurs.
  • Traffic resumes for the mirrored connections after the failover event, which allows the system to identify the correct TCP sequence numbers.
  • The mirrored connections are then left idle for a period of time that exceeds the value of the TCP Keep Alive Interval option.

When this issue occurs, the system does not send Keep-Alive packets as expected, which causes the mirrored FastL4 connections to expire.

Impact

After the failover occurs, the BIG-IP system fails to Keep-Alive connections and drops them when they expire.

Note: Depending on the FastL4 profile configuration options, subsequent packets may reset or transparently create a new connection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TCP Keep-Alive packets were working on the active BIG-IP system before the failover occurred.
  • After the failover, traffic resumes and is then left idle. However, the newly active BIG-IP system fails to send Keep-Alive packets and drops the idle connections on the affected virtual server.
