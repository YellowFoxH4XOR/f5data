Description

When you face a problem with ConfigSync and find a similar logs in /var/log/ltm, it indicates a problem with certificate in big3d directory:

Dec 5 02:39:32 big-ip1.local warning tmm7[12247]: 01260013:4: SSL Handshake failed for TCP 10.50.3.11:4353 -> 10.50.3.10:55316
Dec 5 02:39:32 big-ip1.local warning tmm7[12247]: 01260009:4: (null connflow): Connection error: ssl_basic_crypto_cb:697: alert(20) Decryption error
Dec 5 02:39:32 big-ip1.local warning tmm3[12247]: 01260013:4: SSL Handshake failed for TCP 10.50.1.2:4353 -> 10.50.1.3:21145
Dec 5 02:39:32 big-ip1.local warning tmm3[12247]: 01260009:4: (null connflow): Connection error: ssl_basic_crypto_cb:697: alert(20) Decryption error
Dec 5 02:39:32 big-ip1.local warning tmm5[12247]: 01260013:4: SSL Handshake failed for TCP 10.50.1.2:4353 -> 10.50.1.3:35391
Dec 5 02:39:32 big-ip1.local warning tmm5[12247]: 01260009:4: (null connflow): Connection error: ssl_basic_crypto_cb:697: alert(20) Decryption error
Dec 5 02:39:33 big-ip1.local warning tmm5[12247]: 01260013:4: SSL Handshake failed for TCP 10.50.1.2:4353 -> 10.50.1.3:29225

Environment

  • BIG-IP
  • GTM
  • iQuery

Cause

This issue may be related to GTM module, sometimes if you stop using it, BIG-IP will still try to use the certificates from big3d directory which cause this problem. The problem happens on port 4353, which belongs to iQuery. 

Recommended Actions

To solve this you need to reboot the device, with that BIG-IP will be able to know that GTM is not on device.
