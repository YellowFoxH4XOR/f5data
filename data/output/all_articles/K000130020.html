K000130020: Critical CPF, NMS and TRIPO alarms on both SDC nodes - Tripo process restarted

Type
Support Solution
Published
2023-01-05
Updated
2023-02-07
Source
https://my.f5.com/manage/s/article/K000130020

Description

  • CPF, NMS and Tripo Critical alarms on both SDC nodes
  • Tripo process unexpected restarted on both SDC nodes
  • Error messages from \var\log\rsyslog\<name>.SysWatchDog.log

WebStatMgr crashed. Tripo is shutting down

 

Environment

  • SDC (Traffix) till 5.1 CF30

Cause

Due to connecting to SDC IP via port 5555 from external server (like vulnerability scanner e.g "Qualys"), the Tripo process unexpected restarted.

This is due to known bug id SDC-374

 

 Recommended Actions

  • Perform software upgrade to SDC 5.1 CF31 or higher.
Or
  • Implement workaround to block port 5555 in SDC iptables for external traffic - to do so, follow the steps below:
1. To see the rule/line number 
# iptables -L -v -n --line-numbers | grep 5555
2. Delete the generic rule that allowed access to port 5555 
# iptables -D INPUT yy (that have the default TCP 5555 rules)
Note: The yy refers to the rule or line number.
3. Add new role for block port 5555 for external traffic 
# iptables -A INPUT -d <MGMT network> -i eth0 -p tcp -m tcp --dport 5555 -m comment --comment "Drop connections to WebStatMgr port from outside traffic" -j LOGDROP

Next step is to make sure that iptables monitoring is unmanaged from salt. Then make the iptables changes.

How to unmanage iptables from Salt:

Enable/Disable Salt iptables monitoring

Note: The below procedure should be done on each Salt master's EMS and Sites machines.
  1. iptables Service
Stop the iptables service on each EMS and Site machine associated to the Salt master instances that you are working on.
# service iptables stop
  1. Master machines
Look for Salt two master instances (one per machine). Salt master process can be identified under process containing the word "vnf"
# monit summary
example of output showing the process having the word "vnf"
Process 'sdclab008-05_vnf'     Running
  1. Disabling or Enabling "iptables" Salt monitoring on the master machine only
Change directory to iptables salt configuration folder (folder "5.1-1003" is an example)
# cd /srv/salt/5.1*/system
Edit the file: "firewall.sls"
# vi firewall.sls
Look for the line:
{% if virtWhat != 'kvm' %}
and DISABLE the iptables salt monitoring by replacing the above line with:
{% if virtWhat == ‘kvm’ %}
Comment the whole else block by setting {# in line 758 of the file and #} in line 777
  1. Save the file
Beginning of the else section:
{#                            <<<
{% else %} #virtwhat
### Disabled for virtual machines ###
{% for iptable in 'iptables', 'ip6tables' %}
{{iptable}}_disabled:
 service.disabled:
   - name: {{iptable}}
   - require:
     - pkg: iptables_install
{{iptable}}_stop:
 service.dead:
   - name: {{iptable}}
   - require:
     - pkg: iptables_install
{% endfor %}
#}                            <<<
{% endif %} #virtwhat
Note: If you want to re-enable the iptables Salt monitoring, restore the changes
Verification:
cat firewall.sls --number |grep "758\|777"
grep "virtWhat ==" firewall.sls
  1. Publish the new configuration
It is required to publish the new configuration on all "minion" machines.
# salt “*” state.highstate
  1. Reactivate the iptables service
You need to enable the firewall on all stopped iptables services machines.
# service iptables start

 

Please repeat this for all SDC nodes.
