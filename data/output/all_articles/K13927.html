Known Issue

Running the qkview utility may cause memory resource issues on a BIG-IP system.

This issue occurs when the following condition is met:

  • The /var/log directory contains one or more compressed files that become large files of multiple GBs when uncompressed.

    Note: Whether a file triggers this issue varies on the size of the uncompressed file and the amount of system memory available.

Impact

The BIG-IP system may fail over to the standby unit and temporarily disrupt network traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP host runs out of memory. As a result, the Traffic Management Microkernel (TMM) processes stop responding and trigger the host watchdog, which causes a failover.
  • The qkview utility fails to complete processing.

Workaround

To work around this issue, F5 recommends the following:

  • Avoid unnecessary logging

    Steps to avoid excessive and unnecessary logging are specific to individual deployments. To avoid common reasons for excessive logging:

    • For BIG-IP 11.x, use the High Speed Logging (HSL) feature when logging from within iRules. HSL allows you to send logging data to a remote logging host.
    • Disable any extended BIG-IP debugging options which may have been requested by F5 Technical Support.
  • Rotate log files more often

    F5 recommends that you rotate your log files when they reach a maximum of 1 GB in size. For BIG-IP 11.x and later, perform the procedure documented in K13367: Managing log files on the BIG-IP system (11.x - 13.x). For BIG-IP 10.x, there is no option to rotate log files based on size, but you can make sure that log files are rotated daily, as documented in K7115: Managing log files on the BIG-IP system (9.4.x - 10.x).
