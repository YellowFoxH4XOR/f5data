Description

You want to upgrade your BIG-IP VE device but there's no active boot location. You choose HD2 for new image. Install status is stalled on "audited" or "removing" state. Now both HDs' are set to mode 'none' and you can't change it. Solutions from K91155702 and K000137302 are not working.

 

Example:

HD1 is a 20GB disk, enumerated at /dev/sda. It is not in use at all.

HD2 is an 84GB disk, enumerated at /dev/sdb.

The 'vg-db-vda' volume group containing both boot locations is using the second disk [HD2].

Both disks are set to mode 'none'.

In older versions of BIG-IP, the 'ALL' OVA image would use a second 20GB disk for datastore (AAM) purposes. This would be enumerated as sdb / HD2 and it would be set to mode 'none' if unused.

OVA images for current supported versions do not do that though (AAM is now EoSD, can't be provisioned).

 

On current versions, HD1 (/dev/sda) would be the largest and only disk in the OVA image, and the LVM storage for boot locations ('vg-db-vda' volume group) would be on this disk.

HD1 would be 'mixed' mode. Any additional disk added would be 'none' mode.

Environment

  • BIG-IP
  • Virtual Edition
  • Upgrade

Cause

Disks on your BIG-IP system were reversed.

Recommended Actions

Deploy another VE and restore from UCS to recover from this issue (or just rebuild from scratch if config is minimal). Boot locations should be installed to HD1 (this should be the only disk if you install from a current OVA image).
