K6467: NTLM authentication fails for certain connections

Topic

In order for NTLM authentication requests to be passed properly by the BIG-IP, OneConnect should be configured to aggregate HTTP requests from the same IP address and port. This is accomplished by setting the OneConnect web aggregate setting to port. However, with OneConnect web aggregate set to port, it is still possible for NTLM authentication to fail for certain connections. For additional information about OneConnect, refer to K1548: Overview of the OneConnect (web aggregation) feature.

These NTLM failures are likely due to the Web Aggregate timeout, which defaults to 5 seconds.

If the client establishes a TCP connection to a pool member that requires NTLM authentication, and then fails to send a new HTTP request on the existing TCP connection within the Web aggregate timeout setting, the BIG-IP system resets the server-side TCP connection.

If the client subsequently sends a new request on the same client-side connection, the BIG-IP system attempts to re-open the server-side connection on the same TCP port, allowing the client's authenticated session to continue. In some instances however, the BIG-IP system will re-open the server-side connection on a different TCP port, which causes the client's authenticated session to fail.

To prevent the BIG-IP system from closing the server-side connection prematurely, you can increase the Web Aggregate timeout to match the TCP idle timeout set on the virtual server. The default TCP idle timeout value is 1005 seconds.

To increase the Web Aggregate timeout, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click the Advanced Properties tab.
  4. Under the OneConnect box, change the web aggregate timeout setting to the timeout value you want.
  5. Click the Apply button.
