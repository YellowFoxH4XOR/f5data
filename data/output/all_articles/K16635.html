Known Issue

Using the http-explicit profile's Explicit Proxy feature in combination with the HTTP_REQUEST iRule may cause the Traffic Management Microkernel (TMM) to produce a core file.

This issue occurs when the following condition is met:

  • You have configured the BIG-IP virtual server with the following features:

    • An http-explicit profile (HTTP profile with the Proxy Mode setting configured to Explicit).
    • An iRule that contains suspending commands in the HTTP_REQUEST event.

    When you use the Explicit Proxy feature in combination with an HTTP_REQUEST iRule event, the HTTP profile can suspend while iRule events are processed. When the iRule returns, the HTTP profile may attempt to resume an expired flow (for example, an aborted connection), but since there is no flow to resume, TMM produces a core file.

    Impact

    The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

    Symptoms

    As a result of this issue, you may encounter one or more of the following symptoms:

    • BIG-IP iHealth lists Heuristic H500152 on the Diagnostics > Identified > Medium screen.
    • The BIG-IP system fails over to the standby system if configured for HA.
    • The system logs messages to the /var/log/ltm file that appear similar to the following example:

      notice sod[8810]: 01140045:5: HA reports tmm NOT ready.

    • The system logs messages to the /var/log/tmm* files that appear similar to the following example:

      notice panic: ../base/tclrule.c:1219: Assertion "valid ctx lrule_cnt" failed.

    • The system logs messages to the /var/log/messages file that appear similar to the following example:

      notice logger: Started writing core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897
      notice logger: Finished writing 236194271 bytes for core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897

    • The BIG-IP system generates TMM core files to the /var/core directory, with a time stamp that correlates to the traffic interruption that appears similar to the following example:

      tmm.0.bld2384.0.core.gz
