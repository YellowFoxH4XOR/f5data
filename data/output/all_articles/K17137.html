Known Issue

The Traffic Management Microkernel (TMM) might exit while processing traffic for BIG-IP APM SWG per-request policy.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for SWG per-request policy.
  • The SWG per-request policy contains a Category Lookup action.
  • The Categorization Input property of Category Lookup action is configured to use Subject.CN.
  • The web application certificate presented to the BIG-IP APM system is missing the Common Name (CN) in the Subject field.

Impact

The BIG-IP APM system is unable to process traffic while the TMM process is unavailable.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to access the BIG-IP APM system or may experience a traffic disruption.
  • The TMM process generates a core file to the /shared/core directory.
  • The BIG-IP system generates a SIGSEGV fault and stack trace in the /var/log/tmm file, similar to the following example:

    notice ** SIGSEGV **
    <snip>
    RIP=0x2abe5fa087d0

Workaround

There is no workaround for this issue. However, if the Server Name Indication (SNI) is included in the Client Hello, instead of using the Subject.CN, administrators can use the SNI as Categorization Input for the Category Lookup action. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Configuring the Categorization Input to use SNI in client Hello

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Per-Request Policies.
  3. Open the visual policy editor by clicking Edit to the right of the Access Profile name.
  4. Click the name of the Category Lookup action.
  5. For the Categorization Input property, select Use SNI in Client Hello (if SNI is not available, use Subject.CN).
  6. Click Save.
