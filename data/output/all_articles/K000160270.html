Description

Self-IP addresses on the standby BIG-IP device in an HA cluster become unresponsive to monitoring (e.g., ICMP/ping) when Auto Last Hop is enabled and VLAN-keyed connections are disabled, particularly in environments using MAC masquerade.

Environment

  • BIG-IP LTM
  • High Availability (HA) cluster with active/standby configuration
  • Auto Last Hop: Enabled
  • VLAN-keyed connections (sys db connection.vlankeyed): Disabled
  • MAC masquerade: Enabled
  • Self-IP monitoring (e.g., ICMP/ping) in use

Cause

The interaction between disabled VLAN-keyed connections and enabled MAC masquerade can cause the standby device to mishandle return traffic, resulting in dropped packets or monitoring failures for Self-IPs. When VLAN-keyed connections are disabled, the system may not correctly associate return traffic with the appropriate VLAN and MAC context, especially on the standby device using the masqueraded MAC address. 

Understand Feature Interactions:

  • Auto Last Hop and VLAN-keyed connections are independent features but can interact in HA and asymmetric routing scenarios.
  • Disabling VLAN-keyed connections allows for asymmetric routing but affects connection tracking globally.
  • MAC masquerade provides a consistent MAC address for failover but relies on correct VLAN/MAC association.

Recommended Actions

  1. Confirm the status of Auto Last Hop, VLAN-keyed connections, and MAC masquerade on all HA members.
  2. Temporarily enable VLAN-keyed connections: tmsh modify sys db connection.vlankeyed value enable on the affected cluster.
  3. Test Self-IP monitoring on the standby device.
  4. If monitoring is restored, the issue is due to the interaction described above.

Additional Information

  • Disabling VLAN-keyed connections is a global change and may have unintended consequences across all VLANs.
  • The default and recommended configuration for most environments is to have both Auto Last Hop and VLAN-keyed connections enabled.
  • If you disable VLAN-keyed connections, thoroughly test your environment, as this can affect connection tracking and features such as IPsec, tunnels, and monitoring/failover behavior.
  • Bug ID 842425 (fixed in 17.5.0 and later) relates to mirrored connection issues and VLAN-keyed connections but does not exactly match this scenario.

Assess Asymmetric Routing Needs:

  • If asymmetric routing is required, carefully test the impact of enabling VLAN-keyed connections, as this may affect other traffic flows.

Monitor for Side Effects:

  • Enabling VLAN-keyed connections is the default and recommended setting for most environments.
  • Disabling it can impact all VLANs, cause TMM restarts, or affect features like IPsec tunnels.
