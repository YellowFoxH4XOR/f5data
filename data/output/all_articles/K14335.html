Known Issue

When capturing traffic for a standard virtual server, the tcpdump utility may fail to capture some packets.

This issue occurs when all of the following conditions are met:

  • Capturing traffic for a standard virtual server
  • Capturing traffic on a VLAN or on interface 0.0
  • Using a host filter to limit the amount of traffic captured

If tcpdump is used with a host? filter, it may not capture first fragments if there are more fragments to follow. For example, an iRule with the TCP::payload replace command inserts data at the beginning of TCP payload. The BIG-IP system is actually passing the packets, but tcpdump is just not capturing them.

Note: This issue does not affect Performance L4 virtual servers.

Impact

The tcpdump utility may not capture some packets.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Tcpdump packet captures do not contain all packets for a captured connection.

Workaround

To work around this issue, you should not use the host filter when using tcpdump to capture traffic on a VLAN or interface 0.0.

Impact of workaround: Larger packet capture files may be required to capture desired information.
