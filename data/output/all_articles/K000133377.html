K000133377: BIG-IP resets the client-side with [F5RST(peer): RST stream] or [F5RST(peer): Deactivating]

Type
Support Solution
Published
2023-04-04
Updated
2026-08-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000133377

Description

On a HTTP/1.1 to HTTP/2.0 proxy setup, BIG-IP may send a TCP reset with RST cause: [F5RST(peer): RST stream] to the client side and a RST cause: [F5RST: flow teardown] on the server side after a request is sent from the client.

When a client sends an HTTP/1.1 request that contains a TE header that includes values other than "trailers" (ie. deflate, gzip, compress, etc.), the BIG-IP sends these values over to the server side via HTTP/2.0 HEADERS. The receiving server would immediately respond with RST_STREAM indicating PROTOCOL_ERROR at which point BIG-IP then resets both client-side and server-side connections with [F5RST(peer): RST stream] and [F5RST: flow teardown] respectively.

The underlying reason is that for HTTP/2.0, only "trailers" value is allowed when TE header is used. See RFC9113 Section 8.2.2. Due to ID1032617, BIG-IP is carrying over the extraneous values contained in the HTTP/1.1 TE header of the client-side request into the HTTP/2.0 TE header on the server-side request. This results in the protocol error being triggered on the backend server, hence the RST_STREAM is sent.

In some cases, the backend server will respond with a Close Notify and TCP FIN, resulting in TCP RST cause: [F5RST(peer): Deactivating] on the client-side

Environment

  • BIG-IP
  • HTTP/1.1 client side
  • HTTP/2.0 server side
  • Invalid HTTP/2.0 TE header

 

Cause

Bug ID 1032617

 

Recommended Actions

The below example iRules can be used to ensure that only "trailers" value gets sent with the TE header over the HTTP/2.0 side if it is present in the HTTP/1.1 request, otherwise the TE header is removed.

 

Simple iRule:

when HTTP_REQUEST {
    if {[HTTP::header exists TE]} {
        if {[HTTP::header value TE] contains "trailers"} {
            HTTP::header replace TE "trailers"
        } else {
            HTTP::header remove TE
        }
    }
}

 

Enhanced iRule:

#-------------------------------------------------------------------------------
# iRule:    irule_normalise_te_header
# Purpose:  Normalise the HTTP "TE" (Transfer-Encoding-accepted) request header.
#
# What it does:
#   * If the client asks for "trailers"  -> forward exactly "TE: trailers"
#   * If the client asks for anything else (gzip, deflate, compress, ...) 
#                                        -> remove the TE header completely
#   * If there is no TE header at all    -> do nothing (fast exit)
#
# Why:
#   "TE" is a hop-by-hop header (RFC 7230 s4.3). Because the BIG-IP terminates
#   the client connection, TE values only ever describe what the *client* can
#   accept from the *BIG-IP* - they are not meaningful to the pool member.
#   The only value worth passing on is "trailers", which modern applications
#   (notably gRPC) rely on. Transfer codings such as gzip/deflate/compress are
#   effectively never implemented by origin servers, so they are safely dropped.
#   Collapsing TE to a single, predictable value also removes a header that is
#   commonly abused in HTTP request-smuggling probes.
#
# Events:   HTTP_REQUEST  (requires an HTTP profile on the virtual server)
# Impact:   CMP-compatible. No logging, no regex, no data-group lookups.
#-------------------------------------------------------------------------------

when HTTP_REQUEST {

    #---------------------------------------------------------------------------
    # STEP 1 - Read every TE header the client sent and turn them into one
    #          simple, lower-case string.
    #
    #   HTTP::header values  ... returns ALL instances of the header, so a client
    #                            that sends "TE: gzip" and "TE: trailers" as two
    #                            separate lines is handled correctly.
    #   join ... ","         ... flattens that list into a plain string. This is
    #                            important: without it, Tcl can wrap a value
    #                            containing spaces in curly braces (e.g.
    #                            "{trailers, gzip}") and the comparisons below
    #                            would silently fail.
    #   string tolower       ... transfer codings are case-insensitive, so
    #                            "Trailers" and "TRAILERS" must also match.
    #---------------------------------------------------------------------------
    set te [string tolower [join [HTTP::header values TE] ","]]

    #---------------------------------------------------------------------------
    # STEP 2 - Fast exits. These two checks cover the vast majority of real
    #          traffic and cost almost nothing, keeping the rule off the
    #          critical path for normal requests.
    #---------------------------------------------------------------------------

    # 2a. No TE header present (the common case) - nothing to do.
    if { $te eq "" } { return }

    # 2b. Already exactly "TE: trailers" - it is correct as-is, so leave it
    #     untouched. Rewriting it would only waste CPU.
    if { $te eq "trailers" } { return }

    #---------------------------------------------------------------------------
    # STEP 3 - Work out whether "trailers" is one of the requested codings.
    #
    #          We test each comma-separated token individually rather than
    #          searching for the text "trailers" anywhere in the string. That
    #          prevents false positives on look-alike values such as
    #          "x-trailers-test" or "notrailers".
    #
    #          "keep" is our flag: 0 = drop the header, 1 = replace with
    #          "trailers".
    #---------------------------------------------------------------------------
    set keep 0

    foreach coding [split $te ","] {

        # Each token may carry parameters, e.g. "gzip;q=0.5". Split on ";" and
        # keep only the coding name, then trim the whitespace that normally
        # follows a comma.
        set name [string trim [lindex [split $coding ";"] 0]]

        if { $name eq "trailers" } {
            set keep 1
            break               ;# Found it - no need to inspect the rest.
        }
    }

    #---------------------------------------------------------------------------
    # STEP 4 - Apply the result.
    #
    #          "remove" deletes EVERY instance of TE, guaranteeing no stray
    #          duplicates survive. We then insert a single clean header if the
    #          client legitimately asked for trailers. (We use remove+insert
    #          rather than "replace" because "replace" only acts on one
    #          instance and could leave a duplicate behind.)
    #---------------------------------------------------------------------------
    HTTP::header remove TE

    if { $keep } {
        HTTP::header insert TE "trailers"
    }
}
