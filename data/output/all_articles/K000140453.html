Environment

F5OS-A

Cause

There is no space in /sysroot.

 

# du -h | grep -v lib
Filesystem Size Used Avail Use% Mounted on
devtmpfs 63G 0 63G 0% /dev
tmpfs 63G 0 63G 0% /dev/shm
tmpfs 63G 12M 63G 1% /run
tmpfs 63G 0 63G 0% /sys/fs/cgroup
/dev/mapper/velocity-root 104G 104G 0 100% /sysroot    

 

/sysroot/ostree/deploy/velocity/var/shared/core/container/ contained old and large core files.

Recommended Actions

Remove any core files that are unused or irrelevant at the time of instance to free up space. If the core file is generated at the time of the device going down, copy the core file to your local workstation/SCP server. Collect the md5sum of the core file before removing it.

 

Collecting the md5sum:

 

  1. Login to F5OS CLI (as root).
  2. Enter commands below.

              cd /sysroot/ostree/deploy/velocity/var/shared/core/container/ 

              md5sum <core-filename>.core.gz

 

Transfer the core file to you local workstation or SCP Server.

 

Using the Configuration Utility:

 

  1. Login to the Configuration utility of your F5OS system.
  2. Go to SYSTEM SETTINGS > File Utilities.
  3. For Base Directory, go to where your core files are located. (e.g. diags/shared)
  4. Select the core file
  5. Select Download or Export as appropriate.

 

Using the CLI:

 

  1. Login to F5OS CLI (as root).
  2. Enter commands below.

              cd /sysroot/ostree/deploy/velocity/var/shared/core/container/ 

              scp -p <core-filename>.core.gz <username>@<serverip>:<remote path>

 

After collecting the files, you can remove the core file that is eating up the /sysroot directory and reboot the Host.

 

rm <core-filename>.core.gz

reboot

 

Since there is space already in /sysroot, the tenants will now boot up properly.

Additional Information

To get to the root cause of why there is a core file generated, upload the core file, md5sum, and a qkview of the F5OS Host to the case.
