Security Advisory Description

The BIG-IP system may respond with the NXDOMAIN status when it receives a DNS query on a CNAME wide IP. This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a CNAME wide IP.

    For example:

    test.example.com

  • The BIG-IP system is also configured with a DNS Express (DNSX) zone, but it does not have a record for the CNAME wide IP.
  • The BIG-IP system receives a DNS query of type MX or ANY for the CNAME wide IP.

Impact

DNS cache resolvers that receive the response with the NXDOMAIN status use that response for the entire domain name. As a result, DNS clients that use these DNS cache resolvers for DNS queries of type A/AAAA may receive responses with the NXDOMAIN status until the cache expires.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H645784 on the Diagnostics > Identified > Medium screen.
  • A DNS cache resolver receives a DNS response with the NXDOMAIN status when querying the BIG-IP system for an MX record or ANY records of a CNAME wide IP.
  • A DNS client receives DNS responses with NXDOMAIN when querying an affected DNS cache resolver for A/AAAA records.

Security Advisory Recommended Actions

Enabling the allow NXDOMAIN override setting
Enabling the Allow NXDOMAIN override setting directs the BIG-IP DNS to respond with a NOERROR response to queries for MX or ANY for the CNAME wideip. This prevents an NXDOMAIN getting stored in a resolver cache for the CNAME wideip. Choose the procedure below specific to your fixed version.
Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Enable the allow NXDOMAIN override setting using the Configuration utility (16.1.0 and later)

  1. Log on to the BIG-IP DNS Configuration utility.
  2. Go to DNS > Settings > GSLB > General.
  3. Select the Enabled box next to Allow NXDOMAIN Override.
  4. Select Update.

Enable the allow NXDOMAIN override setting using the TMOS shell (16.1.0 and later)

  1. Log in to the TMOS shell by typing the following command:
    tmsh
  2. Enable Allow NXDOMAIN override by typing the following command:
    modify gtm global-settings general allow-nxdomain-override enabled
  3. Save the configuration change with the following command:
    save sys config

Enable the allow NXDOMAIN override setting using the TMOS shell (Fixed versions earlier than 16.1.0. Refer to the status table)

  1. Log in to the TMOS shell by typing the following command:
    tmsh
  2. Enable Allow NXDOMAIN override by typing the following command:
    modify /sys db gtm.allownxdomainoverride value enable

Important: If this feature is enabled in versions prior to 16.1.0, by modifying the gtm.allownxdomainoverride database key, the functionality will not be migrated when upgrading to version 16.1.0 or later. You will need to follow one of the procedures listed for 16.1.0 and later after upgrading, in order to re-enable this feature. For more information, refer to Bug ID 1351969.

Workaround

To work around this issue, you can either create a TXT resource record for the CNAME wide IP in ZoneRunner, or create an iRule that replaces the NXDOMAIN status with a NOERROR status before sending out the response. To do so, perform either of the following procedures:

  • Create a TXT resource record in ZoneRunner
  • Create an iRule to replace the DNS response status

Create a TXT resource record in ZoneRunner

To create a TXT resource record for the CNAME wide IP in ZoneRunner, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to one of the following locations:
    • BIG-IP 11.5.0 and later

      DNS > Zones > ZoneRunner > Zone List

    • BIG-IP 11.4.0 through 11.4.1

      Global Traffic > ZoneRunner > Zone List

  3. Select the zone name of the affected CNAME wide IP. For example, if the affected CNAME wide IP is test.example.com, the zone name should be example.com.

    Note: If the zone of the affected CNAME wide IP does not exist, you may have to create one before proceeding to the next step. For more information about creating a zone, refer to the Using ZoneRunner to Configure DNS Zones chapter of the BIG-IP DNS Services: Implementations manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  4. Select the Resource Records tab.
  5. Select Create.
  6. For Name, enter the affected CNAME wide IP.

    For example:

    test.example.com

  7. For TTL, enter the value you want to use in seconds.
  8. For Type, select TXT.
  9. For Text, enter the text you want to use.
  10. To save the changes, select Finished.

Create an iRule to replace the DNS response status

To create an iRule to replace the DNS response status, perform the following procedure:

Impact of workaround: The following iRule may not apply to all environments. F5 recommends authoring an iRule that works best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, the iRule may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Go to one of the following locations:
    • BIG-IP 11.5.0 and later

      DNS > Delivery > iRules > iRule List

    • BIG-IP 11.4.0 through 11.4.1

      Local Traffic > iRules > iRule List

  3. Select Create.
  4. For Name, enter a name for the iRule.

    For example:

    K23022557workaround

  5. For Definition, enter an iRule similar to the following example, replacing test.example.com with the affected CNAME wide IP:

    when DNS_RESPONSE {
      if { [DNS::question name] eq "test.example.com" } {
        if { [DNS::header rcode] eq "NXDOMAIN" } {
            DNS::header rcode NOERROR
            DNS::authority clear
            return
        }
      }
    }

  6. To save the iRule. select Finished.
  7. Go to one of the following locations:
    • BIG-IP 11.5.0 and later

      DNS > Delivery > Listeners > Listener List

    • BIG-IP 11.4.0 through 11.4.1

      Local Traffic > Virtual Servers > Virtual Server List

  8. Select the GTM/DNS listener. Typically, the name of this listener ends in _gtm.
  9. Select the Resources tab.
  10. Under iRules. select Manage.
  11. For Available, select the iRule you created in Steps 3 through 6 and move it to Enabled.
  12. Select Finished.
