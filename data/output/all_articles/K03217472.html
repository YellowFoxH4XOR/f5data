Known Issue

If you delete a virtual server, the bd service may restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system is configured with a security policy.
  • A virtual server is configured with the security policy.
  • You delete the virtual server.

Impact

The BIG-IP ASM system temporarily stops processing traffic when you configure it to fail over to a peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you delete the virtual server, the system logs messages to the /var/log/ltm file that appear similar to the following example:

    err mcpd[<pid>]: 0107102e:3: gtm_vs_score refers to nonexistent virtual server (/<partition>/<app>/<virtual server name>)
    notice sod[<pid>]: 010c0044:5: Command:  running enable bd bigstart.
    warning sod[<pid>]: 01140029:4: HA proc_running bd fails action is go offline and down links.
    notice sod[<pid>]: 010c0050:5: Sod requests links down.
    notice sod[<pid>]: 010c006d:5: Leaving Standby for Offline for ha table offline_cond.
    notice sod[<pid>]: 010c0054:5: Offline for traffic group /Common/traffic-group-1.
    notice sod[<pid>]: 010c003e:5: Offline

  • When you delete the virtual server, the system logs messages to the /var/log/ts/asm_start.log file that appear similar to the following example:

    asm_start|INFO|<date time>|<pid>|F5::ASMStart::asm_start,,ASM started successfully
    asm_start|INFO|<date time>|<pid>|F5::LockFactory::Base::unlock,,F5::LockFactory::Base Line 118 is going to unlock '/ts/lock/asm_start.lock', which is owned by PID '<pid>'.

    asm_start|INFO|<date time>|<pid>|,,/usr/share/ts/bin/asm_start starting (user:'root', PPID:'<pid>', parent:'runsvasm')
    asm_start|INFO|<date time>|<pid>|F5::LockFactory::Base::lock,,asm_start Line 44 is going to lock '/ts/lock/asm_start.lock'. (flock flags: '2', dont_block: '1').
    asm_start|INFO|<date time>|<pid>|F5::LockFactory::Base::lock,,asm_start Line 44 has locked '/ts/lock/asm_start.lock'. (Lock count: '1', Self count: '1')
    asm_start|INFO|<date time>|<pid>|F5::ASMStart::asm_start,,ASM starting
    asm_start|INFO|<date time>|<pid>|F5::ProcessHandler::kill_process_group,,Killing process group all
    asm_start|INFO|<date time>|<pid>|F5::ProcessHandler::start_process_group,,Starting process group all

  • When you configure your BIG-IP ASM system to fail over to a peer device, it fails over to a peer device and goes into the Standby state.
