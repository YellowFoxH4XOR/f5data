Description

You may want to integrate your existing databases for authentication purposes with F5 APM. This guide explores the feasibility and potential methods to authenticate F5 APM against SQL, MySQL, and PostgreSQL databases.


Environment

External database authentication through APM

Cause

The need for a custom authentication solution to authenticate using on-premise databases used for storing user credentials and related information with F5 APM. The challenge is that F5 APM does not natively support direct authentication against these types of databases.

Recommended Actions

If the database supports any standard authentication protocols like LDAP, oAuth, or SAML through an interface, it simplifies the process. F5 APM can natively integrate with these protocols, eliminating the need for custom middleware.


Otherwise, since F5 APM does not natively support direct connections to SQL, MySQL, or PostgreSQL databases, an intermediary middleware layer is necessary. This middleware can be an API integrated with the database that accepts authentication requests from F5 APM and interacts with the database to verify user credentials.

Using frameworks such as ExpressJS, you can create an API endpoint that handles POST requests to verify user credentials or GET requests to retrieve specific user information. This API would need to be securely integrated with the database.

Within the APM policy, you can use iRules or iRuleLX to make HTTP requests to this middleware API. For instance, an iRule event can be added after a logon page in the APM policy, which then sends a request to the API to authenticate the user.
