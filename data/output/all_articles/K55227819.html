Description

BIG-IP reporting swap memory usage at or close to 100%

Environment

  • BIG-IP Platform with only 8 GB or less physical memory
  • Multiple Modules Provisioned
    • Application Security (ASM)
    • Application Visibility and Reporting (AVR)
    • Fraud Protection Service (FPS)

Cause

8GB of memory is not sufficient to have 3 modules fully provisioned as Nominal

Recommended Actions

Take steps to relieve the memory pressure:

  • Upgrade to address any known memory issues. (for example ID 833685)
  • De-provisioning any non-required modules
  • Reduce provisioning if possible, for example, reduce AVR provisioning from Nominal to Minimum
  • Provision ASM as Dedicated (if other modules are not required)

If all modules are required then additional memory may be needed. For non-cloud Virtual Edition BIG-IP increased memory is normally the simplest solution.

Additional Information

The following information summarizes swap memory usage:

  • It is normal for a Linux system, including the BIG-IP system, to use swap. When certain memory thresholds are crossed, however transiently, the Linux kernel moves unused or less used memory pages to swap (pagefile) on disk  so that more physical memory is available for more actively used memory pages. This process is more correctly called demand paging.  These pages will stay in swap if not needed, and will be brought back into physical memory only when their content is referenced by a process.  The information in a page can only be used when in main memory, and not whilst in swap.
  • memory freed by swapping may be used by more active processes or for buffers and caches allow the kernel to optimize I/O performance.
  • High swap usage may be a sign that the system is experiencing memory pressure. However, the BIG-IP system may experience high swap usage under normal operating conditions. If MemAvailable in /proc/meminfo is still higher than swap usage by several hundred MB or more, and the swap level appears stable, it is likely that the system is not experiencing an issue and has simply paged out unused or less used pages in order to free memory for other processes. If the value of Buffers in /proc/meminfo is zero to low hundreds of KB the system is likely experiencing memory pressure (lower value is higher memory pressure).

Note: The terms swap and swapping are historical, stemming from a time many decades ago, when whole processes were swapped in and out. Linux, and other modern operating systems, have always used demand paging. This refers to managing process memory in 4KB sized segments (known as pages). Some processes, such as tmm, are set up to use huge pages (2MB size) as well - these pages can never be swapped in or out. If the system is actually near to running out of memory it can enter a state known as thrashing, where pages are constantly moved to swapfile only to very quickly be brought back to main memory because they are needed. This clearly isn't useful, increasing load on the system in several ways and increases delay accessing information on these pages. A process thread cannot run while waiting for a page to be brought back to main memory. The Linux kernel can reach a point where it's actually spending more time managing paging activity than running the processes.  If the memory pressure is not relieved the destabilised system will fail, usually with watchdog timeouts, and may reboot. Systems with higher levels of normal I/O and  iowait are more susceptible to thrashing when there is memory pressure. You can use vmstat command to monitor virtual memory statistics such as paging activity and free memory.
