Description

The sidecar in Aspen Mesh generates a standard set of metrics but you can create new metrics as per your needs. This article provides one such example.

Environment

  • Aspen Mesh: 1.9.x and above

Cause

N/A

Recommended Actions

The sidecar in Aspen Mesh generates a standard set of metrics but you can create new metrics as per your needs. In this example we are adding the request_host and destination_port dimensions to the requests_total metrics that are emitted by the sidecar and gateways in both inbound and outbound directions

  1. Add the following section to the override value file:

    #Custom metrics
    telemetry:
      v2:
        prometheus:
          configOverride:
            inboundSidecar:
              metrics:
                - name: requests_total
                  dimensions:
                    destination_port: string(destination.port)
                    request_host: request.host
            outboundSidecar:
              metrics:
                - name: requests_total
                  dimensions:
                    destination_port: string(destination.port)
                    request_host: request.host
            gateway:
              metrics:
                - name: requests_total
                  dimensions:
                    destination_port: string(destination.port)
                    request_host: request.host

  2. Upgrade the helm installation for istiod using the newly edited file:

    helm upgrade istiod <path to release>/manifests/charts/istio-control/istio-discovery -n istio-system --values sample_overrides-aspenmesh.yaml

  3. After the upgrade is done, you can check the envoy filter if the new metrics are added correctly. The output should look like the following:

    kubectl get envoyfilters -n istio-system stats-filter-1.9 -o yaml | grep metrics -A 3 –B3

    root_id: stats_outbound
    vm_config:
      code:

    root_id: stats_inbound

      code:
    --

    You have successfully added request_host and destination_port as dimensions for the requests_total metric. The name of the envoy filter is stats-filter-1.9 because of Aspen Mesh version 1.9.

  4. If the dimensions are not already in the DefaultStatTags List, add the following annotation to all the pods from which we would need to extract the dimensions into Prometheus. You can check the default stats in the bootstrap configuration of any given pod.

    istioctl pc bootstrap <pod-name> -n <namespace> | jq ".bootstrap.statsConfig"

    DefaultStatTags = []string{
    "reporter",
    "source_namespace",
    "source_workload",
    "source_workload_namespace",
    "source_principal",
    "source_app",
    "source_version",
    "source_cluster",
    "destination_namespace",
    "destination_workload",
    "destination_workload_namespace",
    "destination_principal",
    "destination_app",
    "destination_version",
    "destination_service",
    "destination_service_name",
    "destination_service_namespace",
    "destination_port",
    "destination_cluster",
    "request_protocol",
    "request_operation",
    "request_host",
    "response_flags",
    "grpc_response_status",
    "connection_security_policy",
    "source_canonical_service",
    "destination_canonical_service",
    "source_canonical_revision",
    "destination_canonical_revision",
    }
    apiVersion: apps/v1
    kind: Deployment
    spec:
      template: # pod template
        metadata:
          annotations:
            sidecar.istio.io/extraStatTags: destination_port,request_host

    Refer to the Annotation section of K12253321: Holding up application until proxy starts in Aspen Mesh for more information. As you can see request_host and destination_port is already in the list, so there was no need to annotate.

Additional Information

Istio exposes all standard Envoy attributes which can be used to create custom metrics. Peer metadata is available as attributes upstream_peer for outbound and downstream_peer for inbound with the following fields:

FieldTypeValue
namestringName of the pod.
namespacestringNamespace that the pod runs in
labelsmapWorkload labels
ownerstringWorkload owner
wokload_namestringWorkload name
platform_metadatmapPlatform metadata with prefixedkeys
istio_versionstringVersion identifier for the proxy
mesh_idstringUnique identifier for the mesh
app_containerslist<string>List of short names for application containers
cluster_idstringIdentifier for the cluster to which this workload belongs.
