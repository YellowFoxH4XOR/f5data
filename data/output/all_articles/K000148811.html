K000148811: HTTP(S) traffic reset with reset cause: "Malformed HTTP header error"

Description

After upgrade from v15.x to 16.x or higher, the following behaviour maybe encountered:

  • HTTP response to the BIG-IP is reset.
  • TCP reset reason states "Malformed HTTP header error".
  • HTTP page(s) or page element(s) fail to load.

Environment

The following environmental factors are relevant to the behaviour:

  • HTTP Profile is in use
  • Pool Member sends non-HTTP compliant response
    • Content-Length and Transfer-Encoding cannot be in the same packet

Cause

As of BIG-IP version 16.0.0, HTTP compliance is enforced as part of the HTTP profile and cannot be corrected with an iRule.

Recommended Actions

The actions or steps required to address the topic covered in the description:

  1. If the configuration is not using iRules or settings that rely on the HTTP profile, remove the HTTP profile from the affected configuration.
  2. If the former is not possible, correct the HTTP Response from the Pool Member to be HTTP compliant 

Additional Information

The following wireshark filters can be used to find offending packets:

  • http.te_and_length
  • f5ethtrailer.rstcausetxt == "Malformed HTTP header error"

The above is not related to ASM/(A)WAF HTTP Compliance policies.
