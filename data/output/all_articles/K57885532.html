Description

In APM AD Group Resource Assign - many ACL's can be assign for one user if he belongs to multiple groups for example:

User belongs to group group1 and group2
Rules in AD Group Resource Assign feature have rule for assigning Acl_1 for group1 and for goup2 - Acl_2

For user that belongs to both groups, unwanted assignment of ACL may occur, user may be blocked from resource and tmm log may appear:

Jul 28 16:31:30 testlb.local notice tmm3[22615]: 01580002:5: /Common/VPN-DC2:abb2b347: discard ACL: /Common/Acl_2:6 packet: tcp 10.11.2.141:55907 -> 172.26.5.47:3389

Environment

  • BIG-IP APM
  • AD Group Resource Assign feature

Cause

This is normal behaviour of feature, any matching rule will assign ACL. If user belongs to multiple groups and for that groups are rules assigning ACL's user may end up having wrong ACL than planned. Altering order may affect logic of feature.

Recommended Actions

  1. Avoid using multiple group assignment and/or matching rules in AD Group Resource Assign feature.
  2. Impose negation for second group matching to rule using CLI, tmsh and VI:
Note: Recommended solution is to change AD group assignment and change rule logic as described in point 1. Avoid using edit option, it can impose difficulties when policy or rule/group number will increase.

To manually edit expression in rule, use below command:

tmsh edit apm policy agent resource-assign <example_act_ad_group_mapping_ag>

Original ACL rule:

apm policy agent resource-assign <example_act_ad_group_mapping_ag> {
    rules {
        {
            acls { /Common/ACL_1 }
            expression "expr { [string tolower [mcget -decode {session.ad.last.attr.memberOf}]] contains [string tolower \"CN=group1,\"] }"
        }
    }
    type ad-group-mapping
}

Modified ACL:

tmsh list apm policy agent resource-assign <example_act_ad_group_mapping_ag>
apm policy agent resource-assign <example_act_ad_group_mapping_ag> {
    rules {
        {
            acls { /Common/ACL_1 }
            expression "expr { [string tolower [mcget -decode {session.ad.last.attr.memberOf}]] contains [string tolower \"CN=group1,\"] && !([string tolower [mcget -decode {session.ad.last.attr.memberOf}]] contains [string tolower \"CN=group2,\"]) }"
        }
    }
    type ad-group-mapping
}

Save file while exiting VI editor, save changes in tmsh mode as well. Applying modification of APM policy in GUI is also needed.
