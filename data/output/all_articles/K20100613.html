Known Issue

An enabled sFlow receiver causes poor Traffic Management Microkernel (TMM) performance on certain BIG-IP platforms.

This issue occurs when the following condition is met:

  • The BIG-IP configuration includes at least one sFlow receiver enabled on one of the following platforms:
    • i10000 series
    • i7000 series
    • i5000 series
    • i4000 series
    • i2000 series
    • VIPRION B4450 blade

Impact

BIG-IP performance is impacted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP virtual servers exhibit higher-than-normal latency.
  • ICMP echo requests to BIG-IP self IP addresses exhibit higher than normal latency.
  • The system logs messages to the /var/log/ltm file that appear similar to the following example:

    notice tmm1[<pid>]: 01010029:5: Clock advanced by 112 ticks

  • The system frequently logs messages to the /var/log/kern.log file that appear similar to the following example:

    info kernel: ltm driver: Idle enforcer starting
    info kernel: ltm driver: Idle enforcer exiting

Workaround

There is no workaround. To determine if an enabled sFlow receiver is configured on the BIG-IP system, perform one of the following procedures:

  • Using the Configuration utility to determine whether an sFlow receiver is enabled
  • Using tmsh to determine whether an sFlow receiver is enabled

Using the Configuration utility to determine whether an sFlow receiver is enabled

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > sFlow > Receiver List.
  3. Click the name of each listed sFlow receiver.

    Note: If no receivers are listed, no sFlow receivers are configured on the BIG-IP system.

  4. Observe whether the State is set to Enabled or Disabled.

Using tmsh to determine whether an sFlow receiver is enabled

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Determine whether an sFlow receiver is enabled by typing the following command:

    list /sys sflow receiver

    An enabled sFlow receiver appears similar to the following command output:

    sys sflow receiver test_sflow {
        address 10.11.12.254
        state enabled
    }

    Note: If no receivers are listed in the list /sys sflow receiver command output, no sFlow receivers are configured on the BIG-IP system.
