K12859: The BIG-IP WebAccelerator system does not cache HTTP 301 or HTTP 302 responses with 0 byte Content-Length

Topic

The BIG-IP WebAccelerator system caches content when the origin web server (OWS) returns the following HTTP response codes:

  • 200 OK
  • 201 Created
  • 203 Non-Authoritative Information
  • 207 Multi-Status
  • 300 Multiple Choices
  • 301 Moved Permanently

The system enables this behavior, by default, using the policy's Responses Cached Rules functionality. You can cache content from other HTTP response codes on the BIG-IP WebAccelerator system by adding the appropriate HTTP response codes, which you can find on the Acceleration Rules > Response Cached page of the Policy, under the Response Codes Cached section.

If you have configured the BIG-IP WebAccelerator system to cache content when the OWS returns HTTP 301 Moved Permanently or HTTP 302 Found response codes, and the response has 0 bytes for Content-Length header, the BIG-IP WebAccelerator system does not cache the content, even if the response contains a Cache-Control or Expires header.

For example, if the client sends a standard HTTP request, such as a GET request, and you have configured the BIG-IP WebAccelerator system to cache content when the OWS returns HTTP 301 Moved Permanently or HTTP 302 Found response codes, the system does not cache the content when the OWS returns a response that appears similar to the following example:

HTTP/1.1 302 Found
Connection: Keep-Alive
Date: Fri, 12 Nov 2010 00:28:36 GMT
Server: Apache-MonkeyStuff/1.0
Location: http://wamtest.f5.com/rest/1.1/images/radio/index2.html
Vary: Accept-Encoding
Content-Length: 0
Expires: Fri, 12 Nov 2010 01:28:36 GMT
Cache-Control: public, s-maxage=43200, max-age=3600
X-PvInfo: [S10201.C6169.A26951.RA0.G69BA.UCB0ECDE8].[OT/other.OG/other]

Workaround

You can use an iRule to insert payload into the header of the OWS HTTP 301 Moved Permanently or HTTP 302 Found response that has 0 byte Content-Length, and assign the iRule to the affected BIG-IP WebAccelerator-enabled virtual server. Doing this ensures that the response has a Content-Length header that is greater than 0 bytes and results in the BIG-IP WebAccelerator system caching the OWS HTTP 301 Moved Permanently or HTTP 302 Found response. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Click Create.
  6. Type a name for the iRule in the Name box.

    For example:

    sol12859

  7. In the Definition box, type an iRule similar to the following example:

    when HTTP_RESPONSE {
       if { [HTTP::is_redirect] } {
          if { [HTTP::header value Content-Length] == 0 } {
             set payload " "
             HTTP::payload replace 0 [HTTP::header value Content-Length] $payload
          }
       }
    }

  8. Click Finished.
  9. Click Local Traffic.
  10. Click Virtual Servers.
  11. Click Virtual Server List.
  12. Click the Edit link under the Resources column of the affected WebAccelerator-enabled virtual server.
  13. Click Manage for the iRules section.
  14. Under the Available box, select the iRule that you created in Steps 5-8.
  15. Click << to move the iRule to the Enabled box.
  16. To complete the assignment of the iRule to the affected WebAccelerator-enabled virtual server, click Finished.
