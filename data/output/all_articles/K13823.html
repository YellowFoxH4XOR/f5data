Known Issue

The bigip_add script fails to connect to BIG-IP systems licensed for Appliance mode.

This issue occurs when the following conditions are met:

  • You run the bigip_add script on a BIG-IP GTM system and specify a remote BIG-IP system that is licensed for Appliance mode.

The bigip_add script is an interactive script that logs into the bash shell of a remote BIG-IP system and exchanges SSL device certificates between the systems. This issue occurs because the bash shell is disabled for BIG-IP systems licensed for Appliance mode.

Impact

Affected systems fail to exchange SSL device certificates and are unable to establish an iQuery connection.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The bigip_add script fails to connect to the remote BIG-IP system and generates output similar to the following example:

    # bigip_add 10.0.0.2
    Retrieving remote and installing local BIG-IP's SSL certs ...
    Enter root password for 10.0.0.2 if prompted
    The authenticity of host '10.0.0.2 (10.0.0.2)' can't be established.
    RSA key fingerprint is e6:dc:90:8e:27:0e:20:79:ee:d4:37:33:1f:d8:49:1a.
    Are you sure you want to continue connecting (yes/no)? yes
    Warning: Permanently added '10.0.0.2' (RSA) to the list of known hosts.
    Password:
    Password:
    Password:
    Permission denied (publickey,keyboard-interactive,hostbased).
    ERROR: Can't read remote cert via /usr/bin/ssh.
  • The systems fail to properly exchange SSL device certificates.

Workaround

To work around this issue, you can log in to the Configuration utilities of the affected BIG-IP devices and manually exchange SSL device certificates. To do so, perform the following procedures:

Impact of workaround: If your environment contains multiple BIG-IP systems running in Appliance mode, the below workaround may be time consuming.

Export the BIG-IP GTM SSL device certificate

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Click System.
  3. Click Device Certificates.
  4. Click Device Certificate.
  5. Click Export.
  6. Copy the SSL device certificate from the Certificate Text field.

Import the BIG-IP GTM SSL device certificate to the BIG-IP system licensed for Appliance mode

  1. Log in to the Configuration utility of the system running in Appliance mode.
  2. Click System.
  3. Click Device Certificates.
  4. Click Trusted Device Certificates.
  5. Click Import.
  6. From the Import Method menu, select Append.
  7. Paste the BIG-IP GTM SSL device certificate obtained from the previous procedure to the Certificate Source field.
  8. Click Import.

Export the SSL device certificate of the BIG-IP system licensed for Appliance mode

  1. Log in to the Configuration utility of the system running in Appliance mode.
  2. Click System.
  3. Click Device Certificates.
  4. Click Device Certificate.
  5. Click Export.
  6. Copy the SSL device certificate from the Certificate Text field.

Import the SSL device certificate of the BIG-IP system licensed for Appliance mode to the GTM system

  1. Log in to the BIG-IP GTM command line.
  2. Use a text editor to edit the /config/gtm/server.crt file.

    For example:

    vi /config/gtm/server.crt
  3. Add the SSL device certificate obtained from the system licensed for Appliance mode to the beginning of the file.

    Note: Do not overwrite other certificates existing in the file. In addition, make sure to include the entire certificate, including the ---BEGIN CERTIFICATE--- and ---END CERTIFICATE--- lines.
  4. Save the changes and exit the file.
  5. Restart the gtmd and big3d services by typing the following command:

    bigstart restart gtmd big3d

Restart the big3d service on the BIG-IP system licensed for Appliance mode

  1. Log in to the tmsh shell of the BIG-IP system licensed for Appliance mode.
  2. To restart the big3d service, type the following command:

    restart /sys service big3d
