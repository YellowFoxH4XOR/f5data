K10373: The bigpipe global stats command reports a current connection count higher than the maximum connection count

Known Issue

This is the result of a known issue. The bigpipe global stats command shows the current connection count to be higher than the maximum connection count for BIG-IP systems running Clustered Multi-Processing (CMP). The maximum connection count which is reported by the bigpipe global command is the largest maximum connection count reported by any single TMM instance, rather than the sum of all maximum connection counters for all TMM instances.

For example, the following output from the bigpipe global command shows 722 current connections, but only 444 maximum connections on the clientside, and 946 current connections, but only 437 maximum connections on the serverside:

| | client (cur, max, limit, tot) = (722, 444, 0, 63.19M)
| | client (pkts,bits) in = (272.1M, 159.4G), out = (214.0M, 259.6G)
| | server (cur, max, limit, tot) = (946, 437, 0, 63.08M)
| | server (pkts,bits) in = (274.2M, 158.0G), out = (230.5M, 268.4G)
| | TMM cycles (total, idle, sleep) = (972.4T, 4.237T, 962.4T)
| | denials (maint, addr full, serv full) = (0, 0, 0)
| | (no serv, no listen, no mem, no lic) = (0, 180390, 0, 0)
| | memory (total, used) = (2.976G, 99.46M)
| | packets (drop, err in, err out) = (0, 0, 0)
| | HTTP requests = 0

F5 Product Development is tracking this issue as CR123890.

Workaround

You can calculate the maximum connections statistic by running the bigpipe tmm show all command and adding up the maximum connection counter values from all TMM instances. For example, the clientside global maximum connection count calculated using the output in the example would be 1661, and the serverside global maximum connection count would be 1710.
