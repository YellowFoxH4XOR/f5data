Topic

3-DNS provides two methods for sharing configuration between 3-DNS systems: redundant pairs and sync groups. You can also configure 3-DNS systems to be part of a redundant pair and sync group.

A 3-DNS redundant pair uses failover to provide redundancy at OSI layers 1-3, while a sync group synchronizes configuration to provide redundancy at OSI layers 4-7.

Redundant Pairs

Redundant pairs are distinguished by the following characteristics:

  • A redundant pair may consist of only two members.
  • The units must use physical or network failover to determine which system is active.
  • The pair shares an IP address, which is used by the active unit.
  • Only one unit is active at any given time.
  • The configuration between the two units is manually synchronized, using the config sync command.

Redundant pairs provide an additional level of redundancy by ensuring that each 3-DNS redundant pair is always available. This eliminates the need for the client to attempt to query multiple 3-DNS units when individual units are unavailable.

Sync Groups

Sync groups are distinguished by the following characteristics:

  • A sync group may consist of an unlimited number of members.
  • Sync group members must all have unique IP addresses.
  • Configuration is synchronized automatically between members of a sync group.

Sync groups take advantage of the fact that DNS already provides redundancy. DNS will return available DNS servers, and the client will attempt to use each server until it receives a response. As a result, sync groups provide a reasonable level of redundancy by ensuring that all available 3-DNS units use the same configuration.

Sync Group and Redundant Pair Combinations

Sync groups and redundant pairs may also be used in combination. Using both features together provides the following benefits:

  • Configuration is automatically synchronized between all units.
  • Clients are less likely to increase the response time by querying 3-DNS units that are unavailable.
