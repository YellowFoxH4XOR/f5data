K000163896: BIG-IP configuration fails to load after upgrade to 17.5.1.9 due to a forward slash in a LAG/trunk name

Type
Support Solution
Published
2026-10-26
Updated
2026-10-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163896

Description

After upgrading a BIG-IP LTM tenant from 17.5.1.5 to 17.5.1.9, the configuration fails to load and the system does not come up. 

Typical log messages in /var/log/ltm:

err mcpd[xxxx]: 01070088:3: The requested object name (<trunk name>) is invalid.

err tmsh[xxxx]: 01420006:3: Loading configuration process failed.

emerg load_config_files[xxxx]: "/usr/bin/tmsh -n -g -a load sys config partitions all base" - failed.

err mcpd[xxxx]: 01070422:3: Base configuration load failed.

info install_ucs.pm[xxxx]: ERROR: UCS installation failed.

err tmsh[xxxx]: 01420006:3: UCS loading process failed.

Environment

  • BIG-IP LTM tenant running on F5OS-A
  • Upgrade from BIG-IP 17.5.1.x to 17.5.1.9
  • Trunk/LAG created on the F5OS-A host with a forward slash in its name, then inherited by the BIG-IP tenant as a net trunk object

Cause

The LAG/trunk name contains a forward slash. BIG-IP configuration object names must begin with an alphabetic character and cannot contain unsupported special characters. The 17.5.1.9 configuration validator rejects the name with error 01070088, which stops the base configuration load and the UCS installation.

F5OS-A currently allows a LAG/trunk to be created with a forward slash in its name due to  Bug ID2695445. Earlier BIG-IP versions loaded the same name, but the 17.5.1.9 validator enforces the naming rule.

Resolution

  1. On the F5OS-A host, rename the affected trunk/LAG to a name that contains only letters, numbers, periods, hyphens, or underscores. Start the name with a letter. Do not use forward slashes or other special characters.
  2. Update all BIG-IP configuration references to the new trunk name.
  3. Reload the BIG-IP configuration and confirm that it loads successfully.
