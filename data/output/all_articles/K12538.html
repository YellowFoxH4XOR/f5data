Known Issue

This is the result of a known issue. The BIG-IP system may ignore valid persistence entries on platforms that support Clustered Multi-Processing (CMP).

Note: For more information about CMP, refer to K7751: Overview of Clustered Multi-Processing.

This issue is known to occur with the following configurations:

  • The platform and virtual server support CMP processing.
  • The virtual server references an iRule or HTTP class profile that allows multiple pool selections for a single connection.
  • The virtual server uses Source Address Affinity persistence, or another persistence type that stores the persistence record in memory.

Note: Cookie and Hash persistence types are stateless persistence methods and do not utilize the BIG-IP persistence table.

When a virtual server supports CMP and uses a persistence type that utilizes the persistence table, the BIG-IP system shares the persistence records across all TMM instances. This behavior allows returning clients to persist to the correct pool member, regardless of which TMM processes the request.

However, the CMP persistence lookup mechanism falsely assumes that there will be only one remote TMM persistence lookup per connection. When the configuration contains an iRule or HTTP class profile that is configured to switch from a server-side connection to a different pool based on traffic, the BIG-IP system may ignore persistence entries and send the request to the wrong pool member.

F5 Product Development tracked this issue as ID 341663 and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM release notes.

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about downloading software from F5, refer to K167: Downloading software and firmware from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue using one of the following methods:

  • Use cookie persistence for the virtual server.

    Note: When using cookie persistence, the persistence information is stored in the cookie, not in the BIG-IP persistence table.

  • Change the virtual server configuration so the system does not make multiple pool selections for a single connection.
