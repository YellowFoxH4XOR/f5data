K000163401: Illegal additional property violation due to property name starting with '@'

Description

BIG-IP ASM may reject requests validated against an imported Swagger/OpenAPI definition when JSON property names begin with the @ character. Properties such as @baseType and @type may generate the following error:

Illegal additional property

Environment

  • Product: BIG-IP ASM
  • Feature: API security validation using an imported Swagger/OpenAPI definition.
  • The API payload contains property names beginning with @.

Cause

This behavior is a limitation in BIG-IP ASM schema and property-name validation. Property names beginning with @ may be treated as illegal additional properties during request validation, even when they are defined in the imported API schema.

Recommended Actions

  1. Review the imported OpenAPI definition and identify properties whose names begin with @.
  2. If possible, modify the API schema and payload format to avoid property names beginning with @.
  3. If the property names cannot be changed, evaluate whether configuring additionalProperties: true in the applicable schema objects is appropriate.
  4. Before using additionalProperties: true, assess the potential security and validation impact because this configuration is not a validated workaround for this behavior.
  5. Track the enhancement associated with RFE ID2106785 for support of additional special characters, including @, in parameter or property names.
  6. Review future BIG-IP release information for a fix that addresses this limitation.

Additional Information

  • The behavior is associated with schema validation and does not necessarily indicate that the OpenAPI definition is malformed.
  • Allowing additional properties may reduce schema enforcement and should be evaluated carefully before deployment.
