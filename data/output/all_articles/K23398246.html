Topic

Due to existing limitation of the system, the Virtual Clustered Multiprocessing (vCMP) system does not provide a potential capacity or resource warning at the time of software upgrade.

Description

When you upgrade a vCMP guest that is provisioned with multiple modules, the system allows the software upgrade to proceed on the new target volume and copies over the configuration to the new target volume. The system does not verify whether the vCMP guest's provisioned resources are sufficient for the modules provisioned in the configuration. During the process of booting to the new target volume, the configuration fails to load when the vCMP guest's provisioned resources are insufficient, and the system logs an error message similar to the following example in the /var/log/ltm file:

load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- Loading schema version: 12.1.0 Loading schema version: c.c.0.1 01071008:3: Provisioning failed with error 1 - 'Memory limit exceeded. <xxxx> MB are required to provision these modules, but only <xxxx> MB are available.' . Unexpected Error: Loading configuration process failed. 

Recommended Actions

As a fallback plan, you can restart the BIG-IP system and boot to the previous version. To do so, perform the Restarting and booting into a previous version to restore services procedure.

Alternatively, you may want to redeploy a new vCMP guest with additional resources and then upgrade to the version you want. To do so, perform the Deploying a new vCMP guest with a larger capacity procedure.

Restarting and booting into a previous version to restore services  

Impact of procedure: Performing the following procedure should not have a negative impact to your system. 

  1. Log in to the BIG-IP command line.
  2. Run the switchboot utility in interactive mode by typing the following command: 

    switchboot 

  3. A list of boot image slots and their boot image descriptions displays. Use the arrow keys or type the number of the boot image slot you want to boot at startup, then press Enter. When you restart, the system starts from the boot image you specify.

    Note: The switchboot utility lists only boot image slots that contain an installation

    Note: Any change you make using the switchboot utility is saved in the boot configuration grub.conf file. 

  4. Restart the system and boot to its previous volume by typing the following command: 

    reboot 

Deploying a new vCMP guest with a larger capacity

Impact of procedure: Performing the following procedure should not have a negative impact to your system. 

Important: If you deploy a vCMP guest configuration that matches a currently running deployed vCMP guest, this impacts traffic due to IP address duplication. 

  1. Log in to the Configuration utility of the vCMP host. 
  2. Navigate to vCMP > Guest List. 
  3. Click Create. 
  4. For Initial Image, click the version that matches the original vCMP Guest. 
  5. For Requested State, click Provisioned. 
  6. Enter the rest of the settings you want to use. 
  7. Click Finish. 
  8. When the system completes provisioning for the vCMP guest, check the vCMP guest and click Deploy. 

    Note: You may restore the configurations of the original vCMP Guest on the newly deployed vCMP guest.

  9. Join the newly deployed vCMP guest to the cluster.
  10. Continue with the upgrade procedure for the version you want to use.
