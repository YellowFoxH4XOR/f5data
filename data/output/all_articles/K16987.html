Known Issue

A VIPRION chassis may show an incorrect number of persistence records when you use the TMOS Shell (tmsh).

This issue occurs when all of the following conditions are met:

  • You have a VIPRION system that has multiple blades installed.
  • Your configuration has a virtual server with an associated persistence profile.
  • You view the persistence records from the command line of the primary blade by typing the following command or using the following command syntax:
    • Typing the following command:

      tmsh show ltm persistence persist-records

    • Using the following command syntax:

      tmsh show ltm persistence persist-records client-addr <client ip>

Impact

Persistence records are not reported correctly when you use tmsh.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The number of persistence records is incorrect when compared with other connection related statistics.

Workaround

To work around this issue, you can use the virtual server name when you view persistence records using tmsh. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To view persistence records using the virtual server name, use the following command syntax:

    show ltm persistence persist-records virtual <name of virtual>

    For example, to view the persistence records for the virtual server named virtual_one, type the following command:

    show ltm persistence persist-records virtual virtual_one

  3. Exit tmsh by typing the following command:

    quit
