Known Issue

This is the result of a known issue. When adding a health monitor to a pool member or node whose address would be routed through the mgmt port, the BIG-IP bigd process reports the configuration error inaccurately, and erroneously uses the mgmt port to route health monitor traffic to the pool member or node.

The error is logged to the /var/log/ltm file, and appears similar to the following example, typically including an IP address other than that of the affected pool member or node:

Health check would route via mgmt port, node <ip_address>. Check routing table

The affected pool members or nodes may also be repeatedly marked up and down independent of their actual state.

F5 Networks Product Development tracked this issue as CR73624, and it was fixed in BIG-IP LTM versions 9.3 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Note: For more information about the error message, refer to K6163: Error Message: Health check would route via mgmt port.

Workaround

The management network was never intended to host any part of the load balancing configuration, such as virtual servers and pool members. To work around this issue, F5 Networks strongly recommends that you move the nodes or pool members so they reside on a VLAN defined in the BIG-IP load balancing configuration.
