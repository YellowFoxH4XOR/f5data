Known Issue

This is the result of a known issue. The BIG-IP HTTPS monitor does not allow SSL renegotiation.

An OpenSSL patch, which was implemented to protect the Configuration utility and iControl against a midstream SSL renegotiation vulnerability, disabled SSL renegotiation. For more information about the vulnerability, refer to K10737: SSL Renegotiation vulnerability - CVE-2009-3555 / VU#120541.

The OpenSSL patch was introduced in the following hotfixes and versions:

  • BIG-IP 9.3.1 HF8
  • BIG-IP 9.4.8 HF2
  • BIG-IP 10.0.1 HF3
  • BIG-IP 10.1.0 and later

If a node initiates a renegotiation after application data starts flowing, the HTTPS monitor will mark the node down. It is common behavior for a server to request a client certificate after the application data starts flowing in response to the monitor's request; for example, Microsoft IIS 6 and IIS 7 servers exhibit this behavior.

F5 Product Development tracked this issue as ID 338150 and it was fixed in BIG-IP 10.2.2. For information about upgrading, refer to the BIG-IP LTM release notes.

In addition, BIG-IP iHealth lists Heuristic H383260 on the Diagnostics > Identified > Medium screen

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
