Description

When a REST API call is made from a user with Auditor Role to request full config data (tmsh show running-config), the response will fail with a 400 error:

Request:
$ curl -sk -H "$user: $token"  -X POST -H "Content-Type: application/json" https://<ManagmentPort>/mgmt/tm/util/bash -d "{\"command\":\"run\", \"utilCmdArgs\": \"-c 'tmsh show running-config'\"}"  `sed 's/\\n/\n/g'

Response:
{"code":400,"message":"\"bash\" unexpected argument","errorStack":[],"apiError":26214401}
or
{u'errorStack': [], u'message': u'"bash" unexpected argument', u'code': 400, u'apiError': 26214401}

Environment

  • BIG-IP
  • REST API
  • iControl REST
  • Auditor role
  • tmsh show running config
 

Cause

The Auditor Role cannot access BASH, while the description for this role says that they can access configuration of the device, this doesn't mean that they can run "tmsh show running-config" via REST API.

Recommended Actions

There is no equivalent command for 'tmsh show running-config', however the auditor role can still request configuration elements individually. 

1.  In order to get the available list of ltm configuration items, run the following command:

$ curl -sku $PASS https://$HOST/mgmt/tm/ltm | jq -r '.items[].reference | .link'

2.  Admin Users with bash access can run "tmsh show running-config" in one request:
  
curl -sku admin:admin https://<managementPort>/mgmt/tm/util/bash -H "Content-type: application/json" -X POST \
  -d '{"command":"run", "utilCmdArgs":"-c \"tmsh show running-config\""}' \
| jq -jr .commandResult

Additional Information

Use -u curl option. If you want to use -H for providing basic authentication data, the value should be something like "Authorization: basic <base64Password>".

jq -jr .commandResult  extracts only the relevant part with the literal \n converted to LF in one-shot.
