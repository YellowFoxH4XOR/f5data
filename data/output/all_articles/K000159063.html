K000159063: HTTP Only Flag is not seen even after setting up Persistence

Type
Support Solution
Published
2026-02-20
Updated
2026-02-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000159063

Description

When using BIG-IP LTM with cookie persistence, the HttpOnly and Secure attributes may not appear in the first Set-Cookie HTTP response header for BIG-IP persistence cookies, even when these options are enabled in the persistence profile configuration. This can be confirmed when:

  • The attributes are enabled in the persistence profile but do not appear in the first Set-Cookie header
  • Security scans or browser developer tools show the attributes appear in separate Set-Cookie fields
  • Packet captures do not show the expected cookie security attributes

Environment

  • Virtual server with cookie persistence profile configured
  • HTTP Cookie Insert persistence method
  • HttpOnly and/or Secure attributes enabled in the persistence profile

Cause

The default BIG-IP cookie persistence behavior does not always apply the HttpOnly and Secure attributes to persistence cookies in the first Set-Cookie header position, even when these options are enabled in the persistence profile configuration. An iRule is required to explicitly manipulate the HTTP response and insert these security attributes into the BIG-IP persistence cookies.

Recommended Actions

To ensure that the HttpOnly and Secure attributes are properly set on BIG-IP persistence cookies, implement the following iRule on the virtual server:

  1. Navigate to Local Traffic > iRules > iRule List in the BIG-IP Configuration utility.

  2. Create a new iRule with the following code:

when HTTP_RESPONSE {
    foreach x [HTTP::cookie names] {
        if { $x starts_with "BIGipServer" } {
            set ckname $x
            set ckvalue [HTTP::cookie value $x]
            HTTP::cookie remove $x
            HTTP::cookie insert name $ckname value $ckvalue path "/" version 1
            HTTP::cookie secure $ckname enable
            HTTP::cookie httponly $ckname enable
        }
    }
}

  1. Assign the iRule to the virtual server:

    • Navigate to Local Traffic > Virtual Servers > Virtual Server List
    • Select the virtual server
    • Go to the Resources tab
    • Under iRules, click Manage
    • Move the iRule from Available to Enabled
    • Click Finished

  2. Verify the configuration by testing the application and checking that the persistence cookie includes both the HttpOnly and Secure attributes in browser developer tools or packet captures.

This iRule intercepts HTTP responses, identifies BIG-IP persistence cookies (typically named with the "BIGipServer" prefix), removes the original cookie, and reinserts it with the Secure and HttpOnly flags explicitly enabled.
The iRule uses the HTTP_RESPONSE event, which processes server-side responses.
