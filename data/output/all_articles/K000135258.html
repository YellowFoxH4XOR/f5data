K000135258: Migration from hardware platform BIG-IP ASM to VE with configuration load options platform-migrate and no-license fails

Type
Support Solution
Published
2023-06-27
Updated
2023-06-27
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.X.X, 17.1.X, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K000135258

Description

When attempting to migrate from a hardware BIG-IP ASM to a VE BIG-IP ASM using the configuration load options platform-migrate and no-license fails with an error similar to the following:

Could not import table DCC_ucs.ACCOUNT_NEGSIG_SIGNATURE_PROPERTIES data from file ts_db.data.DCC.ACCOUNT_NEGSIG_SIGNATURE_PROPERTIES.cstmp - ASM configuration load aborted
Issuing rollback() due to DESTROY without explicit disconnect() of DBD::mysql::db handle DCC:127.0.0.1 at /usr/local/share/perl5/F5/ConfigSync.pm line 367. ERROR: Failed during loading ASM configuration.
 

Environment

  • Hardware platform migration
  • VE
  • Configuration load options
  • platform-migrate
  • no-license

Cause

Unknown
 

Recommended Actions

  1. Log on to the BIG-IP ASM command line with administrative privileges.
  2. Attempt to load the UCS file: load /sys ucs /var/local/ucs/<ucs filename> platform-migrate passphrase <passphrase> no-license
  3. Restart the mcpd process: bigstart restart mcpd
  4. Attempt to load the configuration again using the "platform-migrate" option: load /sys ucs /var/local/ucs/<ucs filename> platform-migrate passphrase <passphrase> no-license


Note: In the event that the previous steps do not resolve the issue, re-execute the steps adding the following step prior to the last step of loading the configuration: cp /config/bigip/kstore/.master.recovery /config/bigip/kstore/master
