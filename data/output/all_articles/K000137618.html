K000137618: APM session hangs when using API calls and cURL requests

Type
Support Solution
Published
2023-11-17
Updated
2023-11-17
Source
https://my.f5.com/manage/s/article/K000137618

Description

You are attempting to access or modify a resource behind F5 APM, however the APM session logs show that the policy hangs after printing the first two log messages:
Nov 17 09:00:00 hostname.f5.com notice tmm2: /Common/access:sessionID: Received User-Agent header: curl%2F8.2.1.
Nov 17 09:00:00 hostname.f5.com notice tmm2:: /Common/access:sessionID: New session from client IP 192.168.0.1 (ST=/CC=/C=) at VIP 192.168.0.2 Listener /Common/Vs (Reputation=Unknown)

Environment

Resource behind F5 APM accessed by cURL or API call

Cause

The issue arises because APM access policies are typically configured with interactive elements, such as logon pages, and there is also a 302 redirect to /my.policy, which are not compatible with non-interactive clients like cURL or API calls. When these clients attempt to access resources behind APM, they cannot process these elements, leading to the hanging of the policy as observed in the session logs.

Recommended Actions

Ensure to include the Clientless-Mode header in your request to inform APM of the non-interactive nature of the client. Here is an example for cURL:
curl -H 'Clientless-Mode: 1' -u username:password https://your.domain.com/
You can read more about this in Authenticate on APM with cURL using Clientless-Mode (f5.com).

An alternative would be to use an iRule to automatically add this header, as shown in The functionality of Clientless-Mode in F5 APM
