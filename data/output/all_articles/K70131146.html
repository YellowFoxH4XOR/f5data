Description

  • Visual Studio intermittently failing to connect, or existing VS sessions time out.
  • HTTP POST request, containing NTLMSSP_NEGOTIATE header doesn't make it through the virtual server.

Environment

  • 12.1.5.2 and 15.1.0 are confirmed to be affected.
  • Standard LTM virtual server, containing an HTTP profile.

Cause

Bug ID 851857 may be the issue preventing Visual Studio from staying connected

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. Workaround: remove HTTP profile, or use FastL4 virtual server. 
  2. Workaround: add the following iRule:  

    ltm rule /Common/C3328032_test_Post {
        when HTTP_REQUEST {
            if {  [HTTP::header "Content-Length"] > 0 && [HTTP::header "Content-Length"] < 30000 } {
                log local0. "Client [IP::client_addr]:[TCP::client_port] -> [HTTP::host][HTTP::uri]"
            HTTP::collect [HTTP::header "Content-Length"]
            }
        }
    }

    The iRule will cause tmm to wait until the POST body comes in before forwarding the request to the pool member which is suspected is the trigger for this issue.

  3. Workaround: Upgrade to a software version not effected by this ID

Additional Information

Engineering Hotfixes may be available if a full upgrade is not possible
