Description:

As described in RFC 1035:
Messages carried by UDP are restricted to 512 bytes (not counting the IP or UDP headers).  Longer messages are truncated and the TC bit is set in the header.


And also in RFC 5966:

In the absence of EDNS0 (Extension Mechanisms for DNS 0), the normal behavior of any DNS server needing to send a UDP response that would exceed the 512-byte limit is for the server to truncate the response so that it fits within that limit and then set the TC flag in the response header. When the client receives such a response, it takes the TC flag as an indication that it should retry over TCP instead.

Right now the BIG-IP will check if the UDP message is larger than the expected value and follow some rules to chop off the sections at the end of the response, adjusts the length in the header, and sets the TC bit.

 

Environment:

  • DNS system
  • DNS cache or transparent cache is being used as a resolver

Cause: 

Here's the scenario:

  1. The DNS query from an LDNS (without EDNS0 option that claims UDP payload size) reaches the listener and matches the DNS cache resolver.
  2. BIG-IP DNS system sends the query to other nameservers ( with EDNS0 option UDP payload size 4096 ).
  3. The DNS response includes a CNAME RR.
  4. BIG-IP DNS system sends the query of that CNAME to other nameservers ( with EDNS0 option UDP payload size 4096 ).
  5. The DNS response can be larger than 512 Bytes.
  6. BIG-IP DNS cache resolver will merge these 2 responses, check whether it's over 512 bytes, truncate the response if needed, and then send the modified response back to LDNS.

Here are some of the truncating rules: 

  1. If the merged response is over 512 bytes, the response will be truncated.
  2. The least additional RRs will be removed to make sure the whole response is less than 512 bytes, the TC flag will not be set.
  3. If all of the additional RRs are removed already, but the whole response is still larger than 512 bytes, the least Authority RRs will be removed, TC flag will be set.
  4. If all of the additional RRs and Authority RRs are all removed already, but the whole response is still larger than 512 bytes, all of the Answer RRs will be removed except for the CNAME RR(see the scenario described in the Cause Section), TC flag will be set.
  5. When the TC flag is set, LDNS should establish a TCP connection with the listener to transfer the DNS response.

Recommended Actions:

None

Additional Information:

A DBkey variable is used to control the truncating behavior:


dns.udptruncate:

  • Can be set to enabled (default) or disabled.  
  • When dns.udptruncate is enabled, UDP DNS responses are truncated if the response is larger than 512 bytes.
  • When dns.udptruncate is disabled, the message is not truncated, and the full message is received. If the client specifies a non-default size via EDNS, the message is truncated if the response is larger than the specified size regardless of the value of dns.udptruncate.

regarding the behavior of the cache which is resolver type and dns.udptruncate is disabled :

  • the DNS query sent by the cache will first use UDP.
  • No matter whether the DNS query includes the EDNS0 option UDP payload size, the DNS query sent by the cache ( from BIG-IP ) will not bring that option.
  • If the DNS response received by the cache is larger than 512 bytes, truncating will happen on the server-side, and a TCP connection is required to be established from the cache to the target nameserver to transfer the full response.
  • The cache will deliver the full message on the client-side with TC flag set to 0 even when the response is larger than 512 bytes.
regarding the behavior of the cache which is transparent type and dns.udptruncate is disabled:
  • If a server-side name server truncates the data before it gets to the BIG-IP, a transparent cache will cache and deliver the previously truncated data.
  • Since a transparent cache is not a resolver, the BIG-IP will not attempt the TCP reconnect to get the full answer.

To enable or disable this db key, you may use the below command:

tmsh modify sys db dns.udptruncate value < enable | disable >

For example, to enable the db key:

tmsh modify sys db dns.udptruncate value enable
