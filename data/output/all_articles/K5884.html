K5884: BIG-IP reports VLAN errors when a VLAN on a standby unit has been removed and the standby unit becomes active

Known Issue

This is the result of a known issue. If you delete a VLAN, other than the first configured VLAN, and delete the associated self IP address on a system in standby state, it appears that the objects were deleted successfully; however, the VLAN has not been properly removed. If you then make the standby system active, the VLAN continues to exist, although the VLAN name has been removed.

This scenario can cause any of the following issues to occur:

  • The bigpipe vlan command reports the error, No VLANs were found.
  • Virtual servers that used the deleted VLAN are now associated with a default numbered VLAN.
  • Viewing VLANs in the Configuration utility results in the error message Error 138 -- The requested VLAN was not found.

Important: If any of the issues listed occurs, reboot the BIG-IP system, by typing the following command, and proceed with the Workaround:

reboot

F5 Networks Product Development is tracking this issue as CR58683. Monitor future BIG-IP Release Notes for the status of this CR.

Workaround

To avoid this issue, perform the following steps:

  1. Delete the VLAN.
  2. Delete the associated self IP address.
  3. Save the configuration, by typing the following command:

    bigpipe save

  4. Load the configuration, by typing the following command:

    bigpipe load

When the configuration is reloaded, the VLANs will be created properly.
