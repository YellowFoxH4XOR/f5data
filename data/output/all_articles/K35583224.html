Description

Due to the large size of BIG-IP ASM request logs records, the size of the internal MySQL/MariaDB can become full when the logrotate fails to delete old records, BIG-IP ASM administrator can choose to delete the internal database log requests records from a specific date.

Environment

  • BIG-IP ASM
  • MySQL/MariaDB
  • BIG-IP ASM Event Logs

Cause

None

Recommended Actions

Impact of procedure: Performing the following procedure should not have a negative impact on your system. Once the MySQL/MariaDB records are deleted, those cannot be recovered back.

    1. Log in to the Advanced Shell (bash).
    2. List all the support IDs that are stored on specific date
      mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "select from PRX.REQUEST_LOG where from_unixtime(floor(log_time)) <= '<date>'"

    3. Choose a required date and place it in the following command and execute:
      mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "delete from PRX.REQUEST_LOG where from_unixtime(floor(log_time)) <= '<date>'"

      For example, the below command will delete all the PRX request log records before the date 2021-09-09 00:34:06
      mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "delete from PRX.REQUEST_LOG where from_unixtime(floor(log_time)) <= '2021-09-09 00:34:06'"

     

    Additional Information

    If you determine that a BIG-IP ASM system log located in the /var/log directory is consuming too much space, you can permanently delete the contents of the file. For example, to permanently delete the contents of /var/log/asm.1 log file, enter the following command:

    cat /dev/null > /var/log/asm.1
