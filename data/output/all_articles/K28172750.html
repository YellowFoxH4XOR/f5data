K28172750: The BIG-IP can be configured to use either tmm or mgmt interfaces for remote authentication (LDAP, TACACS, RADIUS, etc.) traffic.

Type

Published
2021-10-25
Updated
2025-04-01
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K28172750

Description

You need to specify either tmm or the management interface for remote authentication traffic. Or you may need to determine whether tmm or the management interface are processing the traffic.

  • If the traffic fails you may see a message similar to "Remote authentication server unreachable; local authentication failed".

Environment

  • Depending on your network needs you will need to route the traffic via either eth0 (management) or tmm
  • Static Routes, Self-IPs, Default Routes
  • Remote Authentication, TMM, and Management Interfaces, LDAP, RADIUS, TACACS, TACACS+, Active Directory

Cause

The Traffic Management Microkernel (TMM) controls all of the BIG-IP switch ports (TMM interfaces), and the underlying Linux operating system controls the BIG-IP management interface. The management interface processes only administrative traffic. The TMM interfaces process both application traffic and administrative traffic.

The Linux operating system processes outbound traffic sent from the BIG-IP system by administrative applications, such as SNMP, SMTP, SSH, and NTP. These connections may use either the management address or a self IP address as the source address. The BIG-IP system compares the destination address to the routing table to determine the interface through which the BIG-IP system routes the traffic.

If you need to use the management interface to communicate with the remote authentication server and they do not reside in the same subnet, then you must add a static management route that is more specific than any TMM routes to this server. This article will help with setting up that static route: K13284: Overview of management interface routing

Recommended Actions

Depending on the needs of your network you will need to set up the proper route configuration. That may entail adding a specific route to enable the traffic to use the management interface or ensuring there is a self-ip for tmm to handle the traffic. Since the answers here can be so varied the article links in the "Related Content" section should help find a direction to go.
 Additional Information
It is worth mentioning here that in a scenario in which remote authentication fails, for instance when the remote auth server goes down, you can setup a back up method so you can still access the BIG-IP.
K49218438: Configuring local authentication as a backup method for remote authentication (13.x - 16.x)

When looking into the routing tables you also need to be aware that tmm and the Linux kernel both maintain their own routing tables and both look different. To review the tmm routing table you would run the command tmsh show net route. For the management route, via the Linux kernel, you would use ip route in the bash shell.
