Known Issue

User configuration set (UCS) archives may fail to load when the configuration contains Secure Sockets Layer (SSL) profiles derived from the clientssl-insecure-compatible or wom-default-clientssl default profiles.

This issue occurs when all of the following conditions are met:

  • An SSL profile is configured with a clientssl-insecure-compatible or wom-default-clientssl default profile as the parent profile.
  • You do one of the following:
    • You attempt to load a UCS archive created using 11.2.1 or earlier on a system running 11.5.0 or 11.5.1.
    • You attempt to upgrade a system running 11.2.1 or earlier to 11.5.0 or 11.5.1.

Impact

You are unable to load the UCS archive.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Attempts to upgrade a BIG-IP system to 11.5.0 or 11.5.1 fail.
  • Attempts to install UCS archives from 11.2.1 or earlier fail in 11.5.0 or 11.5.1.
  • You observe messages in the /var/log/liveinstall.log file that appear similar to the following example:

    sh: line 1: 17370 Killed F5_INSTALL_MODE=install F5_INSTALL_SESSION_TYPE=install chroot /mnt/tm_install/11891.YE8h4N /usr/local/bin/im -force /var/local /ucs/config.ucs 2>&1

    Terminal error: UCS application failed; unknown cause.
  • The installation status in the Configuration utility's System > Software Management > Image List page show messages that appear similar to the following example:

    failed (UCS application failed; unknown cause.)

Workaround

To work around this issue, you can reconfigure the affected SSL profiles to use clientssl as the parent profile, and attempt the upgrade or UCS load operation again. If a UCS load operation failed, you will need to boot back to the system where the UCS archive was generated, reconfigure the affected SSL profiles and create a new UCS archive, and then boot back to the target system to attempt to load the new UCS. To reconfigure the affected SSL profiles, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Click the name of an affected profile.
  4. In the Parent Profile \menu, select clientssl.
  5. Click Update.
  6. Repeat steps 2 through 5 for all the affected SSL profiles.
  7. When you have updated all of the affected profiles, attempt the upgrade or UCS load operation again.

Note: Make sure you return all of the modified profiles to their previous settings once the upgrade or UCS load operation is complete.
