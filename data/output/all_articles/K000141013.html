Description

A newly installed or PXE-booted VELOS controller or blade is unable to join the existing VELOS cluster.

Examination of the /var/log/openshift.log file on the active controller reveals messages similar to the following:

/usr/bin/ansible-playbook -vv --flush-cache -i /tmp/omd/etc_ansible_masters_add /usr/share/ansible/openshift-ansible/playbooks/openshift-master/scaleup.yml
<...>
An exception occurred during task execution. To see the full traceback, use -vvv. The error was: KeyError: 'address'
fatal: [controller-1.chassis.local]: FAILED! => {"changed": false, "module_stderr": "Shared connection to controller-1.chassis.local closed.\r\n", "module_stdout": ...
An exception occurred during task execution. To see the full traceback, use -vvv. The error was: TypeError: sequence item 0: expected string, NoneType found
fatal: [controller-2.chassis.local]: FAILED! => {"attempts": 30, "changed": false, "module_stderr": "Shared connection to controller-2.chassis.local closed.\r\n", "module_stdout": ...
PLAY RECAP *********************************************************************
InstallProgress: Updating the status of playbook AddingController to Done
InstallProgress: Execution for play book AddingController is Failed
Ansible Failed /usr/bin/ansible-playbook -vv --flush-cache -i /tmp/omd/etc_ansible_masters_add /usr/share/ansible/openshift-ansible/playbooks/openshift-master/scaleup.yml

Note the failures:

The error was: KeyError: 'address'
The error was: TypeError: sequence item 0: expected string, NoneType found

Environment

  • VELOS OpenShift cluster
  • System controller

Cause

This issue can happen if the host has no default IPv4 route. This would be the case if the system has no IPv4 management IP configured, for example.

This issue will also occur when using IPv6-only management. Bug ID1581589 tracks the problem.

Recommended Actions

Configure an IPv4 management IP and route.

If you are using IPv6-only management addressing, you can work around this issue by adding a default IPv4 route:

source /etc/sysconfig/chassis_network_active.txt
nmcli conn modify team0 ipv4.gateway ${network_prefix:-100.65}.3.254 ipv4.route-metric 32768

The next run of the Ansible scaleup.yml playbook should not encounter the error.

If you are seeing this issue when you already have IPv4 management configured, further investigation is required. Open a support case with F5.
