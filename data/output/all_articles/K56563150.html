Description

In a specific environment, an iRule may incorrectly send traffic to a pool in a different partition.

Environment

  • You are using multiple partitions
  • You have a Virtual Server on a specific partition and has an iRule from /Common/ partition
  • A pool has the same name from another pool in different partition
  • iRule's logic is to forward traffic to the pool

Example:

/partition_1/my_vs
/partition_1/my_pool
/partition_2/my_pool
/Common/my_irule


iRule Config:

ltm rule /Common/my_irule {
when HTTP_REQUEST {
set part [virtual name]
  log local0. "Virtual Server Partition/Name: $part"
      pool my_pool
      return
}
when LB_SELECTED {
log local0. "Pool Member Partition/Name: [LB::server pool]"
}
}

Virtual Server config:

ltm virtual /partition_1/my_vs {
    destination /partition_1/10.108.124.230:http
    ip-protocol tcp
    mask 255.255.255.255
    partition partition_1
    profiles {
        http { }
        tcp { }
    }
    rules {
        my_irule
    }
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}

Pool Config:

ltm pool /partition_1/my_pool {
    members {
        /partition_1/10.108.124.194:http {
            address 10.108.124.194
            session monitor-enabled
            state up
        }
    }
    monitor gateway_icmp
    partition partition_1
}

ltm pool /partition_2/my_pool {
    members {
        /partition_2/10.108.124.195:http {
            address 10.108.124.195
            session monitor-enabled
            state up
        }
    }
    monitor gateway_icmp
    partition partition_2
}

Logs:

Oct  2 21:07:11 bigip1 info tmm[17943]: Rule /Common/my_irule <HTTP_REQUEST>: Virtual Server Partition/Name: /partition_1/my_vs
Oct  2 21:07:11 bigip1 info tmm[17943]: Rule /Common/my_irule <LB_SELECTED>: Pool Member Partition/Name: /partition_2/my_pool

Cause

The partition is not defined in the iRule command statement

Recommended Actions

The iRule below will capture the current partition of the Virtual Server which the client connected to and will prepend it to the pool name. You can use it or modify it based on your requirement:

when HTTP_REQUEST {
    log local0. "Virtual Server Partition/Name: [virtual name]"
    set part [lindex [split [virtual name] /] 1]
    pool /${part}/my_pool
    return
}
when LB_SELECTED {
log local0. "Pool Member Partition/Name: [LB::server pool]"
}

Additional Information

Once you applied the iRule above which includes the logging statement, you should see this on /var/log/ltm

Oct  2 21:22:42 bigip1 info tmm[17943]: Rule /Common/my_irule-fix <HTTP_REQUEST>: Virtual Server Partition/Name: /partition_1/my_vs
Oct  2 21:22:42 bigip1 info tmm[17943]: Rule /Common/my_irule-fix <LB_SELECTED>: Pool Member Partition/Name: /partition_1/my_pool
