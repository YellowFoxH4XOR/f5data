Known Issue

Creating IPv6 reject blackhole routes using the Traffic Management Shell (tmsh) or the Configuration utility does not update the BIG-IP Advanced Routing Module (ARM) routing table.

This issue occurs when any of the following conditions are met:

  • You create a blackhole IPv6 route using the BIG-IP tmsh utility.
  • You create a reject IPv6 route using the BIG-IP Configuration utility.

Impact

The system adds the desired IPv6 route to the local route table, but does not place it in the BIG-IP ARM dynamic routing table, and the routing protocol does not redistribute the route.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H421077 on the Diagnotics > Identified > Medium screen.
  • After you create an IPv6 reject/blackhole route with tmsh or the Configuration utility and view the BIG-IP ARM routing table with an imish command, the route is not present. To view the BIG-IP ARM routing table, type the following command:

    imish -e "show ipv6 route"

    However, the newly created reject/blackhole route is visible in the local TMOS route table using tmsh or the Configuration utility. To view the newly-created reject/blackhole route, type the following command:

    tmsh show net route

  • When you create a route using tmsh or the Configuration utility, the system does not update the BIG-IP ARM routing table with the route information and does not update the adjacent routers with the change.

Resolution

Status

Workaround

To work around this issue, you can add IPv6 Null0 routes directly to the BIG-IP ARM routing table with the imish BIG-IP ARM console utility.
