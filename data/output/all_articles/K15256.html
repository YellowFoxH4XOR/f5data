Known Issue

Certain iRules can result in abandoned UDP connection flows.

This issue occurs when the following condition is met:

  • A UDP Virtual Server is configured with iRules that have suspending commands in both the CLIENT_CLOSED and SERVER_CLOSED iRule events.

When iRules that are configured with suspending commands are used in both the CLIENT_CLOSED and SERVER_CLOSED iRule events, the system can leave connection flows unallocated. The system leaves these flows in the connection table, and the flows can possibly match new client connections, but they will not pass traffic. Connections remain until you restart the Traffic Management Microkernel (TMM).

You can use certain iRule commands to access information that is external to the current connection flow. For example, you can use an iRule command to access the external data when the system interacts with the BIG-IP session table through the Table or Session commands, and the data in question is not stored within the same TMM, or you can use an iRule command when initiating communication to another side-band resource, in which case you could use, for example, the RESOLV::lookup command.

If you use certain iRule commands to access information that is external to the current connection flow, the iRule becomes suspended until the iRule command accessing the external command completes. For more information, refer to the DevCentral article iRules Concepts: Connection States and Command Suspension.

Impact

The system experiences increased memory usage, which leads to a possible outage.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H457693 on the Diagnostics > Identified > Medium screen.
  • Abandoned connections appear in the output of the tmsh show sys connection command.
  • New connections from the same client port may match an abandoned connection and the BIG-IP system silently drops them.

Workaround

To work around this issue, you can avoid using suspending commands in both the CLIENT_CLOSED and SERVER_CLOSED events for the same UDP virtual server.

To clear affected connection flows, you must restart TMM, which will clear all connection flows.

Impact of workaround: Restarting the TMM causes the BIG-IP system to drop the current connections. You should perform this workaround only during a maintenance window.

You can restart the TMM processes by typing the following command:

bigstart restart tmm
