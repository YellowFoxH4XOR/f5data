Issue

In BIG-IP WebAccelerator versions prior to 10.0.0, the BIG-IP WebAccelerator accepted either a host name or an IP address when configuring a BIG-IP WebAccelerator application host in the Requested Hosts list.

Beginning in BIG-IP WebAccelerator 10.0.0, the BIG-IP WebAccelerator accepts only host names when configuring hosts in the Requested Hosts list; IP addresses are no longer accepted. If you attempt to save a Requested Hosts list that contains an IP address, the following notification is displayed and the update is not saved:

There was 1 error. The application was not saved.
(1) Please check Requested Host details - use hostnames instead of IP addresses.

This functionality was intentionally changed as a result of CR102328 to prevent issues with the MultiConnect feature, which occurred when IP addresses rather than hostnames were specified in the Requested Hosts list.

Beginning in BIG-IP WebAccelerator 10.1.0, and also in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP 10.0.1, the BIG-IP WebAccelerator again accepts either a host name or an IP address when configuring a BIG-IP WebAccelerator application host in the Requested Hosts list. However, if you attempt to enable MultiConnect on a requested host configured with an IP address, the following notification is displayed and the update is not saved:

There was 1 error. The application was not saved.
(1) Please check Requested Host details - use hostnames instead of IP addresses when MultiConnect enabled.

Note: These changes were made intentionally as a result of two enhancement requests tracked by F5 Networks Product Development to allow more flexibility regarding this behavior: ID206692 and ID330884 (formerly CR118431) requested the capability to use IP addresses in the Requested Hosts list; and ID327095 (formerly CR118432) requested a change to prevent MultiConnect functionality from being applied to a Requested Host specified as an IP address.
