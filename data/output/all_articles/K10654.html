Topic

Running a bigpipe command in BIG-IP 9.4.2 through 9.4.8 takes longer than running the same command in previous BIG-IP versions. This behavior is expected; a loosely-typed configuration system was introduced in BIG-IP 9.4.2.

Note: A loosely-typed programming language is typically one that does not require the type of a variable to be explicitly stated. For example, Perl is a loosely typed language. Any type of data can be put into a variable, and Perl will interpret the data based on context.

Due to this change, each time a bigpipe command is executed, all configuration object types are queried so that the parameters passed to the bigpipe utility can be validated. This results in extra time needed to run the command.

For example, running the bigpipe node 192.168.1.1 { } command to create a new node takes 0.026 seconds in BIG-IP 9.3.1 and 0.124 seconds in BIG-IP 9.4.2. Any bigpipe command will take approximately 0.1 seconds longer to run in BIG-IP 9.4.2 through 9.4.8.

This difference is acceptable when a BIG-IP administrator is required to run only a single bigpipe command; however, complex scripts featuring many bigpipe commands can take a few more seconds to run.

Beginning in BIG-IP 10.0.0, the bigpipe utility was further improved to reduce execution times to values similar to those of BIG-IP versions prior 9.4.2.

Workaround

If you require executing several bigpipe commands, you may use the bigpipe merge feature instead of running many single bigpipe instructions.

Note: The bigpipe merge command reads instructions from a text file and executes them.

For example, the following bash script, which calls many bigpipe commands, executes in 1.1 seconds:

#!/bin/bash

bigpipe interface 1.2 media fixed 100baseTX full
bigpipe vlan internal { interfaces 1.2 }
bigpipe self 192.168.1.1 { vlan internal }
bigpipe node 192.168.1.10 192.168.1.11 { }
bigpipe pool http_servers { members 192.168.1.10:80 192.168.1.11:80 monitor all http }
bigpipe profile http my_http_profile { defaults from http redirect rewrite all }
bigpipe interface 1.3 media fixed 100baseTX full
bigpipe vlan external { interfaces 1.3 }
bigpipe self 172.16.1.1 { vlan external }
bigpipe virtual http_vs { destination 172.16.1.10:80 pool http_servers snat automap profiles my_http_profile } 

Each bigpipe instruction needs to query the configuration object types, which results in an extended execution time. Instead of running that script, you may create a new text file, containing the same instructions (but not proceeded by bigpipe), and then run the bigpipe merge command against that file. The bigpipe merge command will only take 0.152 seconds to execute the same instructions, since the configuration object types are queried only once.

To create a merge file for the instructions in the example, you would perform the following procedure:

  1. Log in to the BIG-IP system command line.
     
  2. Change directories to the /var/tmp/ directory by running the following command:

    cd /var/tmp/
  3. Edit a new text file with an editor of your choice.

    For example:

    vi merge_file
     
  4. Paste the following text into the editor:

    interface 1.2 media fixed 100baseTX full
    vlan internal { interfaces 1.2 }
    self 192.168.1.1 { vlan internal }
    node 192.168.1.10 192.168.1.11 { }
    pool http_servers { members 192.168.1.10:80 192.168.1.11:80 monitor all http }
    profile http my_http_profile { defaults from http redirect rewrite all }
    interface 1.3 media fixed 100baseTX full
    vlan external { interfaces 1.3 }
    self 172.16.1.1 { vlan external }
    virtual http_vs { destination 172.16.1.10:80 pool http_servers snat automap profiles my_http_profile }
     
  5. Save the file and quit the editor.
     
  6. Run the bigpipe merge command against the newly created text file.

    For example:

    bigpipe merge merge_file
