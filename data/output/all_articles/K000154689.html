Description

A network loop can occur when ICMP Destination Unreachable (Port Unreachable, Type 3 Code 3) packets are repeatedly forwarded between a BIG-IP system and an upstream router. This results in high CPU usage on the router. Packet captures reveal that the BIG-IP forwarding virtual server (VS) forwards ICMP packets to the router, which then returns them to the BIG-IP, creating a continuous loop. 

Environment

  • BIG-IP LTM
  • UDP protocol

Cause

The forwarding virtual server is configured with a broad destination (e.g., 0.0.0.0/0), which matches all protocols, including ICMP. When the router generates an ICMP Destination Unreachable message (for example, when a client sends a UDP request to a virtual server, and while replying, the client is unreachable), the forwarding VS on the BIG-IP forwards this ICMP packet back to the router. The router then sends it back to the BIG-IP, resulting in a loop. TTL decrements in packet captures confirm the repeated traversal.

Figure: Loop During DNS Query Handling

Recommended Actions

1. Restrict Forwarding VS Protocols:

Limit the forwarding virtual server to only required protocols (such as TCP/UDP). Avoid using "all protocols" or a /0 mask unless necessary.

2. Create Protocol-Specific Virtual Servers:

If ICMP handling is required, create a dedicated forwarding virtual server for ICMP with specific destination and protocol settings, rather than allowing general matching of all ICMP traffic.

3. Apply Global AFM Policy (if provisioned):

Use AFM to create a global firewall policy that drops unwanted ICMP packets (such as Type 3 Code 3) before they reach any forwarding VS. This provides precise control and prevents loops.
