K000159593: Machine Tunnel fails to reconnect after prolonged sleep on Windows 11 EC 7.2.6

Description

On Windows 11 endpoints running BIG-IP Edge Client 7.2.6.2, the F5 Machine Tunnel Windows service (used for pre-logon Network Access) stops after the device resumes from prolonged sleep/standby. After a sleep/wake cycle, the tunnel closes with PPP/LCP indicators such as: LCP_UNKNOWN_OPTIONS, LCP_PROTO_REJ, FSM_UNEXPECTED_DOWN.

Environment

BIG-IP Edge Client 7.2.6 or newer

F5 Machine Tunnel

Cause

Bug ID 2151801, which was discovered after the fix for ID 1166225 was introduced in 7.2.6. The Machine Tunnel includes emergency cleanup logic that restarts/stops the service when a VPN connection is not detected. During power-state transition events, this cleanup is being triggered too early, before the device fully enters sleep/hibernation. As a result, after resume the service does not reliably reconnect, and in some cases, no new Machine Tunnel logs are generated after hibernation/sleep. 

Answer/Recommended Actions

Use Lock instead of sleep/hibernation, as locking should not trigger the same power-transition cleanup behavior.

If sleep cannot be avoided, use a temporary workaround to restart the F5 Machine Tunnel service after wake (manual restart or automated via scheduled task/service recovery action. 

At the time of writing this article, the fix is expected around APM Client version 7270.
