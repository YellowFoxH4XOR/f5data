K000161058: "Another save is in progress" and Config/UCS Save Failures on BIG-IP Caused by Automation Scripts

Description

When attempting to save the system configuration or create a UCS file on BIG-IP LTM, the operation may hang and fail to complete. The system displays the error:

Another save is in progress. You may use the option 'wait'.

This issue can persist even after following standard troubleshooting steps, such as removing lock files, and may be accompanied by multiple long-running or defunct tmsh save processes. Attempts to save the configuration or UCS file continue to fail until further action is taken.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.X
  • Automation: Ansible scripts executing tmsh save commands
  • Symptoms:
    • tmsh save sys config hangs or fails
    • tmsh save sys ucs hangs or fails
    • Error: Another save is in progress
    • Multiple tmsh save processes running for extended periods
    • Defunct processes (e.g., [mysql] <defunct>, [asm_config_serv] <defunct>)
  • No disk space or inode issues detected

Cause

A buildup of stuck tmsh save processes, primarily initiated by Ansible automation scripts, held the configuration lock and prevented new save operations. Secondary UCS save failures were due to a missing temporary directory and a stuck pre-save script, likely resulting from the earlier system state. A full reboot was required to clear all underlying process and lock issues.

Answer/Recommended Actions

  1. Identify and Kill Stuck Processes
    • List defunct and long-running processes:

      ps aux | grep -i defunct

      ps aux | grep tmsh

    • Kill stuck tmsh save and related processes:

      pkill -f "tmsh -c save /sys config file"

      pkill -f "tmsh -c save /sys ucs"

    • For persistent processes, use:

      kill -9 <PID>

  2. Remove Stale Lock Files
    • Check and remove the configuration save lock file if present:

      rm -f /var/run/config_save.pid

  3. Verify System Resources
    • Ensure disk space and inode usage are sufficient on all relevant partitions.
  4. Restart Management Services (if needed)
    • Restart services such as restjavad and syscalld:

      bigstart restart restjavad syscalld

  5. Reboot the Device (if issue persists)
    • If the above steps do not resolve the issue, perform a full device reboot.
  6. Post-Reboot Validation
    • After reboot, verify that tmsh save sys config and tmsh save sys ucs complete successfully.
  7. Review Automation Scripts
    • Update Ansible or other automation scripts to ensure they do not leave orphaned tmsh save processes.

Additional Information

  • This issue is often associated with automation tools (such as Ansible) that may not properly handle process cleanup, leading to orphaned or stuck tmsh save operations.
  • A full device reboot is sometimes required to clear all underlying issues if process and lock file cleanup does not resolve the problem.
