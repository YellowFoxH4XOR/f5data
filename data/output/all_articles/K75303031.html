Topic

This article applies to BIG-IP 13.x through 16.x. For information about other versions, refer to the following article:

  • K91881543: Configuring gateway fail-safe using the Configuration utility (11.x - 12.x)

You should consider using this procedure under the following condition:

  • You require setting up the gateway fail-safe feature using the Configuration utility.

Description

The gateway fail-safe feature allows further redundancy between BIG-IP device group members that point to different gateways. The gateway fail-safe feature allows each BIG-IP system to monitor the upstream gateway it uses to route traffic. If the gateway is marked down, the BIG-IP system can fail over to the next active device to prevent further disruption to traffic.

Before configuring the gateway fail-safe feature, you should consider the following information:

  • If the redundant BIG-IP systems reference the same virtual Hot Standby Router Protocol (HSRP)/Virtual Router Redundancy Protocol (VRRP) gateway, specify the virtual router group IP address in the gateway fail-safe pool.
  • In most cases, the Failover action is the optimal gateway fail-safe action. You can use the Reboot and Restart All actions when upstream equipment requires the BIG-IP system to drop the links to clear out their Address Resolution Protocol (ARP) cache or cause the interfaces to reset.

The gateway fail-safe feature uses gateway pools for monitoring the gateways. Therefore, you must assign the gateway pools to the corresponding units to which they are connected, since the pool information is synchronized between the systems. To configure the gateway fail-safe feature, perform the following procedures.

Note: The BIG-IP system monitors only the gateway pool assigned to itself and does not monitor the gateway pool assigned to peer devices. The peer gateway pools have an unchecked status.

Prerequisites

You must meet the following prerequisites to perform this procedure:

  • Have administrative access to the Configuration utility.
  • Have administrative access to the BIG-IP command line for the optional procedure.
  • Have a basic understanding of the use case for the gateway fail-safe feature.
  • To route traffic, the BIG-IP system must be able to reach each gateway that you plan to use for gateway fail-safe.

Procedures

  • Configuring gateway pools for the BIG-IP systems
  • Configuring the gateway fail-safe feature
  • Syncing the configuration
  • Verifying the gateway fail-safe status using the BIG-IP command line (optional)

Configuring gateway pools for the BIG-IP systems

The first step of configuring the gateway fail-safe feature is to create one gateway pool for each BIG-IP system in the device group. Each gateway pool must consist of the upstream gateway that the system uses to route traffic. For example, if bigip1 points to upstream gateway 10.10.1.1, and bigip2 points to upstream gateway 10.20.2.2, then you must configure two gateway pools; gateway_pool1 consists of pool member 10.10.1.1:any and gateway_pool2 consists of pool member 10.20.2.2:any. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility on the first BIG-IP system.
  2. Navigate to Local Traffic > Pools.
  3. Click Create.
  4. Type a name for the pool
  5. Move the gateway_icmp monitor from the Available list to the Active list by selecting the monitor and clicking <<.
  6. In the Address box, type the IP address of the upstream gateway for this BIG-IP system.

    Important: The gateways specified in the pools should contain only the gateway associated with the unit to which they are assigned. For example, the gateway pool for unit 1 should contain only the IP address of the upstream router that unit 1 uses to route traffic. Failure to follow this rule may result in the units changing state from active to standby as the respective units cannot communicate with the partner system's gateway.

  7. In the Service Port box, type an asterisk (*) to represent all services.
  8. Click Add.
  9. Click Finished.
  10. Repeat steps 3 through 9 for the next gateway pool.

Configuring the gateway fail-safe feature

The next step is to configure the newly created gateway pools with the gateway fail-safe feature. For example, the device for which the gateway pool belongs (Device), the minimum number of pool members before triggering the fail-safe action (Threshold), and the fail-safe action (Action). To do so, perform the following procedure:

Impact of procedure: If the BIG-IP systems are unable to reach their respective gateway through Internet Control Message Protocol (ICMP) after enabling the gateway fail-safe feature, the systems will attempt to take the fail-safe action and may result in a failover loop.

  1. Log in to the Configuration utility on the first BIG-IP system.
  2. Navigate to System > High Availability > Fail-safe > Gateway
  3. Click Add.
  4. In the menu next to Gateway Pool, select one of the pools you created in the previous procedure.
  5. In the menu next to Device, select the device that the pool will belong to.
  6. In the Action section, type a number in the field within When fewer than __ pool member(s) are available:

    For example, to configure the gateway pool to failover when there is less than 1 pool member available, type 1.

  7. In the Action section, select the fail-safe action.
  8. Click Finished.
  9. Repeat steps 3 to 8 for the next gateway pool.

Syncing the configuration

When you have completed configuring the gateway fail-safe feature, you must sync the configuration to the device group. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility on the first BIG-IP system.
  2. Navigate to Device Management > Overview.
  3. In the Device Groups section, click to expand the device group you want to synchronize.
  4. In the Devices section, click the device on which you performed the preceding procedures.
  5. Select Push the selected device configuration to the group.
  6. Click Sync.

Verifying the gateway fail-safe status using the BIG-IP command line (optional)

When you have completed configuring the gateway fail-safe feature and synchronizing the configuration to the device group, you can verify the status of gateway fail-safe from the command line. You must use the BIG-IP command line to complete this procedure. To verify the status of gateway fail-safe, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To verify that the gateway fail-safe feature is enabled by viewing the high availability (HA) table, type the following command:

    tmsh show sys ha-status all-properties | egrep '(-----|Status|Feature|Enabled|pool-mbr-down)'

  3. Repeat steps 1 and 2 for all devices in the device group. If the gateway fail-safe feature has been correctly configured on the gateway pools, you should observe entries from the show /sys ha-status all-properties command on the respective BIG-IP systems similar to the following examples:

    bigip1

    -----------------------------------------------------------------------------------------------------------------------
    Sys::HA Status
    Feature Key Action Fail Feature Take Client Proc Timeout
    Enabled Act Data (sec)
    -----------------------------------------------------------------------------------------------------------------------
    pool-mbr-down gateway_pool1 failover no yes no 1 mcpd 0

    bigip2

    -----------------------------------------------------------------------------------------------------------------------
    Sys::HA Status
    Feature Key Action Fail Feature Take Client Proc Timeout
    Enabled Act Data (sec)
    -----------------------------------------------------------------------------------------------------------------------
    pool-mbr-down gateway_pool2 failover no yes no 1 mcpd 0
