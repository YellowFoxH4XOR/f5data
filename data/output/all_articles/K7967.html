K7967: BIG-IP LTM incorrectly marks an ARP entry down in a VLAN group

Known Issue

This is the result of a known issue. Under certain circumstances, BIG-IP LTM will incorrectly mark an Address Resolution Protocol (ARP) entry down in a Virtual Local Area Network (VLAN) group. This issue can occur when the BIG-IP system sends a proxy ARP request to all VLANs in the VLAN group and does not receive a response.

For example, if the BIG-IP system identifies an ARP request on a VLAN in a VLAN group, it sends a proxy ARP request to all other VLANs in the VLAN group. If the device generating the ARP request resides on the same VLAN segment as the device sending the ARP response, the BIG-IP system does not receive a response to its proxy ARP request. When this occurs, the BIG-IP LTM changes the state of the ARP entry to down.

F5 Product Development is tracking this issue as CR85463 and it was fixed in BIG-IP LTM 9.3.1 and 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.3-HF4, issued for BIG-IP 9.4.3. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You can work around this issue by creating a static ARP entry on the BIG-IP system. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Network > ARP > Static List.
  3. Click Create.
  4. Enter the IP address and MAC address for the device with the downed ARP entry.
  5. Click Finished.
