Known Issue

This is the result of a known issue. Some NFS clients may receive an incorrect, incomplete, or failed directory listing for an ARX managed volume. If the client's READDIR request contains a cookie for a directory that has been changed, the ARX system will respond with a STALE_COOKIE error. The client should handle the STALE_COOKIE response by initiating a new READDIR request. However, some clients will halt the current READDIR request at that point and display the results up to that point or return an input/output error.

F5 Product Development tracked this issue as ID 39076 and it was fixedin ARX 5.2.0. For information about upgrading, refer to the ARX Release Notes.

Additionally, this issue has been fixed in ARX hotfix 5.0.6 HF11 (build 11777), and hotfix 5.1.5 HF6 (build 11980). Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID number.

Workaround

You can work around this issue by resending the directory list request.
