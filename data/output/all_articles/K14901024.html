Description

  • When modifying the configuration using the GUI on the BIG-IP, a file system error occurred.    
  • Can't make changes to the BIG-IP and can observe the similer to below message:
istatsd[<PID>]: 015b0000:3: [rollup.cpp:126 getTempFn] could not create temp file /var/tmstat2/cluster/blade0.tm2.xxxxx: Read-only file system
  • when running the "mount" command from a bash CLI, you will see an output similar to the following:
    /dev/mapper/vg--db--sda-set.2._usr on /usr type ext3 (ro,noatime)
    Note: Notice the ro, this denotes Read-Only.  This should read rw for Read-Write.
     
  • Trying to access tmsh on CLI, the similar to below message is displayed:
    exception: (Can't chmod temp dir (/var/system/tmp/tmsh), Read-only file system) (framework/TempDir.cpp, line 112), exiting...

Environment

  • BIG-IP
     

Cause

File system corruption.
 

Recommended Actions

To resolve this issue a filesystem check should be initiated. Console (VE console) access is required.  
IMPORTANT Restarting the BIG-IP system in a standalone configuration will interrupt traffic processing. If the system is configured as part of a high-availability (HA) pair, the device may fail over. F5 recommends that you perform this procedure during a maintenance window.
  1. Log in to Console
     
  2. To create the /forcefsck file, enter the following command:
    touch /forcefsck && reboot
     
  3. If the system then boots to maintenance mode, you need to run:
    fsck -y /dev/mapper/vg--*

If system shows no boot media available, request RMA HW replacement. Provide F5 Support Qkview or Console output.
If the BIG-IP is VE version, check Host system hardware.
