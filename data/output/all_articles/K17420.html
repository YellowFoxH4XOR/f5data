Known Issue

BIG-IP AFM policies may unexpectedly block Internet Control Message Protocol (ICMP) response traffic.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP AFM policy uses a virtual server that is configured with a last rule as an explicit drop for anything not accepted in a previous rule.
  • Either of the following scenarios occur:

    • Traffic that is destined for a virtual server results in ICMP unreachable or ICMP TTL exceeded responses from the server side of the connection.
    • Network diagnostic utilities, which use ICMP error messages (such as the traceroute utility), are used to test a virtual server.

Impact

Network diagnostic tests (such as tests using the traceroute utility) through a BIG-IP AFM device, and normal traffic resulting in certain ICMP responses, will not receive information from routers between the BIG-IP AFM device and the destination IP address.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Network diagnostic utilities (such as the traceroute utility) fail to display information from routers between the BIG-IP AFM device and the destination address.
  • Normal connection traffic times out without indicating the cause of the timeout to the client.
