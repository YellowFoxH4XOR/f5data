K10223: The = operator in pre-logon rules is now an assignment operator

Issue

Prior to FirePass 6.0.1, the equal sign ( = ) and double equal sign ( == ) comparison operators could be used interchangeably in pre-logon rules. Starting in FirePass 6.0.1, the = operator is now an assignment operator; the == operator remains a comparison operator.

If you upgraded from FirePass 6.0.0 or earlier to FirePass 6.0.1 or later, the upgrade process does not modify the = operator in pre-logon rules. After upgrading, you’ll need to check all pre-logon rules and manually change the = operator to == for comparison operations.
 
Important: The one exception is the Windows registry checker inspector. For all versions of FirePass software, you must use the = operator as the comparison operator when configuring the Windows registry checker
 
For example, in FirePass 6.0.0 and earlier, the following rule checks whether the value of the session variable session.browser.is_ie is 1:
 
session.browser.is_ie = 1
 
If the value is 1, the rule is matched; if the value is not 1, the rule does not match.
 
In FirePass 6.0.1 and later, the same rule assigns the value 1 to the session variable session.browser.is_ie. An assignment function is always successful, so the rule is matched regardless of the original value of session.browser.is_ie. To compare whether the value of session.browser.is_ie is 1 in FirePass 6.0.1 and later, use the == operator instead.
 
For example:
 
session.browser.is_ie == 1
