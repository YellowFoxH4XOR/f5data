Description

The issue seems to be isolated to the TLSv1.3 protocol, as TLSv1.2 connections are established and maintained without any problems.

This situation is unique, the Application Data message seen after TLS handshake (line 14 in the example below) is misleading and in fact contains a fatal alert message sent by BIG-IP. Unfortunately it is encrypted with a wrong key (handshake key instead of session key) due to ID997709. (As results for ID997709, client report Fatal Alert "Description: Bad Record MAC". In line 16 below example).

For security reasons, TLSv1.3 does not support TLS re-negotiation.

Environment

  • BIG-IP 15.0.0 and later
  • TLS Traffic
    • TLS (Including TLSv1.3)
  • Client SSL Profile set with Secure Hash Algorithm 256 - SHA256

Cause

The LTM profile configured with the ssl-sign-hash set to sha256.

A fatal alert was triggered on the client side because the SSL handshake failed. In your specific case, this failure was due to an issue with the hash on the client certificate.

If the hash on the client certificate is incorrect or doesn't match the expected value, the server cannot verify the certificate's integrity. This mismatch causes the handshake to fail, resulting in a fatal alert being sent. This alert indicates that the secure connection could not be established due to the verification failure.

 

Recommended Actions

Use TLS 1.3 with client certificate authentication with supported signature algorithms. It can be achieved for example by changing the SSL sing hash option in the SSL profile from SHA256 to "ANY" (with default cipher settings).

To change the SSL signing hash option in the F5 SSL profile from SHA256 to "ANY" using the GUI, follow these steps:

  1. Navigate to: Local Traffic > Profiles > SSL > Client.
  2. Select the SSL profile you want to modify.
  3. Change "Configuration" to Advanced.
  4. In the profile settings, find the "Sign Hash" option.
  5. Change the "Sign Hash" value from SHA256 to ANY.
  6. Save the changes

This will allow the system to use any available hash algorithm during the SSL handshake, which can help with compatibility.

To change the SSL signing hash option in the F5 SSL profile from SHA256 to "ANY" using the CLI, you can use the following tmsh command:

        tmsh modify ltm profile client-ssl <profile_name> sign-hash

Replace <profile_name> with the name of your SSL profile. This command modifies the sign-hash setting to allow any available hash algorithm during the SSL handshake.
