Description

If BIG-IP is booting or rebooting, then config is not loading because this issue in log:
 

LTM1.example.com tmsh[31360]: 01420002:5: AUDIT - pid=31360 user=root folder=/Common module=(tmos)# status=[01070712:3: Values (/Common/socks_customdefault) specified for virtual server profile (/Common/Example_VS /Common/socks_customdefault: foreign key index (profile_FK) do not point at an item that exists in the database.] cmd_data=load sys config

Environment

  • Modified non-default socks profile
  • BIG-IP system reboot

Cause

A change was made to the default socks profile. There is profile_base.conf file where all the default settings are stored.

Adding changes to non-default profile makes it replicated to bigip.conf file and may cause configuration load issue:

ltm profile socks /Common/socks {
   app-service none
   default-connect-handling deny
   dns-resolver /Common/f5-aws-dns <-------- for example this line was added to default profile.
   ipv6 no
   protocol-versions { socks4 socks4a socks5 }
   route-domain /Common/0
   tunnel-name /Common/socks-tunnel
}

Recommended Actions

  • Remove modified default socks profile from bigip.conf file
  • New, custom socks profile should be created, for example "socks_customdefault" 
  • All virtual servers that were configured to use "/Common/socks" should be configured to use newly created non-default profile like /Common/socks_customdefault"

Additional Information

As a best practice, it is highly recommended to never make any changes to default profiles. This may cause numerous failures that will likely never be documented; however to ensure a stable environment, ensure to follow F5 Best Practice recommendations.
