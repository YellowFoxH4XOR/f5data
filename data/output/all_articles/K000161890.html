K000161890: NGINX App Protect: HTTP Status Code 000 for XML/JSON Parser OOM After Module Update

Type
Support Solution
Published
2026-06-25
Updated
2026-06-25
Applies to
  • NGINX Products
  • NGINX App Protect WAF: 5.6.0
Source
https://my.f5.com/manage/s/article/K000161890

Description

NGINX App Protect returns HTTP status code 000 to the client when the XML/JSON parser encounters an out-of-memory (OOM) condition after updating the nginx-plus-module-appprotect and related NAP components. Previously, such requests were passed to the backend and logged in the access log, but now they are dropped and logged with more detailed information. 

Symptoms:

  • Application access errors.
  • NGINX access logs show HTTP status code 000 for affected requests.
  • NGINX error logs contain messages such as:
    • APP_PROTECT aborting request ... reason: xml_json parser oom from: ngx_http_app_protect_module.c:3619
    • Cannot allocate ... more bytes for XML parser. current memory size ...
  • The issue is triggered when the XML/JSON parser exceeds its allocated memory buffer.

Environment

  • Product: NGINX App Protect
  • Platform: Ubuntu 22.04.5 LTS and Ubuntu 24.04.4 LTS
  • NGINX Plus and NAP installed on Ubuntu VMs
  • Key package versions:
    • nginx-plus-module-appprotect:amd64 (36+5.607.1-1~jammy, 36+5.607.1-1~noble)
    • app-protect-plugin:amd64 (6.28.0-1~jammy, 6.28.0-1~noble)
    • app-protect:amd64 (36+5.607.1-1~jammy, 36+5.607.1-1~noble)
  • Recent action: Upgrade of NGINX Plus and NAP modules (from 6.25.0-1~jammy to 6.28.0-1~jammy)

Cause

A change in the default behavior of NGINX App Protect in recent versions: when the XML/JSON parser encounters an OOM condition, the request is now dropped and HTTP status code 000 is returned. Previously, such requests were passed to the backend. This change was made to "fail close" rather than "fail open," providing more information to help address the root issue.

Workaround Example

To mitigate OOM errors and the resulting HTTP status code 000, increase the XML/JSON engine memory allocation as follows:

  1. Edit the NAP service and save the file: 
    # sudo systemctl edit --full nginx-app-protect.service

Answer/Recommended Actions

  1. Increase XML/JSON Engine Memory:
    • Follow the workaround above to allocate more memory for XML/JSON parsing. Monitor logs for OOM errors and adjust memory allocation as needed.
  2. Monitor System Resources:
    • Ensure the system has sufficient memory to accommodate increased allocations.
    • If memory is tight, consider increasing system RAM.
  3. Understand New Behavior:
    • HTTP status code 000 is now expected for OOM errors in recent NAP versions.
    • This code is not part of the HTTP RFC and is specific to NGINX/F5 WAF for NGINX.
  4. Request for Enhancement (RFE):
    • If the new behavior is not desirable, submit an RFE to request a configurable option to revert to the previous behavior or to return an RFC-compliant status code.

Additional Information

  • There is currently no documented option to revert to the previous behavior; an RFE is required to request this feature.
  • The HTTP status code 000 is an NGINX/F5 WAF construct and not a standard HTTP code.
  • The issue is traffic-dependent; memory allocation should be tuned based on observed OOM errors in logs.
  • If the system is running low on memory, increasing system RAM may be necessary.
