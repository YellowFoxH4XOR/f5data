Description

  • New Remote Desktop connections (RDP, Citrix or View/Horizon resources) slow to establish.
  • Existing Remote Desktop connections are intermittently slow, stalling or disconnecting.

Environment

  • BIG-IP APM
  • Remote Desktop
  • Resources using hostnames

Cause
BIG-IP DNS configuration references a slow responding or unreachable DNS server

When a new Remote Desktop session is being established with a hostname configured as the target, the BIG-IP resolves the hostname using the DNS servers configured in  System > Configuration > Device > DNS . If the DNS server is not responding, the BIG-IP will wait until the DNS query times out and then try the next DNS server in the list. Due to the internal architecture, this delay applies to all current VDI sessions (not just the new session which is being established). As a result existing sessions will stall or even disconnect. VDI resources using hostnames rather than FQDN are more affected as the DNS resolver needs to consult the DNS search list. The more search suffixes there are the more misses and the worse the effect.

Recommended Actions

Make sure the BIG-IP DNS configuration only contains working DNS servers.

Additionally you can configure BIG-IP hosts to provide a permanent host to IP address records for the VDI resources.
  1. To view/modify the BIG-IP Host configuration:
  2. Log on to the Configuration utility 
  3. Go to System > Configuration > Device > Hosts
  4. Add host records for VDI resources
