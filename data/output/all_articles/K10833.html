Known Issue

This is the result of a known issue. BIG-IP WebAccelerator does not associate the Audio/Video Media object type with the MIME type (video/x-ms-wmv) and extension (.wmv) for Windows Media Video (WMV) files. When using the default BIG-IP WebAccelerator configuration, these objects will match the Unclassified node, which is typically set to Always proxy in the Proxying tab. Beginning in Hotfix-BIG-IP-9.4.5-HF2, this issue results in the system adding a no-cache directive to the Cache-Control header. When Internet Explorer is used to load the file and Windows Media Player is used to display the file, a dialog box with  the following message may appear in the browser:

Windows Media Player encountered a problem while playing the file.  For additional assistance, click Web Help.

F5 Networks Product Development is tracking this issue as ID 223451 (formerly CR129834).

Workaround

You can add the appropriate extension and MIME type to the Audio/Video Media object type by performing one of the following procedures:

Version 10.x

1. Log in to the BIG-IP WebAccelerator Configuration utility.

2. Navigate to Configuration >> Policies >> Object Types.

3. Select the Audio/Video Media predefined object type.

4. Add wmv to the Extensions list.

5. Add audio/x-ms-wmv to the MIME-types list. 

6. To save the modified configuration, click Save.

Version 9.4.x

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Change directories to the /config/wa directory by typing the following command:

    cd /config/wa
  3. Back up the original globalfragment.xml file by typing the following command:

    cp globalfragment.xml globalfragment.xml.sol0833
  4. Open the globalfragment.xml file in a text editor.
  5. Locate the media objType entry. 
  6. Edit the ext= section of the media objType object, adding wmv to the list of extensions.
  7. Edit the mimeType section of the media objType object, adding audio/x-ms-wmv to the list of mimeTypes.
  8. Save the globalfragment.xml file.
  9. Restart the pvac daemon by typing the following command:

    Important: Restarting the pvac daemon will briefly disrupt connections, and invalidate objects in the BIG-IP LTM RAM Cache. Restarting the pvac daemon should be scheduled accordingly.  

    bigstart restart pvac
