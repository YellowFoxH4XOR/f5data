K000092914: How to determine which sys db variables are part of the Config Sync and/or synced between blade(s) in the cluster

Type
Support Solution
Published
2022-12-22
Updated
2025-02-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.7
Source
https://my.f5.com/manage/s/article/K000092914

Description

This article covers the following conditions:

  • Some modified sys db variables are not config synced between members of the HA group.
  • Some modified sys db variables are not synced between blade(s) in the same cluster.

Environment

  • HA group configured with config sync enabled.
  • One or more blades configured in a cluster.
  • One or more of the sys db variables configured/modified.

Cause

Depending on the 'realm' of the sys db variable, it may, or may not be part of the config sync to other members of the HA group and/or synced to other blade(s) in the cluster.

Recommended Actions

Review the 'realm' of the sys db variable in the /config/BigDB.dat file to determine if the db variable with be config synced to other members of the HA group and/or synced to other blade(s) in the cluster.

Additional Information

The exact number of sys db variables, and their associated realm will vary between code versions.

 

 Realm Synced to HA Group Synced to other blade(s) in cluster
 local No Yes
 common Yes Yes
 private_internal No No
 internal No Yes
 private_local No No

 

Sample from the /config/BigDB.dat file, showing the 'realm' of 'local':

[HostName]
default=bigip1
type=string
realm=local
scf_config=false
display_name=HostName

 

Based on the above example, with the realm being 'local', this sys db variable would NOT be part of the config sync, but it would be synced between blade(s) in the same cluster.
