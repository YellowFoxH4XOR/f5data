Injection attacks

Injection attacks are one of the most dangerous attacks where an attacker simply sends malicious data to make the application process it and do something it is not supposed to do. Injection vulnerabilities are prevalent, especially in legacy code that does not validate or sanitize user-supplied input.

Common application technologies that may be victims of an injection attack are the following:

  • SQL
  • NoSQL
  • Lightweight Directory Access Protocol (LDAP)
  • XPath
  • Operating system commands
  • XML parsers
  • SMTP headers

Attackers typically exploit injection flaws by injecting an operating system command, SQL query, or even a full script into a parameter, header, URL, other form of data that an application receives.

SQL injection is a very common method of injection attack. To perform SQL injection, an attacker modifies part of a query string sent to a SQL database to perform a malicious action, such as listing all usernames and passwords. For an example of a SQL injection attack, refer to SQL Injection.

Injection attack scenario

In the following attack scenario, the attacker modifies a parameter value in their browser to send a crafted SQL statement to the vulnerable application:

  1. An attacker injects a command, query, or code into a vulnerable element of the application. For example,

    https://example.com/account?id='1'='1

  2. The web application server executes the injection.
  3. The attacker gains unauthorized access, causes a denial of service, steals sensitive data, or causes a similarly nefarious outcome. In the case of the previous example, the attacker may be able to obtain every data field from all users rather than from one specific user.

Secure your applications against injection attacks with F5 products

To protect your application, best practices recommend that you configure F5 products to inspect and validate all user-supplied input to your applications against known attack signatures, evasion techniques, and other known attributes/parameters.
