K000141375: Access Policies constantly returning to non-applied (yellow) state.

Type
Support Solution
Published
2024-10-10
Updated
2024-10-11
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.0, 16.1.3, 17.1.X, 17.1.1, 16.1.4, 15.1.10
Source
https://my.f5.com/manage/s/article/K000141375

Description

Customer after making some changes and clicking on the "Apply Access Policy", this yellow flag requesting to re-apply reappear after a while.

Figure: visual representation of the issue

 

You may see  messages in /var/log/restjavad similar to:

Provider /<partition>/<OAuth_Provider> task ID xxxxxxxx-7fc7-4af7-9580-155d50a8ff49 start run after interval 60 minutes

Task ID <task-ID> for provider /<partition>/<OAuth_Provider> has completed one round, we will schedule the next discover after 60 minutes

However you can not see

Applying access policies [/<partition>/<access_policy_name>] after doing discover for /<partition>/<Oauth_provider_name>

However after the set interval (in this case 60 minutes) nothing happens, which may go on for a couple of hours with no apply access policy then apply access policy is again seen at a random time.

Environment

  • BIG-IP APM
  • Apply Access Policy prompt 
  • Auto oAuth-discovery
  • Partition other than /Common

Cause

  • Bug ID 1473701

Recommended Actions

There are 3 possible ways to fix this:

  • This has been fixed in Big-ip 16.1.5
  • Open an F5 Support case requesting an EHF on top of the version you're running.

  • Using Crontab, schedule a task to restart restjavad, and then save access policy in the non-default profile. 

    tmsh restart sys service restjavad && tmsh modify apm profile access /<partition_name>/<access_profile_name> generation-action increment
