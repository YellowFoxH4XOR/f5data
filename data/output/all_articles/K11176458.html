Description

  • root ('/') directory is full
  • Error message:
    011d0004:3: Disk partition / (slot #) has only 0% free space
  • Running the following command shows no disk space left for root ('/') directory: 
    df -h
Filesystem                             Size  Used Avail Use% Mounted on
/dev/mapper/vg--db--sda-set.1.root     427M  427M     0 100% /            <<--
none                                    32G  2.4M   32G   1% /dev/shm
<snip>
prompt                                 4.0M   28K  4.0M   1% /var/prompt
none                                    32G     0   32G   0% /var/loipc

Environment

  • BIG-IP
  • Disk partition / is full

Cause

  • A user copied files into the root ('/') partition and caused it to fill up to 100%
Important: Avoid storing files in directories that reside on the root file system. The BIG-IP system has a relatively small root file system and separate partitions for file systems, such as /config, /usr, and /shared. Directories, such as /home reside on the root file system and should not be used for file storage.

Recommended Actions

  1. Check the contents of the following directories:
    ls -lstrh /home/root/ 
    ls -lstrh /home/admin/
    ls -lstrh /root/
    ls -lstrh /etc/
    ls -lstrh /
  2. Use rm command to remove unwanted files from the relevant directory to free disk space.
  3. See Additional Information if the unwanted files still can not be found.
Note: F5 recommends storing temporary files in /var/tmp directory

Additional Information
 
The following commands can assist with further troubleshooting:

  • To locate the 20 largest files (measured in KB) on the system:
    find / -xdev -type f -exec du {} \; | sort -rn | head -20
  • Helpful to narrow down where all the space is gone:
    du -xh / --max-depth=1
  • Find directories with most number of files:
    find / -xdev -type d -exec sh -c 'echo "$(find "$0" | grep "^$0/[^/]*$" | wc -l) $0"' {} \; | sort -rn | head -10
