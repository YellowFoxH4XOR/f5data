K000132504: High CPU on KVM Host When a BIG-IP VE Guest Is Deployed

Type
Support Solution
Published
2023-02-13
Updated
2023-04-05
Source
https://my.f5.com/manage/s/article/K000132504

Description

On KVM hypervisor, when a BIG-IP VE is deployed, even from the perspective of BIG-IP VE, CPU utilization is low, KVM host may show high CPU utilization on the CPU cores on which BIG-IP VE runs.

 

Environment

  • BIG-IP VE
  • KVM

Cause

This is by design.

TMM process as well as some other processes may keep checking for activity in a frequent and regular manner even there is no traffic. QEMU itself will occupy CPU cycles for a specified period of time once BIG-IP VE has activity.

 

 Recommended Actions

Consider to reduce default configured value for halt_poll_ns at KVM host, in some linux distributions default value is 400000ns, so you could start by altering the halt_poll_ns value to 200000ns and monitor KVM host CPU usage :

  # echo 200000 > /sys/module/kvm/parameters/halt_poll_ns

If CPU load remains high after initial value reduction, you could test smaller values to find a workable setting. Also you can opt by disabling halt_poll_ns feature as follows :

  # echo 0 > /sys/module/kvm/parameters/halt_poll_ns

Note that above are global changes. Also after set the value halt_poll_ns to 0 the CPU host load will be reduced in exchange of less performance and responsiveness of the VM (latency benefits received by halt_poll_ns).

"Care should be taken when setting the halt_poll_ns module parameter as a large value has the potential to drive the cpu usage to 100% on a machine which would be almost entirely idle otherwise. This is because even if a guest has wakeups during which very little work is done and which are quite far apart, if the period is shorter than the global max polling interval (halt_poll_ns) then the host will always poll for the entire block time and thus cpu utilisation will go to 100%."
