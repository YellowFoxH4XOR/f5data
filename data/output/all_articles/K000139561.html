Cause

Bug ID 901989
"This occurs when the script /etc/sysconfig/sysinit/01bootlogmarker.sysinit runs on startup."

Recommended Actions

Because /etc/sysconfig/sysinit/01bootlogmarker.sysinit is a readonly file, you will need to use (vi editor) and save it (in vi) with the "w!" command.

This is a possible work around to resolve this issue.

Important:  If the system is using FIPS, do not use this workaround! Modifying this file will cause FIPS validation to fail the next time it runs, and the system will halt on the next boot. In addition, this workaround will not persist on software upgrades.

1. Backup the file:

cp /etc/sysconfig/sysinit/01bootlogmarker.sysinit /var/tmp/01bootlogmarker.sysinit.bak

2. Add "btmp" to the excludeFiles list:

Change the following script in (vi editor) from

#!/bin/sh
 
dateCmd="/bin/date"
MarkerCmd="/usr/libexec/install/boot_marker"
bootMarker=""
 
# List of files in /var/log to ignore
excludeFiles=( "lastlog" "wtmp" "tmm*tech.out" "*.json" )


to

#!/bin/sh
 
dateCmd="/bin/date"
MarkerCmd="/usr/libexec/install/boot_marker"
bootMarker=""
 
# List of files in /var/log to ignore
excludeFiles=( "lastlog" "wtmp" "btmp" "tmm*tech.out" "*.json" )

Because /etc/sysconfig/sysinit/01bootlogmarker.sysinit is a read-only file, you will need to use (vi editor) and save it (in vi) with the "w!" command. 

3. Truncate the "/var/log/btmp" file

truncate --size 0 /var/log/btmp

4. Reboot.

After the reboot no boot_marker line is written to "/var/log/btmp"
