K000152593: Repeated UCS backup restoration fails to load ASM configuration

Type
Support Solution
Published
2025-08-10
Updated
2025-08-10
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000152593

Description

Repeated UCS restores on BIG-IP LTM systems with ASM provisioned, using the options no-license and no-platform-check (or platform-migrate), result in failure on the second and subsequent attempts. Similar error occurs during the ASM configuration load phase:

Warnings were generated:
Compliance '/Common/gtp_unknown_tunnel_id' is deprecated and removed from '/Common/protocol_inspection'.
Compliance '/Common/smtp_command_length_overflow' is deprecated and removed from '/Common/protocol_inspection'.

Loading ASM configuration...
Can't use an undefined value as an ARRAY reference at /usr/local/share/perl5/F5/PrepareConf/BotDefense.pm line 266.
ERROR: Failed during loading ASM configuration.

WARNING: There were one or more errors detected during installation.
Check the error messages and take the proper actions if needed.
ERROR: UCS installation failed.
Operation aborted.
Unexpected Error: UCS loading process failed.

Environment

  • BIG-IP LTM 
  • BIG-IP ASM 
  • Generating UCS on rSeries tenant and trying to restore the UCS on iSeries platform using tmsh load sys ucs <filename>.ucs no-license no-platform-check or platform-migrate.

Cause

Unknown.

Recommended Actions

You can restore backup without using no-license and no-platform-check option.

  • Restore backup through GUI (by default GUI does not use no-license, no-platform-check and platform-migrate option).
  • Restore backup though CLI using below syntax:
    tmsh load sys ucs <filename>.ucs
