Topic

Purpose

You should consider using this procedure under the following condition:

  • File storage device that hosts the ARX metadata is no longer available

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The file storage device that user data is stored on is available to the ARX
  • You have enough free storage available for the the new ARX Metadata

Description

If the file storage device that hosts the metadata for a managed volume on the ARX system goes offline, the entire managed volume becomes inaccessible. This is expected behavior. The affected managed volume will recover after the file storage device that hosts its metadata recovers.

However, if it is impossible or undesirable for the file storage device which was hosting the metadata to recover, you must select and define an appropriate new file storage device to host the metadata.

Procedures

You can redefine the metadata location for the managed volume, and bring the volume back online by performing the following procedures:

  • Destaging the volume whose metadata is offline
  • Undefining the defunct metadata share
  • Defining the new metadata share, and bringing the volume online

Destaging a volume whose metadata is offline

To force the volume to no longer require the metadata  you must destage the volume, perform the following procedure:

Impact of procedure: none

  1. Log in to the ARX CLI.
  2. Destaging the volume metadata requires entering priv-exec mode.

    Enter privileged mode by typing the following command:

    enable

    You are now in priv-exec mode.
  3. Destage the volume metadata using the following command syntax:

    nsck <namespace> destage volume <volume> force

    Replace <namespace> with the name of the namespace that contains the relevant volume, and replace <volume> with the name of the volume to be destaged. For example:

    nsck ns1 destage volume /vol1 force

  4. If a confirmation prompt regarding destaging the volume appears, confirm the warning by typing the following:

    yes
  5. The command output will end with a line similar to the following example:

    Scheduling report: destage.3.rpt on switch SupARX1k1a
  6. Note the name of the report in the nsck <namespace> destage volume <volume> force command output for reference in subsequent steps.
  7. Monitor the status of the nsck job by using the following command syntax:

    tail reports <report> follow

    Replace <report> with the name of the report noted earlier in this procedure. For example:

    tail reports destage.3.rpt follow

    The command output will appear similar to the following example:

    **** Destage Report: Started at Mon Sep 24 23:25:10 2008 **** **** Software Version: 2.07.001.10312 (Apr 9 2008 01:11:31) [nbuilds] **** Hardware Platform: ARX-1000+ **** Namespace: ns1 **** Volume: /v1 Share Physical Filer State -------------------- ------------------------------------------- ------------- [s1 ] 10.0.0.1:/ask-s1 Disabled [s2 ] 10.0.0.2:/ask-s2 Disabled **** **** WARNING: Mount failed on metadata share **** **** Total processed: 0 **** Elapsed time: 00:06:36 **** Destage Report: DONE at Mon Sep 24 23:31:52 2008 ****

    Important: It may take up to 10 minutes or longer for the nsck destage command to complete, because timeouts will occur while the ARX system attempts to mount the metadata to formally destage it. During this time, the report output may appear to hang, but it will eventually finish.

  8. When the report indicates that the destage has completed, press control C to return to the ARX CLI.

Undefining the defunct metadata share

After you have destaged the managed volume, you may now undefine its old metadata share using the following procedure:

Impact of procedure: none

  1. Log in to the ARX CLI.
  2. Enter privileged mode by typing the following command:

    enable
  3. Destage the volume metadata using the following command syntax:

    nsck <namespace> destage volume <volume>

    For example:

    nsck ns1 destage volume /vol1
  4. Enter global configuration mode by typing the following command:

    global
  5. Enter namespace configuration mode using the following command syntax:

    namespace <namespace>

    For example:

    namespace ns1
  6. Enter volume configuration mode using the following command syntax:

    volume <volume>

    For example:

    volume /vol1
  7. Remove the metadata share, using the following command syntax:

    no metadata share filer {nfs3 | nfs3tcp | cifs} path [cluster cl-name]

    For example:

    no metadata share nas3 cifs acp_meta

Defining the new metadata share, and bringing the volume online

Once the defunct metadata share configuration has been removed, you may define a new filer and share that the ARX metadata will be stored in and enable the shares to bring services back online.

Impact of procedure: none

  1. Enter the volume configuration mode identified in step 6 of the Undefining the defunct metadata share procedure
  2. Define the new metadata share, using the metadata share command:

    metadata share filer {nfs3 | nfs3tcp | cifs} path
    For example:

    metadata share nas1 nfs3 /vol/vol1/meta1
  3. Bring the volume online by enabling the modified share, by typing the following command:

    enable shares

  4. Exit the volume configuration mode and return to privileged mode by typing the following command:

    end
