Unrestricted access to sensitive business flows

This kind of vulnerability occurs when an API exposes a business flow without regard to whether excessive access to the flow may harm the business.

Attackers may exploit this vulnerability by gaining insight into the business model, finding APIs that expose sensitive business flows and using automated tools to misuse the APIs and harm the business. The unrestricted access to sensitive business flows attacks can result in the following impacts:

  • Financial loss: The application may not restrict paid-per-request API calls, such as SMS or biometrics validation, leading to significant financial losses.
  • Impact to legitimate users: Attacks may prevent legitimate users from tasks such as completing a transaction, purchasing a product, or making a reservation.
  • Service disruption: By overloading the API with a high volume of automated requests, attackers can cause denial-of-service (DoS).

Unrestricted access to sensitive business flows attack scenario

In the following scenario, the attacker buys all the stock of a high-demand product and resells it at a higher price:

  1. An attacker uses code to automatically buy the next-generation release of a popular new shoe.
  2. Since the API doesn't implement the appropriate protection, the attacker uses a bot to run the code and buy up the entire stock before other legitimate users. The attacker later resells the shoes at a profit.

Secure your APIs against unrestricted access to sensitive business flows attacks with F5 products

Best practices recommend that you identify critical business flows and implement request validation mechanisms to protect them attackers using them excessively.

Use BIG-IP APM to reduce unrestricted access to mitigate sensitive business flows attacks

The BIG-IP APM systems provide the controls in the following table to protect your API against unrestricted access to sensitive business flows attacks.

Table 6.1 BIG-IP APM controls that protect against unrestricted access to sensitive business flows attacks
BIG-IP APM protectionRecommendationsResource
Per-request policy designUse a combination of the following in Per-request policies, based on your application logic, to design and implement the request validation mechanism you want:
  • Per-request policy branches: Use to identify the specific API endpoints that are critical.
  • Subroutine gating criteria: Use to decide when to execute a specific sub routine.
  • Subroutine session life and timeouts: Use to configure the timeouts and maximum session life settings of a subroutine so that requests do not have unrestricted access.
  • Subsession and perflow variables: Use to provide granular information on users' session which you can use to decide if a request is legitimate.
  • HTTP connectors: Use if required to get more data or information from application server, for instance, to populate session variables for granular decision making.
