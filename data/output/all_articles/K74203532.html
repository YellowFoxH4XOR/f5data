Known Issue

The BIG-IP system may accumulate generate_config zombie processes when you save the BIG-IP configuration using iControl representational state transfer (REST) or the TMOS Shell (tmsh) multiple times.

This issue occurs when all of the following conditions are met:

  • You save the BIG-IP system configuration using either of the following methods:
    • tmsh utility

      For example, you use save /sys config.

    • iControl REST API calls

      For example, you use the http://localhost/mgmt/tm/sys/config URL, and post with the data "command":"save".

  • You perform multiple save configuration operations.
The command to save the BIG-IP configuration will create the generate_config process, and the system will create one generate_config process per save operation.

Impact

When you save the configuration often, the system creates extraneous processes, which will slowly fill up the process table. This behavior may disrupt or cause a slow response to the services provided by the affected BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When reviewing the processes on the affected BIG-IP system (using the ps command), you may observe that the system processes in a zombie state are marked with the label <defunct> next to the process name:

    # ps aux| grep generate_config.*defunct
    root     13551  0.0  0.0      0     0 ?        Z    13:28   0:00 [generate_config] <defunct>

  • When locating the parent process that has a child process named generate_config that results in a zombie state, you may observe command output that appears similar to the following example:

    # ps --forest | grep -B1 generate_config.*defunct
    17650 ?        Sl     0:05  |       \_ icrd_child -p 8100 -l 2 -i 69b81894-6d1e-4587-917b-213cea279303
      318 ?        Z      0:00  |           \_ [generate_config] <defunct>

    The sample output displays the icrd_child process as the parent process that created the generate_config process, resulting in a zombie state.

Workaround

There is no workaround for this issue. However, you can recover from this issue by locating the parent process that has resulting zombie processes, and restarting the parent process to purge the zombie processes. The parent processes that are known to cause this issue include icrd_child and scriptd. To locate and restart the parent process, perform the following procedure:

Impact of workaround: Restarting any daemon on the BIG-IP system may cause a service disruption. F5 recommends performing this procedure only during a scheduled maintenance period. For more information about the daemon's functions, refer to K05645522: BIG-IP daemons (13.x).

  1. If you are currently logged in to the tmsh utility that is performing the configuration saving operation, exit from the utility first.
  2. Log in to the BIG-IP Advanced Shell (bash) using an account with administrator credentials.
  3. Locate the zombie process and its parent process by typing the following command:

    ps --forest | grep -B1 generate_config.*defunct

  4. Using the parent process name you located in step 3, you can restart the target daemon by typing one of the following commands that apply:
    • icrd_child process

      tmsh restart /sys service restjavad

    • scriptd process

      tmsh restart /sys service scriptd
