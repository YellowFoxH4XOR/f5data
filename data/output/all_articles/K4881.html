K4881: FirePass disables caching for a page that requires caching

Topic



When proxying HTTP content, FirePass automatically sets a Cache-Control: no-cache header, which prevents clients from caching content provided through the VPN.

The Cache-Control: no-cache header can cause problems for some XML applications, as the client will not retrieve XSL files that are not cacheable. When this occurs, the browser displays an error indicating that the XSL file is not cacheable or is not available.

You can work around this issue by configuring FirePass so that it does not insert the cache control headers into files that end with an .xsl extension. To do this, perform the following steps:

  1. Log in to the Administration Console.

  2. In the main navigation pane, click Portal Access.

  3. In the upper navigation pane, click Web Applications.

  4. From the menu, click Caching and Compression.

  5. Locate the Web Applications Global Settings section.

  6. In the Enter the comma-separated list of URL patterns... field, enter the following URL pattern:

    http://*.xsl

FirePass will no longer insert cache control headers into files that end with an .xsl extension.
