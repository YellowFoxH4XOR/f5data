Description

Virtual servers with a DNS profile will not process "Server Status Request" (opcode 2) DNS messages, and those messages are handled according to the DNS profile's "Unhandled Query Action".  This can result in symptoms such as:
  • A traffic loop of DNS messages between the BIG-IP and upstream router
  • "Inet port exhaustion" errors with the virtual server as the target IP and port (the target IP and port are the pool member, typically not addresses on the BIG-IP), similar to the following: 
    01010201:2: Inet port exhaustion on client-ip to virtual-server:53 (proto 17)
  • Unexpectedly large QPS (queries per second) / high CPU utilization for DNS virtual server

Environment

Virtual server with:
  • DNS profile with "Unhandled Query Action" set to "allow" (the default)
  • No pool for traffic
  • "Translate Address" set to disabled (the default when listener is created via DNS >> Listeners menu)

Cause

The DNS profile does not process "Server Status Request" DNS messages, so these messages are handled according to the "Unhandled Query Action" option in the DNS profile.  When this is set to "allow", the BIG-IP will attempt to load-balance these messages.

A virtual server with "translate address" disabled and no pool will attempt to forward traffic to the IP address and port of the virtual server.  If the BIG-IP has a route that matches this traffic, it will forward the traffic according to that route. The upstream router may then forward that traffic back to the BIG-IP, where it will be processed by the virtual server.

Recommended Actions

The "Server Status Request" DNS messages do not appear to serve any purpose, so the simplest way to address this behavior is to change the "Unhandled Query Action" to "drop" or "reject".  Alternately, configure a pool of back-end DNS servers for the virtual server, and enable "Translate Address" on the virtual server.
