Description

This article describes core files generated by the VELOS host system that may be found on the system controller, partition, or blade and for rSeries appliance. For more information on core files generated by the BIG-IP tenant on the F5OS systems, refer to K10062: Overview of managing BIG-IP core files.

The F5OS system can generate core files for a variety of reasons. Depending on this and the process that generated the core file, the name and location of the file may vary.

Core file naming

F5OS core files are named as follows:

core.<app>.<pid>.<timestamp>.core.gz.

For more information, refer to ID 1103105. 

Core file locations

Depending on the actual process that terminated, you may find core files in the following locations on F5OS:

SystemF5OS filesystem directory
VELOS
System Controller/var/shared/core/[host|container]
Partition/var/F5/partition{#}/shared/core/container
Blade/var/F5/partition{#}/shared/blade{#}/core/[host|container]
rSeries
appliance/var/shared/core/[host|container]
Core file retention

F5OS retains 2 core files for every process. When the same process generates a third or subsequent core file, the system retains the first core file while the second core file is overwritten. When a different process cores, the system does not overwrite core files generated from other processes.

Environment

  • F5OS-C VELOS system controller or partition or blade
  • F5OS-A rSeries appliance

Cause

Due to different reasons such as code defects in the target process or the result of a watchdog or failsafe process terminating the target process, F5OS may deliver a signal to a process, terminating it, and resulting in a core file.

Recommended Actions

Use the following information to manage the core files on your F5OS system:

  • Listing, deleting core files
  • Managing new core files for submission to F5 Support
  • Core files in QKviews
Listing, deleting core files

To list and delete core files on your F5OS system, you can login to the VELOS system controller/partition or rSeries appliance CLI and use the confd utilities as follows:

  • List: Enter the following command:
    system diagnostics core-files list
  • Delete: Use the following command syntax:
    system diagnostics core-files delete files [ <filename> ]
Managing new core files for submission to F5 Support

When a new core file is generated, and a core file analysis is required, best practices recommend the following:

  • Immediately following a core dump, you generate an MD5 checksum for each core file, then move all core files with their corresponding checksum files out of their original location to another directory, such as the /var/tmp/ directory. This step ensures that the core files are not overwritten by new core files from a subsequent event. You may delete the core and checksum files once F5 Technical Support determines that they are superfluous, or when analysis of the issue is completed.

  • When you copy, move, export large files, (e.g. core files), verify the integrity of the file using md5sum. To create an MD5 checksum file for the core file, use the following syntax:
    md5sum <name-of-core-file> > <name-of-core-file>.md5

    To verify the integrity of the file after a transfer in its new location, use the following command syntax:
    md5sum -c <name-of-core-file>.md5

  • Exporting and copying core files for submission
    Configuration utility

Use the file utilities feature on F5OS to download or export core files from the system. To do so, perform the following procedure:

    1. Login to the Configuration utility of your F5OS system.
    2. Go to SYSTEM SETTINGS > File Utilities.
    3. For Base Directory, go to where your core files are located. (e.g. diags/shared)
    4. Select the core file
    5. Select Download or Export as appropriate.

Command line

For all F5OS core files, you can login to the shell, and use a file transfer utility such as scp, WinSCP or similar to export or copy the files. 

Note: On VELOS, data, such as core files, QKView files, or similar diagnostic information, and system logs are not replicated between the controllers. So you will need to login to the correct system controller or blade that contains the core file. For more information, on accessing the right system controller or blade refer to K65442484: Overview of access to the F5 VELOS system.

For all F5OS core files, with the exception of core files on VELOS blades, in addition to a file transfer utility, you can also use the confd utility to export the file as follows:

    1. Login to the confD CLI of the system controller or partition or rSeries as appropriate. For more information on how to do so, refer to K65442484: Overview of access to the F5 VELOS system..
    2. To verify the path to the core files, use the following commands:
      Note: Use the output of the system diagnostics core-files list command to display the core files.

      file list path diags/core/[host/container]/<filename>
      file list path diags/shared/core/[host/container]/<filename>

    3. To export a core file, use the following syntax:
      file export local-file <path/core-file> remote-host <host_address> remote-file <path/to/remote_file> [username <user>] [insecure]

      Note: Use the insecure option if you want to skip certificate warnings when exporting files to the remote HTTPS server.

      For example, to export the core.host.confd_cmd.482.1234567890.core.gz file to the /tmp directory of the remote host at 192.168.10.100 using the insecure option as root, enter the following command:

      file export local-file diags/shared/core/host/core.host.confd_cmd.482.1234567890.core.gz remote-host 192.168.10.100 remote-file /tmp/core.host.confd_cmd.482.1234567890.core.gz insecure username root protocol scp

    4. To check the status of the file transfer, enter the following command:
      file transfer-status
  • Submitting diagnostic data and core files to F5 Technical Support
    To submit core files and the diagnostic data described in the previous point to F5 Technical Support, refer to the steps detailed in K000090853: Exchange files with F5 Support using MyF5.

  • Core files alone without accompanying logs do not provide the complete information for troubleshooting. Before you submit core files to F5, you must gather diagnostic information from the F5OS device and then open a case with F5 Technical Support. For information about gathering the diagnostic data and submitting a support case to F5, refer to K2633: Instructions for submitting a support case to F5.

Core files in QKviews

By default, core files that are smaller than 25 MB are included in a QKview. You can include or exclude or set the maximum core size value when generating a QKview as follows:

  1. Login to the confd CLI of the system with admin access.
  2. Use the following command syntax:
    system diagnostics qkview capture exclude-cores { false | true } filename maxcoresize maxfilesize timeout

Additional Information

When troubleshooting core events, apart from collecting and analyzing the core file, you should view the velos.log (VELOS), platform.log (rSeries) files for more information. For example, enter the following commands to display the date, time, location, and more, of the core event:

  • VELOS System controller
    # grep core /var/log_controller/velos.log
    2020-10-06T01:19:26.149395+00:00 controller-1 Core-helper.Controller: priority="Err" msgid="0x6501000000000001" msg="Core dumped on Controller" process="authd" location="/var/shared/core/container/authd-1.core.gz"
    [...]

  • VELOS Partition
    # grep core /var/F5/partition#/log/velos.log
    2020-10-06T01:29:37+00:00 10.1.17.1 blade-1(p1) Core-helper.Blade: priority="Err" msgid="0x6501000000000001" msg="Core dumped on Blade" process="authd" location="/var/F5/partition1/shared/blade1/core/container/authd-1.core.gz"
    [...]

  • rSeries
    # grep core /var/F5/system/log/platform.log 
    2023-09-07T10:55:29.482516+08:00 appliance-1 Core-helper.Appliance: priority="Err" msgid="0x6501000000000001" msg="Core dumped on Appliance" process="network_manager" location="/var/shared/core/container/network_manager"
