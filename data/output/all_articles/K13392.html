Topic

You should consider using this procedure under the following condition:

  • You want to configure your BIG-IP system to send traffic to an intrusion detection system (IDS).

Description

An IDS device monitors inbound and outbound network traffic and identifies suspicious patterns that may indicate malicious activities or a network attack. The BIG-IP system supports the Clone Pool and Interface Mirroring features, which can be used for copying traffic to a dedicated IDS or a sniffer device. The features are described below:

Clone pools

The Clone Pool feature is more versatile than the Interface Mirroring feature and is the recommended method for copying production traffic to IDS systems or sniffer devices.

Clone pools are designed to copy traffic to IDSs. A clone pool is a property of a virtual server, and it receives all of the same traffic as the load-balancing pool. Only new connections are copied by a clone pool; existing connections are not copied when a clone pool is added to a virtual server.

Clone pool traffic is sent from the BIG-IP system to the IDS system (clone pool member) using the IDS system's L2 MAC address. Other packet header information contained in the clone pool traffic, such as the L3 addressing, remains the same as in the original packet sent to the virtual server pool member.

Note: Clone pool members require Layer 2 (L2) forwarding database entries for certain BIG-IP platforms. For more information, refer to K17567: Clone pool members require L2 FDB entries.

Clone pools contain the following characteristics:

  • Clone pool traffic is processed by the Traffic Management Microkernel (TMM).
  • Clone pools can be configured to copy client-side traffic, server-side traffic, or both. A client-side clone pool causes the virtual server to replicate client-side traffic (prior to address translation) to the clone pool member. A server-side clone pool causes the virtual server to replicate server-side traffic (after address translation) to the clone pool member.
  • An unlimited number of clone pools can be configured on the BIG-IP system.
  • Clone pools are not compatible with asymmetric routing.

Interface mirroring

The Interface Mirroring feature allows you to copy traffic from any port, or set of ports, to a separate port where a sniffing device is attached. Interface mirroring is useful for sending traffic at wire speed to a dedicated device for troubleshooting purposes.

Interface mirroring considerations

Interface mirroring overview

  • Interface mirroring always copies both client-side and server-side traffic.
  • Mirroring traffic is processed at the switch layer and not by the Packet Velocity ASIC (PVA) or TMM.

Port configuration and limitations

  • Mirror-to port:
    • The mirror-to port is a dedicated port.
    • It cannot be associated with any Virtual Local Area Network (VLAN) or trunk.
    • Can copy traffic from several ports.
  • Mirror-from port:
    • Mirror-from ports can be only physical ports, not VLANs or trunks.
    • Mirror-from ports can be a member of several VLANs or a trunk.
  • Only one interface mirror instance can be configured on the BIG-IP system.

Bandwidth and performance considerations

  • Wire-speed mirroring: Achieving wire-speed mirroring requires:
    • The aggregate speed of the mirror-from ports matches that of the mirror-to port.
    • The overall bandwidth demand does not exceed the capacity of the switch.
  • Potential issues:
    • Over-subscribing the mirror-to port or failing to configure identical capability ports can lead to degradation of data flow, resulting in delayed or dropped traffic.
  • Impact on switch resources:
    • Mirroring effectively doubles the bandwidth usage of the mirrored interface on shared switch resources.
    • Excess demand may affect throughput on all ports within the system.
    • Recommendation: F5 advises using interface mirroring cautiously due to the potential impact described previously.

Compatibility

  • Interface mirroring is compatible with asymmetric routing.
  • Platform support: Interface mirroring is not supported on the following platforms:
    • BIG-IP 2000s
    • BIG-IP 2200s
    • BIG-IP 4000s
    • BIG-IP 4200v
    • i2000 series
    • i4000 series
    • F5 rSeries
    • F5 VELOS
    • BIG-IP Virtual Edition (BIG-IP VE)

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have administrative access to the Configuration utility or the TMOS Shell (tmsh).
  • You must have an IDS device configured on the network.

Procedures

To configure the BIG-IP system to send traffic to an IDS, perform either of the following procedures:

  • Configure clone pools
    To watch a video demo of the clone pool procedures, go to  K000152697: Configure BIG-IP clone pools to send traffic to an intrusion detections system (IDS).
  • Configure interface mirroring

Configure clone pools

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: When using clone pools with Forwarding or Performance Layer 4 (L4) type virtual servers, the client-side clone pool must be configured in a separate VLAN from the virtual server if the Preserve Strict source port setting is enabled for the virtual server, or if address or port translation is disabled for the virtual server. Failure to do so will result in connections being reset with a Port in use message.

To configure a clone pool, perform the following tasks:

  • Creating a pool with the IDS device as the member IP address
  • Modifying a virtual server to reference the clone pool

Create a pool with the IDS device as the member IP address

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools.
  3. Select Create.
  4. Enter a name for the pool.
  5. For Address, enter the IP address of the IDS system.
  6. For Service Port, enter the port number.
  7. Select Add.
  8. Select Finished.

To create a pool that contains the IDS IP address using tmsh, use the following command syntax:

tmsh create /ltm pool <pool_name> members add { IDS_IP_addr:port }

Modify a virtual server to reference the clone pool

To modify the virtual server to reference the clone pool using the Configuration utility, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the virtual server for which you want to assign the clone pool.
  4. For Configuration, select Advanced.
  5. For Clone Pool (Client) or Clone Pool (Server), select the pool created in the previous procedure that contains the IDS device.
  6. Select Update.

To modify a virtual server to reference the clone pool using tmsh, use the following command syntax:

tmsh modify /ltm virtual <virtual_name> clone-pools add { <pool_name> {context clientside | serverside } }

Configure interface mirroring

To configure interface mirroring, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To configure port mirroring by using the Configuration utility, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Network > Interfaces.
  3. Select Interface Mirroring.
  4. For Interface Mirroring State, select Enabled.
  5. For Destination Interface, select an interface.
  6. Select one or more interfaces from the Mirrored Interfaces list and move the interfaces to the Selected list.
  7. Select Update.

To configure interface mirroring using tmsh, use the following command syntax:

tmsh create /net port-mirror <mirror_to_interface> interfaces add { <mirror_from_interfaces> }

For example, to create a port mirror for the destination port 1.1 on blade 1 from the mirrored interfaces 1.2, 1.3, 1.4 on the same blade, use the following command:

tmsh create /net port-mirror 1/1.1 interfaces add { 1/1.2 1/1.3 1/1.4 }
