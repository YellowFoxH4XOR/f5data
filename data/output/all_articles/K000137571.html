K000137571: Certain newly added ASM violations have been introduced in blocking mode by default

Type
Support Solution
Published
2023-11-14
Updated
2024-04-18
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000137571

Description

Certain newly added ASM violations in v16+ releases have been introduced in blocking mode by default. 

Environment

Create a policy in v16+ release and note that the block setting for these violations are enabled, by default:

1. Disallowed file upload content detected in body
2. GraphQL data does not comply with format settings
3. GraphQL disallowed pattern in response
4. GraphQL introspection query
5. Illegal repeated header
6. Leaked Credentials Detection
7. Malformed GraphQL data

These violations do not exist in versions prior to v16 so devices being upgraded from prior to v16 to a v16+ release can endure false positive blocking events.

Cause

Newly added violations that require some other settings to have any effect are intentionally left as enabled and blocking. For example, GraphQL requires an associated profile, so having these violations in Blocking upon upgrade is correct. This removes friction from the process of adding GraphQL protection with no false positive potential. As for the'Disallowed file upload content detected in body' violation, this was added as a necessary setting for improving security posture based on other previously existing settings.

Recommended Actions

F5 recommends manually disabling the block settings for these violations in impacted releases or utilizing REST API in order to disable the block setting for the newly introduced violations in v16 or v17 releases. Here are the respective API endpoints for these violations:

1. Disallowed file upload content detected in body: /mgmt/tm/asm/policies/<policy-id>/blocking-settings/violations/uGCkZobR5FACyCk6cgia_w
2. GraphQL data does not comply with format settings: /mgmt/tm/asm/policies/<policy-id>/blocking-settings/violations/buG8qkOVckcbasEuYLsF2A
3. GraphQL disallowed pattern in response: /mgmt/tm/asm/policies/<policy-id>/blocking-settings/violations/m2a6qTOBzHjTAdpH764tiA
4. GraphQL introspection query: /mgmt/tm/asm/policies/<policy-id>/blocking-settings/violations/1puFKjS8KqOPkfQ69yfFtA
5. Illegal repeated header: /mgmt/tm/asm/policies/<policy-id>/blocking-settings/violations/fInn336lboKfZ6PyY3ssfw
6. Leaked Credentials Detection: mgmt/tm/asm/policies/<policy-id>/blocking-settings/violations/WD3fINSvTFpMxMKyaM6mUw
7. Malformed GraphQL data: /mgmt/tm/asm/policies/<policy-id>/blocking-settings/violations/3HL4KG8AXkFhMiVr-Ho4PQ

Additional Information

Impact of procedure: We recommend introducing sufficient grace period between each API call so as to ensure there's no resource overhead on the device control plane.

The following script can be utilized to automate this via REST API:

#!/bin/bash
for policyId in $(curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/" | jq . | grep -E '\"id\"' | awk '{print $2}' | cut -d '"' -f2)
do
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/buG8qkOVckcbasEuYLsF2A" | jq .
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/buG8qkOVckcbasEuYLsF2A" -X PATCH -d '{"block": false}' | jq .
	sleep 15
	echo "=========="
 
    curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/uGCkZobR5FACyCk6cgia_w" | jq .
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/uGCkZobR5FACyCk6cgia_w" -X PATCH -d '{"block": false}' | jq .
	sleep 15
	echo "=========="
 
    curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/m2a6qTOBzHjTAdpH764tiA" | jq .
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/m2a6qTOBzHjTAdpH764tiA" -X PATCH -d '{"block": false}' | jq .
	sleep 15
	echo "=========="
 
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/1puFKjS8KqOPkfQ69yfFtA" | jq .
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/1puFKjS8KqOPkfQ69yfFtA" -X PATCH -d '{"block": false}' | jq .
	sleep 15
	echo "=========="
 
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/fInn336lboKfZ6PyY3ssfw" | jq .
	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/fInn336lboKfZ6PyY3ssfw" -X PATCH -d '{"block": false}' | jq .

	curl -sku admin:[password] "https://[IP Address]/mgmt/tm/asm/policies/$policyId/blocking-settings/violations/WD3fINSvTFpMxMKyaM6mUw" -X PATCH -d '{"block": false}' | jq .

done
