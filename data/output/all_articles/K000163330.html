K000163330: macOS 27 Hard Disk Encryption Host Check Fails in BIG-IP APM

Type
Support Solution
Published
2026-09-16
Updated
2026-09-16
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163330

Description

On macOS 27, the BIG-IP APM Hard Disk Encryption Host Check can incorrectly evaluate as failed. The access policy then follows the configured fallback rule to Deny, preventing the client from completing the policy.

The issue is isolated to the EPSEC host-encryption inspection. The following message may appear in the session logs:

Following rule 'fallback' from item 'Hard Disk Encryption' to ending 'Deny'

Environment

  • BIG-IP APM
  • BIG-IP Edge Client
  • macOS 27
  • An access policy configured with a Host Check for Hard Disk Encryption

Cause

The EPSEC Hard Disk Encryption inspection is incompatible with the macOS 27 environment. The inspection incorrectly evaluates the check as failed, causing the access policy to follow the configured fallback Deny rule.

Recommended Actions

  1. Install the latest available EPSEC update that contains the fix for this inspection issue. (epsec-1.0.0-2028.0.iso or later)
  2. Deploy the corresponding updated EPSEC components to the affected BIG-IP Edge Client endpoints.
  3. Retest the Hard Disk Encryption Host Check from an affected macOS endpoint.
  4. Confirm that the access policy no longer follows the fallback rule to Deny.
  5. If the update cannot be deployed immediately, temporarily disable or isolate the Hard Disk Encryption Host Check, subject to the organization’s security requirements.
  6. Validate Host Check behavior after future macOS upgrades before broad deployment.

Additional Information

  • The issue is specific to the Hard Disk Encryption inspection and does not indicate a general failure of the BIG-IP APM access policy flow.
  • All Drives Encrypted verifies that all disk volumes are encrypted.
  • System Disk Encrypted verifies that the system disk is encrypted.
  • For recent macOS versions, disk encryption behavior may not directly reflect the current FileVault status.
