Known Issue

ConfigSync operations may fail after you create a private cli alias.

This issue occurs when the following condition is met:

  • The device group is configured to perform incremental configuration synchronizations.

Beginning in BIG-IP 11.4.0, the default settings for a device group are configured to perform incremental configuration synchronizations for members of the device group. When a private cli alias is created or modified, subsequent incremental configuration synchronization will fail.

Impact

ConfigSync operations fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H427855 on the Diagnostics > Identified > Medium screen.
  • ConfigSync operations fail, and the system logs error messages, similar to the following examples, to the /var/log/ltm file:

    01071506:3: Current user (%cmi-mcpd-peer-10.0.0.1) doesn't match user name specified in cli alias, <aliasname> (admin).

    01071507:3: User, (name), doesn't exist for  alias, (alias name).

Workaround

To work around this issue, you can force a device group member to perform a one-time full configuration ConfigSync operation, or disable incremental synchronization for the device group. To do so, perform one of the following procedures:

Forcing a one-time full configuration ConfigSync

If you create or modify a private cli alias only occasionally, you can use the set-sync-leader command option to force a device group member to perform a one-time full configuration ConfigSync each time you create or modify a private alias.  For additional information, refer to K13887: Forcing a BIG-IP device group member to initiate a ConfigSync operation.

Impact of workaround: This option is not persistent, and you must repeat it each time you create or modify a private cli alias.

Disabling incremental synchronization

Disabling incremental synchronization for the device group causes ConfigSync to perform a full configuration synchronization each time a ConfigSync is performed. You can disable incremental synchronization by setting the device group full-load-on-sync setting to true. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system may experience a performance impact when ConfigSync performs a full configuration synchronization of a large configuration.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Disable incremental synchronization by using the following command syntax:

    modify cm device-group <device_group_name> full-load-on-sync true

    For example:

    modify cm device-group my_devicegroup full-load-on-sync true

  3. Save the change by typing the following command:

    save /sys config

Subsequent ConfigSync operations will perform a full configuration synchronization.

Enabling incremental synchronization

You can re-enable incremental synchronization for the device group by setting the device group full-load-on-sync setting to false. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Enable incremental synchronization by using the following command syntax:

    modify cm device-group <device_group_name> full-load-on-sync false

    For example:

    modify cm device-group my_devicegroup full-load-on-sync false

  3. Save the change by typing the following command:

    save /sys config

Subsequent ConfigSync operations will perform an incremental configuration synchronization.
