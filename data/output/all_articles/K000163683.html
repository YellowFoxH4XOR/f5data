K000163683: Continuous SYN Cookie Mode Changes Cause Incorrect SYN Cookie Status and Statistics Reporting

Type
Support Solution
Published
2026-11-09
Updated
2026-11-09
Applies to
  • F5OS Products
  • BIG-IP
  • F5OS-A: 1.8.0, 1.8.X, 1.8.4, 1.8.3
  • BIG-IP LTM: 21.0.0
Source
https://my.f5.com/manage/s/article/K000163683

Description

BIG-IP LTM can report full-software SYN Cookie mode even when TMM has no active software SYN Cookie instances.

Observed symptoms may include:

  • The syncookies.swsyncookie_inst value in the virtual_server_stat table remains nonzero even though software SYN Cookie enforcement is no longer active.
  • The SYN Cookie instance count does not match the physical TMM count. For example, a system with eight TMMs may report a software SYN Cookie instance count of 10.
  • syncookies.hwsyncookie_inst remains zero while syncookies.hw_accepts continues to increase.
  • tmsh show ltm virtual displays full-software even though TMM is not actively enforcing software SYN Cookies.
  • The displayed SYN Cookie mode does not match the current TMM state. A diagnostic core showing zero active software SYN Cookie instances confirms that the displayed full-software state is stale.
  • SYN Cookie mode repeatedly transitions through NONE -> SW -> HW -> NONE -> SW -> HW.

Environment

  • BIG-IP LTM
  • F5OS
  • FastL4 forwarding virtual servers
  • Hardware and software SYN Cookie protection
  • Wildcard forwarding virtual servers overlapping other virtual servers
  • Traffic that exceeds the configured SYN Cookie activation threshold

Cause

The observed software SYN Cookie instance leak is associated with a hardware/software SYN Cookie mode-flapping defect tracked by Bug ID 2566253

When hardware SYN Cookie offload fails, potentially because of insufficient TCAM database capacity, TMM falls back to software SYN Cookie mode. The fallback implementation can repeatedly transition between hardware and software modes:

NONE -> SW -> HW -> NONE -> SW -> HW

The repeated transitions and asynchronous messaging across multiple TMMs can eventually leave leaked software SYN Cookie instances in the SYN Cookie control state. This may cause the reported SYN Cookie statistics and displayed mode to differ from the actual TMM enforcement state.

Recommended Action

Restart TMM to clear the inconsistent SYN Cookie state and associated anomalies:

tmsh restart sys service tmm

Impact: Restarting TMM causes a brief traffic interruption. Perform this action only during an approved maintenance window and in accordance with the applicable high-availability and change-management procedures.

Additional Information

  • A nonzero syncookies.swsyncookie_inst value alone does not prove that software SYN Cookie protection is actively enforcing traffic.
  • A diagnostic core, current virtual-server statistics, and Big-IP & F5OS qkview should be correlated to determine whether SYN Cookies are actively processing traffic or are only reported by stale statistics.
