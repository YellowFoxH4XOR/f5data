Topic

You should consider using these procedures under the following conditions:

  • You are a new user of the iControl representation state transfer (REST) API.
  • You want basic REST command examples for administering your BIG-IP AFM network firewall policies and rules.

Description

The following command examples show you how to use REST commands for the BIG-IP AFM system with minimal complexity.

Each REST command has multiple values that you can assign when running the command. When a specific value is not stated in the REST command, the default value is assumed. To understand the values available for a command, refer to the iControl REST User Guide that applies to your BIG-IP AFM version, available on DevCentral.

Note: A DevCentral login is required to access this content.

Additionally, viewing a currently configured object using a REST command displays all the values for the object, which can help you understand the required syntax to create an object setting value that is not covered in the examples.

In most cases, you can view an object's configuration using the GET method and the URI of the specific object.

For example, to view the configuration settings for a specific network firewall policy, you can use the URI path used to create the /mgmt/tm/security/firewall/policy object and append the object name to the/mgmt/tm/security/firewall/policy/<policy name> URI:

 curl -sk -u admin:admin -H "Content-Type: application/json" -X GET  https://192.168.1.70/mgmt/tm/security/firewall/policy/Rest-Created-Policy | jq -M

To view the network firewall policy recursive configuration, append the end of the URL with expandSubcollections=true.

For example:

 curl -sk -u admin:admin -H "Content-Type: application/json" -X GET  https://192.168.1.70/mgmt/tm/security/firewall/policy/Rest-Created-Policy?"expandSubcollections=true" | jq -M

Note: The JSON output of the object configuration includes links to view additional nested configuration details.

When using the JSON links, replace localhost with the IP address of the BIG-IP system.

Viewing objects with a REST command can produce verbose JSON output. To format the JSON output to a more user-friendly format, use the jq command-line JSON processor command. The jq command -M flag sets the formatted JSON output to monochrome when displaying output.

For example:

curl -s -k -u admin:admin  -H "Content-Type: application/json" -X GET https://<ip address> /mgmt/tm/security/firewall/globalRules | jq -M

Example output:

{
  "kind": "tm:security:firewall:global-rules:global-rulesstate",
  "selfLink": "https://localhost/mgmt/tm/security/firewall/global-rules?ver=14.0.0",
  "enforcedPolicy": "/Common/Rest-Created-Policy",
  "enforcedPolicyReference": {
    "link": "https://localhost/mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy?ver=14.0.0"
  }
}

Example unformatted output:

{"kind":"tm:security:firewall:global-rules:global-rulesstate","selfLink":"https://localhost/mgmt/tm/security/firewall/global-rules?ver=14.0.0","enforcedPolicy":"/Common/Rest-Created-Policy","enforcedPolicyReference":{"link":"https://localhost/mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy?ver=14.0.0"}}

Typographic conventions

The following typographic conventions are used in the command syntax examples:

  • POST = curl -sk -u admin:<password> -H "Content-Type: application/json" -X POST https://<big-ip address>
  • PUT = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PUT  https://<big-ip address>
  • DELETE = curl -sk -u admin:<password>  -H "Content-Type: application/json" -X DELETE https://<big-ip address>
  • GET = curl -s -k -u admin:<password>   -H "Content-Type: application/json" -X GET https://<big-ip address>
  • PATCH = curl -s -k -u admin:<password>   -H "Content-Type: application/json" -X PATCH https://<big-ip address>

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Your BIG-IP system is licensed and provisioned with the BIG-IP AFM module.
  • Your BIG-IP system is configured with a management IP address.
  • You have administrative access to the Configuration utility.
  • You have command-line access to a Linux system or an alternate BIG-IP system with the curl utility and jq (command line JSON processor) utility installed.
  • You have login access on DevCentral to review iControl REST interface documentation.

Viewing firewall policies and rules

Impact of procedure: Using the following command should not have a negative impact on your system.

To view all the configured network firewall policies, recursively use the following syntax:

<GET> /mgmt/tm/security/firewall/policy?"expandSubcollections=true"

To view an individual network firewall policy, append the policy name including the partition location as part of the query URI using the following syntax:

<GET> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>?"expandSubcollections=true"

For example:

<GET> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy?"expandSubcollections=true"

To view all the configured network firewall rules recursively use the following syntax:

<GET> /mgmt/tm/security/firewall/rule-list?"expandSubcollections=true" | jq -M

To view an individual network firewall rule, append the rule name including the partition location as part of the query URI using the following syntax:

<GET> /mgmt/tm/security/firewall/rule-list/~<partition>~<rule name>?"expandSubcollections=true"

For example:

<GET> /mgmt/tm/security/firewall/rule-list/~alternate_partition~allow-custom-port-123?"expandSubcollections=true"

Creating and viewing schedules

Impact of procedures: Using the following commands should not have a negative impact on your system.

To creating a schedule that can be used when defining a firewall rule, use the following command syntax:

<POST> /mgmt/tm/security/firewall/schedule -d '{"partition":"<partition>","name":"<schedule name>","dailyHourStart":"<24hr time UTC>","dailyHourEnd":"<24hr time UTC>","dateValidStart":"<yyyy-mm-dd>T<24hr time UTC>","dateValidEnd":"indefinite","daysOfWeek":["<lowercase day name>"],"description":"<free form description>"}'

For dateValidStart, you can use epoch to state the current time. For dateValidEnd, you can use indefinite when no end time is needed.

When adding multiple daysOfWeek, use the following syntax:

"daysOfWeek":["<lowercase day name>"],["<lowercase day name>"],["<lowercase day name>"].

For example:

<POST> /mgmt/tm/security/firewall/schedule -d '{"partition":"Common","name":"saturday-maintenance","dailyHourStart":"02:00","dailyHourEnd":"07:00","dateValidStart":"2018-11-03T09:00:00Z","dateValidEnd":"2018-11-03T14:00:00Z","daysOfWeek":["saturday"],"description":"active saturday november 3, 2018 from 2am to 7am"}'

The previous example command creates a schedule with the name of saturday-maintenance in the Common partition. The schedule starts at 2am and ends at 7am for November 3, 2018. The dateValidStart and dateValidEnd is specified using UTC.

To view currently configure network firewall schedules, use the following command syntax:

<GET> /mgmt/tm/security/firewall/schedule?"expandSubcollections=true"

Creating and viewing IP Intelligence policies

Impact of procedures: Using the following commands should not have a negative impact on your system.

To create a new IP Intelligence policy, use the following command syntax:

<POST> /mgmt/tm/security/ip-intelligence/policy -d '{"name":"<policy name>","defaultLogBlacklistHitOnly":"<yes/no>","blacklistCategories":[{"name":"<category>","action":"<action>","matchDirectionOverride":"<override direction>"}]}'

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

Note: defaultLogBlacklistOnly is an optional setting. When not declared, the default setting for defaultLogBlacklistOnly is no.

For example:

<POST> /mgmt/tm/security/ip-intelligence/policy -d '{"name":"rest-ip-policy","defaultLogBlacklistHitOnly":"yes","blacklistCategories":[{"name":"scanners","action":"drop","matchDirectionOverride":"match-source"}]}'

The previous example command creates the IP Intelligence policy of rest-ip-policy. Because no partition is declared, the default partition of Common is used. The policy logs hits from denylisted (blacklisted) addresses defaultLogBlacklistHitOnly yes and derives the denylisted address from the scanners category. Source addresses only are compared to the denylisted addresses.

To view the IP Intelligence global policy type the following command:

<GET> /mgmt/tm/security/ip-intelligence/global-policy 

Setting the IP Intelligence global policy

Impact of procedure: The following command syntax sets the selected IP Intelligence policy as the globally active policy. Depending on the policy settings and traffic processed by the BIG-IP AFM system, traffic may be impacted.

<PUT> /mgmt/tm/security/ip-intelligence/global-policy -d '{"ipIntelligencePolicy":"<policy name>"}'

For example:

<PUT> /mgmt/tm/security/ip-intelligence/global-policy -d '{"ipIntelligencePolicy":"rest-ip-policy"}'

The previous example command sets the global policy IP Intelligence to rest-ip-policy.

Creating a network firewall policy

Impact of procedures: Using the following commands should not have a negative impact on your system.

To create a new network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy -d '{"name":"<firewall policy name>"}'

For example:

<POST> /mgmt/tm/security/firewall/policy -d '{"name":"Rest-Created-Policy"}'  

<POST> /mgmt/tm/security/firewall/policy -d '{"name":"Rest-Created-Policy","partition":"alternate_partition"}'

The first previously listed example creates a network firewall policy named Rest-Created-Policy in the default partition Common. The second example specifies the alternate_partition ("partition":"alternate_partition") and creates the policy Rest-Created-Policy in the specified partition.

When modifying or querying a policy or rule that resides in a partition other than the default partition Common, use the following syntax:

~<partition>~<policy, rule or schedule name>.

For example, the following syntax references the network firewall policy name Rest-Created-Policy, which resides in partition alternate_partition: /mgmt/tm/security/firewall/policy/~alternate_partition~Rest-Created-Policy:

<GET> /mgmt/tm/security/firewall/policy/~alternate_partition~Rest-Created-Policy | jq -M
{
  "kind": "tm:security:firewall:policy:policystate",
  "name": "Rest-Created-Policy",
  "partition": "alternate_partition",
  "fullPath": "/alternate_partition/Rest-Created-Policy",
  "generation": 1051,
  "selfLink": "https://localhost/mgmt/tm/security/firewall/policy/~alternate_partition~Rest-Created-Policy?ver=14.0.0",
  "rulesReference": {
    "link": "https://localhost/mgmt/tm/security/firewall/policy/~alternate_partition~Rest-Created-Policy/rules?ver=14.0.0",
    "isSubcollection": true
  }
}

The following command references the network firewall policy Rest-Created-Policy, with no declaration for a specific partition. Without the declaration, the default partition of Common is used: /mgmt/tm/security/firewall/policy/Rest-Created-Policy.

For example:

<GET>  /mgmt/tm/security/firewall/policy/Rest-Created-Policy | jq -M      {
  "kind": "tm:security:firewall:policy:policystate",
  "name": "Rest-Created-Policy",
  "fullPath": "Rest-Created-Policy",
  "generation": 873,
  "selfLink": "https://localhost/mgmt/tm/security/firewall/policy/Rest-Created-Policy?ver=14.0.0",
  "rulesReference": {
    "link": "https://localhost/mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules?ver=14.0.0",
    "isSubcollection": true
  }
}

Adding firewall rules to an existing policy

Impact of procedure: The following commands add firewall rules to an existing network firewall policy If the network firewall policy is an active policy, the firewall rules can impact traffic processed by the BIG-IP AFM system.

To add a rule to an existing network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules -d '{"name":"<rule name>","ipProtocol":"<protocol name>","action":"<action>","log":"<yes/no>","<policy rule placement>","status":"enabled"}'

For example:

<POST> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules -d '{"name":"no-icmp","ipProtocol":"icmp","action":"drop","log":"yes","place-before":"first","status":"enabled"}'

The previous example command adds the firewall rule no-icmp to the network firewall policy Rest-Created-Policy, which resides in the Common partition. The specified ip protocol is icmp (ipProtocol: icmp), the associated action is to drop the ICMP request ("action":"drop"), and log the event ("log":"yes").The new rule is placed in the policy as the first rule of the policy ("place-before":"first") and is enabled in the policy ("status":"enabled").

To add a new custom port base firewall rule to an existing network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules -d '{"name":"<rule name>","ipProtocol":"<protocol>","action":"<action>","ports":[{"name":"<numeric port>"}],"<policy rule placement>"}'

For example:

<POST> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules -d '{"name":"udp-port-505","ipProtocol":"udp","action":"accept","ports":[{"name":"505"}],"place-before":"last"}'

The previous command example creates the custom port based rule udp-port-505 ("name":"udp-port-505"), for the policy Rest-Created-Policy, residing in the Common partition. The protocol is UDP ("ipProtocol":"udp") for port 505 ("ports":[{"name":"505"}]) and the action is accept ("action":"accept"). The new rule is second-to-last in the policy ("place-before":"last").

To add a new firewall rule referencing a source address list to an existing network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules -d '{"name":"<rule name>","ipProtocol":"<protocol>","action":"<action>","log":"<yes/no>","policy rule placement>","status":"enabled","source":{"addresses":[{"name":"<ip address or ip address range>"}]}}'

For example:

<POST> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules -d '{"name":"reject_icmp_172","ipProtocol":"icmp","action":"reject","log":"yes","place-after":"first","status":"enabled","source":{"addresses":[{"name":"172.16.0.0-172.16.0.255"}]}}'

The previous example command adds the firewall rule reject_icmp_172 to the network firewall policy Rest-Created-Policy, which resides in the Common partition. The specified IP is ICMP ("ipProtocol":"icmp"), the associated action is to reject the ICMP request ("action":"reject") and to log the event ("log":"yes"). The new rule is second in the policy ("place-after":"first").The rule applies to ICMP request coming from the network addresses in the 172.16.0/24 network ("source":{"addresses":[{"name":"172.16.0.0-172.16.0.255"}]}}).

To add a firewall rule configured with source and destination addresses to a network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules -d '{"name":"<rule name>","ipProtocol":"<protocol>","action":"<action>","log":"<yes/no>","<policy rule placement>":"<rule list position>","status":"<enabled/disabled>","destination":{"addresses":[{"name":"<ip address"},{"name":"<ip address>"}]},"source":{"addresses":[{"name":"<individual ip address or ip address range>"}]}}'

For example:

<POST> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules -d '{"name":"drop_udp","ipProtocol":"udp","action":"drop","log":"yes","place-before":"first","status":"enabled","destination":{"addresses":[{"name":"11.0.0.11"},{"name":"11.0.0.12"}]},"source":{"addresses":[{"name":"172.16.0.0-172.16.0.255"}]}}'

The previous example command creates the rule drop_udp ("name":"drop_udp") for the protocol udp ("name":"drop_udp") with the action of drop ("action":"drop"). The rule has logging enabled ("log":"yes"), the placement of the rule is first in the policy ("place-before":"first"), and the rule is enabled ("status":"enabled"). The rule is restricted to the destination addresses of 11.0.0.11 and 11.0.0.12 ("destination":{"addresses":[{"name":"11.0.0.11"},{"name":"11.0.0.12"}]},) from the source network of 172.16.0/24 ("source":{"addresses":[{"name":"172.16.0.0-172.16.0.255"}]}}').

Adding a firewall rule-list to a network firewall policy

Impact of procedure: The following commands add a firewall rule-list to an existing network firewall policy. If the network firewall policy is active, the firewall rule list can impact traffic processed by the BIG-IP AFM system.

To add a scheduled rule list to a network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules -d '{"name":"<rule-list name>","ruleList":"/<partition>/<rule-list name>","schedule":"/<partition>/<schedule name>","<policy rule placement>","status":"scheduled"}'

For example:

<POST> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules -d '{"name":"allow-vnc-maintenance","ruleList":"/Common/allow-vnc","schedule":"/Common/saturday-maintenance","place-before":"last","status":"scheduled"}'

The previous example command adds the rule allow-vnc-maintenance to the policy Rest-Created-Policy in the Common partition. The rule derives its configuration from the rule list allow-vnc ("ruleList":"/Common/allow-vnc"). The rule is enabled by the schedule saturday-maintenance ("schedule":"/Common/saturday-maintenance"), and placed second to last in the policy ("place-before":"last").

Adding a scheduled firewall rule to a network firewall policy

Impact of procedure: The following commands add a firewall rule or rule list to an existing network firewall policy. If the network firewall policy is active, the firewall change can impact traffic processed by the BIG-IP AFM system.

To add a scheduled firewall rule to a network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules -d '{"name":"<rule name>","ipProtocol":"<protocol>","action":"<action>","log":"<yes/no>","<policy rule placement>":"<first/last>","schedule":"<schedule name>"}'

For example:

<POST> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules -d '{"name":"allow_aris","ipProtocol":"aris","action":"accept","log":"yes","place-before":"first","schedule":"saturday-testing","status":"scheduled"}'

The previous command example creates the policy rule allow_aris for the policy Rest-Created-Policy, which resides in the Common partition. The protocol is aris ("ipProtocol":"aris") the action is to accept ("action":"accept") and log the event ("log":"yes"). The rule is first in the policy ("place-before":"first"). The rule is activated by the schedule saturday-testing ("schedule":"saturday-testing"), ("status":"scheduled").

To add a scheduled rule list to a network firewall policy, use the following command syntax:

<POST> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules -d '{"name":"<rule-list name>","ruleList":"/<partition>/<rule-list name>","schedule":"/<partition>/<schedule name>","<policy rule placement>","status":"scheduled"}'

For example:

<POST> /mgmt/tm/security/firewall/policy/~Common~Rest-Created-Policy/rules -d '{"name":"allow-vnc-maintenance","ruleList":"/Common/allow-vnc","schedule":"/Common/saturday-maintenance","place-before":"last","status":"scheduled"}'

The previous example command creates the firewall rule allow-vnc-maintenance ("name":"allow-vnc-maintenance") from the rule list allow-vnc ("ruleList":"/Common/allow-vnc") for the Rest-Created-Policy, which resides in the Common partition. The rule is scheduled to execute based on the saturday-maintenance schedule ("schedule":"/Common/saturday-maintenance"), and the rule is second to last in the policy  ("place-before":"last").

Deleting a firewall rule from a network firewall policy

Impact of procedure: The following command removes a rule from the network firewall policy. If the network firewall policy is active, removing the rule can impact how traffic is processed by the BIG-IP AFM system.

To delete a firewall rule from a network firewall policy, use the following command syntax:

<DELETE> /mgmt/tm/security/firewall/policy/~<partition>~<policy name>/rules/<rule name>

For example:

<DELETE> /mgmt/tm/security/firewall/policy/~alternate_partition~Rest-Created-Policy/rules/allow-custom-port-123

The previous command example deletes the rule allow-custom-port-123 from the policy Rest-Created-Policy, which resides in the partition alternate_partition.

Assigning a network firewall policy as the global policy

Impact of procedure: The following procedure modifies the global network firewall policy for the BIG-IP AFM system and impacts how traffic is processed by the system.

To assign a network firewall policy as the global firewall policy, use the following command syntax:

<PATCH> /mgmt/tm/security/firewall/globalRules/  -d '{"enforcedPolicy":"/<partition>/<firewall policy>"}'

For example:

<PATCH> /mgmt/tm/security/firewall/globalRules/  -d '{"enforcedPolicy":"/Common/Rest-Created-Policy"}'

The previous example command sets the global network firewall policy to use the Rest-Created-Policy, which resides in the Common partition.

Saving the configuration

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Depending on the method used to create and modify the configuration objects, a manual save of the configuration may be necessary. The Configuration utility automatically saves the configuration objects. If you created the configuration using the TMOS Shell (tmsh) or the iControl REST API, you should save your configuration with one of the following commands.

To save the configuration using tmsh, use the following command from the command line of the BIG-IP device:

tmsh save /sys config partitions all

To save your configuration using the iControl REST API, use the following command syntax:

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/sys/config -d '{"command":"save","partition":["<partition name>","<partition name>"]}'

Example:

curl -s -k -u admin:default -H "Content-Type: application/json" -X POST https://192.168.1.70/mgmt/tm/sys/config -d '{"command":"save","partition":["Common","QA"]}'

Note: The iControl REST API does not have a method to save the configuration to all configured partitions. When configuring a BIG-IP device with multiple partitions, you must specify each partition that you intend to save the configuration objects for.

For BIG-IP devices that only have the default Common partition, or when all the configured objects you want to save are in the Common partition, you can use the following command syntax:

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/sys/config -d '{"command":"save"}'
