Known Issue

This is the result of a known issue. The TCP::respond iRule command sends the specified response data directly to the peer. If the TCP::respond iRule command fails (for example if the connection prematurely timed out), the BIG-IP system does not send the response data, and the xfrag(s) containing the response data will be leaked.

When this issue occurs, an error message similar to the following example is logged to the /var/log/ltm file:

TCL error: <rule_name> <CLIENT_DATA> - Not connected (line 2) invoked from within "TCP::respond...

F5 Networks Product Development tracked this issue as CR92947 and it was fixed in BIG-IP LTM version 9.4.6. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue has been fixed in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP version 9.4.5, for the BIG-IP 9.4 software branch. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
