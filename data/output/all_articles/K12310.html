Known Issue

This is the result of a known issue. The BIG-IP system will not execute the CLIENTSSL_DATA iRule event unless a pool or a profile (other than the client SSL and server SSL profiles) is associated with the virtual server.

For example:

rule TestClientSSLRule {
  when CLIENTSSL_HANDSHAKE {
    log local0. "ClientSSL Handshake received"
    SSL::collect 4
  }
  when CLIENTSSL_DATA {
    log local0. "data=|[SSL::payload 3]|"
    SSL::release
  }
}

When the BIG-IP system receives a connection, the BIG-IP system correctly executes the first part of the iRule and subsequently logs a message. However, the BIG-IP system expects a pool or profile other than the client SSL or server SSL profile to be associated with the virtual server. Therefore, the BIG-IP system does not execute the second portion of the iRule.

F5 Product Development tracked this issue as ID 224958 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, or Link Controller release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.0-1789.0-HF2, which has been issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
