Known Issue

Imported zone files may not contain correct $ORIGIN directives.

This issue occurs when the following condition is met:

  • Using the ZoneRunner utility, you import a zone file that contains $ORIGIN directives that use the at (@) symbol.

Impact

The BIG-IP system does not correctly import the original directives.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Zone files that use the at (@) symbol $ORIGIN directives do not maintain the directives when you perform the import.

    The following is an example of a zone file for import:

    ;
    $TTL 3600
    example.com. 86400 IN SOA ns1.example.com. hostmaster.ns1.example.com. 2017020201 10800 3600 604800 86400
    @ IN NS ns1.example.com.
    ns1.example.com. IN A 1.1.1.1
    $ORIGIN alpha.example.com.
    @ IN A 2.2.2.2
    $ORIGIN bravo.example.com.
    @ IN A 3.3.3.3
    ;

    The following is an example of the zone file after it was imported:

    ;
    example.com.                                  86400 IN SOA      ns1.example.com. hostmaster.ns1.example.com. 2017020201 10800 3600 604800 86400
    example.com.                                  3600 IN NS        ns1.example.com.
    example.com.                                  3600 IN A         2.2.2.2
    example.com.                                  3600 IN A         3.3.3.3
    ns1.example.com.                              3600 IN A         1.1.1.1
    ;

    Note: The @ directive is associated with the zone name and is not associated with the $ORIGIN that is specified in the import file.

  • DNS resolution by the BIG-IP DNS system (formerly known as BIG-IP GTM) does not proceed as you expect for the imported zone file.

Workaround

To work around this issue, you can use the named-compilezonecommand from the Linux bind9utils command line tool to normalize the zone file before using the ZoneRunner utility to import the zone file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Copy the import zone file to a BIG-IP or Linux system that has bind9utils installed.
  2. Log in to the command line of the BIG-IP or Linux system.
  3. To normalize the zone file that you intend to import, use the following command syntax:

    named-compilezone -s full -o <normalized zone file> <zone name> <original zone file>

    For example:

    named-compilezone -s full -o example.com.db.compiled example.com example.com.db

    Note: For more information about the named-compilezone command, see the man page.

    For example, type the following:

    man named-compilezone

  4. Import the compiled (normalized) zone file to the BIG-IP DNS system.
