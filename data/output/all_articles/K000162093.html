Description

When you configure BIG-IP Access Policy Manager (APM) to log Virtual Private Network (VPN) user activity, you observe that VPN connection and disconnection events — specifically "PPP Tunnel started" and "PPP Tunnel closed" messages — appear in the CLI log file (/var/log/apm) but are absent from the GUI Access Reports (Access > Overview > Event Logs > Access Reports). If you have configured High-Speed Logging (HSL) or a remote syslog publisher, you may also be uncertain whether these disconnection events are forwarded to your external syslog server.

Environment

  • BIG-IP Access Policy Manager (APM)
  • All supported hardware platforms
  • Network Access (VPN) configurations 

Cause

This is by-design behaviour resulting from an architectural difference between the two APM logging pipelines. The "PPP Tunnel closed" (VPN disconnect) event is generated by the Traffic Management Microkernel (TMM) process and written directly to syslog at Notice level — which is why it appears in /var/log/apm. However, this event is not written to the MySQL reporting database by the apmd daemon, so it does not appear in the GUI Access Reports.

The table below summarises the difference between the two logging destinations:

CLI (/var/log/apm)GUI (Access Reports)
SourceSyslog / TMM directlyMySQL (logdb) database
Writertmm processapmd / logmysqld daemon
PPP Tunnel closed eventPresentNot present (by design)

Recommended Actions

Verifying VPN disconnection logs in the CLI

  1. Log in to the BIG-IP command line.
  2. Run the following command to monitor APM logs in real time, filtering by username:
    1. tail -f /var/log/apm | grep <username>
  3. Ask a test user to connect to the VPN, wait a few minutes, and then disconnect.
  4. Confirm that you see both "PPP Tunnel started" and "PPP Tunnel closed" entries in the output.

Verifying that disconnection logs reach your external syslog server

The HSL and remote syslog pipeline forwards the same log stream as /var/log/apm. Because "PPP Tunnel closed" events originate from TMM syslog — which is exactly what HSL captures — these events are forwarded to your external syslog server or Security Information and Event Management (SIEM) system when HSL is correctly configured.

To confirm your log publisher is correctly associated:

  1. In the BIG-IP Configuration utility, navigate to Access > Overview > Event Logs > Settings.
  2. Select your APM log setting and verify that the Log Publisher is set to your remote syslog or HSL destination (not the local database publisher).
  3. Ask a test user to connect to and then disconnect from the VPN.
  4. Check your external syslog server for "PPP Tunnel started" and "PPP Tunnel closed" entries for that user.

Note: If the log publisher destination is set to the local MySQL publisher, PPP tunnel events will not be forwarded externally. Change the publisher destination to your syslog destination to capture these events on your SIEM.

Additional Information

For general information on configuring APM event logging, refer to the BIG-IP APM documentation for your version.
