Description

  • When modifying network configuration such as the management IP address or gateway of a vCMP guest, other blades may restart unexpectedly.
  • Error messages similar to the following example appear on the /var/log/ltm file:

slot2/localhost err mcpd[PID]: 0107098a:3: The ip address (10.0.0.3%1) for a VCMP Mgmt IP in partition () references a route domain (1) in a different partition (foo). Objects may only reference objects in the same or the 'Common' partition
slot2/localhost err mcpd[PID]: 01070734:3: Configuration error: Configuration from primary failed validation: 0107098a:3: The ip address (10.0.0.3%1) for a VCMP Mgmt IP in partition () references a route domain (1) in a different partition (foo). Objects may only reference objects in the same or the 'Common' partition... failed validation with error 17238410.

Environment

  • vCMP Guest on multiple Blades
  • Non-Common partition
    • Partitions using non-default route-domains

Cause

BugID 990853

From the vCMP host when you are modifying the management IP address or gateway to a vCMP guest, while you are not on the Common partition, the MCPD daemon restarts on secondary blades.
The vCMP guests running on the affected blades will suffer an outage and will be unable to process traffic while the daemons restart.

Recommended Actions

Ensure that you are on the Common partition while you changing the management IP address or gateway of a vCMP guest.
