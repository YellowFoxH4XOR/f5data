Description

Modifying the "Transparent" option on an existing HTTP monitor in BIG-IP LTM does not update the behavior for pool members already associated with that monitor. After changing this attribute, health check packets may continue to be sent to the default gateway MAC address instead of the pool member MAC address, resulting in pool members being marked as down.

Environment

  • Monitor
  • Transparent

Cause

Changing the "Transparent" attribute of a monitor after it has been assigned to a pool or pool member does not update the corresponding monitor instance in BIG-IP's configuration database. The system continues using the previous value for health checks until the monitor is detached and reattached or replaced. This results in unexpected monitoring behavior such as sending packets to the wrong MAC address (typically default gateway instead of target server). The issue related to Bug ID1953069.

Recommended Actions

To apply changes to the "Transparent" attribute, follow one of these methods:

  1. Remove and Reassign: Remove the affected monitor from all associated pools or pool members, then reassign it to ensure the changes take effect.
  2. Create a New Monitor: Create a new HTTP monitor with the desired attributes and directly assign it to the relevant pools or pool members.

Both methods ensure proper application of the updated attribute.
