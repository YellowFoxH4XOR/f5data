Description

An iRule that rewrites HTTP data is converting UTF8 characters to ISO8859, and the ISO8859 encoding is written out as additional UTF8 characters

Environment

  • iRules

Cause

When data is read, it is interpreted as a byte array and not a string. Consequently the 2-bytes that form the UTF-8 character are interpreted as 2 single bytes of ISO8859-1 and not a UTF-8 character.  When the data is written back, out it is interpreted as a string and not a byte array, and the 2 individual bytes now each represent a ISO8859-1 character,  are then written out as 2 X 2bytes of UTF-8 encoded characters.  

For example, if a payload contains "Józef Pilsudski",
it has the byte stream : 4a c3 b3 7a 65 66 20 50 69 c5 82 73 75 64 73 6b 69
and if this is then modified by an iRule to append the string " Chief of State"
which is the additional byte stream :  20 43 68 69 65 66 20 6f 66 20 53 74 61 74 65
When the string is written back to the payload it becomes "JÃ³zef PiÅ?sudski Chief of State".
it has the byte stream :  4a c3 83 c2 b3 7a 65 66 20 50 69 c5 85 c2 82 73 75 64 73 6b 69 20 43 68 69 65 66 20 6f 66 20 53 74 61 74 65

This is because the UTF-8 character for 'ó' has the hex value c3 b3, and the UTF-8 character for 'l' has the hex value c5 82
And when the data is read in , it is read as a byte array and is thus read as 2 bytes from ISO8859-1, where c3 = 'Ã', b3 = '³' , c5 = 'Å' and 82 ='?'
but when this is saved to the new variable it is saved as a string value and not a byte array, and the new values are converted to UTF-8 hex that represent these characters which are  c3 83 = 'Ã' , c2 b3 = '³' , c5 85 = 'Å' and c2 82 = '?', so the hex for 'ó' which is c3 b3 , then becomes c3 83 c2 b3, and the hex for 'l' which is c5 82, then becomes c5 85 c2 82  

Recommended Actions

When the data is written back out it must be forced to remain as a byte array.
The follow iRule gives an example of how to do this using the 'binary scan' command

when HTTP_REQUEST_DATA {
 set original_data [HTTP::payload]
 set new_data "$original_data DATA HAS BEEN MODIFIED"
# the variable new_data now contains a byte array with the modified string
# forcing a binary scan on $new_data keeps it as a byte array and not a string.
 binary scan $new_data @0
# the data is replaced by the byte array variable $new_data which is now handled in the same way as a string
 HTTP::payload replace 0 $content_length $new_data
}
