Description

Efficient configuration of monitor intervals is a crucial aspect of managing BIG-IP DNS deployments, particularly when dealing with extensive configurations involving numerous BIG-IP DNS server objects and a multitude of "bigip" monitoreds. By adhering to these best practices, which include creating monitors with unique intervals and strategically distributing them, you can enhance monitoring capabilities and mitigate potential performance challenges. As you implement these recommendations, remember that every network is distinct, so customization based on specific requirements is key to achieving the best possible results.

Environment

This set of best practices is particularly relevant when working in the context of:

  •   BIG-IP DNS infrastructure with a substantial number of monitors. The infrastructure may be similar to the following:
    •  Multiple BIG-IP DNS server objects utilizing "bigip" monitors. For example, several thousand monitor instances using the default /Common/bigip monitor interval of 30 seconds.
    • A very large number of BIG-IP server objects being actively monitored. For example, several thousand BIG-IP server objects.
    • BIG-IP LTM systems with a large number of virtual servers.

Cause

In such large-scale deployments as mentioned above, the use of a substantial number of monitor instances with uniform intervals can lead to performance bottlenecks and monitoring-related issues. An example is described in bug ID1128369: GTM (DNS) /Common/bigip monitor instances may show 'big3d: timed out' state.

Employing recommended practices for configuring monitor intervals in the BIG-IP DNS environment can alleviate these concerns and contribute to an overall enhancement of monitoring performance.

Recommended Actions

It's important to note that every network design has unique requirements. Prior to implementing any changes, carefully evaluate your internal monitoring needs and tailor the approach accordingly.

  •     Confirm Monitor Instances per Interval: Run the following command to return the number of monitor instances for each Interval.

guishell -c "select count(INTERVAL_MS), INTERVAL_MS from monitor_instance,monitor WHERE monitor.NAME=monitor_instance.MON_NAME GROUP BY INTERVAL_MS ORDER BY 1 ASC;"

# example output, showing a large amount of monitored instances on the default 30 sec interval for gtm monitors
---------------------
|    | INTERVAL_MS |
---------------------
| 11 |        5000 |
| 15 |       15000 |
| 3701 |       30000 |
---------------------

  •    Output List of GTM Monitors with the Large Amount of Monitor Instances: Run the following command to output a list of GTM monitors, using the default 30 sec interval, for example. This for loop iterates through each GTM monitor component (bigip, tcp, http, tcp_half_open, etc).

for i in $(tmsh list gtm monitor | grep ^gtm | awk -F' ' '{print $3}' | uniq -u); do tmsh list gtm monitor $i interval | grep 'interval 30' -B 1; done

#example output, which lists all gtm monitors using the 30 sec Interval
[root@localhost:Active:In Sync] config # for i in $(tmsh list gtm monitor | grep ^gtm | awk -F' ' '{print $3}' | uniq -u); do tmsh list gtm monitor $i interval | grep 'interval 30' -B 1; done gtm monitor bigip bigip { interval 30 gtm monitor http http { interval 30 -- gtm monitor http http_head_f5 { interval 30 gtm monitor tcp tcp { interval 30 gtm monitor tcp-half-open tcp_half_open { interval 30 -- gtm monitor tcp-half-open tcp_half_open_30 { interval 30

  •   Create Monitors with Unique Intervals: Begin by crafting new "bigip" monitors with distinct intervals. As an alternative, the following script can be employed:

    for i in {41..59} ; do echo create gtm monitor bigip bigip_$i interval $i timeout $(($i * 3 + 1)) ; done  | tmsh

    This script utilizes a loop to generate monitor creation commands with the specified properties:
        The monitor name follows the format "bigip_i," with "i" ranging from 41 to 59 as dictated by the loop counter variable.
        Monitor type is set to "bigip."
        Monitor interval is determined by the loop counter variable (ranging from 41 to 59).
        Monitor timeout is calculated as (loop counter variable x 3) + 1.

    The "echo" command prints each "create gtm monitor" command to the console, which is then piped to the "tmsh" command for execution in the BIG-IP Traffic Management Shell.

  •     Distribute Monitors: After creating the monitors, apply them to all DNS servers of type "bigip." Replace the initial "bigip" with "bigip_1," then "bigip_2," and so forth. This distribution ensures that monitors for the same BIG-IP device are evenly spread throughout the interval period. This practice contributes to a more balanced monitoring performance in the BIG-IP DNS setup.

Additional Information

While the provided approach offers valuable guidance, it's essential to adjust interval values according to your network's unique demands and conditions.
