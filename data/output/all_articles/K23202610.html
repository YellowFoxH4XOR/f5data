Description
When viewing the persistence records from the LTM Statistics Module (GUI) or from the command line: tmsh show /ltm persistence persist-records, some persistence records may appear to be duplicated:

source-address  10.17.12.54     172.21.206.238:443  10.0.10.26:3000  (tmm: 0)
source-address  10.17.12.54     172. 21.206.238:443  10.0.10.26:3000  (tmm: 1)
source-address  10.17.12.54     172.21.206.238:443  10.0.10.26:3000  (tmm: 2)
source-address  10.17.12.54     172.21.206.238:443  10.0.10.26:3000  (tmm: 3)

Environment

  • BIG-IP LTM 
  • Virtual Server with Source address persistence

Cause
One TMM is the "Owner" entry. It is the point of authority for the record, but other TMMs may keep a local cached copy of the persistence record as long as that TMM has active connection flows that reference it.  

Recommended Actions

  1. The GUI will not provide the additional TMM information.  The records will appear to be duplicated, but there will not be more "duplicate" records than there are TMMs.
  2. The command line will provide the output shown above.  It lists the TMM holding the persistence record.  It is clear that there are differences (the TMM #) between each record.
  3. By using the "all-properties" argument in the command line, it will be clear which TMM is the owner, as opposed to TMMs that are "local" (cached).  Here is an example:
Sys::Persistent Connections
source-address - 10.65.203.15:80 - 10.65.203.145:80
----------------------------------------------------
  TMM           1
  Mode          source-address
  Value         10.65.203.1
  Age (sec.)    14
  Virtual Name  /Common/HTTP_Application/Application
  Virtual Addr  10.65.203.15:80
  Node Addr     10.65.203.145:80
  Pool Name     /Common/HTTP_Application/pool_0
  Client Addr   10.65.203.1
  Owner entry
The listing "owner entry" identifies that TMM 1 is the authority for this record.  The other listings will show "local"
