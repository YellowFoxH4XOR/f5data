Description

  • Intermittent connection towards the outside server, started occurring for new subnets added to an existing NAT rule.

Environment

  • Viprion chassis is running on HA
  • Server on the internet configured as a Content server
  • Self IP defined for this network and it is working for other subnets as well
  • It is an intermittent issue, sometimes it works and sometimes it doesn't, packet is capture while issue occurs:
    IP 10.10.10.20.41834 > 192.168.1.20.443: Flags [S], seq 1741324170, win 65535, options [mss 1300,sackOK,TS val 849372768 ecr 0,nop,wscale 9], length 0
    IP 10.36.158.43 > 10.10.10.20: ICMP host 192.168.1.20 unreachable - admin prohibited filter, length 36
    IP 10.10.10.20.41834 > 192.168.1.20.443: Flags [S], seq 1741324170, win 65535, options [mss 1300,sackOK,TS val 849373785 ecr 0,nop,wscale 9], length 0
    IP 10.36.158.43 > 10.10.10.20: ICMP host 192.168.1.20 unreachable - admin prohibited filter, length 36
    IP 10.10.10.20.41834 > 192.168.1.20.443: Flags [S], seq 1741324170, win 65535, options [mss 1300,sackOK,TS val 849375801 ecr 0,nop,wscale 9], length 0

Cause

block-idle-timeout is set with large value for timeout.

list /security nat source-translation all-properties
security nat source-translation Pool_BackEnd {
    addresses {
        10.10.10.20%1 { }
    }
    egress-interfaces {
        /Common/Internet
    }
    egress-interfaces-enabled enabled
    hairpin-mode disabled
    inbound-mode none
    mapping {
        mode address-pooling-paired
    }
    pat-mode napt
    port-block-allocation {
        block-idle-timeout 3600    <<<<< The default value is 360s,  for 3600s it will wait for too long
        client-block-limit 1
    }
    ports {
        1-65500 { }
    }
    type dynamic-pat
}

Recommended Actions

Change the security nat source-translation back to the Default value (360 seconds).
 

  • On the Main tab, click: Security -> Network Address Translation -> Policies.
    The Policies screen opens..
    • Block Idle Timeout - Configures the idle time period, after the last connection using the block has completed, that block assignment expires. The default value is 360 seconds.
