K000092819: Initial SSL Handshake attempt fails with the "Internal Error (80)"

Type
Support Solution
Published
2023-02-16
Updated
2023-02-16
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000092819

Description

This article describes an issue with the SSL Handshake where the following errors can be seen.
 
  1.  var/log/ltm:
    Nov 2 09:02:20 pyxb5c6 warning tmm2[13476]: 01260009:4: Connection error: ssl_hs_rsacertvfy:6074: ssl_hs_rsacertvfy (80)
    Nov 2 09:02:20 pyxb5c6 warning tmm2[13476]: 01260013:4: SSL Handshake failed for TCP 10.1.1.1%10:63085 -> 10.2.2.2%10:443
     
  2. Packet capture:
Transport Layer Security
  TLSv1.2 Record Layer: Alert (Level: Fatal, Description: Internal Error)
    Content Type: Alert (21)
    Version: TLS 1.2 (0x0303)
    Length: 2
    Alert Message
      Level: Fatal (2)
      Description: Internal Error (80)
 
Environment
  • BIG-IP LTM
  • HTTPS virtual server
  • Client SSL profile with client authentication configured
     
Cause
This issue could be caused by the client's SSL private key itself having invalid RSA parameters.

Recommended Actions
Verify if the client's private key is valid with the following command.
​​​​​​​
# openssl rsa -in client.key -check

The correct output will show "RSA key ok". If the key is invalid, however, it will show an error. In that case, you should replace the SSL private key along with the certificate.
