Topic

This article describes TMOS Shell (tmsh) output behavior when displaying the Link Aggregation Control Protocol (LACP) SysID.

Description

On a multi-bladed VIPRION, the LACP Partner SysID is not displayed in trunk or vlan tmsh output on blades that do not have an interface configured in the trunk.

The following example shows a trunk configured on blades 1 and 2:

net trunk example_trunk {
    interfaces {
        1/1.0
        2/1.0
    }
    lacp enabled
    lacp-mode active
}

Blades 1 and 2 display the LACP Partner SysID in tmsh output:

  --------------------------------------------------------
  | Net::LACP Status (trunk: example_trunk)
  --------------------------------------------------------
  |                      SysID  Key  Priority
  | Actor    00:00:5e:00:53:FF    1     41472
  | Partner  00:00:5e:05:05:05  104     32768

Blades 3 and 4 do not display the LACP Partner SysID in tmsh output:

  --------------------------------------------------------
  | Net::LACP Status (trunk: example_trunk)
  --------------------------------------------------------
  |                      SysID  Key  Priority
  | Actor    00:00:5e:00:53:FF    1     41472
  | Partner               none    0         0

This is expected behavior and there is no negative impact. The LACP Partner SysID displayed for a given trunk is based on a value received on the physical interface connection on the given blade.
