Known Issue

The BIG-IP system may fail to perform an incremental synchronization to its device group peers. This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to perform incremental synchronization, instead of full synchronization, for a device group.

    Note: This is the default setting in BIG-IP 11.4.0 and later.

  • You have modified an existing iApp application service.

    For example, this condition can occur if you remove a profile from the iApp application service or select a different profile for the iApp application service.

Impact

The BIG-IP system is unable to perform an incremental synchronization to its device group peers.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H518147 on the Diagnostics > Identified > Low screen.
  • The configurations between the members of the affected device group are not consistent.
  • After removing a profile from your application service, you notice that the members of the affected device group receive incremental synchronization log error messages, similar to the following example, in the /var/log/ltm file:

    01070265:3: The Web Accelerator Profile (/Common/example.app/example_optimized-caching) cannot be deleted because it is in use by a virtual server profile (/Common/example.app/example_vs /Common/example.app/example_optimized-caching).
    01071488:3: Remote transaction for device group /Common/mydevicegrp to commit id 441 6065986147531919417 /Common/bigip1.local 0 failed with error 01070265:3: The Web Accelerator Profile (/Common/example.app/example_optimized-caching) cannot be deleted because it is in use by a virtual server profile (/Common/example.app/example_vs /Common/example.app/example_optimized-caching)

  • After selecting a different profile for your application service, you notice that the members of the affected device group receive incremental synchronization log error messages, similar to the following example, in the /var/log/ltm file:

    0107149e:3: Virtual server /Common/example.app/example_vs has more than one clientssl/serverssl profile with same server name.
    01071488:3: Remote transaction for device group /Common/mydevicegrp to commit id 262 6065961322959627342 /Common/bigip1.local 0 failed with error 0107149e:3: Virtual server /Common/example.app/example_vs has more than one clientssl/serverssl profile with same server name.
    01070097:3: Virtual server /Common/example.app/example_vs lists duplicate profiles.
    01071488:3: Remote transaction for device group /Common/mydevicegrp to commit id 263 6065947784393289275 /Common/bigip1.local 0 failed with error 01070097:3: Virtual server /Common/example.app/example_vs lists duplicate profiles.

Workaround

To work around this issue, you can disable incremental synchronization for the device group. Disabling incremental synchronization for the device group causes configuration synchronization (ConfigSync) to perform a full configuration synchronization each time a ConfigSync is performed. You can disable incremental synchronization by setting the device group full-load-on-sync setting to true, and setting the auto-sync setting to disabled. To do so, perform the following procedure:

Impact of workaround: BIG-IP system performance may be affected when ConfigSync performs a full configuration synchronization for a large configuration.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Disable incremental synchronization by using the following command syntax:

    modify cm device-group <device_group_name> auto-sync disabled full-load-on-sync true

    For example:

    modify cm device-group my_devicegroup auto-sync disabled full-load-on-sync true

  3. Save the change by typing the following command:

    save /sys config

Subsequent ConfigSync operations will perform a full configuration synchronization.
