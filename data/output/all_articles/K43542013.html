K43542013: NGINX returns status '400 Request Header Or Cookie Too Large' or '414 Request-URI Too Large'

Type
Support Solution
Published
2020-01-15
Updated
2025-04-02
Applies to
  • NGINX Products
  • NGINX Plus: R20, R19, R18, R17, R16, R15, R14, R13
Source
https://my.f5.com/manage/s/article/K43542013

Description

  • NGINX returns 400 or 414 status to the browser.
  • NGINX writes one of the following messages to the error.log file:

    2019/12/13 01:37:34 [info] 21004#21004: *7 client sent too long header line:
    2019/12/13 01:36:24 [info] 20703#20703: *114 client sent too long URI while reading client request line, client: 10.0.0.1, server: , request:

Environment

  • NGINX Plus

Cause

NGINX allocates in-memory buffers for URI and headers of the request. If the request overflows, these buffers NGINX returns special status codes.

Recommended Actions

  1. Add the large_client_header_buffers 4 16k; directive to the http section of /etc/nginx/nginx.conf file.
  2. Reload the nginx process by entering the following command: 

    sudo nginx -t && sudo service nginx reload

  3. If these steps do not work, double the value of the second parameter of the large_client_header_buffers directive and reload NGINX again.

Note: NGINX may allocate these buffers for every request, which means each request may use up to 'number of buffers' * 'size of single buffer' amount of memory.

Additional Information

  • Module ngx_http_core_module - large_client_header_buffers
  • If the Recommended Actions does not help to resolve the issue then add directive client_header_buffer_size 64k; to the http context within the /etc/nginx/nginx.conf file and restart NGINX:  sudo nginx -t && sudo systemctl restart nginx.service
  • Module ngx_http_core_module - client_header_buffer_size
