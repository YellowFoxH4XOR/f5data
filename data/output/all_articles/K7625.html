K7625: iRule command ONECONNECT::reuse disable does not work within the HTTP_REQUEST event

Known Issue

This is the result of a known issue. The ONECONNECT::reuse disable iRule command is intended to prevent the current connection from being included in the OneConnect connection pool. When invoked in a server-side context, such as the HTTP_RESPONSE iRule event, the command works as expected, and the server-side connection is not reused. However, when invoked in a client-side context, such as the HTTP_REQUEST iRule event, the command does not prevent the connection from using a connection from the OneConnect connection pool, nor does it prevent any new connection that might be established from being included in the OneConnect connection pool to be reused.

F5 Product Development tracked this issue as CR63351 and it was fixed in BIG-IP version 9.1.3. Invoking the ONECONNECT::reuse disable iRule command in the client-side context now creates a new server-side connection that is not included in the OneConnect connection pool. For information about upgrading, refer to the BIG-IP LTM release notes.
