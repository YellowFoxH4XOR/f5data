Topic

You should consider using this procedure under the following condition:

  • You want to configure Data Guard to extend the buffer size for exception regular expression patterns beyond the matched buffer.

Description

Starting in BIG-IP ASM 11.2.0, the data_guard_exception_boundary_len parameter enables you to extend the buffer size for Data Guard Exception Patterns beyond the matched buffer. You can use the parameter to define the number of bytes, on each side of the matched buffer, that the BIG-IP ASM system extends the exception pattern, beyond the matched buffer itself. By default, this parameter's value is 0 bytes, meaning the Data Guard exception pattern is applied only on the matched buffer.

For example, assume you have the following string in the data:

The BIG-IP ASM system will mask this good example or this badexample, but not this bad example.

You configure the Custom Patterns setting for the Data Guard feature with the value example. The Data Guard feature will apply this pattern on the data and match all instances of the example string. If the Exception Patterns setting for the Data Guard feature is configured with the value bad\s (the word bad followed by a space), the Data Guard feature continues to match all instances of the example string, but does not exclude the last instance of the example string, even though the Exception Patterns setting for the Data Guard feature is configured with the bad\s value because the data_guard_exception_boundary_len system variable is set to a value of 0 (zero) by default. If the Mask Data setting is enabled in the Data Guard feature, the BIG-IP ASM system masks all instances of the example string and returns the following string to the client:

The BIG-IP ASM system will mask this good ******* or this bad*******, but not this bad *******.

If the data_guard_exception_boundary_len system variable is now set to a value of 4, the buffer for each match of the example string increases by four characters on either side (without the double quotes):

  • "ood example or "
  • " badexample, bu"
  • "bad example."

In this case, the Data Guard feature will match only the last entry "bad example." for the configured Exception Patterns setting. The BIG-IP ASM system then proceeds to mask only the first two entries and returns the following string to the client:

The BIG-IP ASM system will mask this good ******* or this bad*******, but not this bad example.

To configure Data Guard to extend the buffer size for exception regular expression patterns beyond the matched buffer, perform the following procedures:

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the BIG-IP ASM command line.
  • You have access to the Configuration utility.

Procedures

Configuring the Data Guard custom and exception patterns

Impact of procedure: The following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Security Policies.
  3. Click the relevant security policy.
  4. Click Data Guard.
  5. Select the Enabled check box next to Data Guard.
  6. Select the Enabled check box next to Custom Patterns.
  7. In the New Pattern box, type a PCRE regular expression to specify the sensitive data pattern, then click Add.

    For example, to assign a custom pattern that could be used to mask the word example in the data, type the following regex string:

    example
  8. Select the Enabled check box next to Exception Patterns.
  9. In the New Pattern box, type a PCRE regular expression to specify patterns in the data not to be considered sensitive, then click Add.

    For example, to assign exception patterns that could be used to not mask the word example if it is preceded by the word bad followed by a space, type the following regex strings:

    Note: By default, this setting is not active until the BIG-IP ASM system data_guard_exception_boundary_len variable is appropriately configured for your application requirements by performing the following Configuring the data_guard_exception_boundary_len parameter procedure.

    bad\s
  10. Select the Enabled check box next to Mask Data.
  11. Click Save.
  12. Click Apply Policy.

Configuring the data_guard_exception_boundary_len parameter

Impact of procedure: Restarting the BIG-IP ASM process temporarily interrupts traffic processing.

  1. Log in to the command line.
  2. Set the data_guard_exception_boundary_len parameter by using the following command syntax:

    /usr/share/ts/bin/add_del_internal add data_guard_exception_boundary_len <#_of_bytes_to_extend_exception_buffer>

    For example, if using the previous custom and exception pattern examples to not mask the word example if it is preceded by the word bad followed by a space, the data_guard_exception_boundary_len parameter would be set to 4, as follows:

    /usr/share/ts/bin/add_del_internal add data_guard_exception_boundary_len 4
  3. Restart the BIG-IP ASM system by typing the following command:

    bigstart restart asm
