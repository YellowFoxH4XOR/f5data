Issue

When the BIG-IP ASM system is unable to convert the character strings using the language encoding defined within the security policy, the BIG-IP ASM system reports the following error message:

Failed to convert character

The BIG-IP ASM Application Language setting specifies the default character encoding set for the web application. The language encoding determines how the security policy processes the character sets.

Recommended Actions

To work around this issue, disable blocking for the Failed to convert character setting. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Security >> Application Security :: name of the policy.
  3. Go to the Learning and Blocking Settings.
  4. Under General Settings uncheck Block for Failed to convert character.
  5. Save and Apply.

    Note: If the request is legitimate, verify that the site has the correct Application Language set or site encoding defined. Language localization may change this behavior. Language localization will serve a different language page, such as index.html.en, which may have a different encoding set for each page or language. It may be necessary to ensure that all pages are using the same encoding.

Verifying that the BIG-IP ASM system is using the correct language or encoding set

  1. Log in to the Configuration utility.
  2. Click Security >> Application Security :: name of the policy.
  3. Check the "Application Language".

Note: The Application language set in the policy cannot be changed. Also, a policy cannot be imported to replace a policy that uses a different encoding language

For more information about how to validate the encoding of your site, refer to K6335: Overview of encoding language settings for the BIG-IP ASM system.
