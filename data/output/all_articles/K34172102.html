Description

Rarely, for various reasons (environmental, software defect, etc.), a table in the logdb mysql database could become corrupted.  One symptom of such database corruption is a logmysqld process that constantly restarts, whith errors like the following appearing in /var/log/ltm:

bigip01 logmysqld[12345] Fatal error db.cpp:exec_query:150 LOCK TABLES log_data_current WRITE errno[145] strerror[Table './logdb/log_data_current' is marked as crashed and should be repaired]

Environment

  • At least one of the AFM, ASM, PEM, APM, or SWG modules is provisioned

Cause

Database corruption.

Recommended Actions

The log_data_current, log_data_0, log_data_1, log_data_2, and log_data_3 tables in the logdb database use the MyISAM database engine.  To repair one of these tables, use the myisamchk command after the mysqld daemon has been shut down.

Note: Stopping mysqld will take the BIG-IP offline, if it isn't already.

Log in to the CLI and do the following:

  1. cd /var/lib/mysql/logdb
  2. bigstart stop mysql
  3. myisamchk -r *.MYI
  4. bigstart restart

None.
