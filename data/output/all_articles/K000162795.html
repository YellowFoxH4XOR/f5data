K000162795: F5OS GUI is inaccessible after configuring an Allowed-IP entry without a port

Type
Support Solution
Published
2026-08-05
Updated
2026-08-05
Applies to
  • F5OS Products
  • F5OS-A: 1.8.4, 1.8.3
  • F5OS: 2.0.0
Source
https://my.f5.com/manage/s/article/K000162795

Description

F5OS GUI and management HTTPS access can become unavailable after an allowed-IP entry is committed without a port. The CLI accepts the incomplete configuration, and the resulting firewall rule uses port=0, which can remove default management access rules.

Relevant system log messages include:

Failed to find CDB component

COMPONENT="update_rule: port not configured"

Environment

  • F5OS-A 1.8.3
  • F5 rSeries system
  • system allowed-ips configuration
  • An allowed-IP entry containing an IPv4 address and prefix length without a port
  • SSH or CLI access may remain available while GUI and HTTPS access are unavailable

Cause

Bug ID 2442069

F5OS treats an allowed-IP entry without a port as equivalent to port=0. During firewall rule generation, this can delete the default management-service rules, including the HTTPS rule, resulting in loss of GUI access.

Recommended Actions

  1. Log in to the F5OS system through SSH, console access, or another available CLI method.
  2. Review the allowed-IP configuration:
    show running-config system allowed-ips allowed-ip
  3. Enter configuration mode:
    config
  4. Remove the affected portless allowed-IP entry:
    no system allowed-ips allowed-ip <affected-entry>
  5. Commit the change and exit configuration mode:
    commit and-quit
  6. Verify GUI and HTTPS access from each required management network.
  7. If the entry is required, recreate it with the intended management port explicitly specified, such as HTTPS port 443.
  8. Do not create or retain allowed-IP entries without a specified port until a software fix is available for Bug ID 2442069.
  9. If GUI access remains unavailable after removing the portless entry, collect current diagnostics and open a new support case for further investigation.

Additional Information

  • The F5OS CLI may accept an allowed-IP entry without a port even though the resulting configuration is invalid for firewall enforcement.
  • Explicit port=0 configuration is rejected by the CLI, but omitting the port can cause the value to be used internally.
  • Removing the affected portless entry restores GUI access when this defect is the cause.
  • Configure each allowed-IP entry with the required service port, such as HTTPS 443, SSH 22, HTTP 80, or another supported management-service port.
