Known Issue

This is the result of a known issue. The BIG-IP system incorrectly transitions a node or pool member to an unknown state when a user changes the object's status from Forced Offline to Enabled.

When a node or pool member state is unknown, the BIG-IP system considers the device available to receive traffic. As a result, if you change the status of the node or pool member from Forced Offline to Enabled, it is possible for the BIG-IP system to send connections to the device before the monitor has reported the correct status of the device.

For example, when you use the Configuration utility to change a node or pool member status to Forced Offline, or use the command line to change the status to Down, the BIG-IP system suspends monitor traffic to the node or pool member. When you subsequently use the Configuration utility to change the node or pool member status to Enabled, or to up using the command line, the BIG-IP system resumes monitoring the device; in addition, the BIG-IP system temporarily transitions the device's state to unknown because the monitor results are not yet available for the device. When monitoring results become available, the bigd process updates the node or pool member status depending on the health of the server. During the time that the node or pool member's status status is unknown, the BIG-IP system may incorrectly send connections to the device even though the health checks may ultimately fail.

Note: The BIG-IP command line utilities such as bigtop or bigpipe indicates the unknown state as checking. The Configuration utility indicates the unknown state as follows:

Unknown (Enabled) - Pool member service checking is enabled, but result is not available yet

F5 Product Development tracked this issue as ID 225957 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2, which has been issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
