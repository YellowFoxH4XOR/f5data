Description

After configuring the BIG-IP to log TCP RST packet you are seeing many following entries in /var/log/ltm:

  • <time stamp> <host name> <log level> err <tmm[pid]> 01230140:3: RST sent from <IP address:port number> to <IP address:port number>, <number> RST from BIG-IP internal Linux host

Environment

  • BIG-IP LTM
  • TCP RST logging enabled

Cause

TCP RST packet with reason "RST from BIG-IP internal Linux host" is sent when the BIG-IP system receives a RST acknowledgement (ACK) in response to terminating a service check.

The most common scenario when RST from BIG-IP internal Linux host is sent is when you use TCP half open monitor (it may be seen when using other monitor types as well). BIG-IP sends that reset to terminate the TCP session which was initiated to check the status of pool member. This is normal and expected behavior.

For example:

ltm monitor tcp /Common/<Monitor_name> {
    adaptive disabled
    defaults-from /Common/tcp
    destination *.1099
    interval 5               <==== interval 5 sec
    ip-dscp 0
    recv none
    recv-disable none
    send none
    time-until-up 0
    timeout 16
}

192.0.2.1 (BIG-IP Self IP) ---> 192.0.2.10 (Pool member)

No.     Time            Source          Destination     Prot    Leng   Info
53    15.647990    192.0.2.1    192.0.2.10    TCP    209    OUT s1/tmm1 : 32950 → 1099 [RST] Seq=2 Win=0 Len=0 [F5RST(peer): RST from BIG-IP internal Linux host]
67    20.775847    192.0.2.1    192.0.2.10    TCP    209    OUT s1/tmm1 : 26168 → 1099 [RST] Seq=2 Win=0 Len=0 [F5RST(peer): RST from BIG-IP internal Linux host]

Recommended Actions

  • This is normal and expected behavior. There's no reason to be concerned about that.
