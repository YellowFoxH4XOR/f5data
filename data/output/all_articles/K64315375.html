Description

Configuration failed to load after reboot or when restoring a UCS.

Errors similar to the following observed in /var/log/ltm:

err mcpd[5649]: 01070711:3: Caught runtime exception, 'Cannot get device index for tmm in rd1 - create socket failed: No such file or directory' - rolling back...
err mcpd[5649]: 01070734:3: Configuration error: MCPProcessor::initializeDB: Cannot get device index for tmm in rd1 - create socket failed: No such file or directory
err mcpd[5649]: 01070596:3: An unexpected failure has occurred, Cannot get device index for tmm in rd1 - create socket failed: No such file or directory - net/validation/routing.cpp, line 647, exiting...

Environment

  • Route domains
  • Configuration load

Cause

A Static Route exists that references a non-existent Route Domain.

Route domain in question was previously deleted, leaving the static route orphaned.

Note: It is valid behaviour to allow a route domain to be deleted when a static route references it, but the configuration load failure should not occur. This is tracked by bug ID 1079045.

Recommended Actions

Locate and delete the orphaned static route from the bigip.conf, then reload the configuration.

The error message references the route domain question. In the example given in the description of this article, route domain 1 no longer exists:

Cannot get device index for tmm in rd1

But this static route exists:

net route rd1-default-route {
    gw 10.2.2.2
    network default%1
}

Additional Information

This is not a hardware issue, despite the "Cannot get device index" errors; the issue is purely in software.
