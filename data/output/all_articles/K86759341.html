Topic

You can configure BIG-IP PEM to send subscriber usage data to a Policy and Charging Rules Function (PCRF) application during service delivery. BIG-IP PEM uses the Credit-Control-Request Update (CCR-U) message to notify the PCRF application when the subscriber usage threshold has been reached, and to send usage monitoring (UM) report information. This credit control communication occurs over the Gx interface.

BIG-IP PEM may send multiple CCR-U messages throughout the duration of a subscriber session, even if the PCRF application doesn't provide the Granted-Service-Unit (GSU) after each acknowledgment. Because some PCRF applications consider the additional CCR-U messages unnecessary, the following database variables (or keys) have been introduced to control how the BIG-IP PEM system manages the sending of CCR-U messages to PCRF applications:

  • tmm.pem.session.gx.reporting.disable.afterthreshold
  • tmm.pem.session.gx.reporting.immediate

Description

Beginning in BIG-IP 11.6.0, the tmm.pem.session.gx.reporting.disable.afterthreshold database variable was introduced to reduce the number of CCR-U messages BIG-IP PEM sends to the PCRF application. The database key allows the following options:

  • true: BIG-IP PEM sends a single CCR-U message to the PCRF application when a subscriber usage threshold has been reached, after receiving the GSU. The PCRF application must then indicate to BIG-IP PEM if UM will continue specifying a new GSU in the Credit-Control-Answer Update (CCA-u) message. This option is the default value.
  • false: BIG-IP PEM may send multiple CCR-U messages to the PCRF application throughout the duration of a subscriber session using the GSU specified in the Credit-Control-Answer Initialization (CCA-I) message, or in the CCA-u message if UM began later than the subscriber's initial configuration.

Beginning in BIG-IP 12.1.0, the tmm.pem.session.gx.reporting.immediate database variable was introduced to control when UM report information is sent to the PCRF application. The database key allows the following options:

  • true: BIG-IP PEM sends UM report information immediately after a subscriber usage threshold is reached.
  • false: BIG-IP PEM sends UM report information at periodic intervals. This option is the default value.

Modifying the database keys

Modifying the tmm.pem.session.gx.reporting.disable.afterthreshold database key

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To modify the tmm.pem.session.gx.reporting.disable.afterthreshold database key, use the following command syntax:

    modify sys db tmm.pem.session.gx.reporting.disable.afterthreshold value < true | false >

    For example, if you want BIG-IP PEM to continue to send CCR-U messages after a subscriber has reached the usage threshold, type the following command:

    modify sys db tmm.pem.session.gx.reporting.disable.afterthreshold value false
  3. To save the configuration, type the following command:

    save sys config

Modifying the tmm.pem.session.gx.reporting.immediate database key

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh
  2. To modify the tmm.pem.session.gx.reporting.immediate database key, use the following command syntax:

    modify sys db tmm.pem.session.gx.reporting.immediate value < true | false >

    For example, if you want BIG-IP PEM to send UM report information immediately after a subscriber usage threshold is reached, type the following command:

    modify sys db tmm.pem.session.gx.reporting.immediate value true
  3. To save the configuration, type the following command:

    save sys config
