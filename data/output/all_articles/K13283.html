Known Issue

The BIG-IP system may ignore a failed authorization response from a TACACS+ server.

This issue occurs when all of the following conditions are met:

  • Remote TACACS+ authentication was originally configured on BIG-IP versions 10.2.0 or 10.2.1.

    This issue will not occur if the remote TACACS+ authentication was originally configured on an earlier version, such as BIG-IP version 10.1.0, and then subsequently upgraded to BIG-IP 10.2.0.
  • The External Users Role is set to a value other than No Access.
  • A BIG-IP user successfully authenticates to a remote TACACS+ server.
  • The TACACS+ authorization phase fails.

When a user is allowed to connect to the BIG-IP due to this issue, they will receive whatever access level has been configured for the External Users Role value.

Impact

Users that have successfully completed TACACS+ authentication but have failed TACACS+ authorization will be allowed access.

Important: While a failed TACACS+ authorization phase should result in a failed login attempt, the users that are incorrectly granted access to the BIG-IP by this issue are only granted access if they first successfully authenticate to the TACACS+ server.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP iHealth lists Heuristic H337871 on the Diagnostics > Identified > Low screen.
  • Users that fail TACACS+ authorization will be granted access to the BIG-IP if they successfully authenticate.

    To confirm if a given user is failing TACACS+ authorization you can inspect the TACACS+ Reply packet sent from the server. A server reply packet for a failed authorization will contain strings similar to the following example:

    Type: Authorization (2)
    Auth Status: 0x10 (FAIL)

    Note: In order to examine the reply packet, you will need to use a packet inspection tool such as tcpdump. For more information on troubleshooting with tcpdump, refer to the Supplemental Information section.  For information on auditing and configuring authorization on the TACACS+ server, consult the documentation provided from your vendor.

Workaround

To work around this issue, you can set the Role for External Users to No Access, or alter the TACACS+ server configuration. To do so, perform one of the following procedures:

Impact of workaround: Any legitimate user who successfully connects to the BIG-IP system but does not have a role defined will be denied access. For more information about this configuration option, refer to the Managing User Accounts chapter of the TMOS Management Guide for BIG-IP Systems.

Denying access to undefined External Users

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > Users > Authentication.
  3. In the External Users section, change the Role value to No Access.
  4. Click Update.

TACACS+ configuration

One possible cause of authorization failure is that a user may have no authorization defined in the TACACS+ configuration file. In this case, you may be able to work around the issue by correctly defining authorization for affected users.
