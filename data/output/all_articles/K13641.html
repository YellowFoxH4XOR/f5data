Known Issue

The BIG-IP system may incorrectly consider certain pool members to be unavailable if the pool is being modified under conditions of heavy load.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is processing a high volume of traffic
  • A load balancing pool or gateway pool is modified at the same time a member of that pool is selected by TMM to receive a connection

    A pool member may be affected if it is subject to any of the following operations:
    • Adding, removing, or otherwise modifying the settings for a pool member
    • Merging a configuration file (using either the bigpipe merge or the tmsh load sys config merge command)

This issue is the result of a race condition that may occur if a pool member is picked to receive traffic while the operation to modify that member is still active in mcpd. The BIG-IP system treats the affected member as if it has reached its connection limit, even if no connection limit is defined. A pool with a larger number of members may be more likely to have one of its members become subject to the race condition.

Impact

  • Load balancing pool

    No connections will be routed to the pool member.
  • Gateway pool

    All connections to subsequent resources reached using the gateway pool member may be dropped.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Available pool members receive no connections, resulting in uneven traffic distribution
  • New connections may be terminated by a TCP RST from the BIG-IP system
  • Pool member availability may intermittently alternate between up and down, and the system may write corresponding messages that appear similar to the following examples to the /var/log/ltm file:

    01070638:5: Pool member 10.10.10.1:80 monitor status down.
    01070727:5: Pool member 10.10.10.1:80 monitor status up.
    01070638:5: Pool member 10.10.10.1:80 monitor status down.

  • If an iRule is used to load balance connections for the affected pool, LB_FAILED events may be logged to the /var/log/ltm file

Workaround

To work around this issue, you can mitigate its effects by performing the following procedures:

Restart Services

Impact of workaround: Restarting services will result in a brief traffic disruption.

While there is no direct workaround to prevent this issue, you can mitigate the effect by briefly restarting BIG-IP services after making modifications to pool members as described in the previous Description section. If a pool member has become affected, the BIG-IP system will mark it as having reached its connection limit. Restarting services will remove this internal flag on the pool member, and make it available for connections. To restart services, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Run the following command:

    bigstart restart

Limit the chances of the condition occurring

You can limit the chances of this issue occurring by doing one of the following:

  • High Availability

    Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

    If the device is part of a high availability pair, you can make the changes to the pool members on the standby device and then force that device to the active state.
  • Stand-Alone

    Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

    In a stand-alone deployment, you can limit the chances of this condition occurring by only making the changes to pool members described in the previous Description section during periods of low system traffic, such as a maintenance window or off-hours.

Configure static routes

Impact of workaround: This change in design may not be compatible with the requirements of your specific environment.

In the case of affected gateway pool members, a static route can be configured to the desired network objects instead of using a gateway pool. This may require a topology change that is beyond the scope of this article. For additional documents that will assist in this process, refer to the following Supplemental Information section.
