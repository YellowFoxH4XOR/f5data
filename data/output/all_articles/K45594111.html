Description

You observe that ASM logs an illegal or blocked violation for a percent % meta character appearing in a request that is URL-encoded.

Here is an example request:

GET /Home?t=prod&errmsg=Invalid%252520Login HTTP/1.1

In this example, a space character has been encoded three times.

%252520 --> %2520 --> %20 --> ' '

You observe from the request log that the violation occurs after a single decoding pass, and the parameter value will show as:

Invalid%2520Login

You expect that the final, decoded request would be evaluated for illegal meta characters, not the encoded request.

Environment

  • Security policy
  • Meta characters

Cause

This is expected behaviour.

ASM does a single decoding pass, enforces the security policy on the output and then does further decoding passes to detect whether there is a multiple decoding violation.

Recommended Actions

Since there is still a percent % meta character in the request after a single decoding pass, this meta character must be allowed by the policy to prevent a false positive violation.

The meta character can be configured as allowable at the parameter level. Refer to the following article for more information:

  • K11533467: How to allow a specific meta character being blocked by illegal meta character in value violation
