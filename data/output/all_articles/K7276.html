Known Issue

ServerSSL session information is not stored, preventing SSL sessions from resuming. The SSL connection information is partially inserted into the cache, which does not include the SSL session information. This prevents performing session lookups and allowing an SSL session to resume without having to perform a key exchange. As a result, each new connection must perform the SSL key exchange, instead of using the less intensive and faster SSL-resume method.

F5 Product Development tracked this issue as CR76765 and it was fixed in BIG-IP LTM 9.3 and 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.
