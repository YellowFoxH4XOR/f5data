K000132273: Unable to upload QKView to iHealth site via BIG-IP console

Type
Support Solution
Published
2023-03-22
Updated
2023-03-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.2
Source
https://my.f5.com/manage/s/article/K000132273

Description

  • When you want BIG-IP to upload the QKView directly to the iHealth site, basically, BIG-IP uses the TMM default routing to access the website unless you have a specific management route to go to the website.
  • BIG-IP has the TMM route metric higher than the management route.

Environment

  • LTM

Cause

  • BIG-IP is using the TMM route to the iHealth website, and your system might block a BIG-IP request.

Recommended Actions

  • Add a management static routing to access api.f5.com via the management interface

 

tmsh create /sys management-route <name> network <destination network>/<netmask> gateway <management gateway>

 

  • For example 

tmsh create /sys management-route api-f5 network 104.209.104.0/21 gateway 172.16.1.254

 

Note: If the destination specified in the management route is not directly connected to the management interface, then the entry will not be included into the routing table. The BIG-IP Configuration utility would display a warning to the effect.

  • For the destination network of F5 hosted services, please refer to this article K15202: IP addresses for F5 hosted services

Additional Information

  • You can verify your routing metric by using the command IP route
  • For example

ip route

default via 192.168.1.254 dev External 
default via 172.16.1.254 dev mgmt metric 4096  mtu 1500
  • We can see a default route for management has a metric 4096, which is a lower priority than the TMM route. Then, BIG-IP uses the TMM route to go to the internet instead management route.
  • This also applies to DNS/NTP traffic if you want to use a management address to query a DNS record/NTP traffic. You have to create a management route for DNS/NTP traffic.
