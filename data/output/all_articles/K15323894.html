Topic

You should consider using this procedure under the following condition:

  • You want to troubleshoot BIG-IP APM RSA SecureID AAA user authentication issues.

Description

There are three areas to consider when troubleshooting this issue:

  • The client device
  • The BIG-IP APM system
  • The SecureID RSA server

To get a better understanding of the issue, you should gather the logged client behavior accessing the BIG-APM system, communication between the BIG-IP APM system and the RSA server, and the logged output from the RSA server.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the Configuration utility or the TMOS Shell (tmsh).
  • You have access to the RSA Authentication Manager security console.
  • You are able to reproduce the authentication issue.

Procedures

To collect data required for troubleshooting RSASecureID AAA authentication issues, perform the following procedures:

  • Enabling APM debug logging on the BIG-IP APM system
  • Enabling detailed error logging of the RSA server authentication attempt
  • Collecting data from the BIG-IP APM system while reproducing the issue
  • Opening a support case and uploading collected data

Enabling APM debug logging on the BIG-IP APM system

To enable debug logging on the BIG-IP APM system, refer to the appropriate procedure for your system version in K45423041: Enabling APM debug logging

Enabling detailed error logging on the RSA server for the authentication attempt

Perform the following steps to set up initial data gathering on the RSA Authentication Manager (Security Console):

Important: You should consult your RSA authentication mangers administrators guide and other RSA documentation for version-specific steps.

  1. Log in to the the RSA Authentication Manager Security Console and navigate to Reporting > Real-Time Activity Monitor > Authentication Activity Monitor.
  2. Click Authentication and Starts with, and type the hostname of your authentication agent.
  3. Click Start Monitor.

Collecting data from the BIG-IP APM system while reproducing the issue

Perform the following steps to reproduce the issue and capture the debug logs from the BIG-IP APM system:

 

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, performing the tail of the logs or tcpdump for excessive amounts of time can use up system resources and cause poor performance.

  1. Log in to the root account with two bash sessions on the BIG-IP APM system.
  2. In the first session, send the live BIG-IP logs to a file using the following command syntax:

    tail -f /var/log/apm > /var/tmp/<example_filename.txt>

    For example:

    tail -f /var/log/apm > /var/tmp/rsaApmLogs.txt

  3. In the second session, start tcpdump using the following command syntax:

    tcpdump -ni 0.0:nnn -s0 host <IP Address of RSA server> -w /var/tmp/<example_tcpdump.pcap>

    For example:

    tcpdump -ni 0.0:nnn -s0 host 192.0.2.2 -w /var/tmp/RSA-AUTH_Serverside-capture.pcap

  4. Reproduce the issue by having a user connect to the BIG-IP APM system and attempt to authenticate using RSA Authentication. Note the SessionID of the test user.
  5. After the connection fails, stop the tail and tcpdump commands by pressing Ctrl + C.

     

  6. On the first console session, generate a Qkview file by typing the following command:

    qkview -s0

  7. Use WinSCP or another file utility to copy the logs and Qkview files saved in the /var/tmp directory from the BIG-IP system to your desktop.
  8. Return the log levels to their default setting. For more information, refer to K45423041: Enabling APM debug logging
  9. On the RSA Real-Time Authentication Monitor, capture the resulting error information, and note the result.

Opening a support case and uploading collected data

To open a support case with F5 technical support, or to register for WebSupport access, you must have an active support contract and you must be authorized to open support cases against that contract. If you are an end-user of an F5 product or client application, such as the Edge Client for IOS, the Edge Client for Android, or the Firepass controller, and you require technical support, contact your system administrator or IT department for assistance.
