Known Issue

This is the result of a known issue. Even when the logs are set to roll to prevent the /var/log partition from becoming full, the partition may still report that it is full and new logs may not be generated. This issue occurs because the module responsible for rolling the log files keeps the file handles open to the /var/log/rewrite* files and never releases it. When the log files are rolled or deleted, the space occupied by the file is not returned to the file system. As a result, the file system for the /var/log partition becomes full and is unable to continue writing to the files in the partition.

F5 Product Development is tracking this issue as ID 226731.

Workaround

To temporarily resolve the issue, you can clean up the file system in the /var/log/ partition by executing the bigstart restart rewrite command from the command line. However, executing this command will affect active traffic and should be performed during off peak usage, if possible. You may need to execute this command on a weekly or monthly basis, depending on how many logs are generated on your deployment. It is advisable to review your logging options to ensure that you are only logging the information that you need and use. By lowering your logging options, you will not need to clean the file system as frequently.
