Known Issue

The Traffic Management Microkernel (TMM) produces a core file when the BIG-IP system performs compression.

This issue occurs when all of the following conditions are met:

  • You are running a BIG-IP iSeries or VIPRION 4400 Series platform.
  • One or more virtual servers are performing data compression.

Impact

The BIG-IP system temporarily fails to process traffic while the TMM process restarts. If you configured the BIG-IP system for high availability (HA), the system fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file to the /shared/core/ directory.
  • The BIG-IP system logs messages in the /var/log/tmm file similar to the following example:

    notice panic: ../codec/compress/compress.c:1161: Assertion "context active" failed.
    notice ** SIGFPE **

  • The BIG-IP system fails to process traffic, or if you configured it for HA, it fails over to a standby system.

Workaround

To work around this issue, you can configure the BIG-IP system to perform compression in only the software. To do so, perform the following procedure:

Impact of workaround: Performing all compression in the software may increase CPU usage on your system.

  1. Log in to the BIG-IP Advanced Shell (bash).
  2. To enable only software compression, type the following command:

    tmsh modify /sys db compression.strategy value softwareonly
