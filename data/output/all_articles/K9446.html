Known Issue

This is the result of a known issue. Beginning in BIG-IP version 9.4.2, the bigpipe config install command no longer accepts relative pathnames when installing UCS archives from a directory other than the /var/local/ucs default archive directory.

For instance, if you are in the /var/tmp directory, which contains the UCS archive you want to install, running the bigpipe config install command from the directory containing the archive will fail with an error message that appears similar to the following example:

[root@bigip:Active] tmp # bigpipe config install test
Saving active configuration...
...
/var/local/ucs/test.ucs: File not found
Config install aborted.
BIGpipe parsing error:
01020001:3: The requested operation failed.

The bigpipe utility assumes the default directory, and the file is not found at that location.

Specifying a relative path also fails:

[root@bigip:Active] tmp # bigpipe config install ./test
Saving active configuration...
...
/var/local/ucs/./test.ucs: File not found
Config install aborted.
BIGpipe parsing error:
01020001:3: The requested operation failed.

F5 Product Development is tracking this issue as CR82160.

Note: This issue does not affect the BIG-IP version 10.x software branch.

Workaround

To work around this issue, specify the absolute pathname for the UCS archive file when running the bigpipe config install command, using the following syntax:

bigpipe config install <path><UCSfilename>

For example, to install an archive from the /var/tmp directory from within the /var/tmp directory, you would type the following command:

bigpipe config install /var/tmp/test
