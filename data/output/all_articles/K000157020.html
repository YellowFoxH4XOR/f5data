K000157020: SNMP response sometimes provide the incorrect value for some OIDs such as ltmVirtualServStatClientBytesIn or ltmVirtualServStatClientBytesOut

Type
Support Solution
Published
2025-10-15
Updated
2025-10-15
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000157020

Description

Intermittent abnormal SNMP statistics values may occur on BIG-IP LTM systems. SNMP queries for OIDs such as ltmVirtualServStatClientBytesIn or ltmVirtualServStatClientBytesOut can return values that unexpectedly drop, spike, or report negative deltas, even though these counters should always increase. This may result in SNMP workstation displaying incorrect traffic statistics. Packet captures and debug logs confirm that the SNMP responses from BIG-IP contain incorrect statistical values.

Environment

  • BIG-IP
  • SNMP monitoring with frequent polling intervals (e.g., every 15–30 seconds)
  • Large number of objects, like hundreds of virtual servers or more.

Cause

This issue is caused by delayed statistics merging in the mcpd process. Under high control plane load—such as frequent SNMP queries may fail to update in a timely manner, resulting in negative deltas, sudden spikes, or drops in reported values. This behavior is documented in Bug ID 499348 and Knowledge Article K21811305: Intermittent abnormal SNMP statistics values on BIG-IP LTM systems.

Recommended Actions

Apply the workaround in K21811305: Intermittent abnormal SNMP statistics values on BIG-IP LTM systems to mitigate the issue.

Additional Information

  • Consider increasing the SNMP polling interval (e.g., to one minute or longer) if possible.
  • For performance troubleshooting needs after applying this workaround, we can investigate it case by case.
