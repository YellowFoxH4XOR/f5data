Known Issue

This is the result of a known issue. The BIG-IP GTM system allows some objects to be created that contain parentheses within the name. However, the use of parentheses within the name of a BIG-IP GTM object causes the following unexpected behavior:

  • After an object with parentheses in its name has been created, the contents of the object will not display. This issue affects BIG-IP GTM pools, links, servers, and data centers.

    For example, if you create a pool called MyPool(Test), add some members, click on the pool, and then click the Members option, no members will display.

    Note: iRule names that contain parentheses cause the system to stall when attempting to save. If this occurs, click cancel. Monitor names are not affected—the system will report an error if you attempt to save a monitor that contains parentheses within the name.

  • Using the Manage button to add members to the pool will cause the Configuration utility to display the pool name incorrectly. The Configuration utility will either truncate the pool name by removing anything within the parentheses and only display pool as the name MyPool, or display #this.name#. In addition, any attempts to save the added members will result in an error message indicating that the pool does not exist or the pool member must contain a pool name.

    For example, when adding pool members to a pool, the following will display on the menu bar:

    Global Traffic ›› Pools : Pool List ›› #this.name#
    Error reported when attempting to add pool member 10.10.1.100:80 to MyPool(Test) for which the system is displaying as #this.name#:
    01070225:3: Pool Member 10.10.1.100 must contain Pool Name

F5 Product Development is tracking this issue as ID 341087 and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

To prevent this behavior, do not use parentheses when naming objects. Remove existing objects that contain parentheses in their name, and recreate and rename the objects.
