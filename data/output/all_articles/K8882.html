K8882: Using NTLM authentication and the ARX Secure Agent as a workaround when clients are not in the same domain as the back-end filer

Topic

Using solely Kerberos authentication, several situations may occur that are either unsupported by Microsoft Windows or by the ARX system.

For example, Forest-to-Forest trusts were introduced in Microsoft Windows 2003. If a Windows 2000 filer exists outside of the Active Directory Forest that is relevant to the client, the Domain Controller cannot issue a useful ticket to that client for authentication with that filer. This situation has been known to occur with migrations from Windows 2000 environments to Windows 2003 environments.

In general, any time that the Domain Controller of the client cannot issue a Kerberos ticket that is useful to the client or to the filer, NTLM authentication and the F5 ARX Secure Agent software must be utilized to allow the client to authenticate with the filer.

Note: Newer versions of Windows, such as Windows Server 2008 and Windows 7, use NTLMv2 as the default fallback from Kerberos authentication. Support for NTLMv2 by the ARX Secure Agent was introduced in ARX version 5.1.0. You may download the most recent version of the ARX Secure Agent software from the F5 Downloads site.

Note: For more information, refer to K9298: Defining NTLM authentication servers and adding them to a namespace.

Note: When staging a migration from Windows 2000 to Windows 2003, NTLM authentication may be proactively implemented temporarily in order to avoid potential issues until the migration is complete. For assistance in planning a smooth migration, contact F5 Professional Services for a consultation.

Important: Associating the first NTLM authentication server with a namespace requires temporarily disabling the namespace. If there are currently no NTLM authentication servers associated with the namespace, adding an NTLM authentication server will cause a temporary service interruption while the namespace must be disabled.
