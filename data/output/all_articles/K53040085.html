Description

Sometimes its necessary to move a Virtual Server's Virtual Address (aka it's Destination Address) from one Traffic Group into another Traffic Group. For example, the BIG-IP APM (Access Policy Manager) Module requires that all Virtual Servers with APM Access Profiles assigned reside in the same single Traffic Group. Spreading them out over more than one Traffic Group is NOT supported.

Environment

  • BIG-IP with 2 or more Traffic Groups configured.

Cause

The need to move a Virtual Server's Virtual Address from one Traffic Group to another. 
And in the case of APM Enabled Virtual Servers, all Virtual Servers with an Access Profile assigned MUST reside in the same Traffic Group as all the Virtual Servers with an Access Profile assigned. This is a requirement of the APM (Access Policy Manager) Module. 

Recommended Actions

To move a particular Virtual Server's Virtual Address to a different Traffic Group, follow the below instructions.

  1. Navigate to Local Traffic >> Virtual Servers >> Virtual Address List, and select the Virtual Address for the Virtual Server that needs to be moved.
  2. Select the appropriate Traffic Group from the Virtual Address's Traffic Group drop-down selector.
  3. Click the Update button to save the change. 
To move a group of or all Virtual Server's Virtual Address to a different Traffic Group, follow the below instructions:
  1. Open a CLI/SSH connection to BIG-IP
  2. Start a TMUI transaction: (/Common)(tmos)# create cli transaction
  3. Move one Virtual Server's Virtual Address to a different to the desired traffic group: 
    (/Common)(tmos)# modify ltm virtual-address 192.0.2.1 traffic-group <desired_traffic_group>
    After the command above is run, it should output:
    Command added to the current transaction
  4. Repeat the step #3 above as many times as necessary.
  5. Then, commit the transaction: (/Common)(tmos)# submit cli transaction
