Description

This articles provides step-by-step instructions for downgrading the big3d agent on BIG-IP LTM or DNS devices. The big3d agent is critical for GTM/DNS monitoring and communication.

Environment

  • BIG-IP DNS
  • BIG-IP LTM

Cause

Downgrading may be required to resolve compatibility issues after an upgrade. The big3d agent is designed to be backwards compatible, and generally there is no need to downgrade it, even after reverting back to a previous boot location. 

Refer to article K13703 regarding big3d versioning requirements.

Answer/Recommended Actions

  • Identify the Desired big3d Version
    • The native big3d version for each software volume is located in /shared/bin/big3d.
    • To revert to the version native to the currently booted software volume, follow the steps below.
  • Remove the Upgraded big3d Binary
    • On the target BIG-IP device, delete the /shared/bin/big3d file: 
      rm /shared/bin/big3d
    • This action forces the system to use the big3d version native to the software volume you are booting into.
  • Restart big3d
    • After deletion, restart the big3d process to ensure the native version is active.
    • You can check the new big3d version on the LTM device by using the bash command 
      big3d -v
  • (Optional) Re-install a Specific big3d Version
    • If you need to install a particular big3d version, use the big3d_install utility from a GTM/DNS device running the desired version: 
      big3d_install <BIG-IP_IP_address>

Additional Information

Note: big3d_install will not downgrade big3d if the target device already has a newer timestamp. In such cases, manual deletion as above is required.
