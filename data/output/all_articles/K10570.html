K10570: The BIG-IP WebAccelerator may remove an Expires header from a response

Published
2009-09-30
Updated

Topic

When Intelligent Browser Referencing (IBR) is enabled for the BIG-IP WebAccelerator acceleration policy, the BIG-IP WebAccelerator will remove an Expires HTTP header from a response if the header contains an expired date. The BIG-IP WebAccelerator will forward the Expires header if the date has not expired. This behavior is expected.

For more details, refer to the following examples:

The following response for an IBR enabled image file from an OWS contains an Expires header with an expired date:

HTTP/1.1 200 OK
Accept-Ranges bytes
Age 1742
Cache-Control max-age=259200
Connection Keep-Alive
Content-Length 1290
Content-Type image/gif
Date Wed, 14 Jan 2009 01:05:47 GMT
ETag "17c007-50a-4570fc4fec700"
Expires Fri, 24 Oct 2008 15:38:14 GMT   <--------- The expire date had expired
Keep-Alive timeout=15, max=100
Last-Modified Wed, 17 Sep 2008 04:19:08 GMT
Server Apache/2.2.8 (Ubuntu) PHP/5.2.4-2ubuntu5.1 with Suhosin-Patch

The Expires header is removed from the following BIG-IP WebAccelerator response to the client:

  HTTP/1.1 200 OK
  Accept-Ranges bytes
  Cache-Control private, s-maxage=14400
  Connection Keep-Alive
  Content-Length 1290
  Content-Type image/gif
  Date Wed, 14 Jan 2009 01:56:09 GMT
  ETag "pv9388dd2abd3c8cc93736b069c905829c"
  Last-Modified Wed, 17 Sep 2008 04:19:08 GMT
  Server Apache/2.2.8 (Ubuntu) PHP/5.2.4-2ubuntu5.1 with Suhosin-Patch
  X-PvInfo [S10201.C6784.A1952.RA0.G174E.U345871FF].[OT/images.OG/images]
  X-WAM-ORIG-CC private
  X-WAM-RC-MASQ On

The following response for an IBR enabled image file from an OWS contains an Expires header with an unexpired date:

HTTP/1.1 200 OK
Accept-Ranges bytes
Age 0
Cache-Control max-age=259200
Connection Keep-Alive
Content-Length 3239
Content-Type image/jpeg
Date Wed, 14 Jan 2009 00:36:45 GMT
ETag "17c00b-ca7-4570fe13f7180"
Expires Sat, 16 Oct 2009 00:49:33 GMT  <-------- The expire date is a future date
Keep-Alive timeout=15, max=99
Last-Modified Wed, 17 Sep 2008 04:27:02 GMT
Server Apache/2.2.8 (Ubuntu) PHP/5.2.4-2ubuntu5.1 with Suhosin-Patch

The Expires header is forwarded in the following BIG-IP WebAccelerator response to the client:

(Status-Line) HTTP/1.1 200 OK
Accept-Ranges bytes
Cache-Control private, s-maxage=14400, max-age=259200
Connection Keep-Alive
Content-Length 3239
Content-Type image/jpeg
Date Wed, 14 Jan 2009 01:56:09 GMT
ETag "pv3117a5165442d32f746c6bbc173b94c3"
Expires Sat, 16 Oct 2009 01:56:09 GMT
Last-Modified Wed, 17 Sep 2008 04:27:02 GMT
Server Apache/2.2.8 (Ubuntu) PHP/5.2.4-2ubuntu5.1 with Suhosin-Patch
X-PvInfo [S10201.C6784.A1952.RA0.G174E.U5B99A9C].[OT/images.OG/images]
X-WAM-ORIG-CC private, max-age=259200
X-WAM-RC-MASQ On

F5 Networks Product Development is tracking a request to forward an Expires header with an expired date as CR116037.
