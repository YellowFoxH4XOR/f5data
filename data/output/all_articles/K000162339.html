Known Issue

Usage of certain third-party modules can cause worker process segmentation faults resulting in degradation or stoppage of service.

This issue occurs when all of the following conditions are met:

  • You are running
    • NGINX Plus 37.0.3.1 LTS
    • NGINX Plus R36 P7
  • You have loaded and invoked any of the following third-party modules:
    • ngx_devel_kit (NDK) and any dependent modules, including the set-misc module (openresty/set-misc-nginx-module)
    • ngx_http_lua_module coupled with usage of the ndk.set.var function
    • ngx_postgres
    • ngx_log_if

Impact

Worker process terminates (segmentation fault). Affected worker processes terminate unexpectedly, causing dropped connections and degraded or interrupted service.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • NGINX worker processes terminates with a segmentation fault (SIGSEGV).
  • You observe error log entries similar to:
    [alert] #: worker process exited on signal 11 (core dumped)
  • Process termination correlates with request handling that invokes directives provided by the affected modules (for example, set-misc directives such as set_escape_uri, set_decode_base64, and so on).
  • The issue does not occur when the affected third-party modules are removed or disabled.

Workaround

To work around this issue, you can consider one or more of the following:

  • Roll back to a prior, unaffected NGINX version that predates NGINX Plus 37.0.3 or NGINX Plus R36 P7.
  • Disable or remove the affected third-party modules (e.g., set-misc, ngx_devel_kit, ngx_postgres, ngx_log_if) and refactor the configuration to avoid the directives they provide.

For guidance on official and dynamic third-party modules, see the NGINX Dynamic Modules documentation.
