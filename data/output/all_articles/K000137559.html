Description

BIG-IQ GUI is inaccessible after upgrade to v8.3 with the following message:

Waiting for BIG-IQ services to become available

 

Environment

BIG-IQ upgrade

Cause

Upgrade has not finished

Recommended Actions

BIG-IQ upgrades can vary from 1 hour to multiple hours depending on the number of nodes in the cluster and size of the database.

You can monitor the upgrade progress on the CM using 3 ssh sessions with the following commands running on each:

1. tailf /var/log/tokumon/current

2. while true; do date; psql -U postgres -d bigiq_db -c "select count(*) from bigiqauthorization.shared_authorization_journals;"; sleep 60; done

3. tailf /var/log/tokumon/current | grep percentComplete

 

Soon after booting to new volume you can access GUI to view upgrade preparation: 
Performing BIG-IQ database restore from /var/config/rest/bigiq_db.bin...
Deleting 'bigiq_db' database if exists...
No 'bigiq_db' database detected.
Restoring BIG-IQ database...

....

 

Once preparation is complete, you will be kicked out of GUI: Waiting for BIG-IQ services to become available....

 

The next phase is to rebuild the rbac database:

From ssh session 1:

[INFO] postgres_configurator: configurePostgresqlIsReady:readWriteReady. ready:true
[INFO] postgres_configurator: configurePostgresqlIsReady:replicationReady. ready:true
[INFO] postgres_configurator: configurePostgresqlIsReady:rbacReady. ready:false
[INFO] postgres_configurator: is db ready. dbIsReady:false
[WARNING] tokumon: isDBReady db is NOT ready.

 

 

There is not normally any need to perform rbac-reset as per K61023744. It is only required if this process stalls/fails.

The "count" value in ssh session 2 will progress to 0 eventually.
Note: You may see this count up at some point and this is completely normal. Please be patient during this process.

Once the rbac database is complete, the postgress percentComplete bar in ssh session 3 will increase towards 100% (only 98% will be visibly logged)

Once complete, the BIG-IQ GUI will be accessible again and the upgrade is finished.

Check the logs in ssh session 1 to see if there are any signs of error messages, such as in K51911667. Apply workaround if necessary.
