K000135987: Perform tcpdump for an intermittent pool member down issue by using alertd

Type
Support Solution
Published
2023-08-28
Updated
2026-07-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000135987

Description

  • Gathering packet capture for a pool member that went down at random times.
  • The alertd (user_alert.conf) may be suitable for other kinds of events too, especially when you want to collect something right after the specific log showing in /var/log/ltm.

Environment

  • BIG-IP LTM
  • Trigger a command when a specific log showing in the /var/log/ltm file. (For other log files, for example, /var/log/gtm, this article may not be suitable.)

Cause

  • Capture the required data (for example, a packet capture) after the specific log appears, instead of keeping it (tcpdump) running all the time.

 Recommended Actions

  • Edit the user_alert config file. (vi editor in this example.)
vi /config/user_alert.conf
  • Put the event that you would like to trigger iCall.
alert PoolDown "Pool (.*) member (.*) monitor status down" {
  exec command="tcpdump -nni 0.0 host 192.168.1.1 and port 8080 -C 5 -vw /var/tmp/TEST_ICALL_POOL_DOWN.pcap"
}
Note: In the above example, we use pool member 192.168.1.1:8080 and write a 5MB packet capture file.
  • Save the change.
:wq!
  • Test whether the iCall works or not.
logger -p local0.warning "TEST iCall - Pool /Common/TEST member /Common/MemberA monitor status down"
Note: The above example injects the log message into /var/log/ltm. (facility: local0.)
  • Check if the tcpdump is running or if the file is created.
ps -ef | grep tcpdump
or
ls -l /var/tmp/TEST_ICALL_POOL_DOWN.pcap
