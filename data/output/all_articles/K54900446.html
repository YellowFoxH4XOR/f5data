Topic

You should consider using this procedure under the following condition:

  • You want to configure BIG-IP ASM system resource alerts using the TMOS Shell (tmsh).

Note: For information about configuring BIG-IP ASM system resource alerts using the BIG-IP Configuration utility, refer to the Monitoring ASM System Resources chapter in the BIG-IP Application Security Manager: Implementations manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Description

Beginning in BIG-IP ASM 14.0.0, you can configure the ASM resource health monitor to send alerts when the system has exceeded the configured threshold. The alert messages can be sent over by way of specified methods including system log, SNMP, and email. The ASM resource alerts allow you to recognize the current system resource limitations as well as inform you of troubleshooting resource usage that impacts ASM performance.

The ASM system uses a list of variables to manage the resource monitoring. The variables that support resource monitoring are defined in the following table.

System VariableDescriptionDefault Value
tmm-cpu-usage-enableEnable this variable to monitor the average CPU usage for the TMM processes overall system cores. The TMM processes all load-balanced traffic on the BIG-IP system. Reaching maximum usage impacts system performance for all TMM-based processes, which results in a loss of network information.disabled
tmm-cpu-usage-thresholdThe threshold of the percent of CPU usage for TMM processes overall cores. The ASM alert is triggered when the set value is exceeded.85
total-cpu-usage-enableEnable this variable to monitor the average CPU usage for the entire system's overall system cores. Reaching maximum usage impacts system performance as a whole, and results in a loss of network information.disabled
total-cpu-usage-thresholdThe threshold of the percent of CPU usage for all system processes overall cores. The ASM alert is triggered when the set value is exceeded.90
asm-cpu-usage-enableEnable this variable to monitor the average CPU usage for the BD processes overall system cores. Reaching maximum usage impacts ASM performance, by preventing ASM policy enforcement.disabled
asm-cpu-usage-thresholdThe threshold of the percent of CPU usage for BD processes overall cores. The ASM alert is triggered when the set value is exceeded.85
asm-cpu-usage-per-vs-enableEnable this variable to monitor the average CPU usage for the ASM enforcer per virtual server. This can indicate that an application requires higher resource usage. Reaching maximum usage impacts the ASM performance for the virtual server's corresponding applications.disabled
asm-cpu-usage-per-vs-thresholdThe threshold of the percent of CPU usage for BD processes per virtual server. The ASM alert is triggered when the set value is exceeded.35
tmm-memory-usage-enableEnable this variable to monitor the average TMM memory usage out of the total memory provisioned for the TMM system. Reaching maximum usage impacts system performance for all TMM-based processes, which results in a loss of network information.disabled
tmm-memory-usage-thresholdThe threshold of the percent of  TMM memory usage out of the total memory provisioned for TMM processes. The ASM alert is triggered when the set value is exceeded.95
umu-memory-usage-enableEnable this variable to monitor the average UMU memory usage out of the total memory provisioned for the ASM enforcer. UMU memory is the internal memory used to process all ASM traffic, excluding XML traffic. High memory usage can result from unusually large requests. Reaching maximum usage impacts ASM performance.disabled
umu-memory-usage-thresholdThe threshold of the percent of UMU memory pool usage out of the total memory provisioned for BD processes, excluding XML traffic memory. The ASM alert is triggered when the set value is exceeded.90
xml-memory-usage-enableEnable this variable to monitor the average XML memory usage out of the total memory provisioned for the ASM enforcer. XML memory is the internal memory provisioned for an application that uses web services or XML. Reaching maximum memory usage impacts ASM performance for traffic associated with an XML profile.disabled
xml-memory-usage-thresholdThe threshold of the percent of XML traffic memory usage out of the total memory provisioned for BD processes. The ASM alert is triggered when the set value is exceeded.90
total-swap-memory-usage-enableEnable this variable to monitor the average swap memory usage for all system processes out of the total swap area. High swap usage can indicate that UMU or TMM memory has reached maximum usage. High system swap usage can impact system performance.disabled
total-swap-memory-usage-thresholdThe threshold of the percent of swap memory usage for all processes out of the total swap area. The ASM alert is triggered when the set value is exceeded.10
asm-swap-memory-in-mb-enableEnable this variable to monitor the average amount of swap (MB) usage for the ASM enforcer. ASM swap memory provides swap memory for the ASM enforcer until more system memory becomes available. Relying on swap memory for an extended period of time will affect the overall ASM performance.disabled
asm-swap-memory-in-mb-thresholdThe threshold of the swap memory used for BD processes (in MB). The ASM alert is triggered when the set value is exceeded.5
event-message-queue-usage-enableEnable this variable to monitor the percent of memory (out of the total memory for all queues) used for events that are waiting for the ASM enforcer and are processing in the message queue. Reaching high usage can indicate that the ASM enforcer is not processing incoming traffic. This can also indicate a change in the total CPU availability.disabled
event-message-queue-usage-thresholdThe threshold of the percent of memory usage (out of the total memory for all queues) for events awaiting BD processing in the message queue. The ASM alert is triggered when the set value is exceeded.90
backlog-message-queue-usage-enableEnable this variable to monitor the percent of memory usage (out of the total memory for all queues) for messages removed from the message queues and transferred to the backlog queue. This can indicate that messages are redirected from the event message queue. Reaching high usage can eventually result in bypassed or dropped messages.disabled
backlog-message-queue-usage-thresholdThe threshold of the percent of memory usage (out of the total memory for all queues) for messages removed from the message queue and transferred to the backlog queue. The ASM alert is triggered when the set value is exceeded.5
bypassed-transaction-rate-enableEnable this variable to monitor the number of HTTP transactions per second (TPS) that bypassed ASM processing due to the unavailability of the ASM enforcer. Bypassed translations indicate that some traffic is not evaluated by your ASM policy.disabled
bypassed-transaction-rate-thresholdThe threshold of the number of HTTP transactions per second that bypassed BD processing due to unavailability of the BD (in Million TPS). The ASM alert is triggered when the set value is exceeded.0.1
notification-by-syslogEnable this variable to have the system send notifications to the system log.disabled
notification-by-snmpEnable this variable to have the system send notifications as SNMP traps.disabled
notification-by-emailEnable this variable to have the system send notifications by email to specific email addresses displayed in the notification-email-addresses variable.disabled
notification-email-addressesThe email addresses that will receive notifications from the ASM system.none
smtp-config-nameThe SMTP server setting that the ASM alert system uses to send out email notifications.none

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have administrative access to tmsh.
  • Have working SNMP and SMTP configurations on the BIG-IP ASM system.

Procedures

Configuring ASM resource alerts and thresholds using tmsh

To enable BIG-IP ASM resource alerts and adjust the resource threshold values using tmsh, perform the following procedure:

Impact of procedure: Enabling BIG-IP ASM resource monitoring should have negligible impact on your system. However, F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To enable the monitoring for a specific resource, use the following command syntax:

    modify /asm health-alerts <resource_variable> enabled

    For example, to monitor the average ASM CPU usage overall system cores, type the following command:

    modify /asm health-alerts asm-cpu-usage-enable enabled

  3. Optionally, to adjust the resource threshold for triggering the alerts, use the following command syntax:

    modify /asm health-alerts asm-cpu-usage-threshold <value>

    For example, to set the threshold so the system will send out alerts when the usage exceeds 90 percent of overall ASM CPU usage, type the following command:

    modify /asm health-alerts asm-cpu-usage-threshold 90

  4. To verify the configured variables, type the following command:

    list /asm health-alerts

  5. To save the configuration, type the following command:

    save /sys config

Configuring the methods that the BIG-IP ASM system uses to send alerts using tmsh

The ASM system supports syslog, SNMP, and email for sending resource alerts, which are controlled by notification-by-syslog, notification-by-snmp, and notification-by-email variables, respectively. You must enable at least one method for the BIG-IP ASM system to receive the notification. To do so, perform the following procedure:

Impact of procedure: Enabling BIG-IP ASM resource monitoring should have negligible impact on your system. However, F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. If you want the system to send outbound emails, you must assign an SMTP configuration profile. To do so, use the following command syntax:

    modify /asm health-alerts smtp-config <smtp_config>

    For example, to use the SMTP configuration profile named mysmtp, type the following command:

    modify /asm health-alerts smtp-config mysmtp

  3. If you want to enable email notification, you must first configure the recipient's email address using the following command syntax:

    modify /asm health-alerts notification-email-addresses add { <email_address> }

    For example, to set admin@example.com as the recipient's email address, type the following command:

    modify /asm health-alerts notification-email-addresses add { admin@example.com }

  4. To enable the selected method for the BIG-IP ASM system to send resource alerts, use the following command syntax:

    modify /asm health-alerts <notification_method> enabled

    For example, to set the BIG-IP ASM system to send resource alerts over email, type the following command:

    modify /asm health-alerts notification-by-email enabled

  5. To verify the configured variables, type the following command:

    list /asm health-alerts

  6. To save the configuration, type the following command:

    save /sys config
