Known Issue

The Master Control Program Daemon (mcpd) process may produce a core file and continuously restart when the service check date in the license is not current.

This issue occurs when all of the following conditions are met:

  • Your system license has a service check date that is earlier than the release date of the current version.
  • You modify a default base User Datagram Protocol (UDP) profile.

The service check date is located in the license and is the date that the license was last activated or the date that the service contract for the device expires (whichever is earlier). For example, if you have an active service contract that ends on December 31, and you license a device on June 30, the service check date is set to June 30.

Note: The service check date in the license is updated each time the license is reactivated.

Impact

The BIG-IP system is not functional, and the mcpd process continuously restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Messages similar to the following example are logged to the /var/log/ltm file:

    emerg logger: Re-starting mcpd
    emerg mcpd[7653]: 01070608:0: License is not operational (expired or digital signature does not match contents).
    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all" - failed. -- Error: failed to reset strict operations; disconnecting from mcpd. Will reconnect on next command. The connection to mcpd has been lost, try again.
    emerg logger: Re-starting mcpd

  • Your BIG-IP system generates a an mcpd core file to the /shared/core directory, with a time stamp that correlates with the traffic interruption, similar to the following example:

    -rw-r--r-- 1 root root 144M Apr 29 10:17 mcpd.bld5.0.429.core.gz

Workaround

There is no workaround for this issue; however, you can prevent this issue by re-activating the license prior to upgrading. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system is temporarily unable to pass traffic.

  1. Log in to the Configuration utility as an administrative user.
  2. Navigate to System > License.
  3. Click Re-activate.
  4. Click the method of activation, then click Next.
  5. When the re-licensing is complete, click Continue.
For more information about the re-licensing process, refer to K7752: Licensing the BIG-IP system.
