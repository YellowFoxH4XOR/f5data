Description:

In BIG-IP APM environments utilizing OAuth provider discovery tasks, these tasks do not automatically restart on the new active device following a failover event. Manual intervention is required to re-enable the discovery tasks. There is no built-in SNMP OID or native alerting mechanism to monitor the status of OAuth discovery tasks. If a task is not running, newly discovered keys and related configuration changes may be missing or outdated.

Environment:

  • High Availability (HA) deployment with OAuth provider discovery tasks enabled

Cause:

OAuth provider discovery tasks are not designed to automatically restart on the new active device after a failover event. The product does not provide native mechanisms for automatic restart or monitoring/alerting of these task statuses.

Recommendations:

After a failover, manually verify and restart any required OAuth provider discovery tasks using the BIG-IP GUI.
To monitor OAuth discovery task status, use the BIG-IP REST API to query task state and implement external scripts for alerting. 

Example script:

BIGIP_HOST="https://<BIGIP_MGMT_IP>"
USERNAME="<your_username>"
PASSWORD="<your_password>"
DISCOVERY_TASK_NAME="<your_oauth_discovery_task_name>"
STATUS=$(curl -sk -u $USERNAME:$PASSWORD \

"$BIGIP_HOST/mgmt/tm/access/oidc/discover" | \
jq -r ".items[] | select(.name==\"$DISCOVERY_TASK_NAME\") | .status")
if [[ "$STATUS" != "STARTED" ]]; then
echo "ALERT: OAuth discovery task '$DISCOVERY_TASK_NAME' is not running! Status: $STATUS"
# Trigger alert or notification here
else
echo "OK: OAuth discovery task '$DISCOVERY_TASK_NAME' is running."
fi

Schedule this script periodically (e.g., via cron) and integrate it with your monitoring system.
