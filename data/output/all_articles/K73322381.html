Description
When adding a new rule to a policy with an ordinal value, which is already taken by an existing rule, the new rule is added using the user-input ordinal value, and the existing rule with the same ordinal value, does not change, thus, conserve its original ordinal value.  This leads to 2 rules having the same ordinal value, that is, not unique to each rule. 

This happens when changing the ordinal value from TMOS, by CLI or by API. This does not happen if the change is made from GUI. If the same change is done from the GUI, the new added rule would take the user-input ordinal value, and others existing rules would be reordered automatically.  

Environment

  • BIG -IP LTM Policy

Cause
By design

Recommended Actions

None - this is an expected behavior
