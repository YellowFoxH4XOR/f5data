Description

You see traffic arriving at a pool member with it's original source IP, and traffic doesn't seem to return to the client

Environment

  • BIG-IP LTM
  • Virtual Server
  • Pool

Cause

The virtual server doesn't have a SNAT applied, potentially causing asymmetric routing to occur

Recommended Actions

To determine if this is the issue affecting your traffic, you can first try enabling SNAT Automap on the virtual server to see if traffic starts working.
  1. From the Configuration Utility (GUI), navigate to the virtual server in question
    Local Traffic > Virtual Servers > Virtual Server List > <virtual server>
  2. Locate the Source Address Translation option and select Automap
  3. Click Update at the bottom of the page
  4. Test the virtual server by trying to access the application
  If you find that traffic is now working, you can either leave the configuration as is, or consider creating and applying a SNAT pool  Note: See Related Content for more information
