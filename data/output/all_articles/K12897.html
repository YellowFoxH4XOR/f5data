Known Issue

The foreach iRule command does not properly iterate over a Tcl list when the iRule syntax uses a paired index. When this issue occurs, the BIG-IP system incorrectly evaluates the foreach loop, and assigns the value of the first column to both loop variables for the first evaluation, then assigns the value of the second column to both loop variables on the second evaluation. As a result, the BIG-IP system may evaluate an expression in the body of the foreach loop twice per list element. In addition, using certain iRule commands in the foreach loop may cause the loop to repeat indefinitely. For more information, refer to K12962: Some iRules commands temporarily suspend iRule processing.

For example, in the following iRule, the foreach command uses color and count as index variables to iterate over the associated array:

when HTTP_REQUEST {
array set ::colorcount {
red 2
green 5
blue 4
white 9
}
foreach {color count} [array get ::colorcount] {
log local0. "There have been $count requests for $color."
}
}

As a result of this issue, incorrect output that appears similar to the following example is logged:

There have been red requests for red.
There have been 2 requests for 2.
There have been green requests for green.
There have been 5 requests for 5.
There have been blue requests for blue.
There have been 4 requests for 4.
There have been white requests for white.
There have been 9 requests for 9.

The expected output is a single line of output for each row of the table. For example:

There have been 2 requests for red.
There have been 5 requests for green.
There have been 4 requests for blue.
There have been 9 requests for white.

This issue occurs when the following condition is met:

  • An iRule uses a foreach command that contains two or more index variables

Impact

iRules containing the foreach command may cause system resource-related issues.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • iRules containing the foreach command may produce unexpected results.
  • Using commands that temporarily suspend iRule processing in the foreach loop may potentially cause performance-related issues.
