Topic

You should consider using these procedures under the following condition:

  • You want to encrypt the cookies used by BIG-IP cookie persistence.

Description

You can configure the cookie persistence profile to encrypt persistence cookies. The following three distinct options are available that are not available in the HTTP profile, listed under Cookie Encryption Use Policy:

  • Preferred: Generates an encrypted cookie, but accepts both encrypted and unencrypted formats. This option is best used when transitioning from unencrypted to encrypted, utilizing cookies with a long expiration period and cookies that are not session cookies.
  • Required: Cookie format must be encrypted.
  • Disabled: (Default setting) Generates the cookie format unencrypted.

The BIG-IP system offers four HTTP cookie persistence methods. Of the available methods, three of the methods use cookies that identify the BIG-IP system. Within the cookies themselves, the pool members are encoded. However, the encoding method is published, which may allow a person the ability to profile a system and determine the number of servers used by a particular site. In addition, it may allow a person to view that the BIG-IP system is load-balancing the site.

Note: The Cookie Hash method is the only cookie method that does not contain encoding pool member information. The Cookie Hash method uses an existing cookie the pool member already provides for another function, and applies a hash and offset value in order to use that cookie for persistence tracking purposes.

The BIG-IP cookie used for the HTTP Cookie Insert, HTTP Cookie Passive, and HTTP Cookie Rewrite methods use the following structure and encoding:

  • IPv4

    BIGipServer<pool_name>=<Encoded IP Address>.<Encoded Port>.0000

  • IPv6

    BIGipServer<pool_name>=<Full hexadecimal IPv6 address>.<Encoded Port>

Note: For information about encoding persistence cookie information, refer to K6917: Overview of BIG-IP persistence cookie encoding.

Depending on the network setup, pool member information with an HTTP cookie may not pose a security risk. In an environment where the pool members are accessible without going through the BIG-IP system, the ability to map, profile, and directly access the servers may pose a security risk.

You can mitigate this risk using the cookie encryption use policy within each of the four cookie persistence methods. This option encrypts the BIG-IP cookies using a 192-bit AES cipher, and then encodes it using the Base64 encoding scheme.

A cookie encrypted using the cookie encryption use policy appears similar to the following example:

Set-Cookie: BIGipServerhttp-pool=!LHmYFDA0qZyj4NoylBEaDn0/k2wesiGt0ANZhWaAohjULoWFXRc1b/yfibypy1qfBzD51kqvmwzfcy4=; path=/

Prerequisites

You must meet one of the following prerequisites to perform these procedures:

  • You have Configuration utility access with at least a manager role.
  • You have TMOS Shell (tmsh) access with at least a manager role.

Procedures

  • Using the Configuration utility to configure the cookie encryption use policy
  • Using tmsh to configure Cookie Encryption Use Policy

Using the Configuration utility to configure the cookie encryption use policy

To watch a video demo of this procedure, go to  Configuring cookie encryption for BIG-IP persistence cookies.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, encryption consumes system resources. F5 recommends testing the changes in your staging environment before implementing in production.

  1. Log in to the Configuration utility.
  2. Gp to Local Traffic > Profiles > Persistence.
  3. Select Create.
  4. Enter a name for the profile.
  5. For Persistence Type, select Cookie.
  6. Under Configuration, select the Cookie Method check box.
  7. Choose the option that best suits your requirements.

    Note: For more information, refer to K83419154: Overview of cookie persistence.

  8. Select the Cookie Encryption Use Policy check box.
  9. For Cookie Encryption Use Policy, select one of the following options:
    • Disabled: Default setting. Generates the cookie format unencrypted.
    • Preferred: Generates an encrypted cookie, but accepts both encrypted and unencrypted formats.
    • Required: Cookie format must be encrypted.
  10. Select the Encryption Passphrase check box.
  11. Enter a passphrase to use for cookie encryption.
  12. Select Finished.
  13. Go to Local Traffic > Virtual Servers > Virtual Server List.
  14. Under Resources, select Edit for the virtual server you want to add the new persistence profile to.
  15. For Default Persistence Profile, select the new persistence profile you created.
  16. Select Update.

    Note: Cookie persistence requires an HTTP or FastHTTP profile to be associated with the virtual server.

Using tmsh to configure Cookie Encryption Use Policy

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, encryption consumes system resources. F5 recommends testing the changes in your staging environment before implementing in production.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To configure a cookie persistence profile using the cookie encryption use policy and one of the available four methods, use the following command syntax:

    create ltm persistence cookie <name of profile> defaults-from cookie method [hash | insert | passive | rewrite] cookie-encryption [disabled | preferred | required] cookie-encryption-passphrase <passphrase>

    For example:

    HTTP Cookie Insert with encryption required

    create ltm persistence cookie MyTest defaults-from cookie method insert cookie-encryption required cookie-encryption-passphrase supersecret

  3. To associate the persistence profile to a virtual server, use the following command syntax:

    modify ltm virtual <virtual server> persist replace-all-with { <cookie persistence profile> }

    For example:

    modify ltm virtual ExampleVS persist replace-all-with { MyTest }

    Note: Cookie persistence requires an HTTP or FastHTTP profile to be associated with the virtual server.

  4. To save the configuration, type the following command:

    save sys config

Note: For more information about the different types of HTTP cookie persistence you can configure your BIG-IP system to use, refer to the Enabling Session Persistence chapter of the Configuration Guide for BIG-IP Local Traffic Manager.
