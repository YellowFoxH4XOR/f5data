Description
Route Domain ID specified in traffic matching criteria address list has no effect on Virtual Server IP.

(tmos)# list ltm traffic-matching-criteria TEST_HTTP_VS_TMC_OBJ all-properties
ltm traffic-matching-criteria TEST_HTTP_VS_TMC_OBJ {
    app-service none
    description none
    destination-address-inline 0.0.0.0
    destination-address-list TEST_HTTP_VS_TMC_OBJ
    destination-port-inline http
    destination-port-list none
    partition DMZ
    protocol tcp
    route-domain any
    source-address-inline 0.0.0.0
    source-address-list none
    source-port-inline any
    source-port-list none
    vlans none
}

traffic-management-criteria above having destination-address-list "TEST_HTTP_VS_TMC_OBJ" and route-domain has value of "any" which is default value.
If you check the address-list of "TEST_HTTP_VS_TMC_OBJ",

(tmos)# list net address-list TEST_HTTP_VS_TMC_OBJ
net address-list TEST_HTTP_VS_TMC_OBJ {
    addresses {
        10.0.0.1%1234 { }
    }
    partition DMZ
}

The address has IP 10.0.0.1%1234.
However if you create a VS and assign "TEST_HTTP_VS_TMC_OBJ" to Virtual Server destination address,

(tmos)# list ltm virtual TEST_HTTP traffic-matching-criteria;list ltm virtual-address
ltm virtual TEST_HTTP {
    traffic-matching-criteria TEST_HTTP_VS_TMC_OBJ
}
ltm virtual-address 10.0.0.1 {
    address 10.0.0.1
    mask 255.255.255.255
    partition DMZ
    traffic-group /Common/traffic-group-1
}

The virtual server has address of 10.0.0.1 which is not the expected IP because there is no Route-domain ID specify into the virtual server address.

Environment

  • Traffic matching criteria (TMC)
  • Route domain
  • Virtual Server

Cause
This is documented as ID1080985.

Recommended Actions

Modify the route-domain of TMC to appropriate route-domain value will show the correct VS address.

(tmos)# modify ltm traffic-matching-criteria TEST_HTTP_VS_TMC_OBJ route-domain RD_DMZ;list ltm virtual-address {address}
ltm virtual-address 10.69.161.236%2382 {
    address 10.69.161.236%2382
}
