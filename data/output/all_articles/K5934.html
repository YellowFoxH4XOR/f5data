This article applies to BIG-IP 9.2.0 through 9.4.0. For information about other versions, refer to the following article:

  • K7922: Overview of BIG-IP ASM HTTP response code filtering

The default BIG-IP ASM configuration allows the following HTTP response codes to pass through the BIG-IP ASM to the client:

  • 100-199 - Informational codes
  • 200-299 - Status codes
  • 300-399 - Redirect codes
  • 400 - Bad Request
  • 401 - Unathorized
  • 404 - Not Found
  • 407 - Proxy Authentication Required
  • 503 - Service Unavailable

Note: For more information about HTTP codes, refer to RFC2616, Hypertext Transfer Protocol.

All other HTTP response codes are blocked by the BIG-IP ASM http_error_filter_list internal parameter.

When the BIG-IP ASM receives an HTTP response code that is not allowed, it logs the following error message:

Illegal HTTP status in response

You can configure the BIG-IP ASM to allow additional HTTP response codes by adding them to the http_error_filter_list internal parameter.

To add or remove HTTP response codes from the http_error_filter_list internal parameter, perform the following procedure:

  1. Connect to the BIG-IP ASM internal parameters page by replacing <BIG-IP_ASM_IP> in the following example with the management or self IP address of your BIG-IP ASM unit:

    https://<BIG-IP_ASM_IP>/dms/internal

  2. When prompted, log in using the BIG-IP ASM administrative credentials.
  3. Search for the http_error_filter_list parameter name by using the By Field box at the top of the window, and clicking Go.
  4. Modify the value of the http_error_filter_list parameter and update the HTTP response codes.

    Use a comma without spaces to separate values. For example:

    400,401,404,407,503

  5. Click the Update button.
  6. Restart the BIG-IP ASM process by typing the following command from the BIG-IP ASM command line:

    bigstart restart asm
