K000161674: Big-IQ: Upgrade will fail when DCDs are attached

Type
Support Solution
Published
2026-06-11
Updated
2026-09-10
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.2, 8.4.1
Source
https://my.f5.com/manage/s/article/K000161674

Description

Upgrading Big-IQ version will fail when DCDs are attached. Centralized or License Management only systems in either standalone or HA are not impacted.

Environment

All the following conditions must be met:

  • Centralized Manager Standalone or HA
  • Data Collection Devices
  • Upgrading from Big-IQ 8.4.1 or higher that do not contain a fix for ID 2313605

Cause

ID 2313605

Recommended Actions

To resolve this issue prior to upgrading, follow these steps on both the CM and DCD systems :

Important: If the BIG-IQ system is upgraded to a new version, the cs.dat file is replaced and any customizations to this file will be lost. F5 does not recommend adding the cs.dat file into a UCS archive because you may encounter errors when saving or installing a UCS archive after you upgrade. 

  1. Make the /usr filesystem read/write: mount -o rw,remount /usr
  2. Preserve the existing file: cp -p /usr/libdata/configsync/cs.dat{,.K000161674}
  3. Edit the /usr/libdata/configsync/cs.dat file using a text editor and search for the following text: save.2640.file
    e.g: save.2640.file     = /var/config/rest/elasticsearch/config/elasticsearch.yml
  1. Append the following lines after that:
    # elasticsearch ssl certificate files
save.2641.file     = /var/config/rest/elasticsearch/config/es_admin-key.pem
save.2642.file     = /var/config/rest/elasticsearch/config/es_admin.pem
save.2643.file     = /var/config/rest/elasticsearch/config/es_node-key.pem
save.2644.file     = /var/config/rest/elasticsearch/config/es_node.pem
save.2645.file     = /var/config/rest/elasticsearch/config/es_root-ca-key.pem
save.2646.file     = /var/config/rest/elasticsearch/config/es_root-ca.pem
  2. Save and quit the file
  3. Type the following command to confirm the changes: grep -A 11 -B 1 save.2640.file /usr/libdata/configsync/cs.dat
    The output should look similar to this
    # elasticsearch configuration
save.2640.file     = /var/config/rest/elasticsearch/config/elasticsearch.yml

# elasticsearch ssl certificate files
save.2641.file     = /var/config/rest/elasticsearch/config/es_admin-key.pem
save.2642.file     = /var/config/rest/elasticsearch/config/es_admin.pem
save.2643.file     = /var/config/rest/elasticsearch/config/es_node-key.pem
save.2644.file     = /var/config/rest/elasticsearch/config/es_node.pem
save.2645.file     = /var/config/rest/elasticsearch/config/es_root-ca-key.pem
save.2646.file     = /var/config/rest/elasticsearch/config/es_root-ca.pem

# restjavad configuration
save.2650.file     = /var/config/rest/config/restjavad.properties.json
  4. Perform the upgrade as normal
  5. Following the upgrade, you should go through steps 1 - 7 again when upgrading to a version that does not contain the fix for ID 2313605.

To resolve this issue after upgrading, follow these steps while still booted to 8.4.2 on both the CM and DCD systems :

  1. Stop the elasticsearch service: tmsh stop sys service elasticsearch.
  2. Remove all eslognode files from /var/log to free up space: /bin/rm /var/log/elasticsearch/eslognode-* /var/log/elasticsearch/eslognode.log
  3. Mount the previous volume: volumeset -f mount HD1.X
    e.g.: volumeset -f mount HD1.3
  1. Copy the missing files from the previous volume to the current volume: cp -p /mnt/HD1.X/var/config/rest/elasticsearch/config/*.pem /var/config/rest/elasticsearch/config
  2. Restart the system:  shutdown -r now
  3. If the version of 8.4.2 running does not contain the fix for ID 2313605, follow steps 1 - 7 under Resolving this issue prior to the upgrade.

Additional Information

This issue impacts all upgrades from a system that does not have the resolution for ID 2313605. Going to a fixed version will only prevent future upgrade failures from that version.

Also you may see below log messages in /var/log/restjavad.0.log logs:
