K000092643: SDC component JVM experiencing insufficient memory.

Type
Support Solution
Published
2022-11-26
Updated
2022-11-26
Source
https://my.f5.com/manage/s/article/K000092643

Description

  • Allocation failure log found in the GC logs of the component.

2019-07-30T04:11:58.601+0800: 41135383.834: [Full GC (Allocation Failure) 1998M->1988M(2000M), 8.5451935 secs]

  • "Hashed wheel timer" logs found in the component's main log.

nmsagent.log.1:2021-10-29 12:11:19,653 INFO [10778] Interrupting thread TT Hashed wheel timer #6 (ID 106) which executes org.jboss.netty.util.ThreadRenamingRunnable). [ShutdownThread_252257] [ExtendedThread.interrupt()]

  • Out Of Memory Error log found in the component's main log.

2020-04-01 10:42:51,143 WARN [] Error for /cm-distribution/configuration-changed [qtp129371198-56587_56587] [ServletHandler.doHandle()] java.lang.OutOfMemoryError: Java heap space

  • SDC Applications that are Java based are CPF, FEP, NMSAgent, CM, WebUI and Cassandra DB.
  • When the JVM experiences this, the possible symptoms are : 

1. Sudden failure or major slowness of Java application.

2. Error found in the program log: java.lang.OutOfMemoryError: Java heap space.

3. High CPU utilization of your server due to increased java garbage collector (GC) activity.

 

Environment

  • SDC 5.1
  • CPF, FEP, NMSAgent, CM, WebUI and Cassandra DB.

Cause

Insufficient allocation of memory for the JVM.

 Recommended Actions

Tune Java memory allocations as described in KB K01755841.

Additional Information

K01755841: How to tune Java memory allocation for SDC components?
