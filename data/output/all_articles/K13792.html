Known Issue

The ARX system may respond inappropriately to a file locking response. This issue occurs due to an Isilon filer software update that changes how it interacts with opportunistic locking (oplock) file requests.

This issue occurs when all of the following conditions are met:

  • CIFS oplock is enabled
  • The Isilon filer is running version 6.5.5.4
  • You attempt to access or save *.xls or *.xlsx files to an ARX managed share

Oplocks allow a client to notify the file server that it will not only be the exclusive writer of a file, but will also cache its changes to that file locally in order to speed up file access. When the file server identifies that a file has been opportunistically locked by a client, it marks its version with an opportunistic lock and waits for the client to complete work on the file. At this point, the server expects the client to send the final changes back to the filer for synchronization.

Impact

Users may experience a 30-second delay when opening or saving .xls or .xlsx documents through the ARX.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Slow performance when using Excel
  • When reviewing a packet capture, clients will receive a STATUS_INVALID_HANDLE response to an oplocks request

Workaround

To work around this issue, you can disable CIFS oplock. To do so, perform the following procedure:

Impact of workaround: This command disables oplocks on the entire volume; therefore, no clients can use oplocks on files.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enable global mode by typing the following command:

    global
  4. Enable the namespace configuration mode using the following command syntax:

    namespace [namespace name]

    For example:

    namespace test
  5. Enable the volume configuration mode using the following command syntax:

    volume [volume name]

    For example:

    volume voltest
  6. To disable the CIFS oplock feature, enter the following command:

    cifs oplocks-disable
  7. Exit the channel configuration mode and return to privileged mode by typing the following command:

    end
