K000160182: BIG-IQ won't load on 8.3/8.4 upgrades due to a full /var partition

Type
Support Solution
Published
2026-02-27
Updated
2026-03-05
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.0
Source
https://my.f5.com/manage/s/article/K000160182

Description

After upgrading to 8.3/8.4, the /var directory is rapidly growing and consuming 100% of the disk causing the BIG-IQ upgrade to fail. The observed symptoms are:

  • When logging into the GUI, the configuration fails to load, and a "Launch Status" window appears indefinitely displaying Postgres log activities.
  • Low disk alert warnings triggered, similar to:
    011d0004:3: Disk partition /var has 0% free
  • The Tokumon log repeatedly reports:
    [WARNING] tokumon: isDBReady db is NOT ready

Environment

  • BIG-IQ
  • Upgrade to (8.3 or 8.4)
  • RBAC (with a large number of custom application roles / resource groups)

Cause

Insufficient handling of database maintenance for FAILED tasks, as tracked under Defect ID 2047425.

Answer/Recommended Actions

  1. Roll back the upgrade to the original boot location from before the upgrade.
  2. Delete the newly created boot location that failed during upgrade.
  3. Using the Bash shell, run the following PSQL commands to purge FAILED database tasks that are over one month old, then execute a full vacuum and reindex:

    # psql -U postgres -d bigiq_db -c "DELETE FROM bigiqtasks.global_tasks_deploy_app_service WHERE (_value ->> 'endDateTime')::timestamp < NOW() - INTERVAL '1 month';"

    # psql -U postgres -d bigiq_db -c "VACUUM FULL;"

    # psql -U postgres -d bigiq_db -c "REINDEX DATABASE bigiq_db;"

  4. Run the preUpgradeCheck tool to ensure all tests pass. For more details, see: K15988343
  5. Initiate a new upgrade attempt.
