Description

The command tmsh show /gtm iquery returns data.
However DNS sync does not work.
iqdump returns below error:
iqdump <problem device's IP>

47531120108016:error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed:s3_clnt.c:1269:
SSL return code: SSL_ERROR_SYSCALL


/var/log/gtm shows

err big3d[<PID>]: 012b300e:3: SSL Error: error:14094418:SSL routines:ssl3_read_bytes:tlsv1 alert unknown ca on connection to ::ffff:<Other DNS Self IP>:<port>.
err big3d[<PID>]: 012b3003:3: SSL error during shutdown: SSL SSL_ERROR_SSL


The netstat command below shows other connection with big3d and other device (192.0.2.2 in below example output) is not ESTABLISHED, however with gtmd the connection is ESTABLISHED.

netstat -pan | grep -e ":4353" 

    tcp6       0      0 :::4353                 :::*                    LISTEN      7171/big3d           off (0.00/0/0)
    tcp6       0      0 192.0.2.1:40520      192.0.2.2:4353       ESTABLISHED 7182/gtmd            keepalive (0.27/0/0)
    tcp6       0      0 192.0.2.1:54588      192.0.2.1:4353       ESTABLISHED 7182/gtmd            keepalive (2.37/0/0)
    tcp6       0      0 192.0.2.1:4353       192.0.2.1:54588      ESTABLISHED 7171/big3d           keepalive (903.68/0/0)
 

Environment

  • BIG-IP
  • v14.0 and above
  • DNS sync
     

Cause

Invalid server certificate for itself in the unit under /config/gtm/server.crt.
 

Recommended Actions

  1. Check which server certificate is valid on GUI:
    System  ››  Certificate Management : Device Certificate Management : Device Trust Certificates
     
  2. Find the GTM server certificate on GUI:
    DNS  ››  GSLB : Servers : Trusted Server Certificates
    And then remove old or newer certificate for itself.
     
  3. restart gtmd and big3d
    tmsh restart sys service gtmd big3d
    NOTE: please run this when it is in maintenance window.
