Description

  • F5 BIG-IP sending RST to pool member and tcpdump command showing error "F5RST: No Flow Found for ACK" on the RST packet.

  • SYN packet has FLOW and PEER ID's from F5:

SYN ACK packet has no FLOW and PEER ID:

Environment

  • BIG-IP LTM
  • Pool member TCP handshake getting reset after SYN/ACK provided from pool member

Cause:

  • Asymmetric routing can cause RST to be sent from the BIGIP in response to SYN/ACK.
    If the SYN/ACK from a pool member returns on a different VLAN to where the SYN was sent out on you can see in a capture

Recommended Actions

Verify the VLAN data in the Wireshark capture.  If the SYN leaves on a different VLAN to where the SYN/ACK arrives, look at routing on the BIGIP and pool member to determine why there is a discrpency.

Additional Information

Allowing asymmetrically routed connections across multiple VLANs (11.x - 17.x)
