Known Issue

This is the result of a known issue. When requests traversing the WebAccelerator result in a 401 Unauthorized response, the WebAccelerator system sends a FIN packet to both the client and the server. Since the 401 Unauthorized response begins the NTLM authentication handshake, the FIN packet in some cases interferes with the successful completion of the NTLM authentication handshake. As a result, NTLM authentication fails.

Note: Browsers known to be affected include Google Chrome, and the Vista / Windows 7 Explorer Views, which use the WebClient service.

F5 Networks Product Development is tracking this issue as CR134822.

This issue does not affect BIG-IP version 10.x.

Note: This issue may prevent the SharePoint Explorer View window from displaying through a BIG-IP WebAccelerator virtual server. For more information, refer to K11782: The SharePoint Explorer View window may not display through a BIG-IP WebAccelerator virtual server.

Workaround

You may be able to work around this issue by using an iRule to allow requests from these sources to bypass WebAccelerator as detailed in K6882: Bypassing BIG-IP WebAccelerator with an iRule in version 9.4.x. For example, the following iRule bypasses the WebAccelerator for traffic from Google Chrome browsers:

when HTTP_REQUEST {
   if { [HTTP::header User-Agent] contains "Chrome/" } {
      HTTP::class disable
   }
}
