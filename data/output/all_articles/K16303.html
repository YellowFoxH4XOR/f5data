K16303: The BIG-IP global SSL session cache can be increased to 4,194,304 sessions

Issue

Old Behavior

In BIG-IP versions prior to 11.5.0, the BIG-IP global SSL session cache size of 262,144 sessions per Traffic Management Microkernel (TMM) was not configurable. For background information, refer to K11170: The BIG-IP global SSL session cache size was increased to 262,144 sessions.

New Behavior

Beginning in 11.5.0, the BIG-IP global SSL session cache is configurable and can be set to a maximum of 4,194,304 sessions per TMM using the new system database key, tmm.ssl.cachesize. The default SSL cache size remains at 262,144 sessions per TMM.

It is important to note that SSL profiles allow modification of the SSL cache setting to a maximum value of 4194304 sessions. However, without setting the tmm.ssl.cachesize variable to a larger number of sessions and restarting TMM, the SSL cache will evict older sessions once the default setting of 262,144 sessions has been reached.

Impact

You can modify the BIG-IP global SSL session cache to accommodate up to 4,194,304 SSL session IDs.

Recommended Actions

To resize the SSL session cache for more than the default 262,144 sessions, you must modify the tmm.ssl.cachesize database key and restart TMM. To do so, perform the following procedure:

Impact of workaround: This procedure requires restarting TMM, which will temporarily stop all traffic processing.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To resize the SSL session cache, use the following command syntax:

    modify sys db tmm.ssl.cachesize value <number of sessions>

    For example, to modify the SSL session cache size to allow 1,000,000 sessions, you would use the following command:

    modify sys db tmm.ssl.cachesize value 1000000
  3. To restart TMM, type the following command:

    restart sys service tmm

    You can now proceed to configure the SSL profile with the desired SSL cache setting.
