Known Issue

This is the result of a known issue. The sync_zones process will fail to transfer zone changes if the gtmd utility fails to receive an exit status code from the sync_zones process. The gtmd process will wait for the status code indefinitely. The gtmd process does not allow subsequent attempts by the sync_zones process to synchronize zone changes.

When this issue occurs, the /var/log/gtm file will contain messages similar to the following example:

Jan 01 12:34:01 bigip1 gtmd: 011a001b:5: SYNC_ZONES startedJan 01 12:34:01 bigip1 gtmd: 011a001c:5: SYNC_ZONES skipped.Reason: sync_zones currently running

Conditions known to prevent the gtmd utility from receiving an exit status code from the sync_zones process are a slow network connection between BIG-IP GTM systems in a sync group, or the synchronization of large zone configurations.

F5 Product Development tracked this issue as CR69461, and CR69384 and it was fixed in BIG-IP GTM 9.2.4 and 9.4.0. For information about upgrading, refer to the BIG-IP GTM Release Notes.
