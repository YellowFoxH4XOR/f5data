Description
SAML Single Logout (SLO) doesn't work and produces a log message similar to the following in /var/log/apm. 
When users authenticate to an IDP through a SP webtop and then logout from the IDP, the webtop remains authenticated.

SAML SSO: Cannot identify SAML SP object to create SLO response
Note: This verbiage of the message may vary depending on the browser used.

Environment

  • SAML SP webtop.
  • Remote IDP

Cause

  • The IDP does not maintain any session information.
  • The SLO request from the IDP to the SP does not contain session information (because there isn't any)
  • Therefore APM receives a SLO and can't do anything with it.


However we know that SLO, in general, does work. The key factor here is the MRHSession  cookie which encodes the APM session information.
SLO requests can only succeed when they also have that cookie.
MRHSession is a session cookie. When first specified all session cookies are included in all requests to all sites therefore:

  1. User connects to APM and receives a MRHSession Cookie.
  2. User connects to the IDP, which is a different site, the MRHSession cookie is presented, because it is a session cookie.
  3. User logs out of of the IDP, causing SLO. The MRHSession cookie is presented back to APM.
  4. APM can now close that session.

Growing awareness that session cookies are a privacy threat has caused browsers to handle them differently. Some browsers now default to being presented to the originating site only.

  1. User connects to APM and receive a MRHSession Cookie.
  2. User connects to the IDP, which is a different site, the MRHSession cookie is not presented.
  3. User logs out of of the IDP, causing SLO.  This is a redirection and cannot "pickup" the MRHSession cookie.
  4. APM receives a SLO with no MRHSession cookie and cannot process it.

 

Recommended Actions

  1. Awareness that this can cause issues resulted in a new attribute for session cookies. The "SameSite" attribute
  2. This can be set to restore prior behavior, however the trending default behavior in the absence of the attribute is to prevent it from being presented. This results in SLO failure.
  3. BIG-IP versions prior to 16.0 have no option to modify this option.
  4. You should upgrade to BIG-IP version 16.0 or later

Additional Information

  • Bug ID 761049: APM does not support adding SameSite cookie attribute to APM cookies.
    Note: Not all browsers and versions handle the default  in the same way. For more information refer to:  SameSite cookies (mozilla)
  • K03346798: Chrome 80 SameSite cookie attribute enforcement
