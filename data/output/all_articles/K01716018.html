Topic

You should consider using this procedure under the following conditions:

  • You want to configure Kerberos end-user logon authentication to authenticate Windows domain users to multiple applications.
  • You are using Windows Active Directory (AD) as your key distribution center (KDC).
  • You have configured a virtual server with a BIG-IP APM access policy that includes Kerberos authentication.
  • Your client devices are joined to the domain and users are logged in with their domain-user accounts.

Description

Kerberos end-user logon authentication provides a method for the BIG-IP APM system to authenticate domain users without the need to explicitly enter in login credentials and without user password transmission.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have command line access to the BIG-IP APM system.
  • You have administrative access to the Windows domain controller (DC).

Procedures

To create and merge multiple keytab files to configure Kerberos end-user logon authentication for multiple applications, perform the following procedures:

  • Configure the client browser for Kerberos
  • Create a new keytab file with the ktpass command
  • Verify the service account name configuration on the AD/KDC
  • Merge the keytab files with the ktutil utility
  • Upload a keytab file to a Kerberos authentication server object
  • Use the klist command to verify the contents of a keytab file on the BIG-IP APM system

Configure the client browser for Kerberos

On the client side, you must first join the domain and be logged in as a domain user. In addition, you must configure your browser so that it contacts the DC after the you access the HTTP URL from the browser. The following procedure shows this process using Internet Options:

Note: For other browsers, refer to the relevant documentation for how to add a local intranet site.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Start Control Panel on Windows.
  2. Select Internet options.
  3. Select the Security tab.
  4. Select Local intranet.
  5. Select Sites.
  6. Select Advanced.
  7. For Add this website to the zone, enter the URL of the HTTP site you are configuring for Kerberos. For example https://app1.example.com.
  8. Select Add.

Create a new keytab file with the ktpass command

To create a new keytab file on the Windows DC, perform the following procedure:

Impact of procedure: Using the ktpass command with certain parameters on a domain controller may modify the AD service account. F5 recommends that you perform this procedure during a scheduled maintenance window for the specific service.

  1. Log in to the Windows DC as an administrator.
  2. Open Active Directory Users and Computers and create a new user account for each HTTP service account. For example, you can create the new account with the following values:

    Note: For security purposes, F5 recommends selecting the This account supports Kerberos AES 256 bit encryption check box on the Account tab in the user Properties after the account is created.

    • First name: firstname_app1
    • Full name: http_app1
    • User logon name: upn_app1
    • User logon name (pre-Windows 2000): samaccountname1
    • Account tab > This account supports Kerberos AES 256 bit encryption check box selected

  3. Open a command prompt and create a new keytab file using the following syntax:

    ktpass -princ <userPrincipalName> -mapuser <service account name> -crypto <encryption type> -ptype KRB5_NT_PRINCIPAL -pass <password> -out <keytab filename>

    For example:

    Important: The following command uses AES256-SHA1 encryption. You must therefore select the This account supports Kerberos AES 256 bit encryption check box for the user you created in step 2.

    ktpass -princ HTTP/app1.example.com@EXAMPLE.COM -mapuser http_app1 -crypto AES256-SHA1 -ptype KRB5_NT_PRINCIPAL -pass pass1234 -out app1example.keytab

    Note: The -princ parameter is case-sensitive. app1.example.com is the URL that you enter into the browser to access the HTTP service. For more information, refer to ktpass. This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

    In this example, the ktpass command performs the following changes to the account specified by the -mapuser parameter.

    • Overwrites the original user principal name (UPN) value, upn_app1 with HTTP/app1.example.com
    • Adds HTTP/app1.example.com to the list of service principal name (SPN) of the service account
    • Sets the password of the account
    • Increases the KVNO of the account by 1
    • Generates a keytab file app1example.keytab that supports the AES256-SHA1 encryption type
  4. Review the contents of the keytab file using the following command syntax:

    ktpass /in <keytab filename>

    For example:

    ktpass /in app1example.keytab

  5. You can repeat steps 2 and 3 to create another keytab file for another AD service account for another application.

Verify the service account name configuration on the AD/KDC

Perform the following procedure to verify the service account name's configuration on AD with the adtest and ldapsearch commands.

Note: If your BIG-IP APM system does not have connectivity to AD, you can also view the same configuration directly on the DC.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to Advanced shell (bash) of the BIG-IP APM system.
  2. To query AD for the names of the AD service account, use the following command syntax:

    adtest -t query -h "<IP address of domain controller>" -r "<REALM>" -A <username> -W '<password>' -u <sAMAccountName> -d 4

    Note: You need to include the single quotation marks around the password parameter.

    For example:

    adtest -t query -h "192.0.2.2" -r "EXAMPLE.COM" -A user1 -W 'pass1234' -u samaccountname1 -d 4

    In this example, user1 is any AD user that has read access to query AD.

    You may observe an output that has values similar to the following example:

    distinguishedName: CN=http_app1,CN=Users,DC=example,DC=com
    msDS-SupportedEncryptionTypes: 16
    sAMAccountName: samaccountname1
    servicePrincipalName: HTTP/app1.example.com@EXAMPLE.COM
    userPrincipalName: HTTP/app1.example.com@EXAMPLE.COM

    Note In this example, verify that the HTTP service account http_app1 has the SPN and UPN HTTP/app1.example.com@EXAMPLE.COM and supports Kerberos AES 256 bit encryption.

  3. Verify the KVNO of the HTTP service account using the following command syntax:

    ldapsearch -xLLL -H ldap://<AD server IP address>:<ldap port number> -b '<searchbase>' -D '<username>' -w '<password>' '(sAMAccountName=<service account username>)' msDS-KeyVersionNumber

    For example:

    ldapsearch -xLLL -H ldap://192.0.2.2:389 -b 'dc=example,dc=com' -D 'user1' -w 'pass' '(sAMAccountName=samaccountname1 )' msDS-KeyVersionNumber

    In this example, the service account name is samaccountname1 and uses the read privileges of user1 to perform an Lightweight Directory Access Protocol (LDAP) search (ldapsearch). You should observe an output similar to the following:

    dn: CN=http_app1,CN=Users,DC=example,DC=com
     msDS-KeyVersionNumber: 3

    In this output example, the KVNO of the service account named http_app1 is 3. This KVNO must be the same as the KVNO in the keytab file.

  4. If your BIG-IP APM does not have connectivity to AD, you can also verify the same values by using the following command syntax on AD:

    ldifde -d <RootDN>  -f <output filename> -p subtree -l *,msDS-KeyVersionNumber

    For example:

    ldifde -d CN=http_app1,CN=Users,DC=example,DC=com  -f c:\output.txt -p subtree -l *,msDS-KeyVersionNumber

    Verify the values from the output file specified by the -f parameter.

Merge the keytab files with the ktutil utility

You can use the ktutil utility, available on the BIG-IP APM, to merge multiple keytab files into a single keytab file with individual entries for each service.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Using a utility like scp or winscp, upload all your keytab files you created in the Creating a new keytab file with the ktpass command procedure to the BIG-IP APM system for merging. For example, you can upload them to the /var/tmp directory.
  2. Log in to the BIG-IP command line.
  3. Start the ktutil utility by entering the following command:

    ktutil

  4. To read each keytab file you uploaded in step 1, use the following command syntax in ktutil:

    read_kt <keytab filename>

    For example, if you uploaded your keytab files to the /var/tmp directories, enter the following commands:

    read_kt /var/tmp/app1example.keytab
    read_kt /var/tmp/app2example.keytab
    read_kt /var/tmp/app3example.keytab
     

  5. To merge and write the multiple keytab files, use the following command syntax in ktutil:

    write_kt <merged keytab filename>

    For example, enter the following command to write and save the merged keytab file:

    write_kt /var/tmp/appservice.keytab

  6. To quit the ktutil utility, enter the following command:

    quit

Upload a keytab file to a Kerberos authentication server object

After generating the keytab file in the previous procedure, download it to your computer. To upload it to the Kerberos authentication server object using the Configuration utility, perform the following procedure:

Impact of procedure: Uploading an incorrect keytab file can cause Kerberos authentication failure. F5 recommends that you perform this procedure during a scheduled maintenance window for the specific service.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Access  > Authentication > Kerberos.

    Note: For versions prior to BIG-IP 13.x, Go to Access Policy  > AAA Servers > Kerberos.

  3. Select the name of the Kerberos server
  4. For Keytab File , select Upload New File .
  5. Select Choose File, then browse to and choose the merged keytab file you created in the Merging the keytab files with the ktutil utility procedure.
  6. Select Update.

Use the klist command to verify the contents of a keytab file on the BIG-IP APM system

You may want to verify the contents of your keytab files. To do that, perform the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To find the full path name of your keytab file, use the following command syntax:

    grep kerberos_keytab /config/partitions/<partition_name>/bigip.conf

    For example, if you do not have any partitions, enter the following command:

    grep kerberos_keytab /config/bigip.conf

    You may observe an output similar to the following example:

    cache-path /config/filestore/files_d/Common_d/kerberos_keytab_file_d/:Common:kerbAuth_key_file_64525_1

  3. To verify the contents of a keytab file, use the following command syntax:

    klist -Kket <keytab filename>

    For example:

    klist -Kket /var/tmp/appservice.keytab

    or

    klist -kKet /config/filestore/files_d/Common_d/kerberos_keytab_file_d/:Common:kerbAuth_key_file_64525_1

    Verify all of the values from the output.
