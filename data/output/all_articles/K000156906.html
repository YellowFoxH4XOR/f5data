K000156906: Timezone change is not reflected in GUI without tomcat restart

Type
Support Solution
Published
2025-12-31
Updated
2025-12-31
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000156906

Description

When the BIG-IP system timezone is changed, timestamps displayed in the GUI for pool member and node status changes continue to show in the previous timezone. This affects the following GUI locations:

  • Local Traffic › Pools : Pool List › Members
  • Local Traffic › Nodes : Node List

The timezone change is correctly reflected in the upper right corner of the GUI, but historical and new status change timestamps for nodes and pool members remain in the old timezone until the httpd service is restarted.

Environment

  • Product: BIG-IP
  • Configuration: Systems where timezone has been modified via GUI or TMSH
  • Affected GUI elements: Node and pool member availability status timestamps

Cause

The JVM used by Tomcat determines and caches the current timezone during startup and does not automatically refresh without a JVM restart. 

Recommended Actions

After changing the BIG-IP system timezone, restart the Tomcat service to refresh the JVM timezone cache:

  1. Access the BIG-IP command line interface
  2. Execute the following command:
    bigstart restart tomcat

Note: Alternatively, restarting httpd will also resolve the issue as it restarts both httpd and Tomcat services:

bigstart restart httpd

Additional Information

  • The timezone change itself is successful and reflected in the system
  • Only the GUI display of node and pool member status change timestamps is affected
  • All new status changes logged after the timezone modification will continue to display in the incorrect timezone until Tomcat is restarted
  • The issue is specific to the GUI presentation layer and does not affect actual system time or logging functionality
