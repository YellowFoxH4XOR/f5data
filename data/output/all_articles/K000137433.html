Topic

You should consider using these procedures under the following condition:

  • You want to increase the disk space on a BIG-IP tenant that does not have sufficient disk space for any of the following tasks:
    • Upgrading software or installing point releases
    • Provisioning multiple modules
    • Preparing for increased logging that requires additional disk space
    • Storing more UCS archives in the /var/local/ucs directory which resides on the /var disk directory 

Description

The BIG-IP tenant image is available in multiple sizes, for example T1, T2, T4 and ALL. For information about the BIG-IP tenant image types, refer to K45191957: Overview of the BIG-IP tenant image types. If you have deployed a BIG-IP tenant using one of these images, and find the disk size inadequate for upgrading (including point release installation) or provisioning multiple modules or increased logging or storing more UCS archives, you can increase the BIG-IP tenant disk size. To increase the disk space on a BIG-IP tenant, you must perform the following tasks in sequence:

  • Shutdown the BIG-IP tenant by setting its running-state to provisioned from the F5 VELOS partition or F5 rSeries system CLI.
  • Resize the BIG-IP tenant from the F5 VELOS partition or F5 rSeries system CLI.
  • Start the BIG-IP tenant by setting its running-state to deployed from the F5 VELOS partition or F5 rSeries system CLI.
  • Resize the disk directory in the BIG-IP tenant according to your requirements from the BIG-IP tenant CLI. If you are looking to extending disk space for

    Important: Increasing the disk size for a BIG-IP tenant is irreversible because F5 does not support disk shrinking.

    • upgrading software, or installing point releases on an additional slot, you should extend the /shared disk directory as needed. Note that you should not commit all of the disk resource you have just added into extending the /shared disk directory as the remaining added disk resource is needed to perform software installation into a new software slot.
    • provisioning multiple modules, you should extend the /var, /var/log, /config, /shared, and /appdata disk directories as needed to accommodate the module provisioning. For the /var, /var/log, and /config disk directories, sizes can range from 2 GB to 3 GB or more. The /shared and /appdata disk directories are larger and can range from 10 GB to 15 GB or more.
    • increased logging, you should extend the /var/log disk directory as needed.
    • storing more UCS archives in the /var/local/ucs directory on the BIG-IP tenant, you should extend the /var disk directory as needed.
  • Reboot the BIG-IP tenant from the BIG-IP tenant CLI to effect the change to the disk directory/directories.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • The BIG-IP tenant is deployed using either the T1, T2, T4 or ALL image type on the F5 VELOS partition or F5 rSerles system.
  • You have sufficient access rights (admin user access) to modify the BIG-IP tenant settings on the F5 VELOS partition or F5 rSeries system.
  • You have administrative access (either root user access or admin user with tmsh/Advanced Shell access) to the BIG-IP tenant.

Procedures

  • Extending disk space for upgrading software, or installing point releases on an additional slot
  • Extending disk space for provisioning multiple modules
  • Extending disk space for increased logging
  • Extending disk space for storing more UCS archives on the BIG-IP tenant

Extending disk space for upgrading software, or installing point releases on an additional slot

This procedure is most applicable to BIG-IP tenants that use the T1 image type. You can also use this procefure on BIG-IP tenants that already had a larger disk capacity to allow additional slots if needed. To extend disk space for upgrading software, or installing point releases on an additional slot, perform the following procedure:

Impact of procedure: The BIG-IP tenant will be shut down during the disk provisioning steps, and the system will not be available for traffic processing. F5 recommend you perform this procedure during a suitable maintenance window. Increasing disk size on the BIG-IP tenant is irreversible because F5 does not support disk shrinking.

  1. Log in to the partition command line as the partition administrator for a VELOS system, or the CLI as the admin user for an rSeries system.
  2. Enter the Configuration mode terminal by entering the following command:

    config

  3. Shut down the tenant by changing the running-state of the tenant to Provisioned using the following command syntax:

    tenants tenant <name of the tenant> config running-state provisioned ; exit

    For example, you enter the following command to shut down the my-example-bigip-tenant tenant:

    tenants tenant my-example-bigip-tenant config running-state provisoned ; exit

  4. Save the change by entering the following command:

    commit

  5. Exit the Configuration mode terminal by entering the following command:

    exit

  6. Wait for the tenant to completely shut down. You can query the status of the tenant by running the following command syntax:

    show tenants tenant <name of tenant> state status

    Using the previous example,

    show tenants tenant my-example-bigip-tenant state status

    The output should report the status as Provisioned.

  7. Provision the required disk space for the BIG-IP tenant on the VELOS partition or rSeries system. For example, if you need only one additional slot for upgrading software, or installing point releases on a BIG-IP tenant that is using the T1 image type, you may want to modify the BIG-IP tenant storage size setting from 22 GB to 45 GB on the VELOS partition or rSeries system. 
    1. Enter the Configuration mode terminal by entering the following command:

      config

    2. Provision the required disk space for the BIG-IP tenant by entering the following command syntax:

      tenants tenant <name of tenant> config storage size <new total disk size> ; exit

      For example, you enter the following command to provision the new disk size of 45 GB for my-example-bigip-tenant tenant:

      tenants tenant my-example-bigip-tenant config storage size 45 ; exit

    3. Save the change by entering the following command:

      commit

  8. Start up the BIG-IP tenant on the VELOS partition or rSeries system by entering the following command syntax:

    tenants tenant <name of tenant> config running-state deployed ; exit

    Using the previous example,

    tenants tenant my-example-bigip-tenant config running-state deployed ; exit

  9. Save the change by entering the following command:

    commit

  10. Exit the Configuration mode terminal by entering the following command:

    exit

  11. Wait for the BIG-IP tenant to complete its start up. When the BIG-IP tenant is up, log in to either the Advanced Shell (bash) as the root user or the tmsh utility as the admin user.
  12. Confirm the VELOS partition or the rSeries system expanded the disk by using the following command:

    tmsh list /sys disk

  13. To extend the /shared directory, use the following command syntax:

    Note: Do not commit all of the disk resource that you have just added to the BIG-IP tenant into extending the /shared directory, as the remaining added disk resource is needed to perform software installation into a new software slot.

    Note: This step must be performed on each slot for multi-slot VELOS tenants.

    tmsh modify /sys disk directory /shared new-size <new value in KB>

    For example, you enter the following command to extend the /shared directory to a new size of 10 GB:

    tmsh modify /sys disk directory /shared new-size 10485760

  14. Save the configuration by entering the following command:

    tmsh save /sys config

    Note: df -h output will not show changes until after a reboot of the BIG-IP tenant.

  15. Reboot the BIG-IP tenant by entering the following command:

    Note: This step must be performed on each slot for a multi-slot VELOS tenant. Alternatively, you can use the clsh reboot command for a multi-slot VELOS tenant.

    reboot

  16. When the BIG-IP tenant is up, log in to either the Advanced Shell (bash) as the root user or the tmsh utility as the admin user.
  17. To verify that the /shared directory is successfully extended to the size you have specified in step 13, enter the following command:

    tmsh show /sys disk directory

  18. Upload the ISO images/point releases using the BIG-IP tenant Configuration utility, and install to the next available slot.

    Note: Do not commit all of the disk resource that you have just added to the BIG-IP tenant into extending the /shared directory, as the remaining added disk resource is needed to perform software installation into a new software slot.

  19. Go to System > Resource Provisioning.
  20. Provision the modules as needed.
  21. Select Submit and wait for the system to complete the resource provisioning.
