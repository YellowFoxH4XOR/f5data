Issue

If users experience authentication delays when logging on to the FirePass controller, you can troubleshoot the issue by:

  • Checking the Logon reports
  • Testing dynamic group mapping
  • Optimizing fallback master groups
  • Verifying RADIUS accounting configuration

Checking the Logon reports

The Logon details screen displays each step of a user’s logon process. To view the logon details, select the user’s logon name on the Reports : Logons page.

Additionally, starting in FirePass versions 6.0.2 and 6.1.0, a timestamp for each step is displayed in the first column of the Logon details screen. Use the timestamp information to determine where authentication delays are occurring.

Testing dynamic group mapping

If dynamic group mapping is enabled, and one or more servers configured for group mapping responds slowly, user logons may also be delayed. For FirePass 6.0 and later versions, test master group mapping on the Groups : Dynamic Group Mapping page under the Master group mapping table tab, and test resource group mapping under the Resource group mapping table tab. For FirePass versions prior to 6.0, test master group mapping on the Groups : Dynamic Group Mapping page under the Master mapping table tab, and test resource group mapping under the Resource mapping table tab. If the response is slow, user logons will also be affected. In this instance, verify the configuration of each group mapping method configured under the Group mapping methods tab (FirePass 6.0 and later) or under the Request configuration tab (versions prior to FirePass 6.0). Delete any group mapping methods that are no longer in use.

Optimizing fallback master groups (FirePass version 6.x)

If fallback master groups are enabled on the : Groups : Dynamic Group Mapping page under the Group mapping sequence tab, order the fallback group list so that the most frequently used master groups appear at the top and the least frequently used master groups appear at the bottom.

Verifying RADIUS accounting configuration

If RADIUS accounting is enabled on the Device Management : Maintenance : Accounting page, and the primary RADIUS server is inaccessible or slow to respond, that will result in logon delays. Use the Test feature on the Device Management : Maintenance : Accounting page to test each RADIUS accounting server configured. If the response is slow, resolve the network or server issues resulting in the delay. If the RADIUS server does not respond, or refuses the request, verify that you configured the correct parameters for that RADIUS server. For example, that the correct port number and shared secret is specified.

Additionally, if latency and packet loss are unlikely in your environment, for example if the RADIUS accounting servers are on the same Local Area Network as the FirePass controller, you may want to configure smaller values in the Timeout and Retries fields.
