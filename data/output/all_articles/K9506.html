K9506: Non-RFC compliant SIP messages are dropped as bad messages

Topic

The BIG-IP system drops non-RFC compliant Session Initiation Protocol (SIP) messages as bad messages when received by a virtual server configured to use a SIP profile. Each dropped message incrementally increases the SIP profile Bad Messages counter.

Common causes for the SIP profile to drop a SIP message include the following:

  • SDP messages do not end with a Carriage Return/Line Feed (CR/LF)
  • The SDP message size does not end with a CR/LF

You can view the number of bad messages dropped by a SIP profile using the following tmsh command syntax:

tmsh show ltm profile sip <profile name>

For example, in the following command output, the SIP profile reports that 201 bad messages were received by the profile:

------------------------
Ltm::SIP Profile: sip
------------------------
Requests 0
Responses 0
Bad Messages 201
Packets Dropped 0

Note: The Traffic Management Microkernel (TMM) does not log dropped SIP messages. To determine why messages are dropped, you can use the tcpdump utility to inspect SIP traffic.
