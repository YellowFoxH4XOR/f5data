Known Issue

This is the result of a known issue. TMM uses the mpi_recv_desc subsystem for sending and receiving MPI messages. The mpi_recv_desc subsystem leaks memory when the transmit queue for the tzmd process is full. This issue can occur for BIG-IP systems with hardware compression cards where a large quantity of concurrent requests are processed by the compression card.

You can verify the leak by viewing the output from the bigpipe memory |grep mpi_recv_desc command.

For example:

SUBSYSTEM Alloc Max Obj size
mpi_recv_desc 140.4M 140.4M 32

If the Alloc and Max values are unusually high, the mpi_recv_desc subsystem may be experiencing a memory leak.

F5 Product Development is tracking this issue as CR132511.

This issue does not exist in the BIG-IP 10.x software branch.

Workaround

You can temporarily work around the issue and reclaim the lost memory by restarting TMM. To restart TMM, enter the following command:

bigstart restart tmm

Important: The bigstart restart tmm command will temporarily interrupt traffic processing.
