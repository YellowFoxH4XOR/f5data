Description

You need a method to validate the packet transmitted onto the wire from Trunk interface on the BIG-IP system include or exclude VLAN tag ID according to the VLAN interface defined. However, it is noticed the tcpdump is capturing VLAN tag ID information for both untagged and tagged VLAN interface. VLAN ID 1 is the untagged interface.

tcpdump -nnei 3.0 icmp
tcpdump: verbose output suppressed, use -v or -vv for full protocol decode

20:07:36.415012 f4:15:63:51:ba:05 > 00:01:d7:d0:a1:83, ethertype 802.1Q (0x8100), length 142: vlan 1111, p 0, ethertype IPv4, 10.6.6.1 > 10.6.6.2: ICMP echo request, id 31752, seq 1, length 64 out slot1/tmm0 lis= port=0.35 trunk=trunk_list
 

Environment

  • Trunk interface with untagged and tagged VLAN traffic
  • BIG-IP tcpdump utility

Cause

As explained in section Capture on a specific interface number of article K7227, tcpdump utility receives the packet when the system copies it on switch ingress from the switch fabric to the host. Thus, the VLAN ID information is included. The tcpdump utility is not an appropriate method to confirm packet put onto the wire from BIG-IP Trunk interface.

Recommended Actions

The following methods may be considered to capture Trunk interface traffic

  1. Setup port mirroring or in-line traffic tap or vendor specific feature called Switched Port Analyzer(SPAN) to capture both ingress or egress traffic on the Trunk interface of BIG-IP and copy those traffic to another port that is connected to packet analyzer host.
