Known Issue

The Traffic Management Microkernel (TMM) process may continuously restart.

This issue occurs when all of the following conditions are met:

  • The affected system is a BIG-IP Virtual Edition (VE) instance.
  • The number of CPU cores on the virtual machine does not match the licensed number of CPU cores.

    Note: You can determine the licensed number of CPU cores by locating perf_VE_cores in the /config/bigip.license file.

Impact

Traffic will be affected while the TMM process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The affected system remains in the OFFLINE status while the TMM process continuously restarts.
  • Your BIG-IP system fails over to the standby system if configured as part of a high availability (HA) system.
  • For affected BIG-IP ASM VE systems, you observe that the bd process restarts continuously after provisioning an additional module, or the bigd process continuously restarts after an upgrade.
  • You observe that the licensed number of CPU cores does not match the number of CPU cores on the virtual machine. You can determine the licensed number of CPU cores by typing the following command on the command line:

    grep perf_VE_cores /config/bigip.license

    You should observe output similar to the following example:

    # LTM, 25 Mbps, VE perf_VE_cores 2 key XXXXXXX-XXXXXXX
    perf_VE_cores : 2

    You can determine the number of CPU cores on the virtual machine by typing the following command on the command line:

    cat /proc/cpuinfo | grep processor

    You should observe output similar to the following example:

    processor       : 0
    processor       : 1
    processor       : 2
    processor       : 3

    By comparing the two example outputs, you would notice that the number of licensed CPU cores is 2, while the number of CPU cores on the virtual machine is 4.

Workaround

To work around this issue, you can manually set the provision.tmmcount database variable to the number of licensed CPU cores. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system automatically restarts the relevant processes when you manually set the database variable.

  1. Log in to the command line of the affected system.
  2. To determine the licensed number of CPU cores from the license file, type the following command:

    grep perf_VE_cores /config/bigip.license

    You should observe output similar to the following example:

    # LTM, 25 Mbps, VE perf_VE_cores 2 key XXXXXXX-XXXXXXX
    perf_VE_cores : 2

  3. To set the value of the provision.tmmcount database variable to the licensed number of CPU cores, use the following command syntax:

    tmsh modify sys db provision.tmmcount value <licensed number of CPU cores>

    For example:

    tmsh modify sys db provision.tmmcount value 2
