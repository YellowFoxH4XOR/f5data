Topic

This article applies to BIG-IP 11.x through 12.x. For information about other versions, refer to the following articles:

  • K37361453: Configuring network failover for redundant VIPRION systems (13.x - 14.x)
  • K11939: Configuring network failover for redundant VIPRION systems (10.x)

You should consider using this procedure under the following condition:

  • You want to configure network failover for redundant VIPRION systems running 11.x through 12.x.

Description

To ensure the most stable network failover configuration for redundant VIPRION systems, choose two channels for network failover communication. F5 considers it best practice to define a unicast and a multicast failover address for each VIPRION system in the device group. The unicast failover configuration uses a self IP address and Traffic Management Microkernel (TMM) switch port to communicate failover packets between each VIPRION system, and the multicast failover entry uses the management port to communicate failover packets between each VIPRION system. As an alternative to configuring the multicast failover option, you can define a unicast mesh using the management port for each VIPRION system. This is listed as an alternative option element, following.

To define both unicast and multicast failover addresses, and provide additional failover redundancy, perform the following procedures on each VIPRION system in the device group:

  • Creating a trunk dedicated for failover
  • Creating a dedicated failover VLAN
  • Creating a self IP address and associate the self IP with the failover VLAN
  • Enabling network failover for the device group
  • Defining the failover unicast address
  • Defining the failover multicast address
  • Defining a unicast mesh (alternative option)

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Configuration utility.
  • The VIPRION systems are members of the same sync-failover device group.

Procedures

Creating a trunk dedicated for failover

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Trunks.
  3. Click Create.
  4. Enter a Trunk name.

    For example:

    HA_TRUNK

  5. Add at least one interface from each blade to the Trunk.
  6. Enable Link Aggregation Control Protocol (LACP), if appropriate, for your environment.
  7. Click Finished.

Creating a dedicated failover VLAN

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > VLANs.
  3. Click Create.
  4. Enter a VLAN name.

    For example:

    HA_VLAN

  5. Select the Trunk created in the previous procedure as the interface to be used for the VLAN.
  6. Define the remaining VLAN parameters as appropriate for your environment.
  7. Click Finished.

Creating a self IP address and associate the self IP with the failover VLAN

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Self IPs.
  3. Click Create.
  4. Enter the IP address and netmask for the failover network.
  5. For VLAN, click the failover VLAN.

    For example:

    HA_VLAN

  6. For Port Lockdown, click Allow Default or Allow Custom. When choosing Allow Custom, ensure that port 1026 for the UDP protocol is included in the custom port list.
  7. Click Finished.

Enabling network failover for the device group

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Device Groups.
  3. Click the sync-failover device group in which the VIPRION systems are members.
  4. Click Failover.
  5. For Network Failover, click Enabled.
  6. Click Update.

Defining the failover unicast address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Devices.
  3. Click the local host name.

    For example:

    LTM1.example.com (Self)

  4. For Device Connectivity, click Failover Network.
  5. For Failover Unicast Configuration, click Add.
  6. For Address, click the self IP address associated with the failover VLAN.

    For example:

    10.0.0.1 (HA_VLAN)

  7. Accept the default port of 1026.
  8. Click Finished.

Defining the failover multicast address

F5 recommends that you provide additional redundancy by defining both unicast and multicast failover addresses for each VIPRION system. As an alternative to defining a multicast entry using the management port, you can define a mesh of unicast entries using the management port of each blade for each VIPRION system. The unicast mesh option is discussed later in the Define a unicast mesh (alternative option) section.

Important: This procedure requires that you configure a valid cluster member IP address for each slot on the VIPRION system. To do so, navigate to System > Clusters > Management IP Address. For more information, refer to K14392: Configuring a cluster member IP address for all slots on a VIPRION platform.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Devices.
  3. Click the local host name.

    For example:

    LTM1.example.com (Self)

  4. For Device Connectivity, click Failover Network.
  5. For Failover Multicast Configuration, for Use Failover Multicast Address, click Enabled.
  6. Accept the default multicast address and port.
  7. Click Update.

Defining a unicast mesh (alternative option)

As an alternative to defining a multicast entry using the management port, you can define a mesh of unicast entries using the cluster member IP address of each blade in each VIPRION system. The full mesh of unicast entries includes the cluster member IP address for each slot on the VIPRION system configured to communicate with the cluster member IP address for each slot on the peer VIPRION system. If you are unable to use the above multicast option, you may use the unicast mesh option.

Important: This procedure requires that you configure a valid cluster member IP address for each slot on the VIPRION system. To do so, navigate to System > Clusters > Management IP Address. For more information, refer to K14392: Configuring a cluster member IP address for all slots on a VIPRION platform.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Devices.
  3. Click the local host name.

    For example:

    LTM1.example.com (Self)

  4. For Device Connectivity, click Failover Network.
  5. For Failover Unicast Configuration, click Add.
  6. For Address, click the cluster member IP address that corresponds to slot 1 on the VIPRION system.

    Important: The cluster IP address is not the same as the cluster member IP address. Only use the cluster member IP addresses. Do not add the cluster IP address to the entries in the Failover Unicast Configuration. You can view the cluster member IP address by navigating to System > Clusters > Management IP Address.

  7. Accept the default port of 1026.
  8. Click Finished.
  9. Repeat steps 1-8 for every slot on the VIPRION system.

    Important: Failure to add the cluster member IP address of each blade in the Failover Unicast Configuration may result in failover daemon (sod) communication issues.
