Description
BIG-IP TACACS+ Accounting messages may contain multiple "reason Attribute/Value pairs as seen in the example below:

Aug 5 14:49:15 1.1.1.1 tacacsadmin unknown unknown update service=system protocol=ip task_id=2 start_time=1596638955 event=cmd_acct reason=Aug 5 07:49:15 bigip1 notice mcpd[5184]: 01070417:5: AUDIT - client tmui, user tacacsadmin - transaction #1063883-2 - object 0 - obj_delete { pool { pool_name "/Common/test-pool" pool_update_status 1 } } [Status=Command OK]
tart="Wed Au reason1=g 5 07:49:02 2020"

Environment

  • BIG-IP with TACACS+ Accounting Configured

Cause
Per the latest TACACS+ RFC draft (revision 12), an Attribute/Value (A/V) pair can have a value length of no more than 255 bytes (with each character being a single byte) however there is effectively no limit to the number of arguments. The BIG-IP populates the reason A/V pair with the entire contents of the corresponding /var/log/audit entry. If that audit log message is longer than 255 bytes/characters (including the characters "reason="), the message is then segmented into multiple A/V pairs not exceeding 255 bytes/characters each. The first A/V pair segment is prefaced with "reason=", the next "reason1=", the next "reason2=" and so on until the entire message has been captured in A/V pairs. In the above example there are two pairs with the second pair containing the remaining characters of the audit log message.

Recommended Actions

Ensure that the TACACS+ Accounting server can properly recognize and utilize the segmented reason A/V pairs, for example utilizing only the reason A/V pair for a truncated message or stitching all the reason A/V pairs together for the entire audit message.

Additional Information

  • K13762: Configuring remote RADIUS or TACACS+ accounting
  • K38054210: BIG-IP does not provide cmd and cmd-arg TACACS+ Accounting information
  • TACACS+ RFC Draft Revision 12
