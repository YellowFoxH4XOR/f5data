K10113: NTLM clients may be unable to connect to a CIFS ARX VIP if a LAN Manager authentication level is defined

Topic

If the security policy's Network Security: LAN Manager authentication level is defined, one of the following options must be selected:

  • Send LM and NTLM responses
  • Send LM and NTLM - use NTLMv2 session security if negotiated
  • Send NTLM response only

When NTLMv2 is not enabled for the ARX namespace, NTLM clients will be unable to connect to a CIFS ARX VIP if the security policy's Network Security: LAN Manager authentication level has been defined using one of the following options:

  • Send NTLMv2 response only
  • Send NTLMv2 response only/refuse LM
  • Send NTLMv2 response only/refuse LM and NTLM

When the ARX namespace is NTLM and Kerberos, the client connection fails and the ARX syslog will have an entry that appears similar to the following example:

Failed to parse an extended-security NTLM CIFS authentication request from the client at IP <IP_Address> to service test.arx.com. The error is 'The response length is not 24 bytes (NTLMSSP_RESPBADLEN)'.

When the ARX namespace is NTLM only, the client connection fails and the procdat log file has an entry that appears similar to the following example:

Note: The procdat log file is included in an ARX system diagnostic information file. The procdat log file is located in the /acopia/var/log directory of the diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Support.

VCIFS-2-6-CLIENTAUTHFAIL:: Client authentication failure for service test.arx.com: user <user_name> from <IP_Address>. Reason: client not using ntlm.
