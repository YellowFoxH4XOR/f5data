K000164216: BIG-IP VE on AWS: Admin Password Reverts to Terraform Default After Upgrade Due to cloud-init

Type
Support Solution
Published
2026-11-12
Updated
2026-11-12
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000164216

Description

After a BIG-IP VE upgrade on AWS, the admin account may no longer accept the password that was set after deployment. The password reverts to the default value set by the Terraform cloud-init user_data script.

When BIG-IP boots into a new volume after an upgrade, cloud-init does not find its run history on that volume. It runs again and resets the passwords to the original Terraform values, overwriting the values previously set by Ansible. Switching back to the previous boot location restores the correct password.

Environment

  • Product: BIG-IP LTM, Version 17.5.1.11
  • Platform: BIG-IP Virtual Edition deployed on AWS using Terraform
  • Initial configuration:
    • Terraform cloud-init (user_data) sets a default admin password at deployment.
    • Ansible logs in with the default password and changes the admin password.
  • Upgrade process: Software images are installed to an alternate boot location and the system boots into the new volume.

Cause

Cloud-init runs again on the new boot volume after an upgrade. Cloud-init does not detect its previous run history on the new volume, so it reapplies the Terraform default passwords.

Answer/Recommended Actions

Prevent the issue on future upgrades:

  1. Disable cloud-init on each BIG-IP before the next upgrade:
    tmsh modify sys db service.cloudinit value disable
    tmsh save sys config
  2. To automate this with Ansible, use the f5networks.f5_modules.bigip_sys_db module:
    - name: sys_db | disable cloudinit
  f5networks.f5_modules.bigip_sys_db:
    key: service.cloudinit
    value: disable
    provider: "{{ bigip_provider }}"
  register: bigip_system_sys_db_cloudinit
  delegate_to: localhost

If the admin account is already locked out:

  1. Use the AWS SSH key to access the BIG-IP instance.
  2. Reset the admin password manually. For reference, see K45892262: BIG-IP VE configurations might be changed by cloud-init during upgrade.

Additional Information

  • This behavior is expected. Because cloud-init runs on the new boot volume, it resets the admin password to the Terraform default. It is not a password change made by the user.
  • If the Ansible password change is not reapplied after an upgrade, the default password remains active. Disabling service.cloudinit before upgrading prevents the reset.
