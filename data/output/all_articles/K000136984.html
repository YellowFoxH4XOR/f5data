Description

Vulnerability scan pointing out weak requests when a Path Attribute is set to root.
 

Environment

  • Security Scan 
  • Vulnerability
  • Path Attribute 
  • iRule


Cause

None


Recommended Actions

Scan report points requests as weak when path attribute is set to root "/". Below iRule can be attached to the virtual server to append the keyword PATH instead of root (/) to the http requests.

Note: The following iRule is provided as an example and should be tested to determine impact to your specific environment. F5 also recommends that you review your current global iRule configuration, if any, to ensure that there are no conflicts or redundant configuration.

Sample iRule:

when HTTP_RESPONSE {
foreach mycookie [HTTP::cookie names] {
if {$mycookie starts_with "BIGip"} {
set mypath [HTTP::cookie path $mycookie]
log local0. "Cookie path: ${mypath}"
set mypath [string map -nocase {"/" "/PATH/"} $mypath]
set myvalue [HTTP::cookie value $mycookie]
HTTP::cookie remove $mycookie
HTTP::cookie insert name $mycookie value $myvalue path $mypath
HTTP::cookie attribute $mycookie insert "SameSite" "Strict"
HTTP::cookie secure $mycookie enable
HTTP::cookie httponly $mycookie enable
}
}
}



Above iRule can also be used to set below attributes:

  • SameSite to strict
  • Enables flag secure
  • Enables httponly flag.
