K000152321: ARP Incomplete and Node Down Issues after migrating the BIG-IP to F5OS rSeries Tenants.

Type
Support Solution
Published
2025-07-02
Updated
2026-03-09
Applies to
  • F5OS
  • BIG-IP
  • F5OS-A
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000152321

Description

When configuring a Self IP and VLAN on an F5OS rSeries tenant, nodes or pool members may become unreachable and appear down. Attempts to ping or communicate with these nodes fail. The ARP table shows "incomplete" or "unknown" entries for the affected IP addresses. Packet captures from both the host and tenant show ARP requests being sent, but no ARP responses are received. Switches connected to the appliance do not learn MAC addresses for the relevant ports.

Example command output:

show /net arp
--------------------------------------------------------------------------------
Net::Arp Name Address HWaddress Vlan Expire-in-sec Status
--------------------------------------------------------------------------------
<IP_ADDRESS> <IP_ADDRESS> incomplete vlan_3 0 unknown
...
arp -an
? (<IP_ADDRESS>) at <incomplete> on vlan_3

Environment

  • Product: F5OS - Appliance (rSeries)
  • Platform: Rseries device
  • Software Version: F5OS 1.8.0 (also observed after downgrade/upgrade to 1.7.0)
  • Configuration:
    • Multiple tenants deployed on the appliance.
    • VLANs and Self IPs configured directly within tenants.
    • LAG interfaces used for VLAN assignment.
    • Migration scenario from iSeries to rSeries.

Cause

This issue occurs when VLANs and Self IPs are created directly on the tenant rather than being managed from the F5OS host level and then assigned to tenants as intended by design. As a result, ARP requests generated by the tenant are not answered by network devices, leading to incomplete ARP entries, loss of connectivity, and switch-side failure to learn MAC addresses.

Recommendations

  • VLAN & Self IP Configuration Best Practices:
    • Always create/manage VLANs at the F5OS host level.
    • Assign those VLANs to appropriate LAG or physical interfaces on the host.
    • Attach VLANs to tenants using host configuration only.
    • Once attached, configure Self IPs inside each tenant for those assigned VLANs.
  • Network Troubleshooting Steps:
  • If you observe incomplete ARP entries or node-down status:
      • Confirm that switches receive ARP requests from the appliance.
      • Ensure switches are configured correctly (trunking/allowed VLANs).
      • Use packet captures (host/tenant/switch) to verify traffic flow.
    • Check cabling and port status if MAC learning fails.
  • General Advice:
    • Avoid creating VLANs/Self IPs directly in tenants unless specifically required by your architecture.
    • Validate network connectivity after any changes involving LAG/VLAN/Self-IP configurations.
    • For persistent issues despite following best practices, review switch configuration/hardware for errors.
