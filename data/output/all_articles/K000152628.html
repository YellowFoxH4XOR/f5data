Description

Automating device certificate renewal on BIG-IP LTM using an Ansible playbook fails when the private key is password-protected. The following error appears during import or API operations:

unable to load Private Key

140332609402544:error:digital envelope routines:EVP_DecryptFinal_ex:bad decrypt:evp_enc.c:664:

140332609402544:error:0906A065:PEM routines:PEM_do_header:bad decrypt:pem_lib.c:476:

/usr/bin/openssl command failed. Please ensure your key is not encrypted.

HTTP 400 errors may also be returned by the API when attempting to import a password-protected private key.

Environment

  • Product: BIG-IP LTM
  • Platform: F5 BIG-IP, Ansible
  • Automation method: Ansible playbook (reference article K48569705)
  • Certificate management system (e.g., Venafi) providing CA-signed certificates with password-protected private keys

Cause

The F5 Ansible modules does not support importing CA-signed SSL certificate. This is a supplementary document for K48569705, providing an example(of workaround) when the CA key is password enabled.

Recommended Actions

1. Remove Password from Private Key Before Import
- Decrypt the private key before importing it into BIG-IP via Ansible:
openssl rsa -in encrypted.key -out decrypted.key
- Use `decrypted.key` in your Ansible playbook for certificate/key import tasks.
 
2. Automate Password Handling When Signing CSRs
- If you must sign a CSR with a password-protected CA key within your automation, use OpenSSL’s `-passin` option:
- name: Sign CSR on localhost
  command: >
    openssl x509 -req -in "{{ 'files/' + inventory_hostname + '_server.csr' }}"
    -CA <CA_CERT_PATH>
    -CAkey <CA_KEY_PATH>
    -CAcreateserial
    -out "{{ 'files/' + inventory_hostname + '_server.crt' }}"
    -days 365
    -passin file://servitor_CA_password.txt
  delegate_to: localhost
- Ensure any plaintext password files are securely deleted after use.
 
3. Security Best Practices
- Protect all sensitive files, including decrypted keys and temporary password files.
- Consider using secure storage solutions such as Ansible Vault for managing secrets.
 
4. Module Limitations
- Current F5 official Ansible modules for device certificate management only support unencrypted keys for import operations.
- There is no built-in parameter to pass a decryption password for encrypted private keys during import.
