K000163206: Preserving HTTP Header Name Capitalization with F5 Distributed Cloud HTTP Load Balancers

Type
Support Solution
Published
2026-09-03
Updated
2026-09-03
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud WAF
Source
https://my.f5.com/manage/s/article/K000163206

Description

An F5 Distributed Cloud HTTP Load Balancer forwards HTTP header names in lowercase, causing an origin application that incorrectly treats header names as case-sensitive to reject requests with an error.

Environment

  • F5® Distributed Cloud HTTP Load Balancer
  • Origin application that expects mixed-case HTTP header names
  • Header-case preservation configured on the upstream or origin path
  • HTTP/2 enabled on the downstream or upstream connection

Cause

HTTP/2 requires HTTP field names to be lowercase. Mixed-case header names can be preserved only when HTTP/1.1 is used and header-case preservation is enabled on both the downstream and upstream paths.

Configuring header-case preservation only on the upstream or origin path is insufficient. In addition, some origin servers and application frameworks normalize header names to lowercase before processing them.

Answer/Recommended Actions

  1. Enable header-case preservation on the HTTP Load Balancer downstream configuration.
  2. Confirm that header-case preservation is enabled on the affected upstream or origin configuration.
  3. Force HTTP/1.1 on both connections:
    • Client to Load Balancer
    • Load Balancer to origin
  4. Apply the configuration and retest the request.
  5. Verify at the origin that the required header names retain their expected capitalization, such as:
    • MyExample
    • myExample
    • Example
  6. If the headers remain lowercase, enable request-header logging or debugging on the origin server to determine whether the server or application framework is normalizing them.
  7. Update the application to process HTTP header names case-insensitively, as required by HTTP standards.

Additional Information

  • Header-case preservation on only the upstream or origin path does not resolve a downstream protocol or configuration issue.
  • The downstream preserve-case setting is applied at the Load Balancer level and may affect all domains served by that Load Balancer.
  • Lowercase header names are expected when HTTP/2 is used.
  • Origin-side logging can distinguish between lowercasing by the Load Balancer and normalization by the origin server or application.
  • The recommended configuration is HTTP/1.1 with header-case preservation enabled on both downstream and upstream connections.
