Topic

You should consider using this procedure under the following condition:

  • You want to rollback a BIG-IQ upgrade by rebooting the devices to a boot location containing the older version.
  • An upgrade timed out and you need to rollback a device that was not automatically rolled back due to the upgrade failure.

Description

When performing a BIG-IQ upgrade, you may need to roll back to the previous version due to an issue on the new version of BIG-IQ software. While F5 recommends that you contact F5 Support to help you troubleshoot upgrade issues, this article describes how you can back out of an upgrade, if necessary.

Upgrade task timeouts

When an upgrade task times out, the BIG-IQ system does the following:

  • The BIG-IQ does not stop the upgrade on a device that times out during the upgrade task.
  • The BIG-IQ automatically rolls back any upgraded devices that completed the upgrade before the timeout.

You must manually reboot the device that times out to roll back to the previous version, and verify that the BIG-IQ successfully rolled back the other devices.

Upgrade task timeouts vary by version:

  • BIG-IQ 7.0.0.2, 7.1.0.3, 8.x: 3.5 hours for each device
  • BIG-IQ 6.x and all other 7.x versions: 90 minutes for each device

Note: You can only manage a BIG-IP device with a single BIG-IQ deployment (BIG-IQ standalone or BIG-IQ HA pair); therefore, when upgrading to a new version of BIG-IQ, you should perform an in-place upgrade rather than a migration to a separate BIG-IQ instance. For more information, refer to K52849965: A BIG-IP device can only be managed by a single BIG-IQ deployment.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the user interface and command line of the BIG-IQ Centralized Management (CM) devices and the BIG-IQ data collection devices (DCDs) in your deployment.

Procedures

Roll back a BIG-IQ upgrade

Use this procedure to roll back the upgrade of devices in the BIG-IQ deployment.

Impact of procedure: When booting back to a boot location with an older version of BIG-IQ, you may lose statistics data, events, alerts, and other data collected by the DCDs, and it may not be possible to restore the data from a pre-upgrade snapshot.

  1. Log in to the primary BIG-IQ CM user interface.
  2. Do one of the following:
    • If you completed the upgrade to a new version of BIG-IQ software, but you want to rollback all your devices to your previous version because there is an issue with the new version:
      • Check the software version on each device to verify that it upgraded to the new version and needs to be rolled back. To do so, follow the steps under Check the software version on each device.
    • If you did not complete the upgrade to a new version of BIG-IQ software because the upgrade task timed out:
      • First, roll back the software on the device that caused the time out by continuing to step 3 for that device.
      • Next, check the software version on the devices that the BIG-IQ automatically rolled back to verify they were rolled back to your previous version. To do so, follow the steps under Check the software version on each of those devices.

    Check the software version

    • Go to System > BIG-IQ HA > <device name> >Software Version and verify the boot location, version, and build.
    • Go to System > BIG-IQ Data Collection > BIG-IQ Data Collection Devices > <device name> > Software Update and verify the boot location, version, and build.
    • If necessary, log in to the secondary BIG-IQ and go to System > This Device > General Properties and verify the boot location, version, and build.
    • If the device is running the new version and needs to be rolled back, continue to step 3.

    Note: When a device does not complete an upgrade before the upgrade task times out, you must manually restart the device to roll back to the previous version. For more information, see Upgrade task timeouts.

  3. Reboot the primary BIG-IQ CM device to the previous boot location first. If that's already completed, reboot the peer or a DCD device. To do so, choose one of the procedures described in K36110234: Changing the default boot image on BIG-IQ systems. For convenience, the TMOS shell (tmsh) procedure appears in the following steps. Skip to step 7 if you plan to use one of the other options.
  4. Log in to the tmsh by entering the following command from the BIG-IQ command line:

    tmsh

  5. Determine the boot location containing the BIG-IQ version you want to boot back to by entering the following command:

    show /sys software

  6. Reboot by using the following command syntax:

    reboot volume <boot location>

    For example:

    reboot volume HD1.1

    If connected to the command line using SSH, you lose your connection.

  7. (Optional) When possible log in to the BIG-IQ command line. You can monitor BIG-IQ daemon startup activity by following the restjavad logs. To do so,enter the following command:

    tail -f /var/log/restjavad.0.log

    Press Ctrl + C to stop following the logs.

  8. Repeat the previous steps to roll back the BIG-IQ devices manually until all devices are on the previous boot location.

Verify the status of the deployment and re-adding the peer system

After the rollback is complete use this procedure to verify the status of managed BIG-IP systems, DCDs, and other resources and if necessary pair the BIG-IQ systems again.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. After the rollback is complete, log in to the primary BIG-IQ CM user interface.
  2. Verify that managed devices, DCDs, and the external storage devices are available.
    1. Go to Devices > BIG-IP DEVICES to view the status of your managed BIG-IP systems.
    2. Go to System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Devices to view the status of the DCDs.
    3. Go to System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Cluster > CONFIGURATION > External Storage & Snapshots to view the status of the external storage device.
  3. Check the Elasticsearch cluster health by going to System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Cluster > SUMMARY > Status.

    You may see the error described in K81715478: Error Message: At least one primary shard (and all of its replicas) are missing. This means that you are missing data; searches will return partial results, and indexing into that shard will return an exception. Follow the steps in the article to repair the cluster and restore statistics collection. It may not be possible to recover pre-upgrade statistics, events, and alert data.

  4. If necessary, pair the BIG-IP CM systems again by going to System > BIG-IQ HA and selecting on Add Standby or Add Secondary (BIG-IQ 6.1.0 and earlier).
