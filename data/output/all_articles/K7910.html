Known Issue

This is the result of a known issue. Attempting to manipulate an HTTP request after a response is sent using an iRule may cause TMM to stop responding. This behavior typically occurs within iRules that contain two or more HTTP commands that respond or redirect, or two separate iRules that contain HTTP commands that respond or redirect.

In the following iRule example, the HTTP::redirect command is used to respond with a redirect to http://www.somesite.com when an HTTP request is received:

when HTTP_REQUEST {
HTTP::redirect "http://www.somesite.com"
if {[HTTP::uri] starts_with "/"} {
HTTP::redirect "http://www.thisothersite.com"
}
}

After the redirect is issued, the iRule moves to the next sequential command, and attempts to request the URI of the HTTP request. However, the HTTP request no longer exists since the HTTP::redirect command already responded to the request. Because the request is no longer available for processing, TMM may crash.

This behavior can also occur if two iRules are associated with a virtual server and each iRule is configured to evaluate the incoming data and then manipulate the data using an HTTP command. The first iRule will evaluate the request, and the request will not be available when the second iRule attempts to evaluate the request.

F5 Product Development is tracking this issue as CR80714.

This issue does not affect the BIG-IP LTM 9.4.x software branch.
