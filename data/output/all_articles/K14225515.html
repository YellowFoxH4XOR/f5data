K14225515: The BIG-IP system may fail to process connections if return packets are received on a different VLAN than the sent packets

Type
Knowledge
Published
2019-04-11
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K14225515

Issue

By default, when matching packets against existing connection flows, the BIG-IP system considers on which VLAN the packets arrive. This can cause connections to fail if the return traffic is received on a different VLAN than the one used for egress for that flow.

This situation most often occurs on the server side in an environment with asymmetric routing in which the BIG-IP is not performing SNAT address translation. Server responses to clients may be directed back through the BIG-IP system but may ingress the BIG-IP system on a different VLAN than the one used to reach the servers.

This situation can result in the following:

  • Server-side connections may appear to hang and timeout, even if the return traffic appears in a packet capture.
  • User Datagram Protocol (UDP) traffic may be rejected with an Internet Control Message Protocol (ICMP) destination unreachable message.
  • TCP traffic may be rejected with a TCP RST. If the RST cause is available, it may show TCP 3WHS Rejected.

Recommended Actions

Depending on your network environment, you can resolve this with one of the following options:

  • Ensure that your network returns traffic to the BIG-IP system using the same VLAN on which the system sent it.
  • Enable SNAT address translation on affected virtual servers.
  • If you require asymmetric routing, refer to K13558: Allowing asymmetrically routed connections across multiple VLANs (11.x - 17.x).
