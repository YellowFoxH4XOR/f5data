K13912623: Configuring a default 'catchall' server

Description

  • The configured server processes HTTP requests with a Host header that is empty or does not match any configured server_name. 
  • The configured server should not process such requests. The client should instead receive a 404 response. 

Environment

  • NGINX Plus with configured HTTP server(s)

Cause

On request arrival, NGINX Plus tests the request’s Host header field to determine which server the request should route to. If its value does not match any server name, or the request does not contain this header field, NGINX routes the request to the default server for this port. The default server is the first one met in the configuration file, which is standard default NGINX behavior. You can also set the default server with the default_server parameter in the listen directive.

Recommended Actions

Create a new server block that will accept all these requests. In the below example, the second server processes valid requests with the 'example.com' Host header, and the first server processes all other requests:

server {
  listen 80 default_server;
  server_name _;

  return 404;
}

server {
  listen 80;
  server_name example.com;

  location / {
    proxy_pass http://backend;
    proxy_set_header Host $host;
  }
}
