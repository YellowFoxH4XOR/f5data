Known Issue

BIG-IP Edge Client may persist to the target URL following an HTTP 302 redirect response. If BIG-IP Edge Client is redirected to another location with an HTTP 302 redirect response (either by the access policy or an iRule), the client may persist to the new location even after you manually disconnect the client.

This behavior may cause issues in environments where users are globally directed to BIG-IP APM systems and then redirected to the target location using an HTTP 302 redirect response. For example, when you use BIG-IP GTM systems to load-balance DNS requests for multiple BIG-IP APM systems, the access policy or an iRule may redirect requests to the target location using an HTTP 302 redirect response. If one of the BIG-IP APM systems becomes unavailable and is marked down by a monitor, BIG-IP Edge Client will continue connection attempts to the unavailable system, rather than connecting to the original location to load-balance to another BIG-IP APM system.

Impact

BIG-IP Edge Client is unable to reconnect to the original URL until it is restarted, which causes connection failures in some environments.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In environments where the BIG-IP GTM system directs requests to BIG-IP APM systems, BIG-IP Edge Client users are unable to reconnect if the BIG-IP APM system becomes unavailable.
  • The target URL in the BIG-IP Edge Client graphical interface reflects the redirection location, rather than the original location.
  • Users are unable to connect to the BIG-IP APM system until they restart BIG-IP Edge Client.

Workaround

To work around this issue, you can restart BIG-IP Edge Client and reconnect.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
