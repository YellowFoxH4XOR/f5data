Topic

You should consider using this procedure under the following conditions:

  • You want to deny SNMP access to the BIG-IP system from any hosts including localhost.
  • You want to permit SNMP access to the BIG-IP system from a remote host, but deny access from localhost.

Description

SNMP access to a BIG-IP system allows an SNMP management system the ability to remotely manage and monitor a BIG-IP system. There may be situations where you need to control the SNMP access to the BIG-IP system from a limited list of hosts or even deny SNMP access from all hosts including localhost. By default, the BIG-IP system allows SNMP access from the localhost (127.0.0.1) only.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP system.

Procedures

  • Preventing SNMP access from all hosts including localhost
  • Allowing SNMP access from all hosts including localhost
  • Restricting SNMP access from remote hosts only

Preventing SNMP access from all hosts including localhost

If you want to prevent SNMP access from any hosts including localhost, you can remove all entries including the default entry 127.0.0.0/8 from the Client Allow List (allowed-addresses). To do so, you can use either the Configuration utility or the Traffic Management Shell (tmsh):

Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > SNMP > Agent > Configuration.
  3. From the Client Allow List, select the default entry 127.0.0.0/8
  4. Remove the entry by clicking Delete.
  5. Repeat for any other entries so that the Client Allow List is empty
  6. Click Update.

Traffic Management Shell (tmsh)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Remove all entries with the keyword none by typing the following command:

    modify sys snmp allowed-addresses none

  3. Save the change by typing the following command:

    save sys config

Allowing SNMP access from all hosts including localhost

If you want to allow SNMP access from any hosts including the localhost, you can add the network 0.0.0.0/0 to the Client Allow List (allowed-addresses). To do so, you can use either the Configuration utility or the Traffic Management Shell (tmsh):

Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > SNMP > Agent > Configuration.
  3. For Type, select Host.
  4. In the Address box, type 0.0.0.0/0 and click Add.
  5. Click Update.

Traffic Management Shell (tmsh)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Add an all networks wild card network address range using the network address 0.0.0.0/0 by typing the following command:

    modify sys snmp allowed-addresses add { 0.0.0.0/0 }

  3. Save the change by typing the following command:

    save sys config

Restricting SNMP access from remote hosts only

If you want to allow SNMP access to the BIG-IP system from a list of remote hosts but deny localhost from having SNMP access to the BIG-IP system, you can replace the default entry 127.0.0.0/8 from the Client Allow List (allowed-addresses) with the list of remote hosts. To do so, you can use either the Configuration utility or the tmsh utility:

Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > SNMP > Agent > Configuration.
  3. In the Client Allow List, select the default entry 127.0.0.0/8
  4. To remove the entry, click Delete.
  5. For Type, select Host.
  6. Enter the IP address of the desired remote host in the Address box and click Add.
  7. Repeat step 6 for the remaining desired remote hosts.
  8. Click Update.

    Note: If the all networks range of 0.0.0.0/0 is specified in the Client Allow List, removing the 127.0.0.0/8 entry will not disallow local access.

Traffic Management Shell (tmsh)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Replace the default entry with the list of IP address of the desired remote host by typing the following command:

    modify sys snmp allowed-addresses replace-all-with { <list of IP address or IP address range> }

    For example, to allow SNMP access to remote hosts 10.10.10.10 and 20.20.20.20, type the following command:

    modify sys snmp allowed-addresses replace-all-with { 10.10.10.10 20.20.20.20 }

    To allow SNMP access to remote hosts with IP subnets 10.10.0.0/255.255.0.0 and 20.20.20.0/255.255.255.0, type the following command:

    modify sys snmp allowed-addresses replace-all-with { 10.10.* 20.20.20.* }

    or

    modify sys snmp allowed-addresses replace-all-with { 10.10.0.0/16 20.20.20.0/24 }
    modify sys snmp allowed-addresses replace-all-with { 10.10.0.0/255.255.0.0 20.20.20.0/255.255.255.0 }

  3. Save the change by typing the following command:

    save sys config

  4. To test that local SNMP access is blocked, type the following command:

    snmpwalk -Os -c <snmp community> -v <snmp version> 127.0.0.1 <oid>

    For example:

    snmpwalk -Os -c public -v 2c 127.0.0.1 sysName.0

    Note: You should receive a Timeout: no response error message from the query.
