Issue

Error Message

warning mcpd[PID]: 0107185a:4: Warning generated, for version 13.1.0 or greater  : Disable virtual server /<partition>/<virtual> because it has access profile attached and its associated traffic group (/<partition>/<traffic_group_1>) is different from another one (/<partition>/<traffic_group_2>) that is also associated with a virtual server with access profile attached

In this error message, note the following:

  • <PID> is the process ID of the currently running mcpd process.
  • <partition> is the name of the partition where the configuration object resides.
  • <virtual> is the name of the virtual server.
  • <traffic_group_1> is the name of the first traffic group.
  • <traffic_group_2> is the name of the second traffic group.

For example:

warning mcpd[9872]: 0107185a:4: Warning generated, for version 13.1.0 or greater  : Disable virtual server /Common/vs_apm because it has access profile attached and its associated traffic group (/Common/test-traffic-group>) is different from another one (/Common/traffic-group-1) that is also associated with a virtual server with access profile attached

Note: An error message similar to the following may be displayed by the Configuration utility when configuring the traffic group of the virtual server: 01070734:3: Configuration error: Virtual server (/<partition>/<virtual>) with access profile attached has traffic group (/<partition>/<traffic group name>)that is different from existing one (/<partition>/<traffic group name>)

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when all of the following conditions are met:

  • You assign an access profile to virtual servers in different traffic groups.
  • You upgrade your BIG-IP APM system to 13.1.0 or later.

Starting in BIG-IP APM 13.1.0, you can configure BIG-IP APM traffic objects in a traffic group other than traffic-group-1; however, you must configure all BIG-IP APM objects in a single traffic group. You can apply access profiles only to virtual servers in a single traffic group.

Impact

During the upgrade process, the BIG-IP system disables the virtual server assigned to the second traffic group. Services accessed using these virtual servers are unavailable. 
 

Recommended Actions

Since BIG-IP APM objects can only reside in the same traffic group, all virtual servers with access profile associated need to be moved to the same traffic group. Therefore, you need to remove the BIG-IP APM settings from each affected virtual server, move all of these virtual addresses to the same traffic group, then reapply the access profiles.
