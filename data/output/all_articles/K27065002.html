Description
  • What is the advanced option SSL Configuration Bypass on Handshake Alert and when do I need it?
  • You are receiving a handshake failure, protocol version, or unsupported extension alert message during the server-side SSL handshake and it needs to be mitigated.
Environment
  • SSL Handshakes are failing.
  • Configuration objects involved are the virtual and the applicable SSL Profile.
Cause
  • Bypass on Handshake Alert feature is disabled (default)
Recommended Actions
  1. Navigate to SSL Orchestrator > Configuration
  2. Click applicable topography to modify or create a new one
    1. If you are modifying a current topography click on the pencil icon for SSL Configuration
    2. When you are creating a new topology step two is to create the SSL Configuration
  3. Click Show Advanced Setting
  4. Check/uncheck the box next to Bypass on Handshake Alert.
For outbound scenarios an option to enable or disable SSL forward proxy bypass during the Server-side SSL Handshake is available; Bypass on Handshake Alert. This setting allows the underlying SSL Forward Proxy process to bypass SSL decryption if an SSL handshake error is detected on the server side.
Additional Information

It is recommended to leave this disabled. When the above bypass option is used in conjunction with Bypass on Client Certificate Failure it can create a security vulnerability. If a colluding client and server can force an SSL handshake error, or force client certificate authentication, they can effectively bypass SSL inspection. It is recommended that these settings be left disabled.
If the issue is with the SSL Handshake on the Client-side, such as a bad CA certificate, the handshake will still fail, and a reset will be sent to the Client.
