K000137047: About Big-IP VE partitions' sizes after increasing disk storage at the hypervisor level

Type
Support Solution
Published
2023-10-13
Updated
2023-11-02
Source
https://my.f5.com/manage/s/article/K000137047

Description

Whenever you increase disk size at the hypervisor level, the physical disk Free PE / Size value will increase (as seen by running `vgdisplay` bash command).

This is enough to pass the provisioning checks at

GUI's System ›› Resource Provisioning
and/or
CLI's tmsh modify sys provision <module> level <value> command

But the actual sizes of VGs (Volume Groups) and filesystem partitions will remain unchanged.

Environment

  • BIG-IP VE
  • Increasing disk size at the hypervisor level

Cause

Design

 Recommended Actions

After disk size was increased at the hypervisor level please follow K14952: Extending disk space on BIG-IP VE article to extend /var /var/log /config /shared and /appdata directories' sizes

There are no specific guidelines for specific sizes, but please take into consideration minimums from System requirements for BIG-IP VE modules


One approach is to increase /var /var/log /config /shared and /appdata directories by the same proportion
So if you increased disk size at the hypervisor level by 50%, it's safe to do the same for directories
Example: tmsh show /sys disk directory outputs:

Directory Name                 Current Size   New Size

--------------                 ------------   --------

/config                        503808         -

/shared                        512000         -

/var                           503808         -

/var/log                       512000         -

To increase /config directory proportionally, multiply 503808kB by 1.5 factor: 503,808 * 1.5 = 755,712kB

  1. Thus to set /config size to 1.5 of its original value please run:
    tmsh modify /sys disk directory /config new-size 755712
  2. Save the changes
    tmsh save /sys config
  3. Reboot the system
    reboot

 

Important Note: You must shut down the BIG-IP VE during the disk provisioning steps, and the system will not be available for traffic processing. You should perform this procedure during a suitable maintenance window. Increasing the disk size on the BIG-IP VE is irreversible because F5 does not support disk shrinking. Increasing the disk size beyond 1.9 TB may render the system unbootable. F5 recommends the extended disk space should not exceed 1.9 TB.
