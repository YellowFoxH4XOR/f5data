K70894946: Unable to delete a legacy application in BIG-IQ using Force-Delete

Type
Support Solution
Published
2021-11-12
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K70894946

Description
When trying to delete a legacy application in BIG-IQ, via a force-delete command, there is an error and the application is not deleted.

In the /var/log/restjavad.0.log file, you see these log entries:

[ERROR][<<timestamp>>][/cm/global/tasks/force-delete/<<task ID>>/worker ForceDeleteTaskWorker] unable to retrieve config to delete.: Get document for key: cm/global/classic-configs/<<config ID>> returned nothing
[DEBUG][<<timestamp>>][/cm/global/tasks/force-delete/<<task ID>>/worker ForceDeleteTaskWorker] Task finished with status FAILED: unable to retrieve config to delete.: Get document for key: cm/global/classic-configs/<<config ID>> returned nothing
[DEBUG][<<timestamp>>][/cm/global/tasks/force-delete ForceDeleteTaskCollectionWorker] Handling PUT from https://localhost/mgmt/cm/global/tasks/force-delete/<<task ID>>/worker - FAILED task http://localhost:8100/cm/global/tasks/force-delete/<<task ID>>
[DEBUG][<<timestamp>>]HikariCP - Reset (autoCommit) on connection org.postgresql.jdbc.PgConnection@69811012
[DEBUG][<<timestamp>>][/cm/global/tasks/force-delete/<<task ID>>/worker ForceDeleteTaskWorker] Processing status: FAILED
[DEBUG][<<timestamp>>][/cm/global/tasks/force-delete/<<task ID>>/worker ForceDeleteTaskWorker] Allowing reentrant execution in status FAILED
[DEBUG][<<timestamp>>][/cm/global/tasks/force-delete/<<task ID>>7bd9/worker ForceDeleteTaskWorker] Unregistering worker

Environment

  • BIG-IQ Application Legacy
  • Force remove
  • Changed MachineID

Cause
Legacy applications are linked to an internal managed-device identifier that is called machineId. This ID is created in the BIG-IP and imported into BIG-IQ when discovering the device. Also, this ID might change in some circumstances, some examples can be found in K23145710: Identifying and removing invalid duplicate device objects on the BIG-IQ system.

If the machineId changes, there will be a mismatch in UUID and machine ID, thus the force-delete API is unable to find the application.

Recommended Actions

  1. On BIG-IQ CM, list BIG-IP's uuid and machineId and verify that there is a mismatch. 
restcurl cm/system/machineid-resolver | grep -B 5 <<BIG-IP's IP>>

Note: If you wish to list all devices' uuid and machineId from BIG-IQ for comparison purposes, use the following command:
restcurl cm/system/machineid-resolver | grep "uuid\|machineId\|hostname"
  1. Note the output for the field "uuid"
  2. In the BIG-IP, edit the file "/config/f5-rest-device-id" and replace whatever value is in there with the value from "uuid"  (without the quotes) obtained in step 2.
  3. In the BIG-IP, restart restjavad:
    tmsh restart sys service restjavad
  4. Wait for 5 minutes, then in the BIG-IP, run:
    restcurl /shared/resolver/device-groups/cm-bigip-allDevices/devices/<<uuid>> | jq .machineId
In step 5, make sure to replace "<<uuid>>" for the value obtained in step 2.
  1. Make sure the output is the same as in step 2.
  2. In the BIG-IQ CM GUI, go to the Devices tab and re-import and rediscover LTM for BIG-IP.
    If the discovery / import throws any error, go to the CM console and restart restjavad with "tmsh restart sys service restjavad", wait until GUI is back online, and retry.
  3. Then, in the BIG-IQ CM, run:
    restcurl /shared/resolver/device-groups/cm-bigip-allDevices/devices/<<uuid>> | jq .machineId
In step 8, make sure to replace "<<uuid>>" for the value obtained in step 2.
  1. Make sure the output is the same as in step 2.
  2. Attempt to force-delete the application again, this time it should work.
restcurl -X POST cm/global/tasks/force-delete -d '{"configSetName":"<<Legacy Application Name>>"}'
