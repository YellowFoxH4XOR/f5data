K000156751: Kerberos error "Request ticket server HTTP/app.lab.lan@LAB.LAN kvno x not found in keytab"

Type
Support Solution
Published
2025-10-02
Updated
2025-10-02
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.0
Source
https://my.f5.com/manage/s/article/K000156751

Description

Accessing app website through APM, protected with Kerberos authentication, you see this Kerberos error

GSS-API error gss_accept_sec_context: d0000 : Unspecified GSS failure. Minor code may provide more information
GSS-API error gss_accept_sec_context: 186a5 : Request ticket server HTTP/app.lab.lan@LAB.LAN kvno 3 not found in keytab; keytab is likely out of date

kvno identifies a specific Kerberos service key, 

Environment

  • BIGIP deployed as APM
  • APM configured with Kerberos authentication on client side

Cause

Root cause of this Kerberos error is the Kerberos service ticket, included in the GSSAPI KRB5 packet and sent by client to APM, is encrypted by KDC/TGS with a Kerberos service key that has a different kvno that the Kerberos service key included in the keytab file on APM.

This may happen when a new keytab file has been created and uploaded to APM but computers still have cached Kerberos service tickets obtained from KDC/TGS that were encrypted with a previous Kerberos service key.

From a tcpdump you can check Kerberos service key's kvno

ticket
  tkt-vno: 5
  realm: LAB.LAN
  sname
    name-type: kRB5-NT-SRV-INST (2)
    sname-string: 2 items
      SNameString: HTTP
      SNameString: app.lab.lan
  enc-part
    etype: eTYPE-AES256-CTS-HMAC-SHA1-96 (18)
    kvno: 3   <<=====
    cipher […]:

From APM, you can dump the Kerberos service keys included in its keytab file. Both 'kvno' must match, otherwise APM will consider both Kerberos service keys do not match

KVNO Timestamp           Principal
---- ------------------- ------------------------------------------------------
   4 01/01/1970 01:00:00 HTTP/app.lab.lan@LAB.LAN (aes256-cts-hmac-sha1-96)

Recommended Actions

You can clear Kerberos cache on computers forcing to fetch a new Kerberos service ticket.

If  that does not work, you can create a new keytab file. This will make KDC/TGS to have a new Kerberos service key that will also be included in the keytab file.

After that, you will need to clear Kerberos tickets on computer so next time user tries to access app website through APM, it will have to fetch new Kerberos service ticket from KDC/TGS, encrypted by that new Kerberos service key.
