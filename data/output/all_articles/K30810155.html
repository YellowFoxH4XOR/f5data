K30810155: A virtual server is unreachable after moving a virtual-address from one floating traffic-group to another since GARP is not sent out

Type
Support Solution
Published
2023-06-20
Updated
2023-06-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.0.0, 14.0.1, 15.0.0, 15.0.1, 15.1.0, 15.0.X, 14.1.2, 14.1.0, 14.0.X
Source
https://my.f5.com/manage/s/article/K30810155

Description

Gratuitous ARPs (GARPs) are not sent out when moving a virtual address from one floating traffic-group to another.
 
10.10.10.0 from traffic-group-1 to traffic-group-2
(/Common)(tmos)# modify ltm virtual-address 10.10.10.0 traffic-group <desired_traffic_group>
 

Environment

  • BIG-IP with 2 or more Traffic Groups configured.
  • The traffic groups are active on different devices.
  • Moving a virtual address from one floating traffic-group to another.
  • A virtual server is unreachable when changing traffic groups.
  • Upstream has not received the GARP of the change from BIGIP. 
  • The traffic is going through the device which is active for a previous floating traffic-group.
 

Cause

Bug ID 839401 : Moving a virtual-address from one floating traffic-group to another does not send GARPs out.
 

Recommended Actions

As a workaround, Disable and Enable the ARP setting of the desired virtual address after moving the virtual address. This forces GARPs to be sent out.
  1. Log in to the Traffic Management Shell (tmsh) by typing the following command: 
    tmsh
  2. Disable and enable desired ARP setting for a virtual address using the following command syntax:

    modify ltm virtual-address <nnn.nnn.nnn.nnn> arp enabled|disabled

    For example, to enable ARP for virtual address 10.10.10.0, type the following command: 
    modify ltm virtual-address 10.10.10.0 arp disabled
modify ltm virtual-address 10.10.10.0 arp enabled
    3. Save the change by typing the following command:
save /sys config
To fix the bug, consider upgrading to the fixed version: 16.0.0, 15.1.0.2, 15.0.1.4, 14.1.2.5.
