Known Issue

Network failover packets that are transmitted over the management interface may have an incorrect source IP address.

This issue occurs when all of the following conditions are met:

  • Members of a device service clustering (DSC)/high availability (HA) group have management ports on different IP networks.
  • The DSC/HA group members are configured for network failover.
  • Network failover traffic uses a Traffic Management Shell (tmsh) management route to communicate over the management networks.

After you reboot, network failover packets may be transmitted with an internal (127.x.x.x/8) source address.

Impact

If the affected packets pass through a firewall or router that drops packets with improper or unrouteable source addresses, then the members of the device group cannot communicate through the channel.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After you reboot, network failover packets are transmitted with an internal (127/8) source address.
  • Members of a DSC/HA group experience an unexpected failover or active-active condition.

Workaround

To work around this issue, you can remove the tmsh management route from each member of the device group, and add a static route to the Linux kernel routing table. To do so, perform the following procedure on each member of the device group:

Impact of workaround: This procedure requires you to reboot the system, which temporarily disrupts traffic or causes an active system to fail over.

  1. Log in to the BIG-IP command line.
  2. Delete the existing static tmsh management route by using the following command syntax:

    tmsh delete /sys management-route <route>

    For example, to remove a tmsh route to the 10.10.20.0/24 network, type the following command:

    tmsh delete sys management-route 10.10.20.0/24
  3. Optional: If you have multiple static tmsh routes to delete, repeat step 2 to delete each route.
  4. Save the configuration by typing the following command:

    tmsh save sys config
  5. Create a Linux startup script with the desired static route by using the following command syntax:

    echo "<target> via <gateway> dev eth0" >> /etc/sysconfig/network-scripts/route-eth0

    For example, to create a script that adds a Linux static route to the 10.10.20.0/24 network by way of the 10.10.10.254 gateway, type the following command:

    echo "10.10.20.0/24 via 10.10.10.254 dev eth0" >> /etc/sysconfig/network-scripts/route-eth0
  6. Optional: If you have multiple Linux static routes to add, repeat step 5 for each static route.
  7. Reboot the system by typing the following command:

    reboot

Important: Repeat this procedure for each member of the device group.
