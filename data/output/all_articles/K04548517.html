Description

iApps LX packages such as F5 Telemetry Streaming respond to a REST request with code 404 like below after restoring BIG-IP configurations from UCS archive or after an upgrade. The directory /var/config/rest/iapps/<package name>, which should exist when an iApps LX package is correctly installed, does not exist on the system.

# curl -ks -u 'admin' -H 'Content-type: application/json' https://localhost/mgmt/shared/telemetry/info | jq .
Enter host password for user 'admin':
{
  "code": 404,
  "message": "",
  "referer": "127.0.0.1",
  "errorStack": []
}

Environment

  • Restoring configuration from UCS
    • UCS archive is taken on a device that an iApps LX package such as F5 Telemetry Streaming or AS3 is installed
    • The UCS archive is restored on a BIG-IP device
    • The BIG-IP device may or may not have the iApps LX package installed before loading UCS
  • Upgrading BIG-IP
    • iApps LX package such as F5 Telemetry Streaming or AS3 is installed before upgrade

Cause

The issue is due to ID 929213.

There is a static timeout of 60 seconds for the iApps LX RPM building process. The 60 seconds may not be enough to complete the whole process for some iApps LX packages, and the RPM file to restore the iApps LX package and its configurations will not be included in the UCS archive if the issue occurs.

Recommended Actions

  1. When taking a UCS on BIG-IP versions that do not have the ID fixed, please follow the workaround in ID 929213 to re-install the package after loading UCS.
  2. On BIG-IP versions that have the ID 929213 fixed, there is a new DB key iapplxrpm.timeout available to configure the timeout value (default 60 seconds) for the building process of iApps LX RPM package. Configure the DB key before taking a UCS.
    The time it takes to build RPM package depends on how much resource available on the BIG-IP system, and you can change the value to suit your system.

    For example, run the command below to change the value to 300 seconds.
    Impact of workaround: Increasing the db key and restarting restjavad should not impact service traffic.

    tmsh modify sys db iapplxrpm.timeout value 300
    tmsh restart sys service restjavad
