K000161915: Performance degradation after migration to BIG IP VE from hardware appliances

Description

After migrating from BIG-IP hardware appliances to BIG-IP LTM Virtual Edition (VE), poor performance and outages may occur if the VE license enforces a throughput or CPU core limit that is lower than what the underlying virtual machine (VM) is provisioned with, or lower than what production traffic demands.

Symptoms include:

  • Performance degradation and intermittent outages.
  • LTM log messages such as:

Bandwidth utilization is 248 Mbps, exceeded 75% of Licensed 200 Mbps

Bandwidth utilization is 160 Mbps, exceeded 75% of Licensed 200 Mbps

 

  • CPU spikes in performance graphs.
  • Only a subset of allocated CPUs used for traffic processing.

 

Environment

  •  BIG-IP LTM Virtual Edition (VE)
  • VE is licensed for a specific throughput (Mbps) and N number of CPU cores less than the number of CPU cores allocated to the VM 

 

Cause

The VE license enforces a hard cap of specified throughput in Mbps and limits traffic processing to N CPU cores. Traffic exceeding the licensed throughput is throttled or dropped, and only N number of TMM processes are active, regardless of additional CPUs allocated to the VM.

 

Answer/Recommended Actions

  1. Upgrade to a higher throughput VE license (e.g., 1 Gbps, 3 Gbps) to accommodate production traffic requirements.
  2. Adjust VM CPU allocation to match the licensed core count for optimal resource utilization. If more cores are needed, upgrade the license to higher number of CPU cores to match VM CPU allocation.

 

Additional Information

The throughput limit on VE is a hard cap, enforced separately on ingress and egress, and is independent of the hypervisor’s resource allocation.

Only the number of CPU cores licensed will be used for traffic processing, regardless of how many CPUs are allocated to the VM.

This behaviour is expected and by design for BIG-IP VE licensing.
