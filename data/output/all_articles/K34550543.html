Description

  • Kerberos authentication fails for Mac or iOS users using the Safari Browser.
  • When trying to connect your user may be presented with a error message similar to
    Your session could not be established. Invalid Nonce

Environment

  • Mac OS or iOS devices
  • Safari Browser
  • Kerberos authentication
  • BIG-IP APM
  • MRH session cookie

Cause

This issue is the result of the Safari Browser returning the original MRHSession cookie after the first 24 bits have been rotated by the BIG-IP APM as part of the Access policy evaluation.
Safari does not handle cookie replacement correctly (RFC6265 section 4.1.2), in regard to what the user agent should do with a cookie that has an updated value.

Recommended Actions 
Disabling BIG-IP APM automatic session ID rotation

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:
    tmsh
  2. To view the current configuration setting for session ID rotation, type the following command:
    list /sys db apm.rotatesessionid
  3. Disable automatic rotation of BIG-IP APM session IDs by typing the following command:
    modify /sys db apm.rotatesessionid value disable
  4. Save the change by typing the following command:
    save /sys config

Additional Information

Session ID rotation:
BIG-IP APM tracks all client sessions using a unique, proprietary Session ID. During the course of an access policy evaluation, the Session ID randomly rotates to prevent session hijacking and fixation attempts.
In BIG-IP APM 11.2.0 and later, Session ID rotation is enabled by default. This feature may cause issues with older clients or deployments using iRules if they rely on remembering the Session ID.
