Issue

In the FirePass 5.x branch prior to version 5.5.2 with cumulative hotfix HF-552-11, and in the FirePass 6.x branch prior to version 6.0.2, the FirePass controller 4100 and 4300 hardware platforms would issue ARP requests where the sender IP address field could be set to the IP address of any interface, rather than the interface from which the ARP request was issued.  This behavior corresponded to a Linux kernel setting of the net.ipv4.conf.all.arp_announce variable to 0.  This setting, combined with a common MAC address used by all interfaces of the switch ports, and certain network topologies, could cause connected switching and routing equipment to create incorrect entries in ARP tables or other data structures, such as those used for Layer 3 (network layer) switching.

Beginning in FirePass 6.0.2, the value of the net.ipv4.conf.all.arp_announce variable is set to 1. This setting forces ARP requests from the FirePass controller to prefer the IP address of the local interface on which the ARP packet is sent, when entering an IP address into the sender IP address field of an ARP request.

Note: The 4300 hardware platform is supported on FirePass 6.0.1 and later.

Additionally, cumulative hotfix HF-552-11 has been issued for FirePass 5.5.2. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.
