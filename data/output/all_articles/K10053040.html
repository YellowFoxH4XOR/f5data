Description

After booting to 15.1.x volume, SSLO 7.1.9 dashboard is showing "Bad" status in "peer HA verification response" section. This causes overall status of SSLO to be "Bad".

Environment

  • SSLO
  • After BIG-IP Upgrade

Cause

In SSLO 7 it is required to break HA Trust before upgrading. See Upgrading BIG-IP ISO with F5 Guided Configuration for SSL Orchestrator in high availability for more details.

Recommended Actions

Perform any of the following actions.

Re-Create Device Trust Using iControl REST API

  1. Execute the command below to collect uuid of both units.

    restcurl shared/resolver/device-groups/tm-shared-all-big-ips/devices | jq -r '.items[] | .uuid,.address' | xargs printf "restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices/%s # %s\n"

    Example Output:

    restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices/a07ece78-2d9d-40c7-9de4-ff38f1f732a4 # 10.0.116.225

  2. On both units, perform the commands from the output of Step 1 to delete existing device information in the REST.

    restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices/<uuid>

  3. On both units: Restart the restjavad service.

    bigstart restart restjavad

  4. On the Active or good unit, poke BigIpFailoverStateWorker to pull configuration from CMI and retry device trust.

    restcurl -X POST -d '{}' tm/shared/bigip-failover-state
    Note: If you receive a "code": 400, response; try the command again until you receive a {} response.

Remove and Re-Create Device Trust

Break HA; Break Trust; Recreate Trust; Recreate HA (all this after the upgrade):
  1. Go to Device Management > Device Groups.
  2. Click on the device group <device group name>. I believe this can be done on any of the devices at this point.
  3. Remove both the members & click on update.
  4. Go to Device Management > Device Trust. => Perform this step on both devices
  5. Click on Reset Device Trust & select the option Generate new self-signed authority. => Perform this step on both devices
  6. Go to Device Management > Device Trust > Device Trust Members & add the peer device.
  7. Go to Device Management > Device Groups.
  8. Click on the device group <device group name>.
  9. Add both the devices & click on update.
  10. Go to Device Management > Overview & do a sync.
  11. Now verify the HA status is good & both the devices are in sync.

Boot to Previous Volume and Follow Upgrade Guidance

Another solution is to boot back to previous volume on both device and then break HA and follow the upgrade procedure as before (as per Upgrading BIG-IP ISO with F5 Guided Configuration for SSL Orchestrator in high availability.

Additional Commands

Additional solution that was found to be helpful is to run the following commands:

restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices
restcurl -X POST -d '{}' tm/shared/bigip-failover-state
