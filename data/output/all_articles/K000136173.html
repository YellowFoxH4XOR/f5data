Description

When publishing an API that includes a Developer Portal cluster it fails with the following error:

Error performing the requested operation. The API Connectivity Manager (ACM) host cannot resolve the hostname (FQDN) of the Developer Portal internal cluster. Ensure the ACM host can resolve the FQDN and try again.

Environment

NSM/ACM

Cause

The internal Dev Portal hostname and service must be resolvable and accessible from the NMS/ACM server.

Recommended Actions

Find the internal Dev Portal Hostname and Listeners port(s) on the NMS/ACM server with the following navigation:

  • Go to API Connectivity Manager -> Infrastructure
  • Click on Workspace Name
  • Click on Environments Name
  • Click on Actions (three dots, furthest link to the right) from the Developer Portal row
  • From the dropdown menu select 'Edit Portal <-> API Connectivity Manager Connectivity'

Check if the internal Dev Portal Hostname is resolvable on the NMS/ACM server with use of dig, nslookup, ping, etc. If it's not resolvable then make adjustments in your environment to make it so.

Check if the internal Dev Portal Listeners port (81 by default) is accessible from the NMS/ACM server with the use of curl (should return '400 bad request' and json data):

curl <internal_dev_portal_hostname>:81/api/v1/devportal -v

Additional Information

By default, the internal Dev Portal server is the hostname provided for the Developer Portal cluster, prefixed with acm.. For example: acm.dev-portal.io. This internal Dev Portal virtual server listens on port 81 by default.

  • The hostname can be changed however it cannot be the same name as the hostname provided for the Developer Portal cluster.
  • The Listeners port (81 by default) can be changed or a new one can be added, e.g. Port 443 and TLS Enabled.

The internal Dev Portal virtual server NGINX configuration file can be found on the Developer Portal:  /etc/nginx/http.d/acm.gen.conf
