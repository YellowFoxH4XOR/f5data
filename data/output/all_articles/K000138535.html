K000138535: LACP state of interface flapping in VELOS LAG configured in Passive <-> Passive mode

Type
Support Solution
Published
2024-02-08
Updated
2024-02-08
Applies to
  • F5OS
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000138535

Description

LACP state of one or more interfaces in LAG on VELOS is continuously flapping after a blade reboot, with repeated messages similar to the following observed in velos.log:

blade-1(p1) lacpd[1]: priority="Info" version=1.0 msgid=0x3401000000000038 msg="Link removed from aggregation." key="1/2.0".
blade-1(p1) lacpd[1]: priority="Info" version=1.0 msgid=0x3401000000000036 msg="Link added to aggregation." key="1/2.0".

LAG in question is directly connected between two VELOS systems, and both are configured in PASSIVE mode with a FAST interval:

lacp interfaces interface ha_lag
 config name ha_lag
 config interval FAST
 config lacp-mode PASSIVE

Environment

  • LACP
  • Interface directly connected between two VELOS systems in LACP LAG
  • After reboot

Cause

This is expected at the time of this article's publication. ID1504149 tracks this behaviour.

Recommended Actions

LACP should not be used in a Passive <-> Passive configuration between two VELOS systems, as the aggregation will never come up.

To avoid or recover from this issue, configure at least one side as ACTIVE mode.

Additional Information

When this issue occurs there will also be a lot of log churn inside tenants configured to use the LAG in question.
