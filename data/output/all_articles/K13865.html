Known Issue

The BIG-IP GTM system may incorrectly associate a health monitor with a virtual server.

This issue occurs when one of the following conditions is met:

  • You add a new BIG-IP GTM virtual server with a destination IP address and port number that matches an existing BIG-IP GTM virtual server.
  • You add a new BIG-IP GTM virtual server with a translation IP address and port number that matches an existing BIG-IP GTM virtual server.

Any health monitors associated with the existing virtual server are also associated with the new virtual server when they have a matching IP address and port number.

Impact

The newly-added virtual server may be incorrectly marked down.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The newly-added BIG-IP GTM virtual server appears to be available for the first one to two minutes, and after that the system incorrectly marks it down.
  • You observe activity log entries in the /var/log/gtm file that appear similar to the following example:

    gtmd[8365]: 011ae0f2:1: Monitor instance /Common/bigip 10.1.1.1:80 UNKNOWN_MONITOR_STATE --> UP from 1.1.1.210 (UP)
    gtmd[8365]: 011a6005:1: SNMP_TRAP: VS virtual1 (ip:port=10.1.1.1:80) (Server /Common/ltm.example.com) state change blue --> green
    Saving running configuration...
    /config/bigip_gtm.conf
    gtmd[8365]: 011ae0f2:1: Monitor instance /Common/bigip 10.1.1.1:80 UP --> DOWN from gtmd (no reply from big3d: timed out)
    gtmd[8365]: 011a6006:1: SNMP_TRAP: VS virtual1 (ip:port=10.1.1.1:80) (Server /Common/ltm.example.com) state change green --> red ( Monitor /Common/bigip from gtmd : no reply from big3d: timed out)

Resolution

Status

F5 Product Development has assigned ID 390576 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, you can reconfigure the virtual servers and translation IP addresses to use unique IP addresses on the BIG-IP GTM servers.
