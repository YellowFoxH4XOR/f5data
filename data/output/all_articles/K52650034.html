Description:

The system suffers from network connectivity issues. You may observe one or many phenomenons such as:

  • Health Monitor flaps between up and down randomly
  • HA and Configuration Synchronization is unstable
  • Control plane daemons communication becomes unstable or impossible

The /var/log/kern.log shows the message:

kernel: nf_conntrack: table full, dropping packet

 

Environment:

  • Linux Kernel
  • Connectivity issues
  • Health Monitor check flaps
  • HA and Configuration Synchronization

Cause:

When running multiple instances of a monitor with short interval time on a very busy BIG-IP system, e.g for a TCP monitor with short interval running more than a couple of thousand instances:

ltm monitor tcp /Common/ltm_node_health {
    adaptive disabled
    defaults-from /Common/tcp
    destination *:*
    interval 2   <<<<<<<<<<<< Low time interval
    ip-dscp 0
    recv none
    recv-disable none
    send none
    time-until-up 15
    timeout 5
}

When you have hundreds of instances of a monitor like the above running this causes the monitors to stop working or become unstable as there are a lot of connections in time-wait on the conntrack table when this number reaches the max limit/threshold configured.

You can check the maximum value with the following command:

cat /proc/sys/net/nf_conntrack_max

You can check the number of connections on the conntrack table by the command:

cat /proc/sys/net/netfilter/nf_conntrack_count

 

Recommended Actions:

  1. One approach to try is to reduce the length of TIME-WAIT in conntrack table. The command to do this is as follows:

    sysctl -w net.netfilter.nf_conntrack_tcp_timeout_time_wait=30

    The default value is 120 seconds, you can reduce it to 60s or 30s.

    If you want the solution to survive reboots, upgrades, RMAs, etc., run the command below. From the tee command to the last EOL is one command. Copy all the lines below and paste into your terminal.

    tee -a /config/startup << EOL
    # Recommended action in K52650034, TIME_WAIT APPROACH
    K52650034_WA_EXISTS=\$(grep net.netfilter.nf_conntrack_tcp_timeout_time_wait /etc/sysctl.conf | wc -l)

    if [ "\$K52650034_WA_EXISTS" -eq 0 ]; then
        echo 'net.netfilter.nf_conntrack_tcp_timeout_time_wait = 30' >> /etc/sysctl.conf
    fi
    EOL

  2. You can try increasing the custom short interval value on the monitor to the BIG-IP default value of 5 seconds.

  3. You can also increase the table size by the below process:

    a) Take a backup copy of the existing file with the following command:

    cp /etc/modprobe.d/f5-platform-el7-conntrack-default.conf /var/tmp/f5-platform-el7-conntrack-default.conf

    b) Edit file with vi editor /etc/modprobe.d/f5-platform-el7-conntrack-default.conf

    c) Increase the hashsize value:

    options nf_conntrack hashsize=262144

    d) Save the file.

    e) Reboot the system.   

    f) If you want the conntrack table size to survive reboots, upgrades, RMAs, etc., run the command below.  From the tee command to the last EOL is on command Copy all the lines below and paste into your terminal.

    tee -a /config/startup << EOL

#Recommended action in K52650034, HASH SIZE APPROACH
K52650034_HASH_EXISTS=\$(grep hashsize=262144 /etc/modprobe.d/f5-platform-el7-conntrack-default.conf | wc -l)

if [ "\$K52650034_HASH_EXISTS" -eq 0 ]; then
    sed -i 's/16384/262144/g' /etc/modprobe.d/f5-platform-el7-conntrack-default.conf
    echo 262144 > /sys/module/nf_conntrack/parameters/hashsize
fi

EOL
