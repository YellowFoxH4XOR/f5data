Topic

You should consider using this procedure under the following conditions:

  • You want to upgrade your CISCO Application Policy Infrastructure Controller (APIC) environment, and you have deployed service graphs using the F5 iWorkflow device.
  • You have existing BIG-IP high-availability (HA) clusters that you want to use in service graphs that you deployed with APIC and iWorkflow.

Description

If you upgrade a CISCO APIC that takes advantage of the F5 iWorkflow device package to integrate F5 BIG-IP systems, you may have to also upgrade iWorkflow. If after you review K11198324: F5 iWorkflow compatibility matrix, you determine that you need to upgrade iWorkflow, then F5 recommends that you complete the following tasks, in the following order:

  1. Upgrade the APIC nodes
  2. Upgrade iWorkflow
  3. Upload a new device package to APIC
  4. If required, upgrade any BIG-IP devices

Note: For information about upgrading the Cisco APIC, iWorkflow, and BIG-IP environments, refer to the following documentation:

  • Cisco APIC upgrade documentation

  • K92714254: Upgrading F5 iWorkflow
  • F5 BIG-IP documentation

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have confirmed that the APIC and iWorkflow versions are compatible.

    Note: For information about compatibility between Cisco APIC and iWorkflow, refer to K11198324: F5 iWorkflow compatibility matrix.

  • You must have administrative rights on the APIC controllers.
  • You must have administrative rights on the iWorkflow devices.
  • You must have administrative rights on any BIG-IP devices you will upgrade.
  • You must have adequate disk space to complete the installation.
  • If you have an iWorkflow cluster, it must be synchronized and healthy.
  • All managed BIG-IP devices are healthy.

Note: Administrators using Virtual Clustered Multiprocessing (vCMP) guests with APIC may also need to create a vCMP host connector. For more information, refer to K12237415: F5 iWorkflow APIC connector requires vCMP connector to communicate with vCMP guests.

Procedures

  • Uploading the updated APIC device package
  • Creating and uploading a new APIC device package
  • Uploading the F5DevicePackage.zip to the CISCO APIC environment

Uploading the updated APIC device package

During the iWorkflow upgrade process, the system, by default, upgrades existing connectors; this includes existing APIC device packages. If you have uploaded F5 APIC device packages before upgrading iWorkflow, then download the updated F5DevicePackage.zip files, and upload them into the CISCO APIC environment, as follows. Upgrading the iWorkflow devices will not impact traffic that is traversing the APIC environment, or traffic that is traversing the BIG-IP devices.

Impact of procedure: There should be no impact to iWorkflow or CISCO APIC as a result of downloading and uploading the updated F5DevicePackage.zip file.

  1. Log in to the iWorkflow Configuration utility with your administrator user name and password using the following syntax:

    https://x.x.x.x/ui/login

    For example:

    https://192.168.9.9/ui/login

  2. From the top navigation menu, select the Cloud component.
  3. Select the Clouds panel, and double-click the required connector name to expand the properties.
  4. Under APIC Device Package F5DevicePackage.zip, click the link to initiate the download to your local workstation.  

    Note: Complete the next steps using the CISCO APIC administrative GUI.

Creating and uploading a new APIC device package

If you want to create new F5 APIC device packages based on the updated iWorkflow connector versions, complete the following procedure. You must upload the newly created device packages into the CISCO APIC environment. 

Impact of procedure: There should be no impact to iWorkflow or CICSO APIC as a result of creating a new F5DevicePackage.zip file and uploading it to the CISCO APIC environment.

  1. Log in to the iWorkflow Configuration utility with your administrator user name and password using the following syntax:

    https://x.x.x.x/ui/login

    For example:

    https://192.168.9.9/ui/login

  2. From the top navigation menu, select the Cloud component.
  3. In the Clouds header, click the + icon, and type the cloud name, and if desired, a description.
  4. From the Connector Type menu, select Cisco APIC.
  5. Click Save.

    The Cloud panel should close.

    Note: At this point you are associating a new L4-L7 template with the newly created APIC cloud connector.

  6. On the Catalog panel, click the + icon.
  7. Type a name for the new template.
  8. Select the Input Parameters.
  9. Select the APIC cloud connector that you just created.
  10. From the Application type menu, select the appropriate type of application.  
  11. Complete the required options and define the necessary default values.
  12. To complete the association of this L4-L7 template to the cloud connector, click Save.  

    The Catalog panel should close.

  13. Return to the Clouds panel, and to expand the properties, double-click the required connector name.
  14. To initiate the download to your local workstation, under APIC Device Package, click the link.

    Note: The F5DevicePackage.zip is a zip file that contains the code that CISCO APIC requires to dynamically define the Applications templates that are defined within iWorkflow.

Uploading the F5DevicePackage.zip to the CICSO APIC environment

After you have upgraded the CISCO APIC and iWorkflow environments, and have downloaded either a new or updated F5DevicePackage, your next step is to upload the F5DevicePackage. Complete the following steps using the CISCO APIC administrative GUI. This process will not impact any deployed service graphs, but will enable the new functions and features provided by the iWorkflow upgrade.

Impact of procedure: Uploading a new F5DevicePackage to the CISCO APIC environment will cause no impacts. Existing service graph deployments will not be impacted.

  1. Log in to the CISCO APIC GUI Administration with your CISCO APIC administrator user name and password, by using the following syntax:

    https://x.x.x.x

    For example:

    https://192.168.8.8

  2. From the top navigation menu, click L4-L7 Services.
  3. Just below L4-L7 Services, click Packages.
  4. Right-click L4-L7 Service Device Type in the left navigation window, and select Import device package.
  5. Using a file navigation window that renders, click Browse, and locate your F5DevicePackage.zip file.

    Note: If this is a new device package, you should see the upload in left navigation window. The name is pre-pended with F5-iWorkflow-{version}-{cloud-connector-name}.
