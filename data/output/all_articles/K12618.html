Known Issue

Important: The issue described in this article only occurs when applying 10.2.0 HF2 to a partitioned system. It does not affect systems running volumes.

This is the result of a known issue. Installing 10.2.0 HF2 on a partitioned system with HF1 installed may make the 10.2.0 partition unable to boot. This issue is caused by the failure of the SAM and AOM installation scripts.

This issue typically occurs when running a mixed 9.x and 10.x system. For information about installation of a hotfix for a 10.x system using partitions, refer to K11033: Managing BIG-IP version 10.1.x and 10.2.x hotfixes on systems using the partitions disk formatting scheme. Following the requirements in SOL11033, installation of 10.2.0 HF2 to a 10.2.0 HF1 partition results in a failed installation and the inability to boot to the 10.2.0 partition after reboot.

Workaround

To prevent this issue and allow 10.2.0 HF2 to correctly install, you must revert the system back to the BIG-IP 10.2.0 base install.

To remove a hotfix, perform the following procedure:

  1. Back up the configuration for the 10.2.0 partition.

    Note: For more information, refer to K11318: Backing up and restoring BIG-IP configuration files (10.x).

  2. Revert the BIG-IP 10.2.0 HF1 partition back to a base BIG-IP 10.2.0.

    Note: For information about installing BIG-IP on a partition system, refer to the BIG-IP LTM, BIG-IP ASM, BIG-IP GTM, BIG-IP PSM, Link Controller, or WebAccelerator release notes.

  3. After the partition has been reverted back to 10.2.0 base, re-install the configuration.

    Note: For more information, refer to K11318: Backing up and restoring BIG-IP configuration files (10.x).

  4. Install BIG-IP 10.2.0 HF2.

    Note: For more information, refer to K11033: Managing BIG-IP version 10.1.x and 10.2.x hotfixes on systems using the partitions disk formatting scheme.
