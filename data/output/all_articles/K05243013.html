K05243013: Configuring a BIG-IQ to return HSTS header when scanning only the IP address

Type
Support Solution
Published
2020-12-03
Updated
2025-02-06
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 7.X.X
Source
https://my.f5.com/manage/s/article/K05243013

Description

Security scans targetting the BIG-IQ web interface may alert that HSTS header "Strict-Transport-Security" is not present.

Environment

  • Scanning for HSTS header "Strict-Transport-Security" on BIG-IQ URI endpoint "/" reports missing the HSTS header.

Cause

GET requests made to the BIG-IQ web interface for the URI "/" return a 301 redirect that does not include the Strict-Transport-Security header.

Note: Subsequent client requests to the location in the 301 response will include the Strict-Transport-Security header.

To test this, use the following command from a linux machine:

curl -sIk https://<target-BIG-IQ IP address> | grep Strict-Transport-Security

Note: No results indicate that no HSTS header header was included in the response.

Recommended Actions

Modify the webd.conf configuration file to set Strict-Transport-Security on the URI "/"
  1. Backup the file webd.conf
    cp /etc/webd/webd.conf /etc/webd/webd.conf_ORG
     
  2. Edit the file /etc/webd/webd.conf

    Insert a add_header statement in the stanza below

    # redirect /ui and / to the login URI
    location ~* ^/(ui/)?$ {
        port_in_redirect off;
        return 301 /ui/login;
        add_header Strict-Transport-Security "max-age=16070400; includeSubDomains";
    }

  3. Save the changes and restart webd
    bigstart restart webd
