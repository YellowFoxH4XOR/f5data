Known Issue

The Traffic Management Shell (tmsh) utility allows a monitor type named none to be incorrectly associated with a wide IP pool.

Impact

  • In BIG-IP GTM 11.x, wide IP pools associated with the monitor type none are not marked down; however, the monitor may cause confusion.
  • In BIG-IP GTM 9.x through 10.x, wide IP pools associated with the monitor type none are marked down.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP GTM 11.x:
    • The tmsh utility lists monitor type none as a configurable monitor.
  • BIG-IP GTM 9.x through 10.x:
    • The tmsh utility lists monitor type none as a configurable monitor.
    • Wide IP pools associated with monitor type none are marked down. This symptom will occur when the none monitor type is used either alone or with other monitors.
    • Log messages will appear in the /var/log/gtm file. The messages will appear similar to the following example:

      gtmd[3900]: 011ae0f2:1: Monitor instance none <IP_ADDRESS>:<PORT> UNKNOWN_MONITOR_STATE --> DOWN from gtmd (no reply from big3d: timed out)
      gtmd[3900]: 011a4003:1: SNMP_TRAP: Pool <POOL_NAME> member /Common/<VIP_NAME> (ip:port=<VIP_IP>:<VIP_PORT>) state change green --> red (Pool pool_one member /Common/<VIP_NAME>: Monitor none from gtmd : no reply from big3d: timed out)
      gtmd[3900]: 011a1005:1: SNMP_TRAP: Pool <POOL_NAME> state change green --> red (Pool <POOL_NAME>: No enabled pool members available)
      gtmd[3900]: 011a3004:1: SNMP_TRAP: Wide IP <WIDE_IP_NAME> state change green --> red (Wide IP <WIDE_IP_NAME>: No enabled pools available)

Resolution

Status

F5 Product Development has assigned ID 264607 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, do not select the none monitor type.

Impact of workaround: None.
