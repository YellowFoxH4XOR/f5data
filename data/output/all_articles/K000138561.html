K000138561: Server-tokens directive only hiding version and not the complete Server header

Type
Support Solution
Published
2024-02-09
Updated
2024-02-09
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 2.4.0
Source
https://my.f5.com/manage/s/article/K000138561

Description

 nginx.org/server-tokens: "False"  annotation has been configured in the ingress resource but it only hides the version and not the complete header:

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  annotations:
...
    nginx.org/server-tokens: "False"
➜  curl --resolve cafe.example.com:443:172.18.0.200 https://cafe.example.com:443/tea --insecure -I
HTTP/1.1 200 OK
Server: nginx
...
Content-Type: text/plain
Content-Length: 152
...

In the nginx config it looks like this:

server {
	listen 80;
	listen [::]:80;
	listen 443 ssl;
	listen [::]:443 ssl;
...
	server_tokens "off";
...

 

Environment

Nginx Ingress Controller 3.x

Cause

Incorrect value passed to the directive:

server_tokens: Enables or disables emitting nginx version on error pages and in the “Server” response header field. An empty string disables the emission of the “Server” field.

Recommended Actions

Specify an empty string as the value for the directive/annotation:

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  annotations:
...
    nginx.org/server-tokens: ""

Additional Information

After applying the configuration the nginx config should show the server-tokens directive with an empty string:

server {
	listen 80;
	listen [::]:80;
	listen 443 ssl;
	listen [::]:443 ssl;
...
	server_tokens "";
...

And running a test, the server header is not shown:

➜  Setup curl --resolve cafe.example.com:443:172.18.0.200 https://cafe.example.com:443/tea --insecure -I
HTTP/1.1 200 OK
Date: Fri, 09 Feb 2024 20:01:14 GMT
Content-Type: text/plain
Content-Length: 152
Connection: keep-alive
Expires: Fri, 09 Feb 2024 20:01:13 GMT
Cache-Control: no-cache
