Known Issue

This is the result of a known issue. The bigpipe persist command can be used to configure persistence and to manage the persistence table records on the BIG-IP system. The bigpipe persist <pool> delete and bigpipe persist <virtual> delete commands delete all persistence records for the system. For example, if you have two virtual servers (VS_1 and VS_2) each configured with a source address persistence profile, the bigpipe persist virtual VS_1 delete command should delete persistence records for the VS_1 virtual server. Instead, the command deletes all persistence records for the system.

F5 Product Development tracked this issue as CR92345 and it was fixed in BIG-IP LTM 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To work around this issue, use the bigpipe persist node <node_address:port> delete command.
