Known Issue

This is the result of a known issue. Missing or ambiguous entries in the /etc/protocols or /etc/services files may cause configuration errors.

By default, the bigip.conf file refers to services and protocols by name rather than by number. When saving configuration objects, the BIG-IP system uses the /etc/services file and the /etc/protocols file, respectively, to translate service port and protocol numbers to their corresponding service and protocol names. When loading the configuration, the system performs the inverse translation.

If a protocol or service name referenced in the bigip.conf file is missing from the /etc/services or /etc/protocols file, the configuration may fail to load. When this occurs, an error message that appears similar to the following example displays:

BIGpipe parsing error (/config/bigip.conf Line 747):
012e0010:3: The requested value (ipv6-crypt }) is invalid (<protocol>) for 'ip protocol' in 'virtual'

If a protocol or service name referenced in a bigip.conf file has multiple entries in the /etc/services or /etc/protocols file, even if they reference different transport protocols, the configuration may be inadvertently modified after saving and reloading to reflect the wrong service or protocol.

For example, the /etc/services file in 10.2.0 contains the following entries:

news 2009/tcp
whosockami 2009/udp
whosockami 2019/tcp

If you configure a pool to use the protocol number 2019 for the whosockami service, the pool definition in memory reflects the intended protocol name:

# bigpipe pool test { members 10.146.0.3:2019 }
# bigpipe pool test list
pool test {
members 10.146.0.3:whosockami {}
}

If you save the configuration, the pool definition in the bigip.conf file also reflects the intended protocol name:

# bigpipe save
# grep -A2 "pool pool_t_1" bigip.conf
pool pool_test {
members 10.146.0.3:whosockami {}
}

However, if you then reload the configuration, the service name whosockami is translated to port 2009, which is the port number referenced by the first instance of whosockami in the /etc/services file. Using bigpipe or tmsh commands to list the pool displays the service name news, which is the first instance of port 2009 in the /etc/services file:

bigpipe:
# bigpipe pool test list
pool test {
members 10.146.0.3:news {}
}

tmsh:
(tmos.ltm.pool)# list pool_t_1
ltm pool test {
members {
10.146.0.3:2009 { }
}
}

F5 Product Development tracked this issue as ID 248029 (to correct bigpipe service and protocol translation) and as ID 207495 (to correct tmsh service and protocol translation). ID 207495 was fixed for tmsh in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WAN Optimization, and Edge Gateway release notes.

The bigpipe utility is removed in BIG-IP 11.0.0, the issue described in this article does not apply to BIG-IP 11.0.0 and later. For information, refer to K13076: The bigpipe command is removed from BIG-IP software in version 11.0.0.

Workaround

If you move a configuration to a new version and encounter this error message, a service or protocol name may have been removed from the /etc/services or /etc/protocol file between releases, as described in K11296: The default /etc/protocols file may cause a configuration load failure. You can use the workaround in this article to work around this issue.

If you add a configuration object using a protocol or service number rather than name, and then reload the configuration on the same system, the newly-added object may reference a different service or protocol. When this occurs, it is an indication that there are ambiguous entries in the /etc/services or /etc/protocols file; for example, the files may contain multiple definitions for the affected service or protocol.

You can work around this issue by performing one of the following two procedures:

  • Globally configure the BIG-IP system to not translate service and protocol numbers to names when storing configuration objects in the bigip.conf file
  • Remove unneeded, ambiguous entries by commenting out the offending lines in the /etc/services or /etc/protocol file

Globally configure the BIG-IP system to not translate service and protocol numbers to names when storing configuration objects in the bigip.conf file

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    bigpipe cli service number

    Note: The service option is incorrectly described in the bigpipe cli man page. For more information, refer to K11301: Documentation Erratum: The bigpipe cli man page provides incorrect information for the service option.
  3. Save the configuration by typing the following command:

    bigpipe save

    Note: The bigip.conf file is now saved using service and protocol numbers rather than names.

Remove unneeded ambiguous entries by commenting out the offending lines in the /etc/services or /etc/protocols file

  1. Log in to the BIG-IP command line.
  2. Save the bigip.conf file with service and protocol numbers instead of names by typing the following two commands:

    bigpipe cli service number

    bigpipe save
  3. Back up the /etc/services or /etc/protocol file by typing the following command:

    cp /etc/services /etc/services.SOL12251
  4. Open the /etc/services or /etc/protocol file in a text editor.
  5. Locate the entries you no longer want the system to use for translation.
  6. Type a # character at the beginning of the line.

    For example, to discontinue erroneous translation of the service name whosockami to port 2009, locate the following line in the /etc/services file:

    whosockami 2009/udp

    Modify the line as follows:

    #whosockami 2009/udp
  7. Save the file and exit the editor.
  8. Restore the service names setting and save the bigip.conf file using service names by typing the following two commands:

    bigpipe cli service names

    bigpipe save

Repeat the procedure until all affected services in use on your system have been addressed.
