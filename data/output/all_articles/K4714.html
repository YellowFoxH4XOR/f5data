Topic

Note: For information about recommended methods and limitations for running tcpdump on a BIG-IP system, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system.

F5 Support generally requires a packet trace when assisting you with troubleshooting a network traffic issue. This article provides instructions for using the tcpdump utility to capture a packet trace while you reproduce the issue. If you capture this information before you open a case with F5 Support, it often speeds resolution.

Description

Packet captures are helpful in determining why application traffic processed by the BIG-IP system is either failing or not performing as expected. To thoroughly capture and diagnose an application issue, review the following factors:

  • VLAN traffic

    Determine which of your Virtual Local Area Networks (VLANs) are involved in the application traffic issue. If traffic passes in and out of only one VLAN, you can run the tcpdump utility on that VLAN only. However, if the application traffic passes in and out of multiple VLANs, you must run the tcpdump utility on both VLANs to accurately determine where the issue occurs.

  • Client applications

    Ensure the packet capture starts prior to the client application attempting to reproduce the issue, and is not stopped until after you reproduce the application issue.

  • Web browsers

    If the application involves a client web browser, ensure all browser windows are closed prior to starting the packet capture. It is important for F5 Support to analyze browser sessions from start to finish. If the browser is not closed first, it may already have entered a problematic state and F5 Support will not be able to determine the cause.

You can gather a packet trace using either the command line or the Configuration utility. To do so, perform one of the following procedures:

  • Using the command line to gather a packet trace
    • Preparing and submitting tcpdump packet trace files
  • Using the Configuration utility to gather a packet trace
    • 13.0.0 and later
    • 12.1.4 and earlier

Using the command line to gather a packet trace

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. To run the tcpdump utility on each VLAN and save the results to a file in the /var/tmp directory, use the following command syntax:

    tcpdump -i <vlan>:nnn -s0 -w /var/tmp/<case>.<vlan>.dmp &

    For example, to run tcpdump on the VLAN named internal and save it to a file named C123456.internal.dmp, type the following command:

    tcpdump -i internal:nnn -s0 -w /var/tmp/C123456.internal.dmp &

    In the command syntax, note the following:

    • <case> represents the current F5 Support case number associated with the issue. If you have not yet opened a case with F5 Support, replace <case> with the serial number of the BIG-IP system.
    • -s0 (snaplen) ensures tcpdump captures the maximum amount of data per packet.
    • :nnn includes F5 proprietary data, which F5 Support can analyze.
       
  3. Repeat step 2 for each VLAN that you are troubleshooting.
  4. After you have reproduced the application issue, continue with the procedure.
  5. Each tcpdump capture session was run in the background. To return the tcpdump capture session to the foreground, type the following command:

    fg

  6. To close the tcpdump capture session, press CTRL+C.
  7. Repeat steps 5 and 6 for each tcpdump session that you opened.
  8. The packet traces are located in the /var/tmp directory.

Preparing and submitting tcpdump packet trace files

  1. Compress each of the packet trace files using the following command syntax:

    gzip /var/tmp/<file>

    Replace <file> with the name of the tcpdump file you created in step 3 of the first procedure.

    The gzip command automatically appends a .gz extension to the file.

  2. Copy each compressed tcpdump file from the BIG-IP system to a local host.

    Note: For instructions on performing this task, refer to K175: Transferring files to or from an F5 system.

  3. Upload each compressed tcpdump file to F5 Support.

    Note: For instructions about sending files to F5 Support, refer to K000090853: Exchange files with F5 Support.

  4. Contact F5 Support and inform them that you have uploaded the trace information.

Using the Configuration utility to gather a packet trace

To gather a packet trace using the Configuration utility, perform one of the following procedures:

Impact of procedures: Performing the following procedures should not have an impact on your system.

13.0.0 and later

  1. Log in to the Configuration utility.
  2. Navigate to System > Support.
  3. Click New Support Snapshot.
  4. In the Health Utility menu, select Generate TCP Dump.
  5. Click Add.
  6. From the VLAN menu, select a VLAN on which you want to run the packet trace.
  7. From the Packets menu, select the number of packets for the packet capture. It is important to choose a sufficient number of packets to reproduce the issue.
  8. From the Timeout menu, select a time limit in minutes for the packet capture. It is important to choose a sufficient length of time to reproduce the issue.
  9. Click Add.
  10. Repeat steps 5 through 9 for each VLAN on which you want to run the packet trace.
  11. Click Start.
  12. After you have reproduced the application issue, continue with the procedure.
  13. Optional: If the tcpdump timer has not expired, end the packet trace by clicking Cancel.
  14. Click Download.
  15. To delete the packet trace files from the BIG-IP system, click Delete.
  16. Provide the files to F5 Support.

12.1.4 and earlier

  1. Log in to the Configuration utility.
  2. Navigate to System > Support.
  3. Clear the QKView check box.
  4. Select the TCP Dump check box.
  5. From the VLAN menu, select a VLAN on which you want to run the packet trace.
  6. Click Add.
  7. Repeat steps 5 and 6 for each VLAN on which you want to run the packet trace.
  8. In the Minutes menu, select a time limit for the packet trace. It is important to choose a sufficient length of time to reproduce the issue.
  9. Click Start.
  10. After you have reproduced the application issue, continue with the procedure.
  11. Optional: If the tcpdump timer has not expired, end the packet trace by clicking Cancel.
  12. Click Download Snapshot File.
  13. Click Save.

    Note: The file may automatically download depending on your browser preferences.

  14. Select the desired Name and Location under which you want to save the file.

    Note: F5 Support suggests that you name the file using the case number assigned to you by your F5 Support representative.

  15. Click Save.
  16. To delete the packet trace files from the BIG-IP system, click Delete.
  17. Provide the files to F5 Support.

Note: For more information about providing files to F5 Support, refer to K000090853: Exchange files with F5 Support. Inform the support engineer with whom you have been working that the files have been uploaded.
