K000150601: Renew a Device Certificate with a new key size of 2048 bits.

Type
Support Solution
Published
2025-03-28
Updated
2025-03-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000150601

Description

By default, renewing the Device Management SSL certificate sets a public RSA key size to 1024 bits. This configuration is incompatible with certain Third-Party Certificate Authorities (CAs), which require a minimum key size of 2048 bits. The GUI does not provide an option to modify the RSA key size during renewal.

Environment

  • Device certificate renewal
  • RSA key being set to 1024 bits
  • Organization requires a key size of 2048 bits

Cause

The default Device Management SSL certificate was generated with a public RSA key size of 1024 bits, which is below the minimum requirement for some Third-Party CAs. The GUI lacks functionality to adjust the RSA key size during certificate renewal.

Recommended Actions

To resolve this issue and renew the Device Management SSL certificate with a larger RSA key size:

1.- Generate a Temporary Self-Signed Certificate: Use the command line interface to create a new self-signed certificate with the desired RSA key size (e.g., 2048 bits). Execute the following command from the bash shell: 

openssl req -x509 -nodes -days 3650 -newkey rsa:2048 -sha256 -keyout /config/httpd/conf/ssl.key/server.key -out /config/httpd/conf/ssl.crt/server.crt

2.- Enter Certificate Attributes: During execution, you will be prompted to enter attributes such as country, locality, common name, etc. 

3.- Restart the HTTPD Process: Restart the httpd process to apply changes using this command: 

bigstart restart httpd

4.- Replace Self-Signed Certificate with CA Certificate: Once your temporary self-signed certificate is in place, replace it with your new CA-issued device certificate by following K36564972: Replace Self-Signed device certificate for a third-party CA device certificate using the Configuration Utility.
