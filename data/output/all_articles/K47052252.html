K47052252: Renew device trust certificates on a BIG-IP system

Description

Over time, the Device Trust certificates (dtca.crt and dtdi.crt) will expire and may need to be renewed; these certificates are generated with a 10-year lifetime. Expired device trust certificates will not disrupt the ability to perform ConfigSync operations, but will prevent adding new devices into Device Trust. This article provides information about how to renew these certificates.

Environment

  • BIG-IP system configured as part of DSC / HA
  • Device trust certificates (dtca.crt or dtdi.crt) in need of a renewal

Cause

The device trust certificates can expire and would need to be renewed so that device trust establishment can continue to take place. A valid (not expired) trust CA certificate is required to add new devices to an existing trust domain.

Recommended Actions

In order to renew the device trust certificate, you will need to reset the device trust on all the devices that are part of the trust domain followed by rebuilding the trust. You will have to do so by generating a new self-signed authority.

  • Selecting Generate new self-signed authority option will result in both dtca.crt and dtdi.crt files being renewed in the process.
  • Selecting Retain current authority option will result in the current dtca.crt and dtdi.crt files being retained.

The following steps will need to be performed on all the devices in the device group in order to renew these two certificates:

To watch a video demo of this procedure, go to  Renew device trust certificates on a BIG-IP system using the Configuration utility.

Note: Performing this procedure should remove the peer device(s) from the device group(s) as well as traffic group(s). There should not be a need to manually remove the peer device(s) from these groups prior to this procedure.

Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. This procedure causes the current device to lose connectivity with all other BIG-IP devices. Depending on the device group and traffic group configuration, the connectivity loss may result in an unintentional Active-Active condition that causes a traffic disruption.

  1. Log in to the Configuration utility.
  2. Set the standby device in the device group to Force Offline to prevent a standby device from going active. To do so, go to Device Management > Devices, select the standby device name and then select Force Offline.
  3. Go to Device Management > Device Trust > Local Domain.
  4. Select Reset Device Trust.
  5. Select the Generate new self-signed authority option.
  6. Select Update (or Next).
  7. Select Finished.
  8. Repeat this procedure for each device in the device group.

Note: When you enable the Force Offline option on a chassis system, the TMM interfaces remain configured until you restart the device. If you restart the chassis while Force Offline is enabled, the system marks all TMM interfaces as Uninitialized or Missing. This behavior is by design; the system does not attempt to initialize or bring up TMM interfaces while the system is in the offline state.

After you complete the device trust reset on all devices, set up the device trust by performing the procedures described in the following articles:

  • K63243467: Creating a device group using the Configuration utility
  • K13639: Configuring a device group using tmsh

Note: If you set any standby devices to Force Offline, you should set then to Release Offline after performing the procedure. For more information, refer to K15122: Overview of the Force Offline option.

Additional Information

The BIG-IP system uses SSL certificates to establish a trust relationship between devices. In a device trust, a BIG-IP device can act as a certificate signing authority or a subordinate non-authority. Each device also has peer authorities. When acting as a certificate signing authority, the BIG-IP device signs X.509 certificates for another BIG-IP device that is in the local trust domain. The BIG-IP device for which a certificate signing authority device signs its certificate is known as a subordinate non-authority device.

You can view the DSC device trust certificates in the location shown in the following table:
