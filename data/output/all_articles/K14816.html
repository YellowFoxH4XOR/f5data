Known Issue

BIG-IP APM VMware View portal connections may fail.

This issue occurs when all of the following conditions are met:

  • You configure the BIG-IP APM system with a portal for VMware View PCoIP Secure Gateway (PSG).
  • You configure the BIG-IP system with a wildcard forwarding virtual server that meets any of the following conditions:
    • A forwarding virtual server matches the same virtual address that the system uses for the VMware View portal, and also uses a wildcard port (0).
    • A wildcard forwarding network virtual server matches the same network as the address used for the VMware View portal.
    • A wildcard forwarding virtual server matches "any" traffic (0.0.0.0:0) on the BIG-IP APM system.

Connection requests that the system intends to send to the VMware View server, that the portal configuration uses, are erroneously sent to the wildcard forwarding virtual server and cause the connection to fail.

For example, if a BIG-IP APM VMware View portal uses the virtual server address 172.16.0.10:443 to forward VMware View connections, and the system is configured with a wildcard forwarding virtual server 172.16.0.10:0 that is set with the translate address and translate port disabled, the requests that the system intends to send to the VMware View server 172.16.0.10:443 are erroneously sent to the 172.16.0.10:0 wildcard forwarding virtual server.

Impact

Portal connections for the VMware View PSG receive a TCP reset from the BIG-IP APM system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You cannot access the BIG-IP APM portal for VMware View.
  • You receive one of the following errors:
    FirefoxThe connection was reset
    Internet ExplorerThis page cannot be displayed
    ChromeThis web page is not available
    SafariSafari cannot open the page

    Workaround

    To work around this issue, you can reconfigure or replace the offending wildcard virtual servers. To do so, perform the following procedures:

    Impact of workaround: Creating replacement virtual servers interrupts services that the wildcard virtual servers handle.

    Replacing wild card forwarding virtual servers

    • If a forwarding virtual server matches the same virtual address that the system uses for the VMware View portal, and also uses the wildcard any port (0), remove the wildcard forwarding virtual server and then replace the server with port-specific virtual servers.

      For example, if wildcard forwarding virtual server 172.16.0.10:0 handles multiple services such as SSH (22), Telnet (23) and RDP (3389), create forwarding virtual servers for each of the SSH, Telnet, and RDP services to replace the original wildcard forwarding virtual server 172.16.0.10:0, with the following virtual servers:

      172.16.0.10:22
      172.16.0.10:23
      172.16.0.10:3389

    • If a wildcard forwarding network virtual address matches the same network as the address the system uses for the VMware View portal, remove the network wildcard forwarding virtual server and then replace the server with address-specific virtual servers for each of the forwarding destinations the network requires.
    • If a wildcard forwarding virtual server matches "any traffic" (0.0.0.0:0) on the BIG-IP APM system, remove the wildcard forwarding virtual server and then replace the server with network and address specific virtual servers. Create network virtual servers for all networks except for the network that is most similar to the address that the VMware View portal uses. For devices that require a forwarding virtual server on the network of the VMware View portal, create virtual servers based on the destination address and with specific ports (as noted in the previous bullet).

    For more information on configuring virtual servers, refer to: Configuration Guide for BIG-IP Local Traffic Management: 2 - Configuring Virtual Servers.
