Known Issue

This is the result of a known issue. Saved channel configurations will fail to load on the ARX 2000 platform. This issue occurs because the channel configuration of a running-config is incorrectly saved.

For example, the following show channel <Channel ID> command output properly displays the channel configuration for a channel configured with Slot/Interface members 1/3 and 1/4:

# show channel 1

Channel ID                    : 1
Description                   : default
Load Balancing Algorithm      : Source and Destination Ip
LACP State                    : Passive
Members(Slot/Interface)       : 1/3,1/4
Number of Members             : 2
Admin State                   : Enabled
Channel Oper Status           : Down
Trap Status                   : Disabled
Spanning-Tree Forwarding State: Disabled
Spanning-Tree State           : Disabled
Spanning-Tree Role            : Disabled
Accept Frames                 : All
Total VLANs Configured        : 2

Members  Tag
VLAN ID  VLAN ID
-----------------
1         N/A
19        N/A

Slot/Port    Link Status
-------------------------
1/3            Down
1/4            Down

However, the channel section of the show running-config command will incorrectly indicate the members Slot/Interface are configured as 2/3 and 2/4.

For example:

;================================ channel ================================
  channel 1
    members 2/3
    members 2/4
    spanning-tree shutdown
    vlan 19
    lacp passive
    exit

As a result, when the running-config configuration is saved, it is saved with the incorrect member Slot/Interface configuration. If the saved configuration is loaded, the channel configuration will fail because the Slot/Interface 2/3 and 2/4 do not exist on the ARX 2000 platform.

F5 Networks Product Development tracked this issue as ARX ID 37766 and it was fixed in ARX version 5.1.5. For information about upgrading, refer to the ARX Release Notes.

Workaround

After loading a saved configuration file that contains the incorrect member information, you must manually enter the correct members of the channel using the CLI.

As an alternative, prior to loading the saved configuration file, you could edit the channel section of the configuration file to use the correct members for the channel.
