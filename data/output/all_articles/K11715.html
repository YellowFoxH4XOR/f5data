Known Issue

This is the result of a known issue. If you attempt to downgrade a BIG-IP 8400 or 8800 platform from version 10.1.x or 10.2.x to 9.4.x using the local installation method, the downgrade will fail.

Note: Before attempting to downgrade to version 9.4.x, the version 10.1.x or 10.2.x system must be using the partition disk-formatting scheme. For more information, refer to the following articles:

  • K10817: Determining the disk-formatting scheme used by a BIG-IP version 10.x system
  • K9745: Reverting BIG-IP version 10.x disk formatting (LVM) to version 9.x disk partitions

For example, if the BIG-IP 8400 or 8800 platform is running version 10.1.x or 10.2.x and using the partition disk-formatting scheme, and you attempt to re-install version 9.4.x using the local installation method, the 9.4.x installation fails prior to rebooting to the installation kernel, and error messages that appear similar to the following example are output to the console:

..........info: Configuring boot loader (GRUB)...
disk for boot-loader cfg: sda
error: No boot-loader configuration found (/mnt/tmp/install/boot/sda/grub/grub.conf)
error: Re-create with: /usr/lib/install/grub_util -c

After the installation exits, the system is left in an inoperative state until it is rebooted under the version 10.1.x or 10.2.x installation.

F5 Product Development is tracking this issue as ID 327787 (formerly CR131632).

Workaround

In order to successfully downgrade from version 10.1.x or 10.2.x to version 9.4.x, you must either use the PXE installation method, the USB CD-ROM installation method, or the USB mass storage installation method.

Note: For more information about installation methods, refer to K9447: Choosing an installation method for BIG-IP version 9.x.
