K000148045: How to filter requests coming to your load-balancer based on countries and AS numbers.

Description

  • Customers control who gets access to their web application and can choose to filter depending on a visitor's location
  • Filtering out an entire country is too much
  • How can you block requests from a country while still allowing the requests from an autonomous system (AS) within that same country?
    • Example: F5® Distributed Cloud Services user wants to prevent access to US-based visitors, but still wants their website indexed by Google. How would they configure their Service policy?

Environment

  • F5® Distributed Cloud Mesh

Answer/Recommended Actions

  • In the corresponding namespace of the load-balancer, visit the section Security > Service policy, and create a policy with, say, allow-google-as as a name, and the parameters:
    • Select policy rules set to Allowed Sources
    • Default action set to Next Policy
  • Then configure BGP ASN list to include 15169, Google’s ASN.
  • Then create another service policy named, say "deny-us-requests" and set the parameters:
    • Select policy rules to Denied Sources
    • Default action to Next Policy
  • Then configure Country list to include United States
  • Eventually, in the configuration of the corresponding load-balancer, section Security Configuration, set the parameter Service policies to Apply Specified Service Policies, then click on Edit Configuration
  • In the form showing up, add the policies "<namespace>/allow-google-as", then "<namespace>/deny-us-requests", then eventually "shared/ves-io-allow-all". Click on Apply, and save the load-balancer configuration.

 

Now the three policies are applied sequentially, on a "first match wins". That’s the reason why it’s necessary to add the policy "shared/ves-io-allow-all" at the end, otherwise the requests that match neither of the previous policies would be dropped.

Check that the policies are effective by using services like PageSpeed
