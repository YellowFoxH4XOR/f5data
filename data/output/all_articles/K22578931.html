Issue

Error Message

err tmm[<PID>]: comm_point_tmm_recv_from failed: errno <#>

In this error message, note the following:

  • <PID> is the process ID for the tmm process
  • <#> is the error message number

For example:

err tmm[<3525>]: comm_point_tmm_recv_from failed: errno 103

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message may occur when all of the following conditions are met:

  • You have a virtual server with DNS resolver cache configured.
  • The BIG-IP system receives an Internet Control Message Protocol (ICMP) Unreachable message in response to a DNS query or is unable to connect to the resolver.

These messages generally benign and occur when the connection from the BIG-IP system to the resolver is unsuccessful. For example, the Traffic Management Microkernel (TMM) generates this message when it receives no response from the resolver, the connection expires or aborts, or when the BIG-IP system fails to read socket data. These messages may also be logged after performing a software upgrade.

Impact

DNS resolution fails. Extended network or resolver problems may result in a flood of these messages to the /var/log/ltm file.

Recommended Actions

When this message occurs, you should check connectivity between the BIG-IP system and configured DNS resolvers. To suppress these messages from being sent to remote syslog servers, you can filter the messages in the syslog configuration. For more information, refer to K13333: Filtering log messages sent to remote syslog servers (11.x - 13.x).

To prevent the BIG-IP system from logging these messages, you can configure the dnscacheresolver.loglevel database variable to use a less verbose setting, such as critical. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure prevents the BIG-IP system from logging any messages from DNS Cache that have severity of "error" or below (possible levels in order of severity are: debug, info, notice, warning, error, critical, alert, emergency), and while increasing the level from the default 'notice' up to 'critical' will suppress the messages described in this article, it will also suppress all other 'error', "warning", and "notice" level messages from DNS cache.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To modify the dnscacheresolver.loglevel database variable, use the following syntax:

    modify /sys db dnscacheresolver.loglevel value <value>

    For example, to set the value to critical, type the following command:

    modify /sys db dnscacheresolver.loglevel value critical

  3. To revert the change, either set dnscacheresolver.loglevel to 'notice', or use the reset-to-default option:modify /sys db dnscacheresolver.loglevel reset-to-default
