Description

The current CA signed device certificate is about to expire and attempts to replace it via the Configuration Utility return errors.

Environment

  • The installed Device Certificate is already signed by a Certificate Authority
  • The client certificate and key need to be updated
  • The intermediate certificate needs to be updated

Cause

Unknown at time of publication.

Recommended Actions

Replace a 3rd Party CA signed device certificate from the command line. 
  • Confirm which portions of the device certificate need replacement.
    • Client certificate?
    • Certificate chain?
    • Key?
The instructions below update all three, but if the certificate chain and key aren't changing, then just update the client certificate. Afterwards, save the configuration and restart httpd to see the changes from the Configuration Utility.

Note: If this device is monitored by GTM/DNS, this new certificate must be exchanged with GTM/DNS otherwise this iQuery connection will fail after the certificate expires. Follow instructions from K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities (11.x - 16.x) to exchange this new certificate.

Note: If this device is managed by BIG-IQ, you may need to rediscover this device afterwards.
  1. Upload the files to /var/tmp.
  2. Extract the bundle. If it's already in .pem format skip to the next step (#3).
    • K6549: Converting PKCS certificates to PEM format for use with the BIG-IP system
    • Example: openssl pkcs12 -in /var/tmp/devcert-bigip.p12 -out /var/tmp/devcert-bigip.pem -nodes
      • Include -nodes to avoid applying another password to this bundle
         
  3. Back up the current certificate, key, and certificate chain.
    • Device certificate file
      • Template:
        cp /config/httpd/conf/ssl.crt/<current-cert-name>.crt /config/httpd/conf/ssl.crt/<current-cert-name>.crt.orig
         
      • Example:
        cp /config/httpd/conf/ssl.crt/server.crt /config/httpd/conf/ssl.crt/server.crt.orig
    • Device key file
      • Template:
        cp /config/httpd/conf/ssl.key/<current-key-name>.key /config/httpd/conf/ssl.key/<current-key-name>.key.orig
         
      • Example:
        cp /config/httpd/conf/ssl.key/server.key /config/httpd/conf/ssl.key/server.key.orig
         
    • Certificate chain
      • Check for an existing certificate chain
        tmsh list sys httpd ssl-certchainfile
         
      • Then archive, if necessary.
        cp /config/httpd/conf/ssl.crt/cert-chain.crt /config/httpd/conf/ssl.crt/cert-chain.crt.orig
         
  4. Confirm the backups exist.
    • ls -lh /config/httpd/conf/ssl.key/
    • ls -lh /config/httpd/conf/ssl.crt/
       
  5. Manually create the new certificate and key. This may require a separate SSH or notepad.
    • View the contents of the *.pem file. It should show all certificates and the private key.
      • cat /var/tmp/devcert-bigip.pem
         
    • Create client certificate file
      • vim /var/tmp/devcert-bigip.crt
        • Extract the client certificate, including -----BEGIN CERTIFICATE----- through -----END CERTIFICATE-----. This is usually the top certificate in a bundle.
        • Insert this text into the certificate file.
        • Save these changes.
           
    • Create the key file: 
      • vim /var/tmp/devcert-bigip.key
        • Extract the key, including -----BEGIN PRIVATE KEY----- through -----END PRIVATE KEY-----.
        • Insert this text into the key file.
        • Save these changes.
           
    • Create chain certificate file
      • vim /var/tmp/devcert-bigip-chain.crt
        • Extract the remaining certificates, including -----BEGIN CERTIFICATE----- through -----END CERTIFICATE-----. There may be more than one.
        • Insert this text into the certificate-chain file.
        • Save these changes.
           
  6. Copy and rename both the key and client certificate to the /config/httpd/conf/ssl directory.
    Note: This overwrites the original server.crt and server.key files so confirm the back ups from step 4 exist.
    • cp /var/tmp/devcert-bigip.key /config/httpd/conf/ssl.key/server.key
    • cp /var/tmp/devcert-bigip.crt /etc/httpd/conf/ssl.crt/server.crt
       
  7. Copy the certificate chain to the /config/httpd/conf/ssl directory.
    • cp /var/tmp/devcert-chain.crt /etc/httpd/conf/ssl.crt/devcert-chain.crt
       
  8. Apply the new device certificate and key to the BIG-IP filestore at the same time.
    • tmsh modify sys httpd { ssl-certfile /etc/httpd/conf/ssl.crt/server.crt ssl-certkeyfile /etc/httpd/conf/ssl.key/server.key }
       
  9. Add the certificate chain.
    • tmsh modify sys httpd ssl-certchainfile /etc/httpd/conf/ssl.crt/devcert-chain.crt
       
  10. Confirm the certificate chain was applied.
    • tmsh list sys httpd ssl-certchainfile
       
  11. Save these changes.
    • tmsh save sys config
       
  12. Restart httpd so the Configuration Utility shows these updates.
    • tmsh restart sys service httpd

Additional Information

  • Check the results via the WebUI.
    • System >> Certificate Management : Device Certificate Management : Device Certificate
       
  • Check the certificates from the CLI.
    • openssl s_client -connect <mgmtIP>:443 -showcerts
    • The new client certificate and chain certificates should show
       
  • To roll back these changes. Rename the original certificate and key to overwrite the current certificate and key pair then remove the certificate chain. Save the changes and restart httpd to view these updates from the Configuration Utility.
    • cp /etc/httpd/conf/ssl.key/server.key.orig /etc/httpd/conf/ssl.key/server.key
    • cp /etc/httpd/conf/ssl.crt/server.crt.orig /etc/httpd/conf/ssl.crt/server.crt
    • tmsh modify sys httpd ssl-certchainfile none
    • tmsh save sys config
    • tmsh restart sys service httpd
