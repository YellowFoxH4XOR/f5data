Description

Failover status for a traffic group may become inconsistent across devices in a BIG-IP device group. Multiple devices may simultaneously report themselves as active for the same traffic group. This can be observed in the output of show /cm traffic-group

This issue may occur after changes to the traffic group’s ha-order configuration when auto-failback is enabled.

Environment

  • Product: BIG-IP LTM
  • Configuration:
    • Device group with more than two devices
    • Traffic group configured with ha-order and auto-failback enabled
    • Changes to ha-order performed from a device that is not currently active for the traffic group
    • Auto-failback timer set (e.g., 5 seconds)

Cause

A software defect in the failover daemon (sod) can cause multiple devices to assert themselves as active for a traffic group. This occurs if the ha-order is changed on a non-active device and the configuration is not synchronized to all devices before the auto-failback-time expires. The previous active device may continue to assert active status, resulting in an inconsistent failover state across the device group. i.e.

bigip1 (Active) has the following config:

cm traffic-group traffic-group-1 {
    auto-failback-enabled true
    auto-failback-time 5
    ha-order {
        bigip1
        bigip2
        bigip3
    }
    unit-id 1
}

From bigip2, the ha-order is modified:

cm traffic-group traffic-group-1 {
    auto-failback-enabled true
    auto-failback-time 5
    ha-order {
        bigip2
        bigip1
        bigip3
    }
    unit-id 1
}

After the auto-failback-time 5 expires, show /cm traffic-group displays:

-----------------------------------------------------------------------------------------
CentMgmt::Traffic-Group
Name                      Device                 Status   Next    Previous  Active
                                                          Active  Active    Reason
-----------------------------------------------------------------------------------------
traffic-group-1           bigip1                 active   true    true      -              
traffic-group-1           bigip2                 active   false   false     auto-failback  
traffic-group-1           bigip3                 standby  false   false     -
traffic-group-local-only  -                      -        -       -         -

Recommended Actions

  • To recover from this state:
    • Make the device that is stuck in the active state the preferred device in ha-order and sync the configuration, or
    • Restart the sod process on all affected devices to clear the condition: bigstart restart sod
  • To prevent this issue:
    • Make ha-order changes from the device that is currently active for the traffic group.
    • Ensure configuration changes are synchronized to all devices before the auto-failback timer expires.
    • Avoid making rapid or unsynchronized ha-order changes when auto-failback is enabled.
