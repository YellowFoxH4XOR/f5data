Description
In some case, unexpected failover happens at HA environment with recording the logs as follow.
/var/log/tmm
<13> Dec 15 07:03:27 hostname A notice Received unexpected daglib update while authoritative; discarding
<13> Dec 15 07:03:28 hostname A notice Received unexpected daglib update while authoritative; discarding
 

Environment

  • Active Standby HA redundancy is configured
  • Multiple interfaces for Network Failover are configured
  • Number of interfaces of Network Failover are different among HA

Cause
If the number interfaces of Network Failover are different among HA, synchronization of HA fails and both devices try to become Active.
Sample of the configuration is illustrated as follow
list /cm device
cm device /Common/[hostname A] {
    unicast-address {
        {
            effective-ip x.x.x.x
            effective-port 1026
            ip x.x.x.x
            port 1026
        }
        {
            effective-ip y.y.y.y
            effective-port 1026
            ip y.y.y.y
            port 1026
        }

cm device /Common/[hostname B] {
    unicast-address {
        {
            effective-ip a.a.a.a
            effective-port 1026
            ip a.a.a.a
            port 1026
        }
        {
            effective-ip b.b.b.b
            effective-port 1026
            ip b.b.b.b
            port 1026
        }
        {
            effective-ip c.c.c.c
            effective-port 1026
            ip c.c.c.c
            port 1026
        }

In this example, only [hostname B] is configuring 3 interfaces for network failover while [hostname A] has 2 interfaces.
 

Recommended Actions

Configure the same number of interfaces for Network Failover on HA devices.
