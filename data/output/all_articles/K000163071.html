K000163071: Migration of a BIG-IP LTM Virtual Edition system between hypervisor

Type
Support Solution
Published
2026-08-25
Updated
2026-08-25
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000163071

Description

Migration of a BIG-IP LTM Virtual Edition system between data centers requires preserving the configuration and master key, reusing the license, and adapting the network configuration when interface or VLAN mappings change.

This is a sample step that you can follow, however, if you required a comprehesive assistance, contact your F5 authorized reseller or F5 Professional Services.

Environment

  • Product: BIG-IP LTM Virtual Edition
  • Source and destination BIG-IP Virtual Edition systems
  • The destination system may use the same or different VLAN and interface mappings.
  • Use the same interface template on the destination system when possible.

Cause

Migration BIG-IP VE from old hypervisor to new hypervisor

Answer/Recommended Actions

  1. Back up the source system.
    • Generate a qkview and save a UCS configuration archive:
      qkview
      tmsh save sys ucs backup.ucs
    • Back up the BIG-IP master key:
      f5mku -K
  2. Revoke the license from the source system.
    • If the system has internet access, revoke the license before migration.
    • If the system cannot access the internet, contact F5 Support to request license release.
    • The license must be released before it can be reused on the destination system.
  3. Deploy the destination BIG-IP Virtual Edition system.
    • Deploy the system in the destination data center.
    • Use the same interface template as the source system when possible.
    • Ensure management and licensing connectivity.
  4. Restore the master key.
    • Copy the master key to the destination system and restore it:
      f5mku -r <master_key>
    • Save the configuration and verify the master key:
      tmsh save sys config
      f5mku -K
  5. Create a baseline UCS archive on the destination system (for rollingback purpose).
    • tmsh save sys ucs fresh_install
  6. Install the license.
    • Install the license using the BIG-IP Configuration utility.
      K7752: Licensing the BIG-IP system https://my.f5.com/manage/s/article/K7752
  7. Restore the UCS archive without restoring its license.
    • tmsh load sys ucs <ucs_file_name> no-license
  8. (Optional) Use "platform-migrate" when the network configuration changes.
    • If the destination system uses different interfaces or VLAN mappings, load the UCS archive with the "platform-migrate" option:
      tmsh load sys ucs <ucs_file_name> no-license platform-migrate
    • This option ignores the source interface configuration. Manually assign VLANs to the appropriate BIG-IP interfaces after restoring the UCS archive.
  9. Verify the migrated system.
    • Confirm that the BIG-IP configuration loaded successfully.
    • Verify VLANs, interfaces, self IPs, routes, virtual servers, pools, and monitors.
    • Confirm that BIG-IP system services are operational.
    • Test application traffic and management access.
    • Confirm the license and master key are valid.

Additional Information

  • Revoke the BIG-IP Virtual Edition license from the source system before reusing it on the destination system.
  • Restore the master key and UCS archive without loading the license from the UCS archive.
  • Use "platform-migrate" when the destination interface or VLAN configuration differs from the source configuration.
  • Hypervisor snapshots are not recommended as the primary backup or migration method for BIG-IP Virtual Edition systems. Use a UCS archive instead.
