K15464251: Windows Logon Integration not working with APM+GTM/DNS iRule

Type
Support Solution
Published
2025-07-01
Updated
2025-07-01
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K15464251

Description

  • When using APM together with GTM/DNS for Global Remote Access an iRule has to be configured on the BIG-IP
  • Windows Logon Integration does not work with the Global Remote Access iRule in place
  • Clients may observe error messages "Username or password is incorrect" or similar, VPN does not establish

Environment

  • BIG-IP with APM provisioned
  • APM configured with iRule for GTM/DNS support
  • Windows client
  • User is trying to establish BIG-IP VPN before Windows logon (Windows Logon Integration)

Cause

Windows Logon Integration uses a special sequence of requests, which cannot handle the redirects used by the GTM/DNS iRule.

Recommended Actions

Modify the APM+GTM/DNS iRule to the code below:

when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable
}

when HTTP_REQUEST {
    if {([string tolower [HTTP::host]] starts_with "<FQDN of the global APM instance>") \
          and ! ( [HTTP::method] equals "POST" ) \
          and ! ( [HTTP::uri] starts_with "/my.logon.php3?outform=xml&get_token=1") \
          and ! ( [HTTP::uri] starts_with "/vdesk/vpn/index.php3?outform=xml") \
          and ! ( [HTTP::uri] starts_with "/myvpn?sess=") \
          and ! ( [HTTP::uri] starts_with "/vdesk/vpn/connect.php3?resourcename=")} {
       log local0. "[HTTP::method] [HTTP::uri]" HTTP::respond 302 Location "https:// <FQDN of the local APM instance> [HTTP::uri]"
    }
}



Additional Information

This is a corner case unlikely to affect a significant number of installations.
