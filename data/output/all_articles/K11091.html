Known Issue

This is the result of a known issue. When you remove a self IP address from the BIG-IP system, the system does not remove the corresponding ARP entry from the ARP table. If the IP address you removed is reassigned to another host on the subnet, the BIG-IP system cannot contact that host due to the stale MAC address.

F5 Product Development tracked this issue as CR101898 and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

You can work around this issue by creating and deleting a static ARP entry for the affected IP address. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Create a static ARP entry for the affected IP address by using the following command syntax:

    bigpipe arp <deleted-self-ip-address> <MAC address>

    Note: It does not matter which MAC address you enter, as long as the MAC address is not in use on your network.

    For example:

    bigpipe arp 192.168.1.1 06:00:00:00:00:01
  3. Delete the static ARP entry you just created by typing the following command:

    bigpipe arp <deleted-self-ip-address> delete

    For example:

    bigpipe arp 192.168.1.1 delete

All ARP entries for the affected IP address are now removed from the ARP table used by TMM.
