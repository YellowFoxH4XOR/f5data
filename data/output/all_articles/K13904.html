Known Issue

Client requests made by Internet Explorer may generate CSRF attack detected violations.

This issue occurs when all of the following conditions are met:

  • The client request comes from Internet Explorer.
  • CSRF Protection is enabled in the BIG-IP ASM security policy.
  • The web resource requested contains an onload JavaScript function in the body element.

    For example, a body element similar to the following example would cause this issue to occur:

    <body onload="Javascript:submitForm();">

The onload function may interfere with the CSRF Protection injection process, resulting in requests being made without the required CSRT token.

Impact

CSRF attack detected violations will be generated.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • CSRF attack detected violations are generated for URLs returned from the BIG-IP ASM that contain the CSRT token in the query string. For example:

    <a href="https://host.domain.com/default.aspx?CSRT=17017154763700437104">

    Note: A network inspection or HTTP debugging tool, such as Wireshark or Fiddler, will be required to inspect the HTTP response returned by the BIG-IP ASM before it is executed by the browser.

Workaround

To work around this issue, you must upgrade to one of the BIG-IP releases listed in the Versions Fixed column in the Status table, and enable the search_onload internal parameter. To do so, refer to K13906: Enabling the search_onload internal parameter.
