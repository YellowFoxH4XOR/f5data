K000141081: TMM Memory is leaking when APM SAML is configured on v17.

Type
Support Solution
Published
2024-09-16
Updated
2024-09-16
Applies to
  • BIG-IP
  • BIG-IP APM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.1.X, 17.1.1
Source
https://my.f5.com/manage/s/article/K000141081

Description

TMM memory usage is increasing.

APM Saml is configured without "Sign Authentication Request" enabled, so it is not due to

  • Bug ID 1353021

Checking TMM memory usage in subsystem by running

tmsh show sys memory

sso::sso_saml's Alloc (bytes) and Max Alloc (bytes) are same value and it shows keep increasing steadly.

------------------------------------------------------------------------------
Sys::SubSystem Memory
SubSystem                        Alloc (bytes)  Max Alloc (bytes)  Object Size
------------------------------------------------------------------------------
...
sso::sso_saml                       6445468848        6445468848             1 

Environment

  • BIG-IP APM
  • v17.x
  • TMM memory leak
  • SAML configured

 

Cause

Possibly BUG ID 1378241

 

Recommended Actions

Without having TMM core (manually or due to limit of memory usage), we can not confirm this bug is the cause of the issue.

If you see sso::sso_saml is steadly increasing allocated memory size, then please generate fresh qkview and escalate the issue to F5 Support.

If it is possible, when it is on maintenance window, failover and manually generate TMM core following:

K15569543: Producing a TMM diagnostic core file

And provide it with qkview genarated after the core file.
