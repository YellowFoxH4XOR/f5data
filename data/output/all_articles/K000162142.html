K000162142: High TMM CPU utilization

Type
Support Solution
Published
2026-07-20
Updated
2026-07-20
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162142

Description

  • You observe high CPU utilization on BIG-IP.
  • You see TMM is the one consuming highest CPU. From the qkview file, CPU usage by core graphs shows all data plane (even core) CPUs are highly consumed.
  • You are observe direct co-relation in high CPU with increased SSL traffic.

Environment

  • BIG-IP LTM
  • Virtual server(s) with client SSL profiles using RSA 2048-bit certificates
  • Mutual TLS (mTLS) enabled with client authentication frequency set to "always"
  • iRule logging enabled for SSL traffic

Cause

High CPU utilization is caused by the client SSL profile's client authentication frequency being set to "always," which forces the BIG-IP to perform a full SSL handshake for every connection. The use of RSA 2048-bit certificates and SSL-related iRule logging further increases CPU load during high traffic periods.

Answer/Recommended Actions

This is expected behavior. You will have to optimize the settings of the SSL profile attached to the virtual server which is consuming highest CPU.

  • Change the client authentication frequency in the client SSL profile from "always" to "once" to reduce the number of full SSL handshakes and lower CPU usage.
  • Try to use use ECDSA (ECC) certificates for optimal performance.

Additional Information

  • Performance improvements from switching to ECC certificates may not be realized if only server certificates are changed; both client and server certificates should use ECC.
  • Changes to SSL profile settings will only impact new connections; existing sessions will retain previous settings until they are closed or timed out.
