Topic

You should consider using this procedure under the following conditions:

  • You want the BIG-IP APM system to log a notification in the /var/log/apm log file when the current active sessions, current connectivity sessions or SWG Limited sessions values exceed a configured threshold value.
  • You want to modify the default threshold value of 75% to a value that fits the requirement of your environment.

Description

Monitoring your BIG-IP APM system usage is a critical part of maintaining the uptime of your IT services. An important value to monitor is the active APM license usage of the system. To display this, enter the following command:

tmsh show apm license

Output appears similar to the following:

--------------------------------------------
Global Access License Details:
--------------------------------------------
total access sessions: 2.5K
current active sessions: 0
current established sessions: 0
access sessions threshold percent: 75
total connectivity sessions: 500
current connectivity sessions: 0
connectivity sessions threshold percent: 75
total swg sessions: 0
current swg sessions: 0
swg sessions threshold percent: 75
total swg limited sessions: 2.5K
current swg limited sessions: 0
swg limited sessions threshold percent: 75

For an explanation on the meaning of each field, refer to K15032: Determining license limits of the BIG-IP APM system. This article describes the procedure to configure the following two values:

  • access sessions threshold percent: This is the access sessions threshold warning percent set (default 75%). You can configure this value using the log.alertapmaccessthreshold database variable.
  • connectivity sessions threshold percent: This is the connectivity sessions threshold warning percent set (default is 75%). You can configure this value using the log.alertapmconnectivitythreshold database variable.
  • SWG Limited sessions threshold percent: This is the SWG URLF Limited sessions threshold warning percent set (default is 75%). You can configure this value using the log.alertapmurlflimitedthreshold database variable.

When the access sessions threshold percent value is exceeded, the system logs a message similar to the following in the /var/log/apm file:
notice tmm1[<pid>]: 01490564:5: (null):Common:00000000: Global access license usage is 1900 (76%) of 2500 total. Exceeded 75% threshold of total license.

When the connectivity sessions threshold percent value is exceeded, the system logs a message similar to the following in the /var/log/apm file:
notice tmm2[<pid>]: 01490565:5: 00000000: Global concurrent connectivity license usage is 393 (78%) of 500 total. Exceeded 75% threshold of total license.

When the SWG Limited sessions threshold percent value is exceeded, the system logs a message similar to the following in the /var/log/apm file:
notice tmm2[<pid>]: 01490566:5: 00000000: Global concurrent url filtering license usage is 760 (76%) of 1000 total. Exceeded 75% threshold of total license

 

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the TMOS shell (tmsh).

Procedures

  • Determining the configured threshold
  • Adjusting the configured threshold
  • Resetting the threshold to its default value

Determining the configured threshold

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view the currently configured values of each thresholds, use the following command syntax:

    Access Session:

    list /sys db log.alertapmaccessthreshold

    Concurrent Connectivity: (CCU)

    list /sys db log.alertapmconnectivitythreshold

    SWG URL Filtering: 

    list /sys db log.alertapmurlflimitedthreshold 
     

    The command for log.alertapmaccessthreshold displays an output similar to the following example:

    sys db log.alertapmaccessthreshold {
    value "75"
    }

    In this example, the output indicates that the system is configured to log a notification when the current active sessions exceeds 75% of the total access sessions licensed.

Adjusting the configured threshold

Impact of procedure: The notification logging intensity depends on your total sessions licensed and the rate of increase of usage in your environment. You should configure the threshold at a level sufficient for your capacity planning.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To adjust the threshold, use the following command syntax:

    modify /sys db <database variable> value <your preferred threshold value>

    For example, to configure the BIG-IP APM system to log a notification when the current connectivity sessions value exceeds 80% of the total licensed, enter the following command:

    modify /sys db log.alertapmconnectivitythreshold value 80

Resetting the threshold to its default value

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To reset the threshold to its default value, use the following command syntax:

    modify /sys db <database variable> reset-to-default

  3. For example, to reset the value of access sessions threshold percent to its default value, enter the following command:

    modify /sys db log.alertapmaccessthreshold reset-to-default
