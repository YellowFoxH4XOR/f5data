Issue

Error Message

err clusterd[<PID>]Blade <blade_number> turned RED: Quorum: local and primary SW differ, HA TABLE offline

In this error message, note the following:

  • <PID> is the clusterd process ID.
  • <blade_number> is the number of the affected blade.

For example:

err clusterd[4486]: 013a0018:3: Blade 1 turned RED: Quorum: local and primary SW differ, HA TABLE offline

Message Location

You may encounter this message in the following locations:

  • The /var/log/ltm file

Additionally, you may observe the quorum message when viewing the cluster status in the Configuration utility or the command line.

For example, the output of the tmsh show sys cluster command may appear similar to the following:

Sys::Cluster: default
-----------------------------------------
Address                 192.168.0.1/24
Availability             available
State                     enabled
Reason                 Cluster Enabled
Primary Slot ID      2
Primary Selection Time  08/28/18 18:10:05

------------------------------------------------------------------------------------------------------------------------------
`Sys::Cluster Members
`ID  Address        Availability  State    Licensed  HA       Clusterd  Reason
------------------------------------------------------------------------------------------------------------------------------
`1   192.168.0.2  offline         enabled  false    offline      quorum      Quorum: local and primary SW differ, HA TABLE offline
`2   192.168.0.3  available     enabled  true      standby   running      Run
`3   192.168.0.4  unknown     enabled  false    unknown  shutdown  Slot powered off or empty
`4   192.168.0.5  unknown     enabled  false    unknown  shutdown  Slot powered off or empty

Description

This message indicates a blade is performing the quorum process. Quorum is the process of synchronizing the blades.

When you add a blade to the system or replace a blade through the Return Materials Authorization (RMA) process, the system automatically initiates the quorum process in order to synchronize the software version and configuration from the existing blade to the new blade. 

Impact

The affected blade remains offline and unavailable to process traffic until the quorum process completes.

Recommended Actions

It is important to allow the quorum process to complete without interruption. You can view the status of the newly inserted blade quorum process using the tmsh show sys cluster command on the primary blade.

For additional information on the automated process that occurs when you add or replace a VIPRION blade, refer to K13965: Overview of the automated process of joining a newly installed or RMA replacement VIPRION blade to the cluster.
