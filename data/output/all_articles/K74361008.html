Description

A corrupt or missing server.key will cause the big3d process to restart continuously.

  • Log events similar to the following may appear in /var/log/gtm
    Jun 19 12:00:00 bigip1 err big3d[14259]: 012b3001:3: Private key /config/httpd/conf/ssl.key/server.key did not load
    Jun 19 12:00:00 bigip1 err big3d[14259]: 012b3003:3: CreateSSL_CTX: SSL error:0906D06C:PEM routines:PEM_read_bio:no start line
    Jun 19 12:00:00 bigip1 err big3d[14259]: 012b3003:3: CreateSSL_CTX: SSL error:140B0009:SSL routines:SSL_CTX_use_PrivateKey_file:PEM lib
     
  • Command line may display events similar to the following:
    Jun 19 12:00:00 bigip1 emerg logger: Re-starting big3d
    Jun 19 12:00:00 bigip1 emerg logger: Re-starting big3d
    Jun 19 12:00:00 bigip1 emerg logger: Re-starting big3d
     
  • openssl operations using the Device Certificate and key may show:
    unable to load Private Key----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------> 47933075984904:error:0906D06C:PEM routines:PEM_read_bio:no start line:pem_lib.c:696:Expecting: ANY PRIVATE KEY

Environment

BIG-IP LTM or BIG-IP DNS

Cause

The /config/httpd/conf/ssl.key/server.key file is either missing or corrupt.

Recommended Actions

Generate a new private key and certificate. Please see the section titled "Generating a new self-signed device certificate and private key", in the following article:
K9114: Creating a new SSL device certificate and key pair

Additional Information

It may be possible to repair the server.key file in a text editor, such as emacs or vim.
