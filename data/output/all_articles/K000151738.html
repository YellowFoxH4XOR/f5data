K000151738: Symbolic (soft) links broken between directories such as `/var/tmp` and `/shared/tmp`

Type
Support Solution
Published
2025-09-04
Updated
2025-09-04
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K000151738

Description

After a system reboot, symbolic (soft) links between directories such as /var/tmp and /shared/tmp may become broken on BIG-IP ASM VE systems. This can result in failures when creating new HDs or saving UCS files, with errors like:  

tm_install::VolumeSet::VolumeSet_prep_root -- symlink failed; ...shared/tmp : File exists
umount: ...shared: not mounted
Terminal error: Could not access configuration source; nvme0n1, 1

Attempts to remove affected directories may also fail with "source busy" errors.

Environment


- Product: BIG-IP ASM VE  
- Version: 17.1.2  
- Platform: F5-LTM-1G-PRM-SUB, BIG-IP  
- Configuration: Systems using symbolic links between `/var/tmp` and `/shared/tmp` or similar paths  
- Additional context: High disk usage in `/appdata`, especially from AVR data

Cause


Broken or stale symbolic links between directories (e.g., `/var/tmp` and `/shared/tmp`) after a reboot. This typically occurs if the directory structure or mount points are not properly restored during boot, or if the symbolic link is not recreated as expected. Excessive disk usage from AVR data can contribute by filling up storage and causing file system inconsistencies.

Recommendations

To resolve this issue:

1. **Console Access & Maintenance Mode**
   - Access the system console.
   - Reboot into maintenance mode.

2. **Mount the Affected Volume**
   - Identify the correct device for `/var` using `df -h`.
   - Mount it manually:
     ```
     mount <device> /var
     ```

3. **Remove and Recreate the Symbolic Link**
   - Change to the relevant directory:
     ```
     cd /var
     ```
   - Remove any existing `tmp` directory or broken symlink:
     ```
     rm -rf tmp
     ```
   - Recreate the symbolic link pointing to `/shared/tmp`:
     ```
     ln --symbolic --verbose ../shared/tmp tmp
     ```
   *Note*: The new symlink will only be effective after rebooting into TMOS.

4. **Reboot into TMOS**
   - Reboot back into normal operation mode (TMOS).

5. **Restore Security Contexts**
   - After reboot, restore security contexts for affected paths:
     ```
     restorecon -R -v /var/tmp /shared/tmp
     ```
   - Verify symlinks and contexts:
     ```
     ls -l --directory --context /var/tmp /shared/tmp
     ```
