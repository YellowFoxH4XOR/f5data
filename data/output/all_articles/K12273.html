Known Issue

This is the result of a known issue. If you load a configuration containing duplicate SNAT names, the pvad process will crash and produce a core file. For example, the following SNAT objects have the same name and will cause pvad to core when loading the configuration using the bigpipe load or bigpipe config sync commands:

snat dup-snat {
translation 10.10.10.100
origins 10.0.0.1
}
snat dup-snat {
translation 10.10.10.200
origins 10.0.0.2
}

Note: This issue is only likely to occur if you edit the bigip.conf file and add the duplicate SNAT names.

F5 Product Development is tracking this issue as ID 248674 (formerly CR91719).

Workaround

To work around this issue, ensure that each SNAT object has a unique name.
