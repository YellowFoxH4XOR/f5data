Known Issue

The VIPRION system may fail to boot after a software upgrade.

This issue occurs when all of the following conditions are met:

  • You upgrade the BIG-IP software on a VIPRION platform.
  • The BIG-IP software update includes a newer version of the chassis annunciator firmware.
  • You reboot to the slot with the newer version, shortly after the upgrade completes.

When a primary blade is determined on a multi-blade VIPRION platform, the primary blade attempts to upgrade the chassis annunciator firmware, if a newer version is available. Under certain conditions, where the primary blade reboots to another slot before this firmware update is complete, the chassis annunciator may enter boot loader mode. This results in Traffic Management Operating System (TMOS) startup failures because the system needs the annunciator to access critical data on the chassis.

Impact

The VIPRION system fails to process traffic, and devices configured as a high-availability pair may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The VIPRION system is not accessible using the management IP address.
  • An error message similar to the following example appears repeatedly on the console:

    emerg logger: Re-starting chmand
  • After an upgrade, the VIPRION system fails to process traffic.

Workaround

To work around this issue, you can use the bladectl utility to manually update the chassis annunciator firmware. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line using the serial console.
  2. Stop the chmand process by typing the following command:

    bigstart stop chmand
  3. Manually update the blade firmware by typing the following command:

    bladectl -u annun
  4. After the update command completes, restart the chmand process by typing the following command:

    bigstart start chmand
  5. Reboot the BIG-IP system using the full_box_reboot command.
