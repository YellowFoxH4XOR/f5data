Known Issue

Native Remote Desktop Protocol (RDP) resources may fail when launched from a BIG-IP APM access session webtop.

This issue occurs when all of the following conditions are met:

  • The local user device is running Mac OSX 10.x.
  • An RDP resource configured with the Native client type is assigned to the access session webtop.
  • The RDP profile is configured with SSO enabled.
  • The user attempts to launch the RDP resource from the BIG-IP APM webtop.

Impact

The RDP resource fails to launch.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When attempting to establish the RDP access session an error message similar to the following is displayed:

    An error occurred while communicating with the Remote Desktop Gateway. If this keeps happening, contact your network administrator for assistance.  
    Error code: 0x3000069

Workaround

To work around this issue, you can upgrade the MAC OSX RDP client to 10.2.0 or later. Alternatively you can modify the BIG-IP APM RDP resource and apply a custom iRule to the affected BIG-IP APM virtual server. To do so, perform the following procedure:

Impact of workaround: F5 recommends performing the following procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Connectivity / VPN > VDI / RDP > Remote Desktops.
  3. Click the name of the affected RDP profile.
  4. For Custom Parameters, enter the following stanza:

    full address:s:%{session.server.network.name} promptcredentialonce:i:1

  5. Click Update.
  6. Navigate to Local Traffic > iRules > iRule List.
  7. Click Create.
  8. Enter a Name for the new iRule.
  9. For Definition, enter the following stanza:

    when HTTP_RESPONSE_RELEASE {
        catch {
            set locationUri [HTTP::header Location]
            if { [HTTP::status] == 302 && $locationUri starts_with "rdp://" } {
                if { [regexp {username=s:f5_apm([\/\%\w]+)} $locationUri dummy launchToken] } {
                    HTTP::header Location $locationUri&gatewayaccesstoken:s:$launchToken
                }
            }
        }
    }

  10. Click Finished.
  11. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  12. Click the name of the affected virtual server.
  13. Click the Resources tab.
  14. Click Manage.
  15. Click the newly created iRule in the Available list and move the iRule to the Selected list.
  16. Click Finished.
