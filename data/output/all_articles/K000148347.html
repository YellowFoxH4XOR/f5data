Description

For SSL traffic terminating on LTM, BIG-IP selects cipher suite from the list of configured ciphers.

  • BIG-IP selects the highest TLS version supported by the client and enabled in the Client SSL profile.
  • BIG-IP selects the first cipher suite from the list of ciphers configured in Client SSL profile which is present in Client Hello.
  • The order of cipher suites in Client Hello is not significant. Cipher suite is selected based on the order of ciphers in Client SSL profile.

Note: Cipher suites for TLS 1.3 are not compatible with TLS 1.2 and earlier protocol versions. Even if the list of ciphers displays TLS 1.3 ciphers after TLS 1.2 ciphers, when TLS 1.3 is negotiated (protocol version is selected before a cipher suite) BIG-IP will select the first cipher suite from TLS 1.3 ciphers configured in Client SSL profile which is presented in Client Hello. If Client SSL profile with TLS 1.3 enabled receives Client Hello from TLS 1.3 client but it does not include TLS 1.3 cipher suite supported by the Client SSL profile the connection will be aborted with "no shared ciphers" alert even there are TLS 1.2 cipher suites supported by both client and BIG-IP.

Note: Client SSL profile must contain certificate and key type matching authentication algorithm from the cipher suite.

For example: to be able to use ECDHE-ECDSA cipher suites Client SSL profile must contain ECDSA certificate and key.

Environment

  • Virtual Server with Client SSL profile.

Additional Information

To check the order of configured cipher suites:

  • For Cipher String run 'tmm --clientciphers <string>' for example:

 tmm --clientciphers DEFAULT

  • For Cipher Group run 'tmsh show ltm cipher group <group_name>' for example:

 tmsh show ltm cipher group f5-default
