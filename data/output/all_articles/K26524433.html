Description
When using a stream profile to replace content from http with https, the system may match unexpected HTTP responses, for example, the response with the PNG image. This results in a malformed PNG image and the client browser may not load the web pages as expected. You might observe this issue when you have TLS/SSL offload scenario.

When the issue is happening, you may have a configuration like the below example:

  1. You have a stream profile attached to your Virtual server in trouble. AND,
  2. Your Stream profile is configured with source: http and target: https, the configuration file will be like this:

ltm profile stream /Common/http-to-https {
    app-service none
    defaults-from /Common/stream
    source http
    target https
}

When you have this issue, the PNG image response will have some http schema definition replaced with https if you review the packet capture. Meanwhile, you will find that the content length is not matching from the original PNG image due to the replacements. For example:

HTTP/1.1 200 OK
Content-Type: image/png
Last-Modified: Sun, 30 Jan 2022 00:00:00 GMT
Accept-Ranges: bytes
Server: nginx
Date: Sun, 30 Jan 2022 00:00:00 GMT
Content-Length: 9082

Environment

  • BIG-IP LTM
  • TLS/SSL Offload
  • Stream profile replacing http with https

Cause
The Stream profile itself will process the content and replace all http with https, and such processing will be triggered ahead of the iRule.

Recommended Actions

You can solve this issue by removing the replacement configuration in the stream profile and instead use iRule to replace the contents in a more specific way.

You may attach the below iRule to replace the feature provided by the existing stream profile:

when HTTP_REQUEST {
    STREAM::disable
    HTTP::header remove "Accept-Encoding"
}
when HTTP_RESPONSE {
    if { [HTTP::header value Content-Type] contains "text"} {
       STREAM::expression {@http://@https://@}
       STREAM::enable
   }
}

When you attached the above iRule, the system still will replace the http contents with https for all kind of responses using the profile ahead of the iRule, so you will need to remove the replacement configuration in the stream profile. To remove the replacement configuration, you can:

  1. Go to Local Traffic  ››  Profiles : Other : Stream, find your stream profile that is in use.
  2. Then, clear up the http and https for the source and target options. It should be blank.
  3. Click Save.
