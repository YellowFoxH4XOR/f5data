Known Issue

The BIG-IP system may fail to insert persistence cookies into the HTTP responses.

This issue occurs when all of the following conditions are met:

  • An HTTP virtual server is configured with a Cookie persistence profile and is associated with a TCP profile that has the Verified Accept option enabled.
  • The client sends an HTTP request to an HTTP virtual server.

Impact

The BIG-IP system may incorrectly load-balance HTTP request from a client.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system fails to persist client requests to the correct pool member.

Workaround

To work around this issue, you can apply an iRule to a virtual server with the Verified Accept option configured.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

For example, the following iRule bypasses the Verified Accept option on the first HTTP request and forces load balancing based on persistence:

when HTTP_REQUEST {
        if { [HTTP::request_num] == 1 } { LB::detach }
    }
