K35067300: Istio-proxy sidecar does not utilize assigned resources

Type
Support Solution
Published
2021-11-24
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K35067300

Description

While running traffic for testing performance, it is observed that the istio-proxy sidecar is not utilizing the CPU/Memory assigned to it. We are seeing that even though after assigning 15 CPU and 15G of memory (The setup is done for the test case and is not recommended for general use), the utilization does not go above 2.4/2.5 CPU and the memory stays around 2G, which is causing the latency to increase substantially, and resulting timeouts & failures when more then latency of 150ms is introduced in the environment.

Following are some of the log messages from the istio-proxy sidecar:

Environment

  • Aspen Mesh: 1.9.x

Cause

After looking through config dumps for the client pod, you can see that a destination rule http-rule is added to the cluster to limit the maximum connection to 300 and maximum request to 1000. This caps the amount of memory and CPU sidecar can use.

Recommended Actions

After removing the destination rule, which was capping the number of connections, the sidecar should work as expected.
