Description

Assigning the "Application Editor" user role within a partition grants users write access to most APM objects. This behavior is broader than what is described in some documentation pages, which states that Application Editors are limited to managing nodes, pools, pool members, monitors, and their own password, while in reality, Application Editors can create, modify, and delete a wide range of APM objects with only a few specific restrictions.


Environment

User Role: Application Editor in APM


Cause

The Application Editor role is intentionally configured to provide read/write permissions for most APM objects. The official documentation at https://techdocs.f5.com/en-us/bigip-17-0-0/big-ip-systems-user-account-administration/user-roles.html focuses on LTM object permissions and does not comprehensively describe the extended access granted when the APM module is provisioned. This expanded permission set for APM objects is by design.


Recommended Actions

Application Editor role allows extensive management of APM configuration

  • Can create/modify/delete nearly all objects under "Access" menu tabs.
  • Cannot create or delete Access Profiles.
  • Cannot modify the "Max Concurrent Users" setting of an Access Profile.
  • Can modify most other fields within an Access Policy and activate modified policies.
  • Has full control over AAA server configurations (LDAP, RADIUS, Active Directory), including creation, modification, and deletion.
  • Has full control over ACLs (Access Control Lists), including creation, modification, and deletion.

Review internal security policies and user assignments in light of these permissions to ensure compliance with organizational requirements. If more restrictive or granular access control is needed for APM configuration tasks, consider implementing custom roles or additional access controls where possible.
