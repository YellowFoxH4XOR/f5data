Description

This article describes an issue where enabling HTTP/2 support on a BIG-IP LTM virtual server may prevent client requests from being forwarded to backend pool members. The virtual server accepts TCP and TLS connections and appears to process HTTP/2 traffic, but does not transmit these requests to the selected pool member. As a result, clients may wait indefinitely for a response, while some browsers may downgrade the connection to HTTP/1.1 and continue operating. No explicit errors are generated by the system.

Environment

  • BIG-IP LTM

Cause

The failure to forward HTTP/2 requests occurs when the configuration includes features that are incompatible with BIG-IP full proxy HTTP/2 operation. When unsupported components such as OneConnect, certain caching features, non-cookie persistence methods, or unsupported iRule commands are present, the virtual server cannot correctly relay HTTP/2 traffic to backend servers.

Recommended Actions

To restore proper forwarding of client requests, remove any unsupported configuration elements from the virtual server. If full proxy HTTP/2 is not required, disable HTTP MRF routing so that traffic to backend servers uses HTTP/1.1. If full proxy HTTP/2 is required, ensure that incompatible features such as OneConnect, caching mechanisms, non-cookie persistence, and unsupported iRule commands are not used, and verify that all remaining configuration elements meet the requirements for HTTP/2 operation.
