Topic

You can use passwordless client certificate authentication to grant access to resources that sit behind a virtual server. Using passwordless client certificate authentication will allow users to connect to a virtual server that requires authentication without having to enter their username and password. For this type of authentication to work, the user must have a client certificate, which has a standardized field that can be inspected and installed on their machine. For example, the client certificates could have the username in the Subject field, or all members of group Sales can have Sales in the Organization Unit (OU) value. The following procedure helps you to configure passwordless client certificate authentication by creating an access profile that looks for a client certificate, creates a session variable that extracts the username from the certificate's Subject field, performs an LDAP query that verifies whether the username is valid, and assigns the user to a master group based on the LDAP query results. Users who belong to a master group and who have a valid client certificate installed will be able to access resources behind a virtual server without supplying a password on the BIG-IP APM login page.

Note: Web browsers will not prompt users for client certificates if no client certificate has been imported into their browser, and if the prompting option has been disabled. This setting is located on Windows Control Panel > Internet Options > Security Tab > Custom level for the applicable zone and in Firefox at Tools > Options > Advanced > Encryption. For full instructions, refer to your browser vendor documentation.

Configuring passwordless client certificate authentication

To configure passwordless client certificate authentication, you must perform the following procedures:

  • Creating the Access Profile
  • Verifying whether the client has a certificate
  • Extracting the username from the certificate's Subject field
  • Running LDAP query to validate user and assign group
  • Allowing user access
  • Applying the Access Policy
  • Assigning the Access Profile to a virtual server

Creating the Access Profile

  1. Log in to the Configuration utility.
  2. Expand Access Policy.
  3. Click Access Profiles.
  4. Click Create.
  5. Type a name for the Access Profile.

    For example:

    pwdless_auth

  6. Ensure that the Secure Cookie option is enabled.
  7. Click Finished.

Verifying whether the client has a certificate

  1. Click the Edit link for the Access Profile you created.

    The Visual Policy Editor opens in a new window or tab.
  2. Click the (+) after the Start box.
  3. In the Authentication section, select Client Cert Inspection.
  4. Click Add Item.

    The Client Cert Inspection Properties pop-up screen displays. 
  5. Click Save.

Extracting the username from the certificate's Subject field

  1. Click the (+) on the Successful Branch.
  2. In the General Properties section, select Variable Assign.
  3. Click Add Item.

    The Variable Assign properties pop-up screen displays.
  4. In the Name field, type a name for the Variable Assign action.

    For example: 

    Extract Username

  5. Click the Add new entry button.
  6. Click the change link.

    A new pop-up screen displays.
  7. In the Custom Variable section, type a name for your variable.

    For example:

    session.logon.last.username

  8. In the Custom Expression section, enter the expression you want used to extract this information.

    For example:

    set f1 [mcget {session.ssl.cert.subject} ]
    set f2 [split $f1 "," ]
    set f3 [lindex $f2 1]
    set f4 [split $f3 "="]
    set f5 [lindex $f4 1]

  9. Click Finished.
  10. Click Save.

Running LDAP query to validate user and assign group

  1. Click the (+) on the fallback branch.
  2. In the Authentication section, select LDAP Query.

    Important: Do not select the LDAP Auth option. That option prompts your users for a password.

  3. Click Add Item.

    The LDAP Query properties pop-up screen displays.
  4. From the Server drop-down menu, select the LDAP server you want to query against.
  5. In the SearchDN field, enter SearchDN information that is applicable for your environment.

    For example:

    CN=Users,DC=example,DC=com

  6. In the SearchFilter field, enter a filter that uses the variable you configured above.

    For example:

    (sAMAccountName=%{session.logon.last.username})

  7. Click the Branch Rules tab.
  8. Click the change link.

    The Branch Rule properties pop-up screen displays. 
  9. Change the information in the User is a member of field to match your environment and group name.

    For example:

    CN=Sales,CN=Users,DC=example,DC=com

  10. Click Finished.
  11. Optional: If more than one group is using passwordless certificate authentication, click the Add Expression button that is located under OR and enter the information for a different group. Repeat Steps 9 and 10 until all groups have been added.
  12. Click Save.

Allowing user access

  1. Click the Deny box connected to the User Group Membership branch.
  2. Select Allow.
  3. Click Save.

Applying the Access Policy

  1. Select the check box next to the access profile that you created.
  2. Click the Apply Access Policy button.

Assigning the Access Profile to a virtual server

  1. From the left side navigation panel, expand Local Traffic.
  2. Click Virtual Servers.
  3. Select the Virtual Server that you would like people to access to use this authentication method.
  4. Accept default values with the following exceptions:
     
    • HTTP Profile: Select http from the drop-down menu.
    • SSL Profile (Client): Select prof-clientcert from the drop-down menu.
    • SNAP Pool: Select Auto Map from the drop-down menu.
    • Access Profile: Select the profile that you created.

      For example:

      pwdless_auth

    Important: This virtual server needs to use the Service Port 443. If the virtual server is not using that port, you need to change the Service Port to HTTPS under General Properties.

  5. Click Update.
