Issue

Error Message

info tmm1[<PID>]: 01260039:6: Block cipher data limit exceeded.

In this error message, note the following:

  • <PID> is the process ID for the Traffic Management Microkernel (TMM) process.

For example:

info tmm1[19319]: 01260039:6: Block cipher data limit exceeded.

Message Location

You may encounter this message in the following locations:

  • The /var/log/ltm file
  • The Configuration utility

Description

This message occurs when the following condition is met:

  • The amount of data encrypted or decrypted using the block cipher exceeds the safety limit.

This safety limit is introduced in the fix for K13167034: OpenSSL vulnerability CVE-2016-2183. Beginning in BIG-IP 12.1.2 HF1, the BIG-IP system implements the TLS session data limit (1 GB) for 3DES that makes the use of 3DES secure on the BIG-IP system in reference to the SWEET32 attack CVE-2016-2183.

Impact

When the data limit is exceeded, the SSL session is renegotiated. If renegotiation is successful, there is no impact. If renegotiation fails, the SSL connection terminates and you may observe application issues and SSL handshake failure errors in the logs.

Recommended Actions

  • Configure your SSL profiles so that renegotiated SSL sessions succeed. For more information on SSL renegotiation and its relevant settings, refer to the Renegotiated SSL sessions section in K15475: Troubleshooting SSL/TLS renegotiation.
  • Avoid using block ciphers which have a data safety limit. You can disable 3DES in your SSL profile by performing the mitigation described in K13167034: OpenSSL vulnerability CVE-2016-2183.
