Description

When troubleshooting DNS resolution failures involving large UDP responses (such as EDNS0 queries with buffer sizes exceeding the interface MTU), it may appear that BIG-IP DNS drops all but the first UDP fragment. This can result in incomplete DNS responses and failures for records larger than ~1480 bytes, notably impacting SPF TXT record validation for mail delivery. However, this apparent issue is often caused by limitations in packet capture filters (such as using a port filter), which exclude non-initial fragments from the analysis. No error messages are generated by BIG-IP; the symptom is incomplete DNS responses observed in filtered packet captures.

Environment

  • BIG-IP DNS
  • MTU: 1500 bytes
  • DNS listeners configured for UDP/EDNS0 queries with large buffer sizes
  • DNS responses (e.g., TXT records) exceeding 1480 bytes
  • Packet captures performed with filters such as "port 53" or similar

Cause

Packet capture filters based on port (e.g. "port 53") only capture initial UDP fragments containing the L4 header. Non-initial fragments (offset > 0) do not contain port information and are excluded from the capture, leading to the false impression that BIG-IP is dropping fragments.

Answer/Recommended Actions

When capturing fragmented UDP traffic for DNS troubleshooting, use a packet capture filter based on host or IP address, not port. For example:

tcpdump -nni <interface> -s0 -w <file> host <IP address>

Reproduce the issue and review the capture in a tool such as Wireshark, which can reassemble fragmented packets.

Confirm that all fragments are present and the DNS response is complete.

If all fragments are captured and reassembled, BIG-IP is functioning correctly and not dropping UDP fragments.
