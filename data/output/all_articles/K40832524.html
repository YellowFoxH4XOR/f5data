Topic

You should consider using these procedures under the following conditions:

  • After modifying the management IP/host name of your units, you need to rebuild the device trust.
  • You receive a Returns Materials Authorization (RMA), but you do not have a valid user configuration set (UCS) file to restore the configuration, and you need to join the replacement unit to the high availability (HA) cluster after performing its basic configuration.
  • You need to rebuild the device trust as part of the configuration synchronization (ConfigSync)/device service clustering (DSC) troubleshooting process. For more information, refer to K13946: Troubleshooting ConfigSync and device service clustering issues.

To use the Configuration utility to perform this procedure, refer to K42161405: Rebuilding device trust using the Configuration utility (11.x - 17.x).

Description

To rebuild device trust for BIG-IP systems configured in HA device groups, perform the following procedures:

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You configured the systems for HA device groups.
  • You have administrative access to the TMOS Shell (tmsh).

Procedures

  • Pre-work check list
  • Force the standby device offline and break the trust
  • Remove the configuration from the active device and rebuild the trust
  • Bring the standby devices online

Pre-work check list

Confirm the IP address and device management configuration for each BIG-IP system in the HA configuration. You should perform the following procedure on each device in the device group.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. 

  1. On both systems, verify the full device name by entering the following command:

    tmsh list /cm device hostname

  2. On both systems, verify the management IP addresses by entering the following command:

    tmsh list /cm device management-ip

    Note: You need the password for the administrative account on the standby device.

  3. Make note of the device groups used by the device service clustering (DSC) group by entering the following command:

    tmsh list /cm device-group

  4. Verify the ConfigSync addresses by entering the following command:

    tmsh list /cm device <device> configsync-ip

    For example:

    tmsh list /cm device your.device configsync-ip

  5. Verify Failover unicast addresses by entering the following command:

    tmsh list /cm device <device> unicast-address

    For example:

    tmsh list /cm device your.device unicast-address

    Follow the best practices specified in the Managing Failover section of the BIG-IP Device Service Clustering: Administration guide.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  6. Verify that the ConfigSync and failover self IPs are set to either allow-service all or allow-service default by entering the following command:

    tmsh list /net self

Force the standby device offline and break the trust

You can force the standby device to an offline state, which will prevent devices from entering an active-active state while performing this maintenance. To do so, perform the following procedure:

Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. This procedure causes the current device to lose connectivity with all other BIG-IP devices. Depending on the device group and traffic group configuration, the connectivity loss may result in an unintentional active-active condition that causes a traffic disruption.

  1. On the standby device, log in to tmsh by entering the following command:

    tmsh

  2. Force the standby device offline by entering the following command:

    run /sys failover offline

    If your standby device is a VIPRON or vCMP guest, set Minimum Blades Up to a number that is greater than the total number of blades in the chassis and enable the min-up-members-enabled setting using the following command syntax:

    modify /sys cluster default min-up-members <a number greater than the total number of blades>  

    modify /sys cluster default min-up-members-enabled yes

    For example, in a VIPRION chassis with four blades, set Minimum Blades Up to 5 by entering the following command:

    modify /sys cluster default min-up-members 5

    modify /sys cluster default min-up-members-enabled yes

  3. Delete the device trust members configured on the standby unit by entering the following command:

    delete /cm trust-domain all

    Note: This command will generate new self-signed certificate for the device trust.
    Note: The standby unit displays as Standalone and ForcedOffline, on versions prior to BIG-IP 13.x, and the active unit displays as Disconnected. For BIG-IP 13.x and later, the active unit displays as Active/In Sync. Repeat this procedure for additional standby units.

Remove the configuration from the active device and rebuild the trust

Impact of procedure: F5 recommends that you schedule this procedure during a maintenance window to minimize impact in mission critical environments.

  1. On the active device, log in to tmsh by entering the following command:

    tmsh

  2. To remove the device from the device group, enter the following command:

    modify /cm device-group <sync_group_name> devices delete { all }

    For example, the following command deletes all the devices from the SyncFailover device group:

    modify /cm device-group SyncFailover devices delete { all }

    list /cm device-group

  3. Delete the peer device from the trust by entering the following command:

    delete /cm trust-domain all

    Note: This command will generate new self-signed certificate for the device trust.
    Note: Both devices should now display as Standalone. Repeat step 2 for each device group (besides device_trust_group and gtm).

  4. Add the peer devices to the local trust domain using the following syntax for your version: 

    • BIG-IP 13.x and later

      modify /cm trust-domain /Common/Root add-device { device-ip <mgmt_ip_address> device-name <device name> username <admin_username> password <admin_password> ca-device true }

      For example, the following command adds the remote device called BIGIP.remote.net (with the management IP address of 172.24.10.100, and the administrator user name and password of admin/admin) to the local system's trust domain:

      modify /cm trust-domain /Common/Root add-device { device-ip 172.24.10.100 device-name BIGIP.remote.net username admin password admin ca-device true }

      Note: If you get the error Syntax Error: incomplete command, check to see if the password includes the specific characters. If it does, then enclose the password in single quotations, as in as the following example:

      modify /cm trust-domain /Common/Root add-device { device-ip 172.24.10.100 device-name BIGIP.remote.net username admin password 'test1234!@#$' ca-device true }

    • BIG-IP 11.x - 12.x

      modify /cm trust-domain Root ca-devices add { <mgmt_ip_address> } name <device name> username <admin_username> password <admin_password>

      For example, the following command adds the remote device called BIGIP.remote.net (with the management IP address of 172.24.10.100, and the administrator user name and password of admin/admin) to the local system's trust domain:

  5. Add both devices to the device group by entering the following command:

    modify /cm device-group <SYNC_GROUP_NAME> devices replace-all-with { <active_device_hostname> <standby_device1_hostname> [<standby_device2_hostname>] }

    For example, the following command adds the devices specified to the device group named SyncFailover:

    modify /cm device-group SyncFailover devices replace-all-with { BIGIP.active.net BIGIP.standby1.net [ BIGIP.standby2.net ] }

    Note: Both devices should displays as Awaiting Initial Sync.

  6. Complete the initial synchronization by entering the following command on the active unit:

    run cm config-sync to-group <sync_group_name>

    For example:

    run /cm config-sync to-group SyncFailover

    Note: The initial synchronization takes a couple of minutes.

    Repeat steps for each additional device group.

Bring the standby devices online

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, F5 recommends that you schedule this procedure during a maintenance window.

  1. On the standby unit, log in to tmsh by entering the following command:

    tmsh

  2. On the standby unit, ensure sync and release are offline by entering the following command:

    show /cm sync-status

    Note: You must ensure all devices appear in all appropriate device groups besides gtm by entering the following command:

    list /cm device-group

  3. Bring the standby device online by entering the following command:

    run /sys failover online

    Note: If you're working with a VIPRION or vCMP guest, enter the following command:

    modify /sys cluster default min-up-members 1

    Then enter the following command:

    modify /sys cluster default min-up-members-enabled no

    Note: You must ensure it now displays Standby.

    Repeat step 3 for each additional device.
