Topic

The BIG-IP APM Endpoint Security features allow administrators to detect the presence and state of third-party security software, such as personal firewalls, antivirus, anti-spam, anti-spyware or integrated packages. To perform this detection, several of the endpoint security client-side access policy items use software libraries from a software development kit (SDK) created by OPSWAT.

Description

OPSWAT provides a vendor-independent framework for endpoint security management. The BIG-IP APM system incorporates OPSWAT Endpoint Security Integration SDK libraries with the following endpoint security client-side checks:

  • Anti-spyware
  • Antivirus
  • Firewall
  • Hard Disk Encryption
  • Patch Management
  • Peer-to-Peer
  • Windows Health Agent

To view the third-party security products supported by the OPSWAT SDK libraries installed on your BIG-IP APM system, navigate to System > Software Management > Antivirus Check Updates, click the Device EPSEC Status tab, and click the hyperlink for the Installed OESIS Version.

Note: For some third-party security products, the OPSWAT SDK can only check specific elements. This is indicated by the presence of Implemented or Not Implemented in the product feature columns.

Important: If a specific third-party security product or version is not listed, the product is not supported by the version of OPSWAT currently installed on the BIG-IP APM system.

If the third-party security product used by your organization is not listed in the supported products charts, you can obtain and install the latest OPSWAT SDK hotfix for your version of BIG-IP APM software. For more information, refer to K10942: Installing OPSWAT hotfixes on BIG-IP APM systems (10.x - 11.3.0).

If you are already running the latest OPSWAT SDK hotfix for your BIG-IP APM version, and the third-party security product used by your organization is not supported by that hotfix release, you can configure other access policy items to check the presence of the security product on the connecting computers. For example, you can use a Windows Process, Windows Registry, or File Check to determine if the security product is installed and enabled. To do so, create a client-side endpoint security item to check for the security product not currently supported by the OPSWAT SDK and add the item to the fallback branch of the existing antivirus, firewall, or other endpoint check. If the client-side check determines the security product is installed and enabled on the user's computer, you can choose to lead the user to a successful conclusion of the access policy evaluation.

For information about configuring a Windows Process, Windows Registry, or File Check in your access policy in order to search for the presence of a third-party security product, refer to the relevant section of the BIG-IP Access Policy Manager: Visual Policy Editor manual for your BIG-IP APM software version.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.
