Description

BIG-IP Virtual Edition (VE) instances deployed in AWS may fail to load configuration and report licensing errors after reboot or UCS restore. Common error messages include:

  • The license is not operational (expired or digital signature does not match contents).
  • DossierReq exception: VirtDossier Service: Instance identity retrieval from the metadata failed. Check network connectivity to the instance metadata before retrying
  • Configuration error: Change to Security.FIPS140.Compliance DB variable not allowed without corresponding change in the FIPS 140-3 Compliance license.

The device may remain in a REBOOT REQUIRED state, with management and data interfaces down, requiring manual intervention to restore operation.

Environment

  • Product: BIG-IP VE
  • Version: 15.1.x, 16.1.x, 17.1.x
  • Platform: AWS EC2 (multi-NIC deployment)
  • Licensing: FIPS 140 Compliance license

Cause

During boot, BIG-IP VE must reach the AWS instance metadata service via its management interface to validate its license.

If the mgmt interface is configured with a static IP that does not match the ENI’s primary private IP, cloud-init cannot verify connectivity and attempts DHCP on mgmt.
This can result in cloud-init bringing down the mgmt interface, preventing access to AWS metadata services needed for licensing validation.

Consequently, license checks fail, mgmt interfaces remain down, and configuration cannot be loaded after reboot.

Recommended Actions

  1. Configure the mgmt interface with ENI’s primary private IP only:
    • Ensure that BIG-IP’s management IP matches the primary private IP assigned to its AWS ENI.
    • Do not use a secondary ENI IP as mgmt; revert any such changes by removing the secondary assignment and updating the BIG-IP config if necessary.

  2. Add a static management route:

    Create a management route so that traffic from mgmt can reach the AWS metadata service during boot.

    tmsh create sys management-route default gateway <gateway_ip>

    The gateway should be appropriate for your VPC/subnet.

  3. Follow F5 best practices for AWS deployments:
    • Reference official documentation for multi-NIC deployments.
    • Avoid unsupported manual changes to mgmt addressing.

  4. If the device is stuck post-reboot:
    • Use serial console access if available.
    • Manually bring up the mgmt interface if it was down.
      ip link set dev mgmt up
    • Run reloadlic Then check the status with tmsh show sys license
    • Correct underlying mgmt addressing/configuration as above.
