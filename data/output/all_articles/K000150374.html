K000150374: MySQL Health Monitor fails to initiate TLS1.2 Handshake

Type
Support Solution
Published
2025-03-19
Updated
2025-03-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000150374

Description

Issues setting up MySQL Health Monitor on BIG-IP. The MySQL Health Monitor constantly marks the pool as 'DOWN'.

Upon collecting the packet capture, it is visible that the SSL Handshake for MySQL monitor fails in the phase of negotiation of the TLS version with the following indication:

Alert (Level: Fatal, Description: Protocol Version)

Environment

  • BIG-IP LTM 17.1.x
  • MySQL Health Monitor
  • MySQL backend Server accepts TLS 1.2 and TLS 1.3 only.

Cause

In the BIG-IP TMOS ver. 17.1.x or lower, the MySQL Health Monitor starts the SSL Handshake with TLS 1.1, which results in a failed SSL Handshake Protocol version between the MySQL Health Monitor on BIG-IP and the MySQL backend server.

Beginning with BIG-IP TMOS 17.1.2.1 the MySQL Health Monitor behavior has changed, and it now initiates the SSL Handshake with TLS 1.2

Recommended Actions

Upgrade the BIG-IP to TMOS ver. 17.1.2.1 or above, where MySQL Health Monitor behavior has changed and the BIG-IP MySQL Health Monitor now initiates the SSL Handshake with TLS 1.2.

Please refer to:
K84205182: Guide contents | BIG-IP update and upgrade guide
