Description

Even after configuring SNMP in the BIG-IP, it's not responding to SNMP queries. For example you have verified that (0.0.0.0/0.0.0.0) all IPs are in the allowed hosts list. 
However, when trying to use snmpwalk locally the following error message is shown "Timeout: No Response from localhost"

Example:

snmpwalk -v 2c -c public localhost .1.3.6.1.4.1.3375.2.1.1.2.20.13

Timeout: No Response from localhost



Environment

  • BIG-IP
  • SNMP 

Cause

This can happen if any of the following issues occur:

  • There is more than one instance of snmpd listening on the same port
  • snmpv2c is disabled in the configuration
  • Wrong community string is used when performing SNMP walk
  • SNMP agent IP address is not in the allowed addresses

Recommended Actions

 

  • Verify if there is more than one instance of snmpd
  1. # tmsh show /sys proc-info | grep -A 3 -i snmpd
  2. If there is more than one process, note down both the PIDs. As this could be causing the problem.
  3. Kill both the snmpd instances using command below:

    # kill -15 <PID of instance 1>
    # kill -15 <PID of instance 2>

  4. Once they are terminated, MCPD will automatically restart the snmpd. If it doesn't, run the command to restart snmpd.

    # bigstart restart snmpd

     

    • Verify if snmpv2c is enabled / disabled
    1. # tmsh list sys snmp all-properties
    2. Check the output to see if snmp is disabled (output similar to the following): 
      }
      snmpv1 disable  <----
      snmpv2c disable <----
      sys-contact "Customer Name <admin@customer.com>".

    3. If snmp is disabled use the following command to enable snmp
    4. # tmsh modify sys snmp snmpv2c enable
    5. # tmsh save sys config 



    • Verify the snmp community string from the command line
    1. # tmsh list sys snmp communities (output is similar to the following): 
      sys snmp { 
            communities { 
                  com-public {
                     community-name public       <----- "public" is the community string 
                   }
             }
      }

    2. Verify that you are using the correct community string in your snmp queries as configured on the system

     

    • Verify that the addresses initiating the snmp queries are in this list
    1. # tmsh list sys snmp allowed-addresses (output may be similar to the following): 
      sys snmp {
             allowed-addresses { 127.0.0.0/8 10.0.0.0/8}
      }
    2. To add an address range use the following command:
      # tmsh modify sys snmp allowed-addresses add {12.0.0.0/8} (this command will add the 12 subnet to the allowed-address list)

     

     

    Additional Information

    If these Recommended Actions did not resolve the SNMP issue on the BIG-IP system, you may want to further troubleshoot the issue by attempting packet capture of SNMP traffic between the SNMP agent and the BIG-IP system. You can perform the packet capture either on the SNMP agent (if allowed) or the BIG-IP system. For example, you can run the following command from the BIG-IP system advanced shell (bash) to see if there are any ingress or egress traffic on port 161 (the default SNMP port):

    tcpdump -nni mgmt -A -vv port 161

    If you want to only capture traffic from the SNMP agent, you can include the IP address of the SNMP agent:

    tcpdump -nni mgmt -A -vv <SNMP agent IP address> and port 161

    If you want to save the captured traffic to a file, you should use the -w option with the full path to the file. For example,

    tcpdump -nni mgmt -A -vv <SNMP agent IP address> and port 161 -w /var/tmp/exampleSNMP.pcap

    For more information on how to use the tcpdump utility on the BIG-IP system, refer to K00463541: A breakdown of the tcpdump utility, recommended actions, and information to help you use and apply it to the BIG-IP.
