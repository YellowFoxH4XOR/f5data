Known Issue

The Traffic Management Microkernel (TMM) process may restart and produce a core file when decision logging is enabled and a global server load balancing (GSLB) pool or pool member is disabled.

This issue occurs when all of the following conditions are met:

  • You disable a GSLB pool or GSLB pool member.
  • Pool Member Selection is enabled within the Load-Balancing Decision Log settings on the wide IP to which the pool belongs.

Impact

If the BIG-IP system is a member in a redundant configuration, traffic will fail over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic will be interrupted until TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to another host in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system temporarily fails to process traffic while TMM restarts.
