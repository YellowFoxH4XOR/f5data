Issue

Description

An unusual number of packets with only the TCP FIN flag set is a possible indication of a firewall scanning technique to determine a port as open on a target system. Similarly, while unlikely, sending a flood of random packets with the TCP FIN flag set may affect established connections to a system. This uncommon increase of packets with the TCP FIN flag set is commonly known as a TCP FIN flood attack.

The BIG-IP AFM system is built on full-proxy architecture, and it can determine valid traffic flow and drop FIN traffic floods using the AFM DoS Device Protection configuration Bad Header TCP Category TCP FIN only set attack type vector.

Environment

  • BIG-IP AFM licensed and provisioned

Cause

TCP FIN flood traffic is suspected to be hitting the BIG-IP system.

Recommended Actions

Configure the Detection and Rate/Leak Limit thresholds for the FIN Only Set Attack type. To do so, perform the following procedure:

Note: For BIG-IP AFM DoS protection Device Configuration, the Threshold and Rate/Leak limit values are applied per Traffic Management Microkernel (TMM). For more information, refer to K15023: The BIG-IP AFM system enforces configured thresholds and limits for each TMM. 

Note: The following configuration is based on a BIG-IP AFM 13.1.0 DoS protection Device Configuration. Refer to the BIG-IP AFM manual for your specific version. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  1. Log in to the Configuration utility (GUI).
  2. Navigate to:
    • Security > DoS Protection > Device Configuration > Network Security (13.x)
    • Security > DoS Protection > Device Configuration (11.x - 12.x)
  3. For Category Bad Header TCP, click +, and then click FIN Only Set.
  4. Under Configuration, modify the value for the following options:
    • Detection Threshold PPS
    • Detection Threshold Percent
    • Mitigation Threshold PPS

Note: For Detection Threshold PPS value, as a sample possible value, allow an acceptable value to accommodate the expected increase of this type of traffic. For example, if the Stats rate value has an average value of 5,000 packets per second, and there are four TMMs in the BIG-IP AFM system being configured, and the Detection Threshold PPS value is set to 8,000, this would allow the BIG-IP AFM system to potentially handle a total of 31,996 FIN Only set flood packets before the BIG-IP AFM system detects the IP Unknown Protocol attack vector. However, if one of the TMMs exceeds the Detection Threshold PPS value of 8,000, for example 8,100, the BIG-IP AFM system detects the FIN Only set flood and generates a log message in the /var/log/ltm file.

Additional Information

Denial-of-service (DoS) attacks can also be mitigated in hardware. Many attack vectors such as bad headers, floods, and fragmented packets are processed in hardware and mitigated using the embedded Packet Velocity Acceleration (ePVA) chip. Mitigating these attacks using hardware rather than software improves performance of the BIG-IP device. The TCP FIN Only Set attack type can be hardware accelerated and attacks are handled in hardware improving the BIG-IP system performance for BIG-IP platforms that support it, namely BIG-IP platforms with the ePVA chip.

The following is an example generated FIN Only set attack type log in the /var/log/ltm file:

Mar 25 18:09:34 f5-lan-gw-apm-pem err tmm[12689]: 01010252:3: A Enforced DOS attack start was detected for vector FIN only set, Attack ID 1916407465.
Mar 25 18:10:33 f5-lan-gw-apm-pem notice tmm[12689]: 01010253:5: A Enforced DOS attack has stopped for vector FIN only set, Attack ID 1916407465.

The DoS attack messages will be triggered after the detection threshold is exceeded on either receiving the TCP FIN Flood traffic on a BIG-IP self IP or a virtual server.
