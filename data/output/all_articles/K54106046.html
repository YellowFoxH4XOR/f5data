Known Issue

If you modify the order of or add virtual servers to an inbound wide IP (WIP), you enable all disabled virtual servers for that WIP.

This issue occurs when any of the following conditions are met:

  • You are using the Configuration utility to modify the order of the virtual servers for a WIP.
  • You are using the Configuration utility to add a virtual server to a WIP.

The BIG-IP system uses the order number of the pool member (virtual server) with load balancing methods that involve prioritizing the members, such as the Ratio load balancing method.

Impact

The system may send traffic to disabled systems.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You unexpectedly find that disabled virtual servers are enabled.

Workaround

To work around this issue, you can manage virtual servers for a WIP using the Traffic Management Shell (tmsh). To do so, perform the following actions:

Impact of workaround: Performing the following actions should not have a negative impact on your system.

  • To modify the order of virtual servers within a WIP, use the following syntax:

    modify gtm pool <pool name> members modify { <Virtual Name> { order <value> }}

    For example:

    modify gtm pool pool1 members modify { /Common/big-ip-host:/Common/v1 { order 1 }}

  • To add a virtual server to a WIP, use the following syntax:

    create gtm pool <pool name> members add { <server_name:vs_name> }

    For example:

    create gtm pool pool3 members add { big-ip-host:/Common/v1 }
