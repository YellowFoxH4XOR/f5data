Known Issue

Attack signatures that have been disabled for a specific XML policy may be incorrectly applied to traffic.

This issue occurs when all of the following conditions are met:

  • An attack signature that is set to Enabled for a given security policy is overridden and set to Disabled within an XML profile.
  • You created or modified a second attack signature with the Auto Apply New Signatures Configuration After Create option enabled.
  • You clicked Apply Policy.

When the second attack signature is automatically applied, the Disabled override value for the first signature is ignored, and the signature is applied to traffic.

Impact

Attack signatures may be incorrectly applied to traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • An enabled attack signature that is disabled in an XML policy override will generate violations for traffic processed by the XML policy.

Workaround

To prevent this issue, you can apply the changes to the XML policy before making further changes. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the Configuration utility.
  2. Navigate to the attack signatures list for the desired XML profile:

    BIG-IP ASM 11.x:

    Application Security > Content Policies > XML > <profile name> > Attack Signatures tab

    BIG-IP ASM 10.x:

    Application Security > XML Profiles > <profile name> > Defense Configuration menu
  3. Locate the desired item in the list of attack signatures, and change the State in the drop-down menu to Disabled.
  4. Click Update.
  5. Click Apply Policy.

Any subsequent changes to attack signatures that have the Auto Apply New Signatures Configuration After Create option enabled will no longer cause the attack signatures that are overridden by the XML profile settings to be incorrectly enabled.

To recover from this issue, you need to re-disable the attack signature override in the XML profile. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the Configuration utility.
  2. Navigate to the attack signatures list for the affected XML profile:

    BIG-IP ASM 11.x:

    Application Security > Content Policies > XML > <profile name> > Attack Signatures tab

    BIG-IP ASM 10.x:

    Application Security > XML Profiles > <profile name> > Defense Configuration menu
  3. Locate the affected item in the list of attack signatures, and change the State in the drop-down menu to Enabled.
  4. Click Update.
  5. Locate the affected item in the list of attack signatures again, and change the State in the drop-down menu to Disabled.
  6. Click Update.
  7. Click Apply Policy.
