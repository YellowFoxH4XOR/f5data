Known Issue

The vCMP guest worker-lite system may fail to reattach to the host, causing SSL or compression failures.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION system with a PB200, B2100, B2150, or B4300 blade.
  • You have vCMP guests running 11.4.1 HF6 or 11.5.1 HF6.
  • You have a vCMP guest configuration with either an SSL profile or an HTTP Compression profile enabled.

Impact

The vCMP guest will be unable to process either SSL or compressed traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • A vCMP guest fails to process either SSL or compressed traffic.

Workaround

To work around this issue, you can either restart the Traffic Management Microkernel (TMM) on the vCMP guest or redeploy the vCMP guest on the vCMP host. To do so, perform one of the following procedures:

Impact of workaround: Performing the following procedures will temporarily stop all traffic processing on the vCMP guest system.

Restarting TMM on the affected vCMP guest

  1. Log in to the command line of the vCMP guest.
  2. Restart TMM by typing the following command:

    bigstart restart tmm

Redeploying the affected vCMP guest on the vCMP host

  1. Log in to the command line of the vCMP host and enter the Traffic Management shell (tmsh) by typing the following command:

    tmsh

  2. To list all available guests, type the following command:

    show vcmp guest

  3. To disable the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state configured

    For example, to disable a vCMP guest named vcmp_one, you would type the following command:

    modify vcmp guest vcmp_one state configured

  4. To ensure that the affected vCMP guest is disabled, use the following command syntax:

    Note: Once you disable the vCMP guest, it will not appear.

    show vcmp guest [Name]

    For example, to ensure that the vCMP guest named vcmp_one is disabled, you would type the following command:

    show vcmp guest vcmp_one

  5. To deploy the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state deployed

    For example, to deploy a vCMP guest named vcmp_one, you would type the following command:

    modify vcmp guest vcmp_one state deployed

  6. To verify that the vCMP guest is deployed, use the following command syntax:

    Note: The vCMP guest Status will change to running and the Requested State will change to deployed.

    show vcmp guest [Name]

    For example, to verify that the vCMP guest named vcmp_one is deployed, you would type the following command:

    show vcmp guest vcmp_one
