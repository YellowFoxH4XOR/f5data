Description

  • Configuring and verifying Security Features to protect sensitive information like Password being logged in the ASM request log
  • You follow procedures in masking data in the BIG-IP ASM request log: K52154401: Masking data in the BIG-IP ASM request log
  • Policy continues to log sensitive data in the ASM request log

Environment

  • ASM

Cause

  • The absence of Content-Type *form* from allowed HTTPs URLs wildcard entries at Security  ››  Application Security : URLs : Allowed URLs : Allowed HTTP URLs

Recommended Actions

Verify security policy is configured with required Header name and Value
  1. Log in to the Configuration Utility
  2. Navigate to Security  >  Application Security > URLs > Allowed URLs > Allowed HTTP URLs  > Allowed HTTP URL Properties
  3. Select HTTPS wildcard
  4. Click advanced to expand available options
  5. Select  Header-Based Content Profiles
    • Request Header Name   ==   <content-type> or < specific content-type from specific request>
    • Request Header Value   ==   *form*
    • Request Body Handling   ==   Form Data

Additional Information

  • By default, at a time of policy creation, all security policies would have been created with wildcard HTTP/HTTPs allowed URLs. 
  • HTTPs wildcard would have consisted of three types of content types including form data. 
  • The wildcard content type is required to mask sensitive data and must be present
