Description
The very first BIG-IP ASM Attack Signature Update (ASU) file release for a Major, Minor or Maintenance version will contain cumulative changes from the ASU version used in software development for that software version up through the changes contained in the ASU file. The ASU file release notes will only describe the changes in the ASU so a manual process is needed to determine all the cumulative changes (additions, modifications and deletions of Attack Signatures) which actually occur. This information is needed to evaluate the changes to attack surface coverage from the changes and the effects it can have.

Environment

  • BIG-IP ASM without any ASU ever applied
  • Initial Attack Signature Update (ASU) file for the BIG-IP's Major, Minor or Maintenance version
  • Software version 14.0 or earlier

Cause

  • During software development the latest ASU at the time is used as the default Attack Signature database
  • Newer ASUs continue being released during development
  • ASU readme files from current version's ASU and previous version(s) ASU need to be compiled for complete picture
Note: Every ASU applied after the initial ASU will contain the same undocumented cumulative changes from the previous branch however it will document all changes within the new version's branch.

Recommended Actions
This describes how to gather a full list of all changes the initial ASU for a version will contain.

  1. Determine the ASU file name for the initial ASU for the new version
    1. Note the timestamp portion which is the last 15 characters in format 12345678_123456
  2. Determine the Creation Date for the version's default Attack Signature database
    1. Log into the Configuration Utility
    2. Go to Security > Security Updates > Application Security
    3. Note the full date and time of the Create Date field in format YYYY-MM-DD HH:MM:SS
  3. Determine the previous code branch used for default Attack Signature database
    1. Look at the Major.Minor.Maintenance of the current version and go to the most previous version. For example, 14.1.3 would be based off 14.1.2.
  4. Locate the cumulative ASU readme file for the previous code branch
    1. Go to https://downloads.f5.com and log in
    2. Go to the BIG-IP downloads and locate the link for the previous code branch
    3. Select the appropriate drop down for the Major.Minor.Maintenance code version
    4. Click the link for ASM-LastestSignatureFile
    5. Download the Readme.txt file
  5. Locate the ASU which was selected for the new version's default Attack Signature database
    1. Convert the Create Date from Step 2.3 to ASU file-formatted timestamp
      1. YYYY-MM-DD HH:MM:SS becomes YYYYMMDD_HHMMSS
      2. For example Create Date 2019-10-16 22:02:00 becomes 20191016_220200
      3. Search the Readme.txt for the string of the timestamp from step 5.2 above
  6. Locate the ASU containing the same changes as the new version's initial ASU????
    1. ?Search the Readme.txt for the string of the timestamp from step 1.1
The cumulative changes included in the initial ASU for the new version will be all changes between the ASU used as the new version's default Attack Signature database (found in Step 5.3) and the changes for the new ASU (found in Step 6.1). The changes the new ASU itself adds are documented in it's readme.

Additional Information
Version 14.1 adds the ASU Preview tool in the Live Update functionality which compiles all differences between the current Attack Signature database and the selected ASU, providing an exact snapshot of every addition, modification and deletion.

Software development for a new release happens for a period of time before the release is made public. At a point in the development, the latest ASU from the most recent code branch is used as the default Attack Signature database for the new release. This database is not modified from this point through release. It is likely that the most recent code branch will continue to receive new ASU updates while the new release is in development and consequently will have additional changes that are not present in the new version upon it's release.

The first ASU for the new release will contain some number of Attack Signature additions, modifications and deletions, documented in it's readme information. As stated in K8217, ASU files contain cumulative updates. As mentioned above, this initial ASU will also contain the cumulative changes from the previous code branch spanning from the version used as the default database up through the current ASU's changes. As this isn't documented in the new version's ASU the information has to be gathered manually to get a complete picture of all changes that will occur when the first ASU for the new version is installed.
