K7350: HTTP Keep-Alive sessions may be terminated before expected when using HTTP compression

Topic

When the BIG-IP system passes an HTTP response from the server to the client, the BIG-IP system will attempt to preserve the server's method of indicating the end of the response by using an HTTP Content-Length header, or by using chunked encoding for responses.

When the server uses an HTTP Content-Length header and the BIG-IP system is configured to use HTTP compression, the HTTP Keep-Alive session is terminated if the size of the response exceeds the compression buffer size.

The HTTP Keep-Alive session is terminated because the BIG-IP system needs to buffer all of the compressed data. As a result, a new content length can be determined after compression in order to rewrite the HTTP Content-Length header before forwarding the response to the client. If the amount of buffered data exceeds the compression buffer size, the HTTP Content-Length header is deleted and the BIG-IP system inserts an HTTP Connection: close header into the stream and terminates the HTTP Keep-Alive session.

Server responses that use chunked encoding are not affected by the compression buffer size.

To prevent early termination of the HTTP Keep-Alive session, F5 recommends that you configure the BIG-IP system to use the Rechunk setting for the Response Chunking setting in the HTTP profile used by the virtual server. When the Rechunk setting is selected, the BIG-IP system will use chunked encoding when passing all HTTP responses to the client, regardless of the server's method.

In addition, you can avoid terminating the HTTP Keep-Alive session by identifying the largest possible response and setting the compression buffer size to this value. However, setting a high compression buffer size will introduce a delay for larger responses while data is buffered before it is forwarded to the client. The larger compression buffer size will also consume more BIG-IP memory. The compression buffer size value is configured in the HTTP Compression profile (11.x) or the HTTP profile (9.x - 10.x) used by the virtual server.

Note: When modifying a profile, F5 recommends that you create a custom profile instead of modifying the default profile. For information, refer to K14488: Working with profiles.
