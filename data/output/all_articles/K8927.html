Known Issue

This is the result of a known issue. The BIG-IP system fails to send a TCP window update when interacting with certain TCP/IP stacks. For example, when you configure a virtual server with a TCP profile, and the receive buffer is filled to the proxy buffer high water mark minus one maximum segment size (MSS), the BIG-IP system fails to send a TCP window update. This behavior can cause the session to temporarily stall.

Currently, this issue has only been observed when a virtual server configured with a TCP profile interacts directly with a Blue Coat system's CacheOS TCP stack. This slow behavior is caused by Blue Coat system's method of implementing the SWS (Silly Window Syndrome) avoidance algorithm. The Blue Coat CacheOS device may pause, sending data one MSS before the TCP receive window on the BIG-IP is full, even though data still needs to be sent BIG-IP system. Since the BIG-IP system fails to send a TCP window update, the Blue Coat system waits until a timeout of several seconds before sending out the rest of the data.

Note: Only the Blue Coat CacheOS and SGOS systems are affected; no other network devices are known to be impacted by this issue..

F5 Product Development tracked this issue as CR91846 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, and WAN Optimization release notes.

This issue was fixed in Hotfix-BIGIP-9.4.8-396.1-HF3 issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by configuring the virtual server to use a FastL4 profile.
