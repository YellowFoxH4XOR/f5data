Description

You want to poll the BIG-IP to get the current connection count for a VS or pool member to monitor it against configured connection limits. 
When setting connection limits on a VS or pool member, and the maximum connection limit is reached, new connection requests are rejected with a TCP RST, and a message similar to the following is logged.

For example:
Warning, pool member IP X.X.X.X port 8200 for pool /Common/YYY-pool has reached its connection limit.

Environment

  • BIG-IP
  • SNMP Server v1, v2c, v3

Cause

None

Recommended Actions

If you want to be alerted when a virtual server or pool member is nearing its defined connection limit, you can use the following SNMP OIDs to monitor the configured connection limit and the current connection count, and configure your SNMP monitoring software to perform the required logical operation on the polled data.

For Specific VS:

  • Connection limit:
    • snmpget -On -c public localhost 'F5-BIGIP-LOCAL-MIB::ltmVirtualServConnLimit."/Common/<vs_name>"'
  • Current connection count:
    • snmpget -On -c public localhost 'F5-BIGIP-LOCAL-MIB::ltmVirtualServStatClientCurConns."/Common/<vs_name>"'

For Specific Pool-Member:

  • Connection limit:
    • snmpget -On -c public localhost 'F5-BIGIP-LOCAL-MIB::ltmPoolMemberConnLimit."/Common/<pool_name>"."/Common/<pool_member_name>".<port>'
  • Current connection count:
    • snmpget -On -c public localhost 'F5-BIGIP-LOCAL-MIB::ltmPoolMemberStatServerCurConns."/Common/<pool_name>"."/Common/<pool_member_name>".<port>'

Additional Information

Modifications to the /config/user_alert.conf file may not be preserved after system upgrades or hotfix installations. F5 recommends creating an updated UCS archive immediately before performing an upgrade if you need to retain customizations. If SNMP or other custom configurations are added, ensure these files are also backed up manually.
