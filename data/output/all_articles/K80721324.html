Description

When using the SSL::sessionsecret iRules to decrypt a packet capture a source IP is required. Often being able to pick just one is not possible. To deal with that using a Data Group List will allow the use of multiple IPs/networks.

Environment

  • Need to identify/troubleshoot traffic issues
  • Virtual Servers, iRules, encrypted traffic
  • tcpdump, Wireshark

Cause

In K12783074: Decrypting SSL traffic using the SSL::sessionsecret iRules command (12.x and later) the iRule, as structured, will only allow for the use of 1 client (source) IP address.

Recommended Actions

To allow for the use of more than one client IP address or even a network you can use a Data Group List.

  1. Create a Data Group List.
    1. Go to Local Traffic  ››  iRules : Data Group List and click 'Create'.
    2. Title the Data Group and in the dropdown "Type" choose 'Address'.
      1. Specifies an IP address or network associated with the object. For this setting to work, you must specify a value other than 0.0.0.0/0 or ::/0 (that is, any/0, any6/0). In order to maximize utility of this setting, specify the most specific addresses/prefixes covering all client addresses and no others.

        The format for an IPv4 address is a.b.c.d, for example, 172.16.254.1 (No port as it will an ephemeral number). The format for an IPv6 address is a:b:c:d:e:f:g:h, for example, 2001:db8:85a3:8d3:1319:8a2e:370:7348.
    3. Click 'Finished'.
    4. Use the steps in K12783074 to produce a decrypted capture with the SSL session cache disabled so as to not have SSL session be reused. If it is reused then the SSL session ID will not be recorded to create the Master Secret Log file in the step after that.
    5. However, instead of using the iRule listed in step 7 use the one below. Be sure to change out section labeled <data group name> with the name of the Data Group that has the IP list.
when CLIENTSSL_HANDSHAKE {
if {[class match [getfield [IP::client_addr] "%" 1] equals <data group name>] } {
log local0. "CLIENT_Side_IP:TCP source port: [IP::client_addr]:[TCP::remote_port]"
log local0. "CLIENT_RANDOM [SSL::clientrandom] [SSL::sessionsecret]"
log local0. "RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
}
}
when SERVERSSL_HANDSHAKE {
if {[class match [getfield [IP::client_addr] "%" 1] equals <data group name>] } {
log local0. "SERVER_Side_IP:TCP source port:[IP::local_addr]: [TCP::local_port]"
log local0. "CLIENT_RANDOM [SSL::clientrandom] [SSL::sessionsecret]"
log local0. "RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
 }
}

IMPORTANT: Keep the list as small as possible. As each session will have the SSL session IDs for each connection show up in /var/log/ltm of the BIG-IP. From those entries a command is run to create the needed Master Secret Log file needed to decrypt the capture. Also, a good rule of thumb is to only associate the iRule with the virtual server for only as long as needed to capture the data needed to decrypt it.

Additional Information

An external data group list could also be used for the Data Group List. If one is available the steps to use it can be found here... K73862425: Creating external data groups
