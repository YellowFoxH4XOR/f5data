Description

  • You have a limited budget
  • You want to reduce the number of Load Balancer to optimize the FQDN
  • Max domains/certs per LB

Environment

  • F5® Distributed Cloud Console

  • F5 Distributed Cloud Load Balancer
  • FQDNs

Answer

  • It is best practice to map one Application/FQDN per Load Balancer for ease of management, however XC is flexible and will allow you to manage multiple FQDNs per LB (i.e. and application has multiple FQDNs, etc.)
  • You can put 32 FQDN per LB.
  • The wildcard entry is designed to represent multiple domains, providing a flexible solution for domain management. Each wildcard counts as a single domain on the load balancer, with a maximum allowance of 32 domains per load balancer.
  • When using wildcard certificates, the system supports up to 256 domains based on Host header route matching. However, the load balancer configuration is limited to 32 wildcard domains (e.g., domain1.com, *.domain2.com, ... to .domain32.com)
  • Let’s Encrypt (LE) imposes a limit on the number of SANs per certificate, which may affect AutoCert management. Each multi-certificate configuration object can support up to 32 certificates, aligning with the wildcard domain limit.

For example:

      • *.domain.com = 1 domain on the LB

      • *.sub.domain.com = 1 domain on the LB

    • In both cases, the wildcard (*) can match on as many values in that place of the FQDN as needed.  Its simply there for match logic.
