Known Issue

This is the result of a known issue. The bigpipe command does not return persistence records when you specify an SSL key. For example, the bigpipe persist show all command returns all persistence records, similar to the following:

[root@B8800-R11-S12:Active] config # bigpipe persist show all
PERSISTENT CONNECTIONS
| Mode ssl Value 0b01b459f6261c52c884fbf2135b8863f6c43ce70a404143d9f06fc8c005b180
| virtual 10.1.0.10:https node 10.1.0.200:http age 12sec
| Mode ssl Value 0b01b459f6261c52c884fbf2135b8863f6c43ce70a404143d9f06fc8c005b180
| virtual 10.1.0.10:https node 10.1.0.200:http age 6sec
| Mode ssl Value 0b01b459f6261c52c884fbf2135b8863f6c43ce70a404143d9f06fc8c005b180
| virtual 10.1.0.10:https node 10.1.0.200:http age 12sec
| Mode ssl Value 0b01b459f6261c51c884fbf2135b8863f6c43ce30a404141d9f06fc8c005b01e
| virtual 10.1.0.10:https node 10.1.0.200:https age 136sec
[root@B8800-R11-S12:Active] config #

However, although the output above displays multiple records for the key 0b01b459f6261c52c884fbf2135b8863f6c43ce70a404143d9f06fc8c005b180, the bigpipe command returns no results when you specify that key. For example:

[root@B8800-R11-S12:Active] config # bigpipe persist mode ssl key 0b01b459f6261c52c884fbf2135b8863f6c43ce70a404143d9f06fc8c005b180 show all
No Persistence Table Entries were found.
[root@B8800-R11-S12:Active] config #

F5 Product Development is tracking this issue as ID 224165 (formerly CR134485).
