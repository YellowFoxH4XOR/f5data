Known Issue

This is the result of a known issue. The alertd process does not restart after a configsync is performed. As a result, changes to SNMP traps are not loaded and used on the standby unit.

Changes that are made to configured SNMP traps on an active unit, and then synchronized to the standby unit prevent the alertd process from restarting and using the configuration changes.

For example, this behavior can occur when the SNMP trap sink address is changed on the active unit and the configuration is synchronized to the standby unit. Since the alertd process does not restart on the standby unit, it will continue to use the previous SNMP trap sink address even though the Configuration displays the updated SNMP trap sink address.

F5 Product Development tracked this issue as CR95049 and it was fixed in BIG-IP 9.4.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, or Link Controller release notes.

Workaround

To work around this issue, you must manually restart the alertd process. To do so, log in to the command line and type the following command:

bigstart restart alertd
