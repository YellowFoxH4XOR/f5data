K000156502: Postgress monitor down after initial configuration

Type
Support Solution
Published
2025-09-17
Updated
2025-09-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000156502

Description

After configuring postgress monitor on BIG-IP, you notice that it is down all the time. After enabling monitor logging, you notice logs similar to below one:

Asking daemon to ping remote database.
Expected result not received: Database down, see /var/log/DBDaemon-0.log for details.

In file referenced by above logs, you can observe logs similar to below ones:

2025-09-12 15:28:24,123+0700 [id387_DBPinger-15358783] - Attempting DB connection
2025-09-12 15:28:24,148+0700 [id387_DBPinger-15358783] - DB DriverManager.getConnection failed
2025-09-12 15:28:24,148+0700 [id387_DBPinger-15358783] - SQL Exception:
org.postgresql.util.PSQLException: FATAL: no pg_hba.conf entry for host "x.x.x.x", user "username", database "postgres", SSL encryption

Environment

  • BIG-IP

  • Postgress monitor

Cause

Database access for BIG-IP is not configured correctly.

Answer/Recommended Actions

Make sure that access for BIG-IP is allowed correctly in pg_hba.conf file on database that you are monitoring.

Additional Information

None
