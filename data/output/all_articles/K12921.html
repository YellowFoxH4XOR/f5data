Topic

You can configure an External Application Verification (EAV) FTP health monitor for monitoring pool member listening on standard ftp port 21, regardless of whether the node supports active or passive FTP. However, if you configure an EAV FTP health monitor for a pool member that listens on an FTP port other than port 21, and supports active FTP only, the BIG-IP system marks the pool member down and logs a message to the /var/log/ltm file that appears similar to the following example:

01070638:5: Pool member <IP address>:<Port> monitor status down

In this message, note the following:

  • <IP address> refers to the IP address of the affected node
  • <Port> refers to the FTP port that the affected node is listening on

In the following example, you configure an EAV FTP health monitor ftp10021-activemon and associate it to pool ftp10021-pool, which has node 10.10.10.213 listening on FTP port 10021, and node 10.10.10.213 supports only active FTP:

monitor ftp10021-activemon {
   defaults from ftp
   interval 5
   timeout 16
   get "/ftpmon"
   mode "port"
}
pool ftp10021-pool {
   monitor all ftp10021-activemon
   members 10.10.10.213:10021
}

The BIG-IP system marks the pool member 10.10.10.213:10021 down and logs the following message to the /var/log/ltm file:

01070638:5: Pool member 10.10.10.213:10021 monitor status down

This behavior is by design. F5 recommends that you configure the node to support passive FTP, or if the node supports only active FTP, use standard FTP port 21.

You can work around this limitation by configuring the BIG-IP system to support FTP services listening on non-standard ports in addition to the standard port 21. To do so, perform the following procedure:

Important: The following workaround no longer works after you upgrade your system.

  1. Log in to the command line.
  2. If it does not already exist, create the /config/tmm_init.tcl file, using a text editor of your choice, for example vi.
  3. Append the following object stanza proxy BIGFTP to the /config/tmm_init.tcl file, replacing <FTP port> with the FTP port of your choice:

    BIG-IP version 10.x

    proxy BIGFTP {
        listen 0.0.0.0%${rtdom_any} <FTP port> netmask 0.0.0.0 {
            proto $ipproto(tcp)
            transparent
            no_translate
            no_arp
            tap enable all
        }
        listen ::%${rtdom_any} <FTP port> netmask :: {
            proto $ipproto(tcp)
            transparent
            no_translate
            no_arp
            tap enable all
        }
    }

    For example, if you require the FTP port to be 10021, then the object stanza proxy BIGFTP should look similar to the following:

    proxy BIGFTP {

        listen 0.0.0.0%${rtdom_any} 10021 netmask 0.0.0.0 {
            proto $ipproto(tcp)
            transparent
            no_translate
            no_arp
            tap enable all
        }
        listen ::%${rtdom_any} 10021 netmask :: {
            proto $ipproto(tcp)
            transparent
            no_translate
            no_arp
            tap enable all
        }
    } 

    BIG-IP 9.x

    proxy BIGFTP {
        listen 0.0.0.0 <FTP port> netmask 0.0.0.0 {
            proto $ipproto(tcp)
            transparent
            no_translate
            no_arp
            l2forward
            vlan disable all
            tap enable all
        }
        if {$ipv6_enabled == "TRUE"} {
            listen :: <FTP port> netmask :: {
                proto $ipproto(tcp)
                transparent
                no_translate
                no_arp
                l2forward
                vlan disable all
                tap enable all
            }
        }
    }

    For example, if you require the FTP port to be 10021, then the object stanza proxy BIGFTP should look similar to the following:

    proxy BIGFTP {
        listen 0.0.0.0 10021 netmask 0.0.0.0 {
            proto $ipproto(tcp)
            transparent
            no_translate
            no_arp
            l2forward
            vlan disable all
            tap enable all
        }
        if {$ipv6_enabled == "TRUE"} {
            listen :: 10021 netmask :: {
                proto $ipproto(tcp)
                transparent
                no_translate
                no_arp
                l2forward
                vlan disable all
                tap enable all
            }
        }
    }

  4. Save the changes in the text editor and exit to the command line.
  5. Reboot the BIG-IP system to effect the change.

    Important: If the BIG-IP system is the active member of a redundant pair, rebooting causes a failover. If the BIG-IP system is a standalone unit, rebooting interrupts traffic processing.
