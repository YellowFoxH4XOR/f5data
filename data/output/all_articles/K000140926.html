Known Issue

The BIG-IP Next Central Manager may fail to deploy a BIG-IP Next tenant on a VELOS provider.

This issue occurs when one of the following conditions is met:

  • You selected two or more Slot IDs during the BIG-IP Next instance creation process.
  • In a previous instance creation failed attempt, you selected two or more Slot IDs; you then used that same BIG-IP Next tenant image in a subsequent instance creation attempt.

Impact

The BIG-IP Next Central Manager is unable to deploy a BIG-IP Next tenant on a VELOS provider using the BIG-IP Next tenant image that was used in the failed instance creation attempt. The affected BIG-IP Next tenant image is corrupted and cannot be utilized for future deployments.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP Next Central manager fails to deploy multi Slot IDs BIG-IP Next tenant on a VELOS provider and reports an error similar to the following example in its Alerts & Notification page:

    Summary: Failed to create instance 192.168.8.64

    Description: unable to instantiate VELOS BIG-IP Next instance. Check the log for more details

  • The BIG-IP Next Central manager fails to deploy single Slot IDs BIG-IP Next tenant on a VELOS provider and reports an error similar to the following example in its Alerts & Notification page:

    Summary: Failed to create instance 192.168.8.64

    Description: Tenant Deploy failed, got error: tenant deployment still in In Progress with Timeout Period, please increase timeout

Workaround

To work around this issue, you have to delete the affected BIG-IP Next tenant image from the VELOS provider and then re-upload/re-import a new copy of the BIG-IP Next tenant image to the VELOS provider. To do so, perform the following procedure:

Impact of workaround: If you have deployed a BIG-IP Next tenant with the tenant image prior to triggering this issue, you may have to backup the configuration of that BIG-IP Next tenant and delete the tenant before proceeding with this procedure. Otherwise the VELOS system reports that the software image is in use and does not allow the deletion of the affected image. For information on creating a configuration backup for the BIG-IP Next tenant, refer to the Create an instant Backup for BIG-IP Next Instance section of the How to: Back up managed BIG-IP Next instances to BIG-IP Next Central Manager’s local drive instantly or on a schedule. For information on deleting the BIG-IP Next tenant, refer to How to: Remove a managed BIG-IP Next instance from BIG-IP Next Central Manager.

  1. Login to the webUI of the VELOS provider as the admin user. The VELOS provider is typically a VELOS partition on the VELOS system.
  2. Go to TENANT MANAGEMENT > Tenant Images.
  3. Select the affected BIG-IP Next tenant image, the related .tar.bundle file as well as the related .yaml file.

    For example,

    • BIG-IP-Next-20.2.1-2.430.2+0.0.48
    • BIG-IP-Next-20.2.1-2.430.2+0.0.48.tar.bundle
    • BIG-IP-Next-20.2.1-2.430.2+0.0.48.yaml
  4. Select Delete to delete the affected files from the VELOS provider.
  5. Select OK to confirm the deletion.
  6. To re-upload/re-import a new copy of the BIG-IP Next tenant image to the VELOS provider, perform either of the following:
    • The procedure in the Upload a tenant image onto the chassis partition section of the How to: Create a BIG-IP Next instance on VELOS system from Central Manager.
    • K000139146: Upload a file to the VELOS or rSeries system using REST API
  7. When you have re-upload/re-import a new copy of the BIG-IP Next tenant image successfully to the VELOS provider, you can proceed to create a BIG-IP Next tenant instance on the VELOS provider with the newly uploaded/imported image; ensure you select only one Slot ID during the creation process in BIG-IP Next Central Manager.
