Topic

This article discusses the TCP profile settings. You can find the TCP profile in the Configuration utility by navigating to Local Traffic > Profiles > Protocol > TCP.

Description

The TCP profile allows an administrator to specify how a BIG-IP virtual server processes TCP traffic. To manage traffic, you can use the TCP profile alone, or in conjunction with other profiles. For example, you can use the HTTP profile to process Layer 7 (L7) traffic or use the SSL profile to process SSL traffic.

Note: The BIG-IP system does not allow you to modify the default TCP base profile. For more information, refer to K53830409: The default TCP base profile is read-only starting with BIG-IP 13.x. You can create a modified TCP profile using the default TCP base profile as the parent profile and associate the modified profile, which contains specific settings, with either individual virtual servers or groups of virtual servers.

Timer Management

SettingDefault valueDescription
Close WaitSpecify: 5 seconds
Range: 0 - 4294967295		Specifies the length of time that a TCP connection remains in the LAST-ACK state before quitting. Available options:
  • Specify: Specifies the number of seconds of that a TCP connection is in the LAST-ACK state before closing. Note that the value of zero (0) is equivalent to Immediate while 4294967295 is equivalent to Indefinite.
  • Immediate: Specifies that the TCP connection closes immediately after entering the LAST-ACK state.
  • Indefinite: Specifies that TCP connections in the LAST-ACK state do not close until they meet the maximum retransmissions timeout.
Fin Wait 1Specify: 5 seconds
Range: 0 - 4294967295		Specifies the length of time that a TCP connection is in the FIN-WAIT-1 or CLOSING state before quitting. Available options:
  • Specify: Specifies the number of seconds of that a TCP connection is in a FIN-WAIT-1 or CLOSING state before quitting. Note that the value of zero (0) is equivalent to Immediate while 4294967295 is equivalent to Indefinite.
  • Immediate: Specifies that the TCP connection closes immediately after entering the FIN/WAIT-1 or CLOSING state.
  • Indefinite: Specifies that TCP connections in the FIN/WAIT-1 or CLOSING state do not quit.
Fin Wait 2Specify : 300 seconds
Range: 0 - 4294967295		Specifies the length of time that a TCP connection is in the FIN-WAIT-2 state before quitting. Available options:
  • Specify: Specifies the number of seconds of that a TCP connection is in a FIN-WAIT-2 state before quitting. Note that the value of zero (0) is equivalent to Immediate while 4294967295 is equivalent to Indefinite.
  • Immediate: Specifies that the TCP connection closes immediately after entering the FIN/WAIT-2 state.
  • Indefinite: Specifies that TCP connections in the FIN-WAIT-2 state do not quit.
Idle TimeoutSpecify : 300 seconds
Range: 1 - 4294967295		Specifies the length of time that a connection is idle (has no traffic) before the connection is eligible for deletion. Available options:
  • Specify: Specifies a number of seconds that the TCP connection can remain idle before the system deletes it. Note that the value of 4294967295 is equivalent to Indefinite.
  • Indefinite: Specifies that the system does not delete TCP connections regardless of how long they remain idle.

Note: Take caution when adjusting idle times, as each TCP connection requires resources to track and maintain the connection. Leaving TCP connections for long periods of time uses more resources that can be better used for new connections. For more information on changing a protocol profile idle timeout, refer to: K7166: Changing the idle timeout for a protocol profile

Keep Alive IntervalSpecify : 1800 seconds
Range: 0 - 4294967295		Specifies, when enabled, how frequently the system sends data over an idle TCP connection, to determine whether the connection is still valid. Available options:
  • Specify: Specifies the interval at which the system sends data over an idle connection, to determine whether the connection is still valid. Note that the value of zero (0) is equivalent to Indefinite.
  • Indefinite: Specifies that the system does not send Keep-Alive communications.
Minimum RTO1000 milliseconds
Range: 0 - 5000		Specifies the minimum length of time that the system waits for acknowledgements of data sent, before resending the data. The value must be equal to or less than 5000. The default is 1000 milliseconds, which means that the system uses the RFC-compliant value of 1 second. If the Packet Loss Ignore Rate and Packet Loss Ignore Burst settings contain values other than 0, this value drops to 203 ms. If MPTCP is enabled, the value drops to 200 ms.
Reset On TimeoutEnabledSpecifies, when selected (enabled), that the system sends a reset (RST) and deletes the TCP connection when the connection exceeds the idle timeout value. If disabled, the system deletes the TCP connection when the connection exceeds the idle timeout value but will not send an RST to the client.

Note: This setting can cause the client (if Reset on Timeout is disabled) to assume that the connection is still valid long after it has been removed from the BIG-IP LTM system.

Time WaitSpecify : 2000 milliseconds
Range: 0 - 600000, 4294967295		Specifies the length of time that a TCP connection remains in the TIME-WAIT state before entering the CLOSED state. Available options:
  • Specify: Specifies the number of milliseconds that a TCP connection can remain in the TIME-WAIT state before the system closes it. Note that the value of zero (0) is equivalent to Immediate while 4294967295 is equivalent to Indefinite.
  • Immediate: Specifies that the system closes the connection immediately after the connection enters the TIME-WAIT state.
  • Indefinite: Specifies that the system does not close TCP connections regardless of how long they remain in the TIME-WAIT state.
Time Wait RecycleEnabledSpecifies, when checked (enabled), that connections in a TIME-WAIT state are reused when the system receives a SYN packet, indicating a request for a new connection. When this setting is not enabled, connections in a TIME-WAIT state remain unused for a specified length of time (typically twice the maximum segment lifetime), to ensure that the original transmission is complete. Using this setting enabled, the system can recycle a wait-state connection immediately upon receipt of a new connection request instead of having to wait until the connection times out of the wait state.

Note: If disabled, the system establishes a new connection at the expiration of the TIME-WAIT period and will not reuse the previous connection in TIME-WAIT state.

Zero Window TimeoutSpecify : 20000 milliseconds
Range: 1 - 4294967295		Specifies the timeout in milliseconds for terminating a connection with an effective zero length TCP transmit window. The timeout starts when the peer advertises a zero length TCP window or when enough data has been sent to fill the previously advertised window. The timer is canceled when a non-zero length window is received. Available options:
  • Specify: Specifies a number of milliseconds that the TCP connection can receive zero-length window probes before the system closes the connection. Note that the value of 4294967295 is equivalent to Indefinite.

    Note: The timeout starts when the peer advertises a zero length TCP window or when enough data has been sent to fill the previously advertised window. The timer is cancelled when a non-zero length window is received.

    Note: The BIG-IP system honors timeout values in multiples of 5000 (for example: 5000 ms, 10000 ms, and 20000 ms). This behavior accounts for the minimal time required for CPU timers and Round Trip Time (RTT) of packets to ensure that when a zero window size update is received, the system allows the counter to start and TCP window probes are sent to query whether there is a window size change on the receiver.

    If you enter a value that is not a multiple of 5000, the system rounds the value up to the next multiple of 5000. For example, if a 0 is entered, the system rounds up to 5000 ms. If 7000 is entered, the system rounds up to 10000 ms.

  • Indefinite: Specifies that the system does not delete TCP connections based on zero-length window.

Max Segment Size (MSS)1460 bytes
Range: 0 - 1460		Specifies the largest amount of data that the system can receive in a single TCP segment, not including the TCP and IP headers. If the value is 0 (zero), the system calculates the value from the maximum transmission unit (MTU).
Nagle's AlgorithmDisabledDetailed in RFC 896, Nagle's algorithm is a TCP optimization that makes the stack wait until all data is acknowledged on a connection before sending more data. This process, called nagling, increases the efficiency of a network application system by decreasing the number of packets that must be sent. Available options:
  • Disabled: Specifies that the system will not apply Nagle's algorithm.
  • Enabled: Specifies that the system applies Nagle's algorithm to reduce the number of short segments on the network. When the system receives packets that are less than the maximum segment size (MSS), the packets are coalesced until the peer sends the ACK packet for the previous segment. This helps to reduce congestion by creating fewer packets on the network.
  • Auto: Specifies that the system will determine whether to use Nagle's algorithm based on network conditions.

Note: In some highly interactive client/server environments, the use of Nagle's algorithm might cause undesired behavior, and you should disable it.

PUSH FlagDefaultSpecifies how the BIG-IP system receives ACKs. Frequent receipt of ACKs can affect BIG-IP system performance. To mitigate impacted performance, you can configure PUSH Flag to control the number of ACKs that the system receives because of setting the PSH bit in a TCP header. Available options:
  • Default: Specifies the system receives a TCP acknowledgement (ACK) whenever the system sends a segment with the PUSH (PSH) bit set in the Code bits field of the TCP header.
  • None: Specifies the system never sets the PSH flag when sending a TCP segment so that the system will not receive an ACK in response.
  • One: Specifies the system sets the PSH flag once per connection, when the FIN flag is set.
  • Auto: Specifies the system sets the PSH flag in these cases:
    • When the receiver’s Receive Window size is close to 0.
    • Once per Round Trip Time (RTT), that is, the length of time that the BIG-IP system sends a signal and receives an ACK.
    • At the end of the response from the server side. For example, a TCP FIN is received or HTTP content-length is reached.

  • Decrement: Specifies the system sets the outgoing IP Header TTL value to be one less than the incoming TTL value.
  • Set: Specifies the system sets the outgoing IP Header TTL value to a specific value (as specified by ip-ttl-v[4|6]).

Congestion Control

SettingDefault valueDescription
Appropriate Byte Counting (RFC 3465)EnabledSpecifies, when selected (enabled), that the system increases the congestion window by basing the increase amount on the number of previously unacknowledged bytes that each ACK covers.

Note: F5 recommends that you use the default setting. When this setting is disabled, in situations with lost ACK packets, the congestion window remains small for a longer period of time.

Congestion Metrics CacheEnabledSpecifies, when selected (enabled), that the system uses a cache for storing congestion metrics.
Congestion Metrics Cache Timeout0 seconds
Range: 0 - 1000		Specifies the number of seconds for which entries in the congestion metrics cache are valid. The default value is 0, which defers to the route.metrics.timeout system database variable.
Congestion ControlHigh SpeedSpecifies the congestion control mechanism that the BIG-IP system uses.
Available options:
  • None: Specifies that the system does not use a network-congestion-control mechanism, even when congestion occurs.
  • BBR: Specifies that the system uses a TCP algorithm that is optimized to achieve higher bandwidths and lower latencies.
    Note: BBR Congestion Control is available in BIG-IP 14.1.0 and later.
  • CAIA Delay-Gradient (CDG): Specifies that the system uses a delay-based TCP that senses the onset of congestion by variations in Round Trip Time (RTT).
  • CAIA Hamilton Delay (CHD): Specifies that the system uses a TCP algorithm that aims to keep network queuing delays below a particular threshold (queue_threshold) and decides to reduce the congestion window (cwnd) probabilistically based on its estimate of the network queuing delay.
  • CUBIC: Specifies that the system uses a TCP algorithm that is optimized for high bandwidth, high delay networks.
  • High Speed: Specifies that the system uses a more aggressive, loss-based algorithm. RFC 3649: HighSpeed TCP for Large Congestion Windows.
  • Illinois: Specifies that the system uses a TCP algorithm that is especially targeted at high-speed, long-distance networks.
  • New Reno: Specifies that the system uses a modification to the Reno algorithm that responds to partial acknowledgements when SACKs are unavailable. RFC 2582: The NewReno Modification to TCP's Fast Recovery Algorithm.
  • Reno: Specifies that the system uses an implementation of the TCP Fast Recovery algorithm, which is based on the implementation in the BSD Reno release. RFC 2581: TCP Congestion Control.
  • Scalable: Specifies that the system uses a TCP algorithm modification that adds a scalable, delay-based and loss-based component into the Reno algorithm.
  • Vegas: Specifies that the system uses a TCP algorithm modification that adds a delay-based and loss-based component into the Reno algorithm.
  • Westwood+: Specifies that the system uses a TCP algorithm based on a bandwidth estimation metric.
  • Woodside: Specifies that the system uses a TCP algorithm that is especially targeted at high-speed, long-distance networks with enhanced congestion recovery.
Delay Window ControlDisabledSpecifies, when selected (enabled), that the system uses an estimate of queuing delay as a measure of congestion to control the amount of data sent (in addition to the normal loss-based control).
Explicit Congestion NotificationEnabledSpecifies, when selected (enabled), that the system uses the TCP flags CWR (Congestion Window Reduced) and ECE (ECN-Echo, used to indicate that the TCP peer is Explicit Congestion Notification capable during the three-way handshake) to notify its peer of congestion and congestion counter-measures. The default is enabled.

Note: When this option is enabled, it is used only when two hosts signal that they want to use it. It allows a host to set the ECN bit within the IP header to notify the transmitter that the link is congested.

Initial Congestion Window Size10 MSS units
Range: 0 - 64		Specifies the initial congestion window size for connections to this destination. Actual window size is this value multiplied by the maximum segment size (MSS) for the same connection. Valid values range from 0 to 64.
Packet Loss Ignore Burst0 packet count
Range: 0 - 32		Specifies the probability of performing congestion control when multiple packets are lost, even if the Packet Loss Ignore Rate was not exceeded. Valid values range from 0 to 32. The default is 0, meaning that the system performs congestion control if any packets are lost. Higher values decrease the chance of performing congestion control.
Packet Loss Ignore Rate0 packets lost per million
Range: 0 - 1000000		Specifies the threshold of packets lost per million at which the system performs congestion control. Valid values range from 0 to 1,000,000. The default is 0, meaning the system performs congestion control if any packet loss occurs. If you set the ignore rate to 10 and packet loss for a TCP connection is greater than 10 per million, congestion control occurs.
Rate PaceEnabledSpecifies, when selected (enabled), that the system paces the egress packets to avoid dropping packets, allowing for optimum goodput. This option mitigates bursty behavior in mobile networks.
Rate Pace Maximum Rate0 bytes/second
Range: 0 - 4294967295		Specifies the maximum rate in bytes per second to which the system paces TCP data transmission. If this value is 0, no maximum is enforced.
Slow StartEnabledSpecifies, when checked (enabled), that the system uses the slow start algorithm as described in RFC 5681 in order to ramp up traffic without causing excessive congestion on the link. If you disable this setting, the system initializes the congestion window to the maximum window scale and attempts to transmit as much data as possible until congestion occurs. Note that disabling this setting causes the setting for Congestion Metrics Cache to be ignored.
Timestamps Extension for High Performance (RFC 1323)EnabledSpecifies, when selected (enabled), that the system uses the time stamp extensions for TCP, as specified in RFC 1323, to enhance high-speed network performance. The time stamp option allows for accurate Round Trip Time (RTT) measurement, in addition to simplifying window calculations for the sender.

Note: The window scale functionality is built into the TCP profile, and you cannot manually disable or enable it; it will be negotiated if the send or receive buffer is larger than 65535 bytes. This option controls only the Timestamp functionality.

Loss Detection and Recovery

SettingDefault valueDescription
D-SACK (RFC 2883)DisabledSpecifies, when selected (enabled), that the system uses the Selective ACKs (SACK) option to acknowledge duplicate segments. RFC 2883 specifies an extension to Selective Acknowledgements, known as D-SACK. Using D-SACK, a receiver can notify its peer when it receives multiple copies of data, thus warning the sender of in-band network replication of segments or causing the peer to scale back in its re-sending speed.

Note: F5 recommends that you do not enable this option unless the peer device communicating with the BIG-IP system also supports D-SACK.

Early RetransmitEnabledSpecifies, when selected (enabled), that the system uses early retransmit (as specified in RFC 5827) to reduce the recovery time for connections that are receive- buffer or user-data limited. By default, this setting is enabled. Enabling this setting allows TCP to act as though a packet is lost, after fewer than the standard number of duplicate ACKs, if there is no way to send new data and generate more duplicate ACKs.
Enhanced Loss RecoveryEnabledSpecifies, when selected (enabled), that TCP uses SACK information to increase performance.

Note: This feature can be used only when Selective ACKs is also enabled.

Initial Retransmission Timeout Base Multiplier for SYN Retransmission3000 milliseconds
Range: 0 - 5000		Specifies the initial retransmission timeout (RTO) base multiplier for SYN retransmissions. The default value is 3000 (range is 0 - 5000) which sets the initial base RTO for SYN retransmissions at three seconds. This value is modified by the exponential backoff table to select the interval for subsequent retransmissions.
For example, if the value of this setting is changed to 1000, then the initial base SYN RTO would be changed to one second, and the next RTO would be two seconds, and then the subsequent RTO would be four seconds, etc., based on the exponential backoff table.

Note: For communication with pool members, the first five SYN retransmission intervals are always the configured syn-rto-base value. The system modifies the sixth SYN retransmission, and all subsequent SYN retransmissions, based on the exponential backoff table.

Limited Transmit RecoveryEnabledSpecifies, when selected (enabled), that the system uses limited transmit recovery revisions for fast retransmits, as specified in RFC 3042 to reduce the recovery time for connections on a lossy network.
Maximum Segment Retransmissions8
Range: 0 - 12		Specifies the maximum number of times the system resends data segments.
Maximum Syn Retransmissions3
Range: 0 - 12		Specifies the maximum number of times the system resends a SYN or SYN/ACK when it does not receive a corresponding reply.
Retransmit Threshold3
Range: 3 - 255		Specifies the number of duplicate ACKs (retransmit threshold) to start fast recovery. The default is 3. The range is from 3 to 255.
Selective ACKsEnabledSpecifies, when selected (enabled), that the system processes data using selective ACKs to improve system performance.

Note: F5 recommends that you do not disable this option. Selective ACKs (SACK) improves performance by explicitly listing which packets, messages, or segments in a stream are acknowledged. This lets the sender know specifically what information is missing, so that it only retransmits the missing information. SACK is detailed in RFC 2018.

Selective NACKDisabledSpecifies, when checked (enabled), that the system processes data using a selective negative acknowledgment (SNACK) whenever possible, to improve system performance. Enabling this setting improves packet flow between WAN Optimization Modules in a lossy network, because the system can detect and retransmit missing packets without waiting for the retransmit timer. This is a negotiated option and is automatically disabled if not supported by the peer.

Note: F5 recommends that you not change this setting.

Tail Loss ProbeEnabledSpecifies, when selected (enabled), that the system uses Tail Loss Probe to reduce the number of retransmission timeouts. Retransmission timeouts occur when TCP segments are lost from the tail of a transaction, or a window of data/ACKs are lost. Enabling this setting allows TCP to send a probe segment to trigger fast recovery instead of recovering a loss by way of a retransmission timeout.

Recommendations

The BIG-IP system does not allow you to modify the default TCP base profile, F5 recommends that you create a custom profile using the default profile as the parent profile. You can then modify some or all of the values defined in the custom profile, while leaving the parent profile settings at their default value. For information, refer to K14488: Working with profiles.
