Description

After an upgrade, the BIG-IP complains about a compression profile with an error such as the following appearing in the logs that does not allow the devices in the HA group to sync.

Sync error on <Hostname>: Load failed from /Common/<Peer_Hostname> 01070281:3: Invalid "compress gzip memory level" value for profile /Common/<profile_name>. Value must be one of 1k, 2k, 4k, 8k, 16k, 32k, 64k, 128k or 256k.

This sync error can appear after a recent configuration load failure.

Environment

  • After upgrade
  • Configuration load
  • ConfigSync

Cause

Each device or peer operates with its own instance of MCPD (Master Control Protocol Daemon) actively running. MCPD maintains a comprehensive configuration set in active memory (accessible through the command 'tmsh show running-config'). Under normal conditions, this command should reflect an exact replica of the configuration objects present in the flat configuration files, such as bigip.conf. However, discrepancies between the active memory configuration in MCPD and the flat configuration files can lead to operational issues.

One peer device's MCPD running configuration is properly synchronized, while the other peer's active configuration is not. This misalignment causes a conflict during the ConfigSync process, resulting in this error.

Recommended Actions

A reload of the MCPD process should refresh the active configuration in memory to mirror precisely what is stored in the flat configuration files on disk and should resolve the issue.

Perform a mcpd reload as mentioned in article K13030
