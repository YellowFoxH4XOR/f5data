Description

When a BIG-IP DNS listener is accessible from the public internet, external tools such as shodan.io or the dig command can reveal sensitive information. This includes the hostname of the device (resolver name is the term used by the shodan.io) that provides DNS response from its BIND.

For example, running a command like dig @<LISTENER> hostname.bind TXT CHAOS +short may return the device hostname.

# dig @192.168.100.1 hostname.bind TXT CH +short
"GTM-DC2.example.local"

Environment

  • BIG-IP DNS
  • DNS listener(s) exposed to the public internet
  • dig command

Cause

The DNS protocol allows queries in the CHAOS class (CH), such as hostname.bind, which are designed to return information about the DNS server itself. If the DNS listener is accessible from the internet, these queries can be executed by anyone, exposing internal device information.

Recommended Actions

In this article, we will apply an iRule to the DNS listener that drops any request with class "CH" (CHAOS), which prevents disclosure of resolver names and other metadata.

Creating an iRule

1.) Log in to the Configuration utility.
2.) Go to DNS > Delivery > iRules > iRule List.
3.) Select the Create button.
4.) For Name, type a name for the iRule.
5.) For Definition, enter the DNS iRule code.

when DNS_REQUEST {
    if { [DNS::question class] eq "CH" } {
        drop
    }
}

6.) Click the Finished button.

Applying the iRule to a DNS listener

1.) Go to DNS > Delivery > Listeners > Listener List.
2.) Select the name of the listener you want to apply the iRule.
3.) Select the iRules tab.
4.) For iRules, select Manage.
5.) In the Available list, select the iRule you previously configured, and move it to the Selected list.
6.) Click the Update button.
