Description

When local-ip is configured to the remote syslog server object on GUI, it does not synchronize to peer.

For example :

- Active unit :
[root@LTM1:Active:ChangesPending] config# tmsh list sys syslog
sys syslog {
    remote-servers {
        remotesyslog1 {
            host 10.10.10.1
            local-ip 192.168.1.1
        }
        remotesyslog2 {
            host 10.10.10.1
            local-ip 192.168.1.2
        }
    }
}

After ran configsync, remote syslog server object is synchronized to peer but local-ip doesn't.

[root@LTM2:Standby:InSync] config# tmsh list sys syslog
sys syslog {
    remote-servers {
        remotesyslog1 {
            host 10.10.10.1        <--- local-ip is not synchronized
        }
        remotesyslog2 {
            host 10.10.10.1        <--- local-ip is not synchronized
        }
    }
}

Environment

  • BIG-IP LTM
  • local-ip is configured to the remote logging configuration on GUI
  • Configsync

Cause

This is by design.

Recommended Actions

You can add the local-ip on peer by GUI manually.

or

You can add the local-ip on peer by tmsh command :

  1. For example, to add the local IP address 192.168.1.x to the remotesyslog instances, you would type the following command :

    tmsh modify sys syslog remote-servers modify { remotesyslog1 { local-ip 192.168.1.1} }
    tmsh modify sys syslog remote-servers modify { remotesyslog2 { local-ip 192.168.1.2} }


       2. Save your changes by typing the following command:

         tmsh save sys config

Note: Modification to remote syslog server object triggers configsync while modification to local-ip doesn't.

Additional Information

  • K15608: The BIG-IP system removes the local IP address specified in the remote logging configuration after a ConfigSync operation
