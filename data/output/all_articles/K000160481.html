K000160481: bigip_device_auth_ldap module not enabling after initial change to remote active directory

Type
Support Solution
Published
2026-03-26
Updated
2026-03-26
Source
https://my.f5.com/manage/s/article/K000160481

Description

When using the Ansible bigip_device_auth_ldap module to automate LDAP or Active Directory authentication configuration on BIG-IP LTM, changes made by the playbook may not be immediately activated. The updated LDAP configuration appears in the GUI, but the authentication method is not enabled until the "Finished" button is manually clicked in the GUI. As a result, the new authentication settings do not take effect automatically.

Environment

  • Product: BIG-IP LTM (using F5 Modules for Ansible, collection version 1.37.1)
  • Module: bigip_device_auth_ldap
  • Configuration: Ansible playbook modifies authentication LDAP object properties on BIG-IP LTM; changes are visible in both tmsh and GUI but not activated automatically.
  • Action: Attempted to automate enabling remote Active Directory authentication using Ansible.
  • Affected versions: Pre 2.5.0 of F5 Ansible collection

Cause

The use_for_auth parameter was not set to true in the Ansible task, so LDAP was not activated as the authentication provider automatically. Without this parameter, the system retains the previous authentication method until manual activation is performed in the GUI.

Recommended Actions

Set use_for_auth: true in the bigip_device_auth_ldap module within your Ansible playbook to activate LDAP as the authentication provider upon installation. This ensures that changes take effect immediately without requiring manual activation through the GUI. Example task:

- name: Manage Authentication
  f5networks.f5_modules.bigip_device_auth_ldap:
    provider: "{{ f5_provider }}"
    state: present
    source_type: '{{auth_ldap.source_type}}'
    servers: '{{auth_ldap.servers}}'
    port: '{{auth_ldap.port}}'
    remote_directory_tree: '{{auth_ldap.remote_directory_tree}}'
    scope: '{{auth_ldap.scope}}'
    bind_dn: '{{auth_ldap.bind_dn}}'
    bind_password: '{{auth_ldap.bind_password}}'
    # ... other parameters ...
    use_for_auth: true
