Known Issue

This is the result of a known issue. When a fragmented IPv6 datagram sent to a Layer 2 multicast address traverses a VLAN group, the BIG-IP system compacts the fragments before attempting to re-assemble them. However, after the fragments have been compacted and re-assembled, the BIG-IP system is unable to determine the correct location to insert the required Ethernet header. When this occurs, the TMM process dumps core and restarts.

F5 Networks Product Development tracked this issue as ID 241758 (formerly CR131645) and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WAN Optimization, or Edge Gateway Release Notes.

Additionally, this issue has been fixed in cumulative Hotfix-BIGIP-9.4.8-396.1-HF3, which has been issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.
