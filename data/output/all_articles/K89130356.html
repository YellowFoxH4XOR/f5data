Description

Third party web reporting application shows that a site is vulnerable and detects the target virtual server is using a cipher suite with the insufficient size of Diffie-Hellman small prime 1024 bits.

Environment

  • Client SSL profile
  • Cipher Suites
  • Diffie-Hellman ciphers

Cause

Beginning in BIG-IP 16.1.3 and 17.0.0, the BIG-IP system supports DHE keys larger than 1024 bits. For more information, refer to K79342815: BIG-IP support for RFC7919 Negotiated Finite Field Diffie-Hellman Ephemeral (FFDHE). Prior to these versions, BIG-IP uses only 1024-bit group for DH/DHE ciphers.

Recommended Actions

Choose one of the following options:

  • Update or upgrade to BIG-IP 16.1.3 or 17.0.0 or later and ensure DHE keys larger than 1024 bits are enabled (2048 bit should be enabled by default).
  • If you're not able to upgrade, you can modify the Client SSL profile assigned to the virtual server by changing the Cipher Suites to exclude DH/DHE ciphers, for example, change DEFAULT to DEFAULT:!DHE:!DH. This will disable the use of all DH/DHE 1024-bit ciphers from the cipher suites on that SSL profile. To do so, refer to K01770517: Configuring the cipher strength for SSL profiles (14.x - 21.x)

Important: The impact of changing the Cipher Suites setting depends on the individual environment. F5 recommends testing the changes during a maintenance window with consideration to the possible impact on your specific environment. For more details on how to modify the SSL profile Cipher Suites and to configure the cipher strength, refer to the Related Content articles below.

Additional Information

  • If you disable DH/DHE ciphers in your Client SSL profile as described previously, the profile will still use ECDH/ECDHE cipher suites.
  • Additionally, you can check what cipher suites will be used after modifying the Cipher Suites setting with this command from the CLI:

    tmm --clientciphers 'DEFAULT:!DHE:!DH'
