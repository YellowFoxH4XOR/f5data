K45835021: 5 second delay from wideIP

Type
Support Solution
Published
2023-03-03
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP DNS
Source
https://my.f5.com/manage/s/article/K45835021

Description

The Big-IP DNS receives the query, but doesn’t always answer immediately. Sometimes it only responds to the next query, 5 seconds later.

Environment

  • The Wide IP uses topology load balancing
  • The topology score is the same for each pool
  • The pools use round robin load balancing
  • Some pool members are disabled or offline
  • The fallback load balancing method is Drop Packet.

Cause

When using topology load balancing, tmm (traffic process) evaluates all the pools then selects the one with the highest score. Since these pools have the same score, the traffic is load balanced using round robin between them. The Big-IP then checks all pool members, regardless if they're disabled or offline, to return the best answer. If no pool members are available then the packet is dropped per the fallback load balancing method. The Big-IP then checks the other pool to provide a response, five seconds later.

Recommended Actions

Remove the offline pool and disabled pool members from the Wide IP.
