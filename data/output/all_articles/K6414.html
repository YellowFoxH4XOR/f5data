Topic

You can determine which alerts, by default, will trigger an SNMP trap by viewing the /etc/alertd/alert.conf file. The /etc/alertd/alert.conf file contains pre-configured alert definitions, which instruct the system on what actions to take when the alert is triggered.

Note: This article covers the default behavior and traps controlled by BIG-IP alert daemon (alertd). The traps issued by other daemons, for example, SNMP daemon (snmpd), is not managed in the /etc/alertd/alert.conf file. For more information about BIG-IP daemons, refer to K48615077: BIG-IP daemons (15.x - 16.x).

For example, to view the /etc/alertd/alert.conf file, type the following command:

cat /etc/alertd/alert.conf

An alert definition will display that appears similar to the following example:

alert BIGIP_SYSTEM_CHECK_E_CPU_FAN_SPEED_LOW {
        snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.5";
        lcdwarn description="CPU fan too slow." priority="3"
}

Alert definitions configured to trigger an SNMP trap will contain the snmptrap command, as in the following line from the example provided:

snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.5";

User-defined alert definitions are located in the /config/user_alert.conf file, which takes precedence over the /etc/alertd/alert.conf file. If the same alert is configured in both files, the system uses the action defined in the /config/user_alert.conf file instead of the action defined in the /etc/alertd/alert.conf file. For information about configuring custom SNMP traps in the /config/user_alert.conf file, refer to K3727: Configuring custom SNMP traps.

Important: F5 does not recommend or support modifications to the /etc/alertd/alert.conf file. The /etc/alertd/alert.conf file is not stored in user configuration set (UCS) archives, and it may be overwritten during hotfix installations and software upgrades. All custom alerts should be defined in the /config/user_alert.conf file.

Important: BIG-IP APM messages are not processed by the alertd SNMP process, and therefore custom scripts/traps cannot be triggered based on syslog messages for BIG-IP APM systems.

Note: For information about determining the format of the syslog-ng message strings sent with an SNMP trap, refer to K6420: The /var/run/bigip_error_maps.dat file maps the alertd process input from the syslog-ng utility to an alert name.
