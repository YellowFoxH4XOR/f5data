Known Issue

Portions of the BIG-IP ARM config may fail to load if a password begins with a numeric character.

Following is an example BIG-IP ARM configuration that has passwords beginning with alpha characters and loads correctly:

neighbor internet password a8iL$6LUuGMTsd6dOpi
neighbor 192.168.10.9 password a8iL$6LUuGMTsd6dOpi

#show run
router bgp 65005
aggregate-address 192.168.10.0/24 summary-only
neighbor internet remote-as 123456
neighbor internet password a8iL$6LUuGMTsd6dOpi
neighbor 192.168.10.9 peer-group internet
neighbor 192.168.10.9 password a8iL$6LUuGMTsd6dOpi

Following is an example configuration that has passwords beginning with numeric characters and has failed to load correctly:

neighbor internet password 8aiL$6LUuGMTsd6dOpi
neighbor 192.168.10.9 password 8aiL$6LUuGMTsd6dOpi

#show run
router bgp 65005
aggregate-address 192.168.10.0/24 summary-only
neighbor internet remote-as 123456
neighbor 192.168.10.9 peer-group internet

Impact

Dynamic routing protocols that require authentication will not work due to missing configuration objects.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H496778 on the Diagnostics > Identified > Medium screen.
  • Dynamic routing protocols are failing authentication.
  • Dynamic routing protocol objects are missing when you list the running BIG-IP ARM configuration.

Resolution

Status

F5 Product Development has assigned ID 477859 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, ensure that all ZebOS passwords begin with alpha characters.
