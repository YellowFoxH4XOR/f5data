K000135299: Transfer-encoding response header is missing.

Type
Support Solution
Published
2023-06-29
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K000135299

Description

  • Server sends chunked data with "transfer-encoding: chunked" header but the header is not preserved on client side
  • Virtual server has assigned an HTML profile

Environment

  • BIG-IP LTM
  • HTML Profile
  • Transfer-encoding header

Cause

Seen behavior is caused by Bug ID 745291

Recommended Actions

Upgrade to an unaffected version. As a workaround you can use an use an iRule which selectively enables/disables HTML filter for header Content-Type other than HTML/CSS:

For example if Content-Type is application/json:

when HTTP_RESPONSE {
if { [HTTP::header Content-Type] starts_with \"application/json\" } {
clientside {
HTML::disable
}
}
if { [HTTP::header Content-Type] starts_with \"text/html;\" } {
clientside {
HTML::enable
}
}
}
