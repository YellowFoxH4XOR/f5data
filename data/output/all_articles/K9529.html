Topic

Starting in FirePass 6.0.3, you can configure an external DHCP server to assign IP addresses to Network Access clients. You can enable this option on a per-resource group basis by selecting the Retrieve IP Address from designated DHCP Server check box on the Network Access : Resources page and entering the IP address of the DHCP server in the DHCP Server Address field. The Retrieve IP Address from designated DHCP Server option is not typically configured when NAPT is enabled on the FirePass controller, since NAPT effectively hides the real IP address of a Network Access client behind the IP address of the FirePass controller.

Note: For more information about the differences between NAPT and virtual subnets, refer to K8112: Network-layer routing considerations when using Network Access.

Important: If NAPT is disabled on the FirePass controller, and you enable the Retrieve IP Address from designated DHCP Server option, you must ensure that the devices on your network will route the IP addresses assigned by the DHCP server to the FirePass controller.

In a FirePass cluster configuration, the DHCP Server Address and DHCP Relay Agent Address fields on the Network Access : Resources page are synchronized from the primary cluster node to the secondary cluster nodes. You can only configure one DHCP server in the DHCP Server Address field. If your configuration only requires a single DHCP server, for example if all cluster nodes reside on the same network segment, you can safely configure the DHCP Server Address setting on the primary cluster node. However, in this configuration, you should not enter an IP address in the DHCP Relay Agent Address field. FirePass uses the IP address in the DHCP Relay Agent Address field as the source address for DHCP requests. Since this IP address will only be valid for one of the cluster nodes, all responses from the DHCP server will be sent to that cluster node instead of to the cluster node which sent the DHCP request. If you want to configure an identifier for the cluster nodes on the DHCP server, use the DHCP vendor class identifier or the DHCP agent circuit ID sent by FirePass. FirePass uses F5.FirePass for the vendor class identifier and the name of the resource group for the agent circuit ID.

Note: If you plan to configure a separate Network Access resource for each cluster node, as detailed below, you can safely configure the DHCP Relay Agent Address setting for each Network Access resource. However, even in this configuration, F5 Networks strongly recommends using the vendor class identifier or the agent circuit ID as the identifier used by your DHCP server instead of the relay agent address.

If your cluster configuration requires multiple DHCP servers, for example if your cluster nodes are located in geographically diverse locations, you must configure multiple Network Access connections. For example, if you have one cluster node in Chicago and one in Seattle, you could configure a resource group named Chicago_resource with a Network Access connection named Chicago_VPN. For the Chicago_VPN Network Access connection, you would configure the DHCP settings appropriate for the Chicago cluster node. Next, you could configure a resource group named Seattle_resource with a Network Access connection named Seattle_VPN, and configure Seattle_VPN with the DHCP settings appropriate for the Seattle cluster node.

If you statically assign the resource groups you just created groups to a master group, users may attempt to launch a Network Access connection with invalid DHCP parameters for that cluster node. For example, if a user logs on to the Chicago cluster node and launches the Seattle_VPN Network Access resource, the Chicago cluster node may be unable to contact the Seattle DHCP server, or the Seattle DHCP server may assign a client IP address which is invalid for the Chicago network. To work around this behavior, you can configure dynamic resource group mapping using the Session Variable mapping method.

The %session.network.server.ip% session variable contains the IP address of the FirePass web service used for logon. By configuring the Session Variable resource group mapping method, you can map the cluster node IP address to the appropriate resource group configured for that node’s network. Important: The %session.network.server.ip% session variable always contains 12 digits. For example, if the IP address of the FirePass web service the user logged onto is 10.202.16.5, FirePass sets %session.network.server.ip% to 010.202.016.005.

When a user logs on to the cluster node with the IP address of 192.168.0.38, the user is dynamically assigned the Chicago_resource resource group. When a user logs on to the cluster node with the IP address of 192.168.202.100, the user is dynamically assigned the Seattle_resource resource group.

In order for the resource group to be assigned for the user, dynamic resource group mapping must be enabled for the user’s master group. For information about configuring dynamic resource group mapping, refer to the FirePass Controller Administrator Guide.
