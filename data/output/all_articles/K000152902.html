K000152902: How the Default Load Balancer handles non-SNI clients

Type

Published
2025-08-06
Updated

What Happened?

  • You want to know what exactly does checking the box for "default load balancer" do

Environment

  • F5 Distributed Cloud HTTP Load Balancer
  • F5 Distributed Cloud TCP Load Balancer

Resolution/Answer

This feature enables support for non-SNI clients when multiple HTTP Load Balancers are advertised on a single VIP and port. In such cases, the Load Balancer designated as the default will handle TLS requests from clients that omit the SNI field in the handshake, using its certificate to establish the session.

Cause

When multiple HTTP and/or TCP Load Balancers are advertised on a single VIP, request routing is based on Server Name Indication (SNI). Only requests with matching SNI values are forwarded to the corresponding Load Balancer. If the TLS Client Hello lacks an SNI, the default HTTPS Load Balancer is selected, and its certificate is used to establish the TLS session.

Additional Information

  • The Default Load Balancer should be utilized when multiple undefined or wildcard domains resolve to the same Load Balancer or public IP address.
  • When multiple HTTP and/or TCP Load Balancers are configured on a single VIP, request handling is based on Server Name Indication (SNI). Only requests with matching SNI values are routed to their respective Load Balancers. This behavior introduces the concept of a Default Load Balancer per Advertise policy. If the TLS Client Hello lacks an SNI, the default HTTPS Load Balancer is selected, and its certificate is used to establish the TLS session.
  • When there are multiple wildcard domain, set a single multi-SAN certificate covering the wildcard domains to ensure correct routing for non-SNI clients.
