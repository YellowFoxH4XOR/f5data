Description
vCMP Guest can show new tmm interfaces which were not added from the vCMP Host, these interfaces will have a status of "uninit" and have no MAC Address assigned:

# tmsh show net interface
--------------------------------
Name    Interface Status    Mac-Addr
1/0.11    up                <VALID_MAC>
1/0.12    up                <VALID_MAC>
1/0.21    uninit             none
1/0.22    uninit             none
1/mgmt    up                <VALID_MAC>
3/0.11    up                <VALID_MAC>
3/0.12    up                <VALID_MAC>
3/0.21    uninit             none
3/0.22    uninit             none
3/mgmt    up                <VALID_MAC>

Environment

  • vCMP Guest (s) deployed in a multi-bladed vCMP Host (VIPRION).
  • Rebooting the Guest on it's primary slot assigned.

Cause

  • Unknown at the time of publishing

Recommended Actions

Perform a force reload of mcpd:

Impact of procedure: BIG-IP system traffic processing is interrupted while the system restarts.
  1. Log in to the Advanced Shell (bash).
  2. To create a null file with the file name forceload in the /service/mcpd directory, enter the following command:
touch /service/mcpd/forceload
On VIPRION/vCMP systems, enter the following command to run this command on all blades. You should use this on both multi-slot hosts and multi-slot guests. You do not need to run this if your system is a single-slot host or single-slot guest, but doing so should not have any negative impact on your system.:
 
clsh touch /service/mcpd/forceload
  1. To restart the BIG-IP system, enter the following command:
reboot
On VIPRION systems, enter the following command to run this command on all blades:
clsh reboot
 

Additional Information

The binary mcpd database retains a memory of the allocated HSB interfaces, and if the interfaces get reassigned on startup (such as can occur after a blade or chassis reboot), the previous interfaces are still present in the list of interfaces, but are uninitialized. This memory may well be related to interface statistics that are recorded in MCPD.

The host creates the 0.x interfaces as network interfaces for the guests to communicate to the HSB on the host. There is a fixed number of these interfaces, and the size of the guest dictates how many it is allocated.
When the guests starts for the first time, the host allocates some of the available 0.x interfaces to the guest.

If the host is restarted then all the guests get to start one by one. If there has been significant reconfiguration of the guests prior to the reboot (old guests deleted, new guests created), the host may allocate these HSB interfaces in different ways. This introduces the changes resulting in those old (no longer assigned) interfaces being "uninit".

An mcpd forceload deletes the binary mcpd database, and because the statistics are no longer present, they no longer show up as uninitialized interfaces.
