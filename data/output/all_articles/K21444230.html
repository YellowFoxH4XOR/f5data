Description

An Aspen service mesh is logically split into two parts: data plane and control plane. The data plane consists of independent Envoy proxies injected to application PODs as istio-proxy sidedcar containers. All sidecar proxies are responsible for network communication and reporting metrics about proxied traffic.

Control Plane elements manage and configure all Envoy proxies to route traffic between services, collects metrics from all mesh components, reports problems within the mesh.

Aspenmesh architecture is described here, and it is based on Istio architecture.

Istiod is a heart of Control Plane and it is responsible for configuring all sidecar proxies. Every proxy is independent and, once configured, it holds a complete set of information to communicate with other proxies even without communication to Istiod. While proxies can handle traffic even when the connection to Istiod fails, it is important to monitor Istiod and other Contrtol Plane components. If mTLS is configured in the mesh and Istiod is deployed as a mesh CA then Istiod needs to rotate TLS certificates for all proxies otherwise the certificates will expire and the traffic will be stopped. 

In this article we will document what metrics are by default collected by Aspenmesh for Control Plane components.

Additional Information

Aspenmesh Metrics Collector is responsible for scraping all metrics from the service mesh. Metrics Collector is a customized Prometheus instance and it is deployed by default with other aspenmesh components during installation.

The following Control Plane components are scraped by the metrics collector:

  - job_name: 'aspen-mesh-control-plane' 
    - all pods with “app: aspen-mesh-control-plane” label from istio-system namespace 
    - metrics path: /metrics 
  - job_name: 'jaeger-cassandra' 
    - all pods with “app: jaeger-cassandra” label from istio-system namespace 
    - metrics path: /metrics 
  - job_name: 'pilot' 
    - all Istiod PODs  
    - metrics path: /metrics

Istiod PODs are the heart of the Control Plane responsible for configuring and managing all mesh proxies. Every Istiod is exposing metrics under port 15014 and /metrics URI. We can open a port forward to the POD to get all Istiod metrics from /metrics URI. 

We can also list all metrics scraped by using metrics-collector Prometheus UI e.g. by running the below PromQL query:

{job="pilot", instance="<POD_IP>:15014"}
