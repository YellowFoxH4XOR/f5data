Topic

NameSurfer will only import zones that are defined as master in the /etc/named.conf file. NameSurfer ignores zones that are marked as secondary (slave). To resolve this issue, you must edit the zone file and change it from a secondary zone to a primary (master) zone.

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

Edit the zone file

To change the zone to a master zone, perform the following steps:

  1. Using a text editor, such as vi or pico, edit the /etc/named.conf file zone entry and change it from:

    zone "domain.com" IN {
        type slave; masters port 8054 { 127.0.0.1; };
        file "db.domain.com.bk";
};

    To the following:

    zone "domain.com" IN {
        type master;                                
        file "db.domain.com";   
};

    Note: You are not required to remove the .bk extension, but if you do not, the zone files in /var/namedb and the zone entries in /etc/named.conf file will have an additional .bk extension appended to the name of the zone when the zones are re-imported into NameSurfer. For example: file "db.domain.com.bk.bk".
     

  2. Change the database in the /config/3dns/named/ file to reflect the changes that you made to the /etc/named.conf file.

    For example:

    mv /config/3dns/namedb/db.domain.com.bk /config/3dns/namedb/db.domain.com

    Note: /config/3dns/namedb/ is an example. The directory in which the zone files reside on your system is defined in the directory statement of the options section in the /etc/named.conf file.

    Important: The name of the zone file in the /config/3dns/namedb/ file must match the file name specified in the /etc/named.conf file, or the zone data will not load.

  3. Stop NameSurfer so that it closes all associated files that are currently open, by typing the following command:

    /usr/local/namesurfer/bin/stop

  4. Reload named, by typing the following command:

    ndc restart

  5. Type the following command to check the /var/log/messages file to verify that the zone you edited loads without any errors:

    grep -i 'named' /var/log/messages

    The output should appear similar to the following:

    Jan 4 19:27:11 3dns-001 named[19606]: Zone 'domain.com ' (file db.domain.com): 
No default TTL set using SOA minimum instead
Jan 4 19:27:11 3dns-001 named[19606]: master zone 'domain.com' (IN) loaded (serial 2000072501)

    Note: If the /var/log/messages file shows that the zone did not load properly, verify the zone entry in the /etc/named.conf file and verify the name of the zone file in /var/namedb.

Import the zone files into NameSurfer

Import the zones into NameSurfer as follows, specific to the 3-DNS Controller version you are running.

3-DNS versions 4.2 - 4.6.4

  1. Type the following command:

    config

  2. Choose the N option.

    The Configure NameSurfer screen appears.

  3. Choose the Import new zone files option.

  4. After the script completes, verify that the zone displays on the NameSurfer screen.

  5. Once this procedure works with one zone file, repeat the procedure on the remaining zone files until they are all imported back into NameSurfer.

    Note: You can edit multiple zones at once to accelerate the process.

3-DNS versions 2.0.1 - 4.0.1

  1. Type the following command:

    config_namesurfer

    The Configure NameSurfer screen appears.

  2. Choose the Import new zone files option.

  3. After the script completes, verify that the zone displays on the NameSurfer screen.

  4. Once this procedure works with one zone file, repeat the procedure on the remaining zone files until they are all imported back into NameSurfer.

    Note: You can edit multiple zones at once to accelerate the process.
