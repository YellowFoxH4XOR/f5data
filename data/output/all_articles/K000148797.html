K000148797: Self-IP Violation Logs on BIG-IP AWAF event logs

Type
Support Solution
Published
2025-03-29
Updated
2025-03-29
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.1.X, 17.1.2, 17.1.1
  • BIG-IP ASM: 17.X.X, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source

Description

Encountering BIG-IP AWAF event logs generated by self-IP addresses on F5 devices. The violation type logged is "Unparsable Request Content," with details indicating "HTTP version not found." This issue appears across nearly all ASM policies, resulting in noisy logs and potential resource degradation of device

Environment

  • BIG-IP AWAF event logs generated from BIG-IP self-IP 
  • Self-IP addresses configured and GTM pool group with gateway_icmp health monitor

Cause

The violations are caused by GTM monitors triggering HTTP requests that do not specify a version, leading to "HTTP version not found" violations. This is due to the default HTTP 0.9 monitor configuration, which only includes a request line without specifying the HTTP version.

Recommended Actions

  • Custom HTTP Monitors: Create custom HTTP monitors that use HTTP/1.0 or HTTP/1.1.
  • Remove Monitors: Remove HTTP monitors and rely on the BIG-IP monitor of the server object to communicate the VS status to the GTM. 

 

Additional Information

If still issue is not resolved. Please run below commands during a maintenance window because it could cause increased cpu usage.
 
# Enable gtm debugging
 
tmsh modify /sys db gtm.debugprobelogging {value "enable"}
tmsh modify /sys db log.gtm.level {value "debug"}
tmsh modify /sys db gtm.querylogging {value "enable"}
 
# Wait 30 seconds, then disable debugging.
 
# Disable gtm debugging
 
tmsh modify /sys db gtm.debugprobelogging {value "disable"}
tmsh modify /sys db log.gtm.level {value "notice"}
tmsh modify /sys db gtm.querylogging {value "disable"}
