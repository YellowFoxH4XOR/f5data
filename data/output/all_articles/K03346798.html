Description

From February 17th 2020, Chrome 80 will introduce new behaviour in the browser for handling HTTP cookies in order to reduce exposure to CSRF attacks.  See planned schedule here.

The SameSite cookie attribute is defined in draft rfc6265bis (Currently Draft version 05) with three possible values which dictate how the users' browser treats cookies that could be sent to a third party domain. The previous browser behaviour is most similar to None.

Environment

  • Chrome 80
  • HTTP Cookies

Cause

Chrome changes its behaviour on the handling of HTTP Cookies

Recommended Actions

LTM Configuration Utility (GUI) cookies
LTM GUI cookies should not be impacted by the SameSite cookie attribute enforcement by browsers as these cookies are not intended to be sent to third party sites.

LTM persistence cookies
In most cases LTM persistence cookies should not be impacted as they’re not typically intended to be sent to third party sites, except in cases where a persistence cookie is sent to an element of a webpage in third-party context.

See Increased Security With First Party Cookies and Set the SameSite Attribute for LTM Persistence Cookies on Devcentral if your environment requires persistence cookies be sent across domains. You can use an LTM Policy or iRule to set the SameSite attribute to None and set the secure flag.

A more comprehensive iRule is being actively worked on in DevCentral to cover multiple use cases:
iRule to set SameSite for compatible clients and remove it for incompatible clients (LTM|ASM|APM)

ASM protected applications
ASM added SameSite support in 13.1.0. See Meltdown and Spectre Web Application Risk Management on DevCentral for more details.

Known defect: Bug ID 879841: Domain cookie same-site option is missing the "None" as value in GUI and rest

APM Cookies
See Add SameSite attribute to APM Cookies on DevCentral
