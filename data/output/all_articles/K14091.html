Known Issue

The BIG-IP configuration may fail to load its configuration after you perform an upgrade.

This issue occurs when all of the following conditions are met:

  • You have a vCMP compatible platform.
  • You are upgrading a vCMP guest from BIG-IP 11.1.0 to 11.2.0, or you load a version 11.1.0 UCS file on an 11.2.0 vCMP guest.

This issue occurs because of the following incorrect provisioning statement in the upgraded BIG-IP configuration:

sys provision wam { }

Impact

Upgraded hosts' configurations fail to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H389559 on the Diagnostics > Identified > Medium  screen.

  • The BIG-IP configuration utility may display the following message at the top of the screen:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

  • You may see the following error message when attempting to load the upgraded configuration from the command line; you may also see the message in the /var/log/ltm log file:

    0107100f:3: The provisioning for module (wam) is invalid or cannot be used on this platform.

Workaround

To work around this issue, you can manually remove the offending provisioning declaration. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the BIG-IP command line as the root user.
  2. Using a text editor such as vi, edit the /config/bigip_base.conf file and delete the following line:

    sys provision wam { }

  3. Save the resulting edit, and manually load the BIG-IP configuration using the following command:

    tmsh load sys config
