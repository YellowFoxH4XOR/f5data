Topic

This article applies to BIG-IP 9.x through 11.2.x. For information about other versions, refer to the following article:

  • K14779: Overview of BIG-IP SYN cookie protection (11.3.x - 11.6.x)

BIG-IP software includes the SYN Check Activation Threshold setting, which prevents the BIG-IP SYN queue from becoming full during a SYN flood attack. The SYN Check Activation Threshold setting indicates the number of new or untrusted TCP connections that can be established before the BIG-IP system activates the SYN Cookies authentication method for subsequent TCP connections.

Note: New or untrusted TCP connections are connections that are in the process of the three-way TCP handshake. If the TCP connections never complete the three-way handshake and the threshold limit is reached, the system begins clearing the connection queue and inserts SYN cookies that the client must reply with for any subsequent TCP connections in order to continue.

When the BIG-IP system activates the SYN cookie authentication method, the system behaves as follows:

  1. A client sends a TCP SYN request to the BIG-IP virtual server.
  2. The BIG-IP system sends the SYN+ACK response back to the client but discards the SYN queue entry. This means the BIG-IP system does not need to keep the SYN-RECEIVED state that is normally stored in the connection table for the initiated session. Because the SYN-RECEIVED state is not kept for a connection, the SYN queue is not exhausted, and normal TCP communication can continue.

    Note: The TCP window scale and time stamp options are stripped off in the SYN-ACK response when SYN cookie is enabled. This formatting preserves the SYN cookie sequence space, which is used to store the encoded secret in the SYN-ACK packet.

  3. If the BIG-IP system then receives a subsequent ACK response from the client, it reconstructs the SYN queue entry by decoding data in the TCP sequence number.
  4. When the BIG-IP system validates the client's ACK, the session is added to the connection table and the BIG-IP system initiates a connection to the pool member.

Note: The BIG-IP system does not currently log a message when the SYN cookie threshold is exceeded.

Adjusting the SYN Check Activation Threshold setting

The default SYN Check Activation Threshold is 16,384 connections. To adjust the SYN Check Activation Threshold setting, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click General Properties. For BIG-IP 10.0.0 and later, click Configuration.
  4. From the Local Traffic menu, select General.
  5. In the SYN Check Activation Threshold box, type the desired value.
  6. Click Update.

Self IP Addresses

Starting in BIG-IP 9.4.0, SYN cookie protection is enabled for all self IP addresses configured on the system. For more information, refer to K12267: BIG-IP SYN cookie protection is enabled for self IP addresses.

Profiles that support SYN cookie protection

The following BIG-IP protocol profiles offer SYN cookie protection:

  • TCP
  • FastHTTP
  • FastL4

    Note: The FastL4 profile only offers SYN cookie protection beginning with BIG-IP 9.4.0.

    Note: Unlike for the TCP and Fast HTTP profiles, SYN cookie protection must be enabled manually within the FastL4 profile. By default, SYN cookie protection is disabled for FastL4 profiles.

    Note: On certain BIG-IP platforms, the FastL4 profile supports hardware SYN cookie protection in addition to software SYN cookie protection.

    Note: If you are using an nPath routing configuration, you cannot benefit from SYN cookie protection. With this method of traffic management, return packets bypass the BIG-IP system and reach the client via a different route. Because the BIG-IP system never sends SYN-ACK packets to clients, the BIG-IP system cannot issue SYN cookies. For more information about nPath, refer to the Configuring nPath Routing chapter in the BIG-IP Local Traffic Manager: Implementations guide. For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Hardware SYN cookie protection

You can enable or disable hardware SYN cookie protection for virtual servers using the FastL4 profile when the PVA10 ASIC is present on the BIG-IP system. Only the BIG-IP 8400 and 8800 platforms are equipped with a PVA10 ASIC. By default, hardware SYN cookie protection is disabled in the FastL4 profile.

Note: To use hardware SYN cookie protection, you must enable the autolasthop feature. For more information, refer to K16887: Autolasthop must be enabled for hardware SYN cookie protection to function.

When hardware SYN cookie protection is enabled in the FastL4 profile, the following BigDB variables determine how the algorithm works:

  • pva.syncookies.connectionthreshold:

    When the system starts up, the SYN cookie authentication method is initially disabled in the PVA10 chip. If the current connection count in the PVA10 chip reaches the pva.syncookies.connectionthreshold threshold, the PVA10 chip activates the SYN cookie authentication method. The default value for this variable is 0 (zero).

  • pva.syncookies.synratethreshold:

    Once the SYN cookie authentication method is enabled, the pvad process continues to monitor the unanswered SYN cookie packet rate; its value = (syn_cookies_generated - syn_cookies_answered)/sampling_period. If the unanswered SYN cookie packet rate value is less than pva.syncookies.synratethreshold, the SYN cookie authentication method is disabled. The default value for this variable is 200000 packets per sec.

When hardware SYN cookie protection is enabled for the FastL4 profile, the PVA issues its own SYN cookies to the client. When the three-way TCP handshake is complete, the final ACK from the client is passed to the Traffic Management Microkernel (TMM) for load balancing. TMM then initiates a three-way handshake with the pool member and passes the final ACK containing a PVA snoop header to the server to allow the transition to hardware load balancing.

Note: If the PVA Acceleration mode for the virtual server is demoted to None, or the platform does not contain the PVA chip, then hardware SYN cookie protection is disabled for the virtual server, and SYN cookie protection is performed in software.

Enabling or disabling hardware SYN cookie protection for the FastL4 profile

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol menu, select FastL4.
  4. Click Create.
  5. Type a name for the profile.
  6. From the Parent Protocol menu, select FastL4.
  7. Select the Custom box for Hardware SYN Cookie Protection.
  8. Select the box to enable Hardware SYN Cookie Protection.
  9. Click Finished.

    You must now associate the profile with the virtual server.

Software SYN cookie protection

You can use software SYN cookie protection on any BIG-IP platform. Software SYN cookie protection is enabled by default and cannot be disabled for all TCP and Fast HTTP profiles. If software SYN cookie protection is desired for a FastL4 profile, this must be enabled manually on a per profile basis. By default, the setting is disabled.

Enabling or disabling software SYN cookie protection for the FastL4 profile

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol menu, select FastL4.
  4. Click Create.
  5. Type a name for the profile.
  6. From the Parent Protocol menu, select FastL4.
  7. Select the Custom box for Software SYN Cookie Protection.
  8. Select the box to enable Software SYN Cookie Protection.
  9. Click Finished.

    You must now associate the profile with the virtual server.
