K000162684: Controlling URL Categorization Updates on BIG-IP

Type
Support Solution
Published
2026-09-17
Updated
2026-09-17
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162684

Description

 A BIG-IP LTM system can contact the URL categorization service even when IP reputation updates are disabled with iprep.autoupdate=disable. The wr_urldbd service remains enabled by default and manages URL categorization independently of IP reputation.

Environment

  •  BIG-IP LTM
  • IP reputation updates disabled:
(tmos)# list sys db iprep.autoupdate
sys db iprep.autoupdate {
value "disable"
}
  • wr_urldbd service configured to start by default:
(tmos)# list sys service wr_urldbd
sys service wr_urldbd {
Boot on
Default yes
}

Cause

 IP reputation and URL categorization are independent functions managed by separate daemons:

  • iprepd manages the IP Reputation Database.
  • wr_urldbd manages the URL categorization database.

Disabling IP reputation updates does not stop URL categorization database activity.

Answer/Recommended Actions

To stop the URL categorization, please follow either of the options below:

  1. Stop URL categorization daemon temporarily :
bigstart stop wr_urldbd

Note: This is not persistent. The service can start again after a reboot or service restart.

  1.  Disable BrightCloud database updates persistently by editing the existing URL configuration sections and setting in in /etc/wr_urldbd/bcsdk.cfg:
# cp /etc/wr_urldbd/bcsdk.cfg etc/wr_urldbd/bcsdk.cfg.bak
# vi /etc/wr_urldbd/bcsdk.cfg

DoBcap=true
DoRtu=false
DownloadDatabase=false
