Topic

This article applies to BIG-IP ASM 11.x - 13.x. For information about other versions, refer to the following articles:

  • K6590: Overview of the BIG-IP ASM watchdog process (9.x - 10.x)

The watchdog process in BIG-IP ASM monitors critical ASM daemons and attempts to restart the daemons if they fail.

Description

In BIG-IP ASM 11.6.0 and later, the asm_start watchdog process monitors critical ASM daemons and restarts the daemons in their proper order when failures are detected. The asm_start process logs an error message to the /var/log/asm file when the watchdog reports a daemon failure.

For example:

01310027:2: ASM subsystem error (asm_start,F5::NwdUtils::Nwd::log_failure): Watchdog detected failure for process. Process name: bd, Failure: Insufficient number of threads (required: 8, found: 0).

In BIG-IP ASM 11.0.0 through 11.5.4, the nwd watchdog process monitors critical ASM daemons, reports daemons that fail to the recovery_mngr process, and attempts to restart them. Additionally, the nwd process logs an error message to the /var/log/asm file.

For example:

01310027:2: ASM subsystem error (nwd.pl,F5::NwdUtils::Nwd::log_failure): Watchdog detected failure for process. Process name: bd, Failure: Insufficient number of threads (required: 8, found: 0).

The watchdog process in BIG-IP ASM is responsible for monitoring one or more ASM daemons, depending on the BIG-IP ASM version:

BIG-IP 12.0.0 and later

  • correlation
  • asmcrond
  • asm_config_server
  • clean_db
  • bd
  • bd_agent
  • asmcsd
  • pabnagd
  • dcc
  • asmlogd

BIG-IP 11.6.0 through 11.6.1

  • correlation
  • learning_manager
  • asm_config_server
  • clean_db
  • bd
  • bd_agent
  • asmcsd
  • pabnagd
  • dcc
  • asmlogd

BIG-IP 11.1.0 through 11.5.4

  • correlation
  • learning_manager
  • asm_config_server
  • clean_db
  • bd
  • bd_agent
  • asmcsd
  • pabnagd

BIG-IP 11.0.0

  • log_manager
  • learning_manager
  • asm_config_server
  • clean_db
  • bd
  • bd_agent
  • asmcsd
  • pabnagd
