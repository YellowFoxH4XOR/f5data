K05984131: BIG-IP configuration does not load because the device SSL cert and key do not match, after a code upgrade.

Type
Support Solution
Published
2021-06-11
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP LTM: 12.1.3
Source
https://my.f5.com/manage/s/article/K05984131

Description
Unable to load BIG-IP configuration after code upgrade. Below error messages appeared in /var/log/ltm while trying to load the BIG-IP config file:

01070920:3: Application error for confpp: Syntax OK
The certificate does not match the key.  To change them try 'tmsh modify sys httpd { ssl-certfile /etc/httpd/conf/ssl.crt/server.crt ssl-certkeyfile /etc/httpd/conf/ssl.key/server.key }'

Environment

  • BIG-IP LTM
  • Upgrade
  • Device SSL cert and key mismatch

Cause
This is caused because the device SSL server cert and key get corrupted during the upgrade process.

Recommended Actions

In order to fix this Cert and key mismatch the BIG-IP device cert and key need to be updated by following below steps:

  1. Get the F5 device cert and key from a backup and download it into a local machine
  2. Re-Name the device SSL cert, obtained in step one as server.crt
  3. Re-Name the device SSL key,  obtained in step one as server.key
  4. Using a SCP client move, to this directory to update the SSL cert  /etc/httpd/conf/ssl.crt
Copy and replace the current server.crt file
  1. Then move, to move to this directory to update the SSL key /etc/httpd/conf/ssl.key

Copy and replace the current server.key file

  1. Restart the httpd process so new changes take place

#tmsh restart /sys service httpd tomcat

  1. Verify BIG-IP configuration:

#tmsh load sys config verify

  1. Load BIG-IP configuration file:

#tmsh load sys config

 

Additional Information

First needs to verify the device cert and key integrity by using below commands:

  #openssl x509 -noout -modulus -in /etc/httpd/conf/ssl.crt/server.crt
 #openssl rsa -noout -modulus -in /etc/httpd/conf/ssl.key/server.key


The output from this command should return a HEX string similar to these:

openssl x509 -noout -modulus -in /etc/httpd/conf/ssl.crt/server.crt
Modulus=ABCDEF0123....
openssl rsa -noout -modulus -in /etc/httpd/conf/ssl.key/server.key
Modulus=ABCDEF0123....


But if this issue occurred instead of getting the above results, the outputs will be different:

openssl x509 -noout -modulus -in /etc/httpd/conf/ssl.crt/server.crt
Modulus=ABCDEF0123....
openssl rsa -noout -modulus -in /etc/httpd/conf/ssl.key/server.key
Modulus=0123ABCDEF....
