Description

This article explains how to keep the current management-ip when you restore ucs archive.

This option will not appear in context help or tab completion.

Environment

  • BIG-IP
  • BIG-IQ
  • UCS archive

Cause

Current Management IP changes after loading a UCS.

Recommended Actions

To avoid current Management IP change, you can specify the keep-current-management-ip option to the load sys ucs command.

Impact of procedure: The BIG-IP system replaces any existing configuration with the UCS archive file configuration. Specific system services restart, and the device may temporarily lose network failover connectivity if it is a member of a device group. F5 recommends that you perform this procedure during a maintenance window and when the system is a member of a device group when it is in the standby state.

Note: If using this on a BIG-IQ License Manager, its licensed BIG-IPs will still display the license from the IP of the original BIG-IQ, but this information will update the next time the new BIG-IQ needs to reactivate the license for the BIG-IP.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    # tmsh

  2. To load the ucs, use the following command syntax:

    # load sys ucs <ucs_file_from_another_system> keep-current-management-ip

    For example, to load ucs name myconfig.ucs, the command appears similar to the following example:
    Note: You should include the no-license and platform-migrate options if the UCS is from a different BIG-IP platform. For information about the limitations and caveats for these two options, refer to the articles in the Related Content section at the end of this article.
    Note: When the platform-migrate option is used with keep-current-management-ip option, management routes defined in the UCS will not be restored as noted in K82540512.

    # load sys ucs myconfig.ucs no-license platform-migrate keep-current-management-ip

Additional Information

None.
