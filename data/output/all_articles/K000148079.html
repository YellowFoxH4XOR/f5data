K000148079: Weak ciphers presented by Load Balancer despite High TLS security level

Type

Published
2024-11-08
Updated
2024-11-08
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000148079

Description

You are noticing that a Load Balancer (LB), despite being set to High TLS Security Level, is presenting weak ciphers (such as TLSv1.0 and TLSv1.1), leading to low ratings on SSL testing platforms like SSL Labs.

Environment

  • F5 Distributed Cloud HTTP Load Balancer 
  • TLS Certificate

Resolution/Answer

To ensure a High Security Level for ciphers on a given LB, the following actions can be taken:
  1. Increase the TLS Security Level on the LB that has low-security ciphers (recommended).
  2. Use a different TLS certificate for the LB with high-security requirements.
  3. Use a different dedicated VIP for the LB with high-security requirements.
  4. Disable TLS coalescence by configuring the LB to prevent sharing ciphers with other LBs

Cause

This is expected behavior due to the coalescing of TLS connections across LBs that share the same VIP and certificate. The cipher settings are unified to prevent TLS handshake failures.

  • This can be observed using tools like nmap or SSL Labs.
  • For example, in a setup where one certificate is shared by multiple LBs, inspecting the configurations revealed that one of the LBs one may has a Low TLS Security Level, thus impacting the overall cipher presentation.

Additional Information

This behavior occurs when multiple Load Balancers share the same TLS certificate and same VIP (Virtual IP). By default, unless configured otherwise, LBs in the same tenant use a shared VIP. Under this setup, the VIP consolidates connections using Server Name Indication (SNI) to separate virtual hosts. This consolidation process is known as TLS coalescing.

  • SNI requires that all virtual hosts sharing the same endpoint use the same TLS Cipher settings to avoid handshake failures.
  • F5 Distributed Cloud allows this configuration, but the shared VIP will present a TLS Server Hello with cipher suites matching the lowest TLS Security Level configured across all LBs using the same certificate. This means if an LB configured with High Security ciphers shares the certificate with another LB using Low Security ciphers, the test will return weak ciphers and potentially result in a B- rating or lower on SSL Labs and other validation tools.
