Known Issue

In some circumstances, using deflate decompression cause connections to reset.

This issue occurs when all of the following conditions are met:

  • You are using hardware compression.
  • A compression request asks for an inflate operation.
  • The request is terminated while an incomplete deflate block is not completely processed.

Impact

Connections may reset, which cause sessions to fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Affected connections reset.
  • Repeated error messages display in the /var/log/ltm file that appear similar to the following example:

    01010025:2: Device error: n3-compress1 Zip engine ctx eviction (comp_code=4): ctx dropped.

Resolution

Status

Workaround

To work around this issue, you can avoid using hardware compression by using COMPAT ciphers instead of NATIVE ciphers. For more information, refer to K13163: SSL ciphers supported on BIG-IP platforms (11.x - 13.x).

Impact of workaround: Using software compression over hardware compression may have a significant impact on CPU compression performance.
