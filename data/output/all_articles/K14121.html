Known Issue

The Traffic Management Shell (tmsh) utility does not include the option to target an interface as the management route destination.

For example, using the bigpipe utility in BIG-IP 10.x, you can target an interface as a destination when creating a management route. For example, note the bigpipe command in the following command syntax:

bigpipe mgmt route <IP-Address>/<IP-Netmask or Network-Bits> { <Target-Interface> }

For example, to configure a management route with 10.1.1.0/24 to use mgmt as the target interface, you would type the following command:

bigpipe mgmt route 10.1.1.0/24 { mgmt }

There is no equivalent for the previous command in tmsh.

Impact

  • You are unable to create a management route target to an interface using the tmsh utility.
  • Post upgrade, the configuration fails to load, and the BIG-IP system may be in an offline state.

Note: This issue does not affect BIG-IP system access by way of the management port configuration IP address.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After you upgrade, the configuration loads with error messages that appear similar to the following example:

    01070750:3: Route gateway address does not match destination's address type (inet vs. inet6).
    Unexpected Error: Loading configuration process failed.

  • After you upgrade, the system adds the affected management route. However, the management route does not use the mgmt interface as the route target. You can see this if you type the following command syntax:

    tmsh list /sys management-route <IP-Address>/<IP-Netmask or Network-Bits>

    For example, if you configured a management route with 10.1.1.1.0/24 using the mgmt interface as the route target in a version 10.x configuration, then after upgrading to the affected version, the management route output may appear similar to the following example:

    [root@bigip:Active] config # tmsh list /sys management-route 10.1.1.0/24
    sys management-route 10.1.1.0/24 {
        network 10.1.1.0/24
    }

Workaround

None. There is no workaround for this issue, because there is no equivalent command for configuring an interface type management route using tmsh. However, you may need to configure a management route that references a default gateway as the target. To do so, refer to K13284: Overview of management interface routing (11.x).

Removing the affected management route

If you have upgraded the BIG-IP system to the affected version, and the configuration is unable to load, the workaround is to remove the management route that uses interface as target. To remove the affected management route, perform the following procedure:

Impact of workaround: None.

  1. Back up a copy of the /config/bigip_base.conf file that you are about to modify, using the following command syntax:

    cp -a /config/bigip_base.conf /<Directory-Path>/<Backup-Filename>

    For example, to save a copy as /shared/tmp/bigip_base.conf.SOL14121, you would type the following command:

    cp -a /config/bigip_base.conf /shared/tmp/bigip_base.conf.SOL14121

  2. Use an editor to modify the contents of the /config/bigip_base.conf file.
  3. Look for the line where the affected management route is configured, and remove the stanza.

    For example, if you configured a management route 10.1.1.0/24 in version 10.x, and rolled the configuration forward to the affected 11.x version, the stanza that you should remove would look similar to the following example:

    sys management-route 10.1.1.0/24 {
          network 10.1.1.0/24
    }

  4. If you have more than one management route that is affected by this issue, repeat Step 3.
  5. Save the changes,  and exit the editor.
  6. Load the configuration by typing the following command:

    tmsh load /sys config

    After you load the configuration, the BIG-IP system slowly resumes its services and is available with the appropriate system status.
  7. You can verify that the configuration no longer contains the affected management routes by typing the following command:

    tmsh list /sys management-route
