Known Issue

Description

The BIG-IP APM system may incorrectly use DNS AAAA/A queries instead of DNS SRV records to locate a KDC for a domain.

This issue occurs when the following condition is met:

  • The Domain Controller field in the AAA server configuration is empty.

Active Directory uses DNS SRV records to locate KDCs for a given domain. When querying DNS for a KDC, Active Directory uses the DNS SRV record type _kerberos.tcp.domain.example.com. However, if the BIG-IP APM system uses DNS AAAA/A queries, the DNS resolution may resolve to a server that does not host the KDC service.

Impact

User authentication may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Users receive an error message that appears similar to the following example:

    The username or password is not correct. Please try again.

  • Session variable session.ad.last.errmsg contains an error message that appears similar to the following example:

    Cannot contact any KDC for realm '<domain>', principal name: <username>@<domain>.
    Please verify Active Directory and DNS configuration.

    In the previous error message, note the following :

    - <username> is the logon name.

    - <domain> is the name of the AD domain.

    For example:

    Cannot contact any KDC for realm 'ad.example.com', principal name: <joe@ad.example.com>. Please verify Active Directory and DNS configuration.

  • The log file /var/log/apm contains an error message that appears similar to the following example:

    apd[<pid>]: 01490107:3: <sid>: AD module: authentication with '<username>' failed in krb5_get_init_creds_password(): Cannot contact any KDC for realm '<domain>', principal name: <username>@<domain>. Please verify Active Directory and DNS configuration. (-1765328228)

    In the previous error message, note the following:

    - <pid> is the process ID

    - <sid> is the user session ID

    - <username> is the logon name

    - <domain> is the name of the AD domain

Workaround

To work around this issue, you can specify the FQDN or IP address of a domain controller to use for authentication. To do so, perform the following procedure:

Impact of workaround: Specifying a single KDC limits authentication to that single server. >

  1. Log in to the Configuration utility.
  2. Click Access Policy.
  3. Click AAA Servers.
  4. Click the name of the AAA server to which you want to add the domain controller information.
  5. Enter the FQDN or IP address of the domain controller in the Domain Controller field.
  6. Click Update.
  7. Click Apply Access Policy in the upper left corner.
  8. Click the Apply Access Policy button.
