Description

Restrict iControl REST connectivity on all the platforms.  Already followed the procedure in K69354049, and on a VIPRION the iptables entries only apply to the primary blade.

Environment

  • BIG-IP LTM
  • VIPRION
  • iptables

Cause
When you run a command in a VIPRION appliance without clsh the command is only applied to the primary blade

Recommended Actions

Impact of Procedure: F5 device will NOT be discoverable via Management Port.
  1. Log in to the command line with the root account.
  2. Run below commands to disable port.

    # clsh --slot=1,2,3 iptables -A INPUT -p udp --dport 4353 -d <managment-ip> -j DROP -m comment --comment " 'My Test Comment' "
    # clsh --slot=1,2,3 iptables -A INPUT -p tcp --dport 4353 -d <managment-ip> -j DROP -m comment --comment " 'My Test Comment' "
    # clsh --slot=1,2,3 service iptables save

  3. Verify for disabled port by running command :
    # clsh --slot=1,2,3 iptables -L
  4. To Rollback and enable the port. 
    # clsh --slot=1,2,3 iptables -D INPUT -p udp --dport 4353 -d <managment-ip> -j DROP -m comment --comment " 'My Test Comment' "
    # clsh --slot=1,2,3 iptables -D INPUT -p tcp --dport 4353 -d <managment-ip> -j DROP -m comment --comment " 'My Test Comment' "
    # clsh --slot=1,2,3 service iptables save
  5. Verify by doing telnet management IP address on port 4353
    # telnet <management IP address> 4353

Additional Information

iQuery port is used in DNS TCP port 4353 must be allowed between BIG-IP GTM systems. BIG-IP DNS synchronization group members use TCP port 4353 to communicate.
