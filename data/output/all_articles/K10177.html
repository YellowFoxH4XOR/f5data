Topic

Prior to BIG-IP 10.2.1 HF2, the BIG-IP system buffers a single packet for a destination resource when no Address Resolution Protocol (ARP) entry exists for the destination IP address. Beginning in BIG-IP 10.2.1 HF2, the BIG-IP system buffers four packets for a destination resource when no ARP entry exists for the destination IP address. This behavior applies to virtual server traffic processing and administrative traffic. For example, when the BIG-IP system is configured to send outbound administrative traffic (such as syslog or SNMP traps), SNMP trap packets may be missing, or messages on the remote syslog server may be missing.

Note: Reliable transport protocols, such as TCP, are generally not affected by this behavior; however, packet loss issues with unreliable protocols, such as UDP, may occur.

Virtual server traffic

This behavior applies to virtual server traffic processing. For example, prior to 10.2.1 HF2, when the BIG-IP system processes a packet destined for a virtual server address, and no ARP entry exists for the destination resource, the BIG-IP system buffers the packet and sends out an ARP broadcast. If the BIG-IP system receives another packet for the same destination before it receives the ARP reply from the resource, the BIG-IP system drops the previously queued packet and retains the most recent one. Once the BIG-IP system receives the ARP response from the destination resource, it continues processing the request. Beginning in 10.2.1 HF2, the BIG-IP system behaves exactly like the aforementioned example, except it retains the four most recent packets instead of one.

Administrative traffic

This behavior also applies to cases in which the BIG-IP system is configured to send outbound administrative traffic. For example, prior to 10.2.1 HF2, when the BIG-IP system is configured to send syslog messages to a remote syslog server, and no ARP entry exists for the remote server, the BIG-IP system buffers up to one syslog packet while the ARP request is pending. If the BIG-IP has an additional syslog packet to send before it receives the ARP reply from the remote server, the BIG-IP system drops the previously-queued syslog packet and retains the most recent one. Once the BIG-IP system receives the ARP response from the server, the BIG-IP system continues processing the request. Beginning in 10.2.1 HF2, the BIG-IP system behaves exactly as the aforementioned example, except it buffers up to four syslog packet instead of one.

Modifying the number of packets to be buffered while an ARP request is pending

You can change the number of packets to be buffered while an ARP request is pending, from the default of 4 to a value between 1 and 16. To do so, perform the following steps:

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To change the number of packets that the BIG-IP system buffers for a destination resource when no ARP entry exists for the destination IP address, use the following syntax:

    modify /sys db tmm.nbr.queue value <number_1-16>

  3. Save the change by typing the following command:

    BIG-IP 10.1.0 and later:

    save sys config

    BIG-IP 10.0.x:

    save config
