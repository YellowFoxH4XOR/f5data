Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP configuration uses local traffic policies and virtual server-assigned iRules.
  • You want to disable an iRule from processing or stop all iRules assigned to a virtual server from processing after application of a local traffic policy.

Description

A local traffic policy cannot enable or disable the execution of iRules assigned to a virtual server. In some scenarios, you may want to enable or disable iRule processing after applying a local traffic policy to virtual-server traffic. To work around this local traffic policy limitation, you can use the local traffic policy rule set variable to set a specific variable and value. iRules can obtain the variable and value to determine if the iRule, an iRule sub-context, or subsequent iRules assigned to the virtual server process the request.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the Configuration utility.
  • You have a general understanding of iRules.

Procedures

  • Add a local traffic policy rule with the variable assign setting
  • Use a custom iRule to verify the local traffic policy-assigned variable value

Add a local traffic policy rule with the variable assign setting

You can create a local traffic policy and add a rule set action to assign a variable with a unique value when there is a policy match. The following procedure creates a local traffic policy which checks the client request for a specific URL ending. When the URL matches the policy, the policy assigns the variable (in the example: noRules) with a unique value of the requesting client IP address and source port.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Set the match conditions

  1. Go to Local Traffic > Policies > Policy List.
  2. Select Create.
  3. Enter a policy name.
  4. Select Create Policy.
  5. For Rules, select Create.
  6. Enter a rule name.

    For example:

    url_policy

  7. Expand Match all of the following conditions.
  8. Select HTTP URI.
  9. Select path.
  10. Select ends with.
  11. Select any of.
  12. Enter the ending you want the policy to check for and select Add.

    For example:

    xyz.html

  13. Select request.

The result for this example appears as follows:

HTTP URI path ends with any of xyz.html at request time.

Set the matched action

  1. Expand Do the following when the traffic is matched.
  2. Select Set variable.
  3. After named, enter a unique variable name.

    For example:

    noRules

  4. After equal to, enter a unique session value.

    For example:

    [client_addr].[client_port]

  5. Select a value that indicates that the virtual server iRule should not execute.

    For example:

    request

    Note:This policy rule is simplified for demonstration purposes.

    The result for this example appears as follows:

    Set variable named noRules equal to [client_addr].[client_port] at request time.

  6. Select Save.
  7. Go to Local Traffic > Policies > Policy List.
  8. In Draft Policies select the check box for the new policy.
  9. Select Publish.

Local traffic policy example

ltm policy url_policy {
requires { http }
rules {
match_xyz.html {
actions {
0 {
tcl
set-variable
expression [client_addr].[client_port]
name noRules
}
}
conditions {
0 {
http-uri
path
ends-with
values { xyz.html }
}
}
}
}
status published
strategy first-match
}

Note: In the previous example, the request must be HTTP and the destination URL /xyz.html. When these match, the policy sets the noRules variable.

Use a custom iRule to verify the local traffic policy-assigned variable value

Using the expected local traffic policy variable, an iRule can retrieve the unique, assigned variable value to determine iRule processing of the request. When the policy variable exists and the variable value matches the expected value the current iRule or the subsequent virtual server assigned, or both, the system does not process iRules against the request.

The following procedure creates a custom iRule that verifies that the policy variable is present and that the value of the variable matches the expected unique combination of the client IP address and port. When these values match, processing of this iRule and subsequent iRules for the virtual server is disabled using the iRules event event disable all. To have the system stop processing of only the current iRule, you can use the return event instead of the event disable all event. Using the return event allows any subsequent iRules assigned to the virtual server to process the request.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > iRules > iRule List.
  2. Select Create.
  3. Enter a name for the iRule.
  4. For Definition, enter your iRule definition stanza

    For example, the following example shows an iRule using the event disable all event:

    when HTTP_REQUEST {
    ## Check that the variable exist
    if {[info exists noRules]} {
    set clientData [client_addr].[client_port]
    log local0. "Policy variable noRules = $noRules same as [client_addr].[client_port]"
    if {$noRules equals $clientData} {
    ## Variable exists stop all rule processing for the request using event disable all
    event disable all
    unset noRules
    unset clientData
    }
    }
    }

    Note: In this example, when the system checks the local traffic policy variable noRules to see if it exist. It then checks the variable value against the clients IP address and source port set by the policy. When the variable matches the known client IP address and source port combination, the iRule and subsequent iRules assigned to the virtual server do not process the request due to the event disable all event.

    The following example shows an alternate iRule using the return event:

    when HTTP_REQUEST {
    ## Check that the variable exist
    if {[info exists noRules]} {
    set clientData [client_addr].[client_port]
    log local0. "Policy variable noRules = $noRules same as [client_addr].[client_port]"
    if {$noRules equals $clientData} {
    ## Variable exists stop processing of the rule using the return event
    return
    unset noRules
    unset clientData
    }
    }
    }

    Note: In this example, when the system checks the local traffic policy variable noRules to see if it exist, the system checks the value against the clients IP address and source port set by the policy. When the variable matches, the known client IP address and source port combination processing for the iRule stops, using the return event; however, any subsequent iRules assigned to the virtual server continue to process the request.

  5. Select Finished.
  6. Got to Local Traffic > Virtual Servers > Virtual List.
  7. Select the check box of the virtual server to which you want to apply the new local traffic policy and virtual server.
  8. Select the Resources tab.
  9. For iRules, select Manage.
  10. Select the newly created iRule from the Available list and move it to the Enabled list.

    Important: Ensure that the iRule appears first in the Enabled list by selecting the iRule and selecting Up to move it to the top of the list.

  11. Select Finished.
  12. For Policies, select Manage.
  13. Select the check box for the new local traffic policy in the Available list and move it to the Enabled list.
  14. Select Finished.
