K000160629: F5OS-C 1.8.1: Tenant image bundle (.tar.bundle) auto-syncs to tenant /shared/images and cannot be completely deleted

Type
Support Solution
Published
2026-04-06
Updated
2026-04-06
Applies to
  • F5OS
  • F5OS-C: 1.8.1
Source
https://my.f5.com/manage/s/article/K000160629

Description

When a BIG-IP tenant image bundle file (.tar.bundle) is uploaded to the [Tenant Images] section of the F5OS-C chassis partition, the file is automatically replicated to the /shared/images directory on all tenant blades. Attempts to delete the file from within the tenant using standard file deletion commands (such as rm) result in the file reappearing after a short period.

Environment

  • Product: F5OS-C (Chassis Partition)
  • Platform: VELOS CX410 (multi-blade system)
  • Software Version: F5OS-C 1.8.1
  • Tenant Software: BIG-IP 17.5.1.3, 17.5.1.4
  • File Types: .tar.bundle (current), .qcow2.zip.bundle (deprecated)
  • Configuration: Multiple blades, some may be disabled or physically removed
  • Actions: Uploading tenant image bundles via partition GUI, deleting files via tenant shell or GUI

Cause

  • The .tar.bundle file format is designed to be automatically distributed to /shared/images on all active tenant blades when uploaded to the partition's [Tenant Images] section.
  • All Blades were active when new image is uploaded but deletion is only attempted after 1 of the blade is disabled.
  • Deleting the file from only one blade or from within the tenant does not remove it from all blades, causing it to reappear due to synchronization.
  • The clsh command only affects active/enabled blades; files may persist on disabled or removed blades.

Answer/Recommended Actions

To completely remove a .tar.bundle file from all tenant blades:

  1. Ensure all blades assigned to the tenant are active/enabled. If any blades are disabled or physically removed, re-enable or reinsert them.
  2. From within the tenant's bash shell, run the following command to delete the file across all active blades:
    clsh rm /shared/images/BIGIP-<version>.tar.bundle
    Replace <version> with the actual file name.
  3. If there are hidden temporary files (e.g., .BIGIP-<version>.tar.bundle.*), delete them as well:
    clsh rm /shared/images/.BIGIP-<version>.tar.bundle.*
  4. Verify deletion with:
    clsh ls -al /shared/images/
  5. If some blades remain inactive or removed, the file may persist on those blades and could reappear if they are reactivated or reinserted. In such cases, use:
    clsh --color=red,green rm /shared/images/BIGIP-<version>.tar.bundle
    (Refer to F5 KB K16727 for details on targeting inactive blades.)

Additional Information

  • The automatic replication of .tar.bundle files to /shared/images on all tenant blades is expected behavior by design for F5OS-C.
  • The .qcow2.zip.bundle format is deprecated and will not be distributed in the same way; only .tar.bundle files are supported for new tenant image deployments.
  • Deleting the file from the partition GUI only removes it from the GUI listing, not from the tenant file systems.
  • Complete deletion requires that all blades are active and included in the clsh command scope.
  • The /shared/images directory is synchronized between blades on the tenant; any file created on one blade will be synchronized to other active blades.
