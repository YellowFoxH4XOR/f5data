Description

One or more certificates are replaced/swapped using the GUI or CLI causes TMM to core.
Running configsync to peer after replacing/swapping SSL certificates cause the peer device TMM to core.
 

Environment

  • BIG-IP
  • v13.* and later
  • Platform with non-RAID HDD
  • Certificate replace/swap
  • configsync
     

Cause
Bug ID829317
Bug ID809597

Certificate replace cause high iops and non-raid HDD could not cope with while icrd_child memory leak was causing excessive disk thrashing.
The memory leak affect is more impacting when available host memory is low.
 

Recommended Actions

There are two possible options.

if icrd_restart restjavad
tmsh restart sys service restjavad
Note: This will not affect the processing traffic.

If, tmm memory usage is much lower than it is allocated, then allocate more memory to userland process, the value is depending on your system usage.
tmsh modify sys db provision.extramb value <*MB>
Important: This command will restart tmm and trigger a failover.
Note: <*MB> is the amount of extra memory you wish to allocate in megabytes.
