Topic

All CORBA servers communicate through the ITCMPortal on the loopback address 127.0.0.1; therefore, the respective ports they listen on are not exposed to external networks. Only the ports used by the ITCMPortal process (683 & 684) are exposed to the external network.

Note: You can choose to lock these ports down by using the b global open_corba_ports disable command, however you will not be able to access the ITCMPortal, nor perform any iControl requests, once you have disabled the ports.

BIG-IP and 3-DNS have CORBA servers running as daemon processes to support remote iControl query and management requests. These requests often contain a specific iControl interface. Following are details about the various iControl interfaces and their relationship to these CORBA servers. For additional information about each interface, refer to the iControl SDK documentation.

ITCMPortal

Listens on ports 683 (IIOP) and 684 (IIOPS).
Supports the following interfaces:

  • Portal
  • Access
  • Registration

LocalLBServer

Listens on port 1515.
Supports the following interfaces:

  • AuthorizationModel
  • Class
  • Connections
  • Failover
  • Global
  • Monitor2
  • NAT
  • Node
  • Pool
  • Proxy
  • Rule
  • Service
  • SNAT
  • Version
  • VirtualServer

ITCMSystemServer

Listens on port 1616.
Supports the following interfaces:

  • Inet
  • Services
  • SystemInfo
  • ConfigSync

ITCMNetworkingServer

Listens on port 1717.
Supports the following interfaces:

  • VLAN
  • Interfaces
  • SelfIP
  • Trunk
  • PortMirror
  • SpanningTree

ITCMManagementServer

Listens on port 1818.
Supports the following interfaces:

  • Bigdb
  • SNMPConfiguration

3dnsd

(This daemon supports iControl Global load balancing functionality.)
Listens on port 2121.
Supports the following interfaces:

  • Globals
  • DataCenter
  • SyncGroup
  • BaseServer
  • Statistics
  • Topology
  • Wideip
  • Link
