Issue

If the time zone on a client machine differs from the FirePass controller's time zone, or if the client machine or FirePass controller experiences significant time drift, the user may receive the following error message:

My.activation.php3 - client data is invalid ! (2)
checkToken() failed - token is expired (delta=-28)

In addition, the user may fail to successfully connect. This issue may occur when the FirePass controller is part of a cluster that has load balancing enabled and FirePass is not the master controller.

To resolve this issue, ensure that the client machine and the FirePass controller are using the same time zone and are using Network Time Protocol (NTP) to avoid time drift. If your FirePass cluster spans multiple time zones and you repeatedly see this error message, consider using GMT time for the client's machine and your FirePass controller.

Configuring the time zones and configuring NTP on the FirePass controllers

Note: You must complete the following procedure for all of your FirePass controllers.

  1. Log in to the FirePass Administrative Console.
  2. Navigate to Device Management > Configuration >Time.
  3. In the NTP Time section, populate the New NTP server field with either the fully qualified domain name or the IP address of the NTP server you want to use.
  4. Click Apply.

    A blank web page displays.
  5. Navigate to Device Management > Configuration > Time.
  6. From the Currently Selected Time Zone section, select the time zone that is appropriate for both your client machine and your FirePass controller.

    Note: The default value is set to GMT.
  7. Click Apply.

    Note: The time zone configuration change will not be active until the FirePass services have been restarted.
  8. Click the click here to restart the FirePass services link to restart the services.

    Important: Restarting services affects users that are currently logged on. F5 recommends restarting services after hours or during a scheduled maintenance window.
