Troubleshooting BIG-IP APM Webtop Links Not Routing Traffic Through VPN Tunnel

1. Description

This article explains how to resolve an issue where published URL Webtop links in BIG-IP Access Policy Manager (APM) do not route traffic through the VPN tunnel as expected. Symptoms include remote users being unable to access certain resources via the VPN portal, while local LAN access works and some other links function correctly.

2. Environment

  • Product: BIG-IP APM
  • Version: 17.5.1
  • Platform: F5-BIG-APM-VE200MV18, BIG-IP
  • Configuration:
    • Webtop with published URL links and portal access resources
    • Network Access (VPN) for remote connectivity
    • Access Profile with cookie options
    • Virtual servers configured for resource access
  • Recent actions:
    • Creation and assignment of Webtop links and portal access resources
    • Testing of resource access from both LAN and remote VPN clients

3. Cause

The issue occurs when resources are configured as Webtop URL links instead of portal access resources. Webtop URL links do not route traffic through the VPN tunnel, resulting in failed remote access. Portal access resources are required for proper VPN routing.

4. Recommended Actions

  1. Delete the non-working Webtop URL link from the Webtop configuration.
  2. Create a portal access resource for the required application or resource.
  3. Assign the portal access resource to the appropriate branch in the access policy.
  4. Ensure the access policy and resource assignment are published and active.
  5. Test remote access to confirm that traffic is routed through the VPN tunnel and the resource is accessible.

5. Additional Information

  • Disabling "HTTP Only" cookie option in Access Profile may be necessary for some VPN session scenarios.
  • Ensure valid routes exist on BIG-IP for all resources accessed via VPN, including correct return traffic routing.
  • Asymmetric routing or misconfigured connectivity profiles can also prevent proper VPN resource access.
