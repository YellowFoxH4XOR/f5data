K000161543: Error Messages When Modifying GTM Link Object "Foreign key index (explicit_link_FK) do not point at an item that exists in the database"

Description

On BIG-IP DNS (GTM), modifying a GTM Virtual Server to use an explicit link fails and the change is not retained. The system logs an mcpd configuration exception similar to:

01070712:3: Caught configuration exception (0)... foreign key index (explicit_link_FK) do not point at an item that exists in the database

This can result in incorrect GTM service health status (for example, when a link goes down).

Environment

  • GTM Link objects

  • GTM Server objects with device addresses that reference an explicit link name

  • GTM Virtual Server configured/modified to use an explicit link

Cause

A malformed GTM Link object name containing quotation marks and/or trailing whitespace (for example, gtm link "<link_name> " { ... }). This causes the configuration database reference for the explicit link (explicit_link_FK) to fail because the referenced link object name cannot be resolved as a valid existing object.

For example, this problematic configuration, the link was configured with quotation marks ("") and an additional space within the quotes.

gtm link "/Common/link_name " {
    datacenter /Common/DC
    monitor /Common/bigip_link
    router-addresses {
        10.10.10.1 {
            device-name "/Common/link_name "
        }
    }
}

It should be like below example:

gtm link /Common/link_name {
    datacenter /Common/DC
    monitor /Common/bigip_link
    router-addresses {
        10.10.10.1 {
            device-name /Common/link_name
        }
    }
}

Recommended Actions

  1. Identify the malformed GTM link name (quotes and/or trailing spaces) in the GTM configuration. Common indicators include link stanzas such as:

    • gtm link "link_name " { ... }

    • device-name "link_name " (within the link’s router-addresses)

  2. Edit bigip_gtm.conf to correct the GTM link object name by removing quotation marks and any extra spaces so the link name is a clean, unquoted identifier. For example:

    • vim /config/bigip_gtm.conf

    • Fix the affected gtm link by removing quotes/trailing whitespace.

  3. Reload the GTM configuration:

    • tmsh load sys config gtm-only

  4. Re-attempt the GTM Virtual Server explicit link change and confirm the mcpd error no longer occurs.

Additional Information

  • This issue is typically introduced by unsupported/manual configuration edits that add quoting and/or trailing whitespace to object names. Creating/managing GTM Link objects using supported GUI/TMSH workflows should avoid introducing this malformed naming.
