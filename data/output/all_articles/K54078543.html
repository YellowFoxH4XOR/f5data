Description

When a BIG-IP with 8GB RAM (or less) is provisioned for LTM, ASM, and another module, such as APM, AFM, AVR, simultaneously the system may show dangerously high memory usage That could lead to oom-killer events or other performance issues.  

The "tmsh /show sys memory" usually shows only a fraction of the available TMM memory currently in use. However, this memory is reserved for tmm only leaving those other processes to fight over the scarce remaining memory and swap. K16419: Overview of BIG-IP memory usage  covers how this is all allocated.

Environment

  • BIG-IP v11.* and later.
  • BIG-IP has 8GB RAM or less.
  • LTM, ASM and another modules is licensed and provisioned.
     

Cause

When LTM is provisioned a majority of memory is reserved for TMM, but ASM and other modules daemon's may require more memory.
 

Recommended Actions

If tmm memory usage itself is low, then when a unit with 8GB of RAM (or less) has both ASM and APM provisioned, then LTM can be provisioned as None or Minimum.  ASM and APM should be provisioned as Nominal.
Procedure is in K17173140: Setting LTM Provision NONE does not disable licensed LTM functionality.

Note: LTM None provisioning does not turn off licensed LTM functionality.

Note: If a unit is configured to use iApps, that enforce an LTM provisioning requirement, then when possible they should be modified to remove this requirement before changing the LTM provisioning.

Note: Because of kernel changes in version 13, swap reporting was changed from earlier versions.  Units with only 8GB of RAM will frequently show high swap under normal conditions, even after changes in provisioning.  A better indicator than the graphs as to readily freeable memory is the MemAvailable statistic in the /proc/meminfo output.
