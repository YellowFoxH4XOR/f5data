Topic

You should consider using this procedure under the following condition:

  • You want to configure the BIG-IP system to selectively compress content.

Description

You can configure the BIG-IP system to selectively compress content based on conditions that you specify using local traffic policies or iRules. For example, you can specify that the BIG-IP system compress only content in responses containing certain HTTP headers.

When you configure selective compression, you assign an HTTP compression profile to the virtual server. The compressed content is determined by the conditions in the local traffic policy or iRule, not the HTTP compression profile. To configure selective compression on the BIG-IP system, perform the following procedures:

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have a virtual server configured with an HTTP profile.
  • You have administrative access to the Configuration utility.

Procedures

  • Create an HTTP compression profile and assigning it to a virtual server
  • Create a HTTP compression profile and assign to a virtual server using tmsh
  • Configure the BIG-IP system to perform selective compression
  • Configure the BIG-IP system to perform selective compression using tmsh
  • Configure selective compression using an iRule with tmsh

Create an HTTP compression profile and assigning it to a virtual server

For the BIG-IP system to perform selective compression, you must create an HTTP compression profile with the Selective Compression feature enabled and assign the profile to a virtual server. To do so, perform the following procedure:

Impact of procedure: Enabling compression may increase CPU utilization and impact performance.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > Profiles > Services > HTTP Compression.
  3. Select Create.
  4. Enter a profile name.
  5. In the Custom column, select the Selective Compression setting check box.
  6. Select Finished.
  7. Go to Local Traffic > Virtual Servers.
  8. Select the name of the virtual server.
  9. For Acceleration, select the profile you just created for HTTP Compression Profile.
  10. Select Update.

Create a HTTP compression profile and assign to a virtual server using tmsh

For the BIG-IP system to perform selective compression, you must create an HTTP compression profile with Selective Compression enabled and assign the profile to a virtual server. To do so, perform the following procedure:

Impact of procedure: Enabling compression may increase CPU utilization and impact performance.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Create the HTTP compression profile using the following command syntax.

    create /ltm profile http-compression <profile name> { defaults-from httpcompression selective enabled }

    Note: Replace <profile name> with the name for the new HTTP Compression profile.

    For example:

    create /ltm profile http-compression tmsh_made_compression_profile { defaults-from httpcompression selective enabled }

  3. Assign the HTTP compression profile to a virtual server using the following command syntax:

    modify /ltm virtual <virtual server name> profiles add { <compression profile name> }

    Note: Replace <compression profile name> with the name specified in the previous procedure step.

    For example:

    modify /ltm virtual http_vs profiles add { tmsh_made_compression_profile }

  4. Save the configuration by entering the following command:

    save /sys config partitions all

  5. To exit tmsh enter the following command:

    quit

Configure the BIG-IP system to perform selective compression

You can specify the content to be compressed by the BIG-IP system using either local traffic policies or using iRules. To do so, perform one of the following procedures:

  • Configure selective compression using local traffic policies
  • Configure selective compression using an iRule

Configure selective compression using local traffic policies

You can configure local traffic polices to perform compression based on conditions you specify. For example, you can configure a local traffic policy to compress the response when the HTTP Content-Type header in the response begins with the string text/. To do so, perform the following procedure:

Impact of procedure: Enabling compression may increase CPU utilization and impact performance.

BIG-IP 12.1.0 and later

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies > Policy List.
  3. Select Create.
  4. Enter a name for the policy.
  5. For Strategy, select first.
  6. Select Create Policy.
  7. For Rules, select Create.
  8. Enter a name for the iRule.
  9. Select the add icon (+) next to Match all of the following conditions.
  10. Select HTTP Header.
  11. For named, enter Content-Type.
  12. Select begins with.
  13. Select any of.
  14. Enter text/ and select Add.
  15. Select response.

    The resulting condition should appear similar to the following example:

    HTTP Header named Content-Type begins with any of text/ at response time.

  16. Select the add icon (+) next to Match all of the following conditions.
  17. Select CPU Usage.
  18. Forin the last, select 1 minute.
  19. Select less than or equal to.
  20. Select any of.
  21. Enter 5 and select Add.
  22. Select response.

    The resulting condition should appear similar to the following example:

    CPU Usage in the last 1 minute less than or equal to any of 5 at response time.

  23. Select the add icon (+) next to Do the following when the traffic is matched.
  24. Select Enable.
  25. Select compression.
  26. Select response.

    The resulting action should appear similar to the following example:

    Enable compression at response time.

  27. Select Save.
  28. To save the new rule and policy, under General Properties, select Save Draft. To save the rule and policy for immediate use, select Save and Publish Policy.
  29. Go to Local Traffic > Virtual Servers.
  30. In the Resources column, for the virtual server with the security policy, select Edit.
  31. Under Policies, select Manage.
  32. In the Available list, select the local traffic policy you created in previous steps and move it to the Enabled list.
  33. Select Finished.

BIG-IP 12.0.0 and earlier

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > Policies > Policy List.
  3. Select Create.
  4. Enter a policy name.
  5. For Strategy, select first-match.
  6. For Requires, from the Available list, select http and move it to the Selected list.
  7. For Controls, from the Available list, select compression and move it to the Selected list.
  8. For Rules, select Add.
  9. Enter a rule name.
  10. Under Rule Properties, for Conditions , configure the settings as follows:
    • Operand: http-header
    • Event: response
    • Selector: all
    • Parameters: Name: name*
    • Parameters: Value: Content-Type (select Add to add it to the List)
    • Condition: starts-with
    • Values: Value: text/ (select Add to add it to the List)
  11. Select Add to add the settings to the Conditions table.
  12. For Actions, configure the following settings:
    • Target: compress
    • Event: response
    • Action: enable
  13. Select Add to add the settings to the Action table.
  14. Select Finished to save the rule and policy.
  15. Go to Local Traffic > Virtual Servers.
  16. In the Resources column, for the virtual server with the security policy, select Edit.
  17. Under Policies , select Manage.
  18. From the Available list, select the local traffic policy you created in previous steps and move it to the Enabled list.
  19. Select Finished.

Configure selective compression using an iRule

You can create an iRule to perform selective compression using the COMPRESS:: enable command. The BIG-IP system compresses content in the response based on conditions you specify in the iRule. For example, you can configure an iRule to compress the response when the HTTP Content-Type header in the response begins with the string text/. To do so, perform the following procedure:

Note: When using the COMPRESS:enable request iRule command to compress the body of a request, you must enable Selective for the Request Chunking setting in the HTTP profile.

Impact of procedure: Enabling compression may increase CPU utilization and impact performance.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Enter a name for the iRule.
  5. For Definition, enter the following:

    when HTTP_RESPONSE {
    COMPRESS::disable
    if { [HTTP::header "Content-Type"] starts_with "text/"} {
    COMPRESS::enable
    log local0. "Compressing text file."
    }
    }

  6. Select Finished.
  7. Go to Local Traffic > Virtual Servers.
  8. In the Resources column for the virtual server with the security policy, select Edit.
  9. Under iRules, select Manage.
  10. From the Available list, select the iRule you created in previous steps and move it to the Enabled list.
  11. Select Finished.

Configure the BIG-IP system to perform selective compression using tmsh

You can configure local traffic polices to perform compression based on conditions you specify using tmsh. The following procedure example, configures a local traffic policy to compress the response when the HTTP Content-Type header in the response begins with the string text/.

Impact of procedure: Enabling compression may increase CPU utilization and impact performance.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Use the following command syntax to create a draft traffic policy as outlined in the previous Configuration utility procedure:

    create /ltm policy /<partition>/Drafts/<policy name> { controls add { compression } requires add { http } rules add { <rule name> { actions add { 1 { decompress response enable } } conditions add { 1 { http-header response name Content-Tyoe starts-with values { <content type>/ } } 2 { cpu-usage response last-1min less-or-equal values { <numeric value as percentage> } } } } } }

    Note: Replace <partition> with the partition name that the policy draft is located, and replace <rule name> with a name for the policy rule, and replace <content type>/ with the expect content type returned by the server that you want to compress (in the example text/). Replace <numeric value as percentage> with a numeric value for the amount of CPU utilization percentage of the BIG-IP system at that time.

    For example:

    create /ltm policy /Common/Drafts/tmsh_compression_policy { controls add { compression } requires add { http } rules add { text_check { actions add { 1 { decompress response enable } } conditions add { 1 { http-header response name Content-Tyoe starts-with values { text/ } } 2 { cpu-usage response last-1min less-or-equal values { 5 } } } } } }

  3. Configure the strategy of the policy to use first-match using the following command syntax:

    modify /ltm policy /<partition>/Drafts/<policy name> strategy <strategy>

    Note: Replace <partition> with the partition name that the policy draft is located, and replace <strategy> with the strategy option (all-match, best-match, first-match).

    For example:

    modify /ltm policy /Common/Drafts/tmsh_compression_policy strategy first-match

  4. Publish the policy for use with the following command syntax:

    publish /ltm policy /<partition>/Drafts/<policy name>

    Note: Replace <partition> with the partition name in which the policy draft is located.

    For example:

    publish /ltm policy /Common/Drafts/tmsh_compression_policy

  5. Configure a virtual server with the new policy using the following syntax:

    modify /ltm virtual /<partition>/<virtual server name> policies add { /<partition>/<compression policy name> }

    Note: Replace <partition> with the name of the partition where the virtual server and compression profile resides, and replace <virtual server name> with the name of the virtual server you to which want to apply the new compression policy.

    For example:

    modify /ltm virtual /Common/http_vs policies add { tmsh_compression_policy }

  6. Save the configuration by entering the following command:

    save /sys config partitions all

Configure selective compression using an iRule with tmsh

You can create an iRule using tmsh to perform selective compression using the COMPRESS:: enable command.

Impact of procedure: Enabling compression may increase CPU utilization and impact performance.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create a custom iRule with the following syntax:

    create /ltm rule <rule name>

    Note: Replace <irule name> with the desire name for the iRule.

    For example:

    create /ltm rule text_compression

  3. The iRules definition opens in the vi text editor.
  4. Between the opening and closing braces, enter the definition syntax similar to the following example:

    when HTTP_RESPONSE {
    COMPRESS::disable
    if { [HTTP::header "Content-Type"] starts_with "<content type>/"} {
    COMPRESS::enable
    log local0. "Compressing text file."
    }
    }

    Note: Replace <content type> with the content type for which you want to enable compression.

    For example:

    when CLIENT_ACCEPTED {
    set sourceip [IP::client_addr]
    set mapped_snat [class lookup $sourceip SNAT-Map]
    snat $mapped_snat
    }

  5. To save the configuration and exit the vi text editor, enter the following command:

    Esc:wq

  6. To apply the iRule to the intended virtual server use the following syntax:

    modify /ltm virtual <virtual server name> rules { <irule name> }

    Note: Replace <virtual server name> with the name of the virtual server on which you want to apply selective compression, and replace <irule name> with the name of the iRule created in the previous step.

    For example:

    modify /ltm virtual my_vs rules { text_compression }

  7. Save the configuration changes by entering the following command:

    save /sys config partitions all
