Known Issue

This is the result of a known issue. FTP virtual servers may report incorrect or reversed statistics when Active FTP mode is used.

When Active FTP mode is used, the client issues a port command to open a data channel. The mcpd process incorrectly reverses the statistics reported by the virtual server.

For example, when an FTP client issues a GET request for a 10MB file, a port command is sent to establish the data channel. The statistics reported are reversed, bytes out for the virtual server are minimal, and the bytes in will be approximately the same size as the file requested.

Note: When Passive FTP mode is used, the statistics are reported correctly.

F5 Product Development tracked this issue as ID 226027 and ID 226028 (formerly CR140653 and CR140656), and it was fixed in BIG-IP version 10.2.2. For information about updgrading, refer to the BIG-IP LTM or Link Controller release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.1-473.0-HF1 issued for BIG-IP version 10.2.1, Hotfix-BIGIP-10.1.0-3402.0-HF2 issued for BIG-IP version 10.1.0, and Hotfix-BIGIP-9.4.8-407.0-HF4 issued for BIG-IP version 9.4.8.
