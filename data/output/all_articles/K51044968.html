Description

A message or continuous alert similar to the following example appears in a BIG-IP command line:
# emerg logger: Re-starting alertd

Environment

  • BIG-IP LTM 
  • Continuous messages on CLI of Restarting alertd
  • Changes being performed on user_alert.conf

Cause

A cause is logged in /var/log/ltm stating why it could not process /config/user_alert.conf. It mainly indicates syntax issues in the file. 

Example: 
The BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the below example.  From the /var/log/ltm logs, the user_alert.conf file has been modified and there's a problem with it and it is not loading. 
Mar  6 11:57:52 bigip.example.com err alertd[9353]: 01100021:3: Couldn't process the /config/user_alert.conf: problems at line 167.
Mar  6 11:57:52 bigip.example.com err alertd[9353]: 01100010:3: Couldn't load file /config/user_alert.conf

Recommended Actions
Impact of Procedure: Doing the below workaround should not impact any traffic. 
 
Open the /config/user_alert.conf file and go to the line in question referenced in the /var/log/ltm where the syntax error was seen. 

In the below example, at line 167, there is an extra character "r" after the body.
...
163 alert TEST "Rejecting this request (.*)"  {
164 #snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.152";
165 email toaddress="j.smith@example.com"
166 fromaddress="j.jones@example.com"
167 body="Rejecting this request"r  --------------------------> extra "r" character 
168 }
...

  1. Stop the alertd service:
    # bigstart stop alertd 
  2. Modify the user_alert.conf file via your preferred text editor. Using vi in this example:
    vi /config/user_alert.conf
  3. Go to the particular line in question in the conf file. For vi, press 'i' for insert mode and go to like 167. 
    :167
  4. Remove the extra character that impedes the file-processing: 
    .body="Rejecting this request"r  ------------> delete the "r"
  5. Press escape to enter command mode and save the file.  
    :wq
  6. Start the alertd service: 
    # bigstart start alertd
  7. Check for any logs after restarting the alertd service by typing the below:
    #tail -f /var/log/ltm
