Description

  • With Staging Enabled, when Attack Signatures are updated; multiple versions of updated attack signatures exist - A New and Old Attack Signature.
  • When multiple versions of an attack signature exist, it is difficult to determine the enforcement status.
    • As a result you may encounter unexpected blocking after a signature update, potentially due to new signatures going in to blocking.

Environment

  • BIG-IP ASM
  • ASM Security Policy configured with Signature Staging enabled
  • Attack Signature Update

Cause

When Attack Signature Staging is enabled, having multiple versions of an attack signature is expected behavior within ASM.
Viewing the state of the signatures can be difficult, as there is currently no built in way to view the state of the multiple versions of the attack signature.

Recommended Actions
Before moving Attack Signatures out of staging into an enforced state, you should review the changes to the signature and the potential impact to your environment and applications.

Note: With Attack Signature Staging enabled, the system still enforces the protection of the previous version of updated attack signatures.
When the updated signature is enforced, the previous version is deleted and the new one is enforced instead.

For information about changing Attack Signature status refer to the Assigning Attack Signatures to Security Policies chapter of the BIG-IP Application Security Manager: Attack and Bot Signatures
