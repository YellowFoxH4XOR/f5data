K000093184: Taking a Snapshot of a BIG-IP VIrtual Edition from a hypervisor (eg. VMware ESX, KVM)

Description

You want to take a snapshot of the BIG-IP. What are the effects of doing so? Is it even a good idea?

Per VMWare "Snapshots should not be considered as a backup for any virtual disks associated with the VMs. Running a virtual machine on a snapshot for extended periods of time can cause instability and data loss.


Snapshots can be used for development and testing purposes. It can be considered as a quick failsafe to be able to rollback before a patch performing tests on certain applications residing on VM."

Note: The VMWare link takes you to a resource outside of AskF5, and it is possible that the documents may be removed without our knowledge.

Thus, they are not intended for back up purposes. The only recommended back up method for a BIG-IP is a UCS Archive.

If a Snapshot is attempted you may see log entries such as this in /var/log/ltm...

notice tmm[<PID>]: 01010029:5: Clock advanced by 10893 ticks

sod[<PID>]: 010c0083:4: No failover status messages received for 3.800 seconds, from device BIGIP-A.example.com (192.168.1.3) (unicast: -> 10.10.2.2).

Environment

  • BIG-IP Virtual Edition, One of many hypervisors that perform Snapshots.
  • High Availability
  • There are several issues that may occur if a Snapshot is taken of a running BIG-IP. They include clock advancement, an unexpected failover, an Active/Active state, a complete loss of the VE instance, and others.

Cause

A Snapshot 'freezes' the BIG-IP in time. This interferes with TMM and it loses time. It then has to adjust to catch up. When this happens you will see the log entry previously mentioned.

Note: There are other causes for this log entry so you will need to look into 'why' to be certain.

Since the Snapshot 'freezes' or 'pauses' TMM this prevents real-time access to the CPU. Due to this F5 does not support the Snapshot process being used on a BIG-IP.

Recommended Actions

Creating and archiving backups should be done regularly and prior to any upgrade. The only supported method is to do so via an F5 UCS Archive.

Backups can be set up to be done via BIG-IQ or a Cron job. Doing so via either method can also be setup to have the archive offloaded to storage device in case you lose access to the BIG-IP.
