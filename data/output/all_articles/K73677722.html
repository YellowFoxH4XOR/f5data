Description

You want an BIG-IP LTM pool to go down when another service/device goes down which the actual nodes/pool member of that pool is dependent on.

Environment

  • BIG-IP LTM
  • Pool and LTM Health Monitors

Cause

N/A

Recommended Actions

  1. Create a custom health monitor with an alias address. For example:

    ltm monitor gateway-icmp monitor_dependency {
        adaptive disabled
        defaults-from gateway_icmp
        destination 172.16.1.1:*   <-----!! Alias Address
        interval 5
        time-until-up 0
        timeout 16
    }
  2. Attach the custom health monitor to the pool together with the actual health monitor for the backend member. Make sure that in the Pool Advanced setting 'Availability Requirement' is set to 'All'. It should be 'All' by default.

    ltm pool POOL_TEST {
        members {
            10.1.1.1:http {
                address 10.1.1.1
                session monitor-enabled
            }
        }
        monitor http and monitor_dependency <-----!! Two health monitors attached
    }

Additional Information

By default, the value for the Alias Address setting in the monitors is set to the wildcard * Addresses, and the Alias Service Port setting is set to the wildcard * Ports. This value causes the monitor instance created for a pool, pool member, or node to take that node’s address or address and port as its destination. You can, however, replace either or both wildcard symbols with an explicit destination value, by creating a custom monitor. An explicit value for the Alias Address and/or Alias Service Port setting is used to force the instance destination to a specific address and/or port which might not be that of the pool, pool member, or node.

By configuring and following the steps above, both the actual backend member should respond to the http monitor and the dependency server should respond to the ICMP request (custom health monitor type can be change based on the requirement) so BIG-IP can mark the Pool 'UP'
