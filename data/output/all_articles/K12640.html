Known Issue

This is the result of a known issue. If you configure the HTTP profile RAM Cache URI Caching attribute with an empty Exclude List, the BIG-IP system adds any content within the configured Minimum Object Size and Maximum Object Size to the cache regardless if you configure the Include List to cache content from specific URI.

The following configuration example displays the myhttp-exclude-none HTTP profile configured with an empty Exclude List for URI Caching:

profile http myhttp-exclude-none {
defaults from http-acceleration
ramcache uri exclude none
ramcache uri include ".jpg"
}

Additionally, if you configure the HTTP profile RAM Cache URI Caching attribute with .* in the Exclude List, the BIG-IP system does not add content from any URI to the cache, even if you configure the Include List to cache content from the specific URI.

The following configuration example displays the myhttp-exclude-all HTTP profile configured with .* in the Exclude List for URI Caching:

profile http myhttp-exclude-all {
defaults from http-acceleration
ramcache uri exclude ".\*"
ramcache uri include ".jpg"
}

F5 Product Development is tracked this issue as ID 227220 (formerly CR54077) and it has been fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the BIG-IP LTM, Link Controller, WebAccelerator, or Edge Gateway release notes.

Workaround

You can work around this issue by configuring an iRule using the CACHE::enable and CACHE::disable command with a class of specific items for caching.

The following example displays the mycacherule iRule with the mycacheobjects class:

rule mycacherule {
when HTTP_REQUEST {
if { [matchclass [HTTP::path] ends_with mycacheobjects] } {
CACHE::enable
}
else {
CACHE::disable
}
}
}
class mycacheobjects {
".jpg"
}

In this example, the mycacherule iRule will cache content from any URI ending with .jpg regardless of what is configured in the HTTP profile URI Caching attribute.

Note: Refer to the F5 DevCentral pages regarding the iRules CACHE commands and HTTP events. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

Note: Due to a different issue, the BIG-IP system does not add content to the cache if the CACHE::enable command is invoked from HTTP_RESPONSE event. For more information, refer to K10210: Content is not added to RAM Cache when using the CACHEL::enable iRule command in the HTTP_RESPONSE event.

Adding a class of objects

  1. Log in to the Configuration utility using a privileged account, such as admin.
  2. Click on Local Traffic >> iRules >> Data Group List.
  3. Click the Create button.
  4. Type in the desired name for the class in the Name field.
  5. Select String in the Type drop-down menu.
  6. To add an entry to the class, type in the desired string in the String box and click on the Add button.
  7. Repeat Step 8 to add more entries to the class if desired.
  8. When you have added all entries to the class, click the Finished button.

Adding an iRule

  1. Log in to the Configuration utility using a privileged account, such as admin.
  2. Click on Local Traffic >> iRules.
  3. Click the Create button.
  4. Type in the desired name for the iRule in the Name field.
  5. Type in the iRule syntax in the Definition field.
  6. Click the Finished button.

Associating the iRule to the desired virtual server

  1. Log in to the Configuration utility using a privileged account, such as admin.
  2. Click Local Traffic >> Virtual Servers >> Virtual Servers List.
  3. Click Edit under the Resources column of the desired virtual server.
  4. Click the Manage button for the iRules section.
  5. Highlight the newly created iRule in the Available list box.
  6. Click the << button.
  7. Click the Finished button.
