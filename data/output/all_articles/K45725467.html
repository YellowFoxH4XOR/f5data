Known Issue

Some BIG-IP systems may experience long I/O wait times during the F5 Application Visibility and Reporting module data aggregation.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system collects statistics locally rather than sending data to a BIG-IQ system or other external device.
  • The BIG-IP system collects a large amount of statistics data in a given period.

    Note: This issue may occur even if the Application Visibility and Reporting module is not explicitly provisioned

Impact

The BIG-IP system experiences long I/O wait times, which can negatively impact various processes on the BIG-IP system or cause them to time out. This is caused by the data aggregation process that is running on the local database.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system experiences long I/O wait times and high CPU usage peaking at 10 minute, 1 hour, and 24 hour intervals.
  • Processes running on the BIG-IP system experience degraded performance or must be restarted.
  • The BIG-IP system generates a core file to the /shared/core/ directory.

Workaround

To work around this issue, you can decrease the amount of data collected during aggregation by lowering the value of the avr.stats.internal.maxentitiespertable database variable. The recommended value for systems with more than 16 CPU cores is 20000. For systems with 16 CPU cores or less, the recommended value is 2148. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash).
  2. View the number CPU cores present on the system by entering the following command:

    tmsh show /sys hardware | grep -i cores

    Output appears similar to the following example:

    cores         8  (physical:8)

  3. Based on the number of CPU cores found, set the value for the avr.stats.internal.maxentitiespertable database variable using the following syntax:

    tmsh modify /sys db avr.stats.internal.maxentitiespertable value <#>

    For example, to set the value to 2148, enter the following command:

    tmsh modify /sys db avr.stats.internal.maxentitiespertable value 2148

  4. After you lower the database value, continue to monitor the BIG-IP system for long I/O wait times and high CPU usage. If symptoms persist and the system continues to experience resource issues, you may need to reset the Application Visibility and Reporting statistics. For information about resetting Application Visibility and Reporting statistics, refer to K14956: Resetting F5 Application and Visibility statistics.
