Description
You can configure the peer disconnections based on the number of device watchdog failures count. 

Environment
  • LTM
  • MRF
  • Diameter.
Cause

The diameter peer is not responding to DWRs.

Recommended Actions
When the peer doesn't respond to the number of DWR messages sent by MRF or diameter entities, the peer is treated as busy and should be taken down after the configured number of DWR failures.

To set the number of device watchdog failures, you can go to:
GUI  ››  Local Traffic  ››  Profiles: Message Routing: Diameter  ››  session-profile (session profile name)

In the Maximum Watchdog Failures field, type the maximum number of device watchdog failures that the traffic management system can receive before it tears down the connection.

Note: If the number of device watchdog failures exceeds the specified value, and the Reset on Timeout check box is selected, then the connection will be reset. If the number of device watchdog failures is greater than 3 times the specified value, the connection will be reset, even if the Reset on Timeout check box is cleared.
Select the Reset on Timeout check box to reset the connection when watchdog failures exceed the specified number of maximum watchdog failures.
In the Watchdog Timeout field, type the number of seconds that a client-side or server-side connection can be idle before a device watchdog request (DWR) is sent.
Note: The default value of 0 prevents sending a DWR.
