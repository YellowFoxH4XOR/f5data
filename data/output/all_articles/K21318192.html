K21318192: Exchange 2016 iApp, APM Exchange profile and new REST v2.0 API (/api/*)

Type
Support Solution
Published
2020-04-17
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 14.1.2
Source
https://my.f5.com/manage/s/article/K21318192

Description
You have deployed the Exchange 2016 iApp using APM pre-authentication and currently deploying Teams that use Exchange REST 2.0 API calls:

https://mail.example.com/api


You have noticed that this does not work properly with the Exchange 2016 iApp.
When accessing the above URI (/api), you are presented the APM login page (same once you are accessing "/owa") and you need to change the Front End authentication for "/api/*" to the same authentication method you use for "/ews/*" URI.

Environment

  • Fully license and provision APM
  • Exchange 2016 iApp
  • APM Exchange profile

Cause

No separate place to configure Front End authentication for "/api/*" URI.

Recommended Actions

Front End authentication for /api/* is the same currently used for the /ews/* URI
A minor edit of the iApp created Exchange profile to support for /api/* is needed:
  1. Navigate to Access > Connectivity / VPN > Microsoft Exchange
  2. Select the Exchange profile and click Edit
  3. Go to Exchange Web Service
  4. In URL section replace existing content with: /[ae][pw][is]/*
  5. Save changes with OK
This configuration will match both /api/* and /ews/*

Additional Information

Exchange profile uses matches_glob to verify if the URL (PATH) received matches the URL configured in one of the services.
The matches_glob command use a

    glob style matching that is a small subset of regular expressions.

    The Exchange profile configuration after completing the Recommended Actions allows Exchange profile to listen to both /ews/* and /api/* URIs and apply to them the authentication methods configured in EWS

    Exchange profile configuration example from bigip.conf file:
    apm profile exchange /Common/exch_ {
        web-service-auth-type basic
        web-service-sso-config basic
        web-service-url /[ae][pw][is]/*
