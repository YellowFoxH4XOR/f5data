K47010513: Show cm failover-status shows Error for management interfaces on different subnets

Type
Support Solution
Published
2022-03-30
Updated
2025-11-14
Applies to
  • BIG-IP
  • BIG-IP AFM: 13.1.1
Source
https://my.f5.com/manage/s/article/K47010513

Description

The BIG-IP is not able to communicate with it's HA peer over the configured management interface IP address(es). The following status will be seen

tmsh show cm failover
--------------------
CM::Failover Status
--------------------
Color    gray
Status   STANDBY
Summary  1/1 standby
Details

-----------------------------------------------------------------------------------------------------
CM::Failover Connections
Local Failover Address  Remote Device          Packets  Transitions  Received Last Packet  Status
-----------------------------------------------------------------------------------------------------
192.168.0.111:1026      bigip1.example.com       0           1       -                     Error      <<<<
172.16.0.100:1026       bigip1.example.com       1478588     5       2021-Jan-29 07:49:54  Ok 

Environment

  • BIG-IP HA Pair
  • Different management subnets for each device in the cluster 
  • No packets seen on port 1026 to peer management IP address in packet capture

Cause

Typically management IP of BIG-IPs in an HA cluster are in the same subnet.  If the BIG-IPs participating in the HA Cluster have different management subnets, management routes are required to source the traffic from the correct IP address.  Without a management route to the HA peer's management subnet, the traffic will be forced out the default TMM interface and arrive at the peer with an unexpected source IP address, causing failover communications to fail across the management interface.

Recommended Actions

The recommended action is to add a management route to each of the devices pointing to the peer device's management subnet.

  1. Login to the BIG-IP CLI
  2. Add the management route

tmsh create /sys management-route <name> network <destination network>/<netmask> gateway <management gateway>

  3. Save the changes to the static routes for the management network:

tmsh save /sys config
