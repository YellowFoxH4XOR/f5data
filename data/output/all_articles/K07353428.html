Known Issue

Passing an empty URI to a BIG-IP AAM virtual server may cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • The BIG-IP AAM virtual server is configured with a web acceleration policy that has Intelligent Browser Referencing (IBR) enabled.
  • The virtual server uses an iRule configured to strip the URI from a request.
  • The virtual server receives a request that has an empty URI.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process restarts. If configured as part of a HA group, the BIG-IP system fails over to another system in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

To work around this issue, you can configure the virtual server's iRule to inspect requests for a URI, and insert a forward slash ( / ) if the URI is missing.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window, and consider the possible impact on your specific environment.
