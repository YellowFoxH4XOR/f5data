Known Issue

This is the result of a known issue. As a result of changes introduced in ARX versions 5.1.0 HF4 and 5.1.5 HF2, the ARX system fails to respond to a CANCEL NOTIFY request from a Windows client. When the Windows client sends the CANCEL NOTIFY request, and the ARX system does not respond within approximately 60 to 90 seconds, the Windows client aborts the connection. If no other I/O is being performed at the time of the abort, the resulting disconnect and subsequent reconnect are transparent to the client. However, if a READ or WRITE RPC is in progress when the connection is aborted, the operation fails and the client receives an error message that appears similar to the following example:

The specified network name is no longer available

This issue is most likely to occur when performing long READ or WRITE RPC operations, such as copying files that are larger than 500 MB.

F5 Product Development tracked this issue as ID 39032 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.

Additionally, this issue was fixed in ARX versions 5.1.5 HF4 (build 11974) and 5.1.0 HF6 (build 11936). Customers affected by this issue should request these versions from F5 Technical Support and reference this Solution number and ID 39032.

Workaround

ARX versions 5.1.0 GA (build 11927) through 5.1.0 HF 3 (build 11932) and ARX versions 5.1.5 GA (build 11965) through 5.1.5 HF1 (build 11966) are not affected by this issue. However, some of the affected ARX versions may have included significant changes, such as database schema differences, from the earlier unaffected versions. These changes often require the system to be reset to factory defaults if downgraded. When downgrading from an affected ARX version to an earlier unaffected version, if the downgrade will require the system to be reset to factory defaults, the following warning message will be displayed:

WARNING: Arming this release will cause your configuration to be reset to factory default because it is a lower version than the running release.

Important: When this warning prompt is displayed during the upgrade, you will be required to reload the saved configurations and re-import all shares after the upgrade is complete.

Important: Ensure that you save your configurations before attempting to downgrade the ARX system from an affected version.
