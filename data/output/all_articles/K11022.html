Known Issue

This is the result of a known issue. BIG-IP GTM systems configured to use dynamic load-balancing modes (such as Round Trip Time or Quality of Service) use Metrics Collection protocols to collect path data used for load balancing.

When you select TCP for the Metrics Collection protocol, and the BIG-IP GTM system is configured to use a default gateway pool, the system incorrectly closes the TCP handshake with the remote LDNS server by sending a TCP RST packet containing the source MAC address of tmm0.

For example, if this issue occurs on your BIG-IP GTM system and you run the tcpdump process on the VLAN in which the default gateway pool members reside, you may observe the BIG-IP GTM system send a RST packet containing a source MAC address of 0:98:76:54:32:10. The packet will appear similar to the following example:

0:98:76:54:32:10   0:1:00:00:00:00 ip 54: 10.0.0.10.3568 > 10.0.0.12.domain: R [tcp sum ok] 2:2(0) win 0 (DF) (ttl 64, id 39898, len 40)

Note: To verify the tmm0 MAC address, run the ifconfig -a |grep tmm0 command.

F5 Product Development is tracking this issue as ID 223966.
