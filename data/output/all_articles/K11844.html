K11844: Setting the FFP.UDP.PortOverrideList bigpipe variable to 'all' on a 6900 or 8900 platform may cause TMM to crash

Known Issue

This is the result of a known issue. Setting the FFP.UDP.PortOverrideList bigpipe variable to all on a BIG-IP 6900 or 8900 platform may cause TMM to crash when a UDP virtual server receives a UDP datagram. By default, FFP.UDP.PortOverrideList is set to 0 (zero).

To determine the value set for the FFP.UDP.PortOverrideList variable on a BIG-IP system, type the following command:

bigpipe db FFP.UDP.PortOverrideList show

Note: The FFP.UDP.PortOverrideList variable was introduced in BIG-IP version 10.1.0. For more information, refer to K10786: Overview of the FFP.UDP.PortOverrideList bigpipe db variable.

F5 Networks Product Development is tracking this issue as ID 227009.

Workaround

You can work around this issue by configuring the UDP virtual server to strictly preserve the source port. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Select the name of the UDP virtual server you want to modify.
  5. From the Configuration menu, select Advanced if it is not already selected.
  6. In the Source Port menu, select Preserve Strict.
  7. Click the Update button.
