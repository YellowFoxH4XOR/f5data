Known Issue

Large expressions in Windows Registry check may cause connections to reset.

This issue occurs when all of the following conditions are met:

  • Your system uses an Access Policy configured to perform Windows Registry Endpoint Security checks.
  • The Registry Checker is configured with a large expression (for example, 10,000 bytes).
  • Windows systems connect to the BIG-IP APM system.

Impact

The BIG-IP APM system resets connections and prevents network access.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H453744 on the Diagnostics > Identified > Low|Medium screen.
  • Windows users fail to pass the Client-Side Endpoint Security check.
  • The BIG-IP APM system displays a webtop which does not contain network access.
  • Messages appear in the /var/log/ltm file similar to the following example:

err tmm6[9592]: 01490514:3: 00000000: Access encountered error: ERR_BOUNDS. File: ../modules/hudfilter/access/access.c, Function: access_process_state_client_finish_portal_req, Line: 3374
err tmm6[9592]: 01490514:3: 00000000: Access encountered error: ERR_BOUNDS. File: ../modules/hudfilter/access/access.c, Function: hud_access_handler, Line: 1949

Workaround

To work around this issue, you can split the expression into two separate Windows Registry checks. Alternatively, you may be able to reduce the size of the expression used in the BIG-IP APM policy by removing backslash (\) characters at the end of each registry key and using "HKLM" keywords in place of "HKEY_LOCAL_MACHINE" instances.

For example, the following expression uses extended syntax:

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\services\Tcpip\Parameters\

This example expression can be modified to the following shorter version:

HKLM\SYSTEM\CurrentControlSet\services\Tcpip\Parameters
