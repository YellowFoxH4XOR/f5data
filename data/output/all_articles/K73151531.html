Description

You want to increase the disk space on a BIG-IP Virtual Edition (VE) that does not have sufficient disk space.

  • The /var partition may become 100% full affecting some administrative task like creating a UCS archive file.
  • You may encounter this error message: err diskmonitor: 011d0004: Disk partition var has only 0% free

Environment

  • BIG-IP VE
  • /var directory
  • /var/log/ltm file
     

Cause

The BIG-IP VE image is available in three different sizes for the supported hypervisors. If you have deployed a BIG-IP VE using one of these images, and find the disk size inadequate for upgrading (including hotfix and point release installation), provisioning multiple modules or you run out of space due to small allotment, you can increase the BIG-IP VE disk size.
 

Recommended Actions

If the BIG-IP VE runs out of disk space for the /var, you can extend the disk space by performing the following procedure.

  1. Confirm the hypervisor expanded the disk by using the following command syntax:
    tmsh list /sys disk
     
  2. Extend the /var directories as needed.
    For example, you would enter the following command to extend the /var directory to 3 GB:
    tmsh modify /sys disk directory /var new-size 3072000
     
  3. Save the configuration.
    tmsh save /sys config

    Note: df -h output will not show changes until after a reboot of BIG-IP VE
     
  4. Reboot the BIG-IP VE.
    reboot
     
  5. When the BIG-IP VE is up, log in to bash.
     
  6. Verify that the /var directory is successfully extended to the size you have specified.
    tmsh show /sys disk directory
     
  7. Verify file system disk space usage again.
    df -h
     

Additional Information

Before increasing the disk size of individual directories in the BIG-IP VE, you must first increase the disk size in the hosting hypervisor configuration using the steps appropriate for the given hypervisor system. After this is complete, you can increase the size of the directories on the BIG-IP VE.
