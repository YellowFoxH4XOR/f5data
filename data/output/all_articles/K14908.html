Known Issue

The BIG-IP APM system may not maintain Differentiated Services Code Point (DSCP) when processing packets for network access profiles.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM configuration uses a network access profile.
  • Packets processed by a network access profile have the DSCP packet header value set.

Impact

DSCP traffic control is not retained when passed through a network access tunnel.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • DSCP no longer affects packet processing for network access profile sessions.
  • The system does not retain packet level DSCP header values when they are processed through a network access tunnel.

Workaround

To work around this issue, you can create a Forwarding (IP) virtual server for the affected network or host destination allowing the DSCP header to remain intact. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Creating a Forwarding (IP) virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click Create.
  4. Type a name for the virtual server.
  5. If the destination is a single host, select Host; if the destination is a network, select Network.
  6. If the destination is a single host, enter the IP address for the virtual server; if the destination is a network, enter a Netmask.

    Note: The IP address or network address that you enter should match the destination addresses that the network access profile will access.

  7. Select Forwarding (IP).

    Note: You should configure the Forwarding (IP) virtual server with the Client fastL4 Protocol Profile. (This is the default setting when you view the advanced configuration of the Forwarding [IP] virtual server.)

  8. Set SNAT Pool to Auto Map.
  9. Click Finished.
