K000162304: Identify the Cause of "Changes Pending" on a BIG-IP Device Before Performing ConfigSync

Type
Support Solution
Published
2026-07-16
Updated
2026-07-20
Source

Description

An administrator notices that a BIG-IP device displays a "Changes Pending" status and wants to determine exactly which configuration changes are waiting to be synchronized before performing a ConfigSync operation.

Symptoms:

  • BIG-IP reports "Changes Pending" in the Configuration Synchronization status.
  • Audit logs do not clearly identify the modified configuration object.
  • Uncertainty regarding whether pending changes should be synchronized or reverted.

Error/Log Messages:

  • No specific error messages reported.
  • Audit logs may contain entries such as: 
    list cm device recursive
    and other GUI-generated read-only commands.

Environment

  • BIG-IP systems are members of a device group
  • Configuration Synchronization (ConfigSync).

Cause

Changes have been made to the running BIG-IP configuration that have not yet been synchronized to other devices in the Device Group. The specific modified object is not always readily identifiable through the standard Audit Log view.

Answer/Recommended Actions

To identify the source of a "Changes Pending" status before performing ConfigSync:

  1. Review configuration change records in the audit logs and filter out read-only commands that may obscure actual configuration modifications.

  2. Compare the current configuration against a previously known-good UCS or configuration backup when available.

  3. Use the procedures documented in the following F5 article to identify unsynchronized configuration changes:

    • K09050750: How to find recent configuration changes on the BIG-IP system

  4. Examine recent administrative activity performed through:

    • TMUI (GUI)
    • TMSH
    • iControl REST/API
    • Automation platforms such as Ansible or AS3

  5. If the changes are determined to be unintended and have not yet been synchronized:

    • Restore the affected configuration from a backup if appropriate.
    • Alternatively, manually reverse the changes before performing ConfigSync.
    • Verify the synchronization status after reverting the changes.

  6. Before synchronizing, confirm that the pending changes are expected and desired to avoid propagating unintended modifications to peer devices.

Additional Information

  • Refer to F5 article K09050750: How to find recent configuration changes on the BIG-IP system for supported methods of identifying configuration differences and troubleshooting synchronization status.
