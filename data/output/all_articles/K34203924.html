Known Issue

A newly created Kerberos access policy authentication agent may default to request-based authentication.

This issue occurs when all of the following conditions are met:

  • You add the Kerberos Authentication agent to an access policy and accept the Properties default settings.
  • The access policy is applied to traffic that is processed by the associated access profile.

Impact

Users may not be able to retrieve content from destination resources.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When users attempt to access content, they are presented with an authentication loop.
  • Content processed by the access profile is not displayed or does not render correctly.
  • When the BIG-IP APM system is configured as a Security Assertion Markup Language (SAML) Identity Provider (IdP), authentication fails, and in the /var/log/apm file, you may observe logged messages similar to the following example:

    apmd[5122]: 01490000:3: AccessPolicyProcessor/AccessPolicy.cpp func: "terminate()" line: 382 Msg: current agent index is out of range
    warning tmm1[8923]: 014d0002:4: 3236bd3c: SSOv2 Authn Request has no SAMLRequest
    err tmm1[8923]: 014d0002:3: 3236bd3c: SSOv2 Error(12) Extracting SAML Data from Request

Workaround

To work around this issue, you can change the access policy Kerberos authentication agent properties Request Based Auth setting to disabled. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Profiles/Policies.
  3. To open the visual policy editor, click the Edit link to the right of the affected access profile name.
  4. Click the Kerberos Auth box.
  5. From the menu, toggle the setting for Request Based Auth to Disabled.
  6. Click Save.
  7. Click Apply Access Policy.
