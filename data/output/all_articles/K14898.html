Known Issue

The lopd process may temporarily lose connectivity to the lights-out processor (LOP) Backplane Micro-Controller Hybrid (LBH).

This issue occurs when the following condition is met:

  • Your system platform is a BIG-IP 2000 or 4000 series.

On rare occasions, the LBH can experience an undiagnosed watchdog restart. The lopd process temporarily loses connectivity to the LBH while it resets.

Impact

Communication with the LBH, which is used primarily to report system hardware status, is interrupted temporarily (typically less than 30 seconds).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Management access by way of the LOP is unavailable while the LBH restarts.
  • The /var/log/ltm file contains error messages that appear similar to the following examples:

Resolution

Status

F5 Product Development has assigned ID 419954 and ID 435842 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Type of fixFixes introduced inRelated articles
Release11.5.0*K2200: Most recent versions of F5 software
Point release/hotfix11.4.1 HF3*
11.2.1 HF11*		K9502: BIG-IP hotfix and point release matrix

*With LOP firmware improvements in later releases, there have been no reports of this issue in these versions. If you experience this issue in one of the listed versions, contact F5 Technical Support.

Workaround

There is no workaround for this issue. However, LOP firmware 1.19 or later may help to prevent at least one possible cause of the LOP reset. LOP firmware 1.19 or later is available in BIG-IP 11.4.0, 11.3.0 HF5, and 11.2.1 HF6, for the versions that are applicable to BIG-IP 2000 or 4000 series platforms.
