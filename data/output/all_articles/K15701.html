Known Issue

BIG-IP APM policy synchronization of an access policy to more than one device group may cause an error.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with multiple device groups.
  • A BIG-IP APM administrator uses the Access Policy > Access Profiles > Policy Sync screen in the Configuration utility to synchronize an access policy to a device group.
  • The BIG-IP APM administrator attempts to synchronize the same access policy to an alternate device group.

Impact

The system incorrectly displays a policy synchronization error message, even though the access policy synchronizes successfully.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Attempts to synchronize an access policy, using the Policy Sync operation from the Configuration utility, trigger an error message similar to the following example:

    Sync error on <apm peer system name>: Load failed from <local apm device> 010713f9:3: The folder POLICYSYNC_<access profile name> cannot be deleted because it is not empty

  • During the access policy synchronization, errors similar to the following example appear in the /var/log/apm file:

    info mcpd[6269]: 0107148c:6: Received advertisement for device group /Common/<device group name> from remote device /Common/<apm peer system>, force true, error ' '
    commit_id 2 6080046541940301012 /Common/<local apm device> 90, local commit id is 2 6080046541940301012 /Common/<apm peer device> 91 cached remote device data id 0

    info mcpd[6269]: 01071528:6: Device group '/Common/<device group name>' sync inconsistent, Sync failed on one or more devices in this devicegroup, Sync status may not be consistent..

    mcpd[6269]: 0107148b:6: Sending sync for device group /Common/<device group name> to device /Common/<local apm device>, current commit id 2 6080046541940301012 /Common/<apm peer system> 9

  • When reviewing the access policy for members of the device group, you notice that the access policy was successfully synchronized to the peer devices.

Workaround

To work around this issue, you can clear the synchronization and status data each time you use the Policy Sync operation. To do so, perform the following procedure:

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

Clearing access policy synchronization status and data

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles > Policy Sync.
  3. Synchronize the access policy to the first device group.
  4. Log in to the Traffic Management Shell (tmsh).
  5. Remove the previous synchronization data by typing the following command:

    tmsh delete apm policy psync-status all

  6. Remove the synchronization status data by typing the following command:

    tmsh delete apm policy psync-data all

  7. Exit the tmsh utility by typing the following command:

    quit

  8. Using the Configuration utility, navigate to Access Policy > Access Profiles > Policy Sync.
  9. Synchronize the access policy to the alternate device group.
