K16213: It is not possible to monitor the health of a resource when the BIG-IQ ADC system forced the resource offline

Known Issue

When the BIG-IQ system forces a node or pool member offline, if you enable or disable the object using the BIG-IQ system, you can no longer monitor the health of that object.

This issue occurs when all of the following conditions are met:

  • The BIG-IQ system is managing a BIG-IP device that has pool members.
  • The BIG-IQ system forces the BIG-IP pool member offline, and the change is deployed to the BIG-IP device.
  • You use the BIG-IQ system to enable the same pool member, and the change is deployed to the BIG-IP device.

Impact

The affected node or pool member loses health monitoring capability.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The status of the affected pool member becomes Unknown (enabled), and it should be Available (enabled).

Workaround

To recover from this issue, you can perform one of the following actions depending on your situation:

  • If you have already used the BIG-IQ system to enable or disable the object that the BIG-IQ system forced offline, then you must use the BIG-IP system to force the object offline and then reset the object's enabled or disabled state. This will restore your ability to monitor the health of the affected object.
  • If you have not yet enabled or disabled the object that was forced offline, from a workstation you can send the REST API request to the BIG-IQ system using the PATCH method, using the following HTTP request syntax:

    https://<BIGIQ_IP_Address>/mgmt/shared/resolver/device-groups/<GroupName>/devices/<BIGIP_Device>/rest-proxy/mgmt/tm/ltm/pool/<PoolName>/members/<Member>

    To enable the pool member that the BIG-IQ system has forced offline, send the following body content with the previous URL syntax:

    {
         "state": "user-up",
         "session": "user-enabled"
     }

    To disable the pool member that the BIG-IQ system has forced offline, send the following body content with the previous URL syntax:

    {
         "state": "user-up",
         "session": "user-disabled"
     }

    You can use different commands to enable the affected pool member that was forced offline. For example, if you use a curl command, the command may appear similar to the following example:

    curl -k  -l -H'Accept:application/json' -H'Content-Type:application/json' --user admin:admin123 -X PATCH -T /tmp/enable_poolmem.txt https://localhost/mgmt/shared/resolver/device-groups/GroupA/devices/8f1443e1-45eb-4b71-82f6-7d0e3a3b0fab/rest-proxy/mgmt/tm/ltm/pool/~Common~bip1_pool1/members/~Common~10.10.100.201:80

    Note: The PATCH request uses the file /tmp/enable_poolmem.txt in the previous example, and has the following content:

     {
         "state": "user-up",
         "session": "user-enabled"
     }
