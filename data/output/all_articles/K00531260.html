Description

When using 'bigip_add' or 'gtm_add' command to add a DNS/LTM server object, sometimes it can fail with a message with a syntax like this:

  •  "no matching key exchange method found: client <string> server <string>" 

For example:

[root@BIGIP_A:Active:Standalone] config # bigip_add 172.16.1.2
Retrieving remote and installing local BIG-IP's SSL certs ...
Enter root password for 172.16.1.2 if prompted
no matching key exchange method found: client ecdh-sha2-nistp256,ecdh-sha2-nistp384,ext-info-c server diffie-hellman-group-exchange-sha1,diffie-hellman-group14-sha1,diffie-hellman-group1-sha1

==> Done <==

Environment

  • DNS module provisioned
  • Using "bigip_add" or "gtm_add" command to add a DNS/LTM server object to the DNS mesh
  • Having a custom list of ciphers and MAC and key exchange algorithms used by the SSH service 

Cause

The error is caused due to a missing or discrepancies in Cipher, MAC or Key Exchange algorithms configured to be used by SSH service.

Recommended Actions

In order to avoid this issue, you can customize the SSH setting on your DNS device. Below, an example of the procedure:

       1. Based on an output of the error like this:

[root@BIGIP_A:Active:Standalone] config # bigip_add 172.16.1.2
Retrieving remote and installing local BIG-IP's SSL certs ...
Enter root password for 172.16.1.2 if prompted
no matching key exchange method found: client ecdh-sha2-nistp256,ecdh-sha2-nistp384,ext-info-c server diffie-hellman-group-exchange-sha1,diffie-hellman-group14-sha1,diffie-hellman-group1-sha1

       2. Open an SSH session to your DNS device and perform a backup of the file "/config/ssh/ssh_config". Run the following command to make a copy of the current SSH client configuration file:

cp /config/ssh/ssh_config /config/ssh/ssh_config.bak

       3. Check the current configured KEX Algorithms, for instance you should see an output similar to this:

cat ssh/ssh_config | grep KexAlgorithms

KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384


         Or you can view the complete SSH settings with this command:
tmsh list /sys sshd all-properties

sys sshd {
    allow { ALL }
    banner disabled
    banner-text none
    description none
    fips-cipher-version 0
    inactivity-timeout 0
    include "Ciphers aes128-cbc,aes128-ctr,
    MACs hmac-sha1
    KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384"
    log-level info
    login enabled
    port 22
}


       4.  Modify the KEX Algorithms section to make client's and server's the same. Since the 'client' is using sha2, which is stronger, and the 'server' is using sha1, we will edit the server's Key Exchange. That modification can be done with the following commands:

tmsh
edit /sys sshd all-properties
Note: File will open in a text editor. Press 'i' to insert and then ':wq!' to save.

     5. After editing that file, save it and review your changes with the following command:

cat ssh_config | grep KexAlgorithms

KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384


      6. Now, both of then are having the same KexAlgorithms, test "bigip_add" or "gtm_add" command again and it should be executed just fine.

Additional Information

If having issues while modifying the SSH settings, please review the article below.
