Description:

The attack signatures are not detected if the URL contains the # sign which is a 'fragment identifier' and the matching phrase is located after # sign.


Environment:

ASM or Advanced WAF provisioned

ASM policies configured on a system


Cause:

You might wonder why the attack signature which is enforced on asm policy is not triggering a violation with requests to FQDN similar to e.g.


https://test.com/path#/?<script


This is because an HTTP URL contains the # sign which is a 'fragment identifier' and it is typically used to identify a portion of an HTML document that sits within a fully qualified URL.


As per http://www.w3.org/DesignIssues/Fragment.html


The significance of the fragment identifier is a function of the MIME type of the object


This means that the fragment id is opaque for the rest of the client code. The HTTP engine cannot make any assumptions about it. The server is not even given it.


That means that the interpretation of the 'fragment identifier' is handled by client (mostly web browser). When a URL with # is entered by the client, the # and what follows is not sent across the wire, the ASM does not see it. Therefore you also won't see that part in the Event Logs.


Recommended Actions:

None. It is expected behavior.
