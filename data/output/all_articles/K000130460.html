Description

When policy in JSON format is imported to BIG-IP, the system adds additional Signature sets and wildcard entities such as * [HTTP] URL, * filetype, * parameter .

 

*System has added the following 10 sets:

PostgreSQL Signatures (High Accuracy)

Nginx Signatures (High Accuracy)

Spring Boot Signatures (High Accuracy)

JavaScript Signatures (High Accuracy)

Unix/Linux Signatures (High Accuracy)

Microsoft SQL Server Signatures (High Accuracy)

Apache Tomcat Signatures (High Accuracy)

Java Servlets/JSP Signatures (High Accuracy)

Generic Detection Signatures (High Accuracy)

 

Environment

  • Policy exported in Full JSON
  • Policy was created using Minimal Security Template

Cause

When policy is created with the template Minimal Security Policy, Generic Detection Signatures (High Accuracy) are added.

 

During the course of building the policy, High Accuracy set was removed and High/Medium Accuracy sets were added.

 

While exporting the policy in full mode, it was using using Minimal Security Policy. When imported, the policy is re-created using the "Minimal Security Policy" template, and this template uses the "High Accuracy" signature set by default.

 

This gives creates the difference between the other formats.

 

This is functioning as designed.

 

Note: It's a known limitation of full json export usage, since the json policy is being created based on the specified template.

 

Recommended Actions

To eliminate this behaviour, export the policy in JSON format and then edit the file.

Mark the entities with the $action:delete property.

Save the file and then import it.

The other method is to export the policy using the minimal JSON export option.

 

Additional Information

When importing Security policy using Declarative JSON format which was exported using Full Export, 'Declarative Policy Import' is adds entities into the policy according what it has in the JSON file.

This is a known issue.

For more information, refer to Bug ID 1042917: Using 'Full Export' of security policy should result with no diffs after importing it back to device.
