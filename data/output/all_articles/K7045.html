K7045: The Traffic Learning section of the BIG-IP ASM system does not provide a maximum length restriction on parameter characteristics

Topic

A flow parameter characteristic specifies the data type of the parameter. When a BIG-IP ASM parameter type is defined as user-input, it is important to limit the amount of characters that are sent in the parameter's value field. Setting the maximum length for a parameter provides an additional layer of protection against localized buffer overflow attacks.

However, when defining a new parameter under Illegal parameter in the Traffic Learning section of the Configuration utility, the BIG-IP ASM system does not offer a character restriction in the Check Maximum Length tab.

You can restrict the number of characters available in the parameter value by performing the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Application Security > Web Applications.
  3. Click the active policy name for which you want to restrict the number of characters available in the parameter.
  4. Click the Web Objects tab.
  5. In the Web Application Objects section, click the web object you want to edit.
  6. In the List of Object Parameters section, click Create.
  7. Type the parameter name.
  8. In the Parameter Characteristics section, select the Check Max. Length check box.
  9. In the Check Max. Length box, enter the maximum number of characters allowed for that parameter.

Note: If you do not have a maximum number of characters set for the parameter value, you can perform the following procedure to set it accordingly.

To use the Traffic Learning screen to set maximum number of characters for the parameter, perform the following procedure:

  1. After creating the user-input parameter by following the previous steps, type 1 in the Check Max. Length box. 
  2. Click the Properties tab for the security policy.
  3. In the Security Level section, click Edit.
  4. On the Blocking Policy page, confirm that the Illegal parameter value length is enabled for learning by selecting the Alarm box.
  5. Click Save.
  6. In BIG-IP ASM 9.2.x, click Set Active Policy on the Web Application Properties screen to update settings. In BIG-IP ASM versions later than 9.2.x, click Apply Policy.
  7. Direct traffic to the parameter using live traffic or trusted traffic to accumulate traffic learning suggestions.
  8. After the parameter has received a sufficient amount of traffic, click the Traffic Learning tab.
  9. In the Input Violations section, there should be some violations listed for Illegal parameter value length. Click Illegal Parameter Value Length and locate the relevant parameter name.
  10. The Detected Value Max Length field displays the maximum number of characters detected for that parameter value. To verify that the Detected Value Max Length is a valid parameter value, click the Values column (the number inside the parenthesis).
  11. After establishing that the Detected Value Max Length is valid for the parameter, you may need to increase the value depending on the parameter's function.

    Note: Increasing the Detected Value Max Length enables you to avoid receiving false positive violations for that parameter length. For example, username parameters can vary between 5 and 15 characters, while a detail level parameter such as addresses can hold more than 100 characters.

  12. In BIG-IP ASM 9.2.x, click Set Active Policy on the Web Application Properties screen to activate the security policy. In BIG-IP ASM versions later than 9.2.x, click Apply Policy.
  13. When you have verified that the parameter length is tuned properly, set the policy (or the Illegal parameter Value Length Violation) to Blocking mode.
