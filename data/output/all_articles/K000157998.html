K000157998: HA Failover Status shows "Error" on self IPs - AFM also provisioned

Description

When AFM is provisioned and the "sys db tm.fw.defaultaction" is set to either "drop" or "reject" (firewall mode), then this functions as a default "deny" globally:

sys db tm.fw.defaultaction {
    default-value "accept"
    scf-config "true"
    value "drop"
    value-range "accept drop reject"
}

therefore causing traffic over self IPs to be denied, resulting in an "Error" message in the Failover Status output as shown below:

root@(LTM-1)(cfg-sync In Sync)(Active)(/Common)(tmos)# show cm failover-status

-------------------------------------------
CM::Failover Status
-------------------------------------------
Color    green
Status   ACTIVE
Summary  1/1 active
Details
         active for /Common/traffic-group-1

-------------------------------------------------------------------------------------------
CM::Failover Connections
Local Failover Address  Remote Device  Packets  Transitions  Received Last Packet  Status
-------------------------------------------------------------------------------------------
192.0.2.1:1026          LTM-2          9664837  5            2025-Nov-30 16:46:26  Ok       <<<<<<<< Management IP
198.51.100.1:1026       LTM-2          9666145  1            2025-Nov-30 16:46:26  Error    <<<<<<<< Self IP

root@(LTM-1)(cfg-sync In Sync)(Active)(/Common)(tmos)#

Environment

  • HA cluster (Active/Standby)
  • AFM Provisioned
  • "Error" Seen in Failover Status

Cause

This happens because the "drop" and/or "reject" value in "tm.fw.defaultaction" causes all traffic to be denied by default, unless a firewall policy to allow port 1026 access is created and applied to the appropriate self IPs.

Recommended Actions

There are 2 solutions to this issue.

 

Solution 1: Setting the configuration to appliance mode (from firewall mode)

This option has to be chosen with caution as this option applies globally. The device may be set to firewall mode for a reason and therefore may not be the ideal solution. To switch to appliance mode, the following can be done:

Impact of workaround: This change applies globally and should therefore be applied with extreme caution.

 

From the Configuration Utility / GUI:

  • Go to Security > Options > Network Firewall > Firewall Options
  • Switch the Virtual Server & Self IP Contexts from Drop or Reject to Accept

From the CLI:

  • The following command will switch the configuration to appliance mode:

# (tmsh) modify sys db tm.fw.defaultaction value accept

  • Save the configuration:

# (tmsh) save sys config 

 

Solution 2: Applying a policy to the self IP to allow port 1026

This is the safest option as it only allows the traffic to be accepted for specific self IPs and not globally.

Impact of workaround: Since this change applies only to the configuration objects where the security policy will be applied, only those configuration objects should be affected.

 

From the Configuration Utility / GUI:

  • Go to Security > Network Firewall > Policies
  • Create a new policy and click on Finished (just the name should suffice, the Description is optional)
  • Select the newly created policy and click on the Add Rule List button
  • In the Name column, in the Rule List text box enter "/Common/_sys_self_allow_defaults". Just by starting to type "_" should bring up a list of policy lists from which you can select it.
  • Click on Done Editing, followed by "Commit Changes to System"
  • Next go to Network > Self IPs and select the self IP used for the HA Failover
  • Under the Security tab Enable Enforcement in the Network Firewall section and from the Policy drop down menu select the policy created above

From the CLI:

  • Create the policy with the following command:

# (tmsh) create security firewall policy /Common/<Policy_Name> rules add { _Common__sys_self_allow_defaults { rule-list _sys_self_allow_defaults place-before first } }

  • Apply the policy to the self IP:

# (tmsh) modify net self <SelfIP_Name> fw-enforced-policy <Policy_Name>

  • Save the configuration:

# (tmsh) save sys config 

Run the following command to check that the "Error" message has gone and is now showing "Ok"

# (tmsh) show cm failover-status
