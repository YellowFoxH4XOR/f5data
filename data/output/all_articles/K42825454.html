Known Issue

The BIG-IP system may incorrectly mark a fully-qualified domain name (FQDN) node down.

This issue occurs when all of the following conditions are met:

  • You have an FQDN node configured on the BIG-IP system.
  • A health monitor is applied to this node to monitor the status, using a specified port number (for example, TCP port 80).

Impact

The BIG-IP system erroneously marks the FQDN node down. As a result, the affected node does not process any network requests.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After you configure the health monitor on the FQDN node, you notice the node is marked down.
  • The network capture on the BIG-IP system shows that the monitor probe is sent to an incorrect port number. The command and output of the network capture to the FQDN node with an IP address of 10.0.0.2 appears similar to the following example:

    tcpdump -nni 0.0 host 10.0.0.2

    tcpdump: verbose output suppressed, use -v or -vv for full protocol decode
    listening on 0.0, link-type EN10MB (Ethernet), capture size 96 bytes
    07:33:41.449505 IP 10.0.0.10.60882 > 10.0.0.2.7: S 1708978381:1708978381(0) win 14600 <mss 1460,sackOK,timestamp 1389911880 0,nop,wscale 7>
    07:33:41.450795 IP 10.0.0.2.7 > 10.0.0.10.60882: R 0:0(0) ack 1708978382 win 0

    In this example, the BIG-IP system sends a monitor probe to the FQDN node on port 7 instead of the specified port 80.

Workaround

To work around this issue, you can apply the desired health monitor to the pool where the FQDN node is configured, instead of applying the monitor directly to the node. To do so, perform the following procedure:

Impact of workaround: The desired health monitor should be applicable to all pool members in the same pool as the FQDN node. If you configure more than one health monitor on this pool, the default setting will require all monitors to be successful, or else the pool will be marked down. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Click the name of the pool that contains the FQDN node as a pool member.
  4. Set the desired health monitor as the Active health monitor and configure the Available Requirement accordingly.
  5. To save the change, click Update.
