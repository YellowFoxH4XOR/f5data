Description

DNS queries from the BIG-IP have .localhost appended, similar to the following:

Standard query 0x3ea7 A callhome.f5.com
Standard query 0xc3c0 A callhome.f5.com.localhost

Furthermore, DNS resolution on the system may appear to be failing despite seeing a response.

Environment

  • DNS
  • Administrative queries

Cause

DNS queries are failing to receive a response, or response is being dropped.

When this happens, .localhost will be appended, as per search localhost in /etc/resolve.conf:

#
# THIS IS AN AUTO-GENERATED FILE - DO NOT EDIT!!!
#
# Use the tmsh shell utility to make changes to the system configuration.
# For more information, see tmsh -a help sys dns.
#
search localhost            <----
nameserver      8.8.8.8
options ndots:0

The search option contains a list of hostnames (by default, this is only localhost). These hostnames will be appended to any name that doesn't resolve, and the system will attempt to resolve the new name.

Recommended Actions

Investigate connectivity to the configured DNS servers.

You may wish to verify if the DNS server is reachable via a TMM or management route:

ip r g <dns server ip>

You can also take a tcpdump of DNS traffic, for example:

tcpdump -s0 -vnni 0.0:nnn host <dns server ip>

tcpdump -s0 -vnni eth0 host <dns server ip>

If you see a response to the first query (without the .localhost), it is possible the response has arrived on the wrong VLAN, or otherwise been dropped.
