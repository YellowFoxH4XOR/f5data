Description

When Cylance Powershell is configured to block powershell.exe , F5 endpoint check for AntiVirus detection fails as OPSWAT requires to run powershell.exe to collect client-side information.

F5PolicyServer.exe is invoking powershell.exe in below logs:

grep -i "powershell.exe" Logfile.CSV | grep "Process Create"
"12:18:03.0752748 PM","F5PolicyServer.exe","20968","Process Create","C:\WINDOWS\system32\cmd.exe","SUCCESS","PID: 14720, Command line: C:\WINDOWS\system32\cmd.exe /S /C """"C:\WINDOWS\system32\WindowsPowerShell\v1.0\powershell.exe"" get-wmiobject -namespace root\cylance -class protect > ""C:\Users\xyz\AppData\Local\Temp\OPS6F72.tmp"" 2> ""C:\Users\xyz\AppData\Local\Temp\OPS6F73.tmp"""""

Steps to get above log file :

  1. On Client running Cylance access to APM with AV checking, run procmon.
  2. Export the result into CSV format.
  3. Then go through the logs to see how powershell.exe is getting called.

Environment

  • Cylance AntiVirus has powershell.exe blocked on client machines
  • APM with endpoint check enabled for AntiVirus

Cause

OPSWAT uses Powershell under the hood to detect/collect information.

Recommended Actions

As a workaround, exclude F5PolicyServer.exe on Cylance AntiVirus which will allow F5PolicyServer.exe to run powershell.exe

Additional Information 


The location of F5PolicyServer.exe is in C:\Windows\Downloaded Program Files\F5PolicyServer.exe

Microsoft Explorer by-default does not show the contents in that folder.
Use a CMD prompt (run it with admin-privilege and go to that directory and run "dir" command) such as the example below. 

C:\Windows\Downloaded Program Files>dir
