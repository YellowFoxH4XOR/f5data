K13135345: How to troubleshoot increased disk space due to postgres log

Type
Support Solution
Published
2021-10-19
Updated
2023-02-21
Applies to

  • BIG-IQ Centralized Management: 7.1.X

Source
https://my.f5.com/manage/s/article/K13135345

Description
When BIG-IQ 7.1 and newer version is used for long period of time, postgres daemon log files can potentially fill the disk space of BIG-IQ.
To manage the disk space efficiently, there is a guidance to control log rotation mechanism of postgres.

Environment

  • BIG-IQ 7.1 and newer version
  • Disk Space full
  • Postgres daemon

Cause
Postgres daemon log files under /var/log/postgres/ may consume large space of disk at BIG-IQ.

Recommended Actions

Configure postgres config file to control the log rotation parameter    
  1. Identify postgres config file at the following location.
    /var/lib/pgsql/data/postgresql.conf
  2. Modify the options of the following entries in config file as follow.
  • #log_filename = 'postgresql-%Y-%m-%d.log'    
    Note: This entry controls the name of log file name at /var/log/postgres/
  • #log_truncate_on_rotation = off       
    Note: This entry controls to turn on or off to rotate log file.
  • #log_rotation_age = 1d           
    Note: This entry controls rotation by age, default daily
  • #log_rotation_size = 10MB        
    Note: This entry controls rotation by file size, default 10MB
     
To apply the modified config of postgres
  1. login to tmsh shell
    # tmsh
  2. Verifying the status of postgres daemon
    (tmos)# show sys service postgres
  3. Restart postgres daemon  
    (tmos)# restart sys service postgres
  4. To take effect of the config change, reload postgres via psql command .
    SELECT pg_reload_conf()
  5. Verify the status of postgres daemon    
    (tmos)# show sys service postgres
  6. Verify if the logs are being rotated
