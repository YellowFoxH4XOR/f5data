Description

Unable to locate the Support ID in ASM event logs.

When looking ASM logs at /var/log/ts/asmlogd you might see that ASM skipped many requests due to rate limiting with error messages similar to:

  • asmlogd|INFO|Dec 28 16:54:14.063|20041|F5::RequestLog::log_pulse_message,,203252449 requests handled since startup (last support id handled = 17871726109766940203, last attack id handled = 4161085503, last login object status handled = /api/v1/common/login, 53962 requests handled from RQL, 203330123 requests handled from PBRQL, skipped 77675 requests due to rate limit)
     
  • Error or Warning Message: F5::RequestLog::log_pulse_message,,123456789 requests handled since startup (last support id handled = 1234567890123456789, last attack id handled = 1234567890, last login object status handled = /example/example, 12345 requests handled from RQL, 123456789 requests handled from PBRQL, skipped 123456 requests due to rate limit)
     
  • asmlogd|INFO|Aug 17 21:01:54.013|27912|F5::RequestLog::log_pulse_message,,76226951 request records handled since startup (last support id handled = 13968203879918637794, skipped 586688 requests due to rate limit)
     

Environment

  • BIG-IP ASM
  • Multiple virtual servers with "Log All Request" logging profile.

    Cause

    There's a limit for ASM when it comes to logging security events locally. By default, it is 200 requests per second and it's controlled by internal variable "PRXRateLimit".
    If too many virtual servers are configured with 'Log All Requests' or/and with 'Guarantee Local Logging' option the system can reach the internal rate limit.

    Recommended Actions

    1. Review the configuration of the logging profiles attached to virtual servers with Security Policy. Within each:
      • Limit the usage of the 'Log all request' default logging profile
      • Limit the usage of the guarantee logging option in custom logging profiles.
    2. Ideally, log only illegal requests locally and all requests/responses remotely.
