K5362: The database used to store statistics information may become corrupt, eventually resulting in file descriptor exhaustion

Known Issue

This may be the result of a known issue. 3-DNS uses the Round Robin database to store statistics information. In rare circumstances, the database may become corrupt. When the database attempts to recover from the corrupt files, it repeatedly attempts to open new files until all file descriptors are exhausted.

When 3-DNS runs out of free file descriptors, it may become unresponsive or behave unpredictably.

When this issue occurs, the following message is logged to the /var/log/3dns file:

file <filename> is not an RRD file :rrd.c:262

In addition, 3-DNS processes may report errors containing the following text:

Too many open files in system

To recover from this issue, perform the following steps:

  1. Log in to the command line.
  2. Delete the current copy of the database, by typing the following command:

    Note: This will erase all historical statistics for 3-DNS.

    rm /var/rrd/*.rrd

  3. Restart the 3-DNS, by typing the following command:

    reboot

When 3-DNS reboots, it will create a new database.

F5 Networks Product Development tracked this issue as CR50372.
