K10868: Some browsers may not present expected cookies when the MultiConnect feature is enabled

Topic

Enabling the MultiConnect feature on a BIG-IP WebAccelerator application's requested host may result in the client not presenting the expected cookies with requests for multiconnected URLs. As a result, applications may not function as expected when MultiConnect is enabled.

When a cookie does not have a domain specified, the browser behavior varies depending on the browser used:

BrowserBehavior
Internet ExplorerSends domainless cookies in future requests for the original requested host and its subdomains.

Note: Requests for multiconnected URLs will include the cookie.
FirefoxSends domainless cookies in future requests only when the requested host is the same as the one for which the cookie was set (not for its subdomains).

Note: Requests for multiconnected URLs will not include the cookie.

F5 Networks Product Development is tracking a request for enhancement as CR118316 to add a domain to the Set-Cookie header when an origin web server sets a cookie without specifying a domain.

You can use an iRule to insert a domain when the origin webserver does not. The following iRule adds a domain to each Set-Cookie header that does not have one:

when HTTP_REQUEST {
   set h [HTTP::host]
}

when HTTP_RESPONSE {
   foreach c [HTTP::cookie names] {
      if { [HTTP::cookie domain $c] equals "" } {
         HTTP::cookie domain $c $h
      }
   }
}
