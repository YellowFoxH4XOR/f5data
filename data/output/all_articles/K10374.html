Known Issue

This is the result of a known issue. On rare occasions, when more than eight clients request FTP passive mode transfers through a BIG-IP virtual server configured to use the FTP profile, the ephemeral port that the BIG-IP randomly selects for the data connection may collide with the port already in use by an existing connection to the same virtual server. As a result, the BIG-IP TMM process panics and dumps core, and logs the following error message to the /var/log/tmm file:

panic: ../modules/hudfilter/ftp/ftp.c:863: Assertion "flow_create_ephemeral failed" failed.

When the process cores, the ephemeral port contained in the 227 response from the server is not translated to the port selected by the virtual server before the response is sent to the client. The client attempts to establish the data connection to the incorrect port, and the connection fails.

F5 Networks Product Development tracked this issue as CR109606 and it was fixed in BIG-IP versions 9.4.8 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM and ASM Release Notes.
