K11572: The asmqkview output file is truncated when there is insufficient free disk space in the root partition

Known Issue

Note: For more information about the asmqkview script, refer to: K6824: Overview of the asmqkview script.

This is the result of a known issue. The asmqkview script uses the /tmp directory for storing large temporary files before creating the final archive in the /var/tmp directory. Because the /tmp directory resides in the root partition ( / ), if the root partition does not have sufficient free disk space to hold the temporary files, the asmqkview output file will be truncated. This behavior results in the loss of crucial diagnostic information.

When this issue occurs, the asmqkview script returns one or more instances of the following error message:

mysqldump: Got errno 28 on write

This issue is more likely to impact BIG-IP ASM version 10.x due to the change in partitioning and reduced size of the root file system (a BIG-IP system formatted with the volumes disk-formatting scheme only reserves approximately 250 megabytes for the root volume).

Additionally, the issue is more likely to occur if you invoke the asmqkview script with the --add-proxy-log option, which tells the script to include the PROXY_LOG table in the archive.

F5 Product Development tracked this issue as ID 243879 (formerly CR138217), and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP ASM Release Notes.

This issue was also fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 Networks product hotfixes for BIG-IP version 10.x systems.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

Workaround

You can work around this issue by modifying the asmqkview script so that it stores the temporary files on a bigger file system. To do so, perform the following procedure:

  1. Log on to the BIG-IP ASM command line.
  2. To copy the asmqkview script to the /root/ directory, type the following command:

    cp /usr/sbin/asmqkview /root/
  3. Using a text editor, open the /root/asmqkview file for editing.
  4. Locate the following lines:

    Note: These are respectively line 87, 91 and 101 in BIG-IP version 10.0.0, line 90, 94 and 104 in BIG-IP version 10.0.1 and line 92, 96 and 106 in BIG-IP version 10.1.0.

    TMP_TARBALL="/tmp/asm_snapshot.tmp.$$.tar.gz"
    TMP_TARGET_DIR="/tmp/asm_snapshot_temp_dir.$$"
    TARGET_DIR="/tmp/${TARGET_DIR_ROOT_NAME}"
  5. Replace /tmp/ with /shared/tmp/.

    For example:

    TMP_TARBALL="/shared/tmp/asm_snapshot.tmp.$$.tar.gz"
    TMP_TARGET_DIR="/shared/tmp/asm_snapshot_temp_dir.$$"
    TARGET_DIR="/shared/tmp/${TARGET_DIR_ROOT_NAME}"
  6. Save the changes and quit the text editor.
  7. You can now invoke the modified asmqkview script by running the following command:

    /root/asmqkview

    If desired, you can pass the --add-proxy-log option to the script.

    Once the script has completed running, the final archive will be available in the /var/tmp/ directory.
