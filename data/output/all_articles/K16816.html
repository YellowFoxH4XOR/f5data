Known Issue

A newly generated default SSL certificate and key may not be displayed when you use either the Configuration utility or the Traffic Management Shell (tmsh).

This issue occurs when the following conditions are met:

  • You have generated a new default SSL certificate and key, following the procedure in the article: K13579: Generating new default certificate and key pairs for BIG-IP ssl profiles.
  • You view the default SSL certificate and key details using either the Configuration utility or tmsh utility.

Impact

Instead of the newly generated key pair, the previous default SSL certificate and key are displayed.

Note: You can safely ignore this issue; the system will use the new default certificate and key when you select them in an SSL profile.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system displays the old information when you view the default SSL certificate and key using either the Configuration utility or tmsh utility.

Workaround

To work around this issue, you can force the mcpd process to reload the configuration. To do so, perform the following procedure:

Impact of workaround: Rebooting the BIG-IP system disrupts traffic processing until the system is back up.

  1. Log in to the command line of the BIG-IP system.
  2. Create a null file in the /service/mcpd directory, with the filename forceload, by typing the following command:

    touch /service/mcpd/forceload

  3. Reboot the BIG-IP system by typing the following command:

    reboot
