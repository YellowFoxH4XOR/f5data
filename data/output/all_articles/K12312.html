Topic

The BIG-IP ASM system supports a set of predefined HTTP request methods. From the list of predefined methods, a BIG-IP ASM policy allows the GET, HEAD, and POST methods by default. You can allow additional methods by creating a new method entity in the BIG-IP ASM policy and selecting an act as method, instructing the BIG-IP ASM system how to treat the new method. All methods must be set to act as either POST or GET.

When a request contains an HTTP method that is not included in the predefined list of known methods, the BIG-IP ASM system issues the following error message:

HTTP protocol compliance failed

When a request contains an HTTP method that is included in the predefined list of known methods, but is not specified in the allowed methods list for the policy in question, the BIG-IP ASM system issues the following error message:

Illegal Method

The HTTP protocol compliance failed / Illegal HTTP Format violation covers a broader range of conditions than just the HTTP method. A condition may occur in which you may want to disable blocking for a greater set of HTTP compliance conditions, but still want to block illegal methods. To do so, you can create a new method in the Configuration utility by performing one of the following procedures:

Version 17.x and later:

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Security Policies > Policies List.
  3. Click on a policy.
  4. In the left navigation menu for that poiicy, click on the arrow next to HTTP Message Protection.
  5. Click on Headers.
  6. In the Methods section found on the right side, type the name of the method you want to block or choose it from the list that appears when selecting the field.
  7. Select either act as GET or act as POST for that method.
  8. Click Add.
  9. Click Save.
  10. Click Apply Policy.

Versions before 17.x:

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Headers > Methods.

    For BIG-IP ASM versions prior to 11.4.0, navigate to Application Security > Headers > Methods.

  3. Click Create.
  4. From the menu, select Current Edited Policy.
  5. Set Allowed Method Properties to Advanced.
  6. To define a new Custom Method and Act As Method setting (GET or POST), select Custom.
  7. In the Custom Method box, type the name of the method you want to block.
  8. For the Act As Method value, select GET or POST.
  9. Click Create.
  10. Click Apply Policy.


Note: When the policy is updated, the HTTP method that you created and then deleted from the allowed list will be entered into the table of valid, but not allowed methods. As detailed in the previous description, a method that is included in the list of valid methods, but not allowed in the policy, will cause an Illegal method violation. Please note,

  • HTTP header method does not have a separate disallowed list to keep track of illegal method.
  • A system administrator has to make sure to add all known/required methods (pre-defined or custom) used in his environment to the allowed method list.
  • Once "illegal methods" are moved to blocking, all methods that are not part of legal/allowed methods will be blocked by default.
