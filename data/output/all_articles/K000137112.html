K000137112: When using an encrypted key for HTTPS monitor, the node is incorrectly marked down

Type
Support Solution
Published
2023-10-04
Updated
2023-10-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000137112

Description

  • A https monitor when using an encrypted key in ServerSSL profile, marks the node down incorrectly.
  • When unencrypted key is used, the same monitor marks the node up.
  • Packet capture shows that the BIG-IP doesn't sent client certificate during SSL handshake.

Environment

  • BIG-IP LTM v13.x and above
  • Mutual Authentication or client certificate authentication is configured at the monitor level.

Cause

This is because the BIG-IP doesn't support using certificates with encrypted keys in the Server SSL profile used in https monitor that is performing MTLS or mutual authentication.

Recommended Actions

There is an Request For Enhancement for this feature with ID671462. The workaround is to unencrypted key for the https monitor.

  • Import a certificate that doesn't have an encrypted private key and use that in the https monitor.
(OR)
  • If unencrypted private key can't be obtained, please import or upload the encrypted key to BIG-IP and then follow the steps from K14912 - https://my.f5.com/manage/s/article/K14912#proc3 to save an unencrypted copy of the private key. Then import this to be used with the https monitor.

Note: Certificate with encrypted keys are supported to be used with a virtual servers using mutual authentication/client certificate authentication.
