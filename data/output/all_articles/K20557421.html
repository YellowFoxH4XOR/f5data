Description

  • Multiple emails are received for defined events in /config/user_alert.conf

Environment

  • Email alerts configured for state changes logged by TMM, for example:

    err tmm[12124]: 01010028:3: No members available for pool /Common/http-1

Cause

The log messages triggering the emails are logged multiple times, once for each TMM, similar to the below example:

err tmm2[12124]: 01010028:3: No members available for pool /Common/http-1
err tmm[12124]: 01010028:3: No members available for pool /Common/http-1
err tmm1[12124]: 01010028:3: No members available for pool /Common/http-1
err tmm3[12124]: 01010028:3: No members available for pool /Common/http-1

Recommended Actions

To avoid this issue, consider using similar mcpd alerts which only log once.

For example, the following message is only logged once as it is logged by the mcpd process, not TMM:

notice mcpd[8069]: 01070638:5: Pool /Common/http-1 member /Common/http-member-1:80 monitor status down

Note: The above message would trigger an email alert for every pool member monitor status change.

Alternatively, create custom SNMP traps, matching the same "No members available" message, for a specific TMM only.

For example, the following message is only logged by tmm0 (the first TMM), and a custom alert using this message would only trigger once:

err tmm[12124]: 01010028:3: No members available for pool

Refer to the following article to create custom SNMP traps:

  • K3727: Configuring custom SNMP traps
