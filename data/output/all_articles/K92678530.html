K92678530: Delete redundant or corrupted ElasticSearch indices using the index cleanup utility

Type
Knowledge
Published
2020-10-13
Updated
2026-01-29
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 7.1.0, 7.1.X, 7.0.X
Source
https://my.f5.com/manage/s/article/K92678530

Topic

You should consider using these procedures if your BIG-IQ system is affected by bug ID 942849 and under the following conditions:

  • You want to delete ElasticSearch's analytics indices that meet the following criteria:
    • Have not been aggregated and deleted due to ElasticSearch failures.
    • Have been created with corrupted mapping and prevent aggregation from all indexes.
    • Cause an out-of-memory (OOM) condition at processes, and low disk space at the ElasticSearch Cluster.
  • You want to avoid an ElasticSearch's node panic by preventing its filesystem from reaching full capacity.

Note: This article applies to BIG-IQ 7.0.x and 7.1.x. If your BIG-IQ version is 8.0.0 or later, or is running BIG-IQ 7.x with the ID 942849 bug fix included in an engineering hotfix, then the BIG-IQ system already includes indexes overflow protection and you do not need this article.

Description

The cleanup utility includes the delete_es_indices.py script, which removes ElasticSearch's indices when:

  • The duration (lifecycle period) exceeds the retention value times retention factor.
  • The indices are created with corrupted mapping and prevents aggregation from all indices.

The essential variables used in the script are defined as follows:

  • Index duration: The current time minus the time stamp generated during the index creation.
  • Index retention: The assigned retention period (retentionTime) of the ElasticSearch index.
  • Retention factor: The index is valid for deletion only if the index duration is larger or equal to the index retention multiplies the retention factor (1.5 by default).

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have administrative access to the BIG-IQ system.

Procedures

  • Download the index cleanup utility
  • Install the index cleanup utility
  • Manually run the cleanup script
  • Review the cleanup logs

Download the index cleanup utility

You can find and download the index cleanup utility file on the F5 Downloads site. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to the F5 Downloads site.
  2. Select BIG-IQ
  3. Select Centralized Management.
  4. Select the version 7.0.0 or 7.1.0
  5. Select the release. For example, v7.1.0.
  6. In Select a download file, download all of the following files to your workstation. You need to review and accept the EULA and choose a location from which to download.
    • delete_es_indices.tar.gz
    • delete_es_indices.tar.gz.md5

Note: Before extracting the downloaded TAR file, you can verify the MD5 checksum by transferring the MD5 file to the BIG-IQ system and using the following command to perform the verification:

md5sum --check delete_es_indices.tar.gz.md5

Install the index cleanup utility

You can install the cleanup utility by extracting the downloaded tarball on the ElasticSearch node. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Use an SCP client to copy the downloaded TAR file to the target ElasticSearch node (BIG-IQ Centralized Management or DCD).

    Note: For information about uploading files to an F5 system, refer to K175: Transferring files to or from an F5 system.

  2. Log in to the BIG-IQ command line.
  3. To extract the utility, go to the directory where the tarball is located and enter the following command:

    tar xvfz delete_es_indices.tar.gz -C /

  4. Verity that the following files are extracted to the corresponding directories:

    delete_es_indices.py under /shared/scripts/ directory
    delete_es_indices cronjob under /etc/cron.d/ directory
    delete_es_indices logrotate under /etc/logrotate.d/ directory

  5. The installation is complete and the cleanup utility checks and cleans ElasticSearch's indices with the given cronjob period (3 AM daily by default)

Manually run the cleanup script

You can manually run the index cleanup utility by running the included Python script. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ command line.
  2. To clean up the indices manually, use the following command syntax:

    python2.7 /shared/scripts/delete_es_indices.py --elastic_ips=localhost:9200 --delete_index <additional_arguments> --debug

    For example, to delete the redundant ElasticSearch's indices on the cluster member, enter the following command:

    python2.7 /shared/scripts/delete_es_indices.py --elastic_ips=localhost:9200 --delete_index --debug

    To run a query against the target host without deleting indices, enter the following command:

    python2.7 /shared/scripts/delete_es_indices.py --elastic_ips=localhost:9200 --delete_index --query --debug

    To delete ElasticSearch indices using a custom retention_factor with the assigned value 3 (1.5 by default), enter the following command:

    python2.7 /shared/scripts/delete_es_indices.py --elastic_ips=localhost:9200 --delete_index --retention_factor=3 --debug

Review the cleanup logs

The system generates the script logs in the /var/log/delete_es_indices.log file. To review the log, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ command line.
  2. To change to the /var/log directory, enter the following command:

    cd /var/log

  3. Use a Linux utility such as cat, or less, to review the log file.

    For example, to view the delete_es_indices.log file, enter the following command:

    cat delete_es_indices.log
