K000163488: BIG-IQ: BIG-IP discovery fails with “Failed to update (post or patch) device-group cm-bigip-allDevices” due to an expired device-group certificate

Type
Support Solution
Published
2026-09-30
Updated
2026-09-30
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.0
Source
https://my.f5.com/manage/s/article/K000163488

Description

You are unable to add a BIG-IP device to BIG-IQ and encounter the following error in /var/log/restjavad.log:

[INFO][XX Sep 2026 XX:XX:XX XXX][/cm/global/tasks/device-trust/<ID>/worker BigIPTrustTaskWorker] Failed to add device to bigip device group, state is POST_FAILED : Failed to update (post or patch) device-group cm-bigip-allDevices keys on device <IP address>.

This error is similar to the issue described in K34141619: Unable to discover BIG-IP “Failed to update (post or patch) device-group cm-bigip-allDevices keys on device”. However, the BIG-IP does not have an HTTPD configuration restricting POST or PATCH requests.

Environment

  • BIG-IQ CM
  • BIG-IP being added to BIG-IQ
  • Existing BIG-IP devices may already be successfully managed by BIG-IQ.
  • The BIG-IQ device-group key-pair certificate for cm-bigip-allDevices or cm-bigip-allBigIpDevices may be expired or invalid

Cause

During BIG-IP discovery, BIG-IQ uses the device-group key-pair certificates to establish trust and update the device-group keys on the BIG-IP. If the certificate associated with cm-bigip-allDevices or cm-bigip-allBigIpDevices is expired or invalid, the device-trust operation can fail.

To check the expiration date of the cm-bigip-allDevices certificate, run the following command on BIG-IQ:

$ restcurl /shared/device-group-key-pairs/cm-bigip-allDevices | jq -r '.certificate' | openssl x509 -noout -enddate
notAfter=Sep 15 XX:XX:XX 2026 XXX

To check the expiration date of the the cm-bigip-allBigIpDevices certificate, run the following command on BIG-IQ:

$ restcurl /shared/device-group-key-pairs/cm-bigip-allBigIpDevices | jq -r '.certificate' | openssl x509 -noout -enddate
notAfter=Sep 15 XX:XX:XX 2026 XXX

Answer/Recommended Actions

The actions or steps required to address the topic covered in the description.

  1.  Create a UCS backup of the BIG-IQ system.
  2. Regenerate the certificate and key pair for cm-bigip-allDevices:
    $ restcurl -X PUT /shared/device-group-key-pairs/cm-bigip-allDevices -d '{"groupName":"cm-bigip-allDevices","doGenerateKeyPair":true}'
  3. Regenerate the certificate and key pair for cm-bigip-allBigIpDevices:
    $ restcurl -X PUT /shared/device-group-key-pairs/cm-bigip-allBigIpDevices -d '{"groupName":"cm-bigip-allBigIpDevices","doGenerateKeyPair":true}'
  4. Confirm the expiration dates of these certificates using the procedure described above.
  5. Retry adding or rediscovering the affected BIG-IP.

Note: This is a non-disruptive operation. No re-discovery of existing BIG-IPs is necessary, and ongoing BIG-IQ operations are not interrupted.
