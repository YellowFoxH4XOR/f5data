Known Issue

DNS Express zone resource record statistics are not correctly reset.

This issue occurs when all of the following conditions are met:

  • The DNS server performs an incremental zone transfer (IXFR) to the BIG-IP system.
  • DNS Express zone names contain uppercase letters.
  • The zxfrd process restarts or the BIG-IP system reboots.

Impact

DNS Express zone resource record type-count statistics are inaccurate.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you use the tmsh show ltm dns zone command, output shows that the resource record type-count statistics value is reset to 0.

Workaround

To prevent this issue from occurring, you can create DNS Express zone names that use all lowercase letters.

To work around this issue, you can remove the /var/db/tmmdns.bin file and restart the zxfrd process. To do so, perform the following procedure:

Impact of workaround: Removing the binary file and restarting the zxfrd process requires the system to re-transfer the zone and rebuild its database. Depending on the number of configured zones, the process may take a significant amount of time to traverse the data file and reset the statistics. F5 recommends performing this procedure during a maintenance window to prevent interruption of client requests.
  1. Log in to the command line.
  2. Change the directory to /var/db/ by typing the following command:

    cd /var/db/
  3. Remove the tmmdns.bin file by typing the following command:

    rm -f tmmdns.bin
  4. Restart the zxfrd process by typing the following command:

    bigstart restart zxfrd
