Known Issue

Description

Redundant ARX systems may experience repeated failovers after an upgrade due to network interface stability issues.

This issue occurs when all of the following conditions are met:

  • The ARX systems were upgraded from 5.x to 6.x
  • The client and/or proxy-IP subnet is enabled on VLAN 1 (default VLAN)
  • You are using an ARX 1000, ARX 2000, ARX 4000, or ARX 6000 platform
  • The systems are configured in a High Availability pair
  • The Network Channel configuration is in use

Impact

Client service is interrupted each time devices fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Frequent ARX failover
  • You will see the following messages in the ARX syslog:

    :SQMD-0-NOTE-SQM_LOST_NETHB_REBOOT::Redundancy VLAN is down while the quorum disk is unreachable, rebooting immediately.

    :MGT_SVCMGR-0-NOTE-MSG5:: Received system shutdown notification, preparing for shutdown.

Workaround

Recovery workaround

To temporarily bring the network interfaces back to a stable state, remove the channel configuration and disable and re-enable all interfaces as they were before. To do so, perform the following procedure:

Disable and re-enable the interface configuration

Impact of workaround: Services will be unreachable while the interfaces are disabled and the issue may return if the ARX system is restarted.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enable config mode by typing the following command:

    config
  4. Take note of the interface and channel configuration by typing the following command :

    show running-config
  5. For recovery purposes, save the running configuration using the following command syntax:

    copy running-config configs [filename].cfg

    For example:

    copy running-config configs recovery_running.cfg
  6. Remove the channel configurations using the following command syntax:

    no channel [channel #]

    For example:

    no channel 1
  7. Enter the Interface configuration mode using the following command syntax:

    interface [interface type] [interface number]

    For example:

    interface gigabit 1/4
  8. Disable the interface, use the following command:

    shutdown 
  9. Exit the interface configuration mode and return to config mode by typing the following command:

    exit
  10. Repeat steps 7 through 9 until all interfaces used are disabled.
  11. Re-enable the previous configuration using the running configuration saved in step 5 with the following command syntax:

    run configs <running-config-name>

    For example:

    run configs recovery_running.cfg

  12. To verify the interface and channel configuration are as they were before, type the following command:

    show running-config

Permanent workaround

To permanently work around this issue, you must move all of your client and server subnets to a VLAN other than VLAN 1. To do so, perform the following procedures:

  • Reconfiguring the ARX interfaces to not use VLAN 1
  • Reconfiguring the ARX proxy IP addresses to not use VLAN 1

Reconfiguring the ARX interfaces to not use VLAN 1

If the ARX interfaces are using VLAN 1, you should configure a new VLAN and change the interfaces to that VLAN. To do so, perform the following procedure:

Impact of workaround: Extended downtime may be required.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enable config mode by typing the following command:

    config
  4. Edit the VLAN configuration using the following command syntax:

    vlan [vlan #]

    For example:

    vlan 1
  5. Remove the interfaces from the VLAN configuration using the following command syntax:

    no members [interface #]

    For example:

    no members 1/2
  6. Create a new VLAN using the following command syntax:

    vlan [vlan #]

    For example:

    vlan 10

  7. Enable interfaces on the new VLAN using the following command syntax:

    members

    For example:

    members 1/2
  8. Return to privileged mode by typing the following command:

    end

Reconfiguring the ARX proxy IP addresses to not use VLAN 1

If the ARX proxy IP addresses are using VLAN 1, you need to change the VLAN assigned to the proxy IP addresses. Due to difficulty with changing the VLAN assigned to a proxy IP, this procedure is more disruptive. To change an assigned proxy IP VLAN , you must save your configuration, remove it from the ARX system, reboot, edit the saved configuration with the correct proxy-IP addresses and VLAN, and replay it.

If you need assistance with this procedure, contact F5 Technical Support.

Impact of workaround: Requires a full system reconfiguration and reimport of your file servers.

Important: In a High Availability pair, both systems will require the configuration modification simultaneously.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enable config mode by typing the following command:

    config
  4. Save the startup configuration for recovery purposes using the following command syntax:

    copy startup-config configs [filename].cfg

    For example:

    copy startup-config configs recovery_startup.cfg
  5. Save the global configuration for later use using the following command syntax:

    copy global-config configs [filename].cfg

    For example:

    copy global-config configs recovery_global.cfg
  6. Save the running configuration for editing purposes using the following command syntax:

    copy running-config ftp://[user[:password]@]server/file-name

    For example:

    copy running-config ftp://10.1.1.19/ARX-run.cfg
  7. Using a text editor, edit the running configuration, removing the references to VLAN 1. The following example identifies sections in the running configuration that you will need to change:

    ;================================= vlan ==================================
    config
    vlan 1
    description "personnel dept."
    members 2/5 to 2/5
    members 2/6 to 2/6
    ;============================ config-if-vlan =============================
    config
    interface vlan 1
    ip address 192.168.25.5 255.255.255.0
    no shutdown
    exit
    exit
    ;================================ system =================================
    ip proxy-address 192.168.25.31 255.255.255.0 vlan 1 mac 1 processor 2.1
    ip proxy-address 192.168.25.32 255.255.255.0 vlan 1 mac 2 processor 2.2
    ip proxy-address 192.168.25.33 255.255.255.0 vlan 1 mac 3 processor 2.3
    ip proxy-address 192.168.25.34 255.255.255.0 vlan 1 mac 4 processor 2.4

  8. Delete the system configuration by typing the following command:

    delete startup-config
  9. Reboot the ARX system by typing the following command:

    reload
  10. Repeat steps 1 through 9 for the peer unit.
  11. After the reload has completed, the ARX system will clear of any configurations other than the boot configuration.
  12. Establish connectivity through the out-of-band management IP address.
  13. Log in to the ARX CLI.
  14. Enable config mode by typing the following command:

    config
  15. Copy the edited running configuration to the ARX system using the following command syntax:

    copy ftp://[user[:password]@]server/source-file dir file

    For example:

    copy ftp://jpublic@arxftp.f5.com/mod_running.cfg configs mod_running.cfg
  16. Configure the base ARX system using the edited configuration by typing the following command syntax:

    run configs <running-config-name>

    For example:

    run configs mod_running.cfg
  17. Repeat steps 12 through 16 on the peer unit.
  18. Identify the primary ARX system and configure the global configuration using the global configuration saved in step 5 with the following command syntax:

    run configs [filename].cfg

    For example:

    run configs recovery-global.cfg
  19. The ARX system will begin to re-import all of the associated shares after the global configuration is completed

Note: The global configuration will automatically sync to the peer device.
