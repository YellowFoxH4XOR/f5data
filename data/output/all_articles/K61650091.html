Description

This article explains the behaviour of BIG-IP TCP timestamp negotiation with pool-members.  

Environment

  • TCP 3WHS
  • TCP Profile
  • TCP MSS
  • TCP Timestamp

Cause

None

Recommended Actions

TCP timestamp is one of the fields in TCP headers which helps to measure RTT between two endpoints. In BIG-IP client side  and server side TCP timestamp negotiates independently, and there are few TCP profile settings which impacts BIG-IP TCP timestamp negotiation with pool members.

There are three TCP profile setting which contributes to TCP time-stamp negotiation and those  settings are -  proxy-options, proxy maximum-segment,Timestamps Extension for High Performance.

         (a) Proxy-options doesn't play an effective role and time-stamp negotiation is handled by setting "Timestamps Extension for High Performance". Below are the repro results -

                client side -- tstamp enabled,proxy option disabled
        server side -- tstamp enabled,proxy option disabled
        client side and server side both negotiates tstamp.   --> Proxy option is disabled but still server side negotiates tstamp.

        client side -- tstamp enabled,proxy option enabled
        server side -- tstamp disabled,proxy option disabled
        client side negotiates tstamp but server side doesnt negotiates tstamp.

        client side -- tstamp enabled,proxy option enabled
        server side -- tstamp disabled,proxy option enabled
        client side negotiates tstamp but server side doesnt negotiates tstamp    --> Proxy option enabled on both profile but still server side doesnt negotiate tstamp.

        (b) If "proxy-mss" is also enabled then along with "proxy-options" and  "Timestamps Extension for High Performance",

               clientside mss < = serverside mss: If proxy-mss is enabled on BOTH sides, the serverside will adjust its maxopd to allow the clientside and serverside mss to be the same.
               0 < clientside mss - serverside mss < = 12: if proxy-mss is enabled on both sides, proxy-options is enabled on the serverside, AND timestamps are enabled on the serverside, then BIG-IP will disable timestamps on the serverside and adjust serverside maxopd as needed to make the mss match.
               clientside mss - serverside mss > 12: maxopd will be the full value on both sides regardless of profile, as there's nothing the BIGIP can do to make the mss match.
