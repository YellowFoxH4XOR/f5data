Description

restjavad can leak memory associated with API usage statistics. This issue is tracked as ID 1826505.
The leak needs to be cleared in a specific way. Restarting restjavad or upgrading software won't clear it fully.
restjavad periodically updates a file, /var/log/restjavad-api-usage.json with these statistics.
The size of this file, to some degree, can be used to see whether the memory leak is present.
This article shows a procedure (A) to clear a bigger leak and a procedure (B) to clear a smaller leak and stop the leak getting big again.

Environment

BIG-IP used in high availability clusters.
The leak grows on standby systems. It will persist when such a system is made active, so active systems may have leaked memory if they were previously standby for long enough.
The leak size seems related to how long a device has spent standby.

Cause

Bug ID 1826505

Recommended Actions

Mitigation of the restjavad API statistics memory leak, ID 1826505.

Procedure A 

Use this procedure to clear a well developed leak, which shows as medium to large /var/log/restjavad-api-usage.json file, ~500KB to tens of MB.

Note: qkviews typically truncate this file to 5MB or less if it is larger. The qkview_run.data in top level of qkview will show its true size.

 

From bash:

Stop restjavad:
# bigstart stop restjavad

Truncate the file to empty it:
# truncate -s 0 /var/log/restjavad-api-usage.json

This command should show the file as empty, zero bytes long.
# ls -l /var/log/restjavad-api-usage.json

Start restjavad (if iAppsLX, guided config in use restart restnoded as well 15s or so afterwards)
# bigstart start restjavad

Procedure B 

Use this procedure to clear smaller leaks, or to prevent leak developing in size significantly.

This doesn't require restart of restjavad and should be low impact, as long as the stats leak is small.
If the leak is well developed this may be slow and restjavad may run out of memory and restart, or engage in CPU intensive garbage collection.

The following command instructs restjavad to delete the accumulated API usage statistics, so is useful to clear a small leak.

/bin/curl -u admin: -X DELETE http://localhost/mgmt/shared/diagnostics/api-usage > /dev/null

This procedure can be automated to clear the leak on a regular basis by turning it into a cron job as below.
This will run the command around 3am every day

From bash:

Create a file with the command above, and make it executable:

==copy and paste below=========================================================================
cat > /var/tmp/restjavad-stats-cleaner.sh<<END
#!/bin/sh

/bin/curl -u admin: -X DELETE http://localhost/mgmt/shared/diagnostics/api-usage > /dev/null

END
chmod ug+x /var/tmp/restjavad-stats-cleaner.sh
mv /var/tmp/restjavad-stats-cleaner.sh /etc/cron.daily/restjavad-stats-cleaner.sh

==copy and paste above=========================================================================
