K000161580: F5 WAF for NGINX Override Rules for "Multiple Slashes" violation not functioning as expected.

Type
Support Solution
Published
2026-07-28
Updated
2026-07-29
Applies to
  • NGINX Products
  • F5 WAF for NGINX: 5.11.X, 5.11.2, 5.11.1, 5.11.0
Source
https://my.f5.com/manage/s/article/K000161580

Description

When using F5 WAF for NGINX (NGINX App Protect), enabling an override rule to disable the "Multiple slashes" evasion sub-violation caused the sub-violation to be disabled globally for all requests, not just those matching the override condition. This resulted in all requests with multiple consecutive slashes being allowed, contrary to the intended policy behavior.

Environment

  • F5 WAF for NGINX (NGINX App Protect), version 5.11.2
  • WAF policy with "VIOL_EVASION" and "Multiple slashes" sub-violation enabled by default
  • Custom override rule attempting to disable "Multiple slashes" for specific URIs

Cause

The root cause was a software defect in F5 WAF for NGINX where the presence of an override rule disabling the "Multiple slashes" evasion sub-violation resulted in the sub-violation being globally disabled, rather than scoped to the override rule's condition. This led to unintended bypass of the "Multiple slashes" check for all requests.

Answer/Recommended Actions

Upgrade F5 WAF for NGINX to version 5.13.1 or later, where the bug is fixed. Validate override rule behaviour after upgrade to ensure the "Multiple slashes" sub-violation is only disabled for requests matching the override condition.
