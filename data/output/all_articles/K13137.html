Known Issue

BIG-IP WebAccelerator responds with an S10205 code to all subsequent requests for an object that is in the Smart Cache. This issue occurs when all of the following conditions are met:

  • The BIG-IP system is licensed and provisioned with both ASM and WebAccelerator
  • The BIG-IP system is configured with a single HTTP Class that has both ASM and WebAccelerator enabled
  • BIG-IP WebAccelerator has a copy of the affected object in its Smart Cache
  • The BIG-IP ASM Policy Builder is running

The following sequence of events occurs when this issue is encountered:

  • The BIG-IP ASM Policy Builder inserts the Surrogate-Control: content=”ESI/1.0,no-store” header when processing a request
  • The modified request is then forwarded to BIG-IP WebAccelerator
  • BIG-IP WebAccelerator stops caching objects when it received the request with the Surrogate-Control: content=”ESI/1.0,no-store” header, at the same time any existing objects in the Smart Cache will be invalidated
  • BIG-IP WebAccelerator forwards the request to the origin web server (OWS)
  • The OWS responds back to BIG-IP WebAccelerator
  • BIG-IP WebAccelerator then returns the responses to the client with X-PvInfo code S10205 for all objects
  • For subsequent requests, the BIG-IP ASM Policy Builder continues to insert the Surrogate-Control: content=”ESI/1.0,no-store” header when processing the requests and forward to BIG-IP WebAccelerator
  • BIG-IP WebAccelerator forwards the requests to the OWS
  • The OWS responds back to BIG-IP WebAccelerator
  • BIG-IP WebAccelerator does not cache the object and returns the responses to the client with X-PvInfo code S10205 instead of S10201

Other than BIG-IP WebAccelerator responding with an incorrect X-PvInfo header code, the BIG-IP WebAccelerator functions as normal.

Impact

This issue is cosmetic as it provides the wrong X-PvInfo header code, but BIG-IP WebAccelerator function is not impaired.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP WebAccelerator responds with an S10205 code in the X-PvInfo header for all subsequent requests of the affected object
