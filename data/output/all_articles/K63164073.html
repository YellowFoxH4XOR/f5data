Known Issue

A virtual server may remain in the SYN cookie protection mode due to an incorrect SYN cache count.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured with both the FastL4 and an HTTP profile.
  • The virtual server has SYN cookie protection enabled.
  • The SYN cookie protection mode gets activated (for example, due to a SYN flood attack) on the virtual server.

    Note: For more information about SYN cookie protection activation, refer to K14779: Overview of BIG-IP SYN cookie protection (11.3.x - 12.x).

The SYN cookie protection mode can be activated when the SYN cache count exceeds a certain threshold defined by the pvasyncookies.virtual.maxsyncache database variable. This issue is a result of the SYN cache count not decrementing during a SYN flood attack. As a result, the SYN cookie protection mode remains activated due to the incorrect SYN cache count.

Impact

The affected virtual server may incorrectly remain in the SYN cookie protection mode indefinitely after a SYN flood attack.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you type the following command syntax, you notice that the Current SYN Cache count does not decrease, even after the SYN flood attack has stopped:

    tmsh show /ltm virtual <virtual_server> | grep "Current SYN Cache"

    The command and output from a virtual server named test_vs may look similar to the following example:

    tmsh show /ltm virtual test_vs | grep "Current SYN Cache"

      Current SYN Cache                          4.0K

  • In the /var/log/ltm file, your BIG-IP system keeps logging warning messages similar to the following example:

    01010038:4: Syncookie threshold 1000 exceeded, virtual = 192.168.1.1:80
