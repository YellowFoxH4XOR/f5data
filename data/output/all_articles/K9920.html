Topic

You can create a fully-meshed IPSec VPN between two FirePass controllers. This configuratuion provides one way to use a pair of FirePass controllers to substitute for a WAN or router-terminated IPSec connection between two different networks. 

Note: F5 Networks does not recommend using a pair of FirePass controllers as a substitute for a WAN or router-terminated IPSec connection between two different networks. For more information, refer to K6953: Performance and scalability of IPSec tunnels.

The following configurations are required when creating a fully-meshed IPSec VPN between two FirePass controllers:

  • Server 1 must be able to communicate with Server 2
  • Network Access clients on FirePass-1 must be able to communicate with Server 1 and Server 2
  • Network Access clients on FirePass-2 must be able to communicate with Server 1 and Server 2
  • The Use NAPT to Access LAN option in the Network Access settings is used to simplify routing

IPSec can fulfill these requirements; however, the source and destination addresses are considered in IPSec policies (unlike normal network routes). Therefore, you must build three separate tunnels to satisfy the first three requirements on both FirePass controllers.

To create a fully-meshed IPSec VPN between two FirePass controllers, you must complete the following procedures:

  • Creating IPSec policy 1 on FirePass-1
  • Creating IPSec policy 2 on FirePass-1
  • Creating IPSec policy 3 on FirePass-1
  • Creating IPSec policy 1 on FirePass-2
  • Creating IPSec policy 2 on FirePass-2
  • Creating IPSec policy 3 on FirePass-2
  • Enabling Use NAPT to access LAN
  • Applying Changes

Creating IPSec policy 1 on FirePass-1

This policy will allow Network Acess clients connected to FirePass-1 to access the 30.0.0.0/24 network, which sits behind FirePass-2.

  1. Log in to the FirePass Administrative Console.
  2. Click Device Management.
  3. Click Security.
  4. Click IPsec Configuration.
  5. Click New Configuration.
  6. In the Connection name field, type a connection name.
    For example:
    host100tonet30
  7. In the Local endpoint field, type the following IP address:
    10.0.0.100
  8. Select Gateway from the drop-down menu next to the Local endpoint field.
  9. In the Local subnet field, enter the following: 
    10.0.0.100/32
  10. In the Remote endpoint field, type the following IP address:
    10.1.0.100
  11. Select Gateway from the drop-down menu next to the Remote endpoint field.
  12. In the Remote subnet field, enter the following: 
    30.0.0.0/24
  13. In the Shared secret field, type a password that you will enter on both controllers. 
  14. In the Confirm shared secret field, type the password again. 
  15. In the Key lifetime field, enter the following:
    480 minutes
    This value will prompt the servers to exchange their shared secret every eight hours.
  16. Select the Perfect Forward Secrecy check box.
  17. Click Save.

Enabling Use NAPT to access LAN

To enable the Use NAPT to Access LAN option, select the Use NAPT to access LAN check box on the Network Access: Global Settings page.

Important: You will need to enable this option on both FirePass controllers.

Using the FirePass Network Address Port Translation (NAPT) feature, you translate the client's virtual subnet IP address to the IP address of the FirePass controller. If the FirePass controller possesses multiple IP addresses, the IP address used in NAPT will be the address of the FirePass interface through which the client's packets exit (and translate in reverse for the return packets). The interface through which the client packets exit is determined by routing to the packet destination. Using NAPT, you can avoid any routing infrastructure additions or changes, because the routing infrastructure only needs to know how to route to the FirePass controller, not the virtual subnets behind the FirePass controller.

Applying Changes

Once the policies have been configured and NAPT has been enabled on both FirePass controllers, you can make your configuration operational. To do so, perform the following procedure:

  1. Log in to the FirePass Administrative Console.
  2. Click Device Management.
  3. Click Security.
  4. Click IPSec Configuration.
  5. Click the Apply Configuration button.
