K000157281: BIG-IP may enforce the selection of FFDHE on TLSv1.3 when preferred over other DH groups

Type
Support Solution
Published
2025-11-06
Updated
2026-06-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.0, 21.0.X, 21.0.0, 17.5.1, 17.5.X, 21.X.X, 21.1.X, 21.1.0, 17.1.3
Source
https://my.f5.com/manage/s/article/K000157281

Description

On BIG-IP versions where Bug ID 1352213 fix was included, it may be observed that a Hello Retry Request is being issued by the BIG-IP during the TLSv1.3 handshake, containing the key share for FFDHE and enforcing its usage, even when other groups key shares were included by the client.

Important: using FFDHE increases resource consumption and the system may experience an impact to performance compared with other groups based on Elliptic Curve Cryptography, e.g. X25519, secp256r1. The larger the key size the higher the performance impact could be.

Environment

Product: BIG-IP LTM

Version: those where Bug ID 1352213 fix was included.

Protocol: TLSv1.3

Configuration:

  • Cipher group including FFDHE and other groups (e.g., X25519, secp256r1)
  • Cipher group order preferring FFDHE groups
  • Client listing FFDHE as a supported group on Client Hello but no FFDHE key share present

Cause

When the prior conditions are met, BIG-IP's current implementation is prioritizing the usage of FFDHE (Finite-Field Diffie-Hellman Ephemeral) groups during handshake negotiation. If FFDHE cipher group ordering is preferred over other groups, and the Client Hello includes support for any of these groups but no key share, the BIG-IP will respond the Client Hello with a Hello Retry Request, including only the key share for the FFDHE group selected. This behavioural difference is being tracked on Bug ID 2141297 in order to make it consistent with other groups. Hello Retry Request and Server group selection are described in RFC 8446.

Recommended Actions

If this behaviour is creating a problem or is undesirable in your environment, there are many options while using the cipher rules or cipher groups configuration.

  1. Create a custom cipher rule listing FFDHE undesired groups, and exclude them in the cipher group to be used.
  2. Create a custom cipher rule listing the desired groups and include only those in the cipher group to be used.
  3. Select the most appropriate cipher group ordering for your environment that prioritize other groups before FFDHE.

The configuration and groups can be reviewed as follows:

  • GUI: Local Traffic ›› Ciphers : Groups ›› <cipher_group_name> ›› Group Audit
  • CLI: tmsh show ltm cipher group <cipher_group_name>
