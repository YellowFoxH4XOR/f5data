K13036194: The HTTP/2 profile appends semicolon when a request has one or more cookies

Type
Known Issue
Published
2017-10-10
Updated

Applies to

  • BIG-IP LTM: 13.0.0, 12.1.3, 12.1.2

Known Issue

The HTTP/2 profile appends a semicolon character (;) when a request has one or more cookies.

This issue occurs when all of the following conditions are met:

  • The HTTP/2 profile is configured on a virtual server.
  • The virtual server on the BIG-IP system receives a client request that contains one or more HTTP cookies.

Impact

The system forwards the request to a back-end server and contains an extra semicolon at the end of the cookie string.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • With an HTTP/2 profile, a virtual server on a BIG-IP system receives requests and handles cookies converting those into a cookie string. The BIG-IP system concatenates the cookie pairs with a semicolon (%3B) and a space (%20) in the cookie string. The system also appends this delimiters pair to the last cookie pair.

Workaround

To work around this issue, you can apply a custom iRule to the virtual server to modify the HTTP header removing the extra delimiter. To do so, perform the following procedure:

Impact of workaround: F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name for the iRule.
  5. In the Definition box, enter the following text:

    when HTTP_REQUEST {
        if {[HTTP::header value "Cookie"] contains ";"}
        {
        set new_header [string range [HTTP::header "Cookie"] 0 end-2]
        log local0.notice "$new_header"
        HTTP::header replace "Cookie" $new_header
       }
    }
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. Click the affected virtual server.
  9. Click the Resources tab.
  10. In the iRules section, click Manage.
  11. From the Available column, select the iRule you previously created.
  12. Click << to move the iRule to the Enabled column.
  13. Click Finished.
