Description


F5OS tenants may fail to fully deploy after upgrading F5OS-A host to v1.4.0.

Symptoms may include:
  • Tenant not having license installed when a valid license exists as in effect.
  • Tenant license error:
    • "Cannot connect to mcpd. Your preferences and aliases will not be available until it comes back up. The connection to mcpd has been lost, try again."
  • api_svc_gateway crashing/restarting frequently
  • ConfD logs showing signs of Certificate & Key errors or failures.
 

Environment

  • F5OS-A upgraded to v1.4.0.
  • Tenant(s) deployed.
 

Cause

When upgrading F5OS-A to v1.4.0 automatic firmware updates happen in the background. These can interfere with the encryption key retrieval for the API Service Gateway, causing a new key to be generated and resulting in the api-service-gateway restarting frequently.
 

Recommended Actions

As a workaround, you may delete the offending certificate and key CDB files, restart the daemons and reboot.

Please note the workaround will result in the loss of the tenant data.

1. Delete CDB entry for pvt_key through 
[root@appliance-1 log]# docker exec -it system_manager bash
[appliance-1(system-manager) /var/F5/partition]# /confd/bin/confd_cmd -c "mdel /tenants/platform-self-signed-cert/self-signed-cert"

2. Restart system_TPOB. 
[root@appliance-1 ~]# docker restart system_TPOB

3. Restart system_api_svc_gateway. 
[root@appliance-1 ~]# docker restart system_api_svc_gateway

4. Reboot 
[root@appliance-1 ~]# reboot
