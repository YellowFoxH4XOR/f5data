Known Issue

When you create administrator role user accounts, they may not retain the assigned role.

This issue occurs when all of the following conditions are met:

  • You configure your BIG-IP system as part of a Sync-Failover device group.
  • You configure the REST framework's gossip mechanism.

    The REST framework gossip mechanism works automatically but may not be ready. You can confirm that it is ready by entering the following command:

    restcurl shared/resolver/device-groups/tm-shared-all-big-ips/devices

    The output must display all your devices and show that they all have the same version and the same restFrameworkVersion.

  • You create a new administrator role user account using the iControl REST interface, BIG-IP Configuration utility, or tmsh commands.

Impact

The newly created user account does not retain the assigned administrator role.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view the new user account role configuration directly after you create it, the assigned user's role is set to the expected administrator role.
  • When you view the new user account role configuration a short period of time after you create it, the user's role is erroneously set to the guest role.

Workaround

To work around this issue, you can modify the REST framework gossip mechanism to trigger a rebuild of the REST device groups. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure causes the gossip mechanism to temporarily stop synchronizing.

  1. Log in to the command line of the primary (active) BIG-IP device.
  2. Enter the following restcurl command to disable failover:

    restcurl -X PATCH tm/shared/bigip-failover-state -d '{"isEnabled": false}'

  3. To clear REST devices from the device group, run the following command:

    restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices

    Note: The iControl REST framework gossip mechanism configuration rebuild should occur automatically after you run this command.

  4. Before you run any additional iControl REST commands, enter the following command to ensure that the REST framework gossip mechanism is ready:

    restcurl shared/resolver/device-groups/tm-shared-all-big-ips/devices

    Important: The command output must show all of the device group devices and show that all the devices have the same BIG-IP version and restFrameworkVersion.
