Description

HTTPS monitor fails due to the result a 0-byte certificate being sent during the SSL handshake.

F5 is not sending the client certificate to the pool member in Handshake Protocol: Certificate.

You can verify it using a tcpdump of HTTPS monitor and enabling monitor logging for a pool member: 

  • K12531 : Troubleshooting health monitors
    • Using tcpdump to capture the monitor traffic
    • Enabling monitor logging for a pool member

Environment

  • In-tmm monitoring is disabled (default).
  • An HTTPS monitor is using a client certificate configured in the server-ssl profile.
  • The server-ssl profile has been modified but without changing the configured certificate or key.

Cause

Bug ID 750318 : HTTPS monitor does not appear to be using cert from server-ssl profile

The resulting message passed from mcpd to bigd will contain only the incremental modification to the profile, which bigd treats as a complete profile, meaning that it is possible for the certificate and key parameters to be lost.

Recommended Actions

  • As a workaround, restart bigd process by running the following command:
Impact of workaround: Nodes may temporarily be marked down as the bigd process restarts.
bigstart restart bigd
  • Consider upgrading the version below to fix the bug: 15.0.0, 14.1.2.3, 13.1.1.5
