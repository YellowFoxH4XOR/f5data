K000140117: F5OS reporting "Insufficient memory on node" message when attempting to stop and re-deploy tenant

Description

F5OS system is reporting a message similar to the following when a running (Deployed) tenant is moved to Provisioned or Configured, then back to Deployed, in a short space of a time:

Insufficient memory on node Tenant deployment will be processed when requested memory/hugepages available

Environment

  • F5OS tenant
  • Tenant deployment

Cause

This might happen if you stop a running tenant, then attempt to deploy it again, seconds later. In this case, memory resources haven't yet been released from the tenant's previous virt-launcher pod, so kubernetes may not be able to schedule another virt-launcher pod to the blade until that one was cleaned up and resources returned to the available pool.

This would be more likely to occur if the tenant in question is configured to use a large amount of memory (or multiple tenants are running and using a large amount of memory in total).

Recommended Actions

This message is not cause for concern, as long as it goes away without user intervention and the tenant eventually starts up without issues.

If the message persists, there may be an issue with the system that requires further investigation to diagnose and fix. Generate controller and partition qkviews, then open a case with F5 Support, referencing this article.

Additional Information

This message might also appear if the node (blade) has a genuine, persistent issue with available memory. In that case, the issue won't go away on its own.
