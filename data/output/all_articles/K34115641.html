Issue

Error Message

err mcpd[<PID>]: 01071c08:3: Cannot determine whether agent type <Name of Agent> is appropriate for access policy (/<Directory>/<Application Name>/<Policy Name>) of type access-policy because it is not attached to apm profile access using access-policy property.

In this error message, note the following:

  • <PID> is the process ID for the mcpd process.
  • <Name of Agent> is name of the agent type that is associated with the access policy. 
  • <Directory>  is the directory location for the application.
  • <Application Name> is the name of the application that references the policy.
  • <Policy Name> is the name of the access policy.

For example:

err mcpd[5224]: 01071c08:3: Cannot determine whether agent type aaa-active-directory is appropriate for access policy (/Common/My-Exchange.app/exch) of type access-policy because it is not attached to apm profile access using access-policy property.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when one of the following condition is met:

  • You validate the bigip.conf file and an access policy is not attached to a BIG-IP APM access profile.

    Note: The mcpd process logs the error.

  • You restart the system or upgrade, export, or import an access profile.

Impact

Access policy validation fails and the BIG-IP system cannot load the configuration.

Recommended Actions

To resolve this issue, perform one of the following procedures, depending on the state of your BIG-IP system:

  • Saving the running configuration
  • Performing a configuration synchronization from a peer device
  • Restoring the system configuration from a UCS file
  • Manually editing the bigip.conf to fix the reported error

Saving the running configuration

If your BIG-IP system configuration is running and successfully loaded, perform the following procedure to save the system's running configuration to the bigip.conf file:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To verify the state of the mcpd process, enter the following command:

    tmsh show sys mcp-state

    Output similar to the following may appear, indicating that your BIG-IP system configuration is running and successfully loaded:

    Sys::mcpd State:
    --------------------------------------------------------
    Running Phase                   running
    Last Configuration Load Status  full-config-load-succeed

  2. After you verify that your BIG-IP system configuration is running and successfully loaded, enter the following command to save the running configuration:

    tmsh save sys config

Performing a configuration synchronization from a peer device

If your BIG-IP system is part of a high-availability (HA) pair and the peer device is not experiencing the issue, perform a configuration synchronization (ConfigSync) from the peer device to fix the issue. For more information, refer to K13920: Performing a ConfigSync using the Configuration utility.

Restoring the system configuration from a UCS file

If you have a UCS file that contains the latest configuration, you can perform a restore using a UCS file. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

Manually editing the bigip.conf to fix the reported error

You can edit the bigip.conf file manually to fix the reported error. The error is reported because there is an access policy object that is not attached to an access profile. The corresponding access profile does not exist. To address this, you can manually add an access profile object in the bigip.conf file with the affected access policy attached to it. To do so, perform the following procedure:

Impact of procedure: You should perform this only as a last resort and if you are familiar with the syntax and expressions in the bigip.conf file. Incorrect modification of the bigip.conf file may result in the permanent loss of your system's configuration. F5 recommends performing this only when your BIG-IP system is already unable to load its configuration or during a scheduled maintenance.

  1. Make a backup copy of the original file by entering the following command:

    cp /config/bigip.conf /config/bigip.conf.K34115641

  2. Note the name of the access policy in the error message. Using the previous example policy name:

    /Common/My-Exchange.app/exch

  3. To manually add an access profile object in the bigip.conf file, open the file with a text editor and perform the following sub-procedure:
    1. Locate any existing access profile object. It may appear similar to the following example:

      Note: In this example, an access policy is associated with the access profile object.

      apm profile access /Common/example_name {
          accept-languages { en }
          access-policy /Common/example_name
      [...]
          log-settings {
              /Common/default-log-setting
          }
          modified-since-last-policy-sync true
          type system-authentication
          user-identity-method http
      }

    2. Duplicate the stanza by copying and pasting it into the bigip.conf file.
    3. In the duplicated stanza, replace all instances of the duplicate name with the name of the access policy you noted in step 2.  For example, replace all instances of example_name with /Common/My-Exchange.app/exch
    4. Save the file and exit the text editor.
  4. To load the configuration, enter the following command:

    tmsh load sys configuration

  5. When the configuration successfully loads without the error, review your access profile and access policy to ensure they are correctly configured.
