K000138386: Once applied profile with idle timeout "immediate", changing to another profile with different idle timeout, the new value won't apply.

Type
Support Solution
Published
2024-01-29
Updated
2024-01-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 17.1.1, 16.1.4, 15.1.9, 15.1.10
Source
https://my.f5.com/manage/s/article/K000138386

Description

After applying a fastL4 profile with idle timeout "immediate" on the virtual server, and changing to another profile - with a different idle timeout value, the virtual server remains in the idle timeout "immediate" behavior.


Environment

  • LTM, fastL4 profile.
  • First, apply a fastL4 profile with "idle timeout immediate" on a virtual server.
  • Change the fastL4 profile to another one with a different idle timeout - for example, an idle timeout of 5 seconds.

Cause

Bug ID1494217 was filed for this issue.


Recommended Actions

To workaround this issue, delete the virtual server and reconfigure it with the profile you desire.
