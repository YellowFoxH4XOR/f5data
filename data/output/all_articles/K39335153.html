Description

Automatic Update check fails when BIG-IP is configured to use a Proxy Server

Environment

  • Proxy Sever (db proxy.host, db proxy.port, db proxy.protocol) Configured
  • DNS not configured in System > Configuration > Device > DNS
  • Automatic Update check fails
  • Software Version 12.1.x
Cause

In the script /usr/bin/updatecheck BIGIP attempts to resolve callhome.f5.com before sending to the proxy server.
If there is no DNS configuration, then the Automatic Update check fails.

Recommended Actions

There are two possible solutions:
  • Upgrade to software version 15.1.0.x where the script has been modified to not resolve callhome.f5.com before sending to the proxy server.

    -- OR --
     
  • Modify the /usr/bin/updatecheck script:
    1. Allow changes to files under /usr; run the command:

      mount -o remount,rw /usr

    2. Backup /usr/bin/updatecheck using the command:

      cp /usr/bin/updatecheck /usr/bin/updatecheck.bak

    3. Edit /usr/bin/updatecheck
      • Open the file /usr/bin/updatecheck using any file editor and comment line 343; which is line:

        my $service_ip = F5::ServerLookup::get_ip_address($service_name, $outbound_call_timeout);

      • Then change $service_ip to $service_name in line 383,385. It should then look like below:

        ...
        -> uri ("$service_name$url")
        ...
        -> proxy ("https://$service_name$url", proxy => ['https' => undef], %proxy_opts)
        ...

    4. Save and quit

    5. Alter /usr back to read-only with the command:
      mount -o remount,ro /usr
