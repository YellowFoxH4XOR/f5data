K000139886: Certificate Failure due to Issuer

Published
2024-07-05

Applies to

Source

Description

SSL connections failing due to iRule that checks Certificate details

 

Environment

  • BIG-IP LTM
  • iRule that checks the details of the certificate (e.g. Issuer Organization)

 

Cause

Incorrect certificates are being negotiated between clients/servers and LTM

 

Recommended Actions

To confirm certificate details (such as issuer organization) is different from the data-group configured to check the details of the certificate, you can do the following steps:

 

1. Confirm any similar LTM logs:

Client CN not found or certificate has incorrect issuer (CN: CN=<canonical name>; Issuer: O=<organization>)

 

2. Check for any configured data-group similar below:

ltm data-group internal /<partition>/<partition name> {
 records {
   CN=<Canonical Name> { 
      data "<Information checked from the certificate>"

}

3. Confirm with the configuration of any related iRule:

 

list ltm rule <iRule name>

 

ltm rule <iRule name> {

   partition <partition>

when RULE_INIT {

 set static::debug 0

 set static::client_CNs "<partition name> "

}

when CLIENTSSL_CLIENTCERT {

 # Get Issuer organization

 regexp <expression>

 # Get client CN

 regexp <expression>

 if { [class lookup $CN $static::client_CNs] == $issuer } {

   log -noname "Client Certificate Accepted: $CN (Org: $issuer)"

 } else {

   log -noname "Client CN not found or certificate has incorrect issuer (CN: $CN; Issuer: $issuer)"
}

4. Further confirmation can be done thru packet capture relating to the actual certificate details:

a. From the packet capture, expand related connection, go to 'Transport Layer Security' > 'TLS 1.2 Record Layer' > 'Handshake Protocol: Certificate' > 'Certificates' 

b. Look for the following details:

Certificate: <certificate name> 
Issuer: <certificate issuer details>

 

If the above details are confirmed, the issue is with the certificate being negotiated by the clients/servers and the LTM. Confirm with the customer that the appropriate certificates are installed properly from the clients or servers.
