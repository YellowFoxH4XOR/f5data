Topic

Will BIG-IP fail over if the user space becomes unstable?

In versions prior to 4.5.11 and 4.6.3, BIG-IP will not reboot if user space becomes unstable. As a result, the active BIG-IP could become unresponsive, causing the standby system to become active. Although this occurs only in rare situations, it could result in an unintended active-active situation if the unstable BIG-IP recovers.

Starting in versions 4.5.11 and 4.6.3, you can enable a test timer, deadman_timer, that will prompt BIG-IP to reboot if user space becomes unresponsive.

Enabling the deadman_timer

Important: You must disable this feature before you apply any upgrades.

To enable this feature, type the following command:

set_deadman_timer <seconds>

Where <seconds> is the number of seconds that the kernel will wait for BIG-IP to reset the timer. BIG-IP attempts to reset the timer every sixty seconds, so the value must be greater than 60 seconds. F5 Networks recommends that you use a value of 183 seconds.

When you enable this feature, it places the following line in the /config/crontab file:

*/1 * * * * root /sbin/sysctl -w kern.deadmantimer=18300

This line is required and the timer will not reset once per minute without it, which will cause the timer to run to zero and reboot the system. If this line is missing or cron is not running, one of the following warnings will be displayed.

No deadman timer command in /config/crontab
Current deadman timer value: 17458 ticks = 174 seconds
===========================================================
Warning: panic in 174 seconds !!!!


Current deadman timer in /config/crontab: 183 seconds
===========================================================
Warning: Cron daemon is not running
===========================================================
Current deadman timer value: 14415 ticks = 144 seconds
===========================================================
Warning: panic in 144 seconds !!!!

If you receive one of these messages, immediately reset the timer by typing the following command:

set_deadman_timer 0

Once you have resolved the problem that prevented cron from running, you can reconfigure the deadman_timer.

If the timer expires and reboots the system, BIG-IP will display the following message:

panic (cpu-0): deadman texpired

Disabling the deadman_timer

To disable this feature, type the following command:

set_deadman_timer 0
