Description

You receive below error while creating new DNS zone in ZoneRunner list section:

01150213:3: Zone 'example.company.com.test.' in file 'db.external.example.company.com.test.' contains errors: dns_master_load: db.external.example.company.com.test.:3: department1.example.company.com.test: CNAME and other data. zone example.company.com.test/IN: loading from master file db.external.example.company.com.test. failed: CNAME and other data. zone example.company.com.test/IN: not loaded due to errors.. .

Environment

  • BIG-IP DNS
  • ZoneRunner

Cause

This issue occurs on the DNS Zone page when you try to add or edit a CNAME record. 
Error indicates that you have a domain name in your zone file that owns both a CNAME record and a record of another type. 

This is expected behavior.

Recommended Actions

You need to remove the conflicting record to add the new CNAME record into your Zone.

Following the example for error log from article description - zone example.company.com.test. is failing because it has 2 type of records for department1 entry, where first one is A record and second is CNAME record type, like in example below:

$TTL 300    
@    SOA    ns1.example.com.test.    example.company.com.test. (    
                2018032001    ; serial
                7200        ; refresh (2 hours)
                3600        ; retry (1 hour)
                1814400        ; expire (3 weeks)
                300        ; minimum (1 hour)
                )
...
department1 A 192.0.2.141
...
department1 IN CNAME example.corp.test.net.


Both A record and CNAME record for the same entry are causing the problem.
Please modify your BIND zone file accordingly removing one of the records.

Additional Information

If the problem remains after implementing recommended steps, please collect fresh Qkview file from your affected unit and open a Service Request by contacting F5 Networks Support.
