K59338149: An Error occurred while adding the Secondary BIG-IQ: ''ssh_exchange_identification: read: Connection reset by peer''

Type
Support Solution
Published
2021-09-21
Updated
2023-02-21
Applies to
  • BIG-IQ Platforms
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K59338149

Description

BIG-IQ fails to add Secondary BIG-IQ to cluster  (System > BIG-IQ HA > Add Standby) with error in the WebUI after clicking Add:

An Error occurred while adding the BIG-IQ: ssh_exchange_identification: read: Connection reset by peer


Environment

  • BIG-IQ Centralized Management
  • Configuring BIG-IQ HA

Cause

SSH connection is reset by peer device.
 

Recommended Actions

  1. Check the peer device ssh allow IP address configuration of both units:
    tmsh list sys sshd

    Example:

[root@bigiq-primary:Active:Standalone] config # tmsh list sys sshd
sys sshd {
    allow { 192.168.1.0/24 10.1.1.0/24 }
}  

  1. If the source IP addresses of the BIG-IQ connection is not in the list, you need add it on each device:-
    tmsh modify sys sshd allow add { <IP address you want to allow> }

    Example:

[root@bigiq-primary:Active:Standalone] config # tmsh modify sys sshd allow add { 192.168.0.2/32 }

Note: 192.168.0.2 is the source IP of the Secondary Device.


[root@bigiq-secondary:Active:Standalone] config # tmsh modify sys sshd allow add { 192.168.0.1/32 }

Note: 192.168.0.1 is the source IP of the Primary Device.


          3. Re-attempt the BIG-IQ HA establishment and check if it is successful. 

Additional Information

None.
