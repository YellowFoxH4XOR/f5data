K000132498: Not able to install the Software image on a system with RAID

Type
Support Solution
Published
2023-02-11
Updated
2023-03-03
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K000132498

Description

  • Software installation may fail if a member of a RAID array is not defined or failed.
  • Software installation attempt fails even on a newly created volume.
  • Error messages similar to below logged in /var/log/liveinstall.log
*** Live install start at 2022/09/17 00:31:01 ***
info: Daemon-driven execution indicated by ENV variable.
info: Repository tm_install version/release is 2.12.0.6/11.0
info: System tm_install version/release is 2.12.0.6/11.0
info: Creating target filesystems.
info: Installing packages.
info: Removing and re-creating location cpmirror, 3...
 
info: zero sblock for member device; /dev/dm-4
info: removing member volume; sdb.mdm.set.3./
error: status 1280 returned by command: /usr/sbin/lvremove -f /dev/vg-db-sdb/mdm.set.3.root
 
error: status 1280 returned by command: /usr/sbin/lvremove -f /dev/vg-db-sdb/mdm.set.3._var
info: >++++ result:
info:  Multiple VGs found with the same name: skipping vg-db-sdb
info:  Use --select vg_uuid=<uuid> in place of the VG name.
info: >----
Terminal error: Failed to install.
*** Live install end at 2022/09/17 00:31:55: failed (return code 2) ***

Environment

  • BIGIP platform with RAID
  • One of the RAID array members becomes undefined or fails

 

Cause

When software installation detects RAID it expects to see both array members active.

 Recommended Actions

Follow the below steps to verify if the disk not in the array is physically OK. If status of the disk is as below then re-image the system if removing the disk and adding it back into the array does not work.

 

Note: If below commands return the failed disk as not present no output then contact F5 Support.
