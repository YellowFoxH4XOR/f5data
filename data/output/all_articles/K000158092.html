K000158092: Loss of SSH CLI Access to F5OS-C Partition After Upgrade

Type
Support Solution
Published
2025-12-05
Updated
2025-12-05
Applies to
  • F5OS
  • F5OS-C: 1.8.2, 1.8.1, 1.8.0
Source
https://my.f5.com/manage/s/article/K000158092

Description

After upgrading F5OS-C to version 1.8.x on a VELOS system, users may experience a loss of SSH CLI access to a partition. Attempts to connect via SSH to the partition's management IP result in a "Connection reset" error.

However, CLI access via the "docker exec" command from the controller remains functional.

All other system functionality is not affected.

The problem is isolated to one partition; SSH access to other devices in the same network and via the system controller remains functional. Attempts to connect using SSH with verbose output (ssh -vvv) show the connection is established but reset during the key exchange phase. System logs display repeated errors such as:

  • "Could not load host key"
  • "No supported key exchange algorithms [preauth]"

Looking at the logs, auth.log, - you can see the following:

Could not load host key: /var/F5/partition/ssh-keydir/ssh_host_ecdsa_key

Could not load host key: /var/F5/partition/ssh-keydir/ssh_host_ed25519_key

No supported key exchange algorithms [preauth]

Could not load host key: /var/F5/partition/ssh-keydir/ssh_host_ecdsa_key

Could not load host key: /var/F5/partition/ssh-keydir/ssh_host_ed25519_key

No supported key exchange algorithms [preauth]

Environment

  • System controller and other partitions are operating normally

Cause

The root cause is missing SSH host keys (RSA, DSA, ECDSA, ED25519) on the partition container running on the controller currently handling management traffic. After an F5OS-C upgrade, these keys may not be properly generated or copied on both controllers' partition containers, preventing sshd from starting or accepting connections and resulting in "Connection reset" errors when attempting SSH access.

Recommended Actions

To resolve the issue, generate new SSH host keys for the affected partition:

  1. Navigate to the partition's SSH key directory.
  2. Generate new SSH host keys for all required types using the following commands: (The commands below are an example - depending on the key you are missing.
    • ssh-keygen -t <type> -f <path> -N
    • ssh-keygen -t rsa -f <key_path> -N ''
    • ssh-keygen -t dsa -f <key_path> -N ''
    • ssh-keygen -t ecdsa -f <key_path> -N ''
    • ssh-keygen -t ed25519 -f <key_path> -N ''
  3. Confirm that the new key files are present in the directory.
  4. Restart the SSH service if necessary.
  5. Verify that SSH access to the partition is restored.
