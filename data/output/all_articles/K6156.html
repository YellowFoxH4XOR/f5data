Known Issue

This is the result of a known issue. When multiple F5 devices are located in the same Data Center as an IPv6 Host server, the BIG-IP GTM system may incorrectly select an F5 device with no IPv6 self IP address to monitor the IPv6 Host server in that Data Center. As a result, the IPv6 Host server will be marked DOWN when an F5 device with no IPv6 self IP address is assigned to monitor the IPv6 Host server, then marked UP on a subsequent monitor cycle when an appropriate IPv6 F5 device is tasked to monitor the IPv6 Host server.

F5 Product Development tracked this issue as CR59945 and it was fixed in BIG-IP GTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, or Link Controller Release Notes.

Workaround

To define which F5 device will monitor the IPv6 Host server, perform the following procedure from either the Configuration utility or the command line:

Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Global Traffic > Servers.
  3. Click the IPv6 Host server you want to monitor.
  4. From the Configuration menu, click Advanced.
  5. From the Statistics Collection Server menu, select the F5 device with the IPv6 self IP address that you want to monitor the IPv6 Host server.

Command line

  1. Log in to the BIG-IP GTM command line.
  2. Using a text editor, edit the /config/gtm/wideip.conf file.
  3. Add the following line to the Host server with the IPv6 interface you want to probe, where <prober_ip_address> represents the IPv6 address of the F5 device that will be configured to probe the Host.

    prober <prober_ip_address>

    For example, if the IPv6 Host server name is host.f5.com, add the prober IP address to the Host statement as follows:

    server { // datacenter=gdc, #VS=2   name            "host.f5.com"   type            generic   prober          2002:a0a:7696:0:10:10:118:63        box {      address 2002:a0a:7696:0:10:10:118:101      unit_id 1      }         vs {            name            "blah"            address         2002:a0a:7696:0:10:10:118:101 // http   }
  4. Save the changes to the wideip.conf file.
  5. Verify the wideip.conf file syntax after making the change by typing the following command:

    gtmparse

  6. Load the configuration changes to memory by typing the following command:

    gtmload
