K60030432: Edge Client no longer connects after upgrade or rollback

Type
Support Solution
Published
2025-03-07
Updated
2025-03-07
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.1, 17.1.0, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.2
  • APM Clients
Source
https://my.f5.com/manage/s/article/K60030432

Description

The edge client enters an initializing loop when attempting to connect. It never reaches a logon screen.

  • This same edge client connects successfully to other APMs either on the same or upgraded version.
  • Installing the original edge client version produces the same results, it connects to all other APMs, but not this one.

Environment

  • The BIG-IP was recently updated
  • The BIG-IP was recently rolled back to the original version
  • The APM generates a session ID, but it times out
  • The APM isn't listening on port 8888. 

Cause

This device is encountering ID 994033 where the httpd_sam daemon doesn't recover after the upgrade and needs to be manually restarted.

Recommended Actions

On the BIG-IP, check the logs for entries associated with httpd_sam to confirm whether it's a match to ID 994033 then restart httpd_sam and httpd_apmd.

  1. Search the apm and daemon logs for httpd_sam messages
    1. grep -i httpd_sam /var/log/apm
      results: run_httpd_sam_reinit: httpd_sam is not running. Skip reinit call.
    2. grep -i httpd_sam /var/log/daemon.log
      warning systemd[1]: httpd_sam.service failed.
      notice systemd[1]: Unit httpd_sam.service entered failed state.
      warning systemd[1]: httpd_sam.service start operation timed out. Terminating.

  2. Confirm the device is listening on port 8888. Use netstat and/or tcpdump to check.
    1. netstat -an | grep 8888

      A working example would return the following:
      Proto Recv-Q Send-Q Local Address               Foreign Address             State
      tcp        0      0 127.0.0.1:8888              0.0.0.0:*                   LISTEN

      A non-working example returns no results.

    2. tcpdump -vni 0.0:nnnp host <client-IP> -s0 -w /var/tmp/<ServiceRequest#>-$HOSTNAME.pcap

      Replace <client-IP> with the IP of the client reproducing the issue and <ServiceRequest#> with the relevant service request number.
      Reproduce the issue from this client (attempt to connect via the Edge Client).
      Filter the results by tcp.port == 8888 and it will show the APM resetting client traffic on port 8888. 

  3. Restart the httpd_sam and httpd_apmd process.
    1. tmsh restart sys service httpd_samd httpd_apm
