Topic

This article applies to BIG-IP 13.x. and later. For information about other versions, refer to the following article:

  • K71321196: Gathering data to investigate issues with VMware and BIG-IP APM (11.x - 12.x)

You should consider using this procedure under the following conditions:

  • You have a BIG-IP system with the BIG-IP APM module licensed and provisioned.
  • You are having difficulty accessing VMWare view desktop resources through your BIG-IP APM system.

Description

This article provides steps for data collection that are required in order to troubleshoot issues with BIG-IP APM and VMWare.

Note: To open a support case with F5 Support, you must have an active support contract and you must be authorized to open support cases.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP APM Configuration utility.
  • You have administrative access to the BIG-IP APM command line.
  • You have access to a test system that fails to connect to VMWare resources.

Procedures

When experiencing trouble with users not being able to access VMWare resources, use the following procedures to gather data for troubleshooting:

  • Enabling VDI debug logging on the BIG-IP system
  • Configuring the virtual server to allow decryption
    • Using a Client SSL profile to allow decryption
    • Using an iRule to allow decryption
  • Collecting a packet capture while reproducing the issue
  • Creating a Master Secret log to decrypt the packet capture
  • Gathering the diagnostic data
  • Disabling debug VDI logging on the BIG-IP system

Enabling VDI debug logging on the BIG-IP system

Beginning in BIG-IP APM 13.x, you can use enable virtual desktop infrastructure (VDI) debug logging for a specific access profile. To do so, perform the following procedure:

Impact of procedure: F5 recommends that you return the log level to the default value after you have completed the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor system performance.

  1. Log in to the Configuration utility and navigate to Access > Overview > Event Logs > Settings.
  2. Click Create.
  3. Click General Information.
  4. Type a name for the new APM Log setting.
  5. Select the Enable Access System Logs check box.
  6. Click Access System Logs.
  7. For Access Policy, click Debug.
  8. Click Access Profiles.
  9. In the Available list, select the check box for the affected access profile for which you want to enable debug logging and move it to the Selected list.
  10. Click OK.

Configuring the virtual server to allow decryption

To configure the virtual server to allow decryption of traffic, you can use either of the following methods:

  • Using a Client SSL profile to allow decryption
  • Using an iRule to allow decryption

Using a Client SSL profile to allow decryption

To create a decryptable Client SSL profile temporarily associate with the VMWare virtual server, perform the following procedure:

Impact of procedure: Temporarily associating this Client SSL profile with the virtual server allows you to decrypt any traffic processed by the profile without requiring the server's private key.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client, and click Create
  3. Name the client profile Client_ssl_decryptable_profile.
  4. For the parent profile, click the client profile used by the VMWare virtual server.
  5. For Configuration, click Advanced.
  6. Select the Custom check box.
  7. Change Ciphers to NONE:AES128-SHA.
  8. Change Cache Size to 0.
  9. Change Cache timeout to 0.
  10. Click Finished.
  11. On the VMWare virtual server, note the current profile name so that you can revert to this profile after you've captured the traffic to reproduce the issue.
  12. Change the profile currently assigned to the VMWare virtual server to the Client_ssl_decryptable_profile you just created.

Using an iRule to allow decryption

You can use the SSL::sessionsecret iRules command to extract the SSL session key from SSL sessions that are terminated by the Traffic Management Microkernel (TMM). This method allows you to decrypt an SSL session and review the application data using the Wireshark application without having access to the server's private key. This functions on both client- and server-side and works with Diffie-Hellman and Elliptic Curve Diffie-Hellman key exchange algorithms as well as RSA. For more information, refer to K12783074: Decrypting SSL traffic using the SSL::sessionsecret iRules command (12.x and later).

To revert the changes after capturing the traffic that reproduces the issue, change the virtual server configuration to no longer be associated with the iRule used for this procedure.

Collecting a packet capture while reproducing the issue

Use the tcpdump utility to create packet capture while reproducing the issue. To do so perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on the system. However, performing a tcpdump for long periods of time can use up system resources and cause poor performance.

  1. Log in to BIG-IP Advanced shell (bash) with root credentials.
  2. Capture the client traffic with tcpdump by entering the following command syntax:

    tcpdump -ni 0.0:nnn -s0 host <virtual_server_ip> or <connection_server_ip> or port 4172 -w /shared/tmp/VMWare-1.pcap -vvv

    Note: Replace <virtual_server_ip> and <connection_server_ip> with the appropriate IP addresses.

    For example, if the virtual server IP address is 172.16.10.10, the connection server IP address is 10.10.10.10, and you you want to send the output to the /var/tmp/VMWare-1.pcap file, type the following command:

    tcpdump -ni 0.0:nnn -s0 host 172.16.10.10 or 10.10.10.10 or port 4172 -w /var/tmp/VMWare-1.pcap -vvv

  3. Log in to the client system and reproduce the issue by attempting to access the VMware resources through the virtual server. Be sure to make note of the APM session ID for the attempt.

    Note: Be sure to completely close the app to prevent capturing resumed SSL sessions.

  4. After you reproduce the issue, stop tcpdump by pressing Ctrl+C at the command line. The tcpdump output appears in the /var/tmp/VMWare-1.pcap file.

Creating a Master Secret log to decrypt the packet capture

After you complete collecting a packet capture while reproducing the issue, in order to decrypt and analyze the packet capture, you need to create a pre-master secret (PMS) log file.

If you used the Using an iRule to allow decryption of traffic procedure to configure the virtual server to allow decryption of traffic, refer to the Producing a Master Secret log file procedure in K12783074: Decrypting SSL traffic using the SSL::sessionsecret iRules command (12.x and later).

If you used the Create a temporary Client SSL profile for the purpose of decryption procedure above to configure the virtual server to allow decryption of traffic, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Click the Client_ssl_decryptable_profile that you created the Configuring the virtual server to allow decryption of traffic procedure.
  4. Under Configuration, for Certificate Key Chain, identify the value for the Key setting in the profile.
  5. Match this value to the key file in the following steps:
    1. Log in to the BIG-IP command line.
    2. To open the /config/filestore/files_d/Common_d/certificate_key_d/ directory, type the following command:

      cd /config/filestore/files_d/Common_d/certificate_key_d/

    3. Identify the key file name associated with the value for the Key setting from the previous step. For this example, test.org.key_1.
    4. Generate a pre-master secret (PMS) key log file using the following command syntax:

      ssldump -r /path/to/tcpdump_capture_file -k /path/to/private_key -M /path/to/pre-master-key_log_file

      For example, to create a PMS key log file named Vmware-1.pms using the VMWare-1.pcap capture file and the test.org.key_1 key file, type the following command:

      ssldump -r /var/tmp/VMWare-1.pcap -k /config/filestore/files_d/Common_d/certificate_key_d/\:Common\:test.org.key_1 -M /var/tmp/VMWare-1.pms

You can now upload the resulting VMWare-1.pms file and the VMWare-1.pcap file to a packet-analysis tool, such as Wireshark, to view the decrypted data without the need for the server's private key.

Gathering the diagnostic data

After you are able to reproduce the issue and generate packet captures, you can gather the diagnostic data in one place for future analysis. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Log in to the BIG-IP command line.
  2. Create a new directory for the diagnostic files and change to the new directory by typing the following command:

    mkdir /var/tmp/diag_files

  3. Copy the packet capture files to the new directory by typing the following command:

    cp /var/tmp/VMWare-1.pcap /var/tmp/VMWare-1.txt /var/tmp/diag_files/

  4. Generate a tarball file of the log files by typing the following command:

    Note: This command creates a file named logfiles.tar.gz and places it in the newly created directory.

    tar -czvf /var/tmp/diag_files/logfiles.tar.gz /var/log/*

  5. Generate a tech.out diagnostic file by typing qkview at the command line. Output is saved in the /var/tmp/ directory. Move it to the newly created directory using the following syntax:

    mv /var/tmp/<hostname>.qkview /var/tmp/diag_files

    For example:

    mv /var/tmp/bigip.example.com.qkview /var/tmp/diag_files

Disable debug VDI logging on the BIG-IP

After you have completed troubleshooting or are not actively troubleshooting, you can disable debug VDI logging. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Log in to the Configuration utility
  2. Navigate to Access > Overview > Event Logs > Settings.
  3. Select the check box for the APM Log setting you created in the Enabling VDI debug logging on the BIG-IP system procedure.
  4. Click Delete.
  5. Click Yes to confirm deletion of the debug log settings and to remove the settings from the access profile.
