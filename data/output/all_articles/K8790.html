Known Issue

This is the result of a known issue. Connection limits for nodes are enforced per blade and not per cluster.

For example, in a two blade VIPRION configuration, a node connection limit of 32 is doubled to 64 connections. This behavior occurs since each blade enforces the connection limit separately per blade and not per cluster. For a four blade VIPRION configuration, a node connection limit of 32 is quadrupled to 128 connections, or 32 connections for each of the four blades.

F5 Product Development is tracking this issue as CR99825.

This issue has been fixed in Hotfix-BIGIP-v9.6.1-HF2 issued for BIG-IP 9.6.1, for the BIG-IP 9.6 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
