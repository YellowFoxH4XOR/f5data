Description

Unexpected Hex characters appear throughout a web resource (eg. a page, Javascript, CSS) when accessed via the BIG-IP, and you would like to confirm if there is an issue with chunked encoding.

For example, you expect the browser to display a CSS file as follows:

body {
    background-color: lightblue;
}

h1 {
    color: navy;
    margin-left: 20px;
}
- end -

However, when accessed via the BIG-IP, the browser displays the CSS file as:

002d                                   <===== top of the web resource
body {
    background-color: lightblue;
}

0033                                   <===== hex characters throughout the web resource
h1 {
    color: navy;
    margin-left: 20px;
}

0                                      <===== trailing 0
- end -

Environment

  • BIG-IP
  • virtual server with HTTP profile

Cause

None

Recommended Actions

HTTP chunked encoding is a feature in HTTP/1.1, typically used to stream a response when the response size is not known in advance (eg. a dynamic page that shows results from a database table).

Further Reading:

  • HTTP specification on chunked encoding
  • A more friendly explanation, with examples
Note: These links take you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

If you suspect that BIG-IP returns a malformed chunked encoded response, you can confirm with the following steps:
  1. Perform a packet capture while accessing the web resource. If SSL is used, the packet capture must be decryptable.
  2. Open the packet capture in Wireshark. Apply the decryption key if SSL is used.
  3. Identify the stream, right-click, and "Follow TCP Stream" or "Follow SSL Stream" (if SSL is used).
  4. Identify the HTTP request and response for the web resource.
  5. Check the HTTP response headers and body.
A web server (or BIG-IP) will unilaterally decide if chunked encoding will be used for a response. However, when chunked encoding is applied to the response body, the "Transfer-Encoding: chunked" header must be present.  Any of the following constitutes a malformed response:
  • Response body is chunked encoded, but "Transfer-Encoding: chunked" header is not present
  • "Transfer-Encoding: chunked" header is present, but response body is not chunked encoded
The cause of a malformed response may be due to a known issue or other reasons. The key is to be able to clearly identify if there is an issue with chunked encoding, so that you can decide if you need to troubleshoot further.


Examples of Valid and Malformed Responses

Valid Response - Not chunked encoded

HTTP/1.1 200 OK
Date: Wed, 18 Apr 2018 05:22:55 GMT
Content-Length: 1695                   <===== "Content-Length" is explicitly specified instead
Connection: close                      <===== no "Transfer-Encoding: chunked" header,
Content-Type: text/css                        which means the response is not chunked encoded

body {                                 <===== response body is not chunked
    background-color: lightblue;
}
- snip -

Valid Response - Chunked encoded

HTTP/1.1 200 OK
Date: Wed, 18 Apr 2018 05:22:55 GMT
Transfer-Encoding: chunked             <===== this header indicates the response body is chunked encoded
Connection: close
Content-Type: text/css

002d                                   <===== it is fine to have these Hex characters, they are chunk size indicators.
body {                                        
    background-color: lightblue;
}
- snip -

The "Transfer-Encoding: chunked" header tells the browser that the response is chunked encoded. The browser will unchunk the response, by removing chunk size indicators and combining all the chunks. If the chunks properly align, and the chunk sizes are correct, the browser will recreate the original resource without chunk information.

Malformed Response - Chunked encoded

HTTP/1.1 200 OK
Date: Wed, 18 Apr 2018 05:22:55 GMT
Connection: close                      <===== there is no "Transfer-Encoding: chunked" header,
Content-Type: text/css                        so the response should not be chunked encoded

002d                                   <===== unexpected chunk size indicator
body {                                        
    background-color: lightblue;
}
- snip -

Since there is no "Transfer-Encoding: chunked" header, the browser will not know that it has to unchunk the response, and will return the resource verbatim resulting in chunk size indicators appearing in the resource. This may break execution of Javascript and validity of CSS, and generally prevent the website from displaying correctly.

Malformed Response - Not chunked encoded

HTTP/1.1 200 OK
Date: Wed, 18 Apr 2018 05:22:55 GMT
Transfer-Encoding: chunked             <===== this header indicates the response body is chunked encoded
Connection: close
Content-Type: text/css                 

body {                                 <===== however, response body is not chunked encoded
    background-color: lightblue;              (that is, there is no chunk size indicator)
}
- snip -

The "Transfer-Encoding: chunked" header tricks the browser into expecting a chunked encoded response, but response body is not chunked encoded. The browser will display an error.
