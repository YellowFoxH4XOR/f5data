Description

Several log-setting profiles assigned under the same access-profile may result in excessive (duplicate) log entries in /var/log/apm* files which may eventually result in lack of space under /var/log/ partition.

Environment

  • APM
  • /var/log/apm
  • log lines are duplicate

Cause

It's possible to assign several apm log-setting profiles under the same access-profile. While such configuration can be needed under some scenarios (for example, when log-destination setting is different in assigned publishers of log-profiles), under the scenario when log-destination setting is the same in log-setting profiles (for example, local-syslog), the APM administrator may notice unexpected duplicate entries in /var/log/apm.

Recommended Actions

Keep one log-setting profile per access-profile unless there is a need in logging data into different log-destinations (for example, local-syslog and remote-syslog).

Additional Information

How to check the existing apm log-setting profiles on APM device

  1. in Configuration Utility (GUI) go to 'Access  ››  Overview : Event Logs : Settings'
  2. in CLI type tmsh list apm log-setting.

    For example, there are 3 log-setting profiles in the below example: default-log-setting, log-profile-1, log-profile-2:

    [root@local.bigip:Active:Standalone] config # tmsh list apm log-setting

    apm log-setting default-log-setting {
        access {
            general-log {
                publisher sys-db-access-publisher
            }
        }
        description "Default log setting for all APM messages."
        url-filters {
            urlf {
                publisher local-db-publisher
            }
        }
    }
    apm log-setting log-profile-1 {
        access {
            log-profile-1_access {
                publisher sys-db-access-publisher
            }
        }
        url-filters {
            log-profile-1_swg {
                enabled false
                publisher sys-db-access-publisher
            }
        }
    }
    apm log-setting log-profile-2 {
        access {
            log-profile-2_access {
                publisher sys-db-access-publisher
            }
        }
        url-filters {
            log-profile-2_swg {
                enabled false
                publisher sys-db-access-publisher
            }
        }
    }
    [root@local.bigip:Active:Standalone] config #

How to verify how many log-setting profiles are assigned under access-profile:

  1. In Configuration Utility go to 'Access  ››  Profiles / Policies : Access Profiles (Per-Session Policies)' and check the column 'Logs'
  2. In CLI, type tmsh list apm profile access <name_of_access_profile>.

    In the below example, the name of access-profile is ap_na.

    [root@bigip:Active:Standalone] config # tmsh list apm profile access ap_na

    apm profile access ap_na {
        accept-languages { en }
        access-policy ap_na
        app-service none
        customization-group ap_na_logout
        default-language en
        domain-cookie none
        eps-group ap_na_eps
        errormap-group ap_na_errormap
        exchange-profile none
        framework-installation-group ap_na_frameworkinstallation
        general-ui-group ap_na_general_ui
        generation 5
        generation-action noop
        httponly-cookie false
        log-settings { <<<<<<<<<<<<<<<<<<< (!)
            default-log-setting
            log-profile-1
            log-profile-2
        }
        logout-uri-include none
        logout-uri-timeout 5
    […]

    We can see that 3 log-setting profiles are currently attached: default-log-setting, log-profile-1, log-profile-2.
