Topic

You should consider using these procedures under the following condition:

  • You want to encrypt cookies between the BIG-IP system and the client.

Description

You can configure the BIG-IP LTM system to encrypt HTTP cookies before sending them to the client system. The BIG-IP LTM system can encrypt BIG-IP persistence cookies which are inserted by BIG-IP, as well as cookies that are embedded in the response from the server. You can also configure the BIG-IP LTM system to encrypt cookies to keep information private if the cookie contains sensitive information about the web application.

This article discusses how to configure HTTP cookie encryption using only the HTTP profile. You can also configure BIG-IP persistence cookie encryption from within the cookie persistence profile. Configuring persistence cookie encryption within the persistence cookie profile offers additional options that are not available within the HTTP profile. For more information refer to K23254150: Configuring cookie encryption for BIG-IP persistence cookies from the cookie persistence profile. The cookie encryption option available under persistence cookie profile is only responsible for encrypting cookies which are inserted by BIG-IP system and not the cookies coming from server. To encrypt the cookies coming from server, you need to configure that cookie name and enable cookie encryption under HTTP profile. By default cookies inserted by BIG-IP are not encrypted. For more information about persistence cookies refer to K83419154: Overview of cookie persistence.

When cookie encryption is enabled, the BIG-IP LTM system extracts the unencrypted cookie from the server response, encrypts it using a 192-bit AES cipher, and then encodes it using the Base64 encoding scheme. The BIG-IP LTM system then embeds the encrypted cookie into the HTTP response to the client. On subsequent requests, when the client presents the encrypted cookie to the BIG-IP LTM system, BIG-IP LTM removes the cookie, decodes it using the Base64 encoding scheme, and decrypts it. The BIG-IP LTM system then re-embeds the decrypted cookie in the HTTP request to the server.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have a virtual server with HTTP servers in an associated pool.

Procedures

  • Configuring cookie encryption using the Configuration utility
  • Configuring cookie encryption with the HTTP profile using tmsh
  • Configuring cookie encryption with the HTTP profile using an iRule

Configuring cookie encryption using the Configuration utility

The following procedure allows you to enable cookie encryption and select an encryption passphrase.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Services > HTTP.
    Note: If HTTP is not visible in the menu, either zoom the browser view out or select Services which loads the HTTP profile page by default. If a different profile page loads, select Services > HTTP from the menu bar on this page.
  3. Select Create.
  4. Enter a name for the HTTP profile.
  5. Select the Custom check box so that you can edit the settings.
  6. For Encrypt Cookies, enter one or more cookie names.

    Note: If you want to specify more than one cookie for the BIG-IP LTM system to encrypt, separate the cookie names with a space character. For BIG-IP persistent cookies, the default cookie name is BIGipServer<pool-name>. For example:
    BIGipServerhttp-pool

  7. For Cookie Encryption Passphrase, enter a passphrase for the cookie.
  8. For Confirm Cookie Encryption Passphrase, re-enter the passphrase.
  9. Select Finished.
  10. Associate the HTTP profile with the virtual server.

Configuring cookie encryption with the HTTP profile using tmsh

The following procedure allows you to enable cookie encryption and select a passphrase.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To create an HTTP profile with cookie encryption, use the following command syntax:

    create /ltm profile http <profile_name> defaults-from http encrypt-cookies add { <cookie_name> }

    For example:

    create /ltm profile http test_cookie defaults-from http encrypt-cookies add { cookie1 cookie2 cookie3 }

    To modify an existing HTTP profile to enable cookie encryption, use the following command syntax:

    modify /ltm profile http <profile_name> encrypt-cookies add { <cookie_name> }

    In the previous command syntax, note the following:

    • <profile_name> is the name of the new HTTP profile being created.
    • <cookie_name> is name of the cookie you want to encrypt. You may encrypt multiple cookies by separating them with commas.
  3. To set or modify a cookie encryption passphrase, use the following command syntax:

    modify /ltm profile http <profile_name> encrypt-cookie-secret "<cookie_passphrase>"

    In the previous command syntax, note the following:

    • <profile_name> is the name of the profile you want to modify.
    • <cookie_passphrase> is the passphrase you want to encrypt the cookies with.
  4. Save the change by entering the following command:

    save /sys config

Configuring cookie encryption with the HTTP profile using an iRule

You can also configure cookie encryption by using an iRule. To determine the procedure most applicable to your BIG-IP version and application, refer to Encrypting Cookies on DevCentral.
