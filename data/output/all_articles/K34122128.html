Description

This article describes adm.health.sensitivity db variable that controls Behavioral DoS Sensitivity.

The health sensitivity db variable adm.health.sensitivity is used for tuning. Higher values equal lower sensitivity. The integer value is a range between 30 to 10000. In practice, this means that higher values will lower sensitivity to minimize the number of false positives caused by short traffic spikes and high server load. Increasing this value is sometimes needed to minimize false positives. The negative effect of higher sensitivity is that an attack will be declared later.

Environment

  • DoS Profile with Behavioral DoS Protection

Cause

None

Recommended Actions

If there are multiple false positives relating to BaDoS, you can consider increasing adm.health.sensitivity value.

To view the current setting for adm.health.sensitivity, use the following command:

tmsh list sys db adm.health.sensitivity

The command output appears similar to the following example:

sys db adm.health.sensitivity {
    value "500"
}

To modify the value of adm.health.sensitivity to 1000 (or a value of your choosing), use the following command:

tmsh modify sys db adm.health.sensitivity value 1000

To view the modified setting for adm.health.sensitivity, repeat the list

tmsh list sys db adm.health.sensitivity

The command output should look similar to the following example:

sys db adm.health.sensitivity {
    value "1000"
}

Additional Information

In older software versions, the default adm.health.sensitivity value is 50. In newer versions, it was increased to 500 to minimize false positives. For more information, refer to Bug ID 922597: BADOS default sensitivity of 50 creates false positive attack on some sites
