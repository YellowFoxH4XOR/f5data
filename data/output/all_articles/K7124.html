Topic

It may be necessary to configure the BIG-IP system to issue HTTP 302 Found redirects based on certain HTTP response codes sent from a server. For example, you may want to configure the BIG-IP LTM system to issue an HTTP 302 Found redirect when it receives a response code indicating a server error (HTTP 500 Internal Server Error, HTTP 501 Not Implemented, or HTTP 502 Bad Gateway responses).

You can configure the HTTP profile to redirect client requests based on HTTP server response codes. The redirect location will be the fallback host specified in the HTTP profile, or you can have an iRule handle the redirection.

Note: For more information on the iRule, refer to K3169: Creating an iRule that takes action upon an HTTP server response code.

To configure the BIG-IP system to redirect client requests based on HTTP server response codes, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Click Create.
  4. Type the name of the profile.
  5. In the Parent Profile list, click http.
  6. For Settings, select the Custom check box.
  7. For Fallback Host, type the node name or IP address of the fallback host for which the BIG-IP system sends an HTTP 302 Found response when the system receives the specified HTTP response code from the server. For example:

    http://172.16.0.1

    or

    https://host.example.com

  8. For Fallback on Error Codes, type the HTTP error code(s) to trigger the redirection to the fallback host, if received from the server.

    Note: If you specify more than one code, separate the codes with a blank space; for example, 500 501 502. You can also specify a range of error codes; for example: 505-515.

  9. Click Finished.
  10. Associate the HTTP profile with the appropriate virtual server.

Note: When you use this option in the HTTP profile, the BIG-IP system does not attempt to send the connection to other pool members prior to redirecting to the fallback host specified.
