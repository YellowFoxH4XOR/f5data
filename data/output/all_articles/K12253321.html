K12253321: Holding up application until proxy starts in Aspen Mesh

Type
Support Solution
Published
2021-09-20
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K12253321

Description

In Aspen Mesh release 1.9.x and above, a new feature is available where users can delay application startup until the sidecar has been started fully.

Environment

  • Kuberntes: 1.17x,1.18.x,1.19.x,1.20.x
  • Aspen Mesh: 1.9.x 

Cause

If a user’s application starts before the sidecar is ready to fulfill outgoing requests (e.g. It connects to a database), a silent error may occur if not accounted for in the user application. By delaying the application to wait until the sidecar is ready, this and other issues can be mitigated and will not have to be accounted for with special cases in user-space. See this article for more information.

Recommended Actions

  • Annotate your deployment definition
  • Considerations

Annotate your deployment definition

This can be done on a per-deployment basis, and we do not recommend configuring this globally. To enable this functionality, add the following annotation to your pod specification:

annotations:
  proxy.istio.io/config: '{ "holdApplicationUntilProxyStarts": true }'

The annotation should be placed under the pod template.

For example:
apiVersion: apps/v1
kind: Deployment
metadata:
  name: httpbin
  namespace: default
spec:
  replicas: 1
  selector:
    matchLabels:
      app: httpbin
  template:
    metadata:
      annotations:
        proxy.istio.io/config: '{ "holdApplicationUntilProxyStarts": true }'
      labels:
        app: httpbin
    spec:
      containers:
      - image: docker.io/kennethreitz/httpbin
        imagePullPolicy: IfNotPresent
        name: httpbin
        ports:
        - containerPort: 8080
          protocol: TCP
      dnsPolicy: ClusterFirst
      restartPolicy: Always
      schedulerName: default-scheduler
      securityContext:
        fsGroup: 2000
      serviceAccount: httpbin
      serviceAccountName: httpbin
      terminationGracePeriodSeconds: 30

Considerations

  1. As stated, this is only available on 1.9.x and above.

  2. Do not use it as global configuration, just per deployment.

  3. The wait time for proxy is up to one minute, if the proxy is not able to start for one minute period time, then the proxy will be forced to shut down. If this issue is presented, engage Aspen Mesh support.
