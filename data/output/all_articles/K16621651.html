Issue

Error Message

You may observe the following messages:

  • Received too large (1936094320 B) SFTP packet. Max supported packet size is 1024000 B.
  • An error message about skipping startup.
  • Cannot initialize SFTP protocol. Is the host running a SFTP server?

In the first error message, note the following:

  • A startup script, such as .profile, typically prints this error. This message may start with sftp.
In the second error message, note the following:
  • Your shell is probably incompatible with the application. F5 recommends you use Advanced Shell (bash).

Message Location

You may encounter these messages in the following locations:

  • SFTP (SSH File Transfer Protocol) command line output
  • Windows Secure Copy (WinSCP) Windows program client output

Description

This message occurs when all of the following conditions are met:

  • You use the SFTP protocol to transfer files to the BIG-IP system.
  • The user role you use to log in to the BIG-IP system does not have bash access.
  • Remote authenticated users (TACACS+, Radius, LDAP, and so on) with no bash access.

    Note: To enable Advanced Shell (bash) access for remote authenticated users, refer to K10272: Accessing bash as a remotely authenticated user.

The BIG-IP Resource Administrator vulnerability enables users with the the Resource Administrator role to manipulate user privileges. For more information, refer to K38941195: BIG-IP Resource Administrator vulnerability CVE-2019-6617.

After you install the fix for this vulnerability on your BIG-IP system, user roles that do not have bash access cannot use the SFTP protocol to transfer files to the system. Additionally, you cannot grant bash access to the Resource Administrator role. The only user role that can have bash access is the Administrator role.

Impact

Only users with the Administrator role to whom you also grant bash access can use the SFTP protocol to transfer files to the BIG-IP system.

Recommended Actions

To workaround this issue, do one of the following:

  • Give users the Administrator role and then grant them 'bash' access
  • Use the SCP instead of the SFTP protocol for users with the Administrator role but no 'bash' access

Give users the Administrator role and then grant them 'bash' access

You must first assign the Administrator role to users, and then grant them bash access on the BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Users > User List.
  3. Select the name of the affected user.
  4. In Partition Access, select the existing role, and then select Edit.
  5. In the Role list, select Administrator, and then select Add.
  6. In the Terminal Access list, select Advanced shell.
  7. Select Update.

Use the SCP instead of the SFTP protocol for users with the Administrator role but no 'bash' access

Only use this procedure when a user is already an Administrator but does not have bash access. For users that are not Administrators, you must perform the first procedure. To use the SCP instead of the SFTP protocol, perform the following procedure:

Note: You can only use this procedure if you are using the WinSCP client.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.
  1. Open the WinSCP client.
  2. For File protocol:, select SCP.
  3. Enter the host name, user name, and password.
  4. Select Advanced.
  5. Under Environment, select SCP/Shell.
  6. For Shell:, enter the following:

    bash

  7. Select Ok.
  8. Select Login.
