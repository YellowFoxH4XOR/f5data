Known Issue

Form-based client-initiated single sign-on (SSO) login attempts may intermittently fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for form-based, client-initiated, SSO authentication.
  • The system sends the HTTP headers and body of the client login request to the BIG-IP APM system in separate TCP packets.
  • The Citrix & Java Support (VDI & Java Support for 11.4.x) check box is selected on the affected virtual server.

A client login request may reach the BIG-IP APM system with the HTTP headers and HTTP body in separate TCP packets. If too much time passes from when the BIG-IP APM system receives the HTTP headers and when it receives the HTTP body, the BIG-IP APM system may be unable to parse the body in order to replace the password token with the actual password. As a result, the BIG-IP APM system sends the token back to the server, which causes login failure and a possible authentication loop. When an authentication loop occurs, failed login attempts can lock the user account.

Impact

Users are intermittently unable to log in to web applications, which may cause the system to lock their accounts in the directory service.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Users are unable to access web applications using SSO.
  • Users are locked out of directory service accounts.
  • SSOv2 Logon failed warning messages appear in the /var/log/apm file.
  • Users who run Safari 6 or Internet Explorer 10 experience a higher failure rate than users who run other browsers.
