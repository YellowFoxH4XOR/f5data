K000163394: Distributed Cloud API Validation Rejects Empty Header Values

Type
Knowledge
Published
2026-09-23
Updated
2026-09-23
Source
https://my.f5.com/manage/s/article/K000163394

Description

Distributed Cloud API Protection may report an empty value is not allowed OpenAPI violation when a request explicitly includes an empty HTTP header value.

This can occur even when the header is defined as type: string and is not marked as required.

Environment

  • F5 Distributed Cloud Web App & API Protection

  • HTTP Load Balancer with API Definition and API Inventory

  • Imported or discovered OpenAPI specifications

  • OpenAPI Validation

Cause

When a header such as x-token is explicitly sent with an empty value, Distributed Cloud decodes the value as null and validates the empty value before evaluating the OpenAPI type: string definition.

API Discovery does not automatically add allowEmptyValue: true to the discovered OpenAPI specification.

Answer/Recommended Actions

If the header is expected to accept an explicitly empty value, add allowEmptyValue: true to the corresponding parameter in every applicable OpenAPI specification.

If the same endpoint or header exists in duplicate specifications, update each specification. Retest the request after updating the API definitions, and enable OpenAPI Validation in Block mode only after confirming that the empty value is accepted.

Custom Lists are not intended to exempt a single HTTP header. Excluding HTTP headers from OpenAPI request validation is broader and affects header validation generally.
