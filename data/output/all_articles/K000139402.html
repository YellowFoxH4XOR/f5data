K000139402: X-Forwarded-For header is always included in traffic when HTTP-Proxy-Connect profile is applied to Virtual Server

Type
Support Solution
Published
2025-07-16
Updated
2025-07-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.X, 17.1.X, 17.5.1, 17.5.0, 17.1.2, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000139402

Description

When an HTTP-Proxy-Connect profile is applied to a Virtual Server, HTTP CONNECT requests sourced from that Virtual Server will always include an X-Forwarded-For header, even if the 'Insert X-Forwarded-For' option is disabled in the HTTP profile assigned.

Environment

  • Big-IP Explicit Forward Proxy configurations

Cause

This is expected behavior with the inclusion of an HTTP-Proxy-Connect profile on a Virtual Server.

Most commonly this profile type is included with Explicit Forward Proxy configuration with LTM or SWG/SSLO deployments.

With HTTP-Proxy-Connect, a client connects to the BIG-IP device, which selects a remote proxy device from a pool of proxy devices. An HTTP CONNECT handshake tells the selected remote proxy device where to connect. 

When an HTTP profile is assigned to the virtual server, the HTTP CONNECT handshake is automatically configured.

Recommended Actions

If you need to remove or replace the x-forwarded-for header from the traffic in question, you can use below iRule's to workaround.

when HTTP_PROXY_CONNECT {
HTTP::header remove X-Forwarded-For
}

or

when HTTP_PROXY_CONNECT {
    HTTP::header replace X-Forwarded-For "X.X.X.X"
}
