Description

The following will guide you with the Installation procedure for NFS server.

Environment

  • NFS server

  • Nginx Controller

Cause

Instruction for preparing NFS server to store postgres DB, backups, logs from Nginx Controller server.

Recommended Actions

Set Up the NFS Server Side

  1. Install Ubuntu (For the following example we used v20.04)

  2. Login to installed server and install NFS Kernel Server package. From CLI run the following commands:

sudo apt update
sudo apt install nfs-kernel-server

Type “Y” and press ENTER to start the installation.

  1. Configure Shared Directory

On the host machine NFS server, create a directory you want to share with the Nginx Controller system.

sudo mkdir -p /srv/ctrl/configdb
sudo mkdir -p /srv/ctrl/tsdb

Change the owner user and group to nobody and nogroup. This setting makes the folder public:

sudo chown nobody:nogroup /srv/ctrl/configdb
sudo mkdir -p /srv/ctrl/tsdb

Set permissions to 777, to read, write and execute files in this folder:

sudo chmod 777 /srv/ctrl/configdb
sudo mkdir -p /srv/ctrl/tsdb

  1. Edit NFS Export File to Grant Server Access to Clients

Permission to access the host server machine is granted in the exports file located under /etc directory. 

sudo vi /etc/exports

For each client you want to grant access to, the following lines should be added (in Red):

root@nfs-server-ubuntu-server:/srv/ctrl/configdb# cat /etc/exports
# /etc/exports: the access control list for filesystems which may be exported
#               to NFS clients.  See exports(5).
#
# Example for NFSv2 and NFSv3:
# /srv/homes       hostname1(rw,sync,no_subtree_check) hostname2(ro,sync,no_subtree_check)
#
# Example for NFSv4:
# /srv/nfs4        gss/krb5i(rw,sync,fsid=0,crossmnt,no_subtree_check)
# /srv/nfs4/homes  gss/krb5i(rw,sync,no_subtree_check)
#
#/mnt/nfsdir 10.155.207.61(rw,sync,no_subtree_check)
#/mnt/nfsdir 10.155.207.27(rw,sync,no_subtree_check)
/srv/ctrl/configdb      *(rw,sync,no_root_squash,no_subtree_check)
/srv/ctrl/tsdb          *(rw,sync,no_root_squash,no_subtree_check)
/srv/tmp/logs           *(rw,sync,no_root_squash,no_subtree_check)

Exit the file and save the changes.

The options in the brackets have the following functions:

  • “rw” option provides clients with read and write access to directories on the server.

  • “sync” forces NFS to write changes before responding to the client. This option ensures the state of the host is accurately presented to clients.

  • “no_root_squash”  remote root users are able to change any file on the shared file system

  • “no_subtree_check” disables subtree checking. The subtree process may cause problems when users rename files.

  1. Export Shared Directory

After you make the necessary edits in /etc/exports, use the exportfs command to export all shared directories you registered in that file:

sudo exportfs -a

Next, restart the NFS Kernel Server to apply the changes to configuration:

sudo systemctl restart nfs-kernel-server

In case you enabled UFW, you need to allow clients to access the server:

sudo ufw allow from [clientIP or clientSubnetIP] to any port nfs

To make sure you successfully completed the operation, type:

sudo ufw status
