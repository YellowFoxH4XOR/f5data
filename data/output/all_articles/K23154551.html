Topic

The BIG-IP APM system can apply iRules to an access session at the Access Policy level, and can configure BIG-IP LTM-level iRules, as well.

Description

You can configure the BIG-IP APM system with Access Profile-specific iRules (iRule Event) as well as with BIG-IP LTM iRules. Due to the way access sessions are processed by the BIG-IP APM system, using BIG-IP LTM iRules to add, delete, or modify HTTP content specific to an access session can often produce an erratic application of the BIG-IP LTM iRule. The reason for this behavior is, being processed by the BIG-IP APM module, once the access session is established, the BIG-IP LTM system cannot use iRules to access the access session connection content.

Recommendations

When you have to use a BIG-IP LTM iRule to get access to access session content that you cannot get through using an Access Policy iRule, using a layered virtual server scenario may be the most effective way to apply the BIG-IP LTM iRule to the access session.

A layered virtual server involves creating a BIG-IP LTM virtual server that uses a custom iRule that ultimately sends and receives traffic with the BIG-IP APM virtual server. The two virtual server configurations reside on the same BIG-IP system. The custom iRule can also contain BIG-IP LTM iRules functionality that you want to apply to the access session content.

The following procedures demonstrate how to create a BIG-IP LTM layered virtual server to allow using BIG-IP LTM iRules between the BIG-IP APM virtual server and the client requestor. In these procedures, F5 assumes that the BIG-IP APM is configured with a functioning virtual server.

Important: Using a layered virtual server to apply BIG-IP LTM iRules to an access session will function only for access sessions that do not use a network tunnel.

  • Creating the custom iRule
  • Creating the BIG-IP LTM layered virtual server

Creating the custom iRule

The following procedure creates an iRule that inserts an HTTP header into the packet on both the request and response sides of the access session.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. For Name enter the name of the custom iRule.
  5. For Definition paste the following stanza.

    Note: This is an example iRule that inserts HTTP headers on the client request and in the BIG-IP APM virtual server response. 

    when RULE_INIT {
    # To set debugging - ::debug 1 for debug logging, ::debug 0 to disable debug logging
    set ::debug 1
    # Using debug logging in a production environment is not recommended
    # Only use "::debug 1" when testing and/or troubleshooting.
    # Set the variable "apmVS" to the name of the destination BIG-IP APM virtual server (in this example: apm-virtual-server)
    set ::apmVS "apm-virtual-server"
    }
    when HTTP_REQUEST {
    # Insert HTTP headers into request when forwarding to the BIG-IP APM virtual server
    # Forward request to virtual server as set by the variable "apmVS"
    HTTP::header insert "iRule-HTTP-Request-insert" "HTTP-Request-Header"
    virtual $::apmVS
    }
    when HTTP_RESPONSE {
    # Insert HTTP headers into request when responding to the client request
    HTTP::header insert "iRule-HTTP-Response-insert" "HTTP-Response-Header"
    }

    In the example iRules stanza, the iRule is inserting HTTP headers; however, you can create an iRule to meet your particular needs. Note the following required iRules event statements. Also, you must set the BIG-IP APM virtual server selection in the HTTP_REQUEST event.

    • set ::apmVS "apm-virtual-server"

      This statement sets the iRule-defined variable apmVS to the name of the destination BIG-IP APM virtual server (in the example: apm-virtual-server) that the system will use to process traffic after the BIG-IP LTM iRule is processed. When crafting your custom iRule, you can use a different variable name and must set the variable to use the name of the BIG-IP APM virtual server, as defined in your configuration. Be sure to use the same variable name throughout your custom iRule.

    • HTTP_REQUEST

      This is the client request to the BIG-IP LTM layered virtual server that is modified by the iRule and sent to the BIG-IP APM virtual server.

    • HTTP_RESPONSE

      This is the server response to the client request that is received by the layered virtual server from the BIG-IP APM virtual server.

Creating the BIG-IP LTM layered virtual server

The following procedure creates the layered virtual server that uses the iRule to process (intercept) traffic destined for the BIG-IP APM virtual server and the client.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers > Virtual Server List.
  2. Select Create.
  3. For Name enter a name.
  4. For Type select Standard.
  5. For Destination Address/Mask select Host and enter the IP address for the layered virtual server.
  6. For Service Port select the same port used by the BIG-IP APM virtual server, typically port 443.
  7. For Protocol select TCP.
  8. For Protocol Profile (Client) and Protocol Profile (Server), select the default, tcp, unless you want a specific TCP optimization profile for the client.
  9. For HTTP Profile (Client) select http.
  10. For HTTP Profile (Server) select the default, Use Client Profile.
  11. For SSL Profile (Client) select the same Client SSL profile that the BIG-IP APM virtual server used.
  12. For SSL Profile (Server) select serverssl.
  13. For VLAN and Tunnel Traffic select the default, All VLANs and Tunnels.
  14. For Source Address Translation select Auto Map.
  15. For Resources > iRules, select the iRule created in the previous procedure from the Available column and select << to place the iRule in the Enabled column.
  16. Select Finished.

Note: Users need to connect to the BIG-IP APM virtual server for their access session by connecting to the BIG-IP LTM layered virtual server.
