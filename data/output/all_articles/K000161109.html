K000161109: SSH sessions are being disconnected after 5 minutes of inactivity

Type
Support Solution
Published
2026-05-04
Updated
2026-05-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000161109

Description

SSH sessions to backend servers routed through the BIG-IP VELOS tenant are being disconnected after 5 minutes of inactivity. Packet captures show the BIG-IP sending TCP RST packets with the message "[F5RST: Flow expired (sweeper) (idle timeout)]", resulting in users being forcibly logged out of their SSH sessions.

 

 

Environment

BIG-IP LTM

Forwarding virtual server

FastL4 profile: /Common/fastL4_no_pva (inherits from /Common/fastL4)

Profile settings: idle-timeout 300 seconds (default), reset-on-timeout enabled

SSH traffic routed through BIG-IP as gateway

 

 

Cause

The FastL4 profile /Common/fastL4_no_pva inherits an idle-timeout of 300 seconds and reset-on-timeout enabled from /Common/fastL4. This configuration causes the BIG-IP to forcibly close idle SSH connections after 5 minutes, resulting in session drops and TCP RSTs as observed in the packet captures.

 

Answer/Recommended Actions

Increase the idle-timeout in /Common/fastL4_no_pva to a value that matches operational requirements (e.g., 3600 seconds for 1 hour):

tmsh modify ltm profile fastl4 /Common/fastL4_no_pva idle-timeout 3600

tmsh save sys config

 

(Optional) To avoid abrupt session resets, disable reset-on-timeout:

tmsh modify ltm profile fastl4 /Common/fastL4_no_pva reset-on-timeout disabled

tmsh save sys config

 

These changes will only affect new connections. Existing SSH sessions will not be updated until re-established.

(Optional) To force all connections to use the new settings immediately, clear the connection table:

 

tmsh delete sys connection all

or for specific clients:

tmsh delete sys connection client-addr <SecureKi_source_IP>

Test SSH connectivity after applying changes to confirm sessions remain stable for the desired duration.
