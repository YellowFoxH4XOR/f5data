K54916949: ''user_alert.conf'' does NOT support regex ''or'' expression.

Type
Support Solution
Published
2021-10-13
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K54916949

Description

Custom SNMP traps can be defined in /config/user_alert.conf" file.
And some regex expressions are supported in "/config/user_alert.conf".  For example: "*" for a string, "!" for not.

While "or" expression.  "(?:<data1>|<data2>)"  is not supported.

For example: "(?:aaaaaaa|bbbbbb)"

Once configured, you will see "alertd" keeps restarting and   error logs in /var/log/ltm,

Sep 14 14:39:02 hostname err alertd[32678]: 01100021:3: Couldn't process the /config/user_alert.conf: problems at line 203.
Sep 14 14:39:02 hostname err alertd[32678]: 01100010:3: Couldn't load file /config/user_alert.conf


Environment

Custom SNMP traps are defined in "/config/user_alert.conf"

Cause

"or" expression.  "(?:<data1>|<data2>)"  is not supported.  For example:

alert bigipGtmWideIpNotAvail "(?:01070404|12345)" {
 snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.49"
}

 

Recommended Actions
Use multiple OIDs.
Using the example above:
alert bigipGtmWideIpNotAvail "(?:01070404|12345)" {
snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.49"
}

Can be changed  to:
alert bigipGtmWideIpNotAvail "01070404" {
snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.49"
}
alert bigipGtmWideIpNotAvail "12345" {
snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.50"
}
