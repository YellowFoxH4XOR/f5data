Known Issue

Important: This issue only affects BIG-IP version 9.3.1 HF6, HF7 and HF8 running on the following PVA enabled platforms: 3400, 6400, 6800, and 8400.

This is the result of a known issue. The pvad process will crash under the following conditions:

  • When attempting to add a pool and node at the same time, such as when synchronizing or merging a configuration containing a pool whose members did not previously exist on the system. When this occurs, the pvad process crashes immediately upon modification of the running configuration.
  • When a pool member or node has been Disabled or Forced Offline prior to rebooting the system. When this occurs, the pvad process may crash during the initial configuration load.

Under these conditions, the pvad process attempts to access the pool member(s) before the pool object has been created, which causes the pvad process to panic and restart, possibly dumping core. When pvad restarts, error messages that appear similar to the following example are logged to the /var/log/ltm file:

pvad[1186]: 01130005:3: ../main.cpp:62 - obj id=168043368 key=pool_cdrm 2404:1a8:fe00:33a1::33 80: object wasn't found!
pvad[1186]: 01130005:3: Expression 'cfgObj != cfg.end()' failed in '../CfgEvents.cpp', line: 594
pvad[1751]: 01130003:6: Starting pvad

F5 Product Development is tracking this issue as CR124061.
