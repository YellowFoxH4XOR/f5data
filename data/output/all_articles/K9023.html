K9023: The clusterd process logs an error message when a blade is unreachable

Issue

The VIPRION system is comprised of a group of blades that work together in a cluster to process network traffic. The clusterd process controls the clustering technology for the VIPRION chassis.

In previous versions, if a blade is present and powered up, but the clusterd process cannot communicate with the blade for clustering, no error message is logged to the system log files.

Starting in BIG-IP 9.6.1 for the VIPRION platform, if a blade is present and powered up, but the clusterd process cannot communicate with the blade for clustering, an error message similar to the following example is logged to the /var/log/tmm file:

slot1/<hostname> err clusterd[2346]: 013a0014:3: Blade 1: blade 4 FAILED
slot3/<hostname> err clusterd[2365]: 013a0014:3: Blade 3: blade 4 FAILED

The example error messages indicates that blades 1 and 3 in the cluster lost communication with blade 4.
