Known Issue

This is the result of a known issue. Under certain conditions, the BIG-IP system sends a TCP reset packet with an incorrect sequence number that is one increment higher than allowed. This behavior occurs when the BIG-IP system closes a connection after sending TCP zero window probe packets to the client.

In the following example, the BIG-IP system sends a data segment to the client, and the client system responds with a TCP zero window probe packet. The BIG-IP system sends a number of TCP zero window probe packets to the client before closing the connection with a TCP reset packet. Additionally, the BIG-IP system sends the TCP reset packet with an incorrect sequence number:

F5 Networks Product Development tracked this issue as CR100218 and CR121075 and it was fixed in BIG-IP LTM versions 9.4.8 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Note: When installing BIG-IP version 9.4.8, the system may report an error message similar to the following:

The products you are attempting to upgrade have hotfixes that are not resolved by the new versions you have chosen. BIG-IP 9.4.8 does not resolve CR100218.

This error message can be safely ignored as the issue was fixed in BIG-IP version 9.4.8 by CR121075.

Additionally, this issue was fixed in hotfix BIGIP-9.3.1-HF4, which has been issued for BIG-IP version 9.3.1, and in hotfix BIGIP-9.4.7-326.1-HF1, which has been issued for BIG-IP version 9.4.7. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.
