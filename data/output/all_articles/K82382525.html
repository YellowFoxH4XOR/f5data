Known Issue

The BIG-IP AAM and BIG-IP WebAccelerator systems may incorrectly honor the Age response-header

This issue occurs when all of the following conditions are met:

  • You configure the matched node in the acceleration policy to ignore response headers from the origin web server (OWS), specifically the max_age or s_maxage directives.
  • The OWS sends an Age response-header with a large value in the response.
You can configure the BIG-IP AAM and BIG-IP WebAccelerator systems to ignore HTTP response headers sent by the OWS by disabling the Honor Headers From Origin Web Server option in the Lifetime settings. If you configure the Lifetime settings to ignore the max_age or s_maxage option, the Age response-header is incorrectly honored and sent to the client.

Impact

The lifetime for the response object is incorrectly reduced by the amount of the Age response-header, causing more frequent revalidation requests to the OWS.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP AAM or BIG-IP WebAccelerator system continually returns an S10202 (Proxy due to expire) response code when requesting the object.
  • When using a traffic analysis tool, you see Age response-headers in responses to the client with values larger than the one configured for the Maximum Age setting in the WebAccelerator Cache Settings section of the acceleration policy.

Workaround

To work around this issue, you can perform one of the following procedures as appropriate for your environment:

Impact of workaround: The following procedures involve configuration changes that you should test before implementing them in a production environment.

Honoring the headers sent by the OWS

  1. Log in to the Configuration utility.
  2. Navigate to Acceleration > Web Application > Policies.
  3. Click the name of the policy that you want to edit.
  4. Expand the node tree and select the matched node.
  5. Navigate to Matching Rules and select Acceleration Rules.
  6. Select the Lifetime tab.
  7. Select the check box next to Honor Headers From Origin Web Server.
  8. In the Origin Web Server Headers section, move max_age and s_maxage to the Selected box.
  9. Click Save.  
  10. Click Publish then Publish Now.

Increasing the value for the Maximum Age setting

  1. Log in to the Configuration utility.
  2. Navigate to Acceleration > Web Application > Policies.
  3. Click the name of the policy you want to edit.
  4. Expand the node tree and select the matched node.
  5. Navigate to Matching Rules and select Acceleration Rules.
  6. Select the Lifetime tab.
  7. In the WebAccelerator Cache Settings section, increase the value for the Maximum Age setting appropriately to compensate for the Age response-header values.
  8. Click Save.  
  9. Click Publish then Publish Now.

Removing the Age response-header using an iRule 

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules and click Create.
  3. Enter a name in the Name field. In the Definition field, paste code that appears similar to the following example:

    when HTTP_RESPONSE {
       if { [HTTP::header exists "Age"] } {
          HTTP::header remove Age
       }
    }
     
  4. Click Finished.
  5. Navigate to Local Traffic > Virtual Servers and click Edit next to the virtual server that you want to modify.
  6. In the iRules section, click Manage.
  7. Move the new iRule to the Enabled box.
  8. To save the change, click Finished.
