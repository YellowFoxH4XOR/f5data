Description

It is crucial to ensure that the correct CIDR (Classless Inter-Domain Routing) prefix length or subnet mask is used when configuring the IP Prefix Set. 

Environment

  • Web App & API Protection
  • Web Application Firewall
  • F5®Distributed Cloud (XC)

Cause

Any misconfiguration of the CIDR or subnet mask can potentially lead to significant service disruptions or application issues.

Answer/Recommended Actions

An IP Prefix Set is designed to cover all possible CIDRs, so it’s essential to be precise when adding IP addresses. Try to be as specific as possible, and avoid adding overly broad or incorrect entries.

For example, let's say we intend to add the IP address 1.1.1.1/32 to the prefix set, but instead, we mistakenly configure it as 1.1.1.1/3. The 1.1.1.1/3 range includes an enormous and impractical subnet, vastly exceeding the intended scope.

Such a misconfiguration could have a serious impact on user access or application functionality, possibly allowing unintended traffic to pass through or blocking legitimate requests.

It's also important to understand the range of IP addresses that a particular subnet value covers. For instance, a subnet like 1.1.1.1/3 encompasses a much larger range than intended. Therefore, careful consideration of the CIDR prefix length is necessary to ensure that the correct set of IP addresses is being targeted and that there are no unintended consequences that could affect system stability or performance. Always double-check configurations before finalizing them to maintain optimal service integrity.
