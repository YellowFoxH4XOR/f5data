Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP system or configured software module uses remote Lightweight Directory Access Protocol (LDAP) or Active Directory (AD) authentication.
  • You want to globally prohibit LDAP from following LDAP referrals.

Description

The BIG-IP system's default LDAP configuration automatically allows the LDAP to follow LDAP referrals. In some environments, following referrals can negatively impact the authentication process, such as creating delays in login time. If your environment is impacted by the use of LDAP referrals, you can globally disable this functionality by performing the procedure appropriate for your BIG-IP version.

Note: The REFERRALS configuration option does not apply to LDAP health monitor behavior. To disable referral following for an LDAP health monitor, set the Chase Referrals setting to No. For more information, refer to K17472: Overview of LDAP Monitoring (11.x - 15.x).

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP system or configured software module uses remote Lightweight Directory Access Protocol (LDAP) or Active Directory (AD) authentication. To verify, go to System > Users > Authentication and check the User Directory setting.
  • You have administrative access to the BIG-IP system command line and the TMOS Shell (tmsh).
  • You can use a command line text editor.

Procedures

  • BIG-IP 15.1.0 and later
  • BIG-IP 15.0.1.1 (and later 15.0.x.x), and BIG-IP 14.1.2.3 (and later 14.1.x)
  • BIG-IP 15.0.0 - 15.0.1 and BIG-IP 14.1.0 - 14.1.2.2
  • BIG-IP 14.0.0 and earlier

BIG-IP 15.1.0 and later

You can disable LDAP referrals using tmsh. To do so, perform the following procedure:

Impact of procedure: Performing this procedure should not have a negative impact on your BIG-IP system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Disable the LDAP referrals by entering the following command:

    modify auth ldap system-auth referrals no

  3. Save the change by entering the following command:

    save sys config

  4. You can verify the configuration change by entering the following command:

    list auth ldap system-auth referrals

    You should see an output similar to the following example:

    auth ldap system-auth {
        referrals no
    }

BIG-IP 15.0.1.1 (and later 15.0.x.x), and BIG-IP 14.1.2.3 (and later 14.1.x)

You can disable LDAP referrals by modifying the systemauth.referrals database variable to no. To do so, perform the following procedure:

Impact of procedure: The BIG-IP system may momentarily stop packet processing when you reload the configuration. F5 recommends performing this during an appropriate maintenance window.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Disable the LDAP referrals by entering the following command:

    modify sys db systemauth.referrals value no

  3. Save the changes by entering the following command:

    save sys config

  4. Reload the configuration by entering the following command:

    load sys config

  5. You can verify the configuration change by exiting the tmsh utility and look for referrals no in the /etc/nslcd.conf configuration file. If you are familiar with the Linux command line, you can check for this entry enter grep /etc/nslcd.conf at the command prompt to check for this entry. 

BIG-IP 15.0.0 - 15.0.1 and BIG-IP 14.1.0 - 14.1.2.2

You can disable LDAP referrals by adding referrals no to the /etc/nslcd.conf configuration file. To do so, perform the workaround described in ID 806093.

BIG-IP 14.0.0 and earlier

You can globally disable LDAP referrals by manually modifying the /etc/openldap/ldap.conf configuration file and including the statement REFERRALS no. To do so, perform the following procedure:

Impact of procedure: Performing this procedure should not have a negative impact to your BIG-IP system.

  1. Log in to the command line of the affected BIG-IP system.
  2. Use a text editor to open the /etc/openldap/ldap.conf file.
  3. At the end of the listed configuration items, add the following line:

    REFERRALS no

  4. Save the file.

The content of an ldap.conf file with referrals enabled appears similar to the following example:

# LDAP Defaults
#

# See ldap.conf(5) for details
# This file should be world readable but not world writable.

#BASE   dc=example, dc=com
#URI    ldap://ldap.example.com ldap://ldap-master.example.com:666

#SIZELIMIT      12
#TIMELIMIT      15
#DEREF          never
TLS_REQCERT     never

The content of an ldap.conf file with referrals disabled from BIG-IP 12.x and later appears similar to the following example:

# # LDAP Defaults
# # See ldap.conf(5) for details
# This file should be world readable but not world writable.
#BASE dc=example,dc=com
#URI ldap://ldap.example.com ldap://ldap-master.example.com:666
#SIZELIMIT 12
#TIMELIMIT 15
#DEREF never
TLS_REQCERT never
TLS_CACERTDIR /etc/openldap/certs
REFERRALS no

The content of an ldap.conf file with referrals disabled in BIG-IP 11.x and earlier appears similar to the following example:

# LDAP Defaults
#

# See ldap.conf(5) for details
# This file should be world readable but not world writable.
