Topic

You should consider using this procedures under the following condition:

  • You want to use the iControl REST API to create or delete configuration objects.

Note: The procedures in this article provide examples of creating and deleting BIG-IP LTM pools and pool member configuration objects on a remote BIG-IP device. For information about the command options available to create other configuration objects or to perform other actions, refer to the iControl REST API User Guides in the Supplemental Information section of this article.

Description

The REST interface for iControl provides the ability to execute TMOS Shell (tmsh) transactions by sending specifically formatted HTTPS POST requests to the BIG-IP system. For example, you can use the iControl REST API to create configuration objects, such as a BIG-IP LTM pool, on a remote BIG-IP system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to a client system with a third-party application that can send user-defined HTTPS POST requests to the BIG-IP system.

    Note: The procedures in this article use the client URL (cURL) utility.

  • You have administrative access to the remote BIG-IP system on which you want to create or delete configuration objects.
  • The IP address on the remote BIG-IP system is configured to allow port 443 access to the iControl REST API.

Procedures

  • Using cURL to create BIG-IP LTM nodes and pools with pool member objects through the iControl REST API
  • Using cURL to delete BIG-IP LTM pools and node objects using the iControl REST API
  • Using cURL to cancel REST API transactions before validating

Note:  The following procedures are designed for a locally authenticated user only.  To use a remotely authenticated user, first refer to the following iControl REST API document: Demystifying iControl REST Part 6: Token-Based Authentication. A DevCentral login may be required to access this content.

Using cURL to create BIG-IP LTM nodes and pools with pool member objects through the iControl REST API

The following procedure provides an example of creating configuration objects using the iControl REST API on a remote BIG-IP system, using the cURL utility to create a BIG-IP LTM node and pool with pool member configuration objects.

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to a client system that has the cURL utility.
  2. To retrieve a transaction ID from the remote BIG-IP system, use the following cURL command syntax:

    Note: A transaction ID is optional and allows you to create a batch of objects in one transaction as opposed to individual transactions for each object.

    curl -k -u <username>:<password> -X POST -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/transaction -d '{}'

    In this example, <username>:<password> is the administrative username and password for the remote BIG-IP system and <bigip_IP> is the IP address of the remote BIG-IP system.

    For example, to retrieve a transaction ID using the iControl REST API from a remote BIG-IP system with an IP address 192.0.2.245, use the following cURL command:

    curl -k -u admin:admin -X POST -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/transaction -d '{}'

    The remote BIG-IP system returns a response similar to the following:

    {"transId":1496415088627479,"state":"STARTED","timeoutSeconds":120,"asyncExecution":false,"validateOnly":false, "executionTimeout":300,"executionTime":0,"failureReason":"","kind":"tm:transactionstate","selfLink": "https://localhost/mgmt/tm/transaction/1496415088627479?ver=13.0.0"}

    The transaction ID is listed in the transId field. In this example, the returned transaction ID is 1496415088627479.

    Important: The transaction ID continues to increment over time and is only valid for 120 seconds; therefore you must request a new transaction ID if more than 120 seconds elapses after retrieving the transaction ID.

  3. Create a BIG-IP LTM node configuration object using the iControl REST API on the remote BIG-IP system. To do so, use the following use the following cURL command syntax:

    curl -k -u <username>:<password> -X POST -H "Content-Type: application/json" -H "X-F5-REST-Coordination-ID: <transaction_id>" https://<bigip_ip>/mgmt/tm/ltm/node -d '{"name":"<node_name>","address":"<node_ip>"}'

    In this example:

    • <username>:<password>M is the administrative username and password for the remote BIG-IP system.
    • <transaction_id> is the transaction ID retrieved in step 2.
    • <bigip_ip> is the IP address of the remote BIG-IP system.
    • <node_name> is the name you want to specify for the node configuration object.
    • <node_ip> is the IP address you want to specify for the node configuration object.
  4. Create a BIG-IP LTM pool with a pool member configuration object using the iControl REST API on the remote BIG-IP system. To do so, use the following cURL command syntax:

    curl -k -u <username>:<password> -X POST -H "Content-Type: application/json" -H "X-F5-REST-Coordination-ID: <transaction_id>" https://<bigip_ip>/mgmt/tm/ltm/pool -d '{"name":"<pool_name>","members":"<node_name>:<port>"}'

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • <transaction_id> is the Transaction ID retrieved in step 2.
    • <bigip_ip> is the IP address of the remote BIG-IP system.
    • <pool_name> is the name you want to specify for the pool configuration object.
    • <node_name>:<port> is the name and service port of the node object you want to add as a member to the pool configuration object.

    For example, to create a BIG-IP LTM pool object named REST_pool_01 with a pool member REST_node_01:80, use the following cURL command:

    curl -k -u admin:admin -X POST -H "Content-Type: application/json" -H "X-F5-REST-Coordination-ID: 1496415088627479" https://192.0.2.245/mgmt/tm/ltm/pool -d '{"name":"REST_pool_01","members":"REST_node_01:80"}'

  5. Validate the newly created configuration objects and save them to the BIG-IP system running configuration (memory). To do so, use the following use the following cURL command syntax:

    curl -k -u <username>:<password> -X PATCH -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/transaction/<transaction_id> -d '{ "state":"VALIDATING" }'

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • <bigip_ip> is the IP address of the remote BIG-IP system.
    • <transaction_id> is the transaction ID retrieved in step 2.

    For example, the following command saves the REST_pool_01 and REST_node_01 configuration objects to memory:

    curl -k -u admin:admin -X PATCH -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/transaction/1496415088627479 -d '{ "state":"VALIDATING" }'

    Important: Configuration objects created while communicating with the iControl REST API remain within the API's memory until the REST transaction state is changed to VALIDATING, at which point the configuration objects are created in the BIG-IP's running memory. If you want to cancel a REST transaction before validating and without saving it to the BIG-IP system's running configuration, refer to Using cURL to cancel a REST API transaction before validating.

    Note: If there is an error in one or more of the objects created during the REST API transaction, the BIG-IP system responds with a message similar to the following: {"code":404,"message":"transaction failed:01020036:3: The requested node (/Common/REST_node_01) was not found.","errorStack":[],"apiError":2}.

  6. Save the BIG-IP system's running configuration to disk. To do so, use the following use the following cURL command syntax:

    curl -k -u <username>:<password> -X POST -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/sys/config -d '{"command":"save"}'

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • <bigip_ip> is the IP address of the remote BIG-IP system.

    For example:

    curl -k -u admin:admin -X POST -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/sys/config -d '{"command":"save"}'

Using cURL to delete BIG-IP LTM pools and pool members through the iControl REST API

The following procedure provides an example of deleting configuration objects through the iControl REST API on a remote BIG-IP system, using the cURL utility to delete the BIG-IP LTM pool and node objects you created in the previous procedure.

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to a client system that has the cURL utility.
  2. Delete a the BIG-IP LTM pool configuration object through the iControl REST API on the remote BIG-IP system. To do so, use the following use the following cURL command syntax:

    curl -k -u <username>:<password> -X DELETE -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/ltm/pool/~<partition>~<pool_name>

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • <bigip_ip> is the IP address of the remote BIG-IP system.
    • <partition> is the name of the administrative partition in which the pool object is configured.
    • <pool_name> is the name of the BIG-IP LTM pool object you want to delete.

    For example, to delete a BIG-IP LTM pool object named REST_pool_01 in the common partition on remote BIG-IP system 192.0.2.245, use the following cURL command:

    curl -k -u admin:admin -X DELETE -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/ltm/pool/~Common~REST_pool_01

  3. Delete a BIG-IP LTM node configuration object through the iControl REST API on the remote BIG-IP system. To do so, use the following use the following cURL command syntax:

    curl -k -u <username>:<password> -X DELETE -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/ltm/node/~<partition>~<node_name>

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • lt;bigip_ip> is the IP address of the remote BIG-IP system.
    • <partition> is the name of the administrative partition the node object is configured in.
    • <node_name> is the name of the BIG-IP LTM node object you want to delete.

    For example, to delete a BIG-IP LTM node object name REST_node_01 in the common partition on remote BIG-IP system 192.0.2.245, use the following cURL command:

    curl -k -u admin:admin -X DELETE -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/ltm/node/~Common~REST_node_01

  4. Save the BIG-IP systems running configuration to disk. To do so, use the following use the following cURL command syntax:

    curl -k -u <username>:<password> -X POST -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/sys/config -d '{"command":"save"}'

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • <bigip_ip> is the IP address of the remote BIG-IP system.

    For example:

    curl -k -u admin:admin -X POST -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/sys/config -d '{"command":"save"}'

Using cURL to cancel REST API transactions before validating

The following procedure provides an example of canceling any in-progress REST API transactions before validating them and saving to the BIG-IP system's running configuration.

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to a client system that has the cURL utility.
  2. To retrieve a Transaction ID from the remote BIG-IP system, use the following cURL command syntax:

    Note: A transaction ID is optional and allows you to create a batch of objects in one transaction as opposed to individual transactions for each object.

    curl -k -u <username>:<password> -X POST -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/transaction -d '{}'

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • <bigip_IP> is the IP address of the remote BIG-IP system.

    For example, to retrieve a transaction ID through the iControl REST API from a remote BIG-IP system with an IP address 192.0.2.245, use the following cURL command:

    curl -k -u admin:admin -X POST -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/transaction -d '{}'

    The remote BIG-IP system returns a response similar to the following:

    {"transId":1496415088627479,"state":"STARTED","timeoutSeconds":120,"asyncExecution":false,"validateOnly":false,"executionTimeout":300, "executionTime":0,"failureReason":"","kind":"tm:transactionstate","selfLink":"https://localhost/mgmt/tm/transaction/1496415088627479?ver=13.0.0"}

    The transaction ID is listed in the transId field. In this example, the returned transaction ID is 1496415088627479.

    Important: The transaction ID continues to increment over time and is only valid for 120 seconds; therefore, you must request a new transaction ID if more than 120 seconds elapse after retrieving the transaction ID.

  3. Cancel all in-progress REST API transactions that have not yet been validated and saved to the BIG-IP system's running configuration. To do so, use the following use the following cURL command syntax:

    curl -k -u <username>:<password> -X DELETE -H "Content-Type: application/json" https://<bigip_ip>/mgmt/tm/transaction/<transaction_id>

    In this example:

    • <username>:<password> is the administrative username and password for the remote BIG-IP system.
    • <bigip_ip> is the IP address of the remote BIG-IP system.
    • <transaction_id> is the transaction ID retrieved in step 2.

    For example:

    curl -k -u admin:admin -X DELETE -H "Content-Type: application/json" https://192.0.2.245/mgmt/tm/transaction/1496415088627479
