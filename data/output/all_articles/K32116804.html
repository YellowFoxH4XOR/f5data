Description

After a new Install of BIG-IP on KVM hypervisor that has 40G interfaces, tmsh show sys interface shows the interface at 10G

Using ethtool command on bash does confirm 40G interface.

Environment

BIG-IP VE on KVM hypervisor

Cause

PCI passthrough of physical functions is not supported, SR-IOV for XL710 and related boards are supported. The driver in use (from the device_probed command) shows that the 'sock' driver is being used rather than ixlv.

This means that the Linux kernel's driver (interrupt based rather than poll mode) is being used and the tmm is getting the packets via raw socket. This will be significantly lower throughput and connections per second than using SR-IOV with a virtual function, have higher jitter and latency, and higher CPU and memory consumption.

Recommended Actions

To see which driver is being used run the following command:

'tmctl -d blade tmm/device_probed' 

or check the tmctl data in QKView for 'tmm.device_probed'
