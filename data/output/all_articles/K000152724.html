Description

When using BIG-IP LTM with SNAT Automap or a SNAT pool enabled on a Virtual Server (VIP), there may be a requirement to selectively disable SNAT for specific source IP addresses or subnets. This is typically needed when certain clients must retain their original source IP address as traffic passes through the BIG-IP, while all other clients should continue to use SNAT Automap. No specific error messages are generated, but improper configuration may result in unexpected SNAT behavior.

Environment

  • BIG-IP LTM
  • iRules
  • Configuration: Virtual Server with SNAT enabled

Cause

The default SNAT Automap configuration applies SNAT to all incoming connections. To bypass SNAT for specific source IPs or subnets, an iRule must be used to override the default behavior based on a data group match.

Recommended Actions

  • Create a data group (e.g., `no_snat_source_ip`) containing the IP addresses and subnets that should bypass SNAT.
  • Create an iRule using that data group

This iRule checks if the client IP matches an entry in the data group. If it does, SNAT is disabled for that connection; otherwise, default SNAT applies. 

when CLIENT_ACCEPTED {
       # Optional: Enable debug logging
       set debug 1

       # Check if the source IP address is part of the no_snat_source_ip data group
       if { [matchclass [IP::client_addr] equals no_snat_source_ip] } {
         if { $debug } {
           log local0. "[IP::client_addr] is not SNAT'd"
         }
         # Disable SNAT for this connection
         snat none
       }
     }
  •  Apply the iRule to the virtual server.

 

Additional Information

Data groups: 

  • See K000152726: Creation of a Data Group

Debugging:

  •  Enable logging within the iRule to verify correct operation and confirm which connections are bypassing SNAT.
  •  Logs can be viewed in `/var/log/ltm`.`
