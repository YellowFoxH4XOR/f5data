Known Issue

The BIG-IP ASM system may log benign error messages after an upgrade.

This issue occurs when the following condition is met:

  • You have upgraded your BIG-IP ASM system.

The BIG-IP ASM log error messages, when web scraping client-side statistics, are updated for a non-existent account.

Impact

This error message is benign and may be safely ignored.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP iHealth lists Heuristic H567670 on the Diagnostics > Identified > Low screen.
  • The system writes error messages that appear similar to the following example to the /var/log/ts/dcc.log file:

    dcc|INFO|<date>|<pid>| [DB::add_client_side_drop_data_entry, ] The table CLIENT_SIDE_DROPPED_STAT is empty.
    dcc|ERR|<date>|<pid>| [DB::insert_ev_client_side_dropped_data_reporting, ]  mysql_stmt_execute, failed.
    dcc|ERR|<date>|<pid>| [DB::insert_ev_client_side_dropped_data_reporting, ]  Cannot add or update a child row: a foreign key constraint fails =(`DCC`.`CLIENT_SIDE_DROPPED_STAT`, CONSTRAINT `CLIENT_SIDE_DROPPED_STAT_ibfk_1` FOREIGN KEY (`account_id`) REFERENCES `ACCOUNTS` (`account_id`) ON DELETE ).
    dcc|INFO|<date>|<pid>| [DB::insert_ev_client_side_dropped_data_reporting, ]  invalid affected rows by MySQL.

Resolution

F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can use the bigstart utility to restart the asm process. To do so, perform the following procedure:

Impact of workaround: Restarting the asm process causes a brief traffic disruption.

  1. Log in to the command line of the BIG-IP system
  2. Restart the BIG-IP ASM system by typing the following command:

    bigstart restart asm
