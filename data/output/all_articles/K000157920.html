K000157920: APM: None of the configured JWK keys match the received JWT token. The trigger - Expired token

Source

Description

BIG-IP administrators may notice the below error message when APM is configured as an oAuth Resource Server utilizing the oAuth Scope agent:

Nov 10 13:13:57 bigip.apm err apmd[15118]: 01490290:3: /Common/StartAllow_ap::f82f7602./Common/f5_oauth_scope/YXhzMnN1YnNpZA==:/Common/f5_oauth_scope_act_oauth_scope_subsession_ag: OAuth Scope: failed for jwt-provider-list '<provider list>' , error: None of the configured JWK keys match the received JWT token, JWT Header: <token header>

The error itself may have several triggers. This article will describe the expired token trigger.

Environment

  • APM 
  • oAuth
  • Expired JWT

Cause

The oauth scope agent checks the validity of a token. One such check is the token expiration. A token is rejected by the oAuth scope agent if:

  1. The expiration time (exp) in the jwt has expired
  2. The token was issued at a time (iat claim in the token) longer than the set "Access Token Expires In" value.  This is configured in the Token Configuration or Providers List. A value of 0 means the oAuth Scope agent will use the tokens exp claim.

Recommended Actions

  1. Make sure the token's exp claim is still valid
    1. you can use https://jwt.io to parse the token and see the claims
  2. Check the value of "Acess Token Expires In" value and compare that to the iat claim in the token
    1. Access -> Federation -> JSON Web Token -> Token Configuration and select the configuration in use. "Use Provider List Settings" may be selected in which case use 2b
    2. Access -> Federation -> JSON Web Token -> Provider List and select the provider list in use.
