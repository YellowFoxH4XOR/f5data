Topic

When you define a fallback host and the connection attempt to the selected load balancing target fails by the time the BIG-IP LTM system is ready to send the request, the BIG-IP LTM system sends the specified HTTP redirect in the following situations:

  • A pool member is not chosen (the system failed to select a pool or a pool member, or no pool members were available).
  • A pool member is unreachable (when no route to the target exists).
  • A pool member is unresponsive (resets a connection request).
  • A pool member closes an established connection before the request is sent.

This change in behavior enables the BIG-IP LTM system to send a redirect to the client as soon as the server-side connection attempt fails, regardless of whether a health monitor has marked the node down.

If you want the BIG-IP system to send the specified HTTP redirect to the client only when no pool members are available, apply the following iRule to the virtual server, along with an HTTP profile that has no Fallback Host configured:

when LB_FAILED {
if { [active_members [LB::server pool]] < 1 } {
# The redirect will be sent only if LB_FAILED
# was because the pool had no available members.
HTTP::fallback "http://example.com/redirect.html"
}
}

This iRule sends the specified redirect only if there are no available pool members. No action is triggered if the connection attempt fails while the pool still has available members.

Note: For more information about the use of the LB_FAILED iRules event, refer to the LB_FAILED page.

Note: For information about implementing pool member reselection after a server-side connection failure, refer to K10640: Pool member reselection options.
