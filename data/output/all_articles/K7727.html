After performing an upgrade to a new major or minor release, and upon booting into the new version, the BIG-IP licensing system needs to verify that the static license check date in your BIG-IP version against the service check date in the license file. If the service check date is missing or is earlier than the license check date, the system will fail to load the configuration when you attempt to boot the upgraded software. If you boot into your newly upgraded system and the configuration fails to load due to a service check date issue, you can resolve this by reactivating your license.

F5 defines a system upgrade as moving from one major release to another major release, or moving from a minor release to another minor release. F5 defines a system update as moving from one maintenance release or point release to another maintenance or point release within the same major and minor version.

For example, moving from 15.1.0 to 16.0.0 is considered an upgrade as the major version number changed, and moving from 14.0.0 to 14.1.0 is also an upgrade as the minor version number changed. Moving from 15.0.1 to 15.0.2 (maintenance release) or 15.1.2 to 15.1.2.1 (point release) is considered an update.

When updating to a newer maintenance or point release, no service or license check date verification takes place and the configuration should load normally.

F5 recommends reactivating your license before proceeding with an upgrade or an update. Doing this will reset your service check date, and also verify that there are no licensing issues before upgrading or updating.

Service Check Date

The service check date is located in the BIG-IP license and is the same as the date the license was last activated or the date the service contract for the device expires, whichever date is earlier. For example, if you have an active service contract that ends December 31, 2020, and you license a device on June 30, 2020, the service check date is set to June 30, 2020.

Note: The service check date in the BIG-IP license is updated each time the license is reactivated, if there is an active service contract for this BIG-IP system. For example, if you have an active service contract that ends June 30, 2020, and you license a device on December 31, 2020, the service check date is still set to June 30, 2020.

Enforcement during an upgrade

When you perform a software upgrade on the BIG-IP system, the installation process does validate the service check date with the license check date of the version being installed. If the service check date is missing or is earlier than the license check date, the system will fail to load the configuration when you attempt to boot into the upgraded boot location.

Enforcement during system startup

The license check date enforcement is applied during system startup. The system compares the license check date to the service check date in the license file. If the service check date is earlier than the license check date, the system initializes, but does not load the configuration. To allow the configuration to load, you must update the service check date in the license file by reactivating your license.

Important: Do not upgrade the system if the service check date is earlier than the license check date. If the service check date is earlier, you must first reactivate your license on the system.

Prevent and recover from license-related upgrade issues

You can prevent upgrade issues by relicensing your system before you perform the upgrade, or recover a system that fails to initialize by relicensing your system after you perform the upgrade.

For example, if license enforcement fails during the upgrade, the configuration may fail to load when booting to the new volume. When this occurs, the Configuration utility may display an error message that appears similar to the following example:

The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

To mitigate license-related upgrade issues, you can perform the following procedures:

  • Verify the service check date of your license
  • Reactivate the system license

To watch a video demo of these procedures, go to  Verifying the service check date and reactivating your BIG-IP license.

Verify the service check date of your license

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. To change directories to the /config directory, enter the following command:

    cd /config

  3. To parse the bigip.license file for the Service check date, enter the following command:

    grep "Service check date" bigip.license

    The output appears similar to the following example:

    Service check date : 20230125

    Note: The date format is year-month-day, so this example output is January 25, 2023.

    Alternatively, you can use the following tmsh command:

    tmsh show sys license | grep "Service Check Date"

    The output appears similar to the following example:

    Service Check Date                     2023/01/25

  4. Reference the License Check Date table listed previously in this article, and verify that the service check date from step 3 is a later date than the license check date listed for the version to which you are upgrading. For example, to upgrade to BIG-IP 16.1.x, your service check date should be 20210611 (June 11, 2021) or later.

Important: If the service check date in your bigip.license file is earlier than the license check date for the software version you are attempting to install, you must reactivate the system's license before upgrading.

Reactivate the system license

Important: The license reactivation process will trigger a reload of the configuration, which will temporarily interrupt all traffic processing. This process can also trigger an unexpected Failover event if performed on an Active HA mode BIG-IP system. To prepare for this maintenance and to check for existing errors in the configurations prior to reactivating or updating the license refer to K000151666: Best Practices when preparing to update license on BIG-IP.

Note: For BIG-IP tenants running and using the license on F5OS hardware products such as F5 rSeries or VELOS, you should always perform licensing operations at the F5OS platform layer. The BIG-IP tenant(s) will automatically inherit the license from the F5OS platform layer. For more information about reactivating the license for a BIG-IP tenant running on F5OS, refer to K000151705: Viewing and licensing or reactivating a license for F5OS rSeries.

Note: Be sure to log in as the admin user to relicense the system. For more information, refer to K9965: The admin user account must be used to license the system.

  1. Log in to the Configuration utility.
  2. Go to System > License > Re-activate.
  3. Select either Automatic or Manual as the activation method.

    Note: If your system does not have Internet access to the F5 license server, you must select Manual.

  4. Select Next and follow the instructions.
