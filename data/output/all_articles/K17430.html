Known Issue

Using the http-explicit profile's Explicit Proxy feature in combination with an iRule may cause the Traffic Management Microkernel (TMM) to produce a core file.

This issue occurs when the following condition is met:

  • You have configured the BIG-IP virtual server with the following features:

    • An http-explicit profile (HTTP profile with the Proxy Mode setting configured to Explicit)
    • An iRule that contains HTTP::respond or HTTP::collect in the HTTP_REQUEST event

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if you have configured it for HA.
  • The system logs messages to the /var/log/tmm file that appear similar to the following example:

    notice panic: ../modules/hudfilter/http/http.c:7438: Assertion "Not yet responded" failed
    notice ** SIGFPE **

  • The BIG-IP system generates TMM core files to the /shared/core directory, with a time stamp that correlates to the traffic interruption that appears similar to the following example:

    tmm.0.bld3.36.412.core.gz
