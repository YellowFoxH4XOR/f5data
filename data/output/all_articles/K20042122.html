K20042122: iSeries: 16.1.x / 17.0.x connectivity issues, interfaces or trunks down

Type
Support Solution
Published
2022-03-11
Updated
2023-09-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.X.X, 16.1.X, 17.0.X, 17.0.0, 16.1.3, 16.1.2, 16.1.1, 16.1.0
Source
https://my.f5.com/manage/s/article/K20042122

Description

Connectivity issues occurring while running 16.1.x or 17.0.x, with one or more of the following symptoms:

  • Interfaces down
  • Trunks down
  • Active/Active
  • LACP issues
  • HA disconnected
  • ARP incomplete
  • Traffic disruption
  • Monitor failures
  • Failsafe fault

Environment

  • iSeries (i5000, i7000, i10000, i11000)
  • BIG-IP version 16.1.x, 17.0.x (specific affected versions listed below)
  • Interfaces

Cause

The problem is caused by an issue with interaction between the HSB and internal switchboard interfaces, which receive a large number of pause frames from the HSB.

This is a rare issue that might occur with certain FPGA firmware versions in use.

Most often this issue is experienced shortly after an upgrade, but can also manifest after running an affected version for some time.

Recommended Actions

Use the following command to determine if any of the internal switch interfaces have received a large number of pause frames:

tmctl switch_internal -s name,counters.rx_pause | grep -E 'name|(9|10|11|12)\.1'

Or alternatively, the following two commands will review not only the most recent counters looking for pause frames, but also in the historical stats stored, particularly useful when the problem has occurred some hours ago.

tmctl -lD shared/tmstat/snapshots/blade0/public/3600/ switch_internal -s name,counters.rx_pause | grep -E 'name|(9|10|11|12)\.1'

tmctl -lD shared/tmstat/snapshots/blade0/performance/10/ switch_internal -s name,counters.rx_pause | grep -E 'name|(9|10|11|12)\.1'

Note: For vCMP systems, this command should be used on the vCMP host.

If pause frames are not seen in the output of the above commands, the system is not affected by this issue, and further investigation would be required.

If you determine that your system is affected by this issue, then appropriate action depends on which FPGA firmware type is in use.

An immediate workaround is to reboot the affected system. Collect a qkview while the system is in the problematic state.

Review the output of the tmsh list sys fpga firmware-config command, to determine if the system is running a standard or performance FPGA firmware.

For example:

sys fpga firmware-config {
    type standard-balanced-fpga
}
-or-
sys fpga firmware-config {
    type l7-performance-fpga
}

For systems running 16.1.x with a standard FPGA firmware version, the issue is fixed with new firmware in 16.1.3 onwards with the fix for bug ID 1090097. Upgrade to a fixed version. BIG-IP 16.1.0 through 16.1.2.2 are affected by this issue

For systems running 17.0.x with a standard FPGA firmware version, a fix can be acquired by opening a support case and requesting a hotfix for bug ID 1090097. Until a fix is released all BIG-IP 17.0.x versions are affected.

For systems running 16.1.x with a performance FPGA firmware version, the issue is fixed with new firmware in 16.1.4 onwards with the fix for bug ID 1127009. BIG-IP 16.1.0 through 16.1.3 are affected by this issue

For systems running 17.0.x with a performance FPGA firmware version, a fix can be acquired by opening a support case and requesting a hotfix for bug ID 1127009. Until a fix is released all BIG-IP 17.0.x versions are affected.
