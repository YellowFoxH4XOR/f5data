Topic

A stateless virtual server provides improved User Datagram Protocol (UDP) performance over a standard virtual server in specific scenarios, but with limited feature support. This article discusses some uses as well as the limitations of the stateless virtual server.

Description

A stateless virtual server accepts traffic that matches the virtual server address and load balances the packet to the pool members without attempting to match the packet to a pre-existing connection in the connection table. Any new connection entry is immediately removed from the connection table. This behavior addresses the requirements for one-way UDP traffic that needs to be processed at very high throughput levels. As such, a stateless virtual server is not suitable for processing traffic that requires stateful tracking, such as TCP traffic.

The following examples are scenarios where a stateless virtual server can be useful:

  • When load balancing syslog traffic to a pool of syslog servers
  • When load balancing DNS queries to a pool of DNS servers that do not use the originating BIG-IP system as the gateway to return DNS responses to the clients

    Note: For DNS servers that also use the originating BIG-IP system to return DNS responses to the clients, refer to the Load balancing bidirectional stateless UDP traffic section, later in this article.

    Important: When selecting the pool load balancing method, multiple load balancing options display. However, the BIG-IP system supports only Round Robin load balancing for stateless connections.

The stateless virtual server does not support the following features:

  • iRules
  • IP Fragmentation
  • Persistence
  • Connection mirroring
  • Rate shaping
  • Secure Network Address Translation (SNAT) automap
  • Port translation

    Note: Some of these features that are not supported may still appear when configuring the stateless virtual server. For example, the Port Translation setting will not work as expected if enabled on the stateless virtual server.

Load balancing bidirectional stateless UDP traffic

If you require the BIG-IP system to handle the return traffic from the pool members back to the clients, you must create a separate stateless virtual server. Depending on your setup, you may need the stateless virtual server for the return traffic to use a network address with a SNAT pool that translates the source address of the outbound traffic back to the stateless virtual server that handles the incoming client traffic.

For example, the following configuration stanzas describe the stateless virtual server myIngressStatelessvs that handles incoming client DNS requests, listening on 30.30.30.234, and load balancing to the pool myDNSpool that comprises DNS servers 20.20.20.155 and 20.20.20.156:

ltm virtual myIngressStatelessvs {
destination 30.30.30.234:domain
ip-protocol udp
mask 255.255.255.255
pool myDNSpool
profiles {
udp { }
}
stateless
vlans {
external
}
vlans-enabled
}
ltm pool myDNSpool {
members {
20.20.20.155:domain {
address 20.20.20.155
}
20.20.20.156:domain {
address 20.20.20.156
}
}
}

The following configuration stanzas describe the corresponding stateless network virtual server myEgressStatelessvs that sends traffic back through a gateway pool internal-gw with a gateway 30.30.30.158 using the SNAT pool myEgressSnat with the address 30.30.30.234, which is the address of the originating stateless virtual server:

ltm virtual myEgressStatelessvs {
destination 0.0.0.0:any
ip-protocol udp
mask any
pool internal-gw
profiles {
udp { }
}
snatpool myEgressSnat
stateless
translate-address disabled
translate-port disabled
vlans {
internal
}
vlans-enabled
}
ltm pool internal-gw {
members {
30.30.30.158:any {
address 30.30.30.158
session monitor-enabled
state up
}
}
}
ltm snatpool myEgressSnat {
members {
30.30.30.234
}
}

Creating a stateless virtual server

You can create a stateless virtual server using either the Configuration utility or the TMOS Shell (tmsh). To do so, perform either of the following procedures:

  • Using the Configuration utility to create a stateless virtual server
  • Using tmsh to create a stateless virtual server

Using the Configuration utility to create a stateless virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click Create.
  4. In the Type list, select Stateless.
  5. In the Protocol list, select UDP.
  6. In the Default Pool list, select the pool to use.
  7. Fill in the remaining fields, as appropriate, for your environment.
  8. Click Finished.

Using tmsh to create a stateless virtual server

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To create the stateless virtual server, use the following command syntax:

    create ltm virtual <vs name> stateless ip-protocol udp pool <pool name> destination <IP:Port>

    For example, to create the stateless virtual server myIngressStatelessvs with IP address 30.30.30.234, and port 53 using pool myDNSpool, you would type:

    create ltm virtual myIngressStatelessvs stateless ip-protocol udp pool myDNSpool destination 30.30.30.234:53

  3. Save the change by typing the following command:

    save sys config
