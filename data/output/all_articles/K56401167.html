Description

Standard Virtual Servers do not enable the Window Scaling option in TCP SYN or SYN/ACK packets.
 

Environment

  • Standard Virtual Server
  • TCP profile with the following settings:
    • Send Buffer Size of 65535 or lower
    • Receive Window Size of 65535 or lower

 

Cause

TCP window scaling is automatically enabled when profile settings allow the system to use windows larger than 65535 bytes. TCP profiles have two settings which control the maximum TCP window size:

  • Send Buffer Size controls the maximum size of BIG-IP's congestion window 
  • Receive Window Size controls the maximum window size BIG-IP will advertise

If either of these settings are greater than 65535, BIG-IP will enable the Window Scale option in SYNs and echo it in SYN/ACKs when it is received from clients.
 

Symptoms

In a packet capture, the affected TCP conversations can exhibit the following symptoms:

  • At the time of TCP handshake the BIG-IP does not include option Window Scale
  • Relative to the time of the affected TCP conversation a large part is spent between
    1. TCP fragment flagged as [Expert Info (Warning/Sequence): TCP Zero Window segment] or showing receive window smaller than TCP MSS
    2. TCP fragment showing receive window larger than TCP MSS
  • Relative to the time of the affected TCP conversation a large part is showing the number of bytes in flight less than one TCP MSS away from 65,535
  • Payload arriving from the peer in shorter bursts of around 65,353B separated by longer periods of no traffic

 

Recommended Actions

Depending on the other design requirements, allowing TCP window scaling may help to improve the performance. For further considerations see K3422: Overview of content spooling
 

Additional Information

The TCP Window Scale option is an extension specified in RFC 7323: TCP Extensions for High Performance. This feature allows TCP endpoints to advertise window sizes larger than 65535 bytes through a mechanism known as window scaling.

Note: Increasing the Receive Window size allows the BIG-IP system to receive more data each time, but also increases memory usage for each connection.

The Window Scaling factor is adjusted by modifying the Receive Window with the following calculation:  2^[scale factor] x 65535.  

For example:  2^8 x 65535 = 16776960
