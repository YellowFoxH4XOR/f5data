Description

On Big-IP AFM devices, there is an SNMP MIB OID called ltmFwNatDynamicPoolStatPbaActivePortBlocks, that returns the stats of the number of Active Port Blocks. Active Port Blocks are using as part of AFM's source address translation mechanism when Port Block Allocation (PBA) is used  See K84221832: Understanding CGNAT port block allocation sizing and tools for further details on PBA.

However due to the nature of the design, there is a scenario where the statistics returned by this SNMP OID can be incorrect in comparison to what is actually being processed by the Big-IP.


Environment

When all of the following conditions are met, the SNMP ltmFwNatDynamicPoolStatPbaActivePortBlocks MIB can be incorrect.

  • A bladed chassis with more than one blade.
  • AFM or CGNAT is provisioned and a source translation pool using PBA is configured
  • The Big-IP is standalone in regards to device service cluster.
  • Individual blades have been rebooted at different times.


Cause

The PBA stats can become inconsistent after a blade reboot if not all blades are rebooted at the same time. The expectation is to use HA pair in order to sync the PBA session DB entries and make corrections in PBA entries during blade reboots.

Depending on which blade is rebooted and what kind of PBA session DB entries (created locally or remotely), the stats can go wrong (compared to lsndb list pba, which fetches data directly from session DB) in 2 ways:

  1. Negative (Shown as huge 64 bit number due to the use of unsigned 64 bit counter)
  2. Relatively small Positive numbers, but not in accordance with lsndb list commands.
To check, run this command from the bash prompt on the BIG-IP:

snmpwalk -c <SNMP Community Name> localhost ltmFwNatDynamicPoolStat | grep ltmFwNatDynamicPoolStatPbaActivePortBlocks

and the output should be something similar to:

F5-BIGIP-LOCAL-MIB::ltmFwNatDynamicPoolStatPbaActivePortBlocks."/Common/F5-CGNAT-01-NAT_Pool" = Counter64: 133117


Then take the output of this command:

lsndb list pba

There should be a count of the total number of entries at the end of this output. Similar to the below.

15412 port block entries found

As you can see SNMP shows there are 133117 Active Port Blocks, but in reality there are only 15412 Active Port Blocks.

Recommended Actions

It is recommended if in a standalone AFM bladed environment to ensure all blades are rebooted at the same time using clsh.
