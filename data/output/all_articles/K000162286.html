Security Advisory Description

If a BIND resolver is performing DNSSEC validation and encounters a maliciously crafted zone, the resolver may consume excessive CPU. Authoritative-only servers are generally unaffected, although there are circumstances where authoritative servers may make recursive queries (see: https://kb.isc.org/docs/why-does-my-authoritative-server-make-recursive-queries). This issue affects BIND 9 versions 9.11.0 through 9.16.50, 9.18.0 through 9.18.46, 9.20.0 through 9.20.20, 9.21.0 through 9.21.19, 9.11.3-S1 through 9.16.50-S1, 9.18.11-S1 through 9.18.46-S1, and 9.20.9-S1 through 9.20.20-S1. (CVE-2026-1519)

BIG-IP LTM with no DNS provisioned

The BIG-IP system contains the vulnerable version of BIND, and BIND is enabled by default. However, when LTM is provisioned and DNS is not provisioned, BIND is present but is not used as a resolver performing Domain Name System Security Extensions (DNSSEC) validation. Because the attack requires DNSSEC validation to be in the processing path, LTM with no DNS module provisioned is not vulnerable.

BIG-IP with DNS provisioned

BIG-IP DNS is vulnerable under the following conditions:

  • BIND is acting as a recursive resolver. By default, BIND on the BIG-IP system has recursion no; configured, which means it is not a recursive resolver. If you have manually enabled recursion by adding recursion yes; to the named.conf file, BIND can perform DNSSEC validation on behalf of clients and is therefore vulnerable. You can check this by running grep recursion /var/named/config/named.conf. If the result shows recursion no;, this configuration is not vulnerable.
  • DNS Cache is configured as a Validating Resolver. If a DNS Cache instance has been configured with the type set to Validating Resolver, it performs DNSSEC validation as its core function regardless of what BIND's recursion setting is. This means a system can be vulnerable through this path even if BIND recursion is disabled. You can check this by running the tmsh list ltm dns cache validating-resolver command. If any output is returned, a Validating Resolver cache exists and the system is vulnerable when using this configuration.

    A plain Resolver cache type (not Validating Resolver) performs recursive resolution but does not perform DNSSEC validation, so it is not directly vulnerable to this specific CVE.
    Even if BIND recursion is disabled, if the system relies on BIND's DNSSEC validation logic and can accept queries from sources that could reach attacker-controlled domains, there is still potential exposure. In practice, the Validating Resolver DNS Cache path is the most likely way this applies when BIND recursion is off.

Impact

This vulnerability allows unauthenticated denial-of-service (DoS) when a BIND resolver performs DNSSEC validation when the resolver receives a malicious DNSSEC-signed zone/response. A specially crafted DNSSEC-signed zone can cause the validation algorithm to enter a computationally expensive loop or trigger excessive recursive validation, consuming massive CPU resources, which would eventually cause a DoS.

Mitigation

BIG-IP

To mitigate this vulnerability, you can disable recursion in BIND or disable BIND in the DNS profile. To do so, perform one the following procedures:

Disable recursion in BIND

Impact of procedure: The BIG-IP system no longer performs DNS recursion.

By default, DNS recursion is disabled on the BIG-IP system. This prevents an attacker from using the BIG-IP system as a recursive DNS resolver to launch the attack to create a DoS. If DNS recursion is enabled on your BIG-IP system, you can mitigate this vulnerability by disabling DNS recursion on the affected system. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Using a text editor, edit the /var/named/config/named.conf file.
  3. Locate the options section of the file and change recursion to no.

    For example:

    recursion no;

  4. Save the file.
  5. Restart the named service by entering the following command:

    bigstart restart named

Disable the BIND server in the DNS profile

Impact of action: Disabling the BIND server can affect DNS configurations that use BIND as a fallback method (return to DNS) for resolution.

Configure the DNS profile to not forward queries to BIND by setting Use BIND Server on BIG-IP to Disabled. For queries that don't need to be processed further in BIND, if there is no pool assigned to the virtual server processing the DNS request, set Unhandled Query Actions to any setting other than Allow (for example, Drop or Hint). For a virtual server processing DNS requests assigned with a pool of DNS servers or configured for DNS caching, set Unhandled Query Actions to Allow. Setting Unhandled Query Actions to Allow allows further processing of DNS requests to the pool of DNS servers. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Services > DNS.
  3. Select the applicable DNS profile.
  4. For Use BIND Server on BIG-IP, select Disabled.
  5. For Unhandled Query Actions, choose one of the following:
    • If you have a virtual server processing DNS requests assigned with a pool of DNS servers or configured for DNS caching, select Allow.
    • If there is no pool assigned to the virtual server, select a setting other than Allow. For example, select Drop or Hint.
  6. Select Finished.
