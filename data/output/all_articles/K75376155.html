Topic

This article applies to BIG-IP ASM 14.x - 16.x. For information about other versions, refer to the following articles:

  • K000138908: Creating a security policy automatically (17.x)
  • K79575295: Creating a security policy automatically (13.x)
  • K71159058: Creating a security policy automatically (12.x)

You should consider using this procedure under the following condition:

  • You want to create a BIG-IP ASM security policy automatically using Policy Builder.

Description

F5 recommends that most users create a security policy using the automatic method. Doing so allows the system to create the initial security policy and then refine the policy over time by examining application traffic. When you create a security policy automatically, Policy Builder develops the policy using the following steps:

  • In the initial phase, the system identifies legitimate application usage and begins to build your security policy based on a statistical analysis of your traffic and the intended behavior of your application. In this phase, the system does not block requests until Policy Builder processes sufficient traffic and adds elements to the security policy.
  • In the next phase, Policy Builder refines and tightens the security policy over time until the number of policy changes stabilizes.
  • In the final phase, Policy Builder further refines the security policy until it is ready to enforce the necessary security features.

For example, the following scenario illustrates how Policy Builder automatically adds a legitimate file type to the policy based on an analysis of application traffic:

  1. You create a security policy using the automatic policy building option.
  2. A client sends a GET request for /sell.php.
  3. Since the PHP file type does not yet exist in policy, the BIG-IP ASM system allows the request but marks PHP as an illegal file type and sends a copy of the request to Policy Builder.
  4. The system continues to mark requests for PHP files as illegal until the request threshold is met for that file type.
  5. After the threshold is met for PHP files, the BIG-IP ASM system updates the security policy and no longer considers PHP an illegal file type.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the Configuration utility.
  • You performed basic configuration tasks to create the following:
    • A VLAN
    • A self IP address for the VLAN
    • A local traffic pool
    • A virtual server

Procedures

To create a security policy automatically and review additional action items for the policy, perform the following tasks:

  • Creating a security policy automatically using Policy Builder
  • Refining the security policy
  • Performing additional action items for the policy

Creating a security policy automatically using Policy Builder

To create a security policy automatically using Policy Builder, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Security Policies.
  3. Click Create.
  4. Click Advanced to show advanced policy details.
  5. For Policy Name, type a name for the security policy.
  6. For Policy Type, click Security, or click Parent if you want to use the policy as a parent policy for similar child policies.
  7. For Policy Template, click Fundamental. Alternatively, you can click Rapid Deployment or an application-ready template to develop a security manually. With either option, the system creates a basic security policy that you can review and fine-tune.
  8. For Virtual Server, click the name of the virtual server, or click Configure new virtual server to create a new virtual server.
  9. For Application Language, click Auto detect.
  10. For Learning Mode, click Automatic.
  11. For Enforcement Mode, click Blocking.
  12. For Auto-Added Signature Accuracy, click  Medium Accuracy.
  13. For Server Technologies, specify the server technologies you want to add protections for the policy.
  14. For Trusted IP Addresses, type an IP addresses or network that the system considers safe and click Add. Repeat this step for each address or network.
  15. For Policy Builder Learning Speed, click Medium.
  16. For Signature Staging, click Enabled.
    Note: Attack signature staging helps reduce the number of false positive violations for the policy.
  17. For Policy is Case Sensitive, click Enabled.
  18. For Differentiate between HTTP/WS and HTTPS/WSS URLs, click Enabled if the web application behaves differently for HTTP/WS and HTTPS/WSS URLs.
  19. Click Create Policy.

Refining the security policy

After you complete the initial security policy, have users browse and test their access to the application. As users initially browse the application, the system allows all traffic through the policy, and Policy Builder examines the traffic and makes learning suggestions that you can review. You can then configure Policy Builder to amend the policy based on the learning suggestions.

For example, as the BIG-IP ASM system processes requests, it may alert you to a potential violation, such as Attack Signature Detected. When this occurs, the Learning page displays information about the violation and lists an associated action for you to take, such as the following example:

  • Action: Add Automated client access "curl" (disabled on the Header) to Overridden Attack Signatures.

On the Traffic Learning page, you have the following options for each suggestion: Accept, Delete, Ignore, or Export. If you choose to accept a suggestion, the system performs the specified action.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Traffic Learning.
  3. On the Traffic Learning page, in the Current edited security policy list policy, click the name of the policy you want to refine.
  4. In the Suggestions list, click a learning suggestion to view information about the suggestion and the associated action the system takes if you accept the suggestion.
  5. For each suggestion, you can click Accept, Delete, or Ignore, or Export as appropriate for your policy.
  6. Click Apply Policy to activate any changes you made to the policy.

Performing additional action items for the policy

You can view a list of suggested action items, which the system reminds you to perform, such as required configuration and maintenance tasks. To take action on the items, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Overview > Application > Action Items.
  3. Under Suggested Action Items, review the list of recommended tasks for more information.
  4. For Policy Elements Learned in Automatic mode, review the progress of Policy Builder and policy elements.
  5. Under Quick links, use the links to access common configuration pages in the policy.
