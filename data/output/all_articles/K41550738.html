Topic

You should consider using this procedure under the following condition:

  • You want to view BIG-IP log files using the iControl representation state transfer (REST) API for one or both of the following reasons:
    • You want to verify proper operation of your BIG-IP system.
    • You want to troubleshoot an issue with a BIG-IP system.

Description

BIG-IP log files include important diagnostic information about the events occurring on the BIG-IP system. For example, the Linux host generates system messages that pertain to the Linux host operating system, including messages that are logged during system startup and information logged by the background daemons that run on the system. Other events are specific to the BIG-IP operating system. For example, the BIG-IP operating system generates messages that pertain to local and global traffic events and configuration changes (audit logging). For more information, refer to K16197: Reviewing BIG-IP log files.

The REST procedures described in this article are examples of common BIG-IP maintenance tasks. You can use the iControl REST API to perform most of the BIG-IP system management and configuration tasks that you can perform using the TMOS Shell (tmsh) . For more in-depth information about the iControl REST API, refer to the iControl REST User Guide that applies to your BIG-IP version, available on F5 Cloud Docs.

curl and jq utilities

Performing the following procedures requires command-line access to a system with the curl utility and, optionally, the jq (command line JSON processor) utility installed. These utilities are commonly available on Linux systems but can also be installed on Microsoft Windows and Mac OS X systems. Additionally, you can perform these procedures from an alternate BIG-IP system; however, the jq utility is not available on systems running versions earlier than BIG-IP 12.0.0. You can still use the curl portion of commands, but the resulting output is a single string rather than formatted JSON. For more information about the jq utility, refer to https://stedolan.github.io/jq.

REST endpoint for viewing log files

The BIG-IP REST API exposes the /mgmt/tm/sys/log endpoint for the purpose of viewing log files for the BIG-IP system, and you can query the log files listed in the following table using the REST API.

Log APILog type
daemonUnix daemon logs
gtmBIG-IP GTM Logs
kernelLinux kernel messages
ltmBIG-IP LTM logs
mailMail daemon logs
messagesApplication messages
securitySecurity-related messages
tmmTraffic Manager Microkernel logs
userVarious user process logs
webuiLogs for the web user interface
auditAudits of configuration changes

Note: To see which log files are available from the /mgmt/tm/sys/log endpoint, use the following command syntax:

curl -sku admin:<password> -H "Content-Type: application/json" -X GET https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys/log | jq -r .apiRawValues.apiAnonymous

Collection methods and parameters

The logging API endpoint accepts the GET resource method, the logging endpoint, the log file to query, the keyword stats, and optionally, one or both of the parameters defined in the following table to limit the results that are returned.

Parameter nameDescriptionExampleResult
linesSpecifies the maximum number of lines to display./mgmt/tm/sys/log/ltm/stats?options=lines,10Displays the first 10 lines of the system BIG-IP LTM logs.
rangeSpecifies a date range of logs to display, in UTC time format. Also accepts a single date, and the keywords epoch and indefinite.

Note: The double-hyphen (--) is required between ranges. Additionally, the Z character is required at the end of each UTC timestamp.

/mgmt/tm/sys/log/ltm/stats?options=range,2018-08-31T14:00:00ZDisplays all log entries from the BIG-IP LTM logs, from UTC timestamp 2PM August 31 2018 to the most recent.
/mgmt/tm/sys/log/ltm/stats?options=range,2018-08-31T14:00:00Z--2018-08-31T15:00:00ZDisplays all log entries from the BIG-IP LTM logs, from UTC timestamp 2PM August 31 2018 until 3PM August 31 2018.
/mgmt/tm/sys/log/ltm/stats?options=range,epoch--2018-08-31T14:00:00ZDisplays all log entries from the BIG-IP LTM logs, from the earliest entry available to UTC timestamp 2PM August 31 2018.
/mgmt/tm/sys/log/ltm/stats?options=range,2018-08-31T14:00:00Z--indefiniteDisplays all log entries from the BIG-IP LTM logs, from UTC timestamp 2PM August 31 2018 to the most recent.

Note: Same as specifying a single date.

Note: The requested logs contain all the log rotations for that log type that exist on the BIG-IP system. For example, BIG-IP LTM logs are combined from /var/log/ltm, /var/log/ltm.1, and /var/log/ltm[2-9].gz, if those log rotations exist on the system. Additionally, when specifying options=lines,10, this means the first 10 lines of the oldest logs found for that log type.

Advanced filtering methods

The REST API logging endpoint provides a quick and basic way to collect logs from the BIG-IP system without search and filtering utilities that are available from the command line. If more advanced filtering is required, command line utilities can be invoked with Bash through the /mgmt/tm/util API endpoint using the run command. The run command does not have a direct mapping to an HTTP method, so you must use the POST resource method to specify an absolute URI to the required utility and a JSON body that specifies the command line arguments for the utility. This method allows you to use Bash command line utilities such as grep and tail to search specific log files for strings, and limit the results as needed.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP system is licensed, provisioned, and configured with a management IP address.
  • You have administrative access to the BIG-IP Configuration utility.
  • You have command-line access to a system with the curl utility and, optionally, the jq utility installed. For more information, refer to curl and jq utilities section in this article.

Displaying log files and filter based on date

You can display logs from a given date using the range parameter.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to view specific BIG-IP logs:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys/log/<log type>/stats?options=range,<date> | jq -r .apiRawValues.apiAnonymous

    For example, to view all BIG-IP LTM logs from UTC time June 19 2019 21:20:00 until the current time, on a BIG-IP system using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X POST https://LTM1.example.com/mgmt/tm/sys/log/ltm/stats?options=range,2019-06-12T21:20:00Z | jq -r .apiRawValues.apiAnonymous

Displaying log files and filter for specific events

You can display logs using advanced filtering to return only the most recent specific event types.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to view specific BIG-IP logs:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\"-c '<bash command line commands>'\"}" | jq -r .commandResult

    Note: The utilCmdArgs name is used to provide the command line arguments for the Advanced Shell (bash) utility. The -c option in bash is used to process any system commands which are provided within the single quote characters ('). Due to the requirement for the single quote characters for the bash command line arguments, the quotation mark characters (") are used to enclose the entire JSON payload, which then requires all instances of quotation mark characters within the JSON payload to be escaped with a backslash character (\).

    For example, to use the grep utility to search for the string monitor in the /var/log/ltm.1 file and return only the last 10 results on a BIG-IP system using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X POST https://LTM1.example.com/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\"-c 'grep monitor /var/log/ltm.1 | tail -10'\"}" | jq -r .commandResult
