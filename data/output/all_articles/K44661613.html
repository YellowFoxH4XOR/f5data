Description

There are times when the default disk space provided for a BIG-IP used on Google Cloud either is not enough or future plans may dictate that it be built to accommodate those future plans.

  • You find yourself in need of more space than the BIG-IP is deployed with.
  • When you try to provision additional modules you receive an error message. Or maybe /var/log is full.
  • Error messages you may encounter:

In the GUI when trying to provision an additional module you may see
Modified Resource Allocation (prior to redistribution)

In /var/log/ltm you may see this entry:
err diskmonitor: 011d0004: Disk partition var has only 0% free

Environment
  • Disk Space is not sufficient for the virtual instance or your needs exceed the default settings.
  • BIG-IP, Google Cloud

Cause

The circumstances that bring this about can vary but will center around needing additional disk space to meet the needs of your network.

Recommended Actions

  • If the need is to simply increase the disk space you can follow the steps in K14952: Extending disk space on BIG-IP. Keep in mind that this is not a typical hypervisor, rather a Cloud instance. Other than that the steps would be the same.

  • If you need to plan for additional space or you want to start the instance fresh (instead of using the steps in K14952), that can also be done. To do this you will need to create a custom deployment script using the F5 BIGIP Image Generator to do it automatically when the new instance is deployed. You do this by using the tmsh commands as listed in K14952 when you create a custom deployment image. You will then consume that image in place of the default images. You can find the needed images here f5devcentral/f5-bigip-image-generator along with the applicable README files.
