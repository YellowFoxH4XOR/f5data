Issue

The domaintool utility performs forward and reverse lookups for the IP addresses configured in the /etc/krb5.conf configuration file. The domaintool utility then uses the results to identify the hostnames of the Kerberos Domain Controller (KDC) and Lightweight Directory Access Protocol (LDAP) server, and constructs Kerberos ticket requests.

If DNS returns names that do not match the Kerberos realm, or the realm does not recognize the name in the request, the KDC will not provide the LDAP service ticket to the BIG-IP LTM system. As a result, Server Principal Name (SPN) registration will fail with error messages that appear similar to the following example:

Error: ldap_set_option failed (Local error)
Error: ldap_connect failed
Couldn't join domain(65280). at /usr/bin/domaintool line 311, <FH> line 9.

For example, the domaintool utility requests a service ticket from KDC for the LDAP service (ldap/<hostname-from-dns-lookup>). The utility then presents the ticket to the LDAP database in order to register an SPN for the VIP (HTTP/kerberosvip).

A successful request displays output that appears similar to the following example:

Authenticated to Kerberos v5
-- get_default_keytab: Obtaining the default keytab name: /etc/krb5.keytab
-- get_default_ou: Determining default OU: CN=Computers

An unsuccessful request displays the following error message:

Error: ldap_set_option failed (Local error)
Error: ldap_connect failed
Couldn't join domain(65280). at /usr/bin/domaintool line 311, <FH> line 9.

Important: Kerberos is case-sensitive.

The following items must be in all caps:

  • The realm name value in the krb5.conf file, similar to the following example:

    [libdefaults]
    default_realm = DOMAIN.COM
    [realms]
    DOMAIN.COM = {
    admin_server = 10.10.0.1
    kdc = 10.10.0.1
    }
    [domain_realm]
    [logging]

  • The Service Class of the SPN in the BIG-IP LTM authentication object definition, similar to the following example:

    auth krbdelegate my_kerberos_config {
    server principal "HTTP/backendservice.domain.com"
    client principal "HTTP/kerberosvip.domain.com"
    }

Troubleshooting the cause of the unsuccessful request

If you receive this error message, you must confirm that both forward and reverse lookups resolve to the hostname and IP address configured for the realm on your KDC. Perform the following troubleshooting steps to identify and correct the cause of the error:

  • Confirm the name of your realm.

    For example, for Active Directory, you would type the following command:

    ksetup.exe /DumpState

    The default realm is displayed:

    default realm = domain.com (NT Domain)No user mappings defined.

  • Confirm the SPNs your KDC has registered that are available for use by the domaintool utility:

    C:\Documents and Settings\Administrator>setspn -L DC1
    Registered ServicePrincipalNames for CN=DC1,OU=Domain Controllers,DC=group,DC=domain
    ,DC=com:
    http/app1.domain.com
    ldap/dc1.domain.com/ForestDnsZones.askf5.com
    ldap/dc1.domain.com/DomainDnsZones.askf5.com
    DNS/dc1.domain.com
    ldap/dc1.domain.com/TAPI3Directory.domain.com
    NtFrs-88f5d2bd-b646-11d2-a6d3-00c04fc9b232/dc1.domain.com
    GC/dc1.domain.com/domain.com
    HOST/dc1.domain.com/ES
    HOST/DC1
    HOST/dc1.domain.com
    HOST/dc1.domain.com/domain.com
    E3514235-4B06-11D1-AB04-00C04FC2DCD2/cf85f492-907e-4b5c-91d7-ab8e9479e7f8/es
    .example.com
    ldap/cf85f492-907e-4b5c-91d7-ab8e9479e7f8._msdcs.domain.com
    ldap/dc1.domain.com/ES
    ldap/DC1
    ldap/dc1.domain.com ### DNS should return this domain.com hostname
    ldap/dc1.domain.com/domain.com

  • Confirm that the IP address configured in your krb5.conf file resolves to a hostname matching an SPN defined on the KDC:

    [root@bigip2:Active] config # cat /etc/krb5.conf
    [libdefaults]
    default_realm = DOMAIN.COM
    [realms]
    DOMAIN.COM = {
    admin_server = 10.10.0.1
    kdc = 10.10.0.1
    }
    [domain_realm]
    [logging]
    #nslookup 10.10.0.1
    Server: 10.10.0.254
    Address: 10.10.0.254#53
    1.0.10.10.in-addr.arpa name = dc1.domain.com.

  • Confirm that the BIG-IP system is able to request a ticket for SPN ldap/dc1.askf5.com and that the KDC is able to service this request. To do so, type the following command:

    domaintool --debug --join DOMAIN.COM --admin_principal administrator --host kerberosvip.domain.com

    After entering the administrator password, a successful request displays output that appears similar to the following example:

    Authenticated to Kerberos v5
    -- get_default_keytab: Obtaining the default keytab name: /etc/krb5.keytab
    -- get_default_ou: Determining default OU: CN=Computers

    The BIG-IP system will then use this ticket to access the LDAP database and register the SPN for the VIP.

  • Confirm that the SPN for the VIP was successfully registered:

    E:\SupportTools>setspn -L kerberosvip
    Registered ServicePrincipalNames for CN=kerberosvip,CN=Computers,DC=f5lab,DC=com:
    HTTP/kerberosvip.askf5.com
    HOST/kerberosvip.askf5.com

Note: For more information about configuring Kerberos authentication for the BIG-IP system, refer to K8836: Configuration Guide for Kerberos Delegation.
