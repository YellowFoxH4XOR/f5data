Description

Taking UCS archive on GUI fails after 5 min, and return the below error message:

Internal Server Error
The server encountered an internal error or misconfiguration and was unable to complete your request.
Please contact the server administrator at support@f5.com to inform them of the time this error occurred, and the actions you performed just before this error.
More information about this error may be available in the server error log.

Check /var/log/httpd/httpd_errors if there are similar to the below messages:

[proxy_ajp:error] [pid <PID>] [client a.b.c.d:53870] AH00992: ajp_read_header: ajp_ilink_receive failed, referer: https://bigip/tmui/Control/jspmap/tmui/system/archive/create.jsp.
[proxy_ajp:error] [pid <PID>] (70007)The timeout specified has expired: [client a.b.c.d:5370] AH00878: read response failed from 127.0.0.1:72 (localhost), referer: https://bigip/tmui/Control/jspmap/tmui/system/archive/create.jsp.
 

Environment

  • BIG-IP
  • v14.0 and later
  • Taking UCS archive takes more than 5 minutes

Cause
Bug ID 796605
 

Recommended Actions

Check if there are any unnecessary files in /config directory

  1. check disk usage in /config directory with the below command:
    df -h /config/
    Filesystem                             Size  Used Avail Use% Mounted on
    /dev/mapper/vg--db--sda-set.1._config             3.2G  1.6G  1.5G  51% /config
     
  2. If the used is nearly or more than 1GB, check what is occupying the /config directory with below command:
    du -shc /config/*
    10K     config/aaa
    23K     config/api_settings
    8.0K    config/big3d
    107K    config/BigDB.dat
    245K    config/bigip
    15K     config/bigip_base.conf
    15K     config/bigip_base.conf.bak
    ...
    This will list file and folder size under /config directory, and check the largest folder in there. 
    If you can not find it ,then follow K14403: Maintaining disk space on the BIG-IP system and remove unnecessary files. 
    IMPORTANT: if APM is provisioned, old EPSEC files would occupy  /config/filestore/files_d/Common_d/epsec_package_d/
    Check the location and delete those unused following K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system

Once the /config directory does not have any unnecessary files, then create the UCS archive file by entering the following command syntax:

tmsh save /sys ucs </path/to/ucs>


Note: Replace <path/to/ucs> with the full path to the UCS archive file. For example:

tmsh save /sys ucs /var/tmp/Myucs.ucs


Optional: If you want to encrypt the UCS archive with a passphrase, enter the following command syntax:
 

tmsh save /sys ucs <path/to/ucs> passphrase <password>


Note: Replace <path/to/ucs> with the full path to the UCS archive file, and replace <password> with the passphrase you want to use to encrypt the UCS archive. For example:

tmsh save /sys ucs /var/tmp/Myucs.ucs passphrase password.


Optional: If you want to exclude SSL private keys from the UCS archive, enter the following command syntax:
 

tmsh save /sys ucs <path/to/ucs> no-private-key


Note: Replace <path/to/ucs> with the full path to the UCS archive file. For example: 

tmsh save /sys ucs /var/tmp/Myucs.ucs no-private-key

IMPORTANT: Another workaround is not recommended for this issue.
