Topic

Note: The Enterprise Manager versions listed in the Applies To box do not currently support BIG-IP version 11.0.0.

When you start a device discovery task, the Enterprise Manager executes a particular iControl call that causes the device being discovered to create a UCS archive for each of its boot locations. These automatically-generated UCS archives are then saved to the /var/auto-ucs directory of their respective boot location.

However, if the UCS archives take too long to create, the iControl call may time out. When this behavior occurs, the device discovery task fails and the Enterprise Manager displays an error message that appears similar to the following example:

getSlotInfo: iControl error: 'iControl::char*:SOAPException: 'Timed out waiting for socket read.''>

This issue usually occurs when one of the UCS archives being created includes large, unnecessary files, such as ISO image files, tcpdump files, or core files. If a device discovery task has failed with the previously-mentioned error message, you should check whether the directories that are included, by default, in a UCS archive contain any large unnecessary files on any boot location.

For example, you can list the size of all files in the /home directory, along with all of its subdirectories, by typing the following command from the command line:

du -ach /home

If you find a user with a large home directory, clean up the directory to reduce its size and then attempt to discover the device again.
