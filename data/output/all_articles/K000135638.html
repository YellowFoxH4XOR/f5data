K000135638: NGINX configuration does not load in NIM

Type
Support Solution
Published
2023-07-27
Updated
2023-07-27
Applies to
  • NGINX Products
  • NGINX Instance Manager: 2.10.0
Source
https://my.f5.com/manage/s/article/K000135638

Description

After starting agent NGINX configuration does not load into NIM.
NIM gui error: 

Error getting the NGINX instance configuration: failed to download the configuration.

NMS NGINX error.log: 

[error] 146182#146182: *2986 client intended to send too large chunked body: (size>50MiB) bytes while sending request to upstream, client: <client-ip>, server: _, request: "POST /f5.nginx.agent.sdk.Commander/Upload HTTP/2.0", upstream: "grpc://unix:/var/run/nms/am.sock:", host: "<host-ip>:443"

Agent log messages:

level=error msg="Unable to upload nginx config : EOF"
level=warning msg="Error uploading config: EOF"

Environment

NMS

Cause

NMS NGINX configuration sets the maximum client request size (client_max_body_size) to 50MB by default. Also, the agent only collects data from the specified allowed directories that are defined in /etc/nginx-agent/nginx-agent.conf. For example:

agent_accessible_dirs: "/etc/nginx:/usr/local/etc/nginx:/usr/share/nginx/modules:/etc/nms"

Recommended Actions

There are a couple of ways to address this problem.

Increase client_max_body_size:

  • From NMS cli, edit NMS NGINX file '/etc/nginx/conf.d/nms-http.conf'
  • Find and increase the value of directive client_max_body_size to a size suitable to handle the amount of data being retrieved from agent. If you are unsure of an amount then start with 100M and increase it if necessary. 
    client_max_body_size 100M; # Increase in case of large configuration files
  • Reload NGINX: 
    sudo systemctl restart nginx.service
  • Logon to and restart agent: 
    sudo systemctl restart nginx-agent.service

(Recommended) From agent, find and move large files out of the directories defined by agent_accessible_dirs within the agent configuration (/etc/nginx-agent/nginx-agent.conf)
