Description
The VDI deployment starts failing after the VDI client has its NTP clock set to any NTP Virtual Server, hosted to the same BIG-IP as the one hosting the VDI service(s).

Environment

  • BIG-IP APM
  • VDI deployment
  • Client NTP clock is configured to a Virtual Server to the BIG-IP hosting the APM service

Cause
This may be due to the parameter "match-across-pools enabled" as set in the persistency profile.

Recommended Actions

We'd need to update the configuration of the persistence as follow:
  1. Open a connection to the BIG-IP Configuration Utility
  2. Navigate to Local Traffic  ››  Virtual Servers : Virtual Server List
  3. Click the name of the Virtual Server hosting the VDI service
  4. Click the tab Resources on the top of the webpage;
  5. Take note of the object Default Persistence Profile
  6. Navigate to Local Traffic  ››  Profiles : Persistence
  7. Click the name of the object you noted from step #5
  8. Uncheck the parameter Match Across Pools
  9. Click Update
