K000133701: ASM not blocking request with malformed Range header

Type
Support Solution
Published
2023-04-28
Updated
2024-02-10
Source
https://my.f5.com/manage/s/article/K000133701

Description

  • Requests comprising of Range header value that are non-compliant with RFC 7233 are not getting blocked by ASM.
  • Malformed/Invalid Range header value not detected by ASM's protocol compliance check.
  • Range header doesn't start with the word "Bytes"

     Range: 3578a7f9-cd79-11ed-9773-b809f3fd062b

Environment

  • ASM
  • Security Policy
  • Attack Signature
  • Protocol compliance

Cause

Seen behaviour is tracked as ID 1291657.

Recommended Actions

No fix available at the time of creation of this article. As workaround you can create and assign a custom attack signature with the following rule to enforce some basic compliance checks for the Range header.

headercontent:"Range"; nocase; re2:"/(?m)^range:/H"; nocase; re2:!"/(?m)^range: bytes=/H"; nocase;

Note: This is a basic sanity check and not a robust enforcement of RFC 7233.
