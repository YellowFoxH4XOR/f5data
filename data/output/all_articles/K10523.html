Issue

The ARX system stores metadata changes in NVRAM database logs before writing them to the metadata share. If the ARX system experiences a loss of network connectivity to the metadata share, or if the metadata share is on a slow storage device and the ARX system is unable to write/flush the metadata changes before the NVRAM usage quota is exceeded, the following message is logged to syslog:

DNAS_PGRP-9-5-MSG5:: Instance NVRAM usage quota exceeded, service degraded

When the NVRAM usage quota is exceeded, processing of metadata changes, such as the creation, deletion, or renaming of files and/or directories will be delayed or blocked until changes are written to the metadata share. As a result, you may experience slow client access performance.

When the ARX system is able to write the changes to the metadata share, and space in NVRAM becomes available, the following message is logged to syslog:

DNAS_PGRP-9-5-MSG5:: Instance NVRAM space available, service operating normally
