K000158905: Allowed services setting in the F5BigNetVlan CRD removed Vlans from POD

Type
Support Solution
Published
2025-12-23
Updated
2026-01-14
Applies to
  • BIG-IP Next
  • BIG-IP Next DNS CNF: 2.0.0
  • BIG-IP Next CNF
Source
https://my.f5.com/manage/s/article/K000158905

Description

Adding allowed_services to an F5BigNetVlan custom resource (CR) can cause the VLAN to stop being applied to the BIG-IP Next CNF (TMM) pod. Typical symptoms include:

  • The VLAN no longer appears in the TMM/debug pod (for example, after initially applying the VLAN CR successfully, adding allowed_services causes it to disappear).
  • Kubernetes accepts the CR YAML and does not send the VLAN configuration to TMM.   
  • The output of the command in the tmm debug pod  ' configview vlan ' will not show newly created vlan.  
  • This behavior is triggered when allowed_services.protocol is provided as uppercase (for example, TCP) instead of lowercase (tcp).

Environment

  • Product: BIG-IP Next DNS CNF
  • Version: 2.0.0 or greater
  • Kubernetes CRD/Resource:
    • apiVersion: k8s.f5net.com/v1
    • kind: F5BigNetVlan
  • Configuration area: spec.allowed_services
    • Example input that triggers the issue: 
      spec:
  allowed_services:
    - port: "179"
      protocol: TCP

    Cause

    Misconfiguration: The controller is case-sensitive for allowed_services.protocol and expects lowercase values (for example, tcp). If misconfigured, the controller rejects the CR config even if Kubernetes accepts it.

    Recommended Actions

    1.  Update the F5BigNetVlan resource so allowed_services.protocol is lowercase
    2.  Re-apply the CR.

    Example (correct):

    spec:
  allowed_services:
    - port: "179"
      protocol: tcp

    Additional Information

    • The CRD schema may only define ' protocol ' as a generic string, but the controller enforces specific accepted values and is case-sensitive
    • After correcting to lowercase, the CR should be accepted and the VLAN should remain applied to the TMM pod.
