Known Issue

The Terminal Access Controller Access-Control System Plus (TACACS+) system authentication file descriptor leaks when you are unable to reach servers.

This issue occurs when all of the following conditions are met:

  • You have configured the remote system authentication to use TACACS+.
  • Connections to one or more of the configured TACACS+ servers fail.
  • Administrative access to the BIG-IP system using any HTTP-based method results in leaked file descriptors. Relevant access methods include Web UI, iControl, and iControl-REST.  Repeated, automated access using iControl is the fastest route.

Impact

Depending on the number of connection failures, the system might exceed the open files limit of the web server process, and new connections to the web server fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Administrative access to the system with remote authenticated accounts fails, and in the /var/log/secure security log, you see error messages that refer to too many open files, similar to the following examples:

    httpd[###]: PAM [error: /lib/security/pam_bigip_authz.so: cannot open shared object file: Too many open files].
    httpd[###]: PAM audit_open() failed: Too many open files

  • You no longer have administrative access using remote authenticated accounts; this includes access from secure shell (SSH) and console. The root account, which always uses local authentication, is not affected.

Workaround

To work around this issue, you can remove unreachable TACACS+ servers from the TACACS configuration, or restart the httpd process, as necessary.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Restarting the HTTPD process
1. Log in to the command line using root user access.
2. To restart the HTTPD service, type the following command:
    tmsh restart sys service httpd
