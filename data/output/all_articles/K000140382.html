K000140382: AFM DoS feature could drop packets if vCMP Host run TMOS v17.1.x and Guest TMOS version is lower

Type
Support Solution
Published
2024-07-19
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.X, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000140382

Description

In vCMP capable devices it is possible to deploy one or more vCMP guests. vCMP guests are objects that users create on vCMP host systems to run one or more BIG-IP modules. A vCMP guest consists of a TMOS instance, and one or more BIG-IP modules. Each vCMP guest has its own share of hardware resources that the vCMP host allocates to it, allowing each vCMP guest to function like a separate BIG-IP device.

 

Since each vCMP guest can have different TMOS version this means that version between a vCMP guest and its vCMP Host could be different. F5 broadly recommends to  configure the vCMP host to run the same BIG-IP version as the latest version used by any of its vCMP guests, also in case AFM is provisioned in the vCMP guest F5 warns that vCMP host and guest are required to run the same TMOS version in order to offload DoS in Hardware. This article describes a specific situation in which a vCMP host and guest version mismatch could  lead to drops by the AFM DoS feature.

 

Due to some improvements in the DoS engine carried out in TMOS v17.1 the TCP BADACK vector was deprecated and replaced by two more specialised vectors, TCP ACK (TS) and TCP ACK Flood. Also some malformed DoS vectors coding was improved in Hardware for TMOS v17.1. All these changes caused old deprecated vectors not having correspondence between versions prior to v17.1 and TMOS v17.1, so under specific circumstances where vCMP host is upgraded to TMOS v17.1 while the guest runs an older TMOS version you could notice legitimate traffic drops caused by vectors SYN & FIN or FIN Only Set DoS vectors.

 

Note that no issues are expected when upgrading a non vCMP device to v17.1, this includes VELOS, rSeries and any classic BIG-IP platform, including not vCMP provisioned Viprion.

 

Environment

  • vCMP capable platform
  • BIG-IP AFM provisioned in vCMP guest running TMOS version lower than v17.1
  • vCMP host running TMOS version ≥v17.1
  • Hardware offloaded enabled for DoS feature.

Cause

ID1615101

Recommended Actions

BIG-IP AFM DoS protection in the hardware requires both the vCMP guest and the host to run the same software version. If you are running dissimilar versions, you can work around this issue by disabling hardware DoS protection using the tmsh modify /sys db dos.forceswdos value true command.

 

Additional Information

The following command can be used to identify this issue:

tmctl -f var/tmstat/blade/tmm0 -w $COLUMNS -d blade dos_stat -s vector_name,int_drops,int_dropped_bytes | grep -v " 0$"
