Known Issue

Upgrading to BIG-IP 13.1.0 or later creates a Server SSL profile with an invalid cipher string.

This issue occurs when all of the following conditions are met:

  • You are running a BIG-IP version prior to 13.1.0.
  • You configure a custom HTTPS monitor.
  • You upgrade to BIG-IP 13.1.0 or later.

During the upgrade process, the In-TMM monitoring feature, introduced in BIG-IP 13.1.0, converts the HTTPS monitor into a Server SSL profile, which uses stricter cipher string validation. If the HTTPS monitor from the previous version uses keywords that are incompatible with the Server SSL profile format, such as kEDH, which is included in the default cipher string, a validation error is generated when loading the configuration.

Impact

After the upgrade, the BIG-IP configuration contains a Server SSL profile with invalid keywords in the cipher string. While this does not prevent the configuration from loading, attempts to modify the Server SSL profile or create a new profile with the same cipher string fail during Master Control Program (MCP) validation.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Attempts to modify the Server SSL profile or create a new profile with the same cipher list fail with a message similar to the following example:

    01070312:3: Invalid keyword 'kedh' in ciphers list for profile /Common/example_server_ssl_profile

  • During the upgrade process, a message is logged to the /var/log/ltm file that appears similar to the following example:

    0107185a:4: Warning generated, for version 13.1.0 or greater : Https monitor /Common/example_https_monitor attribute cipherlist and compatibility are deprecated and moved serverssl profile's ciphers and options.

Note: The issue described in this article has similar symptoms to Bug ID 705730. However, Bug ID 705730 will prevent the configuration from loading after an upgrade to an affected version. For more information refer to, K31992159: After upgrading to 13.1.x you are not able to see configuration objects on the BIG-IP due to a configuration load failure.

Workaround

To work around this issue, you can manually remove the offending keywords from the configuration. Alternatively, you can run a script to remove the offending keywords from the configuration in multiple partitions. To do so, perform one of the following procedures:

  • Manually remove offending keywords
  • Run a script to remove offending keywords

Manually remove offending keywords

Impact of workaround: Performing a configuration load on an active device group member can potentially disrupt the service of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the BIG-IP Advanced Shell (bash).
  2. Back up the existing configuration file by entering the following command:

    cp /config/bigip.conf /config/bigip.conf.K82327396

  3. Using a text editor such as vi, open the /config/bigip.conf file for editing.
  4. Locate the affected cipher string. The problematic cipher string may appear similar to the cipher string in the following example Server SSL profile:

    ltm profile server-ssl /Common/example_server_ssl_profile {
    cert none
    cipher-group none
    ciphers DEFAULT:+SHA:+3DES:+kEDH
    <snip>

  5. Edit the cipher string to remove the problematic keywords. Using the previous example, you could change the cipher string to the following:

    ciphers DEFAULT:+SHA:+3DES:+EDH

  6. Save the changes and exit the text editor. If using vi, enter the following command:

    :wq

  7. Load the modification into the running configuration by entering the following command:

    tmsh load /sys config

Run a script to remove offending keywords

You can run a script to remove the offending keywords from the configuration in multiple partitions. To do so, perform the following procedure:

Impact of workaround: Performing a configuration load on an active device group member can potentially disrupt the service of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to bash.
  2. Change invalid keyword kEDH to EDH and back up the existing configuration files by entering the following command:

    for i in `find /config/ -wholename  /config/bigip.conf -or -path "/config/partitions/*" -name bigip.conf`; do sed -i.K82327396 -e 's/+kEDH/+EDH/g' $i ;done

  3. Changes can also be displayed by entering the following command:

    for i in `find /config/ -wholename  /config/bigip.conf -or -path "/config/partitions/*" -name bigip.conf`; do if [ -e $i.K82327396 ]; then echo $i ; sdiff -s $i.K82327396 $i ; fi ;done

  4. Load the modification into the running configuration by entering the following command:

    tmsh load /sys config
