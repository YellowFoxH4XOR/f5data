Description

When BIG-IP sends a TCP reset, it can be configured to disclose the reason to the BIG-IP administrator in the logs and can report this reason via the f5ethtrailer data in packet captures collected from BIG-IP (K13223).

 

A virtual server with an AFM fw-enforced-policy attached may report the reset cause as [F5RST: Policy action] regardless of the actual cause. This also happens when firewall policy is configured in firewall global-rules. While there is no change to the format and function of the TCP reset sent to the peer, the cause reported to the administrator would be inaccurate. 

 

For example, when an ACK is sent to a virtual server for which no connection exists, we can observe the reason BIG-IP sends a reset is No flow found for ACK.

 

# tcpdump -nni 0.0:nnn host 10.10.79.9 and port 80

 

08:31:03.319825 IP 10.10.79.160.20202 > 10.10.79.9.80: Flags [.], ack 0, win 8192, length 0 in slot1/tmm1 lis= flowtype=0 flowid=0 peerid=0 conflags=0 inslot=0 inport=0 haunit=0 priority=0 peerremote=00000000:00000000:00000000:00000000 peerlocal=00000000:00000000:00000000:00000000 remoteport=0 localport=0 proto=0 vlan=0

 

08:31:03.319926 IP 10.10.79.9.80 > 10.10.79.160.20202: Flags [R.], seq 1, ack 0, win 0, length 0 out slot1/tmm1 lis= flowtype=70 flowid=56008D25E940 peerid=0 conflags=4000020 inslot=0 inport=0 haunit=1 priority=0 rst_cause="[0x29e3f03:2418] No flow found for ACK" peerremote=00000000:00000000:00000000:00000000 peerlocal=00000000:00000000:00000000:00000000 remoteport=0 localport=0 proto=0 vlan=0

 

 After adding an Allow_All policy, for example:

 

security firewall policy /Common/FW_allow_all {

 rules {

  Allow_all {

   action accept

   ip-protocol any

  }

 }

}

 

We can observe the reset cause is now Policy action.

 

[root@00393988-bigip:Active:Standalone] config # tcpdump -nni 0.0:nnn host 10.10.79.9 and port 80

 

08:42:19.625641 IP 10.10.79.160.20202 > 10.10.79.9.80: Flags [.], ack 0, win 8192, length 0 in slot1/tmm1 lis= flowtype=0 flowid=0 peerid=0 conflags=0 inslot=0 inport=0 haunit=0 priority=0 peerremote=00000000:00000000:00000000:00000000 peerlocal=00000000:00000000:00000000:00000000 remoteport=0 localport=0 proto=0 vlan=0

 

08:42:19.625697 IP 10.10.79.9.80 > 10.10.79.160.20202: Flags [R.], seq 1, ack 0, win 0, length 0 out slot1/tmm1 lis= flowtype=70 flowid=56008D25E940 peerid=0 conflags=4000020 inslot=0 inport=0 haunit=1 priority=0 rst_cause="[0x29e3f03:2418] Policy action" peerremote=00000000:00000000:00000000:00000000 peerlocal=00000000:00000000:00000000:00000000 remoteport=0 localport=0 proto=0 vlan=0

 

 

Environment

  • AFM provisioned
  • firewall policy applied to virtual server OR applied to firewall global-rules
