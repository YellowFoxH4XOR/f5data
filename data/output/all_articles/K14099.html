Known Issue

An overflow in the Linux kernel sched_clock function may cause system instability.

This issue occurs when the following condition is met:

  • The system has an uptime of 208.5 days, or longer.

Note: This issue does not affect the SCCP/AOM subsystem because the subsystem runs on a different architecture.

Impact

The affected system may crash and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H407369 on the Diagnostics > Identified > Low|High screen.
  • The system experiences CPU soft lockups, and logs error messages to the /var/log/kern.log file that appear similar to the following example:

    err kernel: BUG: soft lockup - CPU#3 stuck for 17163091981s! [swapper:0]

  • The system unexpectedly restarts, especially when processing a high volume of traffic.
  • System daemons fail to increment their heartbeat signal within the time-out period, resulting in a failover action.
  • The system experiences a clock skew.

Workaround

To work around this issue, you can restart the affected system prior to the 208.5-day period. To do so, perform the following procedure:

Impact of workaround: You should restart the system during a maintenance window. Restarting the affected system will result in a failover event and possibly a brief traffic disruption.

  1. Log in to the command line.
  2. Determine the system uptime by typing the following command:

    uptime

    For example, the following output indicates the system has an uptime of seven days:

    14:43:42 up 7 days, 5:48, 1 user, load average: 0.01, 0.02, 0.00

  3. Restart the system by typing the following command:

    reboot
