Description

  • DNS/GTM HTTPS monitor reuses SSL session ID after connection reset
  • Tcpdumps show webserver sending a TCP reset in the packet following big3d sending a Client Hello reusing saved SSL session ID

Environment

  • DNS/GTM HTTPS monitor
  • Monitored server has changed SSL protocol requirements.  Example: Server has changed to no longer accept TLS 1.1 connections

Cause
The DNS/GTM HTTPS monitor daemon, big3d, will reuse a SSL session whenever possible.  This can be problematic if the server had disallowed the SSL protocol of the currently stored session.  For example changed the webserver to no longer allow TLSv1.1.

Recommended Actions

The cached SSL sessions can be cleared by restarting big3d, or by following the process below:

If restarting big3d is not possible, the cached SSL sessions can be expired by triggering a SSL alert from the webserver instead of a TCP reset.  The process will vary based on the webserver and the protocols and ciphers involved.  The example below is for the example where the server had been reconfigured to no longer accept TLSv1.1.

  1.  Re-enable the server disallowed protocol TLSv1.1
  2.  Change the server allowed cipher list to only allow TLSv1.2 ciphers
  3.  Verify monitors have no been marked up (big3d should now be sending TLS1.2 client hello)
  4. Now the server can be configured to refuse TLSv1.1
