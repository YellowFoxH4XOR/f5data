Description

Start in version 13.1.0, with HTTP Cookie Insert options and HTTP Cookie Rewrite options in Cookie Persistence Profile, a new option "Default Cookie Encrypt Pool-Name" is introduced.
Enabling the "Default Cookie Encrypt Pool-Name" option in the BIG-IP LTM cookie persistence profile causes the expected persistence cookie (set-cookie) to not be sent to the client. 

 

Environment

BIG-IP LTM

 

Cause

The "Default Cookie Encrypt Pool-Name" feature requires an Encryption Passphrase to be configured within the same persistence profile.  If no Encryption Passphrase is set, enabling this feature disables the cookie insert persistence function and prevents cookies from being sent to clients.

 

Answer/Recommended Actions

To use "Default Cookie Encrypt Pool-Name," configure an Encryption Passphrase in the relevant cookie persistence profile.

If you do not wish to use encryption or cannot set a passphrase, leave "Default Cookie Encrypt Pool-Name" disabled.
After making changes, verify via HTTP response headers that set-cookie for BIGipServer* is present as expected.
