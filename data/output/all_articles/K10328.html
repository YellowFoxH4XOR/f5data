Topic

This article applies to BIG-IP 10.x through 11.x. For information about other versions, refer to the following article:

  • K73827442: Forcing a file system check on the next system restart (12.x - 16.x)

The fsck utility can scan the file system for errors and correct those errors if possible. File systems must be unmounted to correct errors. Performing a file system check using the fsck utility can be a tedious, manual process that requires the user to restart the system to a minimal run level, and then issue a fsck operation on each file system listed in the /etc/mtab file. This manual method requires direct access to the system to access and run the fsck utility. Additionally, even if the system boots to a minimal run level (single-user mode), the system may not be able to release some file systems to manually perform a file system check using the fsck utility directly.

A more convenient file system check method is to force a file system check on the next system restart. This method removes the tedious manual process and allows the system to reliably check all of the available file systems.

Important: F5 recommends that you have direct access to the system during a forcefsck so that you can observe any errors or information that may be reported during the fsck process. While this method removes the manual process of specifying the various file systems, the system restarts into a minimal run level to perform the necessary tasks.

You can use any of the following procedures to force a file system check on the next restart:

  • Creating a forcefsck file in the root directory

    This method allows you to schedule a file system check during the next restart of the system.

  • Forcing a file system check using the shutdown command

    This method allows you to restart the system immediately and perform a file system check.

  • Booting to single-user mode and forcing a file system check using the shutdown command

    This method allows you to restart the system and perform a file system check when file system errors prevent you from logging in to perform one of the previous procedures.

Creating a forcefsck file in the root directory

This procedure allows you to schedule a file system check during the next restart of the system by creating a blank file, named forcefsck, that resides in the / directory. The presence of the /forcefsck file causes the system to perform a file system check the next time the system boots.

  1. Log in to the command line.
  2. To create the /forcefsck file, type the following command:

    touch /forcefsck

    During the next restart, the /forcefsck file causes the system to perform a file system check.

  3. If you want to restart the system at this time, type the following command:

    reboot

Note: The /forcefsck file is deleted as the system boots and does not remain for subsequent restarts.

Forcing a file system check using the shutdown command

This procedure allows you to restart the system immediately using the shutdown -rF command.

  1. Log in to the command line.
  2. To restart the BIG-IP system and force a file system check, type the following command:

    shutdown -rF now

    The fsck file system check is performed as the system restarts.

Booting to single-user mode and forcing a file system check using the shutdown command

If the system experiences file system errors that prevent you from logging in to perform one of the previous methods, this procedure allows you to boot the system into single-user mode, and restart the system using the shutdown -rF command.

  1. Boot the BIG-IP system into single user mode.

    For information about booting into single-user mode, refer to the following articles:

    • K14662: Restarting the BIG-IP system in single-user mode (GRUB2)
    • K4178: Restarting the BIG-IP system in single-user mode (GRUB 0.97)
  2. From the single-user prompt, restart the BIG-IP system and force a file system check by typing the following command:

    shutdown -rF now

    The system restarts and performs the fsck file system check. Once the fsck operation has finished checking the file systems, the system continues to boot normally into the proper run levels.
