K41135413: Why is 127.127.1.0 in output of ntpd -pn command when ntp server set with include?

Type
Support Solution
Published
2022-08-24
Updated
2025-04-01
Applies to
  • BIG-IQ
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K41135413

Description
Local clock - 127.127.1.0 appear in ntpd -pn command output when server is not set, or using include statement. This is an undisciplined local clock that may lead to NTP sync issues.

     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
 127.127.1.0         .LOCL.      10 l   51   64  377    0.000    0.000   0.000 
*<ntp_ip_include>   <ip_addr>    4 u   45   64   17    0.818    1.683   2.332

The issue described in this article can occur when the output of the following tmsh command displays servers none as follows:

tmsh list sys ntp all-properties

sys ntp {
    description none
    include "
    server <ntp_server> version 3"
    restrict none
    servers none
    timezone America/Los_Angeles
}

This issue can occur when you add servers to the system's ntp configuration using include statements through the tmsh shell. For example:

  • tmsh modify sys ntp include "server 10.154.1.241 iburst"

  • In the tmsh shell, you add a server using the tmsh editor:
    (tmos)# edit /sys ntp all-properties

    include "server 192.168.1.10 key 1 iburst
    trustedkey 1"

Environment

  • BIG-IP / BIG-IQ
  • any version
  • NTP
     

Cause

  • Bug ID 862001
     

Recommended Actions

When you would like to remove 127.127.1.0, the undisciplined local clock from the ntp configuration, set "servers { none }" as follows using the tmsh editor:

(tmos)# edit /sys ntp all-properties
sys ntp {
    description none
    include "
    server x.x.x version 3"
    restrict none
    servers { none }
    timezone America/Los_Angeles
}
