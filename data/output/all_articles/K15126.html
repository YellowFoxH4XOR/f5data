Known Issue

HTTP iRules commands may not work correctly.

This issue occurs when the following condition is met:

  • An HTTP iRules command is called within a non-HTTP event.

iRules events are executed within the scope of both client- and server-side traffic. This allows for events to be executed at the right moment in the network flow as well as within the correct context (the client- or server-side of the BIG-IP system).

When a non-HTTP event handles the client side of a request, a corresponding server-side HTTP context is not set and the ownership bit is not set in the http_data structure. If an HTTP iRules command is invoked, the BIG-IP system does not know whether the client or server side should own the data. As a result, the HTTP iRules command fails with an error message.

Impact

HTTP iRules may not work correctly.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The HTTP iRules command fails.
  • In the /var/log/ltm: file, you observe an error message that appears similar to the following example:

    err tmm1[15461]: 01220001:3: TCL error: /Common/<iRule name> <iRule event> - Illegal argument. Can't execute in the current context. (line 7) invoked from within "<iRule command>"
