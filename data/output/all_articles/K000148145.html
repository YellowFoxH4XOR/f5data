Description

This article explains how to configure rate limiting in F5 Distributed CLoud HTTP Load Balancer. It covers the available options, key behaviors and step-by-step instructions to help you set up rate limiting correctly. 

Environment

  • F5® Distributed Cloud
  • HTTP Load Balancer (LB)

Answer / Recommended Actions

There are two ways to enable rate limiting, depending on your use case:

  1. Enable it at the WAAP level for API Security and Control. It uses AI/ML learning engine and uniquely discovers API endpoints used during service-to-service communication.
    1. Configure API rate limiting
  2. Enable it at HTTP Load Balancer (No WAAP dependency)
    1. Introduction to F5 Distributed Cloud Console Rate Limiting Feature

What is rate limit?

Rate limit is the number of times requests can be sent with the same telemetry data. The default value for this is 10 requests per 5 mins. And this limiter is per RE location, not globally, if you set a limit of 50 req/s, then Per RE has the limit for 50 req/s.

Important Considerations for Rate Limit Behavior

Let's consider the following example configuration:

  • LB with "Custom Rate Limiting Parameters" of 5 requests per minute with 1X Burst Multiplier 

Please understand the following contingencies:

  • If "Rate Limiter Policies" is configured with the value "No Rate Limiter Policies", then all requests to the LB will be rate limited as per the originally specified configuration.
  • If "Rate Limiter Policies" is configured with the value "Rate Limiter Policies" and a single policy "rate-limit" which contains no rules, then all requests to the LB will be rate limited as per the originally specified configuration. THIS IS IMPORTANT. If no rules are matched, then the rate limit values configured on the LB will be enforced. In other words, rate limiting will not be bypassed if no rules are matched. If needed/wanted, a final rule in the set must be created to bypass rate limiting in the case that no other rules are matched.


XC rate limiting abides by what's known as a leaky bucket algorithm (see here for reference). Each request you make adds a token to the rate limit bucket. The bucket drains at the rate configured on the Load Balancer, which is 5 req/min in our imagined example scenario from above (equivalently 1 req/12s). The below data shows how this works:

Additional Information

Rate limiting is at the LB level with the exception of API Security and Control described in above links.

Rate limiting is not supported at the routes level but you can do it following these steps:

1. Go to HTTP Load Balancer configuration > Common Security Controls > Rate limiting

2. Select Custom Rate Limiting Parameters

3. Click View Configuration

4. Under Rate Limiter Policies select Rate Limiter Policies
