Known Issue

This is the result of a known issue. The BIG-IP GTM uses the following two timers:

  • The system clock set by the Network Time Protocol (NTP)
  • The eventlib (monotonic) timer reported by the event library

The eventlib timer calculates system timer events, such as comparing times between BIG-IP GTM systems in a sync group, and advances at slightly different rates on each device. As a result, the timestamps communicated between BIG-IP GTM sync group members may diverge, even though NTP maintains the system clock.

Once the time extends beyond value defined by the Synchronization Time Tolerance setting, the system logs error messages to the /var/log/gtm file that appear similar to the following example:

gtmd[1745]: 011a0022:2: Time difference between GTM <hostname> and me is <value> seconds -- Make sure NTP is running and GTM times are in sync

Note: These error messages are benign and are meant to indicate when BIG-IP GTM systems are out of sync with their system clocks.

F5 Product Development tracked this issue as CR98631 and it was fixed in BIG-IP GTM versions 9.4.8 and 10.0.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

You can work around this issue by restarting the gtmd process. Restarting the gtmd process temporarily synchronizes the system's eventlib clock with the system clock time. To restart gtmd, type the following command:

Note: Restarting the gtmd process restarts all BIG-IP GTM services.

bigstart restart gtmd
