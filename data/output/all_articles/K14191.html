Known Issue

The BIG-IP ASM Configuration utility may time out when attempting to create a new BIG-IP ASM security policy for an existing virtual server.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM system is under heavy load and experiencing high CPU utilization.
  • You attempt to create a new BIG-IP ASM security policy and select the Existing Virtual Server option.

Impact

The new BIG-IP ASM security policy is not created.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H443010 on the Diagnostics > Identified > Low screen.
  • When attempting to create a new ASM security policy for an existing virtual server, the BIG-IP ASM Configuration utility will hang and eventually return a blank page.
  • The /var/log/httpd/httpd_errors file may report a message that appears similar to the following example:

    slot1/bigip1 err httpd[7280]: [error] [client 172.16.112.254] PHP Fatal error: Maximum execution time of 30 seconds exceeded in /var/ts/dms/common/functions/coapi_wraplib.php on line 28, referer: https://172.16.112.10/dms/policy/wizard.php

Workaround

To work around this issue, you can create a new BIG-IP ASM-enabled HTTP class profile, create the new ASM security policy, and then apply the policy to the profile. You can then associate the new profile with an existing virtual server. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol menu, select HTTP Class.
  4. Click Create.
  5. In the Name box, type the desired name of the HTTP Class profile.
  6. Select the Custom check box.
  7. From the Application Security menu, select Enabled.
  8. Configure the new HTTP Class with the desired values.
  9. Click Finished.
  10. Select the newly-created HTTP Class.
  11. Click Security Policy.
  12. From the Current edited policy menu, select the policy named after the newly-created HTTP Class.
  13. Click Run Deployment Wizard.
  14. Navigate through the deployment wizard to configure a new BIG-IP ASM security policy as desired.
  15. To complete the deployment wizard and save the new BIG-IP ASM security policy, click Finished.
  16. To apply the new BIG-IP ASM security policy to the ASM-enabled HTTP Class, click Apply Policy.
  17. Navigate to Local Traffic > Virtual Servers.
  18. Select the existing virtual server you want to associate with the BIG-IP ASM-enabled HTTP Class.
  19. Click Resources.
  20. In the HTTP Class Profiles section, click Manage.
  21. From the Available list, select the new ASM-enabled HTTP Class profile, and click << to move it to the Enabled list.
  22. Click Finished.
