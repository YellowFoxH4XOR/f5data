Known Issue

This is the result of a known issue. If multiple application data records are received in a single packet when both the Client SSL and Server SSL profiles have negotiated non-native ciphers, the processing of the first application data record causes the Secure Sockets Layer (SSL) profile to be reset to use NULL ciphers. As a result, the Traffic Management Microkernel (TMM) will attempt to process and re-encrypt the second application data record in the packet, and TMM will crash.

Note: This behavior only occurs when the native SSL ciphers have been disabled in both the Client SSL profile and the Server SSL profile, both profiles are assigned to the same virtual server, and the client or server sends multiple application data records within the same packet. For example, the following command disables the use of native ciphers within an SSL profile:

ALL!NATIVE

F5 Product Development tracked this issue as CR83261 and it was fixed in BIG-IP LTM 9.3.1 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.
