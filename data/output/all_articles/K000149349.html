Description

There are entries present under "show system alarms" in F5OS CLI and under Alarms & Events tab in GUI. The article applies to both rSeries, Velos controller and partition.

 

The below example comes from rSeries appliance:

 

# show system alarms

ID RESOURCE SEVERITY TEXT TIME CREATED

-------------------------------------------------------------------------------------------------------------

262401 Portgroup 1 ERROR Lanes: 1,2,3,4 Receiver power low alarm 2024-12-13 17:42:49.367753024 UTC

263169 interface-4.0 WARNING Interface down 2025-01-07 09:43:49.864161640 UTC

262401 Portgroup 4 ERROR Lanes: 1 Receiver power low alarm 2025-01-07 09:44:07.640340896 UTC

263169 interface-3.0 WARNING Interface down 2025-01-07 09:55:48.545225653 UTC

262401 Portgroup 3 ERROR Lanes: 1 Receiver power low alarm 2025-01-07 09:56:07.620308018 UTC

 

These examples come from Velos:

 

1) Controller

 

# show system alarms

ID    RESOURCE     SEVERITY TEXT                                                     TIME CREATED

----------------------------------------------------------------------------------------------------------------------------

65554 controller-1 WARNING  Partition-2 image volume utilization growth rate is high 2024-11-27 15:18:22.763564694 UTC

65554 controller-2 WARNING  Partition-2 image volume utilization growth rate is high 2024-12-15 20:16:32.712614763 UTC

 

2) Partition

 

show system alarms

ID     RESOURCE        SEVERITY TEXT                                    TIME CREATED
---------------------------------------------------------------------------------------------------------------
263169 interface-1/2.0 WARNING  Interface down                          2024-07-31 05:00:59.164224863 UTC
263169 interface-2/2.0 WARNING  Interface down                          2024-07-31 05:01:52.069618868 UTC
262401 Portgroup 2/2   ERROR    Lanes: 1,2,3,4 Receiver power low alarm 2024-07-31 05:02:03.551305023 UT

 

Environment

  • F5OS
  • Alarms present under "show system alarms" in F5OS CLI and under Alarms & Events tab in GUI

Cause

          The alarms could be stale, and were not cleared even upon reboot or power cycle.

Recommended Actions

           To clear the alarms from the examples above, use the below commands:

 

rSeries:

# docker exec alert-service /confd/test/sendAlert -n "rxPwr" -s "Portgroup 1" -i 262401 -d "Lanes: 1,2,3,4 Receiver power low alarm" -r clear -se ERROR

# docker exec alert-service /confd/test/sendAlert -n "interface-down" -s "interface-3.0" -i 263169 -d "Interface down" -r clear -se WARNING

# docker exec alert-service /confd/test/sendAlert -n "interface-down" -s "interface-4.0" -i 263169 -d "Interface down" -r clear -se WARNING

# docker exec alert-service /confd/test/sendAlert -n "rxPwr" -s "Portgroup 3" -i 262401 -d "Lanes: 1 Receiver power low alarm" -r clear -se ERROR

# docker exec alert-service /confd/test/sendAlert -n "rxPwr" -s "Portgroup 4" -i 262401 -d "Lanes: 1 Receiver power low alarm" -r clear -se ERROR

 

VELOS:

1) Controller

# docker exec alert-service /confd/test/sendAlert -n "partition2-image-volume-utilization" -s "controller-1" -i 65554 -d "Partition-2 image volume utilization growth rate is high" -r clear -se WARNING

# docker exec alert-service /confd/test/sendAlert -n "partition2-image-volume-utilization" -s "controller-2" -i 65554 -d "Partition-2 image volume utilization growth rate is high" -r clear -se WARNING

 

2) Partition

Note: To run the commands, please SSH into one of the partition blades from Velos controller.  If partition is deployed on blades 1 & 2, choose one of those, and run "ssh blade-X" where X is blade number.

blade-1:

# docker exec partition_alert_service /confd/test/sendAlert -n "link-state" -s "interface-1/2.0" -i 263169 -d "Interface down" -r clear -se WARNING

 

blade-2:

# docker exec partition_alert_service /confd/test/sendAlert -n "link-state" -s "interface-2/2.0" -i 263169 -d "Interface down" -r clear -se WARNING

# docker exec partition_alert_service /confd/test/sendAlert -n "link-state" -s "Portgroup 2/2" -i 262401 -d "Lanes: 1,2,3,4 Receiver power low alarm" -r clear -se ERROR

 

Additional Information

For Alert Name which is "-n" option, refer to:

rSeries: rSeries F5OS-A SNMP Monitoring and Alerting

Velos: VELOS F5OS SNMP Monitoring and Alerting
