Description

The tomcat process is constantly restarting, even after a reboot.

The following message is printed to the CLI and /var/log/daemon.log:

emerg logger[pid]: Re-starting tomcat

Additionally, reviewing /var/log/secure or journalctl -f shows repeated messages similar to the following:

su[pid]: PAM unable to dlopen(/lib/security/pam_rootok.so): /lib/security/pam_rootok.so: wrong ELF class: ELFCLASS32
su[pid]: PAM adding faulty module: /lib/security/pam_rootok.so
su[pid]: PAM unable to dlopen(/lib/security/pam_wheel.so): /lib/security/pam_wheel.so: wrong ELF class: ELFCLASS32
su[pid]: PAM adding faulty module: /lib/security/pam_wheel.so
su[pid]: pam_tally2(su:auth): Tally overflowed for user tomcat
su[pid]: pam_unix(su:auth): auth could not identify password for [tomcat]
su[pid]: FAILED SU (to tomcat) root on none

Environment

  • tomcat
  • PAM

Cause

BIG-IP's bigstart script for tomcat requires use of su.

The PAM configuration file for su has been user modified to specify the 32-bit path for the PAM modules in question, while the 64-bit module is required by su.

cat /config/bigip/auth/pam.d/su
#%PAM-1.0
auth sufficient /lib/security/pam_rootok.so                             <---!!
auth required /lib/security/pam_wheel.so group=wheel                    <---!!
...

Recommended Actions

Modify the PAM configuration file, removing the absolute path, and leaving only the module name. This is the default configuration. PAM will take care of finding the correct module.

Here is a default su PAM configuration file from 14.1.4.1

#%PAM-1.0
auth            sufficient      pam_rootok.so
# Uncomment the following line to implicitly trust users in the "wheel" group.
#auth           sufficient      pam_wheel.so trust use_uid
# Uncomment the following line to require a user to be in the "wheel" group.
#auth           required        pam_wheel.so use_uid
auth            substack        system-auth
auth            include         postlogin
account         sufficient      pam_succeed_if.so uid = 0 use_uid quiet
account         include         system-auth
password        include         system-auth
session         include         system-auth
session         include         postlogin
session         optional        pam_xauth.so

Note: It's not recommended to modify PAM configuration files, unless suggested by F5 Support.

Additional Information

  • In most situations, the default PAM configuration file for a PAM-aware application is sufficient. Sometimes, however, it is necessary to edit a PAM configuration file. Because misconfiguration of PAM can compromise system security, it is important to understand the structure of these files before making any modifications.

  • The module name provides PAM with the name of the pluggable module containing the specified module interface. Since the advent of multilib systems, which store 64-bit PAM modules in the /lib64/security/ directory, the directory name is omitted because the application is linked to the appropriate version of libpam, which can locate the correct version of the module.
