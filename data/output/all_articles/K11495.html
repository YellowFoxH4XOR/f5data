Topic

Note: This issue only affects BIG-IP versions 9.4.0 through 9.4.8.

When a BIG-IP redundant pair is configured to use network failover, the system creates an entry in the connection table for the heartbeat communication that is used to determine which unit should be in an active state and which one should remain in a standby state. If one of the units is replaced, the remaining unit does not clear the connection table entry for the heartbeat communication. This behavior may result in an active/active situation as the remaining unit will attempt to send heartbeat information to the MAC address of the replaced unit.

F5 recommends that you remove the connection table entry for the network failover heartbeat from the remaining active system before you install the replacement unit and its configuration.

To verify the IP addresses being used for network failover and remove the connection table entry for the network failover heartbeat, perform the following procedure:

  1. Log in to the BIG-IP command line of the remaining active system.
  2. To obtain the peer IP address, type the following command:

    bigpipe db Failover.PeerIpaddr
  3.  If no IP addresses are returned in step 2, then the BIG-IP LTM will use the state mirror address for failover. Type the following command:

    bigpipe db StateMirror.PeerIpaddr
  4. To delete the connection table entry for the Peer IP address, type the following command:
    bigpipe conn client <IP address(es) obtained in step 2 or step 3>:1026 protocol udp delete

    The connection entry has been removed if you receive the following message:

    No connection table entries were found.

Once the entry is deleted from the connection table, you may proceed with the replacement system.
