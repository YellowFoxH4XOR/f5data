Description

After upgrading the Checkpoint firewall, BIG-IP sends traffic to the MAC address of the Standby firewall instead of the Active.

Environment

BIG-IP

Check Point Firewalls

Cause

F5 caches the last hop MAC address to overcome connectivity issues when network topology is changed.

This feature is called "auto last hop".

When "auto last hop" is enabled on F5, and the firewalls are configured with ClusterXL in High Availability mode, the "auto last hop" will cache the last MAC address associated with the ClusterXL VIP address (i.e., the physical MAC address of the former Active member) even though the ARP table learns the new MAC address associated with the VIP (i.e., MAC address of the former Standby member that became the new Active member).

Therefore, when a ClusterXL failover occurs, the traffic arriving from the F5 towards the VIP will be addressed to the former Active member, since the F5 only has the physical MAC. This traffic will be dropped because a member in the Down / Standby state does not process any traffic.

Even if VMAC mode is enabled on the firewalls, the gateways only send out information of the Virtual MAC address within a gratuitous arp in the destination mac field. The source mac field will be the physical MAC of the particular gateway sending the G-Arp. When regular TCP/UDP/ICMP traffic is sent, we still use our physical MAC address in the source mac field. 

In VRRP environment, while existing traffic does not continue to flow upon failover, new traffic will pass successfully.

Recommended Actions

NOTE: The following solution is not displayed unless you sign in. The article includes the following iRule. Please fully review the entire Check Point article for full details of the iRule.

Traffic issues during Check Point ClusterXL failover in F5 BIG IP environment
https://support.checkpoint.com/results/sk/sk83420

The following iRule on the F5 allocates the MAC address of the VRRP to its members.

when CLIENT_ACCEPTED {
if { [format %s [LINK::lasthop]] equals "00:a0:8e:bd:eb:34" || [format %s [LINK::lasthop]] equals "00:a0:8e:bd:e7:d4" } {
#set lasthop to the VRRP virtual mac
lasthop 666 00:00:5e:00:01:7b
}
}

Where:
00:a0:8e:bd:eb:34 = physical MAC address of Member A
00:a0:8e:bd:e7:d4 = physical MAC address of Member B
00:00:5e:00:01:7b = VRRP MAC address
666 = VLAN, on which the VRRP routers reside
