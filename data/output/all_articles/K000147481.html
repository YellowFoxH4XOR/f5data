K000147481: HTTP Load Balancer - How to determine if a Support ID/Blocking Page is from a Security Event or from the HTTP Proxy?

Type
Support Solution
Published
2024-11-08
Updated
2026-06-14
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Apps
  • F5 Distributed Cloud Multi-Cloud App Connect
Source
https://my.f5.com/manage/s/article/K000147481

Description

  • When a Block Page is displayed for a request, it may not be obvious whether the request was blocked by security controls (such as WAF or Service Policy), or by the proxy layer (such as upstream connectivity failures and timeouts).

Environment

  • F5® Distributed Cloud (XC)
  • HTTP Load Balancer (LB)
  • Default Error Pages
  • App Firewall

 

Resolution/Answer

  • Under default configuration, the F5 XC HTTP LB returns a Default Error Page to requests that fail proxy processing, for any of the reasons documented here.  This includes 5xx errors due to timeout or origin unreachability, and includes 4xx from route mismatch, Service Policy enforcement, request constraints, and other sources.
  • The Default Error Pages display information including the response code, response status text, and the F5 XC site that sent it, as in the following example:
     
  • The Default Error Page can be customized with the Custom Error Response feature as described here and here.
  • A WAF policy is configured with its own blocking page, separate from the Default Error Page configured on the HTTP LB.

  • The WAF blocking page can be customized within the App Firewall configuration.

Note: If both error page options are disabled and WAF allows the response code then the error page will be served from the origin server.

Additional Information

  • If you are unable to locate a req_id / Support ID displayed by the Default Error Pages, it is important to remember that the access logs these requests are part of are sampled so you may not be able to locate all of these requests in the logs
