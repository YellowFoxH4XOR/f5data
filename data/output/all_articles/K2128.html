K2128: Reasons why nodes may fail health checks after fails over to a redundant network interface card (NIC)

Important: F5 Networks recommends that you do not use proprietary redundant NIC features with BIG-IP. For more information, refer to K3182: Configuring BIG-IP to load balance traffic to nodes that use redundant network interface cards (NICs).

When BIG-IP initially opens a connection to a node to perform a health check, it sends an ARP for the node's MAC address. Once BIG-IP has learned the MAC address, it does not ARP for the address again until the self connection timeout expires. As a result, if you use redundant NICs and an NIC fails over, BIG-IP will not detect the change immediately.

To prevent this issue, set the self connection timeout to the minimum value of one second, by performing the following steps:

  1. Log in to the command line.
  2. Set the self connection timeout, by typing the following command:

    bigpipe global self_conn_timeout 1

  3. Save the configuration, by typing the following command:

    bigpipe save
