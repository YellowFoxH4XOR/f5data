Description

How to disable and enable a pool member using  the REST API.

You can set the node and pool members to a Disabled or Forced Offline state. 
When set to Disabled, a node or pool member continues to process persistent and active connections. It can accept new connections only if the connections belong to an existing persistence session.
When set to Forced Offline, a node or pool member allows existing connections to time out, but no new connections are allowed.

Environment

  • REST API
  • Pool

Cause

None

Recommended Actions

  • The below examples assume the following:
    • The management IP of the BIG-IP system is 192.168.1.1
    • The pool is called '/Common/testpool'
    • ?????The pool member has the IP address 172.16.3.4 and is the node '/Common/172.16.3.4:80'
    • The user id is 'admin'
    • The password is 'password'

Setting the pool member state to Disabled

 
curl -k -u admin:password -X PUT 'https://192.168.1.1/mgmt/tm/ltm/pool/~Common~testpool/members/~Common~172.16.3.4:80' -H 'Accept: */*' -H 'Content-Type: application/json' -d '{ "session": "user-disabled" }'

Note: When the pool member is created using iApp , you need to use the PATCH method for updating the state with the user role of Operator or admin, PUT method cannot be used.

Note: When the role of the user is Operator, you need to use PATCH method. User with the role of Operator can enable or disable nodes and pool members, but cannot create, modify, or delete them.

For example:

curl -k -u operator:password -X PATCH 'https://192.168.1.1/mgmt/tm/ltm/pool/~Common~testpool/members/~Common~172.16.3.4:80' -H 'Accept: */*' -H 'Content-Type: application/json' -d '{ "session": "user-disabled" }'

Setting the pool member state to Forced Offline


curl -k -u admin:password -X PUT 'https://192.168.1.1/mgmt/tm/ltm/pool/~Common~testpool/members/~Common~172.16.3.4:80' -H 'Accept: */*' -H 'Content-Type: application/json' -d '{ "state": "user-down", "session": "user-disabled" }'

Note: When the role of the user is Operator, you need to use PATCH method. User with the role of Operator can enable or disable nodes and pool members, but cannot create, modify, or delete them.

For example:

curl -k -u operator:password -X PATCH 'https://192.168.1.1/mgmt/tm/ltm/pool/~Common~testpool/members/~Common~172.16.3.4:80' -H 'Accept: */*' -H 'Content-Type: application/json' -d '{ "state": "user-down", "session": "user-disabled" }'
 

Setting the pool member state to Enabled

 
curl -k -u admin:password -X PUT 'https://192.168.1.1/mgmt/tm/ltm/pool/~Common~testpool/members/~Common~172.16.3.4:80' -H 'Accept: */*' -H 'Content-Type: application/json' -d '{ "state": "user-up", "session": "user-enabled" }'

Note: When the pool member is created using iApp , you need to use the PATCH method for updating the state with the user role of Operator or admin, PUT method cannot be used.

Note: When the role of the user is Operator, you need to use PATCH method. User with the role of Operator can enable or disable nodes and pool members, but cannot create, modify, or delete them.

For example:

curl -k -u operator:password -X PATCH 'https://192.168.1.1/mgmt/tm/ltm/pool/~Common~testpool/members/~Common~172.16.3.4:80' -H 'Accept: */*' -H 'Content-Type: application/json' -d '{ "state": "user-up", "session": "user-enabled" }'
