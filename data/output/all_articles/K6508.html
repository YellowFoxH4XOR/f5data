Topic

A BIG-IP GTM system's configuration includes server object definitions for both BIG-IP devices and non-BIG-IP devices. A server object is defined for each device that hosts the virtual servers or hosts that the GTM is responsible for load balancing, and uses assigned probers to communicate with each server to determine (depending on the probe or monitor configured) its availability, status, proximity, or responsiveness.

By default, the members of a GTM sync group dynamically determine the best BIG-IP device within the sync group configuration to use as the prober for the non-BIG-IP device server objects. Devices defined within the same data center as the server object to be probed are preferred. If no local prober is available, a remote prober is used. Probe tasks are distributed round robin within each data center to the device responsible for the fewest probing tasks, thus automatically distributing the prober load among all eligible devices.

Alternatively, you can specify which BIG-IP device should probe specific non-BIG-IP device server objects. This alternative configuration may be required for optimal probing of systems in multiple data centers, or where firewalls may block the probe traffic. If specific probers will be defined for multiple nodes, care must be taken to distribute the prober load appropriately.

Note: The term BIG-IP system may refer to a standalone BIG-IP device or a redundant pair. A redundant pair is considered a single system from the GTM perspective. Therefore, individual peers in a redundant pair may not be defined as probers.

Note: For more information about probers in BIG-IP GTM, refer to Understanding Probes section in the BIG-IP GTM Configuration Guide. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Dynamic probing

Note: Dynamic probing of nodes is the default behavior for BIG-IP GTM, and is the recommended configuration.

By default, BIG-IP GTM systems dynamically determine the best BIG-IP device to act as prober for the non-BIG-IP devices. If a prober device or the network path between the prober and the target becomes unavailable, the GTM systems will automatically choose an alternate prober, thus providing some redundancy for the probing process and increasing accuracy of reported availability.

Assigning a specific prober

Note: F5 does not recommend configuring specific probing devices unless your network architecture makes it impossible or undesirable for certain BIG-IP devices to act as probers for specific non-BIG-IP devices. When configuring this option, be sure not to overload any specific prober devices with probing tasks.

When you assign a specific prober to a non-BIG-IP device, you are specifying which BIG-IP system collects statistics for that device. If it is necessary to specify the probing device for a given non-BIG-IP device, specify a BIG-IP redundant pair if possible. If one member of the redundant pair becomes unavailable, its peer will continue to perform probing for the given host, preventing the probing responsibility from being reassigned to another device or pair.

If the specified prober device or pair becomes completely unavailable, the default behavior (dynamic probing) will be used until the specified prober becomes available again. In the interim, the probed device will be marked down if the dynamically assigned prober device cannot reach the device being probed due to your network architecture.

Assigning a specific prober address for a non-BIG-IP server object

Note: It is only possible to assign a specific prober address to a non-BIG-IP server object, such as a Generic Host.

  1. Log in to the Configuration utility.
  2. Navigate to Global Traffic > Servers.
  3. Click the server object for which you want to assign a specific prober.
  4. For Configuration, click Advanced.
  5. For Statistics Collection Server, click the BIG-IP device (preferably, a redundant pair) that you want to probe this host.
  6. Click Update.
