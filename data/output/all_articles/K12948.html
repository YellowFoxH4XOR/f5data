Topic

If you perform a restoration with a UCS archive on a standby unit, the system removes the connection entries that were previously mirrored to the standby unit. This behavior occurs when you have configured the high availability (HA) pair to mirror connections between the units. The restoration operation resets the standby unit configuration and rebuilds it. Although the HA mirroring connection between the units remains operational, the system does not notify the active unit that the standby unit has undergone a configuration rebuild, and as a result has lost the previously-mirrored connection entries; therefore, the active unit does not resend the connection entries that were previously mirrored to the standby unit.

Note: A configuration synchronization or configuration load does not cause this behavior.

You can identify this behavior by comparing the number of concurrent connections that a virtual server has between the active unit and standby unit. To extract the concurrent connections information, run the following command on both units, replacing <VS name> with the virtual server name:

For BIG-IP 10.x and later use the following TMSH command:

tmsh show ltm virtual <VS name>

For BIG-IP 9.x use the following bigpipe command:

bigpipe virtual <VS name> show

If the Current Connections of the specific virtual server on the standby unit are fewer than those on the active unit, you can conclude that the standby unit is experiencing this mirrored connection entries issue.

In the following example, the virtual server myVS on the active unit is reported by the tmsh show ltm virtual myVS command to have 10 connections, while the standby unit, using the same command, is reported to have 5 connections:

Note: The following example output has been truncated for brevity.

Active unit
Current Connections               10          0        -

Standby unit
Current Connections                5          0        -

 

You can recover the previously-mirrored L4 connections from the active unit to the standby unit by restarting the services on the standby unit after performing a UCS archive restoration. To do so, perform the following procedures on the standby unit:

Note: This procedure does not recover the previously-mirrored L7 connections to the standby unit.

Impact of procedure: None.

  1. Log in to the command line.
  2. Type the following command:

    bigstart restart
