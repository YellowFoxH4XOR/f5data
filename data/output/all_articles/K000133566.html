Description

When a Prober Pool Load balancing method is Round Robin method, each request will be answered by the next member in the prober pool.  One potential behavior that may be experienced is when you have the same number of monitored resources as the number of prober pool members. The result will appear that the same Prober pool member will always respond to the same probe request. 


2 monitors using 1 prober pool with 2 members: 

Monitor 1 > pool member 1
monitor 2 > pool member 2
Monitor 1 (second request) > pool member 1
Monitor 2 (second request) > pool member 2.

Because there are the same number of pool members to the number of objects being polled (a ratio of 2:2) , there is an appearance that load balancing is not happening.  Monitor 1 is 'always' answered by the pool member 1. 

Environment

  • BIG-IP DNS/GTM
  • Prober pools with round robin algorithm configured.
  • ** A matching number of monitors targeting a prober pool with the same number of members.

Cause

Functioning as designed.  The Round robin polling is happening as expected, it just gives the appearance that it's not, because the ratio between Monitors and prober pool members is balanced.

 Recommended Actions

Because this is a ratio behavior (one monitor per prober pool member)  it creates a 1:1 ratio between the polling requests, resulting in the same pool member responding over time.  To improve this behavior,   you'll want to ensure 1 of two options are established.

  • Make sure the ratio of monitors polling is not the same as the number of prober pool members.  Have an uneven ratio (eg. 3:2 or 7:4)

or

  • Create a different prober pool for each Monitor  where the ratio will always be (1:1+n)  (always have more prober pool members than the monitor being polled.)
