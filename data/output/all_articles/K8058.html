Known Issue

This is the result of a known issue. The 1500 (C36) platform has an internal trunk with one interface: 4.1. In addition to interface 4.1, the bcm56xxd process incorrectly defines interface 4.2 as a second interface on the internal trunk, and attempts to mark it as up. This causes a misconfiguration with the system's switch hardware, resulting in switchboard failsafe.

When this issue occurs, the following messages are output to the /var/log/ltm file:

Oct 9 21:21:24 sccp bcm56xxd[220]: 00010012:6: Link: 4.2 is UP
Oct 9 21:21:25 tmm tmm[745]: 01230002:4: Interface 0.1: link is down
Oct 9 21:21:29 tmm tmm[745]: 01230002:4: Interface 0.1: link is down

Note: The 1500 (C36) platform is the only system with one interface on the internal trunk. BIG-IP platforms such as the 3400, 6400, and higher numbered platforms, contain an internal trunk with multiple interfaces and are not affected by this issue.

F5 Product Development tracked this issue as CR87184 and it was fixed in BIG-IP LTM version 9.4.4. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.1.3-HF1 issued for BIG-IP version 9.1.3, Hotfix-BIG-IP-9.3.1-HF2 issued for BIG-IP version 9.3.1, and in Hotfix-BIG-IP-9.4.3-HF4 issued for BIG-IP version 9.4.3. You may download these hotfixes or later versions of these hotfixes from the F5 Downloads site.
