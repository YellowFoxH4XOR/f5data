K11757: A Diameter connection may stall if the BIG-IP system does not receive a TCP ACK response from the Diameter server

Type

Published
2010-07-07
Updated

Applies to

  • BIG-IP LTM: 10.2.0, 10.1.0

Known Issue

This is the result of a known issue. If you assign the diameter and message-based load balancing (mblb) profiles to a virtual server, and the BIG-IP system does not receive a TCP ACK response from the selected pool member, the BIG-IP system does not send a TCP RST packet to the client until the connection times out of the connection table. The correct behavior is for the BIG-IP system to send a TCP RST packet to the client after the maximum SYN retransmissions defined in the TCP profile has been reached.

F5 Product Development is tracking this issue as ID 334403 and CR142142.

Workaround

You can work around this issue by applying the following iRule to the virtual server:

when LB_FAILED { after 100; LB::reselect pool [LB::server pool] }

Note: For more information about configuring iRules, refer to F5 DevCentral. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).
