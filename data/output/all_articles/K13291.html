Topic

You should consider using this procedure under the following conditions:

  • The BIG-IP ASM system is configured with a remote logging profile.
  • Connections to the remote syslog server are routed through the management interface.
  • You want to prevent connections to the syslog server from remaining in the TCP CLOSE_WAIT state.

Description

You can configure the BIG-IP ASM system to use the TCP Keep-Alive probes to determine when idle connections to a remote syslog server should be closed.

Note: The BIG-IP ASM system may incorrectly leave connections in the TCP CLOSE_WAIT state indefinitely. For more information, refer to K13262: The BIG-IP ASM may fail to close connections to remote logging servers.

You can configure the TCP Keep-Alive probes by modifying the settings for three internal parameters, as detailed in the following table:

Internal Parameter NameDescription
remote_logging_tcp_keepalive_timeThe interval, in seconds, between the last data packet sent (simple ACKs are not considered data) and the first Keep-Alive probe. After the connection is marked to need Keep-Alive, this counter is not used any further.
remote_logging_tcp_keepalive_intvlThe interval, in seconds, between subsequent Keep-Alive probes, regardless of what the connection has exchanged in the meantime.
remote_logging_tcp_keepalive_probesThe number of unacknowledged probes to send before considering the connection dead and notifying the application layer.

The parameters work according to the following scheme:

The TCP Keep-Alive probe waits for <remote_logging_tcp_keepalive_time> seconds after the last data packet was sent, before sending the first Keep-Alive probe, and then resends the Keep-Alive packet every <remote_logging_tcp_keepalive_intvl> seconds. If <remote_logging_tcp_keepalive_probes> probes have been sent with no response, the BIG-IP ASM system acts as if the connection is down, and clears the connection.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • The BIG-IP ASM system must be running one of the following software versions, or later:
     
    • BIG-IP 11.1.0 and later
    • BIG-IP 11.0.0 HF1
    • BIG-IP 10.2.2 HF2

Procedures

Initial configuration of internal parameters from the command line

  1. Log in to the BIG-IP ASM command line.
  2. To set an internal parameter use the following command syntax, where <parameter_name> is the new parameter name, and <parameter_value> is the value you want for the parameter:

    /usr/share/ts/bin/add_del_internal add <parameter_name> <parameter_value>

    For example:

    /usr/share/ts/bin/add_del_internal add remote_logging_tcp_keepalive_time 300
    /usr/share/ts/bin/add_del_internal add remote_logging_tcp_keepalive_intvl 72
    /usr/share/ts/bin/add_del_internal add remote_logging_tcp_keepalive_probes 9

  3. After you have modified the parameters, restart the BIG-IP ASM service by typing the following command:

    Important: This step will cause a brief traffic disruption.

    bigstart restart asm

With the values set in the previous example, the Keep-Alive counter begins incrementing when the BIG-IP ASM system sends a data packet to the syslog server. If the time since the last packet was sent reaches 300 seconds with no response from the syslog server, the BIG-IP ASM system sends a Keep-Alive packet and continues to do so every 72 seconds until it either receives a response, or 9 Keep-Alive packets have been sent. If the ninth Keep-Alive packet is unanswered, the BIG-IP ASM system closes the connection.

Modifying internal parameters from the Configuration utility

Once you have added these internal parameters from the command line using the previous steps, you may further modify the parameters from the Configuration utility by performing the following steps:

  1. Log in to the Configuration utility.
  2. Navigate to the following page:

    BIG-IP ASM 11.3.0 and later

    Security > Options > Application Security > Advanced Configuration > System Variables

    BIG-IP ASM 10.2.2 through 11.2.1

    Application Security > Options > Advance Configuration > System Variables.

  3. In the Parameter Value box, enter the value you want for any of the three internal parameters that you added while performing the Initial configuration of internal parameters from the command line procedure.
