Description
After user have successfully logged in via APM logon page, the web browser offers to save account password, which is a string f5-sso-token. Next time the same user fails to authenticate with the saved password.

HTTPWatch indicates that the SSO code getting injected and POST is happening from SSO because of the "f5-sso-token" query string parameter.

+ 0.000 13 4 0.205 1604 1704 POST 302 Redirect to [...] ?f5-sso-form=owa

Environment
BIG-IP APM
SSO

Cause
f5-sso-token is what a Client-Initiated SSO Method uses on the client side to hide the customer password. It gets replaced on the APM with the real password before being sent to the backend. When the web browser saves the password , it is submitted using APM therefore the password parameter is seen with the value of f5-sso-token which is then stored by the web browser. In further logins it will ask to use the saved password.

Recommended Action
Option that allows to save passwords can be disabled in the web browser settings.
This is connected with how browser password managers intercept passwords, and not an error on the F5 APM side.

Additional Information
Form-Based Client-Initiated Single Sign-On Method
