Topic

Summary

The BIG-IP AFM system enforces denial-of-service (DoS) Protection Device Protection (located in the Device Configuration in BIG-IP versions prior to 14.0.0), configured detection and mitigation thresholds for DoS vectors per each Traffic Management Microkernel (TMM). The enforced detection and mitigation thresholds are therefore the configured value entered multiplied by the number of TMMs. The system interprets the configured value as per-TMM. For example, a value of 1000 for endpoint sweep (EPS) on a BIG-IP AFM device running four TMM instances uses the enforced value of approximately 4000 EPS when traffic is hashed across all four of the TMMs.

The threshold values configured in DoS Protection profiles, which are applied to virtual servers, are internally divided by the number of TMMs and the threshold is enforced per tmm.

Thresholds for the DoS vectors Single Endpoint Sweep and Single Endpoint Flood are enforced as entered, whether for the device configuration or in a DoS Protection profile.
 

Description

The BIG-IP AFM system provides protection from many types of DoS attacks, and each configurable item has its own detection threshold and limit.

The settings for DoS Protection for the system as a whole are located under Device Protection. The BIG-IP AFM system applies the Device Protection DoS vector detection and mitigation thresholds for each TMM. Single Endpoint Sweep and Single Endpoint Flood vectors are an exception. The system enforces the detection and mitigation values for the SIngle Endpoint vectors as entered by the user for the system as a whole, not per-TMM.

For example, the device, DoS aggregate, default settings for the SYN and FIN Set attack type are as follows:

  • Detection Threshold PPS: 1000
  • Detection Threshold Percent: 500
  • Default Internal Rate Limit: 10000

The assumed behavior is that if the BIG-IP AFM system detects more than 1000 packets per second, it flags that as an ongoing attack. However, since this number is for each TMM, a device with four TMMs could theoretically handle 4000 packets per second before the system detected an attack.  However, as soon as a single TMM crosses the 1000 pps threshold, it is flagged as an attack.

This equation assumes an equal four-way split among the four TMMs in traffic processing. There are several factors that affect how many packets each TMM is currently handling, such as session length, session resumption, persistence, hashing used, and so on.

Recommendations

When configuring DoS Device Protection detection thresholds and rate limits for device DoS aggregates, you should consider the number of TMMs available on your platform. Set the value that reflects the overall system-wide level that you want, and divide that by the number of TMMs that you have.

Alternatively, if the deployment is suitable to use a single TMM, then the configured thresholds and limit are the numbers as configured.

You can determine the number of TMMs available on your platform by using either the command-line ps command or the TMOS Shell (tmsh) command.

Note: For hyper-threaded platforms running BIG-IP 11.5.0 and later, refer to K15003: TMM data plane tasks and non-TMM control plane tasks use separate logical cores on systems with HT Technology CPUs.

To use the command-line ps command, enter the following command:

ps T | grep tmm | grep T
