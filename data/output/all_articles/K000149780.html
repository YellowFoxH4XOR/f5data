K000149780: Setting up primary key on F5OS-C may fail with primary controller becoming inaccessible

Type
Support Solution
Published
2025-02-13
Updated
2025-02-13
Applies to
  • F5OS
  • F5OS-C: 1.6.X, 1.6.2, 1.6.1, 1.6.0
Source
https://my.f5.com/manage/s/article/K000149780

Description

When a primary key is being set up on a F5OS-Chassis system, the process may fail with primary controller becoming inaccessible.

 

  • Setup a primary key so that backups are secure with command "system aaa primary-key set passphrase"
  • After running the command, the primary controller is no longer accessible from it's IP.
  • Command system aaa primary-key state status shows "ABORTED"
  • Remote authentication (TACACS) may also stop working.

Environment

  • F5OS-C 1.6.2
  • CA-signed certificates are being used on the controller
  • The certificate keys are encrypted with a password

Cause

This is caused due to a known bug ID1282185.

Recommended Actions

The workaround for this bug is to create a self-signed certificate for the controller from SSH and then use that certificate. This will resolve the issue.

Alternatively upgrade to v1.8.0 to resolve the issue completely.
