K000161626: Serial Console login fails to fallback to local authentication when TACACS+ unavailable

Type
Support Solution
Published
2026-07-06
Updated
2026-07-06
Applies to

  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161626

Description

Root login via the tenant console (accessed through virtctl console) fails to fallback to local authentication when TACACS+ authentication is configured, the TACACS+ server is unavailable, and systemauth.nolocalonly is set to true. The login prompt restarts repeatedly and no local authentication fallback occurs. Root login via management SSH succeeds under the same conditions, correctly falling back to local authentication.

Environment

  • BIG-IP LTM tenant
  • Remote authentication, fallback ture

Cause

ID2304825, When using a remote authentication server like Radius, TACACS+, or LDAP, the users can log in to the console/virtual console using authentication from that server. If the server, or communication with this server, fails, the users have no fallback to local authentication; this fallback only works with sshd or httpd.

Answer/Recommended Actions

- To allow root login via the tenant console when TACACS+ is unavailable, set systemauth.nolocalonly to false (if permitted by your security policy).
- If systemauth.nolocalonly=true is required, use management SSH for root access during TACACS+ outages, as fallback works correctly in this path.
