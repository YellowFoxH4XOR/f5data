Description

You can configure the BIG-IP for SNI on the server-side SSL connection by using the Server Name setting on multiple server SSL profiles and enabling the serverssl-use-sni property on the virtual server (BIG-IP 15.1.0 and later) or using an iRule.

When connecting to a virtual server, if a client sends a server name in the client hello, the virtual server selects the server SSL profile for the server-side connection with the matching server name configured in the Server Name setting. For example the client hello sent to the virtual server has www.example.com; therefore, the virtual server selects server SSL profile app1 because it has www.example.com configured as the Server Name as opposed to the app2 profile because it's Server Name is www.siterequest.com.
 

Environment

  • Multiple backend servers that enforce TLS SNI extensions.
  • virtual server
  • server SSL profile
  • iRule

Cause

Server-side connections require the correct SNI based on the backend server.

Recommended Actions

  • Create a Server SSL profile with the proper hostname for each website hosted on the pool members.
    • Go to Local Traffic > Profiles > SSL > Server > Create.
    • Select the Advanced view.
    • Enter the hostname of the site in the Server Name setting.
    • Repeat for each website.
  • Apply the profiles to the virtual server's SSL Profile (Server) setting.
    • Go to Local Traffic > Virtual Servers and select your virtual server.
    • Move each Server SSL profile you created from Available to Selected.
    • Select Update.
  • In BIG-IP 15.1.0 and later, for the virtual server to select the appropriate Server SSL profile, enable the serverssl-use-sni property using the TMOS shell. Use the following command sequence syntax:
    tmsh modify ltm virtual <virtual server> serverssl-use-sni enabled
    tmsh save sys config
  • In BIG-IP versions earlier than 15.1.0, for the virtual server to select the appropriate Server SSL profile, use the iRule in the Server-side SNI support section of K13452: Configure a virtual server to serve multiple HTTPS sites using the TLS Server Name Indication feature.
    • To create the iRule referenced in K13452 go to Local Traffic > iRules > Create.
    • Add the iRule to your virtual server by going to Local Traffic > Virtual Servers and select Edit in the Resources column for your virtual server then select Manage in the subsequent page.

Additional Information

Note: The BIG-IP ignores the Server Certificate by default. For more info: K14806: Overview of the Server SSL profile (11.x - 15.x)
