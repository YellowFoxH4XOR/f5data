K6040: Reasons why the SSL connection from an i-mode phone fails

Topic

OpenSSL version 0.9.6d introduced default behavior of sending an empty 0 byte fragment before application data chunks. This behavior was introduced as a countermeasure against vulnerability in CBC cipher suites in SSL 3.0/TLS 1.0.

Because the behavior turned out to be incompatible with some SSL implementations, a new OpenSSL option was introduced in OpenSSL version 0.9.6e that allows users to disable the BIG-IP SSL proxy's ability to send the empty 0 byte. The OpenSSL option to disable this proxy behavior is SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS.

The BIG-IP SSL proxy default behavior is to send the empty 0 byte fragments. Some i-mode phones, however, do not support encryption of 0 byte data packets and will terminate the session when such packets are received.

To disable the BIG-IP SSL proxy's ability to send the empty 0 byte fragments, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Configure the BIG-IP SSL proxy to emulate ModSSL for the purpose of selecting an SSL method by typing the following command:

    bigpipe db set Common.Bigip.Proxy.ModSSLMethods = 1

  3. Configure the BIG-IP SSL proxy to use the OpenSSL SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS option by typing the following command:

    bigpipe db set Common.Bigip.Proxy.SSLOptions = 2048

    Note: 2048 is the decimal value for the OpenSSL SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS 0x00000800L option.

  4. Restart the BIG-IP SSL proxy by typing the following command:

    proxyd

The BIG-IP SSL proxy will now be compatible with i-mode and other affected phones.
