Known Issue

Description

The BIG-IP system may incorrectly promote a virtual server that was demoted from Clustered Multi-Processing (CMP) back to CMP.

This issue occurs when all of the following conditions are met:

  • You are on a multi-CPU or multi-core BIG-IP host
  • The virtual server references both CMP and non-CMP compatible iRules
  • You modify the existing CMP compatible iRule using the Configuration utility or command line utilities

If a virtual server has both CMP compatible and CMP incompatible iRules associated with it, the BIG-IP host will demote that virtual server from CMP, and it will only run on one CPU core.

If a change is made to an existing CMP compatible iRule in such a configuration, the BIG-IP system does not check the compatibility of other iRules associated with that virtual server. As a result, the system erroneously promotes the virtual server to CMP compatibility, even if there are CMP incompatible iRules associated with the virtual server.

Impact

iRules may not function as designed, which may result in unexpected traffic processing.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H388316 on the Diagnostics > Identified > Medium screen.
  • You may see error messages in the /var/log/ltm file related to your iRules

    For example:

    can't read "::variable_name": no such variable
  • Unexpected distribution of processor utilization on multi core BIG-IP hosts

    If you look at the CPU statistics from within the Configuration utility, you may notice a different distribution of CPU over the available CPU cores from the time the iRule was modified. To view the CPU statistics, navigate to Overview > Performance > System. Under System CPU Usage, click View Detailed Graph.
  • After updating an iRule you see the CMP status of a virtual server change after editing the iRule

    To check the CMP status of a virtual server, enter the following command from the BIG-IP command line:  

    Note: In the following commands, replace <virtual server> with the name of your virtual server.

    • BIG-IP 11.x

      tmsh show ltm virtual <virtual server>

      When CMP is enabled, the command output will display similar to the following example:

      Status
        Availability     : available
        State            : enabled
        Reason           : The virtual server is available
        CMP              : enabled
    • BIG-IP 9.x and 10.x

      b virtual  <virtual server> cmp

      When CMP is enabled, the command output will display similar to the following example:

      VIRTUAL <virtual server> - CMP: enable

Workaround

To work around this issue you can perform any of the following three procedures:

Rewrite your iRules to be CMP compatible

Rewriting the affected iRule to be CMP compliant offers a permanent workaround to this issue. Additionally, CMP compliant iRules offer the added benefit of better performance and scalability.

Impact of workaround: None.

For more information, refer to K13033: Constructing CMP-compatible iRules.

Make a change to the non-CMP compliant iRule

You can temporarily work around this issue by updating the non-CMP compatible iRule with a small change to force it to be reloaded. However, the issue can be reintroduced if the conditions listed above are repeated.

Impact of workaround: None. You will need to repeat this procedure if you encounter this issue again due to editing the CMP compatible iRule.

  1. Log in to the Configuration utility.
  2. Go to the Local Traffic > iRules menu.
  3. Select the non-CMP compatible iRule.
  4. Add a blank line to the end of the iRule.
  5. Click Update.

Reload the BIG-IP configuration

You can temporarily work around this issue by reloading the BIG-IP configuration. However, the issue may occur again if the previously listed conditions are repeated.

Impact of workaround: This workaround may temporarily impact traffic and is only recommended during a maintenance window.  You will need to repeat this procedure if you encounter this issue again due to editing the CMP compatible iRule

You can reload the BIG-IP configuration using the following commands:

  • BIG-IP 11.x

    tmsh load /sys config

  • BIG-IP 9.x and 10.x

    bigpipe load
