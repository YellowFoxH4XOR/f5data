Description

The BIG-IP has no built-in SNMP counter for in-progress and established APM sessions.

Environment

  • BIG-IP
  • APM
  • SNMP

Cause

SNMP can be used to monitor a large number of various counters, but for APM there is no separate SNMP OID for in-progress and established sessions. This can be achieved by creating custom SNMP OIDs.

Recommended Actions

To configure a custom SNMP OIDs that return the current value for in-progress and established APM sessions, perform the following procedure:.

  1. Log in, with administrative privileges, to the command line of the affected device.
  2. Using a text editor, create the following file: 
    /config/snmp/custom_mib.tcl
  3. Enter the following command syntax in the /config/snmp/custom_mib.tcl file:
    Optional: You can use the -a flag in tmsh -a show app access all-properties to avoid adding entries to the tmsh history file, ~/.tmsh-history-root.

    register_mib ".1" countAPMInProgreess GAUGE
    register_mib ".2" countAPMEstablished GAUGE
           proc countAPMInProgreess {} {
              set status [catch { exec /usr/bin/bash -c "tmsh show apm access all-properties | grep -c 'status pending'" } result]
              if {[string is integer $result]} {
                 return $result
              }
              return 0
           }
           proc countAPMEstablished {} {
              set status [catch { exec /usr/bin/bash -c "tmsh show apm access all-properties | grep -c 'status established'" } result]
              if {[string is integer $result]} {
                 return $result
              }
              return 0
           }

  4. Save the changes.      
  5. To restart the SNMP service, type the following command:
    tmsh restart /sys service snmpd
  6. To verify that the custom OID is functional, type the following command:
    snmpwalk -Os -c public -v 2c localhost .1.3.6.1.4.1.3375.2.100


(in-progress sessions are shown in OID .1.3.6.1.4.1.3375.2.100.1.0 and established sessions are shown in OID .1.3.6.1.4.1.3375.2.100.2.0)
