K12641: Using the SSL::collect iRule command now causes a virtual server to wait for client data before opening a serverside connection

Issue

Beginning in BIG-IP 10.2.0-HF2, when a virtual server is configured with an iRule that invokes the SSL::collect command, the virtual server waits for data from the client before opening a serverside connection.

In previous BIG-IP versions, the virtual server opens the serverside connection as soon as the SSL handshake has completed, without waiting for data from the client.

Note: For more information about this iRule command, refer to the SSL::collect wiki page on DevCentral. A separate DevCentral login is required to access this content; if necessary, you will be redirected to authenticate or register.

F5 introduced the new behavior discussed in this Solution to resolve a known issue (K12310: The BIG-IP system will not execute the CLIENTSSL_DATA iRule event unless a pool or profile is associated with the virtual server) and improve the performance of the BIG-IP system. Additionally, the new behavior is consistent with that of all other collect iRule commands, such as TCP::collect, SCTP::collect, and HTTP::collect.

The new behavior causes an issue when the client does not send any data before receiving data from the server. This is the case, for example, with the FTP, SMTP, and SSH protocols. For more information, refer to K12646: The use of collect iRule commands may cause certain connections to stall and ultimately be reset.
