Known Issue

The BIG-IP system may miscalculate CPU idle time after an uptime of 49 days.

Impact

The BIG-IP system may miscalculate time thresholds for time based objects.

Symptoms

As a result of this issue, you may encounter the following symptoms in BIG-IP 10.2.2 through 11.1.0:

  • The /var/ltm log file may display unexpected clock time adjustments.
  • A sudden decrease in CPU activity may be noted in the performance graphs as the system crosses the approximate 49.7 day boundary.
  • The system will incorrectly display CPU usage by process in the output of the top command, and SNMP tools that report the same CPU data.
  • BIG-IP monitored objects may be marked as unavailable.
  • GTM big3d communications may be impacted.
  • Erroneous power supply failure alerts may be logged.
  • The tmrouted process may continuously restart

In addition to the above symptoms, you may encounter the following symptoms in BIG-IP 11.1.0:

  • Messages similar to the following example may be written to the /var/log/ltm file:

    • 01010040:4: Clock has unexpectedly adjusted by 24400 ms
    • warning kernel: Clocksource tsc unstable (delta = -396203001 ns)
    • 01160024:4: warning: no receive on 3/2.8 for 45s (timeout=90s)
    • 012a0003:3: CPLD write byte failed : I2C: File I/O Error [No such device or address] at I2cDev.cpp:119 : File MGAI2cCpld.cpp Line 67
    • warning chmand[6178]: 012a0004:4: VCC_ICH = 1239 out of range 945/1155
  • False positive power supply failure alerts may also be written to the /var/log/ltm file. For example:

    emerg system_check[30678]: 010d0006:0: Chassis power supply 1 has experienced an issue. Status is as follows: FAN=good; STATUS=bad.
  • Messages similar to the following example may be written to the /var/log/kern.log file:

    err kernel: i801_smbus 0000:00:1f.3: SMBus is busy, can't use it!
  • The output of the bigstart status command may indicate the tmrouted process continually restarting. For example:

    tmrouted run (pid 25546) 26 seconds, 11776 restarts

Workaround

To work around this issue, you can reset the system uptime. To do so, perform the following procedure:

Impact of workaround: Resetting the uptime requires a system reboot, which will result in a service interruption.

  1. Log in to the BIG-IP command line.
  2. To receive an estimate of the current system uptime, type the following command.

    uptime
  3. To reboot the system, type the following command:

    reboot; exit
