Description

BIGIP is experiencing high cpu utilization and running the top command reveals that bd process is the highest consumer and the oprofile shows that the device spends much time on running re2 (regular expression engine being used by signatures mechanism).
re2 is one of the most expensive function being used in BD, in order to avoid re2, BD maintains in memory cache (implemented as LRU hash tables). When the BD starts up or a policy is updated (sync from active), the cache gets cleaned.

Environment

  • BIG-IP ASM
  • VIPRION

Cause

This is due bug 1359765

Recommended Actions

This is expected behavior and only affects data plane.
When the cache is empty, signatures mechanism including re2 runs more and consumes more CPU, overtime re-current request parts (ex. parameters, headers) are added to LRU cache tables, thus the CPU consumption should improve overtime.
This is safe to ignore because usually the cache will get filled pretty fast.
