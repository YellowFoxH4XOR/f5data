Topic

When a failover between a primary and secondary FirePass controller has been initiated, the failover mechanism synchronizes the currently active session table, the recently expired session table, and the configuration. This behavior occurs continuously if the boxes are in a high availability configuration. When a primary FirePass controller is servicing connections and fails over, all TCP connections are immediately dropped.

This has the following effect on the different modes of connection:

  • Network Access

    Windows clients automatically reconnect. Mac/Linux clients are dropped and need to re-authenticate manually. Edge clients, such as the iPhone, automatically reconnect.
  • Application tunnels

    Windows clients automatically reconnect. Java application tunnels will also automatically reconnect for Mac/Linux.
  • Java patcher

    Automatic reconnect.
  • Portal

    Since HTTP is essentially connection-less, the user may only notice that the connection may be unavailable for 10 to 15 seconds.
  • IPSec tunnels

    The IPSec tunnel will renegotiate once the IPSec timeout threshold has been reached. The exact timing of this will depend on the IPSec peer configuration.
