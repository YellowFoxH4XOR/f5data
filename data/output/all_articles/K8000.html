Known Issue

This is the result of a known issue. If you upgrade your FirePass controller to version 6.0.2 of FirePass software, FirePass will no longer return the session.network.server.ip, session.network.server.name, and session.network.server.host session variables. If you configured a pre-logon sequence that requires one or more of these session variable, users will be unable to logon to the FirePass controller. If you configured a Protected Configuration that requires one or more of these session variables, users will be unable to access any resource which uses that Protected Configuration for its Endpoint Protection.

Note: Pre-Logon Sequences are configured on the Users: Endpoint Security: Pre-Logon Sequence page. Protected Configurations are configured on the Users: Endpoint Security: Protected Configuration page.

F5 Networks Product Development tracked this issue as CR76259 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Important: For FirePass version 6.0.3, if you select the Save user's session variables to Logon Reports check box on the  Device Management : Maintenance : Troubleshooting Tools page, the session.network.server.ip, session.network.server.name, and session.network.server.host session variables do not appear in the Logon Reports. However, these session variables are populated and available for use.

Additionally, a hotfix has been issued for FirePass version 6.0.2. To obtain this hotfix, contact F5 Networks Technical Support.

Workaround

To work around this issue, remove all references to the session.network.server.ip, session.network.server.name, and session.network.server.host session variables from your pre-logon sequence and Protected Configurations.
