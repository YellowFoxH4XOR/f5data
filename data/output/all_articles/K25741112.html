Topic

You should consider using this procedure under the following condition:

  • You want to view or modify a Virtual Clustered Multiprocessing (vCMP) guest's BIG-IP configuration from the command line of the vCMP hypervisor.

Description

If you specify a command as an argument to the ssh client, it runs the command on the remote host instead of running a login shell; therefore, you can use the ssh client on the vCMP hypervisor for quick access to remotely view or modify the guest's BIG-IP configuration. For more advanced work, you can manage guests with BIG-IQ Centralized Management, F5 Modules for Ansible, or another management and orchestration tool.

Note: You can run the commands in the procedures that follow on any Linux host that has network access to the vCMP guests; however, the public key authentication procedure shown in this article may not apply.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have access to the vCMP hypervisor command line.
  • Have a user account on both the vCMP hypervisor and the vCMP guest that gives you access to the Advanced Shell (bash) of the BIG-IP system.

Procedures

  • Set up SSH public-key authentication for the vCMP guests on the vCMP hypervisor
  • Using the ssh client on the vCMP hypervisor to remotely run commands on a single vCMP guest
  • Using the ssh client on the vCMP hypervisor to remotely run commands on multiple vCMP guests
  • Using the ssh client on the vCMP hypervisor to remotely run a script on vCMP guests

Note: In all of the procedures you can omit <user>@ in the ssh command if you are using the same user account on both the hypervisor and guest.

Set up SSH public-key authentication for the vCMP guests on the vCMP hypervisor 

This procedure is not required, but if you want to avoid entering your password each time you run ssh, you should set up public-key authentication with the guests.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the vCMP hypervisor command line.
  2. Generate an SSH RSA key pair on the hypervisor by typing the following command:

    ssh-keygen

    Note: This generates a key pair in .ssh/id_rsa and .ssh/id_rsa.pub in the user's home directory

  3. Choose a vCMP guest user you want to use to remotely run commands. This may be the same user that is on the hypervisor. Append the public key to this vCMP guest user's authorized_keys file by using the following syntax:

    Note: The command below will create the .ssh directory and authorized_keys file for the vCMP guest user if it does not already exist. 

    ssh-copy-id <user>@<guest IP address>

    For example:

    ssh-copy-id user1@192.0.2.121

  4. Enter your password once to transfer the key to the vCMP guest.

    You can now use the ssh client to access the vCMP guest without the need to enter your password.

Using the ssh client on the vCMP hypervisor to remotely run commands on a single vCMP guest

The following procedure introduces you to the basic syntax for viewing or modifying  the vCMP guest BIG-IP configuration.

Impact of procedure: Viewing the configuration of the vCMP guest should not have a negative impact on your system; however, modifying the configuration may have a negative impact depending on the commands you choose to run.

  1. Log in to the vCMP hypervisor command line. 
  2. To remotely run a command on a vCMP guest, use the following syntax:

    ssh <user>@<guest IP address> '<command or series of commands>' [|less]

    For example:

    • Running a bash command:

      ssh root@192.0.2.120 'date'

    • Viewing the contents of the guest's bigip.conf file:

      ssh root@192.0.2.120 'cat /config/bigip.conf' | less

    • Running a TMOS Shell command:

      ssh root@192.0.2.120 'tmsh list /ltm virtual'

    • Running a series of commands. Each command is separated by the ; (semicolon) character.

      ssh root@192.0.2.120 'cat /VERSION;tmsh list /ltm virtual;tmsh list /ltm pool' | less

    • Creating a BIG-IP configuration object in the /Common partition with a TMOS Shell command:

      ssh root@192.0.2.120 'tmsh create /ltm node 198.51.100.1 address 198.51.100.1 && tmsh save /sys config'

Using the ssh client on the vCMP hypervisor to remotely run commands on multiple vCMP guests

If you use the syntax introduced in the previous procedure you can place the ssh command in a bash for loop to repeat it on multiple guests.

Impact of procedure: Viewing the configuration of the vCMP guest should not have a negative impact on your system; however, modifying the configuration may have a negative impact depending on the commands you choose to run.

  1. Log in to the vCMP hypervisor command line.
  2. Create a shell variable with a list of the vCMP guest IP addresses using the following syntax:

    <variable name>='<guest IP 1> <guest IP 2> ...'

    Note: The ... (ellipsis) represents additional guest IP addresses to be appended.

    The following example command creates a guests shell variable. The variable is available only on your current login session. To make it persist upon subsequent logins, you can add it to your ~/.bashrc file on the vCMP hypervisor.

    guests='192.0.2.120 192.0.2.121'

  3. To remotely run commands on multiple vCMP guests, run a one-liner bash for loop with the ssh command syntax introduced in the Using the ssh client on the vCMP hypervisor to remotely run commands on a single vCMP guest procedure. A single guest IP is stored in the i variable during each iteration of the loop. To perform this step, use the following syntax:

    for i in <variable with guest IP addresses>; do ssh <user>@$i '<command or series of commands>'; done [|less]

    Optionally you can add an echo -e '\n' command to print a newline between the output from the guests. To do so, use the following syntax:

    for i in <variable with guest IP addresses>; do ssh <user>@$i '<command or series of commands>'; echo -e '\n'; done [|less]

    The following for loop examples loop over each guest listed in the guests variable and run the specified command:

    for i in $guests; do ssh root@$i 'cat /config/bigip.conf'; echo -e '\n'; done| less
    for i in $guests; do ssh root@$i 'tmsh list /ltm node'; echo -e '\n'; done| less
    for i in $guests; do ssh root@$i 'tmsh create /ltm node 198.51.100.1 address 198.51.100.1 && tmsh save /sys config'; done

Using the ssh client on the vCMP hypervisor to remotely run a script on vCMP guests

You can run a shell script on the vCMP guest remotely by redirecting the output to the bash command that you place as an argument to the ssh client.

Impact of procedure: Viewing the configuration of the vCMP guest should not have a negative impact on your system; however, modifying the configuration may have a negative impact depending on the commands you choose to run.

Remotely run a script on vCMP guests

  1. Log in to the vCMP hypervisor command line and create a shell script in a directory of your choosing. The following is an example of a shell script you can run on the vCMP guest remotely using the ssh client on the vCMP hypervisor:

    #!/bin/bash

    cat /VERSION
    tmsh list /sys global-settings hostname
    tmsh list /ltm virtual
    tmsh list /ltm pool
    tmsh list /ltm node

  2. Use the ssh client on the vCMP hypervisor to run bash remotely on the guest and redirect the local script to it with the following syntax:

    ssh <user>@<guest IP address> 'bash' < <path to script>

    For example:

    ssh root@192.0.2.120 'bash' < /shared/tmp/my_script

Remotely run a script with positional parameters on vCMP guests

  1. You can run a shell script that makes use of positional parameters. Log in to the vCMP hypervisor command line and create a shell script in a directory of your choosing. The following is an example of a shell script you can run on the vCMP guest remotely using the ssh client on the vCMP hypervisor. The positional parameters are signified by the $1, $2, and $3. You can use additional positional parameters in your own custom script:

    #!/bin/bash

    cat /VERSION
    tmsh list /sys global-settings hostname
    tmsh list /ltm virtual $1
    tmsh list /ltm pool $2
    tmsh list /ltm node $3

  2. Use the ssh client on the vCMP hypervisor to remotely run the script with positional parameters on the guest. You run bash with the  -s option to signal that the arguments after the script are for the positional parameters. The sequence of arguments correspond with the positional parameter numbers. Use the following syntax:

    ssh <user>@<guest IP address> 'bash -s' [--] < <path to script> <1st argument> <2nd argument> <3rd argument> ...

    Note: The ... (ellipsis) represents additional arguments to be appended.

    Note: The -- (double dash) is optional as it terminates command line options for bash and is only required if the 1st argument contains a leading - (dash).

    For example:

    ssh root@192.0.2.120 'bash -s' < /shared/tmp/my_fancy_script vip1 pool1 198.51.100.1

Remotely run a script on multiple vCMP guests

Using the syntax introduced previously in this procedure and the Using the ssh client on the vCMP hypervisor to remotely run commands on multiple vCMP guests procedure, you can place the ssh command that runs the script in a bash for loop to repeat it on multiple guests. The following for loop examples loop over each guest listed in the guests variable and run the command to run the script.  A single guest IP is stored in the i variable during each iteration of the loop:

for i in $guests; do ssh root@$i 'bash' < /shared/tmp/my_script; done
for i in $guests; do ssh root@$i 'bash -s' < /shared/tmp/my_fancy_script vip1 pool1 198.51.100.1; done

Optionally you can add an echo -e '\n' command to print a newline between the output from the guests. The following for loop examples demonstrate how to do this:

for i in $guests; do ssh root@$i 'bash' < /shared/tmp/my_script; echo -e '\n'; done
for i in $guests; do ssh root@$i 'bash -s' < /shared/tmp/my_fancy_script vip1 pool1 198.51.100.1; echo -e '\n'; done
