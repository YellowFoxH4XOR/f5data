Description

Configuring an earlier version of the apmclients package does not seem to work.

  • After upgrading the APMClient package the BIG-IP APM will try to update all the client devices to new version of Edge Clients as they connect
  • When browsers are used to connect to the APM, the user is also prompted to upgrade the helper apps (F5vpn and F5epi)

Environment

Relevant environmental factors specific to the topic

  • BIG-IP Versions 17.1, 16.1 and 14.1.4.4 or later 
  • a different apmclients (newer or older) was installed and set as active
  • Windows or MacOS End devices (not using F5 Access)

Cause

After a security upgrades, the BIG-IP versions may have a newer apmclients version built in. On upgrade the system version will initially be active. The system version cannot be removed, and the BIG-IP APM will choose the newest version to be active with each boot. The apmclients package contains the BIG-IP Edge Client and Browser Helper apps for each supported OS (Windows, MacOS and Linux).
Each end device will self-update if it is configured, and when it can. The end devices will not downgrade, even if the APM is set to an older supported version. 

Recommended Actions

There is no way to downgrade the built-in version apmclients package without downgrading BIG-IP (not recommended).
To ensure a newer version can be activated re-upload and select that version from the GUI or CLI.
The Linux packages are not affected as they do not self update.

Additional Information

New BIG_IP versions may also reset the EPSEC package versions, check these and upgrade to the latest version if you are using Endpoint Inspection features.
