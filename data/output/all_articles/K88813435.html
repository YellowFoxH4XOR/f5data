Known Issue

When an internal hardware sensor alert indicates a Bad power supply status, the status does not include details to which characteristic of the power supply's state is causing an overall status for the power supply.

This issue occurs when all of the following conditions are met:

  • One of your power supplies reports an error.
  • You are using one of the following BIG-IP or VIPRION platforms:
    • B2100/B2150
    • B2250
    • C2200/C2400
    • 5000s/5050s/5200v/5250F/5250v
    • 7000/7000s/7050s/7200f/7200s/7200v/7250f/7250s/7250v
    • 10000s/10050s/10200f/10200s/10200v/10350n

Impact

You are unable to diagnose the cause of the Bad status based on the logged error messages.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system logs an error message in the /var/log/ltm file that appears similar to the following example:

    012a0013:2: Blade 0 hardware sensor critical alarm: Power Supply 2 GPIO status(SPAFFIV03G): Bad

Workaround

To work around this issue, you can temporarily enable additional debugging. To do so, perform the following procedure:

Impact of workaround: You should perform the following task during a maintenance window or on a host in a standby state.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To set the libhal logging level to debug, type the following command:

    modify sys db log.libhal.level value debug

  3. Let the system run in this configuration for several minutes to collect a number of chmand error messages that appear similar to the following example:

    debug chmand[...]: 012a0007:7: Power Supply 1 alert objid:0x16f local:1 status:0x3 pin:0x2 action:0xd
    debug chmand[...]: 012a0007:7: Received Sensor Alert: sensor id 0x16f slot 0xff
    debug chmand[...]: 012a0007:7: Power Supply 1 alert objid:0x16f local:1 status:0x1 pin:0x2 action:0x3.

  4. To set the libhal logging level back to notice, type the following command:

    modify sys db log.libhal.level value notice

  5. Perform a QKView and contact F5 Technical Support for further analysis.
