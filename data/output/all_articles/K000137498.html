K000137498: system aaa shows "Error: application communication failure" after setting the primary key in F5OS-C version 1.5.1

Type
Support Solution
Published
2023-11-08
Updated
2023-11-08
Applies to
  • F5OS
  • F5OS-C: 1.5.1
Source
https://my.f5.com/manage/s/article/K000137498

Description

Your unit is running on F5OS-C version 1.5.1 and the system aaa is showing "Error: application communication failure" after you set the primary key.

 

The first instance of the command after setting the primary-key works fine.

 

syscon-1-active(config)# system aaa primary-key set passphrase

Value for 'passphrase' (<string, min: 6 chars, max: 255 chars>): *********************

Value for 'confirm-passphrase' (<string, min: 6 chars, max: 255 chars>): *********************

Value for 'salt' (<string, min: 6 chars, max: 255 chars>): *******************

Value for 'confirm-salt' (<string, min: 6 chars, max: 255 chars>): *******************

response Info: Key migration is initiated. Use 'show system aaa primary-key state status' to get status

syscon-1-active(config)# exit

syscon-1-active# show system aaa primary-key state status

system aaa primary-key state status "COMPLETE    Initiated: Mon Oct 9 08:22:44 2023"

syscon-1-active# show system aaa primary-key state hash

system aaa primary-key state hash ExamPle6U0genLSGZ+ExamPle123Jeal+TeExample123t21ARKi5cOMbAPsbExampleTesting==

 

Then the later instances fail with "Error: application communication failure":

 

syscon-1-active#

syscon-1-active#

syscon-1-active# show system aaa primary-key state hash

Error: application communication failure

syscon-1-active# show system aaa primary-key state hash

Error: application communication failure

syscon-1-active# show system aaa primary-key state status

Error: application communication failure

syscon-1-active# show system aaa primary-key state hash

Error: application communication failure

 

 

In /var/confd/log/confd.log file, you would see a similar error message logged:

 

<CRIT> 9-Oct-2023::08:23:58.049 syscon-1-active confd[415]: - Daemon ConfdKeyMigrationOpHandler timed out

<CRIT> 9-Oct-2023::08:24:07.774 syscon-1-active confd[415]: - no registration found for callpoint primarykey-state-call/get_elem of type=external

<CRIT> 9-Oct-2023::08:24:15.168 syscon-1-active confd[415]: - no registration found for callpoint primarykey-state-call/get_elem of type=external

[...]

 

Command docker exec vcc-confd confd --status shows the relevant callpoint not registered

 

callpoints:

[...]

id=primarykey-state-call ** not registered <------!!

 

Environment

  • F5OS-C
  • VELOS

 

Cause

Unknown

 

Recommended Actions

To recover, run the following steps:

 

1. Restart the confd-key-migration-mgr container from an administrative session in bash

docker restart confd-key-migration-mgr

 

2.Verifying no longer see the error by running the following command from an administrative session in bash

 

syscon-1-active# show system aaa primary-key state hash

system aaa primary-key state hash ExamPle6U0genLSGZ+ExamPle123Jeal+TeExample123t21ARKi5cOMbAPsbExampleTesting==

 

syscon-1-active# show system aaa primary-key state status

system aaa primary-key state status NONE
