K000148973: Creation of a local user for the the remote user is not correctly synchronised on the peer BIG-IP

Type
Support Solution
Published
2024-12-16
Updated
2024-12-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000148973

Description

When an administrator authenticated via remote server, tries to create his own account locally (to have direct access in bash), the account is correctly created on the F5, but the synchronization is wrong on his peer.

On the peer, the ‘partition access’ is missing, which means that the administrator can no longer connect to the peer at all.

Environment

- BIG-IP LTM

- Sync-Failover group

- remote authenticated users

Cause

Bug ID 1599841

Recommended Actions

As a workaround you can:

1) Use "run util bash" for a remote user to access bash (every remote user with admin role has bash access) and therefore there's no need to create a local user with the same name,

Or

2) Manually add partition access to the user on the peer F5 (instead of recreating the user), as in the example below.

tmsh modify auth user testuser partition-access add { all-partitions { role admin } }

tmsh save sys config

Note: Replace "testuser" with the correct user name.
