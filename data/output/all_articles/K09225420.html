Known Issue

The Traffic Management Microkernel (TMM) may restart when Server Secure Sockets Layer (SSL) profiles do not have associated SSL certificates and keys.

This issue occurs when all of the following conditions are met:

  • Your configuration includes one or more virtual servers with associated Server SSL profiles.
  • The Server SSL profiles do not have an associated SSL certificate and key.
  • A backend server (pool member) requests a Client SSL certificate from the BIG-IP system.

Impact

The BIG-IP system fails to process application traffic while TMM restarts, and high availability (HA) devices may experience a failover event.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system temporarily fails to process traffic.
  • You notice a failover event has occurred.
  • You notice an error message in the /var/log/tmm file that appears similar to the following example:

    notice ** SIGSEGV **

  • Your BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

To avoid this issue, ensure Server SSL profiles are configured with appropriate SSL certificates and keys when backend servers are configured to request Client SSL certificates.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

For information about the Server SSL profile, refer to K14806: Overview of the Server SSL profile (11.x - 13.x).
