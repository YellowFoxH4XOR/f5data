Description

When using DOSL7::disable in an irule to disable DosL7 enforcement, the /var/log/dosl7d logs will still show attacks detected.  

Environment

  • BIG-IP using a DosL7 profile applied to a virtual server
  • An irule applied to the virtual server has the command DOSL7::disable

Cause

This behavior is documented in ID 630005.  The reason is due to the way AVR and DOSL7 interact to generate statistical information and how DOSL7 detects and mitigates traffic.  

The logging and the function of the DOSL7 profile act independently of one another. This is due to how the native function of AVR is used for the logging and statistical data versus the function of the DOSL7 profile. Due to this when dosl7::disable is used it only disables the function of the profile not the logging. To also stop the logging adding AVR::disable is also needed.  

Recommended Actions

To remove the log messages, add the following command after the DOSL7::disable command in the irule:

AVR::disable

Additional Information

It is possible when the AVR::disable is used that in rare circumstances it could also effect some logging for AdvWAF and/or Bot Defense, if they are also associated with the virtual server. Please test the usage of adding AVR::disable to the iRule prior to adding the change to production traffic.
