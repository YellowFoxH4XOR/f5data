Description

The following will show how to use the filters for syslog server.

In this scenario we will set different filters to send syslog to a specific syslog server

Environment

  • BIG IP
  • HA environment
  • Remote Syslog

Cause

None

Recommended Actions

The following configuration made to set each filter to send syslog server to a specific server per filter:

Important: Each destination server need to have other persist-name

modify syslog {
    auth-priv-from notice
    auth-priv-to emerg
    clustered-host-slot enabled
    clustered-message-slot disabled
    console-log enabled
    cron-from warning
    cron-to emerg
    daemon-from notice
    daemon-to emerg
    description none
    include "                                <<<< Include state START
    filter f1_remote_loghost {               <<<< 1st filter name
    level(warning..emerg);                   <<<< Different log level
    };
    filter f2_remote_loghost {               <<<< 2nd filter name
    level(info..emerg);                      <<<< Different log level
    };
    destination d1_remote_loghost  {         <<<< Define 1st destination
        udp(\"192.168.0.1\" port(5141) localip(\"192.168.0.111\") persist-name(d1));
        udp(\"192.168.0.1\" port(5141) localip(\"192.168.0.112\") persist-name(d2));
    };
    destination d2_remote_loghost  {         <<<< Define 2nd destination
        udp(\"192.168.0.1\" port(5142) localip(\"192.168.0.111\") persist-name(d3));
        udp(\"192.168.0.1\" port(5142) localip(\"192.168.0.112\") persist-name(d4));
    };
    log {
        source(s_syslog_pipe);
        filter(f1_remote_loghost);           <<<< using 1st filter 
        destination(d1_remote_loghost);      <<<< Followed by 1st destination
    };
    log {
        source(s_syslog_pipe);
        filter(f2_remote_loghost);           <<<< using 2nd filter
        destination(d2_remote_loghost);      <<<< Followed by 2nd destination
    };
    "                                        <<<< <<<< Include state END
    iso-date disabled
    kern-from debug
    kern-to emerg
    local6-from notice
    local6-to emerg
    mail-from notice
    mail-to emerg
    messages-from notice
    messages-to warning
    remote-servers none
    user-log-from notice
    user-log-to emerg
}

Note: Modifications to the syslog configuration properties that are made by using this procedure may not be reflected in the Configuration utility.

Additional Information

To get the localip mentioned above - from both BIG IP's in HA run from CLI:

# ip route get <ip of syslog>

Select source ip as localip

Note: In case of using monitoring tool/SIEM, you will need to get a specific IP for the device, localip should be configured as mgmt ip to correctly join data in siem tool.
