Known Issue

This is the result of a known issue. When the BIG-IP system processes a client request containing an HTTP Keep-Alive header, and the server sends a 304 Not Modified response containing a Content-Length header, the connection stalls. This behavior occurs because the BIG-IP system erroneously holds the connection open as the HTTP filter waits for the server to transfer the entire message-body.

Note: According to RFC2616, a 304 response must not contain a message-body, and is always terminated by the first empty line after the header fields.

F5 Product Development tracked this issue as CR95761 and it was fixed in BIG-IP version 9.4.5. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

In addition, this issue has been fixed in Hotfix-BIGIP-9.3.1-HF5, which has been issued for BIG-IP version 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
