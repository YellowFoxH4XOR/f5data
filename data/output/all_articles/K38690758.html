Description
There are cases where BIG-IP ASM triggers false positive match for signatures when uploading PDF files resulting in a request being blocked.

Environment

  • BIG-IP ASM
  • Content-Type: application/pdf

Cause

  • This usually occurs when request is being handled by a default content profile for the URL, and at some point the characters in the binary content of the PDF in the body of HTTP request matches some signatures intended for text content.

Recommended Actions

With binary payloads such as PDF, we recommend configuring ASM to ignore the binary content for requests with Content-Type: application/pdf.

Here are the steps:

1. Navigate to the affected URL in the ASM Policy, or create an allowed URL if it does not exist yet.

 
Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.


2. Under the Advanced settings, populate the following fields from Header-Based Content Profiles tab:
 

Request Header Name: Content-Type
Request Header Value: application/pdf
Request Body Handling: Do nothing


3. Click Add to get the new header-based handling. Then, click Update (or add) to update (or add) the allowed URL.

4. Click Apply Policy to have the changes take effect.
