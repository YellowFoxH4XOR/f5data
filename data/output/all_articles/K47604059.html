Description

When 'lacpd' service is stopped in BIG-IP using 'bigstart stop lacpd', all trunks in BIG-IP will go down, however, when 'lacp' is stopped, trunk status will still show as 'UP' in the output of 'tmsh show net trunk'
Even there is no lacpd packets generated by BIG-IP to be sent to neighbour switch and trunk is down at the remote switch end, status of trunk in BIG-IP will still display as 'UP'.

Changes what we see when 'lacpd' is manuallly stopped.

  • Trunk configuration will not be allowed . It will throw error  "An error occured while trying to process your request", if it is tried to access the trunk configuration page in GUI.
  • Even if all ports are down / disabled after 'lacpd' is stopped, Trunk will still show UP in the tmsh command output.
  • No lacpd packets will be generated. 
  • All lacpd domain sockets will be removed from the system.
  • 'bsconsole' output will still show the trunk in the list.

Environment

  • LACP Trunk

  • LACPD

Cause
This is an expected behaviour if LACPD is manually stopped ' bigstart stop lacpd'

Recommended Actions

To see the actual status of LACP enabled trunk, 'LACPD' service should be in running status.
# bigstart status lacpd
lacpd        run (pid 12126) 6 days, 4 starts
