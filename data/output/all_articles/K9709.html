Known Issue

This is the result of a known issue. When a disconnect occurs between the BIG-IP ASM bd process and the Traffic Management Microkernel (TMM) process, the following error message is logged in the /var/log/bd.log file:

TMEVT_REQUEST: Request has an unknown <Selector Name> selector: <policy name>

Important: The example error message appears similar to an error message detailed in K8977: The BIG-IP ASM stops processing requests.

The disconnect causes the BIG-IP ASM bd process to lose configuration information, including information regarding which selectors reference certain web applications.

For example, the following /var/log/bd.log file information indicates that a request was made for an HTTP selector that is referenced by the base_policy policy:

IO_PLUGIN|NOTICE|22/11/08 19:38:21|9106|io_plugin.c:510|TMEVT_REQUEST: Request has an unknown HTTP selector: base_policy

Important: The behavior and error message logged in the /var/log/bd.log file is typically accompanied by an UPDATE_CORE message reported in the /var/log/asm file, appearing similar to the following example:

COMMAND_MAN[3280]: [ERR, <date and time>, 3280, dcc, COMMAND_MAN::check_command, ] Command UPDATE_CORE(2) - unique id: (1) failed.

F5 Product Development tracked this issue as ID 347665 (formerly CR115187), and it was fixed in BIG-IP ASM 10.2.3. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

To restore communication between TMM and the BIG-IP ASM bd process, you must either reboot the BIG-IP ASM system, or restart the TMM and BIG-IP ASM bd process.

Important: Both options require the TMM and BIG-IP ASM bd process to restart in order to reload the configuration; both options will cause an outage or failover when using a redundant configuration.

Restarting the TMM and BIG-IP ASM bd process

Note: This method will result in less down time; the system only restarts the various system processes and does not require the unit to be powered down.

To restart the TMM and BIG-IP ASM bd process, type the following command:

bigstart restart

Rebooting the BIG-IP ASM system

To reboot the BIG-IP ASM system, type the following command:

reboot
