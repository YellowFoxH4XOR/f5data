Description

Internal (HSB) interfaces is flapping or disconnecting intermittently.

The following messages are observed in /var/log/ltm:

info bcm56xxd[8004]: 012c0015:6: Link: <iface> is DOWN
info bcm56xxd[8004]: 012c0012:6: HSB 1 HGM 0 LBB address 0x90000008 XLMACs status updated to 0x80000000
info bcm56xxd[8004]: 012c0015:6: Link: <iface> is UP
info bcm56xxd[8004]: 012c0012:6: HSB 1 HGM 0 LBB address 0x90000008 XLMACs status updated to 0x80000001
...
info bcm56xxd[8004]: 012c0015:6: Link: <iface> is DOWN

info bcm56xxd[8004]: 012c0015:6: Link: <iface> is UP
info bcm56xxd[8004]: 012c0012:6: HSB 1 HGM 0 LBB address 0x90000008 XLMACs status updated to 0x80000001

Environment

  • BIG-IP

  • Internal HSB interfaces <iface> - The actual interface number varies by the platform. For example, 9.1/10.1 for i5000, 9.1/9.2/10.1/10.2 for VIPRION B4450N. Please check the respective platform.

Cause

Interface errors

Recommended Actions

  1. Inspect /var/log/ltm and locate logs that state : Link: <iface> is DOWN
  2. Verify whether the optics used are 3rd party or F5-branded, and swap them as a troubleshooting step. Preferably replace the optics with supported F5 optics, otherwise simply use known good optics. This is to eliminate external interface issue causing problem with switch chip.
  3. If the above is true and you see logs similar to the above Description section, follow K34445101: Interface flapping on internal, non-physical interface to reboot the device.

Additional Information

There is a condition in which failures happen on the internal HiGig interfaces on the critical packet path via the HSB, causing traffic interruption. Such failures can be inferred by HSB XLMAC instability or by observing increasing FCS errors. FCS errors are run time errors which can be caused due to bit manipulation happened mostly by hardware or memory corruption during the packet traversal. These are run time errors and cannot be prevented.

The High-Speed Bridge (HSB) is the interface used on certain BIG-IP platforms to connect the switch fabric to the host subsystem. When the system understands that fcs errors are generated, it tries to correct the fcs error situation by resetting the XLMAC phy to make the link stable.

When these HSB XLMAC failures happened, if the failure persisted even after repeated recovery attempts, TMOS triggered a high availability (HA) failover event to prevent prolonged traffic disruption. The failover triggering condition is set as either the consecutive recovery attempts or consecutive FCS failure events that reach a configurable preset limit. After the HA failover was triggered, the original active unit will still keep trying to recover, and will mark itself ready if the failure condition is no longer observed.
