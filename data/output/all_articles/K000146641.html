What Happened?

I want to set up a custom error response based on error code but it is not documented in our Terraform registry.

Environment

  • F5® Distributed Cloud HTTP Load balancer
  • Terraform

Resolution/Answer

To set custom error responses for multiple error codes using the volterra_http_loadbalancer resource in Terraform, you can use the custom_errors variable. This variable is a map that allows you to specify HTTP error codes as keys and provide Base64-encoded content as the values.

 

Example Terraform configuration: 

resource "volterra_http_loadbalancer" "example_lb" {
   name = "example-lb"
   namespace = "default"

// Other necessary load balancer configuration options...

more_option {
   custom_errors = {
     404 = "string:///aW50ZXJuYWwgc2VydmVyIGVycm9y" # Custom message for 404 error
     304 = "string:///UmVkaXJlY3QgbWVzc2FnZQ==" # Custom message for 304 error
    }
  }
}

Key Details:

  • custom_errors: A map where each key represents an HTTP error code (e.g., 404 for “Not Found”) and each value is the Base64-encoded message for that error. The values are formatted as a URL string prefixed with string:///.
  • Base64 encoding: The content (like a custom error message) must be encoded in Base64 format. You can generate this by encoding any text string to Base64, and then prepending it with string:///.

Example Error Messages:

  • 404 code: This example includes a Base64-encoded message "aW50ZXJuYWwgc2VydmVyIGVycm9y", which translates to “internal server error”.
  • 304 code: The message "UmVkaXJlY3QgbWVzc2FnZQ==" translates to “Redirect message”.

This configuration allows you to set unique custom error responses for each error code, improving user experience by delivering tailored error messages.

 

Cause

The custom_errors variable is of map type, allowing you to specify error codes as keys and their corresponding messages in a URL format with Base64 encoded content as values.
