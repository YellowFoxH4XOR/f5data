K42380060: Idle timeout for SMTP monitor connections is now one second less than the monitor interval

Type
Knowledge
Published
2017-04-14
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.0.0, 12.1.1, 12.1.0, 12.0.0, 12.1.2, 11.6.0, 11.6.1
Source
https://my.f5.com/manage/s/article/K42380060

Issue

Old Behavior

In versions prior to BIG-IP 11.6.0 HF5, the idle timeout for SMTP monitor connections does not occur until after the monitor's timeout setting.

New Behavior

Beginning in BIG-IP 11.6.0 HF5, the idle timeout for SMTP monitor connections is one second less than the monitor's interval setting. For example, the following configuration shows an SMTP monitor with the default interval setting of five seconds:

ltm monitor smtp example {
    debug no
    defaults-from smtp
    destination *:*
    domain example.com
    interval 5
    time-until-up 0
    timeout 16
}

The idle timeout for a TCP connection from the BIG-IP system to the SMTP server is four seconds under this configuration.

F5 Product Development tracked this change as ID 490129.

Impact

Slower SMTP servers fail health checks, and the system ultimately marks them down after reaching the SMTP monitor's configured timeout value.

Recommended Actions

Adjust the SMTP monitor's interval setting to allow enough time for your SMTP servers to respond. For example, if your SMTP servers take five seconds to respond to the SMTP monitor HELO, increase the interval setting to seven seconds. F5 recommends that you also adjust the monitor timeout. In most cases, the timeout value should be equal to three times the interval value, plus one. In this example, the ratio should be 7/22 (three times seven plus one equals 22).

ltm monitor smtp example {
    debug no
    defaults-from smtp
    destination *:*
    domain example.com
    interval 7
    time-until-up 0
    timeout 22
}

The idle timeout for a TCP connection from the BIG-IP system to the SMTP server is six seconds under this configuration.
