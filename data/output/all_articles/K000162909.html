K000162909: BIG-IP upgrade fails with “Disk full (volume group)” when boot volumes use a separate partition

Type
Support Solution
Published
2026-08-13
Updated
2026-08-13
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162909

Description

A BIG-IP software installation or upgrade can fail with Disk full (volume group) even when the volume group reports sufficient total free space. The installer requires approximately 14 GB for a new boot volume set, but the partition reserved for boot application volumes has less available space.

Typical messages include:

warning: tm_install::VolumeSet::choose_filesystem_plan -- Selected filesystem plan
error: tm_install::Process::Process_full_install -- predicted image size exceeds remaining volume-group capacity
Terminal error: Disk full (volume group)
*** Live install failed (return code 1) ***

Environment

  • BIG-IP VE
  • Two physical partitions (for example: sda3, sda4)

Cause

Example outputs:

vgs:
VG        #PV  VSize    VFree
vg-db-sda 2    170.00g  70.00g

pvs:
PV                     PSize    PFree
sda3 (data partition)  150.00g  62.00g
sda4 (boot partition)   20.00g   8.00g

The volume group spans two physical partitions:

  • A larger data partition used for data and system volumes (sda3)
  • A smaller boot partition used for boot application volumes (sda4)

The volume group’s free space is distributed across two physical partitions. The BIG-IP installer allocates new boot volume sets exclusively from the boot partition and cannot use free space on the data partition for this operation.

Space on the boot partition can be taken up for various reasons, like an oversized or orphaned MySQL logical volume. As a result, the boot partition has less available space (8GB in example), while the installer requires approximately 14 GiB.

The total free space reported by vgs is therefore not representative of the space available for the installation because it combines free extents from both physical partitions.

Answer/Recommended Actions

Do not rely on the total vgs free-space value alone. Use pvs to check the free space on each physical volume and confirm that the boot partition has sufficient capacity. Do not attempt to force the installer to use the data partition. The BIG-IP installer does not use free space on that partition for boot volume sets in this layout.

 

  1. Backup the BIG-IP configuration using a UCS archive.
  2. Rebuild the VM with a single, sufficiently large disk (do not add a new partition; expand the existing one if more space is needed).
  3. Restore the UCS backup to the rebuilt system.
  4. For future upgrades, ensure disk expansions extend the existing partition rather than adding new ones to avoid partitioning constraints.
