K64001020: Certificates on VELOS blades expire after one year and cause blades and tenants to go offline

Type
Knowledge
Published
2022-09-01
Updated
2026-03-03
Applies to
  • VELOS Platforms
  • F5OS
  • F5OS-C: 1.5.1, 1.5.0, 1.3.2, 1.3.1, 1.2.2, 1.1.4, 1.2.1
Source
https://my.f5.com/manage/s/article/K64001020

Topic

F5OS-C software uses OpenShift certificates on VELOS chassis blades that expire one year after the cluster is initially deployed. When this occurs, the VELOS chassis blades and all tenants go offline, causing a traffic outage.

Description

The VELOS chassis system utilizes an OpenShift cluster which generates OpenShift certificates on the VELOS chassis blades (compute nodes) and system controllers (primary nodes). One year after deploying the VELOS system, the certificates on the VELOS chassis blades expire, which causes the blades to go offline. When this behavior occurs, all the tenants running on the chassis blades also go offline and stop processing data plane traffic.

The clock for the OpenShift certificate expiry on the chassis blades begins when you first deploy the VELOS chassis system, not when the system was originally manufactured.

Note: The certificates on the VELOS system controllers are generated during the manufacturing process and expire one year later; however, this issue has not been observed when they expire.

This issue impacts all VELOS chassis systems running F5OS-C 1.0.0 - 1.5.0. rSeries systems running F5OS-A are not impacted by this issue because F5OS-A uses K3s instead of OpenShift and the certificate expiry is set to 10 years.

Beginning in F5OS-C 1.5.1, OpenShift containers are updated to use a certificate expiration time of 10 years. To make use of these updated containers with longer certificate expiration times after upgrading to a fixed release, it is necessary to rebuild the OpenShift cluster. The rebuild takes 90 minutes or more and causes tenant(s) outage. To rebuild the OpenShift cluster, you can perform the Work around by reinstalling the OpenShift cluster procedure in this article.

After you rebuild OpenShift cluster using this fix, it is not possible to downgrade the F5OS-C version without rebuilding the OpenShift cluster after the downgrade. This is because the updated OpenShift containers is not available after the downgrade. If a downgrade is done before the OpenShift cluster is rebuilt, there will not be any issues.

In addition, in fixed F5OS-C versions, warning messages are added to the show cluster cluster-status command output on the system controller CLI that warn when certificates are within 90 days of expiring and when the OpenShift cluster needs to be rebuilt to take advantage of the new containers with the longer certificate expiration times. For example:

syscon-1-active# show cluster cluster-status 
cluster cluster-status summary-status "Openshift cluster is healthy, and all controllers and blades are ready. WARNING: 1 or more Openshift certificates expiring within 90 days. WARNING: Manual Openshift cluster rebuild necessary to update containers."

Symptoms

  • BIG-IP tenants deployed on the VELOS system go offline and are inaccessible.
  • On the active system controller, messages appear similar to the following example, indicating the certificates are expired:

    controller-2.chassis.local dockerd-current[4212]: E0809 19:48:01.601509       1 authentication.go:62] Unable to authenticate the request due to an error: [x509: certificate has expired or is not yet valid, x509: certificate has expired or is not yet valid]

  • The systemd journal on the system controller logs messages similar to the following example:

    controller-2.chassis.local origin-node[19920]: E0808 08:35:03.754013   19930 certificate_manager.go:326] Certificate request was not signed: timed out waiting for the condition

  • A tenant is stuck at stopping status when we try to change it to provisioned state. From ConfD's perspective the tenant is in provisioned state, which is what matters, so you can proceed with the OpenShift rebuild workaround below.

Workaround 

To watch a video demo of this procedure, go to   Work around the expiration of F5 VELOS chassis blades certificates.

You can check the expiration dates of the OpenShift certificates using the show_certs.sh script provided in the following procedure. If the chassis blade certificates on your system are not yet expired, you can mitigate this issue by renewing the certificates for another 365 days using the provided renew_nodes.sh script. After the chassis blade certificates expire you can no longer mitigate this issue by renewing the certificates. If the chassis blade certificates on your system are expired, the mitigation procedure does not work and you must perform the Work around by reinstalling the OpenShift cluster procedure instead.

When performing the following procedures, consider the following:

  • When renewing the certificates using the renew_nodes.sh script, the length of the outage varies but is expected to be between 5 - 10 minutes for a single VELOS chassis system. When running the renew_nodes.sh script, you should ensure all tenants are failed over to another VELOS chassis system because they may restart in the process,  then run the renew_nodes.sh script on the VELOS chassis where the tenants are in the standby state. After the tenants have fully recovered, fail over all tenants to the VELOS chassis where the certificates were just upgraded, and then run the renew_nodes.sh script on the remaining VELOS chassis.
  • If the certificates on your system controllers are expired but the certificates on your chassis blades are not expired, you can still run the renew_nodes.sh script to bring them all back online. 
  • The renew_nodes.sh script will renew all certificates, however, some may expire in one year from the current date and others expire two years from the current date. This is a temporary mitigation to avoid an outage until a more permanent fix becomes available. The permanent fix, currently being worked on, will extend certificate lifetimes to 10 years, and will require a software upgrade to a new F5OS-C release and a cluster rebuild for certificate expiry options to take effect. After a fixed version is released, this article will be updated to reflect the fixed F5OS-C version.
  • The renew_nodes.sh script renews certificates for 365 days. The script includes a reference to 3650 days which only applies if the -controllers option is specified, and only applies to the certificates the appear in the upper sections of show_certs.sh output, which includes certificates for the cluster services.
  • The kubelet-client and kubelet-server certificates can only be renewed for 365 days without changes to OpenShift software.

Depending on the current state of your VELOS system, perform the following procedures as needed:

  • Check certificate expiry dates using the show_certs.sh script
  • Mitigate by renewing the node certificates using the renew_nodes.sh script
  • Workaround for reinstalling the OpenShift cluster
  • Workaround for expired apiserver certificates

Check certificate expiry dates using the show_certs.sh script

You can check the expiration date of the certificates using the provided script. To run it, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the system controllers floating IP address as root.
  2. Using a text editor, create a file named show_certs.sh with the following content:

    Note: You can download the script file from Github by entering the following command: curl -s https://raw.githubusercontent.com/askf5/K64001020/main/show_certs.sh -O.

    #!/bin/bash

#####################################
# Date: Thu Sep 22 11:16:24 EDT 2022
# Version: 1.5

goodCerts=0;
warnCerts=0;
expiredCerts=0;

warnDays=90
warnAge=$((60 * 60 * 24 * warnDays))
now=$(date +%s)

###############################################################
# Get validity data from the cert
###############################################################

function showCert() {
    openssl crl2pkcs7 -nocrl -certfile /dev/stdin | openssl pkcs7 -print_certs -text | grep Validity -A2
}

###############################################################
# Parse the cert date and determine the validity
###############################################################

function subDate {
    dateSeconds=$(date -d "$tmp" +%s)
    diff=$((dateSeconds - now))
    valid=$((diff/60/60/24))
    if ((diff<warnAge)); then
        if ((diff<=0)); then
            echo "$1EXPIRED: $f cert has already expired $valid days ago"
            expiredCerts=$(( expiredCerts + 1 ))
        else
            echo "$1WARNING: $f cert expires in $valid days"
            warnCerts=$(( warnCerts + 1 ))
        fi
    else
        echo "$1$f cert is valid for $valid more days"
        goodCerts=$(( goodCerts + 1 ))
    fi
}

###############################################################
# Process the cert date information
###############################################################

function processDate {
    tmp=$(echo "$dateInfo" | sed s/[\ A-Za-z]*After\ :[\ ]*// | cut -c -25)
    subDate "$1"
}

###############################################################
# Display controller cert validity
##############################################################

echo ""
echo "###############################################################"
echo "# Process all cert files under /etc/origin/master directory"
echo "###############################################################"
echo ""

for node in $(oc get nodes | grep -E controller | awk '{print $1}'); do
    echo "$node:"
    for f in $(ssh "$node" "find /etc/origin/master -type f \(  -name '*.crt' -o -name '*pem' \)"); do
        if [[ "$f" != /etc/origin/master/openshift-aggregator.crt ]]; then

done

###############################################################
# Display kubelet cert validity
###############################################################

echo ""
echo "###############################################################"
echo "# Process all node cert files /etc/origin/node"
echo "###############################################################"
echo ""

for node in $(oc get nodes |awk 'NR>1'|awk '{print $1}'); do
    echo "$node:"
    for f in $(ssh "$node" "find /etc/origin/node -type f \( -name '*.crt' \)"); do
        dateInfo=$(ssh "$node" cat "$f" | showCert | grep -E After | tail -1)
        processDate "    "
    done

    for f in $(ssh "$node" "find /etc/origin/node -name kubelet-*-current.pem"); do
        dateInfo=$(ssh "$node" cat "$f" | showCert | grep -E After | tail -1)
        processDate "    "
    done

    for f in $(ssh "$node" "find /etc/origin/node -name kubelet-*-.pem"); do
        dateInfo=$(ssh "$node" cat "$f" | showCert | grep -E After | tail -1)
        processDate "    "
    done
done

###############################################################
# Display apiserver-ssl cert validity
###############################################################

echo ""
echo "###############################################################"
echo "# Process apiserver-ssl cert"
echo "###############################################################"
echo ""

now=$(date +%s)
apiExpire=$(date -d "`oc get secret apiserver-ssl -n kube-service-catalog -o jsonpath='{.data.tls\.crt}' | \
                base64 --decode | openssl x509 -noout -enddate -startdate | egrep notAfter | awk -F= '{print $2}'`" +%s)
diff=$((apiExpire - now))

valid=$((diff/60/60/24))
if ((diff<warnAge)); then
    if ((diff<=0)); then
        echo "EXPIRED: apiserver-ssl cert has already expired $valid days ago"
        expiredCerts=$(( expiredCerts + 1 ))
    else
        echo "WARNING: apiserver-ssl cert expires in $valid days"
        warnCerts=$(( warnCerts + 1 ))
    fi
else
    echo "apiserver-ssl cert is valid for $valid more days"
    goodCerts=$(( goodCerts + 1 ))
fi

###############################################################
# Summary
###############################################################

echo ""
echo "###############################################################"
echo "Summary:"
echo "       Good Certs: $goodCerts"
echo "       Warn Certs: $warnCerts"
echo "    Expired Certs: $expiredCerts"
echo "###############################################################"
echo ""

if [[ $expiredCerts -gt 0 ]]; then
    exit 2
fi

if [[ $warnCerts -gt 0 ]]; then
    exit 1
fi

exit 0

Mitigate by renewing the node certificates using the renew_nodes.sh script

If the chassis blade certificates on your system are not yet expired, you can mitigate this issue by renewing the certificates for another 365 days using the renew_nodes.sh script. The script updates certificate expiry for the chassis blades and system controllers, even if the certificates on the system controllers are already expired. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure renews OpenShift certificates causing a traffic disruption to tenants running in the cluster.

  1. Log in to the system controllers floating IP address as root.
  2. Using a text editor, create a file named renew_nodes.sh with the following content:

    Note: You can download the script file from Github by entering the following command: curl -s https://raw.githubusercontent.com/askf5/K64001020/main/renew_nodes.sh -O.

    #!/bin/bash

#####################################
# Date: Fri Sep 16 11:45:19 EDT 2022
# Version: 1.5

days="3650"

update_controllers=0
if [[ "$1" != "" ]]; then
    if [[ "$1" == "-controllers" ]]; then
        update_controllers=1
    else 
        echo ""
        echo "ERROR: invalid option \"$1\""
        echo "    USAGE $0 [-controllers]"
        echo ""    
        exit -1
    fi    
fi

###############################################################
# Get validity data from the cert
###############################################################

function showCert() {
    openssl crl2pkcs7 -nocrl -certfile /dev/stdin | openssl pkcs7 -print_certs -text | grep Validity -A2
}

###############################################################
# Parse the cert date and determine the validity
###############################################################

function subDate {
    dateSeconds=$(date -d "$tmp" +%s)
    diff=$((dateSeconds - now))
    valid=$((diff/60/60/24))
    if ((diff<warnAge)); then
        if ((diff<=0)); then
            echo "$1EXPIRED: $f cert has already expired $valid days ago"
            expiredCerts=$(( expiredCerts + 1 ))
        else
            echo "$1WARNING: $f cert expires in $valid days"
            warnCerts=$(( warnCerts + 1 ))
        fi
    else
        echo "$1$f cert is valid for $valid more days"
        goodCerts=$(( goodCerts + 1 ))
    fi
}

###############################################################
# Process the cert date information
###############################################################

function processDate {
    tmp=$(echo "$dateInfo" | sed s/[\ A-Za-z]*After\ :[\ ]*// | cut -c -25)
    subDate "$1"
}

###############################################################
# Pause orchestration-manager processing while script is running
###############################################################

ssh controller-1.chassis.local touch /tmp/omd/pause
ssh controller-2.chassis.local touch /tmp/omd/pause

###############################################################
# Approve any outstanding CSR's before updating anything
###############################################################

outstandingCerts=$(oc get csr | grep Pending)

if [[ "$outstandingCerts" != "" ]]; then 
    echo "=================================================================="
    echo "Approving any outstand CSR Requests"
    oc get csr | grep -E Pending | awk '{print $1}' | xargs oc adm certificate approve
fi

if [[ $update_controllers == 1 ]]; then
    ###############################################################
    # Make sure etc_ansible_hosts file exists on this CC
    ###############################################################

    blades=$(oc get nodes | grep blade |awk '{print $1}')

    if [[ ! -f /tmp/omd/etc_ansible_hosts ]]; then
        if [[ $(hostname) == "controller-1.chassis.local" ]]; then
            echo "/tmp/omd/etc_ansible_hosts does not exist, copy from controller-2.chassis.local"    
            scp controller-2.chassis.local://tmp/omd/etc_ansible_hosts /tmp/omd/etc_ansible_hosts
        else 
            echo "/tmp/omd/etc_ansible_hosts does not exist, copy from controller-1.chassis.local"    
            scp controller-1.chassis.local://tmp/omd/etc_ansible_hosts /tmp/omd/etc_ansible_hosts
        fi    
    else 
        echo "/tmp/omd/etc_ansible_hosts exists"    
    fi

    ###############################################################
    # If specified, redeploy the controller certs and create a new CA
    ###############################################################

    time docker exec -it orchestration_manager ansible-playbook -i /tmp/omd/etc_ansible_hosts /usr/share/ansible/openshift-ansible/playbooks/openshift-master/redeploy-certificates.yml -e openshift_hosted_registry_cert_expire_days=${days} -e openshift_ca_cert_expire_days=${days} -e openshift_master_cert_expire_days=${days} -e etcd_ca_default_days=${days} -e expire_days=${days} -e expire_days=${days} -e openshift_certificate_expiry_fail_on_warn=false -e openshift_redeploy_openshift_ca=true

    time docker exec -it orchestration_manager ansible-playbook -i /tmp/omd/etc_ansible_hosts /usr/share/ansible/openshift-ansible/playbooks/redeploy-certificates.yml -e openshift_hosted_registry_cert_expire_days=${days} -e openshift_ca_cert_expire_days=${days} -e openshift_master_cert_expire_days=${days} -e etcd_ca_default_days=${days} -e expire_days=${days} -e expire_days=${days} -e openshift_certificate_expiry_fail_on_warn=false -e openshift_redeploy_openshift_ca=true

    ###############################################################
    # Update the ca certs in the kubeconfig files
    ###############################################################

    oc serviceaccounts create-kubeconfig node-bootstrapper -n openshift-infra --config /etc/origin/master/admin.kubeconfig > /tmp/omd/bootstrap.kubeconfig

    ssh controller-1.chassis.local cp /etc/origin/master/admin.kubeconfig /etc/origin/node/bootstrap.kubeconfig
    ssh controller-2.chassis.local cp /etc/origin/master/admin.kubeconfig /etc/origin/node/bootstrap.kubeconfig

    for node in $blades; do
        scp /tmp/omd/bootstrap.kubeconfig /etc/origin/node/bootstrap.kubeconfig
    done

    scp  /tmp/omd/bootstrap.kubeconfig controller-1.chassis.local:/etc/origin/master/bootstrap.kubeconfig   
    scp  /tmp/omd/bootstrap.kubeconfig controller-2.chassis.local:/etc/origin/master/bootstrap.kubeconfig   
fi

###############################################################
# Update the node kubelet certs
###############################################################


for node in $(oc get nodes |awk 'NR>1'|awk '{print $1}'); do
    echo "=================================================================="
    echo "Renew Cert on node: $node"
    echo "=================================================================="

    echo "   Remove /etc/origin/node/certificates/kubelet-server-current.pem"
    ssh "${node}" rm -f /etc/origin/node/certificates/kubelet-server-current.pem
    echo "   Remove /etc/origin/node/certificates/kubelet-client-current.pem"
    ssh "${node}" rm -f /etc/origin/node/certificates/kubelet-client-current.pem

    if [[ $update_controllers == 1 ]]; then
        echo "   Move client-ca"
        ssh "${node}" mv /etc/origin/node/client-ca.crt{,.old}
        echo "   Move node.kubeconfig"
        ssh "${node}" mv /etc/origin/node/node.kubeconfig{,.old}
    fi
        
    echo "   Restart origin-node container"
    ssh "${node}" systemctl restart origin-node &
    
    ((exists=0))
    echo "   Approve outstanding CSR's for node $node ..."
    while [[ $exists != 2 ]]; do
       outstandingCerts=$(oc get csr | grep Pending)
       if [[ "$outstandingCerts" != "" ]]; then 
           oc get csr | grep -E Pending | awk '{print $1}' | xargs oc adm certificate approve
       fi

       ((exists=0))
       ssh "${node}" "ls -lq /etc/origin/node/certificates/kubelet-server-current.pem 2>&1" > /dev/null
       if [[ $? == 0 ]]; then ((exists=exists+1)); fi
       ssh "${node}" "ls -lq /etc/origin/node/certificates/kubelet-client-current.pem 2>&1" > /dev/null
       if [[ $? == 0 ]]; then ((exists=exists+1)); fi

       if [[ $exists != 2 ]]; then sleep 1; fi
    done

    # wait for the restart origin-node call to finish    
    wait
    
    sleep 10

    echo "   Wait for node $node to return to Ready ..."
    nodeReady=$(oc get nodes | grep -E "${node}" | awk '{print $2}')
    while [[ "$nodeReady" != "Ready" ]]; do
        sleep 1
        nodeReady=$(oc get nodes | grep -E "${node}" | awk '{print $2}')
    done
done    

echo "================================================================="

sleep 10

oc get nodes
while [[ $? != 0 ]]; do
  sleep 5
  oc get nodes
done

###############################################################

echo "================================================================="

oc delete pods -n kube-service-catalog -l app=apiserver
oc delete pods -n kube-service-catalog -l app=controller-manager

(( count=1 ))

    echo "================================================================="

    x=$(( x + 1 ))

    if (( x % 40 == 0 )); then
        oc delete pods -n kube-service-catalog -l app=apiserver
        oc delete pods -n kube-service-catalog -l app=controller-manager
    fi

    oc get nodes
    if [[ $? != 0 ]]; then
        (( count=1 ))
    fi

    echo "================================================================="
    echo "Waiting for services to restart and stabilize"
    
    if (( count != 0 )); then
        oc get pods --all-namespaces | grep -E "Pending|Crash|0/1" | grep -E -v "ExitCode|helper|partition-"
        sleep 1 
    fi

    tmp=$(oc get pods | grep Error | grep deploy | awk '{print $1}')
    if [[ "$tmp" != "" ]]; then
        for podName in $tmp; do 
            oc delete pod "$podName"
        done  
    fi

    if [[ $x -gt 240 ]]; then

    fi

# Un-Pause orchestration-manager processing
###############################################################

ssh controller-1.chassis.local rm /tmp/omd/pause
ssh controller-2.chassis.local rm /tmp/omd/pause

###############################################################

goodCerts=0;
warnCerts=0;
expiredCerts=0;

warnDays=60
warnAge=$((60 * 60 * 24 * warnDays))
now=$(date +%s)

Workaround for reinstalling the OpenShift cluster

If your VELOS system is affected by this issue, you can work around this issue by reinstalling the OpenShift cluster on the VELOS system. You must first shutdown all tenants on the system by setting their running-state to provisioned, then use the touch /var/omd/CLUSTER_REINSTALL command as root on the active system controller to reinstall the Openshift cluster. After the cluster reinstall is complete, you should disable and re-enable all chassis partitions before setting the running-state of all tenants back to deployed to ensure they have restarted correctly after the cluster rebuild. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure rebuilds the OpenShift cluster causing tenants running in the cluster to restart.

  1. Before reinstalling the OpenShift cluster, set the running-state of deployed tenants to provisioned in all chassis partitions. To change the running-state of a tenant, log in to the chassis partition CLI where the tenant resides.
  2. Enter the following command:

    config

  3. To set the tenant running-state to provisioned, use the following command syntax, where <tenant_name> is the name of the tenant:

    tenants tenant <tenant_name> config running-state provisioned

    Repeat this step for all other tenants in this chassis partition.

  4. To commit the change and exit, enter the following command:

    commit and-quit

    Repeat steps 1 through 4 for the tenants in the other chassis partitions.

  5. Log in to the active system controller as root.
  6. Force the VELOS system to reinstall the OpenShift cluster by entering the following command:

    touch /var/omd/CLUSTER_REINSTALL

    The VELOS system begins the OpenShift cluster reinstallation process. This operation can take 90 minutes or more to complete.

    In order to check the progress of the rebuild, you can run the following command:
    tail -f /var/log/openshift.log
    The rebuild is complete after approximately 90 minutes and the output will be similar to:
    "Blade 1 is ready in openshift cluster."

  7. After the OpenShift cluster installation is complete and all pods are running, you need to disable the chassis partitions and re-enable them. Log in to the system controller as root.
  8. To enter the system controller CLI, enter the following command:

    su admin

  9. Enter the following command:

    config

  10. To disable a chassis partition, use the following command syntax, where <partition_name> is the name of the chassis partition:

    partitions partition <partition_name> config disabled

    Repeat this step for all chassis partitions.

  11. To commit the change, enter the following command:

    commit

  12. Enter the following command:

    exit

  13. Once all the chassis partitions have been disabled, re-enable them using the following command syntax for each chassis partition, where <partition_name> is the name of the chassis partition:

    partitions partition <partition_name> config enabled

  14. To commit the change and exit, enter the following command:

    commit and-quit

  15. To exit the system controller CLI, enter the following command:

    exit

  16. Check to see that all pods have started successfully and are running, by entering the following command:

    kubectl get pods --all-namespaces

  17. Once all pods are up and running, change the running state of all tenants back to deployed; to change the running state of a tenant, log in to the chassis partition CLI where the tenant resides.
  18. Enter the following command:

    config

  19. To set the tenant running state to deployed, use the following command syntax, where <tenant_name> is the name of the tenant:

    tenants tenant <tenant_name> config running-state deployed

    Repeat this step for all other tenants in this chassis partition.

  20. To commit the change and exit, enter the following command:

    commit and-quit

    Repeat steps 17 through 20 for the tenants in the other chassis partitions.

Workaround for expired apiserver certificates

If the show_certs.sh script reports that the apiserver certificates are expired, they can be renewed without reinstalling the entire OpenShift cluster. To renew expired apiserver certificates, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the active system controller as root.
  2. Enter the following command:

    docker exec -it orchestration_manager ansible-playbook -v -i /tmp/omd/etc_ansible_hosts playbooks/openshift-service-catalog/config.yml

  3. This command takes about five minutes to run to completion.

Additional Information

  • It shouldn't be a problem if the tenant is stuck in a stopping state. That's happening because Kubernetes cannot talk to the kubelet on the blades due to the expired certificates.
  • From ConfD's perspective, the tenant is in provisioned state.
  • When you perform the OpenShift reinstall procedure, the tenant's pod and qemu-kvm process should go away.
  • When you set the tenant back to deployed after the OpenShift rebuild, it should start up as normal.
  • Problems can arise if the tenant is in a deployed state from ConfD and you then perform the OpenShift reinstall. In this scenario, you need to revert the tenant back to provisioned, then deploy it again.
