Topic

This article discusses the hardware requirements for hosting each version of BIG-IP Virtual Edition (VE) on the various supported private cloud platforms, such as VMware, KVM, and Microsoft Hyper-V.

For information about the requirements to host BIG-IP VE on public cloud platforms, such as Google Cloud, Amazon Web Services (AWS), and Microsoft Azure, refer to the BIG-IP Virtual Edition Supported Platforms page.

Each supported private cloud platform is available in three different templates or disk sizes. For more information about VE image disk sizing, refer to K14946: Overview of BIG-IP VE image sizes.

Description

Each version of BIG-IP VE requires specific hardware resources for the system that hosts the BIG-IP VE instance. Upgrading your BIG-IP VE version on a system that has inadequate resources to run the newer version may disrupt the upgrade process.

For example, when you upgrade a BIG-IP VE instance from BIG-IP VE 10.2.3 to BIG-IP VE 11.1.0, the resources deployed on the host system, such as CPU and memory may be inadequate for the upgraded BIG-IP VE version to function, even if you can start the system.

CPU1: In BIG-IP VE 11.5.0 and later, you can provision the number of CPUs in the count of 1, 2, 4, or 8. In BIG-IP VE 13.1.0.1 and later with a High Performance license, you can increase the number of CPUs up to 24. For more information, refer to K14356: Determining the maximum allowed throughput rate on the BIG-IP VE system.

RAM2: The minimum memory required for provisioning a single module is 4 GB. The system may require additional memory when you provision multiple modules or when you load additional databases such as GeoIP or DNS Express zone files. For the memory requirements of multi-module-provisioned BIG-IP VE systems, refer to the release notes of each BIG-IP VE version.

RAM3: Each core requires a minimum of 2 GB RAM. For example, a 2-core CPU requires at least 4 GB of RAM. There is no maximum limit on how much RAM you can assign per core, and you can increase the memory assignment as needed.

Note: The BIG-IP system is designed to allocate available resources (for example, CPU, memory) to TMOS when you start the virtual machine instance. If you modify the allocated resources of a BIG-IP VE instance that is shut down, the system will allocate the modified resources to TMOS when you restart the virtual machine instance.

For example, if you deploy the BIG-IP VE instance with 2 CPUs and 4 GB of memory, and you shut down the instance and increase the allocated resources to 4 CPUs and 8 GB of memory, then when you start  the BIG-IP VE instance, the BIG-IP system seamlessly allocates the new resources to Traffic Management Microkernel (TMM) and the host.

Recommendations

When you plan to upgrade the BIG-IP VE system, review the previously shown resource requirement table to ensure that your host system has adequately provisioned resources.

Additionally, take note that the BIG-IP VE license enforces the number of virtual CPUs allowed, based on the maximum allowed throughput rate. For more information, refer to K14810: Overview of BIG-IP VE license and throughput limits.

Alternatively, review the release notes of the appropriate BIG-IP VE version, which provide information on supported platforms and resource requirements in relation to the type of BIG-IP modules in use.
