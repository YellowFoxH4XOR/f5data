Topic

By default, the BIG-IP ASM system does not log security events locally. As a result, there are no security events for SNMP to trap and the system does not send emails.

Description

Starting in BIG-IP ASM 11.6.0, the system does not write security events to syslog by default and it does not log them locally to the /var/log/asm file. This behavior is introduced as part of several enhancements to improve system performance and stability. If you want to collect a log of security events, you should configure remote logging on the BIG-IP ASM system and send those events to a remote log server. If you want to receive emails when BIG-IP ASM security events occur, you should configure the remote log server to trap on those events and generate emails. For more information about configuring remote logging on the BIG-IP ASM system, refer to the Logging Application Security Events chapter of the BIG-IP Application Security Manager: Implementations manual.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

If you have previously configured a BIG-IP ASM system that was running a version prior to BIG-IP ASM 11.6.0 to perform these tasks and then upgraded the system to BIG-IP ASM 11.6.0 or later, the system will no longer send those emails after the upgrade as there are no longer security events to trap.

If you require the system to write security events to the /var/log/asm file via syslog for troubleshooting purposes, you may do so by enabling the send_content_events internal parameter. You should disable this parameter once troubleshooting is complete to prevent a potential decrease in performance. For more information about enabling this internal parameter, refer to the About syslog request format section under the Logging Application Security Events chapter of the BIG-IP Application Security Manager: Implementations manual.
