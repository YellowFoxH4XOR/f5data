Description
BIG-IP reporting log disk usage higher than 80%

  • alertd[PID]: 01100048:0: Log disk usage still higher than 80% after logrotate and 24 times log deletion
  • /var/log disk partition reporting only 7% free
    011d0004:3: Disk partition /var/log has only 7% free
  • very large /var/log/snmpd.log file

Environment

  • BIG-IP
  • Logging files
  • Disk space full
  • BIG-IP enabled SNMP queries

Cause
The /var/log/snmpd.log file is not being rotated

Recommended Actions

Configure the snmpd.log file to be included in log rotation.

To do so, use the following tmsh sys log-rotate command to modify the log-rotate settings.
 
tmsh modify sys log-rotate syslog-include "/var/log/snmpd.log {
    compress
    missingok
    notifempty
    postrotate
        killall -HUP snmpd 2>/dev/null || true
    endscript
}
"
 
In addition, you can restart snmpd to restarts the snmpd.log file.
bigstart restart snmpd
