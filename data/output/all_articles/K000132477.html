K000132477: Azure VMs lose their IP configuration after being stopped (shutdown)

Type
Support Solution
Published
2023-02-09
Updated
2023-02-10
Source
https://my.f5.com/manage/s/article/K000132477

Description

Azure VMs lose their IP configurations after being shut down (stopped) and booted (started) again. The issue only happens when both VMs running Cloud Failover Extension are shut down (stopped) at the same time, then booted (started) again.


Environment

Big-IP Azure


Cause

IP addresses can become disassociated from Big-IP Azure VMs that use CFE (Cloud Failover Extension) when each member of the device group are simultaneously shut down (stopped).


Normally, when the active unit is stopped it disassociates all floating IPs (IPs with a traffic-group designation) in the Azure VM settings using the Cloud Failover Extension. The peer device will take over the active role and reassign/associate the floating IPs to the newly active VM.


When both VMs are shut down at the same time, the active unit successfully disassociates the floating IPs, but because the peer is also shutting down it cannot reassign/associate the floating IPs to itself.


When the VMs are again started the floating IPs will remain disassociated from each VM.


Recommended Actions

If you need to shut down all VMs in a failover group, it's recommended to always shut down the standby VM(s) first, and allow ~5 minutes before shutting down the active VM.
