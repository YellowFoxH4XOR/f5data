Known Issue

This is the result of a known issue. Adding an Active Directory alias Service-Principal Name (SPN) will fail when the CIFS virtual service is joined to a domain with an organizational-unit (OU) other than the default of Computers.

When the alias SPN fails, an spnAliasUpdateRaise trap is sent. The show health command will display the spnAliasUpdateRaise message that appears similar to the following example:

System Health Information
Date                     ID      Event                       Description
---------------------------------------------------------------------------------------
Wed Nov 11 16:45:00 2009 (725) - spnAliasUpdateRaise         . global server:
ask.askf5.com (domain: askf5.com)

Note: When using the domain-join command to join the domain, if the OU is not specified, the command defaults to an OU of Computers at the domain’s root.

Note: For information about the active-directory alias or domain-join commands, refer to the ARX CLI Reference Guide.

F5 Product Development tracked this issue as ID 37048 and 336778 and it was fixed in ARX version 5.1.7. For information about upgrading, refer to the ARX Release Notes.

Workaround 

To use an alias SPN, when joining the virtual service to the domain, only use the default organizational unit of Computers.

To clear the spnAliasUpdateRaise condition caused by the failed alias SPN, you must reload the ARX system after removing the failed alias SPN using the no active-directory alias <Alias_Name> command.
