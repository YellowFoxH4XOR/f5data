K000146670: HTTP Load Balancer cannot be modified due to Expired Certificate

Applies to

Source

What Happened?

You are trying to modify a HTTP Load Balancer but any changes are rejected upon save due to an expired certificate.  The XC console presents an error such as:

 

  • ReplaceResource: Failed transaction handling http_loadbalancer: STM Error: Applying transaction function: Failed to configure TLS for VH of HTTP LB example-lb: Failed to validate TLS Cert Parameters for example-lb: Certificate is invalid: certificate 0 is only valid between 2024-08-09 00:00:00 +0000 UTC and 2025-08-09 23:59:59 +0000 UTC

Environment

  • Distributed Cloud (SaaS)
  • F5® Distributed Cloud Load Balancer

Resolution/Answer

You are unable to modify your Load Balancer if the certificate has expired. If the certificate is expired or bad, then you can't modify the LB settings.

There are two supported remediation options:

  1. Update the certificate object. Change the current expired cert to a valid one.
    1. A self-signed certificate is OK to use, as long as the LB domain matches the cert CN or SAN.
  2. Recreate the load balancer. If updating the certificate object is not possible, you can delete and recreate the LB using the same configuration by either method below.  Bear in mind that you will need a valid certificate to create the new LB.
    1. Replicate the LB using the Clone function in the Console.  The cloned LB will not be saveable with the same configuration (domain) if assigned the same VIP/listener.  To work around this, either assign the cloned LB a different VIP for advertisement, or first set the clone to "do not advertise", delete the original, then advertise the clone on the original VIP.
    2. Manual recreation:
      1. Export or copy the LB’s JSON configuration.
      2. Delete the existing LB.
      3. Clean up the JSON to remove invalid or corrupt configurations.
      4. Create a new LB through the UI.
      5. Paste the corrected JSON configuration into the new LB.\

If LB is using Inline Certificate (Legacy) and it expired you need to replace following lines in JSON in order to make copy of that LB use uploaded TLS Certificate object instead of Inline Certificate. Use below sample, but remember to keep original default security and mtls settings:

Part of JSON with Inline certificate:

      "tls_parameters": {
        "tls_config": {
          "default_security": {}
        },
        "tls_certificates": [
          {
            "here is expired certificate string": {}
          }
        ],
        "no_mtls": {}
      },

It has to be replaced with following lines:

      "tls_cert_params": {
        "tls_config": {
          "default_security": {}
        },
        "certificates": [
          {
"tenant": "tenant-name",
"namespace": "namespace",
"name": "new TLS certificate name",
"kind": "certificate"
          }
        ],
        "no_mtls": {}
      },
