Topic

The timestamps option, specified in RFC1323, allows a TCP connection to include timestamps in its segments. This option is used to perform two functions: Round-Trip Time Measurement (RTTM) and Protect Against Wrapped Sequences (PAWS).

Note: Because the timestamps option adds 12 bytes to the 20-byte TCP header, less data can be transmitted in each TCP segment when this option is used. This is usually accepted, as the bandwidth saved by reducing unnecessary retransmissions will more than pay for the extra header bandwidth.

On the BIG-IP system, the TCP timestamps option (and the other extensions introduced in RFC1323), can be enabled or disabled in the TCP profile by appropriately configuring the Extensions for High Performance (RFC1323) option. This option is enabled by default.

Because different TCP profiles can be applied to the client and server sides of each virtual server, it is possible for a BIG-IP administrator to create a virtual server where these extensions are enabled only on one side. Assuming a virtual server does not feature these extensions on its client-side, but does on its server-side, and that both the client and the pool member support RFC1323, the following will happen:

  • If the client requests the TCP timestamps option, the virtual server will ignore the request
  • The BIG-IP system will not request the timestamps option to the pool member

Note: Whilst TCP timestamps will be missing, all other extensions introduced in RFC1323 (for example, TCP window scale), will still be present in the server-side TCP connection.

This happens intentionally and is the result of optimizations made at the code level to ensure that the size of IP packets does not vary between the client and the server sides of virtual servers. As a result, unnecessary fragmentation does not occur.
