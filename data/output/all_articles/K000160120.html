K000160120: Ansible UCS Backup Timeout After AS3 Deployment on BIG-IP

Type
Support Solution
Published
2026-02-23
Updated
2026-04-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160120

Description

When AS3 (Application Services 3 Extension) and related iAppLX packages such as f5-service-discovery are installed on BIG-IP systems, automated UCS (User Configuration Set) backups initiated via Ansible using the bigip_ucs_fetch module may fail with timeout errors. The typical error message observed is:

TimeoutError: The read operation timed out (during bigip_ucs_fetch while waiting for the async UCS creation to complete)

This issue occurs because iAppLX packages significantly increase the time required to generate UCS archives, which can exceed the default timeout values configured in both BIG-IP system database variables and Ansible playbook settings.

Environment

  • BIG-IP LTM version 17.5.1 (or other versions with AS3 installed)
  • AS3 (f5-appsvcs) RPM package installed
  • f5-service-discovery iAppLX package installed
  • UCS backups automated via Ansible using the bigip_ucs_fetch module

Cause

The presence of iAppLX packages (such as AS3, f5-service-discovery, Telemetry Streaming, and Cloud Failover Extension) significantly increases the time required to create UCS backups. During UCS creation, the system must build RPM packages for each installed iAppLX application, which can exceed default timeout values on both the BIG-IP system and in the Ansible automation framework.

Answer/Recommended Actions

To resolve UCS backup timeout issues when AS3 and other iAppLX packages are installed, implement the following configuration changes:

On the BIG-IP System:

Increase the timeout values for  iapplxrpm, restjavad, restnoded and icrd

tmsh modify sys db iapplxrpm.timeout value 300
tmsh modify sys db restjavad.timeout value 300
tmsh modify sys db restnoded.timeout value 180
tmsh modify sys db icrd.timeout value 180
tmsh save sys config

Restart the restjavad and restnoded services:

bigstart restart restjavad
bigstart restart restnoded

In the Ansible Playbook:

Set the timeout parameter in the bigip_ucs_fetch task to at least 300 seconds:

Config

- name: Create a new UCS
 f5networks.f5_bigip.bigip_ucs_fetch:
  src: "{{ ucs }}"
  dest: "{{ '/var/tmp/' + inventory_hostname + '/' + ucs }}"
  async_timeout: 300

Configure the Ansible persistent connection timeout in ansible.cfg:

[persistent_connection]
command_timeout=300

Additionally , execute UCS backups sequentially rather than in parallel to avoid resource contention on the BIG-IP system.
