Topic

The BIG-IP Simple Mail Transfer Protocol (SMTP) monitor sends SMTP commands to a mail server and examines the server's response to ensure availability at the application layer. The SMTP monitor may behave differently in some aspects when compared to other monitors, specifically, with regard to determining pool member status, probe management, and the ability to log events.

Description

The SMTP monitor is an External type monitor that checks an SMTP server's response to standard SMTP HELO and QUIT commands. The monitor takes into account both the expected response and the configured timeout period to determine the final status of the pool member. The SMTP monitor program is named smtp_monitor, and can be found in the /config/monitors/builtins directory. F5 recommends that you do not modify this file. The following sections detail the monitor's expected behavior in more detail. 

SMTP command and response sequence

The SMTP monitor sends an SMTP helo command and expects the mail server to reply with code 250. The monitor then sends an SMTP quit command and expects the mail server to reply with code 221. The following sequence details exactly what commands and replies the SMTP monitor expects at the application layer:

helo example.net
250 mail.example.net
quit
221 2.0.0 Bye

Important: The SMTP monitor must be configured to send a Domain name.

Determining pool member status

If a monitored pool member sends an unexpected SMTP response or fails to send an SMTP response, the BIG-IP system will mark the pool member Down at the configured timeout period. This differs from other monitors, such as DNS, that mark pool members down once an unexpected response is received, regardless of the configured timeout. The BIG-IP system will not send new connections to the pool member until the expected SMTP response is received and the pool member status becomes Available. The default SMTP monitor interval is 5 seconds and the timeout is 16 seconds. The following example details how the BIG-IP system uses both the server response and timeout interval to determine the pool member status:

Monitor probes with no response

The SMTP monitor establishes a new TCP connection at the beginning of each monitor interval and sends a TCP FIN packet at the end of each interval to close the TCP connection. This occurs even if the BIG-IP system has not received any response from the monitored host. This differs from other monitors, such as HTTP, that maintain a single TCP connection for the duration of the configured timeout period when no response is received. For more information, refer to K13820: Configuring BIG-IP monitor socket reuse behavior.

Recommendations

  • Set timeout values for SMTP monitors to be three times the interval plus 1 second to ensure that the base monitor has three full requests before declaring a node down.
  • SMTP servers configured to perform SMTP banner checks may provide delayed responses. Consider using a longer interval and timeout for these servers. 
  • The SMTP monitor provides a Debug logging option to assist with troubleshooting monitor failures. The default setting is No. When you set the option to Yes, the system sends additional information to the /var/log/monitors/<monitor_name>-<node_name>-<port>.log file. One log file is created per pool member.
