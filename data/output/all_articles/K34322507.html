K34322507: UDP packets appear to be duplicated on ingress

Type
Support Solution
Published
2020-01-09
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K34322507

Description

UDP traffic may be duplicated after a network issue.

The duplicated packet may have a VIP listed in the f5ethtrailer information. However the initial packet won't have this information. In a packet trace captured with internal TMM info this will appear similar to the following example:

Packet #1:

F5 Ethernet Trailer Protocol
    Low Details
        Type: 1
        Trailer length: 5
        Version: 1
        Ingress: True (IN)
        Slot (1-based): 1
        TMM (0-based): 0
        VIP:

Packet #2:

F5 Ethernet Trailer Protocol
    Low Details
        Type: 1
        Trailer length: 32
        Version: 1
        Ingress: True (IN)
        Slot (1-based): 1
        TMM (0-based): 0
        VIP: /Common/udp-syslog

Environment

  • UDP virtual server

Cause

Packets are duplicated due to a link malfunction in the device that sends traffic to the BIG-IP.

Recommended Actions

Investigate the packet path of the UDP traffic from source to BIG-IP, to determine where packets are duplicated.

Additional Information

The full f5ethtrailer info is available on the duplicated packet because there is an existing connection in TMM's connection table as a result of the first packet. On the first packet received, there is no established flow so the f5ethtrailer detail is not complete. This difference in the f5ethtrailer may cause the BIG-IP to be suspected as the malfunctioning system, but this is intended behaviour.
