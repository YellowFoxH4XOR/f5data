K000092916: How BIG-IP will respond to client traffic when members of gateway pool are not available?

Type
Support Solution
Published
2022-12-02
Updated
2022-12-02
Source

Description

BIG-IP is configured with a wildcard virtual server and has gateway pool configured as the next hop for the 10.122.0.0/16 network.


[root@bigip:Active:Standalone] config # tmsh list ltm virtual

ltm virtual gateway-vip {

   creation-time 2022-12-01:06:59:18

   destination 0.0.0.0:any

   ip-forward

   last-modified-time 2022-12-01:07:51:20

   mask any

   profiles {

       fastL4 { }

   }

   serverssl-use-sni disabled

   source 0.0.0.0/0

   translate-address disabled

   translate-port disabled

   vs-index 4

}


[root@bigip:Active:Standalone] config # tmsh list ltm pool

ltm pool gateway-pool {

   members {

       10.121.157.5:any {

           address 10.121.157.5

           session monitor-enabled

           state down

       }

   }

   monitor gateway_icmp

}


[root@bigip:Active:Standalone] config # tmsh show ltm pool

The client machine (Ubuntu in this case) has a route to 10.122.0.0/16 via BIG-IP self-IP.


root@ubuntu-server:~# ip route

10.122.0.0/16 via 10.121.157.10 dev Internal


root@ubuntu-server:~# ip a

Internal: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000

   link/ether 00:50:56:bd:b7:e0 brd ff:ff:ff:ff:ff:ff

   inet 10.121.157.2/27 brd 10.121.157.31 scope global Internal

      valid_lft forever preferred_lft forever

   inet6 fe80::250:56ff:febd:b7e0/64 scope link

      valid_lft forever preferred_lft forever


[root@bigip:Active:Standalone] config # tmsh list net self

net self 10.121.157.10/27 {

   address 10.121.157.10/27

   allow-service all

   floating enabled

   traffic-group traffic-group-1

   unit 1

   vlan Internal

}


When the Ubuntu machine tries to connect to a host in the 10.122.0.0/16 subnet, BIG-IP receives the traffic but replies back as follows.


UDP:


10.121.157.2.48861 > 10.122.1.1.https: UDP, length 2 in slot1/tmm0

10.121.157.1 > 10.121.157.2: ICMP net 10.122.1.1 unreachable, length 36 (tos 0x0, ttl 64, id 1060, offset 0, flags [DF], proto UDP (17), length 30)


ICMP net 10.122.1.1 unreachable being generated by BIG-IP self-IP.


TCP:


10.121.157.2.58898 > 10.122.1.1.https: Flags [S], cksum 0xd322 (correct), seq 2629758533, win 64240, options [mss 1460,sackOK,TS val 2079512625 ecr 0,nop,wscale 7], length 0 in slot1/tmm0

10.122.1.1.https > 10.121.157.2.58898: Flags [R.], cksum 0xb310 (incorrect -> 0x8a07), seq 0, ack 2629758534, win 0, length 0 out slot1/tmm0 lis=/Common/gateway-vip port=1.1 trunk= flowtype=65 flowid=4000013C9280 peerid=0 conflags=4000E24 inslot=0 inport=0 haunit=1 priority=0 rst_cause="[0x2f548aa:8387] No available egress pool member"

10.121.157.1 > 10.121.157.2: ICMP net 10.122.1.1 unreachable, length 36 (tos 0x10, ttl 64, id 22655, offset 0, flags [DF], proto TCP (6), length 60)


TCP RST with "No available egress pool member" cause + ICMP net 10.122.1.1 unreachable being generated by BIG-IP self-IP.


Environment

  • Static route for a host or network using gateway pool.
  • Virtual server with no pool attached.
  • Gateway pool marked down by the health monitor.

Cause

Expected behavior.


 Recommended Actions

None. This is just an informational article.
