Description

After upgrading to version 14.1.4. The CLI prompt shows localdbmgr down

  •  The show /sys service localdbmgr show the following output:
           localdbmgr down, waiting for mysql to release running semaphore
  •  The show /sys service mysql show the following output:
           mysql down, DB Volume script failed (Cannot create volume).
  •  The following output is found in /var/log/mysql.out:
notice boot_marker : ---===[ HD1.1 - BIG-IP 14.1.4 Build 0.0.11 ]===---
-- start DB Volume script --
info: Creating database volume ('mysqldb' owned by 'ASWADB')
info: tm_install::DataPlane::DataPlane_volume_add -- volume type direct chosen to match active control plane.
error: status 1280 returned by command: /usr/sbin/lvcreate --yes -L 12582912K -n set.1.mysqldb vg-db-vda
info: >++++ result:
info:   Volume group "vg-db-vda" has insufficient free space (1981 extents): 3072 required.
info: >----
error: Disk full (volume group). See SOL#10636
error: Could not create private volume 'mysqldb', size 12582912 KiB; rc=1
-- Cannot create volume
-- DB Volume script failed --
-- error '255' and message: 'Cannot create volume'
ERROR! MySQL server PID file could not be found!
 

Environment

  • vCMP Guest
  • mysql
  • Upgrade
  • localdbmgr

Cause

The database volume that mysql uses can not be created due to insufficient disk space.

Recommended Actions

  1.  Delete any unused volume partitions from the system, first list all available images with the "show /sys software" command: 
    show /sys software

--------------------------------------------------------
Sys::Software Status
Volume  Slot  Product  Version   Build  Active  Status

--------------------------------------------------------
HD1.1      2   BIG-IP   14.1.4  0.0.11     yes  complete
HD1.2      2   BIG-IP 14.1.2.6   0.0.2      no  complete
  2.  To delete the unused volume use the command "delete /sys software volume <volume>". For instance, to delete volume HD1.2, the command is "delete /sys software volume HD1.2"
     
  3. If deleting unused volume partitions doesn't solve the issue, add more CPU cores to the guest. Refer to the "Additional Information" portion of this article for more information on adding more CPU cores to a vCMP guest.
