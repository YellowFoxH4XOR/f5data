K10437: Removing a share after performing a storage removal may cause ARX to core and reboot

Known Issue

Under certain conditions, removing a share after performing a storage removal can cause the virtualization system (dNAS) to fault, forcing the ARX system to reboot. In a redundant pair configuration, the fault will cause each ARX system to alternately core and failover until the bounce limit is reached.

F5 Product Development tracked this issue as ARX ID 35486 and it was fixed in ARX version 5.0.5. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in a hotfix available for ARX version 4.1.1. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this article number and ARX ID 35486.

Workaround

A workaround is available. Contact F5 Technical Support for assistance in resolving the issue.
