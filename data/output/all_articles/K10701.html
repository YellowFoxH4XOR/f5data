Known Issue

This is the result of a known issue. Adding a static ARP entry for a multicast address causes the TMM process to produce a core file and restart. For example, the following bigpipe command will create a static ARP entry for multicast IP address 224.0.0.5, and cause the TMM process to produce a core file:

bigpipe arp 224.0.0.5 1:2:3:4:5:6

Note: Defining a static ARP entry for a multicast IP is an invalid action and should not be allowed by the BIG-IP system.

F5 Networks Product Development is tracking this issue as CR131622.

This issue does not exist in BIG-IP version 10.1.0 or later.

Workaround

If you have created a static ARP entry for a multicast address, delete the entry using the bigpipe arp <ip_addr> delete command.
