Issue

Error Message

VCIFS-1-ERR-DISPTMOTEM:: No response from fastpath (Internal IP) for xid 0xf0006 after 60 secs; filer address (Filer IP).

In this error message, note the following:

  • <Internal IP> is an IP used by ARX for internal systems
  • <Filer IP> is the filer for which ARX is attempting to create the connection

For example:

VCIFS-1-ERR-DISPTMOTEM:: No response from fastpath 169.254.6.128 for xid 0xf0006 after 60 secs; filer address 10.10.10.100.

Message Location

You may encounter this message in the following location:

  • The ARX syslog

Description

This message occurs when the following condition is met:

  • The managed filer reuses a File ID (FID) on the same TCP stream.

If the FID is not unique in a TCP stream, you are experiencing what the ARX system considers a Filecache back-end collision.

The FID is a file handle, and the filer assigns each FID and represents an open file on the that filer. It is specifically mentioned in CIFS specification MS-CIFS Section 2.2.1.6 that a FID must be unique across the entire TCP stream. A FID returned from an open or create operation must be unique within an SMB connection and available to all SMB sessions within the same SMB connection.

Additionally, the system logs an error message in the ARX fastpath log that appears similar to the following example:

NET_APP-2-DBG-DEBUG_TRACE_MESSAGE:: cifs_filecache.c:830:  cifsFileInfo_New: Filecache backend collision, fid: 354, fid2: 8    , client: 192.168.10.10

Note: The fastpath log file is included in an ARX system diagnostic information file. The fastpath log file is located in the /acopia/var/log directory of the diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Technical Support.

Impact

The client connection attempt times out.

Recommended Actions

The collusion is due to the source filer issue. For assistance, refer to your filer's vendor support.

When you experience a Filecache back-end collision, the file vendor may request further information. You may assist with troubleshooting by taking a packet capture at a time that coincides with the fastpath log message.

When reviewing the capture, review the NT Create AndX Requests for the open file calls closest to the time that the fastpath messaged logged the failure.  If a file that is opened is given the FID of X, check if that FID is given to another file that is opened before the previous file is closed.

When reviewing the second open request, you can see the difference in file names and what file was given the FID first. If you traverse through the packet, you will see similar information in the following example:

REQ: NT Create AndX Request, FID: 0x0001, Path: \example\web\content\examplefile\Logs\Import.log
REQ -> SMB -> NT CREATE ANDX REQUEST -> [FID: ..... ]
FID: 0x0001 (\example\web\shared\example\navbars\nav-div.gif)

In the example, nav-div.gif is the original file that received FID 0x0001, but is also given to the Import.log file.
