K000092631: Data Mover lock-up causes application traffic impact and tenant deploy failures

Type
Support Solution
Published
2022-11-15
Updated
2026-03-02
Applies to

  • VELOS Platforms
  • F5OS
  • rSeries 5000
  • rSeries 12000
  • rSeries 10000
Source
https://my.f5.com/manage/s/article/K000092631

Description

  • Impact to BIG-IP tenant virtual server traffic.
  • Pool member health monitors fluctuate up and down, or remain down.
  • LACP LAGs may go down.
  • Depending on which Data Mover (DM) is impacted, a subset of the BIG-IP tenant TMMs will no longer transmit packets. The LACP daemon will be unable to transmit its PDUs.

You may see log messages as the example below in /var/F5/partitionX/log/velos.log :
  blade-1(p1) dma-agent[10]: priority="Alert" version=1.0 msgid=0x4201000000000129 msg="Health monitor detected DM Tx Action Completion ring hung." ATSE=0 DM=2 OQS=3.
  blade-1(p1) dma-agent[10]: priority="Info" version=1.0 msgid=0x4201000000000135 msg="Health monitor DM register dump requested.".
  blade-1(p1) dma-agent[10]: priority="Info" version=1.0 msgid=0x4201000000000137 msg="Health monitor DM register dump complete." FILE="agent-dump-1666310215.txt".

After encountering this, subsequent attempts to deploy a tenant may fail until the blade or the appliance is recovered, since the locked-up Data Mover is unable to free the memory it is holding for the impacted tenants.

 

Environment

  • Data Mover
  • BX110
  • r5000

Cause

ID1128765, ID1783685

 

Recommended Action

To recover a blade on the VELOS chassis, determine which blade is affected by looking at the start the following dma-agent log message in /var/F5/partitionX/log/velos.log - where X is the partition number.
blade-1(p1) dma-agent[10]: priority="Alert" version=1.0 msgid=0x4201000000000129 msg="Health monitor detected DM Tx Action Completion ring hung." ATSE=0 DM=2 OQS=3.

Then, reboot the affected blade. Once the blade boots up, the tenants should run and pass traffic normally.
 
To recover the appliance, reboot the appliance via console or SSH session using the root or superuser credentials.

For VELOS chassis, if the blade cannot be rebooted immediately, it may be possible to mitigate the problem for a multi-slot tenant by disabling the impacted slot to steer traffic to the remaining slots that are still healthy:
  An example of disabling BIG-IP tenant slot 1
  # tmsh modify sys cluster default members { 1 { disabled } }

 

Additional Info


Note: Reducing the use of connection mirroring, especially for standard virtual servers, should reduce the likelihood of encountering this issue.
