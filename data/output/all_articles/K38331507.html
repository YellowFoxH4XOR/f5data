Description

You are trying to generate a UCS backup file and you notice that they are larger than usual.  You may notice that /var might run out of free disk space. The BIG-IP is or has been provisioned in the past with APM module.

To confirm that you may be running into this problem, you run the following command and notice and output similar to this one: du -a /var | sort -n -r | head -n 10

You follow the following knowledge article to extract the UCS file and notice that /var/tmp/filestore_temp/files_d/Common_d/epsec_package_d is taking the largest disk space:

K12278: Removing non-essential files from a UCS when disk space errors are encountered

Environment

  • BIG-IP
  • UCS backup file is large
  • APM is or has been provisioned in the past.

Cause

When APM is or has been provisioned, it will include all EPSEC files, including the ones that are no longer in use. All of them are added to the UCS backup making it unnecessarily large. This behavior will persist even when APM has been un-provisioned if those EPSEC files have not been manually removed.

Recommended Actions

Perform the following recommended actions:

  • Always perform proper housekeeping of installation files on the BIG-IP system. This includes removing EPSEC files that are no longer required. Note that you can upload an EPSEC file previously deleted, to the BIG-IP system again if it is required to rollback a configuration.
  • In particular, you should perform EPSEC file housekeeping before events such as de-provisioning BIG-IP APM, taking a UCS backup, and so on. You can do so using the Configuration utility or tmsh (tmos)  K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system.
  • You should also view and verify that EPSEC files are indeed included in the UCS archive. To do so, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive. You can use the information in the article to exclude EPSEC files from the UCS archive.

  • Avoid removing EPSEC files directly from the command line. When you do so, references to the files are not updated in the BIG-IP configuration files. For example,

    rm <EPSEC filename>

    If you must do so, with no other options available, such as to fix a configuration load issue, consider instead moving the files to another directory such as /shared/tmp. Perform a configuration reload or reboot during a maintenance window and config sync to ensure the change does not result in configuration issues in the future.

Additional Information

This issue may also result in Config sync issues. For the resolution, refer to the Recommended action section K20341134: Config sync is failing, complaining about epsec files .
