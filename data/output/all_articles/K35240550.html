Description

Attack signature update failed with following error in the GUI 
"Installation error: Live Update file could not be loaded"

Following error seen in /var/log/asm :
crit perl[17043]: 01310027:2: ASM subsystem error (apply_asm_attack_signatures,F5::LiveUpdate::PayloadHandler::clean_fail): Fail load update files: Process size (508792832) has exceeded max size (471859200)

Following error seen in /var/log/tomcat/liveupdate.log :
ERROR System:37 - Error executing the following command: '/usr/share/live-update/bin/apply_asm_attack_signatures {"filename":"/var/cache/tomcat/temp/Live-Update4487483000787774445/RPMS/packages/current_update_file.enc","payloadDirectory":"/var/cache/tomcat/temp/Live-Update4487483000787774445/PAYLOAD","isScheduled":false,"sigfile_status_update_mode":"Manual","staging":false,"update_type":"asm-attack-signatures","is_genesis_file":false} '

Environment

  • ASM Signatures
  • live update
Cause

This is likely due to the bug tracked in ID921697

Recommended Actions

Apply the following workaround to increase the MaxMemorySize for the ASM Config Server to 750MB:
IMPORTANT: This workaround should be applied during a maintenance window because restarting ASM will take the system offline for few moments. 
  1. Take backup of /etc/ts/tools/asm_config_server.cfg:

    cp /etc/ts/tools/asm_config_server.cfg /etc/ts/tools/asm_config_server.cfg.bak

  2. Open file /etc/ts/tools/asm_config_server.cfg with preferred text editor (ex: nano or vi)
  3. Increase the value of `MaxMemorySize` from 471859200 (450MB) to 786432000 (750MB)
  4. Restart ASM:

    bigstart restart asm
