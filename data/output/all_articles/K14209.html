Topic

Summary

When the ARX system performs migration for a multiprotocol namespace, you may encounter a cross device boundary migration failure.

Description

When the ARX system performs a migration for a multiprotocol namespace, ARX creates a hard link to the source file from the .acopia folder on the source share. The ARX system performs this action to prevent the filer from generating file names that include invalid characters in one of the protocols. However, when the .acopia folder is considered a cross device boundary, issues may occur when ARX creates the hard link on the source share.

For example, on a Netapp, this issue may occur when importing at the volume level instead of the Qtree level. When the ARX system attempts to connect the hard link to the .acopia directory (located in the volume root, not the Qtree root), the filer considers this to be a cross device boundary. On an EMC Celerra, this issue may occur at the filesystem root level when tree Quotas have been created in the filesystem as well. When the hard link connection is attempted to the .acopia directory (located in the filesystem root, not the Tree Quota root) the filer considers this to be a cross device boundary. At this point, the migration will fail from the source filer.

Example ARX syslog failure message:

POLICY_ACTION-7-ERR-POLICY_ACTION_FAILED:: Rule [example_nfs_cifs:/team:drain_share_rule_for_share_emc_example]: Migration of file [/vol/local/Linux/share/info/w/wvt] from share [emc_example] to share [isilon_example] failed. Attempt [1] encountered an error [The DME was unable to complete an NFSv3 transfer request [-232] (NFS3ERR_XDEV from source)]. Maximum number of attempts is set to [1]. File could not be migrated within the maximum attempts allowed.

Recommendations

If you experience a failure due to a cross device boundary, you may complete the import by performing one of the following options:

  • Split the namespace into a CIFS or NFS only.
  • Change the definition point to the Qtree or Tree Quota level and restart the migration.

When attempting to complete either task, F5 recommends contacting F5 Support for assistance.
