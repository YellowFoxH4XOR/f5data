Description

Unexpected failover occurs due to sod killing TMM process (including vCMP host, guest and BIG-IP platforms).

You can see similar logs in /var/log/ltm:

notice sod[<PID>]: 01140041:5: Killing tmm.0 pid <PID>.
warning sod[<PID>]: 01140029:4: HA daemon_heartbeat tmm fails action is go offline down links and restart.

You might find core file generated around that time with/without SIGABRT log in /var/log/tmm:

ls -al /shared/core/

/var/core:
total 61016
     8 drwxrwxrwt  2 root        root                   4096 MMM DD HH:MM 2021 .
     8 drwxr-xr-x 34 root        root                   4096 MMM DD HH:MM 2021 ..
 61000 -rw-rw-rw-  1 root        root               72393503 MMM DD HH:MM 2021 tmm.0.bld0.0.7.core.gz

When this issue occurs on vCMP Host, vCMP guests would not notice the incident on the Host, but just lose connection.

 

Environment

  • BIG-IP (including vCMP host and guest)
  • any version
     

Cause

Many possible reasons.
This can cause process in loop due to how you configured
or
Bugs
 

Recommended Actions

To confirm the issue is due to these Bug IDs, please contact F5 support with the following data (from vCMP HOST and GUESTs):

  • QKview (taken within 7 days after the incident) with below command
    qkview -s0
    if you want to generate qkveiw with lowest priority (due to heavy load)
    nice -n 10 qkview -s0
     
  • Tmm core file generated at the time of incident and md5sum for the core

    md5sum /shared/core/<name-of-core-file> >> /shared/core/tmm.md5

  • /var/log tar ball running the following command:

    tar -czpf /var/tmp/"$HOSTNAME"_logfiles.tar.gz /var/log/*
