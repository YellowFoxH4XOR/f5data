Description

The issue is that the Virtual Server will get a packet from the client and forward it to the backend server. The backend server (pool) will respond back to the BIG-IP but the Virtual Server will not forward the response to the client.

Below is an illustration of the mentioned traffic flow.

Client BIG-IP Pool
Client→Virtual Server (BIG-IP) 
  Self-IP (BIG-IP)←Backend server (pool)
  Self-IP (BIG-IP)←Backend server (pool)
Client?Virtual Server (BIG-IP)  

 
It is also seen that the BIG-IP will communicate with the backend server (pool) with a non-floating self-IP. This is decided from SNAT automap configuration on the Virtual Server.

This issue can happen to TCP or UDP traffic.

When a tcpdump is captured, the response packet from the backend server to the BIG-IP will not have a flow ID.

Environment

  • BIG-IP LTM
  • SNAT automap is used
  • BIG-IP will communicate with the backend server (pool) via non-floating self-IP
  • Virtual Server will not forward the backend server (pool) response to client
  • Pcap will show that there is no VIP processing the backend server response
  • Pcap will state that there is no flow ID and peer ID

Cause

The issue is that the BIG-IP have not configured a floating self-IP to communicate with the backend server (pool).

When this happens, the BIG-IP will communicate with the backend server using a self-IP of a vlan but the response is processed by another vlan.

For example, the pool member is reachable via vlan 81, but response comes back to us on vlan 511. As a result it's rejected.

You can read further on SNAT autmap selection here K7336.

Recommended Actions

Ensure that non floating self-IP address has been created to communicate with the backend server (pool member).

  1. On the Main tab, click Network > Self IPs.
  2. Click Create. The New Self IP screen opens.
  3. In the Name field, type a unique name for the self IP address.
  4. In the IP Address field, type an IPv4 or IPv6 address. This IP address should represent the address space of the non-floating self-IP.
  5. In the Netmask field, type the full network mask for the specified IP address.
  6. From the VLAN/Tunnel list, select the VLAN to associate with this self IP address.
  7. From the Traffic Group list, select traffic-group-1 (floating).
  8. Click Finished. The screen refreshes, and displays the new self IP address.
