Known Issue

This is the result of a known issue. Configuring the BIG-IP system to use remote LDAP system authentication may prevent SSH access to a locally authenticated user, such as a root user, and those users previously configured for local authentication only.

When the LDAP server is unreachable and the root user attempts to log in, the following error messages are reported in the /var/log/kern.log file:

bigip SubDomain: REJECTING r access to /lib/tls/libpthread-0.60.so (sshd(21507) profile /usr/sbin/sshd active AUTHENTICATED)

F5 Product Development tracked this issue as CR77638 and it is was fixed in BIG-IP versions 9.3.1 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, Link Controller, or WebAccelerator release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.0-HF1 issued for the BIG-IP version 9.3 software branch. This hotfix, or a later version of the hotfix, is available for download at the F5 Downloads site.

For information about downloading software from F5, refer to K167: Downloading software from F5.

For information about installing a hotfix, refer to K6845: Managing F5 product hotfixes.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

If a BIG-IP system access is required before access to the remote LDAP can be restored, you can re-configure the BIG-IP system to use local authentication. To do so, perform the following procedure:

Note: This procedure resets the BIG-IP system to use local authentication so users can login to the BIG-IP system through SSH, GUI or the Console when access to the LDAP server is not available. If desired, when the LDAP server access is restored, the BIG-IP system will have to be reconfigured to use remote LDAP authentication.

  1. Boot the BIG-IP system into single user mode.

    Note: For information about booting the BIG-IP system into single user mode, refer to K4178: Booting BIG-IP into single user mode.
  2. At the login prompt, log in using the root username and password.
  3. To enable local authentication, set the SystemAuth.source db variable to local by typing the following command:

    bigpipe db SystemAuth.source local

    Note: This command will produce an error because it is unable to connect to the MCPD.
  4. Change directories to the /config directory, by typing the following command:

    cd /config
  5. Use a file editor to open the BigDB.dat file.
  6. Ensure the SystemAuth.source section of the BigDB.dat file has the default=local entry.

    The SystemAuth.source section should appear as follows:

    [SystemAuth.source]
    default=local
    type=enum
    realm=common
    enum=|local|ldap|radius|activedirectory|tacacs|
    display_name=SystemAuth.source

  7. Save the BigDB.dat file.
  8. Activate the SystemAuth.source db key, by typing the following command:

    /usr/bin/tw_activate_keys SystemAuth.source
  9. Use a file editor to open the bigip.conf file.
  10. Delete the entire auth ldap system-auth secton from the file.

    For example:

    auth ldap system-auth {

    bind dn "xxxxxxxxxxxx"
    bind pw "xxxxxxxx"
    login attr "xxx"
    search base dn "xxxxxxxxx"
    servers "xxx.xxx.xxx.xxx"
    }

  11. Save the bigip.conf file.
  12. Change directories to the /config/bigip/auth/pam.d directory by typing the following command:

    cd /config/bigip/auth/pam.d/
  13. Create a symbolic link to the /etc/pam.d/local/system-auth directory by typing the following command:

    ln -f -s /etc/pam.d/local/system-auth
  14. Reboot the system into normal startup by typing the following command:

    reboot
  15. Log in to the Configuration utility.
  16. Click System.
  17. Click Users.
  18. Click Authentication.
  19. Click the Change button.
  20. Select Local from the User Directory drop-down menu.
  21. Click the Finished button.
