Topic

You should consider using this procedure under the following condition:

  • You want to regenerate secure shell (SSH) host keys for reasons of functionality or security.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have command line access to the BIG-IP system.

Description

The SSH host key is used to uniquely identify a given device when an SSH connection is established to that device. You may need to regenerate the SSH host keys for a device if the keys become corrupted or compromised.

Procedures

Generating new host keys

Verifying communication between host and SCCP

Verifying communication between host and AOM

Verifying communication between VIPRION blades

Generating new host keys

To regenerate the SSH host key on a BIG-IP system (with the exception of BIG-IP Virtual Edition), run the following command:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: On VIPRION platforms, you may be disconnected from any open SSH sessions to the BIG-IP system.

/usr/bin/keyswap.sh -genkeys

BIG-IP Virtual Edition

To regenerate the SSH host key on any BIG-IP Virtual Edition, run the following command:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Important: This command requires more than three minutes to complete, and may appear to have stalled. Do not interrupt it.

Note: You may be disconnected from any open SSH sessions to the BIG-IP system.

ifconfig lo:1 netmask 255.255.255.255 ; sleep 5 ; keyswap.sh -genkeys ; sleep 180 ; ifconfig lo:1 netmask 255.255.255.0

Verifying communication between host and SCCP

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: This procedure applies to only BIG-IP platforms that contain a switch card control processor (SCCP). For more information, refer to K9476: The F5 hardware/software compatibility matrix.

After regenerating the SSH host key, it is important to verify that communication between the BIG-IP host and SCCP is functioning correctly. To do so, run the following command:

ssh sccp 'uname -m ; ssh host uname -m'

For versions 11.0.0 and later, the command should return output that appears similar to the following example:

ppc
x86_64

For versions prior to 11.0.0, the command should return output that appears similar to the following example:

ppc
i686

If the appropriate output, shown previously, is not returned for your version, repeat the steps listed in the Generating new host keys section.

Verifying communication between host and AOM

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: This procedure applies to only the 800, 1600, 3600, 3900, 6900, 89xx, 11000, and 11050 platforms which have an Always-On Management (AOM) subsystem that has shell access.

After regenerating the SSH host key, it is important to verify that communication between the BIG-IP host and AOM is functioning correctly. To do so, run the following command:

ssh aom 'uname -m ; ssh host uname -m'

For versions 11.0.0 and later, the command should return output that appears similar to the following example:

mips
x86_64

For versions prior to 11.0.0, the command should return output that appears similar to the following example:

mips
i686

If the appropriate output, shown previously, is not returned for your version, repeat the steps listed in the Generating new host keys section.

Verifying communication between VIPRION blades

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

After regenerating the SSH host key, it is important to verify that communication between VIPRION blades is functioning correctly. To do so, use the following command syntax:

Note: On VIPRION platforms, ensure that all installed blades are online and available (shown as green in the Configuration utility).

ssh slot<X> tmsh list sys db platform.chassis.slot

In the previous syntax, note the following:

  • <X> is the slot number of the blade you want to test.

For example, to test communication to the blade at slot2, you would type the following command:

ssh slot2 tmsh list sys db platform.chassis.slot

This command should return information appropriate to the slot number tested, similar to the following example:

sys db platform.chassis.slot {
    value "2"
}

If the appropriate output, shown previously, is not returned for your version, repeat the steps listed in the Generating new host keys section.
