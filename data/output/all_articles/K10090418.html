Topic

You should consider using this procedure under any of the following conditions:

  • You want to use an iRule to redirect all incoming HTTP virtual server requests to an HTTPS virtual server configured for the same DNS host name or IP address.
  • You want to use an iRule to redirect all incoming HTTP virtual server requests to an HTTPS virtual server configured on a non-standard port.
  • You want to use an iRule to redirect all incoming HTTP virtual server requests to an IPv6 HTTPS virtual server.
  • You want to use an iRule to remove www from the HTTP request and redirect all incoming HTTP virtual server requests to an HTTPS virtual server.

Note: If using this iRule or any iRule with an HTTP::redirect or an HTTP::respond command that redirects HTTP requests based on the content of the request, please reference this Security Advisory: K000137322: BIG-IP iRule or LTM policy may generate multiple HTTP redirect responses

Note: An alternative method for redirecting HTTP requests to HTTPS is to use a local traffic policy. For information about using a local traffic policy to redirect HTTP requests to HTTPS, refer to K26312346: Configuring a virtual server to automatically redirect HTTP requests to HTTPS using a local traffic policy (12.x - 16.x).

Description

The method that F5 recommends for redirecting traffic from an HTTP virtual server to an HTTPS virtual server is to use an iRule. The BIG-IP system comes with a default F5 verified iRule named _sys_https_redirect that is provided for this purpose. You can do one of the following:

  • Configure the HTTP virtual server to use the default _sys_https_redirect iRule.
  • Create a new iRule using the _sys_https_redirect iRule code as a template, and then make changes to the code to suit your environment.
  • Configure a custom iRule, depending on your specific requirements.

For example, you can use a custom iRule to redirect HTTP requests if your HTTPS virtual server uses a port other than the default port 443 or an IPv6 IP address.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP Configuration utility or TMOS Shell (tmsh).
  • You have existing HTTP and HTTPS virtual servers using the same virtual address on your BIG-IP system.

Procedures

Perform one of the following procedures:

  • Use the Configuration utility to apply the default _sys_https_redirect iRule to the HTTP virtual server
  • Use tmsh to apply the default _sys_https_redirect iRule to the HTTP virtual server
  • Configure a custom iRule to redirect to HTTPS on a non-standard port
  • Configure a custom iRule to redirect to an IPv6 HTTPS virtual server
  • Configure a custom iRule to remove www from the HTTP request and redirect to HTTPS

To watch a video demo of these procedures, go to  Configure an HTTP virtual server to redirect to HTTPS using an iRule.

Note: You can associate the default _sys_https_redirect iRule with your virtual server. However, in some cases you may want to create a new iRule by using the _sys_https_redirect iRule code as a template, and then making changes to the code to suit your environment.

Impact of procedure: The system responds to any requests that come to the HTTP virtual server with an HTTP redirect to the HTTPS virtual server.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the HTTP virtual server you want to redirect.
  4. For HTTP Profile (Client), select the HTTP profile you want to use. For example, http.

    Note: For versions prior to to BIG-IP 14.x, set HTTP Profile to the HTTP profile you want to use.

  5. Select Update.
  6. Select the Resources tab.
  7. For iRules, select Manage.
  8. For Available, select _sys_https_redirect and move it to the Enabled list.
  9. Select Finished.

Use tmsh to apply the default _sys_https_redirect iRule to the HTTP virtual server

Note: You can associate the default _sys_https_redirect iRule with your virtual server. However, in some cases you may want to create a new iRule by using the _sys_https_redirect iRule code as a template, and then making changes to the code to suit your environment.

Impact of procedure: The system responds to any requests that come to the HTTP virtual server with an HTTP redirect to the HTTPS virtual server.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Modify the HTTP virtual server that you want to redirect to so that it uses HTTP or the HTTP profile you want by using the following command syntax:

    modify ltm virtual <virtual server name > profiles add { <name of HTTP profile> }

    For example, for an HTTP virtual server named my_http_vs80, enter the following command:

    modify ltm virtual < my_http_vs80> profiles add { http }

  3. Modify the HTTP virtual server that you want to redirect to use the _sys_https_redirect iRule by using the following command syntax:

    modify /ltm virtual <virtual server name> rule { _sys_https_redirect }

    For example, for an HTTP virtual server named my_http_vs80, enter the following command:

    modify /ltm virtual my_http_vs80 rule { _sys_https_redirect }

Configure a custom iRule to redirect to HTTPS on a non-standard port

To use the Configuration utility to create a custom iRule to redirect HTTP requests to HTTPS on a non-standard port and apply the custom iRule to an HTTP virtual server, perform the following procedure:

Impact of procedure: The following procedure contains an example iRule to have the HTTP virtual server respond with an HTTP redirect to the non-standard port used for the HTTPS virtual server. The specific iRule customization may differ for your specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Enter the Name you want for this custom iRule.

    For example:

    redirect_8443

  5. For Definition , enter the following iRules syntax:

    when HTTP_REQUEST {
      HTTP::redirect https://[getfield [HTTP::host] ":" 1]:<destination port>[HTTP::uri]
    }

    For example, if your HTTPS virtual server is configured for a non-standard port or 8443, enter the following iRule:

    when HTTP_REQUEST {
      HTTP::redirect https://[getfield [HTTP::host] ":" 1]:8443[HTTP::uri]
    }

  6. Select Finished.
  7. Go to Local Traffic > Virtual Servers.
  8. Select the HTTP virtual server you want to redirect.
  9. For HTTP Profile (Client) select the HTTP profile you want to use. For example, http.

    Note: For versions prior to BIG-IP 14.x, for HTTP Profile, select the HTTP profile you want to use.

  10. Select Update.
  11. Select the Resources tab.
  12. For iRules, select Manage.
  13. For Available, select the custom iRule you just configured, for example, redirect_8443, and move it to Enabled.
  14. Select Finished.

Configure a custom iRule to redirect to an IPv6 HTTPS virtual server

To use the Configuration utility to configure a custom iRule to redirect HTTP requests to an HTTPS virtual server using an IPv6 IP address and apply the custom iRule to an HTTP virtual server, perform the following procedure:

Impact of procedure: The following procedure contains an example iRule to have the HTTP virtual server respond with an HTTP redirect to the IPv6 IP HTTPS virtual server. The specific iRule customization may differ for your specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Enter the Name you want to use for this custom iRule. For example, redirect_IPv6.
  5. For Definition , enter the following iRule syntax:

    when HTTP_REQUEST {
      regsub -all {:\d*$} [HTTP::host] "" host
      HTTP::redirect https://$host[HTTP::uri]
    }

  6. Select Finished.
  7. Go to Local Traffic > Virtual Servers.
  8. Select the HTTP virtual server you want to redirect.
  9. Select the Resources tab.
  10. For iRules, select Manage.
  11. For Available, select the custom iRule you just configured, for example redirect_IPv6, and move it to Enabled.
  12. Select Finished.

Configure a custom iRule to remove www from the HTTP request and redirect to HTTPS

To use the Configuration utility to configure a custom iRule to remove www. from the HTTP request URL, then redirect the request to an HTTPS virtual server and apply the custom iRule to an HTTP virtual server, perform the following procedure:

Impact of procedure: The following procedure contains an example iRule to have the HTTP virtual server respond with an HTTP redirect to the HTTPS virtual server after removing www. from the HTTP request URL. The specific iRule customization may differ for your specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Enter the Name you want to use for this custom iRule. For example, removewww_redirect.
  5. For Definition , enter the following iRule syntax:

    when HTTP_REQUEST {
      if { ( [string tolower [HTTP::host]] starts_with "www." ) }
      {
        HTTP::redirect "https://[string range [HTTP::host] 4 end][HTTP::uri]"
      }
    }

  6. Select Finished.
  7. Go to Local Traffic > Virtual Servers.
  8. Select the HTTP virtual server you want to redirect.
  9. Select the Resources tab.
  10. For iRules, select Manage.
  11. For Available, select the custom iRule you just configured, for example removewww_redirect, and move it to Enabled.
  12. Select Finished.
