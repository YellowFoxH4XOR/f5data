Known Issue

Attempting to change a variation rule in the BIG-IP AAM policy editor may result in an error message.

This issue occurs when all of the following conditions are met:

  • Existing user-agent definitions are present.
  • You attempt to edit or add an existing or new user-agent definition.

Impact

The attempted change in the policy editor is not saved.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to make the required changes. To edit an existing policy, you must delete the policy, and then add a new policy. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Changing the BIG-IP AAM user agent policy settings

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To delete the BIG-IP AAM user agent policy setting, use the following command syntax:

    modify wam policy Drafts/<Policy Name> nodes modify { <node> { variation modify { user-agent { values delete { "<user-agent-text>" } } } } }

    For example:

    modify wam policy Drafts/MyPolicy nodes modify { Media { variation modify { user-agent { values delete { "Mozilla/2.0 (compatible; MSIE 6.0; Windows NT 5.2)" } } } } }

  3. To add a BIG-IP AAM User-Agent policy setting, use the following command syntax:

    modify wam policy Drafts/<Policy Name> nodes modify { <node>  { variation modify { user-agent { values add { "<user-agent-text>"  { cache-as same } } } } } }

    For example:

    modify wam policy Drafts/MyPolicy nodes modify { Media { variation modify { user-agent { values add { "Mozilla/2.0 (compatible; MSIE 6.0; Windows NT 5.2)"  { cache-as same } } } } } }

  4. When changes are complete, you can publish the policy by using the following command syntax:

    publish wam policy Drafts/<Policy Name>

    For example:

    publish wam policy Drafts/MyPolicy
