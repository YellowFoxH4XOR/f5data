K000164071: HTTPS monitors fail after upgrade to 17.5.1.10, 17.1.3.6, 21.1.0.3, or higher

Type
Support Solution
Published
2026-10-30
Updated
2026-10-30
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000164071

Description

After upgrading from a version lower than 17.5.1.10, 17.1.3.6, or 21.1.0.3 to those versions or higher, HTTPS monitors configured with a Server SSL profile may fail. The monitor may use SSLv3, or it may fail to send a ClientHello, depending on configured cipher suites.


This issue only occurs when in-TMM monitoring is disabled.

Environment

  • BIG-IP
    • Upgrade from version affected by Bug ID 1216053 to a fixed version
  • HTTPS monitor configured with Server SSL profile
    • Server SSL profile has "No TLSv1" option enabled
    • Server SSL profile has "No SSLv3" option disabled
  • In-TMM Monitoring disabled

Cause

The fix to Bug ID 1216053 causes monitors running in bigd to follow the Options field in associated Server SSL profiles.


Bug ID 2707837 documents inconsistent behavior between TMM (including Server SSL profile behavior with normal traffic) and bigd in SSL/TLS protocol selection. TMM fully disables SSLv3 unless it is specifically enabled using Cipher Suites, regardless of profile options. The OpenSSL library used by bigd uses only TLS by default, but does not disable SSLv3, and if any version is disabled it implies disabling higher versions unless all lower versions are disabled as well - so if SSLv3 is not explicitly disabled but TLSv1 is disabled, instead of using TLS 1.2 bigd will attempt to use SSLv3.


Answer/Recommended Actions

  1.  Enable No SSLv3 option on Server SSL profiles when No TLSv1 is enabled.
