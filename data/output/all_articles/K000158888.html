K000158888: Ramcache invalidation during ASM policy apply causes temporary TMM memory reduction

Description

When applying an ASM security policy to a virtual server that has a Web Acceleration profile enabled, administrators may observe a sudden drop in TMM memory usage, specifically in xdata allocation.


Environment

  • BIG-IP ASM / Advanced WAF 
  • Virtual server with ASM security policy attached & Web Acceleration profile enabled


Cause

The xdata subsystem is used by TMM to store cached HTTP objects in ramcache.

When an ASM policy is applied or updated on a virtual server with Web Acceleration enabled, the system invalidates the existing ramcache content.


This invalidation is required to ensure that all cached objects comply with the newly applied ASM policy rules. As a result, cached objects are removed from memory and must be re-cached as new traffic is processed.


During this process, xdata memory allocation drops noticeably, which also results in a reduction of overall TMM memory usage.



Recommended Actions

No action is required. No traffic interruption or functional impact is observed



Additional Information

Logs similar to the following may be observed during the ASM policy apply operation, indicating ramcache invalidation:


asm_config_server.pl|INFO|Invalidate cache for policy <policy_name>


TMM memory statistics collected before and after the policy apply operation typically show a decrease in xdata allocation.
