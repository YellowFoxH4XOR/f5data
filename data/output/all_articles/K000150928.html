Description

I want to know why the HTTP redirect does not work using Safari with any iOS device but it works from any other browser.

Environment

  • F5® Distributed Cloud (XC) HTTP Load Balancer

Cause

Safari directly tries https on http domain, it's in their browser logic.

Answer/Recommended Actions

Investigation on why safari doesn't honor the redirect:

  • Took a PCAP to analyze it and Safari does not proceed with sending GET request on port 80 ( though TCP is connected ) ,
  • Safari directly tries https on same domain ( it will get connected as customer have LBs on port 443 on customer VIP) and send client hello .
  • Tried other options like deleting HSTS file locally cached by Mac etc etc , but in all cases this is the behavior .

To handle the redirect scenario:

Create an HTTP Load Balancer with your domain (example.com) and then add a route redirect in the HTTP Load Balancer to redirect to www.example.com.

This should resolve the issue.
