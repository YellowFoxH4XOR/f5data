Description

Monitor's from some BIG-IP's are timing out, causing the pool member status to flap.

/var/log/gtm
alert gtmd[5311]: 011ae0f2:1: Monitor instance /Common/HTTP DOWN --> UP from 192.168.1.1 (connect: success search result true)
alert gtmd[5311]: 011ae0f2:1: Monitor instance /Common/HTTP UP --> DOWN from 192.168.1.2 (connect: timeout search result false)

Environment

  • BIG-IP DNS
  • Generic hosts are being marked down intermittently
  • Monitor timeout

Cause

Some BIG-IP's are unable to probe the destination

Recommended Actions

  1. Enable debugprobelogging to identify which BIG-IP devices the monitor probe originates from.
    tmsh modify sys db gtm.debugprobelogging value enable
  2. Review /var/log/gtm to identify failed probes and the source BIG-IP device.
  3. Troubleshoot the network connectivity between the BIG-IP device and the Generic Host
  4. If it's not possible to allow network connectivity between all BIG-IP devices and the Generic Host, then configure Prober Pool
    K08433560: Configuring prober pools
  5. Disable debugprobelogging when finished troubleshooting
    tmsh modify sys db gtm.debugprobelogging value disable
 

Additional Information

Any BIG-IP may be selected to probe the Generic Host.
If one or more BIG-IP's are unable to reach the Generic Host, then the monitor probe will fail if selected.
