Description

 

Subsession variable values can get mixed up between APM sessions.
A Per-Request Policy execution may get the value of the subsession variable from a different APM session.
 

Environment

 
  • BIG-IP APM
  • Per request policy with a logon page and variable assign
  • Log subsession and session values using logging agent - %{subsession.logon.last.username} and %{session.logon.last.username}
  • Access APM Virtual Server through two different browsers.
  • For each request, the two variables should match, but sometimes they get mixed up


Cause

 

Subsession variables are referenced in the Per-Request Policy outside of the Subsession without the Session ID.
 

Recommended Actions

 


1. Log a session variable instead of subsession variable

or

If using Guided config:


Unlock the app under GC
Edit the per request policy
Under Subroutine -> Subroutine Settings/Rename
Under Gating criteria --> add perflow.subsession.id
 

or 


Contact F5 Support for an Engineering Hotfix on top of v15.1.8.1

or 

Upgrade to v17.0.0 or later
