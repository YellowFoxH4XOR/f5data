K000162154: how to verify connection idle timeout on CNF after change FastL4 profile on CNF

Description

The article article provide step to verify connection idle timeout after configuration change on CNF.

Environment

  • BIG-IP Next DNS CNF, version 2.1.0
  • FastL4 profile used for DNS virtual server
  • Kubernetes orchestration (kubectl)
  • F5BigContextSecure Custom Resource (CR)
  • YAML configuration for FastL4 profile and virtual server
  • TMM debug container for verification

Cause

N.A

Answer/Recommended Actions

  1. Create a new FastL4 profile with the desired idleTimeout value:

    apiVersion: k8s.f5net.com/v1
    kind: F5BigFastl4Setting
    metadata:
    name: fastl4-5sec
    namespace: f5-cnf
    spec:
    idleTimeout: 5

  2. Update the virtual server YAML (F5BigContextSecure CR) to reference the new FastL4 profile:

    apiVersion: "k8s.f5net.com/v1"
    kind: F5BigContextSecure
    metadata:
    name: virtual
    spec:
    profile: "fastL4"
    fastL4Settings:
    profileName: fastl4-5sec
    # other settings as required

  3. Apply the updated YAML using:
    kubectl apply -f <yaml-file>
  4. Log into the TMM debug container and verify the idleTimeout using:
    /bdt_cli -u -s tmm0:8850 connection list --vs_name <virtual-server-name>
  5. Avoid using YAML output with generation values; always update and apply the default YAML version for configuration changes.

Additional Information

  • Verification should be done using bdt_cli in the TMM debug container, not solely by observing configuration output.
