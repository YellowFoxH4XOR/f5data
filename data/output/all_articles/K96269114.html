Description

After an upgrade or reboot, the logs are not arriving at the remote syslog server.  There are no error messages observed in /var/log/ltm.  You may find that the BIG-IP system is sending the syslogs with the wrong source IP address (either the management IP, when intending the TMM Self IP to be used, or the TMM Self IP, when intending the management IP to be used)

  • Logging to remote syslog server has been configured
  • If remote servers are configured via the remote-servers setting and no local IP defined under the System  ››  Logs : Configuration : Remote Logging
  • If remote servers are configured via the include setting, no localip is defined in the log destination
    sys syslog {
        include "
        destination remote_server {
            udp(\"<remote syslog server IP>\" port (514));
        };
        filter f_alllogs {
            level (debug...emerg);
        };
        log {
            source(s_syslog_pipe);
            filter(f_alllogs);
            destination(remote_server);
        };
        "
    }
 

Environment

  • BIG-IP LTM
  • Remote Syslog Server

Cause

Due to a race condition, syslog-ng may start, before the Management Route or TMM routes have been populated.

Recommended Actions

Verifying that incorrect source address is used

  1. When the destination syslog server does not receive log, check the netstat command output carefully for the syslog server IP address:
    netstat -pan | grep syslog

    The incorrect source IP address is being used (management address is used instead of TMM address, and vice versa):
    udp   0   0   <incorrect_source_ip>:<random source-port>   <Syslog-server-IP>:514   ESTABLISHED <pid>/syslog-ng

  2. Restart the syslog-ng daemon:
    bigstart restart syslog-ng
     
  3. After restart of the syslog daemon, verify the output again:
    netstat -pan | grep syslog

    You should observe the correct source IP (the intended management or TMM address) now being used:
    udp   0   0   <correct_source_ip>:<random source-port>   <Syslog-server-IP>:514   ESTABLISHED <pid>/syslog-ng

Explicitly specifying the source address to be used
If the steps above confirm that incorrect source IP is used, you can rectify it by explicitly specifying the correct source address to use.

  1. If remote servers are configured via the remote-servers setting, specify the correct local IP under the System  ››  Logs : Configuration : Remote Logging
    sys syslog {
        include none
        remote-servers {
            /Common/remotesyslog1 {
                description none
                host 10.0.0.21
                local-ip <correct_source_IP>
                remote-port 514
            }
        }
    }
  2. If remote servers are configured via the include setting, specify localip in the log destination
    sys syslog {
        include "
        destination remote_server {
            udp(\"<remote syslog server IP>\" port (514) localip(\"<correct_source_ip>\"));
        };
        filter f_alllogs {
            level (debug...emerg);
        };
        log {
            source(s_syslog_pipe);
            filter(f_alllogs);
            destination(remote_server);
        };
        "
    }
  3. Perform a reboot and verify that remote syslog server receives logs as expected.
