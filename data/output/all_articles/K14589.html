Known Issue

Managing SSL keys or certificates using the tmsh utility may fail.

This issue occurs when all of the following conditions are met:

  • You configure the BIG-IP system with one or more system folders, in addition to the default /Common folder.
  • You perform one of the following actions that references the system folder path using the tmsh utility:

    • Create an SSL key or certificate
    • Install the PKCS12 file

For example, when you create a 1024-bit SSL key in the /Dome-A system folder (where the folder already exists) with the key1 SSL key using tmsh with the system folder path, the command may appear as follows:

root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# create /sys crypto key /Dome-A/key1.key key-size 1024

The system folders in the tmsh utility are associated with the administrative partitions. For more information about folders and administrative partitions for BIG-IP 11.0.0 through 11.3.0, refer to the Administrative Partitions and Folders chapter in the BIG-IP TMOS: Concepts guide.

Impact

Users are unable to create SSL keys, certificates, or install PKCS12 files with the system folder path using the tmsh utility.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H426998 on the Diagnostics > Identified > Medium screen.
  • When creating an SSL key with the system folder path, the system logs an error message and the command will fail.

    For example:

    Key management library returned bad status: -21, Invalid identifier. Identifiers must start with a letter or number and may have the following characters: [A-Za-z][0-9]-._

  • When creating an SSL certificate with the system folder path, the system logs an error message and the command will fail.

    For example:

    Key management library returned bad status: 2, No such file or directory

  • When installing PKCS12 file with system folder path, the system logs an error message and the command will fail.

    For example:

    01070712:3: Caught configuration exception (0), file(/config/ssl/ssl.key//Dome-A/AAclient1.p12.key) expected to exist. - sys/validation/FileObject.cpp, line 3056.


    In addition, from the /var/log/ltm file, you may observe a log entry that appears similar to the following example:

    err mcpd[3958]: 01070712:3: Caught configuration exception (0), file(/config/ssl/ssl.key//Dome-A/AAclient1.p12.key) expected to exist. - sys/validation/FileObject.cpp, line 3056.

Workaround

To work around this issue, you can change directory to the desired system folder before performing the affected tmsh commands excluding the system folder path. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.

  2. By default, the tmsh utility path navigates to the user's default system folder.

    For example, the root user has the default system folder /Common. Therefore, the tmsh command prompt may appear similar to the following:

    root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)#

  3. Change directories to the desired system folder name using the following command syntax:

    cd /<System-Folder-Name>

    For example, to change directories to the system folder named Dome-A, you would type the following command:

    cd /Dome-A

    The tmsh prompt now shows the current system folder name on its command prompt.

    For the previous example of /Dome-A, the tmsh command prompt may appear as follows:

    root@(bigip)(cfg-sync Standalone)(Active)(/Dome-A)(tmos)#

  4. You may now create the desired key/certificate or install the desired PKCS12 file for the current system folder, excluding the system folder path.
  5. To perform more commands on a different system folder, repeat Steps 3 through 5.
  6. To save the changes you made to all system folders/partitions, type the following command:

    save /sys config partitions all

  7. To exit tmsh utility, type quit and press Enter.
