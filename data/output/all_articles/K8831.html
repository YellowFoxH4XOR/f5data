Known Issue

This is the result of a known issue. Moving a self IP address from one VLAN to another, and then deleting the self IP address, leaves the listener hash table in an inconsistent state. This may result in a virtual server not passing traffic, or the TMM process core dumping.

For example, if you assign self IP address 10.1.1.1 to VLAN external, and then move the self IP to VLAN internal, the listener hash table retains the mapping of 10.1.1.1 to the external VLAN. If the self IP address is later deleted from the internal VLAN, the listener hash table entry remains, and the self IP address continues to be accessible on the network from VLAN external.

F5 Product Development tracked this issue as CR93551, and it was fixed in BIG-IP LTM 9.4.5. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You can work around this issue by restarting the TMM process on the BIG-IP system. To do so, type the following command:

Important: Existing connections will be dropped when you restart TMM.

bigstart restart tmm
