Known Issue

XML schema files that do not declare a namespace may fail to load.

This issue occurs when all of the following conditions are met:

  • A schema file contains the import element
  • The import element does not contain a namespace attribute

The import element adds schema files with a different target namespace as shown in the following example:

<import SchemaLocation="/otherfile1.xsd" namespace="http://othernamespace1">

Although namespace is an optional attribute for the import element, omitting the attribute as shown in the following example may cause the known issue to occur:

<import SchemaLocation="/otherfile2.xsd">

Impact

The BIG-IP ASM Configuration utility may be unable to load or apply an XML schema file

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Importing an XML schema file may generate error messages that appear similar to the following examples:

    An error has occurred while the processing the schema or WSDL document.
    (Schema parsing error at: <xxxxx>: unknown type for element)

    In this error message, note the following:
    • <xxxxx> is an xml element declaration specific to the schema file.
  • Applying a policy after importing an XML schema file may generate the following error message:

    Apply Configuration
    ERROR: Apply configuration failed, try again.

Workaround

To work around this issue, you may be able to use the include element, depending on your schema design.

Impact of workaround: None

The include element is used to add multiple schemas with the same target namespace to a document. If the target namespace of the included schema is the same as the namespace of the including schema, you may be able to substitute the include element in place of the import element.

The declaration using the import element, shown previously in this article, may be changed to use the include element, as shown in the following example:

<include SchemaLocation="/otherfile1.xsd" namesspace="http://othernamespace1">

Note: This workaround may not be applicable to your configuration, depending on the design of your specific schemas. For additional information, consult your XML documentation.
