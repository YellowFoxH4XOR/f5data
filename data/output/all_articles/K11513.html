Known Issue

This is the result of a known issue. In some versions of BIG-IP, an IPv6 formatted address cannot be used to define a remote syslog server.

In BIG-IP version 10.0.x and 10.1.x, it is possible to use the bigpipe syslog remote server command to add a remote syslog server with an IPv6 address. However, although the remote server is added, the syslog-ng daemon fails to restart. When this occurs, a sequence of error messages that appear similar to the following example is displayed to the console:

Shutting down syslog-ng: [FAILED]
Starting syslog-ng: Error resolving hostname; host='fd00:0:0:4::200'
No destination address set;
[FAILED]

The configured remote syslog server remains in the configuration, and the syslog-ng daemon fails to restart.

In BIG-IP version 9.4.x, using the bigpipe syslog remote server command to add a remote syslog server with an IPv6 address fails with a sequence of error messages that appear similar to the following example:

BIGpipe unknown operation error:
01070920:3: Application error for confpp: STDERR/STDOUT text begins
Stopping syslog-ng: [ OK ]
Starting syslog-ng: \\Error resolving hostname; host='2001:1000::91'
No destination address set;
[FAILED]
STDERR/STDOUT text ends
*************************************************************
confpp[11265]: reconfig command FAILURE for unix_config_syslog returned: '/etc/init.d/syslog-ng restart 2>&1'
Stopping syslog-ng: [FAILED]
Starting syslog-ng: [ OK ]

The remote syslog server is not added to the configuration, and the syslog-ng daemon is successfully restarted.

F5 tracked this issue as CR137447 for the version 10.x software branch, and it was fixed in version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WAN Optimization, or Edge Gateway release notes.

F5 is tracking this issue as CR116710 for the version 9.4.x software branch.

Workaround

No workaround exists for BIG-IP version 9.4.x. If upgrading is not an immediate option, you can avoid this issue by using only IPv4-formatted IP addresses when configuring remote syslog servers on affected versions.

In version 10.x, if you have encountered this issue by adding an IPv6 remote syslog server as detailed above, you can work around this issue by using the bigpipe syslog remote server none command to remove all remote server definitions, then re-add only the IPv4 remote syslog server entries.

To display the addresses of the configured remote syslog servers, type the following command:

bigpipe syslog remote server list

An IPv6 remote syslog server entry appears similar to the following example:

syslog {
remote server syslogsvr1 {
host fd00:0:0:4::200
}
}

Note: For more information about configuring remote syslog servers, refer to K10057: Syntax change for the 'bigpipe syslog remote server' command.
