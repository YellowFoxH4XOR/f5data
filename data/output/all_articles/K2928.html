On January 7, 2004, one of Verisign's Intermediate certificates, arguably the most widely used intermediate certificate on BIG-IP, expired. This will potentially cause SSL Proxy sites that use Verisign's global certificates to display an error concerning the certificates signing authority.

Following is an example of the error when the 2004 Intermediate CA is installed:

The validity period of this certificate exceeds that of its certification authority

The solution to this issue is to upgrade to a more recent intermediate certificate. This new certificate expires in 2011.

Determining which BIG-IP systems require a new certificate

This issue only affects BIG-IP systems that have the intermediate-ca.crt file in use, typically for chain certificates (also known as global certificates and SGC certificates). If these certificates are not in use on your site, or if your site is functioning properly even though the intermediate-ca.crt file is not present, you are not affected by this issue.

Acquiring the new certificate

The new Verisign Intermediate CA can be found on Verisign's Web site at:

http://www.verisign.com/support/verisign-intermediate-ca/index.html

  1. Once you have opened this page in a web browser, click Get Intermediate CA Here, located in the blue box near the middle of the screen.

    This opens a smaller browser window that contains the Certificate text.

  2. Click the Select All button.

    This will select all of the certificate text, which will simplify step 2 of the Replacing the old certificate procedure.

  3. Copy the text.

Important: This certificate is not trusted by some older browsers and some older clients could display errors when this certificate is used on a site. This is not a BIG-IP error or issue.

Replacing the old certificate

In order to replace the old certificate on the BIG-IP system perform the following procedure:

  1. Using the vi text editor, create a new intermediate-ca.crt file in the /var/tmp directory by typing the following command:

    vi /var/tmp/intermediate-ca.crt

    Note: You can use pico if you are not familiar with vi.

  2. Paste the certificate contents from the Verisign site listed above that you copied in the Acquiring the new certificate procedure into the editor window. Ensure that the certificate text begins with the BEGIN CERTIFICATE line and ends with the END CERTIFICATE line.

  3. Back up the existing certificate-ca.crt file by typing the following commands:

    cd /config/bigconfig/ssl.crt
    mv intermediate-ca.crt intermediate-ca.crt.orig

  4. Copy the new certificate file into place by typing the following command:

    mv /var/tmp/intermediate-ca.crt intermediate-ca.crt

  5. Restart the BIG-IP system's services in order that the new certificate can be read by typing the following command:

    bigstart restart

The new intermediate-ca.crt file should now be in use. If you attempt to connect to an SSL Proxy and still receive an error, the following scenarios indicate :

  • Check to see whether or not the text of the error is the same as the error you received previously.

  • Ensure that you are connecting to the same BIG-IP from which you copied the updated certificate.

  • Make certain the new certificate has the correct name and is in the correct location.

If all of these point pass review and the issue still occurs, please contact F5 support.

If no errors recur and the system appears to be functioning properly, repeat this process on the standby BIG-IP system.

Frequently Asked Questions:

How do I verify whether I need to have the updated intermediate certificate on my BIG-IP?

Type the following command from the /config/bigconfig/ssl.crt directory:

openssl x509 -in intermediate-ca.crt -text |grep -A2 -i validity

The output for the new certificate appears as follows:

openssl x509 -in intermediate-ca.crt -text |grep -A2 -i validity
Validity
Not Before: Apr 17 00:00:00 1997 GMT
Not After : Oct 24 23:59:59 2011 GMT

The older certificate output from the following command looks like this:

bigip1:/config/bigconfig/ssl.crt# openssl x509 -in intermediate-ca.crt -text |grep -A2 -i validity
Validity
Not Before: Apr 17 00:00:00 1997 GMT
Not After : Jan  7 23:59:59 2004 GMT

Notice the Not After date given on the bad cert. This is indicative of a certificate that needs to be replaced.

Does this affect all BIG-IPs or only ones with intermediate.ca installed?

This only affects BIG-IPs that have the intermediate-ca.crt file in use. This is the case when your site uses chain certificate (also known as global certificates and SGC certificates). If these certificates are not in use on your site or your site is working fine even though the intermediate-ca.crt file is not present, you are not affected by this problem.

Will SSL traffic on proxies be affected if I install the new intermediate certificate?

The bigstart restart command will remove all of your current connections. You should perform this operation during a low-traffic period or during a maintenance window.

If you are being affected by this problem and waiting for a maintenance window is not possible, you can execute proxyd on your BIG-IP. This will start a second proxyd.noakamai process, which will handle all new incoming connections while the older connections continue to be handled by the older proxyd process. The old proxyd.noakamai process will stop running when all client connections are finished. This will not affect traffic on your site, though the recommended method is the bigstart restart command.

Does this affect the BIG-IP's self-signed certificates and will this affect re-encryption?

This issue does not affect self-signed certificates, nor does it affect certificates that are not chain or global certificates. Since these certificates do not use the intermediate-ca.crt file, they are unaffected by its expiration.
