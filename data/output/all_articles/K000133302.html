K000133302: Clickhouse pod crashing and restarting at startup

Type
Support Solution
Published
2023-03-31
Updated
2023-03-31
Applies to
  • NGINX Products
  • NGINX Controller: 3.22.8
Source
https://my.f5.com/manage/s/article/K000133302

Description

After starting clickhouse the pod constantly crashes and restarts

Environment

NGINX Controller

Cause

This could be a result of the pod’s readiness and liveness probe commands failing. This can happen when the commands execute before the pod’s container is fully up. The probes' initialDelaySeconds field tells the kubelet that it should wait x seconds before performing the first probe.

Recommended Actions

Update the clickhouse statefulset, setting the "initialDelaySeconds" for the container’s readinessProbe and livenessProbe to 300 (seconds)

kubectl patch sts clickhouse -p '{"spec": {"template": {"spec": {"containers": [{"name":"clickhouse","livenessProbe": {"initialDelaySeconds":300},"readinessProbe": {"initialDelaySeconds":300}}]}}}}'

Delete the clickhouse pod for the changes to take effect

​​​​​​​kubectl delete po -l app=clickhouse

Monitor the clickhouse logs as it starts up

kubectl logs clickhouse-0 -f
