Description
Memory leak on statsd daemon may happen on i-series platform model 11000 when some of the CPU cores are implementing license-based limiting. Symptoms include a growing memory usage value for statsd process which eventually leads to out of memory (OOM) condition. Statsd memory usage can be checked using the following command:

# tmsh show /sys proc-info

The output would look similar to the following:

----------------------------------
Process: statsd
----------------------------------
Process ID                   34753
Blade Id                         0
Associated Modules            mgmt 
                    
CPU Utilization (%) 
  Recent                         0
  Last 1-Mins                    0
  Last 5-Mins                    0
System Utilization (%)
  Recent                         0
  Last 1-Mins                    0
  Last 5-Mins                    0
Memory (bytes)      
  Total Virtual Size         56.1M
  Resident Set Size          37.5M

The "Total Virtual Size" value will continue to grow when the condition mentioned above is met.
 

Environment

  • i-series 11000 model platforms
  • CPU implementing license restrictions

Cause
F5 track this issue as ID1071449.

Recommended Actions

Workaround is to periodically restart statsd daemon to avoid OOM condition using the following command.

# bigstart restart statsd

Bug has been fixed starting BIG-IP v16.1.2.2, so upgrading to that version (or newer) would also resolve this issue.
