Known Issue

This is the result of a known issue. If the BIG-IP GTM system receives a high number of path probe requests, the requests will be stored in a queue until processed. Under rare conditions, the path probe queue can back up, causing the big3d and big3dshim processes to fail. When this occurs, the big3d and big3dshim processes will not recover properly and will need to be manually restarted.

F5 Product Development tracked this issue as CR67749, CR67750, CR69155 and it was fixed in BIG-IP GTM 9.2.4, 9.3.0 and 9.4.0. For information about upgrading, refer to the BIG-IP GTM release notes.
