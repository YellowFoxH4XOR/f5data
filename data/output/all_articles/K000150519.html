K000150519: Client certificates are not being forwarded to the backend services

Type
Support Solution
Published
2025-03-24
Updated
2025-03-24
Applies to
  • NGINX Products
  • F5 Distributed Cloud Services
  • NGINX Ingress Controller
Source
https://my.f5.com/manage/s/article/K000150519

Description

Request headers to the upstream services that derive their values from a client certificate variable, such as $ssl_client_escaped_cert, do not contain the value of the ssl client certificate contained within the client request. Example VS/VSR configuration:

- action:
  proxy:
  requestHeaders:
    pass: true
    set:
      - name: client-cert
        value: ${ssl_client_escaped_cert}

Environment

NGINX Ingress Controller

Cause

NGINX [Plus] requires directive ssl_verify_client to populate ssl client certificate variables

Recommended Actions

Implement the ssl_verify_client directive either by using a server snippet or by implementing an ingressMTLS policy. Example VS/VSR configurations:

Server Snippets:

server-snippets: | 
  ssl_verify_client optional_no_ca;

ingressMTLS Policy:

kind: Secret
metadata:
  name: ingress-mtls-secret
  apiVersion: v1
  type: nginx.org/ca
  data:
    ca.crt: <base64_ca_cert_blob>
---
apiVersion: k8s.nginx.org/v1
kind: Policy
metadata:
  name: ingress-mtls-policy
spec:
  ingressMTLS:
    clientCertSecret: ingress-mtls-secret
    verifyClient: "optional_no_ca"
