Description

  • How to insert a Content Security Policy (CSP) header for SAML Authentication.

Environment

  • BIG-IP with APM and SAML (BIG-IP as SP), optionally also using a stream profile
  • External IdP

Cause

implemented on the Service Provider (SP) includes a Content-Security-Policy (CSP) that restricts certain actions, which can interfere with the redirection process required for SAML authentication.
Specifically, the CSP directive form-action 'self' limits form submissions to the same origin, preventing the browser from submitting forms to the Identity Provider (IdP) during the SAML authentication flow.
By setting form-action 'self', the CSP blocks these form submissions to external domains, disrupting the authentication process.

 Recommended Actions

Apply the following iRule to the SP Virtual Server. 
Please update "idp.delvechio.local" to the actual domain of the IdP in use.

priority 100
 
# Disable iRule events for access control on client acceptance
when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable
    set internalURI false
}
 
# Check if server address starts with "127." to determine if it's internal
when SERVER_CONNECTED {
    set internalURI false
    if { [IP::server_addr] starts_with "127." } {
        set internalURI true
    }
}
 
# Store the requested URI
when HTTP_REQUEST {
    set myURI [HTTP::uri]
}
 
# Apply security headers and CSP upon response release if not an internal URI
when HTTP_RESPONSE_RELEASE {
    if { not ($internalURI) } {
        
        # Insert a secure Content-Security-Policy header with unsafe-inline to allow inline event handlers
        if { !([HTTP::header exists "Content-Security-Policy"]) } {
            HTTP::header insert "Content-Security-Policy" "object-src 'none'; script-src 'self' https://idp.delvechio.local 'unsafe-inline'; style-src 'self'; img-src 'self'; base-uri 'self'; form-action 'self' https://idp.delvechio.local;"
        }
        
        # Add X-XSS-Protection header to enable XSS filtering in browsers
        HTTP::header insert "X-XSS-Protection" "1; mode=block"
        
        # Add X-Content-Type-Options header to prevent MIME-type sniffing
        HTTP::header insert "X-Content-Type-Options" "nosniff"
        
        # Add Strict-Transport-Security header to enforce HTTPS with a max-age of 180 days and include subdomains
        HTTP::header replace "Strict-Transport-Security" "max-age=15552000; includeSubDomains"
    }
}

Explanations:

form-action 'self' https://idp.delvechio.local;: This directive allows form submissions to both the SP's origin ('self') and the specified IdP (https://idp.delvechio.local).
By explicitly including the IdP's URL, you enable the necessary form submissions for SAML authentication without broadly relaxing the policy.

script-src 'self' https://idp.delvechio.local;: Allows scripts from both the Service Provider’s origin ('self') and the IdP (https://idp.delvechio.local).
This supports any JavaScript required by the IdP during the authentication process.

Additionally, if a "stream" profile is applied and "STREAM" commands are used in an iRule applied to the APM Virtual Server, these lines need to be added to that iRule, before the "STREAM::..." command (e.g. at the start of the "HTTP_RESPONSE" event section).

   if { [info exists internalURI] and ($internalURI)}{ return }
   if { $myURI starts_with "/renderer/agent_aaa_saml_form.eui" } { return }
