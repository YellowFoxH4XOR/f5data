Known Issue

The BIG-IP system may send an incorrect session ID.

This issue occurs when all of the following conditions are met:

  • Your virtual server uses a Client SSL profile with Session Ticket enabled.
  • The client attempts to resume an SSL session using a session ticket.

Impact

The affected Client SSL session may fail to resume, and may require a full handshake.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice reduced performance for SSL transactions and higher CPU usage due to the resumed SSL sessions requiring a full SSL handshake.
  • When viewing a packet capture taken by the tcpdump utility, you observe that the BIG-IP system sends an incorrect session ID. For more information about the tcpdump utility, refer to K411: Overview of packet tracing with the tcpdump utility.

Workaround

To work around this issue, you can disable Session Ticket in the Client SSL profile.

Impact of workaround: The SSL client and server cannot use session tickets for session resumption, and the client may complete the full handshake process for each new connection. Session Ticket is the mechanism that allows resuming an SSL session without having to perform a full SSL handshake. The session ticket mechanism is a TLS extension that allows the client to save all necessary session state information, including the negotiated cipher suite and master secret.
