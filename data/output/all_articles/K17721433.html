Topic

Bidirectional Forwarding Detection (BFD) is a protocol that detects faults between two forwarding engines connected by a link. On the BIG-IP system, you can enable the BFD protocol for the OSPFv2, BGP4, IS-IS, and RIP dynamic routing protocols, specifically.

Description

You enable BFD on a per-route domain basis. BFD identifies changes to the connectivity between two forwarding engines, or endpoints, by transmitting periodic BFD control packets on each path between the two endpoints. When a specified amount of time passes before one of the endpoints receives these control packets, the connectivity between the endpoints is considered lost, and BFD notifies the associated dynamic routing protocols. In general, BFD detects connectivity changes more rapidly than the endpoints' standard Hello mechanisms, leading to quicker network convergence, which is highly desirable to data center applications. BFD does not have a discovery mechanism and sessions must be explicitly configured between endpoints. The BIG-IP oamd daemon starts when BFD is enabled in the route domain like any other routing protocol.

A BFD session can operate in one of the following two modes:

  • Asynchronous mode: You configure BFD to operate in Asynchronous mode when you want both endpoints to verify connectivity by periodically sending Hello packets to each other. This is the most commonly-used mode, and it is the default mode when you configure BFD.
  • Demand mode: You configure BFD to operate in Demand mode when you want the endpoints to use a way to verify connectivity to each other, other than sending Hello packets. For example, the endpoints might verify connectivity at the underlying physical layer. However, in Demand mode, either host can send Hello packets if needed.

BFD session state

There are three states through which a session normally proceeds:

  • Init: Indicates that you want to bring the session up in the beginning of a BFD handshake.
  • Up: Indicates that the session is Up.
  • Down: Indicates that either the control detection time has expired in an already established BFD session or the session never came up. If probing time (min_tx) is set to 100ms, for example, and the multiplier is 3, then no response after 300ms makes the system go down.
  • AdminDown: Indicates that the session is administratively forced down by the command, indefinitely.

Enabling the BFD protocol

Before configuring BFD, you must enable BFD on an existing route domain using the Configuration utility. To do so, perform the following procedure:

Note: The BIG-IP system starts one BFD session for the route domain when you enable BFD.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Network > Route Domains.
  3. Select the name of the relevant route domain.
  4. In the Dynamic Routing Protocols setting, enable the BFD and the advance routing protocol:
    • From the Available list, select BFD and move it to the Enabled list.
    • From the Available list, select desired routing protocol and move it to the Enabled list.
  5. Click Update.

Configuring the BFD protocol using the IMI Shell

The first step in configuring the BFD protocol on the BIG-IP system is to use the IMI Shell (imish) to configure the protocol for the relevant advanced routing modules (BGP4, OSPFv2, and IS-IS).

There are two common BFD commands that you can use to perform BFD base configuration. To run these commands, use imish:

Sample commandResults
(config-if)#bfd interval 100 minrx 100 multiplier 3Sets the desired Min Tx, required Min Rx, and detect Multiplier.
(BFD timer intervals of 100ms transmit, 100ms receive and multiplier 3 [hold down time = 300ms])
(config)#bfd slow-timer 2000Sets BFD slow timer to two seconds.
(This value determines how fast BFD starts up a new session and is used to slow down the asynchronous sessions when the BFD echo function is enabled.)

You can use following common BFD commands to configure BFD for the following routing protocols:

ProtocolSample commandResults
BGP4(config)#router bgp 65011
(config-router)#neighbor 1.1.1.1 fall-over bfd multihop		Enables multi-hop BFD to BGP neighbor 1.1.1.1 for autonomous system (AS) 65011.
OSPFv2/v3(config)#router ospf 1
(config-router)#bfd all-interfaces		Enables single-hop BFD for all OSPF neighbors for OSPF area 1.
OSPFv2/v3(config)#router ospf 1
(config-router)#area 1 virtual-link 3.3.3.3 fall-over bfd		Enables multi-hop BFD to OSPF router 3.3.3.3 for OSPF area 1.
ISIS(config)#router isis test
(config-router)#bfd all-interfaces		Enables BFD for all IS-IS neighbors for ISIS test.
RIP(config)#router rip
(config-router)#bfd all-interfaces		Enables BFD for all RIP neighbors.
Static route(config)#ip bfd static all-interfacesEnables BFD for all interfaces.

(config-if)#ip static bfd
(config)#ip static 1.1.1.1/16 172.16.199.150 fall-over bfd		Enables BFD for internal interface -only and associates static IP to BFD.

Configuring OSPF for all BIG-IP devices

Impact of procedure: The impact of configuring OSPF areas depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your routing.

  1. Log in to the BIG-IP-1 command line.
  2. Access imish by typing the following command:

    imish

  3. Enter the Enable mode by typing the following command:

    enable

  4. Enter the Configuration mode by typing the following command:

    config terminal

  5. To enter the Router mode and configure an OSPF routing process 100, type the following command:

    router ospf 100

  6. To advertise network 10.12.19.0/24 in OSPF area 1, type the following command:

    network 10.12.19.0/24 area 1

  7. To enable BFD for all interfaces, type the following command:

    bfd all-interfaces

  8. Repeat the previous steps for each BIG-IP device in the single hop configuration.

Validating BFD sessions

Use following BFD commands to verify all BFD sessions running on the BIG-IP system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Access imish by typing the following command:

    imish

  3. Enter the Enable mode by typing the following command:

    enable

  4. To display all BFD sessions, use the following command syntax:

    show bfd session <detail>

    For example, to display BFD session information on the BIG-IP-2 system, type the following command:

    show bfd session
