Description

Applying configuration from NMS to an NGINX instance that has more than 100 worker_processes running fails with Agent logs similar to the following: 

time="<timestamp>" level=info msg="Commander received <nil>, rpc error: code = Internal desc = stream terminated by RST_STREAM with error code: INTERNAL_ERROR"
time="<timestamp>" level=error msg="Commander Channel Recv: error communicating with <nms-ip>:443, code=Internal, message=stream terminated by RST_STREAM with error code: INTERNAL_ERROR"
time="<timestamp>" level=info msg="Commander Channel Recv: retrying to connect to <nms-ip>:443"

Environment

  • NMS
  • NGINX 
  • worker_processes 

Cause

Agent handles up to and including 100 worker_processes

Recommended Actions

  1. Upgrade Agent to version 3.30.2+
  2. Edit Agent configuration (/etc/nginx-agent/nginx-agent.conf) and implement parameter 'queue_size' with a value equal to or greater than the number of running NGINX worker_processes.
    For example, if running NGINX worker_processes is 256 then set the queu_size to 512 (2x256): 
    # Number of NGINX worker_processes Agent can handle queue_size: 512
