Note: For information about configuring the Whitehat Sentinel with BIG-IP ASM version 10.1.0 and later, refer to K11926: Integrating the BIG-IP ASM system with WhiteHat Sentinel.

Important: You must perform the procedures in this solution in the listed order. For example, you must import the security policy and attack signatures to the BIG-IP ASM system before connecting to the WhiteHat Sentinel portal. If you connect to the WhiteHat Sentinel portal before importing the security policy and attack signatures to the BIG-IP ASM system, you may receive an error message from the WhiteHat GUI. For more information, refer to K9669: The WhiteHat Sentinel GUI returns an error message when accessing the BIG-IP ASM.

Beginning in BIG-IP ASM 9.4.5, you can integrate the WhiteHat Sentinel Scanner with the BIG-IP ASM system to protect applications from cross-site scripting (XSS) attacks and SQL injection attacks. To do so, you must perform the following procedures:

Note: Prior to completing the following procedures, ensure that the WhiteHat Sentinel scanner is pointed to the appropriate BIG-IP ASM virtual server.

  • Importing the security policy to your BIG-IP ASM system
  • Importing the user-defined attack signatures to the BIG-IP ASM
  • Running the WhiteHat Sentinel Scanner
  • Configuring the BIG-IP ASM security policy to mitigate the found vulnerabilities
  • Ensuring that the BIG-IP ASM security policy mitigates the previously-found vulnerabilities

Importing the security policy to your BIG-IP ASM system

To prevent false positive alarms in the security policy, and to ensure effective protection against XSS and SQL injection attacks, you must import the attached security policy to your BIG-IP ASM system. To do so, perform the following procedure:

  1. Navigate to the following location:

    https://downloads.f5.com/esd/product.jsp?sw=BIG-IP&pro=big-ip_v9.x&prodesc=BIG-IP+v9.x

  2. Click the Whitehat-Solution---ASM-Solution-Only link.
  3. If prompted, accept the End-User License Agreement by clicking I Accept.
  4. Click the Whitehat-baseline.plc link.
  5. Select a downloading method to download the file to your local workstation.
  6. In the BIG-IP ASM Configuration utility, navigate to the Policies List screen.
  7. Click Import to import the downloaded security policy.
  8. Use the imported security policy as the baseline security policy for the WhiteHat Sentinel scan.

Importing the user-defined attack signatures to the BIG-IP ASM

  1. Navigate to the following location:

    https://downloads.f5.com/esd/product.jsp?sw=BIG-IP&pro=big-ip_v9.x&prodesc=BIG-IP+v9.x

  2. Click the Whitehat-Solution---ASM-Solution-Only link.
  3. If prompted, accept the End-User License Agreement by clicking I Accept.
  4. Click the sigfile_06-13-08_18-23.xml link.
  5. Select a downloading method to download the file to your local workstation.
  6. In the BIG-IP ASM Configuration utility, click Options in the Application Security section.
  7. On the Attack Signatures screen, click Import to import the attack signatures file to the BIG-IP ASM system.

Running the WhiteHat Sentinel Scanner

Run the WhiteHat Sentinel Scanner from the Schedule screen in the WhiteHat GUI. When the scanner finishes scanning the application, all found vulnerabilities are displayed in the Findings section of the WhiteHat GUI. You can now use the information on the Details screen in the WhiteHat GUI to configure the BIG-IP ASM security policy to mitigate the found vulnerabilities.

Configuring the BIG-IP ASM security policy to mitigate the found vulnerabilities

  1. In the WhiteHat GUI, navigate to the Findings > Vulnerability Details screen.
  2. In the Firewall Configuration section, specify the BIG-IP ASM management IP address and credentials.
  3. In the table, choose your web application and security policy.
  4. Select the Set to Blocking check box.
  5. Click Apply Changes.

Ensuring that the BIG-IP ASM security policy mitigates the previously-found vulnerabilities

To ensure that the BIG-IP ASM security policy mitigates the previously-found vulnerabilities, click Retest Now at the top of the Details screen in the WhiteHat configuration. When the retesting process completes, the Current Status option displays Closed, which indicates that the vulnerabilities have been successfully mitigated.
