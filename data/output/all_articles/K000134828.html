K000134828: UDP DNS queries without EDNS0 option against DNS Express zone get truncated

Description

UDP DNS queries without EDNS0 option against BIG-IP's DNS Express zone for larger responses get truncated. The response does not include an ANSWER section and causes fallback to TCP DNS resolution. In case an application doesn't support TCP fallback, it fails DNS resolution.

Environment

  • BIG-IP DNS
  • UDP DNS query without EDNS0 option sent to DNS Express zone
  • The expected response is larger than 512 bytes

Cause

The issue is due to ID 961229.
 

Recommended Actions

  • Upgrade to the version with the fix.
  • Enable DNS Express minimal-responses using DB key dnsexpress.minimalresponse. For detailed information, please refer to K41004650: Enable DNS Express minimal-responses for the Authority and Additional Records sections
  • Disable truncating UDP DNS response using DB key dns.udptruncate. For detailed information, please refer to K91537308: Overview of the truncating rule when DNS response size is over 512 Bytes

Additional Information

For example, UDP DNS query without EDNS0 option would look like below.

# dig @172.16.27.100 www.example.com +noedns +ignore

; <<>> DiG 9.11.22 <<>> @172.16.27.100 www.example.com +noedns +ignore
; (1 server found)
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: SERVFAIL, id: 44189
;; flags: qr rd; QUERY: 1, ANSWER: 0, AUTHORITY: 0, ADDITIONAL: 0
;; WARNING: recursion requested but not available

;; QUESTION SECTION:
;www.example.com.        IN    A

;; Query time: 1 msec
;; SERVER: 172.16.27.100#53(172.16.27.100)
;; WHEN: Sun May 28 21:12:33 PDT 2023
;; MSG SIZE  rcvd: 33
