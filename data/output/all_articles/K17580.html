Known Issue

The iControl representational state transfer (REST) application programming interface (API) may fail to respond.

This issue occurs when all of the following conditions are met:

  • You use the iControl REST API to obtain data from or modify the configuration of your BIG-IP system.
  • The icrd process starts before the restjavad process.

As a result of a startup race condition, the iControl REST API may be unresponsive if the icrd process starts before the restjavad process has completely started.

Impact

The iControl REST API is not available for configuration queries or modifications.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Requests to the iControl REST API do not receive a response, or receive an error message.
  • In the /var/log/icrd file, you observe error messages that appear similar to the following example:

    err icrd: 5557,16490, RestRequestSender, SEVERE,SocketError: 115 25 11

Workaround

There is no workaround for this issue. However, to recover from this issue and restore connectivity, you can verify that the restjavad process has completely started, and then restart the icrd process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To verify that the restjavad process is running, type the following command:

    show /sys service restjavad

    The output of the command should appear similar to the following example:

    restjavad run (pid 5586) 1 days

  3. To restart the icrd process, type the following command:

    restart /sys service icrd
