Known Issue

When you strip a Session Initiation Protocol (SIP) message routing Via header from incoming SIP responses that contains multiple Via headers combined in a single line, the first character from the second header is lost. This happens when the headers are separated by only a comma rather than a comma suffixed with a space character.

For example, observe the following header:

Via: SIP/2.0/TCP 172.16.15.18:5060;rport;branch=z9hG4bKf5s1psess0rsbZD9QFsSXX6FeT2pMa%aG3CmVEqAxkmY396H56h8EzfczJtL%h4qPEv92VBx9d4iNy%60!,SIP/2.0/TCP
217.243.184.5:5060;branch=z9hG4bKd1cf5a6f6a82fc68f49f98af3feaff9ejaaaaaaiaaaaaa0qn41ca3Zqkv7yuypiwz4y5abu2
aaaaabaaaaacqaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaq,SIP/2.0/TCP
217.243.184.8:5082;branch=z9hG4bK2649418839-1959056933

The previous header becomes the following header:

Via: IP/2.0/TCP 217.243.184.5:5060;branch=z9hG4bKd1cf5a6f6a82fc68f49f98af3feaff9ejaaaaaaiaaaaaa0qn41ca3Zqkv7yuypiwz4y5abu2
aaaaabaaaaacqaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaq,SIP/2.0/TCP
217.243.184.8:5082;branch=z9hG4bK2649418839-1959056933

Note: IP/2.0/TCP should be SIP/2.0/TCP.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system parses multiple Via headers with a comma but no suffixed space character.
  • You are using a SIP message routing profile.

Impact

Affected messages may be incorrectly parsed and potentially dropped as invalid.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • A character is stripped from the Via header, where SIP/2.0/TCP becomes IP/2.0/TCP.
