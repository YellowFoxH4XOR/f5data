K000132237: APM - How-to use ACCESS::log command in irule to write logs to /var/log/apm

Description

This KB article gives an example of how to use ACCESS::log command in irule to write logs to /var/log/apm


Environment

  • APM
  • irule
  • ACCESS::log
  • /var/log/apm

Cause

Not relevant


Recommended Actions

1) create an access-profile with simple VPE logic:


Start -> Logon Page -> Allow


2) verify what log profile is assigned under access-profile and what log level the access-control component has ('notice' in our example) for that log profile:


[root@apm.local:Active:Standalone] config # tmsh list apm profile access ap_irule_access-log

apm profile access ap_irule_access-log {

 accept-languages { en }

[...]

 log-settings {

  default-log-setting

 }

[...]


[root@apm.local:Active:Standalone] config # tmsh list apm log-setting default-log-setting all-properties 

apm log-setting default-log-setting {

 access {

  general-log {

   app-service none

   enabled true

   publisher sys-db-access-publisher

   type access

   log-level {

    access-control notice <<< (!)

[...]


3) assign the irule (the requirements of what to log may vary, so the syntax should be aligned accordingly): 


[root@apm.local:Active:Standalone] config # tmsh list ltm rule irule_access_log

ltm rule irule_access_log {

proc logger { logstring {severity "notice"} } {

set prefix "ACCESS_DEBUG \[[IP::client_addr]->[virtual name]\]:"

ACCESS::log $severity "${prefix} ${logstring}"

}

when HTTP_REQUEST {

  call logger "message from logger"

}

}


Make sure that the given log level ('notice' in our example) in irule matches the log level specified in the log setting for access-control component ('notice' in our example, see the step 2 configuration). If the log levels don't match, then the message is not logged.

 

4) assign the irule and the access-profile under testing virtual server. In our example, the configuration looks like:


[root@apm.local:Active:Standalone] config # tmsh list ltm virtual vs_irule_access-log 

ltm virtual vs_irule_access-log {

  creation-time 2022-09-08:15:00:53

  destination 192.168.1.65:http

  ip-protocol tcp

  last-modified-time 2022-09-08:15:09:38

  mask 255.255.255.255

  pool pool-apache

  profiles {

    ap_irule_access-log { }

    http { }

    rba { }

    tcp { }

    websso { }

  }

  rules {

    irule_access_log

  }

  serverssl-use-sni disabled

  source 0.0.0.0/0

  source-address-translation {

    type automap

  }

  translate-address enabled

  translate-port enabled

  vs-index 182

}
