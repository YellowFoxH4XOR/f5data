K08944443: Recommendations for spinning up Jobs in Aspen Mesh

Published
2021-12-14

Applies to

Description

In the Kubernetes world, Jobs are a resource type which perform specific tasks, wait for its completion, and return an exit code. In Aspen Mesh, we have a sidecar that does routing and networking being separate from the application pod.
 

Environment

Aspen Mesh: 1.14.5
 

Cause

A Job is not considered complete until all its containers have stopped running, while a sidecar in Aspen Mesh runs indefinitely.
 

Recommended Actions

There is a /quitquitquit endpoint in envoy-proxy which when called from the application pod on the envoy admin port 15000, terminates the sidecar. In this example we are running a Perl job which should terminate after successful return of the command it is supposed to run.

apiVersion: batch/v1
kind: Job
metadata:
  name: nginx-job
spec:
  template:
    spec:
      containers:
      - name: nginx
        image: nginx
        command:
        - /bin/sh
        - -c
        - |
          until curl -fsI http://localhost:15021/healthz/ready; do echo \"Waiting for Sidecar...\"; sleep 3; done;
          echo \"Sidecar available. Running the command...\";
          perl -Mbignum=bpi -wle 'print bpi(2000)'; #my command
          x=$(echo $?);
          echo \"Killing sidecar...\";
          curl -fsI -X POST http://localhost:15000/quitquitquit ;
          exit $x
      restartPolicy: Never
  backoffLimit: 4


We query the sidecar at http://localhost:15021/healthz/ready to determine if it's running before the job executes. After the job is done, we will terminate the sidecar by running a POST to the endpoint /quitquitquit and exit the code.

You can add various logic to your Job application defining how it kills the sidecar after the Job code completes. In the logic above, we are in a loop until the sidecar starts before running the job and we only run the /quit endpoint once.
