K000162451: BIG-IP HTTPS Monitor Marks a Pool Member Down When the Backend Closes an HTTP/0.9 GET / Request

Type
Support Solution
Published
2026-07-26
Updated
2026-07-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162451

Description

A BIG-IP HTTPS monitor marks a pool member down because the backend application closes the connection without returning an HTTP response to the monitor’s HTTP/0.9 GET / request. The monitor succeeds when the request is changed to HTTP/1.1 or when it targets a path that returns a valid response.

Environment

  • BIG-IP LTM
  • HTTPS pool member monitored on port 443
  • Default HTTPS monitor with no receive string
  • Backend application that closes the connection for an HTTP/0.9 request to the root path (/)

Cause

The default HTTPS monitor sends a request equivalent to:

GET /

This is interpreted as an HTTP/0.9 request. The backend application closes the connection when it receives this request for the root path and does not return an HTTP response.

Because the monitor receives no valid response to evaluate, the BIG-IP marks the pool member down. This behavior is caused by the backend application’s handling of HTTP/0.9 requests to /, not by TLS, SNI, or the HTTPS monitor’s ability to establish a connection.

Manual curl or OpenSSL tests may succeed because they commonly send an HTTP/1.1 request, include a Host header, or request a different URI.

Resolution

Use one of the following solutions:

  1. Modify the backend application to return a valid response to an HTTP/0.9 GET / request instead of closing the connection.
  2. Configure a dedicated HTTPS monitor that sends an HTTP/1.1 request, such as:

GET / HTTP/1.1\r

Host: <backend-hostname>\r

Connection: Close\r

\r


Configure the monitor to request another URI that consistently returns a valid response.

Example monitor configuration:

ltm monitor https /Common/mon_https_backend {

defaults-from /Common/https

send "GET / HTTP/1.1\r Host: <backend-hostname>\r Connection: Close\r \r "

}

Replace <backend-hostname> with the backend service hostname.

Verification

Capture the monitor traffic and confirm that:

  • BIG-IP establishes the TCP connection.
  • BIG-IP completes the TLS handshake.
  • BIG-IP sends the configured HTTP request.
  • The backend returns an HTTP response.
  • The response satisfies the monitor configuration.

A 505 HTTP Version Not Supported response confirms that TLS was established and that the backend processed an HTTP request. It does not confirm that the BIG-IP monitor sent the same request or received the same response.
