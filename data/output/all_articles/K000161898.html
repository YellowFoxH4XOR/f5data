Description

You may observe that some Disk partitions like '/usr' reports 100% usage and '0 MB' available in "df -h" command output, despite the presence of some free space (e.g., ~200 MB) - below sample snapshot. This article explains the underlying Linux filesystem behavior and clarifies why this is expected, not a sign of disk exhaustion.

Environment

  • BIG-IP LTM
  • The 'df -h' output for Disk partition shows an unexpected usage percentage
  • Actual used space is less than total partition size

Cause

The Linux filesystem reserves a small percentage of each partition (typically 5%) exclusively for the root user. This reserved space is not included in the "Available" column of 'df -h' command output. When user-space data fills the remaining ~95% of the partition, the 'df' command reports '0 MB' available and 100% usage—even though the reserved blocks still physically exist and are accessible to root.

Some Key Points:

  • The 100% usage display is not a sign of disk exhaustion. Reserved blocks ensure system stability and allow root-level operations even when user-space is full.
  • This behavior is expected even after a BIG-IP upgrade, as documented in KB K23607394: The /usr partition shows high disk space usage.

Answer/Recommended Actions

  • No manual action is required for the '/usr' partition if 100% usage is observed.
