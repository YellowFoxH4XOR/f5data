Description

Log system has been flooded with too many info soap log messages.
Want to discard these messages in the ltm log so that they are not on the way from viewing other critical log messages.

Environment

  • BIG-IP v14, v13, v15
  • iControl 

Cause

By default, db icontrol.loglevel is set to none and there should be no debug messages in ltm log.
However, for some versions v13.x, v14.x, and v15.x  there is a known issue that icontrol.loglevel value none variable doesn't disable SOAP messages in LTM log. This is tracked as bug ID718567.

Recommended Actions

To confirm debug messages are showing in ltm log, using below command:
grep soap /var/log/ltm

You should see the messages as below:
Aug 21 14:44:28 bigip.com info soap[14835]: src=10.10.10.10, user=admin, method=get_version, action=

If you would like to suppress these messages,
1. Log in to tmsh by typing the following command:
tmsh

2. To edit the syslog configuration type the following command:
modify sys syslog include 'filter f_local0 {facility(local0) and not match("user=admin, method=");};

3. Save the configuration by typing the following configuration:
save sys config

If you would like to rollback to the default setting,
1. Log in to tmsh by typing the following command:
tmsh

2. To edit the syslog configuration type the following command:
modify sys syslog include ''

3. Save the configuration by typing the following configuration:
save sys config

 

Additional Information

By default, db icontrol.loglevel is set to "none", 
list sys db icontrol.loglevel value
sys db icontrol.loglevel {
    value "none"
}

If you would like to modify it, below is the detailed information:
modify sys db icontrol.loglevel value (none | debug | trace)
"none" = no debug logging
"debug" = debug logging is enabled for method/parameter logging
"trace" = debug logging is enabled for method/parameter and XML payload tracing.
