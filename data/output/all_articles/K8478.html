Known Issue

This is the result of a known issue. When the tightening flag is enabled on a wildcard entity, the Policy Builder is running, or when attack signatures are in the staging process (a form of tightening used by BIG-IP ASM), BIG-IP ASM may log requests for internal purposes, regardless of the logging profile configuration. As a result, information that the user chose not to log through the use of a logging profile is erroneously logged.

You can view this information by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Options.
  3. Select Requests located under the Learning menu.

Note: Not all requests are logged here; however, it will appear that all requests are being logged. This behavior results when the logging profile is set to Log illegal requests. Valid requests that should not be seen will be listed in this view.

You can safely ignore this issue; it does not affect the operation of the BIG-IP ASM system.

F5 Product Development tracked this issue as ID 280413 (formerly CR88149), and it was fixed in BIG-IP ASM 10.1.0. For information about upgrading, refer to the BIG-IP ASM release notes.
