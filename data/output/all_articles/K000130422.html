Description

Are locally logged ASM logs rotated faster if Bot-Defense and DDOS are enabled to log locally as well?

 

Environment

  • ASM provisioned
  • Local Logging Configured
  • Configured to log Application / Bot-Defence / DOS locally

 

Cause

None

 

 Recommended Actions

All the security event logs, including asm/bot defense, go into the PRX database.

If you run the below command, it will list all the tables part of the PRX database, which include asm/bot-defense :

 

mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "use PRX; show tables;"

 

DDOS logs go into a different db (called logdb) altogether unlike asm and bot-defense logs.

 

ASM Logging limits

ASM Logging limits are implemented at two points

 

  1. BIGIP keeps either 5GB (hardware) or 2GB (virtual machine) of request information in /var/asmdata1/request_log, broken up into 20MB protobuf files. When the threshold(depending on the platform type) is reached here, asmlogd will delete the oldest protobuf files to make room for new ones. These settings are controlled by /etc/ts/tools/asmlogd.cfg file, F5 doesnt recommend changing the defaults.
  2. The maximum number of request log entries is 3 million. The /ets/ts/tools/asmlogd_clean_db.yaml files controls the size/rows thresholds for the database tables that asmlogd maintains. F5 doesn't recommend changing the defaults.

 

Bot-defense Logging limits:

For bot defense, they are only limited by the number of rows in the database.

This is controlled by /ets/ts/tools/asmlogd_clean_db.yaml.

F5 doesn't recommend changing the defaults.

 

PRX.BOT_DEFENSE_EVENT_LOG:

row_limit: 100000  

 

DDOS logs do not share the db with other logs. It looks like bot defense and asm are part of the same DB.

However, they have their own limits separately enforced from each other, and it's highly unlikely having bot defense logging enabled would cause ASM logs to be "rotated" out faster.

 

We need to note that local logging requires additional resources such as I/Os which could result in additional resource overhead.

Furthermore, BIGIP has finite resources such as disk space, and cannot hold all logs locally indefinitely.

Please note F5 recommends externally logging all requests or at the very least all legal requests, to a security information and event management system for better data retention, searching, event correlation, and scalability.
