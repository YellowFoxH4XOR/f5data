Known Issue

The bigd process leaks memory after updating to BIG-IP 12.1.5.3.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is updated to version 12.1.5.3.
  • You have HTTPS monitors configured.

Impact

A memory leak occurs in the system as a result of this issue. Depending on the platform, one or more process daemons, including bigd, might restart or fail. Although the restarting of the bigd process does not impact traffic, other daemon processes may restart due to low memory conditions, which can lead to traffic disruption while the affected daemons restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Due to a lack of memory, some processes may restart or produce a core file.
  • Health monitors that rely on the bigd process are affected.
  • The memory consumed by the bigd process increases in size until either of the following symptoms occurs:
    • The Linux kernel runs out of memory and terminates the bigd process (or potentially some other large memory usage process) a few hours after the system starts up.
    • The memory consumed by the bigd process increases to just under 4 GB in virtual size (vsize). This may result in unexpected monitoring behavior, such as the bigd process marking targets down that are not actually down or failing to detect targets that are down.

Workaround

You can work around this issue by switching to non-HTTPS monitors. When you switch to non-HTTPS monitors, you must ensure that you restart the bigd process to release the leaked memory. Restarting the bigd process should not impact service. To do so, perform the following procedure:

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To restart the bigd process, enter the following command:

    restart /sys service bigd
