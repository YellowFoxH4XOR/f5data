Known Issue

This is the result of a known issue. The BIG-IP system uses the MPI channel to exchange messaging information between TMM and plugin processes such as ASM. On CMP compatible systems, TMM uses the MPI channel to communicate with other TMM instances. When an MPI client, such as a plugin module, performs an operation that keeps the MPI channel saturated, TMM can poll the MPI queue indefinitely. As a result, TMM will crash due to a SIGABRT.

When TMM crashes with a SIGABRT, the system generates a TMM core file to the /shared/core directory, and logs a SIGABRT notice to the /var/log/tmm file that appears similar to the following example:

notice ** SIGABRT **

Additionally, the system generates logging indicating that TMM has failed to increment its heartbeat signal, and the BIG-IP system has performed the failsafe mechanism configured for the daemon. For example, when the heartbeat timeout for the TMM process expires, the system logs the following message to the /var/log/ltm file:

sod[2322]: 01140041:5: Killing tmm pid 2018.
sod[2322]: 01140041:5: Killing tmm1 pid 1867.
sod[2322]: 01140029:5: HA daemon_heartbeat tmm1 fails action is failover and restart.

F5 Product Development tracked this issue as CR119287 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, WebAccelerator, or WOM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.0.1-354.0-HF2 issued for BIG-IP version 10.0.1, and BIGIP-9.4.8-385.0-HF2 issued for BIG-IP version 9.4.8. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.
