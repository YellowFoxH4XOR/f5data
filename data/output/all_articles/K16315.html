Known Issue

BIG-IP APM may stop processing traffic and produce a core file while running Kerberos authentication.

This issue occurs when all of the following conditions are met:

  • There are at least two access policies configured with a Kerberos AAA authentication profile.
  • The SSO (single sign on) domain cookie settings of the first access profile are configured with a primary domain.
  • The SSO domain cookie settings of the second access profile are configured with a subdomain based on the primary domain used by the first access profile.

    For example:

    Primary domain: .f5.com
    Subdomain: .abc.f5.com

  • A user session is processed by the first access profile using the primary domain SSO.
  • The same user attempts a request that is processed by the second access profile using the subdomain SSO.

Impact

User access fails while the apmd service restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system logs messages similar to the following example in /var/log/apm file, correlating with the time of the /var/log/apm session resource access failures:

    err apmd[15747]: 01490000:3: AccessPolicyProcessor/AccessPolicy.cpp func: "terminate()" line: 382 Msg: current agent index is out of range"

  • The system logs messages similar to the following example in the /var/log/ltm file, correlating with the time of the /var/log/apm session resource access failures:

    notice apmd[15747]: 01490000:5: ** SIGABRT **

  • The apmd process produces a core file in the /shared/core/ directory.

    For example:

    apmd.bld0.0.141.core.gz
