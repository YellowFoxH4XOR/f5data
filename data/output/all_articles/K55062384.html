Description

When adding an SQL monitor to a pool member, that has parameters that are identical to those of an already configured SQL monitor, the monitoring may unexpectedly fail, and pool members may be marked down incorrectly.

With mysql servers as pool members, an error message may be visible on the BIG-IP in the /var/log/DBDaemon-0.log file:
The TCP/IP connection to the host 192.0.2.1, port 3306 has failed. Error: "The driver received an unexpected pre-login response. Verify the connection properties and check that an instance of SQL Server is running on the host and accepting TCP/IP connections at the port."

Environment
  • Pools with SQL servers as pool members
  • Multiple SQL protocol monitors that have identical send/receive strings
Cause

Connections made by the SQL protocol monitors are internally identified by comparing the following parameters:

  • the pool member IP
  • the TCP port number,
  • the send string (the SQL query)
  • the receive string (the expected response)

When all of the above match more in than one monitor instance, the monitoring process may be unable to assign the received responses to the monitor instance initiating the query.

Recommended Actions
  • Remove duplicate identical SQL monitors from the pool member
    -- or --
  • Change any of the parameters for the SQL protocol monitor that avoids the duplication.
Additional Information

For example, if the configured monitors both have the send string set up as:
    send "SELECT replicationresult FROM replicationstatus"
It may be possible to add an additional column that won't be checked by the monitoring, but which guarantees the two monitors have different send strings, such as:
    send "SELECT replicationresult,1 FROM replicationstatus"
and
    send "SELECT replicationresult,2 FROM replicationstatus"
