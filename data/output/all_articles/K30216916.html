K30216916: Restoring data snapshot from previous BIG-IQ version on BIG-IQ 8.x

Type
Support Solution
Published
2021-06-29
Updated
2023-02-21
Applies to
  • BIG-IQ Platforms
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K30216916

Description

On v8.x when you are trying to restore data snapshot from the 7.x or 6.x version, you see an error "Failed to restore <snapshot-name>"

Environment

  • BIG-IQ 8.x
  • ElasticSearch Data snapshot restore

Cause
On version v8.x we implemented additional elasticsearch security features. Snapshot without them can't be restored in GUI.    

Recommended Actions

1. Copy the snapshot name that you want to restore from the BIG-IQ CM data snapshot menu (System -> BIG-IQ DATA COLLECTION -> BIG-IQ Data Collection Cluster -> External Storage & Snapshots -> View History) 
 
2. Go to the CLI Bash on BIG-IQ CM and assign snapshot name to "snapname" variable:
snapname=<snapname>
Example: 
snapname=test7_1_statsversion5.6.2_2021-04-19t14-32-35.907z 

3. Create current indices file: 

curl -sk https://localhost:9200/_cat/indices?h=index|sort > /var/tmp/indices-cluster.txt

3. Run the below script. You should paste it all at once:

 curl -sk https://localhost:9200/_snapshot/backup/_all  | jq --arg snapname "$snapname" '.snapshots[] | select(.snapshot==$snapname)'| jq .indices | tr -d [ | tr -d ] | tr -d \" | tr -d , | sort -r | while read snap ; do
  egrep -q "^$snap$" /var/tmp/indices-cluster.txt ;
    if [ "$?" -ne "0" ] ; then
      echo "need to load $snap" ;
        curl -sk https://localhost:9200/_snapshot/backup/$snapname/_restore -sX POST -H "Content-type: application/json" -d "{\"indices\":\"$snap\"}" | jq . ;
        concurrent=503
        while [ $concurrent -eq 503 ] ; do concurrent=$(curl -sk https://localhost:9200/_snapshot/backup/$snapname/_restore -sX POST -H "Content-type: application/json" -d "{\"indices\":\"$snap\"}" | jq .status) ; echo "restoring..." ; sleep 5 ; done
    fi ;
done

4. Wait until it's done. It can take a lot of time, all depends how big is your snapshot. 

5. If you restored the APM/ASM data and you don't see them, re-enable the service listeners in  System -> BIG-IQ Data Collection Devices -> DCD Name -> Services menu
