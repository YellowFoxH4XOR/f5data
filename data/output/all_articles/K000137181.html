K000137181: How to migrate standalone BIG-IQ between platforms or virtual hosts

Description

This article describes the process of migrating from one standalone BIG-IQ to another (not HA pair). This can be physical hardware or Virtual Edition. This process involves backing up the BIG-IQ configuration, collecting utilization and inventory reports, then applying the backup file to the BIG-IQ in the new location. 

Environment

  • Standalone BIG-IQ (not in HA pair)
  • Flexible Consumption Program (FCP)
  • Physical platform or Virtual Edition
  • Migration

Cause

It is sometimes needed that a BIG-IQ will need to move between hosts or physical locations. This process will help minimise the impact.
Note: This solution is only applicable on a stand alone BIG-IQ, NOT a HA pair without any DCD.
Note: Remote BIG-IPs aren't impacted during this process.

 Recommended Actions

  1. Create a UCS backup of the “live” BIG-IQ config. It automatically saves to /var/local/ucs/ and appends the .ucs extension. The file is saved in /var/local/ ucs.
    tmsh save sys ucs <backup-file-name>

  2. Contact F5 Support to request an "allow-move" for the BIG-IQ device base registration key and any Catalog (CAT) base registration key. Alternatively, you can select "Unassign" for these keys via this subscription within your my.f5.com portal. Please allow 15 minutes before using them on the new BIG-IQ.

  3. Copy the encryption key from the original BIG-IQ
    f5mku -K

  4. Apply this key to the new BIG-IQ in the new location
    f5mku -r <key_value from original BIG-IP>

  5. Copy the UCS file to the “new” BIG-IQ that is running in a different environment to location:
    scp -p /var/local/ucs/<backup-file-name>.ucs <user>@<new-bigiq-IP>:/var/tmp

  6. Restore this UCS file to the new BIG-IQ:
    tmsh load sys ucs /var/tmp/<backup-file-name>.ucs
    To keep the management IP of the new BIG-IQ, add keep-current-management-ip. To keep the license currently applied to the new BIG-IQ and ignore the license in the *.ucs file, add no-license. If migrating to a different platform, add platform-migrate. The no-license switch can be combined with any of these options.
    Important: This step may require remote console access as SSH and WebUI connectivity will be impacted if the management IP changes.

  7. Once the status of the “new” BIG-IQ has been verified, turn off the original BIG-IQ, so that this new one becomes the source of truth for licenses and reporting.
