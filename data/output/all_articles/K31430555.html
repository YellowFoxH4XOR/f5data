Description

When running the preUpgradeCheck script, you may encounter error:

status key is not present as a part of the getresponse for the url : http://localhost:8100/cm/shared/esmgmt/external-command?target=_cluster%2Fhealth Please Check preUpgradeCheck script for more details.

Environment

  • output from preUpgradeCheck script for BIG-IQ

Cause

curl http://localhost:8100/cm/shared/esmgmt/external-command?target=_cluster%2Fhealth

Results from the above command do not reliably produce output that includes a "status" key.

Recommended Actions

You should see output like this:

  1. From the bash command shell of the BIG-IQ, run this command:

    curl http://localhost:8100/cm/shared/esmgmt/external-command?target=_cluster%2Fhealth

    You should see output like this:

    {
    "cluster_name":"cf8cfe6d-1022-4c34-ae4b-f2d1c541430f",
    "status":"green", <------ this is the status key that the preUpgradeCheck Script is looking for
    "timed_out":false,
    "number_of_nodes":3,
    "number_of_data_nodes":2,
    "active_primary_shards":447,
    "active_shards":894,
    "relocating_shards":0,
    "initializing_shards":0,
    "unassigned_shards":0,
    "delayed_unassigned_shards":0,
    "number_of_pending_tasks":0,
    "number_of_in_flight_fetch":0,
    "task_max_waiting_in_queue_millis":0,
    "active_shards_percent_as_number":100.0
    }

    You may see output like this:

    {
    "code":400,
    "message":"Request timed out.
    remoteSender:http://localhost:8100/cm/shared/esmgmt/external-command,
    uri:http://localhost:9200/_cluster/health,
    method:GET
    referer:http://localhost:8100/cm/shared/esmgmt/external-command",
    "restOperationId":534926464,
    "errorStack":[],
    "kind":":resterrorresponse"
    }

    If you don't get consistent results, or consistently get the code 400 results, ensure that your BIG-IQ has the required minimum resources of 8 CPUs, 32GB memory in order to maintain a consistent elasticsearch experience.
