Issue

Old Behavior

In versions prior to BIG-IP 14.1.0, hardware SYN cookies can only be used to protect a single IP address and port destination for a wildcard virtual server. If the BIG-IP system activates SYN cookie protection for a destination IP address and port, and then the BIG-IP system determines that another destination IP address and port require SYN cookie protection, that subsequent IP address and port SYN cookie protection are handled in software. For more information, refer to K50955355: BIG-IP hardware SYN cookie protection behavior with wildcard virtual servers.

New Behavior

Beginning in BIG-IP 14.1.0, certain F5 platforms can generate SYN cookies in hardware for wildcard virtual servers. All other F5 hardware platforms continue to use the old behavior. This new behavior applies to the following platforms and their variants:

  • BIG-IP iSeries i5x00, i7x00, i10x00, i11x00, i15x00
  • VIPRION B4450 series blade

    Note: The new behavior does not support Virtual Clustered Multiprocessing (vCMP). If vCMP is enabled, the BIG-IP system uses the old behavior.

F5 Product Development tracked this change as ID 685799.

Impact

Supported F5 hardware platforms that do not have vCMP enabled can perform SYN cookie generation and validation for wildcard virtual servers in hardware.

Recommended Actions

This feature is intended to replace VLAN-based hardware SYN cookie protection on supported platforms. If enabled, VLAN-based hardware SYN cookie protection takes precedence over per-virtual server based SYN cookie protection. Therefore, you should disable VLAN-based hardware SYN cookie protection to use this new feature.
