K8973: When a plugin filter references a NULL pointer and the next-hop MAC address does not exist, TMM may crash

Known Issue

This is the result of a known issue. When a plugin connection is established, the plugin filter attempts to pass the current next-hop MAC address to the plugin. If the next hop MAC address does not exist, a NULL pointer is referenced. As a result, the Traffic Management Microkernel (TMM) may crash.

This issue may occur when a route or self IP address is changed on the system while it is being used by an established connection flow. For example, one of the following conditions could cause this issue to occur:

  • A dynamic routing protocol is licensed on the system, and the routes are updated while a connection is in progress
  • A static route is manually changed using the Configuration utility or bigpipe command while a connection is in progress
  • A self IP address is changed resulting in an update to the routing table

F5 Product Development tracked this issue as CR100416 and it was fixed in BIG-IP 9.4.6. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.4-94.0-HF3, issued for BIG-IP 9.4.4, and in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP 9.4.5. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.
