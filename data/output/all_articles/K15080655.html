Issue

Description

The Mac EdgeClient or Browser VPN client remains in the Connecting state giving the impression of a disconnect/reconnect issue when connecting to the VPN. You may also see an error in the svpn logs: Failed to download pac file

Environment

  • BIG-IP APM Network Access in Full or Split Tunnel mode with a Client Proxy AutoConfig (PAC) script
  • BIG-IP Edge Client for MacOS
  • Browser Network Access Client

Cause

The VPN client is not able to download the PAC file from the specified location through the tunnel.

Recommended Actions

Review the log files

  1. Review the svpn.log file under /Users/<username>/Library/Logs/F5Networks for the following messages:

    <date>,<time>,, 1067,55910,svpn, 48, /MacPACHelper.cpp, 234, CPACHelper::PreparePACFileFromURL(), Loading Pac File from URL, http://<IP OR HOST>
    <date>,<time>, 1067,55910,svpn, 1, /MacPACHelper.cpp, 325, CPACHelper::WritePACFileFromURL(), Failed to download pac file, -3

  2. Confirm if the Network Access setting on the BIG-IP APM Ignore Client Proxy Autoconfig Script Download Failure is set. If this is the case then the VPN clients disregards the failure and continues to connect to the VPN. In order to check this setting verify the following:
    1. Log in to the BIG-IP Configuration utility.
    2. Go to Access >  Connectivity / VPN > Network Access (VPN) > Network Access Lists.
    3. Select your Network Access resource.
    4. Select the Network settings tab.
    5. For Client Settings, select Advanced.
    6. Ensure the option Ignore Client Proxy Autoconfig Script Download Failure is enabled.
    7. Select Update.
  3. You can also verify from the client side svpn.log file by searching for the following messages:

    <date>,<time>, 1215,71737,svpn, 1, /svpn.cpp, 319, SSLVpn::SetProperties(), pacignoreerror0, yes, 0
    <date>,<time>, 1215,71737,svpn, 1, /svpn.cpp, 1682, SSLVpn::svpn(), Error occurred for PAC file, but ignoring it

  4. If this setting is configured, the proxy auto-config failure is not what is causing the disconnect condition. 

Check your network routing

  1. Confirm Networking (Routing, DNS, HTTP) and PAC file availability in the following syntax:

    config # ip route get <IP>
