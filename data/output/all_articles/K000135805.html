Description

You have recently configured LDAP on a rSeries or VELOS device and encountered an "Authentication failed" error when attempting to log in with an LDAP user to the GUI:


 

Environment

  • LDAP server that is known to be working
  • rSeries or VELOS with LDAP Auth turned on and configured for users

Cause

The error might occur due to the lack of required attributes configured for the user account on the LDAP side. LDAP integration in F5OS requires that the users authenticating be assigned valid uidNumber and gidNumber Unix attributes.  These are often not present in Active Directory (AD) LDAP deployments.  The group used to provide access to the F5OS system should have a gidNumber attribute that corresponds to the group ID for the desired role.

Recommended Actions

In your LDAP or Active Directory product, set the gidNumber attribute for the user to the of Group ID corresponding to the desired role for the user: 

rSeries
admin           9000
operator        9001
resource admin  9003
tenant-console  9100

Note: version 1.8.0 added two additional group IDs. 
user            9002
superuser       9004

Velos partition
admin           9000
operator        9001
resource admin  9003
root            0
ts_admin        9100
user            9002
superuser       9004

For a Velos system Controller refer to the manual for the version in use. For 1.8.x Group IDs for system controller roles

The following example has a user named 'user' in an Active Directory group called F5OS Admins.

cn=user account,ou=users,dc=mysite
objectClass: user
uidNumber: 1234
gidNumber: 100    # some generic value (in AD it will often be this, which corresponds to, essentially, "all users")
samaccountname: username
memberOf: CN=group1,ou=groups,dc=mysite
memberOf: CN=group2,ou=groups,dc=mysite
memberOf: CN=F5OS Admins,ou=groups,dc=mysite
 
cn=F5OS Admins,ou=groups,dc=mysite
objectClass: group
gidNumber: 9000
member: cn=user account,ou=users,dc=mysite
member: someone else...
 
cn=F5OS Operators,ou=groups,dc=mysite
objectClass: group
gidNumber: 9001
member: cn=some other user...


A full guide with more details can be found at User Management Overview (techdocs.f5.com)

Additional Information

According to User Management Overview, if UID is not set, it defaults to 1001. However, to make authentication work, it is also needed to set UID on LDAP.
