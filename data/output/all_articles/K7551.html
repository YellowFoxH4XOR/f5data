Known Issue

This is the result of a known issue. The sys-reset command line utility can be used to restore the BIG-IP LTM to factory default values. When sys-reset runs, it first determines the BIG-IP platform by checking certain hardware components, and returns the BIG-IP LTM to its original configuration state. If sys-reset is unable to determine the hardware platform, it erroneously continues to run, rendering the BIG-IP LTM inoperative.

This behavior occurs when sys-reset is run by rebooting the BIG-IP LTM into single-user mode using the steps in K4178: Booting BIG-IP in single-user mode. For more information, refer to K7550: Resetting the BIG-IP system configuration to the factory default settings using the sys-reset command. When you use the steps outlined in K4178: Booting BIG-IP in single-user mode to boot the the BIG-IP LTM into single-user mode, the BIG-IP interfaces are not configured, and the sys-reset utility is unable to determine the platform type.

If sys-reset is run on BIG-IP interfaces that are not configured, the BIG-IP LTM will become inoperative following a reboot. Under these circumstances, the command line prompt indicates the status as inoperative, as shown in the following example:

[root@bigip:INOPERATIVE] #

F5 Product Development tracked this issue as CR82259 and it was fixed in BIG-IP LTM version 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

When this issue occurs, you must reinstall the BIG-IP software to return the the BIG-IP LTM to a functional state.

Note: To prevent this issue from occurring, perform the steps outlined in K7550: Resetting the BIG-IP system configuration to the factory default settings using the sys-reset command.
