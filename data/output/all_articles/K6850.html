Topic

The BIG-IP ASM system sets various types of cookies to enforce elements in the security policy:

  • ASM Main cookie
  • ASM Feature cookies
  • ASM Frame cookie
  • ASM Proactive cookie

The BIG-IP ASM system validates these cookies returning from the clients to ensure that the cookies are not modified. In BIG-IP ASM 11.4.0 and later, a random security key is generated uniquely to each deployment and combined with a configurable encryption algorithm to provide a security context for cookie protection. Prior to 11.4.0, the BIG-IP ASM system signs each cookie with an MD5 digest signature, which is verified upon return against a stored message key.

The ASM Main cookie

The ASM Main cookie is inserted into HTTP responses to client requests. The ASM Main cookie serves the following functions:

  • Validates domain cookies and qualifying subdomain cookies: The ASM Main cookie verifies that the domain and subdomain cookies that are sent from the web server to the client are not altered. The BIG-IP ASM system parses HTTP responses from the web server for the Set-Cookie header. If the Set-Cookie header is present, the BIG-IP ASM system performs a hash on the cookie and inserts the hash value into the ASM Main cookie.
  • Detects session expiration: The BIG-IP ASM system uses the ASM Main cookie to track user sessions for session expiration.
  • Validates the integrity of the ASM Frame or Feature cookies: The ASM Main cookie verifies the integrity of the ASM Frame or Feature cookies to ensure they are not altered.

    Note: F5 introduced validation of subdomain cookies in BIG-IP ASM 11.0.0. Prior to BIG-IP ASM 11.0.0, subdomain cookies triggered the Modified domain cookie violation.

In all currently supported versions of the BIG-IP system, the ASM Main cookie has a default expiration time of 600 seconds. The ASM Main cookie name structure is as follows:

  • BIG-IP ASM 11.4.0 and later

    The ASM Main cookie name structure contains eight hexadecimal characters (TSxxxxxxxx). The first two characters are the revision number and the remaining six characters represent the name of the active security policy.

  • BIG-IP ASM 10.0.0 through 11.3.0

    The ASM Main cookie name contains six hexadecimal characters (TSxxxxxx) that represent the name of the HTTP Class profile selecting the active security policy.

    Note: Starting in BIG-IP 11.4.0, the HTTP Class profile is replaced by the Local Traffic Policies feature. For more information, refer to K14409: The HTTP Class profile is no longer available in BIG-IP 11.4.0 and later.

The ASM Feature cookies

The ASM Feature cookies are set for client requests when one or more BIG-IP ASM features are activated or enabled, such as the following policy features:

  • Login/Logout page enforcement
  • CSRF enforcement
  • Session tracking
  • Dynamic parameters
  • CAPTCHA enforcement

The ASM Feature cookie format varies depending on the BIG-IP ASM version and the enabled feature. The structure is as follows:

  • BIG-IP ASM 14.0.0 and later

    The ASM Feature cookie name is constructed with eight hexadecimal characters and three decimal characters (TSxxxxxxxxd). The d in the name represents the type of feature being triggered in the BIG-IP ASM policy.

  • BIG-IP ASM 11.4.0 through 13.x

    The ASM Feature cookie name structure contains eight hexadecimal characters (TSxxxxxxxx_d). The d in the name is a decimal number representing the type of feature being triggered in the BIG-IP ASM policy.

  • BIG-IP ASM 10.0.0 through 11.3.0

    The ASM Feature cookie name structure contains six characters (TSxxxxxx_d) that are a hexadecimal representation of the HTTP Class profile name that holds the active security policy. The hexadecimal characters should match the ASM Main cookie's hexadecimal characters. The d in the name is a decimal number that represents the type of feature being triggered in the BIG-IP ASM policy.

The ASM Frame cookie

The ASM Frame cookie stores the referrer object and enforces dynamic flows attached to frames. The ASM Frame cookies have a default expiration time of 900 seconds.

The values of the ASM Frame cookies are rewritten each time a client accesses flow. The ASM Frame cookie serves the following functions:

  • Stores the referrer object
  • Tracks whether the referrer object is allowed to change the cookie

The ASM Frame cookie also handles the following dynamic data extractions:

  • Dynamic parameters names and values
  • Dynamic session extractions
  • Dynamic flow extractions
  • Dynamic parameter names extractions

The ASM Frame cookie length varies depending on the BIG-IP ASM version. The structure is as follows:

  • BIG-IP ASM 14.0.0 and later

    The ASM Frame cookie name is constructed with eight hexadecimal characters and three decimal characters (TSxxxxxxxxd). The d in the name represents the frame number that generated the flow, which can be a number between 001 and 025.

  • BIG-IP ASM 11.4.0 through 13.x

    The ASM Frame cookie name structure contains eight hexadecimal characters (TSxxxxxxxx_d). The d in the name represents the frame number that generated the flow, which can be a number between 1 and 25.

  • BIG-IP ASM 10.0.0 through 11.3.0

    The ASM Frame cookie contains six characters (TSxxxxxx_d) that are a hexadecimal representation of the HTTP Class profile name that holds the active security policy. The hexadecimal characters should match the ASM Main cookie's hexadecimal characters. The d in the name represents the frame number that generated the flow, which can be a number between 1 and 14.

The ASM Proactive cookies

The ASM Proactive cookies are used to enable features in Bot Defense and DoS Protection. The ASM Proactive cookies serve the following functions:

  • Store information for various proactive client-side challenges
  • Handle client device ID
  • Hold data for cross domain flow

The ASM Proactive cookie format varies depending on the BIG-IP ASM enabled feature. The structure is as follows:

  • The ASM Proactive cookies related to client-side challenges begin with the TSPD_101 prefix by default.
  • The ASM Proactive cookies related to cross-domain flow begin with the TSPD prefix by default.
