Description

Unexpected high availability (HA) failover occurs on BIG-IP ASM deployed in Google Cloud Platform (GCP) due to a Traffic Management Microkernel (TMM) process crash. The crash is caused by an assertion failure (empty xfrag) in the HTTP header rewrite logic, often associated with GCP infrastructure events such as live migration or host maintenance.

Symptoms:

  • HA failover event
  • TMM core file generated with SIGABRT signal
  • Assertion failure message: empty xfrag in lib/c/xbuf.c during HTTP header rewrite
  • Stack trace points to http_header_replace_impl function

Environment

  • Product: BIG-IP ASM
  • Version: 17.1.X
  • Deployment: Google Cloud Platform (GCP)
  • High Availability (HA) enabled

Cause

TMM process crash due to assertion failure (empty xfrag) in HTTP header rewrite logic. This is typically triggered by underlying hypervisor events in virtualized environments, such as live migration or host maintenance activities initiated by GCP Compute Engine. These events can disrupt virtual appliances, leading to process termination and HA failover.

Answer/Recommended Actions

  1. Check GCP Activity Logs and Events:
    • Review GCP Activity Logs for host maintenance, live migration, or similar infrastructure activities that align with the time of the failover.
  2. Configure GCP Maintenance Policies:
    • If such events are identified, consider configuring GCP host maintenance policies or scheduling planned maintenance windows to reduce impact on critical BIG-IP workloads.
  3. Update BIG-IP Software:
    • Keep BIG-IP software updated to the latest recommended version; assertion failures may be addressed in newer releases.
  4. Monitor System Logs:
    • Monitor system logs for recurring assertion failures and engage F5 support if issues persist outside scheduled cloud provider events.
  5. Evaluate Redundancy and Failover Strategies:
    • For deployments requiring high uptime, evaluate additional redundancy or alternative failover strategies to mitigate risks from cloud platform maintenance.

Additional Information

  • Assertion failures in TMM during HTTP header processing are often linked to virtualized environment events, especially in cloud platforms like GCP.
  • Failover behavior is expected when the TMM process terminates unexpectedly due to such assertion failures.
  • Proactively monitor and manage cloud provider maintenance schedules to minimize impact.
