K42915585: BIG-IP HA keeps intermittently going to partial sync status

Type
Support Solution
Published
2021-06-22
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IQ Platforms
  • BIG-IQ
  • BIG-IP
  • BIG-IQ Centralized Management: 8.X.X, 7.X.X
Source
https://my.f5.com/manage/s/article/K42915585

Description

BIG-IP HA flaps between In-Sync to partial sync status

Environment

  • BIG-IP's in HA
  • Devices previously  Managed by BIG-IQ

Cause

BIG-IP's were once managed by BIG-IQ and are trying to contact the BIG-IQ and update the f5.bigiq-analytics.tmpl 

Recommended Actions

  1. Watching the LTM log
      # tailf /var/log/ltm
     
  2.  You see the following error's
    * (OS versions may vary in error log) 

    var/log/ltm
    +++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
    Jun 22 11:46:09 Example.com.local notice mcpd[5534]: 0107167d:5: Data publisher not found or not implemented when processing request (unknown request), tag (61093).
    Jun 22 11:46:09 Example.com.local notice tmsh[25190]: 01420012:5: Loading schema version: 14.1.4
    Jun 22 11:47:25 Example.com.local notice tmsh[26149]: 01420012:5: /var/config/rest/iapps/staging/f5.bigiq-analytics.tmpl .
    Jun 22 11:47:25 Example.com.local notice tmsh[26149]: 01420012:5: Loading schema version: 12.1.0
    Jun 22 11:47:25 Example.com.local notice mcpd[5534]: 0107167d:5: Data publisher not found or not implemented when processing request (unknown request), tag (61093).
     
  3.  On both BIG-IP's run the following from the CLI (clears all previous BIG-IQ cache)
    *(no impact on BIG-IP traffic)
        # clear-rest-storage

    * NOTE: Avoid using clear-rest-storage on BIG-IP SSLO  as its removing configuration from systems.
     
  4. BIG-IP HA now stays in-sync and errors are no longer seen in LTM log
