Description

Due to the default value of a new sys db variable which has been introduced in newer builds (v14.1.5.1, v15.1.7, v16.1.3.1 and v17.0.0.1) to allow an admin to specify exactly how much of the management module's extra provisioning allocation can be used by restjavad, restjavad might end up being allowed to allocate less memory than on the older build. This can lead to restjavad restarts after an upgrade.

Environment

BIG-IP

Cause

In v14.1.5.1, v15.1.7, v16.1.3.1 and v17.0.0.1, there is a new sys db variable called provision.restjavad.extramb, which specifies the exact amount of extra memory which restjavad is allowed to allocate. This value defaults to 192 MB, which can in some scenarios be less than on versions which did not have this sys db variable present in them.

Recommended Actions

If restjavad issues are seen after upgrading to a build with sys db provision.restjavad.extramb present, then a simple way to fix it may be to set the value of provision.restjavad.extramb to 80% of the current value of provision.extramb. This will approximately match the behaviour of many older builds, which often had this value set to "192 MB + 80% of provision.extramb".

Additional Information

It is important to note that the value of provision.restjavad.extramb only controls how much of the total provision.extramb restjavad can allocate (ie. it does not set aside memory by itself from the host linux subsystem, unlike the provision.extramb variable), and that it's only valid when restjavad.useextramb is set to true.
