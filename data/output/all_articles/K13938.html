Known Issue

Data groups containing wildcard patterns may prevent the configuration from loading.

This issue occurs when one of the following conditions is met:

  • You reload the BIG-IP configuration after creating a string data group with a wildcard pattern within one of the records.
  • You upgrade from a version 10.x BIG-IP system that contains a string data group with a wildcard pattern within one of the records.

Beginning in BIG-IP 11.x, when configuring a string data group that contains a wildcard pattern, you must escape the wildcard pattern with the backslash ( \ ) character. If the wildcard pattern is not escaped, the tmsh command reports a syntax error when loading the configuration. In the affected versions, when you create a string data group that contains a wildcard pattern, the system omits the escape character when writing the configuration.

For example, the following string data group would cause this issue to occur:

ltm data-group internal /Common/dg1 { 
    records { 
        *.test.local { }
    } 
    type string 
}

Note: For additional information on using wildcard patterns, refer to the Wildcard Object Identifiers section of the tmsh man page.

Impact

Loading data groups fail in BIG-IP 11.0.0 and 11.1.0

The BIG-IP configuration fails to load if you use the tmsh command after creating a string data group that contains a wildcard pattern.

Configuration fails to load after upgrading from BIG-IP 10.x

The BIG-IP configuration fails to load after you upgrade from a version 10.x BIG-IP system that contains a string data group with a wildcard pattern within one of the records.

Symptoms

As a result of this issue, you may encounter the following symptoms:

Loading data groups fail in BIG-IP 11.0.0 and 11.1.0

  • Loading the configuration using the tmsh command results in an error that appears similar to the following example:

    config # tmsh load sys config
    Loading system configuration...
      /defaults/app_template_base.conf
      /defaults/config_base.conf
      /config/low_profile_base.conf
      /defaults/wam_base.conf
      /usr/share/monitors/base_monitors.conf
      /config/daemon.conf
      /config/profile_base.conf
      /defaults/fullarmor_gpo_base.conf
    Loading configuration...
      /config/bigip_base.conf
      /config/bigip_user.conf
      /config/bigip.conf
    Syntax Error:(at line: 24) the "create" command does not accept wildcard
    configuration identifiers

Configuration fails to load after upgrading from BIG-IP version 10.x

  • After upgrading from a version 10.x BIG-IP system, the Configuration utility displays an error that appears similar to the following example:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

Workaround

To work around this issue, you can edit the /config/bigip.conf file and escape any wildcard pattern within any string data group records. To do so, perform the following procedure:

Impact of workaround: This workaround is a temporary fix that enables the configuration to load. The issue will persist on the next config reload using the tmsh command. 

  1. Log in to the command line.
  2. Create a backup of the bigip.conf file, by running the following command:

    cp /config/bigip.conf /config/bigip.conf.`date +%m-%d-%Y`

  3. Edit the bigip.conf file and escape any wildcard pattern within any string data group records with the backslash (\) character.

    For example:

    ltm data-group internal /Common/dg1 {
        records {
            *.test.local { }
        }
        type string
    }

    When finished, the string data group in the configuration file should appear similar to the following example:

    ltm data-group internal /Common/dg1 {
        records {
            \*.test.local { }
        }
        type string
    }

  4. Save the changes and exit the file.
  5. Reload the configuration using the following command:

    tmsh load sys config
