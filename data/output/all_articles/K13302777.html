Issue

Error Message

warning tmm[<PID>]: 011e0003:4: Aggressive mode sweeper: <policy> (<context>) <#> Connections killed

In this error message, note the following:

  • <PID> is the process ID for the tmm process.
  • <policy> is the partition and name of the eviction policy that was triggered (BIG-IP 11.6.0 and later).
  • <context> is the context to which the eviction policy is associated (BIG-IP 11.6.0 and later).
  • <#> is the number of reaped connections.

For example:

  • BIG-IP 11.6.0 and later

    warning tmm[12663]: 011e0003:4: Aggressive mode sweeper: /Common/default-eviction-policy (vs /Common/vs_http) 10 Connections killed

  • BIG-IP 11.5.x and earlier

    warning tmm[12663]: 011e0003:4: Aggressive mode sweeper: 10 Connections killed.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when all of the following conditions are met:

  • The log.sweeper.activation.enabled database variable is set to true (default).
  • The BIG-IP adaptive connection reaper removes at least one connection flow due to one of the following factors:
    • Memory utilization exceeds the global adaptive reaping threshold.
    • The number of connections to a virtual server configured with an eviction policy exceeds the adaptive reaping threshold.
    • The number of connection flows in a route domain configured with an eviction policy exceeds the adaptive reaping threshold.

The BIG-IP adaptive connection reaping feature can be associated in a global context, or in the context of a virtual server or route domain. When the threshold for the aggressive sweeper is reached, the BIG-IP system reaps connections as needed and generates this message.

Impact

The adaptive connection reaper continues to reap connections while memory utilization or connection flows exceed activation thresholds.

Recommended Actions

When the BIG-IP system generates this error message, consider performing the following actions:

  • This message may indicate an overloaded virtual server or a high traffic load to the BIG-IP system. To mitigate this issue, you can reduce the traffic load to the affected virtual server or reduce overall traffic to the BIG-IP system. You may also be able to mitigate this issue by modifying the parameters in the eviction policy or by changing eviction policies.

    Note: F5 does not recommend modifying the default eviction policy. If you want non-default values, you should create a custom eviction policy.

  • In BIG-IP 12.0.0 and later, you can suppress this message by executing the tmsh modify /sys db log.sweeper.activation.enabled value false command. The adaptive connection reaper still reap connections; however, the system no longer generates this message.
  • For BIG-IP virtual edition (VE) instances if you have determined that the issue is capacity related, you can increase the amount allocated memory of the BIG-IP VE instance. For information about allocating additional memory to the BIG-IP VE system and reduce the TMM memory usage percentage, refer your hypervisor documentation.
