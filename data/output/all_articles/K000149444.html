K000149444: Adv.WAF False-Positive Malformed JSON Data Violation and the assigned JSON Profile N/A

Type
Support Solution
Published
2025-02-27
Updated
2026-06-11
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000149444

Description

Consider the recommendations in this article if a well-formed JSON request is being blocked due to a Malformed JSON Data Violation, and the assigned JSON profile appears as N/A in the event report. Additionally, ensure that the XML/JSON parser is neither under high load nor experiencing memory constraints.

Environment

Adv.WAF

Cause

The exact steps that triggered this behavior remain unidentified.

Recommended Actions

To work around this issue, simply make a minor, inconsequential change to the affected JSON profile and click Save. This action will trigger a health check and refresh the relevant MySQL table entries.

For a long-term fix, please perform the following steps and open a case with F5 to investigate further. If you need assistance going through these steps, please let us know in the case and we will be happy to assist.

(1) Create a backup of the existing bd logging configuration:

 # cp /etc/ts/bd/logger.cfg /etc/ts/bd/logger.cfg.original

 

(2) Add following statements/lines into /etc/ts/bd/logger.cfg file using editor of your choice:

MODULE=IO_PLUGIN;
LOG_LEVEL=TS_INFO | TS_DEBUG;
FILE = 2;
 
MODULE=ECARD_POLICY;
LOG_LEVEL=TS_INFO | TS_DEBUG;
FILE = 2;
 
MODULE=BD_XML;
LOG_LEVEL=TS_INFO | TS_DEBUG;
FILE = 2;
 
MODULE=XML_PARSER;
LOG_LEVEL=TS_INFO | TS_DEBUG;
FILE = 2;

 

(3) After setting the appropriate logging options for desired modules, you will need to run the following command for the changes to take effect:

 # /usr/share/ts/bin/set_active.pl --update_logger_cfg

 

(4) Upon replicating the behavior to gather the problematic data, you can disable bd debugging with the following one-liner command:

 # cp /etc/ts/bd/logger.cfg.original /etc/ts/bd/logger.cfg; /usr/share/ts/bin/set_active.pl --update_logger_cfg

 

Then collect the following data:

 (1) Event report showing N/A value assigned to profile field when the violation is Malformed JSON data.

(2) ASMqkview:

asmqkview -s 7864320000 --add-request-log --include-traffic-data

(3) Tarball of the logs.

(4) MySql Database files:

  mysqldump -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` AVR | gzip -9 > /shared/tmp/avr.dump.gz
  mysqldump -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` DCC | gzip -9 > /shared/tmp/dcc.dump.gz
  mysqldump -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` PLC | gzip -9 > /shared/tmp/plc.dump.gz
  mysqldump -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` PRX | gzip -9 > /shared/tmp/prx.dump.gz
   mysqldump -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` logdb | gzip -9 > /shared/tmp/logdb.dump.gz

Upload the collected data to the F5 Support case for review and additional troubleshooting.
