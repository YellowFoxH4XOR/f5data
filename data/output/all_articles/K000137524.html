K000137524: Missing IPv6 Listener in Sidecar Listener Table

Type
Support Solution
Published
2023-11-09
Updated
2024-09-24
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000137524

Description

When using the AspenMesh dual-stack cluster, ipv6 listeners are not created for each fqdn in ServiceEntry, only ipv4 listeners are created for each fqdn:

➜  aspenmesh-carrier-grade-1.14.6-am5 k get se
NAME                        HOSTS                                         LOCATION        RESOLUTION   AGE
external-svc-https          ["api.facebook.com"]                          MESH_EXTERNAL   DNS          4s
external-svc-https-second   ["api.dropboxapi.com","www.googleapis.com"]   MESH_EXTERNAL   DNS          50m
➜  aspenmesh-carrier-grade-1.14.6-am5 istioctl pc l -n simpleserver nettools-netadmin-5b8856f886-fgxx5 --port 443
ADDRESS       PORT MATCH                   DESTINATION
0.0.0.0       443  ALL                     Non-HTTP/Non-TCP
0.0.0.0       443  SNI: www.googleapis.com Cluster: outbound|443||www.googleapis.com <-
0.0.0.0       443  SNI: api.facebook.com   Cluster: outbound|443||api.facebook.com <-
0.0.0.0       443  SNI: api.dropboxapi.com Cluster: outbound|443||api.dropboxapi.com <-
10.96.0.1     443  ALL                     Cluster: outbound|443||kubernetes.default.svc.cluster.local
10.96.105.109 443  ALL                     Cluster: outbound|443||istiod.istio-system.svc.cluster.local
::            443  ALL                     Cluster: outbound6|443||api.dropboxapi.com <-

Environment

- Aspen Mesh Dual Stack cluster

- Istio Service Entry

Cause

ASM-4263: Invalid Listener Filter Chains for Service Entries in Dual Stack

Recommended Actions

Upgrade AM to 1.14.6-am6 where ASM-4263 is addressed:

https://clouddocs.f5.com/products/aspen-service-mesh/1.14/releases/1.14.6-am6/release-notes-carrier-grade.html

 

ASM-4263: Fixed an issue where—in a dual-stack installation of Aspen Mesh with service entries with a protocol of TLS and multiple hosts—communication fails for some of the hosts when clients initiate communication over IPv6.
