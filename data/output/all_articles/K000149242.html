Description

This article describes the limitations and available options for how you can automate Subject Alternative Name (SAN) Certificate Signing Requests (CSRs) on the BIG-IP.

Environment

  • BIG-IP
  • SAN CSR

Cause

There is no built in mechanism to automate CSR creation in BIG-IP. You can incorporate the iControl REST API into custom automation, but the /mgmt/tm/sys/crypto/key endpoint currently doesn't support the create action so you wouldn't be able to use the API for this case. Instead you could use a scripting language to run the tmsh create sys crypto command from K13471: Creating SSL SAN certificates and CSRs using the Configuration utility or tmsh.

Recommended Actions

You can use this example as a guide to automate creating CSRs using bash:

Make a file that contains the details for the CSR similar to this:

www.example.com "DNS:site1.www.example.com, DNS:site2.www.example.com, DNS:site3.www.example.com"
mail.example.com "DNS:site1.mail.example.com, DNS:site2.mail.example.com, DNS:site3.mail.example.com"
test.example.com "DNS:site1.test.example.com, DNS:site2.test.example.com, DNS:site3.test.example.com"

Then direct the file into a while read loop:

while read cn san; do tmsh create /sys crypto key $cn gen-certificate gen-csr common-name $cn country "US" lifetime 3650 subject-alternative-name $san; done < ./myCSRlist 

You can put in additional CSR details by including them in the file, adding the corresponding properties to the tmsh command, and include the associated variables in the while read loop.
