Known Issue

The system does not apply link reference changes to the currently running BIG-IP GTM or BIG-IP Link Controller server or virtual server object configuration.

This issue occurs when the following condition is met:

  • The BIG-IP GTM server is configured with multiple links.

Impact

  • BIG-IP GTM and BIG-IP Link Controller monitoring may mark the services for the server, or virtual server, as unavailable.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H435116 on the Diagnostics > Identified > High screen.
  • After you use the Traffic Management Shell (tmsh) utility to assign a specific link for a server, or virtual server, the Configuration utility does not reflect the change.
  • The BIG-IP GTM or BIG-IP Link Controller system continues to use the original link for the server or virtual server traffic instead of the assigned link.
  • Servers or virtual servers that are assigned a specific link may be marked as unavailable by the BIG-IP GTM system.

Workaround

To work around this issue, you can restart the BIG-IP GTM daemon, gtmd. To do so, perform the following procedures:

Impact of workaround: The BIG-IP GTM or BIG-IP Link Controller system cannot respond to any wide IP queries until the gtmd process starts.

Restarting the BIG-IP GTM process from the Configuration utility

  1. Using administrator privileges, log in to the Configuration utility of the affected BIG-IP GTM system.
  2. Click System, and then click Services.
  3. Select the gtmd service check box.
  4. Click Restart.

Restarting the BIG-IP GTM process from the tmsh utility

  1. Log in to the tmsh utility by typing the following command:

    tmsh
  2. Type the following command:

    restart /sys service gtmd
