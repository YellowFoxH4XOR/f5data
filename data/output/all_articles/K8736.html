Known Issue

This is the result of a known issue. When multiple host names resolve to a single virtual server IP address, and only a portion of those host names are configured in the HTTP class enabled for the BIG-IP WebAccelerator, requests to host names that are not configured may fail. If a request is sent to an unconfigured host name for an object that matches a RAM Cache entry created by a previous request to a configured host name, the request fails. In addition, an error message that appears similar to the following example is logged in the BIG-IP LTM file:

tmm[1575]: 01220001:3: TCL error: _sys_WA_ramcache_clientside <CACHE_UPDATE> - Illegal argument (line 13) invoked from within "CACHE::header replace "X-PvInfo" $cache_pvinfo"

F5 Product Development tracked this issue as CR117406 and it was fixed in BIG-IP 9.4.7. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

You can work around this issue by disabling RAM Cache for host names not enabled for the BIG-IP WebAccelerator. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Data Group Lists.
  5. Click Create.
  6. Type a name for the data group in the Name field.
  7. From the Type menu, select String.
  8. Type a host name for which the BIG-IP WebAccelerator is enabled.
  9. Click Add.
  10. Repeat Steps 8 and 9 for each host name for which the BIG-IP WebAccelerator is enabled.
  11. Click Finished.
  12. Click iRules.
  13. Click Create.
  14. Type a name for the iRule in the Name field.
  15. Type or paste the following iRule in the Definition field:

    when HTTP_REQUEST {
       if { not [matchclass [string tolower [HTTP::host]] contains $::accelerated_hosts] } {
          log "Disabling RAM Cache for requested host name: [HTTP::host]"
          CACHE::disable
       }
    }
  16. Click Finished.
  17. Associate the iRule with the virtual server.
