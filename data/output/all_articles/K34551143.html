Description

BIG-IP resets connection after HTTP response.

  • In /var/ltm/log you can see following error:

    011f0016:3: http_process_state_prepend - Invalid action:0x109010 Server sends too much data
    -or-
    011f0016:3: http_handle_pipelined_data - Invalid action:0x107000 Server sends too much data.

  • In a packet capture you can see TCP RST sent by the BIG-IP with following cause:

    F5RST(peer): HTTP Unexpected server data past end of response

  • Packet capture analysis in Wireshark shows following decoding error:

    Hypertext Transfer Protocol
    Leading CRLF previous message in the stream may have extra CRLF
       Expert Info (Error/Malformed): Leading CRLF previous message in the stream may have extra CRLF]
          [Leading CRLF previous message in the stream may have extra CRLF]
          [Severity level: Error]
          [Group: Malformed]

Environment

  • HTTP profile applied to the affected virtual server

Cause

The issue is caused by HTTP server appending CR/LF sequence in the middle of HTTP response body, which violates  RFC 7230.

Recommended Actions

The message indicates that the response received from the back end server is not RFC compliant. The back end server should be modified to correct this behavior.
