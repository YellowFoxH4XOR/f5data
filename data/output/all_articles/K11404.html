Known Issue

This is the result of a known issue. The BIG-IP system is unable to connect via ICMP to virtual addresses or floating self IP addresses that live in non-default route domains.

For example:

  • If a BIG-IP system is configured with the 192.168.1.10%20 floating self IP address, you would not be able to ping this address from within the host subsystem
  • If a BIG-IP system is configured with the 192.168.1.50%20:http virtual server, you would not be able to ping the 192.168.1.50%20 virtual address from within the host subsystem

This issue occurs because the BIG-IP system does not recognize virtual addresses or floating self IP addresses that live in non-default route domains as local addresses. Instead, the BIG-IP system tries to resolve these addresses on the route domain’s VLAN.

Note: For more information about route domains, refer to the BIG-IP TMOS: Implementations guide.

Note: Userland applications other than ping do not understand the route domain IP%ID notation. For more information, refer to K10467: Userland applications on a BIG-IP system cannot connect to hosts in non-default route domains.

F5 Product Development tracked this issue as ID 333359 (formerly CR139501) and it was fixed in BIG-IP version 11.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.
