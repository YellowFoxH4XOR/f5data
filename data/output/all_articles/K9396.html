Topic

Downloading a linearized PDF file through the BIG-IP WebAccelerator may fail when using a Firefox browser with the Adobe reader plugin. If the Firefox browser makes a multipart request for multiple byte ranges that overlap, the BIG-IP WebAccelerator will consolidate the overlapping byte ranges into a single range and send a single part response to the client. As a result, the Firefox Adobe plugin will hang because it is expecting a multipart response with a multipart/byte-range Content-Type HTTP header.

This issue is not considered a defect because the BIG-IP WebAccelerator response is RFC-compliant. However, F5 Product Development is tracking an enhancement to modify the BIG-IP WebAccelerator response behavior as ID 247127 (formerly CR109980).

Workaround

To work around this issue, choose one of the following three options:

  • Bypassing the BIG-IP WebAccelerator for PDF documents or Firefox clients
  • Using an iRule to modify the Accept-Ranges HTTP header
  • Using an iRule to rewrite a single part HTTP Response into a multi-part response
  • Proxying all requests for PDF documents

Note: Each option uses a different technique for disabling linearization for PDF documents. Linearization allows the first page to load first and display before the entire document is loaded. Without linearization, a large PDF document can take a long time to load completely. As a result, disabling linearization may increase the amount of time the user must wait to view the document.

Bypassing the BIG-IP WebAccelerator for PDF documents or Firefox clients

To prevent Firefox browser clients from hanging when downloading PDF files, you can use an iRule to bypass the BIG-IP WebAccelerator for PDF files, Firefox clients, or both.

Note: For detailed examples using the wa_bypass iRule variable to bypass the BIG-IP WebAccelerator, refer to K6882: Bypassing BIG-IP WebAccelerator with an iRule in version 9.4.x and K10127: Bypassing BIG-IP WebAccelerator with an iRule in version 10.x.

Note: For more information about iRules, refer to DevCentral and the iRules chapter in the Configuration Guide for BIG-IP Local Traffic Management.

Using an iRule to modify the Accept-Ranges HTTP header

Use an iRule to modify the Accept-Ranges HTTP header so the Firefox clients will ignore linearization. When the Accept-Ranges HTTP header is set to none rather than bytes, the client will not try to grab the document in linearized chunks.

For example:

when HTTP_REQUEST {
  set my_user_agent [HTTP::header "User-Agent"]
}

when HTTP_RESPONSE {
  if { ([HTTP::header "Content-Type"] equals "application/pdf") and ($my_user_agent contains "Firefox") } {
    HTTP::header replace "Accept-Ranges" "none"
  }
}

Proxying all requests for PDF documents

To configure the acceleration policy to proxy all requests for PDF documents, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click WebAccelerator.
  3. Click Policies.
    A new policies configuration page opens.
    Note: You cannot edit predefined acceleration policies. If you are using a predefined acceleration policy, you must copy the policy and edit the new user-defined acceleration policy. 
  4. Select the user-defined acceleration policy to edit.
  5. Expand the Site branch in the Policy Tree.
  6. Expand the Static branch in the Policy Tree.
  7. Expand the Documents branch in the Policy Tree.
  8. Click on the PDF node.
  9. Select Acceleration Rules from the Policy drop-down menu.
  10. Click on the Proxying menu tab.
  11. Select the Always proxy requests for this node option button.
  12. Click the Save button.
  13. Click the Publish button.
  14. Click the Publish Now button.

Note:  If you had to copy a predefined acceleration policy and created a new user-defined acceleration policy, you must also associate the new user defined policy with your BIG-IP WebAccelerator application.
