Topic

The BIG-IP APM system leverages the Secure Vault feature to securely store sensitive data, such as passwords and passphrases.

Description

The Secure Vault feature protects permanent storage of sensitive data in configuration objects (for example, AAA servers, Local User DB, and passphrases for cryptography keys). Secure Vault also secures sensitive data in temporary storage, for example, data in session variables that users provide while running an access policy.  For more information about Secure Vault , refer to K73034260: Overview of the BIG-IP system Secure Vault feature.

Sensitive data permanent storage

Sensitive data, such as AAA servers, administrtor passwords and secrets, AD delegation account passwords, and SSL private key passphrases are permanently stored in the BIG-IP system. Such data is encrypted with the master key and stored in the BIG-IP configuration file.

In the following example, the administrator password for the AAA LDAP server is stored encrypted in the configuration file:

apm aaa ldap /<partition>/<aaa_ldap> {
    admin-dn CN=Administrator,CN=<group>,DC=<domain>
    admin-encrypted-password $M$Lz$H/+1rtSqjFQBjXWSELlDeA==         
    base-dn DC=<domain>
    pool /<partition>/<ldap_pool>
}

Similarly, passphrases to secure cryptographic keys are also stored encrypted in the BIG-IP configuration file. For example:

sys file ssl-key /<partition>/<key_name> {
    cache-path /config/filestore/files_d/<partition>/<location_of_the_key>
    passphrase $M$Iq$Z85+Z1IybtbEaA0sYTDk0Q==      
    revision 1
}

Sensitive data temporary storage

When running a BIG-IP APM policy, the BIG-IP APM system stores the values that actions return in memory (sessionDB) in the form of session variables. User specific values in session variables remain in memory for the duration of the session, and the system can use the values for SSO purposes.

To secure sensitive data, such as a user password stored in memory (sessionDB), the BIG-IP APM system generates a random sequence as a session key. To enhance security, the generated BIG-IP APM session key is encrypted by the Secure Vault master key and stored as a global session variable in memory (sessionDB).  

You can use the command line utility sessiondump to display session variables and verify that sensitive data are not exposed.

Note: For detailed information about working with the sessiondump utility, refer to the Session Variable chapter of the Configuration Guide for BIG-IP Access Policy Manager. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Sensitive data temporary storage in Edge Client

Both BIG-IP Edge Client and F5 Access VPN client store the value of the primary BIG-IP APM session ID (MRHSession cookie value) temporarily in memory to re-establish existing authenticated sessions. After the application is closed, the memory is cleaned and the session ID is no longer stored.

If persistent cookies are enabled, the cookie value may be stored on disk while using BIG-IP Edge Client or F5 Access. Session ID storage in memory is not encrypted.

Sensitive data permanent storage in Edge Client

Windows and Mac Edge Client offer the capability to store the user's password if the Allow Password Caching option is enabled in the connectivity profile. When enabled, the data is stored using the following methods:

  • BIG-IP Edge Client for Mac

    The keychain stores the password to disk, and the Mac crypto functions store the password in memory.

  • BIG-IP Edge Client for Windows

    BIG-IP Edge Client uses Windows crypto functions to store the password to disk and memory. The system uses CryptProtectData and CryptUnprotectData for disk storage, and CryptProtectMemory and CryptUnprotectMemory for memory storage.
