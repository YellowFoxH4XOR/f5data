K000160301: BIG-IP APM VE Offline Due to SELinux Relabel Issue and /var/log Partition Full from Excessive Debug Logging

Type
Support Solution
Published
2026-03-11
Updated
2026-03-11
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160301

1. Description

The BIG-IP APM Virtual Edition appliance goes offline and repeatedly displays messages such as:

  • Broadcast message from systemd-journald: logger[xxxxx]: Re-starting localdbmgr

After recovery, the system reports critical disk space alerts:

  • Disk partition /var/log has only 5% free
  • Log disk usage still higher than 80% after logrotate and 24 times log deletion

These symptoms indicate a SELinux labeling issue (Bug ID 1044281) and excessive log generation due to non-default debug logging levels.

2. Environment

  • Product: BIG-IP APM Virtual Edition
  • Version: 17.1.3
  • Logging configuration: APM and web application logs set to "Debug" (non-default)
  • Condition: /var/log partition critically low on disk space
  • Symptoms triggered after system changes or upgrades

3. Cause

  • Bug ID 1044281: SELinux relabel not triggered, leaving files unlabeled, causing localdbmgr process to continuously restart.
  • Excessive debug-level logging for APM and web applications, filling /var/log partition.

4. Answer/Recommended Actions

  1. Restore Appliance from SELinux Relabel Issue:
  • Run the following command to trigger SELinux relabeling:
  1. touch /.autorelabel
  2. reboot
  • Wait for the system to relabel files and come back online.
  1. Resolve /var/log Partition Full:
  • Identify large files in /var/log:
    • find /var/log -xdev -type f -exec du -h {} \; | sort -rh | head -20
    • Check for large files such as btmp or snmpd.log and truncate or rotate as needed.
  • Reduce APM and web application logging levels to default:
  • View current level: tmsh list sys db log.accesscontrol.level
  • Set to default (Error): tmsh modify sys db log.accesscontrol.level value "Error"
  • Set web applications to Notice: tmsh modify sys db log.webapplications.level value "Notice"
    • Save config: tmsh save sys config
  • Force log rotation:
    • logrotate -f /etc/logrotate.conf
  • Verify disk space:
    • df -h /var/log
  • Check for deleted files still in use:
  • lsof -ws | grep -i 'size|deleted'
    • Restart relevant services if needed.

5. Additional Information

  • Excessive debug logging can quickly fill the /var/log partition and should only be enabled for troubleshooting.
  • Default logging levels are typically "Error" or "Notice" for most environments.
  • SELinux relabeling may take several minutes to complete.
