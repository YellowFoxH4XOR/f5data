K000138163: Not able to reload Nginx Plus server and get error 'APP_PROTECT No "error_line_number" found in error message'

Type
Support Solution
Published
2024-01-24
Updated
2025-02-07
Applies to
  • NGINX Products
  • NGINX Plus
Source
https://my.f5.com/manage/s/article/K000138163

Description

  • Not able to reload the Nginx App Protect instance service, the Nginx worker process ID never changed and get the errors similar to below in the error.log file.

APP_PROTECT No "error_line_number" found in error message

APP_PROTECT connection declined setting timer

APP_PROTECT setting reconnect timer

connect() to unix:/opt/app_protect/pipe/app_protect_plugin_socket failed (111: Connection refused)

 

  • If the Nginx App Protect is under the management of a Nginx Instance Manager or Nginx Controller, not able to modify its configurations.

 

Environment

Relevant environmental factors specific to the topic

  • Nginx App Protect
  • Nginx Plus, Nginx Instance Manager, Nginx Controller

Cause

The excessive number of policies in the 'nginx.conf' file led NAP WAF to open too many files, exhausting the available file descriptors. Nginx App Protect processes initiated by 'nginx -s reload' do not recognize the LimitNOFILE setting, nor does the 'nginx -s reload' command when not run from the systemd. Even setting a higher 'ulimit -n' in the shell executing 'nginx -s reload' doesn't affect the Nginx App Protect WAF processes, as they run in a separate internal session/shell.

 

Recommended Actions

You will need to modify the /etc/security/limits.conf file and set the open file limits on the system level by adding the following lines. The number also can be adjusted to the same value as the nginx.service file if the LimitNOFILE value is defined.

   nginx soft nofile 65536

   nginx hard nofile 65536
