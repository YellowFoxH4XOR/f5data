Description
With BIG-IP APM as OAuth Authorization Server, the OpenID Connect id_token may not contain the standard claims.

Environment

  • BIG-IP APM
  • OAuth Authorization Server
  • Support for OpenID Connect.

Cause
The "scope" must be set to "profile", to match the OpenID Connect specifications.

Recommended Actions

We need to update the scope:
  1. Navigate to Access  ››  Federation : OAuth Authorization Server : Scope
  2. Click the name of the scope in use; or: create a new scope
  3. For "Scope Name", put profile.
  4. Click "Update ..."
  5. Navigate to Access  ››  Federation : OAuth Authorization Server : Client Application
  6. Click the name of the affected application
  7. Scroll down to Security Settings, and for "Scopes", please ensure the scope as updated/created at step #3 is "selected"
  8. Click Update.
  9. If prompted, please click "Apply Access Policy" on the top left of the page.

Additional Information
From the OpenID Connect 1.0 specs:
OpenID Connect defines the following scope values that are used to request Claims:
profile: OPTIONAL. This scope value requests access to the End-User's default profile Claims, which are: name, family_name, given_name, middle_name, nickname, preferred_username, profile, picture, website, gender, birthdate, zoneinfo, locale, and updated_at.
