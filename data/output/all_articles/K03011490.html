Issue

You should consider using this procedure under the following condition:

  • Your BIG-IP system fails to update the IP Address Intelligence Service (IPI Subscription) database.
  • After an upgrade iprep_lookup fails.

Symptoms

When the iprepd service fails to retrieve subscription database updates, you may encounter the following symptom:

  • When reviewing the BIG-IP system IPI Subscription database using the tmsh show sys iprep-status command, the server contact date is not current or no data displays.
  • The system logs network errors to the iprepd.log file.

    Note: You can search for errors in the iprepd.log file using the grep ERR /var/log/iprepd/iprepd.log command.

  • The /var/IpRep directory is empty or contains only old files.
  • iprep_lookup fails:
    iprep_lookup  8.8.8.8
    opening database in /var/IpRep/F5IpRep.dat, /var/IpRep/F5IpV6Rep.dat
    ERROR: Failed to access IP reputation memory-map
    ERROR initializing IP reputation database.

Cause

The IPrep database  is not part of an upgrade. If the update fails, the IPrep database will never be initialised.

Recommended Actions

To verify BIG-IP communication to the IPI Subscription service update server, use the following procedures.

Procedures

When experiencing subscription database update issues, you can use the following troubleshooting steps to determine the root cause:

  • Verifying that the BIG-IP system can resolve the update server hostname
  • Verifying that the BIG-IP can connect with HTTPS to the update server
  • Verifying that the Webroot Threat Intelligence Platform status is operational
  • Enabling debugging for the iprepd service
  • Optional: Disabling debugging for the iprepd service

Verifying that the BIG-IP system can resolve the update server hostname

Ensure that your BIG-IP system is configured with an accessible DNS server in the DNS Lookup Server List, DNS server, and BIND Forwarder Server List.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP system.
  2. Enter the following command:

    nslookup <IPI Subscription service update server>

    Depending on your BIG-IP version, replace <IPI Subscription service update server> with the relevant server(s) from the following table.

    BIG-IP versionIPI Subscription service update server
    BIG-IP 15.1.6, 16.1.3, 17.0.0, and later
    • api.bcti.brightcloud.com (default)
    • localdb-ip-daily.brightcloud.com (base file)
    • localdb-ip-rtu.brightcloud.com (updates)
    • localdb-ipv6-daily.brightcloud.com (IPv6 updates)
    BIG-IP 15.1.4 and later for BIG-IP 15.1.x branch
    • api.bcti.brightcloud.com (default)
    • localdb-ip-daily.brightcloud.com (base file)
    • localdb-ip-rtu.brightcloud.com (updates)
    BIG-IP 13.1.0 and later (excluding BIG-IP 15.1.4.x)vector2.brightcloud.com
    BIG-IP versions prior to BIG-IP 13.1.0vector.brightcloud.com

Note: For systems licensed and provisioned with BIG-IP DNS (formerly known as BIG-IP GTM), use the nslookup <IPI Subscription service update server>. 127.0.0.1 command.

Verifying that the BIG-IP can connect with HTTPS to the update server

Test the connectivity with SSL from the command line of the BIG-IP system to the IPI Subscription service update server. Depending on your BIG-IP version, perform the procedure that applies to your BIG-IP version:

  • BIG-IP 15.1.4 and later for BIG-IP 15.1.x branch
  • All other supported BIG-IP versions (excluding BIG-IP 15.1.4.x)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

BIG-IP 15.1.4 and later for BIG-IP 15.1.x branch

Important: This procedure only applies to BIG-IP 15.1.4 and later for BIG-IP 15.1.x branch. For all other BIG-IP versions, refer to the All other supported BIG-IP versions (excluding BIG-IP 15.1.4.x) procedure.

  1. Log in to the command line of the affected BIG-IP system.
  2. Enable debug for the iprepd service by performing the Enabling debugging for the iprepd service procedure.
  3. Determine the device ID (DEVICEID) and unique ID (UID) of your BIG-IP system by entering the following command:

    grep Uid /var/log/iprepd/iprepd.log

    You should observe an output similar to the following example:

    iprepd|DEBUG|Nov 26 00:49:51.090|27705|Licensed: 1, Uid=123456789, Device ID=IPIntelligence-EVAL-Z100

  4. Disable debug for the iprepd service by performing the Optional: Disabling debugging for the iprepd service procedure.

  5. Initiate an HTTPS request against the IPI Subscription service server by entering the following command syntax:                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   curl -skvv 'https://api.bcti.brightcloud.com/1.0/ip/getthreatlist?oemid=F5&deviceid=<DEVICEID>&uid=<UID>' | jq .


    Using the device ID and unique ID you obtained in step 3, replace <DEVICEID> and <UID> with the value of the device ID and unique ID, respectively. For example, based on the example in step 3, enter the following command:

    curl -skvv 'https://api.bcti.brightcloud.com/1.0/ip/getthreatlist?oemid=F5&deviceid=IPIntelligence-EVAL-Z100&uid=123456789' | jq .

Enabling debugging for the iprepd service

If the connectivity tests are successful and you encounter an issue with the iprepd service not updating the IPI Subscription service server, you can enable debugging for the iprepd service.

Impact of procedure: Performing the following procedure temporarily suspends the IPI Subscription service.

  1. Log in to the command line of the affected BIG-IP system.
  2. Enable debug for the iprepd service by entering the following command:

    tmsh modify /sys db log.iprep.level value Debug

  3. Save the change by entering the following command:

    tmsh save /sys config

  4. Restart the iprepd service in debug mode by entering the following command:

    tmsh restart /sys service iprepd

Optional: Disabling debugging for the iprepd service

  1. Log in to the command line of the affected BIG-IP system.
  2. Disable debug for the iprepd service by entering the following command:

    tmsh modify /sys db log.iprep.level value Info

  3. Save the change by entering the following command:

    tmsh save /sys config

  4. Restart the iprepd service with debug mode disabled by entering the following command:

    tmsh restart /sys service iprepd
