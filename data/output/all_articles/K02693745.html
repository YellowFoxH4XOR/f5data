Chapter 4: Prepare to update or upgrade the BIG-IP system

Table of contents | << Previous chapter | Next chapter >>

Use this chapter to perform procedures that are commonly required to prepare for a BIG-IP system upgrade.

Successfully upgrading the BIG-IP system requires some planning and preparation, such as checking the current health of the system and backing up the configuration to a safe place on your network. Some steps are optional but recommended to ensure a better experience. Failure to perform these procedures may lead to unexpected downtime and extended maintenance windows.

Upgrade vs. update

This chapter may use the word upgrade to refer to either a software upgrade or update. For a definition that explains the difference between the two terms, refer to Upgrading vs. updating in the Introduction.

Consider a maintenance window

When you cannot guarantee a successful outcome of a future upgrade with full confidence, F5 recommends that you schedule a maintenance window. The duration of the maintenance window is not necessarily the time when the service is down; rather, it is the time when you cannot guarantee the service to be up as expected.

Consider the following points when determining the duration of the maintenance window:

  • The time required to complete the reboot into the new boot location—During this time, the active BIG-IP has no backup. When the active BIG-IP becomes unavailable before the standby completes the reboot, traffic is down until at least one BIG-IP comes up.
  • The time required to confirm that all the services are running as expected—For example, it is possible that, after the failover, your network drops some gratuitous ARP (GARP) announcements and keeps forwarding some IP addresses to the BIG-IP that is no longer active. For more information, refer to K7332: GARPs may be lost after a BIG-IP failover event. The more virtual addresses that you configured under the BIG-IP, the more time it usually takes to confirm that they all are operational.
  • The time required to roll back to the previous boot location—After upgrade, if your applications are not functioning as expected, you may need to restore services before you can troubleshoot.

Basic Configuration

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the BIG-IP system.
  • You have access to the Configuration utility, TMOS Shell (tmsh), and the Advanced Shell (bash). For information about accessing tmsh, refer to K12029: Accessing the TMOS Shell.

    Note: Confirm local admin and root user passwords before you begin the upgrade in case you have to perform troubleshooting during the upgrade process.

  • You installed SSH and secure copy protocol (SCP) client utilities on your local computer to access the BIG-IP system. Linux and Mac OS systems typically already have these utilities installed, but Windows users must install third-party tools such as PuTTY and WinSCP.

    Note: These links take you to resources outside of MyF5. The third parties could remove the documents without our knowledge.

    For more information about transferring files, refer to K175: Transferring files to or from an F5 system.

Download a BIG-IP update or upgrade image and matching MD5 checksum file

All F5 software downloads are located on MyF5 Downloads. You need to select an appropriate BIG-IP image and matching MD5 checksum file and save them to your desktop for uploading to the BIG-IP system. For example:

BIGIP-16.0.0-0.0.12.iso
BIGIP-16.0.0-0.0.12.iso.md5

The filenames should be identical, except for the .md5 extension on the checksum file. The checksum file is a text file that contains the calculated checksum value for the corresponding image file.

For specific instructions for downloading software, refer to K000090258: Download F5 products from MyF5.

Verify the MD5 checksum of the BIG-IP update or upgrade image

F5 provides several methods of performing image verification of downloaded software. For methods other than MD5 verification, refer to K24341140: Verifying BIG-IP software images using SIG and PEM files.

Windows systems

On Windows 7 and later, use the certutil utility to generate a hash checksum. For more information about the certutil utility, refer to certutil.

Note: This link takes you to a resource outside of MyF5. The third party could remove the document without our knowledge.

Impact of procedure: There is no impact to your BIG-IP system.

  1. From the Windows Start menu, enter cmd to open the command prompt. Perform the following commands at the command prompt.
  2. Use the cd command to change directories to where you downloaded the BIG-IP upgrade image file and the associated MD5 checksum file. For example:

    c:\Users\JohnSmith>cd Desktop

  3. Enter the following command syntax to calculate the BIG-IP image checksum and compare to the MD5 checksum file:

    certutil -hashfile <image_file.iso> MD5 & type <image_file.iso.md5>

    For example:

    certutil -hashfile BIGIP-16.0.0-0.0.12.iso MD5 & type BIGIP-16.0.0-0.0.12.iso.md5

    Output appears similar to the following:

    MD5 hash of BIGIP-16.0.0-0.0.12.iso:
    e4d36ec57f42ee880d157803e3c2a29a
    CertUtil: -hashfile command completed successfully.
    e4d36ec57f42ee880d157803e3c2a29a  BIGIP-16.0.0-0.0.12.iso

    The hash string from the certutil utility should be identical to the hash string value provided in the MD5 text file.

Mac OS or Linux systems

On a Mac OS or Linux system, use the md5sum utility to generate a hash checksum. For more information about the md5sum utility, refer to 6.5 md5sum: Print or check MD5 digests.

Note: This link takes you to a resource outside of MyF5. The third party could remove the document without our knowledge.

Impact of procedure: There is no impact to your BIG-IP system.

  1. Launch a command terminal. Perform the following commands at the command prompt.
  2. Use the cd command to change directories to where you downloaded the BIG-IP upgrade image file and associated MD5 checksum file.
  3. Enter the following command syntax to calculate the BIG-IP image checksum and compare to the MD5 checksum file:

    md5sum <image_file.iso> && cat <image_file.iso.md5>

    For example:

    md5sum BIGIP-16.0.0-0.0.12.iso && cat BIGIP-16.0.0-0.0.12.iso.md5

    Output appears similar to the following:

    e4d36ec57f42ee880d157803e3c2a29a  BIGIP-16.0.0-0.0.12.iso
    e4d36ec57f42ee880d157803e3c2a29a  BIGIP-16.0.0-0.0.12.iso

    The hash string from the md5sum utility should be identical to the hash string value provided in the MD5 text file.

Generate a QKView file for upload to F5 iHealth

Diagnosing and resolving existing issues prior to upgrading is a good way to prevent difficult troubleshooting issues after a failed upgrade. For example, you can perform a test restart of the BIG-IP system prior to update or upgrade. You should also review log files for critical system errors. One way to do so is to generate a QKview and verify system health on F5 iHealth. For more detailed information about the qkview utility, refer to K12878: Generating diagnostic data using the qkview utility.

BIG-IP 13.0.0 and later

Impact of procedure: The qkview utility runs a large number of commands when collecting information. This behavior may cause an additional performance burden on systems that are already under heavy load.

  1. Log in to the Configuration utility.
  2. Go to System > Support.
  3. Select New Support Snapshot.
  4. For Health Utility, select Generate QKView.
  5. Select Start.
  6. To download the output file, select Download.

BIG-IP 12.1.0 and earlier

Impact of procedure: The qkview utility runs a large number of commands when collecting information. This behavior may cause an additional performance burden on systems that are already under heavy load.

  1. Log in to the Configuration utility.
  2. Go to System > Support.

    The QKView check box is already selected.

  3. Select Start.
  4. When prompted, select Download Snapshot File to download the output file.

Upload your QKView diagnostic file to iHealth and review

After you obtain the QKView diagnostic file, upload the file to the iHealth system to diagnose the health and proper operation of your BIG-IP system. For more detailed information, refer to K27404821: Using F5 iHealth to diagnose vulnerabilities.

Impact of procedures: There is no impact to your BIG-IP system.

Upload your QKView diagnostic file

  1. Open a web browser and log in to F5 iHealth.

    Note: iHealth is free but requires registration. When you select the iHealth link, you are redirected to authenticate or register. For more information, refer to the F5 iHealth Diagnostic Tool page.

  2. Select Upload.
  3. Select Choose.
  4. After selecting the QKView file you downloaded, select Upload QKView(s).

    Note: The iHealth site prompts you when it finishes processing your QKView file. After it finishes, you can move to the next step.

  5. In the Hostname column, select the QKView file you uploaded by selecting the name for your device.

Review potential issues identified by iHealth

  1. Select Diagnostics.
  2. Review all identified potential issues the system displays.

Review a snapshot of the availability status of configuration objects on the device

This data documents whether configuration objects are up or down prior to an upgrade. If you need to troubleshoot after an upgrade, you can compare the status of these objects before and afterwards.

  1. Select Config Explorer.
  2. Select LTM.
  3. Select one of the following: Virtual Servers, Pools, or Nodes.

    The configuration objects display in a table that you can sort and filter by column.

Create a backup of the BIG-IP configuration

Create a user configuration set (UCS) archive of the BIG-IP configuration and save it to a secure remote location in case it is needed for recovery purposes. For more information about UCS archives, refer to K4423: Overview of UCS archives.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Archives.
  3. Select Create.
  4. For File Name, enter a name for the UCS file.

    Note: You must use a unique file name. If a file with the same name already exists, the system does not create the UCS archive file and a warning message displays, similar to the following example: The file already exists on the system.

  5. Optional: If you want to encrypt the UCS archive file, for Encryption, select Enabled and enter a passphrase. You must supply the passphrase to restore the encrypted UCS archive file.
  6. Optional: If you want to exclude SSL private keys from the UCS archive, for Private Keys, select Exclude. For example, exclude the private keys if you are sending the UCS file to F5 Support.
  7. Select Finished.
  8. When the system completes the backup process, examine the status page for any reported errors before proceeding to the next step.
  9. To return to the Archive List page, select OK.
  10. Select the File Name of the newly created UCS file.
  11. Select Download: <filename.ucs> to download the UCS file, then save to a secure remote location.

(Optional) Create a backup of the root crontab file

The root user crontab file (/var/spool/cron/root) is not captured in the UCS archive. If you added any customizations to the root users crontab file, make a backup of this file so that you can add your customizations to the new crontab file after you upgrade. If you have not made any customizations to your root user crontab file, skip this procedure.

Note: Do not overwrite the new /var/spool/cron/root file after booting to the newly installed BIG-IP system. Use the backup file only as a reference to re-add your customizations.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system using bash.
  2. View the contents of the root user crontab by entering the following command:

    cat /var/spool/cron/root

    The output looks similar to the following:

    MAILTO=""
    1-59/10 * * * * /usr/bin/diskmonitor
    0 */4 * * * /usr/bin/diskwearoutstat
    20 03 * * * /usr/bin/updatecheck -a
    20 03 11 * * /usr/bin/phonehome_upload
    13 * * * * /usr/bin/copy_rrd save

    # My custom crontab entry
    0 3 * * 1 /root/myScript.sh

  3. Copy the output from the terminal window and save to a text file on your local system.

Reactivate the BIG-IP license

BIG-IP license enforcement allows software upgrade for devices with active service contracts and that have a license activation date that is greater than the license check date of a given software release. Reactivating the license ensures that the configuration loads after upgrade. For example, the license check date built in to BIG-IP 16.0.0 is June 16, 2020. To upgrade your BIG-IP system to 16.0.0, your BIG-IP license service check date should be June 16, 2020 or later. For more information, refer to K7727: License activation may be required before a software upgrade for BIG-IP.

Note: If you manage BIG-IP licenses using BIG-IQ, ELA license reactivation may be required in BIG-IQ. For more information, refer to K84488720: Update the Service Check Date for a BIG-IP VE licensed by a BIG-IQ.

Verify the service check date of your license

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system using bash.
  2. View the service check date of your license by entering the following command:

    grep "Service check date" /config/bigip.license

    Output appears similar to the following:

    Service check date : 20200607

    Note: The date format is year-month-day, so this example output is June 7, 2020.

  3. Compare the output from step 2 to the license check date for BIG-IP 16.0.0 (June 16, 2020). If the service check date is June 15, 2020 or earlier, you need to reactivate your license.

Important: Do not upgrade the system if the service check date is earlier than the license check date. If the service date is earlier, you must first reactivate your license on the system.

Reactivate the system license

Impact of procedure: The license reactivation process may reload the configuration and temporarily interrupt traffic processing. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Go to System > License > Re-activate.
  3. Select either Automatic or Manual as the activation method.

    Note: If your system does not have internet access to the F5 license server, you must use Manual.

  4. Select Next and follow the instructions. For more information about automatic or manual activation, refer to K7752: Licensing the BIG-IP system.

Perform a configuration save

Systems with high uptimes can sometimes have issues that go unnoticed over time. Performing a configuration save prior to upgrading ensures that the current running configuration has been saved to disk.

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system using bash.
  2. To save the current running configuration to disk, enter the following command:

    tmsh save sys config

    Output appears similar to the following:

    Saving running configuration...
      /config/bigip.conf
      /config/bigip_base.conf
      /config/bigip_user.conf

Set up a serial console connection

You should set up a serial console connection to the BIG-IP system in the event that the upgrade does not go as planned and you are unable to establish network connectivity to the BIG-IP system after a restart. A serial connection allows you to monitor system installation and to shut down and start up activities, as well as perform administrative tasks without network connectivity. For more information, refer to K7683: Connecting a serial terminal to a BIG-IP system and K15372: Overview of the vconsole utility for vCMP guests.

(Optional) Perform a test restart of the BIG-IP system prior to update or upgrade

Systems with high uptimes can sometimes have issues that go unnoticed over time. Consider scheduling a test restart prior to performing an upgrade. If the BIG-IP system is part of a high availability (HA) device group, perform this procedure first on standby systems.

Impact of procedure: If the BIG-IP is not part of an HA device group, the restart process temporarily interrupts traffic processing while the BIG-IP completes the reboot process. When the BIG-IP is part of an HA device group, restarting the active BIG-IP system temporarily interrupts traffic processing while another member of the HA device group takes over traffic processing. When the BIG-IP is part of an HA device group, restarting the standby BIG-IP system does not affect traffic processing. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Device > General.
  3. In the Operations section, select Reboot.
  4. The BIG-IP system prompts with the message Are you sure you want to reboot this device?
  5. Select OK to begin the device restart.
  6. After restart completes, confirm proper operation of the BIG-IP system.

(Optional) Export analytics data prior to the update or upgrade

If you provisioned the F5 Application Visibility and Reporting module and configured the BIG-IP system to gather analytics data, you can export the analytics charts in PDF format from the BIG-IP system. Additionally, if you manage your BIG-IP system using the BIG-IQ system, you can export analytics chart data from the BIG-IQ.

After you complete the upgrade, analytics chart data from prior to the upgrade is still available on the device for you to examine. However, when you export the charts before you upgrade, you have a snapshot of multiple metrics that you can share with others in your organization who do not have access to the BIG-IP or BIG-IQ systems. If you need to troubleshoot issues after the upgrade, you may find it useful to be able to readily compare pre- and post-upgrade analytics data.

If you use a third-party tool to gather statistics from the BIG-IP, refer to the vendor's documentation to learn how to export the data.

Export analytics data from a BIG-IP system

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Statistics > Analytics, and then select an analytics data type, such as HTTP or TCP, or a sub-category of a type.
  3. At the top of the Overview page, use the time settings to select and filter by a specific time period.
  4. In the upper right, select Export.
  5. Select the option to save the file on your computer, and then select Export.

For more information, refer to the Examining and Exporting Application Statistics chapter of the BIG-IP Analytics: Implementations guide.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

Export managed BIG-IP analytics data from a BIG-IQ system

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ interface.
  2. Select Monitoring > Dashboards, and then the analytics data you want to see, such as Local Traffic > HTTP.

    Note: Not every dashboard has the option to export.

  3. On the right, in the filters pane, select the appropriate filters and options to display the analytics data you want.

    For example, you select BIG-IP Host Names, and then select the managed BIG-IP device you want to upgrade.

  4. At the top of the page, use the time and Display filters to display the analytics data you want.
  5. In the upper right, select Export > Charts with user expanded dimension data.
  6. Use the Print box to save the chart as a PDF on your computer.

    Note: The Print box differs depending on the OS of your computer.

For more information, refer to the Statistics Monitoring Overview chapter of the BIG-IQ: Monitoring and Reports guide.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

(Optional) Open a proactive service request with F5 Support

When you have planned the date for the upgrade, you can open a proactive service request with F5 Support to reduce the wait time to speak with a Support engineer in case you have any technical issues during the upgrade procedure. HA configuration

Introduction

When you upgrade a BIG-IP device group, F5 recommends that you upgrade standby systems first and boot to the newly upgraded boot location. After verifying that the configuration loaded properly, force a failover to the newly upgraded system. If traffic is flowing as expected, repeat the upgrade procedures on the next BIG-IP system, which is now in standby mode.

HA communication functions between major software branches using network failover, and you should use network failover for the duration of the upgrade process. For example, a pair of BIG-IP systems running BIG-IP 13.1.0 and 14.1.0 can negotiate active-standby status using network failover. For more information, refer to K8665: BIG-IP redundant configuration hardware and software parity requirements.

Configuration synchronization (ConfigSync) does not operate between different major software branches. For example, you cannot synchronize configurations from a system running BIG-IP 14.1.0 to a system running BIG-IP 13.1.0. You must wait for both systems to upgrade before ConfigSync can operate. For more information, refer to K13946: Troubleshooting ConfigSync and device service clustering issues.

Note: To reduce the time required for an upgrade, you can perform the procedures in this section prior to an upgrade, in a separate maintenance window.

Disable Automatic Sync

When the device group devices are on different versions, disable the Automatic Sync Type on the device group to prevent any sync failures that can occur in the middle of an upgrade. For more information, refer to K14624: Configure Automatic Sync to save the configuration on the remote devices.

Impact of procedure: When you disable Automatic Sync, you must manually synchronize configuration changes within the device group.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Device Groups.
  3. Select the device group you want.
  4. In the Configuration section, in the Sync Type list, select either Manual with Incremental Sync or Manual with Full Sync.
  5. Select Update to save the change.

Verify and update BIG-IP device certificates

The BIG-IP system uses the device certificate to authenticate access to the Configuration utility and accommodate device-to-device communication processes, such as ConfigSync. Prior to upgrading, verify that BIG-IP device certificates for each device in the device group are not expired. If your device certificates are expired or will expire before you complete the upgrade, renew them before you perform the upgrade.

Important: If you renew a device certificate on a BIG-IP system that is monitored using iQuery by BIG-IP DNS or a BIG-IP system that is part of a BIG-IP DNS sync-group, you must copy the new certificate to the trusted device certificate store on the remote BIG-IP DNS systems in the iQuery sync-group. For more information, refer to K6353: Updating an SSL device certificate on a BIG-IP system.

Impact of procedure: Viewing device certificate expiration should not have a negative impact on your system, but renewing the device certificate requires you to reauthenticate if you are using the Configuration utility.

  1. Log in to the Configuration utility.
  2. Go to System > Certificate Management > Device Certificate Management > Device Certificate.
  3. In the Certificate Properties section, in Expires, check the certification expiration.
  4. Do one of the following:
    • If the certificates are not expired, skip to the next procedure.
    • If the certificates are expired, continue to the next step.
  5. Select Renew.
  6. Review Certificate Properties, then select Finished.

    Your browser prompts you to accept the new certificate, and the Configuration utility prompts you to reauthenticate.

Perform a ConfigSync between device group systems

For HA BIG-IP systems, verify that all systems in the device group are in sync. For more information, refer to K13920: Performing a ConfigSync using the Configuration utility.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Overview.
  3. For Device Groups, select the name of the device group you want to synchronize.
  4. For Devices, select the name of the device from which you want to perform the synchronization action.
  5. For Sync, select the appropriate synchronization action.
  6. To synchronize from a device with an older configuration to a device, or devices, with a newer configuration, select Sync and Overwrite when prompted (BIG-IP 13.x and later) or enable Overwrite Configuration (BIG-IP 11.2.1 - 12.x).
  7. Select Sync.
