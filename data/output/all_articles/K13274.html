Known Issue

The iControl interface does not correctly report RAM Cache entry attributes.

This issue occurs when the following condition is met:

  • A Web Acceleration profile with RAM Cache entries is queried via either of the following iControl methods:

    • CacheEntry
    • CacheEntryExactMatch

Impact

iControl applications receive incorrect or incomplete system information.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The iControl LocalLB.ProfileWebAcceleration.get_cache_entry and LocalLB.ProfileWebAcceleration.get_cache_entry_exact_match methods will not report all the information available for RAM Cache entries. The tmm, rank, and slot attributes will not be returned for cache entries, as shown in the following example:

    {'expiration': 1311282051L,
    'hits': 25L,
    'host_name': 'MyBIG-IP',
    'last_sent': 1311282047L,
    'profile_name': My_Cache_Profile',
    'received': 1311282047L,
    'size': 1198L,
    'uri': '/my_page.html',
    'vary_count': 1L,
    'vary_type': 'CACHE_VARY_NONE'}

    By comparison, the tmm, rank, and slot attributes for the same entry are returned in the output of the show ltm profile ramcache My_Cache_Profile TMSH command, as shown in the following example:

    Host: MyBIG-IP
    URI : /my_page.html
    --------------------------------------
    Source Slot/TMM 0/3
    Owner Slot/TMM 0/0
    Rank 1

    Size (bytes) 1198
    Hits 25
    Received 2011-07-21 21:00:47
    Last Sent 2011-07-21 21:00:47
    Expires 2011-07-21 21:00:51
    Vary Type none
    Vary Count 1
    Vary User Agent none
    Vary Encoding none
