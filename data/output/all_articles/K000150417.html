Description

NTLM SSO is not working after the failover.

All setting is correctly set followed

  • K15503: BIG-IP APM HA considerations
  • K000137467: What are the BIG-IP APM session synchronization configuration requirements and expected session behavior during failover

TCPDUMP is taken on BIG-IP after enabling sslprovider value

tmsh modify sys db tcpdump.sslprovider value enable
tcpdump -s0 -ni 0.0:nnnp -w /var/tmp/<filename>.pcap --f5 ssl -vv host <client_IP>

on Both APM unit simultaneously, from the initial access before failover.

 

In the tcpdump on the new active unit's tcpdump shows backend server is sending

HTTP/1.1 401 Unauthorized

Why?

 

Environment

  • BIG-IP APM
  • Session mirror
  • Failover

 

Cause

Backend server (auth server) issue, as BIG-IP side is sending IP, NTLM headers, and credentials from the user, but MAC address (this can be confirmed with the original Active unit's tcpdump)

 

Recommended Actions

Follow the Troublwshooting and confirm auth server side issue.

  • K08915521: Troubleshooting issues with BIG-IP APM NTLM authentication: Enabling logging for NTLM on Windows server

 

Additional Information

You may want to try to use Mac Masquerade:

  • K13502: Configuring MAC masquerade (11.x - 17.x)
