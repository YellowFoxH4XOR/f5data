Description

GSLB configuration and zone files do not synchronize between BIG-IP DNS devices. iQuery connections fail to establish, and the following errors appear in GTM log /var/log/gtm:

iqmgmt_ssl_connect: IP: <Self IP> SSL error:14077410:SSL routines:SSL23_GET_SERVER_HELLO:sslv3 alert handshake failure

err big3d[<PID>]: 012b300e:3: SSL Error: error:1408A0C1:SSL routines:ssl3_get_client_hello:no shared cipher on connection to ::ffff:<self IP and port>.

err big3d[<PID>]: 012b3003:3: SSL error during shutdown: SSL SSL_ERROR_SSL

err gtmd[<PID>]: 011ae0fa:3: iqmgmt_ssl_connect: SSL error: SSL connect (1)

err gtmd[<PID>]: 011ae114:3: iqmgmt_ssl_connect: SSL error: error:14077410:SSL routines:SSL23_GET_SERVER_HELLO:sslv3 alert handshake failure (336032784) from connection <self IP>

iQuery status shows "not-connected" and repeated SSL handshake failures between gtmd and big3d.

Environment

  • BIG-IP DNS
  • Sync group
  • iQuery connection

Cause

The cipher suites configured for gtmd (iQuery client) and big3d (iQuery server) do not overlap, resulting in no shared cipher available for the TLS handshake. This prevents successful iQuery connections, prevents the GSLB configuration and zone file synchronization, prevent the monitor probing, etc.

Recommended Actions

  • Ensure that both gtmd and big3d are configured with at least one common cipher suite.
  • Reference articles for further guidance:
    • K05713133: Configuring the cipher strength for big3d using the tmsh utility
    • K31434426: Configuring the cipher suite for gtmd (iQuery client)
  • After making changes, verify that iQuery connection established, and GSLB configuration / zone files synchronize as expected.
