K8681: The bigpipe conn show command incorrectly displays the maximum idle timeout value for UDP connections when a UDP and SIP profile are used with a virtual server

Known Issue

This is the result of a known issue. When a UDP and SIP profile are both used with a virtual server, the bigpipe conn show command incorrectly displays the maximum idle timeout value, instead of the configured timeout value for idle UDP connections.

For example:

virtual test-vip {
   translate service disable
   pool test-pool
   destination 10.10.1.1:5060
   ip protocol udp
   vlans vlan10 enable
   profiles
      test_udp
      sip <-- Using default SIP profile
}

profile udp test_udp {
   defaults from udp
   idle timeout 300 <-- Idle timeout value listed at 300 seconds
   ip tos 0
   link qos 0
   datagram lb disable
   allow payload enable
}


The bigpip conn show command displays an incorrect maximum idle timeout value that appears similar to the following example:

VIRTUAL 10.10.1.1:5060 <-> NODE 192.168.1.16:5060   TYPE any
    CLIENTSIDE any6:any <-> any6:any
        (pkts,bits) in = (6, 4629)   out = (17, 9350)
    SERVERSIDE 10.1.5.27:5060 <-> 192.168.1.16:5060
        (pkts,bits) in = (6, 4629)   out = (17, 9350)
    PROTOCOL udp   UNIT 1   IDLE 29 (4294967295)   LASTHOP 63 40:91:0b:55:ee:77

The IDLE entry indicates that the connection has been idle for 29 seconds, but the idle timeout value is listed as 4294967295 seconds, which is the maximum timeout value allowed.

This issue is cosmetic. The BIG-IP LTM system will correctly remove any connections that exceed the specified idle timeout value within the UDP profile.

F5 Product Development tracked this issue as CR95134 and it was fixed in BIG-IP 9.4.5. For information about upgrading, refer to the BIG-IP LTM Release Notes.
