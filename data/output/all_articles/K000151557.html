Description

In BIG-IP ASM, requests with large bodies may be classified as "long requests" and stored in long request buffers for processing. This behavior can impact resource allocation and performance. A common question is whether setting the Request Body Handling action to Do Nothing at the URL level prevents requests from being classified as long requests, thus avoiding the allocation of long request buffers.

 

For detailed information, refer to:

K000139492: Understanding Long Request Handling in F5 BIG-IP ASM: Classification, Buffer Allocation, and Best Practices

https://my.f5.com/s/article/K000139492

 

Environment

BIG-IP ASM

 

Cause

When the Request Body Handling action is set to Do Nothing for a specific URL in an ASM policy, the request body is hold by ASM. Consequently, these requests are not classified as long requests and do not trigger the allocation of long request buffers.

 

Recommended Actions

To optimize resource usage and prevent specific requests from being classified as long requests:

 

  1. In your ASM policy, navigate to the relevant URL configuration.
  2. Once you are in the relevant URL, scroll down to the tab Header-based Content Profiles, in the Request Body Handling, set the action to Do Nothing for URLs that do not require body processing.
  3. Save and apply the policy changes.

This configuration ensures that affected URLs bypass long request processing and do not consume long request buffer resources, improving performance for those requests.

 

Additional Information

Ensure that setting Do Nothing aligns with your security requirements, as it disables ASM's inspection of the request body for the specified URLs.
