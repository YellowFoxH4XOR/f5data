K000150190: [F5OS] Duplicate SNMP-USER-BASED-SM-MIB config after restoring a backup file in a different device

Type
Support Solution
Published
2025-03-01
Updated
2025-03-01
Applies to
  • F5OS
  • F5OS-A
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000150190

Description

There is an SNMP user configured in an F5OS device. Then, a backup is taken from that device. After restoring the backup file into a different device, the username gets duplicated.


=== In the first backup, right after the SNMP user was created =====


<SNMP-USER-BASED-SM-MIB xmlns="http://tail-f.com/ns/mibs/SNMP-USER-BASED-SM-MIB/200210180000Z">

<usmUserTable>

<usmUserEntry>

<usmUserEngineID>xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx</usmUserEngineID>

<usmUserName>snmpuser</usmUserName>

<usmUserSecurityName>snmpuser</usmUserSecurityName>

<usmUserAuthProtocol>1.3.4.1.6.3.9.1.1.3</usmUserAuthProtocol>

<usmUserPrivProtocol>1.3.4.1.6.3.9.1.2.4</usmUserPrivProtocol>

<usmUserAuthKey>xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx</usmUserAuthKey>

<usmUserPrivKey>xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx</usmUserPrivKey>

</usmUserEntry>

</usmUserTable>

</SNMP-USER-BASED-SM-MIB>


===


==== After the first backup was restored and a second backup was created ===

<SNMP-USER-BASED-SM-MIB xmlns="http://tail-f.com/ns/mibs/SNMP-USER-BASED-SM-MIB/200210160000Z">

<usmUserTable>

<usmUserEntry>

<usmUserEngineID>xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx</usmUserEngineID>

<usmUserName>snmpuser</usmUserName>

<usmUserSecurityName>snmpuser</usmUserSecurityName>

<usmUserAuthProtocol>1.3.4.1.6.3.9.1.1.3</usmUserAuthProtocol>

<usmUserPrivProtocol>1.3.4.1.6.3.9.1.2.4</usmUserPrivProtocol>

</usmUserEntry>

<usmUserEntry>

<usmUserEngineID>yy:yy:yy:yy:yy:yy:yy:yy:yy:yy:yy</usmUserEngineID>

<usmUserName>snmpuser</usmUserName>

<usmUserSecurityName>snmpuser</usmUserSecurityName>

<usmUserAuthProtocol>1.3.6.1.6.3.10.1.1.3</usmUserAuthProtocol>

<usmUserPrivProtocol>1.3.6.1.6.3.10.1.2.4</usmUserPrivProtocol>

<usmUserAuthKey>xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx</usmUserAuthKey>

<usmUserPrivKey>xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx:xx</usmUserPrivKey>

</usmUserEntry>

</usmUserTable>

</SNMP-USER-BASED-SM-MIB>

===

Environment

  • F5OS backup restoration
  • SNMP username configured
  • Engine ID

Cause

When an SNMP user is read from a backup file and its engine ID is from a different system, a user with the same name is created with the current system's engine ID.

Recommended Actions

  1. After performing the restoration, delete and recreate the snmp user.

Additional Information

None.
