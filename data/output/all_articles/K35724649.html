Topic

You should consider using this procedure under the following conditions:

  • You have a VIPRION B2250 blade running on the C2200 or C2400 chassis.
  • You want to use a non-default FPGA firmware type (bitstream).

Important: The FPGA firmware types are optimized for a very specific setup, and should only be changed for specific configurations that will benefit from the change. F5 recommends consulting with F5 Professional Services before changing the FPGA firmware type.

Description

Beginning in BIG-IP 11.6.0, you can select the FPGA firmware type to load on supported BIG-IP platforms. Loading the FPGA firmware type determines the feature sets that are enabled on the BIG-IP system. The standard-balanced-fpga firmware is the default FPGA firmware type loaded on BIG-IP platforms. This firmware allows the system to use all features, and is a balance in performance for both Layer 4 (L4) and Layer 7 (L7) network traffic. You can choose from the following FPGA firmware types, depending on the hardware platform, provisioned modules, and software versions:

  • standard-balanced-fpga (also known previously as L7L4_BALANCED_FPGA)

The default standard-balanced-fpga firmware type is suitable for all uses and is the only firmware type that supports systems with Virtual Clustered Multiprocessing (vCMP) provisioned.

  • l4-performance-fpga (also known previously as L4_PERFORMANCE_FPGA):

The l4-performance-fpga firmware type is suitable for carrier-grade network address translation (CGNAT) standalone, rules-based firewall deployments, and BIG-IP LTM L4-centric deployments.

While the l4-performance-fpga firmware type has feature sets that are geared towards better L4 performance, the following feature sets are not supported in this firmware type:

  • Q-in-Q support
  • Hardware SYN cookies feature
  • Hardware denial-of-service (DoS) vectors
  • Hardware support for tunnels (NVGRE/VXLAN/EtherIP)

Important: The l4-performance-fpga firmware type is not recommended for the VIPRION C2400 chassis. The VIRRON C2400 chassis architecture has a limitation that does not fully support the l4-performance-fpga firmware type in all blade configurations. The l4-performance-fpga firmware type should only be configured on a VIPRION 2400 chassis that has one or four blades installed. Enabling the l4-performance-fpga firmware type on a VIPRION C2400 chassis with two or three blades installed may experience unexpected performance degradation and encounter high CPU usage and significant packet drops.

  • l7-intelligent-fpga

The l7-intelligent-fpga firmware type is suitable for BIG-IP DNS request hardware distributed denial-of-service (DDoS) validation and DNS hardware response cache. This option is configurable in BIG-IP 12.x only.

Prerequisites

You must meet either of the following prerequisites to use these procedures:

  • You have administrator access to the Configuration utility.
  • You have administrator access to the TMOS Shell (tmsh).

Procedures

  • Using the Configuration utility to configure the FPGA firmware type
  • Using tmsh to configure the FPGA firmware type

Using the Configuration utility to configure the FPGA firmware type

Impact of procedure: Switching the FPGA firmware type automatically restarts BIG-IP daemons, which disrupts network traffic.

  1. Log in to the Configuration utility.
  2. Navigate to System > Resource Provisioning > Configuration > FPGA Firmware Selection.
  3. Select the check box of the FPGA firmware type that you want to use.
  4. Click Submit.

Using tmsh to configure the FPGA firmware type

Impact of procedure: Switching the FPGA firmware type automatically restarts BIG-IP daemons, which disrupts network traffic.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Select the desired FPGA firmware type using the following command syntax:

    modify /sys fpga firmware-config type <desired_firmware>

    For example, to configure the l4-performance-fpga firmware type to be loaded on the BIG-IP, type the following command:

    modify /sys fpga firmware-config type l4-performance-fpga

  3. Save the change by typing the following command:

    save /sys config

Note: This change should be applied per guest when you are using vCMP.
