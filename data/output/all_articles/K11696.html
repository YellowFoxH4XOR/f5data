K11696: The BIG-IP WebAccelerator may append an equals sign to some custom Cache-Control directives

Known Issue

This is the result of a known issue. If an origin web server (OWS) sends a response with a custom Cache-Control directive that has not been assigned a value, and the response matches a policy node whose Client-Cache settings are set to Do Not Change, the BIG-IP WebAccelerator will insert an equals ( = ) sign into the directive when it sends the response to the client.

For example, the OWS may return a response containing the following header:

Cache-Control: foo

When this issue occurs, the BIG-IP WebAccelerator system modifies the header to appear as follows:

Cache-Control: foo=

Note: Configuring the Client-Cache setting with the Do Not Change option is intended to prevent the BIG-IP WebAccelerator from modifying the Cache-Control directives inserted by the OWS. However, the BIG-IP WebAccelerator may insert additional required directives into the Cache-Control header as in the following example:

Cache-Control: public, s-maxage=0, max-age=172800, foo=

F5 Product Development tracked this issue as CR132851 and it was fixed in BIG-IP WebAccelerator 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

If the Cache-Control header modification interferes with your application, you can bypass the BIG-IP WebAccelerator for requests of the affected objects. To do so, perform the procedure appropriate for your version as detailed in K6882: Bypassing BIG-IP WebAccelerator with an iRule in version 9.4.x or K10127: Bypassing the BIG-IP WebAccelerator with an iRule in version 10.x.
