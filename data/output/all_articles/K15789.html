Issue

You should consider using these procedures under the following conditions:

  • The BIG-IP system is configured to use the RADIUS protocol for authenticating application traffic.
  • The RADIUS authentication process fails for virtual server traffic.

Symptoms

As a result of RADIUS authentication failures, you may encounter the following symptoms:

  • The RADIUS authentication process fails for BIG-IP application traffic.
  • The BIG-IP system logs error messages related to RADIUS login failures.

Recommended Actions

The RADIUS protocol provides access control for network devices using one or more centralized servers. RADIUS operates over UDP and provides Authentication, Authorization, and Accounting (AAA) management for users connecting to a network service. RADIUS transactions are secure; messages sent between the BIG-IP system (client) and RADIUS server are authenticated through the use of a shared secret. In addition, the user passwords are sent encrypted between the client and server. To configure remote RADIUS authentication for application traffic for the BIG-IP system, you must create the following local traffic objects:

  • RADIUS server object: The server object includes the RADIUS server address that you are using to store the user accounts, RADIUS port and shared secret.
  • RADIUS configuration profile: The configuration profile references the RADIUS server object, and allows you to specify the client ID which is a string for the system to send in the Network Access Server (NAS)-Identifier RADIUS attribute.
  • RADIUS authentication profile: The authentication profile references the configuration profile, and RADIUS iRule.
  • The virtual server: The virtual server references the RADIUS authentication profile.

The RADIUS protocol

RADIUS is a client/server application layer protocol, using UDP as the transport. The officially assigned port number for RADIUS is 1812. When troubleshooting RADIUS transactions, it is helpful to understand the RADIUS packet format. RADIUS packets contain the following fields:

  • Code: The code field indicates the RADIUS packet type. For example, code type 1, indicates an Access-Request message.
  • Identifier: The identifier field matches a RADIUS request to a corresponding RADIUS response. For example, a RADIUS request message with an identifier value of 200, can be matched to a response message with an identifier value of 200.
  • Length: The length field indicates the length of the RADIUS packet.
  • Authenticator: The authenticator field is used to authenticate the reply from the RADIUS server. The two types of authenticator fields are Request Authenticator (sent in RADIUS request packets), and Response Authenticator (sent in RADIUS response packets).
  • Attributes: The RADIUS attributes field contains information such as authentication, authorization, and configuration details for the request and reply messages.

There may be times when you need to troubleshoot RADIUS authentication, or connections to the remote RADIUS server.

Procedures

When experiencing RADIUS authentication failure for application traffic, you can use the following troubleshooting steps to determine the root cause:

  • Verifying the RADIUS configuration on the BIG-IP system
    • Verifying the RADIUS server object
    • Verifying the RADIUS authentication configuration object
    • Verifying the RADIUS authentication profile
    • Verifying the virtual server object
  • Verifying RADIUS server availability
  • Reviewing the log files for RADIUS messages
  • Enabling debug logging for RADIUS authentication
  • Packet tracing RADIUS traffic
  • Debugging the RADIUS server

Verifying the RADIUS configuration on the BIG-IP system

When using the RADIUS protocol for authenticating application traffic, you must define the RADIUS server object, configuration object, the RADIUS authentication profile, and virtual server object. To verify the RADIUS configuration, perform the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Verifying the RADIUS server object

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Authentication > RADIUS Servers.
  3. Click the RADIUS server object.
  4. Verify that the following RADIUS server settings are correct and match the RADIUS servers:
    1. Host: Specifies the IP address of the RADIUS server
    2. Service Port: Specifies the RADIUS service port. The service port is 1812 by default.
    3. Secret: Specifies the secret key used to encrypt and decrypt packets sent or received from the RADIUS server.

Verifying the RADIUS authentication configuration object

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Authentication > Configurations.
  3. Click the RADIUS authentication object.
  4. Verify that the following RADIUS authentication configuration objects are correct:
    1. RADIUS Servers: The RADIUS server object from the above procedure should appear in the Selected box.
    2. Client ID: Specifies an identification string for the system to send in the NAS-Identifier RADIUS attribute.

Verifying the RADIUS authentication profile

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Authentication > Profiles.
  3. Click the RADIUS profile object.
  4. Verify that the RADIUS authentication configuration object appears in the Configuration drop-down menu.

Verifying the virtual server object

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the relevant virtual server object.
  4. Select Advanced from the Configuration menu.
  5. Verify that the correct RADIUS authentication profile is referenced in the Authentication Profiles section.

Verifying the RADIUS server availability

When experiencing RADIUS authentication issues for application traffic, you should verify that the BIG-IP system can access the RADIUS servers on the network. To verify the RADIUS server availability, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Determine the IP addresses of the defined RADIUS servers using the following syntax:

    list /ltm auth radius-server <radius_server_object>

    For example, the following command displays the RADIUS servers for a RADIUS server object named radius_srv:

    list /ltm auth radius-server radius_srv

    ltm auth radius-server radius_srv {
   secret $M$29$PiZuiLkQJAvm0mIRTZvduQ==
   server 172.24.171.1
}

     

  3. Use a utility, such as ping or traceroute, to verify network availability of the remote RADIUS server.

    For example:

    ping <radius_server_ip>

Reviewing the log files for RADIUS messages

If the RADIUS servers are available on the network, but fail to authenticate users, you may need to review the BIG-IP log files for relevant RADIUS messages. To review the log messages related to RADIUS authentication, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line using the root account.
  2. Use a Linux text utility, such as less or tail, to review the /var/log/secure file.

    For example:

    less /var/log/secure

  3. Review the log entries for error messages related to RADIUS login failures.

When reviewing the log entries for RADIUS login failures, you may view messages related to the following categories:

  • Bad username or password: When an administrative user attempts to log in using a bad username or password, the system logs messages similar to the following example:

    err tamd[6613]: pam_tacplus: unable to obtain username
    alert httpd[11037]: pam_unix(httpd:auth): check pass; user unknown

  • Invalid or incorrect secret key: When the BIG-IP system or RADIUS server is configured to use an invalid or incorrect secret key, the system logs error messages that appear similar to the following example:

    err httpd[11072]: pam_radius_auth: packet from RADIUS server 172.24.171.1 fails verification: The shared secret is probably incorrect.
    err httpd[11072]: pam_radius_auth: All RADIUS servers failed to respond.

  • The RADIUS server fails to respond or refuses the connection: When the specified service port or IP address for the RADIUS server is incorrect, or the RADIUS server is configured to only allow requests from a certain address range, the system logs error messages that appear similar to the following example:

    err httpd[27674]: pam_radius_auth: RADIUS server 172.24.171.1 failed to respond
    err httpd[27674]: pam_radius_auth: All RADIUS servers failed to respond.

Enabling debug logging for RADIUS authentication

You can enable debug logging for the RADIUS authentication configuration object, attempt to log in using remote user accounts, and then review the debug log files. To do so, perform the following procedure:

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor performance.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Enable debug logging using the following syntax:

    modify /ltm auth radius <radius_authentication_config> debug enabled

    For example, the following command enables debug logging for the RADIUS authentication configuration object named radius_config:

    modify /ltm auth radius radius_config debug enabled

  3. Test RADIUS authentication by attempting to log in using remote user accounts.
  4. After testing RADIUS authentication, disable debug logging using the following syntax:

    modify /ltm auth radius <radius_authentication_config> debug disabled

    For example, the following command disables debug logging for the RADIUS authentication configuration object named radius_config:

    modify /ltm auth radius radius_config debug disabled

  5. Review the /var/log/secure file for debug log messages.

Packet tracing RADIUS traffic

You may need to run tcpdump packet captures to troubleshoot RADIUS sessions. To packet trace RADIUS traffic, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. You can capture RADIUS traffic by running one of the following tcpdump captures:
    1. If the RADIUS server is reachable on the management network, use the following syntax:

      tcpdump -s0 -ni eth0 port 1812 -vw /shared/tmp/rad.pcap

    2. If the RADIUS server is reachable on a TMM network, the route to the RADIUS server is set in the BIGIP running the following syntax:

      ip route

      Note: When you have multiple self IPs for the vlan, without proper route, it may start using different IP address to initiate authentication. Please refer K000137708: After upgrade/reboot, Error message: Remote authentication server unreachable; local authentication failed.
    3.  and then use the following syntax:

      tcpdump -s0 -ni <vlan> port 1812 -vw /shared/tmp/rad.pcap

      Note: The -vw switches will write the output to /shared/tmp/rad.pcap and it will also start a packet counter to show if any packets are written to the file.

  3. You can view the capture file in packet analysis program for further debugging.

Debugging the RADIUS server

In some cases it may be necessary to debug the RADIUS server. Depending on your RADIUS server software, you may be able to perform the following tasks when debugging RADIUS server authentication issues:

Note: The steps to debug the RADIUS server will depend on the RADIUS software you are using. F5 recommends consulting your RADIUS server documentation for specific debugging steps.

  • Start the RADIUS server in debugging mode.

    For example, if you are using the FreeRADIUS server software, you can enable debug mode by entering the following command as the root user:

    radiusd -X

  • Test authentication for the specific user account from the RADIUS server.

    For example, if you are using the FreeRADIUS server software, you can test authentication for the user account using the following command syntax:

    radtest <username> <passwd> <radius-server[:port]> <nas-port-number> <secret>

    For example, the following command generates a successful Access-Accept message from the RADIUS server:

    radtest bigipadmin askf5123 127.0.0.1 0 testing123

    Sending Access-Request of id 188 to 127.0.0.1 port 1812
    User-Name = "bigipadmin"
    User-Password = "askf5123"

    NAS-Port = 0
    Message-Authenticator = 0x00000000000000000000000000000000

    Service-Type = Framed-User
