K000160959: BIG-IP ASM Fails to Start Due to Long Regular Expressions in Swagger/OpenAPI Imports, bd in boot loop

Type
Support Solution
Published
2026-04-23
Updated
2026-04-23
Applies to

  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160959

Description

BIG-IP ASM may fail to start and enter a restart loop if a security policy contains regular expressions longer than 255 characters, typically imported via OpenAPI/Swagger files. This results in the ASM bd process failing to parse the configuration during reloads, causing the device to remain offline. Relevant log messages include "Protobuf parsing error: could not parse protobuf message", "CONFIG_TYPE_ACCOUNT_PREREQUISITE_VALID_CRITERIA", and errors in bd.log and ts_debug.log referencing regular expression tables.

Environment

  • BIG-IP ASM versions: 17.1.3, 17.1.3.1, 17.5.1.3, 17.5.1.4
  • Applies to both Virtual Edition and hardware platforms
  • ASM policies created or updated via OpenAPI/Swagger file import
  • Policies containing regular expressions exceeding 255 characters

Cause

Bug ID 1848541: The system does not validate the length of regular expressions during Swagger/OpenAPI import. Regex patterns longer than 255 characters are accepted and stored in the database. Upon configuration reload (e.g., reboot or upgrade), the bd process fails to parse these entries, causing ASM to remain offline.

Answer/Recommended Actions

A. Identify and Remove Problematic Regular Expressions

 

  1. Connect to the BIG-IP system via SSH.
  2. Identify regex entries longer than 255 characters:
    # mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "
SELECT 
 'DCC.GLOBAL_PARAM_REG_EXPS' AS source_table, 
 'N/A (Global)' AS policy_name,
 g.app_id, 
 g.reg_exp_crc, 
 CHAR_LENGTH(g.reg_exp) AS length,
 g.reg_exp
FROM DCC.GLOBAL_PARAM_REG_EXPS g
WHERE CHAR_LENGTH(g.reg_exp) > 255
UNION ALL 
SELECT 
 'DCC.ACCOUNT_PARAM_REG_EXPS' AS source_table, 
 p.name AS policy_name,
 a.app_id, 
 a.reg_exp_crc, 
 CHAR_LENGTH(a.reg_exp) AS length,
 a.reg_exp
FROM DCC.ACCOUNT_PARAM_REG_EXPS a
LEFT JOIN PLC.PL_POLICIES p ON a.policy_name_crc = p.policy_name_crc
WHERE CHAR_LENGTH(a.reg_exp) > 255 \G"
  3. Remove the identified problematic regex entries (replace <CRC> with the actual reg_exp_crc value):
    # mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "use DCC; delete from GLOBAL_PARAM_REG_EXPS where reg_exp_crc = '3972098274'"
# mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "use DCC; delete from ACCOUNT_PARAM_REG_EXPS where reg_exp_crc = '3972098274'"
  4. Restart the ASM service:
    # tmsh restart sys service asm

     

B. Prevent Future Occurrences

  • Before importing Swagger/OpenAPI files, validate that all regex patterns are 255 characters or fewer.
  • Use the provided Python script (see Additional Information) to scan Swagger files for long regex patterns prior to import.
  • Avoid syncing ASM policies from nodes with suspected database corruption.
  • Monitor for future software updates that address this validation gap.

Additional Information

  • The 255-character regex length limitation is not currently documented in public F5 resources but is enforced at the database level.
  • To map a reg_exp_crc to a specific policy, use the SQL query above which joins the regex tables with policy names.
  • Removing problematic regex entries and restarting ASM should restore service.
  • Bug ID 2285497 tracks the lack of GUI warnings when long regex patterns are excluded during Swagger import.
  • A Request For Enhancement (RFE) has been filed to increase the maximum regex length to 512 characters for Alpha-Numeric parameters.
