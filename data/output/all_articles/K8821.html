Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator does not support cookie insert persistence for pools configured to use * All Services (service port 0).
 
If you use cookie insert persistence and the pool contains members configured with service port 0, the cookie generated uses the encoded port of the virtual server rather than that of the pool member. When the next request comes to the WebAccelerator-enabled virtual server, the persistence cookie does not match a pool member, so the request is treated as new, and the request can be load balanced to another web server in the pool.

F5 Networks Product Development is tracking this issue as CR76474. 

Workaround
 
For pools associated with WebAccelerator-enabled virtual servers, use pool members configured with specific ports. Do not configure pool members to use * All Service (service port 0).
