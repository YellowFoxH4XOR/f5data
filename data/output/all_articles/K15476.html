Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when using an iRule table command with large datasets.

This issue occurs when all of the following conditions are met:

  • An iRule contains a table command, such as set, add or replace, which attempts to insert a large set of data (more than 128k):

    when CLIENT_ACCEPTED {
    set base "abcdefghijklmnopqrstuvwxyz01234567890...."
    set val ""
    while {[string length $val] < 132000} {
    append val $base
    }

    set s_addr [IP::client_addr]
    table set $s_addr $val
    }
  • Session mirroring is enabled between BIG-IP high-availability devices.

    Note: Session mirroring is enabled by default through the StateMirror.MirrorSessions database variable.

Impact

The BIG-IP system will temporarily fail to process traffic as it recovers from the TMM restarting.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H474192 on the Diagnostics > Identified > High screen.
  • The TMM stops responding and produces a core in the /var/core directory.
  • An error similar to the following appears in any of the /var/log/tmm files:

    notice panic: ../modules/hudproxy/ha/ha_proxy.c:2134: Assertion "ha pkt is within size limit" failed.

Workaround

To work around this issue, revise the iRule to avoid insertion of large datasets.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure any modification is compatible with your environment.
