K93404447: Identifying a Memory Leak in TMM

Type
Support Solution
Published
2021-08-31
Updated
2023-02-21
Applies to
  • BIG-IQ
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K93404447

Description

TMM fails and restarts for an unknown reason.

The following error message may be observed in /var/log/ltm

01140029:4: HA proc_running tmm fails action is go offline and down links.

Environment

  • BIG-IP or BIG-IQ
  • tmm memory usage increasing over time without releasing.

Cause

Any number of tmm memory leaks. For example, Bug ID 903905

Recommended Actions

Determine if a tmm Memory Leak is Occurring

To determine if any tmm memory cache is leaking memory, we can review the Traffic Management snapshot files with the tmctl utility.

  1. SSH to log into the Advanced Shell (bash) prompt of the BIG-IP

  2. Run the following command

    (echo time,name,allocated,max_allocated;for name in $(tmctl -f /var/tmstat/cluster/blade0-public  -w 300 memory_usage_stat -q -s name);do tmctl -D /shared/tmstat/ -qc -w 3000 memory_usage_stat name="${name}" -s time,name,allocated,max_allocated;done | awk -F, -v a=0 -v b=0 -v c=$1 '{if($3==$4&&$3!=0&&$3>a&&$4>b&&$2==c){print};a=$3;b=$4;c=$2}')  | column -t -s,

    Note: To identify a TMM memory leak on vCMP host systems change the line, tmctl -f /var/tmstat/cluster/blade0-public to the following: tmctl -d /var/tmstat/blade/

With xdata and xhead memory usage increasing, consider reviewing the connection counts to determine if curr_conns continues to increase.

tmctl -D /shared/tmstat  tmm_stat -s client_side_traffic.max_conns,client_side_traffic.cur_conns,server_side_traffic.max_conns,server_side_traffic.cur_conns -w 400
