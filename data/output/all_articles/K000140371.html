Description

In some situations, a user might accidentally delete configuration objects from a Security Policy and realize the action before clicking the "Apply policy" button. In this situation, the Security policy will not apply the change so there will not be any impact on the environment, but the "Apply policy" button will remain and the deleted objects will not be displayed.

For example, if "Allowed URLs" are deleted, if the change is not applied there will not be any impact as the system is using the previous configuration, but when navigating to the "Allowed URL" menu, there won't be any URLs to be displayed.

Environment

  • ASM policy history

Cause

User mishandling.

Recommended Actions

In this situation to revert the changes made without applying the policy you can directly load the the most recent policy history version. Note that every time a policy change is "Applied", ASM will create a policy history version entry. The most recent policy history version contains the configuration of the most recent working configuration.

Security -> Application Security -> Security Policies -> Policies List -> Choose Policy -> General Settings -> Version
