Description

This article aims to collect the data when iControl SOAP API cannot work as expected.

Environment

  • BIG-IP
  • iControl SOAP API

Cause

None

Recommended Actions

  1. Run the following command on the BIG-IP device, enable debug:

# tmsh modify /sys db icontrol.loglevel value debug 

  1. Run the following command on the BIG-IP device:

# tmsh modify /sys httpd ssl-ciphersuite NONE:RSA

  1. Run the following command on the BIG-IP device:

# tmsh save /sys config

  1. Type the following commands:

# cp /config/httpd/conf.d/ssl.conf /config/httpd/conf.d/ssl.conf.original

# vi /config/httpd/conf.d/ssl.conf

Locate the following lines:

#SSLSessionCache        dc:UNIX:/var/cache/mod_ssl/distcache
#SSLSessionCache         shmcb:/var/cache/mod_ssl/scache(512000)
SSLSessionCache         dbm:/var/cache/mod_ssl/scache
SSLSessionCacheTimeout  300

Modify the lines above by disabling session cache:

#SSLSessionCache        dc:UNIX:/var/cache/mod_ssl/distcache
#SSLSessionCache         shmcb:/var/cache/mod_ssl/scache(512000)
#SSLSessionCache         dbm:/var/cache/mod_ssl/scache
SSLSessionCache         none
SSLSessionCacheTimeout  300

Save and exit.

  1. Run the following command on the BIG-IP device:

# tmsh restart /sys service syslog-ng httpd

  1. Run the command below to capture the packets:

    If the client access the self IP:

# tcpdump -s 0 -i 0.0 host <Client IP> -w /shared/tmp/filename.pcap

If the client access the management IP:

# tcpdump -s 0 -i eth0 host <Client IP> -w /shared/tmp/filename.pcap

  1. On the client, access the device via SOAP API, reproduce this issue.

  2. Stop tcpdump, collect the qkview.

  3. Run the command below, generate the pms file

# ssldump -r /var/tmp/filename.pcap -k /config/httpd/conf/ssl.key/server.key -M /var/tmp/filename.pms

  1. Collect the qkview, pcap file and pms file, upload to F5 support.

Additional Information

Restart the httpd maybe cause the issue gone, if gone, please monitor the device, and collect the data if the issue happened again.
