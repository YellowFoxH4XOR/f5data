Description

On HTTP profile enabled VS, when pool member is replying to BIG-IP with non compliance HTTP request, BIG-IP will reset the connection with "[F5RST(peer): Malformed HTTP header error]".

 

For example, when doing packet capture the following can be detected in Wireshark under HTTP field

 

30 45.114819 0.000011 x.x.x.x 443 y.y.y.y 1234 HTTP 1101 IN s1/tmm3 : HTTP/1.1 200 OK (text/html) HTTP

Hypertext Transfer Protocol
  HTTP/1.1 200 OK\r\n
  Cache-Control: no-store\r\n
  Content-Type: text/html; charset=utf-8\r\n
  Content-Encoding: gzip\r\n
  X-Frame-Options : SAMEORIGIN\r\n
  [Expert Info (Warning/Protocol): Illegal characters found in header name]
    [Illegal characters found in header name]
    [Severity level: Warning]
    [Group: Protocol]

 

The error is due to a n unexpected white space before ':' in the HTTP header.

 

Working

X-Frame-Options: SAMEORIGIN

 

Not Working

X-Frame-Options : SAMEORIGIN

 

Environment

BIG-IP LTM

HTTP Profile

[F5RST(peer): Malformed HTTP header error]

Cause

There's a white space between header name and :

Recommended Actions

Remove the white space in header from server response

Additional Information

None
