Description

Audit logs on multi-blade platforms (like VIPRION) show a huge amount of below logs:

client Unknown, user mcpd-primary - transaction #5732844-1 - object 0 - modify { global_sync_status { global_sync_status_sync_status { cmi_sync_status_sync_status 3 cmi_sync_status_status "In Sync" cmi_sync_status_mode 3 cmi_sync_status_color 0 cmi_sync_status_summary "All devices in the device group are in sync" cmi_sync_status_details { "Device2: connected" "device-group1 (In Sync): All devices in the device group are in sync" "device_trust_group (In Sync): All devices in the device group are in sync" } } } } [Status=Command OK]:

The unnecessary logs may make it for you to review the messages when troubleshooting.

Environment

  • Multi-blade platforms

Cause

Audit log messages sent from the primary blade to the secondaries are logged.
This is tracked under Bug ID 692218

Recommended Actions

To Workaround this you could create a log filter by running below commands:

  1. tmsh modify sys syslog include 'filter f_audit { facility(local0) and match("AUDIT") and not match(\"user mcpd-primary\"); };'
  2. tmsh save sys config
  3. tmsh restart sys service syslog-ng

Additional Information

Alternatively it's possible to use:
tmsh modify sys syslog include 'filter f_audit { facility(local0) and match("AUDIT") and not match("mcpd-primary"); };'

To Test:
logger -p local0.notice "date:time <bigip-IP> AUDIT - client Unknown, user mcpd-primary - transaction "
