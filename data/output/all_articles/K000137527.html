K000137527: NGINX HTTP 403 responses are being blocked

Type
Support Solution
Published
2023-11-09
Updated
2023-11-09
Applies to
  • NGINX Products
  • NGINX Plus: R28
Source
https://my.f5.com/manage/s/article/K000137527

Description

Your NGINX configuration utilizes the App Protect default security policy. Request to cause a server HTTP 403 response are not being sent to the requestor.

Environment

  • NGINX App Protect
  • Default security policy

Cause

This is the expected behavior of the default security policy to block HTTP 403 responses.

Recommended Actions

If your environment requires that server HTTP 403 responses be passed to the requestor you can modify the default security policy tp permit the 403 response. To enable HTTP 403 responses to be passed to the requestor add 403 to the allowedResponseCodes section of your security policy.

Example: 

"policy" : {
        "name": "my_policy",
        "template": { "name": "POLICY_TEMPLATE_NGINX_BASE" },
        "general" : {
         "allowedResponseCodes" : [
            400,
            401,
            403,
            404,
            407,
            417,
            503
         ],
         "maskCreditCardNumbersInRequest" : true,
         "trustXff" : false
      }
    }
}　

Note: When adding 403 to the allowedResponseCodes place 403, prior to the final allowed response code (maintaining numeric order is recommended for ease of administration).
