Description

Access Policy Manager has an IP Geolocation match agent that can check the client IP address against the geolocation database to determine the client's physical location. The IP Geolocation match agent can be applied in an access policy and restrict access to APM virtual server from certain geolocations.

Environment

  • BIG-IP APM is provisioned
  • BIG-IP APM access policy is associated to the virtual server

Cause

Traffic from a geolocation is sending a large amount of traffic to the BIG-IP APM protected virtual server.

Recommended Actions

Add an IP Geolocation match agent to the BIG-IP APM access policy in the Visual Policy Editor (VPE), and configure the branch rule to allow and deny access appropriately. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).

    Note: For BIG-IP APM 12.x and earlier, navigate to Access Policy > Access Profiles.

  3. For the appropriate access profile, click Edit.
  4. At the point in the Access Policy branch where you intend to add the IP Geolocation Match agent, click +.
  5. Click the Endpoint Security (Server-Side) tab.
  6. Select IP Geolocation Match and click Add Item.
  7. In the IP Geolocation Match agent, click Branch rules.
  8. Enter a name and click change.
  9. Configure the condition of the Geolocation check. For example, to identify users coming from the country code US, leave the default value as US.
  10. Click the Advanced tab and observe the expression used to identify the US country code.
  11. Click the Add Expression button to create more complex conditions. 
  12. For Context, select IP Geolocation match.
  13. For Condition, select the desired condition from the following list:
    • IP Geolocation Continent code is
    • IP Geolocation Country code is
    • IP Geolocation Country name is
    • IP Geolocation State/Region is
  14. Enter the desired value.

    Note: The values configured here and in step 9 define the values of the condition such that when the values match, users are allowed access. When the values do not match, they are directed to the fallback branch and denied access.

  15. Click Add Expression.
  16. Click Advanced to verify the conditions are correct.
  17. Click Finished and Save.
  18. Click Apply Access Policy to apply the changes.

Additional Information

The IP Geolocation Match action provides the following conditions and their associated BIG-IP APM session variables for defining branch rules.

ValueSession variableDescription
IP Geolocation Continent code issession.user.ipgeolocation.country_codeSpecifies that the user's IP address must match the specified continent code.
IP Geolocation Country code is:session.user.ipgeolocation.country_nameSpecifies that the user's IP address must match the specified country code.
IP Geolocation Country name is:session.user.ipgeolocation.continentSpecifies that the user's IP address must match the specified country name.
IP Geolocation State/Region is:session.user.ipgeolocation.stateSpecifies that the user's IP address must match the specified region or state.

The BIG-IP APM system essentially compares the value the administrator configures with the value of the BIG-IP APM session variable listed in the Session variable column of the previous table. If the geolocation information determined from the IP address does not match the specified conditions, the per-session policy sends the user to the fallback branch. The value of the BIG-IP APM session variable can be found in the /var/log/apm log file. Therefore, to whitelist a specific geolocation, the administrator can observe the value of the session variable first in the /var/log/apm file, before configuring it in the VPE.

Alternatively, administrators can follow the Querying the IP geolocation database for the location of a specific IP address procedure in K15042: Looking up IP geolocation data using the geoip_lookup command.
