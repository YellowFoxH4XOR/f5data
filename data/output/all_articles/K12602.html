Known Issue

This is the result of a known issue. If volume scans have been disabled for a place rule that targets a share farm, the ARX system will fail to auto-migrate files within the share farm when free space for a share within the share farm drops below the configured threshold.

F5 Product Development tracked this issue as ID 348086 and it was fixed in ARX 5.2.2. For information about upgrading, refer to the ARX release notes.

Workaround

The auto-migrate behavior within the share farm will function properly if volume scans are re-enabled for the place rule. You can re-enable volume scans with the volume-scan command by performing the following procedure:

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global configuration mode by typing the following command:

    global
  4. Enter namespace configuration mode using the following command syntax:

    namespace <namespace>

    Replace <namespace> with the name of your namespace.

    For example:

    namespace ns1
  5. Enter volume configuration mode using the following command syntax:

    volume <volume>

    Replace <volume> with the name of your volume.

    For example:

    volume /vol1

    You are now in gbl-ns-vol mode.
  6. Enter placement rule configuration mode using the following command syntax:

    place-rule <place rule>

    Replace <place rule> with the name of your placement rule.

    For example:

    place-rule move2farm
  7. Re-enable volume scans for the placement rule by typing the following command:

    volume-scan
  8. Exit the placement rule configuration mode and return to privileged mode by typing the following command:

    end
