Topic

The Dynamic Ratio load balancing algorithm load balances requests based on a ratio value that is calculated using a set of values collected by an SNMP Data Collection Agent (DCA).

Description

An SNMP DCA is configured as a monitor using one the following two monitor types:

  • SNMP DCA
  • SNMP DCA Base

The main difference between the SNMP DCA monitor and the SNMP DCA Base monitor is that an SNMP DCA monitor has built-in variables to collect SNMP object identifiers (OIDs) for CPU, memory, and disk usage statistics, and the related variables to define the thresholds and coefficients for each object. The SNMP DCA Base monitor has no pre-defined variables.

SNMP DCA Monitor

An SNMP DCA monitor collects values for a pre-defined set of SNMP objects for memory, CPU, and disk usage statistics. The variables for these objects and their related threshold and coefficient values are built in to the SNMP DCA monitor.

Depending on the agent type specified, an SNMP DCA monitor uses different SNMP OIDs for the built-in memory, CPU, and disk usage objects. (See the following tables.) These OIDs are hard coded, and you cannot modify or delete them. If the SNMP agent on the monitored node uses different OIDs than the SNMP DCA monitor uses, you need to use an SNMP DCA Base monitor and configure variables for the custom SNMP OIDs and the threshold and coefficients that the node uses.

An SNMP DCA monitor can collect SNMP objects other than the built-in SNMP objects. Using variable name/value pairs, you can configure the monitor to collect SNMP objects and specify the associated threshold and coefficients that the Dynamic Ratio load balancing algorithm uses for the collected object. For information, refer to K14110: Creating a custom SNMP DCA or SNMP DCA Base monitor.

The BIG-IP system has one pre-defined SNMP DCA monitor. This default SNMP DCA monitor is named snmp_dca. The default snmp_dca monitor uses the UC Davis (UCD) agent OIDs. You cannot modify the default snmp_dca monitor. If you want to use the WIN2000 agent OIDs, or modify the default thresholds or coefficients that the default snmp_dca monitor uses, you need to create a new SNMP DCA monitor.

An SNMP DCA monitor has the following configuration fields.

FieldDescription
IntervalSpecifies, in seconds, the frequency at which the system issues the monitor check. The default is 10.
Time Until UpSpecifies the number of seconds to wait after a resource first responds correctly to the monitor before setting the resource to up. During the interval, all responses from the resource must be correct. When the interval expires, the resource is marked up. The default is 0, meaning that the resource is marked up immediately upon receipt of the first correct response.

Note: SNMP DCA and SNMP DCA Base monitors affect only the dynamic ratio weight of a node and do not mark a node as down, like a standard monitor.

TimeoutSpecifies the number of seconds the target has in order to respond to the monitor request. The default is 30 seconds.

Note: SNMP DCA and SNMP DCA Base monitors affect only the dynamic ratio weight of a node and do not mark a node as down, like a standard monitor.

CommunitySpecifies the community name that the system must use to authenticate with the host server through SNMP. The default value is Public. Note that this value is case sensitive.
VersionSpecifies the version of SNMP that the host server uses. The default is v1. However, v2c is recommended. Other is not v3; SNMP DCA and SNMP DCA Base monitors do not support version 3.
Agent TypeSpecifies the SNMP agent running on the monitored node. UC Davis (UCD) or Windows 2000 (WIN2000). The default is UCD. (For information about the OIDs used with these agent types, refer to the Agent Types section below).
CPU CoefficientSpecifies the coefficient that the system uses to calculate the weight of the CPU threshold in the dynamic ratio load balancing algorithm. The default is 1.5.
CPU ThresholdSpecifies the maximum acceptable CPU usage on the target server. The default is 80 percent.
Memory CoefficientSpecifies the coefficient that the system uses to calculate the weight of the memory threshold in the Dynamic Ratio load balancing algorithm. The default is 1.0.
Memory ThresholdSpecifies the maximum acceptable memory usage on the target server. The default is 70 percent.
Disk CoefficientSpecifies the coefficient that the system uses to calculate the weight of the disk threshold in the Dynamic Ratio load balancing algorithm. The default is 2.0.
Disk ThresholdSpecifies the maximum acceptable disk usage on the target server. The default is 90 percent.
VariablesPresents boxes for specifying variable names and value pairs, and a list containing existing variable definitions that the monitor uses.

Variable name/value pairs

Variable name/value pairs are used by both SNMP DCA and SNMP DCA Base monitors to specify an SNMP object to be collected, and the associated threshold and coefficient that the Dynamic Ratio load balancing algorithm uses.

For Dynamic Ratio to determine a ratio for a given node, the following three variable name/value pairs are required for each metric:

  • The OID to be collected
  • A threshold for the returned value
  • A coefficient to use for the object when calculating the load balancing metrics

When creating these variable name/value pairs, use the following naming syntax:

Name Value

<name> <numeric OID>
<name>_threshold <integer threshold value>
<name>_coefficient <integer coefficient value>

For example:

Name Value

hrSystemProcess .1.3.6.1.2.1.25.1.6.0
hrSystemProcess_threshold 85
hrSystemProcess_coefficient 2

Threshold and Coefficient values

The overall ratio weight is the sum of relative weights calculated for each metric. The relative weights, in turn, are based on three factors: the value for the metric returned by the monitor, the coefficient value, and the threshold value. Given these values, the relative weight is calculated as follows:

w=10^(((threshold - utilization value)/threshold) * coefficient)

You can see that the higher the coefficient, the greater the relative weight calculated for the metric. Similarly, the higher the threshold, the greater the relative weight calculated for any metric value that is less than the threshold. (When the value reaches the threshold, the weight goes to 1.)

Because the SNMP DCA monitor is associated with nodes rather than pools, it does not actually learn the number of nodes in a pool. As a result, the calculation always raises the default value of 10. For more information about this and what threshold and coefficient values the system uses to effect weight values in the Dynamic Ratio load balancing algorithm, refer to K9125: Overview of Dynamic Ratio load balancing.

SNMP DCA Base monitor

The SNMP DCA Base monitor type does not have any pre-defined SNMP objects to collect. It is basically a template that allows you to use the SNMP DCA monitor framework without collecting the pre-defined set of SNMP objects that the SNMP DCA monitor collected.

When creating an SNMP DCA Base monitor, you must use variable name/value pairs to specify each SNMP object to be collected, and the associated threshold and coefficient values that the Dynamic Ratio load balancing algorithm uses. For more information refer to K14110: Creating a custom SNMP DCA or SNMP DCA Base monitor.

Recommendations

When using dynamic ratio load balancing mode, you should consider the following factors:

  • If your pool member's SNMP agent supports the OIDs that the SNMP DCA monitor uses, you can use the default snmp_dca monitor or create a custom SNMP DCA monitor and specify the desired threshold and coefficient to use for the SNMP objects that the SNMP DCA monitor collected.
  • If your pool member's SNMP agent does not support the OIDs that the SNMP DCA monitor uses, you need to create a custom SNMP DCA Base monitor and specify the SNMP objects to collect and the desired threshold and coefficient to use. For information, refer to K14110: Creating a custom SNMP DCA or SNMP DCA Base monitor.
