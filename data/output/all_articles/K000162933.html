K000162933: NGINX Plus Fails to Start When Binding to a Keepalived Virtual IP Address

Type
Support Solution
Published
2026-08-14
Updated
2026-08-14
Applies to
  • NGINX Products
  • NGINX Plus
Source
https://my.f5.com/manage/s/article/K000162933

Description

NGINX Plus fails to start when its configuration binds a listener to a keepalived virtual IP (VIP) that is not currently assigned to a local interface.

The following errors may be logged:

nginx: [emerg] bind() to HA_VIP_ADDRESS:1812 failed (99: Cannot assign requested address)
nginx.service: Control process exited, code=exited, status=1/FAILURE
nginx.service: Failed with result 'exit-code'

Environment

  • NGINX Plus
  • Linux system using systemd
  • Keepalived and VRRP configured in an active-passive HA pair
  • NGINX Plus configured to listen directly on the HA VIP:
    listen HA_VIP_ADDRESS:1812 udp;
  • The HA VIP is assigned only after the node becomes the VRRP MASTER.
  • IPv4 nonlocal binding is disabled:
    net.ipv4.ip_nonlocal_bind = 0
  • A custom keepalived configuration may be used instead of the NGINX-provided nginx-ha-keepalived package and nginx-ha-setup utility.

Cause

The issue is caused by a startup-order dependency between NGINX Plus and keepalived:

  1. NGINX Plus starts during system initialization.
  2. Keepalived initially places the node in the BACKUP state.
  3. The VRRP election has not completed, so the VIP is not present on the local interface.
  4. Because net.ipv4.ip_nonlocal_bind is set to 0, NGINX Plus cannot bind to the unassigned VIP.
  5. NGINX Plus exits with error 99: Cannot assign requested address.
  6. Keepalived later becomes MASTER and assigns the VIP, but NGINX Plus does not automatically restart.

A custom or incomplete HA configuration can expose this startup race. Checking only the network-interface state does not necessarily coordinate NGINX Plus startup with VIP ownership.

Recommended Actions

Option 1: Implement the NGINX Plus HA solution

Use this approach when NGINX Plus must continue listening directly on the HA VIP.

  1. Install the NGINX-provided nginx-ha-keepalived package on both nodes.
  2. Run the nginx-ha-setup utility as the root user on both nodes.
  3. Configure the active-passive pair according to the NGINX Plus HA procedure.
  4. Verify that the generated keepalived configuration includes:
    • NGINX Plus health-check scripts.
    • The manual-failover script, where required.
    • The NGINX HA notification script.
    • Correct unicast source and peer addresses.
    • Correct VIP configuration.
  5. If the deployment requires a second VRRP instance, add and validate that instance manually after running nginx-ha-setup. The setup utility does not automatically support multiple VRRP instances.
  6. Test reboot, failover, VIP assignment, and NGINX Plus service recovery during a maintenance window.

Option 2: Permit binding to nonlocal IPv4 addresses

If the NGINX Plus configuration must continue to reference the VIP directly, enable nonlocal IPv4 binding on both HA nodes:

echo "net.ipv4.ip_nonlocal_bind=1" | sudo tee -a /etc/sysctl.conf

sudo sysctl -p

Verify the setting:

sysctl -a | grep nonlocal_bind

The expected result is:

net.ipv4.ip_nonlocal_bind = 1

Option 3: Listen on all local interfaces

As an alternative, change VIP-specific NGINX Plus listeners to listen on all local interfaces:

listen *:1812 udp;

For additional VIP-specific listeners, replace the VIP address in the same manner:

listen *:<PORT> udp;

After modifying the configuration:

  1. Validate the NGINX Plus configuration.
  2. Reload or restart NGINX Plus according to the applicable change procedure.
  3. Confirm that the listener is active on the intended port.
  4. Verify that firewall and network access controls restrict traffic to the intended interfaces and sources.
  5. Test failover and reboot behavior on both HA nodes.

Additional Information

  • Keepalived and VRRP may require several seconds after boot to complete an election and assign the VIP.
  • NGINX Plus may start before the VIP is available unless the HA configuration accounts for this startup sequence.
  • Enabling net.ipv4.ip_nonlocal_bind allows NGINX Plus to bind to an IPv4 address that is not currently assigned to a local interface.
  • Using listen *:<port> avoids dependence on the VIP being present during NGINX Plus startup, but causes NGINX Plus to listen on all applicable local interfaces. Firewall and access-control rules should therefore be reviewed.
  • A maintenance window is recommended when implementing or migrating HA configurations.
  • If multiple VRRP instances are required, each instance must use the appropriate interface, peer addresses, VIP, and unique VRRP router ID.
