Known Issue

Connections running over a OneConnect-enabled virtual server may prematurely detach.

This issue occurs when all of the following conditions are met:

  • The OneConnect profile on the virtual server has a re-use mask other than 255.255.255.255.
  • You have no SNAT associated with the virtual server, or the affected virtual server is configured with both a SNAT and a SNAT persistence iRule.

    Note: For more information, refer to SNAT Pool Persistence on DevCentral.

  • The configuration contains elements that detach OneConnect connections.

The configuration may contain elements that detach OneConnect connections when one of the following two conditions is met:

  • You have an HTTP application that utilizes a connection-based authentication mechanism with the BIG-IP NTLM profile or Negotiate using the BIG-IP HTTP profile.
  • You have explicitly disabled OneConnect detaching with the ONECONNECT::detach disable iRule statement.

Impact

NTLM or negotiate authentication between the client and BIG-IP pool members may intermittently fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • F5 iHealth lists Heuristic H387711 on the Diagnostics > Identified > Medium screen.
  • Unexplained authentication session failures
  • NTLM or negotiate authentication between the client and BIG-IP pool members may intermittently fail with repeated requests for re-authentication, or repeated notifications that their current credentials are incorrect.

Workaround

To work around this issue, you can set the OneConnect re-use mask to 255.255.255.255. To do so, perform the following procedure:

Impact of workaround: A OneConnect profile with a source mask of 255.255.255.255 only aggregates connections originating from the same client IP address. This may result in less optimal connection re-use on the OneConnect profile associated with the virtual server.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Profiles > Other.
  3. Click OneConnect.
  4. Click the OneConnect profile associated with your virtual server.
  5. Change your Source Mask to 255.255.255.255.
  6. Click Update.
