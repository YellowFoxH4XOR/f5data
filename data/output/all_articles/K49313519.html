K49313519: Virtual server not responding to PING

Type
Support Solution
Published
2022-02-25
Updated
2023-07-26
Applies to
  • BIG-IP LTM: 15.X.X
Source
https://my.f5.com/manage/s/article/K49313519

Description
Virtual server is showing as up but does not respond to ping
 

Environment

  • BIG-IP
  • LTM
  • New configuration

Cause
The IP Address used for a virtual server must belong to a subnet defined by a self IP.
If you are specifying the VLANS for a virtual server, this should include the VLAN that the self IP of the associated subnet belongs to.
 

Recommended Actions

  • Include the correct VLANS in the virtual server configuration.

Additional Information

Here we see that the floating self IP Address is in VLAN 'EXT'

net self EXT_Float {
    address 192.168.1.1/24
    allow-service all
    floating enabled
    traffic-group traffic-group-1
    unit 1
    vlan EXT
}

The Virtual server is in the same subnet as the floating self IP Address, and if VLANs are assigned, this must include the VLAN that the self IP belongs to

ltm virtual VS_test_http {
    destination 192.168.1.50:http
    ip-protocol tcp
    mask 255.255.255.255
    pool pool_test_http
    profiles {
        http { }
        tcp { }
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
    vlans {
        EXT                    <---- Note the VLAN, there should be a self IP configured
    }
    vlans-enabled
}
