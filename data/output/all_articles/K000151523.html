Description

When trying to export a file using one of the SSH-based transfer methods - sftp or scp, the transfer is failing and the transfer-status shows:

R5900# file export local-file configs/my-config remote-host 10.1.1.1 remote-file my-config username root protocol sftp
Value for 'password' (<string>): *******
result File transfer is initiated.(configs/my-config)
operation-id EXPORT-V3tFkdrs
R5900# file transfer-status
result
S.No.|Operation |Protocol|Local File Path |Remote Host |Remote File Path |Status |Time
1 |Export file|SFTP |configs/my-config |10.1.1.1 |my-config |Failed initialization|Thu May 22 13:55:06 2025

At the same time in the /var/F5/system/log/platform.log there are logs like:

2025-05-22T13:55:06.914161+02:00 R5900 utils-agent[10]: priority="Info" version=1.0 msgid=0x5e01000000000004 msg="utils-agent" INFO="SCP/SFTP, Export".
2025-05-22T13:55:06.929927+02:00 R5900 utils-agent[10]: priority="Err" version=1.0 msgid=0x5e01000000000005 msg="utils-agent file transfer error" ERROR="Failure establishing ssh session".
2025-05-22T13:55:06.931274+02:00 R5900 utils-agent[10]: priority="Notice" version=1.0 msgid=0x5e01000000000006 msg="utils-agent" AUDITLOG="File transfer AUDIT. Failed Export file operation. protocol(SFTP) port(22) username(root) password(***hidden***) remoteHost(10.1.1.1) remoteFile(my-config/my-config) localFile(configs/my-config)".

Environment

  • F5OS-A or F5OS-C
  • exporting files
  • 'Failed initialization' error
  • 'Failure establishing ssh session' log

Cause

utils-agent container that F5OS is using for file transfers is using curl version that might be incompatible with some modern systems running recent openSSH versions and fail to establish SSH session.

Recommended Actions

  1. As a workaround, you can try to transfer using HTTPS protocol: 
    file export local-file configs/backup.xml remote-host <IP_ADDRESS> remote-file <remote file location and name> username root protocol https insecure
  2. login as root and transfer the file directly from linux. 
    sftp <username>@<<IP_ADDRESS>>:<remote file location and name> <<< $'put /var/F5/system/configs/backup.xml'
