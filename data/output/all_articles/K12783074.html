Topic

This article applies to BIG-IP 12.x and later. For information about other versions, refer to the following article:

  • K16700: Decrypting SSL traffic using the SSL::sessionsecret iRules command (11.x)

You should consider using these procedures under the following condition:

  • You want to decrypt and examine SSL application data using the SSL session key.

Description

You can use the SSL::sessionsecret iRules command to extract the SSL session key from SSL sessions that are terminated by the Traffic Management Microkernel (TMM). This method allows you to decrypt an SSL session and review the application data using the Wireshark application without having access to the server's private key. This procedure functions on both client- and server-side and works with Diffie-Hellman (DH) and Elliptic Curve Diffie-Hellman (ECDH) key exchange algorithms as well as RSA.

The specific iRules syntax and procedure varies based on whether SSL session caching is enabled or disabled. As described in RFC 5246, when SSL session caching is disabled the server returns a blank Session ID. This requires using the client random rather than the session ID to correlate the session secrets with the actual sessions for decryption. To decrypt SSL traffic using the SSL::sessionsecret iRules command, perform one of the following procedures:

  • Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache enabled)
    • Producing a Master Secret log file and decrypting the SSL session
  • Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache disabled)
    • Producing a Master Secret log file and decrypting the SSL session

Important: Due to a known issue that involves using the SSL::sessionid iRule command with TLSv1.3, the iRules described in the following procedures may not function as expected and log an error in the /var/log/ltm file similar to the following example: 

01220001:3: TCL error: /Common/K12783074-session-cache-enabled <CLIENTSSL_HANDSHAKE> - SSL hudfilter not reached or not in chain (line 2) invoked from within "SSL::sessionid"

For information about this issue as well as alternative client-based methods to log SSL session IDs and master key, refer to the articles listed in the Related Content section at the end of this article.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You are running a system with the Wireshark application installed.

Procedures

Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache enabled)

If the SSL session cache feature is enabled in the SSL profile, you can use the following procedure to decrypt SSL traffic using the SSL::sessionsecret iRules command. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client | Server.
  3. Select the name of the SSL profile.
  4. Set the Configuration view to Advanced.
  5. Verify that the Cache Size setting is a non-zero value.
  6. Go to Local Traffic > iRules > iRules List.
  7. Select Create and define an iRule using a SSL::sessionsecret iRules command syntax similar to the following:

    Note: In the following example, <client_IP_addr> is the IP address of the remote client accessing the BIG-IP virtual server.

    when CLIENTSSL_HANDSHAKE {
      if { [IP::addr [getfield [IP::client_addr] "%" 1] equals <client_IP_addr>] } {
        log local0. "[TCP::client_port] :: RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
      }
    }

    Note: To dump a server-side session key, use SERVERSSL_HANDSHAKE instead of CLIENTSSL_HANDSHAKE.

  8. Associate the iRule with the virtual server.
  9. From the BIG-IP command line, run the tcpdump command on the BIG-IP system.
  10. From the client system, access the virtual server.
  11. Stop the tcpdump command.
  12. Download the generated tcpdump file.
  13. Perform the Producing a Master Secret log file and decrypting the SSL session procedure.

Producing a Master Secret log file and decrypting the SSL session

You can produce a Master Secret log file and use the file to decrypt the SSL session using either of the following methods:

  • Producing a Master Secret log file using the sed command
  • Producing a Master Secret log file manually

Producing a Master Secret log file using the sed command

  1. On the BIG-IP command line, enter the following command:

    sed -e 's/^.*\(RSA Session-ID\)/\1/;tx;d;:x' /var/log/ltm > /var/tmp/sessionsecrets.pms

    Note: Run this command exactly as shown.

  2. Download the /var/tmp/sessionsecrets.pms file to your local drive.
  3. On the client system, open the Wireshark application.
  4. Go to Edit > Preferences > Protocols > SSL.

    Note: In the latest version of Wireshark (3.x and higher) navigate to Edit > Preferences > Protocols > TLS.

  5. For (Pre)-Master-Secret log filename, select Browse and locate the session key file you created.

    Note: If you are using an older version of Wireshark, you may need to manually enter the file information.

  6. Select OK.
  7. Open the packet capture.

    The selected SSL sessions are now decrypted.

Producing a Master Secret log file manually

  1. On the BIG-IP system, locate the SSL session keys in the /var/log/ltm log file. They appear similar to the following example:

    info tmm1[19365]: Rule /Common/Decrypt_session <CLIENTSSL_HANDSHAKE>: 50194 :: RSA Session-ID:2b14674e4bb505ab97a63ab8fe47cf6f827aa34964871338dc3b5bcc034bd91c Master-Key:7bfcb98c9725de0da25eda2110937550d9097039912ad422c877e20b43d8741572d9467365dac6a6a3e4cc19ec608bfd

    Note: The previous example represents a single log line.

  2. Copy the last section of the log lines, starting with the R in RSA.

  3. On the client system, open a text editor such as Notepad.
  4. Paste the string into the text editor and ensure each line of the file has the following syntax:

    RSA Session-ID:<session_id> Master-Key:<master_key>

    Note: Make sure to carefully check the syntax. If you vary the syntax, Wireshark cannot recognize the file.

  5. Save the file. To use the same filename as the previous instructions, name it sessionsecrets.pms 
  6. Open the Wireshark application.
  7. Go to Edit > Preferences > Protocols > SSL.

    Note: In the latest version of Wireshark (3.x and higher) navigate to Edit > Preferences > Protocols > TLS.

  8. For (Pre)-Master-Secret log filename, select Browse and locate the session key file you created.

    Note: If you are using an older version of Wireshark, you may need to manually enter the file information.

  9. Select OK.
  10. Open the packet capture.

    The selected SSL sessions are now decrypted.

Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache disabled)

You can decrypt SSL traffic using the SSL::sessionsecret iRules command in the event that the SSL session cache feature is disabled in the SSL profile. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client | Server.
  3. Select the name of the SSL profile.
  4. Set the Configuration view to Advanced.
  5. Verify that the Cache Size setting is set to zero (0).
  6. Go to Local Traffic > iRules > iRules List.
  7. Select Create and define an iRule using a SSL::sessionsecret iRules command syntax similar to the following example:

    when CLIENTSSL_HANDSHAKE {
     if {[IP::addr [getfield [IP::client_addr] "%" 1] equals <client_IP_addr>] } {
       log local0. "CLIENT_Side_IP:TCP source port: [IP::client_addr]:[TCP::remote_port]"
       log local0. "CLIENT_RANDOM [SSL::clientrandom] [SSL::sessionsecret]"
       log local0. "RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
     }
    }
    when SERVERSSL_HANDSHAKE {
     if {[IP::addr [getfield [IP::client_addr] "%" 1] equals <client_IP_addr>] } {
       log local0. "SERVER_Side_IP:TCP source port:[IP::local_addr]: [TCP::local_port]"
       log local0. "CLIENT_RANDOM [SSL::clientrandom] [SSL::sessionsecret]"
       log local0. "RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
     }
    }

    Note: Replace <client_IP_addr> with the client IP address you want to log the CLIENT_RANDOM information.

  8. Associate the iRule with the virtual server.

Producing a Master Secret log file (SSL session cache disabled)

To produce a Master Secret log file and use the file to decrypt the SSL session, perform the following procedure:

Note: For the log file to contain the required information, you must have the SSL::clientrandom iRule specified in step 9 of the Decrypting SSL traffic using the SSL::sessionsecret iRules command (SSL session cache disabled) procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Extract the client random and master key in PMS ready format from the /var/log/ltm files by entering the following command:

    grep -h -o 'CLIENT_RANDOM.*' /var/log/ltm* > /var/tmp/sessionsecrets.pms

  3. Save the /var/tmp/sessions secrets file to your client system . To use the same filename as the previous instructions, name it sessionsecrets.pms 
  4. On the client system, open the Wireshark application.
  5. Go to Edit > Preferences > Protocols > SSL.

    Note: In the latest version of Wireshark (3.x and higher) navigate to Edit > Preferences > Protocols > TLS.

  6. For (Pre)-Master-Secret log filename, select Browse and locate the session key file you created.

    Note: If you are using an older version of Wireshark, you may need to manually enter the file information.

  7. Select OK.
  8. Open the packet capture.

    The selected SSL sessions are now decrypted.
