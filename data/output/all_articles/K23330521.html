Description
A configured Machine Tunnel does not start.
A Machine Tunnel does not get a DHCP address (Because it didn't start)
The Server logs show the session starts, then times out due to inactivity. There is no associated PPP activity with the session.
 

Environment

  • APM using Network Connectivity (VPN).
  • A Machine Tunnel.
  • The Network Access Resource is using DNS based split tunneling.

Cause
The split tunneling on DNS  names is configured with IP addresses. IP addresses are not DNS names and must not be entered there.
The Edge Client ignores this invalid configuration. The Machine Tunnel does not and fails to start.

Example:
apm resource network-access /Common/SSL_VPN_Access {
    address-space-include-dns-name { 8.8.8.8 }        <<<  8.8.8.8 is not a DNS name

On the client it will log an error message similar to

\DialerSettings.cpp, 647, verifyFQDNMaskList, EXCEPTION - wrong DNS mask, 8.8.8.8
\UClasses.h, 524, f5::clientAPI::APMResourceNA<class f5::clientAPI::APMClientCoreBase>::connectInternal, exit
\MachineTunnels/clientAPI/APMClientCoreBase.h, 965, f5::clientAPI::APMClientCoreBase::workerThreadFunc, done processing message, execute
\MachineTunnels/MachineTunnelsCore.h, 259, MachineTunnels::MachineTunnelsCore<class MachineTunnelsOutput>::run, EXCEPTION caught: MachineTunnels::MachineTunnelsCore<class MachineTunnelsOutput>::runEXCEPTION

Recommended Actions

  1. In the Network Access Resource, remove the IP addresses from fields expecting DNS names.

Additional Information
This is an error of input validation. It should not be possible to enter IP addresses there.
This is resolved in V16 and later.
Bug ID 778321: No validation for DNS Address Space entry
