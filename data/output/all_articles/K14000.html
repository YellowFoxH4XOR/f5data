Known Issue

Cookie persistence may fail when the cookie-name of the cookie starts with a cookie attribute name.

This issue occurs when all of the following conditions are met:

  • You attempt to configure a cookie persistence profile type and its cookie-name starts with a cookie attribute, as defined in RFC6265.
  • The client presents another arbitrary cookie before the BIG-IP system's configured persistence cookie in the HTTP request header.
  • The virtual server references an HTTP profile.

    Note: Virtual servers using the FastHTTP profile are not affected by this issue.

RFC6265 defines the following cookie attribute names for the set-cookie-av attribute, as follows:

  • Comment
  • CommentURL
  • Discard
  • Domain
  • Max-Age
  • Path
  • Port
  • Secure
  • Version

Cookie names starting with any of the attributes included in the previous list may trigger this issue. In addition, the value used in cookie name is not case sensitive.

For example, the cookie name that triggers this issue may appear similar to the following example:

DomainOp

The cookie name that may not trigger this issue may appear similar to the following example:

myDomain

F5 recommends that you avoid using the RFC6265 set-cookie-av attribute name as the start of a cookie name on a persistence profile Cookie setting.

Impact

The BIG-IP system may fail to persist the client connections to the correct pool members.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H402958 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system may fail to persist the client connections to the correct pool members, and the connections will be load balanced among the pool members.

    For example, a client HTTP request with the arbitrary cookie and the BIG-IP-configured persistence cookie is expected to persist the request to pool member A, and going to other pool members in the manner in which the system is configured to load balance.

Workaround

To work around this issue, you can rename the cookie-name of the affected Cookie persistence profile to a new name that does not contain any of the cookie attributes defined in RFC6265. To do so, perform one of the following procedures:

Impact of workaround: Performing the following workarounds should not have a negative impact on your system.

Modifying the cookie name using the Configuration utility

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Profiles > Persistence and select the name of the cookie persistence that is affected by this issue.
  3. Modify the cookie name to a new value.
  4. To save the changes, click Update.

Modifying the cookie name using the tmsh utility (10.x or later)

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.
  2. Modify the cookie name to a new name using the following command syntax:

    modify /ltm persistence cookie <Cookie-Persistence-Profile-Name> cookie-name <New-Cookie-Name>

    For example, if the cookie persistence profile affected by this issue is called Eg_Cookie and the new cookie-name is called EgCode, you would type the following command:

    modify /ltm persistence cookie Eg_Cookie cookie-name EgCode
  3. Save the changes by typing the following command:

    save /sys config
  4. To exit the tmsh utility, type the following:

    quit

Modifying the cookie name using the bigpipe utility (9.x)

  1. Log in to the BIG-IP command line.
  2. Modify the cookie name to a new name using the following command syntax:

    bigpipe profile persist <Cookie-Persistence-Profile-Name> cookie name <New-Cookie-Name>

    For example, if the cookie persistence profile affected by this issue is called Eg_Cookie and the new cookie-name is called EgCode, you would type the following command:

    bigpipe profile persist Eg_Cookie cookie name EgCode
  3. Save the changes by typing the following command:

    bigpipe config save all
