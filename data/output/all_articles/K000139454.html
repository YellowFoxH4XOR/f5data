K000139454: "upstream sent duplicate header" in NGINX log file

Type
Support Solution
Published
2024-04-30
Updated
2024-04-30
Applies to
  • NGINX Products
  • NGINX Plus: R31, R30, R29
Source
https://my.f5.com/manage/s/article/K000139454

Description

  • NGINX server is configured with an upstream block (Application Server) 
  • You are observing error entry "upstream sent duplicate header" in NGINX log file for a response from a particular application server. 
  • You want to know the cause of this error and how to resolve it 

Environment

  • NGINX Plus
  • Upstream
  • HTTP Protocol 

Cause

  • Application server response is NOT HTTP protocol compliant

Recommended Actions

  • NGINX Plus enforces compliance with HTTP RFC.
  • Duplicate header response originate on the Application server and the Application Team must help address identified none-compliance "duplicate Transfer-Encoding header" issue.

Additional Information

  • The error itself indicates NGINX as a proxy, when receiving a response from configured upstream, the application server responded with unexpected duplicate header.
  • "Duplicate Content-Length and Transfer-Encoding headers are now rejected as well as the responses with invalid Content-Length or Transfer-Encoding headers, or if both Content-Length and Transfer-Encoding are present in the response".
  • This same information has been shared in our release note
