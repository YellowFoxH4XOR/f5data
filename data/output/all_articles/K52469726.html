Description

Server Technologies fails to update or install via ASM Live Update.

You observe messages similar to the following in /var/log/tomcat/live_update_upload.log:

com.f5.liveupdate.update.negativesignatures.sigfile.Update.applyChanges.pl|ERR|Jan 21 07:52:55.033|29361|F5::LiveUpdate::PayloadHandler::ServerTechnologies::files_handler,,Fail to update Server Technologies: The uploaded Attack signature update file does not match the current version of BIG-IP

You may also observe in the GUI:

Could not calculate staging data for installation: Live Update file could not be loaded

The update file in question may be a Genesis file. This is a Live Update package that comes with the software ISO.

You can verify this with the following command:

curl -sku admin:<pw> 'https://localhost/mgmt/tm/live-update/server-technologies/update-files?%24select=filename%2CisGenesis' | jq

Note: Replace <pw> with your admin password.

Environment

  • Live Update
  • Server Technologies

Cause

Bug ID 920149: Live Update default factory file for Server Technologies cannot be reinstalled

Recommended Actions

You can work around this issue by uploading the latest ServerTechnologies_*.im file manually.

If there is no newer file available for your version, but you have upgraded and the Live Update list shows a pre-upgrade Server Technologies package as being the latest file, even though the Genesis file is a newer release, the following may help:

tmsh stop sys service tomcat

rm -f /var/lib/hsqldb/live-update/liveupdatedb.*

tmsh start sys service tomcat

After this, the genesis file should show Currently installed, and additional updates can be installed as they are released.
