K000092642: BIG-IP ASM violation: Evasion technique detected (Bad unescape)

Type
Support Solution
Published
2022-11-17
Updated
2022-11-17
Source
https://my.f5.com/manage/s/article/K000092642

Description

A valid request is blocked due to ASM violation: Evasion technique detected. The detected evasion technique is Bad unescape.

 

Environment

  • ASM provisioned
  • ASM security policy attached
  • Request is blocked due to Evasion technique detected

 

Cause

The reason of those violations is that the request URL length is longer than the value of system variable ecard_max_http_req_uri_len (2048 by default). So, the BIG-IP stops parsing midstream when the limit is reached and interprets the last incomplete encoded value as bad unescape.

 

Recommended Actions

To avoid the violation the preferred solution is to increase the value of the system variable ecard_max_http_req_uri_len to a value higher than 2048, for example 2500 or 2600.

Refer the steps from article: K60450445: Configuring the maximum allowed URL length for an HTTP request

Impact of procedure: Performing the following procedure causes a temporary traffic disruption while the BIG-IP ASM service restarts. You should perform this procedure only during a scheduled maintenance window.

 

Additional Information

Normally the violation report would also have a section complaining about the URL length being longer than the allowed. for e.g. below:

HTTP Validation Unparsable request content

Details URL length: 2486 exceeded maximum limit of: 2048

However, this won't be in the event log if 'Unparsable request content' or 'HTTP protocol compliance failed' are not enabled in the learning and blocking settings.
