Known Issue

The Traffic Management Microkernel (TMM) restarts and produces a core file when the system loses the network route to the diameter endpoint. For example, this issue can happen with a Policy and Charging Rules Function (PCRF) system.

This issue occurs when all of the following conditions are met:

  • The BIG-IP PEM system establishes a connection with the diameter endpoint.
  • The system loses the network route to the diameter endpoint.

    For example, this condition occurs when bringing down the affected network interface or removing the static network route.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart.
  • If configured for HA, the affected BIG-IP device fails over to a configured peer device.
  • The BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp that correlates to the traffic interruption.

Workaround

There is no work around for this issue. However, you can avoid this issue by ensuring that you make any network configuration changes on the diameter endpoint during a scheduled maintenance window, when the BIG-IP PEM system is not processing any diameter connections.
