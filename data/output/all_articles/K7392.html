Topic

BIG-IP system includes the Universal Inspection Engine (UIE). The UIE is a set of functions that allows you to observe, direct, and persist load-balanced traffic using iRules. Universal persistence uses the UIE, allowing you to persist sessions based on header or content data specific to your application. For example, using an iRule, you can extract a string from the URI and use a universal persistence profile to persist connections based on the string. The UIE has the ability to inspect header and content data in both the client request and server response.

Note: The BIG-IP system stores universal persistence records in Traffic Management Microkernel (TM) memory, and there is a limit. The total amount of persistence records that they system can store is dependent on the available TMM memory.

The following iRule example illustrates how the BIG-IP system can find a cookie called jsessionid in the first response from the server and add a persistence record with the value of that cookie. Subsequent client requests containing the same cookie name and value pair persists to the same pool member.

when HTTP_RESPONSE {
  if { [HTTP::cookie exists "JSESSIONID"] } {
    persist add uie [list [HTTP::cookie "JSESSIONID"]]
  }
}
when HTTP_REQUEST {
  if { [HTTP::cookie exists "JSESSIONID"] } {
    persist uie [HTTP::cookie "JSESSIONID"]
  }
}

The following list describes the sequence of events for a universal persistence connection using the previous iRule:

  1. An initial HTTP request arrives without a cookie; the BIG-IP system load balances the request normally.
  2. The HTTP server sets the jsessionid cookie in the response to the client.
  3. The BIG-IP LTM UIE parses the server response for the Set-Cookie header, and finds the jsessionid cookie; the BIG-IP system inserts the value of the jsessionid cookie, as an index into the persistence table. For example, if the cookie is jessionid=12345. The BIG-IP system will add the value 12345 to the persistence table.
  4. The next HTTP request arrives from the client.
  5. The BIG-IP LTM UIE parses the client request for the Cookie header, finds the jsessionid cookie, and matches the value of the cookie to the entry in the persistence table.
  6. The BIG-IP LTM system persists the client request to the same pool member.

Note: The persist add uie iRules command is typically used in server-side events to create a persistence records based on the server response. The persist uie iRules command is typically used in client-side events to determine if a persistence record currently exists and sends the client request to the pool member defined in the persistence record if it does. If the persistence record does not exist, then the system proceeds to create a persistence record after the load balancing decision is made and a pool member is selected. If you do not intend to create a persistence record using the persist uie iRules command, you may consider modifying the iRule for the client-side event, HTTP_REQUEST, to something similar to the following:
when HTTP_REQUEST {
  set value [HTTP::cookie "JSESSIONID"]
  if { [persist lookup uie $value] != "" } {
    persist uie $value
  }
}

Configuring a universal persistence profile

To create a universal persistence profile, perform the following procedures:

  • Identifying the data to be used as the session identifier
  • Creating the iRule to be used in the universal persistence profile
  • Creating the universal persistence profile

Identifying the data to be used as the session identifier

Before you create the universal persistence profile, you must first identify the data to be used as the session identifier. The session identifier is a unique variable for the HTTP session that is initiated to the virtual server.

For example, if you want to create persistence based on the jsessionid in the following URI, you can create an iRule to extract the jsessionid number 80 from the URI:

http://www.test.com?jsessionid=80;

Creating the iRule to be used in the universal persistence profile

After you have identified the data to be used as the session identifier, you can create an iRule to extract the session ID.

To create the iRule to extract the jsessionid number from the URI, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Type a name for the iRule.
  5. Enter the iRules syntax in Definition.

    For example, the following iRule extracts the jsessionid number from the URI:

    when HTTP_REQUEST {
      set jsess [findstr [HTTP::uri] "jsessionid" 11 ";"]
      if { $jsess != "" } {
        persist uie $jsess
      }
    }

  6. Click Finished.

Creating the universal persistence profile

To create a universal persistence profile and reference the persistence iRule you created in the previous procedure, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Persistence menu, click Create.
  4. Type a name for the universal persistence profile.
  5. For Persistence, click Universal.
  6. For Configuration, select the iRule check box, then click the persistence iRule you created.
  7. Click Finished.

You must now associate the universal persistence profile with the virtual server.

Note: F5 recommends that you configure a OneConnect profile in addition to the Universal profile, to ensure that BIG-IP LTM system load balances HTTP requests correctly. For more information about OneConnect and HTTP parsing, refer to the Session Persistence Profiles chapter of the BIG-IP Local Traffic Manager: Concepts manual.
