Topic

This article applies to BIG-IP version 10.x. For information about other versions, refer to the following article:

  • K13160: Configuring syslog to minimize delays when sending remote log messages (11.x - 13.x)

Purpose

You should consider using this procedure under the following condition:

  • You require more timely updates to remote syslog-ng servers.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have configured the BIG-IP system to use a remote syslog-ng server, as described in K5527: Configuring the BIG-IP system to log to a remote syslog server (9.x).

Description

After configuring the BIG-IP system to use a remote syslog-ng server, a 60-second delay may occur between viewing the log message in the /var/log file and viewing the message at the remote syslog-ng server. You can eliminate this delay by adding the time_reopen option with a 0 (zero) value to the syslog-ng.conf file. However, you cannot manually edit this file on the BIG-IP system. To add this option, you must use either the bigpipe command or the Traffic Management Shell (tmsh).

Procedures

Adding the time_reopen option using the bigpipe command

Impact of procedure: Modification of the time_reopen value may impact BIG-IP CPU usage. F5 does not recommend setting this value below 10.

  1. To add the time_reopen option, type the following command:

    bigpipe syslog include '"options {time_reopen(10);};"'

  2. To save the configuration, type the following command:

    bigpipe save all

  3. To put your changes into effect, restart syslog-ng by typing the following command:

    bigstart restart syslog-ng
