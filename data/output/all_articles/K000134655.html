K000134655: Unintended Bypass of 2FA with Azure AD as SAML IDP via F5 BIG-IP Edge Client

Type
Support Solution
Published
2023-05-18
Updated
2023-06-14
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000134655

Description

Users connecting to Azure Active Directory (Azure AD) via a dial-up connection may encounter a situation where, if the 'Stay signed in' option is selected during sign-in with Two-Factor Authentication (2FA), subsequent users are not prompted for 2FA, allowing them to sign in without the additional security layer. Additionally, it has been noted that the Edge mini browser is caching the last signed-in user account.

 

Environment

Azure Active Directory (Azure AD) as SAML IdP

Two-Factor Authentication (2FA) enabled

Cause

This issue arises due to a combination of 'Stay signed in' option in Azure AD and the caching mechanism of the Edge Client, which appears to store the last signed-in user's session. This causes subsequent sign-ins to bypass the 2FA prompt, as the session details are retrieved from the cache.

Recommended Actions

Disable caching of passwords by following Controlling password caching for the BIG-IP Edge Client and BIG-IP Edge Portal applications (f5.com). Alternatively, for a more custom solution, Use a script to regularly clear the cache of the F5 BIG-IP Edge Client. Refer to the related article below for instructions on how to remove the cache.

 

Alternatively, you can disable the 'Stay signed in' prompt in Azure AD to avoid storing session details in the cache, which leads to bypassing the 2FA prompt. To do this, navigate to Azure Active Directory > Users > User settings, and set the 'Show keep user signed in' toggle to 'No'.
