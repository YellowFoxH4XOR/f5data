K33251052: Considerations when performing an upgrade or update for a BIG-IP tenant on a VELOS system

Description

Prior to performing an upgrade or update for a BIG-IP tenant on a VELOS system, you may need to do the following:

  • Consider the availability of slots or boot locations on the BIG-IP tenant.

    If the BIG-IP tenant is deployed using the T1-VELOS image type, there is no available slot to perform an upgrade or update since a T1-VELOS image type has only one slot or boot location available. Other image types have two slots or boot locations available which you can use to upgrade or update as needed.

    If you have already used up both slots or boot locations, you can perform an upgrade or update on an inactive slot or boot location on the BIG-IP tenant. However, if the BIG-IP version that you are planning to upgrade or update requires more storage than the existing allocated storage on the BIG-IP tenant, you may not be able to perform an upgrade or update.

    When there are no slots or boot locations available or there is insufficient allocated storage available on the BIG-IP tenant, you may have to perform the following procedure:

    Back up, delete, and restore the BIG-IP tenant

    1. Back up the tenant's configuration using UCS backup.
    2. Save the UCS file to a remote location.
    3. Delete the tenant.
    4. Re-create and deploy the tenant with the software version you want.
    5. Re-import the UCS file to the newly deployed tenant.
    6. Restore the tenant's configuration using the imported UCS file.

  • Import the software version you want to the BIG-IP tenant.

    You must perform the upgrade or update of a BIG-IP tenant within the tenant itself. Before doing so, you need to import the software image you want to install directly to the tenant using either its Configuration utility or the secure copy (SCP) utility.

    If you are importing the software image using the SCP utility, you must upload it directly to the /shared/images directory on the BIG-IP tenant. If you upload it to other directories which are either nearing or exceeding its maximum allocated storage, you may observe an error message similar to the following:

    011d0004:3: Disk partition / (slot 1) has only 0% free

    For more information about this error message, refer to K60799644: Error Message: 011d0004: Disk partition <partition> has only <free_space> free.

    For more information about importing software images and performing an update or upgrade to the BIG-IP tenant, refer to K34745165: Managing software images on the BIG-IP system.
