Description

  • ASM policies do not sync between the ASM peer devices.
  • Log messages may appear in  /var/log/ts/ts_debug.log that are similar to: epoll.cpp:0060|~epoll_t()|(zmq_assert) Assertion failed: load.get () == 0
  • Log messages may appear in the asm log that are similar to: asm_config_server.pl,F5::Cgc::Channel::send): Failed to send a message, error:15638476.

Environment

  • AdvWAF/ASM
  • ASM Policy Synchronization

Cause

BUG ID 912149

The system exhibits various symptoms related to sync and control plane, and reports errors similar to the following in the log file /var/log/ts/ts_debug.log

|ZEROMQ|Jan 15 03:51:07.185|10369|9846|9846|epoll.cpp:0060|~epoll_t()|(zmq_assert) Assertion failed: load.get () == 0 |ZEROMQ|Sep 15 02:03:22.202|19223|21377|21377|epoll.cpp:0060|~epoll_t()|(zmq_assert) Assertion failed: load.get () == 0 |ZEROMQ|Oct 14 22:49:22.427|19646|6576|6576|epoll.cpp:0060|~epoll_t()|(zmq_assert) Assertion failed: load.get () == 0 |ZEROMQ|Oct 15 10:49:22.274|27987|23809|23809|epoll.cpp:0060|~epoll_t()|(zmq_assert) Assertion failed: load.get () == 0
Note: The occurrences of the Cgc::Channel message in the /var/log/asm and /var/log/ts/asm_config_server logs are the most reliable indicator of this issue.

Recommended Actions

  1. As a workaround you can use the following command to restart asm_config_server on each unit in the device group
    pkill -f asm_config_server
     
  2. Upgrade to 16.1.2
