Known Issue

A memory leak may occur when the BIG-IP system aborts iSession connections.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is processing APM application tunnels or AAM iSession connections.
  • The iSession profile is configured with the Reuse Connection property set to Enable.
  • The BIG-IP system aborts a large number of iSession connections while waiting to be reused.

Impact

Memory utilization on the BIG-IP system steadily increases, which may eventually affect other services and overall system performance.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Over time, the system performance may degrade and eventually become unresponsive or reboot due to memory exhaustion.
  • The amount of memory allocated for and used by the iSession subsystem will increase over time.

    To inspect the memory usage for the iSession subsystem, you can use the following Traffic Management Shell (tmsh) command:

    # tmsh show /sys memory | egrep 'Max\ Alloc|^isession\ '

    The command output appears similar to the following example:

    SubSystem Alloc (bytes) Max Alloc (bytes) Object Size
    isession 5.3G 5.3G 1

    Repeating the command will show an increase over time.

Workaround

To work around this issue, you can disable the iSession profile's Reuse Connection setting and restart the Traffic Management Microkernel (TMM) process. To do so, perform the following two procedures:

Disabling the Reuse Connection setting in the iSession profile

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > iSession.
  3. Click on the name of the iSession profile in use.
  4. Set the value of the Reuse Connection property to Disable.
  5. Click Update.

Restarting the TMM process

Impact of workaround: Restarting the TMM process causes a brief traffic disruption.

  1. Log in to the BIG-IP command line.
  2. Restart TMM by typing the following command:

    bigstart restart tmm
