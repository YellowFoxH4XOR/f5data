Description

Users removed from a VPN access group in Active Directory (AD) continued to have VPN access through BIG-IP APM. Investigation revealed that users retained access due to inherited group membership via nested AD groups. BIG-IP APM evaluates effective group membership, including nested groups, not just direct memberOf attributes.

Environment

  • BIG-IP APM
  • APM policy configured for VPN access using AD group membership
  • Nested AD group structure
  • Actions taken:
    • Manual cache clearing in Access >> Authentication >> Active Directory
    • Group Cache Lifetime adjustments
    • Reboot of HA pair
    • Verification of AD replication and domain controller configuration

Cause

BIG-IP APM evaluates effective AD group membership, including nested groups. Users may retain access if they are members of a parent group that is itself a member of the VPN access group, resulting in inherited access rights.

Answer/Recommended Actions

  • When troubleshooting access issues:
    • Check both direct and inherited (nested) group memberships in AD for affected users.
    • Remove users from all parent groups that may confer access through group nesting to fully revoke access.
  • To clear group membership cache on BIG-IP APM:
    1. Go to Access >> Authentication >> Active Directory in the BIG-IP GUI.
    2. Select the relevant Active Directory server object.
    3. In the Group Cache Lifetime section, click "Clear Cache".
  • If using OAuth or other authentication methods, verify which authentication source is being used in the access policy.
  • If unexpected access persists, enable APM policy debugging, reproduce the issue, and review session logs for group membership evaluation.
  • Confirm AD replication and domain controller availability if group changes are not reflected as expected.

Additional Information

  • BIG-IP APM evaluates effective group membership, not just direct memberOf attributes.
  • Removing a user from only the direct VPN access group may not be sufficient if nested groups are present.
  • Access will be denied as expected only after the user is removed from all groups that provide inherited access.
