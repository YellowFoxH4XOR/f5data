Topic

Due to the virtualized nature of vCMP systems, most hardware dependencies are abstracted on the vCMP guest. As a result, there is no direct relationship between the physical interfaces assigned to VLANs on the vCMP host and the interfaces displayed on the guest.

Description

The vCMP feature designates the vCMP host as the system-wide hypervisor that runs BIG-IP instances, known as guests. On vCMP systems, most network resources are configured on the vCMP host system. For example, rather than configuring interfaces on a vCMP guest, a guest administrator simply creates a self IP address within the guest, specifying one of the VLANs that the host administrator previously configured on the host.

The BIG-IP vCMP host administrator performs the following interface-related tasks on the vCMP host as follows:

  • Configures physical interfaces as required.
  • Assigns physical interfaces to VLANs/trunks.
  • Assigns VLANs/trunks to vCMP guest instances.

Review the following information to understand how the vCMP hypervisor assigns interfaces to the vCMP guests:

BIG-IP VIPRION platforms

  • Typically the number of interfaces that the hypervisor allocates to the guest corresponds to the number of CPU cores per-slot that the administrator assigns to the guest when the guest is created or modified; however, some platforms allocate one interface per two CPU cores per-slot. For example the i11800-DS uses this 2:1 ratio.
  • The system designates interfaces on the vCMP guest as follows:
    • vCMP guest interfaces appear in the following form: slot/0.x
      • slot indicates the blade(s) on which the guest is running.
      • 0.x indicates the guest's connection to the internal data plane of the VIPRION chassis.

        For example, the following tmsh output indicates that the guest is running on blades 1 and 2 of the VIPRION chassis, and connected to the internal data plane using internal interfaces 0.9 and 0.10 of the specified blades:

        tmsh show /net interface

        ----------------------------------------------------------------------
        Net::Interface
        Name  Status    Bits    Bits    Pkts    Pkts   Drops  Errs       Media
                          In     Out      In     Out                          
        ----------------------------------------------------------------------
        1/0.9  up       3.3T    2.4T    3.4G    2.2G    0      0        10000T-FD
        1/0.10 up       1.1T    642.8G  1.3G    695.8M  0      0        10000T-FD
        2/0.9  up       4.8T    2.1T    4.1G    2.0G    0      0        10000T-FD
        2/0.10 up       2.9T    629.4G  1.9G    694.2M  0      0        10000T-FD

    • Interfaces assigned to vCMP guests are unique; guest instances do not share interface resources.

BIG-IP appliance platforms (vCMP compatible)

  • The number of interfaces that the hypervisor allocates to the guest corresponds to the number of CPU cores that the administrator assigns to the guest when the guest is created or modified.
  • The system designates interfaces on the vCMP guest as follows:
    • vCMP guest interfaces appear in the following form: 0.x.
      • 0.x indicates the guest's connection to the internal data plane of the BIG-IP appliance.

        For example, the following tmsh output indicates that the guest is connected to the internal data plane using internal interfaces 0.5 and 0.6:

        tmsh show /net interface
        --------------------------------------------------------------------
        Net::Interface
        Name  Status    Bits    Bits    Pkts    Pkts  Drops  Errs      Media
                          In     Out      In     Out                        
        --------------------------------------------------------------------
        0.5   up       309.6M  309.6M  471.9K  471.9K  0     0  10000T-FD
        0.6   up       309.6M  309.6M  471.9K  471.9K  0     0  10000T-FD
    • Interfaces assigned to vCMP guests are unique; guest instances do not share interface resources.

Recommendations

  • Configure specific interface settings on the vCMP host system as needed; interfaces designated to the vCMP guests are abstracted and not configurable on the guest.
