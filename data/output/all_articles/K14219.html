Known Issue

When using a user-defined virtual server for network access VPN traffic, the system does not apply a Layer 4 (L4) access control list (ACL) to the network access tunnel.

This issue occurs when all the following conditions are met:

  • The BIG-IP APM virtual server targets a layered virtual server, such as a single sign-on (SSO) layered virtual server or one used for BIG-IP LTM routing to back-end web servers.
  • You have configured the referenced BIG-IP APM access policy with an L4 ACL.

When you apply an ACL to a BIG-IP APM access policy, the access policy dynamically creates an internal layered virtual server that the system uses to apply the ACL. The specificity of this virtual server is Source: 0.0.0.0/0 and Destination: 0.0.0.0/0. However, if the BIG-IP APM virtual server targets a layered virtual server, such as an SSO-layered virtual server, traffic bypasses the dynamically-created internal layered virtual server and the ACL is not applied.  Based on the order of precedence for virtual server matching, the BIG-IP system selects the layered virtual server you configured ahead of the virtual server dynamically created by the access policy. For more information, refer to K14800: Order of precedence for virtual server matching (11.3.0 and later).

Impact

Applying access control using an L4 ACL may allow unwanted traffic to pass and may also block valid traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system allows unexpected network traffic to pass.
  • Your BIG-IP system blocks expected network traffic.

* Important: To use the feature in a fixed version, you must create and apply a custom iRule to the BIG-IP APM layered virtual server as described in the following procedure.

Creating and applying a custom iRule to a BIG-IP APM layered virtual server

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > Create.
  3. Enter a name for the iRule.

    For example:

    apm_l4acl_eval_rule

  4. For Definition, enter the following text:

    when CLIENT_ACCEPTED {
            ACL::eval
    }

  5. Select Finished.
  6. Select Virtual Servers.
  7. Select the name of the BIG-IP APM virtual layered server.
  8. Select the Resources tab.
  9. For iRules, select Manage.
  10. From the Available list, select the iRule you previously created and move it to the Enabled list.
  11. Select Finished.

Workaround

None

Note: You may configure a Layer 7 (L7) ACL if the network traffic is HTTP.
