K000137727: Updating MS Exchange 2019 server from CU10 to CU13 randomly breaks OWA connections going via BIG-IP VS

Type
Support Solution
Published
2023-11-29
Updated
2023-11-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.3
Source
https://my.f5.com/manage/s/article/K000137727

Description

On some deployments which have multiple MS Exchange 2019 Servers as pool members and OWA enabled, when persistence is expected to take place on the Exchange servers (rather than the BIG-IP, which is not configured for persistence at all), it has been seen that when the Exchange servers are updated from CU10 to CU13, client connection persistence for OWA connections on the MS Exchange Servers is broken when the client connections are going via BIG-IP. Client connection persistence still works fine when the clients go directly to the Exchange servers (ie. when BIG-IP is removed from the mix). 

This has the effect of making it seem that the client connections that go via the BIG-IP are occasionally failing, and some parts of clients' inboxes are not displaying correctly via OWA.

 

Environment

LTM, MS Exchange Server 2019 with Outlook Web Access (OWA) 

 

Cause

Due to some undisclosed changes between MS Exchange Server 2019 CU13 and CU10, where previously Exchange servers were running CU10 and handled persistence fine internally despite all client connections going via the BIG-IP and SNAT being used for OWA, if the Exchange servers are updated to CU13 then persistence no longer works when the client connections are going via BIG-IP and using SNAT (although it continues to work fine when the BIG-IP is bypassed and client connections go directly to the Exchange servers).

 

Recommended Actions

Enabling HTTP cookie-based persistence on the BIG-IP for the OWA VS solves this issue.
In theory any persistence setting applied on the BIG-IP which ensures that OWA connections are persisted to the correct Exchange servers (pool members) should also work.

 

Additional Information

None.
