Description

In addition to maintaining strong authentication and password standards, Monitoring login attempts is an important part of network security. Monitoring login attempts can assist in tracking both authorized and unauthorized attempts to access a F5OS VELOS controller, giving administrators vital information for formulating a security policy and reacting to threats. Monitoring login attempts is an important part of network security. 

 

The following three important log files track F5OS-C login attempts:

/var/log/audit/audit.log - This is a host log:

  • Tracks successful login attempts and the start-to-end session details that are initiated through SSH using bash and confd.
  • Tracks successful and failed login attempts through HTTP using REST API or the Configuration utility.

/var/log_controllers/audit.log - This is a controllers log:

  • Tracks successful login attempts and the start-to-end session details that are initiated through SSH using bash and confd.
  • Tracks successful and failed login attempts through HTTP using REST API or the Configuration utility.

/var/log/secure - This is a host log:

  • Tracks the details of the successful and failed login attempts that are initiated through SSH using bash and confd, including the source IP address.

Environment

F5OS-C all version

Cause

None

Recommended Actions

You can review login attempts from the command line.

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Review current  log files

  1. Connect using SSH to the system controller floating management IP address or chassis partition management IP address.
  2. Log in to the command line interface (CLI) of the system controller or chassis partition using an account with admin access.
  3. To show the contents of a log file, use following command line.
    file show [ log/confd/<filename> | log/controller/<filename> | log/host/<filename>
    For example, to view the host audit log file, enter the following command:
    syscon-1-active# file show log/host/audit/audit.log | more
    To view controller audit log file, enter following command:
    syscon-1-active# file show log/controller/audit.log | more

Interpret the audit log

Successful command-line login attempts appear similar to the following example:

type=USER_AUTH msg=audit(1662636112.097:372): pid=21772 uid=0 auid=4294967295 ses=4294967295 subj=system_u:system_r:sshd_t:s0-s0:c0.c1023 msg='op=PAM:authentication grantors=pam_tally2,pam_exec,pam_unix acct="admin" exe="/usr/sbin/sshd" hostname=10.10.10.29 addr=10.10.10.29 terminal=ssh res=success'
type=USER_AUTH msg=audit(1662636112.106:373): pid=21772 uid=0 auid=4294967295 ses=4294967295 subj=system_u:system_r:sshd_t:s0-s0:c0.c1023 msg='op=success acct="admin" exe="/usr/sbin/sshd" hostname=? addr=10.10.10.29 terminal=ssh res=success'
type=USER_LOGIN msg=audit(1662636112.149:374): pid=21772 uid=0 auid=1000 ses=185135 subj=system_u:system_r:sshd_t:s0-s0:c0.c1023 msg='op=login id=1000 exe="/usr/sbin/sshd" hostname=10.10.10.29 addr=10.10.10.29 terminal=/dev/pts/1 res=success'

Note: Event type USER_LOGIN is not seen when root user succeeded to login. Both event type USER_AUTH and USER_LOGIN is seen when admin user attempts to login.

When the user logs out, the system reports information that appears similar to the following example:

type=USER_LOGOUT msg=audit(1662636136.614:375): pid=21772 uid=0 auid=1000 ses=185135 subj=system_u:system_r:sshd_t:s0-s0:c0.c1023 msg='op=login id=1000 exe="/usr/sbin/sshd" hostname=? addr=? terminal=/dev/pts/1 res=success'

Note: Event type=USER_LOGOUT is not seen when root user logs out. Event type=USER_LOGOUT is seen when admin user logs out.

Unsuccessful command line login attempts simultaneously generate two messages, as follows:

type=USER_AUTH msg=audit(1746178739.471:738): pid=23721 uid=0 auid=4294967295 ses=4294967295 subj=system_u:system_r:sshd_t:s0-s0:c0.c1023 msg='op=challenge-response acct="admin" exe="/usr/sbin/sshd" hostname=? addr=10.154.88.9 terminal=ssh res=failed'
type=USER_ERR msg=audit(1746178739.472:739): pid=23721 uid=0 auid=4294967295 ses=4294967295 subj=system_u:system_r:sshd_t:s0-s0:c0.c1023 msg='op=PAM:bad_ident grantors=? acct="?" exe="/usr/sbin/sshd" hostname=10.154.88.9 addr=10.154.88.9 terminal=ssh res=failed'
type=USER_LOGIN msg=audit(1746178739.473:740): pid=23721 uid=0 auid=4294967295 ses=4294967295 subj=system_u:system_r:sshd_t:s0-s0:c0.c1023 msg='op=login acct="admin" exe="/usr/sbin/sshd" hostname=? addr=10.154.88.9 terminal=ssh res=failed'

Successful GUI Configuration utility login attempts appear similar to the following log/host/secure example:

2025-05-02T02:45:28.028568-07:00 VEL410 external-authenticator: nodename=controller-2 pam_unix(password-auth:session): session opened for user admin by (uid=0)
2025-05-02T02:45:28.054576-07:00 VEL410 external-authenticator: nodename=controller-2 pam_unix(password-auth:session): session closed for user admin

Unsuccessful Configuration utility login attempts appear similar to the following log/host/secure example:

2025-05-02T02:46:55.561248-07:00 VEL410 external-authenticator: nodename=controller-2 pam_unix(password-auth:auth): authentication failure; logname= uid=0 euid=0 tty= ruser= rhost=172.18.203.231  user=admin
