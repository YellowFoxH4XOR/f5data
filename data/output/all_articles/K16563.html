Known Issue

Using the BIG-IP APM system as a Security Assertion Markup Language (SAML) Identity Provider (IdP) may generate assertions with hexadecimal-encoded values.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured as a SAML IdP.
  • The BIG-IP APM system is configured with an LDAP, Active Directory, or RADIUS type AAA server.
  • Attributes received from the AAA server contain values with non-ASCII characters.

For example, if a username configured in the authentication server contains non-ASCII characters, such as Renée, the attribute value in the SAML assertion created by the BIG-IP APM system is encoded with hexadecimal characters:

<saml2:Attribute Name="FirstName" NameFormat="urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified">
<saml2:AttributeValue>0x52656ec3a965</saml2:AttributeValue>
</saml2:Attribute>

Impact

The BIG-IP APM system hex encodes the attribute values when generating SAML assertions. If the service provider (SP) is unable to process the hex-encoded values, SAML authentication may fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to access services when the BIG-IP APM system is configured as a SAML IdP.
  • SAML SPs are unable to process SAML assertions generated by the BIG-IP APM system.
  • Users with non-ASCII character in their username are unable to access services using SAML.

Workaround

While there is no work around for BIG-IP APM as an IdP, you may be able to work around this issue by configuring the SAML SP to properly handle the hex-encoded values in the SAML assertions generated by the BIG-IP APM system. The hex-encoded values begin with the characters 0x.
