K000137576: SAML Assertion rejected: Received invalid SAML response: Invalid SAML Response. Not match the saml-schema-protocol-2.0.xsd

Type
Support Solution
Published
2023-11-14
Updated
2024-03-13
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000137576

Description

SAML assertion fails with the following error:

Received invalid SAML response: Invalid SAML Response. Not match the saml-schema-protocol-2.0.xsd

You may also experience HTTP ERR 400 when trying to connect.

 

Environment

  • SAML environment
  • A xs:base64Binary attribute in SAML response in one of SAML IDP Provider config

Cause

This is due to Bug ID 1397321: [APM][SAML IDP] BIGIP as IDP does not include proper XML namespace declaration when a base64 type SAML attribute is added

Right now, this is not supported on a vanilla version of BigIP.

Recommended Actions

Remove the attribute from your setup on the SAML IDP side.

This is how it could look:

<saml2:Attribute xmlns:saml2="urn:oasis:names:tc:SAML:2.0:assertion" Name="thumbnailPhoto" NameFormat="urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified">

<saml2:AttributeValue xmlns:saml2="urn:oasis:names:tc:SAML:2.0:assertion" xmlns:xsi=http://www.w3.org/2001/XMLSchema-instance xsi:type="xs:base64Binary">base64string==</saml2:AttributeValue>

</saml2:Attribute>

The "base64string==" placeholder in the example above means any binary string of type base64 in your attribute.

Alternatively, please contact F5 Support and open a case to request an Engineering Hotfix for Bug ID 1397321 and Bug ID 1495265 together.

The fix for 1495265 alongside 1397321 is also needed to support this.

Bug ID 1495265: [SAML][IDP] Modifying the Assertion by adding xmlns:xs namespace causes signature failure on SP side
