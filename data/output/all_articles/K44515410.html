K44515410: The BIG-IP may send all traffic to a single pool member

Type
Support Solution
Published
2021-11-04
Updated
2025-04-02
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K44515410

Description
All traffic is being sent to a single pool member despite other pool members being available.

Environment
  • Persistence profile type Destination Address Affinity is configured as primary or fallback.
  • Virtual address uses a /32 subnet mask  (255.255.255.255)

Cause

Destination address persistence is designed to work with virtual servers configured with a network address (typically seen when load balancing between gateways), as opposed to a host address (which is most common and used for traditional server load balancing). Since there can be only one destination address for a /32 subnet, configuring a persistence type of Destination Address Affinity in this scenario will cause all connections to be sent to the same pool member.

Recommended Actions

  1.  Do not configure Destination Address Affinity persistence with a virtual server that uses a /32 destination address
