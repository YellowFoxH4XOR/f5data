K000162092: How to Add Virtual Servers to an Existing GSLB_Server Using AS3 Without Overwriting Existing Configuration

Description

This article explains how to add new virtual servers to an existing GSLB_Server object in a BIG-IP DNS (GTM-only) environment using F5 AS3, without overwriting or deleting the current virtual servers. It addresses the scenario where users want to incrementally add virtual servers to a GSLB_Server managed by AS3, and clarifies the supported methods for doing so.

Environment

  • BIG-IP DNS (GTM) module, version 17.5.1
  • AS3 version 3.56.0 or later
  • Configuration managed via AS3 declarations (API or Terraform)
  • GSLB_Server object in /Common/Shared referencing an existing Data Center

Cause

AS3 is a declarative API. Traditionally, when updating a GSLB_Server object, the declaration must include the full desired state of all virtual servers; otherwise, any virtual servers not listed are removed. However, in AS3 version 3.56.0 and later, the PATCH method is supported for GSLB_Server objects, allowing users to append new virtual servers without removing existing ones.

Answer/Recommended Actions

Option 1: Add Virtual Servers Using PATCH (AS3 3.56.0+)

You can use the PATCH method to append a new virtual server to an existing GSLB_Server object without affecting the current configuration.

Example PATCH Request:

{
  "class": "AS3",
  "action": "patch",
  "patchBody": [
    {
      "op": "add",
      "path": "/Common/Shared/myGSLBServer/virtualServers/-",
      "value": {
        "address": "192.168.1.103",
        "port": 8080,
        "name": "web-vs-3"
      }
    }
  ]
}
",

Example curl command:

curl -sk -u admin:<password> \
  -H "Content-Type: application/json" \
  -X POST \
  https://<BIG-IP-MGMT-IP>/mgmt/shared/appsvcs/declare \
  -d '{"class":"AS3","action":"patch","patchBody":[{"op":"add","path":"/Common/Shared/myGSLBServer/virtualServers/-","value":{"address":"192.168.1.103","port":8080,"name":"web-vs-3"}}]}'
  • Submit this PATCH request to:
    https://<BIG-IP-MGMT-IP>/mgmt/shared/appsvcs/declare
  • The new virtual server will be appended to the existing list, and all previous virtual servers will remain intact.

Option 2: Full-State Declaration (All AS3 Versions)

If PATCH is not supported in your AS3 version, you must submit a full declaration that includes all existing and new virtual servers. Any virtual server not included in the declaration will be removed.

Example Declaration:

{
  "class": "AS3",
  "action": "deploy",
  "persist": true,
  "declaration": {
    "class": "ADC",
    "schemaVersion": "3.56.0",
    "Common": {
      "class": "Tenant",
      "Shared": {
        "class": "Application",
        "template": "shared",
        "myGSLBServer": {
          "class": "GSLB_Server",
          "dataCenter": {
            "bigip": "/Common/DC1"
          },
          "devices": [
            {
              "address": "10.1.1.10"
            }
          ],
          "virtualServerDiscoveryMode": "disabled",
          "virtualServers": [
            {
              "address":"
 "192.168.1.101",
              "port": 80,
              "name": "web-vs-1"
            },
            {
              "address":",
 "192.168.1.102",
              "port": 443,
              "name": "web-vs-2"
            },
            {
              "address":",
 "192.168.1.103",
              "port": 8080,
              "name": "web-vs-3"
            }
          ]
        }
      }
    }
  }
}
",

Additional Information

  • Always validate changes in a test environment before applying to production.
  • PATCH support for GSLB_Server objects was confirmed in AS3 version 3.56.0. Behavior may differ in earlier versions.
  • If you need to assign monitors or modify other properties, include the full updated object in your declaration.
