Description

  • When configuring BIG-IP as Identity Provider (IdP), it is often requested to auto-launch Service Provider (SP) resources for a smooth customer experience.
  • This article outlines how to implement an iRule to auto-launch a single or multiple SP resources.

Environment

  • BIG-IP APM
  • Security Assertion Markup Language (SAML) with BIG-IP as an IdP 
  • Either a single or multiple SP connectors
  • IdP webtop configured with SAML Resources

Recommended Actions

Creating an iRule to auto-launch a single assigned SP resource

Note: As this procedure auto-launches a single SAML resource applied in to the Advanced Resources Assign. No other webtop object is available or visible.

  • The following iRule does nothing if it is a SP initiated connection because it returns automatically to the correct SP.
  • If an IdP initiates the iRule, the iRule knows to auto-launch the single SAML resource that is assigned.
  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List and click Create.
  3. Name the iRule and paste the following into the Definition box.

    when ACCESS_POLICY_COMPLETED {

        if { [ACCESS::session data get session.server.landinguri] == "/saml/idp/profile/redirectorpost/sso" } {
            log local0. "SP initiated SAML detected, not sending redirect"
        } else {
            ACCESS::respond 302 Location "/saml/idp/res?id=[ACCESS::session data get session.assigned.resources.saml]"
            log local0. "IDP initiated SAML detected, sending redirect"
        }
    }
    when ACCESS_ACL_ALLOWED {
        ACCESS::respond 302 Location "/saml/idp/res?id=[ACCESS::session data get session.assigned.resources.saml]"
    }

  4. Click Finished.

Applying the single SP auto-launch iRule to the IdP virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic  > Virtual Servers > Virtual Server List and click the IdP virtual server.
  3. Click Resources
  4. Next to the iRules, click Manage.
  5. Move the iRule you created into the Enabled box.
  6. Click Finished.

Creating an iRule to auto-launch multiple assigned SP resources based off landing URI

For this iRule to work correctly, the IdPs assign the landing URI to each SP. For example, when a user accesses https://idp.example.com/sp1, the BIG-IP APM assigns the landing URI to the following session variable: session.server.landinguri.

  • Each SP needs its own landinguri switch option in the following iRule.
  • Each switch option points to the exact SAML resource based off the landinguri.
  • In the previous example, this example it uses the SAML resource /saml/idp/res?id=/Common/sp1
  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List and click Create.
  3. Name the iRule and paste the following into the Definition box:

    when HTTP_REQUEST {
      set httpURI [HTTP::uri]
    }
    when ACCESS_POLICY_COMPLETED priority 30 {
        if { [ACCESS::session data get session.server.landinguri] == "/saml/idp/profile/redirectorpost/sso" } { 
            log local0. "SP initiated SAML detected, not sending redirect"
        }     else     {
        switch -glob [string tolower [ACCESS::session data get session.server.landinguri]] {
            "/sp1*"
                {
                    log local0. "Setting start uri to sp1"
                    ACCESS::respond 302 Location "/saml/idp/res?id=/Common/sp1"
                    return
                }
            "/sp2*"
                {
                    log local0. "Setting start uri to sp2"
                    ACCESS::respond 302 Location "/saml/idp/res?id=/Common/sp2"
                    return
                }
            }
        }
    }

    when ACCESS_ACL_ALLOWED {
        if { [ACCESS::session data get session.server.landinguri] == "/saml/idp/profile/redirectorpost/sso" } {
        }     else     {
        switch -glob [string tolower $httpURI] {
            "/sp1*"
                {
                    ACCESS::respond 302 Location "/saml/idp/res?id=/Common/sp1"
                    return
                }
            "/sp2*"
                {
                    ACCESS::respond 302 Location "/saml/idp/res?id=/Common/sp2"
                    return
                }
            }
        }
    }

  4. Click Finished.

Applying the iRule created to auto-launch multiple assigned SP resources based off landing URI

  1. Navigate to Local Traffic  >  Virtual Servers > Virtual Server List and click the IdP virtual server.
  2. Click Resources.
  3. Next to iRules, click Manage.
  4. Move the iRule you created into the Enabled box.
  5. Click Finished.

Additional Information

When using auto-launch iRules, the BIG-IP never acknowledges these connections as SP-initiated. Therefore, the system does not maintain relay states sent from an SP or consume SAML requests.
