K12820: A local user password change fails if the CAPTCHA feature is enabled

Type
Known Issue
Published
2011-05-02
Updated

Status
Legacy Content
Applies to
  • Legacy Products
  • FirePass: 7.0.0, 6.1.0
Source

Known Issue

Description

A local user account password will not be updated when the CAPTCHA feature is enabled. You can configure FirePass to force a user to change their password when logging in. If the user is prompted to change the password on login with the CAPTCHA feature enabled, the password will not be updated and the user will fail to log in with the new password. If the user logs in with their original password again, they will be prompted to update their password, once again creating an endless loop.

Impact

Local user accounts with expired passwords will be unable to log in to the FirePass controller.

Symptoms

As a result of this issue, the FirePass system may experience the following symptoms:

  • When a local user with an expired password attempts to log in, they will be prompted to update their password and upon trying to enter the newly updated password will receive the following error message:

    Either Username or Password do not match!  
    Please try again.
  • Entering the old password will once again prompt them to update the password

Workaround

To work around this issue, you can disable the Force password change options. To do so, perform the following procedure:

Impact of Workaround: Applying this workaround will disable the requirement for users to update their passwords periodically.

  1. Log in to the FirePass Administrative Console.
  2. Click Users.
  3. Click the edit button next to the user you want to update.
  4. Clear the Force password change on first logon check box.
  5. Clear the Force periodic password refresh every X days check box.
  6. Click the Update user details button.  

Optionally, you can reset the users password by entering a password in the Password and Confirm Password text boxes.
