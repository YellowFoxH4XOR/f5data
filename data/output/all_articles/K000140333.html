Description

BIG-IP reports via SNMP reply, the BGP peer IP address as 0.0.0.0. Behavior can be seen only when such peer neighbor is DOWN. Established and working peer IPs are unaffected.

Presenting situation for below example:
When SNMP query arrive to F5 unit for below variable:
variable-bindings: 1 item
    1.3.6.1.2.1.15.3.1.7: Value (Null)
        Object Name: 1.3.6.1.2.1.15.3.1.7 (iso.3.6.1.2.1.15.3.1.7)
        Value (Null)

 

BIG-IP would respond with below values for BGP peers with following Values, for following BGP IP peers (DOWN: 192.0.2.14 & 192.0.2.17), (UP: 192.0.2.141):
variable-bindings: 3 items
    1.3.6.1.2.1.15.3.1.7.192.0.2.14: 0.0.0.0
        Object Name: 1.3.6.1.2.1.15.3.1.7.192.0.2.14 (iso.3.6.1.2.1.15.3.1.7.192.0.2.14)
        Value (IpAddress): 0.0.0.0
    1.3.6.1.2.1.15.3.1.7.192.0.2.17: 0.0.0.0
        Object Name: 1.3.6.1.2.1.15.3.1.7.192.0.2.17 (iso.3.6.1.2.1.15.3.1.7.192.0.2.17)
        Value (IpAddress): 0.0.0.0
    1.3.6.1.2.1.15.3.1.7.192.0.2.141: 192.0.2.141
        Object Name: 1.3.6.1.2.1.15.3.1.7.192.0.2.141 (iso.3.6.1.2.1.15.3.1.7.192.0.2.141)
        Value (IpAddress): 192.0.2.141

Environment

  • BIG-IP LTM
  • BGP
  • SNMP

Cause

None, this is expected behavior accordingly to RFC4273.

Recommended Actions

None

Additional Information

The BGP Identifier of this entry's BGP peer MUST be 0.0.0.0 unless the bgpPeerState is in the openconfirm or the established state.
