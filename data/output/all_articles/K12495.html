Known Issue

This is the result of a known issue. For troubleshooting purposes, it may be necessary to administratively disable a VIPRION blade. However, when you do so, the links attached to that blade are not downed. As a result, the blade continues to receive traffic from the upstream devices. This is not the expected behavior; when a VIPRION blade is administratively disabled, its links should be downed immediately. In addition, this issue may create a confusing environment because the primary blade reports the interfaces as down, but the disabled blade itself and the upstream devices report the links as still up.

Note: Even if the links attached to the disabled blade are still up and the upstream devices are sending traffic to the blade, traffic may potentially not be affected. Assuming the VIPRION system was deployed correctly and the internal switching infrastructure is working properly, traffic destined to the disabled blade will be redirected to the other available blade(s).

F5 Product Development tracked this issue as ID 340475 and it was fixed in BIG-IP versions 10.2.2 and 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or PSM release notes.

Workaround

If you need to disable a VIPRION blade and also ensure its links will be downed, you can perform one of the following workarounds:

  • Manually disable the interfaces attached to that blade in addition to administratively disabling the blade by using the Configuration utility
  • Manually disable the interfaces attached to that blade in addition to administratively disabling the blade by using Traffic Management Shell (tmsh) commands
  • Stop all services on that blade instead of administratively disabling the blade

Manually disabling the interfaces on a VIPRION blade in addition to administratively disabling the blade by using the Configuration utility

Impact of procedure: F5 recommends that you perform this task during a maintenance window as Production traffic on the affected VIPRION blade will be disrupted.

  1. Log in to the Configuration utility by connecting to the floating management IP address of the cluster.
  2. Navigate to System > Clusters > Properties.
  3. Select the box next to the desired slot.
  4. Click Disable/Yield.
  5. Navigate to Network > Interfaces > Interface List.
  6. Select the box next to the desired interfaces (typically all the interfaces in use on the blade that was administratively disabled).
  7. Click Disable.

    Note: To re-enable the interfaces and the blade, perform this procedure again, but click Enable instead of Disable.

Manually disabling the interfaces on a VIPRION blade in addition to administratively disabling the blade by using tmsh commands

Impact of procedure: F5 recommends that you perform this task during a maintenance window as Production traffic on the affected VIPRION blade will be disrupted.

  1. Log in to the command line
  2. Set the VIPRION blade to Disabled by using the following command syntax:

    tmsh modify sys cluster default members { <slot number> { disabled } }

    For example:

    tmsh modify sys cluster default members { 2 { disabled } }

  3. Set the VIPRION interfaces to Disabled by using the following command syntax:

    tmsh modify net interface <slot number>/<interface> disabled

    For example:

    For single interface

    tmsh modify net interface 2/1.1 disabled

    For multiple interfaces

    tmsh modify net interface 2/1.1 2/1.2 disabled

    Note: To re-enable the interfaces and the blade, perform this procedure again, but modify the command to use enabled instead.

Stopping all services on a VIPRION blade instead of administratively disabling the blade

Impact of procedure: F5 recommends that you perform this task during a maintenance window as Production traffic on the affected VIPRION blade will be disrupted.

  1. Log in to the command line by connecting to the management IP address of the blade that you want to disable.
  2. To stop all services on the blade, type the following command:

    bigstart stop

    Note: Stopping the services will not terminate your SSH connection to the blade.

    Note: To start the services again, type the bigstart start command.
