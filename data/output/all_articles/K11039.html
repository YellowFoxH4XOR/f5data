Known Issue

This is the result of a known issue. In BIG-IP GTM 9.x, the Internet Control Message Protocol (ICMP) monitor is incorrectly listed as an available monitor type for BIG-IP GTM server objects. This behavior should not occur because the ICMP monitor cannot be applied to any GTM object. The system also allows the creation of custom monitors derived from the ICMP monitor; however, these custom monitors cannot be applied to any BIG-IP GTM object as well.

As a result, this issue may generate confusion as to why the ICMP monitor is available, but cannot be applied to any BIG-IP GTM object.

Note: You may use the gateway_icmp monitor to verify the availability of BIG-IP GTM objects.

F5 Product Development tracked this issue as CR79666 and it was fixed in BIG-IP GTM 10.0.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Beginning in BIG-IP GTM 10.0.0, the ICMP monitor was removed from the list of available monitors. However, as a result of this change, if you created a custom ICMP monitor under BIG-IP GTM version 9.x, and then you upgrade to version 10.x, the system will fail to load the GTM configuration. This issue occurs because the custom ICMP monitor references a parent monitor that does not exist in BIG-IP GTM version 10.x. When this issue occurs, the gtmload command returns an error message that appears similar to the following example:

gtmload: Initializing ...
/usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
/usr/local/gtm/include/base_region.ISP: SUCCESS
/config/gtm/wideip.conf: SUCCESS
gtmload: SUCCESS
ERROR, recvMCPreply: Got bad result: 01070043:3: Monitor my_icmp parent not found.

To restore your BIG-IP GTM configuration to a working state, you must edit the wideip.conf file to remove custom ICMP monitor definitions. To do so, perform the following procedure:

  1. Log in to the BIG-IP GTM command line interface.
  2. Change directories to the /config/gtm/ directory by typing the following command:

    cd /config/gtm/
  3. Back up the current wideip.conf file by typing the following command:

    cp wideip.conf wideip.conf.SOL11039
  4. Using a text editor, edit the /config/gtm/wideip.conf file.
  5. Scroll down the file until you reach the // *** Monitor Definitions *** section.
  6. Remove custom ICMP monitor definitions.

    For example, you would need to delete the following lines for the my_icmp monitor:

    monitor "my_icmp" {
    defaults from "icmp"
    interval 30
    timeout 120
    probe_interval 1
    probe_timeout 5
    probe_num_probes 3
    probe_num_successes 1
    dest *
    partition "Common"
    }
  7. Save the wideip.conf file.
  8. Quit the text editor.
  9. Using the gtmload command, reload the BIG-IP GTM configuration and verify that no errors are returned.

    For example:

    gtmload: Initializing ...
    /usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
    /usr/local/gtm/include/base_region.ISP: SUCCESS
    /config/gtm/wideip.conf: SUCCESS
    gtmload: SUCCESS
