Description

This article describes an issue where the F5 BIG-IP LTM Oracle database monitor may incorrectly mark a pool member as down, even though the Oracle database is up and responding. The problem occurs when the monitor attempts to authenticate with the database and fails due to timezone parameter issues, resulting in Oracle server throwing errors similar to the following when inspecting /var/log/DBDaemon-[0-9]*.log:

 

  ORA-00604: error occurred at recursive SQL level 1

  ORA-01882: timezone region not found

 

As a result, the pool member is marked down despite successful database operation.

Environment

  • BIG-IP LTM
  • Oracle DB Monitor

Cause

Deprecated time zone alias being sent to a DB server that no longer support it. PD has raised ID2144029 for this. This occurs when BIG-IP 'sys ntp timezone' is set to value (eg. America/Los_Angeles) that has other time zone aliases with the same offset (eg. US/Pacific-New) and the DB monitor client instance picks up a deprecated/unsupported alias from the zoneinfo directory as it tries to find a TZ file with a match for the offset. When the monitor sends the timezone parameter towards the database server, and the server does not support the deprecated time zone alias, the server rejects the connection and the error is thrown. DB monitor marks the pool member down.

Recommended Actions

1. Delete the file /etc/localtime:

 rm /etc/localtime

2. Create a symbolic link for the file pointing to the desired timezone as listed in /usr/share/zoneinfo.

For example, if you have 'sys ntp timezone UTC', the command would be:

 ln -sf /usr/share/zoneinfo/UTC /etc/localtime

If you have 'sys ntp timezone America/Los_Angeles', the command would be:

 ln -sf /usr/share/zoneinfo/America/Los_Angeles /etc/localtime

3. Restart bigd.

 bigstart restart bigd
