What Happened?

You may see load balancers with a status of "Good", "Moderate", or "Critical" and you would like to know what this means.

Environment

  • F5 Distributed Cloud Console
  • Load Balancers

Resolution/Answer

Health Status Indicators:

  1. Critical :

    • Meaning: Indicates that there are serious issues affecting the load balancer or origin pool. This status suggests that the load balancer is unable to handle traffic effectively, possibly due to high error rates, significant latency, or failed health checks.
    • Implications: Immediate attention is required to troubleshoot and resolve the underlying problems. Traffic may be significantly degraded or completely halted.

  2. Moderate :

    • Meaning: Indicates that there are some performance issues or warnings, but the load balancer is still operational. This status suggests that there might be elevated error rates, moderate latency, or some health checks failing intermittently.
    • Implications: While the system is still functional, it's advisable to investigate and address the issues to prevent them from escalating to a critical state. Monitoring and preventive measures should be taken.
  3. Good :

    • Meaning: Indicates that the load balancer and origin pools are operating normally. This status suggests that the performance metrics are within acceptable thresholds, and health checks are passing.
    • Implications: No immediate action is needed. The system is healthy and handling traffic as expected.

How These Statuses Are Determined:

The health status is calculated based on various performance and health check metrics, including but not limited to:

  1. Request Rate:

    • Measures the number of requests being handled by the load balancer.
  2. Error Rate:

    • Tracks the number of errors encountered during request processing.

  3. Drop Rate:

    • Monitors the number of dropped requests.

  4. Latency:

    • Evaluates the response time for requests.

  5. Throughput:

    • Measures the data transfer rate between clients and servers.

  6. Connection Duration:

    • Monitors the duration of established connections.

  7. Client and Server Round-Trip Time (RTT):

    • Measures the time taken for a request to travel from the client to the server and back.

  8. Health Check Results:

    • Based on specific health checks configured for the origin servers, such as HTTP, ICMP, or custom health checks. For instance, an HTTP health check might involve sending a specific request and expecting a particular response code.
