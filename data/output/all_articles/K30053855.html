Known Issue

Deleting and recreating a virtual server within a transaction using the TMOS Shell (tmsh) or iControl representational state transfer (REST) and attempting to modify the profiles on the virtual server may result in an invalid in-memory configuration.

This issue occurs when the following condition is met:

  • From within one tmsh or iControl transaction, you perform the following:
    • Delete a virtual server.
    • Recreate this virtual server with an incompatible profile type.

Impact

This behavior may result in traffic failing to pass as the Traffic Management Microkernel (TMM) rejects the invalid configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • At configuration load time, you view an error message that appears similar to the following example:

    01070095:3: Virtual server /Common/<virtual> lists incompatible profiles

    In this error message, note the following:

    • <virtual> is the name of the changed virtual server
  • When you attempt to make the configuration change, you view an error message in the /var/log/ltm file that appears similar to the following example:

    err tmm[22370]: 01010007:3: Config error: Incomplete hud chain for listener: <name>

Workaround

To work around this issue, you can use alternate commands to perform the same tasks. To do so, perform one of the following procedures:

  • tmsh
  • iControl REST

Impact of workaround: Performing the suggested workarounds should not have a negative impact on your system.

tmsh

Use the profile replace-all-with command instead of the profile add commands.

iControl REST

Use three separate REST calls instead of a single call:

  1. Delete the virtual server.
  2. Create the virtual server (with an empty profile list).
  3. Modify the virtual server's profile list.
