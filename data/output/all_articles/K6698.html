Known Issue

This is the result of a known issue. During the synchronization of a large number of zone files, the gtmd utility reports that the sync_zones process is running. The gtmd utility then attempts to initiate multiple instances of the sync_zones process. Eventually the synchronization fails, with the synchronization of the wideip.conf file and only some of the zones completing the synchronization process. The gtmd utility continues to attempt synchronization as the sync_zones process attempts to synchronize all of the changes.

This issue occurs because the shell used to pass information to the rsync utility does not return the status that the rsync process has completed. The rsync utility then times out and is unable to synchronize all of the zones. This results in a loop situation for the sync_zones process, which attempts to continue to synchronize the zone information.

The following output is reported in the /var/log/gtm directory when this issue occurs:

gtmd: 011a001b:5: SYNC_ZONES started
gtmd: 011a001b:5: SYNC_ZONES started
gtmd: 011a001c:5: SYNC_ZONES skipped. Reason: sync_zones currently running
gtmd: 011a001b:5: SYNC_ZONES started
gtmd: 011a001c:5: SYNC_ZONES skipped. Reason: sync_zones currently running

F5 Product Development tracked this issue as CR69386 and it was fixed in BIG-IP GTM version 9.2.4. For information about upgrading, refer to the BIG-IP GTM release notes.
