Description

When client connects to client-ssl virtual server, handshake may be terminated and an error "alert(40) cannot find matching cert" may be thrown.

Oct 10 11:21:37 bigip.local warning tmm[19298]: 01260009:4: 10.1.1.98:65121 -> 10.1.1.191:443: Connection error: ssl_select_suite:11477: alert(40) cannot find matching cert

Environment

  • TLSv1.3 is enabled on client-ssl virtual server (that means, cipher-group is specified and no-tlsv1.3 option is disabled on client-ssl profile).
  • Cipher-rule dh-groups configuration does not cover specific named groups which client offers for key exchange.
  • Client connects to client-ssl virtual server with TLSv1.3 and with named groups which is not covered by "dh-groups" option on cipher rule.

 

Here is example configuration that meets all of the above conditions. Note that cipher rule dh-groups supports only 3 named groups, P256, P384, and X25519.

ltm cipher rule my_tls13_cipher_rule {
    dh-groups P256:P384:X25519
}
ltm cipher group my_tls13_cipher_group {
    allow {
        my_tls13_cipher_rule { }
    }
}
ltm profile client-ssl my_tls13_clientssl_profile {
    app-service none
    cert-key-chain {
        default {
            cert default.crt
            key default.key
        }
    }
    cipher-group my_tls13_cipher_group
    ciphers none
    defaults-from clientssl
    inherit-ca-certkeychain true
    inherit-certkeychain true
    options { dont-insert-empty-fragments }
}
ltm virtual tls13_clientssl_vs {
    destination 10.1.1.191:443
    ip-protocol tcp
    mask 255.255.255.255
    pool http_pool
    profiles {
        my_tls13_clientssl_profile {
            context clientside
        }
        tcp { }
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
}

 

When client connects to the virtual server with "-groups ffdhe2048" options as shown below, "alert(40) cannot find matching cert" error will be thrown and client will fail to connect to client-ssl virtual server. This is because above cipher-rule configuration missed FFDHE2048 on dh-groups setting.

$ openssl s_client -connect 10.1.1.191:443 -tls1_3 -groups ffdhe2048

 

Cause

Cipher rule "dh-groups" option lacks of specific named groups which is used by client.

 

Recommended Actions

First, check supported_groups TLS extension inside client hello pkt which triggered handshake alert. Then, add necessary named group to cipher rule dh-groups configuration.

 

For example, if client came in with FFDHE2048 or FFDHE3072 but those were not on the dh-groups setting, update cipher rule with those named group.

Figure: Client Hello packet

 

# tmsh modify ltm cipher rule [cipher-rule-name] dh-groups P256:P384:X25519:FFDHE2048:FFDHE3072
