Issue

Description

The purpose of this article is to guide you in distinguishing between a user-initiated disconnect or an error on the client. This distinction can help troubleshoot a VPN disconnection issue.

Environment

  • BIG-IP Access Policy Manager (APM)
  • BIG-IP Edge Client for MacOS
  • Browser Network Access Client on MacOS

Cause

The BIG-IP Edge Client ~Library/Logs/F5Networks/edge.log logs several messages to indicate when a user initiated disconnect occurred, with the following message syntax:

<date time> , 514,15579,edge, 48, /DoRequest.mm, 84, DoRequest, DoRequest, cancel
<date time> , 514,15579,edge, 48, /StandaloneModel.mm, 1078, StandaloneModel, StandaloneModel, new mode, 2
<date time> , 514,15579,edge, 48, /SessionController.mm, 379, SessionController, Session Controller,Controller deactivated, err=, ErrUserInitiated

The client sends the hangup code and you observe the corresponding server-side messages in /var/log/apm on the BIG-IP APM in the following message syntax:

<date time> <bigip hostname> notice tmm[1775]: 01490567:5: /Common/NA_full_tunnel:Common:<sessionid>: Session deleted (user_initiated; code - 1).
<date time> <bigip hostname> notice tmm[1775]: 01490505:5: /Common/NA_full_tunnel:Common:<sessionid>: PPP tunnel <tunnelid> (ID: <sessionid>) closed.

Recommended Actions

When troubleshooting VPN network access disconnect issues, it is important to identify a disconnect that is initiated by users. By observing the client and server side logs above, you can determine this.

Additional Information

To enable verbose logging, follow the steps in K12321: Enabling Network Access debugging for Mac OS X and Linux
