Known Issue

A BIG-IP Next instance may fail to process traffic because the license for the TMM process incorrectly expires after forty-nine point seven (49.7) days.

This issue occurs when all of the following conditions are met:

  • You activated a valid license on your BIG-IP Next instance.
  • 49.7 days have elapsed after the last license activation on the affected BIG-IP Next instance.
  • The BIG-IP Next instance has not been restarted within those 49.7 days.

Impact

The BIG-IP Next instance fails to process traffic when the TMM process changed its state to unlicensed after 49.7 days.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP Next instance suddenly stops passing traffic.
  • The f5-fsm-tmm log file shows an entry indicating that the license has expired for the TMM process similar to the following example:

    f5-fsm-tmm-65c974cccc-btp9c tmm[7]: 01010007:3: Config error: License expired

Workaround

To work around this issue, you can restart your affected BIG-IP Next instance. Similarly, you can prevent this issue from occurring by restaring your BIG-IP Next instance before its uptime reaches 49.7 days. If you have not upgraded to a fixed version listed in the status table, you have to perform this workaround every 49.7 days. To determine the current uptime of your BIG-IP Next instance, refer to the Determine the uptime of your BIG-IP Next instance section in this article. To restart your BIG-IP Next instance, perform the procedure relevant to your deployment mode:

Impact of workaround: F5 recommends that you perform the restart of your BIG-IP Next instance during a maintenance window as the affected instance will not be processing traffic during the restart.

  • BIG-IP Next instance deployed on VELOS or rSeries system
  • BIG-IP Next instance deployed on VMWare ESXi

BIG-IP Next instance deployed on VELOS or rSeries system

To reboot your BIG-IP Next instance deployed on a VELOS or rSeries system, refer to K21121803: Shut down and restart a tenant on the VELOS and F5 rSeries systems.

BIG-IP Next instance deployed on VMWare ESXi

To restart your BIG-IP Next instance deployed on VMWare ESXi, perform the following procedure:

  1. Log in to your VMWare ESXi user interface.
  2. Locate the affected BIG-IP Next instance virtual machine.
  3. Select Actions > Power > Restart Guest OS.
  4. Wait for the affected BIG-IP Next instance to complete its restart process.

Determine the uptime of your BIG-IP Next instance

The method to determine the uptime of your BIG-IP Next instance depends on whether it is deployed on VELOS/rSeries system or third-party hypervisors, such as VMWare ESXi. Perform the procedure relevant to your deployment mode:

Impact of workaround: Performing this procedure should not have any negative impact on your system.

  • BIG-IP Next instance deployed on VELOS or rSeries system
  • BIG-IP Next instance deployed on third party hypervisor and managed by BIG-IP Next Central Manager

BIG-IP Next instance deployed on VELOS or rSeries system

  • Using webUI
  • Using CLI

Using webUI

  1. Log in to the VELOS partition (for VELOS environments) or into the F5OS-A Configuration utility for rSeries environments.
  2. Go to TENANT MANAGEMENT > Tenant Details.
  3. Select the BIG-IP Next tenant from the Tenant Name setting.
  4. The Ready Time column indicates when the pods became ready. If the pods have different ready times, the important pod is the one with f5-fsm-tmm in the pod name.

Using CLI

  1. Login to the CLI of the VELOS partition or rSeries system as the admin user.
  2. Obtain the ready time of the tenant by entering the following command syntax:

    show tenants tenant <bip next tenant name> state instances | tab

BIG-IP Next instance deployed on third-party hypervisor and managed by BIG-IP Next Central Manager

For BIG-IP Next instance deployed on third-party hypervisor and managed by BIG-IP Next Central Manager, you must use the Debug utility to log in to the BIG-IP Next instance and enter the uptime command. For information on using the Debug utility to log in to the BIG-IP Next instance, refer to How to: Log in and use the Debug utility. When you have logged in to the BIG-IP Next instance using the Debug utility, enter the following command:

/uptime

The command should return an output similar to the following example:

03:25:27 up 27 min, 0 users, load average: 4.55, 3.38, 2.65

If you are unsure, F5 recommend you schedule a restart of the BIG-IP Next instance in an upcoming maintenance window for your application environment to mitigate the issue for 49.7 more days.
