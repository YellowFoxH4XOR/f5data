K000158927: BIG-IP LTM Pool Members Experience Delayed Connection Establishment During Server Reboots

Description

When a server within an Exchange server pool is rebooting, connections take excessive time to establish to other available servers in the same pool. The BIG-IP LTM does not quickly redirect traffic to healthy pool members, resulting in delayed connection establishment and performance degradation for end users accessing Exchange services.

 

Environment

  • BIG-IP LTM 
  • Virtual server: affected VS with Exchange server pool
  • Health monitor configured with specific interval and timeout values
  • Action On Service Down setting configured on the pool

 

Cause

The delayed connection establishment occurs due to suboptimal health monitor configuration combined with the Action On Service Down setting. When an Exchange server in the pool is rebooting, the health monitor's interval and timeout values are not tuned to quickly detect the unavailability. Additionally, when the Action On Service Down is not set to "Reselect," the BIG-IP does not immediately redirect new connections to available pool members. This causes the BIG-IP to attempt connections to the unavailable member or delay traffic distribution, resulting in extended connection establishment times.

 

Recommended Actions

  1. Modify the health monitor interval and timeout values to more quickly detect pool member unavailability during server reboots
  2. Change the Action On Service Down setting to "Reselect" to ensure immediate redirection of new connections to available pool members when a server becomes unavailable
  3. Test the configuration changes during a planned server reboot to verify improved connection establishment times
  4. Monitor the pool member status and connection behavior after implementing the changes
