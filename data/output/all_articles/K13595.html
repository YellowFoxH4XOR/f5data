Issue

Summary

There are many different tools and resources to aid in troubleshooting issues on the BIG-IP APM and Edge Gateway systems.

Description

This article provides an overview for each of the following utilities and resources:

  • The qkview utility
  • Web applications engine trace
  • Access policy logging agent
  • iRules
  • Documentation
  • Setting logging levels
  • Network trace
  • Log files
  • Web application packet log
  • The mpidump utility
  • The bbrdump utility

The qkview utility

The qkview utility is a BIG-IP program that an administrator can use to automatically collect configuration and diagnostic information from the BIG-IP system.

Note: For details about using the qkview utility, refer to K12878: Generating diagnostic data using the qkview< utility.

Web applications engine trace

The web applications engine trace generates a trace file that captures the HTTP requests and responses exchanged between the client and the BIG-IP APM system, and also the HTTP requests and responses exchanged between the BIG-IP APM system and the back-end web server. This information is useful when troubleshooting issues with the rewrite engine.

Note: For details about using the web applications engine trace, refer to K13384: Performing a web applications trace (11.x - 13.x).

Access policy logging agent

The access policy logging agent is a BIG-IP APM access policy action that writes session variable and custom messages to the BIG-IP APM log file. This information is useful when an access policy is not working as expected. Adding the access policy logging agent allows you to review the session data that the BIG-IP APM system is collecting.

Note: For more information about using the access policy logging agent, refer to K11253: Session variable logging within an access policy.

iRules

Normally you would not use iRules for general troubleshooting, but in certain cases you may want to use them to assist in troubleshooting.

Note: For information about iRules, refer to the DevCentral site. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

Documentation

You can access online help from the Configuration utility. In addition, the release notes for your version contains information regarding issues that are fixed in that release, outstanding issues, and new features.

Note: For more information, refer to the Configuration Guide for BIG-IP Access Policy Manager.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Setting logging levels

You can set the logging levels for the Access Policy, SSO, and Portal Access on the System > Logs > Configuration > Options page of the Configuration utility. Other logging levels are controlled with BIG-IP BigDB keys and you can set them with the tmsh utility using the following syntax:

tmsh modify /sys db <bigdb_key> value <value>

For example, to troubleshoot VMware View traffic, you can increase the logging level for VDI to debug using the following command:

tmsh modify /sys db log.vdi.level value debug

Important: Setting the log level to either informational or debug records large amounts of data. F5 recommends that you avoid setting the log level that high on a production system. To avoid increasing the load on the device, you should reserve increased logging levels for only testing and troubleshooting purposes. For example, tmsh modify /sys db log.vdi.level value notice will return log.vdi.level to its default value.

Note: For more information, refer to K13317: Configuring the level of information that syslog-ng sends to log files (11.x - 12.x).

Network trace

You can use the tcpdump utility from the command line to capture the network communications between the BIG-IP system and other devices.

Note: For more information about using tcpdump on the BIG-IP system, refer to K411: Overview of packet tracing with the tcpdump utility.

Log files

The following logs files are helpful in troubleshooting the BIG-IP APM system:

Note: For more information, refer to the Logging and Reporting chapter of the Configuration guide for BIG-IP Access Policy Manager.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

  • /var/log/apm

    The BIG-IP APM log file contains event log information for access policy-related events, such as session logon, access policy actions, etc. The amount of information logged is dependent on the logging levels set.

  • /var/log/rewrite<x>.log

    The rewrite log contains events from the rewrite profile. The <x> indicates the CPU instance that logged the rewrite info.

  • /var/log/ltm

    The LTM log contains events from the BIG-IP LTM module. The amount of information logged is dependent on the logging levels set.

Web application packet log

You can log packet information from web resource items in Web Application and Portal Access resources.

Note: To enable packet logging for a web resource item, refer to the Configuring Resources for Portal Access chapter of the Configuration Guide for BIG-IP Access Policy Manager.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

The mpidump utility

You can use the mpidump command to view product modules activity. It is especially useful in SSO and mixed module configuration debugging. To use the mpidump utility, perform the following procedure:

Note: You may not readily understand the output from the mpidump utility, but support engineers frequently request that information when you open a case.

  1. Connect to the BIG-IP device using SSH.
  2. To run the mpidump utility, type the following command:

    mpidump -a -v -w /var/log/mtrace1

    Note: This command saves the output to the mtrace1 file in the /var/log directory.

  3. Optional: You can start a second SSH session to capture Single-Sign On sessions by typing the following command:

    mpidump -c "mem://websso" -v >/var/log/mtrace2

  4. Log in to the BIG-IP APM system from either a browser or your Virtual Private Network (VPN) client.
  5. Connect to the application or resource that you want to troubleshoot.
  6. Terminate the mpidump utility by pressing Ctrl + C in the SSH connection.
  7. For closer examination, using a utility such as WinSCP, you can copy the file, which the mpidump utility generated, from the BIG-IP system.

The bbrdump utility
You can use the bbrdump command to view finer grained events than what BIG-IP APM records in the Access Policy debug logs. To use the bbrdump utility, perform the following procedure:

  1. Connect to the BIG-IP device using SSH.
  2. To run the bbrdump utility, type the following command:

    bbrdump -a <client_ip> | tee /var/tmp/bbrdump.txt

    Note: This command saves the output to the bbrdump.txt file in the /var/tmp directory.
     

  3. Connect to the application or resource that you want to troubleshoot.
  4. Terminate the bbrdump utility by pressing Ctrl + C in the SSH connection.
  5. For closer examination, using a utility such as WinSCP, you can copy the file, which the bbrdump utility generated, from the BIG-IP system.
