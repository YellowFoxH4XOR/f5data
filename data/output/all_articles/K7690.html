Topic

When using the Configuration utility to check or change the failover status of a BIG-IP high availability pair, refreshing a browser session may cause the BIG-IP system to unexpectedly fail over. This issue can occur if you use the floating self IP address to administer the BIG-IP system. If you initiate a failover by clicking the Force to Standby button in the Configuration utility, and then immediately refresh the browser session, the BIG-IP system will unexpectedly failover.

Note: This issue will only occur if you use the floating self IP address to administer the BIG-IP system. To avoid this issue, F5 recommends using the management port to administer the BIG-IP system.

For example, if your system is configured with a BIG-IP high availability pair in which bigip1 is the active unit and bigip2 is the standby unit and you want to initiate a failover from bigip1 to bigip2, you can connect to the Configuration utility using the floating self IP address. Then, you click the Force to Standby button in the Configuration utility. This action forces the bigip1 system to failover to the standby unit, bigip2. In this case, if you immediately refresh the browser session, the browser will resend the HTTP POST request to the newly active unit, causing another failover to occur.

The BIG-IP Configuration utility uses HTML forms to gather and submit user input to the system. Refreshing the browser session causes the form to be resubmitted to the active unit, resulting in the failover.

Note: If you need to verify the updated failover status of the unit, you can click the Current Redundancy State icon next to the F5 icon in the upper-left corner of the screen.
