Issue

If you are running a BIG-IP system on a 1500 or 3400 platform that has 1 GB of memory installed, you cannot simultaneously convert the disk formatting scheme to logical volume management (LVM) when upgrading the BIG-IP system to version 10.2.x.

If you attempt to install version 10.2.x by running the image2disk command with the --format=volumes option on a 1 GB 1500 or 3400 platform that was previously formatted using the partition scheme, the installation operation may halt with an error message that appears similar to the following example:

Terminal error: System memory of 1 GiB is insufficient for 'format=volumes' with this product image; 1.5 GiB is required.

Note: If this process results in an installation failure that does not generate the error message above, you should still recover from the failure by using one of the procedures below.

F5 Product Development is tracking this issue as ID 390104.

You can remedy the situation in one of the following two ways:

  • Performing an interim upgrade using the volumes disk formatting scheme
  • Performing a clean installation using the volumes disk formatting scheme

Performing an interim upgrade using the volumes disk formatting scheme

Prior to upgrading to BIG-IP version 10.2.x, perform an interim upgrade to BIG-IP version 10.0.1, using the volumes disk formatting scheme:

  1. Follow the instructions in the BIG-IP version 10.0.1 release notes to perform the interim upgrade to version 10.0.1.
  2. Once you have completed the upgrade to version 10.0.1, follow the instructions in the BIG-IP version 10.2.X release notes to upgrade the system to version 10.2.x.

Performing a clean installation using the volumes disk formatting scheme

Instead of upgrading from your current version, you can perform a clean installation of BIG-IP version 10.2.x using the volumes disk formatting scheme, then restore the existing configuration. To do so, perform the following procedure:

  1. Document the registration keys, host name, and network configuration of the system to be upgraded in a text file or on paper.

    Note: You can locate this information in the Configuration utility by browsing to the System > Platform and System > License tabs.

  2. Back up your data and copy the UCS archive to another system using the procedure detailed in K11318: Backing up and restoring BIG-IP configuration files (10.x). Alternatively, you can export a Single Configuration File (SCF) as detailed in K8435: Overview of the Single Configuration File (SCF).
  3. Copy the UCS or SCF file to another system using the procedures detailed in K175: Transferring files to or from an F5 system.
  4. Perform a clean installation of BIG-IP version 10.2.x as detailed in K10819: Performing a clean installation of BIG-IP version 10.x.
  5. When the installation is complete, connect to the serial console.
  6. Log in to the BIG-IP command line using the username root and the password default.
  7. Run the Setup utility by typing the following command:

    config

  8. Enter your management address and network information.
  9. Using a web browser, access the Configuration utility by browsing to the Management address over HTTPS. For example, if you configured 192.168.1.10 as the management address, browse to https://192.168.1.1.
  10. Follow the prompts to license and configure the BIG-IP system.
  11. Log out of the Configuration utility.
  12. On the serial console, restart the system by typing the following command:

    bigstart restart

  13. Once the system prompt includes the string Active, type the following command to display the active volume:

    switchboot -l

  14. Switch to an inactive volume using the switchboot -b command. For example, if the switchboot command indicates that the active volume is HD1.1, switch to the HD1.2 volume by typing the following command:

    switchboot -b HD1.2

  15. Reboot the system by typing the following command:

    reboot

  16. Once the system reboots, repeat the above process to configure the other volume.
  17. After both volumes are configured, restore your configuration by following the appropriate procedure in K11318: Backing up and restoring BIG-IP configuration files (v10.x) or K8435: Overview of the Single Configuration File (SCF).
