K806: Reasons why the virtual server statistics reported by the BIG-IP and 3-DNS Configuration utilities and bigtop may differ

Topic

The 3-DNS Controller uses information that is collected by the big3d agent (running on remote F5 devices) to display statistics about those devices and the objects configured on them. The big3d agent collects this information by querying the kernel of the controller on which it is running.

On the BIG-IP system, the information passed back to the agent includes the number of current connections to virtual servers. The number of connections provided by the kernel is the number of active connections at that time of the query. This information is not only used by the 3-DNS Controller to make load balancing decisions, but can also be displayed as a statistic on the specified BIG-IP Controller.

The BIG-IP Virtual Server Statistics screen displays the current, maximum (highest number of concurrent connections since the last reboot), and total connections (total number of connections since the last reboot). The current connections displayed may differ from the 3-DNS Controller's Virtual Server Statistics screen because it is showing the number of connections reported from the kernel at the exact moment the screen was loaded or refreshed. You can also use the bigtop utility command on the BIG-IP system to display both total and current connections, in addition to individual virtual server statistics.

If you compare the number of current virtual server connections between what is shown in the Virtual Server Statistics screen on the 3-DNS Controller and that of the BIG-IP system, to the output of the BIG-IP system's bigtop command, they can be very different. The difference between the current connections in bigtop and the current connections in the Virtual Server Statistics screens is that, by default, the bigtop command displays the total number of new connections over the last four seconds.

Any discrepancies between the number of connections, current or total displayed through the various methods are usually due to the fact that the screens are not showing the information for the exact same moment in time. This can be very noticeable if there is a lot of activity on the virtual servers. This is especially true for HTTP, which typically involves a high number of short-lived, small connections. If you were to halt a given virtual server and wait for connections to it to complete, the total number of connections shown on all three methods should be exactly the same.
