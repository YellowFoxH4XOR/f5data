K000091237: Nginx Ingress Controller ConfigMap apply failure causes all Virtualservers to show as "Invalid" in Kubernetes

Type
Support Solution
Published
2022-10-20
Updated
2022-10-20
Source
https://my.f5.com/manage/s/article/K000091237

Description

If you apply a new ConfigMap to your ingress controller that fails due to bad Nginx logic(missing variable, invalid directive, etc), nginx will fail to reload and report to Kubernetes that all your virtualserver CRDs are "Invalid". During this state, your virtualservers will likely still process traffic normally because Nginx will continue to use the previous configuration. However, when you perform a "kubectl get vs" in Kubernetes, the virtualservers will show an invalid state because that's the last update Kubernetes received from the Ingress Controller. If you are using an external monitoring tool, you may receive alerts that your virtualservers are down, when in reality, they may still be processing traffic just fine.
 

Environment

  • Nginx Ingress Controller
  • Virtualserver CRD
  • Kubernetes

Cause

Only certain updates will trigger Nginx Ingress Controller to report to Kubernetes the current state of the virtualservers. So sometimes the nginx.conf files will reload successfully, but will not update Kubernetes.

Update triggers:

  • When a ConfigMap is applied (successfully or unsuccessfully), this will trigger an update to Kubernetes about the state of the virtual servers.
  • When a new virtualserver is applied, this will trigger an update about that specific virtualserver
  • When a meaningful change(adding or removing Nginx specific configs) to an existing virtual server is applied, this will trigger an update.

 

Below is an example log message that appears in the Ingress Controller logs when Nginx Ingress Controller sends an update to Kubernetes about a virtual server state:

I0124 21:17:47.068047    1 event.go:285] Event(v1.ObjectReference{Kind:"VirtualServer", Namespace:"default", Name:"webapp", UID:"90899c01-1f29-440d-8cd9-fc0cbd9eb7c7", APIVersion:"k8s.nginx.org/v1", ResourceVersion:"741467", FieldPath:""}): type: 'Normal' reason: 'AddedOrUpdated' Configuration for default/webapp was added or updated 

 

 Recommended Actions

If you make an error while trying to apply new configurations in the Nginx ConfigMap, and it fails, it is recommended to resolve the issue within the ConfigMap and re-apply it so Kubernetes can be made aware of the current state of the virtual servers for the Ingress Controller.
