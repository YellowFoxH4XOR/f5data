Topic

You should consider using this procedure under the following conditions:

  • You have an IKEv1 security association (SA) you want to display or delete.
  • You have an IKEv2 SA you want to display or delete.

Description

You can display and, in most cases, delete SAs using TMOS Shell (tmsh) commands. However, there are some differences between Internet Key Exchange (IKE)v1 and IKEv2 tunnels. IKEv1 connection setup and maintenance is handled by the racoon daemon; IKEv2 connections are handled entirely by the Traffic Management Microkernel (TMM).

Note: You cannot delete SAs using the Configuration utility.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • Your system has IPsec tunnels configured.

Procedures

The method for displaying and deleting IKEv1 and IKEv2 SAs differs between IKE versions. Before deleting an SAs, you must first display it.

  • Displaying IKEv1 IKE (Phase 1) SAs
  • Displaying IKEv1 IPsec (Phase 2) SAs
  • Displaying IKEv2 IKE SAs
  • Displaying IKEv2 IPsec (Child SA) SAs
  • Displaying IKEv2 IPsec (Child SA) SAs with optional filters
  • Deleting IKEv1 SAs
  • Deleting IKEv2 SAs

Using all-properties in the following commands gives a detailed view on the state of the SA, including lifetime and byte counters.

Displaying IKEv1 IKE (Phase 1) SAs

Impact of procedure: This procedure should not have a negative impact on your system.

To show an IKEv1 Internet Security Association and Key Management Protocol (ISAKMP) SA, use the following racoonctl command syntax, which connects to the racoon daemon to determine the SA state:

racoonctl [-r <route domain id>] -ll show-sa isakmp

Note: [-r <route domain id>] specifies a route domain, if applicable to the configuration.

For example:

# racoonctl -ll show-sa isakmp

Output appears similar to the following:

Source            Destination      Cookies                            ST S  V  E  Created              Phase2
172.16.5.1.500    172.16.6.1.500   2015ca5d10f2383c:68b3fedd758154e2  9  I  10 M  2017-03-30 05:08:56  1

Note: The source address appears as 127.0.0.1:500 when the BIG-IP system is a responder; this is expected.

Displaying IKEv1 IPsec (Phase 2) SAs

Impact of procedure: This procedure should not have a negative impact on your system.

Use the following command syntax to display IKEv1 IPsec (Phase 2) SAs:

tmsh show net ipsec ipsec-sa <optional filters> all-properties

For information about applying optional filters, refer to the Displaying IKEv2 IPsec (Child SA) SAs with optional filters procedure in this article.

Displaying IKEv2 IKE SAs

Impact of procedure: This procedure should not have a negative impact on your system.

You can filter IKEv2 IPsec SAs using various parameters, including destination address, source address, route-domain, SPI, and traffic-selector, by using the following command syntax:

tmsh show net ipsec ike-sa <optional filters> all-properties

For information about applying optional filters, refer to the Displaying IKEv2 IPsec (Child SA) SAs with optional filters procedure in this article.

Displaying IKEv2 IPsec (Child SA) SAs

Impact of procedure: This procedure should not have a negative impact on your system.

You can filter IKEv2 IPsec SAs using various parameters, including destination address, source address, route-domain, SPI, and traffic-selector, by using the following command syntax:

tmsh show net ipsec ipsec-sa <optional filters> all-properties

For information about applying optional filters, refer to the Displaying IKEv2 IPsec (Child SA) SAs with optional filters procedure in this article.

Displaying IKEv2 IPsec (Child SA) SAs with optional filters

Impact of procedure: This procedure should not have a negative impact on your system.

You can use parameters to filter for SAs related to a specific tunnel. For example, using the traffic-selector parameter provides a way of viewing the health of a specific tunnel.

For example:

# tmsh show net ipsec ipsec-sa traffic-selector selector-5-6-1-0 all-properties

Deleting IKEv1 SAs

Impact of procedure: Deleting an IKEv1 ISAKMP or IPsec SA will cause any established network connections relying on that tunnel to end. Assuming that the tunnel is configured correctly, the tunnel should quickly re-establish and the network connectivity should resume without further intervention. Using the racoonctl flush-sa command may cause the status of the tunnel to become out-of-sync among TMM, tmipsecd, and racoon, so you should only use it with instruction from F5 Support.

You can display and delete IPsec SAs, called "phase 2" in the same way as you can IKEv2 SAs; however, the BIG-IP IKEv1 implementation provides no safe method to manually delete ISAKMP SAs.

A racoonctl command is available to delete an SA, but you should only use it when instructed by F5 Support. The command syntax is as follows:

racoonctl [-r <route domain id>] flush-sa isakmp
racoonctl [-r <route domain id>] flush-sa ipsec

Note: [-r <route domain id>] specifies a route domain, if applicable to the configuration.

Important: Use of this command can confuse the state of IPsec tunnels between TMM and racoon. You should never use the command to delete IPsec SAs, but, if absolutely necessary, you can use it to delete ISAKMP SAs.

As a workaround, to delete IKEv1 ISAKMP SAs in BIG-IP 12.1.0 or later, if you reconfigure some element of the IKE-peer configuration (for example, the description), this causes the related phase 1 and phase 2 SAs to be deleted only for that tunnel. In versions prior to BIG-IP 12.1.0, this act destroys all established IKEv1 tunnels and they re-establish as packets matching the traffic-selectors arrive at the BIG-IP system.

Deleting IKEv2 SAs

Impact of procedure: Deleting an IKEv1 ISAKMP or IPsec SA will cause any established network connections relying on that tunnel to end. Assuming that the tunnel is configured correctly, the tunnel should quickly re-establish and the network connectivity should resume without further intervention.

You can delete IKEv2 SAs using the following commands:

tmsh delete net ipsec ike-sa <optional filters>
tmsh delete net ipsec ipsec-sa <optional filters>
