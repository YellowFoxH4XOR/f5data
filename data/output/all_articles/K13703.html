Topic

The big3d data collection agent runs on BIG-IP and Enterprise Manager systems and uses the iQuery protocol to collect performance information from remote F5 devices. For metrics collection to work properly, you must maintain big3d version compatibility on F5 devices, and be aware of big3d installation behavior as outlined below.

Description

big3d version management

To facilitate proper iQuery communication in your environment, you should be aware of the following big3d version management information:

  • F5 recommends that all devices communicating over iQuery run the same big3d version
    • When installing big3d on devices in the iQuery mesh, install the big3d agent from the BIG-IP DNS (formerly BIG-IP GTM) or Enterprise Management system that is running the latest software version, to the other devices in the iQuery mesh. For example, if the devices in the iQuery mesh are running different BIG-IP software versions, install the big3d agent from the device running the newest BIG-IP version to the other devices. This ensures that a device in the mesh does not run a big3d version that is older than its installed software version.

      Note: big3d is designed to be backward-compatible; therefore, you can upgrade big3d without having to upgrade the other monitored devices in the iQuery mesh TMOS version to match the TMOS version on BIG-IP GTM. You can check the big3d version by entering the big3d -v command. For additional information on updating big3d see K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities (11.x - 17.x) .

  • BIG-IP DNS synchronization group communication
    • Sync group members must run the same big3d version to avoid unexpected behavior such as big3d timeouts.
  • DNS/GTM/BIG-IP communication
    • Monitored BIG-IP systems must run the same or newer big3d version as the DNS / GTM devices that are monitoring them.
  • Enterprise Manager/BIG-IP communication
    • Managed BIG-IP systems must run the same or newer big3d version as the Enterprise Manager devices that are collecting data from them.

Note: The big3d (iQuery) SSL cipher suite is currently hard-coded in the BIG-IP system and cannot be modified administratively.

big3d installation behavior

The big3d agent initiates and runs as follows on BIG-IP and Enterprise Manager devices:

  • The default big3d agent is located in the /usr/sbin directory.
  • At start up, the BIG-IP system verifies that the /shared/bin/big3d executable file exists.
    • If the /shared/bin/big3d executable file exists and has an older modification time than the /usr/sbin/big3d executable file, the system copies /usr/sbin/big3d to the /shared/bin directory and runs /shared/bin/big3d.
    • If the /shared/bin/big3d executable file does not exist, the system copies the /usr/sbin/big3d executable file to the /shared/bin directory and runs /shared/bin/big3d.

The expected result is the BIG-IP system runs the newer version of the big3d agent from the /shared/bin directory. However, under certain conditions, the big3d agent in the /shared/bin directory may be a different version than the instance in the /usr/sbin directory. For example, this may occur when an Enterprise Manager device pushes an older version of the big3d agent to the affected system, or when the big3d agent in /shared/bin directory is not replaced by the copy from a newer software version branch because it has an older time stamp. For the recommended workaround procedures, refer to the following examples:

Example 1: Older version of big3d agent push from Enterprise Manager

When an Enterprise Manager device pushes an older version of the big3d agent to the system. To verify that the big3d agent in the /shared/bin and /usr/sbin directories is the same, perform the following procedure:

Impact of procedure: This procedure involves stopping the big3d daemon service, which will interrupt the iQuery connections and the synchronization activities between this system and the rest of the devices in the same GTM synchronization group. F5 recommends to perform this during a scheduled maintenance window.

  1. Log in to the command line.
  2. To verify the big3d version in the /shared/bin directory, type the following command:

    /shared/bin/big3d -v

  3. To verify the big3d version in the /usr/sbin directory, type the following command:

    /usr/sbin/big3d -v

  4. If the /shared/bin/big3d agent is older, copy the newer big3d agent to the /shared/bin/ directory.

    For example, you would type the following command:

    tmsh stop /sys service big3d && cp -a $(which big3d) /shared/bin/ && tmsh start /sys service big3d

Example 2: Newer software branch where the big3d agent has an older time stamp

When you upgraded the BIG-IP system to a newer software branch, for example from 10.2.4 HF12 to 11.5.3, the system will not overwrite the /shared/bin/big3d file (from 10.2.4 HF12) by the /usr/sbin/big3d file (from 11.5.3) because the big3d agent from 11.5.3 has an older time stamp than the copy from version 10.2.4 HF12.

To list the big3d agent files with time stamp on the affected BIG-IP system, type the following command:

ls -al /shared/bin/big3d /usr/sbin/big3d

Output may appear similar to the following example:

-rwxr-xr-x 1 root root 2960517 Jul 27 22:57 /shared/bin/big3d
-rwxr-xr-x 1 root root 5149559 Apr 22 23:35 /usr/sbin/big3d

If the BIG-IP system runs 11.5.3, and you want to use the copy of big3d from 11.5.3, you can replace the /shared/bin/big3d file with the copy from 11.5.3 by performing the following procedure:

Impact of procedure: This procedure involves stopping the big3d daemon service, which will interrupt the iQuery connections and the synchronization activities between this system and the rest of the devices in the same GTM synchronization group. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the BIG-IP command line.

    Note: In this example, on the software slot running 11.5.3.

  2. Stop the big3d daemon by typing the following command:

    tmsh stop /sys service big3d

  3. Remove the copy of big3d in /shared/bin directory by typing the following command:

    rm /shared/bin/big3d

    Note: The BIG-IP system will automatically copy the 11.5.3 version of big3d from /usr/sbin/big3d to /shared/bin directory.

  4. Start the big3d daemon, type the following command:

    tmsh start /sys service big3d

Important: When the BIG-IP system boots into the 10.2.4 software slot, the system will replace the big3d file in the /shared/bin directory with the 10.2.4 HF12 copy. If this behavior occurs, you will have to perform this procedure again.

Recommendations

Installing a new big3d agent to managed/monitored devices when required

If you experience iQuery communication issues, you should verify whether the remote BIG-IP systems are running the same or newer big3d version as the monitoring device (DNS / GTM or Enterprise Manager). For example, when you upgrade a BIG-IP DNS / GTM system to a new software version, a new big3d version is installed on the local system. To ensure big3d compatibility with remote BIG-IP systems, you should run the big3d_install script on BIG-IP DNS / GTM for target BIG-IP systems that are running the same or an older version of BIG-IP software. For information about running the big3d_install script, refer to the following articles:

  • K13312: Overview of the BIG-IP GTM big3d_install, bigip_add, and gtm_add utilities (11.x - 17.x)
  • K8195: Overview of the BIG-IP GTM big3d_install, bigip_add, and gtm_add utilities (9.x - 10.x)

Note: After installing a new big3d version, the Local big3d version reported in the output of the tmsh show /gtm iquery command may not be updated until you restart gtmd using the bigstart restart gtmd command. For example, after installing big3d version 14.1.3.1.0.0.8, the following output still shows the Local big3d version as 14.1.2.6.0.0.2:
