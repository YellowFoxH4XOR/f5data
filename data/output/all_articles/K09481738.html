Known Issue

The iRules command HSL::send does not support the string type of handle.

This issue occurs when the following condition is met:

  • You pass a string type of handle to HSL::send.

Following is an example of an iRule where the handle being passed to HSL::send is a string type:

when HTTP_REQUEST {
    # The following concatenation results in string type.
    set token "[HSL::open -proto UDP -pool /Common/logger_pool]!metadata"
    # Extract handle from HSL "token".
    set handle [lindex [split $token !] 0]
    # handle is str_ObjType
    HSL::send $handle "this is not logged"
    HTTP::respond 200 content "OK"
}

Impact

The HSL::send command does not perform the intended action. The system does not log any information, and there is no indication of any failure.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The HSL::send command performs no action when you supply it with a logging handle that is a Tcl string.

Workaround

To work around this issue, you can use the handle directly provided by the HSL::open command. To do so, use the example provided for HSL::send on F5 Cloud Docs, as follows:

when CLIENT_ACCEPTED {
   set hsl [HSL::open -proto UDP -pool syslog_server_pool]
}
when HTTP_REQUEST {
   # Log HTTP request as local7.info; see RFC 3164 Section 4.1.1 - "PRI Part" for more info
   HSL::send $hsl "<190> [IP::local_addr] [HTTP::uri]\n"
}
