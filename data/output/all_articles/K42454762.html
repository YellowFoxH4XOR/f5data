Description

You see high CPU usage at csyncd after installing the Telemetry Streaming iApp. Sometimes, GUI become slow.

Environment

  • BIG-IP multiblade VIPRION chassis
  • F5 Telemetry Streaming iApp
  • This issue may occur either when configuring F5 Telemetry Streaming or in other circumstances
  • Large numbers of files are contained in one or more of the directories being synced between blades

Cause

There are thousands of files this iApp creates inside of the /var/config/rest/iapps/f5-telemetry directory that csyncd watches every second for changes, but these files will never change.
F5 is tracking this known issue with ID 1002969 csynd uses a lot of CPU if there are thousands of files in a directory that it's monitoring.

Recommended Actions

To workaround this known issue, ID 1002969, you can modify the csyncd configuration to ignore the files in that directory with these steps:

  1.  Log in to the BIG-IP command line

  2.  Stop the csync daemon with this bash command:
      clsh bigstart stop csyncd

  3. Stop any running rsync processes with this bash command:
      /etc/init.d/rsync stop

  4. Change directories to the /etc directory with this bash command:
      cd /etc

  5. Backup the original /etc/csyncd.conf file with this bash command:
      cp csyncd.conf csyncd.conf.`date +"%Y%m%d"`

  6. Using a text editor, open the csyncd.conf file.

  7. Locate the following stanza:
    monitor dir /var/config/rest/iapps {
            recurse yes
            lnksync yes
    }

  8. Add "ignore /var/config/rest/iapps/f5-telemetry" to the bottom of the stanza so it looks like this:
    monitor dir /var/config/rest/iapps {
            recurse yes
            lnksync yes
            ignore f5-telemetry
    }

  9. Start the rsync process on all blades with this bash command:
      clsh /etc/init.d/rsync start

  10. Start the rsync process on all blades with this bash command:
      clsh bigstart start csyncd
