Known Issue

Virtual servers using the Source Address Affinity persistence profile may cause a memory leak in TMM.

This issue occurs when all of the following conditions are met:

  • The BIG-IP is running version 10.2.2 HF2 or version 11.0.0.
  • A virtual server has a Source Address Affinity persistence profile assigned.
  • The persistence profile has the Map Proxies option enabled.

Impact

TMM may crash and fail to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H951917 on the Diagnostics > Identified > High screen.
  • The amount of allocated memory for the net_ip object continually increases and exceeds the max_allocated memory value.

    The following example shows the tmctl command used to display the memory allocation information, and the resulting output:

    tmctl -i -f /var/tmstat/blade/tmm0 -w 200 memory_usage_stat | grep net_ip

    name allocated max_allocated held size tot_allocs cur_allocs
    ----------- --------- ------------- ----- ----- ---------- ----------
    net_ip 720 700 17 40 51 17

    In the previous output, the allocated value has exceeded the max_allocated value.

  • TMM may crash and restart, writing error messages that appear similar to the following example in the /var/log/tmm file:

    notice ** SIGFPE **
    notice fault addr: 0x525f9c
    notice fault code: 0x1
    notice fault time: Tue Aug 30 15:26:02 MDT 2011
    notice version: default padc TMM Version 10.2.2.911.0
    notice ticks since last clock update: 0
    notice ticks since start of poll: 0
    notice EAX=0 EBX=0 ECX=0x1a8ea68 EDX=0
    notice ESI=0x960 EDI=0xb5095a6 EBP=0x21fe118, ESP=0x21fe100
    notice EIP=0x525f9

Workaround

To work around this issue, you can disable the Map Proxies option. To do so, perform the following procedure:

Impact of workaround: Disabling the Map Proxies option prevents the BIG-IP system from persisting the connection prior to applying the persist mask. This can cause users coming from a megaproxy such as AOL fall within a specific netmask range to persist to different nodes instead of the node the system picked for the first AOL client connection.

  1. Log in to the Configuration utility.
  2. Navigate to the Local Traffic -> Profiles -> Persistence menu.
  3. Select the appropriate Source Address Affinity persistence profile.
  4. Click the Custom check box.
  5. Clear the Map Proxies option.
  6. Click Update.
