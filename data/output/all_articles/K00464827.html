Description

The following command examples show you how to use REST commands to change pool member or node status.

To force offline an existing node or a pool member, use the following command syntax
  • <PATCH> /mgmt/tm/ltm/node/~<partition>~<node name>  -d '{"session":"user-disabled","state":"user-down"}'
  • <PATCH> /mgmt/tm/ltm/pool/<pool name>/members/~<partition>~<node name>:<port>/ -d '{"session":"user-disabled","state":"user-down"}'
For example:
  • To force offline the test_node node, enter the following command:
    curl -sku user:password -H "Content-Type: application/json" -X PATCH https://localhost/mgmt/tm/ltm/node/~Common~test_node -d '{"session":"user-disabled","state":"user-down"}' | jq .
  • To force offline the test_node:80 pool member in the test_pool, enter the following command:
    curl -sku user:password -H "Content-Type: application/json" -X PATCH https://localhost/mgmt/tm/ltm/pool/test_pool/members/~Common~test_node:80 -d '{"session":"user-disabled","state":"user-down"}' | jq .
To disable an existing node or a pool member, use the following command syntax
  • <PATCH> /mgmt/tm/ltm/node/~<partition>~<node name>  -d '{"session":"user-disabled"}'
  • <PATCH> /mgmt/tm/ltm/pool/<pool name>/members/~<partition>~<node name>:<port>/ -d '{"session":"user-disabled"}'
For example:
  • To disable the test_node node, enter the following command:
    curl -sku user:password -H "Content-Type: application/json" -X PATCH https://localhost/mgmt/tm/ltm/node/~Common~test_node -d '{"session":"user-disabled"}' | jq .
  • To disable the test_node:80 pool member in the test_pool, enter the following command:
    curl -sku user:password -H "Content-Type: application/json" -X PATCH https://localhost/mgmt/tm/ltm/pool/test_pool/members/~Common~test_node:80 -d '{"session":"user-disabled"}' | jq .
To enable an existing node or a pool member, use the following command syntax
  • <PATCH> /mgmt/tm/ltm/node/~<partition>~<node name>  -d '{"session":"user-enabled","state":"user-up"}'
  • <PATCH> /mgmt/tm/ltm/pool/<pool name>/members/~<partition>~<node name>:<port>/ -d '{"session":"user-enabled","state":"user-up"}'
For example:
  • To enable the test_node node, enter the following command:
    curl -sku user:password -H "Content-Type: application/json" -X PATCH https://localhost/mgmt/tm/ltm/node/~Common~test_node -d '{"session":"user-enabled","state":"user-up"}' | jq .
  • To enable the test_node:80 pool member in the test_pool, enter the following command:
    curl -sku user:password -H "Content-Type: application/json" -X PATCH https://localhost/mgmt/tm/ltm/pool/test_pool/members/~Common~test_node:80 -d '{"session":"user-enabled","state":"user-up"}' | jq .

Environment

iControl REST API

Cause

You need to use  "session" and/or "state" to change the node and pool member status as desired.

session:
When session is disabled, clients that have already established sessions with the node or the pool member may create new connections, but a client that has not already established a session may not create a new one (or make a connection which would create a new session).
  
state:
user-down forces the node or pool member offline, overriding monitors. Use user-down to indicate that the node or pool member may not handle any new connections.

Recommended Actions

Use '{"session":"user-enabled","state":"user-up"}' , to indicate that the node or pool member may accept new connections.
