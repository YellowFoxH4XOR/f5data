Description

After licensing the Big-IP, you may encounter a similar error in the command line when issuing the 'tmsh load sys config' command:

01070712:3: Failed: name (/Common/f5_api_com.crt) Cache path
(/config/filestore/files_d/Common_d/certificate_d/:Common:f5_api_com.crt_116461_1) does not exist
and there is no copy in trash-bin to restore from.
Unexpected Error: Loading configuration process failed.

Environment

  • Big-IP
  • Recently licensed/relicensed

 

Cause

  • Bug ID 1070393

 

Recommended Actions

1. take a UCS backup of the unit, and save remote location.


2. run the following 2 commands to view the existing installed certificate:

tmsh list sys crypto cert f5_api_com.crt
sed -n '/sys file ssl-cert \/Common\/f5_api_com.crt {/,/^}/p' /config/bigip.conf
 
3. delete the existing cert and key by running the following 3 commands:
tmsh delete sys crypto cert f5_api_com.crt
tmsh delete sys crypto key f5_api_com.key
tmsh save sys conf

 

4. now check that the certificate is gone by running following 2 commands:
tmsh list sys crypto cert f5_api_com.crt | wc -l
sed -n '/sys file ssl-cert \/Common\/f5_api_com.crt {/,/^}/p' /config/bigip.conf | wc -l
NOTE: Both commands output should be zero '0'

 

5. re-activate license and save by running the following 2 commands
tmsh install sys license
tmsh save sys conf

7. run the following 2 commands to view the renewed certificate:
tmsh list sys crypto cert f5_api_com.crt
sed -n '/sys file ssl-cert \/Common\/f5_api_com.crt {/,/^}/p' /config/bigip.conf
