Description

BIG-IP ASM/Advanced WAF brute force protection detects failed login attempts and logs violations, but does not enforce configured mitigation actions such as CAPTCHA challenges or IP blocking. The brute force detection violations appear in the event logs, but the enforcement actions are not triggered against the source IP addresses generating the failed authentication attempts.

Symptoms:

  • Brute force violations are logged in ASM event logs
  • Failed login attempts are detected and counted
  • CAPTCHA challenges or blocking page are not presented to users
  • IP blocking does not occur despite exceeding configured thresholds
  • Login requests continue to be processed without mitigation
  • Event logs show "Request Status: Unblocked" but "Enforcement Action: None"

Environment

  • BIG-IP Advanced WAF (all versions)
  • Security policy with brute force protection enabled
  • Brute force protection configured
  • Login detection configured on security policy
  • Source IP addresses belong to trusted IP network range

Cause

The brute force protection mitigation actions are not triggered because the source IP addresses generating the failed login attempts is part of the trusted IPs configured in the security policy. By design, BIG-IP ASM/Advanced WAF does not apply brute force enforcement actions (CAPTCHA challenges, blocking, rate limiting) to IP addresses that match the trusted IP network list, even when failed login attempts are detected and logged as violations.

Recommended Actions

Review the Trusted IP Addresses configuration and remove the IP addresses where the full functionality of the feature is desired.
