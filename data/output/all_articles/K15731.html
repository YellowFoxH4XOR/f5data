K15731: The TMM process may produce a core file and restart when a local traffic policy forwards traffic to another virtual server

Known Issue

The TMM process may produce a core file and restart. This issue occurs when all of the following conditions are met:

  • A virtual server is associated with a local traffic policy that is configured to forward to a destination virtual server.

    For example:

    ltm policy /Common/myLTPforwardpolicy {
    controls { forwarding }
    requires { http }
    rules {
    ...
    fwdtest_rule {
    actions {
    ...
    1 {
    forward
    select
    virtual /Common/mydestVS
    }
    }
    }
    ...
    }
    ...
    }

  • The destination virtual server is subsequently deleted from the BIG-IP system or has its configuration changed (for example, adding or removing a profile).
  • The forward to destination virtual server action is then triggered on the affected local traffic policy.

Impact

The BIG-IP system may temporarily fail to process traffic and fail over if configured as part of a high-availability system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H485144 on the Diagnostics > Identified > High screen.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system fails over to the standby system.
  • If the destination virtual server is deleted from the system, the BIG-IP system logs an error message similar to the following example to the /var/log/ltm file during the TMM startup process:

    016e0000:3: Could not bind action 'forward select policy=/Common/myLTPforwardpolicy rule=fwdtest_rule action-id=0 virtual=/Common/mydestVS', reason ERR_NOT_SUPPORTED
