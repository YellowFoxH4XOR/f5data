Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP APM system is configured with a network access profile.
  • You want to implement single sign-on (SSO) for network resources accessed through the network access session.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP APM system is configured with a functioning network access profile.
  • You have administrative access to the BIG-IP APM system.

Description

The BIG-IP APM network access feature provides secure access to applications and data using a web browser or BIG-IP Edge client. Many organizations allow access to multiple resources using the same credentials. You can configure your network access to support single sign-on (SSO) through a layered virtual server. This configuration allows users full network access to multiple resources without requiring the user to enter their credential multiple times.

Procedures

To configure your network access to support SSO, perform the following four procedures:

  • Creating an access policy profile
  • Creating a destination resource pool
  • Creating an HTTP virtual server for the network access
  • Disabling the virtual server IP address

Creating an access policy profile

You need to configure an access policy to implement SSO for the destination resource.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Access Profiles.

    Note: For BIG-IP 12.x and earlier, go to Access Policy > Access Profiles.

  3. Select Create.
  4. Enter a name for your SSO access policy.
  5. For Profile Type, select LTM-APM.
  6. Under Language Settings, select the appropriate languages.
  7. Leave all other settings at their default values.
  8. Ensure that SSO Configuration specifies the same SSO profile as the configured Network Access profile.
  9. Select Finished.

    The new access policy is now added to the Access Profile list.

  10. From the Access Profiles list, select the Edit link for the access profile you just created.
  11. Ensure that the access policy includes only the Start > Allow flow with no other options.
  12. Select Save.
  13. Select Close.

Creating a destination resource pool

After you have created and configured your access policy profile to manage your network access, you must create a virtual server referencing a pool that contains the destination resource to which you want to apply SSO.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools.
  3. Select Create.
  4. For Name, enter the name of the pool.
  5. For New Members, for Node Name, enter a name for the destination resource.
  6. For Address, enter the IP address of the destination resource.
  7. For Service Port, enter the service port of the destination resource.
  8. Select Add.
  9. Select Finished.

Creating an HTTP virtual server for the network access

After you have created and configured your access policy profile to manage your network access, you must create a virtual server with which the network access associates your access policy.

Impact of procedure: F5 recommends that you create the virtual server during a scheduled maintenance window, due to a possible IP address conflict with the destination resource while the system is creating the virtual server.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select Create.
  4. Specify the Name, Destination, and Service port.

    Note: The destination IP address and service port are the same as the intended destination resource.

  5. For Configuration, select Advanced.
  6. Specify the HTTP profile.
  7. If required, specify the SSL (Client) and/or the SSL Profile (Server).
  8. For SNAT pool, change the default setting from None to Auto Map.
  9. Clear the Address Translation check box.
  10. Clear the Port Translation check box.
  11. Set VLANs and Tunnels to the connectivity profile of the network access object to which connections are being made.
  12. Under Access Profile, select the newly created access profile.
  13. Select Finished.

Disabling the virtual server IP address

After you have created and configured the virtual server, it is important to disable ARP for the IP address of the virtual server, since it shares the same IP address with the destination resource.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Address List.
  3. For Name, select the IP address of the newly created virtual server.
  4. To disable ARP for the virtual server IP address, clear the ARP Enabled check box.
  5. Select Update.
