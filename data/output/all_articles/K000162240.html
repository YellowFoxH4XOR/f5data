K000162240: F5 Distributed Cloud: "Create WAF Exclusion Rule" Button Fails or Returns 404 Error in Console

2026-07-14
Updated
2026-07-14
Applies to

Source

Description

When attempting to create WAF exclusion rules in the F5 Distributed Cloud Console, users may experience the following issues:

  • The "Create WAF Exclusion Rule" button does not respond or fails to open the exclusion form.
  • Error messages such as

    Http failure response: 404 Not Found route with uuid ... not found in HTTP Loadbalancer object

    and

    error getting WAF exclusion policy for route UUID ... not found in HTTP Loadbalancer object

  • UI error:

    Cannot read properties of undefined (reading 'rules')

    in browser console.
  • The issue may affect multiple load balancers and namespaces, and is often intermittent.

Environment

  • F5 Distributed Cloud (XC) SaaS platform
  • Web App & API Protection service
  • HTTP Load Balancer objects managed via Terraform (volterra_http_loadbalancer resource) and/or XC Console
  • Third-party Terraform module
  • WAF exclusion rules managed both via Terraform and Console

Cause

The issue is caused by an incorrect configuration format generated by the Third-party Terraform module. WAF exclusion rules were placed in a deprecated flat field (waf_exclusion_rules) instead of the required nested structure (waf_exclusion → waf_exclusion_inline_rules → rules). This prevented the UI from rendering the exclusion rule form and caused errors.

Answer/Recommended Actions

To resolve the issue:

  1. Update the Third-party Terraform module to use the correct nested structure for WAF exclusions:

    waf_exclusion {
      waf_exclusion_inline_rules {
        rules = var.waf_exclusion_rules
      }
    }

  2. Remove any use of the deprecated waf_exclusion_rules field.
  3. Ensure only one of waf_exclusion_policy or waf_exclusion_inline_rules is present at the load balancer level (they are mutually exclusive).
  4. Use the ignore_changes lifecycle directive on waf_exclusion_inline_rules to safely manage rules in the console without Terraform interference.
  5. If managing WAF exclusions via Terraform, populate the waf_exclusion_inline_rules block with desired rules; otherwise, manage them in the console.
  6. As a workaround, toggling between exclusion policy types ("inline" to "WAF Exclusion Policy" and back) and saving the load balancer can restore the correct structure.

Additional Information

  • Manual exclusion rule creation in the console is effective and can be used as a workaround.
  • The official Terraform provider (terraform-provider-volterra) is not affected; the issue originates from the internal module logic.
  • Route UUID changes or redeployment may cause historical events to reference outdated routes, resulting in 404 errors when creating exclusions for those events.
  • The configuration is compatible with both Terraform and console-based management when the correct structure is used.
