Description

Cisco Meraki security appliances possess an "AutoVPN" feature, which is intended to simplify configuring VPN tunnels between multiple MX/Z appliances, however, unexpected behavior can occur when attempting to add a BIG-IP as a Non-Meraki AutoVPN Peer in an AutoVPN configuration that contains multiple subnets.

Environment

  • BIG-IP 
  • IPsec
  • Meraki MX appliance with multiple subnets included in AutoVPN
  • Attempting to add a BIG-IP as an Non-Meraki AutoVPN peer
 

Cause

Meraki MX/Z appliances will send different AutoVPN-enabled subnets as multiple traffic selectors in a TS proposal. When configuring an IKEv2 IPsec tunnel with multiple subnets on a BIG-IP, only one of the configured networks will work - or the BIG-IP will fail the negotiation and respond with "TS UNACCEPTABLE", meaning that the traffic-selector from the peer was not able to be matched to a locally configured selector. The tunnels may appear to establish correctly, but only one tunnel will "work" in the sense that only one selector/network is reachable while the other network is unreachable.

Cisco Meraki: Site-to-Site VPN Settings

"Meraki Appliances build IPsec tunnels by sending out a request with a single traffic selector that contains all of the expected local and remote subnets. Certain vendors may not support allowing more than one local and remote selector in a given IPsec tunnel (e.g. ASA 5500-X series firewalls running certain firmware releases); for such cases, please use IKEv1 instead."

Cisco Meraki: IKEv1 and IKEv2 for non-Meraki VPN Peers Compared

Note: This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

"Unfortunately, there are known compatibility issues this presents to certain vendors - strongSwan is the process Meraki devices utilize to build tunnels to non-Meraki devices and for L2TP/IPsec Client VPN - as some that continue to enforce the IKEv1 restriction of a single set of src/dst subnets per SA in their IKEv2 implementations (e.g. Cisco ASAs).

Such implementations generally respond to requests to key an IPsec SA by only using a single pair of subnets. When this happens, it blocks any further subnets from participating in the VPN until the SA expires."
 

Recommended Actions

The current advisory per Meraki documentation is to utilize IKEv1 in this scenario. It is possible to only include a single subnet in an AutoVPN configuration, if you desire to build a working tunnel. However, if your deployment requires multiple subnets in AutoVPN, utilizing an intermediate device as a tunnel endpoint between the BIG-IP and Meraki that is able to define traffic selectors such that one selector starts one tunnel, is also possible.
 

Additional Information

This behavior, as it relates to stronSwan's "multi-subnet" feature, is currently being tracked as Bug ID751188.
