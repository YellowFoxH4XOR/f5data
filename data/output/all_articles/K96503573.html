Description

Failing to access application after login screen.

Website hosted through LTM with option to login with username and password showing inconsistency.

Getting the login screen, and trying to login with username and password:

1) While not using LTM, the login is done successfully and the next page is showing.

2) While the LTM is involved, the login screen reappears.

No error messages.

Environment

  • Using the following iRule:
when HTTP_RESPONSE {
 foreach mycookie [HTTP::cookie names] {
  HTTP::cookie secure $mycookie enable
 }
}

Cause

The iRule used causing the Cookie to changed while redirecting. As part of the HTTP response header returned from the BIG-IP system to the client contains the secure attribute. If the virtual server is accepting unencrypted traffic, this cookie will not be sent by the client.

Recommended Actions

Remove the iRule to prevent modifying the Cookie.

  1. Go to Local Traffic >> Virtual Server List >>  VS_name
  2. Go to Resource Tab and click Manage next to iRules.
  3. Move the specific iRule from Enable to Available.
  4. Click Finished

Additional Information

It can easily be seen when running a pcap on the backend server. Use capture traffic on the backend server while using the LTM and when not using it.

A cookie with the Secure attribute is sent to the server only with an encrypted request over the HTTPS protocol, never with unsecured HTTP.
