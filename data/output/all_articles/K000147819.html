What Happened?

You want to test the F5 Distributed Cloud (XC) CDN feature but you are getting a cache MISS every time.

 

Environment

  • F5® Distributed Cloud (XC)
  • HTTP Load Balancer
  • CDN
  • Web App Security & Performance

Resolution/Answer

Check the X-Cache-Status Header:

  • The X-cache-status header in the response will indicate the cache status of the request. Look for values such as HIT, MISS, or BYPASS to determine if the request was served from the cache.

If requests are not being cached, check the following potential causes:

  • Cache-Control Headers from Upstream: If the upstream server sends set-cookie, no-cache, no-store, or private directives in the Cache-Control header, the CDN will not cache the content.
  • Absence of Cache-Control Headers: If the upstream server does not send any Cache-Control headers (like max-age or cache-ttl), the content will not be cached by default. In this case, you can configure a default cache TTL in the CDN distribution to enable caching.
  • Edge Node Cache Population: If there are multiple edge nodes per site, the cache needs to be populated in all edge nodes, unless a mesh CDN topology is in use.

Here's another troubleshooting consideration with Big-IP in the application flow:

  • Client -> CDN -> XC HTTP_LB+WAF -> BIG-IP LB+WAF -> Origin Server ---- This breaks
  • Client -> CDN -> XC HTTP_LB -> BIG-IP LB+WAF -> Origin Server ---- This Works

Cause

  • When the WAF is enabled on the XC HTTP Load Balancer it sets the header "set-cookie".
  • "Set-cookie: TS" Cookie is Causing the CDN to Cache MISS

Additional Information

This behavior is also applied when testing with 'curl', without user-agent header, the cookie appears.
