K57756898: How to enforce HTTP Strict Transport Security (HSTS) when using an iRule to display a maintenance page

Type
Support Solution
Published
2022-11-01
Updated
2025-04-01
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K57756898

Description

Preserve the HTTP Strict Transport Security (HSTS) header when using an iRule to display a maintenance page when no pool members are available for a Virtual Server.

Environment

  • Require all traffic to use HTTPS.
  • HTTP profile with the HTTP Strict Transport Security option enabled and applied to a Virtual Server.
  • iRule to send an HTTP response, such as a maintenance page, to the client when pool members are unavailable.

Cause

The HTTP Strict Transport Security (HSTS) header is not preserved when the iRule responds to the client with the maintenance page since the iRule overrides any settings applied to the HTTP profile.

Recommended Actions

The following procedure allows you to create a maintenance iRule code in order to insert the HSTS header when responding to the client.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List
  3. Click Create.
  4. Type a name in the Name field.
  5. Insert the following code:
when HTTP_RESPONSE_RELEASE {
   HTTP::header insert Strict-Transport-Security "max-age=16070400"
}
when HTTP_REQUEST {
if { [active_members [LB::server pool]] == 0 } {
   HTTP::respond 200 content "Sorry, this page is not currently available."
   }
}
      6. Click Finished.
 
The code above responds with a Strict-Transport-Security Header with a Max Age of 16070400 seconds.
However, you may want to choose different values for Max Age, or include the includeSubdomains and/or preload options.
