K000162850: F5OS-C LACP LAG remains OUT_SYNC/VQF-CC backplane links down

Type
Support Solution
Published
2026-08-10
Updated
2026-08-10
Applies to
  • F5OS Products
  • F5OS-C: 1.8.2
Source
https://my.f5.com/manage/s/article/K000162850

Description

An F5OS-C LAG can go down when the VQF-CC backplane links transition to DOWN across multiple active blades. The system may report a blade as offline with STATE_REASON="blade not present", while LACP members remain OUT_SYNC and stop collecting and distributing traffic.

Example log messages:

STATE="offline" STATE_REASON="blade not present"

vqf-cc-1.2 state="DOWN"

vqf-cc-2.2 state="DOWN"

VQF failover condition on backplane link

Additional symptoms may include VQF IMM Watchdog events, missing VOQ-state entries, and removal of LAG members from the aggregation.

Environment

  • F5OS-C chassis platform with BX520 blades. 
  • Multiple active blades
  • LACP LAG using high-speed interfaces

Cause

Bug ID 2200097

Recommended Actions

Upgrade the chassis to F5OS-C 1.8.2-HR1, where the defect is documented as fixed. F5OS 2.0.0 also contains the fix. 

As an immediate workaround you can reboot the controllers sequentially:

 

  1. Reboot the current standby controller.
    1. Log in to the CLI of the floating management IP address as the chassis administrator. 
    2. Run

      system reboot controllers controller <standby>
  2. Wait for the controller to return to service.
  3. Perform a failover so the other controller becomes standby.
    1. Log in to the CLI of the floating management IP address as the chassis administrator.
    2. Enter the configuration mode terminal by entering the following command: 

      config
    3. Trigger the manual failover of the controllers by entering the following command:

      system redundancy go-standby 
  4. Reboot the newly standby controller.
    1. Log in to the CLI of the floating management IP address as the chassis administrator. 
    2. Run

      system reboot controllers controller <standby>
