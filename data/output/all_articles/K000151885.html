K000151885: NGINX proxy_set_header directives configured in http or server contexts have no effect

Type
Knowledge
Published
2025-06-16
Updated
2025-06-16
Applies to
  • NGINX Products
  • NGINX Plus
  • NGINX Ingress Controller
Source
https://my.f5.com/manage/s/article/K000151885

Description

When NGINX is configured with one or more proxy_set_header directives in the server or http contexts, the defined headers my not be passed to upstream services. This behavior is by design and will occur when one or more proxy_set_header directives are defined in the location context. Furthermore, when one or more proxy_set_header directives are configured in the server and http contexts, but not within the location context, then only the headers defined within the server context will be passed to upstream services. From documentation ngx_http_proxy_module:

(proxy_set_header) directives are inherited from the previous configuration level if and only if there are no proxy_set_header directives defined on the current level.

This means that if there are one or more proxy_set_header directives defined in the location context, then any proxy_set_header directives defined in the server or http contexts will be ignored. Example:

http {
  proxy_set_header Test_Header_http "value_http";
  server {
    proxy_set_header Host $host;
    proxy_set_header Test_Header_server "value_server";
    location / {
      proxy_set_header Test_Header_location "value_location";
      proxy_pass http://test_service;
    }
  }
}

The upstream HTTP request headers would look something similar to the following:

GET / HTTP/1.1
Test_Header_location: value_location
Host: test_service
Connection: close
User-Agent: curl/7.81.0
Accept: */*

Notice the test header is from the proxy_set_header directive defined in the location context. Also notice the headers defined in the proxy_set_header directives within the server and http contexts are not present in the upstream request. This is because they are not inherited since one or more proxy_set_header directives are defined in the location context.

http {
  proxy_set_header Test_Header_http "value_http";
  server {
    proxy_set_header Host $host;
    proxy_set_header Test_Header_server "value_server";
    location / {
      #proxy_set_header Test_Header_location "value_location";
      proxy_pass http://test_service;
    }
  }
}

GET / HTTP/1.1
Host: test.example.com
Test_Header_server: value_server
Connection: close
User-Agent: curl/7.81.0
Accept: */*

In the above configuration, the proxy_set_header directive within the location context has been removed. The headers defined in the server context, Host and Test_Header_server, are inherited and sent with the upstream HTTP request. Notice the header defined in the http context, Test_Header_http, is not passed to the upstream service. This is because one or more proxy_set_header directives are defined in the server context. Any proxy_set_header directives defined in the previous http level context will not be inherited and will be ignored.

http {
 proxy_set_header Test_Header_http "value_http";
 server {
   proxy_set_header Host $host;
   #proxy_set_header Test_Header_server "value_server";
   location / {
     #proxy_set_header Test_Header_location "value_location";
     proxy_pass http://test_service;
   }
  }
}

GET / HTTP/1.1
Host: test.example.com
Connection: close
User-Agent: curl/7.81.0
Accept: */*

In the configuration above, header definition Test_Header_server has been removed from the server context. The header defined in the http context, Test_Header_http, is not passed to the upstream. This is because the proxy_set_header directive for the Host header is still configured within the server context. The proxy_set_header directive configured in the http context is still not inherited and is ignored, as expected.

http {
 proxy_set_header Test_Header_http "value_http";
 server {
   #proxy_set_header Host $host;
   #proxy_set_header Test_Header_server "value_server";
   location / {
     #proxy_set_header Test_Header_location "value_location";
     proxy_pass http://test_service;
    }
  }
}

GET / HTTP/1.1
Host: test_service
Test_Header_http: value_http
Connection: close
User-Agent: curl/7.81.0
Accept: */*

Finally, within the above configuration, both proxy_set_header directives have been removed from the server context. The header defined in the http context, Test_Header_http, has been inherited and passed to the upstream service.
