Environment

  • BIG-IP DNS
  • GTM Server
  • Virtual Server auto-discovery enabled

Cause

Due to difference in Virtual Server configuration between LTM units which are part of GTM server setup, you can observe constant config updates on you BIG-IP DNS unit.
Based on presented example, in your 2 LTM units which are part of "gtm server /Common/local.example.com", you'll be able to find on your LTM units configuration inconsistency.
There might be more than one inconsistency, but in below example you may observe that IP addresses of Virtual Servers are not matching between units, which can trigger this behavior:
On BIG-IP LTM (192.168.2.17):
tmsh list ltm virtual <Virtual_Server_name>
ltm virtual example_vs {
...
    destination 192.168.113.14:0
    ip-protocol tcp
...
}

On BIG-IP LTM (192.168.2.71)
tmsh list ltm virtual <Virtual_Server_name>
ltm virtual example_vs {
...
    destination 192.168.113.41:0
    ip-protocol tcp
...
}

Recommended Actions

Review configuration on your BIG-IP LTM units, for Virtual Server which config is inconsistent between those units.
BIG-IP DNS with Virtual Server configured within GTM Server, requires exactly the same configuration for Virtual Server in all LTM units which use same name for this object.
In short if "example_vs" Virtual Server is configured on multiple LTM units - all those units needs to use same configuration for this Virtual Server.
