Description

SSLO 5.x systems configured with an inline L3 service may experience this issue if the inline L3 service (most commonly a firewall/proxy, or a capture portal which tries to redirect unauthenticated traffic to a logon page) attempts to change application-layer content retrieved from a web server (eg. changing a HTTP 200 OK to a HTTP 307 Redirect) - resetting the connection on all sides instead of forwarding the changed content as expected for an L3 forwarding device. Client connections may fail, receiving a reset instead of being redirected by an inline firewall or capture portal to a login page or a redirected resource.
 

Environment

This issue occurs when all of the following conditions are met:
  • You have an application-layer aware device configured as an inline service in SSLO (eg. a firewall/proxy or a capture portal)
  • This application-aware service attempts to change the application data (decrypted TCP payload) sent to it by the SSLO which was retrieved from the internet web server.


Cause

When an inline firewall/proxy modifies serverside HTTP content and sends it back to the SSLO, the SSLO resets the connection instead of forwarding the modified content on to the client. F5 Product Development has assigned ID 755447 to this issue.

As a result of this issue, you may encounter one or more of the following symptoms:
  • Client connections receive a TCP reset instead of changed content (eg. HTTP 307 Redirect) generated by the inline firewall/proxy device.
