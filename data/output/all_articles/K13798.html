Topic

BIG-IP WebAccelerator 11.0.0 introduced the wainfodecode utility. With this utility, users can quickly decode the X-WA-Info header information into human readable format by using data taken from the local BIG-IP WebAccelerator or BIG-IP AAM policies.

Note: BIG-IP WebAccelerator and BIG-IP WOM were combined to create BIG-IP AAM in 11.4.0.

Description

The X-WA-Info header is optionally inserted into each BIG-IP WebAccelerator or BIG-IP AAM response. It allows a system administrator to track how the BIG-IP WebAccelerator or BIG-IP AAM services an object, including details about how it was cached and which policy nodes were used. For more information about enabling X-WA-Info, refer to K13346: The BIG-IP WebAccelerator X-PvInfo header is renamed the X-WA-Info header.

An X-WA-Info HTTP response header from the BIG-IP WebAccelerator or BIG-IP AAM may appear similar to the following example:

X-WA-Info: [V2.S11101.A38029.P23208.N37551.RN0.U112462967].[OT/jpeg.OG/images]

The following table provides information about the codes:

CodeDescription
VThe V code is the first field of the X-WA-Info header and indicates the version of the X-WA-Info response header code used in the BIG-IP software.
SThe S code is the second field of the X-WA-Info response header. This field indicates whether the object in the HTTP response was served from the BIG-IP WebAccelerator or BIG-IP AAM cache or was sent from the originating web server. To view a table of S code definitions, refer to the BIG-IP Acceleration: Concepts guide. The wainfodecode utility shows a human-readable definition of the S code. Unlike the other codes, this translation remains valid even when the configuration changes.

Note: The wainfocode utility included in BIG-IP WebAccelerator versions prior to 11.2.0 did not recognize response code S10233.

AThe A code is the third field of the X-WA-Info response header, and it identifies to which application the BIG-IP matched the request.  This help you determine which application rules the BIG-IP applied to the request.  The wainfodecode utility shows the name of the application that was matched.  
PThe P code is the forth field of the X-WA-Info response header and indicates the acceleration policy the BIG-IP applied to the request.  The wainfodecode utility shows the name of the acceleration policy to which the request was matched.
NThe N code is the fifth field of the X-WA-Info response header and it identifies the application match of a request to an acceleration policy.  The request node ID matches the policy node ID.
RNThe RN code is the sixth field of the X-WA-Info response header, and it identifies the application match of a response to an acceleration policy. The BIG-IP WebAccelerator or BIG-IP AAM system can perform response-based application matching against MIME types in a response, or by matching file name extensions. Request-based application matching against extensions in the URL path is not considered a response application match. However, a request application match appears in the N field.

In addition, you can configure an assembly rule to specify custom rewrites that redirect one application match to another application match in an acceleration policy. This is most often used to handle exceptions to a general application match rule.

A zero (0) RN code in the X-WA-Info response header indicates that a response-based application matching did not supercede the initial request match and that the initial request match and the response match are the same. A nonzero RN code indicates the response matching superceded the decision made in the initial request match, and that the initial request match and the response match are different.

UThe U code is the seventh field of the X-WA-Info response header and is used to verify the behavior of variation rules.  Two responses with the same U code were served the same cache entry; two responses with different U code values were served different cache entries.
OT and OGThe second section of the X-WA-Info response header contains the object type and object group under which the response is classified. Together, these identify a BIG-IP WebAccelerator or BIG-IP AAM object type, as found in the Object Types screen of the Configuration utility. The wainfodecode utility shows the name of the object type under which the response is classified. The object type for the response indicates whether the BIG-IP WebAccelerator or BIG-IP AAM system superceded the rewrite or compression settings in the assembly rule for the node specified by the N code.

Recommendations

When troubleshooting or debugging a BIG-IP WebAccelerator or BIG-IP AAM installation, you should consider the following factors:

  • Using the wainfodecode utility, the header is quickly decoded into its component parts and is cross referenced to the policies on your host. For this reason, you should always run the wainfodecode utility on the host that processed the response.

Perform the following steps to obtain and decode an X-WA-Info header:

  • Ensure that X-WA-Info is enabled in the BIG-IP WebAccelerator or BIG-IP AAM application, as described in K13346: The BIG-IP WebAccelerator X-PvInfo header is renamed the X-WA-Info header.
  • Capture BIG-IP WebAccelerator or BIG-IP AAM processed HTTP traffic using the tcpdump utility on the BIG-IP host. Or, view incoming HTTP headers using utilities such as HttpWatch or Wireshark on the HTTP client.
  • Copy and paste the data portion of the X-WA-Info header to the BIG-IP system to be processed with the wainfodecode utility. Enclose the data in quotation marks:

    wainfodecode "[V2.S11101.A38029.P23208.N37551.RN0.U112462967].[OT/jpeg.OG/images]"

    The corresponding decoded output from this command will appear similar to the following example:

    V2: X-WA-Info Format Version
    S11101: Response was served from Hot Cache.
    A38029: Application: /Common/example_application
    P23208: Local-policy: /Common/Copy of Generic Policy - Complete
    N37551: Request Policy Node: JPEG
    RN0: Response match did not supersede request match
    UCI hash: 6b40c77
    Object type: jpeg
    Object group: images
