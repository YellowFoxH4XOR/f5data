Description

When testing HTTP requests that trigger an ASM violation, the request times out, and the client doesn't receive a blocking page.

Testing with a curl command similar to the following:

curl '10.10.10.1/test?1=<script>' -H 'Content-Length: 1'

Environment

  • ASM enabled
  • Testing with curl

Cause

This is expected. The Content-Length header was provided, but there is no payload in the request. In this situation ASM will keep the connection open and wait for the number of payload bytes indicated by the Content-Length header, before it finishes processing the request and returns a blocking page (if violations were found).

Recommended Actions

None

Additional Information

When a client issues many such requests, ASM is able to prevent a denial of service (DoS) condition by detecting a slow transactions attack. This is defined by the slow_transaction_timeout and max_slow_transactions internal variables. For more information, refer to:

  • K42552578: Mitigating Slow HTTP POST attacks

Note: A slow transactions attack will be mitigated the same, regardless of HTTP method used. It doesn't need to be a POST.
