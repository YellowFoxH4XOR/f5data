Known Issue

Attack Signature names may not be reported to the remote logging server. The attack signature violation event is delivered to the remote logging server; however, the details of the Attack Signature name are not included.  Full details for the relevant violation are included in local logs.

Impact

Remotely logged attack signature violations do not include the name of the attack signature causing the violation.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Violations reported to a remote logging server do not include the name of the attack signature that caused the violation.
  • Log entries that appear similar to the following example may be written to the /var/log/asm file:

    01310011:3: ASM configuration error: event code T713 Failed to update configuration table

  • Log entries that appear similar to the following example may be written to the /var/log/ts/bd.log file:

    ECARD_POLICY|NOTICE|06/02/12 22:56:29|8078|LoggingAccount.h:0684|add: obj already in table

    ECARD|ERR |06/02/12 22:56:29|8078|table.h:0263|KEY_PUT: Failed to PUT data

    ECARD|ERR |06/02/12 22:56:29|8078|temp_func.c:0714|CONFIG_TYPE_SIG_NAMES message had errors in block_index: 0. status=9

Workaround

To work around this issue, you can update the remote logging profile. To do so, perform the following procedure:

Impact of workaround: None

Note: To update the profile, you need to make a change to any setting, and commit the change. In the following example, the Remote Storage Type setting will be changed, but you can use any setting in the profile.

  1. Log in to the Configuration utility.
  2. Select the appropriate Remote Storage Profile from the Application Security > Options > Logging Profiles menu.
  3. Change the Remote Storage Type value from Remote to ArcSight.
  4. Click Update.
  5. Change the Remote Storage Type  value from ArcSight back to Remote.
  6. Click Update.
