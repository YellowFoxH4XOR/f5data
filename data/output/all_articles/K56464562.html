Description

F5 Edge Client intermittently sends data down tunnel when Netskope is being used.

    Environment

    • F5 Edge Client v7213
    • Netskope v87
    • Mac OS Big Sur but guide is generic for best practice regardless of OS

    Cause

    Misconfiguration.

    Recommended Actions

    Netskope needs to have the APM Virtual server listed as an exception. Discuss with the Netskope admin to get the Netskope Security Cloud IP addresses and the DNS Servers to exclude in the APM configuration.  As of this writing, Netskope uses Google's public DNS server for determining location information (8.8.8.8 and 8.8.4.4)
    Note: APM should be configured as a full tunnel using the Split Tunneling option.
    1. Navigate to Access => Connectivity / VPN => Network Access (VPN) => Network Access Lists
    2. Edit an existing connection or create a new connection
    3. If creating a new connection, add a name and click finished => Network Settings tab. If editing an existing connection, click Network Settings tab.
    4. Configure the following Client Settings: (Make sure Client Settings is set to Advanced):
      1. Traffic Options == Use split tunneling for traffic
      2. IPV4 LAN Address Space == 0.0.0.0/0
      3. IPV4 Exclude Address Space == This is the list in CIDR format that the Netskope admin should have prepared. Add all the addresses here. For example, to add Google's DNS servers:
        1. type 8.8.8.8/32 next to CIDR to specify that full address will be excluded from going down the APM Tunnel
        2. Click Add
        3. Repeat for the remaining addresses you would like excluded from the APM tunnel.
      4. All other settings are configured as necessary for your VPN connection.
    5. Click Update
    6. Go to your access profile and make the Network Access resource available to your users.
