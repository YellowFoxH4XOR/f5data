Known Issue

The BIG-IP system may incorrectly log Limiting closed port RST response messages to the /var/log/ltm file, even though the tm.rejectunmatched BigDB variable is set to false.

This issue occurs when the following condition is met:

  • The number of packets received reaches the value set in the tm.maxrejectrate BigDB variable. The default value is 250 TCP RSTs or 250 ICMP unreachable packets per second.

The tm.rejectunmatched BigDB variable allows the BIG-IP administrator to decide whether to reject or silently drop invalid TCP packets, and by default, the tm.rejectunmatched BigDB variable is set to true. If the BigDB variable is set to false, the BIG-IP system will silently drop unmatched packets as expected. However, the BIG-IP system will still log this message even though the packets have not been sent.

Impact

Even though the BIG-IP system is set to silently drop unmatched packets, it will continue to log messages to the /var/log/ltm file when it receives large numbers of packets.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H481895 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system logs messages to the var/log/ltm file that appear similar to the following example:

    warning tmm1[PID]: 011e0001:4: Limiting closed port RST response from 251 to 250 packets/sec
    warning tmm1[PID]: 011e0001:4: Limiting closed port RST response from 251 to 250 packets/sec
