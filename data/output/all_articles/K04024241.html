Known Issue

macOS High Sierra systems cannot establish network access sessions when the BIG-IP Allow Local Subnet setting is enabled.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured to provide network access.
  • In the network access settings, Allow Local Subnet is enabled.
  • A client system running macOS High Sierra attempts to establish a network access session.
  • A single DNS server is configured on the client system, either manually or by DHCP.

Impact

Users cannot establish a network access session.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After upgrading the BIG-IP APM system to 13.x, users running macOS High Sierra cannot establish a Virtual Private Network (VPN) tunnel using Safari or BIG-IP Edge Client.
  • BIG-IP Edge Client displays a message similar to the following example:

    Error: VPN disconnected

  • The svpn.log file on the client system includes messages similar to the following example:

    1936,96531,svpn, 1, /svpn.cpp, 1742, , EXCEPTION caught: EXCEPTION!!!
    1936,96531,svpn, 0,,,, --------- Exit of Tunneling Loop --------

Workaround

To work around this issue, you can configure the client with more than one DNS server, or you can disable the Allow Local Subnet setting. To disable the Allow Local Subnet setting, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Connectivity / VPN > Network Access (VPN).
  3. Click the name of the network access configuration.
  4. Click the Network Settings tab.
  5. In the Client Settings section, in the Allow Local Subnet setting, clear the Enable check box.
  6. Click Update.
  7. Click Apply Access Policy.
  8. Confirm the correct access policies are selected and click Apply.
