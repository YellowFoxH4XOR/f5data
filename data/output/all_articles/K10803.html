Topic

When the BIG-IP ASM system is configured with a large number of XML schemas or particularly large schemas, the XML processing engine may exhaust its memory. This condition causes the BIG-IP ASM system to lose its ability to process XML requests, leading to XML requests likely triggering meta character violations. Additionally, the system logs the following error message in the /var/log/asm file:

01310003:0: ASM out of memory error: event code X89 Exceeded maximum memory assigned for XML processing

By default, the XML processing engine is allocated as follows:

  • 300 MB of memory on platforms with less than 16 GB of RAM
  • 450 MB of memory on platforms with at least 16 GB of RAM but less than 32 GB
  • 1 GB on platforms with 32 GB of RAM or more (prior to BIG-IP 12.0.0, larger systems use the 450 MB default). 

You can change this value by going to System Variables in the BIG-IP Configuration utility and editing the total_xml_memory variable. Starting in BIG-IP ASM 11.5.4 on the BIG-IP 11.5.x branch, BIG-IP 11.6.1 on BIG-IP 11.6.x branch, and BIG-IP 12.0.0, if additional memory is required beyond the total_xml_memory maximum of 1 GB, you can use the additional_xml_memory_in_mb system variable, which you can configure to allocate up to 64 GB of memory for XML processing.

Modify the total_xml_memory variable using the Configuration utility

To watch a video demo of this procedure, go to K000158207: Customize memory allocation for the BIG-IP ASM XML processing engine using the Configuration utility.

Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. While the asm process restarts, traffic on the BIG-IP system is interrupted. Additionally, when the BIG-IP ASM system is in a device group, it fails over to the next available member.

  1. Log in to the Configuration utility.
  2. Go to Security > Options > Application Security > Advanced Configuration > System Variables.
  3. Under System Variables, select total_xml_memory.

    Note: When the allocated memory for the XML processing engine is at the default setting (300 MB/450 MB), the Configuration utility displays the allocated total_xml_memory as 0 (zero).

    Note: You may need to select Next page (>) to see total_xml_memory.

  4. In Parameter Value, enter the value you want, in bytes.

    For example, to configure a total of 600 MB of memory, enter 629145600.

  5. Select Update.
  6. Log in to the BIG-IP command line.
  7. Restart the BIG-IP ASM service by entering the following command:
    • For VIPRION, to restart the asm process on all blades at once:

      clsh tmsh restart /sys service asm

    • For any other platform, to restart the asm process:

      tmsh restart /sys service asm

Note: If you are using a device group, after you synchronize the setting, you must restart the asm process on all members of the device group in order for this change to take effect on the other device group members.

For information about accessing the System Variables section, refer to K3853: Accessing the System Variables page.

If modifying total_xml_memory does not provide enough memory resources, you can modify the additional_xml_memory_in_mb variable using the command line.

To do so, perform the following procedure:

Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. While the asm process restarts, it interrupts traffic. Additionally, when the BIG-IP ASM system is in a device group, it fails over to the next available member.

Note: The additional_xml_memory_in_mb variable is not exposed by default in the Configuration utility. However, after initially modifying the additional_xml_memory_in_mb variable from the command line, the variable becomes visible in the Configuration utility.

  1. Log in to the BIG-IP command line.
  2. To specify that the system allocate an additional amount of memory to the XML processing engine, use the following command syntax:

    /usr/share/ts/bin/add_del_internal add additional_xml_memory_in_mb <megabytes>

    For example, to allocate 8 GB of memory to the XML processing engine, enter the following command:

    /usr/share/ts/bin/add_del_internal add additional_xml_memory_in_mb 8000

    Note: The maximum possible value for additional_xml_memory is 64000 MB (64GB). Values in excess of this amount revert to 64000 MB. 

  3. Restart the asm process by entering the following command:
    • For VIPRION, to restart the asm process on all blades at once:

      clsh tmsh restart /sys service asm

    • For any other platform to restart the asm process:

      tmsh restart /sys service asm

  4. Enter the following command to review total_xml_max_mem to verify that it displays the amount of memory you want:

    tmctl asm_memory_util_stats

Note: If you are using a device group, after you synchronize the setting, you must restart the asm process on all members of the device group for this change to take effect on the other device group members.
