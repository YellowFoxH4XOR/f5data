Description

When users connect to the BIG-IP APM VPN, they are able to establish a VPN session successfully. However, while connected, they are unable to browse the internet or use cloud-based applications such as Microsoft Outlook and Microsoft Teams. Disconnecting from the VPN restores normal internet and application access. The issue is observed even though split tunneling is configured, and only some users are affected. DNS queries for public domains (e.g., www.google.com) time out when connected to the VPN.

Environment

  • BIG-IP APM
  • Network Access Resource with split tunneling enabled
  • Internal DNS servers assigned to VPN adapter
  • DNS suffix for internal domains
  • Client devices using both VPN and local Wi-Fi adapters
  • "Allow Local DNS Servers" option initially disabled

Cause

DNS queries for public domains are being sent to internal DNS servers provided by the VPN. These internal DNS servers are unable to resolve external/public domains, resulting in failed internet and cloud application access while connected to the VPN. Routing is correct, but DNS resolution for public domains fails.

Answer/Recommended Actions

  1. Enable "Allow Local DNS Servers" in the Network Access Resource:
    • Navigate to:
      Access ›› Connectivity / VPN : Network Access (VPN) : Network Access Lists ›› [Your Network Access Resource] ›› Client Settings
    • Enable the Allow Local DNS Servers option. This allows client devices to use their local DNS servers for public domain queries while continuing to use internal DNS servers for internal resources.
  2. Alternative Option:
    • Configure internal DNS servers to resolve or forward public domain queries.
    • This requires changes to your DNS infrastructure and is not always preferred.
  3. Testing DNS Resolution:
    • While connected to the VPN, run the following commands on the client:
      • nslookup www.google.com
      • nslookup <your_internal_domain>
    • Confirm that public domains resolve using the local DNS server and internal domains resolve using the VPN-provided DNS server.
