Description

After trying to allocate more space to /appdata with 'resize' command, an error like the one below is shown: 

resize2fs: Inappropriate ioctl for device While trying to add group #4096

Also the change is not reflected when running the 'df' command:

df -h  | grep appdata
/dev/mapper/vg--db--vda-dat.appdata     31G  1.4G   29G   5% /appdata
 

While the logical volume resized correctly:
vgdisplay -vA

Cause

Unknown

Recommended Actions

Impact of procedure: While system services are stopped, the system will not pass traffic and the Configuration utility will be unavailable; therefore, F5 recommends that you perform this procedure during a scheduled maintenance window.


1. Stop all  system services on the BIG-IP:
tmsh stop sys service all

Note: The device will change to 'INOPERATIVE' status, this is expected behavior

2. Unmount the file system in question:
umount /appdata

Note: On BIG-IP versions where ID 1121169 exists (16.1.2.2, 16.1.3. and 17.0.0),  you also need to run "systemctl stop jitterentropy-rngd". For more information, refer to ID 1121169.

3. Run a file system check:
e2fsck -f /dev/vg-db-vda/dat.appdata

4. Resize /appdata:
resize2fs /dev/vg-db-vda/dat.appdata

5. Unmount the file system in question:
mount /appdata

6. Start all  system services on the BIG-IP:
tmsh start sys service all

Note: On BIG-IP versions where ID 1121169 exists (16.1.2.2, 16.1.3. and 17.0.0),  you also need to run "systemctl start jitterentropy-rngd". For more information, refer to ID 1121169.
