Description
You can upload and download files to a BIG-IP system using the iControl REST API. The following procedures demonstrate how to upload and download files to and from specific BIG-IP directories. There are some caveats to operation.
You should consider using this procedure under the following conditions:

  • You want to use the iControl representation state transfer (REST) application programming interface (API) to upload or download files on BIG-IP systems.
  • You want to use REST to upload software images to the BIG-IP system.

Environment

  • Administrative access to BIG-IP via REST API
  • BIG-IP or Linux device with curl and stat installed
  • General understanding of Linux Commands

Cause
None.

Recommended Actions

Depending on the action desired, one of the following procedures should be performed.
  • Uploading small files
  • Uploading large files (like ISOs)
  • Downloading general files
  • Managing uploaded files

When uploading a file, either a single HTTP POST or multiple HTTP POSTs are needed based on the file size and BIG-IP software version:

  • BIG-IP 12.0.x allows REST API file upload with a maximum of 1MB per HTTP POST.
  • BIG-IP 12.1 and later allows a maximum of 33554432 bytes (~33.5MB). Note that uploads should not exceed 30MB to reduce the potential for headers making the total size too large.

Based on the file size either a single curl command can be issued to upload or script with multiple curl commands.

Uploading small files

Note: This assumes the file size is less than 33.5MB. If it is larger, the process described in "Uploading Large Files" will need to be used.

Using the following procedure you can upload small files to the BIG-IP system using the iControl REST interface. Since software image files are not small, the general file directory /var/config/rest/downloads on the BIG-IP is used as the destination.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log on to the local BIG-IP or Linux device which will upload the file to the target BIG-IP.
  2. Determine the file size of the file using the follow command syntax:

    stat -c%s <filename> 

    Note: Replace <filename> with the name of the upload file name.
    For example:
    stat -c%s SomeFile
    150640

  3. Use the following curl command syntax to upload the file to the remote BIG-IP system:

    /usr/bin/curl -o /dev/null -sku <username>:<password> https://<ip address or host>/mgmt/shared/file-transfer/uploads/<destination file name> -H 'Content-Type: application/octet-stream' -H 'Content-Range: 0-<file size minus 1>/<file size>' -H 'Connection: Close' --data-binary @<local file name>

    Replace <username> and <password> with the REST Administrator username and password.
    Replace <ip address or host> with the destination BIG-IP system REST-accessible IP address or hostname.
    Replace <destination file name> with the name for the file when uploaded to the BIG-IP system.
    Replace <file size minus 1> with the value obtained from the stat command minus 1.
    Replace <file size> with the value obtained from the stat command.
    Replace <local file name> with the exact path and name of the file you want to upload. 
    For example:
    /usr/bin/curl -o /dev/null -sku admin:admin https://192.0.2.1/mgmt/shared/file-transfer/uploads/SomeFile -H 'Content-Type: application/octet-stream' -H 'Content-Range: 0-150639/150640' -H 'Connection: Closed' --data-binary @/home/root/Downloads/SomeFile

Uploading large files (like ISOs)

You can use the iControl REST interface to upload large files, like software image files (ISOs) to the BIG-IP system. While large files can be placed in file-transfer/uploads directory as well, image files should be placed in /shared/images so a different REST API path is used when uploading. Large files have to be chunked into multiple HTTP POSTs which is not supported natively by curl. Consequently a script needs to be used to chunk and format the sequence of POSTs. The following script is an example and should be used as a starting point for whatever format is appropriate for your specific environment.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log on to a local BIG-IP or Linux device.
  2. Create a new file (recommended name: multi_post_upload)
  3. Paste the following information into the file:
    #!/bin/bash
    # Multiple Post REST File Upload Example Script
    # Oct-23-2020 j.clark@f5.com
    # Based on Python script by Jason Rahm, F5
    # https://devcentral.f5.com/s/articles/demystifying-icontrol-rest-part-5-transferring-files
     
    # 1=debug on, 0=debug off
    debug=0
     
    # Each argument saved as a variable (these are simply for reference and can be removed)
    ipaddress=$1
    username=$2
    password=$3
    filename=$4
    path=$5
    destfilename=$6
    [ $debug = 1 ] && echo "Address: $ipaddress User: $username Password: $password Local File: $filename Remote Path: $path Remote File: $destfilename"
     
    # dd has a default block size of 512. It is specified manually here
    # to allow tuning.
    blocksize=512
    # blocknumber * blocksize = total size of file segment
    # Number of blocks to read at a time.
    # 30720 results in ~15mb segments, getting almost as good performance
    # as 30MB without getting near the 33MB ceiling of 12.1.+.
    blocknumber=30720
    # 61440 results in ~30MB segment, the largest size for 12.1+.
    #blocknumber=61440
    # 2048 results in 1MB segments the same size as BIG-IQ uses.
    # Required for 12.0.x.
    #blocknumber=2048
     
    # Length of the file, in bytes
    filelength=$(stat -c%s $filename)
    [ $debug = 1 ] && echo "File length is: $filelength"
    # Location/name of temporary file to hold the chunk
    tempfile=/tmp/tempfile
    # Initialize at Offset 0 so read starts at the 1st byte
    offset=0
    # Initialize end to -1 for single POST case
    end=-1
    # Initialize Connection type at Keep-Alive
    connection="Keep-Alive"
     
    echo "Uploading $4 to $1."
     
    # Begin loop to iterate through the file and upload in chunks
    while true
    do
            [ $debug = 1 ] && echo "Starting iteration with offset of $offset"
            # Copy portion of file into tempfile as a chunk
            /bin/dd status=none if=$filename of=$tempfile count=$blocknumber skip=$offset bs=$blocksize     2> /dev/null
            [ $debug = 1 ] && echo "tempfile is $(stat -c%s $tempfile) bytes long"
            # Determine length of segment
            chunklength=$(stat -c%s $tempfile)
            # Determine if this segment completes the filelength
            if [ $(( $end + $chunklength + 1 )) -eq $filelength ]; then
                    # This is last segment, set connection to Close
                    [ $debug = 1 ] && echo "Final segment reached."
                    connection=Close
            fi
            # Set start and end for this segment
            start=$(( $offset * $blocksize ))
            # end -1 to adjust to zero-based
            end=$(( $start + $chunklength - 1 ))
            [ $debug = 1 ] && echo "Content-Range: $start-$end/$filelength"
            [ $debug = 1 ] && echo "Connection: $connection"
            # Make the POST request, uploading the content chunk
            # BIG-IP REST JSON response piped to /dev/null
            curl -sku $username:$password https://$ipaddress$path$destfilename -X POST -H "Content-Type: application/octet-stream" -H "Content-Range: $start-$end/$filelength" -H "Expect: " -H "Connection: $connection" --data-binary @$tempfile > /dev/null
            # Print a period to indicate progress.
            printf "."
            # If this was final segment, end loop
            if [ $connection = "Close" ]; then
                    [ $debug = 1 ] && echo "Breaking loop."
                    # Print complete
                    printf "done.\n"
                    break
            fi
            # Increment the offset by the number of blocks read at a time
            offset=$(( $offset + $blocknumber ))
            [ $debug = 1 ] && echo "offset increased to $offset"
    done
    # Delete the tempfile
    rm -f /tmp/tempfile
    # Display md5sum for the local file to compare to remote file
    printf "Calculating md5sum for $4 to compare to uploaded file:\n"
    md5sum $4
  4. Save the file
  5. Make it executable with "chmod +x multi_post_upload"
  6. Use the following curl command syntax to upload the large file (like software image) to the remote BIG-IP system:

  7. ./multi_post_upload <ip address or host> <username> <password> <local file name> <destination path> <destination file name>

    Replace <ip address or host> with the destination BIG-IP system REST-accessible IP address or hostname.
    Replace <username> and <password> with the REST Administrator username and password
    Replace <local file name> with the exact path and name of the file you want to upload. 
    Replace <destination path> with either "/mgmt/cm/autodeploy/software-image-uploads/" for software images or "/mgmt/shared/file-transfer/uploads/" for general files.
    Replace <destination file name> with the name of the file to use when uploaded to the BIG-IP system.

    For example: ./multi_post_upload 192.0.2.1 admin myComplexPassword /shared/images/BIGIP-13.1.1.5-0.0.4.iso /mgmt/cm/autodeploy/software-image-uploads/ 13.1.1.5.iso

    This will result in output like:
    Uploading /shared/images/BIGIP-13.1.1.5-0.0.4.iso to 192.0.2.1.
    ................................................................................
    ....................................................done.
    Calculating md5sum for /shared/images/BIGIP-13.1.1.5-0.0.4.iso to compare to uploaded file:
    5bbe492dcf1cc69fdf5acb00e941c493 /shared/images/BIGIP-13.1.1.5-0.0.4.iso

Downloading general files

You can retrieve files using the iControl REST interface by using a crafted curl command that uses HTTP GET. 

The following procedure demonstrates retrieving files from the BIG-IP system directories /var/config/rest/downloads and /shared/images:

Important: You cannot generate a directory listing of files located on the remote BIG-IP system. The destination file spelling and case must be known and appended to the URL.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • Use the following command syntax to download a file located in the BIG-IP system /var/config/rest/downloads directory:

    /usr/bin/curl -ku <username>:<password> -X GET https://<ip address>/mgmt/shared/file-transfer/uploads/<filename> -o <local downloaded filename>

  • Use the following command syntax to download a file located in the BIG-IP system /shared/images directory:

    /usr/bin/curl  -ku <username>:<password> -X GET https://<ip address>/mgmt/cm/autodeploy/software-image-downloads/<filename>  -o <local downloaded filename>

    Important: The allowable file download size when using the iControl REST interface is capped at 1MB, files greater than 1MB will become truncated.
    Important: Using the HTTP GET command to download files does not function on BIG-IP releases 15.0.0 and later.

    Note: Replace <username> and <password> with the Configuration utility username and password.
    Replace <ip address> with the destination BIG-IP system management IP address.
    Replace <remote filename> with the exact name of the file you want to download. 
    Replace <local downloaded filename> with the file name to use when downloaded to the local device.
    For example:
    /usr/bin/curl -ku admin:admin -X GET https://192.168.1.100/mgmt/shared/file-transfer/uploads/SomeFile -o somefile

Moving uploaded files to alternate locations

After uploading a file to the BIG-IP system you may want to place the file in an alternate location of the BIG-IP Unix file system. The following procedure demonstrates how to move a file from an upload location to another location in the file system.

Impact of procedure: Using the following commands should not have a negative impact on your system.

Use the following command syntax to move files to an alternate location.

curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/util/unix-mv -X -d "{\"command\":\"run\",\"utilCmdArgs\":\"/<filesystem path><file name>/<filesystem path><file name>\"}"

For example:

curl -sk -u JohnSmith:password123 -H "Content-Type: application/json" -X POST https://192.168.0.0/mgmt/tm/util/unix-mv -X -d "{\"command\":\"run\",\"utilCmdArgs\":\"/shared/images/SomeFile  /config/SomeFile\"}"

Change user ownership of a file

File permission can be important when the uploaded file is dependent on specific Unix level ownership, or group association. The following two procedures demonstrate how to set the Unix level ownership and group ownership of the uploaded file.

Impact of procedures: Using the following commands should not have a negative impact on your system, however use with caution. Changing the owner or group ownership of a system dependent file can cause the BIG-IP to stop processing traffic.

Use the following command syntax to change user ownership of a file:

curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'chown <unix user> /<filesystem path>/<filename>'\"}"

For example:

curl -sk -u admin:admin -H "Content-Type: application/json" -X POST https://192.168.1.100/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'chown root  /shared/images/SomeFile'\"}"

Changing group ownership of a file

Use the following command syntax to change group ownership of a file:

curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'chgrp <filesystem path>/<filename>'\"}"

Changing the mode settings of a file

When uploading a file that the BIG-IP system uses, the file may require specific file mode settings. For example an external monitor script needs to be set as executable.

The following procedure demonstrates how to set the specific file mode on the uploaded file.

Impact of procedure: Using the following commands should not have a negative impact on your system; however, use the commands with caution. Changing the mode of a system dependent file can cause the BIG-IP system to stop processing traffic.

To set the specific file mode on an uploaded file, use the following command syntax:

curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'chmod <mode value>  <filesystem path>/<filename>'\"}"

For example:

curl -sk -u admin:admin -H "Content-Type: application/json" -X POST https://192.168.1.100/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'chmod 444  /shared/images/SomeFile'\"}"

Deleting a file

To delete a file from the BIG-IP system you can use the following procedure:

Impact of procedure: Using the following commands should not have a negative impact on your system; however, use caution when deleting any file. Deletion of a system dependent file can cause the BIG-IP system to stop processing traffic.

To delete a file, use the following command syntax:

curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'rm -f /<filesystem path>/<file name>'\"}"

For example:

curl -sk -u admin:admin -H "Content-Type: application/json" -X POST https://192.168.1.100/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\" -c 'rm -f /shared/images/SomeFile'\"}"
