Known Issue

Upgrading to BIG-IP 11.3.0 may impact virtual servers configured with destination address settings that reference virtual address names.

This issue occurs when all of the following conditions are met:

  • Virtual addresses have been configured to have assigned names.
  • Virtual servers have been configured to reference the assigned names of virtual addresses as the destination address of the virtual server.
  • The BIG-IP system is upgraded to 11.3.0.

Note: Assigning names to virtual addresses can only be done with the Traffic Management Shell (tmsh) utility.

Impact

Connections load balanced by virtual servers may fail, because the destination address translation is no longer applied to these virtual servers.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H421533 or H421533-1 on the Diagnostics > Identified > High page.
  • After upgrading, connections to virtual servers appear to fail.
  • When using the BIG-IP Configuration utility to view the advanced virtual server configuration, you note that the Address Translation check box is clear.
  • When using the tmsh utility to list a virtual server configuration, you note that the virtual server has the translate-address disabled setting applied.

Workaround

To work around this issue, you can re-enable address translation for the virtual server(s). To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Enable Address Translation for an existing virtual server

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  2. Set translate-adddress to enabled for a virtual server by typinc the following command:

    modify /ltm virtual <virtual-server-name> translate-address enabled

  3. Save the change by typing the following command:

    save /sys config
