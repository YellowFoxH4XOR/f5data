Known Issue

The iControlPortal.cgi process on a BIG-IP-managed device may leak memory. This issue occurs when all of the following conditions are met:

  • The BIG-IP-managed device is running BIG-IP versions listed in the Applies To box.
  • The Enterprise Manager system is performing one of the following device management operations:
    • Device Discovery
    • Device Refresh
    • Verify Staged Changeset
    • Deploy Staged Changeset

Impact

  • The BIG-IP-managed device may reboot and temporarily fail to process traffic in the event of a severe memory exhaustion.
  • The Enterprise Manager system may fail to properly manage the BIG-IP-managed device

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The iControlPortal.cgi process memory allocation grows over time on the BIG-IP-managed device. You can monitor the memory usage for the iControlPortal.cgi process using the top utility. For example, using the top -p `pidof iControlPortal.cgi` command, you can observe from the following output that the iControlPortal.cgi process memory allocation grew from 32 MB to 791 MB over time:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    4587 root 20 0 53048 32m 21m S 0.0 0.5 0:00.23 iControlPortal.

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    4587 root 20 0 959m 791m 8060 S 0.0 11.4 2:55.89 iControlPortal.
  • The BIG-IP-managed device swap file usage may increase as the iControlPortal.cgi process memory allocation grows. You can monitor the system swap file usage using the top utility.
  • Over time, you may see the BIG-IP-managed device system performance degrade, and the system may eventually become unresponsive or reboot due to memory exhaustion.
  • The Enterprise Manager system fails to properly manage the BIG-IP-managed device and reports error messages in the /var/log/em file that appear similar to the following example:

    04010568:3: Error found on device <IP address> (UID: 0): getSlotInfo: iControl error: 'iControl::OperationFailed - primary code:16908289(0x1020001) secondary code: 1(0x1) string: Error generating boot image information'
    04072112:3: Could not get device information for address: <IP address>: Failed to Retrieve Device Information.

Workaround

There is no workaround. However, you can recover a BIG-IP-managed device that is suffering from the iControlPortal.cgi process memory leak by restarting the httpd process on the BIG-IP-managed device. To do so, perform the following procedure:

Impact of workaround: The Configuration utility of the BIG-IP-managed device will be temporarily unavailable until the httpd process has restarted successfully.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.
  2. Restart the httpd process by entering the following command:

    restart sys service httpd
