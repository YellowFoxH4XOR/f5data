Description

A BIG-IP will sometimes log the following message:

Mar 23 23:11:43 B7250-R14-S6.sea.pslab.local notice icrd_child[16836]: 16836,16839, RestServer, INFO,Connection idle too long fd:12

Environment

  • BIG-IP versions 13.x, 14.x, 15.x, 16.x, 17.x
  • iControl/REST

Cause

An icrd_child process is created for each unique user that connects to a BIG-IP to perform an icontrol/REST command. The icrd_child process stays active after completing a REST command, waiting for more iControl REST calls. If it does not receive anything within a predefined idle timeout, it terminates itself and logs "RestServer,INFO,Connection idle too long fd:12".

Recommended Actions

None as this is expected behavior and does not have any impact. 

Additional Information
Please note that an HA pair of BIG-IPs use (covertly) iControl REST to communicate each other.

You can see the transactions in the restjavad.0.log if debug level verbosity is increased. This happens hourly.
[F][2375][23 Mar 2020 23:10:37 UTC][8100/tm/shared/bigip-failover-state BigipFailoverStateWorker] step UPDATE_REST_LOCALHOST
[F][2376][23 Mar 2020 23:10:37 UTC][8100/tm/shared/bigip-failover-state BigipFailoverStateWorker] step UPDATE_REST_DEVICE_GROUP
[F][2377][23 Mar 2020 23:10:37 UTC][8100/tm/shared/bigip-failover-state BigipFailoverStateWorker] step COMPLETE_POLLING_CYCLE

After which you will see icrd_child log REST timeouts:

The timeouts are define in the configuration file under options section of /etc/icrd.conf: e.g.,

   "options" : {
      "transactionTimeoutSeconds" : 120,
      "transactionExecTimeoutSeconds" : 300,
      "heartbeatSeconds" : 300,
      "childLogLevel" : 2,
      "childIdleTimeout" : 320
   }
