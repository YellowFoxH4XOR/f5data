K000156708: Stale entries of iquery not cleared in GTM

Type
Support Solution
Published
2025-09-30
Updated
2025-09-30
Applies to
  • BIG-IP
  • BIG-IP DNS
Source

Description

Stale iQuery entries may appear in BIG-IP DNS (GTM) following activities such as certificate renewal, software upgrades, or IP address changes. When running the show gtm iquery command, duplicate or "not-connected" entries can be displayed for GTM servers. These entries often show "Server Type unknown" and "State not-connected," and are not cleared automatically from statistics.

Environment

  • Product: BIG-IP DNS (GTM)
  • Common triggers:
    • Certificate renewal on GTM or LTM devices
    • Code/software upgrade of GTM/LTM systems
    • IP address changes for GTM/LTM servers/devices
    • Forced iQuery reconnects via GUI or CLI

Cause

The iQuery daemon retains previous connection information after certain configuration changes (such as cert renewal, IP modification, or code upgrade). Old connection statistics and stale entries are not automatically cleared; this is expected system behavior until the relevant daemons are restarted.

Recommended Actions

  • To clear stale iQuery entries:
    Restart the iQuery daemons:
    bigstart restart gtmd (on DNS)
    bigstart restart big3d (on LTM)
    Restarting these daemons should not cause noticeable service interruption.

  • If stale entries persist after restarting daemons:
    Remove and re-add the affected GTM server from configuration.

  • As a best practice:
    Include iQuery daemon restarts in change management procedures following certificate renewals, code upgrades, or IP address changes.

  • For additional troubleshooting/reset device statistics via CLI:
    reset-stats gtm server <server_name> devices { <device_name> }

Please refer to F5 Knowledge Articles such as K73412117 for further details.

GUI Reconnect Option Limitation

Using the Reconnect option from the BIG-IP DNS (GTM) graphical user interface (GUI) to force an iQuery reconnection does not remove stale or old iQuery connections from statistics. This action may re-establish communication between GTM and LTM devices; however, any duplicate or "not-connected" entries will remain visible until the relevant services are restarted.
To fully clear these old connections, you must restart the iQuery daemons:
bigstart restart gtmd (on DNS)   bigstart restart big3d (on LTM)
