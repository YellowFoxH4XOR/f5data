K000137519: F5 gone offline with some crypto errors

Type
Support Solution
Published
2023-11-21
Updated
2023-12-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.1
Source
https://my.f5.com/manage/s/article/K000137519

Description

Device error: hsbe2 hsb_lbb0 hde1_crc_errs count 65535.
 

Environment

  • LTM
     

Cause

The HSB fell off the PCI bus and that's what caused all subsequent chaos.

 

Recommended Actions

In some rare circumstances, the High-Speed Bridge (HSB) device might fall or drop off of PCI bus, resulting in the BIG-IP system not being able to process traffic. The conditions that lead to HSB to fall off of PCI bus are unknown at this time. A reboot typically clears this condition.

 

Example:

Oct 25 02:32:45 f5net.com crit tmm[1918]: 01010025:2: Device error: hsbe2 hsb_lbb0 hde1_crc_errs count 65535.

 

Lspci outputs give it out as well:

06:00.0 Ethernet controller [0200]: F5 Networks Inc. Device [f5f5:001b] (rev ff) (prog-if ff)

!!! Unknown header type 7f

 

06:00.1 Ethernet controller [0200]: F5 Networks Inc. Device [f5f5:001c] (rev ff) (prog-if ff)

!!! Unknown header type 7f

 

06:00.2 Ethernet controller [0200]: F5 Networks Inc. Device [f5f5:001c] (rev ff) (prog-if ff)

!!! Unknown header type 7f

<...>

 

When this happens (PCI falls off the PCI bus) we typically recommend to perform an End User Diagnostic (EUD) Test ; if EUD fails then RMA. If EUD passes then monitor the unit and if this is ever seen again on the same unit then RMA the unit.

Something important to have in account. We have created BUG ID 989501, which would help greatly in such situation. The fix for it was introduced in later versions (15.1.10, 16.1.4 and 17.1.1) and it will ensure that, in the rare event the HSB falls off the PCI bus, dataplane_inoperable High Availability (HA) event will be triggered by overdog process (which monitors high availability (HA) table for failover action types of restart, restart-all, or reboot) and allow for system to be rebooted automatically to recover.
