Description

You want to create a V1 Secure Mesh Site CE but you are not sure about the steps.

 

Environment

  • F5® Distributed Cloud (XC) Console
  • VMware

Cause

You need to deploy a SMSv1 CE site in VMware

Recommended Actions

To deploy a Secure Mesh Site:

  1. Create a Site Token
  2. Create the CE Node or Nodes
  3. Approve the Registration of the Customer Edge (CE) on the F5® Distributed Cloud (XC) Console

 

Step 1: Create a Site Token

1. On the F5 XC Console go to Cloud and Edge Sites ->Manage -> select Site Management -> Site Tokens and create the token.

2. Add a unique name for your token in the Name field. 

3. Click Save and Exit to create token

4. Copy the token ID

5. Proceed with the creation of the CE Node.

 

 

Step 2: Create the CE Node/s

We proceed with the creation of the VM.

1. Select Deploy a virtual machine from an OVF or OVA file from the options listed.

2. Download the image from our official documentation.

3. Select the storage option that you want.

4. On the Deployment Options when selecting a network mapping you have to understand that:

  • It has to have access to internet
  • Has the appropriate DNS access
  • Permission to have access to the list of addresses and IPs from here: Firewall or Proxy Reference for Network Cloud

5. On Additional Settings you will find the set of parameters to enable the machine to boot up and request registration directly in your tenant. These settings also allow you to configure the static IP address. However, DHCP is used by default.

  • Hostname: Specify the hostname for this device - for example: master-0. Ensure that host names are distinct and unique in case you are installing nodes for multi-node site.
  • Token: Site token required for site generation (the one created on the first step on the F5 XC console). The token should be created prior to using it in site creation.
  • Admin Password: Enter the admin password and re-enter in the Admin Password confirm field.
  • Cluster Name: Set the cluster name.
  • Name for outside network interface: eth0. (IMPORTANT)
  • DHCP support for outside network interface: yes. By default, this is set to yes. If you want to configure static IP addresses, then set this to no.
  • Role for outside network interface: public. By default, this is set to public as the interface will have internet access.(IMPORTANT)
  • IP address/bitmask for network interface: empty by default. If DHCP was set to no, then you can configure your static IP address here, you have to know what mask is it.
  • Default gateway for outside network interface: empty by default. If DHCP was set to no, then you can configure the default gateway for your network here. Example: 10.1.1.254.
  • Route destination (destination network) for outside network interface: empty by default. If DHCP was set to no, then you can configure the destination here. Because this is the default gateway, we can use 0.0.0.0/0. For specific setups, you can change the default destination.
  • Primary DNS: empty by default. If DHCP was set to no, then you can configure your DNS Server here. Example: 8.8.8.8.
  • Secondary DNS: empty by default. If DHCP was set to no, then you can configure your secondary DNS server here. Example: 8.8.4.4.
  • Certified Hardware: The supported options are as follows. The default option is vmware-regular-nic-voltmesh, and this supports 2 interfaces (ensure that both eth0 and eth1 are available). However, this is loaded by default with eth0 interface set as a dedicated site local outside interface. The other interface is an optional regular interface and can be only configured from Console using fleet after the site is provisioned, you can check the "Create a Fleet" documentation.
    • vmware-voltmesh - single service level objective eth0 interface hardware.
    • vmware-voltstack-combo - for managed k8s and vk8s use cases.
    • vmware-regular-nic-voltmesh - 2 virtual NICs, when eth0 is SLO dedicated and eth1 is binded as regular interface, which can be optionally configured from VoltConsole post registration.
  • Latitude: Enter latitude. This can also be specified during registration in Console. (0 is not allowed)
  • Longitude: Enter longitude. This can also be specified during registration in Console. (0 is not allowed)

6. After entering in all the information above the wizard will be completed.

Step 3: Approve the Registration of the CE on F5 Distributed Cloud (XC) Console

If, after completing all the steps above, you go to Cloud and Edge Sites > Manage > Site Management > Registrations and not see your CE there for a pending approval it means that:

  • The site has no access to internet
  • The site does not have DNS
  • The site is blocked by a firewall

To approve:

1. Approve: the registration by clicking the checkmark

2. The Image above is an example of a CE Cluster with HA. If you deployed a Single Node you will only see 1 CE.

3. After clicking the checkmark a "Registration Acceptance" will pop up with the "passport" of the registration.

4. Review it and accept it. Important!: For a Single node CE, Cluster Size must  be “1” and for Multi-Node CE (CE Cluster with HA), Cluster size must be “3”.

NOTE: With CE cluster with HA, all 3 nodes have to be approved and present before CE cluster provisioning started.

 

Conclusion

The provisioning should not take more than 15 to 20 minutes for a single node creation on-prem or DC, and from 20 to 25 min for a Cloud single node (AWS, AZ, GCP).

More than 30 min means there is a problem.

 

Additional Information

Recommendation

If you have issues creating a Cluster of 3 Nodes, try first to deploy a Single Node CE. If that is also failing please follow the guide of  How to collect debug information for cloud and on-premises Customer Edge sites and raise a ticket to support with the debug file attached.
