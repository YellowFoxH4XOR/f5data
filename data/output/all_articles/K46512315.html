Topic

You should consider using this procedure under the following condition:

  • You want to mitigate Transport Layer Security (TLS) handshake attacks.

Description

TLS handshake attacks target the processing power of the web server by initiating false TLS handshakes and forcing the server to perform multiple decryption operations over a short period of time. Small-number clients can effectively perform TLS attacks when using cipher suites (RSA, for example), in which the computational cost of the handshake is significantly higher for the server than for the client.

The TLS fingerprinting feature is an attack detection and mitigation mechanism which identifies signature pattern anomalies found in the TLS handshake and drops traffic that matches a particular signature pattern. This behavior allows you to identify bad actors without the overhead of completing an encrypted session. When you enable TLS fingerprinting, the fingerprinting engine parses the ClientHello message and inspects the following TLS handshake parameters:

  • TLS version
  • Cipher suites
  • Compression options
  • TLS extensions
  • Elliptic curve extensions

The fingerprinting engine identifies anomalous patterns in the ClientHello message and compares the patterns against a valid TLS data set, minimizing the possibility of false positive violations. After a signature is generated, further ClientHello messages matching the signature generate an alert or are dropped, depending on feature configuration.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility and TMOS Shell (tmsh).
  • You have configured an HTTPS virtual server on the system.

Procedures

Configuring TLS fingerprinting

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Important: For BIG-IP ASM 14.1.0, you can access the TLS fingerprinting signatures configuration section only when you had previously selected Use Legacy Application Dos view in the HTTP Properties configuration pop-up.

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Security > DoS Protection > Protection Profiles.
  3. Select the Create button.
  4. For Profile Name, type a name for the profile.
  5. Under Application Security, select Behavioral & Stress-based Detection.
  6. For Behavior Detection and Mitigation, select Edit.
  7. Select the TLS fingerprinting signatures check box.
  8. For Mitigation select the appropriate method.
  9. Define additional settings for the DoS profile as needed.
  10. Select the Finished button.

Associating the DoS Protection profile with the virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the name of the HTTPS virtual server.
  4. Hover over the Security tab and select Policies.
  5. For DoS Protection Profile, select Enabled.
  6. For Profile, select the DoS profile created in the previous procedure.
  7. Select the Update button.

Changing the mitigation mode

By default, when the system identifies signature pattern anomalies, it silently drops the connection. You can change the mitigation mode and force the system to send a reset (RST) when the traffic matches a signature pattern. To change the mitigation mode from drop to reset, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To change the mitigation mode to reset, type the following command:

    modify sys db adm.mitigation.accelerated.signatures.drop.mode value reset
