Known Issue

This is the result of a known issue. Installing a UCS file on a BIG-IP system may cause LACP to temporarily remove interfaces from trunk aggregation. Installing a UCS archive file generates a large amount of MCP messages between the bcm56xxd and mcpd processes. The bcm56xxd main thread processes MCP messages and maintains a list of timers. The large amount of MCP messages causes the LACP packet register to expire earlier. As a result, the system drops incoming LACP packets.

When this issue occurs, error messages that appear similar to the following example may be logged to the /var/log/ltm file:

lacpd[2030]: 01160024:4: warning: no receive on 1.4 for 45s (timeout=90s)
lacpd[2030]: 01160024:4: warning: no receive on 1.13 for 45s (timeout=90s)
lacpd[2030]: 01160016:6: Interface 1.4, link admin status: enabled, link status: up, duplex mode: full, lacp operation state: down
lacpd[2030]: 01160010:6: Link 1.4 removed from aggregation
lacpd[2030]: 01160016:6: Interface 1.13, link admin status: enabled, link status: up, duplex mode: full, lacp operation state: down
lacpd[2030]: 01160010:6: Link 1.13 removed from aggregation

F5 Product Development is tracking this issue as CR139391.

This issue does not exist in BIG-IP version 10.x.

This issue has been fixed in Hotfix-BIGIP-9.4.8-407.0-HF4, which has been issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
