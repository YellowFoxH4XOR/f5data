Known Issue

Persistence may fail when a persistence profile is configured with either Match Across Services, Match Across Virtual Servers, or Match Across Pools enabled.

This issue occurs when the following conditions are met:

  • You have a CMP-compatible BIG-IP system.
  • The virtual server is configured with a persistence profile that has one of the following options enabled:

    • Match Across Services
    • Match Across Virtual Servers
    • Match Across Pools

    When the previously described conditions are met, and a client makes a subsequent connection that is handled by a different TMM instance than the one that handled the client's initial connection, the BIG-IP system attempts to add a duplicate persistence record. Because a persistence record already exists for the client's initial connection, the connection is stopped.

    Note: The Deploying F5 with Microsoft Exchange Server 2010 (BIG-IP 11.x) deployment guide makes extensive use of the Match Across settings.

    Impact

    The BIG-IP system may stop some persisted connections.

    Symptoms

    As a result of this issue, you may encounter one or more of the following symptoms:

    • BIG-IP iHealth lists Heuristic H395224 on the Diagnostics > Identified > Medium screen.
    • Clients experience intermittent connection resets.
    • The system creates incorrect persistence records.
