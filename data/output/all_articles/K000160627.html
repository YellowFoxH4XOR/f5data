K000160627: GTM is not processing DNS queries for the Wide IP

Description

BIG-IP DNS listener stops processing and responding to DNS queries when all members of the configured last-hop-pool become unavailable. Symptoms include DNS resolution failures, client timeouts, and log messages such as "No members available for pool" and "Inet port exhaustion."

Environment

  • DNS listener virtual server with a default pool and last-hop-pool configured
  • Pool members are DNS servers monitored by health monitors
  • SNAT automap enabled
  • High DNS traffic spike observed prior to issue

Cause

A spike in DNS traffic overwhelmed the backend DNS servers in the last-hop-pool, causing health monitors to mark all pool members down. As a result, the BIG-IP dropped incoming DNS queries at the virtual server level due to the last-hop-pool being unavailable. SNAT port exhaustion occurred as connections to unresponsive pool members accumulated, further contributing to the issue.

Recommended Actions

  • Investigate and address the capacity and performance of backend DNS servers to ensure they can handle peak loads.
  • Consider removing the last-hop-pool and default pool from the DNS listener virtual server if fallback to other DNS resolution methods (Wide IP, DNS Express, DNS cache, local BIND) is desired when backend servers are unavailable.
  • If SNAT automap is used, consider configuring a larger SNAT pool to reduce the risk of port exhaustion.
  • Review and tune health monitor settings to avoid unnecessary pool member flapping during transient load spikes.
  • Ensure the DNS profile's unhandled-query-action is set appropriately for your environment.
