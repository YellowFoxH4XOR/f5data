Topic

BIG-IP Virtual Edition (VE) instances can provide improved throughput using Single Root I/O Virtualization (SR-IOV) to interact directly with underlying Network Interface Card (NIC) adapters.

Firmware and PF driver versions have been shown to be backward compatible and BIG-IP is expected to behave properly as long as driver and firmware versions newer than the listed versions are being used. An older PF driver/firmware version might behave as desired, but this cannot be guaranteed and will not be supported.

Note: With SR-IOV, one physical NIC can appear as several virtual NICs as described later in the article.

Recommendations

To a Virtual Machine (VM), an SR-IOV based Virtual Function (VF) appears as an ordinary NIC. The NIC is replicating itself as a PCIe device identical to the physical NIC. The ports off the physical NIC are called a Physical Function (PF). The switch port connected to the PF dictate the VLANs, DHCP, and other network functions available to the VFs on a one-to-many relationship. One PF can have between 8 and 512 VFs depending on the NIC model.

Useful commands on the hypervisor OS

For more information on useful commands to run on the hypervisor OS, refer to F5 BIG-IP Virtual Edition on Clouddocs and select the appropriate hypervisor on the left panel. For instance, for KVM and the Intel E810 series NICs, refer to KVM: Configure Intel X710 - E810 series NICs for High Performance.

For example, after running lshw -c network –businfo on the hypervisor OS, it indicates the NIC PCI Bus location under Bus Info; additionally, the Device name, Class, and Description is provided. From the Description field you can determine if the PCI Device is a VF, because it is typically appended to the PF name. In the following Hypervisor-OS output, enp24s0f0 and enp24s0f1 are the PF’s, where enp24s0f2 through enp24s0f5 are VF’s. When BIG-IP VE is actively using a VF, the Device name is often blank, as shown in the following example output: 

[root@OS ~]# lshw -c network -businfo
Bus info               Device        Class           Description
==========================================================================================================
pci@0000:18:00.0       enp24s0f0     network         MT27800 Family [ConnectX-5]
pci@0000:18:00.1       enp24s0f1     network         MT27800 Family [ConnectX-5]
pci@0000:18:00.2                     network         MT27800 Family [ConnectX-5 Virtual Function]
pci@0000:18:00.3       enp24s0f3     network         MT27800 Family [ConnectX-5 Virtual Function]
pci@0000:18:00.4       enp24s0f4     network         MT27800 Family [ConnectX-5 Virtual Function]
pci@0000:18:00.5       enp24s0f5     network         MT27800 Family [ConnectX-5 Virtual Function] 

Note: The NIC PCIe Bus location is different from the PCIe Device ID; the latter refers to only the type of NIC, where the bus location refers to the unique PCI bus enumeration location, which is often used to assign VFs to a VM. 

Upon VM startup initialization, BIG-IP VE looks to the NIC VF PCIe ID, which is different from the PF PCIe ID. Often multiple PFs from the same manufacturer use a common VF driver, which results in a common VF PCIe ID. The first four digits of a PCIe ID indicate the manufacturer, while the last four digits represent the device itself.  

To determine the NIC VF PCIe ID, perform the following procedure: 

  1. Install and configure the appropriate drivers per the directions in the following documents:

    Enable SR-IOV and KVM: Configure Mellanox ConnectX-5 for High Performance 

  2. Once you have enabled VFs, enter the following command:

    lspci -nn | grep -Ei "Virtual" 

    The PCIe ID is in brackets. For example: [0123:4567] 

  3. At the BIG-IP VE CLI, verify that the correct driver is loaded by entering the following commands:

    • tmctl -d blade tmm/device_probed 

      You may observe output similar to the following: 

      [root@BIG-IP_VE: Active: Standalone] config # tmctl -d blade tmm/device_probed
      pci_bdf             pseudo_name        type         available_drivers      driver_in_use
      ---------------     ---------------    ---------    ------------------     ---------------
      0000:01:00.0                           F5DEV_PCI    xnet, sock, 
      0000:05:00.0        1.3                F5DEV_PCI    mlxvf5, xnet,          xnet
      0000:08:00.0        1.4                F5DEV_PCI    mlxvf5, xnet,          xnet
      0000:09:00.0        1.1                F5DEV_PCI    mlxvf5, xnet, sock,    xnet
      0000:0a:00.0        1.2                F5DEV_PCI    mlxvf5, xnet, sock,    xnet
    • tmctl -d blade tmm/xnet/device_probed

      You may observe output similar to the following: 

      [root@BIG-IP_VE: Active: Standalone] config # tmctl -d blade tmm/xnet/device_probed
      id                  available_drivers      driver_selected  driver_in_use

      0000:08:00.0        mlxvf5, dpdk,          mlxvf5           Yes

      tmctl -d blade xnet/device_probed
