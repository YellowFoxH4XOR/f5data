K2691: Synchronization of dynamic persistence data

Topic

Prior to version 4.5, the 3-DNS Controller synchronized persistence information (using the timer_persist_cache option) as infrequently as once per hour. Starting with version 4.5, the 3-DNS Controller synchronizes dynamic persistence information at the same interval as the TTL for the pool, which has dynamic persistence enabled.

This method is very effective; however, in rare circumstances it is possible that, because the TTL and time to dynamic persistence synchronization are the same value, a user may be able to make another DNS request before the persistence information has been synchronized.

Although this condition should rarely be an issue, starting in version 4.5 PTF-04, the 3-DNS Controller includes a new global option called sync_persist_requests, which you can use to specify a global interval for synchronizing dynamic persistence information. This option allows you to configure dynamic persistence synchronization at an arbitrary interval that is not bound to the same value as the pool TTL.

Important: You can only configure this option by manually editing the wideip.conf file. If you are not comfortable modifying the wideip.conf, contact F5 Technical Support for assistance.

The sync_persist_request option value is written in seconds, such as 60. If the value ends with a letter m, the value is interpreted in minutes.

Note: The value cannot be less than 5 seconds.

Following are two examples of the sync_persist_request option set in the wideip.conf file:

Example 1:

 globals {
sync_persist_requests   60
}

Example 2:

 globals {
sync_persist_requests   1m
}
