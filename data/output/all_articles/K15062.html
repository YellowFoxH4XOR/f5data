Topic

You should consider using this procedure under the following condition:

  • You want to associate multiple Secure Sockets Layer (SSL) certificate/key pair types with an SSL profile.

Description

Starting in BIG-IP 11.5.0, you can associate multiple SSL certificate/key pairs of differing algorithm types with a single SSL profile. This configuration allows the virtual server to accept SSL connections from clients supporting newer cryptographic algorithms, such as Elliptic Curve Cryptography (ECC), while continuing to accept connections from clients supporting traditional algorithms, such as RSA. The BIG-IP SSL profile supports associating one SSL certificate/key pair from each of the following algorithms.

AlgorithmDescription
DSA (Digital Signature Algorithm)Public key algorithm with a secret key that is used for digital signatures.
ECDSA (Elliptic Curve Digital Signature Algorithm)Digital signature algorithm (DSA) that uses ECC. ECC technology is harder to break and shows better performance and response time than an RSA-based key.
RSA (Rivest Shamir Adleman Algorithm)Public key encryption algorithm. The SSL profile requires an RSA certificate/key pair

Note: Prior to BIG-IP 14.1.0, you must have an RSA certificate/key pair assigned to an SSL profile. You can only associate other algorithms such as DSA/ECDSA on top of the RSA certificate/key pair assignment. For example, you can have RSA or RSA+DSA or RSA+DSA+ECDSA; however, you cannot have the combination of DSA or DSA+ECDSA without RSA. Starting in BIG-IP 14.1.0, you can have a stand-alone DSA or ECDSA certificate/key pair without a base RSA certificate/key pair.

Note: In cipher suite names, DSA is called DSS (Digital Signature Standard). For example, DHE-DSS-AES128-SHA. DSS standard (FIPS 186-4) includes more than the DSA algorithm: for example, it also includes ECDSA and RSA.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the Configuration utility or the TMOS Shell (tmsh).
  • You understand various certificate/key types.

Procedures

  • Creating a self-signed SSL certificate or CSR
  • Configuring the SSL profile to support multiple SSL certificate/key pair types

Using the Configuration utility to create a self-signed SSL certificate or CSR

You can use the BIG-IP system to create new self-signed SSL certificates and keys or to generate a new certificate signing request (CSR) for RSA, DSA, or ECDSA certificates. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Certificate Management > Traffic Certificate Management > SSL Certificate List.

    Note: In BIG-IP 12.1.2 and earlier, navigate to System > File Management > SSL Certificate List.

  3. Click Create.
  4. Type a name for the certificate.
  5. Under Certificate Properties, for Issuer, click Self (for a self-signed certificate) or Certificate Authority (for a CA certificate).
  6. Configure Common Name and the other certificate settings.
  7. Under Key Properties, in the Key Type list, click the appropriate key type.
  8. For Size, click the appropriate key size.
  9. Click Finished.

    If you chose Certificate Authority from the Issuer list in step 5, the Certificate Signing Request page displays. You can download the CSR request into a file on your system by performing the remaining steps:

  10. To copy certificate, block and copy the text from the Request Text box or for Request File click Download <certificate name>.
  11. For Certificate Authorities, click a Certificate Authority (CA) name.
  12. After the website for the CA displays, follow the instructions on the website for processing the generated request file.
  13. Click Finished.

Using tmsh to create a self-signed SSL certificate or CSR

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Create the a self-signed SSL certificate and key pair using the following command syntax:

    create /sys crypto key <key_name> gen-certificate <key_options> lifetime <value>

    For example, to create a self-signed certificate and key pair called example, with a lifetime of 10 years, type the following command, separating each domain name with a comma:

    create /sys crypto key example gen-certificate common-name "Example Inc." country "US" lifetime 3650

    Additionally, to generate a certificate signing request, with key pair, add the gen-csr option to the command.

    For example:

    create /sys crypto key example gen-certificate gen-csr common-name "Example Inc." country "US" lifetime 3650

  3. Save the change by typing the following command:

    save /sys conf

Configuring the SSL profile to support multiple SSL certificate/key pair types

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

BIG-IP 12.1.0 and later

Using the Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Click Create.
  4. Type a name for the SSL profile.
  5. For Configuration, click Advanced.
  6. Select the Custom check box.
  7. For Certificate Key Chain, click Add.
  8. On the Add SSL Certificate to Key Chain pop-up window, for Certificate and Key, click the SSL certificate and key pair, then click Add.
  9. Repeat steps 7 and 8 for each SSL certificate and key pair type that you want to associate with the SSL profile.

    Note: You cannot associate more than one of the same certificate/key pair types with the profile. Prior to BIG-IP 14.1.0, the profile must have an RSA certificate/key pair. Starting in BIG-IP 14.1.0, you can have a standalone DSA or ECDSA certificate/key pair without a base RSA certificate/key pair.

  10. If needed, modify the Ciphers string to accommodate ciphers not supported by the default string. For example, to configure the profile to allow the default ciphers and ECDHE-ECDSA-* ciphers, modify the cipher string as follows:

    DEFAULT:ECDHE_ECDSA

  11. Complete the remaining settings for the SSL profile.
  12. Click Finished.

Using tmsh

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Create a SSL profile using following command syntax:

    create /ltm profile client-ssl <profile_name> cert-key-chain add { <cert-key-chain name> { cert <certificate name> key <key name> chain <chain certificate name> } }

    For example, to create a SSL profile called example, with a certificate key chain named rsa, a certificate named rsa.crt, a key named rsa.key, and a chain certificate named ca-bundle.crt, type the following command:

    create /ltm profile client-ssl example cert-key-chain add { rsa { cert rsa.crt key rsa.key chain ca-bundle.crt } }

    To add certificate, key, and chain named ecdsa with a certificate named ecdsa.crt , and key named ecdsa.key, type the following command:

    modify /ltm profile client-ssl example cert-key-chain add { ecdsa { cert ecdsa.crt key ecdsa.key } }

    If needed, modify the ciphers strings using following command syntax:

    modify /ltm profile client-ssl example ciphers DEFAULT:ECDHE_ECDSA

  3. Save the change by typing the following command:

    save /sys conf

BIG-IP 12.0.0 and earlier

Using the Configuration utility

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Profiles > SSL > Client.
    3. Click Create.
    4. Type a name for the SSL profile.
    5. For Configuration, click Advanced.
    6. Select the Custom check box.
    7. For Certificate Key Chain, click Add. In the Add SSL Certificate Key Chain pop-up window, click the SSL Certificate and Key pair you want to use.
    8. Click Add.
    9. Repeat steps 7 and 8 for each SSL certificate and key pair type that you want to associate with the SSL profile.

      Note: You cannot associate more than one of the same certificate/key pair types with the profile. Prior to BIG-IP 14.1.0, the profile must have an RSA certificate/key pair. Starting in BIG-IP 14.1.0, you can have a standalone DSA or ECDSA certificate/key pair without a base RSA certificate/key pair.

    10. If needed, for Ciphers, modify the string to accommodate ciphers not supported by the default string. For example, to configure the profile to allow the default ciphers and ECDHE-ECDSA-* ciphers, modify the cipher string as follows:

      DEFAULT:ECDHE_ECDSA

    11. Complete the remaining settings for the SSL profile.
    12. Click Finished.

    Using tmsh

    1. Log in to tmsh by typing the following command:

      tmsh

    2. Create a SSL profile by entering the following command syntax:

      create /ltm profile client-ssl <profile_name> cert-key-chain add { <cert-key-chain name> { cert <certificate name> key <key name> chain <chain certificate name> } }

      For example, to create a SSL profile called example, with a certificate key chain named rsa, a certificate named rsa.crt, a key named rsa.key, and chain certificate named ca-bundle.crt, type the following command:

      create /ltm profile client-ssl example cert-key-chain add { rsa { cert rsa.crt key rsa.key chain ca-bundle.crt } }

      To add certificate, key and chain named ecdsa with a certificate named ecdsa.crt and key named ecdsa.key, type the following command:

      modify /ltm profile client-ssl example cert-key-chain add { ecdsa { cert ecdsa.crt key ecdsa.key } }

      If needed, modify the ciphers strings. For example:

      modify /ltm profile client-ssl example ciphers DEFAULT:ECDHE_ECDSA

    3. Save the change by typing the following command:

      save /sys conf

    You can now associate the SSL profile with the virtual server.
