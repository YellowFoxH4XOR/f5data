Description

You notice in the tmsh list ltm monitor https output is showing old certificate and key files that have expired or are no longer in use.

ltm monitor https /Common/my_https_monitor {
    app-service none
    cert /Common/myoldcert.crt  <---- old cert is redundant (unable to see in GUI)
    cipherlist AES128-SHA256  <---- cipherlist is redundant (unable to see in GUI)
    compatibility enabled
    defaults-from /Common/https
    description none
    destination *:*
    interval 30
    key /Common/myoldkey.key  <---- old key is redundant (unable to see in GUI)
    manual-resume disabled
    partition Common
    password ***scrubbed***
    recv Health Check Status = 200
    recv-disable none
    reverse disabled
    send "GET /HealthCheck\r\n HTTP/1.1\r\nHost: \r\nConnection: close\r\n\r\n"
    ssl-profile /Common/my_https_monitor_ssl_profile    <---------- New SSL profile contains cert, key and cipherlist
    time-until-up 91
    timeout 91
    transparent disabled
    up-interval 0
    username none
}

Note: In case the cipherlist, cert and key is not specified in the ssl-profile "my_https_monitor_ssl_profile", then BIG-IP will revert back to using the objects marked as redundant.  To avoid confusion, the best practice is to manage and update the cipherlist, cert and key objects in the ssl-profile, "my_https_monitor_ssl_profile" in the above example.

Environment

  • After upgrade to BIG-IP v13.1+
  • HTTPS monitors

Cause

ID651067: SSL/TLS-based monitors now use ServerSSL profiles

Recommended Actions

The redundant parameters (cert, key and cipherlist) can be safely ignored since the SSL Profile is in effect.

However you may wish to remove them from the configuration using the steps outlined below:
  1. Identify https monitor objects using the redundant certificate parameter:

    tmsh list ltm monitor https | grep 'cert /' -B2 | grep 'ltm monitor' | awk '{print $4}' | sort

  2. Identify the redundant cert and key names:

    tmsh list ltm monitor https | grep 'cert /' | awk '{print $2}' | sort | uniq
    tmsh list ltm monitor https | grep 'key /' | awk '{print $2}' | sort | uniq

  3. Remove the redundant certificate, key and cipherlist parameters from the monitor objects (the actual parameters in use are stored in the SSL profile):

    tmsh modify ltm monitor https <MONITOR_OBJECT_NAME> cert none
    tmsh modify ltm monitor https <MONITOR_OBJECT_NAME> key none
    tmsh modify ltm monitor https <MONITOR_OBJECT_NAME> cipherlist none

  4. Delete old certificate and keys from the filestore:

    tmsh delete sys crypto cert <CERT_NAME>.crt
    tmsh delete sys crypto key <KEY_NAME>.key

  5. Save the changes to disk

    tmsh save sys config
