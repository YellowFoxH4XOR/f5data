Description

Application slowness can be observed and suspected to be caused by the BIG-IP when the pool member (back-end server) is delayed in its responses.

Environment

  • BIG-IP

Cause

Pool member response time is visibly slow when analyzing the packet captures from the Server-side. 

38    2021-10-17 14:18:45.667812    10.1.1.1     10.1.1.2        HTTP    593        IN  s1/tmm1 : POST /test/web/xxx HTTP/1.1  (application/x-www-form-urlencoded)
39    2021-10-17 14:18:45.667821    10.1.1.3       10.1.1.4        HTTP    605        OUT s1/tmm1 : POST /test/web/xxx HTTP/1.1  (application/x-www-form-urlencoded)
46    2021-10-17 14:19:03.342411    10.1.1.4      10.1.1.3         HTTP    463        IN  s1/tmm1 : HTTP/1.1 200 OK  (text/html)
47    2021-10-17 14:19:03.342431    10.1.1.2      10.1.1.1       HTTP    1701       OUT s1/tmm1 : HTTP/1.1 200 OK  (text/html)

If you look at the screenshot above, packets 38 and 39 shows POST at 14:18:45.
This POST was coming from client 10.1.1.1 going to the virtual server destination IP 10.1.1.2 (Packet 38).
Now the BIG-IP immediately sent this POST to the pool member 10.1.1.4 (backend server) coming from the Self-IP of the BIG-IP (Packet 39).
Then, the next response from the pool member or backend server 10.1.1.4 is at 14:19:03 (Packet 46).
This clearly shows a delay of 18 seconds from the pool member 10.1.1.4 (backend server).

Without checking the packet capture above, one might think that the delay was caused by the BIG-IP.
In fact it's the backend server that is experiencing slowness and all traffic load balanced to this pool member will be experiencing slow application speed. 

Recommended Actions

  • Run a test and capture the packets when traffic can be directed to the backend server directly without the BIG-IP and compare the result of the 2 pcaps. 
  • You can disable the pool member experiencing slowness using this KB as a guide: K13310: Disabling nodes or pool members for maintenance (11.x - 16.x)
  • Remove the persistence entries for that pool member using this KB as a guide: K55632517: Delete persistence entry
