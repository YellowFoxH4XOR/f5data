K000148053: What is the Custom Error Response feature?

Published

Applies to

Source

Description

Custom Error Responses feature allows users to create their own responses for the error, unsupported protocols, security events that are triggered only on Distributed Cloud (XC) L7 load balancer.

Environment

  • F5® Distributed Cloud Console
  • HTTP Load balancer  

Cause

Distributed Cloud HTTP Load Balancer can generate multiple of different error responses, such as:

  • application servers unavailable (503)
  • request rate limit threshold hit (429)
  • blocking application firewall violation identified (403)
  • internal communication problems between XC L7 Load Balancer
  • additional services that process requests (502)
  • HTTP version not supported by XC L7 Load Balancer (505)
  • and so on.

Custom Error Responses apply only to responses generated by the XC Load Balancer and attached services such as WAF, Service Policies, DDoS protection, and the Envoy proxy itself.  Custom Error Responses do NOT apply to responses from the origin application, which are passed through to the downstream client without modification.

Recommended Actions

To configure Custom Error Responses:

1. Go to More Options section in Distributed Cloud (XC) Load Balancer configuration Dashboard. 

2. Under Custom Error Responses click Configure

HTTP Load Balancer comes with Default Error Pages which structures are as simple as possible. Error Responses should be optimized to the required content, to not to create unnecessary response traffic. 

Here an example of Default Error Page for the application servers unavailable event (error code: 503) generated by HTTP Load Balancer:

# curl -k https://example.com/
<html><head><title>Error Page</title></head> 
<body>The requested URL was rejected. Please consult with your administrator.<br/><br/> 
Your support ID is dddd3dcc-c99b-4522-bde6-abcd123456<h2>Error 503 - Service Unavailable</h2>F5 site: pa4-par <br/><br/><a href='javascript:history.back();'>[Go Back]</a></body></html>

And error message for the same event when Disable Default Error Pages option is marked. 

# curl -k https://example.com/ 
upstream connect error or disconnect/reset before headers. reset reason: connection failure, transport failure reason: delayed connect error: 111

It is recommended to keep Default Error Pages enabled or define Custom Error Response pages. It is also recommended to use {{request_id}} variable in the response. That request id is useful in finding the reason of error code generated by XC L7 Load Balancer. 

Note: XC Application Firewall has its own configuration section where Custom Error Response and Code can be defined. 

 

Testing configuration examples

Backend service unavailable and 503 Custom Error Response

1. Verify if your application is available

# curl -k https://example.com/
<html><head><title>example.com</title></head>
<body>Welcome</body></html> 

2. Stop the http service on origin servers

3. Verify if application is unavailable

# curl -k https://example.com/ 

<html><head><title>Error Page</title></head> 

<body>The requested URL was rejected. Please consult with your administrator.<br/><br/>

Your support ID is 76f9881c-f410-439a-9878-abcdf45412<h2>Error 503 - Service Unavailable</h2>F5 site: pa4-par <br/><br/><a href='javascript:history.back();'>[Go Back]</a></body></html>

4. Configure Custom Error Response

 

5. Verify if your application is unavailable with new Error Response message

# curl -k https://example.com/ 
<html><head><title>503 Error Page</title></head> 
<body>Error Code: 503</body></html>
 

Rate limiting and error code 429 Custom Error Response 

1. Configure Rate Limiter 

2. Verify if requests are rate limited

# curl -k https://example.com/ 
<html><head><title>Error Page</title></head> 
<body>The requested URL was rejected. Please consult with your administrator.<br/><br/> 
Your support ID is 8378eed4-dcb0-4c15-88dc-ababchd45612<h2>Error 429 - Too Many Requests</h2>F5 site: pa4-par<br/><br/><a href='javascript:history.back();'>[Go Back]</a></body></html>

3. Configure Custom Error Response 

 

4. Verify if requests are rate limited with new Error Response. 

 

# curl -k https://example.com/ 
<html><head><title>Error Page</title></head> 
<body>You are rate limited</body></html> 

 

Service policy to deny traffic and error code 403 Custom Error Response 

1. Configure Service Policy to block incoming requests.

2. Verify if requests are blocked

# curl -k https://example.com/ 

<html><head><title>Error Page</title></head>

<body>The requested URL was rejected. Please consult with your administrator.<br/><br/>

Your support ID is 5e49e1c8-d1ae-4684-8b77-78e1764c2cfa<h2>Error 403 - Forbidden</h2>F5 site: pa4-par<br/><br/><a href='javascript:history.back();'>[Go Back]</a></body></html>

 

3. Configure Custom Error Response

 

 

4. Verify if requests are blocked with new Error Response. 

# curl -k https://example.com/ 
<html><head><title>Error Page</title></head> 
<body>You are blocked by service policy</body></html> 

 

5. Configure generic Custom Error Response for all 4xx error codes. 

6. Verify if requests are blocked with new generic Error Response. 

# curl -k https://example.com/
<html><head><title>Error Page</title></head> 
<body>Client Error Response</body></html>

 

Application server responding with error code 406

1. Configure application server to respond with 406 error code

# cat index.php 
<?php 
http_response_code(406); 
?> 

 

2. Keep the same configuration of Custom Error Response

3. Check what the response message returned

# curl -k https://example.com/ 
# curl -k https://example.com/ -I 
HTTP/2 406 
server: volt-adc 
date: Thu, 23 Feb 2023 14:28:13 GMT 
content-type: text/html; charset=UTF-8 
x-envoy-upstream-service-time: 154
x-volterra-location: pa4-par

 

As expected, you should not receive the message defined in Custom Error Response, as XC L7 Load Balancer is not interfering with the error codes returned by application servers.

Important: If you not add the other errors you will get your request IDs flagged and blocked with the error "VIOL_HTTP_RESPONSE_STATUS"
