K000149822: Unable to decrypt traffic for a non-standard port with Wireshark

Type
Support Solution
Published
2025-02-20
Updated
2025-02-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000149822

Description

You cannot decrypt traffic in Wireshark despite adding the .pms file in TLS protocol preferences. You have SSL offloading or SSL bridging configured for a virtual server. The virtual server's or backend servers' port is not usually associated with TLS.

Environment

  • Packet Capture
  • Wireshark
  • Port other than 443 configured for TLS

Cause

By default, Wireshark sees only traffic to and from port 443 as TLS.

Recommended Actions

  1. Go to Edit > Preferences > Protocols > HTTP.
  2. Add the non-standard port used for TLS communication by your virtual server or your backend servers to SSL/TLS Ports.
  3. You should be able to see the decrypted traffic now.

None.
