K92243357: Use of silos for administrative partitioning may result in object duplicity

Type

Published
2021-11-18
Updated
2026-08-12
Status
Legacy Content
Applies to

Source

Description

When silos are used for administrative partitioning of your individual environments, issues with system corruption may result.  You may see duplicate objects, for instance.

Environment

  • Big IQ, with silos used for administrative partitioning

Cause

Silos were never intended to be used for the long term - they were always only intended to be used for temporary administrative work.  

Recommended Actions

  1. Log in to Big IQ as root or an administrative user.  Ensure you are in bash when you log in.
  2. Save your current working environment, in case you must restore:
    1. tmsh save sys ucs pre-deletion.ucs
  3. Run the following, and repeat until item 2 shows zero:
    1. for i in $(restcurl "/shared/index/config?%24filter=cm/silo%20eq%20'silo_frccvddev01'&category=working-config&inflate=false" | jq -r .items[] | cut -d"/" -f 5-); do restcurl -X DELETE ${i}; done
    2. restcurl "/shared/index/config?%24filter=cm/silo%20eq%20'silo_frccvddev01'&category=working-config&inflate=false" | jq .totalItems

Additional Information

Going forward, note that you should not use silos for administrative partitioning under any circumstances whatsoever.  Reserve silo usage for any administrative work that requires you to segregate a Big IQ object from the rest of the environment long enough to make the needed modifications.
