Topic

You should consider using this procedure under the following condition:

  • You want to migrate a vCMP guest to a new vCMP host running on a different platform.

Description

The vCMP feature allows you to provision and manage multiple instances of the BIG-IP software on a single hardware platform. The vCMP host is the system-wide hypervisor that runs BIG-IP instances, known as guests. vCMP guests are instances of the BIG-IP software that you create on the vCMP host for the purpose of processing application traffic. The guest instances contain the local traffic objects, such as virtual servers, pools, and monitors.

If you need to migrate a vCMP guest configuration to a new vCMP host running on a different platform, you must use the platform-migrate TMOS Shell (tmsh) option. The platform-migrate option ignores the configuration items specific to a particular platform.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have configured the low-level network components and management settings on the new vCMP host.
  • You have access to tmsh and the Configuration utility.

Procedures

To successfully migrate the vCMP guest configuration to a new vCMP host running on a different platform, perform the following procedures:

  • Resetting the master key on the vCMP guest
  • Saving UCS file for the vCMP guest
  • Creating a vCMP guest instance on the new vCMP host
  • Uploading the UCS file to the new guest
  • Installing the UCS archive on the new vCMP guest

Resetting the master key on the vCMP guest

Before migrating the vCMP guest to the new BIG-IP system, F5 recommends that you reset the master key on the guest. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh on the vCMP guest you are migrating by entering the following command:

    tmsh

  2. At the system prompt, reset the guest's master key by entering the following command:
    Important: If your configuration contains DNSSEC keys and you are running a version prior to BIG-IP 16.0, do not use tmsh modify sys crypto master-key. Instead use the workaround provided in ID 636606.

    Note: F5 recommends choosing a strong password.

    tmsh modify /sys crypto master-key prompt-for-password

  3. Safely record the password because you need it to install the UCS archive on the destination device.

Saving UCS file for the vCMP guest

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to Configuration utility of the vCMP guest you are migrating.
  2. Go to System > Archives.
  3. Select Create.
  4. For File Name, enter a name for the UCS archive file.
  5. Select Finished.
  6. On the Archive List page, select the name of the archive file you just created.
  7. Select Download and save the file to your local device.
  8. Go to Device Management > Devices.
  9. Select the name of the local device. For example, Guest1.local (Self).
  10. To force the vCMP guest offline, select Force Offline.

Creating a vCMP guest instance on the new vCMP host

Before you can install the vCMP guest's UCS archive, you must log in to the new BIG-IP vCMP host and create a new guest instance. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility for the new vCMP host.
  2. Go to vCMP > Guest List.
  3. Select Create.
  4. For Name, enter a name for the vCMP guest.
  5. For Host Name, enter the host name of the vCMP guest that you are migrating.
  6. For Management Port, enter the IP address, Network Mask, and Management Route settings.
  7. For Initial Image, select the base software release to install on the guest's virtual disk.
  8. For VLAN List, select the VLANs that the guest uses to communicate with the external network.
  9. Complete the remaining settings for the guest instance.
  10. Select Finished.
  11. From the Guest List page, select the guest instance you just created.
  12. Select Deployed.

Uploading the UCS file to the new guest

To upload the vCMP guest's UCS file to the new guest instance, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility for the newly created guest instance.
  2. Go to System > Archives > Upload.
  3. Select Browse.
  4. Go to the vCMP guest's UCS file that you previously created.
  5. Select Open.

Installing the UCS archive on the new guest

You must perform the UCS installation on the new guest using tmsh. To install the UCS configuration on the guest, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh on the new guest by entering the following command:

    tmsh

  2. Set the master-key password by entering the following commands:

    modify /sys crypto master-key prompt-for-password

    save /sys config

  3. Load the UCS file by entering the following command syntax:

    load /sys ucs <filename> platform-migrate

  4. If the platform-migrate command completes successfully, the system displays the following message:

    Platform migrate loaded successfully. Saving configuration.
    /var/local/ucs/<filename>.ucs is loaded.

  5. If the system is joining a device group, confirm the new device joined the trust group and is in Standby mode.
  6. Bring the new device online in the HA configuration by entering the following command:

    run /sys failover online
