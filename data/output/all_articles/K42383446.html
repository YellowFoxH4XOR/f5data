Description

Recently configured HSTS in the HTTP profile (and not with an iRule).

Internal scanner test does not pass, as it uses HEAD request.

When testing with a GET request, we do see the HSTS header inserted correctly, for example:

GET / HTTP/1.1
Host: example.com
User-Agent: curl/7.61.1
Accept: */*

HTTP/1.0 302 Found
Server: BigIP
Content-Length: 0
Strict-Transport-Security: max-age=16070400; includeSubDomains → Note hsts header inserted
Connection: close

HEAD / HTTP/1.1
Host: example.com
User-Agent: curl/7.61.1
Accept: */*

HTTP/1.0 302 Found
Connection: close

Environment

  • Virtual Server with an access policy
  • Virtual Server without access policy and without a pool

Cause

Bug ID 1010809: Connection is reset when sending a HTTP HEAD request to APM Virtual Server

Recommended Actions

On versiosn affected, you can apply the following iRule as a workaround to insert the HSTS header: 

when HTTP_REQUEST {
   if { [HTTP::method] equals "HEAD" and [HTTP::path] equals "/" } {
    HTTP::respond 404 Strict-Transport-Security "max-age=16070400"
   }
}
