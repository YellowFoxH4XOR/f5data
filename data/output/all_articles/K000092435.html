Description

While using the tcpdump utility to capture the traffic between unicast failover addresses of BIG-IP device group members contains a p interface modifier, it may result in duplicate packets marked with opposite directions.
For example, the following command searches for network traffic to or from hosts 10.0.0.1 and 10.0.0.2 on interface VLAN HA_VLAN, where 10.0.0.1 and 10.0.0.2 are self-IPs of BIG-IP devices in HA group:
tcpdump -ni HA_VLAN:nnnp -s0 -w /var/tmp/capture.dmp host 10.0.0.1 or host 10.0.0.2

Captured traffic may look similar to the following:

2       F5Networ_f0:ad:93    F5Networ_f0:f2:82    10.0.0.1        10.0.0.2        UDP    345            IN  s1/tmm3 : 42715 → 1026 Len=219        
3       F5Networ_f0:ad:93    F5Networ_f0:f2:82    10.0.0.1        10.0.0.2        UDP    345            OUT s1/tmm3 : 65473 → 1026 Len=219        
4       F5Networ_f0:ad:93    F5Networ_f0:f2:82    10.0.0.1        10.0.0.2        UDP    345            IN  s1/tmm3 : 42715 → 1026 Len=219        
5       F5Networ_f0:ad:93    F5Networ_f0:f2:82    10.0.0.1        10.0.0.2        UDP    345            OUT s1/tmm3 : 65473 → 1026 Len=219

Environment

  • High availability (HA) group configured
  • tcpdump
  • Packet capture
  • "p" flag used

Cause

None

Recommended Actions

It is not recommended to use the "p" flag to verify the network failover traffic using tcpdump.
