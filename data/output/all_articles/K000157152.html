K000157152: Virtual server in the kubernetes partition is incorrectly assigned to route domain 0 instead of route domain 1, causing backend pool members to show as unavailable.

Published

Description


When deploying F5 BIG-IP Container Ingress Services (CIS) in a Kubernetes environment with multiple partitions and route domains, users may encounter an issue where virtual servers created in a non-default partition are incorrectly assigned to the default route domain (0) instead of the intended route domain (for example, 1). This misassignment results in backend pool members appearing as unavailable and loss of connectivity to cluster pods, even when BGP and VLAN configurations are correct.


Environment


  • BIG-IP Container Ingress Services (CIS)
  • Kubernetes clusters integrated via BGP
  • CNI Cilium
  • Multiple BIG-IP partitions
  • Multiple route domains
  • VLANs and self IPs configured per partition/route domain
  • CIS deployed via Helm in the kube-system namespace
  • AS3 integration enabled


Cause


CIS controller did not have the --default-route-domain argument set, resulting in virtual servers defaulting to route domain 0 regardless of partition configuration.


Recommended Actions


To ensure virtual servers are created in the correct route domain:


Edit your CIS controller deployment to include:


--default-route-domain='1'


Note: Replace '1' with your desired route domain ID.


Redeploy or restart the CIS controller pod after updating this configuration.


Confirm that new virtual servers are now created within the intended route domain and backend pool members appear as available.


Additional Information


The default route domain must be set explicitly in CIS controller arguments even if your BIG-IP partition is associated with a specific route domain.

Using %<route-domain-id> notation alone in yaml manifest is insufficient without proper CIS configuration.

Route domains are network objects and require manual setup on each device in an HA configuration.
