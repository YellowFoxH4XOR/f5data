Description

In some cases, the ASM policy does not learn parameters or entities from requests whose bodies contain unstructured data — for example, plain text or arbitrary strings — even though a valid Content-Type header such as application/json or text/plain is present.


As a result, parameter-level learning suggestions and signature overrides are not generated, and violations may still occur despite existing parameter-level relaxations.


Environment

  • BIG-IP ASM / Advanced WAG
  • asm policy with learning mode enabled (either automatic or manual)


Cause

ASM analyzes and learns from HTTP request bodies based on their declared Content-Type and the associated Content Profiles.


When a request body does not conform to the expected format for its content type, ASM cannot parse it into parameters. In such cases:


  • The body is treated as a single, unparsed text block.
  • The event log shows the context “HTTP Request Body Unparsed Payload.”
  • Parameter-based learning and signature overrides are skipped, because no parameters are detected.
  • Attack signatures are still evaluated against the body as raw text, which may result in blocking or false positives.


This behavior is expected, as ASM learning requires successfully parsed structured data such as JSON, XML, or form-encoded parameters.


Recommended Actions

  • Ensure the Content-Type header matches the actual data format.
  • Assign a Header-Based Content Profile that matches the payload structure (e.g., JSON, XML, form-data).
  • When the body cannot be parsed, use URL-level or content-profile-level signature exceptions instead of parameter-level relaxations.


Additional Information

  • The “Unparsed Payload” context indicates that ASM was unable to extract parameters due to unrecognized or malformed content.
  • Learning, automatic parameter creation, and parameter-based signature overrides depend on successful parsing of structured data.
