Known Issue

The BIG-IP system may incorrectly process non-Session Initiation Protocol (SIP) 2.0 messages.

This issue occurs when the following condition is met:

  • A SIP virtual server with a SIP profile receives SIP 1.0 request messages.

The BIG-IP system will incorrectly accept and process SIP 1.0 requests. As a result, unsupported SIP 1.0 requests are sent to the SIP servers. The BIG-IP system correctly drops the SIP 1.0 responses received from the SIP servers.

Impact

The BIG-IP system processes SIP 1.0 requests that are eventually dropped when the SIP 1.0 response is received by the BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system forwards SIP 1.0 request to the SIP server and drops the corresponding SIP 1.0 response from the SIP server.
  • When you view the tmctl statistic for the SIP profile, you notice badmsgs counter increments when SIP 1.0 responses are dropped.

    For example:

    #tmctl -i -w 400 profile_sipp_stat
    name                 vs_name              requests responses badmsgs drops
    -------------------- -------------------- -------- --------- ------- -----
    /Common/sip          /Common/sip-vip            33         0       4     0
    /Common/sip          _listener                  24         0       3     0
    /Common/sip-outbound /Common/udp-outbound        0        10      14     0
    /Common/sip-outbound _listener                   0         0       0     0
    sipp                 _listener                   0         0       0     0
