Description

When BIG-IP becomes active for traffic processing, below symptoms may be observed:

  • GUI (Configuration Utility) is not accessible.
  • SSH access is experiencing slowness, especially TMSH shell.
  • CPU utilization is constantly at 100% level.
  • Multiple idle enforcer messages similar to below are logged in /var/log/kern.log:

info kernel: ltm driver: Idle enforcer starting - tid: 30764 cpu: 3/3

info kernel: ltm driver: Idle enforcer starting - tid: 30768 cpu: 7/7

info kernel: ltm driver: Idle enforcer starting - tid: 30765 cpu: 5/5

info kernel: ltm driver: Idle enforcer starting - tid: 30769 cpu: 1/1

    Environment

    • BIG-IP LTM
    • 100% CPU utilised when processing traffic

    Cause

    BIG-IP is working at the edge of its capacity.

    Recommended Actions

    You may reduce the volume of traffic processed by BIG-IP, or increase the processing capacity of BIG-IP by adding more CPU and memory (VE's) or purchase a more powerful hardware platform.

    1. From the BIG-IP terminal run the following command to check for license limitation:  
      tmsh show /sys license | grep perf_CPU_frequency
       If the output is like below, it means that CPU of your BIG-IP is throttled by the license (For example iSeries i4600 platform has Quad-Core Intel Xeon 2.2GHz CPU Chipset):
      perf_CPU_frequency [1200000]
      In such scenario, you can update the license to improve the performance. Please contact your F5 Sales Representative.
    2. Alternatively, you may apply the connection limit rate to the virtual server in order to restrict the CPU utilisation.

    Additional Information

    For more information about limiting the number of connection to virtual server, please see the following article: K45530602: Limiting the number of connections to a Virtual Server

    (Optional) From the output of below command, you can see tmm.0 process consuming majority of CPU resources, followed by enforcer processes.
