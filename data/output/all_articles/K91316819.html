Topic

You should consider using this procedure under one of the following conditions:

  • You want to add a new virtual server, its associated pool, and pool members to an existing F5 Application Services 3 Extension (AS3) declaration.
  • You want to add a new application containing a new virtual server and its associated pool to an existing AS3 declaration.

Description

You can deploy an HTTP application containing an HTTP virtual server with a pool of two or more members to a BIG-IP system using an AS3 declaration similar to the following example:
{
    "class": "AS3",
    "action": "deploy",
    "persist": true,
    "declaration": {
        "class": "ADC",
        "schemaVersion": "3.0.0",
        "id": "example-declaration-01",
        "label": "Example 1",
        "remark": "Simple HTTP application with RR pool",
        "example_partition": {
            "class": "Tenant",
            "example_app": {
                "class": "Application",
                "template": "generic",
                "example_http_vs1": {
                  "class": "Service_HTTP",
                  "virtualAddresses": [
                      "192.168.201.10"
                  ],
                  "pool": "example_http_pool1"
                },
                "example_http_pool1": {
                  "class": "Pool",
                  "monitors": [
                    "http"
                  ],
                  "members": [{
                    "servicePort": 80,
                    "serverAddresses": [
                        "172.16.201.10",
                        "172.16.201.11"
                    ]
                  }]
                }
            }
        }
    }
}

This declaration creates the following:

  • A new partition: example_partition
  • A new application: example_app
    • An HTTP virtual server: example_http_vs1 (192.168.201.10)
      • A pool: example_http_pool1
        • Two members (172.16.201.10 and 172.16.201.11)
If you want to add a new virtual server with a new pool, you can use the patch action of the AS3 class to modify the existing declaration. When you use the patch action, you must use the patchBody property to define the following:
  • The operation property, op, which performs one of the following: add, remove, replace, move, or copy
  • The declaration object property, path, which is the relative URI on which you want to perform the operation
  • The value property that you want to use for the operation
For more information about the AS3 patch method, refer to the Method Patch section of the AS3 API Methods Detail.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You licensed and provisioned your BIG-IP system, and you configured it with a management IP address.
  • You have administrative access to the BIG-IP Configuration utility.
  • You have command line access to a Linux system (or an alternate BIG-IP system), and you installed curl and jq (command line JSON processor) utilities on the system.
  • You read the AS3 User Guide.
  • You installed the AS3 package on the target BIG-IP device. For more information, refer to the Downloading and installing the AS3 package section of the AS3 User Guide.

Procedures

You can add a new virtual server with a pool to an existing declaration using one of the following methods, whichever meets your application requirements:

  • Adding a new virtual server with a pool to an existing application under an existing partition
  • Adding a new application to an existing partition
Adding a new virtual server with a pool to an existing application under an existing partition

To add a new virtual server with a pool to an existing application under an existing partition (tenant), perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to a Linux system (or an alternate BIG-IP system) that has curl and jq utilities.
  2. Use a text editor to copy the following template:
    {
      "class": "AS3",
      "action": "patch",
      "patchBody": [
        {
          "op": "add",
          "path": "/<existing partition name>/<existing app name>/<new pool name>",
          "value": {
            "class": "Pool",
            "monitors": [
                "<health monitor name>"
            ],
            "members": [{
              "servicePort": <new pool member port>,
              "serverAddresses": [
                "<new pool member IP address>",
                "<new pool member IP address>"
              ]
            }]
          }
        },
        {
          "op": "add",
          "path": "/<existing partition name>/<existing app name>/<new virtual server name>",
          "value": {
              "class": "Service_HTTP",
              "virtualAddresses": [
                "<new virtual server IP address>"
              ],
              "pool": "<new pool name>"
          }
        }
      ]
    }
  3. Replace the following variables in the template with values applicable to your environment:
    • <existing partition name>
    • <existing app name>
    • <new pool name>
    • <health monitor name>
    • <new pool member port>
    • <new pool member IP address>
    • <new virtual server name>
    • <new virtual server IP address>

    The following example declaration continues the example in the Description section by adding the following to the example_app application (path) in the example_partition partition of the existing declaration:

    • The example_http_vs2 virtual server (192.168.201.20)
    • The virtual server's associated pool, example_http_pool2, which is comprised of two pool members (172.16.201.13:80 and 172.16.201.14:80)

    {
      "class": "AS3",
      "action": "patch",
      "patchBody": [
        {
          "op": "add",
          "path": "/example_partition/example_app/example_http_pool2",
          "value": {
            "class": "Pool",
            "monitors": [
                "http"
            ],
            "members": [{
              "servicePort": 80,
              "serverAddresses": [
                "172.16.201.13",
                "172.16.201.14"
              ]
            }]
          }
        },
        {
          "op": "add",
          "path": "/example_partition/example_app/example_http_vs2",
          "value": {
              "class": "Service_HTTP",
              "virtualAddresses": [
                "192.168.201.20"
              ],
              "pool": "example_http_pool2"
          }
        }
      ]
    }

  4. After you customize the template, save the patch declaration to a file. Note the path to this file, because you need it for the next step.
  5. Use the following command syntax to post the patch declaration to the target BIG-IP system:

    curl -sku admin:<password> -H “Content-Type: application/json-patch+json” -X POST -d @<path/to/patch/declaration/file> https://<BIG-IP management address>/mgmt/shared/appsvcs/declare | jq -M .

    For example, to post the patch declaration file, example_partition.add.new.vs.with.pool.to.existing.app.json, to the BIG-IP management address, 172.16.10.145, you enter the following command:

    curl -sku admin:admin -H “Content-Type: application/json-patch+json” -X POST -d @example_partition.add.new.vs.with.pool.to.existing.app.json https://172.16.10.145/mgmt/shared/appsvcs/declare | jq -M .

Adding a new application to an existing partition

To add a new application that includes a new virtual server with a new pool to an existing partition (tenant), perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to a Linux system (or an alternate BIG-IP system) that has curl and jq utilities.
  2. Use a text editor to copy the following template:
    {
      "class": "AS3",
      "action": "patch",
      "patchBody": [
        {
          "op": "add",
          "path": "/<existing partition name>/<new app name>",
          "value": {
            "class": "Application",
            "template": "generic",
            "<new virtual server name>": {
              "class": "Service_HTTP",
              "virtualAddresses": [
                "<new virtual server IP address>"
              ],
              "pool": "<new pool name>"
            },
            "<new pool name>": {
              "class": "Pool",
