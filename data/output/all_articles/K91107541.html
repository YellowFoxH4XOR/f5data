Topic

Containerization and orchestration allow speed, agility, and efficiency in the application development lifecycle. F5 provides several container integrations to support integration with container ecosystems. For more information, refer to Introduction to F5 Container Ingress Services on F5 Cloud Docs.

Description

Evolution

Application infrastructure has evolved from a mainframe to a PC/server model. Virtualization offers the ability for multiple virtual systems to share the resources of a single physical hardware system. A virtual system can be a virtual machine (hypervisor-based virtualization) or a container (container-based virtualization).

Hypervisor-based virtualization

In hypervisor-based virtualization, virtual machines (VMs) share the host's hardware resources through a hypervisor. The hypervisor sits on top of the host's operating system (OS), which runs the VMs and manages VM access and interconnections. In this type of virtualization, applications must be installed inside a VM to be available.

Container-based virtualization

In container-based virtualization, hypervisors are not used. Instead, an application is contained within a virtual system called a container. Containers share the same OS as the host and embed the necessary components to run the application. Containerization technology, such as Docker, simplifies the development, deployment, and portability of containers. For more information about using Docker on F5 products, refer to Using Docker Container Technology with F5 Products and Services.

 

Orchestration and automation

In computer terminology, orchestration refers to setting a process or workflow to coordinate and arrange the automation of tasks.

Automation itself refers to setting a task to run automatically, using application and network programmability, and interacting with standard and low-level APIs. For example, the task of creating a virtual server using the representational state transfer (REST) API requires automation, whereas building a workflow to offer application services using a declarative interface requires orchestration.

Orchestration allows speed and efficiency in the application development lifecycle and empowers agile and DevOps principles of continuous integration (CI) and continuous delivery (CD).

F5 Application Services 3 Extension (AS3) is a flexible, low-overhead mechanism for managing application-specific configurations on a BIG-IP system. AS3 uses a declarative model; you provide a JSON declaration rather than a set of imperative commands. The declaration represents the configuration that AS3 is responsible for creating on a BIG-IP system. For more information about AS3, refer to the F5 Application Services 3 Extension Knowledge Center.

F5 Modules for Ansible allow to create, edit, update and delete configurations objects on BIG-IP and BIG-IQ. For more information about F5 Modules for Ansible, refer to F5 Modules for Ansible.

Orchestration in containerized environment

In a containerized environment, orchestration tools allow you to manage the lifecycle of containers. This includes the creation, scheduling, discovery, monitoring, permutations, availability, and replication of containers. F5 supports integration with container ecosystems and provides controllers for Cloud Foundry, Kubernetes, Mesos Marathon, and Redhat OpenShift to dynamically allocate BIG-IP Layer 4-Layer 7 (L4-L7) services. For more information, refer to Introduction to F5 Container Ingress Services on F5 Cloud Docs.
