Topic

This article applies to BIG-IP 9.4.x - 10.x. For information about other versions, refer to the following article:

  • K13333: Filtering log messages sent to remote syslog servers (11.x - 13.x)

The log levels configured for BIG-IP system logs only apply to local logs. When you configure a remote syslog server, all log messages are sent to that server unless you configure a filter using the bigpipe syslog include command.

The output of the bigpipe syslog list all command may lead administrators to incorrectly assume that the local log levels apply to remote syslog servers.

For example:

syslog {
   authpriv from notice
   authpriv to emerg
   cron from warning
   cron to emerg
   daemon from notice
   daemon to emerg
   include none
   kern from notice
   kern to emerg
   mail from notice
   mail to emerg
   messages from notice
   messages to warning
   userlog from notice
   userlog to emerg
   remote server log1 {
         host 192.168.1.10
         local ip none
         remote port 514
      }
}
#

If you want to filter the log messages sent to remote syslog servers, you must remove the syslog servers from the current configuration and then use the bigpipe syslog include command to re-add those servers with a syslog-ng filter.

For example, to configure syslog-ng to log only warnings through emergency log level messages to TCP port 1468 on 10.0.0.1 and to UDP port 514 on 10.0.0.2, you would perform the following procedure:

  1. Log in to the command line.
  2. Create the /tmp/syslog.inc file with the desired remote syslog configuration.

    For this example, you would use one of the following configurations for your version:

    BIG-IP 10.x

    syslog include "
    filter f_remote_loghost {
    level(warn..emerg);
    };

    destination d_remote_loghost {
    tcp(\"10.0.0.1\" port(1468));
    udp(\"10.0.0.2\" port(514));
    };

    log {
    source(s_syslog_pipe);
    filter(f_remote_loghost);
    destination(d_remote_loghost);
    };
    "

    BIG-IP 9.x

    syslog include "
    filter f_remote_loghost {
    level(warn..emerg);
    };

    destination d_remote_loghost {
    tcp(\"10.0.0.1\" port(1468));
    udp(\"10.0.0.2\" port(514));
    };

    log {
    source(local);
    filter(f_remote_loghost);
    destination(d_remote_loghost);
    };
    "

  3. To remove the currently configured remote syslog servers, type the following command:

    Important: This step disables all remote logging.

    bigpipe syslog remote server none

  4. To import the new remote syslog configuration, type the following command:

    Note: Importing a new syslog include configuration using the bpsh command or using the bigpipe syslog include command overwrites the previous syslog include entry, if configured. If you want to maintain the current syslog include entry, add that entry to the /tmp/syslog.inc file within the double quotation marks ( " ). Additionally, ensure that you escape any double quotation marks contained within that entry using a backslash ( \ ) character.

    bpsh < /tmp/syslog.inc

  5. After importing is complete, check the syslog syntax by typing the following command:

    syslog-ng -s

  6. Based on your command output results, perform one of the following options:
    • If the new logging configuration is working as expected, save your changes by typing the following command:

      BIG-IP 10.2.2 and later

      bigpipe save all

      BIG-IP 9.4.x - 10.2.1

      bigpipe save

    • If the new logging configuration is not working as expected, make the desired changes to the /tmp/syslog.inc file and return to Step 4.
    • If you receive the following error message:

      # syslog-ng -s syntax error at 751

      Remove the syslog include entries by typing the following command:

      bigpipe syslog include none

      Review the import file for syntax errors before attempting to re-import by typing the command listed in Step 4.

      Note: F5 recommends that you use the vi editor when viewing the import file, specifically if the import file was created on another system as the editor on that system may insert additional line feed characters that are hidden from standard text editors.

Note: To determine the version of syslog-ng running on your BIG-IP system, refer to K9445: The BIG-IP third party software matrix (9.x - 10.x).
