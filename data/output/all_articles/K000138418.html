K000138418: How we to check rejected traffic by throttling/Rate Limiting

Type
Support Solution
Published
2024-01-31
Updated
2025-02-07
Applies to
  • NGINX Products
  • NGINX Ingress Controller
Source
https://my.f5.com/manage/s/article/K000138418

Description

  • You have configured Rate limiting as part of your Nginx Ingress controller configuration
  • By default, NGINX logs requests that are delayed or dropped due to rate limiting.
  • You wish to view/monitor these delayed/dropped requests

Environment

  • Nginx Ingress Controller
  • ConfigMap
  • Nginx error log

Cause

  • None

Recommended Actions

  • You can use Nginx log to check or monitor dropped/rejected requests due to the application of rate limiting. 
  • To view or monitor dropped/rejected requests
  • You would first need to adjust Nginx error log level to notice level using Nginx configMap..
    • to do so, edit Nginx CM following
'kubectl edit cm -n nginx-config'
  • and increase error-log-level from notice to info level as shown below
apiVersion: v1
data:
  error-log-level: info
kind: ConfigMap
metadata:
  name: nginx-config
  namespace: nginx-ingress
  • You may then use "limiting" to grep for these specific log entries from Nginx log.
kubectl logs -n | grep -i limiting
