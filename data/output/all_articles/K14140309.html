K14140309: Restnoded memory utilization is very high after using telemetry streaming

Type
Support Solution
Published
2021-02-17
Updated
2025-04-02
Applies to
  • Virtual Editions
  • BIG-IP
  • F5 Automation and Orchestration
  • F5 BIG-IP Telemetry Streaming
Source
https://my.f5.com/manage/s/article/K14140309

Description

Restnoded memory utilization is very high after using telemetry streaming

Error:

<Date> - severe: [Telemetry_Consumer] Unable to send data chunk: Error: badResponse
<Date> - severe: [Telemetry_Consumer] sendDataChunk::response error:
{
  "error": {
    "code": "ECONNRESET",
    "errno": "ECONNRESET",
    "syscall": "read"
  }
}

Environment

  • Telemetry Streaming (TS)
  • Migrated from Syslog to TS

Cause

  • Restnoded consuming more memory due to it couldn't get it's data off the device

Recommended Actions

  1. This suggests to look into the logging server (example Splunk) communication problem for sending telemetry off the device.

Additional Information

Telemetry Streaming is an iControl LX extension, which means it is ran by the Restnoded process. That is why you see increased memory usage in the restnoded process when Telemetry Streaming is in use.
