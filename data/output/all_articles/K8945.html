Topic

Configuration utility authentication failures do not generate an SNMP trap when SNMP traps are enabled. The only authentication failure trap that is sent occurs when an SSH login attempt fails.

F5 Product Development tracked this enhancement as CR61562 and it was fixed in BIG-IP 9.4.2 and 9.6.1. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, Link Controller, and WebAccelerator Release Notes.

Workaround

To add this functionality to versions that do not include this enhancement, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /etc/alertd directory by typing the following command:

    cd /etc/alertd
  3. Create a backup of the alertd.conf file by typing the following command:

    cp alert.conf alertd.conf.backup
  4. Edit the alert.conf file and locate the following section: 
    /*     * from console login and sshd (CR38227)     */    alert BIGIP_AUTH_FAIL "FAILED LOGIN (.*) FROM (.*) FOR (.*), Authentication failure" {            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.27"    }    alert BIGIP_SSHD_AUTH_FAIL "error: PAM: Authentication failure for (.*) from (.*)" {            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.27"    }
  5. Add the following to the end of the section:

    alert BIGIP_GUI_AUTH_FAIL "[error](.*) AUTHCACHE PAM: user (.*) not authenticated: Authentication failure" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.27"
    }

    The section should now appear as follows:

    /*
    * from console login and sshd (CR38227)
    */
    alert BIGIP_AUTH_FAIL "FAILED LOGIN (.*) FROM (.*) FOR (.*), Authentication failure" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.27"
    }
    alert BIGIP_SSHD_AUTH_FAIL "error: PAM: Authentication failure for (.*) from (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.27"
    }
    alert BIGIP_GUI_AUTH_FAIL "[error](.*) AUTHCACHE PAM: user (.*) not authenticated: Authentication failure" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.27"
    }
  6. Save the changes made to the alert.conf file.
  7. Restart alertd by typing the following command:

    bigstart restart alertd
  8. Test the change by logging in to the Configuration utility with an incorrect user and/or password.

    Note: Login failures are reported to the /var/log/secure file.
