Topic

This article describes the fields the BIG-IP ASM system uses when generating DoSL7 logs for remote logging.

Description

You can configure remote logging on the BIG-IP ASM system in order to log DoSL7 events remotely.  The BIG-IP ASM system reports details about DoSL7 events depending on the entities configured for mitigation in the DoS profile.

Note: Regardless of the configuration, the system always collects and reports request URL and source IP address.

The following tables list the fields the system uses for remote logging when reporting DoSL7 events.

dos_mitigation_actionThe type of mitigation:

  • URL-Based Client Side Integrity Defense

  • Geolocation-Based Rate Limiting
  • URL-Based Rate Limiting
  • Site-Wide Rate Limiting
  • Transparent
  • Behavioral Mitigation
  • No Mitigation
dos_mitigation_reasonThe reason the mitigation occurred on an entity:
  • Abnormal volume: Mitigation happened due to an unusual high volume of traffic coming from this entity.
  • Other entity in request: The system reports the entity because it sent traffic to or from a mitigated entity, for example. a non-suspicious IP sends traffic to a mitigated URL and thus the system blocks. You should report this IP with Other entity in request.  Note: This is more for information gathering on other criteria involved in an attack and not necessarily meaning that it is blocking on those other criteria.  E.g. A mitigated entity may be coming from a specific Geo Location giving the administrator further information to possibly add more protections.
  • Not mitigated: The system did not mitigate the entity. The entity is still suspicious.
  • Bot Signature Matched: A bot signature matched on the entity. There is no information about which bot signature matched.
  • Bot filtering: The system dropped the entity due to proactive bot defense system (you may see this when attacks are not occurring).
  • Auto-detected heavy URL: The system detected the entity detected as heavy URL automatically and mitigated it.
  • Configured heavy URL: The system detected the entity as heavy URL manually and mitigated it.
  • Disallowed GEO-location: Traffic is coming from a geolocation configured as disallowed.
  • Behavioral Anomaly: Behavioral DoS mitigated entity.
