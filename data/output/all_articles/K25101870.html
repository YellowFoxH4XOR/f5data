Topic

This article describes how to configure the BIG-IP APM system as an OAuth client with a Google OAuth authorization server.

Description

The following describes the user experience:

  • You connect to an LTM-APM virtual server on the BIG-IP APM system.
  • The BIG-IP APM uses the access policy directs to authenticate and direct you to the Google authentication and authorization server.
  • You provide your Google credentials to the Google service.
  • After you're authenticated, Google's OAuth authorization server issues an access token and redirects you back to the BIG-IP APM system.
  • The BIG-IP APM system allows the you to access the backend web service in a BIG-IP LTM pool.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have already created a BIG-IP LTM pool on the BIG-IP system, with servers providing a web service.
  • There is network connectivity among the client devices, the BIG-IP APM system, and Google authentication service.
  • There is network connectivity between BIG-IP APM system and Google authentication service.
  • You have a Google account to configure the Google authorization service.

Procedures

The main building blocks of the setup consists of the following:

  • Google OAuth 2.0 Authorization Server
  • BIG-IP APM as OAuth Client
    • Virtual server
    • Access profile/access policy
      • OAuth Client
      • OAuth Google provider (built-in)

Perform the following procedures to build these objects:

  • Configure Google OAuth authentication
  • Configure a BIG-IP APM OAuth client
  • Create a new access profile and access policy
  • Create a virtual server for user access
  • Access the service from a client

Configure Google OAuth authentication

In Google APIs, you need to create a project, a consent screen, and OAuth client ID (for a web application).

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to Google APIs.
  2. Select OAuthProject.
  3. In the Select a project pop-up window, select the name of a project. If you do not have any existing projects, create a new one by selecting NEW PROJECT.
    1. For Project name, enter OAuthProject.
    2. Select CREATE.
  4. Create a consent screen.

    Follow the procedure in Configure OAuth consent & register your app in Google docs. using the following values:

    Note: The consent screen describes who is requesting access to data and what kind of data will be accessed. For the purposes of this article, the BIG-IP APM system is the requester.

    ParameterValue
    App nameAPMApplication
    User support email<your email address>
    Authorized domainsexample.com
    ScopesAdd your scopes or leave the fields empty as you can add them later
    Test usersAdd your test users or leave the field empty as you can add them later

  5. Create an OAuth client ID.

    Perform the following procedure to create access credentials. Google may make changes to their User Interface. Refer to the procedure for Web application in OAuth client ID credentials in Google docs for the updated steps.

    1. Select Credentials.
    2. Select Create credentials.
    3. Select OAuth client ID.
    4. Continue creating OAuth client ID by selecting Web application.
    5. For Name, enter APMApplication.
    6. For Authorized JavaScript origins, provide Google with the URL that will be accessed through browsers. For example, https://apm.example.com, and select the Enter key.
    7. For Authorized redirect URIs, provide Google with the URL to which to redirect upon successful authentication. For example, https://apm.example.com/oauth/client/redirect, and select the Enter key.
    8. Select Create.
    9. Copy the Client ID and Client secret values to use in the next procedure. You can retrieve these values by navigating to your application under Credentials.

Configure the BIG-IP APM OAuth client

The OAuth Client is the interface on the BIG-IP APM that communicates with the Google authorization service. The essential values are the Client Id and Client Secret, which identify the specific Google OAuth server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Federation > OAuth Client / Resource Server > OAuth Server.
  3. Select Create.
  4. For DNS Resolver, select the appropriate selection or create one by selecting + and performing the following steps:
    1. For Name, enter googleDNSResolver.
    2. Select Finished to return to the New OAuth Server Configuration page.
  5. Fill in the remaining settings with the values in the following table and then select Finished.
    SettingValue
    Namegoogle-oauth-server
    ModeClient
    TypeGoogle
    OAuth ProviderGoogle
    Client IdEnter the Client Id from step 4 of the Configuring Google OAuth credentials procedure.
    Client SecretEnter the Client Secret from step 4 of the Configuring Google OAuth credentials procedure.
    Client's ServerSSL Profile Nameapm-default-serverssl

    Note: This value is the SSL profile the BIG-IP APM uses in its SSL handshake with the Google service. You should configure your own SSL profile and Trusted Certificate Authorities in production.

Create a new access profile and access policy

The access profile and access policy determine how the BIG-IP system authenticates and authorizes. The OAuth Client action you configure here selects the OAuth Client configured in the previous step.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  3. Select Create.
  4. For Name, enter OAuthClientToGoogleAP
  5. For Profile Type, select All.
  6. Under Languages Settings, for Language, in the Factory BuiltIn Languages, select English and move it to the Accepted Languages list.
  7. Select Finished.
  8. From the list of access policies, for the one you just created, select Edit to open Visual Policy Editor (VPE).
  9. Create an OAuth Client to authenticate the user using Google services:
    1. Select the Add icon (+) on the fallback branch for Start.
    2. Select the Authentication tab, select OAuth Client, and select Add Item.
    3. Fill in the settings with the values in the following table.
      SettingValues
      Server/Common/google-oauth-server (This is the OAuth Client you created in the Configuring a BIG-IP APM OAuth client for Google) procedure.
      Grant TypeAuthorization Code
      OpenID ConnectDisabled
      Authentication Redirect Request/Common/GoogleAuthRedirectRequest
      Token Request/Common/GoogleTokenRequest
      Refresh Token Request /Common/GoogleTokenRefreshRequest
      Redirection URI Use the default setting
      Scopeemail
    4. Select Save.
  10. On the Successful branch following the OAuth Client policy item, create a Pool Assign by selecting the Add icon (+).
  11. Select the Assignment tab.
  12. Select Pool Assign and select Add Item.
  13. Select Add/Delete and select the appropriate BIG-IP LTM pool that has the resource servers.
  14. Select Save.
  15. Following the Pool Assign, select the Deny end point.
  16. Select Allow and select Save.

Create a virtual server for user access

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select Create.
  4. For Name, enter ltm-apm-google-oauthVS.
  5. For Destination Address/Mask, enter the appropriate IP address. For example, 10.10.10.5.
  6. For Service Port, enter 443.
  7. For SSL Profile (Client), in the Available list, select clientssl and move it to the Selected list.
  8. For SSL Profile (Server), in the Available list, select serverssl and move it to the Selected list.

    Note: The BIG-IP LTM pool member supports HTTPS.

  9. For HTTP Profile, select http.
  10. For Source Address Translation, select AutoMap.
  11. For Access Profile, select OAuthClientToGoogleAP .

    Note: This is the access profile you created in the Creating a new access profile and access policy procedure.

Access the service from a client

After completing the configuration, perform the following procedure on a client to test the service:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your client device.
  2. Using the previous example configuration, add the following example entry to the host file:

    10.10.10.5 apm.example.com

    Note: This is the IP address you assigned to the virtual server created in step 5 of the Creating a virtual server for user access procedure. The apm.example.com URL must match the domains you used in step 3 of the Configuring Google OAuth credentials procedure.

  3. Access https://apm.example.com from a browser.
  4. Enter or select your Google account.
  5. Enter your password.
  6. When your login is successful, you are taken to the BIG-IP APM access policy to the Pool Assign to access the backend service.
