  • K411: Overview of packet tracing with the tcpdump utility

Description

You can use the tcpdump utility to view traffic on the BIG-IP Next Service Proxy for Kubernetes (SPK) Service Proxy pod. The tcpdump utility is provided with other diagnostic tools within the debug sidecar in the BIG-IP Next SPK Service Proxy pod. The debug sidecar is deployed by default with the BIG-IP Next SPK Ingress Controller. Running the tcpdump utility in the debug sidecar allows you to capture ingress and egress traffic to the Traffic Management Microkernel (TMM).

Note: Running the tcpdump utility on a worker node's physical interface shows L2 traffic but does not show TMM ingress and egress traffic.

The tcpdump utility supports capturing additional internal TMM information by specifying the noise amplitude in the command. For more information about capturing internal TMM information, refer to K13637: Capturing internal TMM information with tcpdump.

Note: To save tcpdump capture files to a filesystem on a node, you must have a Kubernetes PersistentVolume available for binding and configure the debug container’s persistence parameter in the Ingress Controller Helm values file. For more information, refer to F5 Service Proxy for Kubernetes on F5 Cloud Docs.

Run the tcpdump utility 

To run the tcpdump utility, you must access the debug sidecar container running in the Service Proxy pod. The debug sidecar shares network namespace with TMM, which allows the tcpdump utility to capture traffic ingressing and egressing the TMM. To access the debug sidecar container, access the OpenShift cluster and use the following command syntax:

oc exec -it deploy/f5-tmm -n <project> -c debug -- bash

For example, if the TMM pod resides in the project named spk-ingress, enter the following command:

oc exec -it deploy/f5-tmm -n spk-ingress -c debug -- bash

Note: If using a scaled TMM deployment, replace deploy/f5-tmm with the specific pod name of the TMM.

From the debug container, you can list the available interfaces by entering the tcpdump -D command. The following example output shows the available interfaces, including tmm and the internal and external VLANs:

[root@f5-tmm-86c4f432c-dg28c /]# tcpdump -D
1.xeth0
2.tmm
3.eth0
4.tmm_bp
5.internal
6.external
7.xnet1
8.xnet2
9.any (Pseudo-device that captures on all interfaces)
10.lo [Loopback]

When running the tcpdump utility in the debug container, you can specify the interface or VLAN on which to capture traffic. You can also include filters to restrict the output to specified addresses, ports, and protocols.

For example, to capture traffic on all TMM interfaces, enter the following command:

Important: Running tcpdump on interface 0.0 has the potential to generate very large files. When capturing on interface 0.0, you should use filters to reduce the size of the capture. 

tcpdump -ni 0.0 

Note: The -n option disables name resolution.

To capture only the internal VLAN, enter the following command:

tcpdump -ni internal 

To specify destination port 8080, enter the following command:

tcpdump dst port 8080

You can combine options and use the -w option to save the output to a file. This example captures traffic on the external VLAN with destination port 8080 and saves the output to the /shared directory on the debug container, which is mapped to the worker node using a Kubernetes PersistentVolume:

tcpdump -ni external and dst port 8080 -w /shared/spk_external.pcap

For more information about using tcpdump filters to capture traffic, refer to K411: Overview of packet tracing with the tcpdump utility.

Download the tcpdump output file

When saving tcpdump output to a file using a PersistentVolume, the tcpdump output file is saved to the location seen in the Path from the PersistentVolume claim object. To locate the Path in the PersistentVolume claim object, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Locate the bound persistent volume claim for the debug sidecar using the following syntax:

    oc get pv -n <project> | grep f5-debug-sidecar

    For example, if the persistent volume claim resides in the project named spk-ingress, enter the following command:

    oc get pv -n spk-ingress | grep f5-debug-sidecar

    The following example output shows the persistent volume claim for the f5-debug-sidecar:

    pvc-c4d5a2bc-5876-4124-a19c-d9213243363c 1Gi spk-ingress/f5-debug-sidecar managed-nfs-storage

  2. To view the Path from the PersistentVolume claim object, enter the following command:

    oc describe pv pvc-c4d5a2bc-5876-4124-a19c-d9213243363c | grep Path:

    The following example output shows the Path with the directory on the worker node of the debug container:

    Path: /opt/local-path-provisioner/pvc-c4dabc-5876-4124-a19c-d9213243363c_ingress_f5-debug-sidecar

  3. Download the tcpdump output file from the Path directory of the worker node using a utility such as Secure Copy (SCP) protocol. For information about transferring files, refer to K175: Transferring files to or from an F5 system.
