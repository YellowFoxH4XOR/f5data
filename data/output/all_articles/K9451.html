K9451: Purpose of the BIG-IP WebAccelerator HTTP X-WAM-RC-MASQ and X-WAM-ORIG-CC headers

Topic

Beginning in BIG-IP WebAccelerator version 9.4.2, the WebAccelerator uses the BIG-IP LTM system's RAM Cache to improve performance. When the BIG-IP WebAccelerator proxies a connection to the origin web server, the HTTP Cache-Control header in the response is set to private to allow the WebAccelerator to control the promotion of cache levels. Normal cache promotion moves from disk cache to in memory cache (IMC), and then to RAM Cache. If the HTTP Cache-Control header is not set to private, the RAM Cache will automatically cache the content after first response, which may break the WebAccelerator's functionality. However, when the origin server initially sets the HTTP Cache-Control header value to public and the BIG-IP WebAccelerator then changes the value to private, it can result in unexpected caching behavior by the client or by an intermediate caching device between the BIG-IP WebAccelerator system and the client.

Note: Beginning in BIG-IP WebAccelerator version 9.4.8, the system no longer inserts the X-WAM-ORIG-CC header.

Beginning in BIG-IP WebAccelerator version 9.4.5 HF2, this functionality has been enhanced by adding two more HTTP headers. The X-WAM-RC-MASQ header was added to indicate the BIG-IP WebAccelerator has modified the HTTP Cache-Control header inserted by the origin server, and the X-WAM-ORIG-CC header was added to preserve the value of the HTTP Cache-Control header inserted by the BIG-IP WebAccelerator.

When the BIG-IP WebAccelerator changes the HTTP Cache-Control header to private, the WebAccelerator will insert the HTTP X-WAM-RC-MASQ header set to On, and inserts the HTTP X-WAM-ORIG-CC header set to the original value of the HTTP Cache-Control header. These headers can then be used to determine if the WebAccelerator has set the HTTP Cache-Control header to be private: the headers can also be used to determine the original value when resetting the value using an iRule (if required).
