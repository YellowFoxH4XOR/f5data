K000137136: Portal Access displays cached content

Updated

Applies to

Source

Description

A Portal Access application displays cached content, for example an older version of a page or a file, instead of the current content of the back-end server.

This article describes the Portal Access cache, and how to display and delete the cache entries.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource and rewrite profile

Cause

Portal Access uses the apm-enduser-if-cache caching profile. You can define other caching profiles (Web Acceleration profiles) and apply them to virtual servers, but the apm-enduser-if-cache profile is used by the internal virtual server for Portal Access.

Answer/Recommended Actions

Display the cache entries

  1. Log in to the command line of the BIG-IP system.

  2. Use the following command:

    tmsh show ltm profile ramcache apm-enduser-if-cache

    Note: Without the max-response option, the show ltm profile ramcache command displays only 10 entries per Traffic Management Microkernel (TMM). For more information, refer to K13255: Displaying and deleting HTTP cache entries from the command line (11.x and later).

Delete the cache entries

Impact of procedure: F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the command line of the BIG-IP system.

  2. To delete a single entry, use the following command syntax:

    tmsh delete ltm profile ramcache apm-enduser-if-cache uri /<uri_object>

    To delete the entire cache, use the following command:

    tmsh delete ltm profile ramcache apm-enduser-if-cache

  3. Start a new access session, and verify that the application displays the current content.

If the issue persists, refer to K14184: Troubleshooting BIG-IP APM Portal Access applications.
