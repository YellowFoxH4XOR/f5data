Description

VMware View PCoIP traffic may cause imbalance of traffic across different TMMs (CPU cores).

As a result of this issue, the following symptoms may be observed:
  • Traffic processing performance is lower.
  • TMM flow counter values are very imbalanced as shown in the following output:

    [root@hostname:Active] / # tmctl -d blade tmm/thread -s tid,flows
    tid flows
    --- -----
      1     432
      5     474
      4     404
      3     431
      2     434
      0    9211  !!! tmm0 has very high traffic load compared to others !!!

  • From a qkview in iHealth, this can be verified in the tmctl -a command output and under tmm.thread.

    Note: The tmctl -a command can be found in iHealth by navigating to Commands > Unix > TMOS

  • From a qkview in iHealth, this can be also verified in the Performance Graphs section and focusing on CPU Usage By Core graph.

Environment

This occurs when all of the following conditions are met:

  • BIG-IP APM VMware View set up in APM-LTM mode
  • VMware View PCoIP traffic is passing.
  • APM-LTM is using the default DAG mode where packets are distributed across different TMMs based on a hash of the source and destination port.
  • The VMware View Client uses default settings which instruct the client to use UDP source port 50002 to initiate PCoIP traffic.

Cause

This happens as the BIG-IP system's default DAG mode uses the source port (in VMware View PCoIP, this is UDP port 50002) and destination port (UDP port 4172) hash to distribute traffic across the different TMMs instances.

Recommended Actions

Consult with your VMware View vendor and see how PCoIP traffic can be re-configured to use an ephemeral source port instead of a static UDP source port starting from 50002.
