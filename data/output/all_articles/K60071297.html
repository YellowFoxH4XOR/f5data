Description

You get an undesired selection result using the topology load balancing method when the eDNS subnet client contains an IPv6 address.

Use the below configurations as an example:

  • For the eDNS configuration:

gtm global-settings load-balancing {
    topology-prefer-edns0-client-subnet enabled
}

  • For the Wide IP and Topology records:

gtm wideip a /Common/vs-example.com {
    pool-lb-mode topology
    pools {
        /Common/pool_external--pool_A_example.com {
                order 1
        }

        /Common/pool_internal--pool_B_example.com {
                    order 0
        }
    }
}

gtm topology ldns: region /Common/region_external server: pool /Common/pool_external----pool_A_example.com {
    order 1
    score 50
}

gtm topology ldns: region /Common/region_internal server: pool /Common/pool_internal--pool_B_example.com {
    order 2
    score 100
}

gtm region /Common/region_external {
        region-members {
            subnet 0.0.0.0/0 { }
    }
}

gtm region /Common/region_internal {
        region-members {
        subnet 10.0.0.0/8 { }
        subnet 172.1.0.0/12 { }
        subnet 192.168.0.0/16 { }
    }
}

You may observe symptoms as:

  1. You might get an abnormal pool selection decision, for example, you may unexpectedly get a result that should be designed as an internal address. For the above configuration, you may unexpectedly get the /pool_internal--pool_B_example.com even if your client address belongs to the external region.

  2. You may have a default match topology record, for example, a region mapping all IPv4 addresses. Using the above configuration, it is gtm region /Common/region_external.

  3. If you turned the topology decision log as per K25751652, you may find it fails for all of the topology records. For example:

Environment

  • BIG-IP DNS
  • Topology load balance with regions
  • Prefer eDNS client subnet is enabled globally, or for the wideip that has the issue

Cause

The designed topology records might be incomplete for the request whose eDNS subnet client is an IPv6 address.

Recommended Actions

You can avoid this situation by adding default IPv6 topology region mapping records similar to the below configuration:
gtm region /Common/region_default {
    region-members {
        subnet 0.0.0.0/0 { }
        subnet ::/0 { }     
    }
}

For how to manage your topology records, you may refer to K13412: Overview of BIG-IP DNS Topology records (11.x - 16.x).
