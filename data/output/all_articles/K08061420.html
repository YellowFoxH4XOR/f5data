K08061420: Tenants may fail to start after upgrading to F5OS-A 1.3.0

Type
Knowledge
Published
2022-11-02
Updated
2023-02-21
Applies to
  • F5OS
  • F5OS-A: 1.3.0
Source
https://my.f5.com/manage/s/article/K08061420

Topic

When upgrading an rSeries system to F5OS-A 1.3.0, the K3s cluster may fail to complete the installation process causing tenant deployments to fail.

Note: This issue is fixed in F5OS-A 1.3.1 available for download at the F5 Downloads site.

Description

When you perform a live upgrade to F5OS-A 1.3.0 from a previous version, the system upgrades the bootloader firmware, which requires a system power cycle. If the power cycle occurs abruptly during the K3s cluster installation, the cluster may remain in an unusable state, preventing tenants from starting.

Symptoms

  • During the upgrade process, tenants fail to start and report error messages that appear similar to the following example:

    Tenant deployment failed  - Server is not responding

  • The following show cluster cluster-status summary-status CLI command output shows the K3s cluster is not ready:

    cluster cluster-status summary-status "1 Appliance is NOT ready, K3S cluster is NOT ready."

  • The /var/log/messages file contains certificate error messages that appear similar to the following examples:

    appliance-1 k3s:  level=info msg="Cluster-Http-Server  http: TLS handshake error from 100.65.6.61:34508: remote error: tls: bad certificate"
    appliance-1 k3s:  level=info msg="Cluster-Http-Server  http: TLS handshake error from 100.65.6.61:34510: remote error: tls: bad certificate"
    appliance-1 k3s: E1028 16:15:15.673106    2030 remote_runtime.go:116] "RunPodSandbox from runtime service failed" err="rpc error: code = Unknown desc = failed to setup network for sandbox \"9762978718c5eac5d416ae3677d2ef79963999fd49237571fc43c63bec588912\": Multus: [kube-system/klipper-lb-6gvf8]: error getting pod: Get \"https://[100.75.0.1]:443/api/v1/namespaces/kube-system/pods/klipper-lb-6gvf8?timeout=1m0s\": x509: certificate signed by unknown authority"

Workaround

Downgrading the F5OS-A software will not fix this issue. To work around this issue, you must uninstall K3s and rebuild the cluster, which can take approximately 10 minutes to complete. To do so, perform the following procedure:

Note: F5OS-A 1.3.0 has been removed from the F5 Downloads site. If you need F5OS-A 1.3.0 software, contact F5 Support. For more information, refer to K2633: Instructions for submitting a support case to F5.

Impact of procedure: Performing the following procedure rebuilds the K3s cluster, causing all tenants running in the cluster to restart.

  1. Log in to the rSeries CLI.
  2. Type the following command:

    config

  3. Set the tenant running-state to provisioned. To do so, use the following command syntax, where <tenant_name> is the name of the tenant:

    tenants tenant <tenant_name> config running-state provisioned

    Repeat this step for all other tenants on the system.

  4. To commit the change and exit, type the following command:

    commit and-quit

  5. As the root user, stop the Appliance Orchestration Manager by typing the following command:

    systemctl stop appliance_orchestration_manager_container.service

  6. To uninstall the K3s cluster and clean up the OMD context, type the following four commands in succession:

    k3s-uninstall.sh

    rm /var/omd/*

    rm /tmp/omd/tokens/*

    rm /tmp/omd/appliance-ansible-host

  7. Start the Appliance Orchestration Manager using the following command. You need to wait approximately 10 minutes for the process to complete:

    systemctl start appliance_orchestration_manager_container.service

  8. Log in as the admin user to enter the rSeries CLI.
  9. Verify the cluster status is ready by typing the following CLI command:

    show cluster cluster-status summary-status

    The following example output shows the cluster is ready for use:

    cluster cluster-status summary-status "K3S cluster is initialized and ready for use."
