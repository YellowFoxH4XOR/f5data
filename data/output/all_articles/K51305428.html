Description
Throughput graph at performance measurement feature does not reflect actual amount of traffic flowing.

Environment

  • Platform with PVA
  • Multiple VLANs routing to same destination
  • Virtual server with FastL4 profile 

    Cause
    PVA incorrectly calculates traffic routed via multiple VLANs, F5 track as ID1144729.

    You can observe this behavior when one flow contains multiple routes to single destination, and those routes are located on different VLANs
    To confirm the behavior, 

    • Take packet capture 
    • Filter relevant session in Wireshark using the filter "tcp==[session ID]"
    • Observe for multiple transactions within single session and same socket that contains different set of VLANs, MAC addresses. 

    Recommended Actions

    To workaround, follow the below steps.  

    1. To disable PVA acceleration for the affected traffic
      • Navigate to Local Traffic >> Profiles : Protocol : Fast L4 (assigned to virtual server) in the BIG-IP configuration utility
      • Set PVA Acceleration = None
    2. Create another FastL4 profile and set the other-pva-offload-direction to server-to-client-only
      • Navigate to Local Traffic >> Profiles : Protocol : Fast L4 in the BIG-IP configuration utility
      • Create a new Fast L4 profile
      • Set the Parent Profile to the FastL4 profile applied to the virtual server
      • Set other-pva-offload-direction to server-to-client-only
      • Finish the new FastL4 profile
    3. Assign both the FastL4 profiles to the virtual server.
