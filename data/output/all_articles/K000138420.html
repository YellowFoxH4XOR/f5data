Description

There are scenarios where it might seem that IP address exceptions configured in an ASM policy are not functioning as expected. Specifically, requests originating from IP addresses listed as exceptions may still appear as "illegal" in the event logs, raising concerns about the policy's effectiveness.

It’s important to note that the IP address format is correctly defined, and the appropriate Route Domain is included if the Virtual Server resides in a different Route Domain.

 

Environments

  • ASM policy
  • IP address Exception

 

Cause


This behavior occurs because the ASM policy is operating in Transparent Mode. In this mode, requests are not actively blocked but are logged for monitoring purposes. Consequently, even requests from IPs in the exception list may be marked as "illegal" in the event logs.

 

Recommended Actions

Switching the ASM policy to Blocking Mode ensures the expected behavior for IP address exceptions. In Blocking Mode, event logs will display the following information for requests from IPs on the exception list, confirming their exemption:

  • Request Status: Unblocked
  • Blocking Exception Reason: IP is in Whitelist

These requests will proceed to the server without any issues on the BIG-IP system.
