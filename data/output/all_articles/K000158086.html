K000158086: Multicast Traffic Double-Tagging (Q-in-Q) on BIG-IP LTM rSeries Tenants

Description

This article describes an issue where multicast traffic egressing from a BIG-IP LTM tenant running on rSeries hardware is observed with double VLAN tags (Q-in-Q). This results in the intended recipients not receiving the multicast packets, impacting services dependent on multicast delivery. The problem is visible in packet captures as two consecutive 802.1Q VLAN headers and is specific to certain VLANs in production environments. The issue does not occur on iSeries BIG-IP platforms with similar configurations.

Environment

  • Product: BIG-IP LTM
  • Platform: rSeries 
  • Software Version: 17.1
  • Configuration details:
    • Multicast routing using PIM Sparse Mode
    • Multicast forwarding between VLANs
  • Comparison: Issue not present in lab environment using iSeries BIG-IP devices
  • Packet captures show double-tagging only on specific VLANs in production

Cause

Bug ID2141125 (BIG-IP 17.1.1.3 multicast traffic issue)

Recommended Actions

  • Obtain and install the EHF containing the fix for Bug ID 2141125 from F5 Support, ensuring it matches your current EHF baseline if applicable.
  • Validate the hotfix in a test environment before deploying to production.

Additional Information

  • This issue specifically affects multicast forwarding; unicast traffic is not impacted.
  • The problem was reproducible only on rSeries tenants; iSeries platforms did not exhibit this behavior under similar configurations.
  • The engineering hotfix must be coordinated with F5 Support, especially if you are running a custom or cumulative EHF build.
  • When forwarding multicast to multiple VLANs, only one may receive correctly tagged frames while others experience Q-in-Q tagging unless patched.
