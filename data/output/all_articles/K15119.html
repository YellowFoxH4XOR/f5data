Known Issue

Duplicate file names in a BIG-IP configuration may cause a BIG-IP system upgrade or user configuration set (UCS) load to fail.

This issue occurs when all of the following conditions are met:

  • You attempt to upgrade a system from BIG-IP 10.x to 11.x.
  • You attempt to load a BIG-IP 10.x UCS file on BIG-IP 11.x.

In BIG-IP 10.x, files that exist in separate directories may have the same name. However, when upgrading to BIG-IP 11.x, which introduced a file-object model, duplicate file names may prevent a BIG-IP system upgrade or UCS load from completing.

For example, the following certificate and key files on a BIG-IP 10.x system could cause this issue: /config/ssl/ssl.crt/filename.ext and /config/ssl/ssl.key/filename.ext.

Impact

The BIG-IP system upgrade or UCS load fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your attempts to upgrade the BIG-IP system or load a UCS fail.
  • After loading a UCS file or upgrading the BIG-IP system, the Configuration utility displays an error message that appears similar to the following example:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.
  • After loading a UCS file or upgrading the BIG-IP system, you notice a message similar to the following example in the /var/log/ltm file:

    File object by name (<filename>) is missing

    Where <filename> is the name of a duplicate file found during the UCS load or upgrade.

Workaround

To work around this issue, you can rename any duplicate file names on the BIG-IP 10.x system before upgrading or saving a UCS file. To do so, contact F5 Technical Support for instructions to complete your upgrade.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
