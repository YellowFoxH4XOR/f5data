K73820426: Patch HTTP Method in iControl_REST_API_User does not work with 404 error message.

Type
Support Solution
Published
2021-07-28
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP LTM: 12.1.3
Source
https://my.f5.com/manage/s/article/K73820426

Description

  • Customer wants to re-add an existing operator role into iControl_REST_API_User role using Patch method because the operator role in iControl_REST_API_User was deleted by Admin.
  • However, the Patch method is not working with 404 error message even though it was working fine when the operator role is added newly.
  • Error messages
[I][32821][22 Mar 2021 05:40:20 UTC][ForwarderPassThroughWorker] {"user":"local/leech","method":"PATCH","uri":"http://localhost:8100/mgmt/shared/authz/roles/iControl_REST_API_User","status":404,"from":"127.0.0.1"}

Environment

  • BIP-IP 12.1.3
  • A new operator role adding into  iControl_REST_API_User using Patch method is working fine.
  • However, the operator role re-adding into  iControl_REST_API_User using Patch method again after deleting it is not working with 404 (not found) error message.

Cause

Unknown 

Recommended Actions

Rebooting the device is helpful for customer to resolve the issue because the related DB information is corrupt.

  1. Login to the Configuration Terminal
  2. Navigate to System  > Configuration > Device > General
  3. Click Reboot
  4. Click OK
Additional Information

None.
