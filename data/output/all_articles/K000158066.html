Description

When resolving vCMP guest version discrepancies on BIG-IP systems (as described in K30356200: One or more slots of vcmp guest on the wrong version), administrators may need to delete and redeploy the vCMP guest’s virtual disk. By default, this process results in a newly deployed guest with factory settings and the default setup page, causing loss of previous configuration unless a backup is restored. This article provides best practices for preserving and restoring your vCMP guest configuration using UCS files during the redeployment process.

Environment

  • Product: BIG-IP LTM (vCMP)
  • Platforms: F5-VPR-LTM-C2400-AC, F100
  • Software Versions: All supported versions
  • Scenario: Remediation of vCMP guest version mismatch by deleting/redeploying the virtual disk as per K30356200: One or more slots of vcmp guest on the wrong version
  • Recent Action: vCMP guest upgrade or remediation requiring disk deletion/redeployment

Cause

Redeploying a vCMP guest by deleting its virtual disk erases all existing configuration data, resulting in a default/factory setup upon first boot.

Recommended Actions

To preserve your configuration when following K30356200 or similar procedures:

  1. Backup Configuration Before Redeployment
    - Log in to the affected vCMP guest.
    - Create a UCS archive of your current configuration:
    tmsh save sys ucs <filename>
    - Download the UCS file from the guest for safekeeping.
  2. Delete and Redeploy Guest Virtual Disk
    - Follow steps outlined in K30356200: One or more slots of vcmp guest on the wrong version to set the guest to "configured," delete its virtual disk, and redeploy it with the desired software version.
  3. Restore Configuration After Redeployment
    - Once the new vCMP guest is deployed and accessible, upload your saved UCS file to the guest.
    - Restore your previous configuration:
    tmsh load sys ucs <filename>
    - Confirm that services and settings are restored as expected.
  4. If No Backup Exists
    - Manually reconfigure all required settings on the newly deployed vCMP guest.

Note: Perform these actions during a maintenance window to avoid service disruption.

Additional Information

  • If you do not restore a UCS backup after redeployment, your vCMP guest will start with factory/default settings.
  • Always verify that backups are recent and complete before proceeding with any destructive operations.
  • For more details on UCS backup/restore procedures, see K13132: Backing up and restoring BIG-IP configuration using UCS files.
