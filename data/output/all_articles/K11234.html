Topic

The default BIG-IP system monitoring configuration includes preconfigured SNMP traps to enable communication with external Network Management Systems regarding events of interest occurring on the device. In some cases, when SNMP is configured to send traps, the preconfigured traps are unnecessary or may be problematic, or you may prefer to use a method other than SNMP for monitoring system events. For example, the volume of traps sent for a specific event may be excessive, thus reducing their value and possibly obscuring other events. You can prevent the BIG-IP system from sending preconfigured SNMP traps by modifying the default alertd configuration to include user alerts that match the preconfigured alerts, but do not include the snmptrap directive. Since the user alert configuration is loaded last, the modified version of the alert is used by the system, preventing the trap from being sent.

Note: Sending messages to a remote syslog server may provide more flexibility in filtering, monitoring, and archiving alert data purposes. For more information about configuring remote syslog logging, refer to the Configuration Guide for your product and version.

To prevent the BIG-IP system from sending a specific preconfigured SNMP trap, perform the following procedure:

  1. Log in to the command line.
  2. Examine the existing /etc/alertd/alert.conf file to locate the object identifiers (OID) for which you want to disable traps.

    Important: Do not edit the /etc/alertd/alert.conf file. All changes should be made to the /config/user_alert.conf file as detailed in the following steps. Changes to the alert.conf file may be lost.

  3. Copy the entire stanza containing the subject OID to the clipboard or a temporary file.

    For example, to disable the trap for CPU high temperature (OID .1.3.6.1.4.1.3375.2.4.0.4), copy the following stanza:

    alert BIGIP_SYSTEM_CHECK_E_CPU_TEMP_HIGH {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.4";
    lcdwarn description="CPU Temp too high." priority="3"
    }

  4. Back up the existing user_alert.conf file by typing the following command:

    cp /config/user_alert.conf /config/user_alert.conf.SOL11234

  5. Using a text editor, open the user_alert.conf file.
  6. Add to the user_alert.conf file the stanza you captured from the alert.conf file in step 3.
  7. Comment out the line beginning with snmptrap by prefixing the line with a # character.

    For example, the resulting stanza for CPU high temperature (OID .1.3.6.1.4.1.3375.2.4.0.4) would appear as follows:

    alert BIGIP_SYSTEM_CHECK_E_CPU_TEMP_HIGH {
    #snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.4";
    lcdwarn description="CPU Temp too high." priority="3"
    }

    Important: Comment out only the snmptrap OID= entry to prevent the associated trap from being sent. If you comment out the entire stanza, the trap will still be sent.

    Note: You can optionally suppress LCD display warnings by commenting the lcdwarn line within the stanza, if it exists.

  8. Save the changes made to the user_alert.conf file.
  9. Restart the alertd process to load the file changes by typing the following command:

    bigstart restart alertd

Traps will no longer be sent for the target OID for the message defined by the stanza.

Note: Some OIDs are used for multiple system messages. To disable all traps sent for some OIDs, you may have to modify multiple alert definitions using the previous procedure.
