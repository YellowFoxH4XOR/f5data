Topic

The lights-out processor (LOP) subsystem does not support you changing the root user's password when the BIG-IP host system is in single-user mode.

Description

This issue occurs because the LOP subsystem is turned off when the BIG-IP host system is in single-user mode for the following types of BIG-IP platforms:

  • BIG-IP 2000 series (C112)
  • BIG-IP 4000 series (C113)
  • BIG-IP 5000 series (C109)
  • BIG-IP 7000 series (D110)
  • BIG-IP 10000 series(D112/D113)
  • BIG-IP 12000 series (D111)

This behavior is by design.

When you change the root user's password in single-user mode, you may receive an LOP error. The password change is updated into the BIG-IP host system, but not on the LOP subsystem. The LOP subsystem error message may appear similar to the following example:

error: unable to obtain slot from LOP : send to lopd failed [lopd addr:/var/run/lopdsvr] [client addr:/var/run/bladectl.getslot.sock] (errno:2) No such file or directory

As a result, you will not be able to access the Always-On Management (AOM) menu over a secure shell (SSH) session to manage the BIG-IP platform with the new password.

Note: Although this error message may not appear when you attempt to change the root user's password in single-user mode of the BIG-IP platform running version 12.1.0 and later due to a separate issue, you are still required to perform the workaround to gain access to the AOM menu with the new password.

Recommendations

To address this issue, change the root user's password again after exiting from the single-user mode. Doing so updates the password change into the LOP subsystem. To do so, perform the following procedure:

Impact of procedure: The procedure involves changing BIG-IP system run levels, so F5 recommends that you perform this procedure only during a scheduled maintenance window.

  1. If you are currently logged in to single-user mode, type the following command to exit and return to multi-user mode:

    exit

    The BIG-IP system boots into run level 3, which is the multi-user mode.

    Note: If you have already exited single-user mode, you can skip this step.

  2. Log in to the BIG-IP host system using the new password that you entered before encountering the error message.
  3. To synchronize the password with the LOP subsystem, type the following command:

    passwd root

  4. Enter the new root user password (twice) that you entered before encountering the error.

    Note: Due to a separate issue for the BIG-IP 12.0.0 base build, you may need to run the /usr/bin/syncpwd command after changing the root password, to synchronize the password between the Traffic Management Operating System (TMOS) and LOP subsystem. For more information, refer to K05272632: BIG-IP AOM password sync vulnerability CVE-2015-8611.

  5. You can verify that the password change is working correctly by logging in again to the BIG-IP system using SSH or Console access.
