K000159910: VIP either not responding and responding with ACK. instead of SYN-ACK.

Description

Clients intermittently received 503 errors and failed to establish TCP connections through a BIG-IP LTM virtual server. Packet captures revealed that, instead of responding with SYN-ACK to incoming SYN packets, the BIG-IP was replying with ACKs, causing repeated client retransmissions and connection failures. The issue was traced to the BIG-IP maintaining a large number of connections in the FIN-WAIT-2 state, exhausting available connection slots and preventing new connections from being established.

 

 

Environment

BIG-IP LTM, version 17.5.1

Platform: F5-BIG-BR-R10900, C128

Virtual server using a TCP profile (tcp-lan-optimized) and HTTP profile

Pool of backend servers with TCP health monitors

Custom iRule for SNAT assignment

Default FIN-WAIT-2 timeout (300 seconds) on the TCP profile

 

 

Cause

Explicit Confirmation: The root cause was an excessive number of connections stuck in the FIN-WAIT-2 state on the BIG-IP due to clients not completing the TCP close sequence (not sending the final FIN). The default FIN-WAIT-2 timeout of 300 seconds caused these connections to accumulate, exhausting available connection slots and preventing new connections from being established. Lowering the FIN-WAIT-2 timeout allowed the BIG-IP to clear these stale connections more quickly, restoring normal operation.

 

 

Answer/Recommended Actions

Reduce the FIN-WAIT-2 timeout on the affected TCP profile from 300 seconds to 5 seconds:

Navigate to Local Traffic > Profiles : Protocol : TCP

Edit the relevant TCP profile

Under Timer Management, set "Fin Wait 2" to 5 seconds

Save and apply the changes

Monitor the system to ensure the issue does not recur.

Investigate and address the client-side behavior to ensure proper completion of the TCP close sequence for long-term stability by verifying the Apache TCP keepalive settings.
