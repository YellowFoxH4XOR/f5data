Topic

Depending on your requirements for securing networked systems to meet organizational security policies and industry standards, such as PCI compliance, you may want to modify the amount and types of access available on a default BIG-IQ configuration.

You should consider using the following recommendations under the following conditions:

  • You want to review or improve your currently configured access controls for the BIG-IQ system.
  • You want to secure access to the BIG-IQ system during initial setup.

Description

Each of the following sections provides information regarding access controls for various parts of the BIG-IQ configuration. You can evaluate each of the sections to determine if the specific configuration modification is appropriate for your environment.

  • Manage passwords and user accounts
  • Manage network access to the self IP and management interface
  • Monitor login attempts

Manage passwords and user accounts

During installation, the BIG-IQ system creates a default root user called root with the default password default. It also creates a default administrative user called admin with the default password admin. Strong passwords are fundamental to mitigating automated brute-force login attacks. F5 strongly recommends that you modify the passwords for BIG-IQ maintenance accounts from their default values. For information about how to modify passwords, refer to K13121: Changing system maintenance account passwords.

In addition to modifying the default accounts with strong passwords, you can create a security policy for generating passwords for local BIG-IQ system user accounts. For information about how to configure secure password policy, refer to K49507549: Configuring a secure password policy for the BIG-IQ system.

If a user account is not actively in use, you should remove it to prevent any possibility of inappropriate use. The default admin user account cannot be removed. If necessary, you can disable the default root user account and create an alternate root user account. For more information about creating an alternate root user account and disabling the default root user account, refer to the Creating an alternative root login account and Disabling the root shell login account using tmsh procedures in K15632: Disabling the admin and root accounts using the Configuration utility or tmsh.

Manage network access to the self IP and management interface

A BIG-IQ system provides administrative access to the user interface and SSH. By default, the BIG-IQ system allows all IP addresses to connect to the user interface and SSH on the management interface and self IP address. F5 recommends that you limit the exposure of administrative ports on the management interface and self IP address to only trusted and allowed IP addresses or IP ranges. Restricting access can help to mitigate security threats, such as DoS attacks or brute force attacks.

For information about restricting access to the BIG-IQ management interface, refer to K92748202: Restrict access to the BIG-IQ management interface using network firewall rules.

For information about restricting access to the BIG-IQ user interface by IP address, refer to K31401771: Restricting access to the BIG-IQ user interface by source IP address.

For information about restricting access to SSH by source IP address, refer to K5380: Specifying allowable IP ranges for SSH access.

If you have deployed your BIG-IQ with self IP address(es), F5 recommends that you review and determine if the port lockdown setting follows the idea behind the principle of least privilege. By default, the BIG-IQ system allows access to only a limited set of the available ports, and the default set includes those ports required for administrative access and inter-device communication.

For information about the list of ports necessary for the proper functioning of various BIG-IQ services and configurations, refer to K15612: Connectivity requirements for the BIG-IQ system.

For information about modifying the port lockdown settings for a self IP, refer to K39403510: Managing the port lockdown configuration on the BIG-IQ system.

Important: F5 strongly recommends that you consult your corporate business and security policies for guidelines regarding enabling administrative ports on management and self IP interfaces that are accessible to the Internet. More specifically, F5 strongly recommends that you consider disabling administrative ports (443 and 22), either directly or through an intermediate NAT device or firewall, on any management and self IP interfaces that are accessible to the Internet when there are no operational requirements for such access.

Monitor login attempts

Distributed brute-force login attacks use automated botnets to repeatedly attempt to log in to target hosts using a dictionary of potential usernames and passwords. If a weak password exists on user accounts configured on any system with public internet access, the password may be guessed. There is no way to completely prevent brute-force password attacks, but it is possible to mitigate the risk of such attacks with the recommendations in this article.

Other than applying mitigation techniques, monitoring login attempts to your system remains an important part of network security. The following list includes several, but not all, conditions that may indicate a brute-force attack:

  • A large number of failed logins from the same IP address
  • Login attempts with multiple accounts from the same IP address
  • Login attempts for a single account coming from many different IP addresses
  • Failed login attempts from alphabetically sequential account usernames

F5 strongly recommends that you monitor login attempts to the BIG-IQ system on an ongoing basis for the possibility of any unauthorized access. For information about how to monitor login attempts to your BIG-IQ system, refer to K08662997: Monitoring login attempts on the BIG-IQ system.
