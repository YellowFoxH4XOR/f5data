Issue

A monitor instance, which is the property of a BIG-IP LTM monitor, allows an administrator to disable or enable health checking for a particular node or pool member. Disabling a particular monitor instance is not the equivalent of downing a node or pool member; the BIG-IP system will continue to load balance traffic to a node or pool member whose monitor instance has been disabled. Disabling a particular monitor instance tells the BIG-IP system to temporarily stop monitoring a node or pool member, which is comparable in effects to dissociating a monitor from a pool, pool member, or node. However, disabling a particular monitor instance offers some advantages over removing a monitor altogether. For example, suppose that a pool is made up of ten pool members and that the HTTP monitor is assigned to the pool, you can disable a particular monitor instance to temporarily interrupt monitor traffic to one specific pool member, allowing the BIG-IP system to continue monitoring the other pool members in the pool.

BIG-IP LTM 9.0.0 through 9.2.5

In BIG-IP LTM 9.0.0 through 9.2.5, when you disable a monitor instance, the disabled status is saved to the bigip.conf file and the status is retained after a reboot or an upgrade. Additionally, if the BIG-IP system is the member of a high availability pair and the configuration is synchronized to the peer system, the peer system will also disable that particular monitor instance.

BIG-IP LTM 9.3.0 and 9.3.1

Starting in BIG-IP LTM 9.3.0, when you disable a monitor instance, the disabled status is not saved to the bigip.conf file and the disabled status reverts to enabled following a reboot or an upgrade. Consequently, if the BIG-IP system is the member of a high availability pair and the configuration is synchronized to the peer system, the peer system will not disable that particular monitor instance.

The following bigpipe command disables a monitor instance from the command line, and does not save the disabled status to the bigip.conf file even after typing the bigpipe save command.

bigpipe monitor <monitor_name> instance <node_ip>:<node_port> disable

For example, the following command sequence disables the 10.10.64.1:80 monitor instance for the http_test monitor, but does not save the disabled status to the bigip.conf file:

bigpipe monitor http_test instance 10.10.64.1:80 disable

bigpipe save

BIG-IP LTM 9.4.0

Beginning in BIG-IP 9.4.0, these versions behave almost identically to version 9.3.x. When you disable a monitor instance, the disabled status is not saved to the bigip.conf file. As in BIG-IP version 9.3.x, the change does not survive a software upgrade, configuration reload using bigpipe load or reload, and is not synchronized to the peer system during a ConfigSync operation. However, in BIG-IP versions 9.4.0 and later, the disabled status is saved within the mcpd database and does not revert to enabled following a restart of the services or a reboot. A disabled monitor instance will remain disabled until it is manually re-enabled by a BIG-IP administrator.
