Description:

This article aims to provide clarity on long request classification and buffer allocation within the BIG-IP ASM environment.

 

Environment:

Within the BIG-IP ASM environment, two default parameters are integral to the classification of requests:

request_buffer_size: 10K

long_request_buffer_size: 10M

 

Cause:

In scenarios where non-chunked requests are received, the determination of whether a request is "normal" or "long" hinges on its size in comparison to predefined thresholds. For instance:

  • Requests up to approximately 128K are considered normal and are allocated within the standard buffer pool size.
  • Requests exceeding this threshold are classified as long requests and are allocated within the long-request buffer.

It's noteworthy that the behavior differs when handling chunked requests.

Chunked requests, regardless of their size, are pre-allocated to a buffer pool size corresponding to the request_buffer_size parameter (by default 10kb). 

However, they are transferred to the long-request buffer when their accumulated size exceeds the request_buffer_size. 

Altering the request_buffer_size parameter impacts the allocation behavior for chunked requests, potentially influencing buffer utilization and request handling.

 

Recommended Actions:

While comprehending these mechanisms is vital for effective resource management, it's prudent to avoid excessive dependence on alterations to the internal parameter request_buffer_size, as such modifications can potentially disrupt system stability and degrade performance.

 

Additional information:

It's crucial to understand that within the F5 BIG-IP ASM environment, the maximum size for a long request is typically set to 10MB by default, defined by the long_request_buffer_size internal parameter. Whenever the accumulated size of incoming requests exceeds the threshold specified by long_request_buffer_size, the system has predefined actions:

- if the violation "Request length exceeds defined buffer size" is set to block, requests surpassing the specified buffer size are blocked with Support ID.

- if the violation "Request length exceeds defined buffer size" has the block flag disabled, requests may either be released (with only the initial 10K being inspected) or blocked due to any other violation found in initial 10K inspected.
