Description

Traffic policy does not support asterisk(*) in the HTTP URI section. It should be an explicit path instead of a wildcard.
This is because there are several options to be selectable such as starts-with, ends-with, or contains, and processes according to the condition type.

(*) URI path here is not case sensitive.

Environment

Traffic policy is in use with URI path

Recommended Actions

If the expectation is to apply the policy for URI path */test/*, the Suggestion is to use policy condition with uri path /test with "contain" instead of 'is' or 'start with' like other options. 

Additional Information

If policy condition has uri path /test with "contain", it covers /test, /test/, /test/*, and */test/*

request
- /test -- ok
- /test/ -- ok
- /aa/test/ -- ok
- /test/aa -- ok

However, if the uri path is set with "contain" /test/, /test or /aa/test is not covered by it.

request
- /test -- no
- /test/ -- ok
- /aa/test/ -- ok
- /aa/test -- no
- /test/aa -- ok
