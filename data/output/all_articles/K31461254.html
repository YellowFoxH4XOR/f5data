Description
After you enable sys db bigd.tmm, http monitors begin to fail.

The following logs are present in /var/log/ltm when sys db log.tma.level value debug

Feb 11 10:16:58 bigip1 debug tmm[28032]: 01ad0017:7: Monitor Agent TMM 0: sent probe: MID 3
Feb 11 10:16:58 bigip1 debug tmm[28032]: 01ad0019:7: Monitor Agent TMM 0: received probe response: MID 3, reason TMA_RESULT_FAIL(Probe response lost due to transient failure), info 0
Feb 11 10:16:58 bigip1 debug tmm[28032]: 01ad0009:7: Monitor Agent TMM 0: sent NOTIFY message: MID 3, seqno 159, status down

Environment

  • BIG-IP LTM
  • sys db bigd.tmm value enable
  • HTTP Monitor with a custom SEND string.

Cause

TMM Monitors enforce RFC 2616 more strictly than bigd monitors did.
The http monitor send string has a space is configured just before an HTTP header.
 
Example Valid and Invalid Send String
 Send String
InvalidGET / HTTP/1.1\r\n Host: example.com\r\nConnection: Close\r\n\r\n
ValidGET / HTTP/1.1\r\nHost: example.com\r\nConnection: Close\r\n\r\n

This has been Enhancements Bug ID 1013937 and Bug ID 1016973

Recommended Actions

Identify all monitors with a space before a header

  1. SSH to log into the Advanced Shell (bash) prompt of a BIG-IP

  2. Run the following command to identify all affected monitors:
    tmsh -c 'cd /;list /ltm monitor recursive' | grep -e '^ltm monitor' -e '^    send' | grep -B1 -P '(\\r|\\n){1,2}\s+.' --color

    Example Output:
    ltm monitor http Common/example_http {
        send "GET / HTTP/1.1\r\n Host: example.com\r\nConnection: Close\r\n\r\n"

  3. For every monitor identified, you must remove the offending space.

    Example:

       send "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: Close\r\n\r\n"

Enable TMM Monitor Agent (TMA) Debug Logging

  1. SSH to log into the Advanced Shell (bash) prompt of a BIG-IP

  2. Enable TMA Logging
    tmsh modify /sys db log.tma.level value debug

  3. Review /var/log/ltm for messages similar to the following:
    Feb 11 10:16:58 bigip1 debug tmm[28032]: 01ad0017:7: Monitor Agent TMM 0: sent probe: MID 3
    Feb 11 10:16:58 bigip1 debug tmm[28032]: 01ad0019:7: Monitor Agent TMM 0: received probe response: MID 3, reason TMA_RESULT_FAIL(Probe response lost due to transient failure), info 0
    Feb 11 10:16:58 bigip1 debug tmm[28032]: 01ad0009:7: Monitor Agent TMM 0: sent NOTIFY message: MID 3, seqno 159, status down

  4. Disable TMA Logging
    tmsh modify /sys db log.tma.level value notice

Enable Pool Member Monitor Logging

  • See K12531: Troubleshooting health monitors for details on enabling Pool Member Monitor logging.
