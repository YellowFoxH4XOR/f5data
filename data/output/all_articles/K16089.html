Known Issue

BIG-IP systems in which the BIG-IP APM system was previously provisioned may be unable to perform software installations or save UCS archive files.

This issue occurs when the following conditions are met:

  • The BIG-IP APM module was previously provisioned, but is not currently provisioned on the system.
  • No other modules that use the MySQL database are provisioned on the system. For example, neither the BIG-IP ASM system nor the BIG-IP Analytics (AVR) system are provisioned.

Impact

Attempts to install software or hotfix images fail or hang at 0%. Attempts to save UCS archive files fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H678586 on the Diagnostics > Identified > Medium screen.
  • Software installations fail, or hang at 0%.

    For example, the tmsh show /sys software command shows that the installation hangs at 0%:

    Sys::Software Status
    Volume Product Version Build Active Status
    -------------------------------------------------------------
    HD1.1 BIG-IP 11.4.1 608.0 no complete
    HD1.2 BIG-IP 11.4.1 608.0 no installing 0.000 pct
    HD1.3 BIG-IP 11.4.1 608.0 yes complete

  • Scripts or processes that rely on the ability to automatically create a UCS archive fail or hang.

Workaround

To work around this issue, you can either provision a module that uses the MySQL database (for example, BIG-IP APM, BIG-IP ASM, or BIG-IP Analytics) and then restart the installation, or modify the /usr/libdata/configsync/cs.dat file. To do so, perform one of the following procedures:

Provisioning a module that uses the MySQL database

Impact of workaround: Provisioning modules allocates additional CPU, memory, and disk resources on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Resource Provisioning.
  3. Change Access Policy (APM) (or other module that uses MySQL) to Nominal.
  4. Click Submit.
  5. After provisioning the BIG-IP APM system (or other module that uses MySQL), you can restart the BIG-IP installation.

Modifying the /usr/libdata/configsync/cs.dat file

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To remount the /usr file system in read-write mode, type the following command:

    mount -o remount,rw /usr

  3. To back up the /usr/libdata/configsync/cs.dat file, type the following command:

    cp /usr/libdata/configsync/cs.dat /usr/libdata/configsync/cs.dat.SOL16089

  4. Use a file editor to edit the /usr/libdata/configsync/cs.dat file.

    For example:

    vi /usr/libdata/configsync/cs.dat

  5. Locate the following section in the file:

    # APM Local User Database
    save.1400.save_pre = (/usr/bin/ldbutil --backup --file="/var/apm/localdb/restore.sql")
    save.1400.file = /var/apm/localdb/restore.sql
    save.1400.save_post = (rm -f /var/apm/localdb/restore.sql)

  6. Comment out the save.1400.* lines.

    For example:

    # APM Local User Database
    # save.1400.save_pre = (/usr/bin/ldbutil --backup --file="/var/apm/localdb/restore.sql")
    # save.1400.file = /var/apm/localdb/restore.sql
    # save.1400.save_post = (rm -f /var/apm/localdb/restore.sql)

  7. Save the changes and exit the file.
  8. To remount the /usr file system back to read-only mode, type the following command:

    mount -o remount,ro /usr

  9. Restart the BIG-IP installation.
