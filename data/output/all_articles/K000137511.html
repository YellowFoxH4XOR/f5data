Description

A request containing a URL-encoded character within the URL and specified verbatim within the Bot Defense profile's Whitelist configuration results in the exception not working as expected and the request continuing to get blocked if a bot signature gets detected.

Environment

Configuring URL Whitelist within Bot Defense profile with the URL involving percent-encoded characters

Cause

When the request URI involves a percent-encoded character and is specified verbatim within the Bot Defense profile's Whitelist configuration, the exception does not work and the request will get blocked if a bot signature gets detected. This is expected behavior due to the fact that dosl7d process decodes the URL-encoded request before parsing and running bot signatures through the request, so it doesn't find a matching whitelisted URL configuration that is previously in place.

Recommended Actions

The Bot Defense profile's Whitelist configuration must be configured such that the URL's corresponding decoded value is specified instead of it's percent-encoded value.

For example, if the URL in question is /example%3A+some+path, then the recommended Whitelist configuration that should be specified is /example!+some+path.

Additional Information

The recommendation works for multi-byte encoded characters as well. The decoded version of those characters can be configured within the Whitelist configuration and incoming requests that comprising of multi-byte encoding will result in them being decoded before the whitelist configuration comes into play to allow the request.
