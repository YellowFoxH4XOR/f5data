Known Issue

This is the result of a known issue. The OneConnect feature works with HTTP Keep-Alive headers to allow the BIG-IP system to minimize the number of server-side TCP connections by making existing connections available for reuse by other clients.

When an HTTP/1.0 client issues a request to a OneConnect-enabled virtual server and receives a response containing the Connection: close HTTP header, the BIG-IP system properly closes the client-side of the connection, but incorrectly makes the server-side connection available for reuse. The BIG-IP system then attempts to send subsequent client requests over the same server-side connection, which causes the server to close the connection without servicing the request. Since the server has indicated that it will close the connection, the server-side connection should not be reused after the response is delivered.

F5 Product Development tracked this issue as CR82404 and it was fixed in BIG-IP version 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, Hotfix-BIG-IP-9.3.1-HF3 has been issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

To work around this issue, you can configure an iRule with the ONECONNECT::detach iRule command. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule.
  6. Enter the following iRule in the Definition box:

    when HTTP_RESPONSE {
    if {[HTTP::header Connection] equals "close"}{
    ONECONNECT::detach enable
    }
    }
  7. Click Finished.
