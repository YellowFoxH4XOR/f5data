Known Issue

An HTTP response with a traffic steering action may cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • The BIG-IP PEM virtual server that is receiving the HTTP response is not associated with an attached HTTP profile. Therefore, the BIG-IP system establishes a server-side connection without waiting for the HTTP request from the client.
  • You install a steering policy as a result of a configuration change. For example, you replace a traffic policy with another policy that contains a steering policy.
  • The server responds with an HTTP Request Timeout message.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and your active system fails over to the standby system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The active BIG-IP system temporarily fails to process traffic and fails over to the standby system.
  • The BIG-IP system generates a TMM core file to the /shared/core/ directory.

Workaround

There is no work around for this issue. However, you can avoid this issue by ensuring that you have an HTTP profile associated with the BIG-IP PEM virtual server, if you want the virtual server to manage the HTTP response that involves a steering policy.
