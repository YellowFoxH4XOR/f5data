Topic

For information about load balancing NFS in BIG-IP 9.x, refer to K6749: Load balancing NFS.

This solution contains the following two NFS load-balancing examples:

  • Using wildcard ports for NFS load balancing (recommended)
  • Using static ports for NFS load balancing

NFS load balancing is not recommended for sessions where users are performing read/write requests to servers, because there is no mechanism to ensure the servers have the same content.

For example, if a user connects to 1.1.2.1 and writes a file called myfile.txt, this file will not be included on 1.1.2.2. Writing a program/shell script or Perl script could potentially solve this synchronization issue, but this is not a part of the functionality of BIG-IP.

Using wildcard ports for NFS load balancing

The following example provides you with the commands to configure wildcard ports for NFS load balancing. This is the recommend method for NFS load balancing. For your configuration, replace the IP addresses in the example with the IP addresses specific to your virtual servers and nodes.

Example:

  1. To create a virtual server of 1.1.1.1:0 that uses the nodes 1.1.2.1:0 and 1.1.2.2:0 as NFS servers, type the following commands:

    b pool nfs { persist_mode simple simple_mask 255.255.255.0 simple_timeout 86300 member 1.1.2.1:0 member 1.1.2.2:0 }

    b service 0 tcp enable
    b service 0 udp enable
    b service 0 timeout tcp 3600
    b service 0 timeout udp 3600
    b virtual 1.1.1.1:0 use pool nfs

  2. Save the configuration, by typing the following command:

    b save

  3. After you have set up and saved the configuration, test the connection from your client using the virtual server address. To do this, type the following command:

    mount -tnfs 1.1.1.1:[mount-point] /mnt

Using static ports for NFS Load balancing

Some Berkley Software Design (BSD) implementations use NFS servers with static ports. In this case, you can also use static ports to load balance NFS. This method is not recommended because it will not work with all types of NFS server implementations.

To set up static ports for NFS load balancing, perform the following steps:

  1. Create a pool with a wildcard port (port 0) for each node (as described in the previous example.)
  2. Create port-specific virtual servers so BIG-IP will not pass every port.
  3. Enable the global persist across_services variable.

    Note: The global persist across_services variable affects all virtual servers.

The following example provides you with the commands to configure static ports for NFS load balancing. For your configuration, replace the IP addresses in the example with the IP addresses specific to your virtual servers and nodes.

Example:

To create a virtual server of 1.1.1.1:0 that uses nodes 1.1.2.1:0 and 1.1.2.2:0 as NFS servers, type the following commands:

b global persist across_services enable
b service 927 udp enable
b service 111 udp enable
b service 111 tcp enable
b service 2049 udp enable
b virtual 1.1.1.1:927 use pool nfs
b virtual 1.1.1.1:2049 use pool nfs
b virtual 1.1.1.1:111 use pool nfs

Testing the Connection

After you have set up and saved the configuration, test the connection from your client using the virtual server address. To do this, type the following command:

mount -tnfs 1.1.1.1:[mount-point] /mnt
