Description

After removing a logical volume via the configuration utility or tmsh the volume is not fully removed from the system


Environment

BIG-IP


Cause

For unknown reasons, when trying to delete a logical volume via the configuration utility or via tmsh delete sys software volume HDx.x the volume is not completely deleted from the system taking up space on the disk. As an example when running the lvscan command you observe the following:


[root@hostname.example.com:Active:Standalone] ~ # lvscan


ACTIVE '/dev/vg-db-sda/dat.maint.1' [300.00 MiB] inherit

ACTIVE '/dev/vg-db-sda/dat.share' [20.00 GiB] inherit

ACTIVE '/dev/vg-db-sda/dat.appdata' [50.00 GiB] inherit

ACTIVE '/dev/vg-db-sda/dat.log' [2.93 GiB] inherit

ACTIVE '/dev/vg-db-sda/dat.swapvol' [1000.00 MiB] inherit

ACTIVE '/dev/vg-db-sda/set.3._usr' [6.09 GiB] inherit

ACTIVE '/dev/vg-db-sda/set.3._config' [2.17 GiB] inherit

ACTIVE '/dev/vg-db-sda/set.5.root' [440.00 MiB] inherit

ACTIVE '/dev/vg-db-sda/set.5._usr' [6.09 GiB] inherit

ACTIVE '/dev/vg-db-sda/set.5._config' [2.17 GiB] inherit

ACTIVE '/dev/vg-db-sda/set.5._var' [4.50 GiB] inherit


In this example we have removed the HD1.3 volume but it is still showing up in an lvscan:


ACTIVE '/dev/vg-db-sda/set.3._usr' [6.09 GiB] inherit

ACTIVE '/dev/vg-db-sda/set.3._config' [2.17 GiB] inherit


Recommended Actions

In the above example you can remove the unwanted volumes using the lvremove command:


# lvremove /dev/vg-db-sda/set.3._usr

# lvremove /dev/vg-db-sda/set.3._config
