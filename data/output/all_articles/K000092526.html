K000092526: Azure BIG-IP was unable to process traffic after failover

Type
Support Solution
Published
2022-11-03
Updated
2022-11-05
Source
https://my.f5.com/manage/s/article/K000092526

Description

Devices failed over due to loss of HA communication. The devices were Active-Active for few seconds until the communication was re-established. Previous Active device was LTM1, and the new active device is LTM2. There was an outage because the Virtual Servers did not switch to the new device.

Environment

  • BIG-IP Virtual Edition deployed in High Availability in Azure Cloud
  • Virtual machines Network Interfaces not configured for Accelerated Networking
  • High Availability failover traffic configured to pass through only internal vlan
  • Internal vlan process shared user and High Availability failover traffic

Cause

High Availability failover traffic shared via the internal vlan dropped due to high throughput load.

Recommended Actions

There are three options available to resolve the issue:

Configure failover via management interface for resilience.
K14135: Defining network resources for BIG-IP HA features (11.x - 16.x)

Upgrade Azure Network Interfaces to Accelerated Networking.
What is Accelerated Networking?

Add additional Network Interface dedicated for High Availability failover traffic.
Add a network interface to an existing VM
 

Additional Information

Although all recommended actions will help alleviate the problem of packet loss it is highly recommended to have the High Availability failover traffic via the management interface for resilience. Failover traffic going through TMM interfaces only can result in momentary active/active when TMM goes down. High Availity failover traffic configured via the management interface offers resilience which prevents transient active/active when TMM interface goes down.
