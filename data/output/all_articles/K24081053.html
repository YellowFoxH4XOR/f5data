Description

   Pool members send 400 Bad request for Client Hello to Virtual server, and client can not succeed HTTP/HTTPs connections.
   Server side connection you will find similar to below flow:

- 172.16.0.10: Virtual server as client (often snat or auto map is used)
- 172.16.0.20: pool member

   2 2019-07-15 09:17:32.967318    172.16.0.20   172.16.0.10   1        TCP        IN  s1/tmm0 : 1443 → 22412 [SYN, ACK] Seq=0 Ack=1 Win=28960 Len=0 MSS=1460 SACK_PERM=1 TSval=3728330855 TSecr=4109124518
   3 2019-07-15 09:17:32.967326    172.16.0.10   172.16.0.20   1        TCP        OUT s1/tmm0 : 22412 → 1443 [ACK] Seq=1 Ack=1 Win=4380 Len=0 TSval=4109124519 TSecr=3728330855

   6 2019-07-15 09:17:32.967928    172.23.0.20   172.16.0.10   1        HTTP       IN  s1/tmm0 : HTTP/1.1 400 Bad Request


   This shows

  1. packet # 1-3:  3WHS is success (no issue in TCP level)
  2. packet # 4   :  Virtual server send "Client Hello" (initiated SSL handshake)
  3. packet # 6   :  Backend server send "HTTP code 400 Bad request." (SSL handshake is not recognized)
     

Environment

  • Server ssl profiles is configured in the Virtual Server in trouble.
  • SSL handshake with backend server never succeed.
     

Cause

   Pool members don't support SSL.
 

Recommended Actions

  • Remove Server SSL profile from the virtual server.

      or

  • Configure pool members to support SSL.
     

Additional Information

   To capture tcpdump on client side and server side in one file

# tcpdump -ni0.0:nnnp host <client_IP_addr> -s0 -w /var/tmp/<captured_file_name>.pcap
- <client_IP_addr>: client IP address
- <captured_file_name>: File name for the packet capture
