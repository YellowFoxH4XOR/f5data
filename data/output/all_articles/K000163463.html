K000163463: BIG-IP APM API Protection profile "Responses" tab stuck on "Loading..." in the GUI

Type
Support Solution
Published
2026-09-30
Updated
2026-09-30
Applies to
  • BIG-IP
  • BIG-IP APM: 21.X.X, 21.1.X, 21.1.0, 21.0.X, 21.0.0
Source
https://my.f5.com/manage/s/article/K000163463

Description

When opening an API Protection security profile in the BIG-IP Configuration utility, the Responses tab may remain stuck on "Loading..." and never populate. This can occur consistently, or intermittently after an initial successful load (e.g., the tab loads once in a fresh/incognito browser session but fails on subsequent attempts).

Inspection of the HTTP requests and responses using the browser's Development tools showed that a GET request issued by the GUI received an HTTP 429 Too Many Requests response instead of the expected data, at the same time the tab was stuck on "Loading...". The GUI did not display any visible error message to the user when this occurred.

Environment

  • BIG-IP APM with an API Protection security profile configured
  • BIG-IP version 21.1.0 (iControl REST API rate limiting was introduced in 21.1.0 per K000161088)

Cause

Starting in BIG-IP 21.1.0, iControl REST requests to the /mgmt endpoint are subject to rate limiting, controlled by three sys httpd DB variables (documented in K000161088). The API Protection profile management GUI may attempt (depending on the configuration size) too many requests for the configured rate limiting settings.

Recommended Actions

  1. Using the browser's development tools, verify if accessing the problematic page shows HTTP 429 responses.
  2. Check the current rate-limiting values on the BIG-IP, and evaluate whether increasing them helps resolve the issue:
    tmsh list sys httpd api-ratelimit
