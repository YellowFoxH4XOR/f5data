K56083564: ''Bad credential stuffing service request'' message in /var/log/asm

Type
Support Solution
Published
2022-09-02
Updated
2023-02-21
Applies to
  • VIPRION Platforms
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP ASM: 16.1.3, 16.1.2, 16.1.1, 16.1.X, 16.1.0
Source
https://my.f5.com/manage/s/article/K56083564

Description

/var/log/asm shows similar entries to the ones listed below:

- event code C617 Bad credential stuffing service request. Message from service: API key not found.
- event code C677 credential stuffing service is unparseable or there is some network configuration issue
- event code C617 Bad credential stuffing service request. Message from service: Authorization header or Bearer scheme not found.

Environment

  • BIG-IP ASM

Cause

The device does not have a valid Blackfish API key/license for credential stuffing detection.

Recommended Actions

In the WebUI, go to 'Security ›› Cloud Services : Cloud Security Services Applications ›› f5-credential-stuffing-cloud-app' to validate there is a valid Blackfish API key/license for credential stuffing detection.

If this feature is needed, you can purchase online through the cloud services dashboard without contacting an F5 sales representative. 
 

Additional Information
If you don't need this feature, and you want to make these logs entries to go away, you will need to disable usage of Leaked Credential detection in brute force settings across all policies.

You will also need to verify that setting for Distributed Brute Force Protection: Detect Leaked Credential Stuffing Attack. Changing this setting to "never" in each login page/brute force page should remove the check.
