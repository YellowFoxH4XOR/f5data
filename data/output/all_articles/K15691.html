Known Issue

The Traffic Management Microkernel (TMM) process may restart and produce a core file when using the TCP::close iRule command within a CLIENTSSL_CLIENTCERT event.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server that uses an iRule.
  • The iRule contains the TCP::close command within a CLIENTSSL_CLIENTCERT event.
  • The virtual server processes traffic that triggers the CLIENTSSL_CLIENTCERT event.

Impact

If the BIG-IP system is a member in a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until the TMM process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H477103 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system fails over to another host in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system temporarily fails to process traffic.

Workaround

There is no workaround for this issue. However, to mitigate the issue, avoid using the TCP::close iRule command in a CLIENTSSL_CLIENTCERT event.
