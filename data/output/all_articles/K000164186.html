K000164186: ASM bd Process Restarts in a Loop When an SMTP Virtual Server Has Protocol Security Enabled Without a TCP Profile

Type
Support Solution
Published
2026-11-10
Updated
2026-11-10
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000164186

Description

The ASM bd process restarts repeatedly. The HA daemon sod logs the following messages and takes the device offline:

01140029:4: HA proc_running bd fails action is go offline and down links

010c0050:5: Sod requests links down

010c0054:5: Offline for traffic group traffic-group-1

Environment

  • BIG-IP ASM 17.5.1.x
  • BIG-IP systems in an HA pair with traffic-group-1
  • Virtual server with ip-protocol tcp, an SMTP profile attached, and no /Common/tcp profile in its profile list
  • SMTP profile with security enabled (defaults-from /Common/smtp)

Example configuration that triggers the issue:

ltm virtual <virtual_server_name> {
    ip-protocol tcp
    profiles {
        <smtp_profile_name> { }
    }
}
ltm profile smtp <smtp_profile_name> {
    defaults-from /Common/smtp
    security enabled
}

Cause

An SMTP profile is attached to a TCP virtual server that has no /Common/tcp profile. TMM cannot complete proxy initialization for this virtual server. The bd_smtp plugin channel does not come up, bd times out, and it restarts in a loop.

Recommended Actions

  1. Before making changes, identify every virtual server that has an SMTP profile with security enabled and confirm whether each one has /Common/tcp attached.
  2. Add tcp profile for each affected virtual server.

    tmsh modify ltm virtual /Common/<virtual_server_name> profiles add { /Common/tcp }
    tmsh save sys config

  3. After applying the change, confirm that the bd process stays running and that sod no longer logs 01140029.

Additional Information

  • After an upgrade, ASM runs post-upgrade processing, including MySQL database and table updates. This can take about 1 second to 5 minutes per ASM policy, depending on the number and complexity of policies. Allow this time before making changes that restart processes. This processing does not cause the bd restart loop described in this article.
  • Re-licensing the device does not resolve this issue.
  • Enabling security on an SMTP profile does not require a /Common/tcp profile to be attached to the virtual server, but the virtual server cannot initialize without one. Configuration validation does not currently reject this configuration.
