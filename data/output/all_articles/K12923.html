Issue

In BIG-IP 9.x, the BIG-IP host subsystem uses the same initial sequence numbers (ISN) after a TCP handshake timeout period of 20 seconds. This applies to administrative traffic that the BIG-IP system generates, such as monitor traffic or SNMP traffic.

For example, packet 1 shows bigd initiating a new monitor connection to a pool member with a TCP Synchronize (SYN) packet. Packets 2 and 3 are SYN packet retrasnmissions sent prior to the TCP handshake timeout. Packet 4 shows the BIG-IP system creating a new TCP connection for monitor traffic using the same ISN:

1 0.000000 10.12.23.137 10.12.23.27 TCP 74 52370 > http [SYN] Seq=3506555312
2 3.000160 10.12.23.137 10.12.23.27 TCP 74 52370 > http [SYN] Seq=3506555312
3 9.000718 10.12.23.137 10.12.23.27 TCP 74 52370 > http [SYN] Seq=3506555312
4 21.002081 10.12.23.137 10.12.23.27 TCP 74 52370 > http [SYN] Seq=3506555312
5 45.004437 10.12.23.137 10.12.23.27 TCP 74 52370 > http [SYN] Seq=3506555312

Beginning in BIG-IP 10.x, the BIG-IP host subsystem adheres to RFC 1948 when generating ISN for new TCP connections. RFC 1948 proposes a TCP implementation that helps deter sequence number guessing attacks by using a hash algorithm to generate ISN.

For example, packet 1 shows bigd initiating a new monitor connection to a pool member with a TCP Synchronize (SYN) packet. Packets 2 and 3 are SYN packet retrasnmissions sent prior to the TCP handshake timeout. Packet 4 shows the BIG-IP system creating a new TCP connection for monitor traffic using a different ISN:

1 0.000000 10.12.23.120 10.12.23.27 TCP 74 58216 > http [SYN] Seq=145327997
2 2.997901 10.12.23.120 10.12.23.27 TCP 74 58216 > http [SYN] Seq=145327997
3 8.998022 10.12.23.120 10.12.23.27 TCP 74 58216 > http [SYN] Seq=145327997
4 20.998061 10.12.23.120 10.12.23.27 TCP 74 58216 > http [SYN] Seq=189360803
5 44.998661 10.12.23.120 10.12.23.27 TCP 74 58216 > http [SYN] Seq=239688803

This change was made as a result of ID 220508 (formerly CR33990).
