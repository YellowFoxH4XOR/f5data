K000152256: The SSL Offloading feature may not work for applications using TDS (Tabular Data Stream) protocol

Type
Support Solution
Published
2025-06-30
Updated
2025-07-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000152256

Description

TDS is a proprietary protocol developed by Microsoft and Sybase that facilitates communication and data exchange between the client and the SQL Server. In TDS versions prior to 8.0 (used in SQL Server versions before SQL Server 2022), the client and server would first establish a plaintext handshake after the TCP connection is established. During this session, the client and server negotiate various capabilities, including whether encryption should be used.  If encryption (TLS/SSL) was negotiated, the connection would then upgrade to an encrypted TLS session after the negotiation step.

 

Starting with TDS version 8.0 (introduced with SQL Server 2022), the protocol was modified for stronger security. In this version and later, if TLS is enabled, the TLS session is established immediately after the TCP connection, and before any TDS packets are exchanged.

 

Environment

  • BIG-IP
  • Virtual server with Client SSL Profile
  • SQL Server

Cause

Due to communication flow in TDS version prior to 8.0, the BIG-IP is not able to establish TLS/SSL connection with the client. If you have virtual server configured with the Client SSL Profile, the BIG-IP expects to receive from the client a TLS/SSL “Client Hello” message immediately after TCP 3-way-handshake. However in TDS versions prior to 8.0 the TLS/SSL handshake can be established only after the session's capabilities negotiation. When the BIG-IP receives TDS data instead of a Client Hello, the connection gets terminated. At the same time you may observe similar error messages to be logged into /var/log/ltm log file:

 

warning tmm[<PID>]: 00000001:1: 10.10.10.10:36134 -> 10.20.20.20:1433: Connection error: ssl_passthru:5935: alert(40) not SSL

 

Recommended Actions

  • For affected applications (e.g., older Microsoft SQL Server versions), configure the virtual server as a Performance (Layer 4) type to pass traffic without attempting SSL offload.
