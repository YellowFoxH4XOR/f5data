Description

ASM triggers false-positive attack signature violation on valid JSON payload similar to: "{\"Key\":\"value\"}"

Environment

  • ASM Security Policy.
  • JSON Content Profile with Parse Parameters option enabled (v13.0.0 and UP).

Cause

ASM treats the above JSON payloads as a valid JSON string, not an object. therefore, it cannot tokenize it into key and value.

Recommended Actions

Below iRule should convert JSON string to a compliance JSON object:

Note. This iRule won't revert the payload to original state before passing it to backend server

Note. This iRule works on requests contains Content-Type HTTP Header.

when HTTP_REQUEST {
    if {[HTTP::method] eq "POST" && [HTTP::header value Content-Type] contains "json"} {
        # Read the Content-Length
        set content_length [HTTP::header Content-Length]

        # Trigger the collection of the HTTP payload with the size from Content-Length
        if {$content_length > 0} {
            HTTP::collect $content_length
        }
    }
}

when HTTP_REQUEST_DATA {
    if {[info exists collected_payload]} {
        # Save the current chunk to the payload
        append collected_payload [HTTP::payload]
    } else {
        set collected_payload [HTTP::payload]
    }

    # Ensure full payload is received
    if {[string length $collected_payload] == $content_length} {

       set json_replaced_1 [string map -nocase [list \"\{ \{ \\\" \" \\\\ "" \}\" \} %22%7B %7B %5C%22 %22 %5C%5C "" %7D%22 %7D] $collected_payload]
       set json_replaced_2 [string map -nocase [list \"\{ \{ \}\" \} %22%7B %7B %7D%22 %7D] $json_replaced_1]
       unset json_replaced_1
       set json_replaced_3 [string map -nocase [list \"\[ \[ \]\" \] %22%5B %5B %5D%22 %5D] $json_replaced_2]
       unset json_replaced_2


       # Update the HTTP payload and headers with the transformed JSON
       HTTP::payload replace 0 [HTTP::payload length] $json_replaced_3
       HTTP::header replace Content-Length [string length $json_replaced_3]

       unset json_replaced_3
    }
}

when HTTP_REQUEST_RELEASE {
    if {0 && [info exists collected_payload]} {
        set x {clientside {HTTP::payload replace 0 [HTTP::payload length] $collected_payload}}
        eval $x
        unset collected_payload
    }
}

Use below iRule if we need to repackage the JSON payload to its original state before passing it to backend server:

when ASM_REQUEST_DONE {
    if {[info exists collected_payload]} {

    #Will create a loop to add the original payload 10000 at a time.
    #First we'll start by clearing the ASM::payload

        ASM::payload replace 0 [ASM::payload length] ""

    # Offset counter   
        set offset 0
        set chunk_size 10000
    
    # Loop through the payload 10000 bytes at a time

        while { $offset < $content_length } {
            # Get a chunk of up to 10000 bytes
            set chunk [string range $collected_payload $offset [expr {$offset + $chunk_size - 1}]]

            # Replace at the correct offset
            ASM::payload replace $offset 0 $chunk

            # Move the offset forward
            incr offset $chunk_size
        }

        HTTP::header replace content-length [ASM::payload length]

        unset collected_payload
    }
}
