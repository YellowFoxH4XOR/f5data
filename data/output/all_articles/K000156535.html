K000156535: Connections reset after SSL handshake when using SNAT pool

Type
Support Solution
Published
2025-09-25
Updated
2025-09-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000156535

Description

When performing SSL handshake between a client and F5 BIG-IP LTM, followed by F5 to server, connections may be reset by the BIG-IP after certificate exchange. Packet captures show successful client-side connection establishment, but the BIG-IP resets the connection to the client after failing to initiate a server-side connection. Server-side statistics indicate zero packets/bytes out, and TCP retransmit timeouts are observed. Example log:

[F5RST(peer): TCP retransmit timeout]

Environment

  • BIG-IP
  • SNAT pool

Cause

The SNAT pool member IP address used for source translation is not configured as a Self IP on the BIG-IP device and is not bound to any VLAN. The BIG-IP cannot source traffic from this address, resulting in failure to establish server-side connections and causing connection resets after SSL handshake.

Recommended Actions

  • Define a new Self IP address on the BIG-IP device that includes the SNAT pool member IP.
  • Ensure the Self IP is explicitly associated with the VLAN corresponding to the egress interface (the interface through which BIG-IP routes traffic to pool members).
  • Alternatively, modify the virtual server configuration to use SNAT Automap. Automap ensures that BIG-IP selects a valid Self IP on the egress VLAN for SNAT translation, eliminating dependency on an incorrectly defined or un-associated SNAT pool address.
