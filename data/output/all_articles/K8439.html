Topic

This article applies to BIG-IP 9.4.2 - 10.x. For information about other versions, refer to the following articles:

  • K13206: Configuring local host name resolution for BIG-IP (11.x)
  • K3625: Configuring local host name resolution for BIG-IP (4.5.x - 9.4.1)

You must enable name resolution on the BIG-IP system to resolve DNS names at the command line. Name resolution may be required for some optional configurations, such as email delivery.

The BIG-IP system uses two sources of information when attempting to resolve DNS names. First the system attempts local hostname resolution by checking for a matching entry in the local /etc/hosts file. If the name cannot be resolved locally, the system attempts to use DNS to resolve the name. Local hostname resolution can be more efficient for hostnames whose addresses seldom change.

Note: For information about configuring DNS name resolution for the BIG-IP system, refer to K8437: Configuring BIG-IP to resolve DNS hostnames (9.x - 10.x).

In BIG-IP versions prior to 9.4.2, you can modify the local /etc/hosts file directly to manage entries for local hostname resolution. Beginning in BIG-IP 9.4.2, the /etc/hosts file is an auto-generated file. If you modify the file directly, the changes will be lost when the system restarts. Remote host entries are instead added to the BIG-IP configuration using the appropriate bigpipe commands. When these objects are modified, or when the BIG-IP configuration is loaded, the local /etc/hosts file is automatically regenerated including the remote host objects defined in the BIG-IP configuration.

Use the following procedures to make persistent changes to the BIG-IP configuration and to the /etc/hosts file:

  • Adding remote host definitions
  • Deleting a single remote host
  • Displaying remote host definitions
  • Testing local name resolution for remote hosts

Note: For information about configuring local host name resolution for BIG-IP versions 9.0.0 - 9.4.1, refer to K3625: Configuring local host name resolution for BIG-IP (4.5.x - 9.4.1).

Note: Beginning in BIG-IP 9.4.2, the /etc/hosts file is an auto-generated file. If you modify the file directly, the changes will be lost when the system restarts.

Adding remote host definitions

  1. Log in to the command line.
  2. Define the remote host in the BIG-IP configuration by typing a command similar to the following example:

    bigpipe system remote host <host> { addr <IP_Addr> \ hostname <FQDN> }

    In the previous example, note the following:

    • Replace <host> with a unique object name within the BIG-IP configuration.
    • Replace <IP_Addr> and <FQDN> with the IP address and the fully-qualified domain name of the host that should be inserted into the local /etc/hosts file.

    For example, to define a remote host object named webserver with an IP address of 10.10.10.1 and a hostname of www.askf5.net, type the following command:

    bigpipe system remote host webserver { addr 10.10.10.1 \ hostname www.askf5.net }

  3. Type the following command to save the configuration:

    bigpipe save

    The BIG-IP configuration now contains the following object:

    system {
    remote host webserver {
    addr 10.10.10.1
    hostname "www.askf5.net"
    }
    }

    The local /etc/hosts file is now configured with the following entry:

    10.10.10.1 www.askf5.net

When the BIG-IP configuration is loaded, the local /etc/hosts file is automatically re-generated including the remote host objects defined in the BIG-IP configuration.

Deleting a single remote host

  1. Log in to the command line.
  2. Remove a single remote host in the BIG-IP configuration by typing a command similar to the following:

    bigpipe system remote host <host> delete

    Replace <host> with the remote host entry's unique object name within the BIG-IP configuration.

    For example, to delete a remote host object named webserver, type the following command:

    bigpipe system remote host webserver delete

  3. Type the following command to save the configuration:

    bigpipe save

The matching entry has been removed from the BIG-IP configuration and the local /etc/hosts file.

To delete all remote hosts, perform the following procedure:

  1. Log in to the command line.
  2. Remove all remote hosts in the BIG-IP configuration by typing a command similar to the following:

    bigpipe system remote host all delete

  3. Type the following command to save the configuration:

    bigpipe save

All remote host entries have been removed from the BIG-IP configuration and the local /etc/hosts file.

Displaying remote host definitions

To display the names of all remote hosts defined in the BIG-IP configuration, type the following command:

bigpipe system remote host show

The command displays output that appears similar to the following example:

SYSTEM - Remote Host:
+-> REMOTE HOST www
+-> REMOTE HOST ftp

To display the configuration of all remote hosts defined in the BIG-IP configuration, type the following command:

bigpipe system remote host list

The command displays output that appears similar to the following example:

system {
remote host {
www {
addr 10.10.10.1
hostname "www.askf5.net"
}
ftp {
addr 10.10.10.2
hostname "ftp.askf5.net"
}
}
}

To display the contents of the local /etc/hosts file, type the following command:

less /etc/hosts

The command displays output that appears similar to the following example:

Testing local name resolution for remote hosts

To test the local host name resolution, use the following command syntax, replacing <name> with the fully-qualified domain name you added to the BIG-IP configuration:

ping <name>

For example:

ping www.askf5.net

If the test is successful, you receive a response that includes an IP address that appears similar to the following:

PING www.askf5.net (10.10.10.1) 56 bytes of data.

If the test is not successful, you receive a response that appears similar to the following:

ping: unknown host www.askf5.net
