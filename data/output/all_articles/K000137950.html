Description

How do I renew an expiring api.f5.com certificate ?

/var/log/ltm may have similar to the below log:

warning tmsh[<PID>]: 01420008:4: Certificate 'CN=XXXXX-XXXXX-XXXXX-XXXXX-XXXXX,OU=BIG-IP,O=F5 Networks Inc,L=Seattle,ST=Washington,C=US' in file /Common/f5_api_com.crt will expire on Dec 23 13:15:44 2023 GMT
 

Environment

  • BIG-IP / BIG-IQ
  • any version
  • SSL certificate

Cause

Certificate expiring: /config/ssl/ssl.crt/f5_api_com.crt
To check the certificate expiry date, run the following command from CLI:

openssl x509 -in /config/ssl/ssl.crt/f5_api_com.crt -text -noout
 

Certificate:
   Data:
       Version: 3 (0x2)
       Serial Number: 203271 (0x31a07)
       Signature Algorithm: sha256WithRSAEncryption
       Issuer: O = F5 Networks Inc, CN = F5 PRD Issuing Certificate Authority F5API-PI V2
       Validity
           Not Before: Dec 23 13:14:02 2020 GMT
           Not After : Dec 23 13:14:02 2023 GMT 
       Subject: C = US, ST = Washington, L = Seattle, O = F5 Networks Inc, OU = BIG-IP, CN = XXXXX-XXXXX-XXXXX-XXXXX-XXXXXXX
       Subject Public Key Info:
           Public Key Algorithm: rsaEncryption
               RSA Public-Key: (4096 bit)
               Modulus:

 

Recommended Actions

  1. (Optional) In the UI, remove the expired f5_api_com.crt by navigating to System ›› Certificate Management ›› Traffic Certificate Management ›› SSL Certificate List.
  2. (Optional) Remove the old/expired physical certificate from the BIG IP, and use the following command from CLI:
    # rm /config/ssl/ssl.crt/f5_api_com.crt
  3. (Optional) Remove the private key to force a new one to be generated: 
    # tmsh delete sys crypto key f5_api_com.key
  4. Reactivate the license. For steps please refer to K7752: Licensing the BIG-IP system

    Important: This process briefly interrupts traffic processing while the BIG-IP system reloads the configuration. Please follow this in a maintenance window.

  5. Navigate to System ›› Certificate Management ›› Traffic Certificate Management ›› SSL Certificate List, click f5_api_com and verify the certificate. 
  6. If the "Certificate Subject(s)" shows "No certificate", You may check whether there is an api_cert section under /config/bigip.license file. If no such value is found you should open a case to F5 Support with those details, otherwise, please proceed with the below steps.
  7. You may verify whether the dates of the certificate /config/ssl/ssl.crt/f5_api_com.crt is updated by

openssl x509 -in /config/ssl/ssl.crt/f5_api_com.crt -noout -dates -serial

  1. If it is NOT updated, you may use the below method to retrieve the certificate from the license file, otherwise, you can skip this step.
cp /config/ssl/ssl.crt/f5_api_com.crt /config/ssl/ssl.crt/f5_api_com.crt.backup
grep api_cert /config/bigip.license | awk '{print $4}' | base64 -d > /config/ssl/ssl.crt/f5_api_com.crt
  1. Then you may manually create the certificate in TMOS using either of the below method

Option 1, Using GUI: click the Import button. Then,

a) click "Paste Text" and paste the new content of /config/ssl/ssl.crt/f5_api_com.crt in the "Certificate Source" box.

or

b) click "Upload File" and upload the new file /config/ssl/ssl.crt/f5_api_com.crt.

Option 2, Using CLI: you may use:

tmsh create sys file ssl-cert f5_api_com.crt source-path file:///config/ssl/ssl.crt/f5_api_com.crt

tmsh save sys config
