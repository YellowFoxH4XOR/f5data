Known Issue

This is the result of a known issue. In BIG-IP version 10.1.0, the minimum TCP retransmission timeout was reduced from 1 second to 300 milliseconds. This change was made to improve performance over lossy, high bandwidth networks, such as Wi-Fi networks. However, under certain conditions, this shorter timeout interval may be too aggressive, and the BIG-IP system may prematurely terminate active TCP connections. Additionally, this change may increase network congestion and server load, due to the larger number of retransmissions.

Note: The minimum TCP retransmission timeout is not a configurable option in the TCP profile.

Note: For more information about the change in behavior, refer to K11073: Change in Behavior: The minimum TCP retransmission timeout was changed in BIG-IP version 10.1.0.

F5 Product Development tracked this issue as CR139609, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.1.0-3372.0-HF1, which has been issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
