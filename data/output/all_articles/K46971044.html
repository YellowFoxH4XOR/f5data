Known Issue

If Auto-Sync is enabled and a very high volume of configuration changes are sent in quick succession, it is possible for a peer system to fall behind in synchronizations.  When this occurs, the device becomes exponentially further behind due to extra sync data, which can lead to the sending mcpd process running out of memory and producing a core file.

This issue occurs when all of the following conditions are met:

  • Auto-Sync is enabled in an high availability (HA) pair.
  • Sustained configuration changes numbering in the hundreds or thousands are made in rapid succession over several minutes.

Impact

The sending mcpd process runs progressively slower as memory is consumed and fails when all system memory is exhausted.  Devices in an HA configuration may experience a failover event.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You see many hundreds or thousands of messages with a syntax similar to the following in the /var/log/ltm log file:

    Incremental sync started: This system is updating the configuration on device group /Common/<DEVICEGROUP> device %cmi-mcpd-peer-/Common/PEER from commit id { 5748 6610441018580267714 /Common/<THISSYSTEM> } to commit id { 5761 6610452932920257900 /Common/<THISSYSTEM> }.

    Incremental sync started: This system is updating the configuration on device group /Common/<DEVICEGROUP> device %cmi-mcpd-peer-/Common/PEER from commit id { 5749 6610441018582132455 /Common/<THISSYSTEM> } to commit id { 5764 6610452932920257900 /Common/<THISSYSTEM> }.

    Incremental sync started: This system is updating the configuration on device group /Common/<DEVICEGROUP> device %cmi-mcpd-peer-/Common/PEER from commit id { 5764 6610441018544245662 /Common/<THISSYSTEM> } to commit id { 5768 6610452932920257900 /Common/<THISSYSTEM> }

    In these examples, <DEVICEGROUP> is the name of the device group in which this host is located, and <THISSYSTEM> is the name of this host in the device group.

    Note: The highlighted commit IDs in the previous examples are within the range of 5478 - 5761, 5749 - 5764, and 5764 - 5768.  In these cases, there is overlap in the ranges among incremental sync messages.  For example 5478-5761 overlaps with the ranges of 5749-5764.  This overlap indicates a high probability that the device is experiencing the issue.

Workaround

To work around this issue, you can avoid sending very high volumes of configuration changes in an auto-sync configuration.

Impact of workaround: None
