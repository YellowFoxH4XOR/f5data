Known Issue

On rare occasions, the TMM or bd process may produce a core file after you reboot a device or join a device to a trust domain.

This issue occurs when the following conditions are met:

  • Application Security is enabled for the virtual server.
  • The virtual server is configured with one of the following profile types:
     
    • Fraud Protection Service (FPS) profile
    • DoS Protection Profile

Impact

The BIG-IP system fails to pass traffic while the TMM or bd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H522941 on the Diagnostics > Identified > High screen.
  • The TMM or bd process produces a core file within 24 hours of either rebooting the device, or joining a trust domain.
  • Messages similar to the following example are logged to the /var/log/ts/bd.log file:

    BD_MISC|CRIT |<date - time>|12345|signals.c:0055|Received SIGSEGV - Core Dumping

Workaround

To work around this issue, you can perform the following procedure:

Impact of workaround: Restarting TMM temporarily interrupts traffic processing, and devices that are configured as a high-availability pair may fail over.

  1. Log in to the BIG-IP command line.
  2. Use a text editor to edit the /etc/bigstart/scripts/datasyncd file.

    For example:

    vi /etc/bigstart/scripts/datasyncd

  3. Locate and remove the following line:

    exec /usr/share/datasync/bin/datasyncd >> /var/log/datasync/datasyncd.log

  4. Replace the previous line with the following:

    exec >> /var/log/datasync/datasyncd.log 2>&1
    echo "`date`: fix start."
    set -x
    tmsh list security datasync local-profile
    tmsh list security datasync local-profile | grep '^security' | awk '{print $4}' | while read -r table; do tmsh modify security datasync local-profile $table max-gen-rows infinite; done
    tmsh list security datasync local-profile
    set +x
    echo "`date`: fix end."
    exec /usr/share/datasync/bin/datasyncd

  5. Save the changes and exit the file.
  6. To restart TMM, type the following command:

    bigstart restart tmm
