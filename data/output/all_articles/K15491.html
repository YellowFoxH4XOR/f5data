Known Issue

Using the verify option with the tmsh load sys config command may disrupt the high availability (HA) connection and disconnect the internal device service clustering (DSC) state.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to use HA.
  • The verify option is used with the from-terminal or file <file> options for the tmsh load sys config command.

    For example:

    • tmsh load sys config from-terminal verify
    • tmsh load sys config file /config/bigip.conf verify

DSC provides the framework for configuration synchronization (ConfigSync) and other HA features, such as failover for BIG-IP device groups. The verify option, when used in the load sys config from-terminal or load sys config file <file> commands, is meant to ensure that a configuration pasted to the terminal or loaded from a file is valid, but does not take effect. However, when the verify option is used in this context, the internal DSC state, including HA connections to other devices, may be lost.

Impact

The BIG-IP system may lose the HA connection with a BIG-IP peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ltm file, you observe messages similar to the following example:

    notice mcpd[7206]: 0107143c:5: Connection to CMI peer /Common/bigip2.askf5.local has been removed
    notice mcpd[7206]: 01071435:5: Disconnecting from CMI peer 10.10.10.12 as a result of a reconfiguration
    notice mcpd[7206]: 01071435:5: Disconnecting from CMI peer 10.10.10.12 as a result of a reconfiguration
    notice mcpd[7206]: 0107143c:5: Connection to CMI peer 10.10.10.12 has been removed

  • The Master Control Program Daemon (MCPD) state transitions to a high-config-load-failed status.

    For example:

    tmsh show /sys mcp-state

    -------------------------------------------------------
    Sys::mcpd State:
    -------------------------------------------------------
    Running Phase running
    Last Configuration Load Status high-config-load-failed

  • Peer devices will indicate a ConfigSync status of Disconnected. For information about verifying ConfigSync statuses, refer to K13946: Troubleshooting ConfigSync and device service clustering issues (11.x - 13.x).
  • The ConfigSync status will appear as Changes Pending, and attempts to perform a ConfigSync will fail.

Workaround

To recover from this issue, you can load the full configuration. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To load the full configuration, type the following command:

    load sys config partitions all

Note: Loading the configuration will restore the HA connection, but you must perform a ConfigSync to clear the Changes Pending status.

To prevent this issue, you can include the merge option with your tmsh load/verify command. To do so, perform the following procedure:

Impact of workaround: The merge option keeps the existing configuration and adds or modifies only what is entered with the command.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To verify your configuration changes, type the following command:

    load sys config from-terminal merge verify

  3. When finished making changes, type the command from step 2 without the verify option, as follows:

    load sys config from-terminal merge

  4. Save the change by typing the following command:

    save config
