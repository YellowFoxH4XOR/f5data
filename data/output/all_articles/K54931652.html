Description

Virtual server has an iRule applied to enable SNAT based on pool member IP.

SNAT is not applied when connecting through the virtual server.

Environment

  • SNAT
  • iRule

Cause

Missing route domain notation in the iRule.

ltm rule /Common/snat_irule_1 {
    when LB_SELECTED {
        if {[IP::addr [LB::server addr] equals 10.10.10.1]} {
            snatpool /Common/my_snat_pool_1            ^^^______!!
            }
        elseif {[IP::addr [LB::server addr] equals 10.10.10.2]} {
            snatpool /Common/my_snat_pool_2                ^^^__!!
            }
    }
}

Virtual server, pool and SNAT pool all reside in a route domain:

ltm virtual /Common/my_vs_1 {
    destination /Common/10.10.30.80%1:80
    ip-protocol tcp               ^^^_______!!
    rules {
        /Common/snat_irule_1
    }
    <..>
}

ltm pool /Common/my_pool_1 {
    <..>
    members {
        /Common/10.10.10.1:any {
            address 10.10.10.1%1
            <..>             ^^^________!!
        }
        /Common/10.10.10.2:any {
            address 10.10.10.2%1
            <..>             ^^^________!!
        }
    }
    <..>
}

ltm snatpool /Common/my_snat_pool_1 {
    app-service none
    description none
    members {
        10.10.10.95%1
    }             ^^^_______!!
    partition Common
}

In this situation, the iRule will execute and look for a matching IP in route domain 0; the connection will not match the if or elseif logic, and no SNAT will be applied.

Recommended Actions

Add correct route domain notation to the iRule.

For example:

ltm rule /Common/snat_irule_1 {
    when LB_SELECTED {
        if {[IP::addr [LB::server addr] equals 10.10.10.1%1]} {
            snatpool /Common/my_snat_pool_1              ^^^______ Correct
            }
        elseif {[IP::addr [LB::server addr] equals 10.10.10.2%1]} {
            snatpool /Common/my_snat_pool_2                  ^^^__ Correct
            }
    }
}

Note: These changes will only apply to new connections handled by the virtual server.
