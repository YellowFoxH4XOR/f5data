K000148900: BIG-IP VE shows the wrong logical disk is in use after major version upgrade

Type
Support Solution
Published
2025-06-03
Updated
2025-06-03
Source
https://my.f5.com/manage/s/article/K000148900

Description

A BIG-IP VE system with more than one virtual disk attached can have its boot drive appear to change (ie. from HD1 to HD2) after upgrading between major releases. This leaves the control plane in an inconsistent state and several daemons such as mysqld, monpd and ipsd can be seen crashing.

Environment

  • BIG-IP VE
  • More than one virtual disk is attached to the virtual machine
  • BIG-IP software upgrade

Cause

Due to a difference in how disk drivers are loaded in different BIG-IP software release versions, disk device name ordering can sometimes change and lead to this issue. ID1756921 has been raised to ensure that HD1 always maps to the same hard disk drive even if the underlying device name changes across reboots.

Recommended Actions

If any of the disk drives attached to the virtual machine are unused, then detach them from the virtual machine to resolve the issue. Alternatively, you may be able to influence disk ordering by ensuring that all virtual disks are attached to virtual disk controllers of the same type and rearranging how the virtual disk images map to the configured virtual controllers. For an example under ESXi you can check the external article: SCSI disk enumeration order for virtual machines in the vSphere Client
