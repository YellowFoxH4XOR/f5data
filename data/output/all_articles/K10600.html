Known Issue

This is the result of a known issue. BIG-IP 1600 and 3600 platforms running BIG-IP version 9.4.7 or 9.4.8 are unable to use up to 760M of system memory. The platforms contain 4 GB of RAM, and version 9.x systems do not run the Physical Address Extension (PAE) kernel, which enables the system to use more than 4 GB of physical memory. BIG-IP version 10.x systems run the PAE kernel and are not affected by this issue.

Note: Systems with 4 GB of physical memory are affected by this issue because pageable memory pushes the memory boundary above 4 GB.

For example, a BIG-IP 3600 platform running version 9.4.7 with 4 GB of RAM will report the following when the bigpipe memory show command is run:

MEMORY STATISTICS -- | (Host) Total = 3.182GB Used = 3.137GB | (TMM) Total = 2.560GB Used = 29.35MB

In the example, the Host total should display the total amount of memory contained in the unit. Instead, the command reports only 3.182 GB of RAM.

Note: For more information about how the total physical memory is displayed by the bigpipe memory command in version 9.4.7 and later, refer to K10099: Change in Behavior: The bigpipe memory show command now displays the total physical memory.

F5 Product Development is tracking this issue as ID 323687 (formerly CR126106).

Workaround

Important: This workaround applies to only 3600 platforms running version 9.x BIG-IP WebAccelerator or BIG-IP Application Security Manager.

The memory utilization issue can be problematic for 3600 platforms running BIG-IP WebAccelerator or BIG-IP ASM version 9.4.7 or 9.4.8. The default memory provisioning leaves a minimal amount of RAM for the BIG-IP WebAccelerator pvac process or the BIG-IP ASM bd process. For example, based on the example bigpipe memory output, approximately 622 MB of RAM is available for the pvac process and other userland processes. This amount of memory is inadequate for most BIG-IP WebAccelerator deployments.

If you are running BIG-IP WebAccelerator or BIG-IP ASM version 9.x on the 3600 platform, you may need to allocate more memory to the Host. To do so, perform the following procedure:

Important: Provisioning 1.5 GB of RAM to the Host leaves slightly less than the 1.5GB minimum recommended RAM for the BIG-IP LTM. If the system processes connection loads where TMM would experience memory pressure from this tuning, F5 advises that you contact F5 Technical Support prior to completing this workaround.

  1. Log in to the command line.
  2. Enter the following command:

    bigpipe db Provision.extraMB 1536

  3. Enter the following command to reboot the system:

    reboot
