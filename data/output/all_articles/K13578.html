Known Issue

Description

The show file-history virtual-service command does not work as documented, and may return incomplete results.

This issue occurs when either of the following conditions is met:

  • You enter the show file-history virtual-service command without supplying a value for the file attribute.
  • You enter the show file-history virtual-service command with the path attribute alone, and the location does not contain at least one file.

The ARX CLI Reference Guide indicates that the show file-history virtual-service command takes the path option either alone or with the file option.

The documentation suggests that entering a pathname alone yields output that appears similar to the following example:

Query Parameters
----------------

Virtual Server: virtsrv.corp.com
Export: Export1
Start date: 04/13/2012
End date: 04/24/2012
File Name:
Path: /
Archive: All
Case Sensitive: No
Recurse: No
Verbose: No

Archive:           filehistarc
Hosting Switch:    ARX1000-1 (switch UUID is displayed here)
 
------------------------------------------------------------------------------
 Archive Date/Time: 04/13/2012 23:04:00 +0000
 Global Server:     myserver.corp.com
 WINS Name:
 WINS Aliases:
 Dynamic DNS Names:
 VIP:               xxx.xxx.xxx.xxx
 Namespace:         namespace01
 Volume Path:       /
 File Server(s):
 Shared Path: \\netapp01\cifs4
 Physical Path: /vol/vol1/cifs4\

Impact

The show file-history virtual-service command returns incomplete results.

Symptoms

When issuing the show file-history virtual-servicecommand, and the path that you enter does not contain at least one file, the system displays incomplete results. As a result, the output reports only the query parameters.

For example:

Query Parameters

----------------

Virtual Server: virtsrv.corp.com
Export: Export1
Start date: 04/13/2012
End date: 04/24/2012
File Name:
Path: /
Archive: All
Case Sensitive: No
Recurse: No
Verbose: No
