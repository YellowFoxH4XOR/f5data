K000092639: HTTP response status codes do not match the result of the file import/export operations

Type
Support Solution
Published
2022-11-20
Updated
2023-07-18
Source
https://my.f5.com/manage/s/article/K000092639

Description


When importing a file via the command line interface (via HTTP POST), HTTP response status codes may not reflect the result of the file import/export operations.

A 200 OK HTTP response may be provided, when a user should expect a 201 Created HTTP response for successful transfers.

An example of a successful file transfer. Note the incorrect HTTP Status code.
 

  {
    "f5-utils-file-transfer:local-file": "images/staging/F5OS-C-1.2.2-12471.PARTITION.iso",
    "f5-utils-file-transfer:remote-url": "https://<snip>/partition/images/F5OS-C-1.2.2-12471.PARTITION.iso"
  }
  EOF

  HTTP/1.1 200 OK
  Date: Mon, 12 Nov 2022 18:42:20 GMT
  Server: Apache/2.4.6 (CentOS) OpenSSL/1.0.2q-fips
  Cache-Control: private, no-cache, must-revalidate, proxy-revalidate
  Content-Length: 147
  Content-Type: application/yang-data+json
  Pragma: no-cache
  X-Auth-Token: <snip>
  Content-Security-Policy: default-src 'self'; block-all-mixed-content; base-uri 'self'; frame-ancestors 'none';
  Strict-Transport-Security: max-age=15552000; includeSubDomains
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  X-XSS-Protection: 1; mode=block

  {
    "f5-utils-file-transfer:output": {
      "result": "File transfer is initiated.(images/staging/F5OS-C-1.2.2-12471.PARTITION.iso)"
    }
  }

 

Environment

  • rSeries Appliance
  • F5OS

 

Cause


HTTP response status codes may not reflect the result of the file import/export operations if a path given is not an allowed path.
 

Recommended Action

None. Please note the incorrect HTTP Status code is a cosmetic issue.
