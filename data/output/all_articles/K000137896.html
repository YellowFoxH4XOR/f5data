Description

A blade fails to join the Kubernetes cluster (showing "Not In Cluster") and the Orchestration Manager is not starting correctly. Moreover, this scenario does not fit the resolution from article VELOS blades not ready, stuck in "Adding to Cluster" or "Not in Cluster", server gave HTTP response to HTTPS client (f5.com) because the --insecure-registry entry in the file /etc/sysconfig/docker is already present.

1. If a blade fails to join the cluster, the output of "show cluster orchestration-manager" shows the state "Not In Cluster":

Environment

VELOS blade shows as Not In Cluster

VELOS blade does belong to a partition

--insecure-registry entry in the file /etc/sysconfig/docker is already present

Cause

The blade's failure to join the cluster is linked to an issue with the OMD pull process.

In turn, the Orchestration Manager's failure is due to an incorrect Docker registry port configuration, resulting from a reboot after the initial setup.

The system attempts to pull from a non-existent port 2002, whereas the correct ports for this version should be 2004 (base services version) or 2504 (patch services version).

Recommended Actions

Conduct a system reboot of both system controllers. This should initialize the base services registry on the correct port.

After the reboot, allow at least 30 minutes for the system to stabilize and recheck the status of the blade addition and Orchestration Manager.

Additional Information

If your blade does not have the --insecure-registry entry in the file /etc/sysconfig/docker, please check the article below.
