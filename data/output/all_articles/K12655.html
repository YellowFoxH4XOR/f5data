K12655: The BIG-IP WebAccelerator system responds with an incorrect value for the Age header when using the Ecommerce policy

Known Issue

This is the result of a known issue. If you configure the Ecommerce policy and do not select the Ignore no-cache HTTP headers in the response setting, and the origin web server (OWS) responds with a max-age directive in the Cache-Control header (Cache-Control: max-age=n), the BIG-IP WebAccelerator system subtracts a few seconds from the configured Maximum Age under the WebAccelerator Cache Settings section of the Lifetime policy and uses this value for the Age response-header in all of its client-side responses. As a result, the next cache entity may expire content in an inconsistent manner and may request content from the BIG-IP WebAccelerator more frequently than expected.

The correct behavior is for the BIG-IP WebAccelerator to respond to the client with an Age response-header starting at zero and adding increments until the number reaches the configured Maximum Age under the WebAccelerator Cache Settings section of the Lifetime policy.

Note: Although the BIG-IP WebAccelerator system calculates the Age response-header incorrectly, the system honors the max-age directive from the OWS and re-validates the content when the content expires.

F5 Product Development tracked this issue as ID 350319, and it was fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.
