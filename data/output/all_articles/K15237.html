Known Issue

When the BIG-IP Edge Client access session experiences a lost connection, the connection may not automatically recover.

This issue occurs when all of the following conditions are met:

  • You are using the BIG-IP Edge Client when initiating an access session.
  • The destination BIG-IP APM access profile's Fully Qualified Domain Name (FQDN) is resolved by a BIG-IP GTM wide IP with a low time to live (TTL) value.
  • The BIG-IP GTM wide IP high-availability configuration contains multiple resolution addresses.
  • The system sends the initial access session connection to the BIG-IP APM system using HTTP, and then the BIG-IP APM system redirects the connection to HTTPS.
  • The BIG-IP Edge Client access session is established, and the connection fails, causing the BIG-IP Edge Client to attempt a reconnection.

Impact

The initial access session recovery fails, causing the system to initiate a new access session, which requires the user to re-authenticate.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • If a user loses connectivity during an established access session, the BIG-IP Edge Client initiates a new access session, requiring the user to re-enter their credentials.
  • When the access session fails, the Edge Client uses the FQDN resolution IP address of the failed connection when attempting to recover the lost connection.
  • End users may receive an error message that the Edge Client configuration is corrupted.
