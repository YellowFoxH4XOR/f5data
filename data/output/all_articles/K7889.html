Known Issue

This is the result of a known issue. When using a Mobile E-mail favorite, the FirePass controller should prompt the user for the credentials to the email account if the credentials have not been configured by the FirePass administrator in the user's account details, or supplied by the server used to authenticate the user to FirePass. However, when using a client other than a full browser, such as a smartphone or PDA, FirePass fails to prompt for some or all of the credentials needed to properly configure the email account. As a result, users may be unable to login to the email account, or they may be able to log in, but the From: field in email headers may be left blank when sending email from their account.

By default, when a user launches a Mobile E-mail favorite, the FirePass controller uses the FirePass login credentials (username and password) to log in to the email server. Additionally, the name and email address used in the From: field of outgoing emails are taken either from the information in the FirePass user database (for a local user) or from the information supplied by the authentication server of the user's master group (for an external user). Administrators can select the source of user information with the Logon Information drop-down menu on the Portal Access: Mobile E-Mail page.

If this user information is not available or if the FirePass user credentials are different from those of the email server, the FirePass controller will prompt the user to enter the information for the email server (Name, User Name, E-mail address, Password) after the user launches the Mobile E-mail favorite. However, when users log in to the FirePass controller using a client other than a full browser, such as a smartphone or PDA, FirePass may fail to prompt for some or all of the four items needed to properly configure the email account. The FirePass controller may prompt for User name and Password, but not the full name and email address. Or the FirePass controller may not prompt for any credentials, and instead display a blank page.

In the former case, users will be able to access their email account, but when users compose emails, the From: field in the SMTP header, which normally would include a full name and a return email address, will be blank. Some SMTP servers will send the emails with a blank From: field; some servers will return the composed email with an error. In the latter case, the user will be unable to access their email account.

External users are affected by this issue if their master group authenticates to a server that does not supply the information needed (Name, User Name, E-mail address, Password), the Mobile E-mail favorite is not configured to query an LDAP server for the information, or the FirePass cannot reach the configured LDAP server. Local users (accounts in the FirePass database) that are affected by this issue typically do not have the following fields configured, located under the User's Details section:

  • First Name
  • Last Name
  • Middle Initial
  • Email

The User's Details section is accessed by editing the user on the Users: User Management page.

F5 Product Development tracked this issue as CR81211, and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue was fixed in Cumulative Hotfix HF-601-5 for FirePass version 6.0.1 and in Cumulative Hotfix HF-552-10 for FirePass version 5.5.2. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

To view a list of the latest available hotfixes, refer to K10322: FirePass hotfix matrix.

Workaround

Users who can access their email accounts can click the Settings button in the Mobile E-mail interface, and enter the remaining information in the Display Name and E-mail address fields.
