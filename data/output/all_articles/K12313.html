Known Issue

This is the result of a known issue. The BIG-IP system will only respond with a full SSL handshake for the client certificate request during SSL session renegotiation if the client does not send an SSL resumption session ID in the ClientHello request.

Note: This behavior occurs regardless of whether the Client SSL profile is configured with the Client Certificate parameter set to request or require.

Note: Generally, Internet Explorer browsers do not send an SSL resumption session ID in the ClientHello request during SSL session renegotiation. However, Safari and Firefox browsers always send an SSL resumption session ID in the ClientHello request.

F5 Product Development tracked this issue as ID 226971 (formerly CR142479), and it was fixed in BIG-IP 10.2.1. For information about upgrading, refer to the BIG-IP LTM, WebAccelerator, APM, and EDGE Gateway release notes.

This issue was fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP 10.2.0. You may download this hotfix or a later version of the hotfix from the F5 Downloads site.
