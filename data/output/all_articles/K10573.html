Known Issue

This is the result of a known issue. The big3d process leaks memory when external monitors are configured. This issue occurs because the environment variables associated with each external monitor instance are not freed after the monitor completes. For most external monitor implementations, the amount of memory leaked is small, and may not be evident until the monitors have been running for several months. However, if you have configured a large number of external monitors that use multiple environment variables, such as the LDAP monitor, the memory leakage is accelerated and may affect system performance after only a short period of time.

F5 Product Development tracked this issue as CR121396 and it was fixed in BIG-IP GTM 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

If you are unable to upgrade to BIG-IP GTM 9.4.8, you can work around this issue by monitoring the big3d process and restarting the big3d process when memory usage exceeds 50 MB.

To monitor memory usage by the big3d process, enter the following command:

top p `pidof big3d`

The memory used by the big3d process is displayed in kilobytes in the SIZE column. For example, the following output indicates the process is using a total of 2,668 KB, or 2.6 MB:

To restart the big3d process and recover the memory, enter the following command:

bigstart restart big3d

Alternatively, you may replace the external monitors with an alternative monitor type, such as TCP or TCP halfopen.
