Known Issue

When the quota bucket timeout parameters are configured as zero, and the validity timer expires, the Credit-Control-Request Update (CCR-U) is not set.

This issue occurs when the Policy and Charging Rules Function (PCRF) system does not grant any Granted-Service-Units (GSU), as the quota is configured as zero, with only the validity timer configured with a value.

Impact

The online charging system (OCS) does not get the CCR-U message and misses the information about the quota.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The CCR-U is not sent out after the validity timer expires.

Workaround

To work around this issue, depending on your environment, you can configure the quota bucket timeout parameters with a suitable non-zero value by modifying the BIG-IP system database variables.

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

The configurable BIG-IP system database variables for the quota bucket timeout parameters of a BIG-IP PEM session are as follows:

  • tmm.pem.session.quota.bucket.denied.timeout
  • tmm.pem.session.quota.bucket.depleted.timeout
  • tmm.pem.session.quota.bucket.idle.timeout

To set a value for the BIG-IP system database variables, use the following TMOS Shell (tmsh) command syntax:

tmsh modify /sys db <Quota_Bucket_Timeout_Variable> value <Non-Zero_Value>

For example:

tmsh modify /sys db tmm.pem.session.quota.bucket.denied.timeout { value "1" }
tmsh modify /sys db tmm.pem.session.quota.bucket.depleted.timeout { value "2" }
tmsh modify /sys db tmm.pem.session.quota.bucket.idle.timeout { value "3" }
