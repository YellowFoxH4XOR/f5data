K000133109: Root password reset is not working

Type
Support Solution
Published
2023-03-22
Updated
2025-04-01
Applies to
  • BIG-IQ
  • BIG-IP
  • F5OS
Source
https://my.f5.com/manage/s/article/K000133109

Description

When trying to reset the root password the change does not save or you are unable to reach the grub menu there are a few issues that commonly occur. Below is what those are and how to work around them.

Cause 

  • VE devices require you to remove the console=ttys0 line
  • Ensure that the root account isn't disabled
  • TACACS secrets with # (number, pound) sign may disable the root and admin accounts
  • AWS doesn't display the grub boot menu to enable single user mode

Recommended Actions

VE devices require you to remove the console=ttys0 line

When starting BIG-IP or BIG-IQ Virtual Edition in single user mode, you should additionally delete the console=ttyS0  line, leaving only console=tty0. If skipped, the BIG-IP or BIG-IQ VE will boot and  may not display the prompt or the procedure may work fine but the password will not be rest after boot.

Ensure that the root account isn't disabled

Important: The BIG-IP system is unavailable for the duration of the following procedure. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Connect a terminal to the BIG-IP serial console port. For a VIPRION system, connect a terminal to the serial port on one of the VIPRION blades.
  2. Boot the system or blade in single user mode. Depending on your system's GRUB version, following the instructions in either K4178: Booting the BIG-IP system in single-user mode (GRUB 0.97) or K14662: Restarting the BIG-IP system in single-user mode (GRUB2).

    Note: To determine your system's GRUB version, refer to K14658: Determining the GRUB bootloader version on the BIG-IP, BIG-IQ, or Enterprise Manager system.

  3. Open /config/BigDB.dat using a text editor such as vi or nano.
  4. Locate SystemAuth.DisableRootLogin and ensure there is no entry for "value=true"
  5. If "value=true" and you don't want the root account disabled then delete that line.
  6. Save and exit the file.
  7. Finish your password reset procedure and reboot.
Example of what the DB variable looks like inside of /config/BigDB.dat 
[SystemAuth.DisableRootLogin]
default=false
type=enum
realm=common
enum=|true|false|
scf_config=true
display_name=SystemAuth.DisableRootLogin
value=true  <----------------------- This line means that the root account is actually disabled. If it's missing then this should not be an issue.
 

TACACS secrets with # (hash, number, pound) sign may disable the root and admin accounts

Important: The BIG-IP system is unavailable for the duration of the following procedure. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Connect a terminal to the BIG-IP serial console port. For a VIPRION system, connect a terminal to the serial port on one of the VIPRION blades.
  2. Boot the system or blade in single user mode. Depending on your system's GRUB version, following the instructions in either K4178: Booting the BIG-IP system in single-user mode (GRUB 0.97) or K14662: Restarting the BIG-IP system in single-user mode (GRUB2).

    Note: To determine your system's GRUB version, refer to K14658: Determining the GRUB bootloader version on the BIG-IP, BIG-IQ, or Enterprise Manager system.

  3. Open one of the following files using a text editor:

BIG-IP 11.x and later

/config/bigip.conf

BIG-IP versions prior to 11.x

/config/bigip_sys.conf

  1. Locate the configuration stanza in the file as appropriate for your version:

    BIG-IP 11.x and later

    auth source {
type tacacs
}

    BIG-IP versions prior to 11.x

    system {
auth source type tacacs
}
  2. To revert to local authentication, change the stanza as appropriate for your version:

    BIG-IP 13.x and later

    Remove the following entry:

    auth source {
type tacacs
}

    BIG-IP 11.x - 12.x

    Change the word tacacs to local:

    auth source {
type local
}

    BIG-IP versions prior to 11.x

    Change the word tacacs to local:

    system {
auth source type local
}
  3. Save and exit the file.
  4. Force the BIG-IP system to read the files in the /config/ directory during startup by creating a null file named forceload in the /service/mcpd directory: 
    touch /service/mcpd/forceload

    On VIPRION systems, use the following command to run this command on all blades:

    clsh touch /service/mcpd/forceload
  5. On a BIG-IP VIPRION system, repeat steps 1 through 8 on each blade before proceeding to the next step.
  6. Restart the BIG-IP system by entering the following command: 
    reboot

    On a BIG-IP VIPRION system, repeat this command on each blade.

  7. Verify that you are now able to access the BIG-IP system using the root and admin accounts.
  8. Configure a new shared secret on the TACACS+ server.
  9. On the BIG-IP system, re-enable TACACS+ authentication and configure the new shared secret.


Additional Information

AWS doesn't display the grub boot menu to enable single user mode

By default the GRUB menu in AWS is disabled so if you have lost the root password before you ran through this procedure then you will not be able to reset the root password and you will need to re-deploy the instance if you can't find a username to login to the device with.  To allow the grub menu to display, refer to the following.

K000092515: Unable to access the grub menu for a BIG-IP AWS instance
