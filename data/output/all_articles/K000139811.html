K000139811: Increasing /var before upgrade on a BIG-IQ hardware if your current partition has /var full

Type
Support Solution
Published
2024-05-29
Updated
2025-10-02
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.2.0
Source
https://my.f5.com/manage/s/article/K000139811

Description

Increasing /var before upgrade or if you run out of disk space for your /var directory

Environment

-BIG-IQ
-/var directory almost full on active partition running v8.x (in this case v8.2.0.1 active on MD1.2)
-BIG-IQ-7000 hardware device
-Raid disk
-You cannot resize directory like /var or /shared on a hardware appliance active partition
-If you have a DCD you need to perform the same steps (if require)

 

For example:

MD1.2 - v8.3.0 - active
MD1.3 - v8.x.0 - inactive

 

Cause

/var full on current active partition

 

Recommended Actions

  • Increase disk provisioning for /var in an inactive partition before upgrade
  • The main difference in the process from the single disk to the RAID solution is the fact that there are two directories and logical volumes created for each boot location on the BIG-IP.

Prerequisite:

You have already reactivate the license before install v8.3.0 in MD1.3

Perform the steps below while running v8.3.0 on MD1.2:

Note: The main difference in the process from the single disk to the RAID solution is the fact that there are two directories and logical volumes created for each boot location on the BIG-IP. 

[root@BIQ7000:Active:Standalone] config # ls -la /dev | grep vg-db-sd
drwxr-xr-x. 2 root root 300 May 28 02:25 vg-db-sda
drwxr-xr-x. 2 root root 300 May 28 02:25 vg-db-sdb

[root@BIQ7000:Active:Standalone] config # ls -la /dev/vg-db-sd* | grep var

lrwxrwxrwx. 1 root root 8 May 23 23:00 mdm.set.2._var -> ../dm-12

1. Increase the size of the logical volume:

lvresize /dev/vg-db-sdX/set.xxx._var -L +

Example output:

[root@BIQ7000:Active:Standalone] images # lvresize /dev/vg-db-sdb/mdm.set.3._var -L +100G
Size of logical volume vg-db-sdb/mdm.set.3._var changed from 75.00 GiB (19200 extents) to 175.00 GiB (44800 extents).
Logical volume vg-db-sdb/mdm.set.3._var successfully resized.

[root@BIQ7000:Active:Standalone] images # lvresize /dev/vg-db-sda/mdm.set.3._var -L +100G
Size of logical volume vg-db-sda/mdm.set.3._var changed from 75.00 GiB (19200 extents) to 175.00 GiB (44800 extents).
Logical volume vg-db-sda/mdm.set.3._var successfully resized.

2. Find the dm-XX value from the symbolic links in the /dev/vg-db-sd* directories.

ls -la /dev/vg-db-sd* | grep set.3 | grep var

Example output:

[root@BIQ7000:Active:Standalone] images # ls -la /dev/vg-db-sd* | grep set.3 | grep var
lrwxrwxrwx. 1 root root 8 May 23 23:46 mdm.set.3._var -> ../dm-18
lrwxrwxrwx. 1 root root 8 May 23 23:46 mdm.set.3._var -> ../dm-19

3. Using either of the dm-XX values, find the MD device name from mdstat:

grep dm-XX /proc/mdstat

Example output:


[root@BIQ7000:Active:Standalone] images # grep dm-18 /proc/mdstat
md12 : active raid1 dm-19[1] dm-18[0]
[root@BIQ7000:Active:Standalone] images # grep dm-19 /proc/mdstat
md12 : active raid1 dm-19[1] dm-18[0]

4. Grow the drive using the dm-XX value above:

mdadm --grow /dev/mdXX -z max

Example output:

[root@BIQ7000:Active:Standalone] images # mdadm --grow /dev/md12 -z max
mdadm: component size of /dev/md12 has been set to 183500736K

5. Run e2fsck on the drive:

e2fsck -f /dev/mdXX

Example output:

[root@BIQ7000:Active:Standalone] images # e2fsck -f /dev/md12
e2fsck 1.42.9 (28-Dec-2013)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
set.3./var: 18473/4915200 files (0.1% non-contiguous), 529895/19660784 blocks

6. Resize the filesystem:

resize2fs /dev/mdXX

Example output:

[root@BIQ7000:Active:Standalone] images # resize2fs /dev/md12
resize2fs 1.42.9 (28-Dec-2013)
Resizing the filesystem on /dev/md12 to 45875184 (4k) blocks.
The filesystem on /dev/md12 is now 45875184 blocks long.

7. Reboot into the new volume

reboot volume MD1.X

Example:

root@(BIQ7000)(cfg-sync Standalone)(Active)(/Common)(tmos)# reboot volume MD1.3

Note: Reboot took 20-30 minutes on a blank device, it might take longer on a device with heavy configuration
