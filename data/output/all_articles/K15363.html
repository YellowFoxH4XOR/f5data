Topic

An improperly placed comment character (#) in an iRule may cause a TCL syntax error and result in disconnection of client connections when the iRule runs. Additionally, the TCL syntax error may prevent the BIG-IP system configuration from loading.

Description

When using either the Configuration utility or the Traffic Management Shell (tmsh) to create or modify an iRule, if you place the TCL comment character (#) at the beginning of a line that ends with an opening brace character ({), the command syntax is invalid because the entire line is commented out and the TCL interpreter ignores the opening brace character at the end of the line. However, the iRule passes validation and you are still able to save the configuration. The saved syntax error may cause the system to disconnect client connections and may prevent the system configuration from loading.

For more information, refer to Why can I not place unmatched braces in Tcl comments.

Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

The following example shows an iRule with the previously described invalid command syntax:

when CLIENT_ACCEPTED {
    # if {[IP::addr [IP::client_addr] equals 10.10.10.10]}{
        pool test_pool
    }
}

When the system triggers the iRule's script at traffic time, the TCL interpreter finds unbalanced braces and fails to run, aborting the connection to the client. When this issue occurs, a message similar to the following appears in the /var/log/ltm file:

err tmm[8673]: 01220001:3: TCL error: /Common/test_rule <CLIENT_ACCEPTED> - invalid command name "}" while executing "}"

If you restart the BIG-IP system with the invalid iRule in place, the configuration may fail to load, possibly causing downtime while the system corrects the configuration. Attempting to load the configuration using the tmsh utility produces an error message that appears similar to the following example:

/Common/test_rule:4: warning: [unmatched closing character][}]
