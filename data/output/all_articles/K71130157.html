Description

This article will describe options for adding HTTP Security Headers to an APM protected Virtual Server to address compliance issues.

Environment

  • Virtual Server with an Access Policy applied
  • BIG-IP LTM+APM

Cause

LTM Virtual Server with a Access Policy is failing compliance checks because of insecure HTTP headers.

Recommended Actions

You can create and apply secure HTTP header options to the Virtual Server with the following procedures:
Create and Apply an iRule to the Virtual Server:

  1. Login to the BIG-IP WebUI
  2. Navigate to Local Traffic --> iRules --> iRule list
  3. Click Create
  4. Enter a name for the iRule in the Name field
  5. If your Virtual Server is not using SAML as an IdP, then in the Definition field, enter the following: 
    when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}
when HTTP_RESPONSE_RELEASE {
    HTTP::header insert X-Frame-Options "SAMEORIGIN"
    HTTP::header insert X-XSS-Protection "1; mode=block"
    HTTP::header insert X-Content-Type-Options "nosniff"
    HTTP::header replace Strict-Transport-Security "max-age=15552000; includeSubDomains"
    HTTP::header insert Content-Security-Policy "object-src *;script-src * 'unsafe-inline' 'unsafe-eval' data:"
}
  6. If your Virtual Server is using SAML as an IdP, then in the Definition field, enter the following instead of the previous one: 
    when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}
when HTTP_REQUEST {
   if { [HTTP::has_responded] } { return } 
   set add_content_type 0
   if { [HTTP::uri] starts_with "/saml/idp/res?id" } {
      set add_content_type 1
   }  
}
when HTTP_RESPONSE_RELEASE {
    if { [info exists add_content_type] && $add_content_type == 1 } {
       HTTP::header insert Content-Type "application/xhtml+xml"
    }
    HTTP::header insert X-Frame-Options "SAMEORIGIN"
    HTTP::header insert X-XSS-Protection "1; mode=block"
    HTTP::header insert X-Content-Type-Options "nosniff"
    HTTP::header replace Strict-Transport-Security "max-age=15552000; includeSubDomains"
    HTTP::header insert Content-Security-Policy "object-src *;script-src * 'unsafe-inline' 'unsafe-eval' data:"
}
