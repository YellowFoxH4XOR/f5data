K00153876: Enabling LDAP remote authentication for Advanced Shell access to the BIG-IQ system

Topic

You can enable Lightweight Directory Access Protocol (LDAP) remote authentication for Advanced Shell (bash) access to the BIG-IQ system. You achieve this by granting remotely authenticated users access to the TMOS Shell (tmsh) and from this shell if the users have administrative privileges, they can execute the command run /util bash to access bash. For more information, refer to K10272: Accessing bash as a remotely authenticated user .

You should consider using this procedure under the following condition:

  • You want to allow LDAP-authenticated users to administer the BIG-IQ system using bash.
  • Your security requirements include using LDAP authentication for user-access controls.

Description

You can use tmsh to configure the BIG-IQ system to allow third-party LDAP-authenticated users to administer the BIG-IQ system. To do so, perform the following procedure:

Note: You cannot perform this procedure through the BIG-IQ user interface.

  1. Log in to bash on the BIG-IQ system using the root-user account.

    For example, you can use a console-access application to establish an SSH connection to the management IP address of the BIG-IQ system.

  2. Log in to tmsh by entering the following command:

    tmsh

  3. To create the authentication configuration, use the following command syntax:

    create /auth ldap system-auth bind-dn "<Bind-Account-DN>" bind-pw "<Bind-Account-Password>" search-base-dn "<Search-Base-DN>" login-attribute "<login-attribute>" servers add { <Server-IP-Address> }

    The following references show the items configured on the LDAP server in your environment:

    • <Bind-Account-DN> is the distinguished name of an account to which to bind and to perform searches.
    • <Bind-Account-Password> is the password for the search account created on the LDAP server.
    • <Search-Base-DN> is the search-base-distinguished name.
    • <login-attribute> identifies the LDAP attribute to compare the entered user against
    • <port> specifies using LDAP, LDAPS, or other port as required
    • <ssl> determines if SSL is enabled, disabled,  or start-tls
    • <Server-IP-Address> is the IP address of the LDAP server(s) that the BIG-IQ system must use to obtain authentication information. To add more than one entry, use comma to separate the multiple IP address entries.
    •  The following Certificate Options are also available as needed:
      • ssl-ca-cert-file
      • ssl-check-peer
      • ssl-ciphers
      • ssl-client-cert
      • ssl-client-key

    For example:

    create /auth ldap system-auth bind-dn "CN=Administrator,CN=Users,DC=US,DC=example,DC=corp" bind-pw "SamplePassword" search-base-dn "DC=US,DC=example,DC=corp" login-attribute samaccountname servers add { 10.0.0.1 }

  4. Choose one of the two options:
    A. To grant all remote users the Administrator role and access to tmsh, enter the following command:

    modify /auth remote-user { default-role admin remote-console-access tmsh }

    B. To grant a specific group of remote users the Administrator role and access to tmsh, do the following:

    1. Specify a role that is not the Administrator for the remote user default role and grant tmsh access using the following syntax:

    modify /auth remote-user { default-role <non-Administrator role> remote-console-access tmsh }

    For example:

    modify /auth remote-user { default-role guest remote-console-access tmsh }

    2. Add a remote role group that grants the Administrator role (role 0) to users with the LDAP attribute of your choosing using the following syntax:

    modify /auth remote-role role-info add { <role group name> { attribute "<LDAP attribute>" console tmsh line-order 1000 role 0 user-partition all } }

    For example:

    modify /auth remote-role role-info add { my_managers { attribute "employeeType=bigiqadmin" console tmsh line-order 1000 role 0 user-partition all } }

  5. To enable LDAP authentication, enter the following command:

    modify /auth source type ldap

  6. To save the configuration changes, enter the following command:

    save /sys config

  7. Tell remote users with the Administrator role they can access bash from tmsh by entering the following command:

    run /util bash
