Description

NTLM Pass-Through Authentication allows a domain-joined server machine (APM) to authenticate a domain user by forwarding NTLM data, like LmChallengeResponse and NtChallengeResponse, to the DC through a Netlogon Secure Channel using the Netlogon Remote Protocol (MS-NRPC)

APM implements MSRPC over TCP and no longer uses SMBv1/v2 protocols to avoid exploits like Eternalblue.

APM enforces secure RPC with Netlogon schannel to be compliant with MSFT after CVE-2020-1472.

Eca and nlad daemons are tied together. Eca log level is applied also to nlad and restarting one daemon may result in the other daemon restarting.


Prerequisites

APM is configured with AAA NTLM. Different apps like Exchange may use NLTM authentication on client side.


Procedures

There are two steps needed to start NTLM Pass-Through Authentication between APM and a DC

1) Joining APM to the domain creating a Machine account on a DC

DNS server should contain records for; _kerberos._udp.<domain>, _kerberos._tcp.<domain>, _kpasswd._udp.<domain> and _kpasswd._tcp.<domain> and _ldap._tcp.<domain>

These ports should be opened on internal Firewalls; Kerberos (UDP,TCP/88 & UDP,TCP/464) and LDAP (TCP/389,636)

You must provide at least; the Machine account name, Domain FQDN, Admin user and Admin password

apm ntlm machine-account {
  domain-fqdn (Domain FQDN)
  machine-account-name (Machine Account Name)
  Admin User
  Admin Password
  domain-controller-fqdn (Domain Controller FQDN) (optional)

If "DC FQDN" is not provided, APM will send DNS query requests "SRV" to resolve domain names into domain controller names. It uses BIGIP DNS server configuration

2) To create and establish a Netlogon shannel to DCs

These ports should be opened on internal Firewalls; RPC Endpoint Mapper (TCP/135) and dynamically assigned TCP ports between 1024-65535 for RPC Netlogon like (TCP/6414)

You must provide at least one "Domain Controller FQDN" in the same domain.

apm ntlm ntlm-auth NTLM-DC3 {
  machine-account-name (Machine Account Name)
  dc-fqdn-list (Domain Controller FQDN List)
  
APM resolves all DC FQDN to IP addresses using system DNS, hosts entries or dns resolution, to establish 3 Netlogon schannels to each DC (MS-NRPC). 

10.1.1.22 10.1.1.13 59828 53 DNS 192 OUT s1/tmm1 : Standard query 0x9100 A dc3.lab3.lan
10.1.1.13 10.1.1.22 53 59828 DNS 304 IN s1/tmm1 : Standard query response 0x9100 A dc3.lab3.lan A 10.1.1.13

The "NTLM Authentication" object will not be registered if any of those DC FQDN can not be resolved.

10.1.1.21 10.1.1.13 37937 53 DNS 192 OUT s1/tmm0 : Standard query 0xd7c9 A dc4.lab3.lan
10.1.1.13 10.1.1.21 53 37937 DNS 251 IN s1/tmm0 : Standard query response 0xd7c9 No such name A dc4.lab3.lan SOA dc3.lab3.lan

In that case these errors will be logged after NTLM Authentication is created or modified or nlad restarted.
