Description

  • I want to enable streaming of your tenant logs from F5® Distributed Cloud Regional Edge (RE) Sites to an external log collection system (Azure Event Hubs in this guide)
  • The streamed logs include all system and application logs of your tenant
  • This also includes logs of all Customer Edge (CE) Sites of that tenant
  • For conceptual information about logging, see Logs. 

Environment

  • F5® Distributed Cloud (XC) Global Log Receiver
  • Azure Events Hubs

Cause

None

Answer/Recommended Actions

Setup Azure Event Hubs instance

Platform log streaming is using Apache Kafka® compatible API endpoint of Azure Event Hubs.

To use global log streaming with Azure Event Hubs, you need to setup individual instance that will be used for logs and create SAS with Send permissions.

Please Note: As Per Azure's Documentation (What is Azure Event Hubs for Apache Kafka): This Kafka "feature is supported only in the standard, premium and dedicated tiers".

 

1. Create namespace

If you already have an existing namespace, it is possible to use it and only create an instance in the next step.

You can keep default settings for this namespace and only select name, location and pricing tier and continue with creation.

For Throughput Units, 1 TU provides:

  • Ingress: Up to 1 MB per second or 1000 events per second (whichever comes first).
  • Egress: Up to 2 MB per second or 4096 events per second.

When reaching this limit, events throttle (which can be seen on namespace dashboard charts) and can be scaled up later if needed. For the start 1TU should be sufficient or you can enable auto-inflate.

For more information about scalability read this Azure doc.

2. Create instance

Click on Entities -> Event Hubs and create new Event Hub instance Partition Count and Message Retention depends on further consumer setup and how you intend to process logs further.

3. Create SAS Policy for newly created instance

Click Shared access policies and create new policy with Send privileges. Save Connection string–primary key which you will need to setup global log receiver.

 

Setup Global Log Receiver

In management dashboard, click on Manage -> Log Management -> Global Log Receiver and add new receiver.

Set Name, in Receiver Configuration select Azure Event Hubs and configure Azure Event Hubs namespace and instance. 

Configure blindfolded Connection String or Clear Secret from SAS Policy with Send privileges that you have created in earlier steps. 

 

Finally Save and Exit, your global log receiver should be deployed in a few minutes, and you could verify that logs are coming into your Azure Event Hubs instance. 

Additional Information

Azure Event Hubs

Azure Event Hubs is a big data streaming platform and event ingestion service. It can receive and process millions of events per second. Data sent to an event hub can be transformed and stored by using any real-time analytics provider or batching/storage adapters.

The following scenarios are some of the scenarios where you can use Event Hubs:

  • Anomaly detection (fraud/outliers)
  • Application logging
  • Analytics pipelines, such as clickstreams
  • Live dashboards
  • Archiving data
  • Transaction processing
  • User telemetry processing
  • Device telemetry streaming
