K000132577: BIG-IP does not accept unencoded space in request URI

Type
Support Solution
Published
2023-02-16
Updated
2023-08-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000132577

Description

Starting from BIG-IP versions 13.1.3.4, 14.1.4, 15.1.2.1, and 16+, BIG-IP no longer accepts unencoded space in URI as it is non-RFC-compliant. (In prior versions, unencoded space is accepted and the request is forwarded on to the pool member.)

According to HTTP RFCs, the space character - " " needs to be encoded as "%20" when used in the URI.

Example of HTTP request with unencoded space in URI (non-RFC-compliant):

GET /script?name=First Last HTTP/1.1
Host: www.example.com
 

Example of HTTP request with encoded space in URI (RFC-compliant):

GET /script?name=First%20Last HTTP/1.1
Host: www.example.com
 

If the client sends a HTTP request with unencoded space in URI, you may observe:

  • Stalled request and an eventual timeout if RFC-compliance is disabled (default)
  • TCP RST with "Invalid HTTP headers blocked" if RFC-compliance is enabled

Note: RFC-compliance setting is defined in http profile, and the default value is disabled. For more information, refer to K40413116: Information about the Enforcement of RFC compliance for the HTTP protocol feature.

In short, as long as a HTTP profile is associated with the virtual server, HTTP requests with unencoded spaces in request URI will always fail.

Environment

  • BIG-IP
  • Virtual server with http profile
  • Request URI contains unencoded space

Cause

The change was due to the fix for Bug ID 858285, which brings the BIG-IP to be RFC-compliant and to resolve the issues described in K27551003: The BIG-IP system may not interpret an HTTP request the same way the target web server interprets it.

Recommended Actions

If a HTTP request is not processed by BIG-IP due to the request URI containing unencoded space, you can resolve the issue with either one of the solutions below:

  • It is recommended that you update the client so that it sends RFC-compliant requests by encoding the space character " " in URI with "%20". RFC-compliant requests will be processed by BIG-IP normally.
  • If it is not possible to change the client or pool member, and you still need the BIG-IP to forward requests with URI containing unencoded spaces to pool member, you can achieve this by removing the HTTP profile from the virtual server. Without a http profile, the virtual server will behave as a plain TCP proxy (as it still has a TCP profile). BIG-IP will not validate requests against HTTP RFC, and will pass requests (even if it may contain unencoded spaces in URI) to the server as plain TCP data. However, please note that, in addition to security risks of not validating HTTP requests, you will also not be able to use features that requires a http profile (eg. HTTP:: commands in iRule).
