K1364: Reasons why 3-DNS may display the status of BIG-IP as blue (unchecked)

Topic

This issue is a symptom of inconsistent communication between the big3d agents in the BIG-IP and 3-DNS Controllers. There are four common reasons for this:

  • The big3d agent is not running.
  • The big3d agent version is not the same on the BIG-IP and 3-DNS Controller.
  • The iQuery keys do not match.
  • The firewall or router between the systems needs to be reconfigured.

Perform the following steps to troubleshoot these issues.

Verify that the big3d agent is running

  1. Activate the big3d agent on the BIG-IP and 3-DNS Controllers, by typing the following command on each controller:

    big3d

  2. Verify that the big3d agent has started, by typing the following command on each controller:

    ps -ax | grep big3d

    The big3d process should appear at least once with a process ID.

Verify and synchronize the big3d agent version

  1. Check the version of the big3d agent, by typing the following command on each controller:

    3dnsmaint

  2. If the versions do not match, update the big3d agent by selecting Check remote versions of big3d from the menu.
  3. If you receive errors, select Configure SSH communication between all 3-DNS and BIG-IP systems from the menu and follow the instructions.

    This process will configure secure communications so the correct big3d agents can be installed. After it is configured, repeat step 2.

Verify and synchronize iQuery Encryption Keys

From the 3-DNS maintenance menu, select Generate and Copy iQuery Encryption Key.

If communication is still not functioning, verify the addresses to which the 3-DNS Controller is trying to communicate and connect them manually using SSH.

Verify the configuration between the BIG-IP and 3-DNS Controllers

  1. Check the connectivity between the BIG-IP and 3-DNS Controllers by running the tcpdump command on both controllers simultaneously, using the following syntax:

    tcpdump -ni <interface> port 245 or port 4353 or port 4354

  2. View the tcpdump information and:
    • Verify that one controller is sending packets and the other is receiving those packets.
    • Look for suspicious behavior like RSTs, long delays, or packets that are sent or received on the incorrect interface. If packets are not being sent or received on the correct interface, verify the address (in the 3-DNS Controller's Configuration utility) of the BIG-IP or 3-DNS Controller and confirm that it is the shared alias, and that the interface statement lists the external interface for each BIG-IP and 3-DNS Controller in the pair.
    • Verify that the BIG-IP and 3-DNS Controller routes are the same route in both directions (ensuring it is not an asymmetric route).
    • Troubleshoot symptoms further by gathering packet dumps at each hop along the route to its destination to see where the packet slows, gets reset, or disappears.

  3. Verify that the 3-DNS or BIG-IP Controller is listening on that IP address and port.

    For example, type the following commands on each controller:

    netstat -an | grep 4353
netstat -an | grep 4354
netstat -an | grep 245

    Note: Refer to the 3-DNS Administrator Guide to see which ports are appropriate given your configuration. It is usually port 4353, although 4354 or 245.

  4. Verify that a principal 3-DNS Controller exists, by typing the following command on each 3-DNS Controller:

    cat /var/run/sync_state

    Note: If you do not have a principal, the 3-DNS Controller cannot communicate with the other 3-DNS Controllers you have configured. There should only be one principal 3-DNS Controller in a given group.

  5. Verify that all of the 3-DNS Controllers are on the same software version.
  6. Restart named, 3dnsd, and big3d, by typing the following command one of the 3-DNS Controllers:

    3ndc restart
