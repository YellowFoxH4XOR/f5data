K000148406: F5OS-A no possible connection to CLI and GUI - no response to TCP SYN

Type
Support Solution
Published
2024-11-06
Updated
2025-11-11
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.7.X, 1.5.X, 1.8.0, 1.7.0, 1.5.2, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000148406

Description

Unable to connect to rSeries management interface via HTTPS or SSH.

A tcpdump shows the rSeries system receives a TCP SYN, but does not respond to it.

Ping works.

Environment

  • F5OS-A
  • rSeries
  • Management interface

Cause

This issue can happen if an IP address has been configured for the mgmt interface.

The mgmt0-system interface should own the configured management IP, not mgmt. The mgmt interface should have no IP address assigned.

Recommended Actions

Review the output of the ip a command to determine if mgmt has been configured with an IP address.

This may have been configured manually in /etc/sysconfig/network-scripts/ifcfg-mgmt, for example (or via other methods), and if so, should be removed.

If you have reverted or made changes to /etc/sysconfig/network-scripts/ifcfg-mgmt, you will need to either reboot the device or restart the network.service unit for the changes to take effect:

systemctl restart network

The management IP should only be configured via confd (system mgmt-ip config), and this should result in only mgmt0-system having the management IP.

This example shows the expected output of ip a:

2: mgmt: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
    link/ether 14:a9:d0:28:dc:82 brd ff:ff:ff:ff:ff:ff

         ^__ No IP address
...
126: mgmt0-system@mgmt: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default qlen 1000
    link/ether 14:a9:d0:28:dc:ff brd ff:ff:ff:ff:ff:ff
    inet 10.10.1.1/24 brd 10.10.1.255 scope global noprefixroute mgmt0-system
       valid_lft forever preferred_lft forever
 
         ^__ IP address assigned

Note: IP and MAC addresses will be unique to each environment.

Additional Information

This problem might be seen in other scenarios. If the ip a command shows the correct, expected output, further troubleshooting is required. Other possible root causes may be: firewall or allow list rules, incorrect MAC address, non-functional system processes, etc.
