Description

When you attempt to use BIG-IP Next Central Manager to create a BIG-IP Next tenant instance on a F5 VELOS or rSeries system, the BIG-IP Next Central Manager fails to create the BIG-IP Next instance and returns an error message similar to the following example where <instance_IP> is the management IP address of the BIG-IP Next instance and <provider_IP> is the management IP address of the provider VELOS chassis partition or rSeries system:

Note: You can view the complete message in Alerts & Notifications by selecting the bell icon at the top right corner in the BIG-IP Next Central Manager webUI.

Failed to create instance <instance_IP>

An unexpected error occurred when creating the f5os client connection.If the error is not clear, please contact the provider developers.

f5os Client Error: Get https://<provider_IP>:8888/restconf/data/openconfig-system:system/aaa: tls:
failed to verify certificate: x509: cannot validate certificate for <provider_IP> because it doesn't contain any IP SANs

Environment

  • BIG-IP Next Central Manager 20.2.1 and later
  • F5 VELOS chassis partition or F5 rSeries system configured as provider on BIG-IP Next Central Manager

Cause

The BIG-IP Next Central Manager 20.2.0 and later requires that the F5OS type provider (F5 VELOS/rSeries) uses a TLS certificate with well formed Subject Alternative Names (SAN). When encountering this issue, you are able to successfully add the VELOS chassis partition or rSeries system as a provider on BIG-IP Next Central Manager, even though the provider is using the default TLS certificate without SAN. However, when you attempt to create the BIG-IP Next instance using the configured provider, instance creation fails with the above error message.

Recommended Actions

You should ensure the F5 VELOS/rSeries system uses a TLS certificate with well formed SAN. This involves updating the TLS certificate and key on the provider system, either the VELOS chassis partition or the rSeries system, to use well formed SAN. Once this is done, you need to delete the previous provider configuration on the BIG-IP Next Central Manager and re-add it in order to validate the updated certificate. You can then use BIG-IP Next Central Manager to create the BIG-IP Next instance on the provider system.

The current F5OS-C/A releases for F5 VELOS/rSeries systems do not support generating a CSR to include SAN, you can use an external system, such as a CentOS-based system, with the OpenSSL utility to generate a CSR with SAN. To generate a new TLS certificate, configure the F5 VELOS chassis partition or rSeries system to use the new TLS certificate and key, and delete and re-add the provider, perform the following procedure:

Impact of procedure: The webUI of the F5 VELOS/rSeries system will be momentarily unavailable when it is configured to use a new TLS certificate and key.

  1. To generate a new TLS certificate and key to include SAN, follow the instructions in the Recommended Actions section of K000139300: DEVICE-00060: Internal error testing authentication. 
  2. After signing the newly created CSR, update the TLS certificate and key on the provider VELOS chassis partition or rSeries system by using the procedure in the Recommended Actions section of K000139300: DEVICE-00060: Internal error testing authentication.
  3. Log in to the BIG-IP Next Central Manager webUI.
  4. Select Manage Instances. 
  5. Select Providers.
  6. Select the provider previously used when attempting to create the new BIG-IP Next instance. You may have to select the down arrow next to VELOS or rSeries to view the configured providers.
  7. Select Delete, then select Yes, Delete in the pop up to confirm.
  8. Select + Add to add the provider again.
  9. For Type, select either VELOS or rSeries.
  10. For Name and Hostname, enter a name for the provider and the hostname or IP address of the provider.
  11. Select Connect.
  12. Enter the username and password for the provider, then select Submit.
  13. Select Accept to accept the fingerprint.
  14. Once the provider has been added to BIG-IP Next Central Manager, you can proceed with the BIG-IP Next instance creation process using the newly updated provider.
