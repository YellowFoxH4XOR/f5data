Known Issue

The BIG-IP configuration validator erroneously allows the session cache size setting in a Secure Sockets Layer (SSL) profile to be configured with a value larger than the global session cache size. Each SSL profile can be configured with its own SSL session cache size, which limits the number of sessions that are cached for a particular profile. However, the global session cache size setting limits the total number of cached SSL sessions among all SSL profiles, and is not configurable. As a result, if the SSL session cache size is set larger than the global session cache size, the configuration loads without error, but the number of cached sessions for the virtual server never exceeds the global SSL session cache size.

Note: For more information about the BIG-IP global session cache size, refer to K11170: The BIG-IP global SSL session cache size was increased to 262,144 sessions.

F5 Product Development tracked this issue as ID 224330 (formerly CR135540) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, WebAccelerator, PSM, APM, WOM and Edge Gateway release notes.

Workaround

You can work around this issue by ensuring that the configured SSL session cache size for each SSL profile is less than the maximum global cache size.
