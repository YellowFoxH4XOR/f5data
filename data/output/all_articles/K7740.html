Known Issue

This is the result of a known issue. When a client's HTTP request ends with an extra /r/n (CRLF) character, the BIG-IP ASM system identifies the CRLF as a subsequent request and issues an illegal HTTP formatted request violation.

According to section 4.1 of RFC 2616, HTTP 1.1 clients must not send extraneous CRLF between requests. However, the same section also recommends that servers ignore extraneous CRLF in the interest of robustness.

F5 Product Development tracked this issue as ID 333111 (formerly CR81601) and it was fixed in BIG-IP ASM 9.4.2. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

Beginning with BIG-IP ASM 9.4.1 HF1, you have the ability to ignore the extraneous /r/n CRLF characters between requests by configuring the bitmask to 1024 for the non-RFC violation.

To change the bitmask for the non-RFC violation to 1024, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Options.

    A new Application Security configuration window opens.

  4. Click the Advanced Configuration menu tab.
  5. In the non_rfc_bitmask option, type the following:

    1024

  6. Click Update.
  7. Click OK to confirm.
  8. Click OK to acknowledge this action requires restart on all units.
