K000140719: Configuring the AOM address identically to the Management IP will disrupt management connectivity

Type
Support Solution
Published
2024-08-15
Updated
2024-08-15
Applies to
  • F5OS
  • F5OS-A: 1.7.X, 1.7.0
Source
https://my.f5.com/manage/s/article/K000140719

Description

When configuring AOM and Management interfaces, the same IP Address may not be validated correctly. The following behaviour maybe encountered

  • Disruption or connection failure when accessing the rSeries platform Management GUI
  • Management IP Address MAC Address flaps between two values.

Environment

The following factors may trigger the above behaviour(s)

  • Management and AOM set to the same IP Address. For example:
    • system mgmt-ip config ipv4 system address 192.168.0.1
    • system aom config ipv4 address 192.168.0.1
  • rSeries platform running 1.7.0 or above.

Cause

The behaviour as per the Description is caused by a failure of the software to properly validate the Management and AOM IP Addresses, allowing a conflict to occur.

Recommended Actions

Please refer to the following Article regarding the configuration of AOM on the rSeries platform:

  • K000138036: Configure AOM SSH access in F5OS-A

Additional Information

The behaviour maybe misidentified as the following Known Issue resolved in 1.7.0:

  • K000135030: ARP probes towards rSeries management IP answered by multiple MAC addresses
  • Bug ID 1295657: ARP probes to rSeries management IP are answered by both mgmt and mgmt0-system
