K000153044: BIG-IP tenant sends unexpectedly TCP RST in response to SYN/ACK from server when using FastL4 profile

Type
Support Solution
Published
2025-08-19
Updated
2025-08-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.X, 17.1.2, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000153044

Description

When using a FastL4 profile on BIG-IP, TCP connections may be unexpectedly reset (RST) by the BIG-IP device after receiving a SYN/ACK from the server. Packet captures show the BIG-IP sending a TCP RST in response to the server's SYN/ACK, interrupting normal connection establishment. No specific error message is logged for the RST event.

Environment

  • FastL4 profile
  • VLAN configured with cmp-hash src-ip
  • Virtual server using FastL4 profile for TCP traffic

Cause

The issue is triggered by the external VLAN being configured with cmp-hash src-ip. This setting causes the clientside and serverside flows of the same TCP connection to be processed by different Traffic Management Microkernels (TMMs). As a result, when the SYN/ACK from the server is received by a different TMM than the one that handled the initial SYN, the BIG-IP is unable to associate the flows correctly and responds with a TCP RST, terminating the connection.

Recommended Actions

  • Change the external VLAN cmp-hash setting from src-ip to its default value (which uses a hash of source and destination IP and port). This ensures that both clientside and serverside flows of each connection are handled by the same TMM, preventing unnecessary traffic redirection and unexpected TCP resets. Example command to restore default:
    tmsh modify net vlan <VLAN_NAME> cmp-hash default
  • After making this change, monitor system behavior to confirm that unexpected RST packets no longer occur.
  • If there was an intentional reason for using cmp-hash src-ip, review your requirements carefully and consult F5 documentation or support before reverting to default.
