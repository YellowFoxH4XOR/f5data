Description
After an upgrade to BIG-IP version 13.0.0 or newer, you can no longer log in to the BIG-IP with either remote or local credentials. Effectively locking you out of the BIG-IP.

Environment

  • Upgrade to BIG-IP 13.0.0 or later.
  • Remote authentication in use.

Cause
Pre 13.0.0, by default BIG-IP would fallback to local user accounts for authentication if the remote authentication servers were unreachable.
In version 13.0.0 of BIG-IP, the option to "fallback to local" authentication was added, and disabled by default.
This means that after an upgrade to 13.0.0 or later, if the BIG-IP is unable to communicate with the remote auth servers, you will not be able to log in because the BIG-IP will no longer allow local user accounts to log in, including Admin and Root users. Authentication will continue to fail as long as the BIG-IP is unable to communicate with the remote auth servers.

Recommended Actions

To work around this issue, you will need to use a console to connect directly to the BIG-IP.
With a console session established, reboot the BIG-IP, and at the initial boot menu, select your previous BIG-IP version to boot into.
Once booted back into your previous version:
  1. Disable remote authentication, allowing only local authentication.
  2. Then boot back to your upgraded software volume.
Remote authentication should be disabled when you boot to the new volume, allowing you to log in with local user accounts.
