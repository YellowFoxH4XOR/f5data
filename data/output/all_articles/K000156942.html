Description

The article describes the steps to verify cookie-based session persistence on BIG-IP LTM. Specifically, when you want to know how to test that persistence is functioning correctly (i.e., requests with the same cookie are routed to the same backend server).

Environment

  • BIG-IP LTM
  • Persistence Method: Cookie-based session persistence

Cause

None, this article is informational.

Recommended Actions

To verify session persistence functionality:

1) Run tcpdump on the BIG-IP to capture the traffic going through virtual server in question. 

The example command may look like below:

tcpdump -envi 0.0:nnnp -s0 -w /var/tmp/cookie-test.pcap host <IP of virtual server> and port <port of virtual server>

Note: Replace <IP of virtual server> and <port of virtual server> with the correct data.

2) Clear statistics for the pool applied to the given virtual server

In GUI go to Statistics  ››  Module Statistics : Local Traffic  ››  Pools. 

Select the correct pool and click Reset.

3) Access your application through the BIG-IP virtual server using a browser or HTTP client (such as curl or Postman) check the response headers for the presence of the persistence cookie (typically named BIGipServer<pool_name>). 

4) Send subsequent requests using this exact cookie value.

5) Confirm, via backend application logs or unique identifiers in responses, that all such requests are consistently routed to the same backend server. 

It can be also confirmed by pool member statistics, if there is no other traffic going to the pool during the tests.

Other way to check the load balancing decisions made by BIG-IP is by analyzing the packet capture collected with tcpdump from step 1).

 

Optionally, clear the cookie and repeat the process to ensure a new server is chosen.

Additional Information

If you would like to ensure that persistence cookies are encrypted, refer to: K23254150: Configuring cookie encryption for BIG-IP persistence cookies from the cookie persistence profile
