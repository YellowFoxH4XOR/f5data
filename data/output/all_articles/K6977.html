Topic

Important: The find_error.pl script is an internal debug tool and should only be used by customers with guidance from Engineering Services.

Important: The find_error.pl script writes output to the current directory by default. Make sure that sufficient space is available or specify the --output_file option when running the command.

The find_error.pl troubleshooting tool allows you to save relevant tcpdump recording data when a certain error appears in a log file. The find_error.pl script records tcpdump files (each containing a predefined number of packets), while reading a specified log file. If the error is logged in the log file, the tool creates a tar archive with files containing the log message and tcpdump traffic. If the error is not found in the log file, the process starts over.

Note: The find_error.pl script is not installed on the Virtual Edition (VE) version of BIG-IP 10.x.

In BIG-IP 10.1.0 and later, the script is located in the /usr/share/ts/bin/ directory. In previous versions, the script is located in the /ts/off_tools/ directory.

The find_error.pl script supports the following command line options:

  • -t, --token='token'

    The token command returns a user-defined log file string.

  • -l, --log_file='log_file'

    The log_file command returns the log file that contains the user-defined string.

  • -p, --packet_num='Packet Number'

    The packet_num command returns the number of packets to include in the tcpdump output file. F5 recommends 10,000 packets or more.

  • -o, --output_file='Output file'

    The output_file command returns the name of the tar archive that will contain the tcpdump and partial log output.

  • -i, --interface='Interface'

    The interface command returns the interface or VLAN name on which the tcpdump will be run (defaults to 0.0 for all interfaces).

  • --zip

    The zip command compresses the final output tar file.

  • --nozip

    The nozip command specifies no compression of the final output file. This is the default setting.

  • -e, --expression='filter expression'

    The expression command specifies a filtering expression to tcpdump.

For example, in 10.2.0, the following my_error_string token is searched for in the /ts/log/bd.log file with the output file being compressed using the following syntax:

/usr/share/ts/bin/find_error.pl -t 'my_error_string' -l '/ts/log/bd.log' -p 10000 -o /var/tmp/case.tar.gz --zip &

While the find_error.pl script is running, it will log to standard output when the temporary tcpdump output file is rolled over. If the script does not find the token in the specified log file by the time packet_num is read, the following will be logged to standard output, and the script will continue to run:

10000 packets received by filter 0 packets dropped by kernel Recorded traffic, return value of tcpdump was 0 The signature my_error_string was not found during the recording

If the script finds the token in the specified log file by the time packet_num is read, the following will be logged to standard output:

10000 packets received by filter 0 packets dropped by kernel Recorded traffic, return value of tcpdump was 0 Found my_error_string at line 1 of the partial log -file name partial.log.1 (line 24 on the original) partial.log.1 record.dmp.1 Created /var/tmp/case.tar with files partial.log.1, record.dmp.1, return code of tar was 0

You must manually stop the find_error.pl script once it has been run. To do so, bring the job into the foreground and press Ctrl + C to break out of the script, or type the following command:

ps | egrep -e 'find_error.pl|record.dmp' | grep -v grep | awk '{system("kill -9 "$1)}'

Additional Information

Example with regular expression

By default, the token parameter ("-t ") does not support regular expression. To allow this, you need to make a minor modification to the script and the user input token will need to conform to regex-compatible pattern. Perform the following procedure to modify the script:

  1. Login to bash.
  2. Open the /var/tmp/find_error.pl script for edit.
  3. Locate the following line of code and replace it with the given condition statement. 
    Replace:
        if(index($line, $args{token}) >= 0)
    With:
        if ($line =~ /$args{token}/)

To use the script with -t for regular expression, refer to the following example:

Impact of procedure: Performing this procedure should not have a negative impact on your system. However, F5 recommends testing this in your staging environment first before performing this on production, taking care to consider disk space, performance and other factors unique to your environment.

  1. Login to bash
  2. Copy the script to the /var/tmp directory:
    cp /usr/share/ts/bin/find_error.pl /var/tmp/
  3. Change directory:
    cd /var/tmp

  4. Run the script using the following command syntax:
    /var/tmp/find_error.pl -t '<Regular expression log file string>' -l '/var/log/ltm' -e 'host <IP1> or host <IP2>' -p 10000 -o /var/tmp/$HOSTNAME-exampleName.tar.gz --zip &

  5. For example, enter the following command:
    /var/tmp/find_error.pl -t 'Pool /Common/example_Pool member.*monitor status down' -l '/var/log/ltm' -e 'host 10.10.10.10 or host 10.10.10.100' -p 10000 -o /var/tmp/$HOSTNAME-exampleName.tar.gz --zip &

    In this example, the script looks for a string in the /var/log/ltm file that matches log entries that start with "Pool /Common/example_Pool member", followed by any sequence of characters (or none) and followed by "monitor status down".
