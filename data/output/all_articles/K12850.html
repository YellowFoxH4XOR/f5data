Known Issue

The BIG-IP WebAccelerator system may become unresponsive when processing a request for a PDF file. This issue occurs when all of the following conditions are met:

  • The BIG-IP WebAccelerator system receives a client HTTP request for PDF documents
  • The client HTTP request uses the HEAD method

The HTTP HEAD method is usually used for obtaining meta-information about the requested object without transferring the full content of the requested object. For more information about the HEAD method, refer to 9.4 HEAD section of the RFC2616 Hypertext Transfer Protocol -- HTTP1.1.

Impact

The BIG-IP WebAccelerator system fails to pass traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Client HTTP request for a PDF document fails
  • The pvac process performs a core dump and restarts
  • Connections to BIG-IP WebAccelerator-enabled virtual servers stall
  • A message that appears similar to the following log message is written to /var/log/wa/pvac.log file:

    emerg logger: Re-starting pvac

Workaround

To work around this issue, you can configure an additional HTTP class for PDF requests to bypass the BIG-IP WebAccelerator. To do so, perform the procedure listed in the following solution: K9585: Using multiple HTTP classes to bypass BIG-IP WebAccelerator, and in that procedure, replace the URI Path field in Step 8 with *.pdf.

Impact of workaround: PDF documents will not be accelerated by the BIG-IP WebAccelerator system.
