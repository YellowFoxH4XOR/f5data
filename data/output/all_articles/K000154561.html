Description

When using BIG-IP ASM, the brute force protection feature may not return the response code configured in the Login Response Page to the client after brute force detection is triggered, even if the Login Page Response settings are configured to return a different code. The expected custom response code from the Login Page settings is not applied to brute force protection events; instead, the system uses the default Blocking Response.

Environment

  • Security policy with custom login pages configured
  • Brute force protection enabled

Cause

Brute force protection in BIG-IP ASM is designed to return the "Blocking Page Default" response code when a brute force event is detected. The custom login page response code (such as 429) is only applied to specific session or login violations, not to brute force protection events. This is expected product behavior.

Recommended Actions

Be aware that brute force protection will always use the Default Blocking response code and not the custom Login Page response code.

If a different response code is required for brute force events, consider submitting a feature request to F5 Support or explore iRules as a potential workaround to modify the response code.
