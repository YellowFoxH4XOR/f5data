Description

Security Events do not appear within the NIM UI, under Security Dashboard and Support ID Details. The following error may occur:

data could not be loaded for support ID<blob>

Environment

NGINX Instance Manager: App Protect Security Monitor

Cause

This issue may occur when the Ingestion and ClickHouse databases do not have enough disk space to store Security Event messages

The following NIM ERROR log messages may occur:

<ING>...ERROR /usr/bin/nms-ingestion clickhouse/sink.go:430 Insert failed: committing transaction: code: 243, message: Cannot reserve 1.00 MiB, not enough space
<DPM>...[ERR] JetStream failed to store a msg on stream '$G > REPORTS': write /var/lib/nms/streaming/jetstream/$G/streams/REPORTS/msgs/17.blk: no space left on device

The /var partion may be filled. For example:

$ df -h /var
/dev/mapper/sysVG-var 10G 9.8G 202M 99% /var

Recommended Actions

To mitigate this issue:

  • Increase the size of the /var partition
  • Reduce the size of stored Security Events by decreasing the number of days they are stored :
nim:$ grep ' ttl_configs' /etc/nms/nms.conf -A 6
ttl_configs:
- feature: metrics
ttl: 32 # number of days
- feature: events
ttl: 120 # number of days
- feature: securityevents
ttl: 32 # number of days
    • The above change requires a system restart: `sudo systemctl restart nms`

Additional Information

Implementing and adjusting logrotate would be effective if NIM logs were consuming large amounts of disk space

However, Security Event messages are stored in the ClickHouse database, and not within the logging directory

Here is documentation on NIM logging recommendations: https://docs.nginx.com/nginx-instance-manager/fundamentals/tech-specs/#logging
