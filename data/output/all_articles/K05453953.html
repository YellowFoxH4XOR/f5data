Description

This article is a guide to do a troubleshooting when ASM local logging is not functioning as it is configured. It's already confirmed the traffic is handled for the Virtual server and an LTM policy or irule which enables an ASM policy (usually done via packet capture). Then,  Virtual server has been configured with a local logging profile but there is no events in the report "Security >> Event Logs >> Application >> Requests".

1. Verify the security log profile is configured in MCPD database

# guishell -c "select * from fw_vs_log_profile;"

-----------------------------------------------------------------------------------------------------
| VIRTUAL_SERVER_NAME |           PROFILE_NAME | OBJECT_ID | PARTITION_ID | FOLDER_NAME | LEAF_NAME |
-----------------------------------------------------------------------------------------------------
|        /Common/test | /Common/logging_local |    135701 |       Common |     /Common |      test |
-----------------------------------------------------------------------------------------------------
1 row 0.059s (mcpd: 0.000s, mcpj: 0.004s, hsql: 0.048s, conn: 0.004s, format: 0.003s)
              (rcv: 0Kb, 0.000s, snd: 38b, 0.000s)

2. Check the vs_name_crc in table VS_RAMCACHE

  # mysql -t -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'select * from DCC.VS_RAMCACHE' | grep "<virtual_server>"

+----------------+-------------+----------------+
| vs_name        | vs_name_crc | ramcache_state |
+----------------+-------------+----------------+
| /Common/test   |   937764819 |              0 |
+----------------+-------------+----------------+

3. Check the log_profile_name_crc in table LOG_LOCAL_STORAGE_CONFIGURATION

  # mysql -t -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'select * from DCC.LOG_LOCAL_STORAGE_CONFIGURATION' | grep "<log_profile>"

+---------------------+----------------------+--------------------+------------------+-----------------------------+
|   log_profile_name  | log_profile_name_crc | guaranteed_logging | response_logging | response_guaranteed_logging |
+---------------------+----------------------+--------------------+------------------+-----------------------------+
|/Common/logging_local|           4287994568 |                  0 |                1 |                           0 |
+---------------------+----------------------+--------------------+------------------+-----------------------------+

4. Check the match between vs_name_crc and log_profile_name_crc

  # mysql -t -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'select * from DCC.VS_LOG_PROFILE' | grep "<vs_name_crc>"

+----------------------+-------------+--------------+
| log_profile_name_crc | vs_name_crc | storage_type |
+----------------------+-------------+--------------+
|           4287994568 |   937764819 |            0 |
+----------------------+-------------+--------------+

5. Reviewed the configuration in MCPD database to confirm security log profiles are configured with the right filter: illegal, all or illegal with staged signatures and threat campaigns

# guishell -c "select PARENT_PROFILE, VALUE_LIST from fw_log_request_filter"

|               PARENT_PROFILE |                          VALUE_LIST |
----------------------------------------------------------------------
|         /Common/illegal_only |                             illegal |
|         /Common/all_requests |                                 all |
| /Common/illegal_n_staged_ASU | illegal-including-staged-signatures |
