Known Issue

Configurations with custom SSL certificates and keys may fail to load after upgrading directly from BIG-IP 10.2.x to 11.6.1.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system configuration contains one or more SSL profiles with custom SSL certificates and keys associated.
  • You have upgraded the BIG-IP system directly from 10.2.x to 11.6.1.

Impact

The BIG-IP system will fail to process traffic as a result of the configuration load failure.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After rebooting the BIG-IP system to a newly installed 11.6.1 software partition, you notice error messages similar to the following in the /var/log/ltm file:

    emerg load_config_files: "/usr/libexec/bigpipe load" - failed. -- BIGpipe parsing error (/config/bigpipe/bigip.conf Line 67):    012e0020:3: The requested item (exampleclientssl {) is invalid (<profile arg> ` show ` list ` edit ` delete ` stats reset) for 'profile'.

Workaround

To work around this issue, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system command line.
  2. To make a backup copy of the /config/bigpipe/bigip.conf file, type the following command:

    cp /config/bigpipe/bigip.conf /config/bigpipe/bigip.conf.save

  3. Using a text editor, edit the /config/bigpipe/bigip.conf file and delete the reference to inherit-certkeychain in the affected SSL profile.
  4. To load the initial portion of the upgraded configuration, type the following command:

    Important: You should use the following command only when instructed to do so in an article or by F5 Technical Support.

    /usr/libexec/bigpipe daol

  5. To save the upgraded configuration, type the following command:

    tmsh save sys config

  6. To load the upgraded configuration into memory, type the following command:

    tmsh load sys config
