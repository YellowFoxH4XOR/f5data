Known Issue

BIG-IP APM connections may temporarily stop responding when access profiles are configured with WebSSO.

This issue occurs when all of the following conditions are met:

  • A BIG-IP APM access profile is configured with WebSSO.
  • Clients that use the access profile attempt to upload large files with HTTP POST during a time when the BIG-IP system experiences high memory utilization.

Impact

The BIG-IP APM system may stop responding to client sessions and administrative access requests.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H427316 on the Diagnostics > Identified > Medium|High screen.
  • While client sessions attempt to re-establish connections, you receive a pop-up message that displays the following:

    you have lost connectivity
  • The active BIG-IP APM status reports as offline when viewed from the Configuration utility or from the command line.
  • Error messages are logged to the /var/log/daemon.log file and appear similar to the following example:

    emerg logger: Re-starting websso0
  • Running the command line ls -l /shared/core command displays WebSSO core files similar to the following example:

    -rw------- 1 root root 612490565 Jan 6 03:50 2014 websso.0.bld2185.0.core.gz
  • Using the bigstart status websso command restarts the websso daemon repeatedly, and displays a message similar to the following example:

    websso run (pid 13365) 32 seconds, 7 starts
