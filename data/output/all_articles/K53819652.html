Known Issue

The BIG-IP system forwards a fragmented Internet Control Message Protocol (ICMP) with an incorrect ICMP checksum.

This issue occurs when the following condition is met:

  • A FastL4 virtual server transmits ICMP frames (ip-protocol, ICMP, or any), a secure network address translation (SNAT), or a network address translation (NAT), only when the system receives a fragmented ICMP packet (or SNAT or NAT) to be passed through the virtual server.

Impact

The recipient drops large ICMP echo packets (greater than the maximum transmission unit [MTU]) due to the checksum error. You will not see any echo responses.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Large, fragmented ICMP packets that traverse the BIG-IP system might have their source or destination IP addresses changed and transmitted, with the checksum incorrectly calculated.

Resolution

Status

Workaround

To work around this issue, you can turn on the IP fragment reassembly on the FastL4 profile that is associated with the virtual server. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > FastL4.
  3. Click the FastL4 profile that the affected virtual server is using.
  4. Click Reassemble IP Fragments.
  5. Click Update.
