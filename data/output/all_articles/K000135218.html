K000135218: Error "Sctp Link is changed" in FEP logs

Type
Support Solution
Published
2023-06-25
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K000135218

Description

  • You see the alarms below in the FEP logs : 

<DATE AND TIME> INFO [12469] **SNMP** Alarm was created: SiteIdTrapProperty = SITE-SDC 1.3.6.1.4.1.3375.3.1.4.3.6.0.10 HostNameTrapProperty = SITE-SDC-1 [SiteIdTrapProperty=SITE-SDC, HostNameTrapProperty=SITE-SDC-1, AffectedObjectTypeTrapProperty=20000, EventTypeTrapProperty=6, EventIdTrapProperty=peerSctpLink, DetectorComponentTrapProperty=SITE-SDC-1_fep-p-sctp, ManagedObjectInstanceTrapProperty=PEERMME01.epc.001.3gppnetwork.org, EventDateAndTimeTrapProperty=XX:XX:XX:XX:XX:XX:XX:X:XX:XX:XX, EventDescriptionTrapProperty=Sctp Link is changed, SeverityTrapProperty=major, AdditionalTextTrapProperty=One of the links between the SDC site and one of its peers is down. The remote address is: YYY.YYY.YYY.YYY:3868, the local address is ZZZ.ZZZ.ZZZ.ZZZ:3868. The reason is No HB acknowledge for Non-Primary address /AAA.AAA.AAA.AAA:3868. The peer type is: Diameter. The peer name is: PEERMME01.epc.001.3gppnetwork.org. The association id is: 13938116., AlarmEventLogAutoClearedTrapPropert...

 

  • Where : 

AAA.AAA.AAA.AAA - The Non-Primary address 

PEERMME01.epc.001.3gppnetwork.org - Client Peer Name

 

Environment

  • Traffix SDC 5.x
  • FEP
  • Diameter Peers

Cause

It can be triggered if the SCTP diameter client/server does not reply to Heartbeat or the SCTP client/server closes the link.

 Recommended Actions

  1. Take a tcpdump/pcap to see the communication between the FEP and the Diameter peer.
  2. Need to determine the FEP involved, traffic flow, routing ID used, transformation rules involved as well. These are needed to understand the whole flow and how the SDC is processing the diameter traffic.

Additional Information
