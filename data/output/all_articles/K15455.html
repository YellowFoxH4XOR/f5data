Known Issue

The merged process may experience high CPU usage.

This issue occurs when the following condition is met:

  • The BIG-IP configuration includes a large number of local traffic objects. (For example, the configuration contains 10,000 local traffic objects.)

The merged process collects statistical data from various subsystems on the BIG-IP system. By default, the merged process runs at a nice level of 5 and collects data every (1) second. For systems with larger configuration sizes, the default data collection interval may cause high CPU usage.

Impact

High CPU usage may adversely affect performance and management of the BIG-IP system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP performance graphs indicate high CPU usage.
  • The top command shows that the merged process is experiencing high CPU usage as indicated in the following output example:

Workaround

To work around this issue, you can change the interval in which the merged process collects statistical information. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system will collect statistical information less frequently.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To change the interval in which the merged process collects statistical information, use the following command syntax:

    modify /sys db merged.merge.interval {value "<1-10>"}

    For example, to change the interval in which the merged process collects statistical information from 1 to 5 seconds, type the following command:

    modify /sys db merged.merge.interval {value "5"}
  3. Save the configuration by typing the following command:

    save /sys config
