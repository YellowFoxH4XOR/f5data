Topic

The ARX metadata is a method for the ARX system to track the location of files and directories on multiple disparate shares for ARX managed volumes. The ARX system uses this data to translate the location of files into one unified volume on the front end to present the information by way of the NFS or CIFS services.

Description

To support the managed volume, the ARX system creates a repository of directories and files on a dedicated Network Area Storage share. Database files within the directories keep track of all the data that is required to manage the ARX volume. This body of information is referred to as the ARX metadata, or the metadata.

Note: For a brief overview of volumes, refer to the ARX Site Planning Guide. 

The ARX metadata only indexes the present location of files; it provides a historical log of the past movements of files between filers by way of policies or client activity. Metadata may be configured for a whole namespace or for each individual managed volume. Additionally, each piece of ARX metadata is uniquely keyed to the ARX system that generated it, and cannot be swapped, migrated, or reassigned in bulk among ARX systems.

If necessary, metadata may be migrated to another target repository.

Note: For more information, refer to K8888: Overview of metadata migration.

In a high-availability ARX configuration, when the active unit loses access to the metadata, but the standby unit maintains access to the metadata, a failover can be automatically initiated. This behavior is not enabled by default, but you can configure it by designating any given metadata share as critical.

Note: For more information, refer to the Designating the Metadata Share as Critical section in the ARX CLI Storage Management Guide.

Troubleshooting ARX metadata failure

If you need to troubleshoot metadata, the ARX system has utilities where you can manage and troubleshoot the metadata with various nsck command invocations.

Note: For more information, refer to the Metadata Utilities chapter in ARX CLI Maintenance Guide.

If the data on the metadata share has been corrupted, you can rebuild the metadata with the nsck rebuild command.

Note: For information about rebuilding metadata, see the Rebuilding a Namespace section of the ARX CLI Maintenance Guide.

Note: If the original share that is hosting the metadata is permanently offline, refer to K9216: Repairing a volume when the volume metadata share is lost.

Recommendations

When you are planning an ARX managed volume, F5 recommends that you define separate metadata shares for each volume, individually, at the gbl-ns-vol level, to reduce common points of failure between managed volumes.

Note: For information about the procedures, and the commands used when setting up metadata for a managed volume, refer to the Storing Volume Metadata on a Dedicated Share section of the ARX CLI Storage Management Guide.
