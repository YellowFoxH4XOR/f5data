Known Issue

Note: This issue only affects the ARX 6000 platform.

This is the result of a known issue. The Adaptive Services Module's (ASM) sntpc process may fail to time out and indefinitely wait for an NTP response from the System Control Module (SCM). As a result the ASM may experience a time skew from the SCM.

To maintain time synchronization between the ASM and the SCM, the ASM's sntpc process requests time updates from the SCM. If the sntpc process does not receive an NTP response from the SCM, the initial request will time out and a new request is sent. However, if sntpc does not receive a response for the subsequent request, the request is not timed out and the sntpc process will indefinitely wait for the response from the SCM. As a result, the ASM time is no longer updated and the ASM may experience a time skew from the SCM. If the ASM and SCM experience a time skew greater than 5 minutes, Kerberos authentication will fail and may result in a service outage.

When the sntpc process is waiting for a response from the SCM, an entry for sntpc will remain persistent in the show system tasks command output.

For example:

The ARX system will not log error messages or send SNMP traps when the sntpc process fails to receive a response from the SCM, or if the ASM experiences a time skew from the SCM. However, if the time skew increases to the point in which Kerberos authentication fails, the ARX system will log an error mesage that appears similar to the following example:

:VCIFS-1-ERR-SECBLOBGET::Failed to obtain authentication credentials for host 'user1@ASK.COM' on behalf of principal 'user2@ASK.COM' at IP address 10.10.10.2 to CIFS service 'arx1.ask.com'. The Kerberos error message is 'Clock skew too great' (KRB5KRB_AP_ERR_SKEW, - 1765328347).

F5 tracked this issue as ID 39300 and it was fixed in ARX version 5.1.7. For information about upgrading, refer to the ARX Release Notes.

This issue has also been fixed in ARX version 5.1.5 Hotfix 7 (build 1982) issued for ARX version 5.1.5. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

Additionally, this issue has been fixed in a hotfix available for ARX version 5.0.6. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID 39300.
