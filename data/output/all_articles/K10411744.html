Description

When using gateway failsafe, you may observe that the gateway failsafe pool may stay in Unknown status even if you have assigned a monitor. On the Local Traffic  ››  Pools : Pool List  ››  Your-Gateway-Pool page, under the Members tab, you can find a similar message like below in the Availability field:

Unknown (Enabled) - Pool member does not have service checking enabled <timestamp>

Environment

The symptom is observed when you are under those conditions:

  • You are using gateway failsafe
  • You have created different pools for the gateway failsafe feature on different HA/DSC devices.

Cause

The Gateway failsafe pool is monitored by the assigned device only.

Recommended Actions

For the gateway pool that belongs to the peer device, no monitor instance will be assigned. Thus, it will stay in the Unknown status as expected. It is normal if you observed this symptom on your devices when you are using the gateway pool for gateway failsafe. You can check on which device your gateway failsafe pool is assigned by the below command:

tmsh list ltm pool <your-gateway-failsafe-pool> gateway-failsafe-device

For example, you've got an HA pair bigip1.local and bigip2.local. The below outputs show that the pool gateway-pool-1 is assigned to the device bigip1.local. So in this example, it's normal to see the pool gateway-pool-1 shows as Unknown on the peer device: /Common/bigip2.local

# tmsh list ltm pool gateway-pool-1 gateway-failsafe-device
ltm pool gateway-pool-1 {
    gateway-failsafe-device /Common/bigip1.local
}
