Description

LTM log contains frequent SIP errors with he following error message

MR SIP: Decrypt branch parameter failed with error : Illegal value

Environment

  • BIG-IP acting as a SIP stateful proxy
  • MRF Virtual Server running in LB mode
  • "Insert via header" enabled on the SIP session profile

Cause

These logs are due to a SIP server sending back an incorrect branch parameter in the topmost via header. "Insert via header" inserts custom flow information in the via header. When this action is done, the BIG-IP expects the same branch parameter to be in the SIP response. If the branch is not the same, it can affect the BIG-IP's ability to match the response to a flow, causing the system to drop the traffic and log the message noted above.

Recommended Actions

  • The branch parameter being sent by a SIP proxy in a single transaction needs to match on both the request and response. If a downstream SIP server is modifying a branch value that was inserted by the BIP-IP the downstream server should be corrected.
  • "MR SIP: Decrypt branch parameter failed with error : Illegal value" is ambiguous and can be hard to troubleshoot as it doesn't give a lot of information about what server is modifying the branch values. To help troubleshoot you can set the following db variables to "debug":

    tmsh modify sys db log.mrsip.level value Debug

    tmsh modify sys db log.mr.level value Debug

  • With those set you will now see logs from MR about what pool member messages are sent to. When a response is received and the branch has been modified MR SIP will log the "Decrypt branch parameter failed with error" message. Immediately after that MRF should log a notice: "No route found for message". These two additional MR logs have a message ID we can use to identify the specific server/node with the problem.

See the example below:
Message correlation ID in example: 5042345234523452

Jan 24 07:01:58 LTM1 info tmm[10495]: 01850019:6: MR: Routing to egress host 10.10.10.10%0:5060 message 93485098345345/5042345234523452
Jan 24 07:01:58 LTM1 err tmm[10495]: 01860003:3: MR SIP: Decrypt branch parameter failed with error : Illegal value
Jan 24 07:01:58 LTM1 notice tmm[10495]: 0185001b:5: MR: No route found for message 93485098345345/5042345234523452. Return to orginator [0.0]

If you see this issue again, you can refer to the "No route found for message" log that immediately follows the branch parameter decryption failure. Once you have the message correlation ID you can match it up with the past MR logs to see what pool member it was received from. In this example you can see that the problematic host is 10.10.10.10.
 

NOTE: Its not recommended to keep the db variables set at debug for extended periods of time. Debug logs, if not managed correctly, can consume excessive amounts of storage on the BIG-IP.

  • When troubleshooting is finished, set the db variables back to the defaults:

    tmsh modify sys db log.mrsip.level value Error

    tmsh modify sys db log.mr.level value Error
