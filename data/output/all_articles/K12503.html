Topic

One of the features that makes HTTP such a powerful and versatile protocol is its ability to allow a web server to stream dynamic information to a web browser within a single request/response transaction. The term dynamic information is used to describe the stream of data generated by interactive applications that do not know in advance how much data they are going to send or when they are going to send it. These applications include stock tickers, web mail, web chats, auctions, and animations (such as progress bars).

To achieve this, chunked transfer encoding was introduced in HTTP 1.1, allowing HTTP messages to be divided into several parts. Chunking is most often used by the server for responses, but clients can also chunk large requests. By sending small chunks of data as soon as new information becomes available (for example, each time the price of a stock changes), a server can keep using the same request/response transaction indefinitely. Overall, chunking may also improve user perception of response time, as the different components of a web page are sent incrementally.

However, if a virtual server on the BIG-IP system is configured to perform HTTP compression, the BIG-IP system will try to buffer as much data as possible (either until the server has received the complete payload, or until the compression buffer has been filled) before initiating compression and sending the data to the client. While this design makes for better performance, it has the opposite affect on applications that are time sensitive or never finish sending chunks. When such applications are run behind a virtual server with HTTP compression enabled, the client may never get a response, even though the server has received the request and is sending data to the BIG-IP system.

In order to make these applications work without having to disable HTTP compression, a new setting was added to the HTTP profile beginning in BIG-IP versions 9.3.0 and 9.4.4. The setting works by preventing the compression buffer from delaying the delivery of data to the client.
