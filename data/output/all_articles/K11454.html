Known Issue

This is the result of a known issue. If a domain controller provides slow responses to Kerberos queries, the ARX Network Services Module (NSM) may not release the UDP port resources used for the Kerberos requests. As a result, the ARX system may eventually consume all available UDP port resources and send an SNMP trap that appears similar to the following example:

- nsmResourceThreshold        UDPPorts 10.10.10.38  utilization:100% slot:4 proc:6

Additionally, a message similar to the following will be logged to syslog:

:NET_OS-0-NOTE-NSM_PORTMGR_OUT_OF_PORTS::No available UDP Non-Priv  ports for 10.10.10.38.

F5 Product Development tracked this issue as ID 37955 and it was fixed in ARX version 5.1.5. For information about upgrading, refer to the ARX release notes.

Additionally, a hotfix has been issued for ARX version 5.0.6. Customers affected by this issue should contact F5 Technical Support, referencing this Solution number and the associated ID number, to request the hotfix.
