Topic

You should consider using this procedure under the following condition:

  • You want to configure an NT LAN Manager (NTLM) machine account on the BIG-IP APM system so the system can connect to a domain controller (DC) on a non-default route domain.

Description

By default, you can configure machine accounts for front-end NTLM authentication only on route domain 0. You can work around this limitation by configuring forwarding virtual servers on route domain 0 that forward NTLM traffic to the domain controller (DC) on a different route domain.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Administrative access to the Configuration utility

Procedures

To configure a machine account for front-end NTLM authentication on a route domain other than 0, you must complete the following tasks:

Note: You must complete the following tasks to use a single DC in your configuration. If you want to use more DCs, repeat the same steps to create additional nodes, pools, forwarding virtual servers, routes and hosts entries. You can add them in NTLM Auth Configuration under Access > Authentication > NTLM.
  • Create or define an administrative partition
  • Create or define a VLAN
  • Create or define a route domain
  • Associate the new route domain to the new administrative partition
  • Create or define a self IP
  • Create or define a default route
  • Create or define a pool/node for the DC
  • Create TCP and UDP forwarding virtual servers with a fictitious IP address to process NTLM traffic
  • Create or define a route for the fictitious IP address 
  • Add a host entry for the DC
  • Create an NTLM machine account

Create or define an administrative partition

Create an administrative partition to organize configuration objects that are related to your implementation. In the following procedure, you will create a partition named Customer1.  

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Users > Partitions List.
  3. Select Create and type the partition name.

    For example:

    Customer1

  4. Select Finished.

Create or define a VLAN

For the previously created partition (Customer1), create a Virtual Local Area Network (VLAN) for your implementation traffic. In the following procedure, you will create a VLAN named Customer1_vlan.  

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > VLANs > VLAN List.
  3. Select Create and type the partition name.

    For example:

    Customer1

  4. Add the appropriate interfaces, and select Finished.

Create or define a route domain

For the previously created partition (Customer1), create a route domain for the NTLM Authentication traffic. In the following procedure, you will create a route domain named RD1 with ID 1.

Note: The route domain for NTLM authentication must be a child of route domain 0.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Route Domain.
  3. Select Create and in Name box, type the route domain name.

    For example:

    RD1

  4. In the ID box, type the ID.

    For example:

    1

  5. In the Parent Name box, select 0.
  6. Select the previously created VLAN (Customer1_vlan) as a VLANs member.
  7. Select Finished.

Associate the route domain to the new administrative partition

Modify the previously created administrative partition named Customer1 to use the previously created route domain ID 1.  

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Users > Partitions List.
  3. Select the partition name Customer1.
  4. In the Partition Default Route Domain drop-down menu, select 1.
  5. Select Update.

Create or define a self IP

For the previously created partition (Customer1), create a self IP address for your implementation. In the following procedure, you will create a self IP named Customer1_self with IP address 10.1.1.142/24.  

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Self IPs.
  3. Select Create and in the Name box, type the name of the Self IP.

    For example:

    Customer1_self

  4. In the IP Address box, type the Self IP and append the route domain sign and ID of the previously created route domain (RD1).

    For example:

    10.1.1.142

  5. In the Netmask box, type the netmask for your self IP address.

    For example:

    255.255.255.0

  6. In the VLAN/Tunnel box, select the previously created VLAN (Customer1_vlan.
  7. Select Finished.

Create or define a default route

For the previously created partition (Customer1), create a default route for your implementation traffic. In the following procedure, you will create a default route with a Gateway address of 10.1.1.2.  

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Routes.
  3. Select Add and in the Name box, type a name.

    For example:

    default

  4. In the Destination box, type 0.0.0.0.
  5. In the Netmask box, type 0.0.0.0.
  6. In the Resource box, select Use Gateway.
  7. In the Gateway Address box, specify the gateway IP Address to your implementation traffic.
  8. Select Finished.

Create or define a pool and a node for the DC

For the previously created partition (Customer1), create a pool and add DCs as nodes. In the following procedure, you will create a pool named Customer1_pool with a single node corresponding to the DC.  

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pool > Pool List.
  3. Select Create, and in the Name box, type a name for the pool.

    For example:

    Customer1_pool

  4. In the New Members section, select or create a new node that corresponds to the DC.

    For example, select Add, and in the New Node box, type the following:

    Address 10.1.1.10

  5. Select Finished.

Create TCP and UDP forwarding virtual servers with a fictitious IP address to process NTLM traffic

For the previously created partition (Customer1), create a TCP and a UDP forwarding virtual server with a fictitious IP address that will process NTLM traffic in route domain 0, directed to the DC. In the following procedure, you will configure a TCP virtual server, vs_fwd_ntlm_customer1_tcp and UDP virtual server vs_fwd_ntlm_customer1_udp that share the same unused IP address 10.55.55.1%0.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create and in the Name box, type a name for the forwarding TCP virtual server.

    For example:

    vs_fwd_ntlm_customer1_tcp

  4. In the Type box, select Performance (Layer 4).
  5. In the Destination Address/Mask box, type the IP address for the virtual server.

    For example:

    10.55.55.1%0

  6. In the Service Port box, select * All Ports.
  7. In the Protocol box, select TCP.
  8. In the Resources section under Default Pool box, select Customer1_pool
  9. In the Configuration section in Advanced mode, make sure Port Translation is not selected.
  10. In the Source Address Translation box, select Auto Map.
  11. Select Finished.
  12. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  13. Select Create and in the Name box, type a name for the forwarding UDP virtual server.

    For example:

    vs_fwd_ntlm_customer1_udp

  14. In the Type box, selectPerformance (Layer 4).
  15. In the Destination Address/Mask box, type the IP address for the virtual server.

    For example:

    10.55.55.1%0

  16. In the Service Port box, select * All Ports.
  17. In the Protocol box, select UDP.
  18. In the Resources section under Default Pool box, select Customer1_pool
  19. In the Configuration section in Advanced mode, make sure Port Translation is not selected.
  20. In the Source Address Translation box, select Auto Map.
  21. Select Finished.

Create a route for the fictitious IP address

For the previously created forwarding virtual server address (10.55.55.1%0), create a route for your implementation traffic. In the following procedure, you will create a route with a Gateway address of 10.1.1.2 (same as the default route).  

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Routes.
  3. Select Add and in the Name box, type a name.

    For example:

    route_to_forwarding_vs

  4. In the Destination box, type 10.55.55.1%0.
  5. In the Netmask box, type 0.0.0.0.
  6. In the Resource box, select Use Gateway.
  7. In the Gateway Address box, specify the gateway IP Address to your implementation traffic.
  8. Select Finished.

Add a host entry for the DC

In the Common partition, create a host entry to match the DC's fully qualified domain name (FQDN) with the IP address of the previously created forwarding virtual server. In the following procedure, you will associate 10.55.55.1 with dc.customer1.com.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > Hosts.
  3. In the IP Address box, type the IP address of the forwarding virtual server.

    For example:

    10.55.55.1

  4. In the Hostname box, type the FQDN of the DC.

    For example:

    dc.customer1.com

  5. Select Update.

Create an NTLM machine account

For the previously created partition (Customer1), create an NTLM machine account in route domain 0. In the following procedure, you will create a machine account for DC dc.customer1.com.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Authentication > NTLM > Machine Account.
  3. Select Create, and in the Name box, type the name of the machine account.

    For example:

    Customer1_maccount

  4. In the Domain FQDN box, type the qualified domain name for the domain you want to join.

    For example:

    customer1.com

  5. In the Domain Controller FQDN box, type the FQDN of the DC.

    For example:

    dc.customer1.com

  6. In the Admin User box, type a user account with administrative privileges.

    For example:

    Administrator

  7. In the Admin Password box, type the password for the admin user.
  8. Select Join.
