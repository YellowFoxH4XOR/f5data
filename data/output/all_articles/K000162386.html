K000162386: F5OS "Image Upload" function failed with "Copy Failed" Error via GUI after HR-1 software upgrade

Type
Support Solution
Published
2026-07-23
Updated
2026-09-18
Applies to
  • F5OS Products
  • F5OS-C: 1.6.4, 1.8.2
  • F5OS-A: 1.8.4, 1.5.4
  • F5OS: 2.0.0
Source
https://my.f5.com/manage/s/article/K000162386

Description 

When uploading a tenant image (e.g., BIGIP-*.tar.bundle) or an F5OS ISO file through the F5OS webUI "Tenant Images → Upload" function, the upload progresses to approximately 99% and then fails with a "Copy Failed" status. Hovering over the failure message displays the popup: "File failed to copy to destination directory."

You will observe the issue when uploading the following images:

  • Tenant images (e.g., BIGIP-*.tar.bundle)
  • F5OS images (e.g., F5OS*.iso)
  • Configuration backup files (upload through System Settings > File Utilities)

Cause

Bug ID 2433793

Recommended Actions

You may select one of the following options below:

  1. Upgrade to an F5OS HR-2 release. This issue is fixed in HR-2 releases for the affected F5OS versions. For more information about F5OS HR-2 releases, refer to K000163032: What are the releases for Hardened Release 2 (HR2).
  2. Use webUI Import instead of Upload. In the F5OS webUI, use the Import function (import via URL from an accessible repository) rather than Upload. This method was confirmed to work reliably in testing. For more information, refer to the following manuals:
    • rSeries: File import from the webUI
    • VELOS: File import from the webUI
  3. Use SCP to push the file directly to the F5OS system. For VELOS systems, replace <F5OS_management_IP> with the IP address of the target system controller or chassis partition to which you are uploading the file.


    For F5OS ISO file:
    If you have "root" access.

    scp <path/to/filename/on/local/workstation> root@<F5OS_management_IP>:/var/import/staging

    If you have "admin" access.

    scp -O <path/to/filename/on/local/workstation> admin@<F5OS_management_IP>:images/staging/


    For Tenant image:
    If you have "root" access.

    scp <path/to/filename/on/local/workstation> root@<F5OS_management_IP>:/var/F5/system/IMAGES

    If you have "admin" access.

    scp -O <path/to/filename/on/local/workstation> admin@<F5OS_management_IP>:IMAGES


    For configuration backup file:
    If you have "root" access.

    scp -O <path/to/filename/on/local/workstation> root@<F5OS_management_IP>:/var/F5/system/configs

    If you have "admin" access.

    scp -O <path/to/filename/on/local/workstation> admin@<F5OS_management_IP>:configs/

Additional Information

Manual image upload via SSH is also documented in K10910515. If you are affected by this issue you should use the Import or SCP workarounds above until you are able to upgrade to a fixed release.
