K15371: The BIG-IP system may mistakenly insert an HTTP header rather than replace it when using a local traffic policy

Known Issue

The BIG-IP system may mistakenly insert an HTTP header rather than replace it. This issue occurs when all of the following conditions are met:

  • The affected virtual server is associated with a local traffic policy.
  • The local traffic policy is configured to replace an HTTP header in either an HTTP request or response using the http-header replace action. The following example configuration snippet describes a local traffic policy that is configured to find the HTTP header Server that has a value starting with MyWebServer, and replace the value with AnonymousServer in an HTTP response:

    ltm policy bug444178 {
    controls { response-adaptation }
    requires { http }
    rules {
    replace_a_header {
    actions {
    0 {
    http-header
    response
    replace
    name Server
    value AnonymousServer
    }
    }
    conditions {
    0 {
    http-header
    response
    name Server
    starts-with
    values { MyWebServer }
    }
    }
    ordinal 1
    }
    }
    strategy first-match
    }

Impact

HTTP traffic that the BIG-IP system processes contains duplicate HTTP headers. As a result, HTTP traffic between the client and server may be affected, depending on the client browser or web server.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A packet capture of the affected HTTP traffic shows that it contains an additional header, which was configured to be replaced by the local traffic policy after the BIG-IP system processed it. The following example shows an HTTP response before the BIG-IP system processed it:

    HTTP/1.1 200 OK
    Date: Tue, 24 Jun 2014 05:28:32 GMT
    Server: MyWebServer/2.0.59
    Vary: Accept-Encoding
    Content-Length: 13
    Content-Type: text/html; charset=UTF-8

    The following example shows the same HTTP response after the BIG-IP system processed it:

    HTTP/1.1 200 OK
    Date: Tue, 24 Jun 2014 05:28:32 GMT
    Server: MyWebServer/2.0.59
    Vary: Accept-Encoding
    Content-Length: 13
    Content-Type: text/html; charset=UTF-8
    Server: AnonymousServer
