Known Issue

This is the result of a known issue. A change to the media settings beginning with the BIG-IP version 9.2 software branch causes a syntax error when upgrading to BIG-IP versions 9.2 through 9.2.4 and rolling forward a BIG-IP version 9.1.x configuration containing an interface with a hard set media type of 1000baseFX, 1000baseTX, 10000baseFX or 10000baseTX. The syntax error will result when you try to load the /config/bigip_base.conf file.

The syntax error message displayed to the console will appear similar to the following example:

BIGpipe: 010a0040:3: Syntax error in /config/bigip_base.conf line 8: media 1000baseFX full

Important: If the /config/bigip_base.conf file contains the syntax error, the base network configuration will not load. The BIG-IP system will not load the management IP address or any self IP addresses and will not be accessible over the network. Only console access will be possible.

F5 Networks Product Development tracked this issue as CR60857 and CR60928, and it was fixed in BIG-IP versions 9.3 and 9.4. For information about upgrading, refer to the LTM, GTM, ASM, or Link Controller Release Notes.

Workaround

Prevention

If your network environment allows setting the media settings to auto negotiate prior to the upgrade, it is possible to prevent the syntax error from occurring after an upgrade. To configure the media type settings to auto negotiate, perform the following procedure:

Configuration utility:

  1. Log in to the Configuration utility.
  2. Click Network.
  3. Click Interfaces.
  4. Select the interface that you want to configure.
  5. From the Requested Media dropdown menu, select auto.
  6. Click the Update button.
  7. Repeat steps 3 through 6 for all interfaces that have been configured with a hard set media type.

Command line:

  1. Log in to the command line using SSH or console access.
  2. To view the current interface media settings, type the following command:

    bigpipe interface media show

  3. Set the media type settings to auto negotiate by typing the following command:

    bigpipe interface <if name list> media auto

    Replace <if name list> with the list of interface names to be configured.

    For example, to configure interfaces 1.1, 1.2, 1.3, and 2.1, you would type the following command:

    bigpipe interface 1.1 1.2 1.3 2.1 media auto

  4. Save the configuration by typing the following command:

    bigpipe base save

Recovery

You can correct the syntax error in the /config/bigip_base.conf file and recover network access if you meet all of the following requirements:

  • You have already upgraded
  • You received the syntax error message
  • You are unable to access the BIG-IP using the network

To do so, perform the following procedure:

  1. Log in to the command line using console access.
  2. Change directories to the /config directory by typing the following command:

    cd /config

  3. Create a backup copy of the bigip_base.conf file by typing the following command:

    cp bigip_base.conf bigip_base.conf_sol6894

  4. Using a text editor, open the /config/bigip_base.conf file and locate the section containing the interface media settings, which will appear similar to the following example:

    
interface 2.1 {
    media 1000baseFX full
    }
  5. Depending on your network environment, you can either edit the interface media entry to use the new media type, or you can edit the interface media entry to configure the interface to auto negotiate.

    Note: For information about the new interface media types, refer to K6893: Change in Behavior: Interface media types.

    Edit the media entry as follows:

    • To use the new media type, use the following example:

      interface 2.1 {
      media 1000baseSX full
      }

    • To configure the interface to auto negotiate, use the following example:

      interface 2.1 {
      media auto
      }

  6. Save the file.
  7. Load the BIG-IP configuration, by typing the following command:

    bigpipe load

  8. The BIG-IP configuration will load successfully, with an output similar to the following example:

    # bigpipe load
    Reading configuration from /config/bigip_base.conf.
    Reading configuration from /usr/bin/monitors/base_monitors.conf.
    Reading configuration from /config/profile_base.conf.
    Loading the configuration ...
    [root@bigip:Standby] config #
