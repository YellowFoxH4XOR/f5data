K92035082: Editing an APM Access Policy through Visual Policy Editor (VPE) is slow

Type
Support Solution
Published
2025-04-04
Updated
2025-04-04
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K92035082

Description
    Performing modifications on an Access Policy through APM's VPE (Visual Policy Editor) is slow.

Environment
APM Agents

Cause
    BIG-IP configuration contains too many objects.

Recommended Actions
1- Consider removing unused configuration objects or re-designing your configuration to use fewer configuration objects.
2- As a temporary workaround, you can add "&nosaveconf=1" at the end of the URL on the VPE editor.
Example:
    Edit the policy called "/Common/POLICYNAME" and see the URL in the browser:
        https://bigipadmin/sam/admin/vpe2/public/php/vpe.php?r[accessPolicyName]=/Common/POLICYNAME
    Modify this URL to be:
        https://bigipadmin/sam/admin/vpe2/public/php/vpe.php?r[accessPolicyName]=/Common/POLICYNAME&nosaveconf=1

When using this "nosaveconf=1" option, VPE changes its default behavior of saving the configuration after each change is performed.
In this alternate mode, you will have to click the 'Apply Access Policy and Save Configuration' button on the top left corner in order to ensure your changes are both saved and applied.
