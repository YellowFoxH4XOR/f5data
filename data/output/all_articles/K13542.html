Topic

You should consider using this procedure under the following condition:

  • You want to install a replacement BIG-IP DNS (formerly known as BIG-IP GTM) Return Management Authorization (RMA) unit in an existing BIG-IP DNS synchronization group that contains DNSSEC zones or password protected objects.

Important: Especially for RMA of standalone devices, F5 recommends setting the device master key during initial configuration in order to use a known master key in case a UCS restore is necessary. Whenever possible, you should use the documented tmsh commands for master and unit key manipulation. Only use the f5mku command with assistance from F5 Support when no tmsh commands exist to perform the task you want.

Description

When a BIG-IP DNS system is configured with DNSSEC configuration, it uses its own master key to decrypt the DNSSEC keys located in either the wideip.conf file for 10.1.0 through 10.2.x, or the bigip_gtm.conf file for 11.x and later.

When a BIG-IP DNS system is configured to join a synchronization group and has successfully synchronized with the remaining members of the synchronization group, it uses the master key that is shared among all the members of the synchronization group to decrypt the DNSSEC keys in the configuration files. When any of the BIG-IP DNS synchronization group members require a replacement, you must ensure the shared master key is preserved across all members of the BIG-IP DNS synchronization group for successful decryption of the DNSSEC keys.

If the master key on the replacement BIG-IP DNS RMA unit is not synchronized with the remaining members of the synchronization group, you can perform either of the following procedures to restore the shared master key.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have configured the BIG-IP DNS RMA replacement unit. For information refer to the following articles:
    • K12880: Configuring a replacement BIG-IP device after a Return Materials Authorization
    • K14083: Preventing synchronization when installing a UCS archive on a BIG-IP DNS system
    • K14044: Removing and re-adding a BIG-IP DNS system to an existing BIG-IP DNS synchronization group
    • K13734: BIG-IP DNS synchronization group requirements
    • K9420: Installing UCS files containing encrypted passwords or passphrases
  • The BIG-IP DNS RMA unit is properly licensed and provisioned with the BIG-IP DNS module and the DNSSEC feature.

Procedures

  • Running the gtm_add utility on the replacement BIG-IP DNS RMA unit that is not responding appropriately to DNSSEC requests
  • Using the f5mku utility to align the master key on the replacement BIG-IP DNS RMA unit

Running the gtm_add utility on the replacement BIG-IP DNS RMA unit that is not responding appropriately to DNSSEC requests

  1. Determine the BIG-IP DNS system that is correctly handling DNSSEC requests, or choose the BIG-IP DNS system for which DNSSEC was implemented. This system will be the master unit from which the replacement BIG-IP DNS RMA unit will pull its configuration by running the gtm_add utility.
  2. Log in to the command line of the replacement BIG-IP DNS RMA unit.
  3. Pull the configuration by running the gtm_add utility and specifying the IP address of the BIG-IP DNS system identified in step 1.

    For example, if the IP address of the BIG-IP DNS system identified in step 1 is 192.168.10.10, you would enter the following on the replacement BIG-IP DNS RMA unit:

    gtm_add 192.168.10.10

  4. Once the replacement BIG-IP DNS RMA unit completes the configuration pull from the BIG-IP DNS synchronization group, you can proceed to test the replacement BIG-IP DNS RMA unit to ensure it correctly answers DNSSEC requests.

    For example, you can use the dig utility on another client to verify a replacement BIG-IP DNS RMA unit that is listening on 192.168.20.20:53 for a DNS request to www.mywideip.com that is signed with DNSSEC keys:

    dig @192.168.20.20 +dnssec +multiline www.mywideip.com

Using the f5mku utility to align the master key on the replacement BIG-IP DNS RMA unit

  1. Determine the BIG-IP DNS system that is correctly handling DNSSEC requests, or choose the BIG-IP DNS system for which DNSSEC was implemented. The master key of this system is used to re-key the replacement BIG-IP DNS RMA unit.
  2. Log in to the command line of the BIG-IP DNS system identified in step 1.
  3. Type the following command:

    f5mku -K

    The output appears similar to the following example:

    fli2mS+z+wNKLbDQ0FUI1Q==

  4. Copy the output. The output is the shared master key that is used to re-key the replacement RMA unit.
  5. Log in to the command line of the replacement BIG-IP DNS RMA unit that needs the shared master key.
  6. Type the following command using the output from step 3:

    f5mku -r <key_value>

    For example:

    f5mku -r fli2mS+z+wNKLbDQ0FUI1Q==

  7. Verify the master key on the replacement BIG-IP DNS RMA unit has been re-keyed to the shared master key by typing the following command:

    f5mku -K

  8. Save the configuration by typing the following command:

    tmsh save /sys config

  9. Restart the replacement BIG-IP DNS RMA unit by typing the following command:

    reboot

  10. After the replacement BIG-IP DNS RMA unit restarts, you can test the replacement BIG-IP DNS RMA unit to ensure that it correctly answers DNSSEC requests.

    For example, use the dig utility on another client to verify a replacement BIG-IP DNS RMA unit that is listening on 192.168.20.20:53 for a DNS request to www.mywideip.com that is signed with DNSSEC keys:

    dig @192.168.20.20 +dnssec +multiline www.mywideip.com
