K02242270: F5 Access for Android - 'Accept-Language' headers are not sent as part of initial request

Type
Support Solution
Published

Updated

Source

Description

It is a know issue that F5 Access for Android does not send the Accept-Language header as part of the initial request

Environment

  • BIG-IP APM
  • F5 Access for Android
  • Locale other than English

Cause

This is a known issue being tracked by ID1081569.
Note: At the time of publications of this support solution, there currently is not a fix for this ID or a BugTracker record publicly available.

Recommended Actions

The current work-around would be to set all locale for Android device to the desired/area dominate language using an iRule.
This will be a global setting for all Android devices using F5 Access until a fix is introduced.

  1. Log in to the Configuration utility (GUI).
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. For Name, enter a name for the iRule. For example:
irule-andriodlocal-id1081569
  1. For Definition, use one of the iRules in the iRule definition section:

    Note: As with all iRules, you should test and customize them as appropriate for your environment prior to deploying in production.

  2. Click Finished.
  3. Navigate to Local Traffic > Virtual Servers.
  4. Click the name of the virtual server to which the access policy will be applied.
  5. Click the Resources tab.
  6. For iRules, click Manage.
  7. In the Available box, highlight the name of the iRule you just created.
  8. Click the << button. The iRule moves to the Enabled box.
  9. Click Finished.

Additional Information

You can additionally leverage GeoLocation with whereis into your iRule, incorporation of this in to above iRule would not be something F5 support can assist with.

If needed, You can obtain additional iRule support from your Account Team. DevCentral iRules 'whereis'

iRule definition

iRule 1

This is a simple and basic iRule that you can modify to meet the requirements in your environment. It applies your desired language when the HTTP request includes the headers for Android and F5 Access.

You should modify the language in the iRule as appropriate. For example,

ACCESS::session data set session.ui.lang "it"

For more information on content languages, refer to RFC 3282

when ACCESS_SESSION_STARTED {
    if { [HTTP::header User-Agent] contains "Android" && [HTTP::header User-Agent] contains "F5Access" }  {
        ACCESS::session data set session.ui.lang  "<language_code>"
    log local0. "Returning Android language to <language_desired>"
    }
}

For example, your iRule may appear similar to the following:

when ACCESS_SESSION_STARTED {
    if { [HTTP::header User-Agent] contains "Android" && [HTTP::header User-Agent] contains "F5Access" }  {
        ACCESS::session data set session.ui.lang  "it"
    log local0. "Returning Android language to Italian"
    }
}

iRule 2

This iRule provides additional functionalities with the following implementation:
  1. Extracts the language found in the Accept-Language header in the web logon page request from the client to set the session.ui.lang variable dynamically. 
  2. You should modify/add additional languages in the iRule switch statement as appropriate. For example,

    ACCESS::session data set session.ui.lang "it"

    For more information on content languages, refer to RFC 3282

  3. As this iRule runs for each request prior to VPN establishment for each user, F5 recommends you monitor the VPN service performance after deploying the iRule. This iRule has been successfully deployed in an environment with around 25,000 users.
when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}

when HTTP_REQUEST {
    set lines [split [HTTP::header Accept-Language] "," ]
    foreach line $lines {
        switch -glob [getfield $line ";" 1] {
            "<language code>" {
                ACCESS::session data set session.ui.lang  "<language code>"
                log local0. "Matched <language desired>[getfield $line ";" 1]"
                break
            }
        }
    }
}

For example, your iRule may appear similar to the following:

when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}

when HTTP_REQUEST {
    set lines [split [HTTP::header Accept-Language] "," ]
    foreach line $lines {
        switch -glob [getfield $line ";" 1] {
            "fr-CA" {
                ACCESS::session data set session.ui.lang  "fr"
                log local0. "Matched French [getfield $line ";" 1]"
                break
            }
        }
    }
}
