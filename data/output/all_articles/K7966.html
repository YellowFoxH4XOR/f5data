K7966: Unsuccessful logon attempts are incorrectly reported as successful when logons are denied due to an invalid Landing URI

Known Issue

This is the result of a known issue. When you specify a Landing URI for a Master Group, and a user in that Master Group attempts to logon to the FirePass controller from a different URI, FirePass will correctly deny access to the user but incorrectly report the logon as successful on the Reports: Logons page. Specifically, the Passed? column on the Reports: Logons page will display Yes instead of No for the failed logon attempt.

For example:

LogonValid user?Passed?
jsmithYesYes


F5 Product Development tracked this issue as CR85761 and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass release notes.

Additionally, Cumulative Hotfix HF-601-7 has been issued for FirePass version 6.0.1. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Downloads page.
