K000157283: OCSP Failure status 'Error querying OCSP responsder host (server.lab.lan) path (/)'

Type
Support Solution
Published
2025-11-05
Updated
2025-11-05
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000157283

Description

You have an OCSP agent in the access policy that verifies with the OCSP responder the real-time revocation status of a specific digital certificate.

The following error comes up, which means OCSP agent did not receive the OCSP response although a tcpdump on BIGIP shows the OCSP response was received and it was good.

OCSP Auth agent: Failure status 'Error querying OCSP responsder host (server.lab.lan) path (/)'

Environment

Conditions

  • BIG-IP deployed with APM.
  • APM with an access policy that includes an OCSP agent
  • OCSP response from OCSP responder is chunk encoded.

Cause

The version of OpenSSL library that BIGIP is running for OCSP API functions is v1.0.2za 

OCSP API functions in that OpenSSL release have limitations regarding advanced HTTP features like chunking.

Recommended Actions

There are two solutions

1) OCSP responder not sending OCSP responses chunk encoded.

It makes not sense OCSP responder to send the OCSP response chunk encoded because this is done for responses where the content length is not known in advance, that is not the case with OCSP.

2) Adding a layered VS on BIGIP that catches OCSP requests to OCSP responder and 'un-chunks' its OCSP responses.

2.1) Replace OCSP url with an internal ip address (like 10.1.100.100)

          apm aaa ocsp {
              url http://10.1.100.100
              ignore-aia true

2.2) Create a standard VS listening to 10.1.100.100:80 that has snat 'automap' enabled.

2.3) Add an http profile to layered VS that unchunks responses

          ltm profile http {
              response-chunking unchunk

2.4) Add an irule to layered VS that replaces Host header "10.1.100.100" with OCSP responder's fqdn (like "server.lab.lan")

          when HTTP_REQUEST {
              if { [HTTP::header exists Host] } {
                  HTTP::header replace Host server.lab.lan
              } else {
                HTTP::header insert Host server.lab.lan
              }
          }

2.5) Add a pool to layered VS with OCSP responder's ip address as pool member. Pool's port is 80
