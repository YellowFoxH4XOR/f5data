K000149210: Unable to whitelist the meta-char in security policy in NGINX App Protect

Type
Support Solution
Published
2025-01-08
Updated
2025-01-08
Applies to
  • NGINX Products
  • NGINX App Protect WAF: 5.0.X, 5.0.0
Source
https://my.f5.com/manage/s/article/K000149210

Description

This article provides guidance on resolving an issue where the meta-character (-) (0x2D) is not whitelisted correctly in an NGINX App Protect security policy. Despite configuring the "urls" block to allow the character, alerts for it persist in security logs. There are no errors observed during policy deployment, but the configuration does not produce the expected behavior.

Environment

  • NGINX App Protect
  • The "urls" block is configured with the following:
"urls": [
   {
      "method": "POST",
      "name": "/meta*",
      "protocol": "https",
      "type": "wildcard",
      "metacharsOnUrlCheck": true,
      "metacharOverrides": [
          {
              "isAllowed": true,
              "metachar": "0x2D"
          }
      ],
      "wildcardOrder": 2
   }
]

Cause

The XML content profile configuration did not explicitly address the meta-character (-) (0x2D). As a result, there was a mismatch between the configuration in the "urls" block and the XML content profile.

Recommended Actions

To resolve the issue, update the security policy configuration to ensure the meta-character (-) is properly addressed in the XML content profile. Use the following configuration::

{
   "policy" : {
      "character-sets" : [
         {
            "characterSet" : [
               {
                  "isAllowed" : false,
                  "metachar" : "0x2d"
               }
            ],
            "characterSetType" : "xml-content"
         }
      ],
      "name" : "xml-meta-test_2",
      "template" : {
         "name" : "POLICY_TEMPLATE_NGINX_BASE"
      },
      "urls" : [
         {
            "isAllowed" : true,
            "metacharsOnUrlCheck" : true,
            "method" : "*",
            "name" : "*",
            "protocol" : "http",
            "type" : "wildcard",
            "urlContentProfiles" : [
               {
                  "headerName" : "*",
                  "headerOrder" : "default",
                  "headerValue" : "*",
                  "type" : "apply-value-and-content-signatures"
               },
               {
                  "contentProfile" : {
                     "name" : "abc"
                  },
                  "headerName" : "Content-Type",
                  "headerOrder" : "3",
                  "headerValue" : "*xml*",
                  "type" : "xml"
               }
            ]
         }
      ],
      "xml-profiles" : [
         {
            "name" : "abc"
         }
      ]
   }
}
