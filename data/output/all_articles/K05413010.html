K05413010: After an upgrade, iRules using the loopback address may fail and log TCL errors

Type
Support Solution
Published
2022-07-28
Updated
2024-11-07
Applies to
  • Virtual Editions
  • BIG-IP
  • BIG-IP LTM: 17.X.X, 16.X.X, 17.0.X, 16.1.X, 16.0.X, 16.1.0, 16.0.1, 16.0.0, 15.1.6, 17.0.0, 16.1.3, 16.1.2, 16.1.1
Source
https://my.f5.com/manage/s/article/K05413010

Description

Post-upgrade, /var/log will start filling up with TCL errors.

  • TCL errors appear to indicate an invalid irule configuration that worked in the previous code.
  • Virtual server using the irule will fail.
  • TCL error: /Common/telemetry_local_rule <CLIENT_ACCEPTED> - disallow self or loopback connection (line 1)TCL error (line 1) (line 1) invoked from within "node 127.0.0.1 6514"

Environment

  • irules that use the "node" command and the loopback address 127.0.0.1 or using "connect" command with loopback address.
  • LTM
  • Normal Traffic

Cause

There is a functional code change in 15.1.6.1 and 16.1.2 and up:  

Database variable 'tmm.tcl.rule.node.allow_loopback_addresses' and 'tmm.tcl.rule.connect.allow_loopback_addresses' were created to toggle whether or not to allow loopback addresses for iRule node or connect commands.

Recommended Actions

Important: Before making this change, be aware that these steps can expose you to CVE-2022-33962.  If you need to take this action, it is also recommended to apply the mitigation in K80970653: BIG-IP iRules vulnerability CVE-2022-33962.

The actions or steps required to address the topic covered in the description.

  1. To disable this variable:
    tmsh modify sys db tmm.tcl.rule.node.allow_loopback_addresses value true
    tmsh save sys config

Note: if the error is happening due to 'connect' command, then change the sys db 'tmm.tcl.rule.connect.allow_loopback_addresses' or both if utilizing both commands.

Additional Information

  • Bug ID 1006921 (iRules Hardening)

  • Some customers have reported a problem with the ephemeral credentials function not working after the upgrade. This is because the iRule for ephemeral authentication is affected by this issue. Manual Chapter : About ephemeral authentication
  • This issue can cause some Telemetry Stream functions stopped to work after upgrade or do not work after configuration on an impacted BigIP release. E.g.  LTM Request Log. 
An irule as below  is attached to telemetry local listener/Virtual Server.
ltm rule telemetry_local_rule {
when CLIENT_ACCEPTED {
    node 127.0.0.1 6514
}
