Known Issue

The BIG-IP APM system may generate a MySQL error message repeatedly.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM systems are configured for high availability.
  • You have local user database instances configured on the BIG-IP APM systems.

Impact

None. You can safely ignore the error message.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H464136 on the Diagnostics > Identified > Low screen.
  • The system generates an error message to the /var/log/ltm file every five minutes that appears similar to the following example:

    err mcpd[5487]: 01071704:3: Not running command (/usr/libexec/localdb_mysql_restore.sh) because the request came from an untrusted connection.

Workaround

While there is no workaround, if the local user database instances are no longer in use, you can mitigate this issue by deleting the instances. To do so, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) of a BIG-IP APM system by typing the following command:

    tmsh

  2. Delete the local user database instance using the following syntax:

    delete apm aaa localdb <instance name>

    For example, the following command deletes the instance named localusers1:

    delete apm aaa localdb localusers1

  3. Repeat this procedure for any other local user database instances on this BIG-IP APM system.
  4. Delete any local user database instances on the other BIG-IP APM systems in the high availability configuration.
