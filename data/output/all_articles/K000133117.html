Description

How to recover the root password on RAID-capable BIG-IQ platforms.


Environment

BIG-IQ 8.x and later

No CLI access to the box

Unable to generate qkview


Cause

You forgot your root password to login to CLI/SSH


 Recommended Actions

You should consider using this procedure under the following conditions:


-You need to reset the password for an administrative account, such as the root account on BIG-IQ v8.x and later.

-You have a RAID-capable BIG-IQ platform.


NOTE: Please make sure to save a backup of your configuration before performing the steps below


1. Connect a terminal (putty with admin rights) to the BIG-IQ serial console port.


2. If you have access to the command line, determine which slot is installed with target version (for example, 8.x) by running the 'switchboot -l' or 'tmsh show sys software' commands.

Then run the 'tmidiag -m' command to show filesystem for '/config' and '/var'.

3. Restart the BIG-IP system.

While starting, the BIG-IP system displays the GRUB menu and counts down before continuing the start process.


4. Before the countdown expires, use the Up Arrow and Down Arrow to select the appropriate boot image.


5. Press e to edit the current entry.

A new GRUB menu screen displays.


6. Use the Up Arrow and Down Arrow to select the line that appears similar to the following example:


module /boot/2/vmlinuz ro root=UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxxx console=ttyS0 panic=1 platform=C117 quiet


7. Press the keyboard Ctrl-E to start editing at the end of the line.


8. Append rd.break to the end of the line.


Depending on the platform, the outcome may appear similar to the following example:


module /boot/2/vmlinuz ro root=UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxxx console=ttyS0 panic=1 platform=C117 quiet rd.break


9. Press the Ctrl-x keyboard sequence to boot to the modified config.


10. After the boot sequence completes, the following command-line prompt appears:


switch_root:\#

11. Next, mount the /sysroot/config and /sysroot/var partitions using the following command:


Depending on the platform, the mount command may appear similar to the following example in reference to Step 2:


switch_root:/# mount /dev/md125 /sysroot/config

switch_root:/# mount /dev/md126 /sysroot/var


12. For any partitions mounted as "ro" that means that they are in read-only mode, you have to re-mount them to read-write mode first.


For example, to re-mount the /sysroot and the /sysroot/usr partitions to Read-Write mode first, use the following commands:


mount -o remount,rw /sysroot

mount -o remount,rw /sysroot/usr


13. Change the root file system to /, type the following command:


chroot /sysroot


When you use chroot command, the command prompt will change to display as follows:


sh-4.2#


14. Change root password using the passwd command and you enter the new password twice.

Upon successful change on the password, you will see the output as follows :


Changing password for user root.

passwd.bin 2 : all authentication tokens updated successfully.


15. After keying in the new root password, force SELinux to relabel context on next boot, type the following:


touch /.autorelabel


16. Enter 'exit' twice to allow the system to boot as normal.


sh-4.2# exit

switch_root:/# exit
