Description

BIG-IP inserts :authority pseudo-header within client-side response when receiving a server response containing a Host header in the response.

Environment

Virtual server with a HTTP/2 profile applied with client-side context, which would translate HTTP/2 requests from client-side to HTTP/1.1 on server-side.

Cause

The observed behavior is due to a known bug ID1166261. This bug speaks to an issue where BIG-IP translates Host header from a server response to :authority pseudo-header in subsequent client-side HTTP/2 response.

Host header in a HTTP/1.1 response is not in violation of RFC; however, a HTTP/2 response with an ":authority" pseudo-header is in violation of RFC7540.

HTTP/2 response must only contain the :status pseudo-header in it's responses. HTTP/2 responses containing any other pseudo-headers, such as :authority, is considered malformed and the connections should get terminated.

Recommended Actions

Consider using an iRule to remove the Host header when it arrives from the server. The following iRule can be created and applied to the virtual server:

when HTTP_RESPONSE {
    HTTP::header remove Host
}
