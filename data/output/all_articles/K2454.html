Topic

The BIG-IP system relies on the content length header while parsing HTTP content. If the data is chunked, there is no content length header for the BIG-IP system to use. The http_unchunk_content internal variable forces the BIG-IP system to unchunk content to a temporary buffer. After the content is unchunked, the BIG-IP system can determine the content length. Then, the BIG-IP system may parse the HTTP content.

The BIG-IP system sends the original chunked content to the client.

Important: F5 Support advises that you do not change internal variables unless you are aware of, and accept, the risks outlined in K920: Overview of internal variables.

To set the http_unchunk_content internal variable, type the following command:

bigpipe internal set http_unchunk_content = 1

To unset the http_unchunk_content internal variable, type the following command:

bigpipe internal set http_unchunk_content = 0
