Description

You may run into an issue when upgrading to 17.5.x. That issue produces an error similar to...

There are other possible errors that also may be seen.

Environment

Upgrade to 17.5.x from any major or minor prior version.

Cause

A license reactivation is commonly not done when upgrading within a major version because it is not required. What is being seen is that upgrades to 17.5.x are failing. This is because an upgrade to a minor version also requires a license reactivation if the current license activation date (Service Check Date on the CLI) is older than the License Check Date of the version being upgraded too.

  1. The first number is the major release number
  2. The second number is the minor release number.
  3. The third number is the maintenance release.
  4. The fourth number (when used) is the point point release.

K7727: License activation may be required before a software upgrade for BIG-IP

This brings about some confusion due to simple habit. 17.1.x.x has a minor release (the second number) that is earlier the minor release number for 17.5.x which is 2025-02-12. This can also occur if at some time the license has been reactivated, but the date is still older than the "License Check Date" of 17.5.x.

Recommended Actions

To address this ensure that the License Activation date (Service Check Date on the CLI) is same or newer than the License Check Date of 17.5.x. If it is not reactivate the license PRIOR to doing the install of 17.5.x. The steps to check the date and to reactivate, if needed, are in the aforementioned KB K7727.

If the upgrade does fail and you suspect this may be the cause then to rectify it please follow these steps...

  1. Boot the system back to previous working boot partition. (DO NOT say yes to "Install Configuration" when falling back to a previous version!).
  2. Reactivate the license... K7727: License activation may be required before a software upgrade for BIG-IP
  3. Boot into 17.5.x selecting "Install Configuration" to 'yes'.
