K53344744: APM RSA auth may fail if next tokencode entered after 30 sec

Type
Support Solution
Published
2021-01-13
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.0
Source
https://my.f5.com/manage/s/article/K53344744

Description

RSA auth might fail if the next token code received through email is entered after 30 sec.

Environment

APM configured for RSA authentication
RSA OnDemand Auth is used - Next Token code sent through email

Cause

This is because the udp source port changes when the next token code is entered after 30 sec (due to udp timeout of 30sec) and the RSA authentication manager uses the source port as part of the session validation from the initial PIN/tokencode to the next token code. If the port changes, RSA auth fails.
 
Recommended Actions

Use a layered Virtual Server with a UDP profile with a timeout of 180 seconds as a workaround.
 

ltm virtual vs_layered_rsa {
    destination 192.168.2.10:5500          <========== rsa server address and port 5500
    ip-protocol udp
    mask 255.255.255.255
    profiles {
        udp_rsa { }                        <========== udp profile
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    translate-address disabled
    translate-port enabled
    vs-index 13
}

ltm profile udp udp_rsa {
    allow-no-payload disabled
    app-service none
    buffer-max-bytes 655350
    buffer-max-packets 0
    datagram-load-balancing disabled
    defaults-from udp
    idle-timeout 180                       <========== extended timeout
    ip-df-mode pmtu
    ip-tos-to-client 0
    ip-ttl-mode proxy
    link-qos-to-client 0
    proxy-mss disabled
    send-buffer-size 655350
}
