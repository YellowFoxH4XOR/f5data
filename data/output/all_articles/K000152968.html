Description

After upgrading MySQL pool members to version 8.4 or later, the BIG-IP MySQL health monitors fail.

Environment

  • BIG-IP LTM or DNS
  • MySQL health monitor
  • Pool members running MySQL 8.4 server or later

Cause

By default, MySQL 8.4 and later uses the caching_sha2_password authentication plugin. Previous versions used the mysql_native_password authentication plugin by default. Current BIG-IP MySQL health monitors are not compatible with the newer caching_sha2_password authentication plugin so they cannot authenticate to MySQL 8.4 pool members and it causes the health monitors to mark pool members down.

Recommended Actions

Choose one of the following workarounds:

Change configuration on MySQL pool members

Note: This procedure will not work on MySQL 9

  1. On the MySQL 8.4 pool members you can add the following in the [mysqld] section of your MySQL configuration file:
    mysql_native_password=ON
  2. Restart MySQL.
  3. If the user's password has been updated to use caching_sha2_password format during the upgrade, then you need to reset it back to mysql_native_password format.
    Enter the following command on the MySQL 8.4 pool member:
    ALTER USER '<dbuser>'@'<remote host>' IDENTIFIED WITH mysql_native_password BY '<Password>';
    Note: <remote host> could also be % if the user is allowed access from any host.

Use a TCP monitor

Use the LTM or DNS TCP monitor for the MySQL pool members. This will verify that the server is up and able to accept TCP connections; however, it does not verify if the MySQL server is able to handle database connections.
