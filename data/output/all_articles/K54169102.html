Description

Due to long I/O wait times during AVR data Aggregation the BIG-IP becomes offline.


Environment

  • LTM log message /var/log/ltm:

    HA proc_running bd fails action is go offline and down links.
     
  • Various daemons including mysqld in /var/log/kern.log invoked OOM-Killer
  • A few minutes before becoming offline, the I/O wait is high

Cause
  • OOM-Killer invoked due to memory exhaustion
  • Evidence of systemd-journald process leaking memory. This is tracked with Bug ID 887637 for more information refer to: K22040951: systemd-journald vulnerability CVE-2019-3815
  • AVR internal tables are much too large for the platform, an issue tracked with Bug ID 828937

Recommended Actions

To resolve the bug ID ID887637, the fix is in the version 14.1.2.4 for other versions, contact support for further information.

To resolve the bug ID ID828937, follow the recommended steps in K45725467: BIG-IP systems may experience long I/O wait times during AVR data aggregation.

The avr.stats.internal.maxentitiespertable is currently set to the default of 50000, where the recommend value for this setting per is 2148.
