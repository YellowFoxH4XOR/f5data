Topic

When using Dynamic Ratio, the BIG-IP will never set the weight of a node to a value less than 1. If the node weight is set to a value greater than 1, but you do not understand the reason for the value assignment, you can review the calculation using the following default Dynamic Ratio formula:
 
(Number of Nodes in Pool)^(Mem Coefficient
((Mem Threshold - Mem Utilization)/Mem
Threshold)) + (Number of Nodes in Pool)^
(CPU Coefficient((CPU Threshold - CPU Utilization)
/CPU Threshold)) + (Number of Nodes in Pool)^
(Disk Coefficient ((Disk Threshold - Disk Utilization)
/Disk Threshold))

The BIG-IP rounds the sum of the value to the nearest whole number when assigning the Dynamic Ratio weight for the node.

Because the snmp_dca monitor, which reads the values used by the Dynamic Ratio load balancing method, is associated with nodes rather than pools, it does not actually learn the number of nodes in a pool. As a result, unless specifically configured, the calculation will always use the default value of 10 for the Number of Nodes in Pool value.

For example:

NODE: 192.168.167.71, Agent type: UCD
Total Mem:     1160320 KB, Mem Coeff:  1.0, Mem Thresh:  70.0 %
Avail Mem:     15020 KB
CPU util:      1  %, CPU Coeff:  1.0, CPU Thresh:  80.0 %
Total disk:    1548096 KB, Disk Coeff: 1.0, Disk Thresh: 90.0 %
Avail disk:    1254864 KB, Disk Use: 15 %
Dynamic ratio: 12

The sampling returned by the snmp_dca monitor produces the following formula values:

10^(1((70-((15020/1160320)*100))/70)) + 10^(1((80-1)/80)) + 10^(1((90-15)/90)) =

The answers for each portion of the calculation include the following values:

9.55 + 9.77 + 6.76 =

The BIG-IP rounds the values to the nearest whole number.

For example:

10 + 10 + 7 =

As a result, the Dynamic Ratio weight value is 27 for this node.

If the BIG-IP frequently assigns a Dynamic Ratio weight value of 1 when the weight value should be higher, this behavior may occur due to one of the following three reasons:

  • The node is not returning SNMP data in the correct format. If the BIG-IP cannot interpret the data returned by the snmp_dca monitor, it will set the weight of the node to 1.
  • The threshold set for a polled item on the node is exceeded; therefore, the BIG-IP will set the weight of that node to 1.
  • A known issue caused the incorrect calculations. For more information, refer to K3767: Known Issue: The snmp_dca monitor does not work properly with very large coefficients.
