K12216: BIG-IP WebAccelerator allows MultiConnect to be selectively enabled for some content in a policy

Issue

In versions prior to 10.2.0 (and 10.1.0 with HF1 applied), the BIG-IP WebAccelerator does not allow the MultiConnect feature to be disabled for some content in a policy and enabled for other content. For example, when the feature is enabled and you configure an application host name with a non-zero number of HTTP (or HTTPS) subdomains, the system rewrites all <img> and <script> links. Conversely, when MultiConnect is disabled, the system does not rewrite any links on matching HTML pages.

Starting in BIG-IP WebAccelerator 10.2.0 (and version 10.1.0 with HF1 applied), you can configure the MultiConnect feature to be selectively enabled in content-specific policy nodes instead of just the HTML pages node. In these versions, the MultiConnect selective assembly option operates as follows:

HTML objects

For HTML objects, the MultiConnect feature still controls how the system rewrites links on the page. For example, when MultiConnect is disabled, the system does not rewrite links on a matching HTML page. When MultiConnect is enabled and an application hostname is configured for a non-zero number of HTTP (or HTTPS) subdomains, MultiConnect rewrites <img> and <script> links on the page.

Non-HTML objects

For non-HTML objects, MultiConnect determines whether links to the object are eligible to be re-written. For an object's link to receive a MultiConnect prefix, the object must have an entry in the BIG-IP WebAccelerator's Etag cache. The following conditions determine whether or not an object is promoted to the BIG-IP WebAccelerator's Etag cache:

  • The BIG-IP WebAccelerator system must process/compile the object so that the system can compute the Etag
  • The BIG-IP WebAccelerator system must be configured to cache the object

    Note: The BIG-IP WebAccelerator system is configured to cache the objects when the Always proxy requests setting is disabled in the policy.

  • The object must not be expired

    Note: Whether an object is expired depends on the policy settings under the Lifetime tab, such as Maximum Age.

The selective assembly option has the following limitations (similar to those observed with IBR pvtags):

  • The BIG-IP WebAccelerator system must process/compile an object before it can create the MultiConnect prefix for the object
  • An object that expires will lose its MultiConnect prefix until the BIG-IP WebAccelerator revalidates the content with the OWS

Enabling Selective Assembly

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Use a text editor to edit the /config/wa/pvsystem.conf file.
  3. Locate the following line in the file:

    <selectiveAssembly>false</selectiveAssembly>

  4. Change the line to the following:

    <selectiveAssembly>true</selectiveAssembly>

  5. Save the changes and exit the file.
Note: The Selective Assembly feature does not function correctly when content in RAM Cache expires after content in Smart Cache. For more information, refer to SOL12171: The selectiveAssembly feature does not function correctly when content in RAM Cache expires after content in Smart Cache.
