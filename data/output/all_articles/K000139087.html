K000139087: RESOLV::lookup Returns an Empty String with error "01220001:3: TCL error: /Common/irule-name <HTTP_REQUEST> - bad IP address format"

Type

Published
2024-04-05
Updated

Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source

Description

The RESOLV::lookup iRule command will fail to connect and return an empty string when targeting a virtual server in a different route domain than the virtual server that the iRule performing the lookup is attached to. This can lead to failures in later commands that rely on that output.

You may see below error message:

bigip_devicename.com err tmm3[4720]: 01220001:3: TCL error: /Common/irule-name <HTTP_REQUEST> - bad IP address format (line 73)TCL error (line 73) (line 73)   invoked from within "node $Node-name 443"

Environment

  • LTM
  • iRule
  • RESOLV::lookup
  • Route Domains

Cause

When using RESOLV::lookup to reference a virtual server name, the system does not append any route domain information, which can lead to DNS resolution failure and return an empty string.

Recommended Actions

Instead of referencing the virtual server by name, point the RESOLV::lookup command at the IP address of it, including the route domain tag.

For example, replace [RESOLV::lookup @/Common/dns_vs -a "www.example.com"] with [RESOLV::lookup @10.20.30.40%2 -a "www.example.com"]
