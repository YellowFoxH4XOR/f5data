Topic

When you license and configure the BIG-IP system to use various Domain Name System (DNS) features, it is beneficial to understand the order in which the system processes DNS queries.

Description

The BIG-IP system offers the following DNS-related features to answer DNS queries:

  • DNS iRules

    DNS iRules include events and commands that specifically work with DNS queries on BIG-IP DNS (12.x and later), BIG-IP GTM (11.x), and BIG-IP LTM (11.x and later) systems. DNS iRule events, such as DNS_REQUEST and DNS_RESPONSE, can modify DNS packet attributes, answer directly, or load balance requests. DNS iRule events and commands require a GTM or DNS Services license.

  • Wide IPs

    • A BIG-IP DNS (12.x and later) wide IP responds to DNS A, AAAA, CNAME, MX, NAPTR, and SRV record queries using load-balancing algorithms, topology-based routing, and iRules to distribute traffic in a manner that best suits the network or application. BIG-IP DNS wide IP functionality requires a BIG-IP DNS license.

    • A BIG-IP GTM (11.x) wide IP responds to DNS A and AAAA record queries using load-balancing algorithms, topology-based routing, and iRules to distribute traffic in a manner that best suits the network or application. BIG-IP GTM wide IP functionality requires a BIG-IP GTM license. DNS queries, received for a wide IP, that are not A or AAAA requests are processed by the GTM listener configuration.

  • DNS Express

    The DNS Express feature, available in 11.x and later, allows a BIG-IP system to act as an authoritative secondary DNS server by performing zone transfers and serving DNS records faster than the primary DNS servers and local BIND servers. The DNS Express feature requires a DNS Express license.

  • DNS profiles

    The DNS profile allows users to configure various DNS attributes that the virtual server applies to DNS traffic. For example, the DNS cache feature, which you can enable in the DNS profile in 11.2.0 and later, centralizes DNS responses by learning and caching the DNS queries as the system passes them on to external resources. The DNS cache can then answer subsequent DNS requests for the domain.

  • BIND

    BIND is the DNS software implementation included on BIG-IP systems.

To determine which DNS features your BIG-IP system is licensed for, you may perform one of the following procedures:

  • In the Configuration utility, navigate to System > License.
  • From the TMOS Shell (tmsh), type the following command:

    tmsh show sys license | more

The entries that are prefixed with the text DNS within the Active Modules sections correspond with the features for which you are licensed.

Note: You must provision modules before you can use the features within them. For more information about provisioning, refer to K12111: Provisioning licensed BIG-IP modules.

When you use some or all of the above DNS features together, it is helpful to understand the order in which the system processes DNS queries.

DNS request order of operation for BIG-IP systems

The BIG-IP system processes DNS requests as follows:

  1. The DNS virtual server or listener receives the query and performs a check on the DNS packet. The system then drops malformed or malicious packets.
  2. After the packet is accepted, the system inspects the DNS header. If the Recursion Desired (RD) flag is set in the request header and the Process Recursion Desired setting is enabled in the DNS profile, the system processes the packet as follows:
    • DNS iRules: Any DNS iRules that associate with the virtual server/listener respond to or modify the packet.
    • DNSSEC key processing: If the DNSSEC feature is licensed as an add-on, the system processes the DNSSEC key requests.
    • wide IPs: Queries that match a wide IP are processed according to the wide IP configuration.
    • DNS Express: If the DNS Express feature is licensed, the system answers authoritatively for other queries matching DNS Express zones.
    • DNS profiles: The Unhandled Query Actions setting in the DNS profile controls how the system handles packets that do not match a wide IP or DNS Express zone.

      Note: When DNS Cache is enabled in the DNS profile, the configured cache handles the packet before the configured Unhandled Query Action.

  3. If the RD flag is set in the request and Process Recursion Desired is disabled in the DNS profile, the request is immediately considered un-handled, and dispatched according to the Unhandled Query Action setting in the DNS profile.
  4. The DNS cache feature, if enabled in the DNS profile, processes remaining queries (for example, www.google.com) that do not match BIG-IP DNS, BIG-IP GTM, or DNS Express records. If a DNS Response Policy Zone (RPZ) is configured in the DNS Cache profile, the requests of malicious domains in the RPZ list are blocked with NXDOMAIN or forwarded to walled garden.

Recommendations

  • F5 recommends that you configure the Unhandled Query Actions setting in the DNS profile as follows:
    • Use the Allow setting (default) if you want to load balance the requests to another authoritative DNS server in the environment, or to local BIND on a GTM-licensed system (if local BIND is enabled using the DNS profile). You should also use the Allow setting if the GTM system sends DNS queries to a pool of DNS resolvers. This setting is also required when DNS cache feature is set to Transparent.
    • Use the Drop setting if the GTM-licensed system is configured as an external, authoritative DNS system. The Drop setting provides maximum protection and security for unmatched packets for systems processing external DNS queries.
    • Use the Reject setting to return a REFUSED status for the DNS query.
    • Use the Hint setting to return a list of the root name servers for the DNS query.
    • Use the No Error setting to return a NOERROR status for the DNS query.
  • F5 recommends that you disable BIND in the DNS profile when you use the DNS Express feature.
  • F5 recommends that you leave Recursion Desired enabled in the DNS profile when the system deploys as an internal DNS resolver. This setting enables the system to answer recursive DNS queries from internal clients.
  • You can view detailed statistics regarding types of requests and responses, and how they are handled, by using the following tmsh command:

    tmsh show ltm profile dns
