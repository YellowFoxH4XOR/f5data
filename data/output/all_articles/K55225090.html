Issue

Old Behavior

In versions prior to 14.1.0, BIG-IP Virtual Edition (VE) contains several custom F5 kernel modules. This includes the lasthop kernel module that provides the Auto Last Hop feature on the BIG-IP VE management interface. 

When enabled, the Auto Last Hop feature allows the BIG-IP system to send response traffic to the MAC address of the device that transmitted the incoming connection (the last hop device), even if the routing table points to a different network or interface. As a result, the BIG-IP system can send response traffic to clients even when there is no default route or other matching route configured. 

When the lasthop module is enabled, the BIG-IP management interface does not require a specific or default route back to the BIG-IP administrator's client machine as the BIG-IP system uses the last hop MAC address to send the response back to the initial client. The lasthop module is automatically loaded at boot time and enabled on the management interface by default.

New Behavior

Note: This behavior is specific to traffic arriving on the management interface 'eth0' (also known as 'mgmt' on some BIG-IP hardware platforms)  Management connectivity to Self IP addresses is not affected by this setting. For information, refer to K55951769: TCP SYN to self IP responded by mgmt interface for port 4353 but not 22

Beginning in BIG-IP VE 14.1.0, F5 Product Development removed the custom F5 kernel modules, including the lasthop kernel module; therefore, the system no longer supports the lasthop module for management interface connections, and the system does not use the Auto Last Hop feature to send response traffic to last hop devices.

The removal of the custom F5 kernel modules eliminates the reliance of BIG-IP VE on custom modules.

Impact

Response traffic on the management interface is no longer sent to the last hop MAC address. If you have not configured a management route on the BIG-IP system, you cannot access the BIG-IP management interface from a client located on a subnet that is not directly connected to the BIG-IP system.

Recommended Actions

For BIG-IP VE 14.1.0 and later, you must configure a default management route or other specific management routes for the BIG-IP system to communicate with devices on a remote network, such as a BIG-IP Administrator's client machine or a DNS server via the management interface. For information about configuring a management route on the BIG-IP system, refer to K15040: Configuring and displaying the management IP address for the BIG-IP system.

Additional Information

When the BIG-IP transmits a packet from the management IP address (for example, when replying to an incoming packet that arrived at the management IP), Linux IP routing rules direct it to use a routing table that includes sys management-routes only (no tmm routes are present).  As long as  management routes are present, this behaviour ensures that BIG-IP responds to managment traffic via the management interface, and not via a tmm interface.  For more information, refer to K13284: Overview of management interface routing (11.x - 17.x)
