Description

When setting pool member to disable, the new and existing connection still going to same pool member

Environment

  • BIG-IP LTM
  • Virtual server with persistence profile

Cause

This is an expected behavior.
If pool member is set to disable state, system continues to process persistent and active connections. It can accept new connections only if the connections belong to an existing persistence session.

Recommended Actions

Run below command to check persistence entries on virtual server 
tmsh show ltm persistence persist-records pool  < pool name >
 
and you can delete them by running 
tmsh delete ltm persistence persist-record pool  < pool name >

or

you can set pool member to forced offline

When set to Forced Offline, a node or pool member allows existing connections to time out, but no new connections are allowed.
