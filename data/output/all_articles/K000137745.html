Description

When logging out of SAML with the BIG-IP as the Service Provider, in some scenarios the Logout URI will not be accessible after the user is logged out, causing the user to land on a inaccessible page.

Environment

  • BIG-IP APM
  • SAML with the BIG-IP as SP SLO (Single Logout)
  • Logout include URI

Cause

The Logout URI is used to trigger SLO and remove the APM session. When the user is redirected back to the SP from the IdP, the user is redirected to the Logout URI.

If the user is not authenticated, the logout URI will not be accessible an result in a request to a URL that cannot be accessed.

Recommended Actions

Use the following iRule to redirect the user to hangup.php3 when they click on the logout URI.

When the user is redirected to hangup.php3 it will trigger SLO and redirect the user to the IdP to remove their session.

Then the user is redirect back to hangup.php3

Create and apply the following iRule:

Replace the﻿ "logout_uri" with the logout URI from the Access Policy

when HTTP_REQUEST {
  if { ([HTTP::uri] contains "logout_uri") } {
    HTTP::respond 302 noserver Location "/vdesk/hangup.php3"
  }
}
