Description

You are receiving threshold messages in /var/log/ltm for pool health and timeouts similar to the following:


Dec 4 03:12:16 ltm1.hostname.com err tmm1[19414]: 01cc0005:3: Peer (diameter.hostname.com from pool /Common/pool1 at 192.168.0.2:3868) health exceeds the major threshold


Dec 4 03:12:16 ltm1.hostname.com err tmm1[19414]: 01cc0004:3: Peer (diameter.hostname.com from pool /Common/pool1 at 192.168.0.2:3868) timeouts percentage 100 exceeds the major threshold 75 percentage


Dec 4 03:12:17 ltm1.hostname.com err tmm1[19414]: 01cc0005:3: Peer (diameter.hostname.com from pool /Common/pool1 at 192.168.0.2:3868) health is back under the major threshold


Environment

BIG-IP

Diameter


Cause

The thresholds are a configurable parameters on the profile level (Local Traffic ›› Profiles : Message Routing : Diameter ›› Session Profiles). There are two parameters:


- peer-errors-major-threshold


Specifies the peer errors major threshold. If the number of peer errors exceeds the provided limit, the SNMP trap is sent. The default is 75.


- peer-timeouts-major-threshold 75


Specifies the peer timeouts major threshold. If the number of peer timeouts exceeds the provided limit, the SNMP trap is sent. The default is 75.



The statistics are collected and been store in the profile_diametersession_stat table which can be accessed using the tmctl utility:


# tmctl profile_diametersession_stat -s name,vs_name,tot_retransmission_error_code,tot_answer_result_code_received_1xxx,tot_answer_result_code_received_2xxx,tot_answer_result_code_received_3xxx,tot_answer_result_code_received_4xxx,tot_answer_result_code_received_5xxx -w 500
