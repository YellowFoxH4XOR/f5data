K000153171: SSL/TLS termination fails on BIG-IP When Proxy Protocol v2 headers are present

Type
Support Solution
Published
2025-08-29
Updated
2025-08-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000153171

Description

When Proxy Protocol v2 is enabled on a device in front of BIG IP, the upstream device may forward requests with PROXY Protocol header in TCP data stream. BIG-IP LTM standard virtual servers with TLS termination do not natively support parsing the PROXY protocol, which can result in connection error and a FIN packet was sent from BIG-IP.

You may observer the below error in LTM logs.

warning tmm1[30539]: 01260009:4: <source_IP_address:source_port> -> <Virtual_server_IP_address:port: Connection error: ssl_passthru:5956: alert(40) not SSL

Environment

  • BIG-IP
  • Standard Virtual server
  • Client-SSL profile
  • Proxy Protocol

Cause

BIG-IP does not natively support or process Proxy Protocol v2 headers on virtual servers configured for SSL/TLS termination. The Client-SSL profile expects the first data after the TCP handshake to be a valid TLS ClientHello. The presence of Proxy Protocol v2 binary data in TCP data stream before the ClientHello causes the SSL handshake to fail, as the data stream does not match the expected TLS protocol format.

Recommended Actions

If SSL/TLS termination is required on BIG-IP, use an iRule to remove the Proxy Protocol v2 header from the TCP data stream before the Client-SSL profile processes the connection. The CLIENT_DATA event occurs before Client SSL profile inspects the payload, allowing you to extract and store data from the PROXY protocol header. After extraction, remove the PROXY protocol header from the data stream within CLIENT_DATA so that subsequent SSL processing receives only valid payload data.

Example iRule implementation and guidance are available at Proxy Protocol Receiver | DevCentral

Ensure thorough testing of any custom iRule to validate correct extraction and removal of headers without impacting application traffic.
