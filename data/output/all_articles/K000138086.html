K000138086: ASM 17.1.x.x - creation of new policy or saving a policy fails

Type
Support Solution
Published
2023-12-29
Updated

Applies to

Source

Description

You run into a problem when trying to save a policy. In the ASM are log entries similar to the following:

asm:Oct 25 21:31:48 00489694-bigip.local crit g_server_rpc_handler_async.pl[9288]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::handle_error): Failed add for policy [policy_name = '/Common/<name of policy>', policy_id = '']
asm:Oct 25 21:31:48 00489694-bigip.local crit g_server_rpc_handler_async.pl[9288]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): Could not add the Policy '/Common/<name of policy>'. InternalError - import_policy failed: DBD::mysql::db do failed: You have an error in your SQL syntax; check the manual that corresponds to your MariaDB server version for the right syntax to use near ')' at line 1
asm:Oct 25 21:31:48 00489694-bigip.local crit g_server_rpc_handler_async.pl[9288]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): Could not add the Policy '/Common/<name of policy>'. InternalError - import_policy failed: DBD::mysql::db do failed: You have an error in your SQL syntax; check the manual that corresponds to your MariaDB server version for the right syntax to use near ')' at line 1

Environment

  • ASM/AdvWAF
  • 17.1.x
  • ID1382365: XML policy import fails due to corrupted user-defined Signature Set definition

Cause

The policy creating failure is due to no content in PLC.VIOLATIONS_PROPERTIES table.

That content can be seen in the xml file by searching for <sig_tag_policy_val/>. This command should help:

cat <ASM_policy_name>.xml | egrep 'sig_tag_policy_val'

Example output:

         <sig_tag_policy_val/>
         <sig_tag_policy_val/>
         <sig_tag_policy_val/>

Recommended Actions

 The steps for recovery are below.

  1. take a note of current .im file versions
  2. take back up of user-defined signatures
  3. take a backup of policies (export them to xml)
  4. re-initialize asm database (https://my.f5.com/manage/s/article/K6992)
  5. update .im files to match the versions noted in step 1), if needed
  6. remove <sig_tag_policy_val/> from the exported xml policy files
  7. re-import the exported user-defined signatures from step 2)
  8. re-import the policies exported in step 3)
