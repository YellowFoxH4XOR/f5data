Description

  • You can see constantly re-starting zrd daemon on your BIG-IP DNS:

logger[5245]: Re-starting zrd
logger[5320]: Re-starting zrd
logger[5390]: Re-starting zrd
logger[5470]: Re-starting zrd

  • When reviewing recent /var/log/gtm logs, you can see following entries:

less /var/log/gtm | grep zrd

err zrd[31567]: 0115020b:3: Errors in config file zone example.company.com.test/IN: loading from master file db.external.example.company.com.test. failed: CNAME and other data. zone example.company.com.test/IN: not loaded due to errors.. external/example.company.com.test./IN: CNAME and other data.

Environment

  • BIG-IP DNS
  • ZoneRunner

Cause

This issue may occur if your configured zone file contain both CNAME and other type of DNS record configured on your BIG-IP DNS unit within zone file config. 
Error indicates that within your zone file you own a CNAME record together with a record of another type for the same entry. 

Recommended Actions

You need to remove one of the conflicting records in your affected zone file.
To resolve problem with constantly re-starting zrd daemon - you need to follow below article steps to allow manual modification to affected zone file:

K7032: Freezing zone files to allow manual update to ZoneRunner-managed zone files

 

Example steps to resolve issue for zone 'example.company.com.test':

  1. Log in to the BIG-IP DNS command line.
  2. Select the directory that contains the zone files by typing the following command:
    cd /var/named/config/namedb
  3. Stop the ZoneRunner utility by typing the following command:
    bigstart stop zrd
  4. Back up the zone file that you want to edit by using the following command syntax:
    cp example.company.com.test. example.company.com.test.original
  5. Freeze the zone you want to edit by using the following command syntax:
    rndc freeze example.company.com.test. in external
  6. Run the named-checkzone command to check the file for any syntax errors by using the following command syntax: (example output for this command is also included)
    named-checkzone example.company.com.test. db.external.example.company.com.test.
    dns_master_load: db.external.example.company.com.test.:13: department1.example.company.com.test: CNAME and other data
    zone example.company.com.test/IN: loading from master file db.external.example.company.com.test. failed: CNAME and other data
    zone example.company.com.test/IN: not loaded due to errors.
  7. Edit zone file which is causing zrd errors, you may use vim text editor to modify zone file.
    vi db.external.example.company.com.test.
  8. When zone file is modified and conflicting record is removed, you can use following command syntax to unfreeze the zone:
    rndc thaw example.company.com.test. in external
    Note: This command allows the changes to be reloaded and the zone to participate in dynamic updates.
  9. Restart the ZoneRunner utility by typing the following command:
    bigstart start zrd
  10. If your BIG-IP DNS system is in a sync group and you have the Synchronize DNS Zone Files option enabled, run the following command to synchronize the changes:
    touch /var/named/config/named.conf

Additional Information

If the problem remains after implementing recommended steps, please collect fresh Qkview file from your affected unit and open a Service Request by contacting F5 Networks Support.
