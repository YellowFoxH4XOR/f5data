Topic

Starting in BIG-IP version 4.5 PTF-04, you can create rules using the same arguments that you would use to test log values. Once the rule is configured, the returned strings will appear in the /var/log/bigip file every time the rule event is triggered.

Note: If you want to implement this functionality, you must be running BIG-IP version PTF-04 or later. For information about upgrading, refer to the BIG-IP Release Notes.

Sample rule:

rule log_me {
  if (http_uri matches_regex "bgz") {
     log "client " + client_addr + ":" + client_port 
     use pool web
  }
  else {
     log "client " + client_addr + ":" + client_port 
     use pool web
  }
}

The output string for this sample rule will appear in the /var/log/bigip file as follows:

May 2 11:39:33 bigip1 kernel: RULE log_me - client 192.168.21.48:1431

Logging rule syntax from prior versions of BIG-IP still functions the same in BIG-IP version 4.5 PTF-04 and later, as long as the total character length is less than 64 characters.

For example:

rule winmedia_rule {
   if (findstr(tcp_content, <0x63,0x6c,0x69,0x65,0x6e,0x74,0x2d,0x69,0x64>, 9, 200)) {
      log "client_addr,${client_addr} passed "
      use pool xpmedia_pool
   }      
   else { 
      log "client_addr ${client_addr} failed "
      use pool xpmedia_pool
   }      
}

The output string for this sample rule will appear in the /var/log/bigip file as follows:

May 20 09:27:20 bigip kernel: RULE winmedia9_rule - client_addr,192.168.14.31 passed

Notice that the rule name is also logged so you know which rule the client traversed.

Note: The value client_addr is a static string for reference and the ${client_addr} is the dynamic string referencing the client address. The quotation marks (") are required for readability.
