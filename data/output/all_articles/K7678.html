Known Issue

This is a result of a known issue. Manually moving pool members, editing the bigip.conf file, and reassigning pool members to different pools that are using the same monitor can cause the mcpd process to crash. This issue occurs when the change is loaded using the b load command.

When the mcpd process is restarted due to the configuration load, the BIG-IP LTM system incorrectly updates the reference count of the pool members and their associated pools for the system.

F5 Product Development tracked this issue as CR77997 and it was fixed in BIG-IP LTM 9.1.3. For information about upgrading, refer to the BIG-IP LTM Release Notes.
