K000163378: Configuring client-max-body-size for NGINX Ingress Controller VirtualServers with Traffic Splits

Type
Support Solution
Published
2026-09-22
Updated
2026-09-22
Applies to
  • NGINX Products
  • NGINX Ingress Controller
Source
https://my.f5.com/manage/s/article/K000163378

Description

The client-max-body-size ConfigMap setting may not apply to the initial location of a VirtualServer route that uses traffic splitting. Requests larger than the default 1 MB limit can fail with 413 Request Entity Too Large before being internally redirected to a split location.

Environment

  • NGINX Ingress Controller
  • Kubernetes VirtualServer resource
  • VirtualServer route configured with traffic splitting
  • ConfigMap parameter:

    client-max-body-size: 50m

  • Traffic-split route such as /coffee

Cause

NGINX evaluates the request body size in the initially matched location before executing the internal rewrite to the traffic-split location.

The generated configuration can contain the configured directive in the internal split locations but not in the initial route location:

location /coffee {
rewrite ^ $vs_cafe_jcafe_splits_0 last;
}

location /internal_location_splits_0_split_0 {
client_max_body_size 50m;
}

Because client_max_body_size is not explicitly configured in the initial location or at the server level, NGINX uses its default limit of 1 MB. A request with a 2 MB body is rejected before reaching the internal split location.

Relevant log messages include:

http cl:2097152 max:1048576

client intended to send too large body: 2097152 bytes

The response is:

413 Request Entity Too Large

Recommended Actions

Configure client_max_body_size at the VirtualServer server context by using server-snippets:

apiVersion: k8s.nginx.org/v1
kind: VirtualServer
metadata:
name: cafe
spec:
host: Web_1.example.com
server-snippets: |
client_max_body_size 50m;

Apply the updated VirtualServer configuration and verify that the generated NGINX configuration contains the directive at the server level:

client_max_body_size 50m;

Retest the request against the traffic-split route. Configuring the directive at the server level ensures that the limit is available when NGINX first matches the request, before the internal rewrite occurs.

Additional Information

Traffic-split internal locations redirect requests to fully configured locations. Duplicating all route directives in the internal redirect locations is unnecessary. Because the request body-size check occurs before the internal redirect, configure the required limit at the server context for traffic-split routes that need a limit greater than 1 MB.
