K000158006: Client Side Defense - Errors: CSD JS script is being flagged with a "High Risk" rating in the CSD console

Description

You want to enable and configure Client Side Defense on your WebApp and after configuring it using our official documentation you get "High Risk" alerts flagging the JS script that you injected on your WebApp. You want to know why is this happening

Environment

  • Client Side Defense
  • Big IP connector (Client Side Defense)

Answer

The script is being tagged as high risk due to the new network interactions being detected with the script. If you click on the "high risk" item, the field should expand and show reasoning/recommendation for the categorization as high risk. 

Basically, there are different behaviors depending on whether CSD is deployed if via XC or via BIG-IP connector.

  • Same application being protected by F5 XC LB with CSD does not show our own CSD script in the dashboard
  • Same application using BIG-IP connector with CSD always show our own CSD script in the dashboards.

For the BIG-IP Connector, the BIG-IP is routing the JS call as a first-party script whereas the F5 XC Load Balancer integration is just using the default domain (us.gimp.zeronaught.com). The CSD JS is aware of the default domain, but not all possible first-party redirect domains that customers deploying using BIG-IP may have, which is why the script is showing up in the dashboard for BIG-IP deployments

Additional Information

Client Side Defense JS script is classified as High Risk, especially for customers evaluating a Client-Side Defense solution they need to keep that in mind.
