Known Issue

The Traffic Management Shell (tmsh) may not display dynamic Address Resolution Protocol (ARP) entries as expected.

This issue occurs when the following conditions are met:

  • You have a BIG-IP system with more than one route domain configured.
  • You are viewing dynamic ARP entries using tmsh.

In BIG-IP 11.x, the show net arp Traffic Management Shell (tmsh) command displays dynamic ARP entries for all route domains. Additionally, you can display dynamic ARP entries for specific route domains by using the show arp any %<route domain id> command; however, you cannot specify the default route domain 0.

In BIG-IP 10.x, the show net arp Traffic Management Shell (tmsh) command displays ARP entries for only the default domain.

Impact

ARP entries are not displayed as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • ARP entries appear to be missing for route domains other than the default (BIG-IP 10.x).

    For example, using the following configuration, the output from the show arp command only displays dynamic ARP entries for the default route domain 0:

    # list net route-domain
    net route-domain 0 {
    description "Default Route Domain"
    vlans {
    2010
    }
    }
    net route-domain 11 {
    description 2011
    vlans {
    2011
    }
    }
    net route-domain 12 {
    description 2012
    vlans {
    2012
    }
    }
    # show net arp

    Net::Arp
    Address HWaddress Vlan Expire-in-sec Status
    --------------------------------------------------------------
    10.1.2.9 0:50:56:a0:10:9 2010 222 resolved

  • The system is unable to display only those dynamic ARP entries specific to the default route domain 0 (BIG-IP 11.x).

    For example, using the following configuration, the show net arp command displays dynamic ARP entries for all route domains, or for a specific route domain. However, the command cannot display only those dynamic ARP entries specific to the default route domain 0:

    # list net route-domain
    net route-domain 0 {
    description "Default Route Domain"
    id 0
    vlans {
    2010
    }
    }
    net route-domain 11 {
    description 2011
    id 11
    vlans {
    2011
    }
    }
    net route-domain 12 {
    description 2012
    id 12
    vlans {
    2012
    }
    }

    # show net arp

    -----------------------------------------------------------------------------------------------
    Net::Arp
    Name Address HWaddress Vlan Expire-in-sec Status
    -----------------------------------------------------------------------------------------------
    10.1.2.9 10.1.2.9 0:50:56:a0:10:9 /Common/2010 166 resolved

    10.12.23.122%12 10.12.23.122%12 0:50:56:a0:5f:56 /Common/2012 4 resolved

    Net::Arp

Workaround

BIG-IP 11.x

To work around this issue, you can display dynamic ARP entries specific to the default route domain 0 by using the following procedure:

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Type the following command to display dynamic ARP entries specific to the default route domain 0:

    show net arp | grep -v %

BIG-IP 10.x

To work around this issue, you can display dynamic ARP entries specific to route domains other than the default route domain by using the bigpipe utility. Because you can invoke the bigpipe utility from within tmsh, this workaround is effective for all users, regardless of their level of access to the BIG-IP system command line.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  • To display all dynamic ARP entries specific to a route domain other than the default route domain, use the following command syntax, from the BIG-IP command line:

    bigpipe arp any%<route domain id>

    For example, to display all dynamic ARP entries specific to route domain 10, type the following command:

    bigpipe arp any%10

  • To display all dynamic ARP entries specific to the default route domain 0, type the following command from the BIG-IP command line:

    bigpipe arp any%0

  • To display all dynamic ARP entries across all route domains, type the following command from the BIG-IP command line:

    bigpipe arp any%65535

  • If you only have access to tmsh, you can invoke the bigpipe utility from within tmsh by using the following command syntax:

    run util bigpipe <arguments>
