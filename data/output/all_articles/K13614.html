Topic

The BIG-IP APM system has the ability to inspect and take action on client-side machine certificates.

Description

A BIG-IP APM access policy can request and inspect a machine certificate installed on a client device running the BIG-IP Edge Client.

Note: The Machine Certificate Authentication is currently supported on Windows and Macintosh clients. It is not supported on Linux and clients such as the Dell Wyse Thin Client.

The BIG-IP APM system requests a certificate from the client device, applies rules based on certificate information, and performs actions based on the results of those rules. The BIG-IP APM system inspects these certificates during processing of the access policy to validate whether it allows the device access to the system.

Machine certificates

Machine certificates are X.509 certificates that are associated to an individual computing device as opposed to an individual user. The certificate subject attribute typically contains the Fully Qualified Domain Name (FQDN) of the device.

For more information about X.509 Public Key Infrastructure (PKI), refer to Internet Engineering Task Force (RFC 5280).

Access policy Machine Cert Auth action

The Machine Cert Auth action is an access policy component that is configured to retrieve and analyze certificate information from a device connecting to the BIG-IP APM system. The configurable fields of the Machine Cert Auth action are as follows:

  • Certificate store name

    The certificate store name on the client device that the access policy uses to locate the certificate. The default is MY and is the default windows store where certificates are imported on client devices. You can change this setting to inspect certificates located in custom stores.

  • Certificate store location

    This field specifies the certificate store location to look in for certificates. Options include LocalMachine or CurrentUser.

  • CA profile

    This option specifies the Certificate Authority (CA) profile to use. Ensure that the issuing certificate authority of the certificates being checked is imported to the BIG-IP system and associated with the CA profile you are using.

    Note: When importing Secure Sockets Layer (SSL) certificates the certificate must be in the BIG-IP PEM format to successfully import. BIG-IP APM CA profiles are defined through the Configuration utility Local Traffic > Profiles > SSL > Certificate Authority.

  • OCSP responder

    This option allows you to define an Online Certificate Status Protocol (OCSP) profile if you have OCSP defined in your environment. You can define OCSP profiles on BIG-IP on the Local Traffic > Profiles > Authentication > OCSP Responders page.

  • Save Certificate in a session variable

    Enabling this feature will place the data of the entire encrypted text of the machine certificate in a session variable (session.check_machinecert.<name>.cert.cert) where <name> is a dynamically created name based off of the access policy name that is configured to save the machine certificate.

  • Allow User Account Control right elevation prompts

    Setting this option to Yes allows the User Account Control (UAC) prompt for users with administrative-level privileges. When this setting is set to No the UAC prompt is suppressed for non-administrative users, which can cause a failure to verify the machine certificate. This setting does not affect users who do not have administrative level privileges.

  • Match issuer

    BIG-IP APM 11.5.0 and later specifies a regular expression to use to match the issuer content against the specified pattern.

    An example regular expression extraction:

    Partial match: CN=.*, OU=FP, O=F5, L=San Jose, S=CA, C=US
    Exact match: E=test@f5.com, CN=f5clientrootcert, OU=es, O=f5, L=london, S=chertsey, C=uk

    Note: The order of RDN is the same as the displayed value on Windows (GUI or CLI certutil); the required separator is a comma.

    For example:

    Entering the following text 'CN=.*, O=f5, L=london, S=chertsey, C=uk' (do not include the quotes) matches any certificate that the issuer contains O=f5, L=london, S=chertsey, C=uk

    Important: The Issuer information should be specified to ensure the correct Certificate is found during the Machine Cert Auth check.

  • Match serial number

    BIG-IP APM 11.5.0 and later specifies a serial number that must be an exact match for the certificate serial. The hex string must be specified in the same order as it is displayed by OpenSSL and Windows certificate tools.

    For example:

    Note: Do not include a colon character (:) or space in the entry.

    33AA7B82000100000033

  • Certificate match rule

    BIG-IP APM prior to 11.5.0

    Note: Starting with the release of BIG-IP APM 11.5.0, the Certificate match rule was replaced by Match Issuer and Match Serial Number.

    This option specifies the criteria to use to validate a machine certificate. The certificate being evaluated is matched on one of the following criteria:

    • SubjectCN Match FQDN: Specifies that the common name (CN) in the certificate subject attribute matches the computer's FQDN.

      For example:

      CN = mycomputer.siterequest.com

    • SubjectAltName Match FQDN: Specifies that the content extracted from the Subject Alternative Name attribute, using a specified regular expression, must match the computer's FQDN.

      A regular expression is used to extract content from the first subgroup matched in the Subject Alternative Name attribute, and then to compare the extracted content with the machine's FQDN. The order of Relative Distinguished Names (RDN) is the same as the displayed value; the required separator is a comma (,). Two of the most common RDN attributes for Subject Alternative Name are DNS Name and Other Name:Principal Name.

      An example regular expression statement for each common RDN:DNS Name example:

      Entering the following text '.*DNS Name=([^,]+).*' (do not include the quotes) into the Subject Alternative Name text box will extract the value after DNS Name= up to the next comma. For example, if the Subject Alternative Name is DNS Name=mycomputer.siterequest.com, O=siterequest.com, then mycomputer.siterequest.com will be returned.

      Note: The regular expression uses an equals sign (=) character instead of a colon (:) character even though Subject Alternative Name is printed as DNS:mycomputer.siterequest.com when the certificate is parsed using OpenSSL. This is because, after BIG-IP APM extracts the value from the certificate, it internally stores the value as DNS Name=mycomputer.siterequest.com.

      Other Name example

      Entering the following text '.*Other Name:Principal Name=([^,]+).*'. (do not include the quotes) into the Subject Alternative Name text box will extract the value after Other Name:Principal Name= up to the next comma. For example, if the Subject Alternative Name is Other Name:Principal Name=e=mycomputer.siterequest.com, O=siterequest.com, then mycomputer.siterequest.com is returned.

    • Any: specifies that the first certificate in the specified certificate store is sent to BIG-IP APM for further validation. Other certificates are ignored.
    • Issuer: specifies that the content from the Issuer field matches the pattern specified by the regular expression.

      A regular expression is used to match the issuer's content against a specified pattern.

      Note: The order of RDN is the same as the displayed value on Windows (GUI or CLI certutil); the required separator is a comma.

      For example:

      Entering the following text 'CN=.*, O=siterequest, L=Seattle, S=CA, C=US' (do not include the quotes) matches any certificate that the issuer contains O=siterequest, L=Seattle, S=CA, C=US

    • Issuer and serial number specifies that the content from the Issuer box matches the pattern specified by the regular expression (see previous explanation for Issuer), and the certificate serial number exactly matches the value defined in the Serial Number box. The serial number must be specified as a hex string exactly as it is stored in the certificate.

      For example:

      2291f9d2000000000d7b

Evaluation of the certificate, the Machine Cert Auth action returns one of the following results:

  • Successful

    A certificate was retrieved that matches the criteria and contains a private key.

  • Found

    A certificate was retrieved that matches the criteria, but a private key was not found for the certificate.

  • Fallback

    Either the certificate did not match the criteria, or another error occurred.

Recommendations

When configuring the Machine Cert Auth action, you should consider the following factors:

  • Which criteria you want to use to determine the validity of a certificate.
  • Which actions you take if you find a certificate but no private key.
  • Where in the access policy you want to check for a valid machine certificate.
  • When you encounter an issue, first identify if it is failing due to an invalid machine certificate or a missing private key. For more information, refer to K12354: Understanding Machine Cert and private key checks of the Machine Cert Auth action
