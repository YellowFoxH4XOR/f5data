K000149243: Troubleshooting unclear F5 VELOS chassis controller /partition-level backup configuration restore failures

Type
Support Solution
Published
2025-01-10
Updated
2025-01-10
Source
https://my.f5.com/manage/s/article/K000149243

Description

During a chassis controller or partition-level backup configuration restore, a vague error message, similar to the one below, may be reported without any further details: 

“Error: Database config-restore failed”

Environment

F5OS-C (VELOS)

Cause

A platform build discrepancy exists between the system where the backup was originally created and the system where the backup is being restored. 

Note: Before restoring a backup, it is essential to ensure that the source and target platforms are identical in setup.

Recommended Actions

To gather detailed information on the cause of the restore failure, you must first enable ConfD debug logging. Then, reproduce the restore failure and review the relevant chassis controller or partition-level devel.log file to identify the specific platform conflict error that needs to be resolved. This procedure may need to be repeated multiple times until all platform conflict errors are resolved.

For further details, refer to: K000092683: [F5OS] Enabling debug logs from the F5OS for the ConfD process

After identifying the platform conflicting object(s) causing the restore failure, one of the following actions is required to ensure a successful restore:

  1. Edit the backup file by opening it in a text editor, removing the problematic section(s), and any references to those sections..
  2. Adjust the platforms current setup to resolve the hardware difference(s) preventing the backup file from being restored.

Additional Information

Identifying the platform conflict entry in the devel.log file can be challenging. A configuration load failure frequently generates numerous "rejected data access path" errors. Typically, the last "Database config-restore failed." error before the final failure message is the one most relevant to the issue.

Here's an example of a devel.log entry that explains the cause of a partition restore failure. In this case, the partition backup file was created on a platform containing a Blade 6. When the same backup was restored on a different platform that did not have Blade 6, it led to the restore failure.
