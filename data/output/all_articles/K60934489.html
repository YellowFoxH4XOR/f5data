Known Issue

A configuration synchronization (ConfigSync) operation fails after you create and delete a file object.

This issue occurs when all of the following conditions are met:

  • Your configure your BIG-IP system for high availability (HA) and enable manual sync.
  • You create then immediately delete a file object on your BIG-IP system, such as a Secure Sockets Layer (SSL) key.
  • You perform a manual sync operation from the active system to a standby system.

Impact

The ConfigSync operation fails to sync the configuration and logs errors to the /var/log/ltm files on the active and standby systems.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The ConfigSync operation fails to sync the configuration.
  • The system logs error messages in the /var/log/ltm file on the active system that appear similar to the following example:

    err mcpd[PID]: 0107134a:3: File object by name (/Common/test.key) is missing.

  • The system logs error messages in the /var/log/ltm file on the standby system that appear similar to the following example:

    err mcpd[PID]: 01070712:3: Caught configuration exception (0), Failed to sync files..
    err mcpd[PID]: 01071488:3: Remote transaction for device group /Common/test to commit id 42 6079477704784246664 /Common/test failed with error 01070712:3: Caught configuration exception (0), Failed to sync files...

Workaround

To work around the issue, you can perform one of the following procedures:

  • Performing a ConfigSync prior to file object deletion
  • Forcing a device to initiate a one-time ConfigSync operation

Performing a ConfigSync prior to file object deletion

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

  • To prevent this issue, perform a ConfigSync operation before you delete the file object.

Forcing a device to initiate a one-time ConfigSync operation

To recover from the issue, you can use either the TMOS Shell (tmsh) or the Configuration utility to force a ConfigSync operation push from the device you deleted the file object on to the device group. To do so, perform one of the following procedures:

Using tmsh with BIG-IP 12.1.0 or later

Impact of procedure: The force-full-load-push command option forces the device to initiate a one-time ConfigSync operation to the device group. You can overwrite the configuration on target devices with newer configurations. The command is not persistent and you must run it again upon every attempt to initiate the ConfigSync process from a device with an older configuration.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To set the device from which you deleted the file object as the synchronization leader of the device group and force the device to initiate the ConfigSync process, use the following command syntax:

    run cm config-sync force-full-load-push to-group <group name>

    For example, to force a full-load ConfigSync operation from the current device to the MyDeviceGroup device group, type the following command:

    run cm config-sync force-full-load-push to-group MyDeviceGroup

Using tmsh with BIG-IP 11.x - 12.0.0

Impact of procedure: The force-full-load-push command option forces the device to initiate a one-time ConfigSync operation to the device group. You can overwrite the configuration on target devices with newer configurations. The command is not persistent and you must run it again upon every attempt to initiate the ConfigSync process from a device with an older configuration.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To set the device from which you deleted the file object as the synchronization leader of the device group and force the device to initiate the ConfigSync process, use the following command syntax:

    modify cm device-group <dg name> devices modify { <device name> { set-sync-leader } }

    For example, to set the device, MyDevice, as the synchronization leader of the device group, MyDeviceGroup, and force the device to initiate the ConfigSync process, type the following command:

    modify cm device-group MyDeviceGroup devices modify { MyDevice { set-sync-leader } }

Using the Configuration utility with BIG-IP 11.x - 12.x

Note: It is not possible to perform the workaround using the Configuration utility in BIG-IP 13.0.0 and later.

Impact of procedure: The Overwrite Configuration option forces the device to initiate a one-time ConfigSync operation. You may overwrite the configuration on target devices with newer configurations. The option is not persistent and you must enable it upon every attempt to initiate the ConfigSync process from a device with an older configuration.

  1. Log in to the Configuration utility on the first BIG-IP system.
  2. Navigate to Device Management > Overview.
  3. Under Device Groups, click the name of the device group you want to synchronize.
  4. Under Devices, click the device on which you created and deleted the file object.
  5. Under Sync Options, click Sync Device to Group.
  6. Select the Overwrite Configuration check box.
  7. Click Sync.
