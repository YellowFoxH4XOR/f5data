Known Issue

ZebOS daemons may stop responding while the AgentX SNMP daemon waits for a return from an external script.

This issue occurs when all of the following conditions are met:

  • You enable dynamic routing.
  • You enable SNMP.
  • The snmpd process becomes unresponsive. For example, this can occur when SNMP calls an external script that takes several seconds to return or when the mcpd process is slow to respond to queries.

Impact

The BIG-IP system may temporarily stop dynamic traffic routing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ltm file, you observe messages similar to the following examples:

    warning sflow_agent[PID]: AgentX master agent failed to respond to ping. Attempting to re-register
    warning sflow_agent[PID]: Warning: Failed to connect to the agentx master agent ([NIL]):

  • The system loses dynamic routes.
  • The snmpd process produces a core file.

Workaround

If the AgentX SNMP process is calling external scripts that take too long to return, you can work around this issue by configuring the AgentX daemon so that it no longer calls the external scripts.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
