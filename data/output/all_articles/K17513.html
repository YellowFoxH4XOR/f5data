Known Issue

The BIG-IP system configuration may fail to load after you modify a parent Secure Sockets Layer (SSL) profile that has a child SSL profile configured to use only GCM-based ciphers.

This issue occurs when all of the following conditions are met:

  • You have created a custom child SSL profile.
  • The custom SSL profile's Cipher option is configured with only Galois Counter Mode (GCM)-based ciphers.
  • You have modified the parent profile listed in the Parent Profile option of the child SSL profile.
  • You have upgraded or installed a user configuration set (UCS) from an earlier software version.

Impact

The BIG-IP system configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system configuration fails to load after you upgrade or install a UCS from an earlier version.
  • You observe error messages similar to the following example on the command line when you load the configuration, or observe the error messages in the /var/log/ltm file after you upgrade.

    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all" - failed. -- 01070312:3: Invalid keyword 'ADH-AES256-GCM-SHA384' in ciphers list for profile /Common/example-client-ssl Unexpected Error: Loading configuration process failed.

Workaround

There is no workaround. F5 recommends that you avoid modifying parent SSL profiles when child profiles are configured to use only GCM-based ciphers.
