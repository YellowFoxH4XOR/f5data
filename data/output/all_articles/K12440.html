Topic

When auto lasthop is enabled, the BIG-IP system records the MAC address from which the frame was forwarded (the last hop) and uses the same MAC address to forward response traffic instead of referring to the routing table. When the Hot Standby Router Protocol (HSRP) is enabled on a neighboring device, and auto lasthop is enabled on the BIG-IP system, return traffic does not route correctly after an HSRP failover.

Note: For more information about this behavior, refer to K9487: BIG-IP support for neighboring VRRP/HSRP routers.

However, if both Virtual PortChannels (vPCs) and HSRP are enabled on a neighboring device, the neighboring device may discard return traffic even if no failover has occurred. Cisco developed vPC technology, which allows devices physically connected to two different devices to appear as a single PortChannel to a third device.

When a neighboring device uses both vPC and HSRP, the BIG-IP system may receive frames from multiple MAC addresses even if no failover has occurred. If auto lasthop is enabled, the BIG-IP system uses the MAC address recorded from the initial frame as the lasthop MAC address for all subsequent frames for that connection. If a vPC device receives a frame from the BIG-IP system, but the frame contains the MAC address of a vPC peer, the vPC device discards the frame by default. To configure a vPC device to accept frames that are destined for a peer device’s MAC address, use the following command:

peer-gateway

Note: For more information about the peer-gateway command, refer to Cisco documentation.
