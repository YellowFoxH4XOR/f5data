Topic

The Proxy SSL feature allows the BIG-IP system to optimize SSL-secured communications that are directly authenticated by the server.

Description

The Proxy SSL feature enables the BIG-IP system to optimize SSL traffic between the client and the destination server, without terminating the SSL connection on the BIG-IP system. This feature is useful when you want all of the following:

  • The BIG-IP system to process encrypted application traffic.
  • The server to retain final authority to directly authenticate and grant access to the client.
  • To use the following BIG-IP system functions:
    • The iRules read or write application data.
    • The BIG-IP ASM security policy inspects and protects web application traffic.
    • The BIG-IP AAM system optimizes application traffic.
    • The system passes client certificates to servers that require mutual authentication.

Note: Proxy SSL may not support certain Transport Layer Security (TLS) extensions. For more information, refer to the following articles:

  • K15827: Session resumption using TLS session tickets fails when Proxy SSL is enabled
  • K34019109: SSL handshakes using TLS extended master secret extensions fail when Proxy SSL is enabled

SSL certificate and key management

The SSL connection does not terminate on the BIG-IP system. You allow the BIG-IP system to decrypt, optimize, and reencrypt the SSL traffic without compromising the security of the SSL connection by doing the following:

  • Importing the certificate and key pair that the destination server uses to the BIG-IP system.
  • Associating the certificate and key pair with the Server SSL profile configured for the BIG-IP virtual server used in the Proxy SSL connection.

When there is a certificate mismatch during the SSL handshake, the BIG-IP system resets the connection, as expected, and logs an error message. For more information, refer to K13393: Error Message: 01260015:3: Certificate supplied by server was not configured on virtual: <virtual server name>.

SSL sequence of events

When using the Proxy SSL feature on a single BIG-IP system, the following sequence of events occurs:

  1. The client establishes a full TCP connection to the BIG-IP virtual server.
  2. The BIG-IP virtual server establishes a full TCP connection to the destination server.
  3. The client and destination server exchange SSL handshake messages.
  4. When the destination server sends its certificate in the SSL ServerHello packet, if the certificate matches the certificate that is configured in the Server SSL profile, the BIG-IP virtual server forwards the SSL ServerHello packet.
  5. While the SSL handshake messages are being exchanged, the BIG-IP virtual server examines the SSL messaging data.
  6. The destination server authenticates and verifies the client and grants access to the client.
  7. When the SSL handshake completes, the BIG-IP virtual server has sufficient information to generate the appropriate tokens to decrypt the traffic.
  8. When the client starts sending traffic through the SSL connection established with the destination server, the BIG-IP system optimizes the traffic using the same SSL credentials that the client negotiated during the SSL handshake phase.

SSL cipher negotiation

The BIG-IP Server SSL profile must support the cipher suite negotiated between the client and destination server. If the negotiated cipher is not supported by the Server SSL profile, the negotiation fails and the BIG-IP system resets the connection. For more information, refer to K14571: Connections to a Proxy SSL-enabled virtual server may fail and K14622: SSL renegotiation may stall when the Proxy SSL feature is enabled.

Introduced in BIG-IP 11.6.0, the Proxy SSL Passthrough feature allows the BIG-IP system to pass traffic through to the server when the Server SSL profile does not support the cipher suite negotiated between the client and the server. This option is disabled by default. To use this option, you must enable it on both corresponding Client and Server SSL profiles. Use caution when enabling this feature as traffic sent directly to the server is not decrypted and/or inspected by the BIG-IP system.

Proxy SSL supports only the RSA key exchange. For proper functioning, the client and server must not negotiate key exchanges or cipher suites that Proxy SSL does not support, such as the Diffie-Hellman (DH) and Ephemeral Diffie-Hellman (DHE) key exchanges, and the Elliptic Curve Cryptography (ECC) cipher suite. To avoid this issue, you can either configure the client so that the ClientHello packet does not include DH, DHE, or ECC; or configure the server to not accept DH, DHE, or ECC. Proxy SSL supports only the NULL compression method.

Important: Both the BIG-IP Client SSL and Server SSL profiles associated with the Proxy SSL virtual server must have the proxy option enabled.

Recommendations

When configuring Proxy SSL, you must consider the following requirements:

  • The BIG-IP system makes load balancing decisions strictly during the TCP three-way handshake phase and does not support load balancing decisions at the application level. When policies or iRules make load balancing decisions based on application data, the BIG-IP system resets the connection.

    For example, if HTTP host header matches www.example.com, using a pool web_pool_example, the BIG-IP system resets the connection with TCP reset (RST) reason: Address in use.

  • Configure only the Certificate, Key, and Cipher options for the BIG-IP SSL profiles that are associated with the Proxy SSL virtual server. Because the BIG-IP system uses only these three options, the remaining options have no effect on Proxy SSL connections. Beginning in BIG-IP 12.1.0, these configuration options are disabled when the Proxy SSL feature is enabled. 
  • A Source address affinity persistence (source_addr persistence) record offers the best behavior and the greatest compatibility when deploying the Proxy SSL feature in a load balanced environment that requires persistence.
  • Configure the tmm.proxyssl.cachesize database variable as appropriate, taking the memory requirements on the system for your environment into account. For more information on how to do this, refer to K46924542: High memory aggressive mode sweeper triggered for Proxy SSL virtual server.
