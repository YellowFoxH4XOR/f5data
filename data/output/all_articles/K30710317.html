Known Issue

The BIG-IP APM system may double free memory and cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a virtual server that uses an APM access policy.
  • A BIG-IP APM access session fails to initialize.

Under rare conditions, when a BIG-IP APM access session initialization fails, the system may attempt to double free a memory location, which results in the system sending an SIGSEGV to TMM.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily fail to process traffic as it recovers from the TMM restart.
  • If configured for HA, the affected BIG-IP device fails over to a configured peer device.
  • The BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp that correlates with the traffic interruption.
  • The BIG-IP APM system logs error messages similar to the following example:

    notice hudfilter_init: filter 'ACCESS' init failed.
    notice Scheduling priority: normal. Nice level: -19.
    notice ** SIGSEGV **
