K000163311: Troubleshooting slow DNS responses in Wireshark

Type
Support Solution
Published
2026-10-29
Updated
2026-10-29
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000163311

Description

DNS monitoring reports response times exceeding one second, while packet captures show sub-millisecond BIG-IP processing and DNS transactions completing within a few milliseconds. Multi-second packet gaps occur between separate DNS queries rather than within a single request-and-response transaction.

Environment

  • DNS traffic between clients, BIG-IP, and DNS servers
  • Wireshark used for packet analysis

Cause

The packet captures did not establish that BIG-IP introduced the reported DNS latency. The source of the monitoring system's reported delay remains undetermined.

Resolution

Use the Wireshark dns.time field to measure the duration of an individual DNS transaction.
Correlate each DNS query with its matching response using the DNS transaction ID.

Do not use the interval between unrelated packets or subsequent client queries as DNS response latency.

Recommended Actions

  1. Verify that the monitoring system measures the same DNS query and matching response.
  2. Review the monitoring tool's latency calculation and identify the packet events used as measurement boundaries.
  3. If the issue persists, collect synchronized packet captures at the monitoring client, BIG-IP virtual server, and DNS server.
  4. Collect a BIG-IP QKView while the issue is occurring for additional platform and configuration analysis.
