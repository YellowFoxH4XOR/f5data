Known Issue

This is the result of a known issue. The HTTPS monitor can erroneously mark a node UP when the server completes the SSL handshake and accepts the monitor request, but fails to send the expected response until after the configured time out period has elapsed.

Note: An HTTPS monitor may also incorrectly marks a node as UP when no data was sent. For more information, refer to K10904: An HTTPS monitor incorrectly marks a node as UP when no data was sent in the server response.

F5 Product Development tracked this issue as CR120158 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.8-385.0-HF2 which was issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
