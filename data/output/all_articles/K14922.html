Topic

You should consider using this procedure under the following condition:

  • You want to change the DNS cache TTL statement for the BIG-IP DNS (formerly GTM) system.

Description

When you configure the BIG-IP DNS system to perform recursive DNS queries, the system stores responses to the recursive queries in memory so that it can respond more quickly to new queries for the same name. The system periodically deletes records from the cache to keep the cache content current.

The system uses the value of the Time to Live (TTL) field in the DNS record, and th max-cache-ttl statement in the BIND configuration file, to determine the timeframe that the records remain in the cache. The max-cache-ttl statement sets the maximum time that records can remain in the DNS cache. The BIG-IP DNS system deletes records from the cache when the max-cache-ttl statement expires for a record, even when the TTL value in the DNS record is greater than the max-cache-ttl statement.

In certain cases, you might want to change the DNS cache TTL statement for the BIG-IP system. For example, setting the max-cache-ttl or max-ncache-ttl statements to a lower value can have one or more of the following benefits:

  • It mitigates DNS cache abuse (for example, ghost domains).
  • It reduces "bad" records caching (for example, poor hostname migration planning may require you to flush the bad records from the DNS cache).

The system supports the following max-cache-ttl statements:

  • The max-cache-ttl statement sets the maximum time (in seconds) for which a DNS server caches positive answers. The default is one week (7 days). You can use this statement in a view or a global options clause.
  • The max-ncache-ttl statement sets the maximum time (in seconds) for which the server caches negative (NXDOMAIN) answers (positive answers are defined by max-cache-ttl). The default max-ncache-ttl statement is 10800 seconds (3 hours). The max-ncache-ttl statement cannot exceed 7 days. If you set the value greater than 7 days, the statement will be silently truncated to 7 days. You can use this statement in a view or a global options clause.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have access to the Configuration utility.

Procedures

Changing the max-cache-ttl statement on the BIG-IP DNS system

To change the max-cache-ttl statement on the BIG-IP DNS system, perform the following procedure:

Impact of procedure: Use caution when configuring a TTL value. Cached DNS responses expire according to the new value setting. If you use an extremely low value setting, the BIG-IP DNS system may generate more traffic depending on the network size and the number of users.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > Zones > ZoneRunner > named Configuration.

    Note: In BIG-IP 11.4.1 and earlier, navigate to Global Traffic > ZoneRunner > Named Configuration.

  3. Add the following statement to the options section of the BIND configuration file:

    max-cache-ttl <seconds>;

    For example, to change the max-cache-ttl statement to 100 seconds, type the following command:

    max-cache-ttl 100;

  4. Click Update.
