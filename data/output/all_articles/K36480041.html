Topic

This article discusses the runtime state change that occurs when a redundant BIG-IP LTM high availability (HA) system configured with Protocol Independent Multicast-Sparse Mode (PIM-SM) experiences a failover event.

Description

The BIG-IP system uses PIM-SM to populate the multicast routing table in Traffic Management Microkernel (TMM) for data-plane traffic. When the PIM-SM routing protocol is first enabled (or disabled and re-enabled), traffic is not forwarded until the protocol is converged and the multicast routes (mroutes) corresponding to the traffic are learned and installed. In a multicast network, traffic forwarding requires both the unicast and the multicast routing protocols to converge. When a BIG-IP system in an HA configuration is running PIM and a failover event occurs, the re-convergence process requires time.

Beginning in BIG-IP 15.1.0, support for fast failover of PIM-SM multicast traffic in a BIG-IP HA pair is introduced. The implementation uses Border Gateway Protocol (BGP) to learn the network routes for unicast traffic and the PIM-SM protocol to calculate the path for multicast traffic. This feature is an HA multicast enhancement that improves the convergence of mroutes after a failover event and is achieved with the following elements:

Note: In BIG-IP 15.1.0, the supported unicast routing protocol is BGP. In addition, PIM-DM is not supported.

  • BGP with PIM-SM: The deployment uses BGP to learn the network routes for unicast traffic and the PIM-SM protocol to calculate the path for multicast traffic. The knowledge of PIM mroutes is on the active BIG-IP system only.
  • Floating IP address: The BIG-IP HA pair must use the floating IP address on both the ingress and egress VLANs. This requires configuring ip pim use-floating-address on both ingress and egress VLANs. To do so, refer to the Make configuration changes through imish procedure in this article.
  • Next-hop: The floating IP address assigns the next-hop in the routes sent to the peers.
  • PIM State sharing: The multicast processes (PIMD and MRIBD) run on the standby BIG-IP system and operate in the same manner as the active system but do not forward traffic. Multicast Forwarding Cache (MFC) entries should be the same between the HA systems. For example, in the PIM-SM routes, the standby device should also have multicast neighborship with other multicast nodes, and in the case of PIM-SM, the standby device should have neighborship with the rendezvous point (RP) as well.

The failover feature works as follows:

  1. In steady state, PIM neighbors exchange periodic PIM hello messages and update the RP with PIM joins to periodically refresh mroute states.
  2. When a failover event occurs, the standby BIG-IP system becomes active.
  3. With PIM state sharing between the BIG-IP HA pair, the new active system uses the routes to route multicast traffic as PIM and BGP continues to update the unicast and multicast routes in the data plane.
  4. PIM neighbor information is flushed and the new active BIG-IP system generates a new PIM generation ID.
  5. The newly active BIG-IP system begins sending PIM hello packets with the new GenID from the floating self IP address, re-instantiating PIM neighboring.
  6. PIM Passive: Do not use ip pim passive with an HA pair. Its usage can result in neighbors becoming unaware of the GenID changes, and therefore network may not properly converge during a failover event. If you need to verify that you are using PIM Passive mode and remove the configuration, refer to the following procedures in this article: Verify floating multicast configurations and Make configuration changes through imish, respectively.
  7. In order to process the GenID value in PIM hello messages, PIM neighbors must comply with the implementation of PIM as described in RFC 4601 Section 4.5.5.

Troubleshooting

When troubleshooting a BIG-IP HA system for PIM multicast traffic, you should consider the following procedures:

For more information on configuring PIM, refer to the BIG-IP Advanced Routing Multicast Configuration Guide.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  • Verify floating multicast configurations
  • Verify the mroutes on the BIG-IP HA systems
  • Review the PIM states on the BIG-IP HA systems
  • Review the log files
  • Make configuration changes through imish

Verify floating multicast configurations

To display the multicast configuration on your BIG-IP system, enter the following command:

imish -e 'sh ru'

From the output, verify that PIM is using the floating IP address at the appropriate interface and that multicast routing is enabled and PIM mode is correctly configured. For PIM sparse mode, you need to configure the PIM RR.

You may observe an output similar to the following example:

[...]
!
ip multicast-routing
!
ip pim rp-address 100.100.100.100
!
interface lo
!
interface tmm
!
interface external
 ip pim sparse-mode
 ip pim use-floating-address
!
interface internal
 ip pim sparse-mode
 ip pim use-floating-address
!
[...]

Verify the mroutes on the BIG-IP HA systems

You can display the mroutes on the BIG-IP system by entering the following commands:

  • imish -e 'show ip pim mroute'
  • imish -e 'show ip mroute'

    Note>: This command displays routes in ZebOS.

  • tmsh show net mroute

    Note>: This command displays routes in TMM.

Review the PIM states on the BIG-IP HA systems

You can display the PIM state of your BIG-IP systems by entering the following commands:

  • imish -e 'show ip pim interface'
  • imish -e 'show ip mroute count'
  • imish -e 'sh ip pim rp mapping'
  • imish -e 'sh ip pim neighbor'

Review the log files

You should also review the log files which describe the multicast and failover events including error messages. Review the following log files:

  • /var/log/ltm
  • /var/log/messages
  • /var/log/zebos/zebos.log

Make configuration changes through imish

You manage a dynamic routing configuration through the IMI shell (imish). To make changes to the dynamic routing configuration for a specific route domain, perform the following procedure:
  1. Enter the IMI shell (imish) shell by entering the following command in bash:

    Note: If the route domain for the protocol you want to configure is the default route domain for the current partition, you do not need to use the -r option to specify the route domain ID.

    imish -r <route domain ID>

  2. In the IMI shell (imish), enter the following commands to enter configuration mode:

    enable
    configure terminal

    You may observe the following output and prompt in configuration mode:
    Enter configuration commands, one per line. End with CNTL/Z.
    examplehostname[0](config)#

  3. Enter Interface mode by specifying the name of the interface you want to configure:

    interface <interface name>

    For example, enter

    interface external

    You may observe the following prompt in interface mode:
    examplehostname[0](config-if)#

  4. Enter commands to make changes to your dynamic routing configuration. The following provide some examples:
    • To remove the ip pim passive configuration, enter the following command:

      no ip pim passive

    • To configure PIM to use floating address, enter the following command:

      ip pim use-floating address

  5. Exit configuration mode by entering the following command:

    exit

  6. Exit Interface mode by entering the following command:

    exit
