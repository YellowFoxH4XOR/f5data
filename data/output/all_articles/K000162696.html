Description

A BIG-IP configuration synchronization fails after a device is removed from device trust because a traffic group retains an invalid default-device reference.

The sync operation displays an error similar to:

A validation error occurred while syncing to a remote device 01070712:3: Caught configuration exception (0),

Values (/Common/decommissioned-device) specified for traffic group (/Common/traffic-group-1): foreign key index (default_device_fk)

do not point at an item that exists in the database.

Environment

  • BIG-IP LTM
  • High Availability configuration using:
    • Device trust
    • A sync-failover device group
    • Traffic groups
  • The affected traffic group is /Common/traffic-group-1.
  • The traffic group’s default-device references a device that is being decommissioned.
  • The device is removed from device trust before the traffic-group reference is cleared.

Cause

The traffic group retains a default-device reference to the decommissioned device. After the device is removed from device trust, the reference becomes invalid.

For example:

cm traffic-group /Common/traffic-group-1 {

default-device /Common/decommissioned-device

description "floating traffic group for unit 1"

unit-id 1

}

The default-device reference is not automatically cleared when a device is removed from the device group. The resulting foreign-key reference prevents the configuration from loading during synchronization.

This behavior is associated with Bug 838885 and Bug 496679. A fix is available for this issue.

Recommended Actions

Perform the following steps on the active primary BIG-IP system before removing the decommissioned device from device trust:

  1. Clear the stale default-device reference:
    tmsh modify cm traffic-group /Common/traffic-group-1 default-device none
  2. Save the configuration:
    tmsh save sys config
  3. Verify that the traffic group no longer references the decommissioned device:
    tmsh list cm traffic-group /Common/traffic-group-1
    The output should show no default-device field or should show:
    default-device none
  4. Identify the sync-failover device group:
    tmsh list cm device-group
  5. Push a full configuration synchronization, replacing <sync-failover-group-name> with the appropriate device-group name:
    tmsh run cm config-sync to-group <sync-failover-group-name> force-full-load-push
  6. After synchronization succeeds, remove the decommissioned device from device trust using:
    System > Device Management > Device Trust > Device Trust Members > Remove

Additional Information

  • Clear the default-device setting before removing the referenced device from device trust.
  • Adding the device back to device trust can temporarily restore synchronization because the referenced object exists again. The stale traffic-group reference must still be cleared before final decommissioning.
  • Verify the traffic-group configuration before retrying synchronization.
