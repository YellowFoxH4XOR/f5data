K8619: Configuring the BIG-IP ASM security policy to not check objects of a specific object type

Applies to

Source

Topic

In BIG-IP ASM 9.4.1 and earlier, you can use the Check Objects check box to configure the security policy to validate a specific object against the Web Objects list. If the Check Objects setting is disabled, the security policy allows requests for the object type to pass through without checking whether the actual object exists in the web application.

Beggining in BIG-IP ASM 9.4.2, the Check Objects check box was removed from the Object Types entity. As a result, if you upgrade from a previous version of the BIG-IP ASM system, or import a security policy from 9.4.2 to 9.4.2 or later, BIG-IP ASM 9.4.2 or later checks those objects. As a result, the security policy may block certain valid requests.

If you have upgraded from a previous version of the BIG-IP ASM system, or imported a security policy from 9.4.2 to 9.4.2 or later, you can configure BIG-IP ASM 9.4.2 to not check objects of a specific object type. To do so, perform one of the three following procedures:

Note: The following three procedures assume that you want to configure the security policy to allow all jpg, asp, no_ext files, and the robots.txt file.

  • Configuring an attack signature to block files not defined for an object type
  • Using a wildcard (*) object with the '.' (dot) meta character disallowed
  • Disallowing the "." (dot) meta character in the *.txt or other wildcard objects
Configuring an attack signature to block files not defined for an object type

To configure an attack signature to block all files that are not explicitly defined for a specific object type, perform the following four procedures:

  • Configuring the security policy to allow certain object type wildcards, web object wildcards and web objects
  • Creating the attack signature set
  • Create a new attack signature
  • Associating the attack signature set with the security policy

Configuring the security policy to allow certain object type wildcards, web object wildcards and web objects

To configure the security policy to allow certain object type wildcards, web object wildcards and web objects, perform the following procedure:

  1. Configure the security policy to allow the following object type wildcards:
    • txt
    • jpg
    • asp
    • no_ext
  2. Configure the security policy to allow the following web object wildcards:
    • *.txt
    • *.jpg
    • *.asp
    • *
  3. Configure the security policy to allow the robots.txt web object.

Creating the attack signature set

To create the Attack Signature set, perform the following procedure:

  1. From the Application Security menu, select Options.
  2. From the Attack Signatures menu, select Attack Signatures Sets.
  3. Click Create.
  4. Type a name for the Signature Set.
  5. In the Signatures Filter section, select the Only button next to User-Defined.
  6. Click Create.

Create a new attack signature

To create the Attack Signature, perform the following procedure:

Note: The following procedure causes the security policy to block all .txt files that are not explicitly defined under the objects.

  1. From the Application Security menu, select Options.
  2. From the Attack Signatures menu, select Attack Signatures.
  3. Click Create.
  4. Type a name and description for the Attack Signature.
  5. Select Request from the Apply To box.
  6. In the Rule box, enter the following text:

    uricontent: ".txt"; objonly; nocase;
  7. Verify the attack signature exists in the new attack signature set.

Associating the attack signature set with the security policy

To associate Attack Signature set with the security policy, perform the following procedure:

  1. From the Application Security menu, select Attack Signatures.
  2. Under Available Signatures sets, select the Signature Set you created above, and click the << to move the Signature Set to the Assigned Signature sets area.
  3. Click Update.
  4. Click Apply Policy.

After completing this procedure, the BIG-IP ASM will first attempt to make a positive match for objects specifically defined in the policy (robots.txt in the above example). If the requested object is not found, the BIG-IP ASM system then applies the attack signature. Wildcard objects are not considered explicit objects, and take a lower precedence than the attack signature.

Using a wildcard (*) object with the '.' (dot) meta character disallowed

To use a wildcard (*) object with the '.' (dot) meta character disallowed to block all files that are not explicitly defined for a specific object type, perform the following two procedures:

  • Configuring the security policy to allow certain object types and web objects
  • Configure the wildcard (*) object with the "." (dot) meta character disallowed

Configuring the security policy to allow certain object types and web objects

To configure the security policy to allow certain object types and web objects, perform the following procedure:

  1. Configure the security policy to allow the following object types:
    • No_ext
    • jpg
    • asp
    • txt
  2. Configure the security policy to allow the following web objects:
    • robots.txt
    • *.asp
    • *.jpg
    • *

Configure the wildcard (*) object with the "." (dot) meta character disallowed

To configure the wildcard (*) object with the "." (dot) meta character disallowed, perform the following procedure:

  1. From the Application Security menu, select Objects .
  2. Click the wildcard (*) object.
  3. In the Meta Character section, select .(0x2e) from the Available box, and click << to move the meta character to the Assigned section.
  4. Select Disallowed from the State drop-down box.
  5. Click Update.
  6. Click Apply Policy.
Disallowing the "." (dot) meta character in the *.txt or other wildcard objects

To configure the policy to disallow the "." (dot) meta character in the *.txt or other wildcard objects, perform the following three procedures:

  • Configuring the security policy to allow certain object types and web objects
  • Order the Wildcard objects
  • Disallowing the "." (dot) meta character in the txt and wildcard (*) objects

Configuring the security policy to allow certain object types and web objects

To configure the security policy to allow certain object types and web objects, perform the following procedure:

  1. Configure the security policy to allow the following object types:
    • No_ext
    • jpg
    • asp
    • txt
  2. Configure the security policy to allow the following web objects:
    • *.jpg
    • *.asp
    • *.txt
    • *
    • robots.txt

Order the Wildcard objects

To order the wildcard objects, perform the following procedure:

  1. Select Objects from the Application Security menu.
  2. Click the Order Wildcards menu.
  3. Order the Wildcard objects so that they appear in the order listed above.
  4. Click Save.

Disallowing the "." (dot) meta character in the txt and wildcard (*) objects

The BIG-IP ASM system matches objects to requests using the most to least specific criteria. As a result, the *.txt object can be modified to always be denied. This is achieved by disallowing the "." character in the object name so that all requests for the object are disallowed.

To configure the policy to disallow the "." (dot) meta character in the txt and wildcard (*) objects, perform the following procedure:

  1. Select Objects from the Application Security menu.
  2. Click the *.txt object.
  3. In the Meta Character section, select .(0x2e) from the Available box, and click << to move the meta character to the Assigned section.
  4. Select Disallowed from the State drop-down box.
  5. Click Update.
  6. Click Apply Policy.

After following this procedure, requests for robots.txt will be allowed, and the wildcard (*) object will be matched only if one of the more specific *.<object type> object does not match, resulting in a match only for no_ext object types.
