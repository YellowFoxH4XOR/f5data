K000134788: Unable to upload qkview file from BIG-IQ CM to iHealth after upgrade from 8.2 to 8.3

Type
Support Solution
Published
2023-09-26
Updated
2025-10-29
Source
https://my.f5.com/manage/s/article/K000134788

Description

Qkview upload from BIG-IQ CM to iHealth no longer works. In GUI you will see:

Login gave unexpected response: HTTP/1.1 415 415

In restjavad logs you will see error like:

/var/log/restjavad.0.log:

[INFO][19 May 2023 03:32:25 CDT][ BasicIHealthAuthenticator] Unable to authenticate user <someuser> at https://api.f5.com/auth/pub/sso/login/ihealth-api/: com.f5.rest.workers.device.ihealth.api.IHealthApiException: Login gave unexpected response: HTTP/1.1 415 415

Environment

BIG-IQ upgrade from 8.2 to 8.3

Cause

Bug ID 1313341

When there are values stored in the database pre-upgrade due to changes in the iHealth settings (ie. concurrent downloads, manual PUT request, etc.), those values are read upon upgrade to v8.3.0 and are set as iHealth settings. As a result, the old APIs are used instead of the new ones for iHealthv2.

Recommended Actions

Perform any of the following workaround from cli:

1. Manually set the API endpoints using a PUT request.

# restcurl -u admin: mgmt/cm/device/ihealth/config -d '{"iHealthEndpoint": "https://ihealth2-api.f5.com/qkview-analyzer/api/", "iHealthAuthEndpoint": "https://identity.account.f5.com/oauth2/ausp95ykc80HOU7SQ357/v1/token"}' -X PUT


2. Send an empty PUT request to cm/device/ihealth/config endpoint.

# restcurl -X PUT cm/device/ihealth/config -d '{ }'

Additional Information

None.
