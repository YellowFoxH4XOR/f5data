Known Issue

BIG-IP APM users may experience an unexpected logout after entering access credentials.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system uses an access profile virtual server configured with an iRule resource.
  • The access policy checks for an iRule event.
  • The access policy includes multiple agents and actions.
  • The BIG-IP APM system dB variable for rotate session IDs is enabled (default setting).

Impact

The BIG-IP APM system terminates user sessions by logging users out.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You receive a sporadic hangup redirect (logout) from the BIG-IP APM system after you enter credentials on the access policy logon page.
  • The /var/log/apm log file shows a successful logon of the user, followed by the BIG-IP APM system logout of the user.

Workaround

To work around this issue, you can disable BIG-IP APM session ID rotation. To do so, perform the following procedure:

Impact of workaround: BIG-IP APM session IDs are no longer rotated on each response while an access policy is being executed.

Disabling BIG-IP APM automatic session ID rotation

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To view the current configuration setting for session ID rotation, type the following command:

    list /sys db apm.rotatesessionid

  3. Disable automatic rotation of BIG-IP APM session IDs by typing the following command:

    modify /sys db apm.rotatesessionid value disable

  4. Save the change by typing the following command:

    save /sys config
