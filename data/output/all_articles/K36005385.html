Known Issue

A monitor that you configured with a large timeout value unexpectedly marks monitored objects as down or unavailable.

This issue occurs when all of the following conditions are met:

  • You create or modify a monitor in which the timeout plus the interval exceeds 86,400 seconds.
  • You assign the monitor to an object, such as a node, pool, or a specific pool member.

Impact

The monitored object is marked as down or unavailable before it reaches the configured timeout value.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system logs messages to the /var/log/ltm file in which the was up for time value is less than the configured timeout value, similar to the following example:

    notice mcpd[<pid>]: 01070638:5: Pool /<partition>/<pool name> member /<partition>/<pool member name>:<port> monitor status down. [ /<partition>/<monitor name>: down; last error: /<partition>/<monitor name>: No successful responses received before deadline. @<YYYY/MM/DD> <HH>:<MM>:<SS>.  ]  [ was up for <HH>hrs:<MM>mins:<SS>sec ]

  • Objects that the monitor prematurely marked as down or unavailable are marked as up or available on the next monitor probe interval.

Resolution

Status

Workaround

To work around this issue, you can modify the monitor interval and timeout settings to achieve three times the interval plus 1 second ratio, where the timeout value is less than 86400 seconds.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
