Description

  • Configured BIG-IP ASM to generate system resource alerts following K54900446
  • But you failed to receive email alerts when  the configured threshold value is exceeded

Environment

  • ASM
  • Resource Alerts

Cause

  • By design

Recommended Actions

  • BIG-IP will ONLY SEND email ALERT ONCE at a time the threshold value is breached
  • and there will be NO subsequent alerts until the usage drops below the threshold. 

Additional Information

  • ASM resource utilization monitoring is performed by monpd. [The monpd process is used in conjunction with the avrd process for reporting/charts].
  • stat collection/monitoring is performed by monpd at 5 minutes interval
  • if the system threshold is set at 80% exceeds at say one minute pass midnight [0001], an alert will be logged in the coming/nearest five minutes interval and alert is sent out at say 00:05.
  • NOTE, if XML Memory Utilization continues to remain above the threshold, NO alert will be sent there after for example at 00:10, 00:15 time interval
  • for example, based on the below tmctl output
    • since usage is at 99% and always above the threshold, we would expect to see no additional alert from this configuration.

      tmctl asm_memory_util_stats -s total_xml_mem_used,total_xml_max_mem |  awk '(c!=0&&c!=1&&$2) {print $1"KB "$2"KB " $1*100/$2"%"} {c++}'
      3096336KB 3096576KB 99.9922%      <-----------  99.99 %

  • if/when the utilization goes below the defined threshold, for example 77%, a new alert will be logged and sent stating that the resource utilization has dropped BELOW the configured threshold.
  • In short, if we follow procedures described in K54900446, we would expect the alert to be a one of email message and if the system continually exceeds configured value,  we would expect no further alert
  • this behavior is as expected and by design.
