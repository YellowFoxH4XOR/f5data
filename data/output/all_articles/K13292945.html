Description

After restarting httpd using the iControl REST API, you observe httpd fails to start, even with a subsequent restart of httpd at the command line.

Similar to the following example:

[root@v15-A:Active:Standalone] config # restcurl -u admin:admin /tm/sys/service -X POST -d '{"name":"httpd", "command":"restart"}'
{
  "kind": "tm:sys:service:restartstate",
  "name": "httpd",
  "command": "restart",
  "commandResult": "Stopping httpd: [  OK  ]\r\nStarting httpd: [FAILED]\r\n(98)Address already in use: AH00072: make_sock: could not bind to address 127.0.0.1:80\nno listening sockets available, shutting down\nAH00015: Unable to open logs\n"
}

[root@v15-A:Active:Standalone] config # tmsh restart sys service httpd
Stopping httpd:                                            [  OK  ]
Starting httpd:                                            [FAILED]

Environment

  • iControl REST API
  • httpd
  • tmsh

Cause

This is expected. It is currently not possible to restart httpd using the iControl REST API.

Recommended Actions

To recover from the failed httpd state, you can kill all instances of the httpd daemon and start httpd:

killall -9 httpd iControlPortal.cgi

tmsh start sys service httpd

If you would like to let F5 know that you require the functionality to restart httpd via the iControl REST API, open a service request with F5 Support and reference this article.

Additional Information

Python script that works around this is available on DevCentral, a link to this is provided in the 'Related Content' section of this article

You can also use the tmsh command "restart sys service httpd":

 

curl -sku <username>:<password> -X POST \
-H "Content-Type: application/json" \
https://<BIG-IP_IP>/mgmt/tm/util/bash \
-d '{"command":"run", "utilCmdArgs":"-c '\''tmsh restart sys service httpd'\''"}'

This will return an error:

curl: (56) OpenSSL SSL_read: OpenSSL/3.5.5: error:0A000126:SSL routines::unexpected eof while reading, errno 0

Because you are effectively killing the service that you are using to run the command, but the service is restarted as expected
