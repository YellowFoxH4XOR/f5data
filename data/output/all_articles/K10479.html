  • K22021244: Bypassing the BIG-IP ASM system (12.1.0 and later)
  • K14709: Bypassing the BIG-IP ASM system (11.4.0 - 12.0.0)
  • K7920: Bypassing the BIG-IP ASM system with an iRule in 9.x

Bypassing BIG-IP ASM in 10.0.1 through 11.3.0

In BIG-IP ASM 10.0.1 and later, the following iRule commands enable or disable BIG-IP ASM processing for certain requests or connections:

  • ASM::disable
  • ASM::enable

For example, you can disable BIG-IP ASM processing for requests starting with /bypass using the following iRule syntax:

when HTTP_CLASS_SELECTED {
ASM::enable
if { [HTTP::uri] starts_with "/bypass" } {
ASM::disable
}
}

Note: When you use the ASM::disable command to bypass BIG-IP ASM for one request, you should always re-enable BIG-IP ASM processing for subsequent connections by using the ASM::enable command at the top of the HTTP_CLASS_SELECTED event. Otherwise, all subsequent requests on the connection will bypass the BIG-IP ASM security policy.

Important: The ASM::disable iRule command will only work in the HTTP_CLASS_SELECTED event.

Bypassing BIG-IP ASM in 10.0.0

To bypass BIG-IP ASM in 10.0.0 only, define the following virtual server and iRule configuration:

  • Create one virtual server with BIG-IP ASM enabled.
  • Create one virtual server with BIG-IP ASM disabled.
  • Create a third virtual server used to target either of the other virtual servers depending on conditions in the request. The third virtual server references an iRule that appears similar to the following example:

    when HTTP_REQUEST {
    if { [HTTP::uri] starts_with "/bypass" } {
    virtual <ASM_disabled_vs>
    }
    else {
    virtual <ASM_enabled_vs>
    }
    }
