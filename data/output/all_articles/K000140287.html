K000140287: Direct traffic to only a single node in a pool at a time using Single Node Persistence

Type
Support Solution
Published
2024-07-22
Updated
2024-07-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000140287

Description

This guide outlines the steps required to configure a BIG-IP system so that traffic is directed to only one node in a pool at any given time, ensuring a failover to the second node only when the primary node is down. 

You may want to perform the steps in this article under the following conditions:

  • The pool consists of two members: server-1 and server-2.
  • Server-1 has a priority group setting of 1 and a minimum up member setting lower than 1 because the customer requires that only one server should handle traffic at any given moment.
  • When server-1 becomes unavailable, server-2 is designed to handle all traffic.
  • Upon server-1's restoration, server-2 should continue to manage all traffic, including new sessions.
  • If server-2 fails, server-1 will resume traffic handling.
  • When server-2 is back online, server-1 should continue serving all traffic, including new sessions.

Environment

  • Pool members of 2.
  • Priority group configurations.
  • iRule.
  • Universal persistence profile.

Cause

Priority group activation within BIG-IP is a mechanism that allows traffic to be directed to pool members based on their assigned priority. A pool member with a priority group value of 0 is considered to be in the lowest priority and will only receive traffic if higher priority members are not available. It is important to manage priority groups correctly to ensure that traffic distribution aligns with the desired failover and failback behaviors.

Recommended Actions

To send traffic to only 1 pool member at a time, you can use an iRule and Universal Persistence to set a single persistence record that applies to all connections. The below procedure assume that the virtual server is already created and attached to a pool.

  1.  Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic  ››  iRules : iRule List and click Create.
  3. In the Name box, type a name for the new iRule.
  4. Type the below codes in the Definition body of the iRule.
when CLIENT_ACCEPTED { 
  persist uie 1
}
  1. Click Finished.
  2. Navigate to Local Traffic  ››  Profiles : Persistence and click Create.
  3. In the Name box, type a name for the new Persistence profile.
  4. Select Universal as Persistence Type.
  5. Check Custom box for iRule and select the name of the iRule created in step 3 under drop down box.
  6. Check Custom box for Timeout and set the value to a value high enough so it will never expire under typical traffic conditions.
  7. Click Finished.
  8. Navigate to Local Traffic  ››  Virtual Servers : Virtual Server List and select the target virtual server name.
  9. Navigate to Resources at the tab and select the name of the Persistence profile created in step 7 for Default Persistence Profile option.
  10. Click Update.
