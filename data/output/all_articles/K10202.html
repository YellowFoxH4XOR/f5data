Known Issue

This is the result of a known issue. If the origin web server sets a max-age value in the Cache-Control header larger than 2,147,483 seconds, the max-age value may be removed from the Cache-Control header in the pvac process response, or may be set to an incorrect value. A value of 2,147,483 seconds (approximately 24.85 days) is the maximum value which can be stored in the 32-bit millisecond counter used by the pvac process. Values exceeding this amount will cause the counter to wrap. As a result, the value of the counter will no longer be accurate.

F5 Product Development tracked this issue as ID 317522 (formerly CR119952) and it was fixed in BIG-IP versions 9.4.8 and 10.0.1. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

You can work around this issue by configuring your origin web servers to set Cache-Control header max-age values to a smaller value for content managed by the BIG-IP WebAccelerator.
