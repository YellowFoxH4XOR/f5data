Description

  • You have NGINX Plus systems running on version R35 or above.
  • You noticed, critical log messages indicating "event loop was stalled for [X] ms," with no apparent CPU pressure.
  • You want to understand the cause, impact, and resolution for these errors.

Nginx Error 

         2026/05/22 22:22:22 [crit] 2220222#2220222: event loop was stalled for 1222 ms

Environment

  • NGINX Plus, version R35 or above
  • No reported CPU or other resource pressure at the time of the event
  • "stall_threshold" directive

Cause

  • The event loop stall errors are caused by blocking operations within the NGINX worker process, such as third-party modules, SSL handshake failures during health checks, or blocking network/DNS calls or other factor that affect worker process efficiency.  

Answer/Recommended Actions

NGINX Plus R35 introduced a new heuristics to specifically capture events that affect worker processes efficiency via directive "stall_threshold".

      stall_threshold

  •     Increase "stall_threshold" directive default value of 1000ms— the simplest way to suppress the message if the latency impact is acceptable  
    •      By default, a stall is reported when an event loop iteration exceeds 1000ms
    • Review and, if necessary, increase the "stall_threshold" directive to suppress the log message if the latency impact is acceptable.
    •      You can find more details about this directive "stall_threshold"
    •      You can also refer this docs for better management of the upstream
  •   Add "jitter" to health checks, if your configuration consists of large number of health checks

      jitter

  •  Sets the time within which each health check will be randomly delayed, by default, there is no delay.
  •  Review SSL health check configurations and network/DNS connectivity for potential sources of blocking.

     debugging

  •   Investigate the use of third-party modules and their potential impact on the event loop.
  •   For more and better understanding of actual root cause, enable debug logging in NGINX to gather more detailed information when the issue occurs.
