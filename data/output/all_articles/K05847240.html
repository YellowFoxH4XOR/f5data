Description

This article is intended to help you troubleshoot various issues you encounter when connecting to a network access resource that could be related to a lease IP address assignment. 

  • Not enough members
  • Edge client perspective: the connection hangs at the "Initializing.." stage
  • APM logs showing lease pool errors
  • APM-side lease pool stats
  • Client-side logs (Windows 10 seen in [%temp%\logterminal.txt or %temp%\Low\logterminal.txt])
  • No lease pool address is assigned
  • APM logs show no lease pool assigned (APM-side logs)
  • Client-side logs show no lease pool assigned
  • Address conflicts (a different user tries to get or use the same lease pool IP address)
  • BIG-IP APM logs show another user trying to use the same lease pool IP
  • Client-side logs show another user trying to use the same lease pool IP

Note: Additional information for each of these is available in the Additional Information section below. 

Environment

  • BIG-IP APM Network Access
  • Lease IP address assignment

Cause
Various

Recommended Actions

The following troubleshooting steps help you determine if the trouble with network access is the result of an issue related to the lease pool.

  • Verify common client-side settings
  • Review the Edge Client after you get connected
  • Review the BIG-IP APM settings, logs, and stats

Review the Edge Client after you get connected

  1. Click on the F5 edge client icon from the task bar.
  2. Open the main console.
  3. Click the View Details button.
  4. You should be able to view the assigned lease IP address on the Connection Details tab.

Not enough members (<lease pool> is out of addresses)

This is what happens: The client connects, the BIG-IP APM system tries to assign a lease pool IP address to the client, but there's no available IP in the lease pool.

This is the solution: Increase the lease pool IP addresses.

No lease pool address is assigned

This is what happens: The client connects, the BIG-IP APM system finds no lease pool, so it fails to assign any lease pool IP address. From the client perspective, this is similar to the no available IP in the lease pool problem.

This is the solution: If it's a configuration issue like no lease pool has been assigned to the network resource, you can easily fix it by assigning a proper lease pool. However, if it's happening during run-time (for example, initially the client connects to the BIG-IP APM system, properly gets a lease pool IP, establishes a VPN tunnel, then later, during a reconnect, the logs seen below appear), there's no good solution for this (it can happen in a legitimate situation).
 

APM logs show no lease pool assigned (APM-side logs)

Address conflicts (a different user tries to get or use the same lease pool IP address)

This is what happens: This is a pure mis-configuration, and what happens is one client will steal another client's lease pool IP address, which causes the other client to get temporarily disconnected. As soon as other client gets disconnected, it will automatically try to reconnect, which will cause an infinite loop in the  worst-case scenario.

This is the solution: Configure your system carefully so that no users can attempt to steal another users IP address.
