Known Issue

After you upgrade your BIG-IP software, IP address objects in non-default administrative partitions with non-zero default Route Domain (RD) IDs may lose their connections.

This issue occurs when all of the following conditions are met:

  • You upgrade a system from BIG-IP 10.x to any of the following affected versions:

    • BIG-IP 11.3.0
    • BIG-IP 11.2.0 through 11.2.1
  • The BIG-IP configuration has an administrative partition that has its default route domain set to a non-zero RD.
  • The previously-mentioned administrative partition contains other IP addressable objects (for example, LTM node) with no RD set, so the default RD ID will be used.

    For example, 10.10.10.100 will follow the partition's default RD ID value 66, so the address is as follows:

    10.10.10.100%66

  • The previously-mentioned administrative partition contains other IP addressable objects (for example, LTM node) with RD ID 0.

    For example:

    10.10.10.100%0

Impact

The system may no longer be able to use the affected IP address and may fail to connect to the IP address after the software upgrade.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After the upgrade, the IP address object (for example, LTM node) in a partition that belongs to RD 0 is treated as part of the default route domain for the partition.
  • The system may no longer be able to connect to the affected IP address object.   
  • If you try to query the affected object with the IP address and its RD ID, the system responds with an object not found error message.

    For example, before you perform the upgrade, send a query by typing the following tmsh command:

    tmsh list /ltm node 10.10.10.100%0

    You will observe the following result:

    ltm node 10.10.10.100 {
        partition A-Domain
        screen node-100
    }

    After the upgrade, if you send the same query, you may observe an error message similar to the following example:

    01020036:3: The requested node address (10.10.10.100%0) was not found.

    You see this error message, because after the software upgrade, the system internally transformed the node address to 10.10.10.100%66, but the address is still displayed as 10.10.10.100, where its partition A-Domain is using a default Route Domain ID value of 66.

Workaround

There is no workaround this issue. However, you can avoid the issue by setting the affected partition's default route domain ID to 0 before performing the software upgrade, then setting the ID back to its original value after the upgrade.

For example, if you have an administrative partition A-Domain with a default RD ID value of 66, and want to avoid this issue before you perform the upgrade, you have to change the A-Domain to use a default RD ID value of 0. You can then perform the software upgrade. After you successfully upgrade the system, change the A-Domain default RD ID back to 66.

Note: Temporarily changing the affected partition's RD ID to 0 will have no effect on the data plane.
