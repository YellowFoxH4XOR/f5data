Issue

Note: Access-based enumeration (ABE) is a configurable feature of Microsoft operating systems that permits a user performing a directory listing to see only those file system objects for which they have been granted access. 

ARX 2.x and 3.x

Important: When ABE is enabled on a filer, it is expected that a large number of perceived metadata skew conditions will occur. As a result, ABE is not supported for ARX versions 2.x and 3.x.

ARX 2.x and 3.x do not have feature support for ABE enabled filers.

When a client requests a directory listing for a managed volume, the find-files request is passed to the filer with the client’s credentials. With ABE enabled on a filer, the filer’s response only contains the file system objects the client has privileges to see. The filer’s response will not match what the ARX system has in metadata, and the ARX system will perceive this as a metadata skew. The ARX system’s response to the client will contain all of the file system objects listed in metadata. The file attributes for the perceived missing files are zeroed.

The perceived metadata skew is not an actual skew, but a result of ABE. However, the ARX system cannot differentiate between an actual metadata skew and a falsely perceived skew. When the perceived metadata skew is reported, the ARX DNAS process will attempt to correct the metadata skew by performing an auto-synchronization for the share’s metadata, sending an SNMP trap, and logging an error message that appears similar to the following example:

Reporting metadata skew from 'find file' for namespace'ns_abe', path '/abe_vol/win_dir': 'Not found [-70]'

ARX 4.x behavior

Support for ABE enabled filers was introduced in ARX 4.x. A managed volume can be configured with the cifs access-based-enum option.

The output of the show namespace command will display the ABE configuration of the volume that appears similar to the following example:

Volumes
-------
  /Vol
    CIFS : compressed files: no; named streams: yes; persistent ACLs: yes
           sparse files: no; Unicode on disk: yes; case sensitive: no

            Volume free space: 64GB (automatic)
           Volume total space: 119GB
    Metadata on internal disk: Yes
                Metadata size: 72k
               Oplock support: Enabled
           Notify-change mode: Normal
              CIFS path cache: Not Enabled
       CIFS access based enum: Enabled
                    Snapshots: Not Enabled
                        State: Enabled

Note: When the managed volume is configured for ABE, the ARX system expects all of the shares for the volume to be ABE enabled on the filer. However, ARX 4.x versions do not actually verify or enforce it when enabling the share.

When the find-files response from the filer does not match what is in the ARX metadata for an ABE enabled managed volume, it is still perceived as a metadata skew. The ARX system will still attempt to correct the perceived metadata skew by performing an auto-synchronization of the metadata. However, the value of the ABE flag is now passed to DNAS, and the ARX system’s response to the client will no longer contain information for the perceived missing file system objects. In addition, the ARX system will adjust the severity of the skew logging to a debug level and suppress the SNMP trap.

When ABE is enabled for a volume, it is expected that a large number of metadata skew conditions will occur. The auto-synchronization process has a throttling mechanism to avoid repetitively resynchronizing the same directories. The throttling mechanism maintains a queue of recently synchronized directories using an age-out mechanism, and refuses to resynchronize directories found in the queue.

Note: A cifs access-based-enum option (ignore-skew) is available to disable skew reporting for find-files operations on an ABE enabled managed volume. This option can be configured to stop excessive metadata synchronizations. However, F5 Networks does not recommend disabling skew reporting because it will result in an actual metadata skew not being reported and resolved. For information about disabling skew reporting for find-files operations on an ABE enabled managed volume, contact F5 Networks Technical Support.

ARX 5.x behavior

In ARX 5.x, the behavior changed for a managed volume that can be configured with the cifs access-based-enum option.

When the managed volume is configured for ABE, the ARX system expects all of the shares for the volume to be ABE enabled on the filer. Beginning in ARX 5.x, the ARX system will now verify and enforce it when enabling the share. For an ABE enabled managed volume, if the filer is not ABE enabled, the managed volume’s share will not be enabled.

Beginning in ARX 5.x, the show exports command will query the filer and display the actual ABE state of each filer share.

For example:

#show exports external-filer Server1 attributes
Export probe of filer "Server1" at 192.168.10.1

CIFS Credentials: TEST\administrator

Attributes:

  CIFS
    Codes: AE=Access-based Enum, CF=Compressed Files, NS=Named Streams,
           PA=Persistent ACLs, SF=Sparse Files, UD=Unicode On Disk
                                         Attributes
    Share                            AE  CF  NS  PA  SF  UD
    -------------------------------  --  --  --  --  --  --
   
    Share1                            X   X   X   X   X   X
    Share2                            X   X   X   X   X   X
    Share3                            -   X   X   X   X   X


When ABE is enabled, the ARX system may experience excessive metadata synchronization, which may result in high DNAS CPU utilization. ARX 5.x also introduced another method to prevent unnecessary auto-synchronization of metadata for an ABE enabled managed volume. When a metadata skew for a find-files operation is reported to DNAS, before performing an auto-synchronization, the ARX system will use the proxy-user credentials to double check the filer for one of the perceived missing files. If the file is found, the metadata skew is considered false and the auto-synchronization is not performed. The proxy-user credentials are used because the proxy-user should have full permissions to access any file on the filer, thus is not affected by the ABE state of the filer.

Note: Beginning in ARX 5.x, an additional cifs access-based-enum option (full-autosync) is available to prevent the ARX system from double checking the filer using the proxy-user credentials. When the full-autosync option is enabled, the ARX system will always perform an auto-synchronization of metadata for a reported metadata skew. However, enabling full-autosync is not recommended because of the potential performance impact of running excessive metadata synchronizations. For information about enabling full-autosync and disabling the ARX system from double checking the filer for a perceived missing file on an ABE enabled managed volume share, contact F5 Technical Support.

Important: If the ignore-skew option (introduced in ARX 4.x) is enabled, the full-autosync option has no effect because any metadata skew will be ignored and therefore not be reported.
