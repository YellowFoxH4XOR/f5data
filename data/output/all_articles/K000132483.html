K000132483: Attack Signature to block requests based on the User-Agent field of an HTTP request.

Type
Support Solution
Published
2023-03-02
Updated
2023-03-02
Applies to

  • BIG-IP ASM: 15.1.0, 15.1.2, 15.1.1, 15.1.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3
Source

Description

To block a Web Crawler or similar not desired requests that contain the same User-Agent string in their HTTP header, you can use custom attack signatures.

 

Environment

BIG-IP ASM 15.1.X

 

Cause

None.

 

Recommended Actions

Enable an attack signature by going to:

Security > Options > Application Security > Attack Signatures > Attack Signatures List > Create

 

  1. Specify a name
  2. Specify "request" in the Signature Type drop-down.
  3. Specify a description, System, and Attack Type (optional)
  4. Add a new rule with the following structure: Matched Element: Request Content; Match Criteria: contains string; Keyword: "specify the user-agent string to detect"
  5. Accuracy and Risk options are not relevant.
  6. Type Create

 

Create the Attack signature set and select the previously created attack signature by going to:

Security > Options > Application Security > Attack Signatures set > Create

Modify settings accordingly and select the previously created signature in the Signatures box.

 

Apply the Attack Signature to the Blocking and Learning settings:

Application security > Policy Building > Learning and Blocking Settings > Attack Signatures > Change> Select the Signature set > Save > Apply Policy

Note: Be aware of the modified policy.

 

You can check if the virtual server contains the policy by going to:

Local Traffic > Virtual Servers > Select Virtual server name > Security > Policies

Confirm if the Application Security Policy field is enabled and with the corresponding policy applied.
