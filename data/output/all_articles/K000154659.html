Known Issue

When you update the NGINX configuration through the NGINX One Console, the configuration push fails with the following error message:

bind() to 0.0.0.0:443 failed (98: Address already in use)

However, applying the same change directly through SSH and reloading NGINX, does not produce the error and NGINX behaves as expected.

This issue occurs when all of the following conditions are met:

  • You are using NGINX One Console to manage NGINX instances
  • You attempt to change an instance listen directive from wildcard to a specific IP:port bind or from IP:port bind to wildcard, pushing that change from NGINX One Console.

Impact

You will not be able to push a new configuration modifying the listening parameters of a server {} block.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • A message similar to the following in the NGINX One Console:

    Config apply failed. Errors found during NGINX reload after applying a new configuration: <timestamp> [emerg] <pid> bind() to 0.0.0.0:443 failed (98: Address already in use)

Status

F5 Product Development has assigned ID 16390 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to box, located at the top of this article.

Workaround

To work around this issue, you can manually make the changes on each NGINX instance. To do so, perform one of the following procedures:

Impact of workaround: Stopping the NGINX service on each instance will drop active connections. This operation should be performed during a maintenance window if the issue occurs in a production environment.

  • NGINX instances in a Config Sync Group
  • Standalone NGINX instances

NGINX instances in a Config Sync Group

  1. Log on to the NGINX instance with administrative access.
  2. Stop the NGINX Agent using the following command:

    sudo systemctl stop nginx-agent

  3. Make the intended configuration changes, including the listen directive.
  4. Restart the NGINX service using the following command:

    sudo systemctl restart nginx

  5. Log on to NGINX One Console.
  6. Repeat the intended configuration changes to the Config Sync Group. This will ensure that the NGINX One Console does not attempt to write the old configuration back to the instance when the NGINX Agent is restarted.
  7. Log back on to the NGINX instance and start the NGINX Agent, using the following command:

    sudo systemctl start nginx-agent

Standalone NGINX instances

  1. Log on to the NGINX instance with administrative access.
  2. Optionally, stop the NGINX Agent using the following command:

    sudo systemctl stop nginx-agent

  3. Make the intended configuration changes, including the listen directive.
  4. Restart the NGINX service using the following command:

    sudo systemctl restart nginx

    The new configuration changes should appear in the NGINX One Console.
