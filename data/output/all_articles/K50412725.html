Description
Data collection for a month period might be inaccurate.

Environment

  • BIG-IP Analytics

Cause
AVR data aggregation can happen on a periodic basis (e.g. monthly) OR earlier to preserve resource and avoid resource limitations.
The monthly data will be aggregated into MySQL database as data points. Let's use _M table for short.
It's possible that 2 monthly data aggregation can happen in the same month like below:

_M1 table aggregation happens on Thu Oct  1 00:00:00 +08 2020
_M2 table aggregation happens on Thu Oct 29 00:00:00 +08 2020

In this case, If we filter the AVR graph from period "Oct  1 00:00:00" to "Oct  31 23:59:59", it actually pulls out statistics from 2 data points in the _M table which are _M1 data + _M2 data. This resulted in the total client connections to be much more than just _M2 data that we want to see.
If we filter the graph from period "Oct  1 01:00:00" to "Oct  31 23:59:59", then it would have only pulled out data point from _M2 table, resulting in e.g. client connections to be only _M2 data, which is what we want to see for the month of Oct.

Recommended Actions

  • Upgrade to 13.1.x onwards to improve the accuracies in aggregated data.
  • Adjust the graph filter time period and make sure it only pull data from a single table. e.g. "Oct  1 01:00:00" to "Nov 1 01:00:00" to view data of month Oct.
