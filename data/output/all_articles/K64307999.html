Known Issue

The BIG-IP system incorrectly marks the Dynamic Host Configuration Protocol (DHCP) trace log as an error log.

This issue occurs when the following condition is met:

  • You send a DHCP request through a DHCP virtual server and wait 30 seconds for the DHCP callback to trigger.

Impact

This issue may cause clutter in the Traffic Management Microkernel (TMM) logs.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You view the following DHCP debug log repeatedly in the /var/log/tmm file that appears similar to the following example:

    <#> <date> <slot#> notice DHCP:dhcpv4_xh_timer_callback/1053: Entering: <mac-addr>

Workaround

To work around this issue, you can set the tmm.dhcp.log.level database variable to critical. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    setdb tmm.dhcp.log.level critical
