Topic

You should consider using this procedure under the following condition:

  • You want to configure a CA-signed device certificate and CRL verification for iQuery communication using OpenSSL.

    Note: If you want to configure CRL verification for iQuery for existing CA-signed SSL device certificates, refer to K40156465: Configure CRL verification for iQuery communication for existing CA-signed SSL device certificates.

Description

The BIG-IP DNS system uses the iQuery protocol to collect dynamic load-balancing and metrics information from remote BIG-IP DNS and other BIG-IP devices and distribute the information to remote BIG-IP DNS synchronization group members.

By default, the BIG-IP system uses a self-signed SSL device certificate to secure iQuery communication and authenticate connections to the BIG-IP Configuration utility. The BIG-IP system also supports using a SSL device certificate that was signed by a certificate authority (CA). In addition, in BIG-IP version 16.0.0 and later, you can configure the certificate revocation list (CRL) revocation for iQuery communication for SSL device certificates that are signed by a CA. Doing so prevents an attacker who compromises the associated private key, from adding a rogue BIG-IP DNS system to the synch group.

This article guides you through using OpenSSL to create a local Root CA, sign new SSL device certificates, and configure CRL revocation for iQuery communication. The procedures in this article create the following example files and directories:

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to a workstation with the OpenSSL software library installed.
  • You have administrative access to the BIG-IP DNS systems.

Procedures

Create a Root CA and sign a new SSL device certificate using OpenSSL

The following procedure uses the OpenSSL utility to create a local Root CA and sign SSL device certificates using the Root CA's private key. To create a Root CA and sign a new SSL device certificate using OpenSSL, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the workstation command line or BIG-IP Advanced Shell (bash).
  2. To create a working directory to store the CA Root certificate and key, use the following command syntax:

    mkdir <directory_name>

    For example, to create a directory named /var/tmp/ca, enter the following command:

    mkdir /var/tmp/ca

  3. To change into the working directory, use the following command syntax:

    cd <directory_name>

    For example, to change into the /var/tmp/ca directory, enter the following command:

    cd /var/tmp/ca

  4. To determine the OpenSSL configuration directory, enter the following command:

    openssl version -a

    In the following example, the OpenSSL configuration directory is in the /etc/pki/tls directory:

    OPENSSLDIR: "/etc/pki/tls"

  5. To copy the OpenSSL configuration file, openssl.cnf, to the working CA directory, use the following command syntax:

    cp </path>/openssl.cnf .

    For example, to copy the openssl.cnf file to your working directory using the path /etc/pki/tls, enter the following command:

    cp /etc/pki/tls/openssl.cnf .

  6. Using a text editor, edit the openssl.cnf file in the working CA directory and review the existing configuration directives in the following example information. At a minimum, make sure to include the below directives and change the values to suit your specific environment. For example, the below configuration specifies bigip_ca.crt and bigip_ca.key as the names of the Root CA certificate and key. Make sure the values in your openssl.cnf file are suitable for your environment.

    ####################################################################
    [ ca ]
    default_ca      = CA_default            # The default ca section
    ####################################################################

    [ CA_default ]
    dir             = .                                               
    certificate     = $dir/bigip_ca.crt                                                  
    private_key     = $dir/bigip_ca.key  
    new_certs_dir   = $dir
    crlnumber       = $dir/crlnumber
    crl             = $dir/crl.pem

    default_days = 3650
    default_md   = sha256
    default_crl_days = 30

    policy = policy_anything

    [ policy_anything ]
    countryName             = optional
    stateOrProvinceName     = optional
    organizationName        = optional
    organizationalUnitName  = optional
    commonName              = supplied
    emailAddress            = optional

    [ req ]
    default_bits            = 2048
    default_md              = sha256

    [ v3_req ]
    basicConstraints = CA:FALSE
    keyUsage = nonRepudiation, digitalSignature, keyEncipherment, keyCertSign, keyAgreement, dataEncipherment, cRLSign
    extendedKeyUsage = serverAuth, clientAuth, codeSigning, emailProtection

    [ v3_ca ]
    basicConstraints = CA:TRUE
    keyUsage = nonRepudiation, digitalSignature, keyEncipherment, keyCertSign, keyAgreement, dataEncipherment, cRLSign

    [ crl_ext ]
    # CRL extensions.
    # Only issuerAltName and authorityKeyIdentifier make any sense in a CRL.
    # issuerAltName=issuer:copy
    authorityKeyIdentifier=keyid:always,issuer:always

  7. Save the file.

  8. To create the necessary CA serial and index.txt files, enter the following commands:

    Note: The index.txt file contains the list of signed SSL certificates, and the serial file is the source of the SSL certificate serial number.

    echo 100000 > serial

    touch index.txt

  9. To create the Root CA certificate and key, use the following command syntax:

    openssl req -new -x509 -extensions v3_ca -newkey rsa:4096 -keyout <key_name>.key -out <cert_name>.crt -days 3650 -config ./openssl.cnf

    For example, to create a Root CA certificate named bigip_ca.crt and a key named bigip_ca.key, enter the following command:

    openssl req -new -x509 -extensions v3_ca -newkey rsa:4096 -keyout bigip_ca.key -out bigip_ca.crt -days 3650 -config ./openssl.cnf

    Enter a challenge password for the Root CA certificate and complete the prompts for the certificate policy information, such as Common Name.

  10. To create a directory to store the new signed SSL device certificate and key, use the following command syntax:

    mkdir <directory_name>

    For example, to create a directory that stores the SSL device certificate and key for a BIG-IP system named bigip1.example.com, enter the following command:

    mkdir bigip1.example.com

  11. To create a certificate signing request and key in the proper directory, use the following command syntax:

    openssl req -new -nodes -out <directory>/<request_name>.req -keyout <directory>/<key_name>.key -config ./openssl.cnf

    For example, to create a certificate request named bigip1_device.req and an SSL key named bigip1_device.key in the directory bigip1.example.com, enter the following command:

    Important: The Common Name should match what you enter in the Web browser's URL field when accessing the Configuration utility.

    openssl req -new -nodes -out bigip1.example.com/bigip1_device.req -keyout bigip1.example.com/bigip1_device.key -config ./openssl.cnf

    When prompted for a challenge password, press Enter for no password and complete the remaining prompts for the certificate policy information, such as Common Name.

  12. To sign the certificate request with the Root CA certificate, use the following command syntax:

    openssl ca -out <directory>/<cert_name>.crt -config ./openssl.cnf -infiles <directory>/<request_name>.req

    For example, to sign a request named bigip1_device.req in the bigip1.example.com directory, enter the following command:

    Note: Provide the CA private key passphrase. Enter Y to the questions that follow.

    openssl ca -out bigip1.example.com/bigip1_device.crt -config ./openssl.cnf -infiles bigip1.example.com/bigip1_device.req

    The command output appears similar to the following example:

    Enter pass phrase for ./bigip_ca.key:

    Certificate is to be certified until Jan 01 12:30:06 2030 GMT (3650 days)

    Sign the certificate? [y/n]:y

    1 out of 1 certificate requests certified, commit? [y/n]y

  13. Repeat steps 10 through 12 for additional BIG-IP DNS systems. Make sure to create a separate directory and change the Common Name for each of the BIG-IP systems.

Replace the BIG-IP self-signed device certificate with the CA-signed device certificate

The BIG-IP device certificate is used to secure iQuery communication and connections to the BIG-IP Configuration utility. F5 recommends replacing the BIG-IP self-signed device certificate with the CA-signed device certificate during a maintenance window as iQuery connections are disrupted during the procedure. To replace the BIG-IP self-signed device certificate with the CA-signed device certificate, perform the following procedures:

Back up the existing self-signed device certificates

As a precautionary measure, F5 recommends that you back up the existing self-signed device certificates prior to installing the new CA-signed certificates. To back up the existing self-signed device certificates, perform the following steps:

  1. Log into the BIG-IP advanced shell (bash).
  2. Back up the existing device certificate by entering the following command:

    cp /config/httpd/conf/ssl.crt/server.crt /config/httpd/conf/ssl.crt/server.crt.bak

  3. Back up the existing device key by entering the following command:

    cp /config/httpd/conf/ssl.key/server.key /config/httpd/conf/ssl.key/server.key.bak

  4. Repeat the above steps for the other BIG-IP DNS sync group members.

Transfer the CA-signed device certificate and key to the BIG-IP DNS system

If you created the CA-signed device certificates on a remote system, such as a Linux workstation, you must transfer the certificates to the BIG-IP DNS systems in the sync group. To overwrite the existing self-signed SSL device certificate and key with the new CA-signed SSL certificate and key, you must copy the new files to the following locations on the BIG-IP system:

  • Device certificate location: /config/httpd/conf/ssl.crt/server.crt
  • Device key location: /config/httpd/conf/ssl.key/server.key

To transfer the self-signed device certificate and key to the BIG-IP DNS system, perform the following steps:

Note: For information about transferring files to or from an F5 system, refer to K175: Transferring files to or from an F5 system.

Impact of procedure: Communication with other BIG-IP sync group members are interrupted until the new certificate is exchanged. There is no impact to high availability (HA) features such as traffic groups and device groups.

  1. Log in to the workstation or BIG-IP that contains your CA environment.
  2. To change into the working directory, use the following command syntax:

    cd <directory_name>

    For example, to change into the /var/tmp/ca directory, enter the following command:

    cd /var/tmp/ca

  3. To allow for proper iQuery communication, use the following syntax to append the Root CA certificate to the BIG-IP CA-signed device certificate:

    cat <path_to_CA_cert_name>.crt >> <path_to_BIGIP_device_cert_name>.crt

    For example,

    cat /var/tmp/ca/bigip_ca.crt >> /var/tmp/ca/bigip1.example.com/bigip1_device.crt

  4. Use the following command syntax to copy the new CA-signed SSL device certificate and key to the BIG-IP DNS system:

    scp <cert_name>.crt root@<BIG-IP_IP_addr>:/config/httpd/conf/ssl.crt/server.crt

    scp <key_name>.key root@<BIG-IP_IP_addr>:/config/httpd/conf/ssl.key/server.key

    For example,

    scp /var/tmp/ca/bigip1.example.com/bigip1_device.crt root@192.0.2.2:/config/httpd/conf/ssl.crt/server.crt

    scp /var/tmp/ca/bigip1.example.com/bigip1_device.key root@192.0.2.2:/config/httpd/conf/ssl.key/server.key

  5. Log into the BIG-IP advanced shell (bash).
  6. Configure httpd to use the new combined certificate file to secure the management interface. To do so, enter the following command:

    tmsh modify /sys httpd ssl-certchainfile /config/httpd/conf/ssl.crt/server.crt

  7. Restart the httpd process by entering the following command:

    tmsh restart /sys service httpd

Update the BIG-IP system Trusted Device Certificate and Trusted Server Certificate stores

For successful iQuery communication, the Trusted Device Certificate and Trusted Server Certificate stores on each sync group peer must contain the following:

  • The device certificate of each sync group member
  • The third-party CA certificate used to sign device certificates

You must manually update the local Trusted Device Certificate and Trusted Server Certificate stores with the new device certificate. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash.
  2. To copy the new device certificate to the Trusted Device Certificate store, enter the following command:

    cat /config/httpd/conf/ssl.crt/server.crt >> /config/big3d/client.crt

    Alternatively, you can add the new certificate to the trusted device certificate file and remove all old certificates by using the following command:

    cat /config/httpd/conf/ssl.crt/server.crt > /config/big3d/client.crt

  3. To copy the new device certificate to the Trusted Server Certificate store, enter the following command:

    cat /config/httpd/conf/ssl.crt/server.crt >> /config/gtm/server.crt

    Alternatively, you can add the new certificate to the trusted server certificate file and remove all old certificates by using the following command:

    cat /config/httpd/conf/ssl.crt/server.crt > /config/gtm/server.crt

  4. To update the trusted certificate stores on remote BIG-IP systems, enter the following command:

    Note: The bigip_add utility prompts you for the root password of each BIG-IP system defined in the BIG-IP DNS configuration file.

    bigip_add

  5. To restart the gtmd process, enter the following command:

    bigstart restart gtmd

  6. To restart the big3d process, enter the following command:

    bigstart restart big3d

Create the PEM-encoded CRL file

After installing the CA-signed device certificates on the BIG-IP sync group members, use the OpenSSL utility to create the PEM-encoded CRL file. The CRL file allows the CA to communicate the revocation status of the BIG-IP device certificates that may have been compromised prior to their expiration date. The CRL file is signed by the Root CA you created in the previous procedure. To create the PEM-encoded CRL file, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the workstation or BIG-IP that contains your CA environment.
  2. To enter the working directory, use the following command syntax:

    cd <directory_name>

    For example, to enter the /var/tmp/ca directory, enter the following command:

    cd /var/tmp/ca

  3. Create the crlnumber file by entering the following command:

    echo 00 > crlnumber

  4. Create the PEM-encoded CRL file by using the following syntax:

    openssl ca -gencrl -keyfile <CA_key>.key -cert <CA_cert>.crt -out <CRL_file>.pem -config <OpenSSL_config_file>

    For example,

    openssl ca -gencrl -keyfile bigip_ca.key -cert bigip_ca.crt -out crl.pem -config openssl.cnf

    When prompted enter the passphrase for the CA key.

Upload the PEM-encoded CRL file to the BIG-IP DNS sync group members

After you create the PEM-encoded CRL file, upload the file to the /config directory on the BIG-IP DNS synchronization group members and name the file as follows: /config/revoked_certs.crl.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the workstation or BIG-IP that contains your CA environment.
  2. To upload the CRL file to the remote BIG-IP systems using secure copy (SCP), use the following syntax:

    scp <CRL_filename> root@<BIG-IP_mgmt_IP>:/config/revoked_certs.crl

    For example:

    scp crl.pem root@192.0.2.1:/config/revoked_certs.crl

  3. Repeat the upload process for each BIG-IP sync group member.

Confirm the CRL loaded properly

When the CRL file is uploaded to the BIG-IP system, you can confirm that the file loaded properly by performing the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP TMOS shell.
  2. To view the global traffic logs, use the following syntax:

    show /sys log gtm range <date range>

    For example, to view ltm logs from two days ago until now, enter the following command:

    show /sys log gtm range now-2d

    The following message indicates that CRL validation is enabled on all remote iQuery connections:

    012b3100:5: CRL file /config/revoked_certs.crl created, enabling CRL validation on all remote iQuery connections

Revoke the CA-signed device certificate using OpenSSL

If you think that the CA-signed device certificate has been compromised prior to its expiration date, you can revoke the certificate using OpenSSL. To do so, perform the following steps:

Impact of procedure: After revoking the device certificate and uploading the updated CRL file to the sync group members, remote iQuery connections are terminated.

  1. Log in to the workstation or BIG-IP that contains your CA environment.
  2. To change into the working directory, use the following command syntax:

    cd <directory_name>

    For example, to enter the /var/tmp/ca directory, enter the following command:

    cd /var/tmp/ca

  3. To Revoke the CA-signed device certificate use the following syntax:

    openssl ca -revoke <Path_to_BIGIP_device_cert_name>.crt -keyfile <CA_key>.key -cert <CA_cert>.crt -config <OpenSSL_config_file>

    For example,

    openssl ca -revoke bigip1.example.com/bigip1_device.crt -keyfile bigip_ca.key -cert bigip_ca.crt -config openssl.cnf

    Enter the passphrase for the CA key.

  4. To regenerate CRL file use the following syntax:

    openssl ca -gencrl -keyfile <CA_key>.key -cert <CA_cert>.crt -out <CRL_file>.pem -config <OpenSSL_config_file>

    For example,

    openssl ca -gencrl -keyfile bigip_ca.key -cert bigip_ca.crt -out crl.pem -config openssl.cnf

    Enter the passphrase for the CA key.

  5. To upload the CRL file to the remote BIG-IP systems using SCP, use the following syntax:

    scp <CRL_filename> root@<BIG-IP_mgmt_IP>:/config/revoked_certs.crl

    For example:

    scp crl.pem root@192.0.2.1:/config/revoked_certs.crl

  6. Repeat the upload process for each BIG-IP sync group member.

    Note: To verify the device certificate is revoked, refer to K02877347: Error Message: <daemon[pid]> <error_code> Certificate with subject <subject> from issuer <issuer> is revoked.
