Description
JSON content-types may sometimes result in "illegal empty parameter value" violations when using the "parse parameters" option within ASM for JSON processing.  These should be analyzed to confirm if the element truly has no value or if the value is another JSON object which can be normal JSON formatting.

Environment

  • ASM policy with "parse parameters" enabled in JSON profile
  • JSON body with a JSON element containing a JSON object value-type 
    ex:  { "key0" : { "key1" : "val1" } }

Cause
When parsing JSON body into key/value pairs for further parameter handling in ASM, a JSON element with another JSON object as its value is parsed as having no value.  This is intended behavior. 
In the above example, "key0" would be considered as having no value while "key1" would be parsed separately as having a value of "val1".

Recommended Actions

Add the JSON element name which allows JSON object value types as an explicit parameter and enable "Allow Empty Value" for this parameter.
