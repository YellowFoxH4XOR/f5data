K8896: Bypassing the WebAccelerator for BEA AquaLogic (Plumtree) internal requests routed back through the BIG-IP WebAccelerator

Topic

The BEA AquaLogic (Plumtree) application makes requests to itself internally when compiling a page. The BEA AquaLogic server can be configured to use WINS or DNS when making resolutions for these internal connections. When configured to use DNS, the requests are often routed back through the BIG-IP WebAccelerator virtual server. When the connections are routed through the BIG-IP WebAccelerator, only half of the page displays.

To ensure the pages render properly, perform one of the following two procedures:

  • Configure the BEA AquaLogic server to route the internal connections directly to itself, rather than route the connections to the BIG-IP WebAccelerator virtual server.

    Note: To configure the BEA AquaLogic server to route the internal connections directly to itself, refer to the BEA AquaLogic product documentation.
  • Use an iRule that identifies the requests coming from the BEA AquaLogic server, and disable the BIG-IP WebAccelerator for the requests.

    For example, the following iRule identifies when the request is coming from the BEA AquaLogic server and disables the BIG-IP WebAccelerator. The iRule specifically looks for an HTTP header named CSP-Gateway-Type, which identifies that the request originated from the server. The iRule disables the HTTP::class for the request and bypasses the BIG-IP WebAccelerator: 
    
when HTTP_REQUEST {     
        if { [HTTP::header exists {CSP-Gateway-Type}] } {
          HTTP::class disable
          CACHE::disable
        }
    }

    Note: If your specific implementation does not use the CSP-Gateway-Type HTTP header, you will need to modify the iRule to use another HTTP header that will identify requests originating from the server. If no unique HTTP headers exist, you may modify the iRule to use the IP addresses of the server to identify the requests originating from the server.
