Topic

The FirePass controller's reverse proxy technology enables remote access to web applications through the use of a browser. Citrix published resources located on Citrix XenApp, Presentation, or MetaFrame servers can be presented to users through a web portal, accessible with a browser. Resources presented by the Citrix portal can be accessed using browser-based Citrix web clients, which can also be located on the portal and downloaded to the browser, if not already present on the user's system. Microsoft Windows-based systems typically use an ActiveX version of the Citrix web client to view resources in a browser.

For Mac OS X or Linux clients, a Java version, the Citrix Java ICA (JICA) client, is available. If the JICA client is hosted on a web portal, and embedded in a web page, a FirePass user can use a Portal Access Web Application favorite to download the JICA client, and run the client in the browser. The Citrix ICA connections created by the JICA client are established securely and automatically through the FirePass controller's reverse proxy. No actions are required by the user to tunnel the ICA connections over the FirePass SSL VPN.

Important: The Citrix Java ICA client may not have the same functionality as the Citrix native client. Refer to Citrix's Java ICA client documentation for a full list of supported features.

Embedding the JICA client in a web page

To embed the JICA client in a web page, perform the following procedure:

  1. Download the Citrix Java client file archive from the downloads page of the Citrix website.

    Note: The link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

    The download is available as either a zip file (.zip) or a gzip tar file (.tar.gz). Download these files to the web server on which your Citrix portal resides, or a system that can transfer the files to the portal site.
  2. Unpack the Citrix Java client files from the downloaded archive file.

    Extract the contents of the file to a temporary directory, using whatever decompression utility is appropriate for the type of system you are using and the type of file you downloaded. The unpacked files consist of Java archive files (.jar), HTML files, text files, and subdirectories.
  3. Create or select a directory on the Citrix portal that will contain the Citrix Java client files and subdirectories that will be accessed by Citrix users through a browser.

    For example, if you were using a Microsoft IIS server as the web server for the Citrix portal, you would create the directory directory:

    /inetpub/wwwroot/Citrix/MetaFrame/site
  4. In the directory from step 3, create a subdirectory for the Citrix Java client's Java archive files (.jar).

    For example:

    /inetpub/wwwroot/Citrix/MetaFrame/site/jica
  5. Copy the Citrix Java client's Java archive files (.jar) from your temporary directory to the directory created in step 4.
  6. In the main temporary directory, copy all the files with a .jar extension from your temporary directory in step 2 to the directory created in step 4.
  7. Copy the desktop.html file from the examples subdirectory of your temporary directory to the directory created in step 3.

    For example:

    /inetpub/wwwroot/Citrix/MetaFrame/site/desktop.html
  8. Modify the desktop.html file's applet tag section

    Using an editor, modify the codebase attribute and the Address parameter's value within the applet tag to reflect the configuration for your directory structure and server name, respectively. The codebase attribute will be a relative or absolute URL to the Citrix Java client's Java archive directory that you created in step 4. The Address parameter's value will be the fully qualified domain name (FQDN) of your Citrix web portal.

    For example:

    codebase="/Citrix/MetaFrame/site/jica"

    Note: A relative URL is used in this example. The path is from the server root directory to the directory containing the Java archive files, which is contained within double quotes.

    param name="Address" value="citrixweb.siteconfig.com"

    Note: Enter the FQDN of the web portal in double quotes for the value of the Address parameter.
  9. F5 Networks recommends that you rename the desktop.html file in order to indicate that the original file has been altered.

    For example:

    /inetpub/wwwroot/Citrix/MetaFrame/site/desktop.html

    You could change the original filename to a filename similar to the following example:

    /inetpub/wwwroot/Citrix/MetaFrame/site/appletdesktop.html
  10. Verify that browsing the file loads the applet.

    To do so, browse to the appletdesktop.html page to determine whether the Citrix Java applet loads into the browser (your browser settings may display pop-up windows requiring your approval to download and run the Citrix Java client). You may use the Java console of your browser as a troubleshooting tool.
  11. Create a Portal Access Web Application favorite on the FirePass controller.

    To do so, use either the Administrative Console or a user's webtop to create a Portal Access Web Application favorite using the URL of the Citrix web portal. In our example, you would use the following URL to configure the favorite:

    http://citrixweb.siterequest.com//Citrix/MetaFrame/site/appletdesktop.html
  12. Verify that browsing through Portal Access loads the applet. To do so, use the favorite created in step 11 to load the Citrix Java client in your browser..

This example demonstrates a basic way to embed the Citrix Java client into a web page. Different configurations than those in the example can be used.  More advanced web content may be created to present the Citrix Java client and perform the download through a more sophisticated user interface experience.

Note: For best performance of Java applets through the Portal Access reverse proxy, your FirePass controller should be running version 6.0.2 or later.
