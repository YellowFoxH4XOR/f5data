Known Issue

Traffic processed by a specific Client SSL profile configuration may trigger the Traffic Management Microkernel (TMM) to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP virtual server is configured with a Client SSL profile.
  • The Client SSL profile has the OCSP Stapling and Session Ticket options enabled.
  • The virtual server processes SSL traffic from a client where the client sends a valid session ticket along with a status_request extension. 

Impact

The BIG-IP system temporarily fails to process traffic while the TMM process restarts. If you have configured the BIG-IP system for high availability (HA), it fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file in the /shared/core directory.
  • The BIG-IP system logs a SIGSEGV to the /var/log/tmm file when the TMM produces the core file and restarts.

Workaround

To work around this issue, you can modify the affected Client SSL profile and disable the Session Ticket option. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Set Configuration to Advanced.
  4. To disable the Session Ticket option, clear the Enabled check box.
  5. Click Update.
