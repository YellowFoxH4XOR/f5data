K000134491: HTTP response header Content-Length is missing from Nginx response

Type
Support Solution
Published
2023-05-06
Updated
2023-05-06
Applies to
  • NGINX Products
  • NGINX Plus: R27, R28, R29, R26
Source
https://my.f5.com/manage/s/article/K000134491

Description

  • You successfully configured your Nginx-Plus as a load balancer 
  • You also enabled gzip compression on a given Virtual Server.
          server {
                   listen 192.168.1.4:443 ssl http2;
                   status_zone 192.168.1.4_https;
                   server_name my.example.com;
                   gzip on; 
                ...
                }
  • With the above configuration, when inspecting HTTP response header, you notice Content-Length is not included with Nginx response.

Environment

  • gzip compression
  • Nginx Plus

Cause

  • When compression is enabled, Nginx is unable to tell the final size of the file and hence it won't include Content-Length in its HTTP response header

Recommended Actions

  • On the Nginx, you cannot have compression enabled and at the same time have Content-Length included in the response header.
  • This is default and expected behavior of Nginx and there are no workaround to have both feature at the same time.
  • If you need "Content-Length" value, then you would need to disable gzip
