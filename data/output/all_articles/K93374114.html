Description
BIG-IP QKViews displayed in iHealth report Virtual Address route-advertisement to be "disabled" instead of the expected value.

Environment

  • 13.0.0 HF1 or later
  • Route-advertisement configured to a non-default (non-disabled) value for one or more Virtual Addresses

Cause
Route Advertisement behavior was changed in TMOS 13.0.0. HF1 as described in K85543242: Additional virtual address Route Advertisement configuration options available. This resulted in 6 options beyond the "Enabled" and "Disabled" previously available. The 6 new states for a Virtual Address's Route Advertisement are tracked in a new internal field with the previous field now set to disabled as it is no longer used. iHealth currently utilizes the original field and consequently reports the route-advertisement to always be Disabled. This can be seen with the iHealth command "tmsh list /ltm virtual-address all-properties" for a Virtual Address which as a Route Advertisement value to set to a value other than Disabled.

Recommended Actions

In iHealth: Review the QKView's bigip.conf file and locate the appropriate virtual address(es) to determine the accurate route-advertisement from the BIG-IP.
On BIG-IP: the tmos command "tmsh list ltm virtual-address all-properties" will display the correct information.
