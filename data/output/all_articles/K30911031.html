Description

Failover occurred and TMM generates a core file in the /shared/core directory.

When TMM produces a core file and restarts (this will make system offline), the BIG-IP system logs a SIGABRT to the /var/log/tmm*:

notice ** SIGABRT **
 

The below logs will be present in /var/log/ltm:

sod[<PID>]: 01140041:5: Killing tmm.0 pid <PID_of_TMM>.  
 

Environment

  • BIG-IP
  • Virtual server
  • iRule
  • TMM core

Cause

TMM enters an infinite loop due to the iRule which contains similar to below:

e.g.1
when HTTP_REQUEST {
      virtual <virtual_server_name>
}

e.g.2
when HTTP_REQUEST {
    if { [HTTP::host] equals "<host_name>" }
    {
        HTTP::redirect "<https://***>"
    }
    virtual <virtual_server_name>
}

Recommended Actions
  • Correct the irule with appropriate action to avoid infinite loop.
       or
  • Remove the Irule from virtual server. 
     
Additional Information

When HTTP_REQUEST, then send the traffic to same virtual server again and again, and so on indefinitely results in TMM crash generating a core The BIG-IP system temporarily fails to process traffic as it recovers from TMM restarting and device is set offline, and devices configured as part of a high-availability pair may fail over.
