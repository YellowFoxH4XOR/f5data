Known Issue

This is the result of a known issue. If an inband monitor marks a pool member down, an active monitor fails to bring the pool member back up once the pool member has become responsive again. Even though the active monitor performs successful health checks, the BIG-IP system continues to report the pool member as down.

Note: When you configure an inband monitor, the BIG-IP system performs passive monitoring as part of client requests. The situation described in the previous paragraph refers to the process of using an inband monitor to detect unresponsive pool members and mark them down, and an active monitor to bring the pool members back up once they are responsive again.

F5 Product Development tracked this issue as ID 349962 and it was fixed in BIG-IP versions 10.2.2 and 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

Avoid using an inband monitor together with one or more active monitors until F5 Product Development has resolved this issue.

If you do not want to lose the inband monitor functionality, you may be able to replace the inband monitor with an iRule that performs the same function. For more information on this technique, refer to K10640: Pool member reselection options.

If you have already experienced the issue described in this Solution, and your system shows one or more pool members incorrectly reported as down, modify your configuration so the system does not use the two monitor types together, and the system marks the affected pool member(s) up again.
