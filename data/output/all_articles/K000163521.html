K000163521: Troubleshooting connectivity after api.f5.com and callhome.f5.com IP address changes

Description

Effective October 2, 2026, the IP address for api.f5.com changes to 185.56.152.6, and the IP address for callhome.f5.com changes to 159.60.134.92. Update outbound firewall allowlists, proxy policies, and other controls that use fixed destination IP addresses.

After the change, BIG-IP or BIG-IQ systems may be unable to reach F5-hosted services if network controls still allow only the previous address range or cached DNS records have not refreshed.

Conditions

  • The environment restricts outbound HTTPS traffic by destination IP address. 
  • A firewall, proxy, security gateway, or network access control list contains the previous address range. 
  • DNS caches or manually configured host mappings return an outdated address. 
  • The device route to the Internet passes through TLS inspection or another intermediary that blocks the connection. 

Cause

F5 updated the public addresses associated with api.f5.com and callhome.f5.com. Connectivity fails when a firewall, proxy, DNS cache, host file, or other control continues to use the previous destination address and does not allow outbound HTTPS on TCP port 443 to the new address. 

Recommended Actions

  1. Update outbound firewall allowlists and proxy policies to permit api.f5.com at 185.56.152.6 over TCP 443 
  2. Update outbound firewall allowlists and proxy policies to permit callhome.f5.com at 159.60.134.92 over TCP 443 
  3. Prefer hostname-based rules supported. If fixed IP rules are required, confirm they match the currently published F5 hosted-service addresses 
  4. Remove or update stale static host entries and clear relevant DNS caches 
  5. From the affected network, resolve each hostname and confirm it returns the expected new IP address 
  6. Test TCP 443 connectivity to each hostname using an approved network diagnostic method 
  7. Retry the affected function: Phone Home, iHealth upload, BIG-IQ license usage reporting, Automatic Update Check, ASM signature update, or FPS signature update. 
  8. Review the applicable BIG-IP, BIG-IQ, proxy, and firewall logs for DNS, timeout, certificate, or connection errors 
  9. If TLS inspection is used and certificate validation fails, confirm the interception configuration and trusted CA chain before retrying 

Additional Information

F5 notes that hosted services are not necessarily bound to a single IP address and recommends resolving the hostname to verify that the returned address is within the published range. Maintain hostname-based access where possible and periodically validate fixed-IP allowlists against the current F5 guidance.
