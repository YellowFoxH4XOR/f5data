Description

Enabling Single Page Application (SPA) Support in ASM.

Environment

  • CAPTCHA or Client Side Integrity Defense is not being displayed properly when using Brute Force Protection in an ASM policy.
  • Brute Force violations are logged but CAPTCHA or Client Side Integrity Defense is not performed on client.
  • Single Page Application is not enabled.
  • Application could be considered an SPA due to login transaction utilizing AJAX/JSON.

Cause

ASM CAPTCHA and Client Side Integrity Defense javascript-based challenges will send an HTML response when triggered without SPA mode enabled.  An AJAX or SPA application may not display this page if the application is expecting a JSON or XML response instead of HTML.

Recommended Actions

Enabling SPA mode in ASM will allow ASM to use pre-loaded javascript to display CAPTCHA or CSID when these mitigation actions are triggered in an ASM policy.  This is similar to the functionality of the AJAX Blocking Response Page.

To enable Single Page Application support, follow the steps for one of the two following options.  

Enabling SPA mode for all virtual servers with ASM policies attached.

Impact of procedure: Performing the following procedure will have an impact on the production system while the ASM system is restarted to apply the setting as the device will be briefly offline.  After device is online all policies will pre-load a new JS file injected into the initial site HTML.  This is not expected to have a negative effect on clients but edge cases may exist. 

  1. Log in to the Configuration Utility
  2. Browse to Security > Options > Application Security > Advanced Configuration > System Variables
  3. In the search field enter 'single_page_application'
  4. Click on single_page_application to enter the configuration settings
  5. In the field Parameter Value enter 1 to enable
  6. Click on Update
    Note: You must perform a 'tmsh restart sys service asm' for this change to take effect! If you are using a device group you must perform 'tmsh restart sys service asm' on all members of the device group for this change to take effect!
Enabling SPA mode for a single virtual server with ASM policies attached.

Impact of procedure:  All ASM policies attached to the virtual server will pre-load a new JS file injected into the initial site HTML.  This is not expected to have a negative effect on clients but edge cases may exist. No restart of the ASM system is necessary for this method.
  1. Log in to the Configuration Utility
  2. Create a new DoS Protection Profile with Application Security enabled.
  3. In General Properties of the DoS Application Security settings enable Single Page Application.
  4. In TPS based protection set Operation Mode to "transparent"
    Note: Detection settings may also be configured as necessary to reduce logging of DoS events.  Additionally, if a DoS Application Security profile is assigned to this virtual server with TPS-based Protection already configured, this can be left in place with the addition of step 3.  Creating a new DoS profile is not necessary in this case.
  5. Save new DoS profile and assign it to the virtual servers as needed under Virtual Server >> Security >> Policies >> DoS Protection Profile
