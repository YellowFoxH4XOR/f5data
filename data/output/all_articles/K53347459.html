Topic

You should consider using these procedures under the following condition:

  • You want to globally set the allowed DNS zone apex (origin) or under-apex (name space beneath the apex) resource record types returned for one-off NODATA by your BIG-IP DNS system.

Description

You can use the following BIG-IP DNS system database variables to configure the NSEC3 types bitmap returned for one-off NODATA:

  • dnssec.nsec3apextypesbitmap
  • dnssec.nsec3underapextypesbitmap

Configuring either database variable will globally configure the NSEC3 types bitmap returned in one-off NODATA responses for apex and under-apex responses, respectively.

Important: The resource record type of caa is not supported in BIG-IP DNS prior to version 14.1.0.

Note: For more information, refer to Internet Engineering Task Force (RFC 8499) and Internet Engineering Task Force (RFC 2308). These links takes you to a resource outside of AskF5, and the third party could remove these documents without our knowledge.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the TMOS Shell (tmsh).
  • You understand DNS resource record types as they apply to your environment. 

Procedures

  • Configuring the permissible apex resource record types returned by the BIG-IP DNS system for one-off NODATA
  • Configuring the permissible under-apex resource record types returned by the BIG-IP DNS system for one-off NODATA

Configuring the permissible apex resource record types returned by the BIG-IP DNS system for one-off NODATA

You can modify the dnssec.nsec3apextypesbitmap system database variable to specify the resource record types returned for one-off NODATA for zone apex (global). The default following resource records are configured for all "ns soa rrsig nsec3param dnskey" zones. You can update these resource record types by using the following procedure.

Impact of procedure: The following procedure modifies the permissible apex resource record types returned by the BIG-IP DNS system for one-off NODATA at the global level.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify the resource record types returned for one-off NODATA for the apex zone of all configured zones, use the following command syntax:

    modify /sys db  dnssec.nsec3apextypesbitmap value "<record type> <record type> <record type>"

    Note: Replace <record type> with each desired record type to be allowed for all under-apex zones.

    Important: When modifying the resource record types for the database variable, you must include all intended resource record types in the quoted string. If you fail to include an existing resource record type in the update, you will remove it from the one-off NODATA resource record types list.

    Important: Setting an unrecognized resource record type causes the configuration to treat the record type as the only default record type for one-off NODATA. 

    For example:

    modify /sys db  dnssec.nsec3apextypesbitmap value "a aaaa dnskey ns nsec3param soa txt rrsig"

Configuring the permissible under-apex resource record types returned by the BIG-IP DNS system for one-off NODATA

You can modify the dnssec.nsec3underapextypesbitmap system database variable to specify the resource record types enabled for the under-apex (global) zone. By default, the following resource records are configured for all "txt rrsig" underzones. You can update the underzone resource record types by using the following procedure.

Impact of procedure: The following procedure modifies the permissible under-apex resource record types returned by the BIG-IP DNS system at the global level.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify all resource record types enabled for the under-apex zones of all configured zones, use the following command syntax:

    modify /sys db  dnssec.nsec3underapextypesbitmap value "<record type> <record type> <record type>"

    Note: Replace <record type> with each desired record type to allow for all under-apex zones.

    Important: When modifying the resource record types for the database variable, you must include all intended resource record types in the quoted string. If you fail to include an existing resource record type in the update, you will remove it from the one-off NODATA resource record types list.

    Important: Setting an unrecognized resource record type causes the configuration to treat the record type as the only default record type for one-off NODATA. 

    For example:

    modify /sys db  dnssec.nsec3underapextypesbitmap value "a aaaa txt rrsig"
