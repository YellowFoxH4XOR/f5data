K2325: 3-DNS may display objects with an unusable (gray) status indicator

Topic

A gray ball next to an object indicates that the 3-DNS Controller cannot use that object for load balancing decision. Objects most commonly marked as gray are routers that are defined for use by BIG-IP. One router should be used as a default and marked green; all others should be marked as gray.

Note: This does not apply to BIG-IP Link Controllers, which are designed to use multiple routers simultaneously. When using a BIG-IP Link Controller, all available routers should be marked green.

An object in a 3-DNS wideip.conf configuration will also be marked gray if it meets any of the following criteria:

  • It is a router object that is defined inside a datacenter and the datacenter does not contain any defined BIG-IP or 3-DNS servers.
  • It is not the first router object that was defined inside a datacenter and the datacenter does not contain any one of the following:
    • A 3-DNS module plus a BIG-IP/3-DNS combination product
    • A BIG-IP Link Controller module plus a BIG-IP/3-DNS combination product
    • A BIG-IP Link Controller
  • It is an object that has a parent marked as gray. For example, if a router has a gray status, all virtual servers that depend on that router will also be marked as gray.
  • The object is configured on a system other than a 3-DNS, BIG-IP, or BIG-IP Link Controller.

Because 3-DNS attempts to use automatic discovery and configuration for F5 devices after installation or upgrade, it is possible that 3-DNS will gather conflicting configuration objects. This can also result in gray objects in the configuration. For more information, refer to the following Solutions.

  • K3392: Resetting the status of virtual servers that were marked gray after running the 3-DNS auto-discovery process
  • K3776: Known Issue: Discovery and automatic configuration may occur even when it is globally disabled
  • K3777: Addresses used by discovery and automatic configuration
