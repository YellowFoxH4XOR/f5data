Known Issue

This is the result of a known issue. In rare cases, AHA hardware compression can stall on the BIG-IP LTM system. As a result, data compression occurs in the software, which causes the system memory usage to climb. The AHA compression card still processes compression streams, but at a degraded level.

For example, you can use the following command to view the compression statistics for soft_sync and aha_offload categories:

b compress stats

The b compress stats command produces the following output:

VIRTUAL COMPRESSION STATISTICS -- soft_sync
bytes (pre, post, queued) = (1.181G, 339.3M, 0)
streams (cur, tot) = (1, 23913)
VIRTUAL COMPRESSION STATISTICS -- aha_offload
bytes (pre, post, queued) = (513.8M, 223.9M, 1.323M)
streams (cur, tot) = (45, 12165)
VIRTUAL COMPRESSION STATISTICS -- soft_offload
bytes (pre, post, queued) = (0, 0, 0)
streams (cur, tot) = (0, 0)

F5 Product Development tracked this issue as CR77431 and it was fixed in BIG-IP LTM 9.3.1, 9.4.8, and 10.1.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.0-HF3 issued for BIG-IP 9.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
