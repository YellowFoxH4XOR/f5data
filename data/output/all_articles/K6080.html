Issue

When the BIG-IP system does not have enough memory required to execute a user space process, you may observe the following error message at the console:

bigmsg2_switch: out of memory

Although there are a number of reasons the BIG-IP system may not have sufficient memory, one common cause is the software configuration for the serial port.

By default, the serial port is handled by the init process, which may over-use system resources when redirecting output to the /dev/null file. If you experience any of the following symptoms in addition to receiving the error message mentioned previously, the serial port terminal software is a likely cause:

  • The following message appears in the /var/log/secure log file:

    init: getty repeating too quickly on /dev/console sleeping

  • Two init processes sometimes run simultaneously and each of the init processes will use a significant amount of memory.

If the serial port terminal software is the cause of the low memory condition, you can correct the issue by performing the following procedure:

  1. Edit the /etc/ttys file.
  2. Find the line that appears similar to the following example:

    tty00 "/usr/libexec/getty pccons" ibmpc3 on secure

  3. Modify the line by replacing the word on with in. For example:

    tty00 "/usr/libexec/getty pccons" ibmpc3 in secure

When the status field is set to on, the serial line is managed by the init process. When the status field is set to in, the serial line is managed by the getty daemon, gettyd. The getty daemon directs output to the /dev/null file instead of waiting to write to a console that is not live.
