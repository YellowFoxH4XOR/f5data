Description

Requests to BIG-IP ASM may be blocked with the violation "Request length exceeds defined buffer size" when an HTTP request exceeds the configured buffer limit. The default value for long_request_buffer_size is 10MB with an upper limit of 30 MB; requests larger than this (such as 35MB) will trigger this violation and be blocked.

Environment

  • ASM
  • Request Length

Cause

BIG-IP ASM enforces a hard-coded maximum on the request buffer size (long_request_buffer_size). This value cannot be set above the product’s maximum (typically 30MB). Requests exceeding this limit are blocked by ASM regardless of other configuration settings. Additionally, parsing binary data with ASM can result in false positives and increased resource usage because ASM is not designed for binary payloads.

Recommended Actions

To overcome this issue the easiest option is to disable the relevant violation from the Learning and Blocking settings of the security policy since the request length is more than the maximum allowed value thar can be configured for long_request_buffer_size.

Alternatively and since the above is more broad, you can be more explicit by configuring an irule to disable the violation for a specific URI. Example:

when ASM_REQUEST_DONE {
if {[ASM::violation names] contains "VIOLATION_REQUEST_TOO_LONG" and [string tolower [HTTP::uri]] contains "/yourURI"}
{
ASM::unblock
log local0. "ASM unblocking [HTTP::uri]"
}
}
