Known Issue

This is the result of a known issue. In certain situations, use of the plugin iRule commands in an iRule can cause a memory leak.

This issue is know to occur when the <plugin>::metadata or <plugin>::disable commands are used in an iRule that is associated with a Client SSL virtual server. When the virtual server processes traffic, the plugin subsystem leaks a small amount of memory.

The memory leak can be observed by viewing the Configuration performance graphs over time, or by watching the bigpipe memory | grep plugin command output over time. If the plugin subsystem is leaking memory, you will observe a gradual rise in memory utilization. For example, the following TMM memory output shows that the plugin subsystem is consuming more than 350 MB of memory:

SUBSYSTEM allocated max_allocated held size tot_allocs cur_allocsplugin
370373544 370570469 370373544 1 255231801 29587197

F5 Product Development tracked this issue as ID 225559 (formerly CR139680) and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Additionally, this issue has been fixed in BIGIP-10.1.0-3402.0-HF2, which has been issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes on systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.
