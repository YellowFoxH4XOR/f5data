Issue

Old Behavior

In versions prior to BIG-IP 13.1.0, local traffic policies use ssl-persistence in the requires stanza for the client-side and server-side events.

New Behavior

Beginning in BIG-IP 13.1.0, the local traffic policies support more framework events than before. When a policy requires SSL persistence, depending whether the events involved are on the client side or the server side, the policy uses the requires stanza to include the appropriate aspect of persistence.

For example, in BIG-IP 13.1.0, when an active policy uses the ssl-client-hello event and ssl-server-handshake event, the ssl-persistence requirement is client-ssl and server-ssl. The requires stanza appears similar to the following example:

requires { client-ssl server-ssl }

During software upgrade, when updating BIG-IP LTM policies that already contained these values, the system changes them as follows:

  • If a policy condition or action references the ssl-client-hello and ssl-client-serverhello-send events, the system changes the requires stanza to client-ssl.
  • If policy condition or action references the ssl-server-hello and ssl-server-handshake events, the system changes the requires stanza to server-ssl.
  • If the policy condition or action references both a client and a server event, the system changes the requires stanza to reflect both client-ssl and server-ssl. For example, client-ssl server-ssl.

F5 Product Development tracked this change as ID 682482.

Impact

A BIG-IP configuration containing a local traffic policy with a requires stanza is automatically updated to the new specific requires aspect of persistence during software upgrade to BIG-IP 13.1.0.
