Known Issue

Origin Address List entries may be lost when you modify a SNAT.

This issue occurs when all of the following conditions are met:

  • You have configured a SNAT with both IPv4 and IPv6 Origin Address List entries.
  • You have modified the SNAT using the BIG-IP Configuration utility.

When you use the BIG-IP Configuration utility to view or modify a SNAT that is configured with both IPv4 and IPv6 Origin Address List entries, the system displays only one type (IPv4 or IPv6). As a result, if you click the Update button, the SNAT is saved with only the displayed IPv4 or IPv6 address list.

For example, if you have a SNAT named DualStackSNAT configured with IPv6 (::/0) and IPv4 (0.0.0.0/0) origin addresses, as shown in the following example, and you view this SNAT in the Configuration utility, the system displays only the IPv6 (::/0) in the Origin Address List; the system does not display the IPv4 (0.0.0.0/0) entry.

ltm snat DualStackSNAT {
    automap
    origins {
        ::/0
        0.0.0.0/0
    }
}

If you click the Update button, the system saves the SNAT without the IPv4 (0.0.0.0/0) entry, as displayed in the following example:

ltm snat DualStackSNAT {
    automap
    origins {
        ::/0
    }
}

Impact

Connections from the removed Origin Address List entry may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Origin Address List for the affected SNAT contains an IPv4 or IPv6 address, not both. 
  • Connections from the removed addresses may fail.

Workaround

To work around this issue, you can create a separate SNAT for each IPv4 and IPv6 origin address.

For example:

ltm snat IPv4StackSNAT {
    automap
    origins {
        0.0.0.0/0 { }
    }
}

ltm snat IPv6StackSNAT {
    automap
    origins {
        ::/0 { }
    }
}
