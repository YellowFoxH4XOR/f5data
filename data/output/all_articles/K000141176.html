Description

This article explains the deprecation of the max_concurrent_long_request internal parameter in F5 ASM. While it remains technically possible to use this parameter, F5 no longer recommends its use. This article outlines the reasons behind its deprecation, the recommended alternatives, and the implications for users.

 

Environment

BIG-IP system with ASM running on versions 12.0 and above.

 

Cause

The max_concurrent_long_request parameter was historically used to set the maximum number of concurrent long requests based on user-defined values. However, following the implementation of Bug ID 445508, the system now calculates the maximum number of concurrent long requests dynamically based on provisioned memory. This change was introduced to enhance performance and resource management.

Starting from version 12.0, the max_concurrent_long_request variable has been hidden from the GUI, making it inaccessible to customers in standard configurations. Although it can still be modified via the command line, this practice is strongly discouraged.

 

Symptoms

Users may encounter the following symptoms when relying on the max_concurrent_long_request parameter:

  • The maximum number of concurrent long requests does not align with the expected values when max_concurrent_long_request is set to a specific number.
  • Adjustments to long_request_buffer_size and long_request_mem_percentage may not yield the anticipated increase in available long request buffers if max_concurrent_long_request is set to a non-zero value.

Recommended Actions

  • If the max_concurrent_long_request parameter was previously configured, please set it to 0 to enable the system to dynamically calculate the maximum number of concurrent long requests based on the provisioned memory and relevant settings.

Additional Information

The removal of reliance on the max_concurrent_long_request parameter aligns with F5's ongoing efforts to streamline performance and resource management in ASM. The changes were motivated by the need to adapt to modern application requirements and improve overall efficiency. Users should refer to Knowledge Base article K01235989 for more detailed information on the new calculation formula for concurrent long requests.
