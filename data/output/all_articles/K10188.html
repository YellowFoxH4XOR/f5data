Known Issue

This is the result of a known issue. When you upgrade from BIG-IP version 9.3.x or 9.4.x to version 10.0.1 and the configuration contains a cookie hash persistence profile(s) with the timeout set to zero, the configuration does not load and the BIG-IP system generates an error message that appears similar to the following example:

BIGpipe persistence profile creation error: 01070695:3: timeout immediate (or 0) invalid for persist mode given in persist profile <name>.

This issue occurs when the cookie hash profile was configured in the earlier version with the default timeout value of zero, and the system was upgraded to version 10.0.1 which does not accept the zero timeout value.

F5 Product Development tracked this issue as ID 222467 (formerly CR119976), and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator and WOM release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-342.0-HF1 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes, refer to in K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

You can work around this issue by editing the /config/bigip.conf file using a text editor to add a timeout value to any cookie hash persistence profile(s).

For example:

profile persist cookiehash {
defaults from cookie
mode cookie
timeout 180
cookie mode hash
cookie name "blah"
cookie hash offset 0
cookie hash length 24
}
