Description

  • You can observe on BIG-IP version 16.1.2.2 or above, that traffic coming to Virtual Server with SSL persistance profile gets TCP RST to TLS1.3 Client Hello with session-ID.
    TLS handshake fails with [F5RST: empty persist key] reason.

Environment

  • BIG-IP LTM
  • After system upgrade to 16.1.2.2 or above
  • Virtual server using SSL persistence and TLS1.3
  • The client-hello message sent to BIG-IP contains a session-ID

Cause
SSL persistence is not compatible with TLS1.3 since session-id based resumption was made obsolete in TLS1.3 (see RFC8446 on section 2.2).
The behavior has changed for TLS1.3 connection on v16.1.2.2 and later versions.

Recommended Actions
As a workaround you can use one of below methods:

  1. Disable SSL persistence or use another type of persistence.
  2. Disable TLSv1.3 and use TLSv1.2.
    K01770517: Configuring the cipher strength for SSL profiles (14.x - 17.x)
  3. Keep SSL Persistence profile and attach below iRule to affected Virtual Server, which would check if SSL handshake is done with TLSv1.3.
    If it does, then iRule will use source_address persistence for that session. For any other TLS version (not TLS1.3) it will use SSL persistence.

when CLIENTSSL_HANDSHAKE {
   if { [SSL::cipher version] eq "TLSv1.3" } {
      persist source_addr 255.255.255.255 360
   }
   else {
      persist ssl
      }
}
Note: This iRule method requires that SSL persistence profile will be attached to the Virtual Server.
You don't need to attach any source-address persistence profile to the Virtual Server, it will be done automatically when the condition in the iRule are met.
