Description

The content of external data-group is not returned via API calls.

Environment

  • BIG-IP
  • Rest API
  • External Data-Group

Cause

The content of external data-groups is not part of the BIG-IP configuration - the configuration instead references a file in the filestore, which mcpd reads in during configuration load.   When querying the details of the external data-group, only the meta details of the object are returned, and not the content of the filestore.   By comparison, internal data-groups are stored in the BIG-IP configuration, and the content is returned.

 curl -vk -u admin https://localhost/mgmt/tm/sys/file/data-group/ext_dg_string_file

...

< HTTP/1.1 200 OK

...

{"kind":"tm:sys:file:data-group:data-groupstate","name":"ext_dg_string_file","fullPath":"ext_dg_string_file","generation":795,"selfLink":"https://localhost/mgmt/tm/sys/file/data-group/ext_dg_string_file?ver=16.1.3.1","checksum":"SHA1:63:xxxxxxxxxxxxxxxxxxxxxxxxx","createTime":"2023-06-28T07:43:56Z","createdBy":"root","lastUpdateTime":"2023-06-28T07:43:56Z","mode":33188,"revision":1,"separator":":=","size":63,"sourcePath":"file:/var/tmp/ext_dg_string.txt","type":"string","updatedBy":"root"}

Recommended Actions

This is expected behavior, because the BIG-IP doesn't store the external file content in the configuration files. The behaviour is the same as would be seen in the BIG-IP management GUI, and in the traffic management shell (tmsh) commandline interface  ('list ltm data-group external ...')
