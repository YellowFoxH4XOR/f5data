Description

BIG-IP may not sent logs to a remote logging server specified in syslog-ng configuration.
E.g. pool member status change of going up or down may not bee seen on a remote syslog server.

Environment

For the issue to be triggered, the configuration need to match all condition below

  • Remote syslog-ng logging is configured
  • Remote High-Speed Logging (HSL) is configured
  • Remote HSL has filter configured

Cause

BIG-IP has two independent methods of remote logging controlled by syslog-ng and errdefsd daemons. Native Linux daemons like logger, syslong-ng, systemd, agetty, crond etc are controlled by syslog-ng. BIG-IP daemons such as mcpd, tmm send their logs via errdefsd by means of HSL.

By default errdefsd gets logs from BIG-IP daemons and writes them into log files and after that sent logs to the syslog-ng daemon if there is any specified in remote syslog-ng configuration.

If you have remote HSL logging configured along with an HSL filter, then errdefsd gets logs from BIG-IP daemons and passes them though HSL logs. If logs match the filter, they sent to the configured HSL destination.  In that case logs are not written into log files and not sent via syslog-ng.

The configuration below is an example of remote HSL logging where  all logs with level Notice or higher from BIG-IP daemons are send via HSL publisher.
  
   sys log-config filter /Common/my_log_filter {
       level notice
       publisher /Common/my_publisher
   }
   sys log-config publisher /Common/my_publisher {
       destinations {
           /Common/my_log_destination{ }
       }
   }
   sys log-config destination remote-high-speed-log /Common/my_log_destination {
       pool-name /Common/my_log_pool
       protocol udp
   }

Recommended Actions

The behaviour is expected and by design. To send log messages by means of syslog-ng, HSL filters need to be tuned and desired logs should not match HSL filter
