Description

Article describes how to create HTTP/S DNS pool monitor. 

Environment

  • DNS pool monitoring
  • DNS HTTP/S Health check
  • DNS Load Balancer Health 

Answer/Recommended Actions

General instruction. how and where create DNS health check is available here: "Create Health Check"  section - https://docs.cloud.f5.com/docs-v2/dns-management/how-to/configure-dns-load-balancer.

When you are setting HTTP/S monitoring, there are important settings to configure.

Send String

This is a payload that we send in HTTP request to the customer. By default it's:

HEAD / HTTP/1.0\r\n\r\n 

You should edit send string. By default, we will send HTTP request as above, without any headers (even host header).  

Example correct HTTP 1.1 send string:

GET /dns-check HTTP/1.1\r\nHost: example.com\r\n\r\n

You can add more headers if needed.

 

Receive String

Regular expression used to match against the response to the health check's request. Mark node up upon receipt of a successful regular expression match. Uses re2 regular expression syntax.
 
As receive string, you can use part of the expected response request e.g. "200" or "Health OK". Receive string will search for inserted string in response. If response will not contain it, we will mark pool as down. 
 

Virtual Host

For HTTP or HTTPS health checks, configure the Virtual host setting by selecting one of the following options:

  • Disable Virtual Host (Default): Does not set a virtual host or use SNI. Select this option when the health check target is addressed directly and does not require an SNI value.

  • Inherit From Load Balancer FQDN: Automatically uses the associated DNS Load Balancer FQDN as the virtual host for SNI. This option keeps the SNI value synchronized with the load balancer domain and eliminates the need to manually specify the hostname. This is the recommended option for CNAME pools associated with a DNS Load Balancer.

  • Enable Virtual Host: Lets you specify the hostname to use as the SNI value. Select this option when the required SNI value differs from the load balancer FQDN.

Additional Information

HTTPS monitor requires valid TLS certificate and Extended Master Secret (EMS) extension (RFC 7627). 

If you will use self-sign certificate or a certificate without valid chain of trust, monitor will fail to establish TLS handshake and will show error: "Error: Encountered Internal Error for Monitor from at least One Region". 

HTTPS monitor operates in FIPS mode, which strictly requires the for all TLS 1.2 connections.

If your server do not support currently EMS in TLS handshake,  you have 2 options:  

1. Option 1 (Recommended): Upgrade to TLS 1.3

  - TLS 1.3 includes EMS-equivalent key protection by default

  - No additional configuration needed

2. Option 2: Enable Extended Master Secret (EMS) for TLS 1.2

  - Update the server's TLS library (OpenSSL, NGINX, HAProxy, etc.) to a version that supports RFC 7627

  - Ensure EMS is enabled in the TLS configuration

How the customer can verify their server's EMS support:

 openssl s_client -connect <server_ip>:443 -tls1_2 

Look for: `Extended master secret: yes` (compliant) vs `Extended master secret: no` or absent (non-compliant)

 

Monitor interval

The health monitor interval is 30 seconds and the timeout value is 90 seconds (i.e. 3x30 seconds). If an endpoint is identified as down, it will be marked as up as soon as it starts to respond correctly again. Configuring health monitor interval and timeout values is currently not supported.
