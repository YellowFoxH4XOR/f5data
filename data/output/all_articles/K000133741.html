K000133741: merge_slashes directive not working

Type
Support Solution
Published
2023-04-29
Updated
2025-02-07
Applies to
  • NGINX Products
  • NGINX Plus: R15
Source
https://my.f5.com/manage/s/article/K000133741

Description

  • You read about "merge_slashes " directives as a good solution in removing additional consecutive slashes from a request.
  • You configured and deployed your Nginx as a proxy with proxy_pass directives pointing to an upstream along with a location block to accept the incoming request.
  • For one reason or another, Nginx receives incorrect request having several slashes at their beginning and in between like ////our-service/... instead of /our-service/...).
  • But you note the "merge_slashes" directive failing to remove these additional slashes and thereby Nginx failing to process request resulting in 404 HTTP response
2023/04/12 12:27:17 [error] 799518#799518: *546544 "/data/www/alpha/index.html" is not found (2: No such file or directory), 
                            client: 127.0.0.1, 
                            server: example.com, request: 
                            "GET ///alpha/// HTTP/1.1", host: "example.com:8050"

Environment

  • Nginx Plus
  • merge_slashes directives

Cause

  • The presence of white space or other character between slashes

Recommended Actions

  • "merge_slashes" directive is enabled by default and for it to be effective, slashes must be adjacent to each other
  • Verify and validate adjacent slashes are free of any character between them

Additional Information

  • Lets assume we have the below configuration
    • Lab setup -- nginx conf
        server {
            listen       8050 default_server;
            server_name  example.com;
            access_log /var/log/nginx/test.access.log custom;
            error_log /var/log/nginx/test.error.log info;

        location /alpha/merge/check {
            resolver 192.168.1.1;
            proxy_pass https://my.example.com/coffee;
                }
            }
  • Request and response without any additional slashes
    • curl http://example.com:8050/alpha/merge/check
        Request: GET /alpha/merge/check HTTP/1.1
         Status: 200
         Request_URI: /alpha/merge/check
         Host: example.com
         Client_IP: 127.0.0.1
         Proxy_IP(s): 127.0.0.1
         Upstream_IP: 192.168.1.2:443
  • Request and response with additional slashes
    • curl http://example.com:8050///alpha//////merge////check
       Request: GET ///alpha//////merge////check HTTP/1.1
        Status: 200
        Request_URI: ///alpha//////merge////check
        Host: example.com
        Client_IP: 127.0.0.1
        Proxy_IP(s): 127.0.0.1
        Upstream_IP: 192.168.1.2:443
  • Request and response with additional slashes and space in between slashes
    • curl http://example.com:8050///alpha/// ///merge////check
       Request: GET ///alpha/// HTTP/1.1
       Status: 404
       Request_URI: ///alpha///
       Host: example.com
       Client_IP: 127.0.0.1
       Proxy_IP(s): 127.0.0.1
       Upstream_IP: -
  • As shown above, having a single space between these slashes results in invalidating the "merge_slashes" directive
  • More importantly, the presence of a white space between these slashes causes Nginx to consider the request to mean something completely different than intended and points to a none existing directory, which results in HTTP 404 response.
  • In conclusion, Nginx "merge_slashes" directive merge these adjacent slashes but any hidden white space or other character could result in an undesired outcome as shown above
