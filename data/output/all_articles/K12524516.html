Description

When the Network Access (VPN) traffic is high, the CPU usage becomes higher causing the issue mentioned in K10095.

Important: Beginning in APM Clients 7.2.6, BIG-IP network access VPN compression (client and server side) is deprecated. For more information, refer to K000158915: BIG-IP network access VPN compression deprecated from APM Client 7.2.6.

Environment

  • BIG-IP APM
  • Network Access (VPN)
  • Enable compression
  • No hardware compression capability

Cause

This is expected result. Compression will save the bandwidth. If there is no hardware compression capability on the BIG-IP APM system, CPU resources will be used for compression leading to high CPU usage. Meanwhile, the client system will use more CPU resources too.

Recommended Actions

Please fully understand the advantages and disadvantages of using the Compression feature in the BIG-IP APM Network Access resource to balance the CPU resource and bandwidth of the system. Configure the Network Access resource to maximize resource usage and performance.

  • Please review the hardware datasheet of the BIG-IP system and article K13469: Determining the compression capability of your BIG-IP system (11.x-13.x), to find the capability for compression of the system.
  • Please investigate the traffic type suitability for GZIP compression in the VPN tunnel. The compression feature in a BIG-IP APM network resource uses GZIP for compression. If the traffic is plain text like text files or telnet, then enabling compression will save network throughput, as plaintext data has high compression ratios. For encrypted HTTP (HTTPS), images and pdf files which are already compressed, enabling GZIP compression may increase the size of the data and increase CPU usage instead.
    Note: Encrypted traffic cannot be compressed.  Only plain-text data transmitted over the VPN tunnel can be compressed.
  • To disable GZIP Compression in a network access resource, perform the following procedure:
  1. Login to the Configuration utility.
  2. Go to Access > Connectivity/VPN > Network Access (VPN)

    Note: For versions prior to BIG-IP 13.x, go to Access Policy > Network Access

  3. Click the name of the affected network access resource
  4. Click Network Settings
  5. For Compression, select No Compression.
  6. Click Update.
Note: The Connectivity Profile's Network Access Compression Settings are applicable only when GZIP Compression is enabled in the Network Access (VPN) settings

Additional Information

Below is an example.
The device is a i2600. 

  • Before the 14 Feb, compression was enabled. 
  • After 14 Feb, compression was disabled.
  • From the 15 Feb to 16 Feb, it was the weekend and most users were not connected to the VPN.

Note for the working days, the Network Access Throughput were almost the same, the Active Network Access Connections was also almost the same, but the CPU usage was significantly lower after compression was disabled.
