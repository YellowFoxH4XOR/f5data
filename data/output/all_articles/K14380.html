Known Issue

Using the sharedvar declaration in an iRule may cause the Traffic Management Microkernel (TMM) to leak memory.

This issue occurs when the following condition is met:

  • You are using the sharedvar declaration in an HTTP_REQUEST event.

Impact

Over time, the BIG-IP host may run out of memory, causing performance impacts and eventual failure of the host.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Available TMM memory steadily decreases over time.

    You can monitor TMM memory usage by using the tmstat command, or the following Traffic Management Shell (tmsh) command:

    tmsh show sys memory

  • The sweeper is triggered, as indicated by error messages in the /var/log/ltm file. The error messages appear similar to the following examples:

    tmm tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode activated. (117504/138240 pages)
    tmm tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode deactivated. (117503/138240 pages)

  • TMM crashes due to lack of available memory.
  • You notice a gradual degradation in performance.

Resolution

Status

F5 Product Development has assigned ID 414457 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, avoid using the sharedvar declaration in an HTTP_REQUEST event. For example, you may be able to move sharedvar declarations from the HTTP_REQUEST event to the CLIENT_ACCEPTED event.
