Known Issue

The BIG-IP vCMP system may experience instability when using the default value for the iCall periodic handler interval.

This issue occurs when the following condition is met:

  • You create an iCall handler without an interval, or modify the value to 0 (the default value).

    For example, the system inserts a default interval 0 into the following iCall script if you create the script without an interval:

    sys icall handler periodic backup-ucs {
    app-service none
    arguments none
    description none
    first-occurrence 2014-03-14:09:22:36
    interval 0
    last-occurrence 1969-12-31:15:59:59
    script test-backup
    status active
    }

Impact

The BIG-IP system may become unstable and cause the evrouted process to restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system may become unstable.
  • The evrouted process may restart and consume 100 percent of the CPU.

Workaround

To work around this issue, you can specify an interval value of 1 or greater for the iCall periodic handler. To do so, perform the following procedure:

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Use the following command syntax to modify the iCall periodic interval:

    modify sys icall handler periodic <handler_name> script <script_name> interval <interval_value>

    For example, to modify the interval to 1 for the periodic handler called my_handler1, type the following command:

    modify sys icall handler periodic my_handler1 script my_script interval 1

  3. Save the configuration changes by typing the following command:

    save /sys config

Impact of workaround: Performing the following procedure should not have a negative impact on your system.
