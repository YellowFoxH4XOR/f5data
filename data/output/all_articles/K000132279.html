Description

A custom bot signature is detected accurately but it triggers an Alarm even though it is meant to be legal.

 

The custom signature example:

 

security bot-defense signature /Common/<name> {

category "/Common/Mobile App without SDK"

risk low

user-agent {

search-string "<string>"

}

}

 

Environment

  • Bot Signature Category: Mobile App without SDK
  • Violation: Malicious Bot
  • Bot Categories:

 

Cause

The alarm for Malicious bot is triggered for Microservices Mitigation.

 

 

In the Micorservices setting, mitigation setting for Malicious Bot is set to Block.

 

Note: In the example shown above, an Alarm is triggered as the Bot Profile is in Transparent mode.

 

Recommended Actions

For custom bot signature ( with Category: Mobile App without SDK ), to take precedence, an iRule may be used.

 

Impact of Procedure: F5 recommends testing the iRule in a controlled environment before deploying it to Production.

 

when BOTDEFENSE_ACTION {

 if { ( ([string tolower [HTTP::header User-Agent]] contains "<user_agent>") &&

     ([HTTP::uri] contains "<URL>") ) } {

   BOTDEFENSE::action allow

   }

}

 

Additional Information

Mitigation action is determined by consulting the configuration according to the following precedence order:

 

  1. Whitelist
  2. DoS Attack Mitigation Mode settings
  3. Microservices
  4. Verified API Access Enforcement settings
  5. Bot Defense Profile Mitigation settings
