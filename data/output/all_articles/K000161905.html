Description

When attempting to retrieve metrics from the F5 Telemetry Streaming (TS) pullconsumer endpoint using an HTTP GET request (e.g., via Postman), the server fails to return the expected data. Instead, it returns a 500 Internal Server Error.

You may see the following error:

  • java.net.ProtocolException: status:500, body:{\"code\":500,\"error\":\"Bad status code: 401 F5 Authorization Required for https://<hostname>:443/mgmt/shared/authn/login\",\"message\":\"Internal Server Error\"}

Environment

  • BIG-IP LTM
  • Telemetry Streaming

Cause

The root cause of this error is an authentication failure resulting from an incorrectly passed password in the initial Telemetry Streaming declaration (sent via a POST request).

In the JSON declaration, under the credentials section:

        "username": "<username>",
        "passphrase": {
            "cipherText": "<password>"
        },

Recommended Actions

  • Verify the JSON declaration: Check the original payload sent to the F5 via POST that contains the Telemetry Streaming configuration. Focus specifically on the "cipherText" section.
  • Escape special characters: Ensure that all problematic special characters in your password are properly formatted according to JSON standards. For example, a quotation mark " inside the string must be preceded by a backslash: \".
  • If escaping characters in your API client continues to cause parsing issues, the quickest workaround is to change the dedicated user's password to one that uses safer characters (e.g., uppercase/lowercase letters, numbers, and special characters that do not require escaping in JSON, such as _ or -)
