K000159906: BIG-IP GTM/DNS iQuery Connection Failure Due to Missing Extended Key Usage (EKU) Extensions in Device Certificates

Type
Support Solution
Published
2026-02-05
Updated
2026-02-24
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.1
Source
https://my.f5.com/manage/s/article/K000159906

1. Description

LTM virtual servers appear up locally but are shown as down on the GTM (BIG-IP DNS). iQuery connections between GTM and LTM devices fail after replacing expired device certificates with third-party CA-signed certificates. The following error messages appear in /var/log/ltm:

  • "big3d SSL cert EXPIRED at IP <IP_ADDRESS>"
  • "SSL error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed"
  • "SSL error:14094413:SSL routines:ssl3_read_bytes:sslv3 alert unsupported certificate"

Attempts to use bigip_add to exchange certificates fail, and only a subset of LTM virtual servers may appear available on the GTM even when all are operational on the LTM. The issue persists even after certificate renewal if the replacement certificates lack required Extended Key Usage (EKU) extensions.

2. Environment

  • BIG-IP DNS (GTM) versions 17.1.1 and later
  • BIG-IP LTM versions 17.1.3 and later
  • Platforms: F5-BIG-R5800, C129, and similar
  • iQuery mesh between GTM and LTM devices
  • Device certificates expired or replaced with third-party CA-signed certificates
  • Certificates missing clientAuth and/or serverAuth EKU extensions
  • Certificate store may contain duplicate, expired, or mismatched certificates
  • Recent certificate renewal or replacement activities

3. Cause

Expired big3d SSL device certificates on LTM systems, or replacement with third-party CA-signed certificates that lack the required Extended Key Usage (EKU) extensions. iQuery connections require both clientAuth (SSL Client) and serverAuth (SSL Server) EKU extensions for mutual authentication. The big3d process operates as a server (requiring serverAuth), while the gtmd process operates as a client (requiring clientAuth). Certificates missing either extension prevent successful iQuery communication, resulting in GTM marking LTM virtual servers as down. Additionally, duplicate or expired certificates in the trusted certificate store can cause partial visibility issues where only some virtual servers appear available.

4. Answer/Recommended Actions

Verify Certificate EKU Extensions

  1. Check if the current device certificate includes both required EKU extensions:
  2. openssl x509 -noout -purpose -in /config/httpd/conf/ssl.crt/server.crt | grep -iE 'client|server'
  3. The output must show "Yes" for both SSL client and SSL server:
  4. SSL client : Yes
  5. SSL client CA : No
  6. SSL server : Yes
  7. SSL server CA : No

If Using Third-Party CA Certificates

  1. Request new certificates from your CA with both clientAuth and serverAuth EKU extensions explicitly included in the certificate template.
  2. Verify the new certificate before installation using the command in step 1.
  3. Follow K9114 to create and install the new device certificate with proper EKU extensions.

If Using Self-Signed Certificates (Recommended)

  1. Generate new self-signed certificates (which include required EKUs by default) following K9114.
  2. Install the new certificates on all GTM and LTM devices.

Clean Up Certificate Store

  1. Remove duplicate or expired certificates from the trusted certificate store on all devices:
  • Navigate to System > Certificate Management > Device Certificate Management > Device Trust Certificates
  • Navigate to DNS > GSLB > Servers > Trusted Server Certificates
  • Delete any old, expired, or duplicate certificates

Restart Services and Exchange Certificates

  1. Restart httpd, gtmd, and big3d services after certificate updates:
  2. bigstart restart httpd
  3. bigstart restart gtmd big3d
  4. Note: Restarting gtmd and big3d will temporarily disrupt iQuery connections. Perform during a maintenance window.
  5. Run bigip_add on GTM devices to exchange certificates with LTM devices:
  6. bigip_add <LTM_IP_address>
  7. or
  8. bigip_add <username>@<LTM_IP_address>
  9. Verify iQuery connectivity:
  10. tmsh show gtm iquery
  11. Confirm that all connections show "State: connected"
  12. Verify virtual server status on GTM to ensure all LTM virtual servers are now visible and showing correct status.

5. Additional Information

Self-Signed vs. Third-Party CA Certificates

  • Self-signed certificates include both clientAuth and serverAuth EKU extensions by default and are the recommended approach for iQuery mesh communication.
  • Third-party CA certificates must explicitly include both EKU extensions. Contact your CA to ensure the certificate template includes these extensions.
  • If you are planning to use self-signed certificates, F5 recommends creating the self-signed certificates with extended expiration dates (10 years) to minimize certificate management overhead.

Industry Changes Affecting Public CA Certificates

Google and other public Certificate Authorities are requiring separation of serverAuth and clientAuth roots, which prevents using a single public CA certificate with both EKU extensions. This industry change may impact the use of public CA-signed device certificates for GTM/DNS iQuery communication. Organizations should plan to use either:

  • Self-signed certificates
  • Private/internal CA certificates that support both EKU extensions
  • Separate certificate infrastructure for iQuery communication

Partial Virtual Server Visibility

When only some LTM virtual servers appear on the GTM while all are operational on the LTM, this typically indicates:

  • Duplicate certificates in the trusted certificate store with the same x509 Subject
  • GTM matching certificates by x509 Subject in order from top to bottom
  • The first matched certificate being expired or invalid
  • Removing duplicate/expired certificates resolves this issue

Certificate File Locations

  • Device Certificate: /config/httpd/conf/ssl.crt/server.crt
  • Device Key: /config/httpd/conf/ssl.key/server.key
  • Trusted Device Certificates: /config/big3d/client.crt
  • Trusted Server Certificates: /config/gtm/server.crt
