Description

NGINX Ingress Controller does not support configuring HTTP Strict Transport Security (HSTS) parameters directly via the ConfigMap for VirtualServer (VS) and VirtualServerRoute (VSR) resources. The following ConfigMap keys are not supported for VS/VSR: hsts, hsts-max-age, hsts-include-subdomains, hsts-behind-proxy, redirect-to-https, and ssl-redirect. Attempts to set these parameters in the ConfigMap for VS/VSR will have no effect.

Environment

  • Product: NGINX Ingress Controller
  • Configuration: Use of VirtualServer and VirtualServerRoute custom resources
  • Platform: Kubernetes (using NGINX Ingress Controller CRDs)
  • Customization via ConfigMap for VS/VSR resources

Cause

HSTS-related ConfigMap keys are not supported for VirtualServer and VirtualServerRoute resources. This limitation is documented in the official NGINX Ingress Controller documentation. The design currently restricts these parameters to Ingress resources and does not expose them for VS/VSR.

Recommended Actions

  • Workaround:
    HSTS can be implemented for VS/VSR using the server-snippets field in the ConfigMap. Example configuration:

    data:
      server-snippets: |
        proxy_hide_header Strict-Transport-Security;
        set $hsts_header_val "";
        if ($scheme = 'https') {
          set $hsts_header_val "max-age=31536000";
        }
        add_header Strict-Transport-Security "$hsts_header_val" always;
        if ($scheme = 'http') {
        return 302 https://$host$request_uri;
      }

    This snippet adds the HSTS header for HTTPS requests and redirects HTTP to HTTPS.
  • Ingress Resource Alternative:
    HSTS can be configured for Ingress resources using annotations as described in the NGINX Ingress Controller documentation.
  • Future Consideration:
    Support for HSTS parameters in VS/VSR is under review for future product implementation (internal tracking ID: NIC-E-241). Monitor product release notes for updates.
