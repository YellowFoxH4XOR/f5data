K00114232: Websockets application failing after upgrade to 15.x

Type
Support Solution
Published
2020-09-24
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.X, 15.0.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.X.X, 15.1.2, 15.1.1, 15.1.0, 15.0.1, 15.0.0, 15.1.3
Source
https://my.f5.com/manage/s/article/K00114232

Description

Following upgrade to 15.x, you may notice Websocket application is no longer working.
This could be due to BIG-IP behavior where it chunks the HTTP response on the client_side.  For example:

> In server response to BIG-IP <
HTTP/1.1 101 Switching Protocols
Connection: Upgrade
Upgrade: websocket
Sec-WebSocket-Accept: n24az0LMz/oGGtSFH4Z982i6aV8=
Sec-WebSocket-Protocol: uint8utf8

> And, BIG-IP response to client <
HTTP/1.1 101 Switching Protocols
Connection: Upgrade
Upgrade: websocket
Sec-WebSocket-Accept: n24az0LMz/oGGtSFH4Z982i6aV8=
Sec-WebSocket-Protocol: uint8utf8
Transfer-Encoding: chunked                <----- BIG-IP adds this header on the client_side

Environment

  • The virtual server has 'rewrite' profile and 'HTTP' profile attached
  • HTTP profile response chunking is set to 'sustain'
  • Server response has no content-type header or if the header 'content-type' exists its value is not 'text/html' or 'text/css'

Cause

This issue is due to a change in behaviour (Bug ID 899097) introduced in 15.0 where chunking happens even if origin server response does not contain 'content-type' header or content-type header is set to anything except text/html or text/css.

Recommended Actions

You can work around this issue by modifying the Response Chunking to Unchunk in the HTTP profile.
  1. Go to Local Traffic > Profiles > Services > HTTP
  2. Click the HTTP profile applied to the Virtual Server processing the Client<->Server traffic
    Note: if the "default" HTTP profile is being used, create a custom HTTP profile
  3. Set Response Chunking = Unchunk
  4. Click Update/Finished
