K000132220: ASM Sync-Only using Auto Sync Requires Manual LTM Sync for Policy Creation, Deletion, and Import

Type
Support Solution
Published
2023-01-24
Updated
2025-12-17
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.7
Source
https://my.f5.com/manage/s/article/K000132220

Description

In use is a separate Device Service Cluster (DSC) for ASM/AdvWAF. It is setup to do an automatic sync to peers. Yet when you create a new policy or import a policy the Sync-Failover group for LTM and other modules also needs to be updated.

 

Environment

  • Create or import a new ASM/AdvWAF policy
  • Auto sync, save-on-auto-sync, ASM/AdvWAF policies, Sync-Only, Sync-Failover
  • ASM/AdvWAF, Device Service Cluster (DSC)

Cause

The question is not with the ASM sync, but with the Sync-Failover used by TMM to sync traffic/failover objects and links to files they need to reference.

 

The use of the Sync-Only for ASM, set to auto sync, and with save-on-auto-sync also set is normally the best way to go. This way only policy changes and such are sync'd and it does not effect TMM traffic/failover objects. Using a Sync-Failover would dictate that each time a policy got an update (for instance when the policy is set to auto learn) then the whole config including traffic/failover and non-traffic objects could be sync'd (By default, the BIG-IP does incremental synchronization unless it exceeds the incremental sync cache size of 1024KB. If that happens then it reverts to a full sync. This is not uncommon when ASM/AdvWAF is in use). This causes a lot of unnecessary overhead, and can bring about unintended consequences.

 

However, when you create a new policy or import a policy TMM needs to know how to reference the files it needs that are stored in a mysql database. That is done by creating a sort of link to the file it needs. That link for TMM, to understand and use it, has to reside in TMM. Also, that link that is created has to reside on all peers, so when created it effects traffic/failover objects and now a sync of the Sync-Failover DSC has to be done. That link is not updated each time there is a change in the ASM/AdvWAF policy, when a separate DSC is used for ASM/AdvWAF, only the policy is updated.

 

The data in the Sync-only only synchronizes configuration data not failover objects. Thus each time there is a policy change TMM failover objects are not effected.

 

So this is by design to ensure that failover objects (virtual servers, pools, etc) do not get effected each time there is a change to a non-failover object (a policy in the mysql database for instance).

 Recommended Actions

This is by design.
