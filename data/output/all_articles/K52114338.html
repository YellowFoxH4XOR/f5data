Security Advisory Description

In systemd through 233, certain sizes passed to dns_packet_new in systemd-resolved can cause it to allocate a buffer that's too small. A malicious DNS server can exploit this via a response with a specially crafted TCP payload to trick systemd-resolved into allocating a buffer that's too small, and subsequently write arbitrary data beyond the end of it. (CVE-2017-9445)

Impact

An unauthenticated remote attacker may be able to perform an out-of-bounds write to cause a denial of service (DoS) or conduct remote code execution.

Security Advisory Recommended Actions

If you are running a version listed in the Versions known to be vulnerable column, you can eliminate this vulnerability by upgrading to a version listed in the Versions known to be not vulnerable column. If the table lists only an older version than what you are currently running, or does not list a non-vulnerable version, then no upgrade candidate currently exists.

Mitigation

You may be able to leverage F5 products to provide mitigation options in the following non-exhaustive ways:

You can use the BIG-IP DNS Cache as a caching resolver for the affected Traffix system to prevent a malicious DNS server from sending malformed packets that allow buffer overflow. The BIG-IP DNS Cache has protections for malformed DNS responses built into the product. For more information, refer to the Configuring DNS Caching chapter of the BIG-IP DNS Services: Implementations guide (11.4.1 - 13.0.0) or the same chapter of the DNS Cache: Implementations guide (11.2.1).
