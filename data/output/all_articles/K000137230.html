K000137230: /Shared directory increasing on Secondary Big IQ where is working fine on Active Big IQ

Description

  • /Shared directory increasing on Standby Big IQ whereas working fine on Active Big IQ
  • df -h /shared is showing different % values for both Primary and Secondary CM
  • /shared/tmp/ contains im* folders consuming lot of space on /shared


Environment

  • BIG-IQ CM cluster
  • Secondary /shared used more than on primary device
  • /shared/tmp contains im* folders

Cause

Customer in the past, configured backup schedule for secondary node in the cluster wich cause backup failures

Due to this filesystem was filled with /shared/tmp/im*/ folders consuming a lot of space

Please refer to K92404505 : Unsuccessful UCS archive creation can fill the /shared partition


Recommended Actions

1. Remove backup schedule for Secondary CM node on primary from System > Backup & Restore > Backup Schedules

2. Clean up existing im folders from /shared/tmp/ following procedure in K92404505 : Unsuccessful UCS archive creation can fill the /shared partition


Additional Information

Manage BIG-IQ UCS Backup and Restore

NOTE "If your BIG-IQ system is part of an high availability (HA) configuration, create a backup schedule only for the active BIG-IQ. Backing up the standby BIG-IQ in a HA configuration is not supported."
