K000137195: SSLO sometimes send TCP RST (F5RST: failed to find service info)

Type
Support Solution
Published
2023-10-25
Updated
2023-10-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000137195

Description

Client tcp connection is reset by BIGIP/SSLO with reason code "F5RST: failed to find service info"

Environment

  • BIGIP configured for SSLO.
  • SSLO is configured for L3 Explicit Proxy with service type "HTTP" (eg: generic http service) configured for proxy type "Explicit".
  • The explicit proxy service is configured to send http response header "Connection: keep-alive" on its proxy ingress side and also to send "Connection: Close" request on its http/https side.
  • Client sends "Connection: keep-alive" and makes a second http request to the server within the same tcp connection.

Cause

SSLO cannot forward a second request from the client if the server has already closed the tcp connection after responding to the first  request.
This is from a security standpoint and is working as designed. 

Recommended Actions

Configure the http explicit proxy itself to use the same "Connection" header for the proxy and http(s) sides of its full proxy support.

Additional Information

The http explicit proxy will receive a proxy request (eg: "CONNECT" request method) from SSLO. It will determine the address for the requested resource and send a http or https request (in plain text) back towards SSLO. The http(s) request will be forwarded by SSLO to the server. The headers generated by the http explicit proxy will be the headers used by SSLO to generate this request. Therefore, the "Connection" type ("keep-alive" or "close") generated by the http explicit proxy will be the same used by SSLO towards the server. To ensure security, the connection type used by client and server not see the client making a second request when the server is not.

Note that if the client sends "Connection: Close" header it will always work as the server side will be closed by SSLO when the client connection is completed.

When the client sends "Connection: keep-alive" header (which is nearly always the case), then the following http explicit proxy settings and actions apply:
  • proxy -> Keep-alive & http(s) -> Keep-alive: will work correctly.
  • proxy -> Keep-alive & http(s) -> Close:  will fail with tcp reset reason code "F5RST: failed to find service info"
  • proxy -> Close & http(s) -> Keep-alive:  will work correctly as SSLO will close the server side when the client side is closed
  • proxy -> Close & http(s) -> Close: will work correctly..
