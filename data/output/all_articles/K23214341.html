K23214341: Install Kong Gateway and Ingress Controller with Aspen Mesh

Published
2022-05-20
Updated
2022-12-16
Applies to

Source

Description

With Kong Gateway and Aspen Mesh, you can combine the mesh features of Aspen Mesh inside your cluster with Kong’s rich feature set for ingress traffic from outside the cluster.

Environment

  • Kubernetes: 1.17x-1.23.x
  • Aspen Mesh: 1.9.x, 1.11.x, 1.14.x

Cause

Aspen Mesh works with Kong however Ingress and Service resources require special annotations and KongIngress resource needs to be created for the traffic to be intercepted and routed correctly by the sidecar.

Recommended Actions

After installing Aspen Mesh and deploying Kong Gateway and Kong Ingress Controller, deploy the BookInfo example application and then create/modify the following resources:

apiVersion: configuration.konghq.com/v1
kind: KongIngress
metadata:
  annotations:
  name: do-not-preserve-host
  namespace: my-istio-app
route:
  preserve_host: false
upstream:
  host_header: productpage
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: productpage
  namespace: my-istio-app
  annotations:
    konghq.com/override: do-not-preserve-host
spec:
  ingressClassName: kong
  rules:
  - http:
      paths:
      - path: /
        pathType: ImplementationSpecific
        backend:
          service:
            name: productpage
            port:
              number: 9080
---
apiVersion: v1
kind: Service
metadata:
  annotations:
    ingress.kubernetes.io/service-upstream: "true"
  labels:
    app: productpage
    service: productpage
  name: productpage
  namespace: my-istio-app
spec:
  ports:
  - name: http
    port: 9080
    protocol: TCP
    targetPort: 9080
  selector:
    app: productpage
