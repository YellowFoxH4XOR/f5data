Description

  • Getting an error during config sync
  • 01070710:3: Database error (13), Cannot update_indexes/checkpoint DB object, class:traffic_matching_criteria_port_update status:13 - EdbCfgObj.cpp, line 127.

Environment

  • You have traffic matching criteria configured, and sync is failing with error.

Cause

  • This may occur on a full-load config sync (not an incremental sync)
  • On the device receiving the ConfigSync:
       - a traffic-matching-criteria is attached to a virtual server
       - the traffic-matching-criteria is using a port-list
  • On the device sourcing the ConfigSync:
       - the same traffic-matching-criteria is attached to the same virtual server
       - the original port-list is modified (e.g. a description is changed)
       - the TMC is changed to reference a _different_ port-list
  • This issue is related to ID943577.

Recommended Actions

To work around this issue, you can Inspect the port-list on the active-standby pair or Copy the "net port-list" and "ltm traffic-matching-criteria" objects from the source to target system. To do so, perform one of the following procedures:

  • Inspect the port-list on the active-standby pair
  • Copy the "net port-list" and "ltm traffic-matching-criteria" objects from the source to target system    

Inspect the port-list on the active-standby pair

Important: If you have other partitions aside from /Common make sure to inspect each partitions for shared objects
  1. Login to the GUI of the both Active-Standby BIG-IP
  2. Go to Shared Objects > Port Lists
  3. Compare Port Lists between the Active and Standby BIG-IP
  4. Manually create the missing shared objects
  5. Login to the BIG-IP TMOS Shell
    # tmsh
  6. List the traffic criteria to look for differences (/Common only)
    # list ltm traffic-matching-criteria
  7. To login to other partitions,
    # cd /<Partition Name>
  8. Repeat step #2 on the each partition
  9. To modify the port list on an existing criteria
    # modify ltm traffic-matching-criteria <Name-of-criteria-object> destination-port-list <port-list-name>
  10. To save changes
    # save sys config

Copy the "net port-list" and "ltm traffic-matching-criteria" objects from the source to target system, merge them with "tmsh load sys config merge", and then perform a force-full-load-push sync from source to target. 

Important: If the BIG-IP systems are using device groups with auto-sync enabled, disable auto-sync temporarily while performing this workaround.
 
  1. On the source system (the system whose configuration you want to sync to peer), save the configuration:
    # tmsh save sys config
  2. Extract the ltm traffic-matching-criteria and port-lists:
    (shopt -s nullglob; echo "#"; echo "# $HOSTNAME"; echo "# generated $(date +"%F %T %z")"
        cat /config{/partitions/*,}/bigip{_base,}.conf |
        awk '
            BEGIN { p=0 }
            /^(ltm traffic-matching-criteria|net port-list) / { p=1 }
            /^}/ { if (p) { p=0; print } }
            { if (p) print; }
        ' ) > /var/tmp/portlists-and-tmcs.txt
  3. Copy /var/tmp/portlists-and-tmcs.txt to the target system.
  4. On the target system, load that file:
    # tmsh load sys config replace file /var/tmp/portlists-and-tmcs.txt

    a. If loading the config file on the target system fails with the same error message seen during a ConfigSync, follow the procedure in K13030: Forcing the mcpd process to reload the BIG-IP configuration.

    # tmsh save sys config
    # clsh touch /service/mcpd/forceload
    # clsh reboot
  5. On the source system, force a full-load sync to the device-group:
    # tmsh run cm config-sync force-full-load-push to-group <name of sync-group>
