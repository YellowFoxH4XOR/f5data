Known Issue

The BIG-IP system may erroneously re-enable a network interface that was disabled.

This issue occurs when all of the following conditions are met:

  • You have disabled a network interface for maintenance or other purposes.
  • You have created a non-default administrative partition and need to re-load the configuration on this partition.

The administrative partitions feature allows you to assign BIG-IP system objects into logical partition groups, and then grant or restrict user access to those partitions. The default administrative partition is the Common partition. For more information, refer to K7230: Overview of administrative partitions.

The configuration on the non-default administrative partition can be re-loaded explicitly without performing a full configuration re-load of the BIG-IP system. For example, to re-load a partition named test, you can type the following command:

tmsh load sys config partitions { test }

Typing the previous command should only affect objects contained within the test partition and should not change the status of the existing network interfaces.

Impact

A disabled network interface may be unexpectedly re-enabled after re-loading a non-default administrative partition.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You notice that a disabled network interface on the BIG-IP system gets re-enabled after re-loading a non-default administrative partition.
