Description

GTM/DNS configuration sync is not occurring properly

Environment

  • BIG-IP GTM/DNS
  • GTMD set to Debug Log Level
  • Large bigip_gtm.conf file
  • /usr/sbin/iqsyncer: iqsyncer already running. pid == XXXXX 
  • The following logs may be found in the BIG-IP DNS peer's /var/log/gtm:
    Jan 3 05:21:31 peer-f5-dns.com notice gtmd[4039]: 011a001d:5: SYNC loading GTM config from: 200.1.1.1
    Jan 3 05:21:32 peer-f5-dns.com notice gtmd[4039]: 011a001c:5: SYNC bigip_gtm.conf from 100.3.3.3 skipped. Reason: iqsyncer currently running from 200.1.1.1
    Jan 3 05:21:35 peer-f5-dns.com err iqsyncer[26879]: 011ae104:3: Gtm config sync result from local mcpd: result {
    Jan 3 05:21:35 peer-f5-dns.com notice gtmd[4039]: 011a0006:5: hookOnChild: SYNC syncer exited with status == 0.(success) 

Cause

GTMD Debug Level Logging can trigger a memory leak (Bug ID 911241) for the iqsyncer process, which prevents iqsyncer from functioning properly

Recommended Actions

Setting GTMD logging to a lower level and clearing the PID file will release memory pressure and allow the sync to complete normally

  1. Set the GTMD process to Log Level Notice
    tmsh modify sys db log.gtm.level value notice
    tmsh save sys config
  2. Clear the PID file to trigger another sync event
    rm -f /var/run/iqsyncer.pid
  3. Restart the services 
    bigstart restart big3d gtmd
