K000134474: The SameSite cookie attribute is only inserted for one of the two ASM main cookies.

Type
Support Solution
Published
2023-05-09
Updated
2025-07-01
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.10, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 17.0.X, 17.1.1, 17.1.0, 16.0.X, 16.0.1, 17.0.0, 16.0.0
Source
https://my.f5.com/manage/s/article/K000134474

Description

 

The SameSite cookie attribute only changes for one of the two ASM main cookies.

Based on the BUG ID: 875909, the Fix Information includes creating the internal parameter "ts_cookie_add_attrs" with a value of "SameSite = None" in order to insert the SameSite attribute to none in the ASM main cookies.

However, this fix is not completely working when the HTTP Response contains more than 1 ASM main cookie. Only the first ASM main cookie will contain the SameSite attribute, but not the second one.

2 ASM Main cookies can be produced in the HTTP response due to inserting the Cookie for a specific path in the back-end server.


Example:
Set-Cookie: TS01862430=016e4a74d77; Path=/;Secure; HTTPOnly; SameSite = none\r\n
Set-Cookie: TS012918e3=016e4a74d51; path=/test; HTTPonly; Secure\r\n


Note: As you can see in the example above, the server inserted the cookie to the "/test" path, therefore 2 ASM main cookies were generated in the response from the virtual server back to the client.
 

Environment

  • BIG-IP ASM
  • Two ASM Main cookies in HTTP Response

Cause

The issue hit the ID1298161.

Recommended Actions

Upgrade the fixed software of ID1298161 or use an iRule to add the SameSite=None attribute to ASM-generated cookies with the Set-cookie command.

The following DevCentral explains an iRule that works for this scenario:

https://community.f5.com/t5/technical-articles/irule-to-set-samesite-for-compatible-clients-and-remove-it-for/ta-p/278650

 

Additional Information

None.
