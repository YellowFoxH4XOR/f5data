Description

A vulnerability scan was executed against the BIG-IP and reported the following issue:

Presence of a Load-Balancing Device Detected

You would like to know how this issue is detected and how to fix it.

Environment

  • Vulnerability scan

Cause

This issue is typically detected in one of two ways.

The scanner will examine various HTTP headers to determine if their values suggest they are generated by different web servers. For example, the scanner may look at the Date or Server header in HTTP responses.

Furthermore, the scanner may attempt to fingerprint the TCP/IP stack in use by examining the IP and TCP header fields.

In most cases the issue is detected in the former scenario; by examining the HTTP headers and determining that they come from different pool members.

Recommended Actions

If you wish to address this issue, it's recommended that you first inspect the HTTP responses to determine which HTTP header may be responsible.

It is advisable to make the appropriate configuration changes on the servers where possible. For example, most web servers allow modification of the Server header.

You may also construct an iRule or Traffic Policy to remove or modify HTTP headers in responses. Here is one example that removes the Server header:

when HTTP_RESPONSE {
    HTTP::header remove Server 
}

Note: Take care not to remove or modify any HTTP headers that might be necessary for the correct function of the application.

Additional Information

It is not recommended to modify TCP profile values in an attempt to prevent fingerprinting, as this may be detrimental to performance. See the following article for more information:

  • K9491: BIG-IP TCP/IP stack fingerprinting
