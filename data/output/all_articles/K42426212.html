Description
When an HTTP header is empty, or does not have a value, the BIG-IP ASM security policy by could block legitimate traffic.

Example:
GET /index.html HTTP/1.1
Host: host.com
Connection: keep-alive
sec-ch-ua:      

Environment

  • BIG-IP ASM security policy
  • RFC-compliant HTTP protocol

Cause
The most common reason to trigger this violation is when the BIG-IP ASM security policy has enabled the setting "Header name with no header value " in the HTTP protocol compliance failed section of the Learning and Blocking settings for the policy.

This is the default behavior for ASM.

Recommended Actions

We can suggest the following options to mitigate this violation when legitimate traffic is affected:

Option 1
You can disable the Header name with no header value sub violation on your ASM security policy, under Security > Application Security > Policy Building > Learning and Blocking Settings > HTTP protocol compliance failed :: Header name with no value uncheck the Enable and Learn blocks for that setting.

NOTE: It is possible, if auto learning is enabled, to reset that setting. K000092549: Violation "Header name with no header value" was enabled by Policy Builder 

While this will stop the BIG-IP ASM from blocking requests which have headers with empty values, this may lower the security posture in some environments. Thus investigating why an empty header value is required in the environment, and removing the header or adding the value, is recommended.

Option 2
If the block requests are only specific to the Header, then you may create a clone of your current ASM policy where you can disable this sub violation 'Header name with no header value'  and then use an iRule to check for the header. If the header is present and empty, then you activate the cloned ASM policy which has the violation disabled (Header has no value), but for all other traffic the main BIG-IP ASM security policy is used.

Option 3
Depending on your application, you may be able to use an iRule to add some value to the header if its value is null. Or, use a simple iRule to remove the header when the value is null. Based on the example headers at the beginning of this article, the following iRule removes the sec-ch-ua header with a null value:

when HTTP_REQUEST { if { [HTTP::header value "sec-ch-ua"] eq "" } then { HTTP::header remove "sec-ch-ua" } } 

Alternatively, you can use the following iRule to loop through each header and check if any of their values is null; and remove the header if its value is null:

when HTTP_REQUEST {
    #Loop through each header by name
    foreach a_header [HTTP::header names] {

        #Check if the header value is empty
        if {[HTTP::header $a_header] eq ""}{

            #Remove the header
            HTTP::header remove $a_header
        }
    }
}

Note: This iRule is adapted from the DevCentral forum: Remove Multiple Headers.

Option 4

Use the steps in K000135496: How to enable empty_header_value_allowed asm system variable to add a security system variable that will allow for that specific header to be passed through with an empty value.
