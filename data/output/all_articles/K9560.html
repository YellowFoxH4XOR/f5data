Known Issue

This is the result of a known issue. The LINK::nexthop and LINK::lasthop iRule commands return Media Access Control (MAC) address information about the current connection. However, the return value incorrectly includes the NULL termination character at the end of the MAC address string, causing string comparisons against these return values to fail.

F5 Product Development tracked this issue as CR112322 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

You can use the TCL format command to remove the NULL terminator from the return value and convert it to a proper TCL string. To do so, wrap each instance of the LINK::lasthop and LINK::nexthop commands in the format command, as follows:

[format %s [LINK::lasthop]]
