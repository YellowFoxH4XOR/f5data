Topic

You should consider using this procedure under either of the following conditions:

  • You want to reprovision a BIG-IP system for different software modules and your module uses application volumes.
  • You want to move a blade from one BIG-IP system to another and the blade was previously configured with a module that uses application volumes with a preservability classification of precious.

Description

Your BIG-IP system may fail due to insufficient disk space when you reprovision a software module or when you move a blade from one BIG-IP chassis to another. Some software modules use application volumes that consume additional disk space. Each software module provisioned and installed on a different software volume may have its own set of the application volume disk usage.

Application volumes consist of disk space that is allocated uniquely for the purpose of storing the application-related data that the provisioned software module uses. You can use the following Traffic Management Shell (tmsh) command to display the application volume preservability that is allocated on the BIG-IP system:

list /sys disk application-volume

There are two types of data preservability, which may be assigned to your application volumes when you provision a software module:

  • precious: The provisioning system is not able to delete the application volume and the user must manually delete the application volume if additional disk space is required.
  • discardable: The provisioning system is able to delete the application volume.

When you move a blade with a precious application volume from one chassis to another and the system encounters a provisioning error, the blade will transition to Offline and the system may report disk space limitation messages in the /var/log/ltm file, similar to the following example:

notice clusterd[9186]: 013a0006:5: Transition from state QUORUM to RUNNING.
notice clusterd[9186]: 013a0015:5: Blade 4 quorum state increasing from QUORUM to RUNNING.
emerg mcpd[8819]: 01071008:0: Provisioning failed. Disabling cluster member. 'Disk limit exceeded. 32288 MB are required to provision these modules, but only 15500 MB are available

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the tmsh utility.
  • Your BIG-IP system is provisioned with application volumes.

Procedures

Unprovisioning a module

You should unprovision the modules on a BIG-IP platform using the application volume if additional disk space is required. The unprovisioning of a module allows you to delete the application volume, which increases the disk space to provision new software modules.

Impact of procedure: This procedure deletes precious application volumes that contain application and configuration data related to the associated module. You should schedule a maintenance window and carefully review any proposed changes before performing this procedure.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Create the user configuration set (UCS) archive file by using the following command syntax. Replace <path/to/UCS> with the full path to the UCS archive file:

    save /sys ucs <path/to/UCS>

    In this command, note the following:

    • <path/to/UCS> is the full path to the UCS archive file.

    For example:

    save /sys ucs /var/tmp/unprovision.ucs

    Note: F5 recommends that you save the UCS archive file to a safe place on your network.

  3. View the application volume used by the module you want to unprovision by typing the following command:

    list /sys disk application-volume

    The command output appears similar to the following example:

    sys disk application-volume avrdata {
    logical-disk HD1
    owner avr
    preservability precious
    size 3900
    volume-set-visibility-restraint none
    }

  4. View the current provisioning of the system by typing the following command:

    list /sys provision

    For example, when you provision Application Visibility and Reporting (AVR) as nominal, the output appears similar to the following example:

    sys provision avr {
    level nominal
    }

  5. Unprovision the module using the following command syntax:

    modify /sys provision <module_name> level <level_type>

    For example, to unprovision AVR, type the following command:

    modify /sys provision avr level none

  6. Delete the application volume of the related modules using the following command syntax:

    delete /sys disk application-volume <name>

    For example, to delete the avrdata application volume, type the following command:

    delete /sys disk application-volume avrdata

  7. To save the system configuration, type the following command:

    save /sys config
