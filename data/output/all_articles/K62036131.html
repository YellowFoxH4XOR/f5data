Description

After upgrading to BIG-IP 13.1.3.6, your Windows ADFS application is not working when going through the BIG-IP.

Your ADFS is using 2 host names (SNI) where after successfully connecting to hostname 1, the connection will redirect to hostname 2. For example in a successful connection, client browser will send a SNI to adfs-1.example.com. This connection will then redirect to adfs-2.example.com.

You might get the following error message:
PR_CONNECT_RESET_ERROR

Environment

  • BIG-IP upgraded to 13.1.3.6
  • Before upgrade the ADFS application was working
  • Your ADFS have 2 hostname where the first hostname will redirect to the second hostname
  • To issue when bypass the BIG-IP Virtual Server
  • You might have the following error message: PR_CONNECT_RESET_ERROR

Cause

The Virtual Server does not forward the SNI which was received by the client browser. SNI is in the Client Hello but this is not seen from the BIG-IP Virtual Server to the ADFS. Because the ADFS does not get the SNI, it will RST the connection immediately after getting the Client Hello.

Recommended Actions

You will need to create a new Server SSL Profile for each hostname. After creating these Server SSL Profiles, create an iRule to decide which Server SSL profile to be used based on the SNI received by the client browser. If you do not know the hostname (SNI) of the ADFS, you can run a pcap to identify the hostname from the SNI.

  1. Login to the BIG-IP GUI.
  2. Navigate to Local Traffic > Profiles > SSL > Server.
  3. Click Create.
  4. Enter a Name.
  5. Parent Profile is serverssl.
  6. Change Configuration from Basic to Advanced.
  7. Under Server Name, enter the first hostname (SNI).
  8. Click Finished.
  9. Repeat step 3 to 8 for the next hostname (SNI). Refer K14806 for further information.
  10. Create an iRule to decide which Server SSL Profile to user. Navigate to Local Traffic > iRules > iRule List.
  11. Click Create.
  12. Enter a Name.
  13. The iRule to decide which Server SSL profile to use based on the client browser's SNI is as below:
    when HTTP_REQUEST {
        set hostname [getfield [HTTP::host] ":" 1]
    }
    when SERVER_CONNECTED {
        switch -glob [string tolower $hostname] {
        "hostname1" {
            SSL::profile serverssl1
        }
        "hostname2" {
            SSL::profile serverssl2
        }
      default {
    #default serversssl profile to be selected if Host header value cannot be matched with predefined values
        SSL::profile serverssl
      }
    }
    }

    For example, if hostname 1 is adfs-1.example.com, hostname 2 is adfs-2.example.com, server SSL profile 1 is adfs1-serverssl and server SSL profile 2 is adfs2-serverssl, the iRule would be:
    when HTTP_REQUEST {
        set hostname [getfield [HTTP::host] ":" 1]
    }
    when SERVER_CONNECTED {
        switch -glob [string tolower $hostname] {
        "adfs-1.example.com" {
            SSL::profile adfs1-serverssl
        }
        "adfs-2.example.com" {
            SSL::profile adfs2-serverssl
        }
      default {
    #default serversssl profile to be selected if Host header value cannot be matched with predefined values
        SSL::profile serverssl
      }
    }
    }
  14. Click Finished.
  15. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  16. Click on the mentioned Virtual Server.
  17. Ensure SSL Profile (Server)  is serverssl.
  18. Click the Resources tab.
  19. Aligned with iRule, click Manage.
  20. Move the created iRule from Available to Enabled.
  21. Click Finished.
