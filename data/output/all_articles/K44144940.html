Description

  • TMM restarted
  • If device is part of an HA pair, traffic is failed over
  • Logs similar to the following can be seen on /var/log/ltm

    notice tmm[15985]: 01010029:5: Clock advanced by 17259 ticks                                    
    crit tmm[15985]: 01010020:2: MCP Connection aborted, exiting
    notice promptstatusd[2825]: 01460006:5: semaphore tmm.running(1) held

Environment

  • BIGIP

Cause

The clock advance was for more than 17 seconds, which is close to or exceeds the watchdog timeout of 10 seconds. When the watchdog timeout is reached can cause TMM failure and restart. The behavior is caused by CPU starvation by the Host hypervisor.

Recommended Actions

  • Check if there was any intensive task performed during the period when the "MCP Connection aborted, exiting" message was logged.
  • Increase the priority or enable CPU reservation for the BIG-IP VE in the Host hypervisor
  • Fix host and provide BIG-IP VE with ample CPU resources.
