K14496445: PAM Authentication failure for root on Viprion with multiple blades

Type
Support Solution
Published
2020-09-16
Updated
2023-02-21
Applies to
  • VIPRION Platforms
  • BIG-IP
  • BIG-IP LTM: 15.1.3, 14.1.2
Source
https://my.f5.com/manage/s/article/K14496445

Description

An alert/events received saying, root authentication fails, and rhost are internal ip address(prefix of 127). 

Jul 23 15:32:35 slot4/lab notice sshd[32521]: pam_unix(sshd:auth): authentication failure; logname= uid=0 euid=0 tty=ssh ruser= rhost=127.3.0.1  user=root

Note: The list of Applies to version may not be exhaustive and this may apply to other versions as well. If you experience this issue on other software versions, please contact F5 Support online or via phone.

Environment

  • Having more than 1 blade running
  • Happen after upgrade

Cause

Due to existing configuration in "/etc/csyncd.conf" which disables the synchronizing of symbolic links with other blades.  

Recommended Actions

  1. Perform a check on the individual slots to display all symbolic links. 
    Example::
    [root@monmon:Active:Standalone] ssh # ll /root/.ssh/
    total 6
    lrwxrwxrwx. 1 root root  29 Jul 16 18:54 authorized_keys -> /var/ssh/root/authorized_keys
    lrwxrwxrwx. 1 root root  22 Jul 16 18:54 identity -> /var/ssh/root/identity
    lrwxrwxrwx. 1 root root  26 Jul 16 18:54 identity.pub -> /var/ssh/root/identity.pub
    lrwxrwxrwx. 1 root root  25 Jul 16 18:54 known_hosts -> /var/ssh/root/known_hosts
    -rw-r--r--. 1 root root 262 Jun 19 09:42 README
     
  2. Once the slot is identified with a missing symbolic link, follow the below workaround on the slot. 

    Note: recreating symbolic link may trigger the issue again in the next upgrade. 

    # ln -s source_file symbolic_link
    For example, consier o/p from step-1
    #ln -s /var/ssh/root/authorized_keys authorized_keys
    #ls -l 
    lrwxrwxrwx. 1 root root  29 Jul 16 18:54 authorized_keys -> /var/ssh/root/authorized_keys

  3. To fix the issue permanently, after creating a symbolic link, update /etc/csyncd.conf file. 
    /etc/csyncd.conf file under /root directory section does not include "lnksync yes"  and hence symlinks are NOT synchronized. 
     
  4. locate this specific section of code in /etc/csyncd.conf
                       monitor dir /root { lnksync yes 
                                          recurse yes }     
  5. Add/set lnksync to yes and recurse to yes for "dir /root" section
    ??
  6. Restarting csyncd and the content of /root/.ssh/ directory will be synchronized with other blades.
    # bigstart restart csyncd
