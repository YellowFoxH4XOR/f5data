Description

Starting since v14.1.4.2, the behavior is partially changed for oAuth Discovery Task Time values.

  • Before v14.1.4.2, in GUI in 'Access  ››  Federation : OAuth Client / Resource Server : Provider  ››  <<<provider_name>>>', we can see:
    • 'OpenID URI -> Last Discovery Time'
    • 'Discovery Task -> Last Run Time'

Both time values were equal under working conditions (if we speak about APM in Standalone Mode OR about APM in active mode from HA pair perspective).
The both time values were equal due to apm inserted the JSON Web Key Set (JWKs) into config each time after JWKs was received from oAuth Provider during oAuth discovery attempt.
 

  • After v14.1.4.2, only the new/unique keys (JWKs) will be inserted into configuration. Due to that 'OpenID URI -> Last Discovery Time' shows the last time when JWKs was inserted into config (when the config was updated with new keys) and 'Discovery Task -> Last Run Time' will show when the last discovery attempt was done.

So, both time values won't be equal as oAuth Provider doesn't send the new keys (which will be merged into config on APM accordingly and time is updated in 'OpenID URI -> Last Discovery Time') as often as oAuth Discover attempt task is done (and time is updated accordingly in 'Discovery Task -> Last Run Time'; it depends on the 'Discovery Task -> Frequency' setting).

Environment

  • oAuth Discovery
Cause

The behavior change is caused by the fix for bug id 995029
