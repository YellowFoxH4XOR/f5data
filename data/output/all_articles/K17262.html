Known Issue

Attempts to load BIG-IP GTM configurations from the Traffic Management Shell (tmsh) may fail.

This issue occurs when one of the following conditions is met:

  • You configure BIG-IP GTM, from the Configuration utility, by performing the following actions:
    • You create a BIG-IP GTM pool that contains HTTP port 80 and any port * members.
    • You configure a member-specific gateway-icmp monitor with a member that uses the (* wildcard) any port.
    • You assign a Layer 4 (L4) or Layer 7 (L7) monitor at the pool level.
    • You attempt to load the BIG-IP GTM configuration from the tmsh utility.
  • You configure BIG-IP GTM, from the Configuration utility, by performing the following actions:
    • You create a BIG-IP GTM server object, and then configure the GTM server to include virtual server objects that use the * any port.
    • You assign a gateway-icmp monitor to any of the virtual server objects configured to use the * any port.
    • You assign an L4 or L7 monitor to the BIG-IP GTM server object.
    • You attempt to load the BIG-IP GTM configuration from the tmsh utility.

Impact

BIG-IP GTM configurations fail to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the BIG-IP GTM system is configured as part of a synchronization group, error messages similar to the following example are logged to the /var/log/gtm file on BIG-IP GTM members of the synchronization group:

    err iqsyncer[<pid>]: 011ae104:3: GTM config sync result from local mcpd: result { result_code 17237538 result_message "01070622:3: The monitor </<partition>/<L4/7 monitor name> has a wildcard destination service and cannot be associated with a node that has a zero service." }

  • When attempting to load the BIG-IP GTM configuration, from the tmsh utility, the system displays an error message similar to the following example:

    tmsh load sys config gtm-only

    Loading GTM system configuration...
    /usr/local/gtm/include/gtm_base_region_isp.conf
    /usr/share/monitors/gtm_base_monitors.conf
    Loading configuration...
    /config/bigip_gtm.conf
    01070622:3: The monitor /Common/<L4 or L7 monitor name> has a wildcard destination service and cannot be associated with a node that has a zero service.
    Unexpected Error: Loading configuration process failed.

Workaround

To work around this issue, you can remove the L4 or L7 monitor from the configuration.

Impact of workaround: The BIG-IP GTM system stops port-level object monitoring for the specific configuration.
