Known Issue

This is the result of a known issue. In BIG-IP version 9.4.5, the default LDAP client configuration was modified to enforce server certificate authentication for TLS/SSL requests. As a result, LDAP monitors with TLS/SSL enabled fail, and mark the associated pool members down regardless of actual server status.

When debugging is enabled in the monitor configuration, error messages that appear similar to the following example are logged:

Bind failed with CN=Administrator,CN=Users,DC=lab,DC=net(-1): Can't contact LDAP server

Note: Debug messages are logged to the debug log file for the affected monitor (/var/log/LDAP_<monitor name>.<IP address>.log).

Important: Disable debugging for the monitor once the issue has been identified to avoid consuming excessive disk space.

Invoking the ldapsearch command using the ldaps protocol scheme will also fail. A message logs to the console that appears similar to the following example:

TLS trace: SSL3 alert write:fatal:unknown CA
TLS trace: SSL_connect:error in SSLv3 read server certificate B
TLS trace: SSL_connect:error in SSLv3 read server certificate B
TLS: can't connect.
ldap_perror
ldap_sasl_interactive_bind_s: Can't contact LDAP server (81)

Failure of the LDAP monitor to establish an SSL/TLS session with the server causes the monitored pool members to be marked down.

This issue was tracked by F5 Networks Product Development as CR103690, and it was fixed in BIG-IP version 9.4.6. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, WebAccelerator, and PSM Release Notes.

Note: Previous versions did not require server authentication for the TLS/SSL-enabled LDAP monitor.

Workaround

You can work around this issue by modifying the LDAP client configuration to not require server certificates. To do so, perform the following procedure:

  1. Use a text editor to open the /usr/etc/openldap/ldap.conf file.
  2. Add the following line to the end of the file, between the last line of text and the closing bracket:

    TLS_REQCERT never
  3. Save and close the file.
  4. Use a text editor to open the /etc/subdomain.d/usr.bin.bigd file.
  5. Add the following line to the end of the file, between the last line of text and the closing bracket:

    /usr/etc/openldap/ldap.conf r,
  6. Restart the security subsystem by typing the following command:

    bigstart restart subdomain

When the new configuration has been successfully loaded, output that appears similar to the following example will be displayed on the console:

Unloading SubDomain profiles[OK]
Loading SubDomain profiles[OK]

Note: The LDAP configuration files are not synchronized between members of a redundant pair. Therefore, when configuring a redundant pair, you must repeat this procedure on both systems.
