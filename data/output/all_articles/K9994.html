Known Issue

This is the result of a known issue. The ARX CLI will allow the creation of a volume name that contains characters that do not map to the character encoding used in the namespace. As a result, the namespace policy will not work.

Important: This issue may cause the ARX system to reboot and core. For more information, refer to K9993: The ARX system may core and reboot if the volume name contains UTF-8 characters.

F5 Product Development tracked this issue as ID 34320 and it was fixed in ARX version 5.1.0. For information about upgrading, refer to the ARX Release Notes.

Beginning in ARX version 5.1.0, If you attempt to create a volume name that contains characters that do not map to the character encoding used in the namespace, you will receive an error message that appears similar to the following example:

% ERROR: VOLUME_PATH_CHAR_ENCODING_CONVERSION_FAILURE (41353989): The volume name entered, [/vol1_ÃƒÂ©ÃƒÃ…], contains characters that are unsupported by the namespace's character encoding.

Additionally, the ARX system will log an error message that appears similar to the following example:

:CLI-0-ERR-CLI_TRANSCODE_UTF16_FAILED:: Failed to transcode CLI output buffer to UTF-16: U_INVALID_CHAR_FOUND

Workaround

You can work around this issue by ensuring that the volume name only contains characters that map to the character encoding in the namespace. For example, if the namespace uses latin1 character encoding, ensure that the volume name only uses characters that map to the latin1 character encoding.
