Description

Accessing the APM URL after abrupt device reboot causes URL to be redirected to /my.logout.php3?errorcode=19, 20, 21, or 25 and browser showing ERR_CONNECTION_RESET.

/var/log/ltm has the below log :

info mprov:<PID>:[<PID>]: 'httpd_apm failed to stop.'

/var/log/daemon.log has

warning systemd[1]: httpd_sam.service start operation timed out. Terminating.
err systemd[1]: Failed to start SYSV: Apache is a World Wide Web server.  It is used to serve HTML files and CGI..
notice systemd[1]: Unit httpd_sam.service entered failed state.
warning systemd[1]: httpd_sam.service failed.

The below command run and see the status for httpd_sam and httpd_apm

tmsh show sys service httpd_sam httpd_apm
httpd_sam down, normally up
httpd_apm down, waiting for httpd_sam to begin

 

Environment

  • BIG-IP APM
  • Virtual server with Access profile

 

Cause

  • Bug ID 994033
  • Bug ID 737237 (fixed in V15 and after)

 



Recommended Actions


Upgrade to the fixed versions,

Once you encountered this issue, manually restart both httpd_sam and httpd_apm services by running the below command:


tmsh start sys service httpd_sam httpd_apm


If the command takes too long to complete and is stuck on trying to initialize httpd_sam, please run the following commands instead:


tmsh start sys service httpd_sam


Validate that httpd_sam is running properly:


tmsh show sys service httpd_sam
httpd_sam (pid <PID>) is running...


Once you see that the daemon is working properly, please proceed to start httpd_apm


tmsh start sys service httpd_apm


Validate that the services are running properly:


tmsh show sys service httpd_sam httpd_apm
httpd_sam (pid <PID>) is running...
httpd_apm             run (pid <PID>) x seconds, x starts
