Known Issue

This is the result of a known issue. The HTTP caching feature (referred to as RAM Cache in BIG-IP versions prior to 11.0.0) does not take the Clustered Multiprocessing (CMP) feature into account when calculating memory consumption.

When the HTTP caching feature is configured for a virtual server on a CMP-enabled platform, the amount of memory allocated for the feature in the Web Acceleration profile is provisioned for each instance of the Traffic Management Microkernel (TMM).

For example, the BIG-IP 8800 platform is capable of running four instances of TMM. If the Cache Size setting is set to 100 MB, each instance of TMM reserves 100 MB for its local cache, for a total amount of 400 MB of memory reserved by the system.

In versions prior to BIG-IP 10.1.0, this means that each TMM has a separate cache. A client connection on TMM2 can only use objects that are stored in TMM2's local cache. In BIG-IP 10.1.0 and later, F5 enhanced the HTTP cache feature for CMP-enabled platforms to allow the system to copy cached objects between TMMs. For more information about distributed RAM Cache, refer to K11990: RAM Cache enhancements for Clustered Multi-Processing-capable systems.

F5 Product Development tracked this issue as ID 227319 (formerly CR92541) and ID 364645, and it was fixed in version 11.0.0 HF1.
