Topic

When presented with certificates containing different Certificate Revocation List Distribution Point (CRLDP) information, the BIG-IP system that is configured with the CRLDP module may authenticate clients using a variety of methods.

Description

The CRLDP authentication module was introduced in BIG-IP version 9.4.0. The module provides the BIG-IP system a means to authenticate client connections that are destined for a virtual server. Depending on the BIG-IP system CRLDP configuration and the CRLDP information located in the certificate that is presented to the BIG-IP system, the BIG-IP system may authenticate the client using the CRLDP server in its configuration or the certificate. If the Use Issuer option in the CRLDP authentication configuration is enabled, the BIG-IP system uses the CRLDP information provided by the issuer certificate instead of the client certificate. The following list describes the behavior under different scenarios:

  • Certificate contains CRLDP information in Directory Name format:

    The BIG-IP system authenticates the client connection with the CRLDP server in its configuration.

  • Certificate contains CRLDP information in URI with host name:

    The BIG-IP system authenticates the client connection with the CRLDP server defined by an LDAP url  in the certificate.

    Note: Using HTTP URLs to define servers in CRLDP authentication for client certificates in BIG-IP LTM is not supported.

  • Certificate contains CRLDP information in URI without host name:

    The BIG-IP system fails to authenticate the client connection and logs error messages that appear similar to the following example to the /var/log/ltm file, if the tamd process is set to log debug messages:

    010b090d:5: CRL: <CRLDP URI> removed
    010b0902:4: no ldapurl found for cert <cert base DN>
    010b0232:4: pam_authenticate: 6

    Note: You can configure the tamd process to log debug messages using the tmsh modify sys db log.tamd.level value debug command (11.x) or the bigpipe db Log.Tamd.Level debug command (9.x - 10.x). Turning on debug log messages may affect system performance and you should use it only during troubleshooting. Always turn off debug log messages for the tamd process when you are done troubleshooting, by using the tmsh modify sys db log.tamd.level value error command (11.x) or the bigpipe db Log.Tamd.Level error command (9.x - 10.x).

CRLDP information formats in a certificate

A client certificate issued by a Certificate Authority (CA) may contain CRLDP information in the following formats:

  • X.500 Directory Name
  • HTTP or FTP URI
  • LDAP URI

    The following example is a snippet of the CRLDP information presented in LDAP URI format with a host name:

         Distribution Point Name:
              Full Name:
                   URL=ldap://win2k3-1.sglab.askf5.com/CN=win2k3-1,CN=win2k3-1,CN=CDP,CN=Public%20Key%20Services,CN=Services,CN=Configuration,
    DC=sglab,DC=askf5,DC=com?certificateRevocationList?base?objectClass=cRLDistributionPoint

    The following example is a snippet of the CRLDP information presented in LDAP URI format without a host name:

    [1]CRL Distribution Point
         Distribution Point Name:
              Full Name:
                   URL=ldap:///CN=win2k3-1,CN=win2k3-1,CN=CDP,CN=Public%20Key%20Services,
    CN=Services,CN=Configuration,DC=sglab,DC=askf5,
    DC=com?certificateRevocationList?base?objectClass=cRLDistributionPoint

For information about CRLDP standards, refer to the following Internet Engineering Task Force (IETF) document. RFC5280: Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile.

Recommendations

When you are planning to configure the BIG-IP CRLDP authentication module, you should consider the following factors:

  • The client or issuer certificates should contain a hostname if the CRLDP information is in the URI format.
  • The BIG-IP system should be configured with the CRLDP server information.
