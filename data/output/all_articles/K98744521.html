Description

We cannot Sync our Active node to its Standby peer.

When trying to sync we get the error below:

Status    Sync Failed
Summary    A validation error occurred while syncing to a remote device
Details
Sync error on Device_Name_1: Load failed from Device_Name_2  01070712:3: Caught configuration exception (0), unable to open file: /tmp/confpp.dat.
Recommended action: Review the error message and determine corrective action on the device

You might also experience the following symptoms:

  • This log on /var/log/ltm or when entering the tmsh command line:

    crit tmsh[PID]: 01420001:2: Can't open command history file (/root/.tmsh-history-root), Read-only file system : framework/CmdHistoryFile.cpp, line 92

  • And I/O errors on /var/log/kern.log similar to:

    err kernel: Buffer I/O error on device dm-10, logical block 168837
    warning kernel: lost page write due to I/O error on dm-10
    err kernel: sd 0:0:0:0: timing out command, waited 180s
    info kernel: sd 0:0:0:0: [sda] Unhandled error code
    info kernel: sd 0:0:0:0: [sda] Result: hostbyte=DID_OK driverbyte=DRIVER_OK
    info kernel: sd 0:0:0:0: [sda] CDB: Write(10): 2a 00 05 5c 6c 0a 00 00 02 00
    err kernel: end_request: I/O error, dev sda, sector 87743050

Environment

  • Config Sync
  • tmsh command line
  • File system errors

Cause

Unknown at the time of publication.

Recommended Actions

  1. Make sure you have a UCS backup file downloaded to your local computer.

    Note: You might also get an error when creating a new UCS file, it is recommended to take regular back up files of the system and have them saved externally from the BIG-IP.

  2. During a maintenance window perform procedures for a file system check, K73827442: Forcing a file system check on the next system reboot (12.x - 15.x).

    Note: You might need to have console access in case you need to perform a manual file system check.
