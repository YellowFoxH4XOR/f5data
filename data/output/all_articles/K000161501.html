K000161501: Multiple iRules using the same static variable name in the RULE_INIT event, may disrupt expected SSLO behavior

Type
Support Solution
Published
2026-08-26
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP SSL Orchestrator
Source
https://my.f5.com/manage/s/article/K000161501

Description

Unexpected behavior may occur on F5 SSL Orchestrator systems when multiple iRules use the same static variable name (e.g., static::default_topology) in the RULE_INIT event.

Modifying the static variable in any RULE_INIT event, regardless of which iRule or virtual server it is associated with (even if disabled), immediately overwrites the value globally for all iRules and all connections.

If the new value does not match an existing SSL Orchestrator topology, traffic for unrelated topologies may be misrouted or dropped, resulting in connectivity failures. 

Environment

  • F5 SSL Orchestrator
  • Multiple iRules using the RULE_INIT event to set static variables (e.g., static::default_topology)
  • Virtual servers for different SSL Orchestrator topologies (e.g., "intercept", "intercept-v2")
  • Issue can occur even when iRule is attached to a disabled virtual server
  • No changes at the SSL Orchestrator topology level; issue triggered by iRule/virtual server configuration changes

Cause

When a static global variable is set in the RULE_INIT event of any iRule, any other RULE_INIT event that modifies the same static global variable name will overwrite the value immediately and globally. This applies to both new and existing connections. If the variable value does not match an existing SSL Orchestrator topology, traffic is dropped or misrouted, causing outages across unrelated topologies.

Recommended Actions

  • Use unique static variable names in the RULE_INIT event of each iRule to prevent cross-impact between iRules and topologies.
  • If multiple iRules must share a value, ensure the variable name and value are consistent and valid for all intended topologies.
  • After making changes to iRules with RULE_INIT events, verify that all static variable assignments match existing SSL Orchestrator topology names.
  • If a network outage or unexpected behavior with SSLO traffic occurs, check for recent changes to iRules or virtual servers that may have overwritten a static variable.
  • Review logs for TCL errors indicating missing virtuals or topology mismatches.
  • If the issue persists after reverting configuration changes, a device reboot may be required to restore normal operation.

Additional Information

  • The RULE_INIT event is triggered when an iRule is saved, when the device starts up, or when the software is restarted. It is global in scope and not limited to the context of a specific virtual server or connection.
  • This behavior is specific to the static namespace in iRules and is particularly impactful in SSL Orchestrator environments where topologies are referenced by name.
  • The issue can occur even if the iRule is attached to a disabled virtual server, as RULE_INIT executes outside the context of traffic processing.
