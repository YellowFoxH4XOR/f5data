Topic

You should consider using this procedure under the following condition:

  • You want to restore a BIG-IQ system using a user configuration set (UCS) backup file that was stored remotely.

Note: This procedure applies to BIG-IQ Centralized Management only. For restoring Data Collection Devices (DCD), you should remove and re-associated the DCD instances from the BIG-IQ Centralized Management system. For more information, refer to K02014651: Removing a DCD association from BIG-IQ Centralized Management.

Description

Using a copy of the BIG-IQ UCS backup file, stored remotely for recovery purposes, you can restore the newly installed BIG-IQ system to the instance for which you generated the UCS backup file.

For more information about BIG-IQ system UCS file backup and restoration, refer to the following manuals:

  • BIG-IQ 7.1.0 and later: The Manage BIG-IQ UCS Backup and Restore chapter of the Setting up and Configuring a BIG-IQ Centralized Management Solution manual.
  • BIG-IQ 6.0.0 through 7.0.0: The BIG-IQ System File Management chapter of the Planning and Implementing a BIG-IQ Centralized Management Deployment manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Advanced Shell (bash) or TMOS Shell (tmsh) access of the BIG-IQ system.
  • You have access to the copy of the BIG-IQ UCS backup file generated from the last working instance of the BIG-IQ system that you want to restore.
  • The target BIG-IQ system is newly re-imaged or installed with no existing configuration.

Procedures

Restore UCS backup

To perform the system restoration, you must transfer the copy of the UCS backup file to the target BIG-IQ system and save the file in the /shared/ucs_backups directory. You can then use the tmsh command to load the target UCS backup file to restore the BIG-IQ system. To do so, perform the following procedure:

Note: If the target BIG-IQ system is a newly installed system, make sure the master/device key on the new system is identical to the original system where the UCS was created from. For more information, refer to the master/device key reset procedures in K73105542: Migrate a BIG-IQ configuration from a 7000 series hardware platform to a BIG-IQ VE system.

Impact of procedure: Performing this procedure erases the existing configuration on the target BIG-IQ system, and you cannot reverse or recover the configuration afterwards. If you perform this procedure, carefully assess the existing data or configuration on the target system. Restoration may take several minutes, and the system may be unavailable during that time.

  1. Transfer the BIG-IQ UCS backup file from the remote folder to the target BIG-IQ system and save it to /shared/ucs_backups directory. For more information about transferring the files, refer to K175: Transferring files to or from an F5 system.
  2. Log in to the BIG-IQ system's tmsh as an administrator.
  3. To restore the UCS backup file, use the following command syntax:

    load /sys ucs /shared/ucs_backups/<UCS_filename>

    For example:

    load /sys ucs /shared/ucs_backups/bigiq_backup_biq1.localdomain_20161210090526.ucs

    Note: When restoring the BIG-IQ UCS file to a different virtual machine instance than the one on which it was created, add the no-license option: load /sys ucs /shared/ucs_backups/<UCS_filename> no-license.

  4. To restart the restjavad service after you successfully complete the restoration, enter the following command:

    restart /sys service restjavad

UCS load failure workaround

If the UCS restore fails to load with the following error message, you may be able to work around it by restarting all system services.

emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- 01071769:3: Decryption of the field (passphrase) for object (/Common/MasterKeyStorageObject.key) failed. Unexpected Error: Loading configuration process failed.

To work around the issue, perform the following procedure:

Impact of procedure: This procedure involves restarting all system services, but this does not have a negative impact on your system because the configuration has already failed to load. When you load the UCS file, the existing configuration on the target BIG-IQ system is erased, and you cannot reverse or recover the configuration. If you perform this procedure, carefully assess the existing data or configuration on the target system. Restoration may take several minutes, and the system may be unavailable during that time.

  1. Log in to tmsh as an administrator on the BIG-IQ system.
  2. After the UCS load fails, restart all system services by entering the following command:

    restart /sys service all

  3. Restore the UCS backup file again using the following command syntax:

    load /sys ucs /shared/ucs_backups/<UCS_filename>

    For example:

    load /sys ucs /shared/ucs_backups/bigiq_backup_biq1.localdomain_20161210090526.ucs

    Note: When restoring the BIG-IQ UCS file to a different virtual machine instance than the one on which it was created, add the no-license option: load /sys ucs /shared/ucs_backups/<UCS_filename> no-license.

  4. To restart the restjavad service after you successfully complete the restoration, enter the following command:

    restart /sys service restjavad

If the UCS restore still fails with the following error message and you know the BIG-IQ passphrase, you may be work around it by editing the /config/bigip.conf file:

Symmetric Unit Key decrypt failure - decrypt failure
Symmmetric Unit Key decrypt
Master key OpenSSL error: 1503569068:error:06065064:digital envelope routines:EVP_DecryptFinal_ex:bad decrypt:evp_enc.c:587:
Cannot load master key file.  Updating to a new master key.
Loading keys from the file.

To work around the issue, perform the following procedure.

Impact of procedure: This procedure involves restarting all system services, but this does not have a negative impact on your system because the configuration has already failed to load. When you load the UCS file, the existing configuration on the target BIG-IQ system is erased, and you cannot reverse or recover the configuration. If you perform this procedure, carefully assess the existing data or configuration on the target system. Restoration may take several minutes, and the system may be unavailable during that time.

You can edit the BIG-IP configuration files, enter the BIG-IQ passphrases in clear text, and then load the configuration. This restores and re-encrypts the configuration. To do so, perform the following procedures:

  1. Log in to tmsh as an administrator on the BIG-IQ system.
  2. After restoring the UCS file, open the /config/bigip.conf file with a text editor.

    Edit each configuration object containing BIG-IQ passphrase, replacing the encrypted passphrase with the unencrypted version.

    For example:

    ltm profile server-ssl /Common/MasterKeyStorageObject.key {
        app-service none
        #passphrase $M$LE$gQiU/JsugC1urv3aHydCXRdJnjQVyfCBa7863pNHHs4W7K0VXiMANr2OofEXmo/J
        passphrase ThisPassPhraseIs34CharactersLong!@
    }

  3. To load the new configuration into memory, enter the following command:

    tmsh load sys config

  4. To save the running configuration with the encrypted passwords or passphrases in the bigip.conf file, enter the following command:

    tmsh save sys config

  5. To restart the restjavad service after you successfully complete the restoration, enter the following command:

    restart /sys service restjavad
