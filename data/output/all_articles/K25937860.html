Description

There may be a time when the device name is required to be changed for any purpose (such as migrating from one data center to another). The following information will provide the steps to accomplish this task using the tmsh command.

Environment

  • BIG-IP devices configured in high availability
  • Device groups configured
  • Incorrect or confusing Device name set

Cause

The Device name is set by the initial creation of the Device using it's host name, while the Hostname may be changed, this will not automatically change the Device name when the Device is in a trust-group.

While this is cosmetic and does not affect function it can be extremely confusing.

Recommended Actions

Follow the Procedures in K40832524: Rebuilding device trust using tmsh (11.x - 16.x)

After removing the devices from the device-group [Step 2 in  K40832524] and breaking device trust [Step 3 in  K40832524] of "Removing the configuration from the active device and rebuilding the trust", do the following on each device that you wish to change the device name on:
  1. Log in to the TMOS shell by entering the following command:
    tmsh
  2. Use the following syntax to change the device name where old_device_name is the device name you wish to change and current_hostname is what you wish to change the device name to:
    mv /cm device <old_device_name> <current_hostname>
    Note: This presupposes that you desire the device name to be in sync logically with your hostname AND that you have already changed the hostname to what you desire it to be.
  3. Check that the device-name is properly changed using the following command:
    list /cm device <current_hostname>
  4. Save the configuration by entering the following:
    save /sys config
  5. Proceed with Step 4 in  K40832524 of "Removing the configuration from the active device and rebuilding the trust"

Additional Information

  • This specific "mv" command does not require enabling the system variable "mcpd.mvenabled".
  • Use of "mv" command in general is officially deprecated and not supported.
  • Consider using the procedure from https://my.f5.com/manage/s/article/K15700 instead.
