Description

The purpose of this article is to help understand behaviour of how BIG-IQ collects object status state from BIG-IP device in BIG-IQ > Configuration > Local traffic >
  • Virtual Servers
  • Pool Members
  • Nodes

Environment

  • Explaining virtual servers, pool members, nodes status on BIG-IQ
  • Stats Collection enabled
  • BIG-IQ Centralized Manager with DCDs
  • Managed BIG-IP

Cause

Based on information K91114310: Reducing the performance impact of BIG-IQ statistics gathering on managed BIG-IP systems there are two options to collect information about  status of objects:

  • Periodical check done from BIG-IQ CM by default done each 5 minutes
  • BIG-IQ data collection device (DCD) is used to collect statistics
 

Periodical check done from BIG-IQ CM 

A Periodical Check is used when "useAppIqDcd": is set to false,

To view the BIG-IQ Stats API configuration, enter the following command:

restcurl /cm/adc-core/current-config/stats-refresh

By default each 5 minutes BIG-IQ send set of REST API POST  requests to gather  statistics related to BIG-IP objects. We can view requests by collecting packet capture on loopback interface

tcpdump -i lo -s0 -w /var/tmp/rest.pcap port 8100 -v

HTTP request example for pool statistics:

POST /mgmt/shared/inflate?em_server_ip=2.23.207.168&em_server_auth_token=<auth_token> HTTP/1.1 , JavaScript Object Notation (application/json)

JavaScript Object Notation: application/json
    Object
        Member Key: items
            Array
                String value: https://localhost/mgmt/tm/ltm/pool/stats?$top=1
            Key: items


NOTE:  'em_server_ip=2.23.207.168' is just a method that BIG-IQ implements to hash device group names into IPv4 addresses. It is not an IP address and does not correspond to any real communication - it's just a numeric hash of a string.

BIG-IQ data collection device (DCD) is used to collect statistics

This is used when  "useAppIqDcd": is set to true 

CONDITIONS

  • At least one DCD node added 
  • AVR provisioned on BIG-IP
  • BIG-IP system must have Statistics collection enabled 
  • TCP 443 port opened between DCD to BIG-IP permitted 

Analytics iapp is installed and it is responsible for collecting status of objects  and storing them with other statistics locally in /var/local/ucs/f5.bigiq-analitics... .  BIG-IQ DCD is establishing connection to BIG-IP on 443 and collecting file then stores it in elasticsearch database  events_tl0* index

BIG-IQ Analytics iapp template part responsible for pushing status:

....SNIP....
# We want to push state of Node/Virtual/Pool/PoolMembers only once in every 2 minutes
        set timeToPushState "0"
        set lastTimePushedState ""
        catch {set lastTimePushedState [exec cat /var/tmp/lastTimePushedState.txt]}
        if {"$lastTimePushedState" == ""} {
            set timeToPushState "1"
            exec echo "$date" > /var/tmp/lastTimePushedState.txt
        } else {
            set timePassed [expr {$date - $lastTimePushedState}]
            if {"$timePassed" >= 120} {
               set timeToPushState "1"
               exec echo "$date" > /var/tmp/lastTimePushedState.txt
            }
        }

/var/tmp/lastTimePushedState.txt contains push status time
