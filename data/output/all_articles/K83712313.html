Description

  • Client to Client communications in the non-default route domain does not work
  • Once VPN tunnel is successfully established and when two users with lease pool IP tries to communicate with each other for an application such as VoIP, communication between two lease pool IPs fails. 
  • PINGing to lease pool IP from each client may fail with with ICMP "Destination unreachable (Network unreachable)"
  • UDP to lease pool IP from each client fails with with ICMP "Destination unreachable (Network unreachable)"
  • TCP to lease pool IP from each client fails with reset cause "Route domain not reachable (strict mode)

Environment

  • APM
  • Edge client
  • Network Access (VPN) configured with Lease Pool
  • "Route Domain and SNAT selection" with non-default route domain is configured in Access Policy VPE

Cause

  • APM Network Access currently does not support client to client communication if configured in a non-default Route Domain

Recommended Actions

  • Make RD0 the parent of the non-default Route Domain assigned in "Route Domain and SNAT selection"
    or
  • Remove non-default route domain configuration from the Route Domain and SNAT selection in VPE if possible
     
  • If the above options are not possible, assign the connectivity profile to the non-default route domain with the steps below:
    1. Go to Network > Route Domains, click your non-default route domain
    2. Move the connectivity profile (that is assigned to the virtual server) from Available list to the VLANs Members
    3. Hit Update
