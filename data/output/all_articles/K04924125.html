Known Issue

The Traffic Management Microkernel (TMM) may restart when you modify the JPEG-XR Quality Factor setting in the web application policy.

This issue occurs when all of the following conditions are met:

  • The AAM module is licensed and provisioned on the BIG-IP system.
  • Request queueing is enabled in the pool settings.
  • The Optimize image to JPEG setting is enabled in the web application policy.
  • The Optimize For Client setting is enabled.
  • You modify the JPEG-XR Quality Factor setting while the BIG-IP AAM system is processing traffic.

Impact

Traffic is disrupted while TMM restarts. The system fails over if configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP AAM system experiences an unexpected failover event.
  • A traffic disruption occurs when you modify the web application policy.
  • The tmm process generates a core file in the /shared/core/ directory.

Workaround

To work around this issue, you can disable image optimization to the client.  To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Acceleration > Web Application > Policies.
  3. Select the name of the policy.
  4. Select the affected node in the policy tree (JPEG).
  5. Select Acceleration Rules.
  6. Select the Assembly tab.
  7. Clear the Enabled box for the Optimize For Client setting.
  8. Select Save.
  9. Select Publish, then Publish Now.
