K13911: The VIPRION 2400 and VIPRION 4400 platforms do not support disabling Clustered Multiprocessing globally

Topic

The VIPRION 2400 and VIPRION 4400 platforms, including Virtual Clustered Multiprocessing (vCMP) guests, do not support globally disabling Clustered Multiprocessing (CMP).

Note: If you attempt to disable CMP globally on the VIPRION 2400 or VIPRION 4400 platforms by configuring the BIG-IP db key Provision.tmmCount setting to 1, this option is silently ignored and CMP processing continues to take place.

Workaround

To work around this issue, you can disable CMP on individual virtual servers. To do so, perform the following procedure:

Impact of workaround: Traffic for the virtual servers for which CMP has been disabled is re-directed to tmm0.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Disable CMP on the virtual server. Replace <virtual server> with the name of the virtual server you want to modify.

    modify /ltm virtual <virtual-server> cmp-enabled no

  3. Save the change by typing the following command:
    • BIG-IP 10.1.0 and later:

      save /sys config

    • BIG-IP 10.0.x:

      save config

On BIG-IP versions that support the bigpipe command, you can use the following command to disable CMP on a specific virtual server. Replace <virtual-server> with the name of the virtual server you want to modify:

bigpipe virtual <virtual-server> cmp disable

You can save this configuration with the following command:

bigpipe save
