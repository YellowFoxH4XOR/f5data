K000160579: TS Cookie may be internally disabled on ePVA/PVA platforms without DoS hardware support

Issue

Beginning in BIG-IP 17.1.3.2 and in versions that include the fix for Bug ID 1671149, BIG-IP performs additional runtime validation before enabling TS Cookie on ePVA/PVA-offloaded flows.

This validation prevents scenarios in which TS Cookie is initially processed in software during connection setup, but the connection is later offloaded to hardware on platforms or licenses that do not support the required DoS hardware capabilities.

Old Behavior

In versions prior to BIG-IP 17.1.3.2, when TS Cookie was enabled, it could be processed in software during connection setup. After the connection was established, the flow could become eligible for PVA offload and transition to hardware without validating whether the platform or license supported TS Cookie handling in hardware.

If the platform or license did not include the required DoS hardware capabilities, such as with a TurboFlex Basic license, TS Cookie translation was not performed in ePVA. As a result, offloaded connections could experience incorrect TS Cookie handling.

This behavior applies to PVA-capable platforms where the virtual server is configured as a Performance (FastL4) type with ePVA acceleration enabled. In these environments, TS Cookie handling might appear correct during the initial handshake or early packets processed in software, but become incorrect after the flow is offloaded to PVA hardware.

New Behavior

Beginning in BIG-IP 17.1.3.2, when TS Cookie is enabled, the system performs additional checks to verify that the platform supports the required DoS hardware capabilities.

This change applies specifically to PVA-capable platforms where the virtual server is operating with ePVA acceleration.

If the platform lacks the necessary DoS hardware capability, or if the installed license does not support the required hardware acceleration, the system will internally disable TS Cookie, even if it remains configured as enabled.

In these cases, TS Cookie processing is not performed, and the system continues normal ePVA connection handling without TS Cookie translation.

This behavior prevents situations in which TS Cookie is partially handled in software during connection setup and then incorrectly offloaded to hardware that does not support TS Cookie generation or translation. As a result, the change improves system stability and helps prevent connection handling issues on PVA-capable platforms using FastL4 (Performance) virtual servers without the necessary DoS hardware support.
