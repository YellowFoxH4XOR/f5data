Topic

If you configure multiple servers for RADIUS authentication or RADIUS dynamic group mapping, FirePass performs the following authentication sequence:

  1. FirePass sends an Access-Request packet to the primary RADIUS server.
  2. If there is no response from the RADIUS server within the number of seconds configured in the Timeout field, FirePass sends another Access-Request packet.

    Important: If the RADIUS server responds, but sends an invalid response, FirePass proceeds to Step 4. A valid response is an Access-Accept, Access-Reject, or Access-Challenge packet.
  3. Step 2 repeats until the number of retries configured in the Retries field has been reached.
  4. If a secondary RADIUS server is configured, FirePass sends an Access-Request packet to the secondary RADIUS server.
  5. FirePass performs Steps 2 through 3 with the secondary RADIUS server.
  6. If a tertiary RADIUS server is configured, FirePass sends an Access-Request packet to the tertiary RADIUS server.
  7. FirePass performs Steps 2 through 3 with the tertiary RADIUS server.
  8. If no response is received from the final configured RADIUS server, RADIUS authentication fails and FirePass proceeds to the next authentication or dynamic group mapping method configured.

If at any point FirePass receives an Access-Accept or Access-Reject response, FirePass accepts or rejects the users’s authentication attempt accordingly and the process is complete. For example, if the primary RADIUS server responds with an Access-Reject packet, FirePass does not attempt to contact the secondary or tertiary servers.

In addition, FirePass supports Access-Challenge (RADIUS code 11) responses. For more information, refer to K9630: FirePass support for RADIUS challenge/response authentication.
