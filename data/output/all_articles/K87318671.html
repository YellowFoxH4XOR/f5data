Description

Under certain situations, performance reports in the Configuration Utility and Qkview may show future date.

Possible symptoms:

  • Performance reports show future date or stop being updated
  • Qkview graphs show future date and may not be updated even if you generate a new qkview later
  • The log shows that the BIG-IP had wild time swing in the past.

    For example:
    # date
    Wed Aug  31 12:00:00 PDT 2022                                       <=== today is 2022-08-31

    # grep boot_marker /var/log/webui.log
    2026-09-29T05:14:14-07:00 localhost notice boot_marker : <volume>   <=== 4 years ahead
    2026-09-29T05:33:28-07:00 localhost notice boot_marker : <volume>   <===
    2027-04-02T10:18:19-07:00 localhost notice boot_marker : <volume>   <=== 5 years ahead
    2027-04-02T11:33:03-07:00 localhost notice boot_marker : <volume>   <===
    2022-01-18T04:53:18-08:00 localhost notice boot_marker : <volume>
    2022-01-28T10:39:23+08:00 localhost notice boot_marker : <volume>
    2022-01-21T02:07:41+08:00 localhost notice boot_marker : <volume>
    2022-01-25T04:55:08+08:00 localhost notice boot_marker : <volume>
    2022-10-24T23:02:28+08:00 localhost notice boot_marker : <volume>   <=== a few months ahead
    2023-10-25T00:22:41+08:00 localhost notice boot_marker : <volume>   <=== 1 year ahead
    2022-04-03T02:46:08+08:00 localhost notice boot_marker : <volume>

    2022-08-30T08:05:12+08:00 localhost notice boot_marker : <volume>
    2022-09-12T13:06:46+08:00 localhost notice boot_marker : <volume>   <=== 12 days ahead

Environment

  • BIG-IP

Cause

Possible causes:

  • NTP is not setup or NTP servers not reachable for a period of time
  • Date/time was manually changed back and forth
  • Software and hardware clock are not in sync
If the BIG-IP ran with a future date in the past, the system will contain statistics of future date. This confuses statsd and merged, and they will stop updating statistics.

Recommended Actions

  1. Make sure NTP is configured and working properly. For more information, refer to:
    K3122: Using the BIG-IP Configuration utility to add an NTP server
    K13380: Configuring the BIG-IP system to use an NTP server from the command line (11.x - 16.x)
     
  2. Make sure the software clock and hardware clock are in sync by following K82503883: How to sync software clock to hardware clock.
     
  3. To allow the BIG-IP to collect new statistics, clear the RRD files by following K11461022: Removing the BIG-IP dashboard utility's RRD data files.
