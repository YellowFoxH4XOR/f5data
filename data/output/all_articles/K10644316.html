Known Issue

Policy synchronization may fail when the Machine Cert Auth agent uses a custom Certificate Authority (CA) profile.

This issue occurs when all of the following conditions are met:

  • You create a custom CA profile.
  • You configure an access profile access policy to use the Machine Cert Auth agent referencing the custom CA profile.
  • You initiate access policy synchronization.

Impact

The access policy fails to synchronize.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When initiating an access policy synchronization, an error message similar to the following examples is displayed:

    • err mcpd[<pid>]: 01070710:3: Database error (13), Cannot update_indexes/checkpoint DB object, class:certificate_summary status:13 - EdbCfgObj.cpp, line 127
    • err mcpd[<pid>]: 01070710:3: Database error (65), Can't set attribute value, type:certificate_summary attribute:name status:65 len:27value:/<partition>/<ca certificate name>.crt.0 - EdbCompositeObj.cpp, line 720.
  • The access policy is not synchronized to the peer BIG-IP APM device.

Workaround

To work around this issue, you can import the custom CA certificate bundle on the BIG-IP APM peer devices prior to synchronization.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the peer BIG-IP APM device.
  2. Navigate to System > File Management > SSL Certificate List.
  3. In the Import Type box, select the type of your custom CA certificate from the drop down menu.
  4. In the Certificate Name box, select Create New and type a name for the certificate in the text box.
  5. In the Certificate Source box, select the type of your custom CA certificate (Upload File or Paste Text).

    Note: When Upload File is selected, click Choose File to select the file from your local device.

  6. Click Import.
