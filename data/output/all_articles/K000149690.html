K000149690: Management IP address is set to 127.0.0.1 on Microsoft Azure cloud

Published

  • BIG-IP LTM: 17.1.X, 16.1.X, 17.1.2, 17.1.1, 17.1.0, 16.1.5, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0
  • BIG-IP Cloud Edition
Source
https://my.f5.com/manage/s/article/K000149690

Description

After upgrading your BIG-IP system, the management IP address is reset to 127.0.0.1 and you lose access to it.
 

Environment

  • Microsoft Azure. This issue is found on the Azure cloud, but could also occur on other clouds and on prem devices when conflicting routes are configured:
  • Use DHCP on management interface
  • Cloud Failover Extension. For more information on CFE, refer to Cloud Failover Extension Overview on Clodudocs.
  • BIG-IP upgrade
     

Cause

This issue is due to conflicting routes on the management interface. As part of the prerequisites for configuring Azure CFE, you need to create management route for Azure Metadata service of 169.254.169.254/32. For more information, refer to Azure CFE Prerequisites on Clouddocs.

This can result in conflicting routes (once from DHCP and once from the static management), causing an issue and the management IP is reset to 127.0.0.1 

Recommended Actions

To avoid this issue, F5 recommends:

  • if possible, do not use DHCP for management interfaces
  • If DHCP is configured for management interface, avoid creating management routes that overlap with any existing routes

After the issue occurs, perform the following procedure to re-configure the management IP and route:

  1. Re-configure the management IP

tmsh create /sys management-ip <address>/<netmask>

  1. Configure a management route
tmsh create /sys management-route <name> network <destination network>/<netmask> gateway <management gateway>

Replace <name> with the name you want to use to identify this route. Replace <destination network>/<netmask> with the IP address and netmask of the network you are routing to. Replace <management gateway> with the IP address of the router used to access the destination network.

  1. Save the configuration

tmsh save /sys config
