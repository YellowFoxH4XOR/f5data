Known Issue

The Traffic Management Shell (tmsh) list /ltm rule command may not generate an error message.

This issue occurs when all of the following conditions are met:

  • An iRule exists in a different folder than the current folder context (for example, /Common/Foo/rule1).
  • You perform an iControl REST query or run the tmsh list /ltm rule command for a non-existent iRule.

Impact

When using the iControl REST query or tmsh list /ltm rule command for non-existent iRules, the system fails to display an error message.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You notice that an iControl REST query or tmsh list /ltm rule command that references non-existent iRules runs successfully and returns empty output.

    If an iRule named rule1 exists in the /Common/Foo folder, running a query for a non-existent iRule named rule2 returns empty output instead of generating an error message.

    For example, the output appears similar to the following:

    [root@bigip:Active:Standalone] config # tmsh list /ltm rule rule2
    [root@bigip:Active:Standalone] config #

    However, this example query should fail with an error message similar to the following:

    [root@bigip:Active:Standalone] config # tmsh list /ltm rule rule2
    01020036:3: The requested iRule (rule2) was not found.
