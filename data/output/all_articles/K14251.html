Issue

Error Message

VCIFS-3-NOTE-VSERVDUPINF:: [internal-(interface number)] connection from (IP address) with 1 previous connections still being run down.

In this error message, note the following:

  • <interface number> is an internal ARX interface number.
  • <IP address> is an ARX systems internal IP or proxy-IP address.

For example:

VCIFS-3-NOTE-VSERVDUPINF:: [internal-3] connection from 169.254.230.72 with 1 previous connections still being run down

Message Location

You may encounter this message in the following location:

  • The ARX syslog

Description

This message occurs when the following condition is met:

  • An XIPLIP inconsistency is present on the ARX system or its peer, and a failover is attempted.

The XIPLIP inconsistency is due to the ARX system (or its redundant peer) having an inconsistency with its mapping of internal IP addresses, proxy-IP addresses, or NSM-core IDs.

Impact

High availability may not be fully functional and a failover may not be successful.

Recommended Actions

To recover from the XIPLIP inconsistency, you must remove the affected ARX systems configuration and reconfigure the device.

Impact of workaround: Peer device and high availability will not be available during this process.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enable config mode by typing the following command:

    config
  4. Review the configuration by typing the following command:

    show running-config
  5. For recovery purposes, save the running configuration using the following command syntax:

    copy running-config configs [filename].cfg

    For example:

    copy running-config configs recovery_running.cfg
  6. For recovery purposes, save the global configuration using the following command syntax:

    copy global-config configs [filename].cfg

    For example:

    copy global-config configs recovery_global.cfg
  7. Delete the ARX system startup configuration by typing the following command:

    Important: Once the ARX startup configuration has been deleted and the system is restarted, console access may be required to complete the recovery process.

    delete startup-config

    Note: This command removes the ARX global and local configurations from the ARX system.
  8. Reload the ARX system to complete the configuration removal process by typing the following command:

    reload
  9. Log in to the ARX CLI using the console or out-of-band management IP.
  10. Enable privileged mode by typing the following command:

    enable
  11. Re-enable the previous configuration using the running configuration saved in Step 5, using the following command syntax:

    run configs <running-config-name>

    For example:

    run configs recovery_running.cfg

  12. To verify that the ARX running configuration is complete, type the following command:

    show running-config

    Note: The ARX global configuration will download from the peer device after the initial rendezvous is complete    .

Supplemental Information

  • For more information about the commands previously outlined, refer to the ARX CLI Reference Guide
