Known Issue

Oracle Access Manager (OAM) ASDK log files may grow to consume excessive disk space.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an OAM AAA server.
  • Lack of purging by the BIG-IP APM system causes oblog.log files to accumulate in the /var/log directory over time.

Impact

Accumulated oblog.log files may eventually consume available disk space.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP APM system becomes unstable.
  • Output from the df -h command indicates that the size of the /var partition is increasing.
  • The /var/log directory contains outdated oblog.log files.

Workaround

To work around this issue, you can manually delete excessive or outdated oblog.log.* files, or you can reduce the log level in order to reduce the size of the log files. To reduce the log level, perform the following procedure:

Impact of workaround: Access management for some third party integrations (such as OAM) is unavailable while the eam service restarts.

  1. Log in to the BIG-IP APM command line.
  2. Edit the oblog_config.xml file using a text editor such as vi or pico. To locate the file, use the following path:

    /config/aaa/oam/<partitionname>/<oamserver>/<accessgate>/oblix/config/oblog_config.xml
  3. Locate the entry for the log threshold level, which should appear similar to the following example:

    <NameValPair ParamName="LOG_THRESHOLD_LEVEL" Value="LOGLEVEL_WARNING" />
  4. To decrease the amount of logging, change the log level value.

    The following table describes the level values that are available:
    LevelDescription
    LOGLEVEL_FATALSerious error, possibly a program halt
    LOGLEVEL_ERRORA transient or self-correcting problem
    LOGLEVEL_WARNINGA problem that does not cause an error
    LOGLEVEL_INFOThe current state of the component
    LOGLEVEL_DEBUG1Basic debugging information
    LOGLEVEL_DEBUG2Advanced debugging information
    LOGLEVEL_DEBUG3Logging of performance-sensitive code
  5. Save the changes, and exit the text editor.
  6. For the change to take effect, restart the eam service by typing the following command:

    tmsh restart sys service eam
