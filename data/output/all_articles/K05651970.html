Description

Web application stops working or some of elements are not displayed after inserting/modifying Content-Security-Policy HTTP header.

Environment

  • Inserting / modifying Content-Security-Policy HTTP Header via iRule or LTM policy
    OR
  • Inserting / modifying Content-Security-Policy HTTP Header in web application

Cause

If Content-Security-Policy policy is miss-configured web browser will block web application or selected elements like fonts, images etc.

Recommended Actions

Review error messages in browsers Console (F12):
Web BrowserPath
Mozilla FirefoxFirefox Menu > Web Developer > Browser Console
Google ChromeChrome Menu > More Tools > Developer Tools
Microsoft EdgeEdge Menu > F12 Developer Tools
Microsoft Internet ExplorerGear Menu > F12 Developer Tools

Note: Microsoft announced the end of support for Internet Explorer on June 15, 2022 . You should use supported browsers such as MS Edge, Chrome or Firefox.


In most cases error messages should lead to miss-configured object.
Adjust Content-Security-Policy HTTP Header configuration accordingly.

Example:
Content Security Policy: The page’s settings blocked the loading of a resource at data:image/png;base64,iVBORw0KGgoAAAANSU… (“img-src”).
Error message points to img-src fetch directive:
img-src * - Wildcard, allows any URL except data: blob: filesystem: schemes.

In this case problem can be fixed by adding 'data:':
img-src * data:

Note: Please note that every change in Content-Security-Policy, should be consulted with application and security team.
