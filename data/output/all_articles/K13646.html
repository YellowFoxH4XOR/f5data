Known Issue

The BIG-IP system deploys an incorrectly-configured virtual server for Microsoft Lync 2010 service. This issue occurs when the following condition is met:

  • The affected virtual server is configured when deploying an Application Service that uses the default f5.microsoft_lync_server_2010 iApp template.

The f5.microsoft_lync_server_2010 iApp template can be used to create a virtual server that processes SIP traffic between the Microsoft Lync clients and the Microsoft Lync Server 2010. When you deploy an Application service that uses the f5.microsoft_lync_server_2010 iApp template, the BIG-IP system uses the information provided in the Microsoft Lync Server Consolidated Edge Virtual Questions - External Interface section to configure the virtual server with the name <AppServiceName>_consolidated_edge_external_ip_access, and incorrectly assigns HTTP, SSL, and cookie persistence profiles to the virtual server.

Impact

The BIG-IP system is unable to process SIP traffic between the Microsoft Lync client and server.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H382808 on the Diagnostics > Identified > Low screen.
  • The Microsoft Lync client SIP communication feature may not function as expected.
  • The virtual server <AppServiceName>_consolidated_edge_external_ip_access is incorrectly associated with HTTP, SSL, and cookie persistence profiles, which is inappropriate for SIP traffic processing.

Workaround

To work around this issue, you can disable Strict Updates for the Application Service using the f5.microsoft_lync_server_2010 iApp template and manually configure the affected virtual server with the appropriate profile. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the Configuration utility.
  2. Navigate to iApp > Application Services > Application Service List.
  3. Click the name of the affected Application Service.
  4. From the Application Service box, select Advanced.
  5. Clear the Strict Updates check box.
  6. To save the change, click Update.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Service List.
  8. Click the name of the affected virtual server.

    (The name is typically <AppServiceName>_consolidated_edge_external_ip_access.)

  9. Click the Resources tab.
  10. From the Default Persistence Profile box, select source_addr (or any desired source address persistence profile).
  11. To save the change, click Update.
  12. Click the Properties tab.
  13. From the HTTP Profile box, select None.
  14. From the SSL Profile box, select None.
  15. To save the changes, click Update.
