K000161942: Active CM has banner “Secondary is not actively streaming. Postgres may be down.” and Standby CM GUI stuck in “Waiting for BIG-IQ services to become available…”

Type
Support Solution
Published
2026-06-28
Updated
2026-07-14
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.0
Source
https://my.f5.com/manage/s/article/K000161942

Description

  • Active BIG-IQ CM displays banner “Secondary is not actively streaming. Postgres may be down.” and Standby CM GUI is stuck on “Waiting for BIG-IQ services to become available…”.
  • Standby CM /var/log is at 100% capacity.  /var/log/elasticsearch/eslognode.log file consuming highest disk space. You see below error in the log file continuously written.
    [2026-06-01T13:30:30,569][WARN ][o.e.g.MetaStateService ] [217e6266-1be5-4adb-9da1-ee0610e45672][[statistics_tl3_default-group_2025-001-00/FmWR9QCxR9K0kFey2oiHMA]]: failed to write index state
    java.nio.file.FileSystemException: /var/config/rest/elasticsearch/data/nodes/0/indices/FmWR9QCxR9K0kFey2oiHMA/_state/state-95.st.tmp: Read-only file system
    at sun.nio.fs.UnixException.translateToIOException(UnixException.java:91) ~[?:?]
    at sun.nio.fs.UnixException.rethrowAsIOException(UnixException.java:102) ~[?:?]
    ---Small snippet of the log---

Environment

  • BIG-IQ Virtual Machine
  • 8.4.0

Cause

Power outage or host level activity on the Standby CM. The logs message indicates the CM went into read-only state. This can be caused due to file system corruption due to power outage or an activity done on host level. Since the log message is continuously written it consumes entire disk space which causes the issue described above.

Answer/Recommended Actions

  1. Freed up disk space by emptying the log file. Do not delete the log file. You can run below command.
    # > /var/log/elasticsearch/eslognode.log

  2. After that you need to reboot that CM.
    # reboot

Additional Information

After freeing up disk space you may still see the described log message being written int the eslognode log file. Additionally you may not see any connection from netstat output for postgres port 5432 (netstat -pano | grep 5432), even though postgres service is up while checking bigstart status postgres. Rebooting the CM will fix this issue.
