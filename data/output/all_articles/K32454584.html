Description

There are times when the standard persistence profiles (source address, cookie, SSL, etc.) cannot reliably direct connections to the same pool member. For example, there is a proxy in-between the original client and BIG-IP. BIG-IP would see the source IP address of the proxy, rather than the original client. 

To workaround this issue requires a custom solution by way of iRules and universal persistence. Although F5 Support does not provide custom solutions with iRules, this is an often asked question that can be resolved with some basic knowledge of iRules from the BIG-IP administrator.

Environment

Relevant environmental factors specific to the topic.

  • BIG-IP LTM
  • HTTP(s) Virtual Server requiring persistence
  • Proxy in-between original client device and BIG-IP

Cause

See below for iRule utilizing the X-Forwarded-For header to create a universal persistence record. Subsequent connections from the same client IP address to the same pool member specified in the persistence record.

Recommended Actions

  1. Configure iRule to persist using the X-Forwarded-For header and universal persistence. 
    # Name: irule_xff_uie
#
# To be used with UIE Persistence Profile
#
# Checks HTTP Request for 'X-Forwarded-For' header and if exists takes the first 'X-Forwarded-For' IP address as sets as
# Persist identifier.
# If the 'X-Forwarded-For' header does not exist then the client IP address is set as Persist identifier.

when HTTP_REQUEST {
    if {[HTTP::header X-Forwarded-For] != ""} then {
persist uie [lindex [ split [lindex [HTTP::header values X-Forwarded-For] 0] "," ] 0]
    } else {
persist uie [IP::client_addr]
}
}
  2. HTTP or HTTPS virtual server with the iRule configured. For HTTPS Virtual Servers, ensure TLS is terminated using a client-ssl profile. 
    root@(localhost2)(cfg-sync In Sync)(Active)(/Common)(tmos)# list ltm virtual vs_irule destination pool rules
ltm virtual vs_irule {
    destination 10.2.115.163:80
    pool pool_nginx
    rules {
        irule_xff
    }
}
root@(localhost2)(cfg-sync In Sync)(Active)(/Common)(tmos)# list ltm pool pool_nginx
ltm pool pool_nginx {
    members {
        10.2.115.178:80 {
            address 10.2.115.178
        }
        10.2.115.179:80 {
            address 10.2.115.179
        }
    }
}

Additional Information

As with processing any iRule, be mindful of the additional load on BIG-IP.

With any type of persistence, processing a higher number of connections will result in a greater imbalance of connections over time. No load balancing decision is made when the same client is passed to the same pool member.
