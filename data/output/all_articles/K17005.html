Known Issue

Secure Sockets Layer (SSL) certificate signing requests (CSR) configured to use Subject Alternative Names (SAN) cannot be created in non-default administrative partitions when using the Configuration utility.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration has multiple administrative partitions.
  • You create an SSL CSR in a non-default administrative partition using the Configuration utility (/Common is the default partition).
  • You have configured the CSR SAN option.

Impact

The SSL CSR is created in the default partition.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You create a new CSR using the Configuration utility, and the CSR appears to be missing.
  • You create a new CSR using the Configuration utility, and the configuration object resides in the wrong administrative partition.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to create the CSR. For more information, refer to K13471: Creating SSL SAN certificates and CSRs using the Configuration utility or tmsh.
