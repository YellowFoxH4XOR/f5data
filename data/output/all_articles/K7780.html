Known Issue

This is the result of a known issue. The standby unit of a redundant BIG-IP LTM configuration can crash if it receives an ICMP need to fragment packet through a mirrored FastL4 virtual server connection from the active BIG-IP LTM system.

This issue occurs when the active unit of a BIG-IP LTM system receives a client-side ICMP need to fragment packet on a virtual server configured with connection mirroring and a FastL4 profile. The crash occurs when the standby BIG-IP LTM attempts to process the ICMP need to fragment packet that was received from the active BIG-IP LTM system.

F5 Product Development is tracking this issue as CR83689, and it was fixed in BIG-IP LTM versions 9.3.1 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.
