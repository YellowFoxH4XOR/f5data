Description

Some pentest may flag that the Server HTTP header/banner for the BIG-IP web GUI is divulging the type and the version of the remote web server in use, and you may want to remove it to address the said vulnerability findings.

Environment

  • BIG-IP Configuration utility
  • Server HTTP header/banner

Cause
None

Recommended Actions

None. It is not possible to remove the Server HTTP response header for the BIG-IP web GUI (Configuration Utility).
 

Additional Information
Our Product Development team have advised that even if we were to modify the HTTPD source code to not include the 'Server' header, someone would still be able to connect to our GUI and would then know they're connected to a BIG-IP device. After a few minutes research, they could then determine that the BIG-IP is running on Apache. So we're not hiding much by just removing the Server header.

Anyway, this (Apache Server HTTP response header) is only seen when accessing the BIG-IP web GUI, which is control plane. It is not seen for production traffic passing through tmm, which is data plane. So in terms of 'possible' exposure, only those who have access to the BIG-IP web GUI will see/know about this 'Server' HTTP header.

By default, all IP addresses (both mgmt and self-IP, so long as the BIG-IP is reachable) are allowed to connect to the BIG-IP web GUI. To restrict access to the BIG-IP web GUI thru the management-IP address only, you can define a list of 'allowed' IP addresses in the httpd conf following the instructions in K13309

In addition to restricting GUI access to trusted sources only, you may also want to apply other ways of securing access to your BIG-IP. See K13092 for more info.
