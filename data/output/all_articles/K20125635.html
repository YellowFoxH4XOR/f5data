Description

System goes offline on ASM restart, even after disabling sys daemon-ha bd running, for example by following the procedures in:

  • K13484: Disabling the BIG-IP ASM system marks the system offline

This occurs immediately when re-enabling sys daemon-ha bd running. You may observe logs similar to the following in /var/log/ltm:

info sod[44006]: 0114002b:6: HA proc_running bd enabled.
warning sod[44006]: 01140029:4: HA proc_running bd fails action is go offline and down links.
notice sod[44006]: 010c0050:5: Sod requests links down.
notice sod[44006]: 010c006d:5: Leaving Standby for Offline for ha table offline_cond.
notice sod[44006]: 010c0054:5: Offline for traffic group traffic-group-1.
notice sod[44006]: 010c003e:5: Offline

Environment

  • ASM
  • HA

Cause

/dev/shm is mounted twice:

# mount | grep shm
tmpfs on /dev/shm type tmpfs (rw,noatime,seclabel)
none on /dev/shm type tmpfs (rw,noatime,seclabel)   <---

This is a result of issuing the mount -a command while running a version affected by the following bug:

  • Bug ID 914645

Recommended Actions

To resolve this issue, unmount the duplicate mount, restart ASM, and avoid using the mount -a command on versions affected by bug ID 914645.

  1. Unmount the duplicate mount of /dev/shm:

    umount -l /dev/shm

  2. Restart ASM

    tmsh restart sys service asm

    Note: This may cause a failover, so a maintenance window is recommended.

Additional Information

The /dev/shm mount is a shared area of memory that numerous processes use (in this case, bd and sod), so there can be various consequences.
