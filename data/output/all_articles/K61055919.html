Known Issue

The aced process may leak file descriptors or memory, produce a core file, and restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an access policy that uses SecurID authentication.
  • The aced process runs for an extended period of time without a restart of the process.

Impact

SecurID authentication may fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • New access session attempts to require SecurID authentication are unable to authenticate.
  • When a user attempts to log in, the system displays a message similar to the following example:

    err apd[<pid>]: 01490122:3: 136c67a7: SECURID module: authentication with '<username>' failed: Exception: Could not bind to port. , code: -1, state: SECURID_AUTH_STATE_ACCESS_DENIED

  • The number of open file descriptors in use by the aced process increases over time. The following command will display the number of open file descriptors used by the aced process.

    lsof -p `pidof aced` | wc -l

  • An aced core file is generated to the /shared/core directory.
