Description

When a virtual server is configured with multiple security profiles — ASM, Bot Defense, and DoS Protection — administrators may need to understand how each module functions and in what order they are applied. There is no pre-determined sequential order and each can work independently.

However, the purpose of this article is to clarify the purpose of each protection method and their logical processing order based on function.

Environment

  • ASM/AdvWAF
  • Supported versions of Bot Defense, DoS, and ASM/AdvWAF configured on the same virtual server.

Cause

Confusion may arise when traffic is handled differently by each security protection method, or when administrators need to understand which module is responsible for a specific blocking or mitigation action.

Bot Defense:

  • Purpose: Identifies and blocks automated clients such as bots, scrapers, DoS tools, headless browsers, and vulnerability scanners.
  • Trigger: Automated client detected
  • Core Question: "Is this client a human or a bot?"
  • How it works: Uses JavaScript challenges, bot signatures, and device identification to distinguish automated clients from legitimate users.
  • Processing Order: First
  • Reference: KB K42323285: Overview of the unified Bot Defense profile

DoS L7 Protection (Denial of Service):

  • Purpose: Mitigates Denial of Service attacks by monitoring and controlling abnormal traffic rates and behaviors.
  • Trigger: Abnormal traffic volume or behavior
  • Core Question: "Is this traffic volume or behavior abnormal?"
  • How it works:Layer 7
    • (L7) DoS: Tracks HTTP request rates, behavioral anomalies, and applies mitigation when thresholds are exceeded.
    • Layer 4 (L4) DoS: Handles volumetric attacks at the transport layer. Because it operates at L4, it fires before L7 protections when enabled.
  • Processing Order: Second (L7 DoS); before all three modules if L4 DoS is enabled
  • Reference:  K13410341: Overview of L7 DDoS attack protection (14.x - 17.x)

Note: L4 DoS is not a direct part of ASM and is handled separately from the L7 security stack, but is being brought in here for reference to provide some clarity. L4 DoS operates at the Transport Layer and fires before all three L7 protections listed above.

ASM (Application Security Manager)

  • Purpose: Protects against application-layer attacks in HTTP request and response content.
  • Trigger: HTTP content violates security policy
  • Core Question: "Does this HTTP request or response violate the application security policy?"
  • How it works: Inspects HTTP/HTTPS traffic against a defined security policy and attack signatures, covering threats such as SQL injection, XSS, CSRF, parameter tampering, protocol violations, and evasion techniques.
  • Processing Order: Third
  • Reference: KB K13564890: BIG-IP ASM Operations Guide
