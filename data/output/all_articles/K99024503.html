Description

Virtual server terminate SSL handshake, and tcpdump reveals Virtual server terminate SSL handshake with following Alert:

Alert (Level: Fatal, Description: Internal Error)

SSL debug log () show failure reason as below:

warning tmm[<pid>]: 01260009:4: Connection error: ssl_shim_vfycerterr:<number>: out of memory (80)
 

Environment

  • BIG-IP
  • Virtual server
  • Client ssl with Client Authentication enabled either by:
    • Client-ssl profile enforce client authentication
    • iRule enforce client-ssl enforcing client authentication

 

Cause

One of the reasion of this error is when the client presents a certificate with more certificates in the chain then the number of objects BIG-IP is allowed to validate.
This parameter is controlled on client-ssl profile by option "Certificate Chain Traversal Depth" (shown below):

NOTE: this part of configuration can not be modified in GUI.

tmsh list ltm profile client-ssl client_auth authenticate-depth

ltm profile client-ssl client_auth {
    authenticate-depth 2
}

It can also be controlled via iRule, through instruction "SSL::authenticate depth" (example below):

when HTTP_REQUEST {
  if { [HTTP::uri] starts_with "/admin" } {
    if { [SSL::cert count] <= 0 } {
      HTTP::collect
      SSL::authenticate always
      SSL::authenticate depth 2    # <--------[!] here you can change the depth
      SSL::cert mode require
      SSL::renegotiate
    }
  }
}
 

Recommended Actions

Increase the number of certificates to be traversed (on client certificate authentication) by increasing the number on the options mentioned above.
