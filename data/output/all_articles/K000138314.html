K000138314: Is it possible to recover or backup F5OS rSeries tenants using their virtual disk file?

Type
Support Solution
Published
2024-01-22
Updated
2024-01-22
Applies to
  • F5OS
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000138314

Description

After deleting a tenant, able to restore its configuration to a newly created tenant by copying a previously backed up virtual disk file to /var/F5/system/cbip-disks/<tenant>/<tenant>.raw.

Newly created tenant has the same name as the previously deleted one.

  • Is this recommended?
  • Is this supported?

Environment

  • F5OS-A
  • Tenant creation

Cause

None

Recommended Actions

This should generally work without issue. If an existing virtual disk exists on tenant deployment, then orchestration agent will not create a new one.
vCMP works the same way. If an existing virtual disk exists, the system will re-use it.

However, this is not the recommended/documented way of backing up and restoring tenants, so it won't be fully supported.
It's unlikely, but if an issue arises as a direct result of this procedure being used, F5 Support might not be able to assist.

UCS archives are the recommended and supported method of backing up and restoring a tenant's configuration.

To minimise user actions needed in the event of re-creating/restoring a previously deleted tenant, the API could be used to create the tenant and restore a UCS file to it. That is fully supported.
