K98313013: BIG-IQ inoperative state due to configuration load error related to PostgreSQL database and rd0 - ioctl error

Type
Support Solution
Published
2020-04-22
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IQ Platforms
  • BIG-IQ
  • BIG-IQ 7000
Source
https://my.f5.com/manage/s/article/K98313013

Description

BIG-IQ Centralized Management configuration fails to load with two errors

  • Error Message 1: 

Cannot create vlan <VLAN> in rd0 - ioctl failed: File exists
Caught runtime exception, 'Cannot create vlan 'internal' in rd0 - ioctl failed: File exists' - rolling back...

  • Error Message 2:

PostgreSQL database error: ERROR:  role "<local_user>" already exists CONTEXT:  SQL statement "CREATE ROLE <local_user> LOGIN" PL/pgSQL function rbac_create_user(name) line 7 at EXECUTE
 

Environment

  • BIG-IQ Centralized Management
  • Local user was deleted or unknown
  • BIG-IQ status is INOPERATIVE in the command line

Cause

  • Possible mcp database corruption
  • Postgres Role already exists.
  • A failure in the config load caused the memory provisioning to not be honored.
  • Related to BUG ID 886657: Certain combination of actions results in the mcpd unable to load the base config after a restart, and therefore causes INOPERATIVE system.

Recommended Actions

To work around this issue, you can perform the following procedures: 
  1. Login to BIG-IQ CM command line 
  2. Enter the following command:
    tmsh load sys config verify
  3. Delete the offending local user(s) from /config/bigip_user.conf using your preferred method (vi, vim, nano or etc)
  4. Repeat step 2 and 3 until there is no PostgreSQL Error.
  5. Run command
    touch /service/mcpd/forceload
  6. Run command to force an MCP reload.
    reboot
