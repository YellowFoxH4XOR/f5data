Known Issue

The BIG-IP system may erroneously accept /var/tmp as a valid Single Configuration File (SCF) file name.

This issue occurs when all of the following conditions are met:

  • You run the tmsh save /sys config file command.
  • You specify /var/tmp as the location to create the SCF file without an explicit file name.

    For example:

    tmsh save /sys config file /var/tmp

When you use the Traffic Management Shell (tmsh) to create an SCF file in the BIG-IP system, the system saves the configuration to a flat file in the /var/local/scf/ directory with the name you specify and the extension of .scf, by default. You can choose to save the configuration file to an alternate location by specifying the desired path and file name. This issue occurs when /var/tmp, which is a symbolic link to the /shared/tmp directory, used internally by BIG-IP daemons, is specified as the desired path and file name. During the SCF creation process, the system unexpectedly overwrites the /var/tmp symbolic link with the SCF file.

Impact

The BIG-IP system fails to perform any activity that uses the /var/tmp/ directory.

Symptoms

As a result of this issue, you may encounter all of the following symptoms:

  • When you run the tmsh save /sys config file /var/tmp command, you observe an error message similar to the following example:

    Saving running configuration...
    /var/tmp
    /bin/mv: cannot stat `/var/tmp/tmsh/lu5QLe/data': Not a directory
    Unexpected Error: Failed to overwrite ("/var/tmp.tar") with file ("/var/tmp/tmsh/lu5QLe/data"exit code (1).

  • When you subsequently attempt to run the tmsh utility, you observe the following error message:

    exception: (Can't create tmsh temp directory "/var/tmp/tmsh" Not a directory) (framework/TempDir.cpp, line 140), exiting...

  • When you run the 'ls -l /var/tmp' UNIX command, the system displays the property of a regular UNIX file:

    -rw-r--r-- 1 root root 195K Mar 5 12:24 /var/tmp

    The correct output should look similar to the following example:

    lrwxrwxrwx 1 root root 13 Mar 5 14:00 /var/tmp -> ../shared/tmp

  • After you run the bigstart restart command, you observe the following error message:

    011d0002: Can not access the database because mcpd is not running.

Workaround

There is no workaround. To recover the BIG-IP system, you can re-create the /var/tmp symbolic link and perform a restart of all BIG-IP services. To do so, perform the following procedure:

Impact of procedure: The bigstart restart command temporarily interrupts traffic processing. If the system is configured as part of a high-availability pair, the device may fail over. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the command line of the BIG-IP system as the root user.
  2. Remove the /var/tmp regular UNIX file by typing the following command:

    rm -f /var/tmp

  3. Re-create the /var/tmp symbolic link by typing the following command:

    ln -s /shared/tmp /var/.

  4. Restart all BIG-IP services by typing the following command:

    bigstart restart
