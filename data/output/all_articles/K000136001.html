K000136001: Tripo service cannot restart from a crash when OAM-DB is in a non fully functional state

Type
Support Solution
Published
2023-08-29
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K000136001

Description

  • You notice that the Tripo service cannot start properly.
  • Stdout logs of Tripo shows it stopped but no successful start.
  • You also noticed that there is an issue with OAM-DB and it is not functioning normally.

Environment

  • SDC 5.x
  • Tripo
  • OAM-DB

Cause

When both OAM-DB in a site is in hang/stop state, the Tripo service will not be able re-initialize when it crashes. As soon as 1 OAM-DB is started and functioning normally, Tripo is able to be restart successfully. Script tripo_init requires OAM-DB to be up and working for it to initialize/stop the Tripo process.

 

 Recommended Actions

If OAM-DB is in a non functional state we need to get it restarted to fix the Tripo restart issue as well.

 

Additional Information

None.
