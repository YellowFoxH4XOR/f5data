Known Issue

The Traffic Management Microkernel (TMM) process may produce a core file while you are using Bandwidth Control (BWC) dynamic policies.

This issue occurs when all of the following conditions are met:

  • You are using BWC dynamic policies.
  • The max-user-rate is set at 2 GB per second or higher

Impact

The BIG-IP system temporarily fails to process traffic while the TMM process restarts. If the BIG-IP system is configured for high availability (HA), the system fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file in the /shared/core directory.
  • Your BIG-IP system logs a SIGFPE to the /var/log/tmm file at the same time TMM produces a core file and restarts.
  • In one of the /var/log/tmm log files, you observe error messages similar to the following example:

    notice BWC: App already attached, use detach first
    notice ** SIGFPE **

Workaround

To work around this issue, you can limit the BWC max-user rate to a maximum of 1 GB per second.

Impact of workaround: You will be limited to 1 GB per second for the maximum user rate bandwidth control.
