K01256175: GTM pool member dependency

Type
Support Solution
Published
2022-02-07
Updated
2023-02-21
Applies to
  • BIG-IP DNS: 15.X.X
Source
https://my.f5.com/manage/s/article/K01256175

Description

GTM pool members dependency is affected by Virtual Server status from GTM server object monitoring.

Environment

  • GTM pool member with dependency configured

Cause

In the following GTM pool member configuration
gtm pool a pool {
    members {
        ubuntu:VS1 {
            member-order 0
        }
        ubuntu:VS2 {
            depends-on {
                ubuntu:VS1 { }
            }
            member-order 1
        }
    }
    monitor tcp <====================== MONITOR
}
 

ubuntu:VS2 pool member will only go down if ubuntu:VS1 will be reported as down by GTM server object level monitoring:

gtm server ubuntu {
    addresses {
        192.168.1.1 {
            device-name ubuntu
        }
    }
    datacenter DC1
    devices {
        ubuntu {
            addresses {
                192.168.1.1 { }
            }
        }
    }
    monitor gateway_icmp <====================== MONITOR
    product generic-host
    virtual-servers {
        VS1 {
            destination 192.168.1.2:http
        }
        VS2 {
            destination 192.168.1.2:ssh
        }
    }
}

Blocking HTTP traffic to 192.168.1.2 will keep both ubuntu:VS1 and ubuntu:VS2 pool members UP since VS1 and VS2 state is determined by gateway_icmp monitor on GTM server object level.
Even though ubuntu:VS1 will go DOWN on pool member level due to 'tcp' monitor being used the dependency configuration will not consider that.

Pool member level dependency is affected by VS status from GTM server object monitoring.

Recommended Actions

None. This article is to explain the intricacies of GTM pool member configuration.

Additional Information

None.
