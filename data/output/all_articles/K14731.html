Known Issue

The zxfrd process may fail to reload the DNS Express zone database files.

This issue occurs when all of the following conditions are met:

  • A Virtual Clustered Multiprocessing (vCMP) guest runs on a single active blade in the chassis.
  • You update a DNS Express zone.

Impact

DNS Express may send DNS queries to the back-end server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The DNS Express feature does not cache zone information as expected.
  • The DNS Express feature sends DNS queries to the back-end server.
  • The BIG-IP system logs error messages to the /var/log/ltm file that appear similar to the following example:

    notice zxfrd[6156]: 01531023:5: Scheduling zone transfer in 0s for mydomain.com from 10.200.30.50.
    notice zxfrd[6156]: 0153101f:5: AXFR Transfer of zone mydomain.com from 10.200.30.50 succeeded.
    notice zxfrd[6156]: 01531023:5: Scheduling zone transfer in 10800s for mydomain.com from 10.200.30.50.
    slot1/tmm1 err tmm1[11674]: 01010225:3: Failure to query dns-express db (DB Not Ready).
    slot1/tmm err tmm[11673]: 01010225:3: Failure to query dns-express db (DB Not Ready).

Workaround

To work around this issue, you can restart the Traffic Management Microkernel (TMM) processes. To do so, perform the following procedure:

Impact of workaround: You should restart the TMM process during a maintenance window because it briefly disrupts traffic. You need to perform this workaround each time you update a DNS zone.

  1. Log in to the BIG-IP command line.
  2. To restart the TMM process, type the following command:

    bigstart restart tmm
