Topic

This article discusses the different types of Carrier-Grade Network Address Translation (CGNAT) persistence on the BIG-IP system.

Description

CGNAT is introduced in BIG-IP 11.3.0 to support large groups of translation addresses and can be configured to provide translation persistence. You can control the behavior of CGNAT translation persistence by using two settings, namely the Persistence Mode setting and the Inbound Connections setting.

CGNAT Terms

The following list serves as a reference for the CGNAT-specific terms used in this article:

TermDescription
NAT SessionAn association between the subscriber endpoint and translation endpoint.
Translation EndpointThe translation address and port used for a given NAT session, also known as a mapping.
SubscriberThe NAT client inside the SP network, subject to translation when communicating to the Internet.
Internet HostThe host on the public Internet.
Translation addressThe public address provided by the NAT.
Translation-endpoint spaceThe full set of addresses and ports available for the CGNAT to assign to subscriber sessions.
Endpoint overloadingThe ability of the same subscriber to reuse the same translation endpoint in several sessions to different Internet hosts and also different subscribers provided each Internet host they want to reach is different.
DNATDeterministic NAT
NAPTNetwork Address Port Translation
EIMPer described in RFC 4787, Endpoint-Independent Mapping (EIM) means that the same external address and port will be used for all connections from a given host if they use the same internal port.

Note: Endpoint-Independent Filtering (EIF) determines who can connect to an internal host, not EIM.

Persistence Mode

Persistence Mode is a configuration setting in a Large-Scale NAT (LSN) pool. This setting specifies how the CGNAT assigns translation endpoints for a given translation mode, for example NAPT or DNAT. CGNAT translation persistence is the ability to reuse a selected translation address or endpoint across multiple connections from the same subscriber address or endpoint. F5 CGNAT implementation supports three such persistence modes:

  • None
  • Address
  • Address-port

Note: CGNAT translation persistence should not be confused with the traditional concept of persistence associated with BIG-IP pool load balancing.

None Persistence Mode

When an LSN pool is configured to set the Persistence Mode to None, CGNAT does not attempt to preserve the translation addresses used by a subscriber. Each outbound connection may get a different translation address. This persistence mode incurs the lowest overhead and provides the best performance amongst the different persistence mode.

Address Persistence Mode

When an LSN pool is configured to set the Persistence Mode to Address, the CGNAT remembers the translation address it has chosen for a subscriber. When a new connection is established by the same subscriber, CGNAT checks for the existence of this persistence record. If the persistence record exists, CGNAT will attempt to reuse the translation address from the record. If CGNAT cannot find a suitable port for this address, it may have to use a different address. This means that CGNAT prefers to accept a connection at the expense of honoring persistence. This persistence mode incurs more overhead for each connection and therefore may slightly degrade the overall system performance.

For DNAT LSN pools (Mode is set to Deterministic), the address and ports that a subscriber can use have already been reserved. Though it is still possible that a deterministic mapping may span two translation addresses, CGNAT will prefer the same address each time.

Address-port Persistence Mode

When an LSN pool is configured to set the Persistence Mode to Address-port, the CGNAT remembers both the translation address and port of the subscriber's connection so that this endpoint may be reused on the subsequent connection. This mode provides EIM behavior. This persistence mode incurs the same overhead for each connection similar to Address persistence mode.

Inbound Connections

The Inbound Connection setting controls whether CGNAT allows connections to be established inbound to the subscriber behind the NAT. Enabling this setting also incurs a performance cost because CGNAT must perform a lookup for inbound entries on each connection to prevent endpoint overloading. This limits CGNAT from using the translation-endpoint space efficiently, but guarantees that only one subscriber address:port tuple can use a translation endpoint. Without the Inbound Connection setting enabled, endpoint overloading is possible. As a result, two different subscribers may be able to use the same translation address and port assuming they are connecting to different Internet hosts.

Since addresses and ports are already reserved to each subscriber for DNAT LSN pools, no endpoint overloading is possible between subscribers; however, a single subscriber's traffic can still leverage endpoint overloading. Enabling the Inbound Connection setting restricts this behavior. The impact may be greater for DNAT when there are only a few ports per subscriber.
