Topic

The remote logging profile allows an administrator to configure the BIG-IP AFM system to direct log information for network firewall events to a syslog server. You can use custom selected Storage Format options to log specific network firewall event data to a local (local is the BIG-IP device) or a remote syslog server. The following table lists the Storage Format fields and descriptions.

Note: Due to the possible verbosity of firewall event data, F5 highly recommends that you use a remote log server for the storage of firewall event data. 

For more information on configuring remote logging, refer to the Manual : External Monitoring of BIG-IP Systems: Implementations.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation

Description

You can configure remote logging on the BIG-IP AFM Network Firewall to log detailed network firewall events locally or remotely.  The BIG-IP AFM system reports details about events based on the entities configured in the firewall profiles and rule sets.

The following tables list the storage format fields that the system uses for remote logging when reporting BIG-IP AFM network firewall events.

acl_policy_typeThe type of acl policy (Enforced, Staged).
acl_rule_nameThe rule name of a policy where the rule triggered an event.
acl_rule_uuidThe assigned Universally Unique Identifier (UUID) to the connection where a rule of the policy triggered an event.
actionThe action taken or reported (None, Drop, Allow, Reject).
bigip_hostnameHost name of the BIG-IP system.
context_namePartition in which the virtual server resides and name of virtual server.
context_typeThe context to which the applied rule is applied (Virtual Server, Self IP, Global).
date_timeDate and time of the request (local machine time).
dest_fqdnDNS mapping of the destination IP address (when configured).
dest_geoThe packet destination location of the event to which the rule applies.
dest_ipThe destination IP address of the event to which the rule applies.
dest_ipint_categoriesThe destination IP address category match from the IP address intelligence categories.
dest_portThe destination port of the event to which the rule applies.
drop_reasonThe reason why the connection was dropped. For example: Policy, Connection Flow Miss, Bad TCP checksum.
management_ip_addressThe configured management IP address of the BIG-IP AFM system.
protocolThe corresponding numeric protocol value that was used in the connection, as specified in the rule.
route_domainThe route domain on which the policy rule was applied.
sa_translation_poolThe source address translation pool name used for translation.
