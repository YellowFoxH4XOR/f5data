Known Issue

The Traffic Management Microkernel (TMM) may restart if a connection flow terminates before an iRules LX Remote Procedural Call (RPC) has completed.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration includes a virtual server with an associated iRule.
  • A new connection is processed by the virtual server.
  • The iRule uses the iRules LX plugin to make an RPC.
  • The new connection has terminated due to either a timeout or external cause.
  • The iRules LX plugin RPC completes.

Impact

Traffic processing is interrupted while TMM restarts, and a failover event occurs if the BIG-IP system is in a high availability (HA) configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system may fail to process traffic for a brief period.
  • The BIG-IP system may fail over to another host in the device group.
  • TMM has produced a core file in the /var/core directory.

Workaround

To work around this issue, ensure that the idle timeout setting for the virtual server's protocol profile allows for longer running iRules LX plugins. For more information, refer to the following articles:

  • K7166: Changing the idle timeout for a protocol profile
  • K7606: Overview of BIG-IP idle session time-outs

Impact of workaround: Performing the recommended workaround causes your system to use more memory.
