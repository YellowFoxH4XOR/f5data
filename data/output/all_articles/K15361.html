Known Issue

The BIG-IP system incorrectly counts virtual server source addresses against Large Scale NAT (LSN) pool translation end-points. This issue occurs when all of the following conditions are met:

  • The affected LSN pool is configured to use Deterministic mode.
  • The affected LSN pool was previously associated to an active virtual server and a translation has occurred at least once.
  • The affected LSN pool is then unassociated from the virtual server.

Impact

When the affected LSN pool has been unassociated from the virtual server, the BIG-IP system continues to count these source addresses against the LSN pool translation end-points, but these translation end-points are never used. As a result, the translation space may be underutilized.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system periodically logs state information for the affected LSN pool that includes the source addresses from the previously associated virtual server.

    For example, an LSN pool is associated with VS1 (source address 10.10.10.0/24), VS2 (source address 10.10.20.0/24), and VS3 (source address 10.10.30.0/24). The BIG-IP system periodically logs state information for this LSN pool that includes the source addresses of the associated virtual servers:

    01670019:3: DNAT configuration: src: 10.10.10.0/24 10.10.20.0/24 10.10.30.0/24

    This LSN pool is then unassociated from VS2 (source address 10.10.20.0/24); however, the BIG-IP system continues to periodically log state information that includes the source address of VS2 for this LSN pool:

    01670019:3: DNAT configuration: src: 10.10.10.0/24 10.10.20.0/24 10.10.30.0/24

    The expected log entry should be without the source address of VS2:

    01670019:3: DNAT configuration: src: 10.10.10.0/24 10.10.30.0/24

Workaround

To work around this issue, you can delete the unassociated LSN pool or restart the TMM process. To do so, perform either of the following procedures:

  • Deleting the unassociated LSN pool
  • Restarting the TMM process

Deleting the unassociated LSN pool

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Carrier Grade NAT > LSN Pools > LSN Pool List.
  3. Check the unassociated LSN pool of your choice.
  4. To delete the LSN pool from the configuration, click Delete.
  5. To confirm the deletion, click Delete.

Restarting the TMM process

Impact of workaround: The BIG-IP system may temporarily fail to pass traffic during the restart of the TMM process. F5 recommends that you perform this workaround during a maintenance window.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the TMM process by typing the following command:

    restart /sys service tmm
