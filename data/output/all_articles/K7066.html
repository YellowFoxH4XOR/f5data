Virtual Local Area Network (VLAN) failsafe is a high-availability feature that allows the BIG-IP system to monitor for network failure on VLANs and take appropriate action. The following are elements describe the operation and configuration options for VLAN failsafe:

  • VLAN failsafe operation
  • VLAN failsafe traffic
  • VLAN failsafe timeout
  • VLAN failsafe action
  • Configuring VLAN failsafe
  • Best practices

VLAN failsafe operation

When you configure VLAN failsafe for a VLAN, the BIG-IP system monitors network traffic on the VLAN. If the BIG-IP system detects a loss of network traffic on the VLAN, the BIG-IP system will attempt to generate traffic by issuing Address Resolution Protocol (ARP) requests or Internet Control Message Protocol (ICMP) echo requests to nodes or the default router accessible through the VLAN.

VLAN failsafe traffic

When the BIG-IP system detects a loss of network traffic on the VLAN, it attempts to generate VLAN failsafe traffic to nodes or the default router accessible through the VLAN in the following manner:

  • After half of the VLAN failsafe timeout value has elapsed, the following actions occur:

    • ARP request for the IP address of the oldest entry in the BIG-IP ARP table is initiated
    • ICMPv6 neighbor discovery probe (only if entries exist in the BIG-IP IPv6 neighbor cache) is initiated

  • After three-fourths of the VLAN failsafe timeout value expires, the following actions occur:

    • ARP request for all IP addresses in the BIG-IP ARP table is initiated
    • ICMPv6 neighbor discovery probe (only if entries exist in the BIG-IP IPv6 neighbor cache) is initiated
    • ICMP echo request to 224.0.0.1 (multicast ping) is initiated

The failover action is avoided if the BIG-IP system receives a response to the VLAN failsafe traffic it generated.

VLAN failsafe timeout

The VLAN failsafe timeout specifies the number of seconds that must elapse before the BIG-IP system triggers the failsafe action and marks the VLAN down.

To avoid unnecessary failover, the VLAN failsafe timeout value should be set to a value larger than the number of seconds the neighboring links take to initialize. F5 recommends using a VLAN failsafe timeout of at least 10 seconds. An unnecessary failover may cause more disruption than a brief flap in network connectivity. Setting the timeout too low can cause system and network instability issues if both members of the redundant system experience intermittent connectivity.

Important: In BIG-IP 9.x, no minimum value was enforced for the VLAN failsafe timeout value. Beginning in BIG-IP 10.0.0, the minimum allowed VLAN failsafe timeout value is 10 seconds. Before you upgrade from version 9.x to version 10.x, F5 recommends that you change your VLAN failsafe timeout value to 10 or greater in order to ensure a successful configuration load after the upgrade has been completed.

Beginning with version 9.2.5, the mode of operation for the VLAN failsafe timeout counter is controlled by the Failover.VlanFailsafe.ResetTimerOnAnyFrame database key. The key can be set to a value of either true or false:

  • false

    When the database key is set to its default value of false, the BIG-IP system resets the VLAN failsafe timeout counter only upon reception of valid ARP or NDP packets, sent in response to VLAN failsafe traffic. Other traffic, such as responses to BIG-IP monitor requests, do not reset the VLAN failsafe timeout counter. Since the default timeout behavior ignores any other traffic on the VLAN, VLAN failsafe may be triggered before the VLAN has been idle for the entire timeout value.

    To configure the BIG-IP system to reset the timeout counter only on solicited ARP or NDP responses on the VLAN, type the following command on the command line:

    bigpipe db Failover.VlanFailsafe.ResetTimerOnAnyFrame false

  • true

    When the database key is set to true, the BIG-IP system resets the timeout counter upon reception of any frame on the VLAN, including responses to BIG-IP monitor traffic.

    To configure the BIG-IP system to reset the timeout counter when it receives any frame on the VLAN, type the following command on the command line:

    bigpipe db Failover.VlanFailsafe.ResetTimerOnAnyFrame true

VLAN failsafe action

The following failsafe actions define options that the system can take if the system does not detect any traffic on this VLAN, and the timeout has expired:

  • Failover:

    The failover action specifies that the active unit fails over to its peer

  • Restart All

    The restart all action specifies that the system restarts all system services

  • Reboot

    The reboot action specifies that the system reboots

Important: If you set the VLAN failsafe action to Restart All or Reboot when a low failsafe timeout value is configure, the BIG-IP may enter a cycle of restarting services or rebooting until VLAN failsafe is disabled. This behavior may occur when the timeout value is set to low and the interfaces are not available after a reboot or restart due to a Spanning Tree update or because LACP enabled trunks have not initialized. To prevent this behavior from occurring, do not set the VLAN failsafe timeout value below the recommended value of 90 seconds.

Configuring VLAN failsafe

To configure VLAN failsafe, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click High Availability.
  4. From the Failsafe drop-down menu, click VLANs.
  5. Click Add.
  6. Select a VLAN from the drop-down menu.
  7. Leave the default timeout value.
  8. Select an action from the drop-down menu.
  9. Click Finished.

Best Practices

  • VLAN failsafe configuration is saved to the /config/bigip_base.conf file, which is not synchronized between high availability pair systems during ConfigSync operations. As a result, you must define VLAN failsafe on both systems in a high availability pair configuration.
  • If you enable VLAN failsafe on a VLAN with nodes that do not respond consistently to the standard VLAN failsafe probes, the BIG-IP high availability pair can experience unintended VLAN failsafe events.

    For example, unwanted VLAN failsafe events can occur if VLAN failsafe is enabled on a VLAN with no default gateway or pool members, and the VLAN only contains devices that do not respond to ARP requests, ICMPv6 neighbor discovery probes, or multicast pings. To help prevent this behavior, you can assign a health monitor to at least one node on that VLAN. This practice will help to consistently populate the ARP tables on both BIG-IP units in the pair, and give a more accurate view of VLAN availability.
  • F5 does not recommend setting the VLAN failsafe timeout to a low setting, such as below five seconds, as this can cause the BIG-IP system to generate aggressive VLAN failsafe traffic when devices on the VLAN are slow to respond.
  • Testing the VLAN failsafe feature for an HA redundant pair, by removal of all nodes from the VLAN may not result in a VLAN failsafe action being triggered. If the VLAN being tested is used for network failover and/or state mirroring, the traffic generated between the redundant BIG-IP systems is sufficient to prevent VLAN failsafe from being triggered.
