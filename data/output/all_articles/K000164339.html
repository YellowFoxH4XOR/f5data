Description

BIG-IP AWAF systems may send high ASM CPU and Total CPU utilization alerts even when actual CPU usage is normal. The ASM CPU reporting graph can over-report utilization, which can trigger false positive alerts.

Example alert values:

  • ASM CPU Utilization: 80.62%, above the upper threshold of 80%
  • Total CPU Utilization: 81.52%, above the upper threshold of 80%

Environment

  • Product: BIG-IP AWAF
  • Alerting: ASM and system CPU alerts sent by email, with upper thresholds set to 80%
  • Alert calculation: Alerts reflect average values per blade, collected over the past minute. 

Cause

  • Bug ID 1294141: The ASM Resources Reporting graph over-reports ASM CPU utilization. This can contribute to false positive ASM CPU alerts. The issue affects all supported releases.

Answer/Recommended Actions

  1. Review the ASM CPU and System CPU graphs for the alert time period. If the ASM CPU graph shows values above 100%, the alert may be caused by Bug ID 1294141.
  2. Apply the workaround documented in Bug ID 1294141.
  3. Monitor the system after applying the workaround. Confirm whether the CPU graph stays at or below 100% and whether false alerts stop.
  4. If the alerts continue or the graph still exceeds 100% after the workaround, contact F5 Support. 

Additional Information

  • Expected behavior: On BIG-IP ASM and FPS systems, CPU usage can rise for several hours per day due to the datasyncd process. This is expected behavior. See K02827102: BIG-IP ASM and BIG-IP FPS systems experience higher CPU usage for several hours per day.
  • Unexpected behavior: ASM or total CPU alerts that occur while the CPU graph shows values above 100% are consistent with the reporting issue in Bug ID 1294141, rather than actual CPU exhaustion.
  • To confirm the cause, compare the alert timestamp with the CPU graphs and system logs. If the device logs show no abnormal activity at that time, the alert may be a false alarm.
