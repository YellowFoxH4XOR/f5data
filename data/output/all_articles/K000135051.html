K000135051: HTTP health check fails with status code '400 Bad Request'

Source
https://my.f5.com/manage/s/article/K000135051

Description

An NGINX Plus HTTP health check returns '400 Bad Request' even though the health-check URI is accessible when tested manually: 

"<health-check-URI> HTTP/1.1" 400 ... "nginx (health check)"

Environment

  • NGINX Plus
  • Active Health Check
  • The 'proxy_set_header Host' directive is configured to use a variable

Cause

  • The proxy_set_header Host directive is set to use a variable (e.g., $host), and if the variable resolves to an empty value, the health check sends requests without a Host header, which is a mandatory requirement in HTTP/1.1.

Recommended Actions

Configure the health check in a separate named location instead of the regular application location.

 

  1. Remove or comment out the health_check directive from the application location: 
    location / {
    proxy_pass https://<UPSTREAM>;
    # health_check fails=1 passes=2 uri=/test; <- Remove/Comment out this line
}
  2. Add a separate named location dedicated to the health check under the same server block: 
    location @health_check {
    health_check fails=1 passes=2 uri=/test;
    proxy_pass https://<UPSTREAM>;
    proxy_set_header Host <UPSTREAM_HOSTNAME>;
}

     

  3. Verify and reload NGINX configuration 
    sudo nginx -t && sudo nginx -s reload

    Additional Information

    • A health-check URI can return 200 OK during a manual test while the NGINX Plus health check fails because the requests can differ in protocol version and headers.
    • A backend 400 response caused by a missing Host header can result in an error such as:

      no live upstreams while connecting to upstream
