Known Issue

This is the result of a known issue. Forwarding virtual servers configured to use a transport layer protocol other than TCP or UDP, such as Encapsulation Security Payload (ESP), discard return traffic when a SNAT pool or SNAT auto map is enabled. When this issue occurs, the BIG-IP system receives the return traffic but does not associate it with the virtual server. Configuring a global SNAT for the traffic does not resolve the issue.

F5 Product Development tracked this issue as ID 362109 (formerly CR137384), and it was fixed in BIG-IP versions 11.0.0 and 10.2.3. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Additionally, this issue has been fixed in cumulative hotfix 10.2.2 HF-1, which has been issued for BIG-IP version 10.2.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

Workaround

You can work around this issue by configuring an iRule to perform the SNAT function.

For example:

when CLIENT_ACCEPTED { snat <IP> }

In the previous command syntax, note the following:

  • <IP> is the translation IP address

Note: For more information about configuring iRules, refer to DevCentral. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).
