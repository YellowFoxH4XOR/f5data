K9855: The standby member of CMP systems may display extra persistence records

Topic

On Clustered Multi-Processing (CMP) systems with connection mirroring and persistence mirroring concurrently enabled, the bigpipe persist show command output differs between the active unit and the standby unit.

On the active unit, locally cached persistence records for the same client on the same TMM are shared, and the total number of active persistence records for that client will never exceed the number of TMMs. In order to avoid a potential race condition when updates are received from the active unit, the standby unit does not share a single locally cached persistence record for the same client on each TMM, but instead creates a separate locally cached persistence record for each mirrored connection. As a result, running the bigpipe persist show command on the standby unit may display what appear to be duplicate persistence records. This is expected behavior; it does not affect the BIG-IP system's ability to resume active connections upon failover.

For example, the following command output was obtained from the active unit using the bigpipe persist show command while two different clients made repeated requests to the same virtual server:

PERSISTENT CONNECTIONS             
|     Mode source addr   Value 192.168.206.100
|        virtual 172.28.21.171:http   node 10.1.21.71:http   age 0sec
|        slot/tmm 2/3
|     Mode source addr   Value 192.168.206.93
|        virtual 172.28.21.171:http   node 10.1.21.71:http   age 0sec
|        slot/tmm 1/1

The following command output obtained from the standby unit several seconds later indicates that two persistent connections from each client are being mirrored concurrently:

PERSISTENT CONNECTIONS             
|     Mode source addr   Value 192.168.206.100
|        virtual 172.28.21.171:http   node 10.1.21.71:http   age 9sec
|        slot/tmm 2/3
|     Mode source addr   Value 192.168.206.100
|        virtual 172.28.21.171:http   node 10.1.21.71:http   age 9sec
|        slot/tmm 1/2
|     Mode source addr   Value 192.168.206.93
|        virtual 172.28.21.171:http   node 10.1.21.71:http   age 13sec
|        slot/tmm 2/3
|     Mode source addr   Value 192.168.206.93
|        virtual 172.28.21.171:http   node 10.1.21.71:http   age 13sec
|        slot/tmm 1/1
