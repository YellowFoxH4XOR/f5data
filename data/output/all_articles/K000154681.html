K000154681: How to Apply CORS Preflight Checks using NGINX Plus Ingress Controller VirtualServer Resource

  • NGINX Ingress Controller: 4.0.0, 5.X.X, 4.X.X, 5.1.X, 5.1.1, 5.1.0, 5.0.X, 5.0.0, 4.0.X
Source

Description

  • CORS (Cross-Origin Resource Sharing) preflight requests may fail or not return the required headers when using NGINX Ingress Controller VirtualServer resource.
  • This can result a browser blocking cross-origin requests due to missing or incorrect CORS headers in the response.

Environment

  • Product: NGINX Plus  Ingress Controller 
  • Kubernetes
  • VirtualServer resource for routing 
  • CORS (Cross-Origin Resource Sharing)

Cause

  • CORS headers are not present in responses 

Recommended Actions

  1. Enable Snippets in NGINX Ingress Controller:
    Edit the NGINX Ingress Controller deployment to include the -enable-snippets argument.
    Example deployment args: 
    - -nginx-plus
- -enable-snippets
- -enable-prometheus-metrics
- -prometheus-metrics-listen-port=9113
- -nginx-configmaps=$(POD_NAMESPACE)/nginx-config
- -default-server-tls-secret=$(POD_NAMESPACE)/default-server-secret
  2. Add CORS Headers Using location-snippets in VirtualServer:
    In the VirtualServer manifest, use the location-snippets field to inject the required CORS headers.
    Example configuration: 
    apiVersion: k8s.nginx .org/v1
kind: VirtualServer
metadata:
  name: my-core-example
  namespace: default
spec:
  host: core.example. com
  routes:
    - action:
        proxy:
          requestHeaders:
            pass: true
          set:
            - name: Host
              value: core.example .com
            - name: accessToken
              value: ${jwt_header_access_token}
          rewritePath: /rest-sts/$1
          upstream: tea
      location-snippets: |
        add_header 'Access-Control-Expose-Headers' 'x-username,X-Username,Access-Control-Allow-Headers,Access-Control-Allow-Origin,Access-Control-Allow-Credentials,Set-Cookie';
        add_header 'Access-Control-Allow-Headers' 'X-Username,x-username,Cookie,Host,Authorization,Access-Control-Allow-Headers,Content-Type,X-OpenIDM-OAuth-Login,X-OpenIDM-DataStoreToken,X-Requested-With,Cache-Control,Accept-Language,accept,Origin,Access-Control-Request-Method,Access-Control-Request-Headers,X-OpenAM-Username,X-OpenAM-Password,iPlanetDirectoryPro,Accept-API-Version';
        add_header 'Access-Control-Allow-Methods' 'GET,POST,OPTIONS,DELETE,PUT';
        add_header 'Access-Control-Allow-Credentials' 'true';
        proxy_hide_header Access-Control-Allow-Methods;
        proxy_hide_header Access-Control-Allow-Headers;
        proxy_hide_header Access-Control-Allow-Origin;
        proxy_hide_header Access-Control-Allow-Credentials;
