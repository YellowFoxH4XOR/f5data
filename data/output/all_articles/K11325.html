K11325: Shadow rules that use an aggressive scheduling frequency may result in CPU threshold messages

Topic

Shadow rules that use an aggressive scheduling frequency, such as every minute, may result in high CPU utilization. As a result, ARX may send SNMP traps that appear similar to the following example:

: SNMP TRAP:systemResourceThresholdRaise (738)  : resource:CPU threshold:80 slot:1 proc:1
: SNMP TRAP:systemResourceThresholdClear (739)  : resource:CPU threshold:80 slot:1 proc:1

You can reduce CPU utilization by reducing the frequency at which rules are scheduled, and ensuring that no more than four rules per Volume Group (referred to as a VPU domain in ARX version 5.x and previous) are scheduled at the same time.

In addition, the number and size of files copied by the shadow rule are contributing factors to high CPU utilization. CPU utilization will increase if the system has to calculate and transfer deltas for a large number of small files. Increasing the minimum file size eligible for delta transfers will also reduce CPU utilization. You can increase the minimum file size from the default of 100MB by using the delta-threshold command.

Note: For information about the delta-threshold command, refer to the ARX CLI Reference Guide.
