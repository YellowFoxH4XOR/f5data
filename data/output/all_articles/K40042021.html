Known Issue

The BIG-IP system fails to set the rport parameter when processing Session Initiation Protocol (SIP) traffic with a Message Based Load Balancing (MBLB) or Message Routing (MR) profile.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to process SIP traffic using either an MBLB or MR profile.
  • The profile has the Insert Via Header setting enabled. Enabled is the default setting.
  • The BIG-IP system receives a subscriber SIP packet with the rport parameter set.

Impact

SIP connections may fail when subscribers or SIP proxies strictly check for rport parameter compliance as defined in RFC 3581.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • SIP subscriber connections fail intermittently.
  • The BIG-IP system fails to set the rport parameter.

Workaround

To work around this issue, you can apply the following iRule to the affected virtual server. 

Impact of workaround: Performing the recommended workaround should not have a negative impact on your system.

when SIP_REQUEST {
set topvia [SIP::via 0]
set replaceval ";rport=[UDP::remote_port];"
if { $topvia contains ";rport;" } {
set newtop [string map ";rport; $replaceval" $topvia]
SIP::header insert Via $newtop 0
SIP::header remove Via 1
}
}
