Topic

This article discusses the various failover capabilities when the Luna FIPS card fails.

Description

A BIG-IP system that is in a high availability (HA) configuration is capable of detecting and responding to Luna FIPS card failures. When operations, such as starting the Traffic Management Microkernel (TMM) or the Master Control Process Daemon (mcpd), or using the fipsutil command fail to access to the FIPS card, the BIG-IP system will first attempt to restart the FIPS card itself. If restarting the FIPS card fails, the BIG-IP system then triggers the GO Offline & Restart HA event and fails over to the peer device. This feature is enabled by default on all BIG-IP devices that have a Luna FIPS card installed and cannot be disabled. You can view the type of FIPS card installed by typing the fipsdevice command at the command line:

(bigip)# fipsdevice
luna

The fipsutil.luna process is responsible for monitoring and resetting the FIPS card in the event of an access failure. When a failure is detected and a restart is initiated, the following message is logged to the /var/log/daemon.log file:

FIPS halted, re-attaching...

The ssl.fips.failuretimeout database variable controls the amount of time in seconds before a failover event is initiated if the FIPS card remains unresponsive. By default, the value of this database variable is 60 seconds. You can view the value of this database variable by typing the following command in the Traffic Management Shell (tmsh):

list /sys db ssl.fips.failuretimeout

The output appears similar to the following example:

sys db ssl.fips.failuretimeout {
value "60"
}

To modify the value of the ssl.fips.failuretimeout database variable, use the following tmsh command syntax:

modify /sys db ssl.fips.failuretimeout value <time in seconds>

For example, to set the ssl.fips.failuretimeout database variable to 90 seconds, type the following command:

modify /sys db ssl.fips.failuretimeout value 90

Note: Modifications to the database variable value are automatically saved. For more information, refer to K16953: BIG-IP system database variables are automatically saved when modified.

Important: Modifying the value of the ssl.fips.failuretimeout database variable changes the amount of time the BIG-IP system takes to fail over to the next available device in the device group, in the event the FIPS card is not functioning properly. When the FIPS card is not functioning properly, SSL profiles that use certificates or keys stored in the FIPS card will not be functional, resulting in traffic processing failure for the associated virtual server. F5 recommends that you should leave the ssl.fips.failuretimeout database variable at its default value unless otherwise advised by F5 Support.

Recommendations

You can configure the BIG-IP system to proactively monitor the Cavium Nitrox SSL hardware accelerator card and take a specified action if failure to process and SSL connection is detected. For more information, refer to K16951: Overview of SSL hardware acceleration fail-safe.
