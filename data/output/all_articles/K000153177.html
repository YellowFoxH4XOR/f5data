Description

When attempting to trigger a UCS backup via Ansible, the UCS backup may fail with errors similar to the following seen in the ltm log:

Aug 11 19:20:23 bigip01.local err iAppsLX_save_pre[24625]: Failed task: /shared/iapp/build-package/77609273-5cf5-4af3-b833-499a0a9c4b16: Failed to clean up spec file /var/config/rest/node/tmp/add8f8c3-9e06-498f-a8d0-73473a24325e.spec

Aug 11 19:20:23 bigip01.local err iAppsLX_save_pre[24625]: Failed to get getRPM build response within timeout for f5-service-discovery

Environment

  • BIG-IP
  • iApps LX packages (i.e. AS3, Telemetry Streaming) are installed 
  • Using Ansible to trigger a UCS backup creation (which does the request via REST API)

Cause

With iAppsLX packages (i.e. AS3, Telemetry Streaming) installed, the process to create a UCS backup may take longer than usual, and a timeout can be exceeded. 

Recommended Actions

Increase the value of the sys db variable restjavad.timeout (default 60) to 300 and restart the restjavad daemon to apply the change:

Impact of workaround: The restjavad restart will momentarily interrupt services that depend on restjavad, such as REST API calls, the Configuration Utility, iApps LX, and automation toolchain components (AS3, DO, TS). However, it does not impact the data plane (traffic processing) in most environments. In rare cases, if system resources are exhausted, there could be broader service impacts, so it is recommended to perform this during a maintenance window if automation is critical.

tmsh modify sys db restjavad.timeout value 300
bigstart restart restjavad
