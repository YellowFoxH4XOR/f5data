Description

Attempting to utilize iControl REST to perform administrative tasks can result in an error message from the target device. The impact of this is an ability to manage any task or gather any information from the target device. Additionally, systems that rely on iControl REST such as BIG-IQ, AS3, Ansible, and more will fail to manage the device. The error message will look something like the following:

Environment

  • BIG-IP
  • iControl REST consumer

Cause

This occurs when there is corruption to the local filesystem storage used by the restjavad process, part of the service chain responsible for servicing iControl REST requests. The BIG-IP attempts to self-recover however this is not always possible due to a flaw in the code which is described in Bug ID 829193.

Be aware that in this instance, the error message is misleading; the error message mentions 'disk corruption' but more accurately the issue is 'file corruption'. A disk or appliance replacement is normally not the most efficient method of recovery. A method for checking to see if this is indeed the case is to check the file system for the presence of the file /var/config/rest/storage/LOST-STORAGE.txt.

Recommended Actions

  • For appliance and Virtual Edition
  • For multi-bladed systems

For Appliance and Virtual Edition

  1. Log in to the command-line of the system via ssh, enter bash mode
    (you may need to issue tmsh run /util bash)

  2. Execute the workaround steps from the related bug tracker article for Bug ID 829193

  3. Try to use iControl in some way
    (such as BIG-IQ, or some iControl query of your choosing, for example restcurl -u user:password tm/sys/version from the command-line)

For multi-bladed systems

  1. Log in to the command-line of the system via ssh, you will be on the primary blade
    (the command-line will designate the blade number) and enter bash mode  (you may need to issue tmsh run /util bash)

  2. Execute the workaround steps from the related bug tracker article for Bug ID 829193

  3. Try to use iControl in some way
    (such as BIG-IQ, or some iControl query of your choosing, for example restcurl -u user:password tm/sys/version from the command-line)

    1. If it's successful, stop here

    2. If you still get the REST error, repeat the workaround steps on additional blades in the cluster
      (you can use ssh slot1, ssh slot2, etc. to move between blades)
