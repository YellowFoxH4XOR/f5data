Description

There are intermittent authentication failures when accessing the BIG-IP administration interfaces via SSH or Configuration Utility (aka GUI).
You may see error message similar to below in /var/log/secure log file

pam_ldap(httpd:auth): error reading from nslcd: Connection reset by peer
pam_unix(httpd:auth): check pass; user unknown

You may see error message similar to below in BIG-IP console (terminal window) if nslcd is running in debug mode on BIG-IP (nslcd -d):

nslcd: [b0dc51] <authc="<username>"> ldap_search_ext() failed: Can't contact LDAP server: Connection reset by peer
nslcd: [b0dc51] <authc="<username>"> DEBUG: set_socket_timeout(15,0)
nslcd: [b0dc51] <authc="<username>"> DEBUG: ldap_unbind()
nslcd: [b0dc51] <authc="<username>"> DEBUG: "<username>": user not found: Can't contact LDAP server

Environment

  • BIG-IP LTM
  • LDAP Autentication
  • Management Interface
  • Configuartion Utility
  • nslcd deamon
  • Upgrading from versions that are not affected by Bug ID 881085


Cause

Bug ID 881085

Recommended Actions

As a workaround set the auth ldap idle-timeout to a smaller value on BIG-IP from CLI:

#tmsh modify auth ldap system-auth idle-timeout 295

Additional Information

An idle timeout RST is received on the LDAP connection before the configured auth LDAP idle-timeout expires on BIG-IP (BIG-IP idle-timeout default value is 3600 seconds (tmsh list auth ldap system-auth idle-timeout)). This RST might be generated by tmm (if the connection to the LDAP server is via a defined VLAN), some other intervening device on the network or from the LDAP server itself (depending on its connection time limit)
