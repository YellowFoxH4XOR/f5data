Known Issue

iRule HTTP::respond statements that contain a respond value greater than 511 may corrupt the HTTP response.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses an iRule statement of HTTP::respond that is configured with a value greater than 511.

    For example:

    when HTTP_REQUEST {
        HTTP::respond 600 content "Unusual Error"
    }
  • Clients that access the HTTP virtual server match conditions that trigger the iRule to send a response with the affected HTTP::respond configuration.

Impact

The affected iRule statement of the HTTP virtual server sends an unexpected value HTTP response code.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Applications that depend on a specific HTTP response code fail.
  • The iRule HTTP response does not return the expected configured value.
  • When you use an HTTP viewer utility, such as HTTP Watch, you see unexpected HTTP header values for a connection response from the iRule (positive or negative numeric values).

    The client receives a response from the iRule HTTP::respond statement that appears similar to the following example:

    HTTP/1.0 -424 Unknown Code

Workaround

To work around this issue, you can modify the iRule by replacing the HTTP::respond statement with a TCP::respond statement. To do so, perform the following procedure:

Replacing HTTP::respond with TCP::respond syntax

You can replace the HTTP::respond statement by using TCP::respond and defining HTTP protocol syntax as part of the TCP response.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click the name of the affected iRule.
  4. Within the iRule syntax, locate the HTTP::respond statement.

    For example:

    when HTTP_REQUEST {
        HTTP::respond 600 content "Unusual Error"
    }

  5. Replace the HTTP::respond line using the following TCP::respond syntax:

    when HTTP_REQUEST {
    set payload "Unusual Error"
    TCP::respond "HTTP/1.0 600 Unusual Error\r\nContent-Length: [string length $payload]\r\n\r\n$payload"
    unset payload
    }

    Include the HTTP/<http version> prefix and the closing double carriage return line feed (\r\n\r\n) within the quotation marks of the TCP::respond syntax.
  6. Click Update.
