Description

Observing ConfigSync messages similar to the following examples in /var/log/ltm:

info mcpd[4527]: 0107148c:6: Received advertisement for device group /Common/Failover from remote device /Common/ltm1.example.com, force true, error '' commit_id 7 7076111547747748200 /Common/ltm1.example.com 0, local commit id is 27 7076111401141756612 /Common/ltm2.example.com 0 cached remote device data 0

info mcpd[4527]: 01071528:6: Device group '/Common/Failover' sync inconsistent, Incremental config sync may not be complete on one or more devices in this devicegroup, Sync status may not be consistent until incremental config sync is complete..

info mcpd[4527]: 0107148b:6: Sending sync for device group /Common/Failover to device /Common/ltm1.example.com, current commit id 27 7076111401141756612 /Common/ltm2.example.com 0.

info mcpd[14727]: 01071528:6: Device group '/Common/datasync-global-dg' sync inconsistent, Sync failed on one or more devices in this devicegroup, Sync status may not be consistent.

Or you might see "unable to connect BIG-IP device"

However, sync is successful for all device groups, and members report In Sync.

Environment

  • High Availability (HA) environment with config sync enabled
  • Logs

Cause

Mcpd log level has been set to the info severity level.

This is expected when mcpd is logging at info severity level. The default level is notice, which is less verbose and does not produce these log messages.

sys db log.mcpd.level {
    default-value "notice"
    scf-config "false"
    value "info"         <----
    value-range "alert crit debug emerg err error info notice panic warn warning"
}

Recommended Actions

Revert sys db log.mcpd.level to the default level of notice:

tmsh modify sys db log.mcpd.level value notice

In some cases, mcpd may be logging info level events due to the presence of a log filter which is publishing logs to local syslog. Investigate the output of tmsh list sys log-config if sys db log.mcpd.level is not changed from the default value.
