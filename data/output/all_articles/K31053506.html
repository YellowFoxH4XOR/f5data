K31053506: Overview of BIG-IP Edge Client failure codes

Type
Support Solution
Published
2020-04-14
Updated
2024-03-19
Applies to
  • BIG-IP
  • BIG-IP APM
  • APM Clients
Source
https://my.f5.com/manage/s/article/K31053506

Description
In some cases you may find log entries indicating reasons and/or codes for Access Session deletion

Environment

  • BIG-IP APM
  • Edge Client

Cause
Non-code Session Deletion

  • Session deleted (expired) 
    • That means session is deleted after maximum session timeout(session lifetime is exceeded).
  • Session deleted (no_hostname).
    • No hostname exists for this connection entry.
  • Session deleted (policy_result)
    • Logon Deny/Policy result, i.e endpoint security check
  • Session deleted (restarted)
    • The client makes a request resulting in an unexpected evaluation of the apm access policy evaluation items causing the apm session to restart. For more information, refer to K02309338: User sessions are deleted with message ''Session deleted (restarted)'.

Coded Session Deletion

  • Session deleted (fatal_error, code - 10).
    • Critical error such like,  RasDial failed, failed to patch routing table or DNS registry, failed to start DNS relay service, etc
  • Session deleted (network_error, code - 4).
    • This error indicates it failed to create tunnnel due to server unreachable. For example, DNS resolution failure, server reset, peer not responding, timeout etc...
  • Session deleted (timed_out, code - 3).
    • Connection attempt has timed out.
  • Session deleted (user_initiated, code - 1).
    • User gracefully disconnected (via Disconnect button) and this message was generated by client.
    • For example, user clicks disconnect or possibly system going to sleep.

Recommended Actions

  • Identify the reason for the failure based on the cause and resolve the affected source.
