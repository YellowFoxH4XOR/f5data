Known Issue

Beginning in BIG-IP 12.0.0, there is additional validation for BIG-IP LTM policy rule names to allow only certain valid characters. The forward slash character (/) is included in the set of valid characters.

As the forward slash character (/) is used as a delimiter in the BIG-IP virtual path hierarchy, extra slashes in a rule name may cause validation problems, because the rule appears to the system as having additional path segments.

This issue occurs when all of the following conditions are met:

  • The BIG-IP LTM policy rule contains the forward slash character (/).
  • You attempt to load the BIG-IP LTM configuration.

Impact

The BIG-IP system will not load its configuration and will not pass traffic. In some cases the Configuration utility may not display that the configuration load was successful.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system does not load the configuration
  • Your BIG-IP system remains in an INOPERATIVE state.

Workaround

To work around this issue, you can edit the bigip.conf configuration file to replace the forward slash characters (/) with a valid alternative.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

In the bigip.conf file, you can manually edit the BIG-IP LTM policy rule names to either remove the illegal character or to substitute a valid character.

For example, the following policy will not load because the rule name contains a forward slash character (/):

    ltm policy mypolicy {
    ...
       rules {
          /testperson/a  {
    ...
    }

The policy will load when the forward slash characters (/) are changed to a legal character, such as underscores (_):

    ltm policy mypolicy {
    ...
       rules {
          _testperson_a  {
    ...
    }
