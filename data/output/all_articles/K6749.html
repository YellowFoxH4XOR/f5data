Topic

NFS load balancing is recommended only for sessions where clients are performing read requests to the servers. 

NFS load balancing is not recommended for sessions where clients are performing read/write requests to servers. This is because the BIG-IP system will load balance a client NFS connection (mapping) to a single server. All read/write operations are sent only to the backend server that the client is load balanced to. The BIG-IP system is not designed to load balance NFS write operations to multiple servers. Load balancing write requests to multiple NFS servers results in the data on these servers being out of synchronization with each other.

For example, when load balancing two NFS servers (NFS_Server_1 and NFS_Server_2), if a client mounts a connection to the NFS virtual server, the client is load balanced to one of the NFS servers. If the client is load balanced to NFS_Server_1, and creates a file (myfile.txt), the file would be created only on NFS_Server_1.  As a result, if a client was subsequently load balanced to NFS_Server_2 and attempted to read the (myfile.txt) file, the file would not be found.

You can configure the BIG-IP system to load balance NFS servers using either of the following first two methods:

  • Creating an NFS load balancing configuration using wildcard ports (recommended)
  • Creating an NFS load balancing configuration for NFS static ports
  • Testing the NFS load balancing configuration (optional)

Creating an NFS load balancing configuration using wildcard ports (recommended)
F5 recommends that you use wildcard ports for NFS load balancing. The following procedures outline the steps to configure the BIG-IP LTM system for NFS load balancing using wildcard ports.

  • Creating an NFS server pool
  • Creating a custom persistence profile
  • Creating a custom FastL4 profile
  • Creating the NFS virtual server

Creating an NFS server pool

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select Create.
  4. For Name, enter a name for the NFS pool.
  5. For each NFS server you want to add to the pool as a member, for Address, enter the NFS server IP address, and for Service Port select *All Services. 
  6. Select Finished.

Creating a custom persistence profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Profiles > Persistence.
  2. Select Create.
  3. For Name, enter a name for the persistence profile.
  4. For Persistence Type select Source Address Affinity.
  5. Select the Custom check box.
  6. For Timeout, in the seconds box enter 86400 (which is 24 hours).
  7. Enter Finished.

Creating a custom FastL4 profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Profiles > Protocol > FastL4.
  2. Select Create.
  3. For Name, enter a name for the profile.
  4. For Parent Profile select FastL4.
  5. Select the Custom check box.
  6. For Idle Timeout, in the seconds box, select 3600 (which is 1 hour).
  7. Select Finished.

Creating the NFS virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers > Virtual Server List.
  2. Select Create.
  3. For Name, enter a name for the virtual server.
  4. For Type enter Performance (Layer 4).
  5. For Destination Address/Mask, enter the NFS virtual server IP address.
  6. For Service Port select *All Ports.
  7. For Configuration select Advanced.
  8. For Protocol select *All Protocols.
  9. For Protocol Profile (Client) select FastL4  (the profile you previously created).
  10. In the Resources section, for Default Pool select the pool you previously created.
  11. For Default Persistence Profile select the persistence profile you previously created.
  12. Select Finished.

Creating an NFS load balancing configuration for static ports

Some Berkley Software Design (BSD) implementations use NFS servers with static ports. In this case, you can also use static ports to load balance these NFS servers. However, F5 does not recommend this method of load balancing, because it will not work with all types of NFS server implementations. The following procedures outline the steps required to configure the BIG-IP LTM system for NFS load balancing using NFS static ports.

Note: When a client connects to a port-specific virtual server, that port will be used to connect to the back end NFS server (pool member). Therefore, when configuring port-specific virtual servers, all of the NFS servers configured in the NFS server pool must each be configured to use the same static ports.

  • Creating an NFS server pool
  • Creating a custom persistence profile
  • Creating a custom FastL4 profile
  • Creating NFS port specific virtual servers

Creating an NFS server pool

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select Create.
  4. For Name, enter a name for the NFS pool.
  5. For each NFS server you want to add to the pool as a member, for Address, enter the NFS server IP address, and for Service Port select *All Services. 
  6. Select Finished.

Creating a custom persistence profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Profiles > Persistence.
  2. Select Create.
  3. For Name, enter a name for the persistence profile.
  4. For Persistence Type enter Source Address Affinity.
  5. Select the Custom check box.
  6. Select the Match Across Virtual Servers check box.
  7. For Timeout, in the seconds box enter 86400 (which is 24 hours).
  8. Select Finished.

Creating a custom FastL4 profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Profiles > Protocol > FastL4.
  2. Select Create.
  3. For Name, enter a name for the profile.
  4. For Parent Profile select FastL4.
  5. Select the Custom check box.
  6. For Idle Timeout, in the seconds box, enter 3600 (which is 1 hour).
  7. Select Finished.

Creating NFS port specific virtual servers

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers > Virtual Server List.
  2. Select Create.
  3. For Name, enter a name for the virtual server.
  4. For Type select Performance (Layer 4).
  5. For Destination Address/Mask, enter the NFS virtual server IP address.
  6. For Service Port select the specific NFS server port used in your environment.
  7. For Configuration select Advanced.
  8. For Protocol select *All Protocols.
  9. For Protocol Profile (Client) select FastL4  (the profile you previously created).
  10. In the Resources section, for Default Pool select the pool you previously created.
  11. For Default Persistence Profile select the persistence profile you previously created.
  12. Select Finished.
  13. Repeat steps 2 to 12, re-using the virtual server Destination Address/Mask for each NFS server port used by your NFS servers.

Testing the NFS load balancing configuration (optional)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

From a Linux client system, mount an NFS mount point to the NFS virtual server address by using the following command syntax:

mount -tnfs <Virtual_IP_Address>:[mount-point] /mnt

In the previous example, note the following:

  • Replace <Virtual _IP_Address> with the Destination Address you used when you created the virtual servers.
  • Replace [mount-point] with the NFS server mount point you used in your environment.
