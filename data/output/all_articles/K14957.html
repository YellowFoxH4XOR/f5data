Known Issue

A local traffic policy may not function after you add rules.

This issue occurs when all of the following conditions are met:

  • The affected policy applies to a single virtual server that consists of multiple groups of related conditions.
  • The affected policy defines a very large number (1,000 or more) of unique conditions.

A policy defines conditions against which action should be enforced. To define a condition, a group is configured within the policy to compare the relevant attribute of the traffic against one or more defined values. The number of unique conditions defined by the group equals the number of values that the group references.

For example, the following group represents two unique conditions:

'http-host ends-with values { abc.com def.com }'

The following groups together represent eight unique conditions:

'http-host ends-with values { abc.com def.com ghi.com }'
'http-host starts-with values { abc.com def.com ghi.com jkl.com mno.com }'

As displayed in the previous examples, an increase in the number of groups directly increases the complexity of the policy.

Impact

The BIG-IP system does not evaluate the local traffic policy condition as expected.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The affected policy may have a rule match, but the BIG-IP system does not enforce the required action.

Workaround

There is no work around for this issue. You may be able to avoid the issue by reducing the number of conditions in the rules and/or the number of the groups, as this reduces the complexity of the policy.
