Known Issue

This is the result of a known issue. Clustered Multi-Processing (CMP) enabled systems may reset the data channel of a Passive FTP connection.

When one TMM process receives the PORT/PASSV command, an ephemeral listener is created for the subsequent data connection. The ephemeral listener is broadcast to other TMM processes, as the data connection could arrive at any other TMM. If a data connection is received on a TMM process before it receives the broadcast message, the TMM will reject the data connection and issue a reset since the ephemeral listener has not be created yet.

This behavior may lead to loss of data, which will be required to be retransmitted after the channel is correctly established.

F5 Product Development tracked this issue as CR108331 and it was fixed in BIG-IP 9.4.6. For information about upgrading, refer to the BIG-IP LTM Release Notes.
