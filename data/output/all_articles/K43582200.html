Issue

Old Behavior

In BIG-IP VE 14.1.0 and earlier, as well as BIG-IP VE 15.0.0 through 15.0.1, the system automatically performs the file system consistency check (fsck) during bootup. This behavior occurs at a 180-day interval and affects BIG-IP VE systems deployed in both private hypervisors and public clouds.

When the fsck operation fails, the system enters maintenance mode and displays a prompt for the root password. For systems deployed on some public cloud environments (Microsoft Azure and Amazon Web Services at the time of publishing), the root account is disabled by default. This scenario can lock the system.

New Behavior

Beginning in BIG-IP VE 15.1.0 and BIG-IP VE 14.1.2, for both private hypervisors and public clouds, the system no longer automatically performs the fsck operation.

F5 Product Development tracked this change as ID 771705.

Impact

The BIG-IP VE system does not check file system consistency at regular intervals.

Recommended Actions

To perform the fsck operation, you must manually trigger the check by following the Forcing a file system check using the shutdown command procedure in K73827442: Forcing a file system check on the next system reboot (12.x - 15.x).

If your system’s root account is disabled (especially for public cloud environments), you should consider enabling it prior to performing the fsck operation on the system. This step is helpful in case the fsck operation fails and the system prompts for the root password. After completing the check, you should disable the root account. To do so, perform the following actions:

  • Enabling the root account
  • Disabling the root account

Enabling the root account

  1. Log in to the Configuration utility as the user you created at the time of deployment.
  2. Go to System > Platform.
  3. Under User Administration, for Root Account, clear the Disable login check box.  
  4. Enter a Root Account password.
  5. Select Update.

Disabling the root account

To disable the root account, refer to K15632: Disabling admin and root accounts using the Configuration utility or tmsh.
