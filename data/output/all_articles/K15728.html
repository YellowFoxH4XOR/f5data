Known Issue

Connection mirroring between high throughput systems may fail.

This issue occurs when all of the following conditions are met:

  • Connection mirroring is enabled between high throughput devices, such as VIPRION. High throughput devices have multiple 10 GB interfaces.
  • The connection mirroring channel fails due to a buffer overflow condition caused by a large number of mirrored connections.

Impact

New connections will not be mirrored while the failed mirroring channel resets or reestablishes connectivity.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Some client connections are not successfully mirrored after a failover event.
  • The system logs the following message to /var/log/ltm indicating the connection mirroring channel has failed:

    err tmm[10293]: 01340002:3: HA Connection with peer 10.12.23.120:1029 for traffic-group /Common/traffic-group-1 lost

Workaround

To work around this issue, you can increase the state mirror queue length to the maximum value of 256 MB. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Modify the database key for the state mirror queue to the maximum value by typing the following command:

    modify sys db statemirror.queuelen value 268435456

Note: For additional information on system database keys, such as obtaining default values, refer to K16953: BIG-IP system database variables are automatically saved when modified.
