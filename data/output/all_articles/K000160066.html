K000160066: Resolving ARP Resolution Issues and Duplicate ARP Entries Due to LACP Trunk Partner Key Mismatch

Type
Support Solution
Published
2026-02-18
Updated
2026-02-18
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160066

Description

ARP resolution problems and duplicate ARP entries occur on specific IP addresses, causing communication failures and intermittent connectivity. Symptoms include:

  • Traffic termination failures on affected IP addresses
  • Duplicate ARP entries are preventing proper traffic completion
  • MAC address flapping on the switch and/or BIG-IP
  • ARP resolution failures
  • Traffic blackholing or intermittent connectivity
  • One or more trunk member interfaces showing different partner keys

Environment

  • BIG-IP LTM version 17.1.3
  • Platform: F5-VPR-LTM-C2400-AC, F100
  • LACP trunk configured with two member ports
  • Both trunk member ports are physically up and connected to the same remote device (same partner MAC address)
  • Partner keys for LACP trunk members are different (e.g., 33,111 and 33,543)
  • Switch-side configuration involving port-channels or link aggregation groups (LAGs)

Cause

The LACP trunk is misconfigured on the switch side. Both member interfaces must have the same partner key to function correctly as a single logical link. When the partner keys differ, it indicates that the switch is not bundling the interfaces into the same port-channel. This misconfiguration results in:

  • MAC address flapping between the switch and BIG-IP
  • Duplicate ARP entries on both devices
  • ARP resolution failures, as ARP requests and responses may traverse different physical links
  • Disruption of proper MAC learning
  • Traffic blackholing or loss

Answer/Recommended Actions

 

  1. Verify the LACP trunk configuration on the BIG-IP system:
  • Use the following command to display trunk details:
    • tmsh show net trunk <trunk_name> detail
    • Check that all member interfaces display the same partner key and partner MAC address.

       2. Review the LACP trunk configuration on the switch side:

  • Ensure both physical interfaces connected to the BIG-IP are assigned to the same port-channel or LAG.
  • Confirm that both interfaces share the same LACP configuration and are properly bundled together.
  • Verify that the switch configuration matches F5's best practices for LACP.

       3. Correct the switch configuration:

  • Reconfigure the switch to assign both member interfaces to the same port-channel.
  • Ensure consistent LACP settings (mode, timeout, system priority) across all member interfaces.

       4. Clear stale entries after correcting the configuration:

  • On the BIG-IP system:
  • tmsh delete net arp all
    • tmsh delete net fdb all
    • On the switch: Use the appropriate vendor-specific commands to clear ARP and MAC tables.

       5. Verify proper operation:

       Confirm that both ends (BIG-IP and switch) agree on:

  • LAG membership
  • Partner keys (must be identical)
  • Partner MAC addresses (must be identical)
  • Hashing policy
    • LACP mode and timeout settings
  • Use the following command to verify trunk status:
    • tmsh show net trunk <trunk_name> detail

       6. Monitor the environment to ensure ARP resolution and network connectivity are restored.

Additional Information

  • Per F5 best practices, both member ports in a LAG must have the same partner key. A mismatch indicates the switch is treating the interfaces as separate port-channels, which is not supported and leads to network instability.
  • The partner key is assigned by the LACP partner (switch) and must be consistent across all member interfaces in the same aggregation.
  • When partner keys differ, ARP requests and responses may traverse different physical links, preventing proper MAC address learning and causing duplicate ARP entries.
  • This issue is a configuration problem and is not caused by a software bug in BIG-IP version 17.1.3.
  • Physical cable cross-linking can also cause partner key mismatches. Verify that cables are properly connected to the intended switch ports.
