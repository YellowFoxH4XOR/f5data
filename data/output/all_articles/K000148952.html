Description

  • You configure an Irule similar to below, to log the reason for Load balancing failures. 
    when LB_FAILED {log local0. lb_err=[event info]}

  •  The event info command returns connection limit although a connection limit  has not been configured on the pool members

 

Environment

  • Load Balancing failure.
  • Irule "event info" command used within LB_FAILED event
  • Irule logging

 

Cause

ID754100

 

Recommended Actions

To understand the real reason for the Load Balancing failure, take a packet capture of the server side traffic between the BIG-IP and pool member. 
You can use a tcpdump command similar to below, where x.x.x.x is the IP address of the client attempting to connect to the virtual server.
tcpdump -ni 0.0:nnnp -s0 host x.x.x.x

 

Additional Information


 The irule LB_FAILED event is triggered when LTM is ready to send the request to a pool member and one hasn’t been chosen (the system failed to select a pool or a pool member), is unreachable (when no route to the target exists), has reached a queue limit, or is non-responsive (fails to respond to a connection request). 
 The specific cause of the failure is available by calling the event info command.
