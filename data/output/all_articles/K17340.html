Known Issue

The BIG-IP management (MGMT) interface may erroneously send IPv6 Multicast Listener Discovery (MLD) packets.

This issue occurs when the following condition is met:

  • The BIG-IP system runs on any of the following affected platforms or blades:

    • BIG-IP platforms

      BIG-IP 2000 series (C112), 4000 series (C113), 5000 series (C109), 7000 series (D110) or 10000 series (D113).

    • VIPRION blades

      B2100 (A109), B2150 (A113), B2250 (A112), B4100 (A100), B4200 (A107), B4200N (A111), B4300 (A108), or B4340N (A110).

This issue affects only the BIG-IP platform that uses the network interface that bridged MGMT to eth0. For example, if you perform the ifconfig mgmt command at the command line on the affected platform, you will observe a valid output detailing the network interface MGMT from the ifconfig command.

Note: This issue does not affect BIG-IP 1600, 3600, 3900, 6900, 8900, 8950, 11000, 11050, BIG-IP Virtual Edition (VE), and vCMP instances (vCMP guests hosted by BIG-IP platforms).

Impact

There is no impact to production traffic. However, the BIG-IP system may create additional management traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When viewing a tcpdump capture for the eth0 MGMT interface, you observe that the BIG-IP MGMT interface sends IPv6 MLD packets.

    For example:

    10:00:18.539065 00:00:00:00:00:01 > 00:00:00:00:00:02, ethertype IPv6 (0x86dd), length 86: 4500:39:721C:0:100:: > FF02::1: HBH ICMP6, multicast listener querymax resp delay: 1000 addr: ::, length 24

Workaround

To work around this issue, you can disable the unwanted IPv6 MLQ packets by typing the following command:

echo 0 > /sys/class/net/mgmt/bridge/multicast_snooping

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

To have this workaround in place when the affected BIG-IP system reboots, you can configure a custom script for the workaround command to run upon system startup. For more information, refer to K11948: Configuring the BIG-IP system to run commands or scripts upon system startup.
