Description

Unable to establish connection with SSL VIP configured for mutual (client/server) authentication (mTLS).

Environment

BigIP SSL VIP with enabled (mTLS)

Cause

The issue might be related with incorrect mTLS implementation.

For instance - client is unable to present correct certificate during SSL handshake process and BigIP was configured to abort connection attempt if no valid client's certificate was provided.

Recommended Actions

In order to correctly implement mTLS following components needs to be present:

  • Root/CA certificate chain required for client's certificate validation installed on BigIP (this should not be confused with chain certificate used to validate server's certificate). This could be internal company Certificate Authority.
  • SSL client profile options: "Trusted Certificate Authorities", "Advertised Certificate Authorities" set to "Root/CA" certificate bundle mentioned in previous step.
  • SSL client profile option: "Client Certificate" set to Request or Require. When profile is set to: "Request" (unlike "Require") BigIP system will request client's certificate but will still allow connection to be established when client will not present any valid certificate.
  • In order for client to successfully authenticate and establish connection with mTLS VIP - it needs to present it's own certificate upon receiving request from server-side (mTLS VIP) during SSL handshake that was signed by CA selected in client-ssl profile for: "Trusted Certificate Authorities", "Advertised Certificate Authorities".
  • Also in order to complete SSH handshake client needs to be able to decrypt message that was encrypted by the server (with SSL public key) using SSL private key. For this reason SSL private key also needs to be installed on client-end (in web-browser certificate store).
  • In most cases certificate chain, certificate and private key are stored in single .PFX file also known as a PKCS#12 file, which is a digital certificate and private key container format used to securely store and transport certificates and their associated private keys. Please note that methodology of PKCS#12 file installation on client-end varies depending on the operating system.
