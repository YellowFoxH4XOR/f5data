K31640940: Aspen Mesh Packet Inspector (pcapper): Port change in mid-transaction

Type
Support Solution
Published
2021-09-29
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K31640940

Description

A complete transaction usually consists of opening a connection, request from the client, response from the server and terminating that connection. In kubernetes environment, most of the communication happens via service objects which have some endpoint to which the traffic is forwarded. Client is not aware of the upstream (server) real IP address, but it uses the service FQDN. 

So, when the envoy filter runs in the sidecar of every application, it collects the necessary metadata and creates the packet captures files before the traffic is encrypted to be sent forward. 

If the pcapper timeout is shorter than the time it takes the client to receive a response. This can happen in any configuration but is exacerbated by shorter timeouts.

Expected:

On the client-side capture, the tuple (srcIP, srcPort, destIP, destPort) is the same for all the packets reported for the transaction.

On the server-side capture, the tuple (srcIP, srcPort, destIP, destPort) is the same for all the packets reported for the transaction.

The client-side tuple and the server-side tuple may differ in srcPort (necessary because this is a virtual capture and client has no information about the real endpoint it needs to connect).

Actual:

When triggered, the client-side capture may have packets from different tuples. For instance, the 3-way handshake and request may use one tuple (srcIP, srcPort, destIP_1, destPort_2), and the response and teardown may use a different tuple (srcIP, srcPort, destIP_2, destPort_2)

Environment

  • Aspen Mesh: 1.6.x, 1.9.x

Cause

None

Recommended Actions

None

Additional Information

Currently, destination address might not get updated in scenarios where the timeout for the pcapper has occurred or the buffer size has been filled. This issue has been resolved in the Aspen Mesh 1.9.5-am3 version. Follow this link for more information. After the fix, pcapper will only send packets to the analytics tool after the upstream information has been updated.
