Description

Some clients that allow only RSA ciphers on TLS 1.2 fail to connect to load balancers using our auto-certs, which are ECDSA certificates. The same service works if the client allows ECDSA (or uses TLS 1.3).

 

Environment

  • F5 Distributed Cloud
  • HTTP Load Balancer

Cause

TLS 1.2 ciphers encode the auth method: …-RSA-… requires an RSA cert; …-ECDSA-… requires an ECDSA cert. If the server (in this case the load balancer) presents ECDSA and the client offers only RSA suites, the handshake fails.

 

Recommended Actions

  1. Preferred: Allow ECDSA on the clientside (or permit TLS 1.3).
  2. Alternative: Create a load balancer and upload a custom RSA Cert.

Additional Information

You can check the key type of the cert with the following command:

openssl s_client -connect <host>:443 -servername <host> -showcerts </dev/null 2>/dev/null | openssl x509 -noout -text | egrep -i 'Subject:|Issuer:|Signature Algorithm'

Repro Steps:

 

Test failing Scenario with TLS1.2 and RSA cipher:

openssl s_client -connect <host>:443 -servername <host> -tls1_2 -cipher ECDHE-RSA-AES256-GCM-SHA384
