Topic

This article describes the Randomize Query Character Case setting of the BIG-IP DNS Cache and the behavior of the BIG-IP DNS Cache resolver when the setting is enabled.

Description

When the Randomize Query Character Case setting is enabled, the BIG-IP DNS Cache resolver randomizes the character case of the name in the question section of a DNS query. The question section of an authentic DNS response contains a copy of the name formatted with matching character cases. This is an additional security measure against DNS cache poisoning, which extends beyond existing measures such as source port randomization, transaction ID randomization, and bailiwick checking. With Randomize Query Character Case enabled, an attacker must not only match the source port and transaction ID but also guess the correct case of each character in the name, which makes it more difficult to forge a DNS response.

Note: The Randomize Query Character Case setting is enabled by default. You have the option to disable it in BIG-IP 11.4.1 and later.

BIG-IP DNS Cache sequence of events

When using the BIG-IP DNS Cache with the Randomize Query Character Case setting enabled, the following sequence of events occurs:

Note: The following examples do not show complete DNS responses.

  1. The client sends a DNS query to the BIG-IP system for the DNS Cache to handle. The query includes information similar to the following:

    IPs: 172.24.171.201.53309 > 172.24.14.250.53
    Transaction ID: 4652
    Question: A www.example.com.

  2. The BIG-IP system answers the query from data stored in the cache. If the answer does not exist in cache, the next event occurs.
  3. Using randomized character case, the BIG-IP system recursively resolves the name. If no nameserver data exists in the cache, the BIG-IP system starts the process by sending a query to one of the DNS Root nameservers. The query from the BIG-IP system includes information similar to the following:

    IPs: 172.24.14.19.16693 > 192.228.79.201.53
    Transaction ID: 13477
    Question: A wwW.EXAmPLe.com.

    The nameserver answers with a referral and echoes back the name with the same character case in the question section. The nameserver’s answer to the BIG-IP system includes information similar to the following:

    IPs: 192.228.79.201.53 > 172.24.14.19.16693
    Transaction ID: 13477
    Question: A wwW.EXAmPLe.com.
    Answer:
    com. NS g.gtld-servers.net.
    com. NS e.gtld-servers.net.
    Glue Records:
    e.gtld-servers.net. A 192.12.94.30
    g.gtld-servers.net. A 192.42.93.30

  4. The BIG-IP system sends the query to the authoritative nameserver provided in the root nameserver's referral and continues randomizing the character case of the name. The BIG-IP system’s query to the nameserver includes information similar to the following:

    IPs: 172.24.14.19.25445 > 192.12.94.30.53:
    Transaction ID: 17796
    Question: A Www.eXaMPLE.COM.

    The nameserver’s response to the BIG-IP system includes information similar to the following:

    IPs: 192.12.94.30.53 > 172.24.14.19.25445:
    Transaction ID:17796
    Question: A Www.eXaMPLE.COM.
    Answer:
    eXaMPLE.COM. NS a.iana-servers.net.
    eXaMPLE.COM. NS b.iana-servers.net.
    Glue Records:
    a.iana-servers.net. A 199.43.135.53
    b.iana-servers.net. A 199.43.133.53

  5. The BIG-IP system follows each referral and continues using randomized query case each time. The BIG-IP system’s query to the nameserver includes information similar to the following:

    IPs: 172.24.14.19.34509 > 199.43.133.53.53
    Transaction ID: 61443
    Question: A WWw.eXAMpLE.Com.

    The nameserver’s response to the BIG-IP system includes information similar to the following:

    IPs: 199.43.133.53.53 > 172.24.14.19.34509
    Transaction ID: 61443
    Question: A WWw.eXAMpLE.Com.
    Answer:
    www.example.com. A 93.184.216.34
    Authority:
    example.com. NS a.iana-servers.net.
    example.com. NS b.iana-servers.net.

  6. The BIG-IP system provides the answer to the client and stores the answer in the DNS Cache. The BIG-IP system’s query to the client includes information similar to the following:

    IPs: 172.24.14.250.53 > 172.24.171.201.53309
    Transaction ID: 4652
    Question: A www.example.com.
    Answer:
    www.example.com. A 93.184.216.34
    Authority:
    example.com. NS a.iana-servers.net.
    example.com. NS b.iana-servers.net.

Recommendations

When configuring a BIG-IP DNS Cache with the Randomize Query Character Case setting enabled, consider that not all nameservers echo back the query exactly as it appears, and this may cause the BIG-IP to drop authentic responses.

In BIG-IP 11.4.1 and later, you can disable the Randomize Query Character Case setting if you repeatedly encounter SERVFAIL messages when the BIG-IP system drops an authentic response that did not match the character query case.

You can also create a DNS cache forward zone for each zone in which authentic responses are provided but do not have matching character case. For more information about configuring DNS cache forward zones, refer to the Configuring DNS Caching chapter of the BIG-IP DNS Services: Implementations guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Note: The DNS Cache Forward Zones feature is introduced in BIG-IP 11.5.0.
