Topic

The BIG-IP ASM system sets two types of cookies in HTTP responses to enforce elements in the security policy: the BIG-IP ASM Main cookie and the BIG-IP ASM Frame cookie.

Note: For more information, refer to K6850: Overview of BIG-IP ASM cookies.

One function of the BIG-IP ASM Main cookie is to validate domain cookies sent by a web server. The BIG-IP ASM system does this by parsing HTTP responses from the web server for the Set-Cookie header. If the Set-Cookie header is present, the BIG-IP ASM performs a hash on the cookie, and inserts the hash value into the BIG-IP ASM Main cookie. When the returning client sends the Main cookie in a subsequent request and the BIG-IP ASM system is unable to verify the hash value, the following violation is logged to the Reporting page:

Modified domain cookie

The BIG-IP ASM system may also generate a Modified domain cookie violation in the following circumstances:

Persistent cookies

BIG-IP ASM cookies are session based and do not get written to disk. If a site that is protected by the BIG-IP ASM system uses persistent cookies with an extended timeout period, the cookies may generate the Modified domain cookie violation. Persistent cookies should be configured as Allowed Cookies in the security policy.

Cookies set prior to the BIG-IP ASM system installation

Cookies that were set by the web server prior to implementing the BIG-IP ASM security policy may continue to generate the Modified domain cookie violation until the web server resets them or configured as Allowed Modified Cookies in the security policy. The BIG-IP ASM system needs to validate the cookie at the time it is set by the web server in order for the policy to accept the cookie as legitimate.

BIG-IP ASM cookie expiration

The BIG-IP ASM Main cookie has a default expiration time of 600 seconds. For more information about BIG-IP ASM cookies, refer to K6850: Overview of BIG-IP ASM cookies.
