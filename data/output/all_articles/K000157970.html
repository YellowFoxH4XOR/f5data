K000157970: Swapping IP addresses between two virtual servers may result in a corrupted configuration

Type
Support Solution
Published
2025-11-25
Updated
2026-04-27
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000157970

Description

Swapping virtual IP (VIP) addresses between two virtual servers in a single CLI transaction on BIG-IP can result in one or more virtual servers entering a corrupted configuration state, indicated by the "EDENY" conf_status when checking tmctl tmctl virtual_server_stat. When this occurs, the affected virtual server(s) deny traffic and become unreachable. Error messages observed in the tmm logs include "Failed to bind to address" and "Listener config update failed ... ERR:ERR_USE". Attempts to resolve the issue by enabling/disabling the virtual server or changing unrelated settings do not restore normal operation.

Environment

  • Product: BIG-IP LTM
  • Version: 17.x
  • Configuration: Multiple virtual servers with unique VIP addresses
  • Actions: Swapping VIP addresses between virtual servers using tmsh CLI transactions
  • tmm Log messages: "Failed to bind to address", "Listener config update failed ... ERR:ERR_USE"
  • Command usage: create cli transaction, modify ltm virtual ... destination ..., submit cli transaction

Cause

When swapping VIP addresses between two virtual servers in a single CLI transaction, the system attempts to assign the same IP address to multiple virtual servers before the swap is fully processed. This results in a binding conflict, causing one or more virtual servers to enter "EDENY" conf_status and deny traffic. This is expected behavior due to the non-serial processing of transaction commands.

Recommended Actions

  • Do not swap VIP addresses between two virtual servers in a single CLI transaction.
  • To change VIPs between virtual servers, follow these steps:
      1. Change the affected virtual server's VIP to a temporary, unused IP address in one transaction.
      2. Change the VIP to the desired address in a separate transaction.
  • If a virtual server enters "EDENY" conf_status: Example as below

    tmctl virtual_server_stat -s name,conf_status

     

    name conf_status

    -------------- -----------

    /Common/vs1 OK

    /Common/vs2 EDENY


      1. Change its VIP to a random, unused IP address in one transaction.
      2. Change the VIP back to the correct address in a separate transaction.

Additional Information

  • The commands in a CLI transaction are not processed strictly serially; there may be a lag between processing steps, which can result in temporary conflicts.
  • This behavior is functioning as designed and is not a software defect.
