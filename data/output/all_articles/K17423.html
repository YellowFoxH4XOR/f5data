Known Issue

Modifying an existing iRule may fail with an error.

This issue occurs when all of the following conditions are met:

  • You have an existing iRule that references a system object, such as a pool or virtual server.
  • You attempt to modify this iRule using either the Configuration utility or the Traffic Management Shell (tmsh).

Impact

The iRule changes will not take effect.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to save your modifications, you view an error message in the /var/log/ltm file that appears similar to the following example:

    01070710:3: Database error (13), Can't save/checkpoint DB object, class:private_rule_dependency status:13 - EdbCfgObj.cpp, line 126.

  • The modified iRule fails to update.

Workaround

To work around this issue, you can manually modify the iRule in the bigip.conf file and reload the configuration from the BIG-IP command line. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Edit the /config/bigip.conf file and find the iRule that is failing to modify.
  3. Modify the iRule.
  4. Save the edited file.
  5. Log in to the tmsh utility by typing the following command:

    tmsh

  6. Reload the configuration by typing the following command:

    load sys config
