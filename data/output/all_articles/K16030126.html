Description
After upgrading the device which contains an iRule with 'class match' command, the configuration fails to load with below error:

01070151:3: Rule [/Common/irule-name] error: /Common/irule-name:2: error: ["wrong # of arguments"][class match [IP::client_addr] not equals data-group-name]

This issue occurs when the iRule contains syntax similar to the following example:

when HTTP_REQUEST {
if { [class match [IP::client_addr] not equals data-group-name] }   <<<-------------
{
   HTTP::redirect "https://www.abc.com"
}
}

Environment

  • Upgraded from older version to 14.x or later 
  • Configuration fails to load
  • Irule configured which contains syntax:  class match [IP::client_addr] not equals data-group-name]
     

Cause
mcpd daemon parsed the iRule and didn't accept the below part: 
class match [IP::client_addr] not equals data-group-name]

In some newer versions iRule syntax changed and mcpd won't accept "class match [IP::client_addr] not equals" part.
 

Recommended Actions

To work around this issue, you can perform one of the following actions:

  1. Create a backup copy of bigip.conf file using below command:
    cp /config/bigip.conf /config/bigip.conf.backupfile
     
  2. Edit bigip.conf in vi editor using under /config folder.
    vi bigip.conf
     
  3. Hit enter to edit the file. Find above irule in config file and change the syntax of irule to below:

    when HTTP_REQUEST {
    if { not [class match [IP::client_addr] equals data-group-name]  }
    {
    HTTP::redirect "https://www.abc.com"
    }
    }
     
  4. Hit ESC on keyboard, then type :wq! to save and exit the file.
     
  5. Verify the config load again using below command: 
    tmsh load sys config verify
     
  6. If no errors, then run below commands to save the config and load:
    tmsh save sys config
    tmsh load sys config
