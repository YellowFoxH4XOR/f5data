Description

Configure the Machine Cert authentication, but it cannot work.

  • When apply the APM Access policy, the error log will be printed in /var/log/apm:

err apmd[<pid>]: 0149015f:3: MachineCert Agent: Init failed in '/<partition>/<machine cert auth agent name>_machinecert_auth_ag_1' reason 'Loading CA file failed'

  • If enable debug log for access policy, the log below should be printed in /var/log/apm, but it is not printed.

info apmd[<pid>]: 01490125:6: /<partition>/<access profile name>:<partition name>:<session ID>: Client response for the machine cert request: No matching certificate found

info apmd[<pid>]: 01490125:6: /<partition>/<access profile name>:<partition name>:<session ID>: Client response for the machine cert request: A matching certificate received

Environment

  • BIG-IP APM
  • Virtual server
  • Access profile
  • Machine Cert authentication
  • Certificate Authority
  • CA Certificate

Cause

The Certificate Authority contain the CA certificate which is belong to other partition.

Recommended Actions

Please check the Access profile, the Certificate Authority, and CA certificate, make sure they are in same partition.

Additional Information

One example to reproduce the issue:

The access profile is belong to the partition Test-partition. It contain the Machine Cert authentication agent, contain the Certificate Authority.

The Certificate Authority is belong to the partition Test-partition, contain the CA certificate in other partition, like Common partition. For example:

ltm profile certificate-authority /Test-partition/CA_Bundle_Test {    /// It is Test-Partition
    app-service none
    authenticate-depth 9
    ca-file /Common/test_CA_Bundle                         ///// CA is belong to the Common Partition, it is the root cause.
    crl-file none
    defaults-from /Common/certificateauthority
    update-crl false
}
