K14600540: Increasing Tripo Storage

Type
Support Solution
Published
2022-03-30
Updated
2023-02-21
Applies to
  • Traffix SDC: 5.2.X, 5.1.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K14600540

Description

Tripo storage stores Diameter session information needed for routing of stateful messages. This article describes the steps involve in increasing the maximum total entries allowed in the Tripo storage. Prior to using this article it is necessary to ensure there is sufficient RAM on all Tripo nodes.

Environment

  • Tripo

Cause

One of the most common purposes of increasing Tripo storage is expecting growth in future traffic.

Recommended Actions

The following steps serve as a general guide only and does not take into consideration any custom SDC setup. We strongly encourage customers to seek additional assistance through F5 Professional Services for the appropriate Tripo storage memory sizing.
 

  1. Backup
    1. Configuration files on each Tripo node
  • mkdir /tmp/TripoReconfiguration
  • cp /etc/fstab /tmp/TripoReconfiguration
  • cp /srv/traffix/.lastRev /tmp/TripoReconfiguration
  • cp /srv/traffix/.oamdb_pillar /tmp/TripoReconfiguration
  • cp /home/traffix/Tripo/sconf/installerTripoParams.scf /tmp/TripoReconfiguration
  • cp /home/traffix/Tripo/sconf/SLF_SysConf.scf /tmp/TripoReconfiguration
  1. Cassandra database data
  • echo "select * from topology.tripo;" | /opt/cassandra/bin/cqlsh <oamDB IP address>
  • Copy and paste data related to tripo to file and store it in /tmp/TripoReconfiguration
  • vi /tmp/TripoReconfiguration/CassandraTripoEntries and save changes
  1. Expanding Tripo node instance one
    1. Stop Tripo
  • monit stop <Tripo process name>
  1. Update /etc/fstab
  • vi /etc/fstab
  • Change the size of /dev/shm as per calculation. (Calculation is not shown in this article.)
  • tmpfs      /dev/shm        tmpfs   defaults,size=2050m,noexec,nodev,nosuid        0       0
  • Save the fstab
  1. Remount tmpfs
  • df -h
  • mount -o remount,size=2G /dev/shm
  • df -h
  1. Clean Tripo
  • su traffix
  • cd ~/Tripo/env/linux-x86_64/
  • . DefEnv Tripo
  • cleansh
  1. Update Tripo maxSessions in Cassandra
The UPDATE command needs to be executed on all row entries of the topology.tripo table using each row respective primary key of "siteId", "vmName" and "name".
  • echo "SELECT * FROM topology.tripo ;" | /opt/cassandra/bin/cqlsh <oamDB IP address>
  • echo "UPDATE topology.tripo SET "maxSessions"=10000 WHERE "siteId"='<sitename>' and "vmName"='server1a' and "name"='TRIPO';" | /opt/cassandra/bin/cqlsh <oamDB IP address>
  1. Update pillar and push changes using salt
  • cd /srv/traffix/
  • ll -a
  • rm .lastRev  .oamdb_pillar
  • ll -a
  • /etc/init.d/salt-master restart
  • ll -a
  • less .oamdb_pillar
  • salt '*' state.highstate
  • diff /home/traffix/Tripo/sconf/installerTripoParams.scf /tmp/TripoReconfiguration/installerTripoParams.scf
  1. Reconfigure Tripo config file
  • vi /home/traffix/Tripo/sconf/SLF_SysConf.scf
  • change
  • <NumOfElementsInInst>XXX</NumOfElementsInInst>
  • <NumSiteRepTableInst>XXX</NumSiteRepTableInst>
  1. Start Tripo
  • monit start <Tripo process name>
  1. Repeat 2.1 to 2.8 on Tripo instance two after resized Tripo instance one has fully synced from other Tripo mate.
