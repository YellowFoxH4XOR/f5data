Known Issue

This is the result of a known issue. If a configuration change is made to a virtual server that is configured with a FastL4 and persistence profile, subsequent loads of the configuration may cause TMM to crash.

This behavior occurs when the following two conditions are met:

  • The persistence profile is removed from the virtual server and either deleted or renamed on the system
  • The FastL4 profile is updated. For example, the idle timeout option is updated with a new timeout value.

When both changes occur, any subsequent reloads of the configuration using bigpipe load may result in a TMM crash.

Note: This behavior exists in BIG-IP version 9.4.2 and later, in reference to the way the BIG-IP system handles configuration changes with FastL4 and persistence profiles. However, due to changes in the code, no TMM crash occurs.

F5 Product Development is tracking this issue as ID 333593 (formerly CR94576).
