K000137131: The BIG-IP Next Central Manager may fail to create BIG-IP Next instance in the VMWare provider due to slow disk in the vSphere environment

Type
Knowledge
Published
2023-10-19
Updated

Status

Applies to
  • BIG-IP Next
  • BIG-IP Next Central Manager: 20.3.X, 20.3.0, 20.2.0, 20.1.X, 20.1.0, 20.2.X, 20.2.1, 20.0.1, 20.0.2, 20.1.1
Source
https://my.f5.com/manage/s/article/K000137131

Description

The BIG-IP Next Central Manager may fail to create BIG-IP Next instance in the VMWare provider due to slow disk in the vSphere environment. You may observe the Instance creation alert in the BIG-IP Next Central Manager Alerts & Notifications page with the following descriptions:

  • failed to login to BIG-IP Next instance (address: <BIG-IP Next instance management IP>): login failed with code 503
  • unable to login to the instantiated BIG-IP Next instance. This can happen when the VSPHERE provider has insufficient resources to start the new virtual machine. Check the resource utilization on the provider and try again.

Environment

  • BIG-IP Next Central Manager
  • VMWare vSphere

Cause

This is likely due to slow disk in the vSphere environment.

Recommended Actions

You may want to retry the instance creation from BIG-IP Next Central Manager again. If subsequent retries continue to fail with the same error, you may want to manually create the instance in the vSphere environment first and then onboard and discover the instance using BIG-IP Next Central Manager.

Alternatively, you can use the BIG-IP Next Central Manager REST API to increase/decrease the delay by specifying a custom value for sleep_time in the instance creation template as documented in Compose an instantiation, onboarding and discovery workflow for a BIG-IP Next. To do so, perform the following procedure from a workstation that has both the curl and jq utilities installed:

  1. Login to the BIG-IP Next Central Manager REST API using the following command syntax:

    curl -sk -H "Content-Type: application/json" -X POST https://<Central Manager management IP>/api/login -d '{ "username": "admin", "password": "<Central Manager admin user password>" }' | jq -M .

    For example,

    curl -sk -H "Content-Type: application/json" -X POST https://192.168.61.181/api/login -d '{ "username": "admin", "password": "MyPassword" }' | jq -M .

Additional Information

By default, the BIG-IP Next Central Manager 20.0.1 through 20.0.2 imposes a delay of 600 seconds (sleep_time) for the creation of the BIG-IP Next instance in VMWare vSphere environment before attempting to onboard the instance and add to the BIG-IP Next Central Manager. Starting in BIG-IP Next Central Manager 20.1.0, this delay (sleep_time) is 15 minutes when you attempt to create a new instance using a VMware vSphere provider. However due to a known issue (ID 1575137), the BIG-IP Next Central Manager 20.1.0 does not allow you to change this setting in the webUI. This issue is fixed in BIG-IP Next Central Manager 20.2.0 and is now configurable via the BIG-IP Next ready wait time (minutes) setting under the Troubleshooting tab when you attempt to create a new instance using a VMware vSphere provider; this setting only allows you to select from the list of values of 15, 30, 45 or 60 minutes. You may want to adjust this number according to your VMWare vSphere environment.
