Known Issue

This is the result of a known issue. If the BIG-IP LTM receives a connection with an MSS value of less than 536 bytes, or if no MSS value is provided, and syncookies are activated for the connection, the TMM process can crash. The resulting connection is given an MSS value of zero, which prevents the BIG-IP system from transferring data.

Important: This is the result of an issue introduced in BIG-IP version 9.3.1 Hotfix-BIGIP-9.3.1-66.0-HF5. Systems not running Hotfix-BIGIP-9.3.1-66.0-HF5 are not affected by this issue.

F5 Product Development tracked this issue as ID 335635, ID 305318, and ID 329001 (formerly CR117246), and it was fixed in BIG-IP version 9.4.7. For more information about upgrading, refer to the BIG-IP release notes.

Additionally, this issue has been fixed in cumulative hotfix, Hotfix-BIGIP-9.3.1-69.0-HF6, which has been issued for BIG-IP version 9.3.1; and Hotfix-BIGIP-10.0.0-5460.0-HF1, which has been issued for BIG-IP version 10.0.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

Workaround

To work around this issue, increase the syncookie activation threshold to 64K or larger by typing the following command:

bigpipe db Connection.SynCookies.Threshold 65536

Note: The Connection.SynCookies.Threshold variable may need to be set to a higher value for configurations containing numerous Layer7 virtual servers with connections using syncookies.

Note: For more information, refer to K7847: Overview of BIG-IP SYN cookie protection.
