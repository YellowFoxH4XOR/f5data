K000151373: Reloading Nginx results in an Nginx App Protect error stating "Could not parse/validate the '/policy/brute-force-attack-preventions' element. Invalid reference for urlReference" when trying to configure brute force prevention

Type
Support Solution
Published
2025-05-15
Updated
2025-09-30
Source
https://my.f5.com/manage/s/article/K000151373

Description

Reloading Nginx results in an Nginx App Protect error stating "Could not parse/validate the '/policy/brute-force-attack-preventions' element. Invalid reference for urlReference" when trying to configure brute force prevention

Environment

  • Nginx App Protect configured

  • Trying to enable Brurte Force Prevention in the Nginx App Protect policy

Cause

This error is due to the Nginx App Protect policy not having a login URL and user-defined URL defined.

Answer/Recommended Actions

A user defined URL is configured under the policy json key and looks like the following example:

{
  "policy": {
    "name": "BruteForcePolicy",
    "template": {
      "name": "POLICY_TEMPLATE_NGINX_BASE"
    },
    "applicationLanguage": "utf-8",
    "enforcementMode": "blocking",
    "urls": [
      {
        "method": "*",
        "name": "/html_login",
        "protocol": "http",
        "type": "explicit"
      }
    ]
  }
}

A login URL is configured under the policy json key and looks like the following example:

    "login-pages": [
      {
        "accessValidation": {
          "responseContains": "Success"
        },
        "authenticationType": "form",
        "url": {
          "method": "*",
          "name": "/html_login",
          "protocol": "http",
          "type": "explicit"
        },
        "usernameParameterName": "username",
        "passwordParameterName": "password"
      }
    ]

The Brute Force Attack Prevention configuration exists under the policy key and looks like the following example:

    "brute-force-attack-preventions": [
      {
        "bruteForceProtectionForAllLoginPages": false,
        "loginAttemptsFromTheSameIp": {
          "action": "alarm",
          "enabled": true,
          "threshold": 20
        },
        "loginAttemptsFromTheSameUser": {
          "action": "alarm",
          "enabled": true,
          "threshold": 3
        },
        "reEnableLoginAfter": 3600,
        "sourceBasedProtectionDetectionPeriod": 3600,
        "url": {
          "method": "*",
          "name": "/html_login",
          "protocol": "http"
        }
      }
    ]

The following example adds all three of the pieces above for a complete brute force example policy.

{
  "policy": {
    "name": "BruteForcePolicy",
    "template": {
      "name": "POLICY_TEMPLATE_NGINX_BASE"
    },
    "applicationLanguage": "utf-8",
    "enforcementMode": "blocking",
    "urls": [
      {
        "method": "*",
        "name": "/html_login",
        "protocol": "http",
        "type": "explicit"
      }
    ],
    "login-pages": [
      {
        "accessValidation": {
          "responseContains": "Success"
        },
        "authenticationType": "form",
        "url": {
          "method": "*",
          "name": "/html_login",
          "protocol": "http",
          "type": "explicit"
        },
        "usernameParameterName": "username",
        "passwordParameterName": "password"
      }
    ],
    "brute-force-attack-preventions": [
      {
        "bruteForceProtectionForAllLoginPages": false,
        "loginAttemptsFromTheSameIp": {
          "action": "alarm",
          "enabled": true,
          "threshold": 20
        },
        "loginAttemptsFromTheSameUser": {
          "action": "alarm",
          "enabled": true,
          "threshold": 3
        },
        "reEnableLoginAfter": 3600,
        "sourceBasedProtectionDetectionPeriod": 3600,
        "url": {
          "method": "*",
          "name": "/html_login",
          "protocol": "http"
        }
      }
    ]
  }
}
