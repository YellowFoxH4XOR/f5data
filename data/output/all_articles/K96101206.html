K96101206: Static hosts failing to resolve a DNS hostname over Network Access Tunnel

Type
Support Solution
Published
2019-10-22
Updated

Applies to

  • BIG-IP APM: 13.X.X, 13.0.X, 13.1.5, 13.1.4, 13.1.3, 13.1.1, 13.1.X, 13.0.1, 13.0.0, 13.1.0
  • APM Clients
Source
https://my.f5.com/manage/s/article/K96101206
Description
  • Clients fail to resolve a DNS hostname when connecting to BIG-IP Network Access Tunnel.
  • Static host entries allow administrators to provide directed DNS names for end users connected via BIG-IP Network Access Tunnel regardless if connecting via Edge Client or browser.

    Following these steps will help to save the static host entries via the network access tunnel.
Environment
  • BIG-IP APM
    • Network Access configured
  • End Users running Microsoft Windows or Mac OSx
  • DNS resolution
Cause

There are many possible causes for this.  A couple examples:
  • DNS failures because the hostnames don't exist on the DNS server 
  • Administrative restrictions don't allow automatic updates to hostnames on the DNS server
  • Public FQDN is different from the internal FQDN
  • User does not have local administrative permissions
Recommended Actions

Configure static host entries for Network Access connections.  To add host and IP addresses manually to a connection-specific hosts file:

  1. On the Main tab, click Access > Connectivity / VPN > Network Access (VPN) > Network Access Lists .
    The Network Access Lists screen opens.

  2. Click the name to select a network access resource on the Resource List.
    The Network Access editing screen will open.

  3. To configure DNS and hosts settings for the network access resource, click DNS/Hosts on the menu bar.

  4. Configure static DNS and Host entries.
    Type the Host Name and the IP Address for that host in the provided fields, and click Add.

  5. Click the Update button.
    Your changes are saved and the page will refreshes.

Note: APM supports static hosts for BIG-IP Edge Client for Windows and BIG-IP Edge Client for Mac only.
 
    Additional Information

    F5 Support recommends the use of BIG-IP Edge Client DNS Relay Proxy Service.  For more information see K9694: Overview of the Windows DNS Relay Proxy service.  The way that the APM use these entries is by saving them on the remote client machine  When the client connects, these entries are going to be automatically created, and when he disconnect, they are going to automatically deleted.
    • When the Windows DNS Relay Proxy service is installed: 

      When you configure static host DNS entries in the network access under "DNS/Hosts" tab > Static Hosts list box, These entries are not in fact saved on the "etc/hosts" file in the Big-IP APM itself.
      These entries are saved in the DNS relay Proxy service database. 

      The static host entry hostname.example.com/8.8.8.8 is going to show up in the edge client logs similar to:

      Info           2019-02-26 19:15:52:381   HOST                CHostCtrl::Load properties, HostCtrl information: property #41, name="Add2Hosts0", value="hostname.example.com|8.8.8.8".
      Info           2019-02-26 19:16:24:205   DIALER              UFilterService::AddStaticEntry(), Static entry added, "hostname.example.com" => "8.8.8.8"

    • When The DNS Relay Proxy service is not installed: 

      The APM will create the  static entries under the hosts file that is located on "Windows/System32/Drivers/etc/hosts". The static host entry for hostname.example.com/8.8.8.8 are going to look like:

      8.8.8.8 hostname.example.com #ADDED BY F5 NETWORKS SSL TUNNEL - ORIGINAL RECORD#

      Note: If End users do not have rights to modify the DNS 'hosts'  file on their machine, this function will fail.

    The static host entry is going to take precedence when resolving a host name if local or remote DNS has an entry for the record.  The DNS Relay Proxy offers improvements to the Network Access split-tunneling feature, so it is best practice to use it instead of relying on the hosts file in Windows OS.
