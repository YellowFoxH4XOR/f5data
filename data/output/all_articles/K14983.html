Known Issue

The BIG-IP APM rewrite profile may fail to parse the client-side cookies that are generated with non-RFC compliant expires date formats.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for portal access.
  • Clients accessing BIG-IP APM portal access generate cookies using JavaScript.
  • The date format used for the cookie expires property is non-RFC compliant.

Impact

Cookie-dependent content processed by the BIG-IP APM rewrite profile may not function as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Client's connection to BIG-IP APM portal access silently fails, unexpectedly.
  • In some instances, clients that use the Microsoft Internet Explorer browser to access the portal, encounter behavior similar to the following example:

    If the client logs out of the Internet Explorer BIG-IP APM portal access session and then logs back in, this action triggers the Internet Explorer browser to display the following message:

    Operation is denied

    After displaying the Operation is denied message, the Internet Explorer browser abruptly closes and displays a pop-up warning message similar to the following example:

    Internet Explorer has encountered a problem and needs to close. We are sorry for the inconvenience.

  • In some instances clients using the Google Chrome browser to access the portal encounter a browser error message similar to the following example:

    403 (Forbidden) Refused to get unsafe header "Set-Cookie"
