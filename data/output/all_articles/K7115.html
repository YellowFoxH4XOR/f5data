Topic

This article applies to BIG-IP 9.4.x - 10.x. For information about other versions, refer to the following articles:

  • K13367: Managing log files on the BIG-IP system (11.x - 13.x)
  • K7259: Managing log files on the BIG-IP system (9.0.0 - 9.3.x)

Note: For information about the BIG-IP log file system, refer to K8479: BIG-IP log file system changes.

Note: Beginning in BIG-IP 9.4.2, the logrotate configuration file is dynamically generated from a template file each time the BIG-IP system boots. Some of the procedures outlined in this article are version-specific; ensure that you are referring to the correct procedure for your BIG-IP software version before you make any changes.

The BIG-IP system uses the logrotate program to rotate the logs on a daily basis. Beginning with BIG-IP 9.4.0, you can manage the following log-related elements on the BIG-IP system:

  • Managing the size of the log file system
  • Changing the log rotation frequency
  • Changing the age at which log files become eligible for removal
  • Changing the number of archive copies that the system retains

Managing the size of the log file system (9.4.x)

Important: Beginning with BIG-IP 10.0.0, the resize-logFS utility was deprecated due to major architectural changes. BIG-IP systems running 10.0.x include the utility; however, any attempts to change the size of the log file system will fail. Beginning with BIG-IP 10.1.0, the resize-logFS utility was removed. Use of this utility is only supported in BIG-IP 9.x.

In BIG-IP 9.4.x, systems containing hard drives allocate a limited amount of disk space for storing the log files. The default amount of disk space that the BIG-IP system allocates for the log file is 7 GB.

You can change the amount of disk space the BIG-IP system allocates for the log file system by using the resize-logFS script.

The minimum amount of disk space that you can specify for the log file system is 1 GB. The maximum amount of disk space that you can specify is 10 GB.

To change the amount of disk space the BIG-IP system allocates for the log file system, type the following command:

resize-logFS

Note: When you run the resize-logFS script, the BIG-IP system prompts you for the amount of disk space you want to allocate for the log file system. The script also validates the following:

  • The amount of disk space you specify falls within the valid range of 1 to 10 GB
  • The BIG-IP system has enough disk space to allocate the requested amount

Changing the log rotation frequency

BIG-IP 9.4.2 or later

Important: The following procedure will not survive a software upgrade. If a BIG-IP system requires upgrading, perform the following procedure (again) after the upgrade.

Important: This procedure instructs you to edit a file located on the /usr filesystem. Beginning with BIG-IP 10.1.0, the /usr filesystem is mounted in read-only mode. If you are performing this procedure on BIG-IP 10.1.0 or later, you must first remount /usr in read-write mode. To do so, refer to the procedure in K11302: The /usr file system is mounted in read-only mode.

  1. Log in to the BIG-IP system command line.
  2. Using a text editor, open the /usr/share/defaults/config/templates/logrotatecommon.tmpl file.
  3. Locate the following section:

    # rotate log files daily
    daily

  4. Change the setting as required. Legal values include:
    • daily
    • weekly
    • monthly

    For example, to configure the BIG-IP system to rotate logs on a weekly basis, replace daily with weekly.

  5. Save the file and quit the editor.
  6. Move the logrotate script to the appropriate crontab directory by using the following command syntax:

    mv /etc/cron.daily/logrotate /etc/<cron directory>/

    Replace <cron directory> with one of the following directories:

    • cron.daily
    • cron.weekly
    • cron.monthly

    For example, if in step 4 you have configured the BIG-IP system to rotate logs on a weekly basis, you would type the following command:

    mv /etc/cron.daily/logrotate /etc/cron.weekly/

The BIG-IP system will use the new setting the next time the crontab utility runs the logrotate script.

BIG-IP 9.4.0 or 9.4.1

Important: The following procedure will not survive a software upgrade. If a BIG-IP system requires upgrading, perform the following procedure (again) after the upgrade. Alternatively, you can configure the BIG-IP system to include any edited or moved files in a UCS file collection, which allows those changes to survive a single upgrade. For more information about modifying the contents of UCS files, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

  1. Log in to the BIG-IP system command line.
  2. Using a text editor, open the /etc/logrotate_common.conf file.
  3. Locate the following section:

    # rotate log files daily
    daily

  4. Change the setting as required. Legal values include:
    • daily
    • weekly
    • monthly

    For example, to configure the BIG-IP system to rotate logs on a weekly basis, replace daily with weekly.

  5. Save the file and quit the editor.
  6. Move the logrotate script to the appropriate crontab directory by using the following command syntax:

    mv /etc/cron.daily/logrotate /etc/<cron directory>/

    Replace <cron directory> with one of the following directories:

    • cron.daily
    • cron.weekly
    • cron.monthly

    For example, if in step 4 you have configured the BIG-IP system to rotate logs on a weekly basis, you would type the following command:

    mv /etc/cron.daily/logrotate /etc/cron.weekly/

The BIG-IP system will use the new setting the next time the crontab utility runs the logrotate script.

Changing the age at which log files become eligible for removal

The logrotate script deletes log files older than the number of days specified by the Logrotate.LogAge bigpipe database variable. By default, this variable is set to 8.

To show the current setting on the Logrotate.LogAge bigpipe database variable, type the following command:

bigpipe db Logrotate.LogAge

To modify this setting, use the following command syntax:

bigpipe db Logrotate.LogAge <number of days>

Legal values range from 0 to 100.

Changing the number of archive copies that the system retains

By default, the BIG-IP system is configured to retain 24 archive copies of each log file.

To show the current setting on the number of archives copies to retain, type the following command:

bigpipe logrotate common backlogs

To modify this setting, use the following command syntax:

bigpipe logrotate common backlogs <number of archive copies to retain>

Legal values range from 1 to 100.

Note: The Logrotate.LogAge bigpipe database variable and the bigpipe logrotate common backlogs setting should be set to a compatible value. Consider the following examples:

Example 1

rotation frequency = daily
Logrotate.LogAge = 8
bigpipe logrotate common backlogs = 24

The BIG-IP system is configured to retain 24 archive copies of each log file; however, the system is also configured to delete archive copies that are older than 8 days. Therefore, if the previous settings are used, the system will only retain log file archives that are not older than 8 days.  Depending on when the archive process begins, and how long it takes to complete, the number of log files that exceed 8 days of age may vary.

Example 2

Rotation frequency = daily
Logrotate.LogAge = 24
bigpipe logrotate common backlogs = 8

The BIG-IP system is configured to delete archive copies that are older than 24 days; however, no archive copy will ever reach 24 days of age. This is because the system is configured to retain only 8 archive copies of each log file. Therefore, if the above settings are used, the system will only retain 8 archive copies of each log file.

Example 3

Rotation frequency = daily
Logrotate.LogAge = 24
bigpipe logrotate common backlogs = 24

If the previous settings are used, the BIG-IP system will retain 24 archive copies of each log file. The logs are rotated daily, the system is configured to retain 24 archive copies, and archive copies are only deleted when they reach 24 days of age.

Example 4

Rotation frequency = weekly
Logrotate.LogAge = 84
bigpipe logrotate common backlogs = 12

If the previous settings are used, the BIG-IP system will retain 12 archive copies of each log file. The logs are rotated weekly, the system is configured to retain 12 archive copies, and archive copies are only deleted when they reach 84 days (12 weeks) of age.
