Description

User notices delays in authenticating to the GTM appliance using the configuration utility. At the same time accessing the LTM appliance configuration utility takes just secs to log in. Both modules have been provisioned on the same Hardware chassis.

Radius servers primary and secondary are reachable and no issues with network connectivity. After around 100 seconds of delay, the user is authenticated successfully.

From the packet captures, It looks the RADIUS authentication request wasn't transmitted immediately. The packet capture was started immediately before clicking the Login button on the BIG-IP Configuration Utility. The packet capture clearly shows 62 seconds go by before the BIG-IP event sends the RADIUS Access-Request packet.

Noticed the below logs from /var/log/secure

Environment

BIG-IP DNS

Radius server

Authentication

Configuration Utility

Vcmp guest

Virprion chasis

Cause

Csyncd processes is very  busy in keeping synchronizing files

Recommended Actions

Workaround1:

# clsh "cp /etc/csyncd.conf /etc/csyncd.conf.$(date +%Y%m%d_%H%M%S)"

# clsh "sed -i '/run\/pamcache/,+2s/^/#/' /etc/csyncd.conf"

# clsh "bigstart restart csyncd"

Workaround2:

Delete the files under  /run/pamcache directory

# find /var/run/pamcache/ -type f -delete
