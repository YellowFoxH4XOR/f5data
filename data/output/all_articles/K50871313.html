Known Issue

The BIG-IP system may fail to load secondary zones after upgrading from 11.4.1 or earlier.

This issue occurs when all of the following conditions are met:

  • Prior to a version upgrade, your BIG-IP system has a secondary zone with an external DNS server.
  • The secondary zone files are in text format.
  • The BIND configuration file (named.conf) does not contain the masterfile-format text; option.

Beginning in BIND 9.9.x, the default format for secondary zones accepted by BIND is raw. In BIG-IP 11.4.1 and earlier, the BIND versions are 9.8.x or earlier. In BIG-IP 11.5.0 and later, the BIND version is 9.9.x. When you upgrade the BIG-IP system, the BIND version is also upgraded.

To review the BIND versions for specific BIG-IP versions, refer to the following articles:

  • K65097545: BIG-IP third-party software matrix (12.x - 13.x)
  • K14457: BIG-IP third-party software matrix (11.x)

Impact

DNS features that rely on secondary zone files, such as DNS Express, fail to process DNS requests for the affected zones.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The named process logs error messages in the /var/log/daemon.log file similar to the following example:

    err named[<PID>]: 04-Jun-2017 08:03:10.054 general: error: dns_master_load: file format mismatch
    err named[<PID>]: 04-Jun-2017 08:03:10.054 general: error: zone askf5.com/IN: loading from master file db.askf5.com failed: not implemented
    err named[<PID>]: 04-Jun-2017 08:03:10.063 general: error: dns_master_load: file format mismatch
    err named[<PID>]: 04-Jun-2017 08:03:10.063 general: error: zone 168.192.in-addr.arpa/IN: loading from master file db.168.192.in-addr.arpa failed: not implemented

  • In the /var/named/config/namedb directory, affected zone files are randomly renamed to db-XXXX files.

Workaround

To prevent this issue from occurring, you can add the masterfile-format text; option to the named.conf configuration file before performing the upgrade. To do so, perform the following procedure:

Impact of procedure: While restarting, BIND may not respond to DNS requests.

  1. Log in to the BIG-IP command line.
  2. To stop the ZoneRunner process on the BIG-IP system, type the following command:

    tmsh stop /sys service zrd

    Note: Stopping the zrd process does not prevent BIG-IP DNS (formerly known as BIG-IP GTM) from processing wide IP requests or BIND from processing DNS requests.

  3. To change to the /var/named/config/ directory, type the following command:

    cd /var/named/config/

  4. To back up the current named.conf file, type the following command:

    cp named.conf named.conf.K50871313

  5. Edit the named.conf file using a text editor such as vi.

    Note: F5 does not support editing the named.conf file directly on BIG-IP Link Controller-only systems. If the Synchronize DNS Zone Files setting is enabled on the BIG-IP Link Controller system, this action may result in DNS zone file synchronization issues.

  6. At the end of the options section, add the following line of text:

    masterfile-format text;

    For example, an updated section may appear similar to the following:

    options {
       listen-on port 53 {
          127.0.0.1;
          "zrd-acl-000-000";
    };
       listen-on-v6 port 53 {
          ::1;
    };
    recursion no;
    directory "/config/namedb";
    allow-transfer {
    localhost;
    };
    masterfile-format text;
    };

  7. Save the changes and exit the text editor.
  8. To restart the named process, type the following command:

    tmsh restart /sys service named

  9. To restart the ZoneRunner process, type the following command:

    tmsh start /sys service zrd
