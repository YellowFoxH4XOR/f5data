K000160514: r2000/4000 device stuck at BIOS 'A0' Post Code after F5OS upgrade or reboot

Support Solution
Published

Applies to

  • F5OS-A: 1.8.3, 1.5.4, 1.8.0, 1.5.0, 1.5.1, 1.5.2, 1.5.3
Source
https://my.f5.com/manage/s/article/K000160514

Description

r2000/4000 series devices become stuck at the BIOS with post code 'A0' following a software upgrade or reboot.

The device fails to boot past the BIOS, displaying the 'A0' code.

Device can later only be recoverable after performing "Reset host subsystem" from the AOM menu or manual power cycle (hard reboot). 

Environment

  •  F5OS-A /Appliance
  • r2000/4000 series with Micron 7450_MTFDKBA480TFR 480GB NVME SSD

Cause

This is due to a known issue as described in following ID 1338645: R2000/R4000 silent reboot

Answer/Recommended Actions

  •  If the device is stuck at BIOS post code 'A0', and only accessible after performing "Reset host subsystem" from the AOM menu or manual power cycle, validate if there are following logs in  /var/log/platform/sel: 

      MCA Error-Reporting Registers Capture. Bank: 6 Core: 0 STATUS Register: 0x0419 Value: 0xb980000000000e0b
      MCA Error-Reporting Registers Capture. Bank: 6 Core: 0 MISC Register: 0x041b Value: 0x0000000000180000

Note: It is also possible sometimes above logs might not be written to /var/log/platform/sel and can only be validated via AOM diagnostic report following K13428255

  •  Run following command from CLI and validate if NVME SSD installed in the system is a 480GB Micron NVME SSD, model 7450_MTFDKBA480TFR .

         #show components

  • If both sel logs or system event logs  and NVME SSD installed on the system matches to ID, follow workaround steps outlined in K000151762: rSeries 2000/4000 systems with NVME SSD may fail to initialize after multiple reboots to avoid recurrence until a permanent fix is released.
