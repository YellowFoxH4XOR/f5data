Known Issue

If the BIG-IP GTM system loads a large configuration, the big3d process might exit.

This issue occurs when all of the following conditions are met:

  • The size of the BIG-IP GTM configuration file /config/bigip_gtm.conf exceeds 10MB.
  • You have previously successfully loaded the BIG-IP GTM configuration.
  • The BIG-IP GTM configuration file was reloaded from a synchronization event, or you manually reloaded it using the Traffic Management Shell (tmsh).

Impact

The BIG-IP GTM system is unable to monitor objects.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H483969 on the Diagnostics > Identified > High screen.
  • The BIG-IP GTM system marks down the monitored server objects.
  • The wide-ip virtual server selects the configured fallback method or fails.
  • In the /var/log/gtm file, you may observe repeated error messages similar to the following example :

    err big3d[7504]: 012b1019:3: An error 'Transport endpoint is not connected' has occurred during finalization of MCPD connection. Retrying...
    alert gtmd[7633]: 011ae0f2:1: Monitor instance /Common/bigip_link 10.10.10.10:0 UP --> DOWN from /Common/Server1 (no reply from big3d: timed out)
    alert gtmd[7633]: 011a2003:1: SNMP_TRAP: Link /Common/10.10.10.10 (ip=10.10.10.10) state change green --> red ( Monitor /Common/bigip_link from /Common/Server1 : no reply from big3d: timed out)
    err big3d[7504]: 012b1019:3: An error 'Transport endpoint is not connected' has occurred during finalization of MCPD connection. Retrying...
    notice big3d[7575]: 012b0014:5: Current executable path is /usr/sbin/big3d. Checking for existence of /shared/bin/big3d.
    notice big3d[7575]: 012b0018:5: Respawning to run /shared/bin/big3d.
    notice big3d[7575]: 012b0000:5: big3d started ===============================

  • The big3d service status indicates that it has restarted multiple times.

    For example, type the following command:

    bigstart status big3d

    You see output similar to the following example:

    big3d run (pid 13508) 24 minutes, 7 restarts

  • The /shared/core directory contains big3d core files.

    For example, type the following command:

    ls -l /shared/core

    You see output similar to the following example:

    -rw-r--r-- 1 root root 2967701 Oct 14 10:00 big3d.bld608.0.core.gz

  • In the /var/log/daemon.log file, the system logs repeated messages similar to the following example:

    emerg logger: Re-starting big3d
