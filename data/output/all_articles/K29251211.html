Description

Unable to open ASM event logs.

Security  ››  Event Logs : Application : Requests

The Configuration utility displays the following message "please wait... loading data"

Environment

  • BIG-IP ASM
  • Configuration utiilty
  • Event logs

Cause

Bug ID 985205

Recommended Actions

You can manually trigger populating missing items in the database to recover from the problem.

1. Suffering from this problem you see all or some of rows have no value in the following output:

# mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "select rest_uuid from PLC.VIOLATIONS"

+-----------+
| rest_uuid |
+-----------+
|           |
|           |
|           |
...snip...

2. Trigger populating those missing values.

# perl -MFile::Slurp -MF5::ASMConfig::Entity::Base -MF5::DbUtils -MF5::Utils::Rest -e 'F5::Utils::Rest::populate_uuids(dbh => F5::DbUtils::get_dbh())'

3. Verify those values are indeed populated.

# mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "select rest_uuid from PLC.VIOLATIONS"
+------------------------+
| rest_uuid              |
+------------------------+
| -GXGw7y7XeOe4EYDgpXA9g |
| -wRSIageblaImzwhL3Pobw |
| 0GtnXx4yBFSqaB7STLh1tA |
...snip...

4. You may need to restart this daemon for the changes to take effect.
 
# pkill -f asm_config_server

5. Wait 30s

Impact of the workaround: This workaround should not have a negative impact on your system

 

Additional Information

This issue can occur after a software upgrade and it could be the result of an incomplete ASM policy restore. There could be more serious problems with ASM policies. The file /var/log/asm should be inspected to make sure there were no problems during the first reboot after the upgrade.
