Known Issue

The BIG-IP ASM system may fail to log Layer 7 (L7) denial-of-service (DoS) events after you individually modify a remote publisher or local publisher.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP ASM virtual server configured with a DoS Protection profile and a Log profile.
  • You modify either a local publisher or a remote publisher.

Impact

The BIG-IP ASM system does not log L7 DoS events.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • If you enable a local publisher and configure a remote publisher as a valid publisher, you observe that log messages stop arriving at the remote logger when you disable the local publisher.
  • If you disable a local publisher and configure a remote publisher as a valid publisher, you observe that log messages stop arriving at the remote logger when you enable the local publisher.
  • If you enable a local publisher and set a remote publisher to none, you observe that log messages stop arriving at the local logger when you set the remote publisher as a valid publisher.
  • If you enable a local publisher and configure a remote publisher as a valid publisher, you observe that log messages stop arriving at the local logger when you set the remote publisher to none.
  • You observe that the system logs incomplete error messages in the /var/log/dosl7/dosl7d.log file that appear similar to the following examples:

    DOSL7D_CONF|NOTICE|<date>|<pid>|dosl7d_conf.cpp:1226|publisher remote <> <0x0>
    DOSL7D_CONF|NOTICE|<date>|<pid>|dosl7d_conf.cpp:1226|publisher local <> <0x0>

Workaround

To work around this issue, modify the remote and local publisher together (for example, disable and then re-enable both). Alternatively, you can restart the DoS L7 daemon after modifying an individual publisher by performing the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Restart the DoS L7 daemon by typing the following command:

    bigstart restart dosl7d
