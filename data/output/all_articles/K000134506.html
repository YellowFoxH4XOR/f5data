K000134506: When the istio-proxy is injected, the "k8s.v1.cni.cncf.io/networks: istio-cni" annotation replaces the pod annotations

Type
Support Solution
Published
2023-05-08
Updated
2023-07-19
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000134506

Description

istio-cni replaces "k8s.v1.cni.cncf.io/networks" annotation values when using multus cni



Environment

Aspen Mesh 1.14.x



Cause

Aspen Mesh 1.11.x appends the values present in the "k8s.v1.cni.cncf.io/networks" annotation when using istio-cni whereas a bug in Aspen Mesh 1.14.x strips them leaving only "k8s.v1.cni.cncf.io/networks: istio-cni".



Recommended Actions

Upgrade to Aspen Mesh 1.14.6-am2



Additional Information

The Istio CNI plugin is a replacement for the istio-init container that performs the same networking functionality but without requiring Istio users to enable elevated Kubernetes RBAC permissions.

Multus CNI is a container network interface (CNI) plugin for Kubernetes that enables attaching multiple network interfaces to pods. Typically, in Kubernetes each pod only has one network interface (apart from a loopback) -- with Multus you can create a multi-homed pod that has multiple interfaces. This is accomplished by Multus acting as a "meta-plugin", a CNI plugin that can call multiple other CNI plugins.
