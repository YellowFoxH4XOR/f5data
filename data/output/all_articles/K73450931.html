Topic

Prior to version 11.2.0, the BIG-IP system has limited support for SNMP traps to report FIPS card failures. In later versions, the BIG-IP system has enhanced SNMP traps to cover reporting of FIPS failures.

Description

The SNMP trap object identifiers (OIDs) described in this article are added to the F5-BIGIP-COMMON-MIB.txt file to cover reporting of FIPS failures.

  • If a FIPS device fails, the BIG-IP system detects and generates the following SNMP trap.

    Object NameOIDVersions
    bigipFipsDeviceError1.3.6.1.4.1.3375.2.4.0.15211.4.0 and later
    11.3.0 HF9 and later
    11.2.1 HF11 and later
  • The BIG-IP 10350v-NEBS series platform introduced the following SNMP trap OID for FIPS card failures. The BIG-IP system detects a FIPS device fault and generates an SNMP trap, indicating that the device is no longer able to perform any FIPS operations.

    Object NameOIDVersions
    bigipFipsFault1.3.6.1.4.1.3375.2.4.0.16612.1.0 and later
    bigipFipsFault1.3.6.1.4.1.3375.2.4.0.15611.6.1
    11.5.4 HF1

Note: In BIG-IP 11.6.1 and 11.5.4 HF1, the bigipFipsFault OID was assigned an OID number of .1.3.6.1.4.1.3375.2.4.0.156. It was later discovered that the previously mentioned OID number conflicted with the bigipGtmDeletedFromGroup OID (introduced in BIG-IP 12.0.0), which also used .1.3.6.1.4.1.3375.2.4.0.156. As a result, starting in BIG-IP 12.1.0, the bigipFipsFault OID was changed to .1.3.6.1.4.1.3375.2.4.0.166.

Recommended Actions

F5 recommends that you configure your network management system (NMS) to use the most recent BIG-IP management information base (MIB) version, appropriate for your BIG-IP version. When you upgrade your BIG-IP version, or if new hardware is deployed, you should verify any FIPS module failures configured with your NMS.
