K000140179: SSLO gives "Cannot deploy topology: Cannot read property 'name' of undefined" error when attempting to deploy a new topology

Description

When attempting to deploy a new topology, SSLO fails the operation giving an error stating "Cannot deploy topology: Cannot read property 'name' of undefined".

When the admin tries to fix this error by clearing the restDB storage/resetting config to defaults with the 'clear-rest-storage' or the 'clear-rest-storage -d' commands, on some deployments the following error is recorded in the /var/log/restjavad.log file, and the clear rest storage operation fails:


[WARNING][205][02 Apr 2024 12:04:03 UTC][8100/shared/iapp/update-named-conf DNSServiceHelperWorker] Error: file /var/named/config/named.conf size unreasonable 109320

 

This prevents the admin from clearing the rest storage, or clearing the rest storage and resetting the box to defaults by using the 'clear-rest-storage' or the 'clear-rest-storage -d' commands at this point.

 

Environment

BIG-IP SSLO


Cause

This secondary error occurs because the current filesize of named.conf (109320 bytes according to the above example log entry) is too large for the Big-IP to accept.

This has the result of not allowing an admin to clear the restDB storage in an attempt to recover the original topology deployment error.

 

Recommended Actions

This secondary error can be fixed by replacing the /var/named/config/named.conf file with either an older version with a smaller size, or just replacing it with a default one from a fresh install of Big-IP and adding any specific required config again.

After this secondary error is fixed, the admin can continue to run the 'clear-rest-storage' or the 'clear-rest-storage -d' commands and clear the restDB config and then recreate the SSLO config as required.
