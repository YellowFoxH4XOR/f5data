Description

  • The output of cat /proc/cpuinfo | grep 'cpu MHz' reports different speed than the  hardware platform capabilities, for example:

[root@BIG-IP-A.lab:Active:Standalone] config # cat /proc/cpuinfo | grep 'cpu MHz'

cpu MHz         : 1200.000
cpu MHz         : 1200.000
cpu MHz         : 1200.000
cpu MHz         : 1200.000

  • The overall cpu usage of the system is high ( above 80% ) especially the data plane cores ( even number cores ).

On the kern logs the idle-enforcer is also being engaged frequently, with logs as below:

var/log/kern.log

BIG-IP-A.lab info kernel: ltm driver: Idle enforcer starting - tid: 11594 cpu: 1/1
BIG-IP-A.lab info kernel: ltm driver: Idle enforcer exiting - tid: 11594 cpu: 1
BIG-IP-A.lab info kernel: ltm driver: Idle enforcer starting - tid: 11595 cpu: 1/1
BIG-IP-A.lab info kernel: ltm driver: Idle enforcer exiting - tid: 11595 cpu: 1

Environment

  • BIG-IP CPU

Cause

One of the causes for this issue is the cpu speed limitation on the license of the respective device.

Recommended Actions

Verify if there is a cpu speed license limit for the device in question by typing the command below:

tmsh show sys license detail | grep 'perf_CPU_frequency'

[root@BIG-IP-A.lab:Active:Standalone] perf_CPU_frequency [1200000]

If you notice a lower value on the perf_CPU_frequency like on the previous example, then please contact with your sales representative in order to verify if this limitation in your license is valid or not.
