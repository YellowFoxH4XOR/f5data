Description

On BIG-IP systems configured with SNMP, you may see below message in /var/log/daemon.log for an abandoned SNMP connection:

warning rmonsnmpd[1234]: AgentX session to master agent attempted to be re-opened.

The rmonsnmpd is a subagent of snmpd that provides remote monitoring, alarm, and event functionality.

Environment

  • SNMP configured

Cause

Using below command, verify whether the PID shown in the message is still active on the system. If not, it suggest to be an abandoned SNMP connection.

tmsh show sys service | egrep -i 'snmpd'

ps tree

In below example, we do not see PID 1234 running on the system; rmonsnmpd and snmpd have different values.

# tmsh show sys service | egrep -i 'snmpd'
rmonsnmpd    run (pid 7292) 8 days
snmpd        run (pid 7286) 8 days

# ps tree
  >> runsv,7277 runsv rmonsnmpd
      >> rmonsnmpd,7292 /usr/sbin/rmonsnmpd -f -c /config/snmp/subagents.conf -s -l /dev/null

Recommended Actions

When possible, you can restart the daemons to resolve the issue:

tmsh restart sys service rmonsnmpd snmpd

Note: Restarting above daemons temporarily interrupts snmp functionality.

Additional Information

You can also filter out the log messages from daemon log file following below steps however it also involves restarting of another service, syslog-ng.

Important: Changes to the syslog configuration should ordinarily be made using tmsh. Incorrect changes to the /etc/syslog-ng/syslog-ng.conf file can prevent syslog-ng from working correctly. Open a service request with F5 Support for assistance if necessary.

  1. Backup current syslog-ng.conf file so it can be used to restore to default in case you make any mistake with editing the file causing syslog-ng failing to start.

    cp /etc/syslog-ng/syslog-ng.conf /etc/syslog-ng/syslog-ng.conf.backup

  2. Using a text editor such as vi or vim, edit filter(f_daemon) section in /etc/syslog-ng/syslog-ng.conf so it looks like below:

    # *daemon.*
    filter f_daemon {
       facility(daemon) and level(notice..emerg);
    };

    destination d_daemon {
       file("/var/log/daemon.log");
    };

    filter f_agentx {
    not match(".*AgentX session to master agent attempted to be re-opened.*");
    };

    log {
       source(s_syslog_pipe);
       filter(f_daemon);
       filter(f_agentx);
       destination(d_daemon);
    };

  3. Save the changes then exit

  4. Restart syslog-ng to update the change

    tmsh restart sys service syslog-ng

  5. Verify if the change is now updated by monitoring the daemon log file. For example:

    logger -p daemon.warning "warning rmonsnmpd[1234]: AgentX session to master agent attempted to be re-opened."

Note: Above changes applied to /etc/syslog-ng/syslog-ng.conf does not sync to the peer system therefore you have to apply the same steps on all affected systems separately. In addition, this modification of default file does not survive upgrade meaning you will need to re-apply all the steps after upgrade, if required.
