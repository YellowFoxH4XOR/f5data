K01463305: Edge Client installation may fail due to an expired Certificate in the APMclients package used by the BIG-IP APM.

Description

Installation on Windows of the OesisInspector.cab component of the Endpoint Inspection libraries is failing. Mac and Linux versions are not affected. If the Windows client already installed this component prior to 6 December, 2021 it will continue to work as long at there is no change to the EPSEC on the APM.

This may present in a number of ways:

  • Client side Logs show that Anti Malware and Firewall checks that are performed by the OPSWAT epsec packages are returning an exception

SINSTALLER, 1, \service.cpp, 1976, VerifyPackage(), (0x654) EXCEPTION - package is NOT signed by trusted certificate

  • An Edge Client installer package created from the APM, will not complete, It gets as far as "Installing OPSWAT Antivirus and Firewall Integration Libraries" then it displays "Rolling Back action:". It ends with the installer reporting "BIG-IP Edge Client Setup Wizard ended prematurely".
  • Automatic updates of epsec fails

Environment

Relevant environmental factors:

  • any supported version of BIG-IP APM with Endpoint Inspection configured on an APM Access Policy
  • all APMclients versions released prior to November 2021 
  • all EPSEC.iso versions released prior to November 2021

Cause

For releases in the last years, F5 has shipped the OesisInspector.cab binary package (as component part of the epsec.iso) with only a partial binary signature. The binary signature is missing a valid timestamp component and as such will fail to be installed as soon as the signing certificate expires (this happened on Dec 6). Prior to this date it installs correctly.
The expected behaviour is that binaries are signed with a valid build timestamp and signature, and that means that even after the signing certificate expires as long as the built in timestamp is before the expiry date that build will continue to be able to be installed forever.

F5 is tracking this as ID977757 (Timestamp invalid), ID1059061 (APMclient, 2021 Signing Certificate) and ID1066361 (Update EPSEC signature)

Recommended Actions

The solution is to upgrade your BIG-IP to an "out of cycle update" (build 5421) of the APMCLIENTS.iso that contains a valid new Signing Certificate, but that is still signed by the current Signing certificate (apmclients 7.2.1.4 Update 1).
At the same time you need to upgrade your BIG-IP to run to a an "out of cycle update" (build 1107) EPSEC.iso that is signed using the certificate in the APMCLIENTS.iso.
As client devices connect to the APM they will automatically be updated to these new versions.

The following .iso updates are now released at downloads.f5.com 

  • apmclients-7214.2021.1126.1205-5421.0.iso  (Under the container APM Clients)
  • epsec-1.0.0-1107.0.iso (under each supported BIG-IP release container
  • Links describing the installation process for both are below, as usual if you have any issues, please open a support ticket.
