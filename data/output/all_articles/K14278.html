Known Issue

An ARX system may core and reload when handling transactions from an NFS source filer.

This issue occurs when all of the following conditions are met:

  • You are using the ARX 500, ARX 1000, ARX 6000, ARX 2000, or ARX 4000 platform.
  • The ARX system is using an NFS namespace.
  • The source filer is using 64 byte file handles.

Impact

The ARX system fails over to the standby unit, interrupting client traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The ARX system restarts two NSM processors simultaneously.
  • Two core files are generated on the ARX system.
  • An error message that appears similar to the following example is logged in the ARX syslog file:

    failover_local_tem_core: Paired NSM cores (0xffd10022, 0xffd10028) both failed. Reboot will be stalled up to three minutes to gather diagnostic information.

Workaround

To work around this issue, you can change the source NFS filer to use 32 byte file handles.

If you want to change the file handle size, F5 recommends that you work with your filer vendor for directions, and to find out the possible impact of the change on your current infrastructure.
