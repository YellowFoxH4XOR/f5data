Known Issue

Network access tunnels configured to use Datagram Transport Layer Security (DTLS) may revert to Transport Layer Security (TLS) if the User Datagram Protocol (UDP) packet order is changed.

This issue occurs when all of the following conditions are met:

  • You use a Mac or Linux client system to establish a network access tunnel to the BIG-IP APM system.
  • The DTLS option is enabled in the network access configuration.
  • During tunnel negotiation, UDP packets arrive in a different order.

Impact

Affected network access tunnels use TLS instead of DTLS.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The tunnel details on the client system show TCP for the protocol rather than UDP.
  • The svpn.log file on the client system includes messages similar to the following example:

    764, 56666,2126506,svpn, 1, /UHTTPChannel.cpp, 414, UHTTPChannel::beginConnection(), EXCEPTION - Could not parse HTTP header.

  • The /var/log/apm file contains log entries similar to the following example:

    01490549:5: /Common/ap_test:1234abcd: Assigned PPP Dynamic IPv4: 100.100.100.10 Tunnel Type: VPN_TUNNELTYPE_TLS NA Resource: /Common/ap_na Client IP: 10.10.10.10 - Reconnect
