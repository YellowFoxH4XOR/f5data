K000138774: Traffic matching policy fails during transaction

Type
Support Solution
Published
2024-02-29
Updated
2024-02-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000138774

Description

tmsh create cli transaction gives warining, when we change in the transaction Virtual server address and attaching traffic-maching-criteria

Command flow is

(tmos)# create /cli transaction

[batch mode]...(tmos)# create /net address-list "<addrss_list_name>" { addresses add { "10.0.0.0/24" {  } } }

Command added to the current transaction

[batch mode]...(tmos)# create /ltm traffic-matching-criteria "<TMC_name>" { destination-address-inline "x.x.x.x" destination-port-inline "<port>" protocol "tcp" source-address-list "<address_list>" source-address-inline "0.0.0.0" }

Command added to the current transaction

[batch mode]...(tmos)# modify /ltm virtual "<virtual_server_name>" { destination "any:any" }

Command added to the current transaction

[batch mode]...(tmos)# modify /ltm virtual "<virtual_server_name>" { traffic-matching-criteria "<TMC_name>" }

Command added to the current transaction

[batch mode]...(tmos)# submit /cli transaction

Traffic Matching Criteria's inline source address has been set to any4 from any6 to match inline destination address' address family.

transaction failed: 01071cc3:3: Cannot specify destination x.x.x.x and virtual server match /Common/<virtual_server_name>

 

Environment

  • BIG-IP
  • TMOS transaction

 

Cause

This is due to conflict of the change in the memory.

  • the virtual server address

AND

  • assigning traffic-matching-criteria.

When the virtual server had not-conflicting virtual server address for the traffic matching criteria already, this should not happen.

Recommended Actions

Once Virtual server's address is changed, submit the transaction, then assign traffic-matchingcriteria.

This way there is no conflict in the memory's configuration.
