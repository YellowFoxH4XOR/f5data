K000163123: L7 Policy Updates Can Cause HTTP/2 RST_STREAM Frames on BIG-IP

Type
Support Solution
Published
2026-08-27
Updated
2026-08-27
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000163123

Description

Modifying or republishing an L7 policy while active HTTP/2 connections are using that policy can cause BIG-IP LTM to send RST_STREAM frames. Clients may receive HTTP/2 stream failures or HTTP 520 responses from a CDN or reverse proxy.

  • TCP connections and TLS handshakes complete successfully.
  • HTTP/2 streams reset before response headers are returned.
  • The underlying TCP connection remains established.
  • HTTP/2 reset counters increase after an L7 policy modification.

Environment

  • BIG-IP LTM is serving as an HTTP/2 server.
  • An HTTP/2 profile is attached to a client-facing virtual server.
  • An L7/LTM policy is attached to that virtual server.
  • Active, long-lived, multiplexed HTTP/2 connections are established.
  • The associated L7 policy is modified or republished while those connections remain active.

Cause

Bug ID 1921049: When L7 policy is updated, existing HTTP/2 connection using it gets a RST_STREAM

Recommended Actions

Immediate mitigation

  1. Remove the HTTP/2 profile from the affected virtual server.
  2. Confirm that clients negotiate HTTP/1.1 to the origin.
  3. Monitor HTTP/2 reset counters and client-side HTTP 520 responses.
  4. Do not re-enable HTTP/2 until the fix has been installed and validated.

Removing the HTTP/2 profile prevents the affected HTTP/2 stream-reset condition but removes HTTP/2 support between the BIG-IP virtual server and its peer.

Recommended fix

Request the Engineering Hotfix that contains the fix for Bug ID 1921049 on the applicable BIG-IP release.

Additional Information

  • A virtual server can remain unaffected if its associated L7 policy is not modified.
  • TCP resets, FINs, packet loss, retransmissions, and TLS failures are not required for this issue.
  • The TCP connection may remain established while individual HTTP/2 streams are reset.
  • Removing the HTTP/2 profile is a mitigation for the trigger, not a correction of the underlying defect.
  • The fix is available through an Engineering Hotfix.
