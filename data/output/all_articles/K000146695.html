K000146695: Why the TLS fingerprint is not working to allow or deny users even using the same device?

What Happened?

You want to create an allow or deny list based on the TLS fingerprint but the same user is creating more than one TLS fingerprint on the same device/session.

Environment

  • Service Policies

Cause

The browsers or some attackers agents are starting to implement randomized TLS fingerprints which will create different TLS fingerprint for every connection, even if it's from the same machine and agent. 

Additional Information

At the moment e.g. Google Chrome is experimenting with TLS fingerprint randomization. Firefox is working on it also.
