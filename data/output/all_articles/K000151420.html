Description

After creating a custom SIP (Session Initiation Protocol) monitor with a custom SIP request, pool members are marked down. Packet capture taken on BIg-IP shows no monitor traffic sent by BIg-IP. 

/var/log/ltm
"error: /Common/udp: No successful responses received before deadline."

Environment

  • BIG-IP LTM
  • SIP monitor
  • UDP mode for SIP monitor is enabled

Cause

When the "SIP Request" field within a SIP monitor configuration on a BIG-IP LTM device is populated with an incomplete or improperly formatted SIP request, the monitor fails to transmit any packets. Request like "sip:10.10.10.10:9060" will fail due to the lack of the version (/2.0) parser. SIP would not be able to interpret headers, it will break the standard. Under these conditions, no outbound monitor traffic was observed from the F5 device under these conditions. Consequently, the associated pool members were marked as down due to the absence of valid monitor responses, indicating a failure in health check communication.

Recommended Actions

To correct the SIP request formatting in the monitor configuration:

  1. Correct the SIP request formatting in the monitor configuration to "<Method> <Request-URI> SIP/2.0 "
    or
  2. Leave the "SIP request" filed empty

Please note that SIP 2.0 is the only official version of the protocol defined in RFC 3261.

Additional Information

When manually customizing the SIP request in a health monitor configuration, ensure that you do not add "\r\n" at the end of the request. The BIG-IP system automatically includes the required carriage return and line feed characters, and adding them manually will result in malformed requests or unexpected behavior.
