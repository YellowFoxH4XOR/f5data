K000092620: F5 VE vNIC is not processing traffic

Type
Support Solution
Published
2022-11-15
Updated
2025-09-17
Source
https://my.f5.com/manage/s/article/K000092620

Description

A virtual interface of a F5 Virtual Edition hosted on a VMware stopped working and intermittently not able to process traffic. You are not able to ping the local self-ip binded to this interface, and also intermittently not able to forward any traffic behind this BIG-IP instance.

 

Environment

  • F5 BIG-IP Virtual Edition hosted on VMware
  • Virtual Interface or vNIC attached is not able to process traffic
  • You may see and increased in CPU and memory
  • Devices are not able to ping/reach the local self-ip of this BIG-IP interface
  • BIG-IP intermittently cannot forward traffic when traversing through this affected interface
  • Disconnecting and reconnecting the VM network adapter would temporarily remediate the issue
  • When you run the command below continuously on BIG-IP command line, you'll see the 'drop_full_iq' column increasing:
# tmctl -d blade tmm/ndal_tx_stats iface=X.Y -w 200 -s iface,device,tmm,blocked,drop_full_iq

Example:

# tmctl -d blade tmm/ndal_tx_stats iface=1.1 -w 200 -s iface,device,tmm,blocked,drop_full_iq
ifacedevicetmmblockeddrop_full_iq
1.1vmxnet3100
1.1vmxnet300141111
 

Cause

It is a bug on VMware hypervisor:

VMs Intermittent connectivity issues after applying a transport node profile to a cluster without detaching a pre-existing TNP first (89352)

 Recommended Actions
