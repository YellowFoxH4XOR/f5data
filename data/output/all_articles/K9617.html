Known Issue

This is the result of a known issue. TMM may crash if it receives a request without a URI or Host Header and RAM Cache is enabled using the CACHE::enable iRule command.

When a request is received without a URI or Host Header, the BIG-IP attempts to force the response information into the cache using a non-existent key, which causes TMM to core. This behavior results in a failover or restart of the system.

F5 Product Development tracked this issue as CR108998, and it was fixed in BIG-IP 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

Workaround

You can work around this issue by preventing the CACHE::enable command from running in the absence of a Host header or URI, or by avoiding use of the CACHE::enable command altogether.

Prevent the CACHE::enable command from running in the absence of a Host header or URI

You can conditionally avoid running the CACHE::enable command if the Host header or URI is missing by using iRule logic similar to the following:

when HTTP_REQUEST {
...
if { !([HTTP::host] eq "") and !([HTTP::path] eq "") }{
CACHE::enable
}
...
}

Avoid use of the CACHE::enable command

Since the CACHE::disable command is unaffected, you can avoid using the CACHE::enable command by enabling RAM Cache in the http profile, then using iRule logic similar to the following to disable caching as required using only the CACHE::disable command:

when HTTP_REQUEST {
...
if { ([HTTP::host] eq "") or ([HTTP::path] eq "") }{
CACHE::disable
}
...
}
