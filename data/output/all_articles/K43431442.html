Description

You can configure a virtual server to select an alternate pool to the one assigned by default within the virtual server configuration, based on the client's IP address. This can be done using an iRule.

  • This is useful when some clients accessing the virtual server need to be sent to a different pool or server than what is associated with the Virtual server. 

Environment

  • BIG-IP
  • Virtual Server that needs to send traffic to 2 different Pool's, based on client IP.
  • Pools
  • iRule

Cause

You want pool selection to be based on the Client IP accessing the virtual server.

Recommended Actions

Creating an iRule to perform pool selection
Create an iRule to perform Pool selection and apply that iRule to the Virtual Server the client will connect to, using the following procedure.
Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In the BIG-IP Configuration utility, go to Local Traffic >> iRules and select Create.
  2. Give the iRule an appropriate name.
  3. For Description, enter the following: 
    
when CLIENT_ACCEPTED {
  if { [IP::addr [IP::client_addr] equals 10.10.10.10] } {
     pool my_pool
 }
}
  4. Edit the 10.10.10.10 IP address in the iRule to reflect the IP you want to send to the alternate pool.
  5. Then edit the my_pool name to reflect the name of the alternate pool.
  6. Then select Finished to save the new iRule.
  7. Go to the virtual server, select the Resources tab.
  8. Select Manage iRules, and add the new iRule.
When the client with the specific IP connects, they will be load balanced to one of the pool members in the alternate pool instead of the default pool assigned to the virtual server. 

Alternately, an iRules data group containing a list of IP addresses can be used along with the class match iRules command to match the client's IP to a list of IP addresses.
Here's an example of such an iRule: 
when CLIENT_ACCEPTED {
  if { [class match [IP::client_addr] equals DG] } {
     pool my_pool_a
  } else {
     pool my_pool_b
 }
}
Note: In the previous example, DG is the name of the Data Group. To create this refer to the Creating a Data Group procedure.

Alternately, the if logic can be repeated to compare the client IP against multiple Data Group lists of IP's, and select between multiple different Pools depending on which Data Group the client's IP is matched to. And if no match is found, the iRule can reject the client's connection.
Here's an example of such an iRule: 
when CLIENT_ACCEPTED {
  if { [class match [IP::client_addr] equals dg_a] } {
     pool my_pool_a
  }
  elseif { [class match [IP::client_addr] equals dg_b] } {
     pool my_pool_b
  }
  else {
     reject
 }
}
Note: In the previous example, the Data Groups are dg_a & dg_b. To create these refer to the Creating a Data Group procedure.

Creating a Data Group
If using one of the iRules from the previous procedure that utilize Data Groups, perform the following procedure to create one:
Impact of procedure: Performing the following procedure should not have a negative impact on your system.
  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > Data Group List.
  3. Select Create.
  4. For Name, enter a name for the data group.
  5. For Type, select Address.
  6. For  Address, enter the IP address you want and select Add. Repeat to add more addresses as needed. You do not need to enter anything in for Value.
  7. Select Finished.
To create an external data group refer to K73862425: Creating external data groups.
