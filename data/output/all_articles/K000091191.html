K000091191: Instance is going offline while pushing the configurations

Type
Support Solution
Published
2022-01-03
Updated
2022-01-05
Source
https://my.f5.com/manage/s/article/K000091191

Description

  • On the Controller, You notice the status of of managed instances is showing offline
  • When inspecting the status of pod/dataplane-manager-*, (kubectl get pod), you note the pod is showing "CrashLoopBackOff" status
  • With the controller dataplane manager pod down, you are unable to perform any kind of management task on managed instances
  • Confirming the host system is provisioned with more than the required minimum resource, you tried to reinstate pod status by deleting pod/dataplane-manager
  • On pod/dataplane-manager recreation, the pod status reverted back "CrashLoopBackOff" status with pod log error

panic: runtime error: invalid memory address or nil pointer dereference

[signal SIGSEGV: segmentation violation code=0x1 addr=0x0 pc=0xd2ee26]

 Environment

  • Nginx Controller

 Cause

  • Known issue IND-26133

 Recommended Actions

  • Upgrade to Nginx Controller version 3.22 ADC

 Additional Information

  • None
