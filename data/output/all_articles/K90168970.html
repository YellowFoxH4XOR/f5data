K90168970: What to do if the ASM attack signature 200012074 is generating false positives or blocking traffic

Type
Support Solution
Published
2022-08-04
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
Source
https://my.f5.com/manage/s/article/K90168970

Description

As a result of this issue, you may encounter one or more of the following symptoms:

  • A false positive violation is reported for Signature ID 200012074 in the ASM Event Logs, which can be found in: Security  ››  Event Logs : Application : Requests
  • Normal Traffic is blocked by ASM due to Signature ID 200012074.  For an end user, an ASM blocking response page will be displayed in their browser with a Support ID when traffic is blocked.

Environment

  • BIG-IP ASM / Advanced WAF
  • Installed Aug 3, 2022 Attack Signature update automatically or manually (ASM-AttackSignatures_20220802_101048.im)
  • Attack Signature with Signature ID 200012074 is enabled in the security policy

Cause

The BIG-IP ASM system may block all traffic or create false positives once Signature ID 200012074 is applied from Aug 3 2022 Attack Signature Update file.  F5 Product Engineering is tracking this as Bug ID 1133685.

Recommended Actions
To resolve this issue, you can install the latest Attack Signature Update or to work around the issue you can remove the offending attack signature from the security policy. To do so, perform one of the following procedures:

Update to the latest Attack Signature Update file
Remove attack signature

Update to the latest Attack Signature Update file
  1. Download the latest ASU file (currently ASM-AttackSignatures_20220804_113147).
  2. Install the ASU file
  3. Enforce the new signature created in order to avoid false positives.  

Remove Attack Signature
Impact of procedure: Performing the following procedure disables functionality for the attack signature. After update to the ASM-AttackSignatures_20220804_113147 or later, please check the check box for Enabled (14.x and previous releases) or not select the Disable(15.x and higher releases) to enable signature ID 200012074.

For 14.x and previous releases
  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Attack Signatures.
  3. In Current edited policy, click the policy to edit.
  4. For versions 11.5.0 through 11.6.x, click the Attack Signatures List tab. This step is not necessary for versions 12.x through 14.x.
  5. Click Show Filter Details.
  6. Type 200012074 in the Signature ID box and then click Go.
  7. Click the name of the filtered attack signature.
  8. Clear the check box for Enabled in the Enable setting.
  9. Click Update.
  10. Click Apply Policy.
For 15.x and higher releases
  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Security Policies > Policies List.
  3. Select the desired policy and navigate through to the Attack Signature tab.
  4. Click on the Filter icon right above the Signature Name field name
  5. Type 200012074 in the Signature ID field and then click Apply.
  6. Select the checkbox for this filtered attack signature.
  7. Select the Disable option on the right top corner to disable this signature
  8. Click Apply Policy to save the changes to your policy.
 

Additional Information

1. Why the latest attack Signature id is placed into non-staging in the new ASM-Attack signature update ?

"Enable Signature Staging"  option will be disabled under Security  ››  Application Security : Policy Building : Learning and Blocking Settings > Attack Signatures under ASM policy. Hence new attack signature update is placed into non-staging immediately.

When cleared (disabled), that the staging feature is not in use, and that the system enforces the signatures’ Learn/Alarm/Block settings immediately. (Blocking is performed only if the security policy’s enforcement mode is Blocking.)

2. How to place the new signature update in staging, whenever there is latest attack signature update.

Enable "Enable Signature Staging" under Security  ››  Application Security : Policy Building : Learning and Blocking Settings > Attack Signatures under ASM policy. Choose either "Retain previous rule enforcement and place updated rule in staging" or "Enforce rule updated rule immediately for non-staged signature". Save and apply the ASM policy
