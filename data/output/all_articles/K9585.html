Topic

Beginning in BIG-IP 11.0.0, Web Acceleration is now configured using a new Web Acceleration profile. For information, refer to K14903: Overview of the Web Acceleration profile.

Note: Bypassing BIG-IP WebAccelerator for specific content using an additional HTTP class profile is more efficient than using an iRule. However, using an iRule may be more flexible. For more information, refer to K10127: Bypassing BIG-IP WebAccelerator with an iRule in version 10.x.

Important: The configuration recommended in this article does not apply to BIG-IP WebAccelerator 10.0.x. For more information, refer to K10928: BIG-IP system may incorrectly send requests to a WebAccelerator-enabled HTTP class.

You can configure a virtual server to use multiple HTTP class profiles, some of which have BIG-IP WebAccelerator disabled, to bypass the BIG-IP WebAccelerator for specific content. HTTP class profiles are processed in the order in which they are applied to the virtual server, and the first matching HTTP class profile applied to the virtual server is used: An HTTP class profile located farther down the list will not be used even if it results in a more specific match. Therefore, if more than one filter may match traffic you want to bypass the BIG-IP WebAccelerator, you must ensure that, in the HTTP class profiles list, the matching BIG-IP WebAccelerator-disabled HTTP class profile is listed before the matching BIG-IP WebAccelerator-enabled HTTP class profile.

For example, to configure a BIG-IP virtual server to use an additional HTTP class to bypass the BIG-IP WebAccelerator selectively for all image files with specific extensions, perform the following procedure:

  1. Log in to the BIG-IP WebAccelerator Configuration utility.
  2. Click WebAccelerator.
  3. Click Class Profile.
  4. Click Create.
  5. In the Name box, type a name for the new HTTP class profile.

    For example:

    bypass_images

  6. To enable editing of the configurable fields, select the Custom check box.
  7. In the WebAccelerator menu, select Disabled.
  8. In the URI Paths menu, select Match only.
  9. In the URI Path box, type the following:

    *\.(gif|jpg|jpeg|bmp)

  10. In the Entry Type menu, select Regular Expression (regex).
  11. Click Add.
  12. Click Finished.
  13. Click Local Traffic.
  14. Click Virtual Servers.
  15. Click the virtual server that you want to configure.
  16. Click the Resources menu tab.
  17. For HTTP class profiles, click the Manage button.
  18. From the Available column, select bypass_images.
  19. To move the bypass_images HTTP class profile to the Enabled column, click the << button.
  20. To move the bypass_images HTTP class profile before all matching BIG-IP WebAccelerator-enabled HTTP class profiles, click the Up button.

    Important: You must ensure that the bypass_images HTTP class profile is listed before all matching BIG-IP WebAccelerator-enabled HTTP class profiles.

  21. Click Finished.

    Requests for files with the listed extensions will now bypass the BIG-IP WebAccelerator system.
