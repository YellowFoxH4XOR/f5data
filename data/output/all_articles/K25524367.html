Description

The following TCL error is seen when checking an IP datagroup:
TCL error: /Common/my-HTTP-irule <HTTP_REQUEST> - invalid IP network mask specification (line X) invalid IP match item 10.2.3.4, 192.168.15.16 for IP class /Common/datagroup_test (line 3) invoked from within "class match [HTTP::header {X-Forwarded-For}] equals datagroup_test"

Environment

  • BIG-IP
  • iRule checking IP address in datagroup
Cause

The error text shows two sample IP addresses, which are being parsed in the X-Forwarded-For header in an iRule such as this:

when HTTP_REQUEST {
if { [ class match [HTTP::header {X-Forwarded-For}] equals datagroup_test ] } {
    ...do something
  }
}

An example datagroup for IP addresses might look something like this:

ltm data-group internal /Common/datagroup_test {
    records {
        10.2.3.0/24 { }
        192.168.15.0/24 { }
        ...etc.
    }
    type ip
  }

The TCL error is seen when trying to parse an exact IP address match from the datagroup. In this case, the X-Forwarded-For header included more than one IP address (which is a valid XFF header), and the TCL engine using type 'ip' only parses one IP at a time.
 

Recommended Actions

It is possible to use contains instead of equals in the datagroup match. This would allow the iRule to match one or more of the IP addresses.

Example:

Change the datagroup to type string:

ltm data-group internal /Common/datagroup_test {
    records {
        10.2.3.0/24 { }
        192.168.15.0/24 { }
        ...etc.
    }
    type string
  }

Change the iRule to use contains instead of equals:

when HTTP_REQUEST {
  if { [ class match [HTTP::header {X-Forwarded-For}] contains datagroup_test ] } {
    ...do something }
  }
This configuration will now match and parse the X-Forwarded-For header correctly.
