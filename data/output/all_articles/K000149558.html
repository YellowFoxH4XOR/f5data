Description

A BIG-IP tenant becomes inoperative or unresponsive, and may fail over if a service monitored in the HA table experiences a failure (show sys ha-status). Attempts to recover the affected BIG-IP by rebooting are unsuccessful. The following error message is observed in the CLI console and logs in /var/log/ltm:

err mcpd[7363]: 01070710:3: Database error (0), Unable to connect to PostgreSQL database.

 

Environment

  • BIG-IP AFM provisioned
  • Database usage (MySQL, PostgreSQL, etc)

Cause

The /var partition of the device is full. This prevents critical services, such as PostgreSQL, from functioning properly.

Recommended Actions

  1. Identify what is consuming space. Run the following command to see large files or directories in /var:
     find /var/ -xdev -type f -exec du -h {} \; | sort -rh | grep -Ev $(mount | awk '/\/var\// {print $3}' | sed -e :a -e N -e 's/\n/|/' -e ta) | head -20
  1. Review and delete unnecessary files from /var. For general recommendations consult K14403: Maintaining disk space on the BIG-IP system.

      3. After clearing sufficient space in /var, reboot the affected tenant and verify if it returns to an operational state.

 

      4. Increase size of /var if AFM blob size increases, see K34126971 or K52061353
