K58417707: VE drops invalid packets in TMM when using virtio driver

Type
Support Solution
Published
2019-09-03
Updated
2025-02-06
Applies to
  • Virtual Editions
  • BIG-IP
  • BIG-IP LTM: 13.1.X, 13.0.X, 13.1.5, 13.1.4, 13.1.3, 13.X.X, 13.1.0, 13.0.1, 13.0.0, 13.1.1
Source
https://my.f5.com/manage/s/article/K58417707

Description

Packets are dropped by TMM.

Environment

  • BIG-IP VE using virtio driver

Cause

The virtio driver causes TMM to drop packets when the packet length is not equal to the Ethernet header plus IP total length as indicated by the IP header Total Length field value. This is by design and intended behavior to prevent invalid packets from entering the system.

In the following example, the value of the Total Length field in the IP header is equal to 566 bytes:

Internet Protocol Version 4, Src: 192.168.1.100, Dst: 192.168.1.150
    0100 .... = Version: 4
    .... 0101 = Header Length: 20 bytes (5)
    Differentiated Services Field: 0x00 (DSCP: CS0, ECN: Not-ECT)
        0000 00.. = Differentiated Services Codepoint: Default (0)
        .... ..00 = Explicit Congestion Notification: Not ECN-Capable Transport (0)
    Total Length: 566 <-----------------

With an Ethernet header of 14 bytes, this packet should be 580 bytes total. However, a capture on the hypervisor before the BIG-IP reveals this packet has a Frame Length several bytes greater than 580 bytes. TMM will drop this packet.

Important: When packets are dropped by TMM in this scenario, a packet capture on the BIG-IP VE will not capture the packets.

Recommended Actions

Perform the following steps to verify if packets are being dropped by TMM due to invalid length:

  • Confirming if the virtio driver is in use
  • Resetting tmm-traffic statistics
  • Reproducing the problem and reviewing statistics
  • Identifying invalid packet length
  • Resolving the issue

Confirming if the virtio driver is in use

Execute the following command to confirm if the virtio driver is in use on the BIG-IP VE:

tmctl -d blade tmm/device_probed

Review the output of the driver_in_use column to confirm if the virtio driver is being used.

Resetting tmm-traffic statistics

Execute the following command to reset the TMM traffic statistics, which show packets dropped in TMM:

reset sys tmm-traffic

Reproducing the problem and reviewing statistics

Reproduce the issue when connecting to the BIG-IP and review the output of the following command to determine if there were packet drops in TMM:

show sys tmm-traffic

Identifying invalid packet length

To identify if packets have an invalid length, it is necessary to capture on the hypervisor layer before the packets reach the BIG-IP VE. It is also useful to capture on the BIG-IP simultaneously, to identify which packets do not reach the BIG-IP.

Once the packets have been captured, use a protocol analyzer such as Wireshark to review the output of the hypervisor capture. Packets which are dropped will have a Frame Length that is greater than IP Total Length plus Ethernet Header.

Note: The relevant display filter field names are frame.len and ip.len.

Additionally, Wireshark may interpret packets with extra bytes as containing a VSS-Monitoring ethernet trailer. These packets can be located by using the vssmonitoring display filter.

Resolving the issue

The source of the extra bytes should be identified by performing an end to end packet capture involving all network devices. In some cases these extra bytes may be caused by an issue with a network driver.

In certain BIG-IP versions, the unic driver may be available. unic does not drop packets with invalid length.

Important: The virtio driver is theoretically higher performance than unic. The best solution to this issue is preventing the extra bytes being added before packets reach the BIG-IP.

Perform the following steps to switch to the unic driver:

  1. Confirm if the unic driver is available by reviewing the output of the following command:

    tmctl -d blade tmm/device_probed

    Review the output of the available_drivers column to determine if unic is available.

    Note: unic is unavailable in BIG-IP version 14.0 and later.

  2. Identify the vendor ID and device ID of the network device by reviewing the output of the following command:

    lspci -nn

    Output will be in the following format:

    [VendorID:DeviceID]

  3. Create the /config/tmm_init.tcl file and add the following line:

    device driver vendor_dev <VendorID>:<DeviceID> unic

  4. Save the file and close.

  5. Restart the TMM process:

    Important: Restarting TMM causes a traffic disruption while TMM is unavailable.

    restart /sys service tmm

  6. After TMM restarts, confirm the unic driver is in use by reviewing the driver_in_use column from the output of the tmctl -d blade tmm/device_probed command.
