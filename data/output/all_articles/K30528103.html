Description

Procedure for restoring the state of an SSL Orchestrator HA pair using UCS archives.

Environment

SSL Orchestrator HA pair running sslo v7.x+ / bigip v15.1.x+ 

Summary

Before the procedure, UCS archives need to have been generated on each box of the HA pair at a time when the ssl orchestrator restdb config is "coherent" between the HA pair, and the mcpd config is also coherent between the pair.

The easiest way to do this is probably to ensure there are no pending mcpd config changes, gossip sync isn't reporting any problems, and then try to generate the UCS archives on each unit at the same time while no one is browsing the SSL Orchestrator admin menu on either box.

Procedure:
1. From bash shell, issue 'clear-rest-storage -d' on both boxes, entering 'y' to reset to defaults. Wait for the box to show "active" again in bash prompt (ie. not status 'iprepd down' or similar).
2. restore from a ucs taken when SSLO config was "coherent and working in the HA pair" on both boxes.
3. do the initial mcpd sync before making any changes or even browsing to the SSLO menu on either box.

The above procedure only works if the user doesn't browse to the SSLO menu or change SSLO config in any way on the box that comes up first, until both boxes are up with the ucs-recovered configs, and then the user does the initial config sync manually as expected (since SSLO doesn't support autosync at present). 

Recommended Actions

None

Additional Information

Note: If a UCS restore becomes necessary, it must be carried out on all units within the HA SSLO pair by following the documented procedures. Failing to do so can lead to backend SSLO restDB synchronization issues between the peers that may not be immediately apparent.
