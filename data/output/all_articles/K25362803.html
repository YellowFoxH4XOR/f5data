Description

You have configured a zone in the ZoneRunner Zone List but the BIG-IP DNS/GTM is resolving another IP address.

For example, you have configured zone www.example.com which will resolve A record 10.10.10.10. When you send a DNS query to the BIG-IP DNS/GTM listener, it will provide another IP address such as 192.168.10.10.

Environment

  • BIG-IP DNS/GTM
  • DNS response IP is not what was configured in the ZoneRunner Zone List

Cause

BIG-IP DNS/GTM uses several configured objects to provide a DNS response. ZoneRunner is the last object to provide a DNS response.

The following are the order of precedence when the BIG-IP GTM/DNS provide a DNS response to the DNS client (top takes the highest precedence)

  1. GSLB (wide-ip)
  2. GTM iRules
  3. DNS Express
  4. DNS Cache (DNS profile) - DNS response has been cached
  5. Resolve Cache (DNS profile) - DNS response has not been cached
  6. DNS Load Balancing
  7. ZoneRunner (BIND)
The following objects refers to a third party nameserver (external from the BIG-IP GTM/DNS).
  • DNS Express
  • DNS Cache (DNS profile) - DNS response has been cached
  • Resolve Cache (DNS profile) - DNS response has not been cached
  • DNS Load Balancing
Recommended Actions

You will need to check for the follow BIG-IP GTM/DNS objects if the mentioned domain (zone) has been configured.

  • GSLB (wide-ip)
  • GTM iRules
  • DNS Express
Refer to article K55502976 on navigating the above objects.

For objects which refers to a third party nameserver, you will need to disable them and test to see if the BIG-IP GTM/DNS provide a response based on the ZoneRunner Zone List. Refer to article K55502976.
