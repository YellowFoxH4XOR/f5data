Topic

Some web servers use the requestor's host header to set the host on emailed password reset requests.  This allows an attacker to generate password reset requests that go to their servers rather than the actual intended system.

This problem can be easily worked around by using a Local Traffic Policy to set an accept list of allowed HTTP hosts, rejecting any hosts that do not match this accept list.  You will want to review K04597703: Overview of the Local Traffic Policies feature (12.1.0 and later)

To do this with an iRule instead refer to K000148533: Blocking HTTP requests with unwanted hosts using an iRule.

You will want to create a local traffic policy rule like this:

conditions: HTTP Header full string named 'host' is not <correct hosts> at request time.
action: Reset traffic connection at request time.

It is important that you select the HTTP Header, not the Host option, as one is part of the URL, while the other is the problematic header.


Additional Information

This solution can also be used to mitigate Qualys scan ID 150307
