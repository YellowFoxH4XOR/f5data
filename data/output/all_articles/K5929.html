Issue

BIG-IP LTM logs the following error messages in the /var/log/ltm file when the tcpdump application is run on a heavily-loaded system:

sccp bcm56xxd[3612]: 00010011:3: Trouble with bcm_ingress_set() Feature not initialized bs_mirror.c(251) sccp bcm56xxd[3612]: 00010012:6: Trouble restoring cpu mirror afterflood control. unit: 0

The tcpdump application mirrors network packets through the CPU using a restricted internal data path between the switch fabric board and the system host board. This restricted internal data path is used for health-check packets, which can be lost if the path is oversubscribed. When the tcpdump application detects an overload condition, it temporarily halts its mirroring to allow the health check packets bandwidth to successfully transmit.

Note: Only the tcpdump session is affected by this behavior.

The tcpdump application is limited in the amount of traffic it can handle. F5 recommends minimizing use of the tcpdump application in a load test or in any other environment where the BIG-IP LTM system is heavily loaded.

Note: For more information about running tcpdump on BIG-IP systems, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP 9.x system.
