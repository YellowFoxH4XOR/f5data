Known Issue

A standby BIG-IP unit may send gratuitous address resolution protocol (ARP) for virtual servers configured with message routing framework (MRF).

This issue occurs when all of the following conditions are met:

  • Your BIG-IP high availability (HA) pair is configured with virtual servers that use MRF.
  • The MRF Session Initiation Protocol (SIP) profile SIP router traffic group is configured (inherited from the folder) with the default traffic group.
  • The MRF SIP profile folder is inherited from parent folder.
  • A configuration change is made to the virtual server configured with the MRF profile on the standby device of the HA pair.

Impact

Traffic destined to the virtual server is sent to the standby HA BIG-IP device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After you modify the virtual server on the standby BIG-IP device, it begins to send gratuitous ARP messages for the modified virtual server.
  • Upstream devices may send request for the virtual server address to the standby BIG-IP device.

Workaround

To work around this issue, using the Traffic Management Shell (tmsh) you can modify the MRF router profile to reference a traffic group other than default one. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh.
  2. Use the following command to view the SIP profile router configuration used by the MRF router profile:

    list /ltm message-routing sip profile router

  3. In the command output, locate the line that for traffic-group and verify that it references the default traffic group.
  4. To modify the SIP profile siprouter setting for traffic group, use the following command syntax

    modify /ltm message-routing sip profile router siprouter traffic-group <traffic-group>

    Note: Replace <traffic-group> with the appropriate traffic group for your deployment.

    For example, to modify the traffic group to use traffic-group-1, type the following command:

    modify /ltm message-routing sip profile router siprouter traffic-group traffic-group-1

  5. To save the configuration, type the following command:

    save /sys config partitions all
