K000130547: TMM/MGMT Routing Problem for monitoring pool members

Description

Why does bigd [monitoring daemon] selecting management port/interface to use as source for probing pool member.

Pool member with node address 10.20.40.41

Default route in route-domain:
/Common/Default default gw 10.244.34.65 static 0

Reviewing Management Route:
sys management-route /Common/example {
app-service none
description none
gateway 10.20.10.1
mtu 0
network 10.20.40.41/32
}

 

Environment

BIG-IP LTM
BIG-IP monitoring
Management route is more specific than TMM one

Cause

This is functioning as designed, we can refer to article K13284:

"Important: When the destination address does not match the management interface subnet, the system uses the default gateway of TMM unless there is a more specific route configured on the management interface. When there is no default route specified in TMM, the system uses the default route specified for the management interface."

K13284: Overview of management interface routing (11.x - 17.x)

Recommended Actions

Use more specific routes designation for networks in TMM
Avoid overlapping subnets on management networks and TMM networks [VLAN/Self-ip]

Additional Information

Manual Chapter : Overview of TMOS Routing
