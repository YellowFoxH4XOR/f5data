Known Issue

Note: This issue only affects the ARX 6000 platform.

This is the result of a known issue. As a result of an inadvertent code change in ARX version 5.1.5, the syslog file on an ARX 6000 platform may be flooded with sync_clock error messages. For example:

: sync_clock: ssb_open() semId:8001 Acquired by Proc:2.2 Pid:994
: sync_clock: ssb_open() semId:8001 Acquired by Proc:4.2 Pid:14796
: sync_clock: ssb_open() semId:8001 Acquired by Proc:3.2 Pid:1251
: sync_clock: ssb_open() semId:8001 Acquired by Proc:3.1 Pid:3864
: sync_clock: ssb_open() semId:8001 Acquired by Proc:2.1 Pid:3994
: sync_clock: ssb_open() semId:8001 Acquired by Proc:4.1 Pid:4046
: sync_clock: ssb_open() semId:8001 Acquired by Proc:2.2 Pid:1058
: sync_clock: ssb_open() semId:8001 Acquired by Proc:4.2 Pid:14928
: sync_clock: ssb_open() semId:8001 Acquired by Proc:3.2 Pid:1315
: sync_clock: ssb_open() semId:8001 Acquired by Proc:3.1 Pid:3973

These messages are benign and may be safely ignored.

F5 Networks tracked this issue as ID 38321 and it was fixed in ARX version 5.1.7. For information about upgrading refer to the ARX Release Notes.

Additionally, this issue has been fixed in ARX version 5.1.5 Build-11980 (Hotfix 6). You may download this version or later versions of the hotfix from the F5 Networks Downloads site.
