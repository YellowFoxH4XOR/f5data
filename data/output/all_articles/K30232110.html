Description

All devices added to device-group have HA peer status check, which is done via restjavad. The restjavad will query for the API (http://localhost:8100/shared/device-availability) once per 20 seconds. This is the iControlREST API checking the device availability.

# restcurl http://localhost:8100/shared/device-availability
{
  "deviceAvailability": {
    "312ad1dc-b162-4261-9c94-63f4958474c4": false,
    "9b5849e3-c452-4b59-8fce-31e2d9c86c7e": true
  },
  "refreshIntervalMillis": 20000,                   
  "pingTimeoutMillis": 15000,
  "isAutomaticRefreshEnabled": true,
  "generation": 1,
  "lastUpdateMicros": 1641544535349862,
  "kind": "shared:device-availability:deviceavailabilityrefreshstate",
  "selfLink": "https://localhost/mgmt/shared/device-availability"
}

However, if this health check fails, you may find the error message below under var/log/secure. The error log means that one of the HA peers tried to check status of the remote server via restAPI, but somehow it could not read status of the remote server.

F5_device     httpd_errors    2022-01-12 06:28:26.000 +08:00    1641940106000    Error    F5_device  httpd[5260]: [proxy_http:error] [pid 5260] (20014)Internal error: [client 192.168.0.1:48450] AH01102: error reading status line from remote server localhost:8100, referer: http://localhost:8100/shared/device-availability

Environment

  • HA
  • Device group
  • restAPI

Cause

There are many possible reasons that may trigger this error log, for example, high CPU, high load, slow performance with API call, network issue between HA peers, httpd process error and so on, or any combination of them. 

Recommended Actions

This error log itself should have no impact on services, and there is no option to disable this health check.

  • If the error does not persist in popping up, you may safely ignore this error.
  • If this error pops up frequently, please contact F5 support for further investigation.
