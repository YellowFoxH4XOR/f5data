Description

When using BIG-IP LTM for Administrative Authentication via RADIUS with Cisco ISE, the remote source IP address of the connecting Administrator's workstation is NOT included in the RADIUS Access-Request sent to the Authentication server. Instead, the BIG-IP system sends its own IP address (either Management or Self-IP) as the NAS-IP-Address. This behavior is by design and cannot be changed through configuration. The actual remote Administrator's client IP address is not supported in the Administrative Authentication flow. 

Environment

  • BIG-IP LTM (TMOS)
  • Administrative Authentication configured via RADIUS to Cisco ISE

Cause

The BIG-IP system, when performing Administrative Authentication via RADIUS, is designed to send its own IP address (as the NAS) in the Access-Request packet. There is no supported feature or configuration to include the remote administrator's client IP address in this authentication flow. 

Answer/Recommended Actions

  • No action required; this is expected behavior by design.
  • If tracking the remote Administrator's client IP is required, consider alternative Authentication or logging mechanisms outside of the standard RADIUS Administrative Authentication flow. 

Additional Information

This behavior applies specifically to BIG-IP's Administrative Authentication. For Application Traffic Authentication, different RADIUS Attributes may be used, and the End-user client IP Address may be included depending on the configuration and use case.
