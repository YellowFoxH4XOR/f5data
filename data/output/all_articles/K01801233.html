Description
It is possible to observe memory leak on persistency when HA mirror connection is down.
To identify the leak, the following symptoms will be observed.

high usage at entry of "persist" at "tmsh show /sys memory "
tmsh show /sys memory 
------------------------------------------------------------------------------------------------
Sys::SubSystem Memory
SubSystem                     Alloc (bytes)  Max Alloc (bytes)  Object Size  Current Allocations
------------------------------------------------------------------------------------------------
persist                                   8565174                  xx          ccc                    x

Note : You will observe Allocated larger than expected value and remained.


To identify the disruption of HA connection, command "tmsh show /net rst-cause" shows high number at "TCP RST from remote system" entry.

tmsh show /net rst-cause
-----------------------------------------------
TCP/IP Reset Cause
RST Cause:                                Count
-----------------------------------------------
TCP RST from remote system               139090

Note : You will observe TCP RST from remote system high number


Environment

  • BIG-IP HA redundant environment.
  • Configured persistency profile
  • Connection mirroring enabled on the persistence profile or the Virtual Server.
  • When mirroring connection is down. 

Cause
TMM memory leak on persistence records while the HA mirror connection is down. F5 Networks tracks this issue as ID747907.
 

Recommended Actions
You can either upgrade the device to fix the issue (or) follow the below workaround. 

Workaround: 
You can consider any one of the below listed workaround to workaround the memory leak issue 

  • Disable persistency
    K84303332: Overview of connection and persistence mirroring

  • Disable session / connection mirroring

  • Disable persistence mirroring.

  • Reset HA mirroring connection, by restarting one of the  BIG-IP HA pair.
    Note: Restarting standby device is recommended.
