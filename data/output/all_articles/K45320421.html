Description

You observe that local ASM event logs are not retained for long, sometimes being rotated out after only a few hours.

Many messages similar to the following may be found in /var/log/ts/asmlogd.log:

F5::RequestLog::delete_unused_protobuf_files,,Dropping protobuf file /var/asmdata1/request_log/0000109146

This can also cause Traffic Learning Reporting to show "No samples found in requests list" under Main >> Security  ››  Application Security : Policy Building : Traffic Learning.

Environment

  • Event logging
  • Security log profile

Cause

This usually happens when hitting the maximum size limit (on a physical system, 5 GB/on a virtual system, 2 GB), or the max entries allowed in the database (3 million rows). The most common cause is that the accumulated local logging from all the logging profiles on the system is too high. When this happens the system purges older logs.
 

Note: In versions prior to BIG-IP 12.1.0, the maximum database size is 2 GB for both virtual and physical systems.

Recommended Actions

Review the logging situation to see if the system is perhaps logging too aggressively. We recommend logging remotely where possible.

Logging all requests in particular may lead to this issue, as opposed to only illegal requests.

Additional Information

clean_db and asmlogd daemons are responsible for maintaining ASM MySQL's databases as well as disk space for request log and they don't require user intervention.
