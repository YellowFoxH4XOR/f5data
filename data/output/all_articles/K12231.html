Known Issue

If a user accesses a resource with a hostname rather than a fully qualified domain name (FQDN), they may experience a significant delay in reaching the site. The BIG-IP APM system makes several queries for the hostname before attempting to append the hostname with different domain suffixes. It can take up to 20 seconds for the BIG-IP system to recognize the attempts to resolve the hostname as failures; the BIG-IP system then performs queries using the FQDN. 

F5 Product Development tracked this issue as ID 337374 and it was fixed in BIG-IP APM 10.2.1. For information about upgrading, refer to the BIG-IP APM release notes.

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP 10.2.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix, refer to K6845: Managing BIG-IP product hotfixes (9.x).

For information about downloading software from F5, refer to K167: Downloading software and firmware from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

To prevent the BIG-IP APM system from querying the hostname, be sure to create resources for favorites like Web tops using the FQDN. For example, instead of using https://intranet/, you would use https://intranet.example.com/ when creating the resource.
