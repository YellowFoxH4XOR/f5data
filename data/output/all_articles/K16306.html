Topic

This article provides information about the Active Directory (AD) and LDAP Group Resource Assign feature that is available for access policies starting with the release of BIG-IP APM 11.4.0.

Description

  • The LDAP and AD Group Resource Assign feature allows the BIG-IP APM system to assign resources based on the user's AD or LDAP group associations. This is achieved through the use of the "session.ldap.last.attr.memberOf" (LDAP) or "session.ad.last.attr.memberOf" (AD) session variable values, against a list of imported group names. To use the AD or LDAP Group Resource Assign functionality, the BIG-IP APM system requires the following configuration items prior to setting up the Group Resource Assign agent:
  • When configuring an AD or LDAP AAA server, which will be referenced by the Group Resource Assign configuration, ensure that the Group section of the AAA server configuration is completed by importing groups from the AAA server. This makes the group names available for inclusion when configuring the access policy Group Resource Assign agent.
  • When configuring the access policy, ensure that a query agent (AD or LDAP) is configured. The query agent must be placed before the Group Resource Assign agent in the access policy flow. When configuring the query, leave the SearchFilter expression empty and remove the default branch rule.

    Note: When the query is set with the Fetch Nested Group setting enabled, administrator-level access privileges are required for the administrator defined in the AAA profile.
    Note: The AAA Server must be set in Group Resource Assign Object in order to acquire the AD/LDAP group associations.

Configuring the group resource assignment

You can use either of the following methods to configure the group resource assignment:

  • Add resources to the Resource Assignment screen without selecting any of the listed groups. The resources are then available to all authenticated user sessions.
  • Select specific groups in alignment with configured resources. The resources are assigned to the authenticated user session, which matches any of the defined groups. When a user is associated with multiple groups, and these groups are defined under the Resource Assignment screen, the user will be assigned resources from each of the matching groups.

All entries that are configured for the Resource Assignment action are evaluated from top to bottom, with each matching resource being assigned to the user's session.

Important: Users with multiple matching groups cannot be assigned multiple webtop resources; only one webtop resource can be assigned to the user.
