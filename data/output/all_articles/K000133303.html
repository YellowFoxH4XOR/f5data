K000133303: Restore configuration data to embedded postgres database

Type
Support Solution
Published
2023-03-31
Updated
2026-08-12
Status
Legacy Content
Applies to
  • NGINX Products
  • NGINX Controller: 3.22.8
Source
https://my.f5.com/manage/s/article/K000133303

Description

The configuration data file (common.dump) found in a supportpkg (can be truncated) or a database backup (full configuration) needs to be restored to an embedded postgres database

Environment

  • NGINX Controller
  • Embedded postgress database
  • Restore Configuration

Cause

Configuration data needs to be restored from backup

Recommended Actions

  1. Copy common.dump file to NGINX Controller
    scp ./common.dump user@controller:/tmp
  2. Stop NGINX Controller, scale up (turn on) an embedded postgres pod and execute a bash shell into it
    /opt/nginx-controller/helper.sh controller stop
    sleep 5
    kubectl scale sts controller-postgres --replicas=1
    sleep 15
    kubectl cp /tmp/common.dump nginx-controller/controller-postgres-0:/tmp/common.dump
    sleep 2
    kubectl exec --stdin --tty controller-postgres-0 -- /bin/bash
  3. Drop and Create the common database using the psql tools
    bash-5.1# psql
    psql (12.5)
    Type "help" for help.

    naas=# DROP DATABASE common;
    DROP DATABASE

    naas=# CREATE DATABASE common;
    CREATE DATABASE naas=# \q
  4. Restore common.db with the pg_restore tool
    bash-5.1# pg_restore -U naas -v -d common /tmp/common.dump
    bash-5.1# exit
  5. Scale down the postgres pod (turn off) and start Controller
    kubectl scale sts controller-postgres --replicas=0
    sleep 2
    /opt/nginx-controller/helper.sh controller start
    watch -n1 kubectl get po
