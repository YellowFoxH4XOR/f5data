K000158880: AFM event logs show packet as dropped for IPs defined in a Data-group and allowed using an iRule with ACL::action allow

Type
Support Solution
Published
2025-12-21
Updated
2025-12-21
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000158880

Description

This article explains a scenario where traffic from specific source IP addresses, which are explicitly defined in a data group and permitted by an iRule using FLOW_INIT and ACL::action allow on a BIG-IP virtual server, appears as dropped in AFM (Advanced Firewall Manager) event logs. Although the iRule is configured to allow these IPs, and it also allows the traffic, AFM logs indicate that packets are blocked at the virtual server context. This can lead to confusion during troubleshooting, as the traffic may actually be permitted but incorrectly logged as dropped.

Environment

  • Product: BIG-IP AFM (Advanced Firewall Manager)
  • Version: 17.5.1
  • Configuration details:
    • Virtual server with an iRule referencing a data group for allowed source IPs
    • iRule using FLOW_INIT and ACL::action allow
    • Global firewall policy and route-domain enforced firewall policy both set to default deny
    • AFM event logging enabled
    • Use of AFM packet tester utility for analysis

Cause

The global and route-domain enforced firewall policies are set to default deny, showing / logging that the packets from a particular source IP as blocked, but the FLOW_INIT and ACL::action allow in the iRule executes at a lower level in the connection forming process before AFM, and it allows the traffic, but there is no way of letting AFM know of this allow override. FLOW_INIT in an iRule and AFM work at different levels. 

Recommended Actions

You can work around this issue in two different ways. 

 

  1. Update global and route-domain enforced firewall policies to explicitly allow all source IPs and control allow/deny using the iRules datagroup entries.

OR

  1. You can create a specific AFM policy for the Virtual Server and use address lists to control allow/deny rules.
    Depending on what option you choose, logging of these events will be done at different levels, as one is being logged by iRules and the other is logged by AFM.

Additional Information

  • Enhancement request RFE ID 2179529 has been submitted requesting support for logging iRule actions within AFM logs.
