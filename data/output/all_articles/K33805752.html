Description

The DNS config sync process only works in one way.

Environment

  • BIGIP DNS.
  • Configured Sync Group.
  • One of the members is configured with more than one Self-IP in the VLAN used for the Sync communication.
  • The device that is not able to send the configuration updates, is using the highest dotted decimal IP address for the sync communication.

Cause

The GTM devices use the lowest number IP address to join the sync group, they make two connections using the lowest dotted decimal IP address to self. Once these two connections have been made the device can now report heartbeat to its peers.

Recommended Actions

You can pick up one of the below options in order to solve this issue, 

  1. Delete the lowest dotted decimal address in the device that has more than one IP address in the same VLAN then restart gtmd/big3d

For example,

  • The device A is not able to send the configuration updates to the device B, but device B can send the configuration updates to the A
  • Device A was configured with two Self-IP addresses in the same subnet like X.X.X.1 and X.X.X.2.
  • The used IP for join the device A to the iQuery mesh was X.X.X.2.
  • To solve the Sync problems you need to remove the IP X.X.X.1.
  • After remove the IP restart gtmd/big3d
# tmsh restart sys service gtmd big3d
  1. Change the object gtm server /Common/device_A IP address by the lowest dotted address
  • First take /Common/device_A out of the sync group.
  • On /Common/device_B  update the server object /Common/device_A IP address to X.X.X.1
  • Run gtm_add from /Common/device_A.
