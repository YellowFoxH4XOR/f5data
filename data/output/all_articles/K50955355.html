Topic

Depending on your F5 hardware platform, the BIG-IP software version installed, and the configuration options defined on the BIG-IP system, SYN cookie protection for wildcard virtual servers may be offloaded entirely to hardware. For all other systems, when SYN cookie protection is activated on a wildcard virtual server, only a single destination address is protected in hardware. All other destinations that are experiencing an attack are protected in software.

Description

Wildcard virtual servers listen for traffic to multiple IP address destinations. The following sections describe the behavior for hardware SYN protection for wildcard virtual servers depending on hardware and software version combination.

BIG-IP 14.1.0 and later on supported F5 hardware

When the BIG-IP system activates SYN cookie protection on a supported hardware and software combination, SYN cookie generation and validation is offloaded to hardware for wildcard virtual servers. VLAN-based hardware SYN cookie protection takes precedence over per-virtual server based SYN cookie protection. Therefore, if you enable SYN cookie protection on the VLAN and wildcard virtual server, the SYN cookie protection behaves as described in the All other BIG-IP hardware and software combinations section. This is also true for systems with Virtual Clustered Multiprocessing (vCMP) enabled. vCMP is not compatible with this feature; if enabled, the BIG-IP system uses the behavior described in the next section. Full hardware offload is supported on the following hardware platforms:

  • BIG-IP iSeries i5x00, i7x00, i10x00, i11x00, i15x00
  • VIPRION B4450 series blade

All other BIG-IP hardware and software combinations

When the BIG-IP system activates SYN cookie protection, SYN cookie protection occurs only for a single destination IP address and port. The system hardware generates SYN cookies for the single destination and then system software generates SYN cookies for all subsequent destination addresses handled by the virtual server.

For example, if you configure a wildcard virtual server with a destination of 0.0.0.0:any and the BIG-IP system initially activates SYN cookie protection for a destination of 10.1.1.1:80, the BIG-IP hardware generates SYN cookies. Meanwhile, if the BIG-IP system determines that virtual server traffic to 10.2.2.2:80 and 10.3.3.3:80 also needs SYN cookie protection, software generates SYN cookies for those destinations.

Note: When you disable and later re-enable SYN cookie protection for a new or resumed attack, the system makes a new decision about what single destination to protect with hardware. Additionally, hardware SYN cookie protection still performs the separate SYN cookie validation function on all IP address destinations.

Software SYN cookie generation for additional destinations through use of a wildcard virtual server as described in the previous example may cause high CPU usage. For more information about SYN cookie protection and the BIG-IP platforms that support the hardware SYN cookie feature, refer to K14779: Overview of BIG-IP SYN cookie protection (11.3.x - 12.x).
