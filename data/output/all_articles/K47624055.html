Description

Observing that some clients are supplying HTTP headers similar to the following in requests:

Sec-CH-UA: "Chromium";v="84", "Google Chrome";v="84"
Sec-CH-UA-Mobile: ?0

Would like to know if something has changed with the BIG-IP system or application in order for these headers to appear.

Environment

  • HTTP traffic

Cause

Deprecation of legacy User-Agent header in modern browsers, replaced by Client Hints.

These headers are unrelated to the BIG-IP system.

Recommended Actions

None

Additional Information

The Sec-CH* headers are used by browsers to provide Client Hints (hence the ch) about the user agent. Historically the User-Agent header has been used for this but is now being deprecated over time for various reasons, mainly improved privacy and security.

The User-Agent header sent by clients volunteers all sorts of information about the user's OS, version, device, and browser version, by default. Similar to the following example:

Mozilla/5.0 (Linux; Android 10; Pixel 3) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/84.0.4076.0 Mobile Safari/537.36

Client hints enable access to the same information in a more privacy-respecting way.

The basic functionality works like this:

  1. A user agent/browser sends a request to a site.

    The client may send some headers by default in the first request, such as Sec-CH-UA and Sec-CH-UA-Mobile, that is because these are considered low-entropy hints that reveal only basic information about the client.

  2. In its response, the server may provide the Accept-CH header, indicating other client hints that it wishes to receive. For example:

    Accept-CH: DPR, Width, Viewport-Width, Downlink

  3. The client is then expected to return the appropriate hints in subsequent requests.

    This allows the server to return resources that will provide the client a better experience, for example, a well-rendered page.

As an alternative to the Accept-CH header, the page may contain an equivalent HTML meta element with the http-equiv attribute, for example:

<meta http-equiv="Accept-CH" content="DPR, Width, Viewport-Width, Downlink">
