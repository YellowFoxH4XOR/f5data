K000139336: Outlook clients suffer from connectivity Issues when Extended Protection for Authentication is enabled on Exchange Servers

Type
Support Solution
Published
2024-04-30
Updated
2024-04-30
Applies to
  • BIG-IP
  • BIG-IP APM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000139336

Description

You may experience connectivity issues with Outlook clients showing as"Disconnected" when connecting externally through F5's Application Policy Manager (APM) after configuring Microsoft Exchange Extended Protection. Internally, all services including OWA (Outlook Web Access), ActiveSync, and Outlook may operate normally. However, external Outlook clients routed through F5 APM fail to establish a proper session.

Environment

  • Microsoft Exchange Server with Extended Protection for Authentication (EPA) enabled.
  • Outlook clients.
  • BIG-IP APM.

Cause

This issue arises due to the incompatibility of the F5 APM with the required Channel Binding Token (CBT) used for Extended Protection for Authentication (EPA), as outlined in the Microsoft documentation on Exchange Extended Protection: https://learn.microsoft.com/en-us/exchange/plan-and-deploy/post-installation-tasks/security-best-practices/exchange-extended-protection?view=exchserver-2019

This has been identified as ID 1567037. The lack of support for CBT in the current implementation of APM prevents Outlook clients from successfully authenticating through Kerberos when EPA is enabled on the Exchange server.

Recommended Actions

To resolve the connectivity issues with Outlook clients, it is recommended to temporarily disable Extended Protection for Authentication (EPA) on the Exchange server until a permanent fix is released. Disabling EPA can be achieved using the following PowerShell script provided by Microsoft:

PS C:\> .\ExchangeExtendedProtectionManagement.ps1 -DisableExtendedProtection

None.
