K000138073: Import ASM to BIG-IQ fails with error 'Invalid value blocked for name request-type'

Type
Support Solution
Published
2023-12-29
Updated
2026-01-07
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.0
Source
https://my.f5.com/manage/s/article/K000138073

Description

  • Cannot import ASM configuration to the BIG-IQ
  • In the /var/log/restjavad.log

[ERROR][15 Dec 2023 11:12:05 CST][/cm/asm/tasks/declare-mgmt-authority/15129e1e-6699-406a-8689-997801ca353b/worker AsmDMATaskWorker] Failed to apply child DMA conflicts; reason: Failed to copy configuration to working-config; reason: Failed copying from source subcollections to target subcollections: %s: java.lang.IllegalArgumentException: Invalid value blocked for name request-type

 

Environment

  • BIG-IQ
  • BIG-IP ASM

Cause

ID1096025

Recommended Actions

  • A Temporary workaround is to change the Request Type option for affected logging profiles (on BIG-IP ASM) from "Blocked requests only" to another value. 
  • On BIG-IQ CM, perform a re-discovery and re-import of LTM and ASM services. If an import conflict exists during the import, specify USE Big-IP for the affected Security Log profile on the conflict resolution page.  This should allow the CM to complete the import of the ASM service. 
  • Once completed, revert the modification by changing the Request Type option on BIG-IP ASM back to Blocked requests only.

Additional Information

None.
