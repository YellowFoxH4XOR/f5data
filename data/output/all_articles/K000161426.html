K000161426: Sensitive Data Remains Masked Despite Disabling Data Guard Masking

Description

Sensitive data (such as credit card numbers) remains masked in Security Event Logs and Learning & Suggestions on BIG-IP Advanced WAF, even when Data Guard masking is explicitly disabled in both the Security Policy and General Settings. This prevents visibility of payload details for evaluating true/false positives.

Environment

  • Product: BIG-IP Advanced WAF
  • Feature: Data Guard (custom patterns configured)
  • Configuration:
    • Data Guard set to Alarm mode
    • "Mask Sensitive Data" option disabled
    • Custom Data Guard patterns in use (maximum pattern length: 16 characters)
    • "Expose first/last characters" setting configured to 50 characters in custom patterns

Cause

If the "Expose first/last characters" value in a Data Guard custom pattern is set higher than the actual pattern length, the entire matched value is masked, regardless of the global masking setting. For example, with a 16-character pattern and an expose value of 50, the system masks the entire value.

Recommended Actions

To resolve unexpected masking when Data Guard masking is disabled:

  1. Go to Security > Application Security > Data Guard in the BIG-IP Advanced WAF GUI.
  2. Select the affected custom pattern.
  3. Check the maximum length of the pattern (e.g., 16 characters).
  4. Set the "Expose first/last characters" value to a number less than or equal to the pattern length.
    Note: For a 16-character pattern, set the expose value to 8 or lower.
  5. Save and apply the policy changes.
  7. Monitor Security Event Logs and Learning & Suggestions to confirm sensitive data is now visible as expected.
