Description

After upgrading NGINX Instance Manager, attempts to Publish configuration them to NGINX managed instances fail with the error:

  • Error Message: "Request deployment was not found: Error code: 131043"

Symptoms:

  • Unable to Publish configuration changes to instances from the UI.

Environment

  • Product: NGINX Instance Manager
  • Version: 2.21.0 (issue observed after upgrade to 2.21.0)
  • Related Components: NGINX, NGINX Agent
  • Operating System: RHEL 9

Cause

The issue is caused by corruption of the NGINX Instance Manager's NATS dpm-queue consumer, which prevents successful deployment and publishing of configuration changes to managed instances. This problem has been observed after upgrades to NGINX Instance Manager 2.21.0.

Answer/Recommended Actions

To resolve the issue, reset the NATS dpm-queue consumer on the NGINX Instance Manager server:

  1. Install NATS CLI (if not already installed):

    curl -fsSL https://binaries.nats.dev/nats-io/natscli/nats@latest | sh

    sudo mv nats /usr/local/bin/

    nats --version

  2. (Optional) Install the watch command if not present:

    sudo dnf install procps-ng

    watch --version

  3. Check the current dpm-queue consumer status:

    nats consumer info DEPLOYMENTS dpm-queue --server "nats://@127.0.0.1:9100"

    nats consumer ls DEPLOYMENTS --server "nats://:127.0.0.1:9100"

  4. Delete the dpm-queue consumer from DEPLOYMENTS:

    nats consumer rm --force DEPLOYMENTS dpm-queue --server "nats://:127.0.0.1:9100"

  5. Verify the consumer has been deleted:

    nats consumer ls DEPLOYMENTS --server "nats://:127.0.0.1:9100"

  6. Restart NGINX Instance Manager services:

    sudo systemctl restart nms

  7. Monitor and ensure the 'dpm-queue' consumer is re-created:

    watch -n1 nats consumer ls DEPLOYMENTS --server "nats://:127.0.0.1:9100"

  8. Attempt to publish a configuration change from the NGINX Instance Manager UI.

If the issue persists, provide the output of the above commands to your support contact for further analysis.

Additional Information

  • The issue is related to the NGINX Instance Manager's internal NATS messaging queue, not App Protect nor NGINX Agent.
  • Reinstalling compilers, agents, or related packages does not resolve the underlying queue corruption.
  • The problem has been observed after upgrades and is not frequent, but the recovery process is consistent.
  • Errors such as missing Perl modules (e.g., YAML::XS) or disk space issues may appear in logs but are not the root cause of this deployment error.
  • If you encounter errors related to disk space (e.g., "no space left on device"), resolve those before proceeding with the above steps.
