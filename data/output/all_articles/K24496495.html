Description

You may encounter a log message similar to following in /var/log/ltm:

Jun  3 11:31:58 bigip1.local warning tmm1[19161]: 01260009:4: Connection error: ssl_hs_session:10831: Inconsistent extended master secret extension: old session included extended master secret extension, but the new one does not. Abort the handshake. (47)
 

Environment

  • SSL profile

Cause

This log message simply means that the client is not sending the extended master secret (EMS) extension consistently in the TLS session. It is not indicative of any issue on the BIG-IP.

Recommended Actions

If necessary, you can choose to investigate why the client is not sending the EMS extension consistently. There can be various reasons why this could happen.

Additional Information

Beginning in BIG-IP 13.0.0, SSL profiles support RFC 7627: Transport Layer Security (TLS) Session Hash and Extended Master Secret Extension. This extension provides additional security to SSL sessions by binding the master secret to a log of the full SSL handshake used to compute it. This behavior prevents attackers from setting up a second SSL session with the same master secrets.

This feature is enabled by default. There are no configuration options for this feature. You can only enable or disable this feature using a database variable.

 # tmsh modify /sys db tmm.ssl.extmsenabled value false
