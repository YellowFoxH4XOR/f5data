Topic

When web aggregation is enabled (by setting it to all, port, or ip), BIG-IP will close the node side of an aggregated connection when the client using that aggregated connection does not transmit data during the web aggregation timeout period.

When enabled, the web aggregation timeout supersedes the TCP service timeout for HTTP connections. As with TCP service timeouts, you should set the web aggregation timeout to a value that allows client connections to complete, but that terminates connections that are not properly closed by the client.

When web aggregation is disabled (by setting it to none), BIG-IP will maintain keep-alive sessions to nodes that use a delayed binding virtual server. For these connections, the web aggregation timeout still applies and supersedes the TCP service timeout for HTTP; therefore, when web aggregation is set to none, you should set the web aggregation timeout to the same value as the TCP service timeout.

You can configure the web aggregate timeout value from the command line or the Configuration utility.

Command line

To change the web aggregate timeout value using the command line, perform the following steps:

  1. Log in to the command line.
  2. Type the following command:

    bigpipe global web aggregate timeout <seconds>

    For example:

    bigpipe global web aggregate timeout 120

  3. Save the configuration, by typing the following command:

    bigpipe save

Configuration utility

To change the web aggregate timeout value using the Configuration utility, perform the following steps:

  1. From the Configuration utility, click System.
  2. Click the Advanced Properties tab.
  3. In the Web Aggregate Timeout box, enter the timeout in seconds.
  4. Click the Apply button.
