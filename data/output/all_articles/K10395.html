Topic

FirePass cluster statistics are reported on the Clustering: Stats page on the primary (master) cluster node. On that page, the Last Sync column reports the time of the last synchronization.

For example:

3 sec ago
 
If the Last Sync column reports Down! for a secondary cluster node, you may observe one or more of the following behaviors:
 
  • The primary cluster node cannot reach the secondary cluster node.

    This behavior may be due to a network issue, or if the cluster node is powered off.
  • There is a software mismatch between the primary and secondary cluster node.

    In a cluster configuration, all cluster nodes must run the same version of FirePass software. Additionally, all cluster nodes must have the same hotfixes installed. If there is a version or hotfix mismatch, synchronization will not occur.

    Note: The software version and installed hotfixes are reported on the Device Management: Current Settings page.
     
  • There is a configuration error on the primary or secondary cluster node.

    For detailed instructions about configuring clusters, refer to the FirePass Controller Administrator Guide. However, a common configuration mistake is incorrectly configuring the Internal Synchronization table on the Management: Configuration: Network Configuration page, under the Clustering tab. You must configure this table on both the primary and secondary cluster nodes, and the table entries must match across all nodes. For example, the IP address and port configured for the Service On Master field must be the same on all cluster nodes. For each Service on Slave field configured on the primary cluster node, there must be an identical IP address and port configured in the Service on Slave field on a secondary cluster node.

    Note: Synchronization ports are configured on the Management: Configuration: Network Configuration page under the Web Services tab.
