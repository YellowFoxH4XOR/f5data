Description

After upgrading to v14.1.0 or later, you may find that External HSM is no longer managing DNSSEC keys as previously configured.  You will see the following log message in /var/log/ltm during the upgrade process:

warning mcpd[6951]: 010712da:4: DNSSEC Key /Common/example.com_ksk may not be stored in FIPS due to platform support.

After upgrade all keys are "use-fips none":

tmsh list ltm dns dnssec key use-fips

ltm dns dnssec key example.com_ksk {
    use-fips none
}
 

Environment

  • BIG-IP DNS
  • Upgrading from pre-v14.1.0 to v14.1.0 or later
  • DNSSEC
  • External HSM (netHSM)

Cause

BugID 758491

If this issue is occurring post v14.1.0, troubleshoot connectivity between BIG-IP and External HSM prior to initiating the upgrade process. Do not uninstall the External HSM client from BIG-IP prior to software upgrade.
Otherwise re-install the HSM client post upgrade and re-establish communication between BIG-IP and External HSM, then restore the UCS taken pre-upgrade. This will restore the original value for "use-fips" for all keys from the ucs archive.

Recommended Actions

There are two options to resolve this issue once you have upgraded to v14.1.0 or later.

  1. Generate new keys from External HSM
    - Example:

    tmsh create ltm dns dnssec key example.com_new_ksk key-type ksk use-fips external

  2. Re-import existing keys from External HSM
    - This example is for nCipher (Thales) HSM where encrypted keys are stored in /opt/nfast/kmdata/local/

    Identify the <key label> using the following command:

    nfkminfo -l

    Keys with module protection:
    key_pkcs11_ua1437fb053c98bf81e97046a52e2aa51b1a2b8979 `_Common_zsk-static-1639D393A48A0D7A9F473B7F8788BC44'
    key_pkcs11_ua405e7319c90c963f161a7314a37c35d75a7375fc `_Common_ksk-static-127E2219D4B539513F8D77553810D4E1'

    tmsh install sys crypto key _Common_zsk-static-1639D393A48A0D7A9F473B7F8788BC44 from-nethsm
    tmsh install sys crypto key _Common_ksk-static-127E2219D4B539513F8D77553810D4E1 from-nethsm

    The above 2 commands import DNSSEC keys as RSA private keys (System  ››  Certificate Management : Traffic Certificate Management : SSL Certificate List) so they may be removed after conversion:

    tmsh delete sys crypto key _Common_ksk-static-127E2219D4B539513F8D77553810D4E1
    tmsh delete sys crypto key _Common_zsk-static-1639D393A48A0D7A9F473B7F8788BC44
