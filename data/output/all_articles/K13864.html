Known Issue

Description

Certain client browsers may not render HTTP responses correctly when Anomaly Detection features are enabled.

This issue occurs when all of the following conditions are met:

  • Any of the following Anomaly Detection features are enabled:
    • DoS Attack Prevention
    • Brute Force Attack Prevention
    • Web Scraping
  • The security policy Enforcement Mode is set to Blocking.

When Anomaly Detection features are enabled, the BIG-IP ASM system generates an HTTP response containing JavaScript that requests a subsequent POST request from the originating client. This response from the BIG-IP ASM system does not contain a Content-Type header. While the omission of the header is compliant with RFC2616, certain browsers may guess the content type incorrectly, resulting in improper handling of the content.

Impact

The client browser may handle web resources incorrectly.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Certain browsers may misinterpret the content type of the HTTP response and render the data incorrectly for the actual content.

    For example, a browser may interpret the content type as .pdf, and attempt to download a file that should be rendered as HTML.

Workaround

To work around this issue, you can insert a Content-Type header using an iRule. To do so, perform the following procedure:

Impact of workaround: iRules may increase processing overhead and require more system resources per connection.

Inserting a Content-Type header with iRules in 11.x

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Enter a name for the iRule in the Name field.
  5. In the Definition field, enter an iRule that appears similar to the following example to set the Content Type to text/html:

    when HTTP_RESPONSE_RELEASE {
    if { not [HTTP::header exists "Content-Type"] } {
    HTTP::header insert "Content-Type" "text/html; charset=utf-8"
    }
    }
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Locate the appropriate virtual server you want to modify.
  9. Under the Resources column for the given virtual server, click Edit.
  10. In the iRules section of the Resources screen, click Manage.
  11. In the Available list, select the iRule you created in Step 4, and move it to the Enabled list by clicking the << button.
  12. Click Finished.

Inserting a Content-Type header with iRules in 10.x

Impact of workaround: The HTTP_RESPONSE_RELEASE event used in the previous workaround does not exist in BIG-IP 10.x. In order to insert the header after the response has been processed by the BIG-IP ASM system, this workaround requires that you create a second virtual server to proxy the client requests and BIG-IP ASM responses. This topology change may require IP address modifications, and should be implemented during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to the LTM > iRules menu.
  3. Click Create.
  4. Enter a name for the iRule in the Name field.
  5. In the Definition field, enter an iRule that appears similar to the following example:

    when HTTP_REQUEST {
    virtual <MyASMVIP>
    }
    when HTTP_RESPONSE {
    if { not [HTTP::header exists "Content-Type"] } {
     HTTP::header insert "Content-Type" "text/html; charset=utf-8"
    }
    }

    Where <MyASMVIP> is the name of the BIG-IP ASM enabled virtual server that you want to modify to include the Content-Type header.
  6. Click Finished.
  7. Navigate to the LTM > Virtual Servers menu.
  8. Click Create.
  9. Enter a Name for the virtual server.
  10. Enter an appropriate Destination IP address and Service Port.

    Important: The IP address and port must be the appropriate values that your client browsers will connect to in order to access the data formerly served by the BIG-IP ASM enabled virtual server.
  11. Select an appropriate HTTP profile from the HTTP Profile menu.
  12. In the Resources > iRules menu, select the iRule you created in Step 4 from the Available list.
  13. Move the iRule to the Enabled list by clicking the << button.
  14. Click Finished.
