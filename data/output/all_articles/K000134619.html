K000134619: Collecting troubleshooting data for tenant management interface inaccessible issue on rSeries platform

Type

Published
2023-05-16
Updated
2025-05-22
Source

Description

This article outlines the steps to collect relevant diagnostic data for resolving issues where the tenant management interface on an rSeries appliance is inaccessible. Collect the following data when the issue occurs.

Environment

  • rSeries appliance
  • Tenant management interface inaccessible

Cause

Not applicable.

Recommended Action

When experiencing inaccessibility of the tenant management interface, perform the following procedures to gather critical diagnostic data:

a) Collect qkview from the rSeries Host:

Refer to the following article for detailed instructions: K04756153 .

b) Check Tenant Status on rSeries Host:

  • Log in to the CLI of the rSeries host using an admin role.
  • Run the following command and save its output:
     
    # show tenants
     
    Identify the problematic tenant from the output and review its status. Below is an example of the output for guidance:
     

    tenants tenant tenant01
    state unit-key-hash ********
    state type BIG-IP
    state image BIGIP-15.1.8.2-0.0.17.ALL-F5OS.qcow2.zip.bundle
    state mgmt-ip 192.168.1.245
    state prefix-length 24
    state gateway 192.168.1.254
    state vlans [ 64 128 192 ]
    state cryptos enabled
    state vcpu-cores-per-node 4
    state memory 12288
    state storage size 80
    state running-state deployed
    state trust-mode true
    state appliance-mode disabled
    state status Running
    state primary-slot 1
    state image-version "BIG-IP 15.1.8.2 0.0.17"
    state mac-data base-mac 00:00:5E:00:53:10
    state mac-data mac-pool-size 8


     

c) Validate Tenant Console Access:

  • If the state status indicates "Running" but management interface connectivity issues persist, attempt to access the tenant's console.

  • Use the following steps from the rSeries host logged in with root role:
     
    # kubectl get vms
    # virtctl console <VM_NAME>

    Example: 

    # kubectl get vms
    NAME AGE VOLUME
    cbip1-1 67m
    # virtctl console cbip1-1
    Successfully connected to cbip1-1 console. The escape sequence is ^]
    root@(localhost)(cfg-sync Standalone)(Active)(/Common)(tmos)#

d) Verify Tenant Status within Console:

  • Confirm the tenant is in an Active state using the prompt provided.

e) Test Host Network Reachability from Tenant:

  • While in the tenant console, check the reachability of the rSeries host by pinging the host-side IP.
  • The IP can be located in the tenant's /etc/hosts file. 

    Example:
     
    # grep "f5platform.host" /etc/hosts
    10.245.3.2 f5platform.host

    # ping 10.245.3.2
     

f) Additional Diagnostic Commands on rSeries Host:

Run the following commands under the root role on the rSeries host and save their outputs:

# kubectl get pods --all-namespaces
# kubectl get cm -o json

Additional Information

  • It is recommended to maintain the issue's state for better troubleshooting. A remote session may be required to investigate the problem further during the issue window.
  • Avoid deleting the tenant. Instead, consider changing its status (e.g., from deployed to provisioned) to preserve tenant data, as the issue may originate within the tenant itself.
