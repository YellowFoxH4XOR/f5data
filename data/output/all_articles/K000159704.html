Description

When attempting to log in to a BIG-IP system via SSH using the root account, authentication fails even after resetting the root password. The following error messages may appear in the system logs:

pam_tacplus: auth failed: Login incorrect

pam_tacplus: user root not authenticated

password check failed for user (root)

pam_unix(sshd:auth): authentication failure

error: PAM: Authentication failure for root

This issue occurs when the systemauth.nolocalonly database variable is set to true, which forces the root and admin accounts to use remote authentication (such as TACACS+ or RADIUS) instead of local authentication.

Environment

  • BIG-IP LTM version 13.0.0 and later (including 17.1.3)
  • Remote authentication configured (TACACS+ or RADIUS)
  • Database variable systemauth.nolocalonly set to true
  • Attempting SSH access with root credentials

Cause

The systemauth.nolocalonly database variable is set to true, which forces the root and admin accounts to authenticate via remote authentication methods (TACACS+/RADIUS) instead of using local authentication. If remote authentication fails or is not configured for the root account, SSH access is denied.

Recommended Actions

  1. Access the BIG-IP system via an alternative method (console access or an existing authenticated session).
  2. Check the current value of the systemauth.nolocalonly database variable:
    tmsh list sys db systemauth.nolocalonly
  3. Modify the systemauth.nolocalonly database variable to false to enable local authentication for root and admin accounts:
    tmsh modify sys db systemauth.nolocalonly value false
  4. Save the configuration to persist changes across reboots:
    tmsh save sys config
  5. Verify SSH access with root credentials.

Note: When systemauth.nolocalonly is set to false (default), the root and admin accounts use local authentication at all times, bypassing remote authentication methods.

Additional Information

  • The systemauth.nolocalonly database variable was introduced in BIG-IP 12.1.0 (for RADIUS only) and BIG-IP 13.0.0 (for all remote authentication methods).
  • This variable supports the following options:
    • true: Root and admin accounts use remote authentication.
    • false (default): Root and admin accounts use local authentication at all times.
  • Remote authenticated users cannot access Advanced Shell (bash) directly, which is required for SCP/SFTP operations. To transfer files via SCP/SFTP, use the local root account after setting systemauth.nolocalonly to false.
