K000148019: How to resolve upstream_reset_before_response_started {OPENSSL_internal:CERTIFICATE_VERIFY_FAILED}

Published
2024-11-08
Updated
2025-09-08
Applies to

  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000148019

Description

  • I am getting a 503 with rsp_code_details as upstream_reset_before_response_started{connection_failure,TLS_error:_268435581:SSL_routines:OPENSSL_internal:CERTIFICATE_VERIFY_FAILED}

Environment

  • F5® Distributed Cloud HTTP Load Balancer

Resolution/Answer

  • This error is received when the TLS certificate presented by the origin server is either invalid or has expired.
  • To check the origin server TLS certificate details , use the following command,
openssl s_client -connect <backend IP>:443 -servername <domain> | openssl x509 -noout -text
  • Check for validity of the certificate and also the common name field from the above output.
  • To resolve this issue , keep the Origin Server Verification to Skip Verification or Use Custom Root CA Certificate if origin server TLS certificate is correct.

 

Cause

  • The origin server sent a TLS certificate for validation and that validation failed.
  • It could be due to certificate expiration, mismatch in common name (CN) field.

Additional Information

  • To get the services back immediately while work on the origin server side certificate is being done, keep the Origin Server Verification to Skip Verification.
  • Please make sure to fix the origin server TLS certificate issue and then change the Origin Server Verification setting to Use Default Root CA Certificate or Use Default Custom CA Certificate.
