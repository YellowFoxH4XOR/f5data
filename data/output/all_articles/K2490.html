Issue

BIG-IP allows one instance of a monitor for a specified node (IP address and port combination). For example, you cannot create two monitors for a specific node with different frequency and timeout values. BIG-IP will only accept the first monitor that you define.

BIG-IP evaluates monitors after it expands any wildcard addresses or ports; Therefore, you may receive the following error if you have defined both a monitor with a wildcard address and an additional monitor with a specific IP address for the same port.

Error in monitor list lookup for node rule: Monitor instance already exists see /var/log/bigip

For example, if you use the following monitor with a pool that contains the nodes 10.90.100.51:80 and 10.90.100.52.80:

monitor Wildcard_HTTP {
# type http
use "http"
interval 6
timeout 18
dest *:80
send "GET /"
recv "Data"
username ""
password ""
}

BIG-IP will consider this monitor definition the same as the following two monitor definitions:

monitor 10.90.100.51_HTTP {
# type http
use "http"
interval 6
timeout 18
dest 10.90.100.51:80
send "GET /"
recv "Data"
username ""
password ""
}


monitor 10.90.100.52_HTTP {
# type http
use "http"
interval 6
timeout 18
dest 10.90.100.52:80
send "GET /"
recv "Data"
username ""
password ""
}

If you then attempt to add a new monitor specifically for 10.90.100.52:80, it will fail, because a monitor for this node already exists, even though it is not distinctively defined.
