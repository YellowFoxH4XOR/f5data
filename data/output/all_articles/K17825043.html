Topic

Note: To find out about the information F5 requires when opening a support case for other F5 products, refer to K2633: Instructions for submitting a support case to F5.

F5 Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration. To help you gather all the required information, use the following guidelines to prepare for opening a case:

General Information

Provide the following information when you open a case with F5 Support:

  • A full description of the issue, including the following details:
    • The symptoms of the issue, including a brief description of any systems applicable to the configuration.
    • The names of the involved systems, hosts, components, and configuration objects.
    • The version of the Linux host system where the instance is running.
    • The approximate time the issue first occurred.
    • The number of times the issue has recurred.
    • Any error output provided by the system.
    • Steps to reproduce the issue.
    • Any changes you made to the system before the issue first occurred.
    • Any steps you took to attempt to resolve the issue.
    • Whether this is a new implementation.
    • Whether you have already provided support items listed in Product specific information.
  • A description of the impact that the issue is having on your site, using the following definitions:
    • Site Down

      Software or hardware conditions on your F5 instance are preventing the execution of high level commerce or critical business activities, including remote access to critical applications. The instance will not power up or is not passing traffic to the detriment of business-critical applications.

       

        Security issue
      - Critical business impact due to an attack or vulnerability.
    • Site at Risk

      Software or hardware on your F5 instance is significantly impairing business activities, including remote access to critical applications. The instance status is putting your network or commerce at risk.

       

        Security issue
      - Severe business impact due to an attack, vulnerability, compliance, or data at risk.
      • Performance Degraded

        Software or hardware on your F5 instance is degraded and this could further impact your traffic or business-critical applications.

         

          Security issue
        - Potential or partial business impact related to mitigation, audit results or vulnerability.
        • General Assistance Required

          General questions and troubleshooting of non-critical F5 software or hardware instances. Requests for product functionality or solutions which are not currently part of the solution.

           

            Security issue
          - General security related questions and/or concerns which are not related to an immediate need.

          Note: For more information about case severity definitions and response times, refer to F5 Technical Support Services Guidelines and Policies.

          • The hours that you are available to work on the issue and any alternative contacts that can work on the issue if you are not available.
          • Remote access information, if possible.

            Remote access to your network environment is important because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Support will work directly with you to resolve the issue over the phone; however, this method can often be more time consuming and may require file transfers, replication, and additional testing.

          Product specific information

          Collect the following information from the affected systems and provide the information when you open the case. For information about sending this information to F5, refer to K000090853: Exchange files with F5 Support using MyF5.

          • NGINX configuration output
          • Log files
          • Core files
          • NGINX ModSecurity WAF files
          • NGINX App Protect WAF support files
          • NGINX App Protect DoS support files
          • NGINX Service Mesh support file

          NGINX configuration output

          The NGINX configuration output is an essential piece of information and is frequently needed to provide F5 Support the context of the ongoing issue. You can obtain the configuration output file by performing the following procedure:

          1. Log in to the NGINX Plus command line.
          2. To dump the NGINX configuration to an output file in the /var/tmp directory, enter the following command:

            sudo nginx -T > /var/tmp/configoutput_$(date +"%Y%m%d%H%M")

          Log files

          If you are unsure if the error logs are related to the issue, or if the issue persists for more than a day, provide all the NGINX log files on the system. To do so, perform the following procedure:

          1. Log in to the NGINX Plus command line.
          2. To create a TAR archive named logfiles.tar.gz in the /var/tmp directory that contains all the files in the /var/log/nginx directory, enter the following command:

            tar -czvf /var/tmp/logfiles.tar.gz /var/log/nginx/*

          Core files

          A core dump file helps identify and fix problems that cause NGINX systems to stop responding. For information about obtaining a core file, refer to Enabling Core Dumps.

          NGINX ModSecurity WAF support files

          If the issue is related to NGINX WAF, you should provide the following WAF-related configuration and log files:

          • /var/log/modsec_audit.log
          • /etc/nginx/modsec/modsecurity.conf

          NGINX App Protect WAF support files

          If the issue is related to NGINX App Protect, you should provide the following NGINX App Protect related configuration and log files:

          • File containing your NGINX Plus and NGINX App Protect versions
            • CentOS and RedHat based systems:

              To create a /var/tmp/rpm_versions.txt file that contains NGINX Plus and NGINX App Protect WAF version information, use the following command:

              rpm -qa nginx-plus* app-protect* > /var/tmp/rpm_versions.txt

            • Debian and Ubuntu based systems:

              To create a /var/tmp/deb_versions.txt file that contains NGINX Plus and NGINX App Protect WAF version information, use the following command:

              dpkg -s nginx-plus app-protect > /var/tmp/deb_versions.txt

          • File containing your OS information

            To create a /var/tmp/system_version.txt file that contains your OS information, use the following command:

            VER="/var/tmp/system_version.txt"; cat /etc/os-release >> $VER && uname -r >> $VER && cat /proc/version >> $VER

          • All NGINX Plus log files specified in the Log files section.
          • All NGINX Plus configuration and NGINX App Protect policy files such as the files in the /etc/nginx directory.

            Note: You can find the policy files defined in the nginx.conf file. For more information, refer to the Configuration files section in K10144744: Overview of NGINX App Protect WAF administration.

            To create a /var/tmp/nginxconfig.tar.gz TAR archive, use the following command:

            tar -czvf /var/tmp/nginxconfig.tar.gz /etc/nginx

          • TAR archive containing all NGINX App Protect log files

            To create a /var/tmp/naplogfiles.tar.gz TAR archive that contains all NGINX App Protect log files, use the following command:

            tar -czvf /var/tmp/naplogfiles.tar.gz /var/log/app_protect/*

          NGINX App Protect DoS support files

          If the issue is related to NGINX App Protect DoS (Denial of Service), you should provide the following related configuration and log files:

          • All NGINX Plus log files specified in the Log files section.
          • All NGINX Plus configuration files such as the files in the /etc/nginx directory
          • All NGINX App Protect DoS policy files defined in the NGINX configuration file nginx.conf.
          • TAR archive containing NGINX and NGINX App Protect DoS log files

            To create a /var/tmp/napdoslogfiles.tar.gz TAR archive, use the following command:

            tar -czvf /var/tmp/napdoslogfiles.tar.gz /var/log/adm /var/run/adm /var/log/nginx

          • The output of admd -c in napd_shmem.log. Use the admd -c > napd_shmem.log command.

          NGINX Service Mesh support file

          If the issue is related to NGINX Service Mesh, you should generate a support package on the affected deployment by entering the following command:

          nginx-meshctl supportpkg

          This command generates a nsm-supportpkg-<YYYYMMDDHHMMSS>.tar.gz file that contains information about the current state of the NGINX Service Mesh deployment including logs, component YAML files, events, Pod descriptions, and so on. The README.md file in the support package describes the information collected.
