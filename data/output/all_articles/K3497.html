K3497: Reasons why the 3dns_add script may synchronize the wrong named.conf file

Topic

3-DNS Controllers in a sync group will synchronize to the named.conf file that has the most recent file system time stamp.

If you have performed any of the following procedures on the new 3-DNS Controller before you add it to the sync group, it can cause the new 3-DNS Controller's named.conf file to propagate to the sync group, rather than have the sync group propagate to the new 3-DNS Controller:

  • Set the 3-DNS Controller to a future date before or during configuration
  • Enabled NameSurfer from the Configuration utility, which causes the named.conf time stamp to be updated
  • Manually opened or edited the named.conf file.

This occurs because these procedures affect the date stamp of the named.conf file.

To work around this issue, you must first remove the named.conf file from the new 3-DNS Controller before you add it to the sync group. To do this, perform the following steps:

Important: If you are running 3-DNS Controller 4.5.x with BIND 9, contact F5 Technical Support for assistance.

  1. Rename the original named.conf file using one of the following version-specific commands.
    • For 3-DNS 4.6.2 through 4.6.4, type the following command:

      mv /var/named/etc/named.conf /var/named/etc/named.conf.3DNS_ADD_BACKUP

    • For 3-DNS 4.5 through 4.6.1, type the following command:

      mv /etc/named.conf /etc/named.conf.3DNS_ADD_BACKUP

  2. Run the 3dns_add script, by typing the following command:

    3dns_add
