Known Issue

The bigpipe or tmsh session monitor command argument allows users to override the actual health status of the pool member.

This issue occurs when the following conditions are met:

  • The health monitor is configured with the Receive Disable String setting
  • You use either the bigpipe session mon command or the tmsh session monitor command argument to disable or enable the pool member status.

    For example:

    • bigpipe

      bigpipe pool <pool-name> members <ip-address>:<port-number> session mon <disabled|enabled>
    • tmsh

      tmsh modify ltm pool <pool-name> members modify { <ip-address>:<port-number> { session monitor-<disabled|enabled> } }

The pool member session monitor status is controlled by the BIG-IP system using the Receive Disable String setting in the health monitor configuration menu for HTTP monitor type. The session monitor disable or enable command argument is not intended to be a configurable item and is removed in BIG-IP version 11.x.

Impact

The system may not reflect the actual pool member health status.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system may not reflect the actual pool member health status

    For example, the following command changes the session monitor to disabled for the pool member in the example_pool pool, even though the pool status is configured to use the Receive Disable String setting:

    tmsh modify ltm pool example_pool members modify { 10.10.10.1:80 { session monitor-disabled } }

    This example command sets the status for pool member 10.10.10.1 to session monitor-disabled, even though the actual monitor requests may be succeeding. As a result, this behavior may override the Receive Disable String setting.

Workaround

To work around this issue, you can reload the configuration to restore the correct state of the pool member that reports from the designated health monitor. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system will require a configuration reload, which may result in a brief interruption in traffic processing.

To reload the configuration for the system, you can use either the bigpipe or tmsh command:

  • bigpipe

    bigpipe load
  • tmsh

    tmsh load sys config
