Description

When HTSplit is enabled on Intel CPUs with Hyper-Threading Technology, TMM processes are assigned to even-numbered logical CPUs, while non-TMM control-plane and analytics-plane processes are assigned to odd-numbered logical CPUs, as documented in K23505424 and K15003.

Additionally, as described in K16469, MySQL is pinned to the highest-numbered logical CPU.

CPU utilization on the logical CPU where MySQL is pinned may periodically spike due to AVR scheduled aggregation, such as hourly aggregation at the beginning of each hour, as documented in K15003 and K73111225.

As a result, it may be observed that the last odd-numbered CPU, CPU N, where N is the highest-numbered logical CPU and where MySQL is pinned, reaches very high utilization while aggregation is being performed for a short period of time, for example, during the first few minutes of an hour. Meanwhile, the neighboring even-numbered CPU, CPU N-1, which runs a TMM instance under HTSplit, may report lower CPU utilization than other even-numbered CPUs running TMM instances.

It can be observed that when the highest-numbered logical CPU, CPU 25, where MySQL is pinned, reached 100% utilization due to hourly AVR aggregation, the other even-numbered logical CPUs showed usage between 20% and 30%. However, the even-numbered logical CPU neighboring the highest-numbered logical CPU, CPU 24, which is adjacent to CPU 25, showed only 8% usage. This was significantly lower than the other even-numbered logical CPUs.

Environment

  • AVR module is provisioned, or the ASM or AFM module is provisioned, which implicitly enables AVR.

  • HTSplit is enabled on BIG-IP hardware platforms with Intel CPUs that support Hyper-Threading Technology.

Cause

The two neighboring CPUs where TMM and MySQL run, respectively, are on the same SMT/Hyper-Threading physical CPU core. They are two hardware threads on the same physical core and share the same execution resources.

The lower CPU busy percentage, or higher idle percentage, is due to how idle time is calculated by the Linux operating system. Linux measures each logical CPU’s usage by sampling, at each timer tick, whether that CPU was running a task or sitting in the idle loop. The busy percentage is simply the fraction of ticks that were not idle.

This works well when each logical CPU is an independent physical core. However, CPU N-1 and CPU N are two hyperthreads on the same physical core. They share the same execution hardware, so they are not truly independent.

When the database job, 'mysqld', saturates CPU N, it consumes a large portion of the shared core’s execution resources. As a result, the tick-based counter on CPU N-1 may no longer accurately reflect how much real work its TMM is doing. This can make the CPU busy percentage appear lower, even though the actual TMM workload is unchanged.

Answer/Recommended Actions

This is generally expected behavior related to how CPU SMT/Hyper-Threading works. When one physical CPU core appears as two logical CPUs in the operating system, the logical CPUs are not fully independent. They share the physical core’s execution resources, so contention can occur when one logical CPU reaches 100% utilization

If the user wants to confirm whether the TMM instance running on the CPU that shows lower CPU usage is still handling traffic correctly, review the tmstat/tmm_stat output. Check whether the incoming traffic for that TMM instance is comparable to the other TMM instances. Specifically, compare inbound bytes, packets, and current connection counters during the time when the CPU usage anomaly occurs.

There should not be a significant imbalance in connection counts or throughput across TMM instances. If an imbalance is observed, contact F5 Support for further analysis.

tmctl tmm_stat

Additional Information

If this becomes a major concern, review K73111225 for options to disable AVR aggregation.

Another option is to use BIG-IQ to offload AVR statistics collection, aggregation, and storage. This can eliminate MySQL aggregation activity on the BIG-IP and help minimize contention between control-plane workloads and TMM packet processing.
