Topic

A common topology is to have a BIG-IP LTM system load balance a group of BIG-IP WebAccelerator systems. If the BIG-IP LTM system monitors the BIG-IP WebAccelerator with a standard HTTP monitor, a BIG-IP WebAccelerator running BIG-IP version 9.x will respond with an HTTP 400 Bad Request response and a BIG-IP WebAccelerator running BIG-IP version 10.0.x will respond with an HTTP 403 Forbidden response because the BIG-IP LTM standard HTTP monitor does not include a Host header. Additionally, beginning in BIG-IP WebAccelerator 10.1.0, all requests that do not include a Host header (regardless of the HTTP version) bypass the BIG-IP WebAccelerator. If the OWS requires a Host header, the OWS will typically respond with an HTTP 400 Bad Request response.

As a result, BIG-IP WebAccelerator performance reports may indicate a large number of HTTP 400 Bad Request or 403 Forbidden403 responses.

Note: For more information about how BIG-IP WebAccelerator processes requests that do not include a Host header, refer to K11336: Client requests that do not include a Host header bypass the BIG-IP WebAccelerator.

To ensure that the BIG-IP WebAccelerator can process the request, configure the BIG-IP LTM HTTP monitor to send a properly formatted HTTP 1.1 request which includes a Host header.

Note: For information about configuring a properly formatted HTTP monitor on the BIG-IP LTM, refer to K2167:Constructing HTTP requests for use with the HTTP or HTTPS application health monitor.
