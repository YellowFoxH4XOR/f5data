Type
Support Solution
Published
2021-04-27
Updated
2023-02-21
Applies to
  • BIG-IQ
  • BIG-IP
  • BIG-IQ Centralized Management: 5.X.X, 7.X.X, 8.X.X, 6.X.X
Source
https://my.f5.com/manage/s/article/K42324500

Description
BIG-IQ tries to assign a license to BIG-IP, but it immediately fails and shows an error similar to this on BIG-IQ GUI.

Error on server request

1. The system returned an unexpected error (400 Bad Request). Cannot grant license to device <host>(<ip>) because it's not a BIG-IP


Environment

  • Use BIG-IQ Central Management to license a BIG-IP


Cause
There are two different issues that could end up showing this error.

Issue 1
One possible cause is ID 702869. If the target BIG-IP is running version v13.1 or later, and tmsh show sys mcp-state returns full-config-load-succeed, it is likely this is the case.

Issue 2
Another possible cause is the issue described in K71538673. The message "Cannot grant license to device localhost (xx.xx.xx.xx) because it's not a BIG-IP" is known to be shown during licensing under following condition.
  • Due to K71538673 or any other issue, mcpd failed to load configuration on BIG-IP
  • BIG-IP is rebooted after mcpd failed to load configuration

In the case of K71538673, /var/log/ltm on BIG-IP contains log messages similar to this.

err mcpd[6504]: 01070356:3: vlan failsafe feature not licensed.
err tmsh[9129]: 01420006:3: Loading configuration process failed.
emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all base " - failed. -- 01070356:3: vlan failsafe feature not licensed. Unexpected Error: Loading configuration process failed.
err mcpd[6504]: 01070422:3: Base configuration load failed.

Due to the error above, MCP state on BIG-IP shows "base-config-load-failed" as follows.

# tmsh show sys mcp-state
-------------------------------------------------------
Sys::mcpd State:
-------------------------------------------------------
Running Phase                   platform
Last Configuration Load Status  base-config-load-failed


Recommended Actions

  1. If it is due to the issue 1, apply the workaround described in ID 702869.

In BIG-IP v14.1.2.7, v15.1.1, v16.0.0 and later, sys db variable restjavad.timeout (default 60 seconds) can be used to increase timeout value of internal commands to retrieve device info, which helps to avoid the issue. If the issue repeatedly occurs after restarting restjavad daemon, consider increasing the value using following command.
# tmsh modify sys db restjavad.timeout value <value>

  1. If it is due to the issue 2, apply the workaround described in K71538673.


Additional Information

None.
