Known Issue

FTP connections through layered virtual servers fail to establish.

This issue occurs when all of the following conditions are met:

  • You configure your BIG-IP system with a virtual server for FTP-based traffic.
  • You configure the virtual server to use a virtual server as the FTP resource destination.
  • You configure the second virtual server with secure network address translation (SNAT).
  • Users attempt to establish an FTP session to the virtual server.

Impact

The FTP session fails to establish to the virtual server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After users authenticate to the FTP session, any related FTP command fails with an error message similar to the following example:

    ftp: connect: Connection timed out

  • When you analyze the network-level TCP connections for the FTP session, you observe that the server data channel communication does not have SNAT applied.

Workaround

To work around this issue, you can modify the second virtual server by removing the SNAT configuration. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure will remove SNAT from the virtual server; traffic processed by the virtual server will not have address translation applied.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the second virtual server used in the configuration.
  4. Set Source Address Translation to None.
  5. Click Update.
