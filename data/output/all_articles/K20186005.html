Description

When a pool member is forced offline, BIG-IP will no longer send monitor packets to the affected pool member, unless the same pool member and monitor are also configured on another pool.

Environment

  • BIG-IP LTM
  • You have two or more pools that contain the same pool member(s), and the same monitor is applied to both pools
  • The pool member is forced offline (in one, some, or all of the pools)

Cause

This is expected behavior

Recommended Actions

In order to prevent monitors being run against these pool members, you can create a copy of the monitor for each pool, so that a single monitor is no longer used against multiple pools.

Additional Information

Here is the example configuration;
(two pools, same pool member, same monitor)

ltm pool Test-Pool-1 {
    members {
        192.0.2.1:http {
            address 192.0.2.1
            session monitor-enabled
            state up
        }
    }
    monitor test_http_monitor
}

ltm pool Test-Pool-2 {
    members {
        192.0.2.1:http {
            address 192.0.2.1
            session monitor-enabled
            state up
        }
    }
    monitor test_http_monitor
}

In this case, the monitor will always run, regardless of the state of the pool members.
