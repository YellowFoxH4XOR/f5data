Description

A BIG-IP pool member, which is a working backend server, is getting marked down by the HTTPS monitor. Monitor traffic captured from the BIG-IP shows that the pool member is reporting Fatal error for Description: Protocol Version.
A packet capture of monitoring traffic can look like the example below:

Environment

  • BIG-IP LTM
  • Pool member
  • HTTPS monitor

Cause

To initialize the TLS handshake in HTTPS monitoring traffic, BIG-IP uses TLS v1.0 by default, which can be rejected by pool members if server administrators forbid the use of TLS v1.0.

Recommended Actions

You may follow one of the below solutions to resolve the problem and allow the HTTPS monitor to properly probe your backend servers:

  1. Create a custom Server SSL profile on the BIG-IP for the HTTPS monitor which would force the BIG-IP to initially use a TLS version higher than v1.0 - the version which is expected by your pool member. You add the Server SSL profile to the health monitor configuration as described in the following article (the article explains how to force the monitor to use TLS v1.3, by choosing different options you can enable the desired TLS version):
    K52220418: Creating a HTTPS or HTTP2 monitor that utilizes TLS 1.3
  2. You can allow TLS v1.0 to be accepted by your pool members; however, this is not an ideal option because TLS 1.0 is an outdated an insecure protocol and should only be performed if absolutely necessary. This modification needs to be performed on your application server.
