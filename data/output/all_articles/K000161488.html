K000161488: SNMP Polling Over Management Interface Fails When SNMPv2 Trap Destinations Are Configured

Type
Support Solution
Published
2026-05-31
Updated
2026-07-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 17.1.2, 17.1.1, 17.1.X, 17.5.X, 17.5.1, 17.5.0, 17.1.3
Source
https://my.f5.com/manage/s/article/K000161488

Description

On BIG-IP systems, SNMP polling over the management interface may fail silently when SNMPv2c trap destinations are configured. SNMP GET requests are received by the device (visible in tcpdump), but no response is returned to the polling host.

Environment

  • BIG IP
  • SNMPv2 Traps

Cause

This issue is caused by Bug ID 2251233, which affects multiple BIG-IP versions and has no software fix as of this writing.

The root cause is that the v2-traps configuration renders to a trap2sink directive, which interferes with SNMP polling over the management interface.

Answer/Recommended Actions

  1. Remove the problematic v2 trap destination:
tmsh modify sys snmp v2-traps delete { <trap-destination-name> }
  1. Re-create the trap destination under the standard traps setcion
tmsh create sys snmp traps <trap-destination-name> {
    host <trap-destination-ip>
    port 162
    network mgmt
    community <community-string>
    version 2c
}
  1. Save configuration
tmsh save sys config
  1. Verify configuraition: 
tmsh list sys snmp

 confirm that the trap destination appears under traps { } block and not as a seperate v2-traps entry  

  1. Test SNMP polling from the external host to confirm responses are now received.
  2. High Availability (HA) environment:

 Once confirmed working on the active unit, sync the configuration to the standby peer: 

tmsh run sys config-sync to-group <device-group-name>

Additional Information

As an example of how it was before and how it should look after modification done - run list /sys snmp and check the 'traps' section.

Before:

<snip>
      traps {
         solarwinds-TEST01{ 
               host 10.10.10.220
               port 162
               network mgmt
               community *********
         solarwinds-TEST02 { 
               host 10.10.10.221
               port 162
               network mgmt
               community *********
      }
}

After Modification done:

    traps {
        solarwinds-TEST01 {
            auth-password-encrypted "****"
            community XXXXXXX
            host 10.10.10.220
            privacy-password-encrypted "****"
        }
        solarwinds-TEST02 {
            auth-password-encrypted "****"
            community XXXXXXX
