K000135797: No Supported authentication methods available (server sent: publickey) when attempting to log into the debug sidecar

Description

After attempting to ssh into the debug sidecar for BIG-IP Next, the ssh session fails with the error "No Supported authentication methods available (server sent: publickey)"

Environment

  • BIG-IP Next
  • Debug sidecar enabled

Cause

SSH errors that report "publickey" as the reason typically mean that either the wrong public key was provided to BIG-IP Next when you enabled the sidecar, or you're using the wrong public key when you attempt to log in via ssh.

Recommended Actions

First, ensure that you have a public key. 

On Linux or Mac:
  • If you have never generated a key or if you have never used ssh, or if you wish to generate a separate key pair for use with the debug sidecar, use ssh-keygen on your local machine to generate new keys for yourself.  Ssh-keygen is included with openssh and is not documented here.
  • If you frequently use ssh, the public key for your user account is stored in ~/.ssh/id_rsa.pub. 
On Windows:
  • If you are using PuTTY to connect, you can generate an ssh keypair using PuTTYgen, which is included with PuTTY.  PuTTY is a third party tool and is not described here.
Second, ensure you are providing the public key in your declaration to enable the sidecar.

You enable the sidecar by sending a PUT request to 

https://{{bigip_next_mgmt_ip}}:{{bigip_next_mgmt_port}}/api/v1/actions/systems/{{system_id}}/dataplane-debug/enable

with the following POST body:

{
"sshPublicKey": "ssh-rsa <<your_public_key_goes_here>>",
"allowedIps": [
"0.0.0.0/0"
],
"username": "admin",
"port": 5444
}
