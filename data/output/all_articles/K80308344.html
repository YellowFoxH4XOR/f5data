K80308344: vCMP guest gets other guest's Management IP which is configured to other guest.

Type
Support Solution
Published
2020-07-09
Updated
2023-02-21
Applies to
  • BIG-IP LTM: 15.0.X
Source
https://my.f5.com/manage/s/article/K80308344

Description

A vCMP guest get other existing guset's management IP address.

HOST system's guest configuration shows
The management IP for A guest:  a.a.a.a,
The management IP for B guest:  b.b.b.b

when B guest is booted, when you run 

tmsh show sys cluster
----------------------------------------------------------------------
Sys::Cluster: default
----------------------------------------------------------------------
Address                 a.a.a.a/24 <<<----------[!!] should be b.b.b.b
Availability            available
State                   enabled
Reason                  Cluster Enabled
Primary Slot ID         1
Primary Selection Time  07/01/2020 19:48:14
 

Environment

  • BIG-IP
  • vCMP guest
     

Cause

Bug ID 759968
 

Recommended Actions

Run the below command on HOST CLI

clsh tmctl -d blade tmm/vcmp -w 200 -s vcmp_name,tmid,rebroad_mac

Then check the 'rebroad_mac' field for duplicate mac addresses.

vcmp_name tmid rebroad_mac      
--------- ---- -----------------
default       0 02:01:23:45:01:00
vcmp1         0 00:00:00:00:00:00
vcmp5         0 02:01:23:45:01:04
vcmp6         0 00:00:00:00:00:00
vcmp7         0 02:01:23:45:01:06
vcmp8         0 00:00:00:00:00:00
vcmp9         0 02:01:23:45:01:08
vcmp10        0 02:01:23:45:01:0A    <--------------
vcmp11        0 02:01:23:45:01:0A    <--------------

You can see duplicate mac address for some of the guests.

Apply workaround of Bug ID 759968 on the guest which takes other guest's management ip address.


Please consider upgrade HOST system to fixed version.
 

    Additional Information

    This is HOST system issue, but workaround is done on guest.
    Upgrade required only for HOST for this known issue.
