Topic

This article describes the information required when opening a support case for F5 Modules for Ansible. To find out what information F5 Technical Support requires when you open a support case for other F5 products, refer to the product table in K2633: Instructions for submitting a support case to F5.

F5 Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration. To help you gather all the required information, use the following guidelines to prepare for opening a case.

Description

General Information

Provide the following information when you open a case with F5 Technical Support:

  • A full description of the issue, including the following:
    • The symptoms of the issue, including a brief description of any systems involved.
    • The approximate time the issue first occurred.
    • The number of times the issue has recurred.
    • Any error output provided by the system.
    • Steps to reproduce the issue.
    • Any changes you made to the system before the issue first occurred.
    • Any steps you took to attempt to resolve the issue.
    • Whether this is a new implementation.
    • Whether you have already uploaded a QKView file to the iHealth portal:
      • Ensure that any QKView files uploaded to the iHealth portal are linked to the support case.
      • If applicable, inform Technical Support of the search criteria used on the AskF5 knowledge base that did not render an article.
  • A description of the impact the issue is having on your site, using the following definitions:
    • Site Down

      Your network or application is down, or critical business functions have stopped due to the issue.

    • Site at Risk

      Your network or application is severely and negatively impacted by the issue.

    • Performance Severely Degraded

      The performance of your network or application has been severely reduced due to the issue.

    • General Assistance Required

      The subject of the case does not currently impact your network or application.

  • The hours that you are available to work on the issue (including the time zone) and any alternative contacts who can work on the issue if you are not available.
  • Remote access information, if possible.

    Note: Remote access to your network environment is important because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Technical Support will work directly with you to resolve the issue over the phone; however, this method can often be more time-consuming and may require file transfers, replication, and additional testing.

Product-specific information

The following product information is required when you open a support case:

Ansible

  1. Name of the F5 Ansible module or modules you need help with. For example bigip_pool. Additionally provide the name of any relevant tasks or roles.
  2. Example playbook.
    • Provide any example playbooks, with sensitive information removed, that may help F5 Technical Support reproduce the problem.
  3. The Ansible implementation you are using:
    • Ansible CLI/engine.
    • Ansible Tower.
    • Ansible AWX.
  4. The Ansible version you are running on your control machine.
    • The command line output from the ansible --version command.
  5. The F5 Modules for Ansible version.
    • The command line output from the following commands.
      • ansible-galaxy collection list f5networks.f5_bigip
      • ansible-galaxy collection list f5networks.f5_modules
  6. The Python version you are running on your control machine.
    • If not displayed in the output of the previous command, you can gather this information from the command line output of the python -V command.
  7. Ansible configuration.
    • Any settings you have changed, added, or removed in ansible.cfg (or if you are using the ANSIBLE_* environment variables).
    • If applicable, the version of the f5ansible galaxy role used in testing.
  8. Control machine OS environment.
    • The operating system that Ansible is running on.
  9. Verbose logging.
    • The output when running the relevant playbook at high verbosity using the following syntax:

      ansible-playbook -vvvvv <playbook>

Note: For specific instructions about how to send the preceding information to F5, refer to K000090853: Exchange files with F5 Support using MyF5.

Managed BIG-IP systems

For managed BIG-IP systems, you must provide a QKView file (a TGZ archive), which contains the configuration files that F5 Technical Support most frequently needs when troubleshooting an issue.

You can use the bigip_qkview module to create and download QKView files from your managed BIG-IP systems. Generate a QKView file from each BIG-IP system that is managed by F5 Modules for Ansible and is relevant to the support case, and provide these files to Technical Support.

Note: For more information about the bigip_qkview module, refer to bigip_qkview – Manage qkviews on the device. This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge. For more information about the qkview utility refer to K12878: Generating diagnostic data using the qkview utility
