Description

REST API very slow

Environment

BIG-IP LTM

Cause

BZID 1002969 csyncd uses a lot of CPU if there are thousands of files in a directory that it's monitoring

Recommended Actions

The workaround is to stop csyncd from syncing these, and then deleting them.

# clsh "sed -i.$(date +%Y%m%d_%H%M%S) '/run\/pamcache/,+2s/^/#/' /etc/csyncd.conf"

# clsh "bigstart restart csyncd"

 

This will resolve the REST API slowness, so removing the files is optional, but recommended.

At this point, you can either reboot the BIG-IP, which will clear all the files, as they reside in a memory based filesystem, or we need to manually delete them, using a script.

Create a script called rm-pamcache.sh

# cat <<EOF > /shared/tmp/rm-pamcache.sh

for x in {0..9} {A..Z}

do rm -f /run/pamcache/\${x}\*

done

EOF

Use clsh to scp the script from the Primary Blade to all Secondary Blades

# export pri_slot=$(getPromptStatus|awk -FS '{print substr($2,1,1)}')

clsh scp slot${pri_slot}:/shared/tmp/rm-pamcache.sh /shared/tmp/

Use clsh to run the script on each Blade

# clsh sh /shared/tmp/rm-pamcache.sh
