K90989836: BIG-IP Device shut down and did not Power On automatically after Power fluctuation or High temperature event

Type
Support Solution
Published
2021-05-09
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP Platforms
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K90989836

Description

A device was discovered to be powered off and did not automatically power on.

Environment

  • BIG-IP
  • Happened after power fluctuation or the system is in high temperature environment

Cause

  • This behavior is by-design and is not indicative of a failure.
  • When a temperature goes beyond the thresholds set, it causes the BIG-IP to shutdown itself for precautionary measures.
  • The environment may no be safe to automatically boot up.
  • It will not power up automatically.
  • A manual power on is required.
    Note: If power was interrupted, the device will power on automatically once power is restored.

Recommended Actions

Power up the device manually (via the  power button on LCD panel) and review the /var/log/ltm.log to identify probable cause of the power down.

The following is how to identify the logs: 

For units that powered down due to a threshold alert, that will not automatically power on, the BIG-IP system logs a message before the bootmarker similar to the following example to the /var/log/ltm file:

bigip1.example.com crit chmand\[10013\]: 012a0031:2: Chassis Inlet 2 temp high(crit)
bigip1.example.com notice boot_marker : ---===\[ HD1.3 - BIG-IP 12.1.2 Build 2.0.276 <HD1.3> \]===--

For units that powered down due to issues other than a threshold alert ,the BIG-IP system logs a message before the bootmarker similar to the following example to the /var/log/ltm file:

bigip1.example.com warning chmand\[6808\]: 012a0040:4: PSU2 Status input lost
bigip1.example.com notice boot_marker : ---===\[ HD1.3 - BIG-IP 12.1.2 Build 2.0.276 <HD1.3> \]===---

In LCD Panel:

Unit might display 0.0.0.0 on LCD panel.

If previous action doesn't work and serial connection shows that boot process is stuck in AOM menu with next message:
--- Press <ESC>( for AOM Command Menu.

Then, access to AOM menu and select option:
I - Display platform information

If the Power status is Off, then power on host subsystem by following below steps. Select options:
P - Power on/off host subsystem
1 - Turn on

After a few minutes, use 'I' option again to confirm that Power status is On. Then, select option:
Q - Quit menu and return to console

Additional Information

If you see nothing in console:

  1. First verify if the baud rate is set correctly (K90989836: BIG-IP Device shut down and did not Power On automatically after Power fluctuation or High temperature event).
  2. Secondly, power cycle the device (shut down the device for 5 minutes or more by removing the power cables and then powering it back on by adding back the power cables).
