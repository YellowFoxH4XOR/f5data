Known Issue

The BIG-IP GTM system can only verify self-signed certificates for use in authenticating iQuery SSL connections from other BIG-IP systems. If you use a third-party certificate to authenticate to the BIG-IP GTM system, the iQuery SSL communication will fail and report the following error message in the Global Traffic log and in the /var/log/gtm file:

7507:error:14090086:SSL routines:SSL3_GET_SERVER_CERTIFICATE: certificate verify failed:s3_clnt.c:844

F5 Product Development tracked this issue as CR67836 and CR75639 and it was fixed in BIG-IP GTM 9.3.0 and 9.4.2. For information about upgrading, refer to the BIG-IP GTM release notes.

Note: For more information about using SSL certificates signed by third-party Certificate Authorities (CAs) with the BIG-IP GTM or Link Controller system, refer to K7717: BIG-IP DNS and Link Controller support for third-party SSL certificates.

Note: For information about self-signed certificates, refer to the following articles:

  • K9114: Creating a new SSL device certificate and key pair
  • K6353: Updating an SSL device certificate on a BIG-IP system
  • K4146: Creating a self-signed certificate that expires in a different value than the default value (9.x)

Workaround

To work around this issue on affected versions, use only self-signed certificates for iQuery SSL communication.
