Known Issue

In rare circumstances, the BIG-IP system may produce a core file while the Traffic Management Microkernel (TMM) is initializing TCP Segmentation Offload (TSO) packets.

This issue occurs when all of the following conditions are met:

  • You are running a BIG-IP or VIPRION platform with HSB (High Speed Bridge) hardware.

    Note: Non-HSB platforms, like BIG-IP 2000 and 4000 series as well as BIG-IP 1600 and 3600 appliances, are not affected.

  • The BIG-IP system is processing TCP traffic.
  • The BIG-IP system is utilizing TSO.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if you have configured it for HA.
  • The BIG-IP system generates TMM core files to the /shared/core directory, with a time stamp that correlates to the traffic interruption.
  • You view an error message in the /var/log/tmm file that appears similar to the following example:

    notice panic: ../net/packet.c:157: Assertion "packet is locked by a driver" failed.

  • TMM memory utilization is high.

Workaround

To work around this issue, you can disable TSO by setting the value of the tm.tcpsegmentationoffload BigDB key to disable, and restarting TMM. To do so, perform the following procedure:

Impact of workaround: Disabling TSO may cause increased CPU usage as segmentation offload will be performed in software when TSO is disabled. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment. Additionally, restarting TMM temporarily interrupts traffic processing and devices configured as a high-availability pair may fail over.

  1. Log in to the BIG-IP command line.
  2. Disable TSO by typing the following command:

    tmsh modify sys db tm.tcpsegmentationoffload value disable

  3. Restart TMM by typing the following command:

    bigstart restart tmm
