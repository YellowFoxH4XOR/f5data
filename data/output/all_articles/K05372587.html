Description
With a significant increase in the number of remote workers, you may seeing an increase in the number of connections, CPU usage as well as memory usage. This article covers techniques from the F5 Support organizations for general guide line of BIG-IP performance check-list.

Environment

  • BIG-IP

Cause
Significant increases in the number of remote workers resulting in higher than normal resource use.

Recommended Actions

  1. Monitor the Active Connections on the BIG-IP
    • How to view the number of Active Connections on the BIG IP
    • Identifying the top source IP addresses contributing to a traffic spike
    • Overview of adaptive connection reaping (11.6.0 and later)
    • Low Water and High Water values for adaptive connection reaping are now configured in an eviction policy
  2. Monitor New Connection performance on the BIG-IP
    • Overview of the New Connections performance graph
    • Handling Connections that have been matched to the wrong Virtual Server
  3. Monitor the Throughput on the BIG-IP
    • Viewing BIG-IP system throughput statistics
    • Overview of BIG-IP traffic flow
  4. Monitor the CPU usage on the BIG-IP
    • Overview of BIG-IP TMM CPU usage
    • vCMP guest memory/CPU core allocation matrix
    • Useful tools to collect historical CPU utilization of the BIG-IP system
    • Collecting relevant data to troubleshoot high CPU utilization
    • Viewing provisioned module resource allocation from the command line
    • Understanding 'top' output on the BIG-IP system
  5. Monitor the Memory usage on the BIG-IP
    • Overview of BIG-IP memory usage 
    • Viewing memory utilization for multiple TMM instances on CMP systems
    • Overview of the tm.tcpmemorypressure database keys
    • Determining the amount of RAM installed on the BIG-IP system (10.x - 12.x)
