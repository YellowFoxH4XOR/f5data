Known Issue

Using the ZoneRunner utility to modify DNS resource records may produce unexpected results.

This issue occurs when the following condition is met:

  • You use the ZoneRunner utility to modify an existing DNS resource record that has a character length of more than 25 characters.

Impact

Users cannot modify the original resource record.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When modifying and saving changes to a DNS resource record, the original record is not modified.
  • When modifying and saving changes to a DNS resource record, the system creates a new resource record.
  • While running the ZoneRunner zrd service in debug mode, messages similar to the following example appear:

    debug zrd[10735]: 01151202:7: rr = <long name dns record>. 3600 IN A 10.10.3.30
    debug zrd[10735]: 01151202:7: rr->getData() = 10.10.3.30
    debug zrd[10735]: 01151202:7: matchRR->rr_data = 10.10.3.30
    debug zrd[10735]: 01151200:7: keeping: fall through
    debug zrd[10735]: 01151202:7: rr = <long name dns record>. 3600 IN A 10.10.3.3
    debug zrd[10735]: 01151202:7: rr->getData() = 10.10.3.3
    debug zrd[10735]: 01151202:7: matchRR->rr_data = 10.10.3.30
    debug zrd[10735]: 01151200:7: deleting: rr data doesnt match
    debug zrd[10735]: 01151200:7: doQueryAll end

Workaround

To work around this issue, you can delete the original, unmodified resource record. To do so, perform the following procedure:

Impact of workaround: This procedure permanently deletes the resource record across all BIG-IP GTM devices in the synchronization group.

  1. Log in to the Configuration utility.
  2. Navigate to Global Traffic > ZoneRunner.
  3. In the Name box, type the name of the original DNS record.
  4. Click the name of the resource record.
  5. Click Delete.
  6. To confirm deletion of the resource record, click OK.
