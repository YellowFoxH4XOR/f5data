Description

  • Configuration fails to load after upgrading from 13.x to 14.x or 15.x
  • Error Messages:
    01071912:3: BOTDEFENSE_ACTION event in rule (e) requires an associated BOTDEFENSE profile on the virtual-server ()
    Unexpected Error: Loading configuration process failed

Environment

  • Current software version is 13.x
  • BotDefense Profile
  • An iRule with a `BOTDEFENSE_ACTION` is applied to one or more virtual servers.
  • ASM, Bot Defense

Cause

This behavior is a bug tracked as ID1008005.

Recommended Actions

Any one of the following tasks can be performed to workaround the issue:
  1. Prior to upgrade, remove all iRules that have a BOTDEFENSE_ACTION event from all virtual servers.
    After the upgrade has completed restore the removed iRules to the virtual servers.
  2. If the upgrade has already been performed you can roll back to the previous version and remove all iRules that have a BOTDEFENSE_ACTION event from all virtual servers then reinstall the new software version.
  3. If the upgrade has already been performed and the config already failed to load you can comment out the iRule configuration block on all virtual servers that have the problem iRule applied in bigip.conf then run the command 'tmsh load /sys config' to load the configuration.
    For Example: 
    ltm virtual /Common/testVS {
    destination /Common/10.10.10.10:80
    ip-protocol tcp
    mask any
    policies {
        /Common/asm_auto_l7_policy__asmPolicy { }
    }
    pool /Common/http
    profiles {
        /Common/clientssl {
            context clientside
        }
        /Common/http { }
        /Common/tcp { }
        /Common/websecurity { }
    }
#    rules {
#        /Common/bot_irule
#    }
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}
