Topic

When the BIG-IP ASM system blocks a request, the system generates a blocking response that contains a support ID for the violation request. Then, the BIG-IP ASM system sends a response to the client that indicates the request was blocked.

The following default response is sent to the client:

<html>
<head>
<title>Request Rejected</title>
</head>
<body>The requested URL was rejected. Please consult with your
administrator.<br><br>Your support ID is:
<%TS.request.ID()%></body>
</html>

Note: The response includes the keyword <%TS.request.ID()%>, which generates the support ID.

Sending the support ID to an external error page hosted on a separate server

Important: If the application is configured to display the support ID within the page content, F5 recommends that the application perform a validation check in order to ensure the support ID parameter only contains 19 or 20 digits. This prevents a potential cross-site scripting (XSS) attack against the application that handles and displays the support ID parameter.

Using the Custom Response option, the support ID can be sent to an external server. For example, you can create a custom blocking response page using JavaScript in the HTML code to redirect the client to a specified address and include the support ID as a parameter. To create a custom blocking response page, you must first navigate to the Response Pages section of BIG-IP ASM, then configure the Custom Response settings.

Navigating to the Response Pages section using the BIG-IP ASM Configuration utility

To navigate to the Response Pages section in BIG-IP ASM, perform the procedure for your version of BIG-IP ASM:

BIG-IP ASM 12.x and later

  1. Log in to the Configuration utility.
  2. Click Security.
  3. Click Application Security.
  4. Click Policy.
  5. Click Response Pages.
  6. From the Current edited policy menu, select the policy to edit.
  7. Proceed to the Configuring the Custom Response settings section.

BIG-IP ASM 11.3.0 - 11.6.x

  1. Log in to the Configuration utility.
  2. Click Security.
  3. Click Application Security.
  4. Click Blocking.
  5. Click Response Pages.
  6. From the Current edited policy menu, select the policy to edit.
  7. Proceed to the Configuring the Custom Response settings section.

BIG-IP ASM 11.0.0 - 11.2.1

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Security Policies.
  4. Click the name of the security policy to update.
  5. Click Response Pages.
  6. Proceed to the Configuring the Custom Response settings section.

BIG-IP ASM 10.0.0 - 10.2.4

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Policies List.
  4. Click the name of the policy to update.
  5. Click Response Page.
  6. Below the Blocking Response Page section, click Edit.
  7. Proceed to the Configuring the Custom Response settings section.

BIG-IP ASM 9.4.3 - 9.4.8

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Web Applications.
  4. Click the name of the web application you want to update.
  5. Click Policy.
  6. Click Blocking.
  7. Click Response Page.

    The Blocking Response Page pop-up screen opens.

  8. Below the Blocking Response Page section, click Edit.
  9. Proceed to the Configuring the Custom Response settings section.

Configuring the Custom Response settings

After you navigate to the Response Pages section, you can configure the custom blocking response page. To configure the response to send the support ID to an external error page hosted on a separate server, perform the following procedure:

  1. From the Response Type list, select the Custom Response option.
  2. Click the Paste Default Response Header button for the Response header.
  3. To redirect the client, enter the necessary parameters used by your web server and TS request ID parameter in the Response HTML code box.

    Note: The following example uses JavaScript for the response sent by the BIG-IP ASM, and the external server is using a PHP script accessed by defaultpage.php for which the support ID is passed.

    Note: You can use this JavaScript redirection to redirect a browser to any location. The destination defined by window.location can be an absolute path including the fully-qualified domain name of a specific site, or a relative path, which may allow for more flexibility of configuration.

    For example:

    <html>
    <body>

    <script type="text/javascript">
    window.location = "http://<FQDN or IP address>/defaultpage.php?parameter=<%TS.request.ID()%>";
    </script>
    </body>
    </html>

    or

    <html> <body>

    <script type="text/javascript">
    window.location = "/defaultpage.php?parameter=<%TS.request.ID()%>";
    </script>
    </body>
    </html>

    Note: The <%TS.request.ID()%> keyword is required; it is used to generated the support ID that is sent to the external server.

  4. Optionally, you can use this alternative method using HTML Meta Tags:

    <html>
    <head>
    <title>Request Redirected</title>
    <meta http-equiv="refresh" content="0; url=http://<FQDN or IP address>/defaultpage.php?parameter=<%TS.request.ID()%>">
    </head>
    <body>
    </body>
    </html>

  5. To save the changes made to the Blocking Response page, click Save.
  6. Apply the policy for the changes to take effect.
