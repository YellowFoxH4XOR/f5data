K56500444: when virtual server and pool are on different port, 302 redirection does not happen correctly

Type
Support Solution
Published
2021-07-24
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K56500444

Description

When virtual server on BIG-IP is setup on different port than the pool member, the HTTP response from pool member with status code 302 does not redirect on correct port. 
The server redirects the traffic on the port server is using instead of port which is virtual server is using. 
This can be seen in a HTTP response from a TCPDUMP. (After decrypting the tcpdump: K12783074)

Environment

  • BIG-IP LTM
  • Virtual server and pool members on different port 

Cause

Incorrect redirection set on backend pool member. 

Recommended Actions

You can approach the issue by following below steps: 

  1. Verify the issue by taking a tcpdump on BIG-IP: K411: Overview of packet tracing with the tcpdump utility
  2. In HTTP response coming from pool member, verify the redirect location and port in the URL. 
  3. If the port is same as the port used for pool member service, suggest end customer to verify and correct the same on server end.
