Description

The CLI is showing /var is full, on a secondary (non-primary) blade.

  • On a multi-bladed VIPRION system, the CLI and logs may indicate the /var filesystem is full, on the non-primary blades. This may prevent the system from being upgraded and can cause system stability problems. 
  • You observe the following error message:
    011d0004:3: Disk partition /var (slot #) has only 0% free on secondary blade.
  • The df -h command shows /var is at or near 100% usage.
  • Excessive number of storageXXXX.zip or .tmp files, in the /var/config/rest folder.

Environment

Multi-bladed VIPRION/VELOS

Cause

Bug ID 996129

Recommended Actions

Workaround:

The .zip and .tmp files can safely be removed from the /var/config/rest folder. This can be done manually, using the following commands:
# bigstart stop restjavad
# rm -rf /var/config/rest/storage*.zip
# rm -rf /var/config/rest/*.tmp
# bigstart start restjavad

To automate these commands with a script, complete the following procedure:

  1. Create a text file named restcleanup.sh on the primary blade in the /config/restcleanup/ directory, containing the following commands:
    mkdir /config/restcleanup
vi /config/restcleanup/restcleanup.sh
    Note: The clsh command executes the command following it on all blades.

    clsh bigstart stop restjavad
    clsh rm -rf /var/config/rest/storage*.zip
    clsh rm -rf /var/config/rest/*.tmp
    clsh bigstart start restjavad

  2. Set permissions to make the file executable:

    chmod a+x /config/restcleanup/restcleanup.sh

  3. Create a cronjob, to run the script daily by using the crontab utility:

    crontab -e
    Note: crontab -e will open the vi editor by default. If there are existing entries in the editor, just add the following after the last line:
    0 3 * * * /config/restcleanup/restcleanup.sh
    Note: the "0 3 * * *" means, "run the script every day at 3:00am". You can change this value. See the crontab manpage for more information.
    Note: crontab may not be survive during software upgrading or backup, recommend to verify crontab job after upgrading or restoring the configuration.

  4. Save your changes. Using vi, which is the default editor the command to save is :wq.

Additional Information

 

Use the following commands to identify the files that are using the most space when /var is highly utilised:

find /var -xdev -printf '%h\n' | sort | uniq -c | sort -k 1 -nr | head -20

find /var/ -xdev -type f -exec du -h {} \; | sort -rh | grep -Ev $(mount | awk '/\/var\// {print $3}' | sed -e :a -e N -e 's/\n/|/' -e ta) | head -20

du -ha /var | sort -rh | grep -Ev $(mount | awk '/\/var\// {print $3}' | sed -e :a -e N -e 's/\n/|/' -e ta) | head -n 20
