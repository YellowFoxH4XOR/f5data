K000160856: Default APM Configuration Injected into bigip.conf When Only Licensed, Not Provisioned

Type
Support Solution
Published
2026-04-17
Updated
2026-04-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160856

Description

Default APM configuration objects are automatically injected into the bigip.conf file on BIG-IP LTM systems with an APM license, even if the APM module is not provisioned and the module is not in use. Manual removal of these configurations is not persistent, as they are re-added when saving or loading the system configuration.

Following is an example of APM default configurations injected into the bigip.conf file:

        2 {
            cipher-name aes192-ctr
        }
        3 {
            cipher-name aes128-ctr
        }
    }
    compressions {
        1 {
            compression-name none
        }
    }
    hmacs {
        1 {
            hmac-name hmac-sha2-512
        }
        2 {
            hmac-name hmac-sha2-256
        }
    }
    kex-methods {
        1 {
            kex-method-name ecdh-sha2-nistp256

Environment

  • BIG-IP LTM
  • Enterprise license includes APM, but APM module is not provisioned
  • Configuration file: bigip.conf

Cause

The presence of an APM license, even without provisioning the APM module, causes the system to automatically inject default APM configuration objects into bigip.conf. This is by design, helps the system to pre populate config objects for future provisioning. 

Answer/Recommended Actions

  • There is currently no supported method to prevent default APM configuration from being added to bigip.conf when an APM license is present but not provisioned.
  • Manual removal of APM configuration followed by mcpd forceload and reboot will temporarily remove the configuration, but running tmsh save sys config or tmsh load sys config will re-insert the default APM configuration.
  • A Request for Enhancement (RFE) ID 2277529 has been raised to consider changing this behavior so that default module configurations are only added when the module is provisioned.

Additional Information

  • RFE Bug ID: 2277529
  • This behavior is confirmed as intended by F5 Product Engineering.
