Researchers recently published a number of articles about novel HTTP/2 desynchronization (desync) attacks against proxy chains containing an HTTP/2 to HTTP/1 proxy. F5 subsequently published several articles in response to that research. Use this article to identify the F5 articles you need to address this issue.

Environment

  • BIG-IP system configured with a virtual server that has a client-side HTTP/2 profile.
  • The virtual server translates client-side HTTP/2 requests into HTTP/1 requests and sends them to the server-side pool members. This is due to the BIG-IP system not having a server-side HTTP/2 profile or its a BIG-IP version that does not support HTTP/2 on the server side. (Server-side support for HTTP/2 is introduced in BIG-IP 14.1.0).

Cause

HTTP/2 desync attacks occur when multiple devices in a proxy chain are handling malicious HTTP/2 requests and do not apply consistent logic. This failure may enable an attacker to:

  • Construct a request that tampers with legitimate user sessions.
  • Bypass configured security mechanisms.
  • Cause other unexpected behavior. Exact behavior differs depending on the specific products and servers deployed in the proxy chain.

Recommended actions

  • Ensure that all devices in all proxy chains respect RFCs and behave in a predictable, consistent manner. For example, ensure the BIG-IP-system—API-gateway—web-server proxy chain behaves predictably.
