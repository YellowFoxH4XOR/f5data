K000151100: Tenant Configuration Loss Observed During VELOS Slot Reassignment

Type
Support Solution
Published
2025-04-30
Updated
2025-05-30
Source
https://my.f5.com/manage/s/article/K000151100

Description

Tenant Configuration Loss Observed During Slot Reassignment.

Environment

  • VELOS-C

Cause

Tenant configurations are not retained during slot adjustments in the following scenarios: 

Single-slot setup: Adjusting from one single slot to a different single slot.

Multi-slot setup: Adjusting from one or more slots to an entirely different set of slots.

Recommended Actions

Expand the Tenant's Allowed Slots to include the additional slots you intend to use as replacement slots. Once the deployment has been replicated across all slots, you then remove the original slots, leaving only the newly allocated slots.

For example, if the Tenant is currently assigned to Allowed Slots 1 and 2, and you intend to replace them with slots 3 and 4, follow these steps:

  1. Set the Tenant to the Configure state.
  2. Update the Allowed Slots to include the additional slots 3 and 4.
  3. Change the Tenant to the Deployed state.
  4. Once the deployment is fully replicated across all slots, return the Tenant to the Configure state.
  5. Modify the Allowed Slots to remove slots 1 and 2, leaving only slots 3 and 4.
  6. Set the Tenant back to the Deployed state. 

Additional Information

A UCS restore must be performed for single-slot setups.

Note: RFE ID 1958049 requests the ability to move VELOS tenants between blades without losing configuration, similar to the functionality in Viprion.
