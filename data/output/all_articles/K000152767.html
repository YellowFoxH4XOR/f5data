K000152767: When trying to add a HA Peer, it's failing with "This device is not found"

Type
Support Solution
Published
2025-07-27
Updated
2025-07-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000152767

Description

After replacing a device, when adding it back to HA cluster, it keeps failing.

  • Ping works between management IPs of both devices.
  • Routing is also proper.
  • When trying to add the peer device, it keeps failing with "This device is not found" error.

Environment

One of the device was replaced recently.

  • BIG-IP 17.1.x
  • High Availability

Cause

This can be caused due to restrictive management firewall rules.

Recommended Actions

  1. Make sure the device is able to ping each others' management IPs. Check K000148576 to verify the path between them has good MTU.
  2. Make sure there are no routing issues. Check K01813098 for details and steps to rule out management routing issues.
  3. Check if there are any management firewall rules from System > Platform > Security.
  4. If there are rules, create a First rule that allows all protocols to and from both devices management IPs of both devices. This may need to be added on both devices. For steps, refer K46122561
  5. Then re-adding HA peer should work without issues.
  6. After adding these rule may be removed if not required.

Additional Information

Though HA would continue to work with restrictive management firewall after the trust is established, more relaxed rules are required when trying to build/rebuild the trust.
