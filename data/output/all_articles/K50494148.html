Description

You need to check if two servers that belong to the same pool can communicate for storage replication between them.

You want to make sure if a client connects to server 1 and uploads a file, then makes a new connection, and this time the client is load balanced to server 2, they can still find the uploaded file.

Environment

  • Storage replication between servers on a pool

Cause

None

Recommended Actions

Consider these 2 scenarios for storage replication:

The servers are on the same subnet and can communicate internally without passing traffic through the BIG-IP:

In this case, the storage replication will happen in the local network (provided it is configured on server side) without needing BIG-IP intervention. The only recommendation to ensure clients are load balanced to the same server where they have previously connected and uploaded a file, is to add a Source Address Persistence Profile to the Virtual Server related. Refer to: Manual Chapter : Session Persistence Profiles.

The servers are on different network ranges and their default gateway is configured to be the BIG-IP:

In this case, you might need to consider adding an IP Forwarding Virtual Server to allow server-to-server traffic to pass through the BIG-IP which is acting as layer 3 gateway between both pool members. Configure the destination network on the Virtual Server to be the server IP (or network range where server belongs), and the destination port to be the service used for storage replication. Refer to: K7595: Overview of IP forwarding virtual servers.
