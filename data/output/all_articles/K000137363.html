Overview of restjavad memory provisioning on BIG-IP and use of restjavad.useextramb, provision.extramb and provision.restjavad.extramb

Background

When first introduced in BIG-IP 11.4, the restjavad process used a relatively small amount of host memory. After many subsequent versions, the default memory allocated to restjavad increased, and new processes to configure memory allocation to exceed the default setting now exist.

This article describes the most recent changes and the various memory tuning options. It also makes recommendations about how to use these options to achieve a consistently sized restjavad process.

Details

The restjavad start-up script, /etc/bigstartup/scripts/restjavad, sets the minimum starting and maximum heap sizes for the restjavad process following rules that look at one or more database variables. The heap is the largest component of restjavad memory and the only part that you can configure for size. You cannot independently configure the minimum and maximum settings. The system passes these values to the Java process as command-line arguments with amounts in megabytes (MB) of memory. The minimum starting value is set by -Xms and the maximum by -Xmx.

The start-up script checks for the presence of the -Xms and -Xmxvalues. If they exist, the script then checks the values of the following system database variables:

With other BIG-IP modules, the effects are more complex. Approximately only 50 to 60 percent of X extra host memory is provisioned (at least typically on small memory systems), and some memory comes from other users of huge pages. This scenario also leads to lower values in module-specific host memory, which may negatively affect BIG-IP ASM because it has smaller URL and Method Unification (UMU) buffers. For such systems, this scenario relies on approximately half the extra host memory required to be free or able to be made free. This may be true for almost all systems other than the smallest. For medium and bigger systems, there may be enough memory to increase the restjavad size with no increase in provision.extramb, but the design that ties to provision.extramb does not allow for this.

restjavad.useextramb (Starting in BIG-IP 13.0.0): If you do not want restjavad memory size increased when you raise provision.extramb, you cannot do so in versions prior to BIG-IP 13.0.0. In this scenario, the heap starts with a much smaller -Xms value and only grows as required towards -Xmx. restjavad only looks at provison.extramb if restjavad.useextramb is set to true. Currently, provision.restjavad.extramb is only used where restjavad.useextramb is set true. In BIG-IP 17.1.x, restjavad.useextramb  is removed and using provision.restjavad.extramb is the only way to set the size of the restjavad heap.

  • provision.extramb (all versions): The system uses this to adjust the split of physical memory for the system between default sized (4KB) and huge pages (2MB) in favor of default sized pages (host memory). Provisioning extra memory for restjavad is tied to this database variable to ensure that extra host memory exists. On systems with BIG-IP LTM and BIG-IP GTM, when you use the provision.extramb value X, the Traffic Management Microkernel (TMM) has less memory allocated to huge pages and X more in host memory. On such systems, little free host memory exists, although there is usually some memory left on all but the smallest allotments.
  • provision.restjavad.extramb (In versions in which ID1025261 is fixed. See the following tables to find such versions). If restjavad.useextramb is set to true, then this new system database variable directly sets the restjavad heap size, so -Xms is equal to -Xmx, which is equal to provision.restjavad.extramb.

    provision.extramb and restjavad.useextramb are still required if you need a restjavad heap size setting other than the default value. provision.extramb still constrains the maximum-possible heap size, but provision.restjavad.extramb allows you to set a smaller value than this. This scenario is useful if you need a larger value of provision.extramb and also a larger-than-default restjavad setting, but it has more flexibility about how size. You can also use this scenario to configure a smaller-than-default restjavad, with a minimum size of 192 MB.

    Since 192 MB is the default value of provision.restjavad.extramb, if you upgrade to a version with this system database variable with a bigger-than-default restjavad configuration, it is likely that you will have to increase its value. Where ID 1153865 is fixed (restjavad.useextramb is removed) you should configure provision.restjavad.extramb with a value appropriate for your environment.

To view the -Xms and -Xmx on the BIG-IP system, use the following bash command-line argument to select the correct Java process and highlight the -Xms and -Xmx arguments:

/bin/ps -p $(pidof java) | grep Rest | grep --color '\-Xms\|\-Xmx'

You can also find these values in the pstree command output of a QKView file produced using F5 iHealth, with the appropriate Java process being a child of runsv restjavad.

dID 1153865 removes restjavad.useextramb, and makes provision. restjavad.extramb always used for setting restjavad heap size. That has default 384 MB and minimum 192 MB.

When provision.restjavad.extramb <= default of 384 MB it directly sets -Xmx to that value, and -XMs is always 96 MB. On very small, devices you can get back to -Xms 96, -Xmx 192 (It may not work if use of restjavad has changed).

When set above the default value of 384 MB, Xms is set to same as Xmx. The value is also limited to be less than the defined maximum heap size for the JVM architecture (3400 MB for 32 bit, 4000 MB for 64 bit). The amount above default size is also limited by value of provision.extramb.

You must set provision.extramb to a value greater than 0 to have higher-than-default restjavad heap.
