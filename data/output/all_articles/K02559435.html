Known Issue

When you add a new policy item using the visual policy editor, the system may fail to create an agent.

This issue occurs when the following conditions are met:

  • You attempt to add a new item to your access policy using the visual policy editor.
  • The policy item (or agent) names in the configuration are malformed or are not properly enumerated.

For example, if the name of the policy item exceeds the character limit when you are configuring a new policy item, the BIG-IP APM system truncates the name of the policy item. If an error occurs during agent name resolution for the truncated name, the visual policy editor is unable to create the agent and the agent section will be missing from the policy item in the /config/bigip.conf file, similar to the following example:

apm policy policy-item /Common/policyname_act_route_domain_selection {
    caption "Route Domain and SNAT Selection"
    color 1
    item-type action
    rules {
        {
            caption fallback
            next-item /Common/policyname_end_allow
        }
    }
}

Note: This issue occurs more frequently when you are configuring an access policy after it has been imported.

Impact

The visual policy editor fails to properly create the agent for the newly added policy item.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to add new policy items using the visual policy editor, you may observe error messages similar to the following examples:
    • Agent <name> is already referenced by another access policy item
    • Access policy item type Action <name> is already referenced by more than one access policy item.
  • Administrators are unable to add new items to an access policy using the visual policy editor.
  • When you add new items to an access policy, configuration options in the visual policy editor are missing or blank.

Workaround

You may be able to mitigate this issue by manually correcting any naming conflicts in the /config/bigip.conf file. For example, you might see a policy item entry with a name that points to a conflicting agent name, similar to the following example:

apm policy policy-item /Common/access_policy_name_example_using_longer_cess_policy_act_route_domain_selection_1 {
    agents {
        /Common/access_policy_name_example_using_longer_s_policy_act_route_domain_selection_1_ag {
            type route-domain-selection
        }
    }

In such a case, you should edit the policy item name to match the agent name, similar to the following example:

apm policy policy-item /Common/access_policy_name_example_using_longer_s_policy_act_route_domain_selection_1 {
    agents {
        /Common/access_policy_name_example_using_longer_s_policy_act_route_domain_selection_1_ag {
            type route-domain-selection
        }
    }

To do so, perform the following procedure:

Impact of workaround: The following procedure requires editing the bigip.conf configuration file, and you should perform the procedure during a maintenance window.

  1. Log in to the Advanced shell (bash).
  2. Create a backup copy of the /config/bigip.conf file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf_K02559435

  3. Using a text editor such as the vi utility, open the /config/bigip.conf file for editing.
  4. Locate and correct any naming conflicts in the policy item configurations.
  5. Save the changes and exit the editor.
  6. Load the configuration by typing the following command:

    tmsh load /sys config
