Topic

This article describes how to add Traffic Management Microkernel (TMM) interfaces to BIG-IP or BIG-IQ Virtual Edition (VE) systems running on VMware ESXi.

Description

By default, when you deploy a BIG-IP or BIG-IQ VE or using an image (.ova file), the virtual machine guest environment includes the following four virtual network adapters:

  • One for the management interface
  • Two for the TMM interfaces
  • One for high availability (HA) purposes

This deployment allows for either a one-armed or two-armed (inline) deployment. If your specific needs demand more TMM interfaces, you can add virtual network adapters to the virtual machine guest environment. Each additional virtual network adapter equates to one additional TMM interface. The following example is a common two-armed deployment:

  • One TMM interface is assigned to an external VLAN, which allows external clients to connect to virtual servers.
  • The other TMM interface is assigned to an internal VLAN, which hosts the BIG-IP pool members in the server environment.

If your network topology includes separate VLANs for internal clients (employees), external clients (customers), and internal servers (BIG-IP pool members), you can add a third TMM interface in order to create a third VLAN. For example:

  • One TMM interface is assigned to an external-client VLAN, which allows external clients to connect to virtual servers.
  • Another TMM interface is assigned to an internal-client VLAN, which allows an internal team of employees to connect to virtual servers.
  • The last TMM interface is assigned to an internal-server VLAN, which hosts the BIG-IP pool members in the server environment.

The software has no limitations on the number of interfaces that you can configure. However, F5 recommends that you do not configure more than 10 virtual network interfaces for each virtual machine.

For more information, refer to the following resources:

  • ESXi/ESX Configuration Maximums (1003497)
  • The VMware What is Virtual Networking? page

    Note: These links take you to a resource outside of AskF5. The third party could remove the documents without our knowledge.

  • K54312549: Quick deployment: One-armed load balancing configuration

Additionally, on BIG-IP versions prior to 15.1.0, although you can add virtual network interfaces, the interface numbering might appear out of order. To view the actual interface mapping, you can compare the media access control addresses (MACs) of the interfaces displayed in the BIG-IP Configuration utility to those displayed in the VMware vSphere client. For more information, refer to K17283: Adding or removing hypervisor network interfaces causes BIG-IP VE interfaces to stop sending or receiving packets. Beginning in BIG-IP 15.1.0, the enumeration of multiple network interfaces number the interfaces in an orderly manner.

Procedures

  • Add up to two additional TMM interfaces (for a total of four)
  • Add more TMM interfaces (for a total range between 5 and 10)
  • Delete TMM interfaces

Add up to two additional TMM interfaces (for a total of four)

Impact of workaround: You must reboot the system, and modifying the network interface disrupts traffic. F5 recommends that you perform the following procedure only during a scheduled maintenance window.

  1. Log in to the BIG-IP or BIG-IQ VE system command line.
  2. Ensure that the system properly detects the new interfaces when the system boots up later by forcing the mcpd process to reload the configuration. To do so, create a null file with the file name forceload in the /service/mcpd directory, by entering the following command:

    touch /service/mcpd/forceload

  3. Shut down the system by entering the following command:

    shutdown -h now

  4. Start VMware vSphere Client.
  5. Log in to the VMware vCenter server.
  6. Right-click the virtual machine.
  7. Select Edit Settings.
  8. Under the Virtual Hardware tab, select ADD NEW DEVICE.
  9. Select the Network Adapter device type.
  10. Select VMXNET 3 as the adapter type.

    Important: By default, the wizard selects Flexible as the adapter type. If you do not change this setting to VMXNET 3, the new interface does not function. While inspecting the hardware of the virtual machine, you may notice that one of the existing virtual network adapters is of the Flexible type. This is because that virtual network adapter is for the management interface. In the BIG-IP LTM VE and BIG-IP APM VE systems, the management interface may use a virtual network adapter of the Flexible or VMXNET 3 type, while TMM interfaces require virtual network adapters of the VMXNET 3 type. For this reason, only one virtual network adapter at most should ever be of the Flexible type (if any).

  11. Enter the remaining required information for the new virtual network adapter.

    Note: Repeat steps 7 through 11 if you need to add more than one virtual network adapter, but only up to four virtual network adapters. To add more TMM interfaces, for a total range between 5 and 10, refer to the Add more TMM interfaces (for a total range between 5 and 10) procedure.

  12. Select OK.
  13. Power on the system.

    Note: Unless the newly added interface is associated with a VLAN, it shows as UNINITIALIZED. This is explained in K12697: Initialization of a TMM interface on BIG-IP Virtual Edition.

Add more TMM interfaces (for a total range between 5 and 10)

To add additional TMM interfaces (for a total range between 5 and 10), you can add one new virtual network adapter at a time to the virtual machine. To do so, perform the following procedure:

Impact of workaround: You must reboot the system, and modifying the network interface disrupts traffic. F5 recommends that you perform the following procedure only during a scheduled maintenance window.

  1. To add more TMM interfaces (for a total range between 5 and 10), you must first perform the previous procedure, Add up to two additional TMM interfaces (for a total of four). If you have already completed that procedure, continue to the following step.
  2. Log in to the BIG-IP or BIG-IQ VE system command line.
  3. Ensure that the system properly detects the new interface when the system boots up later by forcing the mcpd process to reload the configuration. To do so, create a null file with file name forceload in the /service/mcpd directory, by entering the following command:

    touch /service/mcpd/forceload

  4. Shut down the system by entering the following command:

    shutdown -h now

  5. Start VMware vSphere Client.
  6. Log in to the VMware vCenter server.
  7. Right-click the virtual machine.
  8. Select Edit Settings.
  9. Under the Virtual Hardware tab, select ADD NEW DEVICE.
  10. Select the Network Adapter device type.
  11. Select VMXNET 3 as the adapter type.

    Important: By default, the wizard selects Flexible as the adapter type. If you do not change this setting to VMXNET 3, the new interface does not function. While inspecting the hardware of the virtual machine, you may notice that one of the existing virtual network adapters is of the Flexible type. This is because that virtual network adapter is for the management interface. In the BIG-IP LTM VE and BIG-IP APM VE systems, the management interface may use a virtual network adapter of the Flexible or VMXNET 3 type, while TMM interfaces require virtual network adapters of the VMXNET 3 type. For this reason, only one virtual network adapter at most should ever be of the Flexible type (if any).

  12. Enter the remaining required information for the new virtual network adapter.
  13. Select OK.

    Note: You should add only one new network interface at each iteration of this procedure.

  14. Power on the system.
  15. Perform the following steps to ensure that the new network interface is properly mapped:
    1. To map the new network interface and MAC address into the BIG-IP system database, enter the following command:

      f5-swap-eth -w

    2. To review whether the new virtual network interface is added correctly, you can view the file /etc/ethmap. To do so, enter the following command:

      cat /etc/ethmap

      Important: Do not modify this file. This file is output of the network interfaces mapping on the BIG-IP system after you perform the previous commands in this procedure.

  16. Optional: To add another virtual network adapter, repeat steps 2 through 15.

    Note: To add an interface to a VLAN or trunk, refer to the Implementation manual for your version of the BIG-IP system.

    Note: Unless the newly added interface is associated with a VLAN, it shows as UNINITIALIZED. This is explained in K12697: Initialization of a TMM interface on BIG-IP Virtual Edition.

Delete TMM interfaces

Deleting an interface may cause issues when loading the BIG-IP configuration. This issue is due to the many BIG-IP traffic management objects that reference the interface. You must remove all traffic management objects in the following order prior to deleting the interface:

  1. Virtual servers
  2. Pools
  3. SNATs
  4. Self IPs
  5. VLANs
  6. Tunnels

After you have removed the appropriate traffic management objects, delete the interface by performing the following procedure.

Impact of workaround: You must reboot the system, and modifying the network interface disrupts traffic. F5 recommends that you perform the following procedure only during a scheduled maintenance window.

  1. Log in to the BIG-IP or BIG-IQ VE system command line.
  2. Use an editor to edit the /config/bigip_base.conf file.
  3. Find the net interface listing.

    For example:

    net interface 1.1 {
        media-fixed 10000T-FD
    }
    net interface 1.2 {
        media-fixed 10000T-FD
    }
    net interface 1.3 {
        media-fixed 10000T-FD
    }

  4. Delete the interface object. In this example, after you delete net interface 1.3, the file appears as follows:

    net interface 1.1 {
        media-fixed 10000T-FD
    }
    net interface 1.2 {
        media-fixed 10000T-FD
    }

  5. If the interface object that you deleted in step 4 continues to exist in the net stp listing, you should delete it and its corresponding VLAN. In this example, after you delete 1.3 and its corresponding vlan-ha from the net stp listing, the file appears as follows:

    net stp /Common/cist {
        interfaces {
            1.1 {
                external-path-cost 200000
                internal-path-cost 200000
            }
            1.2 {
                external-path-cost 200000
                internal-path-cost 200000
            }
        }
        vlans {
            /Common/vlan-ext
            /Common/vlan-int
        }
    }

  6. Save the /config/bigip_base.conf file.
  7. Ensure that the system properly deletes the interface when the system boots up later, by forcing the mcpd process to reload the configuration. To do so, create a null file with the file name forceload in the /service/mcpd directory by entering the following command:

    touch /service/mcpd/forceload

  8. Shut down the system by entering the following command:

    shutdown -h now

  9. Start the VMware vSphere Client.
  10. Log in to the VMware vCenter server.
  11. Right-click the virtual machine after it has powered down.
  12. Select Edit Settings.
  13. Under the Virtual Hardware tab, select the Network adapter that you want to remove.
  14. Select Remove.
  15. Select OK.
  16. Power on the system.
