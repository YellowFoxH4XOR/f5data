Description

The virtual server closes some of the connections with TCP Reset - [F5RST: No server selected].

 

Environment

  • BIG-IP
  • virtual server with no pool applied
  • traffic directed to back-end servers with irule or ltm policy

Cause

The virtual server has no pool assigned and load balancing is made based on the ltm policy, which forwards traffic to specified pools depending on the HTTP::host header included in the HTTP request.

Requests with HTTP::Host different than ones specified in the policy cannot be forwarded by BIG-IP, because there is no default pool specified.

 

In some rare occasions received request includes unexpected Host header, for example:

Host: _\r\n

 

The result is the same here. With no hostname, BIG-IP is not able to choose the pool/pool member.

 

 Recommended Actions

Cover all possibilities, including default pool selection within the policy.
