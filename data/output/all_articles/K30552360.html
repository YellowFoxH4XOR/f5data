Description

You may see the error below when updating ASM attack signatures;
----------------------------------------------------------------
Error message:
Failed to mount: '/bin/mount': 512 at /usr/local/share/perl5/F5/ImUtils.pm line 74.

/var/log/ts/asm_config_server.log
F5::Sigfile::Update::store_error_and_die,,Failed to mount: '/bin/mount': 512 at /usr/local/share/perl5/F5/ImUtils.pm line 74.
----------------------------------------------------------------

And at this situation, you can confirm that there is no free loop device on BIG-IP.
 # ls -al /dev | grep loop
 # losetup -a
 # losetup -f

Environment

  •  ASM is provisioned
  •  Updating a ASM attack signature

Cause
Due to some reasons of DB corruption, past ASM signature updates were not able to finish completely.
It should cause no free loop device.

Recommended Actions
Note: This should not cause any traffic disturbance.

  1. Delete and Re-create the loop devices. Simply copy and paste below lines so you can run them at once.
     rm -f /dev/loop0
     rm -f /dev/loop1
     rm -f /dev/loop2
     rm -f /dev/loop3
     rm -f /dev/loop4
     rm -f /dev/loop5
     rm -f /dev/loop6
     rm -f /dev/loop7
     mknod -m 0660 /dev/loop0 b 7 0
     mknod -m 0660 /dev/loop1 b 7 1
     mknod -m 0660 /dev/loop2 b 7 2
     mknod -m 0660 /dev/loop3 b 7 3
     mknod -m 0660 /dev/loop4 b 7 4
     mknod -m 0660 /dev/loop5 b 7 5
     mknod -m 0660 /dev/loop6 b 7 6
     mknod -m 0660 /dev/loop7 b 7 7

    Should the previous step fail to resolve the issue,you can execute the following stanza to release the loop devices using the losetup command:
    losetup -d /dev/loop*
