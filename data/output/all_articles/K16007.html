Known Issue

The BIG-IP 11050 platform may fail to go Active, and remain in an Inactive state after starting up.

This issue occurs when one of the following conditions is met:

  • You start a BIG-IP 11050 platform to a volume running BIG-IP 11.5.1 HF5 through HF8.
  • You start a BIG-IP 11050 platform to a volume running BIG-IP 11.4.1 HF6 through HF8.
  • You start a BIG-IP 11050 platform to a volume running BIG-IP 11.2.1 HF11 through HF12.

The /etc/hal/platform-capabilities.xml file for the affected hotfix versions has a duplicate entry for the 11050 platform. These versions do not tolerate the duplicate entries, and the system does not properly detect the system's software raid capability. As a result, when starting to an affected version, the mcpd daemon fails to start with invalid logical disk errors.

Impact

The system will not go Active and will not process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H501121 on the Diagnostics > Identified > Medium|High screen.
  • After booting to the affected version and hotfix, the system does not go Active and remains in an Inactive state.
  • The system's command prompt indicates that the system is inactive.
  • The /var/log/daemon.log file contains messages similar to the following examples:

    err mcpsync: F5::COAPI error -- Transaction Save -- 01071335:3: Invalid logical_disk (0) for application volume (avrdata).
    err mcpsync: disk info mcpsync failed

  • The /var/log/ltm log file contains messages similar to the following examples:

    warning diskmonitor: 011d0002: Can not access the database because mcpd is not running.
    err mcpd[7503]: 01071335:3: Invalid logical_disk (0) for application volume (avrdata).
    notice sod[8287]: 010c0063:5: Waiting for Mcpd without a response. Try again...
    err mcpd[7503]: 01071335:3: Invalid logical_disk (0) for application volume (avrdata).
    err mcpd[7503]: 01071335:3: Invalid logical_disk (0) for application volume (avrdata).
    notice sod[8287]: 010c0063:5: Waiting for Mcpd without a response. Try again...
    err mcpd[7503]: 01071335:3: Invalid logical_disk (0) for application volume (avrdata).
    err mcpd[7503]: 01071392:3: Background command '/usr/lib/install/mcpsync -o' failed. The command was signaled.
    err mcpd[7503]: 01071335:3: Invalid logical_disk (0) for application volume (avrdata).

Workaround

To work around this issue, you can modify the /etc/hal/platform-capabilities.xml file to ensure that the entries for the 11050 platform are unique. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Back up the original platform-capabilities.xml file by typing the following command:

    cp /etc/hal/platform-capabilities.xml /etc/hal/platform-capabilities.xml.sol16007

  3. Using a text editor (for example, vi, pico), open the /etc/hal/platform-capabilities.xml file.
  4. Locate the duplicate platform name entries for the 11050 platform and add an "N" to change the platform name for the Turbo Apollo NEBS platform.

    For example, take the following entry:

            <platform name="BIG-IP 11050"              pid="E102"  >           <!-- Turbo Apollo -->
                <raid type="software" />
            </platform>
            <platform name="BIG-IP 11050"             pid="E103"  >           <!-- Turbo Apollo NEBS -->    
                <raid type="software" />
                <nebs value="true" />

    Change the previous entry to the following:

            <platform name="BIG-IP 11050"              pid="E102"  >           <!-- Turbo Apollo -->
                <raid type="software" />
            </platform>
            <platform name="BIG-IP 11050N"             pid="E103"  >           <!-- Turbo Apollo NEBS -->  
                <raid type="software" />
                <nebs value="true" />
            </platform>

  5. Save the /etc/hal/platform-capabilities.xml file.
  6. Reboot the system by typing the following command:

    reboot
