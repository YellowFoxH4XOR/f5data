Known Issue

A BIG-IP system that is configured with a DNS cache may cause TMM to crash.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a DNS Cache.
  • The BIG-IP DNS cache receives a UDP-based DNS update request.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high availabilty pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H426310 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system fails over to the standby system, if configured as a high availability pair.
  • The BIG-IP system will report error messages to any of the /var/log/tmm* files. For example:

    notice ** SIGSEGV **
    notice fault addr: 0
    notice fault code: 0x80

Workaround

To work around this issue, you can enable datagram load balancing in the UDP profile used by the affected virtual server. To do so, perform the following procedure:

Impact of workaround: During high volume of DNS traffic, the BIG-IP system CPU utilization may increase when using the datagram load balancing option, as it reduces the memory usage.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click Protocol.
  5. Click UDP.
  6. Click on the name of the affected UDP profile.
  7. To enable the datagram load balancing option, select the Datagram LB check box.
  8. Click Update.
