K31100432: Website content is being blocked with ''Mixed Content'' warning

Type
Support Solution
Published
2020-04-28
Updated
2025-04-01
Applies to
  • F5 App Protect
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K31100432

Description

When you try to access a website but get an error similar to: Your connection to this site is not fully secure.

When you check into it, by either looking at the Learn more link, or Developer Tools in the browser, you are informed that the site was blocked due to Mixed Content.

You can also see an error similar to the following example, on a HAR capture file:

[Mixed-Content] The origin 'https://example.mydomain.com' was loaded in a secure context but tried to load an insecure document resource at 'https://example.mydomain.com/blank.html'.

Environment

  • Website with both HTTPS and HTTP content
  • Client browser
  • Stream Profile
  • iRules

Cause

In January 2020 Chrome update 80 included, by default, the blocking of mixed content. Along with this the other major browsers are also following suit. This will become even more ardent with Chrome in version 81.

The traffic was sent from the client using https but some of the content will be returned with http. This can be seen in a packet capture.

The reason for this change is due to the need for increased security. However, some web pages can be neither entirely HTTPS nor completely HTTP. Some web pages are delivered over a secure HTTPS connection, but they pull in images, scripts, or other resources via an unencrypted HTTP connection. Such web pages have "mixed content" because they are not fully secure. The web page itself couldn’t be tampered with, but it may pull in a script, image, or iFrame (a web page inside a "frame" on another web page) that could have been tampered with.

Recommended Actions

Follow the steps required to address the topic covered in the description.

  • The only real fix is to fix the legacy issues within the application. The application developer will need to re-code the application and use https for the objects.
  • A workaround, depending on the browser, you can choose to load the traffic by clicking Load Unsafe Scripts, Display Mixed Content, or similar messages.
The BIG-IP can be used to mitigate the issue using Stream Profile. The Stream Profile will change http code to https. This should not be a permanent fix as using Stream Profile will increase CPU utilization.

If the web server is returning compressed content, the iRule method will be required because the LTM does not decompress response content, so it won't be able to make the replacement.  Either the web server needs to have compression disabled, or the iRule can be used to prevent the web server from sending a compressed response by removing the compression offerings from the client.
  • The BIG-IP may be able to mitigate the issue with the use of a iRule
  • The BIG-IP may be able to mitigate the issue by using a Steam Profile in the Virtual Server.

To mitigate the issue with the use of a iRule follow these steps:

  1. Create an iRule with the following syntax:

    when HTTP_REQUEST {
       # Disable the stream filter for all requests
       STREAM::disable
       # LTM does not decompress response content, so if the server has compression enabled
       # and it cannot be disabled on the server, we can prevent the server from
       # sending a compressed response by removing the compression offerings from the client
       HTTP::header remove "Accept-Encoding"
    }
    when HTTP_RESPONSE {
       # Check if response type is text
          if {[HTTP::header value Content-Type] contains "text"}{
          # Replace http:// with https://
          STREAM::expression {@http://@https://@}
          # Enable the stream filter for this response only
          STREAM::enable
          }
    }
     
  2. Assign the iRule to the Virtual Server.
  3. Assign a Stream Profile to you Virtual Server, in order for the STREAM:: Commands to work. This can be an empty or the default Stream Profile.  On the GUI navigate to: Local Traffic > Profiles > Other > Stream.

Important: Please test this thoroughly before putting it into place. In some cases, it will now allow the traffic through, but due to the age of the app or other factors and it may not render in the browser.
 

To mitigate the issue using only a Stream Profile in the Virtual Server:

  1. Login into the Configuration Utility.
  2. Navigate to Local Traffic > Profiles > Other > Stream.
  3. Click Create.
  4. Give a name to the Steam Profile such as http-to-https.
  5. Check the Custom options.
  6. In Source enter http.
  7. In Target enter https.
  8. Click Finished.
  9. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  10. Click on the Virtual Server which having the issue.
  11. In Configuration, from Basic choose Advanced.
  12. In the Stream Profile, choose the new Stream Profile which as created. For example http-to-https.
  13. Click Update.
Important: Please test this thoroughly before putting it into place. In some cases, it will now allow the traffic through, but due to the age of the app or other factors and it may not render in the browser.
