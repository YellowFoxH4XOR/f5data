Description

/var/log/audit is constantly displaying messages like:

slot2/VIP2400-Rxx-xxx notice mcpd[7084]: 01070417:5: AUDIT - client Unknown, user mcpd-primary - transaction #1065604-4 - object 0 - modify { physical_disk { physical_disk_serial_number "BTHVxxxxxxYTxxxNGN" physical_disk_object_id 12208 physical_disk_slot_id 1 physical_disk_last_smartd_alert "" physical_disk_hpa_error 0 physical_disk_model "ATA INTEL SSDSC2BA40" physical_disk_name "HD1" physical_disk_is_array_member 0 physical_disk_wearout_indicator { wearout_info_t_value 100 wearout_info_t_worst 100 wearout_info_t_threshold 0 } physical_disk_space_available { wearout_info_t_value 100 wearout_info_t_worst 100 wearout_info_t_threshold 10 } physical_disk_power_on_hours 10539 physical_disk_remaining_life 18446744073709551615 physical_disk_selftest_status 0 physical_disk_array_status 0 physical_disk_transaction_id 3 } } [Status=Command OK]

Environment

  • VIPRION
  • Multiple blades
  • /var/log/audit

Cause

This is normal to see when Audit (MCP) logging is enabled, which it is by default. On bladed systems, the blades send these messages between each other to keep drive health status synchronized between them. This is generated by  the mcpd daemon when house keeping task is done on the disk every four hours.

Note: In BIG-IP 11.6.0 and later, the Audit (MCP) config.auditing setting is set to Enable by default. In BIG-IP 11.5.1 and earlier, this setting is set to Disable by default. For more information, refer to K16304: Audit logging for BIG-IP configuration changes is now enabled by default.

Recommended Actions

This is a benign error thus can be ignored.
