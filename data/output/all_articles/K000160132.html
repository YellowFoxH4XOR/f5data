Description

While using "Dynamic Routing Protocol" (Network  ››  Route Domains  ››  0 ), health monitors get delayed status indication (UNCHECK to UP ), since the BIG-IP's routes starts a little later and the static routes configured (IMISH) are added to the routing table later, compared to the static routes added via the tmsh. 

Environment

  • BIG-IP LTM
  • Configuration for the dynamic routing enabled (Zebos)
  • Health monitor with the default values 

Cause

After rebooting the BIG-IP device (in which the static routes towards the pool members are dependent on the Zebos/imish configuration), health monitors/pools experience a delay (approximately up to 10 to 20 seconds) before becoming available.

Recommended Actions

If this delay is unacceptable, use TMSH routes towards the pool member. 
You may still use IMISH (Zebos) to advertise Virtual Server IPs.

Below you will find an example of how to remove routes from IMISH/Zebos configuration and use the TMSH for your Routes. 

Move the static route from the configuration in the Zebos file to the tmsh:

1. Copy the file /config/zebos/rd0/ZebOS.conf for backup: 
cp /config/zebos/rd0/ZebOS.conf /config/zebos/rd0/ZebOS.conf.bck

2. Remove the following static route, i.e.: ip route 0.0.0.0/0 10.10.10.254:
From CLI:
#> imish
IMISH> en
IMISH> conf t
IMISH> no ip route 0.0.0.0/0 10.10.10.254
IMISH> write mem 
IMISH> exit


3. And add it to the TMSH:  

tmsh create net route default gw 10.10.10.254
