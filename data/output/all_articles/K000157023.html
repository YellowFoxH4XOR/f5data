K000157023: DNS Server Link IP address remains after deleting the IP on the LTM.

Type
Support Solution
Published
2025-10-15
Updated
2025-10-15
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source

Description

When Link Discovery is enabled, then any default gateway pool members on an LTM device will be turned into a "GTM Link" and any non-floating self-IP's which fall on the same subnet range as the default gateway pool members will be added as IP addresses under 'gtm server' object on the DNS device. When a pool member or IP address is deleted from the LTM device, the corresponding IP address is automatically removed from the GSLB > Links list in the BIG-IP DNS (GTM) system. However, the same IP address may still appear under GSLB > Servers > Servers List > Links. This behavior is by design and does not indicate a system error.

Environment

  • Product: BIG-IP DNS (GTM)
  • Configuration: GSLB with auto-discovery of links and virtual servers enabled; LTM and DNS (GTM) integration

Cause

The system is designed to automatically update the 'gtm link' configuration when an LTM pool member or IP address is removed. However, the 'gtm server' IP addresses are not automatically updated and require manual intervention to remove obsolete entries.

Recommended Actions

Impact of workaround: There should not be any impact to your production environment when performing these changes, especially considering the IP being deleted is no longer in use.

  • After removing an LTM pool member or IP address, review the GSLB > Servers > Servers List > Links section.
  • Manually remove any obsolete IP addresses from the 'gtm server' configuration if they are no longer needed.
  • Regularly audit the GSLB server configuration to ensure it accurately reflects the current LTM pool members and IP addresses.
