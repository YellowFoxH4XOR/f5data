K28810075: F5 access is not sending certificate

Type
Support Solution
Published
2021-07-15
Updated
2025-07-07
Applies to
  • BIG-IP
  • F5 Access
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K28810075

Description

You have an Access Policy with an "On-Demand Cert Auth" object and is not authenticating for some users.
The debug access logs show on /var/log/apm  that the certificate is not being received by the BIG-IP APM 

 

Example:

/Common/example_policy: Session variable 'session.clientcert.ssl_rehandshake_pending' set to '1'
/Common/example_policy: Session variable 'session.ssl.cert.exist' set to '0'
/Common/example_policy: Session variable 'session.ssl.cert.valid' set to '1'
/Common/example_policy: ./AccessPolicyProcessor/Session.h: 'setSessionInactive()': 1157: done with request processing /Common/example_policy: ApmD.cpp: 'sendAccessPolicyResponse()': 2804: send 'redirect to EUIE' code, redirect URL="/agent_aaa_clientcert_form.cca"
/Common/example_policy: ApmD.cpp: 'process_apd_request()': 1878: ** done with the request processing **
/Common/example_policy: Session deleted due to user inactivity. /Common/pos_apm_authcert_prod:Common:d7364793: Session statistics - bytes in: 4392, bytes out: 3542

 

Environment

  • F5 Access for Android
  • BIG-IP APM

 

Cause

The Certificate on the endpoints affected are expired

 

Recommended Actions

Replace or renovate the certificate on the endpoint
