Known Issue

When source address persistence is configured on more than one virtual server, persistence may break.

This issue occurs when all of the following conditions are met:

  • Two or more virtual servers are configured with source address persistence.

    Note: The virtual servers may have two separate source address persistence profiles or may share the same source address persistence profile.

  • The configuration options in the source address persistence profiles used by the virtual servers have one of the following options enabled:
    • Match Across Services
    • Match Across Virtual Servers
    • Match Across Pools

Impact

Connections will not persist as expected on affected virtual servers.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When a source address persistence record exists for one virtual server, connections to another virtual server will not create a persistence record.

    For example, two virtual servers that meet the previous criteria have open connections, as shown in the following bigtop command output:

    VIRTUAL ip:port |---In----Out---Conn-|---In----Out---Conn-|-Nodes Up--
    10.10.10.81:http 63888 66632 18 0 0 0 2
    10.10.10.80:http 26592 39912 9 0 0 0 2

    However, the BIG-IP system will have persistence records for only one of the virtual servers, as shown in the following bigpipe persist all show all command output:

    PERSISTENT CONNECTIONS
    | Mode source addr Value 10.10.1.2
    | virtual 10.10.10.80:http node 10.11.7.1:http age 19sec

Workaround

To work around this issue, you can choose an alternate persistence. To choose an alternate persistence method, refer to the Enabling Session Persistence chapter of the Configuration Guide for BIG-IP Local Traffic Manager.

Impact of workaround: Changing the persistence method may negatively impact your configuration if the new method is inappropriate for your specific environment. It is imperative that you review the documentation and only make changes that are appropriate to your topology.
