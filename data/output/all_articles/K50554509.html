K50554509: Basic troubleshooting commands for istio-proxy in Aspen Mesh

Type

Published

Updated
2023-07-18
Applies to
  • Aspen Mesh: 1.14, 1.11
Source

Description

Given any application inside the mesh, you can use a variety of tools and commands to troubleshoot your istio-proxy or retrieve information from logs, about its health, etc.

Environment

  • Redhat Openshift: 4.6x, 4.7.x
  • Kubernetes: 1.17x,1.18.x,1.19.x,1.20.x
  • Aspen Mesh: 1.6.x, 1.9.x

Cause

None

Recommended Actions

Perform the following recommended actions:
  • Retrieve the config file from an istio-proxy
  • Retrieve listeners, clusters, routes, endpoints
  • Check the status of your proxy
  • Retrieve certificates loaded into istio-proxy
  • Turn on debug on istio-proxy
Retrieve the config file from an istio-proxy

Retrieving the configuration from the istio-proxy is useful when tracing and debugging the components of the proxy, such as listeners, routes, clusters, endpoints and all the flags used to configure the istio-proxy.

  1. Identify the pod that you want to retrieve the istio-proxy configuration from.

  2. If your app container has curl installed, use the following command syntax:

    Note: Use oc or kubectl depending on your environment.

    kubectl exec <pod-name> -c <container-name> -- curl localhost:15000/config_dump > istio-proxy-config.json

You can use any indicative name for the output file instead of istio-proxy-config.

Retrieve listeners, clusters, routes, endpoints
Sometimes, you do not need to retrieve the whole configuration, but just a little portion. If that is the case, you can use the istioctl command line to do so:
  1. To retrieve the configuration of any of the following components, use the following command syntax:

    istioctl proxy-config <component> <pod-name>.<namespace>

    components:
    • Clusters
    • Endpoints
    • Listeners
    • Routes
For example, you can also output the component configuration in a json format and append to a file with the following command syntax:

istioctl proxy-config <component> <pod-name>.<namespace> -o json > pod-routes.json

Check the status of your proxy

Retrieving the status of the istio-proxy would be useful to determine if pilot (istiod) is sending the correct configuration to your istio-proxy.

  1. You can retrieve all the pods just with one command:

    istioctl proxy-status

  2. If you want to select one particular pod, use the following command syntax?

    istioctl proxy-status <pod-name>.<namespace>

Retrieve certificates loaded into istio-proxy

Retrieving the certificates used by the istio-proxy could be useful if you want to determine if those are active or valid. By default, you can only get the cert-chain and the ROOTCA, private keys are redacted for security purposes.

  1. Verify integrity of the certificates with the following command syntax:

    istioctl proxy-config secrets <pod-name>.<namespace>

  2. You can output the secrets in json format

    istioctl proxy-config secrets <pod-name>.<namespace> -o json

  3. Secrets are encrypted in base64, you can pipe the output to other commands such as openssl to check the signing authority, expiration date, etc.

    • istioctl proxy-config secret <pod-name>.<namespace> -o json | jq '[.dynamicActiveSecrets[] | select(.name == "default")][0].secret.tlsCertificate.certificateChain.inlineBytes' -r | base64 -d | openssl x509 -noout -text

    • istioctl proxy-config secret <pod-name>.<namespace> -o json | jq '[.dynamicActiveSecrets[] | select(.name == "ROOTCA")][0].secret.validationContext.trustedCa.inlineBytes' -r | base64 -d | openssl x509 -noout -text

Turn on debug on istio-proxy

This is the last step in debugging your application using an istio-proxy. Turning on debug logging will increase the verbosity of the loggers inside the proxy.

Important: Note that this is not recommended use, and you use it at your own risk.
  1. Identify the pod that you want to retrieve the istio-proxy configuration.
  2. Use the following istioctl command to enable debug:

    Note: Once debugging completes, return the logger component to the default value warning.

    istioctl proxy-config log <pod-name>.<namespace> --level <logger>:debug
