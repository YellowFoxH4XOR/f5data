Topic

The HTTP Class profile is no longer available in BIG-IP 11.4.0 and later versions.

Description

F5 has replaced the HTTP Class profile with the introduction of the Local Traffic Policies feature in BIG-IP 11.4.0. During an upgrade to BIG-IP 11.4.0, if your configuration contains an HTTP Class profile, the BIG-IP system attempts to migrate the HTTP Class profile to an equivalent local traffic policy.

In some cases, where the HTTP Class profile contains certain complex glob or regular expressions, the BIG-IP system cannot successfully migrate the HTTP Class profile to an equivalent local traffic policy during the upgrade. For example, the BIG-IP system may not be able to successfully migrate glob and regular expressions similar to the following:

Glob

  • string.*string
  • string[1-9]

Regex

  • string.*$
  • string[.+]

However, the following glob and regular expressions can be successfully migrated during the upgrade:

Glob

  • *string*
  • *string
  • string*

Regex

  • string.*
  • ^string
  • ^string.*
  • string$

Note: For matches performed on HTTP headers, the name and value are treated differently. For example, if the header name contains a period (.) or an asterisk (*), the HTTP Class profile is not converted. The header value is treated as the other HTTP Class profile values.

If the BIG-IP system cannot migrate the HTTP Class profile, the upgrade fails with an error message that appears similar to the following example:

HTTP Class profiles with complex globs, regular expressions, or header names cannot be upgraded

You can view the /var/log/liveinstall.log file to find the details about which HTTP Class profiles fail to convert. Any HTTP Class profile that does not successfully migrate is configured to reject traffic and log a message to the /var/log/ltm file.

Note: An HTTP Class profile that does not successfully migrate produces a local traffic policy that consists of two rules. The first rule matches all traffic, rejects it, and logs a message to the /var/log/ltm file. The second rule contains the partially-converted matching expressions from the HTTP Class profile. You should remove the first rule after the rule is successfully converted.

Additionally, if you attempt to restore a user configuration set (UCS) archive from an earlier version to BIG-IP 11.4.0, the UCS install fails with error messages that appear similar to the following example:

info: ERROR: The httpclass profile(s) for policy /Common/regex_path_component_secure did not roll forward:
info: policy rule(s) created from regex_path_component_secure with value .*/secure(/.*)\?
info: See Solution SOL14409

Recommendations

While the BIG-IP system can successfully migrate most HTTP Class profiles with complex glob and regular expressions during the upgrade, there are certain complex glob and regular expressions that may cause the upgrade or UCS install to fail. Before you upgrade to BIG-IP 11.4.0, if your configuration contains an HTTP Class profile that uses a complex glob or regular expression, F5 recommends that you perform the following tasks:

  1. Back up the pre-11.4.0 configuration data to a UCS archive. For more information, refer to K11318: Backing up and restoring BIG-IP configuration files (10.x) or K13132: Backing up and restoring BIG-IP configuration files (11.x - 12.x).
  2. Attempt to upgrade to BIG-IP 11.4.0. The upgrade fails because of the complex globs or regular expressions.
  3. Cancel the failed installation.
  4. Review the /var/log/liveinstall.log file for details about which HTTP Class profiles failed to convert.
  5. Edit the HTTP Class profiles to remove the offending globs and regular expressions.
  6. Upgrade the system to BIG-IP 11.4.0.
  7. Boot to the newly upgraded boot location.
  8. Reconfigure any converted local traffic policies that match a regular expression listed in the previous Description section or implement the policy as an iRule.
