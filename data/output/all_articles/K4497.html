K4497: BIG-IP and 3-DNS switch appliances may not send an SNMP trap at boot

Type
Known Issue
Published
2006-02-17
Updated
2023-02-21
Status
Legacy Content
Applies to
  • Legacy Products
  • 3-DNS: 4.6.4
  • BIG-IP 4.X: 4.6.4
Source

Known Issue

This is the result of a known issue. Beginning in BIG-IP and 3-DNS versions 4.5.11 and 4.6.2, all switch ports are disabled until the spanning tree daemon has started. The SNMP trap for reboot is triggered by the kernel start up message, which occurs before the spanning tree daemon is started. BIG-IP and 3-DNS cannot send the SNMP trap, because the switch ports are disabled.

F5 Networks Product Development is tracking this issue as CR46509, and it is scheduled to be fixed in a future release. Monitor future BIG-IP or 3-DNS Release Notes for the status of this CR.

Workaround

To work around this issue, perform the following steps:

  1. Log in to the command line.
  2. Edit the /etc/syslog.conf file.
  3. Locate the SNMP trap section of the file.

    The SNMP trap section begins with the following lines:

    # To generate traps using the facilities in the previous paragraph,

    # uncomment the following:

  4. At the end of the SNMP trap section, add the following line:
    daemon.*                                        /var/run/trapper

    Save the file and exit the editor.

  5. Edit the /etc/rc.local file.
  6. At the end of the file, add the following line:

    logger -p daemon.info "BIG-IP Kernel 4.x-CPU (SNMP Trap for reboot. See AskF5 Solution 4497 for more information.)"

  7. Save the file and exit the editor.

BIG-IP or 3-DNS will now send an SNMP trap whenever the system is booted.
