Description

When sending HTTPS requests to a TransportServer TLS passthrough configuration, resulting HTTP responses may be 404.

Environment

NGINX Ingress Controller

Cause

The hostname from HTTPS requests' SNI value does not match the hostname configured in the TransportServer TLS passthrough configuration, spec.host.

Recommended Actions

Use the hostname specified in the TransportServer TLS passthrough configuration, spec.host, in requests.

Additional Information

A TransportServer TLS passthrough configuration results in NIC/NGINX configuration that contains a mapping predicated on the SNI value from HTTPS requests. When the SNI value, from HTTPS requests, does not match the mapping value in the resulting NIC/NGINX configuration, the requests will not be forwarded to the upstream service specified by the TransportServer TLS passthrough configuration. For example, if the TransportServer TLS configuration spec.host value is test.example.com, the following curl command would not match and will not be forwarded to the corresponding upstream service. The SNI value is <ip_address>, which does not match test.example.com:

curl https://<ip_address>/test -H "Host: test.example.com"

However, the SNI value from the following curl command's resulting request will successfully match test.example.com.  It will be forwarded to the corresponding upstream service:

curl --resolve test.example.com:443:<ip_address> https://<ip_address>/test
