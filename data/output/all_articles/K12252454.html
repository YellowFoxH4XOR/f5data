Description

With 'preserve-strict' set by source-port translation, when a port has been used and cannot preserve source port, this packet will be silently dropped.

Environment

Virtual Server with 'preserve-strict' source-port translation set.

Cause

None

Recommended Actions

This is expected behavior, so please consider this behavior before setting 'preserve-strict', especially for the VS for stateless protocol, e.g. UDP VS.

For example:

ltm virtual /Common/VS_DNS_53 {
    destination /Common/10.0.0.1:53
    ip-protocol udp
    mask 255.255.255.255
    pool /Common/test_pool
    profiles {
        /Common/fastL4_dns { }
    }
    source 0.0.0.0/0
    source-port preserve-strict
    translate-address enabled
    translate-port disabled
    vlans {
        /Common/Vlan_External
    }
    vlans-enabled
}

When a client sends DNS query with src-port A, then the connection on F5 will not be deleted soon since UDP is stateless.
Then if another client sends a query with same src-port in the following 60s (default UDP timeout), the query will be silently dropped.
