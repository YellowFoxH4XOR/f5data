Known Issue

The Traffic Management Microkernel (TMM) may stop responding if the Cavium compression card fails to initialize.

This issue occurs when all of the following conditions are met:

  • The BIG-IP or VIPRION platform contains a Cavium Octeon compression card.
  • The compression card fails to initialize.

The sod process restarts TMM when it stops responding and the issue repeats, causing a restart loop.

Impact

The BIG-IP or VIPRION system fails to process traffic while TMM continuously restarts, and devices configured in a device group will fail over. On VIPRION systems, one or more blades may cycle between available and offline states.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system cycles between available and offline states while the TMM process is in a restart loop.
  • There are multiple tmm core files in the /var/core directory.
  • The system continuously logs error messages in the /var/log/ltm file similar to the following example:

    emerg logger: Re-starting tmm

  • The system continuously logs error messages in the /var/log/ltm file similar to the following example:

    warning sod[5914]: 01140029:4: HA daemon_heartbeat tmm fails action is go offline down links and restart

  • The system continuously logs error messages in the /var/log/tmm files beginning with the following line:

    notice ** SIGABRT **

Resolution

Status

Workaround

To work around this issue, you can power cycle the BIG-IP or VIPRION system to attempt to reinitialize the Cavium compression card.

Impact of workaround: Traffic processing will be interrupted while the system is powered off and powered on.
