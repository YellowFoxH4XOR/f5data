Description

The configuration fails to load with the following diagnostics also seen in /var/log/ltm:

Mon DD HH:MM:SS bigip err mcpd[#]: 01070523:3: No Vlan association for STP Interface Member #.#.
Mon DD HH:MM:SS bigip err tmsh[#]: 01420006:3: Loading configuration process failed.
Mon DD HH:MM:SS bigip emerg load_config_files[#]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- 01070523:3: No Vlan association for STP Interface Member #.#.

or

Mon DD HH:MM:SS bigip err 01070523:3: No Vlan association for STP Interface Member x.x 
Unexpected Error: Loading configuration process failed.

Environment

  • BIG-IP
  • A closer examination of /config/bigip_base.conf file includes the interface in net stp section e. g.: 
    net stp /Common/cist {
        interfaces {
            1.1 {
                external-path-cost 2000
                internal-path-cost 2000
            }
            1.2 {
                external-path-cost 2000
                internal-path-cost 2000
            }
            1.3 {
                external-path-cost 2000
                internal-path-cost 2000
            }
        }
        vlans {
            /Common/external
            /Common/internal
        }
    }
    NOTE: Path values can vary by interface speed.

However, there is no VLAN present in the configuration for one of the interfaces.

Cause

The problem may be caused by one of the following:

  • For BIG-IP VE software defect ID637827: VADC: after re-deploying a single-nic VM with multiple nics, a load can fail due to stp member 1.0
  • Configuration changes prior to the reboot

This error occurs when there is a presence of a STP (Spanning Tree Protocol) interface member configuration on a multi NIC VE. 

Per K61172462: Disabling or enabling the Spanning Tree Protocol for a trunk (11.x - 16.x) "STP is not supported on BIG-IP Virtual Edition (VE).". 

Despite STP being non-functional on VE, TMOS still writes net stp configuration into bigip_base.conf when interfaces are assigned to VLANs. This is because the STP configuration object is automatically created/maintained by mcpd as part of the standard TMOS configuration model — it's a side effect of the VLAN-to-interface association, not something a user explicitly configures. On physical hardware, this is meaningful; on VE, it's vestigial but harmless — unless the interface-to-VLAN relationship becomes inconsistent.

Thus when this happens it can safely be removed to correct the situation.

Recommended Actions

Remove from the STP configuration in file bigip_base.conf the affected interface, then reload the configuration.

  1.  Before editing /config/bigip_base.conf, please create a backup file for this via command " cp /config/bigip_base.conf /config/bigip_base.conf_backup
  2. Using  an editor such as nano/vi/vim open the bigip_base.conf.
  3. Comment out or delete the "net stp /Common/cist configuration:#net stp /Common/cist {
    #    interfaces {
    #        1.1 {
    #            external-path-cost 2000
    #           internal-path-cost 2000
    #        }
    #        1.2 {
    #            external-path-cost 2000
    #            internal-path-cost 2000
    #        }
    #        1.3 {
    #            external-path-cost 2000
    #            internal-path-cost 2000
    #        }
    #    }
    #    vlans {
    #        /Common/external
    #        /Common/internal
    #   }
    #}
  4. Verify the config file you modified using the command:
    tmsh load sys config verify
  5. If no errors , load the configuration
    tmsh load sys config
  6. Save the loaded configuration
    tmsh save sys config

When the configuration is loading you may see the named daemon and others restart. This is expected.
