Unrestricted resource consumption

Unrestricted resource consumption is a frequently overlooked API vulnerability. API requests consume resources such as network, CPU, memory, and storage. When there are no restrictions on the number, content, or type of requests made by users, an attacker can exploit this vulnerability, impacting the APIs' availability and service rate. The following describes some of the techniques attackers can use:

  • Send a high volume of API requests to overload server resources.
  • Send specially crafted requests with large payloads or large file uploads or downloads that can excessively consume server resources.
  • Make targeted requests that lead to increases in operational costs.

The unrestricted resource consumption attacks can result in the following impacts:

  • Denial-of-service (DoS): The application server resources are insufficient to process the requests, resulting in slow application performance, and, in some cases, becoming unresponsive, leading to a denial-of-service (DoS).
  • Data leakage: The high volume of API requests are crafted to quickly enumerate through large datasets. In the case where these datasets are credentials, a brute-force authentication attack occurs and can lead to data leakage or even compromised accounts.
  • Financial loss: Lack of restrictions on paid-per-request API calls, such as SMS or biometrics validation, may lead to significant financial losses.

Unrestricted resource consumption attack scenario

In the following scenario an attacker manipulates the content of the API request, leading to a server response with an excessively large payload, resulting in slow application performance.

  1. An attacker sends a legitimate API request for a single page with 200 items.
  2. The attacker modifies the page size, increasing it from 200 to 200,000. 

This increase causes the application to return an excessive number of items in response to the query, consuming excessive server resources.

Secure your APIs against unrestricted resource consumption attacks with F5 products

To protect your APIs, best practices recommend that you implement limits (CPU, memory, processes, and so on) on how clients can call your APIs and examine and validate client queries to ensure query strings and request that body parameters conform to your application schema, maximum size, and other requirements.

Use BIG-IP APM to mitigate unrestricted resource consumption attacks

BIG-IP APM lets you implement resource and rate limiting security for your APIs in the following ways:

  • Configure limits based on entities such as Client ID, User Group, Client IP address, User Name, multiple values (like User Group and User Name), or a per-flow variable name. This allows you to specifically group API requests by user, type of request, or any identifiable characteristics.
  • For your selected group of users or API requests, enforce rate limiting restrictions by setting Request Quotas, Spike Arrest values, or direct such requests to a different set of server resources.
  • Create allow/deny lists to allow or reject requests identified by key and key values.
  • Apply different weights to API requests based on key and key values.
  • For the quota, spike, or allow/deny lists you created, generate unique and appropriate responses.

Use NGINX products to mitigate unrestricted resource consumption attacks

There are a variety of NGINX products that provide rate limiting security for your APIs in the following ways:

  • Configure the request rate limit based on NGINX parameters, such as client IP address ($binary_remote_addr), requested URI ($request_uri), and so on.
  • Define the size of the shared memory zone that buffers the excess requests beyond the configured request rate limit.
