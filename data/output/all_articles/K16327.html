Known Issue

Description

VIPRION systems may experience Traffic Management Microkernel (TMM) memory leaks if configured to use intra-cluster mirroring with the iRule table command.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP VIPRION hardware platform.
  • The VIPRION system is configured to use intra-cluster mirroring.
  • A virtual server references an iRule, which uses the table command and -subtable parameter.

Impact

General system instability and possible interruption of traffic processing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing memory usage by using the tmsh show sys memory command, the session, session cache, and session master key values continuously increase in size.

    For example:

    # tmsh show sys memory | grep -B2 'session master key'
    session 1.0M 1.0M 1
    session cache 1.3K 1.3K 128
    session master key 528 528 48
  • When viewing memory usage by using the tmsh show sys tmm-info command, the TMM memory Used value continuously increases in size.

    For example:

    # tmsh show sys tmm-info
    ---------------------------
    Sys::TMM: 0.0
    ---------------------------
    Memory (bytes)
    Available 598.0M
    Used 130.3M

Workaround

There is no workaround for this issue. To avoid this issue, F5 recommends not using the -subtable parameter in a configuration that includes intra-cluster mirroring.
