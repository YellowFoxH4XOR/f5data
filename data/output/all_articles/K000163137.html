K000163137: BIG-IP Does Not Forward ICMP Echo Replies with Identifier 0x0000

Type
Support Solution
Published
2026-09-17
Updated
2026-09-17
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000163137

Description

BIG IP system may not forward ICMP echo replies when the ICMP identifier is 0x0000. Although the request reaches the destination and the reply is received, the reply is not forwarded back to the client. Example flow observed in the packet capture (pcap):

  • Client-side Traffic:

ICMP IN s1/tmm2 : Echo (ping) request id=0x0000, seq=1/256, ttl=62 (no response found!)

  • Serve-side Traffic:

ICMP OUT s1/tmm2 : Echo (ping) request id=0x0000, seq=1/256, ttl=61 (reply in 12565)
ICMP IN s1/tmm2 : Echo (ping) reply id=0x0000, seq=1/256, ttl=116 (request in 12562)

Environment

  • BIG IP
  • Virtual server with 'ipother' profile
  • ICMP reply packet with Identifier 0x0000

Cause

This issue is caused by BIG-IP software defect Bug ID2389757: a virtual server with an ipother profile fails to forward ICMP echo replies when the ICMP identifier is '0x0000' .

Answer/Recommended Actions

  1. Configure a dedicated virtual server for ICMP traffic and process it with FastL4 instead of the existing virtual server using the ipother profile. 
    Example configuration:

ltm virtual vip-icmp {
  destination 0.0.0.0:any
  ip-forward
  ip-protocol icmp       <---!!
  mask any
  profiles {
    fastL4 { }
  }
  serverssl-use-sni disabled
  source 0.0.0.0/0
  translate-address disabled
  translate-port disabled
  vlans {
    External
  }
  vlans-enabled
  vs-index 6
}

  1. Alternatively, open a support case and request the Engineering Hotfix that contains the fix for Bug ID2389757.

Additional Information

  • The dedicated ICMP FastL4 virtual server is a workaround for the virtual server using the 'ipother' profile.
  • This is tracked under bug ID2389757
