Known Issue

This is the result of a known issue. In a VIPRION system with multiple blades, if the primary blade is rebooted when any secondary blade has been disabled, the system may fail to load the configuration. In some cases, the license may fail to load, and the command prompt will indicate the system is inoperative. For example:

[root@bigip1:/S1-P:INOPERATIVE] config #

F5 Product Development tracked this issue as CR117242, CR126260, and CR126668, and it was fixed in version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

Workaround

You can avoid this issue by stopping TMM and its related processes on secondary blades before disabling them. To do so, type the following command while logged into the blade you intend to disable:

bigstart stop

When the command prompt returns, disable the secondary blade.

You may be able to work around this issue once it occurs by restarting the primary blade. To do so, type the following command while logged into the primary blade:

bigstart restart
