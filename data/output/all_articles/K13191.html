K13191: The BIG-IP system fails to load a configuration that has the iRule _sys_APM_Citrix assigned to a virtual server after an upgrade

Known Issue

Description

The BIG-IP system fails to load a configuration after an upgrade to BIG-IP 11.0.0 software. This issue occurs when all of the following conditions are met:

  • The BIG-IP system is licensed and provisioned with the BIG-IP APM module or BIG-IP APM Lite (APML) module.
  • The configuration prior to upgrading has the built-in iRule _sys_APM_Citrix assigned to a virtual server.
  • The BIG-IP system is upgraded from BIG-IP 10.2.1 through 10.2.3 to BIG-IP 11.0.0.

Beginning in BIG-IP 10.2.1, the iRule _sys_APM_Citrix is a built-in iRule for all BIG-IP systems licensed with the BIG-IP APM or APML module. This iRule allows end users to connect to Citrix XenApp from a variety of clients using the BIG-IP APM secure proxy mode.

Impact

The BIG-IP system does not load the configuration. As a result, it will not process any traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system boots up with no configuration loaded after the upgrade
  • The Configuration utility displays an error message that appears similar to the following example after the BIG-IP system is booted into the newly-installed version 11.0.0 slot:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem

  • The BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the following example:

    01070341:3: Virtual server /Common/CitrixICASecureProxy references rule _sys_APM_Citrix which does not exist.

Status

F5 Product Development has assigned ID 368210 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Workaround

If you have already attempted to upgrade to BIG-IP 11.0.0, and the BIG-IP system failed to load the configuration, you can remedy the situation by performing either of the following procedures:

  • If the affected BIG-IP system has a version 10.2.x slot available, you should perform the following procedure:

    Modifying the configuration from the version 10.2.x slot and restoring to the version 11.0.0 slot

  • If the affected BIG-IP system does not have a version 10.2.x slot available, you must perform the following procedure:

    Modifying and restoring a version 10.2.x UCS archive on the version 11.0.0 slot

Modifying the configuration from the version 10.2.x slot and restoring to the version 11.0.0 slot

You can restore the configuration from the previous version 10.2.x slot by booting the BIG-IP system back to the version 10.2.x slot, removing the iRule from the affected virtual server, creating a UCS archive, and restoring the UCS archive on the version 11.0.0 slot. To do so, perform the following procedures:

Impact of workaround: The BIG-IP system does not process any traffic while you perform this procedure.

  • Booting the BIG-IP system back to the slot that has the previous version 10.2.x software
  • Removing the iRule from the affected virtual server
  • Obtaining a UCS archive
  • Booting the BIG-IP system to the version 11.0.0 slot
  • Restoring the version 10.2.x configuration using the UCS archive
  • Configuring the Citrix Support in BIG-IP version 11.0.0

Booting the BIG-IP system back to the slot that has the previous version 10.2.x software

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Software Management.
  4. Click Boot Locations.
  5. Click the name of the slot that has the version 10.2.x software, for example, HD1.1.
  6. To boot to the slot selected in Step 3, click Activate.
  7. To confirm booting to the selected slot, click OK.
  8. Wait for the BIG-IP system to complete booting before proceeding to the next section.

Removing the iRule from the affected virtual server

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click Virtual Server List.
  5. Click the Resources Edit link for the affected virtual server.
  6. Click Manage for the iRules section.
  7. Highlight the _sys_APM_Citrix iRule in the Enabled box, and click >> to disassociate it from the virtual server.
  8. To save the changes, click Finished.

Obtaining a UCS archive

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Archives.
  4. Click Archive List.
  5. To initiate the process of creating a UCS archive, click Create.
  6. Type a name for the UCS archive in the File Name box, and select the options for your environment.
  7. To create the UCS archive, click Finished.
  8. Inspect the status for any errors and click OK to return to the Archive List page.
  9. Click the name of the UCS archive and download it to your desktop.

Booting the BIG-IP system to the version 11.0.0 slot

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Software Management.
  4. Click Boot Locations.
  5. Click the name of the slot that has the version 11.0.0 software, for example, HD1.2.
  6. To boot to the slot selected in Step 3, click Activate.
  7. To confirm booting to the selected slot, click OK.
  8. Wait for the BIG-IP system to complete booting before proceeding to the next section.

Restoring the version 10.2.x configuration using the UCS archive

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Archives.
  4. Click Upload.
  5. Click Browse.
  6. Select the UCS archive saved on your desktop from the Obtaining a UCS archive section.
  7. To upload the UCS archive to the BIG-IP system, click Upload.
  8. Click the name of the uploaded UCS archive.
  9. To initiate the process of restoring the UCS archive, click Restore.
  10. Inspect the status for any errors and click OK to return to the Archive List page.

Configuring the Citrix Support in BIG-IP version 11.0.0

  1. Log in to the BIG-IP Configuration utility.
  2. Optional: Click Local Traffic.
  3. Optional: Click Profiles.
  4. Optional: Click Services.
  5. Optional: Click Connectivity.
  6. Optional: Click Connectivity Profile List.
  7. Optional: Click Create to create a new connectivity profile.
  8. Optional: Type a name for the connectivity profile in the Name box.
  9. Optional: Click Finished to save the changes.
  10. Click Local Traffic.
  11. Click Virtual Servers.
  12. Click Virtual Server List.
  13. Click the name of the affected virtual server.
  14. Select a desired connectivity profile from the Connectivity Profile drop-down box.
  15. Enable Citrix Support by checking the Citrix Support check box under the Access Policy section.
  16. To save the changes, click Update.

Modifying and restoring a version 10.2.x UCS archive on the version 11.0.0 slot

Alternatively, you can remove the iRule from the affected virtual server by modifying the UCS archive file taken from the previous version 10.2.x software and restoring the modified UCS archive. To do so, perform the following procedures:

Impact of workaround: The BIG-IP system does not process any traffic while you perform this procedure.

  • Extracting the UCS archive to a temporary directory
  • Modifying the configuration and related files from the UCS archive
  • Repacking the UCS archive
  • Installing the modified UCS archive
  • Configuring the Citrix Support in BIG-IP version 11.0.0

Extracting the UCS archive to a temporary directory

Note: If the BIG-IP system does not have a copy of the UCS archive taken from the previous slot, refer to K175: Transferring files to or from an F5 system on instructions to upload a UCS archive to the BIG-IP system.

  1. Log in to the command line.
  2. Create a temporary directory by typing the following command:

    mkdir /var/tmp/SOL13191

  3. Extract the UCS archive into the temporary directory by typing the following command:

    tar -zxvf <path/to/UCS archive> -C /var/tmp/SOL13191

    For example, type the following command to extract the UCS archive /var/tmp/myconfig.ucs:

    tar -zxvf /var/tmp/myconfig.ucs -C /var/tmp/SOL13191

Modifying the configuration and related files from the UCS archive

  1. Edit the /var/tmp/SOL13191/config/bigip.conf file using a text editor of your choice, for example vi.
  2. Locate the affected virtual server stanza. In the following example, the affected virtual server is CitrixICASecureProxy:

    virtual CitrixICASecureProxy {
    snat automap
    pool my_XenApp_test_wi_pool
    destination 20.20.20.101:https
    ip protocol tcp
    rules _sys_APM_Citrix
    persist my_XenApp_test_wi_persist_profile
    profiles {
    CitrixICA-SecurePolicy {}
    clientssl {
    clientside
    }
    my_XenApp_test_wi_http_profile-compression {}
    my_XenApp_test_wi_http_profile {}
    my_XenApp_test_wi_lan-optimized_tcp_profile {
    serverside
    }
    my_XenApp_test_wi_wan-optimized_tcp_profile {
    clientside
    }
    /Common/websso {}
    }
    }

  3. Delete the rules _sys_APM_Citrix line from the stanza. The modified stanza appears similar to the following example:

    virtual CitrixICASecureProxy {
    snat automap
    pool my_XenApp_test_wi_pool
    destination 20.20.20.101:https
    ip protocol tcp
    persist my_XenApp_test_wi_persist_profile
    profiles {
    CitrixICA-SecurePolicy {}
    clientssl {
    clientside
    }
    my_XenApp_test_wi_http_profile-compression {}
    my_XenApp_test_wi_http_profile {}
    my_XenApp_test_wi_lan-optimized_tcp_profile {
    serverside
    }
    my_XenApp_test_wi_wan-optimized_tcp_profile {
    clientside
    }
    /Common/websso {}
    }
    }

  4. Save the changes and exit the text editor.
  5. Generate the md5 checksum of the modified /var/tmp/SOL13191/config/bigip.conf file by typing the following command:

    md5sum /var/tmp/SOL13191/config/bigip.conf

    In this example, the previous command generated the following output:

    1defe1480dc89a4322b695b6d9284c2a /var/tmp/SOL13191/config/bigip.conf

  6. Edit the /var/tmp/SOL13191/SPEC-Files file using a text editor of your choice, for example vi.
  7. Locate the line that contains the /config/bigip.conf entry. The line appears similar to the following example:

    N /config/bigip.conf 5e5595742b7b57a053016b7c65eeb62b 33188 0 0 7729 1320-20089

  8. Replace the previous md5 checksum with the md5 checksum generated in Step 5. In our example, the modified line will appear as follows:

    N /config/bigip.conf 1defe1480dc89a4322b695b6d9284c2a 33188 0 0 7729 1320-20089

  9. Save the changes and exit the text editor.

Repacking the UCS archive

  1. Change directories to the /var/tmp/SOL13191 directory by typing the following command:

    cd /var/tmp/SOL13191/

  2. Repack the UCS archive by typing the following command:

    tar -zcvf /var/tmp/modified_myconfig.ucs *

Installing the modified UCS archive

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  2. Install the modified UCS archive /var/tmp/modified_myconfig.ucs file by typing the following command:

    load /sys ucs /var/tmp/modified_myconfig.ucs
