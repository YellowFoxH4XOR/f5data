Description

Http/2 connection failure with BIG-IP sending "HTTP/2 GOAWAY, COMPRESSION_ERROR (9)"

Environment

  • BIG-IP terminating http/2 traffic (BIG-IP acting as server with clientssl profile)

Cause

Compressed http/2 header is too large to be accepted by http/2 profile

Answer/Recommended Actions

Increase value of http/2 profile "header-table-size"

Additional Information

BIG-IP sends "HTTP/2 GOAWAY, COMPRESSION_ERROR (9) and is followed by a RESET_STREAM(n) where "n" is the http2.streamid

If no attempt is made at connecting serverside, check that the http/2 (clientside) and http profile (serverside) is big enough to accept the received decompressed http/2 headers.

You can determine the http/2 header values by using wireshark/tshark and the ssl decryption keys. In Wireshark to view the table size use http2.settings.header_table_size if the value is present it will be displayed.

For example, check that the decompressed header size is big enough to hold the decompressed header 

ltm profile http2 /Common/test-http2 {
    app-service none
    defaults-from /Common/http2
    header-table-size 6000
}

Similarly, check that the http profile is able to accept the number of http headers.

ltm profile http /Common/test-http {
    app-service none
    defaults-from /Common/http
    enforcement {
        max-header-count 80
    }
    proxy-type reverse
}

There will likely be other settings in the http/2 and http profiles to check.
