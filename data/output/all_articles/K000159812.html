Description

You want to replace a VELOS chassis and its system controllers after a Return Materials Authorization (RMA).

  • To replace a VELOS system controller, refer to K000133249: Replacing VELOS system controller after a Return Materials Authorization. 
  • To replace an existing blade in a VELOS system that has only a single blade installed, refer to K19494503: Replacing a blade in a VELOS system that has only a single blade installed.
  • To replace an existing blade in a VELOS system that has multiple blades installed, refer to K08485448: Replacing a blade in a VELOS system that has multiple blades installed.

Environment

  • You have physical access to the VELOS system.
  • You have serial console access to the VELOS system.
  • You have administrative access to the VELOS system.

Cause

You experienced issues with the VELOS system and performed a chassis RMA. 

Recommended Actions

Perform the following procedures in the following order to replace a VELOS chassis

  • Preparation
  • Physical replacement (Unmounting and mounting the VELOS chassis)
  • Restore the system controllers software configuration
  • Restore the blades software configuration
  • Optional: Restore all tenants in each partition
  • Optional: Verify basic system health

Physical replacement (Unmounting and mounting the VELOS chassis)

A new replacement VELOS chassis should include 2 new system controllers. You should use these 2 new system controllers with the new chassis. To replace the VELOS chassis, perform the following procedure:

  1. Shutdown the system gracefully. 
    Note: It is not recommended to do a hard shutdown as you will still require the blades when restoring.
    To do so, refer to K19230226: Turn off or turn on a VELOS system using the AOM Command Menu.
  2. Physically unmount the VELOS chassis and replace it with the new one. For detailed steps and images, refer to the Platform Installation manual.
  3. Verify the following:
    1. 2 new system controllers are seated securely.
    2. Blades are not inserted.
    3. All electrical connections are as per the documentation captured in the Preparation section.

Restore the system controllers software configuration

The VELOS chassis should be powered on with 2 new system controllers seated securely with no blades inserted at this point. Perform the following procedure to restore software configuration on the system controllers:

  1. Power on the VELOS system.
  2. Monitor the system controller readiness. Refer to Verify basic system controller readiness.
  3. Perform initial setup of the system controllers.
    1. Connect to the serial console of the VELOS system. K000139067: Connecting to the serial console on the rSeries and VELOS.
    2. Set up the initial networking for SSH connection.
      Note: If there is the potential for conflict with external devices that fall within this range that need to communicate with F5OS, then there are options to change the configured network-range-type to one of sixteen different blocks within the RFC1918 address space. Changing this will require a complete chassis power-cycle which may take 90 minutes; rebooting is not sufficient. 
      For more information on this step, refer to Initial setup of VELOS system controllers on Clouddocs.
    3. If you made changes in the internal chassis network in step 3b, perform a full chassis power cycle. Refer to K19230226: Turn off or turn on a VELOS system using the AOM Command Menu.
      Note: A complete chassis power-cycle which may take 90 minutes.
  4. Upgrade F5OS-C to the same version as the original one. Refer to VELOS Systems: Software Installation and Upgrade.
  5. Verify required partition images are present.
    1. Login to the system controller 
    2. Go to SOFTWARE MANAGEMENT > Partition Images.
  6. Set the primary key using the information prepared previously in the Preparation section and verify its value.
    Use the Set the primary key procedure in K50135154: Back up and restore the F5OS-C configuration on a VELOS system.
  7. Restore the system controller configuration.
    1. Import the system controller configuration backup file prepared previously in the Preparation section.
      Use the Import a backup file using the webUI or Import a backup file from the command line procedures in K50135154: Back up and restore the F5OS-C configuration on a VELOS system.
    2. Restore the system controller from the imported files.
      Use the Restore your VELOS chassis or partition configuration data procedure in K50135154: Back up and restore the F5OS-C configuration on a VELOS system.
  8. Reactivate the license. For more information, refer to Licensing the VELOS Chassis on Clouddocs.
  9. Enable the partitions (if disabled). Login to the webUI of the system controllers, go to CHASSIS PARTITIONS.
  10. Restore all partition configuration.
    1. Import all partition configuration backup files prepared previously in the Preparation section.
      Use the Import a backup file using the webUI or Import a backup file from the command line procedures in K50135154: Back up and restore the F5OS-C configuration on a VELOS system.
    2. Restore all partition configuration from the imported files.
      Use the Restore your VELOS chassis or partition configuration data procedure in K50135154: Back up and restore the F5OS-C configuration on a VELOS system.
  11. Login into each partition and perform basic checks on the configuration. 

Restore the blades software configuration

  1. Login to the active system controller as root.
  2. Insert the blade(s) one by one into their original slots and wait for all of them to start and ready.
  3. Monitor the status of the blades as you insert them. Refer to Verify basic blade readiness and network connectivity.
  4. Optional but recommended: Copy the BIG-IP tenant qcow bundle images prepared previously in the Preparation section to each partition that needs it.
    To do so, login to the webUI of the partition and go to TENANT MANAGEMENT > Tenant Images.

The blades contain the tenant virtual disks. If all your blades are functional, restoration is complete and you can proceed to deploy and test the tenants from each partition on the webUI at TENANT MANAGEMENT > Tenant Deployments.

Optional: Restore all tenants in each partition

The blades contain the tenant virtual disks. If all your blades are functional, this step is not needed. Restoration is complete and you can proceed to deploy and test the tenants from each partition on the webUI at TENANT MANAGEMENT > Tenant Deployments.

You may need to perform this procedure to restore tenants in each partition under any of the following conditions:

  • There are issues with one or more blades such that one or more tenants are unable to start or start with no configuration.
  • On the partition webUI, TENANT MANAGEMENT > Tenant Deployments, there are 1 or more tenants missing.

Depending on your system, you may need to restore the tenants from UCS archives. To do so, perform the following at each partition as appropriate:

  1. Login to the partition webUI.
    1. Verify the required images are available at TENANT MANAGEMENT > Tenant Images.
    2. Verify the tenants exists at TENANT MANAGEMENT > Tenant Deployments. If not, you may have to create them from scratch using the QKview files generated previously.
    3. Select the tenants and select Deploy.
  2. Login to the BIG-IP tenant when it starts.
    1. Restore the BIG-IP tenant from the UCS archive prepared previously in the Preparation section. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

Depending on the state of your restore, when you suspect hardware issues on a blade and have additional blades, use the following as needed:

  • K19494503: Replacing a blade in a VELOS system that has only a single blade installed.
  • K08485448: Replacing a blade in a VELOS system that has multiple blades installed.

Useful procedures

Verify basic system controller readiness

Perform the following procedure to verify system controller readiness:

  1. Log into the VELOS system controller CLI as the root user.
  2. Monitor the status by
    1. bash: Enter the following command:
      tail -f /var/log/openshift.log
    2. confd: Enter the following commands:

      show cluster | repeat

Verify basic blade readiness and network connectivity

Perform the following procedure to verify a blade's readiness and network connectivity:

Impact of procedure: Performing the procedure should have no negative impact on the system.

On the system controller:

  1. Log into the VELOS system controller CLI as the chassis admin user.
  2. Wait for the new blade to be ready. You can monitor the status of the blade by 
    1. bash: Enter the following command:
      tail -f /var/log/openshift.log
    2. confd: Enter the following command:

      show cluster | repeat

      When the blade is ready, the command will report the cluster-status summary-status as Openshift cluster is healthy, and all controllers and blades are ready.

On the partition:

  1. Log into the partition CLI as the partition admin user.
  2. Wait for the new blade to be the replica in the partition that it is assigned. You can monitor this status by entering the following command:

    show system redundancy

    When the blade is ready as the replica, the command should report the STATUS of the blade as replica.

  3. Verify that the portgroup modes are properly set and the optic-state is showing QUALIFIED. You can verify this by entering the following command:

    show portgroups

  4. Ensure that the needed interface(s) is present and up. You can verify by entering the following command:

    show interfaces

    Note the state oper-status value.
    This will display all interface information in the partition. Alternatively, if you want to verify only a specific state, you can enter the following command syntax:

    show interfaces interface state oper-status

  5. If you have configured LACP LAG for the partition, you should ensure that the LACP LAG is up. You can verify the status entering following command syntax:

    show interfaces interface <LAG name>

    Alternatively, you can enter the command show lacp and verify that there are active members listed in the output.

Verify basic system health

Perform the following procedure to verify system health:

  1. Log into the VELOS system controller CLI as the root user.
  2. Generate and review a system health report using the confd's show system health command:
    1. On bash, generate a system health report by entering the following command:
      Syntax: docker exec vcc-confd /confd/scripts/f5_confd_run_cmd show system health > <health_report_filename>
      docker exec vcc-confd /confd/scripts/f5_confd_run_cmd show system health > health_report
    2. Identify any unhealthy components by entering the following commands:
      Syntax: grep <search string> <health_report_filename>
      grep -B2 "health unhealthy" health_report
      grep -B2 emergency health_report
    3. Change your search string depending on the level of detail you require for further troubleshooting if necessary.
  3. For a more detailed review, review the system health on iHealth.
    1. Generate Qkview files on the system controller and each partition and upload to iHealth K02521182: Generating diagnostic data for the VELOS system using the qkview utility.
