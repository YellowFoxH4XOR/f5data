Description

When you import an external data group file to the BIG-IP, the system stores the file in the system filestore with a designated "cache-path".

If the file in cache-path is missing for any reason, for example, due to accidental deletion by user, the missing file will not be detected until a mcpd forceload is performed.

Example

Relevant entries of an external datagroup in /config/bigip.conf :

ltm data-group external /Common/ext_dg_string {
    external-file-name /Common/ext_dg_string_file
    type string
}

sys file data-group /Common/ext_dg_string_file {
    cache-path /config/filestore/files_d/Common_d/data_group_d/:Common:ext_dg_string_file_66903_1
    revision 1
    source-path file:/shared/tmp/ext_dg_string.txt
    type string
}

Content of /config/filestore/files_d/Common_d/data_group_d/ directory:

# ls /config/filestore/files_d/Common_d/data_group_d/
:Common:ext_dg_string_file_66903_1

The following command deletes the cache-path, so that the behavior of system can be observed.

Important: For illustration purposes only. Do not perform on your system.
# rm /config/filestore/files_d/Common_d/data_group_d/:Common:ext_dg_string_file_66903_1

Effects of missing cache-path for an external datagroup

# tmsh load /sys config verify
Validating system configuration...
   - snip -
Validating configuration...
  /config/bigip_base.conf
  /config/bigip_user.conf
  /config/bigip.conf

The "load /sys config verify" tmsh command does not report the missing cache-path.


# tmsh load /sys config
Loading system configuration...
   - snip -
Loading configuration...
  /config/bigip_base.conf
  /config/bigip_user.conf
  /config/bigip.conf

"load sys config" also works with no issue.


# reboot
Even after a system reboot, and the configuration still loads, and no issue is reported.

When missing cache-path for an external datagroup will be discovered

If you perform an mcpd forceload by following K13030: Forcing the mcpd process to reload the BIG-IP configuration, the configuration will fail to load.

# touch /service/mcpd/forceload
# reboot

Example messages in /var/log/ltm:

notice boot_marker[2279]: ---===[ HD1.1 - BIG-IP 17.1.1.3 Build 0.0.5 ]===---
err mcpd[7309]: 01070712:3: Caught configuration exception (0), Failed: name (/Common/ext_dg_string) Cache path (/config/filestore/files_d/Common_d/data_group_d/:Common:ext_dg_string_file_66903_1) does not exist and there is no copy in trash-bin to restore from..
emerg load_config_files[9715]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01070712:3: Failed: name (/Common/ext_dg_string) Cache path (/config/filestore/files_d/Common_d/data_group_d/:Common:ext_dg_string_file_66903_1) does not exist and there is no copy in trash-bin to restore from.

The BIG-IP will be in INOPERATIVE state and will not pass traffic. Since the BIG-IP no longer has the external datagroup file, you will need to recover it from an external backup source.

Environment

  • BIG-IP
  • External datagroup
  • Missing cache path for external datagroup

Cause

None

Recommended Actions

You can run the following command to check if any cache-path is missing before performing any mcpd forceload. If there is a missing cache-path, do not proceed with mcpd forceload.

# ls -1 $(grep -P 'cache-path\s+\S+' -o -h /config/*.conf /config/partitions/*/*.conf 2>/dev/null | cut -d' ' -f2)

The command shows the cache-path of various objects in the BIG-IP configuration. If a cache-path is missing, an error will be shown specific to that cache-path.

For example:

# ls -1 $(grep -P 'cache-path\s+\S+' -o -h /config/*.conf /config/partitions/*/*.conf 2>/dev/null | cut -d' ' -f2)
ls: cannot access /config/filestore/files_d/Common_d/data_group_d/:Common:ext_dg_string_file_66903_1: No such file or directory
/config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca-bundle.crt_59581_1
/config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca.crt_59577_1
/config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtdi.crt_59573_1
/config/filestore/files_d/Common_d/trust_certificate_key_d/:Common:dtca.key_59579_1
/config/filestore/files_d/Common_d/trust_certificate_key_d/:Common:dtdi.key_59575_1

Above shows that /config/filestore/files_d/Common_d/data_group_d/:Common:ext_dg_string_file_66903_1 is missing. Other files are OK.

If no error is displayed, no file is missing.
