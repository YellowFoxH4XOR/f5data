Known Issue

The BIG-IP system may incorrectly associate a newly-imported Secure Sockets Layer (SSL) certificate/key pair to all SSL profiles of the same type. This issue occurs when all of the following conditions are met:

  • Multiple SSL profiles of the same type (Client SSL or Server SSL) are configured.
  • One of the SSL certificate/key pairs is renewed or updated.

SSL profiles of a different type are unaffected even if they are applied to an affected virtual server. For example, if a virtual server references both a Client SSL profile and a Server SSL profile, and the SSL certificate/key pair for the Client SSL profile is updated, the Server SSL profile is unaffected.

Impact

The BIG-IP system presents an incorrect certificate, which may result in client error messages or connection failure.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H383280 and H383280-1 on the Diagnostics > Identified > Low screen.
  • All SSL profiles of the same type use the newly-imported certificate/key pair.

    For example:

    • The virtual server for which the certificate was updated presents the expected certificate.
    • All other virtual servers using the same type of profile (Client SSL or Server SSL) present an incorrect certificate (the newly-imported certificate).
  • Client browsers may display certificate mismatch errors.
  • Non-interactive applications may fail to establish SSL connections due to the certificate mismatch.
  • The Configuration utility and the tmsh utility both display the correct Certificate and Key configuration.

    For example, the tmsh list /ltm profile client-ssl command, which lists all Client SSL profiles, shows that the expected SSL certificate is assigned to each profile, even though the associated virtual servers are all presenting the newly imported certificate:

    ltm profile client-ssl red-clientssl {
    app-service none
    cert red.crt
    defaults-from clientssl
    key red.key
    }
    ltm profile client-ssl yellow-clientssl {
    app-service none
    cert yellow.crt
    defaults-from clientssl
    key yellow.key
    }
    ltm profile client-ssl blue-clientssl {
    app-service none
    cert blue.crt
    defaults-from clientssl
    key blue.key
    }

Workaround

For a BIG-IP system that has already encountered this issue, you can recover the BIG-IP system by reloading the configuration or updating the SSL profiles. To do so, perform any of the following procedures:

  • Reloading the configuration
  • Updating SSL profiles

Reloading the configuration

Impact of workaround: Traffic processing is briefly interrupted while the configuration reloads.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Reload the BIG-IP configuration by typing the following command:

    load /sys config

Updating SSL profiles

Impact of Workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client or Server, depending on the affected SSL profiles.
  3. Click the name of the affected SSL profile.
  4. Click Update.
  5. Repeat steps 2 through 4 for the remaining affected SSL profiles.
