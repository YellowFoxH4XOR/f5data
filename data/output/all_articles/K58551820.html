Known Issue

The BIG-IP system may experience high CPU utilization when a HTTP/2 profile is applied to a virtual server.

This issue occurs when all of the following conditions are met:

  • An HTTP/2 profile is configured on a virtual server.
  • A source address affinity persistence profile is applied on the same virtual server.

Impact

The Traffic Management Microkernel (TMM) process experiences high CPU utilization levels and may eventually restart. If the BIG-IP system is part of a redundant configuration, traffic fails over to the standby BIG-IP system while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The top command shows TMM instance(s) using a high CPU percentage.
For example, output shows tmm instances utilizing greater than 300% CPU resource:

PID USER      PR  NI  VIRT  RES  SHR S %CPU %MEM    TIME+  COMMAND
<PID> root       1 -19 22.3g 431m 410m S 331.7  0.9 147019:02 tmm.0
<PID> root       1 -19 22.3g 431m 410m R 323.0  0.9 147893:10 tmm.1
  • The sod process restarts TMM when it reaches excessively high CPU utilization levels and fails to update its daemon heartbeat. When this symptom occurs, messages similar to the following example are logged to the /var/log/ltm file:

    notice sod[1234]: 01140029:5: HA daemon_heartbeat tmm fails action is go offline down links and restart.

Resolution

Workaround

To work around this issue, you can enable Match Across Services in the Source Address Affinity persistence profile. To do so, perform the following procedure:

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Persistence.
  3. Click the name of Source Address Affinity persistence profile used in the affected virtual server.
  4. Select the Match Across Services check box.
  5. Click Update.
