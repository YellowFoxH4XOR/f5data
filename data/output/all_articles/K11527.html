K11527: Forest trust cannot be established if the domain security policy requires the NTLMSSP_NEGOTIATE_SEAL or NTLMSSP_NEGOTIATE_SIGN flags to be set

Known Issue

This is the result of a known issue. If a Windows domain security policy requires clients to set the NTLMSSP_NEGOTIATE_SEAL flag or the NTLMSSP_NEGOTIATE_SIGN flag in the NTLM negotiate message, the ARX system cannot establish forest trust with the domain controllers. Additionally, when this issue occurs, the ARX system incorrectly reports that the domain controllers are offline.

F5 Product Development tracked this issue as ID 37610 and it was fixed in ARX 5.2.0. For information about upgrading, refer to the ARX release notes.

Additionally, this issue was fixed in the hotfix release ARX 5.1.7 HF1 (build-12059). Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this article number and the associated ID number.

Workaround

You can work around this issue by removing the existing trust configuration on the ARX system, and using the kerberos auto-realm-traversal command to enable forest-to-forest trust with selective authentication.

Note: For more information about the kerberos auto-realm-traversal command, refer to the ARX CLI Reference Guide.
