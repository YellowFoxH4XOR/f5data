Description

There was a feature change starting in Big-IP version 15.x which added a new policy option called "does not exist"(shown below). This new option causes a change in the way rules are matched when trying to look at HTTP header values.
  
V15 and above policy options

In versions prior to 15.x the "does not contain" could be used to trigger a rule when the header was not present, however now you have to use the newer "does not exist" option if you want to match a rule where you are looking for an HTTP header to be present or missing in a request.
 

 

V14 and lower policy options



Environment

  • Big-IP LTM Policy
  • Big-IP LTM v15

Cause

Feature enhancements were added starting in version 15.x that provided better control over the condition matching properties for the policy.
 

Recommended Actions

If you were previously using the "does not contain" option in versions prior to v15.x to determine if a header was present or not, now use the "does not exist" option when running version 15.x and above.
