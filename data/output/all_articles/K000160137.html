Description

A BIG-IP LTM virtual server configured with round robin load balancing is distributing traffic unevenly across pool members. Despite the round robin configuration, the majority of traffic is being directed to a subset of servers rather than being evenly distributed. Analysis reveals that LTM traffic policies are configured to forward requests matching specific URI patterns directly to designated nodes, bypassing the pool's load balancing method entirely.

Environment

  • BIG-IP LTM
  • Virtual server configured with round robin (or any other) load balancing method
  • LTM traffic policies configured with forwarding actions that select specific nodes
  • Policies matching HTTP URI patterns or other Layer 7 criteria
  • Pool with multiple members

Cause

LTM traffic policies that include forwarding actions to specific nodes take precedence over the pool's configured load balancing method. When a policy rule matches a request and forwards it to a designated node, the pool's load balancing algorithm (such as round robin) is bypassed for that request. This results in uneven traffic distribution when policies direct significant portions of traffic to specific pool members.

Answer/Recommended Actions

To restore even load balancing across all pool members:

  1. Review all LTM traffic policies associated with the affected virtual server to identify policies with node-specific forwarding actions.
  2. Examine policy rules for actions similar to:

    forward select node <IP_address>

  3. Determine if the URI-based or other Layer 7 routing provided by these policies is still required for your application architecture.
  4. If even load balancing is desired:
    • Remove the traffic policies that forward requests to specific nodes, OR
    • Modify the policies to forward to the pool instead of individual nodes
  5. Before removing or modifying policies, verify that all pool members can handle the full range of traffic previously directed by the policies. Ensure application functionality is maintained across all nodes.
  6. After making configuration changes, monitor traffic distribution using pool member statistics to confirm that the load balancing method is functioning as expected.
  7. Clear any existing connection statistics before testing to get accurate measurements of the new traffic distribution.

Additional Information

  • Traffic policies are evaluated before load balancing decisions are made. When a policy explicitly selects a node, the pool's load balancing method is not applied to that connection.
  • This behavior is by design and allows for advanced traffic steering based on Layer 7 content.
  • If you need both content-based routing and load balancing, consider using multiple pools with different members and having policies forward to pools rather than individual nodes.
  • The strategy first-match setting in policies means that once a rule matches and takes action, subsequent rules and the pool's load balancing method are not evaluated for that request.
