K13906: Enabling the search_onload internal parameter

Applies to

Source

Topic

You should consider using this procedure under the following conditions:

  • CSRF protection is enabled in the BIG-IP ASM security policy.
  • Web resources protected by the BIG-IP ASM security policy include a JavaScript onload function in the body element, similar to the following example:

    <body onload="Javascript:submitForm();">

  • Client requests for the previous resource come from Internet Explorer.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Administrative access to BIG-IP ASM
  • For versions prior to 11.2.1, the search_onload parameter is only available if you have installed one of the following hotfix versions or later:

    BIG-IP 11.2.0 HF2
    BIG-IP 11.1.0 HF5

Description

The body onload function in a requested web resource may interfere with the CSRF protection injection process, resulting in requests that do not contain the required CSRT token generating CSRF attack detected violations. When the search_onload internal parameter is enabled, BIG-IP ASM will search the body of the resource returned by the origin web server for an onload function, and ensure that the CSRT token injection occurs correctly before the function is executed.

Procedures

Enable the search_onload internal parameter

Impact of procedure: You must restart BIG-IP ASM services, which causes a brief service interruption.

  1. Log in to the BIG-IP ASM command line.
  2. Enable the search_onload parameter by entering the following command:

    /usr/share/ts/bin/add_del_internal add search_onload 1

  3. Restart the BIG-IP ASM service by entering the following command:

    bigstart restart asm
