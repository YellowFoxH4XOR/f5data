Known Issue

The Configuration utility may intermittently disallow changing the rule order of a BIG-IP AFM firewall policy.

This issue occurs when the following condition is met:

  • You attempt to reorder a firewall rule set by using the Configuration utility.

Impact

Attempts to reorder firewall rule sets will intermittently fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H540615 on the Diagnostics > Identified > Low screen.
  • You cannot reorder firewall rules by using the Configuration utility.
  • Error messages similar to the following example appear in the /var/log/ltm file:

    err mcpd[<pid>]: 010715cd:3: Cannot use order 51 on firewall rule (<rule_a>). Already used by <rule_b> in (/Common/<firewall_policy>).

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to reorder the rules. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Using the tmsh utility to reorder a firewall policy rule list

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Place a rule before another rule by using the following command syntax:

    modify security firewall policy <policy_name> rules modify { <rule_a> { place-before <rule_b>}}

    In this command syntax, <policy_name> is the name of the firewall policy and <rule_a> is the name of the rule within the policy that you want to reorder before the other rule (<rule_b>).

    For example:

    modify security firewall policy test_policy rules modify { test_rule_2 { place-before test_rule_1}}
