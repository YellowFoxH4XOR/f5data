Known Issue

This is the result of a known issue. If an Internet Explorer 8 (IE8) user attempts to connect to a Web Application Tunnel Favorite and a new browser tab is opened, they may fail to connect. IE8 typically opens a new process for each new tab. This behavior is dependent on several factors, including the amount of available RAM, the number of Internet Explorer sessions, and the number of tabs opened. The new process may not be associated with the original process. As a result, traffic is not tunneled and the connection may fail.

F5 Product Development is tracking this issue as ID 265656 (formerly CR136120).

Workaround

A registry edit on the client machine can force IE8 to use one process for all tabs. By changing the TabProcGrowth value to 1, all tabs will run as a single process.

Note: For instructions about editing the registry, refer to the following Microsoft blog entry:
 
Opening a New Tab may launch a New Process with Internet Explorer 8.0 

This link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Important: You must confirm that the change will not negatively impact users prior to editing the registry. Use extreme caution any time you edit the registry.

Alternatively, you can create a custom dynamic App Tunnel Favorite that uses iexplore.exe as the application instead of using a Web Application Tunnel Favorite.

Note: For more information about configuring a custom dynamic App Tunnel Favorite, refer to the Configuring Application Access section of the FirePass Controller Administrator Guide.
