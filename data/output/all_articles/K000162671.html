K000162671: serverssl-use-sni with OneConnect may mismatch client and server-side SNI

Type
Support Solution
Published
2026-07-29
Updated
2026-07-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162671

Description

When using serverssl-use-sni together with OneConnect, requests may be routed to server-side connections which have Server Name Indication (SNI) that does not match the one used on the client side.


This may cause errors if servers require SNI to match the HTTP Host header, or route traffic based on SNI.

 

Environment

• serverssl-use-sni enabled so the server-side SNI would follow the client-side SNI.

• OneConnect was enabled on the virtual server.

 

Cause

OneConnect routes requests to existing server-side connections. OneConnect is not aware of SNI and cannot match requests based on the SNI used on the client and server side, therefore it may cause a mismatch.


 

Answer/Recommended Actions

• Remove or disable OneConnect on the affected virtual server when the server-side SNI must match the client-side SNI for every request.
