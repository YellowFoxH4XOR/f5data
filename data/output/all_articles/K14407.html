Issue

Old Behavior

In versions prior to BIG-IP 11.4.0, the BIG-IP system does not, by default, identify which health monitor caused a change in the availability of an object. Typically, this behavior is not an issue when only one health monitor is assigned to a pool, pool member, or node. However, this behavior may be an issue in configurations in which multiple health monitors are in use, and you want to know which health monitor caused a change in the availability of an object.

In earlier versions, additional steps were required to determine which health monitor triggered a change in the availability of a node or pool member.

New Behavior

Beginning in BIG-IP 11.4.0, the BIG-IP system identifies which health monitor caused a change in the availability of an object.

The BIG-IP system now logs specific details regarding which health monitor caused a change in availability of an object. You can find this information in the /var/log/ltm file. The following example output displays that the http monitor is identified as the health monitor that caused a change in the availability of the p1 pool member:

Pool /Common/p1 member /Common/10.10.10.10:80 monitor status down. [ /Common/http: down, /Common/tcp: up ]  [ was up for 0hr:2mins:37sec ]

F5 Product Development tracked this change as ID 227271.
