K39313135: New FQDN pool nodes not resolving

Type
Support Solution
Published
2023-08-10
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.4, 13.1.0
Source
https://my.f5.com/manage/s/article/K39313135

Description

  • New FQDN pool members don't populate IPs even though the DNS servers are accessible

Environment

  • The pool contains static pool members
  • DNS name servers are configured and available
  • The FQDN resolves correctly from the LTM
  • IP doesn't populate for the FQDN node

Cause

The FQDN node IP addresses overlap with the IP addresses for the static pool members.

 Recommended Actions

Implement one of the following workarounds:

  • Use the FQDN pool member for IPs that don't already exists statically in the pool
  • Convert all pool members to FQDN nodes
  • Switch to all static IP pool members

Additional Information

  • Confirm the correct DNS server is configured.
WebUI: System >> Configuration >> Device >> DNS > DNS Lookup Server list
CLI: tmsh list sys dns name-servers
  • Confirm the DNS server returns the correct IP, without error.
Command: dig @<DNS server IP>  <FQDN-here>
Example: dig @1.1.1.1 www.example.com

;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 25929       <<<<<< No Errors.
;; flags: qr aa rd ra; QUERY: 1, ANSWER: 2, AUTHORITY: 0, ADDITIONAL: 1

;; QUESTION SECTION:
;www.example.com.                 IN      A

;; ANSWER SECTION:
www.example.com. 3600 IN A 10.10.10.1 << Correct IP, but overlaps with static pool member.
  • Confirm the IP doesn't populate
tmsh show ltm pool <pool name here> pool members
  --------------------------------------------------------------
  | Ltm::Pool Member: <fully-qualified-domain-name-here>:80
  --------------------------------------------------------------
  | Status
  |   Availability   : available
  |   State          : enabled
  |   Reason         : The DNS server(s) are available
  |   Monitor Status : fqdn-up << Monitor status is up.
  |   Session Status : enabled
  |   Pool Name      : <pool name here>
  |   IP Address     : :: <<  No IP address is served.
  • Check the IPs of the static IPs already in the pool.
WebUI: System >> Local Traffic >> Pools >> <pool name> >> members tab
Command line: tmsh list ltm pool <pool name>

ltm pool /Common/pool-name-here-80 {
    members {
        /Common/10.10.10.1:80 {
            address 10.10.10.1
        }
        /Common/www.example.com:80 {
            fqdn {
                << No IP address is served.
                autopopulate enabled
                name www.example.com
            }
        }
    }
    monitor /Common/monitor_80_http
}
  • Compare the IP results for the Static pool members with the FQDN pool members.
