Known Issue

On some BIG-IP systems, resetting the AOM subsystem may cause previously-disabled management interfaces to be re-enabled.

This issue occurs when all of the following conditions are met:

  • You are running a BIG-IP platform with an Always-On Management system (AOM) on one of the following platforms:
    • 1600, 3600, 3900, 6900, 8900, 8950, 11000, 11050
  • You have disabled the management interface using the TMOS Shell (tmsh).
  • You have taken one of the following actions on the AOM subsystem:
    • Reset it on a BIG-IP 11.x system

      or

    • Reset or rebooted it on a BIG-IP 10.x system

Impact

The management interface may inadvertently become accessible.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A previously-disabled management interface is enabled after an AOM reset.
  • The BIG-IP configuration continues to show the management interface as disabled. You can verify this by typing the following tmsh command:

    list net interface mgmt

  • Byte counts continue to increment for the management interface. You can verify this by typing the following tmsh command:

    show net interface mgmt

Workaround

To work around this issue, you must manually re-enabled then re-disable the management interface. To do so, perform the following procedure:

Impact of workaround: This workaround requires you to manually intervene every time you reset the AOM subsystem.

Disabling the management interface after an AOM reset

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To re-enable and disable the management interface, type the following commands:

    modify net interface mgmt enabled
    modify net interface mgmt disabled

  3. Save the change by typing the following command:

    BIG-IP 10.1.0 and later:

    save /sys config
