Known Issue

The BIG-IP system may fail to update the SSL certificate/key pair after a configuration synchronization (ConfigSync) operation.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured as part of a high availability (HA) system.
  • Your BIG-IP system is configured with manual sync enabled.
  • You perform a ConfigSync operation in the following sequence if your BIG-IP platform uses FIPS hardware:
    • Modify Client SSL profile to a different certificate/key pair.
    • Delete the original certificate/key pair.
    • Create a new certificate/key with the same name as the original.
    • Re-associate the new certificate/key with the original Client SSL profile.
    • Perform a ConfigSync operation to sync the certificate/key pair with HA peers.
  • You perform a ConfigSync operation in the following sequence if your BIG-IP platform does not use FIPS hardware:
    • Modify the Client SSL profile to a different certificate/key pair.
    • Create a new certificate/key with a different name from the original one.
    • Re-associate the new certificate/key with the original Client SSL profile.
    • Perform a ConfigSync operation to sync the certificate/key pair with HA peers.

Impact

  • Your new certificate/key pair is not synced, and your new and old key remain in the FIPS hardware if your BIG-IP system uses FIPS.
  • If your BIG-IP system does not have FIPS hardware, the new certificate/key is not synced, and the same Client SSL profile uses a different certificate/key pair on different systems.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You may notice an abandoned FIPS key after the ConfigSync operation if your BIG-IP system uses FIPS hardware.
  • In the case of the BIG-IP system, the same Client SSL profile uses two different certificate/key pairs on different systems.

Workaround

To work around this issue, you can perform an extra ConfigSync operation before you re-associate the new certificate/key to your Client SSL profile or you can perform one of the following procedures:

BIG-IP system with FIPS hardware

You can delete the FIPS key by handle on the peer systems. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Find the key_handle_identifier by typing the following command:

    list /sys crypto key

  3. Remove the FIPS key by typing the following command:

    delete /sys crypto fips by-handle <key_handle_identifier>

  4. Save the configuration by typing the following command:

    save /sys config

BIG-IP system without FIPS hardware

You can perform a second ConfigSync operation using the Overwrite Configuration option. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure overwrites the configuration on the target systems.

  1. Log in to the Configuration utility.
  2. Navigate to Device Management > Overview.
  3. Select the device group that you want to sync in the Device Groups list.
  4. Select the device from the Devices list with the configuration you want to push to the group.
  5. Select Sync Device to Group radio button.
  6. Check the box next to Overwrite Configuration.
  7. Click the Sync button to run the ConfigSync operation.

If you also deleted your original certificate/key pair, you should go into the peer systems and manually delete those certificate/key files that were not deleted during your first ConfigSync operation.  To do so, perform the following procedure:

Impact of workaround: Performing the following procedure permanently deletes unused certificate and key files.

  1. Log in to the BIG-IP command line of the device with the certificate/key files you want to delete.
  2. Change the working directory to the certificate directory by typing the following command:

    cd /config/filestore/files_d/Common_d/certificate_d/

  3. Delete the certificate file using the following syntax:

    rm <certificate file name>

  4. Change the working directory to the key directory by typing the following command:

    cd /config/filestore/files_d/Common_d/certificate_key_d/

  5. Delete the key file using the following syntax:

    rm <key file name>
