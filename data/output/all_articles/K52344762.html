Topic

Beginning in the following BIG-IP versions in their respective software branches, BIG-IP Virtual Edition (VE) preserves the order of Single Root I/O Virtualization (SR-IOV) network adapters when the vAPP option is enabled on VMware:

  • BIG-IP 17.x.x: 17.0.0
  • BIG-IP 16.1.x: 16.1.2.2
  • BIG-IP 15.1.x: 15.1.5.1
  • BIG-IP 14.1.x: 14.1.4.6

Description

Old Behavior

BIG-IP VE does not preserve the order of SR-IOV network adapters when you add them in VMware.

SR-IOV network adapters are initialized before the other Ethernet interfaces per the HAL architecture on the VMware kernel. In the NIC ordering on the BIG-IP system, SR-IOV network adapters take precedence over the other network adapters. You can view the NIC ordering by entering the following command on the BIG-IP system:

cat /etc/ethmap 

To display the list of network interfaces on the BIG-IP system, enter the following command:

tmsh show net interface all-properties

Example

For example, the following table illustrates a list of network adapters of a virtual machine on VMWare in the following order: 

Network adapterNetwork adapter typeMAC addressVLAN
1VMXNET300:50:56:b8:00:d3Management
2VMXNET300:50:56:b8:af:6evlan191
3VMXNET300:50:56:b8:1a:1avlan191
4SR-IOV passthrough00:50:56:b8:62:85vlan190

On BIG-IP VE, when you list the network interfaces, the output appears similar to the following example:

# tmsh show net interface all-properties
----------------------------------------------------------------------------------------------------
Net::Interface
Name     Status           Mac-Addr                    [...]      Media       [...]
----------------------------------------------------------------------------------------------------
1.1      uninit           00:50:56:b8:00:d3           [...]      none  
1.2      uninit           00:50:56:b8:af:6e           [...]      none  
1.3      uninit           00:50:56:b8:1a:1a           [...]      none  
mgmt         up           00:50:56:b8:62:85           [...]      100TX-FD 

The management interface on the BIG-IP system takes the MAC address of the SR-IOV adapter instead of the VMXNET3 adapters.

New Behavior

In the new behavior, when you enable the vAPP option on VMware, when you add SR-IOV network adapters from the VMware hypervisor, they are added at the end of the other network adapters, such as VMXNET adapters. The new NIC ordering is consistent with the hypervisor ordering and you can view it by entering the following command:

vmtoolsd --cmd "info-get guestinfo.ovfEnv"

When the vApp option is not enabled on VMware, the system uses the old behavior and the vmtoolsd command returns No value found.

The management interface on the BIG-IP system takes the MAC address of the first VMXNET3 adapter and follows the output from the vmtoolsd command.

F5 Product Development tracked this change as ID 1026005.

Impact

In the old behavior, you may encounter issues with automation scripts that assume the TMM interfaces on the BIG-IP system follow the ordering on the hypervisor.

Recommendation

  • Enable vApp option for your virtual machine to use the new behavior
  • Display the NIC ordering on the hypervisor using the vmtoolsd command
  • Verify the new behavior

Enable vApp options for your virtual machine to use the new behavior

On the vCenter Server inventory configuration utility, enable the following two options for your virtual machine:

  • Enable vApp options

    For more information, refer to Enable vApp Options for a Virtual Machine and your VMware documentation.

    Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

  • OVF environment transport > VMware Tools

Display the NIC ordering on the hypervisor using the vmtoolsd command

After enabling the vApp option, you can use the vmtoolsd command to display the NIC ordering on the hypervisor:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system.
  2. To display the NIC ordering on the hypervisor, enter the following command:

    vmtoolsd --cmd "info-get guestinfo.ovfEnv"

    The XML output appears similar to the following example:

    <?xml version="1.0" encoding="UTF-8"?>
    <Environment
    [...]
          <Version>6.7.0</Version>
          <Vendor>VMware, Inc.</Vendor>
          <Locale>en</Locale>
       </PlatformSection>
       <ve:EthernetAdapterSection>
          <ve:Adapter ve:mac="00:50:56:93:b0:4b" ve:network="Public Access" ve:unitNumber="7"/>
          <ve:Adapter ve:mac="00:50:56:93:2f:c9" ve:network="Public Access" ve:unitNumber="8"/>
          <ve:Adapter ve:mac="00:50:56:93:49:26" ve:network="exampleInternal" ve:unitNumber="9"/>
          <ve:Adapter ve:mac="00:50:56:93:a4:21" ve:network="Public Access" ve:unitNumber="10"/>
       </ve:EthernetAdapterSection>
    </Environment>

    The BIG-IP system follows the order as illustrated by ve:unitNumber=. If you do not have the vApp option enabled on VMware, the output will appear similar to the following example:

    No value found

Verify the new behavior

Verify /var/log/boot.log

To verify the new behavior, refer to the /var/log/boot.log file after a system reboot. The entry appears similar to the following example:

notice: Setting BIG-IP ordering using VMware hypervisor NIC ordering.

When the vApp option is not enabled and the system is using the old behavior, the entry appears similar to the following example:

notice: logger[xxx] : Cannot set VMware's hypervisor NIC ordering: VMware tools transport for ovfEnv/vApp should be enabled and the VE restarted from the hypervisor.

Verify NIC ordering using tmsh

To display the list of network interfaces on the BIG-IP system, enter the following command:

tmsh show net interface all-properties
