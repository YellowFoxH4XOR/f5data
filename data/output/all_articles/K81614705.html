Known Issue

The table iRule command may corrupt data and cause the Traffic Management Microkernel (TMM) to exit.

This issue occurs when all of the following conditions are met:

  • You configure an iRule associated with a virtual server to use the table command.
  • The memory used by the table command is prematurely reallocated during iRule processing.

For example, you can use the table command in a CLIENT_ACCEPTED iRule event similar to the following:

when CLIENT_ACCEPTED {
if { [table lookup -subtable "sub_conns" [IP::client_addr]] != "" } {

When the client event fires and you execute the table command, session table results may be overwritten before being returned.

Impact

Data corruption occurs during iRule processing, causing TMM to exit and restart. If configured as part of a high-availability system, a failover occurs.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system may unexpectedly fail over or the TMM process may restart.
  • The system generates TMM core files to the /shared/core directory.
