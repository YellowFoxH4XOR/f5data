Description

This article describes how to import ASM policies into a specified non-Common partition on BIG-IP systems using the iControl REST API. By default, policy imports are placed in the /Common partition. Users may also encounter errors such as the following during this process:

"Could not add the Import Policy Task 'Import Policy Task (UNNAMED)'. Failed Exclusive Fields: Must not have more than 1 of (name, fullPath, policy)"

This article outlines the correct procedure and payload structure to ensure successful import into a desired partition.

Environment

  • Product: BIG-IP ASM (Application Security Manager)
  • Policy import file format: XML
  • Target Partition: non-Common
  • Action: Importing ASM policy via REST API

Cause

The iControl REST API requires specific payload formatting for importing policies into non-/Common partitions. Including both "name" and "fullPath" fields in the payload for the POST request results in an error:

"Could not add the Import Policy Task 'Import Policy Task (UNNAMED)'. Failed Exclusive Fields: Must not have more than 1 of (name, fullPath, policy)"

Therefore, only "fullPath" should be used when targeting a non-/Common partition.

Recommended Actions

To successfully import an ASM policy into a non-/Common partition using the iControl REST API:

(1) Prepare Your Policy File

Ensure your ASM policy file is in XML format. Note its exact size in bytes for use during upload.

(2) Upload the Policy File

Use this command to upload your XML policy file:

# curl -sk -u <BIGIP_USER>:<BIGIP_PASS> \
-H "Content-Type: application/json" \
"https://<BIGIP_HOST>/mgmt/tm/asm/file-transfer/uploads/<CUSTOM_FILENAME>" \
-X POST \
-H "Content-Range: 0-<FILE_SIZE_MINUS_ONE>/<FILE_SIZE>" \
--data-binary @./test_policy.xml


Few notes regarding the API call:

  • Replace the device hostname and credentials (for token-auth, please see Auth Token by Login page on F5 Cloud Docs page)
  • Replace "CUSTOM_FILENAME" in the URL with the desired filename.
  • Replace "test_policy.xml" with the local filename in your jump host (i.e. the previously exported XML file that is to be imported)
  • Replace Content-Range header with the relevant value. For e.g., if the policy XML file is 1173408 bytes, set Content-Range: 0-1173407/1173408.

 

(3) Import Policy into Desired Partition

Use only "filename" and "fullPath" in your payload:

# curl -sk -u <BIGIP_USER>:<BIGIP_PASS> \
-H "Content-Type: application/json" \
"https://<BIGIP_HOST>/mgmt/tm/asm/tasks/import-policy" \
-X POST \
-d '{"filename": "<FILENAME>", "fullPath": "/<PARTITION>/<POLICY_NAME>"}'


Note: Do not include both "name" and "fullPath" in the payload for this POST request; specify only "fullPath" when targeting a non-Common partition. The same approach can also be used to import policy into Common partition with the "fullPath" parameter.

(4) Verify Import Success

Check status of your import task:

# curl -sk -u <BIGIP_USER>:<BIGIP_PASS> \
-H "Content-Type: application/json" \
"https://<BIGIP_HOST>/mgmt/tm/asm/tasks/import-policy/<TASK_ID>"

Note: The "TASK_ID" value can be fetched from the previous step's output.

(5) Verify Policy Deployment

Confirm existence of the policy in the target partition:

# curl -sk -u <BIGIP_USER>:<BIGIP_PASS> \
-H "Content-Type: application/json" \
"https://<BIGIP_HOST>/mgmt/tm/asm/policies/<POLICY_UUID>" | jq '{name, fullPath, partition, id}'

Note: The policy's REST UUID can be fetched from the output for the command run in the previous step, specifically under the 'policyReference' section.

Additional Information

  • For /Common imports, you may use “name” in the payload; for non-/Common partitions use “fullPath” only.
  • Including both “name” and “fullPath” will result in a 400 error.
  • The Content-Range header must match the file size exactly.
  • Only XML format is supported for successful import.
