Known Issue

This is the result of a known issue. F5 does not recommend mixing braces ( {} ) and pound sign ( # ) characters within the same line of an iRule. The iRules parser incorrectly interprets braces within a comment as Tool Command Language (TCL) executable components. If the syntax between the braces is incorrect, the rule fails to load. Similarly, the iRules parser may incorrectly interpret a pound sign character as a comment when it is used between braces.

Mixing braces and pound sign characters within a single line of an iRule can cause unexpected results. For example, the iRule may load successfully when entered using the Configuration utility, but may fail to load when the BIG-IP system attempts to reload the configuration.

F5 Product Development tracked this issue as ID 221238 (formerly CR94758) and it is fixed in BIG-IP 10.0.0 through 10.2.0, and 11.1.0 and later. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

To prevent this issue from occurring, do not mix braces and pound sign characters within the same line of an iRule.

For example, you would change:

when HTTP_REQUEST {
# Set variable { added 8-24-2010 }
set myvar {a # b c d}
}

to:

when HTTP_REQUEST {
# Set variable - added 8-24-2010
set myvar "a # b c d"
}
