Description

After upgrading from an earlier version you may experience 401 unauthorized issues with token based authentication iControl REST calls.

  • F5 improved token based security by restricting token usage to a single source IP by default.
  • If you enable httpd debug which does not impact traffic, (1. tmsh modify sys db log.http.level value debug 2. bigstart restart httpd) you will see the following log message in /var/log/httpd/httpd_errors when clients are hitting an issue with re-using a token from multiple sources. Notice that it says token client and current client are on different IPs:

    May 26 09:22:25 mareep-1-bigip.blenz debug httpd[29197]: [auth_pam:debug] [pid 29197] mod_auth_pam.c(2531): [client 10.155.112.51:58734] AUTHCACHE Token client (10.15.12.51) and current client mismatch (192.168.1.2)

  • On a client you may see an error such as:

    "{"ClassName":"System.Net.WebException","Message":"The remote server returned an error: (401) Unauthorized.","Data":null,"InnerException":null,"HelpURL":null,"StackTraceString":" at System.Net.HttpWebRequest.GetResponse() at Everweb.Infrastructure.Customer.Automation.f5.GetRestResponse(String url) at Everweb.Infrastructure.Customer.Automation.f5.GetPolicy(String policy) at Everweb.Infrastructure.Customer.Automation.Controllers.f5PolicyController.GetPolicyRules2(String bigip, String partition, String policy)","RemoteStackTraceString":null,"RemoteStackIndex":0,"ExceptionMethod":"8 GetResponse System, Version=4.0.0.0, Culture=neutral, PublicKeyToken=<snip> System.Net.HttpWebRequest System.Net.WebResponse GetResponse()","HResult":-2112345,"Source":"System","Bucks":null}"

Environment

Relevant environmental factors specific to the topic:

  • iControl REST
  • Multiple remote users attempting to use the same token from different IP addresses 
  • sys db httpd.matchclient configured as true (default)
  • This db variable was introduced in 13.1.5, 14.1.4.6, 15.1.5.1, 16.1.2.2 and 17.0.0
  • If this issue is seen intermittently and the client is not changing, then refer to K91334123: After upgrade REST API calls fail with "401 Authentication Failed"

Cause

F5 improved security with new behavior for iControl REST token based authentication, but also introduced a new db variable to revert to the prior behavior which makes token based authentication less secure.

Recommended Actions

If you wish to revert to the older behavior, perform the following steps.

  1. Log into the BIG-IP command line and enter the following command:
    tmsh modify sys db httpd.matchclient value false
  2. Validate the change:
    1. tmsh list sys db httpd.matchclient
    2. Should now return the following: sys db httpd.matchclient { value "false" }
  3. Restart httpd (required for changes to take effect):
    1. bigstart restart httpd
  4. If needed, sync the change to device group peers.

Additional Information

This change was made under ID1033837 as part of improving security related to CVE-2022-1388.
