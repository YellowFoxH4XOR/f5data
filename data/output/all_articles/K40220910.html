Issue

Old Behavior

In versions prior to BIG-IP 12.1.0 and BIG-IQ 5.2.0, the use of Digital Signature Algorithm (DSA) keys for secure shell (SSH) connections is supported. For example, you can configure SSH host-based or public key authentication between the BIG-IP system and a remote system using DSA keys.

New Behavior

In BIG-IP 12.1.0 and BIG-IQ 5.2.0 and later, the use of DSA keys for SSH has changed in the following ways:

  • The SSH client (/usr/bin/ssh) is no longer able to connect to SSH servers that support only DSA.
  • If Common Criteria mode (ccmode) is enabled, the BIG-IP SSH server (/usr/sbin/sshd) does not accept connections from SSH clients that support only DSA. If ccmode is not enabled, there is no change and clients can still connect using DSA keys.

Note: In later versions of OpenSSH, support for DSA keys has been disabled by default at runtime, due to their inherent weakness. F5 has backported this change to the BIG-IP system in a modified version of the OpenSSH suite for remote login with the SSH protocol.

F5 Product Development tracked this change as ID 554357 and ID 554360.

Impact

  • This change in behavior could affect any external monitors that use the ssh command to run commands on remote devices, if those devices run SSH servers that support only DSA.
  • If ccmode is enabled, the BIG-IP SSH server (/usr/sbin/sshd) does not accept connections from SSH clients that support only DSA.

Recommended Actions

For information about configuring SSH public key authentication using RSA keys, refer to K13454: Configuring SSH public key authentication on BIG-IP systems (11.x - 14.x).
