Description

Using # to comment out an elseif clause in a if/elseif/else structure will not prevent the elseif from executing, or may result in a syntax error.

Take the following TCL code:

set my_var 0
set chk {1}

if {$chk eq "0" } {
   set my_var 1<
   break
#} elseif {$chk eq "1" } {
#    set my_var 1
#    break
} elseif {$chk eq "1" } {
   set my_var 2
  break
}

With the comments (#) in place as they are, we might expect that when executed, the second elseif stanza will run, and my_var has a final value of 2

However, it actually holds a value of 0

The first (apparently commented) elseif clause

elseif {$chk eq "1" }

is evaluated and selected, but no variables are set due to the comments,

#    set my_var 1
#    break

and the following elseif clause

elseif {$chk eq "1" }

is not evaluated.

Environment

  • BIG-IP LTM
  • iRules

Cause

TCL comments (as denoted by #) are only treated as comments in specific circumstances.

 

From https://wiki.tcl-lang.org/page/comment

The dodekalogue defines one method for creating a comment in a Tcl script: If A hash character ("#") appears at a point where Tcl is expecting the first character of the first word of a command, then the hash character and the characters that follow it, up through the next newline, are treated as a comment and ignored. The comment character only has significance when it appears at the beginning of a command.

Note: This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge.

Unlike C/C++ style comments that are processed by a preprocessor, and commented lines or partial lines are removed from the assembled code that is to be compiled, TCL comment symbols are evaluated at runtime based on where they appear.

So in the code example above, the first hash (#) symbol does not occur where Tcl is expecting the first character of the first word of a command.
The first hash is just part of the if function string that will be passed to eval:

{
  set my_var 1
   break
#}

So this hash is not a comment, and the line is not excluded.

After the if function string, TCL is expecting an elseif, else, or the first character of the first word of a command.
This is an elseif - the elseif expression string is evaluated, and returns true, so the elseif function string between the braces is collected and evaluated:

{
#    set my_var 1
#    break
}

Here, the # symbols are appearing where Tcl is expecting the first character of the first word of a command. These are valid comments, and no functional execution occurs.
After an elseif branch has been executed, no further elseif branches are evaluated, and the if statement is completed.

The following approach might spring to mind:

set my_var 0
set chk {1}

if {$chk eq "0" } {
   set my_var 1
   break
}
# elseif {$chk eq "1" } {
#    set my_var 1
#    break
#}
elseif {$chk eq "1" } {
   set my_var 2
   break
}

This would appear to satisfy the requirement that the # symbol occurs where Tcl is expecting the first character of the first word of a command.
However, this causes a syntax error - the intervening comment terminates the relationship between the following elseif (or else) clause and the closing brace of the preceding if function string.

Without the preceding if, else and elseif are not valid commands on their own.

Note: these issues are inherent to TCL Language syntax, and this is not expected to change in the future.

Recommended Actions

use logic statements to bypass an element of the elseif, rather than comments

set my_var 0
set chk {1}
set skip 0

if {$chk eq "0" } {
   set my_var 1
   break
}
elseif {($chk eq "1") eq 0 } {
set my_var 1
break
}
elseif {$chk eq "1" } {
set my_var 2
break
}

This changes the expression for the first elseif into something that will never be true, and so the entire stanza is not executed.
