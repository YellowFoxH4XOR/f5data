Topic

The FirePass controller platform supports a customizable grouping of Secure Socket Layer (SSL) and Transport Layer Security (TLS) ciphers.

The FirePass SSL Cipher Security settings are as follows:

  • Low-grade security: Prefers high-speed ciphers. Export browsers are permitted.
  • Medium-grade security: Allows only ciphers supporting 128-bit or higher encryption. Export browsers are not permitted.
  • High-grade security: Allows only ciphers supporting triple-DES (168-bit encryption) and AES. Export browsers are not permitted.

You can control access to the FirePass controller by setting what SSL protocols to allow, as follows:

  • Accept SSLv2, SSLv3, and TLS protocols (maximize compatibility): Provides the widest access.
  • Accept only SSLv3 and TLS protocols (maximize security): The SSLv2 protocols and ciphers are disabled.
  • Accept only TLS protocol (incompatible with some browsers): The SSLv2 and SSLv3 protocols are disabled. Some browsers may not be compatible with this mode.

Important: The FirePass controller supports only SHA-1 certificates for Web Service access, machine certificates, and client certificates; there is no support for SHA-2 certificates.

You can configure the FirePass controller to reject non-compliant ciphers when the cipher is used by the client browser; you can set this configuration with the following option.

Enforce strict SSL ciphers policy on all FirePass URI

The system will immediately reject any SSL connections from web browsers that do not comply with a configured policy. Depending on the client browser implementation, when the connection to FirePass fails, a browser that does not support high-grade security ciphers may only report a connectivity problem, and not provide a clear explanation.

Most Web browsers support high-grade security, by default. In most deployment environments, this option should not cause the system to reject SSL connection attempts to the FirePass controller. Enabling this option removes the redundant SSL Cipher verification on the FirePass controller. Without this option enabled, SSL connections with weaker ciphers than the preferred ciphers of the policy can connect to the FirePass logon page. The FirePass controller will enforce the use of stronger Ciphers when the user logs in, as specified by the policy.

To help users who attempt to access the FirePass controller with non-compliant ciphers, you can configure the FirePass controller to display a warning to the user using the following setting:

Provide notification regarding policy violation to the users via Web Browser (Better usability):

This setting performs redundant verification of SSL ciphers for connections that access the FirePass logon page, and during authentication it displays an HTML page notification indicating that the client's browser SSL ciphers do not comply with the FirePass policy.

Following is an example of an end user notification:

SSL ciphersuite EXP1024-RC4-SHA not permitted. Please see your system admin.
