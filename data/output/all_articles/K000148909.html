Description

When modifying the IP address for a virtual server or creating a new virtual server, it is expected the system sent GARP for the virtual server IP as according to description in article K15858: Performing actions such as adding, modifying, or deleting a BIG-IP virtual IP address object (such as a virtual server, self IP address, VLAN, SNAT, or NAT) may also cause the BIG-IP system to re-send gratuitous ARP requests. But actually, the GARP wasn't sent after modifying the virtual server ip.

 

Environment

  • BIG-IP LTM
  • Virtual Server Address
  • GARP

Cause

The cause of this phenomenon is the IP that modified or created for the vs is the same with an existing vs or it was created previously. As this IP address has already existed in the Virtual Address list, it wouldn't trigger the system to send the GARP for this IP.

Recommended Actions

If the GARP wasn't sent for the virtual address after creating or modifying a virtual server, please follow the actions described in below article to force the system sending GARP for a specific virtual address.

  • K000134493: Forcing the BIG-IP system to resend GARP advertisements for a specific virtual server or virtual address

Additional Information

The article, K15858, is actually saying that the actions can cause the GARP sending are modifying/adding/deleting the virtual IP address objects, not for the virtual server. But sometimes the customer misunderstands the actions is for virtual server, that's why this article is raised.
