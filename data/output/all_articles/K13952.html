Known Issue

NAT64 forwarding virtual server configuration may fail to pass fragmented IPv6 packets.

This issue occurs when the following conditions are met:

  • A NAT64 forwarding virtual server is configured to allow IPv6 hosts to communicate with IPv4 servers.
  • CMP is enabled for the virtual server.
  • The virtual server processes a packet that exceeds the MTU.

This issue is related to CMP and occurs when the ingress TMM instance reassembles the fragmented packet, but does not set the bit that informs the egress TMM instance to ignore whether the packet exceeds the MTU. As a result, when the packet is sent to a different (egress) TMM instance, the egress TMM instance drops the packet.

Impact

Virtual server connections may be delayed or fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A packet capture shows that the virtual server fails to forward fragmented IPv6 packets.
  • The BIG-IP system responds with a packet too big message as shown in the following tcpdump output:

    11:56:12.841433 IP6 1003::11 > 2001:1890:111d:220::1: frag (0|1448) ICMP6, echo request, seq 0, length 1448
    11:56:12.841445 IP6 1003::11 > 2001:1890:111d:220::1: frag (1448|13)
    11:56:12.841932 IP6 1003::13 > 1003::11: ICMP6, packet too big, mtu 1500, length 1240

  • Virtual server connections may be delayed or fail.

Workaround

To work around this issue, you can disable CMP for the affected virtual server. To do so, perform the following procedure:

Impact of workaround: Traffic for the virtual servers for which CMP has been disabled is re-directed to tmm0.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Disable CMP on the virtual server by using the following syntax:

    modify /ltm virtual <virtual-server> cmp-enabled no

    Replace <virtual server> with the name of the virtual server you want to modify.

  3. Save the change by typing the following command:

    BIG-IP 10.1.0 and later:

    save /sys config

    BIG-IP 10.0.x:

    save config
