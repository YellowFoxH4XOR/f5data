K000163459: NTLM authentication is not supported with F5 Distributed Cloud HTTP Load Balancer

Type
Knowledge
Published
2026-09-29
Updated
2026-09-29
Source
https://my.f5.com/manage/s/article/K000163459

Description

Applications that require NTLM authentication may fail when published through an F5 Distributed Cloud (XC) HTTP Load Balancer.

Common symptoms include HTTP 401 or 503 responses during the Windows Integrated Authentication challenge/response sequence, even when the request is allowed by the Web Application Firewall (WAF) or Service Policy.

NTLM authentication is not supported through the standard F5 Distributed Cloud HTTP Load Balancer.

Environment

  • F5 Distributed Cloud Services

  • HTTP or HTTPS Load Balancer

  • Windows Integrated Authentication

  • NTLM authentication

Cause

NTLM is a connection-oriented authentication protocol. The NTLM challenge/response exchange requires authentication state to remain associated with the same connection throughout the authentication sequence.

F5 Distributed Cloud HTTP Load Balancer operates as a reverse proxy and does not support the connection-affinity requirements necessary for NTLM authentication as a standard HTTP Load Balancer use case.

This limitation is not resolved by allowing the Authorization header through a Service Policy or WAF rule. F5 Distributed Cloud HTTP Load Balancer can forward Authorization: NTLM and Authorization: Negotiate headers, but forwarding the headers alone does not provide the connection-oriented behavior required by NTLM.

Answer/Recommended Actions

Do not use NTLM as the authentication method for applications published through the standard F5 Distributed Cloud HTTP Load Balancer.

For Windows Integrated Authentication, F5 recommends migrating the application to Kerberos using Negotiate. Kerberos is also the preferred authentication method for Active Directory environments according to Microsoft.

When migrating to Kerberos, validate the application and Active Directory configuration, including the appropriate HTTP Service Principal Name (SPN) for the application hostname.
