Description

 Load Balancing Public NTP servers is not effective.

Environment

You create a FQDN pool of NTP servers for the *.pool.ntp.org domain.

This is used by your internal NTP clients but NTP performance is poor.

 

Cause

The public pool of NTP servers may contain servers with bad timekeeping or connected with a slow and jittery network connection.

If the pool balances to such a server, then the client will receive bad time information. (falsetickers)

Answer/Recommended Actions

Correct use of NTP clients connecting to a variable pool of servers requires that 3 servers are selected.

The NTP client will evaluate the performance of each server and synchronise to the best.

By adding a load balancer, which exposes one server, this functionality is lost. Some functionality may be recovered by using a NTP Aware health monitor. See below.

 

Additional Information

 This does not apply to internal NTP servers. They don't suffer the same issues, but also don't need to be load balanced.
