Description

A HA device configured for automatic sync is now receiving errors after performing an operation that causes the configuration to be reloaded.

  • HA devices may be unable to sync 
  • You may experience different sync error messages regarding various configuration objects not being found
  • You may notice the configuration will not load on some devices
  • In rare cases the HA devices may successfully sync and show no configuration

Environment

  • BIG-IP devices in a high availability configuration
  • Automatic Sync enabled on a Sync-Failover group
  • Save on Automatic Sync disabled for that Sync-Failover group
  • All configuration changes are made on a specific device
  • Perform operation that causes the configuration file to be reloaded

Cause

This issue can occur on a HA pair configured for Automatic Sync with Save on Automatic Sync disabled and all configuration modifications are made on a specific device.  With the Save on Automatic Sync feature disabled, the devices sync their running configuration but the peer device does not update its configuration file.  Then when a configuration load is performed on that peer device, it will load its configuration file that is missing these changes.  

Recommended Actions

If you believe you are encountering this issue, you will first want to check the date of the configuration file on all devices. 

  1. Log into the CLI for all devices effected
  2. Navigate to the /config directory in the BASH prompt
  3. Enter the following command:
    ll | grep bigip.conf
  4. Review the dates of the bigip.conf file
If you notice a large difference in these files between the devices then you can perform the steps below to resolve this issue.  Depending on the situation, some of these may not work on their own and are listed from least, to most, intrusive.  Begin by trying to force a ConfigSync to the peer unit by following the steps in the article below: 
  • K13887: Forcing a BIG-IP device group member to initiate a ConfigSync operation

If that does not resolve this issue then rebuild device trust by following the steps in the article below and then perform a ConfigSync:
  • K13946: Troubleshooting ConfigSync and device service clustering issues

If the issue still persists after resetting the device trust then proceed with restoring the device to factory defaults and then rebuild device trust to perform a ConfigSync:
  • K13127: Restoring the BIG-IP configuration to factory default settings (11.x - 15.x)
 

Additional Information

Once the configuration has been restored to all devices effected then you can enable Save on Automatic Sync by following the steps below:

  • K14624: Configuring the Automatic Sync feature to save the configuration on the remote devices
