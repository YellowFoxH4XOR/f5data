Description

By default, the syslog-ng daemon processes messages without modifying their time zone, but it can be configured to alter the date on a per-destination basis, to suit the time zone of the log receiver.

Environment

  • BIG-IP
  • Syslog-ng server (the logging daemon bundled with BIG-IP)

Cause

None

Recommended Actions

The time_zone keyword can be used in syslog-ng to specify a custom time zone for the destination. This keyword is not natively supported in tmsh but can be specified using the sys syslog include catch-all. Note that any remote syslog destination specified this way should not also be specified in the sys syslog remote-server section.

A list of valid time zone strings can be obtained by running the timedatectl list-timezones command or the ls -laR /usr/share/zoneinfo command at the bash prompt, or by inspecting the drop down box in the BIG-IP Configuration utility, under System > Platform > Configuration > Time Zone.

For example (replace x.x.x.x with the actual IP address of the remote syslog server)

tmsh modify sys syslog { include "destination remote_server {udp(x.x.x.x port (514) time_zone(UTC));};filter f_alllogs {level (debug...emerg);};log {source(s_syslog_pipe);filter(f_alllogs);destination(remote_server);};" }

After running the modify sys syslog command, save the configuration with the following command:

tmsh save sys config

This the text you add in the include string reformatted for readability:

destination remote_server {
   udp(x.x.x.x port (514) time_zone(UTC));
};
filter f_alllogs {level (debug...emerg);};
log {
    source(s_syslog_pipe);
    filter(f_alllogs);
    destination(remote_server);
};
