Description

You are  attempting to use Cilium BGP with Container Ingress Services (CIS).

The results are unsatisfactory.

Cilium has become the preeminent CNI solution for kubernetes due to its performance and flexibility.

Cilium supports BGP natively.

Environment

F5 Networks' Container Ingress Services can use BGP to connect to pods by their Cluster IP.

This requires advertising the PodCIDR of all worker nodes to the BIG-IP. (Additionally advertising the PodCIDR on Control plane nodes does no harm.)

You are using Cilium BGP  version cilium.io/v2   on version 1.18.1   (Latest at time of publication)
This supersedes CiliumBGPPeeringPolicy.



Cause


On following the Cilium documentation to advertise PodCIDR's you find that only the PodCIDR of the Nodes that match the CiliumBGPClusterConfig are advertised.
This is generally the  Control Plane as  CiliumBGPClusterConfig nodes specify neighbors (bgpInstances: -> peers) 

Thus they have to be manually configured on the BIG-IP  BGP configuration as neighbors . Doing this on a large number of worker nodes and nodes that can be added by autoscaling is infeasible


Recommended Actions


With Cilium 1.18  BGP prefix aggregation is available. This will advertise the Services back to the BIG-IP but will aggregate them to a larger CIDR.


This gives the effect of advertising the PodCIDR block.


Example


apiVersion: cilium.io/v2
kind: CiliumBGPAdvertisement
metadata:
  name: services
  labels:
    advertise: bgp
spec:
  advertisements:

    - advertisementType: "Service"
      service:
        addresses:          # <-- specify the service types to advertise
          - ClusterIP
        aggregationLengthIPv4: 24    # Which is the subnet in the mode
      selector:             # <-- select all services
        matchExpressions:
         - {key: somekey, operator: NotIn, values: ['never-used-value']}
