Known Issue

This is the result of a known issue. Requests sent to a virtual server with HTTP cache enabled and an HTTP fallback host configured may cause the Traffic Management Microkernel (TMM) to restart and temporarily fail to process traffic if the virtual server is configured with all of the following elements:

  • The virtual server is configured with an HTTP profile
  • The HTTP profile is configured with a fallback host
  • HTTP caching is enabled
  • The virtual server is configured with an iRule that uses the CLIENT_ACCEPTED iRule event, along with a reject statement
  • The TCP profile Deferred Accept setting is enabled

If a virtual server that is configured with the previously-described settings receives a connection that triggers the reject iRule statement, the TMM process may restart and temporarily fail to process traffic.

F5 Product Development is tracking this issue as ID 227281 (formerly CR85820).

Workaround

You can work around this issue by removing the fallback host statement from the HTTP profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Services menu, select HTTP.
  4. Click the HTTP profile that is used by the virtual server.
  5. Remove the fallback host statement.
  6. Click Update.
