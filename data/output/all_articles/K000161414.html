Description

On BIG-IP LTM systems with a FIPS HSM, the log entry error: crypto codec FIPS error ok may appear in /var/log/ltm from the openssl process. This message indicates a transient FIPS HSM communication anomaly that self-cleared. FIPS health checks via fipsutil info and tmsh show sys crypto fips may return normal results, with the FIPS module functioning correctly.

Relevant log output:

err openssl[PID]: error: crypto codec FIPS error ok

Environment

  • Product: BIG-IP LTM
  • Feature: FIPS HSM (Hardware Security Module)
  • Process involved: openssl (control plane process)
  • Log file: /var/log/ltm

Cause

The log message reflects a transient FIPS HSM communication anomaly. The ok suffix is the return code from the FIPS library, indicating the error condition was detected and then self-resolved. This is distinct from a persistent FIPS failure.

Answer/Recommended Actions

To confirm the transient nature of the event and rule out a persistent FIPS issue, perform the following steps:

  1. Check FIPS HSM health:
    fipsutil info
    tmsh show sys crypto fips
    • If fipsutil info returns ERROR: Cannot communicate with FIPS device or Driver is in SAFE state, the HSM has a more serious issue.
  2. Check for SSL handshake failures around the same time:
    grep -E "01260010|fips_pkcs1v15|fips-crypto|FIPS" /var/log/ltm
  3. Check kernel log for FIPS driver state:
    grep -i "SAFE state\|fips\|FIPS" /var/log/kern.log
  4. Check HA status to confirm no failover occurred:
    tmsh show sys ha-status all-properties | grep -i fips
  5. Check for recurrence pattern:
    grep "FIPS error" /var/log/ltm | tail -50

Additional Information

  • The openssl process (control plane) is distinct from tmm (data plane). Errors logged from openssl[PID] affect control plane operations (certificate management, key operations) and do not directly impact traffic processing.
  • The log message structure:
    • openssl[PID]: process generating the message
    • error: crypto codec FIPS: module affected
    • error ok: status/return code, indicating the error self-cleared
  • A persistent FIPS error would appear differently, for example:

error: crypto codec fips-crypto0-X queue is stuck

  • If FIPS health checks return healthy results and no SSL handshake failures or HA failovers are observed, no further action is required.
