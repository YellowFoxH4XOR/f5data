Description

ASM attack signature installation schedules and history on the following GUI page are lost after software upgrade. Installation of Automatically Downloaded Updates is set to Disabled.

    System  ››  Software Management : Live Update

Environment

  • ASM module is provisioned
  • BIG-IP TMOS software version is upgraded to:
    • v14.1.4.5 or later
    • v15.1.5 or later
    • v16.1.2.1 or later
    • v17.x

Cause

The issue is tracked as ID 1080613.

During the software upgrade, UCS from the earlier version will be restored on a new version, and the attack signature installation schedules and history will be restored successfully right after upgrade. However, the schedules and installation history may be lost and reverted to the default upon initial restart of tomcat daemon (or reboot of the device). After tomcat is restarted once, the issue no longer occurs and the new configurations will be retained.

Recommended Actions

If you found the installation history of signature before performing a software upgrade of an ASM device to the fixed version above 17.1.0, 16.1.4, 15.1.9, you may follow the workaround of "Procedures for already affected ASM devices" first to recover your installation history back and then perform upgrade to the fixed version, on which will not lose the installation history due to this bug any more.

Please note that, since the fixed versions have been released, it's not recommended to still upgrade to the affected version.

 

Procedures for already affected ASM devices

For the systems, in which the config has already been gone, you may consider performing the following steps to restore the config back.

Impact of workaround: If there have been any Live Update configuration changes since the upgrading, these post-upgrade changes will be lost by performing the workaround, and the Live Update configuration will be back to the state of just-after-upgraded.

  1. Find the latest live-update-import.yaml* file based on the timestamp in the file name. It's likely there is only one file.

    ls -l /var/lib/hsqldb/live-update/live-update-import.yaml*

    Sample output:
    -rw-r--r--. 1 tomcat tomcat 1053618 Aug 15 08:30 /var/lib/hsqldb/live-update/live-update-import.yaml.2022-08-15T15:40:34Z
    -rw-r--r--. 1 tomcat tomcat 1054029 Aug 15 08:42 /var/lib/hsqldb/live-update/live-update-import.yaml.2022-08-15T15:44:03Z
     

  2. Copy and rename the file to "live-update-import.yaml". This will soon trigger a config import process. Wait about 1 minute to let import process to complete.

    cp -p /var/lib/hsqldb/live-update/live-update-import.yaml.<date> /var/lib/hsqldb/live-update/live-update-import.yaml
     

    For example, using the file name returned in step 1:

    cp -p /var/lib/hsqldb/live-update/live-update-import.yaml.2022-08-15T15:44:03Z /var/lib/hsqldb/live-update/live-update-import.yaml
     

  3. Restart tomcat to make sure it survives tomcat restart and reboots.

    bigstart restart tomcat
     

  4. Make sure the configuration is not reverted to default.

    curl -sku <username>:<password> https://localhost/mgmt/tm/live-update/asm-attack-signatures/install-schedule | jq .
