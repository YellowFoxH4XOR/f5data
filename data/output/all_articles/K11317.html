Topic

The Enterprise Manager system requires network connectivity to other systems to perform its intended functions. The following list details the required accesses for the various aspects of Enterprise Manager functionality.

Remote device management 

Remote device management requires bi-directional TCP/HTTPS connectivity between the Enterprise Manager system and all managed devices. Each BIG-IP system or Enterprise Manager system may use either the management address or a self IP address that has been configured to accept HTTPS traffic.

Firewall rules between the Enterprise Manager system and managed devices must allow the following connections:

<Enterprise Manager address>:<random port> to <managed device address>:443 (TCP)

<managed device address>:<random port> to <Enterprise Manager address>:443 (TCP)

Statistics data collection

Statistics data collection requires TCP/iQuery connectivity from the Enterprise Manager system to all managed devices that have statistics data collection enabled. Each BIG-IP system or Enterprise Manager system may use either the management address or a self IP address that has been configured to accept iQuery traffic. 

Firewall rules between the Enterprise Manager system and managed devices that have statistics data collection enabled must allow the following connections:

<Enterprise Manager address>:<random port> to <managed device address>:4353 (TCP)

Remote access to the statistics database

Remote access to the statistics database requires TCP/MySQL connectivity from a client requiring access to the statistics database to the Enterprise Manager system. The Enterprise Manager system may use either the management address or a self IP address that has been configured to accept MySQL traffic.

Firewall rules between the Enterprise Manager system and managed devices that have Statistics Data Collection enabled must allow the following connection:

<client address>:<random port> to <Enterprise Manager address>:3306 (TCP)

Requests to external servers

To carry out tasks configured using the task wizards, the Enterprise Manager system, by default, communicates directly with F5 servers though a secure HTTPS or SFTP (secure file transfer protocol) connection using the Enterprise Manager management address or the self IP address of the egress VLAN. Alternatively, the Enterprise Manager system may be configured to send HTTPS requests through a proxy server. For example, the Enterprise Manager system can use an SSL HTTP proxy for downloading licensing information or BIG-IP ASM attack signature files from F5 servers. The Enterprise Manager system uses the proxy server only for tasks configured in the task wizards.

Note: The Enterprise Manager Administrator Guide incorrectly indicates that it is possible to use an SFTP proxy. For information, refer to K13427: Documentation Erratum: Enterprise Manager Administrator Guide incorrectly documents SFTP support.

Requests made from elsewhere in the Configuration utility, from the command line, or initiated by system services, such as NTP, do not use the proxy. For these requests, the Enterprise Manager system uses the Enterprise Manager management address or the self IP address of the egress VLAN, depending on the service and routing configuration. For example, if you update the licensing information on a device using the License option from the System menu in the Configuration utility, Enterprise Manager does not send the request through the proxy.

If no proxy server is configured, or if requests will be initiated outside the context of the task wizard, firewall rules between Enterprise Manager and the Internet must allow the following connections:

<Enterprise Manager address>:<random port> to <external host address>:<external service port> (<protocol>)

If a proxy server is configured, firewall rules between the Enterprise Manager system and the Internet must allow the following connections:

<Enterprise Manager address>:<random port> to <proxy server address>:<external service port>  (<protocol>)

<proxy server address>:<random port> to <external host address>:<external service port>  (<protocol>)

Note: A separate rule may be required for each external destination. Requests sent to the same destination may use various Enterprise Manager addresses, depending on the source of the request and the path to the external host. In these cases, multiple rules may be required for the same destination.

BIG-IP iHealth service

Beginning in Enterprise Manager 3.0.0, you can create a task for the Enterprise Manager to gather qkview files from its managed devices and upload the qkview files to BIG-IP iHealth. The Enterprise Manager will then display the iHealth diagnostic information, which may include any configuration or product issues, and recommended AskF5 articles. For information about the host and service port connectivity to the F5 iHealth service, refer to K10349: Enterprise Manager may require network access to certain F5 hosts.
