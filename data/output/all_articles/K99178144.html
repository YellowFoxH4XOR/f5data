Description

At working hours, the VPN is not stable, and the APM device hit the performance issue like K12524516:  APM Network Access (VPN) compression cause CPU usage higher.
If capture the packets, when the PPP tunnel closed, the client send Reset packet to APM server.
Before the client send Reset packet to the APM server, in the client log file f5TunnelServer.txt, get the log like:

14756,13872,, 1, \UGZIPCompressionChannel.cpp, 155, UGZIPCompressionChannel::Read(), inflate failed, -3
14756,13872,, 48, \UTunnel.cpp, 752, UTunnel::RunObjectProc(), << TunnelChannel->Read error
16192,9176,, 48, \UTunnel.cpp, 911, UTunnel::RunObjectProc(), Finished data pumping, m_bRequestToStop=0, bServerDown=0, bTunnelDown=1
16192,9176,, 0,,,, Tunnel Channel Disconnected

Environment

  • BIG-IP APM 13.x to 15.x
  • More than 300 Network Access Sessions
  • High load cause the performance issue like K12524516:  APM Network Access (VPN) compression cause CPU usage higher.

Cause

Under investigation.

Recommended Actions

  1. Capture the packets on the client and APM, verify the disconection is not caused by the network issue.
  2. Refer to K12524516, fix the performance issue.

None.
