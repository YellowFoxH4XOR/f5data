K14074: The ARX default volume migration method uses staged migration

Type
Knowledge
Published
2012-12-28
Updated
2023-02-21
Status
Legacy Content
Applies to

  • ARX: 6.2.0
Source

Issue

Old Behavior

In versions prior to ARX 6.2.0, the ARX system migrates a volume using a method known as ?direct migration. Direct migration creates the file on the target filer and then removes the file.

New Behavior

Beginning in ARX 6.2.0, the default migration method changed to staged migration.

Staged migration creates the file from the source filer in a hidden staging area on the target share. After the network transfer is complete, the file is copied from the staging area into the final path on the target filer.

Impact

This change in behavior resets the files archive bit after it is copied from the hidden staging area to the final location.

Recommended Actions

If you need to preserve the archive bit, F5 recommends that you set the volume migration method back to the direct migration method. To do so, perform the following procedure:

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global configuration mode by typing the following command:

    global
  4. Enter namespace configuration mode using the following command syntax:

    namespace <namespace>

    Replace <namespace> with the name of your namespace.

    For example:

    namespace ns1
  5. Enter volume configuration mode using the following command syntax:

    volume <volume>

    Replace <volume> with the name of your volume.

    For example:

    volume /vol
  6. Edit the migrate method using the following command syntax:

    policy migrate-method {direct | staged}

    Replace {direct | staged}  with the direct migration method.

    For example:

    policy migrate-method direct
  7. Exit the placement rule configuration mode and return to privileged mode by typing the following command:

    end
