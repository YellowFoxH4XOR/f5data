Description

When deploying an iRule on BIG-IP DNS to drop DNS queries with non-standard opcodes, as below sample iRule:

when DNS_REQUEST {
    if { [DNS::opcode] != 0 } { drop }
}

The following error may be encountered:

01070151:3: Rule [/Common/irule2] error: /Common/irule2:2: error: [undefined procedure: DNS::opcode][DNS::opcode]

This occurs when the iRule uses "[DNS::opcode]", which is not a valid command in F5 iRules. 

Environment

  • Creating a new iRule under "DNS_REQUEST" Event
  • Using "[DNS::opcode]" as DNS command
  • DNS Module with Listener

Cause

The command [DNS::opcode] does not exist in F5's iRules language. To access the DNS opcode, use "DNS::header" with 'opcode' as its flag. The value returned for 'opcode' is a string (such as "QUERY"), not a numeric value.

Recommended Actions

Replace any usage of [DNS::opcode] with "[DNS::header opcode]" in your iRule script.

To drop all DNS Requests that do not have an opcode of "QUERY", use the following syntax:

when DNS_REQUEST {
    if { [DNS::header opcode] != "QUERY" } { drop }
}

Tip: You need to create this iRule object under "DNS ›› Delivery : iRules : iRule List", to be able for assignment to your desired DNS Listener. Also, the DNS Listener needs to have a "DNS Profile" attached.
