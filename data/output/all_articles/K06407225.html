Known Issue

Mirrored connections that use a last hop pool may fail after a failover event.

This issue occurs when all of the following conditions are met:

  • Multiple BIG-IP systems are configured in a high availability (HA) configuration.
  • The virtual server is configured to mirror connections.
  • The virtual server is configured with the Auto Last Hop setting disabled.
  • The virtual server is configured to use a last hop pool.
  • The last hop pool member's IP address is unresolved by ARP/NDP on a standby BIG-IP system.
  • A failover event occurs and causes the standby BIG-IP system to become active.

Impact

Affected mirrored connection flows will fail after a failover event.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Mirrored connections that use a last hop pool are failing after a failover event.

Workaround

To work around this issue, you can configure a monitor for the last hop pool. The monitor ensures that the standby BIG-IP system will have an active ARP/NDP resolution for the members of the last hop pool. For more information about configuring health monitors, refer to the BIG-IP Local Traffic Manager: Monitors Reference guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
