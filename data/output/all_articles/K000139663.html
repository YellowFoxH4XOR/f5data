Description

How to exchange all certificates from all devices since the iQuery mesh works without exchanging the certificates with any of the commands listed in article K13312. All that is required is to have the Root CA certificate under /config/gtm/server.crt and /config/big3d/client.crt. In addition, the certificates of the iQuery mesh members need to be signed by the same CA as the Root.

 

 

Environment

  • BIG-IP DNS
  • BIG-IP LTM

 

Cause

None

 

Recommended Actions

  1. Create a GSLB DC
  2. Create the GSLB servers objects for the GTM and the LTM
  3. In the GTM, append the third party root CA cert to /config/gtm/server.crt and /config/big3d/client.crt
  4. In the LTM, append the third party root CA cert to /config/big3d/client.crt
  5. Renew the device certificates of the GTM and LTM with the third party certificates
  6. Validate connectivity with iqdump and tmsh show gtm iquery (no need to do bigip_add, big3d_install or gtm_add )

 

Validate connectivity via CLI:

  • tmsh show /gtm iquery all
  • iqdump <device_ip_address>

If the iQuery channel is established, iqdump returns XML similar to the following example:

config # iqdump 10.10.10.20

<!-- Local hostname: lc1.example.com -->
<!-- Connected to big3d at: ::ffff:10.10.10.10:4353 -->
<!-- Subscribing to syncgroup: default -->
<!-- Fri Apr 26 15:23:30 2024 -->
<xml_connection>
<version>16.1.3.3</version>
<big3d>big3d Version 16.1.3.3.0.0.3</big3d>
<connection_id>847</connection_id>
...

 

 

Verify iQuery via GUI

Note: If the configuration synchronization (ConfigSync) peers are being monitored using the bigip monitor, you can verify iQuery connection status to the remote DNS sync group peers using the following procedure.

 

Log in to the Configuration utility of any DNS sync group member:

  • Go to DNS > GSLB > Servers.
  • Under Status, verify that the iQuery communication status is Available (green).
