K000163322: F5OS Tenant upgrade to 17.5.1.8 fails with error Provisioning failed with error 1 - Disk limit exceeded

Type
Support Solution
Published
2026-09-15
Updated
2026-09-15
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163322

Description

BIG-IP configuration loading or validation fails during module provisioning with the following error:

01071008:3: Provisioning failed with error 1 -

'Disk limit exceeded. 20338 MB are required to provision these modules,

but only 20220 MB are available.'

Unexpected Error: Validating configuration process failed.

Environment

  • R5600
  • BIG-IP LTM tenant
  • Tenant disk allocation: 82 GB
  • Provisioned modules and features:
    • BIG-IP LTM
    • BIG-IP ASM
    • BIG-IP APM
    • AVR
    • iRulesLX
  • Configuration validation performed with:

tmsh load sys config verify

  • Required disk space: 20,338 MB
  • Available disk space: 20,220 MB

Cause

Insufficient tenant disk space prevents provisioning of the configured BIG-IP modules during configuration validation. The available space is 118 MB less than the required amount.

Recommended Actions

  1. Run configuration validation to determine whether the failure is caused by insufficient disk space:
  2. tmsh load sys config 
  3. Review the error output for the required and available disk-space values.
  4. Place the tenant into the appropriate configuration mode through the platform management system.
  5. Increase the tenant disk allocation. Increasing the allocation from 82 GB to 83 GB provides sufficient space for the configuration described here.
  6. Restart or redeploy the tenant so that the updated disk allocation is applied.
  7. Run configuration validation again:
  8. tmsh load sys config 
  9. Retry loading or deploying the BIG-IP configuration.
  10. Before future BIG-IP upgrades, verify that the tenant has sufficient disk capacity for all provisioned modules.

Additional Information

  • The failure occurs during provisioning, before configuration validation can complete.
  • Required disk space depends on the combination of provisioned modules and features.
  • Configuration warnings related to deprecated compliance objects, duplicate log destinations, or regular-expression definitions may also appear during validation. These warnings are not the cause of the provisioning failure described here.
  • Increasing the tenant disk allocation by 1 GB resolves the provisioning failure in this configuration.
