Topic

AskF5 articles often have procedures that require you to modify the BIG-IP system's configuration from the command line. The final step in a procedure is typically saving the configuration so that the modification persists beyond a system reboot. However, system database variables, often referred to as database keys, are saved automatically when you modify them. BIG-IP system database keys are automatically saved to the /config/BigDB.dat file.

Description

Modifications to BIG-IP system database keys made from the command line are automatically saved, unlike other configuration modifications. To accurately revert modifications made to a database key, you should first obtain the current value of the database key before you make a modification.

Important: You must save system database keys that control daemon logging levels, for the modification to persist. For more information about logging database keys, refer to K31305921: Overview of BIG-IP logging BigDB database keys (15.x - 21.x).

  • Obtaining database key values
  • Modifying database keys

Obtaining database key values

To list the default-value, the current value, and the possible value-range of a system database key, use the following command syntax:

tmsh list sys db <DB key name> all-properties

For example, to list all-properties for the connection.syncookies.algorithm database key, type the following command:

tmsh list sys db connection.syncookies.algorithm all-properties

sys db connection.syncookies.algorithm {
    default-value "hardware"
    scf-config "true"
    value "both"
    value-range "both hardware software"
}

Modifying database keys

To modify the value of a system database key, use the following command syntax:

tmsh modify sys db <DB key name> value <value>

For example, to modify the connection.syncookies.algorithm database key, type the following command:

tmsh modify sys db connection.syncookies.algorithm value software

Recommendations

When you modify BIG-IP system database keys, you should consider the following factors:

  • If you have multiple BIG-IP systems in a high-availability (HA) configuration, you should perform a configuration synchronization (ConfigSync) after modifying a database key, and ensure that the modification is working as expected.

    Important: Most database key values automatically synchronize to peer devices when the Local Traffic Manager's Automatic Sync or the Global Traffic Manager's Synchronize options are enabled. There are some exceptions such as provision.extramb. To ensure synchronization took place use the list command above to verify the synchronization took place.

  • You should obtain the current value of a system database key before making modifications. You can use this value later to revert or roll back the modification to the previous value.
  • You should save modifications you make to daemon-logged database keys in order for the modification to persist. Debug logging can impact system performance. For more information, refer to K15530: Debug logging and BIG-IP system resource utilization.
