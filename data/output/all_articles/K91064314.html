Description

This article describe a behavior and the solution of the BIG-IP resetting connections while downloading files.
In a traffic capture taken on the BIG-IP, it can be seen that the BIG-IP is sending RST to the backend server:
1740    2021-08-11 09:56:20.989790    10.0.0.14    192.168.0.93    1    443 → 49295 [RST, ACK] Seq=2718194630 Ack=469046052 Win=0 Len=0
On LTM log, the following error message appears at the time of the reset for the given client:
Aug 11 09:56:20 ltm1.example.com err tmm16[30102]: 011f0016:3: http_process_state_prepend - Invalid action:0x10a010 Server sends too much data. serverside (10.0.0.2:80 -> 10.0.0.13:46312) clientside (192.168.0.93:49295 -> 10.0.0.14:443) (Server side: vip=/Common/VS-443 profile=http pool=/Common/pool1 server_ip=10.0.0.2)

Environment

  • A BIG-IP with virtual server configured with a HTTP profile
  • The BIG-IP system receives a response from the pool member that either contains more data than indicated in the Content-Length header or has additional data following the ending chunk of a chunked response

Cause

The virtual server is configured with an HTTP profile and the BIG-IP system receives a response from the pool member that either contains more data than indicated in the Content-Length header or has additional data following the ending chunk of a chunked response.
If the error message occurs as a result of processing HTTP traffic, the message indicates that the response received from the back-end server is not RFC compliant.
The back-end server should be modified to correct this behavior.

    Recommended Actions

    1.  To work around this issue on the BIG-IP system, you can configure the affected virtual server to use an iRule that removes the Content-Length HTTP header from the server response.
      For example, you can use an iRule similar to the following:
      when HTTP_RESPONSE {
        if { [HTTP::header exists "Content-Length"]}{
          HTTP::header remove "Content-Length"
        }
      }

    Additional Information

    Note: This error message may occur more frequently in BIG-IP 12.1.0 and later. Beginning in BIG-IP 12.1.0, this error message is triggered if the excess data is included in either the same packet or an additional packet. For previous versions, the error message would only be triggered if the excess data was received in an additional packet.
