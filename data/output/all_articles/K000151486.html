K000151486: Does removing the signature and signscope fields entirely bypasses the RDP signature validation mechanism in APM?

Type
Support Solution
Published
2025-05-22
Updated
2025-05-22
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000151486

Description

When using BIG-IP APM to provide native RDP resources, users may modify downloaded .rdp files by removing the `signature` and `signscope` fields. In this case, users can alter redirection control settings (such as enabling clipboard or drive redirection) and successfully establish a connection without any warning or error. If the .rdp file is edited but the `signature` and `signscope` fields remain present, the connection attempt fails with a corruption or signature error as expected.

Environment

  • BIG-IP APM
  • RDP signature validation
  • Bug ID 423519
  • Native RDP resource publishing via APM

Cause

BIG-IP APM enforces RDP file signature validation only when the `signature` and `signscope` fields are present in the .rdp file. If these fields are removed entirely, APM does not perform signature validation or enforce rejection of unsigned files. This allows users to bypass redirection controls by using modified or unsigned .rdp files.

Recommended Actions

  • There is no current mechanism in BIG-IP APM to reject .rdp files that are missing the `signature` and `signscope` fields.
  • To prevent users from bypassing redirection controls, enforce these restrictions on the RDP server itself using Windows Group Policy (GPO):  
    • Use GPO settings such as "Allow .rdp files from unknown publishers" or "Allow .rdp files from valid publishers and user's default .rdp settings" to restrict connections from unsigned or modified .rdp files.
    • Enforce redirection control policies (e.g., clipboard, drive, printer redirection) directly on the RDP server.
       No additional configuration options exist within APM to address this limitation.
  • This is a known limitation of the current implementation of BIG-IP APM.
