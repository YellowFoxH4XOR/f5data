Topic

This article applies to BIG-IP ASM 11.4.0 - 12.0.0. For information about other versions, refer to the following articles:

  • K40345000: Bypassing the BIG-IP ASM system for connections that use RPC over HTTP (12.1.0 and later)
  • K7869: Bypassing the BIG-IP ASM system for connections that use RPC over HTTP (9.2.0 - 11.3.0)

Purpose

You should consider using this procedure under the following condition:

  • You want to bypass the BIG-IP ASM system for connections that use remote procedure call (RPC) over HTTP.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP ASM system.
  • You have basic working knowledge of either iRules or the Local Traffic Policy feature.
  • You have an existing BIG-IP ASM virtual server.

Description

The BIG-IP ASM system does not currently support RPC over HTTP. Some Microsoft Outlook implementations use RPC over HTTP to facilitate connections to the Microsoft Exchange server. Typically, these requests can be identified by the following unique HTTP attributes:

  • HTTP path/URI: /rpc/rpcproxy.dll
  • HTTP methods: RPC_IN_DATA or RPC_OUT_DATA

The BIG-IP ASM system will block these requests and log the following violation:

Request blocked, violations: Illegal method.

Note: Because the RPC data payload is in binary form, there is minimal security benefit for the BIG-IP ASM system to perform security enforcement on the RPC message data over HTTP.

Procedures

You can configure an iRule or a local traffic policy rule to bypass the BIG-IP ASM system for connections that use RPC over HTTP. To do so, perform the following procedures:

Configuring a Local Traffic Policy rule to bypass the BIG-IP ASM system

For BIG-IP ASM 11.4.0 through 12.0.0, you can modify the existing BIG-IP ASM-enabled local traffic policy by adding new rules to bypass BIG-IP ASM for the RPC over HTTP requests. When you complete the procedure, the local traffic policy should contain rules with the following logic:

  • Disable BIG-IP ASM when the URI contains /rpc/rpcproxy.dll
  • Disable BIG-IP ASM when the HTTP method is RPC_IN_DATA
  • Disable BIG-IP ASM when the HTTP method is RPC_OUT_DATA
  • Enable BIG-IP ASM for all remaining traffic

To create local traffic policy rules that disable BIG-IP ASM for connections that use RPC over HTTP, perform the following procedure:

Impact of procedure: The default BIG-IP ASM-enabled local traffic policy uses the first-match strategy, hence reordering rules in an incorrect priority may yield unexpected results. Ensure that the order of the rules meets the requirements for your application environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the BIG-IP ASM-enabled virtual server.
  4. Click the Resources tab.
  5. In the Policies section, click the name of the desired BIG-IP ASM-enabled local traffic policy.
  6. In the Rules section, click Add to create a new rule.
  7. In the Rule Name section, type a name for the rule to disable ASM for URIs containing /rpc/rpcproxy.dll.

    For example, URI-rpc.

  8. In the Conditions section, add the condition for HTTP URI path, /rpc/rpcproxy.dll. To do so, select or enter the following options for the described settings using the HTTP attributes:
    • Operand: http-uri
    • Event: request*
    • Selector: path
    • Condition: equals
    • Values: /rpc/rpcproxy.dll
  • For the Values setting, click Add to add the URI value you entered.
  • In the Conditions section, click Add to add the condition to the table.
  • In the Actions section, select the the following values for the Target, Event and Action settings:
     
    • Target: asm
    • Event: request
    • Action: disable
  • In the Actions section, click Add to add the action to the table.
  • Click the Finished button to save the rule.
  • In the Rules section, click Add to create a new rule.
  • In the Rule Name section, type a name for the rule to disable ASM for the RPC_IN_DATA HTTP method.

    For example, RPC_IN_DATA.

  • In the Conditions section, add the condition for RPC_IN_DATA HTTP method. To do so, select or enter the following options:
     
    • Operand: http-method
    • Event: request*
    • Selector: all
    • Condition: equals
    • Values: RPC_IN_DATA
  • For the Values setting, click Add to add the RPC_IN_DATA value to the condition.
  • In the Conditions section, click Add to add the condition to the table.
  • In the Actions section, select the the following values for the Target, Event and Action settings:
     
    • Target: asm
    • Event: request
    • Action: disable
  • In the Actions section, click Add to add the action to the table.
  • Click the Finished button to save the rule.
  • In the Rules section, click Add to create a new rule.
  • In the Rule Name section, type a name for the rule to disable ASM for the RPC_OUT_DATA HTTP method.

    For example, RPC_OUT_DATA.

  • In the Conditions section, add the condition for RPC_OUT_DATA HTTP method. To do so, select or enter the following options:
     
    • Operand: http-method
    • Event: request*
    • Selector: all
    • Condition: equals
    • Values: RPC_OUT_DATA
  • For the Values setting, click Add to add the RPC_OUT_DATA value to the condition
  • In the Conditions section, click Add to add the condition to the table.
  • In the Actions section, select the the following values for the Target, Event and Action settings:
     
    • Target: asm
    • Event: request
    • Action: disable
  • In the Actions section, click Add to add the action to the table.
  • Click the Finished button to save the rule.
  • On the Local Traffic Policies List page, click the name of the BIG-IP ASM-enabled local traffic policy.
  • In the Rules section, click Reorder.
  • Drag the BIG-IP ASM bypass rules that you created in steps 7 through 29 to prioritize them over the default rule for the BIG-IP ASM-enabled local traffic policy.
  • To save the changes, click Update.

Configuring an iRule to bypass the BIG-IP ASM system and associating the iRule with the BIG-IP ASM virtual server

You can configure an iRule and associate it with the BIG-IP ASM-enabled virtual server to bypass the BIG-IP ASM system for RPC over HTTP requests. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Click Create.
  6. In the Name field, type a name for the iRule.
  7. In the Definition field, type the iRule syntax.

    Note: The following iRule may not apply to all environments. F5 recommends that you author an iRule that works best for your application environment. Additionally, adding an iRule will increase the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any changes in an appropriate environment.

    BIG-IP ASM 11.4.0 and later

    when HTTP_REQUEST {
    if { ([HTTP::path] eq "/rpc/rpcproxy.dll") and \
    (([HTTP::method] equals "RPC_IN_DATA") or ([HTTP::method] equals "RPC_OUT_DATA"))}{
    ASM::disable
    log local0. "ASM disabled."
    } else {
    ASM::enable /Common/myasmpol
    log local0. "ASM enabled. Current ASM policy is [ASM::policy]"
    }
    }

  8. Click Finished.
  9. Click Local Traffic.
  10. Click Virtual Servers.
  11. Click Virtual Server List.
  12. In the Resources column for the desired BIG-IP ASM-enabled virtual server, click Edit.
  13. In the iRules section, click Manage.
  14. In the Available box, select the iRule that you created in the previous procedure.
  15. Click << to move the desired iRule to the Enabled box.
  16. Click Finished.
