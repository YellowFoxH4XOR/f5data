Topic

The BIG-IP ASM system may send SNMP traps to report request violations and requests that the system blocked. However, this level of reporting may not be desired or useful. In some cases, the SNMP network manager may not be able to handle the volume of such SNMP traps sent by the BIG-IP ASM system. In other cases, the administrator may want to monitor the same information using a syslog server or a remote logging profile. You can prevent the BIG-IP ASM system from sending SNMP traps for BIG-IP ASM related violations by modifying the alertd configuration.

Note: For BIG-IP ASM 9.4.2 and later, configuring a remote syslog server or using remote logging profiles will provide more detailed information for monitoring and archival purposes. For more information refer to the Configuration Guide for BIG-IP Application Security Management.

Preventing the BIG-IP ASM system from sending SNMP traps for BIG-IP ASM related violations

Important: Do not edit the /etc/alertd/alert.conf file. You should make all changes to the /config/user_alert.conf file as detailed in the following steps. Changes to the alert.conf file may be lost.

  1. Log in to the command line.
  2. Open the /etc/alertd/alert.conf file and locate the following heading:

    /*
     * from trafficshield (ts)
     */

  3. Under the trafficshield heading, copy all of the traps that you want to disable to the clipboard or a temporary file.

    For example:

    alert BIGIP_TS_TS_REQUEST_BLOCKED {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.38"
    }
    alert BIGIP_TS_TS_REQUEST_BLOCKED_EMERG {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.38"
    }
    alert BIGIP_TS_TS_REQUEST_BLOCKED_ALERT {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.38"
    }

  4. Close the /etc/alertd/alert.conf file.
  5. Back up the existing user_alert.conf file by typing the following command:

    cp /config/user_alert.conf /config/user_alert.conf.SOL9896

  6. Using a text editor, open the user_alert.conf file.
  7. Paste the text you copied in step 3.
  8. Disable the SNMP trap by commenting out the snmptrap OID definition, by using the following syntax:

       /* <-- Start of comment
       snmtrap OID="<OID>"
       */ <-- End of comment

    For example:

    /*Disabled ASM request violations and blocks (Disabled 04/27/2009)*/

    alert BIGIP_TS_TS_REQUEST_BLOCKED {
    /*        snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.38" */
    }
    alert BIGIP_TS_TS_REQUEST_BLOCKED_EMERG {
    /*        snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.38"  */
    }
    alert BIGIP_TS_TS_REQUEST_BLOCKED_ALERT {
    /*        snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.38"  */
    }

  9. Save the changes you made to the user_alert.conf file.
  10. Restart the alertd process to load the file changes by typing the following command:

    bigstart restart alertd
