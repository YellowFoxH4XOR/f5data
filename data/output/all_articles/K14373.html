Known Issue

The ZoneRunner utility may fail to display the properties page for resource records in a subdomain.

This issue occurs when all of the following conditions are met:

  • Resource records are configured in a subdomain within a zone.
  • You attempt to view the properties page for an affected resource record using the ZoneRunner utility.

Using the following test.net zone, for example, the ZoneRunner utility properly displays the information for all resource records in the Resource Record List view. However, if you attempt to select individual resource records, the ZoneRunner utility fails to display the properties page for the mail1 and ns2 resource records configured in the sub.test.net zone.

$ORIGIN .
$TTL 30 ; 30 seconds
test.net IN SOA gtm1.test.net. hostmaster.gtm1.test.net. (
2013042505 ; serial
10800 ; refresh (3 hours)
3600 ; retry (1 hour)
604800 ; expire (1 week)
86400 ; minimum (1 day)
)
NS ns1.test.net.
$ORIGIN test.net.
sub NS ns2.sub
$ORIGIN sub.test.net.
mail1 A 10.10.10.3
MX 10 mail1
ns2 A 10.10.10.2
$ORIGIN test.net.
ns1 A 10.10.10.1

Impact

You cannot modify individual resource records in a subdomain using the ZoneRunner utility. However, domain query responses are not affected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H419392 on the Diagnostics > Identified > Low screen.
  • When selecting an affected record, the ZoneRunner utility displays a message similar to the following example:

    Resolver returned no such record

Workaround

There is no workaround for this issue. However, you can modify an affected resource record by editing the zone file from the command line. For information, refer to K7032: Freezing zone files to allow manual update to ZoneRunner-managed zone files.

Impact of workaround: The procedure interrupts the BIG-IP GTM system's ability to perform BIND name resolutions for the zone specified.

Alternatively, instead of modifying an affected resource record using the ZoneRunner utility, you can delete and add the affected resource record again. To do so, perform the following procedure:

Impact of workaround: BIND name resolutions for the affected resource record are not available while the record is deleted.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Global Traffic.
  3. Click ZoneRunner.
  4. Click Zone List.
  5. Select the desired zone.
  6. Click Resource Records.
  7. Select the check box next to the affected resource record.
  8. Click Delete.
  9. To confirm the record deletion, click Delete.
  10. Click Create.
  11. In the Name box, type a record name.
  12. From the Type menu, select the appropriate record type.
  13. Enter values for the new resource record.
  14. Click Finished.
