K000156017: HTTP protocol support changes for OCSP and CRL certificate status checks

Type
Support Solution
Published
2025-09-16
Updated
2025-09-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 17.1.2, 17.1.1, 17.5.X, 17.1.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000156017

Description

Outbound OCSP and CRL traffic from the BIG-IP towards OCSP responders like Digicert are using HTTP/1.0. However, Digicert is sunsetting support for HTTP/1.0 and requires requests to use HTTP/1.1 or use proper Host headers.

 

Environment

LTM Auth profile

OCSP Authentication

 

Cause

BIG-IP is using a version of openssl that uses HTTP/1.0 to send OCSP and CRL queries

 

Recommended Actions

The OSCP requests needs to be passed through a Virtual Server where an iRule similar to the one below can be attached.

 

when HTTP_REQUEST {

HTTP::version "1.1"

HTTP::host "ocsp.digicert.com"

}

 

Additional Information

Using the workaround might not be scalable for some environments but it is the only available method to get OCSP and CRL requests to use HTTP/1.1. Plans are in place to upgrade openssl version so that future releases of the BIG-IP software will use HTTP/1.1 by default.
