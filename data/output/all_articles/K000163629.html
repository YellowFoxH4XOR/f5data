K000163629: Kerberos SSO Fails After Successful SAML/APM Login

Type
Support Solution
Published
2026-11-02
Updated
2026-11-02
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163629

Description

Users log in to BIG-IP APM successfully, but Kerberos single sign-on (SSO) to the backend IIS application fails. The IIS and Windows Security logs may show no corresponding authentication attempt.

/var/log/apm may contain the following message:

Halted SSO retry for request

Environment

  • BIG-IP APM
  • Kerberos SSO constrained delegation to an IIS application

Cause

Kerberos SSO can fail when the backend server SPN required for delegation is missing from the Active Directory configuration. The keytab must include the SPN for the BIG-IP virtual server and the SPN for the backend service. Without the backend service SPN, BIG-IP APM cannot obtain or use the required S4U2Proxy ticket.

Answer/Recommended Actions

  1. Ensure that both the BIG-IP virtual-server SPN and the backend server-name SPN are registered for the Kerberos service account.
  2. Generate or obtain a new keytab containing all required SPNs.
  3. Import the updated keytab into the BIG-IP Kerberos delegation configuration.
