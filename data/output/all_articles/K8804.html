Known Issue

This is the result of a known issue. The findclass iRule command searches a data group list for a member that starts with a specified string, and returns the data group member string. Using the findclass iRule command to search a data group containing IP addresses may cause TMM to crash.

For example, the following iRule references a Host data group called hostclass, containing an IP address of 10.1.1.1:

when CLIENT_ACCEPTED {      set fc [findclass [client_addr] $::hostclass]      log local0. "findclass found $fc"}class hostclass {   host 10.1.1.1}

When the BIG-IP processes a connection that traverses the iRule, TMM may crash.

F5 Product Development tracked this issue as CR93913 and it was fixed in BIG-IP version 9.4.5. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

To work around this issue, use the matchclass iRule command to perform a comparison against a data group.

For example:

when CLIENT_ACCEPTED {  if { [matchclass [IP::client_addr] equals $::hostclass] } {      pool http_pool  }}
