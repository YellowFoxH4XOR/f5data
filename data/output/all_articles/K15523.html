K15523: New latency compression strategy and compression provider selection method

Issue

On most F5 platforms, the BIG-IP system can compress end-user traffic using hardware offload or software. These two mechanisms for compression have different behaviors. Software can compress traffic at a higher quality, while hardware offload can compress traffic at higher rates and also at a lower CPU cost. Mechanisms providing compression services offload are called providers. A series of strategies exist to guide the compression codec to select the provider.

Old Behavior

In versions prior to BIG-IP 11.6.0, the default compression strategy is speed. The speed compression strategy focuses requests toward hardware compression, regardless of desired quality (gzip level).  The compression provider is determined at the time of client connection prior to the server response, and is maintained until the connection is terminated, even if the server does not present compressible traffic.

Additionally, if a server is slow or does not respond, the system will queue the request and allocate the compression resources. When connections have consumed all hardware resources, the system shifts to software compression, which may not be the optimal choice if the resources have been consumed by connections that do not require any compression services.

New Behavior

Beginning in BIG-IP 11.6.0, the default strategy is the newly introduced latency strategy. The latency strategy uses the average load of the hardware and software providers to choose the best compression method for the request. Additionally, the system waits until the first xbuf arrives from the server before determining a compression provider. By waiting for the server response to select the compression provider, rather than making the selection at the client connection, resources are no longer allocated for a non-responsive server and are available for other requests.

Note: The size, ratio, and adaptive compression strategies were not altered. 

Impact

There is an improved selection of hardware or software compression providers. Resources are no longer allocated for a non-responsive server.

Recommended Actions

  • To view the current compression provider strategy, type the following command:

    tmsh list sys db compression.strategy

  • If the new latency strategy introduces unexpected behavior, you can revert to the previous compression strategy used. To do so, use the following command syntax:

    tmsh modify sys db compression.strategy value <latency|speed|size|ratio|adaptive>

    For example, to revert to the default compression strategy used in BIG-IP versions prior to 11.6.0, you would enter the following command:??

    tmsh modify sys db compression.strategy value speed
