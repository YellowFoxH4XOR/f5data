Topic

You should consider using this procedure under the following condition:

  • You would like to deploy a BIG-IP Virtual Edition (VE) that requires multiple elastic network interfaces (ENIs) on Alibaba Cloud.

Description

If you deploy an instance in Alibaba Cloud that requires more than two ENIs, you must deploy the instance initially with only two bound ENIs. Alibaba sets this limitation when you deploy the initial instance. You subsequently modify the instance so you can add more ENIs. The following procedures guide you in deploying a new BIG-IP VE instance by creating the overlaying Virtual Private Cloud (VPC), the underlying virtual switches (VSwitches - interface network ranges), and Security Groups (sets of firewall rules).

Important: All configuration objects must use the same Alibaba Region and Availability Zone.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have an active user account for Alibaba Cloud (Aliyun).
  • Have a general understanding of cloud infrastructure.
  • Are familiar with the Alibaba ECS Console.
  • Know your billing method for the BIG-IP VE deployment (Subscription or Pay-As-You-Go).
  • Know the Alibaba Region and Zone for the deployment.
  • Know the Instance Type (capacities) to use for the BIG-IP VE.

    Important: Ensure that the Instance Type supports the required number of ENIs for your deployment.

    For more information, refer to: Instance Families on Alibaba Cloud.

    Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

  • Have selected the appropriate F5 Marketplace Image for your deployment.

Procedures

  • Creating the VPC
  • Creating Security Groups
  • Initially deploying the BIG-IP VE instance
  • Performing post BIG-IP VE deployment steps
  • Creating Secondary Private IP addresses
  • Licensing and configuring the BIG-IP system

Note: Perform all steps in the Alibaba Cloud ECS Console.

Creating the VPC

Creating a VPC is the central piece to your virtual private cloud for the BIG-IP VE deployment. The following procedure walks you through creating the VPC using the Alibaba provided CIDR Block of 10.0.0.0/8.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Go to Network & Security > VCP.
  2. Select Create VCP.
  3. For Name, enter a name for the VPC (for example, BIGIP_VPC).
  4. For IPv4 CIDR Block, F5 recommends that you use the provided default CIDR Block of 10.0.0.0/8 that will be subnetted.
  5. For the initial VSwitch 0 (eth0), enter a logical name (for example, MGMT).

    Note: This first ENI interface defaults to the BIG-IP management interface.

  6. Select the Zone for the VSwitch.

    Important: The same Region and Zone must be used for all configuration objects.

  7. Leave the IPv4 CIDR Block at the default, 10.0.0.0/24.
  8. Select (+) Add to add an additional VSwitch.
  9. For the VSwitch 1 (eth1), enter a logical name (for example, External).

    Note: This will be automatically mapped to the BIG-IP VE network interface 1.1.

  10. Modify the 3rd octet of the CIDR Block to use "1" (10.0.1.0/24).
  11. Select OK.
  12. Select Complete.

Creating Security Groups

Security Groups behave much like firewall rules, allowing or disallowing specific network traffic. A Security Group is a deny-by-default configuration. The following procedure walks you through creating three Security Groups: MGMT, External, and Internal. In subsequent procedures, each of the Security Group configurations are aligned with an ENI.

Impact of procedure:  An improperly applied Security Group may disallow legitimate traffic or allow unwanted access.

  1. Go to Network & Security > VPC.
  2. Select the newly created VPC.
  3. Select the Actions > Manage link.
  4. Locate Security Groups and select the 0 (zero) link.
  5. Select Create Security Group.
  6. For Template, select Customize.
  7. Enter the name for the Security Group.

    Note: F5 recommends that you use names that logically map to the VSwitch to which the Security Group will be applied.

  8. Set VPC to the VPC name of the previously created VPC (for example, BIGIP).
  9. Select OK.
  10. Select Create Rules Now.
  11. Select Add Security Group Rule.
  12. Repeat step 8 for each Port Range.
  13. Select OK.
  14. Repeat steps 3 through 9 for each Security Group (for example: MGMT, External, and Internal).

Initially deploying the BIG-IP VE instance

The following procedure walks you through creating a BIG-IP VE instance that includes the management network interface (MGMT) ENI and the external network interface (External). However, before the BIG-IP VE instance is configured, the deployment requires additional steps in order to include the internal network interface (Internal).

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Go to Elastic Compute Services > Instances.
  2. Select Create Instance.
  3. Set the Billing Method.
  4. Set the Region and Zone.
  5. Set the Instance Type attributes for Family (see Instance Families on Alibaba Cloud).

    Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

  6. Select MarketPlace Image.
  7. Select the Select from image Marketplace (including operating system) link.
  8. For Search Image, enter f5.
  9. Select Continue for the F5 Networks Virtual Edition you want.
  10. Select Next: Networking.
  11. For VPC, enter the VPC name you created in the Creating the VPC procedure.
  12. For VSwitch, enter the MGMT VSwitch you created in the Creating the VPC procedure.
  13. Select the checkbox for Public IP Address > Assign Public IP.
  14. For Security Group, enter the management interface Security Group name (from the example: MGMT) that you created in the Creating Security Groups procedure.
  15. In the Elastic Network Interface section, select (+) Add ENI.
  16. For VSwitch, enter the external VSwitch name (for example, External).

    Note: The Security Group used for the initial VSwitch (from the example: MGMT) is automatically assigned to this ENI and cannot be modified on this page. This will be modified in a subsequent procedure.

  17. Select Next: System Configurations.
  18. For Logon Credentials, select Key Pair (the default).
  19. For Key Pair, select an existing key pair or select Create Key Pair.
  20. For Instance Name, enter a name that is logical to your deployment.
  21. For Host, enter a host name.

    Note: This is a required step by the page but is not applied to the BIG-IP VE instance.

  22. Select Next: Grouping.
  23. Set any Tags that are appropriate for your deployment.
  24. Select Next: Preview.
  25. Select Terms of Service.
  26. Verify the configuration and select Create Instance.

Performing post-BIG-IP VE deployment steps

When you initially deploy the BIG-IP VE instance, the external network interface (External) Security Group defaults to the same security group as the management interface. The following procedure modifies the external ENI (External) to use the Security Group for External, which you created in the Creating Security Groups procedure. Additionally, the procedure creates a 3rd ENI for the internal network interface and the ENI is bound to the BIG-IP VE instance.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

Modifying the Security Group for the External ENI to use the External Security Group.

  1. Go to Network & Security > ENIs.
  2. For the External ENI, select Modify.
  3. For Security Group, select the external security group (from the example, External).
  4. To the right of the originally aligned Security Group (from the example, MGMT) select Remove.
  5. Select OK.

Creating the internal VSwitch

  1. Go to Network & Security > VPCs.
  2. Locate the VPC created in the Creating the VPC procedure.
  3. Select Actions > Manage.
  4. For VSwitches, select the 2 (two) link.
  5. Select Create VSwitch.
  6. Select the VPC you created in the Creating the VPC procedure.
  7. For Name, enter a name for the new VSwitch (for example, Internal).
  8. For Zone, select the zone for the VSwitch.

    Important: You must use the same Region and Zone for all configuration objects.

  9. Modify the 3rd octet of the CIDR Block to use 2 (10.0.2.0/24).
  10. Select OK.
  11. Go to Network & Security > ENIs.
  12. Select Create ENI.
  13. For Name, enter a logical name for the new ENI (for example, Internal).
  14. Select the VPC that you created in the Creating the VPC procedure.
  15. For Primary IP Address, enter the self IP address for the BIG-IP VE for the network range 10.0.2.0/24.
  16. For Security Group, select the Internal security group that you created in the Creating Security Groups procedure.
  17. Select OK.
  18. For the newly created ENI, select the Bind to Instance link.
  19. Select the previously created BIG-IP VE instance name.
  20. Select OK.

Note: This article covers BIG-IP VE deployments where the BIG-IP system is configured with a total of three network interfaces (ENIs). To add more ENIs, repeat steps 5-20, and modify the VSwitch name and the 3rd network octet of the CIDR Block to create a unique network subnet for each VSwitch. You can reuse an existing Security Group if the configuration matches your network security requirements.

Rebooting the BIG-IP VE instance

For the system to recognize the newly created ENIs, you must restart the BIG-IP VE instance before activating and configuring the BIG-IP system.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Go to Instances.
  2. Locate the BIG-IP VE instance that you previously created.
  3. Select the checkbox to the left of the Instance ID/Name.
  4. Select Restart.
  5. Select Force Restart.
  6. Select the Proceed to Forcibly Restart checkbox.
  7. Select OK.

Creating Secondary Private IP addresses

When you configure the IP addresses used by the BIG-IP instance, configure the Primary Private IP Addresses as the BIG-IP self IP addresses. You can create multiple Secondary Private IP Addresses for each ENI. The BIG-IP VE instance will be manually configured to re-use these addresses for virtual server addresses. If you want public access to the BIG-IP virtual server addresses, you can purchase elastic IP addresses (EIPs) and bind the public EIP to the Secondary Private IP Addresses.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Go to Network & Security > ENIs.
  2. For the External ENI, select the Manage Secondary Private IP Address link.
  3. Select the Assign New IP link.
  4. For IPv4 Addresses, enter the private IP address that you want to use for a BIG-IP VE virtual server.
  5. Select OK.
  6. Repeat steps 2 through 4 for each intended virtual server private IP address.

    Important: Alibaba permits a total of nine secondary private IP addresses.

Licensing and configuring the BIG-IP system

This article does not cover the bring your own license (BYOL) licensing with configuring the BIG-IP VE instance. For more information on that, refer to the Initial Configuration chapter of the BIG-IP System guide.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

When you configure your BIG-IP VE instance, consider the following:

  • Configure the BIG-IP self IP addresses to use the Alibaba-assigned Primary Private IP for each ENI network as listed in the Alibaba ECS Console Network & Security > ENI.
  • For Secondary Private IP Addresses, create a new EIP NAT mode and bind these EIPs to the Secondary Private IP Address that represents the BIG-IP system's configured virtual servers.
  1. Go to Network & Security > EIP.
  2. Select Create EIP.
  3. Select the Region for the EIP.
  4. For Network Mode, select the appropriate Network Mode for your deployment (By traffic or By bandwidth).
  5. For Quantity, enter the number of virtual server addresses configured on the BIG-IP VE instance.
  6. Select Buy Now.
  7. Go to Network & Security > EIP.
  8. For each EIP address, select Bind.
  9. For Instance Type, select Secondary ENI.
  10. For Mode, select NAT Mode.
  11. Select the Secondary Private IP that is configured on the BIG-IP VE instance as a virtual server address.
  12. Select OK.
