Description

After adding new pool members, the statistics show discrepancies and connections are not seen on the backend servers.

Environment

  • Pool
  • Virtual Server
  • Statistics

Cause

Intermediate device is blocking BIG-IP's connection attempts to pool members.

Recommended Actions

  1. Review the connection table for active connections to the pool members in question:

    show sys connection ss-server-addr <pool member IP> ss-server-port <pool member port>

  2. If there are active connections, determine the self IP used for monitoring

    ip r g <pool member ip>

  3. Take a packet trace, using an appropriate syntax:

    tcpdump -s0 -vnni 0.0:nnn -C 1000 -w /shared/tmp/pool_tshoot.pcap host < pool member ip> and <pool member port> and not <monitor self ip determined from step 2>

    • K411: Overview of packet tracing with the tcpdump utility

  4. Review the packet trace for symptoms of connection problems from the BIG-IP to pool member

    • K1893: Packet trace analysis

    One common symptom of connection issues is TCP retransmissions.

    A tshark command similar to the following may be used to see retransmissions:

    tshark -r /shared/tmp/pool_tshoot.pcap -Y 'tcp.analysis.retransmission'

    Note: If there are many TCP SYN retransmissions, it is likely an intermediate device is blocking connections to the pool member.

Additional Information

Certain configuration, such as persistence, may also cause uneven load balancing of connections to pool members. See the following article for more information:

  • K10430: Causes of Uneven Load balancing
