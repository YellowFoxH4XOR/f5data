Description

BIG-IP in a cluster reports error message about expired EM Certificate for gossip communication.

 

  • Client 192.0.2.10 relates to certificate with IP name
  • Certificate stored in as /shared/em/ssl.crt/192.0.2.10.crt
  • Certificate is reported expired even though it is valid
  • Error messages logged in /var/log/httpd/httpd_errors and /var/log/secure

err httpd[PID]: [auth_f5_auth_token:error] [pid 10997] [client 192.0.2.10:23452] Got exception while handling EM auth token request: Invalid Certificate: Certificate has expired., referer: http://localhost:8100/shared/gossip

Environment

  • BIG-IP cluster managed by BIG-IQ
  • BIG-IQ upgraded to 8.4.x
  • BIG-IP cluster no longer managed by BIG-IQ
  • Any BIG-IP products managed by BIG-IQ

Cause

BIG-IP cluster managed by BIG-IQ use certificate/key provided by BIG-IQ stored under device-group-key-pairs/tm-shared-all-big-ips. Device group device-group-key-pairs/tm-shared-all-big-ips was used by BIG-IQ prior to 8.4.0 as such if prior BIG-IQ is upgraded certificate/key stored under "device-group-key-pairs/tm-shared-all-big-ips" becomes orphaned and cannot be updated by BIG-IQ. If the certificate expires that will cause BIG-IPs in cluster to log error message indicating their own certificates as expired which is misleading.

Answer/Recommended Actions

Check for the actual certificate which is expired, use command.

 

restcurl /shared/device-group-key-pairs | jq -r '.items[] | { groupName,certificateId,generation,lastUpdateMicros }'

 

Check if "tm-shared-all-big-ips" or "cm-bigip-cluster_<device name>" or "cm-bigip-allBigIpDevices"

Verify the expiry date of the returned certificate.

Delete the entry from REST database where group name is "tm-shared-all-big-ips" or "cm-bigip-cluster_<device name>" or "cm-bigip-allBigIpDevices".

 

restcurl -X DELETE /shared/device-group-key-pairs/< group name >
