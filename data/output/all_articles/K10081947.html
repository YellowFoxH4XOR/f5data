Description

  • HTTP/2 stream is getting RST with COMPRESSION_ERROR(9)
  • The error does not reproduce after cleaning cookies
  • Open URLs without BIG-IP - no errors

Environment

  • HTTP2 profile is set for client side.

Cause

HTTP/2 profile default value for the max header-count is 64 - exceeding this value will cause a RST_STREAM.

It can be verified with a packet capture and use the following filter:

http2.header.count >64

Important: This is a specific case for Compression Error. There might be other cases where Compresssion Error can be seen.

Recommended Actions

If necessary, you can increase the Maximum Header-Count in the HTTP(1) profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility as the admin user.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Select the HTTP profile that handles your affected traffic.
  4. Change the Maximum Header Count to a higher value, such as 128.
  5. Click Update.
