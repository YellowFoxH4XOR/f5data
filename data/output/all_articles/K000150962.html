K000150962: Understanding and Monitoring Citrix ICA Flows with F5 BIG-IP APM

Description

APM, when deployed in front of Citrix StoreFront and Citrix servers, enables administrators to monitor and correlate incoming Citrix ICA connections with established APM sessions. The debug VDI logs generated by the APM module provide detailed information such as session IDs, session state, policy results, and resource requests. These logs allow identification of which APM session is associated with a specific ICA file request and the internal Citrix server being accessed. Example log entries:

debug vdi: ...: {xxxx.C} TMEVT_SESSION_RESULT
debug vdi: ...: {xxxx.C} 17GetSessionDBValue 'tmm.session.<session_id>.session.policy.result' = 'allow'
debug vdi: ...: {xxxx.C} Session state: 'allow'
debug vdi: ...: {xxxx.C} Found session '<long_session_id>'
debug vdi: ...: {xxxx.C} Request '/citrix/ivcsweb/resources/launchica/<resource>.ica'

Client-side events are marked with [xxxx.C] while server-side events use [xxxx.S].

Environment

APM

Citrix ICA

Cause

Citrix ICA traffic does not use HTTP headers or standard HTTP protocol elements, making it difficult to correlate ICA connections with APM sessions using traditional HTTP logging or iRules. However, enabling debug-level VDI logging on the BIG-IP provides sufficient detail to track these associations.

Recommended Actions

  • Enable Debug Logging for VDI and Access Policy
    1. Go to Access → Overview → Event Logs → Settings
    2. Create or edit a logging profile; enable Access System Logs.
    3. Set both Access Policy and VDI logging levels to Debug.
    4. Assign this profile to your relevant Access Profile.
    5. Monitor & Analyze Logs
  • Review /var/log/apm (and related files) for entries containing session IDs, states, policy results, and resource requests.

Use the session ID present in both authentication/session establishment logs and subsequent ICA resource requests to correlate activity.

Distinguish client-side ([xxxx.C]) from server-side ([xxxx.S]) events as needed.

  • Packet Capture for Advanced Troubleshooting

Use tcpdump on the BIG-IP to capture traffic between clients and backend Citrix servers:

tcpdump -s0 -ni 0.0:nnnp -w /var/tmp/<filename>.pcap --f5 ssl -vv host <client_ip> or host <citrix_backend_ip>

Analyze packet captures alongside debug logs for comprehensive troubleshooting.

  • Export Logs for External Monitoring

Forward debug logs to an external syslog server or SIEM solution if ongoing monitoring or alerting is required.

  • Revert Debug Settings After Troubleshooting

Once investigation is complete, set logging levels back to default values to avoid excessive log generation.
