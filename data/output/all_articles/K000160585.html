Description

When importing OpenAPI (Swagger) files into BIG-IP ASM (Application Security Manager), "Malformed JSON" errors occur during the provisioning process, with error messages including:

**Error Logs**

asm_config_server.pl|ERR|Mar 23 15:53:55.269|24792|F5::ASMConfig::Entity::JsonValidationFile::before_store,,Malformed JSON; JSON schema validation failed; Schema Syntax Error: /ts/var/tmp/json_schema_file_to_validate_24792

asm_config_server.pl|INFO|Mar 23 15:53:55.271|24792|F5::ASMConfig::Handler::handle_error,,Failed add for json_validation_file [file_contents = '{"required":["call_uuid"],"type":"object","title":"SummarizeLiveRequest"...

These errors occur even when the OpenAPI files pass external validation for OpenAPI compliance and JSON schema syntax.

Environment

  • Version: 17.5.1
  • Configuration: OpenAPI (Swagger) file import for security policy creation
  • JSON Schema properties using regex patterns similar to "^[a-z0-0-_]+$/i"

Cause

The root cause is the use of an unescaped hyphen (-) within a regex character class in the JSON Schema pattern property. In this context, the hyphen is interpreted as a range operator, which leads to a schema syntax error during ASM's validation process. Escaping the hyphen (\\-) corrects the pattern and allows successful import.

Answer/Recommended Actions

1.Review all regex patterns in the OpenAPI/Swagger file, especially those within character classes (square brackets).

2.Update affected patterns by escaping the hyphen character. For example:

  • Change "pattern": "^[a-z0-0-_]+$/i" to "pattern": "^[a-z0-0\\-_]+$/i"

3.Re-import the corrected OpenAPI file into ASM.

Additional Information

The error is expected behavior when regex syntax is incorrect in the schema.
