K000161788: Pool members are marked down on version 21.1.0

Type
Support Solution
Published
2026-06-22
Updated
2026-06-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 21.1.0
Source
https://my.f5.com/manage/s/article/K000161788

Description

After upgrading or installing BIG-IP devices to v21.1.x some monitor types may mark pool members down even if pool members are healthy.

Running tcpdump shows no monitor traffic is leaving BIG-IP for affected pool members.

If a monitor has a "recv-disabled" string and a particular pool member sends the "recv-disabled" string, it is possible that a different pool member is marked disabled (instead of the correct one)

Messaged similar to below can be observed in /var/log/bigd log file while enabling bigd debug

  • [1][1849] 2026-06-03 11:53:02.867125: ID 107 :(_do_ping): get kernel route failed; cannot determine management interface for address [ tmm?=false td=true tr=false addr=::ffff:192.168.0.1:443 srcaddr=::%0:6 ]

Attempting to restart bigd may bring some pool members up some down.

 Environment

  • BIG-IP LTM
  • bigd process using more than one thread
    To confirm if bigd is running with more than one thread, run bash command 'ps aux | grep bigd' and check what number is after '-P'.  Example output for two threads:

    root   15966   8735   0.2   0.3  158.0M   52.4M ?   S   Jun03   00:00:00.83 bigd -P 2

Cause

Bug ID2333437: Some monitor types might fail under v21.1 when bigd runs with multiple threads

 Answer/Recommended Actions

If you encounter this issue you may apply one of the following options for immediate workaround

  1. rollback to previous version of software
  2. apply workaround:
       tmsh modify sys db bigd.numprocs value 1
       tmsh save sys config
       bigstart restart bigd
    Note: Restarting bigd process will stop pool member monitoring and may bring them down until bigd is up

For permanent solution request an Engineering  Hot Fix  via support case
