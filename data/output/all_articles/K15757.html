Topic

You should consider using this procedure under the following conditions:

  • You want to rebuild a device trust for VIPRION devices or Virtual Clustered Multiprocessing (vCMP) guests running on VIPRION devices.
  • You configured the VIPRION devices or vCMP guests in high availability (HA) device groups.
  • You want to avoid an active-active situation between HA device group members.

Description

To rebuild a device trust for BIG-IP VIPRION devices or its vCMP guests configured in HA device groups, perform the following procedures:

Note: If a vCMP guest configured as a device group member is forced offline, its self IP addresses become unreachable and you will not be able to rebuild the device trust without both devices transitioning to an active state. The following procedures allow you to rebuild the device trust while avoiding an active-active situation.

Note: For vCMP guests, all of the work you perform in the following procedures is done from within the vCMP guest systems.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a BIG-IP VIPRION platform with multiple blades installed.
  • You have administrative access to the BIG-IP Configuration utility and the Traffic Management Shell (tmsh).

Procedures

  • Pre-work check list
  • Breaking the trust
  • Rebuilding the trust

Pre-work check list

Confirm the IP address and Device Management configuration for each BIG-IP system in the HA configuration. You should perform the following steps on each device in the device group.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, F5 recommends that you schedule this procedure during a maintenance window to minimize impact in mission critical environments.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Device Management > Devices.
  3. Select the device labeled (Self).
  4. Navigate to Device Connectivity > ConfigSync.
  5. Ensure that Local Address is set to the self IP address for the local BIG-IP system.
  6. Navigate to Device Connectivity > Failover Network.
  7. Ensure that at least one network is configured.

    Note: F5 recommends the management IP address and a self IP address from at least one Virtual Local Area Network (VLAN).

  8. Navigate to Network > Self IPs.
  9. Select the self IP that to use for synchronization.
  10. Ensure that Port Lockdown is set to either Allow All or Allow Default.
  11. Repeat this procedure on each device in the device group.

Breaking the Trust

  • Setting the Minimum Blades Up option from standby devices
  • Removing devices from the group and deleting the trust

Setting the Minimum Blades Up option from standby devices

Impact of procedure: Performing this procedure ensures that standby devices are not eligible to become active due to insufficient available blades in the chassis. F5 recommends that you schedule this procedure during a maintenance window to minimize impact in mission critical environments.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Set Minimum Blades Up to a number that is greater than the total number of blades in the chassis. For example, in a VIPRION chassis with four blades, set Minimum Blades Up to 5, by typing the following command:

    modify /sys cluster default min-up-members 5

  3. Enable the Minimum Blades Up setting by typing the following command:

    modify /sys cluster default min-up-members-enabled yes

    Note: You do not save the configuration at this point, since you do not want it to persist after a reboot.

Removing devices from the group and deleting the trust

Impact of procedure: Performing this procedure will remove the HA configuration from your environment. F5 recommends that you schedule this procedure during a maintenance window to minimize impact in mission critical environments.

Note: Perform this procedure first on the active device, then repeat on each standby device in the device group.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Device Management > Device Groups.
  3. Select the failover group from the list.
  4. Remove the standby member from the Device Group by selecting it from the Includes list and moving it to the Available list.
  5. Click Update.
  6. Navigate to Device Management > Device Trust > Peer List.
  7. Select the box to the left of the peer device and select Delete.
  8. Repeat this procedure on each standby device in the device group.

Rebuilding the trust

  • Rebuilding the trust from the active device
  • Rebuilding the trust from the standby devices
  • Confirming that each device recognizes the others
  • Disabling the Minimum Blades Up option from standby devices
  • Testing synchronization between devices

Rebuilding the trust from the active device

Impact of procedure: F5 recommends that you schedule this procedure during a maintenance window to minimize impact in mission critical environments.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Device Management > Device Trust > Local Domain.
  3. Under Trust Information, select Reset Device Trust.
  4. Under Certificate Signing Authority, select Retain Current Authority from the drop-down menu.
  5. Click Update.

    Important: This step breaks device trust for ALL devices in the group. In the event that you have more than two devices in your cluster, you will need to add all devices again.

  6. Navigate to Device Management > Device Trust > Peer List.
  7. Click Add, then add the Device IP Address, Administrator Username, and Administrator Password for the standby device.
  8. Click Retrieve Device Information.
  9. Click Finished.
  10. Navigate to Device Management > Device Groups.
  11. Select your failover group from the list.
  12. Add the standby member to the failover group by selecting it from the Available list, and moving it to the Includes list.

    Note: At this point, both the active and standby devices should be in the Includes list on the active device.

  13. Click Update.

Rebuilding the trust from the standby devices

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Device Management > Device Groups.
  3. Select your failover group from the list.
  4. Add the active member to the failover group by selecting it from the Available list, and moving it to the Includes list.

    Note: At this point, both the active and standby devices should be in the Includes list on the standby device.

  5. Click Update.
  6. Repeat this procedure for each of the standby devices in the device group.

Confirming that each device recognizes the others

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You should perform this procedure from each device in the device group, with similar output from each.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Confirm the cluster device failover state by typing the following command:

    list /cm device failover-state

    The output should appear similar to the following example:

    cm device bigip1.askf5.local {
        failover-state active
    }
    cm device bigip2.askf5.local {
        failover-state standby
    }

    Note: Each device should recognize the same devices as active. For example, both devices in the previous example should recognize bigip1 as the active device. The standby devices can be either standby or offline.

Disabling the Minimum Blades Up option from standby devices

Allow standby devices to once again participate in HA by removing the insufficient blades restriction that was previously set. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh by typing the following command:

    tmsh

  2. Set Minimum Blades Up back to the default setting by typing the following command:

    modify /sys cluster default min-up-members 1

  3. Enable Minimum Blades Up by typing the following command:

    modify /sys cluster default min-up-members-enabled no

    Note: If your systems were previously configured to use this configuration option, you can now revert the configuration back to its previous state.

Testing synchronization between devices

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

BIG-IP 11.3.0 and later

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Device Management > Overview.
  3. In the Devices section, select the device labeled (Self).
  4. Select Sync Device to Group.
  5. Click Sync.

BIG-IP 11.2.0 - 11.2.1

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Device Management > Device Groups.
  3. Select your device group.
  4. Select the ConfigSync tab at the top of the page.
  5. Click Synchronize To Group.
  6. To confirm the settings, click OK.

If either device fails to sync at this point, refer to K13946: Troubleshooting ConfigSync and device service clustering issues (11.x - 13.x).
