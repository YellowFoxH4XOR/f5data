Description

Vulnerability scanners may flag a BIG-IP to be revealing security information during responses that are generated internally.
This article describes a method of removing the flagged headers to conform to security requirements.

Environment

Note:  This will not affect the Server: value in the header for connections that are proxied from a pool member, please see K000140413: Securing BIG-IP: How to Remove Server Header Information in HTTP Responses

  • virtual server with HTTP profile applied
  • Local Traffic Policy that has a Redirect action, or iRule that executes HTTP::respond or HTTP::redirect

Cause

When the BIG-IP generates a HTTP response, it will insert information about the web server type into the response:

Server: BigIP

This server type information may be considered to be an Information Disclosure vulnerability by a vulnerability scanner or security audit.

Recommended Actions

The HTTP profile has the user-configurable option "Server Agent Name" which can be used to change the Server header to display an arbitrary value.
If this option is empty, then the Server header is not included in the BIG-IP generated response.
This can be configured using the Configuration Utility, or from the CLI:

# tmsh create ltm profile http http_noserver server-agent-name none defaults-from http 

ltm profile http http_noserver {
    app-service none
    defaults-from http
    server-agent-name none
}
