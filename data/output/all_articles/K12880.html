Topic

You should consider using these procedures under the following condition:

  • You receive a replacement BIG-IP device from F5 after receiving a Return Materials Authorization (RMA) for a device that you suspect is defective.

Description

When F5 dispatches a new BIG-IP device as a replacement for a suspected defective device, you must perform a series of procedures to configure the new device to match the archived configuration of the defective device.

Prerequisites

You must meet the following prerequisites to perform the procedures in this article:

  • You disabled mirroring for a redundant pair of BIG-IP systems with mirroring enabled by performing the steps described in K8086: Replacing a BIG-IP system in a redundant pair without interrupting service.
  • You have power and physical connectivity, as appropriate, for your environment.
  • You have a user configuration set (UCS) archive from the suspected defective device, and the UCS archive is from a known good state.

    Note: If the device is running BIG-IP 11.x or later, and you do not have a UCS archive, refer to K13551: Configuring a replacement BIG-IP device after an RMA when no UCS archive is available.

  • You installed and configured the replacement device with the same version of software you were using when you created the UCS archive. For more information, refer to the Software installation and configuration section of K12882: Overview of the F5 RMA process.
  • You have a base registration key for the replacement device.

    Note: You should have received an email from F5 Support that includes a base registration key for the replacement device. If you did not receive a base registration key for the replacement device, contact F5 Support.

  • If your restored system contains the FIPS 140 hardware security module (HSM), refer to the Recovery Options chapter of the BIG-IP Platform: FIPS Administration manual for information about recovering FIPS information after a system recovery.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Procedures

Configure the new device to match the archived configuration of the defective device by performing the following procedures:

  • Configuring networking options for the management interface
  • Activating the license for the new hardware
  • Importing and installing the archived configuration (10.x and later)

Configuring networking options for the management interface

  1. Use the serial port to connect a terminal emulator to the BIG-IP system.

    Note: For more information about configuring terminal emulation, modifying baud, and viewing the null modem serial cable requirements, refer to the following articles:

    • K7683: Connecting a serial terminal to a BIG-IP system
    • K13885: Setting the baud rate of the serial console port (11.x and later)
    • K9156: Setting the baud rate of the serial console port (9.x - 10.x)
    • K587: Pinouts for serial terminal cables used to connect the 9-pin serial port on F5 products
  2. From the BIG-IP command line, start the F5 Management Port Setup tool by typing the following command:

    config

  3. Enter the appropriate data to assign an IP address, netmask, and default management route to the management interface.
  4. Connect the management port to your network, as appropriate.

    Note: If you do not have serial access to the device, you can set the management network settings by using the LCD display and keypad on the front panel of the device. For more information, refer to the appropriate Platform Guide for your hardware platform.

Activating the license for the new hardware

To install, run, and upgrade the software, as well as receive technical support, you must activate the license from the Configuration utility.

  • To activate a system's license, navigate to System > License, and then click Re-activate.

    Notes:

    • You should have received an email from F5 Support that includes a base registration key for the replacement device. If you did not receive a base registration key for the replacement device, contact F5 Technical Support.
    • For further assistance with license activation, refer to K7752: Licensing the BIG-IP system.
    • For BIG-IP 10.1.0 and later, refer to K10245: BIG-IP UCS installation and licensing behavior.

If you require assistance with configuring or installing the RMA device, contact F5 Technical Support.

Importing and installing the archived configuration (10.x and later)

Before you install an archived configuration on a replacement device, you must first transfer the UCS archive file to the device. You can perform this action by using Secure Copy (SCP) protocol, HTTPS, or FTP through the management interface.

Notes:

  • For assistance transferring the UCS archive from another BIG-IP device using SCP, from a remote FTP server using FTP, or from an attached workstation using HTTPS, refer to K175: Transferring files to or from an F5 system.
  • For assistance transferring the UCS archive from your workstation to the BIG-IP system using SCP, refer to your SCP application manual.

After you transfer the UCS archive to the new device, you can install the archive by performing the following procedure:

Important: When you are installing a UCS archive on a platform running BIG-IP 10.x, the UCS restore operation restores the full configuration only if the hostname of the target system matches the hostname on which the UCS archive was created. If the hostname does not match, only the shared configuration is restored. You can set the hostname of the BIG-IP system from the System > Platform screen of the Configuration utility, or by using the tmsh utility modify sys global-settings hostname command.

Notes:

  • When you are installing a UCS archive on a platform running BIG-IP 9.x, follow the steps in the Restoring configuration data from the command line section of K3499: Backing up and restoring BIG-IP 9.x configuration files.

Important: You may encounter an error message while loading a UCS file if your configuration contains passwords or passphrases encrypted with a different master key. For more information about the error message, refer to K9420: Installing UCS files containing encrypted passwords or passphrases.
  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Type one of the following commands, replacing <path/to/UCS> with the full path of the UCS archive file you want to restore:

    BIG-IP 11.x and later

    load /sys ucs <path/to/UCS> no-license

    BIG-IP 10.x:

    load /sys ucs <path/to/UCS> rma

    If you do not specify the path, the BIG-IP system performs as if the UCS archive file is located in the default /var/local/ucs directory.

  3. If you encrypted the UCS archive file with a passphrase during the backup, you are prompted to enter the passphrase for the archive file.
  4. If you are running the BIG-IP system on a 6400, 6800, 8400, or 8800 hardware platform, verify that the new or replaced secure shell (SSH) keys from the UCS file are synchronized between the BIG-IP system and the Switch Card Control Processor (SCCP), by typing the following commands:

    run /util bash

    keyswap.sh sccp

  5. To switch back to tmsh, type the following command:

    exit

  6. Restart the system by typing the following command:

    reboot
