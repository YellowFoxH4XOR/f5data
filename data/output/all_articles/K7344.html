Known Issue

This is the result of a known issue. If you launch the Windows Standalone Client from the command line interface (CLI), and use a parameter whose argument includes a forward-slash character ( / ) or a space character, the Standalone Client fails to launch, but runs a process that consumes CPU.

The Windows-based Standalone Client can be launched through a CLI, using the f5fpc.exe utility.

When the value of a parameter such as /host or /username (aliases /h and /u, respectively) contains a forward-slash character or a space character, the command will execute but not return a session ID or other output on the command line, and fail to display the Standalone Client's user interface.

For example, the following commands would fail to launch the Standalone Client from the command line:

  • f5fpc.exe -start /h https://fp.foo.com (forward-slashes in the protocol specification)
  • f5fpc.exe -start /h fp.foo.com/myLandingURI (forward-slash in the Landing URI)
  • f5fpc.exe -start /h fp.foo.com /u "john doe" (whitespace in the username)
  • f5fpc.exe -start /h fp.foo.com /u johndoe /p "pass word" (whitespace in the password)

Other parameters are similarly affected by the use of forward-slash or space characters.

Additionally, the f5fpc.exe command invokes the f5fpclientW.exe command, which will remain active and consume large amounts of CPU. To terminate the f5fpclientW.exe process, you can use the Windows Task Manager or a similar utility.

F5 Networks Product Development tracked this issue as CR77924 and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass Release Notes.
