Known Issue

When you insert a Via header into Session Initiation Protocol request messages in a load balancing mode, the Via header with encrypted branch routing information is not consistent with the returned response message. RFC 3621 states that all messages in the same transaction should contain the same branch parameter header. The branch parameter field returns a different value each time.

This issue occurs when all of the following conditions are met:

  • You are using the SIP profile.
  • You have enabled SIP Via header insertion.
  • You cancel an INVITE.

Impact

The system may not immediately terminate cancelled SIP sessions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system cancels the SIP INVITE on the calling side, while the called side of the line rings until it times out.
  • The Via branch parameter field returns a different value from the one that the system sent.
