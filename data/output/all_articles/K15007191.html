Description

Virtual server configured for Multi Path TCP (MPTCP) is not forwarding MPTCP options from the client's TCP SYN to the pool member.

In a packet capture you see that the client's SYN includes a MPTCP option that is removed from the server side SYN.
src ip            dst ip              info       Multipath TCP version
172.16.0.1   192.168.0.1  IN  32804 → 80 [SYN]      ... TSecr=0 WS=128  1  <<< MPTCP is included in initial SYN to the BIG-IP
192.168.0.1  172.16.0.1   OUT 80 → 32804 [SYN, ACK] ... TSecr=330440204
172.16.0.1   192.168.0.1  IN  GET / HTTP/1.1     
192.168.0.1  172.16.0.1   OUT 80 → 32804 [ACK]      ... TSecr=330440204
198.51.0.1   192.168.0.1  OUT 32804 → 80 [SYN]      ... TSecr=0            <<< MPTCP is missing in SYN to the pool member
192.168.0.1  198.51.0.1   IN  80 → 32804 [SYN, ACK] ... TSecr=1758768744
198.51.0.1   192.168.0.1  OUT 32804 → 80 [ACK]      ... TSecr=1756949400

Environment

  • BIG-IP LTM
  • Virtual server
  • TCP Profile with with MPTCP enabled
  • Application is using MPTCP version 1
Cause

BIG-IP does not yet support MPTCP version 1

Recommended Actions

Re-configure application to use MPTCP version 0

Additional Information

This is an example of what you should see when using MPTCP version 0

src ip           dst ip            info                         Multipath TCP version
172.16.0.1  192.168.0.1  IN   460 → 80 [SYN]      ... TSecr=0 WS=128   0  <<< MPTCP included in initial SYN to the BIG-IP
172.16.0.1  192.168.0.1  OUT  460 → 80 [SYN]      ... TSecr=0 WS=128   0  <<< MPTCP included in initial SYN to a pool member
192.168.0.1 172.16.0.1   IN   80 → 460 [SYN, ACK] ... TSecr=3889385751    
192.168.0.1 172.16.0.1   OUT  80 → 460 [SYN, ACK] ... TSecr=3889385751
