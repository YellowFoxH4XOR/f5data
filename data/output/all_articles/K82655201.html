K82655201: Host OS swap space must be disabled in NGINX Controller 2.8.0 and later

Topic

Beginning in NGINX Controller 2.8.0, Kubernetes is installed as an orchestration tool for the NGINX Controller containers. When upgrading from previous versions of NGINX Controller to 2.8.0 or later, if you have swap enabled on your host system, the system displays a warning that swap must be disabled.

Description

As an orchestration tool, Kubernetes operates on the design principle that deployments should use as close to 100 percent of resources as possible, to maintain efficiency. The Kubernetes scheduler determines the best available node on which to deploy newly created pods. If memory swapping is allowed to occur on a host system, this can lead to performance and stability issues within Kubernetes. For this reason, Kubernetes requires that you disable swap in the host system. For more information, refer to Installing kubeadm.

Recommendations

When planning an installation of NGINX Controller 2.8.0 or later, or when planning an upgrade from a previous version of NGINX Controller to 2.8.0 or later, you should consider the following information:

  • To temporarily disable swap on a currently running system, you can use the swapoff command; however, this will not persist after a reboot. To make this configuration permanent, you must comment out (by adding a number sign character to the beginning of the associated entry) or remove the swap entry from your /etc/fstab file. When commented out, the line appears similar to the following example:

    #/swap.img    none    swap    sw    0    0

    For systems that use Logical Volume Manager, the modified line appears similar to the following example:

    #/dev/VolGroup00/LogVol02   swap     swap    defaults     0 0

    Important: Linux distributions and configurations can vary widely between systems. Before making any changes, review the vendor documentation for your Linux distribution and configuration.
