Description

Vulnerability scanners report the presence of a default or guessable SNMP community string (such as "public") on F5 BIG-IP DNS devices, even after SNMPv1 and SNMPv2c are disabled and SNMPv3 is in use. The scanner may flag CVE-1999-0517 or similar findings, indicating a potential SNMP security risk.

Environment

  • Product: F5 BIG-IP DNS
  • SNMP configuration:
    • SNMPv3 enabled and in use
    • SNMPv1 and SNMPv2c intended to be disabled
    • SNMP allowed-addresses restricted to specific management IPs
  • Vulnerability scanner in use 

Cause

Incorrect SNMP configuration syntax was used—specifically, "disabled" instead of the correct "disable" keyword for SNMPv1 and SNMPv2c. This left SNMPv1/v2c enabled, causing the vulnerability scanner to detect the "public" community string risk. After correcting the configuration, SNMPv1/v2c were properly disabled, and no further responses were sent to SNMPv1/v2c requests.

Answer/Recommended Actions

  1. On all affected BIG-IP devices, run the following commands to properly disable SNMPv1 and SNMPv2c:
    tmsh modify sys snmp snmpv1 disable
tmsh modify sys snmp snmpv2c disable
tmsh save sys config
    To verify confiuguration 
    tmsh list sys snmp
  2. Confirm via packet capture that BIG-IP does not respond to SNMPv1 or SNMPv2c requests.
  3. Rescan the device with the vulnerability scanner to verify the issue is resolved.
  4. If the scanner continues to report the vulnerability:
    • Clear the scanner cache and/or
    • Contact the scanner vendor for further investigation.
