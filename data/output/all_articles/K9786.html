Known Issue

This is the result of a known issue. The mcpd process uses the XtremeDB database when handling objects, which has a fixed transaction size of 5,000. When handling more than 5,000 transactions, the mcpd process may crash or report an error message in the /var/log/ltm file that appears similar to the following example:

mcpd[1254]: 01070008:3: Fatal database error with error code 13914

Note: The transaction size is the number of objects that can be handled in one transaction. The objects can be modifications, creations, or deletions of virtual servers, monitors, pools, iRules, etc. For example, with a transaction size of 5,000, the mcpd process can successfully load less than 5,000 objects into the database and communicate that information to TMM in a single transaction.

The mcpd process may crash or report an error message in the following situations:

  • Installing a UCS file while the configuration auditing setting is set to verbose.
    This configuration causes the objects to be entered into the XtrembeDB database twice.
  • Calling a large external class file that contains more than 5,000 objects.
  • Loading a configuration multiple times before the previous configuration information has be removed from the XtremeDB database.

F5 Product Development is tracking this issue as CR93368.

Note: This known issue does not occur in BIG-IP version 9.4 and later, which use a newer version of the XtremeDB database that dynamically allocates a larger transaction size when necessary.

Workaround

You can increase the number of objects the mcpd process is able to manage in a single transaction. To do so, perform the following procedure:

Important: The following procedure requires a restart of the system. F5 Networks recommends that you perform this procedure on the standby unit first, and then fail over after it has rebooted. If working with a single unit, perform the change during a maintenance window.

  1. Log in to the command line.
  2. Change directories to the /etc/bigstart/scripts directory by typing the following command:

    cd /etc/bigstart/scripts/
  3. Create a temporary backup of the mcpd file by typing the following command:

    cp mcpd /var/tmp/mcpd.backup
  4. Using an editor, open the mcpd file.
  5. Locate the following line:

    exec /bin/mcpd -f >/var/log/mcpd.out
  6. Modify the line to appear as follows:

    exec /bin/mcpd -t 10000 -f >/var/log/mcpd.out

    Note: This modification statically changes the transaction size to 10,000.
  7. Save the changes to the file.
  8. Restart all daemons by typing the following command:

    bigstart restart
