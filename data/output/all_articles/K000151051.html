K000151051: Corruption of SSO Header Values When Concatenating Multiple Session Variables in BIG-IP APM Form-Based SSO Objects

Description

Configuring a form-based SSO object in BIG-IP APM with concatenated session variables directly in the SSO header value field (e.g., "%{session.server.network.protocol}://%{session.server.network.name}%{session.custom.client.uri}") results in the insertion of an unexpected ASCII control character (Group Separator, 0x1d) between variable values. This causes header corruption, leading to malformed redirect URLs or header values, which may appear as random or unreadable characters and result in application failures or invalid redirects.

Environment

  • BIG-IP APM
  • Form-based SSO object with header insertion using concatenated session variables in the header value field

Cause

The SSO engine does not support direct concatenation of multiple session variables in the header value field. When multiple session variables are referenced sequentially, the system inserts an ASCII Group Separator (0x1d) between the values, corrupting the header value and causing application errors.

Recommended Actions

  • Do not concatenate multiple session variables directly in the SSO header value field of a form-based SSO object.
  • Use a Variable Assign agent in the access policy or an iRule to concatenate the required session variable values into a single custom session variable.
  • Reference only the resulting custom session variable in the SSO header value field.

Example (Variable Assign agent in access policy):

  1. Create a new session variable, e.g., session.custom.redirect.
  2. Assign its value using TCL expression: session.custom.redirect = expr { [mcget {session.server.network.protocol}] . "://" . [mcget {session.server.network.name}] . [mcget {session.custom.client.uri}] }
  3. In the SSO object, set the header value to: %{session.custom.redirect}
  • Alternatively, use an iRule to perform the concatenation and set the session variable before SSO processing.
  • If random or unreadable characters are observed in SSO-inserted headers or redirect URLs, inspect the raw HTTP headers for ASCII control characters (such as 0x1d) and review the SSO header value configuration for direct concatenation of multiple session variables.
