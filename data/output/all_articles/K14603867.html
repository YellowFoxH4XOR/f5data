K14603867: Traffic sent to wrong destination when using iRule with node command and HTTP/2 profile

Source

Description

When using an iRule with the node command invoked in the CLIENT_ACCEPTED event, traffic is not sent to the node but to the pool associated with the virtual server when using a HTTP/2 profile.

For example, with the following iRule traffic is expected to be sent to the node 10.10.20.104:80, rather than load balanced to the pool.

when CLIENT_ACCEPTED {
    if { [LINK::vlan_id] == "4093" } {
        node 10.10.20.104 80
    }
}

Environment

  • iRule with node command
  • HTTP/2 profile applied

Cause

Bug ID 940837: The iRule command node is not triggered in CLIENT_ACCEPTED with HTTP/2.

Recommended Actions

Modify the iRule to make the node selection in the HTTP_REQUEST event.

Additional Information

The node iRule command causes the specified server node to be used directly, thus bypassing any load-balancing.
