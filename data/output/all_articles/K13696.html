Known Issue

The ASM::payload command does not update the HTTP Content-Length header to reflect the new payload length.

This issue occurs when all of the following conditions are met:

  • You use the ASM::payload command in an iRule to perform a replacement operation against the existing HTTP payload data
  • The resulting content length differs from the original content length

You can use the ASM::payload command to retrieve or replace the payload when an ASM_VIOLATION_REQUEST event is triggered. When used to replace a payload, the ASM::payload command correctly replaces the data. However, the modified payload will have a new length, which is not reflected in the HTTP Content-Length header.

Impact

Client browsers may fail to load the requested resource.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Client browsers may fail to load the requested resource.
  • The value reported in the HTTP Content-Length header will not match the actual content length of the HTTP response.

    Note: A third party application, such as HTTPWatch or tcpdump, may be required to view the header and calculate the actual length of the response.

Workaround

To work around this issue, you can modify the iRule to recalculate the content length. To do so, perform the following procedure:

Impact of workaround: None

You can use the HTTP:header iRules command to replace the Content-Length header with the new value as a result of the ASM::payload replacement. The following code excerpt shows an example of this logic:

HTTP::header replace Content-Length [ASM::payload length]

Note: For complete information about integrating this code example into your existing iRules environment, refer to iRules resources available at the iRules Home at DevCentral. A separate DevCentral login is required to access this content.
