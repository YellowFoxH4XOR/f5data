K14823198: ASM guided configuration not synced to peer device after upgrade

Type
Support Solution
Published
2020-12-01
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.X.X, 15.1.X, 15.0.X, 14.1.X, 14.0.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 14.X.X, 15.0.1, 15.0.0, 14.1.5, 14.1.4, 14.1.3, 14.1.2, 14.1.0, 14.0.1, 14.0.0, 15.1.0
Source
https://my.f5.com/manage/s/article/K14823198

Description

  • ASM guided configuration not synced to peer device
  • ASM guided configuration is only visible on the ASM device where it was created
  • Both units show status In Sync
  • Output from command restcurl shared/gossip |egrep '\"status\"|\"gossipPeerGroup\"' is similar to the following:

    Standby:In Sync] ~ # restcurl shared/gossip |egrep '\"status\"|\"gossipPeerGroup\"'
      "status": "UNPAIRED",
      "gossipPeerGroup": "tm-shared-all-big-ips",

Environment

  • Advance WAF license
  • ASM provisioned
  • ASM guided configuration

Cause

Seen behavior is caused by known issue tracked with the Bug ID 860245 and Bug ID 835517

Recommended Actions

Upgrade to a software version which is not affected by Bug ID 860245 and Bug ID 835517. Alternatively you can perform the following workaround

  1. Open a BIG-IP terminal session with admin/root level access.
  2. Run the following commands, in the order specified

    bigstart stop restjavad
    rm -rf /shared/em/ssl.crt/*
    bigstart start restjavad
    restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices
    restcurl -X DELETE shared/gossip-conflicts
    restcurl -X DELETE shared/device-certificates
    restcurl -X POST -d '{"generateKeyPair": true}' shared/device-key-pair
    bigstart restart restjavad restnoded
     
  3. Force a GOSSIP sync.

    restcurl -X POST -d '{}' tm/shared/bigip-failover-state

      

Additional Information
