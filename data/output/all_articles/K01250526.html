Known Issue

The BIG-IP system may be unable to synchronize its system clock with a network time protocol (NTP) server as a result of using an incorrect source IP address.

This issue occurs when all of the following conditions are met:

  • You have configure the BIG-IP system to use an NTP server.
  • You have configured a default route on both the management interface and a Traffic Management Microkernel (TMM) interface of the BIG-IP system.
  • You have configured the BIG-IP system with a static route to the NTP server using an MGMT interface gateway.
Upon system startup, the ntpd process attempts to reach the NTP server using the management interface, but will incorrectly use a self IP associated to a TMM interface as its source address. This behavior causes the NTP server to respond to the incorrect interface, preventing NTP synchronization.

Impact

The BIG-IP system clock drifts and may become out of sync with device group peers. In addition, if the affected device is a VIPRION, the clock may also be out of sync between blades. Time-critical features may encounter issues.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system reports an incorrect system time.
  • VIPRION systems report different system times across blades.
  • NTP requests are sent out the MGMT interface with a source IP address belonging to a TMM interface.
  • The ntpq -np command output shows the NTP connection status as .INIT.

    For example:

         remote           refid      st t when poll reach   delay   offset  jitter
    ==============================================================================
    *172.28.4.133     .INIT.          16 u   -   64     0    0.000    0.000   0.000

Workaround

To work around this issue, you can manually restart the ntpd process or automate a restart of the ntpd process. To do so, perform one of the following procedures:

Manually restarting the ntpd process

Impact of workaround: System clock synchronization will be unavailable while the ntpd process restarts.

  1. Log in to the BIG-IP command line.
  2. Manually restart the ntpd process by typing the following command:

    bigstart restart ntpd


Automate a restart of the ntpd process

Impact of workaround: System clock synchronization will be unavailable while the ntpd process restarts.

  1. Log in to the BIG-IP command line.
  2. Back up the /config/user_alert.conf file by typing the following command:

    cp /config/user_alert.conf /config/user_alert.conf.K01250526

  3. Using a text editor, open the /config/user_alert.conf file for editing.
  4. Add the following lines to the end of the file:

    alert ntpd_startup_delay "Initialization complete. The MCP is up and running" {
    exec command="sleep 15";
    exec command="/usr/bin/bigstart restart ntpd";
    }

  5. Save the file and close the editor.
