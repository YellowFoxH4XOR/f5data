Known Issue

This is the result of a known issue. The iControl:GlobalLB/WideIP::get_application() iControl method should get the names of the applications for the specified wide IPs. However, when the iControl:GlobalLB/WideIP::get_application() method is used in an iControl script, a proper query is sent to the mcpd process and a proper response is received from mcpd, but the iControl query looks for the incorrect response element. As a result, the query fails with an error message that appears similar to the following example:

SOAP-ENV:Server Exception caught in GlobalLB::urn:iControl:GlobalLB/WideIP::get_application()
Exception: Common::OperationFailed
primary_error_code : 16908340 (0x01020034)
secondary_error_code : 0
error_string : 01020034:3: This object message has no keys.

F5 Product Development tracked this issue as CR125348 and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, GTM, or Link Controller release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.8-396.1-HF3 issued for BIG-IP 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
