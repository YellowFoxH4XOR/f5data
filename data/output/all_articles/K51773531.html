K51773531: Aspen Mesh metrics collector pod is restarting or not running

Type
Support Solution
Published
2021-06-16
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K51773531

Description

The Aspen Mesh metrics collector pod has been restarting frequently or has not been running properly.

  • The last state of the metrics collector pod reports that it was terminated with the reason OOMKilled. For example:

        Last State:     Terminated
          Reason:       OOMKilled
          Exit Code:    137
          Started:      Thu, 01 Apr 2021 14:25:33 +0000
          Finished:     Thu, 01 Apr 2021 14:43:50 +0000
        Ready:          False

Environment

  • Aspen Mesh 1.5.x - 1.9.x
  • Red Hat OpenShift 4.6.x - 4.7.x
  • Kubernetes 1.17.x - 1.20.x

Cause

This issue is due to insufficient memory allocation for the pod which causes the pod to be terminated with the reason, out of memory (OOMKilled).

Recommended Actions

Confirm that the last state of the metrics collector pod is terminated with reason OOMKilled, then increase the memory limits for the metrics collector and upgrade your helm installation with the new values.

  • Confirm the reason for the pod restarts
  • Increase memory limits for the metrics collector pod

Confirm the reason for pod restarts

Impact of action: Performing the following procedure should not have a negative impact on your system.

  1. List the pods in the istio-system namespace and confirm that the aspen-mesh-metrics-collector pod has been restarted by running the following command:

    kubectl -n istio-system get pods

    The output should appear similar to the following example:

    NAME                                                  READY   STATUS    RESTARTS   AGE

    …
    aspen-mesh-metrics-collector-649d9d46c4-jv6gb         2/3     Running   38         26h
    …

  2. Using the pod name from step 1, show the current pods status and reason for the last restart by running the following command:

    kubectl describe pod aspen-mesh-metrics-collector-649d9d46c4-jv6gb -n istio-system

    If the pod was terminated due to insufficient memory, the output will appear similar to the following example. The Last State section shows that pod was terminated and the reason was due to OOMKilled:

    …

Increase memory limits for the metrics collector pod

If the Aspen Mesh metrics collector pod was terminated with OOMKilled, you can increase the memory limits for the pod and perform a Helm upgrade to mitigate the issue.

Impact of action: Adjustments to memory allocation should be performed in a test environment to ensure compatibility with your environment.

  1. Edit the override Helm values deployment file for your Aspen Mesh installation.
  2. Increase the memory limit to at least double the current value. For example, if the original installation value is 512Mi, you should increase the limit to 1Gi, which would appear similar to the following:

    aspen-mesh-metrics-collector:
      serviceImage: metrics-collector-service-1.9.1-am1
      server:
        serviceResources:
          requests:
            memory: "512Mi"
            cpu: "500m"
          limits:
            memory: "1Gi"
            cpu: "500m"

  3. Save the file and exit, then upgrade your Helm installation with the new values by running the following command:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery -n istio-system --values overrides-aspenmesh.yaml

  4. Confirm that the values have been updated by running the following command and observing the change:

    kubectl -n istio-system get deployment aspen-mesh-metrics-collector -o yaml | grep -A5 'limits' | tail -6

  5. Monitor the Aspen Mesh metrics collector pod and confirm that there are no further restarts.
