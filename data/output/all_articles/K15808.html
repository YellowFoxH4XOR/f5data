Known Issue

Duplicate traffic selectors may cause IPsec tunnel negotiation to fail.

This issue occurs when the following condition is met:

  • Identical traffic selectors are defined with the same source/destination IP address, same source/destination netmask, same source/destination port, and same IP protocol.

The traffic selector portion of the BIG-IP IPsec configuration defines the source and destination address, port and protocol for the application traffic destined for the IPsec tunnel. The BIG-IP system does not prevent the BIG-IP administrator from mistakenly creating a second duplicate traffic selector. This unvalidated misconfiguration leads to tunnel negotiation failures.

Impact

IPsec tunnel negotiation fails and the IPsec tunnel cannot be established.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The system logs messages to the /var/log/racoon.log file that appear similar to the following example:

    ERROR: can't start the quick mode, there is no ISAKMP-SA

  • The racoon daemon may restart and produce a core file in the /var/core directory.
  • The system logs messages to the /var/log/daemon.log file that appear similar to the following example:

    Jun 23 02:04:33 ops-na-an-pl-5500-01 emerg logger: Re-starting racoon

  • The system logs messages to the /var/log/user.log file that appear similar to the following example:

    notice logger: Started writing core file: /var/core/racoon.bld4.0.128.core.gz for PID 7824
    notice logger: Finished writing <size> bytes for core file: /var/core/racoon.bld4.0.128.core.gz for PID 7824

Note: The racoon daemon is responsible for Internet Key Exchange (IKE) key management protocol, which is used to establish security associations between hosts.

Workaround

To work around this issue, you should delete one of the duplicate traffic selectors.
