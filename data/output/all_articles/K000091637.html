K000091637: Creating a default upstream error pod for all namespaces

Description

The scenario here is; you have a Kubernetes cluster with an Nginx Ingress Controller, and many Ingress or Virtualserver resources, each in their own namespaces, processing inbound requests. Instead of configuring each upstream service/application with it's own error response page, you can simply configure the ingress controller to intercept specific error responses and then fetch a default error response page from a completely different upstream pod to be returned to the end user.

If this sounds like a configuration you want to implement, here is a solution to apply the necessary configuration to your Nginx Ingress Controller that will intercept these errors and then fetch a page from another pod that you specify.


Environment

Kubernetes
Nginx+ Ingress Controller
 

Cause

You are looking to simplify your error handling in your cluster. Additionally, cross namespace routing is usually only available by mapping a virtualserver to a virtualserverroute resource on a one-to-one basis. If you have hundreds of virtualservers, and don't want to have to create and manage the same number of virtualserverroutes for a single upstream error service, consider using this solution.
 

Recommended Actions

Keep in mind that this config solution will not create the upstream error pod, service, or namespace for that pod. These must already exist in your environment to reference them in the config solution below. In the example below, I used a namespace called "error-ns" to put my custom error pod and service into.


Add this http-snippet to the ingress controller's configmap:
   # The server IP below is based on your error service's IP created in the cluster
   # "kubectl get svc" can be used to find this IP address for your cluster

===========================================================================

apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config
  namespace: nginx-ingress
data:
  http-snippets: |
    upstream error-ns_error_error {
      zone error-ns_error_error 512k;
      random two least_conn;
      server 10.10.10.10:80 max_fails=1 fail_timeout=10s max_conns=0;  # update the IP:port here to your correct upstream service
    }
    proxy_intercept_errors on;
    error_page 501 502 503 = @error;

The end result of this snippet is the Nginx Ingress Controller will now have a global upstream config block that can be referenced by any other Ingress/Virtualserver resource.




Next, add this server-snippet to each Ingress/Virtualserver so they can point to the global error upstream that was created above:

==================================================================================================

server-snippets: |
  location @error {
    proxy_pass http://error-ns_error_error;
  }
