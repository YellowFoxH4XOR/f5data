K000092558: Peer Watermark logs difference between 4.4 and 5.1

Type
Support Solution
Published
2022-11-26
Updated
2022-11-26
Source
https://my.f5.com/manage/s/article/K000092558

Description

  • Difference between how SDC 4.4 and 5.1 handles watermarks.
  • In 5.1 no watermarks level in printStatus in fep logs, while it is available in 4.4.

Back in 4.4:

Peer Table:

Servers:

PCRF_01 Open 1597112169495 Health:null RRW1 C PCRF_Site_Profile NioClientSocketChannel(id: 0xe374c1ff, /10.1.1.1:44979 => /10.1.1.2:6868, watermarks: [8000/4000])

Clients:

clientpeer Open 1591805904325 Health:null clientpeer_Site_Profile NioAcceptedSocketChannel(id: 0x66e07842, /10.1.1.3:19725 => /10.1.1.4:3868, watermarks:8000/4000])

In 5.1: Each peer does not show watermarks level in printStatus

Peer Table: Signaling peers are Available[No Reason]

Servers:

PEER_01 Open_24798563989090513 None RRW1 C PCRF_Site_Profile

PEER_02 Open_24610915668798592 None RRW1 C PCRF2_Site_Profile

Environment

  • SDC 5.1
  • Watermark FEP logs

Cause

By design.

 

 Recommended Actions

None.

 

Additional Information

  • In 4.4, watermark is using message count.
  • In 5.1, watermark is using byte size.
  • In 5.1, when high water is exceeded, it is being printed like the example below.

2022-10-11 08:02:58,969 WARN [12524] RequestExecutor Queue High Watermark exceeded with queue size 10002. Throttling strategy NONE will be applied. [Internal Server NIO worker #2_23] [RequestExecutor.highWatermarkExceeded()]

The peer that reach high watermark will also be printed in the logs. 

EXECUTION_HANDLER_DISCARDING_MESSAGE_DUE_TO_HIGH_WATERMARK  WARN  Networking  Execution Handler: discarding a message that was received from {0} since the {1} reached High Watermark. The netty event is {2}.   

{0}: name of the Peer from which the message was received; 

{1}: The executor name(Probably clients executor); A peer name will appear here to replace {1}.
