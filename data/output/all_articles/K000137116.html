Description

Several CVEs were recently published affecting libwebp, an open-source library serving as a codec, facilitating the encoding and decoding of the WebP image format (a format introduced by Google as an open image format aiming to supplant established formats like JPEG, PNG and GIF). This library allows developers to incorporate WebP support into web browsers, image editing tools and other applications (including applications served via HTTP) and is commonly used in platforms and services that render and manage images.

Environment

Any web application designed to render or manage images, utilizing libwebp to do so.
Note: For F5's response pertaining to the impact of this vulnerability to F5 products and services, please see K000137054

Cause

  • CVE-2023-41064, CVE-2023-4863 and CVE-2023-5129 (withdrawn) refer to a heap buffer overflow in libwebp which allowed an attacker to perform an out of bounds memory write via a crafted WebP image and impacts Google Chrome and libwebp (CVE-2023-4863) as well as iOS, iPadOS and macOS (CVE-2023-41064)

Recommended Actions

You should update the version of libwebp referred to by your applications as soon as possible, along with any instances of Google Chrome or macOS (etc) in your environments.

If you have a potentially vulnerable web application which allows users to upload arbitrary files (especially WebP images) you may be able to use BIG-IP Advanced WAF with a custom signature to block WebP file uploads until you are able to update your application infrastructure. See Additional Information below for details.

Additional Information

WAF products such as BIG-IP Advanced WAF are not designed to directly analyze binary file formats such as the WebP image format. To determine the vulnerability of a webp file, a product must examine the file directly to identify the section related to lossless compression. It should then verify that the decompressed size matches the size indicated in the file structure. If there's a discrepancy, it suggests the file might be malicious. This type of inspection is typically handled by antivirus or endpoint protection software that examines binary files.

If your antivirus infrastructure can detect maliciously crafted webp files, you may wish to configure ICAP antivirus scanning in BIG-IP Advanced WAF. See K70941653: Configuring BIG-IP ASM antivirus protection for more details.

Alternatively, if you do not have the requisite ICAP/antivirus infrastructure in place, the F5 Security Research team has developed a custom attack signature to block the upload of webp lossless files to your servers. However, for customers allowing the upload of webp images, we advise against using this rule. This is because BIG-IP Advanced WAF is unable to determine if a webp lossless image is malicious or benign, potentially leading to numerous false positives.
