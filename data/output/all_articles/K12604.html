K12604: The BIG-IP ASM DoS Attack Prevention engine does not correctly calculate idle time

Known Issue

This is the result of a known issue. In BIG-IP ASM 0.2.0 and 10.2.1, when evaluating traffic against the IP Detection Parameters defined in the security policy, the BIG-IP ASM DoS Attack Prevention engine may not correctly account for periods of time where no connections are received for a given IP. The resulting calculations based on this data will be incorrect and will result in the BIG-IP ASM system incorrectly detecting a denial-of-service (DoS) attack when the connection rates do not meet the criteria defined in the policy. This behavior will result in entries written to the /var/log/asm file that appear similar to the following examples:

dcc[6100]: 01310046:3: [SECEV] DoS attack: Started. HTTP classifier: my_httpclass, Operation mode: Blocking

dcc[6100]: 01310046:3: [SECEV] DoS attack: Finished. HTTP classifier: my_httpclass, Operation mode: Blocking

Note: These log entries are not unique to this issue. They occur when the DOS Prevention engine is correctly logging a DoS attack. In this case however, they are false positives.

These false positive DoS Attack Prevention events are known to occur after a given client IP has initiated a number of requests to the BIG-IP ASM system. These requests are of a low enough volume and frequency to not be classified as a DoS attack, and the client ceases sending connections for a given period of time. When the same client IP begins initiating connections again, the BIG-IP ASM system may incorrectly classify the new connections as a DoS attack attempt and block the requests. The value of the idle time that will precipitate this behavior is not fixed, but varies depending on the frequency and volume of requests being received by the BIG-IP ASM system.

F5 Product Development tracked this issue as ID 346890 and it was fixed in BIG-IP ASM 10.2.2. For information about upgrading, refer to the BIG-IP ASM release notes.

In addition, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
