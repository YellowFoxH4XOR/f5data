Known Issue

Responses may be truncated when a denial-of-service (DoS) profile is configured on a BIG-IP ASM-enabled virtual server.

This issue may occur when all of the following conditions are met:

  • The response from the pool member has a 0 byte Content-Length header.
  • The response from the pool member is chunked.

For example, the following response could trigger the issue:

HTTP/1.1 302 Found
Connection: Keep-Alive
Date: Fri, 12 Nov 2010 00:28:36 GMT
Server: Server/1.0
Location: https://example.company.com
Content-Length: 0
Transfer-Encoding: chunked

0

Note: Section 4.4 of RFC 2616 states "Messages MUST NOT include both a Content-Length header field and a non-identity transfer-coding."

Impact

The BIG-IP ASM system truncates the server's response or does not send the response to the client system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Responses sent to the client are missing HTTP headers and/or HTTP body.
  • Requests sent to the BIG-IP ASM system fail to return content.

Workaround

To work around this issue, you can remove the DoS profile from the affected virtual server. To do so, perform the following procedure:

Impact of workaround: Removing the DoS profile disables Layer 7 DoS protection for that virtual server.

  1. On the Main tab, click Local Traffic > Virtual Servers.
  2. Click the name of the virtual server you want to modify.
  3. From the Security menu, choose Policies.
  4. To disable DoS protection, from the DoS Protection Profile list, select Disabled.
  5. To save the changes, click Update.
