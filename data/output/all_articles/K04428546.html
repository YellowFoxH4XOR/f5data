Description
How to provision /var with more than 3GB of disk space when applying a TMOS upgrade to a new Virtual Disk

Environment

  • BIG-IP physical hardware, or Virtual Edition

Cause
The /var directory is provisioned with 3GB of disk space by default and on occasion may need to be expanded.

Recommended Actions:
There are two scenarios to consider when resizing the /var partition: Single Disk (ie Virtual Edition) and Multiple Disks (RAID), however the disk space for /var can be increased on either deployment.

Single Disk Procedure
This procedure is specific to BIG-IP platforms running a single Virtual Disk, ie a Virtual Edition.

  • The Logical Volumes for the BIG-IP Virtual Disks are located in the /dev/vg-db-vda/ directory
  • The specific file(s) for the /var partition are in the format, set.xxx._var with xxx referring to the specific Boot Location specified when creating the volume.  (Example: set.123._var on HD1 would be associated with HD1.123)
[root@example-bigip:Active:Standalone] vg-db-vda # ls -la
total 0
...
lrwxrwxrwx.  1 root root    7 Sep 22 11:40 set.1._config -> ../dm-7
lrwxrwxrwx.  1 root root    7 Sep 22 11:40 set.1.root -> ../dm-5
lrwxrwxrwx.  1 root root    7 Sep 22 11:40 set.1._usr -> ../dm-6
lrwxrwxrwx.  1 root root    7 Sep 22 11:40 set.1._var -> ../dm-8
  • Use the lvdisplay | grep varcommand to view the existing logical volumes:
[root@example-bigip:Active:Standalone] dev # lvdisplay | grep var
  LV Path                /dev/vg-db-vda/set.2._var
  LV Name                set.2._var
  LV Path                /dev/vg-db-vda/set.1._var
  LV Name                set.1._var
 
  1. Create a new Boot Location, either in the GUI, or in the CLI.  This action will be reflected in ls -la /dev/vg-db-vda/.

[root@example-bigip:Active:Standalone] dev # ls -la /dev/vg-db-vda/

Multiple Disk/RAID Procedure
The main difference in the process from the single disk to the RAID solution is the fact that there are two directories and logical volumes created for each boot location on the BIG-IP. 

[root@example:NO LICENSE:Standalone] dev # ls -la /dev | grep vg-db-sd
drwxr-xr-x.  2 root root         420 2022-09-22 15:06 vg-db-sda
drwxr-xr-x.  2 root root         420 2022-09-22 15:06 vg-db-sdb

[root@EXAMPLE:NO LICENSE:Standalone] dev # ls -la vg-db-sd* | grep var
lrwxrwxrwx.  1 root root   38 2022-09-20 06:24 mdm.set.1._var -> /dev/mapper/vg--db--sda-mdm.set.1._var
lrwxrwxrwx.  1 root root   38 2022-09-20 06:24 mdm.set.2._var -> /dev/mapper/vg--db--sda-mdm.set.2._var
lrwxrwxrwx.  1 root root    8 2022-09-22 15:06 mdm.set.5._var -> ../dm-20
lrwxrwxrwx.  1 root root   38 2022-09-20 06:24 mdm.set.1._var -> /dev/mapper/vg--db--sdb-mdm.set.1._var
lrwxrwxrwx.  1 root root   38 2022-09-20 06:24 mdm.set.2._var -> /dev/mapper/vg--db--sdb-mdm.set.2._var
lrwxrwxrwx.  1 root root    8 2022-09-22 15:06 mdm.set.5._var -> ../dm-21
