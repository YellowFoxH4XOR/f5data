Description

After adding an additional blade and increasing core allocation for a tenant in an F5OS VELOS HA environment, persistent error messages were observed on both active and standby tenants:

HA Connection detected DAG discrepancy: local pg X, remote pg Y, local pu Z, remote pu Z. Connection will be retried.

Environment

  • VELOS chassis with multiple blades
  • BIG-IP tenants deployed on F5OS
  • HA configuration with two tenants (active and standby)

Cause

One of the slots on one of the tenants was offline due to /var directory being full. It caused mismatch in blade assignments between HA tenants that resulted in inconsistent DAG state and prevented proper HA mirroring and synchronization.

F5OS HA requires identical blade/core configuration on both sides for DAG and connection mirroring to function.

Recommended Actions

- Remove unnecessary files from /var directory to bring affected slot online and restore hardware parity.

- Ensure both tenants are configured with identical slot/core assignments. (It can be checked with show tenants command run in the Partition CLI)

- Redeploy or restart tenants after restoring blade availability to synchronize DAG state.

- Verify DAG state consistency and sdag_table_hash values across both tenants and blades. (It can be checked with show dag-states command run in the Partition CLI)

- Monitor for resolution of HA discrepancy errors in tenant logs.
