Known Issue

Description

The logd process may enter a loop and continuously log error messages.

In some circumstances, when under logging stress, the logd process may interact negatively with other processes while attempting to close or create file descriptors in the BIG-IP APM system.

Impact

Local logging for the BIG-IP APM system is impaired.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP APM system reports high cpu utilization for the logd process.
  • The BIG-IP APM system experiences performance degradation.
  • In the /var/tmp/logd.out file, you may observe messages similar to the following example:

    accept_conn: found duplicate fd in connMap

Workaround

To mitigate this issue, you can restart the logd service using the tmsh utility. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the logd service, use the following command syntax:

    restart /sys service <name>

    For example:

    restart /sys service logd

  3. To exit the tmsh utility, type q and press Enter.
