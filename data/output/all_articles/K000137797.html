K000137797: F5OS unable to add known-hosts entry: "file known-hosts known-host <host> config': Host un-reachable"

Source
https://my.f5.com/manage/s/article/K000137797

Description

Added a known-hosts entry to F5OS configuration, but commit fails with a Host un-reachable message similar to the following:

R4600-R9-S10# conf
Entering configuration mode terminal
R4600-R9-S10(config)# file known-hosts known-host 198.51.100.5
R4600-R9-S10(config-known-host-198.51.100.5)# commit
Aborted: 'file known-hosts known-host 198.51.100.5 config': Host un-reachable

System has connectivity to the destination SSH server in question, and SSH attempts from F5OS command line via bash are successful.

A packet trace of the failing connection reveals that the SSH session initiated from F5OS is only enabling the ssh-rsa host key algorithm, which does not match any of the algorithms enabled on the destination SSH server.

SSH Protocol
    SSH Version 2
        Packet Length: 1148
        Padding Length: 8
        Key Exchange
            Message Code: Key Exchange Init (20)
            Algorithms
                Cookie: c667f67b1aea84908b517d72c9cd0ee4
                kex_algorithms length: 320
                kex_algorithms string [truncated]: curve25519-sha256,...
                server_host_key_algorithms length: 7
                server_host_key_algorithms string: ssh-rsa      <--

Environment

  • F5OS
  • SSH/SCP

Cause

SSH connections originate from the utils-agent container when committing a known-hosts entry. This restricts the host key algorithms to ssh-rsa.

These connections will fail when made towards modern systems running an up to date SSH server, as ssh-rsa is often disabled by default.

Bug ID1399041 tracks this issue.

Recommended Actions

There is no workaround for this issue on F5OS at the time of this article's publication.

However, you can work around this issue by modifying the configuration on the SSH server you are attempting to add as a known-host.

You should first evaluate the security implications of such a change in your environment.

Example, using an Ubuntu 22.04 server:

## Confirm that ssh-rsa is a supported host key algorithm:

ssh -Q HostKeyAlgorithms

root@ubuntu-server:~# ssh -Q HostKeyAlgorithms
ssh-ed25519
ssh-ed25519-cert-v01@openssh.com
sk-ssh-ed25519@openssh.com
sk-ssh-ed25519-cert-v01@openssh.com
ssh-rsa  <-- Note
...

## Determine the currently enabled host key algorithms:

root@ubuntu-server:~# sshd -T | grep hostkeyalg

hostkeyalgorithms ssh-ed25519-cert-v01@openssh.com,ecdsa-sha2-nistp256-cert-v01@openssh.com,ecdsa-sha2-nistp384-cert-v01@openssh.com,ecdsa-sha2-nistp521-cert-v01@openssh.com,sk-ssh-ed25519-cert-v01@openssh.com,sk-ecdsa-sha2-nistp256-cert-v01@openssh.com,rsa-sha2-512-cert-v01@openssh.com,rsa-sha2-256-cert-v01@openssh.com,ssh-ed25519,ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,sk-ssh-ed25519@openssh.com,sk-ecdsa-sha2-nistp256@openssh.com,rsa-sha2-512,rsa-sha2-256

## Edit /etc/ssh/sshd_config (or add a drop in file to /etc/ssh/sshd_config.d), appending 'ssh-rsa' to that string:

root@ubuntu-server:~# tail -1 /etc/ssh/sshd_config

hostkeyalgorithms ssh-ed25519-cert-v01@openssh.com,ecdsa-sha2-nistp256-cert-v01@openssh.com,ecdsa-sha2-nistp384-cert-v01@openssh.com,ecdsa-sha2-nistp521-cert-v01@openssh.com,sk-ssh-ed25519-cert-v01@openssh.com,sk-ecdsa-sha2-nistp256-cert-v01@openssh.com,rsa-sha2-512-cert-v01@openssh.com,rsa-sha2-256-cert-v01@openssh.com,ssh-ed25519,ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,sk-ssh-ed25519@openssh.com,sk-ecdsa-sha2-nistp256@openssh.com,rsa-sha2-512,rsa-sha2-256,ssh-rsa      <-- Note

## Restart the SSH server to effect the changes:

root@ubuntu-server:~# systemctl restart ssh
root@ubuntu-server:~# sshd -T | grep hostkeyalg
hostkeyalgorithms ssh-ed25519-cert-v01@openssh.com,ecdsa-sha2-nistp256-cert-v01@openssh.com,ecdsa-sha2-nistp384-cert-v01@openssh.com,ecdsa-sha2-nistp521-cert-v01@openssh.com,sk-ssh-ed25519-cert-v01@openssh.com,sk-ecdsa-sha2-nistp256-cert-v01@openssh.com,rsa-sha2-512-cert-v01@openssh.com,rsa-sha2-256-cert-v01@openssh.com,ssh-ed25519,ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,sk-ssh-ed25519@openssh.com,sk-ecdsa-sha2-nistp256@openssh.com,rsa-sha2-512,rsa-sha2-256,ssh-rsa
