Description

Virtual Server not functioning on vCMP Guest after upgrade. It is accepting traffic on 443 but not presenting a certificate or doing the proxy function.

You have disabled the Virtual Address from the Address List and disabled and re-enabled ARP, and this did not help.

When capturing traffic to the Virtual Server, you can see similar behaviour:

172.16.1.102  → 192.168.1.10   TCP  IN     s1/tmm0 : 51408 → 443 [SYN]
192.168.1.10  → 172.16.1.102   TCP  OUT s1/tmm0 : 443 → 51408 [RST, ACK] [F5RST: No local listener]
172.16.1.102  → 192.168.1.10   TCP  IN     s1/tmm0 : 51409 → 443 [SYN]
192.168.1.10  → 172.16.1.102   TCP  OUT s1/tmm0 : 443 → 51409 [RST, ACK] [F5RST: No local listener]

Environment

  • Traffic being RST
  • Virtual Server config exists, but is not responding

Cause

Unknown at the time of publication.

Recommended Actions

To workaround the issue, perform an MCPD reload of the Guest:

touch /service/mcpd/forceload
reboot

K13030: Forcing the mcpd process to reload the BIG-IP configuration
