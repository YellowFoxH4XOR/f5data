K47857834: Custom Resource Definitions (CRDs) deprecated in Aspen Mesh version 1.11.x

Source

Description

With the release of Aspen Mesh version 1.11.x, Secure Ingress is no longer supported. Therefore, the number of Custom Resource Definitions (CRDs) installed or upgraded is 15, not 23 as mentioned in the Aspen Mesh 1.9 documentation. For more information, refer to the Installation Guide .

This article provides a few of the FAQ (Frequently Asked Questions) on this topic:

  1. Is Secure Ingress CRDs part of the 23 CRDs installed during Aspen Mesh installation, and if it is, what specific CRD is it?

    Yes, Secure Ingress used to be a part of the Aspen Mesh previous releases where the number of CRDs was 23. You can reference this in the Aspen Mesh documentation . But with new releases, The Secure Ingress CRDs are no longer supported. That means when installing Aspen Mesh in your istio-system namespace, you will not have these CRDs.   2. What are the application dependencies on this CRD and how will deprecating it impact our applications?

    Secure Ingress CRDs can only affect applications if these are being used in your environment. Deprecated CRDs object running in your cluster can be removed manually for cleanup. You can check if any resources for these CRDs are there in your environment by running the command syntax below:

    kubectl get secureingresses.policy.aspenmesh.io -n <namespace>

    If the output for above command is No Resources Found, that means you do not have any Secure Ingress objects running in your cluster. If there are objects in your environment for deprecated CRDs, you would need to delete those objects first before deleting the CRDs itself. 

  3. For manual cleanup, you can delete the CRDs by using the following command syntax:

    kubectl delete crd <crd-name>
