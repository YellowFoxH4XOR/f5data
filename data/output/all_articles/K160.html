Topic

The 3-DNS Controller uses the following three load balancing options:

  • Preferred
  • Alternate
  • Fallback

The 3-DNS Controller uses the fallback load balancing method when the preferred and alternative load balancing methods fail. This most often occurs when a dynamic load balancing method is being used and there is not enough data provided to the 3-DNS Controller for it to make a load balancing decision.

For example, if the preferred load balancing method is round-trip time (which is a dynamic load balancing method), and the 3-DNS Controller has not probed the LDNS servers to determine the round-trip time, 3-DNS will use the fallback load balancing method to return the query.

Following are a few additional examples of situations when the 3-DNS Controller will use a method other than the preferred:

If the preferred load balancing method is set to Quality of Service, but the firewall is blocking probes, or the LDNS that is sending the query has not yet been probed, the 3-DNS Controller will use the alternate load balancing option.

For the same scenario, if the alternate load balancing method is set to Least Connections, but a temporary firewall problem is stopping the 3-DNS Controller from updating statistics from the remote BIG-IP (making the preferred and alternate load balancing methods unavailable), the 3-DNS Controller would use the fallback load balancing method.

The fallback load balancing method will also be used if all of the nodes in a pool are marked down.
