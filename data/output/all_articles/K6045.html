Issue

Generating traffic with the VLAN failsafe feature

The VLAN failsafe feature is designed to trigger an action when no traffic is detected on the VLAN. If the BIG-IP system does not detect traffic on the VLAN, the BIG-IP system will attempt to generate traffic on the VLAN in order to prevent a false VLAN failsafe action from being triggered during legitimate no traffic periods. If the BIG-IP system does not receive a response to the attempts to generate traffic, a VLAN failsafe action is triggered.

BIG-IP 4.x behavior

In BIG-IP 4.x, if no traffic is detected on the VLAN, after half of the VLAN failsafe timeout value has elapsed, the BIG-IP system will attempt to generate traffic on the VLAN by sending an ARP request for the IP address of the default router. 

Important: The ARP request is only sent when VLAN failsafe is enabled on the VLAN hosting the default gateway address. If no default gateway is configured, no ARP request is sent.

The BIG-IP system will repeat the requests every second until traffic is seen on the VLAN or the VLAN failsafe timeout value expires. If any traffic is seen on the VLAN, the VLAN failsafe timeout counter is reset. If the BIG-IP system does not see any traffic on the VLAN, the BIG-IP system will trigger a failover and reboot the system.

Important: The failover action is averted by any traffic on the wire, not necessarily a response to the ARP request. As a result, only the ability to receive traffic is verified by this test. In rare cases in which the BIG-IP cannot send the ARP request, failover may be inappropriately averted. This oversight was corrected in 9.x, and the ResetTimerOnAnyFrame database variable was added in BIG-IP 9.2.3 to emulate the 4.x behavior. 

BIG-IP 9.x behavior

The method for generating traffic changed in BIG-IP 9.x. You can now configure the action triggered by VLAN failsafe. If no traffic is detected on the VLAN, the BIG-IP system will attempt to generate traffic on the VLAN using the following methods:

  • After half of the VLAN failsafe timeout value has elapsed:

    • ARP request for the IP address of the oldest entry in the BIG-IP ARP table
       
    • ICMPv6 neighbor discovery probe (only if entries exist in the BIG-IP IPv6 neighbor cache)

  • After 3/4 of the VLAN failsafe timeout value expires:

    • ARP request for all IP addresses in the BIG-IP ARP table
       
    • ICMPv6 neighbor discovery probe (only if entries exist in the BIG-IP IPv6 neighbor cache)
       
    • ICMP echo request to 224.0.0.1 (multicast ping)

The BIG-IP system will repeat the requests every second until a response is received or the VLAN failsafe timeout value expires. When a response is received the VLAN failsafe timeout counter is reset. If the BIG-IP system does not receive a response before the VLAN failsafe timeout value expires, the BIG-IP system will trigger the configured VLAN failsafe action.

The VLAN failsafe action can be configured to perform one of the following actions:

  • Failover

    This action will initiate a failover from active to standby

  • Restart All

    This action will initiate a failover, and restart all processes

  • Reboot

    This action will initiate a failover, and reboot the BIG-IP system

Generating traffic with the available failsafe actions

The following traffic requirements describe when the BIG-IP system will reset the VLAN failsafe timeout counter and prevent the VLAN failsafe action from being triggered:

BIG-IP 4.x

The BIG-IP will reset the VLAN failsafe timeout counter if any packet is received on the VLAN. This packet does not have to be a response to a request that was sent by the BIG-IP for the purpose of generating traffic on the VLAN. Receiving a packet verifies the BIG-IP system's ability to receive frames on the VLAN. This behavior has changed in the BIG-IP version 9.x software branches.

BIG-IP 9.x

The VLAN failsafe timeout counter will be reset only when the BIG-IP receives a response to a request that was sent by the BIG-IP for the purpose of generating traffic on the VLAN.

Requiring a response to a request sent by the BIG-IP for the purpose of generating traffic on the VLAN verifies the BIG-IP system's ability to transmit and receive frames.

Important: This is a significant behavior change from the BIG-IP version 4.x software branches. The ResetTimerOnAnyFrame database variable was added in BIG-IP version 9.2.3 to emulate version 4.x behavior. The default is Off.

As a result of this behavior change, it is possible for the VLAN failsafe action to appear to have been triggered before the time interval specified by the VLAN failsafe timeout. This is because VLAN failsafe timeout counts from the last successful response, instead of the actual link down or the last received frame.

For example, if the VLAN failsafe timeout value is set for 30 seconds, a successful response packet is received at 00:00:00, and at 00:00:10 the link is disabled, then 20 seconds later (at 00:00:30) the failsafe action is triggered. This gives the appearance that VLAN failsafe was triggered at 20 seconds. If the VLAN failsafe timeout is set to 30 seconds, the failsafe action can occur as fast as 16 seconds from the time the link is down.

F5 Product Development tracked a request for enhancement to enable BIG-IP 4.x VLAN failsafe timeout counter behavior as CR64239 and the ResetTimerOnAnyFrame database variable was added in BIG-IP 9.2.3, allowing the emulation of 4.x behavior.
