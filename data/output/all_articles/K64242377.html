Description

The session Cookie value is changing frequently when is sourced from Akamai Infrastructure. This is causing users to lose their connection to the Web Application as the request goes to another pool member even when you have cookie persistence configured.

Environment

  • BIG-IP LTM
  • Cookie Persistence
  • Traffic is sourced from Akamai Edge solution
  • Client is losing the user session when navigating on the Web Application

Cause

According to Akamai's documentation: "Since Akamai network is using several different machines (for improved performance and redundancy) to route end user's request - the connecting user's IP will almost never be the same. Moreover a single Akamai server can send a request from several end users - even over the same persistent connection." This behavior can impact F5 BIG-IP load balancing.

Recommended Actions

Apply a OneConnect profile in your virtual server. The default OneConnect profile with the Source Prefix Length set to None will work for most implementations.

Additional Information

The OneConnect profile load balances at layer 7 (HTTP) irrespective of the Client Side TCP connection. However it has a useful effect on cookie persistence. For more information, refer to: K83419154: Overview of cookie persistence.

Note: The BIG-IP system inserts the set cookie header on the initial HTTP request for a single TCP session unless there is a OneConnect profile in use.  With OneConnect applied to the same virtual server, the system returns the set cookie header with every HTTP request over the same TCP session.
