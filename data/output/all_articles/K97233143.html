Topic

You should consider using this procedure under the following condition:

  • You want to enable BIG-IQ 7.1.0 to support a different instance type of BIG-IP Virtual Edition (VE) on the Amazon Web Services (AWS) or Azure cloud environment.

Description

This article explains how to modify the restjavad properties to enable BIG-IQ 7.1.0 to support a new AWS or Azure instance type for BIG-IP VE.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a valid AWS or Azure cloud environment configuration on the target BIG-IQ system.
  • You are using the BIG-IQ system to deploy a new BIG-IP VE device to the AWS or Azure cloud environment.
  • You have Advanced Shell (bash) access to the BIG-IQ system with administrator credentials.

Procedures

Starting in BIG-IQ 7.1.0, the restjavad properties file does not contain configuration stanzas for customizing the AWS or Azure environment on the instance types. The system has a default list of the supported environment built-in and updated on each new BIG-IQ release.

To view the supported list of BIG-IP VE versions on the AWS or Azure instance type, use the BIG-IQ system interface and navigate to Applications > ENVIRONMENTS > Cloud Environments, and select the BIG-IP Image Name drop-down list.

Important: If your restjavad.properties.json file does not contain the aws or azure properties, refer to the Workaround section in K02972920: The restjavad.properties.json file does not contain F5-defined default properties after upgrading the BIG-IQ system.
 

Adding a new AWS instance type

You can customize the restjavad properties file to support a new instance type for AWS BIG-IP VE on the BIG-IQ system. To modify the file, perform the following procedure:

Impact of procedure: You must restart the restjavad process after you modify the property file as it will cause interruptions to BIG-IQ services. F5 recommends performing this procedure only during a scheduled maintenance period. 

  1. Log in to bash on the BIG-IQ system.
  2. Save a back-up copy of the restjavad property file by entering the following command:

    cp -a /var/config/rest/config/restjavad.properties.json /shared/tmp/restjavad.properties.json.backup1

  3. Use a file editor to edit the /var/config/rest/config/restjavad.properties.json property file.
  4. Look for the aws section in the file. In BIG-IQ 7.1.0, the AWS configuration stanza will appear similar to the following example: 
        "aws" :
    {
        "images" :
        {
            "includePrivateImages": false,
            "privateImageVersion": "13.1.0.5",
            "privateImageBuild": "0.0.5"
        },
        "ssgMonitoring" :
        {
            "groomingIntervalSec": 86400,
            "monitorIntervalMS": 120000,
            "workflowTimeoutSeconds": 9000
        },
        "configsyncAddrPollIntervalMS": 60000,
        "configsyncAddrPollTries": 20,
        "dscsyncPollIntervalMS": 120000,
        "dscsyncPollTries": 15,
        "retryDMALimit": 50,
        "retryDMAIntervalMS": 20000
    },

    Important: You must include the trailing comma ( , ) in the remaining configuration stanzas. The AWS ending stanza has a trailing comma after the closing brace ( } ) because there are other configuration stanzas included after this line, such as the Azure configuration stanza.

  5. To add new instance type, add the instanceTypes property within the AWS configuration, above the ssgMonitoring line entry.

    For example, you want to add the LTM m4 and c4 instance types for AWS BIG-IP VE to the instanceTypes configuration stanza:

        "instanceTypes": {
      "ltm": [
        "m4.xlarge",
        "m4.2xlarge",
        "m4.4xlarge",
        "m4.10xlarge",
        "c4.4xlarge",
        "c4.8xlarge"
      ]
    },

    Important: You must include the trailing comma in the remaining configuration.

    After you add the instance types stanza, the aws section appears similar to the following example:

        "aws" :
    {
        "instanceTypes": {
          "ltm": [
            "m4.xlarge",
            "m4.2xlarge",
            "m4.4xlarge",
            "m4.10xlarge",
            "c4.4xlarge",
            "c4.8xlarge"
          ]
        },
        "images" :
        {
            "includePrivateImages": false,
            "privateImageVersion": "13.1.0.5",
            "privateImageBuild": "0.0.5"
        },
        "ssgMonitoring" :
        {
            "groomingIntervalSec": 86400,
            "monitorIntervalMS": 120000,
            "workflowTimeoutSeconds": 9000
        },
        "configsyncAddrPollIntervalMS": 60000,
        "configsyncAddrPollTries": 20,
        "dscsyncPollIntervalMS": 120000,
        "dscsyncPollTries": 15,
        "retryDMALimit": 50,
        "retryDMAIntervalMS": 20000
    },
  6. After you have save the changes, you must restart the restjavad service by entering the following command:

    tmsh restart /sys service restjavad

    Once the BIG-IQ system resumes service, you will be able to see the newly added AWS BIG-IP VE instance type when creating a new cloud environment for AWS.

Adding a new Azure instance type

You can customize the restjavad properties file to support a new instance type for Azure BIG-IP VE on the BIG-IQ system. To modify the file, perform the following procedure:

Impact of procedure: You must restart the restjavad process after you modify the property file as it will cause interruptions to BIG-IQ services. F5 recommends performing this procedure only during a scheduled maintenance period. 

  1. Log in to bash on the BIG-IQ system.
  2. To save a back-up copy of the restjavad property file, enter the following command:

    cp -a /var/config/rest/config/restjavad.properties.json /shared/tmp/restjavad.properties.json.backup2

  3. Use a file editor to edit the /var/config/rest/config/restjavad.properties.json property file.
  4. Look for the azure section in the file.

    For example:

        "azure" :
    {
        "ssgMonitoring" :
        {
            "groomingIntervalSec": 86400,
            "monitorIntervalMS": 120000,
            "workflowTimeoutSeconds": 9000
        },
        "configsyncAddrPollIntervalMS": 60000,
        "configsyncAddrPollTries": 20,
        "dscsyncPollIntervalMS": 120000,
        "dscsyncPollTries": 15,
        "provisioningCheckPollIntervalMS": 120000,
        "checkProvisioningPollTries": 20,
        "asmCheckPollIntervalMS": 120000,
        "checkAsmPollTries": 20,
        "retryDMALimit": 50,
        "retryDMAIntervalMS": 20000
    }

  5. To add new instance type, you must add another instanceTypes configuration stanza within the Azure stanza, above the ssgMonitoring line entry.

    For example, you want to add the LTM standard instance types for Azure BIG-IP VE to the instanceTypes configuration:

            "instanceTypes" : {
          "ltm": [
            "Standard_A4",
            "Standard_A6",
            "Standard_A7",
            "Standard_D4",
            "Standard_DS12_v2",
            "Standard_DS13_v2",
            "Standard_DS3",
            "Standard_DS3_v2",
            "Standard_DS4_v2",
            "Standard_DS5_v2"
          ]
        },

    Important: You must include the trailing comma in the remaining configuration stanzas.

    After you add the instance types stanza, the azure section appears similar to the following example:

        "azure" :
    {
        "instanceTypes" : {
          "ltm": [
            "Standard_A4",
            "Standard_A6",
            "Standard_A7",
            "Standard_D4",
            "Standard_DS12_v2",
            "Standard_DS13_v2",
            "Standard_DS3",
            "Standard_DS3_v2",
            "Standard_DS4_v2",
            "Standard_DS5_v2"
          ]
        },
        "ssgMonitoring" :
        {
            "groomingIntervalSec": 86400,
            "monitorIntervalMS": 120000,
            "workflowTimeoutSeconds": 9000
        },
        "configsyncAddrPollIntervalMS": 60000,
        "configsyncAddrPollTries": 20,
        "dscsyncPollIntervalMS": 120000,
        "dscsyncPollTries": 15,
        "provisioningCheckPollIntervalMS": 120000,
        "checkProvisioningPollTries": 20,
        "asmCheckPollIntervalMS": 120000,
        "checkAsmPollTries": 20,
        "retryDMALimit": 50,
        "retryDMAIntervalMS": 20000
    }

    Note: There is no trailing comma for the Azure configuration stanza after the closing brace because it does not include any additional configuration stanzas.

  6. After you save the changes, you must restart the restjavad by entering the following command:

    tmsh restart /sys service restjavad

    Once the BIG-IQ system resumes service, you will be able to see the newly added Azure BIG-IP VE instance type when creating a new cloud environment for Azure.
