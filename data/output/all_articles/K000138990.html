Security Advisory Description

The DNS message parsing code in `named` includes a section whose computational complexity is overly high. It does not cause problems for typical DNS traffic, but crafted queries and responses may cause excessive CPU load on the affected `named` instance by exploiting this flaw. This issue affects both authoritative servers and recursive resolvers. This issue affects BIND 9 versions 9.0.0 through 9.16.45, 9.18.0 through 9.18.21, 9.19.0 through 9.19.19, 9.9.3-S1 through 9.11.37-S1, 9.16.8-S1 through 9.16.45-S1, and 9.18.11-S1 through 9.18.21-S1. (CVE-2023-4408)

Impact

An attacker may be able to craft DNS queries and responses that cause excessive CPU load on the affected named process.

Mitigation

To mitigate the issue on the self IP address, you can prevent access to port 53 on the self IP address. If your self IP address is configured to use the default allow setting, you can remove that port from the list of the default allowed services. To mitigate the issue on the DNS listener, disable the Use BIND Server on the BIG-IP option in the DNS profile.

To do so, use the following procedures:

  • Ensuring that TCP/UDP port 53 is not allowed as a default service (allow-service default)
  • Disabling the Use BIND Server on BIG-IP option in the DNS profile

Ensuring that TCP/UDP port 53 is not allowed as a default service (allow-service default)

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. List the default services allowed by the allow-service default setting by typing the following command:

    list net self-allow

    The command output appears similar to the following example:

    net self-allow {
    defaults {
    ospf:any
    tcp:domain
    tcp:f5-iquery
    tcp:https
    tcp:snmp
    tcp:ssh
    udp:520
    udp:cap
    udp:domain
    udp:f5-iquery
    udp:snmp
    }
    }

  3. If TCP port 53 (tcp:53 or tcp:domain) or UDP port 53 (udp:53 or udp:domain) are listed as a default allowed port, delete the entries by typing the following command:

    modify net self-allow defaults delete { tcp:domain udp:domain }

  4. Save the configuration by typing the following command:

    save sys config

Disabling the Use BIND Server on BIG-IP option in the DNS profile

Important: Disabling the BIND server can affect DNS configurations that use BIND as a fallback method (return to DNS) for resolution.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Services > DNS.
  3. Select the applicable DNS profile.
  4. For the Use BIND Server on BIG-IP option, select Disabled.
  5. Select Finished.

BIG-IP DNS/Link Controller

Choosing a load balancing method other than Return to DNS for the DNS pool (BIG-IP DNS)

Important: If DNS Express is not configured, BIG-IP DNS or Link Controller systems will respond to only A, AAAA, and CNAME type DNS record queries. Queries for other types of records, such as NS or MX, will fail. 

  1. Log in to the Configuration utility.
  2. Go to DNS > GSLB > Pools.
  3. From the Pool List menu, select the applicable pool.
  4. Select Members.
  5. Select a load balancing method other than Return to DNS.
  6. Select Update.
