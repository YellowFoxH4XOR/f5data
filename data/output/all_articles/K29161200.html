K29161200: AS3 GET on /info or /declare endpoint cause BIG-IP to go into ''Changes Pending'' in HA

Type
Support Solution
Published
2021-06-25
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.2
Source
https://my.f5.com/manage/s/article/K29161200

Description

On a BIG-IP configured to have AS3 deployed (version lower than v3.26), when making a Rest API call with GET on /info or /declare from the client tool, the endpoint could cause BIG-IP to go into Changes Pending in HA pair.

For example: 

  • GET /mgmt/shared/appsvcs/info

    This may cause BIG-IP to got into Changes Pending, typically on the first request, and after making a GET request to the /declare endpoint.

    Another symptom of this, could be sending this request to the unit which was being synced from the device group, and this always causes the BIG-IP to go into Changes Pending.

  • GET /mgmt/shared/appsvcs/declare

    This always puts BIG-IP into an out-of-sync state with its peer, regardless if it's sent to Active or Standby unit.

Similar logs below will be seen in /var/log/audit:

bigip.local notice icrd_child[21532]: 01420002:5: AUDIT - pid=21532 user=admin folder=/Common module=(tmos)# status=[01020066:3: The requested value list (/Common/appsvcs/dataStore) already exists in partition Common.] cmd_data=create ltm data-group internal /Common/appsvcs/dataStore { type string }

bigip.local notice icrd_child[21532]: 01420002:5: AUDIT - pid=21532 user=admin folder=/Common module=(tmos)# status=[Command OK] cmd_data=modify ltm data-group internal /Common/appsvcs/dataStore { records replace-all-with { as3_async_records0 { data eNpTio5VAgACeQD9 } } }

Environment

  • Application Services 3 Extension (AS3) (version lower than v3.26)
  • HA pair with Manual Sync

Cause

This issue is tracked with Bug ID 978481.

Recommended Actions

The fix is introduced in AS3 release (3.26).

For the time being, you can consider use of Auto-Sync in the HA device-group a valid workaround.
