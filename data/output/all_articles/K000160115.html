Title Resolving JavaScript TypeError "Cannot convert object to primitive value" in APM Portal Access Legacy Rewrite Mode

Description

When accessing web applications through F5 BIG-IP APM Portal Access with Legacy rewrite mode enabled, JavaScript errors may occur in modern browsers. The specific error message is:

TypeError: Cannot convert object to primitive value

This error occurs when JavaScript code calls the setProperty method of an object and passes an object as the new value for the named property. The APM Portal Access rewrite engine injects a call to F5_Invoke_setProperty, which then calls ur$trace. The injected code at line 17019 in cache-fm-debug.js attempts to coerce the passed value to a primitive type, but when implicit conversion is not possible, it throws an uncaught exception. This exception bubbles up to the client code, causing web application malfunctions or rendering failures.

Environment

  • Product: BIG-IP APM (Access Policy Manager)
  • Version: 17.5.1 and other v17.x versions
  • Configuration:
    • Portal Access profile with JavaScript rewrite enabled
    • Rewrite Profile configured in Legacy mode
    • Portal Access Resource configured
  • Browser: Microsoft Edge 143 (may also affect other modern browsers)
  • Error Location: cache-fm-debug.js line 17019

Cause

The root cause is the use of Legacy rewrite mode in the APM Portal Access rewrite profile. The Legacy JavaScript rewrite engine has limitations when processing modern JavaScript constructs, particularly when handling object-to-primitive conversions in the injected F5_Invoke_setProperty wrapper function.

Answer/Recommended Actions

To resolve this issue, switch from Legacy to Modern rewrite mode using the Rewrite Control List (RCL) configuration:

  1. Navigate to Access > Connectivity / VPN > Portal Access > Rewrite in the BIG-IP configuration utility.
  2. Edit your existing Rewrite Profile or create a new one.
  3. Enable Split Tunneling to display the Rewrite Control List section.
  4. Add a new RCL entry:
    • Pattern: *://* (to apply to all resources)
    • Mode: Select Modern
    • Click Add to save the entry.
  5. Ensure the Rewrite Profile is assigned to your Portal Access resource.
  6. Test the web application to verify the error is resolved.

Important: When implementing Modern rewrite mode, ensure that the cache-fm-Modern.js script is loaded for all relevant pages and resources. If you scope Modern mode to only specific resources, the cache-fm-Modern script may not load properly for the entire application, causing the issue to persist.

Additional Information

  • The Modern rewrite mode provides better support for ES6/ES7 and modern JavaScript constructs compared to Legacy mode.
  • If you encounter additional JavaScript rewrite issues after switching to Modern mode (such as XML entity re-encoding problems), you may need to implement additional workarounds or contact F5 Support.
  • This issue is part of a known class of JavaScript rewrite limitations in Legacy mode. While no specific Bug ID matches this exact error, the pattern is consistent with historical APM rewrite engine bugs.
  • For applications that do not work correctly with Modern mode (such as some versions of Outlook Web Access), you can use the RCL to selectively apply Legacy mode to specific hosts while using Modern mode for others.
