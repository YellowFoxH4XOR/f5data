Known Issue

Description

When Active Directory authentication is used for administrative access to the ARX system, a invalid logon attempt will cause three invalid attempts in the Active Directory domain. As a result, if the domain policy enforces invalid logon attempt restrictions, the user account will be prematurely locked out in Active Directory domain (effectively 1/3rd of the desired invalid logon attempts).

This issue occurs when all of the following conditions are met:

  • The ARX is configured for Active Direcory Authentication for administrative access to the ARX.
  • An invalid logon is attempted (wrong password).

Impact

The user Active Directory account may become locked out and administrative access to the ARX denied.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Active Directory Account becomes locked out after fewer than expected invalid logon attempts.
  • The user account is unable to log in using a known good password after a previous failed logon attempt using a wrong password.
  • The syslog file contains multiple logon failure messages for a single invalid logon. The messages will appear similar to the following example:

    :MS_CLIENT-0-NOTE-MSG5:: client connect to 172.30.65.50 failed: STATUS_LOGON_FAILURE
    :AUTH_SSH-0-NOTE-AUTH_LOGIN_STATUS_FAIL:: LOGIN FAILURE @192.168.48.171 session 2629 interface  auth provider AD
    :SEC_LOCAL-0-ERR-LOCAL_CREDS_NOT_FOUND:: User account not found. [user@domain.com]
    :SEC_LOCAL-0-ERR-LOCAL_DEV_CREDS_NOT_FOUND:: User account not found. [user@domain.com]
    :SEC_LOCAL-0-NOTE-MSG5:: Login error: no account found checklocalauth.cc line 104
    :AUTH_SSH-0-NOTE-AUTH_LOGIN_STATUS_FAIL:: LOGIN FAILURE @192.168.48.171 session 2629 interface 172.30.64.213 auth provider LOC
    :AUTH_SSH-0-ERR-MSG3:: error: PAM: Permission denied for user@domain.com from workstation1.domain.com
  • Once the user's account has exceded the number of invalid logon attempts for the Active Directory domain, the syslog messages for subsequent logon attempts will indicate the account has been locked out. The syslog messages will appear similar to the following example:

    :MS_CLIENT-0-NOTE-MSG5:: client connect to 172.30.65.50 failed: STATUS_ACCOUNT_LOCKED_OUT
    :AUTH_SSH-0-NOTE-AUTH_LOGIN_STATUS_FAIL:: LOGIN FAILURE @192.168.48.171 session 2629 interface  auth provider AD
    :SEC_LOCAL-0-ERR-LOCAL_CREDS_NOT_FOUND:: User account not found. [user@domain.com]
    :SEC_LOCAL-0-ERR-LOCAL_DEV_CREDS_NOT_FOUND:: User account not found. [user@domain.com]
    :SEC_LOCAL-0-NOTE-MSG5:: Login error: no account found checklocalauth.cc line 104
    :AUTH_SSH-0-NOTE-AUTH_LOGIN_STATUS_FAIL:: LOGIN FAILURE @192.168.48.171 session 2629 interface 172.30.64.213 auth provider LOC
    :AUTH_SSH-0-ERR-MSG3:: error: PAM: Permission denied for user@domain.com from workstation1.domain.com

Workaround

To work around this issue, the user's domain policy can be modified to increase the number of invalid logon attempts allowed. This must be done by a domain admin for the user's Active Directory domain account.

Impact of workaround: Increasing the number of invalid logon attempts allowed for a user may be considered a security risk.
