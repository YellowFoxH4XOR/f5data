Topic

You should consider using this procedure when you want to place a Virtual Local Area Network (VLAN) in a BIG-IP tenant in an administrative partition other than the Common partition.

Description

When planning for BIG-IP tenants, you should consider the following factor:

  • If VLANs that reside in administrative partitions other than the Common partition are required, you should perform the following procedure since BIG-IP tenants create inherited VLANs in the Common partition by default.

Important: You must ensure that no other objects, such as self IP addresses, secure network address translations (SNAT), network address translations (NAT) and virtual servers have been configured to reference the inherited VLAN before proceeding to delete the VLAN. If there are objects already configured to reference the inherited VLAN, you must remove them before you attempt to delete the VLAN. Otherwise, the system will report an error that the VLAN is referenced by another object and fails to delete the VLAN.

Prerequisites

You must meet the following prerequisite to perform this procedure:

  • You have administrative access to the Configuration utility.

Procedures

To move an inherited VLAN on the BIG-IP tenant to an alternate partition, you must first delete the VLAN. To do so, perform one of the following procedures:

Moving a VLAN to an alternate partition using the Configuration utility

Impact of procedure: Performing the following procedure may impact traffic processing. You should perform this procedure during a maintenance window.

  1. Log in to the Configuration utility of the BIG-IP tenant.
  2. Navigate to Network > VLANs > VLAN List.
  3. Select the inherited VLAN and then followed by Delete.
  4. Navigate to System > Users > Partition List.
  5. Click Create and fill in the necessary information.
  6. Click Finished.
  7. Change to the new partition using the upper right hand corner selection box.
  8. Navigate to Network > VLANs.
  9. Click Create and fill in the necessary information. If your BIG-IP tenant is running on r2x00 or r4x00 series hardware products, you should select the corresponding interface under the Resources section that the inherited VLAN is tagged in the F5OS host. For example, if the inherited vlan VLAN123 is tagged to interface 5.0 in the F5OS host, you should add interface 1.5 as tagged when creating the VLAN for your BIG-IP tenant. If your BIG-IP tenant is running on r5x00, r10x00 or r12x00 series hardware products, you should leave the interfaces under the Resources section as is.

    Note: The tag used on the BIG-IP tenant VLAN must match the tag on the F5OS host VLAN.

  10. Click Finished.

Moving a VLAN to an alternate partition using the TMOS Shell

Impact of procedure: Performing the following procedure may impact traffic processing. You should perform this procedure during a maintenance window.

  1. Log in to the command line of the BIG-IP tenant.
  2. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  3. List the current VLANs by typing the following command:

    list /net vlan

  4. Delete the inherited VLAN by typing the following command syntax:

    delete /net vlan <VLAN Name>

  5. Create a new partition by typing the following command syntax:

    create /auth partition <Partition Name> description <"Description of the partition">

  6. Change directory to the new partition by typing the following command:

    cd /<Partition Name>

  7. Create the VLAN under the new partition by typing the following command syntax:

    For BIG-IP tenant running on r5x00, r10x00 or r12x00 series hardware products,

    create /net vlan <VLAN Name> tag <TAG> 

    For BIG-IP tenant running on r2x00 or r4x00 series hardware products,

    create /net vlan <VLAN Name> tag <TAG> interfaces replace-all-with { <interface number> { tagged } }

    Note: The <TAG> used on the BIG-IP tenant VLAN must match the tag on the F5OS host VLAN. For BIG-IP tenant running on r2x00 or r4x00 series hardware products, the <interface number> should match the interface on the F5OS host VLAN.

  8. Save the changes by typing the following command:

    save /sys config
