K000161904: Virtual Address marked unavailable when using Source Address List with multiple Virtual Servers on BIG-IP LTM

Type
Support Solution
Published
2026-06-29
Updated
2026-06-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1, 17.1.3
Source
https://my.f5.com/manage/s/article/K000161904

Description

Attaching a source address list (Traffic Matching Criteria) to a virtual server on BIG-IP LTM may cause the associated virtual address to be incorrectly marked as unavailable (status RED), even though at least one virtual server remains available. This impacts BGP route advertisement, causing routes to be withdrawn unexpectedly. The issue occurs when multiple virtual servers share the same virtual address (on different ports), and at least one is in an "Unknown" or "Down" state while another uses a source address list. Log messages may show the virtual address status changing from GREEN to RED and back, depending on configuration changes.

Environment

  • Product: BIG-IP LTM
  • Versions confirmed: 17.1.3, 17.1.3.1, 17.5.1.4, 17.5.1.5, 17.5.1.6
  • Configuration:
    • Multiple virtual servers sharing the same virtual address (different ports)
    • At least one virtual server with a source address list (Traffic Matching Criteria) applied
    • Virtual address configured with "Availability Calculation: When any virtual server is available"
    • "Route Advertisement: selective"
    • BGP used for route advertisement based on virtual address availability

Cause

Bug ID 2229461

Recommended Actions

The actions you can take to remediate this issue are:

  • Apply the Engineering Hotfix to resolve the issue.
  • Interim workarounds if EHF is not an option at the time:
    • Set the virtual address "Availability Calculation" to "Always Available."
    • Ensure all virtual servers sharing the virtual address use address lists, or ensure all are in "Available" state.
    • Remove or update any virtual server in "Unknown" or "Down" state sharing the virtual address.
  • Monitor for inclusion of the fix in future BIG-IP releases.

Additional Information

  • The issue is reproducible when two virtual servers share a virtual address and one is in "Unknown" or "Down" state while the other (with a source address list) is "Available." The virtual address inherits the unavailable status.
  • Removing the second (unknown/down) virtual server or making it available restores the virtual address to UP.
  • Changing both virtual servers to use address lists prevents the issue.
  • The fix resolves the issue.
