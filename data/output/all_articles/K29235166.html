Known Issue

The TCP timestamp rewrite mode does not work correctly on the client-side of embedded Packet Velocity Acceleration (ePVA) offloaded connections.

This issue occurs when all of the following conditions are met:

  • You have a FastL4 profile associated with a virtual server.
  • The TCP Timestamp Mode option is set to Rewrite.
  • The platform supports ePVA.

Impact

The TCP client does not correctly handle the FIN packets, resulting in connection issues.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you set the TCP Timestamp Mode option to Rewrite instead of the default, Preserve, the system does not correctly set the client-side TCP TSecr option for the FIN packets. When the flow is evicted due to FIN processing in ePVA, the process copies the time stamp from the server sending the FIN-ACK. This unexpected behavior causes the TCP client to halt at the FIN-WAIT-2, because the client acts as though the FIN-ACK from the BIG-IP system includes illegitimate time stamp options, and drops the FIN-ACK.

Resolution

Status

F5 Product Development has assigned ID 698462 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, do not use the Rewrite option. Leave the default option of Preserve in place.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
