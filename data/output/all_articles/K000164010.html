K000164010: BIG-IQ DNS discovery fails with Listener NullPointerException when DNS listener virtual servers retain DoS profiles

Type
Support Solution
Published
2026-10-27
Updated
2026-10-27
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.1
Source
https://my.f5.com/manage/s/article/K000164010

Description

BIG-IQ Centralized Management DNS service discovery fails while transforming a listener and returns:

Configuration Discovery: Error while transforming Listener, exception 'NullPointerException' was returned

The DNS Sync Group may remain in “Collecting Data” when a BIG-IP DNS listener virtual server retains BIG-IP AFM DoS or security-log profiles after BIG-IP AFM is no longer provisioned

Environment

• BIG-IP DNS/GTM version 17.5.1.

• BIG-IP DNS devices managed and monitored through BIG-IQ.

• DNS listener virtual servers retained DoS/AFM-related profiles and security-log profiles although AFM was not provisioned.

Cause

A DNS listener is also represented as a BIG-IP LTM virtual server. Retained BIG-IP AFM-related profiles can cause the listener REST response to contain a nameReference for a DoS profile that cannot be resolved. BIG-IQ Centralized Management then fails to transform the listener and returns a NullPointerException.

Answer/Recommended Actions

  • Create a UCS backup of the affected BIG-IP DNS device before making configuration changes.

tmsh save sys UCS <name of the UCS file>.ucs

  • Review the TCP and UDP DNS listener virtual-server configurations:

tmsh list ltm virtual <tcp_dns_listener>

tmsh list ltm virtual <udp_dns_listener>

  • Remove the retained DoS profile and related security-log profiles from each affected listener virtual server. Replace the placeholders with the actual listener and profile names identified in the previous step:

tmsh modify ltm virtual <tcp_dns_listener> profiles delete { <dos_profile_name> }

tmsh modify ltm virtual <tcp_dns_listener> security-log-profiles delete { <security_log_profile_name> }

tmsh modify ltm virtual <udp_dns_listener> profiles delete { <dos_profile_name> }

tmsh modify ltm virtual <udp_dns_listener> security-log-profiles delete { <security_log_profile_name> }

  • Verify that the BIG-IP AFM-related configuration has been removed:

tmsh list ltm virtual <tcp_dns_listener>

tmsh list ltm virtual <udp_dns_listener>

  • Save the configuration:

tmsh save sys config

  • In BIG-IQ Centralized Management, rediscover the affected device’s BIG-IP LTM service, then rediscover its BIG-IP DNS service.
  • Refresh the DNS Sync Group status and verify that the member health is green.

Additional Information

BIG-IP DNS listeners are represented as BIG-IP LTM virtual servers. DoS-profile configuration may therefore appear in the LTM virtual-server configuration even when it is not displayed on the DNS listener page. Removing stale BIG-IP AFM-related configuration from the listener virtual servers allows BIG-IQ Centralized Management to rediscover the BIG-IP LTM and BIG-IP DNS services successfully. If the device has only DNS licensed, you may not see the "Local Traffic" tab in the GUI, please use CLI to check/modify the DNS listener configuration in such condition.
