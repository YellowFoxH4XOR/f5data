Known Issue

After you relicense the BIG-IP system, the configuration may fail to load.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is licensed and provisioned with the Link Controller module.
  • You create an iRule with a proc configuration that contains the DNS:: command.

    For example:

      ltm rule test_rule {
          proc <proc name> { } {
                  DNS::answer
          }
          when DNS_REQUEST {
                  call <proc name>
          }
      }

  • You relicense your BIG-IP system, removing the Link Controller module. 
  • You attempt to load the system configuration.

Impact

Configurations that contain an iRule proc command that uses the DNS:: command fail to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A configuration that contains an iRule proc command that uses the DNS:: command prevents the configuration from loading.
  • When you install a user configuration set (UCS) file that contains an affected iRule, the configuration fails to load.
  • Following an upgrade to an affected version, when you boot to the new boot location and roll forward a configuration containing an affected iRule, the configuration fails to load.

Workaround

Impact of workaround:  Performing the suggested workaround may require an in-depth review of how the virtual servers are currently using the iRule to determine the impact of removing the iRules that contain the DNS:: command.

To work around this issue, you can modify the BIG-IP configuration before you relicense the system, and remove all iRules that contain the proc and DNS:: command combination.
