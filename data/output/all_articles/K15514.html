Known Issue

The memory usage on a standby BIG-IP system may continuously increase. This issue occurs when all of the following conditions are met:

  • Your system uses a diameter virtual server with the Connection Mirroring setting enabled.
  • The diameter virtual server is associated with a diameter profile that has the following options set to a value greater than zero (0):

    • Maximum Retransmit Attempts (default value is 1)
    • Retransmit Timeout (default value is 10)

Impact

Over time, standby unit performance may degrade, and the standby unit may eventually become unresponsive or reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H475795 on the Diagnostics > Identified > High screen.
  • Memory usage on the standby unit continuously increases.
  • The standby unit stops responding or reboots due to memory exhaustion.

Workaround

To work around this issue, you can disable connection mirroring on the affected diameter virtual server. Alternatively, you can disable diameter retransmission for the affected diameter virtual server by configuring the Maximum Retransmit Attempts setting and the Retransmit Timeout setting in the associated diameter profile to 0. To do so, perform either of the following procedures:

Disabling the Connection Mirroring setting on the diameter virtual server

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the affected diameter virtual server.
  4. Clear the Connection Mirroring check box.
  5. To save the changes, click Update.
  6. Ensure that the configuration is synchronized between the high availability (HA) units by performing the appropriate procedure described in K13920: Performing a ConfigSync using the Configuration utility.

Disabling diameter retransmission for the diameter virtual server

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > Diameter.
  3. Click the name of the diameter profile associated with the affected diameter virtual server.
  4. Select the Maximum Retransmit Attempts check box if it is not already selected, and set the value to zero (0).
  5. Select the Retransmit Timeout check box if it is not already selected, and set the value to zero (0).
  6. To save the changes, click Update.
  7. Ensure that the configuration is synchronized between the HA units by performing the appropriate procedure described in K13920: Performing a ConfigSync using the Configuration utility.
