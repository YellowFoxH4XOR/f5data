K000156850: How do I check if Database (DB) variable tm.tcpudptxchecksum is configured as non-default value Software-only on a BIG-IP system?

Description

The tm.tcpudptxchecksum setting determines how the BIG-IP system computes the transmit (TX) checksum for TCP and UDP packets. You may need to modify this setting under certain troubleshooting or operational conditions.

Purpose

This setting controls the mode of TX checksum computation:

  • Hardware-only: Utilizes hardware offload (HSB/NIC) for checksum generation.
  • Software-only: Forces TMM to compute checksums via software, disabling hardware offload.

Why choose Software-only? Troubleshooting hardware/NIC/driver checksum issues or validating system behavior without offload. Note: This setting can increase CPU usage and reduce throughput slightly.

Environment

  • Applicable to BIG-IP systems across various platforms and versions.
  • Behavior depends on default settings specific to platform and version.
  • Systems with hardware offload typically default to Hardware-only.
  • Virtual editions (without offload) may default to Software-only.

Cause

Unknown at the time of publication.

Recommended Actions

Follow these steps to determine if tm.tcpudptxchecksum is configured as Software-only:

  1. Access the BIG-IP system via tmsh (Traffic Management Shell).
  2. Run the following command:
tmsh list sys db tm.tcpudptxchecksum all-properties

Read the output to identify:

  • value: The currently active setting.
  • default-value: The platform and version's default setting.

Interpretation Examples:

  • By default, database variable is set to "Hardware-Enabled", as mentioned in Overview of the 'tm.tcpudptxchecksum' db variable.
  • If the value is Software-only, tm.tcpudptxchecksum is set to non-default value Software-only.

Optional one-liner to check:

tmsh list sys db tm.tcpudptxchecksum all-properties | egrep ' value '
