Topic

This article describes the use of the http-uri operand in local traffic policies with the BIG-IP AAM Intelligent Browser Referencing (IBR) feature.

Description

When using a local traffic policy to enable and disable BIG-IP AAM, you can create policy rules to match the file extension in the request URI using the http-uri operand.  For example, the following local traffic policy rule enables BIG-IP AAM functionality when the file extension equals gif or jpg:
 

ENABLE_AAM {
    actions {
        0 {
            wam
            enable
        }
    }
    conditions {
        0 {
            http-uri
            extension
            values { gif jpg }
        }
    }
    ordinal 1
}

When the IBR feature is enabled in an acceleration policy, the BIG-IP AAM system appends an IBR tag to the file extension. For example, a web page contains a link to an image with the following URL:

http://www.example.com/images/image.jpg

The IBR feature modifies the file name by appending an internal reference tag to the file extension that results in a request for the following URL:

http://www.example.com/images/images.jpg;wa2e5c801a80cacd22

Because the preceding policy rule is configured with the equals condition, the policy rule fails to match the modified file extension and the request may unintentionally bypass BIG-IP AAM.  

Recommended Actions

When using the http-uri operand in local traffic policies to control AAM functionality, use the begins or starts-with condition rather than the is or equals condition to match file extensions modified by the IBR feature.
