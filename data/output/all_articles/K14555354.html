Known Issue

HTTP may close connections on a virtual server configured with a OneConnect profile.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server to use HTTP and a OneConnect profile.
  • A client sends an HTTP/1.0 CONNECT request without a connection header or an HTTP/1.1 CONNECT request with a Connection: close header.

Impact

HTTP closes the connection by sending a FIN on both client and server flows, even if the server responds with an HTTP 200 - OK response.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You may observe that HTTP closes the connection by sending a FIN on both client and server flows, even if the server responds with an HTTP 200 - OK response.

Workaround

To work around this issue, you can use the following iRule to disable HTTP parser after the client detects an HTTP CONNECT request.

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > Create.
  3. In the Name box, type a name for the iRule.
  4. In the Definition box, type the following text:

    when HTTP_REQUEST {
      if { [HTTP::method] eq "CONNECT" } {
     HTTP::disable
     }
    }

  5. Click Finished.
  6. Click Virtual Servers.
  7. Click the name of the virtual server that is affected by this issue.
  8. Click the Resources tab.
  9. In the iRules section, click Manage.
  10. From the Available column, select the iRule you previously created.
  11. Click the << button.

    The iRule moves to the Enabled column.

  12. Click Finished.
