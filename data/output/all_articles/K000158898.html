Title: Accessing BIG-IP APM management IP and Self IP from within an APM SSL VPN (Network Access) tunnel

1. Description

After a user establishes an APM SSL VPN (Network Access) tunnel, the user may be unable to reach:

  • The BIG-IP management IP (for GUI/SSH on the management interface)
  • The BIG-IP Self IP used for SSL VPN termination (or other BIG-IP Self IP/virtual addresses)

This can be unexpected when those same destinations are reachable during normal (non-VPN) access and Self IP port lockdown allows the required services.

2. Environment

  • Product: BIG-IP APM
  • Version: 17.5.1
  • Feature: APM Network Access (SSL VPN)
  • Typical configuration characteristics:
    • Management IP on a dedicated management interface/network (management plane)
    • SSL VPN terminates on the data plane (virtual server / Self IP)
    • VPN clients receive addresses from a lease pool and attempt to reach BIG-IP addresses over the tunnel
    • Self IP port lockdown may be set to “default” or “allow/custom”

3. Cause

  • BIG-IP management traffic is separated from the data plane by design (management/data plane separation), so APM Network Access (VPN tunnel) traffic cannot directly reach the management IP.
  • Access to Self IPs/virtual servers from inside the VPN tunnel can also fail if the destination virtual server is not configured to accept traffic from the VPN-associated VLAN/tunnel context.

4. Recommended Actions

  1. Provide management access over the VPN tunnel using a supported proxy method (K13299)
    1. Create a dedicated internal virtual server that is reachable from the VPN tunnel.
  2. Create and attach an iRule that forwards incoming connections to the BIG-IP management IP and required port (example for GUI/HTTPS shown in the case):
  3. Create iRule:

    • when CLIENT_ACCEPTED { node 10.100.22.113:443 }
  1. Apply the iRule to the dedicated virtual server listening on HTTPS.
  2. Restrict access to the admin virtual server to trusted VPN users/sources only.
  3. Apply the security mitigation referenced by K13299 for CVE-2022-33962 (K80970653).
  4. Allow access to Self IPs / other virtual servers from inside the VPN tunnel
  5. On the destination virtual server, verify:

  7. VLAN and Tunnel Traffic settings permit the VPN path.
    1. The correct VLAN(s) (including the VPN connectivity/VLAN context) are assigned/allowed for that virtual server.
  8. If full-tunnel VPN is used
    1. Review client routing behavior, since full-tunnel configurations can change which paths are used to reach BIG-IP addresses and internal resources.

5. Additional Information

  • Changing a Self IP port lockdown setting alone does not make the management IP reachable through the VPN tunnel because the management interface is not natively routable from the data plane.
  • Using a forwarding/proxy virtual server to reach management services increases exposure; limit access and apply the referenced mitigation guidance.
