K000149146: Connections can hang when using virtual servers with destination address lists and persistence

Type
Support Solution
Published
2024-12-30
Updated
2025-06-30
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000149146

Description

Connections to the virtual server can get stuck or be left hanging.

tmm CPU utilization may increase as the persistence activities increase.

 

Symptoms

The clientside of the connection can be seen as established. However, tmm makes no attempt to create a serverside connection.  The following example shows the clientside connection is established because there is a Flow ID.  However, the serverside Peer ID is never populated, even after the connection timed out.

Normally, for TCP with fastl4, a serverside connection is attempted immediately after a SYN is received.  With a tcp profile, a serverside connection would be attempted after the clientside completes the 3WHS.

 

Also, when there is a problem, persistence activity will appear higher than normal.

Environment

  • A virtual server is configured using address lists as the destination address
  • A persistence profile that uses the persistence table is configured on the virtual server:
    • Source Address (but not hash-algorithm carp)
    • Destination Address (but not hash-algorithm carp)
    • Universal
    • Cookie (only cookie hash)
    • Host
    • SSL session
    • SIP
    • Hash (but not hash-algorithm carp)

Cause

Bug ID: 912293

 

Recommended Actions

Apply the following workaround ( until an EHF is available ):

 

Enable match-across-virtuals in the persistence profile.

 

Note: Enabling match-across-virtuals might might affect the behavior of other virtual servers in the configuration that utilize persistence profile.
