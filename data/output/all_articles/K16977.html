Known Issue

The BIG-IP configuration may fail to load if the admin account is disabled.

This issue occurs when all of the following conditions are met:

  • You have a new user BIG-IP system account with administrator privileges.
  • You disable the default admin account by navigating to BIG-IP Configuration utility > System > Platform > User Administration > Admin Account.
  • You configure the new user account as the replacement for the default administrator account.
  • You perform either of the following actions:
    • You upgrade your system to a version later than BIG-IP 11.6.0.
    • You restart the system while running BIG-IP 12.0.0.

Impact

The BIG-IP system is unable to load the configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system configuration has no objects.
  • The BIG-IP system is not passing any traffic.
  • On BIG-IP 12.0.0 single-NIC virtual deployments, the configurations fail to load after a restart.
  • When you try to load the BIG-IP system configuration, an error message similar to the following appears:

    01070829:5: Input error: can't create user, role partition mapping, user does not exist, admin2
    Unexpected Error: Loading configuration process failed.

Workaround

There is no workaround for this issue. To resolve this issue, you can reboot the BIG-IP system back to the previous working boot location that has the administrator user disabled. For single-NIC virtual deployments, you can re-enable the default administrator user account. To do so, perform one of the following procedures:

Impact of workaround: Since the BIG-IP system is already in the inoperative state, performing the following procedure should not have a negative impact on your system.

Rebooting the BIG-IP system to the previous working boot location:

  1. Log in to the Traffic Management shell (tmsh) by typing the following command:

    tmsh

  2. To reboot the BIG-IP system to the desired boot location, type the following command syntax:

    reboot volume <boot_location>

Re-enabling the default admin user account on BIG-IP system (for single-NIC virtual deployments):

Azure BIG-IP Virtual Edition (VE):

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Re-enable the default administrator user account by typing the following command:

    modify /sys db systemauth.primaryadminuser value admin

  3. Re-load BIG-IP configuration by typing the following command:

    load /sys config

Amazon Web Services BIG-IP VE:

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Re-enable the default administrator user account by typing the following command:

    modify /sys db systemauth.primaryadminuser value admin

  3. Update the password for the default administrator user by typing the following command syntax:

    modify /auth user admin password <password>

  4. Re-load BIG-IP configuration by typing the following command:

    load /sys config
