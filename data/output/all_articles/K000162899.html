Description

  • BIG-IP tenant configuration validation fails when module provisioning requires more disk space than the tenant allocation provides during an upgrading of a F5OS tenant to v17.1.3.6, v17.5.1.8, v21.1.0.1 or above.
  • An error similar to the following appears from /var/log/ltm when running tmsh load sys config verify inside the BIG-IP tenant:

Provisioning failed with error 1 - 'Disk limit exceeded. 16188 MB are required to provision these modules, but only 15100 MB are available.'

Environment

  • rSeries tenant
  • Configuration validation performed inside the BIG-IP tenant
  • Tenant disk allocation at or near the minimum size

Cause

Minimum disk requirements vary between software releases. The tenant disk allocation must be larger than the minimum required size for the installed software and provisioned modules. Refer to K45191957: Overview of the BIG-IP tenant image types for the applicable requirements.

Answer/Recommended Actions

  1. Run tmsh load sys config verify inside the BIG-IP tenant and note the required and available disk-space values.
  2. Change the tenant state to Provisioned.
  3. Increase the tenant disk allocation to a value greater than the reported required amount. See K45191957: Overview of the BIG-IP tenant image types.
  4. Save the updated settings.
  5. Change the tenant state to Deployed.
  6. Retry configuration validation or tenant startup.

Additional Information

Increase the tenant storage allocation. The provisioning error does not identify a specific directory that requires additional space.
