K01293626: How to Access F5 API while using RADIUS authentication 11.6.0 and earlier

Support Solution
Published
2019-09-26
Updated
2023-02-21
Applies to

  • BIG-IP LTM: 16.X.X, 16.1.X, 16.0.X, 11.6.X, 16.1.0, 16.0.1, 16.0.0, 16.1.3, 16.1.2, 16.1.1, 11.6.5, 11.6.4, 11.6.3, 11.6.2, 11.6.1, 11.5.X, 11.5.10, 11.5.9, 11.5.8, 11.5.7, 11.5.6, 11.5.5, 11.5.4, 11.5.3, 11.5.2, 11.5.1, 11.5.0, 11.6.0

Description

  • Not able to do REST calls using remote authentication unless the user's role is admin.
  • TOKEN could be request but it does not work to GET the objects through REST calls.
  • 401 error received when using the TOKEN.

Environment

  • LTM 11.6.0 or earlier
  • RADIUS server

Cause

On version 11.6.0 and below only remote admin users are able to do REST calls.

Recommended Actions

Add a user to the BIG-IP system and assign the desired role. This causes a local account to be created with no password and authenticated through the remote authentication server.

  1. Create user locally with a role different than admin, in this example, we will create one as Auditor.

  2. On the Authentication method ( System  ››  Users : Authentication ) change it to "Local"

  3. Change back to RADIUS or the remote authentication you are using.

  4. You should be able to log in with the RADIUS credentials.

  5. Do a curl on your BIG-IP system to allow the new user to have permissions to do REST calls (this user has to be also on your RADIUS server). 

    curl -sk -u <admin_username>:<admin_password> https://localhost/mgmt/shared/authz/roles/iControl_REST_API_User -H "Content-Type: application/json" -X PATCH -d '{ "userReferences":[{"link":"https://localhost/mgmt/shared/authz/users/<username>"}] }'

    Note: In this command syntax, note the following: Replace <admin_username> and <admin_password> with the username and password of a BIG-IP user account with the administrator role Replace <username> with the username of the user to whom you want to grant iControl access.

  6. After doing so, do the request for the TOKEN:

    curl -sk -H "Content-Type: application/json" -X POST https://<big-ip ip address>/mgmt/shared/authn/login -d '{"username":<username>","password":"<password>","loginProviderName": "tmos"}' | jq

  7. Then do a request to see the Virtual servers configured:

    curl -sk -H "X-F5-Auth-Token: <token value>" https://<big-ip ip address>/mgmt/tm/ltm/virtual/ | jq

You should see that the request is successful.
