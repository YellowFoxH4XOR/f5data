K000158933: Ordinary MAC masquerade address should not have a value of '1' in the least-significant bit in the first byte of the MAC address

Type
Support Solution
Published
2025-12-29
Updated
2025-12-29
Applies to
  • rSeries Platforms
  • F5OS
  • F5OS-A: 1.8.3
  • rSeries 5000
  • rSeries 10000
Source
https://my.f5.com/manage/s/article/K000158933

Description

MAC addresses which have a value of '1' for the least significant bit in the first byte of the MAC address are reserved for multicast and shouldn't be used as an ordinary MAC masquerade addresses when setting up a MAC masquerade address in a traffic group on LTM. 

Environment

BIG-IP LTM


Cause

When an ordinary MAC address is required, it is important not to accidentally choose a MAC address which is reserved for multicast on the box.

 

Recommended Actions

None.


Additional Information

In order to check if a MAC address is reserved for multicast or not, please check the value of the least significant bit of the first byte of the MAC address.

For example, a MAC address of 01:02:03:04:05:06 has 0x01 as the first byte, which translates to '00000001' in binary, which means the least significant bit's value is '1', therefore this is a multicast MAC address and should not be used as an ordinary MAC masquerade address.

Another example: The MAC address FE:FD:FC:FB:FA:F9 has 0xFE as the first byte, which translates to '11111110' in binary, which means the least significant bit's value is '0', therefore this is not a multicast MAC address and can be used as an ordinary MAC masquerade address.
