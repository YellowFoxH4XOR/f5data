K73487471: Diameter connection issue after upgrade

Type
Support Solution
Published
2022-06-06
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.X.X, 15.1.4, 15.1.2, 15.1.1, 15.1.0, 15.0.1, 15.0.0, 16.1.3, 16.1.2, 16.1.1, 15.1.6, 15.1.5, 15.1.3, 16.0.X, 15.1.X, 15.0.X, 16.1.0, 16.0.1, 16.0.0, 15.1.8, 15.1.7, 15.X.X, 16.1.X
Source
https://my.f5.com/manage/s/article/K73487471

Description

  • Diameter connection issue after upgrade to software version 15.x or 16.x
  • When forwarding server side response to the client, F5 sends RST right after the response, instead of letting the client to gracefully close the connection via FIN.
  • At the time of the issue the following TCL error is logged:

    err tmm3[18874]: 01220001:3: TCL error: /Common/irule_diameter <DIAMETER_EGRESS> - Illegal value (line 1) error Illegal value invoked from within "DIAMETER::avp delete 257"
    err tmm3[18874]: 01cc0006:3: Peer (Example at 10.0.0.1:40761) connection state has changed: disconnected

Environment

  • iRule with DIAMETER_EGRESS event
  • Upgrade to software version 15.x or 16.x
  • Diameter

Cause

Seen behaviour is caused by a known issue tracked with the Bug ID 921441.

Recommended Actions

There is no fix at the time of creation of this article. As a workaround you can modify the Diameter iRule as shown in the following example:

  • Original iRule

    when DIAMETER_EGRESS priority 100 {
        DIAMETER::host origin "example"
        if { [DIAMETER::command] ne "257" } {
            DIAMETER::avp delete 257
        }
    }

  • Modified iRule

    when DIAMETER_EGRESS priority 100 {
        DIAMETER::host origin "example"
        if { [DIAMETER::command] ne "257" && [DIAMETER::avp count 257] > 0} {
           DIAMETER::avp delete 257
        }
    }
