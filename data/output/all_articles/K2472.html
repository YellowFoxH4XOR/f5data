Topic

Earlier version of BIG-IP contained a feature that helped you manage very large configurations (many thousands of nodes). This feature, originally called ping node aliasing, provided more precise control for monitoring nodes and services on those nodes. This feature enabled an administrator to configure the BIG-IP to consider an entire group of nodes as up if only one specific node in the group was actually checked.

Beginning in BIG-IP version 4.0, the implementation for health checking nodes changed dramatically and administrators could control ping node aliasing even more effectively than in previous versions.

For example, before version 4.0 you could only ping node IP addresses as a group, and could not check if a specific port was open and responsive. As of version 4.0, you can check addresses and services on one node and have the status of an entire group of nodes depend on the health of that node.

For this configuration, a default wildcard monitor typically is used to monitor the state of a group of nodes. When applied to the nodes in a group, the monitor automatically checks the configured IP address and service port for a given node and marks it up or down accordingly.

Starting in version 4.0, you can create a user-defined monitor with a specific address and/or service to check and then apply this monitor to a large group of nodes. In this configuration, BIG-IP will mark all the nodes as up, as long as one node address alias or node port alias in the group is alive. This is especially useful when you have a group of nodes that are all actually IP aliases to one physical server.

For example, an Apache web server with 100 HTTP 1.1 Virtual Host servers. The benefit is a reduction of network traffic, because this implementation prevents the BIG-IP from having to perform health checks on a large number of individual IP addresses and services.

Configuration examples

Following are two configuration examples for pinging a single node in order to define the health of a group of nodes.

Note: For specific instructions about creating pools, monitors, and node/monitor associations, refer to the BIG-IP Reference Guide.

ICMP

To define the status of a group of nodes when pinging only one node using Internet Control Message Protocol (ICMP), perform the following steps:

  1. Create a pool that contains the addresses and ports for the servers that you want to monitor as a group with a node address alias.
  2. Create a new monitor, using the default ICMP monitor as a template.
  3. In the new monitor's properties, specify the address of one of the nodes in the pool as the destination address (instead of the wildcard character *).
  4. Associate all the pool's node addresses with the new monitor that you've created.

BIG-IP will now only ping the single IP address you specified and mark all nodes in the group with the status of the specified node.

HTTP GET requests

To define the status of a group of nodes when pinging only one node using HTTP GET requests on port 80, perform the following steps:

  1. Create a pool that contains the addresses and ports for the servers that you want to monitor as a group with a node address alias.
  2. Create a new monitor, using the default HTTP monitor as a template.
  3. In the new monitor's properties, specify the address of one of the nodes in the pool as the destination address (instead of the wildcard character *), and use port 80 for the destination service.
  4. Associate all the pool's node addresses with the new monitor that you've created.

BIG-IP will now open HTTP connections to port 80 on only the single IP address you specified and mark all nodes in the group with the status of the specified node.
