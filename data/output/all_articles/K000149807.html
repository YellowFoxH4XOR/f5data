Description

When NGINX Agent reports the same 'client-id' on two or more NGINX instances then only one of those instances will appear in NGINX Instance Manager UI.

Environment

NGINX Instance Manager

Cause

This issue can occur when NGINX instance VMs are cloned from the same template. The NGINX Agent will set the 'client_id' attribute based on information in one of the following files on the host system:

/sys/class/dmi/id/product_uuid
/etc/machine-id
/proc/sys/kernel/random/boot_id

Note: NGINX Agent will stop on the first file found, checking the files from top to bottom.

Recommended Actions

Make the NGINX systems' id information unique to each other.

Additional Information

The 'client_id' information can be found in TRACE level NGINX Agent logs (/var/log/nginx-agent/agent.log). For example:

time="<date_time>" level=trace msg="Process function in the commander.go, comms.status meta:<timestamp:<seconds:1738889126 nanos:767183351 > client_id:\"704253e9-233c-3277-bbc7-a343a3be34e2\" message_id:\"870788d7-a320-41cf-8f92-7b989bac18c8\" ...

And in INFO level NGINX Agent logs when NGINX Instance Manager publishes a configuration:

time="<date_time>" level=info msg="Commander received meta:<timestamp:<seconds:1739552477 nanos:423165768 > client_id:\"704253e9-233c-3277-bbc7-a343a3be34e2\" message_id:\"39117e9d-c2ef-4b38-ac37-38e03e8aa1e2\" > type:DOWNLOAD nginx_config:<action:APPLY config_data:<system_id:\"704253e9-233c-3277-bbc7-a343a3be34e2\" ...

The NGINX Instance Manager will set attributes systemUid and system_id to the value of client_id received from the NGINX Agent. 

curl -kL -X GET https://<nim_host>/api/platform/v1/instances --header 'Authorization: Basic '$CREDS'' --header 'Content-Type: application/json' | jq | grep systemUid
"systemUid": "704253e9-233c-3277-bbc7-a343a3be34e2", ...
