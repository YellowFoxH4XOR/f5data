Description

ASM policies flipped from Transparent to Blocking after the configuration failed to load. It also flipped from manual learning to automatic learning.

Error Messages in /var/log/ltm indicating configuration failure:

"Unexpected Error: Loading configuration process failed.
"warning mcpd[8819]: 01071423:4: High config load failed during a license reset. Fallback to base load"

Environment

  • BIG-IP ASM
  • Configuration failed to load
  • Licensing failures

Cause

Bug ID 842013

Recommended Actions

  1. See Workaround options in Bug ID 842013
  2. Ensure the ASM Policy has a customized policy-template configured with the desired Blocking or Transparant Mode.  In case of config load failure, the ASM policy will be re-created using the policy-template.

For Example:

asm policy /Common/example.com-443 {
        active
        encoding utf-8
        policy-template MY_CUSTOM_POLICY_TEMPLATE  
}

Example of how a Transparent ASM Policy was flipped to Blocking Mode after failure to load the configuration:  
This ASM Policy will be re-created using the POLICY_TEMPLATE_FUNDAMENTAL template (Blocking Mode by default, see K15530590) after a config failure:

asm policy /Common/example.com-443 {
        active
        encoding utf-8
        policy-template POLICY_TEMPLATE_FUNDAMENTAL
}

Create custom policy-template here in v15:
GUI: Security  ››  Options : Application Security : Advanced Configuration : Policy Templates

Additional Information

1. During the re-licensing process or during an upgrade, if a full configuration load cannot be done, BIG-IP falls back to a load base config.
2. Load base config doesn't load any ASM policies as those are not in the base config, but in the database which is lost on a base load.
3. The policies are then recreated because the policy references exist in bigip.conf, but not in the database.
4. The template name used to create the policies is stored and so that template is used to try to recreate the policy.
5. If this template does not have proper settings then the ASM policy recreated will have the wrong settings.
6. These new changes could be synced to the other HA pair
