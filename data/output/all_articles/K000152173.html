K000152173: REST API PUT doesn't default values to parent profile

Type
Support Solution
Published
2025-06-26
Updated
2025-09-30
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000152173

Description

As per https://my.f5.com/manage/s/article/K13225405 - Updating a configuration with PUT will modify the object's configuration, however configuration parameters that are not specified as part of the command will acquire their default settings.

In the below example a client SSL profile which has a custom certificate and a key inherited from its parent profile is updated.

When sending the below PUT request the certificate and the key to be used are not specified - it is expected they are to be set to default values (of the parent profile):

curl -sku admin:admin -H "Content-Type: application/json" -X PUT \
-H "User-Agent: python-requests/2.32.3 f5-icontrol-rest-python/1.3.13" \
https://192.0.2.1/mgmt/tm/ltm/profile/client-ssl/~Common~profile_child \
-d '{"defaultsFrom": "/Common/profile_parent", "name": "profile_child", \
"tmOptions": ["dont-insert-empty-fragments"], "cacheTimeout": "3620", \
"partition": "Common", "renegotiation": "disabled"}' | jq .

The result though is that the profile gets default.crt and default.key now (instead of those inherited from the parent)

Environment

REST API PUT requests to update client SSL profile settings.

 

Cause

ID1966085 Modyfing child clientssl profile via REST API breaks parent profile inheritance for certKeyChain

 

Recommended Actions

None.
