K000149842: Port Exhaustion errors during TMOS Upgrade

Type
Support Solution
Published
2026-08-31
Updated
2026-08-31
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000149842

Description

Inet port exhaustion error logs are observed in /var/ltm log file during upgrade on configsync IPs of bigip peers on port 4353 and port 6699, the error logs start once the HA connection is cut to CMI peer due to an upgrade version mismatch, and stops right after the HA connection is re-established. The BIG-IP log similar logs to example below:

err mcpd[10650]: 01071918:3: CMI device (/Common/hostname) has a different version (17.1.2) from this device (17.1.1).

crit tmm8[5829]: 01010201:2: Inet port exhaustion on <Configsync-ip> to < configsync-ip>:4353 (proto 6)

crit tmm3[23837]: 01010201:2: Inet port exhaustion on <Configsync-ip> to < configsync-ip>:4353 (proto 6)

notice mcpd[7766]: 01071432:5: CMI peer connection established to <configsync-ip> port 6699 after 222 retries

 

Environment

  • Upgrade
  • HA Pair
  • Port

Cause

This is caused by the repetitive connection requests between config sync IPs on port 4353

Impact

There is no production impact as the error log is triggered when the HA connection is already lost.

Recommended Actions

No Actions needed, the error log will stop once the HA connection is re-established to CMI peer.
