Known Issue

Renaming a file or directory to its alternative 8.3 name using the ARX virtual server will result in a metadata inconsistency. The ARX metadata is updated with the 8.3 name. However, the file on the back-end filer remains unchanged.

This issue occurs when the following condition is met:

  • The new name exactly matches the file's alternate 8.3 name.

The ARX sends a rename request to the filer. However, the filer does not rename the file because it recognizes the new name is the same as the 8.3 alternative name, which it already associates with the file. The filer does not respond with an error, so the ARX updates metadata to the new name.

For example, consider a file named Original_File_Name.txt, which has an alternate 8.3 name of ORIGIN~1.txt. If you access the ARX virtual server and rename the file from Original_File_Name.txt to ORIGIN~1.txt, the file rename will complete without an error. However, attempting to access the file using the virtual server will fail. A directory listing using the virtual server will display the ORIGIN~1.txt name, but a directory listing of the back-end filer directly will display the unchanged file of Original_File_Name.txt.

Impact

Unable to access the file due to a metadata inconsistency.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Unable to access the renamed file using the ARX virtual server
  • After renaming a file using the ARX virtual server, a directory listing using the virtual server will display the new name. However, a directory listing using the back-end filer directly will display the original name
  • A metadata report will indicate an inconsistency for the affected file or directory name

Workaround

To recover from this issue, you must repair the metadata inconsistencies. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the ARX command line.
  2. Enable privileged mode by typing the following command:

    enable
  3. Repair the metadata inconsistencies with the sync files command using the following command syntax:

    sync files namespace volume volume path path [share share-name] [recurse] [rename-files]
