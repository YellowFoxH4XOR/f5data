Description
BIG-IP i15800s stop generating performance data and statistics after adding configuration objects. SNMP polling doesn't return any statistical data and network monitoring utilities show empty, zero, or NaN values. You see these error messages frequently in /var/log/ltm

err merged[12345]: 011b0900:3: TMSTAT error tmstat_remerge: Cannot allocate memory.
err merged[12345]: 011b0900:3: TMSTAT error tmstat_remerge: Cannot allocate memory.
err merged[12345]: 011b0900:3: TMSTAT error tmstat_remerge: Cannot allocate memory.

Environment

  • BIG-IP version prior to 16.1
  • BIG-IP i15800 or other platform with a large number of TMMs / CPU cores
  • Large number of configuration objects, such as thousands or tens of thousands of Virtual Servers, profiles, pool members, and monitors

Cause
merged process attempting to allocate 2.7GB or more total memory for itself

Recommended Actions

Update to a version with the memory layout fix for ID 943653 to allow 32-bit processes such as merged to use the full 4GB of memory. Without that fix, 32-bit processes are limited to a total size of ~2.7GB

Additional Information
The size of the merged process can be viewed with the top or ps commands
