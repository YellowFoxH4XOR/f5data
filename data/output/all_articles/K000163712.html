K000163712: SSL VPN Trusted Site Registration Issue

Type
Support Solution
Published
2026-10-14
Updated
2026-10-14
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163712

Description

BIG-IP APM SSL VPN users may repeatedly receive the following prompt during connection or reconnection:

The site [VPN URL] is attempting to inspect your system configuration. This site is not on your Trusted Sites list.

The prompt may continue to appear after selecting Add this site to your Trusted Sites list, and always allow inspection from this site.

Environment

  • BIG-IP APM
  • Full Tunnel SSL VPN
  • Windows 10 or Windows 11
  • Active Directory authentication and Group Policy
  • APM access policy with endpoint inspection agents, such as Windows Info and Windows Registry
  • Connectivity Profile option Add virtual server list to trusted sites enabled

Cause

The endpoint trusted-sites policy did not explicitly include every VPN hostname used during the endpoint-inspection process. In this environment, wildcard entries for the parent domain were insufficient.

The popup can also occur when the Trusted Sites security option Websites in less privileged web content zone can navigate into this zone is configured as Prompt.

Recommended Actions

  1. Identify every VPN hostname used by SSL VPN, including the hostname displayed in the popup.
  2. Add each VPN hostname explicitly to the applicable Active Directory Group Policy trusted-sites list.
    Example:

    VPN1.example.com

  3. Do not rely only on wildcard entries for the parent domain.
  4. Apply or refresh Group Policy on the affected Windows endpoints.
  5. Verify that the exact VPN hostname is present in the endpoint’s Trusted Sites configuration.
  6. In Internet Options, navigate to:

    Security Settings > Trusted Sites Zone

  7. Verify that Websites in less privileged web content zone can navigate into this zone is not configured as Prompt. Configure the setting according to the organization’s security requirements.
  8. Test the following operations:
    • Initial VPN connection
    • VPN disconnect and reconnect
    • SSL VPN connection after workstation restart
    • Connections from multiple affected Windows endpoints

Adding the actual VPN hostnames explicitly to the trusted-sites Group Policy prevented the popup during testing.

Additional Information

  • If the popup continues to appear:
    • Compare the hostname displayed in the popup with the hostname configured in Group Policy.
    • Confirm that Group Policy was applied successfully to the affected endpoint.
    • Check whether multiple VPN hostnames or aliases are used during endpoint inspection.
    • Test from a non-domain-joined Windows endpoint, if available, to determine whether the behavior is related to domain policy.
    • Confirm that endpoint security software or local policies are not preventing updates to the Trusted Sites configuration.
    • Collect a Client Troubleshooting Utility report and review the APM session log for the affected session.
    • Verify that endpoint inspection completes successfully and that the APM session is not failing during authentication or tunnel establishment.
