Description

  • When running an APM Access Report the "Logon" column contains a "<br/>" string next to the username

Environment

  • BIG-IP with APM provisioned
  • The logs in /var/log/apm contain several unique lines with string " Username " for a given APM session

Cause

To store session data for reporting, the BIG-IP parses log messages (/var/log/apm) and stores the result in an MYSQL database. For the "Logon" field in the Access Reports the BIG-IP looks at the log lines containing " Username ". It then adds the value that follows to the MYSQL database. If there are several lines like this with different values in the log for any given APM session, there will be several records in the MYSQL database. When the report is run it queries the MYSQL database and gets several records returned. The delimiter between the records is "<br/>".

Recommended Actions

This is expected behavior.
To avoid this, only populate the session variable "session.logon.last.username" once in the Access Policy (use modified session variable names in if needed, e.g. in different Logon Page VPE objects).
