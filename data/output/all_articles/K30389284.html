Topic

You should consider using these procedures when you want to perform one of the following actions:

  • Backing up your NGINX Controller system from the linked PostgreSQL database.
  • Restoring your NGINX Controller system from the previously generated backup files.

Description

The NGINX Controller uses the PostgreSQL database for storing configuration and analytics data. To back up and restore the NGINX Controller system, you use the PostgreSQL command line tool pg_dump to create PostgreSQL dump files and psql to import the files back to the database. To access the PostgreSQL database linked with the NGINX Controller system, you need the database credentials and the PostgreSQL database must be accessible from your system. This article describes how to back up and restore the database using the database user account naas, which is generated as part of prerequisites before installing the NGINX Controller.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the NGINX Controller command line.
  • You have access to the PostgreSQL database to which the NGINX Controller is connected.
  • The NGINX Controller host server PostgreSQL command line tools pg_dump and psql are available.

Procedures

  • Backing up the NGINX Controller database
  • Restoring the NGINX Controller database

Backing up the NGINX Controller database

To back up the PostgreSQL database linked with NGINX Controller data storage, you can create PostgreSQL dump files for the common, data, and system databases. To do so, perform the following procedure.

Note: For steps that require PostgreSQL database access, you may be prompted for a password for user account naas, depending on your PostgreSQL client authentication settings. For more information, refer to the PostgreSQL 9.5 pg_hba.conf documentation page. This link takes you to a resource outside of AskF5, and it is possible that the information may be removed without our knowledge.

Impact of procedure: Performing the following procedure involves stopping NGINX Controller, which temporarily interrupts the NGINX Controller services. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the NGINX Controller command line.
  2. To shut down NGINX Controller, enter the following command:

    cd /opt/nginx-controller && ./helper.sh controller stop

  3. Create a backup directory using the mkdir command. For example:

    mkdir /var/tmp/pg_backup_$(date +"%Y%m%d%H%M")

  4. To back up the PostgreSQL database, use the following command syntax:

    pg_dump -U naas -h <postgres_host> -E utf8 -d <database_name> -n public -f <backup_directory>/<database_name>.sql

    For example, the following commands create a backup file for locally configured PostgreSQL databases:

    pg_dump -U naas -h 127.0.0.1 -E utf8 -d common -n public -f /var/tmp/pg_backup_201912120808/common.sql
    pg_dump -U naas -h 127.0.0.1 -E utf8 -d data -n public -f /var/tmp/pg_backup_201912120808/data.sql
    pg_dump -U naas -h 127.0.0.1 -E utf8 -d system -n public -f /var/tmp/pg_backup_201912120808/system.sql

  5. To start NGINX Controller after you back up all three databases, enter the following command:

    cd /opt/nginx-controller && ./helper.sh controller start

Restoring the NGINX Controller database

To restore the PostgreSQL database linked with NGINX Controller data storage, you can rebuild and overwrite the common, data, and system databases from the previously generated backup files. To do so, perform the following procedure.

Note: For steps that require PostgreSQL database access, you may be prompted for a password for user account naas, depending on your PostgreSQL client authentication settings. For more information, refer to the PostgreSQL 9.5 pg_hba.conf documentation page. This link takes you to a resource outside of AskF5, and it is possible that the information may be removed without our knowledge.

Note: To restore the database without errors, make sure the PostgreSQL user naas has the Superuser permission during the restore process.

Impact of procedure: Performing the following procedure involves stopping NGINX Controller, which temporarily interrupts the NGINX Controller services. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the NGINX Controller command line.
  2. To shut down NGINX Controller, enter the following command:

    cd /opt/nginx-controller && ./helper.sh controller stop

  3. To rebuild the PostgreSQL database, use the following command syntax:

    psql -U naas -h <postgres_host> -c "drop database <database_name>"
    psql -U naas -h <postgres_host> -c "create database <database_name>"

    For example, to rebuild the common database for the local PostgreSQL instance, enter the following commands:

    psql -U naas -h 127.0.0.1 -c "drop database common"
    psql -U naas -h 127.0.0.1 -c "create database common"

  4. To restore the PostgreSQL database, use the following command syntax:

    psql -U naas -h <postgres_host> -d <database_name> < <backup_directory>/<database_name>.sql

    For example, to restore the common database from the previously generated backup file on the local PostgreSQL instance, enter the following command:

    psql -U naas -h 127.0.0.1 -d common < /var/tmp/pg_backup_201912120808/common.sql

  5. Repeat steps 3 and 4 until all three PostgreSQL databases (common, data, and system) are restored.
  6. To start NGINX Controller after you back up all three databases, enter the following command:

    cd /opt/nginx-controller && ./helper.sh controller start

Note: If the PostgreSQL database is restored on a newly deployed NGINX Controller system, you must reset the Admin account password. For more information, refer to K06962163: Resetting the Admin account password on the NGINX Controller system.
