K000133184: After an upgrade to 17.1.0 ASM restarts - Core Files may be written

Type
Support Solution
Published
2023-03-31
Updated
2023-05-05
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.X, 17.1.0
Source
https://my.f5.com/manage/s/article/K000133184

Description

  • After upgrade to 17.1.0 from supported version BD may core.

Environment

  • Upgraded to 17.1.0 from prior version.

Cause

When upgrading to 17.1.0 a ASM/Adv WAF configuration table is not populated during upgrade. This may trigger a core of the BD process.

 Recommended Actions

  1. Each security policy needs to be "Applied"
  • This can be done manually by altering the policy - change the description for example, save and apply.
  • This can be done using the following command per policy:
perl /usr/share/ts/bin/set_active.pl -p <policy_id> --noignore_if_policy_unmodified
  • This can be done for all policies on the BIG-IP by looping through each policy:
mysql_cmd="mysql -Ns -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw)"; ${mysql_cmd} -e 'select id, name, policy_name_crc from PLC.PL_POLICIES where policy_type = 1;' | while read -r id name policy_name_crc; do echo -e "\nPre policy save Enforcer Settings row count:\t$(${mysql_cmd} -e 'select count(*) from DCC.ACCOUNT_ENFORCER_SETTINGS where policy_name_crc like "'${policy_name_crc}'";')"; echo -e "Running apply for policy - ID: ${id}\tName: ${name}\tCRC: ${policy_name_crc}"; /usr/share/ts/bin/set_active.pl -p ${id} --noignore_if_policy_unmodified; echo -e "Post policy save Enforcer Settings row count:\t$(${mysql_cmd} -e 'select count(*) from DCC.ACCOUNT_ENFORCER_SETTINGS where policy_name_crc like "'${policy_name_crc}'";')\n"; done
 

NOTE:

If this fails to update all the policies, Bug 1284081 might be preventing it. There is a current EHF for ID1284081.
