Known Issue

This is the result of a known issue. If a UDP monitor is associated with a BIG-IP GTM object, such as a virtual server or host server that either does not exist, or does not respond to the monitor request, the big3d process continues to probe the device, and does not properly time out the monitor. This behavior causes the active monitor queue to fill up with the UDP monitors. When this issue occurs, all other monitors are placed in the pending queue and are never sent. As a result, all monitors will fail.

F5 Product Development tracked this issue as CR87859 and it was fixed in BIG-IP GTM 9.4.6. For information about upgrading, refer to the BIG-IP GTM Release Notes.

Workaround

You can work around this issue by disabling the BIG-IP GTM object(s) that do not exist or are unresponsive. Once the unresponsive objects are disabled, restart the big3d process by typing the following command:

bigstart restart big3d
