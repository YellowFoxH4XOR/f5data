Known Issue

This is the result of a known issue. If a Windows Operating System client attempts to connect to a Windows Terminal Server (Remote Desktop) favorite, the connection may fail with an error message that appears similar to the following example where <FavoriteName> is the name of the Windows Terminal Server favorite:

Couldn't connect to terminal server <FavoriteName>
 
This issue occurs when all of the following conditions are met:
 
  • The user connects to the FirePass controller using Microsoft Internet Explorer (IE)

    Important: If the same error message occurs when using an alternate browser, such as Firefox, the user is not affected by the issue described in this Solution.
     
  • Protected mode is enabled in IE
  • The URL of the FirePass controller has not been added to the IE Trusted Sites zone
  • The back-end Windows terminal (Remote Desktop) server uses Per Device licensing mode
 
Protected Mode is a security feature that is enabled by default in IE7 and IE8.

Note: For more information about Protected Mode, refer to the following location:
 
http://www.microsoft.com/windows/windows-vista/features/IE7-protected-mode.aspx

This link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.
 
While this issue has been most frequently seen on Windows Vista clients, other Windows Operating Systems, such as Windows 2003 and Windows 7, are also affected.
F5 Product Development is tracking this issue as ID 279429 (formerly CR75630).
 
Workaround
 
A FirePass administrator can work around this issue by configuring an application tunnel for access to the Windows terminal server.

Note: For more information, refer to K8640: Configuring Windows Terminal Server favorites.
 
Users can work around this issue by performing one of the following four actions:
  • Add the URL of the FirePass controller to the IE Trusted Sites zone.

    Note: For information about configuring the Trusted Sites zone, refer to the following location: 

    http://technet.microsoft.com/en-us/library/dd883248%28WS.10%29.aspx#addinternetsites.

    This link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

    Important: By default, Protected Mode is disabled for the Trusted Sites zone. If Protected Mode is enabled for this zone, perform one of the following alternate workarounds listed below.
     
  • Connect to the FirePass controller using an alternate browser, such as Firefox.
  • If the user has administrator privileges on the Windows Vista system, the user can right-click on Internet Explorer and select the Run as administrator option when launching Internet Explorer. This setting bypasses Protected Mode.
  • If the user does not have administrator privileges on the Windows Vista system, the user can disable Protected Mode in Internet Explorer. F5 Networks does not recommend this workaround, as it may decrease the security of the Window Vista system.

    Note: For information about disabling Protected Mode, refer to the Microsoft IE documentation.
