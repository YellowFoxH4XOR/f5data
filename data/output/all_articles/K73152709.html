Description

Facing an issue while uploading my renewed SSL certificate to BIG-IP resulting in the inability to assign HTTP2 profile to virtual server. For example:

01070734:3: Configuration error: In Virtual Server (/Common/https_vs) an http2 profile with enforce-tls-requirements enabled is incompatible with clientssl profile '/Common/client_profile'; renegotiation must be disabled.

Environment

  • HTTP/2

Cause

The observed behavior is expected. HTTP/2 is incompatible with SSL renegotiation. For more information, refer to RFC9113.

In response to several attacks based on SSL renegotiation, the HTTP/2 specification requires that SSL renegotiation be disabled, but the default clientssl profile allows renegotiation. The implication is that the default HTTP/2 settings and the default clientssl settings are incompatible.

Recommended Actions

In order to use HTTP/2, the administrator must change the default settings of either the clientssl profile or the HTTP/2 profile.

For cases where the administrator wants to remain compliant with HTTP/2 requirements and does not need renegotiation, disable renegotiation in the clientssl profile associated with the virtual server. To do so, use one of the following procedures:

  • Disable renegotiation in the clientssl profile using the Configuration utility
  • Disable renegotiation in the clientssl profile using tmsh

Disable renegotiation in the clientssl profile using the Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select your clientssl profile.
  4. For Configuration, select Advanced.
  5. For the Configuration section, select the Custom checkbox.
  6. For Renegotiation, uncheck the Enabled box.
  7. Select Update.

Disable renegotiation in the clientssl profile using tmsh

  1. Log in to the TMOS Shell (tmsh).
  2. Disable renegotiation using the following command syntax:

    modify /ltm profile client-ssl <clientssl profile> renegotiation disabled

    For example, to disable renegotiation for a clientssl profile named myClientSSL, enter the following command:

    modify /ltm profile client-ssl myClientSSL renegotiation disabled

  3. Confirm renegotiation is disabled using the following command syntax:

    list /ltm profile client-ssl <clientssl profile> renegotiation

    For example, to confirm the status for a profile named myClientSSL, enter the following command:

    list /ltm profile client-ssl myClientSSL renegotiation

    The output should appear similar to the following example:

    ltm profile client-ssl myClientSSL {
        renegotiation disabled
    }

  4. Save the configuration by entering the following command:

    save /sys config

Additional Information

Per RFC9113:

A deployment of HTTP/2 over TLS 1.2 MUST disable renegotiation. An endpoint MUST treat a TLS renegotiation as a connection error (Section 5.4.1) of type PROTOCOL_ERROR. Note that disabling renegotiation can result in long-lived connections becoming unusable due to limits on the number of messages the underlying cipher suite can encipher.

An endpoint MAY use renegotiation to provide confidentiality protection for client credentials offered in the handshake, but any renegotiation MUST occur prior to sending the connection preface. A server SHOULD request a client certificate if it sees a renegotiation request immediately after establishing a connection.
