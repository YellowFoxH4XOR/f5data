Description

Warnings generated during configuration reload, ie in the output from "tmsh load sys config".

Environment

  • BIG-IP
  • Traffic Matching Criteria used in Virtual Server configuration

Cause

When the TMC (Traffic Matching Criteria) does not specify the source or destination, the source or destination is set on the Virtual Server. Since this source or destination is used to match traffic it is included in the TMC validation. It appears that 0.0.0.0 is akin to not setting a source or destination so it seems that this will trigger the warning message. 0.0.0.0 is an any4 address in accordance with what the message is saying anyway:

Jan  8 17:07:21 xxxx warning mcpd[yyyy]: 01071859:4: Warning generated : Traffic Matching Criteria's inline source address has been set to any4 from any6 to match inline destination address' address family.

This message should be generated for each TMC attached to a Virtual Server and logged for every 0.0.0.0 source and destination.

Related to Bug ID 753712: Incorrect warning: Traffic Matching Criteria's inline source address has been set to any4 from any6 to match inline destination address' address family.
Recommended Actions

These warnings and benign and can be safely ignored.

Additional Information

There is no way to suppress these warnings in the CLI. They are logged in both console (CLI) and log files. Log files are handled by local syslog and they are easily suppressible however console logs are handled internally by the system thus are impossible to change.
