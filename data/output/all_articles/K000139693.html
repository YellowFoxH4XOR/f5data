Source
https://my.f5.com/manage/s/article/K000139693

Description

- After successfully installing the Safenet Luna client software, your BIG-IP system reports the message below in /var/log/secure

notice FIPS Integrity Check: FIPS is enable
crit root[24141]: BIG-IP Integrity Check: [ FAIL ] -- THE SYSTEM WILL HALT UPON REBOOT, CONTACT F5 NETWORKS FOR TECHNICAL SUPPORT

- Running the sys-eicheck utility, reports critical file(s) modified, such as below:
[Active:Standalone] ~ # /usr/libexec/sys-eicheck.py
BIG-IP Integrity Check Report
- Critical file modifications result in failure.
=======================================================
0 critical file(s) missing
=======================================================
/usr/safenet/lunaclient/bin/ckdemo
/usr/safenet/lunaclient/lib/libcklog2.so
/usr/safenet/lunaclient/lib/libSoftToken.so
...
20 critical file(s) modified
=======================================================
Integrity Check Result: [ FAIL ]
Contact F5 Networks Technical Support. 

Environment

BIG-IP LTM
FIPS 140 add-on licence
Safenet Luna client installation

Cause

The issue is caused by a known ID tracked as ID1307793

Note: Details about ID1307793 are not available on F5 public Resources at the time of writing this article.

Recommended Actions

Apply one of the workarounds below:

- Workaround 1:

After a successful Luna client software installation, install your current BIG-IP software image on a different volume. For example, if the issue happens while running v16.1.3.2 on HD1.3, do another installation of v16.1.3.2 on HD1.4 and boot into the new volume ( HD1.4).

 

- Workaround 2:

Remove the luna RPM packages from the DB without removing/uninstalling the binary files

Below is an example of how luna RPM packages are removed from the DB.
