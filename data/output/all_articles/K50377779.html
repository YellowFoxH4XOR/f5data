Issue

Error Message

err mcpd[<PID>]: 01071bd1:3: Inbound CMI connection from IP (<IP_address>) denied because it came from VLAN (<VLAN_ID>), not from expected VLAN (<VLAN_ID>).

In this error message, note the following:

  • <PID> is the process ID for the mcpd process.
  • <IP_address> is the source IP address of the inbound centralized management infrastructure (CMI) connection.
  • <VALN_ID> is the name of the VLAN.

For example:

err mcpd[8484]: 01071bd1:3: Inbound CMI connection from IP (10.10.10.84) denied because it came from VLAN (lo), not from expected VLAN (HA).

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when the following condition is met:

  • The mcpd process detects a CMI message that is not from the configured VLAN where the ConfigSync IP is located.

Impact

The CMI traffic is denied by the BIG-IP system due to the unsecured transaction. The device group fails to sync with peer devices.

Recommended Actions

The error can occur when multiple local self IPs are configured within the same VLAN and are used for high availability (HA) connections. To work around this issue, assign only one IP address in the VLAN to handle HA communications for ConfigSync, Network Failover, and Mirroring. 
Another possible reason is, in the HA pair, the ConfigSync IP address are in the same subnet and same VLAN, but there are special route entry (generated by zebos) on the peer, cause the peer create the connection via different VLAN, and access another self IP on the BIG-IP. One solution is, avoid the overlap route entry, the subnet for ConfigSync should not override by other route entry.
