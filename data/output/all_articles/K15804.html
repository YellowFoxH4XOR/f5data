Known Issue

Adding new pool members to an already existing pool may cause the new pool members to receive all new connections.

This issue occurs when all of the following conditions are met:

  • A pool is configured to use either Predictive or Observed load balancing modes.
  • The other pool members in the pool are currently handling traffic.
  • The new pool members do not receive a request before the Slow Ramp Time setting for the pool expires.

For the Predictive and Observed load balancing modes, the BIG-IP system dynamically assigns a load balancing value that determines how subsequent new connection requests will be distributed. The Slow Ramp Time setting in the pool prevents previously unavailable pool members from becoming overwhelmed with connection requests when they first become available, by slowly increasing the number of connection requests that are load balanced to the new pool members. When new pool members are added to a pool, the BIG-IP system assigns a load balancing value of zero to those members. If the new pool members receive a connection while in the slow ramp mode, the load balancing value for those pool members will catch up to the rest of the pool members, allowing connection requests to be evenly distributed across all pool members.

However, if the Slow Ramp Time setting expires before the new pool members receive a connection request, the load balancing value for the new members will not catch up to the rest of the pool members, causing the new pool members to receive all new connection requests until catching up to the previously existing pool members.

Impact

Connection requests may overload newly added pool members.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H488435 on the Diagnostics > Identified > Medium screen.
  • Traffic statistics indicate uneven load balancing, skewing toward the newly added pool members.

Workaround

To work around this issue, you can add new pool members in a Forced offline state using the Traffic Management Shell (tmsh). For pool members that have already been added to a pool and are receiving all of the connections, you can toggle the member state from enabled to Disabled and back to Enabled. To do so, perform one the following procedures:

Adding a new pool member in a Forced offline state

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Note: You must perform this procedure from the tmsh utility.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To add the desired pool member in a Forced offline state, use the following command syntax:

    modify /ltm pool <pool name> members add { <ip address:port> { state user-down } }

    For example, to add a pool member 10.10.10.10:80 to a pool named web_pool, you would type the following command:

    modify /ltm pool web_pool members add { 10.10.10.10:80 { state user-down } }

  3. To enable the new pool member, use the following command syntax:

    modify /ltm pool <pool name> members modify { <ip address:port> { state user-up } }

    For example, to enable pool member 10.10.10.10:80 in a pool named web_pool, you would type the following command:

    modify /ltm pool web_pool members modify { 10.10.10.10:80 { state user-up } }

  4. Save the change by typing the following command:

    save /sys config

Toggling a pool member from Enabled to Disabled and back to Enabled

Impact of workaround: Disabling a pool member will continue to allow persistent or active connections. However, no new connections will be allowed until the pool member is reenabled.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Select the pool with the newly added members.
  4. Select the Members tab at the top of the page.
  5. Select the box to the left of the newly added pool member(s).
  6. Click Disable.
  7. Once again, select the box to the left of the newly added pool member(s).
  8. Click Enable.
