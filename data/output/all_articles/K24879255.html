Description

SSL sessions are failing, pkcs11d cores, pkcs11d and tmm logs such as the following:

info pkcs11d: pkcs11d loading key handles
info pkcs11d: pkcs11d invalidating key handles
crit tmm2[12818]: 01260010:2: FIPS acceleration device failure: fips_poll_completed_reqs: req: 118336 status: 0x1 : Cancel

err pkcs11d[8717]: Nethsm: pkcs1v15_decrypt C_Decrypt error 0x00000020, session[2] key[2000512].
err pkcs11d[8717]: Nethsm: pkcs1v15_decrypt C_Decrypt error 0x00000020, session[26] key[2000260].
err pkcs11d[8717]: Nethsm: pkcs1v15_decrypt C_Decrypt error 0x00000020, session[10] key[2000260].
 

Environment

You must meet the following prerequisites to use this procedure:

  • BIG-IP system using a HSM device.
  • Administrative access to the HSM device.
  • Administrative access to the TMOS shell (tmsh).


Cause
Unknown at time of publication.  Additional data and research will be needed.

Recommended Actions

  1. Initial Data Gathering for F5 Support:

    1. Determine the Thales Hardserver version and determine its compatibility with the BIG-IP version.
      Review Interoperability Matrix for BIG-IP TMOS with nCipher Clients and HSM to determine if an unsupported or untested Thales Client/Hardserver version are in use.

    2. Examine the nethsm-info.sh from QKVIEW or run the nethsm-info.sh from command line. Take note of the "version" parameter. For example:
      Server:
      enquiry reply flags  none
      enquiry reply level  Six
      serial number        <omitted>
      mode                 operational
      version              2.92.1

    3. Gather the Thales hardserver logs to determine the state of connectivity between BIG-IP and the Thales HSM.
      Thales Hardserver logs are located in:
      /shared/nfast/log/hardserver.log

  2. Contact F5 Support with the aforementioned information for further troubleshooting:
    K2633: Instructions for submitting a support case to F5
