K000139052: SSLO "Existing Application" topology option not available when an SSLO main license with add-on LTM license is applied

Type
Support Solution
Published
2024-03-27
Updated
2024-03-27
Applies to
  • F5 App Protect
  • F5 SSL Orchestrator
Source
https://my.f5.com/manage/s/article/K000139052

Description

When an SSLO license is used as a main license on a Big-IP, the "Existing Application" topology option is not available to the administrator. This remains true even if an LTM license is added as an "add-on" license on the same box.

 

Environment

Big-IP with an SSLO license as its main license.

 

Cause

This is a side effect of the logic used by the SSLO Guided Config page - it checks to see if the main license is SSLO or LTM, and if the main license is LTM, it allows the "Existing Application" topology option in the SSLO GUI admin page, however if the main license is SSLO (ie. doesn't have LTM), it removes the "Existing Application" topology option, since that is only designed to create a policy that can be used on an LTM VS.

The only difference between an existing application topology and an inbound application topology is that the latter creates a VS and pool, and auto-applies server SSL settings. 

 

Recommended Actions

As a workaround, an inbound application topology can be created, and the corresponding VS can be changed to suit your needs. Another alternative would be to define a "dummy" inbound application mode topology, then just use the resulting SSLO policies in other LTM Virtual Servers.

Unfortunately the only way to use the "existing applications" feature in Classic Big-IP is to use an SSLO add-on license, as that is the only way to actually enable that feature.

 

Additional Information

There are no plans to change this behaviour on Classic Big-IP at present, and this issue is not applicable to Big-IP Next because there is no concept of "topologies" there - in Big-IP Next an SSLO policy is added to a type of application. This means there's no differentiating concept of inbound application or existing application, so this becomes a non-issue on Big-IP Next.
