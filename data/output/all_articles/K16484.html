Known Issue

The trunk member status may be incorrect when a Virtual Clustered Multiprocessing (vCMP) host and guest have different primary blades.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION chassis with multiple blades installed.
  • You have provisioned vCMP and deployed at least one guest.
  • The vCMP host has a different primary blade than the vCMP guest.
  • You perform a licensing operation on the vCMP host.

Impact

vCMP guests may erroneously display the trunk member status as down.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When viewing the trunk status on vCMP guests, you notice that the trunk status is down.

    For example:

    # tmsh show net trunk

    ----------------------------------------------------------------
    Net::Trunk
    Name Status Bandw Bits Bits Errs Errs Drops Drops Colli
    Mbps In Out In Out In Out sions
    ----------------------------------------------------------------
    t3 down 0 0 0 0 0 0 0 0

Workaround

To work around this issue, you can ensure that the vCMP host and vCMP guest have the same primary blades. To do so, perform the following procedure:

Impact of workaround: This procedure may briefly affect your vCMP guest system's ability to process traffic, and should only be performed during a scheduled maintenance window.

  1. Log in to the Configuration utility of the vCMP host.
  2. Navigate to System > Cluster > Properties.
  3. Under the Cluster Master column, take note of the blade number with Yes indicated.
  4. Log in to the Configuration utility of the vCMP guest.
  5. Navigate to System > Cluster > Properties.
  6. Select the check boxes for all blades, except the blade number that you noted in step 3.
  7. Click Disable/Yield.
  8. Select the check boxes for blades which are now indicated as Disabled (black diamond).
  9. Click Enable.
