Known Issue

This is the result of a known issue. The CACHE iRule commands make use of the RAM Cache feature on the BIG-IP system. A memory leak can result when certain HTTP and CACHE iRule commands are used together in the same iRule. For example, the memory leak occurs when an iRule invokes the HTTP::redirect or HTTP::respond iRule commands along with any of the following CACHE iRule commands for the same request:

  • CACHE::uri
  • CACHE::useragent
  • CACHE::accept-encoding
  • CACHE::userkey

Since cached data is stored in the RAM Cache in xfrag, when an HTTP redirect occurs, the RAM Cache never sees the original request and the BIG-IP system does not free the xfrag from memory.

F5 Product Development tracked this issue as CR88139 and it was fixed in BIG-IP LTM 9.4.4 and 9.6.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF2 issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch, and in Hotfix-BIG-IP-9.4.3-HF2 issued for BIG-IP 9.4.3, for the BIG-IP 9.4 software branch. You may download these hotfixes or later versions of these hotfixes from the F5 Downloads site.
