K5852: BIG-IP may drop connections through a delayed binding virtual server if the first data packet from the node does not acknowledge all of the data sent by BIG-IP

Known Issue

BIG-IP does not buffer node side connections when the connection does not use insert-mode cookie persistence or SSL session ID persistence.

If BIG-IP splits a non-buffered request into multiple packets and the node acknowledges only the first packet, BIG-IP will drop the connection.

This problem is rare and is only likely to occur under all of the following circumstances:

  • A virtual server receives a small POST request from the client.
  • The client does not request HTTP 100 (continue) for the POST.
  • The virtual server is configured to perform header insert.
  • After inserting the header, BIG-IP splits the request into two packets.
  • The node responds with an HTTP 100 (continue) after the first data packet, and acknowledges only the first packet.

At this point, BIG-IP drops the connection.

F5 Networks Product Development tracked this issue as CR52661 and CR52705, and it was fixed in BIG-IP version 4.5.14. For information about upgrading, refer to the BIG-IP Release Notes.
