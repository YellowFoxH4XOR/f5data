Description

  • You wish to configure multiple upstreams, each with own application servers (block IPs).
  • At time of increased HTTP response error/code like 5xx, you wish to use"if" directive, to forward a request to a secondary upstream. 

Environment

  • NGINX Plus
  • "if" Directive
  • upstream

Cause

  • Each HTTP request is processed by NGINX through a pre-defined sequence of phases.
  • That is, an HTTP request, when handled by NGINX, passes through a sequence of phases.
  • In each phase a distinct type of processing is performed on the request.

Recommended Actions

  • Using the "if" directive, NGINX does not support switching traffic to a secondary upstream block
  • Use the proxy_next_upstream directive to handle retries and forward requests to alternate upstreams
  • Refer to official documentation for correct usage directive Proxy_next_upstream
  • Avoid using the "if" directive for error handling or upstream switching in NGINX configuration.

Additional Information

  • The "if" directive as part of ngx_http_rewrite_module comes right at the start of request processing.
  • The function of "if" directive is limited to the rewrite phase and cannot be used for error handling or dynamic upstream selection after a response has been generated.
  • Hence, "if" directive cannot control retries and there isn't a mechanism in NGINX to rewind and restart the request/response phase
