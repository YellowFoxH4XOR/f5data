Description

Customer can see offline status of each auto-populated pool member in  BIG-IP Configuration utility(GUI) and then customer can see it with the error message code (01070639:5:) in the /var/log/ltm as well.

 

show /ltm pool members

 

 --------------------------------------------------------------

 | Ltm::Pool Member: Test123.FQDN.Name.CaseSensitive.amazonaws.com

 --------------------------------------------------------------

 | Status

 |  Availability  : offline

 |  State     : enabled

 |  Reason     : The DNS server(s) are unavailable

 |  Monitor Status : fqdn-down

 |  Session Status : enabled

 |  Pool Name   : Pool-Test123

 |  IP Address   : ::

 

 

/var/log/ltm

 

notice mcpd[<PID>]: 01070639:5: Pool /<partition>/<name> member /<partition>/<name>:<port> session status <status>

 

 

Environment

BIG-IP LTM 16.1.5

Cause

. FQDN Pool Member name is Case-Sensitive

Recommended Actions

Customer resolved the FQDN issue through correcting FQDN Pool Member name into same case letter because there is upper case letter in FQDN name in F5 Pool configuration even though the referenced FQDN in Windows DNS is lower case letter.

 

For Example)

a) F5 Pool Member FQDN : Test123.FQDN.Name.CaseSensitive.amazonaws.com

b) Windows DNS FQDN : test123.fqdn.name.casesensitive.amazonaws.com

 

 

Customer has followed up the Recommended Actions as stated in K50130343 in order to troubleshoot the FQDN issue with the debug log level in /var/log/dynconfd.log because there was no any specific error message in the /var/log/dynconfd.log, yet that both "Response FQDN" and "request FQDN" are not matched in the debug log message as we can double-check it in the 'dig' command tool too.
