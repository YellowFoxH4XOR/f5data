Description

Upgrading to 13.1.3.6 may fail, because it creates a Server SSL profile(s) with an invalid cipher string
After an upgrade to BIG-IP 13.1.3.6 the configuration fails to load successfully and the status of the device is Disconnected. Access to the Configuration utility only functions for the administrator account.  

Log messages similar to the following are logged to /var/log/ltm:
err mcpd[9126]: 01070312:3: Invalid keyword 'kedh' in ciphers list for profile /<partition>/<serverssl profile name>
err tmsh[12241]: 01420006:3: Loading configuration process failed.

Note: You may also notice similar log messages for other partitions (when configured).

Environment

  • BIG-IP
  • Upgrade to BIG-IP 13.1.3.6
  • SSL Server Profiles

Cause

Bug ID 705730
During the upgrade process, the In-TMM monitoring feature, introduced in BIG-IP 13.1.0, converts the HTTPS monitor into a Server SSL profile, which uses stricter cipher string validation. If the HTTPS monitor from the previous version uses keywords that are incompatible with the Server SSL profile format, such as kEDH, which is included in the default cipher string, a validation error is generated when loading the configuration.

Recommended Actions

Upgrade to a fixed version listed in Bug ID 705730.

The actions or steps required to address the topic covered in the description.

  1. You can review the following article in order to follow the Workaround Section: K82327396: Upgrading to BIG-IP 13.1.0 or later creates a Server SSL profile with an invalid cipher string
     
  2. There may be an instance where you probably fixed the kEDH cipher in the configuration file, but this only resides in the /Common partition, and the Error will continue to show up, if there are other monitors applied to the bigip.conf files per partition, so the next workaround can help you determine if this is true: 
    Note: This applies only if you have fixed the issue in the bigip.conf file for the /common partition and the error keeps showing up for monitors located in alternate partitions (when configured).
     
  3. Run the following script:
    for i in `find /config -name bigip.conf |grep -v diffVersions|grep -v \.bak|grep -v bigpipe`; do sed -i.K35149319 -s 's/+kEDH/+EDH/g' $i ; done
     
  4. To verify what changes have been made, run:
    for i in `find /config -name bigip.conf |grep -v diffVersions|grep -v \.bak|grep -v bigpipe`; do echo $i ; sdiff -s $i $i.K35149319 ; done

    You may see something similar to the following:
    /config/bigip.conf
        cipherlist DEFAULT:+SHA:+3DES:+EDH                        |     cipherlist DEFAULT:+SHA:+3DES:+kEDH
    /config/partitions/TEST000/bigip.conf
        cipherlist DEFAULT:+SHA:+3DES:+EDH                        |     cipherlist DEFAULT:+SHA:+3DES:+kEDH
     
  5. You can load the configuration by running the following:
    tmsh load /sys config
     
  6. After you load  the configuration, you will most likely notice no issues on the CLI, but when you access the GUI, you may notice the following output on your banner:

    This device is not operational because the loaded configuration contained errors or unlicensed objects. Please adjust the configuration and/or the license, and re-license the device.
     
  7. If the previous banner is present, you will need to run the workaround contained on the following article: K13223635: Configuration not loading with banner error message "This device is not operational because the loaded configuration contained errors or unlicensed objects. Please adjust the configuration and/or the license, and re-license the device."
     
  8. After a while the configuration should load successfully.
