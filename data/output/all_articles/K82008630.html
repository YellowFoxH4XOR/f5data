Description
F5 uses the OESIS SDK library from OPSWAT for performing endpoint inspection. These endpoint tests can be used to validate allowed access policy.

Releases since mid July 2026 have tracked the new Hardened Release policy as per https://my.f5.com/manage/s/article/K000162252 but EPSEC releases are not curretly bundled in the monthly releases.
Release build EPSEC 1765 was first bundled with BIG-IP 17.1.2.1, BIG-IP 16.1.5.2 and BIG-IP 15.1.6.10 in Jan 2025

This document has been updated to reflect that only BIG-IP versions v17.x will be supported from mid 2025, and references to pre OESIS v4 SDK have been removed (but may be still part of the installer).  Installer changes will happen from build 1826 onwards.
BIG-IP v21.0 is now supported from build v1947

Environment

BIG-IP APM with access policy that involves any of the following Client side policy Agents (Linux support has reduces features)

  • Antivirus or AntiMalware Check
  • Firewall Check
  • Patch Management check *
  • Disk Encryption **
  • File Sharing ***

* Note that Microsoft changes in Patch labelling have mostly made these ineffective, as monthly updates are no longer marked 'critical'
 ** For recent MacOS versions the disks are always encrypted at rest, so note this check does not reflect current Filevault status.
 *** This may detect unexpected applications as capable of sharing files

Cause
F5 Internal log messages and GUI may often only show the Windows SDK component build version, not the F5 release versions or MacOS/Linux SDK

Recommended Actions

  1. Use the table below to search for the component build number and match it to the F5 epsec.iso build number that contains that component.
  2. Important: Due to recent code signing and OESIS licence updates current APM Clients version may also be required for updates to the latest EPSEC updates.
  3. Note: Updating to the latest epsec version is always recommended (but may require APMClient or BIG-IP updates, always check the release notes before updating the epsec version)
    Updating should not have a negative impact on your system. However, the OESIS epsec software may be a critical component in client side endpoint security enforcement that determines if end users are able to login to services. F5 recommends performing this update in a staging environment first and fully testing before deployment. The update may also trigger a configuration synchronization (ConfigSync). For more information, refer to K48955220: Installing an OPSWAT Endpoint Security update on BIG-IP APM systems.

Note 1:  Builds published this year should have current OPSWAT licenses.
Build 1972 (January 2026) contains older Windows releases, due to licences changes.

The updated EPSEC components are automatically downloaded from the APM and installed by the individual clients as needed.

Windows Clients
The OESIS files should be saved at 'C:\windows\Downloaded Program Files\' or if there are insufficient permissions for updating that location then it can be in a subfolder of that directory named 'Conficts.N' where N is an incrementing number (see bug tracker ID 580813 for more background)

The current version can be shown with the PS commands:
PS C:\Users\admin> (get-item 'C:\windows\Downloaded Program Files\f5OesisInspectorCom.dll').VersionInfo | fl FileVersion
FileVersion : 7090, 2020, 0825, 0827

Or for an example if Conflict folders are involved:
PS C:\Users\admin> (get-item 'C:\windows\Downloaded Program Files\Conflict.*\f5OesisInspectorCom.dll').VersionInfo | fl FileVersionRaw
FileVersionRaw : 7090.2021.915.603

MacOS Clients
The OESIS files are saved at '/Library/F5Networks/Inspectors/'

The current version (date code in the middle) can be shown in the terminal with the command:
% cat /Library/F5Networks/Inspectors/OesisInspector.ver
7090.2025.128.1
