Known Issue

This is the result of a known issue. An import report does not contain information about missing pathnames as implied by SNMP trap messages sent during an import.

When performing an import, if a pathname is not found, the ARX system will log an SNMP trap message. The message will appear similar to the following example:

:SNMP TRAP: shareImportFail (650) shr 'NAMESPACE:/VOLUME:SHARE', name 'FILER', ip 'x.x.x.x', : Error: path name was not found. Check the import report for more details.

However, the import report will not contain the missing pathname.

F5 Product Development tracked this issue as ID 38388 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.

Note: You can identify the missing pathname by reviewing the associated Pathname not found during lookup [-340] error messages logged to the syslog file. For information about these messages, refer to K11663: Error Message: Error: 'Pathname not found during lookup [-340]'.
