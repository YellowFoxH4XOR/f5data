K000135544: Adding a GTM/DNS device back into a sync group causes sync direction to be changed

Type
Support Solution
Published
2023-07-20
Updated
2024-12-31
Applies to
  • BIG-IP
  • BIG-IP DNS: 15.1.0, 15.1.2, 15.1.1, 15.1.X, 16.1.X, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 16.1.5, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 15.1.10, 15.1.9, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3
Source
https://my.f5.com/manage/s/article/K000135544

Description

  • A BIG-IP GTM/DNS was removed from a sync group and then added back. After adding it back, this device may push the configuration to other devices instead of pulling the configuration from other devices.

  • This can potentially result in old configuration pushed to all devices.

  • "MCP Message queued for resend. 100 backlogged messages" logs are seen in /var/log/ltm

Environment

  • BIG-IP GTM/DNS provisioned.

  • The BIG-IP GTM/DNS device was removed from sync group renaming the sync group and then disabling "Synchronize".

  • The same BIG-IP GTM/DNS was added back to the sync group by changing the sync group name and then enabling "Synchronize".

  • Configuration was pulled from remove device using gtm_add command.

  • K14044: Removing and re-adding a BIG-IP DNS system to an existing BIG-IP DNS synchronization group - was followed properly.

Cause

This is due to a known bug ID1318625 that happens if the GTM/DNS configuration is quite large.

Recommended Actions

  • Follow the workaround specified in ID1318625 or below to avoid this known issue.

  • On the GTM/DNS device being removed, change the Sync Group name.

  • Disable sync by unchecking synchronize option.

  • Down the interfaces the DNS/GTM Self-IP is configure on (assuming 2.1 is the interface):

# tmsh modify net interface 2.1 disabled

  • Before bringing the device back into the sync group, check the Configuration Configuration Time, Commit ID and Configuration Commit Originator using command below

# tmsh show gtm iquery

  • Compare these values against the GTM/DNS being added.

  • If all DNS/GTMs have the same Configuration Configuration Time and Commit ID, just enable the interface.

  • If the GTM/DNS being re-added to the group, has older Configuration Configuration Time and Commit ID then manually copy over the file /config/bigip_gtm.conf from the other GTM/DNS device that made the latest commit ID (Commit Originator will show this).

  • While the GTM/DNS is still isolated, after copying/overwriting /config/bigip_gtm.conf run below command on the device being re-added:

# tmsh load sys config gtm-only

  • After GTM config is loaded re-enable the interfaces.

# tmsh modify net interface 2.1 enabled
