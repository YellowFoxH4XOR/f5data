Description

The use of very large bind (named) configurations may result in operations performed in ZoneRunner (DNS ›› Zones : ZoneRunner) timing out. You may observe some or all of the following symptoms:

 

  • A modal popup that says "Unable to contact BIG-IP device" - this will appear if the DNS operation take more than 30 seconds to complete. If you wait, the GUI may return to normal, with the operation complete, after a few minutes.
  • A timeout or "ERR_CONNECTION_REFUSED" state when attempting to browse to the BIG-IP management interface.
  • An error message "No such file or directory reading answer from named" in the GUI after the operation completes.

 

Environment

BIG-IP DNS, with a very large number of zones and/or records configured in bind (accessed via ZoneRunner)

 

Cause

The ZoneRunner utility was never intended for use with very large bind configurations, and is limited by the underlying performance of the bind utility, as well as other limitations specific to ZoneRunner and the processes it interacts with.

 

There is no specific definition or upper limit on how many records can be present, as it depends on the specific performance of a given BIG-IP device, as well as other factors such as how much other work the device is doing, but F5 has observed these sorts of symptoms intermittently appearing with over 500,000 resource records, and regularly appearing when more than 1 million resource records have been created.

 

The specific operations that cause these timeouts vary, but the issue has been observed with the following actions

  • Searching for matching resource records under DNS ›› Zones : ZoneRunner ›› Resource Record List
  • Immediately after updating (modifying) a resource record

 

Recommended Actions

F5 recommends that customers who experience these symptoms reduce the size of their DNS database to the point where the symptoms no longer appear. If this is not possible, then a partial workaround may be available, which is to go into DNS ›› Zones : ZoneRunner >> Zone List, select the view and zone that the record you want to modify exists in, then select Resource Records from there, the specific resource record that needs to be modified, make the changes, then click on Update. Note that after clicking Update, the GUI may become unresponsive for a period of time, but the update operational should still be successful, unless the configuration is extremely large.

 

Alternatively, consider hosting and managing large authoritative DNS zones on a separate third-party server, and use BIG-IP's DNS Express feature to accelerate the performance of that DNS server.

 

 

Additional Information

This issue differs from the one described in K34257075 (Bug ID933405) which has the same symptoms, but was caused by a separate bug. That issue has been fixed in all current BIG-IP releases.
