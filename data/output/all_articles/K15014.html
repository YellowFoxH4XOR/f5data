Known Issue

The Trust.ConfigUpdateDone db key may reset to false after you perform a version upgrade.

This issue occurs when all of the following conditions are met:

  • You upgrade a VIPRION system, in a device group, from BIG-IP 11.x to BIG-IP 11.4.1.
  • The user configuration set (UCS) configuration that rolls forward during the upgrade is created on a slot other than 0.

Impact

After the upgrade, the system continuously and unsuccessfully attempts to log in, using iControl, to peer members of the device group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H446742 on the Diagnostics > Identified > Medium screen.
  • The system continuously attempts to log in to the peer members through iControl, and fails each time.
  • The peer devices continuously (in intervals of 30 seconds) log messages similar to the following example to the /var/log/audit and /var/log/secure logs:

    slot1/VIPRION info httpd(pam_audit)[31039]: User=admin tty=(unknown) host=1.1.1.1 failed to login after 1 attempts (start="Wed Jan 01 01:01:07 2014" end="Wed Jan 01 01:01:09 2014").

    In this example, host is the affected system.

Workaround

To work around this issue, you can set the Trust.ConfigUpdateDone db key to true. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected system.
  2. Set the Trust.ConfigUpdateDone db key to true by typing the following command:

    tmsh modify sys db trust.configupdatedone value true
  3. Restart the device management daemon by typing the following command:

    bigstart restart devmgmtd
