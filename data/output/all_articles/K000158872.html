K000158872: In BIG-IP ASM/advanced WAF, iRules with ASM events are not working as expected.

Source

Description

You have an iRule designed to allow traffic from whitelisted IP addresses stored in a Data Group, even when a secuirty violation is triggered. However, requests originating from trusted IPs listed in the Data Group are still being blocked by the WAF, despite the iRule being configured to unblock them. This issue occurs only with a one virtual server, while the same iRule works as expected with others.

Example iRule to unblock requests with attack signature triggers:

when ASM_REQUEST_DONE { 
if { [matchclass [IP::client_addr] eq IP_LIST_DATAGROUP] and [ASM::violation names] contains "VIOLATION_ATTACK_SIGNATURE_DETECTED"} {
        log local0. "Request from Trusted IP [IP::client_addr] with violations, is unblocked"
            ASM::unblock
      }
}

Environment

  • BIG-IP ASM/advanced WAF
  • iRule with ASM event

Cause

Trigger ASM iRule Events Mode is disabled in the non-working security policy attached to the affected virtual server. When this setting is disabled, the system does not trigger ASM-related iRule events (such as ASM_REQUEST_DONE), which prevents the intended iRule logic from executing.

Recommended Actions

Check if Trigger ASM iRule Events Mode is enabled in your ASM security policy.

To enable:
1. Go to your relevant ASM Policy configuration: General Settings.
2. Find Trigger ASM iRule Events Mode.
3. Set it to Normal or Compatibility depends on the iRule event (Additional details regarding these two modes are provided in the Additional Information section).
4. Save and apply changes.

Addition Information

  • The system invokes the event ASM_REQUEST_DONE after the system completes processing each request, regardless of whether the request triggered violations. This gives you the opportunity, using iRules, to configure the system to perform actions after ASM handles requests whether they trigger, or do not trigger, violations. Using this event requires Trigger ASM iRule Events Mode set to Normal in the security policy.
  • The system invokes the event ASM_REQUEST_VIOLATION after the system completes processing each request that triggered a violation. This gives you the opportunity, using iRules, to configure the system to perform actions after ASM handles requests only that trigger violations. Triggering this event requires Trigger ASM iRule Events Mode set to Compatibility in the security policy.
