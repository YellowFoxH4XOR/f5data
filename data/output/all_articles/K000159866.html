Description

After implementing TCP/TLS-encrypted syslog load balancing on BIG-IP LTM following the procedure included in Load Balancing TCP TLS Encrypted Syslog Messages Technical Article on DevCentral, all syslog messages are being sent to the backend server over a single persistent connection instead of being distributed across multiple pool members. The Message Routing Framework (MRF) is not creating new connections for load balancing individual syslog messages as expected.

Environment

  • BIG-IP LTM 
  • Virtual server configured for TCP/TLS-encrypted syslog traffic
  • MRF (Message Routing Framework) configuration implemented per KB guidance

Cause

The root cause is incomplete implementation of the solution for load balancing TCP/TLS-encrypted syslog messages. The required SSL profiles were not applied.

Without a client SSL profile on the virtual server to decrypt incoming TLS traffic and a server SSL profile on the transport-config to re-encrypt outbound connections, BIG-IP cannot decrypt the syslog stream. MRF requires access to plaintext message content to parse individual syslog messages using the configured message terminator (newline). With encrypted traffic remaining opaque, MRF cannot perform per-message load balancing and instead treats each client connection as a single TCP flow pinned to one backend pool member for the connection's lifetime. This results in all syslog messages from a single client connection being sent to the same backend server rather than being distributed across multiple pool members.

Recommended Actions

- Apply a client SSL profile to the virtual server to enable BIG-IP to decrypt incoming TLS-encrypted syslog traffic from clients

- Apply a server SSL profile to the ltm message-routing generic transport-config to enable BIG-IP to re-encrypt outbound connections to backend syslog servers

- Verify the MRF protocol configuration includes the appropriate message-terminator (e.g., %0a for newline) to parse individual syslog messages

- Confirm router, peer, and pool configurations are properly defined as per the referenced Article
