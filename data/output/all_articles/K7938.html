K7938: Security scans report that logon page access is possible when using low-strength SSL ciphers

Topic

Security auditing tools may report that the FirePass controller allows SSL connections to the logon page (/my.logon.php3) with lower-strength security ciphers or protocols than are permitted by the FirePass controller's configuration.  

Note: Ciphers and protocols are configured in the SSL Cipher Security and SSL Protocol Versions sections on the Device Management: Security: User Access Security page.

This type of report is normally caused by one of the following two conditions:

  • The tool has accessed a warning page that the FirePass controller displays instead of the logon page. When a browser configured with a lower-strength setting than permitted by the FirePass configuration attempts to connect to the login page, the FirePass controller instead displays a warning message that appears similar to the following example:

      SSL ciphersuite EXP1024-RC4-SHA not permitted. Please see your system admin.

  • A report may indicate access is possible because the tool has accessed image files (either the default images or custom graphics) used for the logon page.These files are publicly accessible, and not under the restrictions for browser cipher strength that are placed on the actual login page. 

Pages accessed under either of these conditions do not provide an option to enter login credentials or other sensitive information, and therefore, do not present a risk, even when accessed with a low-strength cipher.

Starting in FirePass version 6.0.3, you are able to configure the FirePass device to reject SSL Sessions that do not meet minimum standards by enabling the Reject SSL connection when a non-compliant cipher is used by the client browser option located on the Device Management: Security: User Access Security page.

Note: For more information about vulnerabilities reports in the /my.logon.php3 path, refer to K9306: False positive vulnerability report for the /my.logon.php3 path.
