Known Issue

This is the result of a known issue. When creating a remote logging profile, the BIG-IP ASM Configuration utility allows you to enter an incorrect value for the Maximum Entry Length setting for the chosen syslog protocol. The Configuration utility also fails to specify the maximum TCP value for the Maximum Entry Length setting for RFC3195 syslog messages. The maximum TCP value for the Maximum Entry Length setting for RFC3195 syslog servers is 1024 bytes. The Configuration utility only specifies the maximum TCP and UDP protocol values for the RFC3164 syslog service.

For example, if you create a new TCP-RFC 3195 logging profile, and select the Length button for the Maximum Entry Length setting, the Configuration utility allows you to enter a value that exceeds the maximum length that the system allows for RFC3195 syslog messages. The Configuration utility screen also provides a note indicating incorrect maximum values for RFC3195 syslog messages.

Note: RFC3195 specifies both COOKED and RAW profiles for parsing syslog messages. The BIG-IP ASM system supports the RAW profile for parsing RFC3195 syslog messages, which limits the Maximum Entry Length setting to 1024 bytes for TCP. RFC3195 does not support the UDP protocol.

F5 Product Development tracked this issue as CR97328 and it was fixed in BIG-IP ASM 9.4.5. For information about upgrading, refer to the BIG-IP ASM Release Notes.
