Description

BIG-IP does not re-compress the HTTP request payload by default on the server-side connection in order to conserve CPU utilisation.
A HTTP Compression Profile and iRule is required if re-compression of the HTTP request payload is desired.
 

Environment

  • BIG-IP
  • HTTP request needs to be compressed before sending to server

Cause

This is the default behaviour of the BIG-IP.

Recommended Actions

A HTTP Compression Profile needs to be configured and added to the VIP, together with a custom iRule.
  1. Configure the HTTP Compression Profile and pay special attention to the following parameters:
    Selective Compression must be Enabled
    Content List must include the Content-Type for compression
    Minimum Content Length
  2. Example iRule to compress payload before sending the HTTP Request to server as per the HTTP Compression Profile configuration:

    when HTTP_REQUEST_SEND {
        COMPRESS::enable request
    }

Note: The HTTP Request must match the conditions configured in the HTTP Compression Profile, otherwise the payload will not be compressed.
