Description

BIG-IP sends ICMP Fragmentation needed message and you may see a connection timeout issue. The issue happens when the client sends a packet with the DF bit set, but the total length is larger than the MTU allowed from the next hop(serverside).
From the ICMP error message, you could find the MTU of the next hop. For example,

This is the packet client sent:
Internet Protocol Version 4, Src: x.x.x.x, Dst: x.x.x.x
    0100 .... = Version: 4
    .... 0101 = Header Length: 20 bytes (5)
    Differentiated Services Field: 0x00 (DSCP: CS0, ECN: Not-ECT)
    Total Length: 1500
    Identification: 0xd50b (54539)
    Flags: 0x40, Don't fragment

This is the response from BIG-IP, 'MTU of next hop: 1480' means serverside has an MTU value of 1480.

Internet Control Message Protocol
  Type: 3 (Destination unreachable)
  Code: 4 (Fragmentation needed)
  Checksum: 0x3a2a [correct]
  [Checksum Status: Good]
  Unused: 0000
  MTU of next hop: 1480
  Internet Protocol Version 4, Src: x.x.x.x, Dst: x.x.x.x
    0100 .... = Version: 4
    .... 0101 = Header Length: 20 bytes (5)
    Differentiated Services Field: 0x00 (DSCP: CS0, ECN: Not-ECT)
    Total Length: 1500

 

Environment

  • BIG-IP LTM
  • Virtual server type is standard
  • TCP profile with proxy-mss enabled
  • Client sends packets with DF bit set
  • MTU on client and server are different, BIG-IP system can obtain MTU information from route metrics. You can refer to K21077941: Overview of BIG-IP tmsh cmetrics component for more details.

Cause

With proxy mss enabled, BIG-IP will choose the smallest MTU between the clientside and serverside. For example, MTU on the clientside is 1500, and MTU on the serverside is 1480. If the client sends a packet of more than 1480 bytes (IP header + TCP header + TCP payload) with the DF bit set, BIG-IP will send an ICMP message to tell the client that it can't forward it to the serverside without fragmenting it.

Recommended Actions

You can choose one of the bellowing options to fix the issue:
  • Option#1: Allow processing of ICMP Frag Needed messages by the client or server, this option will introduce latency issues due to MTU renegotiation
  • Option#2: Modify the MSS in the VS to the lowest value among the client and server.
  • Option#3: Disable proxy-mss
For Option#2 or Option#3, you may refer to the articles K74767112: Overview of the TCP profile (15.x) and K14488: Working with profile for how to implement it.
