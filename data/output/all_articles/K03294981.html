K03294981: Unable to sync NTP time with a Windows NTP server

Type
Support Solution
Published
2020-04-10
Updated
2025-04-02
Applies to
  • BIG-IQ
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K03294981

Description

BIG-IP is configured to to sync with a Windows based NTP server but synchronization not working.

When running ntpq -np command, BIG-IP will show that it has not selected a current time source which is represented with a * on the left of the NTP IP address. Example is as below.

ntpq -np
     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
xxx.yyy.zzz.1       xxx.yyy.zzz.2  2 u   54   64  377    0.951  -153457  15

When a BIG-IP is successful at connecting and syncing its time with the NTP server, the ntpd -np output will have a * on the left of the NTP IP address as below:

ntpq -np
     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
*xxx.yyy.zzz.1      xxx.yyy.zzz.2   9 u   12   64    1    1.380   10.813   0.790
 

Environment
  • BIG-IP / BIG-IQ
  • Windows based NTP server

Cause

Windows' default LocalClockDispersion  value is set to too high for Linux based systems.
 

Recommended Actions

To work around this issue, you can include a maxdist value on the BIG-IP or decrease the LocalClockDispersion value on the Windows NTP server. To do so, perform one of the following procedures:

  • Include a maxdist value in the NTP configuration on the BIG-IP
  • Decrease the LocalClockDispersion value on the Windows NTP server

Include a maxdist value in the NTP configuration on the BIG-IP

  1. Log in to the BIG-IP system command line.
  2. To include a maxdist value in the NTP configuration, type the following command:

    tmsh modify sys ntp include 'tos maxdist 16'

    Note: The default ntp include configuration is 'none':
    tmsh list sys ntp include
     sys ntp {
       include none
     }

  3. You will need to force the BIG-IP to sync with the Windows NTP server. Before doing that, you will need to stop the ntpd process and start it again after the force sync. Assume the Windows NTP server IP is xxx.yyy.zzz.1, type the following command:
    bigstart stop ntpd
    ntpdate -s xxx.yyy.zzz.1
    bigstart start ntpd

    For an example, if your Windows NTP server is 10.10.10.10, the command would be as below.
    bigstart stop ntpd
    ntpdate -s 10.10.10.10
    bigstart start ntpd
     
  4. Leave it for sometime and check if the BIG-IP is syncing with the Windows NTP server with the following command:
    ntpq -np
Decrease the LocalClockDispersion value on the Windows NTP server
Important: Please consult with the Windows certified engineer before making changes to the Windows configuration. F5 will not take responsibility for any unexpected outcome. 
  1. Navigate to the following Windows registry key:
    SYSTEM\CurrentControlSet\Services\W32Time\Config\LocalClockDispersion
     
  2. Set the value to 0.
  3. Restart the W32time service on Windows with the following command:
    net stop w32time
    net start w32time
     
  4. Leave it for sometime and check if the BIG-IP is syncing with the Windows NTP server. Log in to the BIG-IP system command line and run the following command:
    ntpq -np

Additional Information

To confirm if your issue is related to Windows' LocalClockDispersion value, you can configure the BIG-IP to a working Linux NTP server or check the Root Dispersion value of the Windows NTP server. To do so, perform one of the following procedures:

  • Change the NTP configuration to a working Linux NTP server
  • Check the Root Dispersion value of the Windows NTP server


Change the NTP configuration to a working Linux NTP server
Note: Ensure that the Linux NTP server is working in your environment. You can confirm this with other devices in your environment which is using this same Linux NTP server.

  1. Login to the BIG-IP Configuration Utility.
  2. Navigate to System  ››  Configuration : Device : NTP.
  3. Remove the Windows NTP server IP by selecting it and click Delete.
  4. Enter the working Linux NTP server IP in the Address box and click Add.
  5. Click Update.
  6. Confirm this setup is working by loging to the BIG-IP command line and run the following command:
    ntpq -np
Check the Root Dispersion value of the Windows NTP server
  1. Login to the BIG-IP command line.
  2. Get the assid value of the Windows NTP server. Type the following command and the output would be as follows:
    ntpq -c as
    Example of the command output is as follows.
    ind assid status  conf reach auth condition  last_event cnt
    ===========================================================
      1 99999  9024   yes   yes  none    reject   reachable  2
     
  3. Take note that the condition is reject.
  4. Copy the assid. For this example, the assid is 99999.
  5. Type the following command to view Root Dispersion:
    ntpq -c "rv <assid>"
     
  6. For the example, the assid is 99999 so the command and output example would be as follows: 
    [root@LTM-01:Peer Time Out of Sync:In Sync] config # ntpq -c "rv 99999"

  7. Note the error code flash=400 peer_dist in the output. This error shows that distance threshold has exceeded.
