Known Issue

This is the result of a known issue. When a web page uses the Javascript method window.open with a UNC path, accessing the page using Portal Access Web Application Favorites will result in an error.  The FirePass controller's Web Application reverse proxy engine fails to rewrite the UNC path to point to the FirePass.

For example:

<HTML>
<BODY>
<INPUT TYPE="image" NAME="Test Me" onClick="window.open('\\\\192.168.1.1\\share\\image2.jpg'); return false;" src="image1.jpg" alt="" border=0/>
</BODY>
</HTML>

In the example web page code, the page displays image1.jpg, which the user can click to open the UNC that points to image2.jpg. The UNC \\\\192.168.1.1\\share\\image2.jpg would not be rewritten when passed from the server through the FirePass reverse proxy engine to the client. A properly rewritten link would be modified to point to the FirePass controller's name instead of the server name or IP address, so that the FirePass can proxy the request to the server.

If the FirePass controller is using the most recent version of the reverse proxy engine (version 6.0.2 engine; not in Compatibility Mode), when users attempt to access the UNC through a link passed to the window.open method, they will be redirected to a blank page with the following URL:

https://name.of.firepass.controller/vdesk/comf5aboutblank.html

If the FirePass controller is using one of the two older (legacy) reverse proxy engines (Compatibility Mode I or II in version 6.0.2; Compatibility Mode in version 5.4 through 6.0.1), when users attempt to access the UNC using a link employing the window.open method, they may receive an error page, a blank page, or a pop-up error message from their browser stating that the UNC is unavailable.

Compatibility Mode settings for legacy versions of the Web Application reverse proxy engine are found under Web Applications Global Settings, on the Global Settings tab of the Portal Access: Web Applications: Content Processing page.

F5 Product Development tracked this issue as CR92369 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Workaround

You can convert the UNC to an HTTP URL, which will allow the window.open method to work correctly through the Web Application reverse proxy.

If you cannot use the HTTP protocol to access your resource, you can convert the UNC to a file: URL. However, the following two potential issues apply:

  • Access to the file will fail if the credentials for the file server are not the same as those for the user's FirePass logon
  • The file cannot be opened in a new window
