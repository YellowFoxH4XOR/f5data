Topic

The high availability (HA) table is a shared memory segment that provides a way for the components to post information about the HA features they implement, and a way for other components to communicate with each other using the HA status feature name or key.

Description

The HA table is a troubleshooting utility that displays the status of certain components on the BIG-IP system, such as daemons or hardware components. The HA table is used by multiple daemons such as mcpd, sod, and tmm to communicate with each other. The HA table provides the following information:

  • Reports failure conditions.
  • Specifies the actions the system takes when a failure occurs.
  • Provides a way for daemons to communicate their status.

The expanded HA table columns are defined as follows:

  • Sys::HA Status Feature: Indicates the name of the HA table feature, such as daemon-heartbeat. Features can trigger a defined action such as failover.
  • Key: Indicates the name of the component that reports its status in the HA table. For example, a daemon.
  • Action: Indicates the action the system takes when the component experiences a failure.
  • Fail: Indicates the failure status of the specific component. The failure status can indicate something other than a fault condition. For example, the Ready for World feature reports a failed status for the Traffic Management Microkernel (TMM) during system initialization or when a chassis is disabled; the failed status is cleared when TMM is ready to process traffic.
  • Feature Enabled: Specifies whether the specific HA feature is currently enabled on the system.
  • Take Act: Specifies whether the system has taken the defined failover action.
  • Client Data: Indicates relevant client data retained by the feature such as the following examples:
    • The daemon heartbeat feature reports the number of heartbeats for each daemon.
    • The ha-group-score feature reports the HA group score for the traffic group.
    • The pool-mbr-down feature reports the minimum number of pool members that can be available before the system takes the failover action.
  • Proc: Specifies the daemon associated with the specific HA feature.
  • Timeout (sec): Specifies the number of seconds the system waits after detecting a failure before performing the action.

Displaying the expanded HA table

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

    show /sys ha-status all-properties

Interpreting the HA table output

The HA table allows you to monitor the HA status of various BIG-IP components and troubleshoot failover events when they occur. You can use the following examples to interpret the HA table output.

crypto-failsafe

The crypto-failsafe HA feature indicates the Secure Sockets Layer (SSL) card status for Cavium Nitrox, Cave Creek, or Coleto Creek SSL cards. The following output indicates that the SSL card (Cavium Nitrox) has locked up or failed on the BIG-IP system. In the following case, the failsafe action is None:

--------------------------------------------------------------------------------------------------------------------
Sys::HA Status      
Feature               Key           Action                        Fail  Feature  Take  Client  Proc          Timeout
                                                                        Enabled  Act   Data                  (sec)
--------------------------------------------------------------------------------------------------------------------
crypto-failsafe       cn-crypto-0  None                          yes    yes      yes   0       tmm            0
...

daemon-heartbeat

The daemon-heartbeat HA feature monitors daemon heartbeat signals and ensures that the daemons are running. The following output indicates that the bigd process incremented its heartbeat signal 6.2 million times, and then subsequently failed to increment the signal within the required timeout period of 150 seconds, causing the system to initiate the failsafe action of restart:

--------------------------------------------------------------------------------------------------------------------
Sys::HA Status      
Feature               Key           Action                        Fail  Feature  Take  Client  Proc          Timeout
                                                                        Enabled  Act   Data                  (sec)
--------------------------------------------------------------------------------------------------------------------
daemon-heartbeat      bigd         restart                        yes   yes      yes   6.2M    bigd          150
...

pool-mbr-down

The pool-mbr-down HA feature indicates that the Gateway failsafe feature is configured to monitor pool members and initiate a failsafe action when the number of available pool members drops below a defined minimum. The following output indicates that the system will initiate the failsafe action of failover when the minimum number of pool members for the pool, MyPool, drops below 1:

--------------------------------------------------------------------------------------------------------------------

proc-run

The proc-run HA feature is used by the system to ensure that key daemons such as tmm are running. The following output indicates that the system will initiate the failover action of go-offline-downlinks in the event that tmm fails to run for 2 seconds:
