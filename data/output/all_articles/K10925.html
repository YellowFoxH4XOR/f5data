Known Issue

Note: For more information about home directories synchronization on the VIPRION system, refer to K10924: Overview of home directories synchronization on the VIPRION system.

This is the result of a known issue. During a ConfigSync operation between VIPRION systems, new home directories are created only on the primary blade of the receiving system. For example, if a new user is added to a VIPRION system, and then that system's configuration is pushed to the peer VIPRION system, the home directory for the new user will be created only on the primary blade of the receiving system. As a result, a user will receive an error if they log in to a blade where their home directory does not exist.

Note: You may receive the aforementioned error even if you always connect to the primary blade of a VIPRION system. This is because a VIPRION system may elect any blade to become the primary blade. Therefore, you may be connecting to a primary blade that used to be a secondary blade, and that blade may not have created your home directory during a ConfigSync operation.

Depending on the type of terminal access a user was granted, they will receive one of the following error messages when they log in to a blade where their home directory does not exist:

  • Advanced shell

    Could not chdir to home directory /home/john: No such file or directory
    -bash-3.00#

    Note: It will be possible to use the shell after the above error is displayed. However, because the user has no home directory, they will be placed in the root (/) directory. Additionally, bash will not save their profile or history.

  • bigpipe shell

    Could not chdir to home directory /home/john: No such file or directory
    bp>

    Note: It will be possible to use the shell after the above error is displayed.

  • tmsh

    Could not chdir to home directory /home/john: No such file or directory
    exception: (Can't open command history file (/home/john/.tmsh-history-john), No such file or directory) (framework/CmdHistoryFile.cpp, line 88), exiting...

    Note: The SSH connection will close automatically after displaying the above error. Some SSH clients, such as PuTTY, may close before you can read the error message.

    Note: The Traffic Management Shell (tmsh) is available beginning in BIG-IP version 10.0.0.

F5 Product Development tracked this issue as ID 247800 (formerly CR133685) and fixed it in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM or PSM Release Notes.

Workaround

If a newly elected primary blade is missing one or more home directories, you may synchronize the missing directories from the primary blade of the peer system by performing a new ConfigSync operation.
