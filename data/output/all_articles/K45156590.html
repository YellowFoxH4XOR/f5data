Topic

You should consider using this procedure under the following conditions:

  • You are using the BIG-IP ASM Layer 7 (L7) denial-of-service (DoS) protection feature.
  • You want to review and understand DoS L7 log messages that are generated by your BIG-IP system.

Description

The BIG-IP ASM L7 DoS protection feature detects the spikes and anomalies in Layer 7 (application layer) traffic. The dosl7d process handles processing for this feature. By default, the dosl7d process logs Notice level messages to the /var/log/dosl7/dosl7d.log file. For information about DoS L7 log messages, refer to the following procedures:

  • Identifying the start of a DoS attack
  • Identifying the end of a DoS attack
  • Reviewing the statistics for an attack that has ended

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The ASM module is licensed and provisioned on the BIG-IP system.
  • You have advanced command line access to the system.

Procedures

Identifying the start of a DoS attack

When an L7 DoS attack starts, the system logs an error message to the /var/log/dosl7/dosl7d.log file that indicates important information about the attack, including when the attack started, among other details. To identify the start of a DoS attack, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To change to the /var/log/dosl7 directory, type the following command:

    cd /var/log/dosl7

  3. Use a Linux utility such as less or grep to search the dosl7d.log file for indications of an ongoing or previously detected L7 DoS attack.

    For example:

    grep -i 'ATTACK STARTED' dosl7d.log

  4. When the system detects the start of an attack, you see an error message that appears similar to the following example:

    DOSL7D|NOTICE|Aug 20 20:46:42.565|10587|dosl7d_anomaly_engine.cpp:2047|>>>>>>>>> ATTACK STARTED on TPS  /Common/VS_172_14_17_238_MyVirtual MODE from 10.45.199.102 detection: 6 legitimate: 1 attack id: 1215537174 Mitigation:transparent <<<<<<<<<

    • In the previous error message, note the following:
      • DOSL7D: indicates the name of the daemon that is logging the message.
      • NOTICE: indicates the syslog level of the message.
      • Aug 20 20:46:42.565: indicates the date and time in which the system detected the attack.
      • 10587: indicates the dosl7d process ID.
      • dosl7d_anomaly_engine.cpp:2047: indicates the name of the module.
      • >>>>>>>>> ATTACK STARTED: indicates that an attack started.
      • TPS: indicates that an attack was detected based on change in the transactions per second for that entity.
      • /Common/VS_172_14_17_238_MyVirtual: indicates the name of the affected virtual server.
      • 10.45.199.102: indicates the source IP address involved in the attack.
      • detection: 6 legitimate: 1: indicates that 'legitimate' is the historical TPS value, and 'detection' is the present TPS value.
      • attack id: 1715537184: indicates the attack ID.
      • Mitigation:transparent: indicates the mitigation state, and how the system reacts when it detects an attack.

Identifying the end of a DoS attack

When an L7 DoS attack ends, the system logs an error message to the /var/log/dosl7/dosl7d.log file that indicates information about the attack, including when the attack ended, among other details. To identify the end of a DoS attack, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To change to the /var/log/dosl7 directory, type the following command:

    cd /var/log/dosl7

  3. Use a Linux utility such as less or grep to search the dosl7d.log file for indications of an ongoing or previously detected L7 DoS attack.

    For example:

    grep -i 'END ATTACK' dosl7d.log

  4. When the system detects the end of a DoS attack, you see an error message that appears similar to the following example:

    DOSL7D|NOTICE|Aug 20 20:46:44.254|10587|dosl7d_anomaly_engine.cpp:1998|>>>>>>>>> END ATTACK on vs /Common/VS_172_14_17_238_MyVirtual no more suspicious entities <<<<<<<<<

    • In the previous error message, note the following:
      • DOSL7D: indicates the name of the daemon that is logging the message.
      • NOTICE: indicates the syslog level of the message.
      • Aug 20 20:46:44.254: indicates the date and time in which the attack ended.
      • 10587: indicates the dosl7d process ID.
      • dosl7d_anomaly_engine.cpp:1998: indicates the name of the module.
      • >>>>>>>>> END ATTACK: indicates that an attack has ended.
      • /Common/VS_172_14_17_238_MyVirtual: indicates the name of the affected virtual server.
      • no more suspicious entities <<<<<<<<<: indicates that the TPS has decreased to the previous legitimate level.

Reviewing the statistics for an attack that has ended

When an L7 DoS attack has ended, the system logs an error message to the /var/log/dosl7/dosl7d.log file that reports statistical information about the attack. To review the statistical information about the end of a DoS attack, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To change to the /var/log/dosl7 directory, type the following command:

    cd /var/log/dosl7

  3. Use a Linux utility such as less or grep to search the dosl7d.log file for indications of an ongoing or previously detected L7 DoS attack.

    For example:

    grep -i 'Stats for ended attack' dosl7d.log

  4. When the DoS attack has subsided, you see an error message that appears similar to the following example:

    DOSL7D|NOTICE|Aug 20 20:46:44.254|10587|dosl7d_anomaly_engine.cpp:1998|Stats for ended attack on vs /Common/VS_172_14_17_238_MyVirtual profile /Common/dos:
    tps_ip_susp_ent : min= 0 avg= 0 max= 0
    tps_url_susp_ent: min= 0 avg= 0 max= 0
    latency_susp_ent: min= 0 avg= 1 max= 1

    • In the previous error message, note the following:
      • DOSL7D: indicates the name of the daemon that is logging the message.
      • NOTICE: indicates the syslog level of the message.
      • Aug 20 20:46:44.254: indicates the date and time in which the attack ended.
      • 10587: indicates the dosl7d process ID.
      • dosl7d_anomaly_engine.cpp:1998: indicates the name of the module.
      • vs /Common/VS_172_14_17_238_MyVirtual: indicates the virtual server name for which the statistics apply.
      • profile /Common/dos: indicates the dosl7 profile name.
      • tps_ip_susp_ent : min= 0 avg= 0 max= 0: populates when the attack is coming from an IP address.
      • tps_url_susp_ent: min= 0 avg= 0 max= 0: indicates when an attack is targeting a specific URL from multiple IP addresses.
      • latency_susp_ent: min= 0 avg= 1 max= 1: indicates latency between suspicious attacks.
