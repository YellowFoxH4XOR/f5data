Description

A VLAN Custom Resource (CR) in BIG-IP Next Service Communication Proxy (SPK) may remain stuck in the "CR config deployment is in progress" state and not be created on the f5-tmm pod. Attempts to delete the VLAN CR can also hang indefinitely. The following error may be observed in the logs:

admission webhook "f5validate.f5net.com" denied the request: Number of IPV4 IPs and IPV6 IPs must be same

Environment

  • BIG-IP Next Service Communication Proxy (SPK)
  • VLAN CR with:
    • Unequal number of IPv4 self IPs than IPv6 self IPs
  • Kubernetes cluster
  • Validation webhook enabled for F5SPKVlan resources

Cause

The number of IPv4 self IPs does not match the number of IPv6 self IPs in the VLAN CR specification. The BIG-IP Next Service Communication Proxy (SPK) admission webhook enforces this requirement and will deny creation or deletion of the VLAN CR if the counts do not match, resulting in the resource being stuck in a non-READY state.

Answer/Recommended Actions

  1. Review the VLAN CR specification and ensure the number of IPv4 self IPs matches the number of IPv6 self IPs.
  2. Update the VLAN CR to include an equal number of IPv4 and IPv6 self IPs.
  3. Apply the corrected VLAN CR or retry deletion if the resource was previously stuck.
  4. If the CR is stuck and cannot be deleted due to validation webhook enforcement, correct the configuration to satisfy the webhook requirements before retrying deletion.

Additional Information

  • The admission webhook will block both creation and deletion of the VLAN CR if the self IP counts do not match.
  • This behavior is by design to enforce configuration consistency.
