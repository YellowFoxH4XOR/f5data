1. Description

This article describes how to configure BIG-IP to forward various log sources to remote syslog servers or Sumo Logic, including:

  • TMM logs (tmmX.log)
  • System logs
  • Custom log files (e.g., bd.log from /var/log/ts)
  • LTM request logs

The configuration must ensure persistence across reboots and upgrades while maintaining existing telemetry streams such as ASM logging.

2. Environment

  • BIG-IP LTM version 11.x or later
  • Platform: BIG-IP systems with syslog-ng
  • Existing High-Speed Logging (HSL) configuration for ASM or other telemetry (optional)
  • Remote syslog server or Sumo Logic endpoint configured to receive logs
  • HTTP profile required on virtual servers for LTM request logging

3. Cause

None

4. Recommended Actions

Forwarding TMM Logs and Custom Log Files Using syslog-ng

Important: Do not edit the syslog-ng configuration file directly, as changes may be overwritten during upgrades. Use the tmsh modify /sys syslog include parameter instead to ensure configuration persistence.

  1. Log in to tmsh by entering the following command:
  2. tmsh
  3. To configure forwarding of TMM logs, use the following command syntax:
  4. modify /sys syslog include "
  5. source s_tmm {pipe(\"/var/log/tmm\");};
  6. destination d_remote_loghost {udp(\"<remote_server_ip>\" port(514));};
  7. log {source(s_tmm);destination(d_remote_loghost);};
  8. "
  9. To forward custom log files (such as bd.log), add a file source:
  10. modify /sys syslog include "
  11. source s_bd_log {file(\"/var/log/ts\");};
  12. destination d_remote_loghost {udp(\"<remote_server_ip>\" port(514));};
  13. log {source(s_bd_log);destination(d_remote_loghost);};
  14. "
  15. To forward multiple log sources simultaneously, combine them in a single include statement:
  16. modify /sys syslog include "
  17. source s_tmm {pipe(\"/var/log/tmm\");};
  18. source s_bd_log {file(\"/var/log/ts\");};
  19. destination d_remote_loghost {udp(\"<remote_server_ip>\" port(514));};
  20. log {source(s_tmm);destination(d_remote_loghost);};
  21. log {source(s_bd_log);destination(d_remote_loghost);};
  22. "
  23. Save the configuration:
  24. save /sys config
  25. If necessary, restart the syslog-ng service:
  26. bigstart restart syslog-ng
  27. Test the configuration in a non-production environment first to ensure correct syntax.

Configuring LTM Request Logging via High-Speed Logging (HSL)

LTM request logging uses High-Speed Logging (HSL) to send logs directly from TMM to a pool of log servers. This method is separate from syslog-ng and is the recommended approach for HTTP request/response logging.

  1. Create a pool for the log server:
  • Navigate to Local Traffic > Pools
  • Click Create
  • Add the IP address and port (typically 514) of your Sumo Logic endpoint or syslog server
  1. Create a Request Logging profile:
  • Navigate to Local Traffic > Profiles > Other > Request Logging
  • Click Create
  • Enable Request Logging or Response Logging as needed
  • Configure the Template field with desired log format (e.g., ${CLIENT_IP} - - ${DATE_NCSA} ${HTTP_REQUEST} ${HTTP_STATCODE} ${RESPONSE_SIZE})
  • Select HSL Protocol (UDP or TCP)
  • Select the Pool Name created in step 1
  1. Assign the Request Logging profile to virtual server(s):
  • Navigate to Local Traffic > Virtual Servers
  • Select the virtual server
  • Click the Resources tab
  • From the Request Logging Profile list, select the profile created in step 2
  • Click Update

Avoiding Conflicts with Existing Telemetry

  • Configure separate log publishers and destinations for each logging profile (ASM, LTM request logging, etc.)
  • When both remote syslog-ng logging and remote HSL with filters are configured, BIG-IP daemons (such as mcpd, tmm) will send logs via HSL only by design
  • Existing ASM telemetry using HSL will not be impacted by adding request logging or syslog-ng configurations when properly separated

Sending Logs to Sumo Logic

Choose one of the following methods:

  • Method 1: Point BIG-IP syslog-ng or HSL configuration to Sumo Logic's syslog collector IP and port
  • Method 2: Use Sumo Logic's HTTP source with F5 Telemetry Streaming extension

Validation

  1. Verify all log sources are being received at the destination
  2. Confirm existing ASM logging remains unaffected after implementation
  3. Monitor for any configuration persistence issues after system reboots or upgrades
  4. Verify the number of active TMM processes to ensure all TMM logs are captured:
  5. tmsh show /sys tmm-traffic

5. Additional Information

The include parameter in the syslog configuration ensures that custom logging configurations persist across reboots and upgrades. This is the recommended method for customizing syslog behavior on BIG-IP systems.

When using iRules for logging, ensure you use a log publisher (via HSL::open -publisher <publisher_name>) rather than direct pool connections for proper integration with the logging infrastructure and RFC 5424 syslog format compliance.

The Request Logging profile can only be used with remote logging. For local logging (not recommended for production), use iRules.
