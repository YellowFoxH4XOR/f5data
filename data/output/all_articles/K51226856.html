Topic

You should consider using this procedure under the following condition:

  • You want to use the iControl REST API to manage services on the BIG-IP system.

Description

You can use the iControl REST API to perform the following tasks when managing services on the BIG-IP system:

  • View the current status of a service
  • Start, stop, or restart a service
  • Add or remove a service from the list of services that start during system startup

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP Configuration utility.
  • You have command line access to a Linux system (or an alternate BIG-IP system) that has the curl and jq (command-line JSON processor) utilities installed.

Procedures

  • Viewing the current status of a service
  • Starting, stopping, or restarting a service
  • Adding or removing a service from the service Boot group

Viewing the current status of a service

To view the current status of a service, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a client system that contains the curl and jq utilities.
  2. Show the current service status using the following syntax:

    curl -ksu admin:<password> -H "Content-Type: application/json" https://<bigip_hostname>/mgmt/tm/sys/service/<service_name>/stats | jq '.' 

    For example, to show the status of the snmpd service, enter the following:

    curl -ksu admin:testing -H "Content-Type: application/json" https://ltm1.example.com/mgmt/tm/sys/service/snmpd/stats | jq '.' 

    The following example output shows the snmpd service state is run and the service has been up for 6 days:

    {
      "kind": "tm:sys:service:servicestats",
      "generation": 0,
      "selfLink": "https://localhost/mgmt/tm/sys/service/snmpd/stats?ver=15.1.0",
      "apiRawValues": {
        "apiAnonymous": "snmpd        run (pid 7537) 6 days\n"
      }
    }

    To show the status for all services, enter the following:

    curl -ksu admin:testing -H "Content-Type: application/json" https://ltm1.example.com/mgmt/tm/sys/service/stats | jq '.' | sed 's/\\n/\n/g'

    Output appears similar to the following truncated example:

    {
      "kind": "tm:sys:service:servicecollectionstats",
      "selfLink": "https://localhost/mgmt/tm/sys/service/stats?ver=15.1.0",
      "apiRawValues": {
        "apiAnonymous": "aced         run (pid 7306) 173 days, 5 starts
    adfs_proxy   run (pid 8705) 173 days, 5 starts
    admd         run (pid 7308) 173 days, 5 starts

    antserver    down, Not provisioned

      }
    }

Starting, stopping, or restarting a service

You can use the iControl REST start, stop, and restart commands to manage services on the BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a client system that contains the curl and jq utilities.
  2. Stop, start, or restart a service using the following syntax:

    curl -ksu admin:<password> -H "Content-Type: application/json" -X POST https://<bigip_hostname>/mgmt/tm/sys/service -d '{"command":"<restart | stop | start>","name":"<service_name>"}' | jq '.'

    For example, to restart the snmpd service, enter the following command:

    curl -ksu admin:testing -H "Content-Type: application/json" -X POST https://ltm1.example.com/mgmt/tm/sys/service -d '{"command":"restart","name":"snmpd"}' | jq '.'

    Output appears similar to the following example:

    {
    "kind": "tm:sys:service:restartstate",
    "command": "restart",
    "name": "snmpd"
    }

Adding or removing a service from the service Boot group

You can add and remove services from the list of services that are automatically started when the BIG-IP system starts up. To do so, perform the following procedure:

Note: When you remove a service from the Boot group using the iControl REST API, the service is also removed from the Default group of services controlled by the bigstart utility.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a client system that contains the curl and jq utilities.
  2. List the current settings for the service using the following syntax:

    curl -ksu admin:<password> -H "Content-Type: application/json" https://<bigip_hostname>/mgmt/tm/sys/service/<service_name> | jq '.'

    For example, to list the settings for the snmpd service, enter the following command:

    curl -ksu admin:testing -H "Content-Type: application/json" https://ltm1.example.com/mgmt/tm/sys/service/snmpd | jq '.'

    The following example output shows the service is in both the service Boot group and Default group:

    {
      "kind": "tm:sys:service:servicestate",
      "name": "snmpd",
      "fullPath": "snmpd",
      "generation": 0,
      "selfLink": "https://localhost/mgmt/tm/sys/service/snmpd?ver=15.1.0",
      "apiRawValues": {
        "Boot": "on",
        "Default": "yes"
      }
    }

  3. Add or remove a service from the Boot group using the following syntax:

    curl -ksu admin:<password> -H "Content-Type: application/json" -X PATCH https://<bigip_hostname>/mgmt/tm/sys/service/<service_name> -d "{\"<add | remove>\":true}" | jq '.'

    For example, to remove a service from the Boot group, enter the following command:

    curl -ksu admin:testing -H "Content-Type: application/json" -X PATCH https://ltm1.example.com/mgmt/tm/sys/service/snmpd -d "{\"remove\":true}" | jq '.'

    Output appears similar to the following example:

    {
      "kind": "tm:sys:service:servicestate",
      "name": "snmpd",
      "fullPath": "snmpd",
      "generation": 0,
      "selfLink": "https://localhost/mgmt/tm/sys/service/snmpd?ver=15.1.0",
      "apiRawValues": {
        "Boot": "off",
        "Default": "no"
      }
    }

    To add a service to the Boot list, enter the following command:

    curl -ksu admin:testing -H "Content-Type: application/json" -X PATCH https://ltm1.example.com/mgmt/tm/sys/service/snmpd -d "{\"add\":true}" | jq '.'

    Output appears similar to the following example:

    {
      "kind": "tm:sys:service:servicestate",
      "name": "snmpd",
      "fullPath": "snmpd",
      "generation": 0,
      "selfLink": "https://localhost/mgmt/tm/sys/service/snmpd?ver=15.1.0",
      "apiRawValues": {
        "Boot": "on",
        "Default": "no"
      }
    }

    In the previous output, you can see the value for Default is "no", so the snmpd service is not in the Default service group. To add the snmpd service back to the Default service group, enter the following command:

    curl -ksu admin:testing -H "Content-Type: application/json" -X POST https://ltm1.example.com/mgmt/tm/util/bash -d "{\"command\":\"run\", \"utilCmdArgs\": \"-c 'bigstart add --default snmpd'\"}" | jq '.' 

    Output appears similar to the following example:

    {
      "kind": "tm:util:bash:runstate",
      "command": "run",
      "utilCmdArgs": "-c 'bigstart add --default snmpd'"
    }
