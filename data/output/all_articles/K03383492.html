Known Issue

The Traffic Management Microkernel (TMM) may produce a core file and restart upon a pool member event.

This issue occurs when all of the following conditions are met:

  • The Action On Service Down setting in the pool is configured to Reselect.
  • All members of the pool are configured with a connection rate limit.
  • Load-balanced traffic to all pool members exceeds the connection rate limit.
  • The BIG-IP system detects all pool members as down.

Impact

The BIG-IP system may temporarily stop processing traffic while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • If configured for high availability (HA), the BIG-IP system fails over to the standby system.
  • The BIG-IP system generates TMM core files to the /var/core directory, which include a time stamp that correlates with the traffic interruption.
  • The BIG-IP system logs messages to the /var/log/daemon.log file that appear similar to the following example:

    emerg logger: Re-starting tmm
    emerg logger: Re-starting tmm1
    emerg logger: Re-starting tmm2
    emerg logger: Re-starting tmm3

  • The BIG-IP system logs messages to the /var/log/tmm file that appear similar to the following example:

    notice ** SIGSEGV **
    notice fault addr: 0x8
    notice fault code: 0x1

Resolution

Status

Workaround

To work around this issue, you can remove the Connection Rate Limit from the affected pool members.

Impact of workaround: Connection rate limiting of pool members will no longer be enforced.
