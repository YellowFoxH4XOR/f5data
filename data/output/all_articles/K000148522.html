Topic

Beginning in BIG-IP 16.1.6, 17.1.2.2 and 17.5.0, you can now use the Database (DB) variable tm.tcpstopblindinjection.

Description

The DB variable tm.tcpstopblindinjection lets you configure the BIG-IP system to mitigate the TCP Blind data Injection attack (a special case of which are Ghost Ack attacks). For more information on this attack, refer to RFC 5961 section 5 and K000151297: BIG-IP TMM vulnerability CVE-2025-58424

By default, tm.tcpstopblindinjection is disabled.

Procedure

To mitigate the TCP Blind data injection attack, you enable the DB variable. To do so, perform the following procedure:

Impact of action: Enabling the tm.tcpstopblindinjection database variable may slightly increase latency and CPU usage on Traffic Management Microkernel (TMM) during typical traffic levels but could further increase under high connection rates or heavy traffic flow.

Important: F5 Product Engineering has identified an issue that affects some connection types like SMTP where the server side sends data first, causing the server data to be dropped. F5 has assigned ID 2132165 to this issue. If you experience connection issues after enabling this DB key, F5 recommends disabling it until the fix is available.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:
    tmsh
  2. To enable the DB variable, enter the following command:
    modify sys db tm.tcpstopblindinjection value enable
