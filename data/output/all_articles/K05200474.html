Description

If a SNAT object is configured, the SNAT settings will be applied globally to all matching traffic, even to a virtual server if that traffic matches.
This behavior can be overwritten by SNAT automap or a SNAT pool configured on the virtual server.
If traffic is intended to pass without having SNAT applied, then additional configuration is necessary to ensure that the SNAT object isn't applied globally.

Environment

  • LTM
  • Virtual Server with no SNAT configured
  • Bypassing SNAT object matching the same traffic

Cause

Configured SNAT objects are applied to all traffic through a system globally, unless that traffic subjected to SNAT through the virtual server configuration
 

Recommended Actions

There are several options for configuring the Big-IP LTM to avoid applying SNAT to traffic.
  1. Configure the destination pool for the virtual server to disallow SNAT.
    • Local Traffic >> Pools > [pool name] >  disable "Permit SNAT" under the advanced options
  2. Configure SNAT through virtual servers as necessary, instead of configuring a global SNAT
  3. Configure SNAT object with narrower origin addresses or VLANs, so it doesn't match traffic through the affected virtual server
