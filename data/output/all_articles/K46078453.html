K46078453: Management IP lost after rebooting BIG-IP LTM VE cloud

Type
Support Solution
Published
2023-11-08
Updated
2023-12-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.0, 15.1.0, 14.1.2, 15.0.X, 14.0.X, 15.0.1, 15.0.0, 14.0.1, 14.0.0
Source
https://my.f5.com/manage/s/article/K46078453

Description

BIG-IP VE deployed on cloud provider may be unable to reach metadata services with static management interface config, this happens after a reboot of BIG-IP VE.

In certain circumstances the Bigip might be forced to reboot via cloud provider or manually by admin, upon booting backup the Bigip can lose its management IP and thus would be unable to authenticate to licensing server.

Errors such as the following can be seen in kernel logs
/var/log/kern.log:

info kernel: : [ 4257.890492] hv_utils: Shutdown request received - graceful shutdown initiated info kernel: hv_utils: Shutdown request received - graceful shutdown initiated

Once Bigip boots back up you might notice the following errors on ltm logs
/var/log/ltm:

err chmand[5540]: Curl request to metadata service failed with error(7): 'Couldn't connect to server' debug chmand[4803]: IR_DEBUG:[CurlReader.cpp:ReadData(181)]: URL: <http://198.51.100.254/latest/meta-data/product-codes> debug chmand[4803]: IR_DEBUG:[CurlReader.cpp:ReadData(243)]: curl_easy_perform failed with result = 7 ::
 

Environment

  • BIG-IP LTM-VE

Cause

Due to the race condition and delay in bringing the management interface up, the licensing services would not work as expected. This issue is caused by ID850777
 

Recommended Actions

To recover from this issue, you can follow one of the following steps:
  • Upgrade to fixed version from ID850777 listed software 
  • Reload license after the BIG-IP LTM-VE has completed booting up, to reload license run reloadlic on tmsh.
