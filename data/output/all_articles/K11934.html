Issue

Beginning in BIG-IP 10.2.3, log messages that report a node status change are no longer throttled.

In versions prior to BIG-IP 10.x, log messages that report a node status change can exceed logging rate limits when a large number of nodes suddenly become unavailable. When this event occurs, the BIG-IP system logs a message similar to the following example to the /var/log/ltm file:

01070640:6: Per-invocation log rate exceeded; throttling.

Note: For more information about the error message and a description of throttling, refer to K10524: Error Message: Per-invocation log rate exceeded.

Note: In BIG-IP 9.x, log messages that report a node status change are not throttled.

The former BIG-IP 10.x behavior may hide critical information from log sifting utilities. For example, if ten nodes simultaneously become unavailable, the BIG-IP system is likely to only log five node status change messages and one log rate exceeded message. As a result, the logs do not show which additional nodes have also become unavailable.

F5 Product Development tracked this change in behavior as ID 338289.
