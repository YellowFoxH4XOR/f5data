Description

Create syslog configuration to filter noisy, recurring logs locally in /var/log/ltm and from being sent to a remote syslog server.

As an example, the workaround for ID1228465 will be used to filter 3 recurring logs, which are causing /var/log/ltm to rollover and reduce visibility of other logged events.

warning chmand[4101]: 012a0004:4: getHostVWireNtiObjectConfigs vCmpShmIntf: Query segment error
warning chmand[4101]: 012a0004:4: VcmpShmIntf::querySeg: err code -34
warning chmand[4101]: 012a0004:4: getHostVWireObjectConfigs vCmpShmIntf: Query segment error

Environment

Confirmed log event is benign. In the case of ID1228465, due to a recent upgrade to an affected 15.1.x version, the 3 chmand warnings are repeatedly logged in /var/log/ltm.

Cause

Benign, recurring logs that decrease visibility of more important logs.

Recommended Actions

Use message filter prefaced with "not" in the filter statement to remote syslog server:

filter f_getHostVWireNtiObjectConfigs {not message(\\getHostVWireNtiObjectConfigs\\) and not message(\\getHostVWireObjectConfigs\\) and not message(\\VcmpShmIntf\\);};

To filter the logs from being written to /var/log/ltm:

filter f_local0 {
    (facility(local0) and not match (getHostVWireNtiObjectConfigs) and not match (getHostVWireObjectConfigs) and not match (VcmpShmIntf));
};

As an example, here is the entirety of a syslog configuration that will filter any events that do not match the 3 strings from being sent to the syslog server 10.253.77.195.

Typically, syslog uses port 514 over UDP. However, syslog can be used over TCP occasionally. F5 Support recommends verifying with your internal syslog administrator, as configuring with the incorrect protocol will result in no captured logs on the remote syslog server.

root@(localhost2)(cfg-sync In Sync)(Active)(/Common)(tmos)# root@(localhost2)(cfg-sync In Sync)(Active)(/Common)(tmos)# list sys syslog
sys syslog {
    include "
    destination d_remote_loghost {
          udp(\"10.253.77.195\" port(514));
 };
    filter f_remote_loghost {level(warning..emerg) ;};
    filter f_getHostVWireNtiObjectConfigs  {not message(\\getHostVWireNtiObjectConfigs\\) and not message(\\getHostVWireObjectConfigs\\) and not message(\\VcmpShmIntf\\);};
      log {
          source(s_syslog_pipe);
          filter(f_getHostVWireNtiObjectConfigs);
          filter(f_remote_loghost);
          destination(d_remote_loghost);
      };
       filter f_local0 {
           (facility(local0) and not match (getHostVWireNtiObjectConfigs) and not match (getHostVWireObjectConfigs) and not match (VcmpShmIntf));
       };
        "
}

Run a tcpdump to see the packets are filtered out. The log events that match any of the 3 strings will be filtered out: "getHostVWireNtiObjectConfigs", "getHostVWireObjectConfigs", "VcmpShmIntf".
