Description

In a BIG-IP system, a pool member is a logical object defined by its IP address and service port. The availability status of a pool and its members can be determined by the health monitor(s) assigned to the entire pool or each individual member. There are a number of functional categories of health monitor, namely:

  • Address-check monitors - a simple monitor that pings an IP address to verify that the address can be reached by the BIG-IP system. For example Gateway ICMP and TCP Echo.
  • Service-check monitors - a monitor that opens a connection to an IP address and port to determine if a service is available. For example, UDP and TCP Half Open.
  • Content-check monitors - a monitor that sends a command to a server and examines the server's response to ensure it is serving the defined content. For example, HTTP and HTTPS.
  • Path-check monitors - a monitor that sends a packet through the network device or to a remote server to verify that traffic can pass through the network device. For example Gateway ICMP and ICMP.
  • Application-check monitors - a custom or external monitor that tests a specific application. For example, FTP and External.

If a pool member has its service port defined as *All Services / any (0), the BIG-IP system imposes limitations on the health monitors that can be assigned to it.

The BIG-IP system imposes limitations on the categories of health monitor that can be assigned to a pool member with its service port defined as *All Services / any (0) because the pool member does not have a definitive service port and monitors such as Service-check and Content-check require either the pool member to have a definitive service port or the monitor to have a definitive service port for monitoring.

Recommended Actions

You can assign a monitor from the Address-check category to a pool member with its service port defined as *All Services / any (0). Note that the ICMP and TCP Echo monitors are only allowed to be assigned at the node level instead of the pool level. As a result, you may only be able to assign the Gateway ICMP monitor from the Address-check category to a pool member with its service port defined as *All Services / any (0). 

For the Service-check, Content-check and Application-check monitor categories, you should create a custom monitor and configure a definitive port for the Alias Service Port setting. The tmsh utility equivalent of this setting is the destination setting; note that this setting is a combination of IP address and service port so you should configure it as *.<service port> if you only want to define the service port to monitor. For example, you should configure the destination setting with the value of *.80 if you want the monitor to monitor port 80.

Additional Information

If you attempt to assign the pre-configured monitors from a category other than Address-check without configuring the Alias Service Port setting to a pool member with its service port defined as *All Services / any (0), for example the HTTP monitor from the Content-check category, you may observe an error message similar to the following:

01070622:3: The monitor /Common/http has a wildcard destination service and cannot be associated with a node that has a zero service.

If you attempt to assign node level monitors such as ICMP and TCP Echo to a pool member, you may observe an error message similar to the following:

01070587:7: The requested monitor rule (/Common/icmp on pool /Common/pool-any) can only be applied to node addresses.
