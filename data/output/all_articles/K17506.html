Known Issue

The BIG-IP configuration may fail to load after you rename the CM device name.

This issue occurs when one of the following conditions is met:

  • You load your BIG-IP configuration.
  • You upgrade your BIG-IP system software.
  • You perform a configuration synchronization (ConfigSync) operation for the device group.

The default-device attribute is not updated on a traffic group when you renamed the CM device name. As a result, the associated traffic group may reference to the old device name and cause configuration load failures.

The default-device attribute has been deprecated beginning in BIG-IP 11.4.0. Prior to 11.4.0, the default-device attribute was used to specify the device group member that failback tries to make active. Beginning in 11.4.0, when auto-failback is enabled, the system uses the first member of the Failover Order. Hence the default-device attribute is no longer in use, and the system will fail validation if it contains a value that does not reference the name of an existing device group member, or if the value is not set to none.

Impact

The BIG-IP system fails to load the configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system may fail to load the configuration.
  • During the configuration load process, you may observe error messages in the /var/log/ltm file that appear similar to the following example:

    01070712:3: Values (/Common/test.abc.es.f5net.com) specified for traffic group (/Common/traffic-group-1): foreign key index (default_device_fk) do not point at an item that exists in the database.

    Note: In the previous error message, traffic-group-1 displays reference to the old device name test.abc.es.f5net.com.

Workaround

To work around this issue, modify the affected traffic group' s default-device attribute to none. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system. Modifying the default-device attribute does not disrupt the system, as the system is no longer using this option.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To list the configured default device for a traffic group, use the following command syntax:

    list /cm traffic-group <traffic group name>

    For example, to list the configured default device for traffic-group-1, type the following command:

    list /cm traffic-group traffic-group-1

  3. Set the affected traffic group's default-device attribute to none using the following command syntax:

    modify /cm traffic-group <traffic group name> default-device none

    For example, to set the default-device attribute to none for traffic-group-1, type the following command:

    modify /cm traffic-group traffic-group-1 default-device none

  4. Save the configuration changes by typing the following command:

    save /sys config
