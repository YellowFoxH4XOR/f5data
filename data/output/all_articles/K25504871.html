Known Issue

An iRule that calls the persist command may result in a Traffic Management Microkernel (TMM) memory leak.

This issue occurs when all of the following conditions are met:

  • You have configured a User Datagram Protocol (UDP) virtual server.
  • An iRule calling the persist command under the CLIENT_DATA event is assigned to the UDP virtual server.
  • Load balancing of the UDP flow fails as the assigned pool has no available members.

Impact

TMM memory usage grows and may lead to TMM restarting.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM memory leak results in growth in memory allocation and an eventual TMM restart.
  • TMM attempts to free up memory by removing idle connection flows.
  • You may experience the system removing idle connection flows before their idle timeout period expires.

Resolution

Workaround

To work around this issue, move the persist command to the CLIENT_ACCEPTED event.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
