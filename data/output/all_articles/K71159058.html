Topic

This article applies to BIG-IP ASM 12.x. For information about other versions, refer to the following article:

  • K75376155: Creating a security policy automatically (14.x)
  • K79575295: Creating a security policy automatically (13.x)

You should consider using this procedure under the following condition:

  • You want to create a BIG-IP ASM security policy automatically using the Policy Builder feature.

Description

The BIG-IP ASM system provides several options for creating and deploying a security policy. F5 recommends that most users create a security policy automatically. Doing so allows the system to create the initial security policy and then refine the policy over time by examining application traffic. When you create a security policy automatically, Policy Builder develops the policy using the following steps:

  • In the initial phase, the system identifies legitimate application usage and begins to build your security policy based on a statistical analysis of your traffic and the intended behavior of your application. In this phase, the system does not block requests until Policy Builder processes sufficient traffic and adds elements to the security policy.
  • In the next phase, Policy Builder refines and tightens the security policy over time until the number of policy changes stabilizes.
  • In the final phase, Policy Builder further refines the security policy until it is ready to enforce the necessary security features.

For example, the following scenario illustrates how Policy Builder automatically adds a legitimate file type to the policy based on an analysis of the application traffic:

  1. You create a security policy using the automatic policy building option.
  2. A client sends a GET request for /sell.php.
  3. Since the PHP file type does not yet exist in policy, the BIG-IP ASM system allows the request but marks PHP as an illegal file type and sends a copy of the request to Policy Builder.
  4. The system continues to mark requests for PHP files as illegal until the request threshold is met for that file type.
  5. Once the threshold is met for PHP files, the BIG-IP ASM system updates the security policy and no longer considers PHP as an illegal file type.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the Configuration utility.
  • You performed basic configuration tasks to create:
    • A Virtual Local Area Network (VLAN).
    • A self IP address for the VLAN.
    • A local traffic pool.
    • A virtual server.

Procedures

To create a security policy automatically and review additional action items for the policy, perform the following tasks:

  • Creating a security policy automatically using Policy Builder
  • Refining the security policy
  • Performing additional action items for the policy

Creating a security policy automatically using Policy Builder

To create a security policy automatically using Policy Builder, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Security Policies.
  3. Click Create.
  4. Under Select Local Traffic Deployment Scenario, click Existing Virtual Server and click Next.
  5. Under Configure Local Traffic Settings, click the application protocol and the virtual server name and click Next.
  6. Under Select Deployment Scenario, click Create a security policy automatically (recommended) and click Next.
  7. Under Configure Security Policy Properties:
    • Type a name for the security policy.
    • For Application Language, click the application's language encoding or click Auto detect to let the system detect the language.
    • Leave the Security Policy is case sensitive check box selected if the application is case-sensitive.
    • Leave the Differentiate between HTTP/WS and HTTPS/WSS URLs check box selected if the web application behaves differently for HTTP/WS and HTTPS/WSS URLs.
    • Click Next.
  8. Under Configure Attack Signatures:
    • For Systems, in the Available Systems list, click the systems your application uses and move them to Assigned Systems.
    • For Signature Staging, leave the Enabled check box selected if you want the system to initially test the signatures for false positives without enforcing them.

      Note: New and updated attack signatures remain in staging for seven days and are recorded but the system does not enforce the Learn, Alarm, and Block flags in the attack signatures configuration during that time.

    • Click Next.
  9. Under Configure Automatic Policy Building:
    • For Policy Type, click the type of policy you want to build. The default Fundamental option creates a security policy that is appropriate for most applications.
    • For Policy Builder Learning Speed, click an option to elect how fast to generate suggestions for the policy.
    • For Trusted IP Addresses, specify a list of networks that Policy Builder considers safe.
    • For AJAX blocking response behavior, select the Enabled check box if you want to display a response page when an AJAX request does not adhere to the security policy.
    • Click Next.
  10. For Security Policy Configuration Summary, review the security policy settings and click Finish.

Refining the security policy

After you finish creating your security policy, you should have users browse and test access to the application. As they browse the application, the system initially allows all traffic through the policy, and Policy Builder examines the traffic and makes learning suggestions which you can review. You can then configure Policy Builder to amend the policy based on the learning suggestions.

As the BIG-IP ASM system processes requests, it may alert you to a potential violation, such as the inability to convert a character string using the default language encoding defined in the security policy. When this occurs, the Traffic Learning page displays the violation, such as Failed to convert character, and lists an associated action for you to take. For example, Action: Set Alarm to enabled. Set Block to enabled. You can accept, delete, or ignore the suggestion. If you accept the suggestion, the system performs the described action. In this example, the system alarms and blocks for requests that trigger the Failed to convert character violation.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Traffic Learning.
  3. On the Traffic Learning tab, in the Current edited security policy list policy, click the name of the policy you want to refine and review the suggestions for that policy:
    • Click a learning suggestion to view information about the suggestion and the associated action the system takes if you accept the suggestion.
    • Review other relevant data, such as the number of requests that triggered the learning suggestion.
    • Click a request to view data about the request, including any violations it generated, the contents of the request itself, and the response.
  4. For each suggestion, you can click Accept Suggestion, Delete Suggestion, or Ignore Suggestion as appropriate for your policy.
  5. Click Apply Policy to activate any changes you made to the policy.

Performing additional action items for the policy

On the Action Items page, you can review a list of suggested action items, which the system reminds you to perform, such as required configuration and maintenance tasks. To take action on the items, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Overview > Application > Action Items.
  3. Under Suggested Action Items, review the list of recommended for more information.
  4. For Policy Elements Learned in Automatic mode, review the progress of Policy Builder and policy elements.
  5. Under Quick Links, use the links to access common configuration pages in the policy.
