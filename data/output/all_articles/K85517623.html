Description

In some circumstances you may want/need to upgrade a device beyond what is listed in the K9476: The F5 hardware/software compatibility matrix
For example, K9476 indicates v11.6.3 is the highest compatible release for a 3900 (106C) platform. However, to resolve CVE-2020-5902, it is necessary to upgrade to  v11.6.5.2.


Environment

  • Hardware involved includes 3900, 6900, 8900, 2000/2200, 4000/4200, 5000/5200 and 7000/7200 platforms.
  • Upgrade planning
  • Questions about supportability
Cause

Product Engineering (PE) does not update the hardware/software matrix document for devices that reach end of software development support (EoSD). Thus, when a new maintenance version of a software line (such as 11.6.x or 12.1.x), occurs after a device reaches EoSD, that version is not included in the "Compatible software versions".

Recommended Actions

Most older platforms currently in use are in extended support, defined in K4309: F5 platform lifecycle support policy. If you are using such a platform, or one completely out of support, you should consider upgrading to a fully supported hardware platform.

We want people to use latest versions of supported software, regardless of K9476 - It is always recommended that you run the latest Maintenance release for your supported software version. This will eliminate the possibilities of you running into resolved bugs and security issues. If 11.6 was supported on a platform, then the latest 11.6.x fix release (11.6.5.3) is expected to work fine - just don't use software branches never supported for that platform (such as v13 or later).

Additional Information

K9476 is a compatibility guide, not a supportability guide. After platform EoSD you are in extended support. Unfortunately the article leads people to think they are not supported on more recent maintenance releases, which isn't true.

F5 will not release engineering hotfixes on maintenance or point releases that were current when a platform passed platform End of Service Date (EoSD) and entered extended support. However, since you are already running a platform that is not fully supported, you may consider updating to a software release with the fixes. F5 does not take steps to break updates for platforms in extended support. So, in general, F5 expects that later maintenance and point releases issued after the platform entered extended support should work normally . For example, a system that was running BIG-IP 12.1.3 when it entered extended support will likely run 12.1.5.3 without issue, and updating will not change the support status. In the meantime, you can immediately apply the mitigations provided in the appropriate security advisory.
