Description

Client side Zoom application fails to launch various features, while connected to the APM Edge Client.
This is due to Zoom DNS requests that are not excluded from VPN tunnel. 

Clients may see that some activity within the Zoom application may fail because certain Zoom DNS requests will still go through VPN tunnel, even though *.zoom.us is in the DNS Exclude Address Space in the Big-IP Network Access Split Tunnel configuration

Environment

  • Big-IP APM Network Access Split Tunnel
  • Client side Zoom application

Cause

Zoom has a dynamic IP address list that correlates with requests to *.zoom.us.
These IP addresses also have to be entered into the IPV4 Exclude Address Space in the Network Access Split Tunnel configuration.
However, since the IP address list from Zoom is dynamic, this may need to be updated in the Network Access Split Tunnel configuration, frequently.

Recommended Actions

The Zoom IP address list can be found here:
https://assets.zoom.us/docs/ipranges/ZoomMeetings.txt
These need to be entered into the IPV4 Exclude Address Space in the Network Access Split Tunnel configuration on the Big-IP.
Additionally, ensure that *.zoom.us is entered into the DNS Exclude Address Space in the Network Access Split Tunnel configuration on the Big-IP

Alternatively, v16.1.0 has a new feature that has a built in dynamic address exclude list specifically for Zoom that manages this specific issue and configuration.
This is configurable through an Address Space and is described in detail here:
https://techdocs.f5.com/en-us/bigip-16-1-0/big-ip-access-policy-manager-network-access/configuring-address-spaces/what-is-address-space.html
