Known Issue

The VIPRION system may fail to change the cluster IP address. This issue occurs when all of the following conditions are met:

  • You log in to the Configuration utility by way of the cluster IP address.
  • You then attempt to change the cluster IP address from the Configuration utility.

Impact

You are unable to change the cluster IP address using the Configuration utility.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H481966 on the Diagnostics > Identified > Low screen.
  • The Configuration utility reports that it is redirecting to the new cluster IP address, but the new cluster IP address does not take effect, and the redirection fails when the page eventually times out.
  • The new cluster IP address does not respond to ICMP packets while the previous cluster IP address continues to respond to ICMP packets.
  • The VIPRION system reports an error message similar to the following example to the /var/ltm/log file:

    01071473:3: Create, modify, and delete commands are not valid for (by class: route_mgmt_entry) while in the root folder.

Resolution

Status

F5 Product Development has assigned ID 435569 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, you can perform the cluster IP address change using the Configuration utility, by logging into the primary blade management IP address. Alternatively, you can perform the cluster IP address change using the tmsh utility, by logging into the serial console or ssh command line of the primary blade. For information about these procedures, refer to K15690: Changing the cluster IP address for VIPRION platforms

Impact of workaround: Performing the following procedure should not have a negative impact on your system.
