Description

You should consider using this procedure under the following condition:

  • You want to use an iRule to block HTTP requests with malicious User-Agent headers.

  • You want to import a file containing a list of malicious user agents.

The HTTP User-Agent header contains client information, such as the type and version of the web browser, operating system, and platform. You can create an iRule to block requests containing certain elements.

Environment

  • BIG-IP LTM
  • Data Group External File Type
  • iRule

 

Cause

None

 

 Recommended Actions

Import the file containing malicious user agents:

 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

 

1. Log in to the Configuration utility.

2. Navigate to Local Traffic > iRules > Data Group List.

3. Click Create.

4. For Name, assign a name accordingly. E.g. malicious_browser_ua

5. For Type, select (External File).

6. For Records, click Import.

7. For File Name, click Choose File to upload the file with a list of malicious user agents.

8. For Name, give the file a name accordingly.

9. For File Contents, select String.

10. Click Import.

11. The imported file will be added to System  ››  File Management : Data Group File List.

12. The created external type data group will now be added to Local Traffic  ››  iRules : Data Group List

 

Note:

On the external file you will be importing to BIG-IP, the malicious user agent list should be in the following format.

 

"MSIE 10.0" := "",

"MSIE 9.0" := "",

"80legs" := "",

"AIBOT" := "",

"curl" := "",

 

Legends:

"MSIE 10.0" <-- This is the user string we want to block.

:= <-- This is the key separator between the string and value.

"" <-- This is the value that we can keep as blank.

 

Create an iRule to block HTTP requests containing a specific string in the User-Agent header

 

Impact of procedure: The impact of the suggested procedure depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

 

1. Log in to the Configuration utility.

2. Navigate to Local Traffic > iRules > iRule List.

3. Click Create.

4. For Name, type a name for the iRule.

5. For Definition, enter the user-agent blocking iRule.For example, the following iRule blocks requests from malicious browsers listed in the data group named malicious_browser_ua:

 

when HTTP_REQUEST {
 if {[class match [HTTP::header "User-Agent"] contains malicious_browser_ua]}{
  log local0. "Malicious Browser User Agent = [HTTP::header "User-Agent"]"
  drop
  }
 }

 

6. Click Finished.

7. Associate the iRule with the virtual server.

 

Note:

Below are the sample of LTM logs when a malicious browser user agent has been detected.

 

May 11 00:06:29 LTM1.example.com info tmm3[16760]: Rule /Common/malicous_ua_irule <HTTP_REQUEST>: Malicious User Agent = Mozilla/5.0 (MSIE 10.0; Windows NT 6.1; Trident/5.0)

May 11 00:23:07 LTM1.example.com info tmm2[16760]: Rule /Common/malicous_ua_irule <HTTP_REQUEST>: Malicious Browser User Agent = AIBOT

May 11 00:26:19 LTM1.example.com info tmm3[16760]: Rule /Common/malicous_ua_irule <HTTP_REQUEST>: Malicious Browser User Agent = curl/7.43.0

 

 

Additional Information

You can use the following key commands to build the iRule:

  • The [HTTP::header "User-Agent"] command returns the user-agent string from the client-request header.
  • The contains operator verifies whether the user-agent string contains the matching element.
  • The drop command discards connections with unwanted user agents.
  • The class match command searches lists of strings in a data group.
  • The log local0. command logs the detected malicious user agent under /var/log/ltm.
