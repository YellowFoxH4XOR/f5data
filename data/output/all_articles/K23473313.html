Description

Behavior of internally generated DNS outbound requests via the management interface on dual stack IPv4 and IPv6.

Internally generated BIGIP traffic via the management interface on a dual stack addressed system uses the IPv4 stack if both IP stack routing paths are available. The system will only use the IPv6 stack if the IPv4 path is unavailable.

Environment

  • Dual stack IPv4 and IPv6 configured on the management interface
  • IPv4 and IPv6 IP DNS servers configured routed via the management configured routes
  • BIGIP system making DNS requests for example traffic for licensing or F5 call home.
Sample configuration
---------------------

[root@bigip1:Active:Standalone] config # tmsh list sys management-ip
sys management-ip 192.0.2.1/24 { }
sys management-ip 2001:db8::1/64 { }

[root@bigip1:Active:Standalone] config # tmsh list sys management-route
sys management-route exampledns {
    gateway 192.0.2.254
    network 198.51.100.8/32
}
sys management-route i6gw {
    gateway 2001:db8::254
    network default-inet6
}

[root@bigip1:Active:Standalone] config # tmsh list sys dns
sys dns {
    name-servers { 198.51.100.8 2001:0db8:ffff:ffff::30 }
    search none
}

Cause

Expected behaviour.

Recommended Actions

None

Additional Information

This is expected behavior by design.
BIGIP system will prefer the IPv4 stack when making outbound DNS requests for internally generated DNS requests. Internally generated DNS requests include "Automatic licensing", "Automatic Update Check", "Automatic Phone Home" and "IP Address Intelligence".
