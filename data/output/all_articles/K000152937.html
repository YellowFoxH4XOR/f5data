Environment

  • mysql database
  • bd

Cause

The behavior is caused by corruption in the mysql database.

Recommended Actions

As an initial measure repairing the database can be attempted as per instructions in K05755225. If this does not resolve the issue, to recover the unit you can boot back to the previous boot location and perform a clean install.

If there is a peer unit in the HA in a working condition then the steps below can be followed to recover the problematic unit.

1. Take backups from both units.

2. Disable ASM auto-sync from the relevant device group as it is not desired for the devices to try syncing before finishing the process.

3. In the unit that is offline reset the ASM database to its default configuration. After this step the device should come back online.

# tmsh stop /sys service asm
# /usr/share/ts/bin/tsconfig.pl
# tmsh start /sys service asm

4. Once the unit is back online. Sync the configuration manually from the active device. Once the sync is complete both units should be online with the same configuration.

5. Test the functionality and restore auto-sync for the device group.
