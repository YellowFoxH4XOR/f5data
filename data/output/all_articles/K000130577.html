Description

  • How to use a specific IP as source IP to send ASM Event logs

Environment

  • ASM Provisioned
  • You are sending event logs through tmm interface

Cause

By default, ASM Logging Profiles will select the corresponding outbound interface by network routes, it will use traffic-group-local-only (non-floating) Self IPs to send logs to remote syslog servers. In some use cases, this is not desirable.

 Recommended Actions

ASM remote storage traffic can be sent to an internal virtual server, configured on the same device that is sending the ASM logs, which then by using Source Address Translation changes the source IP and send them to the destinated logging server.

 

  1. Create a new Standard type virtual server on the BIG-IP you want to send logs from by navigating to Local Traffic  ››  Virtual Servers. This new virtual server will be on your ASM/Adv. WAF device.
  2. The virtual server IP address assigned should be reachable via an existing TMM interface.
  3. Make sure the Virtual Server from step 1 has a TCP profile, but no HTTP profile applied.
  4. In Source Address Translation, assign an SNAT Pool/Use SNAT automap in the Virtual Server
  5. Navigate to the ASM Security Logging Profile at Security  ››  Event Logs : Logging Profiles : [profile name]
  6. Change Storage Destination to Remote Storage
  7. In the Server Addresses configuration for the IP Address and Port fields enter the IP address and port of the virtual server created in step 1.
  8. Select Update
