Known Issue

The BIG-IP system fails to relay Credit-Control-Request (CCR) messages received by a diameter virtual server to the pool member. This issue occurs when the following condition is met:

  • The diameter virtual server is assigned an iRule that uses the table command in the DIAMETER_EGRESS event.

A diameter CCR message is typically used to request credit authorization for a variety of end user services, such as a pre-paid mobile line.

Impact

The client communications may stall and fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H387097 on the Diagnostics > Identified > Low screen.
  • The BIG-IP system fails to relay CCR messages and logs an error message that appears similar to the following example to the /var/log/ltm file:

    01220009:6: Pending rule event DIAMETER_EGRESS aborted for <pool member IP:port>-><client IP or selfIP:port> (listener: <diameter virtual server>)
    014c0001:3: diameter process ingress error Prerequisite operation not in progress

  • A tcpdump file that was captured when the issue occurred may show a diameter CCR message arriving to the BIG-IP system, but the message does not get forwarded to the backend server.

Workaround

To work around this issue, you may be able to use the session command instead of the table command in the DIAMETER_EGRESS event. Alternatively, if you require the use of the table command, avoid using it in the DIAMETER_EGRESS event and instead use it in the DIAMETER_INGRESS event. To do so, perform either of the following procedures:

  • Replacing the table command with the session command
  • Using the table command in the DIAMETER_INGRESS event

Replacing the table command with the session command

Impact of Workaround: Depending on your usage of the table command, you may lose some features that the session command does not have.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click the name of the affected iRule.
  4. Search and replace the table commands in the DIAMETER_EGRESS event with the session commands.

    For example, the following iRule snippet uses the table command in the DIAMETER_EGRESS event:

    when DIAMETER_EGRESS {
    set pool [LB::server pool]
    table set [DIAMETER::session] $pool $static::timeout
    }

    This iRule can be replaced with the session command. For example:

    when DIAMETER_EGRESS {
    set pool [LB::server pool]
    session add uie [DIAMETER::session] $pool $static::timeout
    }

  5. Click Update.

Using the table command in the DIAMETER_INGRESS event

If you require the use of the table command, you may have to reorganize your iRule to use the table command in the DIAMETER_INGRESS event. The DIAMETER_INGRESS event is triggered when the BIG-IP system receives a diameter message, while the DIAMETER_EGRESS event is triggered when the BIG-IP system is ready to send a diameter message. This reorganization may require an extensive rewrite of the iRule depending on how it is written, due to the difference between the triggers for the two events.
