K01408004: LDAP authentication fails after a while

Type
Support Solution
Published
2022-02-25
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.0.X, 15.0.1, 15.0.0, 14.1.2, 14.1.0
Source
https://my.f5.com/manage/s/article/K01408004

Description
After upgrading , LDAP authentication fails after a while.

Environment

  • BIG-IP
  • LTM
  • LDAP remote authentication via a tmm interface.

Cause
The LDAP client nslcd fails to re-establish a session after the TCP connection to the LDAP server is reset. 
 

Recommended Actions

  1. Reduce the idle timeout for the connection to the LDAP server.
    tmsh modify auth ldap system-auth idle-timeout 295
    tmsh save sys config
     
  2. Set referrals to 'no' in the in the nslcd config. 

    Note: As of version 15.1.0, LDAP referrals are configured through the 'auth ldap system-auth' object. For instructions on disabling referrals in more recent BIG-IP versions, please consult Knowledge Base article K000151413. 

    tmsh modify sys db systemauth.referrals value no
    tmsh save sys config
    tmsh load sys config

    Note: it is very important to save and then load the configuration. Otherwise the change to referrals will not be applied.

  3. Confirm that the change has been applied
    grep referrals /etc/nslcd.conf
    The line will show "referrals no"

Additional Information
The idle timeout for the LDAP connection is 3600 by default,  and the default idle timeout in tmm for TCP is 300 by default. This means that when a connection to the LDAP server is via a tmm interface and has been idle for 300 seconds, then tmm will send a RST on this connection, even though LDAP has a default idle timeout of 3600 seconds. The process nslcd struggles to re-establish a connection to the LDAP server which is why subsequent authentication requests will fail, but then later some may succeed. Reducing the LDAP timeout to be less than 300 will allow LDAP to RST its own connection before tmm sends the RST, which allows nslcd to re-establish the connection without any issues.
