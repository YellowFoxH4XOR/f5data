Description

With the change from the Application Security Manager (ASM) to the Advanced Web Application Firewall (AWAF) there will be changes in what and how protection for your application is handled. As of April1, 2021 ASM will hit End of Sale (EoS). F5 will continue to provide BIG-IP ASM and BEST Bundle customers with the ability to continue to consume BIG-IP ASM past EoS. However, license renewals will not be available after April 1. 2021. BIG-IP ASM and BEST Bundle customers can continue to renew there support service for ASM.

  • In regards to SSRF protection ASM will continue to have some protections but as things evolve AWAF will be where improvements will be found. One of those is with Server Side Request Forgery (SSRF) Host Header Injection.
  • You have had a vulnerability check or maybe an actual attack and it was identified as SSRF via Host Header Injection.

Environment

  • Attack signatures, Bot Defense
  • Application Security Manager, Advanced Web Application Firewall

Cause

There is a need address the possibility of a Server Side Request Forgery attack. In a Server-Side Request Forgery (SSRF) attack, the attacker can abuse functionality on the server to read or update internal resources. The attacker can supply or modify a URL which the code running on the server will read or submit data to, and by carefully selecting the URLs, the attacker may be able to read server configuration such as AWS metadata, connect to internal services like http enabled databases or perform post requests towards internal services which are not intended to be exposed.

Recommended Actions

  1. ASM will protect against some SSRF types of concerns via Attack Signatures. Such as localhost or internal IP addresses in the host name, url line, parameter value or a specific CVE. In regards to proxy type SSRF, such as a Host Header Injection, it's not possible to achieve this from an ASM standpoint because ASM doesn't allow for disallowing requests and raising a violation based on hostnames (unless you do it using an iRule). If using an iRule is the way you need  to approach this then you would implement an iRule that would verify that the hostname in the Request URL that matches what's specified within the HTTP Host header for the request. In addition to it, you can also whitelist hostnames specified within the Host header by using a combination of iRules and Data Groups that would drop requests which don't match that hostname.

  2. Starting in version 15.1.0 AWAF adds new SSRF violation protections. This violation is raised when a "Host" header does not contain a host that is related to the host name list (Security >> Application Security : Headers : Host names) or a microservice host (except the wildcard "*"). The Microservice Properties host is found at Security >> Bot Defense : Bot Defense Profiles : Microservice Protection.

  3. To deal with Host Header Injection ASM will have to upgraded to AWAF or you can contact Professional Services for assistance with an iRule for ASM.
