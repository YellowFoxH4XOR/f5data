K14046551: Explicit FTP proxy with SSLO not yet supported

Type
Support Solution
Published
2020-09-02
Updated
2023-02-09
Applies to
  • F5 App Protect
  • F5 SSL Orchestrator: 17.X.X, 17.0.X, 17.0.0, 16.X.X, 16.1.1, 16.1.0, 16.0.1, 16.1.X, 16.0.0, 16.0.X, 16.1.3, 16.1.2
Source
https://my.f5.com/manage/s/article/K14046551

Description

When an SSLO configuration with explicit proxy topology is created, it works well for HTTP traffic but not for FTP.
This is despite the fact that after deployment, the admin can set the L7 profile Interception rule on for FTP.

Environment

  • Big-IP SSL Orchestrator (SSLO)

Cause

FTP is only supported on a transparent proxy topology, not with explicit proxy, on SSLO at present (as of version 7.x).

Recommended Actions

If FTP is required over SSLO, a transparent L2 or L3 outbound deployment should be used, rather than explicit proxy.

Alternatively, you can consider configuring a SOCKS proxy to work with SSL Orchestrator. For more information, refer to the DevCentral article: SSL Orchestrator Advanced Use Cases: Integrating SOCKS Proxy.

Additional Information

This is because an explicit proxy deployment runs not only on a specified IP address, but also on a specified port (default 3128), and the Virtual Server it creates is a Standard type Virtual Server tied to a specific IP and port, with an HTTP profile tied to it (and ftp profile is none/greyed out).
