Description

When L7 policy with bot-defense enable command is configured without setting the bot-defense profile name, TMM can core and may lead to HA failover. Configuring bot-defense enable without profile name is possible only through editing bigip.conf file as GUI does not allow this.

 

Example config showing issue:

ltm policy /TESTENV/L7_SAMPLE_POLICY {
controls { bot-defense }
description "<>"
requires { http }
rules {
"rule 1" {
actions {
0 {
bot-defense
disable
}
}
conditions {
0 {
http-header
name User-Agent
contains
values { Verify CFNetwork Darwin }
}
}
}
"rule 2" {
actions {
0 {
bot-defense
enable
<<----!!!! Missing bot profile reference.

}
}
ordinal 1
}
}
strategy /Common/first-match
}

Environment

  • BIG-IP ASM
  • Bot-profile
  • TMM
  • Core file

Cause

The issue is due to the Bug ID 1624625

Recommended Actions

Set the profile name in the Bot Defense enable command as shown in the example below

Example working config showing bot profile enable command referring default bot profile

ltm policy /TESTENV/L7_SAMPLE_POLICY {
controls { bot-defense }
description "ekamev_scanning_app_bot whitelisting"
requires { http }
rules {
"rule 1" {
actions {
0 {
bot-defense
disable
}
}
conditions {
0 {
http-header
name User-Agent
contains
values { Verify CFNetwork Darwin }
}
}
}
"rule 2" {
actions {
0 {
bot-defense
enable
from-profile /Common/bot-defense <<-----!!!!
}
}
ordinal 1
}
}
strategy /Common/first-match
}
