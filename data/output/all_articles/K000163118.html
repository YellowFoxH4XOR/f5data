K000163118: PSU Present but Not Fully Detected on an rSeries Appliance

Source

Description

On an F5OS-A rSeries Appliance, one of the PSUs (like "PSU-2") may be detected as physically present but fail to provide complete hardware identification and sensor data. The system may report PSU fault detected, Input Lost, Input Active, Absent, or Presence detected. The desired PSU may appear as 'ok' under "show system health" while detailed attributes show zero sensor values or unidentified and mismatch states.

Environment

  • Product: F5OS-A
  • rSeries Appliance with redundant PSUs
  • PSU installed and connected to power
  • PSU family must match the supported Appliance model

Cause

The behavior could be consistent with a transient ConfD or component-registration failure condition.

As a side note, you need to verify that the installed PSU belongs to the correct supported model family. Manufacturing Revision differences within an approved PSU family do not, by themselves, indicate incompatible PSUs. For further details, you can check the below KB Article:

K36588206: AC power supply units for iSeries and rSeries platform models should not be interchanged

Answer/Recommended Actions

1) Verify that both PSUs are approved for the Appliance model. Do not interchange PSUs intended for incompatible iSeries or rSeries models.

2) Verify that both PSUs are fully inserted, properly seated, and connected to active power sources.

3-1) Check the PSU component status:

# show components component psu-*

3-2) Confirm that each PSU reports:

  • A valid Serial Number (S/N)
  • A valid Part Number (P/N)

4) Check the system-health summary:

# show system health

5) If the desired PSU is present but lacks valid identification, reports zero sensor values, or displays stale fault states, Reboot the rSeries Appliance during an approved Maintenance window. [K000130484]

Important: Before Rebooting the rSeries Appliance, consider a Maintenance window to avoid any unexpected service disruption at either Host or Tenant-level.

6) After the Reboot, verify PSU detection:

# show components component psu-*
# show system health

7) Confirm that both PSUs report valid hardware attributes and that no persistent PSU fault detected, Input Lost, Absent, or Unidentified events remain.

8) If the issue recurs, collect the following diagnostic outputs as 'root' user and provide them to F5 Support for further Investigations:

# docker exec platform-hal psf call GET:lop/psu-fru-info subObject=1
# docker exec platform-hal psf call GET:lop/psu-fru-info subObject=2
# docker exec platform-hal psf call GET:lop/psu-present
# docker exec platform-hal psf call GET:chassis/psu-report

Additional Information

  • The system-health summary may show PSU-2 as 'ok', even when detailed attributes contain zero sensor values or stale fault indicators. Review both summary and detailed component output.
  • A Host Reboot can restore PSU component registration and normal reporting when the hardware is present but not fully identified.
  • If the correct PSU family is installed and the issue persists after Re-seating and Rebooting, further hardware and component-registration analysis is required.
