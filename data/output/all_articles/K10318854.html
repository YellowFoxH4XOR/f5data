Description

  • One or more pool members have markedly higher number of connections
  • These reported high CPU usage.

Environment

  • HTTP Virtual Server with OneConnect profile.
  • Pool with Round Robin (default)  balancing.

Cause
The OneConnect profile will distribute L7 requests to servers. If an idle TCP connection is available, it is used.
Otherwise a new connection is made.

The number of connections to a server is thus rate*duration.


On first glance this seems that the load balancing has failed and a pool member is getting a disproportionate amount of traffic, causing high CPU.
However what is really happening is that a L7 request is taking a disproportionate amount of time to complete (stalls). This also slows down processing server wide.
The duration of requests goes up (its slower), therefore the number of connections goes up.
 

Recommended Actions

  1. Change the load balancing method to "Least Connections". This will allow the affected pool member to recover
  2. The root causes lies with the request and the answer will be in the pool member analytics. This is not an F5 issue.
