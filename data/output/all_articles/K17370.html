Topic

This article applies to BIG-IP 12.x through 13.x. For information about other versions, refer to the following articles:

  • K01770517: Configuring the cipher strength for SSL profiles (14.x - 16.x)
  • K13171: Configuring the cipher strength for SSL profiles (11.x)

You should consider using these procedures under the following condition:

  • You want to configure a custom cipher list for a Client or Server SSL profile.

Description

The BIG-IP system NATIVE stack is built into the Traffic Management Microkernel (TMM) and is optimized to take advantage of hardware acceleration for most SSL ciphers. For a complete list of SSL ciphers in the NATIVE stack, refer to K13163: SSL ciphers supported on BIG-IP platforms (11.x - 13.x). For information on the SSL ciphers that are hardware accelerated, refer to K13213: SSL algorithms that are hardware accelerated (11.x - 14.x).

By default, SSL profiles are configured to use an F5 recommended subset of SSL ciphers from the NATIVE stack. This subset of ciphers is designated in the SSL profile Ciphers setting using the DEFAULT cipher string. For a list of SSL ciphers available when an SSL profile uses the DEFAULT cipher string, refer to K13156: SSL ciphers used in the default SSL profiles (11.x - 13.x).

By modifying the SSL profile Ciphers setting, you can make SSL connectivity more or less permissive. For example, you can disable weak ciphers and allow only strong ciphers, thereby enforcing PCI requirement for stronger cryptography and eliminating weak SSL cipher violations. You can use the SSL profile Ciphers setting to create a custom cipher string, and beginning in BIG-IP 13.0.0, you can associate custom cipher groups to specify the cipher suites allowed when the BIG-IP system negotiates new SSL connections. A custom cipher group offers increased visibility of the available ciphers and is also less prone to typographical errors. To create a custom cipher group, refer to K10866411: Creating a custom cipher group using the Configuration utility.

Note: For more information about cipher suites and cipher string syntax used in the procedures, refer to K15194: Overview of the BIG-IP SSL/TLS cipher suite.

Configure the SSL profile to include a specific SSL cipher

After you verify that the cipher you want is not already included in the DEFAULT cipher list, you can add the cipher to the SSL profile. To do so, perform the following steps:

Note: Camellia ciphers are added to the NATIVE stack in BIG-IP 12.0.0 but are not enabled in the DEFAULT cipher.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create or select the name of an existing profile to edit it.
  4. For a new profile, under General Properties, enter a name.
  5. Set Configuration to Advanced.
  6. For Ciphers, select the Custom check box.
  7. (BIG-IP 13.0.0 and later) Under Configuration, for Ciphers, select Cipher String.
  8. Enter the cipher string into the Cipher String box.

    For example, to enable Camellia ciphers, append CAMELLIA to the DEFAULT cipher string using the following syntax:

    DEFAULT:CAMELLIA

  9. Configure the remaining profile settings.
  10. Select Finished.

Note: To configure an SSL profile to include Camellia ciphers using the TMOS Shell (tmsh), use the following command syntax: tmsh create /ltm profile client-ssl <profile_name> ciphers DEFAULT:CAMELLIA.

Configure the SSL profile to use a specific protocol

Impact of procedure: Configuring the profile to use only TLSv1.2 protocol causes connection failure for clients that do not support TLS 1.2.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create or select the name of an existing profile to edit it.
  4. For a new profile, under General Properties, enter a name.
  5. Set Configuration to Advanced.
  6. For Ciphers, select the Custom check box.
  7. (BIG-IP 13.0.0 and later) Under Configuration, for Ciphers, select Cipher String.
  8. Enter the cipher string into the Cipher String box.

    For example, the following string configures an SSL profile to use only TLS 1.2 protocol ciphers:

    TLSv1_2

  9. Configure the remaining profile settings.
  10. Select Finished.

Note: To configure an SSL profile to use only TLSv1.2 protocol ciphers using tmsh, use the following command syntax: tmsh create /ltm profile client-ssl <profile_name> ciphers TLSv1_2.

Configure the SSL profile to block a specific SSL cipher

Impact of procedure: Configuring the profile to block a specific SSL cipher may cause certain client connections to fail.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create to create a new profile, or select the name of an existing profile to edit it.
  4. For a new profile, under General Properties, enter a name.
  5. Set Configuration to Advanced.
  6. For Ciphers, select the Custom check box.
  7. (BIG-IP 13.0.0 and later) Under Configuration, for Ciphers, select Cipher String.
  8. Enter the cipher string into the Cipher String box.

    For example, the following string allows the default ciphers for the SSL profile and blocks the AES128-SHA cipher:

    DEFAULT:!AES128-SHA

  9. Configure the remaining profile settings.
  10. Select Finished.

Note: To create an SSL profile to block the AES128-SHA cipher using tmsh, use the following command syntax: tmsh create /ltm profile client-ssl <profile_name> ciphers 'DEFAULT:!AES128-SHA'.

Configure the SSL profile to order SSL ciphers by strength

Impact of procedure: Ordering SSL ciphers by strength may cause the virtual server to process fewer SSL transactions per second (TPS).

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create or select the name of an existing profile to edit it.
  4. For a new profile, under General Properties, enter a name.
  5. Set Configuration to Advanced.
  6. For Ciphers, select the Custom check box.
  7. (BIG-IP 13.0.0 and later) Under Configuration, for Ciphers, select Cipher String.
  8. Enter the cipher string into the Cipher String box.

    For example, the following string sorts the cipher list in order of encryption algorithm key length:

    DEFAULT:@STRENGTH

  9. Configure the remaining profile settings.
  10. Select Finished.

Note: Alternatively, to create an SSL profile to order SSL ciphers by strength using tmsh, use the following command syntax tmsh create /ltm profile client-ssl <profile_name> ciphers DEFAULT:@STRENGTH.

Configure the SSL profile to block a specific SSL version

Impact of procedure: Configuring the profile to block a specific SSL protocol may cause certain client connections to fail.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create or select the name of an existing profile to edit it.
  4. For a new profile, under General Properties, enter a name.
  5. Set Configuration to Advanced.
  6. For Ciphers, select the Custom check box.
  7. (BIG-IP 13.0.0 and later) Under Configuration, for Ciphers, select Cipher String.
  8. Enter the cipher string into the Cipher String box.

    For example, the following string allows the default ciphers for the SSL profile and blocks TLSv1 protocol:

    DEFAULT:!TLSv1

  9. Configure the remaining profile settings.
  10. Select Finished.

Note: Alternatively, to create an SSL profile to block TLSv1 protocol using the tmsh utility, use the following command syntax: tmsh create /ltm profile client-ssl <profile_name> ciphers 'DEFAULT:!TLSv1'.

View the SSL cipher order

You can view the order of SSL ciphers presented during the SSL handshake using the Advanced Shell (bash). To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash.
  2. To view the SSL cipher order, use the following command syntax:

    Client SSL profile

    tmm --clientciphers '<cipher_one:cipher_two>'

    Server SSL profile

    tmm --serverciphers '<cipher_one:cipher_two>'

    For example, to view the order of SSL ciphers used with the cipher string list DEFAULT:!TLSv1, enter the following command:

    tmm --clientciphers 'DEFAULT:!TLSv1'

Configure the SSL profile to block a specific SSL protocol

You can configure a custom SSL profile to not accept specific SSL protocols. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure negates access to the virtual server when negation of the specific SSL protocol is configured. 

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client or Local Traffic > Profiles > SSL > Server.
  3. Select the name of the SSL profile you want to modify.
  4. Set Configuration to Advanced.
  5. For Options List, in the Available Options box, select the SSL or TLS protocol that you want to disable.

    Possible protocol negation options are No DTLS, No SSL, No SSLv2, No SSLv3, No TLS, No TLSv1, No TLSv1.1, and No TLSv1.2.

  6. To move the option to the Enabled Options box, select Enable.
  7. Select Finished.
