Issue

When you run the bigpipe configsync command, you may receive the following error:

Monitor Template my_http: Invalid destination service

You can configure BIG-IP health monitors to perform a compound check, so that if a database or backend server is down, then all dependent web servers are also marked down. When configuring a compound check, you use the health monitor's dest directive, which uses the argument of ip:port. For this configuration, you must specify a port when you specify an IP address. If you supply only an IP address without specifying a port, the port will not be inherited from the node to which the monitor is applied. This will cause a destination service error.

Note: If the node that you want to monitor is the same node that you associate with the monitor, you do not need to configure the monitor with a destination address/service (dest), because the node will be checked by default.

To correct this issue and eliminate this error, remove the monitor and recreate it, specifying both an IP address and a port.

Note: In BIG-IP version 4.0 through 4.2 PTF-10, the Configuration utility incorrectly accepted an IP address without a port specified in the Destination Service field. This issue was corrected in BIG-IP version 4.5.

For specific instructions about configuring health monitors, refer to the BIG-IP Reference Guide.
