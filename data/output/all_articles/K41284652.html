Description

Received an error when syncing, or when creating a static route:

Error Message: 01070666:3: Static route duplicates Self IP <IP> / <mask> implied route

Environment

  • ConfigSync
  • Routing

Cause

Static route in question does duplicate a directly-connected route which exists due to the presence of a self IP.

For example, given the following portions of show net route output from two HA systems:

BIG-IP A:
-------------------------------------------------------------------------------------
Net::Routes
Name                Destination           Type            NextHop        Origin   MTU
-------------------------------------------------------------------------------------
10.10.10.0/24     10.10.10.0/24      interface   /Common/internal     connected     0

Note: BIG-IP A has a self IP in the 10.10.10.0/24 subnet.

BIG-IP B:
-------------------------------------------------------------------------------------
Net::Routes
Name                Destination           Type            NextHop        Origin   MTU
-------------------------------------------------------------------------------------
/Common/route1    10.10.10.0/24             gw       172.16.1.254        static     0

Syncing the route /Common/route1 from BIG-IP B to BIG-IP A would fail because it duplicates the directly-connected route which is already present on BIG-IP A:

Sync error on BIG-IP-A.ltm: Load failed from /Common/BIG-IP-B.ltm 01070666:3: Static route duplicates Self IP 10.10.10.0 / 255.255.255.0 implied route

Recommended Actions

Avoid use of static routes which duplicate directly-connected routes.

To resolve a Sync Failed state you will need to remove the static route or the self IP.

Additional Information

This may be seen in trust domains which contain more than two devices and multiple device groups. In that case, you can control what is synced by creating the route in a specific configuration folder, then assigning the folder to a device group containing the members you want to sync to.
