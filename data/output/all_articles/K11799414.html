Topic

You should consider using this procedure under the following condition:

  • You want to perform one of the following tasks on the BIG-IP system using the iControl representation state transfer (REST) API:
    • View the configured iRule list.
    • Create a new iRule.
    • Delete an iRule from the system.
    • Update an existing iRule.

Description

You can use the iControl REST API to view, create, delete, and update iRules on the BIG-IP system.

In order to include multi-line iRules in REST calls, use escape special characters and the following new line characters properly:

\n

For more information about the iControl REST API, refer to the iControl REST page on F5 Cloud Docs.

curl and jq utilities

You need command line access to a system with the curl utility and, optionally, the jq (command line JSON processor) utility to perform the following procedure. These utilities are commonly available on Linux systems, but you can also install them on Microsoft Windows and Mac OS X systems. Additionally, you can perform this procedure on a BIG-IP system. For more information about the jq utility, refer to https://stedolan.github.io/jq.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You licensed, provisioned, and configured your BIG-IP system with a management IP address.
  • You have administrative access to the BIG-IP LTM Configuration utility.
  • You have command line access to a Linux system (or an alternate BIG-IP system) that has the curl and jq (command line JSON processor) utilities.

Procedures

  • Viewing the configured iRules
  • Creating a new iRule
  • Deleting an iRule from the BIG-IP system
  • Updating an existing iRule

Viewing the configured iRules

You can view the list of iRules configured on the BIG-IP system using iControl REST. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities.
  2. Use the following command syntax to view a list of the configured iRules:

    curl -sku admin:<password> -H "Content-Type: application/json" -X GET https://<BIG-IP_host>/mgmt/tm/ltm/rule | jq .

    For example, to view the iRule list on a BIG-IP using the example configuration above, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X GET https://LTM1.example.com/mgmt/tm/ltm/rule | jq .

Creating a new iRule

You can create a new iRule on the BIG-IP system using the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities.
  2. Use the following command syntax to create a new iRule:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<BIG-IP_host>/mgmt/tm/ltm/rule -d '{"name":"<iRule_name>","apiAnonymous":"<iRule_content>"}' | jq .

    For example, to create the iRule on a BIG-IP that uses the example configuration above, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X POST https://LTM1.example.com/mgmt/tm/ltm/rule -d '{"name":"example_rule","apiAnonymous":"when HTTP_REQUEST {\n  if { [HTTP::uri] ends_with \"test\" } {\n    pool test_pool\n  }\n}"}' | jq .

    Note: Depending on the system you use to make REST calls, for the iRule code in the JSON body, use the proper technique to escape special characters, and use the following characters for new lines:\n.

    The output looks similar to the following example:

    {
      "kind": "tm:ltm:rule:rulestate",
      "name": "example_rule",
      "partition": "Common",
      "fullPath": "/Common/example_rule",
      "generation": 2184,
      "selfLink": "https://localhost/mgmt/tm/ltm/rule/~Common~example_rule?ver=15.1.0",
      "apiAnonymous": "when HTTP_REQUEST {\n  if { [HTTP::uri] ends_with \"test\" } {\n    pool test_pool\n  }\n}"
    }

Deleting an iRule from the BIG-IP system

To delete an iRule from the BIG-IP system using iControl REST, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities.
  2. Use the following command syntax to delete an iRule:

    curl -sku admin:<password> -H "Content-Type: application/json" -X DELETE https://<BIG-IP_host>/mgmt/tm/ltm/rule/<iRule_name> | jq .

    For example, to delete the iRule on a BIG-IP that uses the example configuration above, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X DELETE https://LTM1.example.com/mgmt/tm/ltm/rule/example_rule | jq .

Updating an existing iRule

You can update an existing iRule on the BIG-IP system using iControl REST. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities.
  2. Use the following command syntax to update an existing iRule:

    curl -sku admin:<password> -H "Content-Type: application/json" -X PATCH https://<BIG-IP_host>/mgmt/tm/ltm/rule/<iRule_name> -d '{"apiAnonymous":"when HTTP_REQUEST {\n  if {[HTTP::uri] ends_with \"test\"} {\n    pool test_pool\n  }\n}"}' | jq .

    For example, to update the iRule on a BIG-IP that uses the example configuration above, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X PATCH https://LTM1.example.com/mgmt/tm/ltm/rule/example_rule -d '{"apiAnonymous":"when HTTP_REQUEST {\n  if {[HTTP::uri] ends_with \"test\"} {\n    pool test_pool\n  }\n}"}' | jq .

    The output looks similar to the following example:

    {
      "kind": "tm:ltm:rule:rulestate",
      "name": "example_rule",
      "fullPath": "example_rule",
      "generation": 2202,
      "selfLink": "https://localhost/mgmt/tm/ltm/rule/example_rule?ver=15.1.0",
      "apiAnonymous": "when HTTP_REQUEST {\n  if {[HTTP::uri] ends_with \"test\"} {\n    pool test_pool\n  }\n}"
