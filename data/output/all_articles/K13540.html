Known Issue

The BIG-IP system may return inaccurate results for the prTable (process table).

This issue occurs when the following condition is met:

  • An SNMP query is sent to fetch the values of the prTable of the BIG-IP system.

The prTable object resides in the UCD-SNMP-MIB file, and displays information on running programs/daemons.

Impact

SNMP is unable to monitor the BIG-IP processes correctly and the snmpwalk query may result in erroneous readings from the prTable.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H383847 on the Diagnostics > Identified > Low screen.
  • The snmpwalk command output lists the prNames incorrectly and displays the process names with the full directory path.

    For example, to display the prNames on the localhost you would type the following command:

    snmpwalk -c public -v 2c localhost prNames

    The prNames output incorrectly displays the full directory path. For example:

    UCD-SNMP-MIB::prNames.1 = STRING: /usr/bin/bigd
    UCD-SNMP-MIB::prNames.2 = STRING: /bin/chmand
    UCD-SNMP-MIB::prNames.3 = STRING: /usr/sbin/httpd
    UCD-SNMP-MIB::prNames.4 = STRING: /bin/mcpd
    UCD-SNMP-MIB::prNames.5 = STRING: /usr/bin/sod
  • The snmpwalk command output may display incorrect prCount values indicating that the processes are not running.

    For example, to query the prCount on the localhost you would type the following command:

    snmpwalk -c public -v 2c localhost prCount

    The incorrect values of prCount will appear similar to the following example:

    UCD-SNMP-MIB::prCount.1 = INTEGER: 0
    UCD-SNMP-MIB::prCount.2 = INTEGER: 0
    UCD-SNMP-MIB::prCount.3 = INTEGER: 0
    UCD-SNMP-MIB::prCount.4 = INTEGER: 0
    UCD-SNMP-MIB::prCount.5 = INTEGER: 0
  • The snmpwalk command output may display incorrect prErrMessage values indicating that the processes are not running.

    For example, to display the prErrMessage on the localhost you would type the following command:

    snmpwalk -c public -v 2c localhost prErrMessage

    The incorrect values of prErrMessage will appear similar to the following example:

    UCD-SNMP-MIB::prErrMessage.1 = STRING: Too few /usr/bin/bigd running (# = 0)
    UCD-SNMP-MIB::prErrMessage.2 = STRING: Too few /bin/chmand running (# = 0)
    UCD-SNMP-MIB::prErrMessage.3 = STRING: Too few /usr/sbin/httpd running (# = 0)
    UCD-SNMP-MIB::prErrMessage.4 = STRING: Too few /bin/mcpd running (# = 0)
    UCD-SNMP-MIB::prErrMessage.5 = STRING: Too few /usr/bin/sod running (# = 0)

Workaround

To work around this issue, you can re-configure the processes of the respective prNames to be monitored using the Traffic Management Shell (tmsh). To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.
  2. Modify the prName for monitoring the bigd process by typing the following command:

    modify sys snmp process-monitors modify { bigd { process bigd } }
  3. Modify the prName for monitoring the chmand process by typing the following command:

    modify sys snmp process-monitors modify { chmand { process chmand} }
  4. Modify the prName for monitoring the httpd process by typing the following command:

    modify sys snmp process-monitors modify { httpd { max-processes infinity process httpd} }
  5. Modify the prName for monitoring the mcpd process by typing the following command:

    modify sys snmp process-monitors modify { mcpd { process mcpd } }
  6. Modify the prName for monitoring the sod process by typing the following command:

    modify sys snmp process-monitors modify { sod { process sod } }
  7. Save the changes by typing the following command:

    save sys config
  8. To exit tmsh, type the following command:

    quit
