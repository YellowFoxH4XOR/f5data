Description

When In-TMM monitoring is enabled, only a portion of monitored resources will report an accurate state and the rest will report availability Unknown and have statuses/messages regarding service checking not being enabled and/or service check results not yet available.
Enabling Monitor Logging (K12531) may show instances of messaging containing "tmm_mid=x:0" where x can be values like 0, 1, 2 etc. For example:

[0][11288] 2019-03-08 10:03:04.686708: ID 10859 :(_do_ping): post ping, status=UNKNOWN [ tmm?=true td=true tr=false tmm_mid=1:0 addr=::ffff:1.2.37.44:443 mon=/Common/https fd=-1 pend=0 #conn=0 up_intvl=5 dn_intvl=5 timeout=16 time_until_up=0 immed=0 next_ping=[1552068189.684126][2019-03-08 10:03:09] last_ping=[1552068184.684909][2019-03-08 10:03:04] deadline=[1552067610.048558][2019-03-08 09:53:30] on_service_list=True snd_cnt=119 rcv_cnt=0 ]

In this example it was tmm_mid=1:0.

Environment

  • BIG-IP
  • v13.1.1 and V14.*
  • Pool/Node
  • In-TMM monitoring enabled

Cause

Bug ID753594

Recommended Actions

Disable in-tmm monitor on CLI run below command:

tmsh modify sys db bigd.tmm value disable

Alternatively the number of monitored instances can be reduced however this is typically impractical and is not recommended.
If in-tmm montior is enabled due to high CPU usage,see K42421592: High CPU utilization of bigd
