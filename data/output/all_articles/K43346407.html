Known Issue

A BIG-IP device group member may appear offline to peer members after it changes its management IP address. This occurs because the change is not synchronized to the device service clustering (DSC) configuration of the peer device group members. The issue arises even if the management IP is not used in the ConfigSync or Network Failover configuration.

This issue occurs when the following condition is met:

  • You change the management IP address of a device group member.

Impact

If you change the management IP of an Active device group member, it will fail over to a peer. If you change the management IP of a Standby device group member, it will no longer be able to take the Active role.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Device group members incorrectly report that a device with a recently changed management IP address is offline.
  • The Active device group member fails over after changing the management IP address.
  • You cannot fail over to a device group member with a recently changed management IP address.
  • DSC configuration is out of sync.
  • In the /var/log/ltm files of the device where the management IP address changed, you may observe messages similar to the following example:

    notice sod[7535]: 010c004a:5: Leaving active in favor of active peer.
    notice sod[7535]: 010c0052:5: Standby for traffic group /Common/traffic-group-1.
    notice sod[7535]: 010c0018:5: Standby

Workaround

To work around this issue, you can force a ConfigSync operation that pushes the management IP address change to the peer device group members, and manually restart the sod process of the device group members that received the ConfigSync. To do so, perform the following procedure:

Impact of workaround: Restarting the sod process will trigger the device it was run on to fail over if the device is in the Active state, which will cause a brief service disruption. The bigd process may also restart when sod is restarted. This will momentarily pause pool and pool member statuses. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Traffic Management Shell (tmsh) of the device group member with the recent management IP address change by typing the following command:

    tmsh

  2. Set the device as the synchronization leader of the device group to force the device to initiate the ConfigSync process using the following command syntax:

    modify /cm device-group device_trust_group devices modify { <device name> { set-sync-leader } }

    For example:

    modify /cm device-group device_trust_group devices modify { deviceA.com { set-sync-leader } }

  3. Perform a ConfigSync operation that synchronizes the management IP address change to the device group by typing the following command:

    run /cm config-sync to-group device_trust_group

  4. After running the ConfigSync process, you can check the synchronization status by typing the following command:

    show /cm sync-status

    The following output shows a successful synchronization status between a device group containing two members:

    ---------------------------------------------------------------------------------------------
CM::Sync Status
---------------------------------------------------------------------------------------------
Color    green
Status   In Sync
Summary  All devices in the device group are in sync
Details
         /Common/deviceA.com: connected (for 12910 seconds)
         /Common/device_trust_group (In Sync): All devices in the device group are in sync
         /Common/example_device_group (In Sync): All devices in the device group are in sync
  5. Log in to the tmsh utility of the device that received the ConfigSync, by typing the following command:

    tmsh

  6. Restart the sod process by typing the following command:

    restart /sys service sod

  7. Verify that the management IP address change was successfully synchronized to the device group peers, and that the device that was modified no longer appears offline, by using the following syntax:

    list /cm device <device name> { failover-state management-ip }

    For example:

    list /cm device deviceA.com { failover-state management-ip }

  8. Repeat steps 5-7 for each device group member that received the ConfigSync in step 3.
