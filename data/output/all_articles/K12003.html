Known Issue

This is the result of a known issue. The TMM time clock may be slow or fail to synchronize with the Linux host clock. This issue may occur when you make an adjustment to the host clock on the BIG-IP system.

The TMM process maintains a time clock and occasionally polls the Linux host clock to ensure that the times are synchronized. When the times are not synchronized, TMM attempts to adjust its clock to match the Linux host clock. Under normal conditions, TMM makes the time adjustment within an 18-minute period. However, in some circumstances the time adjustment may take longer. TMM uses a 32-bit integer to calculate the time offset from the host (in nanoseconds). For any time difference greater than 2 seconds (2,000,000,000 nanoseconds), TMM wraps the offset and may be unable to determine whether to step or skew its clock to match the host clock. This behavior may cause time adjustments to take longer than expected, and in some cases may prevent TMM from synchronizing its clock with the host time.

Note: This issue also occurs on CMP systems in which each TMM instance maintains its own individual clock and synchronizes with the Linux host clock as needed. As a result, the times maintained by TMM instances on a CMP system may vary by a small amount.

You may observe this issue in the following scenarios:

  • Running the tcpdump command on a BIG-IP interface or VLAN

    When running tcpdump on a BIG-IP interface or VLAN, TMM provides the timestamps for packets. When this issue occurs, the tcpdump timestamp does not match the system time.
  • Running an iRule that records TMM timestamps

    When a configured iRule records TMM timestamps, the syslog timestamps do not match the TMM timestamps.

F5 Product Development tracked this issue as ID 222082 (formerly CR111926) and it was fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

If you experience this issue and the TMM clock fails to synchronize with the Linux host clock, you can work around the issue by restarting TMM. To do so, type the following command:

Note: Restarting TMM will interrupt application traffic.

bigstart restart tmm

Note: F5 recommends that BIG-IP systems be configured to use a stable NTP time source. This configuration will prevent the need to adjust the OS clock by large amounts. In addition, NTP performs minimal clock adjustments, which will not cause TMM clock synchronization to exceed 18 minutes. For information about configuring NTP on the BIG-IP system, refer to K3122: Configuring the BIG-IP system to use an NTP server.
