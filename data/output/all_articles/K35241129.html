Description

When clients attempt to access a virtual server configured with a BIG-IP ASM/AWAF security policy they are blocked.
Review of application requests show the request was blocked with the following:
  • Violation  
    • HTTP protocol compliance failed
  • Occurrences
    • HTTP Validation > Check maximum number of headers
    • Details > Number of headers 21 exceeded maximum limit of: 20
      Note: The value for the detected number of headers may vary, however security policy maximum limit is set to 20 (default).
Environment
  • BIG-IP ASM/AWAF 
  • Security Policy
  • HTTP protocol compliance failed

Cause

The application security policy configuration setting for maximum HTTP headers was exceeded.
ID1051213 created to increase this value in future release.

Recommended Actions
  1. Log on to the BIG-IP ASM/AWAF Configuration utility (gui).
  2. Go to Security > Policy Building > Learning and Blocking Settings.
  3. Expand HTTP protocol compliance failed.
  4. Modify the Check maximum number of headers value to the required value for your application.
  5. Click Save.
  6. Click Apply Policy.

Additional Information

Browsers and web servers may increase the number of headers for HTTP sessions inadvertently causing the configured maximum headers protocol violation to be triggered.
  • Mozilla Firefox HTTP headers
  • Google Chrome HTTP headers

For example Chrome, Firefox and Edge periodically increase the number of headers they insert by default.
All include:
Sec-Fetch-Site: same-origin
Sec-Fetch-Mode: navigate
Sec-Fetch-User: ?1
Sec-Fetch-Dest: document

Chrome and Edge additionally include:
sec-ch-ua: "Google Chrome";v="93", " Not;A Brand";v="99", "Chromium";v="93"
sec-ch-ua-mobile: ?0
sec-ch-ua-platform: "macOS"
