Topic

F5 Network products come in a variety of hardware configurations. While many models have a significant amount of free disk space, some models, such as BIG-IP and 3-DNS switch appliances and server appliances that are equipped with a solid state disk, do not have enough free space to store a large tcpdump file.

You can perform a tcpdump on a system with minimal disk space, using one of the following processes:

  • Create a memory file system and write the tcpdump directly to memory.
  • Perform the tcpdump remotely through SSH and write the output to the client system.

Create a memory file system

To create and use a memory file system and write the tcpdump directly to memory, perform the following procedure:

  • Determine the amount of available free space.
  • Determine the maximum size that you can use for a memory file system.
  • Create the memory file system.
  • Perform a tcpdump and write the file to the memory file system.

Determine the amount of available free space

To determine the amount of available free space, perform the following steps:

  1. Type the following command:

    bigpipe ms

    The last line of output should appear similar to the following:

    mem pool total 773094105 mem pool used 3092080 mem percent used   0.40
  2. Subtract the mem pool used value from the mem pool total value.

    For this example, the amount of available free space is 770002025.

Determine the maximum size that you can use for a memory file system

The size of a memory file system is specified in 512KB blocks; therefore, the size you use for the memory file system should not exceed eighty percent of the available free space, divided by 512.

For example, if the available free space is 770002025.

Eighty percent of 770002025 is 616001620.

616001620 divided by 512 is 1203128 (when rounded to a whole number).

For this example, you can create a memory file system no larger than 1203128 512KB blocks.

Create the memory file system

To create the memory file system attached to the /mnt directory, type the following version-specific command:

All other versions:

mount_mfs -s <number> /mnt

Where <number> is the value equal to, or smaller than, the value you determined as the maximum size for the memory file system. This file system will remain until you unmount it or reboot the system.

For example, a common value is 200000, which creates a 100MB file system.

mount_mfs -s <200000> /mnt

Perform a tcpdump to the memory file system

To perform the tcpdump on the system and save it to the local memory file, perform the following steps:

  1. Run the tcpdump commands that you require, specifying the /mnt directory for writing files.

    For example:

    tcpdump -i eth0 -w /mnt/mytcpdump.bin

  2. Copy the file off of the system.

    Note: For specific instructions, refer to K175: Transferring files to or from an F5 Networks system.

  3. Unmount the memory file system, by typing following command:

    Important: All the information that is contained in this directory will be lost when you unmount the file system or reboot the controller.

    umount /mnt

Perform the tcpdump remotely through SSH

To use SSH to save the tcpdump remotely to the client's memory file, perform the following steps:

  1. Connect to the client system using SSH.

  2. Type the following command syntax:

    ssh <user>@<remotehost> 'eval $(which tcpdump) -c<packets>-s0 -w- -i interface' > <filename>

    Where:
    • <user> is specified as the user on the remote system.
    • <remotehost> is the hostname or IP address of the BIG-IP or 3-DNS.
    • <packets> is the number of packets you wish to capture.
    • <filename> is the name you want used for the tcpdump binary file.

    For example:

    ssh root@bigip1.askf5.com 'eval $(which tcpdump) -c10000 -s0 -w- -i internal' >mytcpdump.bin

    This command is executed on the BIG-IP or 3-DNS system, but writes the mytcpdump.bin output file to the client system.

Important: The tcpdump output is buffered. If you issue CTRL-C on the system from which you are running the commands, it will terminate SSH, not the remote tcpdump. This will result in an incomplete or useless tcpdump collection; therefore, it is important to wait for the tcpdump process to complete collecting the specified number of packets.
