Description

When TMOS or hardware identifies a packet as invalid or as not belonging to an existing connection it drops it, or rejects it, depending on LTM configuration. This causes that some attacks never reach the back-end servers, even when AFM is not provisioned. Device considers this type of traffic not legitimate, so it drops it without the need to reach AFM module.

However there are DoS vectors in AFM that match these type of packets as well, so if these packets never reach AFM module, why AFM still have these vectors? What can do AFM regarding to these type of packets?

Environment

  • BIG-IP AFM
  • Invalid/malformed packets

Cause

AFM DoS feature does not only provide a way to avoid attacks reaching the protected services, or BIG-IP itself, it also provides useful information that helps you to have a clear understanding about the state of the security in your environments. This information can be checked in DoS Dashboard or using CLI tools like tmsh. This allows you know what are the expected traffic, how your BIG-IP is handling it, how to tune your configurations, etc.

This is the reason why AFM provides information about DoS vectors that match packets handled even before they reach AFM module, because security administrators want to have as much details as possible about the traffic patterns. So for these type of packets AFM acts only as a monitoring tool.

Note that discarding unwanted traffic at early stages will save device resources, in this case these invalid packets are discarded in FPGA, basically when they hit the box.

Recommended Actions

None

Additional Information

It is expected to have stats increasing for these type of DoS vectors, and administrators will not be able to configure AFM to drop them based on any threshold.

As a result you can see in DoS Dashboard that for these type of packets are mitigated even if they are Not Detected by AFM as an attack, since detection threshold has not been exceeded:

However when detection threshold is exceeded you will see that AFM will show it in Dashboard, also a log will be created warning about it and mitigation will be still done:
