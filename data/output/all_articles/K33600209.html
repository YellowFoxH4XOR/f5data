K33600209: BIG-IP connection table includes an entry showing 127.1.1.1

Type

Published
2021-06-03
Updated
2023-02-21
Status
Legacy Content
Applies to

Source

Description

The BIG-IP connection table includes an entry showing connections from 127.1.1.1.

In the following example, the 127.1.1.1 connection table entry represents IP address assigned to linux kernel on tmm interface, 192.168.100.12 a Pool Member and 192.168.100.33 is the BIG-IP self IP address: 
127.1.1.1 <---->  192.168.100.12:45000  <----> 192.168.100.33 <----> 172.26.11.12:45000

ip -f inet addr show
....<snipped>....
15: tmm0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 9282 qdisc noqueue
    inet 127.1.1.1/24 brd 127.1.1.255 scope global tmm0   ------------------------------------>>>>>


Environment

  • BIG-IP LTM
  • You have a default route that uses a TMM pool

Cause
If you have a default route that uses a TMM pool (similar to example below), it has to route through tmm which causes linux host to install a route via tmm interface, instead of a vlan interface. 

net route /Common/route_default_0.0.0.0 {
    description none
    mtu 0
    network default
    partition Common
    pool /Common/route_example_pool
}
Recommended Actions

The behavior is expected. To avoid this behavior, you can use a gateway IP instead of a gateway pool.
