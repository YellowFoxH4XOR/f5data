Description

This article describes best practices and configuration steps to improve BGP convergence on an BIG-IP platform.

Environment

  • BIG-IP
  • TMROUTED
  • BGP

Cause

Default implementation of BGP on BIG-IP can be slow to recover after failover or peer disconnection and causes applications to timeout until recovery.

Recommendation

By default BIG-IP applies port lockdown on Self-IPs, which permits common management and data ports but blocks inbound TCP/179, preventing remote peers from initiating BGP sessions. Thus when connection fails, BIG-IP attempts to actively initiate a new connection to neighbors via its timers connect command. To reduce the time it takes for BIG-IP to retry its connection attempt we can adjust the timers connect to a lower value:

neighbor X.X.X.Y timers connect 5

This will prompt BIG-IP to keep retrying to connect to a disconnected peer every 5 seconds after connection failure. In addition, we can allow inbound TCP/179 so that BIG-IP will accept incoming connections from peers immediately once they attempt to establish a BGP connection.

Additionally, BIG-IP BGP does not enable BFD out of the box, so BGP relies solely on TCP session timeouts for neighbor-down detection (keep-alive and hold-time expiry timers). We can improve this by adding BFD for immediate link failure detection.
