K000160750: ASM, about “total_xml_memory_used” counter

Type
Support Solution
Published
2026-04-14
Updated
2026-04-14
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160750

Description

When the BIG-IP ASM system is configured with a large number of XML schemas or particularly large schemas, the XML processing engine may exhaust its memory. This condition causes the BIG-IP ASM system to lose its ability to process XML requests, leading to XML requests likely triggering meta character violations. Additionally, the system logs the following error message in the /var/log/asm file:

# egrep -h 'Cannot allocate.*more bytes for XML parser.*' /var/log/ts/bd.log* | sort -nrk 6 | head

 BD_XML|ERR  |May 01 10:14:48.308|0735|xml_validation.cpp:0266|Cannot allocate 29789819 more bytes for XML parser. current memory size 3212654567 (in bytes)
 BD_XML|ERR  |May 01 16:09:47.682|0735|xml_validation.cpp:0266|Cannot allocate 28985215 more bytes for XML parser. current memory size 3214354367 (in bytes)
 BD_XML|ERR  |May 01 11:01:19.785|0747|xml_validation.cpp:0266|Cannot allocate 28799039 more bytes for XML parser. current memory size 3211664630 (in bytes)

Environment

  • ASM module
  • XML memory used counter  

Cause

None

Answer/Recommended Actions

- The XML/JSON engine allocates memory as needed to process XML/JSON requests. The value of total_xml_mem_used increases as larger or more complex requests are processed, or as more concurrent requests are handled.

- This memory is not released after each request; instead, it remains allocated to optimize performance for future requests of similar size or complexity.

- This metric will generally increase over time in response to complex XML/JSON data, eventually reaching a steady state once the highest payload threshold for the current environment has been established.

- The memory is only released when the ASM process is restarted, or in rare cases, when XML/JSON profiles are modified and old parsers are purged (rarely happens)

- Therefore, it's normal to see total_xml_mem_used increase over the time.

# tmctl -i -s total_xml_mem_used,total_xml_max_mem asm_memory_util_stats 2>/dev/null
