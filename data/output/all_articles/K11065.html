Known Issue

This is the result of a known issue. The BIG-IP system ignores the TM.RejectUnmatched bigdb variable and fails to send a TCP RST in reponse to packets that do not match a virtual server or an existing flow.

Note: By default, the TM.RejectUnmatched bigdb variable is set to true and the BIG-IP system should send a TCP RST in response to packets that do not match a virtual server or an existing flow. If TM.RejectUnmatched is set to false, the system silently drops unmatched packets.

F5 Product Development tracked this issue as CR64147 and it was fixed in BIG-IP version 9.4.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or Link Controller release notes.
