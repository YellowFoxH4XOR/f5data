Description

After upgrading to 15.x or later, an iRule may generate "No HTTP header is cached - ERR_NOT_SUPPORTED" error and client may receive TCP RST pkt with rstcause text "iRule execution error".

 

Jan 29 12:13:13 bigip.local info tmm[11521]: Rule /Common/my_samesite_cookie_irule <HTTP_RESPONSE_RELEASE>: 10.1.1.60:33208: Parsed persist cookie name=BIGipServer/Common/http_pool
Jan 29 12:13:13 bigip.local err tmm[11521]: 01220001:3: TCL error: /Common/my_samesite_cookie_irule <HTTP_RESPONSE_RELEASE> - No HTTP header is cached - ERR_NOT_SUPPORTED (line 19)     invoked from within "HTTP::cookie attribute $persist_cookie insert "SameSite" "None""     ("none" arm line 2)     invoked from within "switch [string tolower $samesite_security] {          "none" {             HTTP::cookie attribute $persist_cookie insert "SameSite" "None"            ..."

Before upgrade (v14.x or earlier), same iRule was working fine and no RST was sent to client. Here are sample debug logs of working iRule.

 

Jan 29 12:57:04 bigip.local info tmm3[16821]: Rule /Common/my_samesite_cookie_irule <HTTP_RESPONSE_RELEASE>: 10.1.1.60:33968: Parsed persist cookie name=BIGipServer/Common/http_pool
Jan 29 12:57:04 bigip.local info tmm3[16821]: Rule /Common/my_samesite_cookie_irule <HTTP_RESPONSE_RELEASE>: 10.1.1.60:33968: Set-Cookie header values=

 

Environment

  • BIG-IP 15.0.0 or later.
  • Server response does not have HTTP Header. For instance, client sends HTTP/0.9 request (e.g., "GET /\r\n\r\n" only) to virtual server and backend server returns HTTP body only to BIG-IP.
  • Client-ssl virtual server uses an iRule which manipulates HTTP header (i.e., cookie header) in HTTP_RESPONSE_RELEASE event. Here is example configuration which can generate "No HTTP header is cached - ERR_NOT_SUPPORTED" error.
ltm virtual https_vs {
    destination 10.1.1.205:https
    ip-protocol tcp
    mask 255.255.255.255
    persist {
        cookie {
            default yes
        }
    }
    pool http_pool
    profiles {
        clientssl {
            context clientside
        }
        http { }
        tcp { }
    }
    rules {
        my_samesite_cookie_irule
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
}
ltm rule my_samesite_cookie_irule {
   when HTTP_RESPONSE_RELEASE {
      set persist_cookie_dbg 1
      set samesite_security "none"
      if { not [PROFILE::exists persist cookie] } {
         if { $persist_cookie_dbg } {
            log local0. "[IP::client_addr]:[TCP::client_port]: Exiting because there isn't a cookie persist profile on the VS"
         }
         return
      }
      if { [set persist_cookie [PROFILE::persist mode cookie cookie_name]] ne "" } {
         if { $persist_cookie_dbg } {
            log local0. "[IP::client_addr]:[TCP::client_port]: \$persist_cookie=$persist_cookie"
         }
      } else {
         set persist_cookie "BIGipServer[LB::server pool]"
      }
      if { $persist_cookie_dbg } {
         log local0. "[IP::client_addr]:[TCP::client_port]: Parsed persist cookie name=$persist_cookie"
      }
      switch [string tolower $samesite_security] {
         "none" {
            HTTP::cookie attribute $persist_cookie insert "SameSite" "None"
            HTTP::cookie secure $persist_cookie
         }
         "lax" -
         "strict" {
            HTTP::cookie attribute $persist_cookie insert "SameSite" $samesite_security
         }
         default {
            if { $persist_cookie_dbg } {
               log local0. "[IP::client_addr]:[TCP::client_port]: Invalid SameSite attribute value ''. Needs to be one of None|Lax|Strict"
            }
         }
      }
      if { $persist_cookie_dbg } {
         log local0. "[IP::client_addr]:[TCP::client_port]: Set-Cookie header values=[HTTP::header values {set-cookie}]"
      }
   }
}

 

Cause

Behavior changed in 15.0.0 via Bug ID 752858 fix. When no header response is returned by backend server (for example, server returns HTTP body only as an response for HTTP/0.9 request) and iRule tries to manipulate HTTP response header in HTTP_RESPONSE_RELEASE event, an error "No HTTP header is cached - ERR_NOT_SUPPORTED" may be thrown.

 

Recommended Actions

Try replacing HTTP_RESPONSE_RELEASE event to HTTP_RESPONSE event.

ltm rule my_samesite_cookie_irule-2 {
   when HTTP_RESPONSE {
      set persist_cookie_dbg 1
      set samesite_security "none"
		...

 

Note: Changes to iRule should be tested to determine impact to your specific environment. F5 also recommends that you review your current global iRule configuration, if any, to ensure that there are no conflicts or redundant configuration.
