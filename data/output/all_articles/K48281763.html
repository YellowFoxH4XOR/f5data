Known Issue

Kerberos Authentication may fail if the initial client request contains an Authorization header.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy is configured for Kerberos authentication.
  • The authentication request from the client prior the ''HTTP 401'' challenge response contains an Authorization header. The following example shows an initial POST request containing an Authorization header:

    POST /my.policy HTTP/1.1
    Accept: */*
    Content-Type: application/x-www-form-urlencoded
    Accept-Language: en-NZ
    Accept-Encoding: gzip, deflate
    User-Agent: Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 6.2; WOW64; Trident/7.0; .NET4.0E; .NET4.0C; .NET CLR 3.5.30729; .NET CLR 2.0.50727; .NET CLR 3.0.30729; MS-RTC LM 8)
    Host: hostname.domain.com
    Content-Length: 580
    Connection: Keep-Alive
    Cache-Control: no-cache
    Cookie: LastMRH_Session=62faea3d; MRHSession=4bb96540af900949b88ac0c062faea3d
    Authorization: Negotiate

Impact

Users are unable to access content that requires Kerberos authentication.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to access content that requires Kerberos authentication.
  • Kerberos Authentication fails and the system, again, presents the user with login windows.
