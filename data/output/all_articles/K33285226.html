Topic

You should consider using this procedure under the following conditions:

  • You have configured an XML profile on the BIG-IP ASM system to protect a web application.
  • You want to upload WSDL documents or XML schema files to the XML profile to validate the web application content.

Description

You can configure the BIG-IP ASM system to protect web applications that send XML content between the client and the server. By configuring an XML profile, you can use the BIG-IP ASM system to validate the XML content to ensure the content is well-formed and conforms to the defined schema or WSDL documents. To validate the XML content, you must upload the WSDL documents or XML schema files to the BIG-IP ASM system.

When you upload WSDL documents or XML schema files to the BIG-IP ASM system, note the following:

  • Ensure that the XML Schema Definition (XSD) files comply with the W3C XML schema specifications and point to the http://www.w3c.org/2001/XMLSchema namespace.
  • Ensure that the WSDL documents or XML schema files are in UTF-8 character encoding.
  • Do not upload schema files if your application contains built-in schemas.
  • If the schema file references other schema files, you must upload the main file first, then upload the reference files.
  • If you upload schemas that reference each other, you must upload the main schema twice - the first time as the main schema and a second time as the referenced schema.

    Note: If circular dependencies exist in the files, upload the schemas files in order. For example, if schema 1 references schema 2, which contains a reference back to schema 1, import schema 1, then schema 2, then schema 1 again. This creates a mapping between the files.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The workstation used to configure the BIG-IP ASM system can access the WSDL documents or XML schema files.
  • You have administrative access to the BIG-IP Configuration utility.

Procedures

Uploading WSDL documents or XML schema files to an XML profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Security > Application Security > Content Profiles > XML Profiles.
  3. Click the name of the XML profile.
  4. Click the XML Firewall Configuration tab.
  5. In the Configuration Files section, click Choose File and select the WSDL document (.wsdl) or XML schema file (.xsd) to upload.

    Note: If you are uploading a WSDL or XML schema file that references another WSDL or XML schema file, upload the referenced WSDL or schema file first.

  6. To upload the file, click Upload.
  7. If you want to upload a second WSDL or XML schema file that references the previously uploaded file, do the following:
    1. Click Choose File again and select the second file.
    2. In the Import URL field, enter the URL referenced in the second WSDL or XSD.
    3. Click Upload.

      For example:

      - For a WSDL, enter the value defined for the location attribute in the second WSDL, and click Upload
      - For an XSD, enter the value defined for the schemaLocation attribute in the second XSD, and click Upload

  8. To locate and use files referenced in the WSDL or XSD, ensure that you enable the Follow Schema Links setting.

    Note: When you use this setting, make sure the DNS server is listed in the DNS Lookup Server List (System > Configuration > Device > DNS). If you disable this setting and the uploaded file refers to other XML schemas, the system lists the referenced files in an error message at the top of the screen.

  9. If you imported a WSDL document as part of the configuration, perform these additional steps:
    1. For the system to verify the SOAPAction header, enable the Validate SOAPAction Header setting.

      The system automatically enables this setting when you upload a WSDL file.

    2. Review the Valid SOAP Methods; to disable any of them, clear the Enabled check box.
  10. To save the changes, click Update.
  11. To apply the changes, click Apply Policy and then to confirm click OK.
