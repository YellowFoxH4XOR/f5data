K000138338: APM is not sending emails

Type
Support Solution
Published
2024-02-09
Updated
2024-02-23
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000138338

Description

You are experiencing issue with sending emails with a token for 2FA using Email Agent in Access Policy.
The mails sent from the APM policy are not sent to the internal mail relay. You can see that the Big IP is sending a reset of the tcp connection. On the APM logs you see errors:

Jan 18 10:42:29 example.com info apmd[7392]: 01490007:6: /Common/Access_Policy:Common:12345aa: Session variable 'session.email.last.errmsg' set to 'message send failed. Operation timed out after 0 milliseconds with 0 out of 0 bytes received'

Environment

  • BIG-IP APM
  • Access Policy
  • Email Agent
  • Email with a token for 2FA

Cause

This is due to bug ID 419569 Email Agent- Allow transfer timeout configurable from Email agent UI.
Email fails if the server response is delayed more than 10 seconds. This is due to limitation, currently hardcoded to 10 seconds without option to set the value manually. 

Recommended Actions

Try to configure the email server to respond within 10 seconds response to meet APM limitation of 10 seconds timeout.
