Known Issue

The link state may erroneously be marked as offline.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP DNS (formerly known as BIG-IP GTM) deployment consists of two BIG-IP DNS devices.
  • Each BIG-IP DNS device is located in separate data centers that are connected through different links.
  • Each BIG-IP DNS device can access the link of the other BIG-IP DNS device.
  • The big3d service stops functioning on one or the other of the BIG-IP DNS devices.

Impact

The link associated with the BIG-IP DNS system that has a non-functioning big3d service is marked down on the device with the functioning big3d service.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you analyze network level probing by the BIG-IP DNS device that has a functioning big3d service, you notice that the device does not attempt to probe the link associated with the other BIG-IP DNS device that has the failed big3d service.
  • The BIG-IP DNS device with the functioning big3d service logs messages to /var/log/gtm that appear similar to the following example:

    alert gtmd[<pid>]: 011a500c:1: SNMP_TRAP: Box <device with no big3d service> state change green --> red (<device with no big3d service> on Unavailable)
    alert gtmd[<pid>]: 011a5004:1: SNMP_TRAP: Server /<partition>/<big-ip dns/gtm name> (ip=<device with no big3d service>) state change green --> red (No communication)
    alert gtmd[<pid>]: 011ab004:1: SNMP_TRAP: Data center /<partition>/<big-ip dns/gtm name> state change green --> red (No enabled servers available)
    notice gtmd[<pid>]: 011ae020:5: Connection in progress to <device with no big3d service>

  • DNS resolution by the BIG-IP DNS devices may be incorrectly redirected.
  • The BIG-IP DNS devices may report and synchronize different object statuses.

Workaround

To work around this issue, you can create a new data center that contains the affected link on the BIG-IP DNS device with the functioning big3d service. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility on the BIG-IP DNS device that has a functioning big3d service.
  2. Navigate to DNS > GSLB > Datacenters.

    Note: For BIG-IP GTM systems prior to 11.4.1, navigate to Global Traffic > GSLB > Datacenters.

  3. Click Create.
  4. In the Name box, type a name for the new data center.
  5. Click Finished.
  6. Navigate to DNS > GSLB > Links.

    Note: For BIG-IP GTM systems prior to 11.4.1, navigate to Global Traffic > GSLB > Links.

  7. Click Create.
  8. In the Name box, type a name for the new link object.
  9. In the router address box, enter the address from the affected link, 
  10. To add the address to the Router Address List, click Add.
  11. Select the previously created data center from the Data Center menu.
  12. In the Uplink Address box, enter the local self IP address that will be used to access the router.
  13. Configure the new link Health Monitors to use the monitor bigip_link by selecting the bigip_link monitor from the Available monitors list and moving it to the Selected list.
  14. Click Create.
