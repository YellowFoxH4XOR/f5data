Known Issue

This is the result of a known issue. The Content-Range HTTP header in 206 (Partial Content) responses served from the BIG-IP LTM RAM Cache is not compliant with RFC2616, section 14.16. The Content-Range HTTP header includes an equal sign ( = ) instead of a blank space, and a back slash ( \ ) instead of a forward slash ( / ). A response containing a non-compliant Content-Range HTTP header may cause issues opening linearized PDF files with an older legacy Acrobat plugin, such as versions 4 and 5.

A non-compliant Content-Range HTTP header returned by the BIG-IP system appears similar to the following example:

Content-Range: bytes=15-87\173

A compliant Content-Range HTTP header appears similar to the following example:

Content-Range: bytes 15-87/173

F5 Product Development tracked this issue as CR114400 and CR119956, and it was fixed in BIG-IP version 9.4.8 and version 10.1.0. For information about upgrading, refer to the BIG-IP LTM or WebAccelerator release notes.
