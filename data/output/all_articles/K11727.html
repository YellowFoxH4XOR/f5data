Issue

When a resource threshold is exceeded, the ARX system may not have enough resources to perform required functions. When the ARX system has insufficient resources to perform a function, multiple STATUS_INSUFF_SERVER_RESOURCES messages are logged that appear similar to the following example:

:BESPD-0-5-SHARE_UNAVAILABLE:: Storage Transition: [192.0.2.2] path [/VOL1] id [13411] (Status now unavailable); 4 probes failed over 78 seconds (durations: 4.8ms 1.3ms 0.6ms  22ms); Last probe status: [STATUS_INSUFF_SERVER_RESOURCES]
:TRANFS-4-4-MSG4:: get_space failed at \\192.0.2.5\acopia$10 - STATUS_INSUFF_SERVER_RESOURCES
:TRANFS-4-4-MSG4:: get_space failed at \\192.0.2.5\acopia$70 - STATUS_INSUFF_SERVER_RESOURCES

Additionally, the traplog will contain messages for any SNMP traps sent as a result of the resource threshold being exceeded.

Use the show fastpath resources and show health commands to determine the resource that has exceeded the threshold.

Note: For information about the show fastpath resources and show health commands, refer to the ARX CLI Reference Guide.

If necessary, contact F5 Technical Support to determine the reason for insufficient resources. When opening a support case, use the collect state command to collect the running state diagnostic information, and provide the created file.
