Topic

This article applies to BIG-IP ASM 13.x - 14.x. For information about other versions, refer to the following article:

  • K11914: Updating a BIG-IP ASM security policy when your website changes (10.x - 11.1.x)

You should consider using this procedure under the following condition:

  • You want to update the security policy when your application changes.

Description

When your company changes a web application that is protected by a security policy, you may need to update the security policy to account for entities that were modified or added to the application, such as URLs, file types, and parameters. You can configure the BIG-IP ASM system to automatically update the policy, or you can manually update it. If you know about a planned update to the web application in advance, you can check the policy to make sure that Learning Mode is set to Automatic. This way the the system detects the changes and adjusts the policy as needed with little administrator intervention required. You can also review the automatic changes that were made to the policy and make manual adjustments as required.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.

Procedures

Setting up automated policy building

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Ensure that the current edited policy is set to the security policy you want to update.
  4. Ensure that Enforcement Mode is set to Blocking.
  5. From the Learning Mode list, select Automatic.
  6. From the Auto-Apply Policy list, choose from the following options:
    • Select Real Time to have the system apply any policy updates within 2 minutes of registering the update.
    • Select Scheduled to have the system apply policy updates only on the selected days, hours or a combination of the two.
  7. From the Learning Speed list, choose from the following options:
    • Select Fast for low-security applications that require a quick customized policy.
    • Select Medium for most Internet applications.
    • Select Slow for applications with a high number of unique visitors per day and strict security requirements.
  8. Click Save to keep the configuration changes.
  9. Click Apply Policy.

When the web application changes:

  • The system detects that requests are being blocked due to the site update and immediately loosens the policy to maintain user access.
  • The system makes the necessary adjustments to the security policy, and temporarily puts new entities in staging, or adds wildcard entities.
  • The security policy re-stabilizes after the system analyzes sufficient traffic, from different sessions, over a period of time. Policy entities are moved out of staging and enforced as they meet the rule thresholds for stabilization.
  • After the changes are incorporated into the policy, the system removes any wildcards entities it added, takes the entities out of staging, and enforces the new policy elements.

Reviewing automatic changes made to the security policy

You can review policy revisions using the Traffic Learning screen to understand when and why the system changed the security policy.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Traffic Learning.
  3. Ensure that the current edited policy is set to the security policy you want to update.
  4. Review the Traffic Learning Summary section and add new entities to the policy as required.

Manual policy building

You can manually adjust the security policy as a result of site changes by adding file types, URLs, and parameters. If you do not know all the changes that have been made, you can loosen the policy to learn what changed:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Ensure that the current edited policy is set to the security policy you want to update.
  4. Set the Enforcement Mode to Transparent.
  5. Click Save.
  6. Click Apply Policy.
  7. Ensure traffic is going to the application.
  8. Click the Traffic Learning tab.
  9. Review the Traffic Learning Summary section and add new entities to the policy as required.
  10. When you have added the new entities, click the Learning and Blocking Settings tab and set the Enforcement Mode to Blocking.
  11. Click Save.
  12. Click Apply Policy.

Adding file types

You can manually add specific file types to the policy as needed, or you can add wildcard entities and let the system learn file types.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > File Types > Allowed File Types.
  3. Click Create.
  4. On the Allowed File Type Properties screen, select appropriate file type. For example, Wildcard.
  5. Type the file name.

    For example:

    *.gif

  6. Define the file type properties.
  7. If you want the system place the entity in staging, leave Perform Staging enabled. If you want the system to immediately enforce requests for the entity, clear the Perform Staging box.
  8. Click Create.
  9. Click Apply Policy.

Adding URLs

You can manually add URLs to the policy as needed, or you can add wildcard URLs and let the system learn the specific URLs.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.
  3. Click Create.
  4. In the URL section, define the URL properties, as follows:
    • From the menu, choose Explicit or Wildcard.
      • Explicit URL - Indicates that the URL name will be explicitly defined and contain no wildcard characters. For example, /index.html.
      • Wildcard URL - Indicates that the URL name will contain one or more wildcard characters; any URL that matches the wildcard expression is considered legal. For example, */wildcard/*.
    • From the menu, choose HTTP or HTTPS.
    • Type the name for the URL.
  5. If you want the system to place the URL in staging, leave the Perform Staging check box selected. When staging is enabled for a URL, the system logs learning suggestions to the Learning screen and does not block requests for the URL.
  6. Click Create.
  7. Click Apply Policy.

Adding parameters

You can manually add parameters to the policy as needed, or you can add wildcard parameters and let the system learn the specific entities.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Parameters > Parameter List.
  3. Click Create.
  4. On the Create New Parameter screen, select appropriate parameter type. For example, Wildcard.
  5. Type the parameter name.

    For example:

    [(U|u)]sername

  6. Define the parameter properties.
  7. If you want the system place the entity in staging, leave Perform Staging enabled. If you want the system to immediately enforce requests for the entity, clear the Perform Staging box.
  8. Click Create.
  9. Click Apply Policy.

Reviewing Traffic Learning

To review changes made to the security policy (including both manual and automatic changes), review the Traffic Learning screen.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Traffic Learning.
  3. Ensure that the current edited policy is set to the security policy you want to update.
  4. Review the Traffic Learning Summary section and add new entities to the policy as required.
