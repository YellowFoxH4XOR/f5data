Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP system is configured with route domains.
  • HTTP requests to the BIG-IP virtual server initiate from a non-default route domain.
  • HTTP requests processed by the BIG-IP virtual server include the X-Forwarded-For (XFF) header.
  • The XFF header IP address includes the route domain suffix (%<route domain number>).
  • You want to remove the XFF header IP address value route domain suffix, or you want the XFF value to contain the IP address without the route domain suffix, followed by the IP address including the route domain suffix. For example <IP address>, <IP address>%<route domain number>.

Description

The following procedures demonstrate how to create a custom iRule that modifies the HTTP request containing the XFF header in which the IP address value of the header includes a route domain suffix.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP Configuration utility.
  • The virtual server is configured with an HTTP profile.

Procedures

  • Creating and applying a custom iRule to remove the route domain suffix from XFF header values
  • Creating and applying a custom iRule that alters the XFF header value to contain the IP address without and with the route domain suffix

Creating and applying a custom iRule to remove the route domain suffix from XFF header values

The following procedure describes how to create a custom iRule that replaces the XFF value with the original IP address without the route domain suffix. For example an XFF value of 10.0.0.10%1 is replaced with the value of 10.0.0.10.

Note: If your servers rely on the XFF header for client tracking and you use the same IP address in multiple route domains where clients access the same servers, you cannot determine the route domain of the request from the server logs.

Impact of procedure: F5 recommends performing the following procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. Name the new iRule.
  5. Enter the following text in the Definition box:

    when HTTP_REQUEST {
      if {[HTTP::header exists X-Forwarded-For]}{
        log local0. "Original X-Forwarded-For header value  [HTTP::header X-Forwarded-For] actual client address [IP::client_addr]"
          set no_rdsuffix_ip [getfield [HTTP::header "X-Forwarded-For"] "," 1]
          HTTP::header replace "X-Forwarded-For" $no_rdsuffix_ip
          unset no_rdsuffix_ip
          log local0. "New X-Forwarded-For header value [HTTP::header X-Forwarded-For]"
      } else {
          HTTP::header insert X-Forwarded-For [getfield [IP::client_addr] % 1]
          log local0. "New X-Forwarded-For header value header [HTTP::header X-Forwarded-For]"
      }
    }

    Note: To obtain diagnostic information about the iRule actions, remove the # symbols proceeding the log local0. statements.

  6. Click Finished.
  7. Navigate to Local Traffic Virtual Servers > Virtual Server List.
  8. Click the name of the affected virtual server.
  9. Click the Resources tab.
  10. For iRules, click Manage.
  11. In the Available list, click the new iRule and move it to the Selected list.
  12. Click Finished.

Creating and applying a custom iRule that alters the XFF header value to contain the IP address without and with the route domain suffix

The following procedure describes how to create a custom iRule that sets the XFF value to contain the original IP address without the route domain suffix, followed by the original IP address with the route domain suffix. For example, an XFF value of 10.0.0.10%1 is replaced by the value of 10.0.0.10, 10.0.0.10%1.

Impact of procedure: F5 recommends performing the following procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. Name the new iRule.
  5. Enter the following text in the Definition box:

    when HTTP_REQUEST {
    if {[HTTP::header exists X-Forwarded-For]}{
    # log local0. "Original X-Forwarded-For header value [HTTP::header X-Forwarded-For] actual client address [IP::client_addr]"
    HTTP::header replace X-Forwarded-For "[HTTP::header X-Forwarded-For], [getfield [IP::client_addr] % 1]"
    # log local0. "New X-Forwarded-For header value [HTTP::header X-Forwarded-For]"
     } else {
    HTTP::header insert X-Forwarded-For [getfield [IP::client_addr] % 1]
    # log local0. "New X-Forwarded-For header value header [HTTP::header X-Forwarded-For]"
      }
    }

    Note: To obtain diagnostic information about the iRule actions, remove the # symbols proceeding the log local0. statements.

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. Click the name of the affected virtual server.
  9. Click the Resources tab.
  10. For iRules, click Manage.
  11. In the Available list, click the new iRule and move it to the Selected list.
  12. Click Finished.
