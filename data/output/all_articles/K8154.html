Topic

BIG-IP DNS (formerly BIG-IP GTM) Extended Application Verification (EAV) monitors verify applications running on remote servers.

Note: For information on importing importing a custom EAV monitor and other external files to the BIG-IP system, refer to: K13423: Importing external files to the BIG-IP system.

Note: You can find example custom EAV monitor scripts on BIG-IP devices in the /usr/bin/monitors directory named arg_example and sample_monitor.

    Before you deploy an EAV monitor for host server probing, you should be aware of the following considerations:

    • By default, BIG-IP DNS monitoring is rotated between all F5 devices that reside in the data center, including BIG-IP DNS systems, BIG-IP LTM systems, and BIG-IP Link Controller systems.

      Note: The term data center is meant to indicate the BIG-IP DNS configuration object that represents the top level of your physical network setup. The data center defines the servers (BIG-IP DNS systems, BIG-IP LTM systems, hosts, and routers) that reside at that location.

    • When an F5 device in the data center monitors a server object, the big3d agent running on the F5 device reports the server object status to BIG-IP DNS devices using the iQuery protocol.
    • If you configure an EAV monitor on a BIG-IP DNS system to monitor the host server application, all F5 devices that are configured in the same data center as the BIG-IP DNS device will attempt to monitor the host server application on a rotating basis. As a result, if the EAV monitor is not installed on an F5 device in the data center, the host server will be marked down when that F5 device attempts to monitor the application.

    To ensure that the host server is not incorrectly marked down by the EAV monitor, do one of the following:

    • Installing the EAV monitor on all F5 devices in the same data center as the BIG-IP DNS system

      You can import external files using the BIG-IP Configuration utility.

      Impact of procedure: Performing the following procedure should not have a negative impact on your system.

      1. Log in to the Configuration utility.
      2. Navigate to System > File Management.
      3. Click the tab for the file type that you want to import.

        For example, if you want to import an external monitor script file, click External Monitor Program File List.

      4. Click Import.
      5. Browse to the location of the external file type that you want to import, and then click Open.
      6. In Name, type the file name or select Overwrite Existing to overwrite an existing file.
      7. Click Import.

      Note: After you import the file, you can click Local Traffic in the Configuration utility to create the associated new configuration element based on the imported file.

    • Creating and assigning a prober pool for the host server

      Impact of procedure: Performing the following procedure should not have a negative impact on your system.

      1. Navigate to DNS > GSLB > Prober Pools.

        Note: For BIG-IP GTM versions prior to 12.0.0, navigate to Global Traffic > Prober Pools > Prober Pool List.

      2. Click Create.
      3. In Name, type a name for the prober pool.
      4. On the Load Balancing Method list, click method you want.
      5. Under Available, click the server(s) you want and then click Move left (<<) to assign members to the pool.

        Note: The order of the servers in the list can be important based on the load balancing method selected.

      6. Click Finished.

      Assigning the prober pool to a server

      Impact of procedure: Performing the following procedure will assign the configured prober pool to monitor the specified host server.

      1. Navigate to DNS > GSLB > Servers > Server List.

        Note: For BIG-IP GTM versions prior to 12.0.0, navigate to Global Traffic > Servers > Server List.

      2. Click the server name.
      3. From Prober Preference or Prober Fallback, for Specific Prober Pool, select the prober pool created in the previous procedure.
      4. Click Update.
