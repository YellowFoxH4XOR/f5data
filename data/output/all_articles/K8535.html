K8535: The Redirect Rewite feature incorrectly rewrites the Location header value when the protocol is HTTPS and is not specified in lower case

Known Issue

This is the result of a known issue. When the Redirect Rewrite setting is enabled in the HTTP profile, and the server sends an HTTP 302 Found redirect response where the protocol specified in the Location header is not in lowercase letters, the BIG-IP LTM incorrectly rewrites the protocol field.

For example, this issue can occur if the Redirect Rewrite setting is used to rewrite redirects from HTTP to HTTPS, and the server sends an HTTP 302 Found redirect response in which the protocol is specified in all uppercase letters. The output from this response will appear similar to the following example:

HTTP/1.1 302 Found
Location: HTTPS://site.domain.com/home.htm
Date: Fri, 09 Nov 2007
Server: Apache/2.0.55
Content-Length: 0

When the BIG-IP LTM receives the HTTP 302 Found redirect response, the BIG-IP system incorrectly rewrites the Location header, inserting an s character after the fourth character in the existing value. The resulting Location header contains an invalid URI that appears similar to the following example:

Location: HTTPsS://site.domain.com/home.htm

F5 Product Development tracked this issue as CR89873 and it was fixed in BIG-IP LTM version 9.4.4. For information about upgrading, refer to the BIG-IP LTM release notes.

This issue has been fixed in Hotfix-BIGIP-9.3.1-HF5, which has been issued for BIG-IP version 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.
