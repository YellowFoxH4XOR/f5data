Known Issue

This is the result of a known issue. The mcpd process crashes and produces a core file when a trunk whose name exceeds 46 characters in length is assigned to a VLAN.

Note: Any method that can be used to assign a trunk to a VLAN can trigger this issue.

Important: When this issue occurs, the BIG-IP system will also restart other daemons and will not process any traffic for a few seconds.

Once the BIG-IP system has returned on-line:

  • If the issue occurred while a new VLAN was being created, then the new VLAN will not have been created.
  • If the issue occurred while an existing VLAN was being edited, then the edited VLAN will not use the desired trunk.

Repeating the operation will trigger the issue again.

F5 Product Development tracked this issue as ID 224444 (formerly CR136248) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, APM, ASM, Edge Gateway, GTM, Link Controller, PSM, WebAccelerator, or WOM release notes.

Workaround

In order to avoid this issue, ensure that the names of your trunks do not exceed 46 characters in length.
