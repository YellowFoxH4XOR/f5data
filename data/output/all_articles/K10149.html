Known Issue

This is the result of a known issue. If the big3d process sends a corrupt request to mcpd, the mcpd daemon enters a continuous loop while generating individual request messages for the big3d process. When this behavior occurs, the mcpd process leaks memory, which can eventually lead to mcpd daemon heartbeat timeouts and system failover events.

Note: This issue is more likely to occur when the big3d process sends a large number of messages to the mcpd daemon. This issue has been known to occur in cases where BIG-IP GTM, Enterprise Manager, and F5 Monitoring Pack are communicating with the same big3d daemon.

F5 Product Development tracked this issue as CR122147 and it was fixed in BIG-IP versions 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP LTM and GTM release notes.
