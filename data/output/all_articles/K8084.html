Issue

The BIG-IP system does not allow a health monitor that has a wildcard destination service (*All Ports) to be associated with a pool containing one or more member with a wildcard destination service. If you attempt to associate a BIG-IP health monitor configured with a wildcard destination service with a pool containing one or more members with a wildcard destination service, the configuration is not updated with the new monitor instance, and an error message that appears similar to the following example syntax displays in the Configuration utility and the /var/log/ltm file:

01070622:3: The monitor <monitor_name> has a wildcard destination service and cannot be associated with a node that has a zero service.

The system displays the error because the BIG-IP system requires a specific service port to construct a monitor request. If neither the monitor definition nor the destination service definition specifies a port, the system cannot construct a valid request, and does not create the monitor instance.

Note: You may encounter this error message when attempting to associate a health monitor configured with a wildcard destination service to any object that references a wildcard service. On BIG-IP GTM systems, this includes both server objects that reference a virtual server with a wildcard destination service, and BIG-IP virtual server objects configured with a wildcard destination service.

If you encounter this error, you can resolve it by taking either or both of the following actions:

  • Define a service port for the monitor.
  • Define a service port for each object to which the monitor will be applied.
