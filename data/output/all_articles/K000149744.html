Description

When attempting to upgrade BIG-IP APM devices to higher version like 15.x, 16.x or 17.x, certain slots (e.g., slot 2, slot 3, and slot 4) may remain offline after the upgrade process.

SSH to the slot2 (or slot3 slot4), check the log /var/log/ltm, find the error errors such as:

err mcpd[<PID>]: 0107134b:3: (rsync: write failed on "/config/filestore/.snapshots_d/epsec_package_d/:Common:epsec-1.0.0-1622.0.iso_37732_1": No space left on device (28)

err mcpd[<PID>]: 0107134b:3: (rsync: connection unexpectedly closed (2367 bytes received so far) [generator]

err mcpd[<PID>]: 0107134b:3: (syncer /usr/bin/rsync failed! (3072) ()

err mcpd[<PID>]: 0107134b:3: (Couldn't rsync files for mcpd.

err mcpd[<PID>]: 0107134b:3: (rsync process failed.) errno(255) errstr().

Environment

  • BIG-IP APM
  • VPR with multiple blade.

Cause

The issue is caused by insufficient disk space in the configuration partition during the upgrade process. This is due to the presence of multiple unused epsec packages that occupy significant disk space.

Recommended Actions

The steps to fix the issue.

  1.  Rollback to original version.
  2. Follow K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system, remove the old / unused epsec packages.
  3. Upgrade to higher version again.
