Known Issue

The BIG-IP ASM Configuration utility does not display security policies.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system is running BIG-IP 11.5.0 to 11.5.4 HF1.
  • You restore a policy from policy history or by using the Policy Diff feature.
  • You upgrade your BIG-IP ASM system to a version affected by this issue.
  • You use the Configuration utility to view the configured security policies.

Impact

The Configuration utility does not display security policies.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you navigate to Security > Application Security > Security Policies > Policies List, the BIG-IP system does not display any security policies.
  • When you navigate to Security > Application Security > Security Policies > Policies Summary, the BIG-IP system lists security policies.
  • After you create a new security policy, the behavior does not change.
  • If you restart the BIG-IP services asm, http or tomcat, or reboot the device, the incorrect behavior continues.

Workaround

To work around this issue, you can correct the BIG-IP ASM database so the Configuration utility properly displays the security policies. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure should not have a negative impact on your system.

  1. For BIG-IP ASM devices that are configured as part of a synchronization group, ensure that the synchronization Sync-Type is set to Manual with Full Sync.
  2. Log in to the Configuration utility.
  3. Navigate to Device Management > Device Groups.
  4. Click the device group name that you used to synchronize the BIG-IP ASM device.
  5. Set Sync-Type to Manual with Full Sync.
  6. Click Update.
  7. Log in to the command line of the affected BIG-IP ASM device.
  8. Run the following script on the affected BIG-IP ASM device.

    perl -MF5::DbUtils -MF5::Utils::Rest -MF5::ASMConfig::Entity::Policy -e '$dbh = F5::DbUtils::get_dbh(); 
     $dbh->begin_work(); 
     $dbh->do("UPDATE PLC.PL_POLICIES a SET a.rest_uuid = \"\" WHERE a.rest_uuid IN ( SELECT rest_uuid FROM (SELECT rest_uuid FROM PLC.PL_POLICIES GROUP BY rest_uuid having count(*) > 1) b)");
     F5::Utils::Rest::populate_uuids(dbh => $dbh);
     $dbh->commit();'

  9. Synchronize the local device configuration to the synchronization device group.
