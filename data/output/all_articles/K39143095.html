Description

  • After loading a UCS file into a new device, and trying to load the configuration using tmsh load /sys config, you get an error similar to the one below:
    Unexpected Error: "Can't parse MCP message, can't read string value result { result_code 17236759 result_message "01070317:3: profile /Common/SSL_Profile_Name_ssl_profile's key and certificate do not match" result_warning <error> }
  • A profile by the name: "SSL_Profile_Name", mentioned in the above error, cannot be found on the configuration files bigip.conf of the BIG-IP and does not appear when listed with tmsh list /ltm profile client-ssl all-properties

Environment

  • When upgrading to version 13.1+
  • Configuration load
  • SSL profile
  • HTTPS monitor

Cause
After v13.1, a server side SSL profile is auto generated for the first https monitor instance created. This profile might not appear visible on the config files when upgrading with a UCS from lower versions. The profile uses the name of the monitor followed by "_ssl_profile". For example: HTTPS_Monitor_Name_ssl_profile.
K33244273: HTTPS monitors might share one SSL profile

Recommended Actions

To workaround the issue find the HTTPS monitor related, and remove it before loading the configuration. Alternatively, modify it, not to use an SSL profile. It can later be created again, after the configuration has loaded successfully.
