K000160052: ASM Sync Issue due to diskspace

Type
Support Solution
Published
2026-02-19
Updated
2026-02-19
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000160052

      Description

            The policy configurations doesn’t seem to sync to the HA devices even though automatic ASM sync is enabled

            You would encounter similar errors in the ASM(/var/log/asm) logs as well

            ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): Expected size of                                                /ts/var/sync/sync_1767162152_4e950c9bbb5cf62190eaae35caa50509_full_update (223332203) does not match actual size (152150016)

           ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::spawn_relay_handler): Error during 'sync_receive_file_part' while in                       sync recovery state.  Giving up.  State may be inconsistent with other peers

 

      Environment

         BIG-IP ASM

      Cause


         /var mountpoint has 100% disk utilisation 


     Recommended Actions
 

         ASM config sync needs to receive and write a full configuration which would be impacted due to the diskspace.

          Find and clear any unnecessary files stored in /var. The mentioned article can be followed for the process to clear the files https://my.f5.com/manage/s/article/K14403

         post that restart the ASM config server 

            #pkill -f asm_config_server

        Note: The above command should not cause any impact to your data plane 

        Wait for 30 seconds and see If your configurations are getting synced, if not you can initiate a manual sync as well once.
