Known Issue

This is the result of a known issue. The TMM leaks memory when processing multicast packets that are destined for the host subsystem. This can eventually cause the TMM to core.

This issue affects BIG-IP systems that are configured to process multicast IP packets, such as OSPF traffic. For example, when the OSPF routing module is enabled on the BIG-IP LTM, the system creates a special multicast listener in the TMM. When the system processes an OSPF Hello packet, the TMM passes the packet to the host subsystem and subsequently does not release the memory location for the packet.

Note: By default, the port lockdown feature blocks traffic that is not specifically destined for a BIG-IP traffic management object, such as a virtual server or NAT.

F5 Product Development tracked this issue as CR133528 and CR126771 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

This issue was also fixed in Hotfix-BIGIP-9.4.8-385.0-HF2 which was issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
