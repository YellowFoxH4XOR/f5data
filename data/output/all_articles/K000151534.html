K000151534: Managing IP prefix sets by API group or user roles

Type

Published
2025-05-27
Updated

Applies to

Source

Description

In F5 Distributed Cloud (XC) environments, administrators may need to delegate the ability to add or delete IPs/subnets within shared IP Prefix Sets. The current role-based access control (RBAC) system does not allow for object-level granularity on these permissions. Assigning roles such as ves-io-admin-role to the shared namespace grants full administrative rights over all shared resources, including all IP Prefix Sets, rather than limiting access to specific sets.


Environment

F5 Distributed Cloud (XC)


Cause

The RBAC model in F5 Distributed Cloud is designed at the namespace level and does not support restricting permissions to individual objects like specific IP Prefix Sets. Any user with write access to the shared namespace can modify all resources within that namespace.


Recommended Actions

- Assign users requiring management of Shared IP Prefix Sets a role with write access to the shared namespace (e.g., ves-io-admin-role).  

- Be aware that this permission allows modification of all shared resources, not just selected IP Prefix Sets.  

- There is currently no method to restrict write access only to certain IP Prefix Sets; permissions are applied at the entire resource type level within the namespace.  

- For more granular control, consider submitting a feature request for object-level RBAC or custom API groups via F5’s official channels.  

- F5 has indicated plans for custom API groups assignable to roles in future releases, which may provide improved granularity. However, true object-level RBAC is not currently available and would require significant platform changes.  

- Limit assignment of write-access roles in the shared namespace strictly to trusted administrators until finer controls are available.
