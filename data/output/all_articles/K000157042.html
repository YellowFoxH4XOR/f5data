K000157042: "IPV6 is not supported in 17.1.X and lower versions" error when upgrading to 17.1.3.x with IPv6 servers or hostnames in TACACS servers

Type
Support Solution
Published
2025-10-16
Updated
2025-10-21
Source
https://my.f5.com/manage/s/article/K000157042

Description

When upgrading to v17.1.3, you may see the below error message in the LTM logs:

err mcpd[6073]: 01071e26:3: IPV6 is not supported in 17.1.X and lower versions

 

Environment

  • BIG-IP
  • Upgrading to 17.1.3.x from an earlier version
  • TACACS+ enabled with hostnames or IPv6 addresses configured in the server list

Cause

This relates to a change introduced in 17.1.3 where validation was added to check for IPv6 addresses in TACACS+ configurations.

This issue is being tracked as ID2137861, and is a regression introduced by new validation intended to prevent a customer from entering an IPv6 address into the tacacs configuration's server field. This validation was added because the version of the underlying Linux TACACS+ package (pam_tacplus v1.2.9) did not support IPv6 addresses although both Management UI and TMSH allowed entering an IPv6 address to be configured. Without this validation, an IPv6 address used in the tacacs configuration will be accepted but may result in failed logins with messages in /var/log/secure such as:

err httpd[5948]: pam_tacplus: skip invalid server: 2001::1001:1001 (invalid port: no digits)

The validation can erroneously identify DNS hostnames as IPv6 addresses and throw the validation error mentioned in the description above.

An example TACACS+ configuration in the /config/bigip.conf file with an IPv6 address that will trigger the validation error: 

 auth tacacs /Common/system-auth {
    protocol ip
    servers { 2001::1001:1001 }
    service ppp
} 

The following TACACS+ configuration in the /config/bigip.conf file with a hostname instead of an IPv4 address will also trigger the validation error: 

 auth tacacs /Common/system-auth {
    protocol ip
    servers { bigip.example.com }
    service ppp
}

 

Impact

  • Error message observed in LTM logs "IPV6 is not supported in 17.1.X and lower versions"
  • Unable to load the configuration after an upgrade to 17.1.3
  • Potentially MCPD timing out as a result whilst trying to load configs after the first reboot into the new volume

 

Workaround

Do not use hostnames or IPv6 addresses when configuring the list of TACACS+ servers. Instead replace with an IPv4 address to allow for the configuration to be validated and loaded successfully.

Alternatively, upgrading to v17.5.1.x should resolve this, as v17.5.1 introduced support for IPv6 for TACACS+ via ID740258 with pam_tacplus v1.3.2
