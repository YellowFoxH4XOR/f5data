Description

When installing an upgrade, you encounter the following error:

# tmsh show /sys software status
-------------------------------------------------------------------------------------------------------
Sys::Software Status
Volume  Slot  Product   Version   Build  Active                                 Status  Allowed Version
-------------------------------------------------------------------------------------------------------
HD1.1      1   BIG-IP  16.1.2.1  0.0.10     yes                               complete              yes
HD1.1      2   BIG-IP  16.1.2.1  0.0.10     yes                               complete              yes
HD1.2      1   BIG-IP  16.1.2.2  0.0.28      no                               complete              yes
HD1.2      2   BIG-IP  16.1.2.2  0.0.28      no  failed (See /var/log/liveinstall.log)              yes

Installation on the primary blade completes successfully but on secondary blade(s) it fails with status "failed (See /var/log/liveinstall.log)". 

The /var/log/liveinstall.log on the secondary blade(s) shows an error similar to the following:

# ssh slot2 tail /var/log/liveinstall.log
info: >----
info: Configuration save retries remaining: 1
error: status 256 returned by command: F5_INSTALL_SESSION_TYPE=install tmsh -f save sys ucs /var/tmp/TBjNMTjRoX.ucs
info: >++++ result:
info: Saving active configuration...
info: Thrift: Sat May 28 01:13:26 2022 TSocket::open() getaddrinfo() <Host: 127.3.0.2
info:  Port: 9090>Name or service not known
info: Error during config save.
info: Unexpected Error: UCS saving process failed.
info: >----
Terminal error: See /var/log/liveinstall.log
*** Live install end at 2022/05/28 01:13:27: failed (return code 2) ***

Note that "Host" and "Port" appear in two separate lines.

Environment

  • BIG-IP 16.0.0 and above
  • Multi-bladed (with at least 2 blades) VIPRION chassis or vCMP guest
  • AVR provisioned
  • Scheduled report configured
  • Install a upgrade

Cause

Bug ID 1111189

Recommended Actions

You can workaround the issue by removing all AVR scheduled-reports, performing the upgrade, and then re-defining the AVR scheduled-reports as necessary.

  1. Verify that you have AVR scheduled report configured. Run the following command, which displays the name of any scheduled report configured.

    # tmsh list /analytics | grep scheduled-report
    analytics http scheduled-report myReport {

    If the command does not produce any output, you do not have any scheduled report configured, and this article does not apply.
     
  2. Note the configuration of the scheduled reports and store them in a temporary location.

    You can view the configuration of scheduled reports in the Configuration Utility under Local Traffic > Profiles > Analytics > Scheduled Reports.

    Alternatively, use the CLI command:
    # tmsh list /analytics
     
  3. Remove all scheduled reports
     
  4. Delete the previously failed installation if necessary, and perform the upgrade again.
     
  5. Boot to the new volume, and re-add the scheduled reports
