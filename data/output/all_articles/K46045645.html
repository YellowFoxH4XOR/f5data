Description

When submitting an automatic FCP report from BIG-IQ to F5 an error appears:
"Error: Report submission failed: curl (35) Unknown SSL protocol error in connection to api.f5.com:443. It occurred at (date / time)"

 

 

 

 

 



Scheduled reports may also show an error message:
"Report generated but submission failed for "License key" (task) Report failed. Please provide a valid certificate"

 


 

 

 

 

Environment

  • BIG-IQ
  • Flexible Consumption Plan (FCP)
  • LOAD/Catalog (CAT) license offerings

Cause

In some cases, the certificate in the license file can be corrupted or there could be an HTTPS connectivity issue between the BIG-IQ and api.f5.com.

Recommended Actions

Verify the license on the BIG-IQ then check connectivity between the BIG-IQ and api.f5.com.

Manually verify the CAT license on the BIG-IQ:

  1. Activate a individual license offering within the CAT using the manual option per K15420056: Manually activate CAT license offering for FCP on BIG-IQ. If this is successful, that indicates that the license isn't corrupt and that there's likely a connectivity issue between the BIG-IQ and api.f5.com. Proceed to the next step.

Test Connectivity to api.f5.com from the command line of the BIG-IQ:

  1. Run "telnet api.f5.com 443". Does it connect?
  2. Test the SSL handshake. Run "openssl s_client -connect api.f5.com:443". It should return the peer certificate. If it returns the following results, contact your local network team to allow this traffic.

    ---
    no peer certificate available
    ---
    No client certificate CA names sent
    ---
    SSL handshake has read 0 bytes and written ### bytes

Once connectivity is restored, test the reporting option again, by adjusting the scheduled reporting window.

  1. On the BIG-IQ, navigate to Devices tab > License Management > Reports > Schedule.
  2. Ensure "automatically submit report to F5" is selected then adjust the Day/Time to run the report today in a couple of minutes.
    Note: Though it lists the correct time zone, this report only runs on Pacific time (BugID 1087253).
