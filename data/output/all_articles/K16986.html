Known Issue

Kernel routes may stop advertising when you modify a virtual server netmask.

This issue occurs when all of the following conditions is met:

  • You have enabled dynamic routing protocols on the BIG-IP system.
  • You have enabled route advertisement for a BIG-IP virtual address.
  • You have modified the netmask for the virtual server associated with a virtual address route advertisement enabled.

Impact

Affected BIG-IP virtual addresses are no longer advertised and are redistributed to other routers.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Immediately after changing the netmask, you can no longer view the virtual address using the imish show ip route command.

    The following example is sample output from the show ip route command on a BIG-IP system with a network type virtual server, 1.1.1.0/24. The virtual address 1.1.1.0 has kernel route advertisement enabled, which you can see from the K marking the beginning of the line for 1.1.1.0/24:

    tmsh imish -e "show ip route"

Workaround

To work around this issue, you can restart the tmrouted process after changing an affected virtual server netmask. To do so, perform the following procedure:

Impact of workaround: The tmrouted process is responsible for routing table management. While it is down, the Traffic Management Microkernel (TMM) cannot learn or advertise routes.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Restart the tmrouted process by typing the following command:

    restart sys service tmrouted
  3. Confirm that your virtual address is now correctly advertised by typing the following command:

    imish -e "show ip route"
