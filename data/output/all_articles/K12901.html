Known Issue

Users that have numeric usernames that begin with the number zero may fail SSO authentication. This failure occurs because the BIG-IP system stores the username as an octal number rather than the integer that was specified as the username. The value is stored in the session.sso.token.last.username SSO variable. For example, if the username is 010, the session.sso.token.last.username variable stores the username value as 12.

This issue occurs when all of the following conditions are met:

  • User attempts to access a resource that uses SSO credential mapping
  • User's username is entirely numeric
  • User's username begins with the number zero (0)

Impact

Affected users will be unable to authenticate.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Affected users will be unable to authenticate
  • Affected users will receive the following error message even when they have supplied a valid username:

    The username or password is not correct. Please try again.

Workaround

To work around this issue, you can change the SSO mapping method to use the session.logon.last.username variable. The session.logon.last.username variable will store the information that is supplied during logon without converting it to its octal value. To do so, perform the following procedure:

Changing the variable used by SSO credential mapping

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Policy >> SSO Configurations.
  3. Click on the name of the affected SSO configuration.
  4. In the SSO Method Configuration section, change the Username Source variable to the following:

    session.logon.last.username
  5. Click the Update button.
