Description

When using command line to show connections of BIG-IP system, for example:

show sys connection max-result-limit <max>

The number of connections displayed does not reach the maximum number limited by max-result-limit parameter, even if the current number of connections of the BIG-IP exceeds the max-result-limit.

For example:

Using i5600 device with 1x Quad-Core Intel Xeon 3.7 GHz (total 8 hyperthreaded logical processing cores), so this BIG-IP has 4 TMM processes. When making 2000 connections with this BIG-IP, show sys connection with the default command argument, max-result-limit of 1000, will only display up to 686 link records.
 

Environment

BIG-IP
 

Cause

This is a designed behavior.

In the multi-tmm system, the max-result-limit(default value 1000) would be divided to the limitation to each tmm using this formula:

result_limit = (result_limit + 7) / 8 * 11;
result_limit /= tmm_total_active_npus;

The input result_limit is the max-result-limit parameter, and tmm_total_active_npus stands for the active tmm processes number. And the final result_limit is the per TMM result limit.

As the example above, i5600 with 4 tmm processes, using defaut max-result-limit 1000: The result_limit is 343. Which means BIG-IP would get no more than 343 connections from each tmm to show.

The connections of BIG-IP are from a linux client, and the linux kernel(after 4.2) prefers to use even number source ports to connect to BIG-IP. As the default DAG algorithm, the connections would hash to the even number of tmm processes. So only 2 tmms would be selected to process these connections.

Since the BIG-IP gets no more than 343 connections from each tmm to show, and only 2 even number tmms have connections, the command excuting result would display no more than 686 connections, less than the 1000 connection limit as default.

 

Recommended Actions

None

 

Additional Information

Regarding the Formula Explanation:

  1. scaling the input result_limit up 37.5%, then divided by the tmm number. That means a little more connections could be got from a tmm process to show, In case the connectons are unbanlance in tmm processes. 
  2. the reason for adding 7 before dividing is that integer division truncates the result downward. Without adding 7, the max-result-limit less than 8 would lead result_limit to 0, and no connections can be shown.
