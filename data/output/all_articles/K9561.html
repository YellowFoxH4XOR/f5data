Known Issue

This is the result of a known issue. When configuring the destination address of a virtual server by specifying its Fully Qualified Domain Name (FQDN) instead of the IP address, the cached IP address for the FQDN does not change even if the virtual server is removed and recreated.

The Sun Java Virtual Machine (JVM) used by the Configuration utility caches the results for DNS name lookups indefinitely to prevent DNS spoofing attacks.

Note: For more information, refer to the following document. The following link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge:

http://java.sun.com/j2se/1.4.2/docs/api/java/net/InetAddress.html

F5 Product Development is tracking this issue as ID 247197 (formerly CR111617). This issue does not affect BIG-IP versions 10.1.0 and later because the Sun JVM versions used by them cache the DNS lookup results for 30 seconds by default.

Workaround

The number of seconds that the Sun JVM will cache DNS lookups is configurable. You can work around this issue by using a text editor to modify the cache timeout value. To do so, perform the following procedure:

  1. Using a text editor, open the /usr/java/j2re/lib/security/java.security file.
  2. Find the following line located near the bottom of the file:

    #networkaddress.cache.ttl=-1
  3. Change this line to remove the comment ( # ) symbol and increase the value to an appropriate number of seconds to cache each lookup result.

    For example:

    networkaddress.cache.ttl=60

    This change will cause the system to only cache IP addresses for 60 seconds. A larger value may also suffice, and reduce the burden of repeated DNS lookups on the BIG-IP system.

    Important: F5 does not recommend setting this value to 0 (caching disabled), as it prevents an excessive number of DNS queries from being made as you navigate through the Configuration utility.
  4. Restart the tomcat process by typing the following command:

    bigstart restart tomcat4

Important: You must reapply this workaround after upgrading.
