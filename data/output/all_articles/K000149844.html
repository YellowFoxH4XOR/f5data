K000149844: SSH/SFTP connections fail through TCP Load Balancer

Published
2025-02-18

Description

This article addresses an issue where no connection is established or logged when using the TCP Load Balancer.

Environment

  • Multi-Cloud App Connect
    • TCP Load Balancer

Cause

Compatibility between the protocol used by the client and origin and the configuration of the TCP Load Balancer is critical.

The connection cannot be established if there is a protocol mismatch between the TCP Load Balancer and its origin pool.

Recommended Actions

  1. Review the protocol being used between the client and origin.
  2. Ensure the configuration of the TCP Load Balancer matches the protocol expectations:
    1. Example :
      If using SSH/SFTP as the protocol, and the TCP Load Balancer is configured with TLS over TCP, the connection will fail because SSH/SFTP requires end-to-end encryption.
  3. Adjust the configuration:
    1. Change the TCP Load Balancer setting "Load Balancer Type" to just 'TCP' without certificate.
    2. Disable SNI on the TCP Load Balancer.
    3. Disable TLS on the origin pool..
    4. This ensures compatibility, as SSH/SFTP protocols perform their own encryption and do not require additional TLS wrapping.

Additional Information

By design, SSH/SFTP cannot be proxied.  Attempting the proxy SSH/SFTP traffic, as is implemented by a TCP LB with Certificate and Origin Pool with TLS enabled, breaks the end-to-end encryption of the protocol.
