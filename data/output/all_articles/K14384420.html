Description

Messages similar to the following appearing in /var/log/ltm for each iAppsLX package, while saving a UCS file:

info iAppsLX_save_pre[25624]: Exporting: f5-iappslx-access-saml-sp - /var/config/rest/iapps/f5-iappslx-access-saml-sp
err  iAppsLX_save_pre[25624]: basicRestJavadQuery Error on request(400): POST /shared/iapp/build-package {"appName":"f5-iappslx-access-saml-sp"}

Note: The first message is expected, the second (error) message is not.

Resulting UCS file does not contain iAppsLX packages.

Environment

  • 13.1.5, 14.1.4.6, 15.1.5.1, 16.1.2.2, or later version in those branches
  • iAppsLX packages installed
  • UCS save

Cause

Bug ID 1079817: Java null pointer exception when saving UCS with iAppsLX installed

Recommended Actions

Upgrade to a version where ID 1079817 is fixed.

The iAppsLX packages will be missing and must be reinstalled after upgrade. This is because the iAppsLX packages will not be included in the UCS that is saved and installed to the destination software volume during the upgrade. This will not be a problem when upgrading from a version with the fix, to another version with the fix.

Additional Information

iAppsLX_save_pre is a Python script which runs during a UCS save and utilises the REST API to package the installed iAppsLX packages into an RPM file.

Loading a UCS file without the iAppsLX packages may require re-installation of the missing iAppsLX packages. This can be achieved via the GUI at iApps >> Package Management LX, or by using the REST API.

If an iApp is no longer available/installed, you may see a message similar to the following when saving a UCS:

info iAppsLX_save_pre[25624]: Skipping f5-iappslx-access-saml-sp iapp package that does not have iapp path: /var/config/rest/iapps/f5-iappslx-access-saml-sp
