K000092395: HTTP Health Check monitoring is not working for HashiCorp pool members

Type
Support Solution
Published
2022-10-11
Updated
2022-10-18
Source
https://my.f5.com/manage/s/article/K000092395

Description

Configuring the default "HTTP" or "HTTPS" monitor objects may have failed results (DOWN status) when assigning to the HashiCorp pool member.

 

 Environment

  • BIG-IP LTM
  • Need to have "HTTP-based" monitor on pool members
  • All pool members are working as HashiCorp members as "Active/Standby"
  • The Active pool member responds back with "200" status code
  • All the Standby members respond back with "473" status code

 

 Cause

In normal scenarios, when you want to monitor HTTP-based pool members, you can use the simple "HTTP" or "HTTPS" monitor. Both the "HTTP" and "HTTPS" monitor objects work as HTTP1/1 by default, these monitor types could not monitor the HashiCorp pool members properly since HashiCorp work based on "HTTP/2" by default. So, using the default "HTTP" or "HTTPS" monitors  could always fail.

 

 Recommended Actions

You can create your desired monitor object, based on the below suggested conditions. The most Important section is choosing "HTTP/2" as monitor type. Other parameters of the health monitor could be left default or could be modified based on your configuration requirement. For example, below is the monitor settings.

 

  • Type: HTTP/2
  • Parent Monitor: http2
  • Send String: GET /v1/sys/health\r\n
  • Receive String: 200
  • Receive Disable String: 473
