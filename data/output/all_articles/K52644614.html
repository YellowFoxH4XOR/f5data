Topic

You should consider using this procedure under the following conditions:

  • Your application uses positional arguments in the URL instead of string/value pair parameters.
  • You want to create positional parameters for a URL.

Description

The URL query string is a part of the URL that allows the resource to perform some action, such as performing a search. The query string most often contains parameters that the client uses to pass user input to the web application, enabling you to perform actions like writing to a database. The appearance of a parameter may vary depending on the URL format. Common uses are as follows:

  • Standard URL format: For standard URLs, the parameters follow a question mark (?) and consists of a name and value pair separated by an equal sign (=). For example, id=1234.
  • Clean URL format: Clean URLs, sometimes referred to as RESTful URLs, improve the readability of the URL by obscuring the details of the underlying web application. Clean URLs are those in which the parameter name is not present in the request but in which the values are embedded in URL between slashes (/).

Starting in BIG-IP 14.0.0, you can configure positional parameters to represent parameter values in clean URLs. Creating positional parameters for a URL allows you to perform additional actions for the parameter, such as disabling a specific attack signature.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.

Procedures

Creating positional parameters for a URL

To create a positional parameter for a URL, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.
  3. Select Create.
  4. For Create New Allowed URL, select Advanced.
  5. For URL select Wildcard.
  6. Select the Positional Parameters check box.
  7. For URL with Positional Parameters, select HTTP or HTTPS.
  8. To add a path segment, select Add Segment and, in the pop-up window, select Text and enter the name of the path segment without slashes (/) in the box (for example, path), and then select OK.
  9. To create a new parameter or choose an existing parameter, select Add Segment and perform the following steps, as appropriate:

    To create a new parameter:

    1. In the pop-up window, select Parameter and select Add new parameter.
    2. For Name, enter the parameter value.
    3. For Wildcard Expression, use fnmatch syntax or leave the value as the default asterisk (*) character.
    4. Select OK.

    To choose an existing parameter:

    1. In the pop-up window, select Parameter, select Select parameter, and for Name, select an existing parameter.
    2. Select OK.
  10. Repeat steps 8 and 9 for each path segment and parameter to finish configuring the URL with Positional Parameters.
  11. Define the remaining URL options as needed.
  12. Select Create.
  13. Select Apply Policy.

Note: Check the Wildcards Order tab to make sure the security policy has the right URL order to avoid any conflicts with URL matching. This is important since the wildcard matching strategy is first-match, starting from the top of the list.

Configuring the positional parameter object

After you create the positional parameters for the URL, you can configure the parameter object as needed. For example, you may want to disable a specific attack signature for the parameter. To configure the positional parameter object, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Parameters > Parameter List.
  3. In the Parameter Name column, select the positional parameter that you created in the previous procedure.
  4. Configure the parameter options as needed.

    For example, to disable an attack signature for the parameter, select the Attack Signatures tab and select the check box for the signature you want to disable.

  5. Select Update.
