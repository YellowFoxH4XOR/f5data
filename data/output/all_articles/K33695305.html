Known Issue

The Traffic Management Microkernel (TMM) stalls and does not process the queued connection on pool state transition.

This issue occurs when all of the following conditions are met:

  • Persistence is configured on the virtual server.
  • Slow ramp is configured on the pool.
  • Connection queuing is configured on the pool.
  • Connection limiting is configured on the pool member.
  • The pool member is disabled/down, the connection is enqueued to the pool member, and the pool member is re-enabled/up.

Impact

The queued connection to the virtual server/pool member on the affected TMM will remain in that state until the connection is terminated, or the client shuts down the connection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In certain situations, TMM may not process all connections ordered in a configured connection queue if the relevant pool member has been disabled/down, the connection is enqueued, and the pool member is re-enabled.
  • Any additional connections ordered behind the prior queued connection will also remain queued.

Workaround

To work around this issue, perform the following tasks:

  • Do not use persistence if the virtual server supports Clustered Multiprocessing (CMP) if a single pool member is used in the pool.
  • Disable the Slow Ramp Time option within the pool.
