Known Issue

Windows phones may trigger a false positive match for BIG-IP ASM attack signature 200021071.

This issue occurs when all of the following conditions are met:

  • A BIG-IP ASM policy has the following attack signature enabled:

    200021071 ( Automated client access "lwp")  

  • A Windows phone makes a request with a user-agent string that appears similar to the following example:

    User-Agent: Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1; Trident/5.0; XBLWP7; ZuneWP7)

Impact

Windows phones may trigger a false positive match for BIG-IP ASM attack signature ID 200021071.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H387629 on the Diagnostics > Identified > Medium screen.
  • Violations may be reported for attack signature ID 200021071.
  • If the security policy is set to block violations for attack signatures, requests from Windows phone clients may be blocked.

*The affected attack signature ID 200021071 is removed from the system and replaced with attack signature ID 200021091 that has the updated rule.

Workaround

To work around this issue, you can disable the affected signature and replace it with a user-defined attack signature. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Options > Attack Signatures.
  3. Click Create.
  4. Define a Name for the custom replacement signature.

    For example:

    ID376197-Replacement-Sig

  5. In the Systems section, under the Available Systems menu, select the System Independent value.
  6. To move the System Independent value to the Assigned Systems list, click the << button.
  7. From the Attack Type menu, select Non Browser Client.
  8. In the Rule area, type the following value:

    headercontent:"lwp"; nocase; pcre:"/^User-Agent:.*?\blwp\b/Hmi";

  9. Click Create.
  10. Navigate to the Application Security > Attack Signatures > Policy Attack Signatures menu.
  11. Expand the Custom Filter by clicking the triangle next to Filter.
  12. In the Signature ID field, enter the following value:

    200021071

  13. Click Go.

    Attack signature ID 200021071 displays in the Policy Attack Signatures list below the filter.

  14. Clear the Enabled box.
  15. Click Save.
  16. Clear the value from the Signature ID field.
  17. Enter the value from step 4 into the Containing String field.
  18. Click Go.

    The previously-created attack signature displays.

  19. Ensure that the signature is set to Enabled.
  20. Click Save.
  21. To commit the changes to the active security policy, click Apply Policy.
