K000149172: OCSP Status Monitoring fails when DNS Responder forward zone required

Type
Support Solution
Published
2025-01-02
Updated
2025-01-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000149172

Description

OCSP Status Monitoring (required for OCSP Stapling) may fail when BIG-IP is required to connect to an internal DNS server.

Environment

  • BIG-IP
  • OCSP Status Monitoring configured
  • OCSP Responder points to a CNAME record
  • DNS resolver configured with a forward zone for OCSP responder hostname
  • Limited access to internet from BIG-IP
    • Specifically, if BIG-IP is not able to connect to arbitrary DNS nameservers

Cause

When the DNS Resolver receives a CNAME record in a response, it always tries to resolve the new target by recursing from root nameservers even if the responding nameserver includes an A or AAAA record in the response. This is a defense against cache poisoning.

For example, if the OCSP responder is "ocsp.example.com" which is a CNAME to "ocsp.dc2.example.net", a recursing cache nameserver will typically respond with something like the following:

ocsp.example.com     60 IN CNAME ocsp.dc2.example.net
ocsp.dc2.example.net 60 IN A     192.0.2.37

When DNS Resolver on BIG-IP receives this record, it will try to resolve ocsp.dc2.example.net even though it is included in the response. If a Forward Zone is configured for the DNS resolver with "ocsp.example.com" or "example.com" it only affects the initial lookup, and this will try to recurse from the root namesevers. If those are unreachable, or if any others in the chain down from the root are unreachable, it will fail.

Recommended Actions

Change the DNS Resolver Forward Zone to "." which forces the DNS Resolver to use the specified nameserver for all queries.
