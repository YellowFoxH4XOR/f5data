Security Advisory Description

Multiple desync attacks have been discovered. For more information refer to the following related articles:

  • K27144609: Overview of HTTP/2 desync attacks
  • K63312282: BIG-IP LTM HTTP/2 desync attacks: request line injection
  • K97045220: BIG-IP LTM HTTP/2 desync attacks: malicious CRLF placement

BIG-IP and NGINX systems configured as an HTTP/2 to HTTP/1 proxy are not impacted by the following HTTP/2 desync attack security exposures:

  • Ambiguous requests (authority / host): Both an authority pseudo-header and a declared host header in an attempt to confuse the proxy stack. 
  • Ambiguous requests (multi path/scheme): Multiple path, method or scheme pseudo headers.
  • Content-length conflicts actual length: A declared content length that does not match the length of the content sent in the HTTP/2 data frame.
  • Content-length conflicts transfer-encoding: A Transfer-Encoding header declaring chunked content and either omits the Content-Length header or includes a Content-Length header that does not match the length of the content sent in the HTTP/2 data frame.
  • H2.CL desync: A carriage return (CR), line feed (LF) or CRLF pair within the HTTP/2 path pseudo-header in an attempt to smuggle a request to the back-end server.
  • H2.TE desync: HTTP/2 request contains a smuggled HTTP/1 request in body.
  • H2.TE header name injection: A CR, LF or CRLF pair within an HTTP/2 header name field in an attempt to cause the HTTP/2 proxy to emit an HTTP/1 request with smuggled headers.
  • Header name splitting: A colon in the header name.
  • Header tampering wrap: A space-prepended HTTP/2 header name in an attempt to cause the HTTP/2 proxy to create an HTTP/1 continuation header to tamper with a different request header.
  • Less strict validation: Trailing spaces in header names.
  • No content length forwarding: An HTTP/2 client sends a request containing body content, but does not declare a content length.
  • RFC 8441 Misuse: Specifying the protocol pseudo-header along with smuggled body content.
  • URL prefix injection (host/scheme): Request contains malicious value in pseudo header.
  • URL prefix injection (path/scheme): An invalid scheme header containing a scheme declaration along with an absolute form URI in an attempt to modify the resulting HTTP/1 request.
