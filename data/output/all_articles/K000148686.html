Description

When applying the FTP profile on a virtual server, non-FTP traffic or data-channel FTP traffic might stall. Packets forwarded by the BIG-IP will appear to be cut after a line feed (0x0a) is encountered by the BIG-IP parser, causing the connection to stall.

Environment

BIG-IP with a virtual server configured with the ftp profile

Cause

The ftp profile parses traffic through it as an FTP control channel. If the virtual server intercepts all traffic, such as 0.0.0.0:0, then all new connections to it is parsed as an FTP control channel.

Recommended Actions

Only configure an FTP profile for virtual servers on specific FTP ports, such as port 21.

Implicit FTPS runs on port 990 and immediately initiates an SSL/TLS handshake. If the server uses implicit FTP, do not apply the FTP profile since the SSL/TLS handshake may be parsed as an FTP control channel and may stall.

Explicit FTPS (FTPeS) runs on port 21 and initially uses clear-text FTP in its control channel. If the server runs on port 21 and uses normal FTP or supports explicit secure FTP (FTPeS) then you will need an ftp profile attached to this virtual server.

FTPS and FTPeS data connections will immediately start of with a TLS/SSL handshake, so virtual servers that process this traffic should not have an FTP profile attached.
