Description

You are wondering how to renew/create your XC API Token Service Credential via XC API call, possibly for automation needs. In this case, renewal means extending the expiration date so that the token does not undesirably expire.

Environment

  • F5® Distributed Cloud (XC)
  • XC Console
  • Distributed Cloud API
  • Service Credentials

Answer/Recommended Actions

The relevant API calls are shown here for reference (explanations below):

  • https://docs.cloud.f5.com/docs-v2/api/api-credential#operation/ves.io.schema.api_credential.CustomAPI.CreateServiceCredentials
  • https://docs.cloud.f5.com/docs-v2/api/api-credential#operation/ves.io.schema.api_credential.CustomAPI.Renew

Process for Token Creation

  1. Have your original API token handy (see this article if needed to create your token in XC Console GUI) and stored locally as an environment variable (mine is called "APIToken" in below examples). Note the privileges associated with the token. When you use this token to create a new API token, the new token will be limited to the same privileges as the original token. This limitation is necessary to prevent granting of unauthorized privileges to the new token.
  2. Run the curl command with JSON data shown below. The name and value of the new API token are shown in the curl response output. The new API token will have expiration date of "expiration_days" (from the JSON data) in the future. For example, if the value of "expiration_days" is 1, then the new token will expire tomorrow. 
curl -v --location --request POST "https://<your-tenant-name-here>.console.ves.volterra.io/api/web/namespaces/system/service_credentials" --header "Authorization: APIToken $APIToken" --header "Content-Type: application/json" -d@json_data.json 
### SAMPLE JSON DATA — Change as necessary for your needs

{
  "expiration_days": 1,
  "name": "token-test",
  "namespace": "system",
  "namespace_roles": [
    {
    "namespace": "system",
    "role": "ves-io-admin-role"
    }
  ],
  "type": "SERVICE_API_TOKEN"
}

 

Process for Token Renewal

  1. Have your API token handy (see this article if needed to create your token in XC Console GUI) and stored locally as an environment variable (mine is called "APIToken" in below examples). 
  2. Run the curl command with JSON data shown below. Note that the name of the API Token for renewal must include the unique 8 character suffix value. The renewed API token will have expiration date of "expiration_days" (from the JSON data) in the future. For example, if the value of "expiration_days" is 1, then the new token will expire tomorrow. 
curl --location --request POST "https://<your-tenant-name-here>.console.ves.volterra.io/api/web/namespaces/system/renew/service_credentials" --header "Authorization: APIToken $APIToken" --header "Content-Type: application/json" -d@json_data.json 
### SAMPLE JSON DATA — Change as necessary for your needs

{
  "expiration_days": 2,
  "name": "soctest-lqbwhrwr",
  "namespace": "system"
}
