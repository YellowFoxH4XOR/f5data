Description

A user configuration set (UCS) is a backup file that contains BIG-IP configuration data that can be used to fully restore a BIG-IP system. You can use the third-party tools, AWX or Ansible Automation Controller (formerly known as Ansible Tower), to automate UCS backups of the BIG-IP system. The following procedures guide you through the endeavor. AWX and Automation Controller provide a graphical user interface (GUI) and other features for using Ansible, including scheduling playbook runs.

Note: The content in this article is based on AWX, but should also apply to Ansible Automation Controller. AWX is the open source community project that serves as the upstream project for Automation Controller.

Example playbook

The following example playbook uses the F5 Modules for Ansible (FMFA) bigip_ucs_fetch module to create a UCS archive on a target BIG-IP system.

Note: This example uses the bigip_ucs_fetch module from the imperative collection, f5networks.f5_modules (FMFAv1).

The playbook includes the host name with the date and time in the UCS file name. In this example, the bigips group along with its bigip_username and bigip_password variables are configured in an AWX inventory configuration object. The bigip_ucs_fetch module downloads the UCS file to the AWX control machine.

Depending on your AWX installation you will likely need to customize the pod specification for the Instance Group to add volumes and volumeMounts to the ephemeral AWX execution environment pod. This step enables you to mount a directory from the AWX node to the execution environment pod, so you can save the UCS file. Otherwise, the file will be deleted when the pod is removed at the end of the job. If you don't have this type of installation, you can find other options for durable storage in the AWX environment in Module usage with Tower on CloudDocs.

Alternatively, you can create another task with the command module to use scp to copy the UCS file to a secure remote system, and include only_create_file: yes in the bigip_ucs_fetch module to prevent the Ansible control machine from unnecessarily downloading the file to itself.

---
- name: Fetch BIG-IP UCS
  hosts: bigips
  gather_facts: False
  vars:
    provider:
      password: "{{ bigip_password }}"
      server: "{{ ansible_host }}"
      user: "{{ bigip_username }}"
      validate_certs: False

  tasks:
    - name: get current time on localhost
      command: date "+%H%M%S-%m%d%y"
      register: date
      delegate_to: localhost
      run_once: True
     
    - name: set filename var
      set_fact:
        ucs: "{{ inventory_hostname + '-' + date.stdout +  '-backup.ucs' }}"

    - name: Download a new UCS
      bigip_ucs_fetch:
        src: "{{ ucs }}"
        dest: "{{ '/tmp/ucs/' + ucs }}"
        provider: "{{ provider }}"
      delegate_to: localhost
 

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You are familiar with using Ansible and AWX.
  • You installed BIG-IP 13.x or later on the devices in the environment.
  • You configured the AWX installation to start creating a job template. For more information, refer to the Automation Controller User Guide.

    Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

  • You have an FMFA collection installed in the AWX environment. For more information, refer to K10473506: Using F5 Modules for Ansible collections with AWX or Ansible Tower.

Procedures

Create a job template to run the UCS archive backup playbook

Before you can schedule a playbook run you must create a job template.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the AWX user interface.
  2. Go to Resources > Templates.
  3. Select Add and Add job template.
  4. Add the Name and Job Type.
  5. For Inventory select the one that contains your BIG-IP systems that you want to back up.
  6. For Project select the project with the FMFA collections installed.
  7. For Playbook, choose your playbook that contains the bigip_ucs_fetch module and targets a host or group of BIG-IP systems configured on AWX/Automation controller
  8. Configure Credentials with the credential configuration object that uses the SSH key or the username and password for the BIG-IP systems.

    For more information about setting up SSH keys, refer to K13454: Configuring SSH public key authentication on BIG-IP systems (11.x - 15.x).

  9. Configure other settings as necessary.
  10. Select Save.
  11. (Optional) Verify the job run executes successfully by selecting Launch.

Create a schedule to run the job template

Create a schedule configuration in the job template to begin recurring UCS backups on your target BIG-IP systems.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. While logged in to the AWX instance, go to Resources > Templates and open the job template you created in the previous procedure.
  2. Select the Schedules tab.
  3. Select Add.
  4. Add a Name, choose a Start date/time and Local time zone.
  5. Select a Run frequency option.
  6. In the Frequency details section, select specific recurrence options. For example select the days of the week to run the job.
  7. In the Frequency details section, select when and if the schedule should end.
  8. Select Save.
  9. Go to Views > Schedules to view all configured schedules.
