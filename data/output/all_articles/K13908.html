Known Issue

The BIG-IP GTM system may drop path probe data.

This issue occurs when the following conditions are met:

  • The hardware platform is a BIG-IP 3400 (C62)
  • A wide IP pool uses one of the following dynamic load-balancing methods:
    • Hops
    • Round Trip Time (RTT)
    • Quality of Service (QoS)
  • The pvad process restarts while the system is performing path probing

When the pvad process restarts, the system may generate path probe packets with bad User Datagram Protocol (UDP) checksums. The pvad process then drops the corrupt packets.

When you assign a dynamic load-balancing mode to a pool, the BIG-IP GTM system obtains path probe data to determine how quickly traffic moves between a Local Domain Name System (LDNS) and a resource for which the BIG-IP GTM system is responsible. The system then uses the path data when making load-balancing decisions. You can view path probe statistics in the Configuration utility on the Global Traffic statistics screen.

Impact

The BIG-IP GTM system is not able to gather path probe data used for dynamic load-balancing

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Path probe statistics may appear incomplete
  • Running the tcpdump utility on interface 0.0 indicates that the BIG-IP GTM system generates path probe packets with a corrupt UDP checksum. For example:

    802.1Q vlan#4093 P0 77.247.0.66.32773 > 77.247.254.83.domain: [bad udp cksum c6b1!] 10852 NS? . (19) (ttl 64, id 10853, len 47)
