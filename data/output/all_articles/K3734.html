K3734: Smoothed round trip time calculation may cause SSL proxies to send groups of retransmitted packets

Known Issue

SSL proxies use smoothed round trip time to calculate the expected speed of node responses. The amount of time until a node is considered unresponsive and packets are retransmitted is equal to twice the smoothed round trip time.

If the virtual server that is associated with the SSL proxy is configured to use a delayed binding feature, such as cookie persistence or an iRule, the virtual server will respond much more quickly than the node. This occurs because the virtual server is attached to the BIG-IP loopback interface and will respond without connecting to the node when establishing a new TCP session. This internal communication occurs more quickly than a connection that leaves BIG-IP.

As a result, the calculated smoothed round trip time for the connection may be unreasonably short and, if the node does not respond within the calculated timeout once the data exchange begins with BIG-IP, BIG-IP will retransmit the data.

Because BIG-IP is using a delayed binding feature, it will retransmit all the packets it has buffered, rather than retransmitting only the last packet. This may result in a near-simultaneous retransmission.

Under normal circumstances, the node will ignore any retransmitted packets that it does not need. Occasionally, nodes that have defective TCP/IP stacks respond poorly to these multiple packet retransmissions and drop the connection.

F5 Networks Product Development tracked this issue as CR28421.
