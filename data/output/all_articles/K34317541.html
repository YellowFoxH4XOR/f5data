Known Issue

The BIG-IP APM system may erroneously accept special characters when you create Uniform Resource Identifier (URI) rules.

This issue occurs when the following condition is met:

  • You create a new URI rule that includes special characters after the backward slash and forward slash characters.

By design, the rewrite uri-translation rules work only with a URI path. A URI path such as /blah\?blah/ is not valid because it contains a question mark ( ? ), which is a reserved character for URI.

When you create a URI rule, you must specify the client and server URIs as follows:

  • When the URI is a path prefix only, the path must be preceded by and followed by a /. 

    For example: 

    /sales/

  • When the URI contains more than the path prefix (such as a host), the URI must also contain a scheme and must be followed by a /. 

    For example: 

    http://www.siterequest/sales/  

Impact

During rewrite URI translation, any trailing part after the valid path prefix is removed from the URL.

Symptoms

As a result of this issue, you may encounter the following symptom:

  •  During rewrite URI translation, the system removes, from the URL, any trailing part after the valid path prefix.

Workaround

To work around this issue, you can write the special character in its percent-encoded format. For example, the correct URI path for /blah\?blah/ will be /blah%5c%3fblah/, where \? is %5c%3f.
