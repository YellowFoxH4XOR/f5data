K2499: Recreating the LDAP database to correct problems with slapd authentication

Topic

Starting in version 4.5, BIG-IP and 3-DNS perform local user authentication using an LDAP database. In rare cases, the database or supporting files may become corrupted. If this occurs, the LDAP daemon, slapd will not start or users will not be authenticated even though they exist in the database.

If this issue occurs, reset the database by performing the following steps:

Important: If you have a UCS archive that was created when the LDAP database worked, restore it and skip directly to step 8.

  1. Log in to the command line of the working peer system.
  2. Create an archive of the LDAP files on the working peer system, by typing the following command:

    Important: The following command should be on one line. In this instance, the command was split into three lines for formatting purposes.

    tar -czf /var/tmp/ldap-db.tar.gz /config/openldap-ldbm 
/config/ldapauth.conf /usr/local/etc/openldap/slapd.conf 
/config/bigconfig/ssl.crt/default.crt /config/bigconfig/ssl.key/default.key
  3. Copy the archive to the peer system that is not working, by typing the following command:

    scp /var/tmp/ldap-db.tar.gz root@peer:/var/tmp/

  4. Log in to the command line of the peer system that is not working.
  5. Change directories to the /var/tmp/ directory, by typing the following command:

    cd /var/tmp/

  6. Stop slapd, by typing the following command:

    bigstart shutdown slapd

  7. Overwrite the existing LDAP files with those in the archive that you created, by typing the following command:

    tar -C / -zxf ldap-db.tar.gz

  8. Start slapd, by typing the following command:

    bigstart startup slapd

  9. Locate the LDAP administrative password hash and place it in a variable, by typing the following command:
    passwd=$(grep ^rootpw /usr/local/etc/openldap/slapd.conf | awk {'print $2'})
  10. Reset the LDAP administrative user and password, by typing the following command:

    hostinit "cn=Manager,dc=f5,dc=com" $passwd > /dev/null 2>&1

The LDAP database is now restored.
