Description

This is an additional analysis on scenarios when implementing the Prohibit routing table changes during Network Access connection, either in Full or Split tunnel, as mitigation to  VPN TunnelVision vulnerability CVE-2024-3661. 

Environment

BIG-IP APM Network Access Resource configured for VPN access configured with Full or Split Tunnel

Mitigate VPN TunnelVision vulnerability CVE-2024-3661

Cause

Implementing the Prohibit routing table changes during Network Access (NA) connection as mitigation to TunnelVision vulnerability CVE-2024-3661

DHCP Option 121 route insertion on client system impact on APM NA VPN connection


Recommended Actions

Enable Prohibit routing table changes during Network Access connection to mitigate TunnelVision vulnerability CVE-2024-3661

In addition, enable Integrated IP filtering engine.

Both configuration can be configured in the BIG-IP APM Network Access Resource options.

For more information, refer to the Mitigation section of  VPN TunnelVision vulnerability CVE-2024-3661

Additional Information

If an attacker is already in control of the local DHCP server that will push DHCP option 121 to insert a malicious route when a client system in the local network leases/renews its lease for an IP address and successfully inserts the malicious route to the client system routing table, there are a few scenarios:

In Full Tunnel NA resource configuration, when the client connects to APM VPN, the client system routing table will be backed up/snapshot and the client system's default route will be updated to point to the received APM NA VPN IP address. In this case, the malicious route, assuming it was a default route (the researcher's paper shows its a default route), will be in conflict with APM NA inserted default route. Per testing, the APM NA VPN IP address will be used as the default route and has a metric value of "1" and makes it as the preferred route. In this case, the attacker will not see encapsulated traffic between client and APM (1b-b).

In Split Tunnel NA resource configuration, when the client connects to APM VPN, the client system routing table merges with the APM NA resource routes - influenced by IPV4 LAN/DNS Address Space in the APM NA resource configuration. If there is a conflicting route affecting the VPN tunnel in the client system, the APM NA resource inserted route will be used. If the malicious route that was inserted conflicts with an APM NA VPN route, as the APM NA VPN route will take effect, it is not possible for the attacker to see/observe traffic destined to APM NA VPN route (1b-b) - per observation, the metric value used by the APM NA VPN route is "1" which is the lowest value and makes the route preferred.

In both cases, if the mitigation "Prohibit routing table changes during Network Access connection" is enabled, Edge Client will enforce its route and removes duplicate/conflicting routes affecting the APM VPN tunnel added during the VPN session.
