Description

SNMP (Simple Network Management Protocol) enables a monitoring system (the 'manager') to read status information from a device (the 'agent') and receive alarms ('traps'). This article outlines SNMP usage on F5, including its versions, functionality, and how to check configuration.

Environment

  • F5OS platform (rSeries appliances and VELOS chassis).
  • BIG-IP tenant instances (LTM/ASM/...).

Cause

None.

Recommended Actions

How to Tell if SNMP is Configured on F5OS Appliances (rSeries)

  • WebUI (quickest):
    1. Log in to the appliance’s F5OS web UI using the platform management IP.
    2. Navigate to System Settings > SNMP Configuration.
    3. Verify SNMP Configuration Port, contact/location/name fields, Communities, Users, and Targets or trap destinations.
  • API (definitive, scriptable):
    1. Run: curl -sk -u admin -H "Content-Type: application/yang-data+json" -X GET https://<F5OS-mgmt-ip>/api/data/openconfig-system:system/f5-system-snmp:snmp
    2. Check JSON output for configuration state (communities, v3 users, trap targets).
  • Remote functional test:
    1. v2c: snmpwalk -v2c -c <community> <F5OS-mgmt-ip> .1.3.6.1.2.1.1.1.0
    2. v3: snmpwalk -v3 -l authPriv -u <user> -a [SHA|MD5] -A <authPassword> -x [AES|DES] -X <privPassword> <F5OS-mgmt-ip> .1.3.6.1.2.1.1.1.0

How to Tell if SNMP is Configured on F5OS Chassis Systems (VELOS)

  • WebUI:
    1. Log in to the chassis partition or controller web UI with the management IP.
    2. Navigate to System Settings > SNMP Configuration.
    3. Verify SNMP Configuration Port, contact/location/name fields, Communities, Users, and Targets or trap destinations.
    4. Repeat for the peer controller management IP.
  • API:
    1. Run: curl -sk -u admin -H "Content-Type: application/yang-data+json" -X GET https://<controller-mgmt-ip>/api/data/openconfig-system:system/f5-system-snmp:snmp
    2. Validate configuration fields and trap targets on each controller.
  • Remote functional test:
    1. Run snmpwalk to each controller’s management IP using v2c/v3 settings.

How to Check if SNMP is Configured Inside a BIG-IP Tenant (TMOS)

  • BIG-IP GUI (TMUI):
    1. Log in to the tenant’s management IP.
    2. Navigate to System > SNMP.
    3. Check v2c community, allowed addresses, v3 users (auth/priv), and trap destinations.
  • BIG-IP CLI (tmsh):
    1. Run: tmsh list sys snmp.
    2. Check communities, allowed addresses, v3 users, and trap destinations.
    3. Run: tmsh show sys snmp for runtime info.
    4. Run: bigstart status snmpd to ensure the SNMP service is running.
  • Remote functional test:
    1. v2c: snmpwalk -v2c -c <community> <tenant-mgmt-ip> .1.3.6.1.2.1.1.1.0
    2. v3: snmpwalk -v3 -l <level> -u <user> -a [SHA|MD5] -A <authPassword> -x [AES|DES] -X <privPassword> <tenant-mgmt-ip> .1.3.6.1.2.1.1.1.0

 

Additional Information

How to Confirm Traps are Working (Platform or Tenant)

  • Verify NMS is listening for SNMP traps from the device management IP.
  • Configure at least one trap destination in SNMP settings.
  • Generate a safe test event:
    • Disable/enable a management interface description to trigger a linkUp/linkDown event.
    • Change contact/location fields or send a test trap.
  • Confirm the trap arrives on your NMS.

Common Items to Check

  • Target the correct layer: F5OS platform IP for chassis/appliance health, tenant IP for BIG-IP services.
  • Ensure UDP ports 161 (queries) and 162 (traps) are allowed between the NMS and device IPs.
  • The BIG-IP tenant’s SNMP settings must include NMS in 'Allowed Addresses.'
  • Matching v3 authentication/encryption settings between device and NMS.
  • VELOS dual controllers: monitor and set traps for both controllers if redundancy is required.

Quick Checklist (yes/no)

  • F5OS Appliance/Chassis UI shows SNMP enabled.
  • Either a v2c community or at least one v3 user exists.
  • At least one trap destination set (if expecting traps).
  • snmpwalk from a remote host returns sysDescr.0.
  • VELOS controllers A and B tested.
  • BIG-IP tenants: tmsh list sys snmp confirms v2c/v3 config; snmpd is running; snmpwalk succeeds.
