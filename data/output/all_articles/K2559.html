Topic

Although rare, kernel corruption after a system failure is possible on BIG-IP. Such cases generally occur after a power outage or system panic. In such cases, the BIG-IP will provide boot output similar to the following:

System is booting, Please wait .........
press ESC to boot now, any other key to interrupt boot sequence 4 3 2 1 0
basemem = 636K, extmem = 130048K, total 131072K
unrecognized binary file type   <<<< NOTE: failure to read kernel
Program load failed
Boot: bsd
Checking for ACPI PM SUPPORT...
Not present
Checking for APM BIOS... APM V1.2 found.

F5 Networks, Inc. All rights reserved.
BIG-IP Kernel 4.5PTF-03 Build2
Hardware Configuration: ....root device? wd0
CPU: Pentium III (Coppermine) (996 MHz)
Memory: 128 MB
Crypto Processor

Network Interfaces:
3.1 00:01:d7:15:7e:00 (exp0) ether 100BaseTX 10BaseT
1.1 - 1.16 (bs) ether 100BaseTX 10BaseT
2.1 00:01:d7:15:7e:39 (bsg1) ether 1000Mbps
2.2 00:01:d7:15:7e:3a (bsg2) ether 1000Mbps
Other Devices:
Enter pathname of shell or RETURN for sh:
#

When this occurs, the kernel may need to be replaced. To replace the kernel, perform the following steps:

Note: This is an advanced-level solution that requires the use of many Unix commands. Please read through the entire solution before beginning in order to make sure that these tasks are within your comfort level. If they are not, contact F5 Technical Support for assistance.

  1. Boot the generic kernel into single-user mode.
    1. Boot or reboot the system as normal.
    2. When you see the following prompt, press the space bar:

      press ESC to boot now, any other key to interrupt boot sequence...

    3. At the Boot: prompt, type the following and press Enter:

      bsd.generic

    4. When prompted to specify a root device, type the following:

      wd0a

    5. When prompted to specify a shell, press the Enter key for the default, /bin/sh.

    You are now in single-user mode.

  2. Perform filesystem checks to ensure the filesystems are clean. To do so, type the following commands and wait for them to complete:

    fsck -y /dev/wd0a
    fsck -y /dev/wd0g

  3. Mount the filesystems by typing the following command:

    mount -a

  4. Configure the user environment by typing the following commands:

    TERM=vt100
    export TERM

    These commands will ensure the terminal displays all output properly.

  5. Verify the kernel checksums.

    Run checksums on both the working and non-working BIG-IP and compare the values to ensure the kernel files have not been corrupted.

    Note: To perform this comparison, both BIG-IPs must be running the same version. If the BIG-IPs are not running the same version, contact F5 Technical Support for assistance in verifying the checksums and resolving the issue.

  6. On the non-working BIG-IP, type the following command:

    md5 /bsd.*

    Example output: (This is only an example - do not use these sums for comparison.)

    askf51:~# md5 /bsd.*
    5e51daba17f978767d7d0a09f692d1f0 /bsd.anip
    e1db59af8115fb995360fb8a0574facc /bsd.smp

  7. On the working BIG-IP, type the following command:

    md5 /bsd.*

    Example output: (This is only an example - do not use these sums for comparison.)

    askf52:~# md5 /bsd.*
    f61fb3a4a3263a78439ed7cb06d15252 /bsd.anip
    92cbf286949f55ac4b70126dbeaf7d0a /bsd.smp

    In this example, the values on the working BIG-IP differ from the values on the non-working BIG-IP, which indicates the kernel files are corrupted.

  8. Move the corrupted kernel files and replace them with the kernel files from the working BIG-IP.

    Use the following commands to copy the corrupted kernel files to the /var/tmp directory and compress them:

    cp /bsd.anip /var/tmp/bsd.anip.failed
    cp /bsd.smp /var/tmp/bsd.smp.failed
    gzip -9 /var/tmp/bsd.*.failed

  9. Configure the non-working BIG-IP to connect to the network.
    1. Determine which interface normally has connectivity to the peer BIG-IP.
    2. Because BIG-IP has been booted using the generic kernel, the interface names are different. Type the following command, replacing <interface> with the BIG-IP interface that is normally used to connect to the peer:

      ifconfig -a | awk '$1 = /<interface> / { print $2 }'

      For example:

      ifconfig -a | awk '$1 = /1.4 / { print $2 }'

      This will return the current name of the interface. In this example, the name is bs18.

    3. Connect the interface to the network using the following command syntax:

      ifconfig <interface> <IP address> netmask <netmask> broadcast <broadcast>

      You would replace the IP address, netmask value, and broadcast address with the normally configured addresses for this interface. If you are unsure what values are normally used, you can find this information in the /config/bigip_base.conf configuration file.

      For example:

      ifconfig bs18 10.90.100.51 netmask 255.255.255.0 broadcast 10.90.100.255

  10. Log in to the working BIG-IP and type the following commands to copy the working kernel files to the non-working peer:

    scp /bsd.anip peer:/bsd.anip
    scp /bsd.smp peer:/bsd.smp

  11. After the copy has completed, log in to the non-working system and double check that the new kernels have the correct checksum (follow the instructions in Step 5.)
  12. Ensure that the permissions are correct on the kernel files, by typing the following command:

    chmod 755 /bsd.*

  13. Ensure that the symbolic link to bsd points to the new kernel, by typing the following command:

    ln -s /bsd.smp /bsd

  14. Reboot the BIG-IP.

    15. BIG-IP should now reboot correctly, using the restored kernel files.
