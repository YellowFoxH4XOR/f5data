Topic

When a node is disabled, BIG-IP LTM continues to use the existing connection until the connection times out or terminates normally. However, if a virtual server is configured to use the OneConnect profile, and a node is disabled, the Traffic Management Microkernel (TMM) attempts to select another enabled node within the pool on the next request within the current connection. If there are no enabled members in the pool, then TMM cannot select another node, and all connections to the virtual server that use the OneConnect profile are dropped. This expected behavior occurs to prevent Keep-Alive connections from staying connected to a disabled node, and allows BIG-IP LTM to shed connections and perform maintenance on the disabled node.

If you want connections through the virtual server, using the OneConnect profile, to be allowed to finish communication with a node that is marked as disabled, then persistence must be enabled on the virtual server. This allows all connections that contain a persistence entry for that node to be directed back to the disabled node.

Note: Because the OneConnect Keep-Alive connections are not established with the disabled node, each persisted connection opens a new connection to the node.
