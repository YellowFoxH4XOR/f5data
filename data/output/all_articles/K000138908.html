Topic

This article applies to BIG-IP Advanced WAF / ASM 17.x. For information about other versions, refer to the following article:

  • K75376155: Creating a security policy automatically (14.x - 16.x)

You should consider using this procedure under the following condition:

  • You want to create a BIG-IP Advanced WAF / ASM security policy automatically using Policy Builder.

Description

Using the automatic method to create a security policy allows the system to create the initial security policy and then refine the policy over time by examining application traffic. When you create a security policy automatically, Policy Builder develops the policy using the following steps:

  • In the initial phase, the system identifies legitimate application usage and begins to build your security policy based on a statistical analysis of your traffic and the intended behavior of your application. In this phase, the system does not block requests until Policy Builder processes sufficient traffic and adds elements to the security policy. In addition, the system provides learning suggestions so you can adjust the security policy based on traffic. 
  • In the next phase, Policy Builder refines and tightens the security policy over time until the number of policy changes stabilizes. The system continues to provides learning suggestions based on real traffic.
  • In the final phase, Policy Builder further refines the security policy until it is ready to enforce the necessary security features.

For example, the following scenario illustrates how Policy Builder automatically adds a legitimate file type to the policy based on an analysis of application traffic:

  1. You create a security policy using the automatic policy building option.
  2. A client sends a GET request for /sell.php.
  3. Since the PHP file type does not yet exist in policy, the BIG-IP ASM system allows the request but marks PHP as an illegal file type and sends a copy of the request to Policy Builder. The system adds a learning suggestion for the request.
  4. The system continues to mark requests for PHP files as illegal until the request threshold is met for that file type.
  5. After the threshold is met for PHP files, the BIG-IP ASM system updates the security policy and no longer considers PHP an illegal file type.

Fully Automatic mode

When you create a security policy automatically, you have the option to use Fully Automatic learning mode. The Fully Automatic option accepts all learning suggestions that reach a score 100, even those that normally require manual acceptance by the administrator. This mode is useful when you don't want to spend time reviewing and manually accepting learning suggestions. For more information about Fully Automatic learning mode, refer to K000134503: Overview of Fully Automatic Policy Building learning mode.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the Configuration utility.
  • You created basic configuration elements, such as the following:
    • A local traffic pool
    • A virtual server

Procedures

To create a security policy automatically and review additional action items for the policy, perform the following tasks:

  • Creating a security policy automatically using Policy Builder
  • Refining the security policy
  • Performing additional action items for the policy

Creating a security policy automatically using Policy Builder

To create a security policy automatically using Policy Builder, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies.
  3. Select Create.
  4. For Policy Name, type a name for the security policy.
  5. For Policy Type, select Security, or select Parent if you want to use the policy as a parent policy for similar child policies.
  6. For Policy Template, select the appropriate template for your deployment. For example, you can select Rapid Deployment or an application-ready template.
  7. For Virtual Server, select the name of the virtual server, or select Configure new virtual server to create a new virtual server.
  8. For Application Language, select Auto detect.
  9. For Enforcement Mode, select either Transparent or Blocking.
  10. For Policy Building Learning Mode, select Automatic.
    • Select Fully Automatic if you want the system to automatically accept all learning suggestions that reach a score 100.
  11. For Auto-Added Signature Accuracy, select  Medium Accuracy.
  12. For Trusted IP Addresses, type an IP addresses or network that the system considers safe and select Add. Repeat this step for each address or network.
  13. For Policy Builder Learning Speed, select Medium.
  14. For Signature Staging, select Enabled.
    Note: Attack signature staging helps reduce the number of false positive violations for the policy.
  15. For Server Technologies, specify the server technologies you want to add protections for the policy.
  16. For Policy is Case Sensitive, select Enabled.
  17. For Differentiate between HTTP/WS and HTTPS/WSS URLs, select Enabled if the web application behaves differently for HTTP/WS and HTTPS/WSS URLs.
  18. select Save.

Refining the security policy

After you complete the initial security policy, have users browse and test their access to the application. As users initially browse the application, the system allows all traffic through the policy, and Policy Builder examines the traffic and makes learning suggestions that you can review. You can then configure Policy Builder to amend the policy based on the learning suggestions.

For example, as the BIG-IP Advanced WAF / ASM system processes requests, it may alert you to a potential violation, such as Attack Signature Detected. When this occurs, the Learning page displays information about the violation and lists an associated action for you to take, such as the following example:

  • Action: Add Automated client access "curl" (disabled on the Header) to Overridden Attack Signatures.

On the Traffic Learning page, you have the following options for each suggestion: Accept, Delete, Ignore, or Export. If you choose to accept a suggestion, the system performs the specified action.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Traffic Learning.
  3. On the Traffic Learning page, select the name of the policy you want to refine.
  4. From Suggestions, select a learning suggestion to view information about the suggestion and the associated action the system takes if you accept the suggestion.
  5. For each suggestion, you can select Accept, Delete, or Ignore, or Export as appropriate for your policy.
  6. Select Apply Policy to activate any changes you made to the policy.

Performing additional action items for the policy

You can view a list of suggested action items, which the system reminds you to perform, such as required configuration and maintenance tasks. To take action on the items, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Overview > Application > Action Items.
  3. Under Suggested Action Items, review the list of recommended tasks for more information.
  4. For Policy Elements Learned in Automatic mode, review the progress of Policy Builder and policy elements.
  5. Under Quick links, use the links to access common configuration pages in the policy.
