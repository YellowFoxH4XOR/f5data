K000136996: Application is unhealthy but can ping the virtual IP address

Support Solution
Published
2023-09-26

Applies to

  • BIG-IP Next LTM: 20.X.X, 20.0.X, 20.0.0

Source
https://my.f5.com/manage/s/article/K000136996

Description

  • Central Manager reports that an application is unhealthy
  • All endpoints are marked down by BIG-IP Next
  • All endpoints are confirmed to be up by manual verification
  • You can ping the virtual server address but HTTP requests to the virtual server are reset
  • You are unable to ping the endpoints from the tmm debug sidecar.

Environment

  • BIG-IP Next Virtual Edition
  • An application is deployed

Cause

IP address conflict.   A system on the network is using the same IP address as the internal SelfIP address of BIG-IP Next.  Confirm this by running arp -a <internal SelfIP> from a system on the internal network and seeing if the MAC address is different from the MAC address that tmm is using for the internal network interface.

Recommended Actions

Find and correct the IP address conflict.  Tmm will start responding to arp requests.
