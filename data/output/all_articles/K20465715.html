Topic

This article describes current limitations in implementing route domains in the BIG-IP APM system. Although these limitations are true for the predefined set of versions and hotfixes mentioned in this article, F5 highly recommends that you refer to the product release notes as they become available to find the latest and updated information on these limitations.

Description

Route domain limitations

IDTitleSummary
420493Ability to specify separate DNS server for every authentication, authorization, and accounting (AAA) active directory (AD) server objectAll AD objects use the system-configured DNS server to make a query. Configuring different DNS servers for each AD object is currently not supported.
557929BIG-IP APM support for multi-tenant route domain aware DNSThe BIG-IP APM DNS configuration does not currently support route domains. All DNS communication should happen in route domain 0. For more information, refer to K86413227: BIG-IP APM support for per-tenant DNS.
435291Support route domains for SecurID AAARoute domains are not currently supported for AAA SecurID servers. However, you can work around the issue by following the procedures in K15231348:Route domain support for BIG-IP APM AAA SecurID.
434017Route domain support for Kerberos single sign-on (SSO)Route domains are not currently supported for Kerberos SSO. For more information, refer to K17148: BIG-IP APM support for Kerberos SSO and route domains.
421518Network Access client-to-client communications on non-route-domain-0 route domainsNetwork Access client-to-client communication is not currently supported if the parent route domain is other than route domain 0.
435099Route domain support for EAM plug-inRoute domains are not currently supported for AAA Oracle Access Manager (OAM) servers. All EAM traffic should happen in route domain 0.
791025EMS systems only function on default route domainRoute domains are not currently supported when configuring Endpoint Management Systems. All this traffic should happen in route domain 0.
711565Support route domain for OAuth token requestBIG-IP APM systems configured with the OAuth client cannot obtain the access token because the 'OAuth Token Request' is sent through the default route domain (route domain 0) when attempting to communicate with the OAuth Authorization Server.
Note: This applies to BIG-IP 13.x and later.
820853OCSP does not work with route domains other than 0OCSP traffic egress using route domain 0 or management interface.

Add support for Route Domains with both AAA HTTP and the E-mail AgentRoute domains are only supported for AAA servers that have the option to select a pool. There is no option to select a pool for an HTTP AAA server. Additionally, the SMTP configuration required to support the Email Agent does not have an option to select a pool.
