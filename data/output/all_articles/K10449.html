Topic

This article applies to BIG-IP GTM 9.3.x through 10.x. For information about upgrading to 11.x or 12.x, refer to the following guides and articles:

  • BIG-IP System: Upgrading Active/Standby Systems (12.x / DNS)
  • BIG-IP System: Upgrading Active-Active Systems (12.x / DNS)
  • BIG-IP System: Upgrading Active/Standby Systems (11.x / GTM)
  • BIG-IP System: Upgrading Active-Active Systems (11.x / GTM)

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  • K13123: Managing BIG-IP product hotfixes (11.x - 12.x)

Note: Beginning in 12.0.0, F5 has changed the name of BIG-IP GTM to BIG-IP DNS to better reflect the breadth of the product offering with its functionality.

Beginning in BIG-IP GTM 9.3.0, changes were made regarding how BIG-IP GTM devices communicate. The change includes a version field in the message packets that is used to communicate between BIG-IP GTM devices. This version field alleviates the need to remove BIG-IP GTM devices from a synchronization group. If a BIG-IP GTM device receives a message packet with a version that does not match, no changes are allowed by the device.

F5 recommends that you perform the following steps to ensure a successful BIG-IP GTM software version upgrade and/or hotfix installation:

BIG-IP GTM pre-upgrade recommendations

Before upgrading a single BIG-IP GTM system or a group of BIG-IP GTM systems, F5 recommends that you perform all of the following steps before you apply the upgrade. These actions ensure that the systems are ready to receive the upgrade and minimize downtime while the upgrade is being installed.

  • In versions prior to BIG-IP GTM 10.1.0, reactivate the BIG-IP GTM license

    Note: To verify the license date and instructions to update the license, refer to K7727: License activation may be required prior to software upgrade for the BIG-IQ system. For more information about a related change in behavior, refer to K10245: BIG-IP UCS installation and licensing behavior.

  • Verify that all trusted device certificates and local certificates that are used for secure communication between BIG-IP GTM devices are up to date and will not expire during the maintenance period, or shortly following the maintenance period.

    Trusted device certificates are the SSL certificates used by the Configuration utility. The BIG-IP GTM system uses these certificates to communicate securely with other BIG-IP GTM and BIG-IP devices. To verify and renew SSL certificates, refer to K8187: Overview of BIG-IP device certificates (9.x - 10.x) and K7466: The default validity length for BIG-IP SSL device certificates is one year.
  • Create a current backup copy of the local configuration for each BIG-IP GTM system, and store the backup in a secure and separate location from the device.

    Note: For more information, refer to K11318: Backing up and restoring BIG-IP configuration files (10.x)  or K3499: Backing up and restoring BIG-IP configuration files (9.x).

  • Download the installation IM and/or hotfix to each BIG-IP GTM device and verify that the MD5 checksum of the hotfix file is correct.

    Note: For information about downloading and verifying the installation IM, refer to the BIG-IP GTM release notes for the version you are upgrading to.

    Note: For information about downloading the hotfix and verifying the MD5 checksum, refer to the Downloading the hotfix files and the Verifying the MD5 checksum of the hotfix files sections in K6845: Managing BIG-IP product hotfixes (9.x) or K10025: Managing BIG-IP product hotfixes (10.x).

BIG-IP GTM software version upgrade and/or hotfix recommendations

Important: During these upgrade steps, the unit you are performing this task on will be unavailable to resolve any DNS requests. In addition, no configuration changes should be introduced to the BIG-IP GTM synchronization group until all members of the synchronization group have been upgraded to the same version.

Installing the upgrade software

  1. Log in to the command line of the BIG-IP GTM system you are going to upgrade.
  2. Stop the named process by typing the following command:

    Note: Stopping the named process prevents the BIG-IP GTM system from answering DNS requests that fall back to BIND.

    bigstart shutdown named

  3. Stop the big3d process by typing the following command:

    Note: Stopping the big3d process prevents the BIG-IP GTM system from communicating with other BIG-IP devices.

    bigstart shutdown big3d

  4. Stop the gtmd process by typing the following command:

    Note: Stopping the gtmd process prevents the BIG-IP GTM system from answering DNS requests.

    bigstart shutdown gtmd

  5. Install the upgrade software

    Note: To ensure the correct commands and steps, refer to the BIG-IP GTM release notes for the version you are upgrading to.

Installing the hotfix software

  1. Log in to the command line of the BIG-IP GTM you are going to upgrade.
  2. Stop the named process by typing the following command:

    Note: Stopping the named process prevents the BIG-IP GTM system from answering DNS requests that fall back to BIND.

    bigstart shutdown named

  3. Stop the big3d process by typing the following command:

    Note: Stopping the big3d process prevents the BIG-IP GTM system from communicating with other BIG-IP devices.

    bigstart shutdown big3d

  4. Stop the gtmd process by typing the following command:

    Note: Stopping the gtmd process prevents the BIG-IP GTM system from answering DNS requests.

    bigstart shutdown gtmd

  5. Install the hotfix.

    Note: For more information about installing hotfixes, refer to the Installing the hotfix section in K6845: Managing BIG-IP product hotfixes (9.x) or K10025: Managing BIG-IP product hotfixes (10.x).

  6. Reboot the BIG-IP GTM once the hotfix has finished installing by typing the following command:

    /usr/bin/full_box_reboot

BIG-IP GTM post-upgrade recommendations

  1. Once the BIG-IP GTM system has rebooted and is back online, verify that the BIG-IP GTM system processes have started correctly by typing the following command:

    bigstart status

    Look for the following BIG-IP GTM daemons in the command output:

    big3d run (pid 1005) 16 minutes
    bigd run (pid 977) 16 minutes
    gtmd run (pid 962) 16 minutes
    named run (pid 1008) 16 minutes
    zrd run (pid 1011) 16 minutes

  2. Verify that the BIG-IP GTM system, if configured as part of a synchronization group, has rejoined the synchronization group, by typing the following command:

    cat /var/log/gtm | grep -i joined

    The command output appears similar to the following example:

    dns-gtm gtmd[1770]: 011a5008:1: SNMP_TRAP: BIG-IP GTM gtm.askf5lab.net (10.3.0.121) joined sync group GTM1Group

    Look for the latest entry, which indicates that the newly-upgraded system has joined the synchronization group.
  3. Verify that the gtmd and big3d processes have connectivity to the synchronization group peers by typing the following command:

    netstat -na | head -2; netstat -na | grep ESTAB | grep 4353

    The following command output displays active connections from the gtmd process on the local machine to the big3d process on the remote synchronization group peers:

    Proto Recv-Q Send-Q Local Address Foreign Address State
    tcp 0 0 ::ffff:10.3.0.95:32825 ::ffff:10.3.0.119:4353 ESTABLISHED
    tcp 0 0 ::ffff:10.3.0.95:32826 ::ffff:10.3.0.47:4353 ESTABLISHED
    tcp 0 0 ::ffff:10.3.0.95:35750 ::ffff:10.3.0.121:4353 ESTABLISHED
    tcp 0 0 ::ffff:10.3.0.95:32828 ::ffff:10.3.0.120:4353 ESTABLISHED

    The following command output displays active connections to the big3d process on the local machine from the gtmd process on the remote synchronization group peers:

    Proto Recv-Q Send-Q Local Address Foreign Address State
    tcp 0 0 10.3.0.95:4353 10.3.0.95:32837 ESTABLISHED
    tcp 0 0 10.3.0.95:4353 10.3.0.119:33201 ESTABLISHED
    tcp 0 0 10.3.0.95:4353 10.3.0.47:33163 ESTABLISHED
    tcp 0 0 10.3.0.95:4353 10.3.0.120:33174 ESTABLISHED

    Note: It may take a few minutes for all connections to become established.

  4. Verify that the object status on the newly-upgraded system is consistent with other members of the synchronization group by reviewing the BIG-IP GTM Configuration utility Statistics page.

    Note: The status page is located in the Overview section of the Configuration utility.

    Compare the wide IP, Pools, Data Center, and Server values. The values in the Available, Unavailable, Offline, and Unknown columns should be the same. It is possible that the BIG-IP GTM systems will differ by a few objects, as status may be in transit between units when you review the static web page. Therefore, one BIG-IP GTM system's page may be more current than another system's page.
  5. (Optional) Perform test queries against the wide IPs to ensure that the system is responding correctly.
  6. If the BIG-IP GTM system is active, has connectivity to its peers within the synchronization group, and the object status agrees with its peers, proceed with upgrading the remaining BIG-IP GTM systems within the synchronization group.
  7. Once you have upgraded the software version or applied the hotfix to all the BIG-IP GTM systems, test the synchronization group by creating a test object, such as a Data Center, on one of the BIG-IP GTM systems in the synchronization group.
  8. Check the other members in the synchronization group to ensure that the systems received the update.
  9. Once verified, you can delete the test object.
