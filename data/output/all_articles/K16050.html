Known Issue

The data compression strategy size option does not function as expected. Instead of performing compression in software and hardware, the BIG-IP system uses only hardware compression.

The BIG-IP system allows five different data compression strategies; latency, speed, size, ratio, and adaptive. The default compression strategy is latency.

Impact

Data compression is performed in hardware at a reduced gzip-level.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Compression testing will reveal less efficient compression of HTTP content by percentage.

Workaround

To work around this issue, you can set the compression.providerbusy database key to 0. The default setting is 100. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Modify the value of the database key to 0 by typing the following command:

    modify sys db compression.providerbusy value 0
