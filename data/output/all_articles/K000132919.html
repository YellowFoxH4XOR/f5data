K000132919: istio-proxy sidecar (envoy) injection into grpc pod fails

Type
Support Solution
Published
2023-03-20
Updated
2023-07-18
Applies to
  • Aspen Mesh: 1.11
Source
https://my.f5.com/manage/s/article/K000132919

Description

istio-proxy sidecar (envoy) injection into grpc pod fails when there are multiple network interfaces attached to a pod with IPs assigned and there's a Service with multiple ports associated to the deployment.

The Deployment below will trigger the problem

apiVersion: v1
kind: ServiceAccount
metadata:
  name: httpbin
---
apiVersion: v1
kind: Service
metadata:
  name: httpbin
  labels:
    app: httpbin
    service: httpbin
  annotations:
    k8s.v1.cni.cncf.io/networks: active
    prometheus.io/port: "8088"
    prometheus.io/scheme: http
    prometheus.io/scrape: "true"
    sidecar.istio.io/inject: "true"
    traffic.sidecar.istio.io/excludeOutboundIPRanges: 10.42.0.0/16
spec:
  ports:
  - name: http
    port: 8000
    targetPort: 80
  - name: grpc
    port: 50056
    protocol: TCP
    targetPort: 50056
  - name: http-metric
    port: 80
    protocol: TCP
    targetPort: 8088
  selector:
    app: httpbin
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: httpbin
  annotations:
    deployment.kubernetes.io/revision: "1"
    k8s.v1.cni.cncf.io/networks: active
    prometheus.io/port: "8088"
    prometheus.io/scheme: http
    prometheus.io/scrape: "true"
    sidecar.istio.io/inject: "true"
    traffic.sidecar.istio.io/excludeOutboundIPRanges: 10.42.0.0/16
spec:
  replicas: 1
  selector:
    matchLabels:
      app: httpbin
      version: v1
  template:
    metadata:
      labels:
        app: httpbin
        version: v1
      annotations:
        k8s.v1.cni.cncf.io/networks: active
        prometheus.io/port: "8088"
        prometheus.io/scheme: http
        prometheus.io/scrape: "true"
        sidecar.istio.io/inject: "true"
        traffic.sidecar.istio.io/excludeOutboundIPRanges: 10.42.0.0/16
    spec:
      serviceAccountName: httpbin
      containers:
      - image: docker.io/kennethreitz/httpbin
        imagePullPolicy: IfNotPresent
        name: httpbin
        ports:
        - containerPort: 80
        - containerPort: 50056
          protocol: TCP
        - containerPort: 8088
          protocol: TCP
      - image: docker.io/kennethreitz/httpbin
        imagePullPolicy: IfNotPresent
        name: httpbin1
      - image: docker.io/kennethreitz/httpbin
        imagePullPolicy: IfNotPresent
        name: httpbin2


istio-proxy container logs show the following

2023-02-03T12:47:11.740001Z warning envoy config    gRPC config for type.googleapis.com/envoy.config.listener.v3.Listener rejected: Error adding/updating listener(s) virtualInbound: error adding listener '0.0.0.0:15006': filter chain '0.0.0.0_2123' has the same matching rules defined as '0.0.0.0_2123'


Environment

Aspen Mesh 1.11.8-am2, 1.11.8-am4

 

Cause

Bug identified by Aspen Mesh PD team

 

Recommended Actions

Use Aspen Mesh 1.14.x or 1.11.8-am1 non-dual stack

 

Additional Information

In version 1.14.x there was significant refactoring around creation of the inbound listeners fixing the bug present in Aspen Mesh 1.11.8-am2 & 1.11.8-am4
