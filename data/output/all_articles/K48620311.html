Description

When load balancing UDP traffic generated with traffic generation tools, it is not load balanced to pool members.

Environment

  • Virtual server
  • UDP

Cause

UDP packets generated have no payload. These are dropped when using the default UDP profile options.

ltm profile udp udp {
    allow-no-payload disabled
    app-service none
    buffer-max-bytes 655350
    buffer-max-packets 0
    datagram-load-balancing disabled
    defaults-from none
    description none
    idle-timeout 60
    ip-df-mode pmtu
    ip-tos-to-client 0
    ip-ttl-mode proxy
    ip-ttl-v4 255
    ip-ttl-v6 64
    link-qos-to-client 0
    no-checksum disabled
    partition Common
    proxy-mss disabled
    send-buffer-size 655350
}

Recommended Actions

Test the virtual server using a utility such as netcat to determine if the virtual server load balances UDP traffic with a payload to pool members. Netcat inserts a payload of X.

In a production environment, UDP traffic typically contains a payload, so the allow-no-payload option should generally remain disabled.
