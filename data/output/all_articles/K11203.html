Known Issue

This is the result of a known issue. Long lived FTP control channel connections may cause a memory leak in the listener subsystem. When the connection to the FTP virtual server is in passive mode, the TMM allocates a 256 byte listener object for every FTP command that is issued. However, TMM does not release the listener objects until the control channel is closed.

For example, if a client opens a passive FTP connection to a virtual server and issues the ls command to list the filenames in the remote directory, the TMM allocates a 256 byte listener object for the command. TMM allocates additional listener objects for every subsequent FTP command sent over the control channel, and the memory is not released until the FTP control channel connection is closed.

You can verify the listener memory allocation by using the bigpipe memory command. The following bigpipe memory command output indicates the listener subsystem is allocated 863.1M of memory and the maximum amount of memory that was allocated was 1.224G:

MEMORY STATISTICS --
| (Host) Total = 1001.3MB Used = 967.9MB
| (TMM) Total = 2.952GB Used = 1.318GB
| SUBSYSTEM Alloc Max Obj size

| listener 863.1M 1.224G 256

F5 Product Development tracked this issue as CR127172 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.8-396.1-HF3 issued for BIG-IP 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).

Workaround

It may be possible to mitigate this issue by decreasing the Idle Timeout setting for the relevant protocol profile assigned to the FTP virtual server.

Note: For information about adjusting the Idle Timeout setting for the the protocol profile, refer to the Configuration Guide for BIG-IP Local Traffic Management.
