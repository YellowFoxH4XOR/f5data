When the BIG-IP ASM system is processing a high number of large requests, an error message similar to the following may be logged to the /var/log/asm file:

01310015:6: ASM bad request: event code XXXX Too many concurrent long requests

Note: The error message event code differs depending on the BIG-IP ASM software version you are running.

The BIG-IP ASM system logs the message when it receives a request that exceeds the request_buffer_size internal parameter setting, and the system is currently processing the maximum number of long requests as defined by the max_concurrent_long_request internal parameter setting.

Internal parameters that control how the BIG-IP ASM processes long requests

Internal parameters that control how the system processes long requests are intended to prevent a large number of long requests from causing memory pressure. The internal parameters include the following:

  • request_buffer_size:

    A long request is defined as any request that is greater than the standard buffer length, which is set by the request_buffer_size internal parameter.

  • long_request_buffer_size:

    If a request exceeds the size defined by the request_buffer_size internal parameter as it is being buffered, the BIG-IP ASM system marks it as a long request. When marked as a long request, the BIG-IP ASM system transfers the request to one of the pre-allocated long request buffers and continues buffering the request there. The long_request_buffer_size internal parameter represents the maximum size, in bytes, of the long request buffer. The default value is 10000000 bytes.

  • max_concurrent_long_request:

    The maximum number of concurrent long requests is defined by the max_concurrent_long_request internal parameter. The default value is 100 requests.

    If an incoming request exceeds the request_buffer_size internal parameter, and the max_concurrent_long_request limit has already been reached, then the BIG-IP ASM system will terminate the incoming request with a TCP Reset, and log the Too many concurrent long requests message to the /var/log/asm file.

    Note : Prior to BIG-IP 11.6.0, the default is 100. For later versions, it is based on two other settings that create a dynamic value, based on K01235989: Understanding BIG-IP ASM large file upload behavior.

Recommendations for changing the long request internal parameters

If the BIG-IP ASM system is processing requests that only slightly exceed the request_buffer_size parameter, you can increase the request_buffer_size parameter.

If the BIG-IP ASM system is processing requests that greatly exceed the request_buffer_size parameter, then you should increase the max_concurrent_long_request parameter. However, you should monitor the system memory use.

Changing the request_buffer_size

  1. Log in to the Configuration utility.
  2. Select Security.
  3. For Security, click Options.
  4. Select Application Security.
  5. Select Advanced Configuration.
  6. Select System Variables.
  7. Modify the value of request_buffer_size.
  8. Select Save.
Changing the max_concurrent_long_request
  1. Log in to the Configuration utility.
  2. Select Security.
  3. For Security, click Options.
  4. Select Application Security.
  5. Select Advanced Configuration.
  6. Select System Variables.
  7. Modify the value of max_concurrent_long_request.
  8. Select Save.

Note: For more information, refer to K3853: Accessing the System Variables page.
