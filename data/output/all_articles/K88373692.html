Known Issue

AVR database variable changes may not synchronize across blades on the VIPRION platform.

This issue occurs when one of the following conditions is met:

  • The system selects a new primary blade.
  • You change the avr.stats.internal.maxentitiespertable database variable.

Impact

AVR behavior controlled by database variable settings is inconsistent across blades in a VIPRION platform.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Some AVR behavior is inconsistent across blades in the VIPRION platform.
  • The system logs error messages to the /var/log/monpd.log similar to the following examples:

    err stat_bridge_thread[8350]: monpd|ERR|Jun 21 04:15:02.728|13226| [stat_bridge_thread::load_file, ] File load_dim_tmstat_tcp_1498032900 not loaded: has 91 rows (the maximum is 0)
    err stat_bridge_thread[8350]: monpd|ERR|Jun 21 04:15:02.728|13226| [stat_bridge_thread::load_file, ] All rows of load_dim_tmstat_tcp_1498032900 not loaded (0 rows affected)

Workaround

To work around this issue, you can restart AVR's monpd process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management shell (tmsh) by typing the following command:

    tmsh

  2. Restart the monpd process by typing the following command:

    restart sys service monpd

  3. To exit tmsh, type q and press Enter.
