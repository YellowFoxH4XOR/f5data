Topic

Summary

The BIG-IP ASM automatic Policy Builder feature is designed to automate the creation of a security policy by inspecting application traffic and configuring appropriate objects based on the traffic inspected. Accurate identification of object types requires repeated occurrences of the object for the Policy Builder to evaluate. While this process is ongoing, the characteristics of an object may change as the Policy Builder synthesizes more data.

Description

When the BIG-IP ASM Policy Builder is configured with both the JSON/XML payload detection, and the Automatically detect advanced protocols options enabled, Policy Builder will add new parameters of these types to the policy with the parameter value type set to ignore value. The parameter value type will remain marked as ignore value, as long as the parameter is still under classification by the Policy Builder.

For a parameter value to be classified as XML or JSON, the specific parameter with an appropriate value must be detected by the Policy Builder with enough occurrences to satisfy the values defined for the Accept as Legitimate (Loosen) policy building rule.

For example, using the default Accept as Legitimate (Loosen) rule values for BIG-IP ASM 11.1.0, a parameter could be determined to be JSON or XML once the system detects the appropriate parameter value type in 20 different user sessions, and 20 different IPs, spread out over a time period of at least one hour, but not exceeding seven days.

Recommended Action

No action is necessary. Once the defined criteria have been met, the Parameter Value Type will be automatically updated to the appropriate setting.
