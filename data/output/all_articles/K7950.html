Known Issue

This is the result of a known issue. The session add iRule command, which is used for adding session information to the persistence table, can cause TMM to crash. This issue occurs when the session add iRule command is issued more than once within an iRule, and when a default pool is not defined.

The following iRule will cause TMM to crash because the session add command is issued twice:


rule session_add_irule {

   when CLIENT_ACCEPTED {

      set sid [clock clicks -milliseconds]

      TCP::collect

   }

   when CLIENT_DATA {

      session add uie [list $sid any] [list "1.1.1.1" 9999] 1000

      pool testpool

      TCP::release

   }

   when LB_SELECTED {

      session add uie [list $sid any] [list "1.1.1.1" 9999] 1000

   }

}

When a client connects and data is received, the iRule makes a session entry into the persistence table using the session add command. Once the entry is added, the connection is directed to the testpool pool.

Once load balancing is determined, the LB_SELECTED event is invoked causing the session add iRule command to launch again. Because a default pool is not defined, the iRule enters a null value in the persistence table. As a result, TMM crashes.

To prevent this behavior from occurring, only issue the session add command once within an iRule if you do not have a default pool defined.

F5 Networks Product Development tracked this issue as CR84206, and it was fixed in BIG-IP LTM version 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.
