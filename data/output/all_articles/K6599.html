Known Issue

This is the result of a known issue. When an HTTP request does not match an existing httpclass, and is followed by a persistent HTTP request that does match an enabled httpclass, the ASM_clientside iRule touches an uninitialized variable. As a result, the connection is aborted and the BIG-IP LTM logs the following error message in the /var/log/ltm log file:

TCL error: Rule _ASM_clientside <HTTP_REQUEST_SEND> - can't read "tmm_ts_lbserver": no such variable while executing "HTTP::header insert "TSLBServer" $tmm_ts_lbserver" peer expression (line 1) invoked from within "clientside {HTTP::header insert "TSLBServer" $tmm_ts_lbserver}"

F5 Product Development tracked this issue as CR68375 and it was fixed in BIG-IP version 9.2.4. For information about upgrading, refer to the BIG-IP LTM release notes.
