Topic

You should consider using this procedure under the following condition:

  • You are debugging Domain Name System Security Extensions (DNSSEC)  key generation issues and you want to force a specific member of a DNS synchronization group to be responsible for DNSSEC key creation. 

Important: F5 does not recommend that you perform this procedure as a standard configuration, and performing the procedure is not required under normal operating conditions.

Description

When you configure BIG-IP DNS systems in a DNS synchronization group, each member dynamically derives a unique local ID number in relation to other members of the DNS synchronization group. This local ID is stored as the gtm.peerinfolocalid database key value starting at 0 (zero), and it increments for each system in the sync group.

This situation is important in regard to DNSSEC key generation, because the sync group member with the gtm.peerinfolocalid database key variable designation of 0 is responsible for creating new generations of each DNSSEC key and distributing the keys to each sync group member.

  • The system with the lowest self IP address assigns itself local ID 0 (gtm.peerinfolocalid value of 0), and assumes the responsibility of DNSSEC key generation.
  • If the sync group member that has a local id of 0 drops offline, the system with the next-lowest self IP address assigns itself local ID 0, and assumes the responsibility of DNSSEC key generation.

Note: The default gtm.peerinfolocalid value of -1 indicates that the system is not a member of a DNS synchronization group.

When you are debugging DNSSEC key generation issues, you may want to force one specific system to be the DNSSEC key creation server. You can do this by specifying a member of the DNS synchronization group as the peer leader. You can do this by using the tmsh modify gtm global-settings general { peer-leader /Common/<gtm_server_object_name> } command, or using the Configuration utility DNS > Settings > Delivery > Keys : Key Creation Server setting.

Designating a static DNSSEC key creation server (peer-leader) forces the gtm.peerinfolocalid value to 0 for the designated system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The BIG-IP DNS system must already be part of an existing BIG-IP DNS synchronization group.
  • The BIG-IP DNS system is configured to use DNSSEC.
  • You have configured a DNSSEC zone and added the zone-signing and key-signing keys to the zone.

Procedures

Specify the DNSSEC key creation server (peer-leader)

You can specify a member of the DNS synchronization group to be the DNSSEC key creation server (peer-leader) by performing the following procedure:

Impact of procedure: If the system specified to be the DNSSEC key creation server (peer-leader) is unavailable for an extended period of time, DNSSEC key generation may not be performed as expected and DNSSEC DNS queries may fail when existing keys expire. F5 recommends that you use this configuration for troubleshooting or testing only during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to DNS > Settings > Delivery > Keys.
  3. In the Key Creation Server box, type the object name of the system where you want to perform DNSSEC key functions.

    For example:

    /Common/dns-host.domain.local

  4. Click Update.

Alternatively, you can configure the DNSSEC key creation server (peer-leader) from the command line using the following TMOS Shell (tmsh) command syntax:

tmsh modify gtm global-settings general { peer-leader /Common/<gtm_server_object_name> }

For example:

tmsh modify gtm global-settings general { peer-leader /Common/dns-host.domain.local }

The gtm.peerinfolocalid database key value on the specified system will be forced to 0.

The /config/bigip_gtm.conf file will have a peer-leader entry in the gtm global-settings section that appears similar to the following example:

gtm global-settings general {
    peer-leader /Common/dns-host.domain.local
    synchronization yes
    synchronization-group-name testdnssync
    synchronize-zone-files yes
}

Back-out procedure

You can back out this configuration change by using one of the following methods:

  • Using the Configuration utility, navigate to DNS > Settings > Delivery > Keys, and in the DNSSEC Key Creation Server box, delete the entry, and click Update.
  • Using tmsh, type the following command:

    tmsh modify gtm global-settings general { peer-leader none }
