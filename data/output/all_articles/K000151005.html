K000151005: F5RST: Route domain not reachable (strict mode)

Description

When configuring a new Virtual Server (VIP) on BIG-IP LTM (in our example it use HTTPS), the virtual server may fail to process traffic.packet captures reveal TCP RST packets with the message:

F5RST: Route domain not reachable (strict mode)

Attempts to send HTTP traffic also do not reach the backend server.

Environment

  • Virtual Server configured on port 443 with a client SSL profile
  • Pool members configured on port 443
  • Route Domains enabled, with "Strict Isolation" active
  • Pool members not explicitly assigned to the same route domain as the virtual server (missing %<route-domain-id> in pool member configuration)

Cause

This issue arises when the virtual server and its pool members are placed in different route domains while "Strict Isolation" is enabled. With strict isolation, inter-route domain communication is blocked unless specifically permitted. If a pool member does not have an explicit route domain assignment matching that of the virtual server (e.g., missing %1 for route domain 1), BIG-IP will drop connections and generate a TCP RST with "Route domain not reachable (strict mode)".

Recommended Actions

  1. Assign Pool Members to Correct Route Domain:

Ensure each pool member is assigned to the same route domain as its associated virtual server by appending %<route-domain-id> to each pool member’s address.

/Common/pool-member:443 { address <IP_ADDRESS>%1 }

  1. (Alternative) Disable Strict Isolation:

If cross-route domain communication is required, disable "Strict Isolation" for affected route domains:

  • Go to Network > Route Domains in the Configuration Utility.
  • Select the relevant route domain.
  • Uncheck Strict Isolation.
  • Save changes.

Caution: Disabling "Strict Isolation" can impact network segmentation and security by allowing traffic between route domains. Evaluate your security requirements before making this change.
