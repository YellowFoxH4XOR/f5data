Known Issue

If a client closes a TCP connection to the BIG-IP system and the BIG-IP system has Time Wait Recycle enabled, a condition may occur where a client initiates a new TCP connection and the BIG-IP system sends an RST instead of a SYN-ACK response.

This condition occurs when the client reuses a socket to connect to the BIG-IP system and that socket is still in a TIME_WAIT state from the previous connection. Normally the BIG-IP system immediately recycles the connection if configured to do so. However, if the client connection has a SYN sequence number that falls within the range of the receive window of the previous connection, the BIG-IP system resets the connection.

F5 Product Development tracked this issue as ID340306, and it was fixed in BIG-IP 11.0.0. For more information on upgrading refer to K2200: Most recent versions of F5 software.

Workaround

You can partially work around this issue by minimizing the amount of time the BIG-IP system allows a connection to remain in the TIME_WAIT state. For example, to set the Time Wait value for a given TCP profile to 1 millisecond, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocols.
  3. Select TCP.
  4. Select the appropriate TCP profile you want to modify.
  5. In the Settings section, change the value for Time Wait to 1.
  6. Click Update.

The known issue may still appear with this configuration only if a new connection on a re-used socket arrives with an appropriate SYN sequence number, within one millisecond of the socket entering the TIME_WAIT state. If the new connection arrives after one millisecond, the BIG-IP system closes the old connection and the new connection can reuse the socket. This example uses one millisecond as the smallest value the Time Wait setting can accept. You need to choose a value appropriate for your environment.

Note: For more information about configuring TCP Profile options, refer to K7559: Overview of the TCP profile (9.x - 10.x).
