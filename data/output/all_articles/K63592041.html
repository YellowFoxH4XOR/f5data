Topic

You should consider using this procedure under the following condition:

  • You want enable debug logging on the BIG-IP system and send the log messages to a pool of remote high-speed log servers.

Description

You can configure the BIG-IP system to send log messages to a pool of remote high-speed log servers. Doing so allows you to consolidate logging data in a central location and preserve resources on the BIG-IP system. In some cases, you may want to configure the BIG-IP system to send a subset of log messages to a pool of remote high-speed log servers while you are troubleshooting an issue. For example, if you need to troubleshoot a Traffic Management Microkernel (TMM) issue, you can configure the BIG-IP system to temporarily send debug TMM log messages to a pool of high-speed log servers and then disable the debug logging after you are done troubleshooting the problem. To configure the BIG-IP system to temporarily send debug log messages to a pool of remote high-speed log servers, perform the following procedures:

  • Creating a pool of remote log servers
  • Creating a remote high-speed log destination
  • Creating a formatted remote high-speed log destination
  • Creating a log publisher
  • Creating a log filter
  • Disabling the log filter

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have configured a log destination consisting of one or more remote high-speed log servers.
  • You have access to the Configuration utility.

Procedures

Creating a pool of remote log servers

You should identify the IP addresses and service port of the remote high-speed log servers to which the BIG-IP system sends the debug log messages and then create a pool object on the BIG-IP system. To create a pool of remote log servers, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Click Create.
  4. Type a name for the pool.
  5. Select a load balancing method.
  6. For New Members, define the following parameters:
    1. For Node Name, type a name.
    2. For Address, type an IP address.
    3. For Service Port, type a service port, such as 514.
    4. Click Add.
    5. Repeat the previous steps for each high-speed log server you want to add to the pool.
  7. Click Finished.

Creating a remote high-speed log destination

After you create the pool of remote high-speed log servers to which the BIG-IP system sends the debug log messages, create a log destination that specifies a pool of remote log servers. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Destinations.
  2. Click Create.
  3. Type a name for the log destination.
  4. In the Type list, select Remote High-Speed Log.
  5. Under Pool Settings, in the Pool Name list, select the existing pool of remote high-speed log servers.
  6. In the Protocol list, select the protocol for the system to use to send logs to the pool of remote high-speed log servers.
  7. In the Distribution list, select one of the following distribution methods used by the Remote High Speed Log destination to send messages to pool members:
    • adaptive: Connections to pool members are added as required to provide enough logging bandwidth.
    • balanced: Sends each successive log to a new pool member, balancing the logs among them according to the pool's load balancing method.
    • replicated: Replicates each log to all pool members for redundancy.

Creating a formatted remote high-speed log destination

If your remote syslog servers support a log formatting standard, you should create a formatted log destination in addition to the remote high-speed log destination. A formatted logging destination is appropriate for remote log servers, such as Remote Syslog, Splunk, or ArcSight servers. To create a formatted remote high-speed log destination, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Destinations.
  2. Click Create.
  3. Type a name for the log destination.
  4. In the Type list, selecta logging destination type. Options include Remote Syslog, IPFIX, Splunk, or ArcSight.
    • If you selected Remote Syslog, define the following parameters:
      • In the Syslog Format list, click a format for the logs.
      • In the Forward To list, click the log destination that references the pool of remote syslog servers.
    • If you selected Splunk or ArcSight, define the following parameter:
      • In the Forward To list, click the log destination that points to the pool of high-speed log servers.
    • If you selected IPFIX, define the following parameter:
      • In the Pool Name list, click the pool of high-speed log servers.
  5. Click Finished.

Creating a log publisher

To create a log publisher to send logs to a set of specified log destinations, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Publishers.
  2. Click Create.
  3. Type a name for the log publisher.
  4. Under Destinations, in the Available list, select the appropriate log destination and move it to the Selected list.

    If you are using a formatted log destination, click the destination that matches your log servers, such as Remote Syslog, Splunk, or ArcSight.

  5. Click Finished.

Creating a log filter

You should create a log filter to define the debug messages that the system sends to the pool of high-speed log servers. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Filters.
  2. Type a name for the log filter.
  3. To filter log messages based on log level severity, in the Severity list, select the level of alerts that you want the system to use. For example, if you want to send debug log messages to the pool of high-speed log servers, select Debug.
  4. To filter log messages based on the system process that generated the message, in the Source list, select the system processes you want to use. For example, if you are troubleshooting a TMM issue, select TMM.
  5. Leave the Message ID box blank.
  6. In the Log Publisher list, select the publisher that you created in the previous procedure.
  7. Click Finished.

Disabling the log filter

After you collected the debug log data, you should disable the log filter by changing the source option in the log filter to no-source. To do so, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Filters.
  2. Click the name of the log filter that you created in the previous procedure.
  3. In the Source list, select no-source.
  4. Click Update.
