Known Issue

This is the result of a known issue. Specifying a header match with no value within an HTTP Class will cause TMM to crash when it attempts to parse a matching request.

For example, in the following HTTP Class, the headers section is configured to look for a header named Cookie:, but no value is specified:

profile httpclass my_httpclass {
defaults from httpclass
pool http_pool
redirect none
url rewrite none
hosts "www.f5.com"
headers
"Cookie:"
}

TMM will crash after it receives the matching request, which would appear similar to the following example:

GET /test.htm HTTP/1.1
Host: www.f5.com
Cookie:

TMM crashes after attempting to match the NULL or missing value against the cached NULL value.

Note: Specifying Cookie:* will also fail and cause TMM to crash even though the use of the * wildcard represents 0 or more matches in regular expressions.

Note: TMM caches the values specified within an HTTP Class for optimization, to allow for more efficient traffic handling when working with HTTP Classes.

F5 Product Development tracked this issue as CR100897 and it was fixed in BIG-IP 9.4.8 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

Workaround

You can work around this issue and allow the use of a header without a value, by using the forward slash character ( \ ), which turns off optimization and prevents TMM from caching. To do so, the wildcard value match must be specified as follows:

\<Header Name>:*

For example:

\Cookie:*
