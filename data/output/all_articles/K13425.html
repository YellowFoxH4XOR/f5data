Topic

BIG-IP APM Portal Access is a reverse proxy portal that allows access to web resources through the BIG-IP APM system.

Description

A Portal Access comprises several components that work in conjunction to create a reverse proxy that masks and secures the origin web servers from the client.  Each component is described below.

Portal Access webtop

The Portal Access webtop defines the initial URI where the user is directed, and defines the Portal Access resources that are associated with the webtop. The URI may contain links to additional web resources, which can be internal or external, as long as the BIG-IP system can access the web resource. A Portal Access contains exactly one webtop. The webtop, by default, has the home tab bar defined, which provides the user with a URL text box that allows the user to enter a website address to access, a Home button to return the user to the URI defined by the webtop, and a Logout button. The webtop is the only component that a Portal Access must contain. It is the simplest configuration and relies on the rewrite profile that is associated with the virtual server to provide the reverse proxy functionality.

Portal Access resource

The Portal Access resource defines the patching levels, a proxy host, if needed, and the resource items associated with the Portal Access resource. A Portal Access can have zero, one, or multiple Portal Access resources assigned to it. Following is a brief description of the options available in a Portal Access resource:

  • Match case for paths

    The match case for paths sets whether matching of the resource item paths are case sensitive.

  • Patching

    Patching defines the patching type and items to which patching is applied.

    • Full patching

      Full patching patches HTML, JavaScript, CSS, Flash, and XML content.

      Note: Full Patching does not include Java patching, by default.

    • Minimal patching

      Minimal patching patches CSS and HTML content to replace the URI scheme or to search and replace host strings.

  • Default customization settings

    Customization settings define the default language, the caption, and the ability to set a custom image for the portal.

  • Proxy host (advanced configuration)

    The proxy host allows the Portal Access to access web resources through a proxy server.

  • Proxy port (advanced configuration)

    The proxy port specifies the port used by the portal access resource proxy.

  • Publish on Webtop

    When the Publish on Webtop option is enabled, you must specify the Application URI for the webtop link, in the box that appears.

  • Resource items

    A resource item defines what web content the Portal Access resource will act upon. 

The following conditions apply when you configure a Portal Access resource:

  • When you assign multiple Portal Access resources to a Portal Access, all Portal Access resources must use the same patching type.
  • When you assign multiple Portal Access resources, the system assigns an order of processing to the Portal Access resource. The system processes Portal Access resources from first to last; when conflicting settings are encountered, the system uses the one that is first processed.
  • If you apply no resource items to the Portal Access resource, the Portal Access resource has no effect. 

Portal Access resource item

The Portal Access resource item defines the URIs, compression, caching, and SSO configuration for a Portal Access resource. A Portal Access resource can have zero*, one, or more Portal Access item resources assigned to it. Following is a brief description of the options in a Portal Access item resource.

  • Destination

    The destination specifies the host name, IP address, or network of the web content on which to act. You can use wild cards in the host name.

    For example:

    *.example.com

  • Port

    The port is the IP port that the backend web service uses. Setting the port to 0 (zero) matches any port.

  • Scheme

    The scheme specifies whether the URI scheme for the Portal Access is HTTP, HTTPS, or Any.

  • Paths

    The path defines the URL path on which the resource item will act.

    For example, /path causes the Portal Access resource item to act only on *.example.com/path.
  • Headers (advanced)

    Headers specifies any headers that the Portal Access requires.

  • Compression

    Compression specifies whether the application data sent to the Portal Access is compressed with GZIP compression.

  • Client cache

    Client cache specifies settings for client caching of Portal Access.

    • Default

      Default takes the client cache settings from the rewrite profile. In the rewrite profile, you can specify a client caching option-- CSS and JavaScript, CSS, Images and JavaScript, No Cache, or Cache All. If you configure a client cache setting other than Default in the Portal Access resource item, that setting overrides the cache setting in the rewrite profile.

    • Cache all

      Cache all caches everything that can be cached, including CSS, images, JavaScript, and XML. This caching method provides the fastest client performance, but has the lowest security.

    • No cache

      No cache does not cache anything. This is the slowest client performance and provides the most security.

  • SSO configuration

    SSO configuration specifies a Single Sign On configuration that the system uses with the Portal Access resource item.

  • Log

    Log enables logging of packets that are processed by the resource item. Information is logged to the /var/log/pktfilter file.

  • Session update (advanced)

    Some Portal Access pages that are started through Portal Access connections contain JavaScript code that regularly refreshes the page or sends HTTP requests, regardless of user activity or inactivity. A session that is abandoned at such a site does not time out, because it appears to be active. When disabled, the session update feature prevents these sessions from remaining active indefinitely.

  • Session timeout (advanced)

    Session timeout enables the session to timeout for the resource item. 

  • Home tab (advanced)

    Home tab enables the home tab on the web content specified in the resource item.

*Defining zero Portal Access item resources for a Portal Access resource causes the Portal Access to not act on any content.
