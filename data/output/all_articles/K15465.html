Known Issue

Using the discard iRules command may cause the Traffic Management Microkernel (TMM) process to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses a virtual server configured with an Any IP (ipother) profile and an iRule.
  • The iRule contains the discard iRules command in the CLIENT_ACCEPTED iRules event.
  • The virtual server processes traffic that triggers the discard iRules command.

Impact

If the BIG-IP system is a member in a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until TMM restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system fails over to another system in the device group.
  • The BIG-IP system sends a SIGFPE signal to the TMM process, resulting in a core file in the /shared/core directory.
  • The BIG-IP system temporarily fails to process traffic.

Workaround

To work around this issue, you can rewrite the iRule to use the discard iRules command in the CLIENT_DATA iRules event instead of the CLIENT_ACCEPTED iRules event.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure any modification is compatible with your environment.

The exact modifications required depend on the specific details of your iRule. For more information about these events and how to modify iRules, refer to the iRules Home on F5 Cloud Docs.
