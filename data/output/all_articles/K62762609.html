Description

If you modify an ASM policy Application Language encoding using the tmsh utility it resets all entities (URLs, Parameters, etc) to default.

Environment

  • ASM
  • ASM Policy - Application Language encoding
  • The following command is used to modify an ASM policy Application Language encoding from it's current value to a new value:

    tmsh modify asm policy <policy name> encoding <encoding value>

Cause

The command is similar to the previous behavior of ASM's reconfigure option (available on v12.x for example) where the result is the same in that entities are set to default.

Recommended Actions

If you choose to use the command know that you will need to re-learn or re-add entities.

If you intend to keep the configured entities while changing the Application Language encoding, you can clone an existing policy that has the configured entities you want and it allows you to choose a different encoding. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have an impact on your BIG-IP system.

  1. Log in to the BIG-IP ASM Configuration utility as the administrative user.
  2. Navigate to Security > Application Security > Security Policies > Policies List.
  3. Check the policy you want to clone.
  4. Click on the three dots (...) next to Create and select Clone Policy.
  5. Enter a name for the new policy in the Policy Name setting.
  6. Select the Policy Type.
  7. Select the encoding you want from the Application Language setting.
  8. Select Clone.
