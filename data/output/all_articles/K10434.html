Topology is a proximity-based load balancing mode that allows you to direct traffic by defining topology records and selecting the Topology load-balancing mode for the wide IP or pool. The Topology mode bases the distribution of requests on the topology records and the weighted scores configured for each record. The topology records direct DNS queries to the closest virtual server, based on geographical information. The BIG-IP GTM system is designed to support an unlimited number of topology records; the only limit is the amount of memory available to the gtmd process.

The following elements should be considered for understanding topology records:

  • Topology record format
  • Topology records matching modes
     
    • Longest Match enabled
    • Longest Match disabled
    • Geolocation database matching
    • Topology Threshold
  • Creating topology records

Understanding the topology record format

Topology records are used to match an LDNS request with a destination object. A topology record contains three fields:

  • LDNS Request Source
    This field specifies the location from which the incoming DNS request originated.
  • Destination
    This field specifies the resource to which the BIG-IP GTM system directs the incoming DNS request.
  • Weight
    This field specifies the score that will be given to a destination object that matches the topology record. In the event that a name resolution request matches more than one topology record, the BIG-IP GTM system uses the destination object with the highest weight to determine which statement it uses to load balance the request.

Topology records match LDNS IP addresses to a destination object, such as a pool or IP subnet. Topology records are stored in the /config/gtm/topology.inc file on the BIG-IP GTM system, and can be created using the Topology screen in the Configuration utility. An example topology.inc file and corresponding definition table is displayed below:

topology { // 8 Items
// server                      ldns                            score
   pool."Pool_A"               user."UserRegion"               200
   10.10.0.0/16                ISP."Comcast"                   30
   1.1.1.32/32                 ISP."ChinaTelecom"              1
   country."TG"                continent."Asia"                110
   pool."Pool_B"               user."UserRegion"               150
   pool."Pool_C"               country."CN"                    300
   pool."Pool_C2"              country."CN"                    310
   pool."Pool_EMEA"            continent."Europe"              300

}

Understanding topology records matching modes

The BIG-IP GTM system looks up topology records in the order they are presented in the configuration file. The ordering of the records is defined and preserved in the /config/gtm/topology.inc file.

Topology records are matched to an LDNS source IP address in two modes: the Longest Match option enabled, and Longest Match option disabled.

Note: Topology records are not sorted properly in the Configuration utility. For more information, refer to K10431: BIG-IP GTM topology records are not displayed in the correct in the Configuration utility.

Longest Match (enabled)

The Longest Match option, which is enabled by default, instructs the BIG-IP GTM system to use the topology statement that most completely matches the source IP address of the name resolution request.

The Longest Match option ensures that the BIG-IP GTM system processes topology records as fast as possible. It achieves this by automatically sorting the topology records so that the records that more specifically match the LDNS IP appear first in the topology list. When the Longest Match option is enabled and the records are sorted in this fashion, the BIG-IP GTM looks at the LDNS source IP address, and then searches for the first topology record that matches. If the BIG-IP GTM finds a topology record that matches the LDNS source IP, it determines whether the destination object of that record is available. If the destination object is available, the BIG-IP GTM system stops searching, and it applies that destination object to resolve the DNS query. If the destination object is unavailable, the BIG-IP GTM continues searching the topology statement for the next topology record that matches the LDNS source IP address.

Note: There may be multiple topology records that match the LDNS source IP address, but the records are positioned in the topology statement after the chosen record. In this case, those other records with the same destination/LDNS pair that appear after the first chosen record are skipped.

Note: For specific details about the sorting priority for topology records, refer to K10721: Overview of the Longest Match algorithm (9.x - 10.x).

Longest Match (disabled)

If the Longest Match option is not selected, the BIG-IP GTM system scans the entire topology statement to find the matching topology record with the highest score (weight). With Longest Match disabled, the topology.inc file is no longer automatically sorted, and topology record scores (weights) will determine which topology record is applied first to the LDNS.

Geolocation database matching

BIG-IP GTM uses an IP geolocation database to determine the origin of connection requests. The BIG-IP GTM system uses the following process when matching an LDNS to a region:

  • An LDNS sends a DNS request to the BIG-IP GTM system.
  • If the wide IP uses the topology load-balancing method, the BIG-IP GTM system looks at the topology.inc file to determine where the region information is and whether the information references the geolocation database directly or is user-defined
    • If the region is user-defined, BIG-IP GTM system looks at the region.user file for the definition.
    • If the region contains a collection of geolocation database files, determine which database to reference.
  • BIG-IP GTM then looks at the LDNS IP address and finds the geolocation database file to determine to which region it would map. For example, if the region type is state, country, or continent, the system looks in the region databases. If the LDNS is found in the region databases, it has city, state, country, and continent data.

    For example:
     
    State=WA OR
    Country=US OR
    Continent=NA OR
    Org=F5 Networks OR
    ISP=AT&T

Topology Threshold

Note: The Threshold topology feature was removed from BIG-IP GTM 10.0.0. For more information, refer to K12858: The ACL Threshold topology feature was removed from BIG-IP GTM in version 10.0.0.

The Topology Threshold setting creates an exclusion list based on the topology record score of a given name resolution request. If the topology record score is lower than the Topology Threshold value, the name resolution request does not have access to the listed virtual servers. The default value is 0, which disables the setting.

Creating topology records

Topology load balancing mode requires that you first define the topology records. To create topology records, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Global Traffic.
  3. Click Topology.
  4. Click Create.
  5. On the Topology Record Builder screen, select the appropriate resource and is/is not statement from the Request Source menus.

    Note: The Request Source field specifies the origin of the incoming DNS request. The available origins are as follows:

    Continent
    Country
    IP Subnet
    ISP
    Region
    State (starting in BIG-IP GTM version 10.2.0)

  6. On the Topology Record Builder screen, select the appropriate resource and is/is not statement from the Destination menus.

    Note: The Destination field specifies the resource to which the BIG-IP GTM system directs the incoming DNS request. The available destinations are as follows:

    Continent
    Country
    Data Center
    IP Subnet
    ISP
    Pool
    Region
    State (starting in BIG-IP GTM version 10.2.0)

  7. Enter the appropriate value in the Weight field.

    Note: The BIG-IP GTM system uses the assigned weight to select a topology record when a request matches more than one topology record.

  8. Click Create.
