Topic

This article applies to BIG-IP ASM 13.x - 14.0.x. For information about other versions, refer to the following article:

  • K50801345: Mitigating credential stuffing attacks (14.1.x and later)

You should consider using this procedure under the following condition:

  • You suspect a login page is under credential stuffing attack and the malicious IPs are sourced from bots.

Description

If you suspect one of your login pages is under credential stuffing attack from malicious bots, you can protect your login pages against internet bot traffic by configuring a DoS profile and enabling the Proactive Bot Defense and Bot Signature Checking features.

Prerequisites

You must meet the following prerequisites to use these procedures:
  • You can access the Configuration utility.
  • You have configured a DNS resolver on the BIG-IP system to resolve DNS host names.
  • Client browsers accessing your web application are configured to accept JavaScript.
  • You suspect a login page is under credential stuffing attack and the malicious IPs are sourced from bots.

Procedures

  • Configuring Proactive Bot Defense
  • Configuring bot signature checking
  • Configuring traffic policy to limit the DoS profile to login pages only
  • Assigning the created DoS profile and the traffic policy to the impacted virtual server

Configuring Proactive Bot Defense

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > DoS Protection > DoS Profiles.
  3. Select Create.
  4. Enter a name for the DoS profile and select Finished.
  5. Select the name of the DoS profile that you just created.
  6. Select the Application Security tab.
  7. Select Edit next to Application Security, and then select the Enabled check box.
  8. Select Proactive Bot Defense.
  9. Select Edit next to Operational Mode and then select Always which causes Proactive Bot Defense to always run and helps prevent attacks from starting.
  10. Select Edit to change the following Proactive Bot Defense settings from their default values as needed:
    • Block requests from suspicious browsers and CAPTCHA settings are enabled by default. When these settings are enabled, the system validates browser legitimacy using a set of JavaScript challenges and blocks detected bots.
    • Grace Period is the length of time before the system blocks suspected bots. The default value is 300 seconds.
    • Cross-Domain Requests controls how the system responds when receiving a request for non-HTML resources (images, CSS, XML, JavaScript, and Flash) without a valid cookie and has a Referer header with a different domain than the host domain. The default setting is Allow All Requests.
    • The URL Whitelist setting denotes a list of URLs that are not blocked by Proactive Bot Defense.
  11. Select Update to save the DoS profile.

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

Configuring bot signature checking for the DoS profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > DoS Protection > DoS Profiles.
  3. Select the name of the DoS profile (or click Create to create a new DoS profile).
  4. Select the Application Security tab.
  5. Select Edit next to Application Security, and then select the Enabled check box.
  6. Select Bot Signatures.
  7. Select Edit next to Bot Signature Check, and select the Enabled check box.
  8. Select Edit to change the following Bot Signatures settings from their default values as needed:
    • For Bot Signature Categories, select actions the system takes for each type of bot category.
    • For Bot Signatures List, disable specific bot signatures during signature checking by selecting them from Available Signatures and moving them to Disabled Signatures.
  9. Select Update.

Configuring traffic policy to limit the dos profile to login pages only

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies > Policy List.
  3. Select Create.
  4. Enter a policy name.

    For example: LoginPBD

  5. For Strategy, select the appropriate option for your application environment.

    If you are performing this procedure to only limit DoS action on login pages, you can use the default setting, Execute first matching rule.

  6. Select Create Policy.
  7. Under Rules, select Create.
  8. Enter a name for the rule.

    For example: EnablePBD

  9. For Match all of the following conditions, select the Add icon (+)
  10. Choose the following controls:
    • HTTP URI, path, contains, any of, request.
    • Add the application login URLs in the any of control.
    • Add the following URL in the any of control: /TSPD/.
  11. Expand Do the following when the traffic is matched and enable l7dos from profile (choose the DoS profile that you created in the previous steps) at request time.
  12. Select Save.
  13. Under Rules, select Create a second rule and choose the following settings:
    • For Match all of the following conditions, leave the default setting, All traffic.
    • For Do the following when the traffic is matched, choose Disable l7dos at request time.
  14. Select Save.

Assigning the created DoS profile and the traffic policy to the impacted virtual server

Impact of procedure: Performing the following procedure activates PBD on the defined URLs in the traffic policy.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select  the name of the virtual server with which you want to associate the DoS profile.
  4. Select the Security tab and select Policies.
  5. In the DoS Protection Profile list, select Enabled.
  6. In the Profile list, select the name of the profile you want to associate with the virtual server.
  7. Select Update.
  8. In the Resources column for the virtual server in question, select Edit.
  9. Under Policies, select Manage.
  10. In Available, select the local traffic policy you created in previous steps and move it to Enabled.
  11. Select  Finished
