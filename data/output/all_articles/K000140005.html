Description

When downgrading a BIG-IP device e.g. from version 15.x to 14.x, you may encounter memory-related issues. These issues can manifest as extremely slow performance of the GUI and sporadic occurrences of the following error in the GUI: "Error getting auth token from login provider"

Environment

  • Downgrade to the lower version e.g. 15.x -> 14.x,
  • BIG-IP

Cause

The issue is caused by improper functioning and distribution of memory on the device. This can be disrupted after upgrading to a higher version and then immediately downgrading to a lower version. The memory appears to be clogged and poorly distributed.

Recommended Actions

To solve the issue of bad GUI performance and the appearance of "Error getting auth token from login provider" error, you can try to perform all the below steps in this specific order:

1. Set restjavad.useextramb to true:

tmsh modify sys db restjavad.useextramb value true

2. Set provision.extramb to an amount your system can accommodate. For example 500MB. This transfers memory from TMM to the host. For more information refer to K26427018: Overview of Management provisioning:

tmsh modify sys db provision.extramb value 2000

Note: You can adjust the value from 2000 since your device can warn you that there is not enough memory to extend this value. Then you need to narrow it down from 2000 to the lower value until the command successfully passes.

Important: The BIG-IP system experiences a temporary traffic interruption as it recovers from the restart of services, and devices configured as a high-availability (HA) pair may fail over. F5 recommends changing the Management memory size allocation during a scheduled maintenance window.

bigstart restart restjavad restnoded

3. Set provision.restjavad.extramb to 784MB, save the change, and restart restjavad:

tmsh modify sys db provision.restjavad.extramb value 784

tmsh save sys config

tmsh restart sys service restjavad

4. Run these commands to clear rest storage:

Important: If the BIG-IP is managed by a BIG-IQ, clear-rest-storage will disconnect the BIG-IP from BIG-IQ management. You'll need to remove the device from the BIG-IQ and rediscover it. For more information, refer to K56555353: How to determine if a BIG-IP is managed by a BIG-IQ, K42354921: How to remove a BIG-IP device from BIG-IQ, and K63557165: Discovering a BIG-IP device with a BIG-IQ system and importing the BIG-IP service configuration.

clear-rest-storage

tmsh restart sys service restjavad

Wait 1-2 minutes and run the below:

tmsh restart sys service restnoded

Additional Information

Provision only 2000 for "provision.extramb". If a larger value is allocated (anything above 2700), it will cause the restjavad to keep crashing. It's tracked under ID 839597.
