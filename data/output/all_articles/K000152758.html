K000152758: NGINX Ingress Plus Controller Failed to Resolve Local cluster Service FQDN and logs "no resolver defined to resolve" Error

Description

  • You are using NGINX Plus Ingress Controller
  • You set HTTP header "host" to a value of FQDN, as shown below
                proxy_set_header   Host  example-svc.my-namespace.svc.cluster.local;
  • You verified cluster resolver resolves defined FQDN to correct IP address
  • With the value of the HOST header set to FQDN, access to application fails with "HTTP error 502". 
  • This same error is also logged by the NGINX
                2025/12/12 120:12:12 [error] 1212#1212: 
                                *41012 request unexpected status: 502 while sending to client, 
                                client: 192.168.1.2, 
                                server: example-application.server.local, 
                                request: "GET /example HTTP/1.1", 
                                host: "example-application.server.local"
  • NGINX Ingress Controller logs error 'no resolver defined to resolve (FQDN)', as shown below
                2025/12/12 120:12:12 [error] 1212#1212: 
                                *41012 no resolver defined to resolve example-svc.my-namespace.svc.cluster.local, 
                                client: 192.168.1.2, 
                                server: example-application.server.local, 
                                request: "GET /example HTTP/1.1", 
                                host: "example-application.server.local"

Environment

  • NGINX Plus Ingress Controller
  • Name Resolution
  • Resolver
  • configMap
  • Service
  • Fully Qualified Domain Name (FQDN)

Cause

  • NGINX Plus Ingress Controller addresses the creation, modification or deletion of ingress or virtualServer resources via API call.
  • API call helps eliminate configuration-reload, thereby reducing load on resource as well removing service availability impact.
  • Since, the update take place via API call, NGINX Plus leverages a resolver to dynamically maintain and stay current with the IP address objects that are defined with FQDN
  • Hence, the cause is NOT defining a resolver from within NGINX Plus configuration

Recommended Actions

  • Edit "nginx-config" configMap of the NGINX Ingress Controller and update the data section with directive "resolver-addresses" and "resolver", as shown below
                kubectl edit cm -n <nginx-controller-namespace> nginx-config

Example CM

                                apiVersion: v1
                                data:
                                  resolver: 192.168.1.1 ;
                                  resolver-addresses: 192.168.1.1
                                kind: ConfigMap
                                metadata:
                                  name: nginx-conf
                                  namespace: nginx-ingress

Additional Information

  • NGINX Docs stats, if one use a DNS name (for example, kube-dns.kube-system.svc.cluster.local ) as a resolver address, NGINX Plus will resolve it using the system resolver during the start and on every configuration reload.
  • If the name cannot be resolved or the DNS server doesn’t respond, NGINX Plus will fail to start or reload.
  • To avoid this, we recommend using IP addresses as resolver addresses instead of DNS names. (Supported in NGINX Plus only).
