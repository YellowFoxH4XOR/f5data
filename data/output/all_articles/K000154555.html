K000154555: The HTTP profile can reset connections if the number of headers exceeds its configured limit displaying [F5RST: HTTP header count exceeded by server]

Type
Support Solution
Published
2025-08-30
Updated
2025-08-30
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000154555

Description

The virtual server will reset the connection with the error [F5RST: HTTP header count exceeded by server] if the HTTP response exceeds the maximum number of headers configured in the HTTP profile.

To provide a clearer understanding, here is an example:

 

1./ Based on the HTTP profile configuration, the maximum number of headers allowed is 16.

(tmos)# list ltm profile http http_test enforcement { max-header-count }
ltm profile http http_test {
    enforcement {
        max-header-count 16  
    }
}

2./ When the BIG-IP is bypassed, the server responds with 25 HTTP headers. 

# curl -I localhost/hello_world
HTTP/1.1 200 OK
Server: nginx/1.29.0
Date: Sat, 30 Aug 2025 15:04:41 GMT
Content-Type: text/plain
Content-Length: 62
Connection: keep-alive
Content-Security-Policy: default-src 'self'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
Referrer-Policy: no-referrer
Security: Test
Security: Test1
... 
Security: Test16

3./ The virtual server will reset the connection because the HTTP profile is configured to allow a maximum of only 16 headers, and not 25. 

config # tshark -ta -n -r  /shared/tmp/max_headers.pcap -Y "tcp.flags.reset eq 1"
   14 16:06:13.824277 192.168.0.37 ? 192.168.0.237 TCP 231 OUT s1/tmm3 : 35002 ? 80 [RST, ACK] Seq=86 Ack=608 Win=0 Len=0 [F5RST: HTTP header count exceeded by server]

4./ To resolve this issue, you must increase the maximum number of HTTP headers in the HTTP profile. The value should be set according to your application environment's requirements. In this case, a maximum of 30 headers will be sufficient.

(tmos)# list ltm profile http http_test enforcement { max-header-count }
ltm profile http http_test {
    enforcement {
        max-header-count 30
    }
}

5./ Please test the connection again. If the TCP RESET persists, increase the number of headers once more.

Environment

  • TCP Reset connections
  • HTTP max headers

Cause

HTTP profile configuration

Recommended Actions

  • Log in to the Configuration utility as the admin user.
  • Navigate to Local Traffic > Profiles > Services > HTTP.
  • Select the HTTP profile that handles your affected traffic.
  • Change the Maximum Header Count to a higher value, such as 30
  • Click Update.

Or go to the HTTP profile > settings > enforcement :
