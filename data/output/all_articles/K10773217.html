Known Issue

A Virtual Clustered Multiprocessing (vCMP) guest may fail to perform a subsequent software installation.

This issue occurs when all of the following conditions are met:

  • The vCMP host has two or more versions of software images in its software repository. For example, BIGIP-13.0.0.0.0.1645.iso and BIGIP-11.6.0.0.0.401.iso.
  • Using the block-device-image option in the TMOS Shell (tmsh), you successfully complete a software installation on the vCMP guest with one of the software images on the vCMP host. For example, BIGIP-13.0.0.0.0.1645.iso.
  • Subsequently, you attempt to perform another software installation on the vCMP guest using a software image version that is different from the first installation on the vCMP guest. For example, BIGIP-11.6.0.0.0.401.iso.

Impact

All subsequent attempts to install the software fails with errors.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • After you initiate a subsequent attempt to install software on the vCMP guest, the tmsh show sys software command displays the error message failed (Failure testing installer update status in <software image path>.) in the Status column, similar to the following example:

        ----------------------------------------------------------------------------------------------------------------------------------------------
        Sys::Software Status
        Volume  Slot  Product  Version     Build  Active                                                                                        Status
        ----------------------------------------------------------------------------------------------------------------------------------------------
        HD1.1      2   BIG-IP   13.0.0  0.0.1645     yes                                                                                      complete
        HD1.2      2   BIG-IP   13.0.0  0.0.1645      no                                                                                      complete
        HD1.3      2   BIG-IP   11.6.0   0.0.401      no  failed (Failure testing installer update status in /shared/images/BIGIP-11.6.0.0.0.401.iso.)

Workaround

To work around this issue, you can restart the lind process on all blades on the vCMP guest. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the vCMP guest
  2. To restart the lind process on all blades on the vCMP guest, type the following command:

    clsh --color=all bigstart restart lind
