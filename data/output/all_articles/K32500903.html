Description

You have recently created BIG-IP LTM objects using the GUI. The objects are cretaed on one of the devices of an HA pair and automatically synced to the peer device belonging to a device-group with auto-sync enabled.

The objects replicate to the peer device successfully, but after rebooting the peer device (the one receiving the synced configuration), you notice the objects have disappeared on both devices.

Audit logs do not show the deletion of the lost objects.

Environment

  • Objects dissapear after reboot
  • HA pair with auto sync enabled

Cause

This is expected behaviour for auto-sync device-groups. The BIG-IP syncs the configuration automatically to the peer, but only saves to the running configuration of the receiving device. It does not save the changes to the configuration files on each device in the device group.

If you reboot the BIG-IP peer that received the new configuration, without saving your configuration first, the BIG-IP system reloads your last saved configuration and you lose the last configuration change synchronized via auto-sync.

Note: A manual ConfigSync synchronizes changes to the peer devices and saves the running configuration to the configuration files on the peer devices.

Recommended Actions

You can simply make sure to save the configuration locally on each peer, after large configuration changes, with: tmsh save sys config.

Otherwise, you can consider enabling the save-on-auto-sync option on the device-group so the receiving device saves the recent changes to file, after receiving a sync from the device where the objects were originally created. For details refer to: K14624: Configuring the Automatic Sync feature to save the configuration on the remote devices.

Additional Information

  • The audit logs will not show the deletion of the Virtual Server or other lost objects, as they are not deleted manually.
  • Some logs that might help you identify that this is the cause for lost objects, are:
    • Syncs originated from the peer receiving the configuration with auto-sync, right after the reboot:

       

      notice mcpd[<PID>]: 010714a0:5: Sync of device group /Common/Sync-Failover-Group to commit id <commit id> /Common/LTM2.example.com from device /Common/LTM2.example.com complete.

    • Changes from incremental to full sync:

       

      notice mcpd[<PID>]: 0107168e:5: Unable to do incremental sync, reverting to full load for device group /Common/Sync-Failover-Group device %cmi-mcpd-peer-/Common/LTM2.example.com from commit id { <commit id> /Common/LTM2.example.com } to commit id { <commit id> /Common/LTM2.example.com }.

    • In some cases when ASM is provisioned, the admd log (/var/log/adm/admd.log), can show the deletion of the objects after the reboot:

       

      ADMD.Daemon0 [info] void CConfigurationListener::processVirtualServer(Cave::SchemaObjPtr&, bool&) : thread<0>: Delete Virtual Server </Common/http_example_vs>
