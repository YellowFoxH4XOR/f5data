Description

HTTPS health checks begin failing often. Sometimes, it can take many hours to show the symptom after upgrade where initially HTTPS health check works fine but after few hours depends on number of monitor instances, it starts failing without reasons.

Apart from health check failing, additional symptoms may occurs like OOM killer logs for bigd and other processes, daemon restarts, core files.

/var/log/kern.log has similar to the following error

err kernel: Out of memory: Kill process 12910 (bigd) score 302 or sacrifice child
err kernel: Killed process 12910, UID 0, (bigd) total-vm:4052244kB, anon-rss:1117876kB, file-rss:15044kB


/var/log/messages, /var/log/user.log have similar to the following messages:

Notice     logger Finished writing 708464642 bytes for core file: /var/core/bigd.bld0.0.5.core.gz for PID 15941
Notice     logger Started writing core file: /var/core/bigd.bld0.0.5.core.gz for PID 15941
 

Environment

  • BIG-IP v12.1.5.3 
  • Pool with HTTPS monitor.
  • Pool with SSL based monitor.
  • After software upgraded to 12.1.5.3.
     

Cause

Bug ID 625156, and described in: K50524736: Bigd process memory leak after updating to BIG-IP 12.1.5.3.

Recommended Actions

Upgrade to fixed version 12.1.6.

RSS is the Resident Set Size and is used to show how much memory is allocated to that process and is in RAM.
RSS include memory from shared libraries as long as the pages from those libraries are actually in memory and all stack and heap memory, however, It does not include memory that is swapped out.
