K49466324: SNAT Pool doesn't work for VPN traffic

Type
Support Solution
Published
2020-07-03
Updated
2023-10-16
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.0
Source
https://my.f5.com/manage/s/article/K49466324

Description

  • SNAT Pool is configured in Network Access resource
  • SNAT doesn't work for VPN traffic
  • If you run a tcpdump on BIG-IP filtering by random VPN client ip address you'll see that the client is _not_ handled by internal APM forwarding Virtual Server _tmm_apm_fwd_vip
  • In the below output traffic is handled by forwarding Virtual Server /Common/test_forwarding. Source ip address is not changed:
02:38:57.644570 IP 192.168.77.5 > 10.0.0.1: ICMP echo request, id 1, seq 14134, length 40 in slot1/tmm1 lis=/Common/test_forwarding
02:38:57.644612 IP 192.168.77.5 > 10.0.0.1: ICMP echo request, id 1, seq 14134, length 40 out slot1/tmm1 lis=/Common/test_forwarding

Environment

Relevant environmental factors specific to the topic

  • APM
  • Network Access VPN
  • SNAT Pool

Cause

In order for VPN traffic to use SNAT pool it should be handled by internal forwarding Virtual Server _tmm_apm_fwd_vip

Recommended Actions

The issue could be resolved in multiple ways
  • Enable forwarding Virtual Server only on specific VLANs in VLAN and Tunnel Traffic field. You need to exclude Connectivity profile tunnel interface from the VLANs list
or
  • Create a dedicated forwarding Virtual Server for VPN traffic:
  1. Enable it on Connectivity profile tunnel interface in VLAN and Tunnel Traffic field
  2. In the Source Address field specify a range of VPN clients ip addresses.
  3. Enable SNAT Pool on the Virtual Server in Source Address Translation field
