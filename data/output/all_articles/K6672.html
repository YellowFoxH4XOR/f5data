K6672: An SSL Proxy with an HTTP header insert fails if the POST body is less than the TCP maximum segment size

Known Issue

This is the result of a known issue. HTTP POST connections to an SSL proxy will fail when all of the following conditions are met:

  • An HTTP header insert is configured on the SSL proxy level.
  • The HTTP POST request data is smaller than the TCP maximum segment size (MSS). The entire request is contained in one packet.
  • The web server issues a 100 Continue response prior to sending a 200 Server OK response.

HTTP POST connections to the SSL Proxy will not fail because of this issue, if either one of the following conditions is met:

  • An HTTP header insert is configured at the pool level.
  • The HTTP POST request data is larger than the TCP MSS. The request is contained in more than one packet.

F5 Networks Product Development tracked this issue as CR66649.

Workaround

You can work around this issue if the desired HTTP header insert value is supported at the following pool levels:

client_addr
client_port
server_addr
server_port
ip_tos
link_qos

It is not possible to work around this issue if the desired HTTP header insert value is only supported at the following SSL Proxy levels:

  • Cipher
  • Certificate
    • Version
    • Serial Number
    • Signature Algorithm
    • Issuer
    • Validity
    • Subject
    • Subject Public Key
    • X509 Extentions
    • Certificate
    • Certificate Hash
  • Client Session ID
  • Authorization Header
  • Remote-User Header

To configure the HTTP header insert value at the pool level, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Pools.
  3. Click the pool you want to configure.
  4. Type the desired value in the Header To Insert field.
  5. Click Apply.
