Description

when attempting to load or reload nginx the following error is seen:

~$ sudo nginx -s reload
{
"completed_successfully": false,
"event": "configuration_load_failure",
"error_message": "Failed to read /opt/app_protect/config/config_set.json: open /opt/app_protect/config/config_set.json: permission denied",
"softwareVersion": "4.14.0",
"componentVersions": {
"wafEngineVersion": "11.336.0",
"wafNginxVersion": "5.342.0"
}
}
nginx: [alert] APP_PROTECT No "error_line_number" found in error message
nginx: [error] APP_PROTECT {"completed_successfully":false,"event":"configuration_load_failure","error_message":"Failed to read /opt/app_protect/config/config_set.json: open /opt/app_protect/config/config_set.json: permission denied","softwareVersion":"4.14.0","componentVersions":{"wafEngineVersion":"11.336.0","wafNginxVersion":"5.342.0"}}

This behavior has been seen when using  programmibilty tools to deploy NGINX App Protect either for upgrade or fresh install.

Environment

NGINX App Protect

Cause

umask value got set to 0027, which means other users have no read permission to the files by default

Recommended Actions

after nap installed you can set the permissions 

# setfacl -d -m o::r /opt/app_protect/config/
# setfacl -d -m u::rw /opt/app_protect/config/
# setfacl -d -m g::r /opt/app_protect/config/

alternatively you could set 

# umask 0022

on the deployment before installing nap
