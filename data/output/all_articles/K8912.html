K8912: Inserting an X-Via HTTP header to identify connections that have passed through the BIG-IP WebAccelerator

You can configure the BIG-IP WebAccelerator version 9.4.x system to identify HTTP connections that have passed through a proxy device. To do so, you can insert a Via HTTP header using the sendProxyViaHeader entry in the pvsystem.conf file. The Via HTTP header will appear similar to the following example:

Via: 1.1 wa-4500-1.bfs.wanopt.f5net.com (Pivia Performance Server 5.2.0 255163)

Note: For information about configuring the WebAccelerator to insert the Via HTTP header using the sendProxyViaHeader option, refer to K7589: Overview of the Via HTTP header.

However, F5 Networks recommends identifying HTTP connections that have passed through the BIG-IP WebAccelerator by using an iRule to insert an X-Via HTTP header. Some benefits of using an iRule are as follows:

  • Ability to customize the HTTP header:

    • Identify a proxied connection without disclosing hostname or IP address information.
    • Ability to remove legacy Pivia branding information.
  • Configurable through the Web GUI; does not require command line access.

To insert an X-Via HTTP header into an HTTP response as it is passed from the server to the client, associate an iRule similar to the following example with the virtual server:

when HTTP_RESPONSE {
  HTTP::header insert "X-Via" "<non-IP identifying ID>"
}

To insert an X-Via HTTP header into an HTTP request as it is passed from the client to the server, associate an iRule similar to the following example with the virtual server:

when HTTP_REQUEST {
  HTTP::header insert "X-Via" "<non-IP identifying ID>"
}

Note: Replace <non-IP identifying ID> with the desired message to indicate the connection has been proxied by the BIG-IP WebAccelerator.
