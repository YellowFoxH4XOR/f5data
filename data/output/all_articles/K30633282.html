Description

In case of OSPF flapping or other problems, gathering detailed captures and data is crucial to see what is causing issue.

NOTE: Article describes POA that can be shared with customers. Properly executed is providing basic data for ES escalation.

Open Shortest Path First (OSPF) is a link-state routing protocol that was developed for IP networks and is based on the Shortest Path First (SPF) algorithm. OSPF is an Interior Gateway Protocol (IGP).

In an OSPF network, routers or systems within the same area maintain an identical link-state database that describes the topology of the area. Each router or system in the area generates its link-state database from the link-state advertisements (LSAs) that it receives from all the other routers or systems in the same area and the LSAs that itself generates. An LSA is a packet that contains information about neighbors and path costs. Based on the link-state database, each router or system calculates a shortest-path spanning tree, with itself as the root, using the SPF algorithm.

  • BIG-IP advanced routing

Cause

Not know until logs and captures are available.

Recommended Actions

  1. Take an initial QKview

    # ensure to be in bash mode
    # qkview -s0 -f "$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)".qkview
     
  2. Enable OSPF + NSM debug:

       # imish
       # en
       # conf t
       # log file /var/log/zebos.log
       # debug ospf all
       # debug nsm all
       # wr
       # end
       # quit
       
  3. Start a packet trace:

       # tcpdump -s0 -nni 0.0:nnn -w /var/tmp/tcpdump.pcap 'ip proto ospf'

    NOTE: please make sure that if you are using route domains, please specify route domain first and if needed switch to it using rdsh.
     
  4. Make sure that flapping is occurring.
     
  5. Stop tcpdump after issue was caught.  Disable OSPF + NSM debug:

       # imish
       # en
       # conf t
       # no log file
       # no debug nsm
       # no debug ospf
       # wr
       # end
       # quit
       
  6. Take a final QKview

    # ensure to be in bash mode
    # qkview -s0 -f "$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)".qkview
     
  7. Logs are probably large (and therefore truncated) so please get a tarball with full logs as well

    # tar -czpf /var/tmp/logfiles.tar.gz /var/log/*
     
  8. Share Qkviews, archive of logs and packet captures with support.
