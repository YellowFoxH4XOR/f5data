Topic

This article provides an example on the steps you can take to configure and verify Lightweight Directory Access Protocol over SSL (LDAPS) remote authentication integration with Microsoft Active Directory (AD) for F5OS-C/A administrative users.

Description

The Lightweight Directory Access Protocol (LDAP) can be used for accessing and maintaining distributed directory information over a network. By default, the Microsoft AD domain service listens on port 389 for insecure LDAP requests and port 636 for LDAPS requests.

SSL certificate for LDAPS

If the domain controller does not have a valid SSL certificate installed, an LDAPS client may fail to connect to the domain controller over port 636 for LDAPS requests. If you prefer to use LDAPS instead of LDAP, you must ensure that the domain controller is installed with either a Certificate Authority (CA) signed or self-signed SSL certificate. To verify if the domain controller is properly installed with a valid certificate, you can use the LDP tool (ldp.exe) on the domain controller. The LDP tool is installed on the domain controller by default as part of the AD management feature. Using the LDP tool, connect to the domain controller Fully Qualified Domain Name (FQDN) over port 636 and check the SSL option. If the LDP tool fails to connect and reports Error <0x51> Fail to connect, then the domain controller does not have a valid SSL certificate. You may want to refer to the following Microsoft article for the requirements and process for requesting a CA signed certificate for enabling LDAPS on the domain controller:

  • Enable LDAP over SSL with a third-party certification authority

    Note: This link takes you to a resource outside of MyF5. The third party could remove the document without our knowledge.

Alternatively, you can generate a self-signed SSL certificate for the domain controller if you do not have a certificate authority server. You can use the PowerShell command New-SelfSignedCertificate to generate the self-signed certificate using the following command syntax:

New-SelfSignedCertificate -DnsName <FQDN of the domain controller>, <name of the domain controller> -CertStoreLocation Cert:\LocalMachine\My

For example,

New-SelfSignedCertificate -DnsName DC01.example.myf5.lab, DC01 -CertStoreLocation Cert:\LocalMachine\My

You must then copy the self-signed certificate from the domain controller's certificate Personal store to the domain controller's certificate Trusted Root Certification Authorities store. To do so, launch the certificate management tool certlm.msc from the command prompt as the administrative user. Then locate the self-signed certificate in Personal > Certificates, and copy it to Trusted Root Certification Authorities > Certificates. Then verify the LDAPS connectivity using the LDP tool on the domain controller.

Attributes for F5OS-C/A user roles

LDAP authentication on F5OS-C/A requires that the remote users are assigned valid uidNumber and gidNumber attributes. The value of the gidNumber attribute must correspond to the value of the group ID of the F5OS-C/A role you want the remote user to assume when the remote user logs in. The F5OS-C/A role assumed by the remote user determines the user's privilege on the system. For information about the various roles and their privileges as well as their default group IDs for VELOS chassis, VELOS partition and F5 rSeries, refer to the following manuals:

  • F5 VELOS/F5OS-C: User roles overview section of the Authentication & Access chapter of the VELOS Systems: Administration and Configuration manual
  • F5 rSeries/F5OS-A: User roles overview section of the User Management chapter of the F5 rSeries Systems: Administration and Configuration manual

By default the users and security groups in Microsoft AD do not have these two attributes. If you are creating a new AD user, you should use the PowerShell command New-ADUser to define the uidNumber and gidNumber attributes on the Microsoft AD domain controller. If you are planning to use an existing AD user for remote authentication, you should use the PowerShell command Set-ADUser to define these two attributes for the user on the Microsoft AD domain controller.

For example, you would use the following PowerShell command to create a new AD user f5osadmin with attributes uidNumber 5001 and gidNumber 9000 in Microsoft AD:

New-ADUser -Name "f5osadmin" -DisplayName "f5osadmin" -AccountPassword (ConvertTo-SecureString "password" -AsPlainText -Force) -Enabled $true -OtherAttributes @{'uidNumber'=5001;'gidNumber'=9000}

In another example, you would use the following PowerShell command to add the attributes uidNumber 5002 and gidNumber 9001 to an existing user f5osoper in Microsoft AD:

Set-ADUser -Identity "f5osoper" -Add @{'uidNumber'=5002; 'gidNumber'=9001}

Additionally if you are creating a new security group for the AD user, you should designate the new security group as the non-primary group for the AD user. You should also assign the value of the group ID of the F5OS-C/A role you want the AD user to assume to the gidNumber attribute of the new security group instead of the assigning directly to the AD user. For example, you created a new security group f5os_admins_group and added the remote AD user f5osadmin to the group while keeping f5osadmin as a member of the default Domain Users group. If you want the f5osadmin user to assume the admin role when logging in to the F5OS-C/A device, you would assign the following uidNumber and gidNumber to the following user and groups:

remote AD user / groupuidNumbergidNumber
f5osadmin5001100
Domain Users (primary group)Not Applicable100
f5os_admins_groupNot Applicable9000

You can use the PowerShell command New-ADGroup to define the gidNumber attribute when creating the new security group; if you are planning to use an existing AD security group for the user, you should use the PowerShell command Set-ADGroup to define the gidNumber for the security group.

LDAP authentication settings on F5OS-C/A system

Note the following LDAP authentication settings that may be useful in this deployment scenario and the function/behavior of each of their values:

  • binddn

    The service account used to bind to the remote LDAP server for LDAP search. This can be in the form of distinguished name (for example, cn=admin,dc=example,dc=myf5,dc=lab) or account name in the case of Microsoft AD.

  • bindpw

    The password of the service account used to bind to the remote LDAP server for LDAP search.

  • base

    The base distinguished name from which to start the search for the LDAP user. For example, dc=example,dc=myf5,dc=lab.

  • bind_timelimit

    Determines the maximum amount of time (in seconds) that the system waits to receive an LDAP response from the remote LDAP server before aborting the read attempt. The default is 10 seconds.

  • timelimit

    Determines the maximum amount of time (in seconds) that the system waits before timing out when attempting to reach the remote LDAP server. The default is 0 seconds.

  • idle_timelimit

    Determines the maximum amount of time (in seconds) that an LDAP connection can be inactive before the connection is closed. The default is 0 seconds which means indefinite.

  • ldap_version

    Determines the version of the LDAP protocol to use. The default is 3.

  • ssl

    Determines whether to use SSL/TLS to encrypt the authentication data between the remote LDAP server and the system. The description for each value is as follows:

    • on - Use SSL/TLS to secure all connections.
    • off - Do not use SSL/TLS.
    • start_tls - Starts a connection in unencrypted mode on a port configured for plain text and negotiates the encryption with the remote LDAP server.
  • tls_cacert

    This setting should contain the PEM-encoded of either an SSL/TLS cert from a CA which signed the cert of the remote LDAP server or the self-signed cert of the remote LDAP server.

  • tls_reqcert

    Determines what checks to perform on a server-supplied SSL cert. The description for each value is as follows:

    • allow - The system requests for the SSL cert from the LDAP server. If no SSL cert is presented by the LDAP server, the session proceeds normally. If a bad cert is presented by the LDAP server, the cert is ignored and the session proceeds normally.
    • demand or hard - The system requests for the SSL cert from the LDAP server. If no SSL cert or a bad cert is presented by the LDAP server, the session is immediately terminated.
    • never - SSL cert is not required.
    • try - The system requests for the SSL cert from the LDAP server. If no SSL cert is presented by the LDAP server, the session proceeds normally. If a bad cert is presented by the LDAP server, the session is immediately terminated.
  • active_directory

    This setting can only accept two values: true or false. If you are configuring the system to authenticate against Microsoft AD, then you should set this to true.

  • chase_referrals

    By default, the chase-referrals setting is set to true. The chase-referrals setting is an LDAP protocol feature for the purpose of referring the LDAP client to another LDAP server if the original LDAP server does not have the record. F5OS-C/A systems act as an LDAP client in this situation and accept the URL referral to another LDAP server from the original LDAP server when the chase-referrals setting is set to true. Depending on your LDAP or Microsoft AD environment, this may cause delays and timeouts during an LDAP authentication session.

Prerequisites

  • The Active Directory service is enabled with LDAP over SSL (LDAPS) and a valid SSL certificate is installed on all domain controllers. For more information, refer to the SSL certificate for LDAPS section in this article.
  • A user account in the Active Directory for LDAP binding. This user account must be a member of the built-in Domain Users group in the Active Directory.
  • You have access to the PowerShell utility as a member of the administrators group on the domain controller or member of the Domain Admins group in the Active Directory. This is used for creating users on the Active Directory for remote authentication.
  • You are familar with LDAP protocol and its settings.

Procedures

  • Create/Modify AD user and group with the uidNumber and gidNumber attributes
  • Create the LDAPS server group on the F5OS-C/A system
  • Configure the LDAPS authentication settings on the F5OS-C/A system
  • Enable LDAPS authentication on the F5OS-C/A system

Create/Modify AD user and group with the uidNumber and gidNumber attributes

Using the example described under the Attributes for F5OS-C/A user roles section in this article, you would be performing the following tasks on the Microsoft AD domain controller using PowerShell commands:

    Set-ADGroup -identity "Domain Users" -add @{'gidNumber'=100}

Create the LDAPS server group on the F5OS-C/A system

To create the LDAPS server group on the F5OS-C chassis/F5OS-C partition/F5OS-A system, perform any one of the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • Use the CLI
  • Use the REST API

Use the CLI

  1. Log in to the CLI of the F5OS-C chassis/F5OS-C partition/F5OS-A system as the F5OS-C chassis admin/F5OS-C partition admin/F5OS-A admin respectively.
  2. Enter config to enter the configuration mode.
  3. Enter the following command syntax to create a new LDAPS server group:

    system aaa server-groups server-group <group name> config name <group name> type < LDAP | OCSP | RADIUS | TACACS >

    For example,

    system aaa server-groups server-group adservergroup config name adservergroup type LDAP

  4. Enter the following command syntax to define the remote LDAPS server name and address:

    servers server <LDAPS server IP address or FQDN> config address <LDAPS server IP address or FQDN>

    For example,

    servers server DC01.example.myf5.lab config address DC01.example.myf5.lab

  5. Enter the following command syntax to define the listening port and LDAP type:

    ldap config auth-port <LDAPS server listening port> type <ldap | ldaps>

    For example,

    ldap config auth-port 636 type ldaps

  6. Enter the following command to commit the changes and exit configuration mode:

    commit and-quit

  7. To verify that the configuration is committed, enter the following command syntax:

    show running-config system aaa server-groups server-group <server group name>

    Using the example from previous steps, enter the following example command:

    show running-config system aaa server-groups server-group adservergroup

    The command should return an output similar to the following example:

    system aaa server-groups server-group adservergroup
     config name adservergroup
     config type LDAP
     servers server DC01.example.myf5.lab
      config address DC01.example.myf5.lab
      ldap config auth-port 636
      ldap config type ldaps
     !
    !

Use the REST API

  1. Log in to the CLI of the F5OS-C/A system as the root user. Alternatively, you can log in to a system with the curl utility installed.
  2. Create a new LDAPS server group using the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X POST "https://<ip address>/api/data/openconfig-system:system/aaa/server-groups" -d '{ "openconfig-system:server-group": [ { "name": "<server group name>", "config": { "name": "<server group name>", "type": "f5-openconfig-aaa-ldap:LDAP" }, "servers": { "server": [ { "address": "<LDAPS server IP address or FQDN>", "config": { "address": "<LDAPS server IP address or FQDN>" }, "f5-openconfig-aaa-ldap:ldap": { "config": { "auth-port": <LDAPS server port>, "type": "f5-openconfig-aaa-ldap:ldaps" } } } ] } } ] }'

    In the previous syntax, note the following:

    • Replace <username> and <password> with the username and password that has administrative access to the F5OS-C/A system.
    • If you are running the command from the F5OS-C/A system CLI, replace <ip address> with localhost.
    • If you are not running the command from the F5OS-C/A system CLI, replace <ip address> with the management IP address of the F5OS-C/A system.
    • Replace <server group name> with the name of the server group you want.
    • Replace <LDAPS server IP address or FQDN> with the either the IP address of the LDAPS server or its FQDN. If you are planning to use the LDAPS server FQDN, ensure the DNS server used by the F5OS-C/A system can resolve the LDAPS server FQDN.
    • Replace <LDAPS server port> with the port your LDAPS server is listening on. By default, typical LDAPS server listens on port 636. 

    For example, if you are running it from the F5OS-C/A system CLI, enter the following command:

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X POST "https://localhost/api/data/openconfig-system:system/aaa/server-groups" -d '{ "openconfig-system:server-group": [ { "name": "adservergroup", "config": { "name": "adservergroup", "type": "f5-openconfig-aaa-ldap:LDAP" }, "servers": { "server": [ { "address": "DC01.example.myf5.lab", "config": { "address": "DC01.example.myf5.lab" }, "f5-openconfig-aaa-ldap:ldap": { "config": { "auth-port": 636, "type": "f5-openconfig-aaa-ldap:ldaps" } } } ] } } ] }'

    Note that the command does not return an output. To verify that the system has successfully processed the command and committed the configuration, proceed to perform the next step.

  3. Verify that the configuration was committed by entering the following command syntax:

    curl -X GET -H "Content-Type: application/yang-data+json" -sku <username>:<password> "https://<ip address>/api/data/openconfig-system:system/aaa/server-groups/server-group" | jq -M .

    In the previous syntax, note the following:

    • Replace <username> and <password> with the username and password that has administrative access to the F5OS-C/A system.
    • If you are running the command from the F5OS-C/A system CLI, replace <ip address> with localhost.
    • If you are not running the command from the F5OS-C/A system CLI, replace <ip address> with the management IP address of the F5OS-C/A system.

    For example,

    curl -X GET -H "Content-Type: application/yang-data+json" -sku admin:admin "https://localhost/api/data/openconfig-system:system/aaa/server-groups/server-group" | jq -M .

    The command should return an output similar to the following example:

Configure the LDAPS authentication settings on the F5OS-C/A system

To configure the LDAPS authentication settings on the F5OS-C/A system, perform either of the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • Use the CLI
  • Use the REST API

Use the CLI

  1. Log in to the CLI of the F5OS-C chassis/partition/F5OS-A system as the F5OS-C chassis/partition admin/F5OS-A admin respectively.
  2. Enter config to enter the configuration mode.
  3. Enter the following command syntax to configure the LDAPS authentication settings:

    system aaa authentication ldap binddn <LDAP binding user account name> base [ <LDAP Base DN name-value pairs> ] ssl < on | off | start_tls> tls_cacert "<PEM-encoded CA or self-signed SSL certificate of the LDAP server>" tls_reqcert < allow | demand | hard | never | try > active_directory < false | true > [chase-referrals < false | true >] bindpw

    Note: By default, the chase-referrals setting is set to true. The chase-referral setting is an LDAP protocol feature for the purpose of referring the LDAP client to another LDAP server if the original LDAP server does not have the record. F5OS-C/A systems act as an LDAP client in this situation and accept the URL referral to another LDAP server from the original LDAP server when the chase-referrals setting is set to true.

    Using the LDAP binding user account adldapbinduser with base DN dc=example,dc=myf5,dc=lab and ssl enabled with the CA certificate of the LDAP server, you would enter the following example command:

    system aaa authentication ldap binddn adldapbinduser base [ dc=example,dc=myf5,dc=lab ] ssl on tls_cacert "-----BEGIN CERTIFICATE-----\nMIIDgTCCAmmgAwIBAgIQPO5XpwyXLYVGugCVGV5Y9jANBgkqhkiG9w0BAQsFADBT\n<truncated for brevity>\no+imHv/K991ccyDCfHl/0epPmJVtv3kkw7GkXl2hA5VoBv3LVA==\n-----END CERTIFICATE-----" tls_reqcert demand active_directory true bindpw

    The command then prompts you for a password similar to the following example:

    (<AES encrypted string>):

    Enter the LDAP binding user account password at the prompt.

  4. Enter the following command to commit the changes and exit configuration mode:

    commit and-quit

  5. To verify that the configuration is committed, enter the following command:

    show running-config system aaa authentication ldap

    The command should return an output similar to the following example:

    system aaa authentication ldap binddn adldapbinduser
    system aaa authentication ldap bindpw <LDAP binding user account password hash>
    system aaa authentication ldap base [ dc=example,dc=myf5,dc=lab ]
    system aaa authentication ldap bind_timelimit 10
    system aaa authentication ldap timelimit 0
    system aaa authentication ldap idle_timelimit 0
    system aaa authentication ldap ldap_version 3
    system aaa authentication ldap ssl on
    system aaa authentication ldap active_directory true
    system aaa authentication ldap tls_reqcert demand
    system aaa authentication ldap tls_cacert "-----BEGIN CERTIFICATE-----\nMIIDgTCCAmmgAwIBAgIQPO5XpwyXLYVGugCVGV5Y9jANBgkqhkiG9w0BAQsFADBT\n<truncated for brevity>\no+imHv/K991ccyDCfHl/0epPmJVtv3kkw7GkXl2hA5VoBv3LVA==\n-----END CERTIFICATE-----"
    system aaa authentication ldap chase-referrals true

Use the REST API

  1. Log in to the CLI of the F5OS-C/A system as the root user. Alternatively, you can log in to a system with the curl utility installed.
  2. Configure the LDAP authentication settings using the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X PATCH "https://<ip address>/api/data/openconfig-system:system/aaa/authentication/f5-openconfig-aaa-ldap:ldap" -d '{ "f5-openconfig-aaa-ldap:ldap": { "f5-openconfig-aaa-ldap:binddn": "<user account name>", "f5-openconfig-aaa-ldap:bindpw": "<user account password>", "f5-openconfig-aaa-ldap:base": [ "<name-value pairs>" ], "f5-openconfig-aaa-ldap:ssl": "< on | off | start_tls >", "f5-openconfig-aaa-ldap:active_directory": < false | true>, "f5-openconfig-aaa-ldap:tls_reqcert": "< allow | demand | hard | never | try >", "f5-openconfig-aaa-ldap:tls_cacert": "<SSL certificate>"[, "f5-openconfig-aaa-ldap:chase-referrals": < false | true >] } }'

    • Replace <username> and <password> with the username and password that has administrative access to the F5OS-C/A system.

    • If you are not running the command from the F5OS-C/A system CLI, replace <ip address> with the management IP address of the F5OS-C/A system.
    • Replace <user account name> with the LDAP binding user account.
    • Replace <user account password> with the LDAP binding user account password.

    • Select one of these values < allow | demand | hard | never | try > for the tls_reqcert setting.

Enable LDAPS authentication on the F5OS-C/A system

To enable LDAPS authentication on the F5OS-C/A system, perform either of the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • Use the CLI
  • Use the REST API

Use the CLI

  1. Log in to the CLI of the F5OS-C chassis/partition/F5OS-A system as the F5OS-C chassis/partition admin/F5OS-A admin respectively.
  2. Enter config to enter the configuration mode.
  3. Enter the following command syntax to enable LDAPS authentication:

    system aaa authentication config authentication-method [ <existing authentication methods> LDAP_ALL ]

    For example, you would enter the following command if the existing authentication method is only local user database (LOCAL) and you want to enable LDAP/LDAPS for remote authentication:

    system aaa authentication config authentication-method [ LOCAL LDAP_ALL ]

  4. Enter the following command to commit the changes and exit configuration mode:

    commit and-quit

  5. To verify that the configuration is committed, enter the following command:

    show running-config system aaa authentication config authentication-method

    The command should return an output similar to the following example:

    system aaa authentication config authentication-method [ LOCAL LDAP_ALL ]

  6. You can now proceed to log in to the F5OS-C/A system using the LDAPS remote user account(s). In the event that the configured LDAPS server is unavailable to respond to remote authentication requests, the F5OS-C/A system uses only locally defined user accounts such as the default admin and root accounts in the local user account database for authentication.

Use the REST API

  1. Log in to the CLI of the F5OS-C/A system as the root user. Alternatively, you can log in to a system with the curl utility installed.
  2. Enable LDAPS authentication using the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X PATCH "https://<ip address>/api/data/openconfig-system:system/aaa/authentication/config" -d '{ "openconfig-system:config": { "authentication-method": [ <existing authentication methods>, "f5-openconfig-aaa-ldap:LDAP_ALL" ] } }'

    In the previous syntax, note the following:

    • Replace <username> and <password> with the username and password that has administrative access to the F5OS-C/A system.
    • If you are running the command from the F5OS-C/A system CLI, replace <ip address> with localhost.
    • If you are not running the command from the F5OS-C/A system CLI, replace <ip address> with the management IP address of the F5OS-C/A system.

    For example, if you are running it from the F5OS-C/A system CLI, enter the following command:

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X PATCH "https://localhost/api/data/openconfig-system:system/aaa/authentication/config" -d '{ "openconfig-system:config": { "authentication-method": [ "openconfig-aaa-types:LOCAL", "f5-openconfig-aaa-ldap:LDAP_ALL" ] } }'

    Note that the command does not return an output. To verify that the system has successfully processed the command and committed the configuration, proceed to perform the next step.

  3. Verify that the configuration was committed by entering the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X GET "https://<ip address>/api/data/openconfig-system:system/aaa/authentication/config/authentication-method"

    In the previous syntax, note the following:

    • Replace <username> and <password> with the username and password that has administrative access to the F5OS-C/A system.
    • If you are running the command from the F5OS-C/A system CLI, replace <ip address> with localhost.
    • If you are not running the command from the F5OS-C/A system CLI, replace <ip address> with the management IP address of the F5OS-C/A system.

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X GET "https://localhost/api/data/openconfig-system:system/aaa/authentication/config/authentication-method"

    The command should return an output similar to the following example:

    {
      "openconfig-system:authentication-method": ["openconfig-aaa-types:LOCAL", "f5-openconfig-aaa-ldap:LDAP_ALL"]
    }

  4. You can now proceed to log in to the F5OS-C/A system using the LDAPS remote user account(s). In the event that the configured LDAPS server is unavailable to respond to remote authentication requests, the F5OS-C/A system uses only locally defined user accounts such as the default admin and root accounts in the local user account database for authentication.
