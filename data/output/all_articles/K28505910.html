Known Issue

The Traffic Management Microkernel (TMM) may produce a core file during a failsafe condition.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured for high availability (HA) Virtual Local Area Network (VLAN) failsafe.
  • There is no network activity (other than BIG-IP monitor-generated traffic) on the configured VLAN for 75 percent of the failsafe timeout value. For example, 75 percent of the VLAN failsafe timeout of 90 seconds would be 67.5 seconds.

Impact

The BIG-IP system temporarily fails to process traffic while the TMM process restarts. If the BIG-IP system is configured for HA, the system fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file in the /shared/core directory.
  • Your BIG-IP system logs a SIGFPE to the /var/log/tmm file at the same time TMM produces a core file and restarts.
  • In one of the /var/log/tmm files, you observe error messages that appear similar to the following example:

    notice panic: ../base/sa_trans.c:401: Assertion "refcount valid" failed.
    notice ** SIGFPE **

Workaround

To work around this issue, you can modify the failover.vlanfailsafe.resettimeronanyframe system database variable, additionally you can also increase the VLAN failsafe timeout value where 75 percent of the value is the desired timeout. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure does not alleviate the BIG-IP system from producing a TMM core file and subsequent failover. The procedure only configures the BIG-IP system to experience the impact of the issue at the desired failsafe timeout.  

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To enable the failover.vlanfailsafe.resettimeronanyframe system database variable, type the following command:

    modify /sys db failover.vlanfailsafe.resettimeronanyframe value enable

    Note: Enabling the failover.vlanfailsafe.resettimeronanyframe database variable will allow BIG-IP monitor-generated traffic to reset the VLAN failsafe timer.

  3. To modify the VLAN failsafe timeout value to 4/3 of the intended timeout value, use the following command syntax: 

    modify /net vlan <vlan name> failsafe-timeout <timeout value>  

    For example:  

    modify /net vlan vlan-C failsafe-timeout 120

    Note: The actual failover will occur at 75 percent of the configured timeout value of 120, which is 90 seconds.

  4. Save the configuration changes by typing the following command:

    save /sys config

  5. To exit tmsh, type the following command:

    quit
