Description

After upgrading BIG-IP APM from version 17.1.2.1 to 17.1.3, users attempting to access clientless VPN resources may encounter the error:

"Access was denied by the access policy. This may be due to a failure to meet access policy requirements."

APM logs may show:

  • Rule evaluation failed with error: invalid command name "F5vSd2NpQjdXMjFqWjJWMElIdHpaWE56YVc5dUxtRmtMbXhoYzNRdVlYUjBjaTV0WlcxaVpYSlBPXjFkZlE9PQ=="

  • Variable Assignment Agent: session variable 'session.ad.last.attr.memberOf' not created due to invalid TCL Expression

  • Access policy result: Logon_Deny

Environment

  • Product: BIG-IP APM
  • Version: 17.1.3 (upgrade from 17.1.2.1)
  • Configuration: Access Policy using Variable Assign agents referencing Active Directory group membership (e.g., session.ad.last.attr.memberOf) and custom expressions in Visual Policy Editor (VPE).
  • Authentication: Active Directory, OTP/MFA

Cause

  • The Variable Assign agent in the access policy contained a base64-encoded string in the "expression" field instead of valid TCL code.
  • When APM attempts to evaluate a base64 string as TCL, it results in a syntax error, causing the access policy to fail and deny access.
  • After correcting the syntax, further failures may occur if required session variables (such as group membership) are missing or if access policy branching logic is too strict or does not account for missing attributes.

Recommended Actions

  1. Correct Variable Assign Expressions
    Edit all Variable Assign agents in the access policy to ensure the "expression" field contains valid TCL code, not a base64 string.
    Example of correct usage:

    expression {[mcget {session.ad.last.attr.memberOf}]}
    varname session.ad.last.attr.memberOf

    Remove any base64-encoded or non-TCL content from all Variable Assign agents.

  2. Review and Adjust Access Policy Logic
    In the Visual Policy Editor (VPE), review all branch rules after Variable Assign and AD Query agents.
    Ensure branch conditions are not overly strict and handle cases where attributes may be missing.
    Avoid sending users to "fallback" or "deny" branches unless truly necessary.

  3. Validate Upstream Authentication and Data Flow
    Confirm that AD Query and authentication steps are successful and return all required attributes.
    Use the BIG-IP GUI: Access Policy > Overview > Active Sessions > Variables tab to inspect session variables during test logins.

  4. Enable Debug Logging for Troubleshooting
    Temporarily enable debug logging for APM and authentication modules to gather more detailed information:
    tmsh modify sys db log.access.debug value enable
    tmsh modify sys db log.auth.debug value enable

  5. Test with Multiple User Accounts
    Test access with different user accounts to determine if the issue is user-specific or affects all users.
    Disable debug logging after troubleshooting:
    tmsh modify sys db log.access.debug value disable
    tmsh modify sys db log.auth.debug value disable

  6. Verify Active Directory Group Membership
    Ensure that user accounts are members of the correct AD groups expected by the access policy.
    If group membership changes, update the AD user object accordingly and retest access.
