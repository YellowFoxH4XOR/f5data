Topic

This article applies to BIG-IP ASM 9.2.0 - 11.3.0.  For information about other versions, refer to the following article:

  • K17411: Bypassing the BIG-IP ASM system for connections that use RPC over HTTP (11.4.0 - 12.x)

Purpose

You should consider using this procedure under the following condition:

  • You want to bypass the BIG-IP ASM system for connections using remote procedure call (RPC) over HTTP.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP ASM system.
  • You have basic working knowledge of either iRules or the Local Traffic Policy feature.
  • You have an existing BIG-IP ASM virtual server.

Description

The BIG-IP ASM system does not currently support RPC over HTTP. Some Microsoft Outlook implementations use RPC over HTTP to facilitate connections to the Microsoft Exchange server. Typically, these requests can be identified by the following unique HTTP attributes:

  • HTTP path/URI: /rpc/rpcproxy.dll 
  • HTTP methods: RPC_IN_DATA or RPC_OUT_DATA

The BIG-IP ASM system will block these requests and log the following violations:

BIG-IP ASM 9.4.1 and later:

Request blocked, violations: Illegal method.

BIG-IP ASM 9.2.0 through 9.4.0:

[SECEV] Request blocked, violations: Illegal HTTP format.
HTTP classifier: scheme HTTP, request: <RPC_OUT_DATA>

Note: Because the RPC data payload is in binary form, there is minimal security benefit for the BIG-IP ASM system to perform security enforcement on the RPC message data over HTTP.

Procedures

You can configure an iRule to bypass the BIG-IP ASM system for connections using RPC over HTTP.

Configuring an iRule to bypass the BIG-IP ASM system, and associating the iRule with the BIG-IP ASM virtual server

For BIG-IP ASM 9.2.0 and later, you can configure an iRule and associate it to the BIG-IP ASM-enabled virtual server to bypass the BIG-IP ASM system for RPC over HTTP requests. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Click Create.
  6. In the Name field, enter a name for the iRule.
  7. In the Definition field, enter the iRule syntax.

    Note: The following iRule may not apply to all environments. F5 recommends that you author an iRule that works best for your application environment. Additionally, adding an iRule will increase the resources that the associated virtual server uses. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any changes in an appropriate environment.

    BIG-IP ASM 10.0.1 through 11.3.0

    when HTTP_REQUEST {
       if { ([HTTP::path] eq "/rpc/rpcproxy.dll") and \
    (([HTTP::method] equals "RPC_IN_DATA") or ([HTTP::method] equals "RPC_OUT_DATA"))}{
          set rpcdata 1
       } else {
          set rpcdata 0
       }
    }
    when HTTP_CLASS_SELECTED {
       if { $rpcdata == 1 }{
          ASM::disable
       } else {
          ASM::enable
       }
    }

    Note: There is no workaround for BIG-IP ASM 10.0.0 because the ASM::disable and ASM::enable iRule commands were introduced in BIG-IP 10.0.1. The PLUGIN iRule commands do not function in BIG-IP 10.0.0. For more information, refer to K10128: The PLUGIN iRule commands do not function in BIG-IP version 10.0.0.

    BIG-IP ASM 9.4.2 through 9.4.8

    when HTTP_REQUEST {
       if { ([HTTP::path] eq "/rpc/rpcproxy.dll") and \
    (([HTTP::method] equals "RPC_IN_DATA") or ([HTTP::method] equals "RPC_OUT_DATA"))}{
          set rpcdata 1
       } else {
          set rpcdata 0
       }
    }
    when HTTP_CLASS_SELECTED {
       if { $rpcdata == 1 }{
          PLUGIN::disable ASM
       } else {
          PLUGIN::enable ASM
       }
    }

    BIG-IP ASM 9.2.0 through 9.4.1

    when HTTP_REQUEST {
       if { ([HTTP::path] eq "/rpc/rpcproxy.dll") and \
    (([HTTP::method] equals "RPC_IN_DATA") or ([HTTP::method] equals "RPC_OUT_DATA"))}{
          set asm_bypass 1
       } else {
       set asm_bypass 0
      }
    }

  8. Click Finished.
  9. Click Local Traffic.
  10. Click Virtual Servers.
  11. Click Virtual Server List.
  12. In the Resources column for the desired BIG-IP ASM-enabled virtual server, click Edit.
  13. In the iRules section, click Manage.
  14. In the Available box, select the iRule created in the previous procedure.
  15. Click << to move the desired iRule to the Enabled box.
  16. Click Finished.
