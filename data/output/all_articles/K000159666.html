K000159666: End user connect SSLVPN via explicit proxy have problem

Type
Support Solution
Published
2026-01-22
Updated
2026-01-22
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000159666

Description

End users are unable to establish a full SSL VPN tunnel via BIG-IP APM when connecting through an explicit web proxy that requires authentication. The VPN connection succeeds only when the proxy does not require authentication; otherwise, the connection fails, and users see "Awaiting connection ..." after installing the Endpoint Inspection agent. This issue affects both browser-based VPN connections and the Edge Client. The core question is whether proxy authentication is supported for VPN tunnel establishment and what configuration is required to enable VPN connectivity in environments using explicit proxies.

Environment

  • BIG-IP APM
  • Network Access resource configured for SSL VPN
  • End users accessing the VPN gateway via an explicit web proxy
  • Proxy server configured with and without authentication (basic authentication tested)
  • Endpoint Inspection agent installed on client devices

Cause

BIG-IP APM VPN clients (both browser-based and Edge Client) do not support proxy authentication for VPN tunnel establishment. When the upstream proxy requires authentication, the VPN client cannot supply credentials, resulting in failed VPN connections.

Recommended Actions

  • Configure the explicit proxy to allow unauthenticated access for VPN-related traffic, such as by whitelisting the VPN gateway’s FQDN/IP or the client’s source IP.
  • Alternatively, bypass the proxy for VPN traffic to allow direct connection to the VPN gateway.
  • If proxy authentication is required for other traffic, ensure that VPN traffic is excluded from authentication requirements.
