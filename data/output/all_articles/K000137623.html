Description

When the ldap auth is configured as follows:
 

apm aaa ldap /Common/LDAP-auth-01 {

    group-cache-ttl 0
}


The unit is likely suffering from handling ldap cache.

When the config is as such, it makes it *infinite* (i.e., unless manually cleared, they remain valid as long as they exist on APM).

 

Setting 0 will allow cache to be valid forever or until admin manually deletes it or reboot occurs, it is probably not desirable.

It tends to consume the memory (including swap) extensively and may cause apmd crash.

 

Environment

Using LDAP auth

Cause

Configuring ldap group-cache-ttl to "indefinite"

Recommended Actions

The default value is 30 (= 30 days).

Depending on the amount of configuration or number of users, it is ideal to set the value less than default (such as: 15 or so).
