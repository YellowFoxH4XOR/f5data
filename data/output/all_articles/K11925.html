Known Issue

When the Data Migration Engine (DME) attempts to migrate shares for a multi-protocol volume, if the shares contain device file names with case collisions, the DME is unable to determine attributes for the device file using CIFS.

Impact

The migration will fail.

Symptoms

As a result of this issue, you may encounter error messages that appear similar to the following examples:

  • :DME-1-WARN-MSG4:: The migration subsystem cannot operate on file "TTys0", in directory "/unix/devices/", because of an access inconsistency that prevents correct transfer of the CIFS attributes. This error can be addressed by resolving the inconsistency or disabling strict attribute consistency. Disabling strict attribute consistency will not affect the transfer of the device, only the CIFS attributes.
  • :POLICY_ACTION-1-ERR-POLICY_ACTION_FAILED:: Rule [mpeng:/unix:drain_share-unix-0]: Migration of file [/devices/TTys0] from share [share-unix-0] to share [share-unix-1] failed. File could not be moved: The DME operation was denied because strict attribute consistency might be violated [-446]

Workaround

To work around this issue, you can disable the strict-attribute-consistency setting. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the ARX CLI using the console.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global mode by typing the following command:

    global
  4. Enter the namespace configuration mode using the following command syntax:

    namespace [namespace name]
  5. Enter the volume configuration mode using the following command syntax:

    volume [volume name]
  6. Enter the share configuration mode using the following command syntax:

    share [share name]
  7. Disable the strict-attribute-consistency setting by typing the following command:
no strict-attribute-consistency
  1. End share configuration mode and return to privileged mode by typing the following command:

    end
