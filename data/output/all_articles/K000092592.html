Description

The status of the health monitor with FQDN has been stuck with 'Down' even though the "status=UP" in the Monitor logging is already changed/logged successfully.

| Monitor Status : down

"

/var/log/monitors/Common_https-Common__auto_192.0.2.0-443.log

However, we can see the error message in the /var/log/ltm very often.

/var/log/ltm

"
Oct 31 07:56:36 F5_Device_HostName err mcpd[6052]: 01070712:3: Caught configuration exception (0), Invalid monitor rule instance identifier: 97.
Oct 31 07:56:40 F5_Device_HostName err mcpd[6052]: 01070712:3: Caught configuration exception (0), Invalid monitor rule instance identifier: 97.
"

Environment

BIGIP v15.1.6 VE

Cause

Bug ID 1111473


Recommended Actions

1. Please make sure whether the following error messages are reproduced in the /var/log/ltm as stated in Bug ID 1111473.

"bigip1 err mcpd[4783]: 01070712:3: Caught configuration exception (0), Invalid monitor rule instance identifier: 29."

 

2. Please do the "Recommended Steps" properly as stated in K13030 to reboot the device with the forceload option properly.

# touch /service/mcpd/forceload

# reboot
 

K13030: Forcing the mcpd process to reload the BIG-IP configuration

None.
