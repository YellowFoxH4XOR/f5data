Known Issue

Under rare conditions, a stale HTTP2 or SPDY flow may cause the Traffic Management Microkernel (TMM) to restart.

This issue occurs when the following condition is met:

  • The HTTP2 or SPDY profile is configured and assigned to a virtual server.

Impact

The BIG-IP system temporarily fails to process traffic while TMM restarts. If the BIG-IP system is configured for high availability (HA), the system fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file in the /shared/core directory.
  • Your BIG-IP system logs a SIGSEGV to the /var/log/tmm file at the same time TMM produces a core file and restarts.
