K000160210: Loading LX workspace fails

Type
Support Solution
Published
2026-03-03
Updated
2026-03-03
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160210

Description

iRules LX workspaces fail to load in the BIG-IP GUI, displaying the error:


"Could not list directory: /var/ilx/workspaces/Common/<workspace_name>/extensions"


Symptoms include:

  • The workspace editor fails to load files (such as index.js).
  • Java NullPointerException errors appear in tomcat logs when attempting to list workspace directories.
  • Some LX workspaces load successfully, while others fail with the above error.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1 (also relevant for other versions with iRules LX)
  • Configuration: iRules LX workspaces with Node.js version 6.9.1
  • Multiple LX workspaces present; issue affects some but not al

Cause

Incorrect ownership and permissions on the node_modules directory within affected LX workspaces.

  • Directory was owned by root:sdm with mode 775, instead of root:root with mode 755.
  • This prevented the GUI from listing directory contents, resulting in Java NullPointerExceptions and workspace loading errors.

Answer/Recommended Actions

To resolve the issue, perform the following steps for each affected workspace:


1. Navigate to the workspace extension directory:


cd /var/ilx/workspaces/Common/<workspace_name>/extensions/<extension_name>


2. Update permissions and ownership for node_modules:


chmod -R 755 node_modules

chown -R root:root node_modules


3. Restart relevant services:


bigstart restart restjavad restnoded


4. Reload the workspace in the BIG-IP GUI and verify that it loads successfully.


5. Repeat for other workspaces exhibiting the same issue.


Additional Information

  • Java NullPointerException in tomcat logs is directly correlated with the directory listing error.
  • Zero-byte files and special characters in filenames were investigated but not found to be the primary cause.
  • Workspaces with correct node_modules ownership and permissions load successfully.
