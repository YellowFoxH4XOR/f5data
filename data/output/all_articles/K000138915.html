Description

You want to use policy routing via "nexthop" command in an iRule to assign the same IPv6 address that exists on different VLANs to a non-default route domain. 

Whilst the configuration is saved with no error, you get TCL error in the ltm log file while "nexthop" command is executed and traffic is not forwarded to the configured IPv6 address. 

when CLIENT_ACCEPTED {
  nexthop <vlan name> <ipv6>%<RD>
}

/var/log/ltm:

01220001:3: TCL error: /Common/<irule name> <CLIENT_ACCEPTED> - while executing "nexthop <vlan name> <ip%RD>"

Environment

  • ipv6
  • Route Domain RD
  • iRule

Cause

  • Bug ID1558869 documents the failure of tmsh generated config file to load for vlan specific non-default route-domain IPv6
  • Bug ID534499 documents the current limitation around configuring an ipv6 link local address with %vlan notation in non-default route domain by using both %vlan<tag> and %<rd> simultaneously which is not supported by BIG-IP at this point. In order to use the same link-local address in different VLANs in BIG-IP we need to use the %vlan<tag> notation on the IP address. And, if this ip is used in a non-default route domain, it needs to be followed by another %<RD> notation. 

Whilst ID1558869 has been created to document the issue with the system allowing this format of ipv6 configuration being saved with no error, ID534499 is the root of the experienced failure. 

Recommended Actions

To work around this issue, you need to specify different IPv6 addresses for each VLAN in a single non-default route-domain so that you will only use one %<rd> notation (required to specify which RD). In other words, the %vlan<tag> along with the %<rd> is not supported because the %vlan overrides the %rd and then assumes RD 0. As a result, the same IPv6 address cannot be used.
