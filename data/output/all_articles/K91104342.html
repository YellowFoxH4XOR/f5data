Description

When using Virtual server Auto-discovery in BIG-IP DNS/ BIG-IP GTM, some virtual servers are not discovered automatically.

Environment

  • BIG-IP DNS with virtual server auto-discovery enabled
  • virtual servers using the same destination address and port combination but for different protocols
  • virtual servers using the same destination address and port combination but different VLANs

Cause

Virtual servers using the same IP:port combination but different protocols will most likely cause only one of the services to be discovered correctly. This issue is being tracked as Bug ID 646491.

Recommended Actions

Manually define the 'ltm-name', allowing gtmd to pass unambiguous requests to MCPD over iQuery for multiprotocol virtual servers.

tmsh modify gtm server gtm_myself virtual-servers modify { /Common/vs1_tcp { ltm-name vs1_tcp }}
tmsh modify gtm server gtm_myself virtual-servers modify { /Common/vs1_udp { ltm-name vs1_udp }}

 

Additional Information

It is also important to remember that virtual servers that use Network Destination addresses are not going to be discovered. DNS resolves for a specific host, hence a host (/32) mask is required for virtual servers to be used as pools for Wide IPs.
