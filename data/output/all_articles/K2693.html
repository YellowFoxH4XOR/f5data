K2693: Configuring BIG-IP for compatibility with devices that use shared MAC addresses for redundancy

Topic

BIG-IP has a feature called auto_lasthop that allows BIG-IP to send return packets through the same path on which they were received, based on the packet's Ethernet MAC address.

For example, if BIG-IP received a connection from the Ethernet MAC address: 00:cc:00:ff:ff:ee, BIG-IP would send the response packets to 00:cc:00:ff:ff:ee.

In the case of some clustering technologies, such as Stonebeat, two firewalls would each have unique unicast MAC addresses, but would share a single multicast MAC address. When a device sends an ARP for the shared IP address of the firewall cluster, the firewalls respond with the shared multicast MAC address, which populates the ARP cache on the device that made the ARP request.

In the case of BIG-IP, the process is no different. Once a BIG-IP learns the MAC address of the shared IP address on the firewall cluster, BIG-IP routes packets to this shared MAC address; however, when the firewalls send response packets to the device that originated the connection, the firewalls use the local unicast MAC address (not the shared multicast MAC address) and this forces BIG-IP to re-learn the MAC address to which it sends packets in its internal lasthop connection table.

For example, for the following configuration:

client:   10.10.33.50  00:00:11:12:12:12
firewall: 10.10.33.100 00:00:22:21:21:21 (unique unicast)
firewall: 10.10.33.1   bb:bb:22:21:21:21 (shared multicast)

If the client was configured with a default route of 10.10.33.1, and the client attempted to make a connection to www.f5.com, the process would look like this:

00:00:11:12:12:12 -> ff:ff:ff:ff:ff:ff who-has 10.10.33.1 tell 10.10.33.50
bb:bb:22:21:21:21 -> 00:00:11:12:12:12 tell 10.10.33.1 is-at bb:bb:22:21:21:21
00:00:11:12:12:12 -> bb:bb:22:21:21:21 www.f5.com Connection request
***00:00:22:21:21:21 -> 00:00:11:12:12:12 www.f5.com Connection response***

Notice that the client sends the connection request to the shared multicast MAC address of the firewall cluster (bb:bb:22:21:21:21), but got a response from the local unique unicast MAC address of the firewall (00:00:22:21:21:21).

If the client in this case was a BIG-IP, it would learn that it should send packets to 00:00:22:21:21:21 instead of the MAC address that exists in the ARP table (bb:bb:22:21:21:21).

In most network configurations the auto_lasthop feature simplifies the deployment of BIG-IP, but in this case it is not desirable that BIG-IP sends return traffic to the MAC address from which it received the traffic. Instead, in this case it is desirable that all traffic is sent to the shared multicast MAC address, regardless of where the traffic originated. To achieve this, you must disable the auto_lasthop global variable.

auto_lasthop uses layer 2 (the MAC address layer) to fill in any missing pieces in its routing table (layer 3, which is the IP address layer); therefore, when auto_lasthop is enabled (default) BIG-IP will return packets to the requesting client, even if the routing on BIG-IP is not fully configured. auto_lasthop can cause issues with other vendors who implement layer 2 for load balancing or failover.

Disabling auto_lasthop

You can disable auto_lasthop through the Configuration utility or the command line interface.

Important: Before you disable auto_lasthop, it is critical that you configure all required routes on BIG-IP and, if necessary, that you create last hop pools for situations where BIG-IP is load balancing gateway devices. Refer to the BIG-IP Administrator Guide for instructions about how to configure last hop pools.

Configuration utility

To disable auto_lasthop through the Configuration utility, perform the following steps:

  1. From the navigation pane, click System.
  2. Click the Advanced Properties tab at the top of the screen.
  3. Uncheck the box next to auto_lasthop.
  4. Click the Apply button.

Command line interface

To disable auto_lasthop through the command line interface, perform the following steps:

  1. Type the following command:

    b global auto_lasthop disable

  2. Save the change, by typing the following command:

    b save
