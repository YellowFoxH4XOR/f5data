Description

The named process is the DNS server daemon. Failure to start named may impact BIND functionality.    
If the daemon named stays down and cannot be started up, you may find the error messages below:

  • The log var/log/daemon.log may show the error messages below, indicating the failure to start the named process, because its TCP socket are in use by the zombie named process.

Jan 1 03:49:54 LTM1.example.com emerg logger: Re-starting named
Jan 1 03:49:54 LTM1.example.com err named[28668]: binding TCP socket: address in use
Jan 1 03:49:54 LTM1.example.com err named[28668]: binding TCP socket: address in use
Jan 1 03:49:54 LTM1.example.com err named[28668]: unable to listen on any configured interfaces
Jan 1 03:49:54 LTM1.example.com crit named[28668]: loading configuration: failure
Jan 1 03:49:54 LTM1.example.com​​​​​​​ crit named[28668]: exiting (due to fatal error)

  • The log var/log/tomcat/catalina.out may show the error message below, indicating the failure to stop the zombie named process.

Jan 01, 2023 3:49:06 PM org.apache.catalina.loader.WebappClassLoaderBase clearReferencesThreads
SEVERE: The web application [/tmui] appears to have started a thread named [Thread-2] but has failed to stop it. This is very likely to create a memory leak.

  • The command tmsh show /sys service all  may show named down all the time.

named down 6 minutes, normally up

  • The command ps aux | grep named may show the zombie named process with its PID number.

USER PID PPID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND
root 7607 4597 0.0 0.0 1.9M 396.0K ? S Jan01 00:00:10.07 runsv named
named 11952 1 0.0 0.2 61.7M 31.3M ? S Dec24 00:00:04.32 /usr/sbin/named -f -t /var/named -u named -c /config/named.conf -n 1

Environment

  • BIG-IP DNS

  • named process

Cause

If there is a zombie named process, BIG-IP may fail to start the named process, because its TCP socket are in use by the zombie named process.

 Recommended Actions

As BIG-IP may fail to stop the zombie named process itself, you may need to manually kill the zombie named process, and start the named process afterwards.
Impact of workaround:: Restarting named will temporarily affect BIND functionality.​​​​​​​
1. Manually stop named
    bigstart stop named
2. kill the zombie named process, by its PID number shown in the output of command ps aux | grep named.
    kill -9 11952
3. Manually start named
    bigstart start named
4. check the daemon.log or catalina.out to see if named can be started successfully or not
    tail -f /var/log/daemon.log
    tail -f /var/log/tomcat/catalina.out

Additional Information

To stop, start, restart, or view the status of a daemon, you may use either tmsh, or bigstart, or the Configuration utility, as shown in BIG-IP daemons (15.x - 17.x) (f5.com) ​​​​​​​.
