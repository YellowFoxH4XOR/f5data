Topic

You can configure BIG-IP to filter out the Nimda attack by using a rule to discard the HTTP request from a Nimda attack.

Create this rule from the Configuration utility with the following information (substituting the actual names of the pools in your network configuration):

Note: The following rule works for the latest variant of the Nimda worm dated October 1, 2001. The specifics of the attack may change; if this occurs, you must adjust your rule accordingly.

if (http_uri matches_regex ".*cmd.exe*." or http_uri matches_regex ".*root.exe*." or http_uri matches_regex ".*admin.dll*.") {
  discard
}
else {
  use ( realwebservers )
}

Note: Contact F5 Networks Technical Support if you need assistance or have any questions about creating this rule. Refer also to K770: Overview of BIG-IP rules. For version 4.5 and later, refer to the iRules chapter in the BIG-IP Reference Guide.

After you configure the rule, perform the following steps:

  1. From the Configuration utility, click Virtual Servers.
  2. From the list, select the virtual server you want to use this new rule.
  3. Click Resources.
  4. Click the button next to Rule.
  5. Select the rule you created.
  6. Click Apply.

    This change goes into effect immediately. There may be a brief interruption of service.
