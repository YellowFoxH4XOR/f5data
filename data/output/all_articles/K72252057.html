Known Issue

BIG-IP ASM may fail to process some Internet Content Adaptation Protocol (ICAP) antivirus server responses.

This issue occurs when the following condition is met:

  • Specific connection characteristics exist between BIG-IP ASM and the ICAP server. For example, the ICAP server sends multiple responses in quick succession to the BIG-IP ASM system.

Impact

BIG-IP ASM reports a virus is detected and blocks the request.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Client uploads occasionally fail.
  • Packet captures show valid ICAP server responses.
  • The BIG-IP ASM system logs error messages to the /var/log/bd.log file that appear similar to the following examples:
    • ICAP|INFO <date> icap_client.c:2147|sent data to icap server job <server_job_id> support id <support_id>. waiting for response
    • CAP|NOTICE <date> icap_client.c:1598|Virus check: icap server closed connection. support id <support_id> job <server_job_id> err 0 errno 11 Resource temporarily unavailable
    • ICAP|INFO <date> |io_plugin.c:8416|TMEVT_NOTIFY message received for job <server_job_id> support id <support_id>. virus_found 1 job state 2

Workaround

To work around this issue, you can configure the EnableASMByPass internal parameter so that the antivirus server does not reply, and does not issue a violation when it occurs. To do so, perform the following procedure:

Impact of workaround: The following procedure restarts the asm process, which temporarily interrupts traffic processing. In addition, when the internal parameter is enabled, BIG-IP ASM bypasses large HTTP requests (when they come on multiple connections) instead of resetting them.

  1. Log in to the BIG-IP ASM command line.
  2. To set the EnableASMByPass internal parameter, enter the following command:

    /usr/share/ts/bin/add_del_internal add EnableASMByPass 1

  3. To restart the asm process, enter the following command:

    bigstart restart asm
