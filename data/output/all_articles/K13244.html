Summary

The BIG-IP system includes a feature known as the RAM Cache feature. RAM Cache is a cache of HTTP objects stored in the BIG-IP systems random access memory (RAM) for reuse by subsequent connections to reduce the amount of traffic load on back-end servers.

    Description

    You can use the RAM Cache feature to reduce traffic load to back-end servers. This feature is most useful under the following conditions:

    • High-demand objects - The Ram Cache feature is useful if a site has periods of high demand for specific content. When you configure RAM cache, the content server only has to serve the content to the BIG-IP system once per expiration period.
    • Static content - The RAM Cache feature is useful if a site consists of a large quantity of static content such as CSS files, JavaScript files, or images and logos.
    • Content compression - For compressible data, the RAM cache feature can store data for clients that can accept compressed data. When used in conjunction with the compression feature on the BIG-IP system, the RAM cache takes stress off of the BIG-IP system and the content servers.

    To configure the cache feature, you can enable RAM Cache in the HTTP profile.

    Cacheable content

    The RAM Cache feature complies with the cache specifications described in RFC 2616. You can configure the RAM Cache feature to cache the following content types:

    • 200, 203, 206, 300, 301, and 410 responses
    • Responses to GET requests
    • Other HTTP methods for URIs specified for inclusion in cached content, or specified in an iRule
    • Content based on the User-Agent and Accept-Encoding values. The RAM cache feature holds different content for Vary headers.

    The default RAM cache configuration caches only responses to HTTP GET requests. However, you can use the RAM cache to cache other methods, including non-HTTP methods. To do this, you can specify a URI in the URI Include or Pin List within an HTTP profile, or write an iRule.

    Non-cacheable content

    The RAM cache feature does not cache the following items:

    • Private data specified by cache control headers
    • HEAD, PUT, DELETE, TRACE, and CONNECT methods, by default
