Description

To stop SNMP traps for a given problematic IP triggering the trap, For example, authentication failure trap.

Environment

  • BIG-IP All Versions,All Modules
  • SNMP Trap is configured

Cause

Excessive SNMP Traps sent for a problematic IP.

Recommended Actions

To define custom user-defined SNMP traps, it should be defined in the /config/user_alert.conf file. 

Note: This method will survive reboots.

To halt a specific SNMP trap by IP that is problematic, perform the following procedure:

  1. Log in to the command line.
  2. Edit the /config/user_alert.conf.
  3. Add a new alert definition without action following format:
    alert <alert_name> "<matched message>" {
    }
    For example,
    alert DISABLE_BIGIP_SSHD_AUTH_FAIL_1 "error: PAM: Authentication failure for root from 10.154.100.29" {
    }
    alert DISABLE_BIGIP_SSHD_AUTH_FAIL_2 "error: PAM: Authentication failure for root from 10.155.86.216" {
    }
    Note: Replace <alert_name> with a descriptive name. Do not use an alert name that exactly matches one already used in the /etc/alertd/alert.conf file or the /config/user_alert.conf file. Replace <matched_message> with text that matches the syslog message that you do not want to trigger the SNMP trap.
  4. Save the file an exit the editor.
  5. Restart alertd following
    bigstart restart alertd
