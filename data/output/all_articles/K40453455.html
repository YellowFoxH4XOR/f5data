K40453455: Portal Access to Internal HTTPS site not working when using SNI

Type
Support Solution
Published
2022-03-08
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 15.X.X, 15.0.X, 15.1.0, 15.0.1, 15.0.0, 15.1.8, 15.1.7, 15.1.6, 15.1.X, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 15.1.5
Source
https://my.f5.com/manage/s/article/K40453455

Description
Attempts by the BIG-IP to connect to an HTTPS Portal Access resource with Server Name Indication (SNI) enabled result in the the server closing the connection with TCP reset after Client hello is sent

Environment

  • Portal Access
  • HTTPS portal access resources
  • VS with serverssl profile applied
  • Server Name Indication

Cause
Resources may be configured with Server Name indication, and the VS serverssl profile is not configured to send SNI TLS extension to multiple Portal Access Resources

Recommended Actions

  1. Log on to the Configuration utility.
  2. Go to Local Traffic > iRules > iRules List.
  3. Select Create and define an iRule using the following command stanza:
    when REWRITE_REQUEST_DONE {
      #log local0. "HOST: [HTTP::host]"
      set sni_value [getfield [HTTP::host] ":" 1]
    }

    when SERVERSSL_CLIENTHELLO_SEND {
      # SNI extension record as defined in RFC 3546/3.1
      #
      # - TLS Extension Type                =  int16( 0 = SNI )
      # - TLS Extension Length              =  int16( $sni_length + 5 byte )
      #    - SNI Record Length              =  int16( $sni_length + 3 byte)
      #       - SNI Record Type             =   int8( 0 = HOST )
      #          - SNI Record Value Length  =  int16( $sni_length )
      #          - SNI Record Value         =    str( $sni_value )
      #
      # Calculate the length of the SNI value, Compute the SNI Record / TLS extension fields and add the result to the SERVERSSL_CLIENTHELLO
      SSL::extensions insert [binary format SSScSa* 0 [expr { [set sni_length [string length $sni_value]] + 5 }] [expr { $sni_length + 3 }] 0 $sni_length $sni_value]
    }
  4. Associate the iRule with your portal access virtual server.
Note: F5 Support does not design or configure iRules.  If you are in need of any assistance configuring an iRule to best work for your environment, F5 Professional Services can assist.
