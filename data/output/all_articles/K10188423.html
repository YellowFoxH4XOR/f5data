Description

An SQL injection (SQLi) attack is a common attack against a web application that targets information stored in a database. SQLi can be done in many ways, depending on the SQL server type. The SQL server type dictates the syntax of the type of the executed SQLi attack. SQLi can also include evasion techniques employed by attackers to bypass WAF filters such as BIG-IP ASM and AWAF.

Environment

  • Application is under an SQLi attack
  • BIG-IP ASM / AWAF 14.1.x
  • A security policy is assigned to the virtual server
  • BIG-IP ASM request log is enabled by default to illegal request

Cause

None

Recommended Actions

BIG-IP ASM/AWAF can mitigate SQLi attacks using appropriate attack signatures or defined meta-characters. The following procedures list the steps needed to mitigate SQLi using the attack signatures because this is the fastest and easiest configuration. The procedures include instructions for assigning the relevant attack signature set, enabling it, and configuring it to mitigate SQLi attacks. The final step is the mitigation verification, where the administrator can see the SQLi being blocked.

Note: Default configuration means a security policy created with any of the policy templates, using default settings, and currently in Transparent or Blocking mode.

Impact of procedures: Adding attack signatures to the security policy can generate false positives. For example, known false positives for SQLi can occur due to the presence of English words such as “select” and “from” in the HTTP request. In these cases, you should remove false positives from the Traffic Learning page by accepting any learning suggestions for disabling the signature. Adding the SQL Injection Signatures attack signature set covers various types of SQL servers. This provides protection regardless of the type of SQL server on the backend.

  • Adding the SQLi attack signatures to the security policy
  • Enabling and enforcing the SQLi attack signatures
  • Switching the security policy into Blocking mode
  • Verifying the SQLi attack is being blocked

Adding the SQLi attack signatures to the security policy

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the upper-left corner, from the Current edited policy list, select the desired security policy.
  4. In the upper-right corner, select Advanced.
  5. Select Attack Signatures to reveal the settings.
  6. Under the Attack Signatures table, select Change.

    The Configuration utility displays the Select Policy Attack Signature Sets page.

  7. Select the SQL Injection Signatures check box, and then select Change.
  8. In the Attack Signatures table, verify that the signature set is enabled for Learn, Alarm, and Block.
  9. Select Save, and then select Apply Policy.

Enabling and enforcing the SQLi attack signatures

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the upper-right corner, select Advanced.
  4. Select Attack Signatures to reveal the settings.
  5. For the SQL Injection Signatures set, select Change Signature Properties and then select Enable all Attack Signatures in the Signature Set.
  6. Under the attack signatures list, clear the Enable Signature Staging check box.
  7. Select Save, and then select Apply Policy.

Switching the security policy into Blocking mode

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Under General Settings, for Enforcement Mode, select Blocking.
  4. Select Save, and then select Apply Policy.

Verifying the SQLi attack is being blocked

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Event Logs > Application > Requests.
  3. Select the Open filter (funnel icon), and then select IP / Username / URL.
  4. For Attack Type, select SQL-Injection, and then select Apply Filter.

    The blocked request with SQLi should be listed in the request log.

    Note: In the request log, the violation name will be “attack signature detected.”
