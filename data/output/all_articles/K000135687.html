K000135687: iRule string map function may add an extra slash in HTTP URI

Description

iRule is configured to perform URI replacement with string map function which may result in a double slash in the HTTP URI when sending the request to the backend server (pool member). Here is an example iRule:

when HTTP_REQUEST {
    if {[string tolower [HTTP::uri]] starts_with "/abc" } {
        HTTP::uri [string map {"/abc" "/"}[HTTP::uri]]
    }
}

When a request with a URI starting with /abc hits a virtual server, it gets remapped to / but when /abc/ comes in, it gets remapped to //.

Environment

  • iRule
  • HTTP URI remapping

Cause

This is expected behavior as the string map function catches only what is specified in the first double quotes. In the example, the catch string is /abc.

Recommended Actions

Choose one of the following options:

Option 1: Since string map takes a list of key-value pairs, you can add another key-value to replace the trailing / with an empty value if it appears in the URI of the request. In the following example "/abc" "/" is the first replacement on the original URI and if there is a trailing slash, "/" "" performs the second replacement on the original URI to remove it so the resulting URI is a single / in both the case of /abc or /abc/:

when HTTP_REQUEST {
    if {[string tolower [HTTP::uri]] starts_with "/abc" } {
        HTTP::uri [string map {"/abc" "/" "/" ""}[HTTP::uri]]
    }
}

Option 2: Implement an additional condition to replace // in HTTP URI with a /. For example:

when HTTP_REQUEST {
    if {[string tolower [HTTP::uri]] starts_with "/abc" } {
        HTTP::uri [string map {"/abc" "/"}[HTTP::uri]]
        if {[string tolower [HTTP::uri]] equals "//" } {
            HTTP::uri [string map {"//" "/"}[HTTP::uri]]
        }
    }
}
