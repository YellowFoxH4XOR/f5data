K000149715: Not able to connect to Velos system controller, partition, and/or tenant.

Type
Support Solution
Published
2025-02-07
Updated
2025-02-07
Source

Description

A Velos chassis is setup and after changing the internal chassis IP no connections can be made via the GUI or SSH to the controllers, partitions. or tenants. Each attempt results in a connection attempt timeout.

Environment

There is an internal chassis network for the control plane and management plane. This provides communication between the firmware and software on the system controllers and blades. To do this a specific IP range is defined and reserved for this purpose.

Cause

The default IP range for the internal chassis network is 100.64.0.0/12. However, it can be modified within a predetermined set of choices.

If you then set the IPs for the management IP for the Velos system, the management IP of the controllers, partition or tenants within one of the allowed ranges connection attempts will timeout. This is because, for all intents and purposes, you now have IPs conflicts. The only means of contact is via a console connection.

NOTE: There was one instance when this happened when just the Velos management IP could connect to the GUI but not SSH. So you may get that. The idea here is that because of a combination of the source address of the traffic and how the system handles 443 internally (it is proxied into a Docker container) it "may" get that single GUI connection.

Recommended Actions

In most cases the default IP range for the internal chassis network should not be altered, unless you use that range. If you do use that range and need to alter it that will fall into one of fifteen /12 networks within 10.0.0.0. Just ensure whatever one you use does not fall within a range you will be using for network traffic on the Velos system.

If this does happen you will need to console in and run the steps here to change it....Internal Chassis Networking

What that article does not show is the command needed to return it to the default range of 100.64.0.0/12. To return it to the default range run this command...

system network config network-range-type RFC6598
