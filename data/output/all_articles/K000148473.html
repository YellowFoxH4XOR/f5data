Description

To allow access to a specific URL only from one designated IP address, we can use LTM objects instead of an application security policy. 

Environment

  • BIG-IP

Cause

None

Recommended Actions

You can either create an iRule or an LTM traffic policy for this purpose.

  • Using an iRule to Allow Access Only from a specified IP
  • Using an LTM traffic policy to allow access only from the specified IP

Important: It is essential to adjust the parameters according to your specific requirements and thoroughly test in a staging environment before implementing in production. The provided examples are for guidance only. If you need F5 to write an iRule or create a traffic policy for you, please contact Professional Services.

Using an iRule to Allow Access Only from a specified IP

  1. Log in to the BIG-IP system Configuration Utility.
  2. Navigate to Local Traffic  ››  iRules : iRule List.
  3. Click on Create to create a new iRule. 
    • Example 1: When the client directly connects with BIG-IP without an address translation device (Proxy, NAT or firewall) in between, allow the access to "/special-url" only from 192.168.1.10 
      when HTTP_REQUEST {
# Check if the requested URL matches /special-url
    if { [HTTP::uri] starts_with "/special-url" } {
        # Allow only a specific IP to access the URL
        if { [IP::client_addr] ne "192.168.1.10" } {    
            # Block access for other IPs
            reject
        }
    }
}
    • Example 2: When the client connects to BIG-IP through an address translation device (Proxy, NAT or firewall), allow access to "/special-url" only from 192.168.1.10. Ensure that the request includes an X-Forwarded-For header containing the original client ip address. 
      when HTTP_REQUEST {
    # Check if the requested URL matches /special-url
    if { [HTTP::uri] starts_with "/special-url" } {
        # Extract the client's real IP from the X-Forwarded-For header
        set client_ip [HTTP::header "X-Forwarded-For"]

        # Allow only a specific IP to access the URL
        if { $client_ip ne "192.168.1.10" } {
            # Block access for other IPs
            reject
        }
    }
}
  4. Attach iRule to the virtual server.

Note: If you need access from multiple IP Addresses, you can modify the iRule syntax to match multiple IPs rather than a single one.

Using an LTM traffic policy rule to allow access only from the specified IP

Below is an example of a traffic policy that resets the connection if an HTTP request for a specified URI is received from any IP other than 192.168.1.10.

  1. Log in to the BIG-IP system Configuration Utility.
  2. Navigate to Local Traffic  ››  Policies : Policy List.
  3. Click on Create to create a new draft security policy.  
  4. Create a new rule within the created policy with the following conditions.
    • Example 1: When the client connects directly to BIG-IP without an address translation device (such as a proxy, NAT or firewall) in between, allow access to "/special-url" only from 192.168.1.10
      • HTTP URI path is '/special-url' at request time.
      • TCP address does not match '192.168.1.10' at request time.
    • Example 2: When the client connects to BIG-IP through an address translation device (such as a proxy, NAT or firewall), allow access to "/special-url" only from 192.168.1.10. Ensure that the request contains X-Forwarded-For header with the original client ip address.
      • HTTP URI path is '/special-url' at request time.
      • HTTP Header full string named 'X-Forwarded-For' is '192.168.1.10' at request time.
  5. Add the following action.
    • Reset traffic connection at request time.
  6. Publish the traffic policy and attach to the virtual server.
