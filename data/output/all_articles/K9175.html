Known Issue

Note: For more information about the PVA, refer to K4832: Overview of Packet Velocity ASIC (PVA) Acceleration features and sub features.

This is the result of a known issue. Packet Velocity ASIC (PVA) versions 1 and 2 (PVA1 and PVA2) may improperly modify the checksum value for User Datagram Protocol (UDP) packets that are received with no checksum value.

Note: Only BIG-IP platforms containing PVA1 or PVA2 (BIG-IP 2400, 3400, 6400 and 6800) are affected by this issue.

F5 Product Development is tracking this issue as ID 246887 (formerly CR104357).

Workaround

You can work around this issue by managing flows initiated with no checksum, or managing flows containing responses with no checksum.

Managing flows initiated with no checksum

To manage flows initiated with no checksum, perform one of the following two procedures:

BIG-IP LTM 9.4.2 and later

Beginning in BIG-IP LTM 9.4.2, F5 supports automatic demotion from PVA acceleration of any UDP connection flow that is initiated by a packet containing no UDP checksum value. To enable this support, you must set PVA Acceleration to Assisted. To do so, perform the following procedure:

Note: To perform the following procedure, you must be running BIG-IP LTM 9.4.2 or later. For information about upgrading, refer to the BIG-IP LTM release notes.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click Fast L4 on the Protocol menu.
  5. Click Create.
  6. Type a name for the profile.
  7. Select Fast L4 from the Parent Profile menu.
  8. Select the Custom box for the PVA Acceleration setting, and select Assisted from the menu.
  9. Click Finished.
  10. Click Local Traffic.
  11. Click Virtual Servers.
  12. Click Create.
  13. Type a name for the virtual server.
  14. Enter a Destination address and Service port that match the subset of UDP traffic containing zero checksum requests.
  15. Select Advanced from the Configuration menu.
  16. Select Performance (Layer 4) from the Type menu.
  17. Select UDP from the Protocol menu.
  18. Select the name of the custom Fast L4 profile created in Steps 6 through 9 above in the Protocol Profile (Client) menu.
  19. Select the appropriate VLAN and Resources for the virtual server.
  20. Click Finished.

When this UDP virtual server receives a packet that establishes a new connection flow, its checksum value will be examined. Connection flows initiated with packets containing no checksum value will be demoted to PVA acceleration of None. Connection flows initiated with packets containing non-zero checksum values will remain eligible for PVA acceleration.

Upgrading to BIG-IP LTM 9.4.2 or later is not possible

If an upgrade to BIG-IP LTM 9.4.2 is not possible, you can work around this issue by creating a more specific virtual server with PVA acceleration set to None. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click Fast L4 on the Protocol menu.
  5. Click Create.
  6. Type a name for the profile.
  7. Select Fast L4 from the Parent Profile menu.
  8. Check the Custom box for the PVA Acceleration setting, and select None from the menu.
  9. Click Finished.
  10. Click Local Traffic.
  11. Click Virtual Servers.
  12. Click Create.
  13. Type a name for the virtual server.
  14. Enter a Destination address and Service port that match the subset of UDP traffic containing zero checksum requests.
  15. Select Advanced from the Configuration menu.
  16. Select Performance (Layer 4) from the Type menu.
  17. Select UDP from the Protocol menu.
  18. Select the name of the custom Fast L4 profile created in Steps 6 through 9 above in the Protocol Profile (Client) menu.
  19. Select the appropriate VLAN and Resources for the virtual server.
  20. Click Finished.

No PVA acceleration will be applied to packets traversing this virtual server.

Managing flows containing responses with no checksum

The demotion decision is made on the packet that initiates the connection flow. Therefore, bi-directional UDP traffic in which the initial packet contains a non-zero checksum but the response contains no checksum cannot be accelerated with PVA1 or PVA2. You can work around this issue by creating a more specific virtual server with PVA acceleration set to None. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click Fast L4 on the Protocol menu.
  5. Click Create.
  6. Type a name for the profile.
  7. Select Fast L4 from the Parent Profile menu.
  8. Check the Custom box for the PVA Acceleration setting, and select None from the menu.
  9. Click Finished.
  10. Click Local Traffic.
  11. Click Virtual Servers.
  12. Click Create.
  13. Type a name for the virtual server.
  14. Enter a Destination address and Service port that match the subset of UDP traffic containing zero checksum requests.
  15. Select Advanced from the Configuration menu.
  16. Select Performance (Layer 4) from the Type menu.
  17. Select UDP from the Protocol menu.
  18. Select the name of the custom Fast L4 profile created in Steps 6 through 9 above in the Protocol Profile (Client) menu.
  19. Select the appropriate VLAN and Resources for the virtual server.
  20. Click Finished.

No PVA acceleration will be applied to packets traversing this virtual server.
