Description

In F5 Service Proxy for Kubernetes (SPK) environments using the DNS46/NAT46 feature, multiple IPv6 addresses may incorrectly map to a single IPv4 address in the Distributed Session State Management (dSSM) database. The expected behaviour is a 1:1 mapping between IPv4 and IPv6 addresses.

Symptoms include:

  • Multiple non-stale IPv6 entries mapping to the same IPv4 address in dSSM
  • Application errors such as HTTP 503 responses
  • Intermittent traffic disruptions
  • Inconsistent mapping records when querying the dSSM database using the mrfdb tool

This issue occurs when the dnsnat46 iRule executes rapidly in close succession, causing IPv4-to-IPv6 mapping entries to be overwritten in the dSSM database.

Environment

  • Product: BIG-IP SPK
  • DNS46/NAT46 feature enabled via F5SPKEgress Custom Resource
  • Distributed Session State Management (dSSM) database deployed
  • Dynamic DNS46 entries (non-static mappings)
  • FQDNs with multiple AAAA records in DNS responses
  • High-frequency DNS query patterns

Cause

ID 2162233

Answer/Recommended Actions

Until a fix is released for ID 2162233, you can use static DNS46 Entries for critical mappings to avoid the issue instead of relying on the iRule's dynamic entry creation. Follow the instructions at https://clouddocs.f5.com/service-proxy/1.7.14/spk-egress-crd.html#manual-dns46-entry to learn how to create manual mapping entries.
