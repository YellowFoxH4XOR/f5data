K000134650: Downloading a UCS from BIG-IQ UI fails on v8.3.0

Type
Support Solution
Published
2023-05-17
Updated
2025-08-22
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.X, 8.3.0
Source
https://my.f5.com/manage/s/article/K000134650

Description

Downloading a UCS from the BIG-IQ UI running v8.3.0 fails with an error that appears similar to the following:

File does not exist or file path is not a file: /shared/f5os_backup/{backup_file_name}.ucs

 

Environment

BIG-IQ v8.3.0

 

Cause

ID1295077

 

Recommended Actions

This issue is resolved in BIG-IQ version 8.4.0, upgrade is recommended

or

When BIG-IQ has not been used to manage F5OS platforms or devices

If the BIG-IQ does not have any managed F5OS platform or device, the workaround is to delete directory /shared/f5os_backup and create a symbolic link /shared/f5os_backup pointing to /shared/ucs_backups/ directory.

 

Here are the steps with the corresponding commands:

1. Delete the /shared/f5os_backup/ directory.

rm -rf /shared/f5os_backup


2. Create a symbolic link.

ln -s /shared/ucs_backups /shared/f5os_backup

 

When BIG-IQ has been used to manage F5OS platforms or devices

If the BIG-IQ has been used to manage an F5OS or device, copy any existing backup files from /shared/f5os_backup into /shared/ucs_backups, delete the directory /shared/f5os_backup and then create a symbolic link /shared/f5os_backup pointing to /shared/ucs_backups/ directory.

Here are the commands:

1. Copy any existing backup files from /shared/f5os_backup into /shared/ucs_backups/ directory.

cp /shared/f5os_backup/* /shared/ucs_backups/


2. Delete the /shared/f5os_backup directory.

rm -rf /shared/f5os_backup


3. Create a symbolic link.

ln -s /shared/ucs_backups /shared/f5os_backup
