Description

On Passive FTP Virtual Server, Related iRule for Data Channel contains a TCP::respond command, but it's not triggering.

Environment

  • Virtual Server for passive FTP.
  • Related iRule for Data Channel.

Cause

TCP::respond command is only available when a TCP Full Proxy profile is used on the connection flow.
Control Channel is established by the TCP profile on the Virtual Server.
The related (data) connection is created by the FTP profile. By default, it is done using an internal FastL4 profile.
TCP::respond is not available for FastL4 based flows.

Recommended Actions

Create a custom FTP profile and enable "Inherit Parent Profile". Then, assign this custom FTP profile to your virtual server for passive FTP.
This will establish the data connection using same TCP profile used when creating the control connection.
