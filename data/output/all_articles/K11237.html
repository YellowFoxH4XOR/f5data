Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K14120: Defining advanced NTP configurations on the BIG-IP system (11.x - 12.x)

Purpose

Certain Network Time Protocol (NTP) advanced features such as NTP authentication are not natively supported in the Configuration utility, the bigpipe utility, or the Traffic Management Shell (tmsh) utility. As a result, these features must be configured manually using the methods described in the following sections.

Prerequisites

You must meet the following prerequisite to use this procedures:

  • Expert knowledge of the NTP protocol
  • CLI access
  • Familiarity with a text editor in the Linux environment

Description

NTP is a protocol for synchronizing the clocks of computer systems over the network. On BIG-IP systems, accurate timestamps are essential to guarantee the correct behavior of a number of features. While in most cases it is sufficient to configure a couple of time servers that the BIG-IP system will use to update its system time, it is also possible to define more advanced NTP configurations on the BIG-IP system.

Note: For more information about configuring NTP servers on the BIG-IP system, refer to K3122: Using the BIG-IP Configuration utility to add an NTP server and K8442: Configuring the BIG-IP system to use an NTP server from the command line (9.x - 10.x).

Important: By changing the default NTP configuration, the BIG-IP system may become vulnerable to certain remote attacks that would normally not affect the BIG-IP system. For more information, refer to K9889: NTP vulnerability CVE-2009-0021 and K10905: NTP vulnerability CVE-2009-3563.

Symmetric key authentication

Some of the following procedures involve authenticating NTP packets. Authentication support allows the NTP client to verify that servers are known and trusted, and not intruders intending to masquerade as a legitimate server. This article only describes one authentication method, which is based on symmetric key cryptography; however, you should be aware that other authentication methods are also available.

You must complete this section before implementing any of the configurations described in this article that involve authentication:

Impact of procedure: Configuring the NTP with key authentication will require the remaining NTP peers to have the same key.

  1. NTP keys are specified in the /etc/ntp/keys file. Each line in this file consists of three fields: the key identifier, the key type, and the passphrase or key itself.
  2. Connect to the BIG-IP system command line.
  3. Choose a passphrase and define it in the /etc/ntp/keys file by executing the following command where <passphrase> is the passphrase you have chosen:

    echo "1 M <passphrase> #MD5 Key" > /etc/ntp/keys

    For example:

    echo "1 M KD6ma870?0AD&uP #MD5 Key" > /etc/ntp/keys

    Note: This command assumes that you have not previously configured any other keys in the /etc/ntp/keys file. Running this command will overwrite the file.
  4. Make sure this key is installed on all the NTP servers and clients participating in the NTP time synchronization.
  5. Ensure this key will be backup in a UCS archive by adding this key as an entry to the UCS archive entry. You can do so by following the procedure documented in the Adding a UCS archive entry section on K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive
  6. Optional: You can verify if the NTP authentication is working properly through packet captures by observing that the key IDs are similar for requests as well as responses and the MAC fields are filled.

Configuring the BIG-IP system as an NTP server

Impact of procedure: None.

  1. Ensure that the self IP that you want to listen for NTP requests is configured to accept UDP traffic on port 123. If required, adjust the Port Lockdown setting of the self IP by navigating to Network > Self IPs in the Configuration utility.

    Note: For more information, refer to K7317: Overview of port lockdown behavior (9.x).
  2. Connect to the BIG-IP system command line.
  3. Create a temporary NTP include file that will be later merged into the BIG-IP system configuration:

    touch /var/tmp/ntp_include
  4. Using a text editor, edit the file you have just created.
  5. Paste the following configuration into the text editor:

    ntp include "
    restrict <Network IP> mask <Network Mask> nomodify notrap
    "

    For example:

    ntp include "
    restrict 192.168.1.0 mask 255.255.255.0 nomodify notrap
    "
  6. Save the file and quit the text editor.
  7. Install the NTP include file by executing the following command:

    bpsh < /var/tmp/ntp_include

Configuring the BIG-IP system to synchronize with an NTP server only if authentication is successful

Impact of procedure: None.

  1. Ensure that you have set up NTP authentication as described in the Symmetric key authentication section.
  2. Connect to the BIG-IP system command line.
  3. Create a temporary NTP include file that will be later merged into the BIG-IP system configuration:

    touch /var/tmp/ntp_include
  4. Using a text editor, edit the file you have just created.
  5. Paste the following configuration into the text editor:

    ntp include "
    server <ntp server> key <trusted key number> iburst
    trustedkey <trusted key number>
    "

    For example:

    ntp include "
    server 192.168.1.10 key 1 iburst
    trustedkey 1
    "
  6. Save the file and quit the text editor.
  7. Install the NTP include file by executing the following command:

    bpsh < /var/tmp/ntp_include

Other NTP configurations and the ntp-keygen utility

This article only discusses some of the advanced NTP configurations that you can implement on the BIG-IP system. For example, instead of using symmetric key authentication, you may configure NTP to use the Autokey security protocol, which is based on public key cryptography.

When defining other advanced NTP configurations, you may be required to use the ntp-keygen command line utility. However, executing this utility on the BIG-IP system returns the following error message:

RAND_load_file /root/.rnd not found or empty

This error message indicates that the /root/.rnd random seed file is missing. The /root/.rnd file is used to randomize the entropy seed to initialize the internal pseudo-random number generator, which is used by the OpenSSL library routines. If you require using the ntp-keygen utility, you may generate the missing file by executing the following command:

dd if=/dev/random of=/root/.rnd bs=512 count=1
