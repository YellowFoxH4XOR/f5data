Description

After upgrade from v15.1.x to v16.1.x application fails with [F5RST: Malformed HTTP header error]

 

Environment

LTM upgraded to v16.1.x getting "Malformed HTTP header error" and BIG-IP will reset the connection. This works in v15.1.x

 

Cause

In v15.1.x the white space in header name was controlled with a sys db tmm.http.rfc.allowwsheadername variable, this is enabled by default.

In v16.1.x the sys db tmm.http.rfc.allowwsheadername variable is ignored as a new per http profile enforcement variable "allow-ws-header-name" is introduced. This is disabled by default, hence the application breaks after upgrade.

Recommended Actions

Change the http profile with enforcement variable "allow-ws-header-name" set to enable

Note: Do not modify the default profile, create a new profile if the default one is in use.

In CLI:

1. To view enforcement allow-ws-header-name setting on the http profile used on the virtual server (my-http in the example below)

tmsh list ltm profile http my-http enforcement { allow-ws-header-name }


You should see a similar output:

ltm profile http my-http {
  enforcement {
    allow-ws-header-name disabled
  }
}

 

2. Change allow-ws-header-name enformcement for my-http profile

tmsh modify ltm profile http my-http enforcement { allow-ws-header-name enabled }
tmsh save sys config


In Web Interface (GUI):

1. Navigate to: Local Traffic > Profiles : Services : HTTP
2. Select the profile assigned to the virtual server (if the default one is used, create a new profile instead)
3. Enable Allow Space Header Name under Enforcement section:


4. Save changes.
5. If this is a new profile, assign it to the relevant virtual server.
