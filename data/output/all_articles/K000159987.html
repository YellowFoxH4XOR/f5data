Description

When attempting to access Application Requests in the BIG-IP ASM Configuration utility, users may encounter a pop-up error message stating:

"BIG-IP says: Failed to load requests"

This issue prevents viewing ASM event logs via the GUI at Security > Event Logs > Application > Requests.

Environment

  • BIG-IP systems with ASM provisioned
  • ASM enabled with event logging and policy learning active

Cause

Insufficient disk space on the partition used by ASM for logging and database operations. When the disk becomes full, ASM cannot perform critical operations including:

  • Updating event logs
  • Processing policy suggestions
  • Executing MySQL database operations

The disk space exhaustion prevents ASM subsystems from functioning properly, resulting in the "Failed to load requests" error.

Answer/Recommended Actions

To resolve this issue, perform the following steps:

  1. Check disk space usage on the BIG-IP system using the command:
    df -h
  2. Identify large files consuming disk space, particularly in /var and its subdirectories:
    find /var -xdev -type f -exec du {} \; | sort -rn | head -20
  3. Remove unnecessary large files, such as:
    • .pcap files (packet capture files)
    • .qkview files (diagnostic files)
    • Old backup files
  4. After freeing disk space, verify that ASM operations return to normal.
  5. Monitor disk usage regularly to prevent recurrence.

Note: Use caution when deleting files. Ensure files are no longer needed before removal.

Additional Information

ASM operations, including event logging, policy suggestions, and database operations, require sufficient free disk space to function correctly. When disk space is exhausted:

  • ASM subsystems may fail with MySQL-related errors
  • Policy suggestions cannot be updated
  • Event logs cannot be written or retrieved
  • Database operations fail with "Disk full" errors
