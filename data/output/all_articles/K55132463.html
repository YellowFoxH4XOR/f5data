Known Issue

By default, the Category Lookup policy item in SSL Orchestrator does not categorize non-encrypted HTTP traffic. The Category Lookup policy item works with HTTPS using Server Name Indication (SNI) and HTTP Connect using the header Hostname, but the Category Lookup policy item cannot match the URL database against an HTTP Host header.

Impact

The Category Lookup policy item does not apply to HTTPS traffic. HTTPS traffic is handled correctly.

Workaround

To work around this issue, you can disable strict updates, modify the per-request policy using the Visual Policy Editor to add an iRule to the policy and to mark the category during the initial TCP connection.

Impact of workaround: When you change configuration of certain objects, the system re-deploys the various BIG-IP objects to match your new configuration. This re-deployment overwrites any existing BIG-IP objects without warning about existing changes. Before performing this procedure, you must first refer to the warnings and directions in the Disabling Strict Updates section of K00805840: SSL Orchestrator known issues and workarounds.

This workaround does not catch mid-connection URL changes, and any mid-connection changes continue to follow the policy defined by the original URL. Mid-connection changes that cause an issue for this should be rare.

This issue occurs when all of the following conditions are met:

  • More than one server URL uses the same IP address.
  • The server URLs categorize differently within the URL Categorization policy item and you need to differentiate between the URLs for the policy decisions.
  • Servers use HTTP (not HTTPS).
  • A policy item connects immediately from one system to another without first requesting a different URL.
  • The client uses the same TCP connection for both BIG-IP systems.

Note: The first condition is not uncommon. Conditions 2-4 are not common. Condition 5 is extremely uncommon and may indicate a problem with the client.

Note: If you add a new custom URL category, or if the URL category list changes, you need to update the data group.

Before any traffic is processed, you need to create a data group of the URL categories.

Overview of the system process

For each request, the BIG-IP system does the following:

  • Updates a variable with the hostname from the HTTP URI in the store_host_header iRule
  • In the per-request policy, branches HTTP traffic in using the Categorization macro
  • Runs the get_urlcat iRule on the traffic, matching the URI to the data group and updating a BIG-IP APM variable
  • Copies the BIG-IP APM variable into the variable that the URL branching information uses in the next macro

Creating data groups

  1. Log in to the BIG-IP system command line interface (CLI) using the root account.
  2. Create a data group of URL categories based on the configuration of the system.

    Note: To use this workaround with non-customized categories, you must have URL Filtering or Secure Web Gateway (SWG) licensed and configured. For more information, refer to K53612135: Configuring SSL Orchestrator without licensing URL Filtering or SWG.

  3. To create the data group the first time, enter the following commands:

    tmsh list sys url-db url-category |grep -E 'sys url-db url-category| cat-number' |sed -e 's/sys url-db url-category //g;s/\s\s\s\scat-number//g;s/ {//g' |sed "N;s/\n/ :=/" |sed -e 's/$/,/' > /var/tmp/urlcat.txt

    tmsh create /sys file data-group urlcat_file separator ":=" source-path file:/var/tmp/urlcat.txt type string

    tmsh create /ltm data-group external urlcat_dg external-file-name urlcat_file

  4. To update the data group when the URL categories change, enter the following script commands:

    tmsh list sys url-db url-category |grep -E 'sys url-db url-category| cat-number' |sed -e 's/sys url-db url-category //g;s/\s\s\s\scat-number//g;s/ {//g' |sed "N;s/\n/ :=/" |sed -e 's/$/,/' > /var/tmp/urlcat.txt

    tmsh modify /sys file data-group urlcat_file separator ":=" source-path file:/var/tmp/urlcat.txt

    tmsh modify /ltm data-group external urlcat_dg

Copying and updating iRules

  1. Install the SSL Orchestrator Extras library.

    Note: For more information, refer to the Using the SSL Orchestrator Extras Library section in K00805840: SSL Orchestrator known issues and workarounds.

  2. Navigate to Local Traffic> iRules.
  3. Click Create.
  4. For Name, type sslo_get_category.
  5. In the Definition box, enter the following:

    when ACCESS_PER_REQUEST_POLICY ITEM_EVENT { call /Common/sslo_extras::/get_urlcat }

  6. Click Finished.
  7. Open the iRule named sslo_<system name>-in_t.

    Note: sslo_<system name> is your SSLO system name from the Deployment Settings page.

  8. Copy the contents from the iRule Definition box.
  9. Close the iRule and create a new iRule named <sslo_system name>-in_t-copy.
  10. Paste the contents from the system iRule in the new iRule.
  11. Find the when CLIENT_DATA section of the iRule and immediately after the set said [TCP::payload] item, and before the closing }, add the following:

    ## MOD: Call update host headers for http categorization
    call /Common/sslo_extras::/store_host_header $said
    ## END MOD

  12. Click Finished.

Updating the BIG-IP APM per-request policy

  1. Navigate to SSL Orchestrator > Policies > Access Per-Request Policies.
  2. Find ssloP_<chain name>_prpTcp.

    Note: You can filter by typing the policy name in the box and clicking Search.

  3. Under Per-Request Policy, click the + icon next to Show All.
  4. Click ssloP_<chain name>_prpTcp.

    The Visual Policy Editor opens.

  5. Click the Categorization macro.
  6. Click the L7 Protocol Lookup policy item and click the Branch Rules tab.
  7. Click Add Branch Rule and for Name type HTTP.
  8. For Expression, click change to edit.
  9. Click Add Expression.
  10. For Agent Sel, click L7 Protocol Lookup.
  11. For Condition, click L7 Protocol.
  12. For L7 Protocol Is, click HTTP.
  13. Click Add Expression.
  14. Click Finished.
  15. On the Branch Rules tab, click the down arrow icon to move the new branch rule under the HTTP Connect branch rule.
  16. Click Save.
  17. In the Categorization macro, click the + icon on the HTTP branch.
  18. Click the General Purpose tab, click iRule Event, and click Add Item.
  19. For Name, type HTTP Data Collection.
  20. For ID type sslo_get_category, and for Expect Data click Client Accepted, then click Save.
  21. On the fallback branch after the new iRule event policy item, click the + icon.
  22. On the Assignment tab, click Variable Assign, and then click Add Item.
  23. For Name type HTTP Host Variable Assign, and then click Add new entry.
  24. Click change to edit.
  25. In the Custom Variable box, enter the following:

    perflow.category_lookup.result.categories

  26. In the Custom Expression box, enter the following:

    return [mcget {perflow.scratchpad}]

  27. Click Finished and then click Save.
