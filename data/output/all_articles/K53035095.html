K53035095: New Branch rules in Per-request policy may fail with ''ERR_NOT_FOUND: failed to find next policy item''

Description

The "ERR_NOT_FOUND: failed to find next policy item" message indicates that the system is unable to process the new branch rule that was created or modified. This most likely indicates that the conditional expression being evaluated isn't querying the right session or subsession variables, which can be mishandled in the syntax generated by the simple expression configuration of the visual policy editor.

Environment

  • APM
  • Per-Session Policy
  • Per-Request Policy
  • Visual Policy Editor
  • Session Variable
  • Subsession Variable

Cause
When creating branch rules for a per-session policy, the simple configuration mode that allows you to build statements in a graphical interface will generate conditions that search for a subsession variable:

expr {[mcget {subsession.ad.last.attr.memberOf}] contains "CN=your_group,CN=Users,DC=example,DC=com"

In many circumstances, for example when trying to query a user's AD group membership, it's inefficient to re-run an AD query on every request, so the group membership is stored as a session variable during the initial per-session policy evaluation rather than as a subsession variable specific to this request. This means that that data isn't easily accessible when using the simple configuration mode. Since the request is still a part of the overall APM session that data is still accessible, but accessing it will require us to manually specify the variable.

Recommended Actions

Use the Advanced configuration tab to manually specify the condition, and reference the session variable rather than the subsession variable
  1. Open the relevant policy object in the Visual Policy Editor
  2. Select the "Branch Rules" tab and select the "change" link next to the Expression for the affected branch rule
  3. If you had previously configured this branch rule using the simple configuration mode, it should populate with the current (failing) expression. Click on the Advanced tab to see the exact syntax being evaluated. It will look something like this:
    • expr {[mcget {subsession.ad.last.attr.memberOf}] contains "CN=your_group,CN=Users,DC=example,DC=com"}
  4. When trying to query data that was gathered when the user initially logged in for this session, we need to replace any instance of "subsession" in our variable names with "session". For example:
    • expr {[mcget {session.ad.last.attr.memberOf}] contains "CN=your_group,CN=Users,DC=example,DC=com"}
