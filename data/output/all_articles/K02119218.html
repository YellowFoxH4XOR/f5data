Description

You have BIG-IP appliance that uses the Nitrox 3 hardware compression chip: 5xxx, 7xxx, 12250 or B2250.

To check if the platform has the nitrox3 by running the following command:

tmctl -w 200 compress -s provider

provider
--------
bzip2   
lzo     
nitrox3   <--------
zlib

You have virtual server with HTTP compression enabled.  
You observed the BIG-IP occasionally get restarted and produce a core file. 

In /var/log/ltm log file, you would see similar logs as below are logged 

  crit tmm[12404]: 01010025:2: Device error: n3-compress0 Nitrox 3, Hang Detected: compression device was reset (pci 02:00.1, discarded 1).
  crit tmm[12404]: 01010025:2: Device error: n3-compress0 Zip engine ctx eviction (comp_code=0): ctx dropped.

Environment

  • BIG-IP appliance that uses the Nitrox 3 hardware compression chip: 5xxx, 7xxx, 12250 and B2250.
  • HTTP compression is used

Cause
Bug ID 941257: Occasional Nitrox3 ZIP engine hang

Recommended Actions

  1. Disable HTTP compression from your HTTP profile of the virtual server to work around the issue.
  2. Please upgrade to a fixed version. If you require an EHF on the non-fixed versions, please contact F5 support to acquire the EHF and follow article K13123: Managing BIG-IP product hotfixes (11.x - 16.x) to install it.
