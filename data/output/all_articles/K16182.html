Known Issue

The Traffic Management Microkernel (TMM) may restart when an iRule event has no TCL code to process.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server to use an iRule.
  • The iRule contains an event and TCL code to process when the iRule event is triggered.

    For example, the following iRule logs the connected string when the CLIENT_ACCEPTED event is triggered:

    ltm rule log_connection {
        when CLIENT_ACCEPTED {
            log local0. "connected"
        }
    }

  • You remove the TCL code from the iRule, leaving the iRule event with nothing to process.

    For example, the following iRule has no TCL code to process when the CLIENT_ACCEPTED event is triggered:

    ltm rule log_connection {
        when CLIENT_ACCEPTED {
        }
    }

Impact

TMM may produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H504824 on the Diagnostics > Identified > Medium|High screen.
  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file to the /var/core directory.

Workaround

None. Ensure that all iRule events are configured to process TCL code when triggered, or remove the empty iRule event.
