Description

After migrating a syslog-ng configuration from a VIPRION multi-slot chassis to an rSeries appliance, syslog-ng becomes unstable and crashes at startup. The issue occurs when the syslog-ng include configuration contains the line source(s_cluster).

Environment

  • F5OS
  • Viprion
  • Syslog

Cause

The source(s_cluster); directive is defined exclusively for multi-slot systems such as VIPRION. It configures syslog-ng to receive log messages from cluster members via the mgmt_bp interface. On appliance platforms such as rSeries, this source is not defined in /etc/syslog-ng/syslog-ng.conf. Referencing an undefined source in a syslog-ng include statement causes syslog-ng to crash.

Answer/Recommended Actions

  1. Edit the syslog-ng configuration on the rSeries appliance using:
    tmsh edit sys syslog all-properties
  2. Locate any include block that references source(s_cluster);.
    Remove the source(s_cluster); line from the configuration. For example, change:
log {
    source(s_syslog_pipe);
    source(s_cluster);
    filter(f_splunk);
    destination(d_remlog);
};

to:

log {
    source(s_syslog_pipe);
    filter(f_splunk);
    destination(d_remlog);
};

3. Save the configuration changes.

4. Validate that syslog-ng starts and operates stably after the change.
