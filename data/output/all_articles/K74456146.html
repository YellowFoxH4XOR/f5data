K74456146: SDC /var partition is full

Type
Support Solution
Published
2020-12-17
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.0.0, 5.1.0, 5.0.X, 5.X.X, 5.2.X, 5.2.0, 5.1.X, 4.4.0
Source
https://my.f5.com/manage/s/article/K74456146

Description

There are few causes for /var getting full. One of the causes might be when Traffix’s logs in /var/log are deleted but still occupy space.

Environment

  • SDC
  • EMS

Cause

Deleted log files still occupy space.

Recommended Actions

The following should be performed on each node.

Finding and removing log files that have been deleted
Ensuring Traffix logs are rotated regularly

Finding and removing log files that have been deleted

The first step is to use the 'lsof | grep deleted' command, to find all log files which do not had been deleted but still occupy space (aka ghost’s files).

# lsof | grep deleted
java    6522    root    1w    REG    253,10    12782756    653024    /var/log/traffix_config_mgr-config1-stdout.log-20150921 (deleted)
java    6522    root    2w    REG    253,10    12782756    653024    /var/log/traffix_config_mgr-config1-stdout.log-20150921 (deleted)
java    6614    root    1w    REG    253,10    42119138    652969    /var/log/traffix_cpf-cpf1-stdout.log-20150923 (deleted)
java    6614    root    2w    REG    253,10    42119138    652969    /var/log/traffix_cpf-cpf1-stdout.log-20150923 (deleted)

Although you can no longer see these files using the 'ls' command, they still occupy space. If the files' sizes are large, it can cause /var/log to become full.

If you find files like in the example above, you should consider an immediate action to stop the process to release the deleted files. In this case, Config_mgr & CPF should be restarted, and you can re-run the 'lsof | grep deleted' command to verify that the files have been removed.

Ensuring Traffix logs are rotated regularly

To ensure this issue does not happen again, check the log rotation definitions for Traffix.

Open the '/etc/logrotate.d/logrotate-traffix.conf' file, and make sure all related traffix_*.log are set simiar to the following:

/var/log/traffix_*.log {
    create
    rotate 7
    daily
    missingok
    notifempty
    delaycompress
    compress
    copytruncate
}

If you make any change to /etc/logrotate.d/logrotate-traffix.conf, you need to restart the rsyslog service:
# service rsyslog restart
