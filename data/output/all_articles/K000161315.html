K000161315: 'Illegal cross-origin request' violations triggered against requests

Type
Support Solution
Published
2026-05-21
Updated
2026-05-21
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000161315

Description

Legitimate POST requests to a specific URL are blocked by BIG-IP ASM with a Cross-site Request Forgery Attack type. but the violation is actually triggered by the CORS (Cross-Origin Resource Sharing) enforcement configuration, specifically due to the HTTP Origin header being set to null in the request.

  • Violation logged: Illegal cross-origin request
  • Origin header value in the blocked request is null
  • Violation can occur even when CSRF token validation is configured and the CSRF token is present in the request

Environment

  •  BIG-IP ASM
  • CORS enforcement enabled on the policy

Cause

The root cause is CORS enforcement being enabled in the ASM policy, not a CSRF token misconfiguration. BIG-IP ASM currently does not permit a null value in the Origin header when CORS enforcement is active.

Answer/Recommended Actions

The violation can be resolved by disabling CORS enforcement either globally or per URL:

Option 1: Disable CORS Enforcement Globally

  1. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. Locate the illegal-cross-origin-request violation.
  3. Set the enforcement action to Disabled (uncheck Block).
  4. Click Save and Apply Policy.

Option 2: Disable CORS Enforcement Per URL

  1. Navigate to Security > Application Security > URLs > Allowed HTTP URLs.
  2. Select the specific URL 
  3. Switch to Advanced View.
  4. Select the HTML5 Cross-Domain Request Enforcement tab.
  5. Change the Enforcement Mode to Disabled.
  6. Click Save and Apply Policy.

Additional Information

  • A null Origin header and a CSRF violation (VIOL_CSRF) may appear related but can have distinct underlying causes. Always verify whether the violation is driven by CSRF token validation or CORS enforcement by reviewing the specific violation sub-type (Illegal cross-origin request indicates CORS enforcement).
  • This behavior is expected when CORS enforcement is enabled and the browser sends Origin: null.
