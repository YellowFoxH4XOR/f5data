Issue

This article applies to BIG-IP 10.1.x through 11.4.x. For information about other versions, refer to the following article:

  • K16507: The device certificate is generated using the SHA-2 hash algorithm (11.5.0 and later)

Beginning in BIG-IP 10.1.0, Enterprise Manager 1.8.0 and BIG-IQ 4.0.0, the device certificate is generated using the SHA-1 hash algorithm.

In previous BIG-IP and Enterprise Manager versions, the device certificate is generated using the MD5 hash algorithm.

Note: The device certificate is a self-signed SSL certificate that is automatically generated when the software is first installed on the system. However, when you upgrade the system to a new software version and roll forward an existing configuration, the system will continue to use the same device certificate. The device certificate is used for a number of features; for example, this is the certificate presented to your browser when you connect to the Configuration utility. For more information about its additional uses, refer to:

  • K8187: Overview of BIG-IP device certificates (9.x - 10.x)
  • K15664: Overview of BIG-IP device certificates (11.x)

This change in behavior was introduced in response to the weaknesses discovered in the MD5 hash algorithm.

Note: For more information, refer to K11624: The default BIG-IP SSL profiles no longer include DES-CBC-SHA and ciphers containing the MD5 hash.

F5 Product Development tracked this change in behavior as ID 205419 and ID 316707 (formerly CR114797).

Additional information

Although this is not required from a functional standpoint, if a BIG-IP system or Enterprise Manager is currently using an MD5 device certificate, either because the system is running an old software version or because the device certificate was rolled forward, you can replace it with a SHA-1 device certificate by performing the following procedure:

  1. Connect to the BIG-IP system or Enterprise Manager command line.
  2. Change directories to the /config/httpd/conf/ssl.crt/ directory by typing the following command:

    cd /config/httpd/conf/ssl.crt/
  3. Back up the server.crt file by typing the following command:

    cp server.crt server.crt.sol12647
  4. Generate a new SHA-1 device certificate by typing the following command:

    openssl req -new -key ../ssl.key/server.key -x509 -out server.crt -sha1
  5. Restart the httpd process by typing the following command:

    bigstart restart httpd

Alternatively, if the device in question is running BIG-IP 10.1.0 or later or Enterprise Manager 1.8.0 or later, you can renew the device certificate using the Configuration utility (System > Device Certificates > Device Certificate).

Note: Additional considerations should be taken into account when renewing the device certificate of a BIG-IP GTM or BIG-IP Link Controller. For more information, refer to K6353: Updating an SSL certificate on a BIG-IP GTM or Link Controller system.

If you are unsure about the hash algorithm used by a device certificate, type the following command from the command line of the device in question:

openssl x509 -noout -text -in /config/httpd/conf/ssl.crt/server.crt | grep Signature -m 1

For example, the following output shows that the device certificate was generated using the SHA-1 hash algorithm:

Signature Algorithm: sha1WithRSAEncryption
