Description

/var/log/asm shows similar entries to the ones listed below:

Mar 28 08:42:51 ww.test.com err perl[15837]: 01310001:3: event code I2812 Credential Stuffing cloud service request timeout reached. Current timeout is 1000 and can be changed with the cred_stuffing_timeout internal parameter

When run following command on command line, we see Connection Timeout in the output.

$ tmctl asm_cloud_services_stats

service_name              latency_avg_1_min latency_avg_5_min latency_max_1_min latency_max_5_min state message      

---------------------------------------- ----------------- ----------------- ----------------- ----------------- ------ -------------------

/Common/f5-credential-stuffing-cloud-app        0        0        0        0 Yellow Connection Timeouts

Environment

  • BIG-IP ASM
  • Credential Stuffing

Cause

When there is a delay in getting response on BIG-IP from bf.shpapi.com for service /Common/f5-credential-stuffing-cloud-app, timeout will occur, and sometimes this is expected because we can't contorl the response over the Internet.

 Recommended Actions

If you don't use Credential Stuffing feature on your asm policy, you can safely ignore this message or you can increase the cred_stuffing_timeout to a larger value with following command.

Note: Restarting asm service will affect traffic processing, so please schedule a Maintenance Window to run the command.

# /usr/share/ts/bin/add_del_internal update cred_stuffing_timeout 6000  

# bigstart restart asm
