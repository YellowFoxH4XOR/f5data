K9935: A Stream profile may not perform text replacements when the BIG-IP WebAccelerator is also enabled on the virtual server

Source

Topic

If BIG-IP WebAccelerator is enabled on a virtual server that also has a Stream profile applied, the Stream profile cannot perform the intended text replacements. The BIG-IP WebAccelerator compresses the response before it is processed by the Stream profile. The Stream profile expects a text stream but receives compressed (binary) data and cannot match the configured Source string setting in the Stream profile.

Note: Due to architectural enhancements introduced in BIG-IP WebAccelerator version 10.0.0, this limitation no longer applies.

Note: The BIG-IP WebAccelerator module performs its own compression, separate from that which can be performed by the BIG-IP LTM.

Workaround

You can prevent this issue from occurring by disabling BIG-IP WebAccelerator compression for the affected objects. To do so, perform the following procedure:

  1. Log in to the BIG-IP WebAccelerator Configuration utility.
  2. Select the affected node in the policy tree.
  3. Navigate to the Acceleration Rules Assembly tab.
  4. Disable Content Compression by clearing the Enable Content Compression check box.
  5. Save and publish the new policy.

On BIG-IP LTM systems licensed for compression, it is also possible to enable compression to be performed by the BIG-IP LTM rather than by the BIG-IP WebAccelerator. To do so, disable compression for all nodes in the BIG-IP WebAccelerator policy and configure a BIG-IP LTM compression profile instead. Since BIG-IP LTM compression takes place after the Stream profile has processed the response, the stream replacement will be performed, then the response will be compressed and forwarded to the client.
