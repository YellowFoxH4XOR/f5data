Description

After upgrading BIG-IP VE to v14.1.2.6 running on VMWare ESXi 6.0 Host, the BIG-IP lost network connectivity and was only accessible via the management interface.

Symptoms include:

  • Remote authentication is not working
  • VIP and pool status is unavailable
  • Unable to ping the next hop router

Environment

  • BIG-IP VE v14.1.2.6
  • VMWare ESXi 6.0
  • Vmxnet3 driver
  • No network access on TMM interfaces

Cause

The vmxnet3 driver is not working in this environment

Recommended Actions

Impact of workaround: The following procedure requires you to edit the /config/tmm_init.tcl file and restart the Traffic Management Microkernel (TMM). Network traffic is disrupted while TMM restarts.

Important: The /config/tmm_init.tcl file is not included with a configuration synchronization (ConfigSync); you must perform the procedure on each device individually. For members of a high availability (HA) device group, you must perform the following procedure on each member of the device group. Additionally, the procedure must be performed for each boot location you wish to boot to.

1. Log in to the BIG-IP bash command line.

2. Confirm the driver in use by examining the output of the following command:
tmctl -d blade tmm/device_probed

Output appears similar to the following example:

pci_bdf      pseudo_name type      available_drivers     driver_in_use
------------ ----------- --------- --------------------- -------------
0000:03:00.0             F5DEV_PCI xnet, vmxnet3, sock,               
0000:0b:00.0 1.1         F5DEV_PCI xnet, vmxnet3, sock,  vmxnet3      
0000:13:00.0 1.2         F5DEV_PCI xnet, vmxnet3, sock,  vmxnet3      
0000:1b:00.0 1.3         F5DEV_PCI xnet, vmxnet3, sock,  vmxnet3

3. Enter the following command to append the line to the /config/tmm_init.tcl file:

Note: If the /config/tmm_init.tcl file does not already exist, this command creates it and adds the following line, depending on version.

echo "device driver vendor_dev 15ad:07b0 sock" >> /config/tmm_init.tcl

4. Restart TMM to reload the driver by entering the following command:
bigstart restart tmm

5. After TMM restarts, confirm the driver in use by examining the output of the following command:
tmctl -d blade tmm/device_probed

Output appears similar to the following example:

pci_bdf      pseudo_name type      available_drivers     driver_in_use
------------ ----------- --------- --------------------- -------------
0000:03:00.0             F5DEV_PCI sock, vmxnet3, unic,
0000:0b:00.0 1.1         F5DEV_PCI sock, vmxnet3, unic,  sock
0000:13:00.0 1.2         F5DEV_PCI sock, vmxnet3, unic,  sock
0000:1b:00.0 1.3         F5DEV_PCI sock, vmxnet3, unic,  sock
