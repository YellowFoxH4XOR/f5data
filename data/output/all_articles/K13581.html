Topic

Note: This issue does not affect Windows Vista or later versions of Windows.

If a BIP-IP APM network access IP lease pool is configured to use a supernetted IP range (that is, a block of IP addresses that cross an IP classful boundary), Windows XP may fail to establish a network connection. This issue occurs when an issue in the Windows XP TCP/IP network interface is set to an IP classful broadcast address. For more information on this, refer to the following Microsoft article, KB281579: Issues with using supernetted IP address ranges.

Note: The previous link takes you to a resource outside of AskF5, and it is possible that the information may be removed without our knowledge.

Workaround

To work around this issue, you can break the IP lease pool into classful segments. To do so, perform the following procedure:

Impact of workaround: The network access IP lease pool loses a small amount of IP address space.

This procedure uses the supernet address range 192.168.0.1 - 192.168.1.254 as an example.

  1. Log in to the Configuration utility.
  2. Click Access Policy.
  3. Click Network Access.
  4. Click the IPV4 Lease Pool name for the network access resource you want to edit.
  5. Take your original address range and divide it into a series of classful IP ranges.

    For example:

    Source IP address range: 192.168.0.1 - 192.168.1.254
    New classful IP address ranges:
    192.168.0.1 - 192.168.0.254
    192.168.1.1 - 192.168.1.254

  6. Enter the new IP range start address for the new classful IP range in the Start IP Address field.
  7. Enter the new IP range end address for the new classful IP range in the End IP Address field.
  8. Click Add.
  9. Repeat Steps 6 to 8 for each address range you are creating.
  10. Click the original IP address range in the Member List.
  11. Click Delete.
  12. Click Update.
