K000162103: F5 XC CDN Cache Rules Startswith Operator Does Not Support Wildcards

Type
Support Solution
Published
2026-07-06
Updated
2026-07-06
Source
https://my.f5.com/manage/s/article/K000162103

Description

When configuring CDN caching rules in the XC console there are several expressions that can be used including "Startswith". Startswith is a literal string prefix match. If you include an asterisk (*) in the Path Value then the rule is looking for a path that literally has an asterisk in it. Requests will Bypass the F5 CDN and not be cached.

Environment

  • F5® Distributed Cloud HTTP Load Balancer
  • F5 XC CDN
  • CDN Cache Rules

Answer/Recommended Actions

To match paths correctly using the Startswith operator, you must remove the wildcard and simply use the prefix you would like to match. If you want to use wildcards or regex, you must use the MatchRegex operator instead.

Example: You want to cache all images in the "images" directory like the logo.png in the following URL.
https://www.example.com/images/logo.png

This following will fail to match any image requests. You will see "x-cache-status: BYPASS"  in the response headers:

Path Match --> Startswith
Path Value --> /images/*


This will succeed:

Path Match --> Startswith
Path Value --> /images/
