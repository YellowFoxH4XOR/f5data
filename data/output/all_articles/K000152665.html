K000152665: BIG-IP will not establish HTTP/2 when ALPN is used when backlisted cipher is being used

Type
Support Solution
Published
2025-08-04
Updated
2025-08-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 17.1.2, 17.1.1, 17.1.X, 17.5.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000152665

Description

While trying to establish HTTP/2 connection, you might notice that despite configuring HTTP/2 profile with ALPN being enabled and HTTP/2 being offered by the client, connection is established not using HTTP/2.

Environment

  • BIG-IP

  • HTTP/2
  • ALPN

Cause

This can occur if selected cipher is blacklisted per RFC. Such cipher can not be used if "Enforce TLS Requirements" option in HTTP/2 profile is enabled, and even if HTTP/2 is offered via ALPN extension, HTTP 1.1 connection will be established.

Answer/Recommended Actions

This is expected behavior since per RFC7540 some ciphers are blacklisted as using those can lead to unexpected results. While connection with such ciphers will work if activation mode is set to "Always", this option is only intended for testing purposes.
