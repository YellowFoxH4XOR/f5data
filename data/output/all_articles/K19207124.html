Description

You have created a new virtual server on the BIG-IP system, but the virtual server does not process traffic.

Environment

  • BIG-IP
  • Virtual server
  • Available (green)
  • Existing pool

Cause
Assuming that the configured pool was pre-existing, here are some causes that the new available virtual server does not process traffic:

  • Routing: Pool contains unreachable members or members cannot reach the BIG-IP. Check the Source Address Translation setting on the new virtual server. In many scenarios selecting Auto Map for this setting will resolve the routing issue.
  • Service: Pool members listen on a different port than the virtual server. Check that the Port Translation setting is enabled in the Advanced configuration view.
  • Profile: The virtual server receives incompatible traffic for the pool members. Check that the correct profiles are applied such as udp, tcp, or http.
  • Protocol: The virtual server is configured with an incompatible protocol than the pool members. Protocol is a mismatch such as HTTP traffic sent HTTPS pool members.

Recommended Actions

  1. Verify that the chosen pool, pool members match the intended traffic of the virtual server.
  2. Ensure that traffic sent by the BIG-IP can route to and from the pool members.
    Note: As a quick test for routing issues you can enable SNAT Auto Map on the virtual server.
