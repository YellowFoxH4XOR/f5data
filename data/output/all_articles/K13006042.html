Description
When using an MTU that is smaller than the TCP MSS on the client side of the virtual server and hardware syncookies are enabled, traffic will fail. In a packet capture, you notice that TCP traffic is fragmented into multiple IP packets that are larger than the MTU of the vlan.

When looking at the output of tmsh show /ltm virtual <my-virtual-server>, you see that hardware SYN cookies have been previously activated, or are currently activated. Total Hardware will be larger than 0.

SYN Cookies
  Status                         not-activated
  Hardware SYN Cookie Instances           0
  Software SYN Cookie Instances           0
  Current SYN Cache                      10
  SYN Cache Overflow                      1
  Total Software                       1.0M
  Total Software Accepted                 0
  Total Software Rejected                 0
  Total Hardware                      10.0M
  Total Hardware Accepted              5.0M

Environment

  • BIG-IP versions prior to 14.1.4, 15.1.3, or 16.0
  • VLAN MTU is smaller than MSS. For example, client sends SYN with MSS 1460 and MTU is 1400.

    net vlan /Common/VLAN-EXAMPLE {
        interfaces {
            1.1 { }
        }
        mtu 1400
        tag 100
    }

Cause
Bug ID 803237: PVA does not validate interface MTU when setting MSS

Recommended Actions
If possible, increase the MTU of the VLAN. Otherwise, upgrade to a version with the fix for ID 803237

Additional Information
When troubleshooting this issue, you may notice SYN and SYN/ACK are missing from packet captures. PVA traffic such as hardware syncookies do not appear in TMM tcpdumps.
