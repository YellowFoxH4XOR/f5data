K000136067: Three issues when merging ASM policies

Type

Published
2023-09-25
Updated
2023-09-26
Source

Description

ASMAdvWAF policies can be merged to create one that incorporates both polices.

Environment

When merging polices there are 3 circumstances in which the merge will not work.

1. Application Language - The policies have an incompatible ' Application Language' configuration"

2. The policy is Case Sensitive - The policies have an incompatible 'Case Sensitivity' configuration"

3. Websocket URLs do not match - Differentiate between HTTP/WS and HTTPS/WSS URLs

Example Error message seen in the GUI: "Could not calculate the Policy Diff 'Policy Diff'. The policies have an incompatible 'Differentiate between HTTP and HTTPS URLs' configuration"

With ASM policies configured using the Standard method (from Security ›› Application Security : Security Policies : Policies List then click Create and follow the steps) this may not happen. However, if you try to merge policies created with the Guided Configuration and the Standard method this will likely happen each time you attempt to merge.

ASM policies created via the Guide Configuration by default will not match either the Websocket URLs and in some cases the Application Language with a policy configured the standard way.

Cause

Bug ID749482 Improve Policy Diff GUI

Recommended Actions

There are 3 ways this can be dealt with...

1) Create a policy via the Guided Configuration and add it to the virtual server. You will have to remove any ASM Policy already assigned to the virtual server. It will then need to go through the learning process to become a mature policy.

2) Adjust the polices to match.

a) With the Allowed Websocket URLs you can match them up.
b) For the Application Language and the Case Sensitive configuration that requires exporting the policy and manually modifying these options in the XML file then re-importing it and overwriting the one currently in use...

<encoding>utf-8</encoding>
<description>Fundamental Policy</description>
<case_insensitive>false</case_insensitive>


3) Configure the already existing policy created the standard way to act upon the traffic the Guided Configuration would do. For example if you need to configure API Security Protection and have the json file with the Open API Spec you can go to Security ›› Application Security : Content Profiles : JSON Profiles and create a json profile for the ASM policy by adding the file to the profile. It will still need some tweaking that would have been set up in one created via the Guided Configuration, but learning should take care of that.
