Topic

This article applies to BIG-IP 10.x. For information about other versions, refer to the following article:

  • K13878: The ramcache.maxmemorypercent variable controls memory allocation for the HTTP cache (11.x - 12.x)

Description

The BIG-IP system limits the amount of memory that the RAM Cache feature is allowed to use. By default, RAM Cache cannot use more than 50 percent of the provisioned memory, which is controlled by the BigDB ramcache.maxmemorypercent variable.

Important: The RAM Cache does not initialize and allocate memory until it is associated with a virtual server. Therefore, it is possible to configure a RAM Cache with a maximum cache size greater than 50 percent of the allowed amount, and the BIG-IP system will not report an error message until the RAM Cache is associated with a virtual server.

If the RAM Cache exceeds 50 percent of the memory provisioned to the BIG-IP LTM system, one of the following error messages may be reported:

01300001:3: RAMCACHE Initialize - Not enough memory available to create the cache. Please try reducing the cache size and max entries

01070668:3: The amount of ramcache memory assigned to HTTP profiles (xxxMB) exceeds the maximum amount (yyyMB) defined by Ramcache.MaxMemoryPercent (50)

RAM Cache initialization error message 01300001:3

The following error message is reported to the /var/log/ltm file:

01300001:3: RAMCACHE Initialize - Not enough memory available to create the cache. Please try reducing the cache size and max entries

This error message is reported under the following scenarios:

  • The Maximum Cache Size is configured at the 50 percent mark or within 16 MB of the 50 percent mark.

    For example, if the BIG-IP LTM memory provision is 852 MB, and the RAM Cache Maximum Cache Size is configured for 420 MB or 415 MB, the error message is reported.

  • Multiple HTTP profiles with RAM Cache enabled are assigned to different virtual servers.

    This scenario is most likely to occur in large configurations when multiple HTTP profiles with RAM Cache enabled are associated with different virtual servers. This affects both the BIG-IP LTM and BIG-IP WebAccelerator systems. For example, if a single HTTP profile with RAM Cache enabled is configured using the default Maximum Cache Size of 100 MB and is associated with five virtual servers, the system will allocate 100 MB of memory for the RAM Cache. Since all associated virtual servers are using a single HTTP profile with RAM Cache, they all share the common resource.

    However, if five HTTP profiles with RAM Cache enabled are configured using the default Maximum Cache Size of 100 MB and each one is associated with a different virtual server, the system allocates 100 MB for each RAM Cache or 500 MB total. If the total amount of allocated memory for RAM Cache exceeds the 50 percent allowed, then one or more of the configured RAM Caches will fail to initialize. When this occurs, caching will not occur for the virtual servers whose RAM Cache did not initialize. This may be difficult to determine at first as there is no report in the Configuration utility that the RAM Cache failed to initialize, and the error message reported in the /var/log/ltm file does not specify which RAM Cache failed to initialize.

  • An HTTP profile with RAM Cache enabled that exceeds the 50 percent maximum memory limit is associated with a virtual server.

    The BIG-IP system does not allocate system memory to a RAM Cache until it has been associated with a virtual server. Configuring a Maximum Cache Size greater than 50 percent does not cause an error message to be reported until after the HTTP profile is associated with a virtual server. The system allows the HTTP profile to be associated with a virtual server but does not initialize RAM Cache due to insufficient memory. Since no error message is reported when assigning the profile to the virtual server, the configuration appears to load correctly.

RAM Cache initialization error message 01070668:3

The following error message is reported in the /var/log/ltm file and in the Configuration utility within the RAM Cache screen, where xxx is the configured Maximum Cache Size in MB and yyy is the maximum allowed by the system in MB:

01070668:3: The amount of ramcache memory assigned to HTTP profiles (xxxMB) exceeds the maximum amount (yyyMB) defined by Ramcache.MaxMemoryPercent (50)

This error message is reported under the following scenarios:

  • You attempt to increase the Maximum Cache Size beyond the 50 percent maximum of an HTTP profile that is already associated with a virtual server, and click Update.

    For example, a standalone BIG-IP LTM with 1514 MB provisioned contains a single HTTP profile with RAM Cache enabled and a Maximum Cache Size of 100 MB associated with a virtual server. If the Maximum Cache Size is changed to 800 MB and you click Update, the system reports the following error message in the Maximum Cache Size field:

    01070668:3: The amount of ramcache memory assigned to HTTP profiles (800MB) exceeds the maximum amount (757MB) defined by Ramcache.MaxMemoryPercent (50)

  • You attempt to make a change to either a RAM Cache option or another option within an HTTP profile whose Maximum Cache Size exceeds the 50 percent maximum limit.

    For example, a standalone BIG-IP LTM with 1514 MB provisioned contains a single HTTP profile with RAM Cache enabled and a Maximum Cache Size of 800 MB that has not been associated with a virtual server. The profile is then assigned to a virtual server using the Configuration utility. No error is reported within the Configuration utility, and it appears that the profile is working correctly, but the RAM Cache is not initialized as it exceeds the maximum allowed memory allocation.

    A user then attempts to make a change to the same HTTP profile and save the changes by clicking Update. The BIG-IP system reloads the configuration change and attempts to allocate the necessary memory during which time it reports the following error message in the Maximum Cache Size field:

    01070668:3: The amount of ramcache memory assigned to HTTP profiles (800MB) exceeds the maximum amount (757MB) defined by Ramcache.MaxMemoryPercent (50)

Recommendations

The RAM Cache feature is designed to reduce the traffic load to back-end servers by caching high-demand content, static content, or compressed content. If you are receiving either of the error messages in this Solution, consider the following recommendations:

  • Using the default Maximum Cache Size value
  • Limiting the number of unique HTTP profiles with RAM Cache
  • Knowing your 50 percent maximum memory limit

Using the default Maximum Cache Size value

Do not use RAM Cache to cache an entire site; use RAM Cache to cache only the most common objects, such as logos, buttons, or files that are common across the site. In most situations, the 100 MB Maximum Cache Size is more than enough for caching purposes.

Limiting the number of unique HTTP profiles with RAM Cache

Try to consolidate HTTP profiles that have RAM Cache enabled. If multiple HTTP profiles are created with RAM Cache enabled and associated with individual virtual servers, each RAM Cache is allocated the cache size specified within the profile. If there is nothing unique between the HTTP profiles, a single HTTP profile with RAM Cache enabled can be applied to multiple virtual servers for caching purposes.

Knowing your 50 percent maximum memory limit

To determine the maximum amount of memory available for RAM Cache allocation, find the amount of memory allocated to the BIG-IP LTM system by performing one of the following two procedures. After you find the amount of memory allocated to the BIG-IP LTM system, divide the value by two. For example, if the amount of memory allocated to the BIG-IP LTM system is 1514, that means 757 MB is the 50 percent maximum as specified by the BigDB ramcache.maxmemorypercent variable. The system creates a buffer value of 16 MB. Ensure that your cache value or the sum of multiple cache values is no larger than 740 MB.

Important: F5 recommends that you do not increase the BigDB ramcache.maxmemorypercent variable beyond the 50 percent value, as doing so could lead to resource starvation by allowing RAM Cache to allocate too much system memory.

Determining the amount of memory allocated to the BIG-IP LTM system from the command line

  1. Log in to the BIG-IP LTM command line.
  2. Type the following command:

    bigpipe provision ltm show

    Output appears similar to the following example:

    PROVISION ltm
    |     CPU %   Memory (MB)   Host Mem (MB)   Disk (MB)
    |        90          1514               0           0

Determining the amount of memory allocated to the BIG-IP LTM system from the Configuration utility

  1. Log in to the Configuration utility.
  2. Click System.

    The System menu expands.

  3. Click Resource Provisioning.
  4. Locate the BIG-IP LTM memory value from the Memory section.
