K000164128: APM Edge Client Authentication with Default Browser Fails at Browser Handoff Due to Microsoft Edge "Apps on Device" Permission

Type
Support Solution
Published
2026-11-05

Applies to

  • APM Clients
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000164128

Description

When users authenticate to a BIG-IP APM VPN through the Edge Client configured to use the system default browser, authentication completes successfully, but the session is not returned to the Edge Client. The user sees the following error:

  • Something went wrong, Communication with the server failed

Additionally, the following data points may be observed:

  • A TCP SYN to the localhost on port 8000 is followed by an RST after about 15 seconds.
  • The browser developer tools show a failed request to the APM virtual server with parameters and no status code.
    • http://localhost:8000/?code=<encoded value>&f5_st=1z1z1z1&tin=null&host=https://server.example.com&state=<encoded value>

Environment

  • Product: BIG-IP APM
  • APM Clients: Edge Client on Windows, configure to use the default system browser for authentication
  • Browser: Microsoft Edge with default settings and no extensions loaded

Cause

The Microsoft Edge site permission "Apps on device" blocked the browser from communicating with the local Edge Client. Because the browser did not allow access to the device's local apps and services, the authorization code could not be returned to the client.

Answer/Recommended Actions

Allow Microsoft Edge to access apps on the device for the APM URL:

  1. Open Microsoft Edge and go to Settings > Privacy, search, and services.
  2. Select Site permissions.
  3. Under Additional permissions, select Apps on device. Enable the setting if it is not visible.
  4. Under Customized behaviors, select Allowed to access other apps and services on this device.
  5. Add your APM portal URL in the format https://server.example.com.
  6. Retry the Edge Client connection.

Additional Information

  • Expected behavior: After authentication succeeds, the browser redirects to a localhost address, and the Edge Client completes the connection.
  • Unexpected behavior: Login appears successful, but the browser fails to hand the session back to the client, the Communication with the server failed error appears, and the session is logged out.
