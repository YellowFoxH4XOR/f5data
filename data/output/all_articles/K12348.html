Known Issue

This is the result of a known issue. If you use the Traffic Management Shell (tmsh) to disable or enable STP attributes for a trunk, the utility also modifies the LACP attributes for the trunk. For example, the following tmsh command output indicates that LACP and STP are enabled for the t-1 trunk:

tmsh list net trunk t-1 all-properties

net trunk t-1 {
bandwidth 0
cfg-mbr-count 2
distribution-hash src-dst-ip
id 0
interfaces {
1.2
1.3
}
lacp enabled
lacp-mode active
lacp-timeout long
link-select-policy auto
mac-address 0:1:d7:2c:9:53
stp enabled
working-mbr-count 0
}

If you use the tmsh command to disable STP for the trunk, and then display the properties, both STP and LACP will be disabled for the trunk. For example, the following tmsh command disables STP for the trunk called t-1:

tmsh modify net trunk t-1 stp disabled

If you then display the trunk properties, both STP and LACP are disabled:

tmsh list net trunk t-1 all-properties
net trunk t-1 {
bandwidth 0
cfg-mbr-count 2
distribution-hash src-dst-ip
id 0
interfaces {
1.2
1.3
}
lacp disabled
lacp-mode active
lacp-timeout long
link-select-policy auto
mac-address 0:1:d7:2c:9:53
stp disabled
working-mbr-count 0
}

F5 Product Development tracked this issue as ID 224023 (formerly CR133489) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

To work around this issue, use the Configuration utility screens to modify STP and LACP properties for a trunk.
