Topic

This article applies to BIG-IP 12.1.x. For information about other versions, refer to the following article:

  • K49218438: Configuring local authentication as a backup method for remote authentication (13.x - 14.x)

You should consider using this procedure under the following conditions:

  • You use remote authentication for BIG-IP administrative users or for application traffic.
  • You want to configure the following modes of authentication:
    • You want local authentication as a backup method when the remote RADIUS server is not available.
    • You want remote RADIUS authentication for the default BIG-IP root and admin users.

Description

By default, if you configure a remote authentication method such as RADIUS authentication for BIG-IP administrative users or for application traffic and the remote authentication server is unavailable to answer authentication requests, only locally defined user accounts, such as the default administrator account and the root command line account, can log in to the system.

Starting in BIG-IP 12.1.0 (for RADIUS only) and in BIG-IP 13.0.0 (for all remote authentication methods), you can configure local authentication as a backup method when the remote authentication server is unavailable to answer authentication requests.

The following BigDB variable keys were introduced in BIG-IP 12.1.0 (applying only to RADIUS):

  • The systemauth.fallback.remotetolocal database key supports the following options:
     
    • true

      If this database key is set to true, the system enables local authentication as a backup method when the remote RADIUS server is unavailable to answer authentication requests.

    • false

      If this database key is set to false (default), the system disables local authentication as a backup method when the remote RADIUS server is unavailable to answer authentication requests.

  • The systemauth.nolocalonly database key supports the following options:

    Important: The systemauth.nolocalonly database key is only relevant if the systemauth.fallback.remotetolocal database key is set to true.

    • true

      If this database key is set to true, the root and admin accounts use RADIUS remote authentication and fall back to local authentication when the remote server is down.

    • false

      If this database key is set to false (default), all local accounts like the root and admin accounts use local authentication only. 

Note: As of BIG-IP 12.1.x, this feature is only available for RADIUS remote authentication.

Prerequisites

You must meet both of the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP system.
  • You can access the Traffic Management Shell (tmsh).

Procedures

  • Configuring local authentication as a backup method when the remote RADIUS server is unavailable
  • Configuring the root and admin accounts to use RADIUS remote authentication with fallback to local authentication

Note: To determine if a user login was authenticated locally or remotely, or if fallback to local authentication has occurred, observe the /var/log/secure file. 

Configuring local authentication as a backup method when the remote RADIUS server is unavailable

To configure remote user accounts to authenticate remotely and fallback to local authentication as a backup method when the RADIUS server is unavailable, set the systemauth.fallback.remotetolocal database key to true. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Set the systemauth.fallback.remotetolocal database key to true by typing the following command:

    modify /sys db systemauth.fallback.remotetolocal value true

  3. Set the systemauth.nolocalonly database key to false by typing the following command:

    modify /sys db systemauth.nolocalonly value false

    The system now uses local authentication as a backup method when the remote RADIUS server is unavailable for remote user accounts. The default local accounts root and admin are authenticated locally only.

Note: To revert to the default setting, and disable local authentication as a backup method, you can use the tmsh modify /sys db systemauth.fallback.remotetolocal value false command.

Configuring the root and admin accounts to use RADIUS remote authentication with fallback to local authentication

To configure the root and admin accounts to use RADIUS remote authentication and fall back to local authentication if the remote server is down, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Ensure user accounts are correctly configured on the remote authentication server for all local accounts that you want to use on the BIG-IP system (root and admin).
  2. Log in to the tmsh utility by typing the following command::

    tmsh

  3. Set the systemauth.fallback.remotetolocal database key to true by typing the following command:

    modify /sys db systemauth.fallback.remotetolocal value true

  4. Set the systemauth.nolocalonly database key to true by typing the following command:

    modify /sys db systemauth.nolocalonly value true

    The system now requires all user accounts including the default admin and root accounts to be remotely authenticated and fall back to local authentication when the remote RADIUS server is not available.

Note: To revert to the default setting, and configure the root and admin accounts to use local authentication, you can use the tmsh modify /sys db systemauth.nolocalonly value false  and tmsh modify /sys db systemauth.fallback.remotetolocal value false commands.
