Topic

This article covers creating SSL Subject Alternative Name (SAN) certificates and certificate signing requests (CSRs) using the BIG-IP Next Central Manager.

Description

SAN certificates allow control of the SAN field to associate multiple domains, subdomains, and IP addresses through a single certificate, avoiding cost of purchasing multiple similarly named certificates. This type of certificate is similar to a wildcard certificate; however, it allows you to specify multiple alternative domains instead of a single domain, as in a wildcard certificate. You can use BIG-IP Next Central Manager to create a self-signed certificate or a CSR to include the SAN field with the following supported format:

  • DNS:<Fully Qualified Domain Name (FQDN)>. For example, DNS:example.myf5.com
  • IP:<IP address>. For example, IP:192.168.100.100
  • email:<email address>. For example, email:user1@myf5.com

Note: At the point of publishing, the URI and the userPrincipalName (UPN) formats are not supported for the publicly available BIG-IP Next Central Manager versions.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrator or certificate manager role access to the BIG-IP Next Central Manager webUI and API if you are using the webUI and API respectively to create the SSL SAN certificates or CSRs.
  • If you are planning to use the BIG-IP Next Central Manager API, you have command line access to a client system that has the curl and the jq utilities installed.

Procedures

  • Using the BIG-IP Next Central Manager webUI to create SSL SAN certificates or CSRs
  • Using the BIG-IP Next Central Manager API to create SSL SAN certificates or CSRs
  • Using the BIG-IP Next Central Manager API to view SSL SAN certificates or CSRs

Using the BIG-IP Next Central Manager webUI to create SSL SAN certificates or CSRs

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Next Central Manager webUI as the user with administrator or certificate manager role.
  2. Select the Workspace icon (nine dots located at the top right) next to the F5 logo, and then go to Applications > Certificates & Keys.
  3. Select + Add.
  4. Select Create a Self-signed Certificate.
  5. Type in a name for the Name setting. For example, myf5cert.
  6. If you are creating a new self-signed SSL certificate, select Self for the Issuer setting. If you are creating a new CSR, select Certificate Authority for the Issuer setting.

    Note: At the point of publishing, BIG-IP Next Central Manager webUI does not provide any means to retrieve the newly created CSR. You need to use the BIG-IP Next Central Manager API to retrieve the CSR for CA signing.

  7. Fill in the remaining settings as required/needed.
  8. In the Subject Alternative Name setting, enter a value in the supported format as needed for your environment. If you need to include more than one value, separate the values with comma. For example, DNS:example.myf5.com, IP:192.168.100.100, email:user1@myf5.com
  9. Select Save to create the self-signed certificate and key.

Using the BIG-IP Next Central Manager API to create SSL SAN certificates or CSRs

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the client system that has the curl and jq utilities installed.
  2. Before you can create a new self-signed SSL certificate or CSR, you must first get a login token from the BIG-IP Next Central Manager. You can get the token from the login endpoint and save it to a shell variable for future reference using the following syntax:

    token=$(curl -sk -H "Content-Type:application/json" -X POST https://<bigip_next_CM_mgmt_address>/api/login -d'{"username": "<CM_admin_user>", "password": "<CM_admin_password>"}' | jq -r '.access_token')

    For example, use this command to request a login token and save it to a variable named token:

    token=$(curl -sk -H "Content-Type:application/json" -X POST https://192.168.1.100/api/login -d'{"username": "admin","password": "admin"}' | jq -r '.access_token')

    You can use the echo $token command to view the value of the token variable.

  3. Now you can use the token variable to authenticate to BIG-IP Next Central Manager. To create a new self-signed SSL certificate or CSR, enter the following command syntax:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer <token value>" -X POST https://<bigip_next_CM_mgmt_address>/api/v1/spaces/default/certificates/create -d '{"name": "<cert/csr_name>", "issuer": "<Self | CA>", "common_name": "<cert_common_name>", "division": [ "<division_name>" ], "organization": [ "<organization_name>" ], "locality": [ "<location_name>" ], "state": [ "<state_name>"], "country": [ "<country_name>" ], "subject_alternative_name": "<subject_alternative_name>", "duration_in_days": <cert_validity_in_days>, "administrator_email": "<admin_email_address>", ["key_type": "RSA", "key_size": <2048 | 3072 | 4096>] | ["key_type": "ECDSA", "key_curve_name": <prime256v1 | secp384r1>], ["key_passphrase": "<key passphrase>"], ["challenge_password": "<challenge password for CA signing>"}' | jq -M .

    Note the following:

    • If you are using RSA for the key_type setting, then you must specify the value for the key_size setting. If you are using ECDSA for the key_type setting, then you must specify the value for the key_curve_name setting.

    For further details about the available settings for this API endpoint, refer to the Create certificate/key/csr section of the F5 BIG-IP Next Central Manager API Specifications.

    For example, you would enter the following command when you want to create a self-signed SSL certificate using RSA key type, 2048 size and passphrase mykeypassphrase:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X POST https://192.168.0.51/api/v1/spaces/default/certificates/create -d '{"name": "myf5cert-selfsigned-example-with-passphrase-using-API", "issuer": "Self", "common_name": "example.myf5.com", "division": [ "MyF5_Division" ], "organization": [ "MyF5_Org" ], "locality": [ "Seattle" ], "state": [ "Washington"], "country": [ "US" ], "subject_alternative_name": "DNS:example.myf5.com, IP:192.168.100.100, email:user1@myf5.com", "duration_in_days": 365, "administrator_email": "admin@myf5.com", "key_type": "RSA", "key_size": 2048, "key_passphrase": "mykeypassphrase"}' | jq -M .

    In another example, you would enter the following command when you want to create a CSR using ECDSA key type, secp384r1 key curve, passphrase mykeypassphrase and challenge password mychallengepassword:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X POST https://192.168.0.51/api/v1/spaces/default/certificates/create -d '{"name": "myf5cert-CSR-example-with-passphrase-using-API", "issuer": "CA", "common_name": "example.myf5.com", "division": [ "MyF5_Division" ], "organization": [ "MyF5_Org" ], "locality": [ "Seattle" ], "state": [ "Washington"], "country": [ "US" ], "subject_alternative_name": "DNS:example.myf5.com, IP:192.168.100.100, email:user1@myf5.com", "duration_in_days": 365, "administrator_email": "admin@myf5.com", "key_type": "ECDSA", "key_curve_name": "secp384r1", "key_passphrase": "mykeypassphrase", "challenge_password": "mychallengepassword"}' | jq -M .

    The commands should return an output similar to the following example:

    {
      "_links": {
        "self": {
          "href": "/api/v1/spaces/default/certificates/create"
        }
      },
      "path": "/v1/certificates/bda45fad-8729-4060-98d5-4ceb4fd40923"
    }

    Note the certificate/CSR ID in the path variable from the output; you will need this ID to view the newly created certificate/CSR using the steps in the Using the BIG-IP Next Central Manager API to view SSL SAN certificates or CSRs procedure. 

Using the BIG-IP Next Central Manager API to view SSL SAN certificates or CSRs

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the client system that has the curl and jq utilities installed.
  2. To view the newly created certificate/CSR, you will need a login token from the BIG-IP Next Central Manager. You can get the token from the login endpoint and save it to a shell variable for future reference using the following syntax:

    token=$(curl -sk -H "Content-Type:application/json" -X POST https://<bigip_next_CM_mgmt_address>/api/login -d'{"username": "<CM_admin_user>", "password": "<CM_admin_password>"}' | jq -r '.access_token')

    For example, use this command to request a login token and save it to a variable named token:

    token=$(curl -sk -H "Content-Type:application/json" -X POST https://192.168.1.100/api/login -d'{"username": "admin","password": "admin"}' | jq -r '.access_token')

    You can use the echo $token command to view the value of the token variable.

  3. Now you can use the token variable to authenticate to BIG-IP Next Central Manager. To view the newly created certificate/CSR, enter the following command syntax:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer <token value>" -X GET https://<bigip_next_CM_mgmt_address>/api/v1/spaces/default/certificates/ | jq -M .

    The previous command syntax displays all existing certificates and CSRs on the BIG-IP Next Central Manager. If you have the certificate/CSR ID, you should use the following command syntax:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer <token value>" -X GET https://<bigip_next_CM_mgmt_address>/api/v1/spaces/default/certificates/<certificate/CSR ID> | jq -M .

    Using the certificate/CSR ID from the example output in the previous procedure, you would enter the following command:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET https://192.168.0.51/api/v1/spaces/default/certificates/bda45fad-8729-4060-98d5-4ceb4fd40923 | jq -M .
