K5346: 3-DNS UCS fixup scripts may remove the word ''directory'' from zone files

Known Issue

This is the result of a known issue. If you load a UCS file that was created on a version of 3-DNS older than the version that is currently running, 3-DNS executes fixup scripts that modify the configuration for compatibility with the current version.

Note: These fixup scripts are contained in the /usr/local/lib/ucs_convert/ directory.

The fixup script that modifies zone files incorrectly removes the word directory from zone files, even when the word is part of a valid configuration statement. If you use zones that contain the word directory, those zones will not work correctly after you load the UCS file.

F5 Networks Product Development tracked this issue as CR49153.

Workaround

To avoid this issue, modify the fixup script before you load the UCS file, by performing the following steps:

Warning: This process contains a number of steps that must be followed exactly as stated. Please review the full procedure before attempting the process. If you do not feel comfortable following these instructions, contact F5 Support for assistance.

  1. Log in to the command line.
  2. Change directories to the /usr/local/lib/ucs_convert/ directory, by typing the following command:

    cd /usr/local/lib/ucs_convert/

  3. Edit the 02005000_named.conf file.
  4. Locate the section of the file that begins with the following line:

    # Fix the path that named will use for config information.

  5. Within this section, locate the following line:

    if( $line =~ /directory/ )

  6. Change the line to appear as follows:

    if( $line =~ /directory / )

  7. Save the file and exit the editor.
