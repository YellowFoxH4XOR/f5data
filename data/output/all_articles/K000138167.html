K000138167: BIGIP's device certificate results to 'NET::ERR_CERT_COMMON_NAME_INVALID' error in browser

Type
Support Solution
Published
2024-01-09
Updated
2026-01-29
Source
https://my.f5.com/manage/s/article/K000138167

Description

Administrator may want to replace the default device's certificate on BIGIP (or BIGIQ) with company's issued certificate. Afterwards accessing the device's hostname in browser may result to error 'NET::ERR_CERT_COMMON_NAME_INVALID'.

Environment

  • BIGIQ
  • CM
  • Device certificate

Cause

Mismatched CN value from company's issued certificate and/or lack of SAN extension inside of certificate.

Recommended Actions

  1. Make sure that the typed hostname of device in browser matches with CN value from company's issued certificate
  2. Make sure that the company's issued certificate has the SAN extension with value of what is typed in browser
  3. To include a SAN extension for the CSR file for BIG-IQ please follow K11438: Creating SSL SAN certificates and CSRs using OpenSSL

For example, in browser the administrator types https://bigiq.lab.com. Then the installed on BIGIP company's issued certificate should look like as below example (the openssl tool was utilized to check the certificate's content on BIGIQ CM in this example):

# openssl x509 -in /config/httpd/conf/ssl.crt/server.crt -text -noout

Certificate:

<omitted for brevity>

  Signature Algorithm: sha256WithRSAEncryption

    Issuer: C=PL, ST=Masovian, L=Warsaw, O=F5, CN=ca.lab.com

    Validity

      Not Before: Dec 12 12:12:50 2023 GMT

      Not After : Dec 11 12:12:50 2024 GMT

    Subject: C=PL, ST=Masovian, L=Warsaw, O=F5, CN=bigiq.lab.com <<< (!) the CN matches

    Subject Public Key Info:

      Public Key Algorithm: rsaEncryption

        Public-Key: (2048 bit)

        Modulus:

<omitted for brevity>

        Exponent: 65537 (0x10001)

    X509v3 extensions:

      X509v3 Subject Alternative Name: <<< (!) the SAN extension is present with typed in browser value

        DNS:bigiq.lab.com, IP Address:1.1.1.1

  Signature Algorithm: sha256WithRSAEncryption

     <omitted for brevity>
