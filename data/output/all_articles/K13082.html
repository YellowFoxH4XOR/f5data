Known Issue

When you run nsm commands, the system displays a permission denied message.

This issue occurs when you run one of the following commands on an ARX 4000 platform:

  • nsm recovery
  • no nsm recovery
  • nsm binary-core-files
  • no nsm binary-core-files

This issue occurs because the nsm command attempts to create a temporary temCommandsVars file, but the system denies permission because the file is already present. However, the command does work and updates the desired configuration.

Impact

None; you can safely ignore this issue.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you use the nsm recovery or nsm binary-core-files commands from the CLI, the system displays the following error messages:

    /acopia/bin/updateFlash: line 262: /acopia/boot/slot2/temCommandsVars: Permission denied
    /acopia/bin/updateFlash: line 262: /acopia/boot/slot2/temCommandsVars: Permission denied

  • When you load a running-config using the run configs <config-file> command, the output contains permission-denied messages that appear similar to the following:

    ARX4000(cfg)- no nsm recovery
    /acopia/bin/updateFlash: line 262: /acopia/boot/slot2/temCommandsVars: Permission denied
    /acopia/bin/updateFlash: line 262: /acopia/boot/slot2/temCommandsVars: Permission denied
    ARX4000(cfg)- nsm binary-core-files
    /acopia/bin/updateFlash: line 262: /acopia/boot/slot2/temCommandsVars: Permission denied
    /acopia/bin/updateFlash: line 262: /acopia/boot/slot2/temCommandsVars: Permission denied
