Description

From BIG-IP software version 12.1 and later, ECP is a supported PFS option in IPsec. However, some caveats apply, depending on the software version.

Elliptic Curve Groups (ECP) has been a Perfect Forward Secrecy (PFS) configuration option for IPsec since BIG-IP version 12.1. However, in software versions 12.1 and 13.1, ECP was not fully implemented until BIG-IP software versions 12.1.3.6, 13.1.1.2 and 14.0 when ID679347 was included in those maintenance releases. ID679347 solved the problem of IKEv2 child SAs failing to be establish when PFS was required by the remote IPsec peer.

On the BIG-IP, ECP is only supported in IKEv2. There is no plan to support ECP in IKEv1.

The IPsec Policy "Perfect Forward Secrecy" configuration object (ike-phase2-perfect-forward-secrecy) does not list ECP as a PFS option. That list only applies when IKEv1 is used. When IKEv2 is used, the IPsec Policy PFS is inherited from whatever PFS value is selected in the "Perfect Forward Secrecy" IKE Peer configuration object (phase1-perfect-forward-secrecy). For example, if "ike-phase2-perfect-forward-secrecy modp2048" is selected in the IKE Peer config, the BIG-IP will expect and use modp2048 to establish IKEv2 child SAs.
 

Environment

  • IPsec IKEv2
  • Perfect Forward Secrecy as an ECP type.
 

Cause

None.
 

Recommended Actions

When implementing an IPsec tunnel that requires ECP Perfect Forward Secrecy, you should consider the following factors:

  • You cannot use IKEv1.
  • You must use software versions from 12.1.3.6, 13.1.1.2 and 14.0.
  • Perfect Forward Secrecy in the IKE Peer config carries through to the IPsec Policy, regardless of what is set in the IPsec Policy itself.
 

Additional Information

For IPsec tunnels using ECP and another vendor's IPsec product, ECP may cause tunnels to be unstable. Refer to:
Bug ID 900933
