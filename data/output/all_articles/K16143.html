Known Issue

The BIG-IP AAM and BIG-IP WebAccelerator systems may send an HTTP 416 Requested range not satisfiable response to a valid HTTP Range request.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured with an acceleration policy that is configured to cache responses for a matched object.
  • The virtual server receives a single HTTP Range request that contains more than eight ranges.
  • The requested object has an active cache record and the BIG-IP AAM/WebAccelerator attempts to serve the response from the cache.

Impact

Requests for cached objects fail.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Requests for a cached file fail with an HTTP 416 Requested range not satisfiable response code, even if the request contains valid ranges.

Workaround

To work around this issue, you can configure the acceleration policy to not cache the affected object or object type and always proxy the request to the OWS.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your specific environment.
