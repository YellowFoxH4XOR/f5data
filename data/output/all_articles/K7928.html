Topic

You can view compression statistics for the BIG-IP system from both the Configuration utility and the command line interface.

Viewing compression statistics from the Configuration utility

  1. Log in to the BIG-IP LTM Configuration utility.
  2. Click Overview.
  3. Click Statistics.
  4. Click the Local Traffic tab.
  5. In the Statistics Type field, click Profiles Summary.
  6. In the Profile Statistics section, click View next to HTTP.

    The BIG-IP LTM system displays the following compression statistics in the Content Type Compression section:

    • Total pre-compressed bytes

      The amount of uncompressed traffic that BIG-IP system received.

    • Total post-compressed bytes

      The amount of compressed traffic that BIG-IP system sent.

Viewing compression statistics from the command line interface

You can use the following bigpipe commands to display HTTP compression statistics on the BIG-IP LTM system:

bigpipe http show

bigpipe profile <http profile name> show all

The bigpipe http show command returns the aggregate statistics for all HTTP processing on the BIG-IP system as a single value. The bigpipe profile command shows the statistics for a single specified HTTP profile. If a unique HTTP profile is assigned to each Virtual Server, then you can use this command to report the compression statistics for each Virtual Server individually.

BIG-IP versions 9.4.x and later

The bigpipe http and bigpipe profile commands display the following compression statistics on systems running BIG-IP versions 9.4.x and later:

COMPRESSION STATISTICS --
total bytes (pre, post, null, saved) = (15958, 6716, 0, 57.91%)

The compression statistics parameters are defined in the following table:

Compression StatisticDescription
preThe amount of uncompressed traffic that the BIG-IP LTM received
postThe amount of compressed traffic that the BIG-IP LTM sent
nullThe amount of uncompressed content that is wrapped in compression headers

Note: The BIG-IP LTM system wraps content in compression headers, but the system does not compress the content when one of two situations occurs: either the BIG-IP LTM exceeds the amount of compression (in megabytes) for which it is licensed, or the CPU saver is active.

savedThe ratio between the amount of content before compression and the amount of content after compression
