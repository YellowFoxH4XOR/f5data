Topic

In BIG-IP versions prior to 11.2.0, if you use a large number of certificates in a certificate chain when authenticating client certificates, the Secure Socket Layer (SSL) connection may close if the SSL handshake message exceeds 14304 bytes.

Beginning in BIG-IP LTM 11.2.0, and BIG-IP LTM 11.1.0 HF4, this limit has been removed and the native size of the SSL handshake message array is dynamic with no upper limit. F5 Product Development tracked this change as ID 225445.

The SSL handshake array contains the request sent to the client for its certificate, as well as the bundled or multiple certificates that are advertised to the client. The SSL handshake array also handles the response received from the client.  If the request and response exceeds the maximum size specified for the SSL handshake array, the connection is closed.

In versions prior to 11.2.0, the changes to the SSL handshake array were published in the BIG-IP Local Traffic Manager: Concepts guide under the SSL Profiles section, in the following note:

The maximum size of native SSL handshake messages that the BIG-IP system allows is 14304 bytes. Consequently, if the SSL handshake is negotiating a native cipher and the total length of all messages in the handshake exceeds this byte threshold, the handshake can fail. Although typical use does not cause message length to exceed this threshold, we recommend that when configuring a Client SSL profile to request or require client certificates, you avoid specifying large numbers of certificates with the Advertised Certificate Authorities setting. This minimizes the number of certificates that must be exchanged during a Client SSL handshake.

Due to this expected behavior, when using BIG-IP versions prior to 11.2.0, F5 recommends that you advertise only certificates that are necessary to avoid creating a situation in which the maximum size of the native SSL handshake message exceeds the BIG-IP system limit.
