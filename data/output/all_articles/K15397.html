Known Issue

With remote authentication configured, the BIG-IP local password policy may remain enforced.

This issue occurs when all of the following conditions are met:

  • You have previously configured the BIG-IP system with the local password policy's password maximum age set.
  • You have changed the BIG-IP system user directory authentication to a remote authentication method.
  • You have created user accounts.

Impact

The user accounts that you have created may not be able to authenticate correctly on the affected BIG-IP system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After configuring a remote authentication method for the BIG-IP system, the password maximum age setting remains enforced in the /config/bigip_base.conf file's auth password-policy section. The configuration lines may appear similar to the following example:

    auth password-policy {
    max-duration 3
    }

  • The user accounts you created (after switching to remote authentication) observe that the system denies authorized users from the login process for having an expired password. However, the remote authentication database reports successful authentication.
  • The configured password maximum age (max-duration) value cause the issue's symptoms to vary. For example, a larger value set (90 days) may take you a longer period of time to observe the issue. With a smaller value (one day), you may observe the issue earlier.

Workaround

To work around this issue, you can remove the password maximum age that was set by the BIG-IP local password policy, then delete and recreate the affected user accounts. To do so, perform the following procedure:

Impact of workaround: If deleting the affected user accounts is not feasible, no workaround exists. Performing the following procedure requires saving and reloading of system configuration, which may briefly interrupt the functions of the BIG-IP system. F5 recommends that you perform the procedure in a scheduled maintenance window.

  1. Log in to the BIG-IP command line.
  2. Create a backup for your configuration by typing the following command:

    cp -a /config/bigip_base.conf /var/tmp/SOL15397_backup_bigip_base.conf

  3. Use a text editor to edit the /config/bigip_base.conf file. Navigate to the braces ( { ) in the auth password policy section that contains the following configuration:

    auth password-policy { ... }

    For example, an affected BIG-IP system with three days set to the local password policy with a password maximum age may appear similar to the following example:

    auth password-policy {
    max-duration 3
    }

  4. Remove the max-duration <VALUE> line where <VALUE> is the password maximum age.
  5. After removal, the braces for the section for auth password-policy will appear as follows:

    auth password-policy {
    }

  6. Save the modifications to the /config/bigip_base.conf file and exit the text editor.
  7. Reload the configuration by typing the following command:

    tmsh load sys config

  8. Save the configuration by typing the following command:

    tmsh save sys config

  9. To ensure that the BIG-IP local password policy is correctly modified, type the following command:

    tmsh list /auth password-policy

  10. Verify that the output no longer contains the max-duration settings.
  11. You may now proceed to delete and recreate the affected user accounts, or create new ones with the configured remote authentication.
