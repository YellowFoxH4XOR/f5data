Description

You see the following error in /var/log/gtm frequently:

warning gtmd[5253]: 011ae116:4: The list processing time (32 seconds) exceeded the interval value. There may be too many monitor instances configured with a 30 second interval.

Environment

  • BIG-IP DNS
  • 1000+ virtual server objects in gtm.conf
  • virtual-server-discovery enabled

Cause

When gtmd or big3d is overloaded and monitored objects can not be processed in a timely manner.
In affected BIG-IP versions due to ID 863917, this message is logged when even modest monitor configurations are used.

Recommended Actions

One common cause for this scenario is where BIG-IP DNS is monitoring too many targets because virtual-server auto-discovery is enabled (or previously had been enabled), and every single virtual server is now known to the GTM and is being monitored, but only a few of them are actually used in any GTM pools.

In this situation, gtmd ends up needlessly probing for the status of all of those virtual servers with the bigip monitor, every 30 seconds by default. Simply disabling virtual-server-discovery and deleting the unused virtual servers from the gtm config can reduce the gtmd scheduling load significantly.

The next option is to increase the monitor interval of impacted objects so that there is enough time to process them.

For BIG-IP versions impacted by ID863917, it is recommeded to upgrade to a fixed version or apply the temporary workaround to prevent the log messages.
 

Additional Information

As a temporary workaround for ID863917, create a log filter to prevent BIG-IP from logging the message.
  1. Navigate to System > Logs > Configuration > Log Filters.
  2. Type a name for the log filter.
  3. In the Severity list, click Warning
  4. In the Source list, click gtmd.
  5. In the Message ID box enter 011ae116.
  6. In the Log Publisher list, click None.
  7. Click Finished.
Note: To remove this filter or for more information on log filters, See K35284961 in Related Content
