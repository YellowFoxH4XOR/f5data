Known Issue

This is the result of a known issue. The Redirect Rewrite setting specifies whether the BIG-IP system rewrites URIs that are part of HTTP redirect (3XX) responses. When the Redirect Rewrite setting is enabled in the HTTP profile, and a server sends a redirect response whose Location header contains a non-HTTP protocol or a relative URI, the BIG-IP system  incorrectly rewrites the Location header value. Regardless of the Location header contents, when the Redirect Rewrite setting is enabled, the system inserts a lower case s after the fourth character in the existing header value. The desired behavior is for the system to only modify Location header values whose protocol is specified as HTTP, regardless of case. Relative redirects and redirects specifying protocols other than HTTP should not be modified.

For example, the following HTTP 302 Found response specifies the FTP protocol in the Location header:

HTTP/1.1 302 Found
Location: ftp://path/to/file
Date: Fri, 09 Nov 2007
Server: Apache/2.0.55
Content-Length: 0

When the BIG-IP LTM receives the HTTP 302 Found response, the BIG-IP system incorrectly rewrites the Location header, inserting an s character after the fourth character in the existing value. The resulting Location header contains an invalid URI, which appears similar to the following example:

Location: ftp:s//path/to/file

Relative redirects are similarly affected. For example, the following HTTP 302 Found response specifies a relative redirect in the Location header:

HTTP/1.1 302 Found
Location: /path/to/file
Date: Fri, 09 Nov 2007
Server: Apache/2.0.55
Content-Length: 0

When the BIG-IP LTM receives the HTTP 302 Found response, the BIG-IP system incorrectly rewrites the Location header by inserting an s character after the fourth character in the existing value. The resulting Location header contains an invalid URI, which appears similar to the following example:

Location: /patsh/to/file

F5 Networks Product Development tracked this issue as CR93374 and it was fixed in BIG-IP LTM version 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

This issue still exists in the BIG-IP version 9.3 and 9.4 software branches.

Note: For information about a related known issue that was fixed in BIG-IP version 9.4.0, refer to K8535:The Redirect Rewrite feature incorrectly rewrites the Location header value when the protocol HTTPS and is not specified in lower case.
