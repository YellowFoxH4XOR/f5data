Description

It is not possible to install iso, The following error appears in /var/log/liveinstall.log

warning: tm_install::VolumeSet::choose_filesystem_plan -- Selected tiny plan (disk = 38797312, sz_standard = 14612880, sz_tiny = 8647152) error: tm_install::Process::Process_full_install -- predicted size for BIGIP16121 is 8647152 and vg has 7761920 remaining. Terminal error: Disk full (volume group). See SOL#10636


You may see the same error state, when running the tmsh show /sys software command:

--------------------------------------------------------
Sys::Software Status
Volume  Product  Version   Build  Active  Status
--------------------------------------------------------
HD1.1    BIG-IP 16.1.2.1  0.0.10      no  failed (Disk full (volume group). See SOL#10636)
HD1.2    BIG-IP 15.1.0.4   0.0.6     yes  complete


list /sys disk all-properties
sys disk logical-disk HD1 {
    mode mixed
    size 37888
    vg-free 7580   <---- current available space
    vg-in-use 30024
    vg-reserved 0
}

Environment

  • BIG-IP system

Cause

Not enough disk space. ISO files typically require 15 GiB of available disk space to install. (16.x requires approximately 15 GiB).

In the following example, we use the vgdisplay -vA command, to see that the available space is 7.4 GiB:

Recommended Actions

  1. Manually delete the failed boot location: K16048: BIG-IP VE installation may fail when targeting a second boot location

  2. If your BIG-IP system is a Virtual Edition, you can choose to extend disk space, by following the procedure "Extending disk space for upgrading software, or installing hotfix or point releases on an additional slot": K14952: Extending disk space on BIG-IP VE

    If this is not a Virtual Edition system, you can increase the size of the volume group, by borrowing from the data.appdata logical volume (seen in the lvs command). Reduce the size of the appdata volume, by completing the procedure in K74200262: Reducing the size of the appdata volume with the lvreduce utility. Then, run tmsh delete sys software volume HD1.1 (or other failed installation target, if HD1.1 is not applicable).

  3. Reinstall software to the target boot location.
  4. Delete older Installed versions to alleviate the issue with the lack of space.
