K71205039: IP Reputation database not loaded - 15.1.6.1, 16.1.3, 17.0.0 and later

Type
Support Solution
Published
2022-10-18
Updated
2024-01-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.X.X, 17.0.X, 15.1.7, 15.1.6, 17.0.0, 16.1.3
Source
https://my.f5.com/manage/s/article/K71205039

Description

IP intelligence (IPI) is not working when implemented with an iRule or traffic policy, and errors similar to the following are printed to /var/log/ltm:

TCL error: /Common/IPI_irule <HTTP_REQUEST> - IP Reputation database not loaded (line 1)     invoked from within "IP::reputation [IP::client_addr]"

err tmm1[11566]: 016e0001:3: Could not bind operand 'iprep all', reason ERR_INIT

Environment

  • IP intelligence
  • 15.1.6.1, 16.1.3, 17.0.0 and later

Cause

IPI supports dual IPv4 and IPv6 in 15.1.6.1, 16.1.3, 17.0.0 and later versions. Each database is sourced from a different external server.

If one of those databases is unavailable (typically IPv6) and not loaded into TMM, IPI will not work, with the error described in this article.

Messages similar to the following are printed in /var/log/iprepd/iprepd.log:

iprepd|ERR|Oct 10 12:21:36.615|479|Cannot connect to host localdb-ipv6-daily.brightcloud.com: Connection refused
iprepd|WARNING|Oct 10 12:21:36.617|479|Unable to download update file wr_ipv6_All_1_4024.txt from https://localdb-ipv6-daily.brightcloud.com...
iprepd|INFO|Oct 10 12:21:36.629|475|Downloading IP update_1.4448_26.txt

The show sys iprep-status command returns output similar to the following:

------------------------------------------------------------------------

------------------------------------------------------------------------

Recommended Actions

To resolve this, troubleshoot connectivity with the IPI database servers. For example, the IPv6 database is served from localdb-ipv6-daily.brightcloud.com at the time of this article's publication. Article K03011490 contains the authoritative list.

Start with a DNS lookup (e.g. dig, nslookup) from the system to determine what IP(s) they are resolving to, then take a tcpdump on the applicable interface to determine the cause of the connectivity issue. A restart of iprepd (tmsh restart sys service iprepd) can be used to initiate a new download attempt.

This problem is typically caused by an intermediate device, such as a firewall, blocking the connection attempt from the BIG-IP.

Additional Information

The IPI database files should be present in the /var/IpRep directory on a functional system.

For example:

[root@v15:Active:Standalone] config # ll -h /var/IpRep
total 27M
-rw-r--r--. 1 root root  26M Oct 18 16:18 F5IpRep.dat
-rw-r--r--. 1 root root 953K Oct 18 10:08 F5IpV6Rep.dat

The errors described in the Description of this article can also be caused by an expired IPI subscription. It is a generic error which occurs when the IPI database is not loaded into TMM, and IPI functionality is in use.
