Known Issue

This is the result of a known issue. The SSL::sessionid iRule command returns the SSL session ID for the current connection if it exists in the session cache. If the session no longer exists in the SSL cache, the SSL::sessionid command should return a null string. However, in BIG-IP version 9.x, if the session ID does not exist in the cache, the SSL::sessionid command returns a string of 64 zeroes.

Note: For more information about the SSL::sessionid command, refer to the following DevCentral wiki page. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary):

https://devcentral.f5.com/wiki/iRules.SSL__sessionid.ashx

F5 Product Development tracked this issue as ID 218645 (formerly CR110086), and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, or WebAccelerator release notes.
