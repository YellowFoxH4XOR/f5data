Description
The Source Port: Preserve setting does not preserve source port whereas the port should be preserved.
As a result source port of the incoming traffic on the client side does not match source port of the related traffic leaving on the server side.

The behaviour commonly affects asymmetric (nPath) routed traffic, when response from the pool member bypasses the BIG-IP and goes directly to the client. Because of the behaviour, the client receives the traffic where destination port does not matches the source port of the existing connection. As a result of that, the client side drops/resets the traffic.

Environment

The issue occurs when all condition below are met
  • The virtual server is configured with source-port preserve (the default).
  • The system uses one of the following configurations
    • Using one of the next platforms
      • Virtual Edition (depends on hypervisor settings)
      • 2000 series
      • 4000 series
      • i2000 series
      • i4000 series
    • Configuring a VLAN's 'CMP Hash' setting to a non-default value
    • Using a special variable such as non-default udp.hash or tcp.hash
  • You are running affected version. Please see Bug ID890229 for more details

Cause

The issue is caused by the Bug ID890229.

Recommended Actions

To fix the issue, either method listed below can fix the issue
  • Upgrade to the version listed as fixed. Please see Bug ID890229 for more details
  • For versions that do not have fix, open a case with F5 Technical Support to check get EngHF for ID890229.
To do a workaround, change  source-port preserve (default) to preserve-strict
