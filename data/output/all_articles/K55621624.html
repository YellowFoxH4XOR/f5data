Description

Local accounts are not authenticating with remote authentication configured and 'Fallback to Local' enabled

Environment

  • BIG-IP
  • Remote authentication configured
  • Fallback to Local enabled
  • Local accounts configured

Cause

This behavior is expected when the remote authentication server is configured and able to accept authentication requests:

  • When the remote authentication server accepts the authentication request and the user is authenticated, the system allows access.
  • When the remote authentication server rejects an authentication request, the system denies access.
  • When the remote authentication server is unavailable, the BIG-IP system either denies access for or falls back to local authentication when the user is configured on the local BIG-IP device.

Only the root and admin accounts are still usable as local accounts with Remote Authentication configured.

Recommended Actions

User accounts, not including the root and admin accounts, should be configured on the remote authentication server for use in authenticating access to the BIG-IP.

Additional Information

The behavior of the fallback to local feature changed as summarized in K65475221: The BIG-IP system allows using local authentication as a backup method

A concise way to look at it is as follows:

While server is available:
* Local-only users (root, admin) can login only with local auth.
* Local users without remote counterpart cannot login.
* Local users with remote counterpart can login only with remote auth.
* Remote-only users can login.

While server is unavailable:
* Local-only users (root, admin) can still login. (same behavior as before version 13.x)
* Local users without remote counterpart can now login. (new behavior in 13.x and above)
* Local users with remote counterpart can login with local auth. (new behavior in 13.x and above)
* Remote-only users cannot login. (same behavior as before version 13.x)
