Topic

You can use Active Directory (AD) to authenticate users and assign resources to those users based on attributes in the user's account. For example, you can authenticate a user, perform a query to find which nested groups the user belongs to, and then assign the user a webtop resource based on a nested group. Group assignments are configured within AD. The BIG-IP APM system retrieves the group assignment information from the domain controller and assigns the resources accordingly.

Figure: Example of a Nested group in Active DirectoryA nested group is created when you add one group to a different group, and a user in the first group is not directly assigned to the new group. For example, if Jane Jones is a member of the Research_Development group and the Seattle group, and the Research_Development group is a member of the Engineers group and the Classified group, then Jane Jones belongs to all of those groups (the Research_Development, Seattle, Engineers, and Classified groups). Jane Jones nests the Engineers and Classified group privileges through her membership in the Research_Development group.

Description

Procedures

To configure AD authentication and query with resource assignment for a group of users, perform the following procedures:

  • Creating an access policy with AD authentication
  • Adding an Active Directory query to retrieve group information
  • Assigning resources to users

Creating an access policy with AD authentication

Performing the following procedure creates a logon page that prompts for a username and password. The BIG-IP APM system uses DNS to determine the IP address of the domain controller (DC) for the domain (sometimes referred to as a Realm) configured in the AD AAA server definition. If the forward and reverse pointer (PTR) records do not match, authentication fails. If the records match, the BIG-IP APM system sends a request to the domain controller requesting a Kerberos ticket using the administrator name and password that is configured in the AD AAA server definition. If the BIG-IP APM system and the DC establish a trust relationship, the BIG-IP APM system passes the credentials supplied on the logon page to the DC to authenticate the user. The DC sends back a success or failure message. If the BIG-IP APM system receives a success message, authentication succeeds. If the BIG-IP APM system cannot establish a trust with the DC, authentication fails.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profile / Policies.
    Note: For BIG-IP 12.x and earlier, navigate to Access Policy > Access Profiles.
  3. Click Create.
  4. Type a name for your access policy. For example: Classified_Webtop.
  5. For Profile Type, click the appropriate choice. For example All.
  6. Review the default settings.
  7. Under Language Settings, click the languages you want to use in the Factory Builtin Languages list and move them to the Accepted Languages list.
  8. Click Finished.
  9. Click the Edit link for the access policy you just created.

    The visual policy editor opens.

  10. Click the Add icon (+) between the Start and Deny end points.
  11. On the Logon tab, click Logon Page, and click Add Item.
  12. Review the default settings and click Save.
  13. Click the Add icon (+) on the fallback branch following the Logon Page policy item.
  14. Click the Authentication tab, click AD Auth, and click Add Item.
  15. For Server, click the Active Directory AAA server against which you want to authenticate users.

    Note: For instructions about creating an AD AAA sever, refer to the Configuration Guide for BIG-IP Access Policy Manager manual. For information about how to locate F5 product manual, refer to K12453464: Finding product documentation on AskF5.

    Note: Most environments use sAMAccountName rather than User Principle Name. If User Principal Name is enabled, the user need to submit a user ID as user@domain, where the user is the username and the domain is the AD domain.

    Note: F5 recommends that you enable Show Extended Error only for troubleshooting purposes. Enabling this option can very quickly generate multiple logs.

  16. For Max Logon Attempt Allowed, set a number based on the policies for your environments.

    Note: Setting the value to 1 allows only one attempt at supplying credentials. The default value is 3, but you can set it as high as 5.

  17. Click Save.

Adding an Active Directory query to retrieve group information

  1. Click the Add icon (+) on the Successful branch following the AD Auth policy item.
  2. Click the Authentication tab, click AD Query, and click Add Item.
  3. Under Active Directory, for Type, click the AD AAA server you want to query against. This is likely the same server you chose in the previous procedure.
  4. In the SearchFilter box, type the search query string you want the system to use to query the DC for user information. In the following example, the BIG-IP APM system queries the DC specifying the username:

    (sAMAccountName=%{session.logon.last.username})

    Note: Since you are not using the user's primary group and you are using sAMAcountName rather than User Principal Name, leave both values disabled.

  5. For Fetch Nested Group, click Enabled.
  6. (Optional) If you configure the BIG-IP APM system to query for specific attributes, AD responds with only the necessary attribute rather than all attributes. This can significantly improve the response time experienced during the logon process. This step is particularly useful for large environments. After the BIG-IP APM system makes the initial query, the system stores the information locally on the BIG-IP APM device and uses the information for the remainder of the user session. If changes are made in AD to the user account while the user is connected, the user needs to log out and log back in for the BIG-IP system to acknowledge the changes.
    1. Click Add new entry.
    2. In the topmost Required Attributes box, type the specific AD attribute(s) on which you want resource assignments based. For example, to retrieve the groups that the user belongs to, type memberOf. This limits the response from AD to only include data from the memberOf attribute.
  7. Click the Branch Rules tab.
  8. Delete Name: User Primary Group ID is by clicking the x next to it.
  9. Click Add Branch Rule.
  10. For Expression, click change .
  11. Click Add Expression.
  12. For Agent Sel, click AD Query.
  13. For Condition, click User is a Member Of.
  14. For User is a member of, assign your users a specific webtop. For example, to assign the Classified group users a specific webtop, type:

    CN=Classified,CN=Users,DC=example,DC=com

    Note: By adding expressions under the OR operator in this setting, you can configure the system so multiple groups have access to the same resource as the Classified group.

  15. Click Add Expression.
  16. Click Finished.
  17. Click Save.

Assigning resources to users

At this point, the user is authenticated and you have retrieved all of the nested groups to which the user belongs. You have also told the BIG-IP APM system that members of a specific group (in the examples, the Classified group) can be treated differently than other authenticated users. The next step is to assign the user a webtop based on their group membership.

  1. Click the Add icon (+) following the AD Query policy item on Branch Rule 1.
  2. Click the Assignment tab, click Advanced Resource Assign, and click Add Item.
  3. Click Add new entry.
  4. Click Add/Delete.
  5. Click the Webtop tab.

    Note: You can assign users, ACLs, Network Access, and Web Applications on this tab.

  6. Click the webtop you want to assign to the members of the nested group.

    Note: For information about creating a webtop resource, refer to the Configuration Guide for BIG-IP Access Policy Manager manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  7. Click Update.
  8. Click Add/Delete if you want to add more resources to the webtop.
  9. Click Save.
  10. To assign users who are not in the specific group you created (in the examples, the Classified group) to a different webtop, click the Add icon (+) on the fallback branch that follows the AD Query policy item.
  11. Repeats steps 3 through 9 and make sure that you assign the appropriate resource for that group in step 5.
  12. Click the Deny end point that follows the Resource Assign policy item and change it to Allow.
  13. At the top of the page, click Apply Access Policy.
