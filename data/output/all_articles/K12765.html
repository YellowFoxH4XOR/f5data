Known Issue

This is the result of a known issue. When the HTTP::disable function is called from within an iRule, and HTTP caching is enabled, the BIG-IP system may attempt to access the HTTP cache. As a result, the Traffic Management Microkernel (TMM) may produce a core file.

F5 Product Development tracked this issue as ID 219850 and it was fixed in BIG-IP 11.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, WebAccelerator, or WOM release notes.

Important: For information about a related issue not fixed in BIG-IP 11.2.0, refer to K12938: Calling the HTTP::disable function from within an iRule may result in a TMM core.

Workaround

To prevent the BIG-IP system from accessing the HTTP cache after HTTP processing has been disabled, ensure that the CACHE::disable function immediately precedes the HTTP::disable function within the iRule.
