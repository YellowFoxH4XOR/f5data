Topic

Clone pool members should have valid MAC address entries in the BIG-IP L2 forwarding database (FDB).

    Description

    Clone pools are designed to copy traffic from the BIG-IP system to IDS devices. A clone pool is a property of a virtual server, and it receives all of the same traffic as the load-balancing pool. Clone pool traffic is processed by the Traffic Management Microkernel (TMM).

    When using the clone pool feature, you should make sure that each clone pool member has a valid entry in the L2 FDB. Using the clone pool feature with a pool member that does not have a valid MAC address entry in the BIG-IP FDB may result in high or unbalanced CPU usage. This may be more likely to occur on BIG-IP platforms that contain two High-Speed Bridge (HSB) chips. When the system attempts to send packets to the clone pool, the system scans the forwarding database and looks for an entry for the clone pool member. If the MAC address is not present, then the packets from one HSB chip are forwarded to the other HSB chip, and to the external egress port. This may result in the BIG-IP system having high or unbalanced CPU usage.

    The following platforms contain two HSB chips, and require valid FDB entries for clone pool members:

    • 10000s, 10050s, 10200F, 10200S, 10200v, 10250v, and 10350N
    • PB300 (A110) VIPRION blade

    Note: The same behavior also applies to platforms that are provisioned for Virtual Clustered Multiprocessing (vCMP) regardless of the number of HSBs present. For more information, refer to K94430632: Clone pool members on a vCMP guest require valid MAC addresses in BIG-IP L2 FDB.

    Recommendations

    When you configure clone pools for the previously mentioned platforms, you should confirm that each node in the clone pool has valid ARP and FDB entries. If the nodes do not have ARP and FDB entries, you should add static entries for the nodes in your clone pool. You must update these entries if the MAC address of a node changes or if the network interface or trunk on the BIG-IP system through which the node is reachable changes. To add ARP and FDB entries on a BIG-IP system, perform the following procedure:

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

      tmsh

    2. To verify whether the clone pool member has a valid ARP entry, type the following command:

      show /net arp

    3. If the ARP entry is missing for the clone pool members, you can add a static ARP entry for each member, by using the following syntax:

      create /net arp <node-ip> mac-address <mac-addr>For example, the following command creates a static ARP entry mapping for IP address 192.168.1.1 and MAC address 11:22:33:44:55:66:

      create /net arp 192.168.1.1 mac-address 11:22:33:44:55:66

    4. To verify whether the clone pool member has a valid FDB entry, use the following syntax:

      show /net fdb vlan <vlan-name>

      For example, to verify whether the clone pool member has valid FDB entry for the VLAN named external, type the following command:

      show /net fdb vlan external

    5. If the FDB entry is missing for the clone pool members, you can add a static FDB entry for each MAC address in the clone pool by using the following syntax:

      modify /net fdb vlan <vlan-name> records add { <mac-addr> { interface <int-number> }}

      For example the following command adds a static FDB entry for MAC address 11:22:33:44:55:66 and VLAN external:

      modify /net fdb vlan external records add { 11:22:33:44:55:66 { interface 1.1 } }

    6. To save the configuration, type the following command:

      save /sys config
