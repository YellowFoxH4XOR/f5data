K05053031: After upgrade, zonerunner is empty and named failed to start

Type
Support Solution
Published
2021-01-05
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IP
  • BIG-IP DNS: 15.1.0
Source
https://my.f5.com/manage/s/article/K05053031

Description

  • zones not loaded after upgrade
  • named not starting
  • named in restart loop
  • named errors in /var/log/daemon.log similar to:
    err named[18219]: isc_stdio_open '/log/query.log' failed: file not found
    err named[18219]: configuring logging: file not found
    crit named[18219]: loading configuration: file not found
    crit named[18219]: exiting (due to fatal error)
    notice systemd[1]: named.service: main process exited, code=exited, status=1/FAILURE
    notice systemd[1]: Unit named.service entered failed state.
    warning systemd[1]: named.service failed.
     

Environment

  • named.conf had been customized
  • named logging configured

Cause

Some named.conf customizations are not fully supported on upgrade and need to be cleaned up post upgrade.  In this specific case it's the target logfile that can not be found and opened for writing.

Recommended Actions

Remove the custom logging section from named.conf or create the proper location.

named is started under /var/named/ so that is where it expects the files to be.  For example, given this configuration in /var/named/config/named.conf:

logging {
    channel "query_log" {
        file "/log/query.log" versions 50 size 10m;
        severity info;
        print-category no;
        print-severity yes;
        print-time yes;
    };
};

You would need to do the following from bash:

bigstart stop named
mkdir /var/named/log
chmod 755 /var/named/log
chown named:named /var/named/log
touch /var/named/log/query.log
chmod 644 /var/named/log/query.log
chown named:named /var/named/log/query.log
bigstart start named
