Description

By default some syslog messages will contain the Fully Qualified Domain Name (FQDN) of the system and others will not.

For example, the LTM log file typically only includes the TMM# for pool member changes and not the FQDN in the log messages that are sent to a remote server. Additionally Viprion systems will contain just a slot# or perhaps slot#/<FQDN> depending on version.  You can modify this behavior with the use of syslog templates.

This command will show what the current FQDN/hostname of your device is set to.

[root@Bigip01:Standalone] config # tmsh list sys global-settings hostname
sys global-settings {
    hostname Bigip01.mydomain.com
}

Here is an example from /var/log/ltm detailing a pool member change which contains only TMM3 and not the hostname:

Bigip01 err tmm3[13942]: 01010028:3: No members available for pool /Common/http_pool

You should consider using this procedure under the following condition:

  • You want to include FQDN hostname in messages sent to a remote syslog system
  • You want to modify what hostname the log messages are sent with, such as removing the slot#/FQDN from a Viprion log message and sending only FQDNbut retaining the slot information.

Environment

  • BIG-IP system
  • FQDN required in remote syslog log files

Cause

This is by design that we use only tmm or have slot/hostname but it can be modified.

Recommended Actions

Do not use an include statement with the following options in your syslog configuration:

"options {use_fqdn(yes); keep_hostname(no); };"

This is a global setting and will impact logging to secondary slots on viprion systems and potentially other systems. However, you can modify the behavior and apply it as needed to various destinations.

Open the internal editor using the following command via the CLI:

[root@Bigip01:Standalone] config # tmsh
[root@Bigip01:Standalone(/Common)(tmos)] # edit sys syslog 

Modify the include statement and configure a template for the log messages. Using the template below, messages are sent to the remote system using a static hostname myhostname.static.local. Syslog will append the $HOST variable to the end of the message so that the log retains important information such as which TMM or slot the message is from.
Important: When using an include statement, you must configure remote-servers within the statement itself and not the standard syslog configuration settings. If you already have remote-servers configured then remove those first using tmsh modify sys syslog remote-servers none. Use the include statement to specify remote-servers

Important: Each remote system should have a unique persist-name.

  include "
  filter f_remote_loghost {
      level(info..emerg);
  };
  template custom_remote_template {
      template(\"$DATE myhostname.static.local $PRIORITY $MSG from $HOST\\n\");
      template_escape(no);
  };
  destination my_remote_server {
     udp(\"10.253.41.48\"
      port(514)
      localip(10.75.1.5)
      template(custom_remote_template)
      persist-name(Remote1)
    );
  };
  log {
      source(s_syslog_pipe);
      filter(f_remote_loghost);
      destination(my_remote_server);
  };
  "

Save your changes and close the editor using :wq and pressing enter (vi syntax). When asked to save changes select Y

To verify if config was changed:

tmsh list sys syslog

Additional Information

If you need to remove the changes described in the previous section, you can run the following command from tmsh:

modify /sys syslog include none

Remember to save the change by running the following command from tmsh:

save /sys config
