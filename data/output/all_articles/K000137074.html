Description

When upgrading BIG-IP AFM, following error message is logged in /var/log/ltm log, and configuration load fails. Prompt shows INOPERATIVE, and prompt is slow to respond due to high I/O wait.

Jul 21 11:25:55 bigip1.local err mcpd[7701]: 01071c27:3: Protocol Inspection internal error: Missing system inspection: tag - "/Common/sys_max_each_hs_id_match_count".
Jul 21 11:25:55 bigip1.local err tmsh[10280]: 01420006:3: Loading configuration process failed.
Jul 21 11:25:55 bigip1.local emerg load_config_files[10119]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01071c27:3: Protocol Inspection internal error: Missing system inspection: tag - "/Common/sys_max_each_hs_id_match_count".
Jul 21 11:25:56 bigip1.local err mcpd[7701]: 01070425:3: Full configuration load failed.

Environment

  • BIG-IP AFM module is provisioned
  • Protocol Inspection update 20221206.0512 IM or newer is installed prior to upgrade
  • Upgraded to versions prior to v15.1.9 for v15.x, prior to v16.1.4 for v16.x, or prior to v17.1.0 for v17.x.

Cause

The system compliance /Common/sys_max_each_hs_id_match_count is not correctly migrated to the new volume. However, /config/bigip.conf contains reference to the compliance. Therefore, BIG-IP cannot find the compliance when loading a config.

Recommended Actions

If you face the issue and the prompt is extremely slow, you may first stop TMM, which is consuming disk I/O, and switch back to the original volume.

bigstart stop tmm
switchboot

Within the switchboot screen, choose the original volume to boot from, hit Enter key, and reboot.

reboot

Once in the heathy volume, upgrade to v15.1.9 or later for v15, v16.1.4 or later for v16, v17.1.0 or later for v17.
