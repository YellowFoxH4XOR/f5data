K000152534: FQDN node display a "monitor status FQDN down"

Type
Support Solution
Published
2025-07-11
Updated
2025-07-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K000152534

Description

When using FQDN nodes in BIG-IP LTM, pool members may display a "monitor status FQDN down" message in the logs, for example:

Pool <common/XXXX> member <common/YYYY> monitor status FQDN down. [ ] [ was unknown for 0hr:3mins:9sec ]

This message indicates that the BIG-IP system is unable to resolve the specified FQDN to an IP address, causing health monitors to mark the pool member as down.

Environment

  • Product: BIG-IP LTM
  • Pool members defined by FQDN with autopopulate enabled
  • DNS server(s) configured under sys dns
  • Health monitors applied to these pool members

Cause

The issue occurs when the DNS server configured on BIG-IP does not return an A record for the specified FQDN. Without a valid IP address from DNS resolution, the pool member cannot be monitored and is marked as down.

Recommended Actions

  1. Verify DNS Resolution:
    From the BIG-IP command line, verify that your DNS server returns an A record for the affected FQDN:
    dig @<DNS_SERVER_IP> <FQDN> A
    Replace <DNS_SERVER_IP> with your configured DNS server's IP and <FQDN> with the full domain name of your node.
  2. Check DNS Server Health and Records:
    Ensure that your DNS server is reachable and authoritative for the queried domain.
    Confirm that there is a valid A record for the required hostname.
  3. Adjust Node Interval (Optional):
    You can set a fixed interval (e.g., 60 seconds) for how often BIG-IP queries DNS instead of using 'ttl':

    ltm node <node_name> {
        fqdn {
            autopopulate enabled
            interval 60
            name <FQDN>
        }
    }

  4. Monitor System Logs:
    After making corrections or updates, review system logs to confirm that "FQDN down" messages no longer appear and that pool member status has returned to healthy.
