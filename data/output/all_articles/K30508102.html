K30508102: Chrome and MSEdge clients get /vdesk/hangup.php3 when Access Policy uses SAML Auth

Type
Support Solution
Published
2021-07-18
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 16.X.X, 16.1.X, 16.0.X, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 16.0.1, 16.0.0
Source
https://my.f5.com/manage/s/article/K30508102

Description

When attempting to access federated applications protected by APM acting as a Service Provider (SP) for SAML authentication, first access attempt fails, and users gets redirect to /vdesk/hangup.php3 .

Environment

  • APM as SAML SP
  • Chrome v63+ or Microsoft Edge (prefetch/preload is enabled by default)

Cause
Beginning in Chrome 63, Chrome send requests with a "Purpose: prefetch" header for faster loading of web pages.  This can cause problems with APM when the actual (identical) request is sent by the client.
If during Access Policy processing the BIG-IP receives unexpected requests APM sessions will be terminated. In this case instead of sending a request containing the SAML assertion, the BIG-IP receives the original request that started the APM session again, which is not expected at this phase of the Access Policy,

Recommended Actions
Create an iRule with the code below to drop requests containing the header "Purpose: prefetch" and assign it to the APM Virtual Server.

when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
 }
 when HTTP_REQUEST {
  if { [HTTP::header Purpose] equals "prefetch" } {
    TCP::close
  }
 }
Alternatively you can disable Chrome Prefetch:
  1. Click the Menu button in the upper-right corner, then select Settings.
  2. Scroll down and select the Advanced option.
  3. Scroll down to the Privacy and Security section, then toggle the Use a prediction service to load pages more quickly option to the left to Disable Prefetch.
