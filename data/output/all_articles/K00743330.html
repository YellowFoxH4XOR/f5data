Description
You want to use management network to send logs to Syslog servers, but Syslog traffic is being sent out of a self IP address rather than the management interface.
Even with a proper management route and using management IP as local IP to bind syslog, logs are still sent from a Self IP. For example:

sys syslog {
    remote-servers {
        /Common/remotesyslog {
            description none
            host 10.1.5.14   <<<=== Remote syslog server
            local-ip 10.1.1.100   <<<===  Management IP
            remote-port 514
        }
    }
}

sys management-route /Common/syslog_route {
    gateway 10.1.1.1
    network 10.1.5.14/32   <<<=== Remote syslog server
}

Environment

  • Remote Syslog servers
  • Management route configured

Cause
Existing syslog active connections are using Self IP. Process syslog-ng may need to be restarted to start using Management IP.

Recommended Actions

  1. Please run this command to check and confirm if syslog is somehow sent out via Self IP
netstat -pan|grep -E 'syslog-ng|errdefsd'

Output of example, where IP 192.168.1.3 is a Self IP:
udp        0      0 127.0.0.1:514           0.0.0.0:*                           1967/syslog-ng       off (0.00/0/0)
udp        0      0 192.168.1.3:45621       10.1.5.14:514         ESTABLISHED   1967/syslog-ng       off (0.00/0/0)
  1. If it is confirmed existing active connection is using a Self IP, restart syslog-ng process
bigstart restart syslog-ng
  1. Confirm if syslog is now sent via Management IP
netstat -pan|grep -E 'syslog-ng|errdefsd'
