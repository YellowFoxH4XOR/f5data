Known Issue

This is the result of a known issue. When a failover occurs in a FirePass controller failover pair that is configured with a large number of group-based packet filter rules, Network Access connections may be blocked after failover. Applications that attempt to use the Network Access tunnel will not work until the Network Access client is manually relaunched.

When a failover occurs in a FirePass controller failover pair, Network Access clients should automatically reconnect to the active FirePass controller. However, this issue may cause application connections through the Network Access tunnel, which would normally be allowed by group packet filter rules, to be blocked. The Syslog report shows packets that are accepted by global packet filter rules, but not packets that are accepted or rejected by group-based packet filter rules. Syslog reports are located on the Reports: System Logs page.

F5 Product Development tracked this issue as CR81861, and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass release notes.

Additionally, a hotfix has been issued. For version 6.0.1 of FirePass software, this issue was fixed in Cumulative Hotfix HF-601-5. For version 5.5.2 of FirePass software, this issue was fixed in Cumulative Hotfix HF-552-10. You may download these hotfixes or later versions of the Cumulative Hotfixes from the F5 Downloads site.

For instructions about how to obtain a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

Users can work around this issue by manually relaunching the Network Access client. Once the client is relaunched, the group-based packet filters will function correctly.
