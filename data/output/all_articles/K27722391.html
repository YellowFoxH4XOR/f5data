Description

You may face the following symptoms:

  • Some pool members show a down status only in one monitor Interval, then it recovers to normal.
  • You may find the follow logs at /var/log/ltm.
01010040:4: Clock has unexpectedly adjusted by <#> ms
  • You may find the disorder of the timestamp at /var/log/ltm, for example:

Jan 26 19:49:49 Hostname err tmm[19631]: 01010028:3: No members available for pool /Common/pool_3

  • You have low stratum NTP server set
    NOTE: Stratum level (0-16) indicates the device's distance to the reference clock. and as level goes high, it gets more unreliable.
    Stratum 0 devices are the most accurate, but cannot be connected to via a network connection. A Stratum 0 device is usually used as a reference clock (or synchronisation source) for a Stratum 1 time server.

Environment

  • BIG-IP LTM
  • Pool/Node status
  • Health monitor
  • NTP

Cause

Unstable NTP influences the bigd process, so it marks pool member up/down unexpectedly.
IMPORTANT: Unstable NTP can cause failover depending on your configuration (HA-Group).

Recommended Actions

F5 recommends that you configure at least three external NTP servers with stratum 1-3 to ensure reliability.
Please add more NTP server for BIG-IP, about more detail you can refer K3122: Using the BIG-IP Configuration utility to add an NTP server.
