Known Issue

The Traffic Management Microkernel (TMM) may restart when DNS cache configurations exceed available BIG-IP system memory.

This issue occurs when all of the following conditions are met:

  • You have configured one or more DNS caches on the BIG-IP system.
  • One or more of the following DNS cache settings is modified to a value significantly higher than the default value:
    • Message Cache Size
      The default value is 1048576 bytes.
    • Resource Record Cache Size
      The default value is 10485760 bytes.
    • Name Server Cache Count
      The default value is 16536 entries.

Note: This issue occurs because the BIG-IP DNS cache continues to allocate memory and store resource records until the cache reaches the configured values or runs out of memory.

Impact

Traffic processing is interrupted while TMM restarts, and a failover event occurs if the BIG-IP system is in a high availability (HA) configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H631041 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system fails to process traffic for a brief period.
  • The BIG-IP system fails over to another system in the device group.
  • TMM produces a core file in the /var/core directory.
  • In the /var/log/tmm file, you observe a message similar to the following example:

    panic: unable to alloc 43 bytes

  • In the /var/log/ltm file, you observe messages similar to the following example:

    err tmm[3456]: mesh_attach_sub: out of memory
    err tmm[5678]: hash grow: malloc failed
    warning tmm[12345]: 011e0003:4: Aggressive mode sweeper: 100 Connections killed.

Workaround

To work around this issue, ensure that the sum of all of the configured cache Message Cache Size, Resource Record Cache Size, and Name Server Cache Count settings is half the value or less of the total memory allocated to TMOS. To do so, perform the following procedure:

Note: For VIPRION systems, the total value and total memory calculation applies to a single blade, not the sum of all installed blades in the chassis.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To determine the total memory assigned to TMOS, type the following command:

    show sys provision | grep 'Memory\|tmos'

    In the following example, the total memory assigned to TMOS is 100,698 MB:

    Module  CPU (%)  Memory (MB)  Host-Memory (MB)  Disk (MB)
    tmos         88       100698               560          0

    Note: Based on 100,698 MB, the sum of all of the DNS cache sizes should not exceed 50,000 MB.

  3. Determine the number of TMMs by typing the following command:

    show sys tmm-info | grep Sys::TMM

    In the following example, the BIG-IP system has eight TMMs:

    Sys::TMM: 0.0
    Sys::TMM: 0.2
    Sys::TMM: 0.4
    Sys::TMM: 0.6
    Sys::TMM: 0.8
    Sys::TMM: 0.10
    Sys::TMM: 0.12
    Sys::TMM: 0.14

  4. List the DNS caches and their respective cache sizes by typing the following command:

    list ltm dns cache resolver all-properties | grep cache

    Output appears similar to the following example:

    ltm dns cache resolver test {
        msg-cache-size 1mb
        nameserver-cache-count 16536
        rrset-cache-size 10mb
    ltm dns cache resolver test2 {
        msg-cache-size 1mb
        nameserver-cache-count 16536
        rrset-cache-size 10mb

  5. To determine the total value of all DNS caches, apply the following calculation to each cache and add the results:

    (Message Cache Size + Resource Record Cache Size + Name Server Cache Count * 250 bytes) * 2.5 * Number of TMMs.

  6. Ensure the total value is half the value or less of the total memory.
