Description
IPv4 virtual address is assigned an IPv6 mask when a PUT request is sent to iControlREST with no mask attribute.

The virtual address is unresponsive.

Environment

  • BIG-IP LTM
  • iControlREST
  • PUT request used to modify virtual address
    • PUT request content does not contain mask attribute, for example:
      {"routeAdvertisement": "enabled"}

Cause
In iControlREST, PUT requests replace the entire object. Attributes which are not included are reset to the default.

iControlREST considers an IPv6 128-bit mask the default for virtual addresses and misconfigures virtual addresses under these conditions. This behavior is tracked as Bug ID 818505.

Recommended Actions
When using iControl REST:

  • You can use PATCH requests with a partial definition to update only the included attributes
  • When using PUT you should always send the entire JSON definition for the object you want to modify
