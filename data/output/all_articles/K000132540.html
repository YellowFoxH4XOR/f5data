K000132540: BIGIP-APM reset due to HTTP body too big.

Type
Support Solution
Published
2023-02-14
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP APM: 14.1.5
Source
https://my.f5.com/manage/s/article/K000132540

Description

You are experiencing an issue where your APM is resetting the connection during a POST request when the HTTP body size is greater than 25 MB, even if the request includes a valid MRHSession cookie.

 

Environment

  • BIG-IP APM
  • POST requests

 

Cause

An irule adding the clientless mode header to every POST request.

 

HTTP::header insert "clientless-mode" 1

 

Recommended Actions

One option to consider would be to check for a valid session first, and only insert the header if there is not a valid session. This could potentially resolve the issue, as it would allow for a larger request size limit. Here is a sample iRule you could use to accomplish this:

 

when HTTP_REQUEST {

if {[HTTP::cookie exists "MRHSession"]} {

# Do not insert the "clientless-mode" header

} else {

HTTP::header insert "clientless-mode" 1

}

}

 

The above iRule checks for the presence of the MRHSession cookie in the request. If the cookie exists, it does not insert the "clientless-mode" header. If the cookie does not exist, it inserts the header with a value of 1.

 

By implementing this iRule, you can avoid unnecessary insertion of the "clientless-mode" header in POST requests with a valid MRHSession cookie, and allow for a larger request size limit.
