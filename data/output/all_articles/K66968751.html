Known Issue

An iControl memory leak may occur when using GlobalLB::PoolMember method calls.

This issue occurs when one of the following conditions is met:

  • An iControl call is made using GlobalLB::PoolMember get_all_statistics.
  • An iControl call is made using GlobalLB::PoolMember get_monitor_association.

Impact

A memory leak may occur within the iControl portal.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The iControlPortal.cgi process memory usage grows.

You can view memory usage by typing the following command from the command line:

ps axufw | grep iControlPortal.cgi

Note: Querying large BIG-IP GTM configurations often will cause memory consumption at a faster rate.

Workaround

To work around this issue, you can restart the httpd process. To do so, perform the following procedure:

Impact of workaround: Performing this workaround will not affect traffic, but it will affect access to the Configuration utility as it requires you to restart the httpd process.

  1. Log in to the command line.
  2. Restart the httpd process by typing the following command:

    bigstart restart httpd
