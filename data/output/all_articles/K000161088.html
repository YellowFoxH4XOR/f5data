Topic

This article describes the new feature available from BIG-IP 21.1.0 to rate limit iControl REST API requests.

Description

Beginning in BIG-IP 21.1.0, you can enforce request limits on the management endpoint by configuring rate limiting parameters through the Configuration utility, command line and iControl REST, thus improving resilience and responsiveness to Denial of Service (DoS) attacks. The following 3 parameters are available for you to configure rate limiting:

  • Request Rate Limit Per Client (Requests per Second) 
    Parameter: api-ratelimit
    Default Value: 150 requests/second
    Range: Integer value ≥ 1.
    This parameter restricts the maximum number of requests a single client can send to the /mgmt endpoint per second. You configure this to throttle bursty API requests from individual clients, reducing the risk of resource exhaustion. This ensures no single client can overload the system with excessive API requests, maintaining overall responsiveness.

  • Maximum Concurrent Requests (Total Requests)
    Parameter    : api-requestlimit
    Default Value: 20
    Range: Integer value between 1 and 50.
    This parameter controls the maximum number of concurrent API requests allowed across all clients to the /mgmt iControl REST endpoint. This avoids resource contention by limiting simultaneous API requests, which helps in controlling the overall system load.

  • Error Response Code for Rate-Limiting
    Parameter    : api-ratelimit-errcode
    Default Value: 429
    Range: Valid HTTP status codes from 400 to 499.
    This parameter specifies the HTTP error code returned to clients when they exceed the configured rate limits. This provides administrators the flexibility to align error codes with application requirements and improve client feedback during rate-limiting.

You can configure the rate limiting parameters through any of the following:

  • Configuration utility
  • Command line TMOS shell (tmsh)
  • iControl REST

Configuration utilityTo view or update the rate limit parameters on the Configuration utility, perform the following:

  1. Login to the Configuration utility.
  2. Go to System > Preferences.
  3. In the Security Settings section, select Advanced.
  4. Modify the values of API Rate Limit, API Request Limit and API Rate Limit HTTP Error Code as appropriate.
  5. Select Update.

Command line TMOS shell (tmsh)The parameters are configurable through DB variables. To list the values of the parameters, use the following command syntax:
tmsh list sys httpd <parameter name>For example:
tmsh list sys httpd api-ratelimit

To modify the values, use the following command syntax:
tmsh modify sys httpd api-ratelimit <value>
tmsh modify sys httpd api-requestlimit <value>
tmsh modify sys httpd api-ratelimit-errcode <value>For example, enter the following command to set the api rate limit error code to 403 (Forbidden):
tmsh modify sys httpd api-ratelimit-errcode 403

iControl RESTTo view the configuration of the parameters, use the following syntax:
curl -sk -u <uname>:<password> -X GET https://<big-ip>/mgmt/tm/sys/httpd | jq .
For example:
curl -sk -u admin:password -X GET https://10.1.1.10/mgmt/tm/sys/httpd | jq .
curl -sk -u admin:password -X GET https://10.1.1.10/mgmt/tm/sys/httpd | jq . | grep api
curl -sk -u admin:password -X GET https://10.1.1.10/mgmt/tm/sys/httpd | jq '.apiRatelimit'

To modify the values of the parameters, use the following  command syntax:
curl -sk -u <uname>:<password> -X PATCH -H "Content-Type: application/json" -d '{"api-ratelimit”:<value>}’ https://<big-ip>/mgmt/tm/sys/httpd
curl -sk -u <uname>:<password> -X PATCH -H "Content-Type: application/json" -d '{"api-requestlimit”:<value>}’ https://<big-ip>/mgmt/tm/sys/httpd
curl -sk -u <uname>:<password> -X PATCH -H "Content-Type: application/json" -d '{"api-ratelimit-errcode”:<value>}’ https://<big-ip>/mgmt/tm/sys/httpd

For example, to set the value of api-ratelimit to 1, enter:
curl -sk -u admin:password -X PATCH -H "Content-Type: application/json" -d '{"api-ratelimit":1}' https://10.1.1.10/mgmt/tm/sys/httpd
