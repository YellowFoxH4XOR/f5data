Description

On F5OS Chassis platforms, running the command docker restart authentication-mgr can trigger an unexpected controller failover (CC failover). During this process, system logs may show messages such as:

controller-1 vcc-confd[8]: priority="Warn" version=1.0 msgid=0x4101000000000039 msg="component NOT healthy" comp_str="controller"

controller-1 vcc-confd[8]: priority="Warn" version=1.0 msgid=0x4101000000000039 msg="component NOT healthy" comp_str="controller/services"

controller-1 vcc-confd[8]: priority="Warn" version=1.0 msgid=0x4101000000000039 msg="component NOT healthy" comp_str="controller/services/authentication-mgr"

Environment

  • Product: F5OS - Chassis (Velos)
  • Version: F5OS-C 1.8.0

Cause

Controller failover is triggered when certain monitored service’s health attributes reach an "Error" state. 

For authentication-mgr specifically the following conditions will set the attributes to Error:

  • The service:restart-last-hour attribute exceeding 10 restarts within one hour.
  • The service:ready attribute is not ready after 60 seconds.
  • The service:message-error has a health monitor error.

In addition to that when container:running attribute of the container being temporarily set to "Unhealthy | Error" during a container restart, parent components (controller, controller/services) can be marked as "Unhealthy" as well, triggering a controller failover.

The issue is being tracked under ID2034949.

Other controller monitored services include (but are not limited to):

  • platform-hal
  • cc-switchd
  • vcc-confd
  • authentication-mgr
  • platform-diag
  • platform-monitor
  • platform-fwu
  • diag-agent
  • alert-service
  • platform-stats
  • vcc-terminal-server.main / .default
  • controller_tmstat_zmq
  • lopd
  • controller_rsyslogd / velocity-rsyslogd
  • qkviewd / ihealth-service / otel-collector

Recommended Actions

  • Avoid restarting individual controller service containers (e.g., with docker restart authentication-mgr ). Instead, restart the entire system or active controller for safe state reset.
  • To check current restart counts for authentication-mgr service:

docker exec diag-agent psf call GET:components/attributes --filter="component matches 'auth'" --select=attribute,description,health,severity,value,updatedCount 
If other service is needed, replace ''auth'' with the desired service name (or part of the name).

  • To view monitoring rules and thresholds for authentication-mgr service:

docker exec diag-agent psf call GET:components/limits --filter="attribute matches 'service:' and component matches 'auth'" --select=attribute,expression,message,severity 
If other service is needed, replace ''auth'' with the desired service name (or part of the name).
