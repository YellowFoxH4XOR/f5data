Topic

By default, the members of a 3-DNS sync group dynamically determine the best BIG-IP device within the sync group configuration to use as the prober for a particular node. Devices defined within the same data center as the node are preferred, and probing tasks are distributed round robin within each data center to the device responsible for the fewest probing tasks. This approach is intended to both maintain proximity between the probing device and the probed device, and to distribute the prober load among all eligible devices. In most cases, the automatic distribution of prober tasks results in a fully functional prober configuration. However, due to differing connectivity limitations between peers in redundant BIG-IP and LTM systems, environments that use 3-DNS systems to load balance redundant BIG-IP LTM systems may experience probing anomalies.

Note: This issue is specific to ECV monitors and probers assigned to wide IP addresses in the 3-DNS configuration; it does not affect the iQuery communication stream between BIG-IP LTM and 3-DNS that is used to report virtual server status.

Each member of any BIG-IP redundant system runs the big3d process, and is able to perform probing tasks, whether in the active or standby state. However, you must take into account the following limitations in connectivity between redundant pairs regarding which member of a system should actually be tasked with the probe:

  • As of BIG-IP version 9.4.0, both the standby unit and the active unit can connect to virtual addresses configured on the pair. As a result, either unit may successfully be assigned probing responsibility for any virtual server.
  • In BIG-IP versions 9.0.0 through 9.3.1, the active unit in a redundant pair can connect to virtual addresses configured on the pair, but the standby unit cannot. As a result, only the active unit may successfully be assigned probing responsibility for virtual servers configured on the pair.
  • In BIG-IP version 4.5.0, the standby unit in a redundant pair can connect to virtual addresses configured on the pair, but the active unit cannot. As a result, only the standby unit may successfully be assigned probing responsibility for virtual servers configured on the pair.

Note: For more information about the change in behavior for the BIG-IP LTM 9.x branch, refer to K9206: A standby unit cannot connect to virtual addresses on active unit.

Since 3-DNS version 4.5.0 is unable to distinguish between a BIG-IP version 4.5.0 system and a BIG-IP LTM version 9.x system, the 3-DNS system always assigns probing responsibility to the standby unit. As a result, a 3-DNS system that is configured to load balance BIG-IP LTM versions 9.0.0 through 9.3.1 systems may assign probing responsibility for a virtual server configured on the high availability pair to the standby unit. When this behavior occurs, the prober will fail since the standby unit cannot connect to the active unit.

Note: This issue does not apply to mixed environments using BIG-IP GTM version 9.x to load balance a BIG-IP version 4.x system. The BIG-IP GTM system is capable of recognizing the difference between a BIG-IP version 4.5 system and a BIG-IP LTM version 9.x system and assigns the health checks to the appropriate unit for each.

Workaround

If you are using 3-DNS version 4.5 to load balance BIG-IP LTM versions 9.0.0 through 9.3.1 systems and encounter this issue, you can perform one of the following three workarounds:

  • Upgrading 3-DNS to BIG-IP GTM
  • Upgrading the BIG-IP LTM devices to version 9.4.0 or higher
  • Disabling the ECV and prober factories in the 3-DNS configuration for BIG-IP LTM devices

Upgrading 3-DNS to BIG-IP GTM

F5 strongly recommends you migrate your current 3-DNS deployment to the current BIG-IP GTM maintenance release.

Note: 3-DNS version 4.5.0 reaches end of software development on December 31, 2008. For more information, refer to K5903:BIG-IP software support policy.

Upgrading the BIG-IP LTM devices to version 9.4.0 or later

Upgrading the BIG-IP LTM devices to the latest version of BIG-IP LTM will resolve the issue by allowing either member of a redundant pair to perform the probing tasks for local virtual addresses.

Disabling the ECV and prober factories in the 3-DNS configuration for LTM devices

Important: You should perform this workaround as a last resort. Restricting probing tasks to a subset of available systems may cause an undesirable increase in system load and a decrease in system performance and responsiveness.

By disabling the prober factories for BIG-IP LTM versions 9.0.0 through 9.3.1, you can prevent them from being assigned any probing responsibility. To do so, perform the following procedure:

  1. Within the 3-DNS Configuration utility GUI, navigate to Servers: BIG-IP.
  2. For each BIG-IP LTM device, click on BIG-IP Name.
  3. Clear the Prober and ECV check boxes in the Factories section.
  4. Click Update to save your changes.
  5. Repeat this procedure for all BIG-IP LTM systems running versions 9.0.0 through 9.3.1 that are defined in the 3-DNS.
