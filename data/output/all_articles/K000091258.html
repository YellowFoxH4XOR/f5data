K000091258: Missing Header access-allow-origin

Type
Support Solution
Published
2022-02-12
Updated
2022-02-12
Source
https://my.f5.com/manage/s/article/K000091258

Description

  • Preflight check and handling is performed on Nginx ingress controller 
  • One of the REQUIRMENTS for the ingress is the ability to handle Cross-Origin Resource Sharing [CORS]
  • CORS handling is set within the Nginx plus ingress controller pod 
  • Though, CORS handling is configured on the NGINX ingress, both Chrome & Firefox browsers reject a POST request response with 'net-error'.

URL:

    https://example.com/some.uri.address.services.v1.ContestService/ListSomeConfiguredResource

Result:

    net::ERR_FAILED


  • Also, when setting the browser in set to an insecure mode following command [for Windows systems] "chrome.exe --args --user-data-dir="C:\temp\chrome" --disable-site-isolation-trials --allow-file-access-from-files --disable-web-security --ignore-certificate-errors", then we can see the expected response along with configured header, for example 

access-control-allow-credentials   true

access-control-allow-headers  *

access-control-allow-methods  POST, OPTIONS

access-control-allow-origin  https://example.com 

access-control-expose-headers *

access-control-max-age 86400


  • With CORS enabled on the browser, you are unable to display/load the expected page/resource and the browser rejects Nginx ingress's response  

 Environment

  • Nginx Ingress Controller
  • Cross-Origin Resource Sharing [CORS]

 Cause

  • Nginx ingress controller does not have a built-in feature for CORS support
    • https://github.com/nginxinc/kubernetes-ingress/issues/1414

 Recommended Actions

  • With Nginx, we do have a workaround through the use of snippets for Ingress and VirtualServer/VirtualServerRoute.
  • we could add the necessary headers to the Ingress resource via location snippets [nginx.org/location-snippets annotation].
  • For example, the following article discusses the enablement of CORS in Nginx configuration supporting Preflight requests https://enable-cors.org/server_nginx.html.


nginx.org/location-snippets: |

if ($request_method = 'OPTIONS') {

add_header 'Access-Control-Allow-Origin' 'https://example.com';

add_header 'Access-Control-Allow-Methods' 'POST, OPTIONS';

add_header 'Access-Control-Allow-Headers' '*';

add_header 'Access-Control-Max-Age' 86400;

add_header 'Access-Control-Allow-Credentials' 'true';

add_header 'Content-Type' 'text/plain; charset=utf-8';

add_header 'Content-Length' 0;

return 204;

}

if ($request_method = 'POST') {

add_header 'Access-Control-Allow-Origin' 'https://example.com' always;

add_header 'Access-Control-Allow-Methods' 'POST, OPTIONS' always;

add_header 'Access-Control-Allow-Headers' '*' always;

add_header 'Access-Control-Expose-Headers' '*' always;

add_header 'Access-Control-Allow-Credentials' 'true' always;

}

 Additional Information

  • You can also find further explanation in how to use/work with snippets and NGINX Ingress Controller, https://docs.nginx.com/nginx-ingress-controller/configuration/ingress-resources/advanced-configuration-with-snippets/
