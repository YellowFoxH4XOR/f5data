Known Issue

Creating a new Security Assertion Markup Language (SAML) Identity Provider (IdP) configuration object that contains an empty attribute value may cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when the following condition is met:

  • You create a new single sign-on (SSO) SAML configuration object with one or more attribute values containing a session variable, followed by an empty value ("").

    In the following example, an SSO SAML configuration object has SAML attributes containing the multi-values of value1 and another empty value ("").

    Note: Empty quotes ("") is as an attribute value. The following example is not a valid configuration because empty values must not be provided in the list of SAML attributes.

    apm sso saml idpExample {
              attributes {
                  {
                      multi-values { value1 "" }
                      name test
                  }
              }
              entity-id https://example.com
              saml-profiles { web-browser-sso }
              subject-value "%{session.sso.token.last.username}"
    }

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured for high availability (HA) may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP APM system generates a TMM core file in the /shared/core/ directory.
  • If you have an HA configuration, your BIG-IP APM system fails over to a standby system.
  • In the /var/log/apm file, you observe a log message similar to the following example:

err tmm[<processID>]: 014d0002:3: Internal error processing sso config /Common/<SSO object name> in sso_tmconf_string_parse_list
err tmm1[<processID>]: 014d0002:3: Internal error processing sso config /Common/<SSO object name> in sso_tmconf_string_parse_list
err tmm1[<processID>]: 014d0002:3: SSOv2 plugin error(12) in sso/sso_config.c:2939

Workaround

To work around this issue, you can remove the empty attribute value ("") from the SAML configuration. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

BIG-IP APM 13.0.0 and later

  1. Log in to the Configuration utility of the BIG-IP system.
  2. Navigate to Access > Federation > SAML Identity Provider > Local IdP Services.
  3. Select the check box next to the SAML IdP Service configuration object you want to edit.
  4. Click Edit.
  5. Click SAML Attributes.
  6. Select the check box next to the name of the attribute with the empty value ("").
  7. Click Edit.
  8. Select the check box next to the empty value ("") and click Delete.
  9. Click OK.

BIG-IP APM 12.x

  1. Log in to the Configuration utility of the BIG-IP system.
  2. Navigate to Access Policy > SSO Configurations > SAML.
  3. Select the check box next to the SAML SSO configuration object you want to edit.
  4. Click Edit.
  5. Click SAML Attributes.
  6. Select the check box next to the name of the attribute with the empty value ("").
  7. Click Edit.
  8. Select the check box next to the empty value ("") and click Delete.
  9. Click OK.
