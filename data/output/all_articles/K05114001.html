Known Issue

Enabling load balance decision logging for a DNS profile may cause the Traffic Management Microkernel (TMM) to produce a core file.

This issue occurs when all of the following conditions are met:

  • DNS logging is enabled and the log profile is set on the DNS profile.
  • A wide IP is configured with a last resort pool.
  • The last resort pool is unavailable.
  • A query is load balanced to the last resort pool.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • If configured for HA, the BIG-IP system fails over to the standby system.
  • The BIG-IP system generates TMM core files to the /var/core directory, which include a time stamp that correlates with the traffic interruption.

Workaround

To work around this issue, you can disable the decision logging feature. To do so, perform the following procedure:

Impact of workaround: Decision logging will not be performed.

  1. Log in to the Configuration utility as an administrative user.
  2. Navigate to DNS > GSLB > Wide-IP.
  3. Click on the wide IP that you want to modify.
  4. Under General Properties, select Advanced.
  5. Deselect all the items in Load-Balancing Decision Log.
  6. To save the configuration, click Finished.

Repeat this procedure for all wide IPs that have decision logging enabled.
