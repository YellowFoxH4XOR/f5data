K62265700: BIG-IP VE experiences high CPU usage and packet loss after upgrade

Description

After an upgrade, the BIG-IP VE experiences increased CPU (TMM) usage with no change to the volume of traffic processed.

For example, you may notice the following changes.

TMM's CPU usage before upgrade:
# tmsh show /sys tmm-info | grep -P 'Sys::|Last 1 Minute\d '
Sys::TMM: 0.0
  Last 1 Minute         40
Sys::TMM: 0.1
  Last 1 Minute         35
Sys::TMM: 0.2
  Last 1 Minute         37
Sys::TMM: 0.3
  Last 1 Minute         52

TMM's CPU usage after upgrade:
# tmsh show /sys tmm-info | grep -P 'Sys::|Last 1 Minute\d '
Sys::TMM: 0.0
  Last 1 Minute         97     <=== increased significantly relative to other TMM threads
Sys::TMM: 0.1
  Last 1 Minute         43
Sys::TMM: 0.2
  Last 1 Minute         38
Sys::TMM: 0.3
  Last 1 Minute         44

If any of the TMM threads is overloaded (TMM 0.0 in the example above), the BIG-IP may experience some packet loss.

Environment

All the following conditions are matched:

  • BIG-IP VE
  • Hyper-V hypervisor with SR-IOV enabled adaptor or Azure Cloud with accelerated networking
  • Upgrading from versions prior to 14.1.0 or 15.1.4
  • Upgrading to 14.1.0 or 15.1.4 or later

Cause

Bug ID 1106489 and Bug ID 1121517, which are regressions of Bug ID 985537.

Recommended Actions

Verify that the BIG-IP VE is affected:

  1. Verify that the BIG-IP VE runs in Hyper-V or Azure Cloud.

    Run the following command on the BIG-IP:

    # tmsh show /sys proc-info hypervkvpd | grep hypervkvpd -B1 -A5
    ----------------------------
    Process: hypervkvpd
    ----------------------------
    Process ID             <pid>
    Blade Id                   0
    Associated Modules

    If the command produces an output similar to the above, the BIG-IP runs in Hyper-V or Azure Cloud.

    If the command produces no output, the BIG-IP is not affected and this articles does not apply.
     
  2. Verify that you have SR-IOV or accelerated networking enabled.

    Run the following command on the BIG-IP:

    # lspci -vnn | grep -i Ethernet
    0002:00:02.0 Ethernet controller [0200]: Mellanox Technologies MT27500/MT27520 Family [ConnectX-3/ConnectX-3 Pro Virtual Function] [15b3:1004]
    0003:00:02.0 Ethernet controller [0200]: Mellanox Technologies MT27500/MT27520 Family [ConnectX-3/ConnectX-3 Pro Virtual Function] [15b3:1004]

    The command should list one of the supported SR-IOV adaptors. In the example above, it shows the Mellanox ConnectX-3 adaptor. If you do not find any supported SR-IOV adaptor in the command output, the BIG-IP is not affected, and this article does not apply.

    Note: Refer to K17204: BIG-IP VE NIC adapters that support SR-IOV for the list of support adaptors.
     
  3. Verify that you are using an affected version (14.1.0 or 15.1.4 or later).
     
  4. If you have done the verification above and confirmed the BIG-IP VE is affected, please contact F5 support for assistance.
