K000158854: Master Key Mismatch and Tenant Inoperability Following F5OS-C Upgrade

Type
Support Solution
Published
2025-12-19
Updated
2025-12-19
Applies to
  • F5OS
  • F5OS-C: 1.8.2
Source
https://my.f5.com/manage/s/article/K000158854

Description

After upgrading the F5OS-C (VELOS) controller and partition from version 1.8.0 to 1.8.2, a BIG-IP tenant may fail to start and become inoperative. The following symptoms may be observed:

  • Repeated errors during tenant startup, including:
    • "Decryption of the field (value) for object (configsync.password) failed while loading configuration that is encrypted with a different master key."
    • "Unit key could not be decrypted"
    • "No unit key was found in confd for tenant"
    • "EOF on socket to ConfD" (ERRNO=45)
  • Tenant remains in an INOPERATIVE state.
  • Console messages indicate configuration load failures due to encryption/decryption issues.

These errors indicate a mismatch between the tenant’s master key and its HA peer, resulting in an inability to decrypt configuration data.

Environment

  • Platform: F5OS-C (VELOS), versions 1.8.0 and 1.8.2
  • BIG-IP tenant, version 17.1.2.1
  • Controller/partition upgrades performed with tenants shut down prior to upgrade
  • Issue observed after bringing tenants online post-upgrade 

Cause

Bug ID 1988997

Recommended Actions

Re-key the affected tenant using the same master key as its HA peer.

 1. Open a console window, using a program such as PuTTY to both tenants.
2. Log in to the working tenant, and at the system prompt, obtain the master key by typing this command:

f5mku -K
The command output appears similar to this example:

oruIVCHfmVBnwGaSR/+MAA==

3. Copy the output. The output is the master key that you will install on the affected tenant.
4. Log in to the affected tenant, and at the system prompt, install the master key that you copied from the working tenant by typing this command:

f5mku -r key_value
Here's a sample command sequence:

f5mku -r oruIVCHfmVBnwGaSR/+MAA==


5. Save the configuration, restart the mcpd service, and reboot the tenant.
