K12238: Assigning FirePass resources based on the mobile OS platform using the session.browser.user_agent session variable

Topic

You can determine the type of mobile device (for example, iPhone, iPad, or iPod touch) connecting to the FirePass controller by analyzing the session.browser.user_agent variable and assigning resources based on the value returned. For example, when a user connects to FirePass from an iPhone, they will be mapped to the iPhone_Users group and assigned the resources from the iPhone_resources group. The following procedure illustrates how to gather the device information from the session.browser.user_agent variable and assign resources based on the data returned.

Important: The following series of procedures is an example of how to assign resources; it is not intended to define how to integrate the mobile device into your environment.

Note: For more information, refer to the FirePass Controller Administrator Guide.

To configure FirePass to recognize a mobile device and assign web application resources, perform the following procedures:

  • Creating a pre-logon sequence and adding the user agent action for a mobile device
  • Creating a custom variable
  • Activating the pre-logon sequence
  • Creating a resource group to assign resources to the mobile device
  • Configuring the dynamic group mapping
  • Configuring the dynamic master group

Prerequisites

  • FirePass controller configured with existing web resource
  • Understanding of the pre-logon sequence
  • Understanding of dynamic master group mapping

Creating a pre-logon sequence and adding the user agent action for a mobile device

Important: If you choose to edit an active pre-logon sequence, any changes made are immediate and will affect any users connecting to the FirePass controller.

  1. Log in to the FirePass Administrative Console.
  2. Navigate to Users : Endpoint Security : Pre-Logon Sequence.
  3. Under the New Sequence section, in the Create new sequence text box, enter a name for your new sequence.

    For example:

    MobileCheck

  4. From the Based on drop-down menu, select template : Empty.
  5. Click the Create button.
  6. Click the edit link next to the pre-logon sequence created in Step 3.

    For example:

    MobileCheck

  7. Hover the mouse over the line next to the Sequence Start step.

    A plus character (+) appears on the line.
  8. Click the + character.

    The Change Sequence panel opens on the right.
  9. Click the Check OS radio button.
  10. Click the Apply changes button.

    The Check OS action you just created appears in your sequence diagram.
  11. Hover the mouse over the line on the right side of the Check OS sequence.

    A + character inside a diamond shape appears.
  12. Click the + character.

    The Insert Rule panel opens on the right.
  13. In the Name text box, type the mobile device of your preference.

    For example:

    iPhone

  14. In the large text box below the Name field, enter the string you would like FirePass to inspect. For example, to inspect the user's browser to see if it contains iPhone, iPad or iPod, you would type the following:

    CONTAINS(session.browser.user_agent, "iPhone") OR CONTAINS(session.browser.user_agent, "iPad") OR CONTAINS(session.browser.user_agent, "iPod")

    Note: This step uses the CONTAINS function, which is available starting in FirePass version 7.0.0. The CONTAINS keyword is case sensitive and should be entered all uppercase, as shown above. 

  15. Click the Update button.

    The rule you just created appears in the diagram. For example, a branch named iPhone appears.

Creating a custom variable

  1. Hover the mouse over the line on the right side of the branch you just created. For example, the iPhone branch.

    A + character appears on the line.
  2. Click the + character.

    The Change Sequence panel opens on the right.
  3. From the Using drop-down menu, select New action.
  4. Click the Apply Changes button.
  5. In the Name field, type a name for the new action.

    For example:

    Set iPhone

  6. Click the Update details button.

    The action you just created appears in your sequence diagram.
  7. From the Add new inspector drop-down menu, select Define custom variable.
  8. Click the Add inspector button.

    A new section named Inspectors displays in the edit action panel.
  9. Click the Define custom variable link under the Name column.

    A new browser window opens.
  10. In the Expression text box, type an expression that creates a session variable.

    Note: This expression will be used in Step 9 of the Configuring the dynamic group mapping procedure.

    For example:

    isiphone=1

  11. Click the Update button.
  12. At the end of the fallback branch, following the Set iPhone action, click the Logon Denied Page link.

    The Type panel appears on the right.
  13. Select Logon Allowed Page from the drop-down menu.
  14. Click the Update button.
  15. Click Back to Console in the upper right corner.

Activating the pre-logon sequence

Important: Do not apply the new pre-logon sequence on a production system without testing. This will activate immediately upon clicking Apply.

  1. Click the pre-logon sequence that you created above.

    For example:

    MobileCheck

  2. Click the Mobile Check option button.
  3. Click the Apply button.

Creating a resource group to assign resources to the mobile device

  1. Log in to the FirePass Administrative Console.
  2. Navigate to Users : Groups : Resource Groups.
  3. Click the Create new group button.
  4. In the New group name text box, type the name of the resource group.

    For example:

    iPhone_resources

  5. Click the Create button.
  6. In the Portal Access column of the row of the resource group you just created (for example: iPhone_resources), click the Edit link.

    You are taken to the Portal Access : Web Applications : Resources page.
  7. Click the Add New Favorite link.
  8. In the Name text box, type the name of a favorite that you want the mobile device user to access.

    For example:

    F5

  9. In the URL text box, type the URL of the favorite.

    For example:

    http://www.f5.com

  10. Click the Add to allow list link.

    The URL is added to the Allow list.
  11. Click the Add New button.

Configuring the dynamic group mapping

  1. Log in to the FirePass Administrative Console.
  2. Navigate to Users : Groups : Dynamic Group Mapping.
  3. Select the Determine the user's master group dynamically using the master group mapping table check box.
  4. Click the Group mapping methods tab.
  5. Select Session Variable from the drop-down menu.
  6. Click the Add mapping method button.
  7. Click the Master group mapping table tab.
  8. From the Mapping Method drop-down menu, select Session Variable.
  9. Click the Add button.
  10. In the Session Variable text box, type the variable that was created during the pre-logon sequence inspection. For example, if the pre-logon sequence set the variable isiphone=1, you would type the following session variable:

    %session.userdef.isiphone%

  11. In the Value text box, type the value that you configured in Step 10 in the Creating a custom variable procedure. For example, if you used isiphone=1 you would type the following:

    1

  12. From the FirePass Group drop-down menu, select the name of the dynamic master group.

    For example:

    iPhone_Users

  13. Click Add.

Configuring the dynamic master group

This procedure helps you create a master group that iPhone users will map to. We use local authentication for this example. Select the proper authentication type for your environment.

  1. Navigate to Users : Groups : Master Groups.
  2. Click the Create new group button.
  3. In the New group name field, type the name of the group you want to create.

    For example:

    iPhone_Users

  4. Click the Create button.

    You are taken to the master group configuration for the group you just created.
  5. Select the Allow users to be assigned to this master group using dynamic master group mapping check box.
  6. Click the Update button.
  7. Click the Resource Groups tab.
  8. From the Available list, click the resource group you just created.

    For example:

    iPhone_resources

  9. Click the Add > button.
  10. Click the Update button.
