Summary

The Enterprise Manager may experience MySQL database corruption under certain conditions.

Description

The Enterprise Manager may experience MySQL database corruption under conditions that are similar to the following:

  • The Statistics Data Collection feature is enabled and the Enterprise Manager experiences a loss of power to the unit.
  • The MySQL database is accessed by a different version of Enterprise Manager than the version that generated the database. For example, during an Enterprise Manager software upgrade, the database schemas are updated and are not guaranteed to be compatible with previous versions of Enterprise Manager.

If data corruption occurs, statistics are unavailable and an error message that appears similar to the following example is logged to the /var/log/em file:

emstatsd[3309]: 0402010e:3: EX! StatLoader.cpp:1092::flush:mysqlpp::BadQuery 'Table'./f5em_extern/perfmon_pool_stat' is marked as crashed and should be repaired'

If an error that appears similar to the following example occurs in the /var/log/em file, before attempting a repair, verify that the Enterprise Manager is loaded into the release that generated the database:

emstatsd err [15060]: 040a0100: 3: Could not initialize EM daemon stats: Wrong version of db stats January 25 3:29:48 p.m. local/GSC-MEM4F5-RECN emstatsd err [15105]: 040a0102: 3: The stats Has an incorrect database version (2.3.0.4 expecting, but got 3.0.0.2). Restarting in 15 seconds.

In addition, an error message that appears similar to the following example may appear on the command line:

emerg logger: Re-starting emstatsd

Recommendations

You may be able to repair the MySQL database corruption using one of the following procedures. 

Note: If the repair procedures do not resolve the MySQL database corruption, you may have to rebuild the Enterprise Manager system's databases. For information on how to wipe the MySQL databases and rebuild them, refer to K14226: Performing a wipe of the Enterprise Manager MySQL databases.

Correcting MySQL database corruption on Enterprise Manager 2.0.0 and later

Impact of procedure: None

  1. Log in to the Enterprise Manager command line.
  2. To correct the MySQL corruption, type the following command:

    em-repair-extern

  3. Check the /var/log/em log for additional error messages that refer to table corruption. If the error messages persist, repeat step 2.

Correcting MySQL table corruption on Enterprise Manager 1.7.0 through 1.8.0

Impact of procedure: None

  1. Log in to the Enterprise Manager command line.
  2. To stop the emstatsd process, type the following command:

    bigstart stop emstatsd

  3. To export the MYISAMDIR variable, type the following command:

    export MYISAMDIR=/var/lib/mysql/f5em_extern

  4. To repair the corruption, type the following command:

    myisamchk --silent --force --fast --update-state --key_buffer_size=96M --sort_buffer_size=64M --read_buffer_size=1M --write_buffer_size=1M --tmpdir=/shared/em ${MYISAMDIR}/*.MYI

  5. To restart the emstatsd process, type the following command:

    bigstart start emstatsd

  6. Reboot the system by typing the following command:

    reboot

  7. Check the /var/log/em log for any additional error messages that refer to table corruption. If the error messages persist, repeat steps 1 through 6.?
