Known Issue

Remote syslog entries may use malformed time stamp values.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured for remote syslog logging.
  • The destination remote syslog server is configured for Syslog Format Syslog (RFC5424).
  • The system logs an entry when the BIG-IP system clock rolls over to exactly 1,000,000 microseconds.

Impact

The remote syslog time stamp syntax is malformed.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You view the remote log, and the time stamp for 1,000,000 microseconds contains an additional NULL character.

    For example:

    2003-08-24T05:14:14.100000\00-07:00

  • Your remote log server fails to parse the log message or flags the log entry with a format warning.
  • When you view the logged time stamp, the value of the timestamp is truncated and the exact second is logged as the previous second plus 1,000,000 microseconds.

    For example:

    The time value of exactly 30 seconds is logged as a truncated value of 29 seconds and 1,000,000 microseconds.

    Expected time value: 14:16:30.000000

    Actual time value produced: 14:16:29:100000

Workaround

To work around this issue, you can configure remote syslog logging to use Syslog Format BSD Syslog (RFC3164). To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To modify the remote syslog configuration, use the following command syntax:

    modify /sys log-config destination remote-syslog <remote syslog configuration name> format rfc3164

  3. To save the configuration change, type the following command:

    save /sys config partitions all
