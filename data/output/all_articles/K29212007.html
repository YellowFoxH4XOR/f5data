Environment

  • BIG-IQ Data Collection Cluster
  • Previously experianced issues with filling /var partition, resolved by removing indices or extending /var on DCDs
  • Aggregation not work as expected
  • Yellow status of DCD nodes (System > BIG-IQ Data Collection > BIG-IQ Data Collection Devices) - Statistics overflow protection detected

Cause

Chain of events can cause full /var which will cause corruption of retention and move database to read-only state ID1055153: Elasticsearch cluster goes into read-only if disk space runs low

Recommended Actions

Follow procedure to move Elasticsearch DB to read-write and fix stats overflow and retention issue:

  1. Verify available disk space on DCD nodes: using following command from BIG-IQ CM node:
    curl -s -u admin:admin --insecure https://localhost:9200/_cat/allocation?v
    shards disk.indices disk.used disk.avail disk.total disk.percent host ip node
    1115 14.5gb 21.2gb 77gb 98.3gb 21 10.1.1.1 10.1.1.1 4be404d8-84a2-4c1d-aab6-1e31f3f76bd8
    1115 16.7gb 23.7gb 74.5gb 98.3gb 24 10.1.1.1 10.1.1.1 799f7ec0-d2d6-4c81-8f0d-ba675eed16fd
    1115 14.7gb 21.4gb 76.8gb 98.3gb 21 10.1.1.1 10.1.1.1 4e989ce4-7188-435f-b523-fdc87c79c1b7
    Note: If output shows disk.percent less than 95% proceed with further steps. If is showing more extend disk space according to K58621633: Extending disk space on a BIG-IQ Virtual Edition
  2. Remove read-only state based on workaround provided in ID1055153: Elasticsearch cluster goes into read-only if disk space runs low
    for idx in $(curl -ks https://localhost:9200/_cat/indices | awk '{print $3}'); do if [ $idx != ".opendistro_security" ]; then curl -k -u admin:admin -X PUT "https://localhost:9200/$(echo $(echo $idx | cut -d\+ -f1)*)/_settings?pretty" -H 'Content-Type: application/json' -d'{"index.blocks.read_only_allow_delete": false}'; fi; done
  3. Identify all groups of indices which are causing stats overflow protection issue by reviewing /var/log/appiq/agentmanager.log on DCD box
    Example:
    The number of 'statistics_tl0_default-group\*' indexes , 20, is above [retention(10) + high_watermark(8)]. \*\*\*\*\* Any of those new Statistics will not be written to ElasticSearch - Please Check if the appiqconfigserver or appiqpostaggregator are OK and running at the BIG-IQ CM or check what is the root cause for this accumulation of the indexes \*\*\*\*\*
    You can use following command to list all indices causing this issue :
    egrep -ir overflow \* |awk -F 'of|indexes' '{print $2}' |sort |uniq -c |sort -nr
  4. Remove indices causing this issue using following command on CM node:
    curl -kv -X DELETE "https://localhost:9200/<indexname>"
    Example:
    curl -kv -X DELETE "https://localhost:9200/statistics_tl0_default-group\*"
  5. Repeat step 4 for all indices causing overflow issue
  6. Cleanup corrupted retention settings
    curl localhost:9200/meta\*/ -X DELETE ; sleep 5 ; bigstart restart appiqconfig ;
  7. Reconfigure retention based on customers requirements (System > BIG-IQ Data Collection > BIG-IQ Data Collection Cluster > Configuration > Statistics Data Collection > Configure retention and System > BIG-IQ Data Collection > BIG-IQ Data Collection Cluster > Configuration > Logging Data Collection)
  8. Verify if fresh statistics are visible in Monitoring section
