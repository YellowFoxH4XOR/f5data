Topic

This article applies to BIG-IP 12.x through 17.x. For information about other versions, refer to the following article:

  • K10328: Forcing a file system check on the next system restart (10.x - 11.x)

You should consider using this procedure under the following condition:

  • You want to schedule a file system check on the BIG-IP system during the next system restart.

Description

The fsck utility can scan the file system for errors and correct those errors if possible. File systems must be unmounted to correct errors. Performing a file system check using the fsck utility can be a tedious, manual process that requires the user to restart the system to a minimal run level and then issue a fsck operation on each file system listed in the /etc/mtab file. This manual method requires direct access to the system to access and run the fsck utility. Additionally, even if the system boots to a minimal run level (single-user mode), the system may not be able to release some file systems to manually perform a file system check using the fsck utility directly.

A more convenient file system check method is to force a file system check on the next system restart. This method removes the tedious manual process and allows the system to reliably check all of the available file systems.

Important: F5 recommends that you have direct access to the system during a forcefsck so that you can observe any errors or information that may be reported during the fsck process. While this method removes the manual process of specifying the various file systems, the system restarts into a minimal run level to perform the necessary tasks.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have serial console access to the BIG-IP system.
  • You have administrative or root user access to the command line.

Procedures

Create a forcefsck file in the root directory

This procedure allows you to schedule a file system check during the next restart of the system by creating a blank file, named forcefsck, that resides in the / directory. The presence of the /forcefsck file causes the system to perform a file system check the next time the system boots. To do so, perform the following procedure:

Impact of procedure: Restarting the BIG-IP system in a standalone configuration will interrupt traffic processing. If the system is configured as part of a high-availability (HA) pair, the device may fail over. F5 recommends that you perform this procedure during a maintenance window.

  1. Log in to the command line.
  2. To create the /forcefsck file, enter the following command:

    touch /forcefsck

    During the next restart, the /forcefsck file causes the system to perform a file system check.

  3. If you want to restart the system at this time, enter the following command:

    reboot

    The system restarts and performs the fsck file system check. After the fsck operation has finished checking the file systems, the system continues to boot normally into the proper run levels.

    Note: The /forcefsck file is deleted as the system boots and does not remain for subsequent restarts.
