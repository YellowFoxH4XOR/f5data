Topic

Note: Beginning in BIG-IP 10.1.0, the BIG-IP 6900 and 8900 platforms utilize a RAID configuration. For more information refer to K10856: Overview of hard drive mirroring.

Introduced in BIG-IP 10.0.1, the sparedisk utility allows an administrator to take advantage of the unused secondary hard drive on the BIG-IP 6900 and 8900 platforms, to create a backup of the primary hard drive. The sparedisk utility works by designating the secondary hard drive as a spare and then making an exact copy of the primary hard drive.

A spare backup drive allows the administrator to minimize down time in the event the primary drive fails by allowing the administrator to swap the primary drive for the spare drive.

Important: The sparedisk utility and the spare disk created are not intended to be used on a daily basis for backup purposes. The utility requires the administrator to reboot the system into the TMOS Maintenance OS (MOS), which requires console access and prevents the system from handling traffic.

Note: Swapping the hard drives is not automatic and requires manual intervention to physically power down the system and remove the primary hard drive and move the secondary or spare hard drive into the primary hard drives slot.

Note: This utility can only be used on licensed BIG-IP LTM, GTM, or ASM systems. It cannot be used on system licensed for BIG-IP WebAccelerator or WAN Optimization, as they use the secondary hard drive for caching purposes.

Note: For information about replacing a failed or failing disk refer to the Installation Guide for 6900 and 8900 Hard Drives.

Creating a spare or backup of the primary disk using the sparedisk utility

Important: The sparedisk utility can only be used on BIG-IP 10.0.1 using the Logical Volume Management (LVM) disk-formatting scheme and not the partitioned disk-formatting scheme. For more information regarding LVM or volumes, refer to the BIG-IP Systems: Getting Started Guide.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Important: You must be running BIG-IP version 10.0.1 in order to use the sparedisk utility. Previous versions do not contain the sparedisk utility.

Important: You must have direct console access to the unit in order to perform some of the procedures as they require rebooting the system into the MOS, which does not allow remote network access.

To create a spare or backup of the primary disk using the sparedisk utility, you must perform the following three procedures:

  • Booting into the Maintenance Operating System
  • Creating the spare disk drive
  • Verifying the spare disk was created

Booting into the Maintenance Operating System

Important: The following procedure will reboot the system into the MOS. F5 recommends that you perform this procedure on the standby unit or failover before continuing. If this is a stand alone system, perform the following procedure during a maintenance window.

   1. Connect to the console and log in to the system using the root user and password.

   2. Reboot into MOS using the following command:

      mosreboot

      The system will reboot into MOS (TMOS Maintenance in the boot screen), which runs in the RAM memory.

Creating the spare disk drive

  1. Create a spare disk using the following command:

    sparedisk

    The utility will report a warning that all data on the disk HD2 will be destroyed.
     
  2. Type y to continue.

    While the sparedisk utility is creating the spare disk, output will appear similar to the following example:

    info: Initializing spare disk; sdb
    info: Initializing partition table on disk: sdb
    info: Adding boot volume to disk: sdb
    info: adding sdb.dat.boot...
    info: adding sdb.dat.dbvg...
    info: Marking spare disk; sdb
    info: Installing boot loader...
    info: Copying boot volume...
    info: Creating volume sdb.app.ASWADB.set.3.mysqldb
    info: Copying volume sda.app.ASWADB.set.3.mysqldb to sdb.app.ASWADB.set.3.mysqldb
    info: Creating volume sdb.dat.log
    info: Copying volume sda.dat.log to sdb.dat.log
    info: Creating volume sdb.dat.share

Note: If you see any errors saying that neither disk is marked as a spare, or that both disks are marked as spares, contact F5 Technical Support.

Verifying the spare disk was created

  1. Run the following command to identify and verify the spare disk:

    sparedisk --query

    Output will appear similar to the following example:

    bash (try 'info') / >sparedisk --query
    info: Skipping HD1; it is not a spare.
    info: Checking spare disk HD2                <--- Spare disk identifier
    Found product: BIG-IP 10.0.1 build 283.0
    Filesystem created:       Mon Aug 24 21:45:21 2009

Note: If neither disk is marked as a spare, contact F5 Technical Support.

After the sparedisk utility has completed, reboot the system using the reboot command to return the system to the normal operating system.
