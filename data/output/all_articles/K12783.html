K12783: Users may experience delays when the primary DNS resolver of the FirePass is unavailable

Topic

Users may experience delays in authentication or accessing various resources that require FirePass to resolve the fully qualified domain name (FQDN) for the resource if the DNS resolver that has been configured in the Name server 0 field on the Device Management: Configuration: Network Configuration : DNS tab is unable to provide resolution for FirePass (the DNS server is offline or FirePass does not have a network path to the DNS server). In some cases, this delay may result in the user being unable to authenticate. For example, if a user attempts to authenticate using two factor RSA, the RSA token may expire between the time the user submits their credentials and the time the FirePass is able to resolve the FQDN for the RSA server.

This delay occurs because FirePass will wait five seconds before it attempts to make the DNS query a second time. Additionally, FirePass will attempt to query the same DNS server four times before it will send a DNS query to the next DNS resolver listed on the DNS tab. This means that the users could experience a delay of 25 seconds before a new DNS resolver is queried if the primary DNS server is unresponsive. FirePass is configured to behave in this manner to prevent creating a DNS query storm and potentially taxing the DNS server's recursive query limits.

If your users are reporting delays during login or delays in accessing resources through FirePass, you should confirm that the FirePass DNS resolvers are able to provide resolution for FirePass. If you can confirm that resolution is the root of the delay problem, enter the IP address of a known good DNS server into the Name server 0 field. If you do not have access to a DNS server that can consistently respond to the first query attempt, contact F5 Technical Support to request assistance to lower the timeout and retry thresholds so the FirePass will cycle through the failed DNS queries faster.
