K000151246: TAR UC Web Favicon Unable To Load

Type
Support Solution
Published
2025-05-09

2025-05-09
Applies to

  • BIG-IP ASM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000151246

Description

When a Bot Defense profile is applied on BIG-IP ASM, users accessing a web portal via Chrome may encounter an issue where the website favicon does not load. The favicon loads correctly in other browsers such as Firefox and Edge. No related errors are logged in the ASM Security Event Logs or Bot defense, but browser console errors may appear in Chrome when the Bot Defense profile is active.

Environment

  • Bot Defense
  • Chrome (favicon not loading), Firefox/Edge (favicon loads as expected)

Cause

The default behavior of the Bot Defense profile injects JavaScript immediately after the <head> tag in the HTML. If the favicon link appears after this injected script, Chrome may fail to request or display the favicon because it does not process links that follow injected scripts in certain scenarios.

Recommended Actions

To resolve this issue, adjust the injection point of the Bot Defense JavaScript so that it is inserted before the </head> tag. This ensures that all head elements, including favicon links, are processed correctly by Chrome.

Steps to implement on BIG-IP:

1. List the current value of the database key:

  # tmsh list sys db dosl7.parse_html_inject_tags all-properties

2. Modify the value to inject before </head>:

  # tmsh modify sys db dosl7.parse_html_inject_tags value "before,/head"

3. Save your configuration to ensure persistence across reboots.

  # tmsh save sys config
