K28358628: Configsync to a remote device fails validation with 01b40026:3: Configuration error

Description
Sync Failed with error:
A validation error occurred while syncing to a remote device

Sync error on ASM1.example.com: Load failed from /Common/ASM2.example.com 01b40026:3: Configuration error: Virtual server (/Common/my_virtual_server) with TMC or security ACL/NAT/IPI/DoS/Eviction/Scrubber/Blacklist Publisher configured cannot co-exist between them.

Environment

  • BIG-IP ASM 14.x
  • Virtual server with security logging profile
  • Virtual server uses a source address list Shared Object as traffic matching criteria

Cause
Bug ID 761234

In version 14.1, using an address list on a virtual server with a security logging profile is not supported and there is a validation check that should prevent this. This check is stopping the invalid config from loading during the sync as expected. However, this bug allows you to circumvent the validation check sometimes even though the configuration is invalid.

Recommended Actions

Upgrade to BIG-IP version 15+ where this configuration is allowed via a DB key change. There is no workaround for this issue in version 14. Either remove the address list from the virtual server or the security log profile before ConfigSync.

In 15+ this is the DB key change that is required to allow this:

  tmsh modify sys db afm.allowtmcvirtuals value true

Important: Use of TMC virtual servers with ASM/AWAF is not fully supported at this time, so enabling afm.allowtmcvirtuals should be considered experimental.

Note: If this is changed back to false while a virtual server is using an address list the configuration will get an error if it is reloaded.
