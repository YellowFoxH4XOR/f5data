Topic

The Portal Access reverse-proxy engine rewrites HTML code, JavaScript code, and Java applets to ensure that all Portal Access content is proxied through the FirePass controller. In some instances, the changes made by the reverse-proxy engine may cause certain web applications and scripts to function incorrectly. In these cases, you may want to configure a Web Applications content processing script to change the processed page content to resolve the issue. In other instances, you may want to configure a Web Applications content processing script to change the web page content for other reasons, such as removing proprietary data.

Note: If configuring a content processing script does not resolve the issue, you can configure Minimal Content-Rewriting Bypass for the affected sites. For more information, refer to K4746: Overview of the Minimal Content-Rewriting Bypass feature.
 
Note: Web Applications content processing scripts are also referred to as sed scripts, since they use the Unix sed utility.
 
Before configuring a content processing script, it is helpful to know exactly what changes the reverse-proxy engine has made to the affected web pages. For each page, perform a Web Applications engine trace to see the source content both before and after processing.

Note: For more information, refer to K4879: Overview of the Web Applications engine trace feature.
 
Content processing scripts are configured on the Portal Access: Web Applications: Content Processing page under the Pre-processing Scripts tab. To create a new content processing script, select Add New Favorite in the Web Applications Content Processing Scripts section and then configure the following fields:

Note: Multiple web application content processing scripts can be configured. The FirePass controller will use the first script that matches the url and content type of the web page. 

  • Processing script name

    Enter a unique name for the content processing script.

    For example:

    Webmail-Script
  • URL match patterns

    Enter a comma-separated list of URLs or URL patterns. If the URL requested by the user matches one of the URLs or patterns in this field, FirePass applies the content processing script to the web page content. You can use wildcard characters such as the asterisk ( * ) or question mark ( ? ).

    For example:

    http://webmail.example.com/*, https://webmail.example.com/*, https://???.mail.example.com/*

    Alternately, you can enter a single asterisk character to permit FirePass to apply the script to all URLs. An empty list indicates that the script processed no URLs.
  • Content Type

    Enter the content type match pattern. This pattern matches against the Content-Type header in the HTTP request.

    For example:

    text/html

    If no value is entered, the content type pattern is set to text/*.
     
  • Sed processing script

    Enter the sed command(s) to run on the page content.

    Note: For more information and examples, refer to the following Sed processing script examples section.
  • Processing

    Select whether to run the sed command before or after the reverse-proxy engine rewrites the page content. In most cases, you want the sed command run after content patching. Additionally, you can select the Process request data option to modify the request data from a user before it is sent to the website.

    In failover pair (high availability) and cluster configurations, content processing scripts are synchronized between members of the failover pair or cluster.

Replacing text
 
The most common use of the sed command is the search and replace function, which uses the following format:  

s/OldText/NewText/
 
For example, if a web page contains the following HTML code prior to processing, the example sed command replaces all instances of the string OldText with the string NewText:
 
<TABLE>
<TR><TD>……</TD></TR>
<TR><TD>……</TD></TR>
<TR><TD>OldText</TD></TR>
<TR><TD>……</TD></TR>
</TABLE>

The script rewrites the HTML code in the HTTP response that appears similar to the following example:
 
<TABLE>
<TR><TD>……</TD></TR>
<TR><TD>……</TD></TR>
<TR><TD>NewText</TD></TR>
<TR><TD>……</TD></TR>
</TABLE>
 
Deleting text
 
You can use the search and replace function to delete text by not specifying any replacement text. For example, you can delete the string SomeText from the page content by entering the following sed command:
 
s/SomeText//
 
Inserting text
 
You can insert text by specifying a string to search for, then entering the search string in addition to text you want to insert. For example, to insert the text BGCOLOR=FFFFFF within the <BODY> tag, enter the following sed command:
 
s/<BODY/<BODY BGCOLOR=FFFFFF/ 

Case sensitivity
 
By default, sed scripts are case-sensitive.

For example:
 
s/OldText/NewText/
 
If you configured the previous sed command, the string oldtext would not be replaced since it is lowercase. You can make a sed script case-insensitive by adding the character i at the end of the script.

For example:
 
s/OldText/NewText/i

Note: FirePass version 5.5 does not support the i switch for sed. If you are running FirePass version 5.5, you need to add an additional line to the original script to replace both OldText and oldtext with NewText.

For example:

s/OldText/NewText/
s/oldtext/NewText/

Disabling a sed command
 
If you want to temporarily disable a sed command, enter the hash ( # ) character at the beginning of the script.

For example:
 
#s/SomeText//
 
This action can be useful when you want to disable a sed command for testing purposes without deleting the command.
 
Special characters
 
Special characters must be escaped using the backslash ( \ ) character. For example, the forward slash ( / ) character is a special character, since it is used as a delimiter within the sed command. To replace http://www1.example.com with http://www2.example.com, enter the following sed command:
 
s/http:\/\/www1.example.com/http:\/\/www2.example.com/
 
Configuring multiple sed commands within a single content processing script
 
You can enter multiple sed commands in the Sed processing script field, but you must enter only one command per line.

For example:
 
s/OldText/NewText/
s/One two three/One two three four/
s/BadWord//
