Description

BIG-IP is logging these or similar warning messages in the /var/log/ltm when the TLS connection is closed with the description User Canceled. 

Jul 16 13:30:51 bigip.local warning tmm[22337]: 01260009:4: 10.0.0.1:44356 -> 10.0.0.2:636: Connection error: ssl_codec_rx:2339: alert(90) received alert

Where the 172.16.181.99 is the client IP and 172.16.116.150 is the virtual server IP. In Wireshark, it looks like this:

172.16.181.99   10.0.0.2  IN  s1/tmm : Alert (Level: Warning, Description: User Canceled), Alert (Level: Warning, Description: Close Notify)
172.16.116.150  10.0.0.1   OUT s1/tmm : Alert (Level: Warning, Description: User Canceled)

Environment

  • Virtual server configured with client SSL profile.
  • Client wants to gracefully close TLS channel.

Cause

Client sends Close Notify along with User Canceled in description.

Recommended Actions

  1. Check if there are any issues with the service hosted by the virtual server. If there are, then it needs to be investigated further.
  2. If there are no issues, you may see if it is possible to stop the client from sending such Close Notify message or filter these messages out in ltm log file by following K35284961.

Additional Information

As per https://datatracker.ietf.org/doc/html/rfc8446#section-6.1

user_canceled:  This alert notifies the recipient that the sender is
      canceling the handshake for some reason unrelated to a protocol
      failure.  If a user cancels an operation after the handshake is
      complete, just closing the connection by sending a "close_notify"
      is more appropriate.  This alert SHOULD be followed by a
      "close_notify".  This alert generally has AlertLevel=warning.
