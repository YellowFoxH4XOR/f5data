Overview

Note: F5 has changed the name F5 Container Connector to F5 Container Ingress Services.

The software lifecycle support policy for F5 Container Ingress Services defines the stages of the software lifecycle from initial release through retirement. The intent of this policy is to provide consistent documentation that helps customers plan and prepare for their organization's support needs. For policies regarding products and software versions that have passed their End of Sale date, refer to their respective AskF5 articles.

F5 Container Ingress Services software uses a three-digit software version schema. The three-digit release structure provides delineation between the magnitudes of product releases; it allows customers to select where in a release cycle they would deploy a version of software.

Version schema definitions

F5 Container Ingress Services uses semantic versioning, a three-digit software version schema, in the syntax of MAJOR.MINOR.PATCH.

The definitions for the version schema are as follows:

  • Major release: Major releases may include significant changes in behavior, significant new functionality, significant performance changes, significant API changes, and/or significant architectural changes. The key factor in determining a major version is when the new version has incompatible API changes.
  • Minor release: A minor release includes new product features and functionality as well as fixes for product errors or bugs. The key factor in determining a minor version is when the new version has API changes that do not break backwards compatibility.
  • Patch release: A patch release includes only bug and security fixes. No new functionality or changes in behavior are introduced.
  • Pre-release: A pre-release version (optional) indicates that the version is unstable and might not satisfy the intended compatibility requirements as denoted by the version number. Using this tag, we may choose to release alpha versions that would be built from the top of our current development branch at the end of every 2-week sprint cycle. An example version in this case would be 1.2.3-alpha.1, which is earlier than 1.2.3-alpha.2.

Using this notation, the BIG-IP controller for Mesos+Marathon environments versioned 1.0.0 would be called marathon-bigip-ctlr:1.0.0.

Support phase

The support phase for an existing version of F5 Container Ingress Services begins with the Release To Web (RTW) date of the next major product release, and ends at the End of Tech Support (EoTS) date. The support phase is characterized by the introduction of new backwards-compatible features, software fixes (including security updates), and stability improvements, delivered through minor and patch releases.
