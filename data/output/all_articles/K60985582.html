Known Issue

In rare circumstances, the bd process may produce a core file.

This issue occurs when the following condition is met:

  • The BIG-IP ASM ecard_max_http_req_uri_len internal parameter is set to a value greater than 8 KB.

Impact

The issue may temporarily disrupt traffic, and the system may fail over to another system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You may observe a bd core file in the /var/core directory with a date and time stamp that matches the failover event.

Workaround

To work around this issue, you can change the value of ecard_max_http_req_uri_len to a value smaller than 8 KB. To do so, perform the following procedure:

Impact of workaround: If you modify an internal parameter value, you must restart the BIG-IP ASM service, resulting in a brief traffic disruption.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Application Security > Options > Advanced Configuration.
  3. Enter the value you want for the ecard_max_http_req_uri_len parameter.
  4. Click Save.
  5. Log in to the command line.
  6. Restart the BIG-IP ASM service by typing the following command:

    Important: Restarting the asm process causes a brief traffic disruption.

    bigstart restart asm
