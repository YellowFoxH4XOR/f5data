Issue

Error Message

err websso.0[<PID>]: 014d0005:3: Kerberos: can't get S4U2Proxy ticket for server <service_class>/<domain>@<realm> - KDC can't fulfill requested option (-1765328371)

In this error message, not the following:

  • <PID> is the process ID for the websso process.
  • <service_class> is the protocol for the requested service.
  • <domain> is the fully qualified domain name for the service.
  • <realm> is the realm where the service is registered.

For example:

err websso.0[2389]: 014d0005:3: Kerberos: can't get S4U2Proxy ticket for server HTTP/autodiscover.example.com@example.COM - KDC can't fulfill requested option (-1765328371)

Message Location

You may encounter this message in the following location:

  • The /var/log/apm file
Description

This message occurs when all of the following conditions are met:

  • You configure Kerberos Constrained Delegation as a single sign-on (SSO) method in the access policy on the BIG-IP APM system.
  • Either of the following two conditions are present:
    • The delegation account configured in Active Directory is missing the service for which the BIG-IP APM system is attempting to obtain a ticket on behalf of the user (S4UProxy).
    • The server providing the Kerberos key distribution center (KDC) service, typically not a Windows server, does not support the same options as Microsoft Active Directory.

When this message occurs, packet captures of the Kerberos communication between the BIG-IP APM system and the KDC shows errors similar to the following example:

KRB5 887 OUT s1/tmm0 : TGS-REQ
KRB5 296 IN s1/tmm0 : KRB Error: KRB5KDC_ERR_BADOPTION NT Status: STATUS_NO_MATCH

Impact

The BIG-IP APM system is unable to obtain a Kerberos service ticket on behalf of the user and Kerberos SSO fails for the user. 

Recommended Actions

When this messages occurs, consider the following:

  • In the Active Directory delegation account (Account Properties > Delegation), add the requested service to the Services to which this account can present delegated credentials box.
  • When using a non-Windows Kerberos KDC environment, ensure that the KDC can support the same options as Active Directory.
