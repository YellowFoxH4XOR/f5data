K14711183: LDAPS Monitor failing after installing new certificate on AD server

Description

LDAPS monitor is failing after installing local CA signed certificate to the AD servers.

  • Though the node is up and with valid certificate, it is being marked down by BIG-IP.
  • tcpdump of the monitor probes show that BIG-IP is terminating the connection with
    "TLSv1.2 Record Layer: Alert (Level: Fatal, Description: Certificate Unknown)"

Environment

  • BIG-IP
  • Active Directory (AD) based domain controller connections are the nodes.
  • LDAP Monitors 

Cause

This can happen if the new certificate doesn't have the required critical key usage methods allowed. The Digital Signature and Key Encipherment critical key usage must be allowed in the certificate for the LDAP monitor to accept the certificate. Get a new certificate which has Digital Signature and Key Encipherment critical key usage allowed.

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. Validate that the issue is caused due to lack of critical key usage methods. The command below will show us why the certificate isn't being accepted.
    # ldapwhoami -vvv -H ldaps://<LDAP_HOSTNAME:PORT> -D "<USER_NAME>" -d 255 -w "<PASSWORD>"
     
  2. If the certificate doesn't have the necessary key usage methods, the output of previous command will have something like below:
    TLS: can't connect: TLS error -8102:Certificate key usage inadequate for attempted operation.
     
  3. It can be further validated using the open SSL command below:
    # openssl x509 -in <old_certificate.crt/new_certificate.crt> -purpose -noout -text
     
  4. In the output of the above command, the X509v3 Key Usage: critical section should have at least Digital Signature and Key Encipherment.
