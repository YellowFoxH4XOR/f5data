Known Issue

Note: By default, the BIG-IP WebAccelerator does not encrypt cookies which are set by the OWS. However, for an added level of protection, it is possible to configure the BIG-IP WebAccelerator to encrypt cookies which are set by the OWS. For more information, refer to the Changing cookie encryption parameters section of the Configuration Guide for the BIG-IP WebAccelerator System.

This is the result of a known issue. If the BIG-IP WebAccelerator is configured to encrypt a cookie which is set by the OWS, and the unencrypted cookie value contains a dash (-), the BIG-IP WebAccelerator will strip the cookie from later client requests.

For example:

  • The BIG-IP WebAccelerator is configured to encrypt the session cookie.
  • In one of its replies, the OWS sets the session cookie as shown below:

    Set-Cookie: session=12345-A
  • The BIG-IP WebAccelerator encrypts the cookie before replying to the client. The encrypted cookie is shown below:

    Set-Cookie: session=NFXme6LBUNeHWvzXbTjy0ECHsyzsE6sFMKVWa/sLkwckafNM7gEX+fUCT2RG4mzG
  • In a later request, the client includes the session cookie; however, the BIG-IP WebAccelerator fails to decrypt it and strips it from the request before the request is sent to the OWS.

Because the OWS does not receive the cookie that it had previously handed to the client, the application may fail to maintain a stateful session with the client.

When this issue occurs, an error message that appears similar to the following example may be logged to the /var/log/wa/pvac.log file:

Invalid cookie found and removed.  Will proxy.  Cookie name: session

Note: The error message listed above does not appear in version 10.x with normal pvac logging. If you suspect a version 10.x system is encountering this issue, enable extra HTTP debugging by typing the following command at the BIG-IP WebAccelerator command line:

setDebugZone ZONE_HTTP.verbose

Since verbose logging generates large volumes of extra debugging information and may temporarily degrade system performance, F5 recommends that you perform such testing during a scheduled maintenance window, and restore normal log levels when testing is complete.

F5 Product Development tracked this issue as ID 328313, ID 324333, ID 247982, ID 225835, and ID 330822 (formerly CR140278), and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

This issue has also been fixed in Hotfix-BIGIP-9.4.8-407.0-HF4, which has been issued for BIG-IP version 9.4.8, BIGIP-10.1.0-3402.0-HF2 which has been issued for BIG-IP version 10.1.0, and Hotfix-BIGIP-10.2.0-1755.1-HF1 which has been issued for version 10.2.0. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by not enabling encryption for applications whose cookie values may include the dash character.
