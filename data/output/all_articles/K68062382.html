Issue

Old Behavior

In versions prior to BIG-IP 13.0.0, if the minimum-threshold is set to a non-zero value, only the component score for that individual component is set to 0 (zero) if the threshold is not met. The total high availability (HA) group score is the sum of the component scores.

New Behavior

Beginning in BIG-IP 13.0.0, if fewer than the minimum-threshold of objects within a component are available, then both the monitored component score and the total HA group score are set to 0.

For an HA group to prevent a traffic group from failing over, all of the resource types that you specify in an HA group must meet the defined minimum thresholds for availability.

For example:

If your configuration contains an HA group with associated components such as trunks, pools, or cluster members, and you set a minimum-threshold setting of any of those components to value N: 

  • The number of available members in a pool is at least N.
  • The number of connected links in a trunk is at least N.
  • The number of available blades in a chassis is at least N.

If all of the health checks pass, the traffic group continues to run on current device. Otherwise, it fails over.

The minimum-threshold setting of any of the available members is non-zero, with a non-zero number of members, or if a component value is 0 because it has no members but also has a minimum-threshold equal to 0, then the group is summed normally.

Note:  This behavior only applies if minimum-threshold is set to a value greater than the default value, 0.

New HA status entries in the following table are introduced for this change.

HA StatusStatusExplanation
DegradedActiveAn active unit is processing traffic, but the HA Group monitor fault condition exists on all units, so failover does not occur.
Monitor FaultStandbyA standby unit is not processing traffic, and the standby unit is not eligible to become active because the HA group monitor condition is not satisfied.

Note: An HA group with no object entries has a score of 0. The active bonus has no effect on the monitor feature, and the status becomes one of the listed.

F5 Product Development tracked this change as ID 463903.

Impact

Your system may experience unexpected HA failover events.

Recommended Actions

Set the minimum-threshold parameter for each of the HA group components (trunks, pools, and cluster members) to a value that specifies the minimum number of monitored objects required to consider this contributor valid.
