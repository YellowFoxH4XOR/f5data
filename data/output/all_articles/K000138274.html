K000138274: Unexpected reboot of all tenants on rSeries

Type
Support Solution
Published
2024-01-17
Updated
2024-01-17
Applies to
  • F5OS
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000138274

Description

Multiple tenants rebooted at the same time on rSeries.

The show tenants output indicates the tenant instances were created shortly before the time the reboot was observed, suggesting it was directed by F5OS.

The kubectl get pods command also shows the virt-launcher pods for the tenants have low age:

NAMESPACE     NAME                                      READY   STATUS    RESTARTS   AGE   
...
default       virt-launcher-tenant1-1-vqxfh                1/1     Running   0          11m        <---
default       virt-launcher-tenant2-1-ghljz                1/1     Running   0          12m        <---

Environment

  • rSeries tenants
  • Unexpected reboot

Cause

This can happen if Kubernetes evicts the virt-launcher pods from the node (appliance). For example, a brief taint on the node making pods unschedulable.

Recommended Actions

When all tenants restart or stop around the same time, this is typically triggered by F5OS.
Investigate the log files and ~/.bash_history to determine the root cause.

Additional Information

In one instance this happened when a user created a large file from the F5OS command line using fallocate, then deleted it shortly after (clearing the taint and allowing the pods to be rescheduled).

Messages in /var/F5/system/log/k3s_events.log during this event:

TYPE: Warning REASON: EvictionThresholdMet LOG: Attempting to reclaim ephemeral-storage
Evicted NEW_REASON: Killing OLD_LOG: The node was low on resource: ephemeral-storage. Container compute was using 3512Ki, which exceeds its request of 0. NEW_LOG: Stopping container compute

Note: The compute container runs the tenant from inside a virt-launcher pod.
