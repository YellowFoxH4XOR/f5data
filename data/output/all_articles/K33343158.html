K33343158: Re-enabling root logins when you have lost your Admin password.

Type
Support Solution
Published
2025-05-20
Updated
2025-07-07
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K33343158

Description

In some rare instances a BIG-IP administrator may have root login disabled and lost the admin user password. Without access to another user with the Administrator role or the root user, the admin password cannot be reset. Root logins also cannot be re-enabled without access to a user with the Administrator role. This creates a situation where the BIG-IP admin is unable to login as root or as the admin user which limits them to the roles assigned to other users that they do know the password for.

Environment

  • BIG-IP
  • Administrator role
  • CLI access

Cause

You have disabled root logins and lost the password for the admin user.

Recommended Actions

To work around the issue the following steps can be used as long as you have a UCS archive or another user with an assigned role that has permission to generate a UCS archive.

  1. If you already have a UCS archive, skip to step #2. If you don't have a UCS archive, login to the GUI with a user you know the password for and create a UCS file under "System  ››  Archives". After the file has been created, download it and save it somewhere off of the BIG-IP device.
  2. Next, if you have a user with the "resource-admin" role, restore the device to it's factory default settings via article K13127. If you do not have a user with the "resource-admin" role, perform a clean installation of the software version you currently have installed via article K13117. Make sure to provision all of the same modules that were previously provisioned once the clean installation is complete.
  3. After the clean installation is complete, place the UCS archive in the /var/local/ucs directory but do not load it yet. Alternatively you can login to the GUI with the default admin user as well and import the file there. Once it is imported do not attempt to load it via the GUI.
  4. Login to the CLI using the "root" user which will now be reset to the default password due to step #2.
  5. Load the UCS file with the following command after replacing "UCS_file_name" with the actual file name:

    tmsh load sys ucs UCS_file_name
     
  6. Wait for the UCS file to finish loading. When it finished you should still be logged in as the "root" user. Do not logout at this point. If you do logout you will not be able to log back in as root and will have to start over.
  7. While still logged in as the root user you can then re-enable root logins with the following command or reset the admin user password via article K13121.

    tmsh modify sys db systemauth.disablerootlogin value false
     
  8. You should now be able to logout and back in as root using the root password that was stored in the UCS. You will also be able to login as admin again after changing the admin password.
