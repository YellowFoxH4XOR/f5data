Description

ASM request logs are being truncated.

  • What is the limit or cause for ASM request logs to be truncated?
  • Can we change the value of max_raw_request_len to get the logs?
  • What value do we need to use?
  • Is there any impact in regards to disk space, memory or CPU when changing max_raw_request_len?

Environment

  • ASM request logs

Cause

ASM request logs are truncated when they exceed the value of max_raw_request_len - 5000 bytes by default.

They may also be truncated if they do not exceed max_raw_request_len, but do exceed request_buffer_size - 10000 bytes by default and described in K8292.

The request length set in the logging profile (local or remote) is applied after the limits imposed by max_raw_request_len and request_buffer_size.

Recommended Actions

If you would like to log more than 5000 bytes of request data to avoid truncated logs, consider increasing max_raw_request_len, and optionally request_buffer_size.

The main impact from making this change is increased memory utilization. However, for very large requests there could be performance implications.

Additional Information

Here are some examples to illustrate the relationship between both max_raw_request_len and request_buffer_size in regards to request logging:

Example A

Request: 10k
max_raw_request_len: 5k
request_buffer_size: 10k

Result: Request will be truncated at 5k.

Example B

Request: 10k
max_raw_request_len: 10k
request_buffer_size: 10k

Result: Request will not be truncated.

Example C

Request: 20k
max_raw_request_len: 20k
request_buffer_size: 10k

Result: Request will be truncated at 10k.

Example D

Request: 20k
max_raw_request_len: 20k
request_buffer_size: 20k

Result: Request will not be truncated.
