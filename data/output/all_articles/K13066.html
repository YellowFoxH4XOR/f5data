Topic

To find out what information F5 Support requires when you open a support case for other F5 products, refer to K2633: Instructions for submitting a support case to F5.

F5 Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration. To help gather all of the required information, use the following guidelines to prepare for opening a case:

General Information

Provide the following information when you open a case with F5 Support:

  • A full description of the issue, including the following details:
    • The symptoms of the issue
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the system
    • Steps to reproduce the issue
    • Any changes you made to the system before the issue first occurred
    • Any steps you have made in an attempt to solve the issue
  • A description of the impact the issue is having on your site, using the following definitions:
    • Site Down

      All network traffic has ceased, causing a critical impact to your business.

    • Site at Risk

      Primary unit has failed resulting in no redundancy. Site is at risk of going down.

    • Performance Degraded

      Network traffic is partially functional causing some applications to be unreachable.

    • General Assistance

      Questions regarding configurations. Troubleshooting non-critical issues, or requests for product functionality that is not currently part of the product feature set.

  • The hours that you are available to work on the issue, and any alternative contacts that can work on the issue if you are not available.
  • Remote access information, if possible.

    Remote access to your network environment is important, because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Support will work directly with you to resolve the issue over the phone; however, this method can often be more time consuming and may require file transfers, replication, and additional testing.

Product-specific information

Collect the following information from the affected systems and provide it when you open the case. For information about sending this information to F5, refer to K000090853: Exchange files with F5 Support using MyF5.

QKView

A QKView contains the configuration files that F5 Support most frequently needs when troubleshooting an issue.

For more information about the qkview utility refer to the following articles:

  • K1858: Overview of the qkview utility (9.x)
  • K12878: Generating BIG-IP diagnostic data using the qkview utility

Note: If you are running BIG-IP 10.x or later, you can use F5 iHealth to diagnose a QKView file. iHealth enables you to verify the proper operation of your BIG-IP system. For more information, refer to the iHealth site.

Log files

The qkview utility automatically gathers up to 5 MB of log files and includes them with qkview in a .tar output.

The qkview contains the log files for the previous day. If the issue has existed for more than one day, provide all of the log files on the system by performing the following procedure:

  1. Log in to the command line.
  2. Change directories to the /var/log directory by typing the following command:

    cd /var/log

  3. Create a tar archive named logfiles.tar.gz in the /var/tmp directory which contains all the files in the /var/log directory, by typing the following command:

    tar -czpf /var/tmp/logfiles.tar.gz *

Packet traces

If the issue involves the network, perform a packet trace while the issue is occurring and provide the packet trace when you open the case.

For more information about performing packet traces with tcpdump, refer to K4714: Performing a packet trace and providing the results to F5 Support.

UCS archive

If you cannot give F5 Support remote access to your system, you must provide a UCS archive of the current configuration. For more information, refer to K4423: Overview of UCS archives.

Core files

Core files contain the contents of the system memory at the time a crash occurred. If the system has been configured to save core files, they will be located in the /var/core directory. Provide any existing core files when you open the case.

For information about requirements when submitting core files to F5, refer to K10062: Submitting core files for analysis to F5 Support.
