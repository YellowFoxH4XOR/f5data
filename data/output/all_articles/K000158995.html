Description

When attempting to collect an AVR (Analytics and Visibility Reporting) database dump using the mysqldump command, the following error occurs:

mysqldump: Couldn't execute 'show fields from `AVR_DIM_FW_NAT_NAME`': Deadlock found when trying to get lock; try restarting transaction (1213)


Environment

  • BIG-IP (All versions with AVR/Analytics module)
  • MySQL/AVR Database


Cause

This MySQL deadlock error (1213) occurs when:

  1. The AVR database tables are being actively written to by system processes
  2. The mysqldump utility attempts to access the same table simultaneously
  3. MySQL cannot obtain the necessary lock to perform the dump operation, resulting in a temporary deadlock

Note: This is normal behavior when the AVR database is actively processing analytics data. The table AVR_DIM_FW_NAT_NAME (or other AVR tables) may be busy with write operations at the time of the dump attempt.



Recommended Actions

Use the --single-transaction option with the mysqldump command to avoid locking conflicts:

mysqldump --single-transaction -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` AVR | gzip -9 > /shared/avr.dump.gz


If you cannot use the --single-transaction flag for any reason:

  1. Wait 2-5 minutes for active write operations to complete
  2. Retry the original command
  3. The table may no longer be locked during the second attempt


Additional Information

  • This error does not indicate a problem with your BIG-IP system
  • It is a transient timing issue related to database access
  • The --single-transaction flag is the recommended best practice for dumping active databases
  • This solution applies to all AVR-related mysqldump operations
