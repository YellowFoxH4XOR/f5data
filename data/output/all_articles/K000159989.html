K000159989: F5OS-A Alarm LED Remains Red After Resolving System Health Issues

Type
Support Solution
Published
2026-02-12
Updated
2026-09-11
Applies to
  • F5OS
  • F5OS-A: 1.8.3
Source
https://my.f5.com/manage/s/article/K000159989

Description

  • The Alarm LED on rSeries appliance running F5OS-A remains solid red after resolving underlying system health issues.
  • System health checks (show system health) report all components as healthy with no errors.
  • The show system alarms command returns "% No entries found," indicating no active alarms.
  • The issue persists after system reboot and power cycle.
  • The LED indicator does not automatically clear despite the absence of active alarms or health issues.

Environment

  • Platform: rSeries
  • System health status: All components healthy
  • Active alarms: None
  • Actions taken: System reboot, power cycle, health verification

Cause

ID2502909

The Alarm LED state is stale and was not automatically cleared after the underlying critical hardware alarm. The LED indicator retains the previous alarm state even though the system health has been restored and no active alarms are present.

Answer/Recommended Actions

  1. Verify that no active alarms or health issues exist:

    show system health

    show system alarms

    Confirm output shows healthy status and "% No entries found" for alarms.

  2. Reset the LCD panel to clear the stale LED state:

    1. Connect to the device CLI as root.

    2. Run:

      docker exec -it platform-hal psf call POST:lcd/reboot waitForBootup=True

      This command reboots the LCD module and should clear the red LED indicator. It takes about 90 seconds to fully reboot the LCD. 

  3. Verify the LED status after clearing:

    • Check the front panel to confirm the Alarm LED is no longer red
    • Run show system alarms again to ensure no new alarms have been raised

Additional Information

Rebooting the LCD module does not impact data plane traffic or management connectivity.
