Issue

Description

When testing Session-based Brute Force Protection by sending repeated failed login attempts, you may notice an inconsistent amount of attempts before the configured action (blocking page, captcha, etc) is triggered.

Environment

  • ASM 11.6.x or later
  • Device ID is the only configured
  • Low/no traffic login page such as a test or developer environment

Cause

Device ID requires JavaScript injection. Before the ASM system can inject JavaScript into responses for a URL, it needs to qualify the URL by receiving 10 consecutive HTML responses within the last five minutes. Once the login URL is qualified, Device ID-based Brute Force Attack Prevention will trigger after the configured number of login failures.

Recommended Actions

Qualify the URL before testing by accessing the URL 10 times
