Known Issue

The logd process may exit and produce a core file on the BIG-IP APM system.

In rare circumstances, the logd process may interact negatively with the mysql library in the BIG-IP APM system causing it to exit. Increasing the verbosity of log messages in the BIG-IP APM system may be associated with this issue.

Impact

Local logging for the BIG-IP APM system is impaired

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP APM system reports high cpu utilization for the logd process.
  • The BIG-IP APM system experiences performance degredation.
  • A logd core file is generated to the /shared/core directory.
  • In the /var/log/ltm file, you may observe messages similar to the following example:

    emerg logger: Re-starting logd

Workaround

To work around this issue, you can restart the logd service using the tmsh utility. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the logd service, use the following command syntax:

    restart /sys service <name>

    For example:

    restart /sys service logd

  3. To exit the tmsh utility, type q and press Enter.
