K35361414: Security Events Report will show date stamps of HTTP response in GMT

Support Solution
Published
2022-04-26

2023-02-21
Applies to

  • BIG-IP ASM: 16.X.X, 16.0.X, 16.1.3, 16.1.2, 16.1.1, 16.1.X, 16.0.1, 16.0.0, 16.1.0
Source

Description

Application Security Manager can detect violations that occur in requests. Violations occur when some aspect of a request or response does not comply with the security policy.

In the list of Security ›› Event Logs : Application : Requests, you can view details about a request, including viewing the violation rating, the full request itself, and any violations associated with it. You can also drill down to view detailed descriptions of the violations and potential attacks. In Security Events Report, the Time field of Request Details is shown in local timezone of BIG-IP, however, the date stamps of HTTP response are always shown in GMT.

For example:

HTTP/1.1 200 OK
Date: Mon, 10 Jan 2022 04:21:26 GMT
Content-Length: 601
Content-Type: application/json

Environment

  • Application Security Manager
  • Event Logs
  • Security Events Report

Cause

rfc2616 for Hypertext Transfer Protocol -- HTTP/1.1, requires that:

All HTTP date/time stamps MUST be represented in Greenwich Mean Time (GMT), without exception. For the purposes of HTTP, GMT is exactly equal to UTC (Coordinated Universal Time). This is indicated in the first two formats by the inclusion of "GMT" as the three-letter abbreviation for time zone, and MUST be assumed when reading the asctime format. HTTP-date is case sensitive and MUST NOT include additional Linear White Space (LWS) beyond that specifically included as SPACE in the grammar.

Recommended Actions

None

Additional Information

  • The rfc2616 also mentions that, if an HTTP header incorrectly carries a date value with a time zone other than GMT, it MUST be converted into GMT using the most conservative possible conversion.
  • An informal reason for GMT only might be because,  time zone abbreviations are not necessarily unambiguous and recognized. For exmaple, EST stand for not only US Eastern Standard Time, but also Australian Eastern Standard Time. The advantage of UTC (Universal Time, Coordinated - aka GMT, Greenwich Mean Time) is that, there are no changes, and the system clock (on Unix and derivatives) provides the time as the number of seconds since 'the epoch', which was 1970-01-01 00:00:00 +00:00 (a UTC time, though UTC did not formally come into existence until 1972). Therefore, it is easy to obtain the UTC value; it is unambiguous; the offset from UTC does not change.
