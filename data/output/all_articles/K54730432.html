Description

This article describes possible conditions that could lead to the error vim.fault.NoPermission when using the BIG-IP VE CREATION feature on BIG-IQ 

  • VM may be created on hypervisor even though the BIG-IQ task shows it failed
  • VM may fail to be created on the target VMware ESXi cluster
  • Management-IP may be configured on the VM from an IP pool but the lease is released when the failure occurs
    • This may cause the BIG-IQ IP POOL to hand out an address that is already in use during future VE creation unless failed VMs are removed or powered off
  • If a VM is created deleting, the failed VE task on the BIG-IQ may not remove the VM from the hypervisor
  • Errors logged in restjavad.0.log similar to the following:

    FAILURECannot create VE on vCenter: java.lang.IllegalStateException: VM <vm-name> not found in VMware. Reason: MODULE

  • Error logged in orchestrator.log containing:

    .fault\npyVmomi.VmomiSupport.NoPermission: (vim.fault.NoPermission) 

Environment

  • BIG-IQ configured to use a VMware Cloud Provider

Cause

The following conditions may cause this failure
Note: These are the known conditions that cause this at the time of writing. Others may exist.

  • Insufficient VMware permissions for the user configured in the Cloud Environment used in the BIG-IP Creation Task
  • Insufficient VMware permissions on just one or more of the VMware clusters
    • This causes the failure when BIG-IQ attempts to find the new VM after creation
  • Not enough resources available on target hypervisor 

Recommended Actions

  • Contact the Hypervisor administrator and verify permissions for the user configured in the Cloud Environment
  • Verify that the destination datastore has enough free space, including space to accommodate all the memory assigned to the virtual machine
