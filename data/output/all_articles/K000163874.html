Specific mitigation procedure for Next.js Image Optimizer RCE for node.js CVE-2026-111497

This procedure is relevant for Next.js apps hosted on vulnerable Node.js servers. F5 recommends to restrict the list of domains in the`url`parameter under the allowed URL `/_next/image` to include only trusted websites.

Configure an allowed URL named "/_next/image"

  1. As an Administrator role user, navigate to Security ›› Application Security : URLs : Allowed URLs : Allowed HTTP URLs
  2. Select the specific Adv WAF security policy
  3. Click Create
  4. Under Create New Allowed URL, set Explicit, HTTPS, '/_next/image'
  5. Remove Perform Staging to immediately enforce the URL
  6. Click Create
    The created HTTPS /_next/image URL is now listed in the Allowed URL list.

Configure a URL parameter named "url"

  1. Click on the HTTPS /_next/image URL in the Allowed URL list, it will open the page
  2. Security ›› Application Security : URLs : Allowed URLs : Allowed HTTP URLs ›› Allowed HTTP URL Properties
  3. Click on URL Parameters, it will open the page
  4. Security ›› Application Security : URLs : Allowed URLs : Allowed HTTP URLs ›› URL Parameters
  5. Click Create, it will open the page
  6. Security ›› Application Security : URLs : Allowed URLs : Allowed HTTP URLs ›› Add URL Parameter…
  7. Set Parameter Name as Explicit 'url'
  8. Set Parameter Level as URL, Path HTTPS '/_next/image'
  9. Uncheck Perform Staging to immediately enforce the URL parameter
  10. Set Parameter Value Type to 'User input value'

The ’url’ Parameter’s Data Type can be configured with two options. Each option will use a different Adv WAF policy violation.

Option 1:

  1. Set the 'Data Type' as 'URI' and the 'Host Name Representation' as 'Domain Name'
  2. Under Data Type, Set the 'Data Type' as 'URI' and the 'Host Name Representation' as 'Domain Name'
  3. Click Create
    The newly created URL Parameter 'url' will be listed in the URL Parameters List

Configure Learn, Alarm and Block settings on 'Illegal Parameter Data Type' Violation on Specific Adv WAF Security Policy

  1. Navigate to Security ›› Application Security : Policy Building : Learning and Blocking Settings
  2. Select the specific Adv WAF security policy
  3. Under Parameters, Enable Alarm and Block settings on 'Illegal Parameter Data Type' violation
  4. Click Save

Configure disallowed host names or IP addresses under SSRF Protection

Illegal Parameter Data Type violation works in tandem with the Adv WAF security policy's SSRF protection configuration.

  1. Navigate to Security ›› Application Security : Security Policies : Policies List > select the specific Adv WAF security policy
  2. Under Advanced Protection, SSRF Protection, add in the list the specific hosts that you want to disallow access to. You can use either IP addresses or host names in each entry.
    Note: under URI Data Type Parameters to Mitigate SSRF Evasions, it should list the ‘url’ parameter
  3. Click Save

Note: When configuring host names or domain names under SSRF Protection, ensure these can be resolved by the DNS server configured in the BIG-IP Adv WAF system.

 

Option 2:

  1. Set the 'Data Type' as 'Alpha-Numeric' and define allowed specific pattern for the 'url' parameter value
  2. Under Data Type, Set the 'Data Type' as 'Alpha-Numeric'
  3. Under Regular Expression box, set the regular expression of the allowed specific pattern
    For example:
    http://site\.trusted\.local(?:/[^\s]*)?
  4. Click Create
    The newly created URL Parameter 'url' will be listed in the URL Parameters List

Configure Alarm and Block settings on ‘Parameter value does not comply with regular expression' Violation on Specific Adv WAF Security Policy

  1. Navigate to Security ›› Application Security : Policy Building : Learning and Blocking Settings
  2. Select the specific Adv WAF security policy
  3. Under Parameters, Enable Alarm and Block settings on ' Parameter value does not comply with regular expression' violation
  4. Click Save

Configure Trusted Website Domains

  1. Navigate to Security ›› Application Security : Security Policies : Policies List, Click on the specific Adv WAF Security Policy
  2. Under the Policy configuration page , HTTP Message Protection, Select Headers
  3. Under Host Names, depending on your needs, select Include or Exclude Subdomains, then set the 'Host Name' of the Trusted Website Domains
    Example:
    If Include Subdomains selected, '(and Sub-Domains' is listed: images.trusted.net (and Sub-Domains)
    If Exclude Subdomains selected, specific hostname is listed: secure.trusted.net

Configure Alarm and Block settings on ‘Illegal host name' violation on Specific Adv WAF Security Policy

  1. Navigate to Security ›› Application Security : Policy Building : Learning and Blocking Settings
  2. Select the specific Adv WAF security policy
  3. Under Parameters, Enable Alarm and Block settings on ' Illegal host name' violation
  4. Click Save
  5. Click Apply Policy (at the top right corner)

Create a custom attack signature for node.js CVE-2026-111497

  1. As an administrator role user, navigate to Security ›› Options : Application Security : Attack Signatures > Attack Signatures List
  2. Click Create
  3. Provide an Attack Signature Name, example temp_nodejsCVE-2026-111497
  4. Assign a Tag, example temp_nodejsCVE-2026-111497:
    For Signature Type, use Request
    For Attack Type, use Command Execution
    For Assigned Systems, use Node.js
    For Rule, use Advanced Mode. Paste the custom rule:
    headercontent:"Content-Encoding:"; nocase; re2:"/^Content-Encoding:[^\n]+\bbr\b/Hmi"; re2:"/^(?:POST|PUT|PATCH)/i";
    Note: This signature blocks all requests with an "Content-Encoding" header that indicates the Brotli compression method, while limiting to POST/PUT/PATCH method to reduce false positives.
    Set Accuracy, example Low
    Set Risk, example Low
  5. Click Add

Create a custom attack signature set and configure to match the custom attack signature

  1. Navigate to Security ›› Options : Application Security : Attack Signatures > Attack Signatures Sets
  2. Click Create
  3. Provide an Attack Signature Set Name, example temp_nodejsCVE-2026-111497
    Set Default Blocking Actions, example Learn, Alarm, Block
    Set 'Assign Set to Newly Created Policies', example Always
    Set 'Signature Set Type' , example Manual, then use one of the available filters, example Tag, and use the custom attack signatures Tag, example temp_nodejsCVE-2026-111497. The matched attack signature will appear in the Available Signatures list. Click on the plus sign to assign the Attack Signature.
  4. Click Add
    The newly created Attack Signature set will appear in the list.

Assign the Custom Attack Signature Set to the specific Adv WAF Security Policy

  1. Navigate to Security ›› Application Security : Policy Building : Learning and Blocking Settings
  2. In the dropdown list, select the specific Adv WAF Security Policy
  3. Under Attack Signatures, click Change
  4. Click the checkbox next to the newly created Custom Attack Signature Set, then click Change
  5. Enable the Attack Signature Set's violation settings, example enable Learn, Alarm, Block checkboxes
  6. Click on Save

Ensure that the newly created custom attack signature is Enforced

  1. Navigate to Security ›› Application Security : Security Policies : Policies List > select the specific Adv WAF Security Policy
  2. Under Policy Configuration, Attack Signatures, select the custom attack signature, click Enforce
  3. Click Apply Policy
