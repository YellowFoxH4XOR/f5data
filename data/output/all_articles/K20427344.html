Topic

Disaggregator (DAG) is a key component of Clustered Multiprocessing (CMP) that BIG-IP systems use to define how incoming traffic is disaggregated to the different Traffic Management Microkernels. The cmp_dest utility is a useful tool, available on your BIG-IP system, that you can use to determine the target high-speed bridge (HSB)/TMM.

Description

CMP distributes traffic across available TMM instances based on a hash of the packet content.

DAG modes

The system uses DAG to extract fields from a packet and computes a hash value to determine which TMM to forward the packet to. DAG is made up of the hardware DAG and software DAG (daglib library) components; however, not every BIG-IP platform supports hardware DAG. For more information, refer to K14435: Error Message: This device does not support the requested 'cmp-hash'.

The following table lists the different DAG modes that you can use to configure for each VLAN. To do so, on the Configuration utility, go to Network > VLAN.

DAG modeDescription
Default DAGDisaggregates traffic based on the hash of source and destination ports.
SPDAG

Service provider DAG

Disaggregates traffic based on the hash of either source or destination IP addresses. Not supported on vCMP.

F5 recommends running SPDAG only on BIG-IP platforms that support both hardware and software DAG. For more information, refer to K14435: Error Message: This device does not support the requested 'cmp-hash'.

Round robin DAGHandles connectionless packets that lack entropy in IP addresses and ports, disaggregating traffic in a round robin order. Useful for protection against DDoS attacks.
ReDAGEnables the disaggregation of IP tunnel packets based on their inner IP header in hardware DAG. By default, in hardware DAG, the hardware does not inspect inner IP headers when disaggregating IP tunnel traffic.

Not supported on vCMP.

The cmp_dest utility

The cmp_dest is a deterministic utility available on the BIG-IP system to help you find out which TMM will process a packet based on a set of conditions, namely hardware platform, current hardware state, and software configurations. When you use the utility, you should set the values of different options to obtain an accurate output.

ParametersDescription
Hardware
--platform
  • Simulates the disaggregation on another platform. This sets the default values for values such as hash, npus, npgs, nhsbs, fold-bits, pde-trunk-size, and ht-per-core-is-one.
  • If you do not specify both --platform and --type options, the cmp_dest command behaves as if --platform is set.
  • Specify LOCAL to use the daglib settings on the current system.
  • To obtain the value for your BIG-IP platform, use the tmsh show sys hardware command. The following example output displays A109 as its platform:

    # tmsh show sys hardware | grep -A1 "System Information"
    System Information Type A109

--npus
  • Indicates the number of processing units (TMMs) per blade.
  • Determine the value with: tmctl -d blade tmm/daglib
--npgs
  • Indicates the number of processing groups in a clustered system.
  • Determine the value with: tmctl -d blade tmm/daglib
--nhsbs
  • Indicates the number of HSBs in each blade.
  • Determine the value with: tmctl -d blade tmm/daglib
--enable_ht_split

--disable_ht_split
  • HTSplit is enabled by default if your BIG-IP platform supports even-numbered hyperthreads.
  • To determine if your BIG-IP platform supports HTSplit, refer to K23505424: Overview of the HTSplit feature.
--type
  • Indicates the disaggregation algorithm in use. This can be any of the following values:

    [xor|xor12|xor_ex|xor_fold|dag|dagv2|vdag|hdag|p8dag|rss]

  • Determine the value with: tmctl -d blade tmm/daglib or grep "Hash type" /var/log/tmm*
  • If you do not specify both --platform and --type options, the cmp_dest command behaves as if --platform LOCAL is set.
Only for type dagv2:
  • Generates its disaggregation tables on startup. You get random results in each run unless you specify the dagv2_seed option.

    --dagv2_seed

    When you run the cmp_dest command specifying the platform, the output includes the dagv2_seed value as shown in the following example:

    # cmp_dest --platform A114 --local_port 80 --remote_port 174
    DAGv2 random seed is 0xc676a4fe

  • Instead of specifying the dagv2_seed value, you can also explicitly provide the additional following options. To retrieve the DAGv2 tables (entries are hexadecimal separated by colons), use the tmctl commands in the following table.
    ParametersCommand to retrieve table
    --dagv2_pgstmctl -d blade tmm/daglib_dagv2_pgs
    --dagv2_mirror_pgstmctl -d blade tmm/daglib_dagv2_mirror_pgs
    --dagv2_hsbstmctl -d blade tmm/daglib_dagv2_hsbs
    --dagv2_mirror_hsbstmctl -d blade tmm/daglib_dagv2_mirror_hsbs

For example:

cmp_dest --select remote_ip --platform CERBERUS --dagv2_pgs "00:01:03:03:03:01:02:00:00:03:01:02:02:02:01:00:00:01:02:03:02:03:01:00" --dagv2_hsbs "00:00:01:00:00:00:01:01:00:01:01:00:00:01:01:01:00:00:00:01:01:00:01:01" --remote_ip 10.0.0.1

  • You also can use the --command profile to output the value of the dagv2 hash table given a --dagv2_seed value. For example, given a random seed value, set --dagv2_commands hp:

    cmp_dest --command profile --type dagv2 --npus 24 --nhsbs 2 --npgs 8 --cmp_state 0x3 --dagv2_commands hp --dagv2_seed 0xc676a4fe
    DAGv2 random seed is 0xc676a4fe
    :: Hash table parameters ::
    --dagv2_pgs 01:01:00:00
    --dagv2_hsbs 00:01:00:01F

    From the previous output, you can run the cmp_dest command by specifying either --dagv2_seed 0xc676a4fe or --dagv2_pgs 01:01:00:00 --dagv2_hsbs 00:01:00:01F. Both return the same destination.

  • If you do not specify any values for --dagv2_seed or any of the dagv2 hash tables, you should specify the --platform LOCAL option so that the platform is detected and dagv2 tables are retrieved from the running system.

Hardware state
--cmp_state

  • Hexadecimal representation of the number of currently active blades.

    BinaryHexadecimalDescription
    00010x1Only blade 1 is up
    00110x3Only blades 1 and 2 are up
    01110x7Only blades 1, 2 and 3 are up
    11110xfBlades 1-4 are up

  • You must specify a value for --cmp_state if you use cmp_dest on a VIPRION platform. For example:

    cmp_dest --platform CERBERUS --cmp_state 0x7 --select remote_ip --remote_ip 10.0.0.1

Software configuration
--select
  • Sets the variable that the system uses to create a hash value to distribute traffic. Refer to the DAG modes section of this article for your software configuration.

    [port|remote_port|local_port|ip_port|ip|remote_ip|local_ip]

  • For example:

    Default DAG method:

    cmp_dest --select port --local_port 80 --remote_port 2045

    SPDAG:

    cmp_dest --select remote_ip --remote_ip 10.0.0.1

    IPPORT:

    cmp_dest --select ip_port --local_ip 10.20.1.2 --local_port 772 --remote_ip 10.10.1.1 --remote_port 258

Recommendations

When using the cmp_dest utility, you should consider the following factors:

  • You can run the cmp_dest command with the --help option to display a detailed description of each option.
  • For options that you do not set, cmp_dest uses either the values from the current settings of the local system or default values, except when you use the --platform option to specify a platform. If you are unsure what options to set, you should run the command on the actual BIG-IP system that you are troubleshooting. Use --platform LOCAL to use the settings on the current system.

    For instance, in the following example, the command is run on an iSeries platform using the --platform option to specify a VIPRION platform. Because the cmp_state, type dagv2 and other options are not specified, the output may not accurately reflect the actual outcome.

    cmp_dest --platform A114 --local_port 80 --remote_port 174

  • Run the cmp_dest command with the -v or -V option to display the parameters that the command used to generate the output. For example, the following output shows that the cmp_dest has run with the ahdag disaggregation algorithm on a VIPRION platform with 1 blade running.

    # cmp_dest --platform LOCAL --local_port 80 --remote_port 174 -V
    Parameters:
    command: resolve
    type: ahdag
    [...]
    cmp_state: 0x1

    From the output of each value, verify if those are the settings you require.

  • To retrieve some of the values specific to the platform of your BIG-IP system, run the cmp_dest --command platform_list command. F5 recommends running this command on the latest BIG-IP versions. The last entry in the output displays the information for your local system.

    #cmp_dest --command platform_list
    [...]
    A109 (local platform):
    Hash: vdag
    NPUS: 4 [HTSPLIT], 8 [NON-HTSPLIT]
    NPGS: 4
    HSBS: 1
    PDE trunk size [HTSPLIT]: 1

  • When planning for the IP addresses to include in a SNAT pool of a BIG-IP virtual server, you can use the cmp_dest in a loop to verify if traffic is well distributed across all the TMMs in the system. For example, you can use the following example for a system in SPDAG mode with 4 blades and hashing based on the remote IP address using a SNAT pool of IP addresses 10.0.0.0/24:

    for i in {1..255}; do cmp_dest --select remote_ip --platform LOCAL --enable_ht_split --cmp_state 0xf --dagv2_pgs "00:03:01:03:02:01:01:00:00:02:03:02:02:01:03:00:00:01:02:03:03:02:01:00" --dagv2_hsbs "00:01:00:00:01:01:00:01:00:00:01:00:01:01:00:01:00:01:01:01:00:00:00:01" --npus 24 --npgs 8 --remote_ip 10.0.0.$i; done | grep Destination | awk -F/ '{print $2 " " $3}' | sort | uniq -c
