K63440601: Unable to ssh or access WebUI after upgrade from 13.1.4.1 to 14.1.4.4

Description

After upgrading a VE from 13.1.4.1 to 14.1.4.4, ssh & httpd access no longer works. 

Environment

  • The self IP is used to manage the device.
  • No management route exists.
  • This access works on v13.
  • Deploying v14 OVA templates with the same network configuration are accessible.

Cause

On 14:

  • The interfaces for the self IP are uninitialized.
    • tmsh show net interface
  • The nic driver shows no "driver_in_use" though xnet, vmxnet3, sock are available 
    • tmctl -d blade -i tmm/device_probed
      name    pci_bdf        pseudo_name    type        available_drivers      driver_in_use
      row0    0000:01:00.0                  F5DEV_PCI   xnet, vmxnet3, sock,
      row1    0000:02:00.0                  F5DEV_PCI   xnet, vmxnet3, sock,
      row2    0000:01:00.0                  F5DEV_PCI   xnet, vmxnet3, sock,
      row3    0000:0b:00.0                  F5DEV_PCI   xnet, vmxnet3, sock,

On 13:

  • The interfaces for the self IP are initialized.
  • The nic driver shows unic as "driver_in_use".
  • The /config/tmm_init.tcl disabled vmxnet3 to workaround ID 682171

Recommended Actions

Enable the vmxnet3 nic driver on v14:
Impact of Workaround:  Restarting "tmm" will disrupt traffic processing through the BIG-IP.

  1. Boot into the v14 volume.
  2. Remove /config/tmm_init.tcl.
    • rm /config/tmm_init.tcl
  3. Restart tmm.
    • tmsh restart /sys service tmm
  4. Confirm the nic "driver_in_use" is vmxnet3
    • tmctl -d blade -i tmm/device_probed
      name    pci_bdf        pseudo_name    type        available_drivers      driver_in_use
      row0    0000:01:00.0   1.1            F5DEV_PCI   xnet, vmxnet3, sock,   vmxnet3
      row1    0000:02:00.0   1.2            F5DEV_PCI   xnet, vmxnet3, sock,   vmxnet3
      row2    0000:01:00.0   1.3            F5DEV_PCI   xnet, vmxnet3, sock,   vmxnet3
      row3    0000:0b:00.0   1.4            F5DEV_PCI   xnet, vmxnet3, sock,   vmxnet3
