Description

Following errors are noted under "/ts/log/asmcrond.log" and "/var/log/asm" files.  Why this error logs appear ?

<DATE> <TIME> <HOSTNAME> crit perl[30993]: 01310027:2: ASM subsystem error (asmcrond,F5::PeriodicTask::SessionAwarenessDataPointSweep::module_run): Session Awareness Data Point Sweeper: error encountered while trying to retrieve from SessionDB for policy <POLICY_NAME>

 

<DATE> <TIME> <HOSTNAME> crit perl[30993]: 01310027:2: ASM subsystem error (asmcrond,F5::PeriodicTask::SessionAwarenessDataPointSweep::module_run): Unhandled keyword ()

 

Environment

  • BIG-IP ASM/AWAF module is provisioned 
  • "Session Awareness" feature is enabled at least for one application security policy
  • "Manual"  ASM Sync Type is configured for the device-group between F5 peers


Cause

When security policy is configured with "Session Awareness" feature,  every time a new entry is added to the "session tracking table". It causes the units to be in "Changes Pending" state. This means that if the devices are not in auto-synced state, it can generate several error messages as mentioned above.

It is an expected and normal behavior that such error messages will show up when the Session Tracking Tables are not automatically synced between the F5 peer units.
 

 Recommended Actions

Change BIG-IP ASM device group to Auto sync type
