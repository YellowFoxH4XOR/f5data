Description

TMM typically runs multiple instances (e.g. tmm0, tmm1, tmm2, tmm3), and the DAG (disaggregator) distributes each flow to a particular tmm instance.

Note: For more information about how TMM runs as multiple instances or threads, refer to K14358: Overview of Clustered Multiprocessing (11.3.0 and later).

TMM fast flow forwarding allows an overloaded TMM instance to forward a new flow to another instance.
The fast flow forwarding feature is activated when a TMM instance is processing close to 100% of its capacity.

Below is an example with 4 TMM instances, tmm0 to tmm3.

  1. DAG (disaggregator) sends a new connection to a particular instance, eg. tmm0.
  2. tmm0 feels overloaded, and forwards the connection to another instance, eg. tmm2.
  3. tmm2 processes the traffic.
  4. If the virtual server has the source-port preserve setting (which is default), tmm2 changes the source port when making a connection on the server-side so that return packets from the server go directly to itself for performance reasons.

Additional Information

If source port must be preserved, use source-port preserve-strict setting on the virtual server.

In the example above, this will cause tmm2 to make the server-side connection without changing source port.

However, return packets from the server will be sent to the original instance, tmm0 instead, which forwards to tmm2 for processing.
