Topic

It may be beneficial to configure the BIG-IP DNS (formerly known as BIG-IP GTM) and BIG-IP Link Controller systems to provide NOERROR responses for IPv6 queries to a wide IP in the following configurations:

  • BIG-IP DNS configurations where no IPv6 pool members exist for the wide IP, and the resource record has been removed from the BIND configuration
  • BIG-IP Link Controller systems

    Description

    Configurations where no IPv6 pool members or BIND resource records exist

    When an AAAA or A6 query is received, and no BIG-IP DNS IPv6 pool members exist for the wide IP, the gtmd process passes the request to BIND. If the BIND configuration does not contain the zone for the requested name, BIND responds with a list of the root servers. This process causes a delay in resolving the name, as the client or Local Domain Name System (LDNS) server must query the root name servers before it is able to perform an A record query.

    If the BIND configuration contains the zone, but does not contain any resource records for the requested name, BIND sends an NXDOMAIN response. The LDNS server may cache the NXDOMAIN response and provide the response to all clients requesting that record. As a result, the wide IP name is inaccessible to all users of the affected LDNS.

    Important: If your wide IP configuration uses a last resort pool, any request that cannot be resolved by the last resort pool is dropped. Using a last resort pool in conjunction with IPv6 resolutions can result in the BIG-IP system dropping the query when there are no configured IPv6 pool members. If you want AAAA (IPv6) queries to be answered with a NOERROR response, you can enable this feature through the wide IP advanced settings of the individual wide IP.

    BIG-IP Link Controller systems

    Note: The BIG-IP Link Controller does not use the ZoneRunner utility; you must manually perform any BIND configuration.

    By default, the BIG-IP Link Controller does not create a zone file in BIND when you create a wide IP. Therefore, BIND always sends a list of root servers back to the client or LDNS when an AAAA or A6 query is received. This process causes a delay before the client is able to perform an A record query.

    Configuring BIG-IP DNS or Link Controller to provide IPv6 NOERROR responses

    You can configure BIG-IP DNS or Link Controller to provide NOERROR responses for IPv6 AAAA or A6 wide IP queries, without passing the query to BIND. In addition, in BIG-IP 11.2.1 and later you can configure an optional TTL value for the NOERROR response. To configure NOERROR responses, perform one of the following three procedures, specific to your product and version:

    Note: Due to a known issue, configuring NOERROR responses may cause the BIG-IP DNS system to load-balance requests to the incorrect resource. For more information, refer to K13909: The BIG-IP GTM system may fail to apply a pool load-balancing method when the ipv6_noerror option is enabled for the wide IP.

    • Configuring BIG-IP DNS
    • Configuring BIG-IP Link Controller
    • Using an iRule

    Configuring BIG-IP DNS

    BIG-IP 12.0.0 and later

    Note: In BIG-IP 12.0.0 and later, you must create a type AAAA Wide IP to return a NOERROR response for IPv6 queries. In this procedure, F5 assumes you already have a type A Wide IP created for the fully qualified domain name.

    1. Log in to the Configuration utility.
    2. Go to DNS > GSLB > Wide IPs.
    3. Select Create.
    4. For Name, enter the fully qualified domain name that matches the type A Wide IP for which you want to provide NOERROR responses for IPv6 queries.
    5. For Type, select AAAA wide IP.
    6. For General Properties, select Advanced.
    7. For Return Code On Failure, select Enabled.
    8. For RCODE, select NOERROR (no error).
    9. Optional: For SOA Negative Caching TTL, enter the number of seconds that the local DNS servers consider the IPv6 NoError response to be valid.
    10. Select Update.

    The wide IP now returns NOERROR responses to IPv6 AAAA or A6 DNS requests that come to the wide IP.

    BIG-IP 11.6.x and earlier

    1. Log in to the Configuration utility.
    2. Go to DNS > GSLB > Wide IPs.

      Note: For versions earlier than BIG-IP 11.5.0, go to Global Traffic > Wide IPs.

    3. Select the wide IP for which you want to configure BIG-IP DNS to provide NOERROR responses.
    4. For General Properties, select Advanced.
    5. For IPv6 NOERROR Response, select Enabled.
    6. Optional: For BIG-IP 11.2.1 and later, for IPv6 NoError TTL, enter a TTL value.
    7. Select Update.

    The wide IP now returns NOERROR responses to IPv6 AAAA or A6 DNS requests to the wide IP.

    Configuring BIG-IP Link Controller

    BIG-IP 12.0.0 and later

    Note: In BIG-IP 12.0.0 and later, you must create a type AAAA Wide IP to return a NOERROR response for IPv6 queries. In this procedure, F5 assumes you already have a type A Wide IP created for the fully qualified domain name.

    Note: You must use the TMOS Shell (tmsh) to create the AAAA Wide IP.

    1. Log in to tmsh by typing the following command:

      tmsh

    2. To create a type AAAA Wide IP that provides NOERROR responses for IPv6 queries, use the following command syntax:

      create gtm wideip aaaa name failure-rcode-response enabled

      For example, to provide a NOERROR response for IPv6 queries for the domain name wip.example.com, enter the following command:

      create gtm wideip aaaa wip.example.com failure-rcode-response enabled

    3. To save the configuration, enter the following command:

      save sys config gtm-only

    The wide IP now returns a NOERROR response to IPv6 AAAA or A6 DNS requests that are sent to the wide IP.

    BIG-IP 11.6.x and earlier

    1. Log in to the Configuration utility.
    2. Go to Link Controller > Inbound Wide IPs.
    3. Select the wide IP for which you want to configure the BIG-IP DNS to provide IPv6 NOERROR responses.
    4. For Configuration, select Advanced.
    5. For IPv6 NOERROR Response, select Enabled.
    6. Optional: For BIG-IP 11.2.1 and later, for IPv6 NoError TTL, enter a TTL value.
    7. Select Update.

    The wide IP now returns a NOERROR response to IPv6 AAAA or A6 DNS requests that are sent to the wide IP.

    Note: In BIG-IP Link Controller 11.0.0 - 11.3.0, you cannot enable the IPv6 NoError Response setting in the Configuration utility. For information about using the tmsh utility to enable this setting, refer to K15063: The Wide IP properties page of the BIG-IP Link Controller Configuration utility is missing input controls.

    Using an iRule

    Note: This functionality is available only through the use of BIG-IP LTM and DNS iRules; the BIG-IP Link Controller system does not have iRule functionality.

    1. Log in to the Configuration utility.
    2. Go to the iRules list:
      • For BIG-IP 11.6.x and later, go to DNS > Delivery > iRules.
      • For BIG-IP 11.5.x and earlier, go to Global Traffic > iRules.
    3. Select Create.
    4. Select a name for the iRule.
    5. In the Definition box, enter the following iRule text:
      • BIG-IP 12.x and later:

        when DNS_REQUEST {
        if {[DNS::question type] equals "AAAA" }{
           DNS::header rcode NOERROR
           DNS::return
           }  
        }

      • BIG-IP 11.6.x and earlier:

        when DNS_REQUEST {
        if { [DNS::rrtype] equals "AAAA" } {
        noerror
        }
        }

    6. Select Create.
    7. Add the iRule to the BIG-IP DNS listener.
      • DNS > Delivery > Listeners > Listener List.
