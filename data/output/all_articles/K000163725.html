Description

There was an attempt to import software image, which failed. Multiple BIG-IP tenants on F5OS-A rSeries appliances became unavailable after chassis reboot and entered Linux emergency mode.

Tenant consoles reported Failed to mount Mount TMOS 'share' filesystem, while F5OS continued to show the tenants as deployed or started.

Environment

• F5OS-A rSeries appliance

• Multiple BIG-IP tenants

• Tenant storage located on the host cbip-disks filesystem

• A BIG-IP 17.5.1.9 ISO image was being copied to multiple tenants when the issue occurred

Cause

The cbip-disks filesystem on the F5OS-A host reached 100% utilization because tenant virtual disks had expanded over time and the BIG-IP image-copy operation required additional storage. Once the host filesystem was full, tenant writes and access to the tenant virtual disks failed, resulting in the BIG-IP /shared filesystem mount failure and emergency-mode boots.

Answer/Recommended Actions

• Identify tenant virtual disk usage with:

bash

find /var/F5/system/cbip-disks -type f -exec du -h {} \; | sort -hr

• Reclaim host storage by deleting and recreating tenants with excessively large virtual disks, following the required backup and configuration-recovery process.

• Remove obsolete ISO files, UCS files, and unused tenant boot locations where appropriate.

• Monitor cbip-disks` utilization before and after major tenant operations.

• Before image transfers, upgrades, or creation of new boot locations, verify free space on /var/F5/system/cbip-disks.

• Avoid relying solely on the sparse virtual-disk allocation size. Monitor the actual physical space consumed on the host filesystem.
