Known Issue

The first POST request sent to the BIG-IP APM system for authentication may be lost.

This issue occurs when all of the following conditions are met:

  • Kerberos Auth with RBA enabled is used in the Access Policy.
  • The first request to the BIG-IP APM system before the session has been established is a POST request.

Because the original POST request is lost, in the use case of the BIG-IP APM system configured as Security Assertion Markup Language (SAML) Identity Provider (IdP) and HTTP-POST single sign-on (SSO) binding, AuthnRequest can get lost and authentication will fail.

Impact

The client may not be authenticated as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • In the use case of a BIG-IP APM system as SAML IdP with HTTP-POST SSO binding, in the /var/log/apm file, you may observe error messages similar to the following example:

    warning tmm[17720]: 014d0002:4: d8b25ed8: SSOv2 Authn Request has no SAMLRequest
    err tmm[17720]: 014d0002:3: d8b25ed8: SSOv2 Error(12) Extracting SAML Data from Request

Workaround

To work around this issue, you can disable RBA in the Kerberos Auth action in the visual policy editor. To do so, perform the following procedure:

Impact of workaround: Performing the following procedures will disable the RBA feature for Kerberos Auth.

  1. Log in to the Configuration utility.
  2. Navigate to Access Profiles > Access Profile List.
  3. To open the visual policy editor, click the Edit link to the right of the affected access profile.
  4. Click the Kerberos Auth action.
  5. In the Kerberos Auth action Properties tab, for Request Based Auth, select Disable.
  6. Click Save.
  7. In the upper-left corner of the visual policy editor, click Apply Access Policy.
  8. To exit the editor, click the green Close button in the upper-right corner of the visual policy editor.
