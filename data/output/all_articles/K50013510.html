K50013510: Users cannot associate a local traffic policy with a virtual server when the policy has conditions that reference data group and non-data group types

Known Issue

You are unable to associate a local traffic policy with a virtual server when the policy has conditions that reference data group and non-data group types.

This issue occurs when all of the following conditions are met:

  • You create a local traffic policy that contains rules that define more than one condition.
  • You define at least one condition that references a data group.
  • You define at least one condition that references a non-data group.

For example, the following BIG-IP LTM policy contains a rule named example_Rule that defines two conditions--one that references a data group type and one that references a non-data group type.

ltm policy /Common/example_ltm_policy {
     published-copy /Common/block_URI
     requires { http }
     rules {
         example_Rule {
             conditions {
                 0 {
                     http-host
                     host
                     datagroup /Common/example_datagroup  <------ Datagroup
                 }
                 1 {
                     http-host
                     host
                     values { example.com }  <------ Non-Datagroup
                 }
             }
         }
     }
     strategy /Common/first-match
}

Impact

You are unable to associate the local traffic policy with a virtual server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You are unable to associate a local traffic policy with a virtual server.
  • When you attempt to associate a local traffic policy with a virtual server, you receive an error message that appears similar to the following example:

    010716d8:3: Compilation of ltm policies for virtual server /Common/vs_name failed; Failed to compile the combined policies.

Workaround

To work around this issue, for the condition that references a non-data group type, you can create a new data group to hold its record and then modify the condition to reference this new data group.

For example, the following local traffic policy contains a condition that references a non-data group with a string record example.com.

ltm policy /Common/example_ltm_policy {
     published-copy /Common/block_URI
     requires { http }
     rules {
         example_Rule {
             conditions {
                 0 {
                     http-host
                     host
                     datagroup /Common/example_datagroup  <------ Datagroup
                 }
                 1 {
                     http-host
                     host
                     values { example.com }  <------ Non-Datagroup
                 }
             }
         }
     }
     strategy /Common/first-match
}

The corrected local traffic policy configuration with a new data group should appear similar to the following example. The non-data group type is replaced with a new data group named new_datagroup that contains the string record example.com.

ltm data-group internal /Common/new_datagroup {
    records {
        example.com { }
    }
    type string
}
ltm policy /Common/example_ltm_policy {
     published-copy /Common/block_URI
     requires { http }
     rules {
         example_Rule {
             conditions {
                 0 {
                     http-host
                     host
                     datagroup /Common/example_datagroup  <------ Datagroup
                 }
                 1 {
                     http-host
                     host
                     datagroup /Common/new_datagroup  <------ Datagroup
                 }
             }
         }
     }
     strategy /Common/first-match
}

To perform the workaround, perform the following procedures:

  • Creating a new data group to hold the record you want to match in the condition
  • Modifying the condition that references a non-data group type to reference the new data group you created

Creating a new data group to hold the record you want to match in the condition

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic  >  iRules  >  Data Group List.
  3. Click Create.
  4. Enter the appropriate values.

    For example, to create a new data group to hold a string record example.com, perform the following tasks:

    • For Name, type an appropriate name for the new data group.
    • For Type, click String.
    • For String Records, in the String field, type example.com.
  5. Click Finished.

Modifying the condition that references a non-data group type to reference the new data group you created

Impact of workaround: F5 recommends that you perform the following procedure in a lab environment before implementing it into a production environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic  >  Policies > Policy List.
  3. In the Published Policies section, click the name of the policy you want to modify.
  4. Click Create Draft.
  5. In the Draft Policies section, click the name of the policy you want to modify.
  6. In the Rules section, click the name of the rule that contains the condition you want to modify.
  7. Modify the affected condition so that it references a data group.

    For example, in the list for the affected condition, replace any of with in datagroup and click the name of the new data group that you created in the previous step.

  8. Click Save.
  9. From the drop-down list, click Save and Publish Policy.

Note: For more information about configuring the conditions in Local Traffic Policy, refer to the Introducing Local Traffic Policies chapter of the BIG-IP Local Traffic Management: Getting Started with Policies manual.
