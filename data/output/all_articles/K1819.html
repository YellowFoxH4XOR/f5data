Introduction

The config sync process consists of three primary activities:

  • Collection of files to transmit
  • Transport of collection
  • Installation on remote machine

You can troubleshoot issues with the following information:

  • Primary config sync troubleshooting checklist
  • Secondary config sync troubleshooting checklist

For a list of database config sync entries and descriptions, refer to the Database entries table.

Collection of files to transmit

This first step is defined in part by the requested command, and secondly, by the associated records in the database. The commands are as follows:

CommandAction
bigpipe config syncTransmits and installs only the existing bigip.conf file.
bigpipe config sync allCollects and transmits all configuration files on the system and installs them on the remote system. This collection is identical to the config save operation.
bigpipe config sync runningTransmits and installs only the in-memory configuration (analogous to bigip.conf).

Both the collection and installation process are entirely data driven. Definitions for each of the above commands exist in the database and determine the actual operation of command. It is possible to completely redefine the operations by changing these definitions.

Transport of collection

A CORBA client process is used to transport the collection. During this process, the client connects to the peer machine and performs authentication based on the web admin username and password. After authentication is complete, the collection file is transported and installed on the peer, a log file is returned, and the log file is printed to the screen.

The collection package is completely inclusive and does not rely on the database or any computer specifications. It uses the hostname to determine whether the install is local or common. A local install results in installation of all files. A common install will only install the files that can be shared between systems.

Installation on a remote machine

The processing of the collection file initiates the installation procedure. This collection file, referred to as a UCS (User Configuration Set), is actually an IM (Installation Manager) package with the pre- and post-scripting defined to perform the necessary actions related to configuration synchronization. You can install the IM package by running the bigpipe config install command or the im command. This command will attempt a debug of the installation component of the config sync process.
