Known Issue

BIG-IP APM access to virtual desktop infrastructure (VDI) resources may sporadically fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an application access remote desktop VDI profile.
  • Connections to the VDI resource receive a redirect or error message from the destination resource.

Impact

The BIG-IP APM system sends TCP resets in response to connection attempts to the VDI destination resource.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to connect to the VDI destination resource using the access profile, the BIG-IP APM system resets the attempts.
  • You can connect to the VDI destination resource by using the access profile after you reboot the affected BIG-IP APM system, or restart the VDI process on the affected BIG-IP APM system.
  • In the /var/log/apm file, you observe log messages similar to the following example:

    notice tmm[<pid>]: 01490500:5: 83f2f53b: New session from client ...
    notice tmm[<pid>]: 01490502:5: 83f2f53b: Session deleted due to user inactivity or errors.
    err vdi[<pid>]: 01490000: {.C.83f2f53b} PersistentConnectCoro error system:111 'Connection refused'
    crit vdi[<pid>]: 01490000: {} An exception is thrown: Sid is too short.

    The following log messages continually repeat:

    err vdi[<pid>]: 01490000: {.S.83f2f53b} PersistentConnectCoro error system:111 'Connection refused'
    crit vdi[<pid>]: 01490000: {} An exception is thrown: call to empty boost::function
