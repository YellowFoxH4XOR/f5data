K000149872: Why A pool member with an active persistence record becomes unreachable during internet key exchange or phase 1

Type
Support Solution
Published
2025-02-25
Updated
2025-02-25
Source
https://my.f5.com/manage/s/article/K000149872

Description

You have configured a persistence profile with the feature 'Action on Service Down: Drop' enabled to load balance IPSec traffic among pool members. The feature 'Match across services' is enabled for the persistence profile. You are observing that the persistence record is not obeyed.

 

Environment

Action on Service Down

Match across services

 

Cause

During phase 1 of the Internet Key Exchange (IKE), a secure, authenticated communication channel between two parties is established by using different messages. The connection is persistent to a pool member throughout this process. If the pool member becomes unavailable, the persistence is broken and the key exchange process in interrupted. 

Configuring the 'match across services' settings permits the persistence to different pool members across different pools. If the pools are using the 'Action On Service Down: Drop' setting, the 'Drop' setting will remove connection table entries associated with it without feedback from the BIG-IP system regarding the connection state when pool member/node fails health checks or is forced offline. When a new connection comes in, even if it matches a persistence record that has not timed out, it will remove the old persistence record and create a new one, therefore, this will re-bind the persistence entry to a new pool member after the offline pool member has been marked down and a new connection has been processed.

 

Recommended Actions 

Consider other options for the 'Action On Service Down' setting. An appropriate option for this scenario is the 'Reselect' option as this re-established client connections by moving them to an alternate pool member without a connection teardown or setup.

 

Additional Information 

Extra care has to be made when configuring 'Action on Service Down' is to be configured for stateful devices such as firewalls or authentication, authorization, and accounting (AAA) since they interrupt traffic during authentication.
