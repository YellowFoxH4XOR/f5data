Description

The IPsec tunnels will appear to establish correctly but only one tunnel will work in the sense that only one selector/network is reachable while the other network is unreachable.
The reason for this is completely invisible because the BIG-IP and pfSense will show the tunnel is up.
Since the racoon.log or ipsec.log only logs tunnel events, not the traffic actually inside the tunnel, there will not be any additional logging to help identify the cause.

When debug2 is enabled (see K77632173: Understanding IPsec IKEv2 negotiation log messages), during the actual tunnel negotiation you will see something like below.

The example comes from IKEv2 ipsec.log:

Environment

  • pfSense
  • IPsec IKEv2

Cause

When multiple selectors (networks) are required between the pfSense and BIG-IP, the default options on pfSense will configure Strongswan in a way the BIG-IP does not currently support.
Refer to K96223265: IPsec configurations with multiple subnets result in one tunnel up at a time

Answer/Recommended Actions

In pfSense configuration, enable "Split Connections" for the P1 (IKE phase 1) connection used for IPsec to the BIG-IP:

  1. From pfSense GUI go to the VPN/IPSEC menu.
     
  2. Select the P1 (IKE phase 1) connection used for IPsec to the BIG-IP and click the edit icon.
     
     
  3. Under "Advanced Options", enable the feature:
        Split connections: Enable this to split connection entries with multiple phase 2 configurations. Required for remote endpoints that support only a single traffic selector per child SA.
    Note: This is not enabled by default - once enabled, the "/usr/local/etc/ipsec.conf" configuration is changed to have the Strongswan config needed to work correctly.
     
     
  4. Click Save
     
  5. Click the Apply Changes to commit the changes:
