K000157040: Portal Access: Oracle PeopleSoft page does not finish loading because of PT_WORKER_MIN_ requests

Type
Support Solution
Published
2025-10-16
Updated
2026-10-29
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000157040

Description

You access an Oracle PeopleSoft application through BIG-IP APM Portal Access, and a page or part of a page does not finish loading. The browser shows a spinning cursor, and the expected content is not displayed.

When you troubleshoot this issue, you may observe the following symptoms:

  • In the Network tab of the browser developer tools (F12), the application requests files whose path contains PT_WORKER_MIN_, for example PT_WORKER_MIN_1.js.

  • The issue occurs only through Portal Access. The application works as expected when you access it directly, without BIG-IP APM.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource and rewrite profile

  • Oracle PeopleSoft back-end application

Cause

The PT_WORKER_MIN_ files are used by PeopleSoft for HTML5 Web Workers. Portal Access does not support HTML5 Web Workers. The Portal Access section of the BIG-IP APM Client Compatibility Matrix states: "Javascript Web Workers or Service Workers do not work as expected when executed through Portal Access."

Answer/Recommended Actions

To work around this issue, add an iRule to the Portal Access virtual server. The iRule answers requests for PT_WORKER_MIN_ files itself, with a small Web Worker script that returns each message it receives.

Important: This iRule is a workaround for an unsupported feature, and it may not resolve the issue in every PeopleSoft application. If it does not, open a support case. You can also consider publishing the application with BIG-IP APM in LTM+APM mode, which does not rewrite the application. For more information, refer to K14079: Converting an access policy to LTM+APM mode.

Impact of procedure: F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.

  2. Go to Local Traffic > iRules > iRule List.

  3. Click Create.

  4. Enter a name for the iRule.

  5. In Definition, enter the following iRule:

    when HTTP_REQUEST {
        if { [HTTP::has_responded] } { return }

        if { [HTTP::path] contains "PT_WORKER_MIN_" } {
            HTTP::respond 200 content {
                addEventListener('message', received);function received(e) {
                postMessage(e.data);}
            } Content-Type "application/javascript"
        }
    }

    Important: Keep the Content-Type "application/javascript" part. Safari, and other browsers that use WebKit (for example, Google Chrome on iOS), do not run a Web Worker script that is sent without a JavaScript content type.

  6. Click Finished.

  7. Go to Local Traffic > Virtual Servers > Virtual Server List, and click the name of the Portal Access virtual server.

  8. Click the Resources tab.

  9. In the iRules section, click Manage.

  10. Move the iRule from Available to Enabled, and click Finished.

  11. Start a new access session, and verify that the page loads.

To back out of this procedure, move the iRule from Enabled to Available.

If the application still does not load, follow K14184: Troubleshooting BIG-IP APM Portal Access applications. If the application uses ECMAScript 2015 (ES6) or later JavaScript, refer to K000130439: Configuring the Rewrite Control List (RCL) to use Modern JavaScript rewriting for Portal Access.

Additional Information

For more information about Web Workers and Portal Access, refer to the Portal Access section of the BIG-IP APM Client Compatibility Matrix for your BIG-IP version.
