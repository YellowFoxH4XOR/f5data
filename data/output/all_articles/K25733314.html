Description

Consider the recommendation in this article to modify and apply changes to a security policy that's already been activated using Ansible playbook.

Environment

  • Ansible 2.8
  • Playbook to push ASM policy changes.

Cause

Ansible playbook cannot apply changes to a security policy that's already been activated.

Recommended Actions

When making changes to an activate security policy, the only way to apply the changes using Ansible 2.8 is by deactivating the policy first. Then, activate it again using the bigip_asm_policy_manage module. For more info, refer to below Ansible playbook examples: 

  • Playbook to deactivate a security policy:
        - name: Task - deactivate policy
          bigip_asm_policy_manage:
             name: "X"
             state: present
             provider: "{{ provider }}"
             active: no
          delegate_to: localhost
          tags: deactivate_policy
     
  • Playbook to activate a security policy:
        - name: Task - activate policy
          bigip_asm_policy_manage:
             name: "X"
             state: present
             provider: "{{ provider }}"
             active: yes
          delegate_to: localhost
          tags: activate_policy

Additional Information

F5’s SYS and LTM Ansible module are more feature rich (close to covering all features), the ASM module is currently limited to policy import, activation/deactivation, and creation. Over time this will change as F5 has a strong partnership with Ansible. the above discussed topic has been discussed in f5-ansible GitHub page. for more info click here.

Update: As of June 1, 2020, the github bug has been reported as resolved and should be available in the 1.4 release.
