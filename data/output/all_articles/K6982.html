Known Issue

This is a result of a known issue. The SSL session priming pool that is responsible for tracking and reusing SSL session information for connections does not efficiently reuse the SSL session ID in the serverssl profile. In some cases, the incidence of reuse of session IDs is little to none.

This behavior causes a delay in the connection, because a new session ID must be established for each connection to the server.

F5 Product Development tracked this issue as CR70478, CR70479, and CR70480, it was fixed in BIG-IP 9.1.3, 9.3.0, and 9.4.1. For information about upgrading, refer to the BIG-IP LTM release notes.
