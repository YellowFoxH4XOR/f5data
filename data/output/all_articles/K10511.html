Known Issue

Note The Route Domain feature takes advantage of the fact that all IP addresses are stored in IPv6 format inside the BIG-IP system. Using the higher number of bits available in an IPv6 address, the BIG-IP system stores an IPv4 address and a Route Domain ID inside a special IPv6 address range reserved for this purpose by F5. This current implementation makes the Route Domain feature compatible with IPv4 addresses only. For more information about route domains, refer to the TMOS Management Guide for BIG-IP Systems, the BIG-IP LTM Implementations guide and K12294: The route domains feature is not compatible with IPv6 addresses.

This is the result of a known issue. The BIG-IP system uses the wrong IPv6 address range for the Route Domain feature. In the affected versions, the BIG-IP system uses the following syntax to build an IPv6 address, which is the equivalent of an IPv4 address and a Route Domain ID:

2610:0000:0C10:F501:0000:<Route Domain ID>:<IPv4 IP upper 2 bytes>:<IPv4 IP lower 2 bytes>

The <Route Domain ID> entry is the hexadecimal equivalent to the Route Domain ID, and the <IPv4 IP upper 2 bytes> entry and <IPv4 IP lower 2 bytes> entry are the hexadecimal equivalent to the IPv4 IP address. For example, an equivalent IPv6 address with an IP%ID notation of 10.0.0.2%10 displays as follows:

2610:0000:0C10:F501:0000:000A:0A00:0002

This construction is incorrect. The 2610:0000:0000:0000:0000:0000:0000:0000/32 address range does not belong to F5 Networks. The Route Domain feature should use the 2620:0000:0C10:F501:0000 prefix, which is part of the correct IPv6 address range reserved by F5 Networks.

This issue has no symptoms. However, some BIG-IP systems deployed in an IPv6 environment may block traffic to and from the 2610:0000:0C10:F501:0000/80 IPv6 address range.

F5 Product Development tracked this issue as CR128078 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.
