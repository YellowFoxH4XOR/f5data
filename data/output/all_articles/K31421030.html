Description

BIG-IP DNS Responds with NXDOMAIN for an existent domain when Query Type does not Match a Wide IP Resource Record type.

  • NXDOMAIN response for a valid domain
  • Negative caching on LDNS

Environment

  • At least one of the following
    • DNS Express
    • Load Balanced Pool attached to Listener
    • DNS Caching
  • Wide IP Configured
  • DNS profile with Unhandled Query Action set to Allow
    • Applied to the BIG-IP DNS Listener.

Cause

ID 644192

    Recommended Actions

    Upgrade to a version where ID 644192 is Fixed (note that there are two different fixes - one as a db key, and one as a configuration command - see below) For versions where 644192 is fixed, PRIOR to 16.1.0, the fix is implemented as a system db key. To enable the functionality, set the key to a value of 'enabled', for example:

    tmsh modify /sys db gtm.allownxdomainoverride value enable

    In versions 16.1.0 and later, the setting was migrated to a global configuration setting instead:

    tmsh modify gtm global-settings general allow-nxdomain-override

    Important - if you enable the feature in a version of BIG-IP software the uses the DB key (versions prior to 16.1.0), and then upgrade to a version that uses the tmsh command, the functionality will not be automatically migrated, and you will need to enable the feature using the tmsh command after upgrading. This issue is being tracked as bug ID1351969

    If you are unable to upgrade, and you are running a version of code where ID 708421 is Fixed, you may use the following iRule:

    Note: Refer to the link ID 708421 to identify software versions that have a fix. When ID 708421 is resolved, all of the above configuration may be replaced with the following:

    1. Create the following irule

      ltm rule is_wideip {
      when DNS_RESPONSE {
        # Looking only for NXDOMAIN type responses.
        if { ([DNS::ptype] eq "NXDOMAIN") } {

          #Set original question type, so that it can be reset later for proper client response
          set orig_type [DNS::question type]

          #Alter the question type
          DNS::question type A

          # If this actually exists as a WideIP, then change to RCODE=0 (NOERROR)
          if {[DNS::is_wideip [DNS::question name]]} {
            DNS::header rcode NOERROR
          }
          #Reset question type for client response
          DNS::question type $orig_type
        }
      }

    2. Apply ltm rule is_wideip to all gtm listener objects.

    If you are running a version of BIG-IP Software where ID 708421 nor ID 644192 are fixed, consider the following:

    The following will:

    • Create a sync-only device-group (/Common/dns_sync-only)
    • Create a system folder which uses that device-group (/dns_sync)
    • Create a data-group (/dns_sync/dg_wideip) with the domain name of every WideIP
    • Create the following iRule and apply it to any 'Listener' you desire. (likely all of them)
    1. SSH to log into the (tmos) # prompt of the BIG-IP
    2. Prepare to load the following configuration into the terminal:

      load sys config from-terminal merge

    3. Copy and paste the following configuration into the terminal

      ltm rule is_wideip {
      when DNS_RESPONSE {
          # Looking only for NXDOMAIN type responses.
          if { ([DNS::ptype] eq "NXDOMAIN") } {
          # If this actually exists as a WideIP, then change to RCODE=0 (NOERROR)
              if {[class match -- [DNS::question name] equals /dns_sync/dg_wideip]} {
                  DNS::header rcode NOERROR
              } 
          }
      }
      }
      sys icall handler periodic dnsx_zone_wip_dg_handler {
          interval 60
          script dnsx_zone_wip_dg
      }
      sys icall script dnsx_zone_wip_dg {
          app-service none
          definition {
              set cm_devices {}
              set devicegroup_name "dns_sync-only"
              set foldername "/dns_sync"
              set datagroup_name "${foldername}/dg_wideip"
              set dg_records ""
              set records {}
              set wips {}
              # Find all device names
              set devices [tmsh::get_config cm device]
              foreach device $devices {
                  lappend cm_devices [tmsh::get_name $device]
              }
              # Determine if sync-only device-group exists
              if {! ([tmsh::list cm device-group] contains $devicegroup_name) } {
                  #puts "group $devicegroup_name does not exist"
                  tmsh::create cm device-group dns_sync-only \{ auto-sync enabled type sync-only devices replace-all-with \{ $cm_devices \} \}
              }
              # Create a folder and assign it to the above sync-only device-group
              if {!([tmsh::list sys folder /*] contains $foldername)} {
                  #puts "folder $foldername does not exist; creating it"
                  tmsh::create sys folder $foldername device-group $devicegroup_name traffic-group traffic-group-local-only
              }
              # Create $datagroup_name datagroup only if it does not exist; typically first-run
              if { [catch {tmsh::list ltm data-group internal $datagroup_name } err]} {
                  #puts stderr "datagroup does not exist; ltm data-group internal $datagroup_name"
                  tmsh::create ltm data-group internal $datagroup_name type string
              }
              set dglist [tmsh::get_config ltm data-group internal $datagroup_name records]
              catch {set dg_records [tmsh::get_field_value [lindex $dglist 0] "records"]}
              foreach record $dg_records {
                  # Create a list of datagroup objects
                  lappend records [tmsh::get_name $record]
              }
             foreach x [tmsh::get_config auth partition] {
              set current_partition "/[lindex [split $x " "] 2]"
              tmsh::cd $current_partition
              set wiplist [tmsh::get_config gtm wideip ]
              foreach wip $wiplist {
                lappend wips [tmsh::get_name $wip]
                }
              }
              # If there are multiple resource record types; concat unique domain names
              set wips [lsort -unique $wips]
              foreach wip $wips {
                  # Does wip exist in a DNS Express zone?
                  if {[lsearch -exact -ascii $records $wip] == -1} {
                      # Add $wip to $datagroup_name
                      tmsh::modify ltm data-group internal $datagroup_name records add \{ $wip \}
                  }
              }
              unset cm_devices
              unset devicegroup_name
              unset foldername
              unset datagroup_name
              unset dg_records
              unset records
              unset wips
          }
      }
    4. Press 'Ctrl + d' to submit the configuration.
    5. Apply 'ltm rule is_wideip' to any (likely all) DNS Listener objects
      TMUI -> DNS -> Listeners -> `click` the listener -> iRules

    Additional Information

    "Unhandled Query Actions" is enabled by default, the request is sent to the next viable DNS processing service.

    When the BIG-IP DNS and GTM systems process DNS requests, there are several systems which may actually process and respond to that request. See K14510: Overview of DNS query processing on BIG-IP systems for more details.

    When a Resource Record exists only as a Wide IP, other DNS systems which are also Authoritative for the requested zone will respond with an NXDOMAIN when that domain is requested.
