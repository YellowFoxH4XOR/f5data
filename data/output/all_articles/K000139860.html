K000139860: The tcp-ack-ts vector with lower thresholds is triggered after upgrading to v17.1

Type
Support Solution
Published
2024-05-31
Updated
2025-08-25
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.1.X, 17.1.1
Source
https://my.f5.com/manage/s/article/K000139860

Description

After an upgrade from v15 or v16 to v17.1, may encounter service outages caused by low thresholds for the TCP ACK (TS) DoS vector. The upgrade process retains old threshold values(Detection EPS Threshold: 200, Mitigation EPS Threshold: 100), which are too low compared to the new defaults. These low thresholds trigger frequent DoS attack detections, leading to disruptions in service. May find logs like next: 

/var/log/ltm:
LTM1.example err tmm1[22693]: 01010252:3: A Enforced Device DOS attack start was detected for vector TCP ACK (TS), Attack ID 1317766602.
LTM1.example notice tmm1[22693]: 01010253:5: A Enforced Device DOS attack has stopped for vector TCP ACK (TS), Attack ID 1317766602.
LTM1.example err tmm1[22693]: 01010252:3: A Enforced Device DOS attack start was detected for vector TCP ACK (TS), Attack ID 2171780961.
LTM1.example notice tmm1[22693]: 01010253:5: A Enforced Device DOS attack has stopped for vector TCP ACK (TS), Attack ID 2171780961.
LTM1.example err tmm1[22693]: 01010252:3: A Enforced Device DOS attack start was detected for vector TCP ACK (TS), Attack ID 3888117717.
LTM1.example notice tmm1[22693]: 01010253:5: A Enforced Device DOS attack has stopped for vector TCP ACK (TS), Attack ID 3888117717. 

  • After upgrade:
    #tmsh list security dos device-config {dos-device-vector {tcp-ack-ts } }
    ...
    default-internal-rate-limit 200 <----
    detection-threshold-percent 500
    detection-threshold-pps 100 <----
    tscookie enabled

  • New default values from BIG-IP AFM DoS vectors according to K41305885:

    #tmsh list security dos device-config {dos-device-vector {tcp-ack-ts } }
    ... default-internal-rate-limit 300000 <----
    detection-threshold-percent 500
    detection-threshold-pps 200000 <----
    tscookie enabled

Environment

  • AFM provisioned

  • Upgrade from v15 or v16 to v17.1

   Cause

The TCP BADACK Flood vector is deprecated from v17.1, but has been redesigned as TCP ACK (TS). When the device is upgraded, the thresholds defined for the TCP BADACK flood vector will be applied to the TCP ACK (TS) vector, with TScookie enabled by default. 

  • Note: When upgrading from a system where DoS device protection is configured in bigip.conf(a deviation from the standard, such as modifying any values on Dos device-config), the TCP ACK(TS) vector retains the old thresholds from the TCP BADACK flood vector.

    # grep -i dos-device-config bigip.conf | wc -l
    1

  • In contrast, when upgrading from a default configuration with no dos-device-config in bigip.conf, TScookie option is disabled, and the new default threshold will be set.

    # grep -i dos-device-config bigip.conf | wc -l
    0

Recommended Actions

  • This is expected based on the current migration process.

  • It is recommended to change the threshold to the new defaults or any reasonable values accordingly.For example: #tmsh modify security dos device-config dos-device-config dos-device-vector { tcp-ack-ts {default-internal-rate-limit 300000 detection-threshold-pps 200000}}
