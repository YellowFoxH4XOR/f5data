Description

 
System does not boot due to filesystem corruption / boot error


Environment

  BIG-IP v11-v15


Cause

K73827442: Forcing a file system check on the next system reboot (12.x - 17.x) has good information which should clean most systems most of the time. However, in some cases the filesystem corruption may require additional steps to fully clean.


Recommended Actions

See K4178:Restarting the BIG-IP system in single-user mode (GRUB 0.97) and K14662: Restarting the BIG-IP system in single-user mode (GRUB2) for booting into single-user mode.

Use init=/bin/bash instead of single on the GRUB command-line edit.   That should boot you into a bash environment.
 
Once within bash: /sbin/fsck -y /dev/mapper/vg--db--vda-set.1.root (use the name for whichever filesystem is flagged with errors).

 And when ready to reboot:
    
  sync
  exit                              Note: this command may display a kernel panic on the terminal, and then reboot the device.  That's expected.
    
The system should reboot normally. However, additional filesystem cleaning may still be required. Contact F5 Support if you continue to see errors.
