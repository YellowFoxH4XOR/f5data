Description

  • NGINX Plus may fail to start or experience service impact with the following error message in the logs:
nginx: [crit] ngx_slab_alloc() failed: no memory in upstream zone "<zone_name>"
  • This error can affect multiple upstreams and may also impact the NGINX dashboard and related services. Running nginx -t may show:
nginx: the configuration file <path> syntax is ok
nginx: [crit] ngx_slab_alloc() failed: no memory in upstream zone "<zone_name>"
nginx: configuration file <path> test failed

Environment

  • NGINX Plus
  • Upstream
  • Memory
  • Zone Directive 

Cause

Insufficient memory allocated to the upstream zone. The zone directive in the upstream block reserves memory for storing not only the IP addresses of upstream servers, but also their state, health check results, and DNS resolution data. If the allocated memory is too small for the number of servers and associated metadata, NGINX cannot allocate the required resources, resulting in the no memory in upstream zone error.

Recommended Actions

  • Increase the memory allocated to the affected upstream zone. As a general rule, double the current allocation (e.g., from 256k to 512k).
  • Steps to resolve:
    1. SSH into the host running NGINX.
    2. Locate and edit the configuration file containing the affected upstream block.
    3. Update the zone directive to a higher value, for example:
      upstream backend {
zone myexample 512k;
...
}
    4. Save the configuration file.
    5. Test the configuration: nginx -t
    6. Reload NGINX to apply the changes: nginx -s reload
  • Ensure that the memory allocated to each upstream zone is proportional to the number of servers and amount of state/health data being tracked. Upstreams with servers defined by FQDN or with frequent DNS resolution cycles may require more memory.
  • Monitor NGINX logs for any recurrence of this error and adjust allocation as needed.
