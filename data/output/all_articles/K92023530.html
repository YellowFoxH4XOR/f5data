Description

The BIG-IP is sending connection resets when using TLS 1.3 on the Virtual Server.

RST cause on capture file shows as: [F5RST(peer): SSL error (close_notify(0))]

RSTs happen after Application Data is being sent encrypted already, not during SSL handshake, for example:

10.0.0.1 → 192.168.1.1   TCP OUT s1/tmm0 : 64502 → 443 [SYN]
192.168.1.1 → 10.0.0.1   TCP IN  s1/tmm0 : 443 → 64500 [SYN, ACK]
10.0.0.1 → 192.168.1.1   TCP OUT s1/tmm0 : 64500 → 443 [ACK]
10.0.0.1 → 192.168.1.1   TLSv1 OUT s1/tmm0 : Client Hello
192.168.1.1 → 10.0.0.1   TLSv1.3 IN  s1/tmm0 : Server Hello, Change Cipher Spec, Application Data, Application Data, Application Data, Application Data
10.0.0.1 → 192.168.1.1   TCP OUT s1/tmm0 : 64500 → 443 [ACK]
10.0.0.1 → 192.168.1.1   TLSv1.3 OUT s1/tmm0 : Change Cipher Spec, Application Data
10.0.0.1 → 192.168.1.1   TLSv1.3 OUT s1/tmm0 : Application Data
192.168.1.1 → 10.0.0.1   TLSv1.3 IN  s1/tmm0 : Application Data, Application Data
192.168.1.1 → 10.0.0.1   TLSv1.3 IN  s1/tmm0 : Application Data, Application Data
10.0.0.1 → 192.168.1.1   TCP OUT s1/tmm0 : 64500 → 443 [ACK]
10.0.0.1 → 192.168.1.1   TCP OUT s1/tmm0 : 64500 → 443 [ACK]
10.0.0.1 → 192.168.1.1   TCP OUT s1/tmm0 : 64500 → 443 [FIN, ACK]
10.0.0.1 → 192.168.1.1   TCP OUT s1/tmm0 : 64500 → 443 [RST, ACK] [F5RST(peer): SSL error (close_notify(0))]
192.168.1.1 → 10.0.0.1   TCP IN  s1/tmm0 : 443 → 64500 [FIN, ACK]

Environment

  • Using TLS1.3
  • Virtual Server RSTs connections

Cause

Issue is being tracked with Bug ID 1036013: BIG-IP systems may terminate connections prematurely when a TLS close-notify alert is received.

When backend server sends TLS close-notify alert, BIG-IP may terminate connection prematurely without forwarding HTTP response.

In an LTM VS with clientssl and serverssl profile, when serverside connection is using TLS 1.3, and when server sends a TLS Alert Close Notify without sending a TCP FIN very shortly afterwards (within 0.1ms or so sometimes), LTM sometimes sends a FIN followed immediately by a RST ("RST cause: [2c177f9:3385] SSL error (close_notify(0))" on serverside, and "RST cause: [2c177f9:3385] {peer} SSL error (close_notify(0))" on clientside) on both the serverside and the clientside, without forwarding the actual server's HTTP response to the clientside.

Recommended Actions

This ID is not resolved at the time of publication of this article. Possible workarounds include:

  • Use TLS 1.2 on serverside to avoid the issue.
  • Use "Connection: keep-alive" on client side to avoid the issue.
  • Use a lower version not affected by this ID that still supports TLS1.3 on server side. K10251520: BIG-IP support for TLS 1.3.
