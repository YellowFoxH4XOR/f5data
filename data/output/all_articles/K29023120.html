Description

Facing a problem with the automation script written for out AFM dedicated devices.
The script worked fine on earlier BIG-IP version but stop working after upgrade, but only in specific situation.
The aim of the script is to update specific network objects with a list of IP addresses.
When the number of IP addresses is not really big (several hundred IP), the devices is successfully updated whatever the BIG-IP version.
But when the IP list is much bigger (around several thousand entries), the update process doesn't work anymore on more recent releases of BIG-IP versions.
The script times out with the following restjavad error displayed/recorded:

Failed to update device: 400 Unexpected Error: Bad Request for uri: https://ltm.example.com:443/mgmt/tm/security/firewall/address-list/~Common~custom_deny_list/
Text: '{"code":400,"message":"Expected exception was null","originalRequestBody":"{\\"code\\":400,\\"message\\":\\"remoteSender:192.0.2.1, method:PUT \\",\\"originalRequestBody\\":\\"{\\\\\\"addresses\\\\\\": [\\\\\\<very long list of IPs>\\\\\\]}}}

Environment

  • Using Script to modify Allow/Deny lists with several thousand IPs
  • After upgrade to more recent releases of BIG-IP versions
Cause

ID952521

Recommended Actions

An option that may workaround this issue is to give restjavad more time to complete the scripted instructions:
  1. Update to a version with ID858189 implemented (see "Fixed In") which adds the option to allow more time for the REST task to complete
  2. Use the following commands to increase REST timeouts:
    • # tmsh
    • (tmos)# modify sys db restjavad.timeout value 120
    • (tmos)# modify sys db icrd.timeout value 120
    • (tmos)# save sys config
    • (tmos)# restart sys service restjavad
  3. Attempt the scripted configuration update again
