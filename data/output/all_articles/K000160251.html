Description

The BIG-IP system drops TCP connections due to the aggressive mode sweeper being triggered. Log messages similar to the following appear repeatedly:

011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (global memory) (global memory) Connections killed

Additional symptoms may include failed SSL handshakes and application-level connection drops. Analysis shows that the APM "access" component is consuming an abnormally high percentage of TMM memory (60% or more), leading to memory exhaustion and aggressive connection eviction.

Environment

  • Product: BIG-IP APM
  • Version: 17.5.0, 17.5.1, 17.5.1.2, 17.5.1.3
  • Configuration: Default eviction policy in use
  • Symptom: Aggressive mode sweeper logs, high TMM memory usage by "access" component (60%+ of total TMM memory)

Cause

Bug ID 1975885:  https://cdn.f5.com/product/bugtracker/ID1975885.html   Massive M_ACCESS string leak in TMM.

How to Identify This Issue

  1. Check TMM memory usage for the "access" component: 
    tmctl memory_usage_stat | grep -E "access|Totals"
  2. Calculate the percentage of TMM memory consumed by "access":
    • Normal: The "access" (APM) component typically consumes less than 5% of total TMM memory
    • Affected by this bug: The "access" component consumes 60% or more of total TMM memory
  3. Check system logs for aggressive sweeper activity: 
    grep "Aggressive mode sweeper" /var/log/ltm*
    • Look for repeated connection kills occurring within short time intervals
    • High frequency of sweeper events (multiple occurrences per minute) indicates memory pressure
  4. Verify your BIG-IP version is in the affected range:
    • Affected versions: 17.5.0, 17.5.1, 17.5.1.2, 17.5.1.3
    • If running one of these versions AND seeing high "access" memory percentage, this bug is likely the cause

Answer/Recommended Actions

  • Permanent Resolution:
    1. Upgrade BIG-IP to a fixed version where the memory leak is resolved. Bug ID 1975885 shows that this is fixed in versions: 17.5.1.4 and 21.0.0.
  • Temporary Mitigation:
    1. Reboot the affected BIG-IP system to reclaim the leaked memory.
      Note: This will temporarily resolve the issue, but the memory leak will recur until the system is upgraded.
  • Monitoring:
    • After reboot, monitor TMM memory usage and logs for recurrence of aggressive sweeper events.
    • Plan and schedule the upgrade as soon as possible to prevent further service impact.

Additional Information

  • The "access" (APM) component should normally consume less than 5% of total TMM memory. Usage of 60% or more is abnormal and indicative of the bug.
  • When TMM memory is exhausted, the aggressive mode sweeper forcibly kills active connections to free resources, resulting in application disruptions.
  • The issue is not related to configuration or policy changes, but is a software defect in the affected versions.
