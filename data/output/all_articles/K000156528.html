K000156528: Authentication Failure or Login Loops Due to Non-Compliant Cookies with F5 Distributed Cloud WAAP

Type
Support Solution
Published
2025-09-18
Updated
2025-09-18
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000156528

Description

When accessing a site published via F5 Distributed Cloud, authentication with username and password may result in Authentication Failure or login loops. Analysis of HAR files and packet captures shows that session cookies are not received by the backend during problematic sessions.

Environment

  • Product: F5® Distributed Cloud (XC)
  • No evidence of L3 devices modifying or inspecting L7/cookie data

Cause

The root cause is non-HTTP-compliant cookies present in the request. Specifically, some cookie values do not conform to RFC 6265 section 4.1.1, such as:

  • Raw JSON used as a cookie valuename={"value_source":"example.com",...}
  • Unencoded double quotes within a cookie valuename="value1":"value2"

F5 Distributed Cloud processes cookies differently if they are not RFC-compliant. As a result, these cookies may be dropped or not forwarded to the backend server, causing authentication failures.

Recommended Actions

  • Review all application-set cookies to ensure their values comply with RFC 6265 section 4.1.1.
    • Cookie values must contain only allowed US-ASCII characters:
      • Allowed: most printable ASCII characters except control characters, whitespace, double quotes (unless wrapping), comma, semicolon, and backslash.
      • Not allowed: raw JSON objects/arrays; unencoded double quotes; spaces; semicolons; commas; or backslashes.
    • If special characters are required in a cookie value, encode them appropriately (e.g., URL encoding).
  • After correcting all non-compliant cookie formats, retest authentication.
  • No changes are needed on F5 Distributed Cloud if all cookies are compliant.
  • For further details on valid cookie syntax and character sets see RFC 6265 section 4.1.1.

Additional Information

The syntax shown in RFC 6265 section 4.1.1 is written in ABNF (Augmented Backus–Naur Form), which is a formal grammar notation.
