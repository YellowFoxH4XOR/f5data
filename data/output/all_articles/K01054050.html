Description

Available pool members does not receive traffic, and load balance skewed sporadically. 
The virtual server has iRule with LB::down command.
 

Environment

  • BIG-IP 
  • Virtual server 
  • iRule with LB::down command
  • Multiple pool members

Cause

Bug ID910213
 

Recommended Actions

There are many factors which cause load balance skew described in: K10430: Causes of Uneven Load balancing

To determine the actual cause, please generate fresh qkview within 1 day after issue is occurred, and raise support case.
We will check and confirm and where it is possible we provide you EngHF.

NOTE: v12.1.5.2 - 12.1.6.x are affected, please upgrade to supported versions: K5903: BIG-IP software support policy
Additional Information
 

Additional Information

When this issue start, you might see inconsistent message between mcpd and tmm, indicating mcpd and tmm communication is failing in /var/log/ltm:

mcpd[<PID>]: 01070727:5: Pool /<partition_name>/<pool_name> member /<partition_name>/<pool_member_name>:<port> monitor status up. [ /<partition_name>/<monitor_name>: up ]  [ was down for Xhr:Xmin:Xsec ]

tmm*[<PID>]: 01010028:3: No members available for pool /<partition_name>/<pool_name>
or 

When a pool member is marked down with monitor failure (logged the below log in /var/log/ltm), Virtual server is sending traffic to the pool member in the log below:
 
mcpd[<PID>]: 01070638:5: Pool /<partition_name>/<pool_name> member/<partition_name>/<pool_member_name>:<port> monitor status down. [ /<partition_name>/<monitor_name>: down; last error: /<partition_name>/<monitor_name>: Unable to connect @YYYY/MM/DD hh:mm:ss.  ]  [ was up for Xhr:Xmin:Xsec ]
