Description

BIG-IP VE stops receiving and sending traffic when it detects VF (Virtual Function) reset initialized by PF (Physical Function) on the hypervisor. BIG-IP will not able to recover until TMM is manually restarted.

PF initiated reset messages similar to below are logged under /var/log/tmm:

notice ixlv[00:06.0]: VC Complete v_opcode 17 v_retval 0
notice ixlv[00:06.0]: PF initiated reset!

Environment

  • BIG-IP VE
  • TMM SR-IOV ports using ixlv or iavf driver (Refer to K17204: BIG-IP VE NIC adapters that support SR-IOV for supported NIC)

Cause

If the host machine initiates PF reset, ixlv/iavf drivers on BIG-IP VE detect the reset, and the device stops handling traffic. The issue is tracked with ID 760496 (ixlv) and ID 1144817 (iavf).

For example, PF reset is initiated on the host machine, by marking the interface up or down by running the commands, or by disabling the trust mode of SR-IOV VF.

Recommended Actions

To work around the issue, reboot the device or restart the TMM process by running the command:

# bigstart restart tmm

Note: Restarting TMM under this condition may generate a core file under /var/core/ directory. You may delete the file as required.

/var/log/messages

notice logger[6932]: Started writing core file: /var/core/tmm.0.bld0.27.14.core.gz for PID 701
notice logger[7742]: Finished writing 564316067 bytes for core file: /var/core/tmm.0.bld0.27.14.core.gz for PID 701

 

On versions with the fix of ID 760496 (ixlv) and ID 1144817 (iavf), a DB variable ve.ndal.exit_on_ue was introduced to enable/disable device restart on PF reset.
