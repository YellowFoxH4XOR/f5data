Known Issue

The BIG-IP system may fail to notify the remote IPsec peer to delete the Internet Key Exchange (IKE) security association (SA) when you modify an associated IPsec profile.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with an IPsec IKE peer.
  • The BIG-IP system is configured with an IPsec tunnel that uses an IPsec Interface profile.
  • The BIG-IP system has established the IPsec tunnel with a remote IPsec IKE peer.
  • You modify the IPsec Interface profile associated with the tunnel.

When you modify the tunnel's associated IPsec Interface profile, the BIG-IP system deletes the IKE phase 2 SA locally. However, the BIG-IP system fails to send the remote IKE peer an Internet Security Association and Key Management Protocol (ISAKMP) Delete message to remove the SA. As a result, if the remote IKE peer is configured to initiate the affected tunnel, the remote IKE peer will not attempt to re-establish a new tunnel because the previous (now invalid) SA is still present.

Impact

The affected IPsec tunnel may experience a traffic disruption.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • An IPsec tunnel experiences a traffic disruption after you modify the associated IPsec Interface profile.

Workaround

To work around this issue, you can delete the now invalid SA on the remote IPsec peer.

Note: The remote IPsec peer system can be another BIG-IP system or third-party device.

When the remote peer is also a BIG-IP system, you can delete the now invalid SA on the remote IPsec peer by performing the following procedure on the remote BIG-IP system:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Display the SAs that have been negotiated with the IPsec peer, and determine the SPI of the expired or invalid SA by using the following command syntax:

    show /net ipsec ipsec-sa dst-addr <IPsec_peer_addr>

  3. Delete the invalid SA by using the following command syntax:

    delete /net ipsec ipsec-sa spi <invalid_spi>

  4. Save the change by typing the following command:

    save /sys config

Alternatively, when both peers are BIG-IP systems, you can also work around this issue by restarting the tmipsecd service. To do so, perform the following procedure:

Impact of workaround: Restarting the tmipsecd service causes all IPsec tunnels to be re-established and result in a temporary traffic interruption for all tunnels.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To restart the tmipsecd service, type the following command:

    restart /sys service tmipsecd
