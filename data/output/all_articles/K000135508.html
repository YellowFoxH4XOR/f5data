Description

An application requires to increases Idle Timeout value from default 300 seconds to 400 seconds. What is the  impact on BIG-IP like CPU and memory high utilization or other performance issue by this change?

Environment

  • LTM
  • Idle sessions timeout

Cause

None

 Recommended Actions

Each Session uses some resources and Idle session are removed after default timeout.  If a session idle time out value is changed from 300 to 400 for example, it will result in the  idle sessions to stay 100 sec longer on the BIGIP and this consumes resources. There will most likely result in increased number of current connections count.

Care must be taken to review the number of session on the VS before making the change and monitor it after making the change.

For example if we says that we have the following statistics from the VS by using command: tmsh show system ltm virtual <virtual_server_name> 

Current Connections = 347 

Maximum Connections = 1.7K

Please note that current number of connections are 347, and the maximum number of connections handled by this VS were 1.7k.  Please note these numbers as these will be a baseline to check the difference after the change.

It is recommended to keep monitoring the current connections and Maximum connections numbers, a very large increase in these numbers can be of concern, however a modest increase is expected after idle timeout change.  It is also recommended to keep monitoring CPU and memory use after making the change.
