K000134941: Warning messages may be shown in restjavad log if certificates are lost under /shared/em/ssl.crt/

Type
Support Solution
Published
2023-06-14
Updated
2023-06-15
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.7
Source
https://my.f5.com/manage/s/article/K000134941

Description

When you set up HA group and perform the 1st configsync, BIG-IP will create ssl certificate under /shared/em/ssl.crt/, and exchange this certificate with HA peer device.
These certificates are used for the 1st ConfigSync communication.
If these ssl certificates are deleted or lost, the certificates couldn't be re-created by re-setup HA.
 

Symptoms

After HA group perform the 1st configsync, ssl certificates (.crt files) of both HA peers can be seen under /shared/em/ssl.crt/.

For example, Deivce A (1.1.1.3) and Device B (1.1.1.4) on HA group, and perform the 1st configsync, 1.1.1.3.crt and 1.1.1.4.crt should exist under /shared/em/ssl.crt/ at both Deivce A and Deivce B.
If these crt files are missing, you may get warning messages in restjavad log.
For example,
[8100/tm/shared/bigip-failover-state BigipFailoverStateWorker] Failed to discover 1.1.1.3: java.lang.IllegalStateException: Failed to update (post or patch) certificate 1.1.1.3 on device 1.1.1.4.
Or
[8100/tm/shared/bigip-failover-state BigipFailoverStateWorker] Failed to get gossip peer group members from standby: com.f5.rest.common.RestRequestSender$HttpException: java.net.ProtocolException: status:401, body:<html...>
 

Environment

  • LTM
  • HA Group
 

Impact

No impact on HA configsync and active-standby failover
 

Recommended Action

SSLOFIX is an F5-developed tool that can be used to diagnose and repair control-plane problems with BIG-IP and SSL Orchestrator deployments.

For fixing this issue by SSLOFIX, the steps are shown as below

1. The first one needs to enable SSH passwordless access as defined in K13454. In short, from the Active unit, run:
# ssh-copy-id root@x.x.x.x
Where x.x.x.x is the IP of the Standby unit. Feel free to repeat the procedure in reverse (run the same command on the Standby unit but pointing to the IP x.x.x.x of the Active unit).

2. Then, run the script in Diagnostic mode:
# sslofix -H x.x.x.x -D <device-group-name> --diagnostic
Where x.x.x.x is the IP of the Standby unit and <device-group-name> is the name of the Failover device group. You can run on both units, if desired (just make sure to change the IP to the peer unit IP).

3. If error is found on diagnostic above, for fix it, run the same 'sslofix' command but without the "--diagnostic" on the Active unit.
# sslofix -H x.x.x.x -D <device-group-name>

4. If errors are still found after running the script without the "--diagnostic" flag then add flag "-f" as below:
# sslofix -H x.x.x.x -D <device-group-name> -f
