K32258102: URLs in HTTP 308 redirect are not rewritten by APM Portal Access

Type
Knowledge
Published
2019-05-30
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 15.0.0, 14.0.0, 13.1.1, 13.1.0, 13.0.1, 13.0.0, 12.1.4, 14.1.0, 12.1.2, 12.1.1, 12.1.0, 12.1.3
Source
https://my.f5.com/manage/s/article/K32258102

Issue

Description

Applications accessed via Portal Access will fail if the application uses 308 redirects.

Environment

  • BIG-IP APM
  • Portal Access
  • Web application that uses 308 redirects

Cause

Portal Access doesn't support HTTP 308 Permanent Redirect and does not rewrite URLs in the redirect response.

Recommended Actions

Change the application to use no 308 redirects by using an iRule to modify the 308 to a supported status code:

  1. Log in to the Configuration utility (GUI).
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. In the Name box, type a name for the iRule.
  5. In the Definition box, enter an iRule that changes the 308 status code to one that is supported. The following example rule changes the 308 to a 302:

    when HTTP_REQUEST_SEND {
    TCP::collect 64
    }
    when SERVER_DATA {
    if {[findstr [TCP::payload 12] "308"] == "308"} {
      TCP::payload replace 9 3 "302"
    }
    }
     
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click Edit under the Resources column for the virtual server.
  9. Under iRules, click Manage.
  10. Click the newly created iRule in the Available box and move it to the Enabled box.
  11. Click Finished.
