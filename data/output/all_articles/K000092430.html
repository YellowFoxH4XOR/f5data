K000092430: Restarting tomcat due to syslog when upgrading from v12.1.6 to v14.1.5

Description

Restarting tomcat due to syslog when upgrading from v12.1.6 to v14.1.5


 Environment

-BIG-IP upgrade from v12.1.6 to v14.1.5

-tomcat on reboot loop

-syslog config issue

 Cause

It looks to have two issues here.


First is an SELinux issue, likely caused by ID878365 .


type=AVC msg=audit(2022-09-21T21:51:27PDT:91281): avc: denied { search } for pid=2454 comm="syslog-ng" name="tomcat" dev=dm-1 ino=753665 scontext=system_u:system_r:syslogd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=dir

(note 'unlabeled_t')



Base on boot marker they seem to have upgraded to 14.1.5, then rolled back to 12.1.6, then upgraded to 14.1.5.1.



Second, their syslog include statement is problematic:


sys syslog {

include "source s_solutionary { internal(); unix-dgram(\"/dev/log\"); }; destination d_solutionary { tcp(\"10.1.2.75\" port(514)); }; filter f_solutionary { level(info) and facility(local3); }; log { source(s_solutionary); filter(f_solutionary); destination(d_solutionary); };"

remote-servers {

/Common/remotesyslog2 {

host 10.100.249.115

}

/Common/remotesyslog3 {

host 10.100.249.186

}

}

}

Specifically:


unix-dgram(\"/dev/log\");

After the change to systemd, syslog-ng doesn't read directly from /dev/log, so they probably want to take that out.


 Recommended Actions

1. Boot back to 12.1.6 and do an SELinux relabel:


touch /.autorelabel


reboot



2. Delete the existing 14.1.5.1 boot location


tmsh delete sys sof volume HD1.3


3. Remove the syslog include statement from the 'sys syslog' configuration


tmsh modify sys syslog include none

tmsh save sys config



4. Upgrade to 14.1.5.1 in a new boot location - now it should work


The SELinux relabel and removal of the syslog include could also work in the existing 14.1.5.1 boot location, but I'd be less confident about that. Best to use a new boot location.
