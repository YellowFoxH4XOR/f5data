Issue

Error Message

httpd<pid>: [error] <client_ip> AUTHCACHE Error processing cookie <cookie_string> - Cookie impersonation detected from remote IP

In this error message, note the following:

  • <pid> is the httpd process ID.
  • <client_ip> is the remote client IP address.
  • <cookie_string> is the 40-byte BIGIPAuthCookie cookie value.

For example:

httpd[32157]: [error] [client 172.16.65.11] AUTHCACHE Error processing cookie 37463B53B8C5A55F85DE7A0EB7FEC00AA48C3EC5 - Cookie impersonation detected from remote IP 172.16.65.11 to remote IP 172.16.65.45, referer: https://172.24.65.66/xui/

httpd[2743]: [error] [client 172.16.65.11] AUTHCACHE Error processing cookie 37463B53B8C5A55F85DE7A0EB7FEC00AA48C3EC5 - Cookie impersonation detected from remote IP 172.16.65.11 to remote IP 172.16.65.45, referer: https://172.24.65.66/tmui/tmui/system/settings/redirect.jsp

Message Location

You may encounter this message in the following location:

  • The /var/log/httpd/httpd_errors file

Description

This message occurs when any of the following conditions are met:

  • The client web browser connects to the Configuration utility through a proxy device, and the client's source IP address changes during the session.
  • An iControl application is used to connect to the Configuration utility from multiple client workstations using the same login credentials.

The BIG-IP system implements an authentication cache for all Configuration utility requests. The cache works by storing information such as a username hash and the remote client's IP address in the memory file-system. When the client sends a new request, it authenticates to the cache by submitting a BIGIPAuthCookie to the BIG-IP system. In the event that the client's source IP address changes, the BIG-IP system invalidates the cache entry and terminates the Configuration utility session. This behavior is by design and is intended to prevent a user from impersonating or hijacking another user's Configuration utility session.

Impact

The user may be forced to re-enter Configuration utility credentials.

Recommended Actions

If your client web browser connects to the BIG-IP Configuration utility through a proxy device, and the client's source IP address changes during the session, depending on your specific environment and security requirements, you may be able to perform one or more of the following actions:

BIG-IP Configuration Security Setting

Beginning in BIG-IP 11.3.0, you can disable the Require a Consistent Inbound IP For the Entire Web Session security setting for the Configuration utility. To do so, perform the following procedure:

Impact of procedure: By disabling this security setting, the BIG-IP system will no longer terminate the connection if the inbound IP address changes for an authenticated session.

  1. Log in to the Configuration utility.
  2. Navigate to System > Preferences.
  3. Clear the Require A Consistent Inbound IP For the Entire Web Session check box.
  4. Click Update.

Alernatively, use tmsh to disable the auth-pam-validate-ip setting by typing the following command:

tmsh modify sys httpd auth-pam-validate-ip off

Web browser proxy configuration

You may be able to configure your browser's do not proxy option to not use a proxy when connecting to the Configuration utility.

For example, in the Firefox 3.5 browser:

  1. Navigate to Tools.
  2. Click Options.
  3. Click the Advanced tab.
  4. Click the Network tab.
  5. For the menu item Configure how Firefox connects to the internet, choose Settings.
  6. In the Proxy Configuration section, locate the No Proxy for option.
  7. Type the IP address of the BIG-IP system to which you want to connect.
  8. Click OK.

Note: In the previous steps, F5 assumes that your proxy settings are controlled by the browser and not by an upstream network appliance. To change the proxy settings for other browsers or versions, consult the documentation for your specific browser.

iControl

If your iControl application sends concurrent requests to the same Configuration utility from multiple client workstations, you should ensure that the iControl application uses unique login credentials for each concurrent request.
