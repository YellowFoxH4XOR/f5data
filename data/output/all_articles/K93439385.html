Description

This article provides you with steps to clear the alarms in SDC. 

Environment

  • SDC

Cause
None

Recommended Actions

Login to SDC CLI with root user. Once logged in perform below:

1. monit stop <NMS process> on all nodes (SDC and EMS).
2. /opt/cassandra/bin/cqlsh <MGMT IP>  [run this on any EMS]
3. describe keyspaces;  << Run this command to get the keyspaces
Example:
cqlsh> describe keyspaces;
statusflow          nms_ems_site_ems  nms_sdc_site_tasks  system_traces
system_auth         nms_sdc_site_ems  nms_sdc_site        nms_ems_site
nms_ems_site_tasks  system            system_distributed  topology

4. Truncate the below tables from any one EMS node.
 a. truncate table nms_<ems_site>_ems.stateful_alarms;  <<< The <ems_site> and <sdc_site> names will be different in your env.
 b. truncate table nms_<sdc_site>_ems.stateful_alarms;

5. You can check the alarm count after running step 4.
 a. select count (*) from nms_ems_site_ems.stateful_alarms;
 b. select count (*) from nms_sdc_site_ems.stateful_alarms;

6. exit the Cassandra shell by typing exit
7. Start nmsagent from all nodes (EMS and SDC).
8. Verify that stateful alarms do not appear in webui.

 

Additional Information

You can perform the above in fewer traffic hours or maintenance Window. When you start the nmsagent it will perform a broadcast of request for status to all components. On the webui, a lot of active alarms will appear. Now all components will response to nmsagent and the active alarms will slowly clear up.
