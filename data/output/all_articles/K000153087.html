K000153087: TMM Memory Allocation Failures During Bot Signature Updates

Description

During bot signature updates, the DoS Layer 7 ACY memory usage may temporarily spike, potentially leading to memory allocation failures in TMM (Traffic Management Microkernel). If TMM does not have sufficient memory to handle both the update and normal traffic load, bot signature updates may fail. In some cases, this failure can result in a memory leak.

Environment

  • Systems with limited memory allocated to TMM 
  • Multiple TMM threads in operation (e.g., >8 threads)
  • Regular bot signature updates enabled

Cause

Bot signature updates temporarily require a substantial increase in memory allocation:

  • Approximately 100 MB per TMM thread in steady state.
  • Up to an additional 300 MB per TMM thread during updates.

For example, with 12 TMM threads:

  • Steady-state ACY usage = 100 MB × 12 = 1200 MB
  • Temporary usage during updates = 300 MB × 12 = 3600 MB
  • Total requirement during updates = ~4800 MB

If TMM is not allocated enough memory to support this temporary demand, updates may fail. A failed update can cause memory leaks, whereas a successful update stabilizes memory usage.

Recommended Actions

1. Allocate sufficient memory to TMM:

  • Increase the memory available to TMM by adjusting module provisioning (e.g., provisioning LTM may reduce Host memory and reallocate it to TMM).
  • Ensure enough headroom exists to accommodate both traffic and temporary memory spikes during updates.

2. Monitor memory utilization:

  • Use system statistics and memory graphs to track TMM usage before and after bot signature updates.
  • Watch for allocation failures in TMM logs (MALLOC_ACY failed messages).

Additional Information

  • A successful bot signature update does not cause a memory leak.
  • Memory leaks are observed only when the update process fails due to insufficient TMM memory.
