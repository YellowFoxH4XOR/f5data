K13537502: Unexpected Error: UCS loading process failed while trying to upload a UCS into a device

Type
Support Solution
Published
2022-07-05
Updated
2025-12-30
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K13537502

Description

After uploading the UCS into a device, you try to install it via CLI with the no-license option. The F5 BIG-IP is unable to decompress and install the UCS file. The installation process gets terminated and it shows the below error message:

(tmos)# load /sys ucs <path/to/UCS> no-license
Processing UCS file: /var/local/ucs/UCS-file-name.ucs
grep: /var/tmp/install_all/config/ucs_version: No such file or directory
 
Installing full UCS () data, excluding license file.
Extracting manifest: /var/local/ucs/ UCS-file-name.ucs
Fatal: executing: /bin/sh -c tar -zxf /var/local/ucs/ UCS-file-name.ucs -C /var/tmp/.install_ucs 2> /dev/null
Operation aborted.
Unexpected Error: UCS loading process failed.

Then, you validate that the UCS file  was compressed properly. You get the error "tar: You must specify one of the `-Acdtrux' or `--test-label' options"
Example:

<username> # /bin/sh -c tar -zxvf <path/to/UCS> -C /var/tmp/.install_ucs
tar: You must specify one of the `-Acdtrux' or `--test-label' options
Try `tar --help' or `tar --usage' for more information.


Environment

  • BIG-IP
  • UCS Loading

Cause

In some cases, the UCS files are not compressed properly. This causes that the loading process cannot extract the config file from the UCS. 

Recommended Actions

We can offer three different recommendations:

 1.  (Recommended): Generate Fresh UCS

             tmsh save sys ucs /var/local/ucs/backup.ucs

  • Verify : tar -tzf /var/local/ucs/backup.ucs
  • Output should look like
tar -tzf /var/local/ucs/backup.ucs | head -5
 
# Should show WITHOUT ./ prefix:
# 0
# SPEC-Manifest
# SPEC-Files
# config/


   2.    Re-zip the UCS file using the Linux bash shell:

  • Log into the F5 device and go to the UCS path directory
  • Create a copy from the UCS change the file extension to .tar

cp UCS-file-name.ucs UCS-file-new-name.tar

  • Re-zip the tar file using the below command. It will create a .tar.gz file:

gzip UCS-file-new-name.tar

  • Change .tar.gz file extension to .ucs:

mv UCS-file-new-name.tar.gz UCS-file-new-name.ucs

  • Try to install the new UCS file:

tmsh load /sys ucs <path/to/UCS> no-license

3.  We can try repairing the corrupted UCS

  • Extract: tar -xzf new_config.ucs
  • Re-tar: tar -czf new_config.fixed.ucs --transform 's,^\./,,' .
  • Verify: tar -tzf new_config.fixed.ucs
  • Load: tmsh load sys ucs new_config.fixed.ucs
