This chapter supplements K53013601: BIG-IP APM operations guide | Chapter 8: Management. As the number of user connections to your BIG-IP APM system increases, you must regularly monitor the following to ensure that the system has sufficient resources to handle the additional workload:

  • System resources (CPU, memory)
  • Number of concurrent user sessions
  • Network access statistics such as access sessions, network throughput, lease pool usage, and so on.

This chapter describes the different facilities in BIG-IP system that you can use to view and monitor statistics on your BIG-IP APM network access VPN virtual server to ensure it is performing optimally.

Configuration utility and F5 iHealth

You can use the Configuration utility to view ongoing resource usage on the BIG-IP system and to view usage trends with graphs. In the Configuration utility, refer to the following pages:

  • Statistics > Dashboard: This dashboard provides real-time information of the system.
  • Statistics > Performance: For Graph Interval, select the required interval and monitor at least Memory Used, System CPU usage, Current Connectivity Sessions, Active Network Access Connections, Network Access Throughput, and so on.

F5 iHealth is a tool that helps you troubleshoot potential issues. It does this by analyzing configuration, logs, command output, password security, license compliance, and so on. On iHealth, go to Graphs > Standard and select the relevant graphs before selecting View Selected. For more information on iHealth, refer to K27404821: Using F5 iHealth to diagnose vulnerabilities

TMOS Shell and iControl REST API

The TMOS Shell (tmsh) is a command-line interface for managing and displaying statistics and resource usage on the BIG-IP system. It is the basis for other interfaces, such as iApps and iCall, and is the base mapping for iControl REST. iControl is the open, web services-based API the BIG-IP system uses, allowing complete, dynamic, programmatic control of F5 configuration objects.

Use the following syntax rules when translating tmsh commands to iControl REST URIs:

The way iControl REST API organizes collections of resources is functionally equivalent to the modules in tmsh. For example, to list the current APM license usage on the BIG-IP system, enter the following command:

tmsh show apm license

To retrieve the same information using iControl REST API, use the following command syntax:

curl -sku <username>:<password> GET https://<IP address>/mgmt/tm/apm/license | jq . -M

To specify parameters for a query, in tmsh, use the following command syntax:

tmsh show apm access-info all-properties
tmsh show apm access-info logon-user <username>

To retrieve the same information using iControl REST API, use the syntax ?options=<parameter>,<value>, as shown in the following syntax:

curl -sku <username>:<password> GET https://<IP address> /mgmt/tm/apm/access-info?options=all-properties | jq . -M
curl -sku <username>:<password> GET https://<IP address> /mgmt/tm/apm/access-info?options=logon-user,<username> jq . -M

To specify a named resource using tmsh, use the following command syntax:

tmsh show apm profile access <profile_name>

To retrieve the same information via iControl REST API, use the syntax ~<partition>~<resource_name>, and append /stats to the URI, as in the following syntax:

curl -sku <username>:<password> GET https://<IP address>/mgmt/tm/apm/profile/access/~Common~<profile_name>/stats | jq . -M

To run a command on Advanced Shell (bash) using iControl REST API, use the following command syntax:

curl -sku <username>:<password> -H "Content-Type: application/json" -X POST https://<IP address>/mgmt/tm/util/bash -d "{\"command\":\"run\",\"utilCmdArgs\":\"-c '<command>'\"}" | jq . -M

Monitor with BIG-IP iCall

iCall is an event-based automation system that gives you programmability in the control plane. Using iCall, you can automate tasks using scripts written in the Tcl language. iCall is useful not only for integration into upstream orchestration, but it can also drive orchestration directly from the BIG-IP system. It is made up of three components:

  • Events: You can configure an iCall event-based on system generated events, such as failover, a pool going down, a CPU spike, a specific log message in a log file, and so on.
  • Handler: A handler defines how to handle when an event happens. There are three types of handlers:
    • Triggered: Responds to a specific named event
    • Periodic: This handler runs periodically at a configured interval to call an iCall script.
    • Perpetual: Runs perpetually and under the control of a daemon by subscribing to events.
  • Scripts: This contains the Tcl script that defines exactly what actions should be performed.

For an overview of iCall, refer to iCall - All New Event-Based Automation System.

Similar to SNMP monitoring, you can use iCall to monitor the critical statistics of your BIG-IP APM system and, when certain configured thresholds are exceeded, iCall can alert you to perform remedial actions. The DevCentral article Using iCall to monitor BIG-IP APM network access VPN provides three use cases of using iCall to monitor the health of your system.
