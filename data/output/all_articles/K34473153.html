Topic

You should consider using this procedures under the following conditions:

  • You are running an IPv6 environment.
  • You want a pair of BIG-IPs running OSPFv3/ ZebOS (OSPF6d) to form a full adjacency.

Description

ZebOS OSPF6d implements OSPFv3 and supports IPv6. In order to implement OSPF in IPv6 you must configure ZebOS OSPF6d via the imish or vtysh.

Cause

None

Environment

  • BIG-IP
  • OSPFv3

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have configured IPv6 non-floating self-IPs on both peer BIG-IP.
  • OSPF6d daemon/OSPFv3, network access and port lockdown configuration are enabled. 
  • You have access to the ZebOS Integrated Management Interface (IMI) Shell, or imish.

Procedures

The procedures listed in this HOW-TO will refer to the following information:

Name of BIG-IPIPv6 AddressName of common interface1
BIG-IP_Adead:beef::1/64v215
BIG-IP_Bdead:beef::2/64v215

1: In ZebOS, interfaces are the name of vlans that were previously configured via BIG-IP tmsh or GUI. 
Impact of procedure: Performing the following procedure on a customer's unit may result in the redirection of egress traffic and should only be performed by the customer and during a downtime.

  1. Enter to the 'enable' mode and access the 'configuration' mode, from the ZebOS IMI Shell on BIG-IP_A 
    BIGIP_A[0]>enable
BIGIP_A[0]# configure terminal
BIGIP_A[0](config)#
  2. Configure ZebOS interface for OSPF Area and OSPF6d process ID tagging: 
    BIGIP_A[0](config)#interface v215
BIGIP_A[0](config-if)#ipv6 router ospf area 0.0.0.0 tag 111
BIGIP_A[0](config-if)#exit
  3. Configure the OSPF6d router, router ID and process ID. Include any optional OSPF route redistribution. For the purpose of demonstration, BIGIP_A will be configured with the option: 'default-information originate always'. 
    BIGIP_A[0](config)#router ipv6 ospf 111
BIGIP_A[0](config-router)#router-id 1.1.1.1
BIGIP_A[0](config-router)#default-information originate always
BIGIP_A[0](config-router)#exit
BIGIP_A[0](config)#exit
BIGIP_A[0](config)#write memory
  4. Repeat the steps 1-3 for BIGIP_B, with its own 'router ID' (for demonstration we have used 1.1.1.1  & 2.2.2.2 for BIGIP_A and BIGIP_B respectively).
  5. Run the following commands on BIGIP_A and BIGIP_B to validate that full adjacency has been established. 
    BIGIP_A[0]#show ipv6 ospf neighbor
OSPFv3 Process (111)
Neighbor ID     Pri   State            Dead Time   Interface  Instance ID
2.2.2.2           1   Full/Backup      00:00:37    v215       0
  6. Determine if the full routing tables have been exchanged between BIG-IPs. 
    BIGIP_A[0]#show ipv6 route
IPv6 Routing Table
Codes: K - kernel route, C - connected, S - static, R - RIP, O - OSPF,
       IA - OSPF inter area, E1 - OSPF external type 1,
       E2 - OSPF external type 2, I - IS-IS, B - BGP

C      dead:beef::/64 via ::, v215, 01:43:51

BIGIP_B[0]#show ipv6 route
IPv6 Routing Table
Codes: K - kernel route, C - connected, S - static, R - RIP, O - OSPF,
