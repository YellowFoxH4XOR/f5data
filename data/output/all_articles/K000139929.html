Description

 

In v15.1.0.4 a new AFM DB key was added for controlling how DoS Whitelist behaves. This DB key does not exist anymore for TMOS versions 16.x and 17.x, however if customer upgrade from a version where this DB key is present then this DB key will also exist in the upgraded version for compatibility reasons.

 

This db variable: dos.wl_match_mode_include enables control over whether the DoS Whitelist serves as an 'include list' or an 'exclude list'. The 'dos.wl_match_mode_include' variable defaults to 'false', which maintains existing DoS Whitelist behavior.

Setting the 'dos.wl_match_mode_include' variable to 'true' changes the DoS Whitelist from an 'exclude list' (where traffic matching the whitelist is not subject to DoS enforcement) to an 'include list' (where only traffic matching the whitelist is subject to DoS enforcement, and all other traffic is not subject to DoS enforcement).

This DB key has a below specifications:

  1. By default db variable "dos.wl_match_mode_include" is false.
  2. After enabling db variable "dos.wl_match_mode_include" under device protection, "Whitelist" switches to "Includelist".
  3. When DB variable is set IPV6 entries should not allowed.
  4. When DB variable is not set, IPV6 entries allowed.
  5. When DB variable is not set, matching traffic will exclude the DOS checks.
  6. When DB variable is set, matching traffic will inspect by the DOS checks.
