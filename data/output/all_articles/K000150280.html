Description

How to get the verbose log when On-Demand Cert is failing and working?

 

Environment

  • BIG-IP APM
  • On-Demand Cert Auth
  • Log

 

Cause

  • n/a

 

Recommended Actions

Please refer: K24826763: Configuring the BIG-IP APM Logging Levels (12.x and newer)

Access Policy should be set debug mode for most of access policy.

Then in /var/log/apm, when it received certificate, it will have similar to the below log:

info apmd[<pid>]: 01490007:6: <Access_Policy_Object_name>:<Partition_name>:<session_id>: Session variable 'session.clientcert.ssl_agentnonce' set to '<agentnouce>'
info apmd[<pid>]: 01490007:6: <Access_Policy_Object_name>:<Partition_name>:<session_id>: Session variable 'session.clientcert.ssl_rehandshake_pending' set to '<0/1>'
info apmd[<pid>]: 01490007:6: <Access_Policy_Object_name>:<Partition_name>:<session_id>: Session variable 'session.ssl.cert.certissuer' set to '-----BEGIN CERTIFICATE----- ... -----END CERTIFICATE----- '

 

Further more, taking tcpdump after changing the some db value is also helpful.

tmsh modify sys db tm.rstcause.pkt value enable
tmsh modify sys db tm.rstcause.log value enable
tmsh modify sys db tcpdump.sslprovider value enable
tmsh modify sys db log.ssl.level value Debug

tcpdump -s0 -ni 0.0:nnnp -w /var/tmp/"$HOSTNAME"_"$(date +%H-%M-%S-%d-%m-%y)".pcap --f5 ssl -vv host <client_public_IP>

 

Also the 3rd party tool for client like process monitor or fiddler would give further information.
