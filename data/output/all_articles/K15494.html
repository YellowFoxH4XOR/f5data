Known Issue

BIG-IP APM client-side software checks do not update the state value for session variables.

This issue occurs when the following condition is met:

  • The BIG-IP APM access policy configuration uses any of the following Endpoint Security client-side software checks:

    • Antivirus
    • Anti-Spyware
    • Firewall
    • Hard Disk Encryption
    • Patch Management
    • Peer-to-peer
    • Windows Health Agent

    For example, if a Firewall Endpoint Security check is successful, the value of the session.check_software.last.fw.state session variable is not updated and incorrectly retains a value of 0, similar to the following example:

    fc54f802.session.check_software.last.fw.state 1 0

    If a custom Firewall check is configured to use the session.check_software.last.fw.state session variable to evaluate success (1) or failure (0), subsequent checks will always evaluate to a failed state.

    Impact

    Access policy checks that are based on a returned value of 1 for a session.check_software.last.<check type>.state session variable evaluate to a failed state.

    Symptoms

    As a result of this issue, you may encounter the following symptoms:

    • BIG-IP iHealth lists Heuristic H473335 on the Diagnostics > Identified > Medium screen.
    • Users are denied access by the BIG-IP APM access policy and are unable to establish sessions.
    • session.check_software.last.<check type>.state values are not updated with a value of 1 even when the check is successful.

    Workaround

    To work around this issue, you can configure the access policy to explicitly check for the desired state rather than using the deprecated session.check_software.last.<check type>.state session variable. For example, you can delete a custom software check configured to use the session.check_software.last.<check type>.state session variable for evaluation, and then specify the desired state in a new software check configured with the default evaluation expression. To do so, perform the following procedure:

    Impact of workaround: Performing the following procedure should not have a negative impact on your system.

    1. Log in to the BIG-IP APM Configuration utility.
    2. Navigate to Access Policy > Access Profiles > Access Profiles List.
    3. Near the access policy, click Edit.
    4. In the visual policy editor, locate the software check to be deleted and then click the corresponding X.
    5. In the confirmation screen, choose the appropriate option for your policy.
    6. To delete the check, click Delete.
    7. Click + in the policy where the new software check is to be configured.
    8. In the Endpoint Security (Client-Side) section, select the desired software check.
    9. Click Add Item.
    10. Configure the appropriate software check settings for your policy and then select Enabled or Disabled in the State menu.
    11. Click Save.
    12. In the upper-left corner of the page, click Apply Access Policy.
