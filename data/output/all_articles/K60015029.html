Description

After upgrade to 14.1.x or later unit fails to process SSL/DNSSEC traffic.
You can observe message similar to the following in the /var/log/ltm log:

pkcs11d[8682]: 01680002:3: Key table lookup failed. error.

Environment

  • BIG-IP LTM/DNS after upgrade to 14.1.x or later
  • integration with Thales NetHSM

Cause

ID758491

Recommended Actions

There are two workarounds:
  • Re-create the keys using tmsh command using following manual:

    Managing External HSM Keys for LTM

    IMPORTANT: This workaround is suitable for deployments that are new and not in production.
     
  • Re-import the keys from nethsm using:

    tmsh install sys crypto key <key_label> from-nethsm

    Where key_label is the rightmost string in the output of the Thales command: nfkminfo -l.

Additional Information

The following commands can be used to re-import all the nethsm keys:

First, backup the key files before proceeding.

mkdir /shared/tmp/kmdata_key_backup
cp /opt/nfast/kmdata/local/key_pkcs* /shared/tmp/kmdata_key_backup

  1. Extract all key labels into /shared/tmp/import_keys
    /opt/nfast/bin/nfkminfo -l | awk 'NR >2 {print}' | awk '{print substr($2, 2, length($2) - 2)}' > /shared/tmp/import_keys
  2. Verify the contents of /shared/tmp/import_keys before proceeding to next step.
    cat /shared/tmp/import_keys
  3. Re-import the keys contained in /shared/tmp/import_keys
    for i in $(cat /shared/tmp/import_keys); do tmsh install sys crypto key $i from-nethsm; done
