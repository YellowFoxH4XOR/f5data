K000161072: monpd Down due to Incomplete MySQL Initialization After Disk Space Error on BIG-IP 17.5.1

Type
Support Solution
Published
2026-06-23
Updated
2026-06-23
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161072

Description

After an upgrade, the monpd service may show DOWN because MariaDB/MySQL did not initialize successfully, which prevents monpd from connecting to the database. Symptoms can include repeated MySQL setup failures and permission-related errors such as:

ERROR 1045 (28000): Access denied for user 'root'@'localhost'

Error: could not set root password write failed

Unable to set up root password/permissions

MySQL is not yet setup, failed to initialize. Service would go down.

ERROR: 1005 Can't create table 'tmp_db' (errno: 28)

MySQL Error 28 indicates "No space left on device"

Environment

  • BIG-IP LTM Virtual Edition
  • BIG-IP 17.5.1
  • AVR provisioned
  • monpd 
  • MySQL
  • Observed after upgrade/reinstall preparation on a device in an HA pair

Cause

Insufficient disk space during the upgrade to BIG-IP 17.5.1 prevented the MySQL database from initializing and generating necessary database files. This resulted in persistent MySQL startup failures and the monpd service remaining down.

Answer/Recommended Actions

  1. Verify the service state:
    • tmsh show /sys service mysql
    • tmsh show /sys service monpd
  2. Review logs for MySQL initialization and monpd database dependency failures:
    • /var/log/mysql.out
    • /var/log/avr/monpd.mysql.issues
  3. Check for the historical MySQL initialization failure in logs, including messages similar to:

    ERROR: 1005 Can't create table 'tmp_db' (errno: 28)

    No space left on device

  4. Verify whether the MySQL database directory was created correctly:
    • ls -la /var/lib/mysql
    • ls -la /appdata/mprov/local/<volume>/mysqldb/
  5. If the MySQL database directory is missing expected database files and contains only files such as server.crt and server.key, treat this as an incomplete MySQL initialization.
  6. If standard recovery steps for monpd/MySQL do not resolve the issue, reinstall BIG-IP 17.5.1 or upgrade to a later version containing the fix so the MySQL database can be regenerated properly.
