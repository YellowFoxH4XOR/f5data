Known Issue

The BIG-IP system displays a transient error in the bd.log and asm.log files shortly after you associate a signature set with a security policy.

This issue occurs when the following conditions are met:

  • The BIG-IP system is under heavy load.
  • You associate a signature set with a security policy.

Impact

There is no impact; you can safely ignore this issue.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the bd.log file, you observe error messages similar to the following example:

    ECARD_POLICY|ERR   |Apr 09 01:00:23.205|24966|attack_patterns.cpp:0027|signature collection with id: 13 doesn't exist

    ATTACK_SIG|ERR   |Apr 09 01:00:23.205|24966|attack_patterns_funcs.cpp:0083|Signature collection id: 13 Can't be acquired

  • In the asm.log file, you observe error messages similar to the following example:

    info perl[20236]: 01310053:6: ASMConfig change: Policy Signature Set High Accuracy Detection Evasion Signatures [add]: Alarm was set to enabled. Policy Signature Set Name was set to High Accuracy Detection Evasion Signatures. Block was set to enabled. Learn was set to enabled. { audit: policy = /Common/policy, username = admin, client IP = 192.168.1.1 }

    info perl[20236]: 01310053:6: ASMConfig change: Policy Signature Set High Accuracy Signatures [add]: Alarm was set to enabled. Policy Signature Set Name was set to High Accuracy Signatures. Block was set to enabled. Learn was set to enabled. { audit: policy = /Common/policy, username = admin, client IP = 192.168.1.1 }

Workaround

To work around this issue, you can ignore the messages or only apply new signature sets during times of low load.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
