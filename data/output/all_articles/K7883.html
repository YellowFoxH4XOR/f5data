K7883: Enabling gateway failsafe for a gateway pool and restarting prevents the pool members from being marked up

Known Issue

This is the result of a known issue. When you enable a gateway failsafe for a gateway pool and then restart the BIG-IP LTM, the gateway pool members are not marked up. The monitor that is assigned to pool members functions properly, by sending a request and receiving a response. However, after the restart occurs, the pool members are reported in an active, checking state and do not transition to report an up state.

When this issue occurs, the following error message is recorded in the /var/log/mcpd.out log file:

mcpd[4462]: 01070712:3: Caught configuration exception (0),
Unable to initiate HA action on pool <pool name>,
status 18087954 - Pool.cpp, line 286.

F5 Product Development tracked this issue as CR80814 and it was fixed in BIG-IP LTM 9.4.1. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by restarting the bigd process, which monitors members and reports the status to the master control program daemon (mcpd). To do so, perform the following procedure:

  1. Log in to the command line.
  2. Type the following command:

    Note: Issuing the following command will restart all member monitors on the system.

    bigstart restart bigd

  3. Check the status of the gateway pool or pool used for gateway failsafe by typing the following command:

    bigpipe pool <pool name>

    The pool member should now report active, up as its status.
