Description

AFM may drop packets with following reason:  Drop_reason = “Connection flow miss”  

Environment

  • AFM

Cause

A drop reason of "Connection flow miss" indicates that the BIG-IP received a packet that does not match an existing connection flow, and does not create a new one, for example, a TCP packet with just the ACK flag set, and layer-3/4 addressing that does not match an existing flow.    A virtual server with a fastL4 profile can be configured with loose-initialization enabled, in to order treat all unmatched packets as a new flow, but by default, for TCP, only a packet with the SYN flag (and no ACK) set is able to create a new flow.  For UDP, any packet is able to create a new flow.  Whether a new flow is actually created depends on it matching the requirements of an existing virtual server.

These type of packets are correctly dropped, regardless of any AFM firewall rules that may be configured - AFM is simply reporting the fact that they were dropped. 

Recommended Actions

If the failure to match an existing flow is unexpected, verify that the packet flow is symmetrical, and that the flow's initial TCP SYN passes through the BIG-IP
