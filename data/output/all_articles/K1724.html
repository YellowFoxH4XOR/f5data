Topic

The BIG-IP system allows you to give Secure Socket Layer (SSL) proxy access to a specified site to clients with a particular encryption strength. For instance, you can have the BIG-IP system check the encryption on incoming clients and send those with less than 128-bit encryption to an alternate pool of servers. These servers could then notify the client to update their browser for 128-bit encryption.

You may want the ability to allow only customers using 128-bit encryption to access a site by SSL proxy. The BIG-IP system allows you the flexibility to do this by checking the encryption on incoming clients and sending those with less than 128-bit encryption to an alternate pool of servers.These servers then notify the client to update their browser for 128-bit encryption.

You can configure the BIG-IP system to forward the client encryption level contained in the HTTP header to the server and have the server make a load-balancing decision based on that information. To do this using the encryption information inserted into the header of an SSL proxy connection, you can write a rule (as illustrated in the example in the following Configuration section) to parse for the cipher strength and direct the client to the appropriate pool based on this information.

Configuration

To configure this feature you must first enable inclusion of the SSL encryption strength in the HTTP header. For specific instructions, refer to K991: Configuring BIG-IP to insert an HTTP header that contains the SSL encryption level used in the client-side connection.

After you enable the SSL encryption strength feature, create a rule to parse the header and direct traffic to the appropriate pool. For example, a simple rule that looks for clients with a cipher strength of 128 bits and sends clients to the secure pool of servers would appear similar to the following.

if (exists http_header "SSLClientCipher") {
 
   if (http_header "SSLClientCipher" contains "bits=128") {
       use ( secure )
   }
   else {
      use ( nonsecure )
   }
}

With this rule, clients that have anything less than 128-bit encryption are sent to the non-secure pool of servers, which contain servers with HTML pages. These HTML pages could point clients to a location to upgrade their browser to a higher cipher strength.
