Known Issue

The rsync process may repeatedly create and copy temporary files when synchronizing iStats files to the primary VIPRION blade.

This issue occurs when the following condition is met:

  • The BIG-IP system is configured with more than 1,000 iStats definitions

When iStats are used on a VIPRION system, the rsync process synchronizes per-blade statistics database files from each blade to the /var/tmstat2/cluster/ directory on the primary blade. When there is a large number of iStats counters, the rsync process takes longer to copy the per-blade statistics database files to the primary blade. As a result, the rsync process may create temporary files. The rsync process also synchronizes the temporary files, and creates more temporary files.

Impact

The istatsd, rsync, and csyncd processes may consume CPU and disk I/O resources. Additionally, all available disk space on the /var file system may be consumed.

Workaround

To work around this issue, you can configure the csyncd process to ignore the rsync temporary files. To do so, perform the following procedure:

Impact of workaround: iStats data may be delayed from propagation to all blades in the cluster. Performing this procedure may affect iRules that depend on certain iStats to be synchronized.

  1. Log in to the BIG-IP command line of the primary blade for the VIPRION cluster.
  2. Stop the csync daemon on all blades by typing the following command:

    clsh bigstart stop csyncd

  3. Stop any running rsync processes on all blades by typing the following command:

    clsh /etc/init.d/rsync stop

  4. Change directories to the /etc directory by typing the following command:

    cd /etc

  5. Backup the original /etc/csyncd.conf file by typing the following command:

    cp csyncd.conf csyncd.conf.sol14437

  6. Using a text editor, open the csyncd.conf file. 
  7. Locate the following stanza:

    monitor dir /var/tmstat2/cluster {
            pull    any2any
            delsync no
            defer   no
            stopped "rm -f /var/tmstat2/cluster/blade%s.tm2"
    }

  8. Add ignore blade?.tm2.* to the bottom of the stanza.

    For example:

    monitor dir /var/tmstat2/cluster {
            pull    any2any
            delsync no
            defer   no
            stopped "rm -f /var/tmstat2/cluster/blade%s.tm2"
            ignore blade?.tm2.*
    }

  9. Repeat steps 4 through 8 on each blade of the cluster.
  10. After the /etc/csyncd.conf file has been edited on all blades in the cluster, delete any current temporary files from all blades. To do so, type the following command from the primary blade of the cluster:

    clsh rm -rf /var/tmstat2/cluster/blade?.tm2.*

  11. Start the rsync process on all blades by typing the following command:

    clsh /etc/init.d/rsync start

  12. Start the rsync process on all blades by typing the following command:

    clsh bigstart start csyncd
