Description

The iRule log level configuration is set to a lower level than the default Informational value, but the log command within the iRule keeps sending logs.

Environment

  • The iRule log level is set to a lower level than the default Informational value. For example:
    tmsh list sys db log.rules.level
    sys db log.rules.level {
        value "Error"
    }
  • The log command contains a facility or severity level. For example:
    log local0. "MESSAGE"
    log local0.debug "MESSAGE"

Cause

The log command used in the iRule has a facility or severity level specified. The syntax for the iRule log command is:
log [<facility>.<level>] <message>

The possible values:
Facility : "local0", "local1", "local2", "local3", "local4", "local5", "local6", "local7"
Level: "alert", "crit", "debug", "emerg", "err", "error", "info", "none", "notice", "panic", "warn", "warning"

And if the facility or severity level is specified, it overrides the BigDB variable and writes the message directly to the logs. For example:
log local0. "MESSAGE"
log local0.debug "MESSAGE"

Recommended Actions

By using the log command on its own with no facility or severity level parameters, the message will not appear if db log.rules.level is set to Notice, Warning, or Error.

For example:
log "MESSAGE"
