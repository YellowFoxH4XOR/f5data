Known Issue

When the origin web server (OWS) responds with an empty ETag header, both the client-side and server-side connections may reset.

This issue occurs when all of the following conditions are met:

  • You are passing traffic through a BIG-IP WebAccelerator-enabled virtual server
  • The OWS responds with an ETag header containing no data

Impact

Reset connections will close prematurely.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You may experience incorrect rendering of web pages.
  • You may see errors in the /var/log/ltm file, using the following syntax:

    01230140:3: RST sent from <Source_IP_Address>:<Source_Port> to <Distination_IP_Address>:<Destination_Port>, [0x172aa31:296] {peer} Internal error ((WAM::SMART) tmi abort failed)

    01230140:3: RST sent from <Distination_IP_Address>:<Destination_Port> to <Source_IP_Address>:<Source_Port>, [0x172aa31:296] Internal error ((WAM::SMART) tmi abort failed)

    For example:

    01230140:3: RST sent from 10.206.12.11:36627 to 10.206.108.64:80, [0x172aa31:296] {peer} Internal error ((WAM::SMART) tmi abort failed)

    01230140:3: RST sent from 10.206.100.11:80 to 10.206.108.64:36627, [0x172aa31:296] Internal error ((WAM::SMART) tmi abort failed)
  • Analysis of tcpdump traces of problematic connections will show unexpected RESETs

Workaround

To work around this issue, you can install an iRule that will remove empty ETag headers. To do so, perform the following procedure:

Impact of workaround: iRules may have a small performance impact on a BIG-IP host.

  1. Log in to the BIG-IP Configuration utility as an administrative user.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. In the Name field, enter a name for this iRule.

    For example:

    RemoveEtag
  6. In the Definition field, copy and paste the following iRule:

    when HTTP_RESPONSE {
    foreach aHeader [HTTP::header names] {
    if { [string tolower $aHeader] equals "etag" } {
    if { [string length [HTTP::header value $aHeader]] == 0 } {
    HTTP::header remove $aHeader
    }
    }
    }
    }
  7. Click Finished.
  8. Associate the new iRule with the BIG-IP WebAccelerator-enabled virtual server.

The iRule will take effect immediately.
