K42315530: BIG-IP devices will not maintain LDAP referral settings

Type
Support Solution
Published
2021-12-03
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K42315530

Description
BIG-IP LTM will not maintain LDAP referral settings which prevents admin users from logging in. 

Issuing the command:
modify sys db systemauth.referrals value no
does not retain the system-auth referral.  This can be verified by issuing:
list auth cert-ldap system-auth referrals
with the result being:
Data Input Error: referrals is not a valid name. Only system-auth is allowed.

A manual workaround exists of editing the "referral" section of the /etc/nslcd.conf file.  However, after any configuration changes, loads, or saves this file will be overwritten removing the referral edit.

Environment
- BIG-IP LTM
- Remote LDAP auth enabled
- Administrative users are authenticated with the 'cert-ldap' source - example:
   auth source {
       type cert-ldap
   }

Cause
This is due to ID922185.  nslcd.conf obtains its "referral" section value from the auth cert-ldap system-auth referrals value which is failing to populate.  Any subsequent configuration changes, loads, or saves results in nslcd.conf being reloaded and not able to reference data from auth cert-ldap system-auth referrals and thus defaulting the "referral" value to blank.

Recommended Actions
Update to a fixed code version as referenced in ID922185.

Alternatively, if unable to upgrade then manually edit  /etc/nslcd.conf and set the referrals to no.

Additional Information
If NOT upgrading then note that configuration changes, loads, or saves can overwrite /etc/nslcd.conf thus removing the manual fix.
