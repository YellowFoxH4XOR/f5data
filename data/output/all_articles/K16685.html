Topic

Summary

In high-traffic environments, the BIG-IP ASM system may remove learning suggestions earlier than expected due to the maximum limit of 100,000 learning incidents.

Note: The incident limits and learning suggestion handling as described in this article do not apply to BIG-IP ASM 12.0.0 and later. For more information refer to the Unified Policy Building section of the BIG-IP ASM 12.0.0 Release Note.

Description

The BIG-IP ASM system provides several methods of deploying a security policy. One of the methods allows you to build a new security policy using the Rapid Deployment security policy, where you can further tune the security policy with assistance from system-generated learning suggestions that are listed on the Manual Traffic Learning page (navigate to Security > Application Security > Policy Building > Manual Traffic Learning). Depending on the traffic volume for a protected site, these learning suggestions may be removed from the Manual Traffic Learning page before they can be acted upon. This is generally due to a limit on the number of learning incidents that the BIG-IP ASM system can store.

The BIG-IP ASM system can store a maximum of one hundred thousand (100,000) learning incidents across all security policies at any one time. When the number of learning incidents approaches or exceeds the limit, the system will remove the oldest incidents in groups of ten thousand (10,000) to free up space to store new learning incidents. Additionally, a single learning suggestion on the Manual Traffic Learning page may represent one or multiple learning incidents. For example, if there are 2,000 recent requests that triggered the Automated client access "curl" attack signature for /index.html, the system stores these 2,000 requests as learning incidents and represents them with a single learning suggestion.

This aggregation means that it may not be possible to predict the expected total number of learning suggestions in any given deployment, since theoretically, a single security policy can have one learning suggestion representing 100,000 learning incidents, or each of the 100,000 unique learning suggestions representing one learning incident. This aggregation also means that it is possible to see situations where a security policy that is experiencing high traffic volume may generate a large number of new learning suggestions in a short span of time, and causes older learning suggestions generated by a security policy that is experiencing low traffic volume to be removed earlier than expected.

Recommendations

Generally, F5 has found this behavior to be rare. However, if you encounter this behavior on your BIG-IP ASM system, you may want to consider the following possible steps to mitigate the effects:

  • Check and act upon the learning suggestions on the Manual Traffic Learning page promptly or at regular intervals; once you accept or ignore/clear the learning suggestions, the system will no longer collect the related learning incidents.
  • If feasible for your application environment, deploy only one Rapid Deployment security policy at any given time.
  • If feasible for your application environment, consider using the Automatic Policy Builder to build your security policy so that user intervention is not required for every learning suggestion.
