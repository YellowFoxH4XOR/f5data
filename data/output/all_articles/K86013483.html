Description

The purpose of this article it to provide a basic understanding of how Mobile Device Management (MDM) works and how the BIG-IP APM functions within MDM.

This article uses the following core terminology:

Endpoint Device: Internet-capable computer hardware device that refers to desktop computers, laptops, smart phones, tablets, thin clients, printers, and so on.

Mobile Device Management (MDM): Software that allows administrators to control, secure, and enforce policies to endpoint devices.

Enterprise Mobility Management (EMM): An extension of MDM that includes the following features:

  • Mobile Information Management (MIM) encrypts data and only allows approved applications to access or transmit it.
  • Bring your own device (BYOD) allows employees to bring personally owned endpoint devices to the workplace and use those endpoint devices for work-related purposes.
  • Mobile Application Management (MAM) provisions and controls applications typically used for conducting company business on company-owned endpoint devices or BYODs.
  • Mobile Content Management (MCM) secures access to company data typically involving a file storage and file sharing service.

Unified Endpoint Management (UEM): Next generation MDM, encompassing EMM with the addition of managing more endpoint devices such desktops, laptops, and Internet of Things (IoT) endpoint devices.

Per-App VPN: VPN implemented automatically by an MDM/EMM service on devices that support it. Its function is to automatically start a VPN tunnel when specified managed applications are launched.

Note: Safari Domains is a special Per-App VPN use case..

Safari Domains (iOS only): A special Per-App VPN use case in which a VPN tunnel is automatically started when the device attempts to connect to specified domains using Safari.

On-Demand VPN: VPN tunnel is automatically started when the device attempts to connect to specified domains configured in the Connect On Demand settings within the F5 Access app.

Note: This feature functions independently from Per-App VPN.

Endpoint Management Systems (EMS): A BIG-IP APM Access Authentication object that pulls endpoint device information from an MDM service and is typically used in the Access Policy Endpoint Security (Server-Side) Managed Endpoint [Status,Notification] actions.

Managed Endpoint Status: An Access Policy Endpoint Security (server-side) action you can use for posture checks of managed endpoint devices that are connecting to the access policy. The endpoint device posture check is based on the selected Endpoint Management Systems object.

Managed Endpoint Notification: An Access Policy Endpoint security (server-side) action that sends a custom message to managed endpoint devices that are connecting to the access policy. The endpoint device is sent the message through the selected Endpoint Management Systems object.

The number of diverse endpoint devices used in the workplace makes it extremely difficult for companies to manually administer and maintain policies, restrictions, and controls on these endpoint devices. MDM solves this problem by providing remote administration to endpoint devices.

MDM accomplishes endpoint device management by means of establishing a trust between the endpoint device to be managed and the managing system, typically using a certificate-based profile installed on the endpoint device. After an endpoint device trust is established, the MDM service is free to pull and store the device 's information and push management policies and applications to the endpoint device. If configured and permitted, end-users are able to pull managed applications.

There are a wide range of management policies and attributes that can be pushed to managed endpoint devices. These range from compliance, such as OS versions and changes, geo-fencing, encryption levels, restrictions on jail-braking and rooting, and monitoring of SIM card changes, to endpoint device settings, such as passcode enforcement, application restrictions, WiFi, ActiveSync, VPN (this is where BIG-IP APM lives), and more.

MDM polices are distributed and enforced on endpoint devices using a client agent/application that is based on client OS-specific APIs. For example, Apple 's iOS consumes an XML dictionary configuration file, while Microsoft 's Windows 10 implements the Open Mobile Alliance (OMA) Device Management (DM) protocol, and Google 's Android implements a device policy controller (DPC) based on Gradle. While implementation technologies are unique and may evolve across endpoint devices, each provides the ability to remotely manage the endpoint device.

MDM 's functionality began on dedicated company devices with features, such as endpoint device enrollment, remote control, endpoint device lockdown, and location tracking. As endpoint device features and their use in the workplace evolved, so evolved MDM, giving rise to features such as MIM, BYOD, MAM, and MCM, all of which are encompassed in the term EMM. In other words, EMM==MDM+MIM+BYOD+MAM+MCM. Further endpoint device evolution has lead to broadening remote management to endpoint devices such as desktops, laptops and IoT endpoint devices and wearables, which is termed UEM. In other words, UEM==EMM+remote management of additional endpoint devices. The terms MDM, EMM, and UEM are used interchangeably in the marketplace. For simplicity, this article uses the term MDM when referring to all things endpoint device management.

F5 has developed client-side feature sets within F5 Access and BIG-IP Edge Client applications that allow MDM administration. For example, you can configure MDM systems to require VPN for managed applications (Per-App VPN), which include Safari domains (iOS only). Additionally, F5 has created server-side features that sync with MDM services to retrieve information on managed devices, which allow BIG-IP APM access policy server-side device posture checks, like Endpoint Security (server-side) action Managed Endpoint Status, which implements an Endpoint Management Systems profile that pulls information about managed devices maintained on an MDM server. Refer to: Configuring Access Policy Manager for MDM applications.

F5 Access client information

iOS

With the release of iOS 12, Apple changed the iOS VPN framework to a Network extensible framework. As a result, starting in F5 Access 3.0, F5 modified and updated the Access and Per-App VPN architecture to accommodate these changes. For example, iOS only supports L3 network tunneling which led to the change of the F5 Access Per-App VPN tunnel established using a Network Access resource that is assigned to it within an BIG-IP APM access policy.

For another example, iOS no longer provides a Unique Device Identifier (UDID), which is required for Endpoint Management Systems functionality. This led to the change of relying on the MDM service to push a custom UDID to F5 Access. For more information on these example changes and more, refer to AskF5 Overview F5 Access for iOS.

Note: The initial release of F5 Access 3.0 is referred to as F5 Access 2018, and the name F5 Access refers to version 2.x. F5 Access now refers to version 3.x while version 2.x is referred to as F5 Access Legacy. F5 Access (version 3.x) is not a one-to-one upgrade from F5 Access Legacy (version 2.x).

Android

Google introduced application layer L3 tunneling support in Android v5.0+, in which VPN is established first by the user, and data from admin-user-defined allowed or disallowed applications traverse or do not traverse through the VPN tunnel.

A Per-App VPN configuration requires four configuration components:

  • A device under MDM/EMM management.
  • A managed app installed on the device or the mobile browser.
  • F5 Access for Android installed on the managed device. For Android for Work (Android Enterprise), you should install F5 Access within the Android for Work (Android Enterprise) container.
  • A related F5 Access configuration (VPN). This is configured with an MDM command that associates the app with an F5 Access configuration.

Notes

  • Google introduced normalized APIs for MDM/EMM use cases in Android v5.0+ (Lollipop) which was referred to as Android for Work and now referred to as Android Enterprise.
  • Work profiles within the Android Enterprise architecture natively isolate and protect work data coming to and from managed applications, separated from data coming to and from personal applications.
  • Managed applications are denoted with a red, circled, toolbox badge icon.
  • To support Android Enterprise functionality for devices running Android v4.0 (Ice Cream Sandwich) through v4.5 (Kitkat) or devices that don 't implement work profiles natively, Google created an Android Enterprise app (Android for Work app).
  • Android Enterprise is used in conjunction with an MDM/EMM service.
  • A device policy controller (DPC), custom developed or provided by Google, installed on the Android device is required because it communicates policy and configuration settings between endpoint devices and the MDM/EMM service.
  • Per-app VPN is not currently supported for Android apps on Chrome OS.

Windows 10 [Mobile]

Custom F5 Access VPN settings are administered using PowerShell commands, and you can administer some using MDM services. For more information on configuring custom F5 Access VPN settings, refer to Configuration Notes: F5 Access for Microsoft Windows 10.

Using PowerShell commands, you can configure VPN auto-trigger, which is similar to Per-App VPN, to connect F5 Access VPN automatically when opening a specified application or when accessing a specified domain. Microsoft Intune supports configuring VPN auto-trigger with F5 Access. For more information on configuring VPN auto-trigger with F5 Access refer to Deploying F5 Access for Windows 10.
