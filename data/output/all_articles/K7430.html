Known Issue

This is the result of a known issue. The Active Directory password history is not enforced when changing the password through the FirePass logon. As such, the FirePass controller allows passwords that violate history security policies.

When an Active Directory domain security policy requires a user to change their password, the user can evade the Active Directory password history feature by changing their password using their account on the FirePass controller, if their FirePass account uses the same Active Directory domain for authentication.

If the Active Directory domain security policy requires a user to change their password, and the user logs into the FirePass controller with an account that uses the same Active Directory domain for authentication, the following message will display on the FirePass logon page:

Domain password has expired and must be changed.

Below the message, three fields prompt for the current password and new password. The FirePass controller will permit a user to use a password that violates the domain's password history policy. For example, the FirePass controller will allow the new password to be identical to the current password.

This issue is the result of the FirePass controller using the Kerberos Change Password (KCP) protocol, instead of the Security Account Manager Remote Procedure Call (SAMR) protocol used by Windows-based operating systems. KCP operates by allowing an administrative account to perform the password change. The administrative account permissions typically allow overriding of the security policy.

F5 Product Development is tracking this issue as ID 266766 (formerly CR74769).
