Known Issue

This is the result of a known issue. When moving files, the ARX Data Migration Engine (DME) may experience a failure that causes the ARX system to dump core and reboot.

Additionally, the ARX system will send an SNMP trap that appears similar to the following example:

mib2 warmStart: software reboot: Resource 'dme_svc-3' has failed/exited.

The core backtrace will contain the following entries:

(gdb) Primary backtrace
(gdb) =================
(gdb)     #0  0xf71f27c7 in raise () from /lib/tls/libc.so.6
    #1  0xf71f406b in abort () from /lib/tls/libc.so.6
    #2  0xf71eb735 in __assert_fail () from /lib/tls/libc.so.6
#3  0xf7f84914 in connection::lock_impl_t::begin (this=0xee716db0,
    wt=0xf2689e24) at lockimpl.cc:119

Note: The show cores <core_name> backtrace command can be used to view the core backtrace. For information about the show cores command, refer to the ARX CLI Reference Guide.

F5 Product Development tracked this issue as ID 38956 and it was fixed in ARX 5.2.0. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in a hotfix available for ARX 5.1.0 and 5.1.5. To request this hotfix, contact F5 Technical Support and reference this article and ID number.
