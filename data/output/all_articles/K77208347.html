Known Issue

The BIG-IP system may erroneously send new connections to a disabled node or pool member.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server on your BIG-IP system.
  • The pool associated to the virtual server does not have a health monitor configured.
  • A pool member or a node configured in the pool is set to Disabled.
  • You attempt to reload the BIG-IP configuration using the bigpipe load (10.x) or tmsh load /sys config (11.x) commands.

Impact

The BIG-IP system may not process new connections as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system sends new connections to the disabled pool member.

    To determine if the system is sending connections to the disabled pool member, use the following bigpipe shell (bigpipe) or Traffic Management Shell (tmsh) commands:

    For BIG-IP 11.x, use the following tmsh command syntax:

    tmsh show /sys connection ss-server-addr <x.x.x.x> ss-server-port <XX>

    Replace <x.x.x.x> with the IP address and <XX> with the port number for the pool member in question.

    For example:

    tmsh show /sys connection ss-server-addr 10.20.30.1 ss-server-port 80

    For BIG-IP 10.x, use the following bigpipe command syntax:

    bigpipe conn ss server <x.x.x.x:> show

    Replace <x.x.x.x:xx> with the IP address and port number for the pool member in question.

    For example:

    bigpipe conn ss server 10.20.30.1:80 show

  • After reloading the BIG-IP configuration manually, you notice that the disabled pool member status has changed to enabled.

    To determine the status of the pool member, use the following bigpipe or tmsh commands:

    For BIG-IP 11.x, use the following tmsh command syntax:

    tmsh show /ltm pool members { <x.x.x.x>:<XX> }

    Replace <x.x.x.x> with the IP address and <XX> with the port number for the pool member in question.

    For example:

    tmsh show /ltm pool members { 10.20.30.1:80 }

    Output appears similar to the following example:

    Ltm::Pool: mypool    
    ---------------------------------------------------------------------------------------------------------------------------------------
    Status               
      Availability : unknown
      State        : enabled
      Reason       : The children pool member(s) either don't have service checking enabled, or service check results are not available yet
                         
    Traffic                ServerSide
      Bits In                    9.6K
      Bits Out                      0
      Packets In                   20
      Packets Out                   0
      Current Connections           0
      Maximum Connections           5
      Total Connections             5

    Ltm::Pool Member: mypool  10.20.30.1:80
    ------------------------------------------
    Status               
      Availability : unknown
      State        : enabled
      Reason       :     
                         
    Traffic                ServerSide  General
      Bits In                       0        -
      Bits Out                      0        -
      Packets In                    0        -
      Packets Out                   0        -
      Current Connections           0        -
      Maximum Connections           0        -
      Total Connections             0        -
      Total Requests                -        0

    For BIG-IP 10.x, use the following bigpipe command syntax:

    bigpipe pool <pool_name> member <x.x.x.x:xx>

    Replace <x.x.x.x:xx> with the IP address and port number for the pool member in question.

    For example, type the following command to determine the status of the pool member 10.20.30.1:80 in a pool named mypool:

    bigpipe pool mypool member 10.20.30.1:http

    Output appears similar to the following example:

    POOL MEMBER mypool/10.20.30.1:http   active,unchecked
    |     session enabled    priority 0    ratio 1
    |     (cur, max, limit, tot) = (0, 0, 0, 0)
    |     (pkts,bits) in = (0, 0), out = (0, 0)
    |     requests (total) = 0
