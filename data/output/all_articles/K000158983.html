K000158983: "Waiting for cluster status" status since added the second blade

Type
Support Solution
Published
2026-01-02
Updated
2026-01-02
Applies to
  • F5OS
  • F5OS-C: 1.8.1
Source
https://my.f5.com/manage/s/article/K000158983

Description

On a multi-blade chassis running F5OS, after adding a second blade, the system may become stuck in "Waiting for cluster status." Repeated log messages such as "Failed to open hosts file - /tmp/omd/hosts_tmp""" and "Init DRBD partition: waiting for local CC..." in" "/var/log/openshift.log." may be observed. The first blade may join the cluster without issue, but subsequent blades fail to join, and the cluster does not form".

Environment

  • Multi-blade chassis with system controllers and compute blades
  • Product: F5OS
  • Symptoms: Cluster not forming after adding a second blade, repeated errors about hosts file and DRBD partition initialization, inability to SSH between controllers, and missing or corrupted SSH configuration files on controllers

Cause

Corruption or misconfiguration of the SSH config file on the system controllers, which breaks controller-to-controller communication and prevents the cluster from forming after adding a blade.

Recommended Actions

  1. Verify SSH connectivity between both system controllers. Attempt to SSH from one controller to the other and check for errors such as "No route to host."
  2. Inspect the SSH configuration file (e.g., /root/.ssh/config or the relevant SSH config file) on both controllers for corruption or misconfiguration.
  3. Replace the corrupted SSH config file on both controllers with a known good version from a working system or from F5 support.
      - Copy the known good SSH config file to /root/.ssh/config (or the appropriate location) on both controllers.
      - Restore SELinux context if applicable (restorecon -Rv /root/.ssh/).))
  4. After replacing the SSH config file, verify that SSH connectivity between controllers is restored.
  5. Tail the openshift.log on the active controller (tail -F /var/log/openshift.log))) to monitor cluster status and confirm that the cluster forms successfully.
  6. If issues persist, collect a new qkview and contact F5 Support for further assistance.
