K000152297: "404 Not Found" response on LB port 80

Type
Support Solution
Published
2025-07-01
Updated
2026-07-12
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000152297

Description

When accessing an HTTPS Load Balancer via port 80 (HTTP without SSL), the system returns an HTTP 404 - Not Found response similar to below:

Environment

  • F5 Distributed Cloud
  • Load Balancer configured to listen on port 443 (HTTPS)
  • "HTTP Redirect to HTTPS" option enabled on at least 1 LB
  • No explicit Load Balancer configured to listen on port 80

Cause

If at least one Load Balancer with redirect enabled exists for a given IP, a listener will be present and will accept HTTP connections, responding with a 404 for unmatched domains.

A listener on port 80 is automatically created if any Load Balancer using a particular IP address has the "HTTP Redirect to HTTPS" option enabled. This listener is required for HTTP-to-HTTPS redirects. If an HTTP request is received on port 80 for a domain that does not match any configured domains on the Load Balancers with redirect enabled, the system responds with a 404 error and the message "HTTP 404 - Not Found". 

Recommended Actions

This is expected behavior. 

To completely avoid accepting connections (prevent TCP handshake etc.) on port 80 and some particular IP, disable all HTTP redirects for every Load Balancer sharing that IP address.
