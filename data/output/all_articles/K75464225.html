Topic

You should consider using this procedure under the following conditions:

  • You are using SSL Server virtual servers.
  • You want to configure the system to match SSL/TLS protocol versions in renegotiated sessions.

Description

The SSL/TLS protocol allows either party in the transaction to renegotiate the SSL/TLS handshake inside of the existing secure session using new cryptographic parameters. Renegotiation is useful when an SSL session is established and one of the parties in the transaction (usually the server) needs to change the parameters of the SSL connection.

In most cases, the SSL/TLS server requires that the SSL/TLS versions specified in the ClientHello message used for renegotiation match the SSL/TLS versions specified in the ServerHello message in the initial SSL/TLS handshake.

In some cases, the SSL/TLS server requires that the SSL/TLS versions (Record layer and Handshake protocol) specified in the initial ClientHello message, match the SSL/TLS versions specified in the ClientHello message used for renegotiation. For example, the initial ClientHello message may advertise TLS 1.0 for both the Record layer and Handshake protocols as in the following example:

Secure Sockets Layer
    TLSv1 Record Layer: Handshake Protocol: Client Hello
        Content Type: Handshake (22)
        Version: TLS 1.0 (0x0301)
        Length: 112
        Handshake Protocol: Client Hello
            Handshake Type: Client Hello (1)
            Length: 80
            Version: TLS 1.0 (0x0301)

The SSL/TLS server may require that the SSL/TLS versions specified in the ClientHello message used for renegotiation match the SSL/TLS versions specified in the initial ClientHello message.

By default, the BIG-IP system uses the same Record layer and Handshake protocol versions in the ClientHello message used for renegotiation that was specified in the ServerHello message in the initial SSL/TLS handshake. You can configure the system to use same Record layer and Handshake protocol versions in the ClientHello message used for renegotiation that was specified in the ClientHello message in the initial SSL/TLS handshake, by modifying the ssl.renegotiatewithinitialclienthello db variable.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have access to the Traffic Management Shell (tmsh) utility.

Procedures

Configuring the ssl.renegotiatewithinitialclienthello db variable

To configure the system to use same Record layer and Handshake protocol versions in the ClientHello message used for renegotiation that was specified in the ClientHello message in the initial SSL/TLS handshake, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Change the ssl.renegotiatewithinitialclienthello db variable to enable by typing the following command:

    modify /sys db ssl.renegotiatewithinitialclienthello value enable

  3. Save the configuration by typing the following command:

    save /sys config
