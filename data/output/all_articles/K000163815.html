K000163815: NGINX ACME module fails to process ACME Order authorization URLs containing JSON-escaped slashes

Type
Support Solution
Published
2026-10-21
Updated
2026-10-21
Applies to
  • NGINX Products
  • NGINX Plus: 37.0.2
Source
https://my.f5.com/manage/s/article/K000163815

Description

The NGINX ACME module can fail to update certificates after a successful ACME newOrder request when the ACME Order response contains authorization URLs with JSON-escaped forward slashes (\/). The error is:

cannot deserialize response (

invalid type: string "...",

expected a borrowed string

)

Cause

The authorization URL deserializer requested borrowed &str values. When serde_json encountered an escaped character such as \/, it had to unescape the value and could not return it as a borrowed string from the original input buffer. Deserializing authorization URLs as owned String values resolves the issue.

Answer/Recommended Actions

  • Upgrade to the first NGINX ACME module release containing the engineering fix when available.

  • Until the fixed release is available, configure the ACME service or proxy to serialize JSON without escaped forward slashes, if supported.

  • If the response serialization cannot be changed, continue using the existing certificate-management method for affected hosts until the fixed module is available.

  • Review the related identifiers deserialization logic when adopting the fixed release because it uses a similar borrowing approach.

Additional Information

Escaped forward slashes (\/) are valid JSON and represent the same character as /. The issue affects processing of the authorizations array in an ACME Order response. Directory and newAccount responses containing escaped slashes are processed successfully.
