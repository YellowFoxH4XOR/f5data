Description

When you use third-party snmp agent to query BIG-IP, you may get the messy code like 'X~'
For example, If you use snmpwalk on external linux system to get virtual server IP address, you may get the bellowing output.

snmpwalk -v2c -c public 10.171.108.61 1.3.6.1.4.1.3375.2.2.10.1.2.1.3

iso.3.6.1.4.1.3375.2.2.10.1.2.1.3.15.47.67.111.109.109.111.110.47.116.101.115.116.95.86.115 = STRING: "

X~"

Environment

  • BIG-IP LTM
  • SNMP

Cause

The issue may be due to the Interpretation issue for SNMP OCT String on the third-party system.

Recommended Actions

  • Verify the snmp result on BIG-IP,  you can run the query to the OID on BIG-IP and check the result. For example,
         # snmpwalk -v2c -c public 127.0.0.1 1.3.6.1.4.1.3375.2.2.10.1.2.1.3
       F5-BIGIP-LOCAL-MIB::ltmVirtualServAddr."/Common/test_Vs" = Hex-STRING: 0A 58 7E 0C
  • Run capture on third-party system and BIGIP, check if the snmp response is correct or not. For example, we can check the value part in the capture.

           Object Name:                                                                                                                             1.3.6.1.4.1.3375.2.2.10.1.2.1.3.15.47.67.111.109.109.111.110.47.116.101.115.116.95.86.115                                                 (iso.3.6.1.4.1.3375.2.2.10.1.2.1.3.15.47.67.111.109.109.111.110.47.116.101.115.116.95.86.115)

  • If you find third-party system gets the correct value but still shows messy code, there should be an interpretation issue for SNMP OCT String on the third-party system. You need to check if your monitoring system can recognize the format correctly.
