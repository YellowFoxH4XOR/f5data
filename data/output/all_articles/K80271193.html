Description
You may find that BIG-IP creates and deletes the unexpected radius server configuration objects automatically in /var/log/audit:

Example:
Jan 11 19:14:26 testBIG-IP.com notice mcpd[4256]: 01070417:5: AUDIT - client tmsh, tmsh-pid-17839, user admin - transaction #1221545-2 - object 0 - create { radius_server { <radius_server_name> "/Common/f5-teem_delete_me_ad632ce0d2e6" radius_server_secret "***" radius_server_server "foo" } } [Status=Command OK]
Jan 11 19:14:26 testBIG-IP.com notice icrd_child[17839]: 01420002:5: AUDIT - pid=17839 user=admin folder=/Common module=(tmos)# status=[Command OK] cmd_data=create auth radius-server /Common/f5-teem_delete_me_ad632ce0d2e6 { secret **** server foo }

Jan 11 19:14:26 testBIG-IP.com notice mcpd[4256]: 01070417:5: AUDIT - client tmsh, tmsh-pid-17839, user admin - transaction #1221685-2 - object 0 - obj_delete { radius_server { <radius_server_name> "/Common/f5-teem_delete_me_ad632ce0d2e6" } } [Status=Command OK]
Jan 11 19:14:26 testBIG-IP.com notice icrd_child[17839]: 01420002:5: AUDIT - pid=17839 user=admin folder=/Common module=(tmos)# status=[Command OK] cmd_data=delete auth radius-server f5-teem_delete_me_ad632ce0d2e6

Environment

  • BIG-IP
  • Authenication
  • Radius
  • iAppLX extensions (including AS3 and/or F5 Cloud Failover)

Cause
Creating a radius server configuration object is internally used for encryption using BIG-IP's "Secure Vault" master key. It is used in various iApp LX extensions including AS3 and Cloud Failover Extension.

Recommended Actions
This is expected behavior with certain types of iApp LX extensions are used and can be safely ignored.
