Topic

You should consider using this procedure under the following condition:

  • You want to apply the FIPS HSM change introduced by ID 1023341 while preserving all stored information.

Description

ID1023341 introduced a FIPS HSM configuration change, set during initialization, to disable key export. Applying this change to an existing BIG-IP system requires reinitialization of the FIPS HSM. This normally clears all stored information, leading to the loss of all configured keys. 

The following procedure exports keys before reinitialization, and imports them after, thereby preserving them. This procedure needs to be run on each member of a high availability (HA) group independently.

Platforms

This process applies to only platforms containing the Cavium Nitrox III FIPS HSM: 

  • 10350v-F
  • i5820-DF
  • i7820-DF
  • i15820-DF

Note: This process is not required on the rSeries r5920-DF and r10920-DF. While they contain a Cavium Nitrox III FIPS HSM, these rSeries systems are not affected by this issue.

This process should not be used with older platforms containing the Cavium Nitrox XL FIPS HSM. See the F5 Certifications page for more information.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have root access, using SSH or console, to the Advanced shell (bash). This procedure is not supported in appliance mode.
  • Have the FIPS HSM Security Officer (SO) password.
  • Have your private key passphrases available if keys are encrypted with passphrases
  • Have upgraded your BIG-IP system to the following, or later, version on a given software branch:
    BranchBIG-IP version
    17.0.x17.0.0
    16.1.x16.1.1
    15.1.x15.1.5.1
    14.1.x14.1.4.6
    13.1.x13.1.5

Note: This procedure is required only on FIPS HSMs that have not been initialized since the upgrade to the TMOS versions listed in the previous table. To determine the status of the FIPS HSM, refer to the following Determine the current status procedure.

Important: Downgrading to an earlier version of TMOS and reinitializing the FIPS HSM will remove the fix, re-enabling key export. Downgrading TMOS without reinitializing the FIPS HSM alone will not re-enable key export.

Procedures

Review all of the following steps before attempting to perform the procedures.

Important: You should perform the following procedure during a maintenance window, as it may cause traffic disruption. The process requires disabling services on the BIG-IP system. If the device is part of an HA group, it should be made Standby before the process begins. If it is the sole device, a traffic disruption is unavoidable while the procedure is conducted. F5 recommends that you create a UCS backup and store it off the BIG-IP system before you begin the procedure. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

  • Determine the current status
  • Apply the fix

Determine the current status

The first step is to determine the status of the BIG-IP system and whether any further steps are required. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To download and install the utility, go to https://my.f5.com/manage/s/downloads and sign in using your MyF5 account.
  2. For Group, select Hardware-Specific.
  3. For  Product Line, select FIPS_UTIL.
  4. For Product version and Select a product container, select the latest version.
  5. For Select a download file, select n3fipsutil.
  6. For Download locations, select a location close to you.
  7. To download the file, select Download. 

    To download the md5 file, repeat steps 5 through 7 selecting n3fipsutil.md5 in step 5. You can then verify the file using the steps in K8337: Verifying the MD5 checksum for the downloaded F5 software file.

  8. Transfer the n3fipsutil file to the /var/tmp/ directory on the BIG-IP system using the instructions in K175: Transferring files to or from an F5 system.
  9. Log in to the BIG-IP system as root.
  10. Set execute permissions on the /var/tmp/n3fipsutil file by entering the following command:

    chmod 755 /var/tmp/n3fipsutil

  11. Check the FIPS HSM to see if it has been initialized with the key export by entering the following command:

    /var/tmp/n3fipsutil -exportKeyCheck

    In the command output, note the following:

    • KeyExport: Disabled indicates the fix has been applied; no further action is required.
    • KeyExport: Enabled indicates the fix has not been applied; proceed with the following procedure.
  12. If you do not need to perform additional procedures, you may remove the utility from the system by entering the following command:

    rm /var/tmp/n3fipsutil.

Apply the fix

Note: When you use vCMP, you must perform the following procedure individually on each Guest.

Impact of procedure: Perform the following procedure during a maintenance window, as it may cause a traffic disruption.

  1. Log in to the BIG-IP system as root.

    Note: If the n3fipsutil utility is not installed, you can follow the steps in the previous procedure Determine the current status to install it.

  2. Confirm that the FIPS key export status of the system is KeyExport: Enabled by entering the following command:

    /var/tmp/n3fipsutil -exportKeyCheck

    • If the command output is KeyExport: Disabled, the fix is already present on the system; no further action is required.
    • If the command output is KeyExport: Enabled, complete the rest of this procedure.
    • If the command output is KeyExport: Unknown, means that the HSM does not contain any private keys. You can workaround this by running tmsh create sys crypto key <testexample> security-type fips to generate a key prior to retrying fipsutil -exportKeyCheck.  The workaround can be cleaned up by running tmsh delete sys crypto key <testexample>.
    Note that running with a mix of key export enabled and disabled will cause config sync issues.

  3. Create a temporary directory for the key backups by entering the following command:

    mkdir /var/tmp/fipsexport

  4. Save the current configuration by entering the following command:

    tmsh save sys config

  5. View the configured FIPS keys by entering the following command:

    tmsh show sys crypto fips key

    Record the output for use in step 13.

  6. Export the FIPS keys by entering the following command:

    /var/tmp/n3fipsutil -exportAll /var/tmp/fipsexport [-n <partition_name>]

    In the command, note the following:

    • [-n <partition_name>] is optional and applicable only in the case where the system has custom partition names, such as in vCMP.
  7. Stop the running services by entering the following command:

    tmsh stop sys service all

  8. Reinitialize the FIPS card by entering the following command:

    fipsutil init -f

  9. Restart the running services by entering the following command:

    tmsh restart sys service all

  10. Confirm that the FIPS key export status of the system is KeyExport: Disabled by entering the following command:

    /var/tmp/n3fipsutil -exportKeyCheck

    • If the command output is KeyExport: Enabled, confirm that the BIG-IP system is running a fixed version per above before returning to step 7.
  11. Import the FIPS keys by entering the following command:

    /var/tmp/n3fipsutil -importKeys /var/tmp/fipsexport [-n <partition_name>]

    In the command, note the following:

    • [-n <partition_name>] is optional and applicable only in the case where the system has custom partition names, such as in vCMP.
  12. Restart services again by entering the following command

    tmsh restart sys service all

  13. Verify the FIPS keys have been restored by entering the following command:

    tmsh show sys crypto fips key

    Compare the output with that of step 5.

  14. Remove the key backup from the system by entering the following command:

    rm -rf /var/tmp/fipsexport

  15. Remove the n3fipsutil utility from the system by entering the following command:

    rm /var/tmp/n3fipsutil

The FIPS HSM should now have KeyExport: Disabled, as introduced by ID1023341, and the keys should function as before.

Note: After step 8, you may observe error logs such as the following examples:

  • "load_config_files[15987]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01070712:3: unable to synchronize FIPS key (/Common/otters1)
  • Unexpected Error: Loading configuration process failed.
  • localhost.localdomain load_config_files[15987]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01070712:3: unable to synchronize FIPS key (/Common/otters1)"

These are transient errors, which you can ignore. They will be resolved after step 10.

Important: You should consider the contents of the /var/tmp/fipsexport/ directory as highly sensitive. If this directory is copied off the BIG-IP system, be sure and secure it using the best security practices.
