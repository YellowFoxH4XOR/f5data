Topic

This is an overview of the VIPRION system's home directory synchronization behavior. The home directory is the user's default directory after login.

Description

For each new user you add to the VIPRION system, the system creates a corresponding home directory (/home/<username>). If you grant new users terminal access, the system automatically places the user into their home directory upon login. The system stores the user's Advanced Shell (bash) startup files and history in their home directory.

The VIPRION system synchronizes home directories in two ways:

  • Within the cluster
  • Between clusters

Within the cluster

When you add a new user to the VIPRION system, the system creates the user's home directory on all the blades currently installed in the chassis. In addition, the VIPRION will synchronize the contents of a user's home directory across all blades to maintain consistency of the directory within the cluster. For example, if a user creates a file inside their home directory while they are logged in to the primary blade, the system will replicate the file to the other blades.

In BIG-IP 10.x and earlier, synchronization within the cluster occurs at user creation time only.

Between clusters

When a VIPRION system is a member of a device group, the system will synchronize any newly added users to peer systems during a ConfigSync operation. Peer VIPRION systems will create user home directories with bash startup files, as previously noted, for each user that the ConfigSync operation adds to the configuration. However, content in the home directory is not synchronized in ConfigSync operations. For example, if a user creates a file inside their home directory, the system will not synchronize the file to any device group peers. For more information, refer to K21259300: BIG-IP items that are not synchronized between device group members during a ConfigSync operation.

In BIG-IP 10.x and earlier when the VIPRION system is a member of a high availability pair, the system will synchronize home directories during a ConfigSync operation as follows:

  • The system creates new home directories on all the blades of the receiving system
  • The system synchronizes the home directories, in full, including their contents, to only the primary blade of the receiving system

Note: Synchronization between clusters in 10.x and earlier occurs because the system configures home directories, by default, to be included in a UCS archive. For more information, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive. In versions 11.x and later, the UCS archive is no longer used for synchronization.

Important: In some BIG-IP versions, when executing a ConfigSync operation between VIPRION systems, the system creates new home directories on only the primary blade of the receiving system. For more information, refer to K10925: During a ConfigSync operation between VIPRION systems, new home directories are only created on the primary blade of the receiving system.

Recommendations

Within the cluster

In BIG-IP 10.x and earlier, you can manually synchronize home directories between the primary blade and a secondary blades by running the following command on the primary blade:

Impact of procedure: The procedure will overwrite files in the user's home directory of the secondary blades that have the same name as files on the primary blade.

tar cvf - /home | ssh <slot number of secondary> "( cd / ; tar xvf - )"

For example:

tar cvf - /home | ssh slot2 "( cd / ; tar xvf - )"

Between cluster

In BIG-IP 11.x and later, you can manually synchronize the contents of home directories between the members of the device group by running the following command on the primary blade of the system you want to initiate the synchronization from.

Impact of procedure: The procedure will overwrite files in the user's home directory of the target system that have the same name as files on the source system.

tar cvf - /home | ssh <cluster management IP address or self IP address of device group peer> "( cd / ; tar xvf - )"

For example:

tar cvf - /home | ssh 10.1.1.2 "( cd / ; tar xvf - )"
