Description

This article provides clear guidelines on who is authorized to request configuration changes in F5 Distributed Cloud (XC) and the approval scenarios that determine how the Security Operations Center (SOC) processes such requests.

By defining authorization levels and approval requirements, this document reduces delays, ensures proper governance, and streamlines change management workflows across customer environments.

Environment

F5®Distributed Cloud (XC)

F5® Web Application Firewall (WAF)

F5® DDoS

F5® Bot Defense

Cause

Incomplete or unauthorized configuration change requests often result in:

  • Execution delays
  • Repeated approval cycles
  • Increased operational overhead

Clear eligibility rules ensure SOC can process requests securely and efficiently.

Answer/Recommended Actions

      Who Can Raise a Change Request (Eligibility & Approval Rules): 

      Only users listed in the Tenant IAM User List are eligible to raise a configuration change request. Requests from users outside the Tenant will be considered invalid and will not be processed.

      SOC evaluates eligibility under the following scenarios:

      Scenario A — Tenant-Level Administrative Roles

      • Users with the Tenant Owner role can raise any change request without additional approval.
      • Users who belong to a group with the role ves-io-admin-role (applied either globally across all namespaces or within the specific namespace of the target resource) may also raise change requests directly.

      Note: In these cases, SOC will not request additional approval.

       

      Scenario B —  Service-Based Roles

      F5 Distributed Cloud IAM provides service-specific roles, which come in two forms:

      1. -admin roles (e.g., f5xc-waf-admin, f5xc-bot-defense-admin):
        • Grants administrative rights over all objects within that service, regardless of who created them.
        • A user with a relevant -admin role in the correct namespace can raise a change request for that service without additional approval.

      2. -User Roles (-user, e.g., f5xc-waf-user, f5xc-bot-defense-user):

        • These roles can only modify objects they originally created.
        • If Object Ownership cannot be verified, SOC will require explicit approval from:
          • Tenant Owner, OR
          • A user with the corresponding service-admin role (e.g., f5xc-waf-admin), OR
          • A user/group with ves-io-admin-role for the relevant namespace.
          • (Refer to example screenshot below)

                        

      Scenario C —  Additional Approval Scenarios

      SOC will request explicit approval if:

      • The requester is not a Tenant Owner.
      • The requester is not part of a group with ves-io-admin-role.
      • The requester only has a -user service role and is attempting to change objects created by another user.
      • The requester only has a read/monitoring/reporting role (no configuration privileges; e.g., f5xc-waf-monitor, f5xc-bot-defense-viewer).

       

      How to Provide Additional Approval

      If required, approvals can be provided by:

      • Having the approver add a direct approval comment on the ticket.

      Additional Information

      • ves-io-admin-role provides full administrative rights across the assigned namespace(s).
      • Service-specific -admin roles provide authority over all objects within a service.
      • Service-specific -user roles provide authority only over objects created by the requester.
      • Submitting change requests with complete information and through authorized users ensures faster processing, reduces approval cycles, and aligns with F5’s security and operational governance best practices.
