Topic

You can configure a virtual server to listen on a range of ports, or a list of specific ports, instead of a single port. Currently, this must be done using iRules. For security reasons, when you configure an iRule to specify a range of ports, or a list of specific ports, for a virtual server, you should use the reject iRules command because it triggers the BIG-IP LTM system to reject connections that do not fall within the specified range of ports, or matches the specific ports listed.

Prerequisites to creating the iRule

Before you configure the iRule that specifies a range of ports for a virtual server, you must complete the following steps:

  • Define the destination virtual server with the following service port: 0 (*All Ports).

    For more information about defining the destination virtual server using the 0 (*All Ports) service port, refer to Configuration Guide for BIG-IP Local Traffic Management.

  • Enable port translation for the virtual server.

    For more information about enabling port translation for the virtual server, refer to Configuration Guide for BIG-IP Local Traffic Management.

    Note: You must enable port translation if the pool member service ports do not fall within the range of ports defined in the iRule.

Creating an iRule to specify a range of allowed ports for a virtual server

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRules List.
  3. Select Create.
  4. For Name, enter a name for the iRule.
  5. For Definition, enter the following syntax, replacing the TCP <start port> and TCP <end port> with the boundaries of your port range:

    when CLIENT_ACCEPTED {    
        if {([TCP::local_port] >= <start port>  && [TCP::local_port] <= <end port> ) } {
           return   )
        else reject
    }

  6. Select Finished.
  7. Associate the iRule with a virtual server.

Example iRules

Specifying a single port range

To specify a port range between 799 and 1004 that allows access, you create an iRule similar to the following example:

when CLIENT_ACCEPTED {
    if { ( [TCP::local_port] >= 799 && [TCP::local_port] <= 1004 ) } {
       return }
    else reject
}

This iRules construct specifies the following parameters:

  • When the requested port includes port 799 through 1004, the BIG-IP system accepts the connection.
  • When the requested port is outside of port 799 through 1004, the BIG-IP system rejects the connection and sends a reset to the client.

Specifying two or more port ranges

To specify two separate port ranges that allow access (a range of 799 to 1004 and a range of 3000 to 3050), you create an iRule similar to the following example:

when CLIENT_ACCEPTED {
    if { ( [TCP::local_port] >= 799 && [TCP::local_port] <= 1004 )
    || ( [TCP::local_port] >= 3000 && [TCP::local_port] <= 3050 ) } {
       return }
    else reject
}

This iRule construct specifies the following parameters:

  • When the requested port is between or includes port 799 through 1004 or ports 3000 through 3050, the BIG-IP system accepts the connection.
  • When the port requested does not match either port range, the BIG-IP system rejects the connection and sends a reset to the client.

Specifying two or more specific port numbers

To specify two or more separate port numbers that allow access (to 799 and to 3000), you create an iRule similar to the following example:

when CLIENT_ACCEPTED {
    if { ( [TCP::local_port] == 799 ) }{
       return }
    elseif { ( [TCP::local_port] == 3000 ) }{
       return }
    else reject
}

This iRule construct specifies the following parameters:

  • When the requested port is port 799 or port 3000, the BIG-IP system accepts the connection.
  • When the port requested does not match either of those ports, the BIG-IP system rejects the connection and sends a reset to the client.

Translating the destination port of the request

To have the virtual server accept a request on a port and then send that request to a destination listening on a different port, create an iRule similar to the following example:

when CLIENT_ACCEPTED {
if { ( [TCP::local_port] > 900 && [TCP::local_port] < 10000 ) } {
translate port enable
node 10.0.0.10 22
}
else drop
}

This iRule construct specifies the following parameters:

  • When the requested port is with in the port range of 900-10000, the request is forwarded using the translate port enable command to the specified node 10.0.0.10 port 22.
  • When the port requested does not match the port range, the system drops the request (alternatively, the option you can use reject to send a TCP reset for the request.

when HTTP_REQUEST {
   if { [string tolower [HTTP::uri]] contains "/pictures" } {
      translate port enable
      node 10.0.0.10 8000
   } else {
      pool http_servers
   }
}

This iRule construct specifies the following parameters:

  • When receiving a HTTP request the contains the URL of /pictures the request is forwarded to the node 10.0.0.10 port 8000 using the translate port enable command .
  • When the the HTTP request does not match the URL /pictures, the request is sent to the pool http_servers and load balanced based on the pool configuration .
