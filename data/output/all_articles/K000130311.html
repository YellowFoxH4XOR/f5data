K000130311: Can't login with User AD after added external public internet default routes

Type
Support Solution
Published
2022-12-22
Updated
2022-12-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.7
Source
https://my.f5.com/manage/s/article/K000130311

Description

  • Facing issue login via remote LDAP authentication to BIG-IP Configuration Utility (GUI) or SSH, while other BIG-IP has no issue.
  • The issue only happens after added a new external public default routes for internet access.
  • Added a single IP for the LDAP server instead of the LDAP forest subnet range to be routed via mgmt interface which used for reaching to the LDAP forest IP subnet range
    • example: ldap.com
      • # dig ldap.com or nslookup ldap.com
      • return 3 IPs and only 1 out of 3 IP are added to route through mgmt interface

Environment

  • BIG-IP
  • Remote LDAP Authentication
  • GUI/SSH login

Cause

LDAP subnet routed to internet interface instead of via mgmt interface, and this happen only after added external public internet routes.

Recommended Actions

1. Add LDAP IP subnet range to be routed via mgmt interface, command as below:
# tmsh create /sys management-route <name> network <destination network>/<netmask> gateway <management gateway>
# tmsh save /sys config

2. Check to make sure the new mgmt routes are added successfully with shell command.
# ip route
