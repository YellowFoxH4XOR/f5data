Known Issue

If you attempt to copy a configuration from one volume to another using the cpcfg command, the operation may fail.

This issue occurs when all of the following conditions are met:

  • You are running on a VIPRION chassis platform.
  • You attempt to run the cpcfg command to copy a configuration from one volume to another.

Impact

You are unable to copy a configuration between volumes.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe error messages similar to the following examples:

    info: Getting configuration from HD1.3
    info: Copying configuration to HD1.1
    info: Applying configuration to HD1.1
    error: status 256 returned by command: F5_INSTALL_MODE=install F5_INSTALL_SESSION_TYPE=hotfix chroot /mnt/tm_install/23102.e3MAZU /usr/local/bin/im -force /var/local/ucs/config.ucs
    info: >++++ result:
    info: Extracting manifest: /var/local/ucs/config.ucs
    info: /shared: Not enough free space  
    info:   6144 bytes required
    info:   0 bytes available
    info: /var/local/ucs/config.ucs: Not enough free disk space to install!
    info: Operation aborted.

  • The BIG-IP system fails to copy the configuration to the destination volume.

Workaround

To work around this issue, you can save a user configuration set (UCS) file from the source volume, reboot to the destination volume, then load that UCS file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Back up the configuration of your source volume to a UCS file.
  2. Copy this UCS file to another device.
  3. Start the destination volume.
  4. Copy the UCS file back to the BIG-IP system to the destination volume.
  5. Restore the UCS file in the destination volume.

For more detailed information about backing up and restoring UCS files, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 13.x).
