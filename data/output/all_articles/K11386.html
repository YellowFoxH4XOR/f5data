Known Issue

This is the result of a known issue. In rare instances, if two clients simultaneously request the same stale gzip file located in RAM Cache, TMM may core and report the following error message to /var/log/tmm:

Assertion "only add gzip docs once" failed.

In order for this issue to occur, the RAM Cache gzip consolidation feature must be enabled. By default, this feature is enabled. To verify whether gzip consolidation is enabled on your BIG-IP system, enter the bigpipe db Ramcache.GzipConsolidate command.

For example:

[root@3400a:Active] config # bigpipe db Ramcache.GzipConsolidate
Ramcache.GzipConsolidate = enable
[root@3400a:Active] config #

F5 Product Development tracked this issue as CR138544 and CR138518, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM or Edge Gateway release notes.

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.1.0-3372.0-HF1, which has been issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about downloading software from F5, refer to K167: Downloading software from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 Networks product hotfixes for BIG-IP version 10.x systems.

Workaround

You can work around this issue by disabling the RAM Cache gzip consolidation feature. To do so, run the following command:

bigpipe db Ramcache.GzipConsolidate disable

Note: Disabling the gzip consolidation feature may result in duplicate copies of the same gzip file within RAM cache. When duplicate copies of the same file exist, the RAM cache feature may operate less efficiently.
