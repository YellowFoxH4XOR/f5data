Description

This solution will describe how Windows 11 will identify in a APM OS Check.

  • Windows 11 client display as Windows 10 in an OS Check.
  • You will see the following log message for session variable session.client.platform in /var/log/apm:

<bigip_hostname> info apmd[6377]: 01490007:6: /Common/<acess_policy>:Common:<session_id>: Session variable 'session.client.platform' set to 'Win10'
 

Environment

  • Windows 11 OS
  • APM (Access Policy Manager)
  • VPE (Virtual Policy Editor)
  • Client OS check object.

Cause

This behavior occurs because Windows 11 identifies itself as Windows 10. The APM server uses the browser User-Agent string to identify the client OS. Windows 10 and 11 are indistinguishable from the User-Agent

Important: This is no longer the case on the 7.2.5.0 and newer versions of the APM Client. Please see K000148984: VPN Connections Fail on Windows 11 PCs after upgrade to 7.2.5.0 client for more details.

Recommended Actions

As per current available information, Windows 10 and 11 share the same major and minor version and Windows 11 is differentiated by its build number, 22000 or greater.
Adding a "Windows Registry" agent such as this before the "Windows Info" agent do branch off Windows 11 machines.
Windows 11 machines, you can set the expression like: "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion"."CurrentBuildNumber">="22000"

For Windows 10 machines, you can set the expression like: "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion"."CurrentBuildNumber"<"22000"

Additional Information

On a Windows 11 OS you can use the Windows regedit utility to access the Windows Registry you can navigate to HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion and see that the ProductName Key is set to Windows 10.
