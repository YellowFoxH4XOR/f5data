Known Issue

This is the result of a known issue. The gencert utility implies a default key size of 1024 bits is used if a key size is not specified. However, the utility will exit and display available options if a key size is not specified.

For example, to generate a self-signed key and certificate pair, type the following command:

# gencert -n "askf5.f5.net" -h "askf5.f5.com"

The command displays the following output with available options when a key size is not specified:

generate a self-siged key/cert pair. Options shown are the default.
gencert --path|-p "/config/ssl"
--name|-n "askf5.f5.com"
--commonname|-h "askf5.f5.com"
--country|-c "US"
--state|-s "WA"
--city|-t "Seattle"
--org|-o "MyCompany"
--orgunit|-u "IT"
--email|-e "root@localhost.localdomain"
[--fips|-f] if this option is used, the key may be created in FIPS
<keysize> (1024)

Note: In the last line of the command output example, <keysize> (1024) implies a default key size of 1024 bits is used when a key size is not specified.

F5 Product Development is tracking this issue as CR116940.

Resolution

Workaround

You can work around this issue by specifying a key size.

For example:

gencert -n "askf5.f5.com" -h "askf5.f5.com" 1024

Note: For more information regarding the gencert utility, refer to K6360: Overview of the gencert utility.
