Known Issue

BIG-IP APM configurations may fail to load on freshly installed systems.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system has a fresh manufacturing installation or has just been reformatted.
  • You attempt to boot to a newly installed slot containing a BIG-IP APM configuration or attempt to load a UCS archive containing a BIG-IP APM configuration.

Impact

The configuration fails to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H484988 on the Diagnostics > Identified > Medium screen.
  • When booting to a new installation slot, the configuration fails to load properly.
  • Loading a UCS archive fails.
  • The console may show services restarting.

    For example:

    localhost emerg logger: Re-starting mcpd
    localhost emerg logger: Re-starting named
    localhost emerg logger: Re-starting tmrouted
    localhost emerg logger: Re-starting bigd
    localhost emerg logger: Re-starting lacpd
    localhost emerg logger: Re-starting tmm
    localhost emerg logger: Re-starting tmm1

  • The console may show the mcpd process failing.

    For example:

    Error: failed to reset strict operations; disconnecting from mcpd. Will reconnect on next command.
    The connection to mcpd has been lost, try again.

  • The system generates messages to the /var/log/ltm file that appear similar to the following example:

EPSEC - File Copy to /shared location failed Unexpected Error: Loading configuration process failed.

Workaround

To work around this issue, you can wait a few minutes for BIG-IP APM provisioning to complete, and then attempt to load the configuration again. Alternatively, you can create the /shared/apm/images/ directory and attempt to load the configuration again. To create the /shared/apm/images/ directory, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM command line.
  2. Type the following command:

    mkdir -p /shared/apm/images/

After creating the directory, the file successfully copies and the system properly initializes.
