Description

BIG-IQ is unable to establish device trust with BIG-IP if Basic Auth iControl REST is disabled on BIG-IP. For more information, refer to K58092347: Disable Basic Auth for iControl REST. In addition, if this is disabled on an existing managed BIG-IP, functions such as service (re)discovery, (re)import, config evaluation/deployment and device monitoring for that BIG-IP will fail too.

When Basic Auth is set to disabled on BIG-IP, BIG-IQ's attempt to establish device trust with BIG-IP will lead to errors similar to the following. They can be found in /var/log/restjavad.0.log.
[ERROR][29 Nov 2021 22:59:00 PST][/cm/global/tasks/device-trust/49847abc-6d5a-41d2-b02d-9fd7df41687f/worker BigIPTrustTaskWorker] Failed to connect to 10.10.10.10, check credentials: Unauthorized(401)
[ERROR][29 Nov 2021 22:59:00 PST][/cm/global/tasks/device-trust/49847abc-6d5a-41d2-b02d-9fd7df41687f/worker BigIPTrustTaskWorker] Failed to connect to 10.10.10.10, check credentials: Unauthorized(401)

Similarly, when disabled, BIG-IQ marks those affected BIG-IP as unavailable after a few minutes. Following is an example of the error logs from /var/log/restjavad.0.log:
[INFO][29 Nov 2021 22:18:44 PST][/shared/identified-devices/config/device-refresh DeviceRefreshWorker] Device Refresh Failed (enable DEBUG logging for details): https://10.10.10.10:443/mgmt/shared/inflate
[INFO][29 Nov 2021 22:19:46 PST][/cm/shared/eventsource/device-state DeviceStateEventWorker] device: bigip1.example.com not available for one cycle
[INFO][29 Nov 2021 22:20:44 PST][/shared/identified-devices/config/device-refresh DeviceRefreshWorker] Device Refresh Failed (enable DEBUG logging for details): https://10.10.10.10:443/mgmt/shared/inflate
[INFO][29 Nov 2021 22:21:46 PST][/cm/shared/eventsource/device-state DeviceStateEventWorker] device: bigip1.example.com not available for two consecutive cycles, sending availability event
[WARN][29 Nov 2021 22:21:46 PST][/cm/shared/event/alerts AlertCollectionWorker] Managed device bigip1.example.com (10.10.10.10:443) marked unavailable

Environment

  • BIG-IQ and BIG-IP environment
  • Basic Authentication disabled for iControl REST on BIG-IP


Cause

Communication between BIG-IQ and BIG-IP requires the use of Basic Auth. Without allowing Basic Auth between BIG-IP and BIG-IQ, BIG-IQ is unable to gain access to BIG-IP's API endpoints for management and monitoring purposes.

Recommended Actions

The workaround is to allow Basic Auth between BIG-IP and BIG-IQ.

  1. On BIG-IP, edit /etc/httpd/conf/httpd.conf, search for "ProxyMatch /mgmt/" and add BIG-IQ Discovery address into the access list. Following is an example where 10.10.10.10, BIG-IQ Discovery address, is added into the list.

    <ProxyMatch /mgmt/>
        # Satisfy any means that a connection may satisfy either the address access
        # restriction or the authentication restriction in order to be authorized to
        # access this directory.
        Satisfy any

        # Access is restricted to traffic from 127.0.0.1
        Order Deny,Allow
        Deny from all
        Allow from 127.0.0.1
        Allow from 127.4.2.2
        Allow from 10.10.10.10

        # This is an exact copy of the authentication settings of the document root.
        # If a connection is attempted from anywhere but 127.*.*.*, then it will have
        # to be authenticated.

        # we control basic auth via this file...
        Include /etc/httpd/conf/basic_auth*.conf

        AuthName "Enterprise Manager"
        AuthPAM_Enabled on
        AuthPAM_ExpiredPasswordsSupport on
        require valid-user
    </ProxyMatch>
     
  2. Lastly, on BIG-IP, restart httpd service:
    # bigstart restart httpd
