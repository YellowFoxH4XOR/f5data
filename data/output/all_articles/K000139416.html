K000139416: Firewall Check does not detect UFN on Linux.

Type
Support Solution
Published
2024-04-26
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000139416

Description

Firewall check does not detect for Linux client with UFW (UncomplicatedFirewall) which is functioning.

Release note says it is supported, and the version UFW in the client is supported.

 

/var/log/apm log shows the Access profile detects UFW however produce error:

info apmd[<pid>]: 01490007:6: /Common/<APM_profile>:Common:<session_ID>: Session variable 'session.check_software.last.fw.item_1.name' set to 'UFW'

...

info apmd[<PID>]: 01490007:6: /Common/<APM_profile>:Common:<session_ID>: Session variable 'session.check_software.last.fw.item_2.errors' set to 'Failed to get 'state'. code: -22 method: 1007 define: 'WAAPI_ERROR_ACCESS_DENIED' description: 'Defines an error when the access is denied for the invocation call requested.' '

 

 

Environment

  • BIG-IP APM
  • VPE - Firewall Check
  • UFW

 

Cause

  • Unlike Mac/Windows, Linux f5PloicyServer.exe loads OESIS library only as a normal user, so any code to detect AV/FW products is executed with normal user privileges. To detect few AV/FW states, they need root user permissions.

 

Recommended Actions

  • Run browser as root
  • Use another browser and browser window for browsing
