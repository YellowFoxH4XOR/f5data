Topic

You should consider using this procedure under the following condition:

  • You want to configure two-way Secure Sockets Layer (SSL) authentication to the Configuration utility.

Description

Two-way authentication, also known as mutual authentication, allows both the client and the server to authenticate each other so both parties are assured of the other's identity.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have access to the BIG-IP command line with root privileges.

Procedures

To configure a two-way client and server certificate, perform the following steps:

  • Creating a trusted CA key and certificate
  • Creating and signing a client certificate
  • Creating a client PKCS12 certificate
  • Configuring the BIG-IP http server for two-way authentication

Note: In the following procedures, F5 assumes that you have already created the directory represented as /shared/tmp/exampleCA.

Creating a trusted CA key and certificate

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To generate a random number file, use the following command syntax:

    openssl rand -out <Directory-Path>/<Random-Number-Filename> <Size-to-seed-the-Random-Number>

    For example, to generate a random number with file /shared/tmp/exampleCA/.rand using a 2048 byte size, type the following command:

    openssl rand -out /shared/tmp/exampleCA/.rand 2048

  2. To generate a Certificate Authority (CA) key, use the following command syntax:

    openssl genrsa -rand <Directory-Path>/<Random-Number-Filename> -out <Directory-Path>/<CA-Key-Filename> <Key-Strength: Number-of-bits>

    For example, to create the CA key clientCA.key using the random number file /shared/tmp/exampleCA/.rand and the key size of 2048 bits, type the following command:

    openssl genrsa -rand /shared/exampleCA/.rand -out /shared/tmp/exampleCA/clientCA.key 2048

  3. To generate a CA certificate, use the following command syntax:

    openssl req -x509 -new -key <Directory-Path>/<CA-Key-Filename> -out <Directory-Path>/<CA-Cert-Filename> -days <Number-of-Days>

    For example, to generate a CA certificate clientCA.crt of type x509, using the key clientCA.key that is valid for 7300 days, type the following command:

    openssl req -x509 -new -key /shared/tmp/exampleCA/clientCA.key -out /shared/tmp/exampleCA/clientCA.crt -days 7300

Creating and signing a client certificate

Complete the following procedure to create and sign a certificate using the trusted CA.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To create a client certificate key, use the following command syntax:

    openssl genrsa -rand <Directory-Path>/<Random-Number-Filename> -out <Directory-Path>/<Client-Certificate-Key-Filename> <Key-Strength-in-Bits>

    For example, to create a client certificate key client1.key using the random number file /shared/tmp/exampleCA/.rand and the key size of 2048 bits, type the following command:

    openssl genrsa -rand /shared/exampleCA/.rand -out /shared/tmp/exampleCA/client1.key 2048

  2. To create a client certificate signing request (CSR), use the following command syntax:

    openssl req -new -out <Directory-Path>/<Client-CSR-Filename> -key <Directory-Path>/<Client-Certificate-Key-Filename>

    For example, to create a client CSR client1.req using the client certificate key client1.key, type the following command:

    openssl req -new -out /shared/tmp/exampleCA/client1.req -key /shared/tmp/exampleCA/client1.key

  3. To create and sign the client certificate, use the following command syntax:

    openssl x509 -req -in <Directory-Path>/<Client-Certificate-Request-Filename> -out <Directory-Path>/<Client-Certificate-Filename> -CAkey <Directory-Path>/<CA-Key-Filename> -CA <Directory-Path>/<CA-Cert-Filename> -days <Number-of-Days> -CAcreateserial -CAserial serial

    For example, to create the client certificate client1.crt that is valid for 365 days by using the client certificate request client1.req, and signing it with the CA key clientCA.key and CA cert clientCA.crt, type the following command:

    openssl x509 -req -in /shared/tmp/exampleCA/client1.req -out /shared/tmp/exampleCA/client1.crt -CAkey /shared/tmp/exampleCA/clientCA.key -CA /shared/tmp/exampleCA/clientCA.crt -days 365 -CAcreateserial -CAserial serial

Creating a client PKCS12 certificate

You must convert the client certificate and key to the PKCS12 format before the certificate and key get imported into a client desktop's browser. To perform this conversion, complete the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To create the pkcs12 certificate for the client browser, use the following syntax:

    openssl pkcs12 -export -in <Directory-Path>/<Client-Certificate-Request-Filename> -inkey <Directory-Path>/<Client-Key-Request-Filename> -out <Directory-Path>/<Client-Certificate-PKCS12-Output-Filename> -name "PKCS12-name"

    For example:

    openssl pkcs12 -export -in /shared/tmp/exampleCA/client1.crt -inkey /shared/tmp/exampleCA/client1.key -out /shared/tmp/exampleCA/client1.p12 -name "client1 pkcs12"

    After entering the PKCS12 client certificate password, the system creates the following file:

    /shared/tmp/exampleCA/client1.p12

Configuring the BIG-IP http server for two-way authentication

To install certifications into the BIG-IP httpd configuration, perform the following procedure:

Impact of procedure: Restarting the httpd process temporarily makes the Configuration utility unavailable.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To install the newly created certificate on the BIG-IP system, and name it server_ca, use the following command syntax:

    create sys file apache-ssl-cert <server_cert> source-path file:<Directory-Path>/<Certificate>

    For example:

    create sys file apache-ssl-cert server_ca source-path file:/shared/tmp/exampleCA/clientCA.crt

  3. To modify Apache to request the client certificate and use the CA file, type the following commands:

    modify sys httpd ssl-verify-client require
    modify sys httpd ssl-ca-cert-file /Common/server_ca

    Note: The CA file name requires the full path, including partition; in this example, it is /Common.

  4. Save the configuration by typing the following command:

    save sys config

  5. To restart Apache, type the following command:

    restart sys service httpd

  6. Import the client1.p12 file into your client browser and test it by connecting to the Configuration utility. The Configuration utility should now prompt for the client certificate.

    Note: Based on your particular browser security settings when accessing BIG-IP using the newly created certificate, the browser may display an error message. The browser may generate an error due to the site certificate created references a non-public CA. The browser has no built-in reference to the signing CA of the certificate. This is an expected browser security behavior.
