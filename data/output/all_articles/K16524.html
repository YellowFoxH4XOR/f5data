Known Issue

The Portal Access rewrite profile may incorrectly format rewritten cookie content.

This issue occurs when all of the following conditions are met:

  • Your access profile configuration includes a Portal Access rewrite profile.
  • The rewrite profile is configured to rewrite the path stated in a cookie.
  • The original cookie places the path attribute after the expires attribute.

Impact

Rewritten cookie content is not formatted correctly.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing the original and rewritten cookie contents, you notice that the rewritten path is placed within the expires attribute of the cookie.

    For example, an original cookie may appear similar to the following:

    Set-Cookie: c1=value1; Domain=exampledomain.com; Path=/; Expires=Thu, 15-Apr-2015 19:09:10 GMT; Secure
    Set-Cookie: c2=value2; Domain=exampledomain2.com; Expires=Thu, 15-Apr-2015 19:09:10 GMT; Path=/; Secure

    In this example, the rewritten cookie may appear similar to the following:

    Set-Cookie: c1=value1; Domain=exampledomain.com; Path=/rewritten/; Expires=Thu, 15-Apr-2015 19:09:10 GMT; Secure
    Set-Cookie: c2=value2; Domain=exampledomain2.com; Expires=Thu,; path=/rewritten/ 15-Apr-2015 19:09:10 GMT; Path=/; Secure
  • Application interaction and/or content does not function as expected.

Resolution

Status

F5 Product Development has assigned ID 518283 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, you can alter the format of the original cookie to place the path attribute before the expires attribute.
