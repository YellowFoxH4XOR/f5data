Topic

This article covers how to discover multiple BIG-IP devices. For information about discovering a single BIG-IP device refer to the following article:

  • K63557165: Discovering a BIG-IP device with a BIG-IQ system and importing the BIG-IP service configuration

You should consider using this procedure under the following condition:

  • You want to discover multiple BIG-IP devices with your BIG-IQ system and import the BIG-IP service configuration(s).

Description

To manage a BIG-IP device from a BIG-IQ system, you must first discover the BIG-IP device and then select the BIG-IP device service configuration(s) you want the BIG-IQ system to manage. Beginning in BIG-IQ 6.1.0, you can discover multiple devices in a one batch discovery operation.

If you want to discover multiple devices by using a custom CSV, refer to the Device Discovery and Basic Device Management chapter of the Managing BIG-IP Devices from BIG-IQ manual.

Note: You cannot use the CSV file generated by the Export Inventory feature to discover multiple devices. For more information about the format and device details required for discovering multiple devices using a CSV file, review the previously mentioned manual chapter or perform the following steps:

  1. Go to Devices > BIG-IP DEVICES.
  2. Select Add Device(s).
  3. Select Add multiple BIG-IP devices.
  4. Select View CSV Details.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to BIG-IQ.
  • You have administrative access to the BIG-IP system.
  • You know the management IP or self IP address of the BIG-IP devices you want to discover

Procedures

Discovering multiple BIG-IP devices with your BIG-IQ system and importing the BIG-IP service configurations

For the devices your system discovers, use the following procedure to choose what services to import, how to resolve configuration conflicts, and how to configure cluster properties for devices in a device services cluster (DSC) group.

Important: You cannot add multiple BIG-IP devices with SSL Orchestrator services. These BIG-IP devices must be added individually. For devices with BIG-IP ASM services, you can only add five devices at a time.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ user interface.
  2. Go to Devices > BIG-IP DEVICES.
  3. Under BIG-IP Devices, ensure that All BIG-IP Devices is selected, and select Add Device(s).
  4. Select Add multiple BIG-IP devices.
  5. For Snapshot, leave the check box selected to create a BIG-IQ snapshot, or clear the check box to skip this step.

    Note: Clear this check box if you are adding devices that are in an access group you just created. If you don't, BIG-IQ won't be able to add the device(s).

  6. For Conflict Resolution section, leave the check box selected if you want to review and resolve conflicts from the Services page for the BIG-IP after you finish adding it. Clear the check box if you want BIG-IQ to resolve conflicts for you based on the settings in Conflict Resolution Policies, which you configure in a later step.
  7. Select Add Devices.
  8. For IP Address, enter the management IP address or self IP address of the BIG-IP device you want to add. The address you choose depends on the network that the BIG-IQ discovery address belongs to.
  9. Select + to add another device that has the same settings for username, password, port, service configuration, statistics collection, and cluster properties.

    Note: You can change the password later after adding the device to the Devices list.

  10. Enter an administrative username and password for the BIG-IP device.
  11. For Port, leave the default value of 443 unless you have configured your BIG-IP device to be managed on a different port.
  12. For Services, choose the device service configuration(s). For example, select the check box for Web Application Security (ASM) if the BIG-IP device has a BIG-IP ASM module enabled and you want BIG-IQ to manage this module.
  13. If the Conflict Resolution Policies section does not appear, you can skip this step. For Shared Object Conflict Policy, Version Object Conflict Policy, and Device Specific Conflict Policy, choose a method appropriate for your environment. For a description of the conflict resolution options, select the Help icon (?) or refer to step 17 in K63557165: Discovering a BIG-IP device with a BIG-IQ system and importing the BIG-IP service configuration.
  14. For Status, select the check box to enable statistics collection otherwise leave it cleared.
  15. For Zone, select a statistics collection zone, if applicable.
  16. For Cluster Display Name, select one of the following options:
    • None if the BIG-IP device is not a member of any existing DSC group and you do not want to create a new device service clustering (DSC) group for the BIG-IP device.
    • Create New if you want to create a new cluster to represent the DSC group the BIG-IP device belongs to. The BIG-IQ user interface displays a box for you to enter the cluster display name, which must be the same for each member in a DSC group for BIG-IQ to properly associate devices in the same DSC group.
    • Use Existing if the BIG-IP device belongs to an existing DSC group. The BIG-IQ user interface displays a list from which you can select the DSC group.
  17. If you choose a setting other than None for Cluster Display Name, Deployment Settings is revealed. Use the default recommended settings.
  18. Select Save & Close. The BIG-IP devices appears in the Devices list.
  19. (Optional) You can now change the password BIG-IQ uses to access BIG-IP device if necessary by selecting the check box next to the device and selecting Set Password.
  20. Repeat steps 8 through 19 to add more devices for BIG-IQ to discover in this batch discovery operation or select Discover & Import.
  21. Read the message in the dialog box that appears then select Close. The devices appear in the device inventory as BIG-IQ establishes trust and completes the discovery process.

Reviewing and resolving configuration conflicts individually

If you selected the check box for Do not import a service if it contains a shared object conflict between this BIG-IP device and BIG-IQ, you need to review and choose how to resolve any configuration object conflicts between the BIG-IQs working configuration and the current configuration on the BIG-IP before importing it.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ user interface.
  2. Go to Devices > BIG-IP DEVICES.
  3. Locate any Import error for service messages in the Services column and select the message. This takes you to the SERVICES page for the device.
  4. Locate any Conflicts found, import halted messages and select Import for that service.
  5. If an out-of-date warning appears, you can either select Re-discover to re-discover the service or select Proceed to Import if you know nothing on the BIG-IP configuration has changed since the service was discovered.
  6. If there are any configuration conflicts, in Resolve Import Conflicts, the BIG-IQ user interface displays a list of configuration objects for which you can select the conflict resolution methods. Choose a method appropriate for your environment. For a description of the conflict resolution options, select the Help icon (?) or refer to the following list:
    • Select Use BIG-IQ to keep the object in BIG-IQ's working configuration. If you select this method for a shared object, the next time BIG-IQ deploys a configuration to that BIG-IP device, it updates the shared object to match the one on BIG-IQ.

      For example, if an HTTP profile called MyProfile with Insert X-Forwarded-For enabled is in the BIG-IQ working configuration and, on discovery of a service for BIGIP1, BIG-IQ encounters a profile called MyProfile with Insert X-Forwarded-For disabled, BIG-IQ keeps the MyProfile with Insert X-Forwarded-For setting enabled. The next time BIG-IQ deploys a configuration to the BIGIP1 device, it enables the Insert X-Forwarded-For setting of MyProfile.

    • Select Use BIG-IP to use the object from the BIG-IP device's current configuration to replace the object that is different in the BIG-IQ working configuration. If you select this method for a shared object, the next time it deploys a configuration,  BIG-IQ replaces the shared object for all of your managed BIG-IP devices.

      Continuing with the previous example, if you select this option, the object imports into the BIG-IQ working configuration, and, for a shared object, the next time BIG-IQ deploys a configuration to any of the managed devices that contain MyProfile, it disables the Insert X-Forwarded-For setting if it is not already disabled.

    • Select Create Version if you want BIG-IQ to create and store a copy of the BIG-IP device's BIG-IP LTM monitor or profile object(s) specific to the software version running on that BIG-IP device. If you select this method, the next time it deploys a configuration, BIG-IQ replaces that object for all the managed BIG-IP devices running that version. You can store multiple versions of BIG-IP LTM monitors or profiles. BIG-IQ deploys the appropriate stored version to your managed devices. The next time it imports services that contain BIG-IP LTM monitors or profiles, BIG-IQ automatically resolves conflicts against the appropriate version.

      For example, the values of properties or the properties themselves of profiles and monitors differ between BIG-IP versions.

  7. If necessary, select Device Specific Objects and repeat the previous step.
  8. Select Continue.
  9. Review the conflict resolution definitions and select Resolve to import the BIG-IP configuration.
  10. Repeat the procedure for each device with the Import error for service message.
