Description

When you look at show ip bgp neighbor x.x.x.x received routes, you find extra routes received that are not being installed in routing table.

Environment

  • BIG-IP LTM used to connect to one or more BGP neighbors

Cause

This is an expected behavior of BGP, when BGP receives a route from neigbhor, it has to do some validation testing on each received route, in addition BGP will look at any inbound route-maps that filter the routes from being installed.

For example if BGP doesn't have a subnet or direct connectivity to reach the route advertised from neigbhors, then it will not accept it in routing table to avoid dropping legitimate traffic.

Recommended Actions

  • When comparing received-routes with actual installed routes, we should look at route-maps and any filtering being applied on that neighbor, in addition basic routing reachability needs to be checked.
