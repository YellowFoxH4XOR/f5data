Type

Published
2024-01-30

Description

Velos System Controller's /var/log/openshift.log logs following message every 40 seconds

Detected DRBD split-brain - attempting recovery

Also, the similar to following log can be in /var/log/message log, repeatedly:

kernel: block drbd0: uuid_compare()=-1000 by rule 100
kernel: block drbd0: Unrelated data, aborting!
kernel: drbd etcdbackup: conn( WFReportParams -> Disconnecting ) 
kernel: drbd etcdbackup: error receiving ReportState, e: -5 l: 0!
kernel: drbd etcdbackup: ack_receiver terminated
kernel: drbd etcdbackup: Terminating drbd_a_etcdback
kernel: drbd etcdbackup: Connection closed
kernel: drbd etcdbackup: conn( Disconnecting -> StandAlone ) 
 

Environment

  • F5OS-C
  • Velos
  • System Controller
 

Cause

  • Bug ID 1496893
     

Recommended Actions

1. Log in to CLI of floating IP as root.
2. On the Active system controller, pause orchestration manager by running:

touch /tmp/omd/pause

And then wait ~60 seconds, or until you see "Pausing all processing due to /tmp/omd/pause existing" in /var/log/openshift.log

3. SSH to Standby system controller (ssh controller-x), run the following (one line):

drbdadm down etcdbackup && drbdadm wipe-md etcdbackup && drbdadm create-md etcdbackup && drbdadm up etcdbackup && drbdadm disconnect etcdbackup && drbdadm connect etcdbackup

This will prompt twice for confirmation. Enter 'yes' each time and press [Enter].

Do you really want to wipe out the DRBD meta data?
[need to type 'yes' to confirm] yes
 

Wiping meta data...
DRBD meta data block successfully wiped out.
md_offset 5368705024
al_offset 5368672256
bm_offset 5368508416


Found ext3 filesystem
5242684 kB data area apparently used
5242684 kB left usable by current configuration
 

Even though it looks like this would place the new meta data into
unused space, you still need to confirm, as this is only a guess.

Do you want to proceed?
[need to type 'yes' to confirm] yes
 

initializing activity log
initializing bitmap (160 KB) to all zero
Writing meta data...
New drbd meta data block successfully created.
success

NOTE: if it fails, then follow the procedure in Additional Information.


4. On the Active system controller, run the following:

drbdadm connect etcdbackup
NOTE: Ignore the error output if it produces this error:
etcdbackup: Failure: (102) Local address(port) already in use.


5. On one controller or the other, monitor the status running the following:

cat /proc/drbd
and ensure that it shows that a sync is occurring/progressing.
It should finish resyncing in less than a minute (but as long as it's actually making progress, keep waiting)

version: 8.4.11-1 (api:1/proto:86-101)

        finish: 0:00:07 speed: 190,624 (190,624) K/sec

Once it is completed, it should looks like

 NOTE: If this run on Standby unit, ro is Secondary/Primary
 

6. On the Active system controller, run the following

rm /tmp/omd/pause

 

Additional Information

If you see failure in step 3 above. you may see similar to below message:

Device 'X' is configured!
Command 'drbdmeta X v08 /dev/mapper/xxx internal wipe-md' terminated with exit code 20

In this case, you will need to bring down the device profile by running the following command, replacing 'X' with whichever number appears in the above error:

drbdadm down minor-<X>

After running above, then run

drbdadm create-md etcdbackup && drbdadm up etcdbackup && drbdadm disconnect etcdbackup

And back to step 4.
