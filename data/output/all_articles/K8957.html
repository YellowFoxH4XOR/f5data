K8957: The LB_SELECTED iRule may erroneously fire if it receives an HTTP connection but the client does not send a request

Known Issue

This is the result of a known issue. The LB_SELECTED iRule option may erroneously fire when an HTTP connection is established, but the client never sends a request and terminates the connection.

This behavior establishes a server-side connection, even though the client-side connection has been terminated. As a result, the server-side connection is not used, consumes system resources, and is not closed down until the connection idle timer expires.

F5 Networks Product Development tracked this issue as CR99246 and it was fixed in BIG-IP LTM version 9.4.6.  For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.3-HF4 issued for BIG-IP version 9.4.3, in Hotfix-BIG-IP-9.4.4-HF3 issued for BIG-IP version 9.4.4, and in Hotfix-BIG-IP-9.4.5-HF2 issued for BIG-IP version 9.4.5. You may download these hotfixes or later versions of the hotfixes from the F5 Networks Downloads site.
