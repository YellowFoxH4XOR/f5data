K12765533: GUI / CLI is not accessible due to high disk usage in the ''/var/named/lib'' directory

Type
Support Solution
Published
2022-08-19
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 15.1.6
Source
https://my.f5.com/manage/s/article/K12765533

Description

F5 BIG-IQ system shows the below Alert about the vCMP Guest:

Device Disk Usage Alert '/var/named/lib' filesystem on Hostname: <big-ip-hostname> usage has exceeded threshold value of 95.0 percent: 100%

  • The GUI and/or CLI of vCMP Guest is not accessible.
  • The Management IP Address of vCMP Guest is reachable via 'Ping' command. But, using 'Telnet' command to have SSH (TCP/22) and/or Web User Interface (TCP/443) connections is not successful.
  • F5 BIG-IQ system shows the "100% Disk Usage" Alert for one or all of the following directories: "/var/", "/var/dnscached/lib/", and "/var/named/lib/".

Environment

Check if any of the following conditions match:
  • vCMP Guest
  • The vCMP Guest status on F5 BIG-IQ is Unavailable (RED)
  • The vCMP Guest status on its vCMP Host is Available (GREEN)

Cause

In most cases, the problem is related to the disk usage in different sub-directories of "/var/" (e.g., the "UCS" Archive files), and it is not just about the "/var/named/lib" directory. So, you may need to remove all the larger and unused files from all the sub-directories in "/var/" directory, or even move them from your device to another storage as backup.

Recommended Actions

To work around or avoid this issue you may need to follow the below steps.

  • Try to connect to the vCMP Guest via its vCMP Host: In this regard, you need to connect to the vCMP Host which contains the vCMP Guest, by using SSH session, and then use the "vConsole" command as syntax below to have Internal Console from its Host to the Guest (K15372).
# vconsole <guest_name>
 
  • If the "vconsole" command works fine, try to check the disk usage status: Now, you are able to issue the below command to analyze the disk utilization and find the 20 largest files in "/var/" directory.
    Note: running this command may take a bit longer than normal commands.
# find /var/ -xdev -type f -exec du {} \; | sort -rn | head -20
 
  • Remove all the UCS files: Now, you can make decision about removing all the largest files, to solve the issue, by using the below command.
    Note: Please take a local backup of the UCS files.
# rm /var/local/ucs/<file_name.ucs>
 
  • Then, you can check your logs and monitoring tools to investigate if there is any further warnings about disk usage. 
     
  • If you face any other problem, you can reach out to F5 Technical Support.

Additional Information

This problem may occur on Non-vCMP platforms (like Virtual Editions), as well. So, you can still use all the recommended actions in this article, except the first step which is specific just on vCMP-based platforms, at Host-level.
