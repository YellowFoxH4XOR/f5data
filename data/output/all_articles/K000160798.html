Description

Qualys vulnerability scan detects SHA1 usage in SSH on BIG-IP LTM, even after updating SSH ciphers, MACs, and KexAlgorithms. The scan reports SHA1 because the ssh-rsa host key algorithm, which uses SHA1, is still offered by the SSH daemon. This can be resolved by removing ssh-rsa from the SSH host key algorithms.

Environment

  • Product: BIG-IP LTM
  • SSH daemon (sshd) with custom ciphers, MACs, and KexAlgorithms configured

Cause

The SSH daemon continues to offer the ssh-rsa host key algorithm, which uses SHA1, because the HostKeyAlgorithms directive was not explicitly set in the SSH configuration. Updating only ciphers, MACs, and KexAlgorithms does not remove ssh-rsa, resulting in continued SHA1 detection.

Answer/Recommended Actions

To remediate SHA1 usage detected by vulnerability scanners:

  1. Edit the SSH configuration to include the HostKeyAlgorithms directive:
    tmsh modify sys sshd include "Ciphers 3des-cbc,aes128-cbc,aes192-cbc,aes256-cbc,aes128-ctr MACs hmac-sha2-256,hmac-sha2-512 KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384 HostKeyAlgorithms ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521"
    - Adjust the list as needed for your environment and supported keys.
  2. Save the configuration:
    tmsh save sys config
  3. Restart the SSH daemon:
    bigstart restart sshd
  4. Re-run your vulnerability scan to confirm that SHA1 is no longer detected.

Additional Information

  • Updating only ciphers, MACs, and KexAlgorithms does not remove the ssh-rsa host key algorithm.
  • The ssh-rsa algorithm uses SHA1 and is offered by default unless explicitly removed.
  • Some vulnerability scanners may report based on SSH daemon version rather than actual algorithm usage; verify findings with scanner output.
