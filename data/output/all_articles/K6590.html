Topic

This article applies to BIG-IP ASM 9.x through 10.x. For information about other versions, refer to the following article:

  • K15416: Overview of the BIG-IP ASM watchdog process (11.x)

BIG-IP ASM 9.4.0 through 10.x

In BIG-IP ASM 9.4.0 through 10.x, the nwd.pl watchdog process monitors critical BIG-IP ASM daemons, and attempts to restart the daemons if they fail. The nwd watchdog process is responsible for monitoring one or more BIG-IP ASM daemons, as follows:

  • attack_manager.pl
  • log_manager
  • crawler_manager.pl
  • learning_manager.pl
  • clean_db.pl
  • bd
  • bd_agent
  • asmcsd (BIG-IP 10.x)
  • mysqld (BIG-IP 10.x)

Note: For more information about ASM daemons, refer to K10227: BIG-IP ASM daemons (9.x - 10.x).

The nwd daemon reports daemons that fail to restart to the recovery_mngr.pl process.

BIG-IP ASM 9.2.0 through 9.3.1

In BIG-IP ASM 9.2.0 through 9.3.1, the following watchdog processes monitor critical BIG-IP ASM daemons, and attempts to restart the daemons if they fail:

  • nwd_ts
  • nwd_dms
  • nwd_core

Each watchdog process is responsible for monitoring one or more BIG-IP ASM daemons, as follows:

  • The nwd_ts watchdog daemon monitors the following daemon:
    • log_manager daemon
  • The nwd_dms watchdog daemon monitors the following daemons:
    • crawler_manager
    • learning_manager
    • lclean_db
    • lattack_manager
  • The nwd_core watchdog daemon monitors the following daemons:
    • lbd
    • lbd_agent

Daemon failures are reported to the recovery_mngr daemon and logged to /var/log/asm file in the following syntax:

ASM Process failure: Watchdog detected failure for process. Process name: <process_name>, Failure: Insufficient number of threads (required: 1, found: 0)
