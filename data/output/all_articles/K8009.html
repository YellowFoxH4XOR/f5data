Topic

The tm.continuematching database variable affects how the BIG-IP system processes traffic when a higher precedence virtual server is disabled and a lower precedence virtual server is available.

Description

By default, the tm.continuematching database variable is set to false, and the BIG-IP system does not allow a lower precedence virtual server to handle a request when a higher precedence virtual server is disabled. The BIG-IP system rejects the packet and, if the tm.rstcause.log database key is set to enable, it logs information similar to the following example in the /var/log/ltm file:

01230140:3: RST sent from 10.10.10.100:80 to 192.168.10.100:60044, [0x2274167:2046] VIP disabled (administrative)

When the tm.continuematching database variable is set to true, the BIG-IP system checks if another virtual server is available to handle a request if the higher precedence virtual server is disabled.

In the following example, the port-specific virtual server is disabled, which allows the BIG-IP system to use the wildcard virtual server 10.10.1.10:* to handle a client request to 10.10.1.10:80:

tm.continuematching = true

Virtual Server: 10.10.1.10:80
Status: Disabled

Virtual Server: 10.10.1.10:*
Status: Up and Available

Recommendations

When configuring virtual servers that may overlap in IP addresses and/or ports, you should consider the following factors:

  • If you do not want another matching virtual server to handle an incoming request that is destined for a disabled virtual server, you must set the tm.continuematching database variable to false.
  • If you want another matching virtual server to process an incoming request that is destined for a disabled virtual server, you must set the tm.continuematching database variable to true.

You can change this behavior by modifying the tm.continuematching database variable. To do so, perform the following procedure:

Impact of procedure: Changing this setting may produce unintended traffic patterns. Testing should be performed during a maintenance window.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

    Note: If you are currently logged in to tmsh, you can skip this step.

  2. To modify the tm.continuematching database variable to either true or false, type the following command:

    modify /sys db tm.continuematching value <true|false>

  3. Save the change by typing the following command:

    save /sys config
