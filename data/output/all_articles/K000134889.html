Description

vCMP guests are operating only on one slot while the second slot remains in an offline state.

The following log messages can be seen in the /var/log/ltm:

err diskmonitor[18789]: 011d0004:3: Disk partition /shared/vmdisks (slot 3) has only 0% <--

err diskmonitor[13892]: 011d0004:3: Disk partition /shared/vmdisks (slot 1) has only 13% free
 

Output from "df-h" shows:

Filesystem Size Used Avail Use% Mounted on

/dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks 230G 219G 0 100% /shared/vmdisks

Environment

  • vCMP
  • vmdisks

Cause

When deployed, a guest is assigned 100Gb of space in the host virtual disk. However, it should be taken into account that the virtual disk is created as a sparse file (which means that the file size is not the same that the disk space it occupies, this is because the null bytes are not saved to the disk therefore, the virtual disk takes much less than 100 G). It is important to understand that a sparse file works as a high watermark.

Over time the guest's virtual disk size can grow. Any time the guest writes new data to the disk, it converts unallocated space into allocated space.

When data is deleted from the guest, there is not any automatic procedure to recover sparseness.

Recommended Actions

There are two possible methods/options to address this scenario.

  • Option 1: Remove unwanted/unused guests and their virtual disks to release the space.
  • Option 2: Delete the virtual disk for a guest, redeploy, then restore the config from a UCS backup.

For option 2 refer to K000140235: How to shrink vdisk for vCMP Guest to reclaim host disk space.
