K000159976: OTP via Email Stopped working For Access Profile after changing from ldap to ldaps authentication

2026-02-11
Applies to

Description

After changing the authentication method in BIG-IP APM Access Policy from LDAP (Active Directory) to LDAPS, OTP delivery via email failed for all users. The system continued to prompt for OTP, but no emails were sent.

 

Environment

  • BIG-IP APM
  • Authentication method changed from LDAP (port 389) to LDAPS (port 636) for one AAA server
  • Email OTP delivery configured via APM Access Policy

 

Cause

Switching the AAA server type in the Access Policy from AD/LDAP to LDAPS changes the session variable used to retrieve user attributes such as email address. For AD/LDAP AAA servers, the variable is 'session.ad.last.attr.mail'. For LDAPS AAA servers, it is 'session.ldap.last.attr.mail'. If the Email Agent is not updated to use the correct variable, it cannot find the user's email address, resulting in failed OTP delivery.

 

 

Answer/Recommended Actions

  1. Identify the AAA server type used in your Access Policy (AD/LDAP or LDAPS).
  2. In the Visual Policy Editor (VPE), locate the Email Agent responsible for OTP delivery.
  3. Update the 'To' field in the Email Agent:
  4. - For AD/LDAP AAA servers, use: %{session.ad.last.attr.mail}
  5. - For LDAPS AAA servers, use: %{session.ldap.last.attr.mail}
  6. Save and apply the updated Access Policy.
  7. Test the policy by authenticating a user and verifying that the correct session variable is populated and the OTP email is sent.
  8. Use sessiondump or the Active Sessions report to confirm the session variable is set as expected for the test session.

 

Additional Information

  • Updating the Email Agent 'To' field to the correct session variable resolves the issue for the updated AAA server type.
  • If supporting multiple domains or AAA server types, consider policy branching or variable assignment to ensure the correct variable is used for each scenario.
  • Test changes in a maintenance window to avoid impacting other users or domains.
