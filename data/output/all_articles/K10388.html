Topic

The BIG-IP LTM system supports the ability to use self IP addresses with virtual servers and network address translations (NATs). This ability allows an administrator to maximize the use of all available addresses, which is useful in situations when a limited number of public addresses are available.

When using a self IP with a virtual server and NAT, the order of precedence is the following:

  • Virtual server
  • NAT
  • Self IP

The virtual server follows the order of precedence in K14800: Order of precedence for virtual server matching (11.3.0 and later). The system will match traffic based on address and port.

Important: Do not use a self IP-based virtual server with a wildcard port and FastL4 profile specified. This combination will cause the system to bypass a NAT using the same self IP address. To avoid a NAT bypass, use a virtual server with a 0.0.0.0:0 configuration.

Note: For more information about other objects and their order of precedence, refer to the following articles:

  • K8849: Configuring a virtual server to use the same IP address as a self IP (9.x - 10.x)
  • K13896: Configuring a virtual server to use the same IP address as a self IP (11.x - 13.x)
  • K9038: The order of precedence for local traffic object listeners
  • K9039: A virtual server with a SNAT pool takes precedence over matching the NAT

Note: If the BIG-IP system is a member of a redundant pair, and you are configuring self IP addresses as virtual servers or NATs, ensure that the self IP addresses are floating self IP addresses.
