Description

Are Network Access compression and Connectivity Profile compression related?

Important: Beginning in APM Clients 7.2.6, BIG-IP network access VPN compression (client and server side) is deprecated. For more information, refer to K000158915: BIG-IP network access VPN compression deprecated from APM Client 7.2.6.

Environment

  • BIG-IP APM that has Compression enabled either in the Network Access resource or in the Connectivity Profile (or both)

Cause

None

Recommended Actions

These are 2 different settings:

Network Access compression setting defines if compression is going to be applied to the tunnel traffic
(Access > Connectivity / VPN > Network Access > Network Settings > General Settings > Compression > GZIP Compression).

Connectivity Profile compression setting determines what level of compression is used when a Network Access resource uses compression.
(Access > Connectivity / VPN > Connectivity > Profiles > Compression Settings > Network Access > gzip Compression Level).

If compression is enabled in the NA resource; but disabled in the connectivity profile then the expected behavior is: there is no compression applied but the traffic still flows through the GZIP filter.

This is why if you look at the "Network Access Throughput" graph in the BIG-IP Dashboard, you'll see there are 2 separate categories: From Client and To Client
