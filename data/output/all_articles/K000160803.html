K000160803: HTTP traffic fails with "Cannot Resolve Hostname" error after BIG-IP SSL Orchestrator upgrade to 17.1.3.1

Type
Support Solution
Published
2026-04-15
Updated
2026-04-15
Applies to
  • BIG-IP
  • BIG-IP SSL Orchestrator: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160803

Description

After upgrading BIG-IP to v17.1.3.1, HTTP traffic through the BIG-IP SSL Orchestrator explicit proxy topology fails with the error: Cannot resolve hostname '<hostname>' in explicit-proxy request. HTTPS (CONNECT) traffic continues to function normally.

Environment

  • BIG-IP SSL Orchestrator module, version 17.1.3.1
  • SSLO explicit proxy topology with DNS Resolver profile

Cause

The root cause is the presence of the deprecated RESOLV::lookup command in the SSLO explicit proxy topology's iRule after upgrading to v17.1.3.1. The upgrade process does not automatically update the iRule, and in v17.1+, the RESOLV::lookup command fails for plain HTTP (non-CONNECT) requests, resulting in DNS resolution errors for HTTP traffic. Redeploying the topology regenerates the iRule without the deprecated command, restoring correct DNS resolution.

Answer/Recommended Actions

  1. Take a UCS backup of the device before making any changes.
  2. In the SSLO GUI, make a minor or cosmetic change (such as modifying the description field) to the affected SSLO explicit proxy topology.
  3. Redeploy the topology to regenerate the iRule.
  4. Verify that the RESOLV::lookup command is no longer present in the regenerated iRule.
  5. Test HTTP traffic through the original topology to confirm resolution.
  6. Remove any temporary workarounds (if any) and restore the intended traffic path.
