Description

macOS Edge Client connecting to a non-standard HTTPS port (e.g., 843) may fail to establish VPN tunnel properly.

Environment

  • Two virtual servers running on same IP but different ports (standard port 443 and another on non-standard port like 843) with two different access policies.
  • macOS Edge Client accessing the virtual server on non-standard port.

Cause

F5 Product Development has assigned ID1377793 to this issue.

Recommended Actions

To identify the issue, check client-side logs and APM-side logs

On Client-side logs (~/Library/Logs/F5Networks/edge.log), below kind of logs will be observed:

2023-10-05,16:23:31:818, 8706,22371284,edge, 48, /SessionController.mm, 410, SessionController, DoTokenSuccesfull serverAddress, https://apm-fqdn.com:843/
2023-10-05,16:23:31:818, 8706,22371284,edge, 48, /SessionController.mm, 418, SessionController, DoTokenSuccesfull serverAddress after redirect, https://apm-fqdn.com:843/my.policy

[ ... initially client is connecting to: apm-fqdn.com:843 ... ]

2023-10-05,16:23:50:702, 8706,22371284,edge, 48, /DoRequest.mm, 66, DoRequest, DoRequest, request, https://apm-fqdn.com/vdesk/timeoutagent-i.php?438513766

[ ... later timeoutagent-i.php is going to standard virtual server (at standard port 443) ... ]

On APM-side logs (/var/log/apm), below kind of logs will be observed:

Oct  5 16:23:50 local-test.apm notice tmm3[5046]: 01490576:5: /Common/test-ap-na-01:Common:ee6f5254 Session invalidated due to profile scope mismatch (expected '/Common/test-ap-na-01', got '/Common/test-ap-na-02').

Possible Workarounds

  • Use browser instead of Edge Client. OR,
  • Access a virtual server running on standard port (443). OR,
  • Change Profile Scope to "Global".
