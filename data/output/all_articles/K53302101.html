Topic

Path traversal is a common attack against web applications in which the attacker attempts to manipulate a URL or a parameter with the intention of exploiting a path vulnerability and accessing resources that are not intended to be accessed or displayed.

Description

In path traversal attacks, the attacker manipulates a web application component, such as a URL, by including special characters that modify the directory path. For example, the following attack manipulates the URL and uses the '../' characters to alter the location of the request with the intention of displaying the contents of a file that is outside of the document root directory:

http://example/../../../../../etc/passwd

The BIG-IP ASM system can mitigate path traversal attacks by using appropriate attack signatures or defined meta-characters. The following procedures list the steps needed to mitigate path traversal attacks using the attack signatures, as this is the fastest and easiest configuration.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have access to the Configuration utility.

Procedures

  • Adding the path traversal signatures to the security policy
  • Enabling and enforcing the path traversal signatures
  • Switching the policy to Blocking mode
  • Verifying that the system is blocking path traversal attacks

Adding the path traversal signatures to the security policy

Impact of procedure: Adding attack signatures to the security policy can generate false positives. For example, known false positives for path traversal can occur due to the presence of English words such as “select” and “from” in the HTTP request. In these cases, you should remove false positives from the Traffic Learning page by accepting any learning suggestions for disabling the signature.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the upper-right corner, select Advanced.
  4. Under Policy Building Settings, select Attack Signatures.
  5. Under the Attack Signatures table, select Change.
  6. Select the Path Traversal Signatures check box, and then click Change.
  7. Select Save.
  8. Select Apply Policy.

Enabling and enforcing the path traversal signatures

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Under the attack signatures list, clear the Enable Signature Staging check box.
  4. Select Save.
  5. Select Apply Policy.

Switching the policy to Blocking mode

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Under General Settings, for Enforcement Mode, select Blocking.
  4. Select Save.
  5. Select Apply Policy.

Verifying that the system is blocking path traversal attacks

  1. Log in to the Configuration utility.
  2. Go to Security > Event Logs >  Application > Requests.
  3. Select the Open Filter icon.
  4. Select the IP / Username / URL tab.
  5. For Attack Type, select Path Traversal, and then select Apply Filter.

    Requests that contain path traversal attacks should be blocked and listed in the request log.
