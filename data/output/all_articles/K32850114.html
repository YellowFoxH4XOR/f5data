Known Issue

BIG-IP ASM cluster synchronization may fail after you modify or delete an object.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system is deployed on a multiple blade chassis device.
  • You have multiple active security policies.
  • You modify any of the following ASM objects in the following manner:
     
    • You modify an ASM-enabled HTTP Class, by disabling the ASM feature.
    • You delete an ASM-enabled HTTP Class.
    • You delete an active security policy.
  • You add a new blade to the chassis.

Impact

Cluster synchronization continually fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system continually logs messages similar to the following example to the /var/log/ltm file:

    warning csyncd[8008]: 013b0005:4: Command failed: cmd=rsync -qaI --timeout=15 rsync://127.3.0.2/csync/var/ts/var/cluster/status/status__slot_2__20130716_204820__48900 /var/ts/var/cluster/status/status__slot_2__20130716_204820__48900, rc=23
    info csyncd[8008]: 013b0005:6: Per-invocation log rate exceeded; throttling.

  • When you view system CPU statistics, you notice that utilization is high compared to the normal utilization.

Workaround

To work around this issue, you can remove the stored cluster synchronization files from all blades to regain synchronization. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected blades as root, and type the following command:

    rm -rf /var/ts/var/cluster/send/*
