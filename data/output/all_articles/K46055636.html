Description
You may not be able to access the Configuration Utility (GUI) if you have recently updated the Device Certificate and Key.  SSH will still be accessible and you can check the httpd logs for any error messages.  The following error messages indicate that the Device Certificate and Key pair does not match.

Logs: /var/log/httpd/httpd_errors:

emerg httpd[16444]: [ssl:emerg] [pid 16444] AH02238: Unable to configure RSA server private key
emerg httpd[16444]: [ssl:emerg] [pid 16444] SSL Library Error: error:0B080074:x509 certificate routines:X509_check_private_key:key values mismatch

Environment

  • BIG-IP
  • GUI not loading
  • SSH is still working
  • Device certificate/key has been updated

Cause
Device Certificate and Key pair are invalid
 

Recommended Actions

1. Installing the correct Device Certificate and key pair will allow you to regain access to the GUI.
2. First we verify if the server.crt and server.key files md5sum output results are matching.

/config/httpd/conf/ssl.crt/server.crt
/config/httpd/conf/ssl.key/server.key


3. Verify that the certificate and key are matching pairs by comparing the md5sum output (they should be the same):

# openssl x509 -in /config/httpd/conf/ssl.crt/server.crt -pubkey -noout | md5sum
# openssl rsa -in /config/httpd/conf/ssl.key/server.key -pubout | md5sum


4. If the md5sum output doesn't match, then, please follow the steps below to generate new self-signed device certificate and private key.

# openssl req -x509 -nodes -days <number> -newkey rsa:<keysize> -sha256 -keyout /config/httpd/conf/ssl.key/server.key -out /config/httpd/conf/ssl.crt/server.crt


5. Enter the certificate attributes such as country, locality, common name, etc.

6. Restart the httpd service to allow new device certificate and private key

# bigstart restart httpd

K9114: Creating a new SSL device certificate and key pair
