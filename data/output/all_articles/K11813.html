Known Issue

This is the result of a known issue. The NVRAM battery temperature threshold for the ARX 2000 and 4000 platforms is set too low, and the threshold may be exceeded when the NVRAM battery is charging under normal operating temperatures. When the battery temperature threshold is exceeded, the ARX system stops charging the NVRAM battery.

Note: Over time this issue may shorten the NVRAM battery life by repeatedly interrupting the charge cycle and not allowing the battery to charge completely.

When this issue occurs, the ARX system sends a fault/temperature SNMP trap that appears similar to the following example:

Group:       chassis
Event:       nvram-battery-failure (ID: 419)
Total Events:1

Time(UTC):   2010-04-21T03:17:20.956

Events:
 Message: Nvram battery  :: fault/temperature

Additionally, error messages that appear similar to the following example are logged to the syslog file:

:CHASS-0-ERR-MSG3:: kwaiBatteryMonitor: Bad KWAI battery temperature reading: temp=41 C.
:L2SW_LVL7-0-NOTE-MSG5:: SNMP TRAP: nvramBatteryFail (419) : Nvram battery  :: fault/temperature
:L2SW_LVL7-0-NOTE-MSG5:: SNMP TRAP: nvramBatteryStatus (420) : Nvram battery :: Battery is OK.

F5 Product Development is tracking this issue as ID 39019.

This issue has been fixed in ARX versions 5.1.0 HFRU 8, 5.1.5 HFRU 7, and 5.2.0. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ARX ID 39019.

Note: F5 Product Development is fixing this issue by increasing the battery temperature threshold to a safe value that will not be exceeded under normal operating temperatures, allowing the NVRAM battery to charge completely.
