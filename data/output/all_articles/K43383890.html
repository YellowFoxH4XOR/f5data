Topic

You should consider using this procedure under the following conditions:

  • You notice unusual traffic originating from a specific IP address or from a group of IP addresses from the same geolocation which is causing an impact.
  • You want to block the traffic based on geolocation.

Description

The IP geolocation database includes information to determine the geographic location of a client, such as the origin IP address, country, and country code. Using iRules, you can block access to virtual servers based on the geolocation you specify in a data group. After you determine the geolocation for a given IP address, you can configure a data group with the pertinent geolocation information and reference the data group in an iRule.

Prerequisites

You must meet the following prerequisites to perform this procedure:

  • You have administrative access to the BIG-IP Configuration utility.
  • You have administrative access to the BIG-IP Advanced Shell (bash).

Procedures

  • Viewing the geolocation data of an IP address
  • Creating a data group
  • Creating an iRule to block the traffic

Viewing the geolocation data of an IP address

  1. Log in to the BIG-IP Advanced Shell (bash).
  2. Query the geolocation database for the location of the suspect origin IP address using the following syntax:

    geoip_lookup <IP_address>

    For example, to view the geolocation data of the IP address 24.24.24.24, type the following command:

    geoip_lookup 24.24.24.24

    Output appears similar to the following example:

    Will attempt to lookup ip '24.24.24.24'
    No database specified.
    opening database in /usr/share/GeoIP/v2/F5GeoIP.dat
    size of geoip database = 28148850, segments = 11529593, version = Copyright (c) F5 Networks Inc, All Rights Reserved GEOIP2 v1, 20170918
    geoip_seek = 00e104e0
    geoip record ip = 24.24.24.24
    country_code = US
    country_name = United States
    region_name = New York
    continent_code = NA

Creating a data group

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > iRules > Data Group List.
  3. Click Create.
  4. Enter a name for the data group.
  5. For Type, click String.
  6. For String Records, type the value from the country_code listed in the geolocation data output for the suspect IP address, into the String field (leaving the Value field blank) then click Add.

    For example, the value for country_code in the previous geolocation data output example is US.

  7. Click Finished.

Creating an iRule to block the traffic

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRules List.
  3. Click Create.
  4. Enter a name for the iRule.
  5. For Definition, enter one of the following three code examples, depending on when you want the BIG-IP system to block the incoming traffic:
    • iRule 1 blocks when receiving a TCP SYN packet or UDP/IP packet.
    • iRule 2 blocks after the three-way TCP handshake completes.
    • iRule 3 blocks when receiving an HTTP request.
    • iRule 4 blocks when receiving a DNS request.

    Note: When configuring an iRule using the following examples, be sure to replace example_datagroup with the name of the data group you previously created.

    iRule 1

    when FLOW_INIT {
        set ipaddr [IP::client_addr]
        set fromCountry [whereis $ipaddr country]
        if { [class match $fromCountry equals example_datagroup] } {
             log local0. "Attacker IP [IP::client_addr]"  ;#  This can be removed/commented out if not required
            drop
        }
    }

    iRule 2

     when CLIENT_ACCEPTED {
        set ipaddr [IP::client_addr]
        set fromCountry [whereis $ipaddr country]
        if { [class match $fromCountry equals example_datagroup] } {
             log local0. "Attacker IP [IP::client_addr]"  ;#  This can be removed/commented out if not required
             drop
        }
    }

    iRule 3

    when HTTP_REQUEST {
        if { [HTTP::header exists "X-Forwarded-For"] } {
             set client_ip [HTTP::header value "X-Forwarded-For"]
             set fromCountry [whereis $client_ip country]
             if { ( [class match $fromCountry equals example_datagroup]) }{
                    log local0. "Attacker IP in XFF [HTTP::header X-Forwarded-For]"  ;#  This can be removed/commented out if not required
                     HTTP::respond 403 content "Blocked!"  ;#  This can also be changed to drop or reject based on the requirement
            }
       }
    }

    iRule 4

    when DNS_REQUEST {
        if { [HTTP::header exists "X-Forwarded-For"] } {
             set client_ip [HTTP::header value "X-Forwarded-For"]
             set fromCountry [whereis $client_ip country]
             if { ( [class match $fromCountry equals example_datagroup]) }{
                    log local0. "Attacker IP [IP::client_addr], Attacker Country: $fromCountry, Action: dropped"  ;#  This can be removed/commented out if not required  
                    drop

            }
       }
    }
  6. Navigate to Local Traffic > Virtual Servers.
  7. Click the name of the virtual server to which you want to apply the iRule.
  8. Click the Resources tab.
  9. For iRules, click Manage.
  10. In the Available list, click the iRule you just created and move it to the Enabled list.
  11. Click Finished.
