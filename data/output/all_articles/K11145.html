Known Issue

This is the result of a known issue. Configuring remote syslog server(s) that require DNS resolution on the BIG-IP system may result in a host watchdog reboot loop. This issue occurs when the following configuration elements are in place:

  • DNS resolution is configured on the BIG-IP system
  • Remote syslog servers are defined on the BIG-IP system using hostnames instead of IP addresses
  • The syslog and DNS servers are not on a local network segment, and the BIG-IP system must route the traffic to the destination
  • The BIG-IP system sends a large amount of traffic to the syslog server

For example, if the above configuration elements are in place, and the BIG-IP system is rebooted and is completing boot cycle, client processes will begin sending logging requests to the syslog-ng utility. Before syslog-ng can send the logging requests to the remote servers, it must resolve the DNS names of the syslog servers. If syslog-ng attempts to resolve the hostname before TMM has initialized and before the routes have loaded, client processes, such as bcm56xxd, may terminate with a SIGSEGV. This behavior may result in a host watchdog timeout and subsequent reboots.

F5 Product Development tracked this issue as CR136967, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

To work around this issue, ensure that the syslog server(s) hostname(s) can be quickly resolved. To do this, you can use the bigpipe system remote host command to add the syslog server IP addresses to the /etc/hosts file on the BIG-IP system.

Note: For more information, refer to K8439: Configuring local hostname resolution for BIG-IP versions 9.4.2 and later.
