K000160309: Peer Device IP Needs to Be in HTTPD Allow List to Establish Device Trust

Type
Support Solution
Published
2026-03-12
Updated
2026-06-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 21.1.X, 21.1.0, 21.0.0, 17.1.3, 17.5.1, 21.0.X
Source
https://my.f5.com/manage/s/article/K000160309

Description

In previous versions, it was not necessary to include peer device IP addresses in the httpd allow list (if it was not set to allow all) when adding BIG-IP devices to a Device Trust group for high availability (HA)

Starting in v17.5.1.4 and v17.1.3.1, BIG-IP now checks if the peer device IP address is present (when not set to allow all) in the httpd allow list before establishing device trust. If the IP address is not included, device trust setup fails with the following error:

[xmlHelpers.cpp:90 getXPathValue] expected 1 node for //faultstring, got 0

Environment

  • BIG-IP v17.5.1.4, v17.1.3.1, v21.0.0 or newer
  • httpd allow list configured for specific IPs (not set to All)
  • Adding new devices to a device trust group

Cause

This is a change of behavior introduced by ID944817. With this fix, the peer device IP address must be allowed in both the httpd and icontrol-soap configurations.

 Recommended Actions

Before proceeding, check if httpd and icontrol-soap are not using the default { All } setting, by verifying with the following commands:

tmsh list sys httpd allow
tmsh list sys icontrol-soap allow

Note: This article is applicable when the icontrol.basic_auth database variable is enabled.

Add the peer device IP address to both the httpd and icontrol-soap allow lists using the following command syntax:

tmsh modify sys httpd allow add { <IP address> }
tmsh modify sys icontrol-soap allow add { <IP address> }

For example:

tmsh modify sys httpd allow add { 1.1.1.* 10.1.1.2 10.1.1.1 }
tmsh modify sys icontrol-soap allow add { 1.1.1* 10.1.1.2 10.1.1.1 }

Save the configuration using the following command:

tmsh save sys config

The httpd service restarts it's child processes automatically to implement the configuration change; however, if necessary, you can manually restart httpd using the following command:

tmsh restart sys service httpd
