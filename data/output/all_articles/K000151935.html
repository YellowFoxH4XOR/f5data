Topic

You can use the following utilities to display information about BIG-IP memory allocation:

  • Command-line utilities:
    • tmsh show sys memory
    • tmctl command
      • memory_usage_stat table
      • page_stats table
      • umem
      • Other examples

The headings used to describe BIG-IP memory allocation are defined in the following section.

tmctl command

You can use the tmctl command to display TMM memory usage using the following command syntax:
Note: F5 Support uses tmctl commands and may request you to run them to troubleshoot issues on BIG-IP in advanced troubleshooting. F5 Support does not assist in generating different tmctl commands or provide further information on its use.

tmctl <table name> 

The following sections describe different useful memory tables:

  • memory_usage_stat table
  • page_stats table
  • umem tables
  • Other examples

Note: You can use the following command to list the tables: tmctl -d blade -i -w 200 | awk '!/^\./ {print}'.

memory_usage_stat table

The memory_usage_stat table contains information about BIG-IP memory allocation. tmsh show sys memory draws its statistics from the memory_usage_stat table.

The command output headings are defined in the following table.

The following section describes examples of using tmctl to display information from the memory_usage_stat table:

  • To display specific subsystem object names you want to investigate, use the following command syntax:
    tmctl memory_usage_stat | awk 'NR<=2 || /^(<object1>|object2|objectN>) / {print}' 

    In the following example, the tmctl command displays memory usage for the persist, ssl, and umem objects. For a full list of objects, enter tmsh show sys memory.
    tmctl memory_usage_stat | awk 'NR<=2 || /^(persist|ssl|umem) / {print}'

    name                            allocated max_allocated  size slop cur_allocs
    ------------------------------- --------- ------------- ----- ---- ----------
    persist                                 0             0   160    8          0
    ssl                              24340896      24340896     1    0       2555
    umem                            535684512     889691072     1    0          0
    ...

    allocated = cur_allocs * size

  • To display the top n objects sorted by memory usage, use the following command syntax: 
    tmctl memory_usage_stat -s name,allocated,max_allocated -OK <column to sort by> -L <top n objects> -l

    For example, the following command displays the top 5 objects sorted by allocated memory:
    tmctl memory_usage_stat -s name,allocated,max_allocated -OK allocated -L 5 -l

page_stats table

The page_stats table contains memory information for each TMM instance. A page is 4KB of consecutive memory. To display the pages used and available, enter the following command:
tmctl page_stats -s slot,tmid,pages_used,pages_avail

You may observe an output similar to the following:

  • As pages_used approaches pages_avail, memory pressure increases. Use the following as indication of memory pressure on your system:
    (pages_used / pages_avail) * 100
  • If a single TMM instance uses all of the available pages allocated to the instance, then future pages for that instance will be taken from the next TMM instance that has available pages. For more information, refer to the Additional Information section of K15740: Overview of adaptive connection reaping (11.6.0 and later).

umem

Memory provisioned to TMM is reserved in large blocks of memory. Memory in this pool is locked and not subject to swapping. TMM draws from this pool of memory to construct its heap.

An important part of the TMM memory subsystem and how memory is allocated is umem. Umem is a way to organize memory into 'slabs' of fixed sized chunks that are pre-allocated. A slab is one or more pages of virtually contiguous memory, carved up into equal-size chunks. When TMM requires memory, umem can quickly provide a chunk from an appropriate slab. Allocating memory this way reduces overhead and memory fragmentation especially when frequently allocated objects are of the same size. 

To display umem memory usage, use the following example to query the memory_usage_stat table:
tmctl memory_usage_stat name=umem

name allocated max_allocated size slop cur_allocs tot_allocs fail_allocs type
---- --------- ------------- ---- ---- ---------- ---------- ----------- ----
umem 537569040     889691072    1    0          0          0           0 int:

  • allocated = cur_allocs * size.
  • Refer to the section memory_usage_stat table for column definitions.

It is worth investigating and monitoring further if there are failed allocations (fail_allocs). When this happens, you may observe entries in /var/log/ltm similar to the following:

01010004:3: Memory allocation failed: ssl_session

For more information, refer to K50030452: Error Message: 01010004:3: Memory allocation failed: <tmm memory object>.

Recommendations

When understanding or investigating TMM memory usage on your system, consider the following:

  • Use tmsh commands (e.g. show sys memory, show sys tmm-info) at the first instance, and only use tmctl when you require further details in advanced troubleshooting.

  • When viewing Traffic Management Microkernel (TMM) memory usage, you may notice the amount of memory allocated and the maximum amount allocated are the same for a given subsystem. While this behavior may be normal for the subsystem, if the two amounts increase together over time, it is possible that the usage behavior is a symptom of a TMM memory leak and further investigation is required.

    For example, the following section of output from the tmsh show /sys memory command may indicate the source address translation subsystem exhibiting symptoms of a potential memory leak if the values keep increasing together over time:
    SubSystem               Alloc (bytes) Max Alloc (bytes) Object Size
    source addr translation 7.0G             7.0G                      1
