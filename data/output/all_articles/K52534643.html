Topic

F5 offers several solutions for implementing Federal Information Processing Standards (FIPS). The FIPS BIG-IP Platform Module solution, also referred to as Platform FIPS, is a FIPS 140 validated BIG-IP system.

Platform FIPS requires the F5 Full-Box FIPS add-on license and allows for FIPS 140 validation at level 2 while utilizing the full performance capabilities of the BIG-IP system.

Description

Platform FIPS provides device level FIPS 140-3 and FIPS 140-2 validation at level 2 for specific BIG-IP platforms with the Full-Box FIPS add-on license installed. Introduced in BIG-IP 13.1.0, the Full-Box FIPS license includes a FIPS installation kit that contains tamper-evident stickers that you must apply to the hardware device in order to be FIPS-validated.

BIG-IP systems with the Full-Box FIPS add-on license installed enter FIPS compliant mode during the boot process. When the BIG-IP system enters FIPS mode, the system changes the SSL cipher suites to be FIPS compliant and enables the FIPS required self tests to validate the integrity and operation of the system. If the system fails any of the self tests during the boot process the BIG-IP system halts. For more information about FIPS compliant mode, refer to K91841023: Overview of the FIPS 140 Level 1 Compliant Mode license for BIG-IP VE.

FIPS 140 validated platforms

The Full-Box add-on license can be installed on any BIG-IP hardware platforms running BIG-IP 13.1.0 or later for FIPS compliance, but only specific BIG-IP platforms and versions have been validated for FIPS. For more details about FIPS validated platforms and versions, refer to the security policy and certificates for your platform on the F5 Certifications page.

FIPS 140 validation levels for Platform FIPS

There are four levels of validation for both the FIPS 140-3 and the FIPS 140-2 standard. Platform FIPS systems are FIPS 140-3 and FIPS 140-2 validated at level 2, depending on the presence of an embedded HSM. FIPS self tests

FIPS validation requires the use of self tests to check the integrity and operation of the cryptographic module. If any of these tests fail during the boot process, the BIG-IP system halts. The fips_monitor daemon is introduced in BIG-IP 13.1.0 and monitors the /config/f5_public/fipserr file for any reported errors. If errors are found in the file, the fips_monitor daemon issues the shutdown command to restart the BIG-IP system. On restart, the BIG-IP system scans the /config/f5public/fipserr file, finds the error messages, and halts. The BIG-IP system uses the sys-eicheck utility when performing system integrity checks to detect unexpected changes to the system software, such as modified or missing critical and non-critical files. If the check fails at any time other than the boot process, the BIG-IP system logs the following message to the /var/log/secure file and halt on start up during the next restart:

<datetime> <pid> crit root: BIG-IP Integrity Check: [FAIL] -- Contact F5 Networks technical support.

In addition to that, beginning in BIG-IP 17.1.0, when the sys-eicheck integrity daily cron job fails, then during the next login, the system displays the following message to the user on both the Configuration utility and tmsh (tmos) shell:

BIG-IP Integrity Check: [ FAIL ] -- THE SYSTEM WILL HALT UPON REBOOT, CONTACT F5 NETWORKS FOR TECHNICAL SUPPORT

If your BIG-IP system halted during the boot process you must either boot to another volume or reinstall the system software in order to recover and reload the configuration. If your BIG-IP system failed a system integrity check and is still running, you should run the sys-eicheck utility manually (/usr/libexec/sys-eicheck.py) and correct any problems before restarting the system. If you suspect your system is compromised, you should follow your organization's security policies for suspected compromised systems.

Note: For Platform FIPS systems, output from the sys-eicheck utility is included by default in the /fips_module.xml file when running the qkview utility. Other systems can capture the output from the sys-eicheck utility when running the qkview utility by using the qkview -c command.

Limitations

Only certain BIG-IP modules and functions are FIPS 140 validated at level 2. All licensed BIG-IP features and modules are available to use on Platform FIPS systems; however, traffic traversing any non-validated features or modules is not considered to be FIPS validated. The following limitations apply:

  • FIPS validation is limited to the BIG-IP LTM and BIG-IP AFM modules. You can use other modules on a Platform FIPS system but traffic traversing them is not considered FIPS validated.
  • FIPS validation applies to certain BIG-IP versions, configurations, and options. Upgrading to a non-validated BIG-IP version invalidates the FIPS validation but there is no impact on system operations. For more information, refer to the F5 Platforms: FIPS Administration manual and the Security Policy and Certificates for your platform on the F5 Certifications page.

    Note: For information about how to locate F5 product guides, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  • The restjavad daemon is not FIPS validated. Features reliant upon the REST framework, such as iControl REST calls, iAppLX applications, and iRulesLX scripts, are not considered FIPS validated.

Recommendations

When implementing Platform FIPS systems, you should consider the following factors:

  • You should have at least two volumes configured on your BIG-IP system you can boot into in order to recover from a halted system. The backup volume should not have the Full-Box FIPS add-on license installed. This provides a recovery option for a halted system due to a failed self test.
  • Use only the TMOS Shell (tmsh) or the Configuration utility to make changes to the BIG-IP system. Manually changing system files or Linux host files on the BIG-IP system is not recommended.
  • You should run the sys-eicheck utility at the following times to see if there are any problems that can cause a system integrity self test to fail:
    • Before and after making any configuration changes on a Platform FIPS system.
    • Before restarting a Platform FIPS system, or making a change that initiates a restart of the system.
    • Before adding a Full-Box FIPS add-on license to an existing system.
