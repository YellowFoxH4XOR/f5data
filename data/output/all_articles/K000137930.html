Description

If you wish to mitigate CVE-2023-50164 in your environment using NGINX App Protect signatures, the following procedure may be helpful.
Note: For details of how to mitigate CVE-2023-50164 using BIG-IP Advanced WAF, F5 Distributed Cloud App Firewall or F5 Silverline WAF, see K000137929: How to mitigate Apache Struts CVE-2023-50164 and for details of any impact to F5 products or services, see K000137931: Apache Struts vulnerability CVE-2023-50164

Environment

You have one of the following products in use:
  • NGINX App Protect WAF
  • NGINX Controller App Security
  • NGINX Controller API-Management with Advanced Security

Cause

None

Recommended Actions

In order to protect the pool members against CVE-2023-50164, you should ensure the following signature ID is enforced;

200007016: Directory Traversal attempt "../" (Parameter)

Find specific guidance for your product in one the following sections:
Mitigating the Apache Struts vulnerability CVE-2023-50164 with NGINX App Protect WAF
Mitigating the Apache Struts vulnerability CVE-2023-50164 with NGINX Controller App Security and NGINX Controller API-Management with Advanced Security

Mitigating the Apache Struts vulnerability CVE-2023-50164 with NGINX App Protect WAF

To mitigate the Apache Struts vulnerability with NGINX App Protect WAF, perform the following procedures:
Download and apply the latest signature updates
  • Download and apply the latest signature updates for NGINX App Protect WAF to ensure that all of the signatures you need are available.
  • For information about downloading and updating signatures, refer to Updating App Protect Attack Signatures in the NGINX App Protect WAF Configuration Guide.
Note: F5 advises that you regularly update attack signatures for NGINX App Protect WAF. To be notified of attack signature updates, refer to K9970: Subscribing to email notifications regarding F5 products.

Ensure you enabled the "Generic Detection Signatures (High/Medium Accuracy)" Signature Set in your policy file
Ensure that you included and enabled ("block": true) the Generic Detection Signatures (High/Medium Accuracy) Signature Set, which includes the relevant attack signature ID, in your NGINX App Protect JSON policy file.
  1. If you are using the original, pre-installed JSON policy files — such as NginxDefaultPolicy.json, NginxStrictPolicy.json or NginxApiSecurityPolicy.json — you already have this signature set.
  2. Set the signature set to block, as in the following JSON policy example:
{
    "policy": {
        "name": "block_ssci_policy",
        "template": { "name": "POLICY_TEMPLATE_NGINX_BASE" },
        "signature-sets": [
            {
                 "name": "Generic Detection Signatures (High/Medium Accuracy)",
                 "block": true,
                 "alarm": true
            }
        ]
    }
}

Notes:
  • After updating attack signatures or making configuration changes to a policy, you must reload NGINX Plus to make the changes effective.
  • F5 recommends that you perform adequate testing to ensure that application functionality isn’t impeded as a result of configuration changes. For more information, refer to the NGINX App Protect WAF Configuration Guide.

Mitigating the Apache Struts vulnerability CVE-2023-50164 with NGINX Controller App Security and NGINX Controller API-Management with Advanced Security

Note: NGINX Controller does not manage signature updates on NGINX instances. Therefore, you must perform the signature update process in Mitigating the Apache Struts vulnerability CVE-2023-50164 with NGINX App Protect WAF on each NGINX instance on which you installed NGINX App Protect WAF.

NGINX Controller App Security enables the relevant signatures in the Generic Detection Signatures (High/Medium Accuracy) Signature Set by default. In addition, updating to the latest signature package provides greater mitigation against the vulnerability compared to any previous signature packages.
The relevant signatures are also included in NGINX Controller API-Management with Advanced Security with the same default behavior.

To enable a higher level of mitigation efficacy, the Generic Detection Signatures (High/Medium Accuracy) Signature Set can be set to Always Blocking mode using the Bring Your Own (BYO) NGINX App Protect Policy feature, available on NGINX Controller ADC version 3.20 and later. Using this feature, the policy can be set to always block when these signatures are triggered. Be aware that this setting change may cause false positives.

To enable blocking mode in addition to the NGINX Controller ADC default policy, do the following:
  • F5 recommends using the following custom NGINX App Protect JSON policy:
{
    "policy": {
        "name": "block_ssci_policy",
        "template": {
            "name": "POLICY_TEMPLATE_NGINX_BASE"        },
        "applicationLanguage": "utf-8",
        "enforcementMode": "blocking",
        "signatures": [],
        "signature-sets": [
            {
                "name": "Generic Detection Signatures (High/Medium Accuracy)",
                "block": true,
                "alarm": true            }
        ],
        "bot-defense": {
            "settings": {
                "isEnabled": false            }
        },
        "headers": [
            {
                "name": "*",
                "type": "wildcard",
                "decodeValueAsBase64": "disabled"            },
            {
                "name": "*-bin",
                "type": "wildcard",
                "decodeValueAsBase64": "required"            },
            {
                "name": "Referer",
                "type": "explicit",
                "decodeValueAsBase64": "disabled"            },
            {
                "name": "Authorization",
                "type": "explicit",
                "decodeValueAsBase64": "disabled"            },
            {
                "name": "Transfer-Encoding",
                "type": "explicit",
                "decodeValueAsBase64": "disabled"            }
        ],
        "cookies": [
            {
                "name": "*",
                "type": "wildcard",
                "decodeValueAsBase64": "disabled"            }
        ],
        "parameters": [
            {
                "name": "*",
                "type": "wildcard",
                "decodeValueAsBase64": "disabled"            }
        ]
    }
}
