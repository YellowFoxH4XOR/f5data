Issue

Error Message

0107143a:5: CMI reconnect timer: <status>

In this error message, note the following:

  • <status> is the centralized management infrastructure (CMI) reconnection timer status.

For example:

0107143a:5: CMI reconnect timer: enabled
0107143a:5: CMI reconnect timer: disabled, all peers are connected

Note: The system logs this error message to the /var/log/ltm file when mcpd debug logging is enabled.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file
Description

This message occurs when one of the following conditions are met:

  • The local BIG-IP system has either lost or recovered CMI channel connectivity to a remote peer. This may be due to one of the following reasons:
    • A remote CMI peer was removed from the device trust while it was in an offline state.
    • Network issues are preventing connectivity between the CMI peers over TCP port 4353.
    • A remote CMI peer is attempting to create a CMI connection, but the local CMI device has no self device configured.
    • One of the CMI peers has been rebooted to a software partition where device trust is not configured.

Note: CMI is also referred to as device service clustering (DSC).

CMI timer status:

  • Enabled - Reconnection attempts to the remote CMI peer will occur every 5 seconds until the CMI channel has successfully reconnected.
  • Disabled - The CMI channel has successfully reconnected. 

Impact

If the remote peer CMI peer is expected to be part of the local device trust, synchronization or failover will not occur. If the remote CMI peer is not expected to be part of the local device trust, there is no impact other than moderate disk space consumption due to the additional logging messages.

Recommended Actions

  • Ensure that the BIG-IP systems have correct self IP definitions, and the network allows proper connectivity between the BIG-IP systems.
  • For more troubleshooting information, refer to K13946: Troubleshooting ConfigSync and device service clustering issues (11.x - 12.x).
  • Use the following Traffic Management Shell (tmsh) command to view additional information regarding CMI channel connection status:
    tmsh show /cm sync-status
