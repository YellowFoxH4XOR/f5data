Known Issue

The BIG-IP system may drop server responses for certain types of IP protocol traffic. This issue occurs when all of the following conditions are met:

  • The FastL4 virtual server is configured to process traffic with all protocols enabled.
  • The FastL4 virtual server is configured to SNAT traffic with SNAT Automap or a SNAT Pool.
  • The FastL4 virtual server receives IP protocol traffic that is not TCP, UDP, SCTP, ICMP or ICMPv6.

This issue occurs because the BIG-IP system incorrectly adds a source port to the affected IP protocol traffic before forwarding to the server and drops the return traffic from the server as it is unable to match the traffic with any of the existing connections.

Impact

Connections may appear to stall.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system drops certain server response traffic.
  • The BIG-IP system responds with an ICMP Destination Unreachable - Protocol Unreachable packet to each packet from the server.

Workaround

To work around this issue, you can disable the SNAT configuration on the affected virtual server. To do so, perform the following procedure:

Impact of workaround: Disabling SNAT may prevent clients and pool members from communicating correctly; ensure that this change is appropriate to your environment. You may need to perform the NAT on another device, if necessary.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the affected virtual server.
  4. Select Advanced from the Configuration drop-down menu.
  5. Select None from the SNAT Pool drop-down menu.
  6. Click Update to save the modification.
