Description

Windows 11 or any TLS Client that uses TLS 1.3 may experience issues with On-Demand Cert Auth

Environment

  • BIG-IP APM
  • Windows 11 or any TLS Client that uses TLS 1.3
  • On-Demand Cert Auth

Cause

Up until TLS 1.2, it was possible to request a client certificate, based on conditions such as URI match etc, after the handshake is done. With TLS 1.2 this is done by the BIG-IP initiating a renegotiation on the already established connection and requesting the certificate in the renegotiation handshake.

TLS 1.3 removed the support for renegotiation. The same mechanism used above for TLS 1.2, cannot be used for TLS 1.3. However TLS 1.3 supports post handshake authentication - With this, the server can request a certificate from the client anytime after the handshake is done. 

Currently, BIG-IP does not support this feature and is being tracked by ID846401.   

Recommended Actions

It is recommended that you disable TLS 1.3 in your ClientSSL profile.

  1. Login to the BIG-IP GUI
  2. Navigate to Local Traffic  ››  Profiles : SSL : Client
  3. Choose your SSL Profile
  4. Click the check box on the far right to enable Options modifications
  5. Move No TLSv1.3 from the Available Options to the Enabled Options
  6. Scroll down and click Update
