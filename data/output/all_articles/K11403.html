Known Issue

When the BIG-IP APM system is configured to use SecurID over RADIUS and prompts the end user for a new code, the message displayed to the end user is hexadecimal encoded.

For example:

0x0d0a202020456e74657220796f7572206e65772050494e2c20636f6e7461696e696e67203420
746f2038206469676974732c0d0a202020202020202020202020202020206f720d0a2020203c43
74726c2d443e20746f2063616e63656c20746865204e65772050494e2070726f6365647572653a
2000

This code translates to:

Enter your new PIN, containing 4 to 8 digits,
or
<Ctrl-D> to cancel the New PIN procedure:

Note: This issue appears to be specific to RSA server version 7.1 but may exist on other versions.

In addition, the following message may appear in the /var/log/apm file:

F5 Product Development tracked this issue as ID 328304 (formerly CR139796) and it was fixed in BIG-IP APM 10.2.1. For information about upgrading, refer to the BIG-IP APM release notes.

This issue has been fixed in Hotfix-BIGIP-10.1.0-3402.0-HF2, which has been issued for BIG-IP 10.1.0, and Hotfix-BIGIP-10.2.0-1755.1-HF1 issued for version 10.2.0. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes on systems, refer to K10025: Managing BIG-IP product hotfixes (10.x).
