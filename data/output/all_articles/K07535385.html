Topic

You should consider using this procedure under the following condition:

  • You want to extract data from HTTP payload using iRules.

Description

You can create an iRule to extract specific data from HTTP payload, such as content from a client HTTP POST request, and then output the extracted data to the log files.

The following key commands are necessary to build the iRule:

  • The HTTP::collect command collects the HTTP payload before the data can be extracted. When using the HTTP::collect iRules command, F5 recommends that you include iRules syntax that verifies that the Content-Length header is a non-zero value to avoid collecting empty payload.

    For example, the following iRule code shows the HTTP payload is being collected, up to 1MB (1048576 bytes), when the Content-Length header is not empty:

    if {[HTTP::header "Content-Length"] ne "" && [HTTP::header "Content-Length"] <= 1048576}{
      set content_length [HTTP::header "Content-Length"]
    } else {
        set content_length 1048576
    }
    if { $content_length > 0} {
      HTTP::collect $content_length
    }

  • You need the HTTP::payload command for querying the HTTP payload information. The payload command is available only in very specific iRules events like HTTP_REQUEST_DATA and HTTP_RESPONSE_DATA and after you have collected the data using the HTTP::collect command.
  • You use the findstr function to locate a matching string, and it returns a substring based on the specified offset and end string. The function uses the following syntax:

    findstr <string> <search_string> [<skip_count> [<terminator>]]

    For example, to extract the username substring "tester1" from the string "username=tester1&group=guest&action=go" in HTTP payload, you would type the following command:

    findstr [HTTP::payload] "username=" 9 &

    The previous findstr example is defined as follows.

    SyntaxExampleDescription
    findstrfindstrThe findstr function.
    <string>[HTTP::payload]The collected HTTP payload as search base.
    <search_string>"username="The string needs to be matched.
    <skip_count>9Nine characters are skipped starting with the search string.
    <terminator>&The return string matches up to the terminator character '&'.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP Configuration utility.
  • You have a virtual server configured with an HTTP profile.

Procedures

Creating an iRule to log the extracted data from HTTP payload

To create an iRule that extracts data from the payload of a client HTTP POST request and enters a log entry to the /var/log/ltm file, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. In the Name box, type a name for the iRule.
  5. In the Definition box, enter the HTTP payload iRule.

    For example, the following iRule collects 1MB or less payload and outputs the username to the /var/log/ltm file:

    when HTTP_REQUEST {
      if {[HTTP::method] eq "POST"}{
        if {[HTTP::header "Content-Length"] ne "" && [HTTP::header "Content-Length"] <= 1048576}{
          set content_length [HTTP::header "Content-Length"]
        } else {
            set content_length 1048576
        }
        if { $content_length > 0} {
          HTTP::collect $content_length
        }
      }
    }
    when HTTP_REQUEST_DATA {
      log local0. "Login name = [findstr [HTTP::payload] "username=" 9 &]"
    }

  6. Click Finished.
  7. Associate the iRule with the virtual server.
