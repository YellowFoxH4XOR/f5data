Known Issue

This is the result of a known issue. The RESOLV::lookup iRule command performs a DNS query, returning the resource record type indicated in the iRule syntax. When using the RESOLV::lookup iRule command with the -ptr flag, the BIG-IP system fails to return a valid hostname even if the remote DNS server response contains a valid PTR record for the IP address.

For example, the following iRule queries the nameserver with an IP address of 172.16.65.11, and returns the designated domain name for IP address 172.16.65.55:

when CLIENT_ACCEPTED {
log local0. "The designated domain name for IP 172.16.65.55 is [RESOLV::lookup @172.16.65.11 inet -ptr 172.16.65.55]"
}

In the example, the DNS server returned the PTR record for IP address 172.16.65.55; however the BIG-IP system ignored the valid response and failed to log the designated domain name to local0 as displayed in the following syslog message:

local/tmm info tmm[29999]: Rule resolve_rule <CLIENT_ACCEPTED>: The designated domain name for IP 172.16.65.55 is

F5 Product Development tracked this issue as ID 340659 and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
