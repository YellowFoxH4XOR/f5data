Known Issue

A duplicate IP address conflict may cause an internal traffic loop on VIPRION platforms.

This issue occurs when all of the following conditions are met:

  • A Virtual Local Area Network (VLAN) group is configured to use either the Transparent or Translucent transparency modes.
  • A duplicate IP address exists on the BIG-IP system and another device in the VLAN group.

Impact

Client connections can experience high latency and disconnect, and the Configuration utility may stop responding.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H486212 on the Diagnostics > Identified > Medium page.
  • The BIG-IP system reports unexpectedly high CPU usage.
  • Client connections experience high latency and occasionally disconnect.
  • The Configuration utility appears unresponsive.

Workaround

To work around this issue, you can remove the duplicate IP address from one of the systems in the VLAN group. You can also disable the vlangroup.flow.allocate database variable. To do so, perform the following procedure:

Impact of workaround: Disabling the vlangroup.flow.allocate database variable will stop the BIG-IP system from tracking connection flows that traverse VLAN groups.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Type the following command:

    modify sys db vlangroup.flow.allocate value disable
