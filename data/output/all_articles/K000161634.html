K000161634: ASM falsely detects ChatGPT redirect/referrer as .com file type

Type
Support Solution
Published
2026-06-08
Updated
2026-08-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000161634

Description

ASM was falsely blocking legitimate HTTP requests with a “Disallowed File Type (com)” violation when the .com string appeared at the end of a query parameter, such as a referrer or redirect value from domains like chatgpt.com or bing.com, even though the actual requested URL did not contain a .com file extension.

For example:

https://example.com/?utm_source=chatgpt.com

Environment

  • AWAF/ASM
  • File type .com is set to disallowed in the security policy

Cause

ASM incorrectly parsed .com within query parameters as the request file type when the "Trailing slash" evasion technique detection had "Learn" enabled.

This caused legitimate requests with referrer or redirect parameters containing .com domains to be blocked by the "Disallowed File Type" settings in the policy, even though the actual requested resource did not have a .com extension.

This issue is tracked under Bug ID1782881.

 Answer/Recommended Actions

As a workaround, clear the "Learn" option for the "Trailing slash" evasion technique under "Evasion Technique Detected" in the ASM policy’s "Learning and Blocking Settings".

If this evasion technique detection is not required, you may also clear "Enable".
