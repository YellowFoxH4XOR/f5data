K12994: FirePass is unable to route to resources that use policy based routes with overlapping names

Known Issue

Description

When two policy based route table names start with the same characters, users may be unable to route using either of the policy based routes.

This issue occurs when of the following condition is met:

  • Two or more policy based routes configured on the Device Management: Configuration: Network Configuration: Routing tab have a name that start with the same two or more characters

    For example, if one policy based route table name is prod_1 and the second policy based route table name is prod_2, users may be unable to route to either resource. However, if the names are 2_prod and 1_prod, users should experience no routing issues.

Impact

Users will be unable to route to hosts defined in the policy based routes

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • User sessions may time out before connecting to resources
  • Users may receive error messages indicating that the desired resource is unavailable

Workaround

To work around this issue, you can change the name of an existing policy based route to not overlap with other routes. To do so, perform the following procedure:

Impact of workaround: None

Changing the name of the policy based route

  1. From the Administrative Console, navigate to Device Management: Configuration: Network Configuration.
  2. Click on the Routing tab.
  3. Click the Switch to advanced mode [>>] link.
  4. In the Routing section, inspect the table for any table names that begin with the same two or more characters.
  5. Change the name of the route in the Table Name: field.
  6. Click the Update button for the table that was updated.
  7. After you have ensured that all table names do not begin with the same characters, click on the Finalize Section link located beneath the tabs.
  8. Review the Routing section for any possible errors.
  9. Click the Finalize Changes button.
