Topic

Note: This article applies to platform and software combinations that support CMP; it does not apply to single processor devices.

Port exhaustion or collisions may occur on either Clustered Multiprocessing (CMP) or non-CMP systems experiencing heavy usage or special client traffic patterns. In addition, port exhaustion may also occur on CMP systems experiencing normal traffic volumes, since the system equally divides available ports among all active Traffic Management Microkernel (TMM) instances. This can occur for virtual servers that have been demoted from CMP and may be exacerbated if the virtual server uses a secure network address translation (SNAT), or sends traffic to only one pool member.

When a CMP-compatible system processes an incoming packet, the system uses the address information and ports to hash the packet to a particular TMM instance. The number of ports available to tmm0 depends on the number of TMM instances running. For a device with two active TMM instances, the available ports will be <total_ports>/2. For a device with four active TMM instances, the available ports will be <total_ports>/4. Starting in BIG-IP 12.0.0, the BIG-IP system generates an ephemeral port exhaustion warning to the /var/log/ltm file when approximately 80 percent of the available ephemeral ports are in use.

If the virtual server is not in CMP mode, the packet will be sent to tmm0. If necessary, TMM will translate the source port to one matching its hash, which ensures that return traffic is directed back to tmm0. If the virtual server is in CMP mode and a SNAT is in use, the packet will be sent to the TMM instance matching the source port, which ensures return traffic is directed back to the correct TMM instance. In both cases, the ports available for translation are limited to that fraction of ports, which are allocated to the TMM instance handling the connection.

If several simultaneous connections are made from the same source IP address, each client port will be translated, as needed, to ensure that return traffic is sent to tmm0. Since each connection consumes a unique source port, the number of available client ports is commensurately reduced.

You may be able to mitigate source port exhaustion on CMP-enabled BIG-IP systems using the following method:

Configuring source port preservation for virtual servers/SNATs

You can use the preserve strict option to force TMM to preserve the source port for virtual server and secure network address translation (SNAT) traffic. For information about configuring source port preservation for virtual servers and SNATs, refer to the following articles:

  • K11003: Configuring source port preservation for virtual servers
  • K13433: Configuring source port preservation for SNATs

Important: The preserve strict option is not available for TCP connections until 11.3.0.

In addition, F5 recommends that you configure multiple SNAT addresses or larger SNAT pools to prevent destination port exhaustion. For more information, refer to K8246: How the BIG-IP system handles SNAT port exhaustion.
