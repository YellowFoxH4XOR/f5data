Topic

This article applies to BIG-IP 9.0.0 - 9.3.x. For information about other versions, refer to the following articles:

  • K13367: Managing log files on the BIG-IP system (11.x - 13.x)
  • K7115: Managing log files on the BIG-IP system (9.4.x - 10.x)

The BIG-IP system uses the logrotate program to rotate the logs on a daily basis. You can change the following options for the logrotate scripts:

  • Enable or disable compression
  • Change log rotation frequency
  • Change log rotation variables

Enabling or disabling compression

  1. Log in to the command line.
  2. Change directories to the /etc/logrotate.d/ directory by typing the following command:

    cd /etc/logrotate.d/

  3. Edit the syslog-ng file and locate the line that contains the group of log files for which you want to disable compression. Locate the line that contains the compress statement below the list of log files.

    Note: The default option is to compress the log files after they are rotated in order to conserve space.

    For example:

    /var/log/ltm /var/log/gtm /var/log/messages /var/log/secure /var/log/maillog /var/log/boot.log /var/log/cron /var/log/pktfilter /var/log/em/var/log/tmm /var/log/daemon.log /var/log/kern.log /var/log/bcm56xxd { compress <-- missingok notifempty sharedscripts postrotate /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true endscript}

  4. To disable compression for that group of log files, change compress to nocompress.

    For example:

    /var/log/ltm /var/log/gtm /var/log/messages /var/log/secure /var/log/maillog /var/log/boot.log /var/log/cron /var/log/pktfilter /var/log/em /var/log/tmm /var/log/daemon.log /var/log/kern.log /var/log/bcm56xxd { nocompress <-- missingok notifempty sharedscripts postrotate /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true endscript}

  5. Save the changes to the /etc/logrotate.d/syslog-ng file.

The BIG-IP system will use the new settings next time the logrotate application is run by the cron utility.

Changing log rotation frequency

Important: The following procedure will not survive a software upgrade, which includes full releases, hotfixes, and engineering hotfixes. If a BIG-IP system requires upgrading, perform the following procedure (again) after the upgrade. Alternately, you can configure the BIG-IP system to include edited or moved files in a UCS file collection, which allows those changes to survive a single upgrade. For more information about modifying the contents of UCS files, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

  1. Log in to the command line.
  2. Change directories to the /etc directory by typing the following command:

    cd /etc

  3. Edit the logrotate.conf file and find the line that contains one of the following settings:
    • daily
    • weekly
    • monthly

    Note: The default value is daily.

  4. Change the setting as desired and save the changes.
  5. Move the logrotate script to the desired directory by typing the following command:

    mv /etc/cron.daily/logrotate /etc/<cron directory>/

  6. Replace <cron directory> with one of the following directories:
     
    • cron.hourly
    • cron.daily
    • cron.weekly
    • cron.monthly

    For example, to move the logrotate script to the hourly directory, you would type the following command:

    mv /etc/cron.daily/logrotate /etc/cron.hourly/

The BIG-IP system will use the new setting the next time the cron utility runs the logrotate script.

Changing log rotation variables

  1. Log in to the command line.
  2. Change directories to the /etc/logrotate.d/ directory by typing the following command:

    cd /etc/logrotate.d

  3. Edit the syslog-ng file as follows:

    • To rotate log files, even if they are empty, change the following line associated with that group of log files:

      Change: notifempty to ifempty

      For example:

      /var/log/ltm /var/log/gtm /var/log/messages /var/log/secure /var/log/maillog /var/log/boot.log /var/log/cron /var/log/pktfilter /var/log/em /var/log/tmm /var/log/daemon.log /var/log/kern.log /var/log/bcm56xxd { compress missingok notifempty <-- Change to to ifempty to rotate log files even if they are empty sharedscripts postrotate /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true endscript}

      Note: The default setting is notifempty.

    • To add additional log locations for rotation, add the log file path to an existing group.

      For example: /var/log/newlog

      /var/log/ltm /var/log/gtm /var/log/messages /var/log/secure /var/log/maillog /var/log/boot.log /var/log/cron /var/log/pktfilter /var/log/em /var/log/tmm /var/log/daemon.log /var/log/kern.log /var/log/bcm56xxd /var/log/newlog { <-- new log added for rotation compress missingok notifempty sharedscripts postrotate /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true endscript}

    • To email logs that will be deleted, add the following line to the list of logs to be emailed:

      mail <e-mail address>

      For example:

      /var/log/ltm /var/log/gtm /var/log/messages /var/log/secure /var/log/maillog /var/log/boot.log /var/log/cron /var/log/pktfilter /var/log/em /var/log/tmm /var/log/daemon.log /var/log/kern.log /var/log/bcm56xxd /var/log/newlog { <-- new log added for rotation compress missingok notifempty mail myemail@somesite.com <--- Email entry to email logs that will be deleted. sharedscripts postrotate /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true endscript}

  4. Save the changes.

The BIG-IP system will use the new setting the next time the cron utility runs the logrotate script.

Changing the number of archived versions kept by syslog before deleting

  1. Log in to the command line.
  2. Change directories to the /etc directory by typing the following command:

    cd /etc

  3. Edit the logrotate.conf file.
  4. Locate the following line and change it to the desired value:

    rotate <number>

    Note: The default value is 8.

  5. Save the changes.

The BIG-IP system will use the new setting the next time the cron utility runs the logrotate script.
