Known Issue

This is the result of a known issue. For an ARX system under heavy traffic conditions, if a back-end filer simultaneously disconnects a large number of ARX CIFS connections, the ARX system's NSM processor may not reset the connections properly. As a result, the ARX system may experience NSM resource exhaustion. If the NSM resources become exhausted, the ARX NSM processor will dump core and log error messages to the syslog file that appear similar to the following example:

:NET_CIFS-0-ERR-NSM_CIFS_BE_OPEN_FAIL:: Backend-open for file:<Filename> with the filer:<filer IP> for client:<Client IP> failed. Error:STATUS_INTERNAL_ERROR returned to the client.
:NET_ERR_TRAP-0-ERR-NSM_RESOURCE_ERROR_THRESHOLD:: The fastpath CIFS Connections resource is at 80% utilization level.
:NET_ERR_TRAP-0-ERR-NSM_RESOURCE_ERROR_THRESHOLD:: The fastpath CIFS Connections resource is at 90% utilization level.
:NET_ERR_TRAP-0-ERR-NSM_RESOURCE_ERROR_THRESHOLD:: The fastpath CIFS Sessions resource is at 80% utilization level.
:NET_ERR_TRAP-0-ERR-NSM_RESOURCE_ERROR_THRESHOLD:: The fastpath CIFS Sessions resource is at 90% utilization level.
:TRANFS-1-WARN-MSG4:: get_space failed at <sharename> - STATUS_INSUFF_SERVER_RESOURCES

This issue has only been reported to occur in rare situations where the ARX system is under heavy traffic conditions and the number of connections simultaneously disconnected by the back-end filer are in excess of 8,000 connections. You can view the number of connections processed by the ARX system by typing the show statistics cifs fastpath command. The command output appears similar to the following example:

Proc Transactions FrontEnd    BackEnd     File File
     Handled      Connections Connections Info Handles
---- ------------ ----------- ----------- ---- -------
1.2  808120537    1291        6889        1282 7136

Note: For information about a related situation where Microsoft Windows Server 2003 may suspect a DoS attack and disconnect the ARX connections, refer to K8429: Microsoft Windows Server 2003 resets ARX connections due to denial-of-service attack detection.

F5 Product Development tracked this issue as ID 338421 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.

This issue was fixed in a hotfix release for ARX version 5.1.7 HF1 (build 12059). Customers affected by this issue may request this hotfix release or a later version of the hotfix from F5 Technical Support, referencing ID 338421 and this Solution.
