K000162263: BNK Gateway API: SSL Profile Broken After Invalid Certificate Secret Reference

Type
Support Solution
Published
2026-07-15
Updated
2026-07-15
Applies to
  • BIG-IP Next
  • BIG-IP Next for Kubernetes: 2.2.0
Source
https://my.f5.com/manage/s/article/K000162263

Description

When using BIG-IP Next for Kubernetes (BNK) Gateway API resources, referencing an invalid TLS certificate Secret in a Gateway resource causes the SSL profile in TMM to become broken. The Gateway status conditions (Accepted, Programmed, ResolvedRefs) continue to report success, but HTTPS traffic fails. Updating the certificate Secret to a valid one does not restore functionality; the SSL profile remains broken until the Gateway resource is deleted and recreated.

Environment

  • BIG-IP Next for Kubernetes (BNK) version 2.2.0
  • Gateway API (gateway.networking.k8s.io/v1) resources with TLS listeners referencing Kubernetes Secrets for certificate/key pairs
  • TMM (Traffic Management Microkernel) processes SSL profiles based on referenced Secrets
  • No controller-side validation for certificate/key content

Cause

The BNK controller does not validate the content or cryptographic validity of TLS certificate/key pairs referenced in Gateway resources. When an invalid certificate is referenced, TMM ingests a broken SSL profile. Subsequent updates to valid certificates do not reliably restore the profile, requiring Gateway resource recreation. This is a confirmed bug tracked as Bug ID 2349689.

Answer/Recommended Actions

  • Delete and recreate the affected Gateway resource after correcting the certificate Secret; in-place updates are not sufficient to restore functionality.
  • Manually validate certificate/key pairs in Kubernetes Secrets before referencing them in Gateway resources:
    1. Extract and decode the certificate and key from the Secret.
    2. Use OpenSSL to check certificate and key validity.
  • Await BNK 2.4 for a fix to the SSL profile recovery issue.

Additional Information

  • Bug ID: 2349689
  • Fix targeted for BNK 2.4 
  • Related RFE: 2389101 (certificate validation enhancement)
