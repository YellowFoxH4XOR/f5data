Description

When you configure the DNS cache feature, the BIG-IP system resolves DNS requests and responds to repeated DNS queries by serving answers from the cache. The DNS cache feature optimizes responses to DNS queries.

There were DNS cache scalability and sizing enhancements in BIG-IP 15.0.0, and it changed how each Traffic Management Microkernel (TMM) maintains the dns cache. In both pre-v15 and post-v15 versions, there are no checks preventing sizing a cache so large that it runs the TMM out of memory, and appropriate sizing of the amount of cache is important during deployment.

Note: The article assumes you understand the difference between a TMM process and thread, which is described in K14358: Overview of Clustered Multiprocessing (11.3.0 and later).

For versions prior to BIG-IP 15.0.0

Each TMM thread holds and maintains a replicated copy of the dns cache. This means all threads try to mirror each other and have the same data.

The general guideline for DNS cache sizing considering the point is the formula:

(msg + rrset + NS * 250b) * 2.5 * (# of TMMs per device/blade) <= 1/2 allocated TMM memory

where:

  • msg: Message Cache, a sub-cache of the DNS cache that contains the response to a specific DNS query.
  • rrset: RRset Cache, a sub-cache of the DNS cache that contains the resource record set data referenced by the message cache. In the case of very simple A/AAAA queries, responses may be generated directly from the RRSet cache.
  • NS: Nameserver Cache, a sub-cache of the DNS cache that contains metadata about nameservers used to resolve DNS queries. Information in this sub-cache is used to aid back-end name resolution, and is only used on a cache miss. Transparent caches do not have a nameserver sub-cache.
  • 250b: a fixed size of 250 Bytes.

For versions after BIG-IP 15.0.0

Each TMM process holds and maintains its own copy of the dns cache, and it is not mirrorred between processes. The configured size is the size shared across the TMM processes, and it is split against each TMM process. For example, when total of 10MB max memory is configured on a device or a blade having 2 threads and 2 processes, then each process will have 5MB each.

The general guideline for DNS cache sizing considering the point is the formula:

msg + rrset + NS * 250b + (Memory allocated for number of concurrent TCP and UDP connections) <= 1/2 allocated TMM memory
 
Where the memory allocated for number of concurrent TCP and UDP connections:
  • Approximate allocated memory for number of tcp connections for each cache = 70 KB * (number of tmm threads) * (maximum number of concurrent tcp flows)
  • Approximate allocated memory for number of udp connections for each cache = 0.5 KB * (number of tmm threads) * (maximum number of concurrent udp flows)

Environment

  • DNS Cache is in use

Cause

BIG-IP 15.0.0 introduced the change in behavior as a result of DNS cache scalability and sizing enhancements.

Recommended Actions

Ensure that the sum of all of the configured cache Message Cache Size, Resource Record Cache Size, and Name Server Cache Count settings is half the value or less of the total memory allocated to TMM. To do so, perform the following procedure:

Note: For VIPRION systems, the total value and total memory calculation applies to a single blade, not the sum of all installed blades in the chassis.

  1. Determine the number of TMMs and the total memory available, type the following command:

    tmsh show sys tmm-info global

    In the following example, the system has 16 TMMs, and they have total 42.9 GB of memory.
    Note: For VIPRION systems, devide the number of TMMs and the memory total by the number of blades in the system.

    --------------------------
Sys::TMM
--------------------------
Global
  TMM Count             16

Memory (bytes)
  Total              42.9G
  Used                2.1G

CPU Usage Ratio (%)
  Last 5 Seconds         1
  Last 1 Minute          4
  Last 5 Minutes         2

    Note: Based on 42.9 GB, the sum of all of the DNS cache sizes should not exceed 21.45 GB.

  2. Configure DNS cache so that sum of cache size from all DNS cache does not exceed the memory size derived in step 1.

    Note: Each DNS cache configuration independently maintains DNS cache. For example, when there are DNS cache configurations dns-cache1 with total max size 1GB configured and dns-cache2 with total max size 1GB configured, the device will consume up to 2GB plus a little more for internally managing the cache.
