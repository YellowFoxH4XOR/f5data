Known Issue

A collision in the IP hash table may cause the BIG-IP ASM system to log an error message and core.

This issue occurs when the following conditions are met:

  • Denial-of-service (DoS) attack prevention is enabled in the security policy
  • You reconfigure the security policy

    Note: Reconfiguring the security policy has been known to cause the IP hash table collision. However, other factors may also cause this issue.

The BIG-IP ASM system maintains an IP hash table for DoS prevention calculations. Certain actions may cause the system to remove the wrong IP address from the hash table, and result in a BIG-IP ASM bd process core file.

Impact

The BIG-IP ASM traffic processing is temporarily interrupted.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP ASM system produces a bd core file
  • The BIG-IP ASM system logs an error message to the /var/log/ts/bd.log file. For example:

    ATTACK_ENGINE|ERR |<timestamp>|7783|dos_engine.c:7002|######## Deleted element is not in ip list counter = 100
  • The system sends a SIGSEGV to the bd process and logs a message to the /var/log/ts/bd.log file. For example:

    BD_MISC|CRIT |<timestamp>|7783|signals.c:0075|Received SIGSEGV - Core Dumping
