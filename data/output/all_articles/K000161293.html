Description

GUI inaccessibility occur when the /shared partition reaches 100% disk utilization. Modules such as Event Logs, Parameters List and Bot Traffic may become unresponsive or fail to load. The following error may be observed in the ASM GUI:

mysql::st execute failed: Disk full (/var/tmp/#sql_5b3a_2); waiting for someone to free some space...

Figure: ASM error displayed on GUI

Environment

  • /shared at 100% disk utilization
  • Event Logs, Bot Traffic (GUI inaccessibility)
  • BIG-IP ASM (or BIG-IP Advanced WAF)

Cause

The /shared partition reached 100% disk utilization due to the accumulation of large diagnostic files, including tcpdump .pcap capture files and support archives. This disk exhaustion caused MySQL on the ASM subsystem to fail when attempting temporary disk writes, resulting in GUI inaccessibility and performance degradation across multiple modules.

Recommended Actions

The MySQL error referencing /var/tmp/ is a symptom of the /shared partition exhaustion, as the ASM subsystem relies on available disk space for temporary write operations.

  1. Check the disk utilization of F5 BIG-IP using command through CLI:
    • df -h
  2. Identify the largest files consuming space on the /shared partition:
    • find /shared/ -xdev -type f -exec du {} \; | sort -rn | head -20
  3. Review the output and identify unnecessary large files such as old .pcap capture files and stale support archives.
  4. Safely delete the confirmed unnecessary files.
  5. Verify that disk utilization has been restored to an acceptable level:
    • df -h
  6. Confirm that the BIG-IP GUI is accessible and all modules are functioning as expected.

Additional Information

To investigate large file accumulation on the /var partition, use: find /var/ -xdev -type f -exec du {} \; | sort -rn | head -20
