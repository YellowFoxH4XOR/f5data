Known Issue

Certain header manipulations in the HTTP profile cause a connection reset.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with a Client SSL profile, HTTP profile, and an iRule.
  • The HTTP profile is configured with Insert X-Forwarded-For enabled and/or Request Header Erase.
  • The iRule has an SSL::collect command in at least two events; for example, CLIENTSSL_HANDSHAKE and CLIENTSSL_DATA.

Impact

The TCP connection resets without a response to the client.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The HTTP profile has Insert X-Forwarded-For, which adds a header when a request forwards to a pool member. When a virtual server has an iRule with a collect command, such as SSL::collect, it is affected by the HTTP profile processing, resulting in a TCP reset. The same behavior occurs when you use Request Header Erase, which removes specific headers available in the HTTP profile.

Workaround

To work around this issue, you can use the iRule to insert the X-Forwarded-For option with an appropriate IP address and/or remove headers instead of using the HTTP profile options.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
