Known Issue

Under periods of heavy traffic load, when compression or encryption is enabled, TMM may produce a core file.

This issue occurs when all of the following conditions are met:

  • You are running a BIG-IP 4000 or 2000 series platform.
  • The BIG-IP system is under heavy load.
  • BIG-IP memory usage is high.
  • Compression or Encryption is enabled.

Impact

The BIG-IP system fails over to another system in the device group.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H422923 on the Diagnostics > Identified > High screen.
  • Your BIG-IP system unexpectedly fails over to another system in the device group.
  • You will see core files in the /shared/core directory.
  • You may see one or more error messages that appear similar to the following examples in /var/log/ltm:

    01010004:3: Memory allocation failed: Couldn't allocate memory for buffer list
    01010025:2: Device error: (null) Allocation linked list is empty
    011e0002:4: sweeper_update: aggressive mode activated. (<number>/<number> pages)
    01010025:6: Per-invocation log rate exceeded; throttling.
    011e0003:4: Aggressive mode sweeper: 1 Connections killed
    01010004:3: Memory allocation failed: qaeMemAlloc(), failed for br->session
    01010025:2: Device error: (null) Could not init the Instance List
    01140045:5: HA reports tmm NOT ready
