Known Issue

The ping_access_agent service may continually restart in some deployment scenarios.

This issue occurs when all of the following conditions are met:

  • You deploy the BIG-IP APM system using a Virtual Edition (VE) instance.
  • The hypervisor has more than 24 CPU cores.

Impact

The ping_access_agent service continually restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users attempt to access virtual servers configured with the PingAccess profile receive a connection reject.
  • When viewing the ping_access_agent service, the restart count is extremely high compared to other services (restarted hundreds or thousands of times).

Workaround

To work around this issue, you can modify the number of ping_access_agent services to start based on the Traffic Management Microkernel (TMM) count, rather than CPU cores. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure should not have a negative impact on your system.

  1. Log on to the affected BIG-IP command line with administrator level access.
  2. Determine the number of running TMM processes of the device by typing the following command:

    tmsh show /sys tmm-info global | grep -i 'TMM count'

  3. Using a text editor, open the /etc/bigstart/scripts/ping_access_agent file.
  4. Modify the last line of the file.

    Original last line:

    exec /usr/sbin/${service} -n ${cpu_count}

    Updated last line: 

    exec /usr/sbin/${service} -n <TMM count number>

    Note: Replace <TMM count number> with the TMM count in step 2.
