Known Issue

The BIG-IP system does not reconnect to SafeNet HSM if the connection is interrupted. 

This issue occurs when all of the following conditions are met:

  • You are using a SafeNet network HSM device.
  • The SafeNet network HSM device connection has disconnected from the BIG-IP system.

Impact

SSL connections that use a key that is stored on the network HSM may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • In the /var/log/daemon log file, you may observe an error message similar to the following example:

    err pkcs11d: Nethsm: pkcs1v15_decrypt C_Decrypt error 0x00000030, session[6]

  • In the /var/log/ltm log file, you may observe an error message similar to the following example:

    crit tmm[<pid>]: 01260010:2: FIPS acceleration device failure: fips_poll_completed_reqs: req: 2 status: 0x1 : Cancel

Workaround

To work around this issue, you can restart the pkcs11d process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the pkcs11d process by typing the following command:

    restart sys service pkcs11d
