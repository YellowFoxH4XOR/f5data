K000092448: SLO fails when logging out from APM portal using Entra ID as IdP

Type
Support Solution
Published
2022-10-13
Updated
2026-07-21
Source
https://my.f5.com/manage/s/article/K000092448

Description

BIG-IP APM SAML Single Logout fails with error code "8001" when an end user clicks on "Logout" from the F5 APM Webtop. This causes the APM session to not be terminated even though the SAML logout has completed. 

  • Checking /var/log/apm, you see:
    SAML SSO: Invalid SLO request path. Expected (/saml/sp/profile/redirect/slr or /saml/sp/profile/redirect/slo), received (/saml/sp/profile/post/slo?...)
    SAML SSO: Error (12) extracting SAML SLO message
  • Sometimes end users might see:
    You do not have permission to access this page.
    Internal error. Failed to process SAML request/response. Please try again or contact your system administrator if error persists.

Environment

  • Big-IP 
  • SAML Authentication
  • Microsoft Entra ID 

Cause

The SLO endpoint on Microsoft Entra ID is set to "/saml/sp/profile/post/slo".
However, Microsoft Entra ID supports redirect binding (HTTP GET), and not HTTP POST binding.

Therefore, Microsoft Entra ID sends the LogoutResponse using HTTP-Redirect, which is an HTTP GET request to an HTTP POST SLO endpoint, BIG-IP then rejects the SLO message and returns error code 8001.

 Recommended Actions

  1. In the Microsoft Entra ID SAML application configuration, change the SLO endpoint to:
    /saml/sp/profile/redirect/slo

  2. Verify that the SAML IdP Connector in F5 uses the HTTP-Redirect binding for Single Logout:
    single-logout-binding http-redirect
