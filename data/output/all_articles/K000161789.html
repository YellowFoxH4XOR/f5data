K000161789: [APM] EdgeClient for macOS DNS resolution is failing with iCloud Private Relay

Type
Support Solution
Published
2026-06-18
Updated
2026-06-18
Source
https://my.f5.com/manage/s/article/K000161789

Description

macOS users connected to a BIG-IP APM SSL VPN (Network Access) resource in split-tunnel mode may experience DNS resolution failures for internal corporate hostnames. Specifically:

  • When a hostname has both an internal (corporate) DNS record and an external (public) DNS record, the macOS client resolves the hostname to the public IP instead of the internal corporate IP, even while connected to the VPN.

Environment

  • Product: BIG-IP APM
  • Feature: Network Access (SSL VPN), Split Tunneling
  • Client: BIG-IP Edge Client for macOS

Cause

iCloud Private Relay intercepts DNS queries on macOS. Even when a VPN-scoped DNS resolver is configured (as pushed by BIG-IP APM Edge Client), iCloud Private Relay acts as the first DNS resolver — including for "scoped" queries — and only falls back to the internal (VPN) resolver if the hostname cannot be resolved from public DNS records. Since most corporate hostnames that have split-horizon DNS also have public records, iCloud Private Relay resolves them to public IPs, bypassing the VPN DNS entirely.

Answer/Recommended Actions

Immediate Workaround – Disable iCloud Private Relay:

  1. On the affected macOS device, open System Settings (or System Preferences).
  2. Navigate to Apple ID > iCloud.
  3. Locate Private Relay and toggle it Off.
  4. Reconnect to the BIG-IP APM VPN and verify that DNS now resolves internal hostnames to their corporate IP addresses.

Additional Information

  • The DNS split-tunnel feature (DNS Address Space with specific domain entries) is not fully supported for BIG-IP Edge Client on macOS. This is a known platform limitation. See K23653432: BIG-IP APM client feature matrix, specifically the "Network access resource settings and features" section — DNS split-tunnel settings are marked N (not supported) for BIG-IP Edge Client Mac.
  • The issue may appear intermittent or device-specific because iCloud Private Relay is an opt-in feature tied to an iCloud+ subscription. Devices without an active iCloud+ subscription or with Private Relay disabled will not exhibit this behavior.
  • Even on macOS versions prior to Tahoe, the DNS Address Space split-tunnel limitation exists for Edge Client. Some users may have appeared to work correctly due to other factors (e.g., no iCloud Private Relay, different DNS configurations).
  • Testing confirmed that when * is configured in DNS Address Space and iCloud Private Relay is not interfering, the VPN client correctly sends DNS queries to the corporate DNS server on macOS Tahoe (26.1, 26.4.1) with Edge Client 7270 and BIG-IP TMOS 16.1.6.1.
