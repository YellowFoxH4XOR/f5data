Description

You may find that some configuration objects on your Link Controller system are still showing Unlicensed - Not Authorized even though you've already installed the patch described in K15834 or K36385016.
For example, say you have your LC server objects and links like this:
gtm server /Common/CURRENT_LC_DEVICE {
    datacenter "/Common/DC 1"
    --snipped--
}

gtm link /Common/192.168.1.1 {
    datacenter /Common/DC_1
    monitor /Common/bigip_link
    router-addresses {
        192.168.1.1 { }
    }
}
You will find that your link status will be:
-------------------------------------------
| Gtm::Link: 192.168.1.1
-------------------------------------------
| Status               
|   Availability : unlicensed
|   State        : enabled
|   Reason       : Not authorized.
 

Environment

  • BIG-IP Link Controller
  • Multiple Links using different Data Centers
  • You see "Unlicensed - Not Authorized" while checking configuration objects like the link status, gtm server status, etc.

Cause

This is by design since Link Controller is supposed to manage local objects ONLY.

 Recommended Actions

You may use the method below to check whether you've installed the patch. 
rpm --dbpath /shared/lib/rpm -v -V linkCost
For TMOS version 12 or later, you may also need to check using: 
/opt/bin/rpm --dbpath /shared/lib/rpm -v -V linkCost
The following output indicates that the patch had been loaded as expected:
......... /shared/lib64/liblc.so
Note: to check your rpm version, simply run rpm --version or /opt/bin/rpm --version
Note: for a VIPRION system, you should use the cluster shell command instead, and the output for all the blades should have outputs like the above example if the patch is installed correctly. 
clsh rpm --dbpath /shared/lib/rpm -v -V linkCost
For TMOS version 12 or later, you may also need to check using: 
clsh /opt/bin/rpm --dbpath /shared/lib/rpm -v -V linkCost
It is recommended that you follow the article K15834 or K36385016 if there is no patch installed, and then decide whether to install the patch or not.

If you still see your configuration objects are showing Unlicensed - Not Authorized after installing the patch, please check if the configuration is in the same data center with your current Link Controller device. As explained above, Link Controller is supposed to manage local configuration objects only, for the objects not in the same datacenter, it is supposed to see an Unlicensed - Not Authorized status.

To check the datacenter for your current device and the configuration objects, you may follow this:
  1. Login to the Bash CLI of your Link Controller device.
  2. Identify your gtm server object and its datacenter for the current login device by:
tmsh list gtm server
The datacenter is at the first row of your gtm server configuration:
gtm server /Common/CURRENT_LC_DEVICE {
    datacenter "/Common/DC 1"
    --snipped--
}
  1. Check the configuration object datacenter option. For example, you can use this to check the link object:
tmsh list gtm link <link_name>
The configuration output would be like this, the below example shows a different datacenter with the above gtm server objects, "/Common/DC 1" and /Common/DC_1.
gtm link /Common/192.168.1.1 {
    datacenter /Common/DC_1
    monitor /Common/bigip_link
    router-addresses {
        192.168.1.1 { }
    }
}
  1. If you believe this link object should belong to the same datacenter as your gtm server, you may use the command below to change it:
tmsh modify gtm link 192.168.1.1 datacenter "DC 1"
then, save the configuration by: 
tmsh save sys config
