Description

You might have chance to run some command like below 

[user1@bigip1:/S1-green-P::Active:Standalone] ~ # tmsh show sys cluster

[user1@bigip1:/S1-green-P::Active:Standalone] ~ # ssl slot2

Thus both slots are not seeing each other, and partition is flapping for management access between slot1 and slot2 some reasons.
 

Environment

  • Velos
  • F5OS-C
  • Tenant
  • multiple blade
  • after one of controller's Blades is rebooted or after upgrade
     

Cause
Bug ID 950901
 

Recommended Actions

If you have not set Cluster IP for each blade, then

  1. Set the tenant to Provisioned mode
      The partition GUI:
      TENANT MANAGEMENT >> Tenants Deployments 
      Check the tenant in trouble and click Provision

        The partition CLI:
        # config
        (config)# tenants tenant <tenant_name> config running-state provisioned
        (config)# commit and-quit
         
      • Check the tenant's status
          The partition GUI: 
          TENANT MANAGEMENT >> Tenants Deployments 

            The partition CLI:
            #  show tenants tenant <tenant_name>

            and see running-state and status becomes provisionned

             state running-state Provisioned
             ...
             state status        Provisioned
             
          • Set the tenant back to Deployed mode
              The partition GUI:
              TENANT MANAGEMENT >> Tenants Deployments 
              Check the tenant in trouble and click Deploy

                The partition CLI:
                # config
                (config)# tenants tenant <tenant_name> config running-state deployed
                (config)# commit and-quit
              This should stabilize the issue if issue is due to Bug ID 950901. Please set workaround.
              If issue still persist, please contact F5 Support.

              IMPORTANT: Multiblade BIG-IP must have cluster member IP address: K14392: Configuring a cluster member IP address for all slots on a VIPRION platform

              Please set them if you have not set.
               

              If you have Cluster member IP address is set, then log in to CLI of each blade using the cluster member IP.

              tmsh show sys license | grep "Serial Number"
              Appliance Serial Number                chs599996s <<<-----[!]

              If one of the blade shows Serial Number chs599996s, then your tennant is affected to this bug. Please apply the workaround Bug ID 950901.

              Actual serial number can be found in partition CLI:

              show system licensing
              system licensing license

                                       Platform ID         F101

              Additional Information

              This issue can be encountered when one of blade is rebooted.
