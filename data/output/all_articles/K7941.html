Issue

By default, the BIG-IP ASM system blocks HTTP requests containing Illegal HTTP Format violations in order to prevent improper requests from being sent to the web server. When the BIG-IP ASM system receives an HTTP request containing an Illegal HTTP Format violation, the following message is logged to the Requests log in the Configuration utility, and the /var/log/asm log file:

Illegal HTTP format

The BIG-IP ASM system will block the request and log the Illegal HTTP Format violation when the request contains one or more of the following elements:

  • Unknown HTTP method
  • Unescaped NULL byte in the URI (For example, a NULL byte without the %xx notation.)
  • No URI in the HTTP request
  • Negative or invalid content length
  • Requests containing one of the following multipart violations, most of which will also cause a Non-RFC compliant violation:
    • First multipart boundary not found following request headers
    • Missing closing boundary
    • Chunk in multipart request is NULL

    • Max multipart chunks reached (the maximum is configurable)

    • Multipart request header does not contain boundaries
    • Multipart request header contains forbidden NULL
    • Chunk value body must contain at least CRLF (when the chunk body length is less than 2 bytes)
    • Chunk value body must end with CRLF (13, 10)
    • Multipart form-data request does not contain the Content-Disposition: name=... header
    • Multipart parameter parsing:
      • Character after = with no quotation mark
      • Character after the end of value parsing
      • Value parsing ended prematurely
  • Post data contains unescaped NULL byte
  • Requests containing one of the following HTTP chunk parsing violations:
    • Request chunks continue after last chunk
    • Could not find chunk size when expected
    • Negative chunked size
    • Wrong chunk delimiter
    • Accumulated chunked length is negative
    • Chunk larger then max request length
    • Chunk does not end with \r\n
    • Too many request chunks arrived
    • POST data of chunked request contains forbidden NULL
  • HTTP version is not supported
  • Memory failures during parsing of request
  • Illegal URI length
  • Invalid request cookie length
  • Invalid request cookie2 length
  • Number of headers in request exceeds the limit of 70
  • Some rare internal issues might also cause this violation to appear

While a few of the above violations are generated by Non-RFC compliant requests, some of the violations can also be generated as a result of an error in the web application code. If you have determined that the BIG-IP ASM system is blocking Illegal HTTP Format requests due to an error in the web application code, you can either change the code, or disable the violation using the BIG-IP ASM Configuration utility.

Disabling blocking Illegal HTTP Format requests

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Application Security > Web Applications.
  3. Click the name of the web application.
  4. From the Blocking menu, select Settings.
  5. Under the RFC Violations section, clear the Block check box for the Illegal HTTP Format violation.
  6. Click Save.
  7. Click Apply Policy.

Client requests containing Illegal HTTP Format violations will not be blocked by the BIG-IP ASM security policy; however, the alarm message will continue to be logged in the Requests log.

Note: The Policy builder utility does not resolve the Illegal HTTP Format violations.
