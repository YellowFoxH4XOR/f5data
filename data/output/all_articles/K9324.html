Known Issue

This is the result of a known issue. Under rare conditions, TMM incorrectly increments the open connection count for a FastL4 virtual server.

For example, the following bigpipe profile command output indicates that the number of open connections to the virtual server is more than 5 billion, while the number of accepted connections is 1.8 million:

PROFILE FASTL4 fastl4_test parent fastL4
| idle timeout: 60 PVA acceleration: full
| virtual servers: test_vs
| Conn (open, accept, not accept, expires) = (5294967001, 1.802M, 0, 364242)
| Errors (rx unreachable, rx bad unreachable) = (678183, 8726)
| Errors (rx packet, rx checksum, tx) = (4711, 115, 0)
| SYNcookies (issue, accept, reject) = (0, 0, 0)
| SYNcookies (server SYN rtx) = 0

F5 Networks Product Development tracked this issue as CR96915 and it was fixed in BIG-IP version 9.6.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.

This issue still exists in the BIG-IP version 9.4.x and 10.x software branches.
