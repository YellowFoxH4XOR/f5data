Known Issue

BIG-IP systems may allow you to create duplicate wildcard IPIP tunnels.

This issue occurs when the following condition is met:

  • You create more than one wildcard IPIP tunnel, with the same local IP addresses and tunnel types (DS-Lite, IPv4IPv4, IPIP, IPv4IPv6, IPv6IPv4, or IPv6IPv6).

After you create a duplicate tunnel, the mcpd process notifies the Traffic Management Microkernel (TMM) of the configuration, and TMM subsequently discards the configuration. However, the mcpd process retains the duplicate tunnel configuration, and the BIG-IP system may continuously display the duplicate configuration in the Traffic Management Shell (tmsh) and the Configuration utility.

Impact

The BIG-IP system allows duplicate tunnel configurations without validation.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to configure multiple wildcard IPIP tunnels, with the same local address, the BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the following example:
    ...
    err tmm[15027]: 01010048:3: Unable to create tunnel listener _wcard_tunnel_/Common/test-ipip-2, bind failed: ERR_USE
    err tmm1[15027]: 01010048:3: Unable to create tunnel listener _wcard_tunnel_/Common/test-ipip-2, bind failed: ERR_USE
    err tmm[15027]: 01010047:3: Could not create listener for /Common/test-ipip-2: 192.168.1.1%0, proto: 4
    err tmm1[15027]: 01010047:3: Could not create listener for /Common/test-ipip-2: 192.168.1.1%0, proto: 4
    crit tmm1[15027]: 01230064:2: Vlan /Common/test-ipip-2 not found
    crit tmm[15027]: 01230064:2: Vlan /Common/test-ipip-2 not found
    ...
  • You notice the following tmsh list /net tunnels command output displays duplicate IPIP tunnel configurations; however, TMM discards the duplicate test-ipip-2 tunnel configuration.

    For example:

    net tunnels tunnel test-ipip-1 {
    local-address 192.168.1.1
    profile ipip
    remote-address any
    }
    net tunnels tunnel test-ipip-2 {
    local-address 192.168.1.1
    profile ipip
    remote-address any
    }

Workaround

To work around this issue, you can configure wildcard tunnels with different local addresses and tunnel types.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system
