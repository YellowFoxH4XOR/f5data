Known Issue

The merged process may become unresponsive under certain conditions.

This issue occurs when all of the following conditions are met:

  • The merged.snapshots system database variable is set to true. This is the default setting.
  • Your BIG-IP system unexpectedly removes a directory from the /shared/tmstat/snapshots folder.

The merged process collects statistical data from various subsystems on the BIG-IP system at a defined interval and stores them in the corresponding /shared/tmstat/snapshots folder. This issue is triggered when the merged process attempts to input data into a snapshot folder that has been deleted from the system.

Impact

The merged process does not report the BIG-IP statistical data correctly. Additionally, the Virtual Clustered Multiprocessing (vCMP) hypervisor may not report existing vCMP guest state correctly.

Symptoms

As a result of this issue, you may encounter all of the following symptoms:

  • BIG-IP iHealth lists Heuristic H607216 on the Diagnostics > Identified > Medium screen.
  • On a vCMP hypervisor, the state of the vCMP guest does not update. For example, if the vCMP guest is set to the provisioned state, the tmsh show /vcmp guest command may still show the vCMP guest in the deployed state, even though the vCMP guest OS is already shut down. As a result, the virtual disk associated with the guest may remain in the in-use status.
  • The merged process encounters high CPU usage and may eventually hit 100 percent CPU utilization.
  • The merged process does not report the BIG-IP statistical data correctly.

Workaround

To recover from this issue, you can restart the merged process. To prevent this issue from occurring, you can disable the snapshot feature for the merged process. To do so, perform the following procedures:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Identifying the affected merged process on a chassis with more than one blade

For a chassis with multiple blades or a device with Virtual Clustered Multiprocessing (vCMP) guests, the merged process runs on each blade and on each guest. If your system is running on a chassis, you have to use the SSH protocol to get to the command line for each blade or each vCMP guest to determine which instance of the merged process is not responding. Any instance of the merged process that has a CPU utilization of over 90% for more than a few seconds is potentially in this state and you should restart the instance. To verify the CPU utilization of the merged process, enter the following command on each blade and/or each vCMP guest:

top -p `pidof merged`

Once you have determined the unresponsive instance of the merged process, proceed to the next procedure to restart the instance.

Restarting the merged process

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the merged process by typing the following command:

    restart /sys service merged

Disabling the snapshot feature for the merged process

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Disable the snapshot feature for the merged process by typing the following command:

    modify /sys db merged.snapshots value false
