Topic

You should consider using this procedure under the following condition:

  • You want to enable digital signature protection for locally stored BIG-IP log files.

Description

Starting in BIG-IP 14.1.2.8, 15.1.1, and 16.1.0 you can enable digital signature protection for locally stored BIG-IP log files. When you enable the logintegrity database variable and generate the corresponding private key, you can validate the authenticity and integrity of BIG-IP log files, including the audit logs, and ensure the logs have not been tampered with or manipulated.

To enable digital signature protection for locally stored BIG-IP log files, perform the following procedures:

  • Enable the logintegrity database variables
  • Generate a private key with the name logfile_integrity.key
  • Verify log file signatures

After you enable the logintegrity database variables and install the private key, the system generates digital signature files in the /var/log/digest directory after the log files are rotated.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the BIG-IP system's Advanced shell (bash).

Procedures

Enable the logintegrity database variables

To enable the logintegrity database variables, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Enable the logintegrity database variable by entering the following command:

    modify /sys db logintegrity.support value enable

  3. Set the logIntegrity log level database variable to debug by entering the following command:

    modify /sys db logintegrity.loglevel value debug

    Note: To set the logIntegrity log level database variable back to the default value, enter the following command:

    modify /sys db logintegrity.loglevel value error

Generate a private key with the name logfile_integrity.key

To generate the private key with the name logfile_integrity.key, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into bash.
  2. Generate a private key with the name logfile_integrity.key using the following command syntax:

    tmsh create sys crypto key logfile_integrity.key key-type <private_key_type> key-size <key_size_bytes> gen-certificate security-type <security_level> country <country> organization <organization_name> ou <organizational_unit> common-name <common_name>  lifetime <days_valid>

    For example:

    tmsh create sys crypto key logfile_integrity.key key-type rsa-private key-size 2048 gen-certificate security-type password country US organization "Example." ou "Example Team" common-name www.example.com lifetime 365

  3. Obtain the name of the keyfile that was created by performing the following procedure:
    • Change locations to the filestore location where the keyfile resides by entering the following command:

      cd /config/filestore/files_d/Common_d/certificate_key_d/

    • Search for the keyfile by entering the following command:

      ls | grep logfile_integrity.key

    • The keyfile name is system-dependent and should appear similar to the following example:

      :Common:logfile_integrity.key_12345_2

  4. Using the filename that you obtained from the previous step, create the secure key file using the following syntax:

    openssl rsa -aes256 -in <keyfile_name> -out logfile_integrity_secure.key

    For example:

    openssl rsa -aes256 -in :Common:logfile_integrity.key_12345_2 -out logfile_integrity_secure.key

  5. Enter and verify a passphrase for the keyfile.
  6. Install the keyfile into the secure vault using the following syntax:

    tmsh install sys crypto key logfile_integrity.key passphrase <passphrase> from-local-file logfile_integrity_secure.key

    For example:

    tmsh install sys crypto key logfile_integrity.key passphrase MySecurePwd from-local-file logfile_integrity_secure.key

Verify log file signatures

After you enable the logintegrity database keys and install the private key, the system generates signature files in the /var/log/digest directory after log rotation occurs. To validate the integrity of a specific BIG-IP log file, such as /var/log/audit, locate the corresponding signature file in the /var/log/digest directory and use the openssl command to validate the integrity of the log file. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash.
  2. Locate the expected signature file(s) in the /var/log/digest directory by entering the following command:

    ls -las /var/log/digest/

    For example, output from the below ls -las command confirms that signature files are present for the audit logs, audit.1 and audit.2:

    ls -las /var/log/digest/audit*
    4 -rw-------. 1 root root 256 Jul 27 09:21 /var/log/digest/audit.1.sig
    4 -rw-------. 1 root root 256 Jul 26 13:34 /var/log/digest/audit.2.sig

  3. Change to the filestore location where the certificate file resides by entering the following command:

    cd /config/filestore/files_d/Common_d/certificate_d/

  4. Search for the certificate file by entering the following command:

    ls | grep logfile_integrity.key

    The certificate filename is system-dependent and should appear similar to the following example:

    :Common:logfile_integrity.key_12345_2

  5. Use the name of the keyfile that you obtained from the previous step to generate the public key using the following syntax:

    openssl x509 -in <certificate_name> -noout -pubkey > certificatefile.pub.cer

    For example:

    openssl x509 -in :Common:logfile_integrity.key_12345_2 -noout -pubkey > certificatefile.pub.cer

  6. Verify the signature file using public key by using the following syntax:

    openssl dgst -sha256 -verify /config/filestore/files_d/Common_d/certificate_d/certificatefile.pub.cer -signature <signature_file> <log_file>

    For example, the following command verifies the integrity of the /var/log/audit.1 log file using the /var/log/digest/audit.1.sig signature file:

    openssl dgst -sha256 -verify /config/filestore/files_d/Common_d/certificate_d/certificatefile.pub.cer -signature /var/log/digest/audit.1.sig /var/log/audit.1
    • When the integrity of the log file is intact, the command output appears similar to the following:

      Verified OK

    • When the log file has been manipulated, the command output appears similar to the following:

      Verification Failure
