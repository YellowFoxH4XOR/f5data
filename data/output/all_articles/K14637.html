Known Issue

The Datagram Transport Layer Security (DTLS) virtual server configuration may cause the Traffic Management Microkernel (TMM) to core.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is running BIG-IP 11.3.0 HF6 or 11.3.0 HF7.
  • You have configured a virtual server for DTLS.
  • The virtual server has an associated Client SSL profile, and in the profile the setting for secure renegotiation is disabled.
  • A DTLS client attempts a Secure Sockets Layer (SSL) renegotiation.

Impact

Redundant devices may experience a failover, and stand-alone devices may become unavailable.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • An unexpected failover event may occur between peer devices.
  • A stand-alone device stops processing connections while TMM is restarting.
  • Messages similar to the following example are logged to the /var/log/tmm file:

    notice ** SIGSEGV **" with "RIP=0x83c6b2

  • Messages similar to the following example are logged to the /var/log/apm file:

    ** SIGABRT **

  • A TMM core file is generated in the /var/core file.

Workaround

To work around this issue, you can enable SSL renegotiation for the affected DTLS Client SSL profile. To do so, perform the following procedure:

Impact of workaround: SSL connections will be allowed to renegotiate the SSL session.

Modifying the Client SSL Profile of the DTLS virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL Client.
  3. Select the Client SSL Profile associated with the DTLS virtual server.
  4. Set the profile settings to Advanced.
  5. Select the Custom check box for Renegotiation.
  6. Select the enabled check box for Renegotiation.
  7. Click Update.
