Topic

You should consider using this procedure under all of the following conditions:

  • You deployed your BIG-IP Virtual Edition (VE) in an autoscaling group on Amazon Web Servies (AWS) using F5 AWS CloudFormation 2.0 on GitHub.
  • You want to get the current configuration of the autoscaling rolling update policy of your F5 AWS CloudFormation 2.0 stack.
  • You need to understand and configure how F5 AWS CloudFormation handles rolling updates for your BIG-IP VE instances to upgrade or update your BIG-IP system.

Description

When you deployed BIG-IP instances in an autoscaling group using F5 AWS CloudFormation 2.0, and then you want to update or upgrade them, you need to check and possibly update the UpdatePolicy attribute in the AWS autoscaling group, which specifies how F5 AWS CloudFormation handles updates. Use the following procedures to retrieve and configure your current rolling update policy.

The F5 AWS CloudFormation 2.0 templates consist of the following:
  • The parent template, which takes the name of the stack. The parent template deploys and contains links to other nested templates.
  • Nested templates, which provision network and other AWS resources required to get traffic to the BIG-IP VE.
The following example illustrates the hierarchy of templates in a F5 AWS CloudFormation stack named BigIp-Autoscale-WAF-Examplename:

Note: The number of nested templates may differ for each deployment. For example, BigIp-Autoscale-WAF-Examplename-Application-xxxxxx, which deploys an application instance, may be customized in your environment.

Parent template:
BigIp-Autoscale-WAF-Examplename

Nested templates:
BigIp-Autoscale-WAF-Examplename-Access-xxxxxx
BigIp-Autoscale-WAF-Examplename-Network-xxxxxx
BigIp-Autoscale-WAF-Examplename-Function-xxxxxx
BigIp-Autoscale-WAF-Examplename-Dag-xxxxxx
BigIp-Autoscale-WAF-Examplename-Application-xxxxxx
BigIp-Autoscale-WAF-Examplename-BigipAutoscale-xxxxxx

You find the autoscaling rolling update policy configuration in the nested template, BigIp-Autoscale-WAF-Examplename-BigipAutoscale, in the UpdatePolicy attribute. The following illustrates an example configuration:

Type: 'AWS::AutoScaling::AutoScalingGroup'

UpdatePolicy:
  AutoScalingRollingUpdate:

    MaxBatchSize: 5
    MinInstancesInService: 1
    PauseTime: PT8M

For more information on the UpdatePolicy attribute in AWS, refer to UpdatePolicy attribute in the AWS CloudFormation User Guide.

Prerequisites

You must meet one of the following prerequisites to use this procedure:

  • You have access to the AWS console and AWS Cloudshell.
  • You have your own client system.
    • You have the AWS CLI version 2 tool installed on your client system.
    • You used aws configure to configure the tool on your client system.

Procedures

Perform the following procedures to update the autoscaling rolling update policy for your F5 AWS CloudFormation 2.0 stack:

  • Get the current configuration of the autoscaling rolling update policy
    • Use the AWS Console
    • Use the aws tool on the CLI
  • Edit the autoscaling rolling update policy
  • Update the F5 AWS CloudFormation stack to apply the change
Get the current configuration of the autoscaling rolling update policy

The configuration of the the autoscaling rolling update policy in F5 AWS CloudFormation 2.0 is in the nested template <stackname>-BigipAutoscale. To retrieve the template and get the UpdatePolicy attribute, perform one of the following procedures:

Impact of procedure: Performing the following procedures should not have a negative impact on the system.

Use the AWS Console

  1. Log in to the AWS Management Console.
  2. Go to Services > CloudFormation > Stacks
  3. Select the name of the BIG-IP autoscale nested template. For example, the nested template is named the following:

    BigIp-Autoscale-WAF-examplename-BigipAutoscale-15OTGKZRP880L

  4. Select the Template tab.
  5. Search for the UpdatePolicy attribute in the template.

Use the aws tool on the CLI

  1. Log in to AWS Cloudshell or your client system with the aws tool installed.
  2. To get the BIG-IP autoscale nested template, use the following command syntax:

    aws cloudformation get-template --region <region> --stack-name <stackname>-BigipAutoscale-xxxxxx --output text

    For example, you enter the following command:

    aws cloudformation get-template --region us-east-1 --stack-name BigIp-Autoscale-WAF-examplename-BigipAutoscale-15OTGKZRP880L --output text

Edit the autoscaling rolling update policy

To configure the autoscaling rolling update policy, perform the first procedure in this article, and then do the following:

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Edit the UpdatePolicy attribute in the template for your required values.

    For more information on the UpdatePolicy attribute, refer to UpdatePolicy attribute in the AWS CloudFormation User Guide.

  2. Upload the new template to the same location referenced in the parent template, <stackname>, to replace the old template.

    To upload a template to an AWS S3 bucket, refer to Uploading objects in the Amazon Simple Storage Service (S3) User Guide.

    Note: Instead of replacing the old template, you can also upload the file with a different filename, such as bigip-autoscaleV2.yaml. When you do so, you must replace the templateURL value in the autoscale.yaml template with the new templateURL.

    In the following example, the parent template, autoscale.yaml, references the nested template file, bigip-autoscale.yaml, which is in an S3 bucket URL:

      [...]
      BigipAutoscale:
        Type: 'AWS::CloudFormation::Stack'
        Properties:
          TemplateURL:
            !Sub
            - 'https://cf-templates-xxxxxxxx-us-west-2.s3.us-west-2.amazonaws.com/bigip-autoscale.yaml'
      [...]

    In this example, you must upload the edited template to the S3 bucket URL: https://cf-templates-xxxxxxxx-us-west-2.s3.us-west-2.amazonaws.com/bigip-autoscale.yaml

Update the F5 AWS CloudFormation stack to apply the change

To update the stack, on the AWS Console, perform the following procedure:

Impact of Procedure: Depending on your update policy and the number of active BIG-IP instances in your environment, this procedure may disrupt services.

Note: You can also perform the same procedure on the CLI. For more information, refer to the Use the aws tool on the CLI procedure in K79020475: Overview of updating F5 AWS CloudFormation 2.0 stack???????

  1. Log in to the AWS Management Console.
  2. Go to Services > CloudFormation > Stacks.
  3. Select the parent template.

    This is the name of the stack.

  4. Select Update
  5. Select Next to use the Use current template option.
  6. Select Next without making any changes.
  7. Select Next
  8. Select the two check boxes to acknowledge the changes that F5 AWS CloudFormation will make.
  9. Select Update stack.
