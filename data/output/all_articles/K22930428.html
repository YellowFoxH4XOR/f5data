Description

When the In-TMM monitoring feature is enabled and an HTTPS monitor has its SSL profile set to None, the monitor does not use the default serverssl profile settings as expected.

Environment

  • In-TMM monitoring is enabled
  • Pool member monitored with a HTTPS monitor that has SSL profile set to None 

Cause

Instead of utilizing the default serverssl profile settings when SSL profile is set to None, TMM is making use of an internal profile when In-TMM monitoring is enabled and that can lead to undesirable behavior that can lead to a HTTPS monitor marking down pool members. For example, TLSv1.3 is disabled by default within the serverssl profile; however, the internal profile has TLSv1.3 enabled and it lead to this protocol being used and being incompatible for pool members, which can lead it to fail the health check and be marked down.

F5 Product Engineering is tracking this as a known issue at Bug ID 1019261.

Recommended Actions

In order to workaround this bug, you should explicitly assign a server SSL Profile to each HTTPS monitor when using In-TMM monitoring. Explicitly assigning the default serverssl profile will achieve the desired effect.
