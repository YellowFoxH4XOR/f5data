Description

A multi-bladed HA pair (including vCMP guests) needs to have a unicast mesh with cluster member management IP addresses alongside HA dedicated self IP addresses. See further details in K37361453: Configuring network failover for redundant VIPRION systems.

The communication between the HA pair looks like it is working from a tcpdump, and you can see sod messages coming and going between the clusters. However, the status for the cluster member management IP has "Error" in the Status column, and you see Warinings like below with the following command on the CLI:

tmsh show cm failover

Environment

  • VIPRION multi-bladed 
  • vCMP guest or VIPRION itself
  • v14.1.* - v16.0.*
  • HA pair (device group)
  • unicast
     

Cause

Bug ID 780857
 

Recommended Actions

Apply the workaround in Bug ID 780857, 
Run the below command on the CLI 
 
tmsh modify security firewall management-ip-rules rules add { accept_udp_1026 { place-before first ip-protocol udp destination { ports add { 1026 } } action accept } }

Then, check the connectivity with the below command and you should see "OK" for the management IP address in the status column and a non-zero count in the packet column:

tmsh show cm failover
