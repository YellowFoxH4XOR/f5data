K54335251: F5 iWorkflow system settings panel support is removed for self IP addresses, interfaces, and VLANs

Issue

In versions prior to F5 iWorklfow 2.3.0, you can use the iWorkflow Configuration utility to view and manage self IP addresses and interfaces associated with the local iWorklfow instance. You can also view and manage virtual local area network (VLAN) details. In some cases, you can use the functionality provided by these panels to connect iWorkflow to more than one network in order to communicate with additional devices.

New Behavior

Beginning in iWorkflow 2.3.0, the Self IP Addresses, Interfaces, and VLANs panels are removed from the System Settings module of the iWorkflow Configuration utility. You can create one additional interface during initial setup by clearing the option to Use Management Address for communicating with HA Cluster peers. Doing so causes iWorkflow to create a VLAN called internal, with the self IP address you provide. You must use the TMOS Shell (tmsh) to view the details of this newly created interface under the System Settings module.

Impact

Creating more than two interfaces requires tmsh access. To create a second interface and VLAN, you must use the setup wizard, which you can access using the following URL syntax in your browser:

https://<IP address>/ui/system/settings

For example, to access the setup wizard for an iWorkflow system with the IP address 192.168.1.245, type the following URL in your browser:

https://192.168.1.245/ui/system/settings

You must have tmsh access to view the newly created interfaces or existing iWorkflow VLANs, interfaces, and self IP address details.

Recommended Actions

F5 recommends that you use the management interface to communicate with the managed devices. In situations that require a secondary interface, F5 recommends that you use tmsh to define custom labels and VLANs.
