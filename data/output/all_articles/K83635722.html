Description

When applying a Transparent UDP health monitor with an alias address in a non-default route-domain, BIG-IP is not sending UDP monitor probes.

Environment

  • UDP Health Monitor
  • Transparent setting is enabled
  • Destination Alias Address is configured with an address in a non-default route-domain
  • Sample configuration below:

    ltm monitor udp transparent_alias_udp {
    adaptive disabled
    debug no
    defaults-from udp
    destination 172.16.1.1%1:domain
    interval 5
    recv none
    recv-disable none
    send "default send string"
    time-until-up 0
    timeout 16
    transparent enabled
    }

Cause

F5 Product Development Team is still investigating at the time of publish.

Recommended Actions

As a workaround, you can add a specific route including the route domain ID for the alias address in the non-default route-domain:

# tmsh create net route <name> network <alias address/netmask> gw <gateway address>

Example:

# tmsh create net route aliasaddress network 172.16.1.1%1/255.255.255.255 gw 192.168.1.1%1
