Topic

This article provides an overview of the different F5 VELOS modes of access.

Description

VELOS is a complex system consisting of the system controllers, chassis partitions and tenants and each has its own point of management. The following sections provide an overview and summary of the different ways you can use to log in to manage the VELOS system:

  • VELOS general access:

    Use this for daily system administration or troubleshooting.

  • VELOS console access:

    Use this for troubleshooting when general access is not available.

BladerootSerial console cable

On VELOS (F5OS-C), each partition has it's own root account. The root password for the blades assigned to a partition is same as the partition's root account password.

By default, the root account for a partition is locked. This means you cannot login directly as root to the partition or it's blades until the root account is explicitly unlocked and a password is set. This design is intentional for security reasons, ensuring that direct root access is not available unless specifically enabled by administrator.

Direct login as 'root' to a partition (via SSH or WebUI) is not supported.

To set the 'root' password , SSH to partition using admin user:

config 

system aaa authentication users user root config set-password password

commit

system aaa authentication users user root config last-change 18000

commit 

end

Method 1 through system controller:

  1. Log in as root to the system controller.
  2. Log in to a BIG-IP tenant console using the following command syntax:

    /usr/share/omd/kubevirt/virtctl console -n partition-${PARTITION_ID} ${TENANT_NAME}-${TENANT_INSTANCE_ID}

    For example:

    /usr/share/omd/kubevirt/virtctl console -n partition-2 examplebigip2-2

To exit the console, enter Ctrl-].

 
  • To obtain PARTITION_ID, perform the following procedure:
    1. Log in to the system controller webUI.
    2. Go to CHASSIS PARTITIONS.
    3. Verify the Partition ID.

  • To obtain the TENANT_NAME, perform the following procedure:

  1. Log in to the partition webUI.
  2. Go to TENANT MANAGEMENT > Tenant Deployments.
  • To obtain the TENANT_INSTANCE_ID, perform the following procedure:
    1. Log in to the partition CLI as admin.
    2. Display the tenant instances using the following command syntax:

      show tenants tenant <tenant_name> state instances

      For example:

      show tenants tenant examplebigip2 state instances

1Method 2 over SSH through partition:

  1. Log in to your Linux client that has access to the partition IP address.
  2. Log in to a BIG-IP tenant console using the following command syntax:

    ssh <tenant-name>@<partition-mgmt-ip> -p <700X>

    where X is the instance ID.

    For example:

    ssh bigip-tenant@10.10.10.1 -p 7001
    ssh bigip-tenant@10.10.10.1 -p 7002

    Note: You can find the tenant's instance ID(s) by running the show tenants tenant <tenant name> state instances instance instance-id command from the partition CLI.
  • To get the name of the tenant, log in to the partition webUI, and go to TENANT MANAGEMENT > Tenant Deployments.

To log in to the console for a tenant over SSH through the partition, you must unlock the tenant console user account. This user account is created when a tenant is first created and has the same name. It is expired and has no password by default. To unlock the account, perform the following procedure.

Impact of procedures: Performing the following procedures should not have a negative impact on your system. This user will have console access to the tenant over SSH through the partition.
  1. Log in to the partition CLI.
  2. Type the following command:

    config
     
  3. Set the expiry status for the user to either enabled or an expiry date (in YYYY-MM-DD format) using the following command where <username> is the tenant console user account:

    system aaa authentication users user <username> config expiry-status < YYYY-MM-DD | enabled | locked >
     
  4. Set a password for the tenant console user account by typing the following command:

    config set-password password
    Value for 'password' (<string>): ********
     
  5. To commit the change and exit, type the following command:

    commit and-quit

1When using method 2 to access the tenant console over SSH, you may observe the following error message Can't connect to websocket: x509: certificate signed by unknown authority. F5 Product Development tracked this as 997765. As a workaround, you can access the tenant's console using method 1 through the system controller.
