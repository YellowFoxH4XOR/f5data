Known Issue

Generic Routing Encapsulation (GRE) tunnel traffic may intermittently fail on the BIG-IP system.

This issue occurs when the following condition is met:

  • Your platform uses the Clustered Multiprocessing (CMP) feature.

When using GRE tunnels on a CMP-enabled BIG-IP system, the system may incorrectly remove the tunnel flow from the flow table without tearing down the tunnel. When the flow is removed, the GRE tunnel distributes SYN packets to the wrong Traffic Management Microkernel (TMM) instance, resulting in intermittent connection failures and an xfrag memory leak.

Impact

TMM memory may be exhausted, resulting in a system core. If the system is configured as part of a high availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H446701 on the Diagnostics > Identified > Medium screen.
  • GRE tunnel connections fail.
  • TMM memory is exhausted, resulting in a system core.
  • BIG-IP systems configured as part of a high availability pair fail over.
  • The sweeper is triggered, and error messages appear in the /var/log/ltm file similar to the following examples:

    tmm warning tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode activated. (166681/196096 pages)
    tmm warning tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode deactivated. (166680/196096 pages)

  • The BIG-IP system generates a TMM core file to the /shared/core directory.
