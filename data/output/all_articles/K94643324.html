K94643324: Improper PostgreSQL monitor setting cause high control plane cpu usage

Type
Support Solution
Published
2023-06-21
Updated
2025-02-07
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K94643324

Description

You may meet follow symptoms.

  • Refer K06053059 set PostgreSQL monitor, append &sslmode=allow in the database field as part of the connection string, but the count value is default 0.
  • The PostgreSQL pool member monitor status is normal.
  • The device control plane CPU usage become continue increase and will reach 100%.

Environment

  • PostgreSQL monitor
  • Control Plane CPU 

Cause

On account of network or server, when BIG-IP PostgreSQL monitor connect failed with backend sever, the failed connection will hang and unable released, the monitor connection will retry internally and will continuously use control plane CPU resource. 

Recommended Actions

To avoid this issue, please modify the database (mssql, mysql, oracle, postgresql) monitor option count value to 1 or Any positive value.
Example:
ltm monitor postgresql <monitor name> {
      app-service none
      count 1
      ...
}

This prevents the caching or reuse of network connections to the database server between BIG-IP monitor. When set the count value, BIG-IP will close the connection after the specified number of probes. For example, with a value of 1, the system keeps the connection open for one probe of this monitor, after which the system closes the connection to the database. However, each probe incurs the overhead of establishing a network connection to the database server.
