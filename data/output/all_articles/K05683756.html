Description
 

TMM process is unresponsive and triggered a failover with the following messages under /var/log/ltm and /var/log/tmm as shown below. No core files were produced and no stack traces from crashes observed.

/var/log/ltm
Dec 29 23:20:42 slot3/ warning sod[5717]: 01140029:4: HA tmm_detect_fail_t tmm fails action is failover.

/var/log/tmm
<13> Dec 29 23:12:43 slot4/ notice CDP: exceeded 1/2 timeout for slot 3
<13> Dec 29 23:14:09 slot4/ notice CDP: exceeded 1/2 timeout for slot 3
<13> Dec 29 23:20:43 slot4/ notice HA: state forced to 1, unit mask forced to 0.
<13> Dec 29 23:20:43 slot4/ notice MPI stream: connection to node 10.20.10.1 aborted for reason: TCP RST from remote system (tcp4.c:2320)

Recommended Actions

To find out the root cause collect the following information

  1. Collect the QKView of the vCMP host and guest of the HA pair. 

  2. If the issue trigger again, collect the "top" output to capture the process utilisation. 
    If the issue happens again, you can prepare in advance to collect the "top" o/p by following the below procedure.

    -----------------------------------------
    # run 'top' command from the bigip CLI (from BASH, not TMSH)
    1) Press '1' to get multiple CPU info
    2) Press 'f' to add fields
    3) Press 'j' to add the last processor used 
    4) Press 'p' to add swap size
    5) Press 'l' to add CPU time
    6) Press enter to get back and see the modified top output
    7) Press 'W' to write .toprc --------------> 'W' implies Shift + W in your keyboard
    8) Once done exit top (ctrl+c)
    9) run 'top' again, just to visually verify that the modified top output changes are saved and are shown
    10) Run a while loop script in the bigip cli to collect periodic data:
    # while true; do (date ; top -Hcbn1 ; iostat -x) >> /var/tmp/cpu_script.txt; sleep 10; done &
    -----------------------------------------

  3.  Above command will start the script in the background a specific PID number. To view the process id run the command. 
    # ps -ef | grep -i top 

  4. You should run the script until the issue happens again and collect a new set of QKViews and the /var/tmp/cpu_script.txt file.

  5. If the issue doesn't happen in the next 24 hours stop the script by sending the kill command.  
    # kill -9  <pid>

  6. Delete the file /var/tmp/cpu_script.txt from BIG-IP to avoid disk space utilisation.
    # rm /var/tmp/cpu_script.txt  
    Note: It's important to delete the file regularly so it won't grow too big.

  7. Start the script again as suggested in Step2, point #10.
