Description

When a failover in Azure cloud is triggered, the failover fails and floating addresses are not associated with the new Active device.

You may see the following error in Azure Portal's Activity Log after the failed failover attempt:

[{"code":"DuplicateResourceName","message":"Resource /subscriptions//resourceGroups//providers/Microsoft.Network/networkInterfaces/ has two child resources with the same name (xxxxxxxxxx)."}]}

On older installations deployed via BIG-IP Cloud Solution Templates v1 (CSTv1) and which have not yet been updated to Cloud Failover Extensions, you will also see the above error message in /var/log/cloud/azure/failover.log.

Environment

  • Failover

Cause

This issue is caused by BIG-IP sending a request to Azure API with duplicate configuration.

BIG-IP discovers the ipConfiguration objects to send for failover from two places: the failover status file and by querying Azure for matching IPs and tags. 

Recommended Actions

To resolve the issue, you must double check that a duplicate object does not exist in the Azure portal for the referenced ipConfiguration and then clear the failover status file from Azure blob storage.

On installations using Cloud Failover Extensions, you may initiate a reset of the failover status file with the following API call issued on an affected BIG-IP:

curl -su admin: -X POST -d '{"resetStateFile":true}' http://localhost:8100/mgmt/shared/cloud-failover/reset | jq .

On older installations deployed via CST v1 and which have not yet been upgraded to CFE, you must clear the failover status file in the Azure Portal:

  1. Search for the storage account ending with 'data000'
  2. Go to containers, "failover" container
  3. Delete statusdb file  

Note: F5 BIG-IP Cloud Solution Templates v1 (CSTv1) have reached their End of Life (EoL) and have been replaced by our next-generation templates available in the Cloud Templates 2.0 GitHub repo. We recommend you adopt the next-generation templates for new deployments and update existing deployments to the Cloud Failover Extension as soon as is feasible.
