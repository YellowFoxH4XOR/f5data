Description

When the port of a virtual server is different from its pool members', the source port of the serverside connections are not preserved.

For example:

A virtual server uses port 443, and its pool member uses port 80, with the default source port set to preserve.

ltm virtual /Common/my_https_vs {
    destination /Common/10.10.10.50:443
    ip-protocol tcp
    pool /Common/my_http_pool
    source-address-translation { type automap }
}
ltm pool /Common/my_http_pool {
    members {
        /Common/10.20.20.100:80 {
            address 10.20.20.100
        }
}

When a client connects using the source port 10000, the serverside connection in this example changes the source port to port 63121.

clientside connection:  IP 10.10.10.200.10000 > 10.10.10.50.443: Flags [S]
serverside connection:  IP 10.20.20.50.63121 > 10.20.20.100.80: Flags [S]


In comparison, a virtual server that uses the same port as the pool member does not change the serverside connection's source port.

ltm virtual /Common/my_http_vs2 {
    destination /Common/10.10.10.50:80
    ip-protocol tcp
    pool /Common/my_http_pool
    source-address-translation { type automap }
}
ltm pool /Common/my_http_pool {
    members {
        /Common/10.20.20.100:80 {
            address 10.20.20.100
        }
}

When a client connects using the source port 10000, the serverside connection in this example preserves the source port.

clientside connection:  IP 10.10.10.200.10000 > 10.10.10.50.80: Flags [S]
serverside connection:  IP 10.20.20.50.10000 > 10.20.20.100.80: Flags [S]


Environment

  • BIG-IP
  • Virtual server with default Source Port setting (Preserve)


Cause

This is functioning as designed.

The BIG-IP changes the serverside source port to ensure return traffic is hashed back to the same TMM. When the virtual server and pool member ports are different, depending on the hash algorithm, the serverside IP/port return traffic is likely to be hashed to other TMMs unless the source port is changed accordingly.
 

Recommended Actions

Most applications work fine with source port changes, so for typical applications no changes are necessary.
Note: Source port changes by the BIG-IP may exacerbate packet drops caused by long server TIME-WAIT states.

However, if your application requires the source port to be preserved, you may consider any of the following options:
  • Set virtual server source port to preserve-strict.
    Disadvantage: return traffic will return to other TMMs, reducing performance.
     
  • Set virtual server source port to preserve, but use the same virtual server port and pool member port.
    For example, use :443 for the virtual, and also :443 for the pool member.
    Disadvantage: either virtual servers or pool member servers may need to be reconfigured.
     
  • Set virtual server source port to preserve, and use a different VLAN CMP hash configuration.
    For example, use src-ip on the clientside VLAN and dst-ip cmp hash on the serverside VLAN:

    net vlan /Common/external {
        cmp-hash src-ip
    }
    net vlan /Common/internal {
        cmp-hash dst-ip
    }

    Disadvantage: this will apply globally to all traffic to/from those VLANs.
