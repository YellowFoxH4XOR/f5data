Known Issue

A virtual server may not be demoted from Clustered Multiprocessing (CMP), as expected, when it uses an iRule referencing a global variable.

This issue occurs when all of the following conditions are met:

  • An iRule applied to a virtual server sets a Tcl global variable.
  • A second iRule reads this global variable, but does not set any other global variables.
  • The second iRule is applied to a different virtual server, which has no other iRules associated with it that set a global variable.

The following examples demonstrate this issue:

  • Setting a global variable

rule set_rule_global {

when RULE_INIT {
set ::debug 1
}
}

  • An iRule being read

rule read_rule_global {
when HTTP_REQUEST {
if { $::debug != 0 } {
log local0. "Got HTTP request: ; [HTTP::uri]"
}
}
}

Each of these iRules is attached to a different virtual server. The virtual server associated with iRule set_rule_global, which sets the variable, is correctly demoted from CMP and processes traffic on only tmm0. The virtual server associated with iRule read_rule_global, which only reads the variable, is erroneously not demoted from CMP. As a result, on a four core BIG-IP system, traffic associated with the read_rule_global virtual server would be processed on all processors using tmm0, tmm1, tmm2, and tmm3, while the traffic associated with set_rule_global is processed on only tmm0. Since global variables are accessible only from within the context of the Traffic Management Microkernel (TMM) process where they were set, the read_rule_global iRule will fail when traffic is processed on any TMM except tmm0.

Impact

The BIG-IP system may incorrectly terminate connections traversing TMM instances other than tmm0.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H638394-24 on the Diagnostics > Identified > High screen.
  • You notice errors in the /var/log/ltm file on all TMM instances, except tmm0, that appear similar to the following example:

    can't read "::variable_name": no such variable

  • Some connections traversing TMM instances other than tmm0 may be prematurely terminated with an RST packet.

Workaround

The preferred workaround for this issue is to modify your iRule to use CMP-compliant alternatives to global variables. Alternatively, you can manually demote your virtual server from CMP. To do so, perform the following procedures:

Using a CMP-compliant alternative to Tcl global variables

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Refer to K13033: Constructing CMP compatible iRules.

Manually demoting a virtual server from CMP (10.1.x and later)

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To enter the virtual server subsection of the tmsh utility, type the following command:

    ltm virtual

  3. To demote a virtual server from CMP, use the following command syntax:

    modify <virtual-server-name> cmp-enabled no

    Replace <virtual-server-name> with the name of your virtual server.

    For example:

    modify testhttpvirtual cmp-enabled no

  4. To check the CMP status of a virtual server while in the virtual server subsection of the tmsh utility, use the following command syntax:

    show <virtual-server-name> all-properties

    Replace <virtual-server-name> with the name of your virtual server.

    For example:

    show testhttpvirtual all-properties

  5. Save the changes by typing the following command:

    save /sys config

Manually demoting a virtual server from CMP (10.0.x)

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. Use the following command syntax:

    bigpipe virtual <virtual-server-name> cmp <disable/enable>

    For example, to disable CMP mode for the virtual server named testhttpvirtual, type the following command:

    bigpipe virtual testhttpvirtual cmp disable

  3. To save the changes you made to the virtual server, type the following command:

    bigpipe save

  4. To check the SMP status of a virtual server, use the following command syntax:

    bigpipe virtual <virtual_server_name> cmp mode show

    For example:

    bigpipe virtual testhttpvirtual cmp mode show

    Output showing an SMP mode of single, disable, or none indicates that this virtual server has been demoted from CMP.
