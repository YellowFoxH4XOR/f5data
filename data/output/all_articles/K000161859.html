K000161859: Configuration validation failure after upgrade: /Common/clientssl-legacy cannot contain more than one set of same certificate/key type on BIG-IP

Published
2026-06-23

Applies to

  • BIG-IP LTM: 21.1.X, 21.1.0
Source

Description

After upgrading BIG-IP LTM from version 21.0 to 21.1.0, configuration fails to load with the following error messages:

010717e1:3: Client SSL profile (/Common/clientssl-legacy): cannot contain more than one set of same certificate/key type.

Unexpected Error: Validating configuration process failed.

Additional warnings include deprecated compliance objects in protocol inspection and log-setting attachment advisories.

Environment

  • Product: BIG-IP LTM (Version 21.1.0)
  • Configuration: Client SSL profile (/Common/clientssl-legacy) with cert-key chain entry using default_0 instead of default
  • Recent Action: Upgrade from BIG-IP 21.0 to 21.1.0

Cause

The configuration file for the client SSL profile contained more than one set of the same certificate/key type, specifically using default_0 instead of default in the cert-key chain causes configuration validation to fail.

Answer/Recommended Actions

To resolve the configuration validation failure:

  1. Validate the Problematic Entry
    Run: grep -n 'default_0' /config/bigip.conf to locate the faulty cert-key chain.
  2. Backup the Configuration
    Run: cp /config/bigip.conf /config/bigip.conf.bak.$(date +%Y%m%d%H%M%S)
  3. Replace Faulty Entry
    Run: sed -i 's/default_0/default/g' /config/bigip.conf
  4. Validate the Change
    Run: grep -n 'default_0' /config/bigip.conf (should return nothing if replacement succeeded)
  5. Verify Configuration
    Run: tmsh load sys config verify
  6. Load Configuration
    Run: tmsh load sys config

For VELOS/VIPRION (primary slot):
Prefix commands with clsh (e.g., clsh grep -n 'default_0' /config/bigip.conf).

Additional Recommendations:

  • The same issue is expected on the other device in the HA pair.
