Topic

This article describes the authentication changes in F5 iHealth and what you should do to continue using the service. This new approach represents a significant change from the existing iHealth API authentication mechanism, requiring changes to the iHealth application and the creation of a new API token service.

Note: With the change to OAuth2-based authentication in iHealth, you may not be able to upload QKview file directly from BIG-IP devices. For more information, refer to: K000134919: Error message when uploading QKView from BIG-IP and Bug ID 1225789: The iHealth API is transitioning from SSODB to OKTA.

Description

In March 2023, the F5 iHealth team released new iHealth, which is iHealth with a new identity and authentication provider. When you access iHealth for the first time and are already logged in to MyF5 you are automatically logged in to iHealth. If you are not logged in to MyF5 but have an account, you can log in to iHealth with your MyF5 credentials. If you have not yet accessed MyF5, you need to create a new account as described in the following section.

How to sign up for a new account

When you go to iHealth.f5.com, you are automatically directed to the following login page. To sign up for a new account, select Sign up.

Until June 2023, old iHealth and new iHealth will exist side by side and share QKViews between both systems so as not to disrupt service request case resolution and self-service troubleshooting. By June 2023, all users should have a new account for new iHealth created and API users of iHealth should have generated an API token so they can continue to use iHealth APIs.
