Description

TCP connections can be established to a virtual server that is down or unavailable.Environment

  • BIG-IP
  • Standard Virtual server Offline
  • TCP 3-way handshake
  • Pool State or virtual server state
    • K000159991: Virtual Server TCP connection behavior based on the pool or the virtual server state.

Cause

This is expected behavior.Recommended Actions

If the need were to arise where this functionality is unacceptable there are 2 ways to handle it:

1) Create a custom TCP profile:
Consider enabling the Verified Accept option if you would like the BIG-IP to send a reset packet in response to a new TCP connection when a virtual server is unavailable.

When the Verified Accept option is enabled, the BIG-IP verifies that the pool member is available to accept the connection by sending the server a SYN before responding to the client's SYN with a SYN-ACK; enabling this option causes a server-side load balancing decision to be made before the client-side connection setup has completed when the virtual server is available.

To enable the Verified Accept option, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > TCP.
  3. Click Create to create a new profile.
  4. Provide a name for the profile.
  5. Select the Custom check box next to Verified Accept.
  6. Select the check box next to Verified Accept to enable it for the profile.
  7. Configure the other TCP profile options as appropriate for your configuration. (Fast Open must be disabled as it is not compatible with Verified Accept)
  8. Click Finished to complete creating the profile.
  9. Apply the profile to the virtual server.

2) Within the specific virtual server enable Immediate Action On Service Down. It specifies the immediate action the BIG-IP system should respond with upon the receipt of the initial client's SYN packet, if the availability status of the virtual server is Offline or Unavailable. There are 3 settings:

  • None: Specifies that the system takes no immediate action if the virtual server is reported Offline or Unavailable (default).

  • Reset: Specifies that the system resets the connections when the virtual server is reported Offline or Unavailable.

  • Drop: Specifies that the system drops the connections when the virtual server is reported Offline or Unavailable.

To enable Immediate Action On Service Down perform the following procedure:

  1. Log into the Configuration Utility.
  2. Navigate to Local Traffic  ››  Virtual Servers : Virtual Server List  ›› <virtual server>
  3. In the Configuration section of the virtual server change Basic to Advanced.
  4. Scroll down to Immediate Action On Service Down.
  5. In the dropdown change the setting to whatever best suits network needs.
  6. At the bottom click Update and sync.

Note: in either case please test prior to implementation.

Additional Information

By default, the virtual address object associated with the virtual server responds to address resolution protocol (ARP) requests from the client even if the virtual server is disabled. The virtual server allows TCP connections to be established when certain configuration options are in place. For example, iRules executing code based on the LB_FAILED event.

When a virtual server is unavailable, connection setup will look like this example:

4 17.812063 0.001019 4093 10.10.10.1 → 10.10.10.80 52 36134 80 TCP IN s1/tmm1 : 36134 → 80 [ACK] Seq=1 Ack=1 Win=29200 Len=0 TSval=1449811034 TSecr=2029761799
5 17.812432 0.000369 4093 10.10.10.80 → 10.10.10.1 40 80 36134 TCP OUT s1/tmm1 : 80 → 36134 [RST, ACK] Seq=1 Ack=1 Win=0 Len=0 [F5RST: No pool member available]

When Verified Accept is enabled, connection setup looks like this example:

2 8.111554 0.000448 4093 10.10.10.1 → 10.10.10.80 60 36148 80 TCP IN s1/tmm1 : 36148 → 80 [SYN] Seq=0 Win=29200 Len=0 MSS=1460 SACK_PERM=1 TSval=1450138080 TSecr=0 WS=128
3 8.111875 0.000321 4093 10.10.10.80 → 10.10.10.1 40 80 36148 TCP OUT s1/tmm1 : 80 → 36148 [RST, ACK] Seq=1 Ack=1 Win=0 Len=0 [F5RST: No pool member available]

The Verified Accept option verifies that the system can actually communicate with the server before establishing a client connection. If a virtual server is down, all servers or pool members are considered unavailable for communication, and results in an immediate TCP reset. By default, this setting is disabled.
