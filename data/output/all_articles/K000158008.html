Description

OpenShift cluster install is failing to progress.

Repeated messages similar to the following are observed in /var/log/openshift.log:

fatal: [controller-1.chassis.local]: FAILED! => {"changed": false, "msg": "Unable to start service origin-node: Job for origin-node.service failed because the control process exited with error code. See \"systemctl status origin-node.service\" and \"journalctl -xe\" for details.\n"}

InstallProgress: Execution for play book MasterInstall is Failed
Ansible Failed /usr/bin/ansible-playbook -vv --flush-cache -i /tmp/omd/etc_ansible_cluster_install /usr/share/ansible/openshift-ansible/playbooks/prerequisites.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-checks/pre-install.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-node/bootstrap.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-etcd/config.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-master/config.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-master/additional_config.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-node/join.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-hosted/config.yml /usr/share/ansible/openshift-ansible/playbooks/openshift-service-catalog/config.yml

The output of journalctl -b -u origin-node.service on the controller where the failure is reported (controller-1 in the above example) shows repeated entries similar to the following:

systemd[1]: Starting origin-node.service...
origin-node[812]: time="2025-11-17T17:35:01+05:30" level=error msg="container with id exists: origin-node"
origin-node[812]: container with id exists: origin-node
systemd[1]: origin-node.service: main process exited, code=exited, status=1/FAILURE

Environment

  • OpenShift cluster install
  • OpenShift logs

Cause

This problem is happening when the origin-node.service tries to start the origin-node container, but a stale container already exists with the same name.

Bug ID 2182081 tracks this issue.

Recommended Actions

On the controller where the origin-node container is failing to launch, execute the following commands from bash:

runc --systemd-cgroup kill origin-node KILL
runc --systemd-cgroup delete origin-node

Note: This may need to be done on both controllers in some cases. The kill command may return container not running, but it is fine to proceed to the delete command in that case.

Monitor the /var/log/openshift.log on the active controller to determine whether the cluster install is progressing:

tail -F /var/log/openshift.log

If the problem continues to occur, open a case with F5 Support for further investigation.
