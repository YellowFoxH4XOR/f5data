Known Issue

Using the WEBSSO::select command with no argument may cause the Traffic Management Microkernel (TMM) to exit and restart.

This issue occurs when all of the following conditions are met:

  • You have configured a local traffic policy with a Tool Command Language (Tcl) expression and associated it with a virtual server.
  • The Tcl expression uses the WEBSSO::select iRule command with no argument specified.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high-availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system generates a TMM core file to the /shared/core/ directory.
  • The BIG-IP system fails over to the standby system if configured for HA.
  • The BIG-IP system resets connections to the affected virtual server.

Workaround

To work around this issue, you can ensure all instances of the WEBSSO::select command in the local traffic policy specify a single sign-on (SSO) configuration object as an argument. For more information about using the WEBSSO::select iRule command, refer to the WEBSSO::select page on F5 Cloud Docs.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
