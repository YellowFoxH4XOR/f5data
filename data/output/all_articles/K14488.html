Topic

This article includes recommendations for when to use a default profile on the BIG-IP system and when to create a custom profile using the default profile as the parent.

Description

The BIG-IP software contains a configuration tool called profiles. A profile is an object that allows you to customize the behavior of certain types of network traffic to suit the needs of your environment. When you associate a profile with a virtual server, you can use a default profile or a custom profile.

Default profiles

The BIG-IP system includes at least one default profile for each profile type. A default profile is a system-supplied profile that contains recommended baseline values that are suitable for many environments. Default profiles have the following properties:

  • You can use default profiles as-is, and assign them directly to a virtual server.
  • You can use default profiles as a parent for custom profiles; you can create a custom profile that is based on the default profile, and then change any value for the custom profile to suit the needs of your environment.
  • Some default profiles, such as the TCP profile, are read-only and cannot be modified.

Custom profiles

To create a custom profile, you can use the default profile or another custom profile as the parent. You can use a custom profile for the following purposes:

  • You can modify some or all of the custom profile values to suit the needs of your environment.
  • You can create a custom profile that uses another custom profile as the parent.
  • Child profiles inherit any changes that you make to a parent profile setting, unless you change the setting or you select the Custom box in the child profile.
  • You can configure custom profiles to synchronize between redundant BIG-IP systems.

After you create a profile for a specific type of traffic, you can implement the profile by associating that profile with one or more virtual servers.

Recommendations

When managing BIG-IP profiles, you should consider the following information:

  • F5 recommends that you do not modify the default profiles for the following reasons:
     
    • The default profile types contain a recommended baseline from which an implementation starts; if you change the default profile values, the baseline settings may be difficult to recover.
    • Certain default profiles, such as the TCP profile, are read-only and cannot be modified.
  • Instead of modifying a default profile, you can create a custom profile using the default profile as the parent profile. Then you can modify some or all of the values defined in that profile, leaving the parent profile settings at their default values.
  • When you deploy an application, start with a default profile for the initial deployment. Then you can evaluate the application performance, create a custom profile, and change the custom profile settings as needed.
  • To prevent a custom profile from inheriting changes made to the parent profile, you can select the Custom box in the Settings section of the custom profile.
