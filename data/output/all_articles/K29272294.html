K29272294: BIG-IQ is no longer able to authenticate to a managed device with ''SSO ON'' for Smart Card Authentication

Type
Support Solution
Published
2022-04-07
Updated
2023-02-21
Applies to
  • BIG-IQ
  • BIG-IP Platforms
  • BIG-IQ Centralized Management: 8.X.X, 7.X.X, 6.X.X
Source
https://my.f5.com/manage/s/article/K29272294

Description

  • You want to access the BIG-IP Configuration utility using passwordless SSL client certificate authentication.
    K30030586: Accessing the Configuration utility using passwordless SSL client certificate authentication
  • Manage an existing BIG-IP or discover a new BIG-IP to be managed fails with the following message:
    /var/log/restjavad.0.log
    [ERROR][<TIMESTAMP>][/cm/global/tasks/device-trust/<device-trust-id>/worker BigIPTrustTaskWorker]Could not verify IP address x.x.x.x.  Please see the logs for more information.

Environment

  • BIG-IQ
  • Discover or manage a BIG-IP configured to use passwordless SSL client certificate authentication
  • BIG-IP v14.x or newer
How to tell if the managed device has SSO ON:

# tmsh modify auth cert-ldap system-auth sso on
sys db systemauth.source {
    default-value "local"
    scf-config "false"
    value "cert-ldap"
    value-range "activedirectory apm-auth cert-ldap ldap local radius tacacs"
}

/config/bigip.conf 
auth cert-ldap /Common/system-auth {
    bind-dn CN=<CertCommonName>
    bind-pw ***scrubbed***
    login-attribute userPrincipalName
    login-filter [a-zA-Z0-9]\\\\w*(\\\?=@)
    login-name CN
    port 636
    search-base-dn <Base DN to start search from>
    servers { <IP> }
    ssl enabled
    ssl-ca-cert-file /Common/hp_bundle
    ssl-cname-field san-other
    ssl-cname-otheroid 1.3.6.1.4.1.311.20.2.3
    sso on 
}

    Cause

    Known issue: ID1087749
    This is a new identified issue at the time of writing, there is no publicly facing documentation at this time. 

    When Remote ClientCert LDAP is enabled on BIG-IP, SSO by default is enabled as well. When SSO is enabled, BIG-IP performs remote authentication on BIG-IQ provided "admin" credentials and when it fails, the discovery process halts.  This will be evident in a packet capture for the SSL handshake failing between the BIG-IQ and BIG-IP. The re-negotiation phase fails when BIG-IP was expecting a client cert.
    ========================================================================================
    Example:
    httpd[xxx]: [ssl:error] [pid xxx] [client x.x.x.x:58666]: Re-negotiation handshake failed, referer: http://localhost:8100/cm/global/utility/bigip-device-check
    httpd[xxx]: [ssl:error] [pid xxx] SSL Library Error: error:140890C7:SSL routines:ssl3_get_client_certificate:peer did not return a certificate
    ========================================================================================

    In an older releases of BIG-IP (i.e. v13.1.x), the issue did not surface as the "admin" credentials were locally authenticated instead of remotely authenticated.

    Recommended Actions

    1. Validate network communication on ports 22 and 443 is working bi-directionally, you can use telnet to test.
    2. Validate if local admin account is configured on BIG-IP

    Workaround: 

    1. Backup the /etc/httpd/conf.d/ssl.conf
    # cp /etc/httpd/conf.d/ssl.conf /etc/httpd/conf.d/ssl.conf_backup

    2. Edit /etc/httpd/conf.d/ssl.conf
    # vi /etc/httpd/conf.d/ssl.conf

       Search for 'LocationMatch', then add the following content inside the LocationMatch tag.
       ================
       Default 
       ================
       <LocationMatch "^[/][^/]+[/]">
           SSLVerifyClient require
       </LocationMatch>

       ================================================================================
       New changes for a workaround to provide privilege to only the BIG-IQ IP Address
       ================================================================================
       <LocationMatch "^[/][^/]+[/]">
          <If "%{REMOTE_ADDR} == '10.0.0.1'">
             SSLVerifyClient optional
          </If>
          <Else>
             SSLVerifyClient require
          </Else>
       </LocationMatch>

       Note: 10.0.0.1 is an example of a BIG-IQ IP Address. Please modify accordingly.

    3. Restart httpd for changes to take effect.
       # bigstart restart httpd

    Important: /etc/httpd/conf.d/ssl.conf will get overridden if modified with any of cert-ldap settings through GUI/TMSH. This means you will have to re-perform this workaround again.
