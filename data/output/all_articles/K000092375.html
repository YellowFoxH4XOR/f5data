Description

NGINX Controller becomes inaccessible

Status reports the following: 

$ ./helper.sh controller status
Kubelet server certs will expire soon. Please refer to https://docs.nginx.com/nginx-controller/releases/adc/adc-release-notes-3.20/ to renew these certs
ERROR: No services are deployed. NGINX Controller is not installed.

Running a kubectl command fails with the following error:

$ kubectl get pods
The connection to the server <host>:6443 was refused - did you specify the right host or port?

In container logs, such as kubeapi-server, there are error messages similar to the following:

The kubernetes certificates are expired:

 Environment

NGINX Controller

 Cause

The kubernetes certificate has expired

 Recommended Actions

Renew the kubernetes certificate by running the following commands one at a time:

$ sudo systemctl stop kubelet

$ sudo kubeadm alpha certs renew all

$ cd to the home directory of the user who installed NGINX Controller.

$ mv .kube/config .kube/config.old

$ sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config

$ sudo chown $(id -u):$(id -g) $HOME/.kube/config

$ sudo chmod 777 $HOME/.kube/config

$ export KUBECONFIG=.kube/config

$ sudo shutdown now -r

Note: if you have a multi-node NGINX Controller cluster, run the above commands on each node in your cluster

After the cluster certificates are updated, check the certificates which are installed as kubernetes secrets as part of the product.

cd /var/lib/kubelet/pki
./checkcerts.sh

        server cert: notAfter=Oct 31 03:05:31 2024 GMT
analytics-mgr-certs-c969c82hb5
        client cert: notAfter=Oct 31 03:05:32 2024 GMT
        server cert: notAfter=Oct 31 03:05:30 2024 GMT

..more


Check the NotAfter date.

If these certificates are expired or near expiry, run ./update.sh from the installation files,  /controller-installer    directory.
This will update the device to the same version, with the effect that these certificates will be renewed.
This will not affect the device settings.

You may see messages like:

W0304 00:13:38.871876 1594252 helpers.go:553] --dry-run is deprecated and can be replaced with --dry-run=client.

And an error similar to the following is displayed when starting NGINX Controller:

Resolving conflicts and restarting the analytics database before running the update. statefulset.apps/clickhouse patched




These messages can be ignored. 


Additional Information


For kubernetes and kubelet certificate troubleshooting see article K000092449


In version 3.22.9, the internal certificates are valid for 2 years by default.
