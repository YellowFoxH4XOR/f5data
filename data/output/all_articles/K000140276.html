K000140276: Brute Force Prevention feature with CAPTCHA not working as expected

Type
Support Solution
Published
2024-07-08
Updated
2024-07-08
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000140276

Description

You have configure ASM Brute Force Attack Mitigation, but ASM does not POST the correct data back to the pool member after correctly displaying the Captcha page.

Environment

BIG-IP ASM

Login Page that uses multipart/formdata 

Cause

ASM Captcha does not support forms that use multipart/formdata (Content-Disposition: form-data)

Recommended Action

This issue is tracked as ID667786.

The only way to workaround this issue, is to have a simple form first, for which the Captcha correctly, followed by the form that uses multipart/formdata that does not trigger Captcha
