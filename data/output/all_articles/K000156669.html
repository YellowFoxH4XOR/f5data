Description

When configuring a Virtual Server on BIG-IP LTM to use an Address List as the destination address, traffic may not be matched or processed as expected. This issue occurs specifically when the Address List contains IP addresses associated with a non-default route domain. No error messages are displayed, but traffic (such as ICMP or TCP) fails to match the virtual server when the Address List is used, while matching works correctly when a single IP or subnet is specified.

Environment

  • Address List
  • Virtual Server

Cause

A known issue (Bug ID 1080985) causes the route domain ID specified in the Address List to not take effect on the virtual server IP when configured via the traffic-matching-criteria (TMC) object. As a result, the virtual server does not match traffic destined for addresses in the Address List if those addresses are in a non-default route domain.

Recommended Actions

To resolve this issue, manually configure the route domain on the traffic-matching-criteria object associated with the virtual server. Use these steps:

  1. Identify the traffic-matching-criteria (TMC) object assigned to your virtual server.
  2. Run:
    tmsh modify ltm traffic-matching-criteria <TMC object name> route-domain <route-domain>
    tmsh save sys config
    Example:

    tmsh modify ltm traffic-matching-criteria my-tmc-object route-domain rd-cd-dc4

    tmsh save sys config

  3. After applying this configuration, traffic should match and process through your forwarding virtual server as expected.
