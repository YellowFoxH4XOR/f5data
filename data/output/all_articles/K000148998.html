Description

Cisco ISE authentication does not work when BIG-IP is configured to use the virtual server for handling RADIUS authentication requests over UDP protocol. ISE reports a timeout while exchanging the certificate.

Environment

  • BIG-IP
  • RADIUS UDP virtual server (UDP profile for a pool)
  • Cisco ISE authentication

Cause

The problem is caused by unusual use of IP fragmentation, where the size of a non-final fragmented piece is lower than 552 bytes. The default minimal fragmented packet size for a non-final fragment piece is defined as BigDB variable tm.minipfragsize.

In IP fragmentation, each fragment piece has the IP "more fragments" (mf) header flag set to true (1), and the final fragment piece set to 0.  This can be seen in wireshark with the filter "ip.flags.mf==1" 

IP fragments are typically transmitted as one or more full-length datagrams, followed by a smaller final piece.  The Cisco ISE server does not follow this pattern, and instead sends a large piece, followed by one or more small non-final fragment pieces, followed by the final fragment, causing tmm to drop the non-final fragments

Recommended Actions

If your network carries legitimate IP packets that have non-final fragment pieces with an IP length value lower than the value in the Tm.MinIPFragSize (default 552 bytes) db key, then you should configure the db key to accommodate those packets. You can calculate specific value required by inspecting the IP length field in a packet capture that demonstrates the issue, or just set it to 1, to allow non-final IP fragment pieces of any length.

For example, to change the value to 64, follow the steps below:

1.     Log in to CLI
2.     Execute a command: tmsh modify sys db tm.minipfragsize value 64

 

Important:

  • The change takes effect immediately, without requiring a system restart or configuration reload.
  • Lowering the value may expose the system to IP Fragment Too Small or IP Fragmentation exploits.
  • Exposing the system to denial-of-service (DoS) attacks.
  • Consider changing the default IP fragment size setting only if the system is dropping packets smaller than the default IP fragment size.
  • The tm.minipfragsize variable affects packets with the More Fragments (MF) flag set to 1.
