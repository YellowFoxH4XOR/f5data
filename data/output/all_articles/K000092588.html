K000092588: Diameter flag proxyable bit unset in SDC response when the request has proxyable bit set

Type
Support Solution
Published
2022-11-26
Updated
2022-11-26
Source
https://my.f5.com/manage/s/article/K000092588

Description

  • Client peer message request with a P flag match a pre routing transformation script
  • Server peer that handle this message is down/unreachable or disabled
  • When the target server peer is down and the request contains the P flag and it is using a pre-routing transformation script, then the answer returns without the P flag.

Environment

  • SDC 5.1
  • Pre Routing Transformation Script

Cause

When the CPF sends an error answer it copies the original request. The bug is that when it copies the transformed incoming request it does not copy the P flag. As a result, the answer does not have this flag as well.

 Recommended Actions

This bug is fixed in CF-31.

Additional Information

None.
