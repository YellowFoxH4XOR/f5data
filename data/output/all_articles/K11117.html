K11117: The BIG-IP WebAccelerator may add headers to the body of 302 responses that have a Content Length of 0 (zero)

Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator may add more headers to 302 responses from the originating web server that initially had a Content-Length of 0 (zero), when the matching policy node has the Enable Content Assembly on Proxies option deselected for the policy. This behavior may cause some browsers to incorrectly associate the second set of headers with another request, causing undesired behavior or errors when you attempt to access a site through the BIG-IP WebAccelerator system.

Note: The Enable Content Assembly on Proxies option is available under the Acceleration Rules > Assembly page of the policy. The Enable Content Assembly on Proxies option is already enabled for most predefined policies; however, some policies such as Media, Other Binary, and Unclassified are not. Custom policies might not, by default, have this option enabled, it depends on whether the option was inherited from a parent policy in which it was already enabled.

F5 Product Development tracked this issue as CR127917 and it was fixed in BIG-IP WebAccelerator 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

If you are unable to upgrade, you can prevent this behavior by performing the following workarounds:

  • Create and apply an iRule to add some content to a 302 response that has none
  • Configure a custom node within the BIG-IP WebAccelerator policy that matches the specific 302 requests and has the Enable Content Assembly on Proxies option enabled

Creating and applying an iRule to add content to a 302 response that does not contain content

Creating an iRule that will intercept and add some content to an HTTP 302 response that does not contain content will prevent the BIG-IP WebAccelerator system from adding additional header content to the body.

Note: For information about creating and applying iRules to a virtual server, refer to the Configuration Guide for BIG-IP Local Traffic Management.

Example iRule:

when HTTP_RESPONSE {
    if { [HTTP::status] == 302 and [HTTP::header value Content-Length] == 0 } {
        set location [HTTP::header "Location"]
        HTTP::payload replace 0 0 "<html><body>Page is redirected <a href='$location'>here</a></body></html>\r\n"
    }
}

Configuring a custom node within the BIG-IP WebAccelerator policy that matches the specific 302 requests and has the 'Enable Content Assembly on Proxies' option enabled

Note: For information about creating and modifying nodes and policies, refer to the Policy Management Guide for the BIG-IP WebAccelerator System.

  1. Add a new node to the BIG-IP WebAccelerator policy that matches the affected request.
  2. For the new node, select the Enable Content Assembly on Proxies option. 
  3. To enable the Enable Content Assembly on Proxies option for the node, after the node has been added to the policy, perform the following procedure:
    1. Select Acceleration Rules from the drop-down box.
    2. Choose Assembly.
    3. Select the Enable Content Assembly on Proxies option.
    4. Click Save.
  4. Publish the new policy with the new node entry.
