K000163278: Distributed Cloud HTTP Load Balancer Traffic Uses a Nonlocal Regional Endpoint

Type
Support Solution
Published
2026-09-10
Updated
2026-09-10
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud WAF
Source
https://my.f5.com/manage/s/article/K000163278

Description

An F5 Distributed Cloud HTTP Load Balancer can forward requests to a different Regional Endpoint (RE) when the ingress RE is not eligible to process the configured origin Virtual Site. This can create cross-region traffic and add latency for affected requests. 

Environment

  • F5 Distributed Cloud (SaaS)
  • Regional Edge (RE) data plane
  • Regional Edge POPs with Resiliency Zones configured (e.g., Ashburn, Virginia — dc12-ash, b-dc12-ash)
  • Virtual Sites configured for Regional Edge grouping using SiteName label selectors
  • HTTP, HTTPS, or TCP Load Balancer objects with VIP Advertisement and Origin Pool Virtual Site assignments

Cause

When traffic enters an RE that is not included in the origin Virtual Site, Distributed Cloud forwards the traffic to one of the eligible REs for backend processing. The selected RE is not necessarily in the same geographic location as the ingress RE. For example, SiteName may include dc12-ash but not include b-dc12-ash. If traffic enters b-dc12-ash it may be sent to a distant RE for processing.

 

Answer/Recommended Actions

Update the origin Virtual Site so that the selector includes the intended geographic scope.

 

  1. In the Distributed Cloud Console, go to Shared Configuration > Virtual Sites.
  2. Edit the existing Virtual Site associated with the origin, or create a new Virtual Site.
  3. Replace the site-specific selector with a broader geographic selector:
    - Use a regional selector and include each required region.
  4. Save the Virtual Site configuration.
  5. Update the origin configuration to use the revised Virtual Site.
  6. Confirm that the updated Virtual Site is selected by the origin pool.
  7. Monitor request logs and verify that:
    - Requests entering an eligible RE use the expected local or regional backend path.
    - Cross-region ingress-to-origin traffic decreases.
    - Application latency improves for previously affected requests.
