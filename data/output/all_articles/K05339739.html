Known Issue

The BIG-IP system may incorrectly report the management (MGMT) interface media type as none.

This issue occurs when all of the following conditions are met:

  • The MGMT interface is connected and working as expected.
  • The mcpd process on the BIG-IP system has been manually or automatically restarted.
  • You use the Traffic Management Shell (tmsh) to view the interface status.

Impact

This issue is cosmetic and does not affect access to the MGMT interface.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you run the tmsh show /net interface command, you observe that the BIG-IP system reports the MGMT interface as up with a media type of none.

    For example:

    tmsh show /net interface all-properties | grep -e mgmt -e Media
    Name Status Mac-Addr MTU Bits Bits Pkts Pkts Mcast Mcast Drops Drops Errs Errs Colli Media Flow Trunk Aggreg
    mgmt up 00:23:e9:5a:a7:01 1500 192.4M 8.8M 170.5K 7.3K 144.5K 3.1K 0 0 0 0 0 none none none detached

    However, the BIG-IP system should reflect the active media type.

    For example:

    tmsh show /net interface all-properties|grep -e mgmt -e Media
    Name Status Mac-Addr MTU Bits Bits Pkts Pkts Mcast Mcast Drops Drops Errs Errs Colli Media Flow Trunk Aggreg
    mgmt up 00:23:e9:5a:a7:01 1500 193.5M 9.2M 171.5K 7.6K 145.1K 3.1K 0 0 0 0 0 1000T-FD none none detached

Workaround

To work around this issue, you can restart the chmand process to fix the display issue. To do so, perform the following procedure:

Impact of workaround: Restarting the chmand process may also restart other core BIG-IP system daemons, such as the Traffic Management Microkernel (TMM). Performing this procedure interrupts traffic processing. F5 recommends that you schedule this procedure during a maintenance window to minimize impact in mission critical environments.

  1. Log in to the BIG-IP command line.
  2. Restart the chmand process by typing the following command:

    tmsh restart /sys service chmand

    Note: You may run this command on the affected VIPRION blades, or you may run the clsh command to restart the chmand process on multiple VIPRION blades, if necessary.
