Known Issue

NT Lan Manager (NTLM) ECA checks may fail for Internet Explorer clients.

This issue occurs when all of the following conditions are met:

  • You have configured a policy access profile with NTLM authentication.
  • You have associated an ECA profile with the affected virtual server.
  • The access profile presents a Decision or Message box after the initial logon/authentication.
  • The client is using an Internet Explorer browser.

When you use the ECA profile for the virtual server, the access policy applies the ECA check to all external URLs that the system accesses during the client session. The system treats Message and Decision boxes as internal URLs and, thus, does not successfully run the ECA check.

Note: Clients use Internal URLs to directly interact with the BIG-IP APM device. External URLs do not interact directly with the BIG-IP APM device.

Impact

Clients are unable to access the configured policy resources.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After the client supplies their logon credentials, the system presents the client with a policy Decision or Message box. If the client selects any action for the box, a loop occurs, where the system continues to present the client with a policy Decision or Message box.

Workaround

To work around this issue, you can create an iRule for the affected virtual server to enable ECA checks for all URLs, or create an iRule to run the ECA checks for specific URL paths. To do so, perform one of the following procedures:

Creating an iRule to enable ECA checks on all URLs

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Enter the Name for the iRule.
  6. In the Definition box, enter the following text.

    when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable
    }

  7. Click Finished.
  8. Apply the iRule to the affected policy's virtual server.

Creating an iRule to enable ECA checks on specific URL paths

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Enter the Name for the iRule.
  6. In the Definition box, enter the following text.

    when HTTP_REQUEST {
    if { [HTTP::path] starts_with "/<url path>" } {
    ECA::enable
    ECA::select select_ntlm:/<partition>/<policy virtual server name>
    }
    else {
    ECA::disable
    }
    }

  7. Click Finished.
  8. Apply the iRule to the affected policy virtual server.
