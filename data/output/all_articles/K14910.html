Known Issue

OSPFv3 external Link State Advertisements (LSAs) originated by the TMOS Advanced Routing Module ospf6d process may include external route tag data without setting the corresponding T bit, creating an LSA that does not conform to the Open Shortest Path First (OSPF) RFC specification.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses at least one route domain with OSPF version 3 enabled.
  • You configure OSPFv3 with route redistribution.

Impact

The peer routers adjacency may not reach Full state, and traffic may not be routed as expected through the BIG-IP system and peer routers.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H441826 on the Diagnostics > Identified > High screen.
  • When routes are redistributed to the peer routers, external OSPFv3 LSAs (type 5) have a route tag appended but the T bit is not set.
  • Peer routers reject the LSAs that the BIG-IP system has redistributed.
  • While checking the State field of a peer router, you observe the functional state of the OSPF neighbor as "Loading" because it is in a loop state for Link State Request or Link State Update.

Workaround

To work around this issue, you must explicitly configure the correct route tag for any affected redistributed routes, which ensures that the system constructs a valid LSA. To do so, perform the following procedure:

Note: You must know the correct route tag value to use so that the peer routers can correctly interpret the LSA.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Enter the IMI command line shell with the affected Route Domain ID by using the following command syntax:

    run /util imish -r <RouteDomain-ID>

    For example, if the affected Route Domain ID is 10, type the following command:

    run /util imish -r 10
  3. Enter enable mode by typing the following command:

    en
  4. Enter configuration mode by typing the following command:

    config terminal
  5. Enable the routing process for OSPFv3 by typing the following command:

    router ipv6 ospf
  6. Set the correct route tag to the redistributed kernel routes by using the following command syntax:

    redistribute kernel tag <RouteTag-Number>

    For example, if the correct Route Tag Number is 1000, type the following command:

    redistribute kernel tag 1000
  7. Exit configuration mode by typing the following command:

    end
  8. Write the configuration by typing the following command:

    write
  9. Exit the IMI command shell by typing the following command:

    exit
  10. Exit the tmsh utility by typing the following command:

    quit
