Description

Planning an upgrade?
Need help or recommendation for software version to upgrade to? 

When you are planning an upgrade, the system presents you with multiple version candidates.

You can upgrade to a point release or maintenance release in your version tree, or to a newer version by following the proper upgrade path. K13845: Overview of supported BIG-IP upgrade paths and an upgrade planning reference

For example, you upgrade from:

  • BIG-IP 16.1.3.1 to 17.5.1.4
  • BIG-IP 17.1.1.1 to 17.1.3.1

However, in some cases you may have to jump versions.

For example, if you upgrade from BIG-IP 13.1.5.1 to 17.1.3.1 you will need to make an intermediate jump to a version in between the two. For Example:

  • 13.1.5.1 >> 15.1.10 >> 17.1.3.1

Recommended Actions

F5 suggests you update or upgrade the software on your BIG-IP appliances and virtual editions (VEs) to optimize the security, performance, and total cost of ownership of your BIG-IP systems.  When choosing your software upgrade, the latest maintenance release of each long-term stability (LTS) release version is the best choice for security and sustainability - so, you should consider upgrading your devices to one of the most recent point releases of particular software branch unless you require a specific feature only available in a feature release.   Long-Term Stability (LTS) releases can be identified by versions with x.1.0 release numbers (For example 17.1.0.2).  Feature releases can be identified by versions with x.0.0 release numbers (for example 17.0.0).

For a full listing of Long-Term releases and Feature releases, refer to the "Release type" column in K33062581:
K33062581: Software Release Date Information

F5 recommends that you upgrade your BIG-IP to the most recent maintenance and point release. For more information, refer to K2200: Most recent versions of F5 software.

Because F5 customers use a variety of configurations and tools, there are many update and upgrade scenarios. For details upgrading your BIG-IP system, refer to K31596200: BIG-IP update and upgrade guide | Chapter 2: Introduction. 

When evaluating upgrade version candidates, consider the following factors:

  • Version stability
    • F5 endeavors to release the most stable code possible after a rigorous and extensive QA assessment of scheduled software releases.
  • Version recommendations by F5 Support
    • Because each customer's deployment, environments, and requirements are vastly different, F5 Support does not provide recommendations for version candidates. F5 Support leaves these decisions solely to each customer based on the needs of the specific network. If you need assistance with determining the best version your network please contact F5 Professional Services to assist you in that determination.
  • F5 Support only recommends a version candidate in the event of a break-fix, for which a known issue / bug ID is identified.

Note : For information about F5 Support Scope of Support, refer to Support Policies .

  • New features, fixes, and known issues
    • F5 Support urges you to refer to the release notes for each version to learn about new features, fixes, and known issues.
    • Hotfixes are cumulative. A hotfix of a higher number contains the fixes in past hotfix versions. You do not need to install each hotfix; install the latest hotfix.

Note: Beginning in BIG-IP 11.5.5, 12.1.3, and 13.1.0, BIG-IP software no longer uses cumulative hotfixes. Instead, product defects and security fixes are included in a full release, which is called a point release. F5 identifies point releases using a fourth version element. For information, refer to K8986: F5 product support policies

  • Testing and pre-production evaluation
    • F5 Support recommends that you test your desired software version candidate in a pre-production test environment before using the new version to process production traffic.
