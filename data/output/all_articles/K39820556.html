Description

Pool member monitored by an External SMTP Monitor is down, but the same pool member is up and successfully monitored on the peer device.

Monitor logs displaying output similar to the following:

[1][<PID of bigd>] <TIME> ID <ID>  :(_main_loop): Service ready for read, now=[<TIME>] [ addr=<ADDR> srcaddr=<SRC ADDR> fd=<FD> pend=0 #conn=0 ]
[1][<PID of bigd>] <TIME> ID <ID>  :(_recv_external_node_ping): reading [ addr=<ADDR> ]
[1][<PID of bigd>] <TIME> ID <ID>  :(recv_external_node_ping): EAV failed [ addr=<ADDR> ]
[1][<PID of bigd>] <TIME> ID <ID>  :(_kill_external_pinger): killing pid=<PID of external monitor> [ addr=<ADDR> fd=<FD> ]

Environment

  • SMTP External monitor created by SMTP iApp

Cause

External monitor script and/or file used by curl's -T (--upload-file) option is missing from the /config/monitors directory on the affected device.

Recommended Actions

SCP the missing files from the peer device, then restart bigd:

tmsh restart sys service bigd

Additional Information

There are numerous reasons why an external monitor may not work as expected. To troubleshoot further, run the external monitor script with the -x option and review the output:

sh -x <path to script> <pool member IP> <pool member port>
