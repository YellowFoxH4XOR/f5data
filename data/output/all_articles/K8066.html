K8066: SSL VPN client on Windows Mobile 5.0 and 6.0 devices may not connect if the FirePass hostname contains a dash character

Topic

FirePass Windows Mobile SSL VPN clients 5.0 and 6.0 devices may be unable to connect to the FirePass controller if the Fully Qualified Domain Name (FQDN) of the FirePass controller contains a dash ( - ) character.

For example:

https://firepass-001.siterequest.com

This issue occurs because the Windows Mobile device may strip the dash character from the FirePass FQDN, causing the SSL VPN client to attempt to connect to an incorrect or invalid host. For example, if a user enters firepass-001.siterequest.com in the Server field of the SSL VPN client, the Windows Mobile device may instead attempt to connect to firepass001.siterequest.com.

F5 Networks Product Development tracked this issue as ID 269071 (formerly  CR85799), and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Workaround

If you need to support Windows Mobile 5.0 and 6.0 clients, you can work around this issue by removing the dash character from the FQDN of the FirePass controller. You must perform this change on both the FirePass controller and the authoritative DNS server for your domain.

Note: The FQDN must be changed on both the Hosts and the Web Services tabs on the Device Management: Configuration: Network Configuration page.

Important: If you change the FQDN of the FirePass controller, you should also change the CommonName (CN) on the FirePass certificate to match the new hostname. If you do not update the certificate CN, client browsers will report a certificate mismatch error when they connect to the FirePass controller.
