Known Issue

The configuration may fail to upgrade if health monitor strings contain a quotation mark ( " ).

This issue occurs when all of the following conditions are met:

  • You attempt to upgrade from an affected version.
  • You configure a health monitor with a send/receive string.
  • The monitor string contains backslash quotation ( \" ) characters, but does not contain one of the following characters:
    • single quotation mark ( ' )
    • pipe ( | )
    • open brace ( { )
    • close brace ( } )
    • semicolon ( ; )
    • number sign ( # )
    • literal newline or literal space

For example, the following configuration fails to load:

ltm monitor http /Common/test {
    adaptive disabled
    defaults-from /Common/http
    destination *:*
    interval 5
    ip-dscp 0
    recv \"service_status\":\"on\".+\"maintenance\":\"off\"
    send "GET /\r\n"
    time-until-up 0
    timeout 16
}

Impact

The BIG-IP system fails to load the configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You save the current configuration to the new version without the enclosing quotes. This behavior causes a configuration failure when booting into the new version.
  • During the configuration load process, you observe error messages in the /var/log/ltm file that appear similar to the following example:

    - failed. -- 01070642:3: Monitor /Common/test parameter contains unescaped " escape with backslash. Unexpected Error: Loading configuration process failed.

Workaround

To work around this issue, you can manually modify each monitor strings in the bigip.conf file to include enclosing quotation marks before loading the file. For example, you can add enclosing quotation marks to the receive string in the following configuration:

ltm monitor http /Common/test {
    adaptive disabled
    defaults-from /Common/http
    destination *:*
    interval 5
    ip-dscp 0
    recv "\"service_status\":\"on\".+\"maintenance\":\"off\""
    send "GET /\r\n"
    time-until-up 0
    timeout 16
}
