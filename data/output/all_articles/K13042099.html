K13042099: Configuration fails to load with configuration error 01070734:3: indicating the assertion sent to SP must be signed

Type
Support Solution
Published
2021-01-14
Updated
2023-02-21
Source
https://my.f5.com/manage/s/article/K13042099

Description

Configuration won't load because the SP-Connector has the default value for want-assertion-signed but there is no certificate configured for signing the assertion in the IdP it is bound to.

  • F5 as IdP with the default setting of true for want-assertion-signed
  • Configuration won't load
  • ERROR: 01070734:3: Configuration error: IdP certificate required for IdP Service/sso_config_saml object /Common/<nameOf_IdP> as sp connector object <nameOf_spConnector> indicates that assertion sent to SP must be signed Unexpected Error: Validating configuration process failed.

Environment

When loading the configuration or re-activating a license, the BIG-IP APM fails to load the configuration.

    • want-assertion-signed is set to true on the SP-Connector, but there is no 
    • unchecking the box in the GUI doesn't resolve the issue

    Cause

    The default value is true for want-assertion-signed, but somehow it is bound to an IdP without a certificate for signing the assertion.

    Recommended Actions

    Manually edit the bigip.conf file with the SP-Connector to set the want-assertion-signed value to false, and then load the configuration manually, with these steps:

    1. Use a rich text editor to modify the bigip.conf file; here is how you could start vim to modify an SP-Connector in a partition named Federation:
      vim /config/partitions/Federation/bigip.conf

    • Add this line to SP-Connector so it does not verify whether the IdP it is bound to has a certificate for signing the assertion:
      want-assertion-signed false

    • Verify that the configuration will load with this command:
      tmsh load sys config verify

    • If there are no errors, then you can actually load the configuration:
      tmsh load sys config 

      • Additional Information

      The other thing you can do, is to add a Certificate and Key to the SAML Object that is using this saml-sp-connector, but I would suggest that you first follow the recommended actions, so that the config can load, and then you can add the Certificate and Key to the SAML SSO Object via the GUI, and then enable "Assertion must be signed" to the saml-sp-connector. Both of these settings are in the Security Settings section of each Object.
