Known Issue

The BIG-IP WebAccelerator system may not cache objects when configured to ignore no-cache HTTP headers in the response.

This issue occurs when all of the following conditions are met:

  • The following settings are configured in the BIG-IP WebAccelerator lifetime policy:

    • Use HTTP lifetime headers if present
    • Ignore no-cache HTTP headers in the response
  • The origin web server (OWS) is using an an Expires: header with a date in the past and a Cache-Control header, such as no-cache, mandating the response is not cached.

When a response from the OWS contains a directive not to cache and also contains an Expires: header with a date in the past, BIG-IP WebAccelerator will not cache the response, even though the policy is configured to ignore the no-cache HTTP header.

Impact

Clients may experience slower response times.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Unexpected levels of server-side traffic may occur.
  • Clients may experience slower response times.
  • BIG-IP WebAccelerator will respond with an S10202 X-PvInfo header showing a proxied response due to expired content.

Workaround

To work around this issue in BIG-IP 10.x, you can use an iRule to strip the Expires: header from the HTTP response.  

Note: There is no workaround for BIG-IP WebAccelerator 9.4.x.

Impact of workaround:  Using this iRule may result in a slight performance impact.

For example:

when HTTP_RESPONSE {
      if { [HTTP::header exists "Cache-Control"] and [HTTP::headers exists "Expires"] }
        {  HTTP::header remove "Expires"  }
}

You should use this iRule only in cases when removing the Expires: header will not affect other aspects of the application. It may be possible to modify this iRule to suit your specific application needs.
