K000138987: APM MultiDomain SSO and SAML POST AuthnRequest

Type
Support Solution
Published
2024-03-27
Updated
2025-08-19
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000138987

Description

In BIG-IP APM Multidomain SSO, when accessing a virtual with a POST, the user will be redirected to the primary auth virtual. When the user is redirected back to the original url, we lose the original POST data. 

 

Environment

  • BIG-IP APM
  • MultiDomain SSO enabled in Access Profile
  • SAML IDP
  • POST binding on SAML SP

 

Cause

This is because we use HTTP 302, which allows the browser to change the method. 

 

Recommended Actions

Scenario 1: 

When the policy has already run on the auth virtual and we are only redirecting to the auth virtual to receive the session cookie.

In this situation we can use the below iRule workaround which changes the 302 to 307:


when HTTP_REQUEST {
  set uri [HTTP::uri]
}
when HTTP_RESPONSE_RELEASE {
  if { [HTTP::status] contains "302" && ([HTTP::header value "Location"] contains "SSO_ORIG_URI" || $uri contains "SSO_ORIG_URI") } {
     HTTP::header replace ":S" "307 Temporary Redirect"
  }
}

 

Scenario 2: 

When the client sends a POST to a multidomain SSO resource virtual and is redirected to the auth virtual for the access policy to run to create a new session, then once the access policy is evaluated, we redirect back to the resource virtual.

In this situation , the only workaround is to use GET/redirect binding on the SAML SP.
