Known Issue

Note: This internal parameter is only present in TrafficShield version 3.1, and BIG-IP ASM 9.2 through 9.3.1.

This is the result of a known issue. The internal parameter UseAdvancedVerifier is not set correctly in TrafficShield 3.1 and BIG-IP ASM 9.2 through 9.3.1. The correct default value of this parameter is 0 (zero).

The UseAdvancedVerifier configuration flag indicates which verification method you should use to check the operation and status of the main BIG-IP ASM process, BD.

The two possible settings are as follows:

  • original (UseAdvancedVerifier=0)
  • advanced (UseAdvancedVerifier=1)

Note: F5 recommends using the original setting.

F5 Product Development is tracking this issue as CR58813 and it was fixed in BIG-IP ASM 9.4. For more information about this CR, refer to the BIG-IP ASM Release Notes.

Workaround

You can work around this issue by setting the UseAdvancedVerifier parameter to the default value of 0. To set the UseAdvancedVerifier parameter, perform the following procedure:

  1. Log in to the Configuration utility with administrative privileges.
  2. Click Web Application.
  3. Append the URI with /dms/internal.

    For example:

    https://BIGIP_IP/dms/internal/

  4. Set UseAdvancedVerifier to 0.
  5. Click update.
  6. Restart the BIG-IP ASM by typing the following command:

    bigstart restart asm
