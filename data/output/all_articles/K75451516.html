Known Issue

Local traffic policy rules may fail to match traffic after you modify the policy rule.

This issue occurs when the following condition is met:

  • You use the Configuration utility to modify the local traffic policy rule that contains an escaped character.

    For example, a quotation character ( " ) in your local traffic policy rule will initially be saved in an escaped format as \".

    However, if you modify the rule, the system will also escape the backslash (\) character used to escape the quotation character ( " ) and incorrectly save it as \\\" in the rule. As a result, the rule fails to function as expected.

    Note: A subsequent update to the policy rule will result in the additional backslashes also being escaped (\\\\\\").

Impact

Affected local traffic policy rules will not match traffic conditions as you expect them to.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility incorrectly adds backslashes to the policy rule (adds them before the escaped characters.

    For example, the Configuration utility adds extra backslashes before the quotation marks in the following rule Parameters value:

    https://[getfield [HTTP::host] \\\":\\\" 1][HTTP::uri]

  • Your local traffic policy does not work as expected.

Workaround

To work around this issue, you can use Traffic Management Shell (tmsh) commands instead of the Configuration utility to modify local traffic policies.
