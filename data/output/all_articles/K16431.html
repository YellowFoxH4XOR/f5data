Known Issue

Systems attempting to connect to BIG-IP APM virtual servers may receive a TCP reset.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is licensed and provisioned with the BIG-IP APM and BIG-IP ASM modules.
  • A virtual server is configured with a BIG-IP APM access profile.
  • The same virtual server is configured with a BIG-IP ASM DoS Protection Profile.

Impact

Users who attempt to connect to the virtual server receive a TCP reset and fail to access the virtual server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H516830 on the Diagnostics > Identified > Medium screen.
  • The virtual server sends a TCP reset when the system sends a connection request.
  • In the /var/log/apm file, you observe an error message similar to the following example:

    err apd[4646]: 01490000:3: AccessPolicyD.cpp func: 'process_request()' line:736 Msg: EXCEPTION AccessPolicyD.cpp line:653 function: process_request - error 4 reading/parsing response from socket.

  • In the /var/log/ltm file, you observe error messages similar to the following example when the virtual server sends a TCP reset:

    <timestamp> <virtual ip address> <client ip address> TCP 258 OUT s1/tmm3 : https > <client port> [RST, ACK] Seq=142 Ack=612 Win=3963 Len=63 [F5RST(peer): SSL error (record_overflow(22)vs] 0.002376 https 49176 <timestamp>

Workaround

To work around this issue, you can disable the DoS Protection Profile of the affected virtual server. To do so, perform the following procedure:

Impact of workaround: DoS protection will no longer be enabled on the affected BIG-IP APM virtual server.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the virtual server name.
  4. Select the tab Security > Policies.
  5. Set the DoS Protection Profile to Disabled.
  6. Click Update.
