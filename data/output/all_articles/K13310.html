Topic

This article applies to BIG-IP 11.x through 17.x. For information about other versions, refer to the following article:

  • K7566: Disabling nodes or pool members for maintenance (9.x - 10.x)

For information about disabling nodes or pool members using the iControl REST API, refer to the following article:

  • K00464827: Using the iControl REST API to change node or pool member status to Forced Offline, Disabled, or Enabled

Purpose

You should consider using these procedures under the following conditions:

  • You need to disable a node or pool member for maintenance.
  • You need to force a node or pool member offline for maintenance.
  • You want to delete all existing connections to the node or pool member (optional).

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the partition associated with the node or pool member.

Description

The BIG-IP system designates two terms for network devices to which a BIG-IP system load balances traffic: nodes and pool members. A node is identified as the network device's IP address, such as 10.10.10.10. A pool member is identified as the network device's IP address, the service port on which the pool member is listening, and the name of the pool to which it belongs. For example: myPool:10.10.10.10:80.

You can set the node and pool members to a Disabled or Forced Offline state. When you interrupt access to a network device for maintenance, you should change the state of the node to Disabled or Forced Offline. If the node is set to Disabled or Forced Offline, any pool member in the BIG-IP configuration that uses that same IP address is also set to Disabled or Forced Offline. Alternatively, when you disrupt only some services on a device, you should change the state of the affected pool members to Disabled or Forced Offline. For example, if you want to change the state of the HTTP, HTTPS, and FTP pool members using the server IP 10.0.0.10, you should disable or force the 10.0.0.10 node offline. If you want to only change the state of the HTTP pool members running on address 10.0.0.10 and port 80, you should disable or force all 10.0.0.10:80 pool members offline.

When set to Disabled, a node or pool member continues to process persistent and active connections. It can accept new connections only if the connections belong to an existing persistence session.

When set to Forced Offline, a node or pool member allows existing connections to time out, but no new connections are allowed.

Note: When you remove a pool member from a pool, the system immediately discontinues the pool member monitoring and removes existing persistence entries. This action does not disrupt existing established connections. They remain open until the client disconnects or the connection times out.

Procedures

To watch a video demo of these procedures in the Configuration utility, go to  K000152178: Disable or force offline existing connections to BIG-IP nodes and pool members for maintenance.

To disable a node for maintenance, perform one of the following procedures:

  • Set the node state using the Configuration utility
  • Set the node state to Disabled using the command line
  • Set the node state to Forced Offline using the command line
  • Delete existing connections to the Disabled or Forced Offline node (Optional)

To disable a pool member for maintenance, perform one of the following procedures:

  • Set the pool member state using the Configuration utility
  • Set the pool member state to Disabled using the command line
  • Set the pool member state to Forced Offline using the command line
  • Delete existing connections to the Disabled or Forced Offline pool member (Optional)

Set the node state using the Configuration utility

Impact of procedure: Nodes that have been disabled accept only new connections that match an existing persistence session. Nodes that have been forced offline do not accept any new connections, even if they match an existing persistence session.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Nodes > Node List.
  3. Select the name of the node you want to set.
  4. For the State option, select either Disabled (Only persistence or active connections allowed) or Forced Offline (Only active connections allowed).
  5. Select Update.

Set the node state to Disabled using the command line

Impact of procedure: Nodes that have been disabled accept only new connections that match an existing persistence session.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To set the node state to Disabled, use the following command syntax:

    modify /ltm node <node name> session user-disabled

    For example, to set the state of the node 10.10.10.211 to Disabled, you would enter the following command:

    modify /ltm node 10.10.10.211 session user-disabled

    You can use the same command structure to enable a disabled node by changing the statement user-disabled to user-enabled.

    For example, you would use the following command syntax:

    modify /ltm node <node name> session user-enabled

  3. Save the change by entering the following command:

    save /sys config

Set the node state to Forced Offline using the command line

Impact of procedure: Nodes that have been forced offline do not accept any new connections, even if they match an existing persistence session.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To set the node state to Forced Offline, use the following command syntax:

    modify /ltm node <node name> state user-down session user-disabled

    For example, to set the state of the node 10.10.10.211 to Forced Offline, you would enter the following command:

    modify /ltm node 10.10.10.211 state user-down session user-disabled

    You can use the same command structure to place the node online by changing user-down to user-up and user-disabled to user-enabled.

    For example, you would use the following command syntax:

    modify /ltm node <node name> state user-up session user-enabled

  3. Save the change by entering the following command:

    save /sys config

Delete existing connections to the Disabled or Forced Offline node (Optional)

If after disabling or forcing the node offline, you want to delete all connections to that node, perform the following procedure.

Impact of procedure: This command deletes all connections to the node's specific IP and every possible service port.

Note: Connections to nodes are on the server side (ss-server) of the BIG-IP connection. Connections to virtual servers are on the client side (cs-server) of the BIG-IP connection.

  1. Log in to the BIG-IP command line.
  2. To delete all connections to the node, use the following command syntax:

    tmsh delete /sys connection ss-server-addr <node IP address>

    For example, to delete all connections to node 10.10.10.211, you would enter the following command:

    tmsh delete /sys connection ss-server-addr 10.10.10.211

Set the pool member state using the Configuration utility

Impact of procedure: Pool members that have been disabled accept only new connections that match an existing persistence session. Pool members that have been forced offline do not accept any new connections, even if they match an existing persistence session.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select the Members link for the pool to which the pool member belongs.
  4. Select the pool member you want to set.
  5. For the State option, select either Disabled (Only persistence or active connections allowed) or Forced Offline (Only active connections allowed).
  6. Select Update.

Set the pool member state to Disabled using the command line

Impact of procedure: Pool members that have been disabled accept only new connections that match an existing persistence session.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To set the pool member state to Disabled, use the following command syntax:

    modify /ltm pool <pool name> members modify { <pool member:port> { session user-disabled } }

    For example, to set the state of the pool member 10.10.10.211:http in pool http-pool to Disabled, you would enter the following command:

    modify /ltm pool http-pool members modify { 10.10.10.211:http { session user-disabled } }

    You can use the same command structure when you modify the pool member states from disabled to enabled by changing the session variable from user-disabled to user-enabled.

    For example, you would use the following command syntax:

    modify /ltm pool http-pool members modify { <pool member:port> { session user-enabled } }

  3. Save the change by entering the following command:

    save /sys config

Set the pool member state to Forced Offline using the command line

Impact of procedure: Pool members that have been forced offline do not accept any new connections, even if they match an existing persistence session.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To set the pool member state to Forced Offline, use the following command syntax:

    modify /ltm pool <pool name> members modify { <pool member:port> { session user-disabled state user-down} }

    For example, to set the state of the pool member 10.10.10.211:http in pool http-pool to Forced Offline, you would enter the following command:

    modify /ltm pool http-pool members modify { 10.10.10.211:http { session user-disabled state user-down} }

    You can use the same command structure when you modify the pool member states from Offline to Online by changing the session variable from user-down to user-up and user-disabled to user-enabled.

    For example, you would use the following command syntax:

    modify /ltm pool http-pool members modify { <pool member:port> { session user-enabled state user-up } }

  3. Save the change by using the following command:

    save /sys config

Delete existing connections to the Disabled or Forced Offline pool member (Optional)

If after disabling or forcing the pool member offline, you want to delete all connections to that pool member, perform the following procedure.

Impact of procedure: This procedure deletes all connections to the pool member's specific IP and service port.

Note: Connections to pool members are on the server side (ss-server) of the BIG-IP connection. Connections to virtual servers are on the client side (cs-server) of the BIG-IP connection.

  1. Log in to the BIG-IP command line.
  2. To delete all connections to the pool member, use the following command syntax:

    tmsh delete /sys connection ss-server-addr <member IP address> ss-server-port <member server port>

    For example, to delete all port 80 connections to the pool member 10.10.10.211:http, you would enter the following command:

    tmsh delete /sys connection ss-server-addr 10.10.10.211 ss-server-port 80

Alternatively, in the case where you manually forced the pool member offline, and you want to delete all connections to that pool member, you can use the Action On Service Down pool feature, setting it to Reject on the Configuration Utility or reset in the tmsh shell. For more information on Action on Service Down, refer to K15095: Overview of the Action On Service Down feature. To do so, perform the following procedure:

Note: This method (Setting the Action on Service Down to Reject) does not apply for the case where you disabled the pool member. It only applies when you manually set the pool member offline.

Impact of procedure: The BIG-IP system resets and clears the active connections to the offline pool member but sends subsequent newly arriving connections to available pool member if any.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select the pool name.
  4. For Configuration, select Advanced.
  5. For Action On Service Down, select the option you want.
  6. Select Update.
