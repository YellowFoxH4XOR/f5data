K64800394: Large csyncd.out file in the /shared/tmp/ directory on a single blade

Type
Support Solution
Published
2020-12-04
Updated
2023-02-21
Applies to
  • VIPRION Platforms
  • BIG-IP
  • BIG-IP LTM: 13.1.X, 13.0.X, 13.1.5, 13.1.4, 13.1.3, 13.X.X, 13.1.0, 13.0.1, 13.0.0, 13.1.1
Source
https://my.f5.com/manage/s/article/K64800394

Description

Larger csyncd.out file in the /shared/tmp/ folder utilizing most of the space of /shared partition.

Example -

config # ssh slot4 'find /shared/ -xdev -type f -exec du {} \; | sort -rn | head -20'
15155336        /shared/tmp/csyncd.out
2239832 /shared/images/BIGIP-14.1.2.8-0.0.7.iso
2220244 /shared/images/BIGIP-14.1.2.6-0.0.2.iso

Environment

  • BIG-IP
  • Viprion
  • Multiple blades
  • Config sync

Cause

On a certain blade, /shared partition is running out of space by continuously growing csyncd.out file.
 

Recommended Actions

1. Execute the command below to stop the csyncd process.
   clsh bigstart stop csyncd
 
2. Please delete the file. Check if the file on slot is deleted. If not you can ssh to slot4 and delete it from there.
   clsh rm -f -v /shared/tmp/csyncd.out
 
3. Start the service again and monitor if the file grow again.
   clsh bigstart start csyncd
 

Additional Information
On Viprion systems, the csyncd process replicates portions of the file system between cluster members. When the system meet one of the conditions below.

  • One or more of the cluster members status become unknown or manually disabled.
  • One or more empty files exist on a cluster member/s.
  • One or more files been deleted on a cluster member/s.


The csyncd process fail to replicate the file/s between cluster members causing a large and continuously growing /shared/tmp/csyncd.out file on one of other blade/slot.

You can check the log entries of this by the command below.
tail -n200 /shared/tmp/csnycd.out

If the log entries matches to the example below, we can confirm the missing or empty file/s and take the recommended actions.
 
/shared/tmp/csyncd.out continuously write:

rsync: change_dir "/home/user/folder" (in csync) failed: No such file or directory (2)
rsync error: some files/attrs were not transferred (see previous errors) (code 23) at main.c(1505) [receiver=3.0.6]
