Description

There is slowness in the GUI and CLI; however, no errors were found in the logs.

Environment

  • vCMP Guest
  • GUI Slowness
  • CLI Slowness
  • No errors in logs

Cause

Unknown. All standard troubleshooting steps (resource allocation, process restarts, log review) did not reveal a root cause.

Recommended Actions

Redeploy the vCMP guest by backing up the master key and UCS, deleting the guest and vdisk, recreating the guest, and restoring the configuration.

Step 1

Get the master key.

# f5mku -K

Notes: Copy the output and save it securely

 

Step 2

# tmsh save sys ucs BACKUP_DEC_2023.ucs

Notes: The UCS file will be in /var/local/ucs/. Save it either locally or onto company network storage securely.

Step 3

Take a screenshot of the vCMP Guest configuration and delete it from the vCMP Host guest list.

Please refer to the attached decommissioning guide for unused vCMP Guests:

K71021567: Decomission / Delete / Remove unused vCMP Guest

 

Step 4

Create a new vCMP Guest, by referring to the configuration screenshot taken from the previous Step 3.

Notes: Ensure to select the correct image version to be installed.

For example, if the original vCMP Guest was first deployed with v14.1.x and later upgraded to v16.1.x, the configuration may still show v14.1.x. When redeploying, select the latest image (e.g., v16.1.x) so the vCMP Host uses the correct ISO to create a new virtual disk for the guest.

 

Step 5

Once the guest is created and started, re-key the master key using the value obtained in Step 1.

# f5mku -r <Old_BIG-IP_Master_Key>

 

Step 6

After re-keying the master key, upload the UCS backup file to the BIG-IP at the directory path "/var/local/ucs/".

Notes: WinSCP or the bash SCP command may be used, as preferred.

 

Step 7

Load the vcmp-guest config by using UCS backup file.

# tmsh load sys ucs BACKUP_DEC_2023.ucs no-license 

Notes: When the vCMP Guest boots, it automatically inherits its license from the host system. In most scenarios-such as redeploying a vCMP Guest, performing a clean installation, or restoring the configuration to a replacement device-it is recommended to use the "no-license" option. This ensures the system does not attempt to apply the old license file contained within the UCS backup, which is unnecessary in these cases.

After completing the steps above, allow all system daemons to reach their running state, and then verify whether the GUI slowness issue has been resolved. If the issue persists after redeploying the vCMP Guest, it is recommended to contact F5 Support for further assistance.

Additional Information

Important: These steps require downtime for the affected vCMP Guest. Other vCMP Guests on the same host are not affected.
