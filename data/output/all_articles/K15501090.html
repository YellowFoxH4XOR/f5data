K15501090: BIG-IP may reset a TCP connection with reset cause ''F5RST(peer): Content-Length Exceeded''

Type
Support Solution
Published
2022-04-28
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.X.X, 15.1.2, 15.1.3, 15.1.1, 15.1.0, 15.0.1, 15.0.0, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.0.X, 15.1.X
Source
https://my.f5.com/manage/s/article/K15501090

Description

You may see a connection is reset with reset cause of F5RST(peer): Content-Length Exceeded on client-side.

Environment

  • BIG-IP LTM
  • HTTP2
  • HTTP request method is HEAD
  • Extra payload in server response

Cause

The server response contains extra data payloads for HTTP2 HEAD requests.  For example, The following HTTP2 response contains an extra data stream for an HTTP2 HEAD request.

HyperText Transfer Protocol 2
    Stream: HEADERS, Stream ID: 1, Length 89, 200 OK
        Length: 89
        Type: HEADERS (1)
        Flags: 0x04, End Headers
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0001 = Stream Identifier: 1
        [Pad Length: 0]
        Header Block Fragment: <fragment id>
        [Header Length: 234]
        [Header Count: 9]
        Header table size update
        Header: :status: 200 OK
        Header: content-length: 2121
        Header: content-type: image/gif
        Header: last-modified: Mon, 28 Jun 2021 00:04:07 GMT
        Header: accept-ranges: bytes
        Header: etag: "<etag id>"
        Header: server:
        Header: date: Tue, 29 Jun 2021 09:35:47 GMT
    Stream: DATA, Stream ID: 1, Length 0
        Length: 0
        Type: DATA (0)
        Flags: 0x01, End Stream
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0001 = Stream Identifier: 1
        [Pad Length: 0]
        Data: <MISSING>

Recommended Actions

When the HTTP2 request method is HEAD, the server should only reply with HTTP2 headers without data stream payload. BIG-IP will reset the connection when seeing this non-RFC compliant behavior. You may refer to  rfc7231 for more details
