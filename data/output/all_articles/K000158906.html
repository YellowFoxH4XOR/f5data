K000158906: Expired certificates not able to be deleted due to links to non existent objects

Type
Support Solution
Published
2025-12-23
Updated
2025-12-28
Applies to
  • BIG-IP
  • BIG-IP GTM
  • BIG-IP DNS
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000158906

Description

  • An expired SSL certificate cannot be deleted because BIG-IP reports it is still “in use” and linked to a configuration object that appears to not exist (for example, a monitor).
  • Searching the saved configuration for expected LTM monitor references may return no results, even though the GUI still shows the certificate as “linked/in use.”
  • Error message similar to this when trying to delete the certificate:

    01070265:3: The Certificate File (/Common/<certificate_name>) cannot be deleted because it is in use by a SSL certificate monitor parameter (/Common/<monitor_name> 2 CERT=).

and when clicking on the "Instance" link:

Instance not found:/Common/<monitor_name>

 

Environment

  • BIG-IP with LTM and DNS/GTM provisioned
  • Expired SSL certificates
  • Expired certificates previously associated with configuration objects (for example, monitors)

 

Cause

The certificate was referenced by a GTM monitor; the GUI “instance detection” only exposed links to LTM objects, which made the dependency appear non-existent from an LTM-only view.

Recommended Actions

  1. Identify references to the certificate in the saved configuration:
    1. Run:
      grep -B 10 <certificate_name> /config/*.conf | grep monitor
    2. Note which file returns a match and the name of the monitor.
      Example output:   /config/bigip_gtm.conf-gtm monitor https /Common/<monitor_name> {
  2. If the certificate is confirmed to be used by a GTM monitor:
    1. Update the GTM monitor to use a different certificate (or remove the monitor if no longer needed).
    2. Save/load configuration as appropriate.
    3. Attempt to delete the expired certificate again.

Additional Information
