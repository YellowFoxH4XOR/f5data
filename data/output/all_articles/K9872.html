Known Issue

This is the result of a known issue. A BIG-IP 8900 system may stall when loading the system software after a reboot, for as long as 4 minutes. This behavior may interfere with the signaling used to communicate with the peer unit through the serial failover cable in a redundant pair configuration. As a result, the peer unit may remain in a standby state or flap between an active/standby state.

F5 Product Development tracked this issue as CR118208 and it was fixed in BIG-IP versions 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

This issue has been fixed in Hotfix BIGIP-10.0.1-342.0-HF1 as CR125221, which has been issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

To prevent communication interference to the peer unit, configure a redundant system to use either network-based failover or both network-based and hardwired failover. Do not configure only hardwired failover on BIG-IP 8900 platforms until this issue is resolved.
