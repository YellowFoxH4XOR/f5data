Description

You are running F5 NGINX Ingress Controller (NIC) and want to enable an NGINX directive that lives inside the NGINX events {} block — for example multi_accept on;. You have found that:

  • NIC's ConfigMap snippet keys (main-snippets, http-snippets, location-snippets, server-snippets, stream-snippets) do not include an events context, so no snippet can place a directive inside events {}.
  • The default NIC main template only renders worker_connections inside the events {} block.

This article explains the only supported way to add such a directive, and the critical version-matching requirement.

Environment

  • F5 NGINX Ingress Controller (NGINX Plus and NGINX Open Source)
  • Configuration via the nginx-config ConfigMap

Cause

NIC generates the main nginx.conf from a Go template (nginx-plus.tmpl / nginx.tmpl). Snippets are injected only into predefined contexts; there is no snippet hook for the events context. The main-snippets key renders into the main context (top level of nginx.conf, outside events {}), so it cannot be used to inject a directive inside the events block.

The only supported mechanism to modify the events {} block is to override the entire main template using the main-template ConfigMap key (documented under Custom templates).

Recommended Actions

Step 1 — Identify the exact running NIC version

The template you supply must match the version of the running NIC binary. Determine it with:

kubectl get pod -n nginx-ingress <nic-pod> -o jsonpath='{.spec.containers[*].image}'

Step 2 — Download the template for that exact version tag

Pull nginx-plus.tmpl (NGINX Plus) or nginx.tmpl (NGINX OSS) from the nginx/kubernetes-ingress GitHub repository, using the tag that matches Step 1. For example, for v5.2.1:

curl -k -o nginx-plus.tmpl \
  https://raw.githubusercontent.com/nginx/kubernetes-ingress/v5.2.1/internal/configs/version1/nginx-plus.tmpl

Step 3 — Add the directive inside the events block

Edit only the events {} block; leave every {{ ... }} template action unchanged:

events {
    worker_connections  {{.WorkerConnections}};
    multi_accept on;
}

Step 4 — Place the template into the nginx-config ConfigMap under main-template

apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config
  namespace: nginx-ingress
data:
  worker-connections: "16384"
  main-template: |
    <full contents of the edited nginx-plus.tmpl, indented 4 spaces>

YAML rules for the main-template block:

  • Use the | block scalar.
  • Indent every template line consistently (e.g. 4 spaces). No tab characters — tabs are the most common cause of apply failures.
  • Do not alter the {{ ... }} Go-template actions.

Step 5 — Apply and verify

kubectl apply -f nginx-config.yaml --dry-run=server   # validates first
kubectl apply -f nginx-config.yaml
kubectl exec -it -n nginx-ingress <nic-pod> -- grep -A3 'events {' /etc/nginx/nginx.conf

You should see both worker_connections and multi_accept on; inside the events {} block.

Important: the template version MUST match the running NIC binary

If the template references a field that does not exist in the running binary's Go struct, NIC fails to start with a fatal error such as:

Error generating NGINX main config: template: nginxTemplate:42:11:
executing "nginxTemplate" at <.ClientBodyBufferSize>:
can't evaluate field ClientBodyBufferSize in type *version1.MainConfig

Example: the ClientBodyBufferSize field was introduced in NIC 5.3.0. Using a 5.3.0-or-newer template against a 5.2.x binary triggers the error above. Always pull the template from the tag matching the deployed version.

Additional Information

  • A main-template override is a full copy of the template. It does not inherit future template changes. On every NIC upgrade you must re-download the new version's template, re-add your directive, and re-apply — otherwise you either lose new features/fixes or hit the field-mismatch error.
  • kubectl apply replaces the ConfigMap object. Merge back any other existing keys (proxy timeouts, SSL settings, log formats, etc.) so they are not dropped.
  • worker_connections remains driven by the worker-connections ConfigMap key because the {{.WorkerConnections}} placeholder is preserved.
  • On Linux, NGINX auto-selects the epoll event method; an explicit use epoll; is redundant (harmless).
  • A malformed template causes an nginx: [emerg] config-test failure or a render error in NIC logs; NIC keeps the last known-good configuration. Check kubectl logs -n nginx-ingress <nic-pod>.
