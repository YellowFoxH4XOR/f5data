Known Issue

The BIG-IP GTM system utilizes an SNMP prober to gather information from supported third-party load balancers. The information from the SNMP probe is used to determine the type of response that should be sent to a DNS request. To determine which OIDs will be used to query the device, the big3d daemon uses the Product type specified in the Servers section of the Configuration utility.

RadWare is listed as a supported third-party load balancer in the product drop-down menu under Servers, but there are no corresponding OIDs mapped in big3d with which to query the load balancer. Instead of gathering specific information from the RadWare load balancer, the big3d daemon resumes using generic MIB-2 queries. This results in the RadWare device being treated as a Generic Host.

F5 Product Development tracked this issue as CR70386 and CR70387 and it was fixed in BIG-IP GTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP GTM Release Notes.
