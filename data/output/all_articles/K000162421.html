K000162421: F5OS: Remove a Persistent “Upload Failed” Alert from Image Transfer Status

Type
Support Solution
Published
2026-08-02
Updated
2026-08-02
Source
https://my.f5.com/manage/s/article/K000162421

Description

After a tenant image or software image upload fails, F5OS may continue to display an “Upload failed” alert in Image Transfer Status. The failed entry may not provide a functional delete option in the GUI, even after the failed image has been removed or the upload is no longer active.

This procedure removes stale upload-status metadata. It does not repair an image that failed signature verification, and it does not resolve a new upload failure.

 

Environment

  • F5OS-A or F5OS-C
  • Tenant image or F5OS image upload
  • F5OS GUI
  • Image Transfer Status displaying a persistent “Upload failed” alert

Cause

The alert is retained as stale metadata under:

/file/upload/meta-data

The F5OS GUI may not provide a delete operation for this alert. The metadata must be cleared from the F5OS system, followed by a restart of utils-agent.

 

Symptoms

The GUI displays an upload failure, such as:

  • Upload failed
  • Size mismatch
  • A failed-upload alert that cannot be selected or deleted
  • The failed entry remains after the original upload has completed or failed

Old failed upload entries are tracked in the F5OS file-upload metadata. Bug ID1128633 describes stale failed-upload entries remaining in the transfer-status or transfer-operations lists. The stale entry has no functional impact on running tenants or data-plane traffic. Bug ID1128633

 

Answer/Recommended Actions

Important considerations

  • Run the procedure with the root account.
  • Confirm that no important file-transfer operation is actively running before clearing the upload metadata.
  • The procedure clears the upload-status metadata, including stale entries.
  • Restarting utils-agent briefly interrupts file-transfer operations, such as image import and export. It does not affect running tenants or data-plane traffic. This procedure was provided and verified by Product Development. KB K000133516: Upgrade image failed through GUI

Clear the stale upload metadata

Run the following commands from the F5OS host:

docker exec -it system_manager sh
confd_cmd -dd -o -c 'delete "/file/upload/meta-data"'
exit
docker restart utils-agent

After the restart completes:

  1. Refresh the F5OS GUI.
  2. Navigate to the relevant image-management page.
  3. Open Image Transfer Status.
  4. Confirm that the stale “Upload failed” alert has been removed.

If the alert remains

If the alert remains after running the commands:

  1. Confirm that the commands were executed with the root account.
  2. Confirm that the confd_cmd operation completed successfully.
  3. Refresh or reopen the F5OS GUI.
  4. Verify that the alert is not associated with a new active upload.
  5. Review the upload and image-agent logs.
  6. Contact F5 Support if the metadata cannot be cleared or if new uploads continue to fail.

Distinguish a stale alert from an actual upload failure

This procedure only removes the displayed alert. Investigate the original upload separately when the image itself is unavailable or fails verification.

For example, a tenant image may show “Verification failed” because F5OS cannot validate the image signature. In that situation, clearing /file/upload/meta-data removes the stale status entry but does not make the image deployable. For signing-certificate and tenant-image format compatibility, refer to KB K000157194: F5OS Tenant Image Installation Fails with “Verification Failed”.
