Description

Similar to below message in /var/log/ltm or get snmp alert.

011d0004:3: Disk partition /var/log has only * % free

Or you find /var/log partition is nearly full when you run df command:

df -h

Filesystem      Size  Used Avail Use% Mounted on
/dev/md8        427M  182M  223M  45% /
none             16G  2.2M   16G   1% /dev/shm
/dev/md10       3.2G  450M  2.6G  15% /config
/dev/md9        3.3G  2.6G  563M  83% /usr
/dev/md11       3.0G  1.6G  1.3G  57% /var
/dev/md1         30G   11G   18G  35% /shared
/dev/md2        6.9G  5.8G  801M  90% /var/log  <<<-------[!]
...
 

Environment

  • BIG-IP v11.5.* and later
  • You have enabled pool member  health Monitor logging (debug) or monitor debug enabled, or still enabling.
  • Before disabling debug, deleted the debug logging.
     

Cause

On Linux or Unix systems, deleting a file via rm or through a file manager application will unlink the file from the file system's directory structure; however, if the file is still open (in use by a running process) it will still be accessible to this process and will continue to occupy space on disk. Therefore such processes may need to be restarted before that file's space will be cleared up on the filesystem.
 

Recommended Actions

  1. run below command and find if there is unlinked but occupying disc space.
    lsof 2>/dev/null  | grep (deleted) | grep bigd

    below example output shows 2.8GB  is occupied by opened but unlinked files.
    bigd        26963    root    6w    REG    9,2     2,830,873,725     278530    /var/log/monitors/<partition_name>_<monitor_name>-<partition_name>_<pool_member_name>-<pool_member_port>.log.1 (deleted)

    NOTE: running  lsof 2>/dev/null  | grep (deleted) would find other open files. 
     
  2. Check if the debug logging is enabled on the pool member in the previous output and check if debug is enabled for all by
    tmsh list sys db bigd.debug
    sys db bigd.debug {
        value "enable"
    }
    If it is enabled, disable by
    tmsh modify sys db bigd.debug value disable
    tmsh save sys config
     
  3. Restart bigd
    tmsh restart sys service bigd

    NOTE: until bigd is fully restarted, no monitor traffic will be initiated, and monitor status remain same as before. No impact to processing traffic.
     
  4. Check if the /var/log partition has now enough available space.
    df -f
