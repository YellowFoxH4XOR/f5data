Description

BIG-IP LTM VE deployed on Nutanix AHV can lose network connectivity when the VM is created with an incomplete set of virtual NICs or subnets. Symptoms include successful IPv4 connectivity followed by loss of gateway communication, ICMP requests without replies on the management interface, and traffic appearing on an unexpected data interface.

Environment

  • Product: BIG-IP LTM VE
  • Hypervisor: Nutanix AHV
  • VM deployment using multiple Nutanix VLANs or subnets
  • BIG-IP interfaces mapped to Nutanix AHV virtual network interfaces
  • Nutanix VM network interfaces configured as kNormalNic
  • Multiple VLANs or subnets required by the BIG-IP network design

Cause

Incomplete NIC and subnet assignment during VM creation can cause unexpected BIG-IP interface enumeration or associate traffic with the wrong interface. Assigning only one subnet, or otherwise creating fewer virtual NICs than required by the network design, can result in connectivity loss and inconsistent interface or MAC-address behavior.

Recommended Actions

  1. Review the BIG-IP LTM VE design and identify every VLAN or subnet that must be connected to the VM.
  2. During Nutanix VM creation, assign all required subnets and create the corresponding virtual NICs. Do not deploy the VM with only one subnet when the BIG-IP configuration requires multiple networks.
  3. Verify that each virtual NIC has a unique MAC address. From a Nutanix Controller VM, run:
    acli vm.get <BIG-IP-VM-name>
  4. Confirm that the BIG-IP interfaces correspond to the expected Nutanix NICs and networks. From the BIG-IP console, run:
    tmsh show net arp
    tmsh show net interface
  5. If connectivity fails, capture traffic during both working and failed states:
    tcpdump -s0 -nni 0.0:nnn -w /var/tmp/nutanix-ping.pcap -vv
  6. If the deployment uses Nutanix Flow, VPCs, security policies, or microsegmentation, verify that the policies permit the required traffic, including MAC address spoofing or forged transmissions where applicable.
  7. As an additional Nutanix-side validation, change applicable data or trunk interfaces from kNormalNic to kDirectNic:
    acli vm.nic_update <BIG-IP-VM-name> <vNIC_MAC-address> type=kDirectNic
    Repeat the command for each applicable data or trunk interface. Changing the NIC type alone may not resolve an issue caused by incomplete NIC and subnet assignment.
  8. If the issue persists, collect diagnostic information before and after reproducing the failure:
    • BIG-IP QKView with full logs.
    • Output from tmsh show net arp.
    • Output from tmsh show net interface.
    • Packet captures showing working and failed traffic.
    • Nutanix VM configuration output from acli vm.get.

Additional Information

  • Assign all subnets required by the BIG-IP network design when creating the VM.
  • Ensure that each assigned virtual NIC has a unique MAC address.
  • The required NIC count depends on the BIG-IP network design and the number of connected VLANs or subnets.
  • Changing the Nutanix NIC type to kDirectNic is a validation step and is not a guaranteed resolution.
  • Confirm Nutanix AHV and BIG-IP interoperability against the supported matrix.
