Description

The blade recovered and is currently active 

Following found in /var/log/tmm:
notice panic: unable to alloc 591 byte

Following found in /var/log/messages:
notice logger: Started writing core file: /var/core/tmm.0.bld0.0.5.core.gz for PID 1187
notice logger: Finished writing 382115060 bytes for core file: /var/core/tmm.0.bld0.0.5.core.gz

Environment

  • Viprion blade went offline
  • TMM Core file generated
Cause

TMM cored due to inability to allocate more memory.
iRule to mitigate log4j vulnerability on F5 (iRule is taken from K59329043) is v2.4, which is suffering from poor memory management.
iRule v2.6 now available.

Recommended Actions

Consult the following article and update the iRule to version 2.6:
K59329043: Mitigate the Apache Log4j2 vulnerability with BIG-IP
