K8969: Modifying a profile associated with a BIG-IP ASM virtual server may cause traffic to bypass the HTTP Class filter

Known Issue

This is the result of a known issue. Modifying a profile that is associated with a BIG-IP ASM-enabled virtual server may cause the associated HTTP classes to improperly filter content.

After the associated profile is modified, the BIG-IP ASM system plugin reinitializes and reloads the configuration. This operation may be incomplete and the HTTP class structure may not be properly re-associated with the virtual server. As a result, traffic that would not normally match the HTTP class may be sent to the BIG-IP ASM system for enforcement.

Important: This issue does not lead to any traffic bypassing the BIG-IP ASM system incorrectly; however, it may lead to failed requests.

To determine if you are impacted by this issue, inspect the /var/log/asm file for error messages that appear similar to the following example:

01310012:6: ASM bad request: event code I485 Request has no HTTP selector

Note: The event code I485 used in the example differs from case to case.

F5 Product Development tracked this issue as CR100463 and it was fixed in BIG-IP ASM 10.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.

This issue was fixed in Hotfix-BIG-IP-9.4.3-HF4 issued for BIG-IP 9.4.3, Hotfix-BIG-IP-9.4.4-94.0-HF3 issued for BIG-IP 9.4.4, and Hotfix-BIG-IP-9.4.5-HF2 issued for BIG-IP 9.4.5. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

If you have determined that your traffic is impacted by this issue, you may work around the issue by performing a restart of all services. To restart all services in the correct order and properly reload all configurations, type the following command from the command line:

bigstart restart
