Known Issue

A VIPRION system may fail over to its high availability (HA) peer continuously.

This issue occurs when all of the following conditions are met:

  • You have configured the VIPRION systems in an HA configuration with a traffic group that references an HA group.
  • You rebooted the VIPRION systems in an HA configuration approximately one minute apart.

Impact

You experience traffic disruption while the VIPRION systems in an HA configuration fail over continuously.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H510177 on the Diagnostics > Identified > Medium screen.
  • The affected VIPRION systems fail over continuously.
  • You may observe the following logs in the /var/log/ltm file:

    010717b5:3: HA group (HA) cannot be removed. It is used by traffic group (/Common/traffic-group-1 ).
    01070935:3: Unexpected exception caught in MCPProcessor::rm_DBLowHighWide().
    01070734:3: Configuration error: MCPProcessor::check_initialization:

Workaround

To work around this issue, you can modify the traffic group configuration to remove the HA group reference on the affected systems and restart them. To do so, perform the following procedure:

Impact of workaround: Traffic processing is interrupted while the systems undergo a reboot.

  1. Log in to the BIG-IP command line.
  2. Remove the HA group reference from the traffic group configuration using the following command syntax:

    tmsh modify /cm traffic-group <traffic group name> ha-group none

    For example, to remove the HA group reference from the exampletg1 traffic group, you would type the following command:

    tmsh modify /cm traffic-group exampletg1 ha-group none

  3. Save the modifications by typing the following command:

    tmsh save /sys config

  4. Reboot the system by typing the following command:

    clsh shutdown -r now

  5. Repeat steps 1 through 4 on the peer system.
