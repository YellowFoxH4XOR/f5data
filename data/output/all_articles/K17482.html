Known Issue

When you create a node within a route domain, the BIG-IP system may erroneously create the node in the default route domain.

This issue occurs when all of the following conditions are met:

  • You create a node by using the pool menu of the Configuration utility.
  • The node has a numeric name that matches the IP address of the node.
  • The node's IP address includes a route domain.

Note: This issue does not occur when creating a node by using the node page of the Configuration utility.

Impact

The BIG-IP configuration may be set to an invalid state and unable to load, requiring the restoration of a backup configuration.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP configuration fails to load, and displays an error message similar to the following example:

    01070734:3: Configuration error: Pool member address 192.168.1.1%1 cannot be assigned to node /Common/192.168.1.1. The node already has address 192.168.1.1

Workaround

To work around this issue, you can rename the node with alphabetic characters, or create all nodes from within the node menu of the Configuration utility.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
