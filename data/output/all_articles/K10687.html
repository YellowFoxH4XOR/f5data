Known Issue

This is the result of a known issue. If an iRule is created containing a RULE_INIT event but missing a required Tcl argument, an appropriate error message is not displayed by the Configuration utility or the console. Instead, a generic MCP error message is reported in the /var/log/tmm file, and appears similar to the following example:

1031000 in mcpmsg_to_database

For example, when creating the following iRule containing the RULE_INIT event and referencing a non-existing class, an appropriate error message is not displayed by the Configuration utility or the console:

when RULE_INIT {
log local0. "init"
set ::test [findclass "test" $::test]
}

Note: If you attempt to edit the iRule to add the missing argument, the iRule fails to initialize. For more information, refer to K11243: iRules containing the RULE_INIT iRule event do not re-initialize when a syntax error is corrected.

F5 Networks Product Development is tracking this issue as CR124099.

Workaround

To work around this issue, you must remove and recreate the iRule with the correct Tcl argument.

Note: For information about issues with iRules containing a RULE_INIT event and Data Groups, refer to K11068: An iRule with an RULE_INIT event referencing a Data Group may fail to initialize.
