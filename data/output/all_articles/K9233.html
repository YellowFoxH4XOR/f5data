Topic

The VIPRION system continually monitors certain daemon heartbeats to determine whether the service is running. A daemon heartbeat is a recurring signal that a service generates.

Note: For more information, refer to K9231: Overview of BIG-IP daemon heartbeat failover.

If the VIPRION system does not detect a heartbeat for certain daemons, the system takes some action with respect to failover. The VIPRION system takes failover action when the following daemons fail to increment their heartbeat signal within the timeout period:

The mcpd process

The mcpd process is the messaging and configuration daemon for the BIG-IP system. The heartbeat timeout for the mcpd process is 300 seconds, and the default failover action for redundant systems is restart all. Therefore, if the mcpd process does not increment its heartbeat in 300 seconds, the BIG-IP system restarts all system services.

When the heartbeat timeout for the mcpd process expires, the system logs the following message to the /var/log/ltm file:

overdog[1628]: 01140029:5: HA daemon_heartbeat mcpd fails action is restart all.

The tmm process

The tmm process is the traffic management daemon for the BIG-IP system. Multiple tmm instances run on the VIPRION system. The heartbeat timeout for the tmm process is 10 seconds, and the default failover action for VIPRION systems is go offline down links and restart. Therefore, if a tmm instance does not increment its heartbeat in 10 seconds, the system and all links become unavailable, and the BIG-IP system restarts tmm.

When the heartbeat timeout for a tmm instance expires, the system logs the following message to the /var/log/ltm file:

sod[1957]: 01140029:5: HA daemon_heartbeat tmm<instance> fails action is go offline down links and restart.

The sod process

The sod process is the high-availability management daemon for the BIG-IP system. The heartbeat timeout for the sod process is 60 seconds, and the default failover action for redundant systems is restart all. Therefore, if the sod process does not increment its heartbeat in 60 seconds, the BIG-IP system restarts all system services.

When the heartbeat timeout for the sod process expires, the system logs the following message to the /var/log/ltm file:

overdog[1628]: 01140029:5: HA daemon_heartbeat sod fails action is restart all.

The bigd process

The bigd process is the health monitor daemon for the BIG-IP system. The heartbeat timeout for the bigd process is 60 seconds, and the default failover action for redundant systems is restart. Therefore, if the bigd process does not increment its heartbeat in 60 seconds, the BIG-IP system restarts the bigd service.

When the heartbeat timeout for the bigd process expires, the system logs the following message to the /var/log/ltm file:

sod[27894]: 01140029:5: HA daemon_heartbeat bigd fails action is restart.

The bcm56xxd process

The bcm56xxd process is the switch driver daemon for the BIG-IP system. The heartbeat timeout for the bcm56xxd process is 60 seconds, and the default failover action for redundant systems is no action. Therefore, if the bcm56xxd process does not increment its heartbeat in 60 seconds, the BIG-IP system takes no action.

When the heartbeat timeout for the bcm56xxd process expires, the system logs the following message to the /var/log/ltm file:

bcm56xxd[20148]: 012c0001:3: Remote BCM56xxd heartbeat timeout. bsx_proxy.c(466)

The clusterd process

The clusterd process is the cluster management daemon for the VIPRION system. The heartbeat timeout for the clusterd process is 300 seconds, and the default failover action for redundant systems is go offline down links and restart. Therefore, if the clusterd process does not increment its heartbeat in 300 seconds, the BIG-IP system and all links become unavailable, and the selected service restarts.

When the heartbeat timeout for the clusterd process expires, the system logs the following message to the /var/log/ltm file:

sod[1745]: 01140029:5: HA proc_running clusterd fails action is go offline and down links.

The tmrouted process

The tmrouted process is the routing table management daemon. The heartbeat timeout for the tmrouted process is 30 seconds, and the default failover action for redundant systems is restart. Therefore, if the tmrouted process does not increment its heartbeat in 30 seconds, the BIG-IP system restarts the service.

When the heartbeat timeout for the tmrouted process expires, the system logs the following message to the /var/log/ltm file:

sod[1745]: 01140029:5: HA daemon_heartbeat fails action is restart.
