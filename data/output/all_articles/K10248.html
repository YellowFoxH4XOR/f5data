Known Issue

Note: For information about configuring the quorum disk, refer to the Adding the Quorum Disk section of the Configuring Redundancy chapter in the ARX CLI Network Guide.

This is the result of a known issue. When specifying the quorum disk for redundant ARX systems, one of the quorum-disk command functions is to create a hidden .acopia_qdisk directory on the quorum disk share specified, and to write a test file to the directory to ensure that the quorum disk is functioning properly. When specifying an NFS quorum disk using the quorum-disk command, the hidden .acopia_qdisk directory is not created, and the test file creation fails with an error message that appears similar to the following example:

Cannot mount 10.10.10.1:/qdshare/. Write permission not available.

F5 Product Development tracked this issue as ARX ID 35210 and it was fixed in ARX 5.0.1. For information about upgrading, refer to the ARX Release Notes.

Workaround

To ensure that the ARX redundancy quorum disk operation functions properly, you must manually create the hidden .acopia_qdisk directory created in the directory specified as the quorum disk share.
