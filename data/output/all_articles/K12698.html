Known Issue

Important: This issue was initially found on BIG-IP version 10.2.0 HF2; it has not been reported on any previous versions.

This is the result of a known issue. BIG-IP TMM ephemeral listeners are responsible for corresponding connections such as the data connections used for FTP. A small amount of memory is leaked each time the system sets up a data connection but the listener does not receive any data. When this occurs, TMM memory usage may continue to grow until all memory is consumed, causing TMM to eventually become unresponsive.

F5 Product Development tracked this issue as ID 351214 and it was fixed in BIG-IP LTM versions 10.2.2 and 11.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.

To determine whether a system is affected by this issue, you can monitor the listener count. To do so, use the following command syntax:

tmctl memory_usage_stat|head -2; tmctl memory_usage_stat |grep listener

The command output appears similar to the following example:

# tmctl memory_usage_stat|head -2; tmctl memory_usage_stat |grep listener
name

allocated max_allocated held size tot_allocs
---------------------------- --------- ------------- -------- ----- ----------
listener 65536 65536 256 256 256 <==
listener (variable) 384 384 384 1 10

If the number of allocated listeners (denoted by <==) continues to grow over time, this situation may indicate that the ephemeral listeners are experiencing a memory leak.

In the example, there is no problem as the system is only utilizing 256 allocated listeners out of the total 65536 allocated. When a memory leak is present, all reported allocations increase as the system does not release ephemeral listeners.
