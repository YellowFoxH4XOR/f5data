K47713230: Using the same format when importing the key to BIG-IP and BIG-IQ

Type
Support Solution
Published
2022-03-02
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.X.X
Source
https://my.f5.com/manage/s/article/K47713230

Description
BIG-IQ can manage the SSL certificates and keys on BIG-IP. When a BIG-IP device is added to the BIG-IQ, the LTM service on this BIG-IP can be discovered and imported to BIG-IQ. Then, the SSL certificates and keys on the BIG-IP will appear on BIG-IQ. However, they are in unmanaged status at first because only the object information instead of the data is synchronized to BIG-IQ. To fully manage them, you have to import the certificates and keys into BIG-IQ manually. In this scenario, you have to use the same data that is used for importing to BIG-IP.

Environment

  • BIG-IQ
  • SSL Key

Cause
When importing SSL certificate and key to BIG-IP, BIG-IP will save the certificate and key data into a local file in the same format as what you input. Then a file checksum will be generated based on this content to the certificate and key object. When the LTM service is discovered and imported to BIG-IQ, the same information (file checksum) will also be synchronized to BIG-IQ. Therefore, if you are using a different key format to import to BIG-IQ, an error message similar to the following will be popup:

File checksum does not match SSL Key <KEY_NAME>

On the other hand, if the key data is inconsistent (the header and footer have mismatching "RSA" indicator with the key data), different error message will be popup as below.

The key data is in PKCS#1 format while the header and footer are lacking of "RSA" indicator.

-----BEGIN PRIVATE KEY-----
<KEY_DATA_IN_PKCS#1>
-----END PRIVATE KEY-----

In this scenario, the following error message will appear:

Unable to read key: problem parsing PRIVATE KEY: java.lang.IllegalArgumentException: unknown object in getInstance: org.bouncycastle.asn1.ASN1Integer

The key data is in PKCS#8 format while the header and footer are indicating the "RSA".

-----BEGIN RSA PRIVATE KEY-----
<KEY_DATA_IN_PKCS#8>
-----END RSA PRIVATE KEY-----

In this scenario the following error message will appear:

Unable to read key: malformed sequence in RSA private key
These are expected behaviors.
Recommended Actions
  1. Make sure you're using the same certificate and key content when importing to both BIG-IP and BIG-IQ.
  2. If under some rare situation that you don't have the same content as BIG-IP when trying to import to BIG-IQ, you can try to covert the content.
  • Convert PKCS#1 to PKCS#8
# openssl pkcs8 -in <PKCS#1_FILE> -topk8 -nocrypt
  • Convert PKCS#8 to PKCS#1
# openssl rsa -in <PKCS#8_FILE>
