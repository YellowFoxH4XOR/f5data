Topic

The BIG-IP system provides statistics for various events when using the HTTP/2 optimized profile. 

Description

A virtual with an associated HTTP/2 profile enables the ability to gather various statistics about the traffic being optimized by the BIG-IP. These statistics can be retrieved using the GUI, TMSH, or SNMP.


Recommendations

To view the HTTP2 profile statistics using the GUI

  1. On the Main tab, click Statistics > Module Statistics > Local Traffic
  2. From the Statistics Type list, select Virtual Servers. By default, this displays the list of virtual servers on the BIG-IP system.
  3. In the Virtual Server column, click the name of the virtual server you would like to see Statistics for.
  4. Along the top of the screen, click the Statistics menu.
  5. In the Profiles area of the screen, from the Select Profile list, select an HTTP/2 profile. 


To view the HTTP2 profile statistics using TMSH

tmsh show ltm profile http2 my_http2

  Note: replace my_http2 with the name of your profile
You can monitor specific frame counters using the watch utility:

watch 'tmsh show ltm profile http2 my_http2 | grep RST_STREAM'

  Note: replace my_http2 with the name of your profile

To view the HTTP2 profile statistics using SNMP

snmpwalk -Of -c public -v 2c localhost ltmHttp2

Note: ltmHttp2 will show statistics for all http2 profiles

Understanding HTTP2 statistics

The frame is the smallest unit that transports specific data types, such as HTTP headers or message payloads. Frames from various streams can be mixed together and later reconstructed using the stream identifier found in each frame's header. The following table explains the various Frame identifiers: 
 

Frames
DATADATA frames convey arbitrary, variable-length sequences of octets associated with a stream. One or more DATA frames are used, for instance, to carry HTTP request or response payloads.
HEADERSHEADERS frames are used to open a stream and change connection state. 
PRIORITYPRIORITY specifies the sender-advised priority of a stream. 
RST_STREAMWhen the server receives a RST_STREAM, it will stop sending DATA frames to the client, thereby stopping the response (or the download). The connection is still usable for other requests.
SETTINGSThe SETTINGS frame communicates the configuration parameters for the connection specifically, not individual streams.
PUSH_PROMISEPUSH_PROMISE is used to notify the peer in advance of streams that the sender intends to initiate. It is a block that contains  all  request header field .
PINGPING measures Round Trip Time and idle connections.
GOAWAYGOAWAY initiates connections shutdown and used for error signaling. It can be used to begin a "graceful shutdown" of streams within the connection.
WINDOW_UPDATEA Flow control mechanism used to indicate the maximum data a sender can transmit.
CONTINUATIONIdentifies the headers are too large to fin in a single HEADERS frame, and this is a continuation of that data.



GoAway frames typically include Additional Debug Data that can be interpreted by the BIG-IP HTTP2 profile statistics. The Additional Debug Data can be seen on the wire using tcpdump or wireshark. The GoAway Reason counters increment when the Additional Debug Data message matches the counter.
 

GoAway Reasons
Compression ErrorThe endpoint is unable to maintain the header compression context for the connection.
Decompression ErrorThe endpoint is unable to decompress a header block.
TimeoutAn HTTP/2 connection idly left open was shut down.
Parse ErrorThe headers or http message was unable to be parsed.
Out Of Memory ErrorThe application has notified there has been an an out of memory error.
Stream ErrorFrame errors have occurred within the stream. For example If a DATA frame is received when its stream is not in an open or half-closed state.
Max Streams ExceededThe number of outstanding concurrent requests that are allowed on a single HTTP/2 connection has been reached
Max Headers ExceededThe Maximum Header Count from the HTTP profile being used in conjunction with the HTTP/2 profile has been exceeded 
Insufficient SecurityThe underlying transport has properties that do not meet minimum security requirements such as TLS Renegotiation or Compression.



Resources include the connection parameters from both clientside and serverside of the HTTP/2 protocol.              

Resources
ConnectionA single TCP (or TLS) session over which multiple streams run.
StreamA single bidirectional flow of frames (headers + data) within an HTTP/2 connection.
FlowF5’s full-proxy “message‐routing” construct representing one end-to-end HTTP request/response exchange; created at the start of a new request and destroyed when that exchange finishes
