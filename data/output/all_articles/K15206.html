K15206: The upgrade process no longer migrates HTTP Class profiles configured with invalid URLs

Issue

Old Behavior

In BIG-IP 11.4.0 and 11.4.1, the upgrade process converts HTTP Class profiles configured with invalid URLs to their equivalent local traffic policies but the mcpd process is unable to load the configuration on the BIG-IP system. This same behavior also applies when you attempt to restore a user configuration set (UCS) archive that contains HTTP Class profiles configured with invalid URLs in BIG-IP 11.4.0 or 11.4.1. A URL that does not start with http://, https://, or / is an invalid URL.

New Behavior

Beginning in BIG-IP 11.5.0, the upgrade process validates URLs configured in HTTP Class profiles. If the URLs are determined to be invalid, the upgrade process does not perform the conversion for the affected HTTP Class profiles. As a result, the affected HTTP Class profile no longer exists in the configuration of the upgraded BIG-IP system.

Similarly, if you restore a UCS archive that contains HTTP Class profiles configured with invalid URLs in BIG-IP 11.5.0 and later versions, the restoration process does not convert HTTP Class profiles configured with invalid URLs, and these profiles no longer exist. Additionally, the restoration process reports an error message for each affected HTTP Class profile similar to the following example:

ERROR: The httpclass profile(s) for policy <HTTP Class profile name> did not roll forward:
policy rule(s) created from <HTTP Class profile name> do not contain a proper URL.

Impact

HTTP Class profiles configured with invalid URLs no longer exist in the configurations of upgraded BIG-IP systems.

Recommended Actions

Before upgrading to BIG-IP 11.4.0 and later versions, you should consider the following factor:

  • For HTTP Class profiles that are configured with URLs, you must ensure that the URLs start with any of the following:

    • http://
    • https://
    • /
