Description

After uploading a third-party CA signed device certificate, including the certificate chain and CA certificate, into the file /config/httpd/conf/ssl.crt/server.crt,, the httpd daemon fails to start. The following error message is observed in the system logs:

httpd[22697]: [ssl:emerg] [pid 22697] SSL Library Error: error:0B080074:x509 certificate routines:X509_check_private_key:key values mismatch

This prevents access to the Configuration utility (GUI) and may impact management operations.

Environment

  • BIG-IP
  • Third-party CA signed certificates
  • DNS sync group

Cause

The issue is caused by the incorrect order of certificates in the file /config/httpd/conf/ssl.crt/server.crt. The device certificate must be at the top of this file, followed by the chain certificate, and the CA certificate at the bottom. If the order is incorrect, httpd will fail to start and report a key values mismatch error.

Recommended Actions

When preparing the certificate file, ensure the following order:

  • Device Certificate (top)
  • Chain Certificate (middle, if any)
  • CA Certificate (bottom)

Additional Information

Normally, when using a third-party CA signed certificate for the device, the file /config/httpd/conf/ssl.crt/server.crt should contain only the device's certificate. The chain and CA certificates are typically stored in /config/httpd/conf/ssl.crt/chain.crt..

However, if the device is part of a DNS sync group, and for proper iQuery communication, you must append any chain or root certificates directly into the /config/httpd/conf/ssl.crt/server.crt file, following the order described above. Refer to Replacing the Configuration utility's self-signed device certificate with a CA-signed device certificate
