Topic

This article describes how to keep the BIG-IP configuration you have imported into the BIG-IQ in sync with the configuration running on the BIG-IP system.

Description

When you add a BIG-IP device to the inventory of a BIG-IQ Centralized Management system, you can discover and import the service configurations (BIG-IP LTM and BIG-IP ASM are called services in the BIG-IQ system). BIG-IQ refers to the imported configuration from the BIG-IP system as the working configuration, which you can edit and use to deploy changes to the managed BIG-IP system. You perform these activities from the Configuration and Deployment > EVALUATE & DEPLOY pages of the BIG-IQ user interface. BIG-IQ refers to the configuration on the BIG-IP devices as the current configuration or running configuration, which updates after you deploy the changes from the working configuration. To keep the working and current configurations in-sync, you should make changes to only the working configuration within BIG-IQ.

For example:

  1. You create a node 10.1.1.1 on bigip1.example.com in the working configuration on the BIG-IQ.
  2. You deploy the change to bigip1.example.com and the current configuration updates.
  3. Both the working and current configurations are in sync.

If you make a change directly to the managed BIG-IP system, you must re-import the configuration from the BIG-IP system to the BIG-IQ so that the change is reflected in the BIG-IQ working configuration and you avoid overwriting the direct change you made on a subsequent deployment. Re-importing removes certain changes you made in the working configuration that you have not deployed, such as a node that is not associated to a pool, for example. Other inconsistencies trigger a conflict warning that you must resolve manually.

For example:

  1. You create a node 10.1.1.1 directly on bigip1.example.com.
  2. The change to the current configuration on bigip1.example.com does not exist in the BIG-IQ's working configuration.
  3. Neither the working nor current configurations are in sync, and you must re-import the configuration from BIG-IP system.

Recommendations

If you made configuration changes directly on a managed device bypassing BIG-IQ, you must re-discover and re-import the configuration so that both the working and current configurations are in sync. To do so, perform the following procedure:

Note: You cannot re-import SSL Orchestrator configurations from managed BIG-IP devices.

Impact of procedure: You may lose un-deployed configuration objects in the working configuration on the BIG-IQ.

  1. Log in to the BIG-IQ user interface.
  2. Go to Devices > BIG-IP DEVICES.
  3. Select the check box next to the device you want perform the procedure on.
  4. Select More > Re-discover and Re-import. The New Re-discovery and Re-Import page opens.
  5. Enter a name for the task.
  6. For Shared Object Conflict Policy, Version Object Conflict Resolution Policy, and Device Object Conflict Resolution Policy, select a method appropriate for your environment. For a description of the conflict resolution options, select the Help icon (?) or refer to the following list:
    • Select Use BIG-IQ to keep the object in the BIG-IQ system's working configuration. If you select this method for a shared object, the next time the BIG-IQ system deploys a configuration to that BIG-IP device, it updates the shared object to match the one on the BIG-IQ system.

      For example, if an HTTP profile called MyProfile with Insert X-Forwarded-For enabled is in the BIG-IQ working configuration and, on discovery of a service for BIGIP1, BIG-IQ encounters a profile called MyProfile with Insert X-Forwarded-For disabled, BIG-IQ keeps the MyProfile with Insert X-Forwarded-For setting enabled. The next time BIG-IQ deploys a configuration to the BIGIP1 device, it enables the Insert X-Forwarded-For setting of MyProfile.

    • Select Use BIG-IP to use the object from the BIG-IP device's current configuration to replace the object that is different in the BIG-IQ system's working configuration. If you select this method for a shared object, the next time it deploys a configuration, the BIG-IQ system replaces the shared object for all of your managed BIG-IP devices.

      Continuing with the previous example, if you select this option, the object imports into the BIG-IQ working configuration, and, for a shared object, the next time BIG-IQ deploys a configuration to any of the managed devices that contain MyProfile, it disables the Insert X-Forwarded-For setting if it is not already disabled.

    • Select Create Version if you want BIG-IQ to create and store a copy of the BIG-IP device's BIG-IP LTM monitor or profile object(s), specific to the software version running on that BIG-IP device. If you select this method, the next time it deploys a configuration, the BIG-IQ replaces that object for all the managed BIG-IP devices running that version. You can store multiple versions of BIG-IP LTM monitors or profiles. BIG-IQ deploys the appropriate stored version to your managed devices. The next time it imports services that contain BIG-IP LTM monitors or profiles, BIG-IQ automatically resolves conflicts against the appropriate version.

      For example, the values of properties or the properties themselves of profiles and monitors differ between BIG-IP versions.

  7. For Snapshot select the Create a snapshot of the current configuration before importing check box if you want to save a snapshot of the BIG-IP device's configuration before importing their services.
  8. Select Create. The system performs re-discovery and re-import.
  9. If applicable, locate any Import error for service messages in the Services column and select the message. This takes you to the SERVICES page for the device.
  10. Locate any Conflicts found, import halted messages and select Import for that service.
  11. In the Resolve Import Conflicts pop-up window, review the conflict list and confirm or change the action the BIG-IQ should perform. You can refer to the conflict resolution policies in the previous procedure. Select the configuration object to display the differences.
  12. Select Device Specific Objects and repeat the activities from the previous step.
  13. Select Continue.
  14. Review the conflict resolution definitions and select Resolve to import the BIG-IP configuration.
