Description

You are trying to add External Storage to the BIG IQ cluster but you it's failing with the following error:

The system returned an unexpected error (400 Bad Request). Mounting external storage failed due to command execution timeout. Please ensure there is no network connectivity issues between external storage server and ES cluster.

This article assumes that the connection is correct, and that both side direction from each BIG IQ to ES is working properly.


Environment

  • BIG IQ
  • External storage
Cause
Unknown at time of publication

 Recommended Actions

 1. For each BIG IQ (CM and DCD) in a cluster, check if the ES wasn't mounted already by: 
df -h
2. If mount point exist on any of the BIG IQs you have to umount it by: 
umount -l /var/config/rest/elasticsearch/data/essnapshot
3.If ES is not mounted on any of the devices, for all of them (CMs and DCDs) check the endpoint availability: 
curl http://localhost:8100/cm/shared/esmgmt/es-mount-filesystem | jq .
Output should be similar: 
 % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
100   194  100   194    0     0  25546      0 --:--:-- --:--:-- --:--:-- 32333
{
  "status": false,
  "generation": 0,
  "lastUpdateMicros": 0,
  "kind": "cm:shared:esmgmt:es-mount-filesystem:esmountfilesystemstate",
  "selfLink": "https://localhost/mgmt/cm/shared/esmgmt/es-mount-filesystem"
}

In case of curl stuck, restart restjavad process and rerun curl command. 
bigstart restart restjavad
4. When connectivity is fine, endpoints are responding, and you still cannot mount the External Storage, please raise a ticket to F5 Support.
