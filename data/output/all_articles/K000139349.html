K000139349: How to stop NGINX Server version disclosure

Type
Support Solution
Published
2024-04-19
Updated
2024-04-19
Applies to
  • NGINX Products
  • NGINX Plus: R31, R30, R28, R29
Source
https://my.f5.com/manage/s/article/K000139349

Description

  • You configured NGINX Plus to proxy request/response between users/clients and application server 
  • On the response HTTP Header, you notice NGINX version being displayed
        nginx:~$ curl localhost:8011 -v

            >
            * Mark bundle as not supporting multiuse
            < HTTP/1.1 200 OK
            < Server: nginx/1.25.1
            < Date: Fri, 19 Apr 2024 08:39:16 GMT
            < Content-Type: application/octet-stream
            < Content-Length: 2
            < Connection: close
            <
            * Closing connection 0
  • You want to hide NGINX version being displayed when it proxy response to client

Environment

  • NGINX Plus
  • HTTP Response Header
  • Server Version

Cause

  • None

Recommended Actions

  • The directive that manages server header is "server_tokens"
  • "server_tokens" directive is "on" by default.
  • You can include "server_tokens" from with in the http block, which can then be applied universally across your configuration.

Additional Information

First Option

  • You can keep the server header along the value of NGINX, while removing NGINX version
  • to do so,
    • edit /etc/nginx/nginx.conf file
    • append server_tokens off;
    • save and reload nginx configuration following "sudo nginx -s reload"

Response Header Example

        nginx:~$ curl localhost:8011 -v
          
              * Mark bundle as not supporting multiuse
              < HTTP/1.1 200 OK
              < Server: nginx
              < Date: Fri, 19 Apr 2024 08:39:59 GMT
              < Content-Type: application/octet-stream
              < Content-Length: 2
              < Connection: close
              <
              * Closing connection 0

Second Option

  • You can completely remove the server header from HTTP response header by appending "" to directive "server_tokens"
  • to do so,
    • edit /etc/nginx/nginx.conf file
    • append server_tokens "";
    • save and reload nginx configuration following "sudo nginx -s reload"

Response Header Example

        nginx:~$ curl localhost:8011 -v

              * Mark bundle as not supporting multiuse
              < HTTP/1.1 200 OK
              < Date: Fri, 19 Apr 2024 08:40:36 GMT
              < Content-Type: application/octet-stream
              < Content-Length: 2
              < Connection: close
              <
              * Closing connection 0
