Issue

Old Behavior

The BIG-IP iSeries platform includes a logical volume named appdata. In versions prior to BIG-IP 12.1.2, the TMOS installer reserves 36 GB for base installation images and 5 GB for swap, then allocates approximately 75 percent of the total available storage to the appdata volume. In addition to the appdata volume, the volume scheme allocates 10 percent of the total available storage to the share volume and 5 percent of the total available storage to the log volume.

New Behavior

On iSeries platforms running BIG-IP 12.1.2 or later, the TMOS installer continues to reserve 36 GB for base installation images and 5 GB for swap; however, the installer allocates approximately 85 percent of the total available storage to the appdata volume. In addition to the appdata volume, the installer continues to allocate 10 percent of the total available storage to the share volume and 5 percent of the total available storage to the log volume. If you plan to install more than three TMOS software volumes on your iSeries device, you can prevent the additional 10 percent space allocation to the appdata volume by ensuring you have three volumes with BIG-IP 12.1.1 installed before you install a new volume with a 12.1.2 upgrade.

After you upgrade the system to BIG-IP 12.1.2 and boot to the new software, the TMOS installer increases the appdata volume by an additional 10 percent. The system may log error messages in the /var/log/liveinstall.log file that appear similar to the following example:

Auto-resize disks and directories:  [  OK  ]
info: Increasing sda.dat.appdata size from 318259200 to 358020761 KiB

To compare vgs and lvs command output from before and after the appdata volume increase, refer to the following examples:

Note: Command output is truncated.

  • Before

    # vgs
      VG        #PV #LV #SN Attr   VSize   VFree
      vg-db-sda   1  17   0 wz--n- 447.12g 49.88g

    # lvs
      LV            VG        Attr      LSize   Pool Origin Data%  Move Log Cpy%Sync Convert
      dat.appdata   vg-db-sda -wi-ao--- 301.44g
      

  • After

    # vgs
      VG        #PV #LV #SN Attr   VSize   VFree
      vg-db-sda   1  17   0 wz--n- 447.12g 9.88g

    # lvs
      LV            VG        Attr      LSize   Pool Origin Data%  Move Log Cpy%Sync Convert
      dat.appdata   vg-db-sda -wi-ao--- 341.44g

F5 Product Development tracked this change as ID 618421.

Impact

The increased appdata volume size may prevent the installation of more than three TMOS images. The system may log error messages to the /var/log/liveinstall.log file that appear similar to the following example:

info: Installing packages.
error: tm_install::Process::Process_full_install -- predicted size for BIGIP1212 is 10365728 and vg has 10354688 remaining.
Terminal error: Disk full (volume group). See SOL#10636
*** Live install end at 2017/02/21 11:31:40: failed (return code 2) ***

Output from the command tmsh show sys software appears similar to the following example:

-------------------------------------------------------------------------------------------
Sys::Software Status
Volume  Product  Version    Build  Active                                            Status
-------------------------------------------------------------------------------------------
HD1.1    BIG-IP   12.1.1  0.0.184      no                                          complete
HD1.2    BIG-IP   12.1.1  0.0.184      no                                          complete

Note: If there are two 16.1.x or later boot locations, this issue may be encountered with an installation/upgrade to a third boot location.

Recommended Actions

To remove a failed installation, you can delete the volume by using the tmsh delete sys software volume <volume name> command syntax.

For example:

tmsh delete sys software volume HD1.4

Alternatively, you can reboot the device to clear the failed installation.

After the appdata volume has been increased through an upgrade or clean installation of BIG-IP 12.1.2 or later, you can manually reduce its size with the lvreduce utility. For more information, refer to K74200262: Reducing the size of the appdata volume with the lvreduce utility.
