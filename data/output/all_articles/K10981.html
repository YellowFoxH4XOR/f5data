K10981: The key pair for an SCP log archive is not restored from backup

Known Issue

This is the result of a known issue. When restoring the FirePass configuration from a backup file, the SSH key pair generated for an SCP log archive is not restored.

Note: SCP log archives are configured in the Purge logs section of the Device Management: Maintenance: Logs page. Some earlier versions of FirePass software refer to an SCP archive as an SSH archive.

Restoring from a backup file does not remove an existing SSH key pair associated with an SCP log archive. However, the backup file does not contain the key pair. Therefore, if restoring to an RMA unit or to a FirePass snapshot taken prior to the key generation, the key pair is not restored.

F5 Networks Product Development is tracking this issue as CR134501.

Workaround

You can work around this issue by generating a new key pair for the SCP archive. To do so, select the Generate and download new public key link under the archive configuration on the Device Management: Maintenance: Logs page. After downloading the new public key, cut and paste the key into the appropriate authorized_keys or authorized_keys2 file on the destination SSH server.
