Known Issue

The snmpd process may stop responding and generate a core file.

This issue occurs when the following condition is met:

  • You have changed the SNMP configuration on the BIG-IP system.

After the SNMP configuration changes, the snmpd process de-initializes/re-initializes its configuration. During the de-initialization process, the snmpd process fails to shut down its mcpd message timer thread, and creates an additional thread. This may occasionally cause the snmpd process to stop responding and eventually generate a core file.

Impact

The snmpd process may stop responding and generate a core file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H573034 on the Diagnostics > Identified > Low screen.
  • The snmpd process becomes unresponsive and generates a core file.
  • The snmpd process logs error messages to the /var/log/ltm file that appear similar to the following example:

    warning snmpd[10818]: 010e0004:4: MCPD query response exceeding 30 seconds

Workaround

To work around this issue, you can manually restart the snmpd process after making SNMP configuration changes. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the snmpd process by typing the following command:

    restart sys service snmpd
