Known Issue

The BIG-IP system stops sending iRules-based High-Speed Logging (HSL) messages.

This issue occurs when all of the following conditions are met:

  • You configure your BIG-IP system for HSL.
  • The destination HSL pool contains a single member.
  • You send HSL messages using the HSL::send iRules command.
  • The HSL destination pool member becomes temporarily unreachable.
  • The HSL destination pool member recovers.

Impact

The BIG-IP system stops sending iRules-based HSL messages to the configured HSL destination.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H687701 on the Diagnostics > Identified > Low page.
  • When the HSL logging destination becomes unavailable, the BIG-IP system stops sending HSL messages to the destination. However, after the HSL destination recovers, iRules-based HSL logging to the destination does not resume.

Workaround

To work around this issue, you can configure the HSL log destination pool with multiple destination servers. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Click the Name link of the pool.
  4. Click the Members tab.
  5. Click Add.
  6. Enter a new log destination IP address, fully-qualified domain name (FQDN), or select an existing address from the Node List.
  7. Enter the Service Port of the new destination log server.
  8. Click Finished.
