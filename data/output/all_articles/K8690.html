Known Issue

This is the result of a known issue. Enabling ARP on a network virtual address causes the BIG-IP system to answer both ICMP and ARP requests for an incorrect block of addresses outside the defined network address of the virtual server.

The following conditions are known to cause this behavior:

  • The network virtual server is created with ARP enabled on the virtual address
  • A self-IP address or host virtual IP address within the same network exists on the same VLAN
  • The last octet of the self IP address is divisible by 16, or is divisible by the netmask of the network virtual server

Example configuration:

Self IP Address: 172.17.0.32
Netmask: 255.255.0.0
Configured virtual server IP: 172.17.0.8:http
Configured virtual server mask: 255.255.255.248

Masking 172.17.0.32 with 255.255.255.248 results in 0.0.0.0. Therefore, the system responds to pings and ARPs to IP addresses 172.17.0.33, 172.17.0.34 through 172.17.0.39, although these IP addresses are not defined in the configuration.

F5 Networks Product Development tracked this issue as CR93352 and it was fixed in BIG-IP version 9.4.6. For information about upgrading, refer to the BIG-IP LTM, ASM, or Link Controller Release Notes.

Additionally, this issue has been fixed in BIGIP-9.6.1-839.0-HF3, which has been issued for BIG-IP version 9.6.1. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

For information about managing F5 Networks product hotfixes, refer to K6845: Managing F5 Networks product hotfixes.

Workaround

F5 Networks recommends that the ending octet of both the virtual server and the self IP address are an odd number, in order to prevent the BIG-IP system from answering for addresses that don't exist. For example, a self IP address of 172.17.0.33 will prevent this issue from occurring.
