Description

The device is not responding. Repeatedly, the similar to following error messages are observed on CLI

e.g.
FATAL:  could not remove old lock file "postmaster.pid": Read-only file system

Checking logs, you can see in many logs contains "read-only" message
grep -a -e "read-only" /var/log/*

e.g.
/var/log/kern.log: crit kernel: EXT4-fs (dm-12): Remounting filesystem read-only
/var/log/ltm:  PANIC: could not open control file "global/pg_control": Read-only file system
/var/log/daemon.log: err ntpd[<pid>]: frequency file /var/lib/ntp/drift.TEMP: Read-only file system
/var/log/sesure: Read-only file system: AH00811: Cannot open socache DBM file `/var/cache/mod_ssl/scache' for scanning
/var/log/asm/: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): Could not open /ts/lock/ts_db.lock: Read-only file system
/var/log/cron: Can't open timestamp file for job cron.daily: Read-only file system
/var/log/messages: cannot remove '/var/config/rest/node/tmp/BUILDROOT/f5-service-discovery-1.10.11-1.x86_64/var/config/rest/iapps/f5-service-discovery/package-lock.json': Read-only file system
/var/log/restjavad.log: commit: java.io.FileNotFoundException: /var/config/rest/storage/_8xzz_1id.del (Read-only file system)
/var/log/user.log: cannot remove '/var/config/rest/node/tmp/BUILDROOT/f5-service-discovery-1.10.11-1.x86_64/var/config/rest/iapps/f5-service-discovery/package-lock.json': Read-only file system

etc...

Environment

  • BIG-IP
  • Failure in GUI access 
  • CLI

Cause

This issue is caused by file systems errors which remounts the filesystem into a read-only state due to issues.
Tipically find similar to below messages appears in var/log/kern.log:

err kernel: blk_update_request: I/O error, dev vda, sector <sector_number>
warning kernel: EXT4-fs warning (device dm-12): ext4_end_bio:316: I/O error -5 writing to inode 6333 (offset 0 size 0 starting block <block_number>)
err kernel: Buffer I/O error on device dm-12, logical block <block_number>
crit kernel: EXT4-fs error (device dm-12): ext4_journal_check_start:56: Detected aborted journal
crit kernel: EXT4-fs (dm-12): Remounting filesystem read-only
...

Recommended Actions

Follow Recommended action in K14901024: How to recover from a read-only file system.
