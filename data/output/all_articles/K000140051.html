Description

Unable to deploy tenants to a VELOS blade:

Tenant deployment failed - Platform is not ready

Blade's /var/log/messages contains entries similar to the following:

IOMMU not ready: disabled

-or-

vfio-pci: probe of 0000:66:00.0 failed with error -22

Environment

  • VELOS blade
  • After partition upgrade or inserting blade

Cause

These symptoms indicate the Virtualization Technology options in the blade's BIOS are disabled. This has been observed in rare cases after a partition upgrade.

Bug ID 1574589 

Recommended Actions

It should be possible to (re)enable the Virtualization Technology option in the blade's BIOS, following these steps:

1. From the controller, console to the blade in question using the controller admin user credentials:

 ssh localhost -l admin -p 7002         # For example, port 7002 for blade-2

On successful login after submitting the controller's admin password, you will need to log in to the blade using the partition root user credentials:

Terminal session established
CentOS Linux 7 (Core)
Kernel 3.10.0-1160.119.1.f5.1.el7_8.x86_64 on an x86_64

blade-2 login:

Type root , then hit Enter key. Type the password when prompted, hit Enter again:

blade-2 login: root

Password: 

Last login: Thu Jul 2 12:33:51 on ttyS0

[root@blade-2 ~]# 

If the root password is not known, log in to the Partition GUI and change the password in the following location:

Partition GUI: AUTHENTICATION & ACCESS > Users & Roles > root > Set Password

2. Reboot the blade by entering the 'reboot' command. Alternatively, use the reset cpu' option on the AOM menu (ESC-shift+9).

[root@blade-2 ~]# reboot

3. During startup, tap 'b' to show the boot menu, select 'enter setup', then 'continue'.

4. Navigate to Socket Configuration > IIO Configuration > Intel. VT for Directed I/O (VT-d). Note what is displayed there.

5. Hit F3 then select 'yes' to load defaults.

6. Hit F4 then 'yes' to save and quit.

Note: The function keys (F3, F4 and so on) have been known to register as Esc in some cases, for example when using certain SSH clients such as PuTTY. The OpenSSH client built-in to Windows 11 is confirmed to work as expected.

7. Re-enter the BIOS again on startup, repeat step 4 and confirm that all settings are enabled.

8. Assuming all settings are enabled, hit 'esc' to quit and reboot. Wait for the blade to boot up.
