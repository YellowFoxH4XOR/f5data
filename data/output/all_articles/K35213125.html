Description

Enabling in-tmm monitoring caused http and https monitors to fail.

Environment

  • HTTP/HTTPs monitors
  • In-tmm monitor enabled
  • SNI
  • route domains

Cause

Use of in-tmm monitoring, which SNI feature requires, calls for stricter HTTP compliance for monitor send strings. Refer to article K16343688: HTTP monitor down after changing to in-tmm monitoring
 

Recommended Actions
 

Change the send string on the monitor to add the HTTP version explicitly, as recommended on: K2167: Constructing HTTP requests for use with the HTTP or HTTPS application health monitor. This is how it should look:

Before:

"GET /examplestring \r\n\r\n"

After:

"GET /examplestring HTTP/1.0\r\n\r\n"
 

Additional Information

Bug ID 944121: Missing SNI information when using non-default domain https monitor running in TMM mode.
