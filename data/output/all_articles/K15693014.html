Description

If you are unable to remote desktop via current access policy with iPadOS13, this may be due to not meeting the necessary criteria for the feature to function.
  • RDP connections fail from iPad device on version iPadOS 13.
  • You observe the following log message in /var/log/apm where the User Agent is "Macintosh" instead of "iPad':

    <big-ip_hostname> notice tmm[21976]: 01490506:5: /Common/<access_policy_name>:Common:<session_id>: Received User-Agent header: Mozilla%2f5.0%20(Macintosh%3b%20Intel%20Mac%20OS%20X%2010_15)%20AppleWebKit%2f605.1.15%20(KHTML%2c%20like%20Gecko)%20Version%2f13.0.1%20Safari%2f605.1.15.
Session ID in the above example is the unique APM session ID. For information refer to K15387: Overview of BIG-IP APM session cookies
  • You observe a Reset from the Client in both a packet capture and logged in /var/log/apm:

    <client_ip_address>    <virtual_server_ip_address>    TCP    190    50143 → 443 [RST] Seq=1227 Win=0 Len=0    6.421614000

    <big-ip_hostname> debug tmm[21976]: 019cffff:7: /Common/<access_policy_name>: RD: [C] <client_ip_address>.62128 i <virtual_server_ip_address>.443: server-side connection was reset, reason: TCP RST from remote system

Environment

  • BIG-IP Access Policy Manager (APM)
  • Native Remote Desktop configuration.
  • Apple iPad version iPadOS 13 client

Cause

The RDP information in the location header is crafted based on the client type. If Safari is presenting a MAC OSX User Agent instead of a iPad User Agent this may cause APM to generate the incorrect RDP information. According to the following apple developer thread, User Agent in Safari on iPadOS, this may be an artifact of iOS 13.x on iPad.

Recommended Actions

Disable the Request Desktop Website option in the iPad Safari settings. 

  1. Login to the iPad.
  2. Navigate to Settings > Safari > Request Desktop Website > All Websites.
  3. Disable the All Websites option and now the correct User Agent is displayed.
