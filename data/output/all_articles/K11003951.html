Known Issue

A Lightweight Directory Access Protocol (LDAP) query result triggers the apmd process to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP access profile access policy is configured with an AD Auth agent.
  • The access policy is configured with an LDAP query agent.
  • A user successfully authenticates to the access profile.
  • The LDAP query agent returns no query results.

Impact

You cannot establish an access session while the apmd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The apmd process produces a core file in the /shared/core/ directory.
  • The system logs a ** SIGABRT ** message to the /var/log/apm file.

Workaround

To work around this issue, you can modify the affected access policy that adds an additional Auth agent. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Note: You do not need to perform the following procedure if your Active Directory authentication environment does not require the Complexity check for Password Reset (password change) setting. In this scenario, you can replace the existing access policy AD Auth agent with a configured LDAP Auth agent.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles > Access Profiles List.
  3. To the right of the affected access policy name, click Edit to open the visual policy editor.
  4. Locate the LDAP query agent.
  5. Click the plus sign (+) to the left of LDAP Query agent.
  6. Click the Authentication tab.
  7. Select LDAP Auth agent.
  8. Click Add Item.
  9. Configure the LDAP configuration settings for your specific environment.
  10. Click Save.
  11. In the upper-left corner of the visual policy editor, click Apply Access Policy.
