Topic

F5 may provide temporary code patches or engineering hotfixes to address issues between eligible Major, Minor, and Point software releases. F5 produces engineering hotfixes only for customers who have active contracts with F5 Global Support or F5 Premium Plus Support. For information about the F5 engineering hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Purpose

You should consider using this procedure under the following conditions:

  • You want to install an engineering hotfix on a BIG-IP system.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have active contracts with F5 Global Support or F5 Premium Plus Support.

Description

This article applies to engineering hotfixes. The functionality provided for managing engineering hotfixes includes the following:

Hotfix detailDescription
Availability
  • Engineering hotfixes are normally provided by F5 Support through a support case.
  • Engineering hotfixes may be available on MyF5 Downloads when fixes are required for critical security issues.
Hotfix files
  • ISO: BIG-IP hotfix installation files are ISO archive files. For example,
    • Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso
  • MD5: The ISO installation file has a corresponding MD5 file for checking the integrity of the ISO file. For example,
    • Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso.md5
  • SIG: The ISO installation file is accompanied by an authenticity signature (.sig) file to verify the ISO file authenticity before the BIG-IP software installation. For example,
    • Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso.sig
Installation
  • Engineering hotfixes are installed using the Configuration utility or the TMOS Shell (tmsh).
  • The base image for the engineering hotfix must reside on the BIG-IP system and be stored in the default image location, /shared/images so the BIG-IP system can automatically install the image if needed when you perform a hotfix installation.
    • For example, if you install Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso on BIG-IP 16.1.4.1, the system automatically installs the BIG-IP 16.1.4.1 image before applying the hotfix; therefore, the 16.1.4.1 image must be available to the BIG-IP system. The same occurs when you install the hotfix to a new volume.
  • The hotfix installation automatically installs the running configuration and license from the current boot location to the target install location.
  • Hotfixes must be installed on an inactive boot location. When installing a hotfix, you must run the hotfix installation from an active boot location and specify an inactive boot location as the target install location. This behavior allows you to prepare an inactive boot location, in advance, by installing the hotfix on an existing volume or new volume, and then boot to the new location when you are ready to run the configuration.
    • For example, if the BIG-IP system is running BIG-IP 16.1.4.1 on the active boot location (for example, HD1.1), and you want to install Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso, prepare an inactive boot location for the installation (for example, HD1.2). During the maintenance window, you can then designate HD1.2 as the active boot location and boot the system to it. If you need to revert to the previous version, you can boot to the former-active boot location (HD1.1 in this example).
HA deploymentsHotfixes must be managed on each member of a redundant device group. A configuration synchronization (ConfigSync) does not synchronize a hotfix to a redundant system.
vCMP systemsFor Virtual Clustered Multiprocessing (vCMP) systems, engineering hotfixes that are stored and managed on the vCMP host are available for vCMP guests to install.

Procedures

Use the following procedures to manage BIG-IP hotfixes:

  • Obtain the engineering hotfix files
  • Import the hotfix files to the BIG-IP system
  • Verify the MD5 checksum of the hotfix image
  • Install a hotfix image
  • Verify the hotfix installation
  • Revert to a previous hotfix version or base software build

Note: The license check date is a static date built into the software version, and enforcement occurs during system startup. There is no license check enforcement during hotfix installation.

Obtain the engineering hotfix files

Engineering hotfixes are normally provided by F5 Support through a support case. On some occasions engineering hotfixes may be available on MyF5 Downloads when fixes are required for critical security issues.

If a F5 security advisory indicates that an engineering hotfix is available on MyF5 Downloads as a patch for the CVE, you can download the hotfix as follows:

  1. Follow the Download F5 products that are not NGINX products procedure in K000090258: Download F5 products from MyF5.
  2. To locate an engineering hotfix, select the appropriate release in the Product Container section and then scroll down to the Select a download file section, where you can download files as needed. Make sure the File Name and Description fields match the engineering hotfix you want to install.

    For example, when you select the 17.1.0.3 product container, you have the option to select the following engineering hotifx which was created to address an out-of-band security advisory (OOBSN) released on 10/27/23:

    Hotfix-BIGIP-17.1.0.3.0.75.4-ENG.iso    OOBSN 10/27/23 - ISO for EngHF 75 for ID1117229 ID1240121 ID1381357

  3. After downloading the ISO file, you must download the corresponding MD5 file.

    For example, the following MD5 file is used to check the integrity of the corresponding ISO file:

    Hotfix-BIGIP-17.1.0.3.0.75.4-ENG.iso.md5

Import the hotfix files to the BIG-IP system

After the hotfix and MD5 files are downloaded to your local workstation, you can use the Software Management page in the Configuration utility to import the files to the BIG-IP system. The Software Management interface automatically adds the hotfix file to the image library (the /shared/images directory) on the BIG-IP system.

Note: To install a hotfix on a vCMP system, use the Software Management page in the Configuration utility on the vCMP host system to import the hotfix images. BIG-IP software images that are stored and managed on the vCMP host are available for vCMP guests to install.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Software Management.
  3. Select the Hotfix List tab.
  4. Select Import.
  5. Select Choose File.
  6. Go to the location on your local drive where the hotfix ISO file resides.
  7. After you have selected the hotfix ISO, select Import.

Note: You may also use an alternate method, such as Secure Copy (SCP), to copy the hotfix files to the BIG-IP system. If you do so, you should make sure that the files are installed to the /shared/images/ directory on the BIG-IP system.

Verify the MD5 checksum of the hotfix image

After the hotfix files are imported on the BIG-IP system, and before you perform the installation, F5 recommends that you test the integrity of the ISO file to ensure file quality. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. To change to the /shared/images directory, type the following command:

    cd /shared/images

  3. To verify the hotfix file integrity, use the following command syntax:

    md5sum --check <hotfix.md5>

    For example, the following MD5 command and output verifies the integrity of the Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso file:

    md5sum --check Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso.md5
    Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso: OK

Install a hotfix image

After you have verified the MD5 checksum for the hotfix image, you can use the Configuration utility, or the command line, to install a BIG-IP hotfix. To do so, perform one of the following procedures:

Using the Configuration utility to install a hotfix image

Impact of procedure: When you restart and boot the system into the newly installed hotfix partition, there is a disruption in traffic unless your host is part of a high availability (HA) group.

  1. Log in to the Configuration utility.
  2. Go to System > Software Management.
  3. Select the Hotfix List tab.
  4. Select the check box for the hotfix image name you want to install.
  5. Select Install.
    Note: In BIG-IP 21.1.x and later you can select Dry Run before installing to simulate the hotfix installation (no changes are applied). View the results with tmsh show sys software dry-run status on the BIG-IP command line.
  6. For Select Disk, select an available disk
  7. For Volume Set Name, select a volume set or type a new volume set name.

    Note: You can use any combination of lowercase alphanumeric characters (a-z, 0-9) and the hyphen (-) character for the volume set name. The volume set name can be 1 to 32 characters in length, but cannot be only one 0 (zero) character (for example HD1.0 or MD1.0). For example, if the HD1 disk is active and you type siterequest into the volume set name, the system will create a volume set named HD1.siterequest and install the specified software to the new volume set.

  8. Select Install. If the string you type does not match an existing volume set, the system creates the volume set and installs the software.
  9. Under Installed Images, the Install Status column displays the hotfix installation progress.

After the installation is complete, if you want to activate the boot location that contains the hotfix, use the Configuration utility and browse to System > Software Management > Boot Locations, and then click the boot location that contains the hotfix installation. Clicking the Activate button automatically reboots the system to the specified boot location. For vCMP guest software activation steps, refer to K4704: Installing a configuration when activating a boot location.

Use tmsh to install a hotfix image

Impact of procedure: When you restart and boot the system into the newly installed hotfix partition, there is a disruption in traffic unless your host is part of a high availability (HA) group.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To install the hotfix image, use the following command syntax:

    Note: Include the create-volume option if you are adding a new volume to the system for the hotfix installation. Additionally, in BIG-IP 21.1.x and later you can include dry-run before installing to simulate the hotfix installation (no changes are applied). View the results with tmsh show sys software dry-run status.

    install sys software hotfix <hotfix_name>.iso volume <volume_name> [create-volume]

    For example, to install a hotfix on HD1.1, the command appears similar to the following example:

    install sys software hotfix Hotfix-BIGIP-16.1.4.1.0.50.5-ENG.iso volume HD1.1

  3. To show the status of the hotfix installation, type the following command:

    show sys software status

    For example, the following output indicates that hotfix build 0.50.5 is installing on volume HD1.3:

    -----------------------------------------------------------------------------
    Sys::Software Status
    Volume Product Version Build Active Status Allowed Version
    -----------------------------------------------------------------------------
    HD1.1 BIG-IP 16.1.4 0.0.2 yes complete yes
    HD1.2 BIG-IP 16.1.4.1 0.50.5 no complete yes
    HD1.3 BIG-IP 16.1.4.1 0.50.5 no installing hotfix yes

Verify the hotfix installation

After installing a hotfix, you can verify the installation using one of the following methods:

  • Using the Configuration utility
  • Using tmsh

Use the Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > Software Management.
  3. Note the following categories under Installed Images:
  • Product: Displays the F5 product related to the installed software image.
  • Version: Displays the F5 product version number related to the software image.
  • Build: Displays the F5 build number related to the associated software image.
  • Install Status: Displays the status of the installation operation of the associated image. During in-progress installation operations, this column displays a progress bar with the percent complete for the installation in progress. Next to the progress bar is a Details link that links to a page with more information about the installation in progress. If an installation fails, the system posts a Failed warning and a troubleshooting link, which links to a page with failure details.

Use tmsh

Note: To determine the hotfix version, note the first numeric value of the build of the hotfix release. For example, Build 4.0.420 signifies hotfix 4.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Type the following command:

    show /sys software

    For example, the following output indicates that hotfix build 0.50.5 is installed on volume HD1.2:

    -----------------------------------------------------------------------------
    Sys::Software Status
    Volume Product Version Build Active Status Allowed Version
    -----------------------------------------------------------------------------
    HD1.1 BIG-IP 16.1.4 0.0.2 yes complete yes
    HD1.2 BIG-IP 16.1.4.1 0.50.5 no complete yes

  3. To exit tmsh, type the following command:

    quit

Revert to a previous version or base software build

If you need to revert to the previous software version, you can boot to the formerly active boot location that contains the previous installation.
