Known Issue

The BIG-IP ASM system may leak memory under specific conditions in certain configurations.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system is configured with Application Security Synchronization enabled and is part of a device group that has Automatic Sync enabled.
  • A synchronization error occurs due to a full hard drive, or any of the following circumstances:
    • You are creating, importing, or deleting security policies.
    • The system accepts many policy builder learning suggestions simultaneously.
    • You modify policy builder settings of a security policy.

Impact

The synchronization process uses additional memory with each synchronization attempt, and eventually exhausts memory resources. When configured as part of a high availability (HA) device group, the device may fail over to a peer member.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view memory usage, you notice that the memory usage of the asm_config_server.p process continually grows over time.
  • In the /var/log/ts/asm_config_server.log file, you observe repeating log messages similar to the following example, where the <large numeric value> steadily increases.

    asm_config_server.pl|INFO|<date and time>|<pid>|F5::ASMConfig::Handler::spawn_async_handler,,0 calls handled since async startup (Waiting for previous handler to finish, Async incoming queue has <large numeric value> calls)

  • Before the failover event, in the /var/log/kern.log file, you observe log messages similar to the following example.

    warning kernel: [<numeric value>.<numeric value>] merged invoked oom-killer: gfp_mask=<hex>, order=0, oom_score_adj=0
    err kernel: [<numeric value>.<numeric value>] Out of memory: Kill process <pid> (bd) score 114 or sacrifice child

Workaround

To work around this issue, you can restart the asm_config_server process on all members of the device group. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP ASM system command line with administrative privileges.
  2. To restart the asm_config_server process, type the following command:

    killall asm_config_server.pl

    Note: The BIG-IP ASM watchdog process automatically restarts the asm_config_server process within 10-15 seconds.

  3. Repeat steps 1 and 2 on each member of the Application Security Synchronization-enabled device group.
