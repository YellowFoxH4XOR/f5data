Description

Environment

BIG-IP LTM

High Availability

Azure Cloud

Cloud Failover Extension

Cause

Issue is due to a miss configuration.

Configured the proxy host and port as:

sys db proxy.host {

value "null"

}

sys db proxy.port {

value "8080"

}

This is incorrect as the system will treat it as "using proxy null:8080".

Recommended Actions

The correct configuration for "not using proxy" is:

Sys db proxy.host {

value "<null>"

}

sys db proxy.port {

value "8080"

}

If a proxy is required for some reason, the first thing you need to know is the support by the CFE. For Azure, all control plane API calls will use the proxy while storage upload/download (data-plane) calls will not use the proxy. Hence, if the proxy is still required when making API calls and you understand the support limitation, you need to configure the proxy like this:

# tmsh modify sys db proxy.host value abc.com

# tmsh modify sys db proxy.port value 8080

# tmsh modify sys db proxy.protocol value https

Additional Information

How to Enable debug logging for further troubleshooting

Change is not required for enabling the debug logging towards the cfe.json file dump from the system. Make sure to perform the following step-by-step carefully:

1) Run the following command to dump the current running configuration:

#curl -su admin: -X GET http://localhost:8100/mgmt/shared/cloud-failover/declare | jq .declaration > cfe.json

2) Edit the cfe.json file dumped in step 1 above as what the arrow indicates below:

{

 "class": "Cloud_Failover",

 "environment": "azure",

 "controls": {       <=====

 "class": "Controls",   <=====

 "logLevel": "silly"   <=====

 },

 "externalStorage": {

 "scopingTags": {

  "f5_cloud_failover_label": "HCL-F5-RG"

 }

 },

<...>

3) Submit the modified cfe.json configuration to CFE:

#curl -su admin: -X POST -d @cfe.json http://localhost:8100/mgmt/shared/cloud-failover/declare | jq

4) Run the following commands in order, then save all of the command output from these 4 steps (as what "failover log.txt" do):

#curl -su admin: -X GET http://localhost:8100/mgmt/shared/cloud-failover/info | jq

#curl -su admin: -X GET http://localhost:8100/mgmt/shared/cloud-failover/inspect | jq

#curl -su admin: -X POST -d '{"action":"dry-run"}' http://localhost:8100/mgmt/shared/cloud-failover/trigger | jq
