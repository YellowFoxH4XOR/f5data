Known Issue

The BIG-IP system may fail to delete the AD or LDAP group's retrieval temporary files.

This issue occurs when all of the following conditions are met:

  • You have an Access Policy configured with the AD Group Mapping agent or LDAP Group Mapping agent.
  • The queried AD or LDAP servers have a large number of groups.
  • You cause the BIG-IP APM to update the AD or LDAP groups multiple times in quick succession.

Impact

The system does not delete temporary files from the /tmp directory that were generated by the AD or LDAP group's update.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view the contents of the /tmp directory, you see multiple files with naming conventions similar to the following examples:

    • ad_temp_<numeric value>
    • ldap_temp_<numeric value>
  • In extreme scenarios these files may use all available resources of the /tmp directory.
  • If the /tmp directory resources are exhausted, processes that require the use of the /tmp directory may not function correctly, which impacts system performance.

Workaround

To work around this issue, you can create a cron process to remove the temporary files on a regular basis. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP APM system.
  2. As root, use a text editor to open the file /etc/crontab.
  3. Add the following lines to the bottom of the file:

    0 1 * * * root /bin/rm -f /tmp/ad_temp_*
    0 1 * * * root /bin/rm -f /tmp/ldap_temp_*

    Note: These lines instruct crontab to remove all of the files that start with ad_temp_ or ldap_temp_ in the /tmp directory at 1:00 AM daily.
     
  4. Save the modifications to /etc/crontab.

    Note: Subsequent BIG-IP APM system software upgrades or UCS restoration may overwrite the changes you made to the /etc/crontab file.
