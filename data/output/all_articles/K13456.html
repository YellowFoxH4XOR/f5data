Topic

Starting in BIG-IP 12.1.0, you can use local authentication as a backup method for remote RADIUS authentication. For more information, refer to K03546096: Configuring local authentication as a backup method for remote RADIUS authentication (12.1.x).

Starting in BIG-IP 13.0.0, you can use local authentication as a backup method. For more information, refer to K65475221: The BIG-IP system allows using local authentication as a backup method.

By default, the BIG-IP system uses its own user directory for user authentication. In BIG-IP 10.x - 12.x, if you configure a remote authentication method, such as Lightweight Directory Access Protocol (LDAP), Remote Authentication Dial-in User Service (RADIUS), or TACACS, the system does not allow you to use local authentication as a backup method for remotely stored user accounts in the event that remote authentication fails; if the remote authentication server is unavailable to answer authentication requests, only locally defined user accounts, such as the default administrator account and the root command line account, will be able to log in to the system.

For example, if you change the authentication method from Local to Remote - LDAP, the system uses a remote Active Directory server to authenticate users. If the remote Active Directory server fails or is unavailable, the system does not fall back to the local user directory for user authentication, only the default users of admin and root are authenticated locally in this scenario. Remote authenticated users will not authenticate and login attempts fail even when the user is configured in the local authentication user list.

The BIG-IP system may incorrectly authenticate users when remote radius authentication fails. For more information, refer to K13453: The BIG-IP system may incorrectly use local authentication as a backup when remote radius authentication fails.
