K85996550: Response Policy Zone(RPZ) Records Are Not Enforced while ''Logs and Stats Only'' Is Enabled.

Description

When you send a request that matches the RPZ zone records, you may find the BIG-IP leaves log messages like below in the /var/log/ltm, but it does not enforce the policy as the log describes.

01010268:5: cache /Common/PRZ_EXAMPLE_Cache RPZ QNAME-match rewrite: client 192.168.1.2 queried for rpzblock.example.com, action NXDOMAIN
01010268:5: cache /Common/PRZ_EXAMPLE_Cache RPZ QNAME-match rewrite: client 192.168.1.2 queried for rpzblock.example.com, action Walled Garden

When the Logs and Stats Only option is checked, queries that match a malicious domain in the RPZ list are logged and statistics are created; however, RPZ policies are not enforced. That is saying, when a DNS query matches a malicious domain in the RPZ list, the system does not return an NXDOMAIN response or redirect the query to a walled garden.

Environment

  • BIG-IP DNS
  • Response Policy Zone
  • Logs and Stats only option is enabled(checked)

Cause

None, this is expected behavior by the design.

Recommended Actions

To find your configuration on the Logs and Stats Only option and remove it, you may follow the below procedures:
Using Configuration Utility,

  1. On the Main tab, click DNS > Caches > Cache List.
    The DNS Cache List screen opens.
  2. Click the name of the cache you want to examine.
    The properties screen opens.

  3. On the menu bar, click Response Policy Zones.
    The Response Policy Zones screen opens.

  4. Click the name of the RPZ you want to examine.
  5. Examine the Logs and Stats Only checkbox 
  6. To disable the Logs and Stats Only option, please uncheck the Logs and Stats Only checkbox and click update.

Using tmsh,

  1. Enter the tmsh interactive shell:
    tmsh

  2. Check the Logs and Stats Only option by the below command:
    list ltm dns cache <cache-type> <cache-name> { response-policy-zones }
    The below example shows a transparent cache named with RPZ_EXAMPLE_CACHE that has the Logs and Stats Only option enabled:
    list ltm dns cache transparent RPZ_EXAMPLE_CACHE { response-policy-zones }
    Outputs:
    ltm dns cache transparent RPZ_EXAMPLE_CACHE {
        response-policy-zones {
            rpzblock.example.com {
                action walled-garden
                app-service none
                logs-and-stats-only yes
                walled-garden sorry.example.com
            }
        }
    }

  3. To disable the Logs and Stats Only option, use the below command:
    modify ltm dns cache <cache-type> <cache-name> { response-policy-zones modify {<block-domain> { logs-and-stats-only no } } }
    For example, to disable the Logs and Stats Only option for above example:
    modify ltm dns cache transparent RPZ_EXAMPLE_CACHE { response-policy-zones modify {<block-domain> { logs-and-stats-only no } } }

  4. Save your configuration by the below command:
    save sys config
