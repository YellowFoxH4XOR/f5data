Description

As of version 2.20.x, NGINX Instance Manager does not provide a built-in feature to display a custom security or compliance banner on the login page or within the GUI.
To show such a message (e.g., user obligation, warning, or legal notice), manual modification of application files is required.

Environment

  • Product: NGINX Instance Manager
  • Versions: 2.18.0 and above (including 2.20.0)
  • Deployment: On-premises installation
  • Requirement: File system access to the NGINX Instance Manager host

Cause

  • There is no configuration option or GUI setting in NGINX Instance Manager to display a custom banner on the login page or after login. This limitation is inherent to current product design.

Recommended Actions

Workaround:
A custom banner can be displayed by directly editing frontend JavaScript files on the NGINX Instance Manager host system. This workaround is not officially supported and may be lost after upgrades or patches.

Steps for NGINX Instance Manager 2.18.0 and above:

  1. SSH into the host system
    Access the server where NGINX Instance Manager is installed.
  2. Navigate to UI assets directory
    cd /var/www/nms/ui/assets/
  3. Identify the main JavaScript file
    Look for a file named similar to index-xxxxxxx.js.gz (the exact name varies by version).
    Use browser developer tools (F12) on the login page and search for "Log in to get started" in loaded JS files to confirm which file renders this text.
  4. Backup the original file
    sudo cp index-xxxxxxx.js.gz index-xxxxxxx.js.gz.bak
  5. Edit the JavaScript file
    sudo vi index-xxxxxxx.js.gz
    Search for:

    Log in to get started

    Replace:

    {children:[_.jsx("h3",{children:"Log in to get started"}), ... ]}

    with:

    {children:[_.jsx("h7",{children:"<Your custom security banner message here>"}), ... ]}

    *(Replace <Your custom security banner message here> with your actual warning or compliance text.)*
  6. Save changes and exit editor
  7. Reload NGINX Instance Manager login page
    Open your browser and refresh the login screen.
    The new banner should appear as specified.

Important: This workaround only affects content shown before authentication (login page).
The filename may change between versions; always verify using browser developer tools.
Changes will be overwritten during upgrades/patches—reapply if needed after updates.
Modifying these files does not affect core functionality nor void support, but it is not an officially supported customization by F5/NGINX.
