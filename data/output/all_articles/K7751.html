Summary

Clustered Multiprocessing (CMP) is a feature that was added in BIG-IP 9.4.0. CMP allows specific platforms with multiple processing cores to use multiple Traffic Management Microkernel (TMM) instances to increase traffic management capacity.

The following table lists the CMP-compatible platforms and supported TMM instances:

Description

CMP should not be confused with Symmetric Multi-Processing (SMP). SMP architecture is used in multiple operating systems. SMP operates by allowing operating systems and software applications that are optimized for SMP to use the multiple processors available to the operating system. SMP performs this operation by spreading multiple threads across multiple processors, which allows for faster processing and more efficient use of system resources, as multiple threads can be processed simultaneously instead of waiting in a queue to be processed. CMP uses a similar approach to leverage multiple processing units by spawning a separate instance of the TMM process on each processing unit available to the system. While SMP may be used for any process, CMP processing is available only to the BIG-IP TMM process for the sole purpose of providing more dedicated resources to manage load balanced traffic. With multiple TMM instances simultaneously processing traffic, system performance is enhanced, and traffic management capacity is expanded.

The CMP feature is automatically enabled on CMP-capable platforms, ensuring that all instances of TMM are available to process application traffic as follows:

  • Two TMM processes running on a dual-CPU BIG-IP 8400 system
  • Four TMM processes running on a dual-core, dual-CPU BIG-IP 8800 system
  • 32 TMM processes running on a VIPRION platform with four 2100 blades

Load balancing behavior on CMP enabled virtual servers

Connections on a CMP enabled virtual server are distributed among the available TMM processes. The load balancing algorithm, specified within the pool associated with the CMP enabled virtual server, is applied independently in each TMM. Since each TMM handles load balancing independently from the other TMMs, distribution across the pool members may appear to be incorrect when compared with a non-CMP enabled virtual server using the same load balancing algorithm.

Consider the following example configuration:

Virtual Server: 172.16.10.10:80

Pool with 4 members: 10.0.0.1:80
10.0.0.2:80
10.0.0.3:80
10.0.0.4:80

Pool Load Balancing Method: Round Robin

Scenario 1: Virtual server without CMP enabled

Four connections are made to the virtual server. The BIG-IP system load balances the four individual connections to the four pool members based on the Round Robin load balancing algorithm:

--Connection 1--> | | --Connection 1--> 10.0.0.1:80
--Connection 2--> |-> BIG-IP Virtual Server ->| --Connection 2--> 10.0.0.2:80
--Connection 3--> | | --Connection 3--> 10.0.0.3:80
--Connection 4--> | | --Connection 4--> 10.0.0.4:80

Scenario 2: Virtual server with CMP enabled on a BIG-IP 8800

Four connections are made to the virtual server, unlike the first scenario where CMP was disabled, the BIG-IP distributes the connections across the multiple TMM processes. The BIG-IP 8800 with CMP enabled can use four TMM processes. Since each TMM handles load balancing independently of the other TMM processes, it is possible that all four connections are directed to the same pool member.

--Connection 1--> | | --Connection 1--> TMM0 --> 10.0.0.1:80
--Connection 2--> |-> BIG-IP Virtual Server ->| --Connection 2--> TMM1 --> 10.0.0.1:80
--Connection 3--> | | --Connection 3--> TMM2 --> 10.0.0.1:80
--Connection 4--> | | --Connection 4--> TMM3 --> 10.0.0.1:80

The CMP feature is designed to speed up connection handling by distributing connections across multiple TMM processes. While initially this behavior may appear to favor one or several servers, over time the load will be distributed equally across all servers.

CMP restrictions in BIG-IP 10.x

In BIG-IP 10.x, most CMP restrictions from previous versions were lifted. For example:

  • CMP remains enabled when running BIG-IP system modules such as Application Security Manager and WebAccelerator.
  • CMP supports the use of all persistence options.
  • CMP supports the use of read-only (static) global variables within iRules.
  • CMP supports both limited software compression and limited hardware compression.
  • SSL CMP @ 500 TPS per core is now enabled in the base license for the BIG-IP 1600, 3600, 3900, 6900, 8900, and VIPRION platforms.

In BIG-IP 10.x, if a virtual server uses any of the following BIG-IP features, CMP is disabled for that virtual server and handled by TMM0 only:

  • An iRule using a non-static global variable
  • An iRule which refers to a Data Group List (class) using the $:: global variable prefix

CMP restrictions in BIG-IP 9.6.x

In BIG-IP 9.6.x, if a virtual server uses any of the following BIG-IP features, CMP is disabled for that virtual server and is handled by TMM0:

  • A rate class
  • An iRule using a global variable, including iRules that refer to a Data Group List (class) using the $:: global variable prefix
  • A persistence profile or iRule using a method other than cookie persistence or CMP persistence

    Note: The BIG-IP VIPRION introduced CMP Persistence in 9.6.0. CMP Persistence adds support for session persistence mirroring when TMM is running in CMP mode. Persistence mirroring is a mode of operation where the VIPRION system mirrors persistence records to other blades in the same cluster, or to the other cluster in a redundant system.

  • Traffic Management Operating System (TMOS) plug-ins
  • An SSL profile when SSL CMP is not licensed for the system
  • An HTTP profile with Compression enabled, and the system is licensed for limited software compression only, or contains a hardware compression card but is not licensed for maximum/unlimited compression

CMP restrictions in BIG-IP 9.4.x

Important: Some sub-releases have additional restrictions in addition to those affecting the entire 9.4.x branch. Be sure to read both this section and the section for your version below.

In BIG-IP 9.4.x, CMP is not compatible with certain BIG-IP system configurations. If any of the following configurations exist, CMP will be disabled system-wide:

  • The BIG-IP system is running the BIG-IP ASM or the BIG-IP WebAccelerator module.

In BIG-IP 9.4.x, if a virtual server uses any of the following BIG-IP features, CMP is disabled for that virtual server and handled by TMM0 only:

  • A rate class
  • An iRule using a global variable
  • A persistence profile or iRule using a method other than cookie persistence or CMP persistence
  • Traffic Management Operating System (TMOS) plug-ins
  • An SSL profile when SSL CMP is not licensed for the system

    Note: SSL CMP is a licensed module that allows SSL acceleration with CMP-enabled virtual servers. SSL CMP is enabled by default when the system is licensed for 30000 TPS or greater. To determine if your system is licensed for SSL CMP, you can review the license information located under System > License for one of the following entries in the Active Modules section:

    • ADD SSL CMP
    • Add SSL 30000 TPS (This option automatically enables SSL CMP.)
  • An HTTP profile with Compression enabled, and the system is licensed for limited software compression only, or contains a hardware compression card but is not licensed for maximum/unlimited compression

    Note: To determine if your BIG-IP is licensed for maximum/unlimited compression and contains a hardware compression card, type the following command at the command line:

    bigpipe version | grep -i compress

    The following output is displayed if the system is licensed for unlimited HTTP compression:

    HTTP Compression unlimited

    The following output is displayed if the system includes a hardware compression card:

    HTTP Hardware Compression

CMP restrictions in BIG-IP 9.4.6 through 9.4.8

In addition to the general limitations listed above, which affect the entire 9.4.x software branch, in BIG-IP 9.4.6 through 9.4.8, if a virtual server uses any of the following BIG-IP features, CMP is disabled for that virtual server and handled by TMM0 only:

  • An iRule that refers to a Data Group List (class) using the $:: global variable prefix

CMP restrictions in BIG-IP 9.4.3 through 9.4.5

In addition to the general limitations listed above, which affect the entire 9.4.x software branch, in BIG-IP 9.4.3 through 9.4.5, if a virtual server uses any of the following BIG-IP features, CMP is disabled for that virtual server and handled by TMM0 only:

  • An L7 protocol profile that supports related connections, such as FTP or RTSP
  • An iRule that refers to a Data Group List (class) using the $:: global variable prefix

CMP restrictions in BIG-IP 9.4.0 through 9.4.2

In addition to the general limitations listed above, which affect the entire 9.4.x software branch, in BIG-IP 9.4.0 through 9.4.2, CMP is not compatible with certain BIG-IP system configurations. If any of the following configurations exist, CMP will be disabled system-wide:

  • The BIG-IP system is running BIG-IP GTM module.

In addition to the general limitations listed above, which affect the entire 9.4.x software branch, in BIG-IP 9.4.0 through 9.4.2, if a virtual server uses any of the following BIG-IP features, CMP is disabled for that virtual server and handled by TMM0 only:

  • An iRule that refers to a Data Group List (class)
  • Cookie persistence
  • An L7 protocol profile that supports related connections, such as FTP or RTSP

Recommendations

Benchmarking throughput performance on CMP systems

CMP relies on an equitable hash distribution of traffic among a cluster of traffic processing cores and internal backplane connections. This architecture is optimized for real-world traffic, which generally includes a large variation of IP addresses and L4 port tuples.

When testing throughput performance on CMP systems, the benchmark test should be configured to match real-world traffic. For example, configuring the benchmark test to use multiple concurrent connections with many source IP addresses, several virtual servers and multiple pool members will yield a better test result. This is because CMP spreads connections across processing cores and traffic will also be more evenly distributed among the internal backplane paths.

Disabling or enabling CMP for a virtual server

For performance reasons, F5 recommends that you leave the CMP feature enabled. However, you may occasionally need to disable CMP for a virtual server. To do so, perform the following steps:

  1. Log in to the command line.
  2. Use the following command syntax:

    bigpipe virtual <virtual_server_name> cmp <disable/enable>

    For example, to disable CMP mode for the virtual server named CMP_vip, type the following command:

    bigpipe virtual CMP_vip cmp disable

  3. Save the changes made to the virtual server by typing the following command:

    bigpipe save

Verifying whether CMP is enabled or disabled for a specific virtual server

To verify whether CMP is enabled or disabled for a virtual server, use the following command syntax:

bigpipe virtual <virtual_server_name> cmp show

For example, the following bigpipe virtual cmp show command output indicates that CMP mode is enabled for the virtual server named CMP_vip:

VIRTUAL CMP_vip - CMP: enable

However, even if CMP is enabled on a virtual server, the BIG-IP system will demote a virtual server with incompatible features from CMP processing. To verify whether the BIG-IP system has demoted a specific virtual server even though CMP is enabled, use the following command syntax:

bigpipe virtual <virtual_server_name> cmp mode show

For example, the following bigpipe virtual cmp mode show command output indicates that the virtual server named CMP_vip_demoted has been demoted from CMP processing:

VIRTUAL CMP_vip_demoted - CMP mode: single

Note: Depending on your BIG-IP software version, the output may report enable or all to indicate that the CMP mode is enabled for the virtual server. Output reporting none, disable, or single indicates that the CMP mode is disabled for the virtual server.

Disabling / enabling CMP globally

To disable CMP globally on the BIG-IP system, perform the following steps:

Important: Disabling CMP globally should only be done based on a recommendation from F5, as doing so can have a dramatic impact on overall system performance.

Note: Some platforms do not support this procedure. For more information, refer to K12680: The BIG-IP 8950 and 11050 platforms do not support disabling CMP globally and K13911: The 2400 and 4400 platforms do not support disabling Clustered Multiprocessing globally.

  1. Log in to the command line.
  2. Use the following command, depending on whether you want to disable or enable CMP on the platform:

    Type the following command to disable CMP:

    bigpipe db Provision.tmmCount 1

    Type the following command to enable CMP:

    bigpipe db Provision.tmmCount 0

  3. Reboot the system.
