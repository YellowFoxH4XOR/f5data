Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator is designed to serve a stale object from the cache until the Stand-in Period has expired without reporting an error message. However, the Stand-in Period is only honored when the origin web server (OWS) responds with an HTTP 404 Not Found, 500 Internal Server Error, or 504 Gateway Timeout response status. If the web service is down or the OWS cannot respond for any reason, the Stand-in Period is ignored. When this occurs, the BIG-IP WebAccelerator does not send a response to the client, and the client request eventually times out. 

Important: Regardless of whether a Stand-in Period has been defined, the BIG-IP WebAccelerator will not generate an HTTP 404 Not Found status when the requested content has expired and the BIG-IP WebAccelerator cannot retrieve fresh content from the OWS. Any HTTP 404 Not Found response received from the BIG-IP WebAccelerator is proxied from the OWS.

Note: If an application health monitor has marked all the pool members as unavailable, the virtual server accepts client connections, but does not respond to HTTP requests. Although the symptom is the same, this is a different issue. For more information, refer to K8743: The Stand-in Period cache setting for a BIG-IP WebAccelerator acceleration policy is not honored if all pool members are marked down by a monitor.

F5 Product Development is tracking this issue as ID247725.

Workaround

You may be able to work around this issue by forcing an HTTP 404 Not Found response from an alternate web server when all members of the OWS pool are unavailable. To do so, perform the following procedure:

  1. Create a ForceStandin pool which contains at least one active webserver. The webserver need not host any specific content, but simply respond with an HTTP 404 Not Found status to all requests send to the BIG-IP WebAccelerator enabled virtual server.
  2. Associate the following iRule with the BIG-IP WebAccelerator enabled virtual server:

    Note: Replace OWS_pool with the name of the pool containing your OWS.

    when HTTP_REQUEST { 
      if { [active_members OWS_pool ] !=0 } {
        pool ows_WA_pool
      } else {
        pool ForceStandin
      }
    }

When all members of the original pool are unavailable, the iRule will select the ForceStandin pool and the request will be processed. When the request is for a previously cached object and the Stand-in Period setting is not expired, the object will be served from cache.

Note: For information about creating pools and iRules, refer to the BIG-IP LTM Configuration Guide.
