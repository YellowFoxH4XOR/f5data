K03413033: BIG-IQ Cluster stuck in ''Restarting''

Type
Support Solution
Published
2021-09-21
Updated
2025-04-01
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K03413033

Description

When viewing the BIG-IQ DCD cluster status, it never shifts out of "Restarting"

  • No statistics are collected from BIG-IQ
  • When trying to view the cluster health with    
    curl -s -u admin:<password> --insecure https://localhost:9200/_cluster/health?pretty

Note: Replace <password> with the admin password of the device.

The result is:



    ============================
==== ES Cluster Health =====
============================
# curl -s -u admin:<password> --insecure https://localhost:9200/_cluster/health?pretty
{
  "error" : {
    "root_cause" : [
      {
        "type" : "master_not_discovered_exception",
        "reason" : null
      }
    ],
    "type" : "master_not_discovered_exception",
    "reason" : null
  },
  "status" : 503
}

Environment

  • BIG-IQ CM with DCD's deployed
  • DCD data collection nodes for collection of statistics/module data

Cause

The cause appears to be that the master DCD node was never elected in the cluster.  This can be due to network issues, or possibly data corruption.

Recommended Actions

  1. Use SSH to log in to the first DCD in the cluster. 
     
  2. Restart the Elasticsearch service by running the command:
      bigstart restart elasticsearch.

    Restarting the service for each DCD in the cluster triggers a new master node election. After the last DCD in the cluster is restarted, the cluster status should change to healthy (green).
     
  3. Once completed, the cluster returns to indexing, but may have an issue with a large number of unassigned shards. Clear the unassigned shards with this command:
  curl -s -k https://localhost:9200/_cat/shards | grep UNAS | awk '{print $1}' | sort | uniq | sed 's/+/%2B/g' | while read line ; do curl -s -k -X DELETE "https://localhost:9200/$line" ; done
