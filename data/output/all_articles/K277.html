Topic

You should consider using this procedure under the following condition:

  • When delegating subdomains from a DNS server to BIG-IP DNS or BIG Link Controller systems.

Description

When you use a BIG-IP DNS or BIG-IP Link Controller system to provide wide area load balancing services, you may need to delegate authority for specific host names from the primary DNS server to the BIG-IP system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP DNS or BIG-IP Link Controller system has previously been deployed with the appropriate supporting configuration.
  • You have administrative access to the Primary DNS system for your site.
  • You have a general understanding of BIG-IP DNS or BIG-IP Link Controller systems and DNS configurations.

Procedures

Primary DNS subdomain delegation

Complete the following steps to configure the DNS server to delegate a subdomain to the BIG-IP DNS or BIG-IP Link Controller system.

Impact of procedure: Due to the nature of DNS, F5 recommends that you perform this procedure during a maintenance window with sufficient time allotted for DNS propagation.

  1. Create a new subdomain for which the BIG-IP DNS or BIG-IP Link Controller system is authoritative.

    Make sure the subdomain contains the host names to be load balanced. In most cases, it makes sense to create a new subdomain that is used only for this purpose. For example, the subdomain name wip is often used.

  2. Delegate authority for the entire subdomain to the BIG-IP DNS or BIG-IP Link Controller system.

    On the primary DNS server, delegate authority for the subdomain to the BIG-IP DNS or BIG-IP Link Controller system by modifying the parent zone to include nameserver (NS) records for the new zone, and address (A) records for the new nameservers referenced in the NS records.

    For example, to delegate authority for the wip.example.com subdomain to the BIG-IP DNS systems named gtm1.example.com and gtm2.example.com, the parent zone file should contain the following entries:

    wip IN NS gtm1.example.com. IN NS gtm2.example.com.
    gtm1.example.com. IN A 192.168.101.254
    gtm2.example.com. IN A 192.168.102.254

  3. On the primary DNS server, create a CNAME alias in the parent zone for the host name to be load balanced. The CNAME alias must reference a host name in the subdomain you delegated in step 2.

    For example, to have the BIG-IP DNS or BIG-IP Link Controller system load balance traffic for the www.example.com host name, the example.com zone should contain the following entry:

    www.example.com. IN CNAME www.wip.example.com

  4. On the BIG-IP DNS or BIG-IP Link Controller system, create a wide IP using the CNAME you just created. Continuing with the previous example the wide IP you create would be www.wip.example.com.

    When a client requests DNS resolution for the host name www.example.com, the DNS server that is authoritative for the example.com domain responds with the CNAME (alias) record www.wip.example.com. The client then requests resolution for the host name www.wip.example.com. Since the example.com zone points to gtm1.example.com and gtm2.example.com as the authoritative nameservers for the subdomain wip.example.com, the resolution request for www.wip.example.com is then sent to one of the BIG-IP DNS systems. The BIG-IP DNS system sends a response to the request with the most appropriate A (address) record based on the wide IP configuration.
