Known Issue

This is the result of a known issue. If the hostname in the FirePass controller's URL contains an underscore character, and you use an Internet Explorer (IE) version 6 or 7 browser, FirePass may not display certain icons in the Network Access pop-up window after launching a Network Access favorite. A missing icon may be indicated with a red x in a white square or by an empty space where the icon would normally appear.

Underscores are not valid characters for use in hostnames, although most name-to-IP address mapping sources like DNS or local host files will allow a hostname to contain an underscore and provide a response to name resolution requests. Valid characters for hostnames are specified in RFC 952 from the Internet Engineering Task Force (IETF).

IE will not process HTTP data containing invalid hostnames. When the FirePass controller returns a session cookie to IE, IE constructs the cookie's domain from the hostname in the URL from the address bar. Since hostnames with underscores are invalid, the cookie domain data is invalid and IE does not use the data. When requests arrive at the FirePass controller that do not contain the expected session cookie data, the FirePass controller switches to cookieless mode. In cookieless mode, the Network Access icons fail to load. For more information, refer to K7315: FirePass cookieless mode may prevent certain icons from displaying in the Network Access pop-up window after a Network Access favorite is launched.

F5 Product Development tracked this issue as CR77470 and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass Release Notes.

This issue still exists in the FirePass version 5.x branch.

Additionally, Cumulative Hotfix HF-601-3 has been issued for FirePass version 6.0.1. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can avoid this issue by using a hostname that does not contain an underscore character in the URL used to access the FirePass controller. Ensure that DNS, local host files and any other external name-to-IP address mapping sources do not contain the FirePass hostname with the underscore.

If you cannot alter all sources by configuring a different source with a valid hostname, you can work around this issue by configuring your client operating system to check the valid source before the source with the illegal hostname. For example, if your DNS provides the illegal hostname-to-IP address mapping, configure the local host file on your client operating system with a legal hostname mapped to the FirePass controller's IP address. This configuration will allow you to use the legal hostname in your URL, if your client operating system uses local host files for name resolution before checking DNS. The order in which sources are checked is typically configurable in the client operating system.

If you cannot alter any source name-to-IP address mapping, use a browser other than IE that does not reject cookies with domains containing an underscore.
