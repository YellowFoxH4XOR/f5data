What Happened?

 

error updating HttpLoadbalancer: Replacing object: Unsuccessful PUT at URL https://...console.ves.volterra.io/api/public/namespaces/../http_loadbalancers/i… status code 500, body {"code":13,"details":[{"code":"UNKNOWN","details":"ReplaceResource: Failed transaction handling http_loadbalancer: STM Error: Recovered from panic in etcdApplyFn (runtime error: invalid memory address or nil pointer dereference): goroutine 19505238

.."message":"There was a server error in processing request"}

 

Environment

 

HTTP Load Balancer 

 

Cause

A Terraform “Replace” operation on an existing load balancer object with L7 DDos configuration leads to the observed behavior.

If the l2_ddos_protection statement is removed during a replace operation, this leads to an error in the backend.

 

Resolution/Answer

 

Workaround is to add the missing statements to avoid invalid memory address or nil pointer dereference.

 

L7 DDoS statement:

l7_ddos_protection {
  mitigation_block          = {}
  default_rps_threshold     = {}
  clientside_action_none    = {}
  ddos_policy_none          = {}
}
