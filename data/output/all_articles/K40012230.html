K40012230: Device with id '*' is invalid for resource ownership: Device is not available according to last device availability refresh cycle

Description

The BIG-IP experiences repeated logging of the following messages  in /var/log/restjavad.*.log :

Device with id '11111111-2222-3333-4444-aaaaaaaaaaaa' is invalid for resource ownership: Device is not available according to last device availability refresh cycle

Environment

  • BIG-IPs in device-groups
  • Software upgraded (optional)

Cause

REST framework in the BIG-IP synchronize REST configuration objects using a framework called GOSSIP
The log message noted in this article indicates that this not able to recognize the peer device with the specified UUID (found in /config/f5-rest-device-id) 
 

Recommended Actions

  1. Clear GOSSIP cache on all devices in the BIG-IP HA cluster: 
    # restcurl -X DELETE shared/gossip-conflicts
  2. Clear the sync cache on all devices in the BIG-IP HA cluster:  
    # restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices
  3. Restart restjavad service and wait 60 seconds to make sure restjavad has had sufficient time to return to normal operation:  
    # bigstart restart restjavad
  4. On the unit with known 'good' configuration in the cluster, POST to the BigIpFailoverStateWorker to pull configuration from CMI and retry device trust thereby rediscovering and resynchronising devices for GOSSIP:  
    # restcurl -X POST -d '{}' tm/shared/bigip-failover-state
  5. Perform following command on all BIG-IP is device group to verify:
    # restcurl 'shared/gossip?$select=gossipPeerDevices'
    # restcurl shared/resolver/device-groups/tm-shared-all-big-ips/devices

  6. If this does not resolve the problem, please contact F5 support with the information from step 5 for further troubleshooting towards resolution
