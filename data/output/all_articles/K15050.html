Known Issue

If a standby device is set to an offline state and then subsequently set to a standby state, connection mirroring does not restart.

This issue occurs when all of the following conditions are met:

  • You have two or more systems in a BIG-IP device group.
  • A standby system is manually set to an offline state, and then the system is subsequently set to a standby state.

Impact

Upon failover to the standby system, existing connections are terminated.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The connection mirror table on the standby system is empty. You can view the table by using the following Traffic Management Shell (tmsh) command:

    tmsh show sys connection type mirror

Workaround

To work around this issue, you can restart the tmm process on the standby BIG-IP system. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system temporarily enters an INOPERATIVE state.

  1. Log in to the BIG-IP command line as the 'root' user.
  2. At the prompt, type the following command:

    bigstart restart tmm
