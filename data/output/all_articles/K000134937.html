K000134937: 200007010 matched on legit UTF-8 Arabic string

Type
Support Solution
Published
2023-06-06
Updated
2023-06-29
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000134937

Description

  • ASM attack Signature ID 200007010 triggered on legit UTF-8 Arabic string (False positive)
  • Directory Traversal attempt "/././"(parameter)

Environment

  • ASM
  • Attack Signature
  • Directory Traversal attempt

Cause

As part of normalization, ASM removes whitespace characters as well as high (extended) ASCII characters prior to running the signature on the parameter value. The Arabic characters specified between the slashes (/) and periods (.) are high ASCII characters with multi-byte encoding. When that specific normalization was applied, it resulted in this signature being detected in an expected manner.

Recommended Actions

If there is desire to not remove the high ASCII characters in such situations for web application that utilizes non-English encoding, then you can leverage the dont_norm_high_ascii System Variable configuration that was introduced in 11.6.0+ releases via ID436924. Having tested this in our lab environment by setting dont_norm_high_ascii to '1', we no longer see this signature being raised for such requests.

The following two commands can be issued via the CLI in order to make this change:

/usr/share/ts/bin/add_del_internal add dont_norm_high_ascii 1
bigstart restart asm

Note: An ASM restart is necessary when making this change and that would force the device to failover and go offline for a brief period, so we'd recommend performing this change in a maintenance window.

This approach would help avoid having to override this signature (or even other signatures) for parameters.
