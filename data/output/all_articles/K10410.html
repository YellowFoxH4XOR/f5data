Known Issue

This is the result of a known issue. If connections to a pool member that are idle in the connection reuse pool reach the same number as the connection limit, the connections in the pool will not be reused. This behavior occurs because connection limits are evaluated before a connection reuse decision is made, and any connections in the pool are counted against the pool member toward its limit. If this condition occurs, the virtual server could potentially be inaccessible until at least one of the connections in the connection reuse pool has expired.

Note: For information about the OneConnect profile, refer to K7208: Overview of the OneConnect profile.

F5 Product Development tracked this issue as CR64788 and it was fixed in BIG-IP 9.4.0. For information about upgrading, refer to the BIG-IP LTM and ASM release notes.

Resolution

Workaround

Note: A workaround is not available for BIG-IP 9.0.0 through 9.2.5. A separate issue prevents the Maximum Size configuration parameter from working correctly until BIG-IP 9.3.0.

You can work around this issue for BIG-IP 9.3.0 through 9.3.1 by setting the Maximum Size configuration parameter in your OneConnect profile to a smaller number than the pool member connection limit. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Expand Local Traffic.
  3. Click Profiles.
  4. Click Other: OneConnect.
  5. Choose the appropriate OneConnect profile.

    This step displays the properties of the profile.
  6. Modify the Maximum Size value to be at least one number smaller than your pool member connection limit.

Important: Currently, the Configuration Guide for BIG-IP LTM for 9.4.x and 10.0.x incorrectly states that the above workaround is also required for BIG-IP 9.4.x and 10.0.x. For more information, refer to K10411: Beginning in BIG-IP LTM and ASM 9.4.0, a workaround is no longer required when a virtual server uses a OneConnect profile and pool members with connection limits set.

Note: When setting up pool member connection limits within a Clustered Multi-Processing configuration, the limits are enforced per TMM. For more information, refer to K8457: Connection limits configured on pool members or nodes for a CMP system are enforced per TMM instance.
