Security Advisory Description

The issue is unexpected program termination based on ordering and/or specific content in responses to queries for CNAME or DNAME, and A records. Specifically, if a client queries for a DNAME and A record below the DNAME to the resolver, and the authoritative server responds positively to the A query but delays the DNAME response and later responds negatively, `named` may quit unexpectedly. Or, if a client queries for a CNAME and A record for the same name to the resolver, and the authoritative server responds positively to the A query but delays the CNAME response and later responds with a self-referential CNAME, the same failure may occur. This issue affects BIND 9 versions 9.18.0 through 9.18.50, 9.20.0 through 9.20.24, 9.18.11-S1 through 9.18.50-S1, and 9.20.9-S1 through 9.20.24-S1. (CVE-2026-12617)

Impact

This vulnerability allows an attacker who has control of an upstream DNS server to delay responses for DNAME or CNAME requests and later responds negatively or with a self-referential CNAME. As a result, a BIG-IP DNS system configured to send DNS queries to the compromised upstream DNS server may experience a denial-of-service (DoS).

Mitigation

To mitigate this issue you can either disable BIND or you can disable recursion on your affected BIG-IP DNS system. To do so, perform one of the following procedures:

  • Disabling the Use BIND Server on BIG-IP option in the DNS profile
  • Restricting DNS recursion on the BIG-IP DNS system

Disabling the Use BIND Server on BIG-IP option in the DNS profile

Impact of procedure: Disabling the BIND server can affect DNS configurations that use BIND as a fallback method (return to DNS) for resolution.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > DNS.
  3. Select the applicable DNS profile.
  4. For the Use BIND Server on BIG-IP option, select Disabled.
  5. Select Finished.

Restricting DNS recursion on the BIG-IP DNS system

When you configure the system to allow recursion, the system sends recursive replies only to clients with source IP addresses within a self IP address subnet. You can use the following procedure to modify the default self IP address subnet.

Impact of procedure: Increasing the number of addresses in an IP subnet increases the number of DNS queries that the BIG-IP DNS system performs and therefore increases system resource use.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > Zones > ZoneRunner > named Configuration.
  3. In the Options box, scroll down to the end of the options section of the file and add a list of relevant IP addresses or network addresses for which you want the BIG-IP DNS system to provide recursive DNS queries.

    For example, the following internal access list contains the 192.168.10/24 network:

    acl "internal" { 192.168.10.0/24;};

    For example, the following internal access list contains the 192.168.200.0/24 and 192.168.10/24 networks:

    acl "internal" { 192.168.200.0/24; 192.168.10.0/24;};

  4. Add the following allow-recursion statement to the options section of the file, where internal matches the name of the access list:

    allow-recursion { internal; };

  5. Click Update.
