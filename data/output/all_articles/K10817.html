Topic

You can install BIG-IP 10.x using either the partitions or volumes disk-formatting schemes.

BIG-IP systems that ship with version 10.x are configured to use the logical volume management (LVM) disk-formatting scheme. The volumes disk-formatting scheme employs the Logical Volume Manager (LVM) to allocate disk space on mass-storage devices. LVM offers many advantages over the legacy partitions disk-formatting scheme, and F5 recommends that you retain the LVM formatting scheme for BIG-IP systems that host only version 10.x boot images. However, LVM is not backward-compatible with BIG-IP 9.x installations, and a BIG-IP system that hosts both version 10.x and version 9.x boot images must use a partitioned disk-formatting scheme. Therefore, customers who want to retain a BIG-IP 9.x installation when upgrading to version 10.x must choose the partitions disk-formatting scheme.

Note: It is also possible to revert a BIG-IP 10.x disk formatting scheme (LVM) to version 9.x disk partitions. For more information, refer to K9745: Reverting BIG-IP version 10.x LVM disk format to the partitions disk format.

Correctly determining whether a BIG-IP 10.x system is using the volumes or partitions disk-formatting scheme is useful for many troubleshooting activities; it is a requirement when filing a Return Materials Authorization (RMA), so that F5 may ship a replacement unit that is already formatted with the same disk-formatting scheme.

Perform the following procedure to determine whether a BIG-IP version 10.x system is using the volumes or partitions disk-formatting scheme:

  1. Log in to the BIG-IP command line.
  2. Enter the following command to scan all disks for logical volumes:

    lvscan

    If the output of the lvscan command appears similar to the following example, then the BIG-IP system is using the volumes disk-formatting scheme:

    lvscan -- ACTIVE            "/dev/vg-db-hdc/dat.share.1" [30 GB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/dat.log.1" [7 GB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.1.root" [256 MB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.1._config" [512 MB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.1._var" [3.25 GB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.1._usr" [1 GB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.2.root" [256 MB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.2._config" [512 MB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.2._var" [3.25 GB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.2._usr" [1 GB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.3.root" [256 MB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.3._config" [512 MB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.3._var" [3.25 GB] contiguous
    lvscan -- ACTIVE            "/dev/vg-db-hdc/set.3._usr" [1 GB] contiguous
    lvscan -- 14 logical volumes with 52 GB total in 2 volume groups
    lvscan -- 14 active logical volumes

    If the lvscan command returns no output, or a message that appears similar to the following example, then the BIG-IP system is using the partitions disk-formatting scheme:

    lvscan -- no volume groups found

  3. Note: In BIG-IP versions 10.1.0 and later, the lvscan command returns no output when the formatting scheme is partitions.

If the BIG-IP system that you have to return to F5 is unserviceable, you may run the previous procedure on the other unit of a BIG-IP high availability pair. If the malfunctioning unit is a standalone BIG-IP system, then F5 Technical Support recommends that you request a volumes formatted replacement.
