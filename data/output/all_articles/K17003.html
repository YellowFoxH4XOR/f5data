Known Issue

Description

The BIG-IP system may silently drop packets while an Address Resolution Protocol (ARP) request is in progress.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP system to reach remote devices by using an IPv4 static route.
  • The BIG-IP system does not have an ARP cache entry for the nexthop or gateway device defined in the static route.
  • The BIG-IP system experiences a large burst of traffic.
  • The ARP reply from the nexthop or gateway device is delayed.

Impact

Troubleshooting may be prolonged, as silently dropped packets are not counted in interface statistics.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You notice unequal packet counts when comparing ingress and egress Virtual Local Area Network (VLAN) traffic statistics.?

Workaround

To work around this issue, you can create a health monitor or add a static ARP cache entry for the nexthop or gateway device. To add a static ARP cache entry, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > ARP.

    This screen displays a list of any existing static entries in the ARP cache.

  3. In the upper-right corner, click Create.
  4. In theIP Addressbox, type the IP address for the nexthop or gateway device.
  5. In the MAC Address box, type the MAC address for the nexthop or gateway device (specified in the IP Address box in step 4).
  6. Click Finished.

For more information about creating health monitors, refer to the BIG-IP Local Traffic Manager: Monitors Reference guide for your software version.
