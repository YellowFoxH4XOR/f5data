Known Issue

A BIG-IP GTM monitor with an explicit port number applied to a BIG-IP GTM pool that has a virtual server with translated IP address may fail to work as expected.

This issue occurs when all of the following conditions are met:

  • The configuration contains a BIG-IP GTM monitor that is configured with an explicit port number.
  • The BIG-IP GTM monitor is applied to the BIG-IP GTM pool that has a virtual server with a translated IP address.
  • The BIG-IP GTM monitor with an explicit port number differs from the virtual server's port number.

For example, the BIG-IP GTM monitor defined with an explicit port may appear similar to the following example:

gtm monitor tcp /Common/alltcp22 {
defaults-from /Common/tcp
destination *:22
interval 30
probe-timeout 5
timeout 120
}

The affected BIG-IP GTM monitor is applied to the BIG-IP GTM pool that has a virtual server with a translated address, and the virtual server configuration may appear similar to the following example:

virtual-servers {
eg_vs1 {
destination 10.10.10.2:80
translation-address 10.2.0.2
translation-port 80
}
}

Impact

The BIG-IP GTM monitor will fail and may falsely mark the affected virtual server as unavailable.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H457545 on the Diagnostics > Identified > High screen.
  • You may observe the affected BIG-IP GTM pool member being falsely marked down.
  • If you enabled the debug mode on the BIG-IP GTM monitor, you may observe that the affected monitor will time out and fail to check the state of the BIG-IP GTM pool member correctly.

Workaround

There is no work around for this issue if a port number is required on the BIG-IP GTM monitor. To avoid this issue, you can configure the monitor without using a port number.
