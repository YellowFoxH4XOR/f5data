Description

Unexpected and irregular CPU usage spikes may occur on BIG-IP systems, displaying a sawtooth pattern in performance graphs. High CPU utilization is observed primarily on the control plane (management interface), affecting odd-numbered CPU cores. Audit logs and restjavad logs show repeated failed REST API authentication attempts, with entries such as:

[ForwarderPassThroughWorker] {"user":"local/null","method":"POST","uri":"http://localhost:8100/mgmt/shared/authn/login","status":400,"from":"10.1.1.1"}

Environment

  • Product: BIG-IP SSLO, LTM, DNS
  • Software Version: 17.5.1 or previous
  • Control Plane (management interface)
  • Apache httpd used for Configuration utility, iControl REST, and iControl SOAP interfaces

Cause

The issue is caused by a large number of REST API authentication requests that fail due to incorrect credentials for the API user. These requests are aggressively retried from a specific IP address (10.1.1.1), resulting in excessive load on the httpd process and high control plane CPU usage.

Recommended Actions

  1. Identify and Fix Failed Authentication Requests:
    • Review the application or script making REST API calls to the BIG-IP device.
    • Ensure correct username and password are configured for the API user.
    • If the source IP is not recognized or authorized, block it from accessing the management interface.
  2. Reduce Aggressive Retry Behavior:
    • Update application logic to implement exponential backoff or limit retry attempts after failed authentications.
  3. Monitor System Health:
    After applying changes above, monitor CPU usage and audit logs to confirm resolution.
