Description

Failover fails during a BIG-IP VE reboot in Azure Cloud and the relevant ip-config is no longer associated with the NICs on any VE.

Environment

  • Azure Cloud
  • Cloud Failover Extension

Cause

A small window of time exists between the cloud failover extension disassociating the Azure ip-config objects from the peer BIG-IP VE instance that is going standby and the cloud failover extension associating the ip-config objects with itself.

A reboot of the BIG-IP VE instance or a crash of the restnoded daemon performing the work during this critical window can cause the ip-config to be lost.

ID2185153 has been opened to account for this failure scenario.

Recommended Actions

The missing ip-config will need to be manually restored on the active NIC's in Azure.

Note that this is a rare occurrence as it requires either the BIG-IP VE instance to go down or the restnoded daemon to crash at the same time as it is becoming active. More specifically, the VE must be in the process of attaching the ip-config to the new NIC when the restnoded daemon is terminated.

The recommendation is to avoid triggering reboots or failover actions on multiple devices at the same time. For example, relicensing a VE instance - which will trigger a failover to the HA peer - should be avoided if the HA peer is undergoing an upgrade and is expected to reboot imminently.

Alternatively, if you are running telemetry streaming, please follow the memory adjustments best practice mentioned in K000135911: BIG-IP Telemetry Streaming common issues and best practices as there are instances in which restnoded may restart and trigger this issue during periods of high memory usage.
