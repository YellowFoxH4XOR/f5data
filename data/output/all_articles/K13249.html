Topic

This article applies to BIG-IP 10.1.0 through 11.2.1. For information about other versions, refer to the following article:

  • K48343296: Access policy actions are processed for only the first authentication attempt (11.3.0 - 12.1.1)

Actions that are between a logon page action and an authentication action are not processed again after a failed authentication attempt. An access policy allows for creating actions that occur between the logon page action and the authentication action. These actions are processed only the first time the user submits their logon information for a session. If a logon attempt fails and the Max Logon Attempts authentication action is greater than 1, the authentication actions processes the subsequent authentication attempts without returning to the logon page action. This behavior is by design.

Workaround

You can work around this behavior by creating an Authentication and an Auth Retry macro in the access policy to emulate the authentication loop. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles.
  3. Click Edit... next to the name of the access policy you are editing.

    The Access Policy editor opens in a new window.
  4. Create the Authentication macro. To do so, perform the following procedure:
    1. Click Add New Macro.
    2. Select Empty from the Select macro template: menu.
    3. Enter Authentication in the Name: box.
    4. Click Save.
    5. Click the + next to the macro you just created.

      The macro expands.
    6. Click Edit Terminals.

      The Terminals window opens.
    7. Change Out in the Name: box to Auth OK.
    8. Click Add Terminal.
    9. Enter Auth Failed in the Name: box.
    10. Click the down arrow button.

      The Auth Failed terminal moves to the bottom of the list.
    11. Click Save.
    12. Recreate each action from the Logon Page action through the Authentication action of your current policy connecting the starting point to the In terminal of the macro.
    13. To edit the action, click the name of your Authentication action.
    14. Select 1 from the Max Logon Attempts Allowed menu.

      Note: The following authentication actions support Max Logon Attempts Allowed: AD, LDAP, Radius, RSA SecurID, TACACS, Kerberos, and OAM.
    15. Ensure that the successful branch output from the Authentication action is connected to the Auth OK terminal.
    16. Ensure that the fallback branch of the Authentication action is connected to the Auth Failed terminal.
  5. Create the Auth Retry macro. To do so, perform the following procedure:
    1. Click Add New Macro.
    2. Select Empty from the Select macro template: menu.
    3. Enter Auth Retry in the Name: box.
    4. Click Save.
    5. Click the + next to the macro you just created.

      The macro expands.
    6. Click Edit Terminals.

      The Terminals window opens.
    7. Change Out in the Name: box to Auth OK.
    8. Click Add Terminal.
    9. Enter Auth Failed in the Name: box.
    10. Click the down arrow button.

      The Fallback terminal is now on the bottom of the list.
    11. Click Save.
    12. Click the + on the fallback branch of the In terminal.

      The Add Item window opens.
    13. Select the Authentication macro from the MacroCalls section.
    14. Click Add Item.

      The Add Item window closes. The macro item is added to the macro.
    15. Repeat steps l through n for each time you want the user to retry authentication, substituting the fallback branch of the previous Authentication macro action for the In terminal fallback branch in step l.
    16. Click the Auth OK terminal on the Auth Failed branch of the last Authentication macro action.

      The Select terminal window opens.
    17. Select the Auth Failed option.
    18. Click Save.

      The Select terminal window closes.
  6. Remove the actions from the main policy that you recreated in the Authentication macro by performing the following procedure:
    1. Click the x on the action.
    2. Click the connecting the previous node to the proper output node option.
    3. Click delete.
    4. Repeat steps a through c for each action that you want to delete.
  7. Click the + at the point in the policy flow where you want to insert the new Auth Retry macro.

    The Select Item window opens.
  8. Select the Auth Retry macro.
  9. Click Add Item.
