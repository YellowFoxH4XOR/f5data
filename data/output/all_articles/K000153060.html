K000153060: Dynamic CRL check fails when client submits certificate that has CRLDP extension with multiple CRLDP URI and first CRLDP is LDAP URI.

Description

When client accesses to client-ssl virtual server that uses dynamic CRL check (client-ssl profile "CRL" parameter under "Client Authentication" section), following error may be thrown and SSL handshake may be terminated.

 

Aug 18 17:39:30 bigip.local warning tmm11[17967]: 01260009:4: 10.1.1.50:39478 -> 10.1.1.191:443: Connection error: ssl_hs_do_crl_validation:XXXX: alert(46) unknown certificate error
Aug 18 17:39:30 bigip.local warning tmm11[17967]: 01260013:4: SSL Handshake failed for TCP 10.1.1.50:39478 -> 10.1.1.191:443
Aug 18 17:39:30 bigip.local err keymgmtd[11845]: 01a40000:3: Invalid CRL distrubution point from the certificate (cert_common_name=testuser104)

 

Looking at packet capture, just after client submits its certificate to virtual server, handshake alert is generated and SSL connection is torn down. At that time, neither DNS lookup request for dns-resolver nor HTTP/LDAP traffic towards CRLDP server happens.

 

 

Environment

  • Dynamic CRL check is in use.
  • Client certificate has a CRLDP extension with multiple CRLDP URI.
  • First CRLDP URI is LDAP URI, not HTTP URI.

 

Here is example configuration and client certificate that reproduces errors.

Cause

By design. Dynamic CRL supports client certificate with only one CRLDP and CRLDP has to be HTTP URI.

 

 

Recommended Actions

Use client certificate that has only one CRLDP with HTTP URI when dynamic CRL check is in use. Here is example client certificate with which dynamic CRL check works fine. Only one CRLDP is there and that is HTTP URI.

user1@ubuntu2204client1:~$ openssl x509 -in /home/user1/testuser103.crt -text -noout

            64:d0:b0:f7:49:c7:39:be:40:ce:f4:37:75:67:3f:bc:9c:1b:71:58
        Signature Algorithm: sha256WithRSAEncryption
        Issuer: C = JP, ST = Kanagawa, O = F5SS, CN = ubuntu2204server1ca.f5ss.local

        Subject Public Key Info:
            Public Key Algorithm: rsaEncryption

If it is not possible to use such client certificate, consider using static CRL file instead of dynamic CRL check.

 

Alternatively, consider using APM "On-Demand Cert Auth + CRLDP auth" setup. APM "On-Demand Cert Auth + CRLDP auth" supports multiple CRLDP URIs and supports LDAP URI as well as HTTP URI.
