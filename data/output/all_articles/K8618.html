K8618: Exchange ActiveSync connections fail when using VersaMail

Topic

If a user attempts an Exchange ActiveSync connection through FirePass using VersaMail on a Palm Treo device, the connection may fail. A compatibility issue exists between the VersaMail ActiveSync function and the FirePass ActiveSync proxy.

Note: For information about configuring FirePass to proxy ActiveSync connections, refer to K7812: Configuring FirePass to proxy ActiveSync.

FirePass uses two TCP connections to proxy ActiveSync connections. The first TCP connection authenticates the user and sends an HTTP session cookie to the client device, and the second TCP connection proxies the ActiveSync data. After FirePass authenticates the user and sends the HTTP session cookie, FirePass then sends an HTTP/1.1 Connection: close message followed by a TCP FIN-ACK packet to close the first TCP connection. Applications that are HTTP/1.1 compliant open a new TCP connection after receiving the Connection: close message, and the ActiveSync data is transmitted over the second TCP connection.

When a user attempts an ActiveSync connection using VersaMail, VersaMail may ignore the HTTP/1.1 Connection: close message sent by FirePass. When this behavior occurs, VersaMail closes the first TCP connection but does not open a second TCP connection. This behavior is not compliant with the HTTP/1.1 protocol as defined in RFC2616. Since VersaMail does not open a second TCP connection, ActiveSync data is not transmitted.

Workaround

Users can work around this behavior by installing a third-party ActiveSync client, such as  DataViz RoadSync, on their Palm Treo devices. Users may implement the third-party ActiveSync client instead of VersaMail to perform ActiveSync functions.
