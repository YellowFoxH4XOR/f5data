Topic

This article applies to BIG-IP 10.x. For information about other versions, refer to the following articles:

  • K13117: Performing a clean installation of BIG-IP 11.x - 13.x 
  • K9447: Choosing an installation method for BIG-IP 9.x

On rare occasions, you may be required to perform a clean installation of BIG-IP 10.x.  During a clean installation, all mass-storage devices will be wiped, therefore restoring the BIG-IP system to its factory defaults. In addition, a clean installation allows you to reinstall a BIG-IP unit that no longer boots from any of its boot locations.

To perform a clean installation of BIG-IP 10.x, complete the following procedures:

  • Downloading the installation image
  • Choosing an installation method
  • Installing the software

Downloading the installation image

  1. Download the appropriate product ISO image and its corresponding MD5 file from the F5 Downloads site.
  2. Compare the checksum of the downloaded ISO image to the pre-computed MD5 checksum for the file. For example, on a Linux system you would type commands similar to the following example:

    md5sum BIGIP-10.0.1.283.0.iso
    ef9fdbf673d6355a74c2bae7980127f3  BIGIP-10.0.1.283.0.iso

    cat BIGIP-10.0.1.283.0.iso.md5
    ef9fdbf673d6355a74c2bae7980127f3  BIGIP-10.0.1.283.0.iso

     

    If the two values do not match, then the file was corrupted during transfer.

    Important: Do not skip this step. The procedures that follow will not verify the validity of the file. Continuing with a corrupted ISO image may lead to unpredictable results.

    Note: The md5sum utility is a core component of any Linux operating system. On Microsoft Windows systems, you may use the File Checksum Integrity Verifier utility (http://support.microsoft.com/kb/841290).

Choosing an installation method

The following installation methods are available:

Note: The following installation methods are listed in order of preference. If possible, F5 recommends that you perform a clean installation by using a USB CD/DVD-ROM drive, as this is the simplest and most reliable of all the installation methods.

  • Using a USB CD/DVD-ROM drive
  • Using a USB thumb drive
  • Using a PXE server

You should choose an installation method based on the equipment which is available to you, and on whether or not you have physical access to the system that requires reinstalling. The primary advantage of performing a clean installation using a PXE server is that physical access to the BIG-IP system is not required; everything can be done remotely. Additionally, using a PXE server can be very convenient when you require reinstalling several systems, as this method allows you to perform several concurrent installations. However, using a PXE server is more complex than the other installation methods.

Note: Beginning in BIG-IP 10.1.0, the capacity of a standard CD-ROM (700 MB) is no longer enough to hold BIG-IP ISO images. To perform a disc-based clean installation of these versions or later, you must use a USB DVD-ROM drive and a DVD recordable.

Note: Beginning in BIG-IP 10.0.0, ISO images no longer provide network installation services; therefore, they cannot be used to boot and automatically configure a workstation as a PXE server. However, the essential files are still included in the product ISO images. You can use these files to manually configure a workstation as a PXE server.

Note: The VIPRION platform cannot be re-imaged using a PXE server. To perform a clean installation of BIG-IP 10.x on a VIPRION blade, choose one of the other installation methods.

Depending on the installation method you have chosen, perform one of the following steps:

  • Using a USB CD/DVD-ROM drive:

    Burn the product ISO image to a CD or DVD.

  • Using a USB thumb drive:

    Image the USB thumb drive using the product ISO image file. To do so, refer to the Creating a Bootable USB Thumb Drive section in the BIG-IP Systems: Getting Started Guide.

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  • Using a PXE server:

    Configure a workstation as a PXE server. To do so, refer to the following guidelines:

    Note: The following steps are not exhaustive and should be taken as an example only. Additionally, F5 Technical Support will not be able to assist you in setting up your own PXE server.

    Note: The following steps include example configurations and commands specific to Linux operating systems. However, you can setup a PXE server on other operating systems as well.

    • The workstation you plan to configure as a PXE server must provide tftp, dhcp and http services. If it is of convenience to you, the workstation may be a virtual machine. Make sure to position the PXE server on the same network segment of the F5 system's management port.

      Important: Ensure that no DHCP server is already present on the management network. If a DHCP server is already present, configuring a PXE server may interfere with the normal operation of your existing DHCP server and may cause traffic disruption.

    • The tftp service must serve the contents of the /tftpboot/X86PC/UNDI/F5 directory, which is included in each product ISO file. Additionally, the tftpd daemon must support the tsize option. For example, in Debian, the tftpd package does not support the tsize option and therefore is not suitable for use in a PXE environment; instead, use the tftpd-hpa package.

      Mount the product ISO file to a directory and then copy the required files to your tftp root directory.

      For example:

      mount -o loop /root/BIGIP-10.1.0.3341.0.iso /mnt/iso
      cp -Rv /mnt/iso/tftpboot/X86PC/UNDI/F5/* /tftpboot/

    • The DHCP server must be configured with the next-server and filename options. These options define respectively the IP address of your tftp server and the file that the F5 system should retrieve. The following subnet declaration is an example of how the DHCP server should be configured:

      subnet 192.168.1.0 netmask 255.255.255.0 {
              range 192.168.1.100 192.168.1.200;
              option subnet-mask 255.255.255.0;
              option broadcast-address 192.168.1.255;
              next-server 192.168.1.1;
              filename "pxelinux.0";
      }

      Because this article assumes that one workstation will provide all the required services (tftp, dhcp and http), the IP address of the tftp server (192.168.1.1) is basically that of the dhcp server.

    • The http server must serve the root directory ( / ) of the product ISO file. You may find it convenient to mount the ISO file to a directory, and then place a link to that directory in your www directory.

      For example:

      mount -o loop /root/BIGIP-10.1.0.3341.0.iso /mnt/iso
      cd /var/www/
      ln -sf /mnt/iso/ SOL10819

Installing the software

  1. Connect to the BIG-IP system serial console.

    Important: If you are reinstalling a platform that uses the Always-On Management (AOM) subsystem, the serial port baud rate must match the AOM baud rate. For more information, refer to K10834: The serial port baud rate must match Always-On Management baud rate.

    Note: For more information, refer to K7683: Connecting a serial terminal to a BIG-IP system.

  2. Depending on the choice you made in the previous procedure, perform one of the following actions:
    • Connect the USB CD/DVD-ROM drive to the F5 system and load the disc you burnt with the product ISO image.
    • Connect the USB thumb drive to the F5 system.
    • Ensure that the PXE server is online, all the required services are running, and that the BIG-IP is configured to perform a netboot.

    Note: For more information about netboot, refer to K3525: Configuring SCCP-based BIG-IP platforms to boot from a network boot server or K9599: Configuring AOM based BIG-IP platforms to boot from a network boot server.

  3. Reboot the BIG-IP system. If the BIG-IP system cannot be rebooted, perform a power cycle.

    Note: Upon completion of this step, regardless of the installation method, the BIG-IP system will boot into the Maintenance Operating System (MOS).

  4. The MOS will ask you to specify the type of terminal you are using. If you do not know what to enter, press Enter. The default setting is fine in most cases.
  5. If you have booted the F5 system from a USB removable media, the system may display a manufacturing installation dialog.

    Note: For more information, refer to K11686: When the BIG-IP system is booted from a USB removable media, a manufacturing installation dialog is automatically displayed.

    Press Ctrl+C to exit the dialog and continue with step 6 if any of the following conditions are true:
    • You have booted the BIG-IP system from a USB removable media containing a software installation image older than BIG-IP 10.2.0.
    • You have booted the BIG-IP system from a USB removable media containing image at least as recent as BIG-IP 10.2.0 but you want to perform a custom installation using the diskinit and image2disk utilities.
    • You have booted the BIG-IP system from a PXE server.

    Otherwise, to re-image the BIG-IP system according to the manufacturing installation plan displayed in the output, press Enter and skip to step 9.

  6. To wipe all mass-storage devices inside the BIG-IP system, type the following command:

    diskinit --style <volumes | partitions>

    Important: If you want to run BIG-IP 9.x along with 10.x, you must use the partitions style. If you want to run BIG-IP 10.x exclusively, F5 recommends that you use the volumes style.

    Important: If you choose the volumes disk formatting scheme on a BIG-IP 6900 or 8900 platform, the diskinit utility will create mirrored volume sets exclusively (MD1.1, MD1.2, and MD1.3). Ensure that you specify one of these install locations in step 7. For more information, refer to K10856: Hard drive mirroring (RAID) for BIG-IP 10.1.0 through 10.2.4.

    Important: Do not omit the --style option, doing so will result in the system wiping the drives but not reformatting them.

  7. The diskinit utility will ask you whether you want to proceed wiping the drives. To continue, type y and press Enter. Otherwise, type n and press Enter.

    Important: Confirming this operation will destroy all data on the BIG-IP system. Do not proceed with this step if you have data that needs to be recovered from the system, for example a configuration archive. Using the MOS, it may be possible to manually mount a partition or volume and recover such data.

  8. If you are using a USB CD/DVD-ROM drive or a USB thumb drive created by the mkdisk utility, install the software using the following command syntax:

    BIG-IP 10.2.4

    image2disk --format=<volumes | partitions> --nosaveconfig --nosavelicense

    For example, to install BIG-IP 10.2.4 using partitions formatting, type the following command:

    image2disk --format=partitions --nosaveconfig --nosavelicense

    BIG-IP 10.0.0 - 10.2.3

    image2disk --instslot=<LOCATION> --nosaveconfig

    For example, to install BIG-IP 10.0.0 through 10.2.3 on HD1.1, type the following command:

    image2disk --instslot=HD1.1 --nosaveconfig

    If you are using a PXE server, install the software using the following command syntax:

    BIG-IP 10.2.4

    image2disk --format=<volumes | partitions> --nosaveconfig --nosavelicense http://<SERVER_IP>/<PATH>

    For example, to install BIG-IP 10.2.4 using partitions formatting and the http server configured in the previous procedure, type the following command:

    image2disk --format=partitions --nosaveconfig --nosavelicense http://192.168.1.1/SOL10819

    BIG-IP 10.0.0 - 10.2.3

    image2disk --instslot=<LOCATION> --nosaveconfig http://<SERVER_IP>/<PATH>

    For example, to install BIG-IP 10.x on HD1.1 using the http server configured in the previous procedure, type the following command:

    image2disk --instslot=HD1.1 --nosaveconfig http://192.168.1.1/SOL10819

    Note: BIG-IP 10.x cannot be installed on a CompactFlash media drive. You must use boot locations on the system’s hard drive.

    Note: You must specify the --nosaveconfig option, as the BIG-IP system does not have a configuration to save.

    Note: If you are using a USB CD/DVD-ROM drive or a USB thumb drive, you do not need to specify an installation repository, as the image2disk utility will automatically find and default to /cdserver.

  9. Once the installation has completed, disconnect any removable media from the BIG-IP system.
  10. To restart the system, enter the reboot command. The BIG-IP system will boot from the location you have just re-imaged.
