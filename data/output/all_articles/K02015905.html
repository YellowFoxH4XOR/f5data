K02015905: Token expiration behavior changes after upgrade to versions fixed for CVE-2022-1388

Type
Support Solution
Published
2022-06-08
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 15.1.5, 14.1.5, 14.1.4, 13.1.5, 17.0.X, 16.1.2, 17.0.0
Source
https://my.f5.com/manage/s/article/K02015905

Description

After upgrading your Big-IP to any version fixed for CVE-2022-1388 you may notice that expired or invalid tokens get a different response back.  If your automation software (such as SCOM or older AppviewX (AppviewX has a patch for their current releases for this change)) relies on the older style to trigger a token generation you may need to modify your scripts

Environment

  • BIG-IP
  • 13.1.5, 14.1.4.6, 15.1.5.1, 16.1.2.2, 17.0.0 or newer
  • Rest API, Python, SCOM or curl

Cause

For security reasons F5 has modified its behavior when a token is expired or missing.  In previous version after expiration (or if not present) you would get this reply for about 30 seconds (this time varies slightly based on internal system clocks that remove old tokens):

{  "code": 401,  "message": "X-F5-Auth-Token has expired.",  "referer": "10.155.205.95",  "restOperationId": 18271302,  "kind": ":resterrorresponse"}

After that you would receive this response for that same token:
{"code":401,"message":"X-F5-Auth-Token does not exist.","referer":"10.155.205.95","restOperationId":18278405,"kind":":resterrorresponse"}
In newer versions you will receive this for anywhere from 1 second to 10 minutes (the amount of minutes varies depending on when the internal sweeper fires)
{ "code": 401, "message": "X-F5-Auth-Token has expired.", "referer": "10.155.205.95", "restOperationId": 18271302, "kind": ":resterrorresponse"}

Once that token is removed from the system then you are met with simply a 401 unauthorized message such as this:
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN"> 
<html><head>
<title>401 Unauthorized</title>
</head><body>
<h1>Unauthorized</h1>
<p>This server could not verify that you
are authorized to access the document
requested.  Either you supplied the wrong
credentials (e.g., bad password), or your
browser doesn't understand how to supply
the credentials required.</p>
</body></html>

Recommended Actions
This is normal behavior now and will not be reverted and is by design.
