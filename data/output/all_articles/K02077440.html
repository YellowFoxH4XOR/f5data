Known Issue

Re-enabling a monitored and disabled pool member may modify the pool member's monitor state.

This issue occurs when all of the following conditions are met:

  • You configure the BIG-IP system's pool to monitor a specific pool member.
  • You set the pool member to the user disabled state.
  • You use the Traffic Management Shell (tmsh) to merge a configuration in order to set the pool member to the enabled state.

Impact

The re-enabled pool member monitor configuration is not selected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After the configuration merge, the system re-enables monitored pool members that you changed to disabled, with monitoring cleared.
  • Depending on your specific configuration, the system may not process traffic to the pool member, regardless of the pool member's availability.
  • Depending on your specific configuration, the system may process traffic to the pool member, regardless of the pool member's availability.

Workaround

To work around this issue, you can save the running configuration, and then reload the configuration. To do so, perform the following procedure:

Impact of workaround: Services to the active BIG-IP system may be interrupted while the configuration loads.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To save the running configuration, type the following command:

    save /sys config

  3. To load the recently-saved configuration, type the following command:

    load /sys config

  4. To exit the tmsh utility, type the following command:

    quit
