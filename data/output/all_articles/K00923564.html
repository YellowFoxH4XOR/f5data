Topic

This article applies to BIG-IP 14.x. For information about other versions, refer to the following articles:

  • K31305921: Overview of BIG-IP logging BigDB database keys (15.x)
  • K73208321: Overview of BIG-IP logging BigDB database keys (13.x)
  • K40042130: Overview of BIG-IP logging BigDB database keys (12.x)
  • K13455: Overview of BIG-IP logging BigDB database keys (11.x)
  • K11740: Overview of BIG-IP logging BigDB database keys (9.x - 10.x)

A number of the BIG-IP BigDB keys provide the ability to enable verbose logging, which can be useful for troubleshooting specific BIG-IP issues. When troubleshooting is completed, the keys should be set to their default values.

Displaying the current value of a BigDB key

To display the current value of a BigDB key, use the following command syntax:

tmsh show running-config sys db <bigdb_key>

Note: To see the current value, default value, and value range, append all-properties to the end of the TMOS Shell (tmsh) command string.

For example, to display the log.bcm56xxd.level BigDB key value, enter the following command:

tmsh show running-config sys db log.bcm56xxd.level

Setting the value of a BigDB key

To set the value of a BigDB key, use the following command syntax:

tmsh modify sys db <bigdb_key> value <value>

For example, to set the log.bcm56xxd.level BigDB key value to a value of Informational, enter the following command:

tmsh modify sys db log.bcm56xxd.level value informational

Resetting a BigDB key to a default value 

You can use the reset-to-default command option to reset a BigDB key to its default value, using the following command syntax:

tmsh modify sys db <bigdb_key> reset-to-default

For example, to reset the log.bcm56xxd.level BigDB key value to its default value, enter the following command:

tmsh modify sys db log.bcm56xxd.level reset-to-default

Recommendations

F5 recommends that you do not modify these BIG-IP database keys unless you need to do so for troubleshooting purposes. You should always return database key values to their default value when the system is in production mode. Leaving the verbose logging enabled when the system is in normal production mode can cause poor performance.
