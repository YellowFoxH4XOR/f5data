Description

When configuring an HA group on a BIG-IP LTM (F5OS tenant) and assigning a trunk named "LACP", the GUI may display an alert stating:

 

"At least one object in the HA group has a non-optimal HA score contribution - LACP has an HA score contribution of 0."

 

Despite this alert, the HA group functions correctly and the CLI shows the expected score contribution.

 

Environment

  • BIG-IP LTM tenant
  • F5OS Platform (VELOS / rSeries)
  • Trunk configuration object named "LACP"

Cause

The issue occurs due to a naming conflict. The trunk is named "LACP," which is a reserved word and also a property ("lacp") in TMOS trunk configuration. When the GUI queries trunk details, it returns only the "lacp" property instead of the full trunk object, causing the GUI to misinterpret the trunk's properties and display a false alert. The CLI and actual HA functionality are not affected. Bug ID1964985 has been raised to track this issue.

 

Answer/Recommended Actions

To resolve the false alert and prevent naming conflicts:

 

  1. Create a new LAG (trunk) on the F5OS host with a name other than "LACP."
  2. Move VLANs and interfaces from the old trunk ("LACP") to the new trunk.
  3. Delete the old trunk named "LACP" from the F5OS host.
  4. Reconfigure the HA group on the BIG-IP tenant to use the new trunk.
  5. Move the tenant state from deployed to configured mode on the F5OS host, then re-deploy the tenant (required due to Bug ID1321697).
