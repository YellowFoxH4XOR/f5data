Description

A BIG-IP tenant's statically configured management IP address changes to a DHCP-assigned address, even though DHCP is disabled for management.

  • Symptoms:
    • The tenant management IP differs from the configured static address.
    • Control-plane communication may be affected, including management access and HA communication.
  • Relevant log and process observations:
    • platform_agent_startup logs an interface name change for the internal host-facing interface (hnet), for example:

      Interface name for pci addr:03:00.0 and virtio2 device is eth7

      delete old dhcp config files as system is switch to eth7 from eth2

    • A dhclient process for eth2 (/sbin/dhclient ... -cf ... -lf ...) continues to run after the interface name changes. This is visible with ps aux.
    • The DHCP configuration file for eth2 is removed, but the running process is not stopped.
  • Mechanism: When the internal interface is renumbered, the old dhclient process is left running on the old interface name. If that name is later reassigned to the management interface, a DHCP lease renewal on it can apply a DHCP address to management.

Environment

  • Host software: F5OS 1.8.0 upgraded to 1.8.4-HR-1
  • Tenant software: BIG-IP 17.1.3.2 (affected tenant, as recorded in boot logs). Affected versions are listed in Bug ID 2131833.
  • Configuration:
    • Tenant management IP configured as static on the F5OS host, with DHCP disabled for management.
    • Two-device HA configuration with each device as a tenant on a separate F5OS host, connected through Layer 2 switches.
  • Interface behavior:
    • The internal host-facing interface (hnet) is normally eth2 in the tenant. It is used by platform_agent to configure the guest management address. Its address is in the internal range assigned by the F5OS host, such as 10.0.0.0 - 10.255.255.255 (10/8 prefix).
    • Interface enumeration can change between reboots (eth2 to eth7 and back to eth2).

Cause

  • Bug ID 2131833: A stale dhclient process is not terminated when the hnet interface is renumbered. This leaves a DHCP client bound to an interface name that later becomes the management interface.
  • This issue is rare. A fix for Bug ID 2131833 is available in later releases. Contact F5 Support to confirm fix availability for your release train.

Answer/Recommended Actions

Immediate check:

  1. On the affected tenant, confirm the management IP matches the configured value.
  2. Run ps aux | grep dhclient and confirm that dhclient runs only on the expected internal interface.
  3. Confirm the management interface name and MAC address. If the interface associated with a running dhclient process is now the management interface, the tenant is affected.

Recovery options (apply only with guidance from F5 Support):

  1. Tenant reconfiguration: Set the tenant to Configured, set the management IP address, and then set the tenant to Deployed. This may need to be done twice as the management IP may only be re-proposed if it differs from the last deployed value.

Preventive steps:

  • After any F5OS host upgrade or tenant reboot, verify that dhclient runs only on the expected interface and that the management IP matches the configured value.
  • Plan for a release that includes the Bug ID 2131833 fix if this behavior affects your environment. Engineering Hotfix policy is described in K4918: Overview of the F5 critical issue hotfix policy.

Additional Information

  • The DHCP lease that changed the management address was tied to the internal interface, not a physical front-panel interface. Management DHCP was disabled.
  • Log entries of the form HA Connection with peer ... lost for traffic-group reflect the connection mirroring channel. Connection mirroring was not in use in this environment, so these entries are not, by themselves, evidence of the management IP issue.
  • The interface name for the hnet can differ after a reboot. Expect eth2 or another name after reboot, and check which interface is the management interface before you troubleshoot DHCP behavior.
