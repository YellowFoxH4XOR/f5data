Known Issue

Chunked HTTP responses may not be unchunked before they are compressed and forwarded to the client.

This issue occurs when the following conditions are met:

  • The NT LAN Manager (NTLM) and OneConnect profiles are applied to a virtual server.
  • HTTP compression is enabled on the virtual server.
  • A BIG-IP APM access policy is configured.

Impact

The client connection fails because the HTTP response to the client contains incorrect HTTP chunked encoding markers.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H379811 on the Diagnostics > Identified > Medium page.
  • Clients experience failed responses to HTTP requests.

Workaround

To work around this issue, you can either modify the type of response chunking or disable compression. To do so, perform one of the following procedures:

  • Using an iRule to change response chunking
  • Setting Response Chunking to Unchunk or Rechunk
  • Disabling compression (11.x)
  • Disabling compression (10.x)

Using an iRule to change response chunking

Impact of workaround: Using an iRule may add a small amount of latency and CPU overhead to each HTTP response. F5 recommends testing any such changes during a maintenance window, with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRules List.
  3. Click Create.
  4. Type a name for the iRule.
  5. In the Definition box, copy and paste the following iRule:

    when HTTP_RESPONSE {
    if [HTTP::header exists "Transfer-encoding"] {
    HTTP::payload rechunk
    }
    }

  6. Click Finished.
  7. Assign the newly created iRule to your virtual server.

Setting Response Chunking to Unchunk or Rechunk

Impact of workaround: The impact of the suggested procedure depends on the specific environment. F5 recommends testing any such changes during a maintenance window, with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Select the HTTP profile associated with your virtual server.
  4. Modify the Response Chunking option to Unchunk or Rechunk.
  5. Click Update.

Disabling compression (11.x)

Impact of workaround: You may experience higher bandwidth usage from the BIG-IP system to the client.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the virtual server for which you want to disable compression.
  4. In the HTTP Compression Profile box, select None.
  5. Click Update.

Disabling compression (10.x)

Impact of workaround: You may experience higher bandwidth usage from the BIG-IP system to the client.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Select the HTTP profile associated with your virtual server.
  4. In the Compression box, select Disabled.
  5. Click Update.
