Known Issue

A UCS archive created on a BIG-IP APM 10.x system may fail to install on a version 11.0.0 system.

This issue occurs when the following condition is met:

  • The UCS archive contains customized APM Access Policies configured with a single language.

Impact

You are unable to restore the BIG-IP configuration from the UCS archive.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You receive an error that appears similar to the following example:

    Can't use string ("<text>") as a HASH ref while "strict refs" in use at /usr/local/bin/apm_customization.pm line 291.
    /tmp/configsync.spec: Error installing package
    Config install aborted.
    Unexpected Error: UCS loading process failed.
    nn

    In the previous error message, note the following:
  • <text> is a text string from the APM customization file.

    For example:

    Can't use string ("Logon") as a HASH ref while "strict refs" in use at /usr/local/bin/apm_customization.pm line 291.
    /tmp/configsync.spec: Error installing package
    Config install aborted.
    Unexpected Error: UCS loading process failed.

Workaround

To work around this issue, you can reset the language of the customization and recreate the UCS archive on the source BIG-IP 10.x system. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. Click the name of the access policy that contains the customization.
  5. Type an additional language identifier (en, ja, zh-cn, zh-tw, etc) in the Language Settings : String textbox. The language cannot be in the list already.
  6. Click Add.
  7. Click Update.
  8. Repeat Steps 3 - 7 for each access policy that has a customization.
  9. Create a new UCS archive file. For more information, refer to K11318: Backing up and restoring BIG-IP configuration files (10.x).
