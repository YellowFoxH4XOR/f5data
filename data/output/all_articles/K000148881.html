K000148881: The peer routers may see different path cost when using OSPF NSSA with metric-type 1 redistribution

Type
Support Solution
Published
2024-12-06
Updated
2024-12-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000148881

Description

The peer OSPF neighbors may see different metric value.

  • Topology - BIG-IP (R1) connections to R2 via VLAN 10, and connect to R3 via VLAN 20, no connectivity between R2 and R3.
  • BIG-IP (R1) has two neighbors - R2 and R3, while R2 and R3 only have one neighbor R1.
  • When show ip route, the external route propagate by R1 shows different metric on R2 and R3.
  • Manual increase interface cost on R1, it will reflect on one of the neighbors only.

Environment

  • LTM v17.1.x
  • Redistribute kernel routes (for example, virtual address route-advertisement enabled) into OSPF with metric-type 1.
  • OSPF area type is NSSA.
  • OSPF network type is broadcast.

Cause

This is an expected behavior.

Recommended Actions

Impact of workaround: When "clear ip ospf process", it restarts the OSPF process and rebuild the OSPF neighbor.

To achieve OSPF ECMP (equal cost multip-path) function, you may either use:

  1.  Use metric-type 2 in route redistribution. (Type 2 does not increment the path cost, so the two rotuers show the same metric.)
  2. Create a loopback interface on the BIG-IP with the lowest IP address and restart the ip ospf process.

# tmsh create net vlan LOOP

# tmsh create net self LOOP_IP address 1.1.1.1/32 vlan LOOP

<Once done, go into the imish>

# imish

# enable

# clear ip ospf process
