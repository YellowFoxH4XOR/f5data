K000163168: BIG-IP REST API endpoint /mgmt/tm/sys/ucs can fail with a 502 Proxy Error during UCS backup

Type
Support Solution
Published
2026-09-02
Updated
2026-09-02
Status
Final
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000163168

Description

A UCS backup initiated through the BIG-IP REST API endpoint /mgmt/tm/sys/ucs can fail with a 502 Proxy Error when the UCS save operation takes longer than the Apache httpd reverse-proxy timeout. the actual ucs backup could be successful, but user may still observe the error logs in API client end.

Relevant errors can be found in /var/log/httpd.error include:

err httpd[845]: [proxy_http:error] [pid 845] (70007)The timeout specified has expired: [client 192.168.1.1:12345] AH01102: error reading status line from remote server localhost:8100
err httpd[845]: [proxy:error] [pid 845] [client 192.168.1.1:12345] AH00898: Error reading from remote server returned by /mgmt/tm/sys/ucs

Environment

  • BIG-IP LTM
  • AS3 iAppLX packages installed
  • UCS backups initiated through the BIG-IP REST API
  • REST-related timeout database variables configured for long-running operations
  • Apache httpd reverse-proxy timeout configured independently from the REST service timeouts

Cause

During UCS creation, the iAppsLX_save_pre process rebuilds the RPM package for each installed iAppLX application. When the combined rebuild operation exceeds the Apache httpd timeout, the local management proxy stops waiting for the REST service on port 8100 and returns a 502 response.

Increasing the REST service timeout values alone does not increase Apache httpd’s independent reverse-proxy timeout.

Recommended Actions

Increase the Apache httpd timeout by using the supported BIG-IP configuration command:

tmsh modify /sys httpd include 'Timeout 600'

Ensure the REST-related timeout values also accommodate the duration of the UCS operation:

tmsh modify sys db icrd.timeout value 300
tmsh modify sys db restjavad.timeout value 300
tmsh modify sys db restnoded.timeout value 300
tmsh modify sys db iapplxrpm.timeout value 300

Save the configuration and restart the relevant REST services:

tmsh save sys config
bigstart restart restjavad && sleep 20 && bigstart restart restnoded

Retry the UCS backup through:

/mgmt/tm/sys/ucs

Additional Information

  • The iAppsLX_save_pre package rebuild is performed during each UCS save operation.
  • The package rebuild behavior is independent of whether AS3 was upgraded or downgraded.
  • The Apache httpd timeout and the REST-related database timeout values are separate controls. Both must allow sufficient time for the complete UCS operation.
  • Removing unused iAppLX packages may reduce the total RPM rebuild time during UCS creation.
  • A UCS file created locally does not by itself confirm that the REST API request completed successfully. The REST client can still receive a 502 response if the management proxy timeout is reached.
