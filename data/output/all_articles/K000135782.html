K000135782: Access logs showing InboundPassthroughClusterIpv4

Type
Support Solution
Published
2023-08-14
Updated
2023-08-14
Applies to
  • Aspen Mesh: 1.11, 1.14
Source
https://my.f5.com/manage/s/article/K000135782

Description

istio-proxy sidecar access logs can show messages similar to these: 

[2022-02-13T12:40:40.044Z] "- - -" 0 UF,URX - - "-" 0 0 6 - "-" "-" "-" "-" "192.168.0.5:15053" InboundPassthroughClusterIpv4 - 192.168.0.5:15053 172.16.0.6:49192 - -
[2022-02-13T12:40:40.051Z] "- - -" 0 UF,URX - - "-" 0 0 1 - "-" "-" "-" "-" "192.168.0.5:15000" InboundPassthroughClusterIpv4 - 192.168.0.5:15000 172.16.0.6:7555 - -
[2022-02-13T12:40:40.055Z] "- - -" 0 UF,URX - - "-" 0 0 3 - "-" "-" "-" "-" "192.168.0.5:15004" InboundPassthroughClusterIpv4 - 192.168.0.5:15004 172.16.0.6:14569 - -

 

Environment

Aspen Mesh 1.11.x and Aspen Mesh 1.14.x

 

Cause

The InboundPassthroughClusterIpv4 cluster is a special cluster that is used by the Istio sidecar to receive inbound traffic on ports that are not declared in the service definition. (no match found)

Make sure to not configure any application listening on the ports reserved by istio.

 

Recommended Actions

Consider the following next steps to investigate further:

 

Traffic Analysis:

Investigate the traffic patterns to your service mesh. Check where the unmatched requests are coming from and what they are trying to access. You could also look at the HTTP headers and other request details from the Envoy logs. Tools like Wireshark or tcpdump could also help analyze the network packets.

 

Istio Configuration Review:

Review your Istio configuration. Check the defined ServiceEntries, DestinationRules, and VirtualServices. Make sure they match the expected traffic patterns to your services. Use istioctl analyze command to spot any potential issues in your Istio configuration.

 

Istio Proxy Debugging:

You could increase the log level of your Envoy proxies temporarily for more verbose logging. This can help provide more details about the traffic that is being passed through. Be aware that this could also increase the amount of log data significantly. 

 

Applications Logs:

Check the logs of your applications to see if they are experiencing any issues. These issues could potentially lead to incoming requests not matching any of the defined services.

 

Additional Information

The InboundPassthroughClusterIpv4 is not an error message but a configuration detail of the Istio's Envoy sidecar proxy. It's an automatic configuration created by Istio for handling inbound traffic for which no explicit istios objects have been defined in the Istio service mesh. Essentially, this passthrough cluster is a catch-all configuration for unspecified traffic. When traffic matches InboundPassthroughClusterIpv4, it means that the incoming connection doesn't match any of the ServiceEntry, DestinationRules, or VirtualService configurations defined in your Istio service mesh. As a result, the traffic goes through a passthrough in the Envoy proxy, and Istio applies no additional routing rules to this traffic.
