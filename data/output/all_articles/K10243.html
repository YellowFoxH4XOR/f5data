K10243: Schema files that are not UTF-8 encoded will report an error message when attempting to load

Known Issue

This is the result of a known issue. When loading schema files during the process of creating an XML profile, an error message that appears similar to the following example may be reported if the schema file is not UTF-8 encoded:

Schema Document cannot be parsed (too big or bad syntax): Couldn't open encmap windows-1252.enc: No such file or directory

This error message occurs when you upgrade from BIG-IP ASM version 9.4.x to 10.x. because BIG-IP ASM versions prior to 10.x accepted character encoding formats other than UTF-8.

Note: BIG-IP ASM version 10.x requires schema files to use the UTF-8 character encoding.

F5 Networks Product Development is tracking this issue as CR102535 and CR122854.

Workaround

You can work around this issue by using one of the following two options:

  • Manually edit the XML file and change the encoding declaration at the top of the schema to note UTF-8.

    Note: This method my cause some characters to be represented incorrectly if they do not have a corresponding encoding value in UTF-8.

  • Open the schema file in an XML utility that will allow you to convert the existing encoding to UTF-8. Once the scheme file character encoding has been changed, import the schema file.

    Note: For more information about importing schema files, refer to the Configuration Guide for BIG-IP Application Security Management.
