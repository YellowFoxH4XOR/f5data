Topic

This article applies to BIG-IP 12.1.0 and later. For information about other versions, refer to the following articles:

  • K16565: Configuring a Web Acceleration profile for use with a BIG-IP ASM-enabled virtual server (11.4.0 and later)
  • K13112: Configuring a Web Acceleration profile for use with a BIG-IP ASM-enabled virtual server (11.0.0 - 11.3.0)

You should consider using this procedure under the following condition:

  • You want to increase the processing speed of a BIG-IP ASM web application by caching static content.

Description

The Web Acceleration profile provides settings to configure caching for the BIG-IP system. Caching is designed to save bandwidth and reduce the amount of traffic load on the origin web servers. You can apply a Web Acceleration profile to a BIG-IP ASM-enabled virtual server for caching commonly requested static content (such as images). To do so, you can create a custom local traffic policy to define the traffic profiles that you want to cache, allowing for faster processing, lower overhead, and more efficient use of the cache.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The BIG-IP ASM module is licensed and provisioned.
  • The existing configuration has a functional virtual server that references a BIG-IP ASM security policy.

Configuring the Web Acceleration profile

To create the Web Acceleration profile, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services.
  3. Select Web Acceleration.
  4. Click Create.
  5. Provide a name for the custom Web Acceleration profile.

    For example:

    MyAccelerationProfile

  6. Change the Minimum Object Size option to 1 byte (the default setting is 500 bytes).
  7. Change the Maximum Object Size option to 150000 bytes (default setting is 50000 bytes).
  8. Click Finished.

Associating the Web Acceleration profile with the ASM-enabled virtual server

To associate the Web Acceleration profile with the ASM-enabled virtual server, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the ASM-enabled virtual server with which you want to associate the Web Acceleration profile.

    The system displays the Properties screen for the virtual server.

  4. In the Acceleration section, select the name of the Web Acceleration profile from the Web Acceleration Profile list.

    For example:

    MyAccelerationProfile

  5. Click Update.

Modifying the local traffic policy to cache static content

When you attach a security policy to a virtual server, the BIG-IP system automatically creates a local traffic policy. The local traffic policy forms a link between the local traffic components and the BIG-IP ASM security policy. To enable caching for the ASM-enabled virtual server, you must modify the existing local traffic policy and create a new rule that allows the system to cache static content. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the ASM-enabled virtual server.
  4. Click the Resources tab.
  5. In the Policies section, click the name of the local traffic policy that references the BIG-IP ASM security policy.

    For example:

    /Common/asm_auto_l7_policy__http_vip

  6. Click the Create Draft button.
  7. The system creates a draft of the local traffic policy and returns you to the Policy List page.
  8. In the Draft Policies section, click the name of the local traffic policy draft that references the BIG-IP ASM security policy.
  9. In the Rules section, click the Create button.
  10. Click the default rule that sends requests to the security policy.

    Note: The default rule is likely named default, and configured to send all traffic through the security policy.

  11. In the Do the following when the traffic is matched section, click the add button (+).
  12. Select the appropriate values from the menus to disable the cache:

    For example:

    • disable
    • cache
    • request
  13. Click Save.
  14. To create a new rule for enabling the cache for static content, click Create.
  15. Type a name for the rule.

    For example:

    MyCacheRule

  16. In the Match all of the following conditions section, click the add button (+).
  17. Select the appropriate conditional statements from the menus:

    For example:

    • HTTP URI
    • extension
    • is
  18. Enter each file type that you want the system to cache and click the Add button to add the value to the any of box.

    For example:

    • gif
    • jpg
    • bmp
    • png
    • css
  19. In the Do the following when the traffic is matched section, click the add button (+).
  20. Select the appropriate values from the menus to enable the BIG-IP ASM system for the appropriate security policy:

    For example:

    • enable
    • asm
    • <security_policy_name>
  21. In the Do the following when the traffic is matched section, click the add button (+).
  22. Select the appropriate values from the menus to enable the cache:

    For example:

    • enable
    • cache
    • request
  23. Click Save.
  24. In the Rules section, drag the default rule that disables caching to the bottom of the rules list.
  25. Click the Save Draft button.

    The Policies List page is displayed.

  26. In the Draft Policies section, check the box next to the local traffic policy draft that you edited.
  27. Click Publish.

After you have completed the previous steps, any static media content that you have defined in the local traffic policy that has been validated by the BIG-IP ASM security policy can use the Web Acceleration cache. This behavior allows content that has been checked by the BIG-IP ASM system to be served from the cache.
