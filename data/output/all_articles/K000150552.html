K000150552: Source-Checking and Auto-LastHop

Type
Support Solution
Published
2025-03-26
Updated
2025-04-01
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP DNS: 17.5.0
Source
https://my.f5.com/manage/s/article/K000150552

Description

DNS functionality breaks when both "Source-check enabled" and "Auto-LastHop disabled" settings are applied on the DNS VLAN. Queries to the DNS listener are dropped due to routing issues, preventing proper resolution of DNS requests.

Environment

  • Product: BIG-IP DNS

Cause

When "Source-checking" is enabled, the BIG-IP system verifies that it has a route back to the originating VLAN for incoming traffic. If no route exists for a discontiguous subnet back through the ingress VLAN, the packets destined for the DNS Listener t will be dropped. The configuration guide for the Source Check option specifies when checked (enabled), that the system verifies that the return route to an initial packet is the same VLAN from which the packet originated. The system performs this verification only if the Auto Last Hop option is disabled.

 

Recommended Actions

Configure static routes on the BIG-IP system for each LDNS server subnet that lacks a valid return path:

tmsh create net route <LDNS_Subnet>/<mask> interface /<Partition>/<Associated_VLAN>

For example:

tmsh create net route ldns_vlan 10.1.1.0/24 interface /Common/DNS_VLAN

 

Testing Validation:

After applying changes, perform packet captures using `tcpdump` to verify proper routing behavior:

tcpdump -nni 0.0:nnn port 53 and net <LDNS_Subnet> -vv -s0 -w /var/tmp/${HOSTNAME}_$(date "+%Y%m%d").pcap

 

Analyze captured packets for successful query responses and ensure no drops occur due to routing issues.
