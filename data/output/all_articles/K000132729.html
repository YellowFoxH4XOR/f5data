Description

Certain situation or requirement  may require selectively dropping traffic based on Geolocation for matched IP reputation categories. This can be done thru iRules.

Environment

Potentially during a DDoS attack
IP Intelligence is licensed
iRules

Cause

Certain situation or requirement  may require selectively dropping traffic based on Geolocation for matched IP reputation categories, for example, allowing certain Geolocations regardless of the source IP address IP reputation. 

Recommended Actions

To selectively drop traffic based on Geolocation for matched IP reputation categories, on a BIG-IP system that has an IP Intelligence license, the sample iRule can be created.

Important: The provided iRule is an example only. Customers should test the iRule in a test environment and ensure it matches their requirement before implementing it on a production environment. iRules are community supported.  


1 In the Configuration utility of the BIG-IP, go to Local Traffic  ››  iRules : iRule List,  click create 

2 Provide a name for the iRule and paste sample iRule syntax, click save

This iRule will make use of a Data Group (in this example, exceptGeo is the Data Group) where allowed Geolocations can be defined. The source IP address Geolocation and IP reputation category will be checked by the iRule, if the source IP address is from the allowed Geolocation, regardless of its IP reputation, traffic will be allowed. Traffic from other Geolocations will be checked and if the source IP address is matched to an IP reputation category, traffic will be dropped. 
  
when CLIENT_ACCEPTED {

set ipaddr [IP::client_addr]

set fromGeo [whereis $ipaddr country]

log local0. "$ipaddr from $fromGeo with reputation [IP::reputation $ipaddr] - incoming"
#log statement for troubleshooting purpose only and can be commented out

  # Check if the IP reputation list for the client IP is not 0

  if {([llength [IP::reputation $ipaddr]] != 0) and (![class match $fromGeo contains exceptGeo])}{

log local0. "$ipaddr from $fromGeo with reputation [IP::reputation $ipaddr] - drop"
    #log statement for troubleshooting purpose only and can be commented out 
    # Drop the connection

    drop

  }

}


3 Create the Data Group. go to Local Traffic  ››  iRules : Data Group List and provide a name.
In this example the Data Group name is exceptGeo.

4. Use the type string for the Data group and provide a string and a value. click Finished.
In this example, the string is TH and the value is TH, which represents the 2 letter country code that can be checked thru the iRules whereis command.
 

root@(big-ip)(cfg-sync Standalone)(TimeLimitedModules::Active)(/Common)(tmos)# list ltm data-group

ltm data-group internal exceptGeo {

  records {

    TH {

      data TH

    }

  }

  type string

}

5 Apply the iRule to the Virtual Server
