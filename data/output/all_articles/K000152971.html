K000152971: F5 Integration with Riverbed netprofiler fails with error 'Access denied by load balancer' on netprofiler

Description:

Integrating F5 BIG-IP LTM with Riverbed NetProfiler for iControl API access may result in authentication failures and access forbidden errors. You can observe a example error messages below:

  • AUTHCACHE Error processing cookie <cookie_string> - Cookie user mismatch
  • AUTHCACHE PAM: user '<username>' (fallback: false) - not authenticated: Authentication failure
  • Bad password (<username>): BAD PASSWORD: it is too simplistic/systematic
  • lookup failed: Invalid credentials

These errors are commonly triggered when multiple BIG-IP user accounts are configured on Riverbed netprofiler and alternatively try to authenticate to BIG-IP.

Environment:

  •  MS Active Directory (AD) integration
  • Riverbed NetProfiler requires iControl API access
  • Riverbed IP whitelisted for HTTPd and SSHd
  • Users created both locally and in AD
  • Guest group mapped to AD group
  • Remote authentication (AD) enabled

Cause:

The root cause is the configuration of two or more different BIG-IP user accounts on Riverbed NetProfiler. When authentication attempts alternate between these accounts, BIG-IP interprets this as cookie impersonation, resulting in repeated authentication failures and potential AD account lockouts.

Recommendations:

Configure only one BIG-IP user account on Riverbed NetProfiler for authentication.

Additional Information

  • The riverbed user does not need to be created locally on BIG-IP when remote authentication is enabled.
  • Local authentication fallback will only function if the remote server is unavailable.
  • Only local root and admin accounts can authenticate both locally and remotely at the same time.
  • Ensure that Riverbed NetProfiler saves and returns the BIGIPAuthCookie for each session; alternatively, adjust the pamcache timeout on BIG-IP to match Riverbed’s polling interval.
