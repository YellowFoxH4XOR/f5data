Description

Receiving invalid redirects after tried to send to https, with httpd's local port number, that received the request (https://hostname:80/) instead of the proper https port.

Environment

  • OIDC behind a reverse proxy
  • iRule
  • HTTP Profile
  • SSL proxy

Cause

OIDC behind a reverse proxy, requires X-Forwarded-For and X-Forwarded-Port.

Recommended Actions

  1. Create an iRule to insert X-Forwarded-For and X-Forwarded-Port
  2. In the new iRule write the following:
    when HTTP_REQUEST {
    HTTP::header insert X-Forwarded-For [IP::remote_addr]
    HTTP::header insert X-Forwarded-Port [TCP::local_port] }
  3. Add the new iRule created to the relevant Virtual Server

Additional Information

    OIDC:
    OpenID Connect is a simple identity protocol and open standard that is built using the OAuth 2.0 protocol.
    It enables client applications to rely on authentication that is performed by an OpenID Connect Provider (OP) to verify the identity of a user.
