K000139669: VCMP Guest is stuck with Please wait while this BIG-IP device reboots.. after upgrade

Type
Support Solution
Published
2024-05-17
Updated
2024-05-24
Applies to
  • BIG-IP
  • BIG-IP APM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000139669

Description

VCMP Guest is stuck with Please wait while this BIG-IP device reboots... yet never completes reboot or the upgrade process.

  • Webui is inaccessible
  • SSH session is connected and stable
  • vconsole is also possible
  • Pre-Upgrade version boot location shows active
  • New version shows as default Boot

 

Environment

  • BIG-IP
  • Upgrade to 16.1.43
  • VCMP Guest

Cause

Undetermined

Recommended Actions

Ensure a backup has been taken before starting the upgrade process. Otherwise Backup the system before moving on to next steps. 

K13132: Backing up and restoring BIG-IP configuration files with a UCS archive

Also it is a good idea to collect a qkview just in case support is needed. Please collect qkview from both hypervisor (host) and guest systems.

K12878: Generating diagnostic data using the qkview utility

Force the guest to reboot from Vcmp Host system.

K20081511: Shutting down and restarting the vCMP guest from the vCMP host

 

Additional Information

  1. Login to the vcmp Host system.
  2. Set the vcmp guest to configured status.
  3. Confirm you ssh session has ended. You should also not be able to ping at this point.
  4. Now from the vcmp host system set the impacted vcmp guest back to deployed status.
  5. Wait for the system to start up. Confirm you have access to both the webui and CLI. Verify the system is running version 16.1.4.3

Remember the webui sometimes can take some time as tomcat is one of the last services to start.
