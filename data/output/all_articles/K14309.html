Known Issue

Downloading files such as PDFs, Excel spreadsheets, or Word documents, through the BIG-IP APM system fails.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy is of type LTM+APM.
  • The virtual server uses a Secure Socket Layer (SSL) connection.
  • The file request is made before BIG-IP APM authentication.

    For example:

    https://<apm virtual server>/myfile.docx

  • You access the files using an Internet Explorer 7 or 8 browser.

The behavior of the BIG-IP APM authentication process was changed in BIG-IP 11.1.0 HF2 to add cache control headers to the URI landing page of the BIG-IP APM system. An issue with Microsoft Internet Explorer 7 and 8 prevents downloading files over an SSL connection when a cache control header is used. For more information about the Internet Explorer issue, refer to the following Microsoft document:

Note: The following link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

KB323308 - Internet Explorer file downloads over SSL do not work with the cache control headers

Impact

Users are unable to download files through the BIG-IP APM system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The user receives an error message that appears similar to the following example:

    Unable to open this Internet site. The requested site is either unavailable or cannot be found.

Workaround

To work around this issue, you can add an iRule to the virtual server that disables the cache control for Internet Explorer 7 or 8. To do so, perform the following procedure:

Impact of workaround: There will be a small performance impact.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name for the iRule.

    For example:

    IE7-fix

  5. In the Definition box, type the following text:

    when HTTP_REQUEST {

       set IE8 0

       if { [HTTP::header "User-Agent"] contains "MSIE 7.0" || [HTTP::header "User-Agent"] contains "MSIE 8.0" }{

          set IE8 1
       }
    }

    when HTTP_RESPONSE_RELEASE {

       set app 0

       if { [string tolower [HTTP::header Content-Type]] contains "application/" } {

           set app 1
       }

       if { $app == 1 && $IE8 == 1  } {

           HTTP::header replace Cache-Control "private,max-age=0"

           HTTP::header remove Pragma
       }
    }

  6. Click Finished.
  7. Click Virtual Servers.
  8. Next to the name of the affected virtual server, click Edit.
  9. In the iRules section, click Manage.
  10. From the Available column, select the previously-created iRule.
  11. Click the << button.

    The iRule moves to the Enabled column.

  12. Click Finished.
