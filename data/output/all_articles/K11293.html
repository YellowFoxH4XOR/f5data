Known Issue

This is the result of a known issue. By default, the BIG-IP system uses the /etc/services file to translate numeric service ports to their corresponding service names when saving configuration objects to the bigip.conf file, and to translate the service names in the bigip.conf file to their corresponding service ports when loading the configuration. In BIG-IP version 10.1.0, the /etc/services file was updated to include a number of well-known services whose service names begin with a digit. If a BIG-IP configuration contains objects that reference these services, the configuration may fail to load. 

Objects using these service ports may be created in the Configuration utility without error. The service port is translated to the service name and written to the bigip.conf file as expected, and the object functions as expected. However, subsequent attempts to load the resulting configuration fail with an error message that appears similar to the following example:

012e0022:3: The requested value (10.10.65.1:4talk {) is invalid (show | <pool member list> | none) [add | delete]) for 'members' in 'pool'

Note: The error message may reference a different member in the same pool as the member that is actually causing the error.

In this example, the pool member was originally created by specifying service port 3284. The BIG-IP system saved the pool member using the corresponding service name, 4talk, but the system is unable to translate the service name back to the service port.

This issue may occur when the configuration is manually reloaded by entering the bigpipe load command, or by any of the following three methods:

  • Synchronizing the configuration between units of a redundant pair
  • Restoring a configuration archive
  • After upgrading your BIG-IP system to version 10.1.0 - 10.2.4

F5 Product Development tracked this issue as ID 339850 (formerly CR136194).

Note: The issue described in this article does not apply to BIG-IP version 11.0.0 and later.

Workaround

You can work around this issue by performing one of the following two procedures:

  • Globally configuring the BIG-IP system to not translate service ports to service names when storing configuration objects in the bigip.conf file
  • Individually commenting out the lines in the /etc/services file that correspond to offending service names

Globally configuring the BIG-IP system to not translate service ports to service names when storing configuration objects in the bigip.conf file

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    bigpipe cli service number

    Note: The service option is incorrectly described in the bigpipe cli man page. For more information, refer to K11301: Documentation Erratum: The bigpipe cli man page provides incorrect information for the service option.
  3. Save the configuration by typing the following command:

    bigpipe save

    Note: The bigip.conf file is saved using service port numbers rather than service name strings.
  4. Test the configuration by typing following command:

    bigpipe verify load

Individually commenting out the lines in the /etc/services file that correspond to offending service names

  1. Log in to the BIG-IP command line.
  2. Save the bigip.conf file with port numbers instead of service names by typing the following two commands:

    bigpipe cli service number

    bigpipe save
  3. Back up the /etc/services file by typing the following command:

    cp /etc/services /etc/services.SOL11293
  4. Open the /etc/services file in a text editor.
  5. Locate the entries you no longer want the system to translate, and type a # character at the beginning of the line.

    For example, to discontinue translation of port 3284 to its registered service name, 4talk, locate the following line in the /etc/services file:

    4talk           3284/tcp                        # 4Talk

    Modify the line as follows:

    #4talk           3284/tcp                        # 4Talk
  6. Save the file and exit the editor.
  7. Restore the service name setting and save the bigip.conf file using service names by typing the following two commands: 

    bigpipe cli service name

    bigpipe save
  8. Test the configuration by typing following command:

    bigpipe verify load

    Repeat the procedure until all affected services in use on your system have been commented out and the configuration load can be verified without errors.
