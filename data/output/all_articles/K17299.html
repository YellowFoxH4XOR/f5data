Known Issue

A Simple Network Management Protocol (SNMP) trap is not triggered when a Redundant Array of Independent Disks (RAID) disk failure event occurs.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP platform with RAID configured.
  • One of the disks in the RAID configuration experiences a failure event.

Impact

No SNMP traps are sent and no LCD front panel messages are displayed.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system fails to send SNMP traps when log messages similar to the following example appear in the /var/log/kern.log file:

    alert kernel: md/raid1:md12: Disk failure on dm-29, disabling device.

Workaround

To work around this issue, you can create a custom trap for the Disk failure log message. For more information, refer to K3727: Configuring custom SNMP traps.
