Topic

You should consider using this procedure under the following condition:

  • You want to disable default SNMP traps or email notifications for specific virtual servers.

Description

The BIG-IP system includes preconfigured SNMP traps to provide alert notifications for standard system events. Custom SNMP traps allow you to configure the BIG-IP system to send email notifications as well as traps for monitored events. In some cases, you may want to disable SNMP alert notifications only for a specific virtual server while continuing to receive alert notifications for the other virtual servers. By creating a custom SNMP trap in the /config/user_alert.conf file, you can filter for the specific log message generated for the event and comment out any directives you want to disable. For example, to disable traps and email notifications when the virtual server named /Common/example_vip becomes unavailable, the entry in the /config/user_alert.conf file appears similar to the following example:

alert VIP_DISABLE_ALERT "Virtual /Common/example_vip has become unavailable" {
#          snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.999";
#          email toaddress="email@example.com"
#          fromaddress="root@bigip.company.com"
#          body="Virtual server is unavailable!"
}

With this configuration, the user_alert.conf file is read after the alert.conf file, effectively disabling the trap and email notifications for the /Common/example_vip virtual server. The BIG-IP system continues to send the default alert notifications when the other configured virtual servers become unavailable.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the Advanced Shell (bash).

Procedures

To disable SNMP alert notifications for a specific virtual server, perform the following procedure:

Impact of procedure: System alert messaging is temporarily disrupted while the alertd process restarts.

  1. Log in to the Advanced Shell (bash).
  2. Review the log file to locate the alert message for which you want to disable notifications.
  3. Back up the user_alert.conf file by typing the following command:

    cp /config/user_alert.conf /config/user_alert.conf.K53142338

  4. Using a text editor such as the vi utility, open the user_alert.conf file for editing.
  5. Create a new alert entry using the following syntax:

    alert <custom_alert_name> "<matched_log_message>" {
    #          snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.<300 - 999>";
    #          email toaddress="<destination_email_address>"
    #          fromaddress="<source_email_address>"
    #          body="<message_body>"
    }

    Replace <custom_alert_name> with a custom alert name that is not already listed in the /etc/alertd/alert.conf file. Replace <matched_log_message> with the log message you located previously. You can use a regular expression to match multiple messages. Comment out the lines containing the directives you want to disable by prefixing the line with a # character.

    For example, if you want to disable traps and email notifications when virtual servers become unavailable with names beginning with /Common/example_, such as /Common/example_test and /Common/example_dev, the stanza appears as follows:

    alert VIP_DISABLE_ALERT "Virtual /Common/example_(.*)has become unavailable" {
    #          snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.999";
    #          email toaddress="email@example.com"
    #          fromaddress="root@bigip.company.com"
    #          body="Virtual server is unavailable!"
    }

  6. Save the changes made to the user_alert.conf file.
  7. Restart the alertd process to load the file changes by typing the following command:

    tmsh restart /sys service alertd
