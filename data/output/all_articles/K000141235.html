Description

  • All the fields in the DNS logs.

Environment

  • BIG-IP DNS provisioned
  • Different formatted logs are seen in /var/log/ltm other than the format explained in https://my.f5.com/manage/s/article/K16197

Cause

All the fields in the DNS logs explained for better clarity.

Recommended Actions

Aug 17 04:46:03 bigip.test info tmm[11212]: 2024-08-17 04:46:02 bigip.test qid 10035 from 10.110.181.34#35827: view none: query: google.com IN A +E (10.110.181.35%0)

Aug 17 04:46:03 bigip.test info tmm[11212]: 2024-08-17 04:46:02 bigip.test qid 10035 to 10.110.181.34#35827: [NOERROR qr,rd,ra] response: google.com. 290 IN A 142.251.33.78;

Below is a sample tcpdump for the same two logs above:

  2 04:46:03.619844 10.110.181.34 ? 10.110.181.35 DNS 126 IN s1/tmm0 : Standard query 0x2733 A google.com OPT

  3 04:46:03.620044 10.110.181.35 ? 10.110.181.34 DNS 144 OUT s1/tmm0 : Standard query response 0x2733 A google.com A 142.251.33.78 OPT

 

Fields from request : 

- day

- hour

- hostname

- qid 10035 is query id. From pcap you see 0x2733, 10035 is decimal value of 0x2733. See below:

root@00667500-ubuntu-server:~# printf "%d\n" 0x2733

10035

- from 10.110.181.34#35827 is the client IP and port (where query comes from)

- view none relates to BIND views. BIND uses views so if a query happens to hit BIND then this will have a view other than none. View none means the query was not replied by BIND. Hence no view.

- query describes the hostname which was queried. In our case, it was google.com

- IN is the class

- A is the query type

- +E means EDNS was used
