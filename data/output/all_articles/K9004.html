Topic

Voice over IP (VoIP) is a technology that transmits voice traffic across IP-based networks. Deploying VoIP in a data network requires careful planning and engineering, since networks must be engineered to support the unique nature of voice-based data as opposed to application-based data. For example, VoIP is typically intolerant of data loss as it affects the quality of the call, while many network applications can manage with data loss. VoIP is typically intolerant of network delays and retransmissions, while many network applications are tolerant of such delays and retransmissions.

VoIP is a well established technology with a wide community of open source and commercial products acting as clients, servers, gateways, and proxies. VoIP implementations are typically UDP-based and function on an isochronous communications logic (they maintain a constant stream of small-byte UDP data). Networks designed to support VoIP typically deploy IP Quality of Service (QoS) policies to guarantee the bandwidth required by VoIP applications. This is typically implemented through the use of a strict priority and/or low latency queue. Depending on the voice codec deployed (for example G.711 or G.729a), voice packets are typically sent every 20 milliseconds isochronously at a constant rate. Due to the nature of IP networking, each packet may be routed differently, lost, or delayed due to routing changes, busy networks, or congested network links. The time variation between packets arriving is referred to as jitter.

Users can transmit VoIP data over a FirePass Network Access connection, and many existing FirePass customers have deployed Network Access based solutions for protecting VoIP data. However, there are several considerations, which are outlined below.

Note: F5 Networks does not recommend any specific VoIP application for use over FirePass Network Access connections.

VoIP and QoS

Networks designed for VoIP typically implement QoS policies to prioritize time-sensitive applications such as VoIP. Since FirePass is primarily designed to function on the Internet, which itself does not support any QoS, FirePass does not support specific QoS related features. VoIP traffic receives the same priority as the other network traffic transmitted between the client system and the FirePass controller.

When a user makes or receives a VoIP call through a Network Access connection, the user may want to close other network applications to increase available bandwidth for the VoIP data. For example, if the user’s email client remains open during the call, and the email client downloads a new message with a large attachment, the quality of the user’s VoIP call may be affected.

VoIP and NAT

Some VoIP protocols and applications are not compatible with Network Address Translation (NAT). By default, FirePass Network Access connections use Network Address Port Translation (NAPT). If the VoIP protocol or application you’re using does not support Network Address Translation, configure FirePass to use a virtual subnet instead of NAPT.

Note: For information about configuring a virtual subnet, refer to the FirePass Controller Administrator Guide.

Note: For information about the routing differences between a virtual subnet and NAPT, refer to K8112: Network-layer routing considerations when using Network Access.

VoIP and TCP

Most VoIP applications use UDP to transmit data, since VoIP is time-sensitive and intolerant of retransmissions. Although FirePass supports non-TCP traffic over Network Access connections, all traffic between the client system and the FirePass controller is encapsulated within TCP-based SSL packets. This means that if an SSL packet between the client system and the FirePass controller is lost, the packet will be retransmitted even if the original UDP packet contained within the SSL packet would not have been retransmitted.

VoIP and gzip compression

Most VoIP data is compressed prior to transmission and will receive little, if any, additional compression from gzip. If you enable gzip compression for a FirePass Network Access connection, the additional processing overhead required by gzip may reduce the quality of VoIP transmissions.

By default, gzip compression is disabled for Network Access connections. If you enabled gzip compression for a Network Access connection, and users transmit VoIP traffic through that Network Access connection, you may want to disable gzip compression.

To disable gzip compression, perform the following procedure:

Important: Disabling gzip compression may improve the quality of VoIP transmissions, but it may also reduce the performance of other applications accessed through that Network Access connection.

  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Network Access : Resources page.
  3. In the Resource Group menu, select the name of the resource group you want to configure.
  4. In the Additional Settings section, clear the Use gzip compression check box.
