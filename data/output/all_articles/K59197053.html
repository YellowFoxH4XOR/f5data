Security Advisory Description

When an LTM Client or Server SSL profile with TLS 1.3 enabled is configured on a virtual server, along with an iRule that calls HTTP::respond, undisclosed requests can cause the Traffic Management Microkernel (TMM) to terminate. (CVE-2022-34651)

Impact

Traffic is disrupted while the TMM process restarts. This vulnerability allows a remote unauthenticated attacker to cause a denial-of-service (DoS) on the BIG-IP system. There is no control plane exposure; this is a data plane issue only.

Note: TLS 1.3 is disabled by default. This vulnerability affects only configurations where TLS 1.3 has been explicitly enabled.

Mitigation

To mitigate this vulnerability, you can perform either of the following procedures:

  • Disable the TLS 1.3 protocol from the ClientSSL and ServerSSL profiles
  • Remove the iRule or remove the HTTP::respond command within the iRule that is associated with the impacted virtual server

If you cannot perform these procedures, F5 recommends that you configure systems with high availability (HA) clustering to lessen the impact of this vulnerability.

For more information, refer to K02234544: Manually setting up device service clustering.

For more information about configuring the HA table to take specific actions, refer to K9231: Overview of BIG-IP daemon heartbeat failsafe.

Disable the TLS 1.3 protocol from the Client SSL and Server SSL profiles

If you have enabled TLS 1.3 support by following K10251520: BIG-IP support for TLS 1.3, you can mitigate this issue by disabling TLS 1.3. To do so, perform the following procedure.

Impact of action: Disabling TLS 1.3 may have speed and security implications which can vary depending on the individual implementation and customer needs.

Note:  You can make this change on an active system.  All existing connections will continue to use the previous configuration, and new connections will use the new configuration. F5 recommends that you follow the best practice of making changes during a maintenance window.

  1. Log in to the BIG-IP Configuration utility as an administrative user.
  2. Go to Local Traffic > Profiles > SSL > Client or Server.
  3. Select the SSL profile you want to change.
  4. Under Configuration, select Advanced from the pull-down menu.
  5. For Options List, in the Enabled Options box, ensure the No TLSv1.3 option is listed.

    If it is not, select it from the Available Options box and select Enable.

  6. To save your changes, at the bottom of the screen, select Update.
  7. Repeat the previous steps for each Client or Server SSL profile in use.

Remove the iRule or remove the HTTP::respond command within the iRule that is associated with the impacted virtual server

Impact of action: The impact is specific to the implementation you choose.

Modifying a custom iRule is outside the scope of this document.  Refer to F5 Support or F5 Professional Services for further assistance.
