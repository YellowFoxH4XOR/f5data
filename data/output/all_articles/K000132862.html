K000132862: F5OS tenant restarted when running grep with xargs on /var/F5/system

Type
Support Solution
Published
2023-03-06
Updated
2023-03-06
Applies to
  • F5OS
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000132862

Description

An F5OS tenant died and restarted when running a grep command similar to the following:

find /var/F5/system/ -name "*" -type f | xargs grep "Unit key was found"

And grep was terminated with signal 9 (SIGKILL):

xargs: grep: terminated by signal 9

Environment

  • F5OS
  • Command line

Cause

Out of memory condition, caused by grep attempting to read from very large files under /var/F5/system (tenant disks).

Low host memory from the bloated grep process results in OOM killer, which kills off the tenant processes, and finally the grep:

Feb 24 14:18:12 appliance-1.chassis.local kernel: Out of memory: Kill process 21124 (grep) score 134 or sacrifice child
Feb 24 14:18:12 appliance-1.chassis.local kernel: [ pid ] uid tgid total_vm rss nr_ptes swapents oom_score_adj name
Feb 24 14:18:12 appliance-1.chassis.local kernel: [21124] 0 21124 6294260 2266699 4440 0 0 grep
Feb 24 14:18:12 appliance-1.chassis.local kernel: Killed process 21124 (grep), UID 0, total-vm:25177040kB, anon-rss:9066120kB, file-rss:676kB, shmem-rss:0kB

Recommended Actions

Care should be taken when constructing grep commands.

In this case, it would've been sufficient to do a recursive grep on the log directory:

grep -r 'Unit key was found' /var/F5/system/log

When a find/xargs pipeline is used, run the find on its own first to check what files are found.

Avoid grepping inside very large files, and limit the directory tree to only include files that are relevant (e.g. log directories).
