Topic

You should consider using these procedures under the following condition:

  • You want to configure geolocation enforcement for a BIG-IP ASM security policy.

Note: This article applies to the BIG-IP ASM security policy. For information about configuring Geo IP in the BIG-IP LTM local traffic policy, refer to the BIG-IP Local Traffic Management: Getting Started with Policies manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

Description

When you configure geolocation enforcement for a BIG-IP ASM security policy, the system determines the geolocation of a client request and controls access to the application in specific countries. For example, you can configure a list of countries from which users are not allowed to access the application. If a client attempts to access the application from a restricted country, the system blocks the request and logs the Access from disallowed GeoLocation violation to the BIG-IP ASM Security > Event Logs page.

You can use the following approaches when configuring geolocation enforcement:

  • To allow application access to users only in certain geographical locations, you can add those specific locations to the Allowed Geolocations list and all other locations to the Disallowed Geolocations list.
  • To deny application access to users only in certain geographical locations, you can add those specific locations to the Disallowed Geolocations list and all other locations to the Allowed Geolocations list.

Note: F5 regularly releases database updates in the GeoLocationUpdates product container for each version of each BIG-IP product line on the F5 Downloads site. For more information, refer to K11176: Downloading and installing updates to the IP geolocation database.

Enable Accept XFF in the HTTP profile

If you deploy the BIG-IP system behind a trusted proxy, then you should enable the Accept XFF setting in the HTTP profile associated with the virtual server. Doing so allows the BIG-IP ASM system to use the IP address that initiated the connection to the proxy when determining the geolocation.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Services > HTTP.
  3. Select the HTTP profile associated with the BIG-IP ASM-enabled virtual server.
  4. In the Settings section, select the Custom check box.
  5. Select the Accept XFF check box.
  6. Select Update.

Enable the Trust XFF Header in a security policy

If you deploy the BIG-IP system behind a proxy, you should enable the Trust XFF Header option in the security policy properties. Doing so allows the system to identify the location using the address from the XFF header instead of the source IP address. To enable the Trust XFF Header option, perform the following procedure that applies to your version.

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

BIG-IP 15.1.0 and later

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the security policy.
  4. In the Security Policy Configuration section, select General Settings.
  5. For Trust XFF Header, select Enabled.
  6. Select Save Changes.
  7. Select Apply Policy to put the changes into effect.

Configure geolocation enforcement (16.1.0 and later)

To configure geolocation enforcement for the security policy, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the security policy.
  4. Select General Settings.
  5. Under Advanced Settings in the Geolocation Enforcement section, move geolocations into Disallow Access or Allow Access as appropriate for your policy.
    Note: If no geolocations are disallowed, the Disallow Access list is empty.
    • To restrict traffic from anonymous proxies, move Anonymous Proxy to the Disallow Access list.
    • To restrict traffic from locations that the system cannot identify, such as RFC-1918 addresses or unassigned global addresses, leave N/A in the Disallow Access list.
  6. Select Save.
  7. Select Apply Policy.

Configure geolocation enforcement (12.x - 16.0.x)

To configure geolocation enforcement for the security policy, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Geolocation Enforcement.
  3. In the Current edited security policy list, select the name of the policy you want to edit.
  4. In the Geolocation List, move geolocations into Disallowed Geolocations or Allowed Geolocations as appropriate for your policy.

    Note: If no geolocations are disallowed, the Disallowed Geolocations list shows None.

    • To restrict traffic from anonymous proxies, move Anonymous Proxy to the Disallowed Geolocations list.
    • To restrict traffic from locations that the system cannot identify, such as RFC-1918 addresses or unassigned global addresses, leave N/A in the Disallowed Geolocations list.
  5. Select Save.
  6. Select Apply Policy.
