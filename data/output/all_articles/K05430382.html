Error Message

01070712:3: Caught configuration exception (0) Values <…> specified for <…>: foreign key index (<…>_FK) do not point at an item that exists in the database

In this error message, note the details listed in section of the message highlighted as <…> specified for <…>:

For example:

01070712:3: Caught configuration exception (0), Values (/Common/TMG_HTTP) specified for virtual server policy (/Common/TMG_HTTP /Common/Redirector): foreign key index (vs_FK) do not point at an item that exists in the database.

or

Mon DD 00:00:50 localhost emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all gtm-only" - failed. -- 01070712:3: Values (/Common/Link) specified for GTM IP (10.10.10.10 /Common/Server): foreign key index (explicit_link_FK) do not point at an item that exists in the database. Unexpected Error: Loading configuration process failed.

Message Location

You may encounter this message in the following location[s]:

  • The /var/log/ltm file
  • TMUI -> Device Management -> Overview
  • tmsh CLI show /cm sync-status
  • tmsh CLI after applying load sys config or load sys ucs


Description

This message occurs when the configuration still contains a link to a configuration object which is no longer defined in the configuration.

Impact
  • Configuration load fails
  • Config Sync fails

Workaround
Follow the guidance of K13132 to create a UCS archive of All BIG-IP systems in the CMI cluster prior to making any changes.

  1. Disregard the element mentioned in <…>_FK It is generated automatically and cannot be corrected directly. Focus on the elements listed in <…> specified for <…>:

  2. Review the elements throughout the configuration files. Identify the element missing and consider either commenting out these links or creating it in the configuration file
  3. Validate that the modified configuration is able to load successfully by running tmsh load sys config verify
