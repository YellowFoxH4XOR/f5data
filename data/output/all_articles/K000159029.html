Description

After pushing a license from BIG-IQ to a BIG-IP Virtual Edition device, the mcpd process continuously restarts, preventing normal operation. The system logs display repeated "Re-starting mcpd" messages:

Broadcast message from systemd-journald@test.openstacklocal (Wed 2026-01-07 03:25:38 PST):

logger[12404]: Re-starting mcpd

Additional log entries show:

Jan 7 06:07:56 test.openstacklocal emerg logger[25987]: Re-starting mcpd

Jan 7 06:07:56 test.openstacklocal emerg logger[26070]: Re-starting devmgmtd

The device cannot maintain a stable licensed state. When the bigip.license file is manually deleted, the process restarts stop, but the device loses its license.

Environment

  • BIG-IP Virtual Edition version 17.1.1.3
  • None KVM based Linux hypervisors 
  • License:  license distributed from BIG-IQ

Cause

Platform incompatibility: The BIG-IP VE image is designed for KVM-based hypervisors and is not compatible with None KVM based hypervisors. None KVM based hypervisors causing the mcpd process to continuously restart when attempting to apply the license.

Recommended Actions

  1. Verify the underlying hypervisor architecture of cloud instances before deploying BIG-IP VE:
    • Confirm that the selected instance type uses standard KVM or other supported virtualization technology
    • Consult the cloud provider's documentation to identify the hypervisor type for each instance series
  2. Refer to F5's supported platform matrix to ensure compatibility with the deployment environment before deployment
  3. If already deployed on an incompatible instance type, migrate the BIG-IP VE to a KVM-based instance type and reapply the license

Additional Information

None KVM based private Cloud is not officially listed in F5's tested and supported public cloud platforms. Compatibility depends on the underlying hypervisor being Linux KVM-based or another supported virtualization technology.  

When deploying on cloud platforms not explicitly listed in F5's compatibility matrix, always verify that the underlying hypervisor matches one of the supported platforms (Linux KVM, VMware ESXi, Microsoft Hyper-V, etc.).
