K12646: The use of collect iRule commands may cause certain connections to stall and ultimately reset

Topic

The BIG-IP system includes several iRule commands to capture the payload data of various communication protocols. These iRule commands include, but are not limited to, TCP::collect, SCTP::collect, SSL::collect, and HTTP::collect.

When a virtual server is configured with an iRule that invokes one of the collect commands, the virtual server waits for data from the client before opening a server-side connection. This is the default and intended behavior.

While in the vast majority of cases this behavior works well, it causes an issue when the client does not send any data before receiving data from the server. This is the case, for example, with the FTP, SMTP, and SSH protocols. As soon as a connection is opened to one of these services, the service advertises itself to the client with one or more greeting lines that appear similar to the following example:

FTP
220 Welcome to ftp.example.com
220 FTP server ready

SMTP
220 smtp.example.com ESMTP service ready

SSH
SSH-2.0-OpenSSH_4.3

As a result, if the client does not receive the expected greeting line, the connection will stall, and will ultimately be reset by the BIG-IP system for exceeding its configured idle timeout.

For example, if the following iRule is associated with an FTP virtual server, the virtual server will immediately stop working:

when CLIENT_ACCEPTED {
TCP::collect
}
when CLIENT_DATA {
if { [TCP::payload] contains "dev" } {
pool dev_ftp_servers
} else {
pool ftp_servers
}
TCP::release
}

Note: The SSL:::collect iRule command only behaves in the way described in this Solution beginning with BIG-IP version 10.2.0-HF2. For more information, refer to K12641: Using the SSL::collect iRule command now causes a virtual server to wait for client data before opening a serverside connection.

Note: For the TCP::collect iRule command, it is possible to avoid the issue described in this article by specifying the <skip_bytes> argument. When this argument is specified, the BIG-IP system does not delay the serverside connection. For more information, refer to the TCP::collect wiki page on DevCentral. An equivalent option for the other collect iRule commands does not currently exist. A DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

F5 recommends that you avoid using collect iRule commands that delay the serverside connection in conjunction with protocols where the server sends data first.

F5 Product Development is tracking a Request For Enhancement (RFE) to introduce a new option to control whether the execution of a collect iRule command should delay the serverside connection.

F5 Product Development is tracking this RFE as ID 347534.
