K000152866: Configuring Multiple RADIUS Servers for Admin Authentication on BIG-IP

Type
Support Solution
Published
2026-02-05
Updated
2026-02-05
Applies to
  • BIG-IP
Source

Description

When configuring admin authentication on F5 BIG-IP LTM using RADIUS, it is possible to add more than two RADIUS servers for redundancy and high availability. By default, only the first two servers listed in the configuration are used for authentication failover. 

Environment

  • F5 BIG-IP LTM
  • Admin authentication via RADIUS

Cause

The main authentication configuration references only a subset of available RADIUS server objects (typically two). Additional server objects must be explicitly included in the authentication profile to participate in failover. If additional servers are added but not referenced in the main authentication profile, authentication requests will not reach these backup servers. No error messages are generated, but failover may not occur as expected.

Recommended Actions

Add Additional RADIUS Servers Using TMSH (CLI)

  • Create a radius-server object for each server:
    • tmsh create /auth radius-server system_auth_name3 server IP_ADDRESS_3 secret SECRET
    • tmsh create /auth radius-server system_auth_name4 server IP_ADDRESS_4 secret SECRET

Update Authentication Profile to Reference All Servers

  • Modify the profile to include all desired servers in order
    • tmsh modify auth radius system-auth servers replace-all-with{ system_auth_name1 system_auth_name2 system_auth_name3 system_auth_name4 } 

Enable fallback:

  • tmsh modify /auth source type radius fallback true
  • tmsh save sys config

Verify Configuration

  • List configured RADIUS servers:
    • tmsh list auth radius-server
  • List current authentication profile:
    • tmsh list auth radius

Testing and Validation

  • There is no built-in command to directly test RADIUS authentication from BIG-IP.
  • Use network monitoring tools such as tcpdump to observe traffic and confirm that requests fail over through all configured servers.
    Ensure all BIG-IP devices are registered on each RADIUS server and that network connectivity is established.

Additional Information

Order your configuration so primary data center servers are listed first, followed by disaster recovery servers for optimal failover behavior.
