Topic

The BIG-IP system does not remove BIG-IP ASM client cookies from requests that are sent to an origin web server (OWS).

Note: Starting in version 14.0.0, the BIG-IP system no longer passes ASM cookies to OWS by default. For more information about the new behavior, refer to K30023210: The BIG-IP ASM cookies are no longer passed to origin web servers.

Description

The BIG-IP ASM system sets two types of cookies to enforce elements in the security policy. The ASM cookie length varies, depending on the version of BIG-IP ASM you are running: 

Cookie typeFormat 11.3.0 and aboveFormat 11.2.1 and below
Main ASM cookieTSxxxxxxxxTSxxxxxx
ASM Frame cookieTSxxxxxxxx_dTSxxxxxx_d

After these cookies are set, they are not removed from HTTP requests proxied by the BIG-IP ASM system. These cookies are not usable by the OWS. However, the cookies are left intact to conserve the processing resources that would otherwise be dedicated to removing the cookies from every HTTP header before the BIG-IP ASM system passes the connection to the OWS.

Recommendations

The BIG-IP ASM cookies are unlikely to be relevant or problematic to an OWS receiving connections from the BIG-IP ASM. However, you can create an iRule to remove the BIG-IP ASM cookies from the server side connections, if your specific environment requires it. To do so, perform the following procedure:

Impact of procedure: Adding an iRule will increase the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing could introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

Note: The following procedure uses the HTTP_REQUEST_RELEASE iRules event, which was introduced in BIG-IP 11.x. For information about creating iRules for earlier versions of BIG-IP software, refer to DevCentral. A DevCentral login is required to access this content.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Provide a Name for the iRule.
  5. For Definition, enter the following data:

    when HTTP_REQUEST_RELEASE {
      set cookies [HTTP::cookie names]
      foreach aCookie $cookies {
        if {$aCookie matches_regex {^TS(?:[0-9a-fA-F]{6,8})(?:$|_[0-9]+$)}} {
          # Remove ASM Cookies
          HTTP::cookie remove $aCookie
        }
      }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the appropriate BIG-IP ASM enabled virtual server.
  9. Under Resources, click Edit.
  10. In iRules, click Manage.
  11. In the Available list, highlight the name of the iRule you defined in step 3.
  12. Click << to assign the iRule to the virtual server.
  13. Click Finished.
