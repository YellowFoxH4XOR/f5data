Description

Unused interfaces on a BIG-IP LTM tenant hosted on an rSeries platform may remain displayed as enabled and Uninitialized after being disabled at the F5OS host level. External monitoring may incorrectly report these interfaces as being in an error state.

Environment

  • F5OS on an rSeries platform
  • BIG-IP LTM tenant
  • Unused interfaces disabled at the F5OS host level
  • No VLAN association configured for the interfaces in the tenant
  • External interface monitoring

Cause

Network interfaces assigned to BIG-IP tenants on rSeries platforms are managed at the F5OS host level and are read-only from the tenant. An interface without an associated VLAN is displayed as Uninitialized in the tenant.

The Uninitialized state is expected for unused interfaces without VLAN mappings and does not indicate a BIG-IP fault.

Although tmsh may permit tenant-side interface modification, direct interface changes from the tenant are unsupported. Fixes are available for the discrepancy in which tmsh permits changes that are blocked by the Configuration Utility.

Recommended Actions

  1. Manage tenant network interfaces from the F5OS host level.
  2. Do not attempt to disable or enable interfaces directly from the BIG-IP LTM tenant.
  3. Exclude unused tenant interfaces from external monitoring.
  4. Alternatively, configure the monitoring system to treat Uninitialized as an expected state for interfaces without VLAN assignments.
  5. Do not interpret the tenant-side Uninitialized display state as an operational interface failure.

Additional Information

  • BIG-IP tenant interfaces on rSeries platforms are intentionally read-only from the tenant.
  • Directly disabling or enabling interfaces in the tenant is not supported.
  • Interface modifications should be performed only at the rSeries F5OS host level.
  • Tenant-level interface control for testing or HA/failover simulation is not currently supported.
