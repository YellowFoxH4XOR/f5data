Known Issue

The Traffic Management Microkernel (TMM) may restart and produce a core file when a client accesses multiple browser tabs through a BIG-IP APM access profile.

This issue occurs when all of the following conditions are met:

  • A user's browser is configured to open multiple browser instances (home page tabs) that reference the same BIG-IP APM access profile.
  • The BIG-IP APM access policy is accessed from multiple tabs with long initial URLs before the session is fully established.
  • The length of the encoded URLs is about 4,000 characters.
  • The user opens the browser and launches all BIG-IP APM access profile requests simultaneously.

Impact

The BIG-IP APM system fails to process traffic while the tmm process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users cannot access the BIG-IP APM system, or may experience traffic disruptions.
  • The tmm process generates a core file to the /shared/core directory.
  • The BIG-IP system generates a SIGSEGV fault and stack trace in the /var/log/tmm file.
