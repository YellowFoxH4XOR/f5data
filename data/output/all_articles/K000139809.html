K000139809: Getting 'UH - BlackHoleCluster' errors when communicating to an IPV6 only service

Type
Support Solution
Published
2024-09-30
Updated
2024-09-30
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000139809

Description

When you are trying to communicate to an IPv6 only Service, and you are getting the following errors:

[2024-05-28T17:15:24.300Z] "- - -" 0 UH - - "-" 0 0 0 - "-" "-" "-" "-" "-" BlackHoleCluster - [fd02:0:0:4::45d]:7000 [fd02:0:0:c::e6]:36934 - -
[2024-05-28T17:15:24.301Z] "- - -" 0 UH - - "-" 0 0 0 - "-" "-" "-" "-" "-" BlackHoleCluster - [fd02:0:0:8::1af]:7000 [fd02:0:0:c::e6]:57428 - -
[2024-05-28T17:15:24.301Z] "- - -" 0 UH - - "-" 0 0 0 - "-" "-" "-" "-" "-" BlackHoleCluster - [fd02:0:0:4::45d]:7000 [fd02:0:0:c::e6]:36944 - -


And you have the following Service Entry for the communication:

apiVersion: networking.istio.io/v1beta1
kind: ServiceEntry
metadata:
  name: ipv6se
  namespace: default
spec:
  addresses:
  - 10.96.35.61
  exportTo:
  - .
  hosts:
  - 'httpbin.default.svc.cluster.local'
  location: MESH_INTERNAL
  ports:
  - name: http-7000
    number: 7000
    protocol: HTTP
  resolution: NONE

 

Environment

  • AspenMesh 1.14.6-am6 and later
  • Dual-Stack enabled 

Cause

On the "Adresses" field of the Service entry, there is an IPv4 address for an IPv6 only setup. If you add that IPv4 address, it won't create the ipv6 listener for that Service Entry, since it has to match that virtual IP/subnet addresses associated with the service:

istioctl pc listeners sleep-698cfc4445-8vfwn --port 7000
ADDRESS PORT MATCH DESTINATION
0.0.0.0 7000 ALL   Route: 7000

Recommended Actions

In order to create the IPv6 listener for the Service Entry, remove the IPv4 address or replace it with an IPv6 address. For example(not ipv4 Addresses):

apiVersion: networking.istio.io/v1beta1
kind: ServiceEntry
metadata:
  name: ipv6se
  namespace: default
spec:
  exportTo:
  - .
  hosts:
  - 'httpbin.default.svc.cluster.local'
  location: MESH_INTERNAL
  ports:
  - name: http-7000
    number: 7000
    protocol: HTTP
  resolution: NONE

 

Additional Information

Once you removed the IPv4 Address from the Service entry, now you are able to see the IPv6 Listener too:

istioctl pc listeners sleep-698cfc4445-8vfwn --port 7000
ADDRESS PORT MATCH DESTINATION
0.0.0.0 7000 ALL   Route: 7000
::      7000 ALL   Route: 7000.ipv6
