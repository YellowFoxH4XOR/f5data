Known Issue

The Traffic Management Microkernel (TMM) may exit and restart when executing the STATS:: iRules command

This issue occurs when all of the following conditions are met:

  • You have an iRule configured to use the ACCESS_SESSION_CLOSED event associated with a virtual server.
  • You use a STATS:: command, such as STATS::set, within the ACCESS_SESSION_CLOSED event.

The ACCESS_SESSION_CLOSED iRules event executes on the global context and triggers outside of flow context. You cannot use iRules commands, such as STATS::set, which require flow context within the ACCESS_SESSION_CLOSED event.

Impact

Traffic to the virtual server is disrupted while TMM restarts. If configured for high availability (HA), the BIG-IP system fails over to another device in the device group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file to the /shared/core/ directory.
  • The active system fails over to another device in the device group.
  • Your BIG-IP system generates a SIGSEGV fault to the /var/log/tmm file that appears similar to the following example:

    notice ** SIGSEGV **

Workaround

To work around this issue, you can remove the STATS:: commands from the ACCESS_SESSION_CLOSED events in the iRule. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules and click the name of the iRule you want to edit.
  3. For Definition, locate STATS:: commands in ACCESS_SESSION_CLOSED events and delete the STATS:: commands.
  4. Click Update.
