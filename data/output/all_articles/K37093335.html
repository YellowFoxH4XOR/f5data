Known Issue

The Traffic Management Microkernel (TMM) restarts when you use Session Initiation Protocol (SIP) message routing with Stream Control Transmission Protocol (SCTP).

This issue occurs when all of the following conditions are met:

  • You configure a virtual server for SIP message routing and associate an SCTP profile.
  • You enable the the Insert Record-Route Header setting in the SIP profile associated with the virtual server.

Impact

TMM generates a core file and restarts, disrupting traffic. The BIG-IP system fails over if configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system halts the server-side flow of the SIP traffic.
  • The BIG-IP system generates a core file to the /shared/core directory.

Workaround

To work around this issue, you can do one of the following:

  • Disable the Insert Record-Route Header setting.
  • Reconfigure the SIP environment to use Transmission Control Protocol (TCP) or User Datagram Protocol (UDP), instead of SCTP.

To disable the Insert Record-Route Header setting, perform the following procedure:

Impact of workaround: Performing the following procedure prevents the BIG-IP system from adding the Record-Route header, which can break proxy routing. You should test this procedure during a maintenance window before implementing this change in a production environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > SIP.
  3. Click the affected profile.
  4. Clear the Insert Record-Route Header check box.
  5. Click Update.
