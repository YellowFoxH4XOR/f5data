Known Issue

The BIG-IP system may fail to complete a Secure Sockets Layer (SSL) handshake with the client. This issue occurs when all of the following conditions are met:

  • The affected virtual server is processing the Client SSL connection with an iRule.
  • The iRule uses the TCP::close command in the CLIENTSSL_HANDSHAKE event.

The TCP::close command can be used in the CLIENTSSL_HANDSHAKE event to close the client connection. For example, the iRule closes the client connection if the hostname requested by the client does not match the common name in the SSL cert.

Impact

The client's SSL connections may stall or close with an SSL handshake failure.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Client SSL connection stalls until the TCP connection is timed out by the BIG-IP system.
  • The Client SSL connection fails at the Change Cipher Spec Protocol during the SSL handshake.

Workaround

To work around this issue, you can insert a delay with the after command for the TCP::close command. To do so, perform the following procedure:

Impact of workaround: Depending on the type and volume of the connections, the after command may introduce noticeable latency. F5 recommends that you test any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click the name of the affected iRule.
  4. In the CLIENTSSL_HANDSHAKE event, locate the TCP::close command.
  5. Add the after command with the desired delay to the TCP::close command.

    For example, to insert a delay of 20 milliseconds with the after command, the TCP::close command should appear similar to the following:

    after 20 {TCP::close}

  6. Click Update.
