Description

iApps LX packages such as Declarative Onboarding (DO), Application Services 3 (AS3) and Telemetry Streaming are not available and stops working after a blade failover (change of primary blade).

Environment

  • Multi-blade systems like VIPRION, vCMP on VIPRION, VELOS tenant
  • iApps LX packages are installed a little while before the blade failover

Cause

ID 653726

Files of an iApps LX RPM package are extracted under /var/config/rest/iapps directory. The csyncd daemon monitors the directory and syncs files between blades, but it takes a while to synchronize all files. If a blade failover is initiated before the sync completes, the iApps LX package will not be available on a new primary blade.

Recommended Actions

  • Wait for all files to be synchronized between blades.

    You can check the number of files per per directory per slot using the following command.
    (printf "Slot Path Files\n----- ----- -----\n";
for slot in $(seq 1 $(tmsh show sys cluster field-fmt | grep running | wc -l)); do
ssh "slot${slot}" "slot=$slot" '
for dir in $(find /var/config/rest/iapps/ -maxdepth 1 -mindepth 1 -not -path '*/RPMS' | sort); do
  echo $slot $dir $(find $dir -type f -not -path '*~' |wc -l);
done';
done) | column -t

    For example, output would look like below when 3 iApps LX packages DO, AS3, and Telemetry Streaming are installed.

    Slot   Path                                              Files
    -----  -----                                             -----
    1      /var/config/rest/iapps/f5-appsvcs                 1143     # AS3
    1      /var/config/rest/iapps/f5-declarative-onboarding  1932     # DO
    1      /var/config/rest/iapps/f5-service-discovery       11818    # AS3's sub-package
    1      /var/config/rest/iapps/f5-telemetry               9327     # Telemetry Streaming
    2      /var/config/rest/iapps/f5-appsvcs                 0
    2      /var/config/rest/iapps/f5-declarative-onboarding  1044
    2      /var/config/rest/iapps/f5-service-discovery       0
    2      /var/config/rest/iapps/f5-telemetry               0


  • When you are in a hurry, you may create a file /var/tmp/sync_iappslx.sh and executing it using commands below. You may need to change TARGET_DIR to cover directories you want to synchronize.
     
    tee /var/tmp/sync_iappslx.sh << 'EOF'
#!/bin/bash
# Version: 1.1

TARGET_DIR="/var/config/rest/iapps/f5-*"

echo "Archiving $TARGET_DIR..."
tar czf /var/tmp/iapps.tgz --exclude '*~' --exclude '.tmp' -C /var/config/rest/iapps $(ls -d $TARGET_DIR | xargs -n 1 basename)

primary=$(tmsh show sys cluster field-fmt | grep current-primary-slot-id | awk '{print $2}')
echo "Primary slot: $primary"

slots=($(tmsh show sys cluster field-fmt | grep ' slot-id' | awk '{print $2}'))
echo "Slots in chassis: ${slots[@]}"

for slot in ${slots[@]}; do
    if [ "$slot" != "$primary" ]; then
        if ssh slot${slot} uname > /dev/null; then
            echo "Copying /var/tmp/iapps.tgz to slot ${slot}..."
            scp -q /var/tmp/iapps.tgz slot${slot}:/var/tmp/iapps.tgz

            echo "Stopping csyncd, extracting /var/tmp/iapps.tgz under /var/config/rest/iapps/, and restarting csyncd on slot ${slot}..."
            ssh slot${slot} "bigstart stop csyncd; sleep 5; tar xzf /var/tmp/iapps.tgz -C /var/config/rest/iapps/; sleep 5; bigstart start csyncd; rm -f /var/tmp/iapps.tgz"
        else
            echo "Failed to ssh into slot${slot}. Appears offline."
        fi
    fi
done
rm -f /var/tmp/iapps.tgz
EOF

    bash /var/tmp/sync_iappslx.sh
  • Re-run the earlier command to confirm files are synchronized between blades.
