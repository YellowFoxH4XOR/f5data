Known Issue

The Traffic Management Microkernel (TMM) may leak memory if new User Datagram Protocol (UDP) connections fail to initialize due to a full message queue.

The uninitialized UDP messages remain in memory because they do not have a timeout period, causing memory to leak.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to process UDP traffic.
  • The BIG-IP system is processing a very high number of UDP requests.

Impact

Memory exhaustion may cause TMM to become unstable and possibly produce a core file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Error messages similar to the following example appear in the /var/log/tmm file:

    notice hud_msg_queue is full

  • The BIG-IP system fails to process UDP traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.
