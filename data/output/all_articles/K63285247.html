K63285247: Configuring SDC to log verbose message for Tomcat

Type
Support Solution
Published
2022-01-13
Updated

Applies to

Description

WebUI is not responsive or inaccessible. WebUI web application runs on Tomcat. By default, SDC Tomcat console log is disable. To enable verbose Tomcat logging when there is observation of regular WebUI status check failure even after Tomcat process is restarted.

Environment

  • SDC 5.x
  • WebUI not responsive

Cause

Tomcat process has been restarted. However, unresponsive WebUI recurs after sometime and there is need to enable verbose Tomcat logging to investigate the issue.

Recommended Actions

This procedure needs to be performed on both Salt master nodes unless indicated. Steps to enable verbose Tomcat logging:

  1. Backup /srv/salt/<sdc version>/tomcat/template-catalina-sh
Replace <sdc version> with the actual SDC running version.
cp /srv/salt/<sdc version>/tomcat/template-catalina-sh /srv/salt/<sdc version>/tomcat/template-catalina-sh.backup
For example:
cp /srv/salt/5.1_26-1/tomcat/template-catalina-sh /srv/salt/5.1_26-1/tomcat/template-catalina-sh.backup
  1. Edit the following line of /srv/salt/<sdc version>/tomcat/template-catalina-sh and save the changes.
Original:
Uncomment line 199,200,201 and 387, while adding words, >> "$CATALINA_OUT", before 2>&1 "&".
Line
199 #if [ -z "$CATALINA_OUT" ] ; then
200 # CATALINA_OUT="$CATALINA_BASE"/logs/catalina.out
201 #fi
387 #touch "$CATALINA_OUT"
401       2>&1 "&"
410       2>&1 "&"

Modified:
if [ -z "$CATALINA_OUT" ] ; then
 CATALINA_OUT="$CATALINA_BASE"/logs/catalina.out
fi
  touch "$CATALINA_OUT"
      >> "$CATALINA_OUT" 2>&1 "&"
      >> "$CATALINA_OUT" 2>&1 "&"
  1. You only need to perform this step from one of the Salt master nodes. Push the updated template-catalina-sh and verify the file is copied to Tomcat home folder.
salt '*' state.sls tomcat
salt '*' cmd.run 'awk '/CATALINA_OUT/' /opt/traffix/apache-tomcat/bin/traffix_catalina.sh'
  1. Update the log level of the following lines from INFO to FINE for /opt/traffix/apache-tomcat/conf/logging.properties
Backup the file
cp /opt/traffix/apache-tomcat/conf/logging.properties /opt/traffix/apache-tomcat/conf/logging.properties.backup 
org.apache.catalina.core.ContainerBase.[Catalina].[localhost].level = FINE
org.apache.catalina.core.ContainerBase.[Catalina].[localhost].[/manager].level = FINE
org.apache.catalina.core.ContainerBase.[Catalina].[localhost].[/host-manager].level = FINE
  1. Restart tomcat process.
monit restart <tomcat process name>

For example:
monit restart sdcrepro1_tomcat
  1. As Tomcat debugging log will fill up disk quickly, setup logrotate to manage appropriate retention copies on the system. You are advised to adjust logrotate settings such as rotate ,and size to fit your system disk available.
Backup the file:
cp /srv/salt/<sdc version>/system/logrotate/logrotate-traffix-hourly.conf /srv/salt/<sdc version>/system/logrotate/logrotate-traffix-hourly.conf.backup

Append the following to /srv/salt/<sdc version>/system/logrotate/logrotate-traffix-hourly.conf
/opt/traffix/apache-tomcat/logs/catalina.out {  
 copytruncate  
 daily  
 rotate 5 
 compress  
 missingok  
 size 5M  
}
  1. You only need to perform this step from one of the Salt master nodes. Push the updated logrotate-traffix-hourly.conf and verify the file is updated in /etc/logrotate.d/logrotate-traffix.conf.
salt '*' state.sls system.logrotate
  1. Ensure the catalina.out is logging and logrotate is rotating the file.
