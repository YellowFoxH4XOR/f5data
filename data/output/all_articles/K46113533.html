Topic

By default, the BIG-IP system attempts to preserve the client ephemeral ports. However, ephemeral port exhaustion may occur under heavy usage or special client traffic patterns. This condition may cause a disruption of service during peak production periods. The BIG-IP system helps the administrator to identify and avoid this condition early with the help of database variables.

Description

The tm.portfind.linear and tm.portfind.random database variables determine how the BIG-IP system handles the ephemeral port that is configured by the client. The BIG-IP system will increment the ephemeral port sequentially, based on the value of tm.portfind.linear, if the BIG-IP system cannot use the configured ephemeral port configured by the client. For example, if the client connection is using ephemeral port 2560, and that port is in use by a BIG-IP secure network address translation (SNAT) address, then the BIG-IP system begins looking for a free port starting at 2561, and then 2562, until the value of tm.portfind.linear is reached (the default setting is 16).

If the BIG-IP system fails to find a port, then the system starts looking for a random port based on the value of tm.portfind.random (the default setting is 16). If the random search fails, the BIG-IP system may log the following ephemeral port exhaustion message to the /var/log/ltm file:

tmm[15690]: 01010201:2: Inet port exhaustion on 10.12.15.1 to 10.12.15.16:80 (proto 6)

Viewing default database variable settings for tm.portfind.linear and tm.portfind.random

You can use the following procedure to view the default settings for tm.portfind.linear and tm.portfind.random database variables:

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To list the default settings, use the following command syntax:

    list /sys db <DB key name> all-properties

    For example, to list the default database setting for tm.portfind.linear, type the following command:

    list /sys db tm.portfind.linear all-properties

The BIG-IP port handling behavior varies slightly depending on the number of Traffic Management Microkernel (TMMs) on the device, because the BIG-IP system will divide the possible ports among each TMM instance for a given IP address. As a result, finding a sequential port may not appear to be sequential. For example, your client may be on ephemeral port 5008, and the server side ephemeral port could end up being 5032. This is mathematically greater than 16, but that does not mean it was selected as part of a tm.portfind.random variable after tm.portfind.linear failed. Assume that the device has 8 TMM instances, and then it is possible that the selected TMM has ports 5008, 5016, and 5024 being used, and 5032 marked as free. The device will go through its linear list and select the first free port, which was 5032 in this case. However, it is important to keep in mind that CPU/TMM relationships and various BIG-IP hardware differ slightly in their use of the algorithm, but the functionality remains the same.

Beginning in BIG-IP 12.0.0, the following three new database variables are introduced to notify potential port exhaustion events.

  • tm.portfind.threshold.warning - This database variable turns threshold warning On or Off. The default setting is On.
  • tm.portfind.threshold.trigger - The system triggers a warning message when the threshold trigger is reached after 8 random searches, twice, within the threshold timeout period. The default setting is 8.
  • tm.portfind.threshold.timeout - The system logs the following port exhaustion threshold message to the /var/log/ltm file if the threshold trigger is reached within this timeout period. The default setting is 30 seconds.

    Inet port exhaustion threshold reached on 10.12.15.1 to 10.12.15.16:80 (proto 6)

Viewing default database variable settings for tm.portfind.threshold.warning, tm.portfind.threshold.trigger, and tm.portfind.threshold.timeout

You can use the following procedure to view the default settings for tm.portfind.threshold.warning, tm.portfind.threshold.trigger and tm.portfind.threshold.timeout database variables:

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To list the default settings, use the following command syntax:

    list /sys db <DB key name> all-properties

    For example, to list the default DB setting for tm.portfind.threshold.warning, type the following command:

    list /sys db tm.portfind.threshold.warning all-properties

Recommendations

F5 carefully tunes the database variable settings, and you should use extreme care when you modify the settings, or consult F5 support for guidance. If the BIG-IP system logs the ephemeral port exhaustion threshold, that indicates that the device is coming close to running out of ephemeral ports, and you should consider ways to mitigate the situation. If the virtual server is using a SNAT Automap or a single IP SNAT Pool, then consider switching to a SNAT Pool with multiple addresses so you have more IP/Port combinations available.
