Description

During a BIG-IP High Availability (HA) failover event in Azure, the Cloud Failover Extension (CFE) on the newly active device fails to reassociate IP configurations from the previous active device's network interface. The failover is triggered successfully, and the standby device becomes active, but the floating IP addresses remain associated with the original active device's network interface, resulting in a network outage.

The following error messages appear in /var/log/restnoded/restnoded.log`::

Failover initialization failed: Error getting auth token Error: HTTP request failed: 503 {"error":"InternalError","error_description":"Request has timed out."}

HA Connection with peer 10.0.13.11 lost.

CMI heartbeat timer expired, status: 10.0.13.11

The issue occurs when CFE attempts to obtain an authentication token from the Azure Instance Metadata Service (IMDS) but receives a timeout error, preventing it from executing the necessary Azure API calls to move IP configurations.

Environment

  • BIG-IP LTM 
  • Cloud Failover Extension 
  • Active/Standby HA configuration

Cause

Transient unavailability or connectivity issue with the Azure Instance Metadata Service (IMDS) endpoint at the time of failover. CFE requires access to IMDS to obtain an authentication token for making Azure API calls. When IMDS is unreachable or times out, CFE cannot authenticate and therefore cannot perform IP address reassociation operations.

Recommended Actions

Immediate Recovery:

  1. If CFE fails to move IP configurations during a failover, perform a manual failback to restore service:
    • Force a failover back to the original active device
    • Verify that IP configurations are correctly associated after the manual failback

Verification and Testing:

  1. Test Azure IMDS connectivity from the BIG-IP device:
    • From the bash shell, run:
      curl -H Metadata:true "http:/169.254.169.254/metadata/instance?api-version=2021-02-01" --max-time 5 --
    • Test OAuth token retrieval:
      curl -H Metadata:true "http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https://management.azure.com/" --max-time 10
    • If these commands fail or timeout, there is a connectivity issue to IMDS
  2. Verify network routing to IMDS endpoint:
    • Ensure the BIG-IP has a route to 169.254.169.254
    • IMDS is accessible only from within the Azure VM and should not require special routing
    • Check for any network security groups or firewall rules that might block access
  3. Schedule a planned failover test during a maintenance window:
    • Monitor CFE logs in real-time during the test
    • Verify that IP configurations move successfully
    • Document the time required for complete failover

Monitoring and Prevention:

  1. Enable detailed CFE logging for ongoing monitoring:
    • Set logLevel to "silly" in CFE configuration
    • Monitor for authentication errors
  2. Review Azure Service Health:
    • Check for any platform incidents or maintenance events in your Azure region
    • Subscribe to Azure Service Health alerts for proactive notification

Additional Information

Understanding BIG-IP HA Failover Behavior:

  • BIG-IP HA failover is triggered by loss of heartbeat communication between cluster members, independent of Azure IMDS availability
  • The failover mechanism is designed to prevent split-brain scenarios; the active device will step down if it cannot communicate with its peer
  • CFE operations occur after the BIG-IP failover is complete; CFE does not control when failover happens

CFE and Azure IMDS:

  • CFE requires access to Azure IMDS to obtain managed identity authentication tokens
  • IMDS is a REST endpoint available at 169.254.169.254 accessible only from within accessible only from within the Azure VM
  • Authentication tokens are required for CFE to make Azure API calls to reassociate IP configurations
  • Transient IMDS issues are rare but can occur during Azure platform maintenance or network disruptions
