General Information

Provide the following information when you open a case with F5 Technical Support:

  • A full description of the issue, including the following:
    • The symptoms of the issue
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the system
    • Steps to reproduce the issue
    • Any changes you made to the system before the issue first occurred
    • Any steps you have taken in an attempt to resolve the issue
  • A full description of the F5 VNF Manager deployment, including the following:
    • The type of NFV solution: NFV VNF Manager Base, NFV Gi LAN Solution, or NFV Gi FW Solution
    • A description on your private cloud infrastructure used to execute the NFV solution
    • A description of the affected F5 VNF Manager deployments
  • A description of the impact that the issue is having on your site, using the following definitions:
    • Site Down

      Your network or application is down, or critical business functions have stopped due to the issue.

    • Site at Risk

      Your network or application is severely and negatively impacted by the issue.

    • Performance Degraded

      The performance of your network or application has been severely reduced due to the issue.

    • General Assistance Required

      The subject of the case does not currently impact your network or application.

  • The hours that you are available to work on the issue, and any alternative contacts who can work on the issue if you are not available.
  • Remote access information, if possible.

    Remote access to your network environment is important because it is the most effective method to collect information and troubleshoot technical issues. If you cannot provide remote access, F5 Support will work directly with you to resolve the issue over the phone and through email; however, this approach can often be more time consuming and may require file transfers, replication, and additional testing.

Product-specific information

Collect the following information from the affected systems and provide the information when you open the case. For information about sending files to F5, refer to K000090853: Exchange files with F5 Support using MyF5.

F5 VNF Manager

Log files

To provide all of the log files on the system, perform the following procedure:

  1. Log in to the command line.
  2. To create a logfiles.tar.gz .tar archive in the /var/tmp directory that contains all the files in the /var/log directory, type the following command:

    tar -czpf /var/tmp/logfiles.tar.gz /var/log/*

Blueprint hash

To provide the blueprint hash, perform the following procedure:

  1. Log in to the command line.
  2. Navigate to ~/files.
  3. To generate the secret, run the following script:

    ./signature_maker.sh

    Output appears similar to the following example:

    Secret `signature_list_25_10_2018_12_55_58` created

  4. To extract the blueprint hash from the secret, use the following command syntax:

    vnfm secret get <secret>

    For example, to extract to blueprint hash from the secret signature_list_25_10_2018_12_55_58, type the following command:

    vnfm secret get signature_list_25_10_2018_12_55_58

Deployment Inputs

To provide the Inputs of the affected deployment, perform the following procedure:

  1. Log in to the VNF Manager Web UI.
  2. Navigate to Deployments.
  3. Locate the main Gi solution deployment and click either the OpenStack-F5-VNF-Service-Layer-xxxx or the vSphere-F5-VNF-Service-Layer-xxxx blueprint depending on the virtual infrastructure manager (VIM) platform deployed.
  4. Locate the Deployment Inputs section and retrieve the Inputs information.

BIG-IP

To collect information from the affected BIG-IP system, refer to K135: Information required when opening a support case for BIG-IP LTM, AFM, DNS, Link Controller, and PEM.

BIG-IQ

To collect information from the affected BIG-IQ system, refer to K14378: Information required when opening a support case for the BIG-IQ system.
