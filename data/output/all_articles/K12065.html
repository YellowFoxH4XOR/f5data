Known Issue

This is the result of a known issue. BIG-IP VIPRION systems use the MPI channel to exchange messaging information between primary and secondary blades. If a virtual server on a VIPRION system listens on UDP port 62720, such as a wildcard virtual server or a virtual server that listens on all UDP ports, messaging traffic between the blades may become disrupted. As a result, various failures may occur including monitor failures, pool members flapping, and intermittent failures in forwarding traffic.

This issue only occurs if the virtual server is configured to listen on all VLANs, which is the default setting.

F5 Product Development tracked this issue as ID 226399 and ID 248017 (formerly CR141404), and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, or PSM release notes.

Workaround

You can work around this issue by disabling the tmm_bp VLAN for wildcard virtual servers and virtual servers that listen on UDP port 62720 (or all UDP ports). The VLAN tmm_bp is used for internal system communications such as the MPI channel.

Note: Alternately, you can enable the virtual server to listen on specific VLANs. By enabling specific VLANs, the tmm_bp VLAN is automatically disabled for that virtual server.

To disable the tmm_bp VLAN on a virtual server, perform one of the following two procedures:

  • Disable the tmm_bp VLAN on a virtual server using the Traffic Management Shell (versions 10.0.0 and later)
  • Disable the tmm_bp VLAN on a virtual server using bigpipe (all versions)

Additionally, if MPI communications were disrupted on your VIPRION system, you must restart the TMM process on each blade to restore the MPI channel after making the configuration change. To restart the TMM process, perform the following procedure:

  • Restart the TMM process

Important: If the VIPRION system is part of a redundant pair, you must also synchronize the configuration change to the peer and then restart the TMM process on the blades of the peer system.

Disable the tmm_bp VLAN on a virtual server using the Traffic Management Shell (versions 10.0.0 and later)

  1. Log in to the Traffic Management Shell (tmsh).

    Note: For more information, refer to K12029: Accessing the Traffic Management Shell.
  2. For each virtual server which listens on UDP port 62720 (including wildcard virtual servers), type the following command, where <vs_name> is the name of the virtual server:

    modify /ltm virtual <vs_name> vlans add {tmm_bp} vlans-disabled
  3. Save the change by typing the following command:

    BIG-IP versions 10.1.0 and later:
    save sys config

    BIG-IP versions 10.0.x:
    save config

Disable the tmm_bp VLAN on a virtual server using bigpipe (all versions)

  1. Log in to the command line.
  2. For each virtual server that listens on UDP port 62720 (including wildcard virtual servers), type the following command, where <vs_name> is the name of the virtual server:

    bigpipe virtual <vs_name> vlans tmm_bp disable
  3. Save the changeby typing the following command:

    bigpipe save

Restart the TMM process

If MPI communications were disrupted on your VIPRION system, you must restart the TMM process on each blade to restore the MPI channel.

Important: Restarting TMM will temporarily interrupt traffic processing.

To restart the TMM process on all available (green) blades, use the clsh command. For example:

clsh bigstart restart tmm

To restart the TMM process on all blades, use a for loop. For example, to restart TMM in the order of blade 1, 4, 2, 3 you would type the following command:

for i in 1 4 2 3 ; do echo "Restarting TMM in slot $i" ; ssh slot$i bigstart restart tmm ; done

Important: The for loop above will also shut down blades in red/unavailable status if the blades respond to SSH. If a blade does not respond to SSH, or if it is in blue/unknown status, connect to the console port on the blade to issue commands.
