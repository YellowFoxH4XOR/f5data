Known Issue

The Traffic Management Microkernel (TMM) may leak memory when an iRule makes a sideband connection by using the connect command, and the destination is unreachable.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system processes traffic through a virtual server that references an iRule.
  • The iRule includes the sideband connect command.

    For example:

    when CLIENT_ACCEPTED {
    set conn_id [connect 192.168.10.100:80]
    close $conn_id
    }

  • The IP address and port, defined in the connect command, are unreachable due to a possible routing misconfiguration.

Impact

TMM may become unstable and produce a core file due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.

Workaround

To avoid this issue, you can ensure that the IP address and port defined in the connect iRule command are reachable. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Use the telnet command to send an HTTP/1.1 GET request to the IP address and port member defined in the connect iRule command.

    For example, to send an HTTP/1.1 GET request to 192.168.10.100:80, you would type the following command, and then press the Enter key:

    telnet 192.168.10.100 80

  3. At the prompt, enter an appropriate HTTP request line and HTTP headers. Press the Enter key once after each line, and twice after the last line.

    For example:

    GET / HTTP/1.1 <enter>
    Host: www.yoursite.com <enter>
    Connection: close <enter>
    <enter>

  4. You should receive a message that includes Connected to and HTTP/1.1 200 OK, similar to the following example:

    Trying 192.168.10.100...
    Connected to 192.16.10.100.
    Escape character is '^]'.
    GET / HTTP/1.0

    HTTP/1.1 200 OK
