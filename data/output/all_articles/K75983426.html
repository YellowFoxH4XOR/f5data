Description
Viewing SSL Hardware Acceleration statistics in an SSL profile may show connections as Partial Acceleration instead of the expected Full Acceleration of SSL/TLS connections.

Environment

  • This only applies to systems utilizing Cavium Nitrox SSL hardware acceleration cards, not Intel Quick Assist Technology (QAT).

Cause

Full Acceleration refers to both the handshake and bulk crypto portions of a TLS connection being performed by the Nitrox hardware. Partial Acceleration refers to either the handshake or the bulk crypto being performed by Nitrox hardware with the other component performed by software. None refers to both components being performed by software.

K13213 provides a list of hardware-accelerated algorithms which varies by model and software version. Any handshake or bulk crypto which does not utilize the algorithms listed in that article cannot be hardware-accelerated. There are additional factors which can cause the TLS handshake portion to be performed in software rather than hardware-accelerated on the Nitrox; when that occurs the connection is reported as Partial Acceleration if the bulk crypto is performed in hardware and None if the bulk crypto is also performed in software.

The list of additional factors which result in the TLS handshake being performed in software are:

  • TLS 1.3 is negotiated
  • F5 FIPS 140-2 utilized
  • Handshake buffer is > 32K
  • The db variable tmm.ssl.cn.shunt is set to "disabled"
  • Any ECC ciphersuite is negotiated
The following factors only apply to BIG-IP devices which utilize the Nitrox3 and NitroxPX SSL hardware acceleration cards:
  • RSA is used, and the key size > 4K
  • The microcode is CNPx-MC-SSL-MAIN-0017, and TLS 1.1 is negotiated
  • The MAC is not one of the following:
    • MD5
    • SHA1
    • SHA256
    • SHA384
  • The Cipher and Key Size is not in this table:
CipherKey size (in bits)
RC440, 56, 128
AES-CBC128, 256
DES-CBC40, 56, 64,192
  • vCMP guests:
    • TLS with a pre-master secret size < 16 or > 128 is not supported
    • TLS 1.1 in a vCMP guest is not supported
    • SHA384 in a vCMP guest is not supported
  • SSLv3 is negotiated and the pre-master secret is not a multiple if 4, or is < 4 or > 256 bytes
  • TLS or DTLS is negotiated and the pre-master secret is not a multiple of 16, or is < 16 or > 256 bytes
  • Next Protocol Negotiation is used
  • TLS 1.2 is negotiated, and the cipher key size is < 128 bits
  • Extended Master Secret (RFC7627) is negotiated
The following factors only apply to BIG-IP devices which utilize the Nitrox 1 or Nitrox 1-lite SSL hardware acceleration cards:
  • DTLS is not supported
  • TLS > 1.0 is not supported
  • Proxy SSL functionality is not supported
  • RSA is used, and the key size is > 2K
  • The MAC is not one of
    • MD5
    • SHA1
  • The Cipher and Key Size is not in this table:
CipherKey size (in bits)
RC440, 56, 128
AES-CBC128, 256
DES-CBC40, 64, 192


Note that even if the Nitrox has hardware support for a certain cipher as documented in K13213, if that cipher is not represented in the tables above the handshake will not be accelerated, but the bulk encryption will be. This is most notable with AES-GCM ciphers. This is a firmware limitation in the Nitrox cards.
