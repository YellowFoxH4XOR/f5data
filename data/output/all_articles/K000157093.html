K000157093: Can F5 provide insight in a pool member becoming unavailable

Type
Support Solution
Published
2025-10-22
Updated
2025-10-22
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.2
Source
https://my.f5.com/manage/s/article/K000157093

Description:


Pool members in BIG-IP DNS (GTM) may intermittently become unavailable, with their status flapping between up (green) and down (red). Log entries may include messages such as:

Monitor instance /Common/http <IP>:80 UP --> DOWN (state: timeout)

SNMP_TRAP: Pool /Common/fax member <hostname> (ip:port=<IP>:80) state change green --> red (Monitor /Common/http : state: timeout)

Monitor instance /Common/http <IP>:80 DOWN --> UP (state: success)

This behavior is typically associated with monitor probe timeouts.

Environment:

  • Product: BIG-IP DNS (GTM)
  • Version: 17.1.2
  • Platform: F5-BIG-CAT-A-1, BIG-IP
  • Configuration: Pool members monitored by HTTP or TCP monitors, possibly with multiple GTM devices in different data centers.

Cause:


Monitor probe timeouts occur when not all GTM devices can reach the pool member. This results in inconsistent health checks and causes the pool member status to flap between up and down.

Recommendations:

  1. Enable Debug Probe Logging:

  3. To identify which GTM device is failing to probe the pool member, enable debug probe logging:
  4. tmsh modify sys db gtm.debugprobelogging value enable
  5. Review logs in /var/log/gtm to determine which device is experiencing probe failures. Disable debug probe logging after troubleshooting:
  6. tmsh modify sys db gtm.debugprobelogging value disable
  7. Configure Prober Pools:

  9. If not all GTM devices can reach the pool member, configure a prober pool so that only reachable devices perform health checks. Refer to F5 article K08433560 for detailed steps.
  10. Monitor Settings:
    • Set the monitor timeout to at least three times the interval plus one second (e.g., interval 5s, timeout ≥16s) to prevent unnecessary flapping.
    • Ensure the pool member is not set to monitor type "none," as this can also cause timeouts and result in the member being marked down.
  1. Network Connectivity:

  3. Verify that all GTM devices responsible for probing the pool member have proper network connectivity to the target.
