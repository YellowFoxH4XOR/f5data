Issue

Description

A virtual server’s status is determined by both the default pool’s status, and the status of any pools referenced by an associated iRule. When no default pool is assigned, the virtual server’s status is determined by the status of the pools referenced in an associated iRule. When no default pool is assigned and the iRule references pools using a variable, then the status of the virtual server will be unknown.

Environment

  • Virtual server
  • Pools
  • iRules

Cause

This is by design to reflect the availability of the virtual server based on the available pool status.

Recommended Actions

None

Additional Information

In the instance that all pools associated with the virtual server are offline, the virtual server will be marked offline. If there are any available pools, either the default pool or an iRule referenced pool, the virtual server will be marked as available. For example:

  • Virtual server with no default pool and iRule referenced pool is unavailable, virtual server status will be offline.
  • Virtual server with no default pool and iRule referenced pool is available, virtual server status will be available.
  • Virtual server with no default pool and an iRule that references multiple pools, as long as one pool is available, the virtual server status will be available.
  • Virtual server with default pool and iRule referenced pool are both unavailable, virtual server status will be offline.
  • Virtual server with default pool and iRule referenced pool is available, virtual server status will be available.
  • Virtual server with default pool unavailable and iRule referenced pool is available, virtual server status will be available.
  • Virtual server with default pool available and iRule referenced pool is unavailable, virtual server status will be available.

Note: When a virtual server with no default pool uses an iRule for pool selection, the logic of the rules do not impact the state of the virtual server. For example, the iRule selects a pool from multiple pools to fulfill a request based on the URL ending or content type. If any of the defined pools of the iRule are available the associated virtual server status will be available.  The use of variable substitution for the pool(s) in the irule can lead to the virtual server being marked down even when there is a pool that is up.
