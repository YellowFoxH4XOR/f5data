Description

After enabling Oneconnect, the system complains about port exhaustion even when there are rather few connections. Messages like the following one are present in the LTM logs.


crit tmm: Inet port exhaustion on x.x.x.x to x.x.x.x:x (proto 6)

Environment

  • Vxlan tunnel on the server-side that handles the outgoing traffic
  • Vlan on the server-side with cmp-hash dst-ip 
  • Oneconnect profile 

Cause

The "cmp-hash dst-ip" on vlans causes two different tmms to handle the OUT and the IN traffic on the server-side. This misconfiguration is what is causing the accumulation of apparently unremovable connection flows, that in turn are likely causing the unexpected "Inet port exhaustion" messages.

Recommended Actions

  1. Configure the default cmp-hash on vlans using the following tmsh command:
    #tmsh modify net vlan <vlan_name> cmp-hash default
  2. Save the configuration #tmsh save sys config
  3. Restart tmm  #tmsh restart sys service tmm

Additional Information
The following BUG may have a part in this - ID803109: Certain configuration may result in zombie forwarding flows
