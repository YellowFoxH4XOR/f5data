Known Issue

Description

A request with a URL that does not exceed the defined URL length for a given file type may incorrectly generate Illegal URL Length violations.

This issue occurs when all of the following conditions are met:

  • An incoming request matches a defined file type in the security policy.
  • The URL length of the request is less than the defined URL length value for the file type.
  • The URL length exceeds the value defined for the ecard_max_http_req_uri_len internal parameter.
  • The blocking mask for the Illegal URL Length violation has at least one option enabled.

Impact

Requests may generate false positive violations.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • False positive Illegal URL Length violations

Workaround

Impact of workaround:

  • Increasing the value of the ecard_max_http_req_uri_len parameter value changes the length of URLs that are buffered into memory across all web applications on the BIG-IP ASM system.
  • Increasing the length of allowed URLs may cause resource usage to increase.
  • Modifying an internal parameter value requires the BIG-IP ASM service to be restarted, resulting in a brief traffic disruption.

To work around this issue, you can increase the length of allowed URLs by modifying the value of the ecard_max_http_req_uri_len internal parameter. To do so, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to the Application Security > Options > Advanced Configuration screen.
  3. Enter the desired value for the ecard_max_http_req_uri_len parameter value.
  4. Click Save.
  5. Log in to the command line.
  6. Restart the BIG-IP ASM service with the following command:

    Important: Restarting the asm process will cause a brief traffic disruption.

    bigstart restart asm
