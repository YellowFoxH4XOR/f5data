Description

By default, when the OSPF process initializes, it selects the highest IP address on a BIG-IP as router ID for the OSPF process. The router ID uniquely identifies a Layer 3 device within an OSPF domain. In an OSPF router process that has active neighbors, a new router ID is used at the next reload or when you start the OSPF manually.

Note. The process of selecting a router-id is within zebos, and it can only see the interfaces (and addresses) the kernel does. The Linux kernel isn't actually aware of floating self IPs.

The system may report logs similar to:

OSPF[id]: OSPF-4: Detected router with duplicate router ID<this-routers-id> in area 0.0.0.0

Environment

OSPF was configured through third-party ZebOS:

  • OSPF
  • Two or more interface in same OSPF area or domain

Cause

If there is no router-id defined for a protocol, the highest IP address in the router is used as the router ID. 

Answer/Recommended Actions

Check the router ID on zebos on each route domain on each system and make sure they're different/unique.
