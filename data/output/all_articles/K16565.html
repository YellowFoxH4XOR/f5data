Topic

This article applies to BIG-IP 11.4.0 - 12.0.0. For information about other versions, refer to the following article:

  • K17707311: Configuring a Web Acceleration profile for use with a BIG-IP ASM-enabled virtual server (12.1.0 and later)
  • K13112: Configuring a Web Acceleration profile for use with a BIG-IP ASM-enabled virtual server (11.0.0 - 11.3.0)

You should consider using this procedure under the following condition:

  • You want to increase the processing speed of a BIG-IP ASM web application by caching static content.

Description

You can apply a Web Acceleration profile to a BIG-IP ASM-enabled virtual server for caching commonly requested static content (such as images) that conforms to the BIG-IP ASM security policy. To do so, you can use a custom local traffic policy to define the traffic profiles that you want to cache, allowing for faster processing, lower overhead, and more efficient use of the cache.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have the BIG-IP ASM module licensed and provisioned.
  • Your existing configuration has a functional virtual server and pool combination that serves HTTP traffic to client connections.

Procedures

  • Configuring a custom Web Acceleration profile
  • Configuring a local traffic policy to build a BIG-IP ASM security policy
  • Associating the local traffic policy with the virtual server
  • Building the BIG-IP ASM security policy
  • Associating the custom Web Acceleration profile with the virtual server
  • Modifying the local traffic policy to handle caching

Important: If you already created a BIG-IP ASM policy, you must verify that it is in blocking mode before you configure the local traffic policy to handle caching. Blocking mode prevents direct and non-secure access to the web servers.

Configuring a custom Web Acceleration profile

F5 recommends that you create a new child profile based on the Web Acceleration profile, rather than modifying any settings in the default profile.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services.
  3. Select Web Acceleration.
  4. Click Create.
  5. Provide a name for the custom Web Acceleration profile.

    For example:

    asm_acceleration_profile

  6. Optional: In the Settings section, if you want to use all of the options available, select the Custom check box.

    Note: You should configure your cache settings as appropriate for your environment.

  7. Change the Minimum Object Size option to 1 byte.

    Note: The default setting is 500 bytes.

  8. Change the Maximum Object Size option to 150000 bytes.

    Note: The default setting is 50000 bytes.

  9. Click Finished.

Configuring a local traffic policy to build a BIG-IP ASM security policy

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Policies.
  3. Click Create.
  4. Provide a name for the local traffic policy.

    For example:

    ASM_cache_static_content

  5. For the Strategy setting, select first-match.
  6. For the Requires setting, move the http option from Available to Selected.
  7. For the Controls setting, move the asm option from Available to Selected.
  8. To save the changes, click Finished.

    The Configuration utility displays the Policies List page.

  9. Select the name of the local traffic policy that you created in steps 3 through 8.
  10. In the Rules section, click Add.
  11. Provide a name for the new rule. This is the default rule that sends the request to the BIG-IP ASM security policy to be evaluated.

    For example:

    Default_ASM_No_Cache

  12. In the Actions section, select the values appropriate for each setting to send the request to the BIG-IP ASM security policy to be evaluated.

    For example:

    Target: asm
    Event: request
    Action: enable
    Value: <select your desired BIG-IP ASM security policy>

  13. To the right of the parameters setting, click Add, and then click Add above the Actions table.
  14. To save the default rule, click Finished.

    The Configuration utility displays the Policies List page.

Associating the local traffic policy with the virtual server

After you configure the local traffic policy, you must associate it with the virtual server before you proceed to build the security policy. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Select the desired virtual server.
  4. Click Resources.
  5. In the Policies section, click Manage.
  6. In the Policies setting, move the local traffic policy that you configured in the previous procedure to the Enabled box.
  7. To save the changes, click Finished.

Building the BIG-IP ASM security policy

After you configure all of the previously-mentioned requirements, you must run traffic to the site and build a BIG-IP ASM security policy for the static content web application. F5 recommends that you use a policy configured with the following elements:

  • File types

    Wildcard (*) without tightening. Using a wildcard makes the entry case-insensitive and you do not have to specify both gif and GIF. Additionally, the tightening is not required because the file type filtering is performed at the local traffic policy level.

  • URLs

    Wildcard (*) without tightening. Using a wildcard makes the entry case-insensitive and you do not have to specify every new image in the site (a task that requires configuration and could cause errors for users). As with file types, filtering is performed at the local traffic policy level.

  • Blocking enabled for BIG-IP ASM violations

Before enabling the Web Acceleration profile, you must verify that the BIG-IP ASM policy is blocking the following violations:

  • Cookie not RFC-compliant
  • Evasion technique detected
  • Illegal HTTP format
  • Non-RFC request
  • Illegal HTTP status in response
  • Illegal meta character in object
  • Illegal method
  • Illegal object type
  • Non-existent object Error
  • Request length exceeds defined buffer size
  • Illegal cookie length
  • Illegal header length
  • Illegal object length
  • Illegal request length
  • Failed to convert character
  • Forbidden Null in request
  • Illegal meta character in header
  • Illegal query string or POST data
  • Null in multi-part parameter value
  • Modified ASM cookie
  • Modified domain cookie(s)
  • Information leakage detected Error
  • Attack signature detected

Associating the custom Web Acceleration profile with the virtual server

After you build the policy for the site, and enable blocking for the policy, you can enable the custom Web Acceleration profile on the virtual server. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Select the virtual server that you want to configure.

    The system displays the Properties screen for the virtual server.

  4. For the Web Acceleration Profile setting, select the custom Web Acceleration profile created in the Configuring a custom Web Acceleration profile procedure.

    For example:

    asm_acceleration_profile

  5. Click Update.

Modifying the local traffic policy to handle caching

After you build the policy for the site, and enable blocking for the policy, you can modify the existing rule and add a new rule to the local traffic policy to allow the system to cache static content. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Policies.
  3. Select the local traffic policy that you created in the Configuring a local traffic policy to build a BIG-IP ASM security policy procedure.
  4. For the Controls setting, move the caching option from Available to Selected.
  5. Click the default rule that sends requests to the security policy to be evaluated.
  6. In the Actions section, select the values appropriate for each setting to disable caching.

    For example:

    Target: cache
    Event: request
    Action: disable

  7. Above the Actions table, click Add.
  8. To save the changes, click Update Rule.
  9. To return to the local traffic policy, click Properties.
  10. In the Rules section, click Add.
  11. Provide a name for the new rule. This is the rule that sends the request to the BIG-IP ASM security policy to be evaluated, and also enables caching for static content that matches the list of defined URI extensions.

    For example:

    Static_Content_Cached

  12. In the Conditions section, select the values appropriate for each setting to define the list of URI extensions that you want to enable caching.

    For example:

    Operand: http-uri
    Event: request
    Selector: extension
    Condition: equals     (clear the case sensitive check box)

  13. For the Value setting, enter each of the following items and click Add (to the right of the Value setting) after each entry:
    • gif
    • jpg
    • bmp
    • png
    • css
  14. Above the Conditions table, click Add.
  15. In the Actions section, select the values appropriate for each setting to send the request to the BIG-IP ASM security policy to be evaluated.

    For example:

    Target: asm
    Event: request
    Action: enable
    Value: <select your desired ASM security policy>

  16. To the right of the parameters setting, click Add, and then click Add above the Actions table.
  17. In the Actions section, select the values appropriate for each setting to enable caching.

    For example:

    Target: cache
    Event: request
    Action: enable

  18. Above the Actions table, click Add.
  19. To save the caching rule, click Finished.

    The Configuration utility displays the Policies List page.

  20. Select the local traffic policy that you have just modified.
  21. Click Reorder.
  22. Move the default rule that disables caching to the bottom.
  23. To save the changes, click Update.

After you have completed these steps, any static media content that has been validated and cleared by the BIG-IP ASM system can now use the Web Acceleration cache. This behavior allows content that has been checked by the BIG-IP ASM system to be served from the cache, allowing the BIG-IP ASM system to focus on checking and validating dynamic content.
