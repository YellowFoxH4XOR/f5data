Topic

Path traversal is a common attack against web applications in which the attacker attempts to manipulate a URL or a parameter with the intention of exploiting a path vulnerability and accessing resources that are not intended to be accessed or displayed.

Description

In path traversal attacks, the attacker manipulates a web application component, such as a URL, by including special characters that modify the directory path. For example, the following attack manipulates the URL and uses the '../' characters to alter the location of the request with the intention of displaying the contents of a file that is outside of the document root directory:

http://example/../../../../../etc/passwd

The BIG IP ASM system can mitigate path traversal attacks using appropriate attack signatures or defined meta-characters. The following procedures list the necessary steps to mitigate path traversal attacks using the attack signatures, since this is the fastest and easiest configuration.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Have access to the Configuration utility.

Procedures

Adding the path traversal signatures to the security policy
Enabling and enforcing the path traversal signatures
Switching the policy to blocking mode
Verifying that the system is blocking path traversal attacks

Adding the path traversal signatures to the security policy

Impact of procedure: Adding attack signatures to the security policy can generate false positives. For example, known false positives for path traversal can occur due to the presence of English words such as “select” and “from” in the HTTP request. In these cases, you should remove false positives from the Traffic Learning page by accepting any learning suggestions for disabling the signature.

  1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. Select Advanced from the list on the top right.
  3. Expand the Attack Signatures option.
  4. Select the Change button to display the Select Policy Attack Signature Sets window.
  5. Select Path Traversal Signatures and select Change.
  6. Verify that the signature set has the Learn, Alarm and Block options enabled.
  7. Select Save.
  8. Select Apply Policy.

Enabling and enforcing the path traversal signatures

  1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. Select Advanced from the list on the top right.
  3. Expand Attack Signatures.
  4. Clear the Enable signatures staging check box.
  5. Select Save.
  6. Select Apply Policy.

Switching the policy to blocking mode

  1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. Go to the general setting in the upper part of the page and select Blocking from the Enforcement Mode list.
  3. Select Save.
  4. Select Apply Policy.

Verifying that the system is blocking path traversal attacks

  1. Go to Security > Event Logs >  Application > Requests.
  2. To open the filer, select Show Filters Details.
  3. Under Violation select Attack Signature Detected, and select Go.

    Requests containing path traversal attacks should be blocked and listed in the request log.
