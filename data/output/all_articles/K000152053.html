Description

The purpose of this article is to understand some of the general best-practices to configure and manage ASM Event Logging profiles to have a more stable system and preventing from huge amount of logs which can simply lead to missing some part of local / remote logs, and making the Troubleshooting procedure harder for either Application Security, Bot Defense, or DoS events.

So, you need to review and keep some recommended considerations to have optimized ASM Event Logging profiles to prevent from excessive logging problem.

Environment

  • BIG-IP ASM / AWAF
  • Logs Rate limited
  • Excessive Local / Remote Logs
  • Local / Remote Logging profiles

Cause

By design, ASM local logging has limitations. So, in case of having duplicated logging objects attached to the virtual servers, and/or mis-configuration of logging profiles and having huge local / remote logging, It can lead to missing significant logs for either the Security Policy, Bot Defense or DoS events.

Recommended Actions

To optimize and stabilize your BIG-IP ASM logging for Application Security, Bot Defense, and DoS Profile events—while reducing log volume and preventing missed logs—the following best-practices are generally recommended:

 

1. Log Only Illegal Requests (Not All Requests):

  • Logging all requests can quickly fill up local storage, causing logs to be rotated out rapidly and potentially missing important events.
  • It is recommended to log only Illegal requests (those that trigger a violation or are blocked) to reduce log volume and avoid overwhelming the system.
  • Logging all requests is a common cause of rapid log rotation and loss of historical data.
    K45320421 ASM event logs are deleted or rotated out very quickly

 

2. Use Remote Logging Where Possible:

  • Local logging is limited by disk/database size (5 GB on physical, 2 GB on virtual, or 3 million rows).
  • Remote logging to the SIEM (like 'Splunk', 'ArcSight') is recommended to avoid local storage limitations and ensure log retention.

 

3. Enable "Guarantee Local Logging" (If Local Logging is Required):

  • If you must log locally, enable the "Guarantee Local Logging" option in the logging profile to ensure logs are written even under resource contention.

       K08411122 Not all ASM events are being logged locally

Note: Enabling this may impact performance in high-traffic environments, and some logs may still be dropped if the system is overloaded.

 

4. Use "OR" Logic in Storage Filter (Advanced Logging Profile):

  • When configuring advanced storage filters in the logging profile, use the "OR" operator rather than "AND" to avoid overly restrictive logging conditions that may result in no logs being captured.
    K64229035 Application Security Manager (ASM) and the Logging Profile Storage Filter Logic Operators 'AND' and 'OR'

 

5. Monitor and Adjust Logging Profiles:

  • Regularly review which logging profiles are attached to your virtual servers. Remove unnecessary or duplicate profiles to avoid excessive logging.
  • For example, prevent from having two logging profile objects attached to a virtual server for both the log "All requests" and "Illegal requests only" at the same time. Since such type of log settings is the true Indication of log duplication Issue and can simply lead to missing many sample logs due to the huge logging.
  • Try to have the 'Remote Logging' object as attached to the Virtual Servers, preferably ONLY for Illegal requests and/or responses Logs.
  • In case of any demand for T-shoot purpose, you can temporarily attach a 'Local Logging' profile to ONLY the Involved Virtual Server(s), and detach that once troubleshooting is completed, to prevent from excessive logging. 
  • You need to consider all the best-practices mentioned in this Article for all the Virtual Servers to reduce the total amount of logging on your system. 

 

6. Restart Logging Services if Issues Occur:

  • If logging stops or behaves abnormally, restarting the "asm_config_server" and "asmlogd" services can resolve issues without impacting traffic.
    K05199822 ASM constantly logging to Event Log even if Logging profile is disabled
    K90214131 ASM/Advanced WAF may stop logging for specific security policies

 

7. Additional Notes for Bot Defense and DoS Profiles:

  • The same principles apply here to log only significant (Illegal or Blocked) events, and prefer Remote logging, and monitor log volume.
  • For Bot Defense and DoS logging, ensure that only actionable events are logged to avoid excessive noise.
  • Try to configure ONLY Remote logging, and use Local Logging just for Temporary Troubleshooting procedure.
