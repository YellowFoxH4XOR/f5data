K000139055: TSIG key value is case sensitive

Type
Support Solution
Published
2024-03-27
Updated
2024-03-27
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.X, 15.1.0, 15.1.1, 15.1.2, 15.1.3, 15.1.4, 15.1.5, 15.1.6, 15.1.7, 15.1.8, 15.1.9, 15.1.10, 16.1.0, 16.1.1, 16.1.2, 16.1.3, 16.1.4, 17.1.0, 17.1.1, 15.1.X, 16.1.X
Source
https://my.f5.com/manage/s/article/K000139055

Description

When configuring BIG-IP system as secondary/slave DNS server, you may notice dynamic zone update requests are not initiated by BIG-IP despite receiving DNS Notify packet from the Primary/Master nameserver and TSIG key is being present. On the other hand, if the zone is manually reloaded with 'rndc refresh' command on BIG-IP CLI, the recent change in the Primary/Master nameserver gets updated in the BIG-IP zone subsequently.

/var/log/daemon.log:

err named[21032]: <date> <time> xfer-in: error: transfer of 'example.com/IN/external' from <ip_address of master_nameserver#53>: failed while receiving responses: NOTAUTH

Environment

  • BIG-IP DNS
  • Zone Transfer
  • TSIG key

Cause

This issue could simply be due to the definition or formatting of the TSIG key that is case sensitive unlike DNS records. To confirm this, you can take a packet capture on BIG-IP then compare the value of TSIG key name in the Notify update packet versus BIG-IP response and verify they are identical in case.

Recommended Actions

Update the TSIG name in BIG-IP to exact value as defined in Primary/Master nameserver.

To do so, you can use a text editor in BIG-IP Command Line and update relevant objects in /var/named/config/named.conf and /config/bigip.conf, then save changes and exit editor mode. Please see below example for your reference.

1_ /var/named/config/named.conf

key "TEST" {

  algorithm hmac-sha256;

  secret "Ldfzuw5n4Z7nMu/lpEU9Pe9etzm+YWouihZA2GXfHmg=";

};

  zone "example.com." {

    type slave;

    file "db.external.example.com.";

    masters {

      <ip_addr> port 53 key TEST;        

    };

  };

};

 

2_ /config/bigip.conf

ltm dns nameserver /Common/<name> {

  address <ip_addr>

  route-domain /Common/0

  tsig-key /Common/TEST

}

ltm dns tsig-key /Common/TEST {

  algorithm hmacsha256

  secret ***scrubbed***

}
