Description

Besides providing username and password in Ansible Provider info to connection to BIGIP, Ansible also supports using SSH keys to connection to BIGIP, when Provider.Transport mode is "CLI".

This article is an example about how using SSH keys to connect BIGIP with Ansible.

Environment

Using Ansible to manage BIGIP.

Recommended Actions

  • Generate SSH key on the client, and upload the public-key to BIGIP.

Refer to https://my.f5.com/manage/s/article/K13454

 Configure public-key authentication from a remote system to the BIG-IP system

Please be noted,

  • You need to upload the public-key to the user's folder used by Ansible.

For example if you use user "admin", as ansible_ssh_user, you need to add publish to /home/admin/.ssh/authorized_keys file

  • Ansible playbook example
Client:~/playbook$ cat bigip_ssh_test.yaml
- name: Collect device facts
 hosts: localhost
 vars:
  provider:
   transport: cli
   server: 10.10.10.177
   user: admin
   ssh_keyfile: "~/.ssh/id_rsa" 
   validate_certs: no
 tasks:
  - name: Run single command - provider-cli
   bigip_command:
    commands:
     - "tmsh show sys version"
    provider: "{{ provider }}"
   register: result
  • Ansible-playbook command
Client$ansible-playbook bigip_ssh_test.yaml

Additional Information

"Provider.Transport:REST" mode does not support SSH Key access method.

"Provider.Transport:Cli" mode is only supported by a few f5 modules.

(List may be incomplete.)

  • bigip_command – Run TMSH and BASH commands on F5 devices
  • bigip_device_certificate – Manage self-signed device certificates
  • bigip_wait – Wait for a BIG-IP condition before continuing
