K000141418: iRule does not match country code from whereis command with data-group records

Type
Support Solution
Published
2024-10-11
Updated
2024-10-11
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000141418

Description

When using iRule which checks IP geolocation with whereis command and matches it against data-group with country codes the iRule does not give the expected results.


iRule example:

------

ltm rule allow-by-country {

when HTTP_REQUEST {

   set from_country [whereis [IP::client_addr] country]

   if { ( ![class match $from_country equals allowed_country_codes]) }{

       reject

   }

}

}



data-group example:

------

ltm data-group internal allowed_country_codes {

   records {

       country_code {

           data US

       }

   }

   type string

}


The expected behavior is that client IPs classified as US-based should be allowed, but they are getting rejected.


Environment

  • LTM
  • geoip_lookup
  • iRule with whereis command
  • data-group

Cause

This is happening because

class match <item> <operator> <class>

matches items against class (data-group) record names, not values. This means that in the example above, iRule tries to match "US" (the result from whereis command) against string "country_code" and not string "US" from data-group.


Recommended Actions

Modify the data-group so that allowed country codes are names of the data-group records and not values.

data-group from the example above should be modified to:

-------

ltm data-group internal allowed_country_codes {

   records {

       US { }

   }

   type string

}
