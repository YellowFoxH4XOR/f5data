Known Issue

A virtual server IP address may fail to bind to the Traffic Management Microkernel (TMM).

This issue occurs when all of the following conditions are met:

  • More than one virtual server is listening on the same IP address, port, and protocol.

    • The virtual servers have different Virtual Local Area Network (VLAN) assignment methods; one virtual server has a VLAN enable list and the other virtual server has a VLAN disable list. For example, virtual server 1 is enabled on VLAN_1 and virtual server 2 is disabled on VLAN_1.

      OR

    • The BIG-IP system is processing Passive FTP client traffic with multiple control connections.

Impact

TMM may misdirect or drop traffic for the affected virtual servers. For Passive FTP traffic, data connections from a client may end up going to the wrong server.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H432440 on the Diagnostics > Identified > Medium screen.
  • TMM misdirects or drops traffic for the affected virtual servers. For example, when TMM is processing a passive FTP connection with multiple control channels, the data connection of a client can end up going to the wrong listener, resulting in the data connection eventually going to the wrong pool member/server.
  • In the /var/log/ltm file, you may observe error messages that appear similar to the following example:

    01010009:3: Failed to bind to address

Workaround

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

To work around this issue, you should ensure that all the affected virtual servers use the same method for VLAN assignments. For example, if virtual server 1 and virtual server 2 used the same IP address, port, and protocol, you would configure virtual server 1 to be enabled on VLAN_1 and virtual server 2 to be enabled on VLAN_2. Alternatively, you could configure virtual server 1 to be disabled on VLAN_2 and virtual server 2 to be disabled on VLAN1.

Note: This workaround does not apply to the passive FTP issue.
