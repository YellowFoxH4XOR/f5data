Known Issue

This is the result of a known issue. BIG-IP WebAccelerator can be configured to proxy a request for a node using either the Always proxy requests for this node option, or by configuring a proxy rule on the matching policy node's Acceleration Rules >Proxying tab. When BIG-IP WebAccelerator proxies a request to the origin web server (OWS), it may send an unconditional GET request for the specified entity, rather than sending a conditional GET request. As a result, the OWS may be required to re-send data already present in the BIG-IP WebAccelerator cache.

Note: The only side effect of this issue is a potential increase in server-side traffic due to content being re-served from the OWS rather than from the WA cache; BIG-IP WebAccelerator functionality is unaffected.

Note: When forwarding the response to an unconditional GET to the client, BIG-IP WebAccelerator inserts S-code S10203 into the X-PvInfo response header, indicating the request was proxied to the OWS and not cached. For more information about the X-PvInfo header information, refer to the Viewing X-PvInfo response headers section of the Using HTTP Headers chapter in the BIG-IP WebAccelerator Policy Management Guide.

The HTTP/1.1 protocol specification provides a number of headers used to specify conditions under which the server is not required to send the requested entity. Such a request is known as a conditional GET, which requests that the entity be transferred only under the circumstances described by the conditional header fields. A conditional GET can be identified by the presence of any one of the following headers in the request:

  • If-Modified-Since
  • If-Unmodified-Since
  • If-Match
  • If-None-Match
  • If-Range

The conditional GET method is intended to reduce unnecessary network usage by allowing cached entities to be refreshed without requiring multiple requests or transferring data already held by the client. BIG-IP WebAccelerator typically makes extensive use of the If-Modified-Since and If-None-Match headers to eliminate the unnecessary transfer of information already in the BIG-IP WebAccelerator cache.

Note: For more information regarding the HTTP/1.1 GET method and the conditional request headers listed above, refer to RFC2616: Hypertext Transfer Protocol -- HTTP/1.1.
