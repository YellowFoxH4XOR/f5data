Description
Service Provider Disaggregation (SPDAG) is a mode of disaggregation configured on each VLAN to process and load balance incoming packets across a large number of TMMs based on source or destination IP addresses. When a CGNAT virtual server is configured to use SPDAG, and the number of IP addresses is low, for example lower than the number of TMMs on the BIG-IP system, this could lead to uneven distribution of traffic amongst the TMMs giving rise to high CPU utilization. When this happens, you may observe the following:
  • There is high CPU utilization on some CPUs and some CPUs are under-utilized. From the output of tmsh show sys cpu |  grep "CPU\|Utilization %" , an output similar to the one below may be observed:

Environment

  • CGNAT virtual server using SPDAG CMP hash
  • VIPRION blades
  • SNAT or NAT

Cause

To process traffic efficiently, a BIG-IP virtual server requires the same TMM to process the client side and server side connection of a flow. When a CGNAT virtual server is configured with SPDAG mode, packets are hashed to TMMs based on their IP addresses. When the number of IP addresses of the packets are low on one side of the flow, and does not provide enough entropy for even distribution of traffic amongst the TMMs, it may not be possible to have the same TMM to process the data when it returns. This leads to CMP redirection for the connection and high CPU utilization on certain cores. The low number of IP addresses can be due to the IP ranges available in a SNAT or NAT pool. 

Recommended Actions

The following resolutions are recommended:
  • Change from SPDAG mode to the default DAG method which uses a hash of source and destination port to provide sufficient entropy to distribute traffic evenly between the available TMMs. To do so, perform the following procedure:
    1. Login on the Configuration utility,
    2. Go to Network > VLANs,
    3. Click the name of the affected VLAN.
    4. For the CMP Hash field, select Default.
    5. Click Update.
  • When using SPDAG mode, ensure that there are sufficient IP addresses on both the client and server side connections of the BIG-IP system. For example, on the server side of the CGNAT virtual server, configure a SNAT pool with a block of contiguous IP addresses that is at least two times the number of TMMs in the BIG-IP system.

    Note: Do not use SPDAG mode without sufficient planning and testing. When the number of IP address entropy is insufficent, the issue described in the article arises.

Additional Information

Use the cmp_dest tool to determine which specific tmm the BIG-IP system uses to process traffic under a set of conditions. For example, the cmp_dest command below determines that tmm4 is used for the specified IP address port combinations on the E101 platform:

# cmp_dest --platform E101 --local_port 80 --local_ip 10.12.15.5 --remote_port 58257 --remote_ip 10.12.15.2
Destination: bucket0/slot1/tmm4/pde4
