K000160870: GTM Monitor Receive Strings Do Not Support \d and \D Regex Escape Sequences

Type
Support Solution
Published
2026-06-18
Updated
2026-06-18
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160870

Description

GTM (BIG-IP DNS) HTTPS monitors fail to match server responses when receive strings that use regular expression escape sequences such as \d (any decimal digit) and \D (any non-digit character). This results in pool members being marked as unavailable (red), even though the server is responding correctly.

Observed behavior:

Receive StringPool Member State
HTTP/1.1 200 OKGreen
HTTP/1\.1\ 200\ OKGreen
HTTP/1\.1\ 2[0-9][0-9]\ OKGreen
HTTP/1\.1\ 2[0-9][[:digit:]]\ OKGreen
HTTP/1\.1\ 2\d\d\ OKRed (connect: success, search result: false)
HTT\D/1\.1\ 200Red (connect: success, search result: false)

Log message example:

alert gtmd[10099]: 011a4003:1: SNMP_TRAP: Pool /Common/<pool_name> member <ip:port> state change green --> red ( Monitor /Common/<monitor_name> : connect: success, search result: false)

Environment

  • Product: BIG-IP DNS (GTM)
  • Version: 17.5.1.x (and potentially other versions)
  • Monitor type: GTM HTTPS monitor
  • Configuration: Receive string using \d or \D Perl-compatible regex escape sequences
  • Monitor daemon: big3d

Cause

GTM monitors use the big3d daemon for health checks, which only accepts \r and as valid escape sequences in monitor receive strings. Other Perl-compatible regex escape sequences—including \d, \D, \s, \S, \w, and \W—are not supported in GTM monitor receive strings. This is a functional difference between LTM and GTM monitors.

Answer/Recommended Actions

Replace unsupported PCRE escape sequences in GTM monitor receive strings with equivalent POSIX character classes or bracket expressions:

  • Replace \d (any digit) with [0-9] or [[:digit:]]
  • Replace \D (any non-digit) with [^0-9] or [^[:digit:]]

Example — Before (not working):

recv "HTTP/1.1 \d\d\d OK"

Example — After (working):

recv "HTTP/1.1 [0-9][0-9][0-9] OK"

To validate the monitor receive string against the actual server response:

  1. Run a curl command from BIG-IP to retrieve the actual server response:

    curl -X GET "https://<server_ip>/<path>" -vk

  2. Review the response body and HTTP status line to confirm the exact string to match.
  3. Update the GTM monitor receive string using only supported syntax ([0-9], [[:digit:]], \r, ).
  4. Enable monitor logging on the pool member to verify monitor behavior.
  5. If the issue persists after updating the receive string, enable GTM debug logging via tmsh:

    modify /sys db log.gtm.level value debug; modify /sys db gtm.debugprobelogging value enable

    After capturing a monitor failure, disable debug logging:

    modify /sys db log.gtm.level value notice; modify /sys db gtm.debugprobelogging value disable

  6. Collect a new qkview for further analysis if needed.

Additional Information

  • This behavior is by design and represents a functional difference between LTM and GTM monitor implementations.
  • Only \r and are accepted as escape sequences in GTM monitor receive strings.
  • POSIX character classes such as [0-9] and [[:digit:]] are fully supported alternatives.
