Topic

You should consider using this procedure under the following conditions:

  • You want to use granular signature enforcement options for attack signature sets.
  • You want to immediately enforce attack signatures in a particular signature set.

Description

When you first activate a security policy, the system puts the attack signatures into staging for a period of seven days by default. In addition, when you add or change signatures in assigned signature sets, those signatures are also put into staging. When attack signatures are in staging, the system applies the attack signatures to application traffic, but does not apply any blocking action to requests that trigger those attack signatures. The staging period allows you to track signature usage and helps to reduce the number of false positive violations.

There may be occasions when you want to immediately enforce all attack signatures in a particular signature set, bypassing the staging period. For example, if your application experiences a high number of SQL injection attacks, you can enable the SQL Injection Signatures attack signature set and choose the option to enforce all SQL signatures in the signature set, bypassing the staging period of seven days. Doing so does not affect the staging timing for other attack signatures.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the BIG-IP Configuration utility.

Procedures

Enforce attack signatures in a particular signature set

To enforce attack signatures in a particular signature set, bypassing the staging period, perform the following steps:

Impact of procedure: Bypassing the staging period for one or more signature sets may increase the number of false positive violations for the security policy.

  1. Log into the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Under Policy Building Settings, select Attack Signatures.
  4. Select Change.
  5. On the Select Policy Attack Signature Sets screen, select the signature set that you want to assign to the policy.
    For example, SQL Injection Signatures.
  6. Select Change.
  7. Select Save.
  8. Under Attack Signatures, locate the signature set you added.
  9. For Change signature properties, select one of the following options:
    • Enforce and Enable all Attack Signatures in the Signature Set
      • Select this option to enforce all signatures in the signature set. This option also enables any signatures in the signature set that are in a disabled state.
    • Enforce all Attack Signatures in the Signature Set
      • Select this option to enforce all signatures in the signature set. This option does not enable signatures in the signature set that are in a disabled state.
    • Enable all Attack Signatures in the Signature Set
      • Select this option to enable any signatures in the set that are in a disabled state. This option does not enforce signatures in the signature set.
  10. Select Save.
  11. Select Apply Policy.
