K000161358: Big-IP upgrade to 17.5.1.6 - Stuck on reboot with 'Login incorrect' repeating error

Description

A BIG-IP VE instance became stuck in a "Login incorrect" boot loop after upgrading to version 17.5.1.6, preventing the system from booting into the newly installed volume.


 

Environment

BIG-IP LTM VE, platform (VMWare)

Target upgrade version: 17.5.1.6.0.39.25 Engineering Hotfix

Hosted on VMware vSphere

Wrong hotfix ISO installed: the iSeries-specific build of 17.5.1.6 was used instead of the VE-specific build


 

Cause

The "Login incorrect" boot loop was caused by installing an iSeries-specific engineering hotfix ISO on a BIG-IP VE instance. The iSeries build of BIG-IP 17.5.1.6 is incompatible with VE platforms; when installed on a VE, critical post-boot initialization steps fail, resulting in a broken boot volume that presents a persistent "Login incorrect" error on the console. Installing the correct VE-specific hotfix (17.5.1.6.0.63.25) ISO resolves the issue. Per this article: Users with Administrator role cannot see configuration in partitions other than /Common after upgrading BIG-IP to 17.1.3.2, 17.5.1.6, or 21.0.0.2

 

Answer/Recommended Actions

When upgrading BIG-IP VE to an engineering hotfix, always confirm the correct platform-specific ISO is used.


For iSeries bare-metal: use the iSeries-specific build

Verify the target platform type (VE, iSeries, rSeries, vCMP) before downloading and applying any engineering hotfix

Upgrade VMware VM hardware version to version 13 or higher for BIG-IP 17.5.x compatibility, per K69120675 and K000159615

If a "Login incorrect" boot loop is encountered after an upgrade, boot back to the previous known-good volume and verify the correct ISO before retrying
