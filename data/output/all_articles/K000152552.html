Description

To block any request containing a specific keyword—whether it appears in the URI, a header value, or the request body—you can use a custom attack signature in BIG‑IP ASM.

This article demonstrates how to create a signature that detects the keyword “aswd” anywhere in the URL (path or query string) and configures it to trigger an alarm and block the request whenever a match is found.

Example Requests:

GET /api/v1/data?aswd HTTP/1.1
User-agent: python-requests/2.31.0
....

GET /api/aswd/data?abc=123 HTTP/1.1
User-agent: python-requests/2.31.0
....

Environment

  • BIG-IP ASM/WAF
  • Custom Attack Signature

Cause

None

Recommended Actions

Proceed with the steps outlined below in the order presented.

  1. Navigate to Security  ››  Options : Application Security : Attack Signatures >> Attack Signatures List and click on Create.


  2. Fill the information to match your requirement and click on the Add. Once created note down the custom Signature ID which will be required in the next step.



    Note    : Make sure to give a meaningful name and the appropriate attack type can be selected. In the Rule: Matched Element and Criteria, you need to select available options based on the requirement. In our example we are checking for a plain string "aswd" in the URI including Query String. There are several other options as well, also instead of an exact match, you can define a regex as well. 



  3. Create a new Attack Signature Set to include this Attack Signature (if you already have a previously created set for custom signatures, you can add this signature to that). Navigate to Security  ››  Options : Application Security : Attack Signatures >> Attack Signatures Sets and click on Create.


    Once you type the SignatureID, it will appear in the list of available signatures, use + to add it to the set. Then finally click on "Add" to complete the signature additions.



    Note: Here, we are selecting Assign Set to Newly Created Policies to "Never", as in our example, we only need this set for one application/policy. If you would like to have this set for all the newly created future policies, you can leave this settings to "Always".

  4. Assign this created signature set to the policy. Navigate to Security  ››  Application Security : Policy Building : Learning and Blocking Settings : Attack Signatures >> Change. Select the newly created set from the list and click on Change again. Save and Apply the policy. 



  5. The newly added signature will be placed on staging. If you need this signature to be enforced immediately, Navigate to Security  ››  Application Security : Security Policies : Policies List  ›› <policy_name> : General Settings : Attack Signatures, select the signature, enforce and apply the policy.
