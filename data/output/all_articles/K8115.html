This article applies to BIG-IP 9.x through 10.x. For information about BIG-IP 11.x and later, refer to K39394712: Overview of the Stream profile.

Summary

The Stream profile performs a search and replace procedure for all occurrences of a string in a data stream.

The Stream profile operates as follows:

  • You can use the Stream profile with any TCP traffic. You can apply the Stream profile to any Standard virtual server that is configured with the TCP protocol. You can also configure the virtual server with the HTTP profile, but this is not a requirement.
  • When you do not configure the virtual server with the HTTP profile, the Stream profile performs the search and replace procedure on the entire data portion of each TCP segment. This applies to both data transmitted by the client and data transmitted by the server.
  • When you configure the virtual server with the HTTP profile, the Stream profile performs only the search and replace procedure on the HTTP payload. This applies to both client requests and server responses.
  • The Stream profile also works when the string to be replaced is split across multiple TCP segments (including when the virtual server uses an HTTP profile). Traffic Management Microkernel (TMM) buffers just enough data at the end of a packet if it looks like there may be a replacement once the next packet arrives.
  • When using iRules, the Stream profile can have different states (enabled or disabled) on each side of the proxy. Calling STREAM::enable or STREAM::disable in the HTTP_REQUEST event enables or disables the Stream profile on the client side for HTTP requests on the same connection coming in towards the virtual server. However, calling STREAM::enable or STREAM::disable in the HTTP_RESPONSE event enables or disables the Stream profile on the server side for HTTP responses on the same connection going out towards the client. 

Standard TCP virtual server with no HTTP profile

When the Stream profile is applied to a standard TCP virtual server that is not configured with the HTTP profile, the search and replace procedure occurs on the entire data portion of each TCP segment. This applies to both data streams (the data transmitted by the client and the data transmitted by the server).

If such a virtual server processes Layer 4 (L4) connections encapsulating HTTP requests and responses, the search and replace procedure is performed on both the HTTP headers and the HTTP payload (that is, the entire data portion of each TCP segment).

Standard TCP virtual server with an HTTP profile

When the Stream profile is applied to a standard TCP virtual server that is also configured with the HTTP profile, the search and replace procedure occurs only on the HTTP payload. This applies to both client requests and server responses.

For example, the following Stream profile searches HTML for the statement <h1>Sunshine</h1> and replaces the statement with <marquee><h1>Moon</h1></marquee>:

ltm profile stream h1_marquee { 
app-service none 
defaults-from stream 
source <h1>Sunshine</h1> 
target <marquee><h1>Moon</h1></marquee> 
}

Note: When the HTML text pattern <h1>Sunshine</h1> is identified in the stream, the text is replaced with <marquee><h1>Moon</h1></marquee>.

Responses

If you expect to see the string to be replaced in both HTTP requests and responses, F5 recommends that you add an iRule similar to the following example to the virtual server. You can perform the search and replace procedure exclusively on HTTP responses by using an iRule (thus avoiding application failures if the matching string is replaced in an HTTP request).

when HTTP_REQUEST {
# Disable the stream filter for client requests
STREAM::disable
}

when HTTP_RESPONSE {
# Disable the stream filter for server responses
STREAM::disable

# Enable the stream filter for text responses only
if {[HTTP::header value Content-Type] contains "text"}{

# Replace 'old_text' with 'new_text'
STREAM::expression {@old_text@new_text@}

# Enable the stream filter
STREAM::enable
}
}

Requests

In BIG-IP 9.x through 10.x, you cannot chunk the request and the system does not alter the Content-Length header value of HTTP requests. Without the use of the chunking feature, if the size of the content is modified by the replacement action of the Stream profile, the Content-Length header contains the wrong value. Since the Content-Length header is proxied to the server before the Stream replacements are performed, there is no way to adjust the reported content length or chunk lengths. Applications are likely to fail if the length of the HTTP payload does not match the value reported by the Content-Length HTTP header (for example, if the server receives more POST data than what is reported by the header).

Recommendations

  • To prevent the BIG-IP system from attempting to perform replacements against non-text payloads, HTTP content re-writing should be restricted to specific content types that represent potentially re-writable text (for example, Content-Type header values matching the string text/*).
  • A Stream profile must be associated with the virtual server before an iRule calling the Stream profile can be associated with the virtual server. You may use the default Stream profile (with all parameters blank).
  • The Stream profile performs all replacements in a single pass, so data changed once are not changed again in the same operation, even if the data matches another replacement pattern after the initial replacement.
  • Since HTTP compression on the server prevents the BIG-IP system from reading the data stream and performing the intended replacement, you may need to configure the HTTP profile to remove the Accept-Encoding header in the request to prevent compression by the server.
  • The Stream profile uses Basic Regular Expressions to evaluate the Stream expression. As a result, matches are case-sensitive, by default. If case-insensitive matches or other flexibility is required, you may specify a valid Basic Regular Expression construct as the Stream expression.
  • Leave Source  blank and start, separate, and end each find/replace pair with an appropriate delimiter (there are two delimiters between pairs) when replacing multiple strings and when using Basic Regular Expressions.
  • Optional: To improve readability, insert white space between the search/replace pairs; the behavior remains the same (do not insert extra white space within the replacement pairs).
