Description

Unexpected blocks may occur with Automatic Policy Builder when an object such as URL or parameter is enforced after the enforcement readiness period has expired.  ASM does not change the Enforcement Mode of the policy automatically, only the staging mode of the objects within the policy.   

Environment

  • ASM with policy attached to virtual server
  • Policy Builder set to automatic
  • ASM policy set to "blocking" mode

Cause

Several default ASM policy templates are initially deployed with the policy enforcement in "blocking" mode and automatic policy builder enabled.  When traffic is first seen by this policy you may see violations which could be false positives, but these will not be blocked at the time.   This could be due to the violations occurring on an object or entity which is staged, such as a URL, parameter, attack signature, etc.  A policy in blocking mode will not block violations for staged entities so this may behave similarly to a policy in transparent mode.

Automatic policy builder will not change an entity from staging to enforced until sufficient traffic is received.  When these conditions are met policy builder will log a message similar to this in /var/log/asm:

ASMConfig change: File Type css [update]: Perform Staging was set to disabled. { audit: policy = /Common/<asm policy name>, component = Policy Builder }

If there are violations for this object, a File Type of "css", these violations will now result in a block because the policy is in blocking mode and the entity is no longer staged.
 

Recommended Actions

To ensure the application remains otherwise protected, the unexpected blocks on the object which is no longer staging should be handled as false positives.  A policy exception to the individual violation or object should be made.  Switching the policy to transparent mode effectively removes all blocking actions.  

If transparent mode was intended for the policy, meaning no blocks can be delivered regardless of staging settings on the objects, the policy should be manually changed to transparent mode.

  1. Navigate to Security Policy Configuration for desired policy
  2. Change "Enforcement Mode" to Transparent

This setting must be changed manually during policy deployment for common templates such as "Fundamental" and "Comprehensive".

Alternatively, using manual policy building will produce learning suggestions which must be acted on by an administrator.  This can increase workload for the administrator but will ensure no objects are enforced automatically.

  1.  Navigate to Security Policy Configuration for desired policy
  2. Change "Policy Building Learning Mode" to Manual
