K000151549: The BIG-IP GTM/DNS displays an unexpected state for a BIG-IP LTM virtual server status change.

Published

Updated

Applies to

Description

After changing disabled virtual server object back to enabled status, GTM/DNS shows the re-enabled virtual server object as "offline/enabled" (red diamond icon) with "no reply from big3d: timed out" message despite actual virtual server status on remote LTM device is "up".

Environment

All of the following conditions need to be met.

  • GTM/DNS software version which has fix for Bug ID 1133201 (as of article publication, 16.1.5 or later / 17.1.1 or later / 17.5.0 or later).
  • Virtual server object is configured on remote LTM device. Remote LTM devices monitors virtual server pool by itself.
  • On GTM/DNS device, no monitor object is directly attached to the virtual server object which is managed by remote LTM device. That means, availability of the virtual server object is to be acquired from remote LTM device via iquery communication.
  • On GTM/DNS device, virtual server object was disabled and after then gtmd service restarted (or GTM/DNS device was rebooted).
  • On GTM/DNS device, virtual server object is re-enabled after gtmd service restarted or GTM/DNS device was rebooted.

 

Here is example configuration of GTM/DNS device.

gtm server /Common/bigipltm {
    datacenter /Common/MYDC
    devices {
        bigipltm {
            addresses {
                10.1.1.200 { }
                192.168.10.200 { }
            }
        }
    }
    monitor /Common/bigip
    product bigip
    virtual-server-discovery enabled
    virtual-servers {
        /Common/vs1 {
            destination 10.1.1.201:80
        }
    }
}

 

Here is example configuration of remote LTM device.

ltm pool /Common/p1 {
    members {
        /Common/10.1.1.60:80 {
            address 10.1.1.60
        }
    }
    monitor /Common/tcp
}
ltm virtual /Common/vs1 {
    destination /Common/10.1.1.201:80
    ip-protocol tcp
    mask 255.255.255.255
    pool /Common/p1
    profiles {
        /Common/tcp { }
    }
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}

 

Key point is that on GTM/DNS device no monitor object is directly attached to LTM virtual server "vs1". With this configuration, GTM/DNS device acquires virtual server status from remote LTM device via iquery communication. And on remote LTM device, pool monitor is attached to.

 

Figure: GTM/DNS virtual server object configuration

 

Note: if on GTM/DNS device any monitor object is attached to virtual server and virtual server does not get back to "available/enabled" status (green circle icon) with "no reply from big3d: timed out" message even after re-enabled it, it is likely due to separate issue Bug ID 1592209. Bug ID 1592209 and Bug ID 1856289 is very similar, however, condition is slightly different. Bug ID 1856289 occurs only when virtual server is managed by remote LTM device _and_ no GTM/DNS monitor object is directly attached to the virtual server. Meanwhile, Bug ID 1592209 can happen not only on virtual server on remote LTM device but also on Generic Host type server. Also, Bug ID 1592209 can happen even though on GTM/DNS device any monitor object is directly attached to virtual server. In other words, Bug ID 1856289 fix covers a corner case which was not covered by Bug ID 1592209 fix.

 

Cause

Bug ID 1856289

 

Recommended Actions

If virtual server had already been affected and stucking at "offline/enabled" (red diamong icon) status with "no reply from big3d: timed out" message, you can rescue affected virtual server by restarting gtmd on GTM/DNS device. After restarts gtmd service, virtual server will be getting back to "available/enabled" status (green circle icon) from "offline/enabled" status (red diamond icon).

# tmsh restart /sys service gtmd

 

Alternatively, you can prevent issue from occurring by setting "monitor-disabled-objects" parameter to "yes" (default "no"). This needs to be done prior to disabling virtual server managed by remote LTM device.

# tmsh modify gtm global-settings general monitor-disabled-objects yes
# tmsh save sys config gtm-only

 

On GUI, go to "DNS >> Settings : GSLB : General" and you will find "Monitor Disabled Objects" setting.
