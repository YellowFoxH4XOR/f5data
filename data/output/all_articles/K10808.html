Known Issue

This is the result of a known issue. BIG-IP ASM does not correctly reapply a security policy with signature settings that have not been changed.

For example:

  • Two security policies are configured with All Signatures set with learn/alarm/block enabled, parameter wildcard enabled, no staging on the policies, and no staging on the wildcards.
  • One policy is applied, then removed.
  • The second policy is applied.
  • The first policy is reapplied without any changes.

As a result of the example sequence of events, BIG-IP ASM will not correctly apply the policy, and an Attack Signature Detected violation will not be reported.

F5 Product Development tracked this issue as ID 209867 (formerly CR124995) and it was fixed in BIG-IP ASM 10.1.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
