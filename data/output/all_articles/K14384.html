Known Issue

The BIG-IP ASM system may incorrectly trigger Malformed XML data violations. This issue occurs when all of the following conditions are met:

  • An XML profile is associated with a URL for the affected security policy.
  • The client request received by the BIG-IP ASM system contains the xsi:nil attribute with the value of numeric one or zero.

    The following example shows the xsi:nil attribute with the value of numeric one (1) for the XML element exampleatt:

    <exampleatt xsi:nil="1"></exampleatt>

The xsi:nil attribute is typically used to indicate an XML element as valid without content if it has the value of true. If the client request contains the xsi:nil attribute with the value of true or false, the BIG-IP ASM system will properly recognize the attribute as a valid XML request instead of triggering a Malformed XML data violation.

Impact

The BIG-IP ASM system may report false positive Malformed XML data violations.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP ASM system triggers the Malformed XML data violation, although the XML content is valid.
  • In BIG-IP ASM 11.x, the system reports the violation detail description as Malformed Document Syntax Error.
  • In BIG-IP ASM 10.x, the system reports the violation detail description as Malformed Document.

Workaround

There is no workaround for this issue. However, you may be able to mitigate this issue by configuring the client application to send the xsi:nil attribute with the value of true or false instead of the numeric one or zero.
