K000132714: SDC receives INIT but doesn't reply with any message

Type
Support Solution
Published
2023-02-22
Updated
2023-02-22
Source
https://my.f5.com/manage/s/article/K000132714

Description

  • A client peer using SCTP sends an INIT message to the SDC/DRA but the SDC doesn't respond with any messages. 

Environment

  • SDC 5.1

Cause

  • When an SCTP packet is received, the receiver MUST first check the CRC-32c checksum:

  1. Store the received CRC-32c value.

  2. Replace the 32 bits of the Checksum field in the received SCTP packet with all '0's and calculate a CRC-32c value of the whole received packet.

  3. Verify that the calculated CRC-32c value is the same as the received CRC-32c value. If not, the receiver MUST treat the packet as an invalid SCTP packet.


  • There is no parameters in the Peer Profile to change the SCTP checksum.

 Recommended Actions

Change the SCTP checksum to CRC32.


Additional Information

None.
