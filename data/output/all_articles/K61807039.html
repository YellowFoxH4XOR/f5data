Description

After upgrade to version 14.1.x+ you observe in /var/log/ltm that configuration fails to load with following error:

The requested profile (/Common/<analytics profile>) was not found.

 

Environment

  • Upgrade to a version 14.x or newer
  • Configuration includes an analytics profile 

Cause

ID835381
 

Recommended Actions

As a workaround  you can manually edit configuration file bigip.conf and deattach affected profile out of Virtual-Servers:

Important:  Any mistakes made while completing the following procedure could prevent the configuration loading.

  1. Login into the device via SSH or console.
     
  2. Make a backup of the /config/bigip.conf file by typing the following command from BIG-IP bash shell:

    cp /config/bigip.conf /config/bigip.conf.backupfile

  3. Edit and Search /config/bigip.conf for the configuration object in question.

    Example of Virtual-Server config:

    ltm virtual /Common/http_80 {
        destination /Common/10.10.10.10:80
        ip-protocol tcp
        mask 255.255.255.255
        persist {
            /Common/source_addr {
                default yes
            }
        }
        pool /Common/Pool_80
        profiles {
            /Common/http { }
            /Common/tcp { }
            /Common/<analytics profile> { }  <--------!!!
        }
        source 0.0.0.0/0
        source-address-translation {
            type automap
        }
        translate-address enabled
        translate-port enabled
    }

  4. Remove line containing Analytics profile definition.

    Expected result:

    ltm virtual /Common/http_80 {
        destination /Common/10.10.10.10:80
        ip-protocol tcp
        mask 255.255.255.255
        persist {
            /Common/source_addr {
                default yes
            }
        }
        pool /Common/Pool_80
        profiles {
            /Common/http { }
            /Common/tcp { }
        }
        source 0.0.0.0/0
        source-address-translation {
            type automap
        }
        translate-address enabled
        translate-port enabled
    }

     

  5. Repeat step #3 for each Virtual-Server containing affected profile.
     
  6. Once completed save the configuration file.
     
  7. Load the configuration by typing the following command:

    tmsh load sys config

Additional Information

As a alternative workaround you can boot back to previous software volume and deattach Analytics profile out of Virtual-Servers.
Once completed perform perform upgrade procedure again.
