Known Issue

This is the result of a known issue. When a Microsoft Windows Vista client enters Protected Workspace and launches a Network Access favorite, then temporarily switches out of Protected Workspace, a window appears on the Vista desktop with the following error message:

Windows host process (Rundll32) has stopped working

Clicking the Close program button in the window will allow the user to continue working normally outside Protected Workspace. The user can re-enter Protected Workspace normally and the Network Access favorite will continue to function.

F5 Product Development tracked this issue as CR94816 and is fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

Additionally, cumulative hotfix HF-602-4 has been issued for FirePass version 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

The user can work around this issue with one of the following options:

  • Add the URL of the FirePass controller to the Internet Explorer 7 (IE7) Trusted Sites zone.

    For information about configuring the Trusted Sites zone, refer to the Microsoft IE7 documentation.

    Important: By default, Protected Mode is disabled in IE7 for the Trusted Sites zone. If Protected Mode is enabled for this zone, use one of the alternate workarounds listed below.

  • Disable Protected Mode in Internet Explorer.

    For information about configuring Protected Mode, refer to the Microsoft IE7 documentation.
  • Disable Windows Vista User Account Control for the user. 

    For information about configuring User Account Control, refer to the Microsoft Windows Vista documentation.
