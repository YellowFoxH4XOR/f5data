Description

When BIG-IP's objects are monitored from a SNMP tool collector, the collector could receive logs with an HTTP 404 error not found messages. 

Log in the SNMP tool

<date> <hostname> <date> <hostname> info logger[11269]: [ssl_acc] 10.10.10.10 - username [<date>] "/mgmt/tm/ltm/monitor/http/~Common~http/stats" 404 84

Logs in the BIG-IP:


/var/log/restjavad-audit.0.log

[I][633817][<date>][ForwarderPassThroughWorker] {"user":"local/username","method":"GET","uri":"http://localhost:8100/mgmt/tm/ltm/monitor/http/~Common~<monitor name>/stats?ver=15.1.5.1","status":404,"from":"10.10.10.10"}

Environment

  • iRestControl
  • SNMP collectors
  • Monitor unassigned to a pool

Cause

After a SNMP tool sends iControl request to BIG-IP, If the monitor is not attached to a pool or is attached to a pool without actual members, it will not show any stats and Big-IP will respond with a "404 object not found" and this is expected and common.

Recommended Actions

Since this is an expected behavior the messages can be safely ignored or if you prefer the message can be filtered
K16932: Configuring the BIG-IP system to suppress sending SSL access and request messages to remote syslog servers

None.
