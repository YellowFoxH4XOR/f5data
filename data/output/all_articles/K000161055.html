K000161055: Istio-proxy isn't coming up on app pod seeing LDS ACK ERROR

Type
Support Solution
Published
2026-06-21
Updated
2026-06-21
Applies to
  • Aspen Mesh: 1.18, 1.14, 1.21
Source
https://my.f5.com/manage/s/article/K000161055

Description

In Aspen Mesh 1.14.x, application pods with injected istio-proxy sidecars may fail readiness or enter CrashLoopBackOff when an EnvoyFilter configures access log formats containing %COMMON_DURATION(...)%. Sidecar and istiod logs can show LDS ACK errors such as: "Error adding/updating listener(s) ... Not supported field in StreamInfo: COMMON_DURATION". This can prevent Envoy listeners from loading and keep the sidecar from becoming ready.

2026-04-27T21:41:43.338260Z  warn ads  ADS:LDS: ACK ERROR pod_name.namespace Internal:Error adding/updating listener(s) 0.0.0.0_15014: Not supported field in StreamInfo: COMMON_DURATION

Environment

  • Aspen Mesh 1.14.x
  • Istio-proxy (Envoy) 1.22

Cause

Unsupported Envoy access-log format configuration in customer EnvoyFilters used %COMMON_DURATION(...), but Aspen Mesh 1.14 ships Envoy 1.22 where that StreamInfo field is not available. As a result, Envoy rejected listener configuration with "Not supported field in StreamInfo: COMMON_DURATION", causing the istio-proxy sidecar to fail readiness/startup.
So, %COMMON_DURATION(...)% is not available for the Envoy release you have installed on Aspen Mesh.
%COMMON_DURATION(...)% was introduced in Envoy 1.30 and is not supported by the Envoy 1.22 version used by Aspen Mesh 1.14.x

Answer/Recommended Actions

  • Review failing istio-proxy logs for LDS rejection or ACK errors similar to:
ADS:LDS: ACK ERROR ... Internal:Error adding/updating listener(s) ... Not supported field in StreamInfo: COMMON_DURATION
warning envoy config gRPC config for type.googleapis.com/envoy.config.listener.v3.Listener rejected: Error adding/updating listener(s) ... Not supported field in StreamInfo: COMMON_DURATION
  • Identify EnvoyFilter resources that reference %COMMON_DURATION(...)%. For example:
oc get envoyfilters.networking.istio.io --all-namespaces
oc get gateways,virtualservices,destinationrules,envoyfilters --all-namespaces -o yaml | grep COMMON_DURATION
oc get envoyfilters.networking.istio.io -n <namespace> -o yaml
  • Confirm the deployed Aspen Mesh version and corresponding Envoy version. Aspen Mesh 1.14 uses Envoy 1.22, which does not support %COMMON_DURATION(...).
  • Back up the affected EnvoyFilter resources before making changes. For example:

oc get envoyfilters.networking.istio.io -n <namespace> <envoyfilter-name> -o yaml > <envoyfilter-name>_backup.yaml

  • Remove %COMMON_DURATION(...)% from the access log format, or delete the affected EnvoyFilter if it is not required.
  • Restart the impacted pod or deployment after updating or deleting the EnvoyFilter, then verify the sidecar becomes ready and the application returns to service.
  • If multiple EnvoyFilters were recently added, review all access-log-related filters in the affected namespace for occurrences of %COMMON_DURATION(...)%.

Additional Information

The issue is configuration-related rather than an Aspen Mesh product defect.
