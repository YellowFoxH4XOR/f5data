Description

In /var/log/asm, one of the following error message can be seen:

ASM out of memory error: event code X242 Exceeded maximum memory assigned for XML/JSON processing
ASM out of memory error: event code X260 Exceeded maximum memory assigned for XML/JSON processing
ASM out of memory error: event code X264 Exceeded maximum memory assigned for XML/JSON processing


Environment

  • ASM Policy configured to process XML Requests
  • XML requests are not processed
  • During the time of issue, logs similar to below are generated in the following directories:

    /var/log/ts/bd.log
    BD_XML|ERR |Jan 01 12:00:00.000|PID|xml_validation.cpp:0244|Cannot allocate 21846735 more bytes for XML parser. current memory size 300294455 (in bytes)

    /var/log/asm
    emerg perl[PID]: 01310003:0: ASM out of memory error: event code X242 Exceeded maximum memory assigned for XML/JSON processing
    emerg perl[PID]: 01310003:0: ASM out of memory error: event code X260 Exceeded maximum memory assigned for XML/JSON processing
    emerg perl[PID]: 01310003:0: ASM out of memory error: event code X264 Exceeded maximum memory assigned for XML/JSON processing 

Cause

This is due to XML processing engine memory exhaustion.
 

Recommended Actions

The procedure describes steps to determine how much memory in addition is needed to allow XML processing without memory exhaustion. Then allocate additional memory to BIG-IP ASM XML processing engine.

Determine how much additional memory is in use and maximum currently

tmctl asm_memory_util_stats --select total_xml_mem_used,total_xml_max_mem

for example:

# tmctl asm_memory_util_stats --select total_xml_mem_used,total_xml_max_mem
total_xml_mem_used total_xml_max_mem
------------------ -----------------
              7254            460800

#

 

Determine how much additional memory is required

 

  1. Log in to the BIG-IP through the Command Line Interface
  2. Run the following command to list the biggest requests that ASM was unable to process:

    zgrep -i 'XML parser' /var/log/ts/bd.log* | awk '{print $7,$9}' | sort -nr | head

    The output will be as following e.g.:
    27493539 bytes
    27154167 bytes
    24292013 bytes
    24285560 bytes
    23940302 bytes
    23731950 bytes
    23661717 bytes
    22909164 bytes
    22432388 bytes
    22374345 bytes

    The largest request required at least 27493539 more bytes to be processed by ASM.

Note: The size of the largest request is just an indicator of the smallest amount of additional memory which needs to be allocated before the errors stop appearing. The actual amount of additional memory will have to be determined by trial and error and may be several times larger. The uncertainty margin is so high because the memory allocated to a request is not released immediately after it has been processed. Instead, the software may keep it for a while in case it becomes required again. More than 1 GB memory can be allocated using additional_xml_memory_in_mb , see K10803: Customizing the amount of memory allocated to the BIG-IP ASM XML processing engine

Allocating additional memory to BIG-IP ASM XML processing engine

  1. Determine the default memory allocated to XML processing engine for your BIG-IP.
    • For platforms with memory less than 16 GB of RAM, the XML processing engine is allocated 300 MB of memory.
    • For platforms with more than 16 GB but less than 32GB of RAM XML processing Engine is allocated 450 MB of memory.
    • For platforms with more than 32GB of RAM, the processing Engine is allocated with 1GB of memory.
  2. After you have determined how much additional memory is required, add that value to the default memory allocated to the ASM XML processing engine
    • For example, If the allocated memory is 300 MB, the memory can be increased to 500 MB (536870912 Bytes)
  3. To modify the total_xml_memory, refer to the procedure provided in the article K10803: Customizing the amount of memory allocated to the BIG-IP ASM XML processing engine
