K000150906: DNS cache resolver is not working after upgrade from 17.1.1.3 to 17.5.0

Type
Support Solution
Published
2025-04-28
Updated
2025-06-30
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.X, 17.5.X, 17.5.0, 17.1.2, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000150906

Description

After upgrading from 17.1.1.x and below to 17.1.2 or higher, some DNS queries fail with "Server failure" sent by listener configured with DNS cache resolver or forward zones.

In debug logs we can find the below messages:

Mar 24 20:07:27 bigip.dns.us info tmm[20301]: DNScache: resolving example.com. A IN
Mar 24 20:07:27 bigip.dns.us debug tmm[20301]: DNScache: request has dependency depth of 0
Mar 24 20:07:27 bigip.dns.us debug tmm[20301]: DNScache: forwarding request
Mar 24 20:07:27 bigip.dns.us debug tmm[20301]: DNScache: cannot forward RD=0 query, to stop query loops
Mar 24 20:07:27 bigip.dns.us debug tmm[20301]: DNScache: return error response SERVFAIL

Environment

  • BIG-IP DNS
  • software upgrade to v.17.1.2 or higher
  • DNS cache resolver
  • Forwarding Zones

Cause

Starting from version 17.1.2 new code was introduced. The BIG-IP now sends a SERVFAIL to queries with no cached entries that has 'recursion desired' set to 0 (no recursion). This change is to protect the device from DNS amplification attacks. 

Recommended Actions

Issue can be fixed by one of the following options:

1) addressing a problem with client sending DNS query to a recursive resolver with RD flag unset (RD=0). In other words - dns query received by BIG-IP needs to have RD flag set to 1.

2) creating dns express zones

3) creating an irule which will change RD flag in dns queries received by the listener

An example irule may look as below. For more information check: K23111337: Setting DNS header flags using iRules.

when DNS_REQUEST {
DNS::header rd 1
}
