Description

VPN tunnel fails to connect or repeatedly reconnects when using BIG-IP Edge Client for Windows 11 if SSL decryption/inspection is enabled on a client-side device (such as a firewall or proxy performing SSL interception). Symptoms include repeated:


  • PPP tunnel reconnects.
  • RAS error 628 ("The remote computer disconnected before the connection could be completed").
  • Decryption errors in client logs (e.g., "Error returned by DecryptMessage").

Packet captures show that, with SSL inspection enabled, the Server Hello does not include the expected certificate, breaking the TLS handshake required for VPN tunnel establishment. Disabling SSL decryption on the inspection device restores VPN connectivity.


Environment

  • BIG-IP APM
  • VPN configured with TLS tunnel (PPP over TLS)
  • Client-side SSL decryption/inspection device (firewall or proxy) present between client and BIG-IP APM

Cause

SSL inspection devices that intercept and decrypt TLS traffic between the client and BIG-IP APM can disrupt the VPN tunnel establishment process. These devices may fail to properly re-sign or forward the server certificate, or otherwise interfere with the TLS handshake, resulting in the Edge Client being unable to establish a secure tunnel. This leads to repeated reconnect attempts, RAS error 628, and decryption failures.


Recommended Actions

  1. Bypass SSL inspection/decryption for VPN traffic destined to the BIG-IP APM virtual server (e.g., by whitelisting the APM's FQDN or IP address in the SSL inspection device's policy).
  2. Ensure that the SSL handshake between the Edge Client and BIG-IP APM is not modified or intercepted by intermediate devices.
  3. If SSL inspection cannot be disabled for all traffic, create an explicit exception for VPN-related traffic to the BIG-IP APM.
  4. If issues persist, verify that the server certificate and chain are correctly installed on both the BIG-IP and client devices, and confirm that no other network devices are interfering with the TLS handshake.
