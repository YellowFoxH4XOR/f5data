Known Issue

This is the result of a known issue. When a BIG-IP GTM 9.x big3d daemon is installed on a BIG-IP 4.x system, and a configsync is performed on the BIG-IP 4.x system, the big3d daemon is disabled.This behavior should not occur, as it will prevent the BIG-IP GTM from querying the BIG-IP 4.x system.

F5 Product Development tracked this issue as CR88060 and it was fixed in BIG-IP GTM 9.4.4. For information about upgrading, refer to the BIG-IP GTM release notes.

Additionally, this issue was fixed in HOTFIX-BIG-IP-9.3.1-HF2 issued for BIG-IP 9.3.1, for the BIG-IP 9.3.x software branch. You may download this hotfix or later versions of this hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Resolution

Workaround

To work around this issue, check the status of the big3d daemon and restart it by performing the following procedure:

  1. Log in to the command line of the BIG-IP 4.x system

    Note: This procedure must be performed on both BIG-IP 4.x systems in the redundant pair.
  2. To check the status of the big3d daemon, type the following command:

    bigstart status big3d
  3. If the big3d daemon reports that it is not running, restart the daemon by typing the following command:

    bigstart restart big3d
