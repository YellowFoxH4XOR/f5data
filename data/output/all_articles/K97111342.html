Description
There is a known Bug ID 947125: Unable to delete monitors after certain operations

Conditions
-- Monitors are attached directly to pool members, or node-level monitors exist.
-- Performing an operation that causes the configuration to get rebuilt implicitly, such as "reloadlic".

Workaround
When the system gets into this state, save and reload the configuration:
# tmsh save sys config && tmsh load sys config

Environment

  • BIG-IP
  • When navigating in the GUI under Local Traffic  ››  Monitors  ›› <MonitorName> you see the monitor applied to pool members which are unexpected.
     

Cause
Possibly related to Bug ID 947125: Unable to delete monitors after certain operations

Recommended Actions

If the workaround in Bug ID 947125 "tmsh save sys config && tmsh load sys config" does not work, then you can manually edit the /config/bigip.conf configuration file to remove the unexpected monitor from the pool members.

1) Backup the system with a UCS archive and manually backup /config/bigip.conf

K4423: Overview of UCS archives

# cp /config/bigip.conf /var/tmp/<FileName>_bigip.conf.bak

2) Now edit /config/bigip.conf

# vi /config/bigip.conf

 Use the forward slash "/" character to search for the pool and associated monitor.

Example: 
ltm pool /Common/mainProxy {
    members {
        /Common/x.x.x.x:80 {
            address x.x.x.x
            monitor /Common/<MonitorName> <--- delete this line
    }
    monitor /Common/http <----- expected schema for a pool monitor
}

3) Save and reload the configuration

# tmsh save sys config && tmsh load sys config

Important: Reloading the configuration will cause traffic interruption. This may result in a failover. F5 recommends that you perform this procedure on the standby device.
