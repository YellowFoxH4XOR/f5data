Known Issue

The BIG-IP GTM sync group members may create duplicate persistence entries.

This issue occurs when all of the following conditions are met:

  • The BIG-IP GTM system is in a sync group.
  • You have enabled persistence for the wide IP.
  • You have associated an IPv6 address pool member with the wide IP.

When the BIG-IP GTM system synchronizes an IPv6 persistence entry, the is_ipv6 field is not set on the BIG-IP GTM system receiving the synchronization. This behavior may cause the system to create and synchronize a duplicate persistence entry after receiving a request from the same Local Domain Name System (LDNS).

Impact

The BIG-IP GTM system may allocate additional resources to accommodate the duplicate persistence entries.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H384640 on the Diagnostics > Identified > Low screen.
  • The Traffic Management Shell (tmsh) command displays duplicate persistence entries for AAAA queries from the same source IP address. For example:

    tmsh show /gtm persist

    Value Level:Destination -> Target Expiration
    10.11.16.231 wideip:/Common/www.example.org -> pool-member:ipv6_vip 12-11 12:20:11
    10.11.16.231 wideip:/Common/www.example.org -> pool-member:ipv6_vip 12-11 12:19:15
  • The Configuration utility statistics page displays duplicate persistence entries for AAAA queries from the same source IP address.
