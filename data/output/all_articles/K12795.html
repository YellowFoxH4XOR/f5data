Known Issue

The BIGpipe parser does not correctly parse nested quotation marks within an iRule. The Configuration utility accepts an iRule containing nested quotation marks without reporting any error messages. However, the parser reports an error message when attempting to parse the nested quotation marks within an iRule. This situation prevents the system from loading the configuration into memory, and all traffic is stopped. If you reload the configuration using the bigpipe load command, perform a configuration synchronization (ConfigSync), or perform a reboot, the system reports error messages within the Configuration utility, at the command line, or in the /var/log/ltm file.

The following iRule example contains three sets of arguments where nested quotation marks are used:

when HTTP_RESPONSE {
  if { [HTTP::is_redirect] } {
    HTTP::header replace Location "[string map -nocase {"argument1" "argument 2" "argument.3"} [HTTP::header Location]]"
  }
}

The BIGpipe parser cannot correctly process this example iRule. If a user attempts to load the configuration, they receive an error message.

Impact

The configuration may fail to load, and as a result, the system may not process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to reload the configuration by using the bigpipe load command, the operation fails and the Configuration utility displays an error message similar to the following example:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

  • When you perform a ConfigSync, the operation fails and the Configuration utility or command line displays an error message similar to the following example:

    Reading configuration from /defaults/config_base.conf.
    snip...
    Reading configuration from /config/bigip.conf.
    BIGpipe parsing error:
       012e0008:3: The requested command (}) is invalid

  • When the BIG-IP system attempts to load the configuration after a reboot, the operation fails and the system generates an error message to the /var/log/ltm file. The error message appears similar to the following example:

    err bigpipe[16459]: 012e0006:3: Shell: BIGpipe parsing error (/config/bigip.conf Line 0):    012e0008:3: The requested command (}) is invalid

Workaround

To work around this issue, use braces ( {<argument>} ) or single quotation marks ( '<argument>' ) to group the arguments.

For example:

The following iRule uses nested quotation marks to group arguments. When the BIGpipe parser attempts to read the iRule, it reads the first quotation mark, and when it encounters the quotation marks around test01, it produces an error message:

when HTTP_RESPONSE {
  if { [HTTP::is_redirect] } {
    HTTP::header replace Location "[string map -nocase {"test01" "main.askf5.example.com" "test02" "main.askf5.example.com"} [HTTP::header Location]]"
  }
}

To prevent this issue from occurring, replace the double quotation marks that group the arguments with braces. For example:

when HTTP_RESPONSE {
  if { [HTTP::is_redirect] } {
    HTTP::header replace Location "[string map -nocase {{test01} {main.askf5.example.com} {test02} {main.askf5.example.com}} [HTTP::header Location]]"
  }
}

This workaround allows the BIGpipe parser to correctly interpret the previous section as a single argument with multiple strings surrounded by quotation marks.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
