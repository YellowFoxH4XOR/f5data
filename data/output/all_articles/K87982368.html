K87982368: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::spawn_relay_handler): Sync recovery state timed out. State may be inconsistent with other peers

Type
Support Solution
Published
2021-12-16
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP ASM: 13.1.3
Source
https://my.f5.com/manage/s/article/K87982368

Description

After upgrading one side of an HA pair to v.13.x , ASM is still using the old asm timestamp under non-existing hostname for its sync recovery task.

The following errors are generated in /var/log/asm
NEW_HOSTNAME_A/B info asm_config_server.pl[24432]: ASM is now entering sync recovery state. Requesting complete configuration from /Common/OLD_HOSTNAME_A
NEW_HOSTNAME_A/B crit g_server.pl[24432]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::Cgc::Channel::new): Could not open a cgc connection with group_id '/Common/OLD_HOSTNAME_A', service 'asm_cgc_high_pri_to_single'
NEW_HOSTNAME_A/B crit g_server.pl[24432]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::spawn_relay_handler): Sync recovery state timed out. State may be inconsistent with other peers
NEW_HOSTNAME_A/B info asm_config_server.pl[24432]: ASM is now entering sync recovery state. Requesting complete configuration from /Common/OLD_HOSTNAME_B
NEW_HOSTNAME_A/B crit g_server.pl[24432]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::Cgc::Channel::new): Could not open a cgc connection with group_id '/Common/OLD_HOSTNAME_B', service 'asm_cgc_high_pri_to_single'
NEW_HOSTNAME_A/B info asm_tables_dump.pl[26110]: ASM config saved

Environment

  • BIG-IP HA pair
  • ASM Synchronization
  • One side of the HA pair has been upgraded

Cause

After upgrading ASM will try to recover its sync task with the peer. In some rare cases, it will still utilize its old timestamp object to communicate with the peer. Due to mismatch version and incorrect hostname, configsync task will fail.

Recommended Actions

There are two workarounds available :

  1. Ignore the error and continue to upgrade its peer, the sync take will automatically recover once the two are able to synchronize.

  2. Remove the timestamp with old device name from the BIG-IP config 
    a.Verify if the old device definitions exist on the HA pair
    tmsh list asm device-sync recursive

    asm device-sync /Common/<Device group name>_asm_sync/OLD_HOSTNAME_A {
        timestamp xxxxxxxxxx
    }
    asm device-sync /Common/<Device group name>_asm_sync/OLD_HOSTNAME_B {
        timestamp xxxxxxxxxx
    }

    asm device-sync /Common/<Device group name>_asm_sync/NEW_HOSTNAME_A {
        timestamp xxxxxxxxxx
    }
    asm device-sync /Common/<Device group name>_asm_sync/NEW_HOSTNAME_B {
        timestamp xxxxxxxxxx
    }

    b. Delete the timestamp with old hostname definition

    tmsh delete asm device-sync <stale record>

    ex.
    tmsh delete asm device-sync OLD_HOSTNAME_A
    tmsh delete asm device-sync OLD_HOSTNAME_B
