Topic

The pva.offload.uniflow database key allows you to control how the BIG-IP system handles unidirectional User Datagram Protocol (UDP) traffic that is processed by a FastL4 virtual server.

Description

When the pva.offload.uniflow database key is set to false (default value), unidirectional UDP traffic will not be eligible for embedded Packet Velocity Accelerator (ePVA) hardware acceleration. For example, a wildcard forwarding virtual server with a FastL4 profile assigned, which is configured to process UDP traffic from client to server only, or from server to client only, will not utilize hardware acceleration by default.

When the pva.offload.uniflow database key is set to true, unidirectional UDP traffic is eligible for offload to the ePVA for hardware acceleration.

Recommendations

When planning to modify the pva.offload.uniflow database key, you should consider the following factors:

  • This is a global database key, and will affect all virtual servers with a FastL4 profile assigned, which process unidirectional UDP traffic. If you require both accelerated and non-accelerated UDP traffic in your environment, you can set the pva.offload.uniflow database key to true and then build separate virtual servers to accommodate the different traffic requirements. For a virtual server that requires no acceleration, create a custom FastL4 profile with acceleration set to none and assign it to the virtual server. For more information about acceleration in the FastL4 profile, refer to K12837: Overview of the ePVA feature.
  • This setting affects both IPv4 and IPv6 UDP traffic.
  • The default value is intended to ensure that UDP traffic is legitimate, in order to avoid UDP denial-of-service (DoS) attacks.
  • The performance impacts of modifying this key are negligible for other BIG-IP traffic types.

Procedures

To configure the pva.offload.uniflow database key, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system, however F5 recommends testing any changes in an appropriate environment.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To modify the value of the pva.offload.uniflow database key, use the following command syntax:

    modify /sys db pva.offload.uniflow value <true|false>

    For example, to set the pva.offload.uniflow database key to true, type the following command:

    modify /sys db pva.offload.uniflow value true

  3. To confirm the change, type the following command:

    list /sys db pva.offload.uniflow

    The output should appear similar to the following example:

    sys db pva.offload.uniflow {
        value "true"
    }

  4. Optionally, to reset the value to default, type the following command:

    modify /sys db pva.offload.uniflow reset-to-default
