Description

WebSocket traffic may be incorrectly blocked by BIG-IP ASM when ASM signature 200018023 is enabled. This occurs because the signature detects hexadecimal 0x0a (line break, ) characters in the WebSocket payload. The signature is intended to detect HTTP header injection but triggers on legitimate line breaks used in WebSocket protocols. According to RFC 6455, line breaks are valid within WebSocket data frames and do not represent a protocol violation.

Cause

ASM signature 200018023 is designed to detect HTTP header injection attacks by searching for the presence of the hexadecimal character 0x0a (line break) in HTTP header values. However, this detection does not distinguish between HTTP headers and WebSocket payloads. In WebSocket data frames, line breaks are valid and often required. As a result, legitimate WebSocket traffic containing line breaks can be falsely identified as malicious and blocked.

Recommended Actions

  • Disable ASM signature 200018023 in the affected ASM policy’s signature list to prevent false positives for WebSocket traffic.
  • When supporting applications that use protocols like WebSockets, confirm that your security policies accommodate expected protocol behaviors as defined in RFC 6455.
