Description

  • I need step-by-step instructions for creating an HTTP Load Balancer (LB) in F5 Distributed Cloud (XC), including configuration of FQDN, certificate options, origin pools, health checks, TLS settings, and DNS records
  • What are some best practices and important considerations to ensure proper LB functionality and secure, reliable traffic distribution?

Environment

  • F5 Distributed Cloud
  • HTTP(S) Load Balancer

Cause

  • Customers may require guidance on setting up an HTTP Load Balancer, including proper configuration of health checks, certificates, and DNS records to ensure secure and reliable traffic distribution to origin servers

Answer/Recommended Actions

  1. Access Load Balancer Management

    • Navigate to the LB management section
    • If you already have a load balancer, click the top left-hand corner to "Add HTTP Load Balancer." Otherwise, use the blue button to create a new LB

  2. Name Your Load Balancer

    • Assign a unique and descriptive name to your LB

  3. Configure FQDN

    • Enter the Fully Qualified Domain Name(s) (FQDN(s)) that the LB will serve

  4. Certificate Selection

    • If you have your own certificate, select the custom option
    • Otherwise, choose the automatic certificate option

  5. Configure Origin Pool

    • Add an item under the origin pool to define the group of origin servers by clicking the Add Item button in the Origin Pools section
    • Select an existing Origin Pool or make a new one by selecting Add Item from the Origin Pool Dropdown Menu
    • If making a new Origin Pool, enter the desired name for the Origin Pool
    • Click Add Item button in the Origin Server Section
    • Select the type of Origin Server to add:
      • Public DNS Name of Origin Server - use if origin server is a DNS Name
      • Public IP of Origin Server - use use if origin server is an IP
      • There are more advanced configurations available if required for your configurations
    • Configure the Port of your origin server (if different from default value)

    • Configure Health Check (Highly Recommended)

      • It is strongly advised to configure a health check
      • Without a health check, the LB will always assume the origin is online, which can lead to traffic being sent to unhealthy servers
      • Choose either HTTP or TCP health check (HTTP is preferred as it includes TCP checks and tests more functionality)
      • Default thresholds are typically sufficient; adjust only if necessary
      • Only change the health check path, response, or host header if required
      • If your root path (/) redirects, set the health check path to the redirect target to ensure a 200 response, rather than configuring for a 302 response

    • TLS Configuration

      • If the LB is serving HTTP only, TLS can be disabled
      • For HTTPS, enable TLS as it is required for secure connections

    • Origin Weight and Priority

      • Leave these settings at their default values unless you have specific load distribution requirements

    • Apply and Save Configuration

      • Click "Apply" to confirm settings
      • Hit "Save and Exit" at the bottom of the configuration page

  6. DNS Records and Certificate Challenge

    • Reopen the LB configuration in "Manage Configuration" mode (not edit).
    • Scroll down to the DNS Records section
    • If using automatic certificates, configure the ACME challenge record on your DNS server
    • Wait for the challenge to be verified and the certificate to be issued.

Additional Information

  • Health checks are critical for ensuring traffic is only sent to healthy origin servers
  • HTTP health checks are generally preferred over TCP for more comprehensive testing
