Known Issue

This is the result of a known issue. It is possible to delete a node address that is in use. This issue only occurs when a node using that address has been modified since it was created, due to an incorrectly decremented counter tracking the number of references to the node. If a node address that is in use is deleted, the pvad process will core immediately, and may continue to core until it is shut down and restarted. In addition to the pvad core files written to the /var/core/ directory, messages that appear similar to the following example are written to the Local Traffic log (/var/log/ltm):

Jan 23 15:44:46 bigip-one pvad[24327]: 01130003:6: Starting pvad
Jan 23 15:44:47 bigip-one pvad[24327]: 01130003:6: MCP connected!
Jan 23 15:44:48 bigip-one pvad[24327]: 01130003:6: Log level changed to: Informational
Jan 23 15:44:48 bigip-one pvad[24327]: 01130005:3: ../LogStream.cpp:89 - no obj w/key=10.113.120.131 w/rel1 to obj w/key=http_pool 10.113.120.131 20001 - Expression 'relObj != Global::cfg.end()' failed in '../GraphBuilder.cpp', line: 301
Jan 23 15:47:15 bigip-one sod[1835]: 010c0027:4: Failover condition, this standby will not be able to go active.

F5 Product Development tracked this issue as ID323097 and ID206092 (formerly CR116932 and CR116932-1), and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can avoid this issue by deleting all pool members using a given node address before deleting the node address. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. To list pools containing members using the node address you want to delete, use the following command syntax and replace the IP address with the node address you want to delete:
    bigpipe list | egrep '^pool|member[s] 10.10.10.1'
  3. Examine the command output to determine if the node address is in use by any pool members. The command output will list the names of all defined pools, and any pool members within each pool that use the address you want to delete.

    If the IP address is not displayed in the command output, the address is not in use by any pool member, and may be safely deleted. For example, the following output indicates that four pools are configured on the system, none of which contain the node address to be deleted:

    pool ftp_test {
    pool http_test {
    pool http_test2 {
    pool https_test {

    If a pool includes a member that uses the indicated node address, the name of the pool containing the matching member is listed on the line immediately preceding each incidence of the address. For example, the following output indicates that four pools are configured on the system, but that only the http_test pool and the https_test pool contain a member using the indicated node address:

    pool ftp_test {
    pool http_test {
    members 10.10.65.1:http {}
    pool http_test2 {
    pool https_test {
    members 10.10.65.1:https {}
  4. After deleting the pool members discovered in steps 2 and 3, repeat steps 2 and 3 to confirm there are no remaining pool members using the node address to be deleted.

Once you have confirmed that all pool members using the node address have been deleted, you may safely delete the node address.
