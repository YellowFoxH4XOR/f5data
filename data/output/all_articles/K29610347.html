Description
A high percentage of swap being used in itself is normal and expected behaviour on BIG-IP over time, as items using memory are pushed out to swap by the Linux kernel to free up physical ram, and typically the BIG-IP only has 1GB of swap allocated, while it can have far more other memory allocated.

Environment
  • BIG-IP
Cause
Given a constant usage/stable usage environment, as long as the physical memory usage under "Other memory used" in qkview graphs is dropping in line with the swap usage increasing, then the total memory usage of the system is constant and thus the increasing swap does not represent an increase in memory usage of the box. 

The point to note is that both graphs are displayed as percentages, but 100% usage of the 1GB swap memory available would only correspond to a decrease of 1GB in the total "Other memory" (or non-TMM memory) being used on the box, which is likely only a small percentage of the total non-TMM memory on the box and thus may not be easily visible in a percentage graph (depending on how much total non-TMM memory is allocated on the system).
