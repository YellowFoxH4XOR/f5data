Description

In accord with our published policies in K4602: Overview of the F5 security vulnerability response policy, F5 proactively investigates vulnerabilities in specific third-party packages (OpenSSL, Apache, Apache Tomcat, and bind) and investigates vulnerabilities in all other third-party packages (for example, log4j, node.js, and MySQL) as needed. F5 will investigate the impact of any disclosed CVE regardless of whether it was disclosed in the third-party package version running on the F5 product or a later version and regardless of the support status of the third-party package with the vendor (for example, the Apache Foundation or ISC).

Additional Information

F5 investigates vulnerabilities in third-party code regardless of the published impacted version. For example, BIG-IP 17.0 runs bind 9.11, which went End of Life (EoL) in January 2022. If bind discloses a CVE affecting bind 9.16 or later, regardless of whether ISC has evaluated bind 9.11, F5 will investigate whether the same problem impacts bind 9.11, as deployed within the F5 product (BIG-IP, BIG-IQ, F5OS, and so on) and respond accordingly, prioritizing fixes based on Common Vulnerability Scoring System (CVSS) score and exposure in the specific F5 use case.

For EoL third-party components, F5 may take fixes from later supported branches and apply them to the version installed in F5 products, and, therefore, the package version number alone cannot be relied upon to determine whether a specific CVE impacts the version in use within an F5 product; F5 security advisories on MyF5 are the source of truth for customers to understand their exposure based on the specific F5 use case for the third-party component in question.

Vulnerabilities that impact F5 products and services are reviewed through these outlined processes, and fixes are prioritized based on the risk they pose to the security of the system. F5 products are not general-purpose Linux systems; therefore, many vulnerabilities which impact general-purpose Linux systems either do not impact F5 products because the vulnerable code is not exposed or they have a lesser impact due to other security controls F5 has in place (specifics vary based on the CVE).

If a vulnerability does impact an F5 product, F5 reviews it for technical severity using the CVSS score and then prioritizes fixes based on the risk posed to the security of the platform. To maintain the system stability and compatibility with the other software installed on BIG-IP system, minor revisions will sometimes need customized patching instead of rebasing software packages to a new version. This practice is like that of Redhat's.
