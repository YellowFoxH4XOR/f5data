Description

BIG-IP APM Endpoint inspection (e.g. Machine Certificate Auth agent) checking failure may occur with "invalid request format".

When APM is configured to perform EPI (Endpoint inspection), APM instructs the connecting clients to perform endpoint inspection, collect the result, and send it to APM for verification.

Upon receiving the EPI results from the client, APM parses the result and checks whether the required fields are present. If parsing fails or required fields are absent, the APM will generate a message "invalid request format" to indicate some errors in the received EPI result. A sample error message looks like this (inside /var/log/apm):

Feb 4 11:48:09 apm.name.com info apmd[29890]: 01490125:6: /Common/test-accesspolicy:abc12345: Client response for the machine cert request: invalid request format

Please note that this error log is logged at the info log level (APM default log level is Notice, so such logs will not be visible at the default log level).

When such logs are observed, the access policy evaluation will go through the Fallback branch of the EPI agent.

Environment

BIG-IP APM Any versions

Access policy configured with EPI (Endpoint inspection agent like "Machine Cert Auth", "Machine Info", "Antivirus", "Firewall", etc.)

Cause

The root cause of such an error log is an incomplete or malformed HTTP POST request arriving at the APM during EPI checking. Such an incomplete or malformed HTTP POST request can be triggered by external factors such as an intermediate network device resetting connections, security software intercepting HTTP POST but failing to inspect it due to an unknown decoding method, or heuristic behaviors of third-party endpoint security software running on the client.

Recommended Actions

If more information is required, follow the steps outlined below:

(1) From the APM logs identify the APM session and the corresponding username.

(2) On the PC of the related username, check the client-side logs focusing on the session:

%temp%\f5InspHostCtrl.txt (default file location)

2025-02-17, 3:31:14:650, 5456,1980,, 48,,,, CUAgentHost::downloadNextAgent() - sending request to server "https://APM-vs-fqdn.com/my.policy_host?sess=abc12345&dummy=0"
2025-02-17, 3:31:14:651, 5456,1980,, 48,,,, CUAgentHost::downloadNextAgent() - POST data "version=2.0&client_data=c2Vz ... encoded data ... 3PT0=" !!! HTTP POST by the EPI agent !!!
2025-02-17, 3:32:04:614, 5456,1980,, 48, \ubindstatuscallback.h, 124, UBindStatusCallback::OnStopBinding, Http status code:2147954419 !!! the response of the above EPI agent POST (this is an indication that the HTTP POST was TCP reset by an intermediate device) !!!

If more lower-level information is required during the problem, simultaneous sets of packet capture (on the client and APM) will be required during the problem.
