Description

When developing automation solutions using F5 Application Services 3 Extension (AS3), it is important to understand the naming limitations for various objects. AS3 object names have different maximum length restrictions depending on the object type and the underlying BIG-IP TMOS constraints. This article provides a comprehensive overview of object name length limitations across AS3 declarations to help developers implement appropriate guardrails in their automation workflows.

General AS3 Path Limitations

BIG-IP AS3 3.17.0 and later allows names longer than 64 characters, with the following constraint:

  • Total path length: The combined character length of tenant name + application name + item name (along with 3 forward slashes) must be less than or equal to 195 characters

Path format:

/TenantName/ApplicationName/ItemName

Where:

  • TenantName: Partition/Tenant name
  • ApplicationName: Application folder name
  • ItemName: Object name (Virtual Server, Pool, Profile, iRule, etc.)

BIG-IP TMOS Limitations

From the MCPD perspective:

  • Folder path names: Limited to 255 characters in length (Reference: K14440)

For detailed property-specific limitations, refer to the AS3 Schema Reference: https://clouddocs.f5.com/products/extensions/f5-appsvcs-extension/latest/refguide/schema-reference.html

Example schema definition for Declaration ID contains type   pattern min and maxlength:

"id": {
  "title": "Declaration ID",
  "description": "Unique identifier for this declaration (max 255 printable chars with no spaces, quotation marks, angle brackets, nor backslashes)",
  "type": "string",
  "pattern": "^[^\\x00-\\x20\\x22'<>\\x5c^`|\\x7f]*$",
  "minLength": 0,
  "maxLength": 255
}

Environment


  • AS3
  • Names, length type details in AS3


Cause


AS3 and BIG-IP TMOS have specific character length limitations for object naming that must be adhered to for successful declaration processing.


Developers need to understand the maximum character length allowed for object names when creating AS3 declarations to avoid deployment failures and implement proper validation in their automation workflows.


Recommended Actions


  • Implement naming conventions that keep object names well below the maximum limits
  • Set guardrails in automation workflows to validate name lengths before submitting AS3 declarations
  • Test declarations in a non-production environment when using longer names
  • Review the AS3 schema for specific object types to understand their individual maxLength constraints
  • In case of getting issues with name length different then the one described in article create support case to address specific issue
