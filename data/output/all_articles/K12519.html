Known Issue

This is the result of a known issue. If the BIG-IP Advanced Routing Module (ARM) receives a BGP OPEN message containing an unsupported capability code, and the unsupported capability code is less than or equal to 128, the BIG-IP ARM incorrectly responds with Error Subcode 7 (Unsupported Capability) and then terminates the connection. As a result, BGP peering fails. The correct behavior as defined in RFC5492 is for the BIG-IP ARM to ignore the unsupported capability.

Important: The BIG-IP ARM does not currently support 32-bit Autonomous System Numbers (ASNs) as described in K11211: BIG-IP support for 32-bit Autonomous System Numbers. The 32-bit ASNs are increasingly common, and they correspond to capability code 65. As a result, the BIG-IP ARM will terminate peering if the BGP neighbor advertises support for 32-bit ASNs.

F5 Product Development is tracking this issue as ID 347664, and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by disabling BGP capabilities negotiation on the neighboring device. However, doing so may affect all negotiated capabilities, such as graceful restart.

Certain Cisco platforms allow you to disable capabilities negotiation on a per-peer basis using the dont-capability-negotiate command.

For example:

router bgp 64512
neighbor 192.168.1.100 remote-as 64512
neighbor 192.169.1.100 dont-capability-negotiate

Note: For more information about the dont-capability-negotiate command, refer to the Cisco documentation pertaining to your particular device and software version.
