Description

When generating a UCS archive, users may see warnings saying that 'not everything was saved' or fail to create UCS archive file through GUI or CLI.
One may notice the below log message under /var/log/liveinstall.log or while taking UCS back-up through CLI.

Example:
Operation Status
Saving active configuration...

/var/tmp/configsync.spec: Error creating package

WARNING:There are error(s) during saving.
        Not everything was saved.
        Be very careful when using this saved file!

Error creating package
Error during config save.
Unexpected Error: UCS saving process failed.

OR

Saving active configuration...

tar: /var/tmp/im16366/configsync-2.0-1-Linux-3.10.0862.14.4.7..8664.im: Wrote only 8192 of 10240 bytes
tar: Error is not recoverable: exiting now
Fatal: executing: tar --no-recursion -rf /var/tmp/im16366/configsync-2.0-1-Linux-3.10.0862.14.4.7..8664.im --no-unquote --files-from=/var/tmp/im.16611/Files
Operation aborted.
/var/tmp/configsync.spec: Error creating package

WARNING:There are error(s) during saving.
        Not everything was saved.
        Be very careful when using this saved file!

Error creating package
Error during config save.
Unexpected Error: UCS saving process failed.

Or

Messages indicating low memory var/log/ltm log file :
err diskmonitor[56049]: 011d0004:3: Disk partition /shared has only 17% free
err diskmonitor[56049]: 011d0004:3: Disk partition /shared has only 17% free

???Environment

  • BIG-IP
  • APM module is provisioned
  • UCS Archive
  • Disk Space


Cause

  • Out of disk space or low memory space in  /shared or /var partition. 
  • Bug ID 782157: Cannot save UCS with a passphrase when unused EPSEC files are available.


Recommended Actions

To make some space in the partition, please follow the below procedure.
Impact of procedure: Running this procedure should not have a negative impact on the traffic. 

Procedure 1: Free up some space in /shared partition 

  1. Log in to the command line.

  2. Check disk space usage with command in bash: 
    # df -h

    Example :
    Filesystem                             Size  Used Avail Use% Mounted on

  3. Run the below command to list the top 20 largest files in the /shared partition. This would help to determine large files.
     # find /shared/ -xdev -type f -exec du {} \; | sort -rn | head -20
     
  4. Remove large files which are not necessary and free some space. 
    # rm <filename>
    Example :
    #rm /shared/tmstat/snapshots/blade1/public/3600/blade1-public-3600-2021-06-29T12
    Note : Only remove unnecessary files, once deleted, they cannot be recovered.
     
  5. Now try to take a UCS back up.
    # tmsh
    # save sys ucs /var/tmp/myucs.ucs

     
Procedure 2: If the above steps do not resolve the issue, then check for any OPSWAT EPSEC packages in BIG-IP provisioned with the APM module.
Please refer to the article steps outlined in the article K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system.
Try to generate a UCS after removing the packages.
