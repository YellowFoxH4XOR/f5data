Known Issue

The Traffic Management Microkernel (TMM) may restart when a DNS cache resolver's max-concurrent-queries setting value is significantly larger than the default.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration contains a cache resolver that resolves DNS queries.
  • You have modified the max-concurrent-queries setting to a value significantly larger than the default value of 1024.
  • The BIG-IP system receives a large amount of DNS traffic.

Impact

TMM restarts and temporarily fails to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.

Workaround

To work around this issue, you can avoid setting the DNS cache resolver's max-concurrent-queries setting to a value above 2048.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
