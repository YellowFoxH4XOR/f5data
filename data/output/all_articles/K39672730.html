Known Issue

The mcpd process may randomly exit while performing a configuration synchronization (ConfigSync) operation.

This issue occurs when all of the following conditions are met:

  • You configure a device group with two or more BIG-IP systems.
  • While executing a ConfigSync operation, the mcpd process encounters an uninitialized variable.

Impact

Traffic is disrupted while the mcpd process restarts. A failover occurs if you have configured the systems for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The mcpd process generates a core file to the /shared/core/ directory.
  • If logging for the mcpd process is set to Debug, the BIG-IP system may generate a log message to the /var/tmp/mcpd.out file that appears similar to the following example:

    Received request message from connection 0x5fe47008 (user %cmi-mcpd-peer-/Common/hostname.example):
    query_all {
    sync_file {
    sync_file_file_to_sync "/var/apm/localdb/mysql_bkup.sql"
    sync_file_target_dg "/Common/example_dg"
    sync_file_postprocess_action "/usr/libexec/localdb_mysql_restore.sh"
    sync_file_originator "/Common/hostname.example"
    }
    }

  • The BIG-IP system fails over to another device in the device group during a ConfigSync operation.
