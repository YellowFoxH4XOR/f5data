Known Issue

Pool members may be displayed with an inconsistent and fluctuating list of health monitors.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration makes use of partitions.
  • You are using route domains.
  • You are using the Configuration utility from the Local Traffic > Pools > <pool_name> > Members > <pool_member_name> menu to display the health monitors for a pool member.

    In the previous example, note the following:

      - <pool_name> is the name of the pool.
      - <pool_member_name> is the name of a specific pool member in that pool.

Impact

You may not be able to display the correct list of health monitors for pool members using the Configuration utility.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility may list no health monitors, or up to the true number of health monitors for that member.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to view the list of health monitors for a pool member. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Displaying health monitors for a member using the tmsh utility

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Display member information using the following command syntax:

    show ltm pool <pool_name> members {<member_ip>:<port>}

    In the previous syntax, note the following:

      - <pool_name> is the name of the pool with which the member is associated.
      - <member_ip> is the IP address of the pool member.
      - <port> is the TCP port for which the pool member is configured.

    For example:

    show ltm pool f5_pool members {192.168.1.1:80}

  3. Note the list of associated monitors under the Montior heading.
